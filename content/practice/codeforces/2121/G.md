 ## 解決策
 ## 問題の理解

 バイナリ文字列を処理し、すべての連続する部分文字列について、いずれかの最大頻度を計算するように求められます。`0`または`1`その部分文字列内で、すべての部分文字列にわたるこれらの値を合計します。 たとえば、文字列では`0110`、部分文字列`011`2つあります`1`と 1`0`、したがって、その最大頻度は 2 です。出力は、すべての可能な部分文字列にわたるこれらの最大頻度の合計です。 

入力には複数のテスト ケースが含まれています。 各テスト ケースには最大 200,000 の長さの文字列が与えられ、すべてのテスト ケースの合計長も 200,000 によって制限されます。 2 秒の時間制限では、部分文字列の数がおおよそ 2 次関数的に増加するため、すべての部分文字列を個別に検査するアルゴリズムは遅すぎます。`n*(n+1)/2`。 のために`n = 2*10^5`これは約 200 億個の部分文字列に相当し、2 秒で処理できる量をはるかに超えています。 に対して線形または線形演算時間で実行するアプローチが必要です。`n`。 

単純な実装が失敗する原因となる可能性のあるエッジ ケースには、完全に 1 文字で構成される文字列が含まれます。 たとえば、`1111`、各部分文字列には、`1`s、最大頻度の合計はすべての部分文字列の長さの合計、つまり 10 です。個別のセグメントまたは交互のみをカウントする不注意な実装では、過小カウントされる可能性があります。 もう 1 つの微妙なケースは、次のような文字列を交互に使用することです。`010101`; ここで、部分文字列の最大頻度は長さに応じて変化するため、ソリューションでは連続する等しい文字の長さを正確に考慮する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。開始インデックスと終了インデックスのすべてのペアを反復処理します。`(l, r)`、部分文字列を抽出します`s[l:r+1]`の数を数えます`0`と`1`s、最大値を取得し、それを合計します。 これは正しいですが、複雑です`O(n^3)`素朴に実装された場合 (または`O(n^2)`カウントが増分的に維持される場合)、これは遅すぎます。`n`最大 2*10^5。 

重要な洞察は、部分文字列内の最大頻度は、連続する同一文字の実行によって決まるということです。 部分文字列の最大頻度は、その中の同一文字の最長連続ブロックの長さです。 したがって、部分文字列を列挙する代わりに、連続する同一文字のブロックを反復処理して、それらの寄与を効率的にカウントできます。 

長いランの場合`k`、この実行が寄与する部分文字列の数`i`最大値は組み合わせによって決定されます。 すべての実行の寄与の合計は、系列を合計することで計算できます。`1 + 2 + ... + k`実行ごとに。 これが機能するのは、ランの一部を含む各部分文字列には少なくとも 1 つの文字が含まれており、最大頻度はその中の最長のブロックによって決まるためです。 これにより問題は線形時間に短縮されます`O(n)`テストケースごとに。

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`answer = 0`現在の文字列の最大頻度の合計。 
2. 連続する同一文字の実行を追跡しながら、文字列を反復処理します。 カウンターを開始する`count = 1`。 
3. 位置の各文字について`i`(2 文字目以降) 前の文字と一致する場合はインクリメントします`count`。 それ以外の場合は、現在の実行を処理します。合計を加算します。`count*(count+1)//2`に`answer`そしてリセット`count = 1`。 
4. ループが終了したら、最後の実行の合計を`answer`。 
5. 計算結果を出力します。`answer`このテストケースでは。 
6. テスト ケースごとに上記の手順を繰り返します。 

機能する理由: 部分文字列内の最大頻度は常に、少なくともその部分文字列に含まれる同一文字の最長の連続の長さ以上です。 連続した実行の長さを合計することで、すべての部分文字列の寄与を効果的に考慮できます。 各部分文字列の最大頻度は、合計の中で 1 回だけカウントされます。`0`走るか、`1`含まれているものを実行します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        answer = 0
        count = 1
        for i in range(1, n):
            if s[i] == s[i-1]:
                count += 1
            else:
                answer += count * (count + 1) // 2
                count = 1
        answer += count * (count + 1) // 2
        print(answer)

if __name__ == "__main__":
    solve()
```コードは複数のテスト ケースを効率的に処理します。 単純なカウンターを使用して同一文字の連続を追跡し、各実行について、次の式を使用して 1 からランの長さまでのすべての整数の合計を計算します。`count*(count+1)//2`。 これにより、部分文字列を明示的に列挙することなく、各部分文字列の最大頻度寄与が正しくカウントされることが保証されます。 単一文字の文字列や最後の文字で終了するランなどのエッジ条件は、ループの後に最後のランを追加することで自然に処理されます。

 ## 特殊なケース

 単一文字列の場合`0`、アルゴリズムが初期化されます`count=1`、ループに入らず、追加します`count*(count+1)//2 = 1`に`answer`、正しい出力が生成されます。 

のような文字列の場合`1111`、カウンタは実行全体を通してカウントし、その後追加します。`4*(4+1)//2 = 10`最後に。 この実行を含む部分文字列はすべて合計に正しく考慮されます。 

交互弦用`010101`、カウンターは実行ごとに 1 を交互に繰り返し、合計します。`1*2//2`繰り返し。 それぞれの小さな実行は、それを含む部分文字列に正しく寄与しており、すべての寄与の合計は予想される合計と一致します。 これは、アルゴリズムが、長時間の均一な実行と頻繁な交代の両方の極端な状況に対応していることを裏付けています。
