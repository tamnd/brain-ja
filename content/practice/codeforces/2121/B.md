 ## 解決策
 ## 問題の理解

 指定された文字列について、それを 3 つの空でない部分に分割できるかどうかを判断するように求められます。$a$、$b$、 そして$c$、そのような$a + b + c = s$そして真ん中のセグメント$b$連結の部分文字列として表示されます$a + c$。 言い換えれば、「中間の部分」があるかどうかを知りたいのです。$b$プレフィックスの組み合わせのどこかにすでに表示されているもの$a$と接尾語$c$。 

入力は複数のテスト ケースで構成され、それぞれの長さは 3 以上、最大でも 3 文字以下の文字列です。$10^5$。 すべてのテスト ケースの文字列長の合計が次を超えない$2 \cdot 10^5$。 これは、考えられるすべての分割をチェックする余裕がないことを意味します$a, b, c$素朴に、大まかにあるので、$O(n^2)$エンドポイントを選択する方法$b$単一の長さの文字列の場合$n$。 近づくアルゴリズム$O(n^2)$遅すぎるので、それに近いものが必要です$O(n)$文字列ごとに。 

微妙なエッジ ケースは、文字列が「aaa」などの同一の文字で構成されている場合です。 3 つのセグメントに分割しても、最初と最後のセグメントを連結した中に中央の部分が表示されるようになります。 もう 1 つの注意が必要なケースは、「abc」など、すべての文字が異なる場合です。 ここで、部分文字列条件を満たすには、中央の文字が最初または最後の文字と一致する必要があります。 不注意な実装では、常に中間セグメントを複数の文字として取得しようとしたり、最も単純な分割オプションを無視したりして、間違った答えが生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能なすべての開始位置と終了位置を反復処理することです。$b$そして、次のことを確認します$b$の部分文字列として表示されます$a+c$。 ある長さの文字列の場合$n$、これには時間がかかる可能性があります$O(n^3)$最悪の場合の時間 (開始と終了を選択してください)$b$、次に部分文字列をチェックします$O(n)$比較）。 これは明らかに不可能です$n$まで$10^5$。 

重要な観察は、長い中間セグメントを考慮する必要がないということです。 私たちが取るなら$b$単一の文字である場合、それが次のいずれかの最初の文字と一致するかどうかをすぐに確認できます。$s$または最後の文字。 具体的には、$s[0] == s[1]$または$s[1] == s[-1]$、有効な分割が存在します: 選択できます$a$最初のキャラクターとして、$b$2番目として、そして$c$残りとして。 あるいは、$s[-2] == s[-1]$または$s[0] == s[-2]$、最後の文字を次のように選択できます。$c$そしてその前のものは$b$。 

これは、長さ 1 の部分文字列が自明に現れるため機能します。$a+c$いずれかのエンドポイントと一致する場合。 文字列の長さは少なくとも 3 であるため、このチェックで十分です。$b$条件を満たすには 1 文字以上にする必要があります。 この貪欲な洞察により、複雑さが軽減されます。$O(1)$文字列ごとにチェックするため、十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 文字列ごとに$s$長さの$n \ge 3$で分割することを検討してください。$b$単一の文字として。 2番目の文字に注目$s[1]$または最後から2番目の文字$s[-2]$。 
3. 次のことを確認します。$s[1]$マッチ$s[0]$または$s[-1]$。 存在する場合は「はい」を出力します。 それ以外の場合は、次のことを確認してください$s[-2]$マッチ$s[0]$または$s[-1]$。 どちらかの条件が真の場合、「Yes」を出力します。 
4. 上記のチェックのいずれにも合格しない場合は、「いいえ」を出力します。 

機能する理由: 空ではない中間セグメントを含む有効な分割では、その中間セグメントがプレフィックスとサフィックスの組み合わせに出現することを許可する必要があるため、このアプローチでは正確さが保証されます。 単一文字セグメントは空ではない最小限の部分文字列であるため、有効な分割が存在する場合は、2 番目と最後から 2 番目の文字を文字列のエンドポイントと照合することで検出されます。 長い部分文字列の場合は、その文字の 1 つがエンドポイントと一致することのみが必要であり、これはこの最小限のチェックでカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    if s[0] == s[1] or s[-1] == s[-2] or s[1] == s[-1] or s[0] == s[-2]:
        print("Yes")
    else:
        print("No")
```このソリューションは、まずテスト ケースの数を読み取り、各文字列を反復処理します。 偶発的な不一致を避けるために、文字列を読み取った後に改行をトリミングします。 このチェックは、中央の文字は 1 文字であり、どちらかの端と一致する必要があるという観察を直接実装します。 真に一致するものが 1 つだけ必要なため、条件の順序は任意です。
