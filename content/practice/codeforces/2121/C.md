 ## 解決策
 ## 問題の理解

 整数の長方形グリッドが与えられます。 1 回の操作で、単一の行と単一の列を選択します。 選択した行または列にあるすべてのセルが 1 つ減らされ、交差するセルは 1 回だけカウントされます。 

タスクは、この 1 つの操作を実行した後、グリッド内の任意の最大値ができるだけ小さくなるように、この行と列を選択することです。 

主な難点は、1 行 1 列を減らすと、単純な部分配列ではなく、十字型の領域に影響が及ぶことです。 行と列の候補を選択するたびに多くのセルが一度に変更されるため、この構造化された減分後に最大要素がどのように動作するかを推論する必要があります。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースにわたるセルの合計。 それはすぐにすべてを試すことを排除します$n \cdot m$すべてのテスト ケースの行と列のペア。これにより、大まかに次の結果が得られます。$O(n^2 m^2)$最悪の場合の動作が大きすぎます。 テスト ケースごとに線形または線形に近い方法が必要です。 

最大値が一意である場合、微妙なエッジケースが発生します。 唯一の最大値が 1 つのセルにある場合は、いつでもその行と列を選択して値を減らし、グローバル最大値を減らすことができます。 ただし、複数の最大値が異なる行と列に存在する場合、1 回の操作ではそれらすべてをカバーできず、一部の最大値がそのまま残される可能性があります。 この違いがソリューション全体を推進します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアを試します$(r, c)$、行内のすべてのセルの減少をシミュレートします。$r$そしてコラム$c$を計算し、結果の最大値を計算します。 各シミュレーションの費用$O(nm)$、そして、あります$O(nm)$選択肢、それにつながる$O(n^2 m^2)$最悪の場合。 これはまったく実現不可能です。 

重要な点は、各選択を完全にシミュレートする必要はないということです。 操作後の最大値が元の最大値になるか、それより 1 つ小さくなるかだけを考慮します。 影響を受けるすべてのセルはちょうど 1 だけ減少するため、グローバル最大値を減らす唯一の方法は、現在の最大値がすべて選択された行と列で「カバー」されるようにすることです。 

最大値のセルが選択した行または列にない場合、セルは変更されないため、最大値も変わりません。 すべての最大値セルがカバーされている場合、すべての最大値セルは最大でも最大値から 1 を引いた値まで減少し、2 番目に大きい値が影響を受けずに元の最大値から 1 を引いた値に等しくない限り、新しい答えはその値になります。 

したがって、問題は、グローバル最大値を含むすべての位置をカバーする行と列を選択できるかどうかを確認することに帰着します。 「はい」の場合、答えは減ります。 それ以外の場合は、変更されないままになります。 

これをさらに改良していきます。 最大値がいくつかのセルに現れるとします。 すべての最大値がその行または列のいずれかに収まるように、行と列を選択しようとします。 そのようなペアが存在する場合、最大値は 1 つ減ります。 それ以外の場合は、同じままです。 

唯一の候補者は、$r$そして$c$その問題は最大の要素の位置から導出されます。 それらの位置に表示される行と列を調べるだけでよいため、最大セル数の線形検索が維持されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. グリッド全体をスキャンして最大値を見つけます。 

これにより、排除または削減しようとしている目標レベルが確立されます。 
2. この最大値が表示されるすべての座標を収集します。 

これらのセルは、操作によって答えを減らすことができるかどうかを決定するために重要な唯一のセルです。 
3. 行が存在するかどうかを確認してみます。$r$すべての最大セルが行内に収まるようにする$r$または単一の共通の列に配置します。 

より正確には、少なくとも 1 つの最大値を含む候補行ごとに、残りの未カバーの最大値がすべて同じ列を共有しているかどうかをチェックします。 
4. 候補行をテストするには$r$、行内にないすべての最大位置を確認します。$r$。 それらが存在する場合、それらはすべて同じ列を持つ必要があります$c$。 これが当てはまる場合、有効なペアが見つかりました$(r, c)$。 
5. そのような構成が存在しない場合、単一の行と列ですべての最大値セルをカバーすることは不可能であるため、少なくとも 1 つの最大値は影響を受けません。 
6. 有効なペアが存在する場合、最終的な答えは最大値から 1 を引いたものになります。 それ以外の場合は、元の最大値のままになります。 

### なぜ効果があるのか

 この操作では、選択した 1 つの行または列にあるセルのみが削減されます。 グローバル最大値を削減したい場合は、すべての最大値セルに影響を与える必要があります。 最大値セルは、選択した行または列にある場合にのみ影響を受けます。 したがって、すべての最大位置は 1 つの行と 1 つの列の和集合に属している必要があります。 

2 つの最大値セルが異なる行と異なる列に同時に存在する場合、行の 1 つがメイン行として選択され、残りの最大値がすべて 1 つの列を共有しない限り、単一の行と列のペアで両方をカバーすることはできません。 これはまさにアルゴリズムでテストされた条件です。 行と列によるカバレッジの構造は実現可能性を完全に特徴付けるため、この条件を確認することは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = []
        mx = 0

        for _ in range(n):
            row = list(map(int, input().split()))
            grid.append(row)
            mx = max(mx, max(row))

        positions = []
        for i in range(n):
            for j in range(m):
                if grid[i][j] == mx:
                    positions.append((i, j))

        rows = set(i for i, _ in positions)
        cols = set(j for _, j in positions)

        ok = False

        # try fixing a row
        for r in rows:
            col_candidate = -1
            valid = True
            for i, j in positions:
                if i == r:
                    continue
                if col_candidate == -1:
                    col_candidate = j
                elif col_candidate != j:
                    valid = False
                    break
            if valid:
                ok = True
                break

        # try fixing a column if not already ok
        if not ok:
            for c in cols:
                row_candidate = -1
                valid = True
                for i, j in positions:
                    if j == c:
                        continue
                    if row_candidate == -1:
                        row_candidate = i
                    elif row_candidate != i:
                        valid = False
                        break
                if valid:
                    ok = True
                    break

        print(mx - 1 if ok else mx)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず最大値とその出現箇所をすべて抽出します。 次に、それらの出現がいずれかの方向の 1 行と 1 列でカバーできるかどうかをテストします。 2 段階のチェックは、選択された 2 つのインデックスのうちどちらが支配的な行または列として機能するかを選択することに正確に対応します。 

一般的な実装上の落とし穴は、多くの最大値を個別に含む行と列を選択するだけで十分であると想定していることです。 制約はより厳密です。選択した行の外側にあるすべての最大値は単一の列に整列する必要があります。 

## 実用的な例

 小さなグリッドを考えてみましょう。 

入力:```
1
3 3
2 1 2
1 2 1
2 1 2
```最大値は 2 で、四隅に発生します。 候補行をテストします。 

| ステップ | 選択された行 | 残りの最大ポジション | 個別の列 | 有効 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | (2,0)、(2,2)、(1,1)、(2,0)、(2,2) | 0,2,1 | いいえ |

 行が残りの最大値を 1 つの列に分離しないため、行ベースのカバーは失敗します。 残りの最大値が複数の行と列にまたがっているため、列ベースのチェックも同様に失敗します。 したがって、出力は 2 のままです。 

このトレースは、極大値が頻繁に発生するにもかかわらず、その幾何学的広がりにより単一の十字がそれらをカバーできないことを示しています。 

ここで次のことを考えてみましょう。 

入力:```
1
2 3
5 1 5
1 1 1
```位置 (0,0) および (0,2) では最大は 5 です。 

行 0 を選択すると、すべての最大値がすでにその行に含まれているため、操作によって自動的に最大値がカバーされます。 

| ステップ | 行 | 残りの最大ポジション | 行の外側の列 | 有効 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | なし | なし | はい |

 よって答えは4になります。 

これは、すべての最大値が既に 1 つの行に存在する場合、操作によって最大値が自明に減少することを確認します。

 ## 特殊なケース

 重要なエッジケースは、すべてのセルがすでに最大値になっている場合です。 この場合、任意の行と列を選択すると、影響を受けない多くのセルが残りますが、すべてが均一に削減されるため、最大値はちょうど 1 つ減少します。 すべての最大位置がすべての行に存在するため、アルゴリズムはこれを処理します。そのため、行ベースのチェックはすぐに成功します。 

もう 1 つの特殊なケースは、最大位置が L 字型を形成する場合です。 たとえば、(0,0)、(0,1)、(1,0) の最大値。 単一の行または列ですべてを同時にカバーすることはできません。 行または列を修正した後も、残りの位置が複数の行および列に分割され、チェックが失敗するため、アルゴリズムはこれを検出します。 

最後の微妙なケースは、最大セルが 1 つだけ存在する場合です。 それを含む選択された行と列はすぐに成功し、正解は最大値から 1 を引いたものになります。
