 ## 解決策
 ## 問題の理解

 整数配列と、テスト ケースごとに 2 つのターゲット値が与えられます: 必要なサブ配列の合計`s`および必要な最大値`x`。 このタスクは、合計が次と正確に等しい連続する部分配列がいくつあるかを数えるというものです。`s`そしてその最大の要素は正確に`x`。 

これについて考えると、すべての部分配列が 2 つの独立した制約に寄与すると考えると便利です。 合計条件はすべての要素に依存しますが、最大条件はセグメント内の最大の要素のみに依存します。 有効なセグメントは両方を同時に満たす必要があります。 

制約により、私たちは線形または線形に近い動作を強いられます。 すべてのテスト ケースの合計の長さは最大でも`2 · 10^5`したがって、テスト ケースごとに O(n log n) よりも悪いソリューションはタイムアウトになる危険性があります。 すべてのサブアレイにわたる二次スキャンは、最悪の場合でも最大約 10^10 のセグメントを検査することになるため、直ちに実行不可能です。 

いくつかのエッジの状況が重要であり、素朴なロジックを壊す可能性があります。 

問題の 1 つは、いつ`x`セグメントには表示されませんが、すべての要素が小さくなります。 このようなセグメントは合計条件を満たす可能性がありますが、最大値が厳密に小さいため除外する必要があります。`x`。 たとえば、次の場合`x = 5`そしてセグメントは`[1, 2, 3]`、その合計は一致する可能性があります`s`、しかしそれは無効です。 

要素が次の値を超える場合、別の微妙なケースが発生します。`x`。 より大きい要素を含む任意の部分配列`x`最大値は自動的に要件に違反するため、完全に除外する必要があります。 たとえば、次の場合`x = 3`、次に以下を含むセグメント`4`は、その合計に関係なく常に無効です。 

最後に、合計のカウントと最大制限の間には重要な相互作用があります。合計のカウントはプレフィックス合計を使用すると簡単ですが、最大制限は配列を独立した領域に分割するため、慎重に扱う必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのサブ配列が試行されます。`[l, r]`、それらの合計と最大値を計算し、両方の条件に一致するものをカウントします。 合計はプレフィックス合計を使用して O(1) で計算できますが、前処理しない限り最大コストはセグメントごとに O(n) かかります。 前処理を行ったとしても、すべての O(n^2) セグメントを列挙すると二次時間になり、2 · 10^5 までの n に対しては非常に遅すぎます。 

重要な観察は、最大制約が実際の構造の推進力であるということです。 「最大値が x に等しい」を直接チェックする代わりに、問題を分割できます。 

部分配列には最大値が正確にあります`x`次の場合にのみ:

 1. すべての要素は最大でも`x`、そして
 2. 以下に等しい要素が少なくとも 1 つ含まれます。`x`。 

これは、配列を、より大きい要素で区切られた最大のブロックに分割することを示唆しています。`x`。 各ブロック内では、すべての要素が ≤ x であるため、有効性の残りの条件は「少なくとも 1 つの x が含まれる」ということだけになります。 

ここで問題は、各ブロック内で部分配列を合計でカウントすることです。`s`少なくとも 1 つの発生を含む`x`。 

標準的な分解トリックを使用してこれを処理します。すべての部分配列を合計でカウントします。`s`ブロック内で、何も含まれていないものを減算します。`x`。 を含まないサブ配列`x`ブロックをあらゆる位置で分割することによって形成された小さなセグメント内に完全に存在します。`a[i] == x`。 

したがって、各ブロックは厳密に要素のセグメントに分割されます`< x`。 このようなセグメントごとに、合計を使用してサブ配列をカウントします。`s`プレフィックス合計とハッシュマップ頻度カウントを使用します。 

これにより、全体的な問題が線形セグメントにわたるプレフィックス合計カウントの 2 つのパスに削減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

### 1. x より大きい要素で配列を分割します。 

配列をスキャンし、すべての値が x 以下である連続したセグメントに分割します。 > x の値を含むセグメントは、その値を超える有効なサブ配列を提供できないため、ハード境界として機能します。 

これにより、最大値が x になる可能性がある領域内でのみ作業することが保証されます。 

### 2. 各有効なセグメント内で、x に等しい個別の位置

 セグメント内でインデックスを特定します。`a[i] == x`。 これらの位置には、「x を含める必要がある」という要件が適用されます。 

概念的には、すべての値が厳密に x より小さい、セグメントをより小さなサブセグメントに分割します。 

### 3. セグメント内の合計を含むすべての部分配列をカウントします。 

合計を使用して部分配列の数を計算します`s`プレフィックス合計を使用します。 私たちはハッシュマップを維持します`freq[prefix_sum]`そして、位置ごとに、以前のプレフィックスの合計がどれだけ等しいかを計算します。`current_sum - s`。 

これにより、サブ配列の合計と合計が得られます`s`x が含まれるかどうかに関係なく。 

### 4. x を含まない部分配列を減算します。 

x のない部分配列は、x が出現するたびに切り取って作成される「< x のみ」セグメントの 1 つの内側に完全に存在する必要があります。 

したがって、これらの小さなセグメントを反復処理し、合計でサブ配列を再度カウントします。`s`同じプレフィックス合計方法を使用して、そのようなすべてのセグメントを合計します。 

### 5. 結果を結合する

 有効なセグメントごとに次のようになります。 

結果 += (すべての sum-s 部分配列の数) − (x を含まない sum-s 部分配列の数)

 ### なぜ効果があるのか

 このアルゴリズムは、検索スペースを互いに素なクラスに分割することに依存しています。 すべての要素 ≤ x である領域内のすべての部分配列には、x が完全に欠落しているか、少なくとも 1 つの x が含まれています。 これら 2 つのカテゴリは独立しており、あらゆる可能性をカバーしています。 プレフィックス合計法は、合計制約をプレフィックスの差の周波数一致に変換することにより、サブ配列を正確にカウントします。 各セグメントは独立して処理されるため、サブ配列が 2 回カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def count_sum(arr, target):
    freq = defaultdict(int)
    freq[0] = 1
    cur = 0
    res = 0
    for v in arr:
        cur += v
        res += freq[cur - target]
        freq[cur] += 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, s, x = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        i = 0

        while i < n:
            if a[i] > x:
                i += 1
                continue

            j = i
            while j < n and a[j] <= x:
                j += 1

            segment = a[i:j]

            total = count_sum(segment, s)

            # subtract subarrays that contain no x
            bad = 0
            k = 0
            while k < len(segment):
                if segment[k] == x:
                    k += 1
                    continue
                l = k
                tmp = []
                while k < len(segment) and segment[k] != x:
                    tmp.append(segment[k])
                    k += 1
                bad += count_sum(tmp, s)

            ans += total - bad
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、最大制約を満たすことができる有効な領域を分離します。 次に、プレフィックス頻度マップを使用して、必要な合計を持つすべてのサブ配列をカウントします。 その後、決して含まれないサブ配列を削除します。`x`以下の出現によって区切られたサブセグメントに対して同じカウントプロセスを再計算することにより、`x`。 

微妙な点は、カウント関数内の最大値を明示的にチェックしないことです。 最大制約は、直接計算されるのではなく、セグメンテーションによって構造的に強制され、サブ配列あたりの最大クエリ数が O(n) になることが回避されます。
