 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数が 10 進数形式で与えられ、任意の整数を選択できます。`x`それはそれらの間の包括的な範囲内にあります。 選ばれた人のために`x`、その桁をエンドポイントの桁と比較し、コストを割り当てます。`x`左の端点と一致する場合は 1 単位に寄与し、すべての位置が`x`正しいエンドポイントと一致すると、1 単位も寄与します。 目標は、`x`一致する位置の総数ができるだけ少なくなる範囲内にあります。 

重要な構造は、コストが完全に位置に依存し、桁間で独立しているということです。ただし、次の制約があります。`x`制限された間隔内にとどまる必要があります。 この制約は、独立した桁の決定を結合するものです。 

各数値は最大 9 桁であるため、可能な状態の範囲は十分に小さく、桁動的計画法が実行可能です。 すべての値に対する総当たりの列挙`x`せいぜい$10^9$テストケースごとに、これは大きすぎて最大で$10^4$テストケース。 

素朴だが誘惑しやすい間違いは、各桁を独立して扱うことです。つまり、可能な限り両方のエンドポイントとは異なる桁を選択することです。 ローカルで異なる数字を選択すると、範囲内に留まるというグローバル制約に違反する可能性があるため、これは失敗します。$[l, r]$。 もう 1 つのよくある間違ったアプローチは、厳密に間隔内に既に存在するかどうかを追跡せずに、桁ごとに貪欲に選択することです。 

より高い桁で間隔が狭い場合、微妙なエッジケースが現れます。 たとえば、次の場合`l = 199`そして`r = 201`、中間の数字を自由に選択できますが、接頭辞が次と等しくなってしまうと、`l`または`r`、後の決定は、状態でのみ処理できる方法で制約されます。 

## アプローチ

 ブルートフォースソリューションでは、すべての整数を反復処理します。`x`間`l`そして`r`、両方のエンドポイントとの桁ごとの一致を計算し、最小値を追跡します。 これは、すべての有効な候補を直接チェックするため、正しいです。 ただし、間隔は最大 10 億近くの値に及ぶ可能性があるため、1 万個のテスト ケースはおろか、1 つのテスト ケースでもこれは完全に実行不可能になります。 

重要な観察点は、コストは桁数のみに依存し、有効性制約はプレフィックス比較のみに依存するということです。 これはまさに数字動的計画法の問題の構造です。 それぞれの位置で数字を決めます`x`、ただし、プレフィックスがまだ次と等しいかどうかを追跡する必要があります。`l`、依然として等しい`r`、またはすでに開いた間隔内にあります。 

厳密に間隔内に移動すると、以降の桁数は制限されなくなります。 これにより、問題は境界状態のある位置にわたる小さな DP に変換され、遷移では現在のプレフィックス境界で許可されているすべての桁が考慮されます。 各選択肢は、対応する数字と一致するかどうかに応じてコストを追加します。`l`または`r`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((r - l) · d) | お(1) | 遅すぎる |
 | 桁DP | O(d · 10 · 4) | O(d · 4) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方の数値を同じ長さの文字列として扱います。 させて`n`桁数になります。 各州が私たちの位置を追跡し、下限と上限の制約がまだ一致しているかどうかを追跡する DP を構築します。 

1.変換`l`そして`r`数値配列に変換することで、各位置に直接アクセスできるようになります。 
2. DP 状態を定義する`dp[i][tightL][tightR]`、位置からの最小コストを表します`i`それまでのプレフィックスがまだ等しい場合、以降`l`もし`tightL = 1`、そして依然として等しい`r`もし`tightR = 1`。 制約が厳しくなくなった場合、対応する境界は無視されます。 
3. 各ポジションで`i`、許可される桁の範囲を決定します。 まだ厳しい場合は`l`、最小桁は`l[i]`、そうでない場合は、`0`。 まだ厳しい場合は`r`、最大桁は`r[i]`、そうでない場合は、`9`。 
4. すべての数字を試してください`d`この許容範囲内で。 それぞれの選択肢について、コスト寄与度を次のように計算します。`1`もし`d == l[i]`、プラス`1`もし`d == r[i]`。 
5. 次の状態に遷移します。 私たちが選んだなら`d == l[i]`、低い気密性は残ります。 そうしないと壊れます。 同様に、`d == r[i]`、上部の締め付けが残ります。 そうしないと壊れます。 
6. すべての選択肢から最小値を選択し、メモ化します。 

答えは`dp[0][1][1]`。 

### なぜ効果があるのか

 DP の不変条件は、すべての状態が、指定された厳密性制約と一致するすべてのプレフィックスの中で最適なソリューションを表すということです。 各遷移では、実現可能性を維持するすべての有効な数字が考慮されるため、有効な構築は行われません。`x`常に排除されます。 同時に、すべての無効なプレフィックスは、`l`そして`r`。 決定は現在の位置と緊密状態のみに依存するため、最適な下部構造が保持され、DP は冗長性なしで検索空間を完全にキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    l, r = input().split().strip()
    n = len(l)
    
    l = list(map(int, l))
    r = list(map(int, r))

    dp = [[[INF] * 2 for _ in range(2)] for _ in range(n + 1)]
    dp[n][0][0] = dp[n][0][1] = dp[n][1][0] = dp[n][1][1] = 0

    for i in range(n - 1, -1, -1):
        for tl in range(2):
            for tr in range(2):
                best = INF

                lo = l[i] if tl else 0
                hi = r[i] if tr else 9

                for d in range(lo, hi + 1):
                    cost = 0
                    if d == l[i]:
                        cost += 1
                    if d == r[i]:
                        cost += 1

                    ntl = tl and (d == l[i])
                    ntr = tr and (d == r[i])

                    best = min(best, cost + dp[i + 1][ntl][ntr])

                dp[i][tl][tr] = best

    return dp[0][1][1]

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP は、最後の桁から最初の桁に向かってボトムアップで構築されます。 各状態は、現在のプレフィックス制約と一致するすべての実行可能な数字を試行します。 タイトネス フラグは慎重に更新されます。数値が基準から外れるたびに更新されます。`l[i]`または`r[i]`、対応する制約は永続的に緩和されます。 

実装でよくある落とし穴は、厳しい制約を破ると元に戻せないことを忘れていることです。`ntl`そして`ntr`論理積を使用して計算されます。 もう 1 つの微妙な点は、緊密さが失われたときに境界を正しく処理することです。 これがないと、DP は後の位置の桁を誤って制限してしまいます。 

## 実用的な例

 ### 例 1:`l = 17`、`r = 19`桁ごとに評価します。 

| 私 | TL | tr | ローハイレンジ | 選択された d | 私にかかる費用 | 次のTL | 次のTR | DP |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1-1 | 1 | 2 | 1 | 0 | 1 |
 | 0 | 1 | 1 | 1-1 | 1 | 2 | 1 | 0 | 2 (最終集計) |

 ここで、ピッキング`x = 18`収量コスト`f(17,18)=1`、`f(18,19)=1`、 合計`2`、DP 出力と一致します。 

このトレースは、最初の位置に 1 桁の選択肢しか存在しないにもかかわらず、2 番目の桁に柔軟性が現れ、DP がそれを捕捉する様子を示しています。 

### 例 2:`l = 199`、`r = 201`最初の桁は、すべての有効な数字で始まる必要があります。`1`ので、締め付け感が持続します。 2 桁目では、選択に応じて間隔内で遷移できます。 

| 私 | TL | tr | ローハイレンジ | 選択された d | コスト | 次のTL | 次のTR |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1-2 | 2 | 0 | 0 | 0 |
 | 1 | 0 | 0 | 0-9 | 0 | 0 | 0 | 0 |
 | 2 | 0 | 0 | 0-9 | 0 | 0 | 0 | 0 |

 選択する`x = 200`すべての位置でゼロの一致が得られ、これが最適です。 DP は、両方の境界から最初に発散した後、完全に自由な状態に正しく移行します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t · n · 4 · 10) | 各テストは、状態ごとに最大 10 個の遷移で最大 9 桁にわたって桁 DP を実行します。 
| スペース | O(n · 4) | ポジションとタイトネス状態に関する DP テーブル |

 制約により、最大で$10^4$テスト ケースはありますが、それぞれの桁の長さが非常に小さいため、この DP は制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    INF = 10**18

    def solve_case(l, r):
        n = len(l)
        l = list(map(int, l))
        r = list(map(int, r))

        dp = [[[INF] * 2 for _ in range(2)] for _ in range(n + 1)]
        for tl in range(2):
            for tr in range(2):
                dp[n][tl][tr] = 0

        for i in range(n - 1, -1, -1):
            for tl in range(2):
                for tr in range(2):
                    best = INF
                    lo = l[i] if tl else 0
                    hi = r[i] if tr else 9
                    for d in range(lo, hi + 1):
                        cost = (d == l[i]) + (d == r[i])
                        ntl = tl and (d == l[i])
                        ntr = tr and (d == r[i])
                        best = min(best, cost + dp[i + 1][ntl][ntr])
                    dp[i][tl][tr] = best

        return dp[0][1][1]

    data = sys.stdin.read().strip().split()
    t = int(data[0])
    idx = 1
    out = []
    for _ in range(t):
        out.append(str(solve_case(data[idx], data[idx + 1])))
        idx += 2
    return "\n".join(out)

 ## 特殊なケース

 のために`l = r`、DP にはいかなる自由もありませんし、唯一有効なのは`x`同じ番号です。 すべての桁が両方のエンドポイントに一致するため、コストは単純に長さの 2 倍になります。 すべての状態で両方のタイト フラグがアクティブのままであり、パスが 1 つだけ存在するため、DP はこれを処理します。 

のようなケースの場合`l = 899`、`r = 999`、最初の数字は選択を大きく制限します。 DP は、数字のみが含まれることを保証します。`[8, 9]`位置 0 で考慮され、`9`これにより、下限制約が即座に破られ、後続の数字が一致を自由に最小化できるようになります。
