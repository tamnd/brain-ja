 ## 問題の理解

 正の整数が与えられます$K$。 数値のすべての 2 進数表現を調べます$N$、しかし、通常の最小限の形式ではありません。 代わりに、各数値は正確に記述されます。$K$先行ゼロを含むビット。 だから、すべての$N$長さの固定長バイナリ文字列に対応します。$K$。 

数字$N$と呼ばれます$K$-バイナリ反復の場合$K$-bit 文字列は、より短いバイナリ パターンの繰り返しとして表現できます。 言い換えれば、空ではないバイナリ文字列が存在します。$S$、長さより短い$K$を繰り返すように、$S$何度か正確に与える$K$-ビット表現の$N$。 

タスクは、クエリごとに次のとおりです。$K$、整数の数を数える$N$範囲内で$[0, 2^K - 1]$を生み出す$K$-この意味で周期的なビット表現、およびカウントモジュロを出力$10^9 + 7$。 

重要な点は、整数の意味での周期性を求めているのではなく、先頭のゼロを含む固定長のバイナリ文字列の周期性を求めていることです。 これは次のような文字列を意味します`0011`整数自体は通常は別の方法で記述される場合でも、繰り返しパターンの有効な候補です。 

制約は非常に重要です。 まであります$10^5$テストケースと$K$まで$10^6$したがって、それぞれを処理するソリューションはすべて$K$線形時間内で独立して行うことは不可能です。 平$O(K)$クエリごとに、$10^{11}$限界をはるかに超えた最悪の場合の操作。 これにより、事前計算または閉じた形式の組み合わせ観測が強制され、各クエリが次のように削減されます。$O(1)$。 

いくつかの特殊なケースで定義を明確にします。 

いつ$K = 1$、文字列は 2 つだけです。`0`そして`1`。 どちらも空ではない短い文字列を繰り返しても形成できないため、答えは次のようになります。$0$。 

いつ$K = 2$、文字列は`00`、`01`、`10`、`11`。 ここ`00`の繰り返しです`0`、 そして`11`の繰り返しです`1`, したがって、有効な数値は 2 つあります。 

よくある間違いは、先頭のゼロを無視して、「きれいな」整数表現のみを扱うことです。 それは次のようなケースを誤って拒否します`00`、これらは周期構造にとって重要です。 

もう 1 つの間違いは、繰り返し文字を含む文字列が有効であると想定していることです。 例えば`0101`有効ですが、`0110`両方に繰り返しビットが含まれている場合でも、最初のビットのみが全長を分割する一貫した周期を持つため、そうではありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。$K$-ビット文字列、可能なすべてのピリオドの長さを試します$d$それは分ける$K$。 各約数について$d < K$、長さのプレフィックスかどうかを確認します$d$繰り返された$K/d$回は完全な文字列を再構築します。 いずれかの除数が機能する場合、文字列がカウントされます。 

これが機能するのは、周期文字列が全長を正確に分割する適切な周期を持つ文字列であるためです。 ただし、これは壊滅的に高価です。 それぞれについて、$2^K$文字列、最大までチェックする可能性があります$O(K)$約数と実行$O(K)$比較、与える$O(K \cdot 2^K)$、非常に小さい場合でも実行不可能です$K$、ましてや、$10^6$。 

重要な点は、固定文字列を操作しているのではなく、長さの文字列の数を数えていることです。$K$定期的です。 これにより、問題は文字列ごとのチェックから組み合わせカウントの問題に変換されます。 

長さのバイナリ文字列$K$は最小期間によって完全に決定されます$p$そして修正したら$p$、文字列は最初の文字列を選択することによって決定されます。$p$ビットを繰り返します。 ただし、ピリオドを含む文字列を使用するとオーバーカウントが発生します。$p$のすべての倍数についてもカウントされます$p$。 これはまさに除数格子構造です。$K$。 

したがって、周期的な文字列を直接カウントする代わりに、すべての文字列をカウントし、「プリミティブ」な文字列、つまりそれ以下の周期を持たない文字列を減算します。 全文字列の数は$2^K$。 プリミティブ文字列の数は、次の約数に対するメビウス反転を使用して計算できます。$K$。 すべての約数のプリミティブ数がわかれば、周期的な数を効率的に導き出すことができます。 

これは、約数に対する標準の数理論的 DP につながります。$2^K$次に、包含排除を使用して、より小さい約数の寄与を減算します。

 ## アルゴリズムのチュートリアル

 1. 2 の累乗を最大まで事前計算します。$K$すべてのクエリにわたって、$2^K$長さのすべてのバイナリ文字列を表します$K$。 これにより、すべてのケースの塩基数が得られます。 
2. 各値について$K$、プリミティブな文字列を除外する前に、すべての文字列が有効な候補であるという考えを初期化します。 繰り返しの構造は約数にのみ依存します。$K$, そこで、約数の関係に焦点を当てます。 
3. 考えられるすべての約数を反復処理します。$d$それぞれの$K$昇順に、治療します$d$潜在的な期間の長さとして。 ピリオドを含む文字列$d$あるサイズのブロックを繰り返すことによって形成されます$d$、あります。$2^d$オーバーカウントを検討する前に、そのようなブロックを削除してください。 
4. すでにより基本的なパターンを表している小さな約数から寄与を差し引きます。 このステップにより、各周期構造がその最小周期で正確に 1 回カウントされることが保証されます。 減算は、除数格子に対する包含と除外の後に行われます。 
5. すべての約数のプリミティブ文字列の数を計算した後、全長のプリミティブ文字列の合計を引いたものとして周期文字列の数を導出します。 これにより、適切な繰り返し構造を持つ文字列が正確に分離されます。 
6. の各質問に答えます。$O(1)$事前に計算された配列を使用します。 

### なぜ効果があるのか

 毎$K$-bit 文字列には固有の最小ピリオドがあり、これは繰り返しによって生成される最小のプレフィックスです。 これにより、すべての文字列が最小期間で分割されます。 ピリオドが最小限の文字列であるため、総当たりカウントが重複します。$d$のあらゆる倍数とも互換性があります$d$、ただし、属性は 1 回だけにしてください。 メビウス反転は、より小さい約数からの寄与を体系的にキャンセルすることによってこの過大なカウントを修正し、各文字列が正確に 1 つの最小周期クラスに割り当てられるようにします。 これにより、最終的な減算ベースのカウントの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAX_K = 10**6

# precompute powers of 2
pow2 = [1] * (MAX_K + 1)
for i in range(1, MAX_K + 1):
    pow2[i] = (pow2[i - 1] * 2) % MOD

# mobius function via linear sieve
mu = [1] * (MAX_K + 1)
is_prime = [True] * (MAX_K + 1)
primes = []

for i in range(2, MAX_K + 1):
    if is_prime[i]:
        primes.append(i)
        mu[i] = -1
    for p in primes:
        if i * p > MAX_K:
            break
        is_prime[i * p] = False
        if i % p == 0:
            mu[i * p] = 0
            break
        else:
            mu[i * p] = -mu[i]

# precompute periodic counts using divisor sums
periodic = [0] * (MAX_K + 1)

for i in range(1, MAX_K + 1):
    # strings with period dividing i
    total = 0
    j = 1
    while j * j <= i:
        if i % j == 0:
            d1 = j
            d2 = i // j
            total = (total + mu[i // d1] * pow2[d1]) % MOD
            if d1 != d2:
                total = (total + mu[i // d2] * pow2[d2]) % MOD
        j += 1
    periodic[i] = (pow2[i] - total) % MOD

t = int(input())
for _ in range(t):
    k = int(input())
    print(periodic[k] % MOD)
```コードは問題を 2 つの概念的な層に分割します。 まず、すべてのバイナリ文字列がビットの自由な選択に対応するため、2 の累乗を事前計算します。 次に、メビウスベースの除数に対する包含-排他を使用して、プリミティブ文字列を分離します。プリミティブ文字列は、まさに小さなブロックの繰り返しによって形成されないものです。 最終的な答えは、合計スペースからプリミティブ数を差し引きます。 

よくある実装の落とし穴は、先頭のゼロが文字列スペースの一部であることを忘れることです。これが、すべてのカウントがオーバーする原因です。$2^K$、縮小表現の整数を超えない。 

もう 1 つの微妙な点は、除数の列挙を効率的に処理することです。 Möbius を事前計算すると、クエリごとに除数構造を再計算することが回避されます。そうしないとタイムアウトが発生します。$10^5$クエリ。
