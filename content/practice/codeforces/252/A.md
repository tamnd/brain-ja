 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられ、そのブロック内のすべてのビットごとの XOR をとったときに結果ができるだけ大きくなるように、要素の連続ブロックを選択したいと考えています。 タスクは、すべての可能なサブ配列に対して達成可能な最大の XOR を返すことです。 

入力サイズは小さく、要素数は最大 100 で、各値は 30 ビット以内に収まります。 これは、部分配列の総数がおよそ 5,000 で制限されており、プレフィックス XOR を前処理すれば各 XOR 計算を定数時間で実行できるため、3 次または 2 次の解であっても受け入れられることがすぐにわかります。 

セグメントに対する XOR の構造には、しばしば間違いを引き起こす微妙な特性が 1 つあります。XOR は単調ではないため、セグメントを拡張すると結果が予期せず増加または減少する可能性があります。 これにより、単一の最適なウィンドウを拡張しようとする貪欲な戦略が除外されます。 

よくある誤った試みは、実行ウィンドウを維持し、エンドポイントを貪欲に調整することです。 たとえば、次のような配列では、`[1, 2, 3, 0]`、貪欲な拡張機能が選択する可能性があります`[1, 2] = 3`、次に追加します`3`与える`0`、見た目が悪くなり、時期尚早に破棄される可能性があります。 しかし、その後のセグメントは次のようになります`[2, 3] = 1`または`[1, 2, 3] = 0`局所的な決定は全体的な最適性を反映していないことを示しています。 

もう 1 つの落とし穴は、各セグメントの XOR を最初から O(n) 時間で再計算し、O(n^3) の動作が発生することです。 n = 100 の場合でも技術的には問題ありませんが、これは不必要であり、より単純な構造が隠蔽されます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。エンドポイントのすべてのペア (l、r) を試し、そのセグメントの XOR を計算し、最大値を追跡します。 O(n^2) 個のセグメントがあり、各 XOR 計算は単純に実行すると O(n) で実行でき、O(n^3) になります。 これは n が小さいため機能しますが、作業の繰り返しが多くなります。 

重要な点は、プレフィックス XOR を使用してセグメント上の XOR を O(1) で計算できることです。 prefix[i] をインデックス 0 から i までの要素の XOR として定義すると、セグメント [l, r] の XOR は単純に prefix[r] XOR prefix[l - 1] になります。 これにより、内部計算コストが削減され、冗長性が排除されます。 

これが利用可能になると、すべてのサブ配列をそれぞれ O(1) で評価し、スキャン全体を O(n^2) にすることができます。 n ≤ 100 の場合、これで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各セグメントを再計算) | O(n^3) | お(1) | 受け入れられるが非効率的 |
 | プレフィックス XOR + 列挙 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置に、そのインデックスまでのすべての要素の XOR が格納されるプレフィックス XOR 配列を構築します。 これにより、定数時間のセグメント クエリが可能になります。 
2. セグメントの可能なすべての左端点を反復処理します。 各インデックスは部分配列の開始候補になります。 
3. 開始インデックスごとに、配列の開始点から終了点までのすべての可能な右端点を反復処理します。 これにより、すべての連続セグメントが 1 回だけ列挙されます。 
4. 各ペア (l、r) について、プレフィックス値を使用してセグメントの XOR を計算します。 これにより、XOR を最初から再計算することがなくなり、各評価が O(1) に保たれます。 
5. これまでに確認された最大 XOR を追跡する変数を維持し、各セグメントの評価後に更新します。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての連続セグメントを 1 回だけ評価し、プレフィックス XOR が共有プレフィックスをキャンセルするという ID を使用して XOR を正しく計算します。 XOR は結合的で自己反転であるため、プレフィックスのキャンセルによりセグメント抽出の正確さが保証されます。 すべてのセグメントがチェックされるため、検出された最大値はグローバル最大値である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    prefix = [0] * n
    prefix[0] = a[0]
    for i in range(1, n):
        prefix[i] = prefix[i - 1] ^ a[i]

    ans = 0

    for l in range(n):
        for r in range(l, n):
            if l == 0:
                cur = prefix[r]
            else:
                cur = prefix[r] ^ prefix[l - 1]
            if cur > ans:
                ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、セグメント クエリが定数時間操作になるように、プレフィックス XOR 値を構築することから始まります。 ネストされたループは、考えられるすべてのセグメントを列挙します。 内部の条件付き分岐は、減算するプレフィックスがないため、セグメントがインデックス 0 から始まる境界ケースを処理します。 

比較`cur > ans`すべての値が負ではない整数であるため安全です。`ans = 0`可能な最小限の答えを正確に取得します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    prefix = [0] * n
    prefix[0] = a[0]
    for i in range(1, n):
        prefix[i] = prefix[i - 1] ^ a[i]

    ans = 0
    for l in range(n):
        for r in range(l, n):
            cur = prefix[r] if l == 0 else (prefix[r] ^ prefix[l - 1])
            ans = max(ans, cur)
    return str(ans)

# provided sample
assert run("5\n1 2 1 1 2\n") == "3"

# custom cases
assert run("1\n0\n") == "0", "single zero"
assert run("2\n5 5\n") == "5", "equal elements XOR cancels"
assert run("3\n1 2 4\n") == "7", "full range best"
assert run("4\n8 1 2 3\n") == "11", "mixed bits"

 ## 特殊なケース

 次のような単一要素配列の場合`[0]`、プレフィックス配列は`[0]`、評価される唯一のセグメントは`(0, 0)`、XOR を生成します`0`。 アルゴリズムは正しく返します`0`特別な取り扱いを必要とせずに。 

同一の要素が繰り返される場合、次のようになります。`[5, 5]`、プレフィックス値は次のようになります`[5, 0]`。 セグメント`[0, 1]`収量`5 XOR 5 = 0`、一方、単一要素セグメントは`5`。 このアルゴリズムは、最適な選択が任意の単一要素であることを正確に識別します。 

次のような交互パターンの場合`[1, 2, 3]`、プレフィックス値は次のとおりです。`[1, 3, 0]`。 セグメント`[0, 2]`収量`0`、 その間`[0, 1]`収量`3`そして`[1, 2]`収量`1`。 アルゴリズムはすべての候補を正しく探索し、選択します`3`、最適なセグメントが必ずしも最長であるとは限らないことを示しています。
