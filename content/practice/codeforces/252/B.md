 ## 解決策
 ## 問題の理解

 長さ _n_ の整数の配列が与えられ、結果の配列がソートされなくなるように、異なる位置で 2 つの要素を交換できるかどうかを判断するように求められます。 ここでの並べ替えは広範に定義されており、配列が非減少または非増加の場合に並べ替えられます。 たとえ位置が異なっていても、同じ要素を交換することはできないため、可能であれば交換を実行する必要があります。 

入力制約は 1 ≤ _n_ ≤ 10^5 で、配列要素は最大 10^9 です。 _n_ が 100,000 になる可能性があり、制限が 2 秒である場合、O(n^2) の解には 10^10 の演算が必要となり、これでは遅すぎます。 これは、線形または線形に近いアプローチが必要であることを意味します。 メモリは 256 MB とたっぷりあるため、サイズ _n_ の補助配列をいくつか保存することが可能です。 

ここではエッジケースが重要です。 単一要素の配列は、スワップによってソートを解除できないことは明らかです。 すべての要素が等しい配列も、等しい要素を交換できないため、ソートを解除することはできません。 厳密に増加または減少し、すべての一意の要素を含む配列は交換可能ですが、末尾に値が繰り返される単調な配列では、個別の値を慎重に選択する必要があります。 

## アプローチ

 ブルートフォースアプローチは、個別のインデックスのすべてのペアを反復処理し、要素が等しくない場合は交換を試み、結果の配列がソートされていないかを確認することです。 これは正しいですが、最悪の場合は O(n^2) となり、n = 10^5 では完了しません。 ブルート フォースはすべてのオプションを体系的にテストするため機能しますが、ペアの組み合わせが急増するため、大規模な配列では失敗します。 

最適なアプローチは、ソートされた配列を破壊するには、別の要素と異なる最初の要素を交換するだけでよいという観察を活用します。 配列が厳密に増加している場合、最初の要素を後続の小さい要素と交換すると、順序が崩れます。 同様に、厳密に減少する場合は、最初の要素をより大きな後の要素と交換すると機能します。 これにより、問題は、要素が異なる 2 つのインデックスの線形スキャン (O(n)) に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の長さが 1 であるかどうかを確認します。配列の長さが 1 である場合、単一要素の配列はスワップによってソートを解除できないため、-1 を出力します。 
2. 配列を最初の要素から最後から 2 番目の要素まで繰り返します。 異なる 2 つの連続する要素を見つけた場合は、それらのインデックスを記録します。 これら 2 つの位置を交換すると、ソートされていない配列が生成されることが保証されています。これは、ソートされた配列内の 2 つの異なる要素を交換すると、増加または減少のプロパティが壊れるためです。 
3. 線形スキャン中にそのようなペアが見つからない場合は、すべての要素が等しいことになります。 この場合、等しい要素の交換は許可されないため、-1 が出力されます。 
4. 見つかった最初のペアのインデックスを出力します。 

機能する理由: ソートされた配列では、2 つの異なる要素には相対的な順序があります。 2 つの異なる要素を交換すると、少なくとも 1 つの位置でその順序に違反します。 リニア スキャンにより、最初のそのようなペアがすぐに見つかることが保証されます。 ペアが存在しない場合、すべての要素は等しいため、交換はできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

if n == 1:
    print(-1)
else:
    found = False
    for i in range(n - 1):
        if a[i] != a[i + 1]:
            print(i + 1, i + 2)
            found = True
            break
    if not found:
        print(-1)
```このソリューションは、高速入力を使用して配列のサイズと要素を読み取ります。 些細な単一要素のケースを即座に処理します。 等しくない隣接要素のペアは単調性を破る有効なスワップを保証するため、線形スキャンは隣接要素をチェックします。 出力で 1 から始まるインデックスを使用すると、問題の要件が満たされます。 旗`found`すべての要素が等しい場合に、-1 が正しく出力されるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 2 つの異なる要素を見つけるために配列を 1 回線形スキャンします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    if n == 1:
        return "-1"
    for i in range(n - 1):
        if a[i] != a[i + 1]:
            return f"{i+1} {i+2}"
    return "-1"

assert run("1\n1\n") == "-1", "sample 1"
assert run("4\n1 2 3 4\n") == "1 2", "sample 2"
assert run("3\n5 5 5\n") == "-1", "all equal elements"
assert run("2\n10 20\n") == "1 2", "minimum size distinct"
assert run("5\n1 3 3 3 1\n") == "1 2", "distinct at start"
assert run("6\n2 2 2 3 3 3\n") == "3 4", "distinct in middle"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 ## 特殊なケース

 次のような単一要素配列の場合`1\n1`の場合、解決策はすぐに -1 を返し、不可能な場合を正しく処理します。 すべての要素が等しい配列の場合、次のようになります。`3\n5 5 5`の場合、線形スキャンでは明確な隣接要素が検出されず、解は正しく -1 を出力します。 厳密に増加または減少する配列の場合、最初の不等隣接ペアが選択され、これにより、交換後に配列がソートされなくなることが保証されます。 このアルゴリズムは、配列を 1 回通過するだけで済み、O(n) 時間と O(1) 空間を維持するため、最大許容サイズの配列を正しく処理します。
