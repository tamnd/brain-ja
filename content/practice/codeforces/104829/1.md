 ## 問題の理解

 バスケットボールの試合で獲得された合計ポイント数が与えられ、成功したすべての得点アクションが 1、2、または 3 ポイントのいずれかに貢献します。 実際のショットのシーケンスは不明で、最終的な合計のみが重要です。 タスクは、正確にこの合計を生成できる可能な最小数のスコアリング アクションを再構築することです。 

したがって、入力は単一の整数 n であり、両チームが合計して蓄積した合計スコアを表します。 出力は、各項が 1、2、または 3 である n の分解における項の最小数です。言い換えれば、集合 {1, 2, 3} からの可能な最小の整数の合計として n を表現しようとしています。 

制約 0 ≤ n ≤ 1000 により、これは非常に小さな状態空間になります。 O(n²) から O(1) までの任意の解は簡単に十分ですが、すべての分解に対する指数関数的検索や総当たり検索は不要になります。 

最も微妙なエッジ ケースは、n の値が小さい場合に現れます。 n = 0 の場合、得点アクションは存在しないため、答えは 0 でなければなりません。n が 1 または 2 の場合、それぞれ 1 つまたは 2 つ未満のショットで表すことができないため、答えは数値そのものと一致します。 もう 1 つの少し単純ではないケースは n = 3 です。この場合、1 つの 3 ポイント ショットは 3 つの 1 ポイント ショット、または 1 つの 2 ポイントと 1 つの 1 ポイント ショットよりも厳密に優れています。 

n の構成をすべて 1、2、3 に列挙しようとする素朴なアプローチは、制約内で機能しますが、すぐに冗長で非効率になります。 問題の構造は貪欲な分解を示唆しています。これは、カウントの最小化という点で、より高い値のショットが常に低い値のショットよりも優勢であるためです。 

## アプローチ

 ブルートフォース戦略では、合計が n になる 1、2、および 3 のすべてのシーケンスを探索し、有効なシーケンスの中で最小の長さを追跡しようとします。 これは本質的に、{1, 2, 3} の部分を持つ n の順序付けされた構成をすべて生成することです。 各ステップで最大 3 つの可能性に分岐し、最悪の場合は 3^n に似た再発が発生します。 枝刈りを行ったとしても、状態の数は非常に急速に増加するため、n が 1000 までの場合、これは実行不可能になります。 

重要な点は、シーケンスを数えたり構築したりすることは求められておらず、要素の数を最小限に抑えることだけを求められているということです。 1ポイントシュート3本を3ポイントシュート1本に置き換えるたびに、合計は変えずにシュート数を減らしていきます。 同様に、2 つの 1 ポイント ショットを 1 つの 2 ポイント ショットに置き換えることでもカウントが減ります。 これは、よりスコアの高いショットが常に好ましいことを示唆しています。 

項の数を最小限に抑えるために、できるだけ多くの 3 ポイント ショットを使用し、残りを 2 ポイント ショットで最適に処理し、最後に必要に応じて 1 ポイント ショットを使用します。 これにより、問題は n を 3 で単純に除算し、剰余は慎重に処理するという単純な問題に帰着します。 

これが機能するのは、3 が許容最大値であり、より小さな値の組み合わせをより大きな値に置き換えても項の数が増加することがないためです。 したがって、最適な構造は、できるだけ多くの 3 を取得し、次に 2 を取得し、次に 1 を取得することになります。

 ## アルゴリズムのチュートリアル

1. 整数除算を使用して、n から 3 ポイント ショットを何本取れるかを計算します。 これにより、残りの合計を最も効率的に減らす高価値アクションの最大数が得られます。 
2. 3 点の寄与をすべて削除した後の剰余を計算します。 整数 mod 3 がその範囲内にあるため、この剰余は 0 ～ 2 の範囲になります。 
3. 余りが 0 の場合、追加のショットは必要ありません。 分解は 3 ポイント ショットのみを使用してすでに最適化されています。 
4. 余りが 1 または 2 の場合、1 は 1 つの 1 ポイント ショットとして表現でき、2 は 1 つの 2 ポイント ショットとして表現できるため、正確に 1 つの追加ショットに寄与します。 これらをさらに分割してもメリットはありません。 
5. 最終的な答えは、3 ポイント ショットの数に、残りがゼロでない場合は追加の 1 ショットを加えた数になります。 

機能する理由: このアルゴリズムは、より小さなスコアリング アクションのグループを 1 つのより高いスコアリング アクションに置き換えることで用語の数が厳密に削減されるという事実に基づいています。 3 が最大許容値であるため、その使用量を最大化すると加数の数が全体的に最小化されます。 すべての 3 を貪欲に使用すると、残りの値は厳密に 3 未満になるため、ゼロでない場合は単一の項以外の組み合わせによってさらに改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n == 0:
    print(0)
else:
    print((n + 2) // 3)
```この実装は、3 ポイント ショットの数が n // 3 であるという観測に基づいています。剰余処理は式 (n + 2) // 3 に暗黙的にエンコードされており、n が 3 で割り切れない場合は常に正しく切り上げられます。これにより、最適な構造をキャプチャしながら剰余での明示的な分岐が回避されます。 

特殊なケース n = 0 は、正確性を保証するために明示的に処理されます。この場合、数式も 0 を返しますが、条件付きにより推論が明示的かつ拡張に対して堅牢になるためです。

 ## 特殊なケース

 n = 0 の場合、分解する点がないため、アルゴリズムは直接 0 を返します。 式 (n + 2) // 3 も 0 と評価され、予想される出力と一致します。 

n = 1 の場合、3 で割った余りが 1 つあります。計算により (1 + 2) // 3 = 1 が得られ、これは 1 つの 1 ポイント ショットに対応します。これは、より大きな得点アクションでは表現できないため最適です。 

n = 2 の場合、この式では (2 + 2) // 3 = 1 も得られます。 これは、最小の分解である 1 つの 2 ポイント ショットに相当します。 

n = 1000 の場合、除算により 333 のフル 3 ポイント ショットが得られ、余りは 1 になります。アルゴリズムは 334 を返します。これは、333 のスリー ショットと 1 つのシングル ポイント ショットを意味します。 3 ポイント ショットを 2+1 または 1+1+1 に置き換えようとすると、アクションの数が減少するのではなく増加するため、これは最適な構造と一致します。
