 ## 問題の理解

 長方形の合板が 2 枚与えられました。 これらは、一方の長方形が水平、もう一方の長方形が垂直になり、直角に交差するように配置する必要があります。 結果として得られる図形は適切な十字でなければなりません。 これは、オーバーラップが両方の長方形の内側に厳密に存在する必要があることを意味し、4 つのアームのそれぞれが交差部分を超えて正の距離だけ伸びます。 

最終的な図形の面積は、2 つの長方形を合わせたものになります。 長方形領域を追加する際には重なりが 2 回カウントされるため、交差条件を満たしながら重なりをできるだけ小さくすることが目的です。 有効なクロスを生成できる配置がない場合、答えは次のとおりです。`0`。 

各辺の長さは最大で`1000`したがって、高度な最適化は必要ありません。 唯一の本当の困難は、長方形のどの辺が水平の腕の長さの役割を果たし、どの辺が垂直の腕の長さの役割を果たすかを特定することです。 すべての長方形は 90 度回転することができ、可能な向きは一定数のみとなります。 

最もよくある間違いは、すべての腕が厳密に正の長さでなければならないことを忘れていることです。 たとえば、入力の場合```
2 2 2 2
```正しい答えは```
4
```重なりは正確に一致する必要があります`1 × 1`、産地`4 + 4 - 1 = 7`。 重なり部分が長方形の全幅または全高になるように不用意に実装すると、無効な配置が誤って受け入れられてしまいます。 

もう 1 つの簡単な間違いは、すべての長方形のペアが十字を形成できると仮定することです。 考慮する```
1 2 5 7
```小さい辺が次の長方形`1`オーバーラップには少なくとも幅が必要であるため、オーバーラップの後の両側に正の拡張子を付けることはできません。`1`。 正しい答えは、```
0
```3 番目の微妙なケースは、回転によって答えが変わるときに発生します。 例えば、```
3 5 4 2
```方向を 1 つ選択するだけで、最適な領域が得られます。 回転を無視すると、正しい最大値が失われます。 

## アプローチ

 直接幾何学的検索では、2 つの長方形を移動可能なオブジェクトとして扱い、一方をもう一方の上にスライドさせ、考えられるすべての重なりを計算し、交差条件が当てはまるかどうかをテストします。 すべての有効な配置が最終的に検査されるため、このような方法は正しいです。 残念ながら、座標が整数値に制限されている場合でも、辺の長さが次の値に達すると、相対位置はおよそ 100 万通りになります。`1000`、すべての方向もチェックする必要があります。 位置が連続していると、検索の実用性がさらに低くなります。 

何が領域を決定するのかを観察すると、ジオメトリははるかに単純になります。 和合面積は以下に等しい$$A_1 + A_2 - \text{overlap}.$$長方形の領域は固定されているため、結合領域を最大化することは、重なりを最小化することとまったく同じです。 

有効な交差の場合、重なり部分の幅と高さは正の値でなければなりません。 横長の長方形に高さを持たせる`h`、縦の長方形には幅があります`w`。 オーバーラップは強制的に正確に行われます`w × h`。 これ以上大きくしても結合面積は減少するだけです。 その結果、オーバーラップが両方の長方形の内側に厳密に収まる場合、可能な限り最小のオーバーラップがすぐに得られます。 

横長の長方形に次元があると仮定します。`(L, h)`縦の長方形には寸法があります`(w, H)`。 適切なクロスはまさに次のようなときに存在します。$$L > w \quad\text{and}\quad H > h.$$これらの不等式により、交差点の両側での正の拡張が保証されます。 

すべての長方形には可能な方向が 2 つしかないため、調べる必要がある方向のペアは 4 つだけです。 それぞれが個別にチェックされ、最適な有効領域が維持されます。

 ## アルゴリズムのチュートリアル

 1. 最初の長方形の 2 つの可能な方向を生成します。`(a, b)`そして`(b, a)`ここで、最初の値は水平方向の長さを表し、2 番目の値は高さを表します。 
2. 2 番目の長方形の 2 つの可能な方向を生成します。`(c, d)`そして`(d, c)`ここで、最初の値は垂直方向の長方形の幅を表し、2 番目の値はその高さを表します。 
3. 方向のペアごとに、横の長方形が縦の長方形の幅より広いかどうか、および縦の長方形が横の長方形の高さより高いかどうかを確認します。 

これらの厳密な不等式は、まさに 4 つのアームすべてが正の長さであるという要件です。 
4. 方向が有効な場合、和合面積を次のように計算します。$$L \cdot h + w \cdot H - w \cdot h.$$最後の項は重複領域です。 
5. 4 つの向きのペアすべてにわたって最大の有効領域を維持します。 
6. 4 つの構成のいずれも有効でない場合は、次のように出力されます。`0`。 

### なぜ効果があるのか

 固定方向の場合、有効な配置はすべて、少なくとも縦方向の長方形の幅以上のオーバーラップ幅と、少なくとも横方向の長方形の高さ以上のオーバーラップ高さを持ちます。 どちらかの寸法を大きくすると、オーバーラップが拡大し、結合領域が減少するだけです。 したがって、その方向に対する最適な配置では、常に最小限のオーバーラップが使用されます。`w × h`。 

残りの問題は、この最小限の重複が実現可能かどうかです。 両方の長方形の内側に厳密に収まる場合に正確に実行可能です。これは次と同等です。`L > w`そして`H > h`。 あらゆる向きが検査されるため、アルゴリズムはあらゆる可能な幾何学的構成を考慮し、達成可能な最大の結合領域を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c, d = map(int, input().split())

ans = 0

first = [(a, b), (b, a)]
second = [(c, d), (d, c)]

for L, h in first:
    for w, H in second:
        if L > w and H > h:
            area = L * h + w * H - w * h
            ans = max(ans, area)

print(ans)
```プログラムはまず、各長方形の両方の回転を列挙します。 各方向は一貫して解釈され、最初の長方形は水平バーとして機能し、2 番目の長方形は垂直バーとして機能します。 

面積を計算する前に、2 つの厳密な不等式がチェックされます。 使用する`>`の代わりに`>=`は不可欠です。 等しいということは、一方の腕の長さがゼロであることを意味し、十字の定義に違反します。 

面積式は包含排除原則を直接適用します。 すべての値は最大であるため、`1000`、可能な最大の領域は`2,000,000`、これは Python の整数に簡単に適合します。 

方向のペアは 4 つだけ存在するため、実装では一定量の作業が実行されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    a, b, c, d = map(int, input().split())

    ans = 0
    first = [(a, b), (b, a)]
    second = [(c, d), (d, c)]

    for L, h in first:
        for w, H in second:
            if L > w and H > h:
                ans = max(ans, L * h + w * H - w * h)

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# provided samples
assert run("3 5 4 2\n") == "17", "sample 1"
assert run("1 2 5 7\n") == "0", "sample 2"

# custom cases
assert run("1 1 1 1\n") == "0", "minimum sizes"
assert run("2 2 2 2\n") == "4", "strict inequality boundary"
assert run("1000 1000 1000 1000\n") == "1000000", "maximum sizes"
assert run("6 3 2 8\n") == "36", "rotation required"
```| テスト入力 | 期待される出力 | 検証内容 |
