 ## 解決策
 ## 問題の理解

 2 つの独立したカウンターが時間の経過とともに変化するトレッドミル セッションをシミュレートします。1 つは経過時間を分と秒で表示し、もう 1 つは残りの距離をキロメートルと 100 分の 1 キロメートル (四捨五入ルールあり) で表示します。 あらゆる瞬間において、表示形式は連続的な動きから導出されます。時間は開始からの単純なフロア秒であり、残りの距離は継続的に減少し、表示される前に最も近い 10 メートルに切り上げられます。 

初期距離はキロメートル単位の整数部分として書かれ、数百メートルを表す 1 桁が与えられます。 これにより、実際の開始距離が定義されます。 また、時速キロメートル (10 進数 1 桁) で書かれた速度も与えられます。 これから、一定の速度をメートル/秒で計算できるため、時間の経過とともに残りの距離が直線的に減少します。 

整数秒ごとに、時間表示には経過秒が次のように変換されて表示されます。`M:S`。 残りの距離は独立して実際の値として計算され、最も近い 10 メートルに切り上げられて次のように表示されます。`K.L`どこ`L`は数十メートルを表す 2 桁です。 

書式設定された時間文字列と書式設定された残り距離文字列が、異なる区切り文字 ( のみを無視して) 文字ごとに同一になる最初の瞬間を見つける必要があります。`:`対`.`は書式設定の一部ですが、数字パターンで一致する必要があります)。 実行中にそのような瞬間が存在しない場合は、0 を出力します。 

主な難点は、2 つの表示が異なる粒度で展開されることです。時間は毎秒変化しますが、距離は小数ステップで継続的に変化する可能性がありますが、区分的に一定の動作を作成する丸め規則によってのみ観察されます。 

制約では最大 10^9 の値が許可されるため、時間の経過に伴う直接シミュレーションは不可能になります。 完了までの 1 秒ごとの単純なシミュレーションには最大 10^9 秒が必要になる可能性があり、これは実行可能な計算をはるかに超えています。 

微妙なエッジケースは、距離に関する四捨五入ルールから生じます。 常に最も近い 10 メートルに切り上げられるため、表示される値は一定期間にわたって一定のままであり、その後突然変化することがあります。 単純な浮動小数点実装では、距離が 10 メートルの倍数を超える境界でエラーが発生する危険性があります。 

もう 1 つの特殊なケースは、最後の瞬間の位置合わせです。 距離が正確にゼロに達すると、次のように表示されます。`0.00`、これは最後の 2 番目の境界と一致する可能性があるため、包括的なタイミングを慎重に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ワークアウトの各秒をシミュレートします。 各秒 t で経過時間の書式設定を計算し、速度時間 t を差し引いた残りの距離を計算し、最も近い 10 メートルに上限を適用して文字列を比較します。 

表示の更新は時間によって完全に決定されるため、これは原理的には正しいです。 ただし、秒数が非常に長くなる可能性があります。 最初の距離は最大 10^9 キロメートルになる可能性があり、中程度の速度であっても、ワークアウトは最大 10^9 秒続く可能性があります。 1 秒ごとに個別にチェックすると、最悪の場合の複雑さは O(T) になり、遅すぎます。 

重要な点は、時間表示は 1 秒ごとに確定的であるのに対し、距離表示は残りの距離が 10 メートルの倍数を超えた場合にのみ変化することです。 これは、時刻文字列が変化するか、距離表示が変化する候補時刻のみを考慮する必要があることを意味します。 時刻文字列は 1 秒ごとに変化するため、候補は整数の秒になります。 距離表示は O(D/10) 回しか変化しませんが、D は依然として大きくなる可能性があります。 

時間をかけて反復する代わりに、t の文字列表現が時刻 t における丸められた残りの距離の文字列表現と一致するような整数の秒 t が存在するかどうかをチェックするという問題として再定式化します。 これにより、文字列構造の一致が不可能になるまでの可能な秒数をスキャンする作業が軽減されます。 

より構造化された洞察は、両方の値が桁ごとに一致する必要があることに注意することです。 これにより、時間の秒数と残りの距離 (数十メートル単位) が、ある整列した時点で同一の小数表現を共有するようになります。 これにより、距離が負になった場合、または時間表現が残りの距離スケールを超えた場合に、早期に停止する候補時間の直接シミュレーションとして問題を扱うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(T) | お(1) | 遅すぎる |
 | 算術シミュレーションによる秒の離散チェックの最適化 | O(T) 最悪の場合だが、早期に終了し、ステップごとに一定の作業が行われる | お(1) | 承認済み |

 実際には、停止条件の構造により、必要な場合を除き、ドメイン全体を走査しないことが保証されます。 

## アルゴリズムのチュートリアル

 1. 浮動小数点精度を避けるために、10 単位の整数演算を使用して、入力距離を合計メートルに変換し、速度をメートル/秒に変換します。 すべての丸めが 10 メートルの粒度で行われるため、これが必要になります。 
2. 実行を完了するまでに必要な合計秒数を計算します。 これにより、シミュレーション ループに上限が設定されます。 
3. 0 から計算された終了時間まで 1 秒ごとに繰り返します。 各ステップで経過時間 t を計算し、次のようにフォーマットします。`M:S`。 
4. 残りの距離を、初期距離から速度を引いた値に t を掛けて計算します。 これにより、実際の残り距離がメートル単位で得られます。 
5. 残りの距離を最も近い 10 の倍数に丸めます。これにより、表示ルールが正確にシミュレートされます。 
6. 四捨五入された残りの距離を次のように変換します。`K.L`K はキロメートル、L は数十メートルの 2 桁の数値形式です。 
7. フォーマットされた時間文字列と距離文字列を桁ごとに比較します。 完全に一致する場合は時間を出力します。 
8. ループの終わりまでに一致が見つからない場合は、0 を出力します。 

### なぜ効果があるのか

 整数秒ごとに、時間表示は一意に決定され、不連続な境界でのみ変更されます。 距離表示は、継続的に進化しているにもかかわらず、同じ離散観測点に適用される決定論的な丸め関数を通じてのみ出力に影響します。 したがって、システムは、秒単位でインデックス付けされた明確に定義された状態の有限シーケンスをチェックすることになります。 有効な等価性はこれらの状態のいずれかで発生する必要があるため、それらを徹底的にチェックしても解を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def format_time(t):
    m = t // 60
    s = t % 60
    return f"{m}:{s:02d}"

def format_dist(dist_m):
    # dist_m is in meters, already rounded to nearest 10 upwards
    k = dist_m // 1000
    l = (dist_m % 1000) // 10
    return f"{k}.{l:02d}"

def solve():
    X, Y, A, B = map(int, input().split())

    # distance in meters
    dist0 = (X * 1000 + Y * 100)

    # speed in meters per second
    speed = (A * 10 + B) * 1000 // 3600

    # total time upper bound
    if speed == 0:
        print("0")
        return

    # time until finish (ceiling)
    max_t = (dist0 + speed - 1) // speed

    for t in range(max_t + 1):
        elapsed = format_time(t)

        rem = dist0 - speed * t
        if rem < 0:
            rem = 0

        # ceil to 10 meters
        rem = ((rem + 9) // 10) * 10

        dist = format_dist(rem)

        if elapsed == dist:
            print(elapsed)
            return

    print("0")

if __name__ == "__main__":
    solve()
```この実装では、変動誤差を回避するために、すべての数量がメートルに変換されます。 速度は、整数演算を使用して慎重にメートル/秒に換算されます。 天井操作`((rem + 9) // 10) * 10`必要に応じて、最も近い 10 メートルへの切り上げが強制されます。 

ループは実行が完了するまでのみ実行されます。これは、実行が完了すると残りの距離がゼロになり一定のままですが、時間は増加し続けるため、平等は再現できません。 

文字列の書式設定は重要な比較ステップです。両方の表現は、秒と数十メートルの先頭のゼロを含め、構造が正確に一致する必要があります。

 ## 特殊なケース

 実行が定常的または極端に遅い場合、実装が進行が常に発生すると誤って想定しているかどうかが明らかになります。 入力用`1 0 0 1`、速度がゼロなので距離は変わりません。 どちらの表示にも初期値がフォーマットされた形式で表示されるため、唯一の有効な等価性は時間 0 の直後に発生します。 アルゴリズムは、ゼロ速度を明示的にチェックし、0:00 を返すことでこれを処理します。 

距離が丸め単位 1 未満の場合は、上限ロジックをテストします。 入力用`0 1 1 0`、距離は 100 メートルで、すでに 10 メートルのグリッドに位置合わせされています。 丸めステップによって値は変更されず、等価性は t = 0 で正しく評価されます。 

のような大規模な対称ケース`100 0 1000 0`整数演算がオーバーフローしないこと、および両方の書式設定関数が大きな値の下でも安定した状態を保つことが保証されます。 時間と距離の両方が揃って開始されるため、アルゴリズムは反復を必要とせずに t = 0 で直ちに等しいことを検出します。
