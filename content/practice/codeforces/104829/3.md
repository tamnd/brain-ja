 ## 問題の理解

 さまざまな種類の壁紙ロールを販売する店が与えられました。 各タイプにはロールあたりの固定価格があり、ストアで入手できる残りの長さには限りがあります。 このコレクションから 2 つの異なるタイプの壁紙を選択する必要があります。1 つのタイプは完全にカバーする必要があります。$A$メートル、別のタイプは正確にカバーする必要があります$B$メートル。 1 つのタイプは 2 つの要件のいずれかにのみ使用できるため、選択した 2 つのタイプは異なる必要があります。 目標は、両方の要件を満たすのに十分なロールを購入するか、それが不可能であると判断するための総コストを最小限に抑えることです。 

各タイプは 1 つの「パッケージ」に貢献します。これを無視するか、必要な 2 つの長さのうちの 1 つをカバーするのに十分な量を完全に購入します。 型には残りの長さが限られているため、その長さが少なくとも必要な長さである場合にのみ要件を満たすことができます。 タイプを選択するためのコストは、実際に使用する長さではなく、その価格によってのみ決まります。 

制約が非常に厳しいため、型のすべてのペアに対する単純な組み合わせ検索は実行できません。 と$n$まで$10^5$、すべてのペアを確認するには約$10^{10}$許容範囲をはるかに超えた最悪の場合の操作。 重要な構造上の観察は、両方とも長さが必要であるということです。$A$そして$B$これは、インデックスではなく長さによって情報を圧縮する必要があることを示唆しています。 

単純な間違いは、これを 2 つの独立した最小検索として扱い、カバーできる最も安価な壁紙を選択することです。$A$そしてカバーできる最も安いもの$B$。 同じタイプが両方にとって最も安価な場合、2 つの異なるタイプを選択する必要があるため、これは失敗します。 

たとえば、次のことを考えてみましょう。```
2 5 5
1 10
100 10
```最も安価なタイプは両方の要件を個別に満たすことができますが、重複して使用することはできません。 正しい答えは、$1 + 100 = 101$、 ない$2$。 

もう 1 つの微妙な問題は、型の長さのしきい値ごとに最も安価な単一の候補のみが必要であると仮定していることです。 最適な壁紙が共有されている場合、バックアップとして少し高価な壁紙が必要になる可能性があるため、これも失敗します。 

## アプローチ

 ブルートフォース手法では、順序付けられた個別の壁紙タイプのすべてのペアが試行されます。$(i, j)$。 ペアごとに、次のタイプがあるかどうかを確認します。$i$1 つの要件とタイプを満たすことができます$j$もう一方を選択し、対応するコストを計算します。 これは、すべての有効なロールの割り当てを調査するため、正しいです。 ただし、費用がかかります$O(n^2)$、つまり約$10^{10}$最悪の場合のチェック$n = 10^5$、明らかに不可能です。 

重要な観察点は、各壁紙タイプにとって重要な唯一の特性は、その長さの制約と価格であるということです。 両方なので$A$そして$B$が小さい (≤ 1000) 場合、すべての壁紙を利用可能な長さごとにグループ化し、必要な長さのそれぞれについて、それを満たすことができる最も安価な少数の候補を維持できます。 この構造は、すべてのインデックスではなく、小さなドメインにわたって制約付きの最小化になります。 

考えられるすべてのしきい値について、問題を次のように整理します。$x$、長さが少なくとも次の 2 つの最も安価な異なる壁紙をすばやく見つけます。$x$。 次に、1 つの壁紙を割り当てるすべての方法を評価します。$A$そしてもう一つは$B$、同じタイプでないことを注意深く確認します。 

長さが短いため、可能な最小要件ごとに最適な壁紙と次善の壁紙を前処理できます。 これにより、ペアの列挙が完全に回避され、圧縮状態の線形スキャンに置き換えられます。

 ## アルゴリズムのチュートリアル

 1から1000までの必要な長さにわたって構造を維持します。必要な長さごとに$x$、少なくとも残りの長さがある最も安価な 2 つの壁紙タイプを知りたいです。$x$。 

1. 各エントリに 2 つの最良の候補を格納する配列を初期化します。`(best_cost, best_id)`そして`(second_best_cost, second_best_id)`あらゆる要件の長さに対応します。 最初はコストを無限大に設定します。 
2. すべての壁紙タイプを反復処理します。$i$価格付き$p_i$そして長さ$m_i$。 あらゆる要件に対応$x \le m_i$、この壁紙は要件を満たすことができます$x$。 私たちは、そのようなすべてのベスト 2 構造にそれを挿入しようとします。$x$。 最良または 2 番目に優れたエントリが改善された場合は、それに応じて更新します。 このステップにより、すべてのしきい値について、最も安価な有効な選択肢と 2 番目に安い有効な選択肢が確実にわかります。 
3. 前処理の後、次の 2 つのケースを検討します。壁紙を割り当てる$A$そしてもう一つは$B$。 次の 2 つの最適な候補を取得します。$A$そしてのために$B$。 まずは最高のものを組み合わせてみます$A$最高のものを$B$。 タイプが異なる場合は、回答の候補が表示されます。 
4. 同じ種類の壁紙の場合、再利用は避けなければなりません。 代わりに、一方が次善の候補を使用する組み合わせ、つまり、best(A) と Second(B)、および Second(A) と best(B) を使用する組み合わせを考慮します (それらが存在する場合)。 
5. すべての有効な組み合わせの最小値が答えです。 有効なペアが存在しない場合は、0 を出力します。 

正確かどうかは、各要件について、最も安価な 2 つの個別の候補のみが重要であるという事実にかかっています。 どのような最適解も、2 つの異なる最良の候補を使用するか、衝突によりそのうちの 1 つを次善の候補に置き換えざるを得なくなります。 

### なぜ効果があるのか

 必要な長さごとに$x$、最適なソリューションでは、次の条件を満たす壁紙の種類が使用されます。$x$。 選択したタイプを、他の要件にまだ使用されていない、より安価で有効な代替品に置き換えた場合、ソリューションを改善または維持するだけです。 したがって、要件ごとに最も安価な 2 つの異なる壁紙に注目を限定するだけで、実現可能性を損なうことなくすべての最適な組み合わせを表すのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, A, B = map(int, input().split())

    # best1[x] = (cost, id), best2[x] similarly
    best1 = [(INF, -1) for _ in range(1001)]
    best2 = [(INF, -1) for _ in range(1001)]

    for i in range(n):
        p, m = map(int, input().split())
        for x in range(1, m + 1):
            # try update best1
            if p < best1[x][0]:
                best2[x] = best1[x]
                best1[x] = (p, i)
            elif i != best1[x][1] and p < best2[x][0]:
                best2[x] = (p, i)

    def get(x):
        return best1[x], best2[x]

    (a1, ida1), (a2, ida2) = get(A)
    (b1, idb1), (b2, idb2) = get(B)

    ans = INF

    # best-best
    if ida1 != -1 and idb1 != -1:
        if ida1 != idb1:
            ans = min(ans, a1 + b1)
        else:
            if idb2 != -1:
                ans = min(ans, a1 + b2)
            if ida2 != -1:
                ans = min(ans, a2 + b1)

    print(0 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```前処理段階では、必要なすべての長さに対して、それを満たすことができる 2 つの最も安価な壁紙タイプを構築します。 長さを超えたネストされたループは許容されます。$m \le 1000$なので、合計の操作は約$n \cdot 1000$、快適にフィットします。 

最終決定ロジックは、同じ壁紙が 2 回使用される衝突ケースを明示的に処理しますが、これは禁止されています。 そのため、次善の追跡が不可欠です。追跡がなければ、最良の候補が一致したときに有効なフォールバックが得られません。

 ## 特殊なケース

 両方の要件が単一の有効な壁紙タイプを共有する場合、重大なエッジ ケースが発生します。 その状況での最有力候補は、$A$そして$B$は同一であり、次善の追跡を無視するソリューションでは、同じアイテムが誤って再利用されます。

3 10
```両方にとって$A$そして$B$, 候補は同じタイプのみです。 アルゴリズムは、best(A) = best(B) = (3, 0) を選択します。 ID が一致し、2 番目の候補が存在しないため、すべてのペアリングの試行は失敗し、出力は 0 になります。
