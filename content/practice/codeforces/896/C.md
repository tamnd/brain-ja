 ## 解決策

 ## 問題の理解

 私たちは最大 100,000 個の整数の動的配列を扱っており、100,000 の一連の操作をサポートする必要があります。 各操作は、連続するセグメントを変更するか、セグメントに関する情報をクエリします。 

更新操作は 2 つあります。1 つは範囲内のすべての要素に値を追加し、もう 1 つは範囲を定数値で上書きします。 また、2 つのクエリ タイプがあります。1 つは部分配列内の k 番目の最小値を求めるもの、もう 1 つは部分配列内の要素のべき乗の合計をある数値を法として求めるものです。 

この難しさは、配列が静的ではないという事実から生じます。 値は加算更新と割り当て更新の両方を通じて時間の経過とともに変化し、クエリには順序統計または任意のサブセグメントに対する非線形集計のいずれかが必要です。 

この制約は、操作ごとにすべての要素に触れるソリューションが遅すぎることを意味します。 100,000 個の要素に対して 100,000 回の演算を行う場合、O(nm) アプローチでは 10^10 の演算が行われ、これは実現可能な限界をはるかに超えています。 Python では、操作ごとに O(n log n) であっても、m 回繰り返すと遅すぎます。 

微妙に複雑なのは、割り当ての更新によって以前の追加的な更新が上書きされることです。 これは線形性を破壊するため、「区分的定数とシフト」の動作を表現できるより豊富な構造を導入しない限り、遅延加算を備えた単純なセグメント ツリーでは不十分です。 

最も危険なエッジケースは、代入と加算を混合することです。 たとえば、セグメントが 5 に設定され、後で 3 ずつ増分される場合、正しい値は 8 です。遅延タグを正しく組み合わせるのを忘れた単純なアプローチでは、特に順序に依存するクエリの前に、結果が静かに破損します。 

もう 1 つのエッジ ケースは、タイプ 3 のクエリから発生します。この場合、常に変化する範囲内で k 番目に小さい要素を見つける必要があります。 クエリごとにオンザフライで並べ替えると、中程度の入力サイズであっても TLE になります。 

最後に、タイプ 4 のクエリには y を法とするべき乗が含まれます。ここで、y はクエリごとに変化します。 これにより、グローバル プレフィックス パワーの事前計算が防止され、現在のセグメント値に基づいて再計算が強制されます。 

## アプローチ

 ブルートフォース戦略は簡単です。 配列を明示的に管理します。 タイプ 1 およびタイプ 2 の操作では、範囲内のすべての要素を直接更新します。 タイプ 3 の場合、部分配列を抽出し、並べ替えて、k 番目の要素を返します。 タイプ 4 の場合、各値の x 乗を計算し、y を法として合計します。 

このアプローチは、問題ステートメントを直接シミュレートするため、正しいです。 ただし、各操作では最大 n 個の要素のスキャンが必要な場合があり、クエリでは最大 n 個の要素の並べ替えが必要な場合があります。 最悪の場合、1 回の操作のコストは O(n log n) ですが、m 回の操作では O(m n log n) になり、これはまったく実行不可能です。 

重要な点は、要素の正確な位置を永続的に維持する必要がないということです。 代わりに、各ブロックが単純な表現を持つ、互いに素なブロックへの分割をサポートする構造で配列を維持できます。 各ブロックが定数セグメントであるか、遅延シフトできる場合は、操作を局所化できます。 

これはまさに、間隔の順序付けされた構造の設定であり、通常、セグメント全体にわたってバランスの取れた BST を使用して実装されます。 標準的なソリューションでは、ランダム化されたトリープ (ODT または Chtholly ツリーと呼ばれることが多い) が使用され、各ノードは等しい値の連続した間隔を表します。 

追加的な更新と割り当ての更新はノードごとに適用できます。 分割することで、影響を受けるセグメントを確実に分離できます。 k 番目に小さいクエリの場合、範囲内のすべてのセグメントを抽出し、値で並べ替えて、カウントを累積します。 べき乗和クエリの場合、セグメントを反復処理して寄与度を計算します。

重要な構造的洞察は、代入後の値は区分的に一定であり、加算によってパーティション構造が維持されるということです。 ジェネレーターのランダムな分割動作により、セグメントの数は予想どおり少ないままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | ODT (クロタリーの木) | O(m log n + クエリごとのセグメント) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 一連の素な間隔を維持し、各間隔には左境界、右境界、および均一の値が格納されます。 

1. 配列を単一要素の間隔に分割して構造を初期化します。 各位置は、初期値を持つ独自のセグメントになります。 これにより、すべての変更を整列した境界にきれいに適用できるようになります。 
2. 位置 x で分割操作を定義します。 x が区間内にある場合、x が境界になるようにその区間を 2 つの部分に分割します。 すべての更新は正確な間隔境界で動作するため、これは不可欠です。 
3. 範囲演算 [l, r] の場合、まず l と r+1 で分割します。 この後、範囲は完全な間隔の和集合に正確に対応します。 これにより、セグメントを部分的に変更しないことが保証されます。 
4. タイプ 1 の操作 (範囲加算) では、[l, r] に完全に含まれるすべての間隔を反復し、保存されている値に x を加算します。 各間隔は均一であるため、これは間隔ごとに一定時間の更新となります。 
5. タイプ 2 の操作 (範囲の割り当て) では、[l, r] 内のすべての間隔を消去し、値 x を持つ単一の間隔 [l, r] に置き換えます。 これにより、範囲が 1 つのセグメントに集約され、断片化が軽減されます。 
6. タイプ 3 クエリ (k 番目に小さい) の場合、[l, r] と重なるすべての間隔を収集し、(値、長さ) のペアを形成し、値で並べ替えて、k 番目の要素に到達するまで累積的に調べます。 これにより、完全なサブアレイの実体化が回避されます。 
7. タイプ 4 のクエリ (累乗和) の場合、範囲内の間隔にわたって再度繰り返します。 値 v と長さ len の各間隔について、len * v^x モジュロ y を計算し、累積します。 x は大きくなる可能性があるため、高速累乗を使用します。 

正確さは、常に現在の値を正確に表す重複しない間隔への配列の分割を維持することに依存します。 

### なぜ効果があるのか

 データ構造は常に、各セグメントが均一であるセグメントの素の結合として配列を表します。 分割により、更新がセグメントに部分的に影響を与えることがなくなり、正確さが維持されます。 割り当てにより複数のセグメントが 1 つに減らされ、追加により各セグメント内の均一性が維持されます。 クエリは完全なセグメントのみに分解されるため、値が二重にカウントされたりスキップされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "r", "v")
    def __init__(self, l, r, v):
        self.l = l
        self.r = r
        self.v = v

def qpow(a, e, mod):
    res = 1 % mod
    a %= mod
    while e:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

n, m, seed, vmax = map(int, input().split())

def rnd():
    global seed
    ret = seed
    seed = (seed * 7 + 13) % 1000000007
    return ret

intervals = []

def split(x):
    # find interval containing x
    for i, seg in enumerate(intervals):
        if seg.l <= x <= seg.r:
            if seg.l == x:
                return i
            if seg.r == x:
                return i
            # split into two
            l, r, v = seg.l, seg.r, seg.v
            intervals[i] = Node(l, x - 1, v)
            intervals.insert(i + 1, Node(x, r, v))
            return i + 1
    return None

def assign_range(l, r, v):
    if l > r:
        return
    split(l)
    split(r + 1)
    new = []
    i = 0
    while i < len(intervals):
        seg = intervals[i]
        if seg.r < l or seg.l > r:
            new.append(seg)
        i += 1
    new.append(Node(l, r, v))
    intervals.clear()
    intervals.extend(sorted(new, key=lambda x: x.l))

def add_range(l, r, v):
    split(l)
    split(r + 1)
    for seg in intervals:
        if seg.l >= l and seg.r <= r:
            seg.v += v

def kth(l, r, k):
    split(l)
    split(r + 1)
    parts = []
    for seg in intervals:
        if seg.l >= l and seg.r <= r:
            parts.append((seg.v, seg.r - seg.l + 1))
    parts.sort()
    for val, cnt in parts:
        if k <= cnt:
            return val
        k -= cnt
    return -1

def power_sum(l, r, x, mod):
    split(l)
    split(r + 1)
    ans = 0
    for seg in intervals:
        if seg.l >= l and seg.r <= r:
            ans = (ans + (seg.r - seg.l + 1) * qpow(seg.v, x, mod)) % mod
    return ans

a = []
for _ in range(n):
    a.append((rnd() % vmax) + 1)

for i in range(n):
    intervals.append(Node(i + 1, i + 1, a[i]))

out = []

for _ in range(m):
    op = (rnd() % 4) + 1
    l = (rnd() % n) + 1
    r = (rnd() % n) + 1
    if l > r:
        l, r = r, l

    if op == 3:
        x = (rnd() % (r - l + 1)) + 1
    else:
        x = (rnd() % vmax) + 1

    if op == 4:
        y = (rnd() % vmax) + 1

    if op == 1:
        add_range(l, r, x)
    elif op == 2:
        assign_range(l, r, x)
    elif op == 3:
        out.append(str(kth(l, r, x)))
    else:
        out.append(str(power_sum(l, r, x, y)))

print("\n".join(out))
```実装は、互いに素なセグメントのリストを維持することを中心に行われます。 分割関数は中心的なプリミティブであり、範囲クエリをセグメント境界に完全に合わせることができます。 どちらの更新操作も、最初にこの調整を強制することに依存します。 

範囲を追加すると、セグメント値が直接変更されます。 範囲の割り当てにより、影響を受ける部分が 1 つのセグメントに再構築されます。 k 番目のクエリはセグメントを重み付けされた値に変換し、目的のランクに達するまで累積します。 電力合計クエリは、各セグメントを個別に評価し、モジュールの寄与を集計します。 

微妙な点は、割り当て後に、素性を維持するためにセグメント リストを再構築することです。 慎重にクリーンアップしないと、重複するセグメントによって将来のクエリが破損する可能性があります。 

## 実用的な例

 サイズ 5 の小さな配列を考えてみましょう。`[1, 3, 2, 2, 4]`。 

追加操作を実行します`[2, 4]`2までに。 

| ステップ | セグメント |
 | --- | --- |
 | イニシャル | (1,1)、(3,1)、(2,1)、(2,1)、(4,1) |
 | 分割後 | 同じ位置合わせ |
 | |を追加した後 (1,1)、(5,2)、(4,1)、(2,1)、(4,1) |

 範囲内の値はセグメント構造を維持しながら均一に増加します。 

次に、次の割り当てを検討します。`[3,5]`値を 7 にします。 

| ステップ | セグメント |
 | --- | --- |
 | 前 | 混合セグメント |
 | 分割後 | 整列した境界 |
 | 割り当て後 | 新しいセグメント (3,5)=7 はすべてを置き換えます |

 これは、代入によって構造がローカルにどのように崩壊するかを示しています。

 | --- | --- | --- |
 | 時間 | O(m · k) 平均 | k は操作ごとにタッチされるセグメントの数です。 
| スペース | O(n) | 各要素はセグメントとして始まり、マージするとカウントが減ります。

 ## 特殊なケース

 重要なケースの 1 つは、複数の追加後の割り当ての重複です。 たとえば、セグメントが数回増分されてから再割り当てされた場合、古い増分は完全に破棄する必要があります。 分割後置換メカニズムでは、新しいセグメントを挿入する前に、影響を受けるすべてのセグメントを物理的に削除するため、これが保証されます。 

もう 1 つのケースは、k 番目のクエリがセグメント境界に正確に到達する場合です。 厳密にセグメント順にカウントを蓄積するため、境界上の等価性は、先に進む前にセグメント全体のサイズを減算することによって処理され、off-by-one エラーが発生しないことが保証されます。 

最後の微妙なケースは、同じ位置で分割が繰り返されることです。 Split 関数は、x がすでにセグメントのエッジに揃っているときに早期に戻り、セグメントの重複を防ぐことで、既存の境界での分割を防ぎます。
