 ## 問題の理解

 私たちは、映画館のレジ係が小銭を切らさず、全員にサービスを提供した後、残りの 50 元札の枚数が一定の間隔内に収まるように、客の列をどのように配置できるかを数えています。 

各顧客は独立して 3 つのタイプのいずれかに属します。 1種類は50元札で、おつりが1単位増えます。 1 種類は 100 元札を持参しますが、支払い時に事前に収集した 50 元札を 1 枚消費し、その時点で 50 元札が利用可能な場合にのみ有効です。 最後のタイプは VIP です。これは、お釣りを与えたり消費したりせず、実現可能性に影響を与えることなくどこにでも表示できます。 

このプロセスは順番に行われます。顧客の順序が重要であり、列の各先頭で 100 元の顧客の数が、これまでに出現した 50 元の顧客の数を超えることはできません。 n 人の顧客全員を処理した後、50 元紙幣の最終余剰額を計算し、この最終値が [l, r] にある取り決めのみをカウントします。 

制約により、これはシミュレーションではなく組み合わせ計数方式に押し込まれます。 n が 100000 までの場合、順列を列挙したり、すべてのシーケンスにわたる完全な状態を追跡したりするアプローチは不可能です。 答えは、構造化パスに関する閉じた形式のカウント引数、またはプレフィックス実現可能性制約のある多項式スタイルの集計から得られる必要があります。 

微妙なエッジケースは、実現可能性と最終的なバランスの間の相互作用から生じます。 たとえば、プレフィックスの有効性を無視すると、「B B A」(100, 100, 50) のようなシーケンスは、最初から無効であるにもかかわらず、最初の顧客にサービスを提供できないため、誤ってカウントされる可能性があります。 もう 1 つのエッジ ケースは VIP 顧客から生じます。これらはバランスには影響しませんが、注文の多重度には影響します。また、早期に顧客を崩壊させるアプローチは組み合わせ要素を失うリスクがあります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべての 3^n シーケンスが生成され、それぞれのレジプロセスがシミュレートされます。 各シーケンスについて、50 元の顧客で増加し、100 元の顧客で減少する残高カウンタを追跡し、残高がマイナスになるシーケンスを拒否します。 終了後、最終的なバランスが[l, r]にあるかどうかを確認します。 これは正しいですが、3^n の可能性を探索しており、枝刈りを行っても n は指数関数的なままであるため、非常に小さい入力を超えると実行不可能になります。 

重要な構造的観察は、VIP 顧客は中立であるということです。彼らは実現可能性に影響を与えず、配置にのみ影響します。 これは、問題を 2 つの層に分離することを示唆しています。 まず、VIP のポジションを選択し、投票問題と同等のプレフィックス制約を使用して、A (50 元) と B (100 元) のみからなる残りのポジションに対して有効なシーケンスをカウントします。 最終的なバランスは A と B のカウントの差のみに依存しますが、VIP は組み合わせでアレンジメントを掛け合わせます。 

A シーケンスと B シーケンスに分解すると、実現可能条件は、すべてのプレフィックスで A カウントが少なくとも B カウントであるという古典的な条件とまったく同じになります。 これは Dyck パスのバリアントです。 固定数の A と B を持つ有効なシーケンスの数は、カタルーニャ語スタイルの投票式によって与えられます。 次に、VIP を n 個の位置に分配し、[l, r] の最終的なバランスと一致するすべての可能なカウントを合計します。 

最終的な解は、有効な (a、b、c) の二重合計になります。ここで、a + b + c = n、c は VIP の数、最終バランスは a - b ですが、有効な A/B プレフィックスは、リフレクション原理から導出された組み合わせ係数を使用してカウントされます。

 ## アルゴリズムのチュートリアル

 このプロセスを、50 元の顧客の数と 100 元の顧客の数という 2 つの意味のある数量の観点から再解釈します。 VIP 顧客は、置換多重度を高める区切り文字としてのみ機能しますが、妥当性制約には影響しません。 

### 1. Fix counts of A, B, and C

 a (50 元の顧客の数)、b (100 元の顧客の数)、および c = n − a − b (VIP 顧客) の考えられる値を反復します。 このような各トリプルの最終的なバランスは a − b です。 これは [l, r] 内に存在する必要があります。そうでない場合、構成はゼロを寄与します。 

これが機能する理由は、順序付けの制約が A と B の相対的なプレフィックス数のみに依存し、C が不活性であるためです。 

### 2. プレフィックス制約を使用して有効な A/B シーケンスをカウントする

 固定の a と b については、すべてのプレフィックスで A カウントが少なくとも B カウントになるように、a 個の A と b 個の B のシーケンスをカウントします。 This is a standard ballot number:$$\text{valid}(a,b) = \frac{a-b+1}{a+1} \binom{a+b}{a}
\quad \text{for } a \ge b$$a < b の場合、実現可能性は直ちに失敗するため、値はゼロになります。 

この式は、対角線を横切る無効なパスを反映することで得られます。 

### 3. VIP 顧客を挿入する

 A/B スケルトンが固定されたら、c 個の同一のニュートラル要素を n 個の位置に挿入します。 これは、C の位置を選択するのと同じです。$$\binom{n}{c}$$### 4. 貢献を結合する

 有効なトリプルごとに次を乗算します。 

有効(A/B構造) × VIP配置方法

 そしてモジュロpを累積します。 

### なぜ効果があるのか

 核となる不変条件は、実現可能性制約が A と B のプレフィックスのみに依存し、中立要素の挿入による影響を受けないことです。 C をどのように配置しても、A と B の相対的な順序は維持されるため、すべての有効なインターリーブは、有効なスケルトンと挿入位置の選択に一意に対応します。 この全単射により、過大カウントまたは過少カウントが発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def modinv(a, mod):
    return pow(a, mod - 2, mod)

def solve():
    n, mod, l, r = map(int, input().split())

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % mod

    invfact = [1] * (n + 1)
    invfact[n] = modinv(fact[n], mod)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % mod

    def C(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % mod * invfact[n - k] % mod

    ans = 0

    for a in range(n + 1):
        for b in range(a + 1):
            c = n - a - b
            if c < 0:
                continue

            balance = a - b
            if balance < l or balance > r:
                continue

            # ballot number: valid A/B sequences
            if a == 0:
                ways_ab = 1 if b == 0 else 0
            else:
                ways_ab = (a - b + 1) * C(a + b, a) % mod * modinv(a + 1, mod) % mod

            ways_c = C(n, c)
            ans = (ans + ways_ab * ways_c) % mod

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、モジュラー演算で二項係数をサポートするために階乗と逆階乗を事前計算することから始まります。 機能`C`O(1) の組み合わせを計算します。 

次に、A と B の実行可能な数をすべて列挙します。ペアごとに、残っている VIP の数を計算します。 バランス チェックは無効な状態を早期に削除します。そうしないと二重ループが不必要なべき乗剰余演算を行うことになるため、これは不可欠です。 

投票式は、(a + 1) の逆モジュールを使用して直接実装されます。 特殊なケース a = 0 により、割り算の問題が回避され、50 元紙幣が存在しない場合でも正確さが保証されます。 

最後に、すべてのポジションに VIP 顧客を配置する方法の数を掛けて、結果を累積します。 

よくある落とし穴は、投票式でプレフィックスの有効性がすでに強制されているため、追加のシミュレーションが必要ないことを忘れていることです。

 ## 特殊なケース

 エッジケースの 1 つは、100 元の顧客がいない場合です。 その場合、投票の制約はなくなり、A と C のすべての順序が有効になります。 b = 0 の場合、投票式は 1 に減少し、残りのカウントは純粋に組み合わせ配置になるため、アルゴリズムはこれを処理します。 

b > a の場合、別のエッジ ケースが発生します。 投票式は自動的にゼロを返します。これにより、一部のプレフィックスで変更が不十分である無効な州が正しく除外されます。 

3 番目の微妙なケースは、すべての顧客が VIP である場合です。 したがって、a = b = 0、c = n となります。 空の A/B シーケンスは 1 つだけであるため、このアルゴリズムでは構造が 1 つだけカウントされ、C が同一として扱われると、すべての順列が 1 つの構成にまとめられます。
