 ## 問題の理解

 の列を維持しています。`n`ポジション、それぞれ最初は空です。 時間が経つにつれて、私たちは一連のメッセージを受け取ります。`m`numbers. 各番号が到着したら、すぐにそれを次のいずれかに割り当てる必要があります。`n`位置が変更され、以前に存在していたものが上書きされる可能性があります。 目標は、プロセス中のある時点で、すべての`n`位置が埋められ、結果の配列は左から右に減少しません。 

これは一発で構築できる問題ではありません。 配列をオンラインで構築していますが、有効な完全に入力されたソート構成が表示されるとすぐにプロセスが停止するという追加の制約があります。 その瞬間以降は、インタラクションは即座に終了するため、それ以上の決定は問題になりません。 

制約構造が鍵となります。`n`そして`m`は大きくなる可能性があるため (典型的な CF インタラクティブ境界)、各ステップの後にグローバル構造を再計算する戦略は遅すぎます。 すべてを繰り返しチェックするソリューション`n`移動ごとのポジションは次のように動作します`O(nm)`両方とも大きい場合は生き残れません。 

微妙な失敗例は、構造のない貪欲な配置によって発生します。 たとえば、各数値を常に左端の可能なスロットに配置したり、任意に上書きしたりすると、有効な順序が存在するにもかかわらずそれを破棄してしまう状況を簡単に作り出すことができます。 上書きが許可されているため、初期の不適切な配置により配列が一時的にソートされる可能性がありますが、壊れやすくなり、次の更新時に壊れます。 

もう 1 つの危険は、早期終了ロジックです。 インタラクションの問題では、成功後に読み取りを続けると未定義の動作が発生します。 たとえば、次の場合`n = 2`そして私たちはすでに到達しています`[1, 3]`ラウンド 3 の後にラウンド 4 の入力を読み取ると、論理的には無害であってもプロトコルが破損します。 

## アプローチ

 強引な考え方では、各ステップで考えられるすべての選択肢をシミュレートすることになります。 値を受け取った後、それをそれぞれの`n`を配置し、将来のシーケンスがソートされた完全な配列につながるかどうかを再帰的に調査します。 これはすぐに指数関数的になります。`m`ステップは次のように分岐します`n`選択肢、与えること`O(n^m)`州。 部分的な順序付けに基づいて枝刈りを行っても、依然として扱いにくい検索スペースが残ります。 

状態を圧縮する方法が必要です。 重要な観察は、常に正確な配置には関心がなく、最終的にソートされた完了に達することだけを気にしているということです。 これは、部分解を非減少の完全な配列に拡張する機能を保持する構造を維持する必要があることを示唆しています。 

重要な洞察は、「可能な限り最良のプレフィックス」構造を維持する方法で配列を常に維持することです。 任意の配置について考える代わりに、各位置が現在の値を持つシステムとして配列を扱い、柔軟性を維持したいと考えています。小さい値は左に留まり、大きい値は右にドリフトする必要があります。 これはまさに、ローカル違反を常に修復する貪欲な配置戦略によって強制される動作です。 

対話型の構築的な問題でこれを実現する標準的な方法は、配列を維持し、各挿入後に違反を外側に押し出すことによって順序をローカルに修復することです。 値はステップごとに 1 つの位置でのみ変化するため、移動ごとに導入される乱れは限定されており、決定論的に修正できます。 

最適なソリューションでは、グローバルに検索するのではなく、各操作を最小限の妨害でソートされた構造を保存または復元する位置を選択するだけで済みます。

 ## アルゴリズムのチュートリアル

 配列を維持します`a[1..n]`、最初は空です。 

1. すべての位置を空として初期化し、概念的には非常に大きなセンチネル値または「設定解除」を意味する特別なマーカーとして処理します。 これにより、チェックごとに特別なケースを使用せずに比較を推論することができます。 
2. 受信値ごとに`x`、配置する位置をスキャンします。`x`注文への混乱が最小限に抑えられます。 自然なターゲットは、スロットが空であるか、またはスロットが空である左端の位置です。`a[i] <= x`潜在的な非減少構造を維持しながら。 
3. 複数の位置が有効な場合は、ソート順序を維持する可能性を侵害しない最も古い位置が優先されます。 この設定では、より小さい値をできるだけ左に保持するため、より大きな値に対する将来の柔軟性が維持されます。 
4. 場所`x`選択した位置に移動し、以前の値を上書きします。 
5. 挿入後、ローカル修正を実行します。`a[i] > a[i+1]`更新の影響を受ける隣接ペアについては、既に一貫した構造を他の場所で変更することなく、非減少特性が可能な限り復元されるように、値を交換または再配置します。 
6. 各ラウンドの後、すべてのポジションが埋まっており、配列が減少していないかどうかを確認します。 その場合、現在位置を出力し、直ちに終了します。 

### なぜ効果があるのか

 中心的な不変条件は、すべての操作の後、表示される値のすべての可能な配置の中で、アルゴリズムが完全な非減少配列に拡張できる少なくとも 1 つの有効な部分構成を保存することです。 貪欲な選択では、単一の新しい値を挿入することによって発生するローカルな競合のみが解決されるため、すべての有効な補完が削除されることはありません。また、常に、小さい値をできるだけ左に、大きい値をできるだけ右に保つことで、順序付けの実現可能性を維持する方法で値が配置されます。 最終条件は純粋にグローバルな順序付けであるため、完全に満たされた状態が表示された後、それがすでにソートされている必要があることを保証するには、各ステップの後にローカルの一貫性を維持するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, c = map(int, input().split())
a = [None] * n
filled = 0

for _ in range(m):
    x = int(input())

    pos = -1

    for i in range(n):
        if a[i] is None:
            pos = i
            break
        if a[i] <= x:
            pos = i

    if pos == -1:
        pos = n - 1

    if a[pos] is None:
        filled += 1
    a[pos] = x

    i = pos
    if i > 0 and a[i - 1] is not None and a[i] is not None and a[i - 1] > a[i]:
        a[i - 1], a[i] = a[i], a[i - 1]
        i -= 1

    i = pos
    if i + 1 < n and a[i] is not None and a[i + 1] is not None and a[i] > a[i + 1]:
        a[i], a[i + 1] = a[i + 1], a[i]

    if filled == n:
        ok = True
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                ok = False
                break
        if ok:
            print(pos + 1)
            sys.stdout.flush()
            break

    print(pos + 1)
    sys.stdout.flush()
```The implementation keeps an explicit array and updates it online. The position selection logic is a greedy scan that tries to place the current value in the rightmost compatible position among existing values, or the first empty slot if possible. This ensures smaller values tend to stay left, which is the structural requirement for eventual sorting.

 After placement, only local adjacent corrections are attempted, because only neighboring inversions can be created by a single overwrite. This keeps updates cheap compared to full re-sorting.

 The termination check is performed immediately after filling all slots, ensuring we stop interaction correctly as soon as the condition is satisfied.

 ## 特殊なケース

 重要なエッジケースは、値が厳密に降順で到着する場合です。 そのような状況では、単純に左端に配置すると有用な構造が常に上書きされ、収束が妨げられます。 互換性のある右端への貪欲な配置により、小さい値が早期に左にプッシュされるため、最終的な構成は依然としてソート可能になります。 

別の特殊なケースは、同じ値が繰り返されることです。 等しい値の順列はすべて有効であるため、アルゴリズムは位置を慎重に区別する必要がなく、比較では等値が安全な配置として扱われるため、安定性が自動的に維持されます。 

最後のエッジケースは、早期に完了することです。 アルゴリズムは、配列が最初に完全に埋められ、ソートされたときに直ちに停止する必要があります。 さらに入力の読み取りを続けると、内部状態がすでに正しい場合でも、対話プロトコルが中断されてしまいます。
