 ## 解決策
 ## 問題の理解

 私たちは一連の演習を与えられます。 各エクササイズについて、ボブには 3 つの選択肢があります。スキップする、簡単なバージョンを実行する、または激しいバージョンを実行するです。 各選択肢のエネルギーコストは 0 です。$a_i$、 または$b_i$それぞれ、$a_i < b_i$。 

ボブは総エネルギー予算を持っています$x$、合計エネルギーが次を超えないように、エクササイズごとに 1 つのオプションを選択する必要があります。$x$。 

すべての有効な計画の中から、選択は 3 つの基準によって辞書編集的に判断されます。 まず、エネルギー制限を超えないようにする必要があり、すべての有効な計画の中で、スキップされる演習の数を最小限に抑えたいと考えています。 スキップの最小数を修正した後、選択される激しいバージョンの数を最大化したいと考えています。 

したがって、意思決定の構造は、コストや利益によって純粋に貪欲なものではありません。 同時にスキップを最小限に抑え（これは、非ゼロの選択肢の数を最大にするのと同じです）、それらの間の強度を最大にします。 

制約は大きく、最大で$2 \cdot 10^5$演習と非常に大きなエネルギー予算$10^{15}$。 これにより、エネルギーに対する指数関数的な検索や DP が除外されます。 アイテムに対する二次関数の DP でも遅すぎます。 

主な難点は、各演習に 3 つの状態があることですが、その目標は単純なナップザックではないということです。私たちは世界的な予算の下で 2 つの目標を辞書編集的に最適化しています。 

欲張ってできるだけ激しいものを選ぶと、微妙な失敗例が現れます。 たとえば、ある演習が次のようなものであるとします。$a_i = 1, b_i = 100$、そして別の人は$a_j = 2, b_j = 3$、少ない予算で。 最初の項目に集中して取り組むと、予算が過剰に消費され、後の多くの項目をスキップせざるを得なくなる可能性があります。これは、より多くの参加者を獲得できる簡単な選択をすることよりも悪いことです。 すべての項目にわたる結合により、ローカルな決定が安全でなくなります。 

他の失敗例は、最初にどこでも簡単なバージョンを貪欲に採用し、次に可能な場合は強力なバージョンにアップグレードすることでスキップを最小限に抑えようとした場合に発生します。 アップグレードが独立していないため、これは失敗する可能性があります。簡単なアップグレードを強力なアップグレードに変換すると、コストが次のように増加します。$b_i - a_i$、一部のアップグレードは、間接的にスキップ数を変更し、他の必須の簡単な選択の実行可能性をブロックする可能性があります。 

## アプローチ

 強引なアイデアは、演習ごとに 3 つの選択肢すべてを検討し、実現可能性をチェックすることです。 これは$3^n$可能性はありますが、すぐには不可能です。 

より構造化されたブルートフォースは、アイテムと残りのエネルギーに対する動的プログラミングです。 DP 状態は、考えられる各エネルギー使用量の最小スキップ数と最大強度カウントとして定義できます。 ただし、エネルギーは次のように上昇します$10^{15}$したがって、この状態空間は大きすぎます。 圧縮されていても、遷移ではアイテムごとにすべての状態を反復処理する必要があるため、おおよその結果が得られます。$O(n \cdot x)$、それは不可能です。 

重要な観察は、スキップを最小限に抑えることは、受講する演習の数を最大限に増やすことと同じであるということです。つまり、可能な限り、最初に各項目を簡単または強度のどちらかに割り当てるように努める必要があります。 簡単なバージョンであっても、アイテムをスキップする唯一の理由は、エネルギーが残っていないことです。 

これは 2 層構造を示唆しています。 まず、選択した合計コストを実現可能にするためにどの項目をスキップする必要があるかを決定しようとします。 スキップを回避するあらゆる方法の中で、アップグレードする余裕がある場合は、簡単な方法よりも強力な方法を好みます。 

変革とは、すべてのアイテムを簡単なコストで入手できるというベースラインの観点から考えることです。 これにより、総ベースライン エネルギーが得られます。$S = \sum a_i$。 もし$S > x$, その場合、簡単なレベルですべてのアイテムを取ることさえできないため、いくつかのアイテムをスキップする必要があります。 スキップするたびにコストが削減されます$a_i$、スキップを最小限に抑えたいので、最大の項目をスキップする必要があります$a_i$初め。 

もし$S \le x$の場合、スキップする必要はありません。 現在、いくつかのアイテムを簡単なものから強力なものにアップグレードしようとしています。各アップグレードのコストは次のように増加します。$b_i - a_i$。 スキップはすでに最小化されているため、アップグレードの数を最大化しますが、残りのエネルギーによって制限されます。 

これにより、問題は古典的な貪欲なアップグレードの問題に帰着します。すべて簡単なことから始めて、コストの増加が最小のアップグレードを最初に繰り返し選択します。 

最終的な構造は次のようになります。必要に応じていくつかのアイテムを削除し、残りのアイテムを貪欲にアップグレードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(3^n)$|$O(n)$| 遅すぎる |
 | エネルギーよりもDP |$O(n \cdot x)$|$O(x)$| 不可能 |
 | 貪欲なベースライン + アップグレード |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つのフェーズでソリューションを構築します。最初にスキップを最小限に抑えて実現可能性を確保し、次に強度を最大化します。 

## アルゴリズムのチュートリアル

 1. すべての演習をイージーモードで受講した場合の合計コストを計算します。 これは$S = \sum a_i$。 これは、実行されるすべてのエクササイズがエネルギー使用量に最小限に寄与するため、スキップを最小限に抑えるための最良のシナリオを表しています。 
2. もし$S > x$、いくつかの演習をスキップする必要があります。 各スキップは正確に保存されます$a_i$したがって、スキップを最小限に抑えて総コストを可能な限り削減するには、最大のエネルギーを使用する演習をスキップする必要があります。$a_i$初め。 並べ替え順$a_i$降順にすると、各スキップでエネルギーが最大限に削減され、必要なスキップの数が最小限に抑えられます。 
3. どの演習をスキップするかを決定した後、残りのセットを必須の「少なくとも簡単なレベルで受講する」項目として修正します。 結果として得られるベースラインコストは次のように保証されます。$\le x$。 
4. 残りの予算を計算する$R = x - \sum a_i$スキップされていない項目の上に表示されます。 これはアップグレードに利用できる予算です。 
5. スキップされていない演習ごとに、アップグレード コストを定義します。$c_i = b_i - a_i$。 これは、簡単な状態から激しい状態に移行するために必要な追加のエネルギーです。 私たちの目標は、予算内でできるだけ多くのアップグレードを選択することです$R$、アップグレードするたびに激しい練習の数が増えるためです。 
6. 残りの演習を次の順序で並べ替えます。$c_i$上昇。 この順序で繰り返し、次の場合にのみ演習をアップグレードします。$c_i \le R$、次に減算します$c_i$から$R$。 最初に最小の増分を選択すると、アップグレードの数が最大化されます。これは、すべてのアップグレードが独立して予算を消費し、目標に均等に貢献するためです。 
7. 最終的な割り当てを出力します。スキップされた項目は 0、アップグレードされた項目は 2、その他すべては 1 とマークされます。 

### なぜ効果があるのか

 重要な不変条件は、追加の項目をスキップしてもスキップ数が達成可能な最小値を超えて増加するだけであるという意味で、ステップ 3 の後、残りの項目はすべて必須であるということです。 したがって、問題はすべてのアイテムが基本コストにすでに含まれており、アップグレードのみがオプションのままであるというナップザックにきれいに縮小されます。 各アップグレードの価値は同じ (1 つの強力な割り当て) ですがコストが異なるため、最適な戦略は最も安価なアップグレードを最初に採用することです。これは標準的な交換の議論です。より高価なアップグレードを使用し、より安価なアップグレードをスキップするソリューションは、実現可能性や客観的価値に影響を与えることなく、アップグレードを交換することで改善できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

idx = list(range(n))

# Phase 1: try to minimize skips
base = sum(a)

skip = [False] * n

if base > x:
    # need to skip some items
    idx.sort(key=lambda i: a[i], reverse=True)
    cur = base
    for i in idx:
        if cur <= x:
            break
        skip[i] = True
        cur -= a[i]
    base = cur

# remaining items
remaining = [i for i in range(n) if not skip[i]]

# Phase 2: maximize upgrades
gain = [(b[i] - a[i], i) for i in remaining]
gain.sort()

R = x - sum(a[i] for i in remaining)

upgrade = [False] * n
for c, i in gain:
    if c <= R:
        R -= c
        upgrade[i] = True

# build answer
ans = []
for i in range(n):
    if skip[i]:
        ans.append('0')
    elif upgrade[i]:
        ans.append('2')
    else:
        ans.append('1')

print(''.join(ans))
```コードはまず、すべてをイージー モードで実行する場合のベースライン コストを計算します。 それが予算を超える場合は、実行可能性が回復するまで、高コストの簡単な項目を貪欲に削除します。これは、スキップされる演習の数を最小限に抑えることに直接対応します。 

その後、残りのすべての項目を実費で必須として扱います$a_i$、残りの予算を使用してそれらの一部をアップグレードします。 並べ替え順$b_i - a_i$追加エネルギーの各単位が最初に最も効率的な強度の増加に費やされるようにします。 

スキップ処理とアップグレード処理を混在させると、2 つの異なる最適化目標を誤って組み合わせる可能性があるため、スキップ処理とアップグレード処理を分離することが重要です。 

## 実用的な例

 サンプル 1 の簡略化されたバージョンをトレースします。 

次のように仮定します。$n=4, x=6$

$a = [1,5,2,1]$

$b = [3,7,3,4]$ベースラインコストは$1+5+2+1 = 9$を超える$x=6$。 したがって、スキップする必要があります。 

並べ替える$a_i$降順: インデックス$a$項目 2 (5)、項目 3 (2)、項目 1 と項目 4 (1) です。 

最初に項目 2 をスキップし、コストをすでに 4 に削減します。$\le 6$。 したがって、必要なスキップは 1 回だけです。 

残りの項目は、ベースラインコストのインデックス 1、3、4 です。$1+2+1=4$。 残りの予算は、$2$。 

現在のアップグレードコストは次のとおりです。 

項目 1: 2、項目 3: 1、項目 4: 3。 

アイテム 3、アイテム 1、アイテム 4 のコスト順に並べ替えます。 

アイテム 3 (コスト 1)、残りの予算 1 をアップグレードしますが、アイテム 1 (コスト 2) をアップグレードできません。停止します。 

最後: 1 回スキップ、1 回激しい、安心してください。 

次に 2 番目の構築例を示します。$n=3, x=5$

$a=[2,2,2]$、$b=[5,5,5]$ベースラインは 6 なので、少なくとも 1 つの項目をスキップする必要があります。 最大のものを 1 つスキップする$a_i$4 に減ります、実現可能です。 残り 2 つのアイテムのコストは 4、予算の残りは 1 であるため、アップグレードはできません。 出力には 0 が 1 つ、1 が 2 つ含まれます。 

これらのトレースは、スキップは最小限の数で実現可能性を満たすために純粋に決定されるのに対し、アップグレードはその後の純粋に予算の最適化であることを示しています。

 ## 特殊なケース

 重要なエッジケースは、最初のイージーサムがすでに予算内に正確に収まっている場合です。 この場合、スキップ ロジックはトリガーされず、アルゴリズムは直接アップグレードに進む必要があります。 たとえば、次の場合$a=[2,3], x=5$の場合、両方の項目は必須です。 このアルゴリズムではスキップは設定されず、アップグレード コストのみが考慮されます。 アップグレードは予算を超える可能性があるため、残りの容量に応じて 1 と 2 の組み合わせが正しく生成されます。 

もう 1 つのエッジ ケースは、1 つを除くすべての項目をスキップした後でも、依然として予算を超過している場合です。 制約があるためこれは起こりません$a_i \ge 1$ですが、アルゴリズムは自然にそれを処理します。実行可能になるまでスキップし続け、最終的には 1 つの項目だけが残り、終了と正確性が保証されます。 

最後の微妙なケースは、複数のアイテムが同じものを共有する場合です。$a_i$または同じアップグレードコスト。 ソートは一意性に依存しないため、同順位は正確さに影響しません。 交換によって総コストや目標値が変更されないため、等コスト項目間のどの順序でも実現可能性と最適性の両方が維持されます。
