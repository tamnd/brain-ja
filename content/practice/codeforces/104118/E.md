 ## 解決策
 ## 問題の理解

 都市がノード、道路が無向エッジである重み付けされたグラフが与えられます。それぞれの横断にはちょうど 1 時間かかります。 出発都市から目的地の都市に到達するまでの時間を最短にする必要があります。 

ややこしいのは、パトカーが固定の環状ルートを走行していることだ。 各パトカーはグラフ内の閉じられた歩行をたどり、道路セグメントごとに 1 時間を費やします。 車が道路を走行している間、その道路はその時間完全に使用できなくなります。 どの都市でも任意の時間待つことができ、いつでも安全に待つことができます。 

タスクは、都市からの最短の移動時間を計算することです。`a`街へ`b`ただし、パトカーが走っているときは決して道路に入らないようにしてください。 

制約は大きく、最大 200,000 の都市と道路、最大 200,000 のパトロール、合計パトロール記述サイズは最大 1,000,000 です。 これにより、時間を段階的にシミュレートするアプローチは即座に除外されます。 どのソリューションでも、グラフの明示的な時間拡張を避けなければなりません。 

時間拡張グラフ上の単純な最短パスでは、すべてのノードに対してノードが作成されます。`(city, time)`ペア。 パトロールは周期的に繰り返されますが、周期が長くなる可能性があるため、時間の次元には事実上制限がありません。 パトロール サイクルは独立しており、エッジ上でローカルにのみ相互作用するため、時間を共通の期間に圧縮することさえ一般に不可能です。 

待機が重要な場合には、微妙なエッジケースが発生します。 

入力:```
4 4 1 3
1 2
2 3
3 4
4 1
1 2 3
1 3
```ここで、ダイレクトパスは、`1 → 2`パトロール エッジにより最初の 1 時間でブロックされる可能性があり、ノード 1 での待機が強制されます。タイミングを無視した貪欲な最短パスは、誤ってそのエッジをすぐに取得し、キャッチされてしまいます。 

最大の問題は、エッジの可用性が絶対時間に依存するのに、動的なエッジ制約の下で最短パスが必要であることです。 

## アプローチ

 ブルートフォースビューは、これを時間拡張された状態グラフの最短パスとして扱うことです。 それぞれの状態は、`(node, time)`、そして遷移はから始まります`(u, t)`に`(v, t+1)`エッジの場合`(u, v)`時間は空いています`t`。 この暗黙的なグラフに対してダイクストラまたは BFS を実行できます。 

これは正しいですが、時間には制限がないため、直接実行することはできません。 解答に時間を制限したとしても、解答自体が膨大になる可能性があり、各状態遷移ではその時点でのすべてのパトロール位置を確認する必要があります。 それは少なくともそうでしょう`O(answer × m)`あるいはさらに悪いことに。 

重要な観察は、実際にはグローバル時間の拡張を必要としないということです。 各道路はパトロールの移動によって定められた特定の間隔の間のみ封鎖されます。 すべてのパトカーは長さのサイクルで決定的に移動するため、`l`、各有向エッジは既知のスケジュールで定期的に占有されます。 時間の観点から考える代わりに、視点を逆転させます。エッジごとに、ブロックされるすべての時間間隔をパトロール サイクル セグメントの発生ごとに法的に事前計算できます。 

しかし、それでも世界的には大きすぎます。 重要な簡素化は、完全な定期スケジュールが必要ないことです。 都市からの特定の出発イベントについて、特定のエッジの最も早い安全な通過がいつ可能になるかを知る必要があるだけです。 

これにより問題は、エッジが単に重み 1 ではなく、追加の制約を持つグラフに変換されます。`t`エッジがフリーの場合のみ`[t, t+1]`」 待機が許可されているため、エッジの実効コストは、出発できる最も早い時刻から現在時刻を引いたものに 1 を加えたものになります。 

したがって、このタスクは、各エッジに時間依存の待機ペナルティがある最短経路問題となり、常に可能な限り早い出発を選択します。 

すべてのパトロール セグメントを処理し、有向エッジごとに、各パトロール サイクル内でブロックされる一連の時間を構築します。 パトロールの全長は最大でも 10^6 であるため、パトロールカーの端を越えた移動をすべて列挙し、占有間隔を記録できます。 各セグメントはタイム ステップごとに 1 つのブロック単位間隔に寄与するため、「エッジ (u, v) は時間 t でブロックされている」という形式のイベントを保存できます。 

次に、都市に対してダイクストラのようなプロセスを実行しますが、静的な重みの代わりに、現在の到着時刻の後に次に利用可能になったときに各発信エッジを計算します。 これには、エッジごとにブロックされた時間のソートされたリストを維持し、次の禁止間隔をバイナリ検索する必要があります。 

これにより、問題は、各エッジ クエリがそのエッジのブロック イベントの数において対数になる、時間依存の待機を伴う最短パスに短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 時間拡張 BFS/ダイクストラ | O(T×m) | O(T × n) | 遅すぎる |
 | ブロッキング スケジュールを使用したイベント ドリブンの最短パス | O((n + m) log m + total_patrol log m) | O(m + total_patrol) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのパトロール ルートをエッジ トラバーサル イベントに変換します。 各パトカーは長さのサイクルに従います`l`なので、連続するペアごとに`(x[i], x[i+1])`そして`(x[l-1], x[0])`、この無向エッジがサイクル内の特定の時間オフセットで占有されることを記録します。 

時間を剰余として扱います`l`各パトロールを個別に実行しますが、サイクルを結合する代わりに、各パトロールの開始時間に相対的な絶対的なイベント パターンを単に記録します。 

### ステップ

 1. グラフを読み取り、すべての道路の隣接リストを保存します。 各道路は一意に識別されるため、遮断情報を道路に添付できます。 
2. 各巡回ルートについて、サイクル全体にわたる移動をシミュレーションします。 ステップで`t`、パトロールは連続する都市の間の端を横断します。 このエッジは、そのタイム ステップ中にブロックされることが記録されます。 各走査にはちょうど 1 時間かかるため、各セグメントは 1 つのブロック単位間隔に寄与します。 
3. すべてのエッジについて、ブロックされた時間のソートされたリストを維持します。 このリストは、エッジへの立ち入りが禁止されているすべての瞬間を表します。 
4. 州が都市のみである都市に対して修正されたダイクストラを実行しますが、緩和は現在の到着時間に依存します。 
5.エッジを緩める場合`(u, v)`現時点で`t`、最も早いものを計算する必要があります`t' ≥ t`エッジがブロックされないように`t'`。 これは、ブロックされたタイム リスト内でバイナリ検索を行い、占有されているタイムスタンプをスキップすることによって行われます。 
6. 最初の有効な出発時刻が見つかったら`t'`、距離を更新します`v`として`t' + 1`改善された場合は優先キューにプッシュします。 
7. 到達可能なすべてのノードが処理されるか、宛先が完了するまで続行します。`b`に達します。 

### なぜ効果があるのか

 重要な不変条件は、優先キューから除外された各都市について、すべての有効なスケジュールの下でその都市への可能な限り最も早い到着時刻が判明したことです。 エッジ緩和では常に可能な限り早い出発時刻が選択されるため、優先キューによって強制される順序に矛盾することなく、代替パスがより早くノードに到達することはできません。 ブロッキング制約はトラバーサルを遅らせるだけであり、代替のより高速なショートカットを作成することはありません。そのため、ダイクストラの貪欲な選択は、この時間増加したコスト構造においても引き続き有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq
from collections import defaultdict

def solve():
    n, m, p, l = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    edge_id = {}
    eid = 0

    def get_id(u, v):
        nonlocal eid
        if u > v:
            u, v = v, u
        if (u, v) not in edge_id:
            edge_id[(u, v)] = eid
            eid += 1
        return edge_id[(u, v)]

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        get_id(u, v)

    blocked = defaultdict(list)

    for _ in range(p):
        route = list(map(int, input().split()))
        for i in range(l - 1):
            u, v = route[i], route[i + 1]
            eid = get_id(u, v)
            blocked[eid].append(i)
        u, v = route[-1], route[0]
        eid = get_id(u, v)
        blocked[eid].append(l - 1)

    dist = [10**30] * (n + 1)
    dist[1] = 0  # will fix below
    # we need actual a,b
    a, b = map(int, input().split())

    dist = [10**30] * (n + 1)
    dist[a] = 0
    pq = [(0, a)]

    for k in blocked:
        blocked[k].sort()

    def next_available(eid, t):
        arr = blocked.get(eid, [])
        if not arr:
            return t
        # simple linear skip via binary search style jumping
        i = 0
        lo = 0
        hi = len(arr)
        while True:
            j = lo
            # binary search first block >= t
            l, r = 0, len(arr)
            while l < r:
                mid = (l + r) // 2
                if arr[mid] < t:
                    l = mid + 1
                else:
                    r = mid
            if l == len(arr) or arr[l] != t:
                return t
            t += 1

    while pq:
        t, u = heapq.heappop(pq)
        if t != dist[u]:
            continue
        if u == b:
            print(t)
            return
        for v in adj[u]:
            eid = get_id(u, v)
            nt = next_available(eid, t)
            nt += 1
            if nt < dist[v]:
                dist[v] = nt
                heapq.heappush(pq, (nt, v))

    print("IMPOSSIBLE")

if __name__ == "__main__":
    solve()
```この実装では隣接関係が維持され、各無向エッジに一意の識別子が割り当てられるため、パトロール ブロッキング情報をエッジごとに保存できます。 各パトロールは、通過するエッジのブロックされたタイムスタンプを提供します。 最短パスは優先キューを使用して計算され、各緩和ステップで最も早い安全な出発時刻が計算されます。 

重要な点は、内部で暗黙的に待機を処理することです。`next_available`。 時間を明示的にシミュレートするのではなく、現在の時間がブロックされた瞬間と衝突した場合にのみ進みます。 

よくある落とし穴は、複数のパトロールが同じエッジを同時にブロックできることを忘れていることです。 そのため、すべてのブロック時間がエッジごとに集計され、並べ替えられます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始都市からのすべての発信エッジが時間 0 でブロックされている場合です。アルゴリズムでは、少なくとも 1 つのエッジが使用可能になるまで無期限に待機できる必要があります。 待機は暗黙的に行われるため、`next_available`、検索が途中で失敗することはありません。 

もう 1 つのケースは、重複するパトロールが同じエッジを繰り返しブロックすることです。 すべてのブロックされた時間がマージされて並べ替えられるため、繰り返しのエントリは正確さに影響を与えず、二分探索のスキップ長がわずかに増加するだけです。 

最後の微妙なケースは、最適なパスが異なるノードで複数の連続した待機を必要とする場合です。 各ノード拡張が実行可能な最も早い出発時刻を個別に再計算するため、待機はグローバルに計画されるのではなく自然に分散されるため、ダイクストラ公式でもこれを処理できます。
