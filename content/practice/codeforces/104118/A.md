 ## 問題の理解

 私たちには役割が与えられている$f(x)$実数に基づいて定義されますが、次の 3 つの領域に分割されます。$x$。 各領域は異なる式を使用します。つまり、左端に線形式、中央に別の線形式、右側に 3 次多項式が使用されます。 

この問題では関数をどこでもスムーズにする一意の値がすでに提供されているため、タスクは定数を導出することではありません。 代わりに、単一の整数入力に対する固定係数を使用して関数を直接評価します。$x$。 入力は小さいことが保証されており、$-10$そして$10$したがって、必要なのは定数時間の評価だけです。 

重要な構造上の詳細は、関数が区分的であるということです。 つまり、計算の唯一重要な部分は、与えられた条件にどの式を適用するかを決定することです。$x$。 正しいセグメントが選択されると、評価は簡単な算術で行われます。 

ここでの単純な間違いは、間隔の境界を誤解することです。 左の部分に含まれるものは、$x \le -3$、真ん中の部分には以下が含まれます$-3 < x \le 2$、右の部分には以下が含まれます$x > 2$。 境界点$-3$そして$2$したがって、特に重要です。 たとえば、$x = -3$, 間違った分岐を使用すると、両方の式が有効な式であっても、答えが完全に変わってしまいます。 

入力範囲が狭いため、パフォーマンス上の懸念はありません。 1 つの分岐を一定時間で評価する適切な実装であれば十分です。

 ## アルゴリズムのチュートリアル

 まず、評価が機械的になるように、提供された定数を使用して関数を書き換えます。 

のために$x \le -3$、関数は$f(x) = -(x + 4) + 8 = -x + 4$。 

のために$-3 < x \le 2$、関数は$f(x) = -2x + 1$。 

のために$x > 2$、関数は$f(x) = x^3 - 14x + 17$。 

これで、計算は単純な決定プロセスになります。 

1. 整数を読み取る$x$。 これが唯一の入力値であり、分岐を完全に決定します。 
2. かどうかを確認します。$x \le -3$。 この条件が成立する場合、計算します$-x + 4$。 この分岐は左端の線形セグメントに対応するため、他の項は関係ありません。 
3. それ以外の場合は、$x \le 2$。 これが真の場合、計算してください$-2x + 1$。 これは中間のセグメントであり、両方が含まれます。$x = -2$そして$x = 2$したがって、不等式は右端点を含む必要があります。 
4. 上記のどちらも当てはまらない場合は、$x > 2$。 コンピューティング$x^3 - 14x + 17$。 これが残りの唯一の領域であるため、追加のチェックは必要ありません。 

正確さは、これら 3 つの間隔が実線の完全な重複しない分割を形成しているという事実から得られます。 考えられるすべての整数入力は 1 つのブランチに属するため、1 つの式が適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input().strip())

if x <= -3:
    print(-x + 4)
elif x <= 2:
    print(-2 * x + 1)
else:
    print(x**3 - 14 * x + 17)
```この実装では、間隔ロジックが直接反映されます。 最初の条件は、以下のすべての値を処理します。$-3$, そのため、最初に確認する必要があります。 2 番目の条件は自動的に範囲を暗黙的に示します。$-3 < x \le 2$前の分岐ではより小さい値が除外されていたためです。 他のすべては立方体の場合に当てはまります。 

唯一の微妙な点は、条件の順序が確実に保持されるようにすることです。 それらを誤って並べ替えると、次のような境界値が発生する可能性があります。$-3$または$2$間違った式に割り当てられる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x = int(sys.stdin.readline().strip())

    if x <= -3:
        return str(-x + 4)
    elif x <= 2:
        return str(-2 * x + 1)
    else:
        return str(x**3 - 14 * x + 17)

# sample-style checks
assert run("-3") == "7"
assert run("3") == "2"

# boundary cases
assert run("-10") == "14"
assert run("-4") == "8"
assert run("2") == "-3"
assert run("0") == "1"

# cubic edge
assert run("10") == str(1000 - 140 + 17)

 ## 特殊なケース

 最も重要なエッジ ケースは、まさに次の間隔の境界です。$x = -3$そして$x = 2$。 

のために$x = -3$の場合、条件が次のとおりであるため、入力によって最初の分岐がトリガーされます。$x \le -3$。 計算は$-(-3) + 4 = 7$。 プログラマが誤って厳密な不等式を使用したり、最初に中間の分岐をチェックしたりすると、この値は誤って線形中間式に分類されてしまいます。 

のために$x = 2$、次のように定義されているため、2 番目の分岐が適用されます。$x \le 2$。 計算は次のようになります$-2 \cdot 2 + 1 = -3$。 条件が間違って次のように書かれていた場合$x < 2$、 それから$x = 2$誤って 3 次式にジャンプして、まったく異なる結果が生成されてしまいます。 

どちらの場合も、正確さは算術演算ではなく、正確な間隔分割の維持に依存することがわかります。
