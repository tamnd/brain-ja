 ## 問題の理解

 私たちに最初に与えられたのは、$n$素数なので、それらを 2 つのグループに分割する必要があります。1 つはアリス用、もう 1 つはボブ用です。 各素数は分割できず、完全にそのうちの 1 つに完全に一致する必要があります。 アリスが和を持つ素数のセットを受け取った場合$A$, ボブは自動的に残りの金額を受け取ります。$B = S - A$、 どこ$S$最初の合計です$n$素数。 

制約は任意ではありません。 分割は、それらの合計の比率が固定比率と一致する場合にのみ有効とみなされます。$p : q$、ここで両方とも$p$そして$q$素数です。 つまり、パーティションは次の条件を満たす必要があります。$A : B = p : q$。 最初のサブセットの数を数えるように求められます。$n$この比例関係が維持されるように、素数をアリスのセットとして選択できます。 

条件を書き直すと、比率の曖昧さがなくなります。 から$A / B = p / q$、私たちは得ます$qA = p(S - A)$を再配置すると、$(p + q)A = pS$。 これは、固定の場合、$n, p, q$、目標合計が 1 つであるか、$A$アリスが達成する必要がある、または有効な分割がまったく存在しない場合$pS$で割り切れない$p + q$。 この問題は、最初の部分に対する制約付きサブセット合計カウント問題になります。$n$素数。 

この制約により、サブセットに対するブルート フォースが不可能になります。$n$2000 まで上がることを意味します$2^{2000}$分割の可能性。 典型的なものでも、$O(n \cdot \text{sum})$テスト ケースあたりのナップザックは、最大数があるため、遅すぎます。$10^5$クエリ。それぞれが異なるプレフィックス長について尋ねる可能性があります$n$。 

必要な分数が必要な場合、微妙なエッジケースが発生します。$p/(p+q)$合計額と一致しません。 たとえば、素数が$[2,3,5]$、 それから$S = 10$。 もし$p:q = 2:3$、必要になります$A = 4$、ただし、のサブセットはありません$[2,3,5]$合計は 4 になるため、答えは 0 になります。任意の比率が達成可能であると仮定する単純なアプローチでは、明示的に割り算をチェックしない限り、構成が誤ってカウントされます。$pS$。 

もう 1 つのエッジ ケースは対称性です。アリスのサブセットを選択すると、ボブのサブセットが一意に決定されるため、補数を二重にカウントしてはなりません。 常にアリスのみのサブセットをカウントする場合、定式化ではこの問題を回避できます。 

## アプローチ

 ブルートフォースアプローチでは、最初のサブセットのすべてが列挙されます。$n$素数を計算してその合計を計算し、比率条件が成立するかどうかを確認します。 すべての有効な分布は、アリスに割り当てられたインデックスの 1 つのサブセットに正確に対応するため、これは概念的には正しいです。 ただし、検討が必要です$2^n$サブセット、さらには$n = 40$、ましてやこれは不可能になります。$n = 2000$。 

標準的な改善は、サブセット合計のカウントに動的プログラミングを使用することです。 目標額を決めれば$A$、最初のサブセットがいくつあるかを計算できます。$n$素数はナップザック スタイルの DP を使用してその合計を達成します。 問題は、クエリごとにこの DP を個別に再計算できないことです。$10^5$クエリ。 

重要な観察点は、クエリがプレフィックスベースであるということです。$n$。 増えるにつれて$n$、一度に追加する新しい素数は 1 つだけであり、DP 状態は段階的に更新できます。 これは、素数を順番に処理するにつれて進化するグローバルなサブセット合計構造を維持することを示唆しています。 また、クエリをグループ化します。$n$したがって、新しいプレフィックス長に達するたびに、そのためのすべてのクエリにすぐに答えます。$n$。 

これにより、問題は、特定のチェックポイントで複数のターゲット合計クエリに応答しながら、単一の配列にわたって増加するサブセット合計 DP を維持することに変わります。

## アルゴリズムのチュートリアル

 各クエリは最初の素数の合計に依存するため、2000 番目の素数までの素数のリストとそれらの接頭辞の合計を事前計算します。$n$素数。 

また、すべてのクエリをその内容ごとにグループ化します。$n$、インデックスに到達したときに$n$、続行する前に、そのプレフィックスに依存するすべてのことに答えることができます。 

私たちは動的プログラミング構造を維持します`dp`、 どこ`dp[x] = 1`合計を持つ処理された素数のサブセットが存在することを意味します$x$。 これはビットセットとして実装されます。ここで、ビットは$x$合計に相当する$x$。 

新しいプライムごとに$p_i$、現在のビットセットをシフトすることで DP を更新します。$p_i$そしてそれを既存の状態と OR 演算します。 これは、現在の素数を含めるか除外するかを選択することを表します。 

プレフィックスに到達したとき$n$、合計を計算します$S_n$。 クエリごとに$(p, q)$、必要な合計を計算します。$$A = \frac{p \cdot S_n}{p + q}.$$もし$pS_n$で割り切れない$p+q$、答えはすぐにゼロになります。 それ以外の場合は、単純に合計かどうかを読み取ります。$A$現在の DP で達成可能であり、ビットセット DP (合計ごとのカウントを保存する) でエンコードされたウェイの数を介してカウントします。 

### なぜ効果があるのか

 どのプレフィックスでも$n$、DP ビットセットは、最初のビットセットを使用して達成可能なすべてのサブセット合計を正確にエンコードします。$n$素数。 素数を追加するときの遷移では、すべてのサブセットに新しい素数が含まれるか含まれないかのいずれかがあり、シフト アンド マージ操作で両方のケースが重複せずに列挙されるため、正確さが保たれます。 各クエリは固定プレフィックスの状態にのみ依存するため、そのプレフィックスに到達した時点で応答することで、その DP 状態が完全で最終的なものであることが保証されます。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1169996969

# generate first 2000 primes
def sieve_primes(limit_count=2000):
    limit = 200000  # safe upper bound for 2000th prime
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            if len(primes) == limit_count:
                return primes
            for j in range(i * i, limit + 1, i):
                if j <= limit:
                    is_prime[j] = False
    return primes

primes = sieve_primes(2000)

n_queries = int(input())
queries_by_n = [[] for _ in range(2001)]

for _ in range(n_queries):
    n, p, q = map(int, input().split())
    queries_by_n[n].append((p, q))

max_n = max(i for i in range(2001) if queries_by_n[i])

max_sum = sum(primes[:max_n])

dp = 1  # bitset: only sum 0 reachable
current_sum = 0
answers = [0] * n_queries
qid = 0

# we need stable ordering, store query ids
qid_map = [[] for _ in range(2001)]
qid = 0
for n in range(2001):
    for pq in queries_by_n[n]:
        qid_map[n].append(qid)
        qid += 1

qid = 0
ptr = 0

for i in range(1, max_n + 1):
    current_prime = primes[i - 1]
    dp = dp | (dp << current_prime)
    current_sum += current_prime

    if queries_by_n[i]:
        for (p, q) in queries_by_n[i]:
            A_num = p * current_sum
            denom = p + q
            if A_num % denom != 0:
                answers[qid] = 0
            else:
                target = A_num // denom
                if target < 0 or target > current_sum:
                    answers[qid] = 0
                else:
                    answers[qid] = (dp >> target) & 1
            qid += 1

for v in answers:
    sys.stdout.write(str(v % MOD) + "\n")
```ソリューションの中核はビットセットです`dp`、達成可能なすべてのサブセット合計をコンパクトに保存します。 移行`dp |= dp << x`各素数の包含/除外の選択をエンコードします。 

比率条件はクエリごとに単一の目標合計に変換されるため、2 つの変数を同時に推論する必要がなくなります。 唯一のデリケートな部分は、そのプレフィックスの DP が完全に構築された後にのみクエリを評価するようにすることです。

 ## 特殊なケース

 重要なエッジ ケースは、計算されたターゲットの合計が整数ではない場合です。 たとえば、合計が 10 で比率が次の場合、$2:5$、必要な合計は$10 \cdot 2 / 7$、これは整数ではありません。 その状況では、アルゴリズムは DP に問い合わせる前にクエリを即座に拒否し、近くの合計からの不正確な一致を回避します。 

別のエッジケースが発生するのは次の場合です。$n$とても小さいです。 素数が 1 つまたは 2 つだけの場合でも、空のサブセットが常に存在し、シフトによって単一要素のサブセットが 1 回だけ追加されるため、DP は正しく初期化されます。 

最後に、この比率が、アリスが合計のほとんどすべてを取得するか、ほとんどまったく取得しない必要があることを暗示している場合でも、DP には両方の極端な値 (空のサブセットからの合計 0 と合計) が含まれるため、依然として正しく動作します。$S_n$すべての要素を取得することから。
