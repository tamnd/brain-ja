 ## 解決策
 ## 問題の理解

 各セルが陸地または水のいずれかである長方形のグリッドが与えられます。 ちょうど 3 つのセルがすでに土地になっており、任意の数の水セルを土地に変換することができます。 これを行った後は、陸上領域全体が接続される必要があります。つまり、どの陸上セルからでも、陸上セルを通って上下左右に移動するだけで他の陸上セルに到達できるようになります。 

コストは単純に陸上に変換する水域セルの数です。そのため、目標は、既存の 3 つの陸上セルを接続するだけでなく、追加されるセルの数を最小限に抑えて接続することです。 グラフ用語では、各セルはノードであり、隣接関係は 4 方向です。 事実上、3 つの固定ターミナル ノードを 1 つの接続コンポーネントに接続する追加グリッド ノードの最小セットを見つけることが求められます。 これはグリッド上の古典的なシュタイナー木問題ですが、厳密に 3 つの端末に制限されています。 

グリッド サイズは最大でも 100 x 100 であるため、セルのすべてのサブセットまたはすべての可能な接続構造に対するブルート フォースは大きすぎます。 水セルの数が指数関数的に増加することは、直ちに実行不可能になります。なぜなら、それらは最大 10,000 個も存在する可能性があるからです。 

調整せずに 3 つのランド セルをペアごとに貪欲に接続しようとすると、微妙な失敗のケースが発生します。 たとえば、2 つのパスが重複する場合、単純なアプローチでは二重にカウントされたり、非効率的に交差する次善のルートが選択されたりする可能性があります。 もう 1 つの問題は、各ペア間の最短パスが個別に最適解を形成すると仮定することですが、共有パスは総コストを削減し、共同で計画する必要があるため、これは誤りです。 

## アプローチ

 強引なアイデアは、水域セルのすべてのサブセットを考慮し、それらを陸地に変え、元の 3 つの陸上セルが接続されるかどうかを確認することです。 これは正しいですが、組み合わせ的にはすぐに爆発します。 最大 10,000 個のセルを使用すると、サイズ 20 のサブセットを考慮するだけでもすでに天文学的になります。 

構造上の重要な洞察は、端末が 3 つしかないということです。 最適解は、これら 3 つの点を接続するツリーのように見える必要があります。グリッド グラフ内のそのようなツリーは非常に制約された形状になります。つまり、単一の集合点 (シュタイナー ポイント) で交わる 3 つの最短パスの結合です。 これにより、任意のサブグラフの検索から 1 つの会議セルを選択し、3 つのソースすべてをそれに最適に接続するという問題が軽減されます。 

候補となる会議セルを修正すると、そのセルを介してすべての端末を接続するための最適コストは、各端末からそのセルまでの最短パス距離の合計になります。 移動コストは均一であるため、各最短パスはグリッド内の BFS 距離にすぎません。 

したがって、問題は、BFS を使用して 3 つの距離マップを計算し、すべてのセルを潜在的な会合点としてスキャンし、距離の合計を最小化することに帰着します。 最終的な構造は、各端末から BFS 親を取得し、選択した最適なミーティング ポイントからパスをたどることによって取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^(rc)) | O(rc) | 遅すぎる |
 | マルチソース BFS + ミーティング ポイント | O(rc) | O(rc) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 3 つの末端セルを特定します。 

グリッドをスキャンし、土地を含む 3 つのセルの座標を記録します。 これらは、シュタイナー ツリーの固定エンドポイントです。 グリッドの残りの部分は、接続を構築するための潜在的な素材となります。 

### 2. 各端末から BFS を実行します。 

3 つの陸上セルのそれぞれについて、グリッド上で BFS を実行し、他のすべてのセルまでの最短距離を計算します。 また、後でパスを再構築できるように親ポインターも保存します。 

移動コストはエッジ全体で均一であるため、この手順は正しいです。そのため、BFS は重み付けされていないグリッド グラフ内の最短パスを保証します。 

### 3. すべてのセルを潜在的なミーティングポイントとして試してください

グリッド内のすべてのセルについて、そのセルを介して 3 つの端末すべてを接続する総コスト、つまり 3 つの BFS 距離の合計を計算します。 この合計を最小化するセルを追跡します。 

これが機能する理由は、重み付けされていないグラフ内の 3 つの端末に対する最適なシュタイナー ツリーは、ある頂点で交わる 3 つの最短パスとして見なせるためです。 

### 4. 選択したミーティングポイントからソリューションを再構築します。 

最適なミーティング ポイントが決定したら、BFS 親ポインターを使用して、そのセルから 3 つの端末のそれぞれに戻るパスを再構築します。 これらのパス上のすべてのセルは土地としてマークされます。 

必要に応じて、元の 3 つの陸上セルも保存します。 

### 5. 最終的なグリッドを出力します。 

再構築されたすべてのパス セルをランドとしてマークした後、グリッドを印刷します。 

### なぜ効果があるのか

 重要な不変条件は、固定された会議セルの場合、そのセルを通過するように制約されているすべての接続されたサブグラフ間で、そのセルから各端末までの最短パスの和集合が最小であることです。 3 つの端末に対する最適なソリューションには、パスが合流する中心が必要であるため、すべての可能な合流セルを列挙することで、真の最適なシュタイナー構造を評価することが保証されます。 BFS は各ブランチが個別に最短であることを保証するため、冗長な迂回が導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**9

def bfs(start, r, c, grid):
    dist = [[INF] * c for _ in range(r)]
    par = [[None] * c for _ in range(r)]
    
    sr, sc = start
    dist[sr][sc] = 0
    q = deque([(sr, sc)])
    
    while q:
        x, y = q.popleft()
        for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < r and 0 <= ny < c:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    par[nx][ny] = (x, y)
                    q.append((nx, ny))
    return dist, par

r, c = map(int, input().split())
grid = [list(input().strip()) for _ in range(r)]

terms = []
for i in range(r):
    for j in range(c):
        if grid[i][j] == '#':
            terms.append((i, j))

dists = []
pars = []

for t in terms:
    d, p = bfs(t, r, c, grid)
    dists.append(d)
    pars.append(p)

best_cost = INF
best_cell = None

for i in range(r):
    for j in range(c):
        cost = dists[0][i][j] + dists[1][i][j] + dists[2][i][j]
        if cost < best_cost:
            best_cost = cost
            best_cell = (i, j)

def mark_path(par, start, end, mark):
    x, y = start
    ex, ey = end
    while (x, y) != (ex, ey):
        mark.add((x, y))
        x, y = par[x][y]
    mark.add((ex, ey))

mark = set()
for i in range(3):
    mark_path(pars[i], best_cell, terms[i], mark)

for x, y in mark:
    grid[x][y] = '#'

for row in grid:
    print(''.join(row))
```BFS 関数は、距離ポインターと親ポインターの両方を構築します。これらは、選択したシュタイナー ツリー ブランチを後で再構築するために不可欠です。 トリプル BFS は独立しており、それぞれが元の陸上セルの 1 つに根付いています。 

すべてのグリッド セルにわたるネストされたスキャンにより、最適なミーティング ポイントが選択されます。 これは O(r・c) ですが、操作数はわずか 10,000 回であり、十分に制限内です。 

再構築ステップでは、保存されている親を使用して、ミーティング ポイントから各端末まで慎重に逆方向に進みます。 これにより、パスの再計算や追加の BFS の実行が回避されます。 セットは、パスが重複する場合に重複マーキングを避けるために使用されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    from collections import deque

    INF = 10**9

    def bfs(start, r, c, grid):
        dist = [[INF] * c for _ in range(r)]
        par = [[None] * c for _ in range(r)]
        sr, sc = start
        dist[sr][sc] = 0
        q = deque([(sr, sc)])
        while q:
            x, y = q.popleft()
            for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
                nx, ny = x+dx, y+dy
                if 0 <= nx < r and 0 <= ny < c:
                    if dist[nx][ny] > dist[x][y] + 1:
                        dist[nx][ny] = dist[x][y] + 1
                        par[nx][ny] = (x, y)
                        q.append((nx, ny))
        return dist, par

    r, c = map(int, input().split())
    grid = [list(input().strip()) for _ in range(r)]

    terms = [(i,j) for i in range(r) for j in range(c) if grid[i][j] == '#']

    dists, pars = [], []
    for t in terms:
        d, p = bfs(t, r, c, grid)
        dists.append(d)
        pars.append(p)

    best = 10**18
    best_cell = None
    for i in range(r):
        for j in range(c):
            cost = dists[0][i][j] + dists[1][i][j] + dists[2][i][j]
            if cost < best:
                best = cost
                best_cell = (i, j)

    mark = set()
    def add(par, start, end):
        x, y = start
        ex, ey = end
        while (x, y) != (ex, ey):
            mark.add((x, y))
            x, y = par[x][y]
        mark.add((ex, ey))

    for i in range(3):
        add(pars[i], best_cell, terms[i])

    out = []
    for i in range(r):
        row = []
        for j in range(c):
            row.append('#' if grid[i][j] == '#' or (i,j) in mark else '.')
        out.append(''.join(row))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つの端末がすでに隣接しているか、ほぼ接続されている場合です。 その状況では、最適なミーティング ポイントは端末の 1 つに直接存在する可能性があります。これは、1 つの BFS パスの長さがゼロであることを意味します。 端末から端末自体までの BFS 距離がゼロであり、距離の合計の最小化によりそのセルが有効なミーティング ポイントとして正しく選択されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、最短パスが重なり合う場合です。 たとえば、2 つの端末が回廊状の領域にある場合、それらの BFS パスは早期にマージされます。 再構築ではマークされたセルのセットを使用するため、重複するセグメントが出力で二重にカウントされたり重複したりすることはなく、コストを増大させることなく正確性が維持されます。
