 ## 解決策
 ## 問題の理解

 私たちには n 個の派閥の列が与えられており、それぞれが西から東の固定された順序で座っており、それぞれが富の価値を持っています。 時間の経過とともに、派閥は 1 つずつ消滅し、最終的には 1 つの派閥だけが残ります。 どの勢力が消滅するかを決定するルールは、現在の富の分布から計算された世界情勢に依存します。 

ある派閥が厳密に他のすべての派閥の合計よりも多くの富を持っている場合、システムは常に覇権状態にあると言われます。 同様に、現在の最大資産価値が総資産の半分より大きい場合。 

各ステップでは、派閥を 1 つだけ削除します。 システムが覇権を握っていない場合、最大の富を持つ人々の中で最も西側の派閥が排除されます。 覇権を握っている場合は、最低限の富を持つ人々の中で最も西側の勢力が排除される。 除去後、除去された陣営の直接に生き残っている隣接勢力（西側に最大 1 人、東側に最大 1 人）がそれぞれフロア（removed_wealth / 2）を獲得します。 削除された派閥は永久に消滅します。 

出力では、再配布が行われる前に、削除命令と、削除された各勢力のラベルと資産を、削除の正確な瞬間に報告する必要があります。 

この制約では最大 200,000 の派閥が許可され、各削除は一定数の隣接要素のみに影響するため、ステップごとに線形の作業を行うソリューションはすでに遅すぎます。 n が十分に大きいため、スキャンや構造の再構築を繰り返すと通常の時間制限を桁違いに超える可能性があるため、2 次の動作や n の 2 乗に近い動作は直ちに実行不可能になります。 

微妙な問題は、選択 (動的重みによる最大値または最小値) と更新 (削除後の隣接値の増加) の両方が繰り返し発生することです。 削除のたびにグローバルな最小値、最大値、ヘゲモニーを最初から再計算する単純なアプローチでは、ステップごとに最大 n 個の要素が繰り返しスキャンされ、O(n^2) の動作が発生します。 

もう 1 つの重要なエッジ ケースは、値が同値であることです。 複数の派閥が同じ最大または最小の富を共有する場合、最も西側の派閥を選択する必要があります。 このため、インデックスの順序付けが不可欠になります。 これを無視すると、重み付けロジックが正しい場合でも、削除順序が間違ってしまいます。 また、近隣更新ではフロア分割が使用されるため、1 の半分の寄与がゼロになり、誤って不要なヒープ更新をトリガーしてはなりません。 

## アプローチ

 直接シミュレーションでは、派閥のアクティブなリストを保持し、それを繰り返しスキャンして、現在の最大値、最小値、および合計を決定します。 削除するたびに、必要な統計をすべて再計算し、近隣を更新します。 これは正しいですが、コストがかかります。各ステップで O(n) 回のスキャンが行われ、n 回繰り返されるため、結果として O(n^2) になります。 n が 2×10^5 までの場合、これは許容範囲をはるかに超えています。 

重要な観察は、プロセスの構造が局所的であるということです。 ステップごとに 1 つのノードだけが削除され、その 2 つの隣接ノードのみが重みを変更します。 それ以外はすべて変更されません。 これは、グローバルな順序付けを最初から再計算する必要がないことを意味します。 必要なのは、タイブレークによる重みによる現在の最大値の抽出、タイブレークによる重みによる現在の最小値の抽出、および個々のノードに小さな増分更新を適用するという 3 つの操作を効率的にサポートする構造だけです。 

これはまさに、遅延削除を備えたヒープのペアが提供するものです。 私たちは、現在の重みとインデックスをキーとする 1 つの最大指向の優先順位構造と 1 つの最小指向の優先順位構造を維持します。 重みが変化すると、各ヒープ エントリが失効する可能性があるため、ポップ時に現在保存されている重みに対してエントリを検証します。 近隣の更新は、新しいバージョンを両方のヒープにプッシュすることによって処理されます。 

また、派閥を削除した後、O(1) でその西側と東側の生き残った隣接勢力をスキャンせずにすぐに見つけられるように、二重リンク リストも維持します。 

これにより、各ステップが O(log n) に削減され、全体として O(n log n) のソリューションが得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(n²) | O(n) | 遅すぎる |
 | ヒープ + リンク リストのシミュレーション | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 現在の重みの配列、生存インデックスの二重リンクリスト、およびすべての重みの現在の合計を初期化します。 また、(-weight, Index) をキーとする最大ヒープと (weight, Index) をキーとする最小ヒープの 2 つのヒープも初期化します。 インデックスのタイブレークにより、最西側の優先順位が常に尊重されます。 
2. 現在の最大重みが total_sum - minimum_weight を超えているかどうかを確認することによって、システムが覇権を握っているかどうかを繰り返し判断します。 最大重みは、有効なエントリが見つかるまで古いエントリを破棄することによって、最大ヒープから取得されます。 このステップは、ノードごとの最新の重みのみが正しいとみなされるため機能します。 
3. 覇権を握っていない場合は、最大ヒープを使用して削除するノードを選択します。 覇権を握っている場合は、最小ヒープを使用して選択します。 どちらの場合も、保存されている重みがヒープ キーと一致し、まだ生きているノードに到達するまで、古いヒープ エントリをスキップします。 
4. 選択したノードのインデックスと現在の重みを出力の一部として記録します。 次に、合計からその重量を差し引きます。 
5. 西側と東側の隣接ノードを直接接続して、リンク リストからノードを削除します。 これにより、スキャンせずに隣接構造が維持されます。 
6. 既存の各近隣 (存在する場合は西と東) について、増分を Floor(removed_weight / 2) として計算します。 増分がゼロ以外の場合、その近隣の重みを更新し、新しい (重み、インデックス) 状態を両方のヒープにプッシュします。 
7. 削除されたノードを非アクティブとしてマークし、それを参照する今後のヒープ エントリが無視されるようにします。 
8. ノードが 1 つだけ残るまで繰り返します。 

これが機能する理由は、すべての決定が現在の重みのマルチセットとその順序極値のみに依存し、両方を増分的に維持できるためです。 ヒープには古いエントリが含まれている可能性がありますが、ヒープ エントリを積極的に削除することはないため、正確性は保たれます。 代わりに、抽出時に信頼できる重み配列に対して検証します。 リンク リストにより、削除によって隣接関係が再形成されても、近隣クエリが正しいままであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    
    if n == 1:
        return
    
    alive = [True] * n
    left = [i - 1 for i in range(n)]
    right = [i + 1 for i in range(n)]
    right[n - 1] = -1

    total = sum(w)

    maxh = []
    minh = []

    for i, val in enumerate(w):
        heapq.heappush(maxh, (-val, i))
        heapq.heappush(minh, (val, i))

    def clean_max():
        while maxh:
            negv, i = maxh[0]
            if not alive[i] or w[i] != -negv:
                heapq.heappop(maxh)
            else:
                return

    def clean_min():
        while minh:
            v, i = minh[0]
            if not alive[i] or w[i] != v:
                heapq.heappop(minh)
            else:
                return

    def get_max():
        clean_max()
        return -maxh[0][0], maxh[0][1]

    def get_min():
        clean_min()
        return minh[0][0], minh[0][1]

    for _ in range(n - 1):
        mx, _ = get_max()
        if mx * 2 > total:
            _, i = get_min()
        else:
            _, i = get_max()

        wi = w[i]
        print(i + 1, wi)

        total -= wi
        alive[i] = False

        l = left[i]
        r = right[i]

        if l != -1:
            right[l] = r
        if r != -1:
            left[r] = l

        add = wi // 2

        if l != -1:
            w[l] += add
            heapq.heappush(maxh, (-w[l], l))
            heapq.heappush(minh, (w[l], l))

        if r != -1:
            w[r] += add
            heapq.heappush(maxh, (-w[r], r))
            heapq.heappush(minh, (w[r], r))

solve()
```このソリューションは、現在の状態を 3 つの同期構造 (真実のソースとしての重み配列、高速極値クエリ用のヒープ、および隣接関係用のリンク リスト) に保持します。 重要な実装の詳細は、ヒープ内の遅延削除です。 ノードの重みが変更されたときに古いエントリを削除する代わりに、更新された状態をプッシュするだけです。 候補を抽出するとき、現在の重みと一致しなくなったヒープ エントリ、または削除されたノードを参照するヒープ エントリは破棄されます。 

もう 1 つの微妙な点は、覇権チェックです。 現在の合計を維持することで、残りのすべてのノードの合計を再計算することを回避します。 条件は、ヒープから抽出された現在の最大値を使用してチェックされます。 

インデックスのタイブレークは、インデックスを 2 番目のヒープ キーとして保存することによって暗黙的に処理されます。 max-heap の場合、重みを反転しますが、インデックスの昇順を維持するため、等しいものの中から最も西のものが選択されます。 min-heap の場合は、(weight,index) を直接使用します。

 ## 特殊なケース

 エッジ ケースの 1 つは、フロア分割で更新がゼロになる場合です。 削除された派閥の富が 1 の場合、隣接する派閥はどちらも 0 を受け取ります。単純な実装では依然として不必要にヒープ更新をプッシュする可能性がありますが、正確性を保つために値を変更する必要はありません。 実装では、動作を変更せずに同じ重みが再挿入される可能性があるため、add = wi // 2 をチェックして安全にプッシュすることでこれを処理します。 

もう 1 つのケースは、同じノードに対する複数の更新により、古いヒープ エントリが繰り返されることです。 たとえば、ノードは削除される前にいくつかの増分を受け取る場合があります。 ヒープには複数の古いバージョンが含まれますが、遅延削除メカニズムにより最新の重みのみが確実に受け入れられるため、古いエントリは無視されます。 

3 番目のケースは、境界付近での隣接関係の更新です。 削除された派閥が端にある場合、隣接する派閥は 1 つだけになります。 リンク リスト表現では、-1 を使用して欠落している近傍を自然に処理し、更新ロジックは境界チェックを超えた特別なケースを使用せずに、単純に存在しない辺をスキップします。
