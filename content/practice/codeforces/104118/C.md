 ## 解決策
 ## 問題の理解

 学生のシャツに書かれた値を表す整数の配列が与えられます。 毎日、すべてのポジションがグローバル統計に基づいてその値を同時に更新します。`v`の出現数になります`v`その日のアレイ全体で。 

したがって、プロセスはローカルではありません。 すべての要素は配列全体を調べ、その現在の値が何回出現するかを計算し、それ自体をそのカウントで置き換えます。 この動作を繰り返す`k`最終的な配列が必要になります。 

重要な難点は、`k`と同じ大きさにすることができます$10^9$, そのため、単純な方法で毎日シミュレーションすることはできません。 

この制約は、配列の長さが最大であることを意味します。$2 \cdot 10^5$したがって、実行されるステップごとの解は線形または線形演算に近くなければならず、実行されるステップの数は非常に少なくなければなりません。 何かに比例するもの`k`すぐには無理です。 

微妙なエッジ ケースは、値が次のように大きくなる可能性があるという事実から生じます。$10^9$ただし、最初の変換後、すべての値は範囲内に収まります。$[1, n]$を超えることはできないため、周波数は`n`。 この崩壊は、問題を扱いやすくする重要な構造的単純化です。 

素朴だが重要な間違いは、値が増加し続ける、またはランダムに動作すると仮定することです。 たとえば、次のことを考えてみましょう。 

入力:```
5 2
100 100 100 200 300
```1日後:```
3 3 3 1 1
```2日目以降:```
3 3 3 2 2
```変換はすべてのステップでの正確な頻度カウントに完全に依存するため、個別の値のみを追跡しようとしたり、多重度を無視したりする不用意な実装は、ここでは失敗します。 

別の障害モードは、プロセスが多くの異なる構成を取る可能性があることを想定しています。 実際には、システムはすぐに崩壊して安定状態または短サイクル状態になります。 

## アプローチ

 ブルートフォースアプローチは、次のプロセスを直接シミュレートします。`k`繰り返し。 各反復では、現在の配列の周波数マップを構築し、そのマップを使用してすべての要素を書き直す必要があります。 各反復のコスト$O(n)$したがって、全体の複雑さは次のようになります。$O(nk)$、これは実現不可能です。$k = 10^9$。 

重要な観察は、変換によって大きな構造が急速に破壊されるということです。 最初のステップの後、すべての値は周波数になるため、次の制限を受けます。`n`。 その後、システムは小さな整数の範囲内でのみ進化し、急速に安定します。これは、周波数対周波数を繰り返し適用しても、固定サイズのアレイ上に無限に新しい構成を生成できないためです。 経験的および構造的に、シーケンスは非常に少ないステップ (これらの制約の下では最悪でも 10 ステップ程度) の後で一定になります。 

これは、少数のステップ、特に最大で`k`ただし、配列が安定する小さな定数境界によって制限されます。

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 最初の配列から始めます。 

毎日を、前の配列の頻度分布のみから派生したまったく新しい配列を生成するものとして扱います。 
2. までの変換を繰り返します。`k`ただし、配列の変更が停止した場合は早期に停止します。 

ある反復のすべての値の場合`v`すでに次の周波数に等しい`v`、システムは固定点に達しており、それ以上の操作は何も行われません。 
3. 1 つの変換を実行するには、現在の配列の頻度テーブルを計算します。 

これにより、各値が何回出現したかが取得されます。これが、次の状態に必要な唯一の情報です。 
4. 各要素を置き換えて次の配列を構築します`a[i]`と`freq[a[i]]`。 

このステップはすべてのポジションに同時に適用されるため、常に前のスナップショットに基づいて更新されます。 
5. 反復中に配列が変更されたかどうかを追跡します。 

値が変更されない場合は、さらなる反復で同じ結果が繰り返されるため、早期に中断します。 
6. 最悪の場合の反復回数を回避するには、シミュレーションの上限を小さな定数 (約 60 反復) に設定します。 

値は以下によって制限されるため、システムはこの深さを超えて有意義に進化することはできません。`n`安定した周波数構造に繰り返し圧縮します。 

### なぜ効果があるのか

 変換では常に配列が次の境界を持つ空間にマップされます。`[1, n]`最初のステップの後。 その時点以降、システムの状態は、固定された有限範囲にわたるマルチセットによって完全に決定されます。 各反復では、このマルチセットのみに基づいて決定的な圧縮が適用され、圧縮を繰り返すことで構造の変動が迅速に除去されます。 最終的に、操作を再度適用すると同じ配列が得られ、システムが固定点になります。 安定化するまで、または安定化に達するまで明示的にシミュレーションしているため、`k`、その日の正確な状態と一致します`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def transform(a):
    n = len(a)
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    return [freq[x] for x in a]

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k == 0:
        print(*a)
        return

    seen = 0
    while seen < k:
        b = transform(a)
        if b == a:
            break
        a = b
        seen += 1
        if seen >= 60:
            break

    # If k is larger than stabilization point, we already stabilized
    print(*a)

if __name__ == "__main__":
    solve()
```このソリューションは、反復ごとに頻度辞書を計算し、直接検索によって配列を再構築します。 停止条件は、反復によって何かが変更されるかどうかをチェックします。これは固定点を示します。 追加の反復上限により、病的な推論の場合でも過剰なシミュレーションが行われないことが保証されます。 

実装の重要な詳細は、各変換が部分的に更新された値ではなく、以前の配列スナップショットに基づいている必要があるということです。これは、新しいリストを構築することで保証されます。`b`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        def transform(a):
            freq = defaultdict(int)
            for x in a:
                freq[x] += 1
            return [freq[x] for x in a]

        for _ in range(min(k, 60)):
            b = transform(a)
            if b == a:
                a = b
                break
            a = b

        print(*a)

    solve()
    return sys.stdout.getvalue().strip()

assert run("7 2\n6 7 1 1 1 9 9") == "2 2 3 3 3 2 2"

assert run("6 3\n1 2 2 3 3 3") == run("6 3\n1 2 2 3 3 3"), "deterministic stability"

 ## 特殊なケース

 エッジケースの 1 つは、すべての要素が同一である場合です。 その値の頻度は`n`したがって、1 ステップの後、配列全体が定数になります。`n`。 次に 2 番目のアプリケーションがマッピングします`n`その周波数、つまり`n`再度実行すると、システムはすぐに安定します。 

もう 1 つのケースは、すべての値が異なる場合です。 各値は 1 回だけ出現するため、最初の変換によりすべての要素が次のように変換されます。`1`。 その後、配列はすでに均一になっており、これ以上のステップは何も行われません。 これは、敵対的な入力に対しても収束が非常に速い理由を示しています。 

3 番目のケースは、繰り返される一意の値の混合です。 例えば`1 2 2 3 3 3`すぐに小さな周波数セットに崩壊し、その後安定します。 各反復でグローバル ヒストグラムを最初から再計算し、以前の構造に関係なく一貫性を確保するため、アルゴリズムはこれを自然に処理します。
