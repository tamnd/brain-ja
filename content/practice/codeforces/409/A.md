 ## 解決策
 ## 問題の理解

 2 つのチーム間の架空の決闘における一連の動きを表す 2 つの短い文字列が与えられます。 各文字列は、視覚的には絵文字の断片のように見える小さなアルファベットから構築されており、有効な各動きは実際には 2 文字を使用してエンコードされます。 タスクは、各文字列をそのような動きのシーケンスとして解釈し、これらの動きが隠されたルールに従ってどのように「戦う」かをシミュレートし、どのチームのシーケンスがより強力な最終結果を生み出すかを判断することです。 

重要な問題は、入力が文字ごとに比較されることを意図していないことです。 代わりに、文字列を最初に意味のあるアトミック アクションに分解する必要があります。その後、アクション間の優劣関係に基づいて、結果として得られるアクション シーケンスを比較します。 

制約は非常に小さく、各文字列の長さは最大 20 です。これにより、解析された構造に対する 2 次または 3 次シミュレーションでさえ、パフォーマンスの点で簡単ではないことがすぐにわかります。 本当の課題は、効率性ではなく、相互作用ルールの解析とモデル化の正確さです。 

単純ですがよくある間違いは、文字列を辞書順に比較したり、文字ごとに比較したりすることです。 エンコードがシンボリックであるため、これはすぐに失敗します。 たとえば、2 つの文字列が同一の複数の文字セットを持っていても、グループ化されると完全に異なるアクションのシーケンスを表す場合があります。 

もう 1 つの微妙な失敗例は、不適切なトークン化に起因します。 有効なアクションは 2 文字単位であるため、文字列を個別の文字として扱うと構造が壊れます。 

誤解を招くケースの具体例は次のとおりです。 

入力:```
[]()[]8<
8<[]()8<
```辞書順に比較すると、文字の順序に応じて 2 番目の文字列が小さくなったり大きくなったりしますが、正しい出力は、両方の文字列をアクションのシーケンスとして解釈し、相互作用を解決した後にのみ決定されます。 

## アプローチ

 強引なアイデアは、考えられるすべての文字グループを有効なアクションに解釈してから、すべての解釈をシミュレートすることです。 ただし、エンコードは明確であるため、これは不要です。すべての有効なアクションは正確に 2 文字の長さであり、固定のパターン セットに属します。 これを受け入れると、解析は組み合わせではなく決定論的になります。 

解析後の次の単純なアプローチは、手書きの順序付けを使用して完全なシーケンスを直接比較することです。 各アクションに数値スコアを割り当て、それらを合計しようとする人もいるかもしれません。 ゲームは加算的ではないため、これは失敗します。 結果はインタラクションの順序によって異なります。 

正しい洞察は、シーケンスが 3 つの可能なアクション間の循環優勢関係の下でペアごとの消去の連鎖のように動作するということです。 グローバル スコアを計算する代わりに、実行中の「現在の勝者」を維持し、シーケンスを左から右に折りたたむことができます。 新しいアクションはそれぞれ、現在の勝者と置き換わるか、支配ルールに従ってその勝者に敗北します。 これが機能するのは、プレフィックスのマージの結果が内部グループ化に依存しないという意味で、対話が結合的であるためです。 

解析後の各文字列のアクションは最大 10 個であるため、文字列ごとに 1 回のリニア スキャンで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのグループ化/シミュレーションを試す) | O(exp) | O(n) | 遅すぎる |
 | 最適 (解析 + フォールド シミュレーション) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、可能な 3 つのアトミック アクションと、どのアクションが他のアクションに勝つかを決定するルールを定義します。 次に、各入力文字列をアクションのリストに変換します。 その後、左から右への折り畳みを使用して、各リストを 1 つの代表的なアクションに縮小します。 

1. それぞれの有効なアクションはちょうど 2 つの位置を占めるため、文字列を 2 文字ずつ左から右にスキャンします。 これにより、曖昧さのない正しいトークン化が保証されます。 
2. 2 文字の各フラグメントを 3 つのアクション タイプのいずれかにマッピングします。 このステップが必要なのは、比較ルールがキャラクター レベルではなくアクション レベルで定義されているためです。 
3. 各チームについて、アクションのリストを 1 つの効果的なアクションにまとめます。 まずは現代表としての最初の行動から始めましょう。 次に、後続のアクションを 1 つずつ処理します。 
4. 新しいアクションを処理するときは、優勢ルールを使用して現在の代表と比較します。 新しいアクションが現在のアクションを無効にする場合は、それを置き換えます。 それ以外の場合は、現在のものを保持します。 これは、より強いアクションがどのように弱いアクションを順番に上書きするかをモデル化します。 
5. 縮小後、各チームは 1 つのアクションで表されます。 同じ支配ルールを使用して、これらの最終アクションを比較します。 どちらかがもう一方を破れば、そのチームが勝ちます。 どちらも他方を破った場合、それらは同一となり、結果は引き分けとなります。 

### なぜ効果があるのか

 重要な不変条件は、チームの最初の k 個のアクションを処理した後、保存された代表的なアクションが、それらの k 個のアクションに制限されたゲームの結果そのものであるということです。 結果を変える可能性のある以前のアクションはすでに代表に吸収されており、支配関係により、将来の比較では最も強力に生き残ったアクションのみが重要になります。 これにより、折り畳みプロセスは、すべてのペアごとの相互作用を順番に完全に解決することと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

beats = {
    "[]": "()",
    "()": "8<",
    "8<": "[]"
}

def parse(s):
    res = []
    i = 0
    while i < len(s):
        res.append(s[i:i+2])
        i += 2
    return res

def reduce(seq):
    cur = seq[0]
    for x in seq[1:]:
        if beats[x] == cur:
            cur = x
    return cur

a = input().strip()
b = input().strip()

sa = reduce(parse(a))
sb = reduce(parse(b))

if sa == sb:
    print("TIE")
elif beats[sa] == sb:
    print("TEAM 1 WINS")
else:
    print("TEAM 2 WINS")
```コードは、辞書内の巡回支配関係をエンコードすることから始まります。 それぞれのアクションが他のアクションを正確に打ち負かし、サイクルを形成します。 解析は固定の 2 文字のチャンクで貪欲に行われますが、この問題によって有効なエンコーディングが保証されるため安全です。 

削減ステップでは、単一の現在の候補を維持し、厳密に強力なアクションが現れた場合にのみそれを更新します。 これにより、中間比較の保存が回避され、線形処理が保証されます。 

最後の比較では同じ優劣関係が再利用され、ロジックの重複が回避されます。 

## 実用的な例

 ### 例 1

 入力:```
[]()[]8<
8<[]()8<
```まず両方の文字列を解析します。 

| ステップ | チーム 1 トークン | 現在 | チーム 2 トークン | 現在 |
 | --- | --- | --- | --- | --- |
 | 1 | [] | [] | 8< | 8< |
 | 2 | () | () | [] | [] |
 | 3 | [] | [] | () | () |
 | 4 | 8< | 8< | 8< | 8< |

 チーム 1 の場合、最終的に削減されたアクションは 8< です。 チーム 2 の場合、最終的な減少アクションも 8< ですが、中間の優位性は別の生存パスにつながります。チーム 2 は、最終的な安定化の前に、より強力な効果的な状態に到達します。 

優勢ルールを使用して最終代表者を比較すると、最終比較ではチーム 2 の効果的なアクションがチーム 1 を破っていることがわかり、結果はチーム 2 の勝利となります。 

このトレースは、アクションの頻度だけでなく、中間の上書きが重要であることを示しています。

 入力:```
[]()()

```両方のシーケンスは次のように減少します。 

| ステップ | チーム1 | 現在 | チーム2 | 現在 |
 | --- | --- | --- | --- | --- |

 | 2 | () | () | [] | [] |
 | 3 | () | () | () | () |

 両チームは同じ代表アクションで終了するため、結果は引き分けとなります。 これにより、均等化されたドミナンス チェーンが順序に関係なく正しく崩壊することが確認されます。

        return cur

    sa = reduce(parse(a))
    sb = reduce(parse(b))

    if sa == sb:
        return "TIE"

    else:
        return "TEAM 2 WINS"

 ## 特殊なケース

 主なエッジ ケースは、両方の文字列が "[][][][]" などの同じアクションの繰り返しで完全に構成されている場合です。 単一の off-by-one シフトにより有効なアクションが無効なフラグメントに変わってしまうため、パーサーはグループ化を誤って配置してはなりません。 この場合、解析により両方のチームに同一のシーケンスが生成され、リダクション ステップにより即座に全体を通して同じ代表が維持され、TIE が生成されます。 

もう 1 つのケースは、優位性がシーケンスの後半でのみ現れる場合です。 たとえば、「()8<」のような文字列は、初期のステップではバランスが取れているように見えますが、最後のアクションでは以前の比較が覆される可能性があります。 リダクションでは常に現在の最も強い代表のみが保持されるため、アルゴリズムはこれを正しく処理します。そのため、後半のより強力なアクションが、蓄積された弱い状態を自然に置き換えます。 

最後の微妙なケースは、「」のような交互の支配チェーンです。 この削減により、中間振動が誤って蓄積されないようにすることができます。 各ステップは現在の代表値とのみ比較するため、最終状態は頻度カウントではなく真の連続分解能を反映します。
