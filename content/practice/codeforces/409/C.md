 ## 解決策
 ## 問題の理解

 この問題により、いくつかの錬金術成分の量を表す整数のリストが得られます。 目標は、これらの量の最大公約数 (GCD) を決定することです。 言い換えれば、最大の整数を見つけたいのです$d$与えられた各数値が次の数で割り切れるようになります。$d$。 

入力配列には、それぞれ 0 から 100 の範囲の要素を最大 100 個含めることができます。数値が小さいため、単純な算術演算でも高速ですが、ゼロには注意する必要があります。数値の GCD とゼロは数値そのものであるため、ゼロを無視すると間違った答えが得られる可能性があります。 

微妙な特殊なケースは、すべての数値がゼロの場合です。 この場合、数学的には GCD は未定義ですが、この問題の文脈では 0 を返すか一貫して処理するのが通例です。 もう 1 つのケースは、1 つの数値だけがゼロでない場合です。GCD はまさにその数値です。 1 から最小の数値までのすべての候補の割り算を単純に反復してチェックすることは機能しますが、不必要に時間がかかり、さらに重要なことに、数値の範囲が大きい場合には拡張できません。 

出力は単一の整数、つまりすべての入力値の GCD です。 これは、すべての量を均等に分割できる最大の「バッチ サイズ」に直接対応します。 

## アプローチ

 ブルートフォース ソリューションでは、1 から入力数値の最小値までのすべての整数を反復処理し、すべての要素が分割されているかどうかを確認します。 これが機能するのは、数値がすべての要素を分割する場合、その数値が最小の要素より大きくてはいけないためです。 入力サイズの場合、最小数は最大 100 であるため、この問題ではこのアプローチは実行可能です。 ただし、一般的に、数値が最大であれば、$10^9$、最小値まで反復すると遅すぎるため、$O(n \cdot \text{min}(a_i))$操作。 

より洗練されたソリューションのための重要な洞察は、ユークリッド アルゴリズム、つまり 2 つの数値の GCD から得られます。$x$そして$y$次のように再帰的に計算できます$\gcd(y, x \% y)$。 この方法は、モジュロ演算ごとに問題のサイズが大幅に縮小され、数値自体が対数的に複雑になるため高速です。 これを複数の数値に拡張するのは簡単です。配列の GCD は次のようになります。$\gcd(\gcd(a_1, a_2), a_3, ..., a_n)$。 

ブルートフォース手法は数値が小さいため機能しますが、数値が大きくなると失敗します。 ユークリッドのアプローチは、問題を対数時間が保証された一連の単純な演算に縮小し、より大きな入力に対して堅牢になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * min(a_i)) | お(1) | 数値が小さい場合は機能しますが、数値が大きい場合は遅すぎます。 
| ユークリッドGCD | O(n * log(max(a_i))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力から整数のリストを読み取ります。 これらは成分の量を表します。 
2. 変数を初期化する`current_gcd`配列の最初の数値に置き換えます。 これは実行中の GCD として機能します。 
3. 配列の残りの部分を繰り返し処理します。 番号ごとに更新します`current_gcd`の GCD になる`current_gcd`およびユークリッド アルゴリズムを使用した現在の数値。 これにより、各ステップの後に、`current_gcd`これまでに確認されたすべての数値を除算します。 
4. 反復が完了したら、`current_gcd`配列全体の GCD です。 この値を出力します。 

なぜ機能するのか: ユークリッド アルゴリズムは次のことを保証します。$\gcd(x, y)$は、x と y の両方を除算する最大の整数です。 すべての数値に繰り返し適用することで、次の不変式が得られます。`current_gcd`除算では、遭遇したすべての数値が維持されます。 この実行中の GCD より大きな数値ですべての要素を分割することはできないため、最終的な値は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd
from functools import reduce

# read input and convert to integers
arr = list(map(int, input().split()))

# compute gcd of the entire array using reduce
result = reduce(gcd, arr)

print(result)
```私たちが使用するのは`reduce`を折ります`gcd`配列全体で関数を実行します。 使用する`math.gcd`ユークリッド アルゴリズムを手動で実装することを回避し、正確さを保証します。 入力文字列を整数に変換する`map(int, ...)`入力内の任意のスペースを処理します。 ゼロのようなエッジケースは自動的に処理されます。`gcd(x, 0)`返品`x`。

## テストケース```python
import sys, io
from math import gcd
from functools import reduce

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    arr = list(map(int, input().split()))
    return str(reduce(gcd, arr))

# provided sample
assert run("2 4 6 8 10\n") == "2", "sample 1"

# single element
assert run("42\n") == "42", "single element"

# all zeros
assert run("0 0 0\n") == "0", "all zeros"

# mixed zeros
assert run("0 6 12 18\n") == "6", "zeros and non-zeros"

# all equal
assert run("7 7 7 7 7\n") == "7", "all equal numbers"

# prime numbers
assert run("3 5 7 11\n") == "1", "coprime numbers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 42 | 42 | 単一要素のエッジケース |
 | 0 0 0 | 0 | すべてのゼロが正しく処理されました。 
| 0 6 12 18 | 6 | ゼロは GCD を壊しません |
 | 7 7 7 7 7 | 7 | 同じ数値は GCD を減少させません。 
| 3 5 7 11 | 1 | 互いに素な数値は 1 を返します |

 ## 特殊なケース

 入力にゼロのみが含まれている場合、次のようになります。`0 0 0`、`reduce(gcd, arr)`正しくは 0 を返します。入力が`[0, 6, 12]`、アルゴリズムはゼロを中立要素として扱います。`gcd(x, 0) = x`したがって、実行中の GCD は 6 で安定します。単一要素配列の場合`[42]`の場合、アルゴリズムはその数値を正しく返します。 

すべてのエッジケースはユークリッド アルゴリズムによって自然に処理され、`reduce`したがって、追加の条件は必要ありません。
