 ## 解決策
 ## 問題の理解

 2 つの王国間の国境は、垂直方向に等しい間隔で積み重ねられた 3 本の水平線で構成されています。 各線にはいくつかの「穴」があり、それぞれが水平軸に沿った整数の位置にあります。 硬い針は、3 本の線それぞれにあるちょうど 1 つの穴を同時に通過する場合にのみ、境界線を通過できます。 針は交差中は硬くて真っ直ぐであるため、選択された 3 つの穴は平面内の単一の直線上になければなりません。 

上部、中間、下部のバリアをそれぞれ垂直座標 2、1、0 に配置すると、各穴は (x, 2)、(x, 1)、または (x, 0) の形式の点になります。 有効な避難通路は、各レベルから 1 つずつ、3 つの点が同一線上にある 3 つの穴です。 タスクは、そのようなトリプルがいくつ存在するかを数えることです。 

この制約により、レベルごとに最大 50,000 個のホールが許可され、座標は -30000 から 30000 までの比較的小さい整数範囲になります。ホールのすべての 3 つをチェックするのは、最悪の場合でも 10¹4 回のオーダーになるため、これにより、すべてのレベルにわたる 3 次または 2 次のペアが即座に排除されます。 中央の穴ごとに上位レベルと下位レベルの間で単純なペアごとのマッチングを行う場合でも、最大 2.5 × 10⁹ の操作が必要ですが、Python では遅すぎます。 

浮動小数点の傾きについて考えると、微妙な問題が生じます。 共線性は勾配を使用してチェックできますが、繰り返し行うと精度の問題が発生し、すべての点が 3 つの固定された水平線上にあるため不要です。 この構造により、条件は X 座標に関する純粋な算術演算になります。 

いくつかの特殊なケースについては、明示的に説明する価値があります。 すべてのホールが 3 つのレベルすべてにわたって同じ x に整列している場合、すべての中央のホールは多くの有効なトリプルに参加します。 有効な線形アライメントがない場合、答えはゼロになります。 すべての穴が同じ範囲の周囲に密集している場合、ソリューションは最悪の場合の合計ポイント 150,000 点でも効率を維持する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、各レベルの 1 つのホールで構成されるすべてのトリプルが試行され、それらが同一線上にあるかどうかがチェックされます。 これは簡単です。上の穴、真ん中の穴、下の穴を選択し、傾斜の状態を確認します。 これは幾何学的拘束を明示的に適用するため正しく機能しますが、n_u × n_m × n_l の組み合わせが検査されます。 各 n が最大 50,000 であると、1.25 × 10¹⁴ チェックが必要となり、これは実行可能な制限時間をはるかに超えています。 

より構造化された観察は、共線性条件を代数的に書き直すことで得られます。 3 点を (x_u, 2)、(x_m, 1)、(x_l, 0) とします。 共線性とは、連続するセグメント間の傾きが等しいことを意味するため、x_m − x_u は x_l − x_m と等しくなければなりません。 並べ替えると、2x_m = x_u + x_l になります。 これにより、問題は幾何学からペアの合計を数える問題に変わります。 

これで、中間レベルがアンカーとして機能します。 各中央の穴 x_m について、x_u + x_l = 2x_m を満たすペア (x_u, x_l) がいくつあるかを知りたいと思います。 上位および下位のホール セットを有界整数領域にわたる周波数配列として解釈すると、固定合計に対するそのようなペアの数が上位分布と下位分布の間の畳み込みクエリになります。 

まさに、FFT による高速畳み込みが役立つのはこの場合です。 上部と下部のバリアの穴数を表す 2 つの配列を構築し、それらの畳み込みを計算します。 インデックス s での畳み込みにより、x_u + x_l = s となるペア (x_u, x_l) の数が得られます。 次に、中央のホール x_m ごとに、インデックス 2x_m で畳み込みをクエリし、結果を累積します。 

主な改善点は、O(n²) ペアリング プロセスを O(R log R) 畳み込み (R は座標範囲サイズ) に置き換えたことです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n_u · n_m · n_l) | お(1) | 遅すぎる |
 | 最適 (FFT 畳み込み) | O(R log R) | O(R) | 承認済み |

 ## アルゴリズムのチュートリアル

 座標を負でない範囲にシフトすることで座標を減らし、配列のインデックスとして使用できるようにします。 座標は [−30000, 30000] にあるため、すべてを +30000 シフトします。 

1. 上部のホール用に周波数アレイを構築し、下部のホール用に別の周波数アレイを構築します。 各インデックスには、その x 座標に存在する穴の数が格納されます。 これにより、セットが多重度を認識したベクトルに変換されます。 
2. FFT を使用して、上位および下位の周波数配列の畳み込みを計算します。 結果の配列`conv`シフト後の 1 つの上位座標と 1 つの下位座標の可能な合計によってインデックスが付けられます。 各エントリは、上部と下部の 1 つの穴を使用して合計を形成する方法が何通りあるかを表します。 
3. 中央の各穴の座標を反復処理します。`x_m`。 シフトインデックス形式に変換し、必要な合計値を計算します。`s = 2 * x_m + offset`ここで、オフセットは両方の端点の座標シフトを考慮しています。 
4. 蓄積する`conv[s]`答えに。 各寄与は、現在の中央のホールと一致する有効な (上部、下部) ペアの数に対応します。 
5. 最終的な累積カウントを出力します。 

中間層に焦点を当てる理由は、中間層が必要な合計制約を一意に決定し、3 方向の幾何学的条件を中間点ごとの 1 つの畳み込みルックアップに集約するためです。 

### なぜ効果があるのか

 すべての有効なパッセージは、正確に 1 つのトリプル (x_u、x_m、x_l) に対応します。 3 本の等間隔の水平線上の共線性の幾何学的制約は、一次方程式 2x_m = x_u + x_l と等価です。 畳み込みは、考えられるすべての合計について、その合計に達する上位と下位のペアの数を事前計算します。 各中央のホールは合計要件を独立して選択するため、これらの事前計算されたカウントを合計すると、重複や省略なしにすべての有効なトリプルが正確に列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def fft(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        ang = 2 * math.pi / length * (-1 if not invert else 1)
        wlen = complex(math.cos(ang), math.sin(ang))
        for i in range(0, n, length):
            w = 1 + 0j
            half = length // 2
            for j in range(half):
                u = a[i + j]
                v = a[i + j + half] * w
                a[i + j] = u + v
                a[i + j + half] = u - v
                w *= wlen
        length <<= 1

    if invert:
        for i in range(n):
            a[i] /= n

def convolution(a, b):
    n = 1
    while n < len(a) + len(b):
        n <<= 1
    fa = list(map(complex, a)) + [0] * (n - len(a))
    fb = list(map(complex, b)) + [0] * (n - len(b))

    fft(fa, False)
    fft(fb, False)

    for i in range(n):
        fa[i] *= fb[i]

    fft(fa, True)

    return [int(round(x.real)) for x in fa]

def solve():
    nu = int(input())
    upper = list(map(int, input().split()))
    nm = int(input())
    mid = list(map(int, input().split()))
    nl = int(input())
    lower = list(map(int, input().split()))

    SHIFT = 30000
    SIZE = 60001

    A = [0] * SIZE
    B = [0] * SIZE

    for x in upper:
        A[x + SHIFT] += 1
    for x in lower:
        B[x + SHIFT] += 1

    conv = convolution(A, B)

    ans = 0
    for x in mid:
        ans += conv[2 * (x + SHIFT)]

    print(ans)

if __name__ == "__main__":
    solve()
```FFT の実装では、反復的な Cooley-Tukey 変換が使用されます。 重要な実装の詳細は、すべての可能な合計を含めるのに十分な大きさの 2 のべき乗まで両方の配列をパディングすることです。 畳み込み出力インデックスはシフトされた座標の合計に直接対応するため、中間層のクエリは単純な配列アクセスになります。 

微妙なポイントは丸みです。 FFT は浮動小数点演算を使用するため、最終結果は最も近い整数に丸められます。 座標範囲は十分に小さいため、標準の倍精度では精度誤差は安全です。 

## 実用的な例

 上の穴が -1 と 1 にあり、真ん中の穴が 0 にあり、下の穴が -1 と 1 にある小さな構成を考えてみましょう。対称性を保つすべての組み合わせは、有効な直線を形成します。 

| 中央 x_m | 必要な合計 2x_m | 有効な上位と下位のペア | 貢献 |
 | --- | --- | --- | --- |
 | 0 | 0 | (−1,1)、(1,−1) | 2 |

 合計の答えは 2 です。 

このトレースは、明示的なペアリングを必要とするのではなく、単一の中央のホールが畳み込みテーブルへのクエリとしてどのように機能するかを示しています。 

次に、上 = [0, 1]、中 = [0, 1]、下 = [0, 1] である 2 番目のケースを考えてみましょう。 値が 2x_m = x_u + x_l を満たす組み合わせのみが機能します。 

| x_m | 2x_m | 有効なペア | カウント |
 | --- | --- | --- | --- |
 | 0 | 0 | (0,0) | 1 |
 | 1 | 2 | (1,1) | 1 |

 合計は 2 です。 

これにより、複数のホールが座標を共有している場合でも、畳み込みが多重度を正しく集計していることが確認できます。

 ## 特殊なケース

 重要なエッジケースは、多くの穴が同じ座標を共有する場合です。 たとえば、上部と下部の両方に x = 0 で複数のホールがある場合、畳み込みは合計 0 で大きなカウントを生成し、x = 0 でのすべての中央のホールがすべての組み合わせを累積します。 頻度カウントはセットとしてではなく明示的に保存されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、座標が境界 -30000 と 30000 にある場合です。シフト後、これらは配列インデックス 0 と 60000 にきれいにマップされ、それらの合計は畳み込み境界内に残ります。 FFT 配列は次の 2 のべき乗までパディングされるため、オーバーフローやインデックスの切り捨ては発生しません。 

最後の微妙なケースは、FFT の精度誤差です。 寄与するペアの数が多い場合、浮動小数点の丸めにより原理的に 1 ずつずれたエラーが発生する可能性があります。 逆 FFT 後の丸めステップによりこれが修正され、実際には境界のある座標範囲によって数値の不安定性が制御されます。
