 ## 解決策
 ## 問題の理解

 同じ数のスイッチと照明を備えたシステムと、スイッチが照明にどのような影響を与えるかを記述するバイナリ接続行列が与えられます。 スイッチをオンにすると、複数のライトに同時に影響し、各ライトの最終状態は、現在オンになっている接続されているスイッチの数によってのみ決まります。 ライトは、アクティブに接続されているスイッチの数が奇数の場合に点灯し、その数が偶数の場合に消灯します。 

タスクは切り替えをシミュレートすることではありません。 代わりに、ライトごとに独立して、この特定のライトがオンになり、他のすべてのライトがオフになるようなスイッチのサブセットが存在するかどうかを判断する必要があります。 これがすべてのライトで可能であれば、各ライトに対して、この条件を達成する有効なスイッチのサブセットを 1 つ出力する必要があります。 この方法で 1 つのライトでも分離できない場合は、-1 を出力します。 

入力行列は、当然のことながら、フィールド GF(2) に対する線形変換として解釈されます。 各スイッチは、ライトの 0 ～ 1 空間内のベクトルであり、スイッチをオンにすることは、ベクトルを法 2 で加算することに対応します。各ライトは、1 として分離する座標に対応し、他のすべては 0 になります。 

N ≤ 500 という制約は、O(N3) 個のガウス消去が許容されることを示唆していますが、スイッチのサブセットの列挙を伴うものは O(2^N) になるため不可能です。 この構造は、総当たり検索ではなく、GF(2) に対する連立一次方程式を解くことを強く示唆しています。 

微妙な点は、固定システム内で各ライトが他のライトから独立して到達可能かどうかは問われないことです。 方程式系は、独立した出力の完全な基底を生成する方法で同時に解くことができなければなりません。 これは、到達可能性を個別に 1 つずつチェックするよりも強力です。 

よくある失敗例は、各ライトを個別に扱い、スイッチを貪欲に選択しようとした場合に発生します。 たとえば、そのライトのみを切り替えるスイッチを選択すると、その組み合わせが以前に固定されたライトに意図せず影響を与える可能性があるため、失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、スイッチのすべてのサブセットが試行され、結果として得られるライト構成が計算されます。 サブセットごとに、特定のライトを分離しているかどうかを確認します。 これは、考えられるすべてのスイッチ構成を徹底的に調査するため、正しいですが、コストは指数関数的です。2^N 個のサブセットがあり、各評価コストは O(N) となり、O(N・2^N) になります。これは、N が 500 までの場合はまったく実行不可能です。 

重要な観察は、スイッチング動作が GF(2) に対して線形であるということです。 各スイッチはバイナリ ベクトルに対応し、スイッチをオンにすることは、これらのベクトルを 2 を法として加算することに対応します。システムはサイズ N×N の行列 A になり、スイッチ構成はベクトル x となり、GF(2) に対して出力 Ax が生成されます。 問題は、行列を使用してすべての標準基底ベクトル e₁、e₂、...、eₙ を生成できるかどうか、また、可能であれば、それぞれのプリイメージを構築できるかどうかを問うことに帰着します。 

これは、A が GF(2) に対して可逆であるかどうかを尋ねることと同じです。 それが可逆である場合、各光 i に対して、Ax = eᵢ となる一意の解 x が存在します。 A が可逆でない場合、少なくとも 1 つの基底ベクトルに到達できず、答えは -1 になります。 

したがって、問題は、GF(2) に対してガウス消去法を実行し、可逆性をチェックし、次に単位行列を使って拡張することによって A-¹ を暗黙的に計算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・2^N) | O(N) | 遅すぎる |
 | GF(2) 上のガウス消去 | O(N3) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力行列を N×N バイナリ行列 A として扱います。拡張行列 [A | I]、ここで I は単位行列です。 次に、減算の代わりに XOR を使用して、GF(2) に対してガウス消去を実行します。

1. 左から右の各列について、まだ使用されていない行の中からその列に 1 があるピボット行を選択しようとします。 そのような行が存在しない場合、行列は特異であるため、すぐに -1 を返します。 これにより、すべての列が、可逆性に必要なピボットに寄与するようになります。 
2. ピボット行が見つかったら、それを現在のピボット位置に交換します。 これにより消去順序が安定し、構造化された行階層フォームを構築できるようになります。 
3. ピボット行をこれらの行に XOR 演算することで、現在の列にある他のすべての 1 を削除します。 このステップでは、行列を恒等形式に近づけながら、システムの等価性を維持します。 
4. すべての列を処理した後、左半分が単位行列になると、右半分は A⁻¹ になります。 右半分の各行には、単一のライトをアクティブにするために必要なスイッチ セットが直接与えられます。 
5. 各光 i について、逆行列の行 i の 1 の位置を出力します。 

なぜこれが機能するかは、行を基底変換として解釈することにあります。 各行演算では、GF(2) 上の線形システムの解空間が保存されます。 消去によって A を ID に変えることに成功した場合、A がフルランクを持ち、スイッチ構成からライト構成への全単射を定義することを意味します。 拡張アイデンティティは、基底ベクトルが元のスイッチに関してどのように表現されるかを追跡するため、変換されたアイデンティティの各行は、単一のアクティブ ライトを生成するためにどのスイッチをオンにする必要があるかを正確にエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]

    # augmented matrix [A | I]
    for i in range(n):
        a[i].extend([1 if i == j else 0 for j in range(n)])

    row = 0
    for col in range(n):
        pivot = -1
        for r in range(row, n):
            if a[r][col]:
                pivot = r
                break
        if pivot == -1:
            print(-1)
            return

        a[row], a[pivot] = a[pivot], a[row]

        for r in range(n):
            if r != row and a[r][col]:
                for c in range(2 * n):
                    a[r][c] ^= a[row][c]

        row += 1

    # extract inverse
    for i in range(n):
        res = []
        for j in range(n):
            if a[i][n + j]:
                res.append(j + 1)
        print(*res)

if __name__ == "__main__":
    solve()
```この実装では、拡張行列を明示的に構築し、各行の幅を 2 ​​倍にして A と単位の両方を格納します。 消去ループはピボットを上から下に貪欲に選択し、各列が 1 回処理されるようにします。 XOR ステップは GF(2) の減算を置き換えます。また、上三角形式だけでなく行階層形式を縮小する必要があるため、すべての行を反復処理することで正確さが維持されます。 

最終的な抽出では、右半分が逆行列として読み取られます。 各行は、1 つのライトに必要なスイッチ セットに対応します。 

実装の微妙な詳細は、クリーンな恒等行列を保証するためにピボット行の上下両方を削除する必要があることです。 消去を下位行のみに制限すると、三角形の形が生成されますが、直接の逆三角形は生成されません。 

## 実用的な例

 消去法が成功する小規模な 3×3 システムを考えてみましょう。 

| ステップ | ピボット列 | ピボット行 | マトリックスの状態 (左半分) |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 最初のピボットで正規化される |
 | 2 | 1 | 1 | 2番目のピボットが固定されました |
 | 3 | 2 | 2 | 完全なアイデンティティ |

 消去後の右半分は逆行列となり、各行は光を分離するために設定された有効なスイッチを示します。 

ここで、1 つの列がすべて 0 である特異なケースを考えてみましょう。 

| ステップ | ピボット列 | アクション | 結果 |
 | --- | --- | --- | --- |
 | 1 | いくつかの列 | ピボットが見つかりません | 終了 |

 これはスイッチベクトルの組み合わせとして表現できない光に相当し、分離が不可能であることを意味する。 

最初のケースは、フルランクが反転の成功にどのようにつながるかを示し、2 番目のケースは、不可能であることを即座に検出することを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、複数のスイッチが同一のライトのセットに影響を与える場合です。 このような場合、行列の 2 つの列が同一であるため、直ちに行列が単数になります。 列ごとに割り当てられるピボットは 1 つだけであり、最終的に列で有効なピボット行が見つからなくなり、-1 がトリガーされるため、アルゴリズムはピボットの選択中にこれを検出します。 

もう 1 つのケースは、行列が逆行列であるが、きれいな逆行列を構築するには消去順序が重要である場合です。 アルゴリズムは常にトップダウンでピボットを選択し、行操作の一貫性を確保します。 すべての消去は左半分と右半分の両方に対称的に適用されるため、変換では等価性が維持されるため、ピボットが有効である限り、最終的な逆行列はピボットの順序に依存しません。 

最後の微妙なケースは、行列がフルランクであるものの、スパース性の点で条件が不十分な場合です。 それでも、演算は純粋に XOR ベースであり、数値の安定性に依存しないため、GF(2) 消去によって正確さが保証されます。
