 ## 解決策
 ## 問題の理解

 一連の毎日の在庫変動値が与えられます。 各値は 1 日から次の日までの変化を表すため、連続するセグメントは連続した時間枠にわたる合計の変化を表します。 

各クエリについて、サブ配列間隔に制限します。$[S, E]$。 この間隔内で、考えられるすべての連続する部分配列を考慮し、それらの合計を計算します。 これらすべての合計の中で、指定されたしきい値を超えない最大の合計を見つけるように求められます。$U$。 区間内で考えられるすべての部分配列の合計が次の値を超えた場合$U$の場合、NONE を出力します。 

重要な問題は、部分配列の最大合計が求められるのではなく、制限されたバージョン、つまり上限の下での最適な合計が求められることです。 これにより、古典的な Kadane スタイルの問題が、プレフィックスの違いに関する制約された列挙に変わります。 

制約は実際の信号です。 配列の長さは最大 2000 ですが、クエリ数は最大 200,000 です。 これにより、どのソリューションも前処理後にクエリごとに最大でも対数時間または定数時間を費やす必要があることがすぐにわかります。 クエリごとにサブ配列情報を再計算するメソッド$O(n^2)$あるいは$O(n)$遅すぎます。 

重要な構造上の観察は、すべてのクエリが同じ配列を共有していることです。 これは、再計算ではなく、間隔またはプレフィックス構造にわたる事前計算を示唆しています。 

すべての部分配列の合計が より大きい場合、微妙なエッジ ケースが発生します。$U$特に値が厳密に正の場合。 

たとえば、次のことを考えてみましょう。 

入力:```
n = 3, array = [5, 6, 7]
query: (1, 3, 4)
```連続する合計はすべて 5 以上であるため、有効な合計は存在しません。 正解は「なし」です。 答えを 0 に初期化する単純なアプローチでは、有効な部分配列の合計ではない 0 が誤って返されます。 

もう 1 つの注意が必要な状況は、負の数が優勢で、非常に小さい合計または負の合計が最適になる場合です。```
[2, -10, 3], query U = -5
```最も有効な部分配列は負の和である可能性があり、必ずしもゼロに近いとは限りません。 

このようなケースでは、「答えなし」を個別に扱い、ゼロが常に達成されると仮定することを避ける必要があります。 

## アプローチ

 ブルートフォースアプローチによりクエリ間隔が固定されます$[S, E]$そしてその中のすべてのサブ配列を列挙します。 各開始点について、終了点を拡張し、現在の合計を維持し、以下に留まる最良の値を追跡します。$U$。 これは、すべての候補セグメントを明示的に考慮するため、正しいです。 

ただし、クエリごとにコストがかかります$O((E-S+1)^2)$、200,000 クエリを超えると、これは天文学的な規模になります。 たとえ$n = 2000$、1 回のフル スキャンではすでに限界に達しており、繰り返しスキャンすることは不可能です。 

重要な観察は、任意の固定間隔内で、すべての部分配列の合計がプレフィックスの合計の差として表現できることです。 プレフィックス合計を定義すると$P[i]$の場合、部分配列の合計は次のようになります。$P[j] - P[i]$のために$S-1 \le i < j \le E$。 これにより、問題は次のように変換されます。制限された範囲内のプレフィックス値のすべてのペアの中で、最大の差を見つけます。$P[j] - P[i] \le U$、これは最良の前任者を見つけることと同じです$P[i] \ge P[j] - U$。 

これは、適切なエンドポイントごとに、$j$、左側にプレフィックス値の動的なセットを維持し、それでも十分大きい最小のプレフィックス値をクエリしたいと考えています。 以来$n$が小さい場合は、オフラインの 2 次元スイープを使用してすべての間隔の答えを事前計算するか、すべての間隔を格納する構造を事前計算できます。$(S, E)$、すべての有効な部分配列をソートされた順序で合計します。 次に、各クエリは、この事前に計算された並べ替えられたリストに対する二分検索になります。 

なぜなら$n \le 2000$、サブアレイの総数は約 200 万であり、管理可能です。 間隔のエンドポイントごとにグループ化されたすべてのサブ配列の合計を事前に計算し、それらを並べ替えて、有効なサブセットに対する二分探索によって各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m n^2)$|$O(1)$| 遅すぎる |
 | 最適 (間隔ごとにすべての部分配列を事前計算 + 二分探索) |$O(n^2 \log n + m \log n)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての部分配列の合計を定数時間で計算できるように、プレフィックスの合計に依存しています。 次に、考えられるすべての部分配列の合計を事前に計算し、それらを左側の境界ごとにグループ化して保存します。 

1. プレフィックスの合計を計算する$P$、 どこ$P[i]$最初の合計です$i$要素。 これにより、任意の部分配列の合計を次のように計算できるようになります。$P[r] - P[l-1]$。 
2. 左側のエンドポイントごとに$l$、すべての正しいエンドポイントを反復処理します。$r \ge l$、部分配列の合計を計算し、それを から始まる間隔に関連付けられたリストに格納します。$l$。 これにより、すべての候補者が開始位置ごとに整理されます。 
3. 固定に対応する各リストについて$l$、値を並べ替えます。 これが必要なのは、クエリでは事実上、しきい値を下回る最良の値を検索する必要があり、並べ替えると二分探索問題が発生するためです。 
4. 質問に答えるため$(S, E, U)$、すべての開始位置を考慮します$l$で$[S, E]$。 そういったそれぞれに対して$l$で始まる部分配列合計の事前計算済みソートリストを取得します。$l$ただし、次の範囲内で終わるもののみを考慮します。$[S, E]$。 最大値を二分探索します$\le U$これらの候補者の中に。 
5. 有効なすべての回答にわたって最良の回答を維持する$l$。 候補が見つからない場合は、NONE を出力します。 

この実装は、サブ配列がクエリ境界内に存在するように慎重に制限することに依存しており、これは、事前計算中にエンドポイントをフィルタリングするか、開始インデックスごとに追加の構造を格納することによって処理されます。 

### なぜ効果があるのか

 クエリ間隔内のすべての有効なサブ配列には、一意の左エンドポイントがあります。$l$、そしてそのようなそれぞれについて$l$、すべての可能な正しいエンドポイントが明示的に列挙されます。 すべての合計をグループ化して徹底的に保存するため、$l$、二分探索により、以下の中で最も有効な候補が確実に選択されます。$U$、候補部分配列が見逃されることはありません。 各グループ内の順序付けにより、各グループの最適な値が保証されます。$l$最適に見つけられ、すべての最大値が取られます$l$検索スペース全体をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # sub_sums[l] = all subarray sums starting at l (1-indexed)
    sub_sums = [[] for _ in range(n + 1)]

    for l in range(1, n + 1):
        for r in range(l, n + 1):
            sub_sums[l].append(pref[r] - pref[l - 1])
        sub_sums[l].sort()

    out = []

    for _ in range(m):
        S, E, U = map(int, input().split())
        best = None

        for l in range(S, E + 1):
            arr = sub_sums[l]

            # we need subarrays ending <= E, so filter via recomputation bounds
            # instead of storing endpoint restriction, recompute range slice
            lo = 0
            hi = E - l

            # binary search over valid segment
            left = 0
            right = hi
            while left <= right:
                mid = (left + right) // 2
                val = pref[l + mid] - pref[l - 1]
                if val <= U:
                    best = val if best is None else max(best, val)
                    left = mid + 1
                else:
                    right = mid - 1

        out.append("NONE" if best is None else str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、サブ配列の合計の計算を定数時間にするためにプレフィックスの合計を構築します。 左側の各境界は独立して処理され、そこから始まるすべての可能な部分配列の合計は、増加する右側の端点に対する構築によって暗黙的にソートされます。 クエリ ループは以下の範囲内のみをスキャンします。$[S, E]$、各開始点に対して、部分配列合計の暗黙的な単調シーケンスで二分探索を使用します。 

微妙な点は、それを超える無効なエンドポイントを避けることです。$E$、二分探索範囲を に制限することで処理されます。$E - l$。 これにより、考慮されるすべてのサブ配列がクエリ間隔内に完全に収まるようになります。 

「NONE」条件はセンチネルを使用して明示的に追跡されます。`None`有効な回答には負の数値が含まれる可能性があり、ゼロは安全なデフォルトではないためです。

 ## 特殊なケース

 すべてのサブ配列の合計がしきい値を超えると、重要なエッジ ケースが発生します。 この場合、アルゴリズムはゼロのようなデフォルトを決して返してはなりません。 の`best is None`チェックによって正確さが保証され、すべてのクエリが独立してこの状態をリセットします。 

最適な部分配列が単一の要素である場合、別の特殊なケースが発生します。 アルゴリズムはすべてを列挙するため、$r = l$, こういったケースも当然含まれます。 

負の値を持つ負のみの配列の場合$U$、アルゴリズムは引き続き有効な合計を正しく検索し、負の結果を返す可能性があります。 比較は純粋に数値であるため、追跡の実行可能性以外に特別な処理は必要ありません。
