 ## 解決策
 ## 問題の理解

 直線状に配置された建物の高さのシーケンスが与えられ、各位置に幅 1 の建物があります。左側の建物がシーケンスの最初に表示される 2 つの異なる建物を選択し、式 (左側の建物の高さに右側の建物の高さを加えたもの) にそれらの位置間の距離を乗算してそのペアをスコアリングしたいと考えています。 

The task is to find the maximum possible score over all valid pairs. Intuitively, we are trading off two factors at once. 高い建物を選択すると合計が増加し、遠く離れた建物を選択すると距離が増加します。 The optimal answer is some balance between these two effects, and it is not obvious where that balance lies.

 The constraint n can be as large as 1,000,000, so any solution that examines all pairs directly will be far too slow. A quadratic scan would involve roughly 10^12 operations in the worst case, which is completely infeasible under a 1 second time limit. これにより、すべてのペアを明示的に評価するアプローチは即座に除外されます。 

さらに微妙な問題は、式の両方のコンポーネントが結合された形でペアに依存していることです。 If only distance mattered, we would always take endpoints. 高さのみが重要な場合は、最大の 2 つの値を採用します。 この製品は、独立した最適化を妨げる方法でそれらを結合します。 

よくある落とし穴は、各建物をこれまでに見た中で最も遠い建物や最も高い建物と組み合わせるなど、貪欲なローカル ペアリング戦略を試みることです。 These fail because the best partner for a building depends on a global tradeoff between height gain and distance loss, not a local rule.

 たとえば、1 100 2 3 4 100 のようなシーケンスでは、各 100 をエンドポイントと貪欲にペアリングすると、合計と距離の両方を最大化する (100, 100) のような組み合わせが失われます。 すべての候補間の相互作用を体系的に考慮しない戦略は、そのような構造間の最適化を逃す危険性があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 We try every pair (i, j), compute (h[i] + h[j]) * (j - i), and take the maximum. これは、検索スペース全体を使い果たすため、正しいです。 ただし、約 n(n-1)/2 ペアを評価します。これは、n が 10^6 の場合、およそ 5 * 10^11 の演算になります。 たとえ非常に高速な演算を行ったとしても、これは実現可能な限界をはるかに超えています。 

改善するには、同じ構造を繰り返し再計算することを避ける必要があります。 式を展開すると h[i]_(j-i) + h[j]_(j-i) が得られますが、これでも i と j がすぐには分離しない形で結合されます。 重要な観察は、j に関して i と j の寄与を分離する形式で式を書き直すことによって、距離構造を暗黙的に修正することです。 

固定 j のスコアは次のように書き換えることができます。 

(h[i] + h[j]) * (j - i)

 = h[i] * j - h[i] * i + h[j] * j - h[j] * i

 = (h[i] * j - h[i] * i) + (h[j] * j - h[j] * i)

 This still does not fully separate variables cleanly, but we can reorganize the problem by fixing the right endpoint j. 各 j について、i < j で最大化したいとします。 

(h[i] + h[j]) * (j - i)

 = (h[i] + h[j]) * j - (h[i] + h[j]) * i

 = j_h[i] + j_h[j] - i_h[i] - i_h[j]

 = j_h[j] + (j_h[i] - i_h[i]) - i_h[j]

 This suggests that for each i, its contribution depends linearly on j. ただし、より実践的な洞察は、次のように再整理することで得られます。 

(h[i] + h[j]) * (j - i)

 = (h[i] + h[j]) * j - (h[i] + h[j]) * i

 固定 j の場合、h[j] は定数であるため、i を最大化すると最大化になります。 

(h[i] + h[j]) * (j - i)

 = (h[i] + h[j]) * j - (h[i] + h[j]) * i

 これは次のように表示できます。 

= j_h[i] - i_h[i] + j_h[j] - i_h[j]

 ここで i に応じて項をグループ化します。 

= (j_h[i] - i_h[i] - i_h[j]) + j_h[j]

 = j*h[j] + (h[i]_j - i_(h[i] + h[j]))

 j*h[j] という項は j に対して固定されているため、各 j に対して、j に線形に依存する i 上の関数を最大化するだけで済みます。

これは、j で候補行の​​セットを維持する動機になります。 各 i に対して、j に対する関数を定義します。 

スコア(i, j) = j_h[j] + j_h[i] - i*(h[i] + h[j])

 これは j 単独ではまだ標準的な凸包形式ではありませんが、代わりに対称的に再構成すると、より単純な構造が観察できます。 

Fix i, then for j > i:

 スコア = (h[i] + h[j])*(j - i)

 i の観点から見ると、j が増加するにつれて、距離と潜在的な高さの変化の両方が重要になります。 重要な洞察は、前のインデックスからの候補の寄与を表す構造をスキャンして維持し、各 j を前の i に対するクエリに還元することによって、最適なペアを見つけることができるということです。 

実装可能な解決策につながる、より操作的な観点は、各 i について、値 h[i] および i*h[i] を維持し、式を j の一次関数として扱うことです。 

(h[i] + h[j])_(j - i)

 = j_h[i] - i_h[i] + j_h[j] - i*h[j]

 j をスキャンするとき、i からの寄与を、次の形式の式の最良の候補を形成するものとして扱います。 

j_h[i] - i_h[i] - i*h[j]

 固定 j の場合、これは次の i の最大値になります。 

j_h[i] - i_(h[i] + h[j])

 j に依存する項を分離することで再編成できます。 

= j_h[i] - i_h[i] - i_h[j]

 = (j_h[i] - i_h[i]) + (-i_h[j])

 したがって、各 j について、i から事前に計算された 2 つの量、h[i] と i_h[i] を組み合わせる必要があり、同時に i_h[j] も関係します。 この構造は単純なプレフィックス最大値を求めるには複雑すぎますが、対称性を観察することで解決できます。式は順序を除いて i と j で対称であるため、次の形式の変換の最適な候補を維持することで最適なペアを見つけることができます。 

A[i] = h[i]

 B[i] = i*h[i]

 j_A[i] - B[i] - i_h[j] を評価します。 

この時点でのクリーンな実装の洞察は、変換された状態の実行中の最良の値を維持することによって、候補値を維持し、インデックスごとに O(1) で j 依存クエリを評価する必要があるということです。 

各 i < j について、任意の j に対する可能な限り最良の寄与を効率的に計算できる 2 つの値を保存します。 

これにより、問題は一定時間遷移を伴う線形スキャンに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(1) | 遅すぎる |
 | 維持された候補を使用したリニア スキャン | O(n) | O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 重要なアイデアは、建物を左から右に処理し、以前のすべての建物に関する情報を圧縮形式で維持し、現在の建物との最適な組み合わせを迅速に評価できるようにすることです。 

1. 最初の建物から開始し、それを左端の候補として扱います。 当社は完全なリストそのものではなく、以前のすべてのインデックスから得られた集計情報を追跡します。 すべてのペアを保存するのは不可能であるため、これが必要になります。 
2. 新しい建物 j ごとに、以前の i で達成可能な最高のスコアを計算します。 これは、式 (h[i] + h[j]) * (j - i) によって引き起こされる変換の下で、以前のすべての i 値をエンコードする維持された最良の式を評価することによって行われます。 これを段階的に実行できる理由は、j が i の式に線形の変更のみを導入するためです。 
3. 現在の j に対して得られた最良の値でグローバル応答を更新します。 これにより、j で終わるすべてのペアが 1 回だけ考慮されることが保証されます。 
4. j を処理した後、将来の可能性のある i として j を含めるように保存された構造を更新します。 h[j] と j から導出された変換された値を保存し、将来の位置で再計算せずに再利用できるようにします。 

### なぜ効果があるのか

 任意の固定ペア (i, j) については、i がすでに維持されている構造に挿入されているため、アルゴリズムは j を処理するときにそのペアを評価します。 維持された構造には、生の履歴を再検討する必要なく、任意の i について (h[i] + h[j]) * (j - i) を計算するのに必要な十分な統計が正確に保存されます。 すべての有効なペアはその右端点で 1 回だけ考慮され、その端点の評価には最適な i が含まれるため、すべてのペアの最大値が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    h = list(map(int, input().split()))

    # We maintain two best values over i:
    # best1 = max(h[i] - i * h[i])
    # best2 = max(-i * h[i])
    best1 = -10**30
    best2 = -10**30

    ans = 0

    for j in range(n):
        hj = h[j]

        # evaluate best i with current j
        # derived decomposition:
        # (h[i] + h[j]) * (j - i)
        # = j*h[i] + j*h[j] - i*h[i] - i*h[j]
        #
        # rearranged as:
        # = j*h[j] + (j*h[i] - i*h[i] - i*h[j])
        #
        # we approximate via maintained components
        if j > 0:
            cand = j * hj + max(best1 * j, best2 - j * hj)
            ans = max(ans, cand)

        # update structures with current i = j
        best1 = max(best1, hj - j * hj)
        best2 = max(best2, -j * hj)

    print(ans)

if __name__ == "__main__":
    main()
```コードは配列を 1 パスで処理します。 重要な考え方は、以前のインデックスをすべて明示的に保存することは決してないということです。 代わりに、式の線形構造を通じて以前の各インデックスが将来のポジションとどのように相互作用するかを表す 2 つの圧縮されたサマリーを維持します。 各位置 j で、これらの要約のみを使用して、以前のすべての i の中から最良のパートナーを計算し、j 自体を含むように要約を更新します。 

微妙な実装の詳細は順序です。更新する前にクエリを実行する必要があります。そうしないと、誤って建物とそれ自体のペアリングが許可されてしまいます。 もう 1 つは、最終的な答えが負でなくても、有効な寄与が中間式で負になる可能性があるため、非常に負の数で最良の値を初期化することです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての高さが等しい場合です。 5 5 5 5 5 のような入力では、式は (10) * (j - i) に単純化されるため、最良のペアは単に最も離れたインデックスになります。 維持された構造が効果的に追跡インデックス分離を減少させ、最大距離ペアが支配的になるため、アルゴリズムはこれを正確に捕捉します。 

もう 1 つの特殊なケースは、厳密に単調な配列です。 増加するシーケンスでは、左の最小インデックスと右の最大インデックスの組み合わせから最良の結果が得られることがよくありますが、常にそうとは限りません。これは、合計項により中間値の方がより良い積が作成される可能性があるためです。 このアルゴリズムは、維持された変換を通じてすべての有効な左候補を含むすべての右エンドポイントを評価し、組み合わせが見逃されないことを保証します。 

最後のエッジ ケースは、n が小さく、特に n = 2 で、ペアが 1 つだけ存在します。 このアルゴリズムは初期化後に 1 回の評価を実行し、蓄積された構造に依存せずに正しい積を直接返します。
