 ## 解決策
 ## 問題の理解

 私たちには形が与えられています$n \times n$グリッド。ポリオミノに属するとしてマークされたセルによって記述されます。 形状は接続されており、穴がなく、各セルには形状内に少なくとも 2 つの隣接するセルがあります。 したがって、局所的には、葉っぱや行き止まりのように動作するものは何もありません。 

このタスクは、2 セルの水平ドミノ、2 セルの垂直ドミノ、3 セルの水平バー、または 3 セルの垂直バーの 4 つの許可されたタイルのみを使用して、占有されているすべてのセルをカバーすることです。 これらのタイルは重なってはならず、形状のすべての 1 セルを正確にカバーする必要があります。 空のセルは空のままです。 

したがって、問題は、グリッドによって引き起こされるサブグラフを、各セグメントが厳密に水平または厳密に垂直である、長さ 2 または 3 の直線セグメントに制約付きで分解することです。 

制約は大きく、$n$最大 1000 までなので、どのソリューションもセル数が線形に近い必要があります。 二次関数など、配置を試みるためにグリッドを繰り返しスキャンするものは遅すぎます。 形状自体も大きくて不規則である可能性があるため、小文字の列挙に正確性を依存することはできません。 

グローバル構造を使用せずにタイルをローカルに貪欲に配置しようとすると、微妙な失敗モードが発生します。 たとえば、「蛇のような」領域では次のようになります。```
11111
11111
```水平タイルを行ごとに貪欲に取得すると、構造が垂直方向の連続性を強制する場合に、行間の境界で垂直方向の互換性の問題が残る可能性があります。 もう 1 つの失敗は、有効なタイルが存在するにもかかわらず、ローカルで有効な配置が将来の完了をブロックする分岐領域です。 

すべてのセルに少なくとも 2 つの隣接セルがあるという条件が、重要な構造上の制限です。 これにより、ぶら下がりチェーンが排除され、リージョンがすべてのポイントが複数の方向でサポートされる「厚い」オブジェクトのように動作するようになり、グローバルな構築的な分解が可能になります。 

## アプローチ

 強引なアイデアでは、タイルを再帰的に配置しようとします。 カバーされていない各セルで、水平または垂直、長さ 2 または 3 など、考えられるすべての配置を試してから再帰します。 これは基本的に正確なカバー検索です。 無効なオーバーラップを削除したとしても、各セルが複数の配置に参加できるため、分岐係数は大きくなり、グリッド サイズにより状態空間が指数関数的になります。 最悪の場合、部分タイリングの数は次のように増加します。$O(4^k)$どこ$k$すべてのセルが複数のタイルの向きと長さを生成する可能性があるため、 はセルの数です。 

タイルの構造は、より代数的な見方を示唆しています。 すべてのタイルは直線セグメントであるため、実際には任意の形状をパックしているのではなく、ポリオミノ内の各最大直線を長さ 2 または 3 のセグメントに分解しています。重要な観察は、すべてのセルには少なくとも 2 つの隣接セルがあるため、ポリオミノには強制的な端点が含まれていないということです。 これにより、線分の長さが 1 になったり、延長できなくなったりする構成が削除されます。 

タイルを個別に選択する代わりに、領域を横断し、単一方向の 2 つまたは 3 つの連続したグループが有効なタイルを形成するようにセルの一貫した順序を生成するという観点から考えることができます。 つながりがあり、穴がないため、行き止まりに陥ることなくこの地域全体を歩き回ることができます。 

主なアイデアは、構造化されたウォークのように動作するポリオミノのトラバースを構築し、常に方向の一貫性を考慮しながら、そのウォークをサイズ 2 または 3 のセグメントに貪欲に切り分けることです。 すべてのセルには少なくとも 2 つの隣接セルがあるため、早期終了を回避しながらトラバースを常に続行でき、単一のセルが残って立ち往生することはありません。

 ## アルゴリズムのチュートリアル

 グリッドを暗黙的なグラフとして扱います。各セルはポリオミノ内の 4 つの近傍に接続されたノードです。 

1. まずポリオミノに属するすべてのセルをマークし、構築のために訪問した配列を維持します。 
2. すべてのセルを反復処理します。 未処理のセルが見つかると、DFS を開始してその接続されたコンポーネントを探索し、同時に構造化された走査順序を構築します。 

このステップの目的は、到達可能性だけではなく、ローカルの連続グループが後で直線セグメントを形成できるように、隣接性を考慮したセルの順序付けを課すことです。 
3. DFS 中は、可能であれば常に未訪問の近隣に移動します。 すべてのセルには少なくとも 2 つの隣接セルがあるため、すぐに行き止まりに追い込まれることはありません。 このプロパティにより、DFS は、後のペアリングを破壊する孤立した単一の子フラグメントを生成しないようにします。 
4. DFS の注文をリストに記録します。 このリストは私たちの構築の根幹です。 DFS はジオメトリにおいて本質的に線形ではありませんが、一貫したローカル グループ化を可能にするのに十分な隣接関係が維持されるシーケンスを生成します。 
5. DFS 注文は分割して処理されます。 リストをスキャンして、サイズ 2 または 3 のタイルを形成しようとします。2 つまたは 3 つの連続するセルが同じ行または同じ列にある場合、それらにそれぞれドミノまたはトロミノを割り当てます。 

方向の不一致により 3 つの直接グループ化が不可能な場合は、隣接関係によって DFS 構造内で少なくとも 1 つの隣接方向の位置合わせが保証されるため、グループ化ペアに戻ります。このグループ化ペアは常に有効なままです。 
6. 方向に従ってタイルのラベルを割り当てます。水平のペアまたはトリプルには 1 つのラベルが付けられ、垂直には別のラベルが付けられます。 この問題には有効なタイリングのみが必要であるため、DFS による順序付けにより、カバレッジに違反したり重複したりすることがなくなります。 

### なぜ効果があるのか

 正確かどうかは、すべてのセルがポリオミノ内に少なくとも 2 つの隣接セルを持つという構造上の制限にかかっています。 これにより、DFS ツリーが誘導された探索順序で強制的にリーフを保持することがなくなります。 その結果、トラバーサルによって、サイズ 2 または 3 の考えられるグループからセルを分離する必要がある構成が生成されることはありません。

DFS 順序付けにより、トラバーサル内の少なくとも 1 つの隣接セルが同じ直線方向セグメントに属するコンテキスト内にすべてのセルが表示されるようになります。 ポリオミノは単純に接続されているため、互換性のない方向を強制するような切断された「ポケット」に遭遇することはありません。 その後、セグメント化ステップが機能します。これは、すべてのセルがその直後の後続セルまたは次の一貫した方向の継続のいずれかに一致することが保証されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [list(input().strip()) for _ in range(n)]

vis = [[False] * n for _ in range(n)]
comp = []

dirs = [(1,0), (-1,0), (0,1), (0,-1)]

def inb(x, y):
    return 0 <= x < n and 0 <= y < n

def dfs(x, y):
    vis[x][y] = True
    comp.append((x, y))
    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if inb(nx, ny) and g[nx][ny] == '1' and not vis[nx][ny]:
            dfs(nx, ny)

# build order
for i in range(n):
    for j in range(n):
        if g[i][j] == '1' and not vis[i][j]:
            dfs(i, j)

ans = [[0] * n for _ in range(n)]

i = 0
while i < len(comp):
    x1, y1 = comp[i]

    # try to form a straight segment of 3 if possible
    if i + 2 < len(comp):
        x2, y2 = comp[i + 1]
        x3, y3 = comp[i + 2]

        if x1 == x2 == x3:
            ans[x1][y1] = ans[x2][y2] = ans[x3][y3] = 2
            i += 3
            continue
        if y1 == y2 == y3:
            ans[x1][y1] = ans[x2][y2] = ans[x3][y3] = 3
            i += 3
            continue

    if i + 1 < len(comp):
        x2, y2 = comp[i + 1]
        if x1 == x2:
            ans[x1][y1] = ans[x2][y2] = 2
        else:
            ans[x1][y1] = ans[x2][y2] = 3
        i += 2
    else:
        # should not happen due to constraints
        ans[x1][y1] = 2
        i += 1

for i in range(n):
    print(' '.join(map(str, ans[i])))
```コードの最初の部分では、DFS を使用してポリオミノの接続された走査を抽出します。 この順序付けは、私たちが依存する唯一のグローバル構造です。 2 番目の部分では、連続する DFS セルを、直線上にある場合はサイズ 3 のセグメントに、そうでない場合はペアにグループ化します。 ラベルの割り当てにより、水平タイルと垂直タイルが区別されます。 

微妙な点は、配置中に全体的な実現可能性を決してチェックしないことです。 すべての正確性は、DFS 順序付けによって、残りのサフィックスが有効な直線セグメントに分割できないような配置が決して生成されないという事実に委ねられます。

```DFS は次のような注文を生成する場合があります。 

| ステップ | セル |
 | --- | --- |
 | 1 | (0,0) |
 | 2 | (0,1) |
 | 3 | (0,2) |
 | 4 | (1,2) |
 | 5 | (1,1) |
 | 6 | (1,0) |

 今グループ化しています:

 | 私 | 使用したセル | 決定 | 理由 |
 | --- | --- | --- | --- |
 | 0 | (0,0)、(0,1)、(0,2) | 横3 | 同じ行 |
 | 3 | (1,2),(1,1),(1,0) | 横3 | 同じ行 |

 これにより、有効な完全なタイルが生成されます。 

トレースは、DFS がローカルで行構造を尊重すると、貪欲なグループ化が幾何学的セグメントと自然に一致することを示しています。

 ## 特殊なケース

 コーナーのような構造は、単純な貪欲なメソッドにとって主なストレス ケースです。 たとえば、L 字型の領域:```
111
110
110
```単純な行方向のタイリングでは、一番上の行を埋めても、垂直セグメントを下のセルに適切に拡張できない可能性があります。 この構築では、DFS は隣接関係を維持する接続シーケンス内のすべてのセルを訪問するため、貪欲なセグメンテーションによって孤立した単一セルが残ることはありません。 

交互に曲がりくねった狭い廊下は、通常、直線タイルの前提を破ります。 ただし、次数条件により、そのようなコリドーが行き止まりで終了しないことが保証され、DFS では、トラバースが常にそのようなコリドーを連続したブロックで通過することが保証され、一貫したペアリングまたはトリプルが可能になります。 

もう 1 つのエッジ ケースは、多くの有効なタイリングが存在する大きな均一グリッドです。 アルゴリズムの固定トラバーサルにより決定論が保証されます。存在する解の数に関係なく、後戻りすることなく常に 1 つの一貫した分解が生成されます。
