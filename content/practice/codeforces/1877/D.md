 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた配列が与えられます。 インデックスの空でないサブセットを繰り返し選択し、それらを特別なものとしてマークします。 選択されたインデックスは黒で表示されます。 その後、まだ選択されていないインデックスが少なくとも 1 つの黒のインデックスの倍数である場合、そのインデックスは緑になります。 他はすべて白いままです。 

選択のスコアは、この伝播ステップの後に定義されます。黒または緑になったすべてのインデックスを調べ、それらの中で最大の配列値を取得します。 インデックスの空でないすべてのサブセットに対してこのスコアを計算し、これらのスコアをすべて合計する必要があります。 

この困難は、選択された各サブセットが可分性よりも決定論的な閉包に影響を及ぼし、その閉包が局所的隣接性ではなく数論的構造に大きく依存するという事実から生じます。 

制約により、n は最大 100,000、値は最大 100,000 まで許可されます。2^n 個のサブセットがあるため、すべてのサブセットを直接列挙することは不可能です。 サブセットごとの状態を保存することすら不可能です。 これにより、サブセットを明示的にシミュレートしたり、サブセットごとの伝播を実行したりするソリューションは即座に除外されます。 

単純なアプローチでは、サブセットごとにすべての倍数をマークし、最大値を計算しようとする可能性があります。 たとえ伝播が速かったとしても、すべてのサブセットを反復すると、すでにこの速度は指数関数的になります。 この問題では、要素の寄与を列挙するのではなく組み合わせてカウントするという再定式化が必要です。 

可算性によって大きなインデックスが小さなインデックスを支配する場合、微妙なエッジ ケースが発生します。 たとえば、インデックス 1 を選択すると、常にすべてのインデックスがアクティブになるため、スコアは他の選択肢に関係なく、単純にグローバル最大値になります。 単純な実装では、黒の要素を緑のクロージャとは独立して扱う場合、この優位性を過小評価する可能性があります。 

もう 1 つの特殊なケースは、大きなインデックスのみが選択される場合です。 たとえば、インデックス n のみを選択しても、多くのインデックスが n を分割しない限り、配列の大部分はアクティブになりません。 これにより、伝播が非対称になり、除数構造に依存します。 

## アプローチ

 ブルート フォース ソリューションでは、インデックスの空でないすべてのサブセットが列挙されます。 サブセットごとにクロージャを計算します。選択したインデックスを黒でマークし、次に選択したインデックスのすべての倍数を緑でマークし、最後にすべてのアクティブ化されたインデックスをスキャンして最大値を見つけます。 これは、説明されているプロセスに直接従うため、正しいです。 ただし、n = 20 の場合でもサブセットは 100 万を超え、n = 100,000 の場合、これは完全に不可能になります。 各評価のコストは最大 O(n) であるため、合計の複雑さは O(n · 2^n) となり、制限をはるかに超えています。 

重要な点は、サブセットを追跡する必要がないということです。 代わりに、視点を逆転させます。値のしきい値を固定し、最大アクティブ値がそのしきい値以上であるサブセットの数を尋ねます。 これは当然、インデックスを値で並べ替え、降順で処理することになります。 インデックス i を考慮すると、より高い値はすべてすでに考慮されており、i を最初にアクティブ化された最大値にするサブセットをカウントするだけで済みます。 

伝播ルールは割り算のみに依存するため、各インデックス i はすべての倍数をアクティブにする「ジェネレーター」と見なすことができます。 したがって、サブセットが i を最大値として寄与するかどうかは、i またはその約数を強制的にアクティブ化するインデックスが少なくとも 1 つ含まれているかどうかによって決まります。 この構造はインデックスに対して乗算的であり、除数に対して包含/除外を使用して有効なサブセットをカウントできます。

a[i] の降順でインデックスを処理します。 i を考慮する場合、より高い値のインデックスがアクティブにならないようにすることで、i が最大のアクティブ化された要素であるサブセットをカウントします。 これは、除数構造を通じて i をアクティブにしながら、より高い寄与の「ブロック」を回避するサブセットをカウントすることに帰着します。 結果として得られる計算は、事前に計算された除数リストと独立したコンポーネントをカウントする乗算サブセットを使用して実行できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. a[i] の値を降順にしてインデックスを並べ替えます。 インデックスを処理するときに、厳密に大きな値がすべて最終的な寄与ロジックですでに考慮されるように、より大きな値を最初に処理します。 これにより、常に現在の値が最大となる寄与を計算することが保証されます。 
2. n までのすべてのインデックスのすべての約数を事前計算します。 これが必要なのは、緑の伝播が完全に割り算に依存しており、すべての活性化パスが隣接関係ではなく割り算関係によって決定されるためです。 
3. どのインデックスが既に「より高い値によってアクティブ化」されているかを追跡する構造を維持します。 概念的には、特定のインデックスがサブセットに含まれている場合に最大値にならないようにインデックスをマークします。 
4. a[i] の降順でインデックス i ごとに、i が最大アクティブ値になるサブセットの数を計算します。 これには、i をアクティブにする構成を少なくとも 1 つ含むサブセットをカウントする必要がありますが、その構成を支配する可能性がある厳密に大きな値を持つすべてのインデックスは除外されます。 
5. 有効なサブセットを数えるために、問題を i の約数で因数分解します。 各約数は、黒から倍数への伝播ルールを通じて i が到達可能になるかどうかに独立して影響します。 これらの約数コンポーネントに対して組み合わせカウントを使用します。 
6. a[i] に i の有効なサブセットの数を乗算した値を最終的な答えに追加します。 これにより、すべてのインデックスからの寄与がすべてのサブセットにわたる潜在的な最大値として集計されます。 
7. すべてのインデックスが処理されるまで続行し、各サブセットがその最大アクティブ化要素の下で正確に 1 回カウントされるようにします。 

### なぜ効果があるのか

 すべてのサブセットには、アクティブ化された最大値によって決定される固有のスコアがあります。 値を降順で処理することにより、値 a[i] の寄与をカウントするときに、カウントされるサブセットにそれ以上の値が出現しないことが保証されます。 割り算構造により、活性化が局所的な乗算閉包のみに依存することが保証されるため、固定最大値に寄与するサブセットは、割り数ベースの分解を通じて独立してカウントできます。 これにより、二重カウントが防止され、各サブセットに 1 つの寄与最大値が確実に割り当てられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = list(enumerate(a, start=1))
    vals.sort(key=lambda x: -x[1])

    maxn = n + 1
    divs = [[] for _ in range(maxn)]
    for i in range(1, n + 1):
        for j in range(i, n + 1, i):
            divs[j].append(i)

    pow2 = [1] * (n + 2)
    for i in range(1, n + 2):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    used = [False] * (n + 1)
    res = 0

    for i, val in vals:
        cnt = 0
        for d in divs[i]:
            if not used[d]:
                cnt += 1

        if cnt:
            contrib = pow2[cnt - 1]
        else:
            contrib = 0

        res = (res + val * contrib) % MOD
        used[i] = True

    print(res)

if __name__ == "__main__":
    solve()
```実装は、大きい値が最初に処理されるようにインデックスを並べ替えることから始まります。 これにより、「最大優先」分解の正確さが保証されます。 活性化ルールは乗法構造に依存するため、約数はすべてのインデックスに対して事前に計算されます。 

の`used`配列は、どのインデックスが潜在的な最大値としてすでに処理されているかを追跡します。 インデックス i を評価するとき、その約数のうちまだ使用されていないものがいくつあるかを数えます。 これらは、選択された黒のセットを介して i をアクティブにする独立した方法を表します。 このような使用可能な約数が cnt ある場合、それらの空でないサブセットを選択して i をトリガーすることができ、これにより 2^(cnt−1) の可能性が得られます。 

最終的な合計は、各値に最大アクティブ化要素となるサブセットの数を乗算します。

 ## 特殊なケース

 n = 1 の最小入力により、基本寄与ロジックが確認されます。 インデックスが 1 つである場合、サブセットは {1} だけであり、当然のことながら黒と緑の両方になるため、スコアは a[1] に等しくなります。 このアルゴリズムはインデックス 1 を処理し、使用可能な約数を 1 つ見つけて、必要な出力に一致する寄与 2^0 = 1 を割り当てます。 

すべての値が等しい場合、すべてのインデックスは何らかの順序で処理されますが、並べ替えにより決定的な処理が保証されます。 寄与度は値の関係ではなく除数構造のみに依存するため、各インデックスは独立して寄与します。 このアルゴリズムは依然として、インデックスごとに 1 つの有効なサブセット構成を割り当て、対称性を一致させます。 

n = 4 の値 [1、2、4、8] のような場合、割り算連鎖は密になります。 インデックスが高くなると、初期の処理後に使用可能な約数が少なくなり、それに応じて寄与も縮小します。 このアルゴリズムは、除数インデックスが一度処理されると、それ以降のインデックスのトリガーとして機能しなくなるという事実を正しく考慮しており、サブセットが複数回カウントされることはありません。
