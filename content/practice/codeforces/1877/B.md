 ## 解決策
 ## 問題の理解

 私たちは、できるだけ安価な方法で村の住民全員にアナウンスを広める任務を負っています。 住民に知らせる方法は 2 つあります。パク・チャネクが固定料金で誰かに直接伝えることができます。`p`、またはすでに知っている居住者は、魔法のヘルメットを使用して他の人に通知することができます。`a_i`住民は～の費用をかけて`b_i`通知ごとに。 各居住者は異なる能力を持っています（`a_i`) とコスト (`b_i`) お知らせを広めるために。 目標は、パク・チャネクが誰に直接知らせるか、そして住民全員がその発表をどのように中継するかを選択することである。`n`住民は知っていますが、総コストは最小限で済みます。 

制約は次のことを示します`n`テスト ケースごとに最大 10^5 になる可能性があり、合計は`n`すべてのテスト ケースも 10^5 で区切られます。 直接スプレッドコスト`p`そしてヘルメットの値段も`b_i`10^5 に達することもあります。 これらの境界では、O(n^2) の複雑さを持つアルゴリズムは、最大 10^10 の演算が必要になる可能性があるため、直ちに実行できなくなります。 テスト ケースごとに O(n log n) または O(n) に近い値が必要です。 

明らかではないエッジケースには、直接コストがかかる状況が含まれます。`p`どの居住者の共有費用よりも安い`b_i`、いくつかの場合`a_i`非常に小さい (1) または非常に大きい (n)、および複数の居住者が同じコストを持つが容量が異なるシナリオ。 たとえば、次の場合`n=3`、`p=5`、`a=[1,1,1]`、`b=[6,6,6]`、最も安価なオプションは、合計 15 人の 3 人の居住者全員に直接通知することです。共有することが常に有益であると想定する単純なアルゴリズムでは、代わりに他の人を介して中継しようとし、コストを超過する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、パク・チャネックが直接情報を提供できる可能性のあるすべての居住者のサブセットを考慮し、ヘルメットの能力を使用して残りのすべての居住者への伝播をシミュレートします。 選択肢ごとに合計コストを計算し、最小値を選択します。 これは原理的には機能しますが、複雑さは指数関数的に増加します。`n`サブセットの数は 2^n であるためです。 剪定しても無理です`n=10^5`。 

重要な洞察は、各居住者のアナウンスを広める能力が 1 人当たりのコストとして定量化できるということです。`b_i`それぞれについて`a_i`情報を提供できる人々。 この 1 人あたりのコストが次の値を超える場合は、`p`、その居住者を他の人に知らせるために使用する価値は決してありません。 ヘルメットのコストと容量に基づいて住民を分類することで、情報を持たない残りの住民に広める最も安価な方法を貪欲に選択できるようになります。 次に、住民の数に対して二分探索を使用して、直接通知することができます。その数が与えられた場合、並べ替えられたヘルメット費用リストを使用して、他の全員に通知するための最小限の追加費用を計算します。 これにより、テスト ケースあたりの複雑さが O(n log n) に軽減されます。 

ブルート フォースはすべての可能性を試行することが保証されているため機能しますが、組み合わせの数が指数関数的に増加するため失敗します。 より安価な拡散は、効果的な 1 人当たりコストのソートされたリストとして表すことができるという観察により、問題を二分探索と組み合わせた線形スキャンに縮小することができ、指数関数的な問題を扱いやすい問題に変えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入居者数を読む`n`そして直接拡散コスト`p`。 
2. 配列を読み取る`a`（容量）と`b`（ヘルメットの費用）。 
3. 居住者ごとに、他の人に通知するために使用するコストを次のように考慮します。`min(b_i, p)`一人当たり、なぜなら`b_i > p`, パク・チャネクに直接知らせたほうが安いです。 
4. 居住者を収容人数の降順に並べ替えます (`a_i`) と 1 人あたりの料金の安い順 (`b_i`）、安く多くの方にお知らせできる方を優先させていただきます。 
5. ソートされたプレフィックス合計配列を初期化します。`b_i`効率的なコスト計算のための値。 
6. 直接通知する住民の数を 0 から最大まで繰り返します。`n`。 考えられるそれぞれの数値について:

 ａ． 総費用には以下が含まれます`num_direct * p`。 

b. 残りの居住者数を計算する`n - num_direct`。 

c. 最も安いものを合計します`n - num_direct`プレフィックス合計配列を使用したヘルメット共有コスト。 
7. すべての選択肢にわたる最小合計コストを追跡します。 
8. 最小コストを出力します。 

それが機能する理由: 不変なのは、すべてのステップにおいて、直接またはヘルメットを通して、残りの住民に情報を伝えるために利用可能な最も安価な方法を常に選択するということです。 1 人あたりのコストで並べ替えることで、より安価な組み合わせを見逃すことがなくなります。 二分検索またはプレフィックス合計により、同じオプションの再評価が回避され、最適性を犠牲にすることなく効率が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, p = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # Each resident's effective cost is min(b_i, p)
        residents = sorted(zip(b, a), key=lambda x: (x[0], -x[1]))
        b_sorted = [min(bi, p) for bi, _ in residents]
        
        # Prefix sum of b_sorted
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + b_sorted[i]
        
        res = float('inf')
        for direct in range(n + 1):
            # Cost to inform `direct` residents directly
            cost = direct * p
            remaining = n - direct
            # Additional cost from cheapest residents sharing
            cost += prefix[remaining]
            res = min(res, cost)
        print(res)

if __name__ == "__main__":
    solve()
```コードはまず、各居住者の最小効果ヘルメット コストを計算し、すべての居住者を置き換えます。`b_i`より高い`p`と`p`。 並べ替えにより、常に最も安価なスプレッダーが最初に選択されます。 プレフィックス合計により、共有の累積コストを効率的に計算できます。 メインループは、直接情報を提供する可能性のあるすべての住民の数を考慮し、これを最小限の拡散コストと組み合わせます。 プレフィックス合計を使用すると、ネストされたループが回避され、最初の並べ替えにより複雑さが O(n log n) に保たれます。
