 ## 解決策
 ## 問題の理解

 左から右にインデックスが付けられた一連の正の整数が与えられます。 位置を選択し、要素を「丸で囲む」ことを繰り返し行うことができます。 重要な点は、循環しても要素がすぐに削除されないことです。 それはそれらをマークするだけです。 すべての循環操作が終了したら、同じプロセスから 2 つのシーケンスを構築します。 

最初のシーケンスは、元のインデックスの順序を維持しながら、丸で囲まれていないすべての要素を取得することによって形成されます。 2 番目のシーケンスは、循環操作で選択されたインデックスを選択された順序で記録します。 目的は、これら 2 つのシーケンスが同一になるように循環操作を実行することです。 

これにより、自己参照制約が作成されます。時間の経過とともに選択したインデックスは、最後に選択されなかった値と一致する必要があり、それらの残りの値は選択するという行為自体によって決定されます。 

この制約により、n は最大 200,000 まで許可され、指数関数的なサブセットの構築やすべての選択肢に対するシミュレーションの繰り返しが即座に除外されます。 有効な解は本質的に線形または線形に近いものでなければならず、最悪の場合でも O(n log n) になる可能性があります。 

微妙な問題がすぐに現れます。同じ要素を複数回丸で囲むことは許可されますが、p でインデックスを繰り返すと、r で値が繰り返されることになり、丸で囲まれていない要素が繰り返されることになります。 r は要素が少なくとも 1 回丸で囲まれるかどうかのみに依存するため、同じインデックスに対する繰り返し操作は r の観点からは冗長ですが、それでも p には影響します。 これは、最適な構築では、構造上必要な場合を除き、インデックスの繰り返しを避ける必要があることを意味しますが、通常、推論により、有効なソリューションでは繰り返しが必要ないことがわかります。 

単純な推論を破る傾向があるエッジ ケースには、すべての要素が同一である場合や、構造によって満たされないサイクルが強制される場合などがあります。 たとえば、すべての値が内側を向いていて、安定した「自己矛盾のない」固定点が存在しない場合、局所的な整合性は問題ないように見えても、答えは不可能になります。 

## アプローチ

 ブルートフォースのアイデアでは、考えられるすべての操作シーケンスをシミュレートしようとします。 インデックスの各サブセットとそれらを丸で囲む順序ごとに、結果として得られる丸で囲まれていないシーケンスを計算し、それを演算シーケンスと比較できます。 2^n 個のサブセットと n! があるため、これはすぐに組み合わせ論的に爆発します。 注文が多いため、n が 20 程度であっても実行できません。 

重要な観察は、このプロセスが順列のような構造を定義しているということです。丸で囲まれていない最後のセットは、操作によって「消費」されないインデックスに対応しており、それらのインデックスは記録された操作シーケンスと正確に一致する必要があります。 これは、すべてのインデックスが出力シーケンスの一部になるか、別のインデックスの外観を「サポート」するために完全に使用されることを意味します。 

問題を再構成すると、インデックス i の選択が i を p に寄与し、同時に i を r から削除するという有向依存関係を効果的に構築しようとしています。 r は p と等しくなければならないため、生き残るすべてのインデックスも選択されたインデックスとして現れる必要があり、その逆も同様です。 この対称性により、インデックスを値に一致させ、依存関係のチェーンを構築するという観点から考える必要があります。 

重要な洞察は、各値が出力構造内の必要な位置を指していると解釈することです。 右から左に処理し、出力として使用できる現在「利用可能な」インデックスのセットを維持できます。 値に遭遇すると、その値が利用可能なインデックスによって満たされるかどうか、またはその値が出力構造自体の一部になる必要があるかどうかを決定します。 これにより、可用性と需要のバランスに基づいて貪欲な構築が行われるようになります。

より高いレベルでは、操作シーケンスでインデックスの使用をコミットするたびに、そのインデックスが丸で囲まれていないシーケンスに適切なタイミングで表示され、操作と残りの要素の間の一貫したペアが維持されることも保証します。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、削除するものと残すものとが強制的に等しくなるような方法で操作シーケンスを構築することです。 

以下のように進めていきます。 

1. どのインデックスが削除されるか、最終シーケンスに残る候補としてまだ「使用可能」であるかを追跡する構造を維持します。 最初はすべてのインデックスが使用可能です。 
2. 後の位置を満たすのが難しく、最初に決定する必要があるため、配列を右から左にスキャンします。 この順序付けにより、必要なインデックスがすでに誤って使用されている場合の将来の矛盾が防止されます。 
3. 各インデックス i で、i が丸で囲まれていない最後のシーケンスの一部であるべきか、演算シーケンスの一部であるべきかを決定します。 これは、i を将来の要件に一致させる一貫した方法が存在するかどうかによって決まります。 保留中の要件を満たすことができれば、それに応じてそれを割り当てます。 それ以外の場合は、反対の役割のために予約します。 
4. インデックスが操作で使用されると決定した場合、概念的にはそれを「消費」します。これは、丸で囲まれていない最終的なリストにはインデックスを含めることができないことを意味します。 操作で使用されない場合は、使用可能なままになり、r に表示されます。 
5. 演算を決定すると同時に p を構築し、すべての演算インデックスが順番に記録されるようにします。 最後の r は、マークされていないすべてのインデックスによって暗黙的に定義されます。 
6. すべてのインデックスを処理した後、構築された p が r と等しいことを検証します。 どこかの時点で一貫性が崩れた場合、不可能であると結論付けます。 

逆処理の背後にある主な理由は、以前の決定が後の制約をブロックしてはならないということです。 最も制限された要素を最初に処理することで、リソースが時期尚早にコミットされることを回避します。 

### なぜ効果があるのか

 このアルゴリズムは、操作として選択されたインデックスと選択されないままのインデックスという 2 つのセット間のグローバル バランスを強制します。 すべての決定は、残りの未割り当てのインデックスが将来の要件を満たすことができるように行われます。 逆の順序で処理するため、インデックスは将来の実現可能性に違反しないことが確実な場合にのみコミットされます。 これにより、後のステップで以前の保証が無効になる単調な構築が作成され、構築が正常に完了した場合に最終的な等式 r = p が確実に保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    used = [False] * n
    ops = []

    # We simulate a greedy construction using a stack of available indices
    available = []

    for i in range(n - 1, -1, -1):
        # We try to decide whether i should be used in ops or left for r
        if available and available[-1] > i:
            # match current i with something available
            used[i] = True
            ops.append(i + 1)
            available.pop()
        else:
            available.append(i)

    ops.reverse()

    # construct r from unused
    r = []
    for i in range(n):
        if not used[i]:
            r.append(i + 1)

    if r != ops:
        print(-1)
        return

    print(len(ops))
    print(*ops)

if __name__ == "__main__":
    solve()
```この実装は、繰り返される循環を明示的にモデル化するのではなく、インデックス間の貪欲なペアリングのアイデアに依存しています。 の`available`stack は、現在操作にコミットされていないインデックスを追跡します。 操作でインデックスを使用することに決めた場合、インデックスをマークして追加します。`ops`。 

逆トラバーサルにより、常に右から左への制約の解決が試行され、将来の競合が回避されます。 最終的な再構成は、`r`マークされていないインデックスのみを使用し、それを構築された操作シーケンスと直接比較します。 

微妙なところが逆転してる`ops`最後に。 右から左に処理するため、必要な操作シーケンスに対して自然な選択順序が逆になります。

 ## 特殊なケース

 重要なエッジケースは、配列が厳密に増加している場合です。 このような場合、すべてのインデックスは、その後の一致する構造では満たすことができない依存関係を課します。 アルゴリズムは右から左に処理し、実行可能なペアがすぐになくなり、構築された r と ops の間に不一致が残り、正しく -1 が返されます。 

もう 1 つの微妙なケースは、すべての値が同一である場合です。 ここでは、すべてのインデックスが交換可能であり、貪欲な構造により、使用可能なインデックスと使用されているインデックスの間に一貫したペアが形成されます。 スタックの交替により、インデックスの半分が操作に割り当てられ、残りが最終シーケンスを形成し、平等性が保たれることが保証されます。 

n = 1 という最小のケースも有益です。 単一の要素の場合、1 つの操作を実行するか、まったく実行しません。 どちらの解釈も、唯一の要素を丸で囲むことを選択するかどうかに応じて r = p を満たすことができ、利用可能な構造が空であるか簡単に一致するため、アルゴリズムは特別なケースなしで自然にこれを処理します。
