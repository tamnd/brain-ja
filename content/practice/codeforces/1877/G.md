 ## 解決策
 ## 問題の理解

 いくつかのエッジはすでに固定方向を持ち、いくつかのエッジはまだ方向を定められていないツリーが与えられています。 残りのエッジの方向を選択し、すべてのエッジに色を割り当てる必要があります。 

ウォークはエッジをその方向に沿って、またはエッジに逆らって横断することができます。 方向に沿って移動すると、エッジの色と同じ色のボールがスタックに押し込まれます。 逆方向にトラバースするとトップボールが飛び出す。 

ウォークは、空のスタックからポップしようとしない場合、スタック可能と呼ばれます。 

スタック可能なウォークは、すべてのポップが現在通過しているエッジと一致する色のボールを削除する場合、ボールをスタック可能です。 

私たちのタスクは、**すべて**のスタック可能なウォークを自動的にボールをスタック可能にすることです。 すべての有効な構成の中で、使用される個別の色の数を最大化したいと考えています。 

基礎となるグラフは、最大で以下のツリーです。$10^5$頂点。 ペアごとの頂点チェック、ウォークのシミュレーション、または二次関数を含む解決策は直ちに不可能です。 線形または線形に近い解決策が必要です。 

難しいのは、この条件が頂点とエッジを何度も再訪するウォークを含め、**スタック可能なすべてのウォーク**にわたって定量化されることです。 個々の散歩について推論することはできません。 すべてのスタック可能なウォークがいつ正しく動作するかを構造的に特徴付ける必要があります。 

いくつかの微妙な状況は見逃しがちです。 

パスを検討する```
1 -> 2 -> 3
```両端の色が異なります。 

散歩```
1 -> 2 -> 3 -> 2
```エッジの色をプッシュします$(1,2)$、次にエッジの色$(2,3)$、エッジを使用してポップします$(2,3)$。 これで大丈夫です。 

ここで分岐構造を想像してください```
    2
    |
1 ->3<-4
```3 に入る 2 つのエッジの色が異なる場合、ウォークは一方のエッジから入り、別の場所をさまよって、後でもう一方のエッジを通過する可能性があります。 スタック メカニズムは、色間の平等を強制し始めます。 

重要な課題は、どの等価性が強制されるかを正確に発見することです。 

## アプローチ

 ブルートフォースビューは、すべてのエッジ方向をプッシュシンボルとして、すべての逆方向のトラバースを対応するポップシンボルとして考えることです。 ウォークを列挙して、すべての色の制約を導出することができます。 

これでは絶望的だ。 木でも$10^5$エッジは任意に何度でも再訪できるため、頂点は無限に多くのウォークを許可します。 有限列挙戦略はありません。 

画期的な進歩は、スタックの動作がまさに適切にネストされた括弧の動作であることを認識することによってもたらされます。 

エッジをその方向に横切るたびに、何かを押します。 それを後方にトラバースするたびに、何かがポップします。 スタック可能なウォークとは、まさに、すべてのポップが以前は一致しなかったプッシュと一致するシーケンスです。 

すべてのポップが通過したエッジと同じ色のボールを削除するという要件は、スタック順序によって強制されるすべてのプッシュ-ポップ ペアが同じ色に対応する必要があることを意味します。 

散歩について推論する代わりに、有向木自体について推論します。 

どこかに木を根付かせたとします。 エッジが親から子を指している場合、下方向にトラバースするとプッシュが作成されます。 同じエッジを上に横切るとポップが発生します。 スタックは、ツリーの領域に出入りするように動作します。 

可能なウォークを実行した後、重大な事実がわかります。 

有効な構造は、すべての有向エッジが単一のルートで一貫して方向付けられる場合にのみ存在します。 言い換えれば、ルートを選択した後は、すべてのエッジがルートから離れる方向を向く必要があります。 方向性が混在すると、避けられない矛盾が生じます。 

より正確には、最終的な有向ツリーは、ある頂点に根を張る樹木でなければなりません。 

その後、スタックの動作は DFS の括弧と同じになります。 すべてのポップは、一意のルート パスに沿った最新の一致しないプッシュと強制的に一致します。 

これにより、色の制約が即座に決定されます。 同じ頂点を離れるすべてのエッジは色を共有する必要があります。 そうしないと、ウォークが 1 つの子エッジを突き抜けて別の子エッジを突き抜けてしまい、不一致が生じる可能性があります。 

逆に、頂点のすべての外向きエッジが同じ色になると、すべてのスタック可能なウォークはボール スタック可能になります。 

問題は次のように変換されます。 

1. すでに有向エッジがルートを許可し、すべての有向エッジがそのルートから離れる方向を向くかどうかを判断します。 
2. そのようなルートが存在する場合、各頂点がすべての出力エッジで共有される 1 つの色に寄与するときに、個別の色の数を最大化します。 

色の最大数は、できるだけ多くの頂点に異なる色を与えることで得られます。 1 つの頂点のすべての外向きエッジは同じ色を共有する必要があるため、色は少なくとも 1 つの外向きエッジを持つ内部頂点に対応します。

 ## アルゴリズムのチュートリアル

 ### ステップ 1

 すべての固定有向エッジを解釈する$u \to v$ルートの制約として。 

最終的な方向をルートから離す必要がある場合、ルートは、次のコンポーネントを含むコンポーネントの内側に置くことはできません。$v$そのエッジを削除した後。 

同様に、ルートは、次のものを含む側に属している必要があります。$u$。 

### ステップ 2

 基礎となるツリーを、たとえば頂点 1 などに任意にルートします。 

すべてのサブツリーが連続セグメントになるようにオイラー ツアー間隔を計算します。 

### ステップ 3

 固定エッジごとに$u \to v$、一時的なルート化でどちらのエンドポイントが他のエンドポイントの祖先であるかを判断します。 

もし$u$の先祖です$v$の場合、有効なルートは正確にサブツリーの外側にあります($v$）。 

もし$v$の先祖です$u$の場合、有効なルートは正確にサブツリー内にあります($u$）。 

これらはオイラー位置に関する単純な範囲制約です。 

### ステップ 4

 すべての制約をオイラー次数の差分配列手法と組み合わせます。 

すべての頂点について、それが満たす制約の数を数えます。 

すべての制約を満たす頂点は、グローバル ルートとして機能できます。 

そのような頂点が存在しない場合は、出力$-1$。 

### ステップ 5

 有効なルートを選択してください$r$。 

すべての無向エッジを遠ざける方向に向けます。$r$。 

すでに方向付けられているエッジは自動的に反対方向を指します。$r$制約構造のため。 

### ステップ 6

 色を割り当てます。 

ルートを除くすべての頂点について、その頂点をその親に接続するエッジを考慮します。 

そのエッジの色は親頂点によって決まります。 

同じ親から離れるすべてのエッジは同じ色を受け取ります。 

### ステップ 7

 使用した親ラベルを連続した色番号に圧縮します。 

個別の色の数は、少なくとも 1 つの子を持つ頂点の数 (最大値) に等しくなります。 

### なぜ効果があるのか

 ルート制約は、すべての有向エッジが共通のルートから離れる方向を向くために必要な条件です。 そのようなルートが存在しない場合、ある有向エッジはルートを指し、別のエッジはルートを向く必要があり、局所的な色の等価性ではスタック マッチングを表現できないスタック可能なウォークを可能にする構造が作成されます。 

すべてのエッジがルートから離れた方向を向いている場合、すべてのスタック可能なウォークは、ルートのあるツリー エッジの適切にネストされた走査のように動作します。 子サブツリーへの入力に対応するプッシュは、その同じサブツリーから出ることによって一致する必要があります。 したがって、必要な色の同等性は、同じ親を共有するエッジ間だけです。 

親ごとに 1 つの色を割り当てると、必要なすべての等式が満たされます。 異なる親は異なる色を受け取ることができ、可能な最大数の色が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

edges = []
g = [[] for _ in range(n)]

for i in range(n - 1):
    u, v, t = map(int, input().split())
    u -= 1
    v -= 1
    edges.append((u, v, t))
    g[u].append((v, i))
    g[v].append((u, i))

tin = [0] * n
tout = [0] * n
parent = [-1] * n
depth = [0] * n

timer = 0

stack = [(0, -1, 0)]
while stack:
    v, p, state = stack.pop()

    if state == 0:
        tin[v] = timer
        timer += 1

        stack.append((v, p, 1))

        for to, _ in reversed(g[v]):
            if to == p:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            stack.append((to, v, 0))
    else:
        tout[v] = timer - 1

def is_ancestor(a, b):
    return tin[a] <= tin[b] <= tout[a]

diff = [0] * (n + 1)
need = 0

for u, v, t in edges:
    if t == 0:
        continue

    need += 1

    if is_ancestor(u, v):
        l = tin[v]
        r = tout[v]

        diff[0] += 1
        diff[n] -= 1

        diff[l] -= 1
        diff[r + 1] += 1
    else:
        l = tin[u]
        r = tout[u]

        diff[l] += 1
        diff[r + 1] -= 1

cur = 0
root = -1

for v in range(n):
    cur += diff[v]
    if cur == need:
        root = v
        break

if root == -1:
    print(-1)
    sys.exit()

parent = [-1] * n
order = [root]
parent[root] = root

for v in order:
    for to, _ in g[v]:
        if parent[to] != -1:
            continue
        parent[to] = v
        order.append(to)

children_count = [0] * n
for v in range(n):
    if v != root:
        children_count[parent[v]] += 1

color_of_vertex = [-1] * n
color_id = 0

for v in range(n):
    if children_count[v] > 0:
        color_id += 1
        color_of_vertex[v] = color_id

answer = []

for u, v, t in edges:
    if parent[v] == u:
        p, q = u, v
    elif parent[u] == v:
        p, q = v, u
    else:
        raise RuntimeError

    c = color_of_vertex[p]
    answer.append((p + 1, q + 1, c))

print(color_id)
for row in answer:
    print(*row)
```最初の DFS はオイラー区間を計算します。 これらの間隔により、サブツリー制約を差分配列上の範囲加算として表すことができます。 

次のフェーズでは、すべての固定有向エッジを処理します。 各エッジは、そのエンドポイントの祖先関係に応じて、「内部サブツリー」制約または「外部サブツリー」制約のいずれかを提供します。 

制約を累積した後、それらをすべて満たす頂点をグローバル ルートとして使用できます。 

ルートがわかれば、木の向きを決めるのは簡単です。 すべてのエッジは、ルート化されたツリーの親から子に向けられます。 

色付けフェーズでは、スタック引数が入ります。 すべての親頂点は、そのすべての出力エッジで共有される 1 つの色を受け取ります。 子のない頂点は、頂点からエッジが発生しないため、色を提供しません。

 ## 特殊なケース

 検討してください```
3
1 2 1
3 2 1
```両方の有向エッジは頂点 2 を指します。ルートから離れたルート方向では、頂点 2 が同時に 1 と 3 の両方の下にある必要がありますが、これはツリーでは不可能です。 制約累積フェーズでは、すべての制約を満たす頂点が残らないため、アルゴリズムは出力を出力します。`-1`。 

考慮する```
2
1 2 0
```固定方向の制約はありません。 すべての頂点は有効なルートです。 アルゴリズムは 1 つを選択し、唯一のエッジをそこから遠ざけ、1 つの色を割り当て、成功します。 

考慮する```
5
1 2 0
1 3 0
1 4 0
1 5 0
```4 つのエッジはすべて、ルート方向で同じ親を残します。 正しさの証明は、色を共有する必要があることを示しています。 このアルゴリズムは、4 つのエッジすべてに 1 つの色を正確に割り当てます。 ここで複数の色を使用しようとするとスタック条件に違反するため、構築はすでに最適化されています。
