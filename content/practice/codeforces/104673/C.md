 ## 解決策
 ## 問題の理解

 私たちには、それぞれが正確に 9 桁で構成される、クリーンな電話番号の固定データベースが与えられています。 これに加えて、電話番号の破損したバージョンを表すクエリ文字列も多数受信します。 これらのクエリ文字列の一部の数字が汚れのために欠落しています。 コーヒーの染みはちょうど 1 桁を隠し、単一のワイルドカード文字で表されます。 ジュースの染みは 1 つ以上の数字の連続したブロックを隠し、別のワイルドカード文字で表されます。 損傷した各数値は、元の 1 つの数値に由来します。タスクは、損傷したクエリごとに、有効な汚れパターンを適用した後に、クリーンなデータベースからその数値がいくつ生成されたかを判断することです。 

重要な点は、単一の元の数値を再構成しているわけではないということです。 代わりに、各クエリは、そのクエリ内のワイルドカードの少なくとも 1 つの有効な解釈と互換性のあるデータベース エントリの数を求めます。 

この制約により、データベースに含まれる数値は最大 10,000 個ですが、最大 300,000 個の非常に多くのクエリが強制されます。 したがって、すべてのデータベース エントリに対する単純なクエリごとの比較では、最悪の場合、最大約 3×10^9 の完全一致チェックが必要になりますが、これでは遅すぎます。 ワイルドカードは独立した文字の一致ではないため、各一致自体は自明ではありません。ジュースの染みは連続したセグメントにまたがりますが、コーヒーの染みは孤立した 1 桁の穴です。 

微妙なエッジ ケースは、クエリの解釈が重複していることから発生します。 みたいなパターン`12?34?56`どの桁が欠落しているかを一意に指定するわけではありません。 元の番号の割り当てが異なると、ワイルドカードの異なる解釈が満たされる可能性があるため、ジュースとコーヒーの染みの少なくとも 1 つの一貫した配置の存在に対して候補番号をチェックする必要があります。 

ジュースの汚れが複数の指に重なっている場合、別の特殊なケースが発生します。`12***34`アスタリスクは元の数値の単一の連続セグメントにマップする必要があるため、3 つの独立したコーヒーの染みとはまったく異なる動作をします。 単純な文字ごとの一致では、これを独立した位置および過剰カウントとして誤って処理します。 

## アプローチ

 ブルートフォース手法では、クエリごとにすべてのデータベース番号を反復処理し、最大 2 つの孤立した未知の数字と最大 1 つの連続した未知のブロックを挿入することで、クリーンな数値をクエリに変換できるかどうかをテストします。 特定の候補について、考えられるジュース セグメントのすべての配置を試し、残りの不一致が最大 2 つのコーヒーの染みでカバーできることを確認する必要があります。 注意深く枝刈りしたとしても、このペアごとのチェックは各比較が O(9) であるためコストが高くなりますが、構造マッチングには追加のケース分析が必要であり、3×10^5 クエリの下では実効コストがはるかに高くなります。 

重要な観察は、汚れの構造が非常に限られているということです。 各クエリがきれいな数値と異なるのは、非常に制限された方法で最大 3 つの互いに素なセグメントを置き換えることだけです。長くても 1 つのセグメント (ジュース)、最大 2 つの単一の位置が欠落する可能性があります (コーヒー)。 数値の長さは固定で小さいため、クエリを固定数字とワイルドカード セグメントで構成される正規化パターンに解釈し、前処理されたデータベース文字列と照合するための可能なすべての方法を列挙できます。 

すべての数値に対して各クエリを独立して処理するのではなく、視点を逆転させます。 データベース番号ごとに、有効な染色ルールに基づいて一致する可能性のあるすべてのパターンを生成し、それらをハッシュマップでカウントします。 各数値の長さは 9 であるため、生成できる有効な汚れパターンの数は、コーヒーの場合は最大 2 つの位置、ジュースの場合は最大 1 つの間隔の選択から導出される小さな定数によって制限されます。 これは最大でも 9^3 の可能性のオーダーですが、それでも 10^4 の数値には十分小さいです。 

次に、各クエリは制約の正規表現に変換され、その数を直接検索します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 重い定数因数を使用した O(N · Q · 9) | お(1) | 遅すぎる |
 | パターンを事前計算する | O(N · 1) 前処理 + O(Q · 1) クエリ | O(パターンの合計) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、クリーンな各数値を、考えられるすべての損傷パターンを生成できるソースとして扱います。 

1. すべてのクリーン番号について、ジュース汚れセグメントを選択するためのあらゆる方法を検討します。 これは、ジュース汚れが存在しない可能性を含め、連続ブロックの開始インデックスと終了インデックスを選択することを意味します。 これを最初に列挙する理由は、ジュース染色が複数の数字を単一の未知の領域にマージする唯一の操作であるためです。 
2. ジュースセグメントを修正した後、それらの位置を非表示としてマークします。 残りの目に見える位置はコーヒーのシミの候補です。 
3. 残りの表示位置から、コーヒーのシミとして隠すインデックスを最大 2 つ選択します。 これは、不明になる 0 個、1 個、または 2 個の孤立した数字を選択することに対応します。 制約が「最大 2 つ」であるため、明示的に 2 つ未満を許可します。 
4. ジュースセグメントとコーヒーの位置の組み合わせごとに、非表示の位置がプレースホルダーで置き換えられる正規パターン文字列を構築します。 すべての非表示セグメントを正規化して、連続する非表示領域がどのように形成されたかに依存するのではなく、一貫して表現されるようにします。 
5. このパターンを生成できるデータベース番号の数をカウントするハッシュ マップにこのパターンを挿入します。 
6. クエリごとに、それを同じ正規形式に変換します。 これには、次の実行の解釈が含まれます。`*`潜在的な果汁セグメントとして分離されます`?`ただし、クエリはすでに制約をエンコードしているため、正規化された署名を生成するだけで済みます。 
7. その署名の事前計算されたカウントを出力します。 

正確さは、クリーンな数値からクエリへのすべての有効な変換が、ジュース区間への 1 つの分解と最大 2 つの単一の削除に正確に対応するという事実にかかっており、私たちの列挙はそのような分解をすべてカバーしています。 

それが機能する理由は、表現の完全性と独自性に基づいています。 ジュースの間隔は選択したセグメントによって一意に決定され、コーヒーの位置は明示的に列挙されるため、すべての有効な染色シナリオは、私たちの構築の下で正確に 1 つの標準パターンを生成します。 逆に、私たちが生成するすべてのパターンは、元の数値に適用される有効な染色操作に対応するため、無効な一致は導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_patterns(s):
    n = len(s)
    res = []

    # no juice case
    juice_ranges = [(-1, -2)]
    for l in range(n):
        for r in range(l, n):
            juice_ranges.append((l, r))

    for l, r in juice_ranges:
        hidden = [False] * n

        # apply juice
        if l != -1:
            for i in range(l, r + 1):
                hidden[i] = True

        visible = [i for i in range(n) if not hidden[i]]

        # choose up to 2 coffee stains
        m = len(visible)
        # 0 coffees
        def add_pattern(cset):
            arr = []
            for i in range(n):
                if hidden[i] or i in cset:
                    arr.append('*')
                else:
                    arr.append(s[i])
            res.append(''.join(arr))

        add_pattern(set())

        # 1 coffee
        for i in range(m):
            add_pattern({visible[i]})

        # 2 coffees
        for i in range(m):
            for j in range(i + 1, m):
                add_pattern({visible[i], visible[j]})

    return res

def normalize_query(q):
    return q

def main():
    n = int(input())
    mp = {}

    for _ in range(n):
        s = input().strip()
        for pat in generate_patterns(s):
            mp[pat] = mp.get(pat, 0) + 1

    q = int(input())
    out = []
    for _ in range(q):
        s = input().strip()
        out.append(str(mp.get(s, 0)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```前処理ステップでは、各クリーン番号から考えられるすべての損傷パターンを構築します。 機能`generate_patterns`ジュースセグメントを明示的に列挙し、最大 2 つの追加のコーヒー位置を選択します。 結果として得られる各文字列は、頻度マップのキーとして使用される正規表現です。 

クエリ側は直接辞書検索になります。 クエリは最終的な表示パターンをすでにエンコードしているため、追加のデコードは必要ありません。 

微妙なポイントは、ジュースとコーヒーが間違って重ならないようにすることです。 残りのインデックスのみからコーヒーの位置を選択する前に、ジュースの位置を永久に非表示としてマークすることで、これを強制します。 

## 実用的な例

 2 つの数値を含む小さなデータベースの例を考えてみましょう。`123456789`そして`123450789`。 

のようなクエリの場合`12345*789`、中央に単一の連続した未知のブロックが観察されます。 

| ステップ | ジュースシリーズ | コーヒーのポジション | 生成されたパターン |
 | --- | --- | --- | --- |
 | 1 | なし | なし | 123456789 |
 | 2 | (5,5) | なし | 12345*789 |
 | 3 | (5,5) | {6} | 12345**89 |

 これは、異なる解釈によって、同じ基数に対して複数の有効なパターンがどのように生成されるかを示しています。 

次にクエリを考えてみましょう`1234??789`、2 つの孤立した欠落数字を表します。 

| ステップ | ジュースシリーズ | コーヒーのポジション | 生成されたパターン |
 | --- | --- | --- | --- |
 | 1 | なし | {5,6} | 1234??789 |
 | 2 | (4,6) | なし | 1234???789 |
 | 3 | (4,6) | {5} | 1234???89 |

 これは、ジュースとコーヒーがどのように相互作用するかを示しています。連続した非表示領域は複数のワイルドカード文字を吸収できますが、コーヒーはその領域の外側にある個々の数字を削除します。 

これらのトレースは、前処理によって破損した文字列の構造的に有効な解釈がすべて生成されたことを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · 9^3 + Q) | 固定長 9 と最大 2 つのコーヒー + 1 つのジュース セグメントにより、各数値は一定数の汚れパターンを生成します。 
| スペース | O(P) | P は、ハッシュ マップに格納されている個別に生成されたパターンの数です。 

文字列の長さは一定であるため、数値ごとのパターンの数には制限があります。 N が最大 10^4 であれば、この前処理は簡単に実現でき、クエリ処理はクエリあたり O(1) であり、制限内に問題なく収まります。

 ## 特殊なケース

 のようなケース`?????????`最大限の曖昧さを引き起こします。 このアルゴリズムはデータベースのすべての数値を正確にカウントします。すべての数値は、すべての桁にわたる単一のジュース セグメント、または最大 2 つのコーヒーの染みと小さなジュース セグメントに分割することで完全に隠すことができるためです。 

コーヒーのような汚れだけがついたケース`12?45?78?`孤立した位置のみが非表示になるパターンを生成することで処理されます。 前処理により、このような位置の最大 2 つの組み合わせがすべて含まれることが保証されます。 

みたいなフルジュース専用ケース`*********`文字列全体をカバーするジュース セグメントを選択することで処理され、データベース番号ごとに 1 つのパターンが生成され、複数のコーヒー構成から過大なカウントが行われないようにします。
