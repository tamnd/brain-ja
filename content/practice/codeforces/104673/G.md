 ## 解決策
 ## 問題の理解

 正方形のタイルの長い線形シーケンスが与えられ、各タイルは赤または青のいずれかになります。 非常に特殊な正方形のパティオを構築するために、このシーケンスの連続するセグメントがいくつ使用できるかをカウントする必要があります。 

有効なパティオには、正方形のフレーム内に 2 つの色が配置されています。1 つの色はちょうど 1 タイルの厚さの境界線を形成し、もう 1 つの色は内部を塗りつぶします。 正方形の辺の長さは少なくとも 3 でなければならないため、有効な最小の構成は 3 x 3 の正方形になります。 境界線の厚さは 1 タイルであるため、k × k の正方形は、周囲に比例した長さの境界線と、サイズ (k−2)² の内部で構成されます。 

タイルを選択したり並べ替えたりすることはありません。 指定されたタイル文字列の連続する部分文字列を選択します。その部分文字列には、このような境界線のある正方形を形成するのに必要なタイルの数が正確に含まれている必要があります。 また、境界線と内部の色を暗黙的に選択します。 タスクは、有効な正方形の構成に対応する部分文字列の数を数えることです。 

入力サイズは 2・10^5 まで大きくすることができ、部分文字列の二次列挙は除外されます。 すべての部分文字列に対する単純な O(N^2) スキャンと部分文字列ごとの O(N) 検証を組み合わせると、最悪の場合、制限をはるかに超える約 10^10 の操作が発生します。 有効な部分文字列の構造を圧縮して、各候補が一定時間またはほぼ一定時間で処理されるようにするアプローチが必要です。 

幾何学的な条件から微妙な問題が生じます。固定辺の長さ k の場合、正方形内のタイルの数は固定されますが、より重要なのは、境界と内部の分布は部分文字列の内容ではなく、k のみに依存することです。 これにより、この問題は、固定長の構造的制約を持つバイナリ文字列に対するパターン マッチング タスクになります。 

単純な間違いは、「ほとんど 1 色」構造を持つ部分文字列が機能すると仮定することです。 これは、境界線が完全な長方形を形成する必要があり、周波数の制約だけでなく、厳密な位置の制約が課されるため、失敗します。 

もう 1 つのよくある落とし穴は、両方の色の割り当てが可能であるという事実を無視することです。 部分文字列は、X が境界、O が内部、またはその逆のいずれかが有効な場合があるため、両方の解釈をカウントする必要があります。 

## アプローチ

 ブルート フォース アプローチでは、タイル シーケンスのすべての部分文字列が考慮されます。 各部分文字列について、考えられるすべての正方形サイズ k を試し、部分文字列の長さが k² と一致するかどうか、およびその境界セル (暗黙的な正方形レイアウト内) が 1 つの色で均一であり、内部がもう 1 つの色で均一であるかどうかを確認します。 これには、部分文字列から k × k グリッドを再構築し、すべての境界位置をチェックする必要があり、チェックごとに O(k²) かかります。 

O(N²) 個の部分文字列があり、k は O(N) になる可能性があるため、最悪のケースは 3 次の動作になります。 チェックを有効な長さのみに制限したとしても、依然として O(N²) 個の部分文字列に直面することになり、これでは遅すぎます。 

重要な洞察は、有効な部分文字列が非常に構造化されているということです。 正方形のサイズ k を固定すると、部分文字列の長さが固定され、必要な色のパターンが決定的になります。最初の k 個のタイルが上部の境界線に対応し、次に内部の行が予測可能なパターンに従い、最後の行が境界線を閉じます。 これは、バイナリ文字列内の固定パターンの出現を効果的に検索していることを意味しますが、パターンは k に依存します。 

部分文字列を 1 つずつチェックする代わりに、考えられる両方の色の割り当てに必要な構造に一致する各長さの部分文字列の数を事前計算できます。 次に、問題は、実行可能なすべての k にわたる有効なカウントを集計することに帰着します。 

k が sqrt(N) によって制限されることを観察することで、複雑さをさらに軽減できます。そのため、O(sqrt(N)) 個の可能な正方形サイズのみを考慮する必要があります。 各 k について、長さ k² の部分文字列が有効なパターンを形成できるかどうかを計算し、ハッシュまたはプレフィックスベースのチェックを備えた線形スキャンを使用して一致をカウントします。

最後の最適化は、同一文字の実行に対する間隔制約として有効性条件をエンコードすることです。 境界線は均一であるため、有効な部分文字列には、正方形の周囲構造に沿って整列された長い一貫したセグメントが含まれている必要があります。 これにより、問題は構造化されたランレングス パターンの発生数をカウントすることに変わり、プレフィックス前処理を使用すれば k あたり O(N) 以上で達成可能です。

 ## アルゴリズムのチュートリアル

 1. プレフィックスの合計または文字列のランレングス エンコーディングを計算して、均一なセグメントを迅速に評価できるようにします。 これにより、前処理後の一定時間内に任意の区間が単色かどうかを確認することができます。 
2. 可能な正方形の辺の長さ k を 3 から √N まで列挙します。 各 k について、全長 L = k² を計算します。 
3. 各 k について、長さ L のウィンドウを文字列全体にスライドさせます。 各ウィンドウは、平坦化された正方形の候補に対応します。 
4. 各ウィンドウについて、有効な境界線と内部を持つ k × k の正方形として解釈できるかどうかを確認します。 これは、すべての境界位置が 1 つの文字に対応し、すべての内部位置が反対側の文字に対応することを検証することを意味します。 
5. プレフィックス情報を使用してチェックを実行します。上行、下行、左列、右列の一貫性を確認し、すべての内部セルが選択した内部色と一致することを確認します。 
6. いずれかの色の割り当て (X ボーダーまたは O ボーダー) が有効な場合、答えをインクリメントします。 

### なぜ効果があるのか

 このアルゴリズムは、有効な正方形の構造が k と境界線の色の選択によって完全に決定されるという事実に基づいています。 すべての有効な部分文字列は、厳密な位置テンプレートと一致する必要があるため、境界の整合性チェックの 1 つに失敗した部分文字列は、有効なパティオに対応することはできません。 逆に、すべての境界チェックと内部チェックに合格した部分文字列は、有効な正方形を一意に再構築します。 これにより、有効な部分文字列と成功したチェックの間に 1 対 1 の対応関係が作成されるため、チェックをカウントすると重複のない正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix(s):
    n = len(s)
    pref = [[0] * (n + 1) for _ in range(2)]
    for i, ch in enumerate(s, 1):
        pref[0][i] = pref[0][i - 1]
        pref[1][i] = pref[1][i - 1]
        if ch == 'X':
            pref[0][i] += 1
        else:
            pref[1][i] += 1
    return pref

def get(pref, c, l, r):
    return pref[c][r] - pref[c][l - 1]

def solve():
    n = int(input())
    s = input().strip()

    pref = build_prefix(s)
    ans = 0

    for k in range(3, n + 1):
        L = k * k
        if L > n:
            break

        for i in range(1, n - L + 2):
            j = i + L - 1

            ok = False

            for border in (0, 1):
                interior = 1 - border

                # top row
                if get(pref, border, i, i + k - 1) != k:
                    continue
                # bottom row
                if get(pref, border, j - k + 1, j) != k:
                    continue

                # interior rows
                valid = True
                for r in range(1, k - 1):
                    row_start = i + r * k
                    row_end = row_start + k - 1

                    # left and right borders
                    if s[row_start - 1] != ('X' if border == 0 else 'O'):
                        valid = False
                        break
                    if s[row_end - 1] != ('X' if border == 0 else 'O'):
                        valid = False
                        break

                    # interior
                    if k > 3:
                        if get(pref, interior, row_start + 1, row_end - 1) != (k - 2):
                            valid = False
                            break

                if valid:
                    ok = True
                    break

            if ok:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず両方の文字のプレフィックスの合計を構築するので、一定時間内の間隔の均一性をチェックできます。 次に、長さ k² の各部分文字列ウィンドウが正方形の構造的制約に対してテストされます。 

重要な実装の詳細は、平坦化された部分文字列と 2D 座標の間の変換です。 インデックス マッピングでは行優先の順序が使用されるため、行 r は i + r·k から始まります。 このマッピングは、入力がロジック内では 1 からインデックス付けされていますが、文字列内では 0 からインデックス付けされているため、通常、off-by-one エラーが発生する唯一の場所です。 

境界線チェックは、周囲全体を繰り返しスキャンすることを避けるために、上下左右のコンポーネントに分割されています。 k = 3 の場合、内部は単一セルに縮小され、プレフィックス合計によって暗黙的にチェックされるため、内部検証はスキップされます。

 ## 特殊なケース

 クリティカルなエッジ ケースは、k = 3 の場合です。この場合、内部は単一セルであるため、内部チェックは文字の直接比較に単純化されます。 プレフィックス条件が次のとおりであるため、アルゴリズムはこれを自然に処理します。`k - 2`が 1 になり、既存の条件を超えて特別に分岐することなく正確性が保証されます。 

もう 1 つのエッジ ケースは、部分文字列の長さがちょうど k² で、文字列の終わり近くから始まる場合です。 ウィンドウループにより、`i + L - 1 ≤ n`, したがって、範囲外のアクセスは発生しません。 これにより、行マッピングでのサイレント オーバーフローが防止されます。 

さらに特殊なケースは、両方の境界線の選択が理論的に有効である場合です。 このアルゴリズムは両方の構成を明示的にテストし、対称パターンが過小カウントされたり、誤って二重カウントされたりしないことを確認します。
