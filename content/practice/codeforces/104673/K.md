 ## 解決策
 ## 問題の理解

 平面内に一連の点が与えられ、それぞれが 1 回だけ訪問する必要がある火山を表します。 旅行者は、選択した任意の地点から出発し、すべての地点を訪れ、最後に訪れた地点で終了するパスを構築する必要があります。 動作ルールは制限的です。各動作は北、南、東のいずれかでなければなりません。 西に移動することはできないため、移動中に x 座標が減少することはありません。 y 座標は自由に上下できます。 

移動のコストは、これらの軸に沿った移動の下でのパスのユークリッド グリッドの合計長さです。これは、実際には、x または y に沿ったすべての単位ステップが合計距離に寄与することを意味します。 軸に沿った移動のみが許可されるため、問題は、すべてのポイントが確実に訪問されるようにしながら、水平方向および垂直方向の移動の合計を最小限に抑えることになります。 

制約の構造上の重要な意味は、西方向への移動がないため、X 座標がタイムラインのように機能することです。 一度大きな x 値に移動すると、元に戻ることはできません。 これは、有効なルートであれば、x 座標の非降順でポイントを効果的に処理し、おそらく等しい x 値でグループ化されていることが直ちに示唆されます。 

最大 100,000 点の場合、サブセットに対して順列やパス検索を試みるソリューションは不可能です。 点のペアを直接比較する二次アプローチでも、速度が非常に遅くなります。 私たちは、x 座標によってポイントを圧縮し、各グループを線形または線形に近い時間で処理する戦略を余儀なくされています。 

複数の点が同じ x 座標を共有する場合、微妙な問題が発生します。 その場合、その垂直線内で訪問を自由に並べ替えることができるため、垂直移動コストが大幅に変わる可能性があります。 もう 1 つの重要なエッジ ケースは、すべての点が 1 つの垂直線上にある場合です。 この場合、水平方向の移動はまったくなくなり、問題は、ライン内の y 値のセットをカバーする最短パスを見つけることになります。これは、それらの広がりのみに依存します。 

## アプローチ

 自然な最初の試みは、西進禁止の制約を尊重しながら、任意の順序でポイントを訪問するという観点から考えることです。 点のすべての順列または x の増加を考慮したすべての可能なシーケンスを試すことを想像することもできます。 これはすぐに実行不可能になります。x でソートされた順序に制限しても、点を同じ x でインターリーブする方法とそれらの間で遷移する方法を選択する自由がまだ残っているからです。 可能性の数は、個別の x 値の列の数に応じて指数関数的に増加します。 

重要な観察は、動きの制限により、ジオメトリが x 内で基本的に 1 次元になるということです。 ポイントが x 座標によってグループ化されると、パスはこれらのグループを x の昇順で移動する必要があり、連続する 2 つの x 値間の水平方向の遷移はすべて強制されます。 これにより、水平方向の組み合わせの自由が完全に失われます。 

残りの問題は垂直方向の問題です。各固定 x 座標グループ内で、ある y 値 (前のグループによって決定された) でグループに入り、選択した y 値のままにするとして、すべての y 値を横断する方法を決定する必要があります。 グループ内の最適な構造は、常に「一方の極端に進み、次にもう一方の極端に移動する」パターンです。極端に到達しない迂回は、追加のポイントをカバーするのに役立ちずに垂直距離を無駄にするためです。 

これにより、各 x グループが小さな状態に縮小されます。考慮する必要があるのは、最小 y または最大 y でグループを終了するかどうかだけです。 グループ内の他のすべては厳密に悪いです。 

ブルートフォース手法でも、グループごとに入場と退出の動作を選択するあらゆる方法が試行されるため、グループ間の指数関数的な分岐が発生します。 最適化では、各グループが意味のある終了状態を 2 つだけ提供することが認識され、左から右への単純な動的プログラミング遷移が可能になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての訪問命令に対する総当り攻撃 | お(ん!) | O(N) | 遅すぎる |
 | エンドポイントの状態を含むソートされた x グループの DP | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての点を X 座標でグループ化し、個別の X 値を昇順に並べ替えます。 各グループ内で y 値を並べ替え、最小値と最大値 y を計算します。 

このステップでは、平面を一連の垂直列に変換し、それぞれが垂直スパンによって要約されます。 
2. 各列について、その垂直範囲を事前に計算し、端点のみを記憶します。 

列の内部ポイントは、最小値と最大値を除いて、最適な遷移に影響を与えることはありません。 
3. 各列について 2 つの可能性を追跡する動的プログラミング状態を定義します。つまり、その列の走査をその最小 y で終了するか、最大 y で終了するかです。 

これは、垂直セットの最適なトラバースを、コストを増加させることなく極端に終了するように調整できるため、十分です。 
4. 内部のどこからでも開始できることを考慮して、最初の列を初期化します。 最適な戦略は、一方の端からもう一方の端まで移動し、柱の垂直スパンに等しいコストを与え、どちらかの端で終了することです。 

事前の制約がないため、内部コストを最小限に抑えるためにエントリ ポイントを自由に選択できます。 
5. 列を左から右に処理します。 列 i にいて、列 i−1 の両端での終了の最良コストが既知であるとします。 
6. 列 i-1 から列 i に移動するとき、x 座標の差に等しい水平コストを追加します。 この移動中、y 座標は変化しないため、列 i の入口 y は、列 i-1 の選択された出口 y とまったく同じになります。 
7. 列 i の考えられる各エントリ y (列 i-1 のいずれかの状態からのもの) について、列 i のすべての点を横断し、その最小値または最大値 y で終了するコストを計算します。 線分上の最適な走査は次のように動作するという事実を利用します。 

エントリがセグメントの外側にある場合は、遠方のエンドポイントに直接進みます。 入口が内側にある場合は、両端に行かなければなりません。 
8. 列 i の両方の終了選択肢の最小コストを保存し、続行します。 
9. 答えは、最後の列の 2 つの DP 状態の最小値です。 

### なぜ効果があるのか

 どの列においても、過去に関する唯一の関連情報は、到達する y 座標であり、未来に関する唯一の関連情報は、どの極値から離れるかです。 列の内部では、すべての点が単一の垂直線上にあるため、実現可能性を変えることなく、それらを通過するパスを両端の間の単調なスイープに再配置できます。 これにより、合計距離を増加させることなく、非極端なエンドポイントを極端なエンドポイントに変換できるため、状態を最小エンドポイントと最大エンドポイントに制限しても最適解が決して破棄されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    pts.sort()
    
    cols = []
    i = 0
    while i < n:
        x = pts[i][0]
        ys = []
        while i < n and pts[i][0] == x:
            ys.append(pts[i][1])
            i += 1
        ys.sort()
        cols.append((x, ys[0], ys[-1]))
    
    m = len(cols)
    
    if m == 1:
        # single column: just cover vertical span
        return cols[0][2] - cols[0][1]
    
    # dp[i][0] = end at min y, dp[i][1] = end at max y
    x0, lo0, hi0 = cols[0]
    dp0 = [hi0 - lo0, hi0 - lo0]
    
    for i in range(1, m):
        x, lo, hi = cols[i]
        px, plo, phi = cols[i-1]
        dx = x - px
        
        ndp = [10**30, 10**30]
        
        for prev_end in (0, 1):
            prev_y = plo if prev_end == 0 else phi
            base = dp0[prev_end] + dx
            
            # enter at prev_y, traverse current column
            # compute cost to end at lo
            if prev_y <= lo:
                cost_lo = base + (hi - prev_y)
            elif prev_y >= hi:
                cost_lo = base + (prev_y - lo)
            else:
                cost_lo = base + (hi - lo) + min(prev_y - lo, hi - prev_y)
            
            # end at hi
            if prev_y <= lo:
                cost_hi = base + (hi - lo) + (lo - prev_y)
            elif prev_y >= hi:
                cost_hi = base + (prev_y - lo) + (hi - lo)
            else:
                cost_hi = base + (hi - lo) + min(prev_y - lo, hi - prev_y)
            
            ndp[0] = min(ndp[0], cost_lo)
            ndp[1] = min(ndp[1], cost_hi)
        
        dp0 = ndp
    
    print(min(dp0))

if __name__ == "__main__":
    solve()
```実装は、ポイントを x 座標でソートされた垂直列に圧縮することから始まります。 個々の点を保存せずにすべての内部構造を最適に再構築できるため、各列はその最小値と最大値 y に削減されます。 

動的プログラミング配列は、列の最下部または最上部での終了に対応して、列ごとに 2 つの状態を格納します。 各遷移について、前の出口 y で次の列に入るのを明示的にシミュレートし、水平距離を追加して、いずれかのエンドポイントで終了しながら現在の列をスイープする最適な方法を計算します。 

よくある微妙な点は、エントリ y が前の状態によって固定されているため、独立して選択できないことです。 もう 1 つの重要な点は、最適なパスが列間で方向を切り替える可能性があるため、両方の dp 遷移で以前の両方のエンドポイントを考慮する必要があることです。

 ## 特殊なケース

 単一の x 座標の場合、DP 全体が折りたたまれます。 水平方向の移動や状態遷移の必要がないため、アルゴリズムは垂直方向のスパンを返すことによってこれを明示的に処理します。 

すべてのポイントが同じ座標を共有する場合、最小値と最大値の両方が同じ値に折りたたまれるため、すべての DP 状態は全体を通してゼロのままとなり、正しくゼロコストが生成されます。 

列の x に大きなギャップがある場合でも、各列の遷移が 1 つの東方向への移動セグメントに対応するため、水平方向の寄与は遷移ごとに 1 回だけ正しく累積されます。
