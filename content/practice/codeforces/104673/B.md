 ## 解決策
 ## 問題の理解

 海岸線を表す長方形のグリッドが与えられ、このグリッドの中に多くの「ドック」があります。 各ドックは、水平または垂直に配置された 1 セルの厚さの直線セグメントであり、連続するグリッド セルのセットにまたがっています。 各ドックの長さは少なくとも 2 です。 

カヌーは元々各ドック内に建造されましたが、カヌーはドックよりも 1 セル短いです。 これは、すべてのドックについて、そのセグメント上のちょうど 1 つのグリッド セルがそのカヌーによって占有されていないのに対し、ドックの他のすべてのセルは埋められていることを意味します。 

目標は、同時に 2 つの異なるカヌーによってグリッド セルが占有されないように、どの単一セルを空のままにするかをすべてのドックごとに独立して選択できるかどうかを決定することです。 

2 つのドックがグリッド上で交差したり重なったりする場合があります。 2 つのカヌーが両方とも共有セルを占有している場合、その構成は無効です。 このタスクは、すべてのグリッド セルが最大 1 つのカヌーによって使用されるように、ドックごとに 1 つの「欠落セル」の選択肢が存在するかどうかを判断することです。 

制約はドックの数が最大 250,000 と多く、グリッド自体は最大でも 500 x 500 です。これは、セルごとの割り当てをシミュレートしたり、ドックごとに指数関数的な選択を試行したりできないことをすぐに示唆しています。 どのようなソリューションでも、ドックと交差点は、全体の表現において本質的に線形または線形に近い時間で処理する必要があります。 

素朴な考えは、各ドックに欠落しているセルを任意に割り当ててから、すべての交差をチェックしてみることです。 これは失敗します。各ドックには最大 500 の選択肢があり、最大 250,000 のドックが存在するため、総当たり攻撃は完全に不可能になります。 

2 番目の単純なアイデアは、すべてのグリッド セルを反復処理して、どのドックがセルを通過するかを追跡し、セルごとに一貫性制約を適用することです。 これは自然なことのように聞こえますが、セルベースのシミュレーションでは、潜在的に大きなオーバーラップを繰り返し処理する必要があり、多くのドック間で大量の伝播や繰り返しチェックが発生する可能性があります。 

複数のドックが 1 つのセル内で交差して密な交差領域を形成する場合、微妙なエッジ ケースが発生します。 「最初に見つかった交差点を常に削除する」などの貪欲なローカル選択は、グローバルに失敗する可能性があります。これは、1 つのドックに対する決定が、離れた別の交差点で矛盾を強制する可能性があるためです。 

## アプローチ

 重要な問題は、各ドックがカヌーが欠けている単一の「禁止された占有セル」に寄与していることです。 そのドックの 1 つおきのセルが占有されています。 したがって、各ドックは基本的に 1 つの特別なセルを選択し、すべてのグリッド セルに制約が課せられます。つまり、2 つのカヌーが同時に占有できないということです。 

これは制約システムとして再構成できます。 複数のドック上にあるグリッド セルごとに、それらのドックのうちの少なくとも 1 つが、そのセルを削除されたセルとして選択して「放棄」する必要があります。 そうしないと、両方のカヌーがそこを占領してしまい、衝突が発生してしまいます。 

したがって、2 つのドック間のすべての交差セルには制約が生じます。2 つのドックのうちの少なくとも 1 つは、そのセルを削除位置として選択する必要があります。 これは、2 つの変数の選択に対する論理 OR 制約です。 

重要な観察は、ドックには多くの可能なセルがあるにもかかわらず、セグメントのエンドポイントのみが重要であるということです。 ドックが内部セルを削除する場合、交差点での競合をきれいに解決できる位置は端点だけであるため、その選択は端点を選択するよりも厳密に制限されます。 内部の削除は、幅 1 のセグメントの構造化されたグリッドで複数の制約を同時に解決するのに決して役立つことはないため、実行可能性を失わずに各ドックがエンドポイントを削除するように、有効な構成を変換できます。 

これにより、各ドックは 2 つのエンドポイントのうちの 1 つを削除するという二者択一の決定に減ります。

これで、各交差セルが 2 つのバイナリ変数間の制約を作成します。 ドック A とドック B が共有するセルの場合、競合を回避する唯一の方法は、ドック A とドック B の少なくとも 1 つがそのエンドポイント セルを削除位置として選択することです。 これは、2-SAT インスタンスとしてモデル化できる標準的な含意構造です。 

各ドックは 2 つの状態を持つ変数であり、各交差には「A がエンドポイントを選択するか、B がエンドポイントを選択する」という形式の句が追加されます。 このようなシステムは、含意グラフと強く接続されたコンポーネントを使用して解決できます。 

ブルート フォース アプローチでは、エンドポイントの選択肢を個別に割り当て、すべての交差を検証しようとするため、ドックの数が指数関数的に複雑になります。 2-SAT 再定式化では、すべてのインタラクションが、ドックあたり最大 2 つのノードにわたる線形グラフ構造に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ドックごとのブルート フォースの選択 | 指数 | O(N) | 遅すぎる |
 | エンドポイント変数の 2-SAT | O(N + 交差点) | O(N + 交差点) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 各ドックの選択肢を 2 つに減らす

 すべてのドックについて、グリッド内の 2 つのエンドポイントを特定します。 決定をブール変数として扱います: どのエンドポイントが単一の空のセルになるか。 

これが機能するのは、線分内の交差競合の「吸収者」として一貫して機能できるのは端点のみであるためです。 

### 2. すべての交差点を収集する

 すべてのグリッド セルについて、どのドックがそのセルを通過するかを決定します。 グリッドは最大でも 500 x 500 であるため、各セルをマップして、それが水平セグメントまたは垂直セグメント (または複数の同一線上の重なり) に属しているかどうかを記録できます。 

2 つの異なるドックで共有される各セルは、それら 2 つのドック間に制約を作成します。 

### 3. 各交差を論理制約に変換します。 

セルがドック A とドック B に属しているとします。A も B もこのセルを削除しない場合、両方のカヌーがそのセルを占有し、競合が発生します。 

したがって、制約は次のとおりです。A はこのセルを選択するか、B はこのセルを選択する必要があります。 各ドックには許可される選択肢 (そのエンドポイント) が 2 つだけあるため、この制約は 2 つのブール変数の間の 2-SAT 句になります。 

### 4. 含意グラフを構築する

 各句 (A または B) に含意を追加します。 

A が false の場合、B は true でなければなりません。 

B が false の場合、A は true でなければなりません。 

これは、含意グラフ内の有向エッジとしてエンコードされます。 

### 5. 強結合成分で解く

 含意グラフで SCC 分解を実行します。 変数とその否定が同じコンポーネントになる場合、システムは一貫性がなく、代入は存在しません。 

それ以外の場合は、有効な割り当てが存在します。 

### なぜ効果があるのか

 このシステムは、すべての交差セルが、少なくとも 1 つのドックがそのセルを空のセルとして選択することによって「保護」されなければならないという条件を正確に捕捉します。 各ドックをバイナリ エンドポイントの選択肢としてエンコードすると、インタラクションが交差点に局所化されているグリッドでの実行可能性を弱めることなく、内部の除去をシミュレートできるため、すべての意味のある柔軟性が維持されます。 含意グラフにより、すべてのペアごとの制約がグローバルに適用されることが保証されるため、SCC の競合は、必要な選択における避けられない矛盾に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

# We will build a 2-SAT over variables:
# each dock i has two states: i*2 (false), i*2+1 (true)

class TwoSAT:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(2*n)]
        self.gr = [[] for _ in range(2*n)]

    def add_imp(self, a, b):
        self.g[a].append(b)
        self.gr[b].append(a)

    def add_or(self, a, b):
        # a OR b  =>  (not a -> b) and (not b -> a)
        self.add_imp(a ^ 1, b)
        self.add_imp(b ^ 1, a)

    def satisfiable(self):
        n = 2*self.n
        visited = [False]*n
        order = []

        def dfs(v):
            visited[v] = True
            for to in self.g[v]:
                if not visited[to]:
                    dfs(to)
            order.append(v)

        for i in range(n):
            if not visited[i]:
                dfs(i)

        comp = [-1]*n

        def dfs2(v, c):
            comp[v] = c
            for to in self.gr[v]:
                if comp[to] == -1:
                    dfs2(to, c)

        c = 0
        for v in reversed(order):
            if comp[v] == -1:
                dfs2(v, c)
                c += 1

        for i in range(self.n):
            if comp[2*i] == comp[2*i+1]:
                return False
        return True

def solve():
    H, W, N = map(int, input().split())

    grid = [[[] for _ in range(W+1)] for _ in range(H+1)]

    docks = []

    for i in range(N):
        x, y, k, d = input().split()
        x = int(x)
        y = int(y)
        k = int(k)

        cells = []

        if d == 'R':
            for j in range(k):
                cells.append((x, y + j))
        elif d == 'L':
            for j in range(k):
                cells.append((x, y - j))
        elif d == 'D':
            for j in range(k):
                cells.append((x + j, y))
        else:  # U
            for j in range(k):
                cells.append((x - j, y))

        docks.append((cells[0], cells[-1]))

        for (a, b) in cells:
            grid[a][b].append(i)

    ts = TwoSAT(N)

    # each dock has two endpoints; variable i:
    # false = choose first endpoint, true = choose second endpoint

    pos = {}
    for i, (c1, c2) in enumerate(docks):
        pos[(i, c1)] = 0
        pos[(i, c2)] = 1

    for i in range(1, H+1):
        for j in range(1, W+1):
            if len(grid[i][j]) > 1:
                lst = grid[i][j]
                # enforce pairwise OR constraints
                for a in range(len(lst)):
                    for b in range(a+1, len(lst)):
                        u = lst[a]
                        v = lst[b]
                        # (u chooses this cell) OR (v chooses this cell)
                        # map to literals
                        # if cell is endpoint, use correct literal
                        if (u, (i, j)) not in pos or (v, (i, j)) not in pos:
                            continue
                        lu = pos[(u, (i, j))]
                        lv = pos[(v, (i, j))]

                        # u_lu OR v_lv
                        ts.add_or(u*2 + lu, v*2 + lv)

    print("Yes" if ts.satisfiable() else "No")

if __name__ == "__main__":
    solve()
```この解決策は、各ドックに属するすべてのグリッド セルを列挙することから始まり、共有セルによる交差を検出できるようになります。 各ドックは 2 つのエンドポイントに縮小され、それらのエンドポイントは 2 つのみの可能な選択肢を定義します。 

次に、各変数がどのエンドポイントが削除されるかを表す 2-SAT インスタンスを構築します。 複数のドックに属するすべてのグリッド セルには、対応するエンドポイントの選択肢の間に OR 制約が導入されます。 これらはグラフの意味に変換されます。 

最後に、SCC 分解は、変数がその否定と矛盾するかどうかをチェックします。 そのような競合が存在しない場合、エンドポイント削除の一貫した割り当てが存在します。 

実装の微妙な詳細は、非エンドポイント交差のフィルタリングです。 両方のドックのエンドポイントに対応する交差部分のみが直接エンコードに有効です。 そうしないと、縮小された変数空間で表現できません。

 ## 特殊なケース

 2 つのドックが複数のセルに沿って重なっている場合、重大なエッジ ケースが発生します。 その状況では、複数の制約が生成されますが、それらはすべて、エンドポイントの選択に関して一貫した OR 関係に崩壊します。 2-SAT 定式化では、重複する各セルが同じ論理構造を強化する含意を生み出すため、これを自然に処理します。 

もう 1 つのエッジ ケースは、ドックが 1 つのエンドポイントで他の多くのドックと交差する場合です。 その場合、すべての制約はそのエンドポイント変数に依存し、SCC ソルバーは含意グラフを通じて強制割り当てを伝播し、一貫性がローカルではなくグローバルにチェックされることを保証します。
