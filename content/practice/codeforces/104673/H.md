 ## 解決策
 ## 問題の理解

 私たちは方向指示のない道路でつながった村のグラフに取り組んでいます。 私たちが制御する 1 台のロボットは、村 S から出発し、目標の村 F に到達したいと考えています。ロボットは夜間にのみ移動し、毎晩、隣の村まで 1 本の道路を横切るか、その場に留まります。 

2 番目のロボットは既知の村 T からスタートします。私たちはそれを制御できません。 毎晩、隣の村まで一本の道を正確に移動しなければなりません。 時間の経過とともに、その位置はまったく予測できなくなりますが、経過した夜の数に等しい長さの有効な散歩を常にたどる点が異なります。 

重要な制約は、両方のロボットが同じ日に同じ村にいた場合、システムが失敗するということです。 これは、毎晩の移動の後、両方のロボットが日中に「休んでいる」ときは、決して同じノードを占有してはいけないことを意味します。 夜間に反対方向の端を横切るときに会うことは無害です。 同じタイムステップで同じ頂点に存在することだけが重要です。 

2 番目のロボットがどのように動いても、この衝突が決して起こらないことを保証しながら、ロボットが F に達するまでに必要な最小の夜数を見つける必要があります。 そのような安全な戦略が存在しない場合、答えは不可能です。 

制約は大きく、最大 100,000 個のノードと 200,000 個のエッジがあります。 これにより、すべてのパスを探索したり、両方のロボットを指数関数的に共同でシミュレートしたりするアプローチは除外されます。 解は、グラフのサイズが線形またはほぼ線形である必要があり、通常は O(N + M) です。 

微妙な難点は、2 番目のロボットが敵対的であることです。 たとえ特定のパスを選択しなかったとしても、常に衝突を可能にしようとしていると想定する必要があります。 つまり、各タイム ステップで占有する可能性のあるすべての頂点を考慮する必要があります。 

単純な間違いは、時間の経過とともに増加する T からの最短経路距離を回避するだけでよいと考えることです。 たとえば、サイクル内で 2 番目のロボットは頂点への到達が遅れたり、ノードを再訪問したりする可能性があります。これは、単一の最短パス レイヤーが示唆するよりも多くの場所にロボットが出現する可能性があることを意味します。 

T の BFS 層を回避すれば十分だと考えると、別の障害モードが現れます。 T が 1 つの頂点である三角グラフを考えてみましょう。 2 つのステップの後、敵は最短経路と同じパリティの任意の頂点に存在する可能性があります。これは、危険な領域が時間とともに交互に現れ、単純な「成長するボール」の意味での単調ではないことを意味します。 

## アプローチ

 直接総当り戦略では、両方のロボットの考えられるすべての状態を時間の経過とともにシミュレートします。 各タイム ステップで、敵のあらゆる可能な位置とロボットの到達可能なすべての位置を追跡します。 状態空間はノードと時間の積となり、遷移は両側で大きく分岐します。 時間を無視しても、位置のペアはすでに O(N²) の可能性を与えており、時間を追加すると無限になります。 これはすぐに実行不可能になります。 

重要な観察は、実際には 2 番目のロボットの正確な位置は必要ないということです。 我々が知る必要があるのは、それが特定の時点で特定の頂点に存在する可能性があるかどうかだけです。 

これにより、問題は敵側の到達可能性の問題に帰着します。 T から、最短距離 d(v) を計算します。 頂点が距離 d(v) にある場合、敵対者は、v で終わる正確に t ステップのウォークを完了できれば、時刻 t に v に到達できます。エッジを再訪問できるため、唯一の制限はパリティです。d(v) ステップで v に到達できると、d(v) + 2、d(v) + 4 などでも到達できます。 

したがって、各頂点は特定の時点で安全でなくなります。つまり、t ≥ d(v) であり、t が d(v) と同じパリティを持つすべての t です。 これにより、きれいな時間依存の禁止セットが得られます。

ここで、私たちのロボットは最短経路検索を実行しますが、状態の一部として時間を伴います。 時刻 t で頂点 v にいることは、時刻 t で v が安全でない場合にのみ有効です。 時間は一晩あたりちょうど 1 ずつ増加するため、BFS オーバー (ノード、時間パリティ) を実行します。 安全性は、t が d(v) に対するパリティ条件に一致するかどうか、および t がしきい値を超えるかどうかのみに依存するため、パリティは十分です。 

これにより、問題はノードごとに 2 つの層を備えた層状グラフ検索に変換され、偶数時間と奇数時間を追跡します。

 | --- | --- | --- | --- |

 ## アルゴリズムのチュートリアル

 1. T から BFS を実行して、すべての頂点の最短距離 d(v) を計算します。 これは、敵対者が最初に各頂点に到達できる最小時間を表します。 
2. 各頂点 v について、初めて安全でなくなる時間を決定します。 d(v) が偶数の場合、d(v)、d(v)+2、d(v)+4 などの時点では安全ではありません。 d(v) が奇数の場合、奇数回でも同じパターンが当てはまります。 この周期構造が、敵から必要な唯一の情報です。 
3. 状態を (u, p) として定義します。ここで、u は頂点、p はそこに到着するときの時間のパリティです。 時間は手ごとに 1 ずつ確実に増加するため、パリティは十分です。 
4. BFS を (S, 0) から初期化します。 初期時間はゼロです。 
5. 状態 (u, t) から、隣接する v へのすべての移動と、u に留まるオプションを試します。 移動するたびに時間が t+1 に増加します。 
6. (v, t+1) への移動を受け入れる前に、時刻 t+1 で v が安全かどうかを確認します。 これは、t+1 < d(v)、または (t+1 - d(v)) が奇数であることを意味します。 
7. 状態が安全で、以前に訪れたことがない場合は、その状態を BFS キューにプッシュします。 
8. パリティ状態で最初に F に達すると、最小泊数が得られます。 

正確さは、BFS が時間の増加順に状態を探索するという事実に依存します。 ある状態 (v, p) に到達すると、後で同じ (v, p) に到達しても時間が増加するだけであり、安全性の状態を改善することはできません。これは、安全でない状態は固定パリティ クラス内の時間に単調に依存するためです。 

## なぜ機能するのか

 敵対者の移動制約は、頂点ごとに決定論的に到達可能な時間のセットに減ります。 正確な位置を追跡する代わりに、一定の時間内に頂点が恒久的に危険になる時期を分類します。 私たちの BFS は、これらの禁止された時間と頂点のペアを回避します。 ロボットのすべての有効な戦略はこの時間拡張グラフ内のパスに対応しており、BFS はそのような最短のパスを見つけるため、F への最初の到着はすべての安全な戦略の中で最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N, M, F, T, S = map(int, input().split())
    g = [[] for _ in range(N)]
    for _ in range(M):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    INF = 10**18
    dist = [INF] * N
    q = deque([T])
    dist[T] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == INF:
                dist[v] = dist[u] + 1
                q.append(v)

    def unsafe(v, t):
        d = dist[v]
        if d == INF:
            return False
        if t < d:
            return False
        return (t - d) % 2 == 0

    dq = deque()
    dq.append((S, 0))
    visited = [[False, False] for _ in range(N)]
    visited[S][0] = True

    t = 0
    while dq:
        size = len(dq)
        for _ in range(size):
            u, p = dq.popleft()

            if u == F:
                print(t)
                return

            # stay
            nt = t + 1
            if not unsafe(u, nt):
                if not visited[u][nt % 2]:
                    visited[u][nt % 2] = True
                    dq.append((u, nt % 2))

            # move
            for v in g[u]:
                if not unsafe(v, nt):
                    if not visited[v][nt % 2]:
                        visited[v][nt % 2] = True
                        dq.append((v, nt % 2))

        t += 1

    print("death")

if __name__ == "__main__":
    solve()
```このソリューションは、敵対者の動作を前処理 BFS に分離し、メイン タスクを時間依存の有効性を持つ制約された最短パスとして扱います。 実装における唯一の微妙な点は、安全性チェックでは依然としてフルタイム値が使用されている一方で、訪問が絶対時間ではなく頂点と時間パリティによって追跡されていることです。 この組み合わせにより、状態空間を爆発させることなく正確さが可能になります。

 ### サンプル 1

 グラフは 0 から 4 までの単純な線です。敵は 1 から始まります。

 敵は 1 から外側に拡大しますが、ライン構造により安全な通路が可能になります。 BFS は、単調な進行が安全であることを確認します。 

### サンプル 2

 2 番目のグラフでは、敵の開始位置はより密な構造の中央に位置しています。 

| ステップ | 安全な動き | 安全でない競合 | 結果 |
 | --- | --- | --- | --- |
 | 0 | 4時からスタート | なし | わかりました |
 | 1 | 複数のオプション | ノード 3 は早期に安全でなくなります | 制限付き |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | T からの 1 つの BFS と時間パリティ状態にわたる 1 つの BFS、各エッジは定数回処理されます。 
| スペース | O(N + M) | グラフストレージと訪問/パリティ追跡 |

 この制約により線形グラフの走査が可能になるため、200,000 のエッジであっても制限内に快適に収まります。

        return (t - d) % 2 == 0

    t = 0

    while dq:
        for _ in range(len(dq)):
            u, p = dq.popleft()

    return "death"

 ## 特殊なケース

 1 つのエッジ ケースは、宛先がすでに開始ノードである場合に発生します。 このアルゴリズムは BFS を (S, 0) で初期化し、S が F に等しいため、遷移なしで時間 0 で即座に終了します。これは、移動が必要ないという要件と一致します。 

別のケースは、攻撃者がグラフの一部に対して切断されたコンポーネントから開始した場合に発生します。 その状況では、多くの頂点は T から無限の距離にあるため、決して安全ではありません。 BFS はそれらを常に安全なものとして正しく扱うため、唯一の制約は S から F への構造的な到達可能性になります。 

より微妙なケースが周期グラフで発生し、パリティの変更によって敵が以前は到達できなかった状態に再び入ることができます。 距離ベースの安全でない関数は、常にパリティに一致する安全ウィンドウを繰り返すことを許可することでこの問題をすでに捉えており、BFS が単一のタイム ステップ後に安全が永続的になると誤って想定することがなくなります。
