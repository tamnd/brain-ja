 ## 解決策
 ## 問題の理解

 互いに素な「雲」のセットが与えられます。各雲は、その凸包が単純な凸多角形を形成する点のセットです。 これらのポリゴンは内部で重なり合わず、空のスペースでのみ接触し、互いに交差することはありません。 

針は点 S から始まり、点 T に到達する必要があります。動きは平面内で行われます。 重要な制限は、針が多角形の雲の内部を通過できないことです。 ただし、すべての雲の外側を自由に移動でき、また、制限なく雲の境界に沿って移動することもできます。 

タスクは、これらのルールに基づいて S から T までの可能な最短のパス長を計算することです。 

幾何学的には、これは、凸包の境界のみが問題となり、障害物のエッジに沿って歩くことが許可される、多角形の障害物を含む平面内の最短経路問題です。 

この制約は、すべてのクラウドにわたる入力ポイントの合計数が最大 500 であり、存在するクラウドの数が最大 200 であることを意味します。 これは、頂点の数が 2 次またはそれよりわずかに劣るアルゴリズムを使用できるが、最悪の場合、3 次のアルゴリズムは遅すぎることを強く示唆しています。 ここでの一般的なしきい値は、約数十万の幾何学的チェックは問題ありませんが、数百億に近いものは問題ありません。 

計算上の主な困難は、関連する点間のどの直線セグメントが有効であるか、つまり凸多角形の内部を通過しない直線セグメントを判断することです。 

素朴な試みとして、平面全体をグリッドとして扱ったり、連続的な動きをシミュレートしようとしたりする可能性がありますが、ジオメトリは連続的であり、障害物はグリッドに並んでいない多角形であるため、すぐに失敗します。 

さらに微妙な落とし穴は、入力点のみのグラフとして扱うことです。 元の雲点間の移動のみを許可すると、最短経路には任意の指定点ではなく凸包頂点での回転が必要になる可能性があることを見逃します。 

ポリゴンのエッジをかすめることを除いて、S と T がお互いを「見る」ことができる場合、別の微妙なケースが発生します。 境界に触れることを無効として扱う単純なセグメント交差テストでは、ポリゴンの境界に沿った有効な最短パスが誤ってブロックされてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、エッジに沿った任意のブレークポイントを効果的に考慮して、S、T、およびすべてのポリゴン境界上のすべての点の間のすべての可能なパスを離散化しようとします。 連続空間では可能なパス ブレークポイントの数が無限にあるため、これはすぐに手に負えなくなります。 

より構造化されたブルート フォース グラフのアプローチは、すべての元の点と S および T をノードとみなして、セグメントがポリゴン内部と交差しない場合は、ユークリッド距離で重み付けされたエッジでノードのすべてのペアを接続することです。 各ペアについて、すべてのポリゴンとそのすべてのエッジに対してテストします。 頂点が最大 500 個ある場合、これにより約 250,000 ペアが得られ、すべてのエッジに対して単純に実行した場合、各妥当性チェックに最大 O(500) のコストがかかる可能性があり、その結果、およそ 10^8 の幾何学的テストが必要になります。 これは境界線ですが、慎重に実装すればまだ許容可能です。 

ただし、ポリゴン境界のトラバースが正しくモデル化されていることを確認しない限り、このアプローチはまだ不完全です。 重要な点は、凸多角形内で、その境界上にいる場合、2 つの頂点間の多角形に沿った最短パスは、内部弦を通らず、常に多角形のエッジに沿っているため、有効な接続として多角形のエッジを明示的に追加する必要があることです。 

重要な構造的洞察は、凸状の障害物がある平面内の S と T の間の最適なパスは常に、障害物の頂点、S と T の間の直線の可視セグメントと、ポリゴンのエッジに沿った移動で構成されるということです。 これにより、問題は可視性グラフ上の最短経路に帰着します。

したがって、ノードが S、T、およびすべての凸包頂点であるグラフを構築します。 各凸包の連続する頂点の間にエッジを追加します (境界に沿って歩くことが許可されているため)。 また、2 つのノードを接続するセグメントが凸包の内部を通過しない場合は、それらの間にエッジを追加します。 このグラフに対してダイクストラを実行すると、答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 構造を使用しないブルート フォース セグメント チェック | O(V^2 * V) | O(V^2) | 遅すぎる/危険 |
 | 可視性グラフ + ダイクストラ | O(V^2 * N + V^2 log V) | O(V^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各雲を凸包に縮小します。 これが必要なのは、移動には境界のみが重要であり、内部の点は可視性に影響を与えないためです。 

次に、すべてのハル頂点と S および T から構成されるノードのグローバル セットを構築します。 

次に、境界越えのための隣接情報を構築します。 各凸包について、ユークリッド距離に等しいエッジの重みを使用して、連続する頂点を両方向に接続します。 これは、境界に沿った移動が常に許可され、実際の幾何学的距離が必要になるという事実をエンコードしています。 

次に、ノードのすべてのペア間の可視性エッジを計算します。 

1. ノード A と B の各ペアについて、セグメント AB が有効かどうかを確認します。 

妥当性とは、AB が凸包の内部を通過しないことを意味します。 エッジに触れるだけ、または頂点を通過するだけの場合でも、許可されます。 
2. 1 つの凸包に対する妥当性をテストするために、多角形の各エッジとのセグメントの交差をチェックします。 AB が交差を示す方法でエッジと交差する場合、それは拒否されます。 また、A と B が両方とも厳密に同じポリゴンの内側にないことも確認する必要がありますが、S と T は外側に保証されており、ハルの頂点が境界上にあるため、これは起こり得ません。 
3. AB が有効な場合、ユークリッド距離を使用して A と B の間に無向エッジを追加します。 

グラフを作成した後、S から開始してダイクストラを実行し、T までの最短距離を計算します。 

### なぜ効果があるのか

 この設定の最短パスは、ポリゴンの頂点、S、または T でのみ曲がるパスに変換できます。パスのセグメントが障害物に触れずに自由空間を通過する場合は、直線にすることができます。 凸多角形に接触した場合、内部を通るショートカットは禁止されるため、最適なパスは頂点の周りを「包み込む」必要があり、これは船体の頂点との接触を意味します。 この標準の凸状障害物プロパティにより、検索を可視性グラフに制限しても最適なソリューションが破棄されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math
import heapq

EPS = 1e-9

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def orient(ax, ay, bx, by, cx, cy):
    return cross(bx - ax, by - ay, cx - ax, cy - ay)

def on_segment(ax, ay, bx, by, cx, cy):
    return min(ax, bx) - EPS <= cx <= max(ax, bx) + EPS and \
           min(ay, by) - EPS <= cy <= max(ay, by) + EPS and \
           abs(orient(ax, ay, bx, by, cx, cy)) < 1e-9

def seg_intersect(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    o1 = orient(ax, ay, bx, by, cx, cy)
    o2 = orient(ax, ay, bx, by, dx, dy)
    o3 = orient(cx, cy, dx, dy, ax, ay)
    o4 = orient(cx, cy, dx, dy, bx, by)

    if o1 * o2 < -EPS and o3 * o4 < -EPS:
        return True
    return False

def dist(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    def build_half(ps):
        res = []
        for p in ps:
            while len(res) >= 2 and orient(res[-2][0], res[-2][1],
                                            res[-1][0], res[-1][1],
                                            p[0], p[1]) <= 0:
                res.pop()
            res.append(p)
        return res

    lower = build_half(points)
    upper = build_half(points[::-1])
    return lower[:-1] + upper[:-1]

def segment_valid(a, b, hulls):
    for hull in hulls:
        m = len(hull)
        for i in range(m):
            c = hull[i]
            d = hull[(i + 1) % m]
            if seg_intersect(a, b, c, d):
                return False
    return True

def dijkstra(adj, s, t):
    n = len(adj)
    distv = [float('inf')] * n
    distv[s] = 0.0
    pq = [(0.0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != distv[u]:
            continue
        if u == t:
            return d
        for v, w in adj[u]:
            nd = d + w
            if nd < distv[v]:
                distv[v] = nd
                heapq.heappush(pq, (nd, v))
    return distv[t]

def solve():
    N, sx, sy, tx, ty = map(int, input().split())
    S = (sx, sy)
    T = (tx, ty)

    hulls = []
    nodes = [S, T]

    for _ in range(N):
        data = list(map(int, input().split()))
        c = data[0]
        pts = []
        idx = 1
        for _ in range(c):
            x = data[idx]
            y = data[idx + 1]
            idx += 2
            pts.append((x, y))
        hull = convex_hull(pts)
        hulls.append(hull)
        nodes.extend(hull)

    n = len(nodes)
    adj = [[] for _ in range(n)]

    # boundary edges
    offset = 2
    for hull in hulls:
        m = len(hull)
        idxs = list(range(offset, offset + m))
        for i in range(m):
            u = idxs[i]
            v = idxs[(i + 1) % m]
            w = dist(nodes[u], nodes[v])
            adj[u].append((v, w))
            adj[v].append((u, w))
        offset += m

    # visibility edges
    for i in range(n):
        for j in range(i + 1, n):
            if segment_valid(nodes[i], nodes[j], hulls):
                w = dist(nodes[i], nodes[j])
                adj[i].append((j, w))
                adj[j].append((i, w))

    s_idx = 0
    t_idx = 1
    print(f"{dijkstra(adj, s_idx, t_idx):.10f}")

if __name__ == "__main__":
    solve()
```コードはまず各クラウドの凸包を構築し、関連するすべての頂点をグラフ ノードの単一のリストに平坦化します。 次に、2 種類のエッジを構築します。1 つは連続したハル頂点間の保証された境界エッジ、もう 1 つは障害物の内部に違反しないノードのペア間のオプションの可視エッジです。 

セグメント検証は幾何学的コアです。 これにより、セグメントが凸多角形のエッジと交差しないことが保証されます。凸多角形の境界を越えるということはその内部に入ることを意味するため、これで十分です。 

次に、ダイクストラは、この幾何学的グラフ上の最短経路を計算します。 

## 実用的な例

 単一の三角形の雲と反対側に S と T がある最小限のシナリオを考えてみましょう。 このアルゴリズムは三角形の境界サイクルを構築し、S と T がお互いを直接認識できるかどうかをチェックします。 セグメントが三角形を横切る場合、視界が遮られ、パスは三角形の 2 つのエッジに沿ってルートする必要があり、ダイクストラはそれを自然に発見します。 

2 番目のシナリオは、両方の外側に S があり、反対側に T がある 2 つの互いに素なポリゴンです。 このアルゴリズムは、S と各ポリゴンの最も外側の可視頂点の間に可視エッジを追加し、境界に沿ったトラバースを可能にします。 通常、最短パスは、接点までの 1 つの直線セグメント、境界ウォーク、次に T への別の直線セグメントで構成されます。グラフ表現は、直線と境界の動きの両方を均一に捕捉します。

 ## 特殊なケース

 ポリゴン エッジに接触する場合を除いて S と T が直接表示される場合、交差は境界接触ではなく真の交差としてのみ考慮されるため、アルゴリズムはセグメントを許可します。 これにより、有効な直線運動が誤って禁止されるのを防ぎます。 

最適なパスがポリゴンの境界に沿って正確に長く伸びる場合、グラフ内の明示的な境界エッジにより、ダイクストラは内部を強制的に迂回するのではなく、この動きを一連のエッジトラバースとして表現できるようになります。 

複数の船体がほぼ整列している場合、各セグメントがすべてのポリゴンに対して個別に検証されるため、可視性チェックは正確なままであり、縮退した幾何学的構成であっても隠れた内部貫通が発生しないことが保証されます。
