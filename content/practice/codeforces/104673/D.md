 ## 解決策
 ## 問題の理解

 という文字列で表されるジャーナルのスタックが与えられます。`+`そして`-`, ここで、各記号はジャーナルの表紙の向きを表します。 文字列が指定されると、スタックは上から下に読み取られます。 目標は、隣接する 2 つのジャーナルが同じ符号を持たないようにスタックを再配置することです。つまり、最終的な文字列は厳密に交互に配置される必要があります。`+`そして`-`。 

許可された操作は構造化されていますが、効果的に強力な変換を実現します。 スタックの最上位から一部のプレフィックスを削除し、残ったものから連続したブロックを取り出し、そのブロックを反転して、最後に削除したプレフィックスを最上位に戻すことができます。 重要な点は、これによりスタックの連続した部分文字列を 1 回の操作で反転できるということです。 

反転することが唯一の実際の変更であるため、問題は変換タスクになります。つまり、部分文字列の反転の最小数を使用して、最初のバイナリ文字列を代替ターゲット文字列に変換します。 

入力長は最大です$2 \cdot 10^5$これにより、すべての部分文字列を試行したり、二次時間で各操作を貪欲にシミュレートしたりするソリューションは即座に除外されます。 線形または線形に近い戦略が必要です。 

微妙な点は、有効なターゲット構成が 2 つだけ存在することです。`+`そして、から始まるもの`-`。 どちらも有効な交互パターンなので、必要な操作が少ない方を選択する必要があります。 

重要なエッジ ケースは、小さな文字列とすでに正しい文字列です。 たとえば、入力`"+-"`すでに条件を満たしているため、答えはゼロになります。 のような文字列の場合`"++--"`、単純なアプローチでは、たとえ中間セグメントの 1 回の反転によって結果が生成されても、局所的な競合を貪欲に修正し、操作を過剰にカウントしようとする可能性があります。`"+-+-"`。 

## アプローチ

 ブルート フォース ビューでは、各状態を文字列として扱い、可能なすべての部分文字列の反転を試み、構成に対して BFS を実行します。 それぞれの州には、$O(n^2)$到達可能な文字列の数が爆発的に増加するため、浅い深さの探索さえ不可能になります。 最適なパスに限定したとしても、状態空間は次のようになります。$2^{2K}$、まったく手に負えません。 

重要な洞察は、任意の構成に到達しようとしているのではなく、2 つの固定された交互パターンのいずれかに到達しようとしているということです。 これにより、グローバル構造について推論する必要がなくなります。 代わりに、現在の文字列をターゲットと比較し、不一致の位置に焦点を当てます。 

リバーサルのエンドポイントを慎重に選択すれば、1 回の移動で 2 つの境界の不一致を修正できます。 直観的に、ターゲットに対して 2 つの位置が間違っている場合は、それらをペアにして、1 回の反転で両方を修正できます。 これにより、問題は不一致をカウントし、それらを最適にペアリングすることに軽減されます。 各操作で最大 2 つの不一致を排除でき、慎重に選択した反転により、以前に固定された構造を壊すことなく常にこのペアリングを実現できます。 

これは単純な削減につながります。2 つの交互のターゲットのそれぞれに関して不一致を計算し、より良い結果を取得します。 答えは、不一致の数を 2 で割って切り上げたものになります。

 ## アルゴリズムのチュートリアル

 考えられる交互のターゲットの両方を評価し、それぞれに一致しない位置がいくつあるかを数えることで、問題を解決します。 

1. 次で始まる仮想のターゲット文字列を構築します。`+`、全長にわたって交互に。 

これは、1 つの有効な最終構成を表します。 
2. 入力文字列とこのターゲットを比較し、異なるインデックスの数を数えます。 

それぞれの異なる位置は、目標に対して現在間違った方向にあるジャーナルを表します。 
3. このターゲットに必要な操作の数を次のように計算します。`(mismatch_count + 1) // 2`。 

これは、正しくペアになっている場合、1 回の反転で 2 つの不一致の位置を修正できるという事実から来ています。 
4. ターゲットに対して同じプロセスを繰り返します。`-`。 
5. 2 つの計算結果の間の最小値を返します。 

### なぜ効果があるのか

 重要な特性は、不一致の位置が反転によるペアリングを除いて独立していることです。 単一の反転では、内部構造をターゲット パターンと一致させたまま、エンドポイントで意味のある修正を「ペアにする」ことのみが可能です。 すべての操作で修正できる不一致は最大 2 つであり、単一の不一致には少なくとも 1 つの操作が必要であるため、最適な戦略は不一致をできるだけ効率的にペアリングすることと同じです。 両方のターゲット パターンを試すことで、間違った開始パリティに偏ることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    def cost(start_char):
        mismatches = 0
        cur = start_char
        for i in range(n):
            if s[i] != cur:
                mismatches += 1
            cur = '+' if cur == '-' else '-'
        return (mismatches + 1) // 2

    ans1 = cost('+')
    ans2 = cost('-')
    print(min(ans1, ans2))

if __name__ == "__main__":
    solve()
```この実装では、2 つの候補となる交互パターンを直接エンコードします。 ヘルパー関数は文字列を一度調べて、各位置で期待される文字を維持します。 不一致数は 1 回のパスで累積され、解が線形に保たれます。 

表現`(mismatches + 1) // 2`ペアリング引数をキャプチャします。すべての操作で 2 つの間違った位置を解決できますが、一方がペアになっていないままの場合は、追加の操作が必要になります。 

## 実用的な例

 次のような単純な入力を考えてみましょう`"+-+-"`。 同じパターンに対する不一致数はゼロであるため、操作は必要ありません。 

より具体的なケースとして、次のようにします。`"++--"`。 

### で始まるターゲット`+`| 私 | s[i] | ターゲット | 不一致 |
 | --- | --- | --- | --- |
 | 0 | + | + | 0 |
 | 1 | + | - | 1 |
 | 2 | - | + | 1 |
 | 3 | - | - | 0 |

 不一致数は 2 なので、必要な操作は 1 です。 

### で始まるターゲット`-`| 私 | s[i] | ターゲット | 不一致 |
 | --- | --- | --- | --- |
 | 0 | + | - | 1 |
 | 1 | + | + | 0 |
 | 2 | - | - | 0 |
 | 3 | - | + | 1 |

 不一致数は再び 2 になり、操作は 1 になります。 

これは対称性を示しています。両方のターゲット方向が同等に有効であり、アルゴリズムはどちらかを正しく選択します。

import sys, io

 ## 特殊なケース

 次のような単一文字列の場合`"+"`、両方のターゲット パターンは交互ルールの切り捨てまで有効であり、不一致数はゼロであるため、アルゴリズムはすぐにゼロを返します。 

次のようなすでに交互になっている文字列の場合`"+-+-+-"`の場合、ターゲットの 1 つに対して不一致数が 0 であるため、操作は必要なく、アルゴリズムによって自然にそのターゲットが選択されます。 

次のような均一な文字列の場合`"++++"`、両方のターゲットで 2 文字ごとに 2 つの不一致が生成され、合計 2 つの不一致が発生し、したがって 1 つの操作が発生します。これは、中央のセグメントを反転して交互を作成することに相当します。
