 ## 解決策
 ## 問題の理解

 この問題で説明されている構造は、セルの三角形グリッドであり、各行は前の行よりちょうど 1 セル分だけ長くなります。 最初の行には 1 つのセルが含まれており、後続の行はすべて対称に広がります。 各行の境界にあるセルは、一番上のセルと合わせて、すべて値 1 が割り当てられます。他のすべてのセルには、直前の行でそのセルのすぐ上にある、それに最も近い 2 つのセルの合計が割り当てられます。 

この構造はパスカルの三角形とまったく同じ反復です。 0 から始まる行にインデックスを付ける場合、行 r および位置 k の値が二項係数 C(r, k) になります。 境界値は C(r, 0) と C(r, r) で、両方とも 1 に等しく、内部値は C(r, k) = C(r-1, k-1) + C(r-1, k) に従います。 

各クエリでは数値 N が与えられ、この無限のパスカルのような三角形内のセルの値であることが保証されます。 タスクは、N に等しい値が出現する最小の行インデックスを決定することです。 

この制約では、最大 100,000 個のクエリと最大 10^9 の値が許可されます。 これは、三角形をシミュレートしたり、クエリごとに大きな深さまで独立して行全体を計算したりすることはできないことを直ちに示唆しています。 行を 1 つずつ構築する単純なアプローチでは、行ごとに O(r^2) 値を生成する必要があります。また、行は直線的に増加するため、適度な r に達するだけでもすでに時間制限を超えてしまいます。 

さらに微妙な点は、値が非常に急速に増加することです。 行の中央の二項係数は、r とともにほぼ指数関数的に増加し、非常に早い段階で 10^9 を超えます。 これは、一定の小さいサイズを超える行はこの問題とは無関係であることを意味します。 

N が大きいため、潜在的に r = 10^9 まで検索する必要があると考えるのは単純な間違いです。 行のインデックスと値が一致していないため、これは不正確です。 たとえば、N = 10^9 の場合、10^9 に近い行は必要ありません。 実際、計算の限界内でそのような行の近くにはそれほど大きな二項係数は存在せず、行の最大係数が N を超えるまで小さな r をチェックするだけで済みます。 

もう 1 つの微妙なケースは、N = 1 です。この値はすべての行に表示されますが、最初の行にすでにこの値が含まれているため、答えは 0 でなければなりません。 先頭の行を正しく考慮せずに最初の出現を検索するアプローチでは、より大きなインデックスが返される可能性があります。 

## アプローチ

 強引な解釈では、パスカルの三角形を行ごとに構築します。 各行について、前の行からの反復を使用してすべての二項係数を計算し、N に等しいエントリがあるかどうかをスキャンします。見つかった場合は、その行インデックスを返します。 

この構造は三角形の定義と正確に一致するため、これは正しいです。 ただし、コストは生成される値の数によって決まります。 行 r には r + 1 要素が含まれており、r までのすべての行を構築するには、以前のすべてのサイズを合計する必要があり、およそ O(r^2) の演算が必要になります。 行ごとに早めに停止しようとしても、クエリ全体で繰り返し再計算が行われることになり、100,000 クエリでは実行不可能になります。 

重要な点は、すべての行を作成する必要はないということです。 二項係数は非常に速く増大するため、固定 N の場合、N を含む行は小さくなければなりません。 各行 r の最大値は C(r, Floor(r/2)) です。 これは急速に増加し、r が 30 台前半になると 10^9 を超えます。 これにより、すべてのクエリの検索スペースが制限されます。 

完全な行を構築する代わりに、0 から開始して行 r を反復し、値が N を超えるまで各行内で二項係数を段階的に計算できます。行 r で N が見つかった場合、それが答えになります。 r はグローバルに小さいため、多くのクエリに対しても効率的になります。 

強引な解法から最適な解法への移行は、構造がパスカルの三角形であり、その成長によって探索に必要な深さが制限されることを認識することから始まります。

 | --- | --- | --- | --- |
 | ブルート フォース (フルトライアングル) | クエリあたり O(R^2) | O(R) | 遅すぎる |
 | 最適 (境界行検索) | O(R^2 + Q・R) ただし、R ≤ ~35 | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 最大 10^9 の値を含むことができるのは少数の行のみであるという事実を利用します。 

1. グローバルには何も事前計算しませんが、0 から始まる行インデックス r ごとに、二項係数の実行乗算式を使用して行 r の値を生成します。 各行は値 1 から始まります。 
2. 固定行 r の場合、恒等式 C(r, k+1) = C(r, k) * (r - k) / (k + 1) を使用して各エントリを繰り返し計算します。 これにより、階乗の再計算が回避され、整数演算における値が正確に保たれます。 
3. 行 r のエントリを生成しているときに、N に等しい値があるかどうかを確認します。N に等しい場合は、そのクエリの答えとして r をすぐに返します。 
4. 一致するものが見つからない場合は、次の行 r + 1 に進みます。 
5. 行の最大値が 10^9 を超え、すべての候補行を通過したら停止します。これは実際には非常に早い段階 (r ≈ 35 付近) で起こります。 

正確さの背後にある理由は、構造内のすべてのセル値が二項係数であり、すべての二項係数が対応する行に正確に現れるということです。 したがって、N が現れる最初の行は、正確に、ある k に対して C(r, k) = N となる最小の r です。 行を昇順に列挙し、各行を完全にスキャンするため、最初の一致は最小限であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def row_has_value(r, target):
    val = 1
    if val == target:
        return True
    for k in range(0, r):
        val = val * (r - k) // (k + 1)
        if val == target:
            return True
        if val > target:
            break
    return False

def solve():
    q = int(input())
    queries = [int(input()) for _ in range(q)]

    max_n = max(queries)

    # rows beyond this are unnecessary; C(r, r//2) already exceeds 1e9
    # around r = 34..35
    limit = 60

    # precompute answers for all possible N by scanning rows
    # but since Q is large and N varies, we just answer per query
    for n in queries:
        if n == 1:
            print(0)
            continue

        for r in range(limit):
            if row_has_value(r, n):
                print(r)
                break

if __name__ == "__main__":
    solve()
```コードは各クエリを独立して処理しますが、行検索スペースが小さな定数によって制限されるという事実に依存しています。 機能`row_has_value`乗法二項恒等式を使用して行を増分的に構築します。これにより、前の行の再計算が回避され、整数安全な計算が保証されます。 

二項係数は対称的に増加してから減少するため、値がターゲットを超えたときに早期に終了することで、各行の後半での不必要な作業が防止されます。 

実装上の微妙な点は、二項漸化式で整数の除算を使用していることです。 C(r, k) は整数であるため、除算は常に正確ですが、次を使用します。`//`浮動小数点エラーなしで整数演算の範囲内に収まるようにします。 

## 実用的な例

 クエリが 1 と 3 である小さなケースを考えてみましょう。 

N = 1 の場合、最初の行にはすでに値 1 が含まれています。 

| r | k | 値 | 見つかりました |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | はい |

 答えはすぐに0です。 

N = 3 の場合、行ごとに処理を進めます。 

| r | 行の値 | 一致 |
 | --- | --- | --- |
 | 0 | 1 | いいえ |
 | 1 | 1 1 | いいえ |
 | 2 | 1 2 1 | いいえ |
 | 3 | 1 3 3 1 | はい |

 行 3 で 3 が見つかるため、答えは 3 になります。これは、常に最初の出現箇所で停止し、最小限の行インデックスを確保していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q・R) | 各クエリは最大約 60 行をスキャンし、各行はインデックス内で線形時間で計算されます。 
| スペース | お(1) | 計算中に保存される整数は少数だけです。 

R の定数境界により、解はクエリの数において実質的に線形になります。 クエリが 100,000 件あったとしても、操作の合計数は、制限内で快適に実行できるほど十分に少ないままです。

 ## 特殊なケース

 N = 1 の場合、最初の行には値 1 のセルが 1 つだけ含まれているため、正解は常に 0 です。アルゴリズムは、行の構築が開始される前にこれを明示的に処理し、不必要な計算を回避します。 

N = 2 の場合、値は最初に行 2 に C(2, 1) として表示されます。 このアルゴリズムは、最初に行 0 と行 1 をチェックし、一致が見つからなかった後、シーケンス 1、2、1 が生成される行 2 を構築し、k = 1 で一致を検出します。 

N = 10^9 などの上限に近い値の場合、アルゴリズムは二項係数が目標を超えるまで行をすぐにスキップします。 値が急速に増加するため、チェックは各行の早い段階で終了し、大きな行を完全に走査することができなくなります。
