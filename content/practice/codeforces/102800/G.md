 ## 解決策
 ## 問題の理解

 マトリックスはゼロで埋められ始めます。 すべてのポジティブペアについて`(i, j)`、行インデックスが次の値で割り切れるすべてのセルを反転する 1 つの操作を実行します。`i`そしてその列インデックスは次の数で割り切れます。`j`。 

特定のセルは、そこに到達しない操作を気にしません。 行のセルの場合`r`そしてコラム`c`、関連する操作は次の操作だけです。`i`分割する`r`そして`j`分割する`c`。 このようなペアごとにセルが 1 回反転されます。 すべての操作が完了すると、セルには次の内容が含まれます。`1`奇数回反転された場合、それ以外の場合はそのままになります。`0`。 

各テスト ケースは 1 つの行列の次元を示します。 タスクは、次のように終わるセルの数を数えることです。`1`。 

寸法は次のように大きくできます。`10^18`したがって、すべての行を反復処理することさえ不可能です。 に比例する任意のアルゴリズム`n`、`m`、 または`n × m`はすぐに除外されます。 ソリューションでは、テスト ケースごとに少数の算術演算のみを使用する必要があります。 

簡単な間違いの 1 つは、すべての約数が独立して寄与していると考え、答えがパリティのみに依存することを忘れることです。 

例えば：```
1
2 2
```正しい答えは次のとおりです。```
1
```セルのみ`(1, 1)`になる`1`。 他のセルは数回反転されますが、それぞれのセルは偶数回反転されます。 

もう 1 つの微妙なケースは、1 つのインデックスだけが完全な正方形である場合です。```
1
3 4
```正しい答えは次のとおりです。```
2
```行`1`は唯一の完全な正方形ですが、列は`1`そして`4`は完全な正方形です。 のみ`(1,1)`そして`(1,4)`として終了`1`。 1 つの次元だけをチェックする不注意なソリューションでは、過剰にカウントされてしまいます。 

最後のエッジケースは、可能な最大の入力です。```
1
1000000000000000000 1000000000000000000
```解ではシミュレーションを回避し、整数の平方根から直接答えを計算する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる操作に対して`(i, j)`、影響を受けるすべてのセルにアクセスして反転します。 これは定義に正確に従っているため、正しいです。 残念ながら、`n × m`可能な操作のペアがあり、各操作は多くのセルに影響を与える可能性があります。 寸法が次の値に達すると、すべてのセルを反復処理することさえ不可能になります。`10^18`。 

重要な観察は、1 つのセルを独立して分析することです。 

セルを見てみましょう`(r, c)`。 約数ごとに 1 回反転されます`i`の`r`そしてすべての約数`j`の`c`。 もし`d(x)`は約数の数を示します`x`、フリップの合計数は次のようになります。`d(r) × d(c)`。 

パリティのみが重要です。 積が奇数になるのは、両方の因数が奇数の場合のみです。 

ここで必要となるのは、古典的な数理論の事実 1 つだけです。 整数が完全な平方である場合、整数の約数は奇数になります。 正方形以外のすべての約数はペアで表示されます`(a, x / a)`、一方、完全な平方には、対になっていない約数、つまり平方根が 1 つあります。 

したがって、細胞は次のようになります`1`行インデックスと列インデックスの両方が完全な正方形である場合に正確です。 

問題は、各次元の完全な正方形を数えることに帰着します。 まさにあります`⌊√n⌋`間の完全な正方形`1`そして`n`、同様に`⌊√m⌋`間`1`そして`m`。 

最終的な答えは単純に、`⌊√n⌋ × ⌊√m⌋`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × m × 平均影響を受けるセル) | O(n × m) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. コンピューティング`a = ⌊√n⌋`整数平方根関数を使用します。 これにより、完全な正方形の行インデックスの数が得られます。 
3. コンピューティング`b = ⌊√m⌋`整数平方根関数を使用します。 これにより、完全な正方形の列インデックスの数が得られます。 
4. 出力`a × b`なぜなら、完全な正方形の行と完全な正方形の列を組み合わせると、奇数回反転されるセルが生成されるからです。 

### なぜ効果があるのか

 固定セルの場合`(r, c)`、フリップの数は除数のペアの数に等しい`(i, j)`と`i | r`そして`j | c`、つまり`d(r) × d(c)`。 セルは次のように終了します`1`この製品が奇数である場合に限ります。 完全平方の場合、約数の数は正確に奇数になるため、両方とも`r`そして`c`完全な正方形でなければなりません。 このような行と列を個別にカウントすると、含まれるセルの正確な数が得られます。`1`。 

## Python ソリューション```python
import sys
from math import isqrt

input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    print(isqrt(n) * isqrt(m))
```プログラムは数学的結果を直接実装します。`math.isqrt`整数の平方根を返します。これは正確に`⌊√x⌋`浮動小数点エラーなし。 入力は次のように大きくなる可能性があるため、これは特に重要です。`10^18`、浮動小数点平方根の精度が失われる可能性があります。 

各テスト ケースは、2 つの整数平方根計算と 1 つの乗算のみを実行します。 Python の整数は可能な最大の答えを快適に処理できるため、オーバーフローの心配はありません。

## テストケース```python
import sys
import io
from math import isqrt

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(isqrt(n) * isqrt(m)))
    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    ans = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return ans

# provided sample
assert run("1\n2 3\n") == "1"

# minimum size
assert run("1\n1 1\n") == "1"

# rectangular boundary
assert run("1\n3 4\n") == "2"

# no additional perfect square after 15
assert run("1\n15 15\n") == "9"

# maximum values
assert run("1\n1000000000000000000 1000000000000000000\n") == "1000000000000000000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`1`| 可能な最小の行列 |
 |`3 4`|`2`| 1 つの次元だけが複数の完全な正方形に寄与します。 
|`15 15`|`9`| 正しい床平方根の処理 |
 |`10^18 10^18`|`10^18`| 許可される最大値 |

 ## 特殊なケース

 最小の行列を考えてみましょう。```
1
1 1
```

`isqrt(1) = 1`両方の次元の場合、答えは次のようになります。`1 × 1 = 1`。 唯一のセルが一度反転されます。`1`約数が 1 つだけあります。 

ここで、1 つの次元にのみ複数の完全な正方形が含まれる場合を考えてみましょう。```
1
3 4
```アルゴリズムは計算します`isqrt(3) = 1`そして`isqrt(4) = 2`、生産`1 × 2 = 2`。 細胞`(1,1)`そして`(1,4)`フリップ数が奇数のものだけです。 

最後に、最大の法定値を検討します。```
1
1000000000000000000 1000000000000000000
```

`isqrt(10^18) = 10^9`、したがって、答えは次のとおりです`10^9 × 10^9 = 10^18`。 このアルゴリズムは定数時間の演算のみを実行し、実際の行列サイズには依存しません。
