 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 配列内のすべての値は最大でも`m`。 各クエリ値について`x`、注文されたペアの数を数えなければなりません`(ai, aj)`満足する`gcd(ai, aj) = x`。 順序ペアの意味`(i, j)`そして`(j, i)`の場合は別個にカウントされます。`i ≠ j`、 そして`(i, i)`も有効なペアです。 

単純な解釈は、すべてのインデックスのペアの最大公約数を計算し、その結果からクエリに答えることです。 それは正しいのですが、入力サイズによってはそれが不可能になります。 両方`n`そして`m`到達できる`10^5`、あるかもしれません。`10^5`クエリ。 すべてを計算する`n²`ペアには最大で`10^10`GCD 計算。1 秒に収まる量をはるかに超えています。 すべてのペアの情報を保存することさえ不可能です。 

値の上限が実際の機会です。 すべての配列要素は最大でも`m`したがって、個々のインデックスについて推論する代わりに、値とその約数について推論できます。 すべての整数の倍数を反復処理するアルゴリズムはおおよそ実行されます。`m log m`時間だから$$\sum_{i=1}^{m}\frac{m}{i}=m\log m.$$それは十分に許容範囲内です`m = 10^5`。 

簡単な間違いの 1 つは、問題では順序のないペアではなく順序のあるペアが求められていることを忘れていることです。 

例えば、```
n = 2
array = [2, 4]
query = 2
```正しい答えは、`4`なぜなら有効なペアは`(2,2)`、`(2,4)`、`(4,2)`、 そして`(4,4)`。 ペアに順序がないかのように 2 で割ると、間違った答えが得られます。 

もう 1 つの微妙なケースは、クエリされた GCD が配列値として表示されない場合です。```
array = [6, 12]
query = 3
```GCD が等しいペアはありません`3`たとえすべての数値が次の数で割り切れるとしても、`3`。 単純に割り切れる数を数えるだけ`3`間違って戻ってきます`4`。 

3 番目のよくある間違いは、GCD がクエリそのものではなくクエリの倍数であるペアを数えることです。```
array = [4, 8]
query = 2
```両方の数は次で割り切れます`2`しかし、実際にはすべてのペアに GCD があります。`4`。 正しい答えは、`0`。 これがまさに、包含と除外のステップが必要な理由です。 

## アプローチ

 ブルート フォース手法では、順序付けられたインデックスのペアをすべてチェックし、計算します。`gcd(ai, aj)`、対応する答えをインクリメントします。 問題の定義を直接実装しているため、その正しさはすぐにわかります。 残念ながら、`n = 10^5`、それは実行します`10^10`ペアチェックなので、まったく実用的ではありません。 

重要な観察は、GCD が割り算によって定義されるということです。 ペアを 1 つずつ調べる代わりに、考えられるすべての値で割り切れる配列要素の数を数えます。 

させて`cnt[v]`値の周波数になります`v`配列内で。 

あらゆる約数について`d`、計算する$$f[d]=\text{number of array elements divisible by }d.$$これは、複数の処理を繰り返すことで効率的に行われます。`d`。 

もし`f[d]=c`、それから、`c²`2 つの値が両方とも割り切れる順序ペア`d`。 これらのペアの GCD は次のとおりです。`d`またはその倍数`d`。 

残りのタスクは、GCD が正確に一致するペアを分離することです。`d`。 約数を大きいものから小さいものまで処理することで、これが可能になります。 させて`ans[d]`GCD で順序付きペアの数を正確に示します`d`。 当初は、$$ans[d]=f[d]^2.$$ここでは、GCD が実際にあるすべてのペアがカウントされます`2d`、`3d`、または、より大きな約数が最初に処理されるため、別の倍数がすでに計算されています。 これらの寄与をすべて差し引くと、次のようになります。$$ans[d]=f[d]^2-\sum_{k\ge2}ans[kd].$$これは、倍数に関する古典的な包含-排他原理であり、メビウス関数を明示的に計算せずにメビウス反転として説明されることがよくあります。

 | ブルートフォース | O(n² log m) | O(m) | 遅すぎる |
 | 最適 | O(m log m + k) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、周波数配列を構築します`cnt`、 どこ`cnt[v]`値の出現数です`v`。 
2. すべての整数について`d`から`1`に`m`、配列要素の数が何で割り切れるかを計算します。`d`。 反復処理`d, 2d, 3d, ...`それらの周波数を蓄積して、`divisible[d]`。 
3. 回答配列を作成します。 
4. プロセス除数`m`まで`1`。 
5.セット`ans[d] = divisible[d] * divisible[d]`。 これは、2 つの値が次の値で割り切れるすべての順序付きペアをカウントします。`d`。 
6. 複数の処理を繰り返す`2d, 3d, ...`そして引きます`ans[multiple]`から`ans[d]`。 これらのペアは前のステップでカウントされましたが、実際には GCD の方が大きくなります。 
7. 前処理が完了すると、すべてのクエリに対して出力が行われます。`ans[x]`。 

### なぜ効果があるのか

 あらゆる約数について`d`、`divisible[d]²`GCD が次の倍数であるすべての順序付きペアをカウントします。`d`。 このようなペアはすべて、正確に 1 つの値、つまりその正確な GCD に属します。 より大きな約数からより小さな約数に向かって処理すると、より大きな GCD 寄与がすべてすでに計算されていることが保証されます。 これらの寄与を差し引くと、GCD が等しいペアが正確に残ります。`d`。 すべてのペアには最大公約数が 1 つだけあるため、すべてのペアは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m, k = map(int, input().split())

        cnt = [0] * (m + 1)
        for v in map(int, input().split()):
            cnt[v] += 1

        divisible = [0] * (m + 1)
        for d in range(1, m + 1):
            s = 0
            for x in range(d, m + 1, d):
                s += cnt[x]
            divisible[d] = s

        ans = [0] * (m + 1)
        for d in range(m, 0, -1):
            cur = divisible[d] * divisible[d]
            for x in range(d * 2, m + 1, d):
                cur -= ans[x]
            ans[d] = cur

        for _ in range(k):
            x = int(input())
            out.append(str(ans[x]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```周波数配列は、入力を位置ではなく値のカウントに圧縮します。 これが前処理を依存させる理由です`m`それよりも`n²`。 

2 番目のループは、各約数で割り切れる数値の数を計算します。 すべての整数はその約数についてのみ倍数として現れるため、倍数の反復は効率的です。 

逆ループはアルゴリズムの中心です。 減算は、より大きな除数がすでに処理された後に行う必要があります。そのため、反復は次のようになります。`m`まで`1`。 この順序を逆にすると、まだ計算されていない値が減算されます。 

広場`divisible[d] * divisible[d]`すでに順序付きペアを正しくカウントしています。 この問題では順序付きペアが必要であるため、2 の因数は必要ありません。 

すべての中間値は Python 整数に快適に適合します。 固定幅の整数を使用する言語では、可能な最大の答えは次のとおりであるため、64 ビット型が必要です。`n²`に達する`10^10`。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    out = []
    t = int(input())

    for _ in range(t):
        n, m, k = map(int, input().split())
        cnt = [0] * (m + 1)
        for v in map(int, input().split()):
            cnt[v] += 1

        div = [0] * (m + 1)
        for d in range(1, m + 1):
            for x in range(d, m + 1, d):
                div[d] += cnt[x]

        for d in range(m, 0, -1):
            ans[d] = div[d] * div[d]
            for x in range(d * 2, m + 1, d):
                ans[d] -= ans[x]

        for _ in range(k):
            out.append(str(ans[int(input())]))

    return "\n".join(out)

 ## 特殊なケース

 配列を考慮してください```
1
2 4 1
2 4
2
```割り切れる数は次のとおりです`divisible[4] = 1`そして`divisible[2] = 2`。 アルゴリズムは最初に計算します`ans[4] = 1`。 除数の場合`2`、から始まります`2² = 4`順序ペアを計算し、GCD で 1 つのペアを減算します。`4`、出発`4`。 これは、GCD が正確に一致する 4 つの順序ペアと一致します。`2`。 

ここで考えてみましょう```
1
2 12 1
6 12
3
```両方の値は次のように割り切れます。`3`、 それで`divisible[3] = 2`初期カウントは`4`。 より大きな約数を処理すると、GCD が次の 4 つのペアが減算されます。`6`、出発`0`。 このアルゴリズムは、割り算と正確な GCD を正確に区別します。 

ついに、```
1
2 8 1
4 8
2
```また`divisible[2] = 2`、初期カウントは次のようになります。`4`。 計算では引き算が行われます`ans[4] = 3`そして`ans[8] = 1`、ゼロを残します。 すべての候補ペアはより大きな正確な GCD に属しているため、除数として残るものはありません`2`。 これは、大きな約数から小さな約数への処理が重要である理由を示しています。
