 ## 解決策
 ## 問題の理解

 各水泳選手は一定の長さのレーンを前後に移動します`m`。 すべてのスイマーはポジションからスタートします`0`、位置に向かって泳ぎます`m`、到達するとすぐに向きを変え、この動作を永遠に繰り返します。 水泳選手のスピード`i`固定されており、次と等しい`x[i]`メートル/秒。 すべてのクエリは、指定された秒数後の特定の水泳選手の位置を尋ねます。 

スイマーは互いに対話することがないため、すべてのクエリは完全に独立しています。 クエリに必要な情報は、水泳者の速度、レーンの長さ、経過時間だけです。 

制約こそが本当の課題なのです。 まであります`10^6`水泳選手と`10^6`クエリ。 1 つのクエリには最大で`10^9`秒。 速い泳ぎの選手は何億回もの移動を完了する可能性があるため、すべてのターンをシミュレートすることさえ失敗します。 クエリが 100 万件ある場合、クエリごとに一定時間の作業のみが現実的です。 入力だけを読み取ると、すでに入力サイズの線形時間がかかるため、アルゴリズムが費やす必要があるのは`O(1)`クエリごとに追加の作業が必要になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

正確に壁に到達することを考慮してください。```
Input
1 5 1
1
5 1
```水泳選手は正確に移動しました`5`メートルなので、正解は```
5
```剰余を求めた後に常に反映する不注意な実装では、誤って返される可能性があります。`0`。 

ここで、完全な往復サイクルの終わりに正確に着陸することを考えてみましょう。```
Input
1 5 1
1
10 1
```水泳選手はそこから去ってしまった`0`に`5`そして戻って`0`、したがって、正しい答えは次のとおりです。```
0
```周期の長さを混同する`m`の代わりに`2m`間違って戻ってきます`5`。 

もう 1 つのよくある間違いは、泳者が遠くの壁に到達した後に方向を逆転することを忘れることです。```
Input
1 3 1
2
2 1
```水泳選手は旅する`4`合計メートル。 ポジションに到達後`3`, 戻るときの移動距離は 1 メートルなので、答えは次のようになります。```
2
```単純にコンピューティングする`(speed × time) % m`間違って戻ってきます`1`。 

## アプローチ

 最も直接的な解決策は、水泳者の動きをシミュレートすることです。 ポジションから始める`0`、壁の 1 つに到達するまでスイマーを繰り返し前進させ、方向を逆にし、要求された時間が経過するまで続行します。 これは物理プロセスと正確に一致しているため、明らかに正しいです。 残念ながら、それは遅すぎます。 1 つのクエリには数十億秒または数億回のターンがかかる場合があり、最悪の場合は完全に実行不可能になります。 

重要な観察は、水泳選手の動きが完全に周期的であるということです。 壁に反射するのではなく、車線を無限の直線に延長することを想像してください。 総距離を移動した後```
distance = speed × time
```水泳選手はスタートからその距離にいるだけです。 

反射は、この無限の線を折り畳むことによってモデル化できます。`2m`メートル。 完全な 1 つの期間は、`0`に`m`そしてそこから戻ってきました`m`に`0`、サイクル長は次のようになります。`2m`。 

させて```
r = (speed × time) mod (2m)
```もし`r ≤ m`、水泳者はまだ往路の途中なので、位置は単純に`r`。 

それ以外の場合、水泳者は帰路に就きます。 遠い壁までの残り距離は`r - m`、したがって、位置は```
2m - r
```各クエリで必要となるのは、乗算、モジュロ演算、および比較 1 つだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 効率的にバインドすることは不可能です。`O(speed × time)`シミュレーション |`O(1)`| 遅すぎる |
 | 最適 |`O(1)`クエリごと |`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 水泳者の数、レーンの長さ、クエリの数を読み取ります。 
2. すべてのスイマーの速度を配列に読み取り、各クエリが一定時間でそのスイマーの速度にアクセスできるようにします。 
3. サイクル長を次のように計算します。`cycle = 2 × m`、すべての往路と復路が正確にカバーされているため、`2m`メートル。 
4. クエリごとに、水泳者の速度を取得し、総移動距離を次のように計算します。`speed × time`。 
5. この距離を法的に小さくします`cycle`。 最後の不完全なサイクルより前のすべてが正確に繰り返されるため、残りの部分のみが現在の位置に影響します。 
6. 残りが最大の場合`m`、スイマーはスタートから遠ざかっているので、残りを出力します。 
7. それ以外の場合、水泳者はスタートに向かって後退します。 次のように出力して、残りを反対側の壁に反映します。`cycle - remainder`。 

### なぜ効果があるのか

 水泳選手の位置は、流れ内のどこにいるかによってのみ決まります。`2m`メーターサイクル。 すべての完全なサイクルは、開始時とまったく同じ位置および方向で終了するため、モジュロ演算で完全なサイクルを削除すると、答えが保存されます。 1 つのサイクル内では、パスは次の直線セグメントになります。`0`に`m`からの直線セグメントが続きます`m`に戻る`0`。 2 つの式はこれら 2 つの半分に正確に対応するため、考えられるすべての残りが正しい物理的位置にマッピングされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    speeds = list(map(int, input().split()))

    cycle = 2 * m
    out = []

    for _ in range(q):
        p, k = map(int, input().split())
        r = (speeds[k - 1] * p) % cycle
        if r <= m:
            out.append(str(r))
        else:
            out.append(str(cycle - r))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```プログラムは最初にすべての水泳選手の速度を保存し、各クエリが直接インデックスを作成してアクセスできるようにします。 スイマーには 1 から番号が付けられますが、Python リストにはゼロのインデックスが付けられるため、コードでは次を使用します。`k - 1`。 

サイクル長は決して変更されないため、一度計算されます。 すべてのクエリは同じ一連の算術演算を実行します。 Python の整数は、次のような大きな値を安全に処理します。`10^9 × 10^9 = 10^18`なので、オーバーフローは問題になりません。 

比較には、`<= m`それよりも`< m`。 余りがちょうどのとき`m`、水泳者はちょうど遠い壁に到達し、まだその位置にいます。`m`。 厳密な比較を使用すると、この点が偶然に誤ってそれ自体に反映され、他の言語で異なる数式を使用すると、微妙なバグが発生する可能性があります。 

モジュロは次のように取得されます`2m`、 ない`m`。 使用する`m`そうすると、水泳者が外側に向かって進んでいるのか、それとも戻ってきているのかに関する情報が完全に失われてしまいます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n, m, q = map(int, input().split())
    speeds = list(map(int, input().split()))
    cycle = 2 * m
    ans = []
    for _ in range(q):
        p, k = map(int, input().split())
        r = (speeds[k - 1] * p) % cycle
        if r <= m:
            ans.append(str(r))
        else:
            ans.append(str(cycle - r))
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# provided sample
assert run("1 3 2\n5\n1 1\n7 1\n") == "1\n1"

# minimum input
assert run("1 1 1\n1\n0 1\n") == "0"

# exact turning point
assert run("1 5 1\n1\n5 1\n") == "5"

# complete cycle
assert run("1 5 1\n1\n10 1\n") == "0"

# reflection
assert run("1 3 1\n2\n2 1\n") == "2"

# multiple swimmers
assert run("2 5 2\n2 3\n2 1\n2 2\n") == "4\n4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | シングルスイマー、タイムゼロ |`0`| 最小限の入力と動きなし |
 | 到達位置`m`まさに |`5`| 転換点の正しい対処 |
 | 完全なサイクル |`0`| の正しいモジュロ周期`2m`|
 | 反映例 |`2`| サイクルの半分を返す |
 | 複数の水泳選手 |`4`、`4`| 速度配列への正しいインデックス付け |

 ## 特殊なケース

 水泳者が正確に遠い壁に到達すると、残りは次の値に等しい`m`。```
Input
1 5 1
1
5 1
```アルゴリズムは計算します`r = 5 mod 10 = 5`。 以来`5 ≤ 5`、それは戻ります`5`、壁でのスイマーの実際の位置と一致します。 

水泳選手が往復を完了すると、残りはゼロになります。```
Input
1 5 1
1
10 1
```アルゴリズムは計算します`r = 10 mod 10 = 0`。 最初のブランチが戻ります`0`、これはまさに 1 つの完全なサイクル後の開始位置です。 

スイマーがすでに向きを変えたときは、反射が必要です。```
Input
1 3 1
2
2 1
```総距離は`4`。 アルゴリズムは計算します`r = 4 mod 6 = 4`。 以来`4 > 3`、それは戻ります`6 - 4 = 2`。 物理的には、水泳選手は所定の位置に到達します`3`後`1.5`数秒後、さらに 1 メートル戻り、その位置で終了します`2`、計算結果と正確に一致します。
