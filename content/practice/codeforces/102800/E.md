 ## 解決策
 ## 問題の理解

 隣接する 2 つの正の値を選択することによって、配列を繰り返し短縮します。 これら 2 つの値は削除され、次のいずれかに置き換えられます。`a % b`または`b % a`、その操作のために自由に選択されます。 2 つの要素が 1 つになるため、すべての操作で配列の長さが 1 だけ減少します。 

問題は、最終的な値が何になるかではなく、どれだけの要素を削除できるかです。 隣接する正の数のペアが存在しなくなると、それ以上の操作はできなくなります。 達成可能な最終的な最小の長さを計算する必要があります。 

配列の長さは次のように大きくできます。`10^6`単一のテスト ケースで、最大で`10`テストケース。 さまざまな操作順序を探索したり、多くの可能性をシミュレートしたりするアルゴリズムは、直ちに除外されます。 二次時間でも約`10^12`最大の入力に対する操作ですが、これは完全に実行不可能です。 ソリューションでは、各配列を線形時間で処理する必要があります。 

難しいのは、どちらかの残りを選択できることです。 この自由は、実際の値が見た目よりもはるかに重要でないことを意味します。 

配列を考慮してください`[1, 1, 1]`。 最初の 2 つの要素を次のように置き換えることができます。`1 % 1 = 0`、取得`[0, 1]`。 残りのペアは両方とも正ではないため、プロセスは長さで停止します。`2`。 可能な限り常にマージしようとする貪欲な試みは長さに達しません`1`。 

ここで考えてみましょう`[2, 3]`。 以来`2 % 3 = 2`そして`3 % 2 = 1`、どちらの選択もゼロを生成します。 配列は常に単一の正の値になるため、答えは次のようになります。`1`。 

もう一つの重要な事例は、`[5, 5, 5, 5]`。 値が等しい場合は、すぐにゼロを生成できます。`5 % 5 = 0`。 このアイデアを繰り返すとゼロが 2 つ残るため、最小の長さは次のようになります。`2`、 ない`1`。 すべての正のブロックを完全に還元可能なものとして扱うと、間違った答えが得られます。 

## アプローチ

 ブルート フォース ソリューションでは、すべての有効な操作、すべての可能な隣接ペア、および両方の残りの選択肢が調査されます。 各操作によって将来の可能性が変化するため、検索は指数関数的に分岐します。 到達可能な配列の数が膨大になるため、メモ化しても効果がありません。 このアプローチはすべての正当なシーケンスを検査するので正しいですが、数十の要素の配列の場合でも絶望的になります。 

重要な観察は、ゼロが将来のマージを永久にブロックするということです。 隣接する正の数値のみをマージできるため、正の値の最大連続ブロックはすべて独立して動作します。 ゼロは決して消えることがないため、1 つのブロック内の操作が他のブロックと相互作用することはありません。 

残る問題は、単一のポジティブブロックをどこまで削減できるかということです。 

ブロック内のすべての値が同一であると仮定します。 すべてのマージではゼロが生成されます。`x % x = 0`。 マージごとにセパレーターが作成され、ゼロが再び参加するのを防ぎます。 一定の長さのブロックから開始`k`、すべてのマージはちょうど 2 つの正の数を消費し、1 つのゼロを作成します。 最終的にはゼロだけが残り、さらにおそらく手付かずの正の値が 1 つだけ残ります。`k`奇数です。 そのブロックの最終的な長さは、`ceil(k / 2)`。 

ここで、ブロックに少なくとも 2 つの異なる値が含まれていると仮定します。 そうすれば、ユークリッド アルゴリズムを繰り返し適用している間、ブロックの最大公約数を常に保存できます。 等しくない数値は最終的に厳密に小さい正の剰余を生成するため、正の値が 1 つだけ残るまではブロッキング ゼロの作成を避けることができます。 ブロック全体が 1 つの要素に折りたたまれます。 

これは、すべてのポジティブ ブロックを完全に特徴づけます。

 ## アルゴリズムのチュートリアル

 1. アレイを左から右にスキャンします。 
2. ゼロがすでに独立した領域を分離しているため、ゼロに遭遇した場合は常にスキップします。 
3. 正の値が見つかった場合は、最大の連続する正のブロック全体を識別します。 
4. そのブロックをスキャンしながら、すべての要素が最初の要素と等しいかどうかを確認します。 同時にブロック長も記録します。 
5. ブロック内のすべての値が同一の場合は、次の値を追加します。`(length + 1) // 2`答えに。 これはまさに`ceil(length / 2)`。 
6. それ以外の場合は、追加します`1`ブロック全体を 1 つの要素に減らすことができるため、答えが得られます。 
7. ブロックの終了後、配列全体が処理されるまでスキャンを続けます。 

### なぜ効果があるのか

 隣接する正の数値のみが演算に参加できるため、ゼロは永続的なバリアです。 すべての操作は 1 つの正のブロック内に留まるため、異なるブロックが互いに影響を与えることはありません。 

少なくとも 2 つの異なる値を含むブロック内で、ユークリッド アルゴリズムを繰り返し適用すると、避けられないゼロが導入されることなく、ブロック全体が 1 つの正の値に減ります。 すべての値が同じブロック内では、マージが実行されるとすぐにゼロが作成され、残りの正の値が小さな独立した部分に分割されます。 そのプロセスは正確に残ります`ceil(length / 2)`生き残った要素。 すべてのブロックは独立しているため、これらの寄与を合計すると、最終的な配列の最小長が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        i = 0

        while i < n:
            if a[i] == 0:
                i += 1
                continue

            first = a[i]
            same = True
            j = i

            while j < n and a[j] > 0:
                if a[j] != first:
                    same = False
                j += 1

            length = j - i

            if same:
                ans += (length + 1) // 2
            else:
                ans += 1

            i = j

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```外側のループは各テスト ケースを独立して処理します。 ポインタ`i`配列を 1 回スキャンし、すべての正のブロックが 1 回だけ検査されます。 

コードはブロックごとに最初の値を記憶し、その後のすべての値がその値と一致するかどうかをチェックします。 これにより、ブロックが均一かどうかを判断する際に追加のデータ構造を保存することがなくなります。 

表現`(length + 1) // 2`計算する`ceil(length / 2)`整数演算を使用します。 これは、均一ブロックに必要な唯一の特殊なケースです。 

1 つのブロックが終了すると、スキャンはそのブロックの最後に直接ジャンプします。 要素が再考されることはないため、実装は線形のままです。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = 0
        i = 0
        while i < n:
            if a[i] == 0:
                i += 1
                continue
            first = a[i]
            same = True
            j = i
            while j < n and a[j] > 0:
                if a[j] != first:
                    same = False
                j += 1
            length = j - i
            ans += (length + 1) // 2 if same else 1
            i = j
        out.append(str(ans))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    print(solve(), end="")
    return sys.stdout.getvalue()

assert run("1\n3\n1 1 1\n") == "2", "sample"
assert run("1\n2\n3 4\n") == "1", "two distinct values"
assert run("1\n4\n5 5 5 5\n") == "2", "all equal"
assert run("1\n5\n2 3 4 0 7\n") == "2", "zero separates blocks"
assert run("1\n2\n9 9\n") == "1", "minimum uniform block"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 4`|`1`| 二つの等しくない価値観は完全に崩壊します。 |
 |`5 5 5 5`|`2`| 均一なブロックが必要`ceil(length / 2)`。 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
1
3
1 1 1
```アルゴリズムは、長さが正のブロックを 1 つ見つけます。`3`、すべての値が同一であることを観察し、貢献します`(3 + 1) // 2 = 2`。 出力は`2`、最適な操作シーケンスと一致します。 

次に、次のことを考えてみましょう。```
1
2
2 3
```ブロックの長さは`2`ですが、値は同一ではありません。 アルゴリズムが貢献する`1`、等しくない数値はいつでも 1 つの残りの値にマージできることを正しく認識しています。 

最後に、次のことを考慮してください。```
1
5
4 4 0 6 7
```スキャンにより 2 つの独立したブロックが検出されます。 1つ目は一律寄付あり`1`。 2 番目には寄与のある個別の値が含まれます`1`。 それらの合計は`2`。 処理中にゼロを横切ることはなく、演算に非正の近傍を含めることができないという制限と正確に一致します。
