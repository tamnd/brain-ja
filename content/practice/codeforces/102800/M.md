 ## 解決策
 ## 問題の理解

 整数の配列があります。 クエリ範囲ごとに`[l, r]`では、そのセグメント内の要素のみを確認します。 このセグメントに偶数回出現するすべての値について、その値を 1 回取得し、選択されたすべての値を XOR します。 奇数の頻度の値は無視されます。 

入力は配列と多くの範囲を与えます。 出力には、すべての範囲の回答が個別に含まれている必要があります。 

制約が主な課題です。 配列の長さとクエリの数は両方とも 500000 に達する可能性があります。すべての範囲をスキャンするソリューションのパフォーマンスは次のとおりです。`n * q`最悪の場合の動作、つまり約`2.5 * 10^11`、1秒で実行できる速度をはるかに超えています。 線形または線形に近いクエリを処理する必要があります。`n log n`時間。 

難しいのは、クエリが奇数頻度の値の XOR を要求しないことです。これは、XOR によって利用される通常の特性です。 逆のパリティを要求します。 不注意な実装では、すべての出現の XOR のみを計算してそれを返す可能性がありますが、そうすると奇数の頻度の値の XOR が得られます。 

たとえば、次のことを考えてみましょう。```
4 1
1 2 2 3
1 4
```値`2`が 2 回表示されるので、答えは次のようになります。`2`。 すべての要素の XOR は次のとおりです。`1 xor 2 xor 2 xor 3 = 2`、ここではたまたま動作しますが、これは動作が一般的に正しいためではありません。 本当の理由は、すべての出現の XOR が奇数頻度の値の XOR に等しく、この場合、奇数頻度の値のみが存在するためです。`1`そして`3`。 

間違いが明らかになるケースは次のとおりです。```
3 1
5 5 7
1 3
```正しい答えは、`5`、なぜなら、`5`均等な周波数を持っています。 すべての要素の XOR は次のとおりです。`5 xor 5 xor 7 = 7`、それは間違いです。 

もう 1 つの境界ケースは、すべての値が 1 つだけ出現する範囲です。```
3 1
1 2 3
1 3
```すべての値は奇数の頻度を持つため、答えは次のようになります。`0`。 「一度出現」を有効なものとして扱うメソッドはすべて失敗します。 

## アプローチ

 直接的な解決策では、各クエリを個別に処理します。 要求された範囲内のすべての値の頻度をカウントし、それらの頻度を反復処理して、偶数のカウントで値を XOR することができます。 これは定義に正確に従っているため、正しいです。 ただし、クエリには最大 500,000 個の要素を含めることができ、500,000 個のクエリが存在する場合もあります。 最悪のケースでは、次のことを調べる必要があります。`250000000000`配列の位置を調整するため、遅すぎます。 

重要な観察は、要求された回答を 2 つの簡単な部分に分割することから得られます。 させて`D`範囲内のすべての個別の値の XOR になります。 させて`O`その範囲内の奇数の頻度を持つすべての値の XOR になります。 XOR ではペアが消えるため、値が出現するたびに XOR を実行すると、頻度が奇数の場合にのみその値が残ります。 したがって、範囲内のすべての配列要素の XOR は正確に次のようになります。`O`。 

望ましい答えは、偶数周波数値の XOR です。 個別の値は奇数周波数値と偶数周波数値に分割されるため、次のようになります。```
D = O xor answer
```XOR を使用して並べ替えると、次のようになります。```
answer = D xor O
```第二部は、`O`、簡単です。 範囲全体を XOR 演算すると奇数周波数値の XOR が得られるため、プレフィックス XOR 配列を構築できます。 

残りのタスクは見つけることです`D`、多くの範囲内のすべての個別の値の XOR。 これはオフラインでも処理できます。 クエリを適切なエンドポイントで並べ替えます。 右端を左から右に移動しながら、すべての値の最新の出現位置を維持します。 フェンウィック ツリーには、最新の出現位置ごとに値が格納されます。 新しい値が出現すると、その前の位置が削除され、新しい位置が挿入されます。 クエリ`[l, r]`次に、から保存されている XOR を要求します。`l`に`r`、これには、範囲内に最新の値が出現するすべての値のコピーが 1 つだけ含まれます。 

ブルート フォースは頻度を直接カウントするため機能しますが、重複するクエリ間でほぼ同じ作業を繰り返します。 オフラインのアプローチでは、右側の境界が進むにつれて変化する個別の値のセットを維持することで、クエリ間で作業を共有します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | オフラインのフェンウィック ツリー | O((n + q) log n) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス XOR 配列を構築します。`pref[i]`最初の XOR を格納します`i`要素。 お問い合わせの場合`[l, r]`、`pref[r] xor pref[l - 1]`そのセグメント内のすべての出現の XOR を返します。これは、奇数の頻度を持つ値の XOR です。 
2. すべてのクエリを元の位置とともに保存し、右側のエンドポイントの昇順で並べ替えます。 この順序でクエリを処理すると、データ構造はクエリの右境界で終わる現在のプレフィックスを正確に表すことができます。 
3. インデックスがその配列値の最新の出現位置である場合にのみ、インデックスに値が含まれるフェンウィック ツリーを維持します。 位置処理時`i`、以前の発生を見てください。`a[i]`。 取り除く`a[i]`その古い位置から追加します`a[i]`位置にある`i`。 これにより、これまでに確認されたすべての値のアクティブなコピーが 1 つ保持されます。 
4. 現在の右境界がクエリの境界に達したとき`r`、フェンウィック ツリーに XOR をクエリします。`l`に`r`。 これにより、内部のすべての個別の値の XOR が得られます。`[l, r]`なぜなら、これらの値は、この間隔内で最新の値が出現するからです。 
5. 2 つの部分を組み合わせます。 個別値の結果と接頭辞の XOR 結果を XOR します。 個別の XOR には奇数と偶数の両方の周波数値が含まれますが、プレフィックス XOR には奇数の周波数値のみが含まれるため、奇数の値はキャンセルされ、偶数の周波数値のみが残ります。 

なぜ効果があるのか:

 処理されたすべての位置でのフェンウィック ツリーの不変条件は、処理されたプレフィックスに出現するすべての値が、その最新の出現位置で 1 回だけ寄与するということです。 現在の位置で終了するクエリの場合、値は Fenwick 範囲に表示されます。`[l, r]`正確に、その最新の発生が少なくとも`l`これは、値がクエリ範囲内のどこかに出現したことを意味します。 したがって、Fenwick クエリは、範囲内のすべての個別の値の XOR を返します。 

範囲のプレフィックス XOR は、等しい値のすべてのペアを削除し、奇数の頻度の値のみを残します。 これを個別値 XOR と XOR 演算すると、これらの奇数周波数値が削除され、偶数周波数値が正確に保持されます。これが必要な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class FenwickXor:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, val):
        n = self.n
        tree = self.tree
        while i <= n:
            tree[i] ^= val
            i += i & -i

    def query(self, i):
        res = 0
        tree = self.tree
        while i:
            res ^= tree[i]
            i -= i & -i
        return res

    def range_query(self, l, r):
        return self.query(r) ^ self.query(l - 1)

def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    n = int(next(it))
    q = int(next(it))

    arr = [0] + [int(next(it)) for _ in range(n)]

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] ^ arr[i]

    queries = [[] for _ in range(n + 1)]
    for idx in range(q):
        l = int(next(it))
        r = int(next(it))
        queries[r].append((l, idx))

    ans = [0] * q
    last = {}
    bit = FenwickXor(n)

    for r in range(1, n + 1):
        x = arr[r]
        if x in last:
            bit.update(last[x], x)
        bit.update(r, x)
        last[x] = r

        for l, idx in queries[r]:
            distinct_xor = bit.range_query(l, r)
            odd_xor = pref[r] ^ pref[l - 1]
            ans[idx] = distinct_xor ^ odd_xor

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、合計ではなく XOR 寄与を保存します。 これが機能するのは、XOR がここで必要とされるのと同じキャンセル動作を備えているためです。同じ論理位置に同じ値を 2 回挿入すると、その値が削除されます。 

の`last`ディクショナリは、すべての値の前のアクティブな位置を追跡します。 新しいオカレンスが到着した場合、新しいものを追加する前に古いコントリビューションを削除する必要があります。 ツリーには常に最新のもののみが含まれている必要があるため、順序は重要です。 

クエリ ストレージは右エンドポイントごとにグループ化されているため、明示的な並べ替えが回避され、単一の左から右へのスキャンが可能になります。 処理順序が入力順序と異なるため、回答は元のクエリ インデックスによって格納されます。 

プレフィックス XOR 配列は 1 から始まるインデックスを使用するため、位置の前に空のプレフィックスが追加されます。`1`自然に次のように表されます`pref[0]`。 これにより、クエリが最初の要素で開始されるときの特別な処理が回避されます。

## テストケース```python
import sys
import io

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class FenwickXor:
        def __init__(self, n):
            self.n = n
            self.tree = [0] * (n + 1)

        def update(self, i, x):
            while i <= self.n:
                self.tree[i] ^= x
                i += i & -i

        def query(self, i):
            res = 0
            while i:
                res ^= self.tree[i]
                i -= i & -i
            return res

        def range_query(self, l, r):
            return self.query(r) ^ self.query(l - 1)

    data = sys.stdin.buffer.read().split()
    if not data:
        return ""

    it = iter(data)
    n = int(next(it))
    q = int(next(it))
    a = [0] + [int(next(it)) for _ in range(n)]

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] ^ a[i]

    queries = [[] for _ in range(n + 1)]
    for i in range(q):
        l = int(next(it))
        r = int(next(it))
        queries[r].append((l, i))

    ans = [0] * q
    last = {}
    bit = FenwickXor(n)

    for r in range(1, n + 1):
        if a[r] in last:
            bit.update(last[a[r]], a[r])
        bit.update(r, a[r])
        last[a[r]] = r
        for l, idx in queries[r]:
            ans[idx] = bit.range_query(l, r) ^ (pref[r] ^ pref[l - 1])

    return "\n".join(map(str, ans))

 ## 特殊なケース

 単一発生の場合:```
3 1
1 2 3
1 3
```フェンウィック ツリーは個別の XOR を返します。`1 xor 2 xor 3 = 0`。 プレフィックス XOR も`0`すべての値が奇数の周波数を持つためです。 彼らの XOR は`0`これは、値が偶数回出現しないという事実と一致します。 

値が繰り返される場合:```
3 1
5 5 7
1 3
```配列を処理した後、フェンウィック ツリーには個別の値が含まれます`5`そして`7`、したがって、それは返されます`5 xor 7 = 2`。 プレフィックス XOR は次のとおりです。`5 xor 5 xor 7 = 7`。 それらを組み合わせると、`2 xor 7 = 5`、偶数の頻度の値のみを残します。 

最新の出現が移動する値の場合:```
4 1
2 3 2 4
1 3
```3 番目の位置が処理されると、`2`位置にある`1`が削除され、その位置に新しいコントリビューションが追加されます`3`が挿入されます。 フェンウィックのクエリ`[1,3]`まだ見えます`2`これは、データ構造が出現ではなく個別の値を表すためです。 個別の XOR は次のとおりです。`2 xor 3`、奇数周波数の XOR も`2 xor 3`、そして答えは`0`範囲内のすべての値が奇数回出現するためです。
