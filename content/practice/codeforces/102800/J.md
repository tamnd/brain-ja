 ## 解決策
 ## 問題の理解

 私たちには、部分的に塗りつぶされた 3 × 3 三目並べボードが与えられます。 アリスが使う`O`、ボブが使用する`X`、一部のセルはまだ空である可能性があります。 通常の三目並べとは異なり、誰かが線を完成してもゲームが止まることはありません。 すべての空のセルは最終的には埋められます。 最後に、すべての行、すべての列、および両方の対角線をカウントします。 各行は完全に次のもので構成されます`O`貢献する`+1`、各行は完全に次のもので構成されます。`X`貢献する`-1`、および混合行が寄与します`0`。 必要な答えは、両プレイヤーが常に最適なプレイをしたと仮定した場合の最終スコアです。 アリスはスコアを最大化しようとしますが、ボブはスコアを最小化しようとします。 

各テスト ケースは、次に誰のターンになるか、および現在のボード構成を指定します。 すべてのテストケースに対して最適な最終スコアを計算する必要があります。 

テスト ケースの数は 40,000 にも及ぶため、ボードが小さくても、テスト ケースあたりの作業は非常に少なくて済みます。 すべてのテスト ケースについてゼロから完全なミニマックス検索を行うと、同じゲーム状態を何千回も繰り返し解決することになります。 ゲーム全体には 9 つのセルしか含まれていないため、個別のボード位置の数は限られています。 これは、到達可能なすべての状態を一度事前計算し、その後、単純な検索で各クエリに応答することを強く示唆しています。 

いくつかの状況では、誤った実装が簡単に発生する可能性があります。 

行が完了してもゲームは**停止しません**。 例えば、```
1
OOO
...
...
```アリスはすでに勝ちの列を持っていますが、両方のプレイヤーはボードがいっぱいになるまで駒を置き続けなければなりません。 ボードを即座に次のように評価するソリューション`+1`追加の完成した行、列、または対角線が後で表示される可能性があるため、これは不正確です。 

移動するプレイヤーは、駒の数ではなく入力によって決まります。 例えば、```
0
...
...
...
```通常、空のボードはアリスに属しますが、この入力ではボブが次に移動することが明示的に示されています。 ターン値を無視すると、誤ったミニマックス決定が生成されます。 

もう 1 つの簡単な間違いは、移動のたびに最も新しい完了した行のみを評価することです。 考慮する```
1
OO.
OO.
...
```最後の移動は行と列を同時に完了する場合があります。 スコアは中間イベントではなく、常に最終ボードに依存します。 

## アプローチ

 最も直接的な解決策は、再帰的なミニマックス検索です。 現在の位置からすべての正当な手を試し、残りのゲームを再帰的に解き、アリスに最大値を選択させ、ボブに最小値を選択させます。 ボードがいっぱいになったら、完成した行、列、対角線を数えて、最終スコアを取得します。 

この検索は、可能なすべての継続を明示的に探索するため、正しいです。 問題は繰り返しです。 部分的に満たされている同じボードには、さまざまな移動順序を介して到達することができるため、同じサブツリーが繰り返し再計算されます。 1 つのゲームには最大 9 つの手が含まれますが、最大 40,000 の独立したテスト ケースを解決すると、この不必要な重複によりコストがかかります。 

重要な観察は、ゲームの状態はボードの構成とそのターンのプレイヤーによって完全に決定されるということです。 ボード構成の合計数は$3^9 = 19,683$、すべてのセルが空であるため、`O`、 または`X`。 2 人の可能なプレイヤーを掛け合わせると、異なる状態は 40,000 未満になります。 

すべてのクエリを個別に解決するのではなく、メモ化されたミニマックスを使用して各状態を 1 回だけ解決します。 再帰が以前に計算された状態に達すると、その答えがすぐに再利用されます。 すべての状態は最大 1 回評価されるため、作業全体は再帰パスの数ではなく、個別の状態の数によって制限されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(b!)$、 どこ$b$は空のセルの数です |$O(b)$| 多くのテストケースには遅すぎる |
 | 最適 |$O(3^9 \times 9)$前処理、$O(1)$クエリごと |$O(3^9)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのボードを 9 文字の文字列として表します。 これはゲームの状態を一意に識別し、メモ化キーとして使用できます。 
2. 3 つの行すべて、3 つの列すべて、および両方の対角をチェックしてボード全体を評価する関数を作成します。 それぞれがすべて――`O`行に 1 つ追加され、それぞれの行ですべてが追加されます。`X`行は 1 を減算します。 
3. 現在のボードと移動するプレイヤーを受け取る再帰的ミニマックス関数を作成します。 
4. ボードに空のセルが含まれていない場合は、ステップ 2 の評価を返します。これが、完了したゲームの最終スコアです。 
5. この状態がすでに計算されている場合は、保存されている答えをすぐに返します。 これにより、同じ位置を複数回解決することが回避されます。 
6. それ以外の場合は、現在のプレーヤーのマークを 1 つの空のセルに配置することによって、すべての正当な手を生成します。 
7. 結果の状態を反対側のプレーヤーで再帰的に解決します。 
8. アリスが移動した場合、最大の最終スコアが必要なため、最大の戻り値を維持します。 ボブが移動した場合、最終スコアを最小にする必要があるため、戻り値を最小に保ちます。 
9. 計算された値を返す前に、メモ化テーブルに保存します。 
10. 各テスト ケースについて、ボードを選択した表現に変換し、移動するプレーヤーを読み取り、メモ化されたミニマックス関数を呼び出し、戻り値を出力します。 

### なぜ効果があるのか

 すべての再帰呼び出しは、正確に 1 つの正当なゲーム ポジションを表します。 再帰では、その位置から可能なすべての継続が探索されます。 ボードがいっぱいになった後でのみ完了した行をカウントするため、終了評価は問題で定義されたスコアと正確に一致します。 アリスは常に最大スコアの継続を選択し、ボブは常に最小スコアを選択するため、反復はまさに最適なプレイの定義です。 メモ化では、状態がどのような値を受け取るかではなく、状態が解決される頻度のみが変更されるため、戻り値は正しいままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LINES = [
    (0, 1, 2),
    (3, 4, 5),
    (6, 7, 8),
    (0, 3, 6),
    (1, 4, 7),
    (2, 5, 8),
    (0, 4, 8),
    (2, 4, 6),
]

memo = {}

def score(board):
    res = 0
    for a, b, c in LINES:
        if board[a] == board[b] == board[c]:
            if board[a] == 'O':
                res += 1
            elif board[a] == 'X':
                res -= 1
    return res

def dfs(board, alice_turn):
    key = (board, alice_turn)
    if key in memo:
        return memo[key]

    if '.' not in board:
        val = score(board)
        memo[key] = val
        return val

    if alice_turn:
        best = -10
        mark = 'O'
        for i, ch in enumerate(board):
            if ch == '.':
                nxt = board[:i] + mark + board[i + 1:]
                best = max(best, dfs(nxt, False))
    else:
        best = 10
        mark = 'X'
        for i, ch in enumerate(board):
            if ch == '.':
                nxt = board[:i] + mark + board[i + 1:]
                best = min(best, dfs(nxt, True))

    memo[key] = best
    return best

t = int(input())
for _ in range(t):
    turn = int(input())
    board = "".join(input().strip() for _ in range(3))
    print(dfs(board, turn == 1))
```の`LINES`配列はすべてのスコア ラインを 1 回だけ保存し、プログラム全体でインデックス計算を繰り返すことを避けます。 

の`score`関数は完全に埋められたボードに対してのみ呼び出されます。 8 つの勝ちとなる可能性のあるラインをそれぞれチェックし、アリスの完成したラインとボブの完成したラインの間で必要な差を計算します。 

再帰的`dfs`関数はミニマックスをメモ化とともに実装します。 同じボードでも、誰の順番に応じて最適な値が異なる場合があるため、メモ化キーにはボードと現在のプレイヤーの両方が含まれます。 

再帰は、ボードに空のセルがなくなった場合にのみ終了します。 これは、プレイ中にセリフが完成してもゲームが終了しないという、修正されたゲームのルールに一致します。 

初期値`-10`そして`10`スコアは常に の間にあるので安全です`-8`そして`8`、ボード上には可能なラインが 8 つしかないためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    from functools import lru_cache

    LINES = [
        (0,1,2),(3,4,5),(6,7,8),
        (0,3,6),(1,4,7),(2,5,8),
        (0,4,8),(2,4,6)
    ]

    @lru_cache(None)
    def dfs(board, turn):
        if '.' not in board:
            s = 0
            for a,b,c in LINES:
                if board[a]==board[b]==board[c]:
                    if board[a]=='O':
                        s += 1
                    elif board[a]=='X':
                        s -= 1
            return s
        if turn:
            ans = -10
            for i,c in enumerate(board):
                if c=='.':
                    ans = max(ans, dfs(board[:i]+'O'+board[i+1:], 0))
            return ans
        ans = 10
        for i,c in enumerate(board):
            if c=='.':
                ans = min(ans, dfs(board[:i]+'X'+board[i+1:], 1))
        return ans

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        turn = int(input())
        board = "".join(input().strip() for _ in range(3))
        out.append(str(dfs(board, turn)))
    return "\n".join(out)

 ## 特殊なケース

 勝ちラインがすでに存在しているが、ボードがいっぱいではない場合を考えてみましょう。```
1
1
OOO
...
...
```アルゴリズムは、完了した行を観察した後も停止しません。 空のセルが残るため、すべてのマスが占有されるまで再帰が続きます。 その後のみ、評価関数は完了したすべての行をカウントします。 これは、修正されたゲーム ルールと正確に一致します。 

次に、ターンが既存の駒の数と一致しないボードを考えてみましょう。```
0
...
...
...
```メモ化キーには、移動するボードとプレイヤーの両方が含まれます。 この位置は通常のゲームでは決して発生しませんが、検索はボブが結果を最小化することから始まります。 アルゴリズムは、個数から推測するのではなく、入力に従います。 

最後に、1 つの動きで複数のラインが同時に作成される位置を考えてみましょう。```
1
OO.
OO.
...
```再帰的検索は最終的に完全に埋められたボードに到達し、評価関数は 8 つの可能な行すべてを独立してチェックします。 1 つの手で行と列の両方を完了した場合、すべてのスコア ラインが個別に検査されるため、両方がカウントされます。 これにより、複数の同時接続によるポジションの過小カウントが回避されます。
