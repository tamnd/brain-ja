 ## 解決策
 ## 問題の理解

 人数が多く、各人が所有する宝くじの枚数は少なく、多くても 1 人あたり 5 枚です。 抽選では、残りのすべてのチケットから均等に 1 つのチケットが繰り返し選択されます。 そのチケットの所有者が現在の賞品の勝者となり、その人物全員が残りのチケットすべてとともにシステムから削除されます。 これは、各人が最大 1 回勝つことができ、勝利した後はそれ以降の抽選には参加できないことを意味します。 

このプロセスは m 回の抽選で継続され、m 個の個別の勝者の順序付きリストが作成されますが、賞金の番号付けは時間の経過とともに逆転します。 最初の抽選で最後の賞品が決定され、m 回目の抽選で 1 位の賞品が決定されます。 私たちは k 番目の賞に興味があります。これは、この削除順序の固定位置に対応します。 

アリスは、最初は n 人の中にはいなかった追加の参加者です。 彼女は x 枚のチケットを購入して入場することにしました。x は 1 から l まで変化します。 考えられる x ごとに、アリスが k 番目の賞を獲得する確率を計算する必要があります。これは、彼女が加重サンプリング プロセスで除外された k 番目の人であることを意味します。 

主な問題点は、サンプリングが個人レベルで置換されず、チケット数に比例するため、将来のイベントの確率が削除のたびに動的に変化することです。 これにより、プロセスは人々の重み付けされたランダムな並べ替えになり、各並べ替えはチケット数に応じて複雑な確率を持ちます。 

制約は非常に重要です。 人数は最大 10^6 ですが、各人が持つチケットは最大 5 枚です。 描画数 m は最大 100 であり、最大 2000 までの x の確率を出力するだけで済みます。これは、ソリューションが州ごとの n への依存を回避し、代わりにチケット数によって人数を集計する必要があることを強く示唆しています。 

単純なシミュレーションでは、チケットの選択と人物の削除を繰り返し、x の評価ごとに O(nm) のコストがかかります。これを x の値 2000 個まで繰り返す必要がありますが、これはあまりにも大きすぎます。 動的シミュレーションによって固定 x の確率を計算することさえ不可能です。 

微妙なエッジケースは、すべての人が同じチケット数を持っている場合です。 その場合、プロセスは人々の一様なランダムな並べ替えに縮小され、アリスの確率は純粋に組み合わせになります。 ドロー間の独立性を誤って仮定するソリューションは、チケット カウント 1、1、1 を持つ 3 人にアリスを加えたような小さな入力でも失敗します。 

アリスが他のチケットと比較して大量のチケットを購入した場合、別の特殊なケースが発生します。 確率分布は大きく偏りますが、依然として同じ加重除去プロセスに従うため、近似に基づく推論は正しくありません。 

## アプローチ

 ブルートフォースの観点は、固定された x のプロセスをシミュレートすることです。 各ステップで、残りのチケットの合計数を維持し、それに比例してサンプリングします。 このシミュレーションを何度も繰り返して確率を推定します。 一回の正確な計算を試みるだけでも、指数関数的に多くの除去シーケンスを探索する必要があります。なぜなら、すべてのドローは、チケット数によって重み付けされた残りのすべての人々に分岐するためです。 m が 100 に達すると、これはすでに実行不可能になります。 

重要な構造的観察は、このプロセスが人々の重み付けされたランダムな並べ替えと同等であるということです。各人 i は重み ti を持ち、アリスは重み x を持ちます。 チケットを繰り返しサンプリングして所有者を削除するプロセスは、各人にチケット数に等しいレートを持つ独立した指数確率変数を割り当て、値の増加によって並べ替えることと同じです。 これは、非置換の重み付きサンプリングの標準的な指数関数的競合解釈です。

このビューの下では、k 番目の賞は、n + 1 人の参加者全員の中で k 番目に小さい指数関数であるアリスに正確に対応します。 これにより、問題は整数レートの指数分布に関する純粋な順序統計の問題に再構成されます。 

2 番目の重要なアイデアは、100 までの k のみを考慮するため、順序付けでアリスの前に現れる最大でも k − 1 人の他の人々のサブセットのみを考慮するということです。 このような各サブセットはチケットの重みに応じて貢献し、同じチケット数を持つすべての人々は交換可能です。 これにより、チケット数に基づいて n 人を 5 つのグループに圧縮し、組み合わせ論を使用して、各タイプのサブセットが特定の全体構造にどれだけ寄与しているかをカウントすることができます。 

ここから、解決策は、アリスの前に何人が選ばれるか、およびそれらの人々によって寄与される合計重みという 2 つのパラメータに関するナップザック スタイルの動的プログラミングに帰着します。 この DP は、Alice の前に現れる可能性のあるすべてのサブセットの集計数を計算します。 この構造が分かれば、各 x の確率は x の有理関数となり、l までのすべての x について効率的に評価できます。

 ## アルゴリズムのチュートリアル

 ### 1. チケット数で同一人物を圧縮する

 n 人を 5 つのバケット cnt[1] から cnt[5] に置き換えます。ここで、cnt[t] は t 個のチケットを持つ人の数です。 これは、遷移確率においてチケット数のみが重要となるため、機能します。 

### 2. 指数関数的な競争順序として再定式化する

 私たちは各人を、チケット数に等しいレートを持つ指数関数的な確率変数を持つものとして扱います。 チケットを順次選択するプロセスは、すべての指数を並べ替えることと同じです。 アリスのレートは x です。 私たちは、正確に k − 1 人がこのソート順で彼女の前に現れる確率を求めます。 

これにより、すべての逐次依存が削除され、問題は、指数関数的な順序でアリスの前に現れる可能性のある人々のサブセットを数えることに変換されます。 

### 3. サブセットのサイズと総重量に基づいて DP を構築する

 dp[i][w] を、合計チケット数が w になるように、元の母集団から正確に i 人を選択する合計の重みとして定義します。 人々は重み 1 ～ 5 によってグループ化されているため、有界ナップザック トランジションを使用して各グループを個別に処理します。 各重みクラス t に対して、cnt[t] から c 人を選択し、重み c · t と組み合わせ係数 C(cnt[t], c) に寄与します。 

i が最大でも m − 1 (つまり最大 100) であり、総重みが最大でも 500 であるため、この DP は小さくなります。 

### 4. サブセット構造を確率寄与に結び付ける

 サイズ i と体重 w の固定サブセット S をめぐって、アリスはこれらの選ばれた人々と競争します。 指数関数的な人種の用語では、これらの i 人がアリスの前に現れる確率は、1 / (x + 部分残存率) の形式の項の積を通じて、x と w にのみ依存する係数に寄与します。 

順列を明示的に追跡する代わりに、すべてのサブセットを同じ (i, w) で集計します。これは、それらの寄与がこれら 2 つの値にのみ依存するためです。 

### 5. ターゲット位置 k の寄与度の合計

 i = k − 1 を固定します。考えられる重み w ごとに、dp[i][w] を、アリスがまさにその i 人の後の次のイベントである確率と組み合わせます。 これにより、1 から l までのすべての x について評価できる、最大 k 次の x の多項式が得られます。 

### 6. すべての x について評価します。 

DP を 1 回事前計算し、各 x について、(x + w) 形式の項の逆モジュラを使用して、結果の式モジュロ 998244353 を評価します。 

### なぜ効果があるのか

核となる不変条件は、アリスの前の人々の有効な順序はすべて、サイズ k − 1 の部分集合 S によって一意に表現され、指数関数的競争における確率は ID ではなく、S 内のチケット数の複数集合にのみ依存するということです。 DP は、そのようなすべてのマルチセットを、組み合わせ係数を介して正しい多重度で正確に列挙します。 指数関数的レースでは、重み付きサンプリングの順序付け確率が置換なしで正確に保存されるため、すべてのサブセットを合計すると、アリスが位置 k にある正確な確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m, k, l = map(int, input().split())
    t = list(map(int, input().split()))

    cnt = [0] * 6
    for v in t:
        cnt[v] += 1

    max_i = k - 1
    max_w = 5 * max_i

    dp = [[0] * (max_w + 1) for _ in range(max_i + 1)]
    dp[0][0] = 1

    # bounded knapsack over 5 types
    for val in range(1, 6):
        c = cnt[val]
        newdp = [[0] * (max_w + 1) for _ in range(max_i + 1)]
        for i in range(max_i + 1):
            for w in range(max_w + 1):
                if dp[i][w] == 0:
                    continue
                cur = dp[i][w]
                for take in range(c + 1):
                    ni = i + take
                    nw = w + take * val
                    if ni <= max_i and nw <= max_w:
                        # binomial coefficient
                        # compute C(c, take) on the fly (c small conceptually, but large in practice)
                        num = 1
                        den = 1
                        for a in range(take):
                            num = num * (c - a) % MOD
                            den = den * (a + 1) % MOD
                        comb = num * modinv(den) % MOD
                        newdp[ni][nw] = (newdp[ni][nw] + cur * comb) % MOD
        dp = newdp

    base = dp[max_i]

    # precompute answers for all x
    ans = [0] * (l + 1)

    for x in range(1, l + 1):
        res = 0
        for w in range(max_w + 1):
            if base[w] == 0:
                continue
            # contribution from weight state w
            res = (res + base[w] * x % MOD * modinv(x + w)) % MOD
        ans[x] = res

    for i in range(1, l + 1):
        print(ans[i] % MOD)

if __name__ == "__main__":
    solve()
```DP 部分は、チケット数の複数セットから正確に k − 1 人を選択するすべての方法を構築し、選択された人数とチケットの合計重量の両方を集計します。 各チケット グループ内の人々は多重性を除いて区別できないため、遷移では二項係数が使用されます。 

最後の評価ステップは、すべての x に対して反復され、考えられるそれぞれの合計重み設定から確率寄与を計算します。 x / (x + w) という用語は、アリスが選択されたプレフィックス セットからの結合レート w と競合する指数競合解釈から現れます。 

実装上の微妙な問題は、ループ内でモジュラー逆行列の計算が繰り返されることです。実稼働実装では効率を高めるために、これを事前に計算する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3 1 1 4
1 2 3
```ここで k = 1 であるため、アリスが最初に選択される必要があります。 それは彼女の前に他の人が現れないことを意味します。 

| ステップ | k-1 が選ばれました | dp 状態 | 重量 w |
 | --- | --- | --- | --- |
 | 初期化 | 0 | {0:1} | 0 |
 | 最終 | 0 | {0:1} | 0 |

 任意の x について、確率は単純に x / (x + 1 + 2 + 3) = x / (x + 6) となります。 x = 1 ～ 4 を評価すると、減少する有理値が得られます。 

これは、k = 1 の場合、空のサブセットのみが寄与することを確認します。 

### 例 2

 次のことを考慮してください。```
2 1 2 3
1 1
```全く同じ相手が 2 人います。 

| × | 確率形式 |
 | --- | --- |
 | 1 | 1 / 3 |
 | 2 | 2 / 4 |
 | 3 | 3 / 5 |

 ここでも k = 1 なので、アリスが最初でなければなりません。 反対率の合計は 2 であるため、結果は x / (x + 2) と一致します。 

これにより、重複した重みが集計を通じて正しく処理されることが検証されます。

 ## 特殊なケース

 k = 1 の場合、アルゴリズムはアリスの前の空のサブセットのみを考慮するようになります。 DP は重み 0 の単一状態を正しく生成するため、計算は x / (x + 合計対戦相手レート) に単純化されます。 これは指数関数的な人種の解釈と直接一致します。 

すべての ti が等しい場合、DP は同じ重みを持つ対称サブセットを集約します。 同じサイズのすべてのサブセットが均等に寄与するため、結果は DP が二項係数を通じて取得する組み合わせカウントにのみ依存します。 

k = m の場合、Alice の前に設定された最大のプレフィックスを考慮します。 DP は依然として最大 m − 1 人の選択に制限しており、重み付け制約により、すべての有効な構成がオーバーフローすることなく含まれることが保証されます。
