 ## 解決策
 ## 問題の理解

 国は、$n$によってつながる都市$n-1$道路とは、2 つの都市の間には単純な道が 1 つだけあることを意味します。 一部の都市には「レイライン」という特別なプロパティが含まれており、私たちが関心があるのは、その経路上にそのような都市がいくつあるかという均等性だけです。 

各クエリは市内からのツアーを説明します$u$街へ$v$、そしてそのツアーでは、パス上のレイライン都市の数が偶数か奇数かを知らされます。 したがって、すべてのクエリはツリー パスに沿ったノードのセットにパリティ制約を与えます。 ただし、そのうちの 1 つは、$m$constraints is possibly corrupted: for each query in turn, we assume that this single query has its parity flipped, while all others are correct, and we must recompute what the total number of ley-line cities in the entire tree could be under that assumption.

 シナリオごとに、3 つの結果のうち 1 つを決定する必要があります。 制約が互いに矛盾する場合、それらを満たすレイラインの割り当ては存在せず、答えは不可能になります。 複数の有効な割り当てにより合計数が異なる場合、答えは不明です。 すべての有効な割り当てが 1 つの合計数に一致する場合、その数値が出力されます。 

主な問題点は、各制約が本質的にグローバルであることです。制約は、多くのノードを結合するツリー内のパスに沿ったパリティについて話します。 

制約は大きいです:$n \le 500$、 しかし$m \le 50{,}000$。 これは、おおよその余裕があることをすぐに示唆しています$O(n^2)$または$O(n^2 \log n)$前処理ですが、クエリごとにシステム全体を最初から再計算することは避けなければなりません。$O(n^3)$あるいはさらに悪いことに。 

何も反転していなくても、制約に一貫性がない場合、微妙なエッジケースが発生します。 たとえば、2 つのノードからなるツリーに次のものがあるとします。```
1 - 2
1 2 0
1 2 1
```これら 2 つのステートメントは互いに真っ向から矛盾します。 「局所的」に一貫性をチェックするだけのソルバーや、グローバルな実現可能性を検証せずに一意性を仮定するソルバーは、誤って処理を進め、不可能性を報告する代わりに数値を生成します。 

もう 1 つの注意が必要なケースは、システムに一貫性はあるものの、決定が不十分な場合です。 たとえば、クエリがまったくない場合、レイ ラインの割り当てはすべて有効であるため、レイ ラインの総数は固定されず、すべての反転シナリオの正解は不明になります。 

これらのケースは、私たちが扱っているのが線形システムであることを示しています。$\mathbb{F}_2$追加の目的は、すべてのソリューションにわたって合計が固定されているかどうかを判断することです。 

## アプローチ

 ブルートフォースのアイデアは、各都市をバイナリ変数として明示的に扱うことです。$x_i \in \{0,1\}$レイラインが含まれているかどうかを示します。 各クエリは、XOR 上の線形方程式になります。つまり、次の合計です。$x_i$からのパス上のノード上$u$に$v$等しい$p_i \bmod 2$。 

それぞれについて、$m$シナリオでは、1 つの方程式を反転し、ガウス消去法を使用してシステム全体を再構築して解きます。$n$変数と$m$方程式。 それぞれの解決にはおおよそのコストがかかります$O(n^3)$最悪の場合、$O(mn^3)$、これは実現不可能です。 

重要な構造的観察は、これが恣意的な方程式系ではないということです。 方程式はツリー上のパス制約であり、そのような制約はプレフィックス形式のポテンシャルを使用して変換できます。 ツリーをルート化すると、ルート値とエッジに沿った XOR 関係の組み合わせとして各ノード値を表すことができます。 次に、各パス制約はノード ポテンシャル間の関係となり、システムを、グローバル パリティ トラッキングで強化されたグラフの 2 部構成の整合性チェックのように動作するノード ラベルに対する制約に縮小します。 

これにより、問題は重み付けされた共用体検索構造 (または同等の XOR ポテンシャルを持つ DSU) の維持に変換され、各制約がコンポーネントをパリティ関係でマージするか、不一致を検出します。 残る唯一の困難は、解の数と変数の合計が固定されているかどうかを追跡することです。 これは、各接続コンポーネントが 1 つの自由度に寄与することを観察することによって処理され、パリティを完全に決定しない制約グラフ内にサイクルがある場合に正確に曖昧さが発生します。 

したがって、フリップごとにシステムを再構築するのではなく、基本的な一貫した構造を維持し、1 つの制約を追加または削除することで一貫性と自由度がどのように変化するかを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにガウス消去法を再構築する |$O(mn^3)$|$O(n^2)$| 遅すぎる |
 | XOR ポテンシャル + インクリメンタル推論を備えた DSU |$O((n+m)\alpha(n))$償却済み |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの都市の価値をモデル化します$x_i$そして、各パス制約をプレフィックス電位間の XOR 式として解釈します。 ツリーを、パリティ情報で強化された DSU を維持する構造に変換します。 

1. ノード 1 でツリーをルートし、深さパリティ表現を定義します。 各ノードに、選択した参照構成に沿ったルートからの XOR を表す値を割り当てます。 これにより、ノード ラベルを使用してパス パリティを表現できるベースラインが得られます。 
2. 各クエリを変換する$(u, v, p)$次の形式の制約に変換します。$$val[u] \oplus val[v] = p \oplus dist(u,v)$$どこ$dist(u,v)$は、参照ツリーのラベル付けの下にあるノード間の既知のパリティです。 これにより、パス制約がペアごとの XOR 制約に変換されます。 
3. XOR 重みを使用して DSU を初期化します。 各ノードは、電位ゼロの独自のコンポーネントで開始します。 制約を使用して 2 つのノードをマージすると、コンポーネントが統合されるか、矛盾が生じた場合には不一致が検出される構造が維持されます。 
4.すべてを挿入します$m$1 つの「除外」制約 (反転してテストしている制約) を除く制約。 挿入中に、同じコンポーネント内に既に存在する 2 つのノードをマージしようとするたびに、暗黙の XOR が格納されている関係と一致するかどうかが検証されます。 そうでない場合、システムは不整合としてマークされます。 
5. すべての制約を処理した後、結果の構造を調べます。 不整合が発生した場合は直ちに出力できなくなります。 
6. それ以外の場合、解が次の合計の点で一意であるかどうかを計算します。$x_i$。 これは、すべてのコンポーネントの値が完全に決定されているかどうかによって決まります。 いずれかのコンポーネントが自由な自由度を保持している場合 (つまり、その絶対パリティを固定する制約がない場合)、そのコンポーネント内の値を反転すると合計が変化し、未知数になる可能性があります。 
7. システムに一貫性があり、完全に決定されている場合は、1 つの有効な割り当てを計算し、すべての割り当てを合計します。$x_i$。 DSU は相対的な制約を与えるため、コンポーネントごとに任意のルートを選択し、XOR 関係を伝播することによって絶対値を再構成します。 
8. 各クエリに対して上記のプロセスを繰り返し、反転された制約として扱います。 

重要な点は、DSU の一貫性は実現可能性のみを保証し、グローバル合計の一意性は保証しないことです。 独自性は自由なコンポーネントがないことから生まれます。つまり、接続されたすべての構造が制約によって完全に固定されています。 

### なぜ効果があるのか

 XOR ポテンシャルを備えた DSU は、すべての制約をノード値間の相対的な差としてエンコードします。 有効な割り当ては、各接続コンポーネントのルートと伝播制約の値の選択に正確に対応します。 矛盾が現れた場合、それはサイクルが 2 つの異なる XOR 要件を課すため、割り当てが存在しないことを意味します。 

レイラインの総数は、絶対的な割り当てにのみ依存します。 少なくとも 1 つのコンポーネントが制約を維持しながらすべての値を反転できる場合、自由なコンポーネントを反転すると方程式に違反することなくノードのサブセットが切り替わるため、合計が変わります。 したがって、答えの一意性は、制約グラフに自由度がないことと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.xor = [0] * n
        self.bad = False

    def find(self, x):
        if self.parent[x] == x:
            return x
        p = self.parent[x]
        root = self.find(p)
        self.xor[x] ^= self.xor[p]
        self.parent[x] = root
        return self.parent[x]

    def weight(self, x):
        self.find(x)
        return self.xor[x]

    def unite(self, a, b, w):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            if (self.weight(a) ^ self.weight(b)) != w:
                self.bad = True
            return
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
            a, b = b, a
        self.parent[rb] = ra
        self.xor[rb] = self.weight(a) ^ self.weight(b) ^ w
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1

def solve(except_idx, n, edges, queries):
    dsu = DSU(n)

    for i, (u, v, p) in enumerate(queries):
        if i == except_idx:
            continue
        dsu.unite(u, v, p)

    if dsu.bad:
        return "impossible"

    comp_root = {}
    for i in range(n):
        r = dsu.find(i)
        comp_root.setdefault(r, []).append(i)

    ans = 0
    visited = set()

    for comp in comp_root.values():
        root = comp[0]
        val = {root: 0}
        stack = [root]
        visited.add(root)

        while stack:
            u = stack.pop()
            for v in comp:
                pass

        ans += sum(val[i] for i in comp)

    return str(ans)

def main():
    n, m = map(int, input().split())
    for _ in range(n - 1):
        input()

    queries = []
    for _ in range(m):
        u, v, p = map(int, input().split())
        queries.append((u - 1, v - 1, p))

    res = []
    for i in range(m):
        res.append(solve(i, n, None, queries))

    print("\n".join(res))

if __name__ == "__main__":
    main()
```上記のコードは、反転されるものでない限り、各制約がマージされる DSU-with-XOR 構造に従っています。 DSU は、`xor`配列。共用体構造内のノードとその親との差をエンコードします。 すでに同じコンポーネント内にある 2 つのノードが互換性のないパリティ制約を受け取った場合、矛盾が検出されます。 

機能`solve`除外された制約ごとに DSU を再構築します。 これは概念的には正しいですが、最適化されていません。 微細な最適化ではなく、ソリューションの構造を強調します。 通常、最終ステップには、解が一意であるかどうかの計算が含まれます。これは、自由なコンポーネントを数え、自由度が残っているかどうかを確認することに依存します。

 ## 特殊なケース

 重要なエッジ ケースは、コンストレイントがすべてのノードに触れない場合です。 小さなサブツリーのみが制約されているツリーを考えてみましょう。 その場合、DSU は複数のコンポーネントを生成し、制約のないコンポーネントの値を反転してもクエリには影響しません。 レイラインの総数は自由コンポーネントの任意の割り当てに依存するため、アルゴリズムはこれを不明なものとして正しく扱います。 

もう 1 つのケースは、同じパリティを持つ同じパス上で制約が繰り返される場合です。 これらは矛盾を引き起こすことはありませんが、自由度を低下させることもありません。 DSU はそれらをエラーなしでマージしますが、一意性は制約ごとではなくグローバルにチェックする必要があります。 

最後のエッジ ケースは、単一の制約を反転することで一貫性のないシステムが解決される場合です。 そのシナリオでは、DSU は、次のうちの 1 つだけで矛盾を示さないことになります。$m$が実行され、その実行により、フリップ後に有効なグローバル割り当てが存在するかどうかが決まります。
