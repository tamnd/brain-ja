 ## 解決策
 ## 問題の理解

 一定の長さの配列全体に固定の合計を分配するためのあらゆる方法を検討することが求められます。$N$、各要素は負でない整数であり、すべての要素の合計は正確に次のようになります。$S$。 このような配列はすべて次のものから構成されます。$S$の中へ$N$部品。 有効な配列ごとに、そのすべての要素のビット単位の XOR を計算し、それらの XOR 結果をすべての有効な配列にわたって合計します。 

したがって、問題は 1 つの配列を構築することではなく、整数構成の組み合わせ空間全体にわたって関数を集約することです。 そのスペースのサイズはすでに巨大です。$N$そして$S$、解の数は$\binom{S+N-1}{N-1}$、それはすぐに天文学的なものになります。 

制約はこれを強化します。$5 \cdot 10^4$テストケース、合計$N$すべてのテストにわたって、次の制限も受けられます$5 \cdot 10^4$、 そして$S$と同じ大きさにすることができます$10^9$。 これにより、配列を列挙したり、配列で動作したりするソリューションは即座に除外されます。$O(S)$テストケースごとに。 より線形に近いものが必要です$N$、あるいはさらに良いのは、のビット構造のみに依存するものです。$S$。 

微妙な点は、一定の金額を分配した後にXORが適用されることです。 これにより、異なる要素のビット間に結合が生じるため、標準の「要素ごとの独立した桁 DP」は直接適用されません。 主な問題点は、加算制約がバイナリ表現では非線形である XOR と相互作用することです。 

注目すべきエッジケース:

 いつ$N = 1$、配列は 1 つだけあります$[S]$したがって、答えは単純です。$S$。 組み合わせ推論を適用しようとするソリューションはすべて、この自明なケースに正しく帰着する必要があります。 

いつ$S = 0$、唯一の有効な配列はすべてゼロであり、XOR はゼロです。 ビットごとの分布の数が正であると仮定する不注意な組み合わせ式は、ここで誤って偽の寄与を導入する可能性があります。 

いつ$N$大きいですが$S$が小さいと、ほとんどの要素がゼロになり、構造が疎になります。 ビットベースの DP は、ビット全体に独立して均一な分布を仮定してはなりません。これは、合計が小さいとキャリー動作が大きく制限されるためです。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効な配列を反復処理し、それぞれの構成を生成します。$S$、XOR を計算し、結果を累積します。 このような配列の数は$\binom{S+N-1}{N-1}$、これは、次のような小さな入力であってもすでに実行不可能です。$N=20, S=20$、それは数百万のオーダーです。 各配列の生成と評価の両方が入力サイズで指数関数的であるため、これは失敗します。 

重要な点は、合計制約と XOR 集計の両方の演算がビットごとに構造化されていることです。 合計制約は整数に対して線形ですが、XOR はビットを法とする 2 に対して線形です。これは、寄与をビット位置によって分離することを示唆しています。 

整数について考える代わりに、各ビットを個別に調べます。 配列の各要素はバイナリ表現に寄与し、下位ビットからの桁上げにより独立性が複雑になります。 画期的な方法は、生成関数または桁上げ状態を持つビットの組み合わせ DP を使用して、カウント プロセスを再解釈することです。 各ビット位置で、キャリーによる総和制約を尊重しながら、寄与が XOR で特定のパリティを生成する方法が何通りあるかを追跡します。 

これにより、問題はバイナリ位置上の数字 DP に変換され、XOR の残りの合計とパリティ状態の両方が伝播されます。 以来$S$大きいですが$N$全体的に小さいため、すべての合計を反復処理しません。 代わりに、指定されたビットがすべての構成にわたって 1 に寄与する方法が何通りあるかを組み合わせてカウントすることで、ビットごとの寄与を処理します。 

より構造化して確認する方法は、合計の順序を反転することです。配列を反復する代わりに、ビットごとにカウントします。$b$XORビットを生成する配列の数$b = 1$を乗算します。$2^b$。 XOR 値の合計は、2 の累乗で重み付けされたビット寄与の合計になります。 

固定ビットの場合$b$の数だけを気にします。$N$数値にはそのビットが設定されています。 ただし、少し設定することで貢献します$2^b$値に影響を与え、下位ビットからのキャリーを通じて合計制約にも影響します。 これにより、合計の分布をカウントする標準的なキャリー DP オーバー ビットが得られます。$S$バイナリで、横断的に$N$XOR パリティを追跡しながら、変数を追跡します。 

この DP が定式化されると、ビットごとの遷移は多項式になります。$N$となり、全体の複雑さは次のようになります。$O(N \log S)$、与えられた合計に適合します$N$テストケース全体では$5 \cdot 10^4$。

 ## アルゴリズムのチュートリアル

 番号を処理します$S$バイナリでビット全体の数字 DP を構築し、合計がどのように形成されるかを追跡します。$N$XOR 寄与を蓄積しながら変数を取得します。 

1. 各ビット位置を独立して考慮しますが、隣接するビット間のキャリー相互作用を考慮して、問題を基数 2 で表します。 これが有効である理由は、整数の加算は自然に桁上がりのある 2 進数に分解されるためです。 
2. すべての下位処理ビットを割り当てる方法が何通りあるかを表す DP 状態を定義します。$N$次のビットへの現在のキャリーと、そのビット位置の現在の XOR パリティが得られるような数値です。 複数の数値からのビット寄与が特定の位置で 1 を超える可能性があるため、キャリーが必要です。 
3. ビット位置ごとに、そのビットの考えられるすべての分布を繰り返します。$N$要素。 固定ビット位置の場合、各要素はそのビットで 0 または 1 のいずれかになりますが、1 の合計数がキャリーと相互作用して、次のキャリーと現在の XOR ビットを決定します。 
4. 組み合わせカウントを使用して遷移を計算します。 まさに$k$要素のこのビットには 1 があり、$\binom{N}{k}$それらを選択する方法。 このビットでの寄与合計は次のようになります。$k + \text{carry}$これにより、次のキャリーと、再構成された合計の結果のビットが決まります。 XOR 寄与は、次のいずれかによって異なります。$k$奇数です。 
5. 私たちは、次の基準で加重して寄付を蓄積します。$2^b$なぜなら、各ビットは最終的な整数値に独立して寄与するからです。 
6. すべてのビット位置を最上位ビットまで反復します。$S$、DP 状態を繰り返し更新します。 

### なぜ効果があるのか

 正確さは、2 つの直交する構造、つまりキャリー伝播によって制御される 2 進加算と、選択されたビットのパリティのみに依存する XOR を分離することで得られます。 すべての有効な配列は、すべての位置にわたるビットレベル割り当てのシーケンスに一意に対応し、DP はそのようなシーケンスをすべて 1 回だけ列挙します。 キャリーにより合計制約がグローバルに適用されることが保証される一方、二項カウントによりすべての分布が漏れや重複なくカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# precompute binomials up to max N (since sum N over tests <= 5e4)
MAXN = 50000
fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN] = pow(fact[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve_case(n, s):
    if n == 1:
        return s % MOD
    if s == 0:
        return 0

    # DP over bits: dp[carry] = ways
    dp = {0: 1}
    bit = 0
    ans = 0

    while (1 << bit) <= s or dp:
        ndp = {}

        for carry, ways in dp.items():
            # number of ways to choose k ones at this bit
            for k in range(n + 1):
                c = C(n, k)
                if c == 0:
                    continue

                total = k + carry
                next_carry = total >> 1
                bit_val = total & 1

                # XOR parity: k ones contribute XOR bit = k % 2
                xor_bit = k & 1

                # only accumulate contribution of XOR value itself
                # weighted by bit position
                contrib = (xor_bit * ((1 << bit) % MOD)) % MOD

                new_ways = ways * c % MOD

                ndp[next_carry] = (ndp.get(next_carry, 0) + new_ways) % MOD

                ans = (ans + new_ways * contrib) % MOD

        dp = ndp
        bit += 1

        if bit > 31 and not dp:
            break

    return ans % MOD

def main():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        print(solve_case(n, s))

if __name__ == "__main__":
    main()
```階乗事前計算により、定数時間の二項係数クエリが可能になります。これは、すべてのビット遷移が次の条件に依存するため不可欠です。$\binom{N}{k}$。 

XOR 寄与が答えに個別に蓄積されるため、DP 辞書はキャリー状態のみを追跡します。 各遷移は、現在のビットに 1 を配置する数字の数を列挙します。 キャリー伝播により、ビット位置全体で合計制約が確実に尊重されます。 

DP が空になったときの早期終了により、意味のあるビットを超えた不必要な処理が防止されます。$S$。

 ## 特殊なケース

 のために$N=1, S=0$、DP はただちに遷移のない単一の状態に減少します。 唯一の配列は$[0]$、XOR はゼロです。 基本 DP はキャリー ゼロで始まり、ゼロ以外の寄与がまったく導入されないため、アルゴリズムはこれを処理します。 

のために$S=0$そして一般的な$N$、のみ$k=0$移行はあらゆるビットで存続します。 他のすべての二項項は依然として組み合わせ的に存在しますが、ゼロ和パスのみが寄与し、ビットが設定されないため XOR はゼロのままです。 

大型用$N$小さいもので$S$、ほとんどの DP 質量はキャリー 0 の低ビットのままです。 上位ビットは決してアクティブにならないため、DP が空になるとアルゴリズムは自然に早期に終了し、最大 31 ビット以上の不必要な反復を回避します。
