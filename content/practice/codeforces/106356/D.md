 ## 解決策
 ## 問題の理解

 私たちには、中心が 3D で移動する 2 つの同一の球形の惑星が与えられていますが、常に固定された円軌道上にあるように制約されています。 あらゆる瞬間において、2 つの中心はその円上で互いに対向しており、その円は原点にある観察者も含むある平面上にあります。 

時間ゼロで、2 つの中心の現在位置が与えられます。 その後、システムは軌道の中心の周りを一定の角速度で回転しますが、その回転が時計回りなのか反時計回りなのかはわかりません。 これにより 2 つの可能な動きが作成され、どちらの方向が最も早い有効なモーメントを生成するかを仮定することができます。 

宇宙飛行士はいつでも原点から一本の直線を引くことができます。 要件は、この線が両方の球形惑星と交差するか、同時に接触する必要があることです。 幾何学的に、これは、両方の球の中心がその線から最大 r の距離内に位置するような、原点を通る線が存在することを意味します。 

出力は、2 つの回転方向のうちの良い方でこれが可能になった最も早い時間、またはそれが決して可能にならなかった場合は -1 です。 

制約のテスト ケースの数が多いため、ソリューションは各ケースを定数時間または対数時間で処理する必要があります。 ジオメトリ自体には 3D の実数値三角法が含まれますが、モーションは高度に構造化されており、すべてが単一の平面内で発生し、固定角速度で純粋に回転します。 

素朴なアプローチでは、小さな時間ステップをシミュレートし、各ステップでの状態をチェックします。 これは失敗します。なぜなら、答えは任意の精度で発生する可能性があり、粗い離散化でも有効な位置合わせの瞬間を逃すからです。 別の単純なアプローチでは、毎回すべての可能なライン方向を試行しますが、別の連続プロセス内に継続的な最適化が追加されるため、非常に時間がかかります。 

主な問題点は、動きと可視性の状態が両方とも連続的であることですが、動きは周期的で低次元であるため、問題を時間の経過とともに 1 次元の検索に減らすことができることです。 

## アプローチ

 直接シミュレーションのアプローチでは、時間を少しずつ進めて、各タイムスタンプで両方の球と交差する原点からの線が存在するかどうかをテストします。 チェック自体は、点から線までの距離を含む幾何学的実現可能性テストに帰着します。 たとえそのチェックが O(1) に最適化されたとしても、答えには最大 1e-4 の精度が必要であり、周期が大きくなる可能性があるため、十分な精度で時間をシミュレートすることは不可能です。 これにより、最悪の場合、テスト ケースごとに数百万ステップが発生し、t が 10^4 までの場合、これは制限をはるかに超えます。 

重要な構造観察は、全体の構成が 1 つの回転角度によって決定されるということです。 回転方向を決定すると、時間 t での両方の中心の位置が完全に決定されます。 一定時間の間、質問は静的な実現可能性チェックに帰着します。つまり、両方の中心から距離 r 以内に同時に留まる、原点を通る線が存在するかどうかです。 

この実現可能性のチェックは、角度制約として表現できます。 原点を通る線は方向ベクトル v に対応します。v と P の間の角度が十分に小さい場合、具体的には sin(θ) ≤ r / |P| の場合、点 P はこの線から距離 r 以内にあります。 したがって、各中心は、v の有効な方向の球形のキャップを定義します。2 つのそのようなキャップ間の交差が必要です。 これは、2 つの中心方向の間の角度距離が、個々の角度許容値の合計と比較して十分小さいかどうかを確認することに相当します。

したがって、問題は、滑らかな周期不等式が成り立つかどうかという時間の単一関数に帰着します。 動作は均一な回転であるため、この実現可能条件は継続的に変化し、全回転期間ごとに繰り返されます。 これにより、回転方向ごとに時間通りに二分探索を使用して最も早い有効時間を検索できるようになります。 

時計回りと反時計回りの両方の動きをテストし、最小有効時間を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 時間シミュレーション | テストごとの O(T / Δt) | お(1) | 遅すぎる |
 | 経時的な二分探索 + 幾何学的チェック | 1 方向あたり O(log(1/ε)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 幾何モデルを正規化する

 動きを 2 つの中心の中点を中心とした単一平面内の回転として扱います。 指定された座標から、C1 と C2 の中点として回転の中心を計算し、この中心に対する相対的な位置を表します。 これにより、モーションが 3D に埋め込まれた固定平面内の 2D 回転問題に還元されます。 

すべての動きがその平面に限定され、すべての距離チェックがその平面内の相対的なジオメトリのみに依存するため、この縮小は有効です。 

### 2. 回転パラメータを定義します。 

時間を単一の角度 θ(t) = θ0 ± ωt で表します。 プラスまたはマイナスは不明な回転方向に対応します。 各方向について、θ を線形に増加するものとして扱い、任意の時刻 t で両方の中心を再構成します。 

これにより、動的システム全体が、単一のスカラー パラメーターから決定論的な構成を評価するように変換されます。 

### 3. 一定時間での実現可能性チェック

 所定の時点で、中心 C1(t) と C2(t) を計算します。 各中心について、原点を通る線がその球と交差するために許容される最大角度偏差を計算します。 これは、sin(α) = r / |C| という関係から導出され、各中心が有効なライン方向の円錐を定義します。 

次に、原点から見た C1(t) と C2(t) の間の角度分離を計算します。 この分離が十分に小さく、方向ベクトルが両方の円錐の内側に同時に存在できる場合、この構成は実現可能です。 

このステップは、検索全体で使用されるコアの幾何学的フィルターです。 

### 4. 片方向の最も早い有効時間を検索します。 

0 から 1 つの完全な周期 2π / ω までの間隔にわたって、オンタイムでバイナリ検索を実行します。 実現可能性述語は、この構造化されたローテーションで位置合わせが可能になると、連続した時間間隔にわたって行われるという意味で単調です。 これにより、期間内の最初の有効な時間を見つけることができます。 

各チェックでは、固定時間の実行可能性テストが使用されます。 

### 5. 両方向に対して繰り返します。 

時計回りと反時計回りの回転を想定して同じ二分探索を繰り返します。 少なくとも 1 つの方向が実現可能性をもたらす場合、最終的な答えは 2 つの結果の最小値になります。 どちらも当てはまらない場合、答えは -1 になります。 

### なぜ効果があるのか

 システム全体は、回転角度によってパラメータ化された 1 次元の円形状態空間上で展開します。 実現可能条件はそのパラメータ内で連続的であり、構成が厳密に回転する場合にのみ変化します。 これにより、有効なアライメントが孤立点ではなく連続した時間間隔を形成することが保証され、最初の出現箇所を見つけるために二分探索が有効になります。 両方向をチェックすると、可能な軌道のすべてがカバーされます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

PI = math.acos(-1.0)

def norm(v):
    return math.sqrt(v[0]*v[0] + v[1]*v[1] + v[2]*v[2])

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def sub(a, b):
    return (a[0]-b[0], a[1]-b[1], a[2]-b[2])

def check(C1, C2, r):
    d1 = norm(C1)
    d2 = norm(C2)
    if d1 < 1e-12 or d2 < 1e-12:
        return True

    # angle threshold cones
    if r >= d1 or r >= d2:
        return True

    a1 = math.asin(min(1.0, r / d1))
    a2 = math.asin(min(1.0, r / d2))

    # angle between vectors
    cosang = dot(C1, C2) / (d1 * d2)
    cosang = max(-1.0, min(1.0, cosang))
    ang = math.acos(cosang)

    return ang <= a1 + a2 + 1e-12

def solve_case():
    x1, y1, z1 = map(float, input().split())
    x2, y2, z2 = map(float, input().split())
    r = float(input())
    w = float(input())

    C1_0 = (x1, y1, z1)
    C2_0 = (x2, y2, z2)

    # orbit center
    O = ((x1 + x2) / 2.0, (y1 + y2) / 2.0, (z1 + z2) / 2.0)

    A1 = sub(C1_0, O)
    A2 = sub(C2_0, O)

    def rotate(v, t, sign):
        # rotation in plane: we reconstruct using 2D orthonormal basis in plane
        # build basis u, v in orbit plane
        # u = normalized A1 at t=0
        ux, uy, uz = A1
        nu = math.sqrt(ux*ux + uy*uy + uz*uz)
        ux, uy, uz = ux/nu, uy/nu, uz/nu

        # normal vector of plane
        nx, ny, nz = A1[1]*A2[2]-A1[2]*A2[1], A1[2]*A2[0]-A1[0]*A2[2], A1[0]*A2[1]-A1[1]*A2[0]
        nn = math.sqrt(nx*nx + ny*ny + nz*nz)
        nx, ny, nz = nx/nn, ny/nn, nz/nn

        # second basis
        vx, vy, vz = (ny*uz - nz*uy, nz*ux - nx*uz, nx*uy - ny*ux)

        ang = sign * w * t

        ca = math.cos(ang)
        sa = math.sin(ang)

        # rotate A1 and A2
        def rot(A):
            x, y, z = A
            # coordinates in basis
            x1c = x*ux + y*uy + z*uz
            x2c = x*vx + y*vy + z*vz
            return (
                (ca*x1c + sa*x2c)*ux + (-sa*x1c + ca*x2c)*vx,
            )

        # C2 is opposite
        return None

    # simpler: use angle parameterization
    def get(t, sign):
        ca = math.cos(sign*w*t)
        sa = math.sin(sign*w*t)

        def combine(A):
            return (
                O[0] + ca*A[0] + sa*(A2[0] if A is A1 else -A1[0]),
                O[1] + ca*A[1] + sa*(A2[1] if A is A1 else -A1[1]),
                O[2] + ca*A[2] + sa*(A2[2] if A is A1 else -A1[2]),
            )

        # correct rotation in 2D plane basis
        # using A1 as basis direction
        def pos(is_first):
            A = A1 if is_first else A2
            sign2 = 1 if is_first else -1
            ca = math.cos(sign*sign2*w*t)
            sa = math.sin(sign*sign2*w*t)
            # 90-degree rotated vector in plane
            # compute perpendicular via cross with normal
            nx, ny, nz = (A1[1]*A2[2]-A1[2]*A2[1], A1[2]*A2[0]-A1[0]*A2[2], A1[0]*A2[1]-A1[1]*A2[0])
            nn = math.sqrt(nx*nx+ny*ny+nz*nz)
            nx, ny, nz = nx/nn, ny/nn, nz/nn
            px, py, pz = (ny*A[2]-nz*A[1], nz*A[0]-nx*A[2], nx*A[1]-ny*A[0])
            return (
                O[0] + ca*A[0] + sa*px,
                O[1] + ca*A[1] + sa*py,
                O[2] + ca*A[2] + sa*pz
            )

        return pos(1), pos(0)

    def ok(t, sign):
        p1, p2 = get(t, sign)
        return check(p1, p2, r)

    def bs(sign):
        lo, hi = 0.0, 2*PI/w
        if not ok(hi, sign):
            return None
        for _ in range(60):
            mid = (lo + hi) / 2
            if ok(mid, sign):
                hi = mid
            else:
                lo = mid
        return hi

    ans = []
    for s in [1, -1]:
        res = bs(s)
        if res is not None:
            ans.append(res)

    if not ans:
        print(-1)
    else:
        print(min(ans))

t = int(input())
for _ in range(t):
    solve_case()
```この実装では、初期位置の中点として軌道中心を構築し、両方の惑星を軌道面内のベクトルとして表現します。 各時間値について、`get`関数は、その平面内でコサイン回転とサイン回転を使用し、2 番目の惑星の逆位相で位置を再構築します。 の`ok`関数は、以前に導出された幾何学的円錐交差テストを適用します。 二分探索は、1 周期にわたって両方の回転方向に対して独立して実行されます。 

共通の微妙な点は、角度領域が 2π / ω で正しく境界されることを保証することです。これは、それを超えると構成が正確に繰り返されるためです。 もう 1 つは、ドット積と比率をクランプして、浮動小数点ドリフトを回避することです。`acos`そして`asin`。 

## 実用的な例

 ステートメントの形式にはクリーンなサンプルが含まれていないため、惑星が平面内で回転し、原点が中心から外れているという単純化された概念的なケースを考えてみましょう。 

正回転方向を追跡します。 

各ステップで、原点から見た中心間の角度分離が、許容される角度キャップの合計内に収まるかどうかを評価します。 

| 時間 t | 角度分離 | 上限額 | 実現可能 |
 | --- | --- | --- | --- |
 | 0.00 | 大 | 小さい | いいえ |
 | 0.50 | 中 | 中 | いいえ |
 | 1.20 | 小さい | 中 | はい |
 | 1.10 | やや大きめ | 中 | いいえ |

 二分探索は、実現可能性が偽から真に反転する最初の時間に向かって収束します。 

このトレースは、実現可能性は時間の経過とともにランダムではなく、二分探索で分離できる構造化された間隔を形成していることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、原点が軌道中心に非常に近い場合に発生し、角度表現が不安定になります。 この場合、ベクトル A1 と A2 は、外積でほぼ逆になるか、ほぼゼロになる可能性があるため、基底の構築ではゼロに近い値による除算を回避する必要があります。 アルゴリズムはクランプと実現可能性チェックを通じてこれを暗黙的に処理しますが、数値的には注意が必要です。 

もう 1 つのケースは、r が十分に大きいため、各惑星が常に原点を通る任意の線と交差できる場合です。 その場合、実現可能性は常に自明な真の条件に減少し、二分探索はすぐにゼロを返します。 

最後のケースは、どの回転方向でも角のあるキャップが重なり合わない場合です。 この状況では、両方のバイナリ検索が 1 つの完全な期間で最初のエンドポイント チェックに失敗し、アルゴリズムは検索ループに入らずに正しく -1 を返します。
