 ## 解決策
 ## 問題の理解

 上を移動するヘビをシミュレートしています。$n \times n$エッジが回り込むグリッドなので、グリッドはトーラスのように動作します。 ヘビは単一細胞として始まります。$(1,1)$。 私たちには次のシーケンスが与えられています$k$移動するたびにヘッドが基本方向に 1 ステップ移動し、範囲外になるとラップアラウンドが適用されます。 

各ステップで、頭が動いた後、頭が現在の食物セルに着地する場合はヘビを成長させるか、そうでない場合は尾を前方に移動して長さを変更しないようにします。 食べ物は一定の順序で 1 つずつ表示されます。常に 1 つの食べ物だけが存在し、現在の食べ物を食べるとすぐに次の食べ物が現れます。 重要なのは、ヘビが頭を動かした後に体のどこかに着地すると死ぬことです。ただし、同じステップで尾が同時に離れる場合にのみ、現在の尾セルへの移動が許可されます。 

課題はヘビが最後まで生き残るかどうかを判断することです$k$動く。 先に死んだ場合は出力します`DEAD`、それ以外の場合は出力します`ALIVE`その後に最終的な長さが続きます。 

制約は次のとおりです$10^5$すべてのパラメータに対して、動きごとにヘビの体全体をスキャンするアプローチは即座に除外されます。 各ステップでボディ全体を反復処理して衝突をチェックする単純なシミュレーションではコストがかかります。$O(k^2)$最悪の場合、遅すぎます。 移動ごとに一定または対数の償却操作が必要です。 

微妙な問題は、「末尾例外」ルールに起因します。 ヘビが成長していない場合は、頭が動いた後に尾が離れるため、古い尾房に足を踏み入れても安全です。 このタイミングを考慮せずに全身との衝突をチェックする単純なアプローチでは、一部の有効な技が誤って死亡としてマークされてしまいます。 

もう 1 つの微妙なエッジケースはラップアラウンドから発生します。 たとえば、$3 \times 3$グリッド、列 1 から左に移動すると、列 3 に到達します。モジュラー正規化を適用する前に衝突ロジックが実装されている場合、境界外の状態が誤って検出される可能性があります。 

最後に、餌のタイミングも重要です。ヘビは着地するとすぐに成長します。つまり、そのステップでは尾は動きません。 体の形状が成長なしの場合とは異なるため、これにより次の動きの衝突ルールが変更されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。頭から尾までのすべてのヘビの体のセルの明示的なリストまたは deque を維持します。 動きごとに新しい頭の位置を計算し、体全体をスキャンして頭がセグメントと衝突するかどうかを確認します。 衝突がない場合は、新しい頭を追加して尾を削除するか (餌がない場合)、頭だけを追加します (餌が食べられている場合)。 これはルールを直接シミュレートするため、これは正しいです。 

ただし、このアプローチでは各ステップで最大 30 分の 1 までのスキャンが必要になる可能性があるため、時間がかかりすぎます。$O(k)$体の部分、$O(k^2)$ヘビが直線的に成長する場合の総仕事量。 と$k = 10^5$、これは次の順序です。$10^{10}$限界をはるかに超えています。 

重要な点は、実際にはボディ全体を明示的に保存したりスキャンしたりする必要がないということです。 必要な操作は 2 つだけです。セルが現在ヘビによって占有されているかどうかを確認し、ヘビの移動に合わせてセルを挿入または削除します。 これは、末尾を効率的に削除できるように、占有セルのハッシュ セットと順序付けされた本体のデックを維持することを示唆しています。 

唯一の複雑な点は、「尾部が同時に移動する」ルールを処理することです。 衝突をチェックする際、テールセルが同じステップで移動する場合は、テールセルが一時的に無視されることを確認する必要があります。 つまり、占有を確認する前に、ヘビが成長しているかどうかを判断する必要があり、成長していない場合は、概念的には、衝突テストを実行する前に占有セットから尾を削除します。 

この構造では、各手は償却されて処理されます。$O(1)$これは、deque および set のすべての操作が一定の平均時間であるためです。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの構造を維持しています。1 つはヘビの本体を頭から尻尾まで保存する deque で、もう 1 つは高速メンバーシップ クエリのために占有されているすべてのセルを保存するハッシュ セットです。 

### ステップ

 1. 単一のセルでスネークを初期化します。$(1,1)$deque と set の両方で、food インデックスを 0 に設定します。現在の food はリストの最初の項目です。 
2. 移動ごとに、ラップアラウンドモジュロを適用して、方向を使用して次の頭の位置を計算します。$n$。 これにより、すべての座標が有効な範囲内に収まるようになります。 
3. 新しい頭の位置が現在の食物セルと等しいかどうかを判断します。 これにより、この動きでヘビが成長するかどうかが決まります。 
4. ヘビが成長していない場合は、衝突を確認する前に現在の尾セルをセットから削除します。 これは、頭のステップと同時に尻尾が遠ざかるという事実をモデル化しています。 
5. 新しい先頭セルがセット内にすでに存在するかどうかを確認します。 そうなると、現在の構成ではヘビが体に衝突するため、ヘビはすぐに死んでしまいます。 
6. それ以外の場合は、新しい先頭セルを両端キューの前に追加し、セットに挿入します。 
7. 餌を食べた場合は、尾を切らずに長さを伸ばし、次の餌に進みます。 食べ物が食べられない場合は、挿入ロジックが解決された後、両端キューから尾部セルを削除します。 

微妙な順序のポイントは、正しい状態、つまり尻尾が取り除かれた状態 (非成長の場合) または完全なボディがそのままの状態 (成長のケース) に対して衝突をチェックする必要があることです。 

### なぜ効果があるのか

 不変条件は、各移動の開始時に、デクとセットがそれまでのすべての移動後のヘビの体を正確に表すということです。 動きを処理する際、衝突検出の前に非成長の場合にのみ尾を一時的に削除することで、頭と尾の同時の動きを正確にモデル化します。 これにより、頭が動いた瞬間のヘビの実際の物理的状態が占有チェックに反映されることが保証されます。 すべての更新でデキューとセットの間の一貫性が維持されるため、古い位置は残らず、すべての衝突はシミュレーション内の実際の自己交差に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k, m = map(int, input().split())
s = input().strip()

food = [tuple(map(int, input().split())) for _ in range(m)]

from collections import deque

snake = deque()
snake.append((1, 1))

occupied = set()
occupied.add((1, 1))

head_x, head_y = 1, 1
food_idx = 0

dir_map = {
    'L': (0, -1),
    'R': (0, 1),
    'U': (-1, 0),
    'D': (1, 0)
}

for ch in s:
    dx, dy = dir_map[ch]
    nx, ny = head_x + dx, head_y + dy

    if nx == 0:
        nx = n
    elif nx == n + 1:
        nx = 1
    if ny == 0:
        ny = n
    elif ny == n + 1:
        ny = 1

    eat = (food_idx < m and (nx, ny) == food[food_idx])

    if not eat:
        tx, ty = snake[-1]
        occupied.remove((tx, ty))

    if (nx, ny) in occupied:
        print("DEAD")
        sys.exit(0)

    snake.appendleft((nx, ny))
    occupied.add((nx, ny))
    head_x, head_y = nx, ny

    if eat:
        food_idx += 1
    else:
        snake.pop()

print("ALIVE", len(snake))
```コードはシミュレーション モデルに直接続きます。 Deque は、ヘビを左側の頭から右側の尾まで保存します。 このセットは、O(1) 衝突チェックのためにそれをミラーリングします。 重要な点は、ヘビが成長しないときに衝突チェックの前にセットから尻尾を削除することです。これにより、同時の動きが正確にモデル化されます。 

ラップアラウンドは、移動を適用した後の境界チェックによって明示的に処理されます。 これにより、特殊な場合に若干読みにくくなる可能性があるモジュロ演算に依存することがなくなります。 

身体を改造する前に食事の摂取量をチェックし、同じ動きですぐに成長が適用されるようにします。

 ## 特殊なケース

 重要なエッジケースの 1 つは、成長していないときに尾細胞に移動することです。 たとえば、体長 3 のヘビが尻尾の位置に向かって前進する場合、尻尾が同時に取り除かれても死ぬことはありません。 この実装では、非成長ステップでの衝突チェックの前に占有セットから末尾を明示的に削除し、このケースが正しく処理されることを保証します。 

もう 1 つのエッジケースは、ラップアラウンドでの即時食物の消費です。 頭が動いてしまったら$(1,1)$小さなグリッド上に放置すると、反対側に回り込んで食物セルに正確に着地する可能性があります。 食物チェックは座標正規化後に行われるため、この場合は正しく成長がトリガーされます。 

最後のエッジケースは、成長直後の自己衝突です。 ヘビが餌を食べるとき、尾は動かないので、占有されたセットは尾を外してはなりません。 これにより、ボディがただちに 1 セル長くなり、その場合は完全に占有されているセットと照合するため、拡張されたボディとの衝突は正しく検出されます。
