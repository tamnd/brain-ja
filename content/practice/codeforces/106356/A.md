 ## 解決策
 ## 問題の理解

 私たちには、1 から n までの番号が付けられた部屋からなる 1 次元の回廊が与えられています。 粒子は固定チャンバー i から始まります。 どの部屋からでも、正確に a ステップ、または正確に b ステップだけ左または右に移動しようと試みることができます。 各移動はコリドー内に着地した場合にのみ成功し、それ以外の場合は無視され、パーティクルはその場に留まります。 

時間の経過とともに、パーティクルは、両方のステップ サイズと両方向を混合して、有効な一連の動きを実行できるようになります。 問題は、動作を段階的にシミュレートすることではなく、開始位置からどの部屋に到達できるかを判断することです。 最終出力は、まったく到達できない [1, n] 内のチャンバーの数です。 

n が 10^9 までの制約により、位置に関するシミュレーションが直ちに除外されます。 訪問した状態を保存するだけでもメモリを超えるため、すべてのチャンバーにわたる BFS または DP は不可能です。 最大 10^5 のテスト ケースが存在する可能性があるため、各テストは定数時間または対数時間で解決する必要があります。 

ローカルの到達可能性の観点だけで考えると、微妙な失敗例が現れます。 たとえば、n = 10、i = 5、a = 4、b = 6 の場合、ジャンプが大きいため、粒子は近くの少数の位置にしか到達できないと誤って仮定する可能性があります。 実際には、動きを組み合わせると到達可能な位置の格子が作成され、一部の遠く離れた部屋には線形結合によって到達できる可能性があります。 

別のエッジ ケースは、ステップ サイズの一方が他方を法としてゼロである場合、または a と b が大きな gcd を共有する場合に発生します。 たとえば、a = 2 および b = 4 の場合、実質的には偶数のオフセットのみが可能であり、両方の動きが個別に柔軟であるように見えても、コリドーの半分は到達不能になります。 

最も難しいのは、到達可能なセットがグラフ探索ではなく算術構造によって支配されることを認識することです。 

## アプローチ

 これを直接解決しようとすると、各チャンバーをグラフ内のノードとして扱い、±a と ±b が到達可能な位置に接続します。 次に、i から開始して BFS または DFS を実行します。 これにより到達可能性が正しく計算されますが、最悪の場合、コリドーのサイズは 10^9 であるため、ノードのごく一部を探索することさえ不可能になります。 グラフは暗黙的ですが、依然として巨大な状態空間を持っています。 

重要な観察は、すべての移動が +a、-a、+b、または -b のいずれかだけ位置を変更することです。 これは、到達可能な位置は、a と b の整数線形結合だけ開始位置 i とは異なることを意味します。 言い換えれば、x が到達可能であるとすると、x - i は整数 k1 および k2 に対して k1・a + k2・b として表現可能でなければなりません。 

古典的な数理論の結果は、a と b のすべての整数の組み合わせが gcd(a, b) の倍数を正確に形成することを示しています。 したがって、到達可能な位置は等差数列を形成します。 

i + t・g。位置が [1, n] 内にある限り、g = gcd(a, b)。 

したがって、問題は [1, n] 内の整数が i を法とする g と同じ剰余クラスにいくつあるかを数えるということになります。 このセットがわかれば、あとはすべて簡単に数えることができます。 

ブルート フォースは状態を明示的に探索するため失敗しますが、最適解では動作システム全体が 1 つの不変式に圧縮されます。つまり、gcd が接続性を制御します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース BFS/DFS | テストあたり O(n) | O(n) | 遅すぎる |
 | GCD 算術推論 | テストあたり O(log min(a,b)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. g = gcd(a, b) を計算します。 この値は、任意の順序で 2 つの動きを組み合わせることで生成できる最小ステップ サイズを表します。 到達可能な変位は g の倍数でなければなりません。 
2. g を法とする開始位置の残基クラスを決定します。 到達可能なすべての位置は x ≡ i (mod g) を満たす必要があるため、コリドーを 1 つの等差数列に制限します。 
3. [1, n] 内でこの合同を満たす数値がいくつあるか数えます。 最初の有効な位置は、x ≡ i (mod g) となる最小の x ≥ 1 であり、その後 g ステップごとに別の有効な位置が現れます。 
4. 単純な算術を使用してこの数を計算します。[1, n] 内の最初の有効な位置 f を見つけて、f + k・g 形式の項が n 内にいくつあるかを数えます。 
5. 答えは、n から到達可能な数を引いた、到達不能なチャンバーの数です。 

ステップ 3 が機能する理由は、到達可能なセットが合同クラス内で任意ではなく、範囲内で完全に満たされるためです。 残差クラス内の 1 つの位置が到達可能になると、廊下内にいる限り、そのクラス内の他のすべての位置に到達可能になります。 

### なぜ効果があるのか

 移動システムは、a と b によって生成される整数の加法サブグループを正確に生成します。 その部分群は g·Z です。ここで、g = gcd(a, b) です。 したがって、到達可能な位置間のすべての差のセットは固定されており、パス構造とは独立しています。 これにより、問題は、有界区間と交差する 1 次元の等差数列内の格子点を数えることになります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    for _ in range(q):
        n, i, a, b = map(int, input().split())
        
        g = math.gcd(a, b)
        
        # first reachable position >= 1 in the same residue class
        # as i modulo g
        r = i % g
        
        # find first x in [1, n] such that x % g == r
        first = r if r != 0 else g
        
        if first < 1:
            first += g
        
        if first > n:
            out.append(str(0))
            continue
        
        reachable = (n - first) // g + 1
        unreachable = n - reachable
        out.append(str(unreachable))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは最初に 2 つのステップ サイズの gcd を計算します。これにより、到達可能な剰余クラス構造が完全に決定されます。 変数 r は開始位置の合同クラスを取得します。 次に、この残基クラスに一致するコリドー内の最初の有効な位置を構築します。 

開始点がわかれば、到達可能な位置を数えることは単純な等差数列のカウントになります。 除算 (n - first) // g は、サイズ g の完全なジャンプが n まで何回収まるかを計算します。 

i が g で正確に割り切れる場合、剰余算術の処理には注意が必要です。 その場合、r はゼロになりますが、有効な剰余クラスは、1 インデックス付きシステムの 0 ではなく g に対応します。 これが、コードが r == 0 を g にマップする理由です。 

## 実用的な例

 ### 例 1

 入力:

 n = 9、i = 3、a = 3、b = 6

 ここで、 g = gcd(3, 6) = 3 です。到達可能なセットは、3 mod 3 に一致する位置、つまりすべての位置に留まる必要があります。 したがって、すべての部屋にアクセスできます。 

| ステップ | 値 |
 | --- | --- |
 | g | 3 |
 | 残留物 | 0 (3 として扱われます) |
 | 最初 | 3 |
 | 到達可能 | (9 - 3)//3 + 1 = 3 |
 | 到達不能 | 9 - 3 = 6 |

 これは、ジャンプが制限的であるように見えても、gcd は構造を完全な等差数列に崩壊させることを示しています。 

### 例 2

 入力:

 n = 15、i = 10、a = 1、b = 17

 ここで g = 1 であるため、すべての整数が範囲内で到達可能です。 

| ステップ | 値 |
 | --- | --- |
 | g | 1 |
 | 残留物 | 0 (1として扱われます) |
 | 最初 | 1 |
 | 到達可能 | 15 |
 | 到達不能 | 0 |

 これは、ステップ サイズを 1 にすると、他のジャンプに関係なく、すぐに廊下全体に到達可能になることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import math
    input = sys.stdin.readline
    
    q = int(input())
    out = []
    for _ in range(q):
        n, i, a, b = map(int, input().split())
        g = math.gcd(a, b)
        r = i % g
        first = r if r != 0 else g
        if first < 1:
            first += g
        if first > n:
            out.append("0")
        else:
            reachable = (n - first) // g + 1
            out.append(str(n - reachable))
    
    return "\n".join(out)

# custom cases
assert run("1\n1 1 2 3\n") == "0", "single cell always reachable"
assert run("1\n10 5 2 4\n") == "5", "even-only reachability"
assert run("1\n10 1 7 11\n") == "9", "gcd = 1 full reachability"
assert run("1\n20 3 6 9\n") == "13", "multiple of gcd structure"

 ## 特殊なケース

 n = 1 の場合、単一の位置は移動ルールに関係なく常にそれ自体から到達可能であるため、アルゴリズムは到達不能なチャンバーを正しく返しません。 

a と b が大きな gcd を共有する場合 (a = 100、b = 150 など)、到達可能な位置は 50 ステップでジャンプします。 n = 200 および i = 10 の場合、範囲内の最初の到達可能な位置は 10 であるか、または 50 の倍数でシフトされる可能性があり、アルゴリズムは剰余クラスに正しく位置合わせされ、境界内の有効な倍数のみをカウントします。 

i が g より小さい場合、または i ≡ 0 mod g の場合、剰余 0 を g にマッピングする正規化ステップにより、コリドー内で有効な代表が確実に選択されます。 これにより、剰余クラスの算術演算がドメイン内に存在しない位置 0 を示唆するような、off-by-one エラーが防止されます。
