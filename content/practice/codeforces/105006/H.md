 ## 解決策
 ## 問題の理解

 最大 20 個のノードを持つツリーが与えられ、各ノードは固定の美味しさの値を持つおやつを表します。 2 人のプレイヤーが何も残らないまで繰り返しノードを削除します。 各移動において、ボブはまず、残りのツリー内で現在葉になっている任意の 2 つのノードを選択します。 次に、チャーリーは 2 つのうちのどちらを食べるかを決め、ボブはもう 1 つを食べます。 両方が除去されると、それらの入射エッジが消え、構造は後の移動のために新しい葉を露出させる可能性があります。 

どちらのプレイヤーも完璧に最適です。 ボブは最終的に食べる美味しさの合計を最大化したいと考えていますが、チャーリーは自分自身の合計を最大化したいと考えています。チャーリーは常に提供された 2 枚の葉のうちより価値のある方を受け取るため、選択したペアごとにボブが得られる利益は間接的に最小化されます。 

ボブの観点からは、値 x と y を持つ葉のペアを選択すると、チャーリーは max(x, y) を取るため、その動きから保証されるゲインは min(x, y) になります。 ツリーの構造が重要なのは、それが各ステップでどのノードをペアにすることができるかを制限するためだけです。選択できるのは、現在残っている誘導サブグラフの葉だけです。 

ここで重要な信号は、制約 N ≤ 20 です。 N の指数関数的な状態空間は、おおよそ最大約 2^20 (約 100 万) まで許容されます。 すべての削除命令の順列を伴うものは大きすぎますが、サブセット動的計画法が現実的になります。 

単純な考え方による微妙な失敗例は、ボブが単純に世界的に最小の値を組み合わせたり、最も見栄えの良い組み合わせを貪欲に選択できると仮定した場合です。 ツリー制約により、値の低いリーフが強制的に早期に削除され、将来のリーフの可用性が変化する可能性があります。 

値 100、1、100、1 を持つ 1-2-3-4 のような単純なチェーンを考えてみましょう。最大のリーフの貪欲なペアリングでは、削除が将来のリーフにどのような影響を与えるかを考慮せずに (100,100) または (100,1) を繰り返し選択する可能性がありますが、リーフ ペアの実際の合法性は削除のたびに変化します。 

主な問題は、「リーフ」が静的プロパティではないことです。 最初はリーフではないノードも、後でリーフになる可能性があるため、どのようなソリューションでも、最初の次数だけでなく動的な構造変化を考慮する必要があります。 

## アプローチ

 ブルートフォース戦略では、有効な動きの考えられるすべてのシーケンスが試行されます。 各ステップで、現在のリーフを 2 つ選択し、そのようなすべてのペアで分岐し、削除を再帰的にシミュレートします。 ペアを選択した後、チャーリーが最適な選択をしたと仮定します。そのため、各ペア内でボブは小さい値のみを受け取ります。 

このアプローチはゲームを直接反映しているため、その正しさは明白です。 ただし、状態の数は、残りのノードのサブセットと、それらが削除される順序の両方によって決まります。 順番を無視しても(2n-1)あります!! 可能なペアがあり、動的に進化するリーフ制約により、分岐要素が爆発的に増加します。 n = 20 の場合、これは実行可能な計算をはるかに超えています。 

重要な点は、移動の順序は重要ではなく、残りのノードのセットのみが重要であるということです。 ノードのサブセットによって定義された状態になると、関連する情報は、次にどのリーフのペアを削除できるかということだけになります。 これにより、問題は、遷移によって一度に 2 つのノードが削除されるサブセット DP に変わります。 

ツリー構造は、現在のサブセットの誘導されたサブグラフ内のノードが葉であるかどうかをチェックすることによって暗黙的に処理されます。 これにより、サブセット表現を超えた一連の操作を明示的にシミュレートすることが回避されます。

 ## アルゴリズムのチュートリアル

 ノードの各サブセットを、残りのトリートのセットを表す状態として扱います。

1. 各状態をサイズ N のビットマスク S として表します。ここで、ビット i はノード i がまだ存在するかどうかを示します。 
2. 隣接関係をビットマスク形式で事前計算します。これにより、各ノード u について、サブセット S 内にまだ存在する u の近傍がいくつあるかを迅速に判断できます。これにより、アクティブな近傍が最大 1 つあるかどうかを確認することで、u が S のリーフであるかどうかを判断できます。 
3. DP[S] を、ボブが残りのセット S から開始してまだ得られる最大合計美味しさとして定義します。 
4. 各サブセット S について、すべての有効な手を考慮します。 移動は、S の誘導部分グラフの葉である 2 つの異なるノード u と v を選択することで構成されます。u と v を使用せずに次の状態 S' = S を計算し、ボブはこの移動から min(t[u], t[v]) を獲得します。 
5. このような有効なペアをすべて試し、DP[S'] + min(t[u], t[v]) の最大値を取ることで DP[S] を計算します。 基本ケースは DP[0] = 0 です。 
6. すべての遷移が、すでに計算されている大きなサブセットから小さなサブセットに進むように、サイズの大きい順にサブセットを反復処理します。 

重要な部分は葉のチェックです。 元のツリー内の隣接ノードの中で、最大でも 1 つの隣接ノードが S に存在する場合、そのノードはサブセット S のリーフです。ツリーの誘導されたサブグラフはフォレストのままであり、どのフォレストでもリーフは正確に次数 1 のノードであるため、この条件は十分です。 

### なぜ効果があるのか

 すべての有効なゲーム状態は、一連の正当な手の後に残る可能性のあるノードのサブセットに正確に対応します。 そのような状態からは、現在のリーフのペアのみが決定可能であり、そのようなすべてのペアは決定論的により小さい有効な状態につながります。 各移動によるボブのゲインは、選択したペアのみに依存し、将来のランダム性には依存しないため、最適な部分構造が成立します。つまり、S からの最良の結果は、到達可能なすべての S' からの最良の結果によって完全に決定されます。 これにより、サブセット上の DP が、到達可能な構成を見逃すことなく、考えられるすべての最適な再生シーケンスをキャプチャすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    
    adj = [0] * n
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    size = 1 << n
    dp = [0] * size

    # iterate by increasing subset size
    for mask in range(size):
        nodes = [i for i in range(n) if mask >> i & 1]
        m = len(nodes)
        if m < 2 or m % 2 == 1:
            continue

        # compute degree in induced subgraph
        deg = [0] * n
        for u in nodes:
            deg[u] = bin(adj[u] & mask).count("1")

        # find leaves
        leaves = [u for u in nodes if deg[u] <= 1]

        # try all leaf pairs
        for i in range(len(leaves)):
            for j in range(i + 1, len(leaves)):
                u = leaves[i]
                v = leaves[j]
                if u == v:
                    continue
                nxt = mask ^ (1 << u) ^ (1 << v)
                gain = min(t[u], t[v])
                dp[mask] = max(dp[mask], dp[nxt] + gain)

    print(dp[(1 << n) - 1])

if __name__ == "__main__":
    solve()
```この実装では、各サブセットをビットマスクとしてエンコードし、そのサブセット内のどのノードがリーフであるかを明示的に再構築することで遷移を計算します。 隣接関係はビットマスクとして保存されるため、次数を計算する際に交差を高速にカウントできます。 

DP はサブセットにわたってボトムアップで埋められます。 各状態について、有効なリーフのペアのみが考慮され、各遷移ではちょうど 2 つのノードが削除され、すでに評価されているより小さなサブセットに確実に移行します。 

よくある落とし穴は、誘導サブグラフの葉の代わりに元の木の葉を誤って使用することです。 そうなると違法な動きが許され、過度に楽観的な結果が生まれるだろう。 各サブセット内の次数の計算により、その間違いが回避されます。 

## 実用的な例

 ### サンプル 1

 最適なペアリングが動的な葉の形成に依存する小さな木でのプロセスを追跡します。 

各サブセットで、候補者の離脱と移行を追跡します。 

| マスクの状態 | 葉 | 選択されたペア | ゲイン | 次の状態 |
 | --- | --- | --- | --- | --- |
 | フルセット | {1,2,3,4} | (10,100) | 10 | 両方を削除する |
 | 削減 | {残り} | (1,2) | 1 | 空 |

 重要な動作は、最初のペアを削除した後に新しい葉が出現し、2 番目の最適なペアリングが可能になることです。 DP は両方のフェーズを独立して取得し、それらの寄与を組み合わせます。 

これは、2 番目の移動は最初の除去後に誘発された構造に完全に依存するため、部分的な貪欲ペアリングだけでは不十分であることを裏付けています。 

### サンプル 2

 この構成では、価値の高いノードが分離されるため、最適なプレイを行うには、後の状態まで一部のリーフへのアクセスを遅らせる必要があります。 

| マスクの状態 | 葉 | 選択されたペア | ゲイン | 次の状態 |
 | --- | --- | --- | --- | --- |
 | フルセット | {1,10,50,100} | (1,10) | 1 | 削減 |
 | 次へ | {50,100} | (50,100) | 50 | 空 |

 このトレースは、ボブが、後でより良い構造を維持するために、初期に低価値のリーフをペアにすることで利益を得ていることを示しています。 DP は両方のステージを正しく評価し、それらの寄与を合計します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^N · N^2) | 各サブセットはすべてのリーフ ペアを評価し、リーフ検出はサブセットごとに O(N) です。 
| スペース | O(2^N) | すべてのサブセットにわたる DP 配列 |

 N ≤ 20 の場合、2^20 は約 100 万の状態になります。 リーフセットは通常 N よりはるかに小さいため、二次係数は実際には十分に小さく、時間制限内で管理可能なペア チェックの有効数が維持されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、ツリーがパスに縮退する場合です。 パスでは、リーフ ペアは常に、現在残っているセグメントの終点になります。 誘発された次数が各サブセットのエンドポイントを正確に識別するため、DP はこれを自然に処理します。 

もう一つのケースはスターグラフです。 最初は中央だけが葉ではありませんが、葉をペアで削除した後、中央が孤立し、後の状態では葉として動作する可能性があります。 リーフ ステータスは静的であると想定されるのではなく、サブセットごとに再計算されるため、サブセット DP はこの遷移を正しくキャプチャします。 

最後のケースは、値がノード間で同一である場合です。 すべての有効なペアリングは同じゲインをもたらすため、DP は手の数をカウントすることになります。 min(a,b) はペア間で不変であり、すべての遷移が同等になり、DP は単純に均一な寄与を蓄積するため、このアルゴリズムは引き続き機能します。
