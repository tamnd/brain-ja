 ## 解決策
 ## 問題の理解

 円形の配置が与えられています$N$コーギー。 各コーギーは、1 色または 2 色の非常に小さな「カラー セット」を持ち、どちらも小文字で表されます。 円は、最初と最後のコーギーも隣接していることを意味します。 

この円をいくつかの連続したセグメントに分割する必要があります。 各セグメントは正確に 1 つのアダプターに割り当てられ、すべてのコーギーは正確に 1 つのセグメントに属している必要があります。 制約は、任意のセグメント内で、そのセグメントのすべてのコーギーに出現するすべての色を収集する場合、異なる色の合計数は最大 2 つでなければならないということです。 

目標は、必要なセグメントの数を最小限に抑えることです。 

問題は、セグメントが直線上ではなく円上で連続しているため、任意の点で円を「分割」して線形として扱うことができますが、その選択が最適な分割に影響することです。 したがって、問題の主な構造は、小さなカラー セットの結合に依存するローカル制約を伴う循環分割問題です。 

制約が十分に大きいため、$O(N^2)$またはセグメントを繰り返しスキャンするものは不可能です。 平$O(N \log N)$要素ごとに本質的に線形でない限り、大量の前処理を行うことは危険です。 これは、各コーギーが一定の回数処理される必要があり、セグメント境界が貪欲に計算されるか、または 2 ポインター構造を使用して計算される必要があることを強く示唆しています。 

微妙なエッジケースは円形の性質から生まれます。 開始点が固定されていると仮定する単純なソリューションは、最適なセグメンテーションが終了点を「ラップアラウンド」すると失敗します。 もう 1 つの注意が必要なケースは、長いセグメントが有効ではないように色が分散されている場合に発生し、特に各コーギーが既に 2 色を使用している場合に頻繁にカットを余儀なくされます。 

単純な線形スキャンが失敗する小さな例は次のとおりです。 

入力:```
4
ab ba ab ba
```インデックス 1 から開始して線形に処理すると、解析によってはセグメントを誤って拡張してしまう可能性がありますが、最適な解決策は円をどこで切り取るかを選択することで決まり、セグメントの数が変わる可能性があります。 

もう 1 つの特殊なケースは、すべてのコーギーが単一の色を共有する場合です。 この場合、円全体が 1 つのセグメントとなり、正しい解決策では、実装の選択による人為的な分割を回避する必要があります。 

## アプローチ

 ブルートフォース手法では、円を有効なセグメントに分割するためにあらゆる方法が試行されます。 円内の開始カットの考えられる選択肢ごとに、配列を平坦化し、それを貪欲にまたは再帰的に有効なセグメントに分割し、色の結合を最初から再計算することで各セグメントの色の制約をチェックします。 

単一の開始位置の場合、実行中の色のセットを維持したとしても、拡張または検証の各ステップでは依然として最大の管理が必要になります。$N$要素。 すべての開始位置を試してみると、$O(N^2)$動作が変化し、パーティションに対するより深い検索はすぐに指数関数的に増加します。 と$N$まで$10^6$、これはまったく不可能です。 

重要な観察は、各セグメントが個別の色の数によってのみ制約され、各要素が寄与する色は最大 2 つであることです。 これは、セグメントを拡張するときに、個別の色の数が制御された方法でのみ増加または減少し、正しい境界を維持していれば、以前の決定を再検討する必要がないことを意味します。 

2 番目の重要な洞察は、円の開始点を固定する代わりに、開始カットを固定し、線形時間で必要なセグメントの数を計算できるということです。 円は対称であるため、配列を複製し、長さ方向のスライディング ウィンドウ手法を使用して、考えられるすべての開始点をシミュレートできます。$N$、ラップアラウンド処理により、循環問題を線形問題に効果的に変換します。 

開始位置ごとに、2 ポインター手法を使用してセグメントを貪欲に拡張します。つまり、現在のセグメント内の色の周波数マップを維持し、それが 2 つの異なる色を超えないようにします。 コーギーの追加が制約に違反する場合は常に、新しいセグメントを開始します。 

各開始オフセットに必要なセグメントの数を計算し、最小値を取得します。 

これが機能するのは、固定開始の貪欲なセグメンテーションが最適であるためです。セグメントが 2 色を超えると、それ以上拡張できなくなり、カットを遅らせても色が追加されるだけなので役に立ちません。

 ## アルゴリズムのチュートリアル

 まず、各コーギーをその色の小さな表現に変換します。 それぞれに最大 2 文字が含まれるため、小さなセットとして扱うことができます。 

次に、循環性を処理するためにシーケンスを複製しますが、長さのウィンドウのみを考慮します。$N$。 

1. 開始インデックスを修正する$s$から$0$に$N-1$。 これは、円を「カット」する場所を表します。 

セグメンテーションは円が線形化される場所に依存するため、開始点の選択が必要です。 
2. ポインタを初期化する$i = s$、セグメント数 = 1、および現在のセグメント内の色の空の周波数構造。 

周波数構造は、現在アクティブな個別の色の数を追跡します。 
3. セグメントを前方に伸ばしながら、$i < s + N$。 それぞれのコーギーの位置について$i$、その色を現在の構造に追加します。 

制約はセグメント全体にわたってグローバルであるため、個々のコーギーではなく、個別の色を明示的に追跡します。 
4. 現在のコーギーを追加することで異なる色の数が 2 を超える場合、現在のセグメントを次の位置で閉じます。$i-1$、セグメント数を増分し、次から始まる新しいセグメントを再開します。$i$。 

これは正しいです。なぜなら、以降で終わる有効なセグメントは存在するからです。$i$このモデルでは個別の色の単調増加により、すでに制約に違反しています。 
5. ウィンドウ全体が覆われるまで続けます。 
6. この開始点に必要なセグメントの数を記録します。 
7. すべての開始点の最小値を返します。 

最後の最適化は、文字が 26 個しかないため、色を圧縮するか固定配列を使用する場合、実際には完全な周波数マップは必要ないということです。 

### なぜ効果があるのか

 開始位置が固定されている場合、各セグメントは制約に違反することなく可能な限り拡張されるため、貪欲な手順では最小数のセグメントが生成されます。 セグメントが必要よりも早く切断された場合、将来の要素は変更されず、失われた容量を補うことができないため、セグメントの総数が増えるだけです。 この制約は色の結合のみに依存するため、3 番目の異なる色が出現すると、現在のセグメントを拡張しても有効性を回復できなくなります。 

すべての開始位置にわたって、そのうちの 1 つが円の最適なカットと一致し、線形化の間で全体的な最適値を確実に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_corgi(s):
    return list(set(s.strip()))

def solve():
    n = int(input().strip())
    arr = [parse_corgi(input()) for _ in range(n)]

    # duplicate for circular handling
    arr = arr + arr

    best = n

    for start in range(n):
        cnt = 0
        color_count = [0] * 26
        distinct = 0
        i = start
        end = start + n

        while i < end:
            # try to extend segment
            ok = True
            temp_colors = arr[i]

            # check if adding would exceed constraint
            new_additions = 0
            for c in temp_colors:
                idx = ord(c) - 97
                if color_count[idx] == 0:
                    new_additions += 1

            if distinct + new_additions <= 2:
                for c in temp_colors:
                    idx = ord(c) - 97
                    if color_count[idx] == 0:
                        color_count[idx] = 1
                        distinct += 1
                i += 1
            else:
                # cut here
                cnt += 1
                color_count = [0] * 26
                distinct = 0

        best = min(best, cnt)

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、コーギー内の重複がセグメント ロジックに影響を与えないように、各コーギーを最大 2 文字の一意のセットに前処理します。 ラップアラウンドを適切に処理するために配列が複製され、各開始位置が個別にテストされます。 

重要な点は、セグメントがカットされたときに色の状態をリセットすることです。 このリセットが正しく行われない場合、前のセグメントの色が誤って引き継がれ、セグメントの数が人為的に減少します。 

コーギーの追加が 2 つの異なる色を超えているかどうかのチェックは、新しい色の数を数えることによって行われます。 これにより、セットの共用体を繰り返し再計算することが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのコーギーがまったく同じ単一の色を含む場合です。 この状況では、個別の色の数が 1 を超えることはないため、貪欲なプロセスによってカットがトリガーされることはありません。 このアルゴリズムは、単一のアクティブな色を維持し、セグメントを全長まで拡張して、1 つのセグメントを正しく生成します。 

別の特殊なケースは、すべてのコーギーがすでに 2 つの異なる色を含んでおり、それらのペアが隣接するコーギー間で互いに素である場合に発生します。 この場合、セグメントを拡張しようとするたびにすぐに 3 番目の色が導入され、ほぼすべての位置でセグメンテーションが強制されます。 このアルゴリズムは、3 番目の色が表示されるとすぐにカットをトリガーすることでこれを処理し、互換性のないノードを誤ってマージするのではなく、多くの短いセグメントを生成します。 

最後のエッジ ケースは循環ラップアラウンドで、最適なセグメンテーションを行うには均質なブロックの中央から開始する必要があります。 配列の複製により、考えられるすべてのカット位置が線形開始としてシミュレートされるため、アルゴリズムは全体的に最適な配置を見逃すことはありません。
