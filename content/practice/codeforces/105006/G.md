 ## 解決策
 ## 問題の理解

 私たちは、左下隅から連続した 2D 平面として扱うことができる長方形の公園内で作業しています。$(0,0)$右上隅に$(N,M)$。 コーギーは次から始まります$(0,0)$そして到達したい$(N,M)$。 コーギーはどの方向にも自由に動き続けることができますが、家族を中心とした円形の「危険ゾーン」が存在します。 コーギーがこれらのサークルのいずれかに入ると、すぐに捕らえられます。 

家族全員を使用する必要はありません。 代わりに、アクティブ化するサブセットを選択することもできます。 有効化されたサークルのみが重要です。 目標は、コーギーが連続した経路を持たないように、できるだけ少ない円を選択することです。$(0,0)$に$(N,M)$選択したすべての円を回避します。 

したがって、本当の問題は、グリッド上で段階的に移動することではありません。 これはジオメトリに関するものです。長方形の対向する 2 つの角の間の可能な連続パスがすべてブロックされるように、最小数のディスクを選択しています。 

制約は、幾何学的な縮小が必要な理由を示しています。 座標は次のようになります$10^9$したがって、平面をグリッドに離散化することはできません。 サークルの数$K$せいぜい$10^3$を強く示唆しています。$O(K^2)$または$O(K^2 \log K)$グラフベースのソリューションを目的としています。 平面内のパスの列挙や幾何学的サンプリングを伴うものはすべて不可能です。 

ローカルで考えると微妙な失敗例が出てきます。 「半径が最も大きい円を最初に選択する」などの欲張りな考えは機能しません。ボードの中央にある大きな円は無関係である可能性があり、一方、境界近くにある小さな重なり合う円の連鎖が脱出を完全にブロックする可能性があるからです。 

もう 1 つの落とし穴は、単一の円が開始と終了を独立して分離できると想定していることです。 円は、長方形の一方の辺から反対側まで広がる接続されたバリアに接続するか、接続するバリアに寄与する場合にのみ役立ちます。 孤立するだけでは十分ではありません。 接続性が重要です。 

## アプローチ

 重要な変化は、コーギーの動きについて考えるのをやめ、代わりに、考えられるすべての経路を遮断することが何を意味するかを考えることです。 平面トポロジでは、一連の障害物が脱出を妨げるのは、開始コーナーと終了コーナーを隔てる連続的な障壁が形成される場合のみです。 

各円は障害物領域です。 一連のサークルをアクティブにすると、コーギーはその結合に入ることが禁止されます。 これらの禁断の領域が境界線に接し、分離するような接続構造を形成するとき、まさに脱出は不可能になります。$(0,0)$から$(N,M)$。 

これにより、問題がグラフの構築に変わります。 それぞれの円がノードになります。 2 つのノードの円が重なり合うか接触する場合、重なり合う円は連続した障害物コンポーネントのように機能するため、接続されています。 境界もモデル化する必要があります。 左または下の境界に触れる円は、開始側からのアクセスをブロックする原因となる可能性があります。 同様に、上部または右側の境界に接する円は、出口側へのアクセスをブロックする原因となる可能性があります。 

2 つの仮想ノードを紹介します。 1 つは「開始側」(下と左の境界領域) を表し、もう 1 つは「終了側」(上と右の境界領域) を表します。 開始境界と交差するすべての円は開始ノードに接続され、終了境界と交差するすべての円は終了ノードに接続されます。 

ここで問題は、このグラフの開始ノードと終了ノードを接続するために必要な円の最小数を見つけることです。 各円を選択するとコストが 1 になるため、これは重み付けされていないグラフ上の最短経路の問題になります。 

ブルートフォースアプローチでは、円のすべてのサブセットを試し、連続平面内のすべてのパスをブロックしているかどうかを確認し、サイズを最小化します。 これは指数関数的です$K$、 だいたい$O(2^K)$, も不可能になります。$K=40$。 

グラフの洞察により、問題が最短経路に短縮されます。$K+2$ノード、$O(K^2)$エッジ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサブセットを試してみる |$O(2^K \cdot K)$|$O(K)$| 遅すぎる |
 | グラフ + 最短経路 |$O(K^2)$|$O(K^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ファミリー メンバーをグラフ内のノードとして扱います。 2 つのノードの円が重なるか接触する場合、つまり中心間の距離が半径の合計以下である場合、それらのノードは接続されています。 これは、コーギーが重なり合う危険ゾーンの間を滑ることはできないという考えを捉えています。 
2. 2 つの特別なノードを追加します。1 つは下と左の境界の結合を表す開始ノード、もう 1 つは上と右の境界の結合を表す終了ノードです。 
3. 円盤が下端のいずれかと交差する場合、円ノードを開始ノードに接続します。$y=0$または左端$x=0$。 これは、そのようなサークルがオリジン側からのアクセスをブロックできることをモデル化しています。 
4. 円盤が上端のいずれかと交差する場合、円ノードを終端ノードに接続します。$y=M$または右端$x=N$。 これは、そのような円が出口領域のブロックに寄与する可能性があることをモデル化します。 
5. すべてのエッジが重み 1 を持つ開始ノードから終了ノードまでの最短パス アルゴリズムを実行します。最短距離は、連続したブロック構造を形成するために必要な円の最小数に対応します。 
6. エンドノードに到達できない場合、出力$-1$。 それ以外の場合は最短距離を出力します。 

重要な考え方は、有効なブロッキング構成には、境界分離を橋渡しする接続された円のチェーンが含まれている必要があるということです。 このようなチェーンがグラフに存在しない場合、サブセットは連続した幾何学的バリアを形成できません。 

### なぜ効果があるのか

 有効な解は、両方の境界領域に接する、選択された円の接続されたコンポーネントに対応します。 障害物が切断されると、連続したパスを利用できるギャップが残るため、接続性は不可欠です。 逆に、グラフ内の最初から最後までのパスは、連続したバリアを形成する一連の重なり合う円を表しており、それらの円を正確に選択することで分離が保証されます。 すべての円のコストは等しいため、最適なバリアはそのようなチェーンの中で最も短いものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N, M, K = map(int, input().split())
    
    x = []
    y = []
    r = []
    
    for _ in range(K):
        xi, yi, ri = map(int, input().split())
        x.append(xi)
        y.append(yi)
        r.append(ri)

    S = K
    T = K + 1

    adj = [[] for _ in range(K + 2)]

    def touch_boundary(i):
        xi, yi, ri = x[i], y[i], r[i]
        if xi - ri <= 0 or yi - ri <= 0:
            adj[S].append(i)
            adj[i].append(S)
        if xi + ri >= N or yi + ri >= M:
            adj[T].append(i)
            adj[i].append(T)

    for i in range(K):
        touch_boundary(i)

    for i in range(K):
        for j in range(i + 1, K):
            dx = x[i] - x[j]
            dy = y[i] - y[j]
            rr = r[i] + r[j]
            if dx * dx + dy * dy <= rr * rr:
                adj[i].append(j)
                adj[j].append(i)

    dist = [-1] * (K + 2)
    dist[S] = 0
    q = deque([S])

    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    print(dist[T])

if __name__ == "__main__":
    solve()
```コードはまず、隣接リストを使用して明示的にグラフを構築します。 境界接続は、円が長方形のいずれかの辺と交差するかどうかをチェックすることによって計算されます。 浮動小数点演算を回避するために、標準の二乗距離テストを使用して円間のエッジが追加されます。 

すべてのエッジがもう 1 つの円の選択を表すため、ダイクストラの代わりに BFS が使用され、すべてのエッジの重みが等しくなります。 距離配列は、チェーン内で使用される円の数を直接カウントします。 

微妙な点の 1 つは、コーギーの実際の動きについて推論しようとしていないことです。 このグラフでは、幾何学的複雑さ全体が接続性に吸収されているため、大きな座標でもソリューションの効率性が維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(K^2)$| ペアごとの円交差チェックが優勢で、BFS は線形です。 
| スペース |$O(K^2)$| 隣接リストにはすべての重複が格納されます。 

と$K \le 1000$、$K^2 = 10^6$操作は十分に制限内にあり、メモリ使用量は管理可能なままです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import deque

    def solve():
        N, M, K = map(int, input().split())
        x = []
        y = []
        r = []
        for _ in range(K):
            xi, yi, ri = map(int, input().split())
            x.append(xi)
            y.append(yi)
            r.append(ri)

        S, T = K, K + 1
        adj = [[] for _ in range(K + 2)]

        def touch(i):
            if x[i] - r[i] <= 0 or y[i] - r[i] <= 0:
                adj[S].append(i); adj[i].append(S)
            if x[i] + r[i] >= N or y[i] + r[i] >= M:
                adj[T].append(i); adj[i].append(T)

        for i in range(K):
            touch(i)

        for i in range(K):
            for j in range(i + 1, K):
                dx = x[i] - x[j]
                dy = y[i] - y[j]
                rr = r[i] + r[j]
                if dx*dx + dy*dy <= rr*rr:
                    adj[i].append(j)
                    adj[j].append(i)

        dist = [-1]*(K+2)
        dist[S] = 0
        q = deque([S])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        return str(dist[T])

    return solve()

 ## 特殊なケース

 円がバリアを形成しているように見えるだけで、接続されていない場合、厄介な状況が発生します。 たとえば、2 つの大きな円は両方とも長方形の反対側に接していますが、重なり合うことはありません。 その場合、コーギーはそれらの間の隙間をすり抜けてしまう可能性があり、正解は 2 ではありません。これら 2 つのノード間にパスがないため、グラフ モデルがこれを処理します。そのため、BFS は接続された開始から終了までのチェーンを形成できません。 

もう 1 つのエッジ ケースは、開始境界領域と終了境界領域の両方に同時に触れる円です。 これは、大きな円が長方形全体にまたがる場合に発生します。 グラフは単一のノードを介して開始と終了を即座に接続し、他の推論を必要とせずに答え 1 を生成します。 

最後の微妙なケースは、1 つの境界にのみ接触する円が、別の境界に接触する円につながるチェーンを形成する場合です。 BFS はパスに沿って選択された円の数を蓄積し、完全に接続されたバリア構造のみが答えに寄与することを保証するため、アルゴリズムはチェーン全体を正確にカウントします。
