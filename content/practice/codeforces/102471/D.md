 ## 解決策
 ## 問題の理解

 頂点 1 でツリーをルートします。パンはルートから開始し、最終的にはすべての頂点で正確に 1 回魔法を唱える必要があります。 すべての有向エッジは最大 1 回しか使用できないため、サブツリーに入り、その後その親を経由して退出するサブツリーの移動コストは完全に決定されます。`s`頂点を通過し、頂点を正確に使用するエントリに戻ります`2s`動く。 唯一の自由は、兄弟サブツリーが処理される順序と、どのサブツリーにウォーク全体の最終頂点が含まれるかです。 

させて`a[v]`頂点の温度になります`v`1日目朝直前。パンが頂点で魔法を発動した場合`v`当日`t`、イブニングマジック後の気温は`a[v] - t + k`。 彼がその日に出発する場合`d`、その日の朝`d`はすでにその温度を適切な日数だけ下げているため、ソース頂点は厳密に正である必要があります。 宛先は非負である必要があります。 これら 2 つの異なる不等式は、いくつかの境界ケースの原因となります。 

出力は、パンが頂点 1 で準備できる最も遅い日です。これは、パンがその日に頂点 1 で魔法を唱え、翌日に最初の動きを行うことを意味します。 0日目でも機能しない場合、答えは次のとおりです。`-1`。 

バウンド`n <= 100000`特に制限時間は 1 秒しかないため、二次関数は除外されます。 ツリー全体の走査はすでに線形であるため、ターゲットは本質的に`O(n)`または`O(n log n)`。 気温と`k`到達できる価値観`10^9`、サブツリーのサイズは次の範囲に達する可能性がありますが、`10^5`, したがって、次のような中間表現`k + a[v] - 2 * size[v]`固定幅整数を使用する言語では、64 ビット算術で処理する必要があります。 Python の整数には任意の精度があるため、実装ではオーバーフローの問題は発生しません。 

1 つの境界ケースは、目的地の温度が正確にゼロになる可能性があることです。 次の 2 頂点ツリーを考えてみましょう。`k = 0`と温度`2 1`。```
2 0
1 2
2 1
```答えは、`0`。 Pang は 0 日目に頂点 1 にキャストし、1 日目に移動して、温度 0 の頂点 2 に到着します。 宛先の温度が正であることを要求する不注意な実装では、このケースが誤って拒否されてしまいます。 

ソース頂点には逆の条件があり、厳密に正である必要があります。 同じ木と`k = 0`、根元温度を次のように変更します。`1`。```
2 0
1 2
1 1
```答えは、`-1`。 0 日目にキャストした後、根の温度は 1 になりますが、1 日目の朝には温度が 0 に下がるため、Pang は移動できません。 宛先温度のみをチェックすると、この失敗を見逃します。 

兄弟サブツリーの順序も重要です。 考慮する```
5 2
1 2
1 3
1 4
4 5
100 1 100 100 100
```正しい答えは、`93`。 頂点 2 には非常に厳しい期限があるため、頂点 4 をルートとする大きなサブツリーよりも前にそのサブツリーにアクセスする必要があります。入力順序で子を処理すると、大きなサブツリーが最初に配置され、頂点 2 に時間内に到達できなくなる可能性があります。 隣接リストの順序で DFS を試行するだけのソリューションでは、有効なスケジュールが存在していても失敗する可能性があります。 

最後に、0 日は気温が下がらないため特別です。 のために```
2 2
1 2
0 1
```答えは`0`。 Pang は、0 日目に頂点 1 で魔法を唱えて温度を 0 から 2 に上げ、1 日目に頂点 2 に移動します。その朝の温度はちょうど 0 です。 最初の気温低下がすでに起こったかのように 0 日目を扱うと、この有効な解決策が失われます。 

## アプローチ

 直接的なアプローチでは、木の中を通る可能性のある歩き方を列挙します。 ツリーがルート化されると、最終ではないすべての子サブツリーに入り、完全に探索され、そこから返される必要があります。 最後のサブツリーは、リターンを必要としない唯一のものです。 子どもたちに可能な限りの注文をするために、移動や魔法の操作の前に体温をチェックしながら、その日をシミュレーションすることができました。 

これは正しいです。なぜなら、すべての合法的なウォークにはまさにこの再帰構造があるからです。 問題は注文数です。 スターと`n - 1`葉はすでに持っています`(n - 1)!`可能な注文、および各注文のシミュレーションには時間がかかります`Theta(n)`動く。 したがって、最悪の作業は次のとおりです。`Theta(n * (n - 1)!)`、私たちが到着するずっと前に`n = 100000`。 

ツリーがすべての完成したサブツリーを単一のエクスカーションのように動作させるため、ブルート フォースが機能します。 重要な観察は、このようなエクスカーションの継続時間が固定であり、サブツリー内の頂点の数のちょうど 2 倍であるということです。 子サブツリーが入力される最後の日までに要約されると、親は期限前にこれらの固定期間のエクスカーションをスケジュールするだけで済みます。 

の子供たちを仮定します`u`として注文されます`v_1, v_2, ..., v_d`。 パンがキャストした場合`u`当日`t`、それから子供`v_i`当日に入力されます

 [
 t + 1 + 2\sum_{j<i} サイズ[v_j]。 
]

もし`f[v_i]`は、往復の最終有効到着日です。`v_i`、必要です

 [
 t + 1 + 2\sum_{j<i} サイズ[v_j] \le f[v_i]。 
]

 並べ替えると

 [
 t \le f[v_i]-1-2\sum_{j<i}size[v_j]。 
]

 これはスケジュールの問題です。 各子には処理時間があります`2 * size[v]`、その有効期限は`f[v] + 2 * size[v]`。 この値で子を並べ替えると、最適な順序が得られます。 これは、この問題の公式スタイルのソリューション ノートで説明されている順序と同じです。 

もう 1 つ複雑な問題があります。 ウォーク全体を頂点 1 に戻す必要はありません。実際、リーフで終了する必要があります。 したがって、親に戻らずに最後の子サブツリーを通過できるようにする 2 番目の DP 状態が必要です。 最後の子の前の子も、同じ最適な順序でスケジュールする必要があります。 

1 つの固定された最後の子の場合、順序付きリストからその子を削除しても、その後の子のプレフィックス時間のみが変更されます。 プレフィックスとサフィックスの最小値を使用すると、可能な最終的な子ごとに、残りすべての子の最適な期限を一定時間で計算できます。 したがって、子をソートした後、1 つの頂点の遷移全体は次数が線形になります。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`Theta(n * (n - 1)!)`星の中で |`O(n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

### なぜ効果があるのか

 中心的な不変条件は次のとおりです`f[u]`まさに、完全に処理されたトラバースの実行可能な最新のキャスト日です。`u`のサブツリーを展開してその親に戻りますが、`g[u]`これは、サブツリー内のどこででもトラバースが終了する可能性がある、実行可能な最新のキャスト日です。 のために`f[u]`、すべての子エクスカーションには固定期間と許可される最新の開始時刻があるため、誤って順序付けされた 2 つの隣接する子を交換すると、次の順序で並べ替えられることがわかります。`f[v] + 2size[v]`が最適です。 のために`g[u]`、すべての有効な走査には、最後の子が 1 つだけあります。 他のすべての子は完全なエクスカーションを形成し、同じ最適な順序でスケジュールを設定できます。 プレフィックスとサフィックスの最小値は、最後の子が削除された後、それらのエクスカーションの制約を正確に計算します。 考えられるすべての最終的な子が考慮されるため、`g[u]`最善の有効な選択を採用します。 ルートでは、すべての完全なウォークは、そのような最終子の選択の 1 つに対応します。`g[1]`は、まさに可能な限り最も遅い準備日です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        graph[x].append(y)
        graph[y].append(x)

    a = list(map(int, input().split()))

    parent = [-2] * n
    parent[0] = -1

    order = [0]
    for u in order:
        for v in graph[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    size = [1] * n
    f = [0] * n
    g = [0] * n

    INF = 10**30

    for u in reversed(order):
        children = [v for v in graph[u] if parent[v] == u]

        if not children:
            size[u] = 1
            f[u] = min(a[u], a[u] + k - 2)
            g[u] = a[u]
            continue

        size[u] = 1 + sum(size[v] for v in children)

        children.sort(key=lambda v: f[v] + 2 * size[v])

        m = len(children)

        deadline = [0] * m
        prefix = [INF] * (m + 1)

        used = 0
        for i, v in enumerate(children):
            deadline[i] = f[v] - 1 - 2 * used
            prefix[i + 1] = min(prefix[i], deadline[i])
            used += size[v]

        suffix = [INF] * (m + 1)
        for i in range(m - 1, -1, -1):
            suffix[i] = min(suffix[i + 1], deadline[i])

        f[u] = min(
            a[u],
            a[u] + k - 2 * size[u],
            prefix[m]
        )

        total_children_size = size[u] - 1
        best = -INF

        for i, v in enumerate(children):
            sv = size[v]

            # Remove v from the child order.
            # Children before v keep their original prefix.
            # Children after v start 2 * sv days earlier.
            side_deadline = min(
                prefix[i],
                suffix[i + 1] + 2 * sv
            )

            remaining_size = total_children_size - sv

            candidate = min(
                a[u],
                a[u] + k - 2 - 2 * remaining_size,
                g[v] - 1 - 2 * remaining_size,
                side_deadline
            )

            best = max(best, candidate)

        g[u] = best

    answer = g[0]
    print(answer if answer >= 0 else -1)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、ツリーを繰り返しルート化します。 再帰は回避されます。`100000`頂点は単一のチェーンにすることができますが、これは Python の通常の再帰制限を超えるほど深いものです。 

逆走査順序では、リーフからルートに向かって DP が計算されます。 の`size`配列は、完全な子エクスカーションの期間中と、すべての子孫が処理された後の頂点での温度制約の両方に必要です。 

頂点ごとに、子は次の基準で並べ替えられます。`f[v] + 2 * size[v]`。 の`deadline`配列には、キャスト日の正確な境界が格納されます。`u`子どもたち一人ひとりが貢献してくれました。 の`prefix`配列は、選択された最後の子の前の子間の最小期限を示します。`suffix`その後の子の中で最小値を与えます。 

表現`suffix[i + 1] + 2 * sv`間違いやすいです。 お子様以降`v`が削除され、その後の子がすべて開始されます`2 * size[v]`そのため、その制約はちょうどその分だけ緩和されます。 このため、サフィックス値は減らすのではなく増やす必要があります。 

間の区別`-1`そしてゼロも意図的です。 DP 状態は、親を基準とした最新の実行可能なキャスト日を表すため、負になる場合があります。 ただし、ルートでは、負でない日のみが使用可能です。 したがって`g[0] == 0`は有効ですが、`g[0] < 0`インスタンスが不可能であることを意味します。 

すべての算術演算は Python 整数を使用して直接行われます。 を含む表現`2 * size[u]`そして`k`32 ビット範囲を超える可能性があるため、固定幅の実装では次を使用する必要があります。`long long`。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n log n)`| すべての頂点の子がソートされ、ソートの総コストは最大で`O(n log n)`|
 | スペース |`O(n)`| ツリー、親/順序配列、サブツリー サイズ、および DP 状態はすべて線形です。 

木にはせいぜい`100000`頂点なので、`O(n log n)`意図した漸近範囲内に簡単に収まります。 この実装では、再帰的 DFS も回避されます。これは、最悪の場合のチェーンに役立ちます。 一時的なプレフィックス、サフィックス、デッドライン配列には、現在処理されている頂点の子のみが含まれるため、それらの合計保持メモリは線形のままです。

 ## 特殊なケース

 宛先温度がゼロの場合は、子到着不等式によって処理されます。`t + 1 <= g[c]`。 到着後の余分な減算はありませんので、正確にゼロの温度が受け入れられます。 温度のある 2 つの頂点の場合`2 1`そして`k = 0`、ルートは 0 日目にキャストし、1 日目に移動して、温度 0 の 2 番目の頂点に到着します。 アルゴリズムは計算します`g[2] = 1`、ルート遷移は次のようになります`g[1] = 0`、それで印刷されます`0`。 

厳密なソース条件は、`a[u] + k - 2`リーフの項と、内部頂点の対応する出発項。 と`n = 2`、`k = 0`、および温度`1 1`、根は 0 日目にキャストできますが、1 日目の朝以降は温度が 0 になります。この遷移により、`g[1] = -1`、不可能を正しく報告します。
