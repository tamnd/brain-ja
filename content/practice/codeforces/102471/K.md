 ## 解決策
 ## 問題の理解

 グラフは、頂点に周期的に番号が付けられた凸多角形の内側に描画されます。 すべてのポリゴンの辺が存在し、追加の対角線を追加できますが、共通の端点を除いて対角線が交差することはありません。 各エッジには非負の容量があります。 

すべての頂点のペア (s,t) について、(s)-(t) の最大流量の値が必要です。これは、(s)-(t) カットの最小容量と同じです。 必要な出力は、すべての順序付けされていない頂点ペアにわたるこれらの値の合計、縮小法 (998244353) です。 元の問題には (n\le 200000) と (m\le 400000) があり、すべてのポリゴン辺が存在します。 

この制約により、すべてのペアに対して独立して何かを行うことは直ちに禁止されます。 あります

 [
 \frac{n(n-1)}2
 】

 これは、(n=200000) の場合、ほぼ (2\cdot 10^{10}) のペアになります。 ペアごとに (O(m)) 時間しかかからない操作でも、すでにおよそ (8\cdot10^{15}) 個のエッジ検査が必要になります。 実際の最大流量アルゴリズムは、単にエッジをスキャンするよりも大幅にコストがかかるため、ソリューションでは平面構造をグローバルに利用する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 最小のグラフは三角形です。 容量1の3つのエッジで、```
3 3
1 2 1
2 3 1
3 1 1
```答えは`6`、 ない`3`。 直接エッジと 2 エッジ代替パスの両方がフローを搬送できるため、すべてのペアには 2 つのフロー単位があります。 

容量ゼロも合法です。 のために```
3 3
1 2 0
2 3 1
3 1 2
```答えは`4`。 ゼロ容量エッジでは、すべてのペアが切断されるわけではありません。 たとえば、頂点 (1) に付随する 2 つのエッジで構成されるカットには容量 (2) があるため、頂点 (1) と (3) の間の最大フローは依然として (2) です。 

容量が大きい場合は、最終的な係数を取得する前に 64 ビット演算が必要です。 のために```
3 3
1 2 1000000000
2 3 1000000000
3 1 1000000000
```すべてのペアにはフロー (2000000000) があるため、変更されていない答えは (6000000000) になります。 必要な出力は次のとおりです`10533882`。 

最後に、平面構造を構築する際、エッジ ((1,n)) には特別な処理が必要です。 これは頂点番号付けの循環境界を横切るため、このエッジを分離せずにすべてのエッジを単に間隔 ([u,v]) として扱うと、誤った入れ子構造が発生します。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 すべてのペア (s,t) に対して、最大フロー アルゴリズムを実行し、その結果を答えに追加します。 最大フロー最小カット定理によれば、これは正しいですが、(n(n-1)/2) 回の呼び出しがあります。 (n=200000) では、正確に (19999900000) の最大フロー計算になります。 たとえすべての計算に魔法のように (O(m)) しかかからなかったとしても、合計は約 (8\cdot10^{15}) 個の基本的なエッジ検査になります。 本物の最大流量計算では、状況はさらに悪化します。 

有用な観察は平面埋め込みから得られます。 現在非有界領域の境界上にあるエッジ (e) を考え、そのようなすべての境界エッジの中で最小の容量を持っていると仮定します。 (C) を (e) を含む最小のサイクルとする。 (e) を削除し、その容量を (C) の他のすべてのエッジに追加して、すべてのペアごとの最小カットを保存できます。 これは、問題に使用される中心の縮小です。 

なぜこれが機能するのでしょうか? 平面グラフでは、境界のない面が 2 つの終点で分割された後、2 つの頂点間のカットは平面双対のパスによって表現できます。 境界領域を囲むサイクル (C) は、このような二重パスによって 1 回だけ交差することはできません。 最適なカットが (C) と相互作用する場合、(e) と (C) の他の 1 つのエッジを使用して表すことができます。 (e) は現在露出されている最も安価な境界エッジであるため、露出された交差を (e) で置き換えてもカット値は増加しません。 

(e)の現在の容量を(w)とする。 (e) を削除すると、(e) を使用するカットが (-w) によって変更されます。 (w) を (C) の 1 つおきのエッジに追加すると、カットで (C) の別のエッジが使用されるたびに正確に補正されます。 (C)を回避するカットは変更されません。 逆に、必要に応じて、変更されたグラフ内の任意のカットを (e) で拡張して、元のグラフ内の値がそれ以下のカットを取得することができます。 したがって、すべてのペアごとの最小カットは変更されません。 

(n-1) 個のエッジだけが残るまでこの操作を繰り返すことができます。 この場合、グラフはツリーとなり、2 つの頂点間の最大フローは、単にそれらの一意のパス上の最小エッジ容量になります。 元の全ペア問題は、ツリーのボトルネック問題に縮小されました。 

残りの課題は、適切なサイクルを効率的に見つけることです。 直接シミュレーションでは、平面グラフの変化する外側境界を維持する必要があります。 より明確な表現には、交差しない対角線から派生したツリーが使用されます。 対角線は、左端点を減少させ、右端点を増加させることによって並べ替えられます。 現在の境界を表す順序付けられた構造により、どの前のエッジが各対角線によって作成された新しい面に属しているかがわかります。 これにより、(m+1) 個のノードを持つツリーが生成されます。ここで、元の各グラフ エッジが 1 つのツリー エッジに対応します。 

以下の実装では、順序付きマップの代わりにフェンウィック ツリーを使用します。 アクティブな境界部分は、ポリゴンの位置ごとに保存されます。 対角線 ((l,r)) の場合、([l,r)) 内のすべてのアクティブな位置がその対角線の子になり、対角線は位置 (l) に挿入されます。 すべてのアクティブなポジションは子になるときにのみ削除されるため、そのような削除の合計数は線形です。 フェンウィックの各操作には (O(\log n)) のコストがかかります。 

この補助ツリーが存在すると、そのリーフを利用可能な最小の容量から順に処理します。 面が露出すると、その選択されたエッジが削除され、その容量が他の入射エッジに伝播されます。 優先キューは次の候補エッジを維持します。 すべての補助ツリー エッジがキューに入るのは最大 1 回であるため、総処理コストは (O(m\log m)) になります。 これは、この問題に対する標準的な解決策で説明されているのと同じ削減です。

最後に、残った (n-1) 個の元のエッジがツリーを形成します。 変換された容量によって降順に並べ替えます。 最初は、すべての元の頂点は別個の DSU コンポーネントです。 重み (w) のエッジがサイズ (a) と (b) のコンポーネントを結合すると、正確に (ab) の頂点ペアがしきい値 (w) で初めて接続されるため、(w\cdot a\cdot b) が答えに追加されます。 これは、通常のクラスカルのボトルネックカウント引数の降順バージョンです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 少なくとも (O(n^2m)) 個のエッジ検査、実際の最大流量ではさらに多くの検査 | (O(n+m)) | 遅すぎる |
 | 最適 | (O(m\log m+n\log n)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、ポリゴンの辺を対角線から分離します。 すべての辺 ((i,i+1)) はその位置 (i) で表され、特別な辺 ((1,n)) は位置 (n) で表されます。 1 つおきのエッジは対角線 ((l,r)) であり、(l<r) です。 
2. すべての対角線を減少 (l) してソートし、増加 (r) で同点を解消します。 この順序は、交差しない対角線の入れ子構造に従います。 後の対角線は、その間隔内にある現在露出している境界部分とのみ対話できます。 
3. 現在露出されているポリゴン位置ごとに 1 つのアクティブ エッジを維持します。 フェンウィック ツリーには、どのポジションがアクティブであるかが保存されます。`edge_at[pos]`どの元のエッジがその位置を占めているかを示します。 対角線 ((l,r)) の場合、([l,r)) 内の最初のアクティブな位置を繰り返し見つけます。 そのエッジの補助ツリーの親を対角線に割り当て、その位置をアクティブ セットから削除します。 
4. ([l,r)) 内のアクティブな位置をすべて削除した後、対角線自体を位置 (l) に挿入します。 これは、新しく作成された面を 1 つの代表的な境界位置で表します。 グラフは交差していないため、結果として生じる親関係はツリーを形成します。 
5. すべての対角線が処理された後、まだアクティブなすべての境界エッジを単一のルート ノード (m+1) に接続します。 元の各エッジ (i) は、ノード (i) とノードの間の補助ツリー エッジに対応します。`fa[i]`。 
6. 最初は、補助ツリーの各リーフは、親につながる境界エッジが 1 つだけある面を表します。 このようなエッジをすべて最小ヒープに配置し、対応するリーフをエクスポーズ済みとしてマークします。 ヒープ キーは、その境界エッジに現在関連付けられている容量です。 
7. 最小のヒープ エントリを削除します。 その補助エッジのもう一方の端点がすでに露出している場合、そのエッジはすでに処理された境界の一部になっているため、現在の値をその変換された重みに追加します。 
8. それ以外の場合は、他のエンドポイントを公開します。 エクスポーズするために使用されたエッジは変換されたグラフから削除されるため、その変換された重みを非常に負のセンチネルでマークします。 顔を露出するために使用される容量は、1 つおきのインシデント補助ツリー エッジに追加されます。 隣接する面がまだ公開されていない場合は、新しく増加した容量を使用してそのエッジをヒープに押し込みます。 
9. ヒープが空になるまで続行します。 非負の変換された重みでマークされたすべての元のエッジは、最終ツリーの (n-1) 個のエッジの 1 つになります。 削除されたすべてのエッジには負のセンチネルがあります。 
10. 変換された重みによって残っているエッジを降順に並べ替えます。 元のグラフ頂点ごとに 1 つのコンポーネントを使用して DSU を初期化します。 重み (w) を持つ各ツリー エッジ ((u,v)) について、その端点を含む 2 つの現在のコンポーネントを見つけます。 サイズが (a) と (b) の場合、答えに (wab) を追加してコンポーネントをマージします。 
11. 累積された答えのモジュロ (998244353) を縮小して出力します。 

アルゴリズム全体の背後にある不変条件は、すべての変換で元の頂点のすべてのペア間の最小カットが保持されるということです。 サイクル操作では各カット値が保存されるため、すべての削除の後、最終的なツリーは元のグラフとまったく同じペアごとの最大フロー値を持ちます。 ツリー上では、ペアの値はその一意のパス上の最小エッジです。 降順 DSU 処理は、パスの最小値が現在のエッジの重みであるペアを正確にグループ化するため、すべてのペアが 1 回だけ寄与します。 これは、最終的な合計がすべての最大流量の必要な合計であることを証明します。 

## Python ソリューション```python
import sys
import heapq
from array import array

input = sys.stdin.readline

MOD = 998244353
NEG = -(10 ** 18)

def solve():
    n, m = map(int, input().split())

    # Original endpoints and capacities.
    eu = array('i', [0]) * (m + 1)
    ev = array('i', [0]) * (m + 1)
    cap = array('q', [0]) * (m + 1)

    # fa[i] is the parent of auxiliary-tree node i.
    fa = array('i', [0]) * (m + 2)

    # Active boundary position -> original edge id.
    edge_at = array('i', [0]) * (n + 1)

    diagonals = []

    for eid in range(1, m + 1):
        u, v, w = map(int, input().split())
        if u > v:
            u, v = v, u

        eu[eid] = u
        ev[eid] = v
        cap[eid] = w

        if v == u + 1:
            edge_at[u] = eid
        elif u == 1 and v == n:
            edge_at[n] = eid
        else:
            diagonals.append((u, v, eid))

    # Fenwick tree containing 1 exactly at active positions.
    bit = array('i', [0]) * (n + 1)
    for i in range(1, n + 1):
        bit[i] = i & -i

    def bit_add(i, delta):
        while i <= n:
            bit[i] += delta
            i += i & -i

    def bit_sum(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    def bit_kth(k):
        """Return the position of the k-th active point, 1-indexed."""
        pos = 0
        step = 1 << (n.bit_length() - 1)
        while step:
            nxt = pos + step
            if nxt <= n and bit[nxt] < k:
                k -= bit[nxt]
                pos = nxt
            step >>= 1
        return pos + 1

    # The nesting order of noncrossing diagonals.
    diagonals.sort(key=lambda x: (-x[0], x[1]))

    for l, r, eid in diagonals:
        before = bit_sum(l - 1)
        right = bit_sum(r - 1)

        # Every active position in [l, r) becomes a child of eid.
        while before < right:
            pos = bit_kth(before + 1)
            old_edge = edge_at[pos]

            fa[old_edge] = eid
            edge_at[pos] = 0
            bit_add(pos, -1)

            right -= 1

        # The new diagonal becomes the representative of this face.
        edge_at[l] = eid
        bit_add(l, 1)

    root = m + 1

    # Remaining active boundary pieces belong to the outer root.
    for pos in range(1, n + 1):
        eid = edge_at[pos]
        if eid:
            fa[eid] = root

    # The auxiliary tree is represented by parent -> children links.
    head = array('i', [-1]) * (m + 2)
    nxt = array('i', [-1]) * (m + 1)

    for eid in range(1, m + 1):
        p = fa[eid]
        nxt[eid] = head[p]
        head[p] = eid

    # nw[i] is the final transformed weight of original edge i.
    nw = array('q', [0]) * (m + 1)
    vis = bytearray(m + 2)

    heap = []

    # Every non-root leaf is initially an exposed face.
    for i in range(1, m + 1):
        if head[i] == -1:
            heapq.heappush(heap, (cap[i], i, fa[i]))
            vis[i] = 1

    while heap:
        cur, u, v = heapq.heappop(heap)

        if vis[v]:
            # Both sides are already exposed. The edge contributes
            # its current value to its transformed weight.
            nw[u] += cur
            continue

        # Expose face v through auxiliary edge u-v.
        vis[v] = 1
        nw[u] = NEG

        # The parent side of v is another incident edge.
        p = fa[v]
        if p != 0:
            if vis[p]:
                nw[v] += cur
            else:
                heapq.heappush(heap, (cur + cap[v], v, p))

        # Process all child sides of v except the edge we arrived through.
        c = head[v]
        while c != -1:
            if c != u:
                if vis[c]:
                    nw[c] += cur
                else:
                    heapq.heappush(heap, (cur + cap[c], v, c))
            c = nxt[c]

    # The non-deleted edges form the final tree.
    tree_edges = []
    for eid in range(1, m + 1):
        if nw[eid] >= 0:
            tree_edges.append((nw[eid], eu[eid], ev[eid]))

    tree_edges.sort(reverse=True)

    # Descending Kruskal on the final tree.
    parent = array('i', range(n + 1))
    size = array('i', [1]) * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    ans = 0

    for w, u, v in tree_edges:
        ru = find(u)
        rv = find(v)

        if ru == rv:
            continue

        if size[ru] < size[rv]:
            ru, rv = rv, ru

        ans = (
            ans
            + (w % MOD) * (size[ru] % MOD) % MOD
            * (size[rv] % MOD)
        ) % MOD

        parent[rv] = ru
        size[ru] += size[rv]

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```最初の部分は、元のすべてのエッジをコンパクトな整数配列に格納します。 数十万の Python 整数の Python リストは大量のメモリを消費する可能性があるため、`array`そして`bytearray`大規模な数値構造に使用されます。 

対角線構造では、フェンウィック ツリーを順序付けられたセットとして使用します。`bit_sum(r-1)-bit_sum(l-1)`([l,r)) にアクティブな境界代表がいくつあるかを示します。`bit_kth`最初の位置を特定し、その後その位置が削除されます。 すべての削除は 1 回だけ発生するため、個々の操作にはコスト (O(\log n)) がかかりますが、削除の総数は線形です。 

補助ツリーは次を使用します。`head`そして`nxt`Python タプルのリストではなく。 ノード (i) には親があります`fa[i]`、 そして`head[v]`(v) の最初の子を与えます。 ツリーは人工的な外面ノードにルートしているため、この表現で十分です。 

ヒープストア`(current_capacity, child, parent)`。 候補は、補助エッジの一方の側が露出し、もう一方の側が露出していない場合にのみ挿入されます。 したがって、各補助エッジは最大でも 1 つのヒープ エントリを作成します。 エントリが処理されると、`vis[v]`他の顔がすでに公開されているかどうかを示します。 

ネガティブセンチネルは、変換される可能性のある容量よりも意図的にはるかに小さくなっています。 元の容量はすべて最大 (10^9) であり、追加は最大 (4\cdot10^5) であるため、変換された有効な容量はすべて (4\cdot10^{14}) 未満になります。`-10**18`したがって、すべての有効な値から安全に分離されます。 

最後の DSU はエッジを降順で処理します。 生き残ったグラフはツリーであるため、そのエッジが処理されるとき、すべての生き残ったエッジのエンドポイントは異なる DSU コンポーネント内にあります。 それらのコンポーネント サイズの積により、パスがこのエッジのしきい値で最初に接続されるペアが正確にカウントされます。 

Python の整数はオーバーフローしませんが、容量を格納する配列では符号付き 64 ビット整数が使用されます。 可能な最大の変換容量は、問題なくその範囲内に収まります。 答えは、DSU が寄与するたびに減算法 (998244353) になります。

 ### サンプル 1

 サンプルには 6 つのポリゴン頂点と 2 つの対角線があります。 対角線の間隔は ((1,4)) および ((1,5)) であるため、補助ツリー構造では次の親関係が得られます。 

[
 1,2,3\rightarrow7,\qquad
 7,4\rightarrow8,\qquad
 8,5,6\rightarrow9.
 】

 ここで、ノード (1) ～ (6) はポリゴン エッジを表し、ノード (7) と (8) は 2 つの対角線を表し、ノード (9) は人工的な外側のルートです。 

重要な処理状態は次のとおりです。 

| ステップ | ヒープエッジ値 | 露出したノード | 重要な変換された重み |

### カスタム三角形

 検討してください```
3 3
1 2 1
2 3 1
3 1 1
```対角線がないため、補助ツリーは 3 つのポリゴン エッジすべてに接続された単純なルートになります。 

| ステップ | ヒープ値 | 露出したノード | 変換された重み |
 | --- | --- | --- | --- |
 | 1 | 1 | ルート | (w_1=-\infty,\ w_2=1,\ w_3=1) |
 | 2 | 1 | ルートはすでに公開されています | (w_2=2) |
 | 3 | 1 | ルートはすでに公開されています | (w_3=2) |

 生き残ったツリーには、容量 (2) の 2 つのエッジが含まれます。 DSU の寄与は (2\cdot1\cdot1=2) および (2\cdot2\cdot1=4) です。`6`。 

この例では、サイクルが単一エッジよりも多くの流れを提供できることを確認しています。 削減により、存続するツリーの容量が増加するため、余分な接続が維持されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(m\log m+n\log n)) | 対角ソート、フェンウィック操作、ヒープ処理、および最終エッジ ソート |
 | スペース | (O(n+m)) | オリジナルのエッジ、補助ツリー、フェンウィック ツリー、ヒープ、および DSU |

 入力には (m\le400000) があるため、(m) は (n) より大きい定数係数にすぎません。 したがって、アルゴリズムは (O(m\log m)) として動作し、意図した制限に適しています。 Python 実装の大規模な構造では、実用的な場合にはコンパクトな配列が使用され、グラフ サイズに比例したメモリが維持されます。

 ## 特殊なケース

 最小サイズの三角形```
3 3
1 2 1
2 3 1
3 1 1
```根元に付いている3枚の補助葉から始まります。 最初のリーフが削除され、他の 2 つはその容量を受け取り、変換された容量は (2) と等しくなります。 結果のツリーには重み (2) の 2 つのエッジがあるため、その 3 つの頂点ペアが寄与します (2+2+2=6)。 このアルゴリズムは、元のグラフがすでにツリーであるとは決して想定しません。 

容量ゼロの場合```
3 3
1 2 0
2 3 1
3 1 2
```最初に容量ゼロのエッジを選択します。 その容量は他のエッジに追加されるため、数値的には何も変わりません。 残りのツリーには容量 (1) と (2) があります。 そのペアごとのボトルネック値は (1,1,2) であり、次のようになります。`4`。 これは、ゼロが有効なヒープ値のままでなければならない理由と、削除センチネルが「削除」を意味するゼロを使用するのではなく負の値でなければならない理由を示しています。 

斜めのケース```
4 5
1 2 1
2 3 1
3 4 1
4 1 1
1 3 1
```には、対角線 ((1,3)) とともに循環境界エッジ ((1,4)) が含まれています。 対角線構造では、((1,4)) を (1) から (4) までの通常の間隔としてではなく、境界位置 (4) として扱います。 結果として変換されたツリーでは、6 つのペアごとのフローがすべて保存され、その合計は次のようになります。`13`。 この 1 つのラップアラウンド エッジの処理を誤ると、補助ツリーが変更され、静かに別の答えが生成される可能性があります。 

最大容量の三角形```
3 3
1 2 1000000000
2 3 1000000000
3 1 1000000000
```2 つのエッジの容量 (2000000000) を持つ変換されたツリーが生成されます。 変更されていない合計は (6000000000) で、必要な結果は次のとおりです。`10533882`。 この実装では、容量を符号付き 64 ビット配列に保持し、最終的な集計モジュロ (998244353) を実行するため、元の容量も中間の変換値もオーバーフローしません。
