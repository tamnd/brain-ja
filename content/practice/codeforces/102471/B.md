 ## 問題の理解

 (n\times m) 個のチェス盤があり、そのセル ((i,j)) の値は、(i+j) が偶数の場合は (+1)、そうでない場合は (-1) になります。 有効なパスは、左下隅から始まり右上隅で終わる、正確に (n) 個の北のステップと (m) 個の東のステップで構成されます。 

有向パスの左側にあるセルは、その値をスコアに寄与します。 スコアが正確に (k)、法 (998244353) を持つパスがいくつあるかを数える必要があります。 

入力には最大 (100) の独立したテスト ケースが含まれます。 どちらの次元も (10^5) になる可能性があるため、(nm) に依存する解はすでに大きすぎます。1 つのテスト ケースには (10^{10}) 個のセルが含まれる可能性があります。 すべてのパスを列挙することはさらに絶望的です。 

[
 \binom{n+m}{n},
 】

 これは、中程度の寸法であっても巨大です。 有用なアルゴリズムは、グローバル階乗事前計算後、本質的に一定時間でテスト ケースを処理する必要があります。 

推定されたスコア範囲に基づいた実装が失敗する可能性がある境界ケースがいくつかあります。 (n=m=1) の場合、2 つのパスのスコアは (1) と (0) であるため、入力`1 1 0`答えは(1)ですが、`1 1 -1`答えは(0)です。 スコアがゼロの周りで対称であると仮定する式は、ここですでに失敗します。 

(n+m) のパリティも重要です。 のために`2 3 1`の場合、正解は (1) ですが、`2 3 -1`それは(3)です。 合計の経路長が奇数の場合、2 つの辺は対称ではありません。 最後に、次のようなあり得ないスコア`2 2 2`には答え (0) があり、最も安全な実装では、すべてのスコア境界を個別に処理するのではなく、無効な二項係数からこれを自動的に取得する必要があります。

 ## アルゴリズムのチュートリアル

 1. パスを (n) の単語として表現します。`N`歩数と(m)`E`ステップ。 すべての単調パスはそのような単語 1 つと正確に対応するため、パスを数えるということは、これらの単語を数えるということと同じです。 
2. すべての行 (i) について、パスが行 (i) から行 (i+1) まで北にステップする列を (c_i) とします。 その垂直ステップの左側のセルは、まさに列インデックス (0,1,\ldots,c_i-1) を持つセルです。 

彼らの署名された寄稿は、

 [
 \sum_{j=0}^{c_i-1}(-1)^{i+j}。 
】

 (c_i) が偶数の場合、この合計はゼロになります。 (c_i) が奇数の場合、((-1)^i) と等しくなります。 
3. 北のステップに出現順に番号を付けます。 (q) 番目の北ステップが完全なパス ワード内の位置 (t_q) で発生するとします。 そのステップの前には (q-1) 個の北ステップがあるため、その列は次のようになります。 

[
 c_{q-1}=t_q-q。 
】

 この列が奇数の場合、(t_q) と (q) は逆パリティになります。 この北ステップの寄与は ((-1)^{q-1}) となります。 
4. 偶数位置における北側のステップ数を (A) とします。 正の寄与はまさに北のステップであり、偶数の位置に奇数のインデックス (q) が付いています。 負の寄与はまさに北のステップであり、偶数のインデックス (q) が奇数の位置にあります。 

(\lfloor n/2\rfloor) 偶数インデックスの北の階段のうち、すべての階段は偶数か奇数の位置にあります。 したがって、

 ## #(\text{奇数}q,\ t_q\text{偶数})

 # #(\text{偶数}q,\ t_q\text{奇数})

 A-\左\l階\frac n2\右\r階。 
】

 このアイデンティティは、ソリューション全体の重要な不変条件です。 
5. 必要なスコア (k) について、(A) の恒等式を解きます。 

[
 A=\left\lfloor\frac n2\right\rfloor+k。 
】

 (\lfloor(n+m)/2\rfloor) 偶数の位置があるため、

 [
 \binom{\lfloor(n+m)/2\rfloor}
 {\lfフロア n/2\rフロア+k}
 】

 北側の階段が占める均等な位置を選択する方法。 
6. (\lceil(n+m)/2\rceil) 個の奇数の位置があります。 残りの (n-A) 北側のステップはこれらの位置を占める必要があります。 以来

 [
 n-A=\left\lceil\frac n2\right\rceil-k、
 】

 あります

 [
 \binom{\lceil(n+m)/2\rceil}
 {\lceil n/2\rceil-k}
 】

 選択肢。 
7. 2 つの二項係数を法 (998244353) で乗算します。 どちらかの下位引数が有効範​​囲外にある場合、対応する二項係数はゼロになるため、不可能なスコアには特別なケースは必要ありません。 

### なぜ効果があるのか

 北の各ステップを含む行は、その行のどのセルがその左側にあるかを直接説明します。 セルの色が交互になるため、その行の符号付き合計は偶数列ではゼロ、奇数列では正確に (+1) または (-1) になります。 (q) 番目のノース ステップの列を (t_q-q) として表現すると、この条件がノース ステップ インデックスとパス ワード内のその絶対位置の間のパリティ関係に変換されます。 

この変換後、スコアへのすべての寄与は、北のステップが偶数の位置を占めるか奇数の位置を占めるかによってのみ決定されます。 合計スコアは、偶数位置の北のステップの数 (A) から (\lfloor n/2\rfloor) を引いたものになります。 (A) が固定されると、ワードの偶数部分と奇数部分のノースステップ位置の選択は独立します。 2 つの二項係数はそれらの選択肢を正確にカウントするため、有効なパスはすべて 1 回カウントされ、無効なパスはカウントされません。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 998244353

def prepare(max_n):
    fact = [1] * (max_n + 1)
    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (max_n + 1)
    invfact[max_n] = pow(fact[max_n], MOD - 2, MOD)
    for i in range(max_n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    return fact, invfact

def comb(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def main():
    T = int(input())
    tests = [tuple(map(int, input().split())) for _ in range(T)]

    max_size = 0
    for n, m, _ in tests:
        max_size = max(max_size, n + m)

    fact, invfact = prepare(max_size)

    ans = []

    for n, m, k in tests:
        even_positions = (n + m) // 2
        odd_positions = (n + m + 1) // 2

        north_on_even = n // 2 + k
        north_on_odd = (n + 1) // 2 - k

        left = comb(even_positions, north_on_even, fact, invfact)
        right = comb(odd_positions, north_on_odd, fact, invfact)

        ans.append(str(left * right % MOD))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()

の`comb`この関数は、下位引数が負の場合、または上位引数より大きい場合、明示的にゼロを返します。 これにより、メイン アルゴリズムに分岐を追加することなく、可能な範囲外のスコアが処理されます。 

テストケースごとに、`even_positions`そして`odd_positions`長さ (n+m) のパス ワード内の位置 (2,4,\ldots) と (1,3,\ldots) の数です。 変数`north_on_even`そして`north_on_odd`スコアのアイデンティティから直接得られます。 それらの合計は正確に (n) であり、健全性チェックに役立ちます。 

Python では整数オーバーフローの問題はありません。 すべての乗算は剰余 (998244353) で還元され、剰余は素数であるため、フェルマーの定理を使用して逆剰余が得られます。
