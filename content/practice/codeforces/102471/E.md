 ## 解決策
 ## 問題の理解

 グラフは特殊な形状をしています。ソース頂点 1 からシンク頂点 n に向かう複数の独立したルートから作成されます。 すべてのルートには同じ数のエッジが含まれており、ルートは内部頂点を共有しません。 エッジ上の容量は単位操作によって移動できます。 1 つの操作で、現在ある程度の容量があるエッジから 1 単位の容量が取得され、それが別のエッジに配置されます。 

目標は、最終的な能力を構築することではありません。 可能な最大流量が総容量が許す限り大きくなるように、移動するユニットの必要最小限の数だけが必要です。 

エッジ キャパシティを持つ単一ルートの場合`c1, c2, ..., cl`、ルートが伝送できるフローの量は、その最小エッジ キャパシティです。 容量を再配分した後、すべてのルートの合計容量は変わりません。 フローのすべての単位には、すべてのフローに 1 単位の容量が必要であるため、`l`ルートのエッジの絶対最大流量は次のとおりです。```
total_capacity // l
```制約があるためシミュレーションは不可能です。 最大 100,000 個の頂点と 200,000 個のエッジを含めることができ、容量は 10^9 まで大きくすることができます。 流量を一度に 1 ユニットずつ増やすなど、容量値に直接依存するアルゴリズムでは、数十億回の操作が必要になる可能性があります。 

主な隠れエッジのケースは、最良の再配布が必ずしもすべてのパスを独立してバランスさせることではないという事実から生じます。 

考慮する：```
4 3
1 2 0
2 3 100
3 4 100
```パスの長さは 3 です。合計容量は 200 であるため、最終的な最大フローは 66 です。すべてのパスを次と等しくしようとする貪欲な方法です。`total/l`ここでは、欠落しているエッジをすべて直接埋めることで機能する可能性がありますが、すべての追加ユニットが均等に分散されるべきであると仮定するアプローチは、パスを増やす限界コストが急激に変化する可能性があるため、失敗します。 

別のケースは次のとおりです。```
4 3
1 2 5
2 3 5
3 4 5
```答えは 0 です。現在のボトルネックはすでに 5 であり、合計容量は同じ最大流量を与えます。 理論上の最大値を計算した後に常に再配分を実行する方法では、不必要な手を誤ってカウントしてしまいます。 

最後の重要なケースは、容量がゼロのパスです。```
2 1
1 2 0
```最大流量は 0 であり、操作は必要ありません。 パスを分解するときにすべてのエッジに正の容量があると想定する実装は、ここで失敗する可能性があります。 

## アプローチ

 直接的な解決策では、グローバル最大値に達するまで、一部のパスのフローが繰り返し増加します。 追加のフロー単位ごとに、容量が不十分なパス エッジを見つけて、そこに容量を移動します。 これは正しいです。なぜなら、すべての操作は、どこかのエッジで 1 つの不足しているユニットの代償を支払っていると見なすことができるからです。 ただし、最大流量は約`10^14`, したがって、ユニットのシミュレーションは不可能です。 

有益な観察は、1 つのパスを観察することで得られます。 現在のボトルネックが`x-1`に`x`。 その増加に必要な操作の数は、容量が以下のエッジの数と同じです。`x`なぜなら、そのようなエッジにはさらに 1 つのユニットが必要だからです。 これらのコストは、すべてのパスに対して非減少シーケンスを形成します。 

最終的な流量値は固定されています。 正確に選択する必要があります`total_capacity // l`すべてのパス増分シーケンス間で最小の総コストで増分します。 すべての増分コストは減少しないため、全体的に最小のコストを取ることで答えが得られます。 

コストは常に 0 ～`l`したがって、可能なすべての増分を保存する必要はありません。 すべてのパスについて、コスト 0、コスト 1 などの増分がいくつあるかを数えます。`l-1`。 残りのすべての増分コスト`l`。 次に、これらのカウントを最小コストから順に消費します。

 ## アルゴリズムのチュートリアル

 1. 頂点 1 からグラフをトラバースします。ソースの各出力エッジは、独立したパスの 1 つを開始します。 頂点 n に到達するまで各パスをたどり、そのエッジ容量を保存します。 内部頂点は 1 つのパスのみに属するため、すべての内部頂点には次のエッジが 1 つだけ存在します。 
2. しましょう`l`パスの長さになります。 すべてのエッジ容量の合計を で割ったものとして目標流量値を計算します。`l`整数の除算を使用します。 これは、再配布後に作成する必要がある 1 ユニットのパス層の数です。 
3. パスごとに、そのエッジ容量を並べ替えます。 現在の望ましい流量レベルが`x`、このレベルに到達するコストは、以下の容量の数です。`x`。 等しい容量をグループ化することで、考えられるすべてのコストを持つ連続レベルの数を数えます。 
4. これらすべてのカウントを、演算コストによってインデックス付けされたグローバル周波数配列に追加します。 コストが以下より小さい`l`有限です。 パス上の最大のエッジ容量以降の追加レベルにはコストがかかります`l`。 
5. コスト 0 から開始して、ターゲットの流量値が正確に選択されるまで、できるだけ多くのレベルを取得します。 選択したコストの合計が最小操作数になります。 

機能する理由: 最終フローの各ユニットは、1 つのパス上の 1 つの選択されたレベルに対応します。 パスはそのレベルを順番に選択することしかできませんが、そのレベルのコストは決して減少しないため、利用可能な最も安価なコストを最初に採用することによって、世界的に最も安価な有効な選択が得られます。 コスト頻度の構築では、これらの限界コストが正確に保存されるため、累積合計は、移動された容量ユニットの最小可能数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    indeg = [0] * n

    edges = []
    total = 0

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, c))
        indeg[v] += 1
        edges.append((u, v, c))
        total += c

    paths = []
    length = None

    for _, first_c in adj[0]:
        caps = [first_c]
        cur = adj[0][len(paths)][0]

        while cur != n - 1:
            nxt, c = adj[cur][0]
            caps.append(c)
            cur = nxt

        if length is None:
            length = len(caps)
        paths.append(caps)

    if length is None:
        print(0)
        return

    need = total // length

    freq = [0] * length
    cheap_count = 0
    cheap_sum = 0

    for caps in paths:
        caps.sort()
        cur = 0
        idx = 0
        i = 0
        while i < length:
            v = caps[i]
            j = i
            while j < length and caps[j] == v:
                j += 1
            cnt = j - i
            levels = v - cur
            if idx < length:
                freq[idx] += levels
                cheap_count += levels
                cheap_sum += levels * idx
            idx += cnt
            cur = v
            i = j

    ans = cheap_sum
    if need > cheap_count:
        ans += (need - cheap_count) * length

    print(ans)

if __name__ == "__main__":
    solve()
```パスの抽出は特別なグラフ構造に依存します。 ソースには複数の出力エッジを含めることができますが、内部頂点に入った後は次のエッジが 1 つだけ存在します。 これにより、一般的なグラフ アルゴリズムの実行が回避されます。 

周波数配列には、次のコストのみが格納されます。`0`に`l-1`。 パス上のすべてのエッジが制限エッジになると、パス フローをさらに増加させると常にコストがかかります`l`, したがって、残りの寄与は算術的に計算できます。 

容量に関係するすべての値と答えは Python 整数を使用します。 これが必要なのは、最大の場合、答えが 32 ビットおよび 64 ビットの制限を超える可能性があるためです。

 ## 特殊なケース

 ゼロ容量パスの場合:```
2 1
1 2 0
```パスの長さは 1 で、総容量は 0 です。 必要なフロー層の数はゼロであるため、アルゴリズムはコストを選択せず​​、ゼロを返します。 

すでに最大可能フローを持っているグラフの場合:```
4 3
1 2 5
2 3 5
3 4 5
```合計容量は 15、パス長は 3 で、ターゲット フローは 5 になります。コスト シーケンスには、5 つのユニットすべてを作成するのに十分なゼロコスト レベルが含まれているため、容量は移動されません。 

非常に大きなエッジを持つパスの場合:```
4 3
1 2 0
2 3 100
3 4 100
```最初のエッジが埋められた後、パスは多くの安価なレベルに寄与します。 頻度アプローチでは、100 回以上繰り返すのではなく、レベルをグループ化することでこれに対処します。 1 回の操作ですべての等コスト増分をカウントし、グローバルに最も安価な必要なレイヤーを選択します。
