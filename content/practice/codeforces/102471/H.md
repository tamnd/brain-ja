 ## 解決策
 ## 問題の理解

 プライム (p) を法とする非ゼロ残基のシーケンス (b_1,b_2,\ldots,b_n) があります。 キング シーケンスは、1 つの固定非ゼロ剰余 (q) を乗算することで連続した値が得られるサブシーケンスです。 言い換えれば、いくつかの位置 (i_1<i_2<\cdots<i_k) を選択した後、その値は次の条件を満たす必要があります。 

[
 b_{i_{j+1}}\equiv q b_{i_j}\pmod p
 】

 連続するペアごとに。 

タスクは、可能な最大長を見つけることです。 特別なエスケープ句があります。最大値が (n/2) より小さい場合は、(-1) を出力するだけで済みます。 それ以外の場合は、実際の最大長を出力する必要があります。 元のステートメントではシーケンスの長さに同じ (n) が使用されているため、全体で (n) を使用します。 

(p) の素数により、1 つの重要な特性が得られます。 すべての (b_i) は (p) を法とする非ゼロであるため、すべての (b_i) は乗法逆元を持ちます。 その結果、任意の 2 つの異なる位置により、可能な比率が即座に決定されます。 (b_i) と (b_j) がキング部分列の連続するメンバーであると判断した場合、可能な比率は次のとおりです。 

[
 q\equiv b_j b_i^{-1}\pmod p.
 】

 制約 (n\le 200000) は、合計 (n) が最大 (200000) であることと合わせて、通常の場合、二次または三次を除外します。 (O(n)) 個の可能な比率ごとにシーケンス全体を 1 回スキャンするソリューションでは、最大サイズで約 (4\cdot10^{10}) 回の反復で (O(n^2)) の作業がすでに実行されます。 2 秒の制限では、一定の試行回数ごとに基本的に線形の作業が必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、(n=2) は、任意の 2 つの非ゼロ値がキング シーケンスを形成するため特別です。それらの比は単純に (b_2b_1^{-1}) です。 したがって、答えは常に (2) になります。 たとえば、(n=2,p=7) およびシーケンス (3,5) の場合、答えは (-1) ではなく (2) になります。 

2 番目の境界ケースは、分数しきい値から生じます。 条件は少なくとも (n/2) の長さであるため、整数の比較は (2L\ge n) になります。 (n=5) の場合、(3\ge2.5) であるため、長さ (3) のシーケンスが適格となります。 例えば、```
1
5 7
2 4 5 6 8
```(2,4,8) と比率 (2) を使用した答え (3) があります。 を使用した不注意な実装`length >= n // 2`誤って長さ (2) を十分なものとして扱います。 

繰り返される値も重要です。 すべての値が等しい場合は (q=1)、配列全体がキング シーケンスになります。 例えば、```
1
5 7
3 3 3 3 3
```答えは(5)です。 (q\ne1) を前提とする実装は、有効な最大シーケンスを拒否します。 

最後に、モジュラー除算は、通常の整数除算ではなく、逆モジュラーを使用して実行する必要があります。 (p=7) の場合、(2) と (5) の比率は、通常の整数演算の (5/2) ではなく、(5\cdot2^{-1}\equiv5\cdot4\equiv6\pmod7) になります。 

## アプローチ

 最も直接的な総当り攻撃は、King サブシーケンスの最初の 2 つの要素を選択することから始まります。 それらが位置 (i<j) で発生すると仮定します。 彼らは一意に決定します

 [
 q=b_jb_i^{-1}\pmod p.
 】

 (q) が固定されたら、サブシーケンスを貪欲に拡張できます。 (b_j) から開始して、右にスキャンして、(qb_j) に等しい最初の要素を取得し、次に (q^2b_j) に等しい最初の要素を取得します。 同じ考え方が (q^{-1}) を使用して逆方向に機能します。 

これは正しいです。開始要素と比率が固定されている場合、次の出現をできるだけ早く取得しても、将来の選択に悪影響を与えることはありません。 後のすべての要素には、シーケンスを継続するための少なくとも同じくらいの余地があります。 

問題は、可能な開始ペアの数です。 (O(n^2)) 個のペアがあり、シーケンス コスト (O(n)) をスキャンして各ペアをテストすると、最悪の場合 (O(n^3)) が得られます。 (n=200000) では、これは (8\cdot10^{15}) 回の基本スキャン操作に相当し、完全に実行不可能です。 

特殊な出力条件により問題が変わります。 ここで考慮するのは、King サブシーケンスに配列の少なくとも半分が含まれる場合だけです。 このような大きなサブシーケンスは、元のシーケンス内に密集しています。 考えられるすべての開始ペアを試す代わりに、配列の位置 (x) をランダムに選択します。 (x) が少なくとも (n/2) の長さのキング部分列に属している場合、それは有用なアンカーです。 意図したランダム化ソリューションでは、非常に近い位置 (x+1) と (x+2) を使用して候補の比率を取得し、各候補の配列全体をスキャンします。 

これが重要な削減点です。比率を決定論的に特定する必要はありません。 アルゴリズムは実験を何度も繰り返すことができるため、正しい比率を生成する一定の確率だけが必要です。 標準的に受け入れられているアプローチでは、この実験を 100 回繰り返します。 

固定の候補比率 (q) の場合、スキャン自体は線形です。 選択したアンカーが位置 (x) にある場合、(q^{-1}) を使用して後方に拡張し、次に (q) を使用して前方に拡張します。 最も早い一致の出現が常に安全に取得されるため、結果の長さは、この比率のアンカーを含む最大のキング サブシーケンスになります。 

報告されたすべての回答はこの構造によって個別に検証されるため、ランダム化により生じる可能性があるのは偽陰性のみであり、偽陽性は決して発生しません。 アルゴリズムが長さ (L) を出力する場合、実際に収集された要素は長さ (L) の有効なキング サブシーケンスを形成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(1)) | 遅すぎる |
 | 最適なランダム化 | (O(Kn))、(K=100) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n)、(p)、および配列を読み取ります。 すべての (b_i) は (1) と (p-1) の間にあるため、すべての値は逆剰余を持ちます。 
2. 非常に小さい配列の場合は、ペアを直接列挙します。 これにより、小さな境界ケースの周囲での不必要なランダム性が回避され、正確な結果が得られます。 位置のペア (i<j) について、次のように計算します。 

[
 q=b_jb_i^{-1}\pmod p
 】

 そして、その比率を使用して最長のキング部分列を計算します。 

1. 配列が大きい場合は、ランダム化実験を 100 回繰り返します。 一様にランダムな位置 (x) を選択します。 
2. (x+1\le n) の場合、次を使用します。 

[
 q=b_{x+1}b_x^{-1}\pmod p
 】

 候補比率としては。 この候補は、(x) と (x+1) が目的のキング サブシーケンスの連続する要素である場合に特に役立ちます。 

1. (x+2\le n) の場合も同様に使用します

 [
 q=b_{x+2}b_x^{-1}\pmod p.
 】

 2 番目の候補は、有用な要素が 1 つの破棄された配列要素によって分離されている状況を処理します。 これは、この問題に使用されるランダム化戦略の一部です。 

1. すべての候補比 (q) について、フェルマーの小定理を使用して (q^{-1}) を計算します。 

[
 q^{-1}\equiv q^{p-2}\pmod p.
 】

 (p) は素数であり、(q\ne0) であるため、この逆数は常に存在します。

1. (b_x) から開始して、左にスキャンします。 現在の期待値を、現在の値に (q^{-1}) を乗算した値に等しく保ちます。 スキャンされた要素が期待値と等しい場合は常に、それを取得して期待値を更新します。 最初に発生する可能性のあるものを取得することは貪欲であり、使用できる要素の数を最大化します。 
2. 2 番目のアンカー位置から再度開始し、右にスキャンします。 要素が現在の値に (q) を乗算した値に等しい場合は常に、それを取得します。 両側で取得した要素の数と 2 つのアンカー要素を加算します。 
3. ベストアンサーを更新します。 最後に、(2\cdot\text{best}\ge n)を満たす場合に最適な長さを出力します。 それ以外の場合は (-1) を出力します。 

### なぜ効果があるのか

 固定の候補比率 (q) ごとに、グリーディ スキャンは、選択された要素が有効なキング シーケンスを形成し、最後に選択された要素が必要な値を持つ最も早い要素であるという不変条件を維持します。 選択した要素を以前の出現で置き換えても、後で利用可能な位置のセットを減らすことはできないため、貪欲スキャンは、そのアンカーと比率と互換性のある最大のサブシーケンスを取得します。 

最適な King サブシーケンスの長さが少なくとも (n/2) であると仮定します。 その要素は元の位置の少なくとも半分を占めるため、一様にランダムな位置は一定の確率でこのサブシーケンスにヒットします。 有用なアンカーが選択されると、意図したランダム化戦略の下で、近くの要素が一定の確率で候補比率を提供します。 実験を 100 回繰り返すと、有用な候補をすべて見逃す可能性が非常に低くなります。 これが、この問題の異常な (n/2) 要件によってランダム化された線形時間解が可能になる理由です。 

すべての候補の長さは明示的に構築されたキング サブシーケンスに由来するため、アルゴリズムは無効な肯定的な応答を出力できません。 ランダム性は、十分に長いシーケンスが検出されるかどうかにのみ影響します。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

TRIALS = 100
SMALL = 50

def fixed_ratio_length(a, p, left, right, q):
    """
    a is 0-indexed.
    left and right are two consecutive chosen positions,
    and a[right] == q * a[left] (mod p).

    Return the longest King subsequence with ratio q that
    contains both anchor positions.
    """
    inv_q = pow(q, p - 2, p)

    length = 2
    cur = a[left]

    for i in range(left - 1, -1, -1):
        if a[i] == cur * inv_q % p:
            cur = a[i]
            length += 1

    cur = a[right]

    for i in range(right + 1, len(a)):
        if a[i] == cur * q % p:
            cur = a[i]
            length += 1

    return length

def exact_small(a, p):
    n = len(a)
    best = 1

    for i in range(n):
        inv_ai = pow(a[i], p - 2, p)

        for j in range(i + 1, n):
            q = a[j] * inv_ai % p
            best = max(best, fixed_ratio_length(a, p, i, j, q))

    return best

def solve_case(n, p, a, rng):
    if n <= SMALL:
        return exact_small(a, p)

    best = 1

    for _ in range(TRIALS):
        x = rng.randrange(n)

        if x + 1 < n:
            q = a[x + 1] * pow(a[x], p - 2, p) % p
            best = max(best, fixed_ratio_length(a, p, x, x + 1, q))

        if x + 2 < n:
            q = a[x + 2] * pow(a[x], p - 2, p) % p
            best = max(best, fixed_ratio_length(a, p, x, x + 2, q))

    if 2 * best >= n:
        return best
    return -1

def main():
    rng = random.Random()

    T = int(input())
    out = []

    for _ in range(T):
        n, p = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(solve_case(n, p, a, rng)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`fixed_ratio_length`関数はコアの貪欲スキャンを実装します。 2 つのアンカー位置は、候補比率の連続するメンバーであることがすでにわかっているため、初期の長さは次のようになります。`2`。 逆方向スキャンでは、`inv_q`、順方向スキャンでは`q`。 

表現`pow(x, p - 2, p)`Python のべき乗剰余演算です。 の逆数を計算します`x`(O(\log p)) 時間における素数 (p) の法。 Python には整数オーバーフローの問題はなく、剰余はべき乗と乗算の際に適用されます。 

比較`2 * best >= n`浮動小数点演算を意図的に避けています。 これにより、(n) の偶数値と奇数値の両方が正しく処理されます。 たとえば、(n=5) の場合、長さ (3、4、5) は適格ですが、長さ (2) は適格ではありません。 

の`SMALL`漸近アルゴリズムには分岐は必要ありません。 これにより、小さな入力に対して実装が決定的になり、三次総当たりのコストが低くなり、小さな配列の厄介な境界動作がなくなります。 

ランダム化された部分では 100 回の試行が使用され、標準的な解決戦略と一致します。

## テストケース

def fixed_ratio_length(a, p, left, right, q):

    cur = a[left]

                )

    return str(best if 2 * best >= n else -1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    rng = random.Random(123456789)

    try:
        T = int(sys.stdin.readline())
        ans = []

        for _ in range(T):
            n, p = map(int, sys.stdin.readline().split())
            a = list(map(int, sys.stdin.readline().split()))
            ans.append(solve_case(n, p, a, rng))

        return "\n".join(ans)
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 (n=2) の場合、答えは常に (2) です。 と```
1
2 7
3 5
```比率は (5\cdot3^{-1}\equiv5\cdot5\equiv4\pmod7) なので、(3,5) はキング シーケンスです。 実装の正確な小文字ブランチは、このペアを直接見つけます。 

値が等しい場合は、次のようにします。```
1
5 7
3 3 3 3 3
```(q=1) を選択すると (1\cdot3\equiv3\pmod7) が得られるため、連続するすべてのペアがルールを満たします。 最大値は (5) および (2\cdot5\ge5) であるため、出力は次のようになります。`5`。 

奇数のしきい値については、次のことを考慮します。```
1
5 1000000007
2 4 5 6 8
```部分列 (2,4,8) は比率 (2) を持つため、その長さは (3) になります。 (4) King 部分列の長さはありませんが、(2\cdot3=6\ge5) であるため、(3) で十分です。 正しい出力は次のとおりです`3`。 このため、実装では次を使用します。`2 * best >= n`の代わりに`best >= n // 2`。 

閾値を下回るシーケンスの場合、```
1
5 1000000007
2 4 5 6 7
```最長の King サブシーケンスの長さは (2) です。 任意の 2 つの要素で比率を定義できますが、必要な順序で 3 つの要素をサポートする比率はありません。 (2\cdot2=4<5) であるため、出力は次のようになります。`-1`。 

最大入力サイズでは、(7) のコピー (200,000) を検討してください。 比率 (q=1) は配列全体で機能するため、答えは (200000) になります。 このアルゴリズムでは、値または比率でインデックス付けされた動的プログラミング テーブルを保存する必要はありません。 配列を保持して繰り返しスキャンするだけなので、メモリは残ります (O(n))。 

(q=1) の場合、モジュール逆境界も安全です。 フェルマーの公式は (1^{p-2}\equiv1) を与えるため、後方スキャンと前方スキャンは等しい値まで正しく継続されます。 すべての入力値は非ゼロモジュロ (p) であるため、ゼロの反転は要求されません。
