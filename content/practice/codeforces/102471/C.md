 ## 解決策
 ## 問題の理解

 正の整数でインデックス付けされた配列を操作しますが、配列の乗算は通常の要素ごとの乗算ではありません。 2 つの関数 (f) と (g) の (n) におけるディリクレ畳み込みは次のようになります。 

[
 (f*g)(n)=\sum_{d\mid n}f(d)g(n/d)。 
】

 入力は、関数 (g) の最初 (n) の値と指数 (k) を与えます。 を満たす関数 (f) を回復する必要があります。 

[
 f^k=\underbrace{f_f_\cdots*f}_{k\text{ 回}}=g,
 ]

 (f(1)=g(1)=1) で、すべての計算は (998244353) を法として実行されます。 公式声明には (n\le 10^5) と 1 秒の時間制限があります。 

出力は、そのような (f) の最初の (n) 値です。 与えられた制約の下では、実際には解決策は常に存在し、一意です。 (-1) を出力する可能性は明らかですが、問題の一般的な表現から来ていますが、ここで (k) は厳密に素数係数よりも小さく、以下の漸化式ではすべての (n>1) に対して非ゼロの分母があります。 

境界 (n\le10^5) は、(n) 内の二次関数を除外します。 (O(n^2)) であっても、約 (10^{10}) 回の反復が必要になります。 ディリクレ畳み込みは積がターゲットとなるインデックスのペアのみであるため、関連するすべてのペアを約 (n\log n) 時間で列挙できるという事実を利用する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、(k=1) は完全に有効です。 例えば、```
2 1
1 7
```正しい出力がある```
1 7
```なぜなら (f^1=f=g) だからです。 (k\ge2) を前提とした実装は、ここで不必要に失敗します。 

次に、複合因数分解を含める必要があります。 考慮する```
4 2
1 2 2 1
```正しい出力は次のとおりです```
1 1 1 0
```なぜなら

 [
 (f*f)(4)=f(1)f(4)+f(2)f(2)+f(4)f(1)=0+1+0=1。 
]

 2 つの要素 (1) と (4) のみを考慮する方法では、(2\cdot2) の寄与が欠落します。 

第三に、漸化式で使用される量は多重度を持って素因数を数えなければなりません。 たとえば、

 [
 \オメガ(4)=2、
 ]

 (1)ではありません。 異なる素因数の数を使用すると、(n=4) の分母が不正確になり、漸化式が壊れます。 

最後に、(k) は係数に非常に近くなる可能性があります。 例えば、```
2 998244352
1 1
```答えがあります```
1 998244352
```なぜなら (k=-1\pmod {998244353})、つまり (f(2)=1/k=-1\pmod {998244353}) だからです。 すべての除算は、通常の整数除算ではなく逆モジュラーとして実行する必要があります。 

## アプローチ

 直接的なアプローチは、(f) を構築し、それ自体と繰り返し畳み込み、結果を (g) と比較することです。 1 つのディリクレ畳み込みは、すべてのペア (ab=n) を列挙することで計算できます。 (n\le N) ごとに、そのようなペアの総数は次のようになります。 

[
 \sum_{a=1}^{N}\left\lfloor\frac Na\right\rfloor
 =O(N\log N)。 
]

 したがって、1 回の畳み込みには (O(n\log n)) のコストがかかりますが、それを (k-1) 回実行すると (O(kn\log n)) のコストがかかります。 最悪の場合、(k) はほぼ (10^9) であるため、(n=10^5) の場合、これは (10^{15}) の算術演算のオーダーになります。 このアプローチは正しいですが、指数のせいで使用できなくなります。 

有益な観察は、通常の微分を行うと累乗が (k) による乗算に変わるということです。 

[
 (F^k)'=kF^{k-1}F'。 
]

 ディリクレ級数は、ディリクレ畳み込みに対して同様の代数表現を与えます。 問題は、(n^{-s}) を微分すると (-\ln n) が導入され、これは法として直接役に立たないことです (998244353)。 

実際には対数の数値特性は必要ありません。 必要なのはアイデンティティだけです

 [
 \ln(ab)=\ln a+\ln b。 
]

 したがって、(\ln n) を完全な加法関数に置き換えることができます。 自然な選択は、

 [
 \オメガ(n)、
 ]

 多重度でカウントされた (n) の素因数の数。 満足する

 [
 \オメガ(ab)=\オメガ(a)+\オメガ(b)。 
]

 関数の演算子 (T) を次のように定義します。 

[
 (Tf)(n)=\オメガ(n)f(n)。 
]

 (\Omega) の加法的性質は、ディリクレ畳み込みに対するライプニッツ則を与えます。 

[
 T(f_g)=Tf_g+f*Tg。 
]

 したがって、(G=F^k) については、

 [
 T(G)_F=kG_T(F)。 
]

 (n) に属する係数を見ると、(f(n)) を 1 回だけ含む方程式が得られます。 他のすべての用語は (d<n) に対して (f(d)) を使用します。 これにより、元の根本的な問題が単純な再発に変わります。 

残りの実装の詳細は、すべての適切な除数の寄与を効率的に評価することです。 (f(d)) が判明すると、(a\ge2) を持つすべての (n=d\cdot a) に寄与します。 その貢献をすぐにアキュムレーターに分配できます。 そのようなペア ((d,a)) の数は (O(n\log n)) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(kn\log n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (1\le i\le n) ごとに (\Omega(i)) を計算します。 (\Omega(p)=1) および (\Omega(ip)=\Omega(i)+1) であるため、これを線形ふるいで行うことができます。 
2. 変換を定義する

 [
 (Tf)(n)=\オメガ(n)f(n)。 
]

 (\Omega(ab)=\Omega(a)+\Omega(b)) であるため、この変換は次のようになります。 

[
 T(f_g)=Tf_g+f*Tg。 
]

 これは、通常の導関数が通常のべき乗則に寄与する正確な代数的特性です。 

1. (g=f^k) なので、(T) を両辺に適用し、べき乗則を使用すると、次のようになります。 

[
 T(g)_f=k,g_T(f)。 
]

 (n) の係数を書き出すと、

 k\sum_{d\mid n}g(d)f(n/d)\オメガ(n/d)。 
]

 1. (f(n)) を含む項を分離します。 右辺では、(g(1)=f(1)=1) であるため、(d=1) のときにそれが発生します。 (\Omega(1)=0) なので、左側には対応する (f(n)) 項はありません。 並べ替えると

 \sum_{\substack{d\mid n\d<n}}
 f(d)g(n/d)
 \left(\オメガ(n/d)-k\オメガ(d)\right)。 
]

 したがって、

 [
 \箱入り{
 f(n)=
 \frac{
 \表示スタイル
 \sum_{\substack{d\mid n\d<n}}
 f(d)g(n/d)
 \left(\オメガ(n/d)-k\オメガ(d)\right)
 ｛
 k\オメガ(n)
 }
 }。 
]

 すべての (n>1) について、(\Omega(n)\ge1)。 また、(1\le k<998244353) なので、(k\not\equiv0\pmod{998244353}) となります。 したがって、分母は反転可能です。 

1. (f(1)=1) に設定します。 アキュムレータを保守する`acc[m]`(f(m)) の漸化式の分子を含みます。 

(f(d)) が計算されたら、すべての (a\ge2) と (d a\le n) を考慮します。 ペア

 [
 (d,a)
 ]

 (m=da) に寄与するのは、

 [
 f(d)g(a)
 \left(\オメガ(a)-k\オメガ(d)\right)。 
]

 したがって、正確にこの値を次の値に追加します。`acc[d*a]`。 

1. (d=1,2,\ldots,n) を昇順に処理します。 (d=1) の場合、(f(1)=1) はすでにわかっており、その更新によってすべてのアキュムレータに項 (g(n)\Omega(n)) が作成されます。 (d>1) の場合、(d) のすべての適切な約数はすでに処理されているため、`acc[d]`完成したので計算できます

 [
 f(d)=
 \text{acc}[d],(k\Omega(d))^{-1}\pmod p.
 ]

 次に、新しくわかった (f(d)) をその倍数すべてに直ちに分配します。 

1. (k) および (\Omega(n)) の可能な小さな値のモジュラー逆数を計算します。 (n\le10^5), (\Omega(n)\le16) なので、必要なのは小さな逆テーブルだけです。 

### なぜ効果があるのか

 中心となる不変式は、(f(n)) を計算する前の不変式です。`acc[n]`正確に含まれています

 [
 \sum_{\substack{d\mid n\d<n}}
 f(d)g(n/d)
 \left(\オメガ(n/d)-k\オメガ(d)\right)。 
]

 すべての項は、その小さい因数 (d) が処理されたときに加算されており、(a\ge2) を乗算するだけであるため、(f(n)) に関係する項は加算されません。 

(\Omega) は完全に加法的であるため、変換 (T(f)(n)=\Omega(n)f(n)) はライプニッツの法則を満たします。 したがって、すべての有効なルートは再帰性を満たします。 逆に、再帰はその再帰を満たす値を構築します。 (H=f^k) と仮定します。 (H) と指定された (g) は両方とも、同じ変換された畳み込み方程式を満たします。 それらの差は (1) で値 0 を持ち、すべて (n>1) でその係数に非ゼロ値 (k\Omega(n)) が乗算されますが、他のすべての項にはより小さなインデックスが含まれます。 (n) に対する帰納法は、(n\le N) ごとに (H(n)=g(n)) を強制します。 したがって、構築された (f) は正しい (k) 番目のディリクレ根です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    g = [0] + list(map(int, input().split()))

    # Linear sieve for Omega(n), the number of prime factors
    # counted with multiplicity.
    lp = [0] * (n + 1)
    omega = [0] * (n + 1)
    primes = []

    for i in range(2, n + 1):
        if lp[i] == 0:
            lp[i] = i
            primes.append(i)
            omega[i] = 1

        for p in primes:
            x = i * p
            if x > n or p > lp[i]:
                break
            lp[x] = p
            omega[x] = omega[i] + 1

    # Modular inverse of k.
    inv_k = pow(k, MOD - 2, MOD)

    # Omega(n) <= 16 for n <= 1e5, but 20 is a convenient safe bound.
    inv_omega = [0] * 21
    for x in range(1, 21):
        inv_omega[x] = pow(x, MOD - 2, MOD)

    f = [0] * (n + 1)
    acc = [0] * (n + 1)

    f[1] = 1

    for d in range(1, n + 1):
        if d > 1:
            f[d] = (acc[d] % MOD) * inv_k % MOD
            f[d] = f[d] * inv_omega[omega[d]] % MOD

        fd = f[d]
        od = omega[d]

        # Every a >= 2 gives m = d * a > d.
        # This contribution is part of the recurrence for f[m].
        for a in range(2, n // d + 1):
            m = d * a
            acc[m] += fd * g[a] * (omega[a] - k * od)

    print(*f[1:])

if __name__ == "__main__":
    solve()
```入力はインデックス 0 にダミー 0 を付けて保存されるため、数学的インデックス (i) と Python インデックス (i) は一致します。 これにより、繰り返しを避けることができます`i - 1`変換。 

線形ふるいは計算します`omega[i]`最小の素因数表現を使用します。 (i) に素数 (p) を掛けると、さらに 1 つの素因数が導入されます。`omega[i * p] = omega[i] + 1`。 

アキュムレータは意図的に剰余を減算しません。`MOD`最も内側のループの内側。 それぞれ`acc[m]`は、(m) の適切な約数ごとに 1 つの項のみを受け取るため、(O(\tau(m))) 項のみが含まれます。 Python の任意精度の整数は、(n\le10^5) に対してこれらの値を快適に処理できると同時に、すべての約数のペアに対するコストのかかるモジュロ演算を回避します。 

反復の開始時に、`d`、のすべての適切な約数`d`はすでにその貢献を広めています`acc[d]`。 これが、次の昇順が増加する理由です。`d`は不可欠です。 計算してから`f[d]`、それをすぐに大きなインデックスに伝播し、後の反復で必要な不変式を保持します。 

表現```
omega[a] - k * od
```意図的に負の値になることが許可されています。 最終的なモジュール化`acc[d]`負の累積値を正しく処理します。 

Python には整数オーバーフローの問題はありません。 固定幅の整数を使用する言語では、係数を取得する前に積を十分に幅の広い整数型で格納する必要があります。 

コードでは明示的にテストも行っていません。`-1`。 これらの制約の下では、分母 (k\Omega(n)) は常に素数法を法として非ゼロであるため、漸化式では常に有効な根が生成されます。

 ## 特殊なケース

 (k=1) の場合、再帰は変更なしで機能します。 と```
2 1
1 7
```(\Omega(2)=1) となり、(2) のアキュムレータは (7) になります。 分母は (1\cdot1) なので、(f(2)=7) になります。 したがって、出力は次のようになります`1 7`、必要に応じて正確に。 

素因数が繰り返される合成数の場合、(\Omega) は多重度をカウントする必要があります。 で```
4 2
1 2 2 1
```根は`1 1 1 0`。 (n=4) では、適切な約数 (d=2) が寄与します。 

[
 f(2)g(2)(\オメガ(2)-2\オメガ(2))
 =1\cdot2(1-2)=-2。 
]

 初期 (d=1) の寄与は (g(4)\Omega(4)=1\cdot2=2) です。`acc[4]=0`したがって (f(4)=0) となります。 異なる素因数の数を使用すると、(\Omega(4)=1) が誤って使用され、間違った分母が生成されます。 

許容される最大の指数については、```
2 998244352
1 1
```(k\equiv-1\pmod{998244353}) があります。 再発により得られるのは、

 [
 f(2)=1/(-1)=-1\pmod{998244353}、
 ]

 したがって、出力は`1 998244352`。 これは、入力指数が通常の正の整数として表される場合でもモジュラー逆変換が必要な理由を示しています。 

(n=1) の場合、(\Omega(1)=0) であるため再帰はなく、分母が無意味になります。 問題は (n=2) から始まり、他のインデックスを処理する前に明示的に (f(1)=1) を設定します。 これは、その後のディリクレ畳み込みごとに必要な恒等要素も提供します。 

(g) のゼロ値の可能性は特別なケースを引き起こしません。 たとえば、次のルート```
4 2
1 2 2 1
```は (f(4)=0) であり、再帰処理では他のすべての値とまったく同じように処理されます。 このアルゴリズムは (g(n)) で除算することはありません。そのため、(g) のゼロエントリは無害です。 

見かけの (-1) 出力ケースでも、指定された制約に対する特別な処理は必要ありません。 (k) は素数 (998244353) を法とする非ゼロであり、(\Omega(n)) は (n\le10^5) の素数より厳密に小さい正の整数であるため、すべての分母 (k\Omega(n)) は可逆です。 したがって、再帰により、すべての有効な入力のルートが決定されます。
