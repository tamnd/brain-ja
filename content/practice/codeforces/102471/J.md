 ## 解決策
 ## 問題の理解

 以下の数字の順列があります。`1`に`n`、および整数`c`。 操作は正確に見ます`c+1`連続ポジション。 その間隔の最小値が一方の端点にある場合、その端点は固定されたままになり、もう一方の端点は固定されます。`c`値は任意に並べ替えることができます。 

タスクは、到達可能な順列を 1 つ見つけることではありません。 このような操作を何度でも適用した後に到達できる個別の順列の合計数が必要です。答えはモジュロで求められます。`998244353`。 公式ステートメントでは、同じ 2 つのエンドポイント ケースが使用されており、1 つは左側のエンドポイントでの最小値、もう 1 つは右側のエンドポイントでの最小値です。 

決定的な役割を果たすのは、`1`。 以来`1`はグローバルに最小であるため、操作によって移動することはできません。 を含むすべての操作`1`持っている必要があります`1`そのエンドポイントとして。 したがって、を使用した操作は、`1`並べ替えることしかできません`c`すぐ左に配置するか、`c`そのすぐ右側に位置します。 

ありましょう`L`の左側の要素`1`そして`R`その右側に要素があります。 両側の演算は相互作用する必要がないため、到達可能な順列の合計数は、左側から取得できる数と右側から取得できる数の積になります。 

この制約により、指数関数または階乗アルゴリズムは不可能になります。 声明では許可されていますが、`n`まで`500000`、の合計`n`すべてのテスト ケースにわたって、最大でも`500000`。 これは、意図したソリューションが合計入力サイズにおいて本質的に線形である必要があることを意味します。 平`O(n log n)`ここでは不要ですが、`n!`可能な順列は即座に不可能になります。 

不注意な実装によって誤って処理される可能性がある、簡単な境界ケースがいくつかあります。 たとえば、次のように考えてみましょう```
1
2 2
1 2
```長さの間隔はありません`3`, そのため、操作はできません。 答えは`1`。 を治療するソリューション`c`横の位置`1`より少ない場合でも自由に変更可能`c`位置が存在すると誤って返される`2`。 

もう一つの重要な事例は、```
1
3 2
2 1 3
```値`1`は中央にあるため、両側に要素は 1 つだけあります。 どちらの面にも必要なものが含まれていません`c=2`要素。 繰り返しになりますが、答えは`1`。 という事実`1`近くの要素があるだけでは不十分です。グループ全体`c`可動要素が存在する必要があります。 

一方で、```
1
3 2
1 2 3
```の右側に 2 つの要素があります`1`。 ペア全体を並べ替えることができるため、答えは次のようになります。`2`。 これは、操作が実際に存在する最小の例です。 

入力は順列であることが保証されているため、「すべての値が等しい」テストはこの問題に対して有効なテストではありません。 このような入力は順列の定義に違反します。 実装は個別の値に依存する必要があり、特殊な場合として重複をサポートしようとすべきではありません。 

## アプローチ

 直接的なアプローチは、到達可能な順列に対して幅優先検索を実行することです。 現在のすべての順列について、長さのすべての間隔を検査します。`c+1`。 最小値が終点にある場合は常に、他のすべての順列を生成します。`c`要素を作成し、結果の配列を訪問セットに挿入します。 

これは正しいです。すべての正当な操作が明示的に列挙されており、目に見えない順列がなくなるまで BFS が続行されるからです。 問題は状態空間のサイズです。 あり得る`n!`さまざまな順列、さらにはすべての状態のすべての間隔をチェックすることさえすでにコストがかかります`O(n · n!)`。 オペレーション内で考えられるすべての再配置が明示的に生成される場合、移行作業には最大で別の要素が含まれます。`c!`。 と`n`到達`500000`、これは遠隔的には実現可能ではありません。 

周囲の構造`1`はるかに短い説明を与えます。 以来`1`決して動かないので、片側だけを考えてください。 この側に次のものが含まれているとします。`m`要素は、最も近い位置から順に並べられます。`1`外側に向かって。 

最初`c`位置は、存在する場合はいつでも並べ替えることができます。 このうち`c`位置では、1 つの要素、つまり最小の要素が区別されます。 それらの中を移動できる`c`しかし、それを逃れることはできません。 別の完全なグループが`c`位置が利用可能になると、同じ推論により、位置が最初に制限される別の区別された要素が作成されます。`2c`サイドの位置。 外側に向かって続けると、完全なグループごとに 1 つの制限された要素が作成されます。`c`ポジション。 

したがって、もし

 [
 k=\left\lfloor\frac{m}{c}\right\rloor,
 】

 まさにあります`k`ネストされた制限。 の`j`-番目の制限された要素は、最初の要素のいずれかを占有する必要があります`jc`ポジション。 これらの制限された要素を、許可されるプレフィックスの最小のものから最大のものまで数えると、`j-1`その位置は、以前の制限された要素によってすでに占められています。 したがって、`j`-th 要素には次の要素があります

 [
 jc-(j-1)=j(c-1)+1
 】

 選択肢。 

結局`k`制限された要素が配置されている場合、その他の要素は`m-k`要素には残りの制限はなく、任意に配置できます。 彼らの貢献は、`(m-k)!`。 

したがって、含む側の貢献は`m`要素は

 [
 F(m,c)=
 (m-k)!\prod_{j=1}^{k}\left(jc-j+1\right),
 \qquad
 k=\left\lfloor\frac{m}{c}\right\rloor。 
]

もし`m<c`、 それから`k=0`、与える`F(m,c)=m!`。 ただし、この式は実際の演算ルールでは間違っています。`c`要素が存在します。 その場合、正しい貢献度は次のとおりです。`1`。 したがって、私たちは使用します

 [
 F(m,c)=
 \begin{ケース}
 1,&m<c,\
 (m-k)!\displaystyle\prod_{j=1}^{k}(jc-j+1),&m\ge c.
 \end{件}
 】

 最終的な答えは単純に、

 [
 F(L,c)\cdot F(R,c)。 
】

 ブルートフォースは、組み合わせ引数が記述するのと同じ到達可能な状態空間を明示的に探索するため、機能します。 についての観察`1`この巨大な状態空間を 2 つの独立した側面と少数の入れ子になった位置制限で置き換えてみましょう。 これは、公開されたソリューションの説明で強調されているのと同じ構造観察です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n · n! · c!)`明示的な移行バージョンでは |`O(n!)`| 遅すぎる |
 | 最適 |`O(n)`テストケースごと |`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. の位置を見つけます。`1`。 ゼロベースの位置にある場合`pos`、それから、`L=pos`その左側の要素と`R=n-1-pos`その右側にある要素。 以来`1`これらの 2 つの辺は独立して数えることができます。 
2. 階乗モジュロを事前計算する`998244353`最大のものまで`n`。 最終側の式には次のものが含まれます。`(m-k)!`したがって、定数時間アクセスには階乗値が必要です。 
3. 長さの一辺の寄与を定義する`m`。 もし`m<c`、 戻る`1`を含む操作を形成するのに十分な要素がないためです。`1`そして`c`可動要素。 
4. それ以外の場合は設定します`k=m//c`。 がある`k`ネストされた制限された要素は、すべての完全なグループが存在するため、`c`位置は、識別された要素が移動できるもう 1 つのプレフィックスを作成します。 
5. 副次的な貢献を開始します。`(m-k)!`。 これらは、すべての制限された要素が考慮された後、完全に制限されないままになる要素です。 
6. あらゆる人にとって`j`から`1`を通して`k`、乗算します`jc-j+1`。 の`j`-番目の制限された要素は次のとおりです`jc`許可されたプレフィックス内の可能な位置ですが、`j-1`それらの位置のうち、すでに処理済みの制限された要素が占めています。 
7. 左側と右側の寄与を独立して計算し、剰余を乗算します。`998244353`。 両者はポジションを争わない。`1`それらを永久に分離します。 

### なぜ効果があるのか

 不変条件は、暴露後の`j`の完全なグループ`c`片側に正確に配置`j`特徴的な要素は場所が制限されており、`j`- 番目は最初の内部のどこでも許可されます`jc`ポジション。 以前に識別された要素はこれらの接頭辞の内側に残りますが、露出された領域内の他のすべての要素は自由に再配置できます。 

これらの許可された接頭辞は入れ子になっているため、制限された要素を次々に配置できます。 ステージにて`j`、 その通り`j-1`最初の内側の位置`jc`位置は以前に制限された要素によってすでに占有されているため、`jc-j+1`選択肢。 もう一度`k`制限された要素が配置され、他のすべての要素は制限されず、`(m-k)!`手配。 

操作により最小エンドポイントが固定されるため、到達可能なすべての配置はこれらの制限を満たします。 逆に、操作は、次のグループを連続的に露出することによって、入れ子になった制約を満たすすべての配置を実現できます。`c`ポジションを作成し、現在空いているすべてのポジションを並べ替えます。 したがって、この式では、到達可能なすべての順列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 998244353

def side_ways(m, c, fact):
    if m < c:
        return 1

    k = m // c
    ans = fact[m - k]

    for j in range(1, k + 1):
        ans = ans * (j * c - j + 1) % MOD

    return ans

def solve():
    t = int(input())

    tests = []
    max_n = 0

    for _ in range(t):
        n, c = map(int, input().split())
        p = list(map(int, input().split()))
        tests.append((n, c, p))
        max_n = max(max_n, n)

    fact = [1] * (max_n + 1)
    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    out = []

    for n, c, p in tests:
        pos = p.index(1)

        left = pos
        right = n - 1 - pos

        ans_left = side_ways(left, c, fact)
        ans_right = side_ways(right, c, fact)

        ans = ans_left * ans_right % MOD
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

の位置`1`で見つかります`p.index(1)`。 ゼロベースのインデックスでは、その位置はその左側の要素の数と同じになります。`n-1-pos`その右側の数字です。 

の`m<c`チェックは必須です。 の式は`k=0`与えるだろう`m!`、ただし、以下の場合`c`要素は存在しますが、それに関わる法的間隔はありません。`1`、したがって、側面は完全に変更されず、正確に貢献します`1`。 

のために`m>=c`、`k=m//c`の完全なグループをカウントします`c`ポジション。 ループは次の値を乗算します。`k`要因`jc-j+1`。 両側にわたる反復の合計数は次のとおりです。`O(n/c)`テストケースの場合、最大でも`O(n)`。 

Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`998244353`。 階乗配列には、同じ法を法とする値も格納されます。 

入力は次を使用して読み取られます`sys.stdin.readline`、合計入力サイズが大きい場合に必要なため。
