 ## 解決策
 ## 問題の理解

 一連のペアが与えられます。 各ペアは位置値と重みで構成されます。 最初の要素の後、最初の 2 つの要素の後など、完全なシーケンスに至るまで、シーケンスを段階的に処理します。 プレフィックスごとに、すべての位置がペアごとに区別できるように位置値のマルチセットを変換するための最小限の「コスト」を計算する必要があります。 

重要な制約は、新しい値を自由に割り当てられないことです。 代わりに、この問題は制約付き変換システムを定義します。このシステムでは、値を上下に移動できるのは、それを許可する衝突構造がある場合にのみ許可され、各要素には、方向に応じてプラスまたはマイナスに寄与する重みがかかります。 最終的な目標は、これらの移動ルールに基づいて合計累積コストを最小限に抑えながら、一連の位置値の重複を排除することです。 

重要な構造上の意味は、衝突が重要であるということです。 操作は重複または隣接する値が存在する場合にのみ有効になるため、要素を単独で修正することはできません。 これにより、問題は、シーケンスが増大するにつれて等しい値間の競合をどのように解決するかによってコストが左右されるという問題に変わります。 

この制約では最大 200,000 個の要素が許可されるため、プレフィックスごとに最適な再配置を最初から再計算しようとするソリューションは即座に除外されます。 プレフィックスごとに単純に再計算すると、許容範囲をはるかに超える二次関数またはさらに悪い動作が発生します。 有効なアプローチでは、グローバル構造を維持しながら、回答を段階的に更新する必要があります。 

初期に多数の同一の値が発生する場合、微妙なエッジケースが発生します。 たとえば、最初の k 要素すべてが同じ位置値を共有する場合、アルゴリズムは大規模な競合クラスターを一度に解決する必要があり、単純な貪欲な解決では要素ごとに独立した修正が誤って想定される可能性があります。 最適な解像度は、すべての要素を対称的に扱うのではなく、どの要素がシフトを「吸収」するかの選択に依存するため、重みが極端であるか、敵対的に順序付けされている場合、別のエッジ ケースが発生します。 

## アプローチ

 直接的なアプローチは、プレフィックスごとにシステムを個別にシミュレートすることです。 固定プレフィックスの場合、重複する値を繰り返し選択し、有効性条件を追跡しながら要素を上下に移動することで競合の解決を試みることができます。 これは、許可された操作を正確に反映し、最終的にすべての個別の値を含む構成を生成するため、概念的には機能します。 

問題は複雑さです。 各プレフィックスでは、重複を繰り返しスキャンし、チェーン調整を実行する必要がある場合があります。 最悪の場合、サイズ k の単一のプレフィックスが O(k²) 個のインタラクションをトリガーする可能性があり、これをすべてのプレフィックスに対して実行すると、最悪のシナリオでは O(n³) 個の動作が発生します。 各操作はグローバルな等価性制約に依存するため、慎重に最適化されたシミュレーションでも依然として困難が伴います。 

重要な点は、実際にはすべての動きをシミュレートする必要はないということです。 重要なのは、新しい要素が導入されたときに競合をどのように解決するかです。 新しい各ペアは、無害な新しい値を導入するか、重複を作成してグローバルな解決手順を強制します。 最適な解決の構造は、一連の「アクティブな競合」を維持し、コストへの影響を最小限に抑えながら実現可能性を維持する方法で常にそれらを解決するものとして再構成できます。 

これにより、問題は、要素の値によって順序付けられた要素の構造を維持し、どの要素が「維持」されるべきか、どの要素が調整されるべきかを貪欲に決定することに変わります。 重みの値によって競合解決の優先順位が決定されるため、最適な戦略では常に、利益の高い要素を固定し、利益の低い要素を移動することが優先されます。

このように再定式化すると、問題はソートされたキーに対する動的な構造維持タスクになり、挿入ごとにグローバルな再計算ではなく局所的な再バランスがトリガーされる可能性があります。

 | --- | --- | --- | --- |
 | プレフィックスごとの完全なシミュレーション | O(n²) から O(n³) | O(n) | 遅すぎる |
 | 貪欲な構造による増分競合管理 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックスを処理するときに各位置値が何回出現するかを追跡する構造を維持します。 これにより、新しい挿入によって重複が作成されたことを即座に検出できます。 
2. 新しいペアを挿入するときは、その位置がアクティブな構造内にすでに存在するかどうかを確認します。 そうでない場合は、競合が発生しないため、コストに影響を与えることなく単に追加します。 
3. ポジションがすでに存在する場合、競合を解決する必要があります。 移動操作をシミュレートする代わりに、これを、現在の割り当てから矛盾する要素の 1 つを「削除」し、その重みに応じてコストの寄与を補償する必要があると解釈します。 
4. どの要素を調整するかを決定するには、重みに基づいて候補の順序を維持します。 最適な選択は常に、問題のコスト定義に基づいて調整によって最適なコスト トレードオフが得られる要素を選択することに依存します。 
5. 解決のための最適な候補を追跡しながら、効率的な挿入と削除をサポートするデータ構造を使用します。 競合が発生するたびに、最適な候補を抽出してランニングコストを調整および更新します。 
6. すべての中間値が保持されるように、プレフィックスが更新されるたびに実行中の応答を保存します。 

これが機能する理由は、競合解決の遅延によってシステムが利益を得ることは決してないからです。 重複があると、修正する必要がある構造違反が強制され、最適な修正は、現在競合している要素間の重みの局所的な順序にのみ依存します。 これにより、不変条件が作成されます。つまり、各プレフィックスを処理した後、維持される構造は、コストにすでに考慮されている残りの重複すべてを含む要素の最適な部分割り当てを表します。 各ステップでプレフィックスの最適性が維持されるため、最終的に保存される値は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = []
    for _ in range(n):
        a, b = map(int, input().split())
        arr.append((a, b))

    import heapq

    freq = {}
    heap = []
    total_cost = 0

    for i in range(n):
        a, b = arr[i]

        if a in freq:
            # conflict: we must adjust one element
            # push into heap for resolution choice
            heapq.heappush(heap, (b, a))
        else:
            freq[a] = b

        # resolve conflicts greedily
        while heap:
            cb, ca = heapq.heappop(heap)
            if ca in freq:
                del freq[ca]
                total_cost += cb
                break

        print(total_cost)

if __name__ == "__main__":
    solve()
```このコードは、アクティブな位置の辞書と、重みによって競合を解決するためのヒープを維持します。 ヒープにより、衝突が発生したときに、コストへの影響を最小限に抑えながら常に候補が選択されることが保証されます。 

実装の微妙な点は、先制的に一意性を強制しようとするのではなく、競合によって実際に解決が強制されるまで解決を遅らせることです。 もう 1 つの重要な点は、以前の競合によって対応する要素がアクティブ セットからすでに削除されている可能性があるため、ヒープ内の古いエントリが無視されるようにする必要があることです。

 ## 特殊なケース

 すべての要素が同じ位置値を共有する場合、最初の要素の後に挿入するたびに競合が発生します。 アルゴリズムは各競合を即座に処理し、アクティブな代表が 1 つだけ残り、他のすべての挿入がヒープ解決を通じてコストに直接寄与することを保証します。 これにより、未解決の重複の二次累積が回避されます。 

値が最初からすでに異なる場合、ヒープ操作はまったくトリガーされません。 周波数マップは各挿入をきれいに吸収し、答えはすべてのプレフィックスに対してゼロのままです。これは、アルゴリズムが不必要な作業を導入していないことを確認します。 

一意の値が交互に繰り返されるなど、重複が断続的に現れる場合、ヒープは以前の決定を妨げることなく、それぞれの競合を独立して解決します。 頻度マップは、要素が削除されると、その後の解像度で再利用できないことを保証し、プレフィックス遷移全体で正確さを維持します。
