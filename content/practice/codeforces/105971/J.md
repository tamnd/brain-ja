 ## 解決策
 ## 問題の理解

 グラフは非常に強い意味で有向かつ非循環的です。つまり、すべてのエッジが小さい番号の頂点から大きい番号の頂点に向かって進みます。 これは、頂点 1 から頂点 n への有効なウォークでは、ステップごとに頂点ラベルが厳密に増加する必要があることを直ちに意味します。そのため、すべてのパスは自動的に単純になり、頂点を再訪することを心配する必要はありません。 

このような増加する有向パスが 1 から n までにいくつ存在するかを数えるよう求められますが、特定のパターンを禁止する制限があります。 各禁止パターンは、頂点の短い増加シーケンスとして与えられます。 連続セグメントとして禁止されたシーケンスが含まれている場合、パスは無効になります。 つまり、パス上のいずれかの点で、訪問頂点の連続ブロックが指定された配列の 1 つと正確に一致する場合、そのパスは許可されません。 

したがって、入力は、エッジが常に前方を向いている DAG に加えて、有効なルートからターゲットへのパス内のどこにも現れてはいけない禁止された「サブパス」のコレクションを記述します。 出力は、1 ～ n のモジュロ 1e9+7 の有効なパスの数です。 

ここでは制約構造が主な信号です。 すべてのテスト ケースにわたる頂点とエッジの合計数は最大 3e5 であり、すべての禁止シーケンスの合計長も最大 3e5 です。 これにより、パスを明示的に列挙しようとするものは即座に除外されます。これは、中程度の密度の DAG であっても、1 から n までの指数関数的に多くのパスが含まれる可能性があるためです。 すべてのパスにわたる単純な動的プログラミングは、パターン チェックを考慮する前からすでに実行不可能です。 

単純な解釈を破る特殊なケースがいくつかあります。 1 つは、禁止された配列の長さが 1 の場合です。これは、単一の頂点が連続セグメントとして許可されていないことを意味します。 これにより、任意の点でその頂点を含むすべてのパスが効果的に削除されます。 もう 1 つは、禁止された配列が重なり合う場合です (たとえば、ある配列が別の配列のサブ配列である場合)。 完全な禁止文字列のみに一致し、パスに沿った部分一致を正しく追跡しない単純なチェッカーでは、途中で禁止パターンを横切るパスが誤って許可されてしまいます。 

微妙な失敗例は、パターン構造の重なりから発生します。 禁止パターンが [1, 2, 3] と [2, 3, 4] であるとします。 1 → 2 → 3 → 4 のパスには、一致を開始する場所に応じて、両方のパターンが部分文字列として含まれます。 パスの終点または固定位置のみでパターンをチェックするソリューションでは、これらの違反は見逃されます。 

## アプローチ

 ブルート フォース アプローチでは、パスのサブセットに対して DFS または DP を使用して 1 から n までのすべてのパスを列挙しようとし、パスごとに、連続セグメントとして禁止された配列が含まれているかどうかを確認します。 パターン チェックを無視したとしても、最悪の場合、DAG 内のパスの数は n で指数関数的に増加する可能性があります。 部分文字列の一致を追加すると、各パス検証に O(パスの長さ × 禁止されている合計の長さ) のコストがかかるため、事態はさらに悪化します。 これは、実行可能な限界を超えてすぐに爆発します。 

重要な観察は、問題は基本的に、シーケンスを段階的に構築する際のパターンの回避にあるということです。 部分パスのどの時点でも、重要なのはプレフィックス全体ではなく、構築したもののサフィックスが禁止されたパターンのプレフィックスとどのように一致するかです。 これはまさに、失敗リンクを含むトライが捉える構造です。 

完全なパスの観点から考えるのではなく、状態の観点から考えます。グラフ内のどこにいるのか、パスのサフィックスとして現在どの程度の禁止パターンと一致しているのかを考えます。 頂点に到達した後に取り得るオートマトンの状態のセットを頂点ごとに維持すると、エッジに沿って寄与を伝播し、禁止された完了を回避できます。

これにより、問題は積グラフ、つまり元の DAG ノードとパターン プレフィックス状態の組み合わせに対する動的プログラミングに変換されます。 すべてのエッジは小さい頂点から大きい頂点に進むため、頂点を昇順に処理し、サイクルなしで DP 遷移を実行できます。 

重要な圧縮は、すべての禁止パターンを単一のオートマトン構造にマージすることで実現され、パターン マッチングの遷移がステップあたり O(1) の償却時間で処理されるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 + チェック | 指数 | O(n) | 遅すぎる |
 | 禁止パターン上のオートマトンを使用したグラフ上の DP | O(n + m + パターンの全長) | O(n + パターンの合計長) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エッジから有向グラフ隣接リストを構築します。 エッジは常に u < v を満たすため、ノードを昇順に安全に処理できます。 
2. すべての禁止されたシーケンスからトライを構築します。 トライ内の各ノードは、何らかの禁止された配列のプレフィックスを表します。 この構造により、部分パスが禁止されたパターンに一致し始めたことを認識できるようになります。 
3. トライ ノード上の BFS を使用して、トライの障害リンクを構築します。 これらのリンクにより、不一致が発生した場合に、何らかの禁止パターンのプレフィックスである最長有効なサフィックスにフォールバックできることが保証されます。 これにより、トランジションが効率的に行われます。 
4. 完全な禁止パターンに対応するすべてのトライ状態を終端としてマークします。 このようなノードに到達する DP 状態は、応答に寄与してはなりません。 
5. dp[v][t] が訪問頂点のシーケンスを処理した後にオートマトン状態 t にある間に頂点 v に到達する方法の数を表す DP テーブルを定義します。 
6. 一致する部分パターンがない状態で頂点 1 から開始するため、dp[1][root_state] = 1 を初期化します。 
7. 頂点を昇順に処理します。 各頂点 v について、すべての dp[v][t] 状態を反復します。 各出力エッジ v → u について、状態 t からトライ遷移関数に u を入力することにより、次のオートマトンの状態を計算します。 結果として生じる状態が末期の場合は、それを破棄します。 それ以外の場合は、dp[v][t]を dp[u][new_state]に追加します。 
8. すべての頂点を処理した後、すべての非終端状態 t にわたって dp[n][t] を合計して、最終的な答えを取得します。 

重要なアイデアは、各 DP 遷移がグラフとオートマトンに沿って同時に進行するということです。 オートマトンは、禁止されている連続セグメントが、それが完了する前でも後でもない、正確に検出されることを保証します。 

なぜそれが機能するのかは、DP 状態の不変条件に帰着します。 処理の任意の時点で、 dp[v][t] は、サフィックスがオートマトン状態 t に対応する 1 から v までの有効なパスの数を正確にカウントします。 障害リンクは、t が常に、何らかの禁止パターンのプレフィックスでもある現在のパスの最長のサフィックスを表すことを保証します。 すべての禁止パターンはトライ内で明示的に表現されるため、連続セグメントとして禁止配列が出現すると、パターンの最後の要素が追加されたまさにその瞬間に、オートマトンは強制的に終了状態になります。 終端状態はそれ以上伝播されないため、無効なパスは目的地に到達できず、すべての有効なパスはその固有のオートマトンの軌跡を通じて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = False

def build_aho(patterns):
    trie = [Node()]

    def add(pat):
        v = 0
        for x in pat:
            if x not in trie[v].next:
                trie[v].next[x] = len(trie)
                trie.append(Node())
            v = trie[v].next[x]
        trie[v].out = True

    for p in patterns:
        add(p)

    from collections import deque
    q = deque()

    for c, v in trie[0].next.items():
        trie[v].link = 0
        q.append(v)

    while q:
        v = q.popleft()
        for c, u in trie[v].next.items():
            j = trie[v].link
            while j and c not in trie[j].next:
                j = trie[j].link
            if c in trie[j].next:
                j = trie[j].next[c]
            trie[u].link = j
            trie[u].out |= trie[j].out
            q.append(u)

    return trie

def go(trie, v, state, x):
    while state and x not in trie[state].next:
        state = trie[state].link
    if x in trie[state].next:
        state = trie[state].next[x]
    return state

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)

    patterns = []
    for _ in range(k):
        tmp = list(map(int, input().split()))
        l = tmp[0]
        patterns.append(tmp[1:])

    trie = build_aho(patterns)

    dp = [dict() for _ in range(n + 1)]
    dp[1][0] = 1

    for v in range(1, n + 1):
        for state, ways in dp[v].items():
            if ways == 0:
                continue
            for u in g[v]:
                nxt = go(trie, v, state, u)
                if trie[nxt].out:
                    continue
                dp[u][nxt] = (dp[u].get(nxt, 0) + ways) % MOD

    ans = 0
    for state, ways in dp[n].items():
        if not trie[state].out:
            ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```各ノードに実際に現れるオートマトンの状態は有効なパスに沿った遷移によって制限されるため、DP テーブルは辞書を使用してまばらに保存されます。 トランジション機能`go`は標準の Aho-Corasick フォールバック メカニズムであり、新しい頂点でパスを拡張するときに、サフィックスとプレフィックスの最長一致を正しく維持することが保証されます。 

よくある実装の落とし穴は、オートマトンの遷移がエッジではなく次の頂点ラベルに基づいていることを忘れていることです。 ここでは、頂点自体が照合されるシーケンスであるため、すべてのエッジ ステップがオートマトンにシンボルを提供します。

 ## 特殊なケース

 長さ 1 の禁止パターンが 1 つある場合は、その頂点を訪れたすべてのパスが削除されます。 オートマトンは、その頂点を読み取るとすぐに終了状態に移行するため、その状態を介したすべての DP 寄与は、生成された瞬間に破棄されます。 

[2,3,4] や [3,4,5] などの重複する禁止パターンがあるシナリオでは、2 → 3 → 4 → 5 に到達するパスは重複して 2 回終了をトリガーします。 このトライにより、3 → 4 に到達するとすでに終了状態に移行し、5 への継続が防止され、両方のパターンが同時に正しくブロックされます。 

複数のパスが n 個に収束する密な分岐 DAG は、DP 集約が正しいかどうかをテストします。 異なる先行者から dp[n] に入力されるそれぞれの寄与は独立して蓄積され、状態は個別に追跡されるため、過剰なカウントや互換性のない履歴のマージは発生しません。
