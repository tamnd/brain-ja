 ## 解決策
 ## 問題の理解

 トーナメントには、`n`チーム。 すべてのチームのペアが 1 回プレーし、そのチームがプレーする確率`i`チームを破る`j`チームの強さのみに依存します。つまり、より強いチームが勝つ可能性が高くなりますが、どちらの結果になる可能性もあります。 勝利の連鎖を通じて他のすべてのチームに到達できた場合、チームは勝者とみなされます。つまり、直接的または間接的な勝利がカウントされます。 

タスクは、考えられるすべてのトーナメント結果からそのような勝者の予想される数を見つけることです。 

入力により、チームの数と各チームの強さがわかります。 出力は予想される勝者の数を法的に計算したものです。`10^9 + 7`。 確率は分数であるため、計算には逆モジュラーが必要です。 

チーム数も少ないので、`n`最大 14 です。これにより、考えられるすべてのトーナメントのシミュレーションが除外されます。`2^(n*(n-1)/2)`起こり得る結果は、あまりにも急速に増加します。 しかし、`2^n`サブセットはまだ管理可能です。`2^14 = 16384`、したがって、サブセット動的プログラミングアプローチが意図された方向です。 

難しいのは、何がチームのセットを勝利セットにするのかを理解することです。 よくある間違いは、最も強いチームが常に勝者であると想定することです。 サイクルが存在する可能性があるため、弱いチームでも、強力なチームと同じ強く接続されたコンポーネントに属することができます。 

たとえば、強みを持つ 3 つのチームを考えてみましょう。`[1, 1, 1]`。 すべての試合の結果は同様に起こります。 考えられる結果は、チーム 1 がチーム 2 に勝ち、チーム 2 がチーム 3 に勝ち、チーム 3 がチーム 1 に勝つというサイクルです。1 つのチームだけではなく、3 つのチームすべてが勝者となります。 

もう 1 つの特殊なケースは、単一チームです。 試合はなく、唯一のチームがすべてのチームに簡単に到達できます。 入力の場合:```
1
5
```答えは次のとおりです。```
1
```チームが試合に勝つかどうかだけをチェックするソリューションでは、誤ってゼロが返されます。 

## アプローチ

 強引なアプローチでは、あらゆるトーナメントが発生します。 生成されたグラフごとに、すべてのチームからグラフの走査を実行し、他のすべてのチームに到達できるチームの数をカウントできます。 これは正しいです。なぜなら、勝者の定義は、直接トーナメント グラフにおける到達可能性であるからです。 

問題は大会数だ。 と`n`チーム、あります`n * (n - 1) / 2`すべてのゲームには 2 つの結果があります。 したがって、可能なグラフの数は次のようになります。`2^(n*(n-1)/2)`。 のために`n = 14`、これはもう`2^91`、それは不可能です。 

重要な観察は、勝者は常に厳密に 1 つの強く接続されたコンポーネントを形成するということです。 チームのセットが勝者セットの場合、そのセットの外側にあるすべてのチームは、そのセット内のすべてのチームに対して負ける必要があります。 そうしないと、外部チームが優勝コンポーネントに到達し、優勝者になる可能性があります。 

これにより、サブセットごとに答えを構築する方法が得られます。 各サブセットが勝者の強連結成分である確率を計算します。 サブセットの場合、それが勝利コンポーネントである確率は、そのサブセットが内部的に強く接続されており、外部のすべてのチームに勝つ確率と等しくなります。 

すべてのサブセットの強力な接続を直接確認するのは依然として不便です。 代わりに、サブセット サイズが増加する際の確率を計算します。 サブセットの場合`S`、すべてのチームが参加する確率から始めます。`S`外にいる全員を殴る`S`。 次に、実際の勝利コンポーネントがより小さいサブセットであるケースを減算します。`S`。 

勝者が内側にセットした場合、反復は機能します。`S`適切なサブセットです`T`、 それから`T`の残りのチームに勝たなければなりません`S`に必要な条件とまったく同じです。`T`フルトーナメントで勝者となること。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^(n^2))`|`O(n^2)`| 遅すぎる |
 | 最適 |`O(3^n + n^2 * 2^n)`|`O(2^n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 強みを読み取り、すべてのチームが他のすべてのチームに勝つ確率を事前計算します。 の値`i`殴る`j`は`a[i] / (a[i] + a[j])`モジュラー演算の下で。 
2. 事前計算`win[mask]`、すべてのチームが内部にいる確率`mask`外のチームをすべて倒す`mask`。 

固定サブセットの場合、これはサブセットからその補数までのすべてのクロス エッジの積です。 同じサブセット クエリが繰り返し現れるため、これらの値を保存すると再計算が回避されます。 
3. チーム数の昇順にサブセットを処理します。 すべてのサブセットについて`mask`、初期化します`dp[mask]`と`win[mask]`。 

これは、サブセット全体が勝者コンポーネントであるというイベントを表し、その一部のみが強く接続されている可能性は無視されます。 
4. 空ではないすべての適切なサブマスクを反復処理します。`sub`の`mask`。 次のようなケースを削除します。`sub`実際の勝者コンポーネントです。 

削除された投稿は次のとおりです。`dp[sub] * probability(sub beats mask - sub)`なぜなら、より小さなコンポーネントがこのサブセットの残りのチームを支配する必要があるからです。 
5. 小さなコンポーネントをすべて取り外した後、`dp[mask]`まさにその確率になる`mask`勝者のコンポーネントです。 追加`popcount(mask) * dp[mask]`答えに。 

不変条件は、サブセットを計算した後、`dp[mask]`という確率が含まれています`mask`それ自体は、トーナメントの順序付けにおける最初の強く関連したコンポーネントです。 小規模な勝利コンポーネントはすでに考慮されて削除されているため、無効なケースは残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    inv = [0] * (2 * 10**6 + 1)
    for i in range(1, 2 * 10**6 + 1):
        inv[i] = pow(i, MOD - 2, MOD)

    prob = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                prob[i][j] = a[i] % MOD * inv[a[i] + a[j]] % MOD

    total = 1 << n
    win = [1] * total

    for mask in range(total):
        cur = 1
        for i in range(n):
            if mask >> i & 1:
                for j in range(n):
                    if not (mask >> j & 1):
                        cur = cur * prob[i][j] % MOD
        win[mask] = cur

    dp = [0] * total
    ans = 0

    for mask in range(1, total):
        cur = win[mask]
        sub = (mask - 1) & mask
        while sub:
            if sub != mask:
                cur -= dp[sub] * win[sub | 0] % MOD * 0
                cur %= MOD
            sub = (sub - 1) & mask

        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if other:
                cur -= dp[sub] * get_cross(sub, other, prob, n) % MOD
                cur %= MOD
            sub = (sub - 1) & mask

        dp[mask] = cur
        ans = (ans + cur * (mask.bit_count())) % MOD

    print(ans)

def get_cross(a, b, prob, n):
    res = 1
    for i in range(n):
        if a >> i & 1:
            for j in range(n):
                if b >> j & 1:
                    res = res * prob[i][j] % MOD
    return res

if __name__ == "__main__":
    solve()
```実装はサブセットの繰り返しに直接続きます。 確率行列は、すべてのペアごとの勝利確率を 1 回保存し、モジュラー逆計算の繰り返しを回避します。 

の`win`配列には、サブセットがその外側のすべてを支配する確率が格納されます。 動的プログラミング段階では、可能な限り小さな勝者コンポーネントが減算されます。 

2 つのネストされたサブセット ループはコストがかかる部分です。 彼らは、`3^n`すべてのチームが現在のサブセット内、より小さなサブコンポーネント内、または両方の外に存在する可能性があるため、複雑になります。 これは許容できる理由です`n`まだ14歳です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース |`O(2^n + n^2)`| サブセット確率とペアごとの勝利確率を保存します。

 ## 特殊なケース

 単一チームの場合、そのチームを含むサブセットには外部の対戦相手はいません。 その優勢確率は 1 であり、動的計画法値は 1 のままです。 答えは、それ自体から到達できるのはチームだけであるため、1 を追加します。 

強さが同じであれば、どのチームも有利ではありません。 このアルゴリズムは、最強のチームが存在することを前提としていません。 サブセットの反復を通じて、考えられるすべての強く接続されたコンポーネントのサイズをカウントし、複数のチームが勝者となるトーナメントを正確にキャプチャします。 

強さが非常に不平等な場合、より強いチームが優位に立つ可能性が非常に高くなりますが、それでも場合によっては弱いチームが勝つこともあります。 確率の計算では浮動小数点値の代わりにモジュラー演算を使用するため、小さな確率が正確に保存されます。
