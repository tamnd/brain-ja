 ## 解決策
 ## 問題の理解

 パターン文字列が与えられています`S`とテキスト文字列`T`。 から`T`、すべての連続した部分文字列を考慮します。 このような部分文字列ごとに`X`、そのレーベンシュタイン距離を計算します。`S`これは、ある文字列を別の文字列に変換するために必要な挿入、削除、または置換の最小数を意味します。 

単一の答えを求める代わりに、次の部分文字列がいくつあるかを数えるように求められます。`T`正確に距離がある`0`、 その通り`1`、などまで`k`。 2 つの部分文字列は位置によって区別されるため、異なる場所に出現する同一の文字シーケンスは別々に寄与します。 

キースケールの問題は入力サイズに起因します。 両方`S`そして`T`最大 100,000 文字にすることができ、`k`は最大 30 です。動的プログラミングによる単純な比較は、次のとおりです。`S`そしてそのすべての部分文字列`T`二次数の部分文字列境界にわたって計算を繰り返す必要がありますが、これは直ちに実行不可能です。 たとえレーベンシュタイン DP が 1 つであっても、`O(|S||T|)`、そして部分文字列ごとにそれを行うことは制限をはるかに超えています。 

各部分文字列を個別に扱い、DP を介して編集距離を計算したいという単純な誘惑があります。 もう 1 つのよくある間違いは、状態空間の境界を設定せずにウィンドウをスライドさせて DP を更新しようとすることです。これは、定時更新を可能にする方法での拡張下では編集距離が単調ではないため、静かに中断されます。 

誤った推論を明らかにする小さな特殊なケースは、次のような場合です。`S = "a"`そして`T = "aaaa"`。 部分文字列は次のとおりです。`"a"`、`"aa"`、`"aaa"`、`"aaaa"`、など。距離は次のとおりです。`0`、`1`、`2`、`3`同じ長さの部分文字列のみが重要であると仮定するアプローチは、挿入と削除が優先されるため、すぐに失敗します。 

もう 1 つのエッジケースは次のような場合です`S`部分文字列よりもはるかに長いです。 例えば、`S = "abcde"`そして`X = "a"`。 距離は 4 ではなく、4 削除ですが、配置によっては置換の方が安くなる場合もあります。 長さの違いのみに基づいた推論は置換構造を見逃します。 

主な困難は、次のすべての部分文字列を処理しなければならないことです。`T`編集距離の計算を局所化して境界を維持しながら、`k`。 

## アプローチ

 ブルートフォースソリューションは部分文字列を修正します`[l, r]`の`T`そしてレーベンシュタイン距離を計算します`S`標準DPを使用します。 このような各計算コストは`O(|S| * (r-l+1))`あるいは、単純に行うとさらに悪いことになります。`O(|T|^2)`部分文字列。 これにより、最悪の場合の複雑さが発生します。`O(n^3)`には全く使えません。`n = 10^5`。 

サブストリングごとの DP を最適化したとしても、`O(|S| * k)`対角線を切り捨てることによって、部分文字列の数は 2 次のままになるため、依然として制限を桁違いに超えています。 

重要な構造的観察は、これよりも大きな距離は決して必要ないということです。`k`。 編集距離を超えると`k`、私たちが気にするのは、それが「大きすぎる」ということだけなので、その状態の追跡を停止できます。 これにより、完全な動的プログラミング テーブルが帯域制限されたプロセスに変換されます。 

各部分文字列の距離を個別に計算する代わりに、視点を逆転させます。つまり、開始位置を固定します。`T`、右のエンドポイントを段階的に拡張します。 各開始位置について、間の編集距離を追跡する DP 状態を維持します。`S`および現在の部分文字列プレフィックス`T`ただし、境界のある幅の範囲内に限ります。`k`。 

これにより、問題は、スライディング ウィンドウ上でローリング編集距離 DP を維持することに変わります。`T`、距離を超えた剪定を伴う`k`。 DP 状態は次のように進化します。`O(k)`文字拡張子ごとに、現在の最適距離が範囲内に収まる部分文字列のみをカウントします。`[0, k]`。 

重要なのは、レーベンシュタイン DP は挿入、削除、置換の 3 つの遷移のみに依存するということです。 注目をコスト ≤ k の状態に限定すると、DP 行列の狭い対角バンドのみが維持されます。これは、位置合わせが大きくずれると編集が多すぎるためです。

 ## アルゴリズムのチュートリアル

 編集距離の計算を、1 つの軸が次のようなグリッド内の最短パスとして再解釈します。`S`もう 1 つは現在の部分文字列です`T`。 各移動は挿入、削除、または置換に対応し、それぞれのコストは 1 です。コストが 1 を超えるパスを探索することはありません。`k`。 

加工いたします`T`左から右に、各位置を多くの部分文字列の潜在的な終点として扱います。 

1. 各開始インデックスについて`l`で`T`、DP配列を初期化します`dp`どこ`dp[j]`間の最小編集距離を表します。`S[0:j]`そして空の文字列、これは単に`j`。 上記の値はすぐに切り捨てられます`k+1`「大きすぎる」ことを意味するセンチネル値に。 

この初期化は、文字を読み取る前にそれを反映します。`T`、のプレフィックスとのマッチング`S`削除だけが必要です。 

1. 反復処理によって部分文字列を拡張します。`r`から`l`に`n-1`、2 番目の DP 配列を更新します`ndp`挿入に基づいて`T[r]`。 

それぞれについて`i`で`S`から遷移を計算します。`dp[i]`、`dp[i-1]`、 そして`ndp[i-1]`それぞれ削除、置換、挿入に対応します。 これは標準的なレーベンシュタイン回帰ですが、すべての結果を次のように固定します。`k+1`。 

これが機能する理由は、部分文字列の各拡張では 1 文字だけが追加されるため、追加される DP 列は 1 つだけであるためです。 

1. 計算後`ndp`、チェックします`ndp[m]`どこ`m = |S|`。 この値は、次の間の編集距離です。`S`そして`T[l:r+1]`。 ≤ k の場合、その距離の答えを増分します。 

これは有効です。`(l, r)`ペアは 1 つの部分文字列にのみ対応します。 

1. すべての値が`ndp`超える`k`、これを延長するのはやめます`l`、これ以上延長しても距離は増加または維持されるだけであるため、すでに許可された帯域を超えているために、しきい値よりも短くしないでください。 

この枝刈りにより、実際には二次関数の爆発が防止されます。 

### なぜ効果があるのか

 各遷移は 1 つの有効な編集操作に正確に対応するため、DP 状態は常に、現在の部分文字列に制限されたプレフィックスの正しい最小編集距離を表します。 上記のクランプ値`k+1`値 ≤ k を生成する最適なパスは、k を超える中間状態に決して依存しないため、すべての結果 ≤ k の正確性が維持されます。 したがって、大きな状態を破棄しても、必要な範囲内の到達可能な最適解には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input().strip())
    S = input().strip()
    T = input().strip()

    n, m = len(T), len(S)
    INF = k + 1

    ans = [0] * (k + 1)

    for l in range(n):
        dp = list(range(m + 1))
        dp = [min(x, INF) for x in dp]

        if dp[m] <= k:
            ans[dp[m]] += 1

        for r in range(l, n):
            ndp = [0] * (m + 1)
            ndp[0] = min(dp[0] + 1, INF)

            for i in range(1, m + 1):
                cost_del = dp[i] + 1
                cost_ins = ndp[i - 1] + 1
                cost_sub = dp[i - 1] + (S[i - 1] != T[r])

                ndp[i] = min(cost_del, cost_ins, cost_sub, INF)

            dp = ndp

            if dp[m] <= k:
                ans[dp[m]] += 1

            if min(dp) > k:
                break

    for i in range(k + 1):
        print(ans[i])

if __name__ == "__main__":
    solve()
```このソリューションは、可能なすべての開始インデックスを反復処理します。`T`そして部分文字列を右に段階的に拡張します。 DP アレイ`dp`のプレフィックスに対して編集距離を追跡します`S`。 繰り返しは、削除、挿入、および置換のコストを直接エンコードします。 クランプは`k+1`必要なしきい値までの意味のある状態のみを区別できるようにします。 

早期停止条件`min(dp) > k`重要です。 すべての部分調整コストが超過すると、`k`、これ以上拡張しても、より短い距離の有効な部分文字列を復元できないため、続行しても計算が無駄になるだけです。

| r | 部分文字列 | dp[m] | 解釈 |

 これは、編集距離が局所的な不一致のみに依存するのではなく、グローバルな位置合わせ構造に依存することを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`S`単一の文字であり、`T`繰り返される同じ文字で構成されます。 この場合、すべての部分文字列には長さの違いのみに基づいて予測可能な線形編集距離があり、DP は置換を必要とせずに挿入を正しく蓄積します。 アルゴリズムはこれを処理します。`r`増加する`dp[m]`文字が一致しない場合、または挿入が必要な場合は 1 つだけ増加し、切り捨ては値 ≤ k に影響を与えることはありません。 

もう 1 つのエッジケースは次のような場合です`k = 0`。 間の完全一致のみ`S`と部分文字列`T`数えるべきだ。 DP は正確な部分文字列一致に削減され、早期の枝刈りによって不一致が即座に拒否され、実質的にローリング完全一致 DP のように動作します。 

3 番目のエッジケースは次の場合に発生します。`|S|`大きいですが`T`小さいです。 DP は削除の多い状態を正しく初期化し、アルゴリズムはほとんどの部分を削除する部分文字列をカウントします。`S`低コストで、長さが大幅に異なる場合でも正確さを保証します。
