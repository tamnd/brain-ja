 ## 問題の理解

アイテムを処理するとき、現在のプレフィックスの合計によって、グローバル予算でそのアイテムの「支払い」が可能な額が決まります。$k$。 アイテムの前のプレフィックスの合計とそのフルサイズを超えない場合$k$、レベルでアイテムのボーナスを完全に適用できます$p_i$。 プレフィックスの合計がすでに少なくとも$k$、アイテムは何も貢献しません。 それ以外の場合、部分的な金額のみが適用され、ボーナスは残りの容量に正確に対応します。$k$。 

重要な決定は項目の並べ替えです。 注文が異なると各ステップでプレフィックスの合計が変化し、各項目が完全に寄与するか、部分的に寄与するか、まったく寄与しないか、またどのインデックスが寄与するかが変化します。$w_{i,j}$が使用されます。 

タスクは、収集されたボーナスの合計を最大化することです。

微妙なエッジの動作は部分的な消費から生じます。アイテムはちょうど境界で「切断」される可能性があります。$k$、それによってどちらが決まるか$w_{i,j}$が使用されます。 単純に貪欲なアプローチは失敗します。$p_i$早いか遅いかは、将来の可用性だけでなく、どのインデックスが$w_{i,j}$アイテムごとにトリガーされます。

## アプローチ

ただし、$n!$順列。 たとえ$n = 12$、これはすでに実行可能な限界を超えています。 各シミュレーションの費用$O(n)$、与える$O(n \cdot n!)$、それは完全に不可能です。 

重要な観察点は、このプロセスは、すでに処理されたアイテムの ID には依存せず、これまでに消費された合計サイズのみに依存しているということです。 順序を修正したら、各ステップで現在の合計のみを考慮します。$s$、項目の選択が変わります$s$による$p_i$。 これは、プレフィックス合計に対するナップザックのような DP を示唆しています。 

この問題を、合計を合計する一連の増分を選択するのと同等の順序を選択するものとして再解釈します。$k$、現在の合計と比較して各アイテムがいつ配置されるかに応じて報酬の貢献を最大化します。 以来$p_i \le 10$、各項目は状態をわずかにシフトするだけであり、合計サイズの累積に基づいて DP 遷移を構造化できます。 

これまでに蓄積された合計サイズと使用されたアイテムの数に対して DP を定義します。 ただし、どのアイテムが直接使用されたかを追跡するのは大きすぎます。 代わりに、各アイテムの寄与が、それが配置される最終的なプレフィックスの合計にのみ依存するという事実を利用します。 これにより、総消費容量の状態に対して最良優先の方法でアイテムを処理するように変換できます。 

標準的なソリューションは、DP オーバー ナップザック容量で項目を処理することであり、増加するプレフィックスに応じて各項目のスケジュールを決定します。 各州$dp[s]$現在のプレフィックス合計が次の場合に達成可能な最大報酬を表します。$s$, 次にアイテムを配置してみます。 

アイテムを置くとき$i$状態で$s$、次のように決定します。

これは本質的に、状態の層状グラフ上の最短パスのような DP です。$0 \to k$、各項目は状態間の遷移を引き起こします。

 ## アルゴリズムのチュートリアル

 1. サイズの DP 配列を初期化します。$k+1$、 どこ$dp[s]$いくつかのアイテムを処理し、累積サイズに達した後に達成可能な最大合計ボーナスを格納します$s$。 すべての値は負の無限大として始まります。$dp[0] = 0$。 これは、項目を選択する前に開始することを表します。 
2. 各項目を順序の任意の時点に配置できるように、項目を 1 つずつ繰り返します。 これを達成するために、項目ごとに、すべての状態に対して降順で DP 緩和を実行します。$s$、同じアイテムの複数の使用を防ぎます。 
3. 州ごとに$s$、次の状態を計算します$s' = \min(k, s + p_i)$。 これは、アイテムが配置されたときにプレフィックスの合計がどのように増加するかをモデル化します。 
4. に応じて報酬貢献度を計算します。$s$。 もし$s \ge k$、バッファがすでに使い果たされているため、貢献度は 0 です。 
5. もし$s + p_i \le k$、 追加$w_{i,p_i}$。 これは、アイテムが残りの容量内で完全にカバーされていることに対応します。 
6. それ以外の場合は、残りの容量を計算します$r = k - s$そして追加します$w_{i,r}$、アイテムは境界で部分的にカットされているためです。 
7.アップデート$dp[s'] = \max(dp[s'], dp[s] + \text{contribution})$。 
8. すべての項目を処理した後、答えはすべての dp 状態の最大値になります。 

### なぜ効果があるのか

 DP 状態は、総消費容量のみをエンコードします。これは、将来のアイテムの評価方法に影響を与える唯一のグローバル数量です。 各トランジションは、特定のアイテムを順序の次に配置することをシミュレートします。 すべての順列はアイテム配置のシーケンスに対応し、すべての配置は DP 遷移として表されるため、すべての有効な順序が暗黙的に探索されます。 

反復の減少$s$各アイテムが DP レイヤーごとに最大 1 回使用されることを保証し、アイテムの ID 状態を明示的に追跡することなく正確さを維持します。 これにより、各項目が構築されたシーケンス内で 1 回だけ寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    items = []
    for _ in range(n):
        tmp = list(map(int, input().split()))
        p = tmp[0]
        w = tmp[1:]
        items.append((p, w))

    dp = [-10**18] * (k + 1)
    dp[0] = 0

    for p, w in items:
        ndp = dp[:]
        for s in range(k + 1):
            if dp[s] < 0:
                continue

            if s >= k:
                gain = 0
                ns = k
            else:
                if s + p <= k:
                    gain = w[p - 1]
                else:
                    gain = w[k - s - 1]
                ns = min(k, s + p)

            ndp[ns] = max(ndp[ns], dp[s] + gain)

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 配列は、消費される可能性のあるプレフィックス合計ごとに、達成可能な最高の報酬を追跡します。 移行では、完全寄与、部分寄与、ゼロ寄与のケースが定義どおりに注意深く区別されます。 コピーした配列の使用`ndp`同じ反復内で繰り返し連鎖するのではなく、各項目が順序付けレイヤーごとに 1 回使用されるようにします。 

微妙な実装ポイントは、インデックス作成です。$w$。 Pythonは0ベースなので、$w_{i,j}$としてアクセスされます`w[j-1]`。 部分的なケースでは、`k - s - 1`残りの容量を正しいインデックスに変換します。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$k = 0$。 DP は次から始まります$dp[0]$, しかし、すべてのアイテムはすぐに「すでにいっぱい」のカテゴリーに分類され、何も貢献しません。 すべての遷移がチェックされるため、アルゴリズムがこれを処理します。$s \ge k$そしてゼロゲインを割り当てます。 

もう 1 つのケースは、アイテムのサイズが早期に残容量を超える場合です。 例えば、$k=3$、$p=5$、$w=[2,4,6,8,10]$。 状態で$s=1$、残りを計算します$k-s=2$, したがって、貢献度は次のようになります。$w[2]=6$。 DP は部分ルールを使用して寄与を正しくクランプします。 

最後に、早期配置を巡って競合する複数の大きなアイテムについて考えてみましょう。 DP はこれを自然に処理します。これは、各項目がすべての状態で試行されるため、明示的な置換推論を必要とせずに、より良いプレフィックス状態を生成する順序が最大化を通じて優先されるためです。
