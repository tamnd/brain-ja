 ## 解決策
 ## 問題の理解

 接続された無向の単純なグラフが与えられます。$G$。 このグラフから、すべてを使用するすべての接続されたサブグラフを考慮します。$n$頂点を正確に含む$n-1$エッジ。 そのようなサブグラフは必ず次のスパニング ツリーになります。$G$、接続されているため、非循環（エッジが等しいため）$n-1$)、すべての頂点にまたがります。 

質問は木が存在するかどうかを尋ねます$T$すべてのスパニング ツリーが$G$構造的には同じです$T$頂点の再ラベルまで。 つまり、どのスパニング ツリーを選択しても、$G$、それらはすべて根のない木と同型である必要があります。 

出力はテスト ケースごとの単純な決定であり、指定されたグラフのすべてのスパニング ツリーが互いに同型の場合は「YES」、そうでない場合は「NO」になります。 

制約により、最大で$10^5$テストケースと合計$n$そして$m$テスト全体で最大$10^6$。 これにより、テスト ケースごとに線形または線形に近いソリューションが強制されます。 スパニング ツリーを列挙したり、エッジ選択ごとに複雑な組み合わせ推論を実行したりするアプローチは、単一のグラフでも指数関数的に多くのスパニング ツリーを持つ可能性があるため、直ちに不可能になります。 

素朴な試みは、複数のスパニング ツリーを生成し (たとえば、DFS スパニング ツリーの異なるエッジを削除することによって)、それらの間のグラフの同型性をチェックすることです。 ツリーのグラフ同型性も線形時間でチェックできますが、密なグラフ内のスパニング ツリーの数は依然として指数関数的であるため、このアプローチはすぐに破綻します。 

もう 1 つの素朴な方向は、「小さなサイクルの変化」は構造に影響を与えないが、分岐が存在するグラフでは直観が機能しないと仮定することです。 たとえば、サイクルとリーフがアタッチされたグラフでは、削除されたサイクル エッジのさまざまな選択により、結果として得られるツリー内の分岐が位置する場所が移動する可能性があり、より複雑な分岐が他の場所に存在する場合、ツリーの形状が非同型的に変化する可能性があります。 

## アプローチ

 最初の観察は、任意のサブグラフを比較しているのではなく、スパニング ツリーのみを比較しているということです。 スパニング ツリーの構造は、グラフのサイクル スペースによって完全に制御されます。 ツリーを越える余分なエッジごとに少なくとも 1 つのサイクルが導入され、各サイクルに柔軟性が導入されます。異なるサイクル エッジを削除すると、異なるスパニング ツリーが生成されます。 

グラフがすでにツリーである場合は、スパニング ツリーが 1 つだけ存在するため、条件は自明に当てはまります。 

グラフに 1 つのサイクルが含まれている場合、すべてのスパニング ツリーはそのサイクルから 1 つのエッジを削除することによって形成されます。 残りの構造は固定されたままです。 これにより、単一サイクルのどのエッジが削除されたかのみが異なるツリーのファミリーが生成されます。 サイクルは任意の位置でパスに「開く」ことができるため、結果として得られるツリーはすべて同形です。サイクルはパスになり、サイクル頂点へのすべてのアタッチメントは、再ラベル付けされるまでそのパスに沿った対応する位置に取り付けられたままになります。 

グラフに複数の独立したサイクルが含まれる場合、困難が始まります。 2 つのサイクルでは、削除するエッジの独立した選択肢が複数あり、さまざまな組み合わせによってグローバル分岐パターンが変化する可能性があります。 これにより通常、次数の分布が異なるスパニング ツリー、またはパスに沿った分岐点の配置が異なるスパニング ツリーが生成され、同型性によって調整することはできません。 

境界を確認する便利な方法は、エッジ数を使用することです。 接続されたグラフ$n-1$エッジは木です。 と$n$エッジでは一環式です。 以上で$n$エッジでは少なくとも 2 つのサイクルがあり、これがまさに非同型スパニング ツリーが出現し始める場所です。 

したがって、条件は、グラフがツリーであるか単純なサイクルであるかをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 重要な考え方は、ツリーの向こう側に「余分な」エッジがいくつあるか、そしてその余分な構造が正確に 1 つの単純なサイクルを形成しているかどうかによってグラフを分類することです。 

### ステップ

 1. エッジの数を計算します。$m$と頂点$n$。 もし$m = n - 1$、グラフはすでにツリーになっているため、スパニング ツリーは 1 つだけです。 すぐに「YES」を出力できます。 
2. もし$m = n$の場合、グラフにはツリー構造を超えた余分なエッジが 1 つだけあり、これは単環式であることを意味します。 この場合、すべての頂点の次数が正確に 2 であることを確認します。この条件により、グラフが分岐を持たない単純なサイクルであることが保証されます。 
3. グラフが単純なサイクルの場合、エッジを削除すると常にパスが生成されます。$n$頂点。 すべてのスパニングツリーは同じサイズのパスであり、すべて同型であるため、「YES」を出力します。 
4. その他すべての場合、グラフは分岐構造または複数のサイクルのいずれかを持ちます。 これにより、異なる構造特性を持つ少なくとも 2 つのスパニング ツリーが存在することが保証されるため、「NO」を出力します。 

### なぜ効果があるのか

 ツリーにはスパニング ツリーが 1 つだけあるため、条件は自明に満たされます。 シンプル サイクルは、正確に 1 つのサイクルを持ち、分岐のない唯一の接続されたグラフであり、その場合、すべてのスパニング ツリーは再ラベル付けまで同一のパスになります。 追加のサイクルまたはサイクルと互換性のない次数の頂点が存在すると、スパニング ツリーに構造的な非対称性が導入され、少なくとも 2 つの非同型結果が可能になります。 これにより、すべてのグラフが「最大 1 つのサイクルと均一な構造」と「構造的に多様なスパニング ツリー」にきれいに分割されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        deg = [0] * (n + 1)

        for _ in range(m):
            u, v = map(int, input().split())
            deg[u] += 1
            deg[v] += 1

        if m == n - 1:
            out.append("YES")
        elif m == n:
            ok = True
            for i in range(1, n + 1):
                if deg[i] != 2:
                    ok = False
                    break
            out.append("YES" if ok else "NO")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、テスト ケースごとの次数のカウントとエッジのカウントのみに依存します。 重要な決定点は、ツリーと単純なサイクルを区別することです。 次数チェックにより、単環式の場合がツリーが付加されたサイクルではなく、純粋なサイクルであることが保証されます。 

微妙な点は、条件です。$m = n$だけでは十分ではありません。 グラフ$n$ツリーが接続されたサイクルが存在する場合、エッジには分岐が存在する可能性があります。 これらのアタッチメントは次数 2 を超える頂点またはリーフを作成し、すべてのスパニング ツリーが同型を維持するために必要な均一なサイクル構造を即座に破壊します。

 エッジを削除すると、5 つのノードのパスが得られます。 結果として得られるすべてのツリーはパスであるため、すべてのスパニング ツリーは同形です。 

### 例 2

 入力グラフは、追加のリーフが付加された三角形です。 

| ステップ | n | メートル | 程度の条件 | 決定 |
 | --- | --- | --- | --- | --- |
 | 入力 | 4 | 4 | 頂点次数がすべて 2 ではない | いいえ |

 ここで、スパニング ツリーは、どのサイクル エッジが削除されるかによって異なります。 場合によっては、リーフは結果として得られるパスの内部ノードに接続され、別の場合には端点の近くに接続されて、非同型ツリーが生成されます。 

これは、サイクルへの 1 つのアタッチメントでもスパニング ツリーの均一な構造を壊すことを示しています。

 ## 特殊なケース

 単一の頂点グラフにはエッジがなく、スパニング ツリーが 1 つだけあるため、「YES」を返さなければなりません。 アルゴリズムはそれを次のように分類します$m = n - 1$、すぐに通過します。 

純粋なサイクルは、次の場合の標準的な肯定的なケースです。$m = n$。 各頂点の次数は 2 であるため、次数チェックは成功し、出力は「YES」になります。 すべてのスパニング ツリーはパスであるため、構造的なバリエーションは存在しません。 

単一の余分なリーフを持つサイクルでは、次数 3 の頂点が導入されます。アルゴリズムは次数スキャン中にこれを検出し、拒否します。 スパニング ツリーは、どのサイクル エッジが削除されるかに応じて異なり、結果のパスに沿ってリーフの異なる取り付け位置が生成され、非同型性が確認されます。 

複数のサイクルを持つグラフには必ず次のような特徴があります。$m > n$、すぐに拒否されます。 このようなグラフでは、サイクルが独立して相互作用し、非同型の結果を生み出すため、異なるスパニング ツリーの分岐構造が異なる可能性があります。
