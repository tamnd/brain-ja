 ## 解決策

 ## 問題の理解

 正の整数の配列が与えられており、どの要素が長さ 2 以上の配列の連続セグメントの合計として「説明」できるかを特定したいと考えています。 配列内に出現する各値について、合計がその値と等しい長さ 2 以上の部分配列が配列内のどこかに存在するかどうかを確認します。 複数のインデックスに同じ数値が含まれている場合でも、値がこの条件を満たすすべてのインデックスがカウントされます。 

主な難点は、定義が配列全体にわたってグローバルであることです。位置 i の値は、i 自体を含む部分配列によって形成される必要はありません。 合計がその値に等しい限り、配列内の任意のセグメントが有効です。 

制約はサイズではなく構造において厳しいです。 各テスト ケースには合計最大 8000 個の要素があり、すべての要素は最大で n です。 単純な 3 次解では、各位置のすべての部分配列を反復処理することになり、およそ O(n³) 個の動作が発生しますが、これは許容範囲をはるかに超えています。 テスト ケースあたりの解が O(n²) であっても境界線にありますが、すべてのテストの合計 n には制限があるため、慎重に実装すれば許容可能です。 

微妙な点は、多くの値が繰り返されることです。 値が特別であるかどうかを発生ごとに個別に再計算する必要がないため、これは重要です。 代わりに、どの値が部分配列の合計として表現可能であるかを事前に計算してから、頻度をカウントすることができます。 

よくある失敗例は、各インデックスで開始または終了するサブ配列のみを考慮しようとした場合に発生します。 たとえば、次のような配列では、`[1,2,3,4]`、値`3`特別だから`1+2=3`ただし、各インデックスの周囲の境界限定スキャンでは、そのインデックスを含むセグメントのみをチェックする場合、スキャンを見逃す可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 少なくとも 2 つの長さのすべての部分配列を列挙し、その合計を計算し、その合計を達成可能としてマークします。 その後、配列をスキャンして、この「達成可能な合計」セットに含まれる要素の数を数えます。 

これは定義に直接従っているため、正しいです。 問題は、すべてのサブ配列を列挙するコストです。 O(n²) 個の部分配列があり、それぞれの合計を単純に計算すると、O(n) の別の係数が追加され、O(n³) が得られます。 プレフィックスの合計によって各部分配列の合計が O(1) に減っても、依然として O(n²) 個の部分配列があり、n の合計が 8000 までは許容されますが、慎重な枝刈りが必要です。 

重要な観察は、実際にはすべてのサブ配列が必要ではないということです。 すべての値は n によって制限されるため、合計が n より大きい部分配列はすぐに無視できます。 これにより、開始インデックスの有用な拡張の数が大幅に減少します。これは、実行合計が n を超えると、それ以上拡張しても増加するだけであるためです。 

これにより、問題は、境界のある 2 ポインターまたは各開始位置からの拡張ウィンドウ スキャンに変換され、合計が大きくなりすぎると早期に停止します。 各内部ループは最大でも合計が n を超えたときに停止するため、合計の反復回数は最悪の場合でもほぼ O(n²) になりますが、実際には大幅に減少し、制約の下では許容可能です。 

達成可能なすべての合計をブール配列に n まで保存し、元の配列で到達可能とマークされた値の頻度をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての部分配列) | O(n³) または O(n²) (プレフィックス合計あり) | O(n) | 遅すぎる |
 | 有界 2 ポインター展開 | O(n²) 最悪の場合、実際にはより高速 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値の周波数配列を事前計算します。 これにより、到達可能な合計を前処理した後、結果を O(n) でカウントできます。 
2. ブール配列を作成する`good[v]`値かどうかを示す`v`は少なくとも 2 の長さの部分配列の合計として形成できます。値は最大でも n であるため、n までのみ追跡します。 
3. 各開始インデックスについて`i`、累計を 0 に初期化します。部分配列を右に拡張します。 
4. それぞれについて`j >= i`、 追加`a[j]`累計に。 もし`j > i`(少なくとも 2 の長さを確保)、合計が ≤ n である場合、マークを付けます。`good[sum] = True`。 
5. 現在の合計が n を超える場合は、それ以上の拡張は合計を増やすだけで有効になることができないため、直ちにループから抜け出します。 
6. すべての開始点を処理した後、合計して答えを計算します。`freq[v]`みんなのために`v`そのような`good[v]`それは本当です。 

重要な枝刈りステップは、合計が n を超えたときに中断することです。 すべての配列要素が正であるため、部分配列を拡張すると合計は厳密に増加するため、後で拡張しても合計を有効な範囲に戻すことはできません。 

### なぜ効果があるのか

 正しさは 2 つの特性に基づいています。 まず、少なくとも 2 の長さのすべての部分配列が、インデックスのペア (i, j) として 1 回だけ考慮されます。 第 2 に、すべての数値が正であるため、固定開始インデックスからの累計は、j が増加するにつれて単調増加します。 これにより、合計が n を超えると、それ以上の拡張では有効なターゲットを生成できないことが保証されるため、プルーニングは安全です。 達成可能なすべての合計はそのカットオフの前に引き続き訪問されるため、有効な値が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * (n + 1)
        for x in a:
            if x <= n:
                freq[x] += 1
        
        good = [False] * (n + 1)
        
        for i in range(n):
            s = 0
            for j in range(i, n):
                s += a[j]
                if s > n:
                    break
                if j > i:
                    good[s] = True
        
        ans = 0
        for v in range(1, n + 1):
            if good[v]:
                ans += freq[v]
        
        print(ans)

if __name__ == "__main__":
    solve()
```周波数配列により、カウントが到達可能性の計算から分離されます。 この分離により、合計ごとに配列を繰り返しスキャンする必要がなくなります。 

ネストされたループはすべての部分配列を列挙しますが、合計が n を超えると早期に終了します。 条件`j > i`少なくとも 2 つの長さのサブ配列のみが寄与することを強制します。 

最後に、元の値を事前に計算された到達可能なセットと照合することで結果を集計します。

 ## 特殊なケース

 すべての要素が大きい場合には、厄介な状況が発生します。たとえば、`[8,7,6,5]`。 多くの部分配列が存在するにもかかわらず、ほとんどすべての合計はすぐに n を超えるため、非常に短いセグメントのみが問題になります。 このアルゴリズムは早期に適切に中断し、不必要な探索を回避し、追加のコストをかけずに正確性を確保します。 

もう 1 つのケースは、配列に多数の値が含まれる場合です。 多くの部分配列があるにもかかわらず、和はゆっくりと増加し、多くの小さな和が生成されます。 アルゴリズムは依然としてそれらを正確に列挙し、重複を見逃したり過剰にカウントしたりすることなく、到達可能なすべての値をマークします。 

最後の微妙なケースは、単一要素の配列です。 少なくとも 2 の長さの部分配列は存在しないため、答えは常に 0 になります。 条件`j > i`誤ったマーキングが発生しないようにします。
