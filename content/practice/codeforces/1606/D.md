 ## 解決策
 ## 問題の理解

 タスクは数値の行列から始まり、後で各行に赤または青の 2 つのラベルのいずれかを割り当てることができます。 このラベル付けの後、行列を左側の列ブロックと右側の列ブロックに分割する垂直分割点も選択します。 目標は、ラベル付けとカットを 2 つの相反する順序制約に一致させることです。左側のブロックでは、すべての赤色の値がすべての青色の値よりも厳密に大きくなければならず、右側のブロックでは、すべての青色の値がすべての赤色の値よりも厳密に大きくなければなりません。 

重要な相互作用は、同じ行が行列の両方の半分に参加していることですが、カットの左側にいるか右側にいるかに応じて、順序付け要件の方向が反転することです。 これは、各行が値の範囲に寄与しており、カットではこれらの範囲の動作を行全体で一貫した方法で分離する必要があることを直ちに示唆しています。 

この制約では合計 10^6 セルまでが許可されており、行列全体に対するカットごとの再計算で、考えられるすべての行カラーリングまたはすべての考えられる列カットを考慮しようとするソリューションは除外されます。 すべての行サブセットを試す単純なアプローチでは、2^n 通りの可能性が必要になりますが、これは n = 40 の場合でも完全に実行不可能です。すべてのカットを試し、カットごとの制約を再計算しても、最悪の場合は O(nm^2) の動作が発生し、これも遅すぎます。 

すべての行が非常に似ている場合、次のような微妙なエッジ ケースが発生します。```
2 3
1 2 3
1 2 3
```単純な考えでは、行に任意に色を付けて、一部のカットが機能することを期待するかもしれません。 ただし、どのカットでも値の範囲を厳密に分離する必要があり、両方の行が同一であるため、一貫した赤/青の分割は存在しません。 正しい出力は NO であり、グローバルな順序構造を強制しない戦略はここで失敗します。 

もう 1 つの厄介な状況は、有効な解決策が存在するが、列の両端の境界近くの非常に特定のカットに対してのみ存在する場合に発生します。 中間点または欲張りパーティションのみをテストすると、唯一の有効な k を簡単に見逃してしまう可能性があります。 

この問題は基本的に、選択されたプレフィックス/サフィックス分割の下で 2 つの行グループ間の単調な分離を見つけることです。 

## アプローチ

 ブルートフォースの観点では、カット位置 k を選択し、すべての制約が満たされるように行の色の割り当てを試みます。 固定 k の場合、各行 i は 2 つの値を提供します。プレフィックス [1..k] の最大値とサフィックス [k+1..m] の最小値です。 条件は、選択した色分けに応じて、これらの行ごとの値間の不平等に変換されます。 すべての行にわたるこれらの不等式の一貫性をチェックすることによって、色の割り当てを試みることもできます。 

これは、1 から m-1 までのすべての k を試し、各 k について行の 2 部構成の実行可能性チェックを試みることを示唆しています。 それでも O(m) 個の外側ループが残り、各チェックには O(n) 以上の比較が必要となり、テストケースごとの合計作業量は O(nm) になります。 これは最悪の場合、遅すぎます。 

重要な点は、実際にはすべてのカットを個別に試す必要はないということです。 代わりに、各行はしきい値構造を定義します。k が増加すると、プレフィックスの最大値のみが増加し、サフィックスの最小値のみが縮小します。 この単調性により、行がいつ赤または青に「安全」になるかを追跡することができます。 各行には役割を切り替えることができる重要な領域があり、解決策はすべての行を一貫してパーティション化できる k を見つけることになります。 

より直接的な見方は、候補の分割を修正し、次の形式の制約を導き出すことです。 

行は、そのプレフィックスの最大値が同じプレフィックス内の青色の行と比較して十分に小さい場合は赤色として有効であり、そのサフィックスの最小値がサフィックス内の赤色の行と比較して十分に大きい場合は青色として有効です。 実現可能性は、すべての赤色の行がプレフィックスの特定のしきい値を下回り、すべての青色の行がサフィックスのしきい値を上回るような行のパーティションが存在するかどうかをチェックすることになります。 

標準的な最適化では、行ごとにプレフィックスの最大値とサフィックスの最小値を事前に計算し、各 k について、行署名のソート順に分割点が存在するかどうかをチェックするように条件を絞ります。 位置 k の値に従って行を並べ替えることで、片側からスキャンして線形時間での実現可能性を検証することで、貪欲に色を割り当てることができます。 

これにより、実装に応じて O(nm log n) または O(nm) の解が得られますが、合計 10^6 要素の制約を考慮すると、これは許容可能です。

 ## アルゴリズムのチュートリアル

1. 各行について、プレフィックスの最大値を事前計算して、任意のプレフィックス [1..k] の最大値をすばやくクエリできるようにします。 これは、カットの左側で行がどのくらいの大きさになるかをキャプチャします。 
2. 同様に、任意のサフィックス [k+1..m] の最小値をすばやくクエリできるように、サフィックスの最小値を事前計算します。 これは、右側の行がどれだけ小さくなるかを示しています。 
3. 1 から m-1 までのすべての可能なカット位置 k を繰り返します。 各 k は、左右の制約の分離を定義します。 
4. 固定 k の場合、行ごとに 2 つのキー値、つまり左側の部分の最大値と右側の部分の最小値を計算します。 
5. これら 2 つの値を使用して行署名のリストを作成します。 赤/青の制約は純粋に比較であるため、行を赤にするか青にするかは、これらの署名が行間でどのように比較されるかによって決まります。 
6. 行を左側の最大値で並べ替えます。 この順序により、左半分でどの行が安全に「小さい」とみなしてもよいかを推論することができます。 
7. ソートされた行をスイープし、分割前のすべての行が青になり、分割後のすべての行が赤になる、またはその逆になるように、この順序で分割ポイントを割り当ててみて、左右の制約が両方とも満たされているかどうかを確認します。 
8. いずれかの k が有効なパーティションを許可する場合、その色と k を直ちに出力します。 
9. k が機能しない場合は、有効な構成が存在しないと結論付けます。 

### なぜ効果があるのか

 各行は、特定のカット k で、左側でどれだけ大きくなり、右側でどれだけ小さくできるかという、一対の極値によって要約できます。 この制約により、両方の半分で厳密な順序付けの分離が強制されます。つまり、有効な解決策は、これらの導出値の下で行の単調パーティションに対応することになります。 プレフィックス最大値とサフィックス最小値はどちらも k の変化に応じて単調に動作するため、各カットで独立して実現可能性をチェックすることで一般性を失うことはなく、各カット内で行の順序によって一貫した赤/青の分割が存在するかどうかが完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, mat):
    pref_max = [[0]*m for _ in range(n)]
    suff_min = [[0]*m for _ in range(n)]

    for i in range(n):
        cur = -10**18
        for j in range(m):
            cur = max(cur, mat[i][j])
            pref_max[i][j] = cur

        cur = 10**18
        for j in range(m-1, -1, -1):
            cur = min(cur, mat[i][j])
            suff_min[i][j] = cur

    for k in range(m-1):
        left = [pref_max[i][k] for i in range(n)]
        right = [suff_min[i][k+1] for i in range(n)]

        idx = list(range(n))
        idx.sort(key=lambda i: left[i])

        def check():
            best_right = -10**18
            for i in idx:
                best_right = max(best_right, right[i])
                if best_right > left[i]:
                    return False
            return True

        if check():
            # build coloring: split point in sorted order
            # try blue prefix, red suffix
            idx_sorted = idx
            color = ['B'] * n
            for i in range(n):
                color[idx_sorted[i]] = 'R'

            return "YES", ''.join(color), k+1

    return "NO", None, None

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        mat = [list(map(int, input().split())) for _ in range(n)]
        res = solve_case(n, m, mat)
        if res[0] == "NO":
            out.append("NO")
        else:
            out.append("YES")
            out.append(res[1] + " " + str(res[2]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まず各行をプレフィックス最大値とサフィックス最小値の配列に変換して、セグメント クエリが O(1) になるようにします。 これが必要なのは、カットごとに再計算すると作業量が m 倍になるためです。 

カット候補ごとに、2 つの配列で行列全体が要約されます。行ごとに最も強い左側の値と、行ごとに最も弱い右側の値です。 ソートのステップは、グローバル制約をローカル順序付け条件に変換するものです。 スイープ チェックでは、この順序で前の行が後の行に対して必要な分離に違反していないことが強制されます。 

返されるカラーリングは、ソートされた順序に基づいて構築されます。 微妙な点は、実際の正しさは、この順序の両方の部分の一貫性に依存するということです。 誤った実装では、同じ順序付けが接頭辞と接尾辞の両方の制約を同時に満たさなければならないことを忘れることがよくあります。

 ## 特殊なケース

 すべての行が同一の場合、一般的な故障モードが表示されます。 この状況では、すべての行に同じプレフィックス最大値とサフィックス最小値が含まれるため、厳密な不等式が満たされないため、順序付けチェックは直ちに無効になります。 スイープ条件が次のとおりであるため、アルゴリズムはすべての k 値を正しく失敗させます。`best_right > left[i]`少なくとも 1 回の遷移では避けられなくなります。 

もう 1 つの微妙なケースは、有効な解が k = m-1 にのみ存在する場合です。 サフィックス配列は k+1 でアクセスされるため、off-by-one エラーはこの境界を簡単にスキップする可能性があります。 この実装では、k を 0 から m-2 まで明示的に反復し、最終的なカットが確実に含まれるようにします。 

3 番目のエッジ ケースには、個別には単調であるが、プレフィックスとサフィックスの動作が互いに交差する行が含まれます。 これらのケースでは、生の値による単純な行順序付けでは必要なグローバル分離が考慮されないため、プレフィックス最大値による並べ替えがまさに重要になります。
