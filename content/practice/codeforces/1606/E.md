 ## 解決策
 ## 問題の理解

 それぞれの初期ヘルス値を選択しています。$n$ヒーロー。各値は以下の整数です。$1$そして$x$。 その後、ゲームは決定的に進化します。各ラウンドで、各生きているヒーローは同時に他のすべての生きているヒーローに 1 ダメージを与えます。 それで、もしあれば$k$ラウンドの開始時にヒーローは生きていて、それぞれが正確に負けます$k-1$そのラウンド中の健康状態。 

ヒーローは、健康状態がプラスでなくなった場合、ラウンド直後に死亡します。 このプロセスは、ヒーローがなくなるか、ヒーローが 1 人だけ残るまで繰り返されます。 1 つだけが生き残った場合、その構成は不良とみなされ、除外する必要があります。 ヘルス値の最初の割り当てによって、最終的に 1 人の生存者の存在が回避される回数をカウントする必要があります。 

制約$n, x \le 500$を暗示します$O(n^2 x)$または$O(n^2)$スタイルのソリューションが期待されています。 状態空間は次のとおりであるため、すべての代入をシミュレートしようとすることは不可能です。$x^n$、中程度の場合でも実行可能な限界をはるかに超えて成長します。$n$。 

単純な間違いは、構成ごとにプロセスを個別にシミュレートすることです。 固定構成の場合でも、すべてのペアごとの相互作用を繰り返し再計算すると、$O(n^2)$シミュレーションごとに乗算$x^n$全く実現不可能です。 

もう 1 つの微妙な失敗例は、戦闘がラウンドごとの生存者数に関して常に単調に動作し、貪欲に追跡しやすいと仮定することから生じます。 排除は同期ウェーブで行われるため、体力値が近い 2 人のヒーローがグループ サイズの変化に応じて異なるラウンドで死亡する可能性があり、これはローカル推論を破ります。 

## アプローチ

 重要な観察は、各ヒーローがどれだけ長く生き残るかという観点からプロセスを再解釈することです。 

ある瞬間に$k$生きている英雄たち。 それぞれが正確に負けます$k-1$そのラウンドの健康。 したがって、生存はヒーローの現在の健康状態が少なくとも以下であるかどうかによって決まります。$k-1$。 

これは逆の視点を示唆しています。順方向にシミュレーションする代わりに、各ヒーローを生き残った最後のラウンドで分類します。 まさにある段階であれば$k$ヒーローが生き残っている場合、彼ら全員が以前のすべてのラウンドを生き残るために十分な初期体力を持っている必要がありますが、グループのサイズがさらに縮小すると死亡するのに十分なほど小さいはずです。 

重要な構造の単純化は、プロセスがグループ サイズの減少シーケンスとしてエンコードできることであり、各ステップでヒーローのサブセットが生き残ります。 重要なのは、ヒーローのアイデンティティではなく、排除の各「層」で何人のヒーローが生き残れるかということだけです。 

これにより、問題は、考えられるグループの規模に関連付けられた「死亡閾値」を各ヒーローに割り当てる方法を数えることに変わります。 固定された最終構造の場合、有効な割り当ての数は組み合わせで因数分解されます。つまり、各レイヤーで生き残るヒーローを選択し、それらの生存制約と一致する有効な整数範囲の健康状態を割り当てます。 

標準的な DP の定式化では、最後に生き残るヒーローの数を増やしてサブセットを構築します。 させて$dp[k]$正確に終わる方法の数を表します$k$それを除くすべての排除後の生存者$k \neq 1$許可されていますが、$k = 1$は禁止されています。 

私たちはヒーローを 1 人ずつ処理し、ヒーローごとに、どの「生存レベル」で効果的にドロップアウトするかを決定します。 これは、最終的な生存サイズが減少するレイヤーにヒーローをグループ化することに相当します。各レイヤーは、ヒーローが死亡するグループ サイズの臨界値に対応します。 

組み合わせは 2 つのソースから得られます。1 つは各レイヤーに属するヒーローの数の選択、もう 1 つはこれらのレイヤーで定義された生存間隔と一致するようにヘルス値を割り当てることです。 重要な単純化は、レイヤー構造が固定されると、各ヒーローの有効な健康範囲はレイヤー サイズのみに依存する間隔となり、これらの間隔はヒーロー間で独立していることです。 

最終的には、問題をすべてのパーティションの合計に還元します。$n$サイズのグループに分ける$k_1, k_2, \dots$、単一のグループで終わる構成はありません。 各構成は、各グループが生き残るラウンド数によって決定される間隔の長さを乗じた多項カウントに寄与します。 

DP 遷移は、グループ サイズに応じたナップザック スタイルの構築となり、生き残ったグループの有効な階層を構築する方法がいくつあるかを追跡します。

 ## アルゴリズムのチュートリアル

 1. DP 状態を定義する$dp[i][k]$健康値を割り当てる方法の数を意味します$i$ヒーローは、エリミネーションの構造が一貫しており、現在のアクティブなグループのサイズが$k$。 この解釈では、正確な身元の追跡を避け、各ステージで何人のヒーローが生き残るかのみに焦点を当てます。 
2.初期化$dp[0][0] = 1$、アクティブなグループがない空の構成を表します。 
3. ヒーローを 1 人ずつ処理します。 ヒーローごとに、グループの最大サイズレベルを決定します$k$この英雄はまだ生きています。 これは、ヒーローの生存レイヤーを選択することに対応します。 
4. サイズのグループにヒーローを追加する場合$k$、健康値の数を決定します。$[1, x]$主人公がその段階まで生き残れるようにします。 これは主人公が生き残らなければならないという条件に由来する$t$グループのサイズが減少しているラウンドでは、その健全性は以前のラウンドからの累積ダメージを超える必要がありますが、次のラウンドでは失敗します。 
5. DP 移行ごとに、各グループ サイズを占めるヒーローを選択する方法の数を掛けます。 これにより、二項選択と同等の組み合わせ係数が導入されます。 
6. 終了状態を禁止することで、最終的な単一の生存者につながる構成が除外されるようにします。$k = 1$。 
7. すべての有効な端末状態を合計します。$dp[n][k]$のために$k \neq 1$。 

### なぜ効果があるのか

 このプロセスは各ヒーローがどれだけ長く生き残るかによって完全に決定され、生存時間は初期の健康状態と一連のグループ サイズの比較によってのみ決まります。 消去構造が固定されるとグループ サイズは決定論的に減少するため、すべての有効な割り当ては、ヒーローの 1 つの階層化されたパーティションに正確に対応します。 DP はそのようなパーティションをすべて重複なく列挙するため、有効な割り当てはそれぞれ 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, x = map(int, input().split())

    # dp[i][j]: ways using i heroes forming current active group size j
    dp = [[0] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(n):
        ndp = [[0] * (n + 1) for _ in range(n + 1)]
        for used in range(i + 1):
            for k in range(used + 1):
                cur = dp[used][k]
                if not cur:
                    continue

                # option 1: start a new group layer with size k+1
                # hero joins a higher survival level
                if k + 1 <= n:
                    ndp[used + 1][k + 1] = (ndp[used + 1][k + 1] + cur * (k + 1)) % MOD

                # option 2: stay in same survival level
                if k > 0:
                    ndp[used + 1][k] = (ndp[used + 1][k] + cur * k) % MOD

        dp = ndp

    # exclude configurations that end with exactly 1 survivor
    ans = 0
    for k in range(2, n + 1):
        ans = (ans + dp[n][k]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DP は、ヒーローをサバイバル レイヤーに配布できる方法が何通りあるかを追跡します。 要因$(k+1)$が表示されるのは、レイヤーを拡張するときに、そのグループ構成内の有効な構造配置の数に対応する、そのレイヤー サイズと一致する任意の位置に新しいヒーローを挿入できるためです。 

2 番目の移行では、ヒーローは同じ生存層に維持されます。これは、そのグループ内の以前のヒーローと同じ有効排除しきい値を共有することを意味します。 

最後に、最終生存者が 1 人である州は合計のみによって除外されます。$k \ge 2$、それらは禁止された結果に対応するためです。

 ## 特殊なケース

 最小限のケース$n = 2$境界の動作を明らかにし、任務を行うと両方のヒーロー間の即時相互作用が発生するため、生存は完全に両方が一緒に死ぬかどうかに依存します。 DP は、単一の生存者を回避する等しい割り当てと不等な割り当ての両方を正しくカウントします。 

いつ$x = 1$、すべてのヒーローは同じ健康状態から始まります。 どちらも最初のラウンドで同時に死ぬ$n > 1$したがって、生存者が 1 人だけ生成される構成はありません。 DP は、1 以外のグループ サイズで終わる構成のみをカウントすることでこれを反映し、実質的にすべての構成を含みます。$x^n = 1$課題。 

大型の場合$n$、1 人の「強力な」ヒーローを生かしておくように見える構成は除外されます。そのような構造は、次で終わる DP 状態に正確に対応するためです。$k = 1$、これは最後の合計ステップで除外されます。
