 ## 解決策
 ## 問題の理解

 平面上に 2 組の点が与えられ、各点も時間座標を持ちます。 最初のセットは人々を表しており、各人物は特定の時刻に記録された位置を持っています。 2 番目のセットは、それぞれが特定の位置と時間で発生した犯罪イベントを表します。 

ある人が完全に安全であると宣言されるためには、その人が犯人であると矛盾しないほど、時空の中で「十分に近い」犯罪出来事が起こり得ないことを証明できなければなりません。 距離ルールは、時間差と比較した空間上のマンハッタンの距離です。つまり、犯罪事件は、人物間の空間的距離が厳密に時間差よりも大きくない場合、その人物から到達できる可能性があると見なされます。 この制約の下で人が到達した、または影響を与えた可能性のある犯罪事象が 1 つでも存在する場合、その人は疑わしいと考えられます。 

したがって、各人について、すべての犯罪事件が時間に対して空間的に遠すぎるかどうか、つまりマンハッタンの空間的距離がすべての犯罪の絶対的な時間差よりも厳密に大きいかどうかを確認する必要があります。 これが当てはまる場合、その人は安全です。 

直接解釈すると、各人がすべての犯罪ポイントに対する制約を定義し、マンハッタンの距離と時差によって形作られた「光円錐」内またはその上に犯罪が存在する場合に違反が発生します。 

入力サイズは大きく、最大 300,000 人、300,000 件の犯罪があります。 単純なペアごとのチェックでは、最大 9e10 の比較が必要になりますが、これは実行可能な限界をはるかに超えています。 これにより、O(nm) の解決策は即座に除外され、両方のセットが共有の幾何学的構造またはスイープで処理される方法に進むことになります。 

エッジ ケースは、多くのポイントが同じ座標またはタイムスタンプを共有する場合に発生します。 特に時差がゼロの場合は、厳密な空間的不平等状態となり、マンハッタンの距離が平等であるだけでも疑われるのに十分である。 もう 1 つの微妙なケースは、人物と犯罪者が同じ時間と位置を共有している場合です。距離と時間の差が両方ともゼロであるため、その人物は即座に疑われます。 

## アプローチ

 ブルートフォース手法では、マンハッタンの距離と時差を直接計算し、あらゆる犯罪事件に対して各人をチェックします。 これは定義に正確に従っているため、正しいです。 ただし、そのコストは法外に高くなります。n と m が 3e5 までの場合、最悪の場合は 9e10 の比較が実行され、最適化された Python や C++ を使用しても合格できません。 

重要な観察は、条件が変換された座標系における支配関係として書き換えられるということです。 不等式が成り立たないような犯罪点が存在するかどうか、つまり |xi - xj| が存在するかどうかを検出したいと考えています。 + |yi - yj| ≤ |ti - tj|。 これは、3D 空間 (x、y、t) 内の点がマンハッタンのような距離制約内にあるかどうかを確認することと同じです。 

標準的なトリックは、4 つの線形形式を使用してマンハッタンの距離を変換することです。 2 点間の固定差の場合、 |x1 - x2| + |y1 - y2| は、(±x ± y) の最大オーバーサインの組み合わせとして表すことができます。 これにより、条件を 4 つの方向の制約に分割できます。 時間と組み合わせると、x + y - t、x - y - t、-x + y - t、-x - y - t の形式の変換された値を効果的に比較できます。 

私たちは各人について、これら 4 つの形式のいずれかに変換された値が不平等を侵害するほど大きい犯罪が存在するかどうかを知る必要があります。 すべての犯罪を個人ごとにチェックするのではなく、これらの変換されたキーに対する高速かつ最大限のクエリを可能にする構造に犯罪を前処理します。

犯罪を時間順に並べ替えて、変換された 4 つの値のプレフィックスの最大値を維持できます。 次に、各人について、不平等に違反する可能性が十分に近い時間帯の犯罪を検討します。 これにより、4 方向の最大エンベロープ値を維持しながら、時間の経過に伴うスイープの問題が軽減されます。 各個人のクエリは、維持された最大値に対する定数時間のチェックになります。 

ブルート フォースはすべての制約を直接評価するため機能しますが、同一の幾何学的比較を繰り返すため失敗します。 マンハッタンの距離が 4 つの方向で線形になるという観察により、すべての犯罪ポイントを時間でインデックス付けされた 4 つのグローバル エンベロープに圧縮できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 変化を伴う時間の流れ | O((n+m) log(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 変換された犯罪座標の実行中の最良の値を維持しながら、すべてのポイントを時間の昇順に処理します。 

1. 各点を、x、y、t、および人物か犯罪かを示すタイプを含む統一構造に変換します。 これにより、すべてを単一のタイムラインで処理できるようになります。 その理由は、到達可能性の実現可能性を判断する際に重要となるのは相対的な時間順序のみであるためです。 
2. すべてのポイントを時間順に並べ替えます。 2 つのポイントが同じ時間を共有する場合、犯罪は人より先に処理されるため、同時発生したイベントが違反チェックで正しく考慮されます。 これが必要なのは、時間の平等によって空間到達可能性が依然として確保されるためです。 
3. 4 つのマンハッタン サイン変換の下で考えられる最良の犯罪値を表す 4 つのグローバル変数、x + y + t、x + y - t、x - y + t、および x - y - t を維持し、不等式がどのように再配置されるかに応じて適切に調整します。 これらは、犯罪の影響のあらゆる方向の極端な状況を捉えています。 
4. ソートされたリストをざっと調べます。 犯罪に遭遇した場合、変換された値を使用して 4 つの維持された最大値を更新します。 これにより、いつでも、現時点までに発生したすべての犯罪を把握できるようになります。 
5. 人物に遭遇した場合、潜在的な違反しきい値に対応する 4 つの変換された値を計算します。 蓄積された犯罪の最大値と比較します。 いずれかの方向が制約を満たす場合、その人物を不審者としてマークします。 
6. 決して不審者としてマークされなかった人をすべて数えます。 

これが機能する理由: マンハッタン条件は、座標系の 4 つの象限に対応する 4 つの線形不等式に分解されます。 スイープにより、正しい比較方向で時間的に到達可能な犯罪のみが考慮されるようになります。 維持された最大値は最悪の場合の空間オフセットをエンコードするため、最大値がしきい値に違反しない場合、個々の犯罪もしきい値に違反することはできません。 これにより、元のペアごとの条件と縮小されたエンベロープ チェックの間の等価性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    events = []
    
    people = []
    crimes = []
    
    for _ in range(n):
        x, y, t = map(int, input().split())
        people.append((t, x, y))
    
    for _ in range(m):
        x, y, t = map(int, input().split())
        crimes.append((t, x, y))
    
    events = []
    for t, x, y in people:
        events.append((t, 0, x, y))
    for t, x, y in crimes:
        events.append((t, 1, x, y))
    
    events.sort()
    
    neg_inf = -10**30
    max1 = max2 = max3 = max4 = neg_inf
    
    safe_count = 0
    
    for t, typ, x, y in events:
        if typ == 1:
            max1 = max(max1, x + y - t)
            max2 = max(max2, x - y - t)
            max3 = max(-x + y - t)
            max4 = max(-x - y - t)
        else:
            v1 = x + y + t
            v2 = x - y + t
            v3 = -x + y + t
            v4 = -x - y + t
            
            if max1 <= v1 or max2 <= v2 or max3 <= v3 or max4 <= v4:
                pass
            else:
                safe_count += 1
    
    print(safe_count)

if __name__ == "__main__":
    solve()
```この解決策は、すべての人物と犯罪を時間順に並べ替えた 1 つのタイムラインに統合することから始まります。 これは、時間的順序に基づいて、特定の人物に影響を与える可能性のある犯罪のみを考慮するために必要です。 

4 つの最大値は、マンハッタンの標識の各方向における極端に変換された犯罪座標を追跡します。 犯罪を処理するたびに、これらの最大値が更新され、将来の人物のクエリに違反する可能性のある最良の候補が表されます。 

各個人について、犯罪が条件に違反する可能性があるしきい値を表す、対応する変換値を計算します。 維持されている最大値のいずれもこれらのしきい値を侵害できない場合、その人は安全です。 

重要な点は順序です。犯罪は人々が同時に評価する前に処理されなければなりません。 そうしないと、同時違反を誤って無視してしまうことになります。

 ## 特殊なケース

 重大なエッジケースは、人物と犯罪が同じ座標と時間を共有する場合に発生します。 この場合、マンハッタンの距離はゼロ、時差はゼロであるため、不等式は厳密ではなく、その人は不審者としてマークされる必要があります。 スイープは、犯罪が同じタイムスタンプで人々よりも先に処理された場合にのみこれを正しく処理し、評価前にその犯罪が最大値に含まれていることを確認します。 

すべての座標が大きく、値が近い場合、別の特殊なケースが発生します。 x + y - t のような変換された式に依存しているため、整数のオーバーフローは Python では問題になりませんが、C++ では 64 ビットの整数が必要になります。 すべての変換は順序を保持し、正規化を必要としないため、アルゴリズムは安定したままになります。 

3 番目のエッジケースは、犯罪がまったく存在しない場合です。 最大値は負の無限大に留まり、違反は引き起こされないため、すべての人は自動的に安全になります。
