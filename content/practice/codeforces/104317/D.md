 ## 問題の理解

 2 つの文字列が与えられています。$A$そして$B$。 空の文字列から始めます$C$、そして私たちは構築することを許可されています$C$部分文字列を繰り返しコピーすることにより、$A$そしてそれを末尾に追加します$C$。 文字列$A$変更されることはなく、各操作では内部の任意の連続セグメントを選択できます。$A$、前の選択と重複しているか、前の部分文字列が繰り返されている可能性があります。 

任務は構築することです$B$まさにその通り$C$このようなコピー操作を最小限に抑えます。 

したがって、本当の質問は構築に関するものではありません$C$直接ですが、分割について$B$各セグメントが内部のどこかに表示されるように、最小限のセグメントに分割します。$A$部分文字列として。 

制約は大きく、すべての全長が$A$そして$B$テストケース全体で最大$2 \cdot 10^5$。 これにより、二次時間で考えられるすべてのセグメントに対して部分文字列の存在を単純にチェックするソリューションは即座に除外されます。 素朴なアプローチは、あらゆるポジションに対して、$B$、すべての部分文字列を試します$A$または、スキャンによって各候補を検証すると、次のようになります。$O(|A| \cdot |B|)$が遅すぎます。 

主なエッジケースは、短いマッチを貪欲に取ることが魅力的に見えるが、最大限に拡張しないと次善となるパターンから生じます。 たとえば、次の場合$A = \text{"abcd"}$そして$B = \text{"abcdabcd"}$、「abcd」を 2 回とると、最適な答えは 2 になります。 「a」、「b」、「c」、... のように早めにカットする不用意な戦略は 8 つの操作を生成します。これは正しいですが、最小限ではありません。 もう一つの微妙なケースは次のような場合です。$B$重複する部分文字列を繰り返します$A$、試合を内側で完全に延長できなかった場合$A$無駄なカットにつながります。 

重要な構造上の観察は、$B$～のどこかに存在することが確認されている$A$、新しい操作を開始する前に、可能な限り拡張することをお勧めします。 

## アプローチ

 直接的な総当たり戦略は、構築プロセスをシミュレートすることです。$B$考えられるすべての部分文字列を試してみることで、$A$各ステップで。 それぞれの位置で$B$のすべての部分文字列を列挙できます。$A$、残りのサフィックスの現在のプレフィックスと一致するかどうかを確認します。$B$を選択し、最も長い有効なものを選択します。 これは操作ルールを直接反映しているため正しいですが、部分文字列の比較を繰り返し行う必要があります。 それぞれの比較にはコストがかかる場合があります$O(|B|)$最悪の場合、$O(|A|^2)$の部分文字列$A$、そのため、このアプローチは実行不可能になります。 

重要な簡素化は、操作を再解釈することで実現します。 すべての操作で次の部分文字列が追加されるため、$A$、問題はパーティション分割になります$B$連続したブロックに分割します。各ブロックは次の部分文字列でなければなりません。$A$、最小のブロック数が必要です。 重要な特性は、文字列が有効なブロックであるかどうかは、次の要素のみに依存するということです。$A$、前のブロックがどのように選択されたかではありません。 

この独立性により、現在の位置から開始するという貪欲な戦略が可能になります。$B$、現在のブロックを部分文字列のままで可能な限り拡張する必要があります。$A$。 より早く停止した場合、将来の実現可能性に影響を与えることなく、有効なブロックの長さが減少するだけであり、ブロック数が増加するだけです。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、次から構築されたサフィックス オートマトンを使用します。$A$部分文字列の有効性を効率的にテストします。 

1. 文字列に対してサフィックスオートマトンを構築する$A$。 この構造は、次のすべての部分文字列をエンコードします。$A$初期状態からの有効なパスとして。 
2. スキャンを開始します$B$一番左の位置から。 ポインタを維持する`i`これは、構築しようとしているセグメントの現在の開始をマークします。 
3. セグメントごとに、オートマトンの状態を初期状態にリセットし、2 番目のポインタの拡張を試みます。`j`から始まる`i`。 
4. ながら`j`範囲内にあり、キャラクターのオートマトンに遷移が存在します$B[j]$、オートマトンの中を進んで進みます`j`。 これにより、部分文字列が$B[i:j]$は有効な部分文字列です$A$。 
5. 拡張が不可能になった場合は、現在のセグメントを次の位置で終了する必要があります。`j`。 答えを 1 つ増やします。 
6.セット`i = j`文字列全体になるまで繰り返します$B$消費される。 

重要なアイデアは、それぞれのキャラクターが$B$は、成功した拡張の一部として 1 回だけ処理され、拡張に失敗するたびに 1 つの操作をコミットします。 

### なぜ効果があるのか

 どの位置でも$i$、アルゴリズムは次の最長のプレフィックスを構築します。$B[i:]$の部分文字列として存在する$A$。 代わりに短いプレフィックスが選択された場合、将来のセグメントは以前のセグメントの分割方法とは無関係であるため、到達可能な継続のセットを拡張することなく、追加のカットが導入されるだけになります。 実現可能性は各セグメントが存在するかどうかのみに依存するため、$A$、各セグメントの長さを局所的に最大化すると、セグメントの数がグローバルに最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SuffixAutomaton:
    def __init__(self):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.last = 0

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def build_sam(s):
    sam = SuffixAutomaton()
    for ch in s:
        sam.extend(ch)
    return sam

def solve():
    t = int(input())
    for _ in range(t):
        a = input().strip()
        b = input().strip()

        sam = build_sam(a)

        i = 0
        ans = 0
        n = len(b)

        while i < n:
            state = 0
            j = i

            while j < n and b[j] in sam.next[state]:
                state = sam.next[state][b[j]]
                j += 1

            ans += 1
            i = j

        print(ans)

if __name__ == "__main__":
    solve()

よくある間違いは、セグメント間でオートマトンの状態を再利用しようとすることです。 各操作はからの独立したコピーであるため、これは問題には対応しません。$A$、前の部分文字列の継続ではありません。
