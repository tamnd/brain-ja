 ## 解決策
 ## 問題の理解

 標準のバイナリ検索とまったく同じように動作するプロシージャが与えられていますが、ターゲット値の位置を返す代わりに、検索でターゲット要素が見つかるまで実行されるループ反復回数を返す点が異なります。 

検索は整数セグメントに対して実行されます$[L, R]$、目標値が達成されることを保証します。$x$この間隔の中にあります。 各反復で中間点が選択され、それと比較されます。$x$と一致する場合は停止するか、中点が大きいか小さいかに応じて間隔を左半分または右半分に縮小します。$x$。 必要な出力は、単に終了前に実行された反復回数です。 

制約は小さいです。$L, R, x \le 1000$、そしてせいぜい$100$テストケース。 これは、各二分探索には最大で約$\log_2(1000)$、これは 10 回未満の反復です。 したがって、単純な実装であっても、全体では 1,000 回をはるかに下回る操作で実行されます。 

主な微妙な点は、最終的な位置やパスが求められるのではなく、ループの正確な実行数が求められることです。 よくある間違いは、これが 1 つの要素が残るまでの間隔の半分の数に等しいと想定することです。これは、中間点が早くターゲットに到達する場合、これに近い値ですが、必ずしも同一であるとは限りません。 

注目に値するエッジケースは、次のような些細な間隔です。$L = R$、ループは 1 回だけ実行され、すぐに終了します。$x$は 1 回目または 2 回目の反復の中点に等しく、完全な二分探索ツリー走査と比較して深さが変わります。 

## アプローチ

 この手順は決定的であり、すでに完全に定義されています。 強引なアイデアは、文字通りループを記述どおりにシミュレートすることです。$l, r$、計算する$mid = (l + r) // 2$、境界を更新し、反復回数をカウントします。$mid == x$。 これが機能するのは、ループ内のすべての状態遷移が明示的に定義されており、隠れた依存関係がないためです。 

重要な点は、シミュレーション以外の最適化は必要ないということです。 範囲は小さく、反復ごとに間隔が厳密に縮小されるため、ループの長さは次のように制限されます。$\lceil \log_2(R-L+1) \rceil$。 最悪の場合でも、これはテスト ケースごとに一定規模の作業となります。 

したがって、「最適な」ソリューションは総当たりシミュレーションと同じであり、違いは概念的なものにすぎません。プロセスはすでに十分に効率的であると認識しています。

 ## アルゴリズムのチュートリアル

 二分探索を正確にシミュレートし、ループ本体が実行される回数をカウントします。 

1. カウンタをゼロに初期化します。 このカウンタは、バイナリ検索ループが終了するまでに何回反復されたかを追跡します。 
2. 現在の間隔の間$[l, r]$有効です、つまり$l \le r$、検索を 1 回繰り返します。 この条件により、検索スペースが空でない間のみ続行することが保証されます。 
3. 直後に終了するかどうかに関係なく、各ループの実行は 1 つの二分探索ステップに対応するため、カウンターをインクリメントします。 
4. 中点を計算する$mid = (l + r) // 2$。 これは、特定の実装と同じ決定論的な選択であり、現在のプローブの位置を定義します。 
5. もし$mid == x$、すぐに壊れます。 これは、検索が正常に終了したことをモデル化します。 
6. もし$mid < x$、左の境界を に移動します。$mid + 1$、小さすぎる値をすべて削除します。 
7. それ以外の場合は、右側の境界を次のように移動します。$mid - 1$、大きすぎる値をすべて削除します。 

これらの手順の後、カウンターは、到達するまでに必要な反復回数を正確に反映します。$x$。 

正確さは、アルゴリズムが指定されたプロシージャの直接の実行トレースであるという事実から得られます。 反復ごとに、状態は$(l, r)$元の関数と一致し、カウンタはループ実行ごとに 1 回だけインクリメントされます。 ループは次の場合にのみ終了するため、$mid == x$、増分の数は正確に、終了前に実行される反復の数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        l, r, x = map(int, input().split())
        cnt = 0
        while l <= r:
            cnt += 1
            mid = (l + r) // 2
            if mid == x:
                break
            if mid < x:
                l = mid + 1
            else:
                r = mid - 1
        print(cnt)

if __name__ == "__main__":
    solve()
```解決策は、指定された関数を直接転写することです。 唯一の追加コンポーネントはカウンターです。カウンターは、元のコードのセマンティクスと正確に一致するように、各ループ反復の開始時に増加します。 ループ条件と更新は変更されず、同一の動作が保証されます。 整数の除算は、Python のセマンティクスを提供された疑似コードと正確に一致させるために使用されます。 

微妙な点は、カウンタが次のことをチェックする前にインクリメントされることです。`mid == x`。 これが必要なのは、問題の定義と一致して、終了する反復もカウントする必要があるためです。

 最初のサンプル入力ケースを考えてみましょう`3 7 6`。

 | 1 | 3 | 7 | 5 | 中央 < x、右に移動 | 1 |

 ループは 2 回実行されるため、答えは 2 です。これは、中間点の配置によっては、間隔が完全に崩壊する前に終了が発生する可能性があることを示しています。 

ここで考えてみましょう`5 8 6`。 

| 反復 | l | r | ミッド | アクション | CNT |

 ここではターゲットがすぐに見つかるため、反復は 1 回だけ実行されます。 

これは、カウントが間隔サイズだけではなく、正確な中間点シーケンスに依存することを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2

    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []

    for _ in range(t):
        l = int(data[idx]); r = int(data[idx+1]); x = int(data[idx+2])
        idx += 3

        cnt = 0
        while l <= r:
            cnt += 1
            mid = (l + r) // 2
            if mid == x:
                break
            if mid < x:
                l = mid + 1
            else:
                r = mid - 1
        out.append(str(cnt))

    return "\n".join(out)

 ## 特殊なケース

 いつ$L = R$、条件が次のとおりであるため、ループは 1 回だけ実行されます。$l \le r$それは本当です、$mid$唯一の値と等しい場合、関数はただちに終了します。 実装では等価性をチェックする前にカウンターがインクリメントされるため、出力は 1 となり、期待される動作と一致します。 

のようなケースの場合$L = 1, R = 3, x = 2$、最初の中間点は 2 であるため、最初の反復で終了が発生します。 カウンタは 1 になり、それ以上の更新は適用されません。 これにより、早期終了によって成功した反復のカウントがスキップされないことが確認されます。 

ターゲットが極端な境界にある場合など、$L = 1, R = 7, x = 7$の場合、検索は右端に到達する前にいくつかの中間点を通過します。 各反復では間隔が正しく縮小され、ループ数は暗黙的二分探索ツリー パスの右端のリーフまでの深さと一致します。
