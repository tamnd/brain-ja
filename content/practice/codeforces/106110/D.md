 ## 解決策
 ## 問題の理解

 ループを何度も実行するプログラムの非常に単純化されたコスト モデルが与えられました。 各ループ反復では、多数の計算操作とデータ構造への多数の整数の挿入という 2 種類の作業が実行されます。 計算および挿入ごとのコストは固定されていますが、プログラミング言語によって異なります。 

このことから、プログラムが時間制限、メモリ制限、またはその両方に違反しているかどうか、あるいはどちらにも違反していないかを判断する必要があります。 制限時間は、言語ごとに裁判官が 1 秒あたりに処理できる基本操作の最大数として表されます。 メモリ制限は、保存できる整数の最大数として表されます。 

重要な考え方は、実行中に動的またはアルゴリズム的なことは何も起こらないということです。 ループ全体で合計を集計し、2 つのしきい値と比較しているだけです。 

入力は、ループの反復数、反復ごとに発生する計算の数、反復ごとに発生する挿入の数、および言語識別子の 4 つの値で構成されます。 これから、合計時間コストと合計メモリ使用量を計算し、結果を分類します。 

この制約により、各数値パラメーターに最大 100 万の値が許可されます。 これにより、複雑な方法で反復ごとにシミュレーションを行うアプローチは即座に排除されますが、テスト ケースごとに一定量の演算のみを実行するため、ここでは線形シミュレーションでも問題ありません。 ソリューション全体は基本的にテストごとに O(1) です。 

両方の制限を超えると、微妙な障害が発生することがあります。 単純な実装では、最初に時間をチェックしてすぐに返すか、最初にメモリをチェックしてすぐに返す可能性があります。 必要な出力は 4 つの状態を区別するため、これは不正確です。 もう 1 つのよくある間違いは、メモリと時間のしきい値が言語に依存するため、単一の制限をハードコーディングすると間違った答えが生じることを忘れていることです。 

具体的なエッジケースは、両方を正確に超えた場合です。 

入力:

 n = 1e6、q = 1e6、k = 1e6、言語 = py

 時間コストは膨大であり、メモリも膨大であるため、正しい出力は「TL と ML」です。 最初に違反した制約のみを返す単純なチェッカーでは、誤って「TL」のみが出力されます。 

もう 1 つのエッジ ケースは、正確に 2e7 のメモリ整数にヒットする場合や、正確に 2e7 の Python 演算にヒットする場合など、値が境界上に正確に位置する場合です。 条件は「以上」ではなく「超過」であるため、これらは有効なものとして扱う必要があります。 

## アプローチ

 ブルートフォース解釈では、各ループの反復をシミュレートし、操作とメモリを段階的に加算し、制限と繰り返し比較します。 これは機能しますが、不要です。 反復ごとの計算は一定であるため、合計の複雑さは O(n) になります。これは制約の下では問題ありませんが、概念的には無駄です。 

重要な観察は、すべての反復が同一であるということです。 シミュレーションの代わりに、1 回乗算します。合計操作は n 回 (2・q + 5・k)、合計メモリは n・k です。 これらの集計を計算した後は、2 つの比較のみを実行します。 

本当の単純化は、反復間で状態の依存性が存在しないことを認識することから生まれます。 各反復は独立したコストに寄与するため、プログラム全体は線形スケーリングに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 反復シミュレーション | O(n) | お(1) | 承認済み |
 | 直接集計 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. n、q、k、および言語文字列を読み取ります。 言語は時間制限とメモリ制限という 2 つの定数を決定するため、それをすぐにそのしきい値にマッピングします。 
2. 合計の計算操作を n と q の積として計算し、各計算に 2 つの操作が必要となるため、2 を掛けます。 
3. 各挿入には 5 つの操作が必要となるため、合計の挿入操作を n と k の積にさらに 5 を乗算して計算します。 
4. 両方の部分を加算して、合計時間コストを取得します。 
5. 挿入された各整数が 1 単位のメモリを占有するため、合計メモリ使用量を n と k の積として計算します。 
6. メモリ使用量を言語固有のメモリ制限と比較し、それを超えているかどうかを記録します。 
7. 使用時間を言語固有の制限時間と比較し、それを超えているかどうかを記録します。 
8. 2 つのブール フラグに基づいて、OK、TL、ML、または TL と ML の 4 つの文字列のうち 1 つを正確に出力します。 

### なぜ効果があるのか

 プログラムの構造は、コストの線形加算性を保証します。つまり、すべての反復で同じ独立した量の計算とメモリが寄与します。 どちらのコストも前の反復に依存しないため、リソース使用量の合計は同一の項の単純合計となります。 この決定は、2 つの決定論的なスカラー値を固定しきい値と比較することになるため、順序付けやシミュレーションの影響によって結果が変わることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
q = int(input())
k = int(input())
lang = input().strip()

if lang == "cpp":
    TL = 5 * 10**8
elif lang == "java":
    TL = 10**8
else:
    TL = 2 * 10**7

ML = 2 * 10**7

time_cost = n * (2 * q + 5 * k)
mem_cost = n * k

time_exceeded = time_cost > TL
mem_exceeded = mem_cost > ML

if time_exceeded and mem_exceeded:
    print("TL and ML")
elif time_exceeded:
    print("TL")
elif mem_exceeded:
    print("ML")
else:
    print("OK")
```コードはアルゴリズムに直接に従います。 言語マッピングは、分岐の繰り返しを避けるために、最初に 1 回実行されます。 算術演算には 64 ビットの安全な Python 整数が使用されるため、オーバーフローは心配ありません。 

実装の微妙な詳細は、両方の比較における厳密な不等式です。 制限との等しいことが有効であるため、厳密に大きい値のみが失敗をトリガーします。 

もう 1 つの重要な点は、最終条件の順序を一貫して保つことです。 結合されたケースを最初にチェックする必要があります。 そうしないと、単一フラグ分岐が 2 番目の違反を誤ってマスクしてしまいます。 

## 実用的な例

 ### 例 1

 入力:

 n = 2、q = 2、k = 1、lang = java

 反復あたりの合計計算量は 2·2 = 4、挿入コストの合計は 5·1 = 5 であるため、反復あたりのコストは 9 です。2 回の反復で、時間コストは 18 になります。メモリは 2·1 = 2 です。 

| ステップ | 時間コスト | メモリコスト | TL を超えました | ML を超えました |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 偽 | 偽 |
 | 計算後 | 18 | 2 | 偽 | 偽 |

 Java の制限は両方とも範囲内に収まるほど大きいため、出力は問題ありません。 

これは、スケーリングが線形で独立していることを示しています。 反復ごとに何も変化しません。 

### 例 2

 入力:

 n = 5、q = 0、k = 2、lang = cpp

 反復ごとの時間コストは 5 · 2 = 10 なので、合計時間は 50 です。メモリは 5 · 2 = 10 です。 

| ステップ | 時間コスト | メモリコスト | TL を超えました | ML を超えました |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 偽 | 偽 |
 | 最終 | 50 | 10 | 偽 | 偽 |

 この例では、計算がゼロの場合でも、挿入は依然としてメモリと時間の両方のコストに寄与し、両方を独立して考慮する必要があることを確認しています。

 ## 特殊なケース

 主なエッジケースは、両方の制限を同時に超える場合です。 たとえば、Python で大きな n と大きな q および k を組み合わせると、メモリが範囲内に留まりながら、時間コストが簡単に 2 · 10^7 を超えます (パラメータに応じてその逆も同様です)。 出力を決定する前に両方のブール フラグが独立して計算されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つの特殊なケースは、境界の等価性です。 time_cost が言語の制限に正確に等しい場合、それは違反とみなされるべきではありません。 厳密な比較によってこれが保証され、Java の n = 1、q = 10^8/2、k = 0 などのトレースは、TL をトリガーせずに正確なしきい値を生成します。 

3 番目のエッジ ケースは、q または k のいずれかが 0 である場合です。 k = 0 の場合、メモリは増加しませんが、時間は依然として q に依存します。 q = 0 の場合、時間は挿入コストによってのみ決まります。 この式は依然として均一に適用され、特別な分岐は必要ありません。
