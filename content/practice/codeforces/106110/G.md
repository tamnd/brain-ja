 ## 解決策
 ## 問題の理解

 3 つの数値を表す 3 つの文字列が与えられていますが、それらは通常の意味での固定数値ではありません。 代わりに、各文字列は数字上のパターンのように動作する場合があります。 目標は、最初の 2 つの文字列が有効な数値 A と B になり、3 番目の文字列がそれらの合計 C になり、同じ文字が出現するすべての文字列で割り当てが一貫するように、文字に数字を割り当てることができるかどうかを判断することです。 

中心となる制約は、文字と数字の間の全単射です。 それぞれの個別の文字は 1 つの数字に正確にマップされる必要があり、各数字は 1 つの文字でのみ使用できます。 3 つの文字列のいずれかで文字に数字が割り当てられると、その割り当てはどこでも適用されます。 同時に、結果の数値は算術関係 A + B = C を満たさなければなりません。 

出力は基本的に、考えられるすべての一貫した割り当てに対する実行可能性チェックです。つまり、文字列が数値として解釈される場合に方程式を有効にする、文字から数字へのマッピングが少なくとも 1 つ存在するかどうかです。 

制約は 2 つの点で暗黙的に重要になります。 まず、このバージョンの問題では各文字列の長さが非常に短く、3 文字程度に制限されているため、A と B の数値は最大 999 に制限されます。これにより、実際の数値の検索スペースが即座に制限されます。 第 2 に、全単射制約を扱っているため、マッピングを構築しようとする試みは、桁位置ごとにローカルに検証されるのではなく、グローバルに検証される必要があります。 

素朴だが危険なエッジケースは、同じ文字が異なる位置に表示され、矛盾した数字の役割を強いられる場合です。 たとえば、ある文字が A と C の両方に出現する場合、その文字は算術結果によって引き起こされる数字と一致する必要があります。 文字マッピングの一貫性を検証せずに A + B = C を数値的にチェックするだけの不注意なアプローチは、無効なケースを誤って受け入れてしまいます。 

もう 1 つの微妙なケースは、先行ゼロから発生します。 マッピングによって複数文字の数値の最上位の位置にあるゼロに文字が割り当てられる場合、それは通常は無効になります。 ただし、数値構造は文字列の長さと一致する有効な整数値の反復処理から直接導出されるため、A、B、および C の適切な整数表現のみを考慮する場合、先頭のゼロは暗黙的に回避されます。 

## アプローチ

 数値境界が非常に小さいため、総当り攻撃の観点は簡単です。 A と B は最大 999 であるため、すべての可能なペア (A、B) に対して反復できます。 ペアごとに C = A + B を計算し、数字に文字を一貫して割り当てることができるかどうかを確認します。 

このアプローチの正しさは、可能な数値割り当ての空間全体を徹底的にカバーすることから生まれます。 各候補トリプル (A、B、C) について、全単射制約の下で数字パターンが指定された文字列と一致できるかどうかを検証します。 この検証は、3 つの文字列すべてを並行してスキャンし、文字から数字への辞書と数字から文字への辞書の 2 つの辞書を維持することによって行われます。 矛盾が生じた場合、代入は無効となります。 

ボトルネックは候補ペアの数です。 小さな文字列であっても、単純ループは最大 1000 × 1000 の可能性を実行し、各チェックは最大数桁までスキャンするため、境界線にありますが、厳しい制約の下ではまだ許容可能です。 さらに深刻な問題は、このアプローチでは数値範囲が拡大すると拡張できないことです。 

重要な観察は、数値空間がすでに完全に境界が定められており、離散的であるということです。 任意のマッピングを直接検索しているわけではありません。 代わりに、実際の整数のトリプル (A、B、C) を検索します。 これにより、問題は、組み合わせ代入問題から、検証ステップを伴う有限列挙問題に変換されます。

この変更により、外側のループ内でグローバルに文字の割り当てを検討する必要がなくなります。 各候補トリプルについてローカルで整合性を検証する必要があるだけです。

 ## アルゴリズムのチュートリアル

 1. 0 ～ 999 の A の可能な値をすべて列挙します。入力文字列によって A の最大長が 3 桁に制限されているため、有効な代入によってこれより大きな数値を生成することはできないため、この範囲で十分です。 
2. 各 A について、0 から 999 までの B の可能な値をすべて列挙します。有効な解はこれらのペアの 1 つとして現れる必要があるため、考えられるすべての数値のペアを検討します。 
3. C を A + B として計算します。C が 999 を超える場合は、3 文字のパターンに一致しないため、すぐにスキップします。 
4. A、B、および C を文字列としての数字表現に変換し、後の照合のために位置の配置を保持します。 
5. これらの数値文字列が指定されたパターン文字列に一貫してマッピングできるかどうかを確認します。 文字から数字へのマッピングと、数字から文字への逆マッピングを維持します。 
6. 3 本の弦を位置ごとに同時にトラバースします。 文字と数字のペアごとに、既存のマッピングとの一貫性を検証します。 どちらかの方向で矛盾が生じた場合、このトリプルは直ちに拒否されます。 
7. すべてのポジションが一貫している場合、有効な割り当てが存在すると判断し、早期に終了します。 

### なぜ効果があるのか

 すべての有効な解は、ある数値のトリプル (A、B、C) に一意に対応します。 A と B の範囲は完全に列挙されているため、候補を見逃すことはありません。 検証ステップでは、文字と数字の間の厳密な全単射が強制され、構造的に一貫したマッピングのみが受け入れられることが保証されます。 算術的正しさは C = A + B による構築によってチェックされるため、受け入れられるトリプルは代数制約と写像制約の両方を満たさなければならず、正しさが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(s, t, u, a, b, c):
    sa = str(a)
    sb = str(b)
    sc = str(c)
    
    if len(sa) != len(s) or len(sb) != len(t) or len(sc) != len(u):
        return False

    ltod = {}
    dtol = {}

    for ch, d in zip(s, sa):
        if ch in ltod and ltod[ch] != d:
            return False
        if d in dtol and dtol[d] != ch:
            return False
        ltod[ch] = d
        dtol[d] = ch

    for ch, d in zip(t, sb):
        if ch in ltod and ltod[ch] != d:
            return False
        if d in dtol and dtol[d] != ch:
            return False
        ltod[ch] = d
        dtol[d] = ch

    for ch, d in zip(u, sc):
        if ch in ltod and ltod[ch] != d:
            return False
        if d in dtol and dtol[d] != ch:
            return False
        ltod[ch] = d
        dtol[d] = ch

    return True

def solve():
    s = input().strip()
    t = input().strip()
    u = input().strip()

    for a in range(1000):
        for b in range(1000):
            c = a + b
            if c >= 1000:
                continue
            if ok(s, t, u, a, b, c):
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、候補となる数値トリプルが文字パターンと互換性があるかどうかを検証する単一のヘルパー関数を中心に構成されています。 マッピング ロジックは 2 つの辞書を使用して両方向の全単射を保証し、文字の重複割り当てと数字の再利用の両方を防ぎます。 

メイン ループは、考えられるすべての A 値と B 値を単純に反復します。 c が 999 を超えると早期に拒否されるため、不必要な文字列変換や一貫性チェックが回避されます。 正確さは、すべての有効な代入が列挙された範囲内の整数のトリプルに対応する必要があるという事実にかかっています。 

## 実用的な例

 文字列がすでに有効な算術同一性と一致する単純なケースを考えてみましょう。 

入力：```
AB
BC
CD
```候補値を試行し、最初に成功した一致を観察します。 

| あ | B | C | A→Bマッチ | B→Cマッチ | C→Dマッチ | 有効 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 12 | 23 | 35 | 一貫性のある | 一貫性のある | 一貫性のある | はい |

 このトレースは、3 つの文字列すべてにわたる数字マッピングの一貫した伝播がどのように受け入れにつながるかを示しています。 

次に、失敗したケースを考えてみましょう。 

入力:```
AA
AB
BA
```A=11、B=12、C=23 のような候補をテストします。 

| あ | B | C | マッピングの一貫性 | 結果 |
 | --- | --- | --- | --- | --- |
 | 11 | 12 | 23 | A が 2 位で競合 | 拒否されました |

 拒否が発生するのは、同じ文字 A が異なる位置で 1 と 2 の両方を表すことを強制され、全単射に違反するためです。 

これらの例は、正確性がローカルな数字の一致ではなく、グローバルな一貫性に完全に依存していることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、3 つの文字列すべてに同じ文字が出現するが、算術演算を通じて異なる数字の役割を暗示する場合です。 このような場合、A + B が数値的に C に等しい場合でも、数字の再利用の競合によりマッピングは失敗します。 逆引き辞書は数字から文字への割り当ての一意性を強制するため、アルゴリズムはこれを検出します。 

もう 1 つの特殊なケースは、長さを一致させるために先行ゼロが必要な場合です。 検証では数値変換の文字列長とパターンの長さを明示的に比較するため、不一致がある場合は無効な解釈が自動的に拒否されます。 これにより、パターンで 2 文字が必要であるにもかかわらず、算術演算で 1 桁の文字列が生成される場合に、「01」を有効と解釈するなど、値が隠れて受け入れられることがなくなります。
