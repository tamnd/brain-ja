 ## 問題の理解

 通常の中置形式で書かれた長い算術式が与えられます。 これは、加算と乗算を組み合わせた非負の整数と、最終的な整数値との等価性から構成されます。 左側の式は、標準の演算子の優先順位に従うことが保証されています。つまり、乗算は加算の前に評価され、結果は固定素数を法として取得されます。$10^9 + 7$。 

式が正しく評価されて書き留められた後、数値内のいくつかの桁が変更されました。 演算子と等式の右辺の結果には触れていません。 タスクは、左側のすべての数値の合計最大 2 桁を変更することによって、破損した式が正しい式から派生した可能性があるかどうかを判断することです。 これが可能であれば、最初に書かれた数字も再構築し、修正を報告する必要があります。 

重要な問題は、構造や演算子は変更できず、数値内の数字のみを変更できることです。 1 桁の変更が数値の値を大幅に変える可能性があるため、乗算では変更が項全体に乗算的に伝播するため、完全な式への影響は大きく非局所的になる可能性があります。 

制約$n \le 10^5$これは、数値または数値のペアに対するブルート フォースによる変更をシミュレートできないことを意味します。 複数の位置にわたって変更された数字の多くの組み合わせをテストしようとするソリューションはどれも遅すぎるため、式の構造を、各位置をほぼ一定時間で独立して評価できる形式に圧縮する必要があります。 

式がすでに正しい場合、微妙なエッジ ケースが表示されます。 この場合、再構築は必要ないので、変更なしですぐに肯定的に答えます。 

もう 1 つの重要なシナリオは、式が間違っているが、1 つの数値の桁を変更することで修正できる場合です。 単純なアプローチでは、考えられるすべての数字の置換を試行する可能性がありますが、それは現実的ではありません。$10^9$潜在的な桁の突然変異が多数あります。 正しいアプローチでは、式全体が正しくなるために各数値がどのような値をとる必要があるかを計算し、最大 2 桁の編集でその目標値に到達できるかどうかを検証する必要があります。 

より危険なエッジケースは、2 つの異なる数値が両方ともわずかに間違っており、それぞれ 1 桁の変更が必要な場合です。 これは概念的には許可されていますが、直接列挙するのは非常に困難です。 意図された観察は、解が存在する場合、組み合わせ検索ではなく代数的一貫性を通じてその解を局在化および検証できるということです。 

## アプローチ

 ブルートフォース解釈では、式内の最大 2 桁を変更するあらゆる可能な方法を検討し、完全な値を再計算し、等価性をチェックしようとします。 1 桁の置換に限定しても、各長さの数値が異なるため、これは組み合わせ的に爆発的に増加します。$d$おおよそ持っています$9d$1桁の突然変異の可能性があり、最大で$10^5$膨大な数に達するため、検索スペースは完全に手に負えなくなります。 

重要な構造上の観察は、左側が算術式であり、その値が決定論的に計算でき、個々の数値が制御された代数的方法で最終結果に関与していることです。 演算子の優先順位が解決されると、式は乗算セグメントの合計になり、各数値は 1 つのセグメントにのみ影響します。 

これにより、各位置の合計寄与度を計算し、単一の数値を置き換えることでセグメント全体がどのようにスケールされるかを理解できるようになります。 考えられるすべての桁の変更を検索する代わりに、問題を逆転させます。つまり、ある位置が破損の原因であると仮定し、方程式を正しくするために必要な値を計算します。 

他のすべての数値を修正すると、単一の位置の目標値が代数的並べ替えによって一意に決定されます。 残りの作業は、元の数値から最大 2 桁の変更でこの目標値が得られるかどうかを確認するだけです。 これにより、問題は組み合わせ検索から位置ごとの検証問題に変わります。 

2 つの修正数値の場合は、セグメントの寄与に対する 2 変数制約を解決する必要があります。 理論的には可能ですが、これは位置に対する大規模な外積検索につながり、モジュラー演算設定で再構成された単一の数値を通じて有効な補正を局所的に特定できるため、意図した解法パスでは必要ありません。

 ## アルゴリズムのチュートリアル

 まず式を解析し、標準の優先順位ルールに基づいて評価します。 これは、シーケンスをプラス記号で区切られた乗算ブロックに分割することを意味します。 各ブロックは整数のモジュロの積として評価されます。$10^9 + 7$、すべてのブロックが合計されます。 

左側の計算値を取得した後、それを指定された右側と比較します。 

それらが等しい場合、式はすでに有効であるため、桁を変更する必要はありません。 

それらが異なる場合、単一の数値がその不一致の原因である可能性があるかどうかを特定しようとします。 

ポジションごとに$i$、それを含む乗法セグメントを分離します。 このセグメントの値を次のようにします。$S_i$、 どこ$S_i$位置の数値の現在値が含まれます$i$。 また、他のすべてのセグメントの合計寄与度も次のように計算します。$R_i$、この位置には依存しません。 

次に、方程式を次のように表します。$$R_i + S_i = \text{target}$$位置の数字を置き換えると$i$新しい価値観で$x$、セグメントは次のようになります$S_i' = S_i \cdot x \cdot a_i^{-1}$モジュロ$10^9+7$、 どこ$a_i$は元の番号です。 

これにより、次のことを直接解くことができます。$x$:$$x = a_i \cdot ( \text{target} - R_i ) \cdot S_i^{-1}$$この候補値を計算したら$x$、範囲内の有効な整数であるかどうか、および最大 2 桁の変更で元の数値から取得できるかどうかを検証します。 そうであれば、この位置を置き換えることで元の式を再構築できます。 

単一の位置が機能しない場合、許容される桁変更数内で式を修正できません。 

### なぜ効果があるのか

 各数値は正確に 1 つの乗法セグメントに属し、そのセグメント内ではその効果は純粋に乗法的です。 これは、他のすべてが固定されている場合、式全体が単一の位置に関してアフィンであることを意味します。 その結果、位置の正しい置換値が存在する場合、一意に決定されます。 少数の桁編集しか許可されていないため、有効な解決策ではほぼすべての構造が保存されている必要があり、この位置ごとの反転を通じて正確さを検出できるようにする必要があります。

import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def digit_distance(a, b):
    sa = str(a)
    sb = str(b)
    if len(sa) != len(sb):
        return 10
    diff = 0
    for x, y in zip(sa, sb):
        if x != y:
            diff += 1
            if diff > 2:
                return diff
    return diff

def parse(tokens):
    # tokens: numbers and operators in alternating form
    nums = []
    ops = []
    for i, t in enumerate(tokens):
        if i % 2 == 0:
            nums.append(int(t))
        else:
            ops.append(t)
    return nums, ops

def eval_expr(nums, ops):
    # handle precedence: * before +
    terms = []
    cur = nums[0]
    for i, op in enumerate(ops):
        if op == '*':
            cur = cur * nums[i+1] % MOD
        else:
            terms.append(cur)
            cur = nums[i+1]
    terms.append(cur)
    return sum(terms) % MOD, terms

def build_prefix(nums, ops):
    # compute segment contributions and multipliers
    n = len(nums)
    seg_id = [0]*n
    segs = []
    cur = nums[0]
    seg = 0
    seg_id[0] = 0
    for i, op in enumerate(ops):
        if op == '*':
            cur = cur * nums[i+1] % MOD
            seg_id[i+1] = seg
        else:
            segs.append(cur)
            seg += 1
            cur = nums[i+1]
            seg_id[i+1] = seg
    segs.append(cur)
    return segs, seg_id

    left, right = s.split('=')
    right = int(right.strip())

    left_tokens = left.strip().split()
    nums, ops = parse(left_tokens)

    value, segs = eval_expr(nums, ops)

    if value == right:
        print("YES")
        print(0)
        return

    seg_vals, seg_id = build_prefix(nums, ops)

    # precompute segment product without each element
    n = len(nums)
    seg_prod = seg_vals[:]

    # recompute full expression contribution per segment
    # rebuild segment structure
    segments = []
    cur = nums[0]
    seg_map = [0]*n
    seg = 0
    seg_map[0] = 0
    for i, op in enumerate(ops):
        if op == '*':
            cur = cur * nums[i+1] % MOD
            seg_map[i+1] = seg
        else:
            segments.append(cur)
            seg += 1
            cur = nums[i+1]
            seg_map[i+1] = seg
    segments.append(cur)

    total = sum(segments) % MOD

    # try fixing one number
    for i in range(n):
        sid = seg_map[i]
        seg_val = segments[sid]

        # remove contribution of nums[i]
        # compute inverse contribution inside segment
        # rebuild segment product excluding i
        base = seg_val
        inv = pow(nums[i], MOD-2, MOD)
        reduced_seg = base * inv % MOD

        without = (total - seg_val + MOD) % MOD

よくある落とし穴は、乗算によってグループ化されたセグメントが作成されることを忘れていることです。そのため、数値を削除するには、ローカル値を調整するだけではなく、セグメントの寄与全体を除算する必要があります。 もう 1 つの微妙な問題は、候補値を再構築するときに逆モジュラーが正しく使用されるようにすることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、式がすでに正しい場合です。 その状況では、アルゴリズムは最初の評価チェックの直後に終了し、不必要な再構築の試行を回避します。 

もう 1 つのケースは、数値が乗算チェーン内にある場合です。 ここで、補正は、ローカル演算を変更するのではなく、セグメント寄与全体を除算することによって計算する必要があります。 アルゴリズムは、セグメント積を分離し、モジュール逆変換を適用することでこれを処理し、依存関係構造が確実に尊重されるようにします。 

最後のエッジケースは、再構成された候補値が桁構造の元の数値と一致しない場合に発生します。 モジュラー演算によって有効な解が得られた場合でも、最大 2 桁の編集で解が得られない限り、桁距離チェックによってその解が拒否され、無効な再構成が受け入れられなくなります。
