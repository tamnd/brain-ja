 ## 解決策
 ## 問題の理解

 小文字から構成される 2 つの文字列が与えられます。 最初の文字列はボブが作成した文字の長いテープであり、2 番目の文字列はボブの修正後に残るはずだとアリスが信じている短い文字列であると考えてください。 

ボブは文字列から文字を削除することができますが、その方法は非常に限定されており、一度に 2 つの隣接する文字を繰り返し削除します。 削除するたびに、連続するペアが削除され、文字列が短くなります。 この操作を何度でも実行した後、問題は文字列がターゲット文字列と正確に等しくなるかどうかです。 

したがって、このタスクは恣意的な削除に関するものではありません。 文字列をサイズ 2 のチャンク単位でのみ消去でき、常に現在の文字列内の隣接する位置から消去できます。 元の文字列をターゲットに変換するような一連の削除が存在するかどうかを判断する必要があります。 

この制約により、最大 200,000 文字の文字列が許可されます。 これにより、削除を明示的にシミュレートしたり、すべての削除シーケンスを探索しようとしたりするソリューションは即座に除外されます。これは、直線的な数の分岐選択肢でも組み合わせが爆発的に増加するためです。 有効な解は線形時間に近いものでなければなりません。 

微妙な特殊なケースは、「隣接する削除」が実際に何を意味するのかを理解することから生まれます。 削除の順序が最終的な構造に大きな制約を与えることは容易に想定できますが、重要な観察点は、繰り返しの隣接削減によって文字をペアにすることができる限り、文字の内容に関係なく、削除を使用して均等なサイズの残った部分を削除できるということです。 

たとえば、ターゲット文字列をサブシーケンスとして選択した後、残りの文字が偶数の長さの文字列を形成する場合、その残りはいつでも完全に削除できます。 

入力:```
abac
a
```ここでは「a」をそのままにして「bac」を削除します。 削除された部分の長さは 3 で奇数であるため、ペア削除を使用して完全に削除することはできません。 これにより、「a」が有効な部分列であっても拒否が強制されます。 

素朴な考え方の主な失敗モードは、削除プロセス自体をシミュレートする必要があると仮定することです。 これにより、複雑なスタック シミュレーションやインターバル DP が必要になりますが、これは不必要です。 

## アプローチ

 ブルートフォースアプローチでは、隣接ペアの削除の考えられるすべてのシーケンスをシミュレートしようとします。 各ステップで、隣接するペアを選択して削除し、新しい文字列を生成できます。 これにより、巨大な分岐要素が作成され、中程度の長さであっても状態の数が指数関数的に増加します。 200,000 文字では、これは完全に不可能です。 

より構造化された試みは、プロセスを逆にすることです。 からペアを削除する代わりに、`s`到達する`t`, どのキャラクターが生き残るかを選択することが考えられます。 生き残ったキャラクターは順番に出現する必要があるため、`t`の部分列である必要があります`s`。 これらの文字を選択すると、他のすべてがペアで削除されます。 

重要な洞察は、隣接関係ベースの削除では、長期的にはどの文字を一緒に削除できるかが制限されないということです。 偶数の長さの文字列は、隣接するペアを繰り返し削除することで完全に空にできます。 ペアの値が一致する必要はなく、削除の時点で隣接していれば十分です。 いつでもローカルで削除の順序を変更して要素をまとめることができるため、長さのパリティが完全な削除に対する唯一の制約になります。 

したがって、問題は 2 つのチェックに集約されます。 

まず、それを確認します`t`の部分列として取得できます`s`。 

次に、残りの文字数を確認します。`|s| - |t|`は偶数です。 偶数の場合は、隣接する削除を使用して、残った文字列を常に完全に削除できます。

 ## アルゴリズムのチュートリアル

 リニア スキャンと 2 つのポインターを使用して 2 つの文字列を処理します。 

1.トラバース`s`の文字を一致させようとしながら、左から右へ`t`順番に。 登場人物を見るたびに、`s`現在必要な文字と等しい`t`、ポインタを進めます`t`。 これにより、`t`の続きです`s`。 これが機能する理由は、削除では文字のみが削除されるため、残りの文字の相対的な順序が保持されるためです。 
2. スキャン後、次のすべての文字が存在するかどうかを確認します。`t`一致しました。 そうでない場合は入手方法がありません`t`削除しても新しいキャラクターを作成したり、既存のキャラクターを並べ替えたりすることはできないためです。 
3. 削除された文字の数を次のように計算します。`len(s) - len(t)`。 これは、隣接ペア操作によって削除する必要がある文字の数を表します。 
4. この数値が偶数であるかどうかを確認します。 おかしい場合はすぐに拒否してください。 その理由は、各操作でちょうど 2 文字が削除されるため、削除される文字の合計が 2 で割り切れる必要があるためです。 
5. 両方の条件が満たされる場合は、変換を受け入れます。 

### なぜ効果があるのか

 サブシーケンス条件は、削除によって保持された文字間の相対的な順序が決して変更されないという事実を捉えています。 パリティ条件は、削除操作によって文字列サイズが毎回ちょうど 2 ずつ減少し、偶数長の文字列は隣接する削除を繰り返すことで常に空になる可能性があるという事実を捉えています。 これら 2 つの条件を組み合わせると、次のような状況が完全に特徴づけられます。`t`から入手できます`s`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    
    n, m = len(s), len(t)
    
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
    
    if j != m:
        print("NO")
        return
    
    if (n - m) % 2 != 0:
        print("NO")
        return
    
    print("YES")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず貪欲なサブシーケンス スキャンを実行します。 ポインタ`j`次に必要な文字と一致した場合にのみ先に進みます。`t`。 終わりに達したら`t`に埋め込まれていることがわかっています。`s`順番に。 

2 番目のチェックでは、必要な削除の数がペアの削除と互換性があるかどうかを強制します。 各操作ではちょうど 2 文字が削除されるため、長さの差が均等である必要があります。 

削除プロセスのシミュレーションは必要ありません。これにより、ソリューションが線形に保たれます。

 ## 特殊なケース

 エッジケースの 1 つは、両方の文字列が同一である場合です。 サブシーケンス チェックは簡単に通過し、長さの差はゼロ (偶数) であるため、アルゴリズムはすぐに受け入れます。 削除する必要はなく、答えは正しいです。 

もう 1 つのエッジケースは次のような場合です`t`は空です。 サブシーケンス条件は常に合格し、答えは次の条件にのみ依存します。`|s|`は均等です。 もし`s`長さが奇数の場合、1 文字は削除できないままになるため、答えは次のようになります。`NO`。 アルゴリズムはパリティ チェックを通じてこれを正しく捕捉します。 

最後のエッジケースは次のような場合です`t`長さがある`|s| - 1`。 たとえ`t`が有効なサブシーケンスの場合、差は 1 (奇数) であり、強制的に拒否されます。 これは、ペア操作を使用して残った 1 文字を削除できないという事実と一致します。
