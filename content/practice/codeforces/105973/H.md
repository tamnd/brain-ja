 ## 問題の理解

 固定の参照文字列が与えられます`a`そして別の文字列`b`。 連続した部分文字列の場合`c`から取られた`b`、内部部分文字列がどのように比較されるかに依存する関数を定義します。`a`。 

選んだ長さに合わせて`k`のすべての連続した部分文字列を調べます。`c`長さの`k`。 の値`k`これらすべての長さが満たされている場合、有効であるとみなされます。`k`部分文字列も内部のどこかに表示されます`a`連続した部分文字列として。 機能`f(c)`は単にそのような有効な長さの数です`k`。 

各クエリはセグメントを与えます`[l, r]`の`b`、そして計算しなければなりません`f(b[l:r])`。 

重要な問題は、単一の部分文字列が存在するかどうかだけをチェックしていないことです。`a`ただし、重複する部分文字列のセット全体がすべて`a`。 これにより、クエリ部分文字列内の位置間の依存関係が作成されます。 

制約が十分に大きいため、部分文字列を直接反復するアプローチは不可能です。 すべての文字列の合計の長さは最大 4 · 10^5 ですが、クエリの数は 10^6 に達する可能性があります。 これにより、クエリごとに部分文字列をスキャンしたり、文字ごとのマッチングを繰り返し実行したりするソリューションは即座に除外されます。 単純なループ内の部分文字列ごとの対数処理でも、このスケールでは遅すぎます。 

微妙なエッジケースが現れるのは、`c`はとても短いです。 もし`r = l`、その後は毎回`k = 1`自明ですが、その単一の文字が`a`。 もう 1 つの例外的なケースは次のような場合です`c`に存在しない文字が含まれています`a`まったく、その場合、答えはゼロです。`k = 1`失敗します。 

## アプローチ

 直接解釈すると、あらゆる可能性が試されるでしょう`k`各クエリについて、すべての部分文字列の長さが次のとおりであるかどうかを確認します。`k`セグメント内に表示される`a`。 これはすぐに実行不可能になります。 固定の場合`k`のすべての部分文字列をチェックします`b[l:r]`費用`O(r - l)`部分文字列検索の後、および部分文字列検索自体は、重い構造を構築しない限り一定ではありません。 最大 10^6 のクエリでは、時間制限がかかると制限されます。 

重要な点は、部分文字列の存在を最初から繰り返し再計算する必要がないということです。 代わりに、前処理することができます`a`これで、「の最長のプレフィックスは何ですか」とすぐに答えることができます。`b[i:]`のどこかに現れる`a`?”。すべてのポジションでこれがわかったら、`i`で`b`で始まる部分文字列がどこまで続くかについてのローカル制約があります。`i`有効です。 

この観点から見ると、それぞれの立場`i`最大許容長に貢献します`len[i]`、で始まるすべての部分文字列を意味します`i`までの長さ`len[i]`に存在することが保証されている`a`。 

ここでクエリセグメントを考えてみましょう`[l, r]`。 固定長の場合`k`、長さのすべての部分文字列`k`このセグメント内の位置は次の位置から始まります`l`を通して`r - k + 1`。 有効性の条件は、これらの開始位置がすべて満たさなければならないことになります。`len[i] ≥ k`。 したがって、当然のことながら`k`、範囲最小条件をチェックしています`len`。 

これにより、次から派生した静的配列に対する最小クエリの範囲の問題が軽減されます。`b`、さまざまな条件で実行可能性チェックを繰り返すことと組み合わせて、`k`。 有効性は単調であるため、`k`(長さが機能する場合は、それより小さい長さもすべて機能します)、各クエリは有効な最大値の二分検索になります。`k`。

 ## アルゴリズムのチュートリアル

 ### 1. 構造を構築する`a`部分文字列を認識する

 文字列に対して接尾辞オートマトンを構築します`a`。 これにより、任意の文字列を処理し、各位置について、そこから始まる最長のプレフィックスを決定することができます。`a`。 これを使用して、部分文字列がどこまであるかを評価します。`b`～に関して有効であり続ける`a`。 

### 2. の各ポジションの有効限界を計算します。`b`スキャンします`b`オートマトンを使用して左から右へ。 各インデックスで`i`、計算します`len[i]`、次のような最大長`b[i:i+len[i]-1]`に登場する`a`。 

これにより、グローバルな部分文字列比較の問題が位置ごとの制約に変換されます。 

### 3. 範囲最小のクエリ構造を構築する`len`スパーステーブルを構築します`len`そのため、範囲最小クエリは一定時間内に応答できます。 これにより、任意の間隔で制約をチェックできるようになります。`b`効率的に。 

### 4. 二分検索を使用して各クエリを処理します

 お問い合わせの場合`[l, r]`、有効な最大値を検索します。`k`。 

固定で`k`、長さのすべての部分文字列`k`セグメント内はインデックスから始まります`[l, r - k + 1]`。 最小値を問い合わせます`len`この間隔の値。 この最小値が少なくとも`k`、 それから`k`実現可能です。 それ以外の場合はそうではありません。 

実現可能性が下がってしまうので、`k`大きくなると、二分探索が直接適用されます。 

### 5. 最高のものを返す`k`有効な長さの数はまさに実現可能な最大数です`k`。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`len[i]`で始まる部分文字列の安全な最大拡張子を正しく表します。`i`で`b`に関して`a`。 のすべての部分文字列`b[l:r]`長さの`k`すべての開始位置が次の場合にのみ有効です。`[l, r - k + 1]`この境界を尊重します。 範囲最小クエリはこれらの位置の中で最も弱いリンクを捕捉し、バイナリ検索は最大のリンクを分離します。`k`それはいかなる制約にも違反しません。 これにより、無効な長さがカウントされたり、有効な長さが見逃されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SuffixAutomaton:
    def __init__(self):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.last = 0

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def build_sa(s):
    sa = SuffixAutomaton()
    sa.next = [{}]
    sa.link = [-1]
    sa.length = [0]
    sa.last = 0
    for ch in s:
        sa.extend(ch)
    return sa

def compute_len(sa, b):
    n = len(b)
    res = [0] * n
    v = 0
    l = 0
    for i, ch in enumerate(b):
        if ch in sa.next[v]:
            v = sa.next[v][ch]
            l += 1
        else:
            while v != -1 and ch not in sa.next[v]:
                v = sa.link[v]
            if v == -1:
                v = 0
                l = 0
                continue
            l = sa.length[v] + 1
            v = sa.next[v][ch]
        res[i] = l
    return res

class SparseTable:
    def __init__(self, arr):
        n = len(arr)
        self.log = [0] * (n + 1)
        for i in range(2, n + 1):
            self.log[i] = self.log[i // 2] + 1

        k = self.log[n] + 1
        self.st = [arr[:]]

        j = 1
        while (1 << j) <= n:
            prev = self.st[-1]
            cur = []
            step = 1 << (j - 1)
            for i in range(n - (1 << j) + 1):
                cur.append(min(prev[i], prev[i + step]))
            self.st.append(cur)
            j += 1

    def query(self, l, r):
        j = self.log[r - l + 1]
        return min(self.st[j][l], self.st[j][r - (1 << j) + 1])

def solve():
    n, m, q = map(int, input().split())
    a = input().strip()
    b = input().strip()

    sa = build_sa(a)
    ln = compute_len(sa, b)
    st = SparseTable(ln)

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        lo, hi = 1, r - l + 1
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if st.query(l, r - mid + 1) >= mid:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()

よくある間違いは、すべての人の答えを事前に計算しようとすることです`k`世界的に。 制約はクエリ間隔に依存するため、範囲の最小値を組み込むことなく、有効な長さのグローバルな事前計算だけでは十分ではありません。
