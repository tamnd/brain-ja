 ## 解決策
 ## 問題の理解

 10進数の文字列から始めます`s`。 次に、一連の置換ルールが順番に適用されます。 各ルールの形式は次のとおりです。`d -> t`、出現するすべての数字を意味します`d`文字列に置き換えられます`t`。 

重要な点は、置換は現在の文字列に対して一度に 1 文字ずつ実行されるわけではないということです。 各ルールは現在の文字列全体を変換します。 後のルールでは、以前の置換文字列内に表示される数字が再定義される可能性があるため、数字の最終的な展開は、その後に続くすべてのルールに依存します。 

すべての置換が適用された後、結果の文字列は 10 進数として解釈され、その値の剰余を計算する必要があります。`10^9 + 7`。 先頭のゼロは文字列表現の一部として残りますが、数値には影響しません。 

制約により、最終的な文字列のシミュレーションが即座に除外されます。 元の文字列の長さは次のとおりです。`10^5`、最大で`10^5`交換ルール。 すべての右辺を合計した長さはわずかですが、`10^5`、置換を繰り返すと、概念的な最終文字列が天文学的に大きくなる可能性があります。 1 つの数字が長い文字列に展開され、その数字が再び展開される、というようになります。 実際の結果には、指数関数的に多くの文字が含まれる可能性があります。 

これは、最終的な文字列を決して構築してはいけないことを意味します。 結果の数値の剰余を計算できる圧縮表現が必要です。`10^9 + 7`。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
s = "3"
rule: 3->
```最後の文字列は空です。 この問題では、結果の数値を次のように定義します。`0`。 すべての置換で少なくとも 1 つの数字が生成されると想定するアプローチは、ここでは失敗します。 

考慮する：```
s = "2"
rules:
2->00
```最後の文字列は`"00"`。 数値的にはまだこれ`0`。 アルゴリズムは、先頭のゼロを削除するのではなく、文字列の長さとモジュラー値を個別に処理する必要があります。 

考慮する：```
s = "1"
rules:
1->23
2->4
```正しい最終結果は次のとおりです`"43"`、 ない`"23"`。 2 番目のルールは数字に影響します`2`最初のルールによって導入されました。 このルール間の依存関係が、この問題の中心的な難しさです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 現在の文字列を維持し、各置換を文字通りに適用します。 ターゲットの数字と等しいすべての文字に、置換文字列を追加します。 

これは問題文に正確に従っているため、正しいです。 問題はサイズの成長です。 たとえ小さなチェーンであっても、```
1->11
```何度も繰り返すと、ステップごとに長さが 2 倍になります。 最終的な文字列は指数関数的に大きくなり、メモリ制限をはるかに超える可能性があります。 

重要な点は、最後の文字列自体が必要ないということです。 10 進数のモジュロを計算するには`M`、文字列は次の 2 つの情報のみを提供します。 

1. その長さ。 
2. その数値の剰余`M`。 

文字列を仮定します`A`価値がある`val(A)`そして長さ`len(A)`、および文字列`B`価値がある`val(B)`そして長さ`len(B)`。 

連結用`AB`:$$val(AB)=val(A)\cdot 10^{len(B)}+val(B)$$モジュロ`M`。 

これは、展開されたすべての数字がペアで表現できることを意味します。$$(value,\ length)$$実際の文字列を保存することはありません。 

次に、置換ルールを見てみましょう。 数字の意味は、過去のルールではなく、将来のルールに依存します。 これは、ルールを逆方向​​に処理することを示唆しています。 

後のすべてのルールが適用された後、すべての桁の最終展開がすでにわかっていると想像してください。 それからルールとしては```
d -> t
```の最終展開を計算できます。`d`内部の数字の既知の展開を連結することによって`t`。 

最後のルールから最初のルールに向かって処理すると、まさにこの状況が得られます。 

最初は、ルールが処理される前に、各桁がそれ自体に展開されます。 次に、後方ステップごとに、右側に表示されている桁の現在の拡張を使用して 1 桁が更新されます。 

すべてのルールが処理されると、元の文字列の各桁の最終的な展開がわかります。 最終スキャン`s`答えを計算します。

 | ブルートフォース | 最悪の場合は指数関数的 | 指数 | 遅すぎる |
 | 最適 | O( | s | + 総置換長) |

 ## アルゴリズムのチュートリアル

 1. しましょう`MOD = 10^9 + 7`。 
2. 10 のべき乗をモジュロで事前計算する`MOD`可能な最大拡張長寄与まで。 すべての置換文字列の合計の長さは最大でも`10^5`、その範囲までのコンピューティング能力で十分です。 
3.各桁ごとに`0...9`、 維持する：`val[d]`= 最終展開モジュロの値`MOD`。`len[d]`= 最終展開モジュロの長さ`MOD-1`。 
4. 各数字がそれ自体を表すように初期化します。`val[d] = d`

`len[d] = 1`5. すべてのルールを読んで保存します。 
6. ルールを最後から最初に処理します。 
7. ルールについて`d -> t`、の拡張を構築します`d`スキャンすることで`t`左から右へ。 
8. 2 つの変数を維持します。`cur_val`

`cur_len`最初は両方ともゼロです。 
9. 各桁について`x`で`t`、すでに計算された次の展開を連結します。`x`:$$cur\_val = cur\_val \cdot 10^{len[x]} + val[x] \pmod{MOD}$$

$$cur\_len = cur\_len + len[x] \pmod{MOD-1}$$1. 右辺全体が処理された後、次を割り当てます。$$val[d] = cur\_val$$

$$len[d] = cur\_len$$1. すべてのルールが処理された後、元の文字列を処理します。`s`。 
2. ゼロから始めて、各桁の最終展開を連結します。`s`同じ式を使用します。 
3. 結果の値を剰余として出力します。`MOD`。 

長さがモジュロで保存される理由`MOD-1`10 の累乗は常に剰余として計算されるということです`MOD`、これは素数です。 フェルマーの定理によると、$$10^k \bmod MOD = 10^{k \bmod (MOD-1)} \bmod MOD$$なぜなら`10`そして`MOD`は互いに素である。 

### なぜ効果があるのか

 ルールを逆の順序で処理します。 ポジションからすべてのルールを処理した後`i+1`これからはペア`(val[d], len[d])`数字から取得した文字列を正確に記述します`d`後のルールを適用した後。 

ルール処理時`i`、右側に表示されるすべての数字は、その後のすべての置換の下ですでに最終的な表現を持っています。 これらの表現を連結すると、ルール後の左側の数字の最終表現が正確に得られます。`i`およびその後のすべてのルール。 

逆の処理順序の帰納により、保存されているすべてのペアは正しいままになります。 最初のルールが組み込まれた後、各数字のペアは完全な最終展開と等しくなります。 元の文字列に対する最終的な連結により、完全に変換された数値のモジュロの値が再構築されます。`10^9 + 7`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    s = input().strip()
    n = int(input())

    rules = []
    for _ in range(n):
        line = input().strip()
        d = int(line[0])
        t = line[3:]
        rules.append((d, t))

    max_len = 100000
    pow10 = [1] * (max_len + 1)
    for i in range(1, max_len + 1):
        pow10[i] = (pow10[i - 1] * 10) % MOD

    val = [i for i in range(10)]
    length = [1] * 10

    for d, t in reversed(rules):
        cur_val = 0
        cur_len = 0

        for ch in t:
            x = ord(ch) - ord('0')
            cur_val = (cur_val * pow10[length[x]] + val[x]) % MOD
            cur_len = (cur_len + length[x]) % (MOD - 1)

        val[d] = cur_val
        length[d] = cur_len

    ans = 0
    for ch in s:
        x = ord(ch) - ord('0')
        ans = (ans * pow10[length[x]] + val[x]) % MOD

    print(ans)

solve()
```このソリューションでは、桁ごとに 2 つの数量が保存されます。`val[d]`数字の完全な拡張モジュロの 10 進数値です。`10^9+7`。`length[d]`は拡張長のモジュロです`10^9+6`。 

逆の処理順序が中心的なアイデアです。 ルールにアクセスすると、その右側に表示されるすべての数字がその最終展開をすでに知っています。
