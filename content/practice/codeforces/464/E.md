[CF 464E - 古典的な問題](https://codeforces.com/problemset/problem/464/E)

 **評価:** 3000
 **タグ:** データ構造、グラフ、最短パス
 **解決時間:** 1 分 20 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 最大 100,000 個の頂点と 100,000 個のエッジを持つ無向重み付きグラフが与えられます。 各エッジの重みは 2 の累乗であり、次のように指定されます。$2^{x_i}$、 どこ$x_i$0 ～ 100,000 の間です。 タスクは、開始頂点からの最短パスを見つけることです。$s$ターゲット頂点まで$t$、その長さを法として報告します$10^9 + 7$、存在する場合は、パスに沿った一連の頂点を出力します。 パスが存在しない場合は、-1 を返します。 

グラフは疎または密である可能性がありますが、頂点とエッジの数は、複雑度がより悪いソリューションであることを示しています。$O((n + m) \log n)$制限時間を超える可能性があります。 隣接行列を使用する BFS のような単純なアプローチは、次のように遅すぎます。$O(n^2)$操作が到達できる$10^{10}$最大限の$n$、それは不可能です。 同様に、すべてのパスを明示的に探索することは指数関数的で不可能です。 

明らかでないエッジ ケースには、エッジがゼロのグラフが含まれます。$s$そして$t$切断されています。 たとえば、次のようなグラフ$n = 2$、$m = 0$、 そして$s = 1$、$t = 2$出力する必要があります`-1`。 接続を前提とした不注意な実装では、近隣にアクセスしようとしてクラッシュする可能性があります。 もう 1 つの微妙な点は、エッジの重みの大きさです。エッジの重みは 2 のべき乗であるため、たとえ小さくても$x_i$一般的な 32 ビット整数を超える非常に大きな数値になる可能性があります。 モジュラー演算は、距離の比較中ではなく、最終出力時にのみ適用する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、次からのすべてのパスを列挙しようとします。$s$に$t$、エッジの重みを合計し、最小合計を追跡します。 これは原理的には正しいですが、グラフ内のパスを列挙すると、$10^5$ノードは組み合わせ的に爆発的であるため、適切な時間内に完了することができません。 

自然な改善策は、標準の最短パス アルゴリズムを考慮することです。 すべてのエッジの重みは負ではないため、ダイクストラのアルゴリズムが適用されます。 優先キューを使用して現在の最小の暫定距離を持つ頂点を選択し、隣接する頂点の距離を更新します。 単純な配列ベースの実装は次のように実行されます。$O(n^2)$が遅すぎます。 バイナリ ヒープを使用すると、複雑さが軽減されます。$O((n + m) \log n)$、制限内に収まります。 

微妙な最適化は、エッジの重みが 2 の累乗であることから生じます。 これにより、その時点までに同じ頂点を共有しない限り、2 つの異なる最短パスが同じプレフィックスを持つことはなくなります。 この事実は正しさにとって必須ではありませんが、ダイクストラの標準的な貪欲な選択が失敗しないことを保証します。 すべての重みが 0 または 1 の場合、0-1 BFS を使用したさらなる最適化が可能ですが、この問題では重みが 2 の大きな累乗になる可能性があるため、標準のダイクストラが適切です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | バイナリ ヒープを使用したダイクストラ | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、隣接リストを作成します。 各エントリにはペアが格納されます`(neighbor, weight)`。 隣接リストを選択する理由は、$m$よりもはるかに小さい可能性があります$n^2$。 
2. 距離配列を初期化する`dist`サイズの$n+1$無限大を除く`dist[s] = 0`。 この配列は、からの最小既知距離を追跡します。$s$それぞれの頂点に。 
3. を初期化します。`parent`最短パスに沿った各頂点の先行データを格納するサイズ $n+1` の配列。 これは、距離を計算した後にパスを再構築するために使用されます。 
4. 最小ヒープ (優先キュー) を使用する`pq`そして押します`(0, s)`これは、距離 0 の開始頂点を表します。 ヒープには常に格納されます`(current_distance, vertex)`。 
5. ながら`pq`は空ではありません:

 - ポップ`(d, u)`山から。 
- もし`d`よりも大きいです`dist[u]`、 続く; これは古いエントリです。 
- 隣人ごとに`(v, w)`の`u`、どうかを確認してください`dist[u] + w < dist[v]`。 true の場合、更新します`dist[v] = dist[u] + w`そして`parent[v] = u`を押してから、`(dist[v], v)`の中へ`pq`。 
6. ループの後、if`dist[t]`無限大のまま、出力`-1`道がないから。 
7. それ以外の場合は出力`dist[t] % 10^9 + 7`パスの長さとして。 パスを再構築するには、次から始めます。`t`そして、に従ってください`parent`後方へのポインタ`s`、シーケンスを逆にします。 

**機能する理由**: ダイクストラのアルゴリズムでは、常に現在の最小の暫定距離で頂点を拡張するため、正確さが保証されます。 頂点を完成させるたびに、その最短距離がわかります。 の`parent`配列は最小パスに沿って先行データを正しく記録します。 ヒープを使用すると、操作が効率的になり、全体的なパフォーマンスが向上します。$O((n + m) \log n)$複雑。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, x = map(int, input().split())
        w = 1 << x  # 2^x
        adj[u].append((v, w))
        adj[v].append((u, w))
    s, t = map(int, input().split())

    dist = [float('inf')] * (n + 1)
    dist[s] = 0
    parent = [-1] * (n + 1)
    pq = [(0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in adj[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                parent[v] = u
                heapq.heappush(pq, (dist[v], v))

    if dist[t] == float('inf'):
        print(-1)
        return

    print(dist[t] % MOD)
    path = []
    u = t
    while u != -1:
        path.append(u)
        u = parent[u]
    path.reverse()
    print(len(path))
    print(' '.join(map(str, path)))

if __name__ == "__main__":
    main()
```隣接リストは近隣を効率的に格納し、ヒープは現在の最小フロンティアを維持し、親配列はパスの再構築を可能にします。 シフトする`1 << x`遅いべき乗を回避します。 ダイクストラ比較の破壊を避けるために、出力でのみモジュロを適用します。 使用する`float('inf')`初期化されていない距離を安全に処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各頂点はヒープに複数回入ることができ、各ヒープ操作のコストは log n、合計エッジ m は更新ごとに 1 回考慮されます。 
| スペース | O(n + m) | 隣接リストにはすべてのエッジが格納され、dist 配列と親配列にはそれぞれ n 個の要素が格納されます。 

n と m が最大 100,000 の場合、合計操作は 10^6 ～ 10^7 以内で、5 秒の制限内に十分収まります。
