 ## 解決策
 ## 問題の理解

 単純に 1 から n までの数字を順番に並べる恒等順列から始めます。 誰かが最初にこの配列を未知のシフト k だけ右に循環的に回転し、次に最大で m 個の要素の任意の交換を実行します。 これらの操作の後、最終的な順列のみが表示されます。 

タスクは、回転後に指定された順列に到達するために最大 m 個のスワップが許可されると仮定して、どの開始回転量 k がこの最終配列を生成するかを決定することです。 

このプロセスについて考えるのに役立つ方法は、配列が回転されたアイデンティティである循環構造から開始し、その後、スワップを使用してそれを「修復」できるということです。 各スワップでは、最終的なターゲット位置に関して 2 つの間違って配置された要素を修正できるため、m は置換が純粋な回転からどれだけ逸脱できるかを制御します。 

制約は大きく、すべてのテスト ケースの合計 n は最大 3 · 10^5 で、最大 10^5 のテスト ケースが存在します。 これにより、すべてのテスト ケースに対してすべての k を試し、スワップをシミュレートしたり、二次時間で距離を計算したりするアプローチは即座に除外されます。 最悪の場合、テスト ケースあたり O(n√n) でも遅すぎます。 

微妙な難しさは、回転が不明であり、スワップもカウント以外の制約がないという事実から生じます。 単純なアプローチでは、k ごとに試行し、配列の回転を解除し、同一性を復元するための最小スワップ数を計算します。 これには、k ごとのサイクル分解が必要となり、テスト ケースごとに O(n^2) が得られますが、これは実行可能ではありません。 

もう 1 つのよくある間違いは、スワップを完全なソート能力として扱い、m 回の反転内の順列が有効であると誤って結論づけることです。 これは、置換がスワップ前の単一の巡回シフトと一致する必要があるという、強力な構造的制約を無視しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。候補シフト k を仮定し、配列を k だけ回転して戻し、それを恒等順列に変換するために必要なスワップの数を計算します。 順列のスワップ距離は n からその順列グラフ内のサイクル数を引いたものであるため、シフト解除後のサイクルを計算できます。 これは正しいですが、k ごとに完全な順列を再構築し、サイクルを再計算するため、テスト ケースごとの合計作業量が O(n^2) になるため、コストがかかります。 

重要な観察は、各 k についてすべてを個別に再計算する必要がないということです。 代わりに、視点を逆転させます。 最後の順列 p を修正します。 与えられた k について、その回転とすでに「構造的に整列」している位置の数を確認することで、最大 m 個の交換後に p が k シフトされた単位から得られるかどうかを解釈できます。 

k だけシフトした後、要素 i は理想的には位置 (i + k) mod n に現れるはずです。 したがって、固定 k の場合、この予想される巡回位置にすでに一致する要素の数を数えることができます。 要素がすでにシフトと一致している場合は、修正する必要はありません。 各スワップで修正できる不一致は最大 2 つであるため、不一致要素の数によって実現可能性が決まります。 

これにより、問題は各 k に対して一致する位置の数を数えるように変換されますが、単純に計算してもやはり O(n^2) になります。 最後のコツは、一貫性が循環アライメント条件として書き換えられることに気づくことです。 

p[j] = (j - k mod n) + 1

 これを再配置すると次のようになります。 

k ≡ j - (p[j] - 1) (mod n)

 したがって、各位置 j は、p[j] を正しく位置合わせする k の剰余値を与えます。 有効な k の場合、多くの位置がこの剰余と一致する必要があります。 x の位置が一致する場合、n - x 要素は不一致となり、少なくとも (n - x) / 2 のスワップが必要になります。 したがって、実現可能性は、シフトによって生成される一致の数に関するしきい値条件になります。 

したがって、モジュール式アライメントを使用して、各 k について、それに投票するインデックスの数を計算し、不一致が最大 2m である k を保持します。

 | 最適 (環状残基上の頻度) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各シフト k を、配列がそのシフトから取得された場合にすでに正しい要素の数によってテストしたいと考えています。 

### ステップ 1: 正しさの条件をモジュラー方程式に変換する

 各インデックス j について、シフト k の正しい値は (j - k mod n) + 1 になります。再配置すると、各 (j, p[j]) ペアが一意の k モジュロ n を意味するという条件が与えられます。 

これにより、各配列要素が特定のシフト値の投票に変わります。 

### ステップ 2: 各シフトの投票を数える

 配列 cnt[k] を計算します。ここで、各位置 j は、方程式から導出される 1 つの k 値に正確に寄与します。 これにより、シフト k と一致する位置の数がわかります。 

解釈は直接的です。シフト k を選択した場合、cnt[k] はすでに正しく配置されている要素の数です。 

### ステップ 3: マッチを必要なスワップに変換する

 cnt[k] 要素がすでに正しい場合、n - cnt[k] 要素は間違っています。 各スワップで修正できる誤った要素は最大 2 つであるため、必要な最小スワップは (n - cnt[k]) / 2 です。 

これは ≤ m である必要があります。これは次と同等です。 

n - cnt[k] ≤ 2m

 または

 cnt[k] ≥ n - 2m

 ### ステップ 4: すべての有効な k を収集する

 0 から n - 1 までのすべての k を反復し、しきい値を満たすものを出力します。 

### なぜ効果があるのか

 重要な不変条件は、特定のシフトの下でのすべての正しい位置合わせが、k に対する固定モジュラー制約に正確に対応することです。 これにより、k ごとの投票を数えることで、そのシフトと既に一致している要素の数が正確に測定されます。 スワップは不一致要素にのみ影響し、スワップごとに不一致数が最大 2 ずつ減少するため、実現可能条件は不一致数のみに依存し、不一致の配置には依存しません。 これにより、構造が順序から切り離され、カウントが十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        p = list(map(int, input().split()))

        cnt = [0] * n

        for j, val in enumerate(p):
            # We want k such that after shifting right by k,
            # val ends up at position j.
            # In identity, val is at position val-1.
            # After shift k: position becomes (val-1 + k) % n = j
            # So k ≡ j - (val-1) mod n.
            k = (j - (val - 1)) % n
            cnt[k] += 1

        threshold = n - 2 * m

        res = []
        for k in range(n):
            if cnt[k] >= threshold:
                res.append(k)

        print(len(res), *res)

if __name__ == "__main__":
    solve()
```この実装は、位置と値の間のモジュール関係を直接エンコードします。 重要な行は、投票として機能する各 (j, val) ペアの k の計算です。 残りは、スワップ制限から導出される単純なしきい値チェックです。 

モジュラー演算には注意が必要です。j と val-1 はどちらも 0 から始まるため、追加の調整は必要ありません。 最良の場合、スワップごとに不一致数がちょうど 2 ずつ減るため、しきい値には 2m が使用されます。 

## 実用的な例

 ### 例 1

 入力:```
n = 4, m = 1
p = [2, 3, 1, 4]
```k の投票を計算します。 

| j | p[j] | k = (j - (p[j]-1)) mod 4 |
 | --- | --- | --- |
 | 0 | 2 | 0 - 1 = 3 |
 | 1 | 3 | 1 - 2 = 3 |
 | 2 | 1 | 2 - 0 = 2 |
 | 3 | 4 | 3 - 3 = 0 |

 したがって、cnt：

 k=0:1、k=2:1、k=3:2。 

しきい値は n - 2m = 4 - 2 = 2 です。 

k=3 のみが cnt[k] ≥ 2 を満たします。 

したがって、答えは {3} です。 

これは、単一のスワップ許容値であっても、許容されるシフトをどのように厳密にフィルターするかを示しています。 

### 例 2

 入力:```
n = 3, m = 1
p = [3, 2, 1]
```投票:

 | j | p[j] | k |
 | --- | --- | --- |
 | 0 | 3 | 0 - 2 = 1 |
 | 1 | 2 | 1 - 1 = 0 |
 | 2 | 1 | 2 - 0 = 2 |

 各 k は 1 票を取得するため、cnt = [1,1,1]。 しきい値は 3 - 2 = 1 であるため、すべての k が有効です。 

これは、3 サイクルの反転で回転を実現するには 1 回のスワップで十分であるという事実と一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        p = list(map(int, input().split()))

        cnt = [0] * n
        for j, val in enumerate(p):
            k = (j - (val - 1)) % n
            cnt[k] += 1

        threshold = n - 2 * m
        res = [str(k) for k in range(n) if cnt[k] >= threshold]
        out.append(str(len(res)) + (" " + " ".join(res) if res else ""))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、m が十分に大きく、どの回転からでもほぼすべての順列に到達できる場合です。 恒等の場合、すべての k は cnt[k] = n を生成するため、しきい値は常に満たされ、すべてのシフトが有効になり、回転に関係なくスワップが必要ないという考えと一致します。 

もう 1 つの特殊なケースは、完全に逆の順列です。 ここで、各シフトにより一致の均一な分布が生成されますが、m が最大許容スケールにある場合、しきい値はすべての k が通過するほど十分に小さくなります。 アルゴリズムは構造ではなくカウントのみをチェックするため、これを自然に処理します。 

縮退の場合は m = 0 で、cnt[k] = n が必要です。これは、すべての要素がすでに回転と完全に位置合わせされている必要があることを意味します。 これは、配列がまさに恒等の回転である場合に限り、一意の k を強制します。 モジュール式投票により、正しいローテーションのみが完全なサポートを蓄積することが保証されます。
