 ## 解決策
 ## 問題の理解

 ソース文字列をスキャンする入力プロセスをシミュレートしています。`s`左から右へ。 各位置で、現在の文字を展開中のテキスト バッファに追加するか、Backspace キーを押して、最後に追加された文字が存在する場合は削除します。 

問題は、すべての文字を処理した後にバックスペース操作の選択肢が存在するかどうかです。`s`、最後のバッファは正確にターゲット文字列になります`t`。 

このプロセスについて考えるのに役立つ方法は、すべての文字が`s`最終文字列に残るか、後のバックスペースによって削除されます。 制約は、削除は常に現在構築されているシーケンスの末尾から行われるため、後から十分なバックスペースが発生した場合にのみ、前の文字を削除できることです。 

入力は多くの独立したテスト ケースで構成されており、すべてのケースで文字列の合計長は最大 200,000 です。これにより、すべての可能性をシミュレートしたり、文字ごとに指数関数的な選択肢を使用したりするソリューションは即座に除外されます。 テスト ケースごとに O(n log n) のソリューションであっても、慎重に集計しないと遅すぎる危険があるため、テスト ケースごとに線形のソリューションが必要です。 

重要な微妙な点は、登場人物が次の場合に現れます。`s`マッチ`t`しかし、後で削除されたため整列できません。 たとえば、次の場合`s = "ababa"`そして`t = "ba"`、最初の文字をスキップし、後の文字を選択的に削除して、2 番目と最後の文字だけが正しい順序で残るようにすることができます。 ただし、`t`プレフィックスを強制的に保持する順序で文字が必要であり、後で順序を破壊する方法で部分的に削除する必要がある場合、それは不可能になります。 

別の失敗例が発生するのは、`t`は、生き残ることができる最終的な文字数よりも長いです。 各バックスペースは以前に入力された 1 文字を削除し、入力すると非バックスペース ステップごとに 1 文字だけ生成されるため、最終的な長さは、入力された文字数からバックスペースを差し引いた数を超えることはできません。`|t| > |s|`、即答は不可能です。 さらに微妙なのは、長さには互換性があるが、相対的な順序の制約により一致が不可能な場合です。 

## アプローチ

 ブルートフォースの観点は、各ポジションを次のように扱うことです。`s`二者択一で決定します。入力するか、バックスペースを押すかのどちらかです。 これはおおよそ次のことにつながります`2^n`可能性があり、それぞれについてスタックの動作を O(n) でシミュレーションし、O(n 2^n) を与えます。これは、n が約 40 であっても制限をはるかに超えています。 

どの文字が削除されるかという観点から考えるのをやめ、逆に考えると、問題の構造は単純化されます。 すべてのバックスペース操作により、以前に保持されている必要がある文字が削除されます。つまり、実際にどの文字が含まれるかを決定していることになります。`s`サブシーケンスとして存続しますが、追加の制約があります。削除すると以前に保持されていた文字が消去される可能性があるため、単純にサブシーケンスを選択するわけではありません。`s`。 ただし、このプロセスを、後で各文字を削除できるスタックを構築するものとして再解釈でき、最終的なスタックが等しくなるようにする必要があります。`t`。 

重要な観察は、次のことを処理すると、`s`左から右にスタックを維持する場合、実際の唯一の選択肢は、現在の文字をプッシュするかバックスペースをシミュレートするかです。 すべての選択肢を試す代わりに、最後から貪欲に推論することができます。`t`最後に残ったシーケンスとして、`t`スタックの最後に残った要素として順番に表示されます。 

さらに構造を単純化すると、`t`内の何らかの出現に対応する必要があります`s`それはその後すべての削除が行われても存続します。 逆算すると、貪欲に一致させることができます`t`の終わりから`s`、キャラクターを一部として使用するかどうかを決定します。`t`または、削除されたもの、または以前の文字を削除するために使用されたものとして扱います。 これは、右から左にスキャンする 2 ポインタ戦略に帰着します。 

ポインタを維持します`j`の上`t`最後の文字から始めてスキャンします`s`右から左へ。 以下に等しい文字を見たとき`t[j]`、生存キャラクターとしてマッチングして移動できます`j`後ろ向きに。 それ以外の場合は、その文字`s`つまり、入力して後で消去することも、作成時に単純に無視することもできます。 すべての文字を一致させることができれば、`t`、施工可能です。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. ポインタを設定する`j`の最後のインデックスまで`t`。 これは、逆の順序で照合する必要がある次の文字を表します。 その考えは、`t`は有効な最終スタックのサブシーケンスとして出現する必要があるため、後ろから埋め込むことを試みます。 
2.トラバース`s`インデックスを使用して右から左へ`i`。 各文字を、最終的に一致する構造に寄与する可能性があるものとして検査します。 
3. もし`s[i]`等しい`t[j]`、この文字は、現在必要な文字と一致するものとして扱います。`t`そして減少します`j`。 これは、最終結果で生き残るキャラクターの 1 人としてこのポジションをコミットすることを意味します。 
4. もし`s[i]`等しくない`t[j]`、無視します。 概念的には、この文字は入力され、後でバックスペースによって削除されるか、最終スタックにまったく寄与しません。 
5. スキャンが終了したら、次のことを確認します。`j`に移動しました`-1`。 そうであれば、すべての文字が`t`正しく逆順にマッチングされているので構築可能です。 

これが機能する理由は、最後から一致させることで、常にそれぞれに割り当てられるためです。`t[j]`の中で最も右にある可能性のあるもの`s`。 の任意の文字`s`バックスペースを使用すると、以前に入力した文字を任意に削除できるため、スキップすることは実現可能性に違反しないため、スキップする文字は安全に削除可能として扱うことができます。 有効な構造内に一致が存在する場合、この貪欲な右端一致が有効になるように削除を選択する方法が常にあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    j = len(t) - 1

    for i in range(len(s) - 1, -1, -1):
        if j >= 0 and s[i] == t[j]:
            j -= 1

    print("YES" if j == -1 else "NO")

q = int(input())
for _ in range(q):
    solve()
```実装は後方一致戦略に直接従います。 スタック操作やバックスペース操作は、一致しない文字を破棄する自由によって暗黙的に処理されるため、スタック操作やバックスペース操作のシミュレーションは避けます。 

唯一の微妙な点は、削除を明示的にシミュレートしないことです。 バックスペースは最新の文字を削除することによって制限するだけであり、右から左にスキャンすることで、そのような削除によって無効になる順序付けの制約に依存することがないため、これは安全です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    q = int(input())
    out = []

    for _ in range(q):
        s = input().strip()
        t = input().strip()

            if j >= 0 and s[i] == t[j]:
                j -= 1

        out.append("YES" if j == -1 else "NO")

    return "\n".join(out)

 ## 特殊なケース

 微妙なケースとしては、`t`の末尾から一致する文字数を超えています`s`、 のような`s = "abc"`そして`t = "abcd"`。 アルゴリズムはすぐに失敗します。`j`到達できない`-1`、バックスペースのシーケンスは余分な文字を作成できないため、不可能性を正しく反映しています。 

もう 1 つのエッジケースは次のような場合です`s`必要な文字がすべて含まれていますが、効果的な順序が不十分です。`s = "abac"`そして`t = "abc"`。 スキャンは一致します`c`、 それから`b`、しかし、それ以前の`a`順序付け要件を補うことはできず、貪欲な逆マッチングにより、最終的な順序付けが行われたときに失敗が正しく判断されます。`c`一貫したサフィックス構造でペアにすることはできません。
