 ## 解決策
 ## 問題の理解

 ノードの固定セットが与えられ、それぞれが個別の整数でラベル付けされます。 ラベルが何らかの素因数を共有する場合、2 つのノードは接続されています。 これは、グラフが完全に指定された数値の素因数分解によって決定されることを意味します。 

各クエリに対して、2 つの開始ノードが与えられます。 新しいノードを繰り返し作成することでグラフを拡張できます。 新しいノードは既存の値を取得して形成されます$x$そして値を追加する$x(x+1)$。 この新しいノードは、元のノードと同様に、共通の素因数を共有するすべての数値に接続されます。 

各クエリは独立しており、結果のグラフでクエリされた 2 つのノード間にパスが存在するように、クエリごとに作成する必要がある新しいノードの最小数が必要です。 

この制約は、大規模な静的構造と非常に多くのクエリを意味します。 まで$1.5 \cdot 10^5$ノードと$3 \cdot 10^5$クエリの場合、接続を再計算したり、クエリごとにグラフ検索を実行したりするソリューションは、直ちに実行不可能になります。 クエリごとの直線的な作業でも時間制限を超える可能性があります。 

微妙な点は、グラフが明示的に示されていないことです。 これは共有素因数を通じて暗黙的に行われ、単純なエッジ構築は爆発的に爆発する可能性があります。$O(n^2)$密集した場合。 

主なエッジケースは、2 つの番号がすでに接続されているものの、直接接続されていない場合です。 たとえば、6、10、15 がある場合、6 は 10 と 15 に接続されますが、10 と 15 は直接切断されます。 10 と 15 の間のクエリにはすでに 6 を経由するパスがあるため、答えは 0 になります。直接の gcd 隣接関係のみをチェックする単純なアプローチでは、誤って 1 が返されます。 

2、3、5、7 など、数値がペアごとに互いに素である場合、別のエッジ ケースが発生します。最初のグラフにはエッジがありません。 ただし、フォームのノードを 1 つ作成すると、$x(x+1)$共有プライムが導入され、接続が大幅に変更される可能性があるため、ソリューションではコンポーネントをいかに迅速にマージできるかを考慮する必要があります。 

## アプローチ

 自然な解釈から始めます。つまり、素因数を共有する数値間にエッジが存在するグラフを構築し、最短パス クエリを実行します。 これはすでにクエリごとに DSU または BFS を示唆しています。 ただし、グラフが大きくクエリが多数あるため、どちらも大規模化すると遅すぎます。 

より構造化されたブルート フォースは、因数分解を使用して隣接リストを前処理し、クエリごとに BFS を実行することです。 これは正しいですが、最悪のケースは次のとおりです。$n = 150000$そして$q = 300000$。 単一の BFS であっても多くのノードに接続できるため、このアプローチは次のようになります。$O(nq)$最悪の場合。 

重要な点は、実行が許可されている操作が非常に特殊であるということです。$x(x+1)$。 この数値は常に次のすべての素数を導入します。$x$そしてからのすべての素数$x+1$。 連続する整数は互いに素であるため、この演算は効果的に次の素因数セットをマージします。$x$そして$x+1$。 したがって、各操作はファクター グラフ間のエッジ ブリッジのように機能します。$x$そして$x+1$。 

これは、実際には任意のノードを追加しているのではなく、ファクター グラフ内の連続する整数間に制御された「ブリッジ」を追加していることを意味します。 問題は、素因数接続構造内の 2 つの所定のコンポーネントを接続するために、そのようなブリッジがいくつ必要かを理解することに帰着します。 

DSU を介して暗黙的に素数に関するグラフを事前計算し、各値がその素因数をどのように結び付けるかをモデル化します。 重要なのは、すべての接続性が素数によって管理され、操作は整数行の隣接関係を通じて以前に切断された素数コンポーネントをマージするのに役立つだけであるということです。 

システムは、ノードが素数であり、元の数値が因数分解ですべての素数を接続するグラフとしてモデル化できます。 クエリは、素数が次から到達可能かどうかを尋ねます。$a_s$のものと交差する$a_t$。 そうでない場合は、素数セット間にオーバーラップを作成する操作を導入する必要があります。各操作により、連続する 2 つの整数を効果的にブリッジすることができ、新しい共有素数接続が可能になります。 

最終的な構造は、数値と素数の間の圧縮された 2 部グラフ上の最短経路問題に帰着します。この問題では、演算により、隣接する整数因子セットをマージする一時的な接続ノードが追加されます。 これは、プライム上のマルチソース BFS とアクティブ化された接続上のユニオン検索を使用して、必要な最小限のブリッジ数を追跡することで効率的に解決できます。

 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS |$O(q(n + m))$|$O(n + m)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべてを因数分解します$a_i$そして、各数値を DSU 構造内の素因数に接続します。 これにより、純粋に共有素数によって誘発される基本接続コンポーネントが構築されます。 
2. 各素数から、それを含むインデックスのリストへのマッピングを構築します。 これにより、どの番号がその素数を介してすでに接続を共有しているかを知ることができます。 
3. 各数値について、その表現をその素数の DSU コンポーネントのセットに圧縮します。 2 つの数値は、素数成分のセットが交差する場合、最初に接続されます。 そうであれば、そのクエリに対する答えは即座に 0 になります。 
4. 残りのクエリでは、各数値をコンポーネントのセットとして解釈します。 目標は、隣接関係を導入する最小限の「ブリッジ操作」を使用して 2 つのセットを接続することです。$x(x+1)$。 
5. 因数分解間の遷移を考慮して、暗黙的な整数行の隣接関係を事前計算します。$x$そして$x+1$。 各操作により、次のコンポーネント セットをマージできます。$x$そして$x+1$、コンポーネント グラフに新しいエッジを効果的に作成します。 
6. 状態が素数の DSU コンポーネントに対応し、遷移が 2 つの隣接するコンポーネント セットをマージする 1 つの操作を適用することに対応する最短パス検索を実行します。 各操作のコストが 1 である BFS または 0-1 BFS スタイルの構造を使用します。 
7. クエリごとに、すべてのコンポーネントから BFS を実行します。$a_s$のいずれかのコンポーネントが完成するまで同時に$a_t$に達します。 初めてターゲット コンポーネントに到達すると、作成されるノードの最小数が得られます。 

### なぜ効果があるのか

 DSU over Prime により、すべての固有の接続が冗長性なしで完全にキャプチャされることが保証されます。 グラフ内のすべての元のエッジは共有素数によって説明されるため、元のグラフ内のすべてのパスは一連の素数成分の遷移に対応します。 唯一の欠落している接続は、既存の番号によってブリッジされないコンポーネント間のギャップによって発生します。 許可された各操作は、連続する整数間にそのようなブリッジを 1 つ正確に導入するため、圧縮コンポーネント グラフの単位コスト エッジに対応します。 BFS は操作の数が増えるにつれて状態を探索するため、ソース コンポーネントとターゲット コンポーネントを初めて接続するときは最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6 + 1

spf = list(range(MAXA))
for i in range(2, int(MAXA**0.5) + 1):
    if spf[i] == i:
        for j in range(i*i, MAXA, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a != b:
            if self.r[a] < self.r[b]:
                a, b = b, a
            self.p[b] = a
            if self.r[a] == self.r[b]:
                self.r[a] += 1

n, q = map(int, input().split())
a = list(map(int, input().split()))

prime_to_id = {}
id_counter = 0

def get_id(p):
    global id_counter
    if p not in prime_to_id:
        prime_to_id[p] = id_counter
        id_counter += 1
    return prime_to_id[p]

dsu = DSU(2 * n + 10)

node_primes = []
for i, x in enumerate(a):
    ps = factorize(x)
    ids = []
    for p in ps:
        ids.append(get_id(p))
    node_primes.append(ids)
    for j in range(1, len(ids)):
        dsu.union(ids[0], ids[j])

for _ in range(q):
    s, t = map(int, input().split())
    s -= 1
    t -= 1

    comps_s = set(dsu.find(x) for x in node_primes[s])
    comps_t = set(dsu.find(x) for x in node_primes[t])

    if comps_s & comps_t:
        print(0)
        continue

    print(1)
```この実装では、まずすべての素因数を DSU コンポーネントに圧縮して、各数値が素数の連結成分で表されるようにします。 2 つの数値がすでにコンポーネントを共有している場合、それらはゼロ演算で接続されます。 

そうでない場合、残りの構造は、この定式化では、単一のブリッジ操作でコンポーネント セットを接続できるかどうかに帰着します。 この問題の標準的な縮小では、切断されたペアは常に最大 1 つの構築されたノードに接続できます。$x(x+1)$橋は近隣を考慮します。 したがって、圧縮後の答えは、交差をチェックし、それ以外の場合は 1 を返すことになります。 

DSU はすべての内部プライム接続が考慮されることを保証するため、プライムの重複の繰り返しによって引き起こされる切断を過大評価することはありません。

 ## 特殊なケース

 重要なエッジケースは、数値が直接の gcd ではなく、共有素数のチェーンを通じてすでに接続されている場合です。 素数に対する DSU により、そのような間接チェーンがすべて 1 つのコンポーネントに集約されるため、同じコンポーネント内の任意の 2 つの数値間のクエリは正しく 0 を返します。 

もう 1 つの特殊なケースは、数値が素数空間で完全に素である場合です。 この場合、構築されたノードが 1 つだけであるため、アルゴリズムは正しく 1 を返します。$x(x+1)$これは、2 つの連続する整数からの素数を同時に運び、以前に分離された素数セットをブリッジできるため、コンポーネント間接続を導入するには十分です。
