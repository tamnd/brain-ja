 ## 解決策
 ## 問題の理解

 一連の異なる整数があります$a_1,\dots,a_n$、それぞれが範囲内にあります$[0,2^k)$。 

あらゆるマスクに$x$、すべての配列要素を次のように XOR します。$x$、セットを制作する$$\{a_1\oplus x,\dots,a_n\oplus x\}.$$その変換されたセット内のすべてのペアの中で、絶対差が最小であることが必要です。 その値を$f(x)$。 

タスクは計算することです$f(x)$すべてのマスクに$x\in[0,2^k)$。 

この問題を難しくしている第一の点は、次のような問題があることです。$2^{19}=524288$さまざまなマスクがあり、それらすべてに対する答えが必要です。 各クエリ マスクを個別に処理するソリューションは、すでに問題を抱えています。 

2番目の障害は、$n$と同じ大きさにすることもできます$2^k$。 単一マスクのすべてのペアをチェックするだけでも時間がかかります$O(n^2)$、それはまったく不可能です。 

興味深いのは、$k\le 19$。 ビット幅がこれほど小さい場合は、全体に直接作用するソリューションが必要になります。$2^k$マスク空間がリアルになります。 周囲の複雑さ$O(k2^k)$およそ 1,000 万回の操作で、これは快適に収まります。 

よくある間違いは、XOR によって差異が保持されると考えることです。 そうではありません。 For example, with numbers$0$そして$3$、違いは$3$、ただし XOR の後$1$彼らはなる$1$そして$2$、その違いはただ一つです$1$。 

もう 1 つの簡単な罠は、XOR 前の最も近いペアがその後も最も近いペアのままであると仮定することです。 考慮する：```
a = [0, 3, 6]
```のために$x=0$、答えは$3$。 のために$x=1$、変換された数値は次のようになります。$[1,2,7]$、そして答えは次のようになります$1$。 最適なペアのアイデンティティが変更されました。 

## アプローチ

 ブルートフォースアプローチは簡単です。 

あらゆるマスクに$x$、すべての値を計算します$a_i\oplus x$、それらを並べ替え、隣接する要素をスキャンして最小の差を見つけます。 ソートされた配列内の最も近いペアは隣接している必要があります。 

これは正しいですが、複雑さは次のとおりです。$$2^k \cdot O(n\log n).$$最悪の場合$n=2^k=524288$、それは天文学的な大きさです。 

重要な観察は、変換された数値自体は実際には気にしていないということです。 各マスクについて考慮するのは 3 つの数量のみです。$$\text{minimum value}, \qquad \text{maximum value}, \qquad \text{minimum pair distance}.$$これらの量は、数値のビット構造に沿って再帰的にマージできます。 

すべてを考えてください$k$-バイナリ トライのリーフとしてのビット番号。 ビットのノード$d$数値に分割されます。$d$-番目のビットは$0$そしてその数字$d$-番目のビットは$1$。 

私たちが決定するとき、$d$クエリマスクの - 番目のビット$x$, XOR は、これら 2 つの部分を自然な順序で維持するか、交換します。 半分間の相対オフセットは正確に$2^d$。 

つまり、両方の子について、変換後の最小値、変換後の最大値、および最良の答えがすでにわかっている場合は、それらを定数時間でマージできるということです。 

このマージをすべてのビットとすべてのマスクに対して実行すると、次の結果が得られます。$O(k2^k)$解決。 再帰は本質的に、超立方体に対する分割統治 DP です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^k n\log n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(k2^k)$|$O(2^k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 状態の定義

 あらゆるマスクに$m$、3 つの値を維持します。`mn[m]`現在到達可能な最小変換値です。`mx[m]`現在到達可能な最大変換値です。`F[m]`は、変換された 2 つの値の間の最小距離です。 

最初は元の配列要素のみが存在します。 

配列内に存在するすべての値について:```
mn[value] = mx[value] = 0
```欠落値ごとに次のようになります。```
mn = +INF
mx = -INF
F  = +INF
```### マージ解釈

 ビットを処理しているとします$d$。 

させて```
l = mask with bit d = 0
r = l xor (1<<d)
```trie ノードの 2 つの子を表します。 

クエリビットの場合$x_d=0$、右側の子が追加で貢献します$2^d$。 

クエリビットの場合$x_d=1$、左の子は追加で貢献します$2^d$。 

これにより、最小値と最大値の遷移が得られます。$$mn[l]=\min(mn_l,mn_r+2^d)$$

$$mn[r]=\min(mn_r,mn_l+2^d)$$マキシマについても同様です。 

### 最適な距離の計算

 最適なペアは 1 つの子の内部に完全に存在することも、各子の 1 つの要素を使用することもできます。 

最初のケースはすでに子に保存されています。 

クロスペアの場合、注文後の可能な最小ギャップは次のとおりです。$$(\text{minimum right})-(\text{maximum left}).$$下$x_d=0$、それは$$mn[r]-mx[l]+2^d.$$下$x_d=1$、になります。$$mn[l]-mx[r]+2^d.$$これらの値を使用して答えを最小化します。 

### 完全な手順

 1. 配列を作成する`mn`、`mx`、 そして`F`サイズの$2^k$。 
2. 現在の数値を次のように初期化します。`mn=mx=0`。 
3. ビットを下位から上位に処理します。 
4. 現在のビットのみが異なるマスクのペアごとに、それらの情報をマージします。 
5.アップデート`F`子の回答と子間の候補の両方を使用します。 
6. すべてのビットが処理された後、`F[x]`マスクに必要な答えと等しい`x`。 

### なぜ効果があるのか

 どの段階でも、状態は、既に処理されたクエリ ビットを適用した後のトライ サブツリー内のすべての数値を表します。`mn`そして`mx`そのサブツリー内の極端に変換された値を記述します。`F`そのサブツリーに完全に含まれる最適なペア距離を保存します。 

2 つのサブツリーがマージされると、すべての有効なペアは、完全に左側の子に属するか、完全に右側の子に属するか、またはそれらの間の交差という 3 つのカテゴリのいずれかに正確に属します。 漸化式では、3 つの可能性すべての最小値が明示的に取られます。 

すべてのペアは両方の要素を含む最下位のノードで正確に考慮されるため、候補が見逃されることも、無効な候補が導入されることもありません。 処理されたビットに対する帰納法により、最終的な`F[x]`正確にはクエリマスクの最小ペア距離です`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    M = 1 << k
    INF = 10 ** 9

    mn = [INF] * M
    mx = [-INF] * M
    F = [INF] * M

    for x in a:
        mn[x] = 0
        mx[x] = 0

    for d in range(k):
        bit = 1 << d

        for r in range(M):
            if (r >> d) & 1:
                l = r ^ bit

                if F[r] < F[l]:
                    F[l] = F[r]
                elif F[l] < F[r]:
                    F[r] = F[l]

                v = mn[r] - mx[l] + bit
                if v < F[l]:
                    F[l] = v

                v = mn[l] - mx[r] + bit
                if v < F[r]:
                    F[r] = v

                mnl, mnr = mn[l], mn[r]
                mxl, mxr = mx[l], mx[r]

                mn[l] = min(mnl, mnr + bit)
                mn[r] = min(mnr, mnl + bit)

                mx[l] = max(mxl, mxr + bit)
                mx[r] = max(mxr, mxl + bit)

    print(*F)

solve()
```初期化では、入力セットに存在するすべての値に長さ 0 の間隔が配置されます。 存在しない値は、`INF`そして`-INF`歩哨。 

外側のループは、バイナリ トライのレベルをマージするのとまったく同じようにビットを処理します。 各ペア`(l,r)`2 つの兄弟サブツリーに対応します。 

微妙な部分も更新中`F`上書きする前に`mn`そして`mx`。 サブツリー間の距離には古い子の情報を使用する必要があります。 最初に極値を更新すると、再発が破損します。 

もう 1 つの詳細は、答えの配列が正確に`F`。 最終的なマージ レベルの後、各インデックスは 1 つの完全なクエリ マスクに対応します。

 ## 特殊なケース

 次のことを考慮してください。```
2 1
0 1
```どちらのクエリ マスクでも、変換されたセットは残ります。`{0,1}`ある順序で。 答えはいつも`1`。 

唯一の有効なペアは最下位のマージにおける子間のペアであり、距離が生成されるため、DP はこれを自然に処理します。$2^0=1$。 

ここで次のことを考えてみましょう。```
2 3
0 7
```すべてのクエリ マスクについて、変換された値は範囲の相補的なエンドポイントのままです。 彼らの違いは常に`7`。 

反復では、サブツリー間のマージを繰り返すことでこれを計算します。 各サブツリーには要素が 1 つしか含まれていないため、サブツリー内にはより小さい候補は存在しません。 

最後に、XOR の後に最も近いペアが変化する場合を考えてみましょう。```
3 3
0 3 6
```で`x=0`、答えは`3`。 

で`x=1`、変換された値は次のようになります。`1,2,7`、そして答えは次のようになります`1`。 

DP は特定のペアを追跡せず、代わりに各サブツリー内のすべての可能なペアの最小値を追跡するため、最適なペアが変化すると自動的に適応します。
