 ## 解決策
 ## 問題の理解

 2 つのサッカー チーム間のペナルティ シュートアウトをシミュレーションしています。各チームは交互に最大 5 回のキックを行い、合計 10 回のキックを行います。 各キックは成功する (ゴールを決める)、失敗する、または不明です。 入力では、これらの結果を表す 10 文字の文字列が与えられます。「1」は確実なゴール、「0」は失敗、「?」はゴールを意味します。 不確実な結果に対して。 

一方のチームの得点により、残りのキック数を考慮してもう一方のチームが追いつくことが不可能になった場合、主審はシュートアウトを早期に終了します。 私たちの仕事は、先頭チームの最も楽観的な結果と後続チームの最悪の結果を考慮して、*銃撃戦が終了するまでに必要なキックの最小数**を決定することです。 

制約は厳しいですが、管理可能です。 各文字列は長さ 10 に固定されており、最大 1,000 個のテスト ケースを含めることができます。 テスト ケースごとの合計作業量が「?」の数で指数関数的に増加する可能性があるためです。 完全な総当たり攻撃を試みる場合は、よりスマートな線形時間シミュレーションを見つける必要があります。 エッジケースには、「?」でいっぱいの文字列が含まれます。 または、試合をできるだけ早く終了できるようにする文字列。例:`1111100000`10回目のキックの前に終了する可能性があります。 

単純なアプローチでは、交互キックを無視したり、早期終了には残りの可能性のあるゴールを考慮せずに得点されたゴールのみをカウントする必要があると想定したりすると、誤った計算を行う可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、「?」のあらゆる組み合わせが考慮されます。 「1」または「0」のいずれかです。 10 回のキックの場合、最大でも$2^{10} = 1024$単一の文字列では実現可能ですが、最大で次の文字列が必要になります。$10^3 \cdot 1024$すべてのテスト ケースにわたる操作。 これでも実行できますが、より適切に実行して、不必要な組み合わせを避けることができます。 

重要な洞察は、すべての結果を明示的に必要とするわけではないということです。 **テスト ケースごとに 2 回銃撃戦をシミュレート**できます。 まず、すべての「?」を想定します。 最初のチームのターンにはゴールがあり、すべての「？」 2 番目のチームのターンはミスです。 これにより、最初のチームの早期勝利を保証するために必要なキックの数が最小限に抑えられます。 次に、2 番目のチームに対してその逆を行います。 両方のシミュレーションの後、キックの数が少ないほど、早期終了の可能性は真に最小限になります。 

この観察により、文字列の長さの問題が指数関数的な問題から線形問題に軽減されます。$O(10)$テストケースごと、または$O(10 \cdot t) = O(10^4)$合計は制限時間内に十分に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^10 * t) | お(1) | 受け入れられるが不要 |
 | 最適なシミュレーション | O(10 * t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのスコアを初期化します。`score1`最初のチームにとって、`score2`2番目のチームのために。 両チームの残りのキックも追跡します。 
2. 「楽観的な最初のチーム」シナリオの銃撃戦をシミュレートします。 各キックについて:

 1. 最初のチームのターンの場合、「1」または「?」の場合はゴールとしてカウントします。 「0」の場合は0をカウントします。 
2. 2 番目のチームのターンの場合、「1」の場合のみゴールとしてカウントします。 扱う '？' ミスとして。 
3. 各キックの後、一方のチームのスコアがもう一方のチームの**可能な最大残りスコア**を超えているかどうかを確認します。 その場合、キックインデックスを記録して終了します。 
3. 「?」の処理を交換して、「楽観的な 2 番目のチーム」シナリオのシミュレーションを繰り返します。 各チームごとに。 
4. 2 つのシミュレーションから記録されたキックの最小数を返します。 

機能する理由: 審判は、残りの潜在的な最大スコアに基づいてシュートアウトを停止します。 極端なシナリオをシミュレートすると、「?」の実際の結果とは関係なく、終了が保証される最も早い時点を確実に見つけることができます。 これにより、すべての組み合わせを列挙することなく正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_kicks(s: str) -> int:
    def simulate(s, first_opt=True):
        score1 = score2 = 0
        rem1 = rem2 = 5
        for i in range(10):
            if i % 2 == 0:  # first team
                if s[i] == '1' or (s[i] == '?' and first_opt):
                    score1 += 1
                rem1 -= 1
            else:  # second team
                if s[i] == '1' or (s[i] == '?' and not first_opt):
                    score2 += 1
                rem2 -= 1
            if score1 > score2 + rem2:
                return i + 1
            if score2 > score1 + rem1:
                return i + 1
        return 10

    return min(simulate(s, True), simulate(s, False))

t = int(input())
for _ in range(t):
    s = input().strip()
    print(min_kicks(s))
```機能`simulate`単一の極端なシナリオをモデル化します。`first_opt`「?」に遭遇したときにどのチームを支持するかを決定します。 審判のロジックは各キックの直後に適用され、後続チームがまだ追いつくことができるかどうかをチェックします。 正確さを期すために、両方のシミュレーション間の最小値を返します。

 ## 特殊なケース

 文字列の場合`??????????`、シミュレーションでは両方の極端なシナリオが考慮されます。 最初のチームが常に「?」を得点した場合 2 番目のチームは常にミスします。最初のチームはキック 6 で勝つことができます。逆転した場合、2 番目のチームも 6 で勝つことができます。アルゴリズムは 6 を返しますが、これは正しいです。 「?」の交互の処理 完全に列挙することなく、考えられるすべての結果に対して早期終了が正しく評価されるようにします。 

のために`1111100000`、最初のチームは5回のキック後に大きなリードを持っています。 たとえ理論的には 2 番目のチームが残りのキックで得点できたとしても、審判のロジックは次のことを検出します。
