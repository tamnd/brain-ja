 ## 解決策
 ## 問題の理解

 各人のフルネームは一連の単語として与えられます。 その名前から、すべての単語の最初の文字を取得し、これらの文字を順番に連結することによって、NAME と呼ばれるコンパクトな識別子が構築されます。 したがって、「ホセ・オソリオ・ヒメネス・オロスコ」のような名前は「ジョジョ」になります。 

タスクは、出力用にこれらの識別子を明示的に生成することではなく、指定されたすべての人々の中にそのような異なる NAME 文字列が何個存在するかをカウントすることです。 

入力サイズは最大 10,000 の名前で、各名前には最大 20 単語が含まれます。 これは、処理される単語の総数が最大でも数十万語であることを意味します。 各単語を 1 回処理し、単語ごとに一定の作業を実行するソリューションであれば、制限時間内に問題なく収まります。 私たちが許容できないのは、すべての NAME を他のすべての NAME と比較することです。これは、人数に二次関数が導入されてしまうためです。 

微妙な特殊なケースは、重複した構造から発生します。 2 つの完全に異なるフルネームから、同一のイニシャルが生成される場合があります。 たとえば、「juan perez」と「jose prieto」は両方とも「jp」を生成するため、これらは 1 つの一意の NAME としてカウントされる必要があります。 もう 1 つの特殊なケースは、同一のフルネームが複数回出現し、これも単一の NAME に折りたたまれることです。 

単純な間違いは、入力名の一意性が生成されたイニシャルの一意性を意味すると仮定することです。 この仮定は、異なる単語シーケンスが同じ最初の文字を共有するたびに、直ちに失敗します。 

## アプローチ

 直接的なアプローチは、各人の NAME を計算してリストに保存し、新しい NAME ごとに、リストをスキャンしてその名前がすでに表示されているかどうかを確認することです。 これは、比較による一意性を明示的に強制するため、正しいです。 ただし、各挿入では、以前に確認されたすべてのエントリをスキャンする必要があるため、最悪の場合、約 N の 2 乗比較が発生します。 N が最大 10,000 の場合、これは 1 億回の比較に達する可能性があります。これは、文字列が関係する場合、Python では境界線に達するか、遅すぎます。 

重要な観察は、私たちは、頻度や順序ではなく、個別の文字列のみを考慮しているということです。 これを認識すると、問題は一連の文字列を維持することに帰着します。 ハッシュ セットでは、予期される定数時間の挿入とメンバーシップ チェックが行われるため、各名前を 1 回処理し、そのイニシャルを計算して、結果をセットに挿入できます。 最終的な答えは単純にセットのサイズです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースリストチェック | O(N²・L) | O(N・L) | 遅すぎる |
 | NAME のハッシュ セット | O(N・L) | O(N・L) | 承認済み |

 ここで、L は名前ごとの平均単語数を表します。イニシャルを抽出するには各単語をスキャンする必要があるためです。 

## アルゴリズムのチュートリアル

 1. 名前 N の数を読み取ります。これにより、処理する独立した文字列の数が決まります。 
2. 空のセットを初期化して、すべての一意の NAME 文字列を保存します。 セットは、独自性を効率的に強化する中心的な構造です。 
3. N 個の名前のそれぞれについて、行を読み取り、トークンに分割します。 最初のトークンは単語の数で、残りのトークンは名前の単語です。 後に続く単語の数を知ることを除いて、整数は無視します。 
4. すべての単語を反復処理し、各単語の最初の文字を取得して NAME を作成します。 順番に連結すると、元の名前の構造が維持されます。 
5. 構築された NAME をセットに挿入します。 すでに存在する場合、セットは変更されずに残ります。これはまさに私たちが望んでいることです。 
6. すべての名前を処理した後、セットのサイズを出力します。 これは、検出された個別の NAME 値の数を表します。 

### なぜ効果があるのか

各名前は、単語のみに基づいて単一の文字列に決定的にマッピングされます。 このマッピングは同一の入力間で一貫しているため、最初の文字のシーケンスが一致する場合にのみ、2 人が同じ NAME を生成します。 セットには、個別の値ごとに 1 つの代表が正確に格納されるため、すべての入力を処理した後、このマッピングにある名前のすべての同値クラスは、セットに 1 つの要素だけを提供します。 したがって、最終的なサイズは、一意の NAME の数とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    seen = set()

    for _ in range(n):
        parts = input().strip().split()
        x = int(parts[0])
        words = parts[1:]

        name = ''.join(word[0] for word in words)
        seen.add(name)

    print(len(seen))

if __name__ == "__main__":
    main()
```このソリューションは、各行を 1 回読み取り、すぐに圧縮表現を構築します。 各行の先頭の整数は、入力によって一貫性が保証されるため、スライスの正確さに厳密には必要ありませんが、概念的に構造を検証するのに役立ちます。 

重要な実装の詳細は、ジェネレーター式を使用して NAME を構築することです。 これにより、ループ内で文字列の連結が繰り返されることが回避されます。そうしないと、Python 文字列で二次的な動作が発生する可能性があります。 使用する`join`名前ごとに直線的な構造を保証します。 

セット`seen`中心となる正確性メカニズムです。 手動チェックを行わずに、重複が自動的にマージされることが保証されます。

 ## 特殊なケース

 重要な特殊ケースの 1 つは、同じ名前が繰り返されることです。 例えば：```
3
2 a b
2 a b
2 a b
```それぞれの名前は「ab」になります。 アルゴリズムはそれらを順番に処理します。 

名の後に = {ab} を設定します。 2 番目以降の挿入は、既に存在するため無視されます。 3回目以降も変化なし。 最終出力は 1 で、個別の NAME 値の数と一致します。 

もう 1 つのケースは、名前が最大長である場合です。```
1
20 a a a a a a a a a a a a a a a a a a a a
```構築される NAME は、20 個の「a」文字が繰り返される文字列です。 セットは正確に 1 つの要素を受け取り、出力は 1 です。文字列の構築とハッシュは長さに比例してスケールされ、挿入は 1 つだけであるため、アルゴリズムはこれを問題なく処理します。 

最後の微妙なケースは、異なる名前のイニシャルが衝突する場合です。```
2
2 aa bb
2 ab ab
```どちらも「ab」を生成します。 このセットは再びそれらを 1 つのエントリにまとめます。これは、一意性が完全な名前の構造ではなく、派生した NAME によってのみ決定されることを示しています。
