 ## 解決策
 ## 問題の理解

 円形に配置されたキャンディ ブロックが与えられます。各ブロックには小文字で表されるフレーバーがあります。 循環性は、最初と最後の位置が隣接していることを意味するため、取得したセグメントは文字列の終わりに回り込むことができます。 

この円から連続したセグメントを選択したいのですが、そのセグメントはフレーバー制約を満たす必要があります。つまり、フレーバーは次の値を超えて出現することはできません。`k`選択したセグメント内の回数。 複雑なのは、あるフレーバーのブロックを選択すると、元のサークル内でそのフレーバーの最大の連続ラン全体を取得する必要があることです。 したがって、個々の文字を選択するのではなく、同じ文字の連続した全体を選択します。 

タスクは、文字に展開し直したときに文字が次の文字を超えないように、これらのランのセグメント (おそらくラップアラウンド) を選択することです。`k`文字数の合計が最大化されます。 有効なセグメントが存在しない場合は、次のように出力します。`-1`。 

制約は次のとおりです`n = 10^6`したがって、文字に対して明示的にすべての循環開始と終了を試みるソリューションは遅すぎます。 部分文字列に対する二次走査さえ不可能です。 問題の構造から、文字列を圧縮し、オーバーランを理由にする必要があることがわかります。 

素朴なアプローチが文字を実行するのではなく独立して扱う場合、微妙な失敗例が発生します。 たとえば、`"aaa"`と`k = 2`素朴な見方では、1 つまたは 2 つの文字を選択することが可能であると考えるかもしれませんが、ルールでは 3 つすべてを選択することが強制されます。`a`を一度に実行すると、即座に制約に違反するため、答えは次のようになります。`-1`。 

もう 1 つのエッジケースは、ラップアラウンドによって人為的にロングランが発生する場合です。 例えば、`"aaabaaa"`は円形で、境界はより長いものに結合します。`a`セグメント。 循環マージを無視したソリューションでは、実行サイズが過小評価され、無効なセグメントが誤って受け入れられます。 

## アプローチ

 直接的な総当たり戦略では、円形文字列上のすべての可能な開始位置を試し、各文字のカウントを維持しながら前方に拡張します。 各拡張機能では、頻度カウントを更新し、有効性をチェックする必要があります。 各チェックが O(1) であっても、開始が O(n) で拡張が O(n) なので、O(n²) になりますが、これは 100 万文字には遅すぎます。 

重要な構造上の観察は、ランから任意の文字を選択するとラン全体が強制されるため、連続する同一の文字が原子単位として動作するということです。 これは、文字列をランに圧縮し、各ランにその文字と長さを格納することを示唆しています。 

圧縮後、問題はランの円形配列上で連続するセグメントを選択することになります。各ランはその全長が文字頻度バジェットに寄与します。 すべての文字について、サブ配列内のラン長の合計が以下を超えないような、ランの循環サブ配列の最大合計長が必要です。`k`。 

これは円形配列上の 2 ポインタ スライディング ウィンドウですが、文字ごとの合計を追跡する追加の制約が付いています。 実行配列を 2 倍にすることで循環性をシミュレートし、周波数カウンターでウィンドウを維持できます。 ウィンドウは貪欲に拡大し、文字が超過すると縮小します。`k`。 

これにより、問題は文字レベルの推論から実行レベルの間隔の最適化に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(26) | 遅すぎる |
 | 実行圧縮 + スライディング ウィンドウ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を連続した実行のリストに変換し、各実行が格納されます。`(character, length)`。 これが必要なのは、選択したセグメントにはラン全体が含まれている必要があり、個々の文字は意味のある決定単位ではないためです。 
2. 円上のどこからでも開始できる場合は、実行リストをそれ自体と連結することで循環性をシミュレートします。 これにより、ラップアラウンド セグメントを通常の部分配列として扱うことができます。 
3. 2 つのポインターを維持する`l`そして`r`この 2 倍の実行配列と、現在ウィンドウに含まれている各タイプの文字数を格納するサイズ 26 の頻度配列を対象とします。 
4. 展開する`r`ステップバイステップで、その位置にフルランを追加します`r`窓の中へ。 対応する文字にランレングスを加算して文字数を更新します。 
5. 各展開後、文字数が超過していないか確認します。`k`。 存在する場合は、ランを削除して左から縮小します。`l`すべての制約が再び満たされるまで。 これは有効です。なぜなら、ランを削除してもカウントが減るだけであり、常に最も広い有効ウィンドウが次の値で終わる必要があるからです。`r`。 
6. 有効なウィンドウごとに、その全長を計算し、それが現在の最良のものより大きい場合は、答えを更新します。 また、循環選択は複数の完全なサイクルを再利用してはいけないため、ウィンドウの長さが元の実行数を超えないようにします。 
7. 有効なウィンドウが正の長さを生成しない場合、出力`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、実行可能な解は円上の連続セグメントに対応するという事実に基づいています。 実行配列を 2 倍にすることにより、すべての円形セグメントが線形サブ配列になります。 スライディング ウィンドウは、現在のウィンドウ内のすべての文字頻度が範囲内にあるという不変条件を維持します。 有効な場合のみ拡大し、無効な場合はすぐに縮小するため、記録されたすべての候補が実行可能です。 2 ポインター戦略では、各実行がウィンドウに追加およびウィンドウから削除されるのは最大 1 回であることが保証され、すべての最大有効セグメントが繰り返しや省略なしに探索されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # build runs
    runs = []
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        runs.append((s[i], j - i))
        i = j

    m = len(runs)
    
    # edge: if any run itself exceeds k, that character can never be chosen
    # but it doesn't immediately mean impossible; only matters if we try selecting it
    # if all runs exceed k, answer is -1
    if all(length > k for _, length in runs):
        print(-1)
        return

    arr = runs * 2

    freq = [0] * 26
    l = 0
    total = 0
    best = 0
    best_l = 0
    best_r = 0

    def add(run):
        nonlocal total
        c, v = run
        freq[ord(c) - 97] += v
        total += v

    def remove(run):
        nonlocal total
        c, v = run
        freq[ord(c) - 97] -= v
        total -= v

    for r in range(2 * m):
        add(arr[r])

        while True:
            ok = True
            for x in range(26):
                if freq[x] > k:
                    ok = False
                    break
            if ok:
                break
            remove(arr[l])
            l += 1

        if r - l + 1 <= m:
            if total > best:
                best = total
                best_l, best_r = l, r

    if best == 0:
        print(-1)
        return

    # reconstruct answer from best window
    # map run indices back to original string
    res = []
    for i in range(best_l, best_r + 1):
        c, v = arr[i]
        res.append(c * v)

    print(best)
    print("".join(res))

if __name__ == "__main__":
    solve()
```実行境界によってのみ有効なカット ポイントが定義されるため、解決策は入力を実行に圧縮することから始まります。 次に、実行配列を 2 倍にして、特別なケーシング境界ロジックを使用せずに循環ラップアラウンドを表します。 

スライディング ウィンドウは 2 つのポインターを使用します。 右ポインターが進むたびに、実行全体が周波数トラッキングに挿入されます。 いずれかの文字が超過した場合`k`、有効性が復元されるまで左から縮小します。 周波数配列により、一定のアルファベット時間で制約違反をチェックできるようになります。 

条件`r - l + 1 <= m`同じ循環構造を人為的に 2 回再利用することになる、完全な実行サイクルを複数回使用することを防ぎます。 

最後に、ランを文字に展開して答えを再構築します。

 入力:```

```圧縮を実行すると、以下が生成されます。`[(a,2), (b,1), (c,2), (b,1), (a,1), (b,1), (a,1)]`2 倍の実行にわたるウィンドウをシミュレートします。 

| ステップ | l | r | ウィンドウが実行される | 周波数(a,b,c) | 有効 | 合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | a2 | (2,0,0) | はい | 2 |
 | 2 | 0 | 1 | a2 b1 | (2,1,0) | はい | 3 |
 | 3 | 0 | 2 | a2 b1 c2 | (2,1,2) | はい | 5 |
 | 4 | 0 | 3 | a2 b1 c2 b1 | (2,2,2) | はい | 6 |
 | 5 | 0 | 4 | a2 b1 c2 b1 a1 | (3,2,2) | いいえ | 縮小 |

このトレースは、制約が実行境界ごとではなく文字ごとにどのように適用されるかを示します。これは、実行数が集計されるため重要です。 

### 例 2

 入力:```
3 4
aaa
```圧縮を実行します。`[(a,3)]`唯一の実行にはすでに長さ 3 があるため、`k = 4`、技術的には単独で有効です。 ただし、循環解釈により、次のいずれかの選択が強制されます。`a`には 3 の完全な実行が含まれるため、最も有効なセグメントは完全な文字列になります。 

| ステップ | l | r | ウィンドウ | 周波数(a) | 有効 | 合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | a3 | 3 | はい | 3 |

 頻度が有効であっても、すべての構造的制約が選択を禁止している場合、より厳密な解釈の下では空でない選択を形成する方法はありません。 解釈によっては、実装はゼロを超える有効な改善を正しく検出し、出力します。`-1`必要に応じて。 

この例では、単一実行文字列がアトミックな実行可能性チェックとして動作することを強調しています。

 ## 特殊なケース

 重要なエッジ ケースは、文字列全体が 1 つの繰り返し文字である場合です。 で`"aaaaa"`と`k = 2`、実行圧縮により単一の実行が生成されます。`(a,5)`。 アルゴリズムは、実行が開始されると、包含が制約に違反していることを即座に検出するため、スライディング ウィンドウは有効なセグメントを生成しません。`-1`。 

もう 1 つのケースは、有効なセグメントがラップアラウンド後にのみ存在する場合です。 のために`"aabccbaa"`中程度の`k`、最適なセグメントは終わり近くで始まり、最初から続く可能性があります。 実行配列を 2 倍にすると、このセグメントが通常の連続した間隔として表示されるようになり、スライディング ウィンドウは特別な循環ロジックを使用せずにセグメントを検出できます。 

最後の微妙なケースは、同じキャラクターの複数の短いランが他のキャラクターによって分離されている場合です。 頻度はグローバルに集計されるため、アルゴリズムは、隣接していなくても同じ文字の繰り返しの寄与を正確に考慮し、純粋にローカルな貪欲スキャンで発生する偶発的な過小カウントを防ぎます。
