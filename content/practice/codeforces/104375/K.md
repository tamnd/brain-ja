 ## 解決策
 ## 問題の理解

 ゲームは、各レベルがノードであり、各前提条件関係が有向エッジである有向グラフとしてモデル化できます。 レベルからのエッジがある場合`u`平らにする`v`、その後仕上げ`u`ロックを解除する`v`、 それで`v`以降プレイ可能になります`u`完成しました。 

ランと呼ばれる 1 回のプレイスルーは、指定された開始レベルのいずれか 1 つで開始され、指定されたエッジに沿って進み、常にロック解除されたレベルに移動し、プレイ可能なオプション間で出力遷移がないレベルに到達します (指定された終了レベルの 1 つであることが保証されます)。 ランを終了した後、プレーヤーは新しいゲームを最初から開始しますが、厳しい制限があります。以前のランで使用されたすべてのレベルは、今後のすべてのランでは永久に使用できなくなります。 

目標は、すでに使用されているノードを再利用せずに、開始レベルから別の実行を開始して終了レベルに到達することができなくなる前に、実行できる完全な実行の回数を最大化することです。 

重要な相互作用は、実行が独立していないことです。 各実行では、選択したパス上のすべてのレベルが消費され、それらのノードは後で再利用できません。 これにより、問題は、複数のパスにノードが出現できないという制約のもとで、開始ノードのセットから終了ノードのセットまで可能な限り多くの有効なパスを選択することになります。 

制約`N ≤ 100`指数関数的なパスの列挙は実行不可能であることを強く示唆しています。 中程度の分岐因子グラフであっても、ソースとシンク間の単純なパスが指数関数的に多く含まれる可能性があるため、すべての実行をリストまたは試行しようとするアプローチは失敗します。 多項式フローベースまたはマッチングベースの定式化が期待されます。 

複数の開始レベルが重複する中間構造に到達できる場合、微妙なエッジ ケースが発生します。 たとえば、2 つのスタートが両方ともシンクに到達する前に共有チェーンにつながる場合、1 つのパスを単純に貪欲に選択すると、後でより最適な組み合わせがブロックされる可能性があります。 

もう 1 つのエッジ ケースは、レベルが開始点から到達可能であり、異なる終了点への複数の潜在的なパス上にある場合に発生します。 貪欲なパス選択の早い段階でこれを選択すると、可能性のある素な実行の総数を減らすことができます。 

## アプローチ

 直接的な試みは、実行を貪欲にシミュレートすることです。 開始ノードを繰り返し選択し、DFS または BFS を使用して終了ノードへのパスを検索し、そのパス上のすべてのノードを削除し、有効なパスが存在しなくなるまで繰り返すことができます。 これは簡単で、各実行は個別に有効です。 

ただし、このアプローチはパスが選択される順序に大きく依存します。 ローカルで有効なパスは、後で他の 2 つの独立したパスを有効にするために重要なノードを消費する可能性があります。 ボトルネックが共有されているグラフでは、貪欲な選択により合計数が大幅に削減される可能性があります。 

中心となる観察は、各実行はあるソース ノードからあるシンク ノードへのパスであり、実行をまたがって再利用されるノードはないということです。 これは、まさに、複数のソースとシンクを持つ有向グラフにおける頂点の非結合パスの最大数の問題です。 

これは、ノード分割を使用して最大流量問題に変換できます。 各ノードは、容量 1 のエッジによって接続された「インノード」と「アウトノード」に分割され、ノードは最大 1 回の実行で使用できるようになります。 あらゆるオリジナルの有向エッジ`u -> v`から無限の容量エッジになります`u_out`に`v_in`。 スーパー ソースはすべての開始ノードに接続し、すべての終了ノードはスーパー シンクに接続します。 

このネットワークの最大フローは、互いに素な有効な実行の最大数と等しくなります。 フローの各単位は、開始から終了までの 1 つの完全なパスに対応し、ノード容量の制約により、異なる実行間でレベルが再利用されないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 貪欲なパスの削除 | 最悪の場合は指数関数的 | O(N + M) | 遅すぎる/不正確 |
 | ノード分割時の最大流量 | O(F · E) とディニック、F ≤ N | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、パスが実行に対応し、フロー ユニットが完了したプレイスルーに対応するフロー ネットワークに変換します。 

1. すべてのノードを分割する`i`2つのノードに分割`i_in`そして`i_out`、それらを容量 1 のエッジに接続します。これにより、各レベルは最大 1 回の実行で使用できるようになります。 
2. 前提条件となるエッジごとに`u -> v`から有向エッジを追加します。`u_out`に`v_in`無限の容量を備えています。 これにより、エッジを横断できる異なるランの数を制限することなく、元の移動ルールが維持されます。 
3. スーパーソースノードを追加します。 に接続します`s_in`開始レベルごとに`s`これにより、各開始レベルが最大 1 回の実行を開始できるようになります。 
4. スーパーシンクノードを追加します。 接続する`e_out`終了レベルごとにシンクへ`e`これにより、各終了レベルが最大 1 回の実行で終了できるようになります。 
5. スーパー ソースからスーパー シンクまでの最大流量アルゴリズムを実行します。 結果として得られるフロー値は、素の実行の最大数です。 

この構造が機能する理由は、任意の有効な実行がフロー ネットワーク内のパスに対応し、フローの任意の単位がそのようなパスの選択に対応するためです。 ノードの分割により、すべての実行にわたって非結合性が保証されます。 

### なぜ効果があるのか

 実行可能な実行セットは、ソースからシンクまでの一連の頂点が分離されたパスを定義するため、各パスが 1 つのユニットを伝送する有効なフローに直接マッピングできます。 逆に、整数フローはソースからシンクへのパスに分解でき、各分割ノードの容量 1 制約により、複数のパスにノードが出現しないことが保証されます。 これにより、有効なソリューションと実行可能なフローの間に 1 対 1 の対応関係が確立されるため、フローを最大化すると実行数が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = [s]
        self.level[s] = 0
        for u in q:
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, t, min(f, c))
                if pushed:
                    self.adj[u][i][1] -= pushed
                    self.adj[v][rev][1] += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**9
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

n, s, e = map(int, input().split())
starts = list(map(int, input().split()))
ends = set(map(int, input().split()))
m = int(input())

N = 2 * n + 2
SRC = 2 * n
SNK = 2 * n + 1

dinic = Dinic(N)

for i in range(1, n + 1):
    dinic.add_edge(2 * (i - 1), 2 * (i - 1) + 1, 1)

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dinic.add_edge(2 * u + 1, 2 * v, 10**9)

for st in starts:
    st -= 1
    dinic.add_edge(SRC, 2 * st, 1)

for en in ends:
    en -= 1
    dinic.add_edge(2 * en + 1, SNK, 1)

print(dinic.max_flow(SRC, SNK))
```実装は、各レベルが容量 1 で接続されたノード内とノード外に寄与するノード分割構造を構築することから始まります。 これは、すべての実行にわたって単一の使用を強制するメカニズムです。 

前提条件のエッジは、大容量のアウトノードからインノードに追加されるため、構造を超えた再利用が制限されません。 

開始はスーパー ソースからインノードに接続し、終了はアウトノードからスーパー シンクに接続し、各実行の開始と終了が適切に行われるようにします。 

最後に、Dinic のアルゴリズムは、切り離されたソースからシンクへのパスの最大数を計算します。これは、ゲーム実行の最大数に直接対応します。

 ## 特殊なケース

 重要なエッジ ケースは、複数の有効なパスが単一の中間ノードをめぐって競合する場合です。 たとえば、2 つの開始レベルが両方とも、異なる終点に到達する前に共有コリドーにつながっている場合、ノード キャパシティは 1 であるため、そのコリドーを通過できるのは 1 つのランだけです。 フロー モデルは、最初のパスが選択された後、共有ノードの分割エッジを飽和させることでこれを自然に強制します。 

もう 1 つのケースは、開始レベルが終了レベルでもある場合です。 この構造により、そのノードを介してソースからシンクへの直接接続が可能になり、その容量制限により、すべての実行で 1 回しか使用できないことが保証されます。 フローは、グローバルな最適性に応じて、スタンドアロンの実行として使用するか、より長いパス用に予約します。 

最後のケースは、開始レベルが終了レベルに到達できない、完全に切断されたグラフです。 この状況では、フロー ネットワークに拡張パスが存在しないため、最大フローはゼロとなり、実行が不可能であるという事実と一致します。
