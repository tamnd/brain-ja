 ## 解決策
 ## 問題の理解

 私たちは単語の集合と、怪物の体に書かれた長い文字列を与えられます。 課題は、この長い文字列を連続する部分に切り分けて、各部分が指定された単語の 1 つに正確に一致するように、何通りの方法で分割できるかを決定することです。 

有効な「切断計画」は、すべてのセグメントが辞書の単語に対応する文字列のパーティションです。 同じ単語を異なる分割パターンで使用している場合でも、切り取り方が異なると、異なるものとみなされます。 

入力サイズにより、セグメンテーションを明示的に列挙しようとするアプローチは直ちに除外されます。 すべての辞書の単語とターゲット文字列の合計の長さは最大 200,000 であるため、部分文字列を繰り返しスキャンしたり、すべての分割点をバックトラックしたりするアルゴリズムは 2 秒以内には存続しません。 ソリューションでは、各文字をほぼ線形時間、または最悪の場合でも小さな定数の線形時間で処理する必要があります。 

単純な落とし穴は、これをメモ化せずに再帰的な文字列セグメンテーション問題のように扱うことであり、指数関数的な分岐につながります。 もう 1 つの微妙な問題は、辞書の単語の重複です。これにより、同じ接頭辞に対して複数の有効な分解が作成される可能性があり、個別にカウントする必要があります。 

たとえば、辞書に次のような内容が含まれている場合、`a`、`aa`、文字列は`aaaa`の場合、複数の分解が存在し、各位置での異なる分割決定から生じます。 単純な貪欲な DP や単一パスの DP は、これらの代替手段を見逃してしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、インデックス 0 から開始し、プレフィックスに一致するすべての辞書単語を試し、残りのサフィックスを再帰的に調べ、すべての結果を合計しようとします。 これは有効なセグメンテーションの定義を直接モデル化しているため、構造的には正しいです。 ただし、各位置は多くの辞書一致に分岐する可能性があり、文字列の長さは最大 100,000 に達する可能性があるため、再帰ツリーは指数関数的に爆発的に増加する可能性があります。 最悪の場合、次のような文字列`aaaaa...`言葉で`a`、`aa`、`aaa`など、組み合わせによるセグメンテーションの数が得られます。 

重要な観察は、この問題には重複する部分問題があるということです。 位置から始まるサフィックスを分割する方法の数`i`どのようにして到達したかとは無関係です`i`。 これはすぐに動的プログラミングを示唆します。 

すべての位置ですべての単語をスキャンすることを避けるために、視点を逆転させます。 ここでどの単語が一致するかを位置ごとに尋ねる代わりに、反転された単語の高速な前方一致を可能にする構造を構築します。 これは当然トライによって処理されます。 すべての単語をトライに挿入し、文字列を左から右にスキャンすることで、トライを前方に進むことによって、特定の位置で始まるすべての辞書の単語を効率的にチェックできます。 

DP 配列を維持します。`dp[i]`プレフィックスをセグメント化する方法の数です`S[0:i]`。 ポジションごとに`i`、トライを使用して一致を前方に拡張しようとし、終端の単語に到達するたびに、`dp[i]`対応する終了位置に移動します。 

これにより、部分文字列チェックの繰り返しが減り、各文字が制限された回数だけ処理されるようになります。

 ## アルゴリズムのチュートリアル

 すべての辞書単語を含むトライを構築します。各ノードには、文字の遷移と単語がそこで終わるかどうかを示すフラグが格納されます。 

サイズのDP配列も用意しています`|S| + 1`、 どこ`dp[i]`位置で終わるプレフィックスをセグメント化する方法の数を表します`i`。 

設定しました`dp[0] = 1`なぜなら、空のプレフィックスをセグメント化する方法は 1 つだけだからです。 

次に、文字列内のすべての開始位置を反復処理します。 それぞれの立場から、私たちは次の文字に従って前進します。`S`。 辞書の単語の終わりに対応するトライ ノードに到達するたびに、その単語の終了位置の DP 状態を更新します。 

### ステップ

 1. すべての単語をトライに挿入します。 これにより、文字列を繰り返し比較するのではなく、一致した文字に関して線形時間で単語の一致をチェックすることができます。 トライは共有プレフィックスを圧縮しますが、これは効率にとって非常に重要です。 
2. DP 配列を初期化する`dp`長さの`n + 1`、 セット`dp[0] = 1`。 これは、空のプレフィックスを構築する方法が 1 つだけあることをエンコードしています。 
3. インデックスごとに`i`から`0`に`n - 1`、次の場合にのみ、単語の始まりの可能性があるものとして扱います。`dp[i] > 0`。 この位置に到達する方法がない場合、それ以上の移行に貢献することはできません。 
4. トライルートから開始して、位置から文字列をトラバースします。`i`フォワード。 キャラクターごとに`S[j]`、トライで動きます。 遷移が存在しない場合は、これ以上一致する単語がないため、早めに停止してください。 
5. 位置で単語の終わりとしてマークされたトライノードに到達するたびに`j`、 アップデート`dp[j + 1] += dp[i]`。 これは、有効な単語を形成することを表します。`i`に`j`。 
6. モジュロを取る`10^9 + 7`オーバーフローを防ぐために、DP 更新ごとに。 

### なぜ効果があるのか

 どの位置でも`i`、`dp[i]`プレフィックスのすべての有効なセグメンテーションをすでに表しています`S[0:i]`。 からの延長`i`trie traversal を使用すると、次で始まるすべての辞書単語が正確に検索されます。`i`。 一致が成功するたびに、単語境界で終わるプレフィックスの新しい有効なセグメンテーションが作成されます。 すべてのセグメンテーションは何らかの単語境界で終了する必要があり、すべての単語境界はトライ トラバーサルを通じて正確に検出されるため、有効な分解はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("next", "end")
    def __init__(self):
        self.next = {}
        self.end = False

def insert(root, word):
    node = root
    for c in word:
        if c not in node.next:
            node.next[c] = Node()
        node = node.next[c]
    node.end = True

def solve():
    n = int(input())
    root = Node()

    words = [input().strip() for _ in range(n)]
    for w in words:
        insert(root, w)

    s = input().strip()
    m = len(s)

    dp = [0] * (m + 1)
    dp[0] = 1

    for i in range(m):
        if dp[i] == 0:
            continue

        node = root
        for j in range(i, m):
            c = s[j]
            if c not in node.next:
                break
            node = node.next[c]
            if node.end:
                dp[j + 1] = (dp[j + 1] + dp[i]) % MOD

    print(dp[m])

if __name__ == "__main__":
    solve()
```トライ構造では、すべての辞書単語が共有プレフィックス構造に格納されます。 これにより、DP 遷移中に単語を繰り返しスキャンすることが回避されます。 

DP 配列はインデックスの昇順で更新され、位置を処理するときに確実に`i`、それに対するすべての寄与はすでに計算されています。 

ネストされたループと trie トラバーサルを組み合わせることで、辞書の単語の有効な接頭辞のみを検索することが保証されます。 欠落している遷移を早期に中断することで、無効なブランチに対する不必要な作業を防止します。

 ## 特殊なケース

 エッジケースの 1 つは、複数の辞書単語が同じ位置で始まる場合です。 のような入力の場合`s = "aaaa"`言葉で`a`、`aa`、 そして`aaa`の場合、アルゴリズムは各インデックスからすべての有効な継続を探索します。 位置 0 では、`dp[0] = 1`、トライトラバーサルは複数の終端ノードに到達し、複数の将来の状態への寄与を作成します。 DP は、各部分セグメンテーションが個別にカウントされることを保証します。
