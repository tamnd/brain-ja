 ## 解決策
 ## 問題の理解

 最初にコーヒーをいくつかの同一の小さな容器に詰める状況が与えられます。 それぞれの小さな容器は常に正確に保持されます$K$コーヒーの単位、$N$このようなコンテナ。 したがって、コーヒーの総量は単純に次のようになります。$N \times K$。 

このコーヒーは、それぞれの大きな容器に最大でも入れることができる、より大きな容器に再詰めする必要があります。$L$単位。 目標は、最適に梱包する場合に必要な大きなコンテナの数を決定することです。つまり、次のコンテナを使用する前に、各大きなコンテナを可能な限り満たします。 

したがって、タスクは容量を計算することになります。$L$合計を保管するにはビンが必要です$N \cdot K$単位。 

制約は小さいです。$N, K, L \leq 1000$。 これにより、コーヒーの総量が最大で次であることがすぐにわかります。$10^6$そのため、単位や単純な演算に関するシミュレーションでも十分に高速になります。 入力サイズまたはコーヒーの総量の線形時間までは許容されますが、明らかに目標とすることができます。$O(1)$算術解。 

合計金額が正確に割り切れる場合、微妙なエッジケースが発生します。$L$。 たとえば、次の場合$N=2, K=3, L=6$、合計は$6$、バケットが 1 つだけ必要です。 単純な整数除算のアプローチでは、切り上げによって割り切れる場合と割り切れない場合の両方を正しく処理できるようにする必要があります。 

もう 1 つの例外的なケースは次のような場合です。$L = K$。 すると、それぞれの大きなバケツには、1 つの小さなバケツが保持するものとまったく同じものが保持され、答えは正確に次のようになります。$N$。 実装が誤って合計の集計を考慮せずに整数の除算を実行すると、構造が誤って崩壊する可能性がありますが、ここでも正しい推論は純粋に合計に基づいています。 

## アプローチ

 これを考える簡単な方法は、一度に 1 つのユニットを大きなバケツに入れるプロセスをシミュレートすることです。 私たちはコーヒーを全額受け取ります$N \cdot K$、減算を繰り返します$L$、その回数を数えます。 これは正しいです。各減算は 1 つの大きなバケツを満たすことを表すためです。 

ただし、このアプローチは最悪の場合には非効率になります。 もし$N \cdot K$大きくて、$L = 1$までパフォーマンスします。$10^6$繰り返し。 まだ許容範囲内ですが、問題の構造を考えると不要です。 

重要な観察は、本質的に固定量をサイズのグループに分割しているということです。$L$。 これはまさに切り上げを伴う整数の除算です。 シミュレーションする代わりに、次の上限を直接計算します。$\frac{N \cdot K}{L}$。 これにより、完全なバケットと部分的に満たされた最終バケットの両方が 1 つの式でキャプチャされます。 

シミュレーションから算術への移行は、プロセス中に何も変化せず、合計だけが重要であることを認識することから始まります。 すべてのコーヒーを 1 つの値に集約すると、最初にどのように梱包されたかという内部構造は無関係になります。

 | 最適な算術 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値を読み取る$N$、$K$、 そして$L$。 これらは、小さなコンテナの数、その容量、および大きなコンテナの容量を定義します。 
2. コーヒーの総量を次のように計算します。$T = N \cdot K$。 再梱包には総質量のみが重要となるため、このステップでは初期構成全体が 1 つの数量にまとめられます。 
3. いっぱいになった大きなコンテナが何個入るかを計算します。$T$、つまり$T // L$。 
4. 残りがあるかどうかを確認します$T \bmod L$。 コーヒーが残った場合、それを保管するためにさらに大きな容器が 1 つ必要になります。 
5. 出力$T // L + (1 \text{ if } T \bmod L \neq 0 \text{ else } 0)$。 

### なぜ効果があるのか

 大きな容器を充填するプロセスは、総量のみに依存します。 各コンテナは独立して次のものを保持できます。$L$したがって、最適な梱包戦略であれば、可能な限りコンテナを完全に満たすことができます。 サイズの完全なグループをできるだけ多く抽出した後$L$可能な限り、残りの正の量は正確に 1 つの追加コンテナを占有する必要があります。 これにより、数式で必要なコンテナーの最小数が計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, K, L = map(int, input().split())

total = N * K

ans = total // L
if total % L != 0:
    ans += 1

print(ans)
```このソリューションでは、まず入力を 1 つの合計値に圧縮します。 これにより、梱包プロセスのシミュレーションを回避できます。 整数除算は完全に満たされた大きなバケットの数を示し、条件付き増分は残りのケースを処理し、正しい上限動作を保証します。 

よくある間違いは、剰余の大文字と小文字を忘れて、単に印刷することです。`total // L`。 合計が正確な倍数にならない場合は常に過小評価されます。$L$。 

## 実用的な例

 ### 例 1

 入力:```
2 3 6
```ここ$T = 2 \times 3 = 6$。 

| ステップ | 合計 T | T // L | T%L | 答え |
 | --- | --- | --- | --- | --- |
 | 合計を計算する | 6 | - | - | - |
 | L で割る | 6 | 1 | 0 | 1 |

 合計は 1 つの大きなバケツにちょうど収まるので、残りは表示されません。 これにより、正確な割り算によって余分なバケットが生成されないことが確認されます。 

### 例 2

 入力:```
5 3 4
```ここ$T = 5 \times 3 = 15$。 

| ステップ | 合計 T | T // L | T%L | 答え |
 | --- | --- | --- | --- | --- |
 | 合計を計算する | 15 | - | - | - |
 | L で割る | 15 | 3 | 3 | 4 |

 サイズ 4 の 3 つの完全なバケットは 12 ユニットを占め、残り 3 ユニットには 4 番目のバケットが必要です。 これは、残りがある場合に天井効果がどのように現れるかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    N, K, L = map(int, input().split())
    total = N * K
    ans = total // L
    if total % L != 0:
        ans += 1
    return str(ans)

# provided samples
assert run("2 3 6\n") == "1", "sample 1"
assert run("5 3 4\n") == "4", "sample 2"
assert run("1000 500 1000\n") == "500", "sample 3"

# custom cases
assert run("1 1 1\n") == "1", "minimum case"
assert run("1 1000 1000\n") == "1", "exact fit large bucket"
assert run("3 2 10\n") == "1", "fits into single bucket"
assert run("10 1 3\n") == "4", "remainder case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 1 | 1 | 最小境界の場合 |
 | 1 1000 1000 | 1 | 最大容量での正確な除算 |
 | 3 2 10 | 1 | 複数の小さなバケツが 1 つの大きなバケツに収まります。 
| 10 1 3 | 4 | 残りの天井動作 |

 ## 特殊なケース

 いつ$N = 1, K = 1, L = 1$、合計はちょうど 1 であり、アルゴリズムは次のように計算します。$1 // 1 = 1$、残りはありません。 答えは正しく 1 になり、基本ケースが正しく動作することがわかります。 

合計が以下の場合$L$、 例えば$N=3, K=2, L=10$、合計は 6 です。除算により、完全なバケットが 0 になり、残りが 6 になり、追加のバケットがトリガーされます。 アルゴリズムは 1 を出力します。これは、少量であっても 1 つのコンテナーが必要であるという要件に一致します。 

次のように合計が正確に割り切れる場合$N=1000, K=500, L=1000$、合計は 500000 です。この除算により、完全なバケットが 500 個になり、余りがゼロになるため、追加のバケットは追加されません。 これは、アルゴリズムがきれいな除算の場合にオーバーカウントしないことを確認します。
