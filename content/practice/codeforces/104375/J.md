 ## 解決策
 ## 問題の理解

 それぞれの値が物質の「ジャンプ エネルギー」を表す整数の配列が与えられます。 エネルギーを持った二つの物質が結合すると、$a$そして$b$混合すると、それらは次のエネルギーに寄与します。$ab$。 2 つ以上の物質が混合される場合、総エネルギーは、選択された元素間のすべてのペア積の合計として定義されます。 

したがって、どのクエリ範囲に対しても$[L, R]$、部分配列を取ります$A_L, A_{L+1}, \dots, A_R$そして計算します:$$\sum_{L \le i < j \le R} A_i A_j$$各クエリはこの値のモジュロを要求します$10^9 + 7$、最大で$10^6$最大サイズの配列に対するクエリ$10^6$。 

直接読むと、多くの部分配列にわたって関数を繰り返し計算する必要があり、その関数は部分配列内のすべてのペアごとの相互作用に依存していることがわかります。 

重要な制約の意味は、両方とも$N$そして$Q$十分な大きさがあるため、どのソリューションでも$O(R-L)$クエリごとの速度が遅すぎます。 クエリごとの 2 次アプローチは完全に不可能です。単一の最悪のクエリがすでに存在するためです。$O(10^{12})$操作。 

もう少し素朴なアプローチではまだ不十分です。$O(N)$クエリごとにつながる$10^{12}$トータルオペレーション。 

唯一許容できるターゲットはおおよそ次のとおりです$O((N+Q)\log N)$または$O(N+Q)$。 

単純な定式化では微妙な問題が発生します。ペアの合計をクエリごとに個別に再計算すると、式を再構築しない限り再利用できない繰り返し作業が発生します。 

## アプローチ

 ブルートフォース手法は定義に直接従います。 クエリごとに$[L, R]$、すべてのペアを反復処理します$i < j$そして蓄積する$A_i A_j$。 これは、ペアごとの積の合計としてのエネルギーの定義と正確に一致するため、正しいです。 ただし、長さの範囲については、$k$、これには必要です$k(k-1)/2$掛け算。 最悪の場合$k = N = 10^6$したがって、単一のクエリはすでに実行不可能になります。 

1 つのエンドポイントを修正し、もう 1 つのエンドポイントを合計することで改善しようとしても、各クエリの範囲サイズは線形のままであり、依然として最悪の場合の 2 次の合計複雑さにつながります。 

重要な観察は、ペアごとの和が標準的な代数的恒等性を持っているということです。 次のように定義すると、$$S = \sum A_i, \quad S_2 = \sum A_i^2$$それから：$$\left(\sum A_i\right)^2 = \sum A_i^2 + 2\sum_{i<j} A_iA_j$$並べ替えると次のようになります。$$\sum_{i<j} A_iA_j = \frac{S^2 - S_2}{2}$$これにより、問題は「すべてのペアの合計」から、要素の合計と二乗の合計という 2 つの接頭辞の合計を計算する問題に変換されます。 これらが利用可能になると、各クエリは O(1) になります。 

プレフィックスの合計を事前計算します。$$P[i] = \sum_{k=1}^{i} A_k,\quad Q[i] = \sum_{k=1}^{i} A_k^2$$それからクエリについては$[L, R]$:$$S = P[R] - P[L-1], \quad S_2 = Q[R] - Q[L-1]$$そして答えは次のとおりです。$$(S^2 - S_2) \cdot inv2 \bmod (10^9+7)$$2 による除算には 2 の逆剰余が必要です。

 ## アルゴリズムのチュートリアル

 1. 配列に対してプレフィックスの値の合計とプレフィックスの二乗和を事前計算します。 

これにより、セグメントの合計または二乗和を一定時間で計算できます。 
2. 各インデックスについて$i$、 店：$P[i] = P[i-1] + A[i]$そして$Q[i] = Q[i-1] + A[i]^2$。 

事前に値を二乗する理由は、最終的な式が線形集計と二次集計の両方に依存するためです。 
3. 以下の 2 の逆モジュラーを事前計算します。$10^9+7$。 

これが必要なのは、ペアのカウントでは 2 による除算が導入され、これをモジュラー算術で処理する必要があるためです。 
4. 各クエリについて$[L, R]$、次を計算します。$S = P[R] - P[L-1]$そして$S_2 = Q[R] - Q[L-1]$、正規化されたモジュロ。 

これらは、選択したセグメントの合計と二乗和を表します。 
5. 以下を使用して、セグメントをペア和に変換します。$(S^2 - S_2) / 2$。 

このステップは、和の二乗を拡張する代数恒等式に依存します。 
6. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 正しさは、和の二乗をマルチセットにわたって拡張することで得られます。 すべての製品$A_iA_j$と$i \ne j$に正確に 2 回出現します$S^2$、一度として$A_iA_j$そして一度$A_jA_i$。 引き算$\sum A_i^2$対角項を削除し、必要なペアごとの合計のちょうど 2 倍を残します。 2 で割ると過剰カウントが修正され、順序付けされていない各ペアが正確に 1 回だけ寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV2 = (MOD + 1) // 2

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(1, n + 1):
        x = a[i - 1] % MOD
        pref[i] = (pref[i - 1] + x) % MOD
        pref2[i] = (pref2[i - 1] + x * x) % MOD

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        s = (pref[r] - pref[l - 1]) % MOD
        s2 = (pref2[r] - pref2[l - 1]) % MOD

        ans = (s * s - s2) % MOD
        ans = (ans * INV2) % MOD
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```プレフィックス配列`pref`そして`pref2`累積和と累積二乗和をそれぞれ格納し、両方とも剰余を取得します$10^9+7$。 各クエリは、これらの事前計算された値の定数時間演算に帰着します。 

掛け算`s * s`すべての演算は既にモジュロ MOD に変換されているため、モジュロ算術では安全です。 減算も負の値を避けるために正規化されます。 MOD は素数であるため、2 の逆数は 1 回事前計算されます。

## 特殊なケース

 重要なエッジケースは、範囲に要素が 1 つしかない場合です。 次のような入力の場合:```
1 1
7
1 1
```ペアがないため、正解は 0 です。 アルゴリズムはこれを処理します。$S^2 = S_2$, したがって、除算の前に減算するとゼロが得られます。 

もう 1 つのケースは、大規模な均一配列であり、単純な実装では、乗算の繰り返しによりオーバーフローや速度低下の危険性があります。 たとえば、すべての値は次のようになります。$10^6$中間合計が大きくなりますが、モジュラー演算により値の制限が維持され、プレフィックスの計算は安定したままになります。 

最後の微妙なケースは、剰余算術において減算によって負の中間結果が生成される場合です。 実装では、すべての減算の後にモジュロを取得することでこの問題を修正し、次のような場合でも正確性を保証します。$P[L-1]$または$Q[L-1]$にある対応するプレフィックスよりも大きいです$R$。
