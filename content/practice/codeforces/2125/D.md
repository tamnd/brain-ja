 ## 解決策
 ## 問題の理解

 私たちは次のようなラインで取り組んでいます$m$細胞。 各セルは、最終的に、選択した 1 つの間隔だけでカバーされる必要があります。 

がある$n$候補セグメント。 各セグメント$i$連続した範囲をカバーする$[l_i, r_i]$、しかし、それが存在するという保証はありません。 代わりに、確率的に独立して表示されます$p_i / q_i$。 すべてのランダム性が解決された後、実際に存在するセグメントのセットを調べます。 これらのアクティブなセグメントがラインの完全なパーティション (1 から 1 までのすべてのセル) を形成する確率が必要です。$m$は、重複やギャップがなく、正確に 1 つのアクティブなセグメントによってカバーされます。 

出力はこの確率モジュロです$998244353$、モジュラー分数として表されます。 

制約は次のとおりです$2 \cdot 10^5$セグメントと$2 \cdot 10^5$細胞。 これにより、セグメントのすべてのサブセットを列挙することは即座に除外されます。$2^n$天文学的に大きいです。 セグメントにわたる 2 次 DP であっても、最悪の場合は遅すぎるため、どのソリューションでも、ソートされたエンドポイントにわたる線形または線形に近い時間に似た方法で間隔を処理する必要があります。 

複数のセグメントが同じ領域に重なる場合、微妙な問題が発生します。 素朴な解釈では、各セルを独立して扱うことを示唆するかもしれませんが、セグメントは範囲にまたがるため、独立性はすぐに壊れます。 もう 1 つのよくある落とし穴は、存在しないセグメントを補正せずにタイリングを形成するセグメントの確率を乗算することです。正しい計算には、存在確率と干渉セグメントの除外の両方が含まれている必要があります。 

A small edge case clarifies the difficulty. 仮定する$m=2$、セグメントあり$[1,2]$そして$[1,1],[2,2]$。 単純なアプローチでは、「大きなセグメントを取得するか、両方の小さなセグメントを取得するか」と考えるかもしれませんが、正確性の条件では、重複のない正確なカバレッジが必要です。 3 つすべてが表示される場合は、すべてのセルがカバーされているにもかかわらず、構成は無効です。 これは、単なる報道ではなく、報道の独自性を確保する必要があることを示しています。 

## アプローチ

 ブルートフォースのアイデアは簡単です。セグメントのすべてのサブセットを列挙し、その発生確率を計算し、それが有効なタイリングを形成しているかどうかを確認します。$[1,m]$。 各サブセットについて、セルにマークを付けるか間隔を並べ替えて、それらが互いに素なチェーンを形成していることを確認することでカバレッジを検証します。 これにはすでに費用がかかります$O(n \cdot m)$または$O(n \log n)$検証に応じてサブセットごとに、$2^n$サブセットであるため、合計は指数関数的となり使用できなくなります。 

重要な構造は、有効な構成がラインのチェーン分解のように動作する必要があるということです。 どのセグメントが選択されるかを固定すると、「各セルが 1 回だけカバーされる」という条件により、選択されたセグメントが完全に一致する連続した重複しないブロックにパーティションを形成するように強制されます。$[1,m]$。 つまり、有効な設定は、プレフィックス間隔を正確にタイル化するセグメントのシーケンスを選択することに対応します。 

次に、視点を反転して考えてみましょう。 サブセットを直接推論する代わりに、確率を 2 つの部分、つまりセグメントの独立した存在と、それらの既存のセグメントから有効なタイルを選択する組み合わせ構造に分けます。 これは、セグメントの正しいエンドポイント上の DP を示唆しています。 

各セグメントについて、位置で終了するタイルの潜在的な最後の部分として扱います。$r$。 セグメントの場合$[l,r]$が最後の部分として選択され、その後はそれ以前のすべてが選択されます$l$すでに有効なタイリングを形成している必要があります$[1,l-1]$。 これにより、からの遷移が得られます。$l-1$に$r$。 

セグメントが存在する確率の寄与は次のとおりです。$p_i/q_i$、欠席が寄与する一方で$(q_i-p_i)/q_i$。 標準的なトリックは、すべての分母をグローバルに因数分解することです。 最終的な答えにすべての積を掛けます。$q_i^{-1}$後で調整することで、各セグメントが次のいずれかに寄与する加重システムで効果的に機能します。$p_i$または$(q_i-p_i)$選択したタイル構造で使用されるか除外されるかによって決まります。 

主な削減は重み付けされた間隔 DP になります。各セグメントが構造エッジとして選択されているかどうかに応じて乗算重みを与え、遷移がセグメントの端点でのみ発生するプレフィックスをタイル化する方法を計算します。 

ポジション全体にわたって DP 配列を維持します。$dp[i]$プレフィックスの正しいタイリングを形成する重み付き確率質量の合計を表します$[1,i]$。 で終わる各セグメントについて$r$からのトランジションを追加します。$l-1$に$r$そのセグメントの確率の重みを乗算します。 独立性を明確に説明するために、各セグメントが寄与するように乗算係数を事前計算します。$p_i \cdot inv(q_i)$使用される場合、使用されない場合は正規化によって暗黙的に処理されます。 

これにより、問題はエンドポイントにわたる古典的な区間 DP に変換され、ソートされたセグメントにわたって線形時間で解くことができます。

 ## アルゴリズムのチュートリアル

 1. 各セグメントについて、次を使用してその確率をモジュラー形式に変換します。$prob_i = p_i \cdot q_i^{-1}$。 これにより、分数の代わりにモジュラー演算を行うことができます。 
2. 適切なエンドポイントごとに隣接構造を構築します。$r$で終わるすべてのセグメントを保存します。$r$ペアとして$(l, prob_i)$。 DP 遷移はセグメントのエンドポイントに依存するため、これが必要になります。 
3. DP 配列を初期化します。$dp[i]$プレフィックスの有効で正確なタイリングを形成する合計確率を格納します$[1,i]$。 セット$dp[0] = 1$空のプレフィックスは自明に有効であるためです。 
4. 位置を 1 から 1 までスイープします。$m$。 それぞれのポジションで$i$、計算する$dp[i]$で終わるすべてのセグメントからの寄与を合計することにより、$i$。 各セグメント$(l,i)$貢献する$dp[l-1] \cdot prob_i$。 これは、有効なタイリングを拡張することを表します。$[1,l-1]$セグメントカバー付き$[l,i]$。 
5. 最終的な答えは次のとおりです。$dp[m]$有効なフルカバー タイルをすべて正確にカウントするためです。 

### なぜ効果があるのか

 すべてのセルを 1 回だけカバーするセグメントの有効な構成では、ラインが連続するブロックに一意に分割されます。 各ブロックは、選択された 1 つのセグメントに正確に対応します。 DP は、すべてのプレフィックスの最後のブロックを選択することによって、これらのパーティションを列挙します。 セグメントは独立しており、セグメントの存在確率を直接乗算するため、各有効なタイリングは正しい確率の重みで 1 回だけ寄与します。 遷移は正確なプレフィックス境界からのみ拡張され、厳密なパーティション構造が強制されるため、無効なオーバーラップは決して発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    ends = [[] for _ in range(m + 1)]

    for _ in range(n):
        l, r, p, q = map(int, input().split())
        prob = p * modinv(q) % MOD
        ends[r].append((l, prob))

    dp = [0] * (m + 1)
    dp[0] = 1

    for i in range(1, m + 1):
        total = 0
        for l, prob in ends[i]:
            total = (total + dp[l - 1] * prob) % MOD
        dp[i] = total

    print(dp[m])

if __name__ == "__main__":
    solve()
```この実装は、各 DP 状態が関連する遷移のみを処理するように、セグメントを適切なエンドポイントごとにグループ化することに依存しています。 これにより、$O(nm)$すべての位置のすべてのセグメントをスキャンします。 

逆モジュラーは、各確率をフィールド要素に変換するために使用されます。 確率は選択されたセグメント間で独立して乗算されるため、この表現はモジュラー演算の下で正確さを維持します。 

微妙な実装の詳細が初期化されています$dp[0]=1$。 これがないと、有効なタイリングはすべて位置 1 から開始する必要があるため、最初のセグメントは決して正しく寄与しません。 

## 実用的な例

 ### 例 1

 入力:```
3 3
1 2 1 3
3 3 1 2
1 3 2 3
```確率を計算します。 

- [1,2]: 1/3
 - [3,3]: 1/2
 - [1,3]: 2/3

 DP を追跡します:

 | 私 | i で終わるセグメント | dp[i] の計算 | dp[i] |
 | --- | --- | --- | --- |
 | 0 | - | ベース | 1 |
 | 1 | - | セグメントが終了していません | 0 |
 | 2 | [1,2] | dp[0] * 1/3 | 1/3 |
 | 3 | [3,3]、[1,3] | dp[2]*1/2 + dp[0]*2/3 | 5/18 |

 したがって、最終的な答えは、$5/18$、サンプルと一致します。 

これにより、DP が、セグメント全体の使用、または 2 つの部分への分割の両方の可能なタイリングを正しく列挙していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、複数のセグメントが同じ領域で重なり合い、互換性のないタイル間で競合が発生する場合です。 たとえば、すべてがカバーするセグメントを考えてみましょう。$[1,m]$。 有効な構成ではそのようなセグメントは 1 つだけ使用でき、DP はこれを自然に処理します。これは、各セグメントが独立して遷移に寄与し、遷移の合計が相互に排他的な選択肢を表すためです。 

もう 1 つのケースは、特定のセグメントを選択しないとカバー範囲にギャップが生じる場合です。 カバーするセグメントが 1 つだけあると仮定します。$[1,3]$中間パーティションには何も必要ありません。 DP は、そのセグメントを通過する唯一の有効な遷移を強制し、その確率が低い場合は、それに応じて最終結果を直接スケーリングします。 

3 番目のケースには、開始点が異なり、同じ位置で終了する多くのセグメントが含まれます。 DP は、考えられるすべての最終ステップの選択を同じ状態に正しく蓄積し、各タイリングが各プレフィックスの 1 つの最終セグメントに正確に対応するため、構成が二重にカウントされることがなくなります。
