 ## 解決策
 ## 問題の理解

 大文字で構成されるいくつかの文字列が与えられます。 各文字はコンテストの問題を表します。 文字列に次のいずれかが含まれる場合、コンテストは難しいと見なされます。`"FFT"`または`"NTT"`連続した部分文字列として。 

文字列の文字を任意の順序で並べ替えることができます。 タスクは、禁止パターンを含まない元の文字の順列を出力することです。 

すべての文字列の合計の長さは最大でも$2 \cdot 10^5$。 これが重要な実際の制約です。 各文字を一定の回数だけ処理するソリューションは、簡単に十分に高速です。 二次動作のアルゴリズムは不要であり、入力が最大サイズに達すると危険になります。 

興味深いのは効率ではなく構築です。 再配置された文字列が両方を回避することを保証する必要があります。`"FFT"`そして`"NTT"`。 

いくつかの特殊なケースは注目に値します。 

次の文字列を考えてみましょう。```
FFT
```元の文字列は難しいです。 そのまま出力するのは誤りです。 有効な答えは次のとおりです。```
FTF
```元の文字列が難しいかどうかだけをチェックするソリューションは、ここでは失敗します。 

考慮する：```
NTT
```繰り返しになりますが、オリジナルアレンジは禁止です。 有効な再配置は次のとおりです。```
TNT
```文字はまったく同じである必要があり、順序のみが変更できます。 

多くの出現を含む文字列を考えてみましょう。```
FFTFFTFFTNNTNNT
```最初の禁止された部分文字列だけを削除するだけでは十分ではありません。他の場所に別の文字列が残る可能性があるためです。 建設ではすべての発生を同時に防止する必要があります。 

最後に、何も含まない文字列を考えます。`F`または`N`:```
ABCDE
```このような文字列には決して次の内容を含めることはできません`"FFT"`または`"NTT"`, したがって、どのような順列も有効です。 アルゴリズムは、特別なロジックを使用せずにこのケースを自然に処理する必要があります。 

## アプローチ

 強引なアイデアは、次のものが含まれなくなるまで順列を生成することです。`"FFT"`または`"NTT"`。 この問題は有効な再配置のみを要求するため、これは概念的には機能します。 

残念ながら、長さ 15 の文字列でもすでに$15!$順列、つまりおよそ$1.3 \times 10^{12}$。 順列を徹底的に検索することは完全に不可能です。 

重要な観察は、両方の禁止パターンが同じ構造を持っているということです。 それらは次のように終わります。`"TT"`そしてどちらかから始めてください`'F'`または`'N'`。 

すべて配置するとします`'T'`すべての前の文字`'F'`そしてすべての`'N'`。 それならいいえ`'F'`または`'N'`すぐに 2 つを続けることもできます`'T'`キャラクター、すべてなので、`'T'`文字は文字列の前の方にすでに配置されています。 

さらに単純な構造は、文字列をアルファベット順にソートすることです。 アルファベット順:```
... F ... N ... T ...
```全て`'T'`文字は毎回登場します`'F'`そしてすべての`'N'`。 

のために`"FFT"`発生する、`'F'`その後に 2 つが続く必要があります`'T'`文字。 それは不可能です。`'T'`キャラクター、いいえ`'F'`後から登場する。 

同じ議論は排除します`"NTT"`。 

ソートにより複数の文字セットが保持され、両方の禁止パターンが自動的に回避されるため、問題は簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 (ソート文字列) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります。 
2. すべての文字をアルファベットの降順で並べ替えます。 
3. 結果の文字列を出力します。 

重要な観察は、並べ替えた後、すべての`'F'`毎回の前に表示されます`'N'`、そしてすべての`'N'`毎回の前に表示されます`'T'`。 

ずっと`'T'`ソートされた文字列の接尾辞を形成する文字、いいえ`'F'`または`'N'`直前に現れることもある`"TT"`。 

### なぜ効果があるのか

 ソート後、次のすべての出現が`'T'`すべての発生の後に配置されます`'F'`そして`'N'`。 

次のように仮定します。`"FFT"`ソートされた文字列に表示されます。 決勝戦`'T'`この部分文字列には、`'F'`その前に。 ずっと`'F'`文字はブロック全体の前に出現します`'T'`文字の場合、パターンは非文字間の境界を越える必要があります。`'T'`手紙と`'T'`手紙。 その場合、中央の文字も次のようにする必要があります。`'T'`、これは不可能です。`'T'`ソートされた順序で表示され、それ以降の文字もすべて表示されます`'T'`。 アン`'F'`二人の前に立つことができない`'T'`文字。 

同じ理由が次の場合にも当てはまります`"NTT"`。 

したがって、禁止された部分文字列は発生しないため、生成された配置は常に有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    s = input().strip()
    print(''.join(sorted(s)))
```ソリューションは構築に直接続きます。 

テストケースごとに、`sorted(s)`文字をアルファベット順に返します。 それらを結合して文字列に戻すと、まったく同じ文字が保持され、順序のみが変更されます。 

部分文字列のチェックは必要ありません。 正確さは、後で結果を検証することではなく、並べ替えられた順序の構造的特性から得られます。 

全体の課題は構造を発見することであるため、実装は短くなります。 この観察が行われれば、コーディング部分は簡単になります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()
        t_count = s.count('T')
        rest = ''.join(c for c in s if c != 'T')
        ans.append('T' * t_count + rest)

    sys.stdout.write('\n'.join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample

AFFTBFFNTTFTTZ
"""
) == (
"""TFF

TTTTTAFFBFFNFZ
"""
)

# minimum size

"""1
A
"""
) == "A\n"

# all T
assert run(
"""1
TTTT
"""
) == "TTTT\n"

# only forbidden letters
assert run(
"""1
NTT
"""
) == "TTN\n"

# large repeated pattern
assert run(
"""1
FFTFFT
"""
) == "TTFFFF\n"
