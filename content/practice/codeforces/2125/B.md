 ## 解決策
 ## 問題の理解

 ロボットを座標に配置することから始めます$(a,b)$無限グリッド上にあり、それを原点に戻したい$(0,0)$。 各動きはペアを選択することによって定義されます$(dx,dy)$両方のコンポーネントが間にある場合$0$そして$k$、そしてそのベクトルを現在の位置から減算します。 つまり、あらゆる動作がロボットを左に移動させます。$dx$そして下に$dy$。 同じペア$(dx,dy)$再利用可能ですが、初回のみ1コスト、2回目以降は無料となります。 

実際の決定は、動きの数を最小限に抑えることではなく、使用する個別の動きベクトルの数を最小限に抑えることです。 ベクターを導入すると、追加コストなしで何度でも再利用できます。 

制約は次のとおりです$10^{18}$両方の座標と$k$したがって、可能なベクトルを反復したり、パスを段階的に構築したりすることに依存する解決策は不可能です。 解決策全体では、問題をベクトルの可分性または構造特性に関する推論に帰着させる必要があります。 

重要な点は、ロボットが異なるベクトルを混合できることです。 素朴な直感は、次のような単一のベクトルが必要であることを示唆するかもしれません。$(a,b)$正確にはそうですが、それは必須ではありません。 必要なのは、合計が以下に等しい許可されたベクトルのマルチセットだけです。$(a,b)$。 

よくある失敗例は、貪欲なアプローチが次のようなものを繰り返し減算しようとしたときに発生します。$(k,k)$または$(k,0)$。 たとえば、次の場合$(a,b)=(3,5)$そして$k=2$、最大の動きを貪欲に使用すると、単一の動きはターゲットに直接到達できないため失敗し、方向を誤って混合すると、不必要な個別のベクトルが発生する可能性があります。 

もう一つの微妙なエッジケースは次のような場合です。$a$そして$b$は十分に独立しているため、複数の移動「方向」が必要ですが、それでも十分小さいため、慎重に選択された 2 つのベクトルが両方の座標に正確にまたがることができます。 

## アプローチ

 コスト構造により、繰り返し使用することでベクトルを表現できる個別のベクトルの数を最小限に抑えることが問題になります。$(a,b)$合計として、各ベクトルは次のように制約されます。$0 \le dx,dy \le k$。 

ブルートフォースビューは、許可されたベクトルのすべての可能なサブセットを考慮し、各サブセットについて、$(a,b)$は、これらのベクトルの非負の整数の組み合わせとして表現できます。 これはすぐに失敗します。$(k+1)^2$考えられるベクトルは次のとおりです$10^{36}$、列挙さえ不可能になります。 

重要な洞察は、実際にはベクトルを使用する回数は気にせず、それが出現するかどうかだけを気にするということです。 そこで問題は、内部のベクトルの最小数はいくらかということです。$k \times k$非負の線形結合が生成できるグリッド$(a,b)$?

 すべてのベクトルが第 1 象限にあるため、すべての組み合わせで単調性が維持され、小さな生成セットを使用して 2D 円錐内の点を効率的にカバーできます。 2 次元では、座標の 1 つが縮退構造を強制しない限り、適切に選択されていれば、常に最大 2 つのベクトルを使用して任意のターゲットを表現できます。 

したがって、答えは、1 つのベクトルで十分かどうかを確認し、そうでない場合は 2 つで十分かどうかを判断し、そうでない場合は 3 つ必要かということになります。 

両方の座標が範囲内にある同じステップで割り切れる場合にのみ、単一のベクトルで十分です。$(a,b)$それ自体は、何らかのものによって生成された光線上に存在する必要があります。$(dx,dy)\le k$、これはまさに次の場合に可能です$\max(a,b)\le k$または、ペアを有効な有界整数ベクトルにスケールダウンできる場合。 

1 つのベクトルでは不十分な場合は、2 つのベクトルを見つけることができるかどうかを尋ねます。$(x_1,y_1)$そして$(x_2,y_2)$次のような:$$a = \alpha x_1 + \beta x_2,\quad b = \alpha y_1 + \beta y_2$$いくつかの非負の整数の場合$\alpha,\beta$。 境界のある座標を持つ 2D では、両方の座標が複数の「単位方向」を必要とする場合を除き、これは常に可能です。これは両方の座標が必要な場合にのみ発生します。$a > k$そして$b > k$、共有スロープを介して位置合わせすることはできません。 

構造を単純化することで、明確な分類が可能になります。 

もし$\gcd(a,b)$範囲内の方向を許可します。答えは 1 です。 それ以外の場合、両方の座標が次の値を超えない限り、答えは 2 です。$k$これは、3 つの独立した方向を強制する方法ですが、この構造では決して起こらないため、答えは常に最大 2 になります。 

したがって、最終的なロジックは、次のことを確認することになります。$(a,b)$それ自体は 1 回の移動で実行可能ですが、それ以外の場合は常に 2 回の移動で十分です。

 ## アルゴリズムのチュートリアル

 この問題を、必要な個別のステップ ベクトルの数を決定することに変換します。 

1. 1 つのベクトルで実行できるかどうかを確認します。 これには、次のものが存在する必要があります。$(dx,dy)$繰り返し適用すると正確に届くようになります$(a,b)$。 つまり、$(dx,dy)$両方の座標を除算する必要があります。$a = t \cdot dx$、$b = t \cdot dy$、そして両方$dx,dy \le k$。 最有力候補は$(a,b)$両方が範囲内にある場合、それ自体。 
2. もし$\max(a,b) \le k$、その後、単一の操作を選択できます$(a,b)$そして一手で終わらせます。 
3. それ以外の場合は、スケールダウンすることで 1 つのベクトルが引き続き動作できるかどうかを確認します。 もし$\gcd(a,b) = g$の場合、プリミティブ方向は次のようになります。$(a/g, b/g)$。 このプリミティブ ベクトルの両方の成分が$\le k$、繰り返し使用できます。 
4. プリミティブ方向が超過した場合$k$の場合、単一のベクトルは両方の座標を正確に生成できません。有効なジェネレーターは同じ光線上に存在する必要がありますが、次の値を超えてはなりません。$k$。 
5. その場合、2 つのベクトルを使用します。 一方は水平方向の進行ともう一方の垂直方向の進行を独立して処理でき、両方の軸が単調で独立して有界であるため、常に 2 つの方向で十分です。 

### なぜ効果があるのか

 すべての動きは加算的であり、第 1 象限に制限されているため、すべての解決策は分解に対応します。$(a,b)$ベクトルの和に変換$[0,k]^2$。 有効な分解はすべて、2D で最大 2 つの独立した方向の最小生成セットに折りたたまれます。 単一の方向が境界内に収まる場合、ターゲットを正確にカバーするランク 1 の円錐が生成されます。 そうでない場合、ターゲットには必ず少なくとも 2 つの独立した方向が必要であり、2D では、到達可能な格子内の任意の点にまたがるには 2 つの方向で十分です。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, k = map(int, input().split())
        
        # If we can directly jump to (0,0) in one move
        if max(a, b) <= k:
            out.append("1")
            continue
        
        # Check if a single direction can generate both
        g = math.gcd(a, b)
        x = a // g
        y = b // g
        
        if x <= k and y <= k:
            out.append("1")
        else:
            out.append("2")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードはまず、ターゲット ポイント自体が有効な移動であるという自明なケースを処理します。これは、すぐにコスト 1 が与えられるためです。次に、ベクトルを削減します。$(a,b)$gcd を使用してそのプリミティブ方向に戻ります。 その方向が許可されたボックス内に収まる場合、それを繰り返し使用すると、他のベクトルを必要とせずにターゲットが構築されます。 それ以外の場合は、少なくとも 2 つの異なるベクトルが必要であると結論付けられるため、答えは 2 になります。 

微妙な点は、プリミティブ方向のみをチェックするだけで十分であるということです。 そのスケーリングされたバージョンが範囲内に収まる場合、プリミティブも適合する必要があるため、この条件は必要かつ十分です。

宛先自体が有効なベクトルであるため、アルゴリズムは早期に終了します。つまり、分解は必要ありません。

 ## 特殊なケース

 1 つのエッジ ケースは、1 つの座標がそれよりもはるかに大きい場合に発生します。$k$、しかし、もう一つは小さいです。 例えば、$(a,b,k) = (100,1,50)$。 直接チェックは失敗します。$100 > 50$。 gcd は$1$したがって、基本的な方向は次のようになります。$(100,1)$、これも超えます$k$。 このような不均衡な傾きを再現できる単一の制限された方向はないため、アルゴリズムは正しく 2 を出力します。 

もう 1 つのケースは、両方の座標が等しく、十分に小さい場合です。次のような場合です。$(5,5,10)$。 ここで、直接条件はすぐに成功し、答えは 1 です。プリミティブ方向が次のとおりであるため、gcd パスでもそれが確認されます。$(1,1)$、これは境界内にあり、斜めの動きを繰り返すだけで十分であることを裏付けています。 

最後の微妙なケースは次のような場合です。$(a,b)$大きな gcd を共有しますが、縮小された方向は依然として限界に違反します。$(30,45,10)$。 プリミティブは$(2,3)$、制限内に収まるため、必要なベクトルは 1 つだけです。 これは、生の座標ではなく、スケールダウンが実現可能性を検出する正しい方法であることを示しています。
