 ## 解決策
 ## 問題の理解

 それぞれが複数の整数間隔で構成される、いくつかの独立したゲームが与えられています。 各間隔は、現在「生きている」整数のセットを表し、以下のすべての整数として始まります。$l_i$に$r_i$。 固定倍率もあります$p > 1$。 2 人のプレーヤーが交互に動き、各動きでプレーヤーは間隔の 1 つを選択し、特定の方法でそれを縮小します。 

インターバルでの移動は次のように機能します。 現在の間隔に、現在の最小値と最大値の間のすべての整数が含まれているとします。 プレイヤーは値を選択する必要があります$x$間隔内から、次のように乗算します。$p$の場合、結果は少なくともその間隔の現在の最大値になります。 一度$x$が選択されており、それ以上のものはすべて$x$が削除されるので、間隔は$[l, x-1]$。 

有効な動きが認められるインターバルがなくなった場合、ゲームは終了します。 動けなくなったプレイヤーが負けとなります。 各テストケースで最初のプレイヤーが勝利する戦略を持っているかどうかを判断する必要があります。 

制約は大きく、最大で$2 \cdot 10^5$合計間隔と最大値$10^9$。 これにより、移動ごとのシミュレーションや間隔の状態空間の探索が即座に除外されます。 すべての有効な選択肢を反復しても、$x$間隔には最大で$10^9$値と各動きは、次のようなグローバル条件に依存します。$p$。 

微妙なエッジケースは、間隔が非常に短い場合や次の場合に発生します。$p$大きいです。 たとえば、間隔が$[5, 5]$が存在しないため、移動はまったく不可能です。$x$満足のいく$x \cdot p \ge 5$ない限り$p = 1$、これは許可されていません。 もう 1 つの例外的なケースは次のような場合です。$p$選択しても十分な大きさです$x = r$条件を満たすには不十分なため、間隔がすぐに終了します。 これらのケースは、手数がゼロであってもゲームの結果に影響を与えるため、重要です。 

## アプローチ

 直接シミュレーションでは、有効な間隔を繰り返し選択し、可能な限りすべてを試してゲームをプレイしようとします。$x$選択肢。 ゲームは有限であり、すべての動きが厳密にインターバルを短縮するため、これは原理的には機能しますが、スケール的にはすぐに失敗します。 各間隔では多くの可能な状態が生成される可能性があり、分岐係数は実質的に有効な状態の数になります。$x$、間隔サイズは線形になる可能性があります。 1 つのテスト ケースでも膨大な数の遷移の処理が必要になる可能性があるため、このアプローチは完全に実行不可能になります。 

重要な観察は、各間隔での勝負は、実際にはすべての可能な値を考慮しているわけではなく、間隔が小さすぎて移動できなくなる前に、間隔を何回「圧縮」できるかだけを考慮しているということです。 間隔が現在の最大値に達したら$r$そして最低限の$l$唯一意味のある質問は、削減できるかどうかです。$r$繰り返しのステップで大幅に小さいものに変更し、各インターバルがゲーム全体にどれだけの強制削減に貢献するか。 

動きをより深く見る方法は、次のことを選択することです。$x$新しい上限を選択することと同じです$x-1$、しかし制約$x \cdot p \ge r$力$x$少なくとも$\lceil r / p \rceil$。 つまり、最小の法的選択はまさに$x = \lceil r / p \rceil$、さらに大きなものを選択すると、将来のオプションが増えることなく、より多くの要素が削除されるだけです。 したがって、最適なプレイでは常に最小の有効な値が選択されます。$x$、間隔を$[l, \lceil r/p \rceil - 1]$。 

これにより、各間隔が決定論的なプロセスに短縮され、繰り返し置き換えられます。$r$による$\lfloor (r-1)/p \rfloor$(または、しきい値を使用して同等に縮小します)$\lceil r/p \rceil$）以下になるまで$l$。 それぞれの置換は、正確に 1 つの移動に対応します。 したがって、各インターバルは明確に定義された手数に寄与し、ゲーム全体はすべてのインターバルにわたる独立した手数の合計になります。 勝者は、この合計手数の同等性によって決定されます。

 ## アルゴリズムのチュートリアル

 各インターバルを個別に処理し、それが寄与する手の数を計算します。 

1. 間隔をあけて開始する$[l, r]$。 移動がなくなるまで有効な縮小操作を何回実行できるかに興味があります。 各操作は現在の上限を厳密に減少させるため、プロセスを終了する必要があります。 
2. 間隔がまだアクティブである間に、有効な最小値を計算します。$x$、つまり$x = \lceil r / p \rceil$。 この値は、カットが許可される最も早いポイントを表します。 
3. もし$x \le l$の場合、有効なカットは区間全体を削除するか、制約に違反するため、移動は不可能になります。 この場合、この間隔の間、手数のカウントを停止します。 
4. それ以外の場合は、1 つの移動が実行され、実質的な間隔は次のようになります。$[l, x-1]$。 アップデート$r$に$x-1$、以上のものはすべて等しいので、$x$が削除されます。 
5. 終了するまでプロセスを繰り返し、この間隔の移動数を累積します。 
6. すべての間隔の移動回数を合計します。 合計の手数が奇数の場合は、最初のプレーヤーが勝ちます。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 

重要な単純化は、最適な選択が強制されることです。 有効な最小値からの逸脱$x$インターバルをより積極的に短縮するだけで、今後の手数は増加しないため、プレイヤーの結果を改善することはできません。 

### なぜ効果があるのか

 インターバルは相互作用せず、各手は単一インターバルの現在の最大値にのみ依存するため、ゲームはきれいに分解されます。 固定間隔では、状態は現在の上限によって完全に記述されます。$r$、 以来$l$決して変わりません。 からの移行$r$に$\lceil r/p \rceil - 1$すべての選択は最小限の有効なカットによって支配されるため、最適なプレイの下では決定的です。 これにより、間隔ごとの移動数が一意に定義されます。 

プレイヤーはゲーム全体で交互に手を動かし、各手は正確に 1 インターバルを減らすため、ゲームは Nim のようなパイルと同等であり、各インターバルは強制減少の数に等しいパイル サイズに寄与します。 勝利条件は、総手数のパリティを計算することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def moves(l, r, p):
    cnt = 0
    while r >= l:
        x = (r + p - 1) // p  # ceil(r / p)
        if x <= l:
            break
        cnt += 1
        r = x - 1
    return cnt

t = int(input())
for _ in range(t):
    n, p = map(int, input().split())
    total = 0
    for _ in range(n):
        l, r = map(int, input().split())
        total += moves(l, r, p)
    print("First" if total % 2 == 1 else "Second")
```このコードは、上記の削減プロセスを直接実装します。 ヘルパー関数は、単一区間の強制縮小をシミュレートし、天井分割を使用して常に最小の正当なカット ポイントにジャンプします。 有効な値が存在しない場合、ループは停止します。$x$存在します。これは、しきい値がそれ以下になったときに発生します。$l$。 

重要な実装の詳細はコンピューティングです$\lceil r/p \rceil$整数演算を安全に使用できます。 アップデート$r = x - 1$間隔が連続したままであるという不変条件を保持し、残りの有効な値を正確に表します。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def moves(l, r, p):
        cnt = 0
        while r >= l:
            x = (r + p - 1) // p
            if x <= l:
                break
            cnt += 1
            r = x - 1
        return cnt

    t = int(input())
    for _ in range(t):
        n, p = map(int, input().split())
        ans = 0
        for _ in range(n):
            l, r = map(int, input().split())
            ans += moves(l, r, p)
        print("First" if ans % 2 else "Second")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

 ## 特殊なケース

 主なエッジケースは次のような場合です$l = r$。 その状況では、間隔には要素が 1 つだけあり、移動の条件は決して満たされません。$x = l$必要$l \cdot p \ge l$これは事実ですが、結果の操作ではすべての要素を削除しようとします。$\ge x$、空白の間隔が残り、続行できなくなります。 アルゴリズムはこれを正しく処理します。$x \le l$即座に終了をトリガーし、移動はゼロになります。 

もう 1 つの重要なケースは次のような場合です。$p$非常に大きいです。 たとえば、次の場合$p > r$、 それから$\lceil r/p \rceil = 1$、したがって、そうでない限り$l = 1$、移動は不可能です。 アルゴリズムは最初の反復でこれを検出します。$x \le l$、間隔がターミナルとして正しく分類されていることを確認します。 

3 番目の微妙なケースは、間隔が非常に広い場合に発生しますが、$p$小さいです。 反復ごとに上限が少なくとも 1 分の 1 ずつ減少するため、繰り返される半減または縮小は依然として迅速に収束します。$p$したがって、ループは循環したり成長したりできません。
