 ## 問題の理解

 私たちに与えられたタイムラインは、$n$日々。 一部の日は定休日（法定休日）となります。 他の日はすべて当初は営業日です。 追加労働日を休日に換算することが認められており、この換算日を有給休暇といいます。 法定休日も有給休暇も同じように休日として扱われます。 

目標は、連続稼働日に関する 2 つの構造的制約が満たされるようにスケジュールを変更することです。 まず、以上のものを持つことは決して許可されません$x$連続勤務日。 次に、稼働日を左右に分割する休日を考慮します。 あれば$a$その直前の連続営業日および$b$その直後に合計$a + b$を超えてはなりません$y$。 

私たちは、有給休暇に換算する労働日数を最小限に抑えながら、有効なスケジュールを達成したいと考えています。 

膨大な入力範囲にもかかわらず、キー入力構造はシンプルです。$n$: 最初の日の前の接頭辞と最後の日の後の接尾辞を含む、連続する固定休日の間の距離のみを考慮します。 このような各間隔内では、最初はすべてが機能しており、追加の休息日をどこに挿入するかを決定します。 

制約$n \le 10^{18}$日々のシミュレーションを即座に除外します。 完全な配列を明示的に表すことさえできません。 定休日の数$m \le 2 \cdot 10^5$は、どのソリューションも線形時間内で機能する必要があることを示唆しています。$m$、ギャップごとに一定の値を加えます。 

のみを強制する単純な貪欲な戦略を試みると、微妙な失敗モードが現れます。$x$- ローカルで制限します。 このアプローチでは、$a+b \le y$休息日をまたいだ状態。 

たとえば、次の場合$x = 5$、$y = 7$、長いセグメントをサイズ 5 のチャンクに貪欲に分割すると、隣接するセグメントが得られる可能性があります。$5$そして$5$休符で区切られていると違反します$5+5 \le 7$。 「どのセグメントも超過しない」ことを保証するだけの単純なソリューション$x$」はこれを完全に見逃してしまいます。 

常に正確にカットしようとすると、別の間違いが発生します。$x$日々。 これは、次の遷移を実行可能にするために、以前のセグメントを短縮する必要がある場合があることを無視しています。$y$-制約。 

## アプローチ

 強引な解釈では、現在の勤務日数を維持しながら日ごとにシミュレーションを行い、制約に違反するたびに有給休暇を挿入します。 これは常に違反を即座に修復するため、概念的には正しいですが、次の理由から完全に実行不可能です。$n$できる$10^{18}$。 国家を明示的に表現することさえ不可能です。 

重要な観察は、固定休息日の間の構造が独立しているということです。 2 つの固定休息日の間の連続稼働日の各間隔は個別に解くことができ、答えはすべての間隔の合計になります。 1 つの間隔内では、基本的に長いセグメントを、選択した休息日によって区切られた稼働日の小さなブロックに分割します。 

結果として得られる各ブロックは 2 つのローカル ルールを満たす必要があります。 その長さは最大でも$x$、および長さの隣接するブロックに対して$a$そして$b$、私たちは持っている必要があります$a + b \le y$。 以来$x \le y \le 2x$、隣接するブロック間の相互作用は厳しく制限されており、これが構造を繰り返しパターンに崩壊させる原因です。 

各ブロックをできるだけ大きくしようと常に努めると、最初のブロックは自然に次のようになります。$x$。 次のブロックは両方によって制約されます。$x$そして$y - x$, となるので、$\min(x, y-x)$、これを単純化すると、$y-x$なぜなら$y \le 2x$。 その後、パターンが繰り返されます。一定のサイズのブロックができたら$y-x$、次に許可される最大値は次のようになります。$\min(x, x)$、つまり$x$。 したがって、大きな間隔内の最適な構造は次のようになります。$x$そして$y-x$。 

これにより、各間隔が予測可能な交互シーケンスに短縮されます。 問題は、どれだけ満たされているかを数えるということになります$x, (y-x)$サイクルは間隔の長さに収まります。

 ## アルゴリズムのチュートリアル

 連続した定休日の間は、それぞれのセグメントを独立して処理します。 セグメントの長さ（連続稼働日数）を次のようにします。$L$。 

1. 固定休日は必須の区切り文字として機能し、削除または移動できないため、各セグメントを個別に扱います。 
2. もし$L = 0$、この間隔内には何もスケジュールする必要がないため、作業は必要ありません。 
3. 直接制約の下で、営業日の最初のブロックをできるだけ大きくします。つまり、最初のブロックは次のようになります。$a_1 = \min(x, L)$。 配置後、残りの長さを短くします$L$。 
4. 何も残っていない場合、この期間は有給休暇には寄与しません。 
5. それ以外の場合は、やむを得ず休息日を設けさせていただきます。 次のブロックは前のブロックに依存します$a_1$、その最大可能サイズは次のようになります。$\min(x, y - a_1)$。 下$y \le 2x$、これは次のように評価されます$y-x$、つまり 2 番目のブロックのサイズは固定です$b = y-x$残りのインターバルが短くならない限り。 
6. 残り長さが以下の場合$b$、単純にそれを最後のブロックとして受け取り、停止します。 
7. そうでない場合は、減算します$b$ここから、パターンはブロックの繰り返しペアに安定します。 

サイズのブロック$x$、次にサイズのブロック$y-x$、それぞれ合計を消費します$y$勤務間隔の長さの日数。 
8. 全長の完全なペアの数を数えます。$y$整数除算を使用して残りのセグメントに適合します。 それぞれの完全なペアは 2 つのブロックに貢献します。 
9. 残りの長さを決して超えないように、交互パターンで次のブロックを貪欲に配置し、残りの部分を慎重に処理します。 
10. この期間に必要な有給休暇の日数は、ブロック数から 1 を引いた数になります。 

### なぜ効果があるのか

 任意の間隔内で、選択した休息日で区切られた一連の最大作業ブロックを構築します。 各休日は、隣接する 2 つのブロックのみを制約し、制約は$a+b \le y$任意のブロック サイズを排除するローカル依存関係を強制します。 なぜなら$y \le 2x$、ブロックが到達すると$x$、次のブロックは一意に制約されます。$y-x$、その後、システムは同じ状態に戻ります。 これにより 2 状態の決定論的なオートマトンが作成されるため、常に最大の有効なブロックを取得するという貪欲な選択によって、将来の実現可能性が妨げられることはなく、常に分割数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, x, y = map(int, input().split())
    if m:
        holidays = list(map(int, input().split()))
    else:
        holidays = []

    # build gaps
    prev = 0
    ans = 0

    def solve_gap(L):
        if L <= 0:
            return 0

        # first segment
        first = min(x, L)
        L -= first
        segments = 1

        if L == 0:
            return 0

        # now we are at second segment
        b = y - first
        if b > x:
            b = x
        if b <= 0:
            # degenerate, cannot place more blocks, each remaining day must be isolated
            # but constraints ensure y>=x so b>=0 always; still safe guard
            return L  # each day becomes its own segment

        # second segment
        if L <= b:
            return 1  # one extra segment

        L -= b
        segments += 1

        # now pattern cycles: x, (y-x)
        cycle = x + (y - x)

        full_pairs = L // cycle
        segments += full_pairs * 2
        L -= full_pairs * cycle

        # leftover handling
        if L > 0:
            # next expected is x
            take = min(x, L)
            segments += 1
            L -= take

            if L > 0:
                segments += 1

        return segments - 1

    for i in range(m + 1):
        left = holidays[i-1] + 1 if i > 0 else 1
        right = holidays[i] - 1 if i < m else n
        if left <= right:
            ans += solve_gap(right - left + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、タイムライン全体が固定休日間の独立したギャップに圧縮されます。 各ギャップはヘルパーに渡され、有効な作業セグメントに分割するために追加の休息日が何日必要かを計算します。 

内部`solve_gap`、最初のブロックは常に最大化されます。$x$。 ギャップがすぐになくなる場合は、有給休暇は必要ありません。 それ以外の場合は、前に選択したブロックによって制約される 2 番目のブロックを明示的に構築します。$y - a$。 その時点を過ぎると、構造は安定して長さの完全なサイクルを繰り返すようになります。$x + (y-x)$これにより、除算を使用して一定時間内に大きな部分をスキップできます。 

最終的な残りは最大 2 つの追加ブロックによって処理されますが、完全なサイクルを終了するとパターンは決定的であり、それ以上のシミュレーションを必要としないため、これで十分です。

 ## 特殊なケース

 主なエッジケースは、休日がまったくない場合です。 この状況では、配列全体が 1 つの大きなギャップであるため、アルゴリズムはそれを交互のブロックに正しく分割する必要があります。 このソリューションは、全範囲を仮想境界間の単一の間隔として扱うため、これに対処します。 

もう 1 つのケースは、ギャップが よりも小さい場合です。$x$。 ここでは、分割が必要なく、両方の制約が自動的に満たされるため、アルゴリズムはすぐにゼロの有給休暇を返します。 

さらに微妙なケースが発生するのは、$y = x$。 この領域では、合計制約に違反しない限り、隣接するブロックが両方とも空でないことはできません。 アルゴリズムは自然に縮退します。$y-x = 0$これにより、各ブロックが強制的に分離されます。つまり、ギャップ内の最初の営業日以降のすべての営業日が事実上独自のセグメントになります。
