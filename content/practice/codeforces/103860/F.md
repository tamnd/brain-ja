 ## 問題の理解

 最大 21 個の正の整数の配列と初期値が与えられます。$x$。 配列を任意に並べ替えることができます。 順序を決定した後、要素を 1 つずつ処理し、更新を繰り返します$x$と置き換えることで$x \bmod a_i$。 

目標は、すべてのモジュロ演算を適用した後、次の最終値が得られるように配列の順序を選択することです。$x$できるだけ大きいです。 

重要な点は、操作が対称的ではないことです。$x \bmod a$早期に大幅に削減できる$x$これにより、その後の MOD 操作の効果が制限されます。 このため、順序は非常に重要です。 

制約は非常に小さいです$n$、 と$n \le 21$、ただし、値自体は次のように大きくすることができます。$10^{18}$。 これにより、値の列挙に依存するアプローチは即座に除外されます。$x$密な方法で、または多項式で何かを行う$x$。 利用可能な唯一の小さなパラメータは要素の数であるため、正しい解決策は順列またはサブセットに対する指数関数的な検索に依存する必要があります。 

微妙なエッジ動作が現れるのは、$a_i > x$。 その場合、$x \bmod a_i = x$つまり、適切なタイミングで適用された場合、そのような要素は事実上何も操作されません。 ただし、その後に適用された場合は、$x$減少すると、アクティブになり、値が減少する可能性があります。 たとえば、次の場合$x = 10$、$a = [15, 6]$、最初に 15 を適用します$x = 10$ただし、最初に 6 を適用すると、$x = 4$、その後 15 を適用してもそれ以上何もせず、4 が残ります。正解は 10 です。 

別の失敗例は、貪欲なソートを想定した場合です。$a_i$。 たとえば、降順での並べ替えは自然に見えるかもしれませんが、初期に大きなモジュロを使用すると、別の順序で有益だったはずの後の削減が妨げられる可能性があるため、これは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。配列の可能なすべての置換を試し、モジュロ演算をシミュレートし、最良の結果を維持します。 それぞれの順列には次のものが必要です$O(n)$移行があり、$n!$順列なので、全体の複雑さは次のようになります。$O(n! \cdot n)$。 と$n = 21$、これは天文学的に大きく、実行不可能です。 

重要な観察は、最終的な値は要素の相対的な順序にのみ依存し、要素の数が十分に少ないため、サブセットに対する動的プログラミングが可能であるということです。 完全な順列を構築する代わりに、どの要素がすでに使用されているか、および現在の値が何であるかを追跡しながら、段階的にプロセスを構築します。$x$いくつかの順序で適用した後です。 

重要な構造は、プロセスの状態が、使用されるインデックスのサブセットと現在の値によって完全に決定されるということです。$x$。 どの状態からでも、次に未使用の要素を選択できます。 これにより、当然、最短パスのような構造、つまりサブセット上の DP 構造が形成され、遷移によってセット サイズが 1 つ減少し、値が決定論的に更新されます。 

ただし、サブセットに対する単純な DP と正確な$x$価値観は不可能だから$x$までかかることができます$10^{18}$明確な価値観。 節約に関する重要な観察事項は、$x$それ自体 (係数が大きい場合) または選択した値よりも厳密に小さい値にのみ変更されます。$a_i$。 それで、その間$x$の範囲が広いため、すべての状態にわたる個別の到達可能な値の数は、小さなセットに対する mod 演算によって引き起こされる分岐構造によって大きく制限されます。 

これにより、ビットマスク状態のメモ化が行われ、各状態が達成可能な最良の値を保存します。$x$。 トランジションでは、未使用の各要素が試行され、結果が更新されます。 状態グラフはマスク サイズの点で非巡回であるため、再帰または DP は安全です。

 ## アルゴリズムのチュートリアル

 各状態は、どの要素がすでに使用されているかを示すビットマスクと、現在の値とともに表されます。$x$。 

1. DP 関数を定義する$f(mask, x)$状態から開始して可能な最大の最終値を返します$mask$現在の値で$x$。 この定式化は、問題で説明されているプロセスを直接反映しています。 
2. すべての要素が使用されている場合は、戻り値を返します。$x$。 この時点では、それ以上の操作は残っていないため、現在の値が最終的な値になります。 
3. それ以外の場合は、未使用のインデックスをそれぞれ選択してみてください$i$。 選択肢ごとに次の値を計算します$x' = x \bmod a_i$、再帰的に評価します$f(mask \cup \{i\}, x')$。 
4. すべての選択肢から最大値を取得します。$i$。 これは、可能な限り最適な次の操作を選択することに対応します。 
5. 状態の結果をメモ化します。 同じペアなので$(mask, x)$異なる順列を介して到達する可能性があるため、キャッシュにより再計算が回避されます。 

実際的な改良点は、完全なメモ化です。$x$到達可能な状態の数は依然として管理可能であるため、Python ハッシュを使用して慎重に実装されていれば、単純な意味では不要です。$n \le 21$。 しかし、概念的なDPはまだ終わったままです$(mask, x)$。 

### なぜ効果があるのか

 配列のすべての有効な順序付けは、次から始まるこの状態グラフ内の 1 つのパスに正確に対応します。$mask = 0$そしてイニシャル$x$、で終わる$mask = (1<<n)-1$。 逆に、すべてのパスは有効な順列に対応します。 各状態からのすべての遷移を評価して最大値を取るため、有効な順序が除外されたり、無効な順序が導入されたりすることはありません。 再帰では、同一の状態の繰り返しの再計算を回避しながら、構造化された形式で置換空間全体を探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    x0 = int(input())

    from functools import lru_cache

    @lru_cache(None)
    def dp(mask, x):
        if mask == (1 << n) - 1:
            return x

        best = 0
        for i in range(n):
            if not (mask >> i) & 1:
                nxt = x % a[i]
                cand = dp(mask | (1 << i), nxt)
                if cand > best:
                    best = cand
        return best

    print(dp(0, x0))

if __name__ == "__main__":
    solve()
```解決策は、前述のサブセット DP を直接実装することです。 再帰状態には、使用済みマスクと現在の値の両方が含まれます。$x$。 の`lru_cache`繰り返される状態が 1 回計算されるようにします。 

実装の微妙な詳細は、以下を含める必要があるということです。`x`DPキーにあります。 これを省略すると、使用されている要素は同じだが現在の値が異なる状態が誤ってマージされ、将来の展開では根本的に異なります。

 最適なパスの 1 つは、最初に 10 を選択することです。 

20 mod 10 = 0 ですが、これは良くありません。 代わりに、最初に 7 を選択すると 20 mod 7 = 6 が与えられ、次に 6 を適用すると 0 が与えられ、最終的に 0 が与えられます。ただし、6 を選択すると、最初に 2 が与えられ、次に 7 を選択すると 2 が与えられ、次に 10 を選択すると 2 が与えられ、最後に 2 が与えられます。 

最適な順序付けでは、強力な削減を遅らせることにより、より大きな中間値が保存されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、次のような場合です。$a_i$現在よりも大きいです$x$。 この状況では、すべての操作が終了します$x$変更されていないため、どのような順列も有効であり、答えは単純です。$x$。 すべての遷移が維持されるため、DP はこれを自然に処理します。$x' = x$したがって、すべてのパスは終了するまで値を保持します。 

もう 1 つのエッジ ケースは、非常に小さなエラーが存在する場合です。$a_i$1. のようなアプリケーション$a_i = 1$すぐに強制する$x$DP は、他のすべての選択肢が使い果たされない限り、そのような要素の使用を正しく遅延します。これは、初期に 1 を使用する分岐は最終値 0 を生成し、他のすべてのパスも崩壊しない限り、決して最適ではないためです。 

最後の微妙なケースは、最適な戦略が、多くの no-op 操作にわたって大きな中間値を保持することに依存する場合です。 マスクベースの再帰では、有害な削減を避けられなくなるまで遅らせるものも含め、すべての置換を明示的に試行するため、これが確実に調査されます。
