 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられ、それに対して変更された選択ソートを実行します。 各位置 i について、左から右に i の右側のサフィックスをスキャンし、位置 i で現在の値より小さい要素が見つかるたびに交換します。 このようなスワップごとに、そのラウンドのカウンター ci が増加します。 

重要な出力は、最終的にソートされた配列ではなく、このプロセスの実行時に所定のスワップ カウント t1、t2、...、t(n-1) のシーケンスを生成する初期順列の数です。 

重要な観察は、最初の順列が固定されるとアルゴリズムが決定的になるため、各順列が正確に 1 つのカウンターのシーケンスを誘導することです。 タスクは、指定されたシーケンスを正確に誘導する順列の数を数えることです。 

2⋅10^5 までの制約 n は、すべての順列のプロセスをシミュレートするアプローチや、順列を素朴に再構築しようとするアプローチを即座に除外します。 順列あたりの O(n^2) でさえすでに大きすぎるため、順列にわたる指数関数的な検索は明らかに不可能です。 解決策は、問題を線形または線形に近い組み合わせ構造に還元する必要があります。 

微妙なエッジ ケースは、スワップ プロセスが反復中に配列を変更することです。 たとえば、[4,1,3,2] のような接尾辞で始まると、固定 i でのスワップの数は、同じラウンド内の以前のスワップ後に値がどのように変化するかによって決まります。 スワップが発生すると Pi が変化するため、元のサフィックスの Pi より小さい要素のみをカウントする単純な解釈は間違っています。 

正しく解釈するには、静的な比較だけでなく、スキャン中に進化する「現在の最小値」を追跡する必要があります。 

## アプローチ

 ブルート フォースのアイデアは単純です。すべての順列を生成し、選択ソート バリアントをシミュレートし、すべての ci 値を記録し、ターゲット シーケンスと比較します。 これが機能するのは、アルゴリズムが明確に定義されており、シミュレーションが順列ごとに O(n^2) であるためです。 ただし、順列の数は n! であるため、n = 10 の場合でもこれはすでに実行不可能になり、2⋅10^5 までの n ではまったく不可能になります。 

重要な洞察は、完全な順列の観点から考えるのをやめ、代わりに ci が構造的に測定するものを再解釈することです。 位置 i のスキャン中、アルゴリズムはサフィックス上の実行最小値を効果的に追跡します。 新しい小さい要素が出現するたびに、それが位置 i の新しいアクティブな値になり、このイベントによって ci が増加します。 

したがって、ci は、最初の要素を除いて、サフィックスの実行最小値が何回減少するかをカウントします。 つまり、ci + 1 は、左から右に読むと、シーケンス P[i..n] 内のプレフィックス最小レコードの数と正確に一致します。 

これにより、問題は、各サフィックスに最小レコード数がいくつ含まれなければならないかというグローバルな制約に変わります。 このように表現すると、この構造は組み合わせ配置問題になります。各接尾辞は、その中に出現しなければならない「新しい最小イベント」の数を強制し、これらの制約は接尾辞全体でネストされます。 

位置を右から左に処理できます。 左側に新しい要素を追加してサフィックスを拡張する場合、残りの値のうちのいくつがこのサフィックスの新しいレコードの最小値として機能するかを決定します。 この構造により、最小値として割り当てられる「利用可能な」値の数を追跡すると、これらの選択肢はポジション間で独立することが強制されます。 これにより、各位置がそのサフィックス レベルで導入された新しい最小イベントの原因となる要素を選択する二項因子に寄与する乗法的なカウント プロセスが発生します。

 ## アルゴリズムのチュートリアル

未使用のままの値の数を維持しながら、左から右に制約を処理します。 

各位置 i で、値 ti は、サフィックス i+1..n によってすでに強制されているものを超えて、サフィックス i..n 内にいくつの新しい「レコード最小イベント」を出現させる必要があるかを示します。 サフィックスはネストされているため、これらの新しいイベントは、まさにこのレベルで実行最小値を破る原因となる残りの値のプールから要素を選択することに対応する必要があります。 

まだ割り当てられていない要素の数である変数 rem と、より深いサフィックスでレコード最小トリガーとして機能するためにすでにコミットされている要素の数を追跡する実行値を維持します。 

1 から n−1 までの各 i について、このレベルで新たに指定する必要がある要素の数を計算し、利用可能な残りのプールからそれらを選択します。 

正式には、ステップ i で、利用可能な候補の数は rem − used であり、この接尾語レベルで導入される新しい最小トリガー要素として機能するために、それらの中から ti 要素を選択する必要があります。 このような各選択により、サフィックス i をスキャンするときに実行最小値の新たな減少がどこで発生するかが決まります。 

二項係数を使用してウェイの数を乗算し、すでに使用されている要素の数を更新します。 

最後に、すべての位置を処理した後、998244353 を法とする積を返します。 

### なぜ効果があるのか

 各サフィックス制約は、そのサフィックス内で実行最小値が減少する回数を修正します。 これらの減少イベントは、各接尾辞境界で新しい最小値として機能するようにどの要素が割り当てられるかによって完全に決定されます。 

接尾辞は入れ子になっているため、位置 i で新しい最小値として割り当てられた要素は、その左側にあるすべての短い接尾辞にも属している必要があり、一貫した階層割り当てが強制されます。 これにより曖昧さが解消されます。各レベルで導入される新しい最小値の数を決定すると、実際のアイデンティティの選択は独立しており、未使用の値がどれだけ残っているかにのみ依存します。 

この独立性により、最終的なカウントを組み合わせ選択の結果に反映させることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

n = int(input())
t = list(map(int, input().split()))

fact, invfact = build_fact(n)

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

rem = n
used = 0
ans = 1

for i in range(n - 1):
    take = t[i]
    ways = C(rem - used, take)
    ans = ans * ways % MOD
    used += take
    rem -= 1

print(ans)
```この実装では階乗を事前計算して、二項係数を効率的に評価します。 このループは、割り当てられていない要素の数と、以前のサフィックス制約にすでにコミットされている要素の数を維持します。 各ステップで、そのサフィックスでの新しいレコード最小イベントの原因となる要素を選択する方法の数を掛け合わせます。 

一般的な実装の落とし穴は、残りの要素の off-by-one 処理です。 接尾辞のサイズはステップごとにちょうど 1 ずつ縮小しますが、すでにコミットされた要素の数は t[i] に応じて増加します。

 ## 特殊なケース

 重要なエッジ状況は、すべての ti がゼロの場合です。 これは、最初の要素を超える接尾辞には新しいレコードの最小値が出現しないことを意味します。 このアルゴリズムは、各ステップで常にゼロ要素を選択することによってこれを強制するため、二項因数はすべて C(x, 0) = 1 となり、有効な置換構造が 1 つだけ生成されます。 

ti が初期のポジションで大きい場合、別の境界ケースが発生します。 これにより、使用可能な要素が積極的に消費され、後のサフィックスのプールが縮小されます。 使用される要素が可用性を超えると、二項係数がゼロになるため、組み合わせ構造はこれを自然に処理します。 この問題は妥当性を保証するため、入力にそのような矛盾は発生しません。 

最後の微妙なケースは、初期の i に対して ti = n − i で、残りのすべての要素が新しい最小値になることを強制する場合です。 これは、サフィックス内の厳密に減少する構造に対応します。 各ステップでは、残りの要素をすべて選択する方法が 1 つだけあり、製品の安定性と明確な定義が維持されます。
