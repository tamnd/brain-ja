 ## 解決策
 ## 問題の理解

 頂点に 1 から n までのラベルが付けられたツリーが与えられます。 タスクは、残りの接続コンポーネントが強力な順序制約を満たすように、いくつかのエッジを削除することです。つまり、すべてのコンポーネントがラベルの順序で連続セグメントに正確に対応する必要があります。 つまり、コンポーネントに最小ラベル l と最大ラベル r を持つ頂点が含まれている場合、ラベルが l と r の間にあるすべての頂点は、同じコンポーネントに属している必要があります。 

同様に、エッジを削除した後、頂点はコンポーネントに分割され、各コンポーネントはラベル付け内の連続する整数の間隔になります。 

1 から k までのすべての x について、ツリーが正確に x 個の間隔成分に分割されるようにエッジを削除できる方法が何通りあるかを数えるように求められます。 

n が 2 · 10^5 までという制約により、解は k の値ごとに線形または n log n に近づきますが、k は小さく、最大でも 400 です。これは、各状態がすべての r で再利用され、遷移が償却される動的計画法を強く示唆しています。 

素朴なアプローチではエッジのすべてのサブセットを試しますが、「間隔への有効な分割」に制限したとしても、依然として指数関数的に多くの可能性が残されています。 隠された構造は、すべての有効な解が配列 1..n の連続セグメントへの分割に対応し、各セグメント自体がツリー内の接続されたサブグラフを誘導する必要があるということです。 この問題は、接続制約の下で有効なセグメンテーションをカウントすることに帰着します。 

ツリー構造がラベルとまったく一致しない場合、微妙なエッジ ケースが発生します。 たとえば、ツリーが頂点 1 を中心とし、葉 2..n を持つスターである場合、l > 1 の区間 [l, r] は、ラベルが連続していても中心を除外するため切断されます。 「すべての区間が有効な候補である」と仮定する単純な区間 DP では、大幅に過大カウントされます。 

ラベルの順序付けで隣接関係のみを介して接続がチェックされる場合、別の失敗ケースが発生します。 たとえば、パス 1-3-2-4 は、ツリー構造内の連続したラベルがラベル空間内の有効な間隔を意味しないことを示しています。 

## アプローチ

 直接総当たり戦略では、エッジのすべてのサブセットを列挙し、結果のコンポーネントが有効な間隔であるかどうかをテストします。 サブセットごとに DFS または Union-find を実行してコンポーネントを計算し、各コンポーネントが連続した範囲を形成していることを確認します。 エッジ サブセットは 2^(n−1) 個あり、1 つの構成を検証するだけでも O(n) コストがかかるため、このアプローチは完全に実行不可能です。 

問題の構造は、視点を逆転させることを示唆しています。 削除するエッジを選択する代わりに、シーケンス 1..n のパーティションを連続セグメントに構築するという観点から考えることができます。 各セグメント [l, r] は、これらの頂点上に誘導されたサブグラフが元のツリー内で接続されるようなものでなければなりません。 

これにより、問題はプレフィックス [1..r] を有効なセグメントに分割する方法を数えることに減らされ、r 上の DP とセグメント数が即座に示唆されます。 

主な困難は、セグメント [l, r] がツリー内で接続されているかどうかを判断することです。 重要な単純化は、ツリーにはサイクルがないため、誘導されたサブグラフはすべてフォレストであるということです。 フォレストでは、接続性は正確に |S| を持つことと同等です。 − 誘導されたサブグラフ内の 1 つのエッジ。 したがって、接続を直接追跡する代わりに、間隔内に両方のエンドポイントを持つエッジの数を数えるだけで済みます。 

これにより、間隔の有効性がスライディング ウィンドウで維持できる数値条件に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジサブセットに対するブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | スライド エッジ数を含む間隔にわたる DP | O(nk) 償却 | O(n + k n) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[r][t] を、プレフィックス頂点 1..r を正確に t 個の有効なコンポーネントに分割する方法の数として定義します。

このようなパーティションの最後のセグメントに注目します。これは一定の間隔 [l, r] でなければなりません。 どの l 値が有効であるかがわかっている場合は、dp[l−1][t−1] からの遷移を蓄積できます。 

1. r を 1 から n まで処理し、区間 [l, r] にわたってスライディング構造を維持します。 目標は、どの開始位置が間隔を有効にするかを決定することです。 
2. 固定区間 [l, r] について、誘導された部分グラフが接続されているかどうかを確認する必要があります。 ツリーのサブグラフはどれもフォレストであるため、接続性はちょうど r − l である区間内のエッジの数に相当します。 
3. 両端点が [l, r] 内にあるエッジの数である cntEdges(l, r) を維持します。 また、2 つのポインターを使用してウィンドウ [l, r] を維持します。 
4. r が増加すると、頂点 r を挿入し、もう一方の端点がすでにウィンドウ内にある r に付随するすべてのエッジをチェックして cntEdges を更新します。 
5. l が増加すると、頂点 l を削除し、v がまだ [l, r] 内にあるすべてのエッジ (l, v) を減算します。 
6. 各 r について、条件 cntEdges(l, r) = r − l が有効で安定するまで、l を前方に移動します。 実際には、妥当性を満たす最小の l を維持し、有効な開始部分が r で終わる連続した接尾辞を形成することを観察します。 
7. 有効な範囲 [L[r], r] がわかったら、プレフィックスの合計を使用して DP を更新します。 

dp[r][t] += [L[r], r] のすべての l に対する dp[l−1][t−1] の合計。 

高速範囲合計をサポートするために、プレフィックス DP 配列を維持します。 

### なぜ効果があるのか

 重要な不変条件は、任意の区間 [l, r] において、誘導されたサブグラフはフォレストであるため、その接続性はエッジ数によって完全に決定されるということです。 これにより、明示的な DFS または Union-find 接続チェックが不要になります。 

両方のエンドポイントが間隔に入るとき、または間隔から出るときにすべてのエッジが正確に考慮されるため、スライディング ウィンドウは正しいエッジ カウントを維持します。 各 DP 遷移は有効な接続セグメントに対応するため、カウントされるすべてのパーティションは有効な間隔の一意のシーケンスに対応し、すべての有効なパーティションは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    # active vertex in window
    active = [False] * (n + 1)

    # current edge count inside window
    edge_cnt = 0

    # helper: check if edge is inside current window
    def add_vertex(x):
        nonlocal edge_cnt
        active[x] = True
        for y in g[x]:
            if active[y]:
                edge_cnt += 1

    def remove_vertex(x):
        nonlocal edge_cnt
        for y in g[x]:
            if active[y]:
                edge_cnt -= 1
        active[x] = False

    # dp[r][t]
    dp = [[0] * (k + 1) for _ in range(n + 1)]
    pref = [[0] * (k + 1) for _ in range(n + 1)]

    dp[0][0] = 1
    for j in range(k + 1):
        pref[0][j] = 1 if j == 0 else 0

    L = 1
    active = [False] * (n + 1)
    edge_cnt = 0

    def get_pref(r, t, l):
        if l <= 1:
            return pref[r - 1][t]
        return (pref[r - 1][t] - pref[l - 2][t]) % MOD

    for r in range(1, n + 1):
        add_vertex(r)

        # move L as long as invalid
        while L <= r and edge_cnt != (r - L):
            remove_vertex(L)
            L += 1

        dp[r][0] = 0

        for t in range(1, k + 1):
            dp[r][t] = get_pref(r, t - 1, L) % MOD

        for t in range(k + 1):
            pref[r][t] = (pref[r - 1][t] + dp[r][t]) % MOD

    for t in range(1, k + 1):
        print(dp[n][t] % MOD)

if __name__ == "__main__":
    solve()
```この実装では、スライディング ウィンドウ [L, r] を保持し、その中に完全に含まれるエッジの数を維持します。 各 r について、ウィンドウが接続条件を満たすまで L を調整します。 次に、すべての有効な開始点 l を t あたり O(1) に集約できるように、プレフィックス合計を使用して dp 遷移が計算されます。 

プレフィックス合計テーブル pref[r][t] は r までの dp 寄与を保存し、明示的に反復することなく l にわたる範囲クエリを許可します。 

微妙な点は、エッジのカウントが頂点の挿入と削除の両方で対称的に更新されることです。 両方のエンドポイントがアクティブな場合、各エッジは 1 回だけカウントされるため、これはウィンドウのシフトを通じて一貫したままになります。

 ## 特殊なケース

 最小の単一ノード ツリーは、DP が正しく初期化されるかどうかをテストします。 唯一の有効なパーティションは 1 つのコンポーネントであり、ウィンドウはエッジがゼロの同じ頂点で開始および終了するため、アルゴリズムはこれを処理します。 

星型ツリーは、接続のために中心を含める必要があるため、アルゴリズムに有効な間隔を積極的に縮小させます。 ウィンドウが拡大すると、エッジ数が急速に増加し、条件edge_cnt = r − l により有効なセグメントが大幅に制限され、意図したロジックと一致します。 

パス グラフは、最も単純な接続構造での動作を確認します。すべての間隔が有効であるため、すべての r に対して L は 1 のままで、DP は標準の間隔分割カウントに減少し、すべての r にわたるスライディング ウィンドウの不変条件の一貫性が確認されます。
