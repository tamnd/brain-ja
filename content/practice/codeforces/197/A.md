 ## 解決策
 ## 問題の理解

 寸法が記載された長方形のテーブルがあります`a × b`半径のある同一の円形プレートを無制限に供給可能`r`。 2 人のプレーヤーが交互にテーブルに皿を置きます。 すべてのプレートは長方形の内側に完全に収まる必要があり、プレートは接触していても重なり合うことはできません。 

The game ends when the current player cannot place another plate. Both players play optimally, and we must determine whether the first or second player wins.

 The geometry is much simpler than it first appears. 半径のプレート`r`テーブルの中心が少なくとも留まっている場合にのみテーブル内に収まります`r`すべての国境から離れた単位で。 つまり、中心はより小さな寸法の長方形の内側になければなりません`(a - 2r) × (b - 2r)`。 

制約は小さく、すべての値は最大でも`100`したがって、強引な幾何学シミュレーションでも技術的には制限内に収まります。 本当の課題は、ゲームの構造を認識し、ジオメトリを正しく単純化することです。 

重要なエッジケースは、プレートが 1 枚だけ適合する場合です。 例えば：```
5 5 2
```正しい答えは、`"First"`プレートが 1 枚中央に配置されるとゲームが終了するためです。 

不注意なアプローチを行うと、残りの覆われていない領域が大きいため、さらに多くの配置が可能であると誤って判断する可能性があります。 実際の制限は、未使用領域ではなく、円の重なりによって発生します。 

もう 1 つの微妙なケースは、プレートがまったく適合しない場合です。```
3 3 2
```直径は`4`、両方のテーブルの寸法よりも大きいため、単一のプレートさえ配置できません。 正しい答えは、`"Second"`最初のプレイヤーには移動がないからです。 

よくある間違いはチェックです`a >= r`そして`b >= r`全直径のためのスペースを必要とせずに済みます。 正しい条件は、`a >= 2r`そして`b >= 2r`。 

境界に触れるケースもあります。```
4 7 2
```プレートの直径はテーブルの高さと正確に一致します。 境界線に触れることは許可されているため、これは依然として有効です。 プレートは 1 枚で収まるので、答えは`"First"`。 

非厳密な不等式の代わりに厳密な不等式を使用する実装は、ここで失敗します。 

## アプローチ

 強引な解釈では、ゲームを幾何学的にモデル化します。 すべての有効なプレート配置を生成し、以前に配置された円との重複をチェックし、ミニマックスで勝ち負けの状態を再帰的に評価してみることができます。 

ゲームは有限かつ決定的であるため、そのアプローチは原理的には正しいです。 問題は、状態空間がすぐに爆発してしまうことです。 位置を離散化した後でも、プレートの中心は連続的に変化する可能性があるため、構成の数は膨大になります。 完全な幾何学的なゲーム検索はまったく実用的ではありません。 

画期的な発見は、ボードには複数のプレートを含めることはできないということです。 

プレートには直径があります`2r`。 2 つのプレートがテーブル上に置かれている場合、それらの中心は少なくとも`2r`別に。 ただし、有効な中心は長方形の内側に留まる必要があります。```
[r, a-r] × [r, b-r]
```両方の場合`a < 4r`または`b < 4r`、2 つの中心を距離で隔てる十分なスペースがありません`2r`。 

もっと直接的に言うと、Codeforces の元のトリックはさらに単純です。 両方のプレートがテーブルの内側に完全に収まる必要があるため、半径の重ならない 2 つの円を配置します。`r`少なくとも 1 つのテーブル ディメンションが少なくとも`4r`。 問題の制約と形状の下では、重要なのは少なくとも 1 つのプレートが適合するかどうかだけです。 

プレートが収まらない場合は、最初のプレイヤーがすぐに負けます。 

少なくとも 1 つのプレートが適合する場合、2 番目の動きが存在しないため、最初のプレーヤーがそれを配置し、勝ちとなります。 

したがって、ゲームは 1 つの条件に集約されます。```
a >= 2r and b >= 2r
```true の場合、印刷します`"First"`。 それ以外の場合は印刷します`"Second"`。

 ## アルゴリズムのチュートリアル

 1. テーブルの寸法を読む`a`そして`b`、プレート半径とともに`r`。 
2. プレートが 1 枚テーブルに収まるかどうかを確認します。 

プレートはその直径にのみ適合します`2r`どちらのテーブルの寸法も超えません。 これにより、次の条件が得られます。$a \ge 2r \text{ and } b \ge 2r$3. 条件が true の場合、出力します。`"First"`。 

最初のプレイヤーは唯一可能なプレートを配置し、合法的な手を残しません。 
4. それ以外の場合は、印刷します`"Second"`。 

皿は一切置けないので、先攻は即負けとなります。 

### なぜ効果があるのか

 ゲーム全体は、合法的な先手が存在するかどうかにかかっています。 半径のプレート`r`正方形の辺が必要です`2r`テーブル内に収まるだけです。 いずれかのテーブルの寸法が以下の場合`2r`、移動は存在しません。 

移動が存在する場合、最初のプレイヤーはいつでもプレートを 1 枚置くことができます。 その後、同じ半径の 2 番目の円を配置するには十分なスペースが残っていないため、別のプレートをオーバーラップせずに追加することはできません。 ゲームは常に 0 手か 1 手のどちらかで継続するため、勝者は完全に先手の有無によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, r = map(int, input().split())

    if a >= 2 * r and b >= 2 * r:
        print("First")
    else:
        print("Second")

solve()
```この実装は、ウォークスルーからの数学的観察を直接反映しています。 

表現`2 * r`プレートの直径です。 プレートは、テーブルの両方の寸法が少なくともその大きさである場合にのみ適合します。 

比較には使用する必要があります`>=`の代わりに`>`。 この問題では境界線に触れることが明示的に許可されているため、直径がテーブルの寸法と正確に一致するプレートは依然として有効です。 

結果は単一の幾何学的チェックに依存するため、ループや追加のメモリは必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a, b, r = map(int, input().split())

    if a >= 2 * r and b >= 2 * r:
        print("First")
    else:
        print("Second")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("5 5 2\n") == "First\n", "sample 1"

# no plate fits
assert run("3 3 2\n") == "Second\n", "no valid move"

# exact boundary fit
assert run("4 7 2\n") == "First\n", "touching border allowed"

# minimum values
assert run("1 1 1\n") == "Second\n", "smallest table"

# large valid case
assert run("100 100 50\n") == "First\n", "maximum exact fit"

# one dimension too small
assert run("10 3 2\n") == "Second\n", "fails on one dimension only"

## 特殊なケース

 次の入力を考えてみましょう。```
4 7 2
```直径は`4`。 テーブルの高さもぴったり`4`, そのため、円は上下の境界線に同時に触れます。 

アルゴリズムは以下をチェックします。```
4 >= 4  -> True
7 >= 4  -> True
```そしてプリント`"First"`。 

これにより、実装が非厳密な不等式を正しく処理していることが確認されます。 

次に、次のことを考えてみましょう。```
3 3 2
```直径は`4`、両方の寸法より大きい。 チェックは次のようになります。```
3 >= 4  -> False
3 >= 4  -> False
```アルゴリズムは出力します`"Second"`法的な配置が存在しないからです。 

最後に、混合ケースを考えてみましょう。```
10 3 2
```幅は十分に大きいですが、高さが足りません:```
10 >= 4 -> True
3 >= 4  -> False
```アルゴリズムはまだ出力します`"Second"`プレートは両方の寸法に完全に適合する必要があるためです。 よくある間違った解決策は、1 つの次元のみをチェックするか、エリアベースの推論を使用するものですが、ここではどちらも失敗します。
