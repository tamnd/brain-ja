 ## 問題の理解

 間隔内の整数を数える必要があります$[a,b]$最小の約数が次より大きいもの$1$まさに$k$。 

数字の場合$x$、その最小の約数は$k$2 つのことが同時に起こることを意味します。 

1.$x$で割り切れます$k$。 
2.$x$～のどの整数でも割り切れません$2$に$k-1$。 

2 番目の条件は、直ちに次のことを意味します。$k$それ自体が素数でなければなりません。 もし$k$合成された場合、その小さい約数の 1 つが除算も行うことになります$x$、 それで$k$最小の約数になることはありません。 

限界は大きい。 両方$a$そして$b$到達できる$2 \cdot 10^9$, そのため、間隔を繰り返すことは不可能です。 治験部門ですべての数値を個別にチェックするだけでも、最悪の場合、数十億の操作が必要になります。 

の値$k$も大きいですが、重要な観察によって救われます。$k$が素数の場合、すべての有効な数値は次の形式になります$$x = k \cdot t$$そして$t$より小さいすべての素因数を避けなければなりません$k$。 

合成数の最小の約数は素数であるため、以下の素数による割り算を禁止するだけで十分です。$k$。 これにより、問題は包含排他とメビウス関数を使用した計数問題に変換されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。

## アプローチ

 ブルートフォースアプローチは定義に直接従います。 すべての整数に対して$x$で$[a,b]$、その最小の約数が より大きいことがわかります。$1$。 その約数が等しい場合$k$、それを数えます。 

最小の約数によって数値が条件を満たすかどうかが一意に決まるため、これは論理的に機能します。 問題はスケールです。 間隔の長さはほぼ$2 \cdot 10^9$。 たとえ$O(\sqrt{x})$1個あたりのチェック数が絶望的に​​多くなります。 

重要な観察は、次のことです。$x$等しい$k$、 それから$k$素数である必要があり、$x$で割り切れる必要があります$k$。 書く：$$x = k \cdot t$$では、どのような条件が当てはまるのか聞いてみましょう$t$。 

いくつかのプライムなら$p < k$分割する$t$、 それから$p$も分割します$x$、矛盾しています$k$最小の約数になります。 それで$t$より小さいすべての素数の積に対して互いに素でなければなりません$k$。 

これにより、問題は素数のセットで割り切れない範囲の整数を数える問題に変換されます。 

より小さい素数の数$k$製品が以下にとどまる場合、大きくすることはできません$2 \cdot 10^9$。 最初の 10 個の素数の積はすでにこの制限を超えています。 つまり、これらの素数のすべてのサブセットに対して包含-排他を安全に使用できるということです。 

ブルートフォースはすべての数値を個別にチェックします。 最適解は、禁止素数の倍数を減算することによってグループ全体を一度にカウントします。

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。$k$プライムです。 

もし$k$複合なのですぐに印刷します$0$。 合成数は、その小さい素約数の 1 つが最初に現れるため、別の数の最小の約数になることはできません。 
2. 数値から間隔を変換する$x$乗算器へ$t$。 

有効な数値はすべて次の形式になります。$$x = k \cdot t$$それで：$$L = \left\lceil \frac{a}{k} \right\rceil$$

$$R = \left\lfloor \frac{b}{k} \right\rfloor$$ここで整数を数える必要があります$t \in [L,R]$より小さい素数で割り切れないもの$k$。 
3. より小さいすべての素数を生成します。$k$。 

までの素数だけが必要です$\sqrt{k}$素数性をテストするためですが、以下のすべての素数も保存します。$k$これらは禁止された約数であるため、$t$。 
4. 包含/除外を適用します。 

禁止された素数を次のようにします。$$p_1,p_2,\dots,p_m$$これらの素数のすべてのサブセットについて、その積を計算します。$$d = p_{i_1}p_{i_2}\cdots p_{i_s}$$中の数字が何個あるか数えてください$[L,R]$で割り切れます$d$:$$\left\lfloor \frac{R}{d} \right\rfloor - \left\lfloor \frac{L-1}{d} \right\rfloor$$サブセット サイズが偶数の場合はこのカウントを加算し、サブセット サイズが奇数の場合は減算します。 
5. 最終的な包含/除外の結果は、有効な乗数の数です。$t$、有効な整数の数に等しい$x$。 

### なぜ効果があるのか

 すべての有効な数値は次のように一意に書くことができます。$x = kt$。 以来$k$はプライムです、唯一の方法です$x$より小さな約数を持つことは、$t$より小さい素因数を含む$k$。 アルゴリズムはそれらを正確にカウントします$t$すべての禁止された素数を回避します。 

包含排他は、少なくとも 1 つの禁止素数で割り切れる数値を減算することと、複数回カウントされたバックナンバーを加算することを交互に行うため、正しいです。 すべてのサブセットを処理した後、すべての無効な$t$正味カウントはゼロですが、有効なカウントはすべて含まれます。$t$ちょうど 1 つだけ貢献します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1
    return True

def primes_less_than(k):
    primes = []
    for x in range(2, k):
        ok = True
        d = 2
        while d * d <= x:
            if x % d == 0:
                ok = False
                break
            d += 1
        if ok:
            primes.append(x)
    return primes

def solve():
    a, b, k = map(int, input().split())

    if not is_prime(k):
        print(0)
        return

    L = (a + k - 1) // k
    R = b // k

    if L > R:
        print(0)
        return

    primes = primes_less_than(k)

    ans = 0
    m = len(primes)

    for mask in range(1 << m):
        bits = 0
        prod = 1

        for i in range(m):
            if (mask >> i) & 1:
                bits += 1
                prod *= primes[i]

                if prod > R:
                    break

        else:
            cnt = R // prod - (L - 1) // prod

            if bits % 2 == 0:
                ans += cnt
            else:
                ans -= cnt

    print(ans)

solve()
```最初の部分では次のことを確認します。$k$プライムです。 これは最適化ではなく、正確性の要件です。 もし$k$合成です。正確に最小の約数を持つ数値はありません$k$。 

次に、元の間隔を乗数空間に変換します。 すべての候補数は次の倍数です$k$したがって、次の値のみを扱います。$t$。 左側の境界の天井分割は間違いやすいです。 使用方法:```
(a + k - 1) // k
```最小の整数を正しく計算します$t$そのような$kt \ge a$。 

包含-除外ループは、禁止された素数のすべてのサブセットを反復します。 変数`prod`現在のサブセットに素数の積を格納します。 その商品がすでに超過している場合`R`、範囲内のどの数値もそれで割り切れないため、サブセットは何も寄与しません。 

交互の符号は包含と排除から直接生じます。 偶数サイズのサブセットはカウントを加算し、奇数サイズのサブセットはカウントを減算します。 

Python の整数は任意精度であるため、この実装ではオーバーフローの危険はありませんが、初期段階では問題が発生します。`prod > R`サブセットの処理を小さく保ちます。
