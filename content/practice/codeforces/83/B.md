 ## 解決策
 ## 問題の理解

 医者を待っている動物たちの列ができています。 動物`i`正確に医者に行かなければなりません`a[i]`永遠に離れる前の回。 

動物を検査すると、必ず 2 つのうちのいずれかが起こります。 さらに訪問が必要な場合は、すぐにキューの最後尾に移動します。 その訪問が必要な検査をすべて完了した場合、その訪問はキューから消えます。 

医師は正確に処置します`k`検査が行われ、その後動作が停止します。 その時点でまだキューにある動物を、前から後ろへ正確な順序で出力する必要があります。 

この制約により、直接シミュレーションが完全に排除されます。 動物の数は最大で`10^5`、それは管理可能ですが、`k`と同じ大きさにすることができます`10^14`。 文字通りのシミュレーションでは、検査ごとに 1 つの操作が必要となり、これは 100 兆のキュー操作を意味する可能性があります。 高度に最適化された実装でも、これに対処することはできません。 

検査可能な総数は、すべての検査の合計です。`a[i]`。 その合計が以下の場合`k`、医者は手術すらできない`k`試験、そして答えは`-1`。 

難しい部分は、膨大な数の循環ローテーションと削除の後にキューを再構築することです。 

簡単な間違いの 1 つは、キューがちょうどその直後に空になるケースの処理を誤ることです。`k`-回目の試験。 

例：```
Input:
1 1
1
```1回の検査の後、唯一の動物は永遠に去ります。 キューは空であるため、正しい出力は空行ではなく空行です。`-1`。 

別の微妙なケースは、同じ「ラウンド」中に複数の動物が終了した場合に発生します。 

例：```
Input:
4 5
2 1 2 1
```不用意に実装すると、削除後に動物が間違って回転し、間違った残りの順序が生成される可能性があります。 

正しいプロセスは次のとおりです。```
Initial: 1 2 3 4
After 1: 2 3 4 1
After 2: 3 4 1
After 3: 4 1 3
After 4: 1 3
After 5: 3
```正しい出力:```
3
```もう一つの危険なコーナーケースは、`k = 0`。 

例：```
Input:
3 0
5 2 7
```検査は行われないため、キューは変更されません。```
1 2 3
```常にキューを少なくとも 1 回進める実装は、ここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 キューを明示的に保存します。 前の動物を繰り返しポップし、残りの訪問回数を減らし、捨てるか押し戻します。 

このシミュレーションはプロセスに正確に従っているため、正確です。 問題は規模だ。 すべての動物が最大で必要な場合、`10^9`訪問と`k`それ自体が到達する`10^14`、シミュレーションには何兆もの操作が必要になる場合があります。 

プロセスの構造により、より良いアプローチが得られます。 

現在生きているすべての動物がキューを 1 サイクル完了するところを想像してください。 すべての生きている動物は、そのサイクル中に必要な訪問を 1 回だけ失います。 訪問を 1 つずつ処理する代わりに、レイヤー全体を一度に処理できます。 

現在あると仮定します`m`生きている動物たちには、少なくとも`d`さらに多くの訪問。 そうすれば、私たちは過ごすことができます`m * d`一括検査により、生きているすべての動物を減らすことができます。`d`。 

これにより、問題はすべての番号から同時にレイヤーを剥がすことに似たものになります。 

必要な訪問ごとに動物を分類すると、一部の動物が消える前に何層の完全な層を削除できるかを判断できます。 削除されたレイヤーの数は、すべての生きている動物に適用されるグローバル オフセットのように機能します。 

最終的には、次の完全なレイヤーが次のレベルを超える点に到達します。`k`。 この時点では、部分的なサイクルのみが残っています。 残りの検査数が生きている動物の数よりも少ないため、最終キューを直接再構築できます。 

ブルート フォースはキュー操作が単純であるため機能しますが、すべての検査を個別に処理するため失敗します。 最適化されたソリューションが機能するのは、多くの連続した検査が生きているすべての動物に同様に影響を及ぼし、膨大なプロセスを 1 つの算術ステップに圧縮できるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値を読み取り、可能な検査の合計数を計算します。`sum(a)`。 

もし`sum(a) < k`、印刷`-1`医師はそれほど多くの検査を行うことができないため、すぐに。 
2. ペアを作成する`(a[i], i)`そしてそれらを並べ替えます`a[i]`。 

並べ替えを行うと、動物が消えた順に処理できるようになります。 
3. 3 つの変数を維持します。`prev`、すでに削除された完全なレイヤーの数。`alive`、まだキューにある動物の数。`used`、すでに検査数が占めています。 
4. 分類された動物を繰り返し処理します。 

現在の動物が次のことを要求しているとします。`x`訪問。 以来`prev`層はすでに世界中で削除されていますが、この動物にはまだ必要があります`x - prev`消える前に追加の完全なレイヤー。 
5. 以下を計算します。```
cost = (x - prev) * alive
```これは、生きているすべての動物を次の失踪点まで減らすために必要な検査の数です。 
6. もし`used + cost <= k`、このブロック全体を消費します。 

アップデート：```
used += cost
prev = x
alive -= count_of_animals_removed_here
```複数の動物が同じものを共有する場合があります`x`, それで、それらはすべて一緒に消えます。 
7. そうしないと、次の完全なレイヤーを完了できません。 

この瞬間、生きているすべての動物はすでに命を落としています。`prev`訪問。 残りの検査は次のとおりです。```
rem = k - used
```8. 元の価値が次の値より大きいすべての動物を収集します。`prev`。 これらはまさに今も生きている動物たちです。 
9. キューの順序では生存している動物間の相対的な順序が常に維持されるため、これらの生きている動物を元のインデックスで並べ替えます。 
10. 残りのプロセスは、アクティブなキューをローテーションしているだけです。`rem`ステップ。 

以来`rem < number_of_alive_animals`、最後のキューは次の位置から始まります。```
rem % len(alive_animals)
```11. 生きている動物をその位置から循環的に出力します。 

### なぜ効果があるのか

 取り外し後`prev`完全な層、生き残ったすべての動物が正確に持っています`a[i] - prev`残りの訪問数。 すべての完全なレイヤーがすべての生きている動物の完全な 1 回転に対応するため、キュー内のそれらの相対的な順序は変わりません。 

別の完全なレイヤを完了する前に停止すると、残りの検査は生きているキューを部分的に通過するだけになります。 前進`rem`キュー順序内の位置は、残りの検査を 1 つずつ実行するのと正確に一致します。 

削除は動物を削除するだけであり、生存者の順序を変更することはないため、アルゴリズムはキューの順序を失うことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if sum(a) < k:
        print(-1)
        return

    arr = sorted((a[i], i) for i in range(n))

    used = 0
    prev = 0
    alive = n
    ptr = 0

    while ptr < n:
        value = arr[ptr][0]
        diff = value - prev
        cost = diff * alive

        if used + cost > k:
            break

        used += cost
        prev = value

        while ptr < n and arr[ptr][0] == value:
            ptr += 1
            alive -= 1

    remaining = k - used

    survivors = []

    for i in range(n):
        if a[i] > prev:
            survivors.append(i + 1)

    if not survivors:
        print()
        return

    start = remaining % len(survivors)

    answer = survivors[start:] + survivors[:start]

    print(*answer)

solve()
```最初の重要な詳細は、早期の不可能性チェックです。 必要な検査の合計が以下の場合`k`, 処理が早く終了したため、医師の終了時間を過ぎてもキューは存在しません。 

ソートされた配列により、レイヤーの削除プロセスが開始されます。 それぞれの個別の値は、新しい動物のグループがいつ消滅するかを教えてくれます。 

表現:```
cost = diff * alive
```がソリューションの核心です。`diff`は、すべての生きている動物に均一に適用できる完全なラウンドの数を表し、各ラウンドはすべての生きている動物に一度だけ触れます。 

内側の`while`ループは、必要な訪問数が現在のしきい値と等しいすべての動物を削除します。 等しい値を一緒に処理することが重要です。 これを忘れると、不正な生存数が生成され、後の計算が中断されます。 

一括処理が停止した後、残りのすべての動物は次の条件を満たします。```
a[i] > prev
```これらの動物は、元のインデックスに従ってキューの順序で表示されます。 完全なレイヤーは循環順序を保持するため、実際のキューは必要ありません。 

残りの検査は生存者の数よりも少ないため、単純なローテーションにより最後のキューが得られます。 

空のキューの場合は微妙です。 すべての動物が正確な時間に消えてしまったら`k`、正しい出力は単なる空行です。

        if sum(a) < k:

 ## 特殊なケース

 最終検査の直後にキューが空になった場合を考えてみましょう。 

入力：```
1 1
1
```このアルゴリズムは 1 つの完全なレイヤーを処理します。```
cost = 1 * 1 = 1
```摂取後:```
used = 1
alive = 0
```生き残った人はいないため、アルゴリズムは空の行を出力します。 これは実際のプロセスと正確に一致します。 

次に、同時削除を検討します。 

入力：```
4 5
2 1 2 1
```並べ替え後:```
(1,1), (1,3), (2,0), (2,2)
```最初のレイヤーのコストは次のとおりです。```
1 * 4 = 4
```それを食べた後、両方の動物に価値があります`1`一緒に消える。 生存者は次のとおりです。```
1, 3
```残る検査はあと1つ。 1 回回転すると次のようになります。```
3
```ここでは、等しい値を一緒に処理することが重要です。 一度に 1 つずつ削除すると、同じレイヤー内の生存数が誤って変更されてしまいます。 

最後に考えてみましょう`k = 0`。

1 2 3
```これにより、アルゴリズムが空のプレフィックスの場合を正しく処理することが確認されます。
