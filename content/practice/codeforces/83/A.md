 ## 問題の理解

 整数配列が与えられているので、「魔法の」連続した部分配列がいくつあるかを数える必要があります。 最小値が最大値と等しい場合、部分配列は魔法のようになります。 

最小値と最大値が等しくなるのは、部分配列内のすべての要素が同じである場合のみです。 この観察によって問題は完全に変わります。 任意の部分配列について考える代わりに、同じ数の連続したブロックのみを考慮します。 

たとえば、配列では次のようになります。```
2 1 1 4
```連続する等しい値のブロックは次のとおりです。```
[2]
[1 1]
[4]
```すべての単一要素の部分配列は魔法のようであり、ブロックは`[1 1]`サブ配列にも貢献します`[1, 1]`長さ2。 

配列の長さは次のように大きくできます。$10^5$。 すべての部分配列をチェックする二次アルゴリズムでは、大まかに次のように検査されます。$$\frac{n(n+1)}{2}$$部分配列、これは約になります$5 \times 10^9$いつ$n = 10^5$。 これは 2 秒の制限をはるかに超えています。 

この制約は、線形または線形に近い解決策が必要であることを強く示唆しています。 

見落としやすいエッジケースがいくつかあります。 

すべての要素が異なる配列を考えてみましょう。```
5
1 2 3 4 5
```正しい答えは、`5`単一要素のサブ配列のみが対象となるためです。 不注意な実装では、エンドポイントのみをチェックする場合、誤って長い範囲をカウントしてしまう可能性があります。 

ここで、すべての要素が等しい配列を考えてみましょう。```
4
7 7 7 7
```すべての部分配列は魔法です。 答えは次のとおりです。$$\frac{4 \cdot 5}{2} = 10$$バグのある実装では、セグメント内のすべての部分配列をカウントするのではなく、最大の等しいセグメントを 1 回だけカウントする可能性があります。 

もう 1 つの微妙なケースは、等しいブロックが複数回出現する場合です。```
6
1 1 2 2 2 1
```最後`1`の最初のブロックに接続しません`1`■ サブ配列は連続していなければならないためです。 正しい答えは、等しいセグメントをそれぞれ独立して扱うことで得られます。```
2 + 6 + 1 = 9
```どこ：$$\frac{2 \cdot 3}{2} = 3$$最初のブロックについては、$$\frac{3 \cdot 4}{2} = 6$$真ん中のブロックに関しては、

 そして$$1$$最後の要素については。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての部分配列を列挙し、その最小値と最大値を計算し、それらが等しい場合はカウントします。 

サブアレイの場合`a[l:r]`、条件:```
min(a[l:r]) == max(a[l:r])
```すべての要素が同一であることを意味します。 

単純な実装では、次の 3 つのネストされた操作が使用されます。 

1. 左側のエンドポイントを選択します。 
2. 適切なエンドポイントを選択します。 
3. サブ配列をスキャンして最小値と最大値を計算します。 

それには費用がかかります$O(n^3)$。 

最小値と最大値を段階的に最適化したとしても、すべてを検査します。$O(n^2)$サブアレイ。 と$10^5$要素、それはまだ遅すぎます。 

重要な観察は、部分配列は、その内部のすべての要素が等しい場合にのみ魔法であるということです。 

つまり、魔法の部分配列は異なる値の間で交差することはありません。 それらは完全に同一の番号の連続する範囲内に存在します。 

ある長さのブロックがあるとします。$k$:```
x x x x ... x
```このブロック内のすべてのサブ配列は魔法です。 

長さ内のサブ配列の数 -$k$セグメントは:$$\frac{k(k+1)}{2}$$なぜなら:

 - あります$k$長さ 1 の部分配列、
 -$k-1$長さ 2、
 -$k-2$長さ3の、
 -など。 

したがって、問題全体は次のようになります。 

1. 最大の連続する等しいセグメントの長さを見つけます。 
2.合計$\frac{k(k+1)}{2}$すべてのセグメントにわたって。 

現在のセグメントの長さを追跡しながら、配列を 1 回スキャンできます。 これにより、線形時間の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) から O(n³) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列サイズと配列自体を読み取ります。 
2. 回答変数を次のように初期化します。`0`。 
3. 現在のブロックの長さを等しい値に維持しながら、配列の左から右へのスキャンを開始します。 
4. 現在のブロック長を次のように設定します。`1`最初の要素については。 
5. 次の各要素について:

 1. 前の要素と等しい場合は、長さを増やして現在のブロックを拡張します。 
2. それ以外の場合は、前のブロックが終了しています。 追加：$$\frac{len \cdot (len + 1)}{2}$$答えに対して、長さを指定して新しいブロックを開始します`1`。 

この式では、その等しい値セグメント内のすべての部分配列がカウントされます。 

1. ループが終了したら、最後のブロックの寄与を追加します。これは、まだセグメント内にある間に配列が終了する可能性があるためです。 
2. 合計の答えを出力します。 

### なぜ効果があるのか

 すべての魔法の部分配列は、完全に等しい値で構成されます。 このような部分配列は、1 つの最大の連続した等しいセグメント内に完全に存在する必要があります。 

ある長さのセグメントの場合$k$、その中にある可能なすべての連続した部分配列は魔法のようであり、まさに次のものが存在します。$$\frac{k(k+1)}{2}$$彼らのうち。 

このアルゴリズムは、配列を最大の等しいセグメントに分割し、各セグメント内のすべてのサブ配列を 1 回だけカウントします。 魔法のサブ配列が欠落することはなく、無効なサブ配列もカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0
length = 1

for i in range(1, n):
    if a[i] == a[i - 1]:
        length += 1
    else:
        ans += length * (length + 1) // 2
        length = 1

ans += length * (length + 1) // 2

print(ans)
```プログラムは、等しい値の現在の連続セグメントを追跡します。 

変数`length`現在のセグメントのサイズを格納します。 次の値が前の値と一致するたびに、セグメントが拡張されます。 それ以外の場合、セグメントは終了し、その寄与分が追加されます。 

式:$$\frac{k(k+1)}{2}$$は次のように実装されます。```
length * (length + 1) // 2
```結果は整数のままでなければならないため、整数の除算が必要です。 

ループ後の最後の追加は忘れがちです。 これがなければ、最後のセグメントは決して答えに貢献しません。 

このソリューションでは、一定の追加メモリのみを使用し、配列を 1 回スキャンします。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    length = 1

    for i in range(1, n):
        if a[i] == a[i - 1]:
            length += 1
        else:
            ans += length * (length + 1) // 2
            length = 1

    ans += length * (length + 1) // 2

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4\n2 1 1 4\n") == "5\n", "sample 1"

# all elements different
assert run("5\n1 2 3 4 5\n") == "5\n", "all distinct"

# all elements equal
assert run("4\n7 7 7 7\n") == "10\n", "all equal"

# minimum size
assert run("1\n42\n") == "1\n", "single element"

# multiple separated blocks
assert run("6\n1 1 2 2 2 1\n") == "10\n", "multiple segments"

# alternating values
assert run("6\n1 2 1 2 1 2\n") == "6\n", "no long magical subarrays"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 2 3 4 5`|`5`| 単一の要素のみがカウントされます |
 |`7 7 7 7`|`10`| 1 つの大きなセグメントの式 |
 |`42`|`1`| 最小入力サイズ |
 |`1 1 2 2 2 1`|`10`| 別々の等しいブロックは独立して処理されます。 
|`1 2 1 2 1 2`|`6`| 交互の値は長さ 1 の部分配列のみを生成します。 

## 特殊なケース

 すべての値が異なる場合を考えてみましょう。```
5
1 2 3 4 5
```このアルゴリズムは、長さ 1 の 5 つの別々のセグメントを作成します。 

彼らの貢献は次のとおりです。```
1 + 1 + 1 + 1 + 1 = 5
```値が変更されるたびにセグメントが即座に中断されるため、サブ配列はカウントされなくなりました。 

ここで、すべての値が等しい配列を考えてみましょう。```
4
7 7 7 7
```スキャンによってセグメントが分割されることはありません。 最後に：```
length = 4
```アルゴリズムは以下を追加します。$$\frac{4 \cdot 5}{2} = 10$$これは、考えられるすべての部分配列の合計数と一致します。 

最後に、分離された等しいブロックについて考えます。```
6
1 1 2 2 2 1
```アルゴリズムは以下を処理します。```
[1 1]
[2 2 2]
[1]
```独立して。 

最初で最後`1`マージされることはありません。`2`連続性を解除します。 これにより、次のような無効な部分配列のカウントが正しく防止されます。```
1 1 2 2 2 1
^           ^
```それは魔法ではありません。
