 ## 解決策
 ## 問題の理解

 実線上に一連のセグメントが与えられ、各セグメントはその左右の端点によって定義されます。 タスクは、結合がすべてのセグメントの結合と正確に等しい、これらのセグメントのサブセットをカウントすることです。 言い換えれば、サブセットからセグメントを削除すると全体のカバレッジが減少するような、セグメントを選択する方法の数が必要になります。 

入力サイズは最大 200,000 セグメント、エンドポイントは最大 200,000 セグメントまで可能です。$10^9$。 ポイントの総数が天文学的に大きくなる可能性があるため、セグメント内のすべてのポイントを明示的に反復するアプローチは除外されます。 同様に、単純なサブセット列挙には次のことが必要になります。$2^n$明らかに実行不可能な操作$n$その周り$10^5$。 したがって、点ではなく、セグメント自体とその関係の観点から推論する必要があります。 

セグメントが他のセグメントを完全に含んでいる場合、またはセグメントが一致している場合には、明らかではないエッジ ケースが発生します。 たとえば、セグメント [1,6]、[2,6]、および [1,1] の場合、結合は [1,6] になりますが、一部のセグメントは冗長です。 すべてのセグメントが含まれなければならないと仮定する不注意なアプローチでは、サブセットが 1 つだけカウントされますが、正しい答えでは、冗長セグメントを省略する方法が考慮され、この例では 4 つのサブセットが得られます。 

もう 1 つの微妙なケースは、長さがゼロのセグメントです。 たとえば、すべてのセグメントが [2,2]、[2,2]、[2,2] のような点である場合、和集合は単一の点 2 になります。これらのセグメントの空でないサブセットはすべて「良好」であるため、良好なサブセットの数は次のようになります。$2^n - 1$。 厳密に増加する間隔に依存するアルゴリズムは、これらの入力で失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$2^n$セグメントのサブセットを作成し、それぞれの和集合を計算し、それがすべてのセグメントの和集合と一致するかどうかを確認します。 これは原理的には正しいですが、$n=200,000$それはまったく不可能ですので、$2^{200,000}$実行可能な計算をはるかに超えています。 

重要な洞察は、セグメントが以前のセグメントでカバーされていないポイントをカバーする場合にのみ必要であるという観察から得られます。 セグメントを左端点で並べ替えると、右端点がこれまでに確認された最大右端点以下であるセグメントは一部のサブセット内で冗長であり、自由に含めたり除外したりできます。 結合を拡張するセグメントのみが必須です。 

これは自然に動的プログラミングのアプローチにつながります。 セグメントを左の端点で並べ替えることができます。 セグメントごとに、特定の点までをカバーするセグメントで終わる適切なサブセットを形成する方法の数を追跡できます。 セグメントが以前のカバレッジ内に含まれている場合は、そのセグメントを含めるか含めないかのどちらかになり、その時点から組み合わせの数が 2 倍になります。 カバレッジを拡張すると、左端の直前で終了するセグメントから組み合わせの数が蓄積されます。 

問題の構造 (単調なカバレッジと含まれるセグメントのサブセットの独立性) により、このアプローチが実現可能になります。 さまざまな正しいエンドポイントで終わる有効なサブセットの数を維持し、二分探索を使用して重複しない最後のセグメントを効率的に見つけることで、複雑さを次のように軽減できます。$O(n \log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 (ソートされたセグメントを含む DP) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを左の端点で並べ替えます。 2 つのセグメントが同じ左側を共有する場合は、右側の端点で昇順に並べ替えます。 これにより、セグメントが左から右の順序で処理されるようになり、冗長なセグメントを識別しやすくなります。 
2. 動的プログラミング配列を初期化する`dp`、 どこ`dp[i]`最初のサブセットの中の良好なサブセットの数を保存します。`i`正確にセグメントで終わるセグメント`i`。 
3. プレフィックスの合計を計算する`pref[i]`の`dp`効率的な範囲の合計のために。 これにより、二分探索を使用して対数時間で以前の有効なセグメントの合計を計算できます。 
4. セグメントごとに`i`、二分探索を使用して最後のセグメントを見つけます`j`その右端点が左端点よりも小さい`i`。 これにより、重複しないセグメントが識別されます。`i`。 セグメントを含める方法の数`i`一方、適用範囲の拡大は次の合計です。`dp[k]`みんなのために`k ≤ j`。 
5. セグメントの場合`i`前のカバレッジ内に完全に含まれている (つまり、その右端点 ≤ 前のセグメントの最大右端点)、`i`はオプションです。 含めるか除外するかを考慮して、カウントに 2 を掛けます。 
6. すべてのセグメントを処理した後、次の合計が`dp[i]`最大右端点に達するすべてのセグメントについて、良好なサブセットの総数が得られます。 

なぜ機能するのか: 不変条件は次のとおりです。`dp[i]`和集合がセグメントの右端点で正確に終了するすべてのサブセットをカウントします`i`隙間なく。 含まれるセグメントではギャップが発生しないため、サブセット数が増加します。 カバレッジを拡張するセグメントは、その開始前に終了する有効なサブセットとのみ結合され、正確性が維持されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline
MOD = 998244353

n = int(input())
segments = [tuple(map(int, input().split())) for _ in range(n)]
segments.sort()

rights = [r for _, r in segments]
dp = [0] * n
pref = [0] * (n + 1)
max_r = 0

for i, (l, r) in enumerate(segments):
    # binary search for last segment ending before l
    idx = bisect.bisect_right(rights, l - 1) - 1
    dp[i] = 1 if idx == -1 else pref[idx + 1]
    dp[i] %= MOD
    # double count if contained in previous coverage
    if r <= max_r:
        dp[i] = (dp[i] * 2) % MOD
    max_r = max(max_r, r)
    pref[i + 1] = (pref[i] + dp[i]) % MOD

# sum dp[i] for all segments reaching max_r
answer = sum(dp[i] for i, (_, r) in enumerate(segments) if r == max_r) % MOD
print(answer)
```このソリューションでは、まずセグメントを並べ替えてから、反復的に構築します。`dp`以前の重複しないセグメントに基づいています。 二分探索により、結合する安全なセグメントが特定され、オプションで含まれるセグメントのアカウントが 2 倍になります。 プレフィックス合計により効率的な合計が可能になります。 更新中`max_r`以前のカバレッジに完全に含まれていたセグメントを確実に特定します。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 998244353

    n = int(input())
    segments = [tuple(map(int, input().split())) for _ in range(n)]
    segments.sort()

    rights = [r for _, r in segments]
    dp = [0] * n
    pref = [0] * (n + 1)
    max_r = 0

    for i, (l, r) in enumerate(segments):
        idx = bisect.bisect_right(rights, l - 1) - 1
        dp[i] = 1 if idx == -1 else pref[idx + 1]
        dp[i] %= MOD
        if r <= max_r:
            dp[i] = (dp[i] * 2) % MOD
        max_r = max(max_r, r)
        pref[i + 1] = (pref[i] + dp[i]) % MOD

    answer = sum(dp[i] for i, (_, r) in enumerate(segments) if r == max_r) % MOD
    return str(answer)

# provided sample
assert run("3\n1 1\n2 6\n1 6\n") == "4", "sample 1"

# minimal case
assert run("1\n1 1\n") == "1", "minimal case"

# all equal
assert run("3\n2 2\n2 2\n2 2\n") == "7", "all equal points, 2^3-1"
