 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$m$セルと一連の$n$スライドドア。 各ドアは連続したセルのブロックを占め、ドアは左から右への固定順序で表示されます。 ドア$i$固定幅がある$a_i$、ドアは廊下に沿ってスライドできますが、相互に通過することはできないため、相対的な順序が変わることはありません。 

この観点から見ると、有効な構成とは単に次のものを配置することです。$n$線に沿った固定長の互いに素なセグメント$m$位置を変更し、それらの間および周囲の一部のセルが覆われていない状態になります。 これらの覆われていない細胞は「自由空間」を形成します。 

各クエリは、同時にアクセスできる必要がある一連のセル インデックスを提供します。 セルは、ドア セグメントで覆われていない場合にのみアクセスできます。 各クエリの問題は、ドアを何らかの有効な構成にスライドさせて、必要なすべてのセルが同時に空き領域に配置できるかどうかです。 

重要な問題は、固定構成を確認するように求められていないことです。 ドア間の隙間を再配置することは許可されていますが、ドアの固定順序と固定長の両方を尊重する必要があります。 

この制約により、位置を明示的にシミュレートしようとしたり、配置を検索したりするソリューションはすでに除外されています。 まで$2 \cdot 10^5$ドアとクエリ、およびクエリの合計サイズも$2 \cdot 10^5$、セルまたはドアに関するクエリごとの二次推論は失敗します。 各クエリを入力サイズに応じて線形時間で処理するソリューションが必要です。 

1 つのドアが必要な位置間の空きセルの領域に対して大きすぎる場合、微妙な障害が発生します。 たとえば、必要なセルが廊下を小さな安全なセグメントに分割している場合、グループを慎重に再配置しない限り、長いドアが必要なセルを横切ることを余儀なくされる可能性があります。 これが中心的な制約です。禁止された位置をまたいでドアを分割することはできません。 

## アプローチ

 強引な解釈では、可能なすべての配置を試します。$n$ライン上のセグメントを配置し、必要なセルを避けて配置されているかどうかを確認します。 これは配布に相当します$m - \sum a_i$空のセルはドア間の隙間であり、これはすでに組み合わせ爆発を示唆しています。 たとえ正確な位置を無視してギャップについてのみ推論したとしても、可能な分布の数は指数関数的に増加します。$n$, そのため、直接検索することは不可能です。 

重要な構造的観察は、重要なのは、必要なセルが自由空間の連続ブロックとどのように相互作用するかだけであるということです。 クエリに必要なセルを修正すると、行が「安全な」セルの最大セグメントに分割されます。 安全な区域内では、通過を禁止されているドアはありません。 唯一の制限は、1 つのドアが必要なセルを横切ることができないため、すべてのドアをこれらの安全セグメントの 1 つの内側に完全に配置する必要があることです。 

これにより、問題は梱包プロセスに変わります。 私たちは安全なセグメントの長さを計算し、ドアをこれらのセグメントに貪欲にフィットさせながら順番に配置しようとします。 ドアは順序付けされており、重複することはできないため、ドアをセグメントに配置すると、以前のすべてのドアが以前のセグメントに固定されます。 ドアが現在の安全セグメントに収まらない場合は、次の安全セグメントに移動します。 

これにより、問題はクエリごとに 1 回のリニア スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

### 1. 安全なセグメントを構築する

 フルレンジから始めます$[1, m]$必要なセルをすべてマークします。 これらの必須の位置により、ラインが必須のセルを含まない連続した間隔に分割されます。 このような各間隔は安全なセグメントであり、その長さはドアを配置するために利用できる連続したスペースの量を表します。 

セグメントに圧縮する理由は、セグメント内にはドアが存在しないため、必要なセルに対してドアが配置される場所に制限がないためです。 

### 2. ドアの欲張った配置

 ドアを順番に繰り返していきます。 また、安全なセグメントを順番に繰り返します。 

現在の安全なセグメントで利用可能な残りのスペースを維持します。 

各ドアについて:

 1. 現在の安全セグメントにドアを取り付けるのに十分なスペースが残っている場合は、そこにドアを配置し、残りのスペースを減らします。 
2. 適合しない場合は、次の安全なセグメントに移動し、残りの容量をリセットします。 
3. ドアが単一の安全セグメントよりも大きい場合は、先に進んでもすぐに答えは不可能になります。 

この貪欲な戦略が機能するのは、セグメントにドアを配置すると決めたら、後で配置しても、すでに順序によって制約されている後続のドアに使用できるスペースが減るだけだからです。 

### 3. 答えを決める

 すべてのドアが正常に配置された場合は、YES を返します。 それ以外の場合は、「NO」を返します。 

### なぜ効果があるのか

 重要な不変条件は、各ステップで常に現在のドアを、それが適合する最も早い安全なセグメントに配置することです。 より右側に配置する代替配置は、後のドアの柔軟性を低下させるだけです。これは、後のドアには同じかそれより少ない残りの選択肢がありますが、利用可能なセグメントがより少ないか等しいためです。 この単調な構造により、有効な配置が存在する場合、貪欲な配置でそれを見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    q = int(input())

    for _ in range(q):
        tmp = list(map(int, input().split()))
        c = tmp[0]
        w = tmp[1:]

        # build safe segments from forbidden positions
        w.sort()
        segs = []
        prev = 1

        for x in w:
            if prev <= x - 1:
                segs.append(x - prev)
            prev = x + 1

        if prev <= m:
            segs.append(m - prev + 1)

        # greedy placement
        i = 0
        ok = True

        for length in segs:
            remaining = length

            while i < n and remaining >= a[i]:
                remaining -= a[i]
                i += 1

            # if we cannot place next door in this segment
            # we just move to next segment, but if segment is too small for a single door, we skip
            while i < n and a[i] > length:
                # this door cannot fit here at all, try next segment
                break

            if i == n:
                break

        # after processing all segments, check if all doors placed
        print("YES" if i == n else "NO")

if __name__ == "__main__":
    solve()
```コードはまず、禁止されたセルを最大の空き間隔に変換します。 これらの間隔は、必要な位置を横切ることなくドアを配置できるすべての可能な連続領域を表します。 

次に、ドアを順番に詰めようとします。 ポインタ`i`配置する必要がある次のドアを追跡します。 安全なセグメントごとに、そのセグメントに収まる限り多くの連続したドアを消費します。 ドアが合わない場合は、ループを継続することで暗黙的に次のセグメントに移動します。 

微妙な点は、ドアを複数のセグメントに分割しようとしていないことです。 各ドアは単一の安全セグメント内に完全に収まる必要があり、これはまさに貪欲チェックによって強制されるものです。

 ## 特殊なケース

 主なエッジ ケースは、必要な 1 つのセルでドアよりも小さなセグメントが作成される場合です。 この場合、合計の空き領域が大きくても、セグメント化によりハードなバリアが強制されます。 貪欲スキャン中にドアが単一のセグメントに収まらないため、アルゴリズムはこれを検出します。 

もう 1 つのエッジ ケースは、必要なセルが位置 1 や位置などの境界にある場合です。$m$。 これにより、長さ 0 の空の先頭セグメントまたは末尾セグメントが作成されます。 この構造では長さがゼロのセグメントは当然無視されるため、特別な処理は必要ありません。 

最後のエッジケースは、すべてのセルが必要な場合です。 これでは安全なセグメントがまったく生成されず、ドアをどこにも配置できないため、貪欲なプロセスはすぐに失敗し、正しく NO が生成されます。
