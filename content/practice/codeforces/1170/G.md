 ## 解決策
 ## 問題の理解

 エッジが繰り返され、自己ループが許可される無向マルチグラフが与えられます。 タスクは、単純なサイクルを選択し、そのサイクルに属するすべてのエッジを削除することを繰り返して、すべてのエッジを完全に削除することです。 ここでの単純なサイクルは、開始と終了を除いて頂点を繰り返さない閉じたウォークであり、ループは長さ 1 の有効なサイクルとしてカウントされます。 

アウトプットは単なる決定ではありません。 エッジ セットが元のエッジ マルチセットを分割するような一連のサイクルを明示的に構築する必要があります。 すべてのエッジは正確に 1 つの印刷サイクルに表示される必要があり、各サイクルは選択時のグラフ内の実際のサイクルに対応する必要があります。 

制約は最大 200,000 個の頂点とエッジに及ぶため、削除ごとに接続性を再計算したりサイクルを最初から検索したりするアプローチは、直ちに遅すぎます。 各エッジが一定の回数処理される、本質的に線形または線形に近い分解方法を期待する必要があります。 

微妙な点は、エッジが単なるセットではなくマルチセットであることです。 同じ頂点間の 2 つの同一のエッジは、分解において別個のオブジェクトとして扱われる必要があります。 もう 1 つの特殊なケースは自己ループです。これはすでにサイクルになっており、シングルトン サイクルとして出力する必要があります。 

素朴な間違いは、慎重に記録を作成せずに DFS を使用して「サイクルを見つけて削除する」ことを繰り返し試行することです。 エッジを削除すると接続が動的に変更され、単純な DFS サイクル抽出ではエッジの分離が保証されず、有効なパーティションでの終了さえも保証されないため、これは頻繁に失敗します。 

別の失敗例は、ローカル サイクルの選択により残りのエッジがツリー状の残差にトラップされる可能性がある、奇妙な構造を持つマルチグラフで発生します。 たとえば、未使用のエッジを追跡せずに貪欲にサイクルを選択すると、全体的に分解が存在する場合でも、残りのグラフにどのサイクルにも属さない残りのエッジが生じる可能性があります。 

## アプローチ

 強引なアイデアは、DFS または BFS を使用してグラフ内で単純なサイクルを繰り返し検索し、そのサイクルを出力し、そのエッジを削除することです。 各サイクル検索は O(n + m) であり、最悪の場合は最大 O(m) サイクルが必要になる可能性があります。 これにより、制限をはるかに超える O(m(n + m)) の複雑さが生じます。 

中心となる観察は、この問題は基本的に、すべてのエッジが正確に 1 つの閉じられたトレイルに属するようにエッジの使用をペアにすることに関するものであるということです。 トラバーサルの観点から考えると、未使用のエッジを経由して頂点に入るたびに、ループを閉じるまで別の未使用のエッジを経由して頂点から出ることができるはずです。 これはオイラー トラバーサルを思い出させますが、接続されたコンポーネントごとに 1 つのオイラー ツアーを生成する必要はなく、代わりに複数のサイクルに分割できるという違いがあります。 

重要な洞察はオイラー スタイルの DFS をシミュレートすることですが、再帰スタック内の既にアクティブな頂点に戻るたびに、現在の DFS ツリー内にサイクルが見つかります。 そうすれば、そのサイクルをすぐに剥がすことができます。 各エッジは DFS で 1 回だけ使用され、サイクルは DFS スタックのバック エッジから抽出されます。 これにより、訪問状態を追跡するときに、DFS バック エッジが基礎となる無向グラフ内の単純なサイクルを常に閉じるため、単純なサイクルへの分解が保証されます。 

これにより、タスクがエッジ セット上の単一の DFS に削減され、各頂点が現在再帰スタック内にあるかどうかが維持され、アクティブな頂点のパスが追跡されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返しサイクルの検出 | O(m(n + m)) | O(n + m) | 遅すぎる |
 | DFSサイクルピーリング | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各無向エッジを一意のエッジ識別子を持つ 2 つの有向隣接エントリとして表すため、エッジを 1 回だけ使用されたものとしてマークできます。

1. すべての頂点の (neighbor、edge_id) ペアを格納する隣接リストを作成します。 これにより、マルチグラフであっても曖昧さなくエッジをトラバースすることができます。 
2. 配列を維持する`used_edge`サイズ m は false に初期化されます。 これにより、各エッジが正確に 1 サイクルに含まれることが保証されます。 
3. DFS 状態配列を維持する`in_stack[v]`頂点が現在アクティブな再帰スタックにあるかどうかを示します。 
4. スタックを維持する`path`現在の DFS パスを表す頂点の数。 
5. 未使用のインシデント エッジがまだあるすべての頂点から DFS を実行します。 接続は必要ありません。 すべてのコンポーネントを処理する必要があります。 
6. 頂点 v からの DFS 中に、v をパスにプッシュし、in_stack としてマークします。 
7. 未使用のエッジ (v、to、id) ごとに、使用済みのマークを付けて再帰します。`to`。 もし`to`はすでに in_stack です。サイクルが見つかりました。到達するまでパスを後ろ向きに歩きます。`to`、頂点を収集します。 このシーケンスは現在の再帰スタック セグメントに正確に対応するため、単純なサイクルを形成します。 
8. サイクルを抽出するとき、そのセグメント内の連続する頂点間の横断エッジも関連付けます。 これらのエッジはこのサイクルに割り当てられており、トラバース中にすでに使用済みとしてマークされているため、再利用されません。 
9. v からすべてのエッジを探索した後、スタックから v をポップします。 
10. すべてのエッジが使い果たされるまで続けます。 

これが機能する理由は、DFS がすべてのエッジを 1 回だけ探索することを保証するためです。 現在再帰スタック内にある頂点に遭遇すると、その頂点と現在のノードの間のパスが DFS フォレスト内で単純なサイクルを形成します。 エッジは決して再利用されないため、サイクルはエッジに素です。 すべてのエッジは、正確に 1 つの DFS ツリー パス セグメントに属し、検出されたバックエッジ サイクルの一部、または最終的に何らかのサイクル クロージャの一部となる前方トラバーサルの一部です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]

for i in range(m):
    x, y = map(int, input().split())
    adj[x].append((y, i))
    adj[y].append((x, i))

used = [False] * m
in_stack = [False] * (n + 1)
parent = [-1] * (n + 1)
parent_edge = [-1] * (n + 1)

cycles = []

def extract_cycle(u, v):
    cycle = [v]
    cur = u
    while cur != v:
        cycle.append(cur)
        cur = parent[cur]
    cycle.append(v)
    cycle.reverse()
    cycles.append(cycle)

def dfs(v):
    in_stack[v] = True
    for to, eid in adj[v]:
        if used[eid]:
            continue
        used[eid] = True
        if not in_stack[to]:
            parent[to] = v
            dfs(to)
        else:
            extract_cycle(v, to)
    in_stack[v] = False

for i in range(1, n + 1):
    if any(not used[eid] for _, eid in adj[i]):
        dfs(i)

print("YES")
print(len(cycles))
for c in cycles:
    print(len(c), *c)
```隣接リストにはすべてのエッジが 2 回格納されるため、トラバーサルは対称的になります。 の`used`配列により、両方向のエッジの再訪問が防止されます。 

再帰スタック マーカー`in_stack`が不可欠です。 これがないと、ツリーのエッジとバック エッジを区別できず、サイクル抽出が失敗するか、不正確なパスが生成されてしまいます。 

バック エッジが検出されると、親ポインターは DFS パス セグメントを再構築し、正確な頂点サイクルを順番に与えます。 

## 実用的な例

 ### 例 1

```これは単一の三角形です。 

| ステップ | 現在の頂点 | 使用エッジ | スタック | 形成されたサイクル |

 3 の DFS がすでにスタックにある 1 へのエッジを認識すると、サイクル 1-2-3-1 を抽出します。 

これにより、DFS のバック エッジが完全なサイクルを正しく識別していることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各エッジは、隣接トラバーサルで 1 回だけ使用され、2 回処理されたとマークされます。 
| スペース | O(n + m) | 隣接リストと DFS ブックキーピング配列 |

 線形の複雑さは 200,000 のエッジに必要です。 サイクルの検索を繰り返すと制限を超える可能性がありますが、エッジ マーキングを備えた DFS では各エッジが 1 回処理されることが保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for i in range(m):
        x, y = map(int, input().split())
        adj[x].append((y, i))
        adj[y].append((x, i))

    used = [False] * m
    in_stack = [False] * (n + 1)
    parent = [-1] * (n + 1)

    cycles = []

    def extract_cycle(u, v):
        cycle = [v]
        cur = u
        while cur != v:
            cycle.append(cur)
            cur = parent[cur]
        cycle.append(v)
        cycle.reverse()
        cycles.append(cycle)

    def dfs(v):
        in_stack[v] = True
        for to, eid in adj[v]:
            if used[eid]:
                continue
            used[eid] = True
            if not in_stack[to]:
                parent[to] = v
                dfs(to)
            else:
                extract_cycle(v, to)
        in_stack[v] = False

    for i in range(1, n + 1):
        if any(not used[eid] for _, eid in adj[i]):
            dfs(i)

    out = ["YES", str(len(cycles))]
    for c in cycles:
        out.append(str(len(c)) + " " + " ".join(map(str, c)))
    return "\n".join(out)

 ## 特殊なケース

 自己ループは長さ 1 のサイクルを形成するため、すぐに処理されます。 DFS 中に、頂点からそれ自体へのエッジとして検出されますが、頂点はすでに再帰スタック内にあるため、その頂点のみを含むサイクルが生成されます。 

2 つの頂点間の平行エッジにより、DFS に複数のバック エッジが作成されます。 各エッジは独立して使用されるようにマークされるため、各エッジは抽出された 1 つのサイクルにのみ参加します。 親の再構成により、エッジが繰り返されてもサイクルが誤ってマージされないことが保証されます。 

切断されたグラフは、未使用のインシデント エッジがまだあるすべての頂点から DFS を開始することによって処理されます。 これにより、コンポーネントがスキップされず、すべてのエッジが最終的に何らかのサイクル抽出によって消費されることが保証されます。
