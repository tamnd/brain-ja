 ## 問題の理解

 一連のホイール圧力が与えられているので、正確に選択する必要があります$m$彼らのうち。 それらを選択した後、$m$ホイールの圧力を変更して、すべての値が単一の値に等しくなるようにすることができます。 ホイールを 1 増やすか減らすなど、単位を変更するたびに 1 分かかります。 

問題を非対称にする追加の制限が 1 つあります。圧力の低下は常に許可されますが、すべての操作で増加するユニットの合計数が以下を超えることはできません。$k$。 したがって、ホイールを全体で 5 増やすと、すでにグローバル増加予算の 5 ユニットが消費されます。 

課題はどちらを選択するかです$m$使用するホイールと最終的な均等圧力を目標に設定することで、費やされる合計時間を最小限に抑えながら、世界的な増加予算を決して超えないようにすることができます。 

制約により、私たちは次のように考えることを強いられます。$O(n \log n)$または$O(n)$条項。 と$n \le 2 \cdot 10^5$、すべてのサブセットまたはサブセットのすべてのペアを試すような解決策は、直ちに不可能になります。 平$O(n^2)$建設が遅すぎる。 これにより、ソートされた構造と、連続するセグメント、プレフィックスの合計、またはスライディング ウィンドウに基づくソリューションが求められます。 

目標値を独立して固定し、最も近い要素を貪欲に選択しようとすると、微妙な失敗のケースが発生します。 これは、選択されたすべての要素を結合する増加予算を無視しています。 もう 1 つの落とし穴は、対称性を仮定することです。コストの増加はグローバルに制限される一方、減少は制限なく常に許可されるため、コストは対称的ではありません。 

要素ごとの貪欲な選択が失敗する具体例としては、高い値はわずかに少ないものの、減らすのにコストがかかり、低い値は多いが個別には安価であるにもかかわらず、それらの合計増加が違反する場合が挙げられます。$k$。 単純な「ターゲットに最も近い m を選択する」戦略では、気付かないうちに増加予算を簡単に超えてしまう可能性があります。 

## アプローチ

 直接的な強引なアイデアは、サイズのすべてのサブセットを試すことです$m$、各サブセットについて、考えられるすべての最終的な等しい値を試します。 固定のサブセットと目標値の場合、差の絶対値を合計し、合計の増加を追跡することでコストを計算できます。 これは正しいですが、完全に実行不可能です。サブセットの数は$\binom{n}{m}$、これは指数関数的です$n$、各サブセットを評価する場合でも、次のように線形になります。$m$。 

重要な構造的観察は、配列をソートした後、最適なセットが$m$ホイールはソートされた順序で連続したブロックを形成します。 その理由は、最終値を固定する場合、ソート順に遠い要素を近い要素と交換することはコストを削減するだけであり、増加要件を悪化させることはないからです。 

連続する長さのセグメントに制限すると、$m$、問題はさらに構造化されます。 各セグメントについて、最終的な等しい値を決定する必要があります。 絶対偏差コストの場合、最適値は常に選択したセグメントの中央値です。 これにより、ターゲットの選択肢が大幅に減少します。 

残りのタスクは、サイズのウィンドウごとにチェックすることです$m$、増加制約の下で実現可能かどうかを判断し、そのコストを効率的に計算します。 これは、ソートされた配列のプレフィックス合計を使用して実行でき、ウィンドウごとに一定時間の評価が可能になります。

 ## アルゴリズムのチュートリアル

 まず配列をソートして、次の候補グループが$m$車輪は連続したセグメントとして表されます。 

次に、長さのすべてのセグメントを調べます$m$、潜在的な候補グループとして扱います。 

1. 配列をソートする$a$降順ではない順に。 
2. 任意の範囲合計をクエリできるようにプレフィックス合計を構築します。$O(1)$。 
3. すべてのウィンドウについて$[l, r]$長さの$m$、中央位置を計算します$p = l + \frac{m-1}{2}$。 これを最終的な等圧値として選択します。 
4. ウィンドウの左半分のすべての要素を最大まで引き上げるコストを計算します。$a[p]$。 増加コストの合計は次のとおりです。$$\text{inc} = a[p] \cdot (p - l) - \sum_{i=l}^{p-1} a[i]$$これを超えると$k$、ウィンドウは無効なのでスキップします。 
5. すべての要素を次と等しくするための全コストを計算します。$a[p]$:

 左側は上記のように増加に寄与し、右側は減少に寄与します。$$\text{dec} = \sum_{i=p+1}^{r} a[i] - a[p] \cdot (r - p)$$総費用は$\text{inc} + \text{dec}$。 
6. すべての有効なウィンドウにわたって最小コストを追跡します。 

重要な決定は、目標値として中央値を選択することです。 これは、固定セット内の絶対偏差を最小限に抑えるのに最適です。 追加の唯一の制約は、増加予算を超えないようにすることです。これは中央値を下回る要素にのみ依存します。 

### なぜ効果があるのか

 選択したウィンドウについて、最終値を固定すると、絶対偏差を最小化する最適値が中央値になります。 中央値から逸脱すると、両側で対称的に総コストが増加します。 コストの増加は目標を下回る要素にのみ依存するため、目標を中央値からずらすと、全体の目標を改善することなくコストが増加するか、実現可能性が低下します。 したがって、すべての最適解を取得するには、隣接する各ブロックをその中央値でチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    INF = 10**30
    ans = INF

    for l in range(0, n - m + 1):
        r = l + m - 1
        p = l + (m - 1) // 2
        x = a[p]

        left_cnt = p - l
        left_sum = pref[p] - pref[l]
        inc = x * left_cnt - left_sum

        if inc > k:
            continue

        right_cnt = r - p
        right_sum = pref[r + 1] - pref[p + 1]
        dec = right_sum - x * right_cnt

        ans = min(ans, inc + dec)

    print(ans)

if __name__ == "__main__":
    solve()
```ソートのステップにより、すべての最適な選択がこの順序で連続したウィンドウになることが保証されます。 プレフィックス合計を使用すると、セグメント合計を高速に計算できます。これは、ウィンドウごとの合計を再計算すると、$O(nm)$解決。 

唯一の微妙な実装の詳細は、中央値付近の正しいインデックス付けです。 左側は厳密に中央値インデックスの前にあり、右側は厳密にその後から始まります。 包括的な境界を混在させると、コストが誤って移動する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    def solve():
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        ans = 10**30

        for l in range(n - m + 1):
            r = l + m - 1
            p = l + (m - 1) // 2
            x = a[p]

            inc = x * (p - l) - (pref[p] - pref[l])
            if inc > k:
                continue

            dec = (pref[r + 1] - pref[p + 1]) - x * (r - p)
            ans = min(ans, inc + dec)

        return str(ans)

 ## 特殊なケース

 エッジケースの 1 つは、すべての要素が同一である場合です。 この状況では、すべてのウィンドウのコストがゼロになるため、計算された増加コストがゼロであるために、アルゴリズムが誤ってセグメントを拒否してはなりません。 この式では、増加項と減少項の両方で正しくゼロが得られるため、すべてのウィンドウが有効です。 

別のエッジケースが発生するのは次の場合です。$m = 1$。 中央値ロジックは依然として各ウィンドウ内の唯一の要素を選択し、増加と減少の両方がゼロになり、変更が必要ないという事実と一致します。 

より微妙なケースは次のような場合です。$k = 0$。 ここで、選択したすべての要素が既に中央値以上にない限り、中央値を下回る要素を持つウィンドウは無効になります。 計算された増加コストはウィンドウを受け入れる前にゼロに対して厳密にチェックされるため、アルゴリズムはこれを正しく処理します。
