 ## 解決策
 ## 問題の理解

 いくつかの隠れた整数シーケンスから生成された単一の平坦化されたシーケンスが与えられます。 エンコード プロセスでは、すべてのシーケンスが「列順」に混合されます。まず、各シーケンスの最初の要素がすべて、次に 2 番目の要素がすべて、次に 3 番目の要素がすべて、というように混合されます。 シーケンスの要素がなくなると、その時点以降、代わりに特別なマーカー値 -1 が使用されます。 

タスクは、このマージされたストリームから元のシーケンス (グループ化と内部順序の両方) を再構築することです。 

このプロセスについて考えると便利な方法は、各元のシーケンスが「ラウンド」ごとに 1 つの値に寄与するということです。 ラウンド 1 では各シーケンスの最初の要素を取得し、ラウンド 2 では各シーケンスの 2 番目の要素を取得します。 エンコードは、すべてのシーケンスがその終了 -1 を提供した場合にのみ停止します。 

出力では、エンコード前に存在したシーケンスの数と各シーケンスに何が含まれているかを正確に再構築する必要があります。 

この制約により、最大 300,000 個のエンコード値が許可されます。 これにより、単純なネストされた方法でシーケンスごとまたはラウンドごとにプロセスを繰り返しスキャンまたはシミュレートしようとするソリューションは即座に除外されます。 各エンコードされた要素を 1 回または一定回数処理する線形再構成が必要です。 

微妙な困難は、エンコード プロセス内の実際の -1 マーカーと構造的な終端を区別することに起因します。 すべてのシーケンスはちょうど 1 つの -1 に寄与し、それらの -1 値は同期された「ラウンド」に表示されます。 -1 をすべてのシーケンスのハードストップとして扱う単純なアプローチは、シーケンスが異なる時点で終了するため、機能しません。 

もう 1 つの特殊なケースは、空のシーケンスです。 一部のシーケンスには要素がまったく含まれていない場合があります。これは、最初の寄与がすでに -1 であることを意味します。 これらは出力内で正しく表現される必要があります。 

## アプローチ

 ブルートフォース解釈では、シーケンスを繰り返しスキャンし、要素をラウンドごとに収集し、終了マーカーが表示されるまでシーケンスに割り当てて、逆方向にエンコードをシミュレートしようとします。 エンコードされた配列を複数回繰り返し、各パスでまだアクティブなすべてのシーケンスの値の次の「列」を抽出することを想像することもできます。 

これではすぐに遅くなりすぎます。 あれば$m$要素と潜在的に$O(m)$ラウンドごとに大きなプレフィックスをスキャンすると、$O(m^2)$最悪の場合の行動。 

重要な構造的洞察は、エンコーディングが厳密なインターリーブ パターンを保持していることです。つまり、要素はレイヤーに書き込まれ、各レイヤー内では常にシーケンス順に表示されます。 これは、アクティブなシーケンスの現在のリストを維持し、検出された各値をストリーミング形式で正しいシーケンス位置に割り当てることによって、シーケンスを段階的に再構築できることを意味します。 

ラウンドの観点から考える代わりに、ストリームを左から右に処理し、現在「生きている」シーケンスの動的なリストを維持します。 値を検出するたびに、現在のラウンドでの位置に基づいて、その値を正しいシーケンスに追加します。 シーケンスに対して -1 をヒットすると、そのシーケンスは今後のラウンドから削除されます。 

主な課題は、シーケンスが消失したときに各値がどのシーケンスに属するかを追跡することです。 この構造により、各ラウンドで常に順序どおりにシーケンスが埋められるため、前のラウンドからの位置を再利用して、進行中にアクティブ セットを圧縮できます。

 ## アルゴリズムのチュートリアル

 1. エンコードされたシーケンスをスキャンし、最初にシーケンスが終了する場所を特定します。 各 -1 は、正確に 1 つのシーケンスの終わりに対応します。 シーケンスはラウンドごとに順番に処理されるため、シーケンスが -1 より前に最後に出現する時刻によって、その長さの構造がわかります。 
2. 現在再構築中のシーケンスの動的リストを維持します。 最初はシーケンスは作成されません。 
3. ポインターを現在の「ラウンド位置」に保持​​しながら、エンコードされた配列を反復処理します。 値ごとに、新しいシーケンスを開始するか、既存のシーケンスを継続するかを決定します。 
4. -1 以外の値が表示され、現在のラウンド位置に十分なアクティブなシーケンスがない場合は、新しいシーケンスを作成し、それに値を追加します。 これは、新しいシーケンスがこの位置に最初の要素を提供するという事実を反映しています。 
5. -1 以外の値が表示され、対応するアクティブなシーケンスがその位置に存在する場合、その値をそのシーケンスに追加します。 
6. -1 に遭遇すると、それは現在のラウンドのこの位置で終了するシーケンスに対応します。 そのシーケンスを終了としてマークし、アクティブな追跡から削除します。これにより、以降のラウンドには参加しなくなります。 
7. エンコードされた配列全体が消費されるまで続行し、すべてのシーケンスが完全に構築されていることを確認します。 

重要な不変条件は、アクティブなシーケンス リストが現在または将来のラウンドに寄与する要素をまだ持っているシーケンスをどの時点でも正確に表すということです。 ラウンド内の各位置は安定した配列の同一性に対応し、-1 によって配列が削除されると、後のラウンドでは再び出現することはありません。 これにより、各値が正しい元のシーケンスに 1 回だけ割り当てられ、順序が維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input())
    b = list(map(int, input().split()))

    seqs = []
    active = []

    idx = 0

    for val in b:
        if val == -1:
            if idx < len(active):
                # mark sequence as finished
                active[idx] = None
            idx += 1
        else:
            if idx == len(active):
                active.append(len(seqs))
                seqs.append([])
            seq_id = active[idx]
            seqs[seq_id].append(val)

    # filter out removed slots if any
    result = []
    for i in active:
        if i is not None:
            result.append(seqs[i])

    print(len(result))
    for s in result:
        print(len(s), *s)

if __name__ == "__main__":
    solve()
```コードは 2 つの構造を維持します。`seqs`、再構成されたシーケンスを保存します。`active`、現在のラウンド位置をシーケンス インデックスにマップします。 ポインタ`idx`現在どの列（ラウンド位置）を埋めているかを追跡します。 新しい値が到着し、その位置にシーケンスが存在しない場合、新しいシーケンスが作成されます。 

あ`-1`現在その列を占有しているシーケンスの終了をマークするため、それを無効にします。`active`。 これにより、後のラウンドが再度追加されることがなくなります。 

最後のフィルタリング ステップでは、早期に終了したシーケンスが削除され、有効な再構成されたシーケンスのみが印刷されることが保証されます。

 ## 特殊なケース

 すべての値が -1 である完全に空のシナリオは、各 -1 が個別のシーケンスの終了に対応するため、アルゴリズムが依然として複数の空のシーケンスを生成する必要があることを示しています。 

例えば：```
-1 -1 -1
```このアルゴリズムは、アクティブ列ポインタを -1 ごとにインクリメントし、シーケンス スロットを終了済みとしてマークします。 実際の値が追加されていない場合でも、3 つのシーケンスが再構築されます。 

もう 1 つのエッジ ケースは、シーケンスが異なる深さで終了する場合です。 で：```
1 2 -1 3 4
```最初のシーケンスは早期に終了しますが、2 番目のシーケンスは成長を続けます。 このアルゴリズムは、最初のシーケンスを削除した後も 2 番目のシーケンスを正しくアクティブに保ち、終了したシーケンスに値が誤って追加されないようにします。
