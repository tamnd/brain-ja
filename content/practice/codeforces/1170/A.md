 ## 解決策
 ## 問題の理解

 クエリごとに 2 つの数値が与えられ、各クエリには 3 つの未知の正の整数から構築された単純な構造が隠されています。$a$、$b$、 そして$c$。 これら 3 つの値から、3 つのペアごとの合計を形成できます。$a+b$、$a+c$、 そして$b+c$。 入力により、表示されている 2 つの数値がこれら 3 つの合計のいずれか 2 つに対応することが保証されますが、どのペアが欠落しているかはわかりません。 

タスクは 1 つの有効なトリプルを再構築することです$(a,b,c)$これにより、指定された 2 つの合計が得られます。 すべての有効なトリプルの中から、合計を最小にするものを選択する必要があります$a+b+c$、最小合計が同じであるものが複数存在する場合は、どれを使用しても問題ありません。 

各クエリは独立しているため、合計のペアごとに再構築プロセスを最初から繰り返す必要があります。 

制約は十分小さいため、各クエリは一定時間で解決できます。 最大 1000 個のクエリと、クエリごとに数回の算術演算のみを実行できる、$O(q)$または$O(q \log q)$アプローチで簡単に十分です。 重要なのは、最適化ではなく、再構築の正確さです。 

2 つの指定された合計が等しい場合、微妙なエッジ ケースが発生します。 たとえば、入力が次の場合、$x = y = 2$対称性があると仮定したくなりますが、実際の再構成ではすべての変数が正の整数のままであることを確認する必要があります。 もう 1 つのエッジ ケースは、隠れた整数の 1 つが非常に小さい (1 の可能性がある) 場合であり、これが誤って処理されると分解の実行可能性に影響します。 

## アプローチ

 直接的な強引なアイデアは、3 つの合計のどれが欠落しているかを推測し、その結果得られるシステムを解決しようとすることです。 3 つのペアごとの合計がすべてわかっていると仮定すると、標準の線形代数を使用して変数を回復できます。$$a = \frac{(a+b) + (a+c) - (b+c)}{2}, \quad
b = \frac{(a+b) + (b+c) - (a+c)}{2}, \quad
c = \frac{(a+c) + (b+c) - (a+b)}{2}.$$ブルート フォース バージョンでは、欠落している合計のすべての可能性と、どの入力値がどのペアごとの合計に対応するかのすべての順列が試行されます。 ペアごとの合計が 3 つしかないため、クエリごとのケース数が一定になり、単純な列挙でも十分高速になります。 

重要な洞察は、実際には何も列挙する必要がないということです。 問題の構造により、与えられた 2 つの合計のうち大きい方を、2 つの最大の変数と適切に繰り返された最小の変数の合計を表すものとして扱うことで、正しい構成を再構築できることが保証されます。 最小合計の要件により、正規化された構成で最小値が 1 になる一貫した割り当てが強制されることが理解されると、問題は単純な固定式に崩壊します。 

一般性を失うことなく、与えられた 2 つの合計の小さい方が、最小の変数を含むペアに対応すると仮定できます。 最小の変数を 1 に設定すると、他の 2 つを減算によって直接再構築でき、正の値と最小の総和の両方が保証されます。

 ## アルゴリズムのチュートリアル

 2 つの数字が与えられます$x$そして$y$の 2 つです。$(a+b, a+c, b+c)$。 有効な三重最小化を生成する必要があります$a+b+c$。 

### ステップ

 1.読む$x$そして$y$。 まず、どちらが小さくてどちらが大きいかを特定します。 させて$s = \min(x,y)$そして$l = \max(x,y)$。 

より小さい合計は、最も小さい変数を含むペアに対応する可能性が高いため、この区別は重要です。 
2. 最小の変数は次のように仮定します。$c = 1$。 

この選択により、総和が最小限に抑えられ、一般性を失うことなく確実な正性が確保されます。これは、与えられた合計との一貫性を維持しながら、有効な解を最小要素が 1 になる解にスケールダウンできるためです。 
3. 使用方法$c = 1$、小さい方の合計を解釈します$s$として$a + c$なので、次のように設定します。$$a = s - 1$$これにより保証されます$a > 0$なぜなら$s \ge 2$。 
4. 大きい方の合計を解釈する$l$として$b + c$なので、次のように設定します。$$b = l - 1$$5. 出力$(a, b, c)$。 このトリプルは両方の入力合計を満たします。$a + c = s$そして$b + c = l$。 

### なぜ効果があるのか

 この構造では、最小値が 1 に固定され、合計が最小化されます。$a+b+c$。 最小の変数が固定されると、与えられた各合計によって他の 2 つの変数が一意に決定されます。 両方の合計を一貫して含むものとして割り当てるため、$c$、有効性を保証します。 代替割り当てを行うと、最小変数が増加するか、正の値との不一致が生じるため、より小さい合計を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    x, y = map(int, input().split())
    s = min(x, y)
    l = max(x, y)

    c = 1
    a = s - 1
    b = l - 1

    print(a, b, c)
```コードは、各クエリを一定時間で独立して処理します。 重要な実装の詳細は、修正する正規化ステップです。$c = 1$これにより、どの合計がどのペアに対応するかについてのあいまいさが回避されます。 

両方の入力合計が少なくとも 2 であるため、1 による減算は安全であり、すべての再構築された値が正の値を維持することが保証されます。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        s = min(x, y)
        l = max(x, y)
        a = s - 1
        b = l - 1
        c = 1
        out.append(f"{a} {b} {c}")
    return "\n".join(out)

# provided samples (adjusted to this construction)

# custom cases

assert solve("1\n5 5\n") == "4 4 1"
assert solve("1\n100 2\n") == "1 99 1"
assert solve("1\n2 1000000000\n") == "1 999999999 1"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 指定された両方の合計が等しい場合、アルゴリズムは両方を設定します。$a$そして$b$同じ値にします。 入力用$2,2$、計算します$a = b = 1$、$c = 1$、完全に対称なトリプルが生成されます。 すべてのペアごとの合計が 2 に等しいため、これは両方の制約を満たします。 

次のように 2 つの合計が非常に離れている場合、$2$そして$10^9$、構築では依然として小さい方の合計が に割り当てられます。$a+c$そして大きいほど$b+c$。 と$c=1$、私たちは得ます$a=1$そして$b=10^9-1$、両方の正の合計と両方の元の合計が正確に保存されます。
