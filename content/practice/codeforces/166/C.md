 ## 解決策
 ## 問題の理解

 整数の配列とターゲット値から始めます`x`。 配列には任意の数の追加の整数を追加することができ、最終的な配列の中央値が正確になるようにしたいと考えています。`x`。 タスクは、それを実現するために必要な追加要素の最小数を計算することです。 

ここでの中央値の定義は、Codeforce の規則に従います。 配列をソートした後、中央値は位置の要素になります。`⌊(n + 1) / 2⌋`1 から始まるインデックスを使用します。 偶数の長さの配列の場合、これは左中央の要素が選択されることを意味します。 

制約が十分に小さいため、ソートを繰り返し行うことは完全に手頃な価格です。 元の配列の長さは最大でも`500`、追加された要素によってサイズがわずかに増加するだけです。 たとえ`O(n^2 log n)`解決策は快適に通過するでしょう。 課題はパフォーマンスではなく、どのような条件が生み出すのかを正確に理解することです`x`中央値と、最小限の挿入で中央値を達成する方法。 

最初の微妙なケースが現れるのは、`x`配列内にまったく存在しません。 

例：```
n = 3, x = 10
array = [20, 30, 40]
```答えはそうではありません`0`、たとえ位置を変えることはなんとなく想像できたとしても。 もし`10`が存在しない場合、中央値は決してなり得ません`10`中央値は並べ替え後の実際の配列要素でなければならないためです。 少なくとも 1 つを挿入する必要があります`10`。 

もう 1 つの簡単な間違いは、どの中間要素が均等な長さに使用されるかを誤解することによって発生します。 

例：```
n = 4, x = 4
array = [1, 4, 5, 6]
```ソート順は次のとおりです。```
[1, 4, 5, 6]
```中央位置は`⌊(4 + 1) / 2⌋ = 2`したがって、中央値は次のようになります。`4`、 ない`5`。 適切な中間要素を使用する不用意な実装は、間違った答えを生成する可能性があります。 

より微妙なエッジケースが発生するのは、`x`はすでに存在しますが、その前に小さな要素が多すぎます。 

例：```
n = 5, x = 4
array = [1, 2, 3, 4, 100]
```ソートされた配列は次のとおりです。```
[1, 2, 3, 4, 100]
```中央値は`3`、 ない`4`。 より小さい数値を挿入してもこれを修正することはできません。`4`、それは押すだけなので、`4`さらに右端。 有用な加算は以下の数値のみです。`4`、中央位置が発生する方向に移動します。`4`。 

逆のシナリオも重要です。 

例：```
n = 5, x = 10
array = [10, 20, 30, 40, 50]
```中央値はすでに`30`。 ここでは、大きな数値を入力しても役に立ちません。 中央位置を左に引っ張って着地させるには、より小さい数値が必要です。`10`。 

これらの方向性の効果は、ソリューションの背後にある重要な観察です。 

## アプローチ

 ここでは強引なアプローチが驚くほど自然です。 現在の中央値が以下に等しいかどうかを繰り返しテストできます。`x`。 そうでない場合は、慎重に選択した番号を 1 つ挿入して、再試行します。 

最も単純なバージョンは次のように動作します。 配列を並べ替えます。 中央値が以下の場合`x`、別のものを挿入します`x`。 中央値がより大きい場合`x`、別のものも挿入します`x`。 中央値になるまで続ける`x`。 

これは正しいです。`x`～の発生数が増加します`x`そして徐々に中央値をそれに向かって引き寄せます。 制約が小さいため、挿入のたびにソートを繰り返しても十分高速です。 

この強引なアイデアの弱点は、計算上のものではなく概念的なものです。 なぜプロセスが機能するのか、実際にどのような条件が成功を定義するのかについては説明されていません。 より明確な特徴付けが必要です。 

重要な観察は、並べ替え後に、次のような現象が発生することです。`x`中央の位置を占めなければなりません。 配列をソートして、最初に出現したものを確認するとします。`x`。 

その出現が中央位置の左側にある場合、それより大きい要素が多すぎます。`x`。 相対的に中央値インデックスを左にシフトするには、より小さい数値を追加する必要があります。`x`。 

その出現が中央位置の右側にある場合は、中央位置よりも小さい要素が多すぎます。`x`。 中央値インデックスを相対的に右にシフトするには、より大きな数値を追加する必要があります。`x`。 

これをよりクリーンに実装する方法はさらに簡単です。 挿入し続けます`x`中央値になるまでそれ自体`x`。 

なぜこれが機能するのでしょうか? 追加`x`小さい値と大きい値の間の相対的な順序を変更することはありません。 同じ値のブロックを増やすだけです。 最終的には、中央値インデックスがそのブロック内に収まる必要があります。 

最大でも数百の挿入が必要なため、ソートを繰り返してもまったく問題ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k · n log n) | O(n) | 承認済み |
 | 最適 | O(k · n log n) | O(n) | 承認済み |

 ここ、`k`挿入された要素の数です。 与えられた制約の下では、`k`小さいままです。 

## アルゴリズムのチュートリアル

 1. 配列を読み取り、次のコピーを 1 つ挿入します。`x`配列にそれがまだ含まれていない場合は、すぐに実行されます。 

中央値は実際の配列要素と等しくなければならないため、この手順は必須です。 
2. 配列をソートします。 

中央値は並べ替え順序のみに依存するため、すべてのチェックは並べ替え後に実行する必要があります。 
3. 中央値インデックスを次のように計算します。`(len(array) - 1) // 2`。 

これは、問題の定義のゼロベースのバージョンです。 
4.中央値要素が等しいかどうかを確認します`x`。 

そうなった場合は、すぐに中止してください。 必要な場合にのみ挿入したため、現在の挿入数は最小限です。 
5. 中央値が以下の場合`x`、別のものを追加`x`。 

これにより、要素の数が次の数以上増加します。`x`、中央値を押し上げます。 
6. 中央値が次の値より大きい場合`x`、別のものも追加します`x`。 

これにより、要素の数が以下のように増加します。`x`、中央値を押し下げます。 
7. 中央値が高くなるまで手順 2 から繰り返します。`x`。 

### なぜ効果があるのか

 挿入するたびに、次のコピーが追加されます`x`の連続ブロックを展開します。`x`ソートされた順序での値。 中央値の位置は配列が大きくなるにつれて変化しますが、ブロックの`x`価値観も高まります。 最終的に、中央値インデックスはそのブロック内に収まります。 

操作ごとにカウントが増加するため、`x`たった 1 回の操作だけで、中央値は次のようになります。`x`以前。 中央値が等しくなる最初の瞬間`x`必然的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
arr = list(map(int, input().split()))

added = 0

while True:
    arr.sort()

    median = arr[(len(arr) - 1) // 2]

    if median == x:
        print(added)
        break

    arr.append(x)
    added += 1
```基礎となる考え方がシンプルであるため、実装は意図的にコンパクトになっています。 

ループは常に配列をソートすることから始まります。 中央値はソート順に依存するため、ソート前にチェックしても意味がありません。 

中央値インデックスは以下を使用します。```
(len(arr) - 1) // 2
```これは、偶数の長さの問題の左中間の定義と一致します。 使用する`len(arr) // 2`正しい中間要素が誤って選択され、多くの場合失敗します。 

中央値がそうでない場合は常に`x`、別のものを追加します`x`。 中央値が小さすぎるか大きすぎるかを区別する必要はありません。 追加`x`等しい値のブロックを拡大するため、両方向に役立ちます。 

変数`added`挿入した数字の数を追跡します。 すべてのループ反復で値が 1 つだけ挿入されるため、最初に成功した状態は自動的に最小になります。
