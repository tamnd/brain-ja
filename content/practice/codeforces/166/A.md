 ## 解決策
 ## 問題の理解

 プログラミングコンテストの最終結果が届きました。 各チームには、解決した問題の数と合計ペナルティ時間という 2 つの値が関連付けられています。 

ランキング ルールは、標準の ICPC スタイルの順序付けです。 より多くの問題を解決したチームは、より高いランクにランクされます。 2 つのチームが同じ数の問題を解決した場合、ペナルティが小さいチームが上位にランクされます。 全く同じペアのチーム`(solved, penalty)`順位表で同じ順位を共有しています。 

タスクは、何チームが共有するかを決定することです。`k`- 位。 

重要な点は、入力がすでにランクによってソートされていることが保証されていないということです。 まずコンテストのルールに従って順位を再構築し、次にその位置に座っているチームを特定する必要があります。`k`, そして最後に、同じ結果になったチームが何チームあるかを数えます。 

制約は非常に小さいです。 チームの数は最大 50 なので、二次アルゴリズムでも十分に高速です。 50 個の要素は基本的に瞬時に処理されます。 これは、問題は最適化の圧力に関するものではなく、ランク付けルールを微妙な間違いなく正しく実装することにあることを意味します。 

最も一般的な間違いは、「k 位を共有する」の意味を誤解していることです。 問題は、現在インデックスに保存されているチームを要求していないことです`k`。 結果が同じチームを占めているすべてのチームを求めます。`k`ソート後の - 番目の位置。 

次の例を考えてみましょう。```
5 4
5 1
4 10
4 10
4 10
3 1
```ソート後の順位は次のようになります。```
1st: (5,1)
2nd-4th: (4,10)
5th: (3,1)
```4位は`(4,10)`グループなので、答えは`3`。 

不注意な実装では、正確なインデックスのみがチェックされる可能性があります`k-1`そして出力`1`。 

すべてのチームが同一である場合には、別の微妙なケースが発生します。```
4 2
3 20
3 20
3 20
3 20
```各チームは 1 から 4 までのすべての順位を共有します。正解は次のとおりです。`4`。 

一意のランクを手動で割り当てようとする不適切な実装により、誤って等しいチームが分離される可能性があります。 

また、Codeforces の位置は 1 からインデックス付けされているのに対し、Python リストは 0 からインデックス付けされているため、1 つずつずれてしまう可能性もあります。 もし`k = 1`、関連するチームがインデックスにあります`0`並べ替え後。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのチームを他のすべてのチームと比較し、ランキング グループを手動で決定できます。 各チームについて、厳密に優れているチームの数を数えて、どのチームが同じ順位グループに属しているかを特定できます。 

これが機能するのは、ランキング ルールがペアごとの比較によって完全に決定されるためです。 と`n ≤ 50`、たとえ`O(n²)`ソリューションは、最悪の場合でも 2500 回の比較のみを実行します。 

このアプローチの弱点は実行時間ではなく、実装の複雑さです。 ランクを手動で再構築すると、不必要な簿記が導入され、結合グループに関する特殊なケースが誤って処理されやすくなります。 

もっと明確な観察は、コンテストのランキングはまさに並べ替え順序であるということです。 チームの順序は次のとおりです。 

1. 最初に解決済みの数が大きくなります。 
2. 最初にペナルティを小さくします。 

チームが並べ替えられると、そのチームがインデックスに表示されます`k-1`のランクグループ全体を定義します。`k`- 位。 どのチームも同じ`(solved, penalty)`ペアはその場所を共有します。 

これにより、問題は 2 つの単純な操作に変わります。 

1. チームを正しく並べ替えます。 
2. その位置のチームと同じチームが何チームあるか数えます`k-1`。 

ランク付けルールの構造により、等しい結果がソート順に連続したブロックを形成するため、ソートは自然なソリューションになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n log n) | O(1) 並べ替えスペースを除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. チーム数を読む`n`そして目的の場所へ`k`。 
2. すべてのチームをペアとして保存します`(problems_solved, penalty)`。 
3. コンテストのランキングルールを使用してチームを並べ替えます。 

より多くの問題を解決したチームが最初に来る必要があるため、その値を降順に並べ替えます。 解決された数が等しい場合は、小さいペナルティが最初に来る必要があるため、ペナルティを昇順に並べ替えます。 
4. コンテストの順位を Python インデックスに変換します。 

コンテストの順位は 1 から始まるので、代表チームは`k`- 位はインデックスに格納されます`k-1`。 
5. ペアをインデックスに保存します`k-1`。 

このペアは、`k`- 位。 
6. ソートされたリストを調べて、まったく同じペアを持つチームが何チームあるかを数えます。 
7. カウントを出力します。 

### なぜ効果があるのか

 並べ替え後、順序付けは次の要素のみに依存するため、同じ結果を持つチームは隣接します。`(solved, penalty)`。 チームの位置`k-1`に関連する正確なパフォーマンスを表します。`k`- 位。 同じペアを持つすべてのチームは順位を共有し、異なるペアを持つすべてのチームは別のランキング グループに属します。 等しいペアを数えると正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

teams = []

for _ in range(n):
    p, t = map(int, input().split())
    teams.append((p, t))

teams.sort(key=lambda x: (-x[0], x[1]))

target = teams[k - 1]

answer = 0

for team in teams:
    if team == target:
        answer += 1

print(answer)
```最初のセクションは入力を読み取り、各チームをタプルとして保存します。 タプルを使用すると、等価性チェックが自動的かつ信頼性の高いものになるため便利です。 

並べ替え行はソリューションの中核です。```
teams.sort(key=lambda x: (-x[0], x[1]))
```マイナスサインオン`x[0]`解決された問題の降順を作成します。 ペナルティが小さいほど上位にランクされるはずなので、ペナルティはプラスのままです。 

並べ替えた後、`teams[k - 1]`に対応するパフォーマンスを識別します。`k`- 位。 Python はゼロベースのインデックスを使用するため、1 による減算が必要です。 

最後のループでは、そのタプルが出現するたびにカウントされます。 同点チームは両方の値が等しいことによって定義されるため、タプル比較はコンテスト ルールに完全に一致します。 

よくある実装上の間違いは、ペナルティを降順に並べ替えることです。 これでは、より大きなペナルティがより小さなペナルティよりも上位に誤ってランク付けされてしまいます。 

もう 1 つのよくある間違いは、インデックスの周囲で連続する同数のチームのみをカウントすることです。`k-1`。 これもソート後に等しいチームが連続しているため機能しますが、完全な走査の方が簡単でエラーが発生しにくくなります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())

    teams = []

    for _ in range(n):
        p, t = map(int, input().split())
        teams.append((p, t))

    teams.sort(key=lambda x: (-x[0], x[1]))

    target = teams[k - 1]

    print(sum(1 for team in teams if team == target))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

## 特殊なケース

 難しい状況の 1 つは、要求された場所が同点のグループの真ん中にある場合です。 

入力：```
5 4
5 1
4 10
4 10
4 10
3 1
```並べ替え後:```
(5,1)
(4,10)
(4,10)
(4,10)
(3,1)
```4位がインデックスに相当`3`、現在も所属しています`(4,10)`。 アルゴリズムはそのタプルをターゲットとして保存し、すべての同一のタプルをカウントし、`3`。 

もう 1 つの微妙なケースは、すべてのチームが同一である場合です。 

入力：```
4 2
3 20
3 20
3 20
3 20
```並べ替えても何も変わりません。 対象のタプルは`(3,20)`、どのチームもそれにマッチします。 アルゴリズムは正しく返します`4`。 

境界が 1 つずれているケースは、次の場合に発生します。`k = 1`。 

入力：```
3 1
5 10
4 1
3 1
```ソート後のターゲットはインデックスにあります`0`、つまり`(5,10)`。 一致するチームは 1 つだけなので、答えは次のとおりです。`1`。 

使用する`teams[k]`の代わりに`teams[k - 1]`誤って 2 位のチームを選択してしまう可能性があります。
