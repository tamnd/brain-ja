 ## 解決策
 ## 問題の理解

 当社には靴のコレクションがあり、すべての靴には独自のサイズと価格があります。 私たちにも顧客がいて、それぞれの顧客には予算や足のサイズがあります。 顧客は 2 つの条件が満たされる場合にのみ靴を購入できます。 

最初の条件は財務面です。靴の価格は顧客の予算を超えてはなりません。 

2 番目の条件はサイズの互換性です。靴のサイズが次の場合です。`s`の場合、お客様の足のサイズは次のいずれかである必要があります。`s`または`s - 1`。 つまり、顧客は自分のサイズとまったく同じサイズの靴を履くことも、1 サイズ大きい靴を履くこともできます。 

各靴は最大 1 回販売でき、各顧客が最大 1 足購入できます。 目標は、販売数を最大化することではなく、販売された靴からの総収益を最大化することです。 

制約によってソリューションが完全に形作られます。 両方`n`そして`m`到達できる`10^5`したがって、すべての顧客と靴の組み合わせをすぐに試すような解決策は不可能になります。 二次アルゴリズムには次のものが必要です`10^10`最悪の場合、制限時間を大幅に超えて操作が行われる可能性があります。 に近いものが必要です`O(n log n)`または`O((n + m) log n)`。 

独特の靴のサイズは非常に強力な構造上の特性です。 すべてのサイズが靴に現れるのは多くても 1 つだけであるため、各顧客が対応できる靴のサイズは最大 2 つです。 これにより、マッチング構造が大幅に簡素化され、問題は一般的な 2 部マッチングよりもはるかに管理しやすいものになります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次の入力を考えてみましょう。```
2
100 5
1 6
1
100 5
```正解は、最初の靴を売って利益を上げることです`100`。 

靴を任意の順序で処理する不用意な欲張りな戦略は、顧客がサイズを履くこともできるため、安い靴を最初に販売する可能性があります。`6`。 それは高価な販売を阻止し、利益をもたらします`1`の代わりに`100`。 

もう 1 つの微妙なケースは、2 人の顧客が同じ靴を購入できるが、そのうちの 1 人だけが代替品を持っている場合です。```
2
50 10
40 11
2
50 10
50 11
```最適な解決策は次のとおりです。```
90
2
1 1
2 2
```欲張ってサイズを割り当てると`10`靴からお客様へ`2`、次に顧客`1`比類のないものとなり、総利益は`50`。 

地元で高価なセールを選択すると、将来の 2 つのセールが妨げられるという危険なケースもあります。```
3
100 5
99 6
98 7
2
100 5
99 6
```正しい答えは、`199`、靴を売ることで`5`そして`6`。 

常に最高価格の靴を優先する貪欲なアルゴリズムが靴を奪う可能性がある`7`顧客のために`2`、サイズなので`6`お客様もサイズを着用できます`7`。 それから靴`6`売れなくなって結果は`198`。 

根本的に問題は、全体の価値を最大化しながら、柔軟性を慎重に維持することです。 

## アプローチ

 最も直接的な定式化は二部マッチングです。 片面には顧客が、もう片面には靴が入っています。 顧客が靴を購入できるときにエッジを追加します。 すべての顧客が関連付けられる靴のサイズは最大 2 つであるため、グラフはまばらになります。 

ブルート フォース ソリューションでは、グラフ全体を構築し、重み付けされたマッチング アルゴリズムを実行できます。 マッチングでは靴の価格の合計が最大化する必要があります。 ここでは、一般的な重み付き 2 部マッチングはコストが高すぎます。 考えられるすべてのペアを単純に構築するだけでも時間がかかります`O(nm)`操作。 

重要な点は、靴のサイズはそれぞれ異なるということです。 適切なサイズの靴`s`足のサイズがあるお客様のみご購入いただけます`s`または`s - 1`。 

つまり、すべての靴は 2 つの顧客グループのみとやり取りします。 

これにより、サイズがソートされた順序で処理されるときに、グラフがチェーンのような構造に変換されます。 依存関係はグローバルではなくローカルになります。 

靴をサイズごとに分類するとします。 靴のサイズを調べると`s`、サイズのお客様のみ`s`そして`s - 1`案件。 これからの靴は大きいサイズになるので、サイズのあるお客様`s - 1`サイズの後に将来の機会はない`s`。 このような顧客の割り当てを今スキップすると、その顧客を永久に失うことになります。 

これは当然、ソートされたサイズに対する動的プログラミングを示唆しています。 

すべてのサイズポジションについて、以前の靴が現在のサイズの顧客をすでに消費したかどうかを知る必要があるだけです。 相互作用は隣接するサイズ間でのみ発生するため、この小さな状態で十分です。 

DP は以下を行うかどうかを決定します。 

1. 現在の靴をスキップします。 
2.同じサイズの顧客に販売します。 
3. 1つ小さいサイズのお客様に販売します。 

これらの移行を効率的に行うために、靴のサイズごとに、サイズが一致する最適な顧客を前処理します。 

結果として得られるアルゴリズムは次のように実行されます。`O((n + m) log n)`仕分けと優先処理のため。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースマッチング | O((n + m)^3) 以上 | O(nm) | 遅すぎる |
 | ソートされたサイズの DP | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての靴を読んで保管してください`(size, price, index)`。 
2. すべての顧客を読み取り、足のサイズごとにグループ化します。 

足のサイズごとに、顧客を予算別に降順に並べ替えます。 最初に必要なのは、残っている最も裕福な顧客だけです。 

1. 靴をサイズごとに分類します。 

互換性には等しいサイズか 1 つ小さいサイズのみが含まれるため、サイズを順番に処理すると、すべての依存関係がローカルになります。 

1. すべての靴について、2 人の顧客候補を事前計算します。 

最初の候補は、足のサイズが靴のサイズと等しい最も裕福な未使用の顧客です。 

2 番目の候補は、足のサイズが 1 つ小さい、最も裕福な未使用の顧客です。 

顧客が靴を買う余裕がない場合、その靴は廃棄されます。 

1. DP 状態を定義します。 

させて`dp[i][t]`最初の処理後の最大利益になる`i`靴。 

旗`t`現在の靴のサイズの最良の顧客がすでに前の靴で消費されているかどうかを示します。 

相互作用するサイズは隣接する靴のサイズだけであるため、この状態で十分です。 

1. シューズをスキップして移行します。 

現在の靴を無視して、前の答えを引き継ぐこともできます。 

1. 同規模の顧客への販売による移行。 

同じサイズの利用可能な顧客が存在する場合は、靴の価格を追加して次の状態に進みます。 

1. 小規模顧客への販売による移行。 

ある程度のサイズのお客様の場合`s - 1`が存在し、前の靴によってまだ消費されていない場合は、それらを使用できます。 

1. 親ポインタを保存します。 

マッチングを再構築するには、以前の状態と実行されたアクションを保持します。 

1. DP 状態を遡って、選択した割り当てを再構築します。 
2. 合計利益と選択した顧客と靴のペアを出力します。 

### なぜ効果があるのか

 重要な不変条件は、サイズの増加順に靴を処理する場合、現在のサイズとそのすぐ下のサイズの顧客のみが現在の靴を操作できるということです。 

サイズの大きなお客様`s - 1`サイズの後に将来の機会はない`s`、後の靴はさらに大きくなるからです。 つまり、そのような顧客に関するあらゆる決定は直ちに最終的なものになります。 

DP 状態は、前方に伝播する可能性がある唯一の曖昧性、つまり現在のサイズの顧客が以前の靴で既に使用されていたかどうかを正確に捉えます。 より大きな依存関係は存在しません。 

すべての移行では、最適な下部構造を維持しながら、現在の靴のすべての法的可能性が考慮されるため、DP はすべての最適なマッチングを暗黙的に探索します。 再構成ステップは、最適な値を生成した選択に従うだけです。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

INF = 10**30

def solve():
    n = int(input())

    shoes = []
    for i in range(n):
        c, s = map(int, input().split())
        shoes.append((s, c, i + 1))

    m = int(input())

    customers_by_size = defaultdict(list)

    for i in range(m):
        d, l = map(int, input().split())
        customers_by_size[l].append((d, i + 1))

    for l in customers_by_size:
        customers_by_size[l].sort(reverse=True)

    shoes.sort()

    ptr = defaultdict(int)

    same_customer = [None] * n
    prev_customer = [None] * n

    for i, (s, c, idx) in enumerate(shoes):
        arr = customers_by_size[s]

        while ptr[s] < len(arr) and arr[ptr[s]][0] < c:
            ptr[s] += 1

        if ptr[s] < len(arr):
            same_customer[i] = arr[ptr[s]]

        arr2 = customers_by_size[s - 1]

        while ptr[s - 1] < len(arr2) and arr2[ptr[s - 1]][0] < c:
            ptr[s - 1] += 1

        if ptr[s - 1] < len(arr2):
            prev_customer[i] = arr2[ptr[s - 1]]

    dp = [[-INF] * 2 for _ in range(n + 1)]
    parent = [[None] * 2 for _ in range(n + 1)]

    dp[0][0] = 0

    for i in range(n):
        s, c, shoe_idx = shoes[i]

        for used in range(2):
            if dp[i][used] < 0:
                continue

            # skip
            if dp[i][used] > dp[i + 1][0]:
                dp[i + 1][0] = dp[i][used]
                parent[i + 1][0] = (i, used, 0, None)

            # use same size customer
            if same_customer[i] is not None:
                val = dp[i][used] + c

                nxt = 1

                if val > dp[i + 1][nxt]:
                    dp[i + 1][nxt] = val
                    parent[i + 1][nxt] = (
                        i,
                        used,
                        1,
                        same_customer[i][1],
                    )

            # use smaller size customer
            if used == 0 and prev_customer[i] is not None:
                val = dp[i][used] + c

                if val > dp[i + 1][0]:
                    dp[i + 1][0] = val
                    parent[i + 1][0] = (
                        i,
                        used,
                        2,
                        prev_customer[i][1],
                    )

    if dp[n][0] >= dp[n][1]:
        state = 0
    else:
        state = 1

    best = dp[n][state]

    ans = []

    cur_i = n
    cur_state = state

    while cur_i > 0:
        p_i, p_state, action, customer_id = parent[cur_i][cur_state]

        if action == 1 or action == 2:
            shoe_idx = shoes[cur_i - 1][2]
            ans.append((customer_id, shoe_idx))

        cur_i = p_i
        cur_state = p_state

    ans.reverse()

    print(best)
    print(len(ans))

    for x, y in ans:
        print(x, y)

solve()
```このソリューションは、足のサイズに応じて顧客をグループ化することから始まります。 サイズごとに、顧客は予算の降順に並べ替えられます。 これにより、靴の買い手を探すとき、最初の有効な顧客が常に最も役に立つことが保証されます。 

前処理段階では、すべての靴に対して最適な同じサイズおよびそれより小さいサイズの候補が計算されます。 サイズは靴によって異なるため、これらの候補の関係は局所的なものになります。 

DP テーブルには、位置ごとに 2 つの状態しかありません。 これがソリューションを効率化する核となる圧縮です。 ブール状態は、現在のサイズ グループが前の靴によってすでに使用されているかどうかを記録します。 

移行ロジックは排他性を慎重に保持します。 の`used == 0`小規模な顧客を割り当てる場合、この条件は重要です。 これがないと、同じ顧客グループが隣接する靴間で誤って再利用される可能性があります。 

再構成フェーズでは、保存されている親ポインタを最適な最終状態から逆方向にたどります。 各アクションは、どの顧客がどの靴を購入したかを正確に記録します。 

すべての利益の計算では、可能な最大合計値を安全に処理する通常の Python 整数が使用されます。

# helper: run solution on input string, return output string

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    from collections import defaultdict

    input = sys.stdin.readline
    INF = 10**30

    out = io.StringIO()
    sys.stdout = out

    n = int(input())

    shoes = []
    for i in range(n):
        c, s = map(int, input().split())
        shoes.append((s, c, i + 1))

    m = int(input())

    customers_by_size = defaultdict(list)

    for i in range(m):
        d, l = map(int, input().split())
        customers_by_size[l].append((d, i + 1))

    for l in customers_by_size:
        customers_by_size[l].sort(reverse=True)

    shoes.sort()

    ptr = defaultdict(int)

    same_customer = [None] * n
    prev_customer = [None] * n

    for i, (s, c, idx) in enumerate(shoes):
        arr = customers_by_size[s]

        while ptr[s] < len(arr) and arr[ptr[s]][0] < c:
            ptr[s] += 1

        if ptr[s] < len(arr):
            same_customer[i] = arr[ptr[s]]

        arr2 = customers_by_size[s - 1]

        while ptr[s - 1] < len(arr2) and arr2[ptr[s - 1]][0] < c:
            ptr[s - 1] += 1

        if ptr[s - 1] < len(arr2):
            prev_customer[i] = arr2[ptr[s - 1]]

    dp = [[-INF] * 2 for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        s, c, idx = shoes[i]

        for used in range(2):
            if dp[i][used] < 0:
                continue

            dp[i + 1][0] = max(dp[i + 1][0], dp[i][used])

            if same_customer[i] is not None:
                dp[i + 1][1] = max(
                    dp[i + 1][1],
                    dp[i][used] + c
                )

            if used == 0 and prev_customer[i] is not None:
                dp[i + 1][0] = max(
                    dp[i + 1][0],
                    dp[i][used] + c
                )

    best = max(dp[n])

    return str(best).strip()
