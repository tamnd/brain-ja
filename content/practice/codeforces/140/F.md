 ## 解決策
 ## 問題の理解

 対称的な雪の結晶の一部が溶けた後に残った結晶を表す、平面上の一連の点が与えられます。 もともと、結晶の完全なセットは中心対称性を持っていました。つまり、ある点が存在していました。$C$すべてのクリスタルに対して$P$、反射した点$C$、つまり$2C - P$、もクリスタルでした。 結晶はまさに中心自体に存在する場合があります。 

一部のクリスタルは消えましたが、せいぜい$k$彼らのうちは消えた。 生き残ったポイントはすべて異なります。 私たちの仕事は、元の対称中心の可能なすべての位置を回復することです。 

候補中心は、最大でも追加できる場合に有効です。$k$欠落している点を修正して、結果のセットがその中心を中心に対称になるようにします。 

入力サイズによってソリューションが完全に決まります。 いくらでもあるかもしれません$2 \cdot 10^5$したがって、すべての点のペアを明示的にチェックし、それらを個別に検証するアルゴリズムは不可能です。 平$O(n^2)$すでに周りを意味します$4 \cdot 10^{10}$操作。 同時に、$k$この非対称性が問題の核心です。ほぼすべての点が対称性の下ですでに正しく一致している必要があります。 

最も危険なエッジケースは、多くのセンターが表面的にもっともらしいと思われる状況から発生します。 

次の 1 つの点を考えてみましょう。```
1 0
5 7
```1 つの生き残ったポイントは常に 1 つの欠けているポイントとペアになる可能性があるため、すべてのセンターが機能します。 無限に多くの答えが存在するため、正しい出力は次のようになります。```
-1
```既存の点のペアから中心を生成するだけの不注意な実装では、これを見逃してしまいます。 

もう 1 つの注意が必要なケースは、いくつかの点がすでに対称構造を形成しているが、一致しない点がいくつか残っている場合です。```
3 1
0 0
2 0
10 0
```センター$(1,0)$有効です。 ポイント$(0,0)$そして$(2,0)$お互いに一致しながら、$(10,0)$不足している点が必要になります$(-8,0)$。 欠落点は 1 つだけ許容されます。 

現在すべてのポイントにパートナーがあるわけではないため、単純な実装ではこれを誤って拒否する可能性があります。 

重複した候補中心もバグの原因となります。 仮定する：```
4 0
0 0
0 2
2 0
2 2
```すべての反対のペアは同じ中心を生成します$(1,1)$。 浮動小数点比較では、座標が正確に表現されていない限り、誤って重複が出力される可能性があります。 

無限回答条件も微妙です。$n \le 2k$。 すべての不一致を個別に修復するのに十分な点を削除または追加できる場合、どの中心も実行可能になります。 例えば：```
2 1
0 0
10 0
```任意の中心を選択してください$C$。 存在する各点は、対称的な対応する点が溶けたと単純に主張できます。 両方の点が一致しない可能性があるため、$k=1$、無限に多くの中心が存在します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての有効な中心は、2 つの生き残った点の中点であるか、生き残った点自体を通過する必要があります。 すべて列挙できます$O(n^2)$次に、各候補について、対称の対応物を見つけることができなかった点の数を確認します。 

検証自体は次のように行うことができます$O(n)$ポイントのハッシュセットを使用します。 センターの場合$C$、各点$P$それが必要です$2C-P$存在しない場合、そのパートナーは溶けた結晶の中に数えられる必要があります。 

問題は候補者の数だ。 がある$O(n^2)$明確な中間点と各テイクの検証$O(n)$、につながる$O(n^3)$時間。 すべての候補を保存することさえすでに不可能です$n=2 \cdot 10^5$。 

重要な観察は、次の小さな値から得られます。$k$。 せいぜい$k$ポイントが欠落している場合、ほぼすべての生き残ったポイントには、生き残ったセット内に反映されたパートナーがすでに存在している必要があります。 

有効な中心を修正する$C$。 反射が通過した場合、そのポイントは不良と呼ばれます。$C$は生き残ったセットには存在しません。 失われたすべてのクリスタルは、せいぜい 1 つの悪い生存点を説明できます。 せいぜい$k$結晶が溶けた、せいぜい$k$悪い点。 

つまり、少なくとも$n-k$ポイントは良好であり、すべての良好なポイントが生き残った対称ペアに参加します。 そのようなペアごとに$(P,Q)$、中心はそれらの中点に等しくなります。 

次に、任意の生存点を選択します。$A$。 もし$A$それが良好な場合、それを反映されたパートナーと組み合わせると、すぐに真の中心が明らかになります。 もし$A$悪いので、破棄して別のポイントを試してください。 せいぜいあるので$k$悪い点の中でも特に$k+1$少なくとも 1 つは優れている必要があります。 

これにより、検索が大幅に減少します。 少数のアンカー ポイントと他のすべてのポイントの間に形成された中間点を調べるだけで済みます。 具体的には、最初のものを取ると、$k+1$ポイントは、少なくとも 1 つのアンカーが真の対称ペアに参加していることを保証します。 各アンカーは最大でも$n$候補者中心なので、候補者の総数は次のようになります。$O(kn)$、これは管理可能です。$k \le 10$。 

その後、各候補を線形時間で検証できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(k n^2)$最悪の場合、実際には非常に小さい$k$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを読み取り、それらをハッシュ セットに保存します。$O(1)$会員チェック。 
2. かどうかを確認します。$n \le 2k$。 

この状況では、無限に多くの中心が存在します。 生き残ったすべてのポイントは単純に不一致として扱われ、各不一致ポイントは不足しているクリスタルを 1 つだけ消費します。 せいぜい$2k$ポイントが存在する場合、どのセンターも最大で次の使用量を使用して修復できます。$k$ペアが欠けています。 
3. 最初の項目を選択します$\min(n, k+1)$ポイントをアンカーポイントとして使用します。 

せいぜい$k$有効な中心に対してポイントが不適切であるため、少なくとも 1 つのアンカー ポイントが適切である必要があります。 
4. アンカーポイントごとに$A$、あらゆるポイントとペアリングします$B$セットで。 

それらの中点が中心候補になります。$$C = \frac{A+B}{2}$$浮動小数点の精度の問題を回避するには、2 倍の中心を保存します。$$D = (A_x + B_x,\ A_y + B_y)$$を表す$2C$。 
5. セットを使用して候補中心を重複排除します。 

多くの異なるペアが同じ中間点を生成します。 
6. 各候補センターを検証します。 

あらゆる点について$P=(x,y)$、その反射点を計算します。$$P' = D - P$$ここで、減算は座標的に行われます。 

もし$P'$点セットに存在しない場合は、一致しない点の数を増やします。 
7. 一致しないポイントの数が最大でも次の場合、候補者を受け入れます。$k$。 

一致しない各生存点は 1 つの溶融結晶に対応します。 
8. 受け入れられたすべてのセンターを出力します。 

2倍の座標を保存したので、印刷時に2で割ります。 

### なぜ効果があるのか

 有効なセンターの場合、最大でも$k$生き残ったポイントには、生き残った反映されたパートナーが欠けています。 1 つおきの点は、中点が中心に等しい生き残った対称ペアに属します。 

最初のものの中には$k+1$アンカーポイント、少なくとも 1 つは悪いものであってはなりません。 その優れたアンカーは生き残った対称ペアに参加するため、それを反映された対応するペアとペアにすることで、候補の列挙中に真の中心が生成されます。 

ポイントは、反映されたパートナーが存在しない場合に正確に不一致カウントに寄与するため、検証は正確です。 欠落している各クリスタルは、一致しない生存ポイントを 1 つだけ説明できるため、候補は一致しない数が以下を超えない場合に限り実現可能です。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    pts = [tuple(map(int, input().split())) for _ in range(n)]
    st = set(pts)

    if n <= 2 * k:
        print(-1)
        return

    anchors = pts[:min(n, k + 1)]

    candidates = set()

    for ax, ay in anchors:
        for bx, by in pts:
            candidates.add((ax + bx, ay + by))

    ans = []

    for dx, dy in candidates:
        bad = 0

        for x, y in pts:
            rx = dx - x
            ry = dy - y

            if (rx, ry) not in st:
                bad += 1
                if bad > k:
                    break

        if bad <= k:
            ans.append((dx, dy))

    print(len(ans))

    for dx, dy in ans:
        print(dx / 2.0, dy / 2.0)

if __name__ == "__main__":
    solve()
```最初の重要な詳細は、無限回答条件です。 もし$n \le 2k$、すべての生き残ったポイントは一致しないままになる可能性があり、各一致しないポイントは 1 つの不足している反射パートナーのみを必要とします。 幾何学的制限が残っていないため、無限に多くの中心が可能です。 

この実装では、浮動小数点座標の代わりに 2 倍の中心が格納されます。 中点計算によって生成された中心には、半分が含まれる場合があります。たとえば、$(0.5, 1.5)$。 それを次のように表すと、$(1,3)$精度エラーを回避し、ハッシュの信頼性を高めます。 

候補生成では最初のもののみが使用されます$k+1$アンカーとしてのポイント。 これは重要な最適化です。 有効なセンターは、これらすべてのアンカーを同時に不良にすることはできません。$k$悪い点の合計。 

検証中に、$(x,y)$中央を2倍にしたあたり$(dx,dy)$単純に$(dx-x,\ dy-y)$。 すべての算術演算は整数のままです。 

早めの休憩のとき、`bad > k`パフォーマンスにとって重要です。 通常、無効な候補はすぐに失敗するため、実際の実行時間は理論上の上限よりも大幅に短くなります。

 ## 特殊なケース

 無限の答えがある状況をもう一度考えてみましょう。```
1 0
5 7
```アルゴリズムはすぐに次のことをチェックします。$n \le 2k$。 ここ$1 \le 0$は誤りなので続行します。 候補の生成では、無限に多くの概念的中心が生成されますが、検証では、すべての中心に 1 つの欠落点が必要であることが示されています。 以来$k=0$、それ自体にポイントを置く中心だけが生き残ります。 生成された候補は単一の中心に正しく折りたたまれます。$(5,7)$。 

次に、次のことを調べます。```
2 1
0 0
10 0
```この時$2 \le 2$、アルゴリズムは次のように出力します`-1`。 両方の点に反映されたパートナーが単に欠けている可能性があるため、どの中心でも可能です。 

もう 1 つの微妙なケースは、中心が既存の点上にある場合です。```
3 0
-1 0
0 0
1 0
```有効なセンターは$(0,0)$。 検証時のポイントは、$(0,0)$セット内に存在するそれ自体に反映されます。 自己反映に特殊なロジックが必要ないため、アルゴリズムはこれを自然に処理します。 

最後に、重複した中間点の生成を検討します。```

0 0
2 0
0 2
2 2
```いくつかのペアが二重中心を生成します$(2,2)$。 候補セットはそれらを自動的に重複排除するため、検証は 1 回実行され、答えは 1 回表示されます。
