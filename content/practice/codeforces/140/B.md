 ## 問題の理解

 アレクサンダーは友達からカードを一枚ずつ受け取ります。 友達`i`カードを送る`i`, したがって、カード番号とフレンド番号は同じものです。 アレクサンダーはいつでも、何人かの友人にカードを送ることを決めるかもしれません。 彼は新しいカードを作成することはなく、すでに受け取ったカードを再利用するだけです。 

アレクサンダーが友人にカードを送るとき`i`、2 つのルールが適用されます。 彼はカードを送ることができない`i`その友人に話を戻し、彼が現在所有している残りのカードの中で、彼は常に個人的に最も好きなカードを選びます。 

各友達には独自のカードのランキングもあります。 私たちは、すべての友人がアレクサンダーの行動の下で手に入れることができる最高のカードを受け取ってほしいと考えています。 アレクサンダーの選択は強制されるため、私たちの仕事はカードを直接選択することではありません。 代わりに、各友人がカードを受け取る瞬間を選択します。 出力では、これらの瞬間を圧縮形式で要求します: すべての友人に対して`i`、友達を印刷してください`k`アレクサンダーがカードを送るように`i`カード受け取り直後`k`。 

制約は十分に小さいため、かなり直接的なシミュレーションが可能です。`n`せいぜい`300`なので、三次アルゴリズムでも問題ありません。 アン`O(n^3)`ソリューションは周囲で実行されます`27 million`Python では 2 秒の制限内で快適です。 これは、高度なグラフ アルゴリズムやフロー技術が必要ないことを意味します。 課題は、プロセスの構造を理解し、貪欲な構築が有効であることを証明することです。 

素朴な推論を簡単に打ち破る微妙なケースがいくつかあります。 

よくある間違いの 1 つは、各友達が自分のカードを除くすべてのカードの中からお気に入りのカードを受け取るべきだと思い込むことです。 これは、Alexander の好みやカードの利用可能性を無視しています。 

考慮する：```
n = 3

Friend 1: 2 3 1
Friend 2: 1 3 2
Friend 3: 1 2 3

Alexander: 3 2 1
```友人 1 はカードを気に入るはずです`2`、しかしアレクサンダーはカードを好みます`3`もっと。 ワンスカード`3`が利用可能になった場合、アレクサンダーは代わりにそれを送信する必要があります`2`。 したがって、利用可能なカードの最終セットよりもタイミングが重要です。 

もう 1 つの簡単なバグは、時間の経過とともにカードが出現することを忘れることです。```
n = 3

Friend 1: 3 2 1
Friend 2: 3 1 2
Friend 3: 1 2 3

Alexander: 3 1 2
```友達`1`そして`2`どちらもカードが欲しい`3`ただし、アレクサンダーがカードを取得するまでは誰もそれを受け取ることはできません`3`友人から`3`。 到着時間を考慮せずにランキングのみを考慮したソリューションでは、不可能なスケジュールが生成されます。 

3 番目のトラップは、すべての送信操作が個別の瞬間に発生する必要があることを前提としています。 この声明では、Alexander が同じカードを受け取った直後に複数の友人にカードを送信することを明示的に許可しています。 多くの友人が同時に同じカードを最適に受け取る可能性があるため、これは重要です。 

例えば：```
n = 4

Alexander: 4 3 2 1
```イフカード`4`複数の友達が利用可能で有効ですが、友達になった直後に全員が受け取ることができます。`4`カードを送ります。 

## アプローチ

 強引なアイデアは、カードの送受信のあらゆるスケジュールをシミュレートすることです。 カードを受け取るたびに、アレクサンダーは満足していない友人のサブセットにカードを送信できます。 友人ごとに、最終的にどのカードを受け取るかをテストし、最適なスケジュールを保つことができます。 

これはすぐに不可能になります。 それぞれの後でさえ、`n`イベントを受信すると、どの友達を処理するかについての選択肢が飛躍的に増えます。 スケジュールの総数は、管理できる範囲をはるかに超えて爆発的に増加します。 

重要な観察は、現在利用可能なカードがわかれば、アレクサンダーの行動は完全に決定的であるということです。 

アレクサンダーがすでにいくつかのカードのセットを受け取っていると仮定します。 友人のために`i`, アレクサンダーは、自分自身の優先順位を最良から最悪までスキャンし、そうでない最初の利用可能なカードを選びます。`i`。 

だから、すべての友人にとって`i`、受け取ったカードは、アレクサンダーが現在所有しているカードのセットにのみ依存します。 

次に、実際にどのようなセットが可能であるかを考えてみましょう。 カード受け取り後`1...k`, アレクサンダーはまさにそれらのカードを所有しています。 他の状態は発生しません。 これは、プロセスには次のものしかないことを意味します。`n`意味のある瞬間:```
after receiving 1
after receiving 2
...
after receiving n
```友人ごと、プレフィックスごとに`1...k`、その瞬間にアレクサンダーがどのカードを送るかを計算できます。 

これらすべての瞬間の中から、友人の好みリストに従って最高ランクのカードを友人に与える瞬間を選択します。 

これにより、問題はプレフィックスに対する純粋な総当り攻撃に変わります。 

友人のために`i`そして時間`k`:```
available cards = {1,2,...,k}
chosen card = highest-ranked available card in Alexander's order, excluding i
```次に、可能なすべてを比較します`k`そして友人にとって最良の結果を選択してください`i`。 

総当り攻撃が可能になるのは、`n^2`状態を評価し、各状態を評価するには最大で`O(n)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 徹底したスケジュール検索 | 指数 | 指数 | 遅すぎる |
 | プレフィックスシミュレーション | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての友人の好みの順列を読み取ります。 
2. Alexander の好みの順列を読み取ります。 
3. すべての友人の位置テーブルを作成します。`rank[i][x]`友達をどれくらい保存するか`i`いいねカード`x`。 値が小さいほど、より優れたカードを意味します。 
4. プレフィックス長ごとに`k`から`1`に`n`、アレクサンダーがカードを受け取った直後にカードを送った場合、各友人にどのカードを送るかを決定します。`k`。 

現時点ではアレクサンダーがカードを所有しています`1...k`。 
5. 友達に送ったカードを決定する`i`、アレクサンダーの優先順位を最高から最低までスキャンします。 

両方の条件を満たす最初のカードが選択されます。`card <= k`、カードがすでに利用可能であることを意味します。`card != i`, なぜなら、アレクサンダーは友人自身のカードを返すことができないからです。 
6. この候補カードを、友人用にすでに見つかった最良のカードと比較します。`i`。 

友達のランキング表を使用して、どのカードがより好ましいかを決定します。 
7. 新しいカードの方が優れている場合は、次のものを保管します。 

カード自体、

 そしてその瞬間`k`それが実現可能になったとき。 
8. すべてのプレフィックスを処理した後、すべての友人に対して選択した瞬間を出力します。 

### なぜ効果があるのか

 カード受け取り後いつでも`k`、利用可能なカードは正確に`{1,2,...,k}`。 アレクサンダーは常にお気に入りの有効なカードを選択するため、それらのカードの中からの選択は決定的です。 

したがって、友人に対するすべての実現可能な結果は、正確に 1 つのプレフィックス長に対応します。`k`。 私たちのアルゴリズムは、そのようなプレフィックスをすべて明示的にチェックします。 

友人ごとに、その友人の好みに応じて、達成可能な最高のカードを保持します。 考えられるすべての送信瞬間が検査されるため、検索以外にはこれ以上の結果は存在しません。 したがって、保存されたプレフィックスは最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    prefs = [list(map(int, input().split())) for _ in range(n)]
    alex = list(map(int, input().split()))

    rank = [[0] * (n + 1) for _ in range(n)]

    for i in range(n):
        for pos, card in enumerate(prefs[i]):
            rank[i][card] = pos

    best_card = [-1] * n
    answer = [1] * n

    for k in range(1, n + 1):

        for i in range(n):

            chosen = -1

            for card in alex:
                if card <= k and card != i + 1:
                    chosen = card
                    break

            if best_card[i] == -1 or rank[i][chosen] < rank[i][best_card[i]]:
                best_card[i] = chosen
                answer[i] = k

    print(*answer)

solve()
```最初の部分は順列を読み取って構築します`rank`。 優先リスト内を繰り返し検索する代わりに、位置を事前に計算します。 これにより、「友達はいますか？」というような比較になります。`i`カードを好む`a`またはカード`b`？」 定時間演算に移行します。 

外側のループはすべてのプレフィックスを反復します。`1...k`。 それはアレクサンダーがカードを受け取った後の瞬間を直接表しています`k`。 

すべての友人に対して、私たちはアレクサンダーの強制された選択をシミュレートします。 Alexander は以前のカードの方が好むため、Alexander の好みの順列を左から右にスキャンします。 友人自身のカードではない、最初に利用可能なカードが、まさにアレクサンダーが送るものになります。 

比較```
rank[i][chosen] < rank[i][best_card[i]]
```友人が新しい候補者をより強く好むかどうかを確認します。 

細かい点の 1 つはインデックスです。 友達は 0 から始まるインデックスを使用して配列に保存されますが、カード番号は 1 から始まります。 条件```
card != i + 1
```この変換は慎重に処理します。 

もう 1 つの微妙な点は、瞬間を保存することです。`k`、カード自体ではありません。 出力形式では、送信する前にカードを受け取ったばかりの友人を尋ねます。
