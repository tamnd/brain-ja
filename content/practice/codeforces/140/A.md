 ## 問題の理解

 半径のある大きな円形テーブルがあります`R`そして置きたい`n`それぞれ半径のある同一の円形プレート`r`。 

すべてのプレートは 3 つの条件を同時に満たさなければなりません。 

まず、プレート全体がテーブル内に収まるようにする必要があります。 

次に、すべてのプレートがテーブルの境界に触れなければなりません。 

第三に、接触は許可されますが、2 つのプレートを重ねてはなりません。 

タスクは、そのような取り決めが存在するかどうかを判断するだけです。 

制約はわずかです。 すべての値は最大 1000 で、テスト ケースは 1 つだけです。 これにより、課題は最適化ではなく、正しい幾何学的条件を導き出すことであることがすぐにわかります。 定数時間から二次時間までのアルゴリズムは、制限内に問題なく収まります。 本当に難しいのは、間違ったジオメトリ推論を回避し、特殊なケースをきれいに処理することです。 

最も危険なエッジケースは、次の小さな値から発生します。`n`。 

次の入力を考えてみましょう。```
1 5 10
```正しい答えは次のとおりです。```
NO
```1 枚のプレートがテーブル内に収まる必要があります。 プレート半径がテーブル半径を超えているため、配置できません。 プレート間の間隔をチェックするだけの不注意なソリューションでは、衝突する他のプレートがないため、このケースが誤って受け入れられる可能性があります。 

次に見てください:```
2 4 2
```正しい答えは次のとおりです。```
YES
```各プレートには直径があります`4`、テーブルの半径に等しい。 2 つのプレートは向かい合って配置され、正確に 1 点で接触することができます。 非厳密な不等式の代わりに厳密な不等式を使用する実装では、多くの場合、この有効な構成が拒否されます。 

最も厄介なケースは次のとおりです。```
2 2 1
```正しい答えは次のとおりです。```
YES
```2 つのプレートの中心は半径の円上にあります`R - r = 1`。 その円上の反対側の点は距離です`2`離れて、正確に等しい`2r`, そのため、プレートは接触していますが重なりません。 

別の微妙なケースは次のとおりです。```
3 2 1
```正しい答えは次のとおりです。```
NO
```多くの誤った解決策は、次のことを確認するだけです。`2r <= R`、ここではそれが当てはまります。 ただし、3 つの単位円がすべて重ならずに半径 2 のテーブルの境界に接することはできません。 

## アプローチ

 この問題を考える強引な方法は、半径の円上にプレートの中心を配置することを想像することです。`R - r`テーブルの境界に触れるすべてのプレートは、その中心をテーブルの中心から正確に離れた位置に置くためです。 

すべての角度配置を試してみると、`n`この円の周りの点とプレート間のペアごとの距離を確認すると、有効な配置が存在する場合、最終的にそれが見つかります。 ジオメトリは中心位置によって完全に決定されるため、これは概念的には正しいです。 

問題は、連続ジオメトリには無限に多くの構成があることです。 角度を十分に細かく離散化しても、やはり扱いにくく不必要です。 制約は小さいですが、構造が非常に対称的であるため、数値検索はここでは間違ったツールです。 

重要な観察点は、最良の配置は常にテーブルの周囲に均等な間隔であるということです。 

各プレートの中心は同じ半径円上にあります`R - r`。 中心を均一に分布させると、隣接する中心は等しい角度を形成します。`2π / n`。 隣接する中心間の距離が弦長になります。$$2(R-r)\sin\left(\frac{\pi}{n}\right)$$プレートが重ならないようにするには、この距離は少なくとも`2r`。 

したがって、次のものが必要です。$$2(R-r)\sin\left(\frac{\pi}{n}\right) \ge 2r$$これは次のように単純化されます。$$(R-r)\sin\left(\frac{\pi}{n}\right) \ge r$$三角関数を完全に回避するさらにクリーンな方法があります。 

いつ`n >= 2`、プレートは次の場合に適合します。$$R \ge 2r$$また、周囲の配置にも余裕を持たせています。 Codeforces 編集ソリューションは通常、同等の条件を導き出します。$$n \cdot r \le R$$特殊な幾何学解釈の場合のみですが、ここでは正しくありません。 
正しい標準偏差は次のとおりです。 
のために`n = 1`、必要なのは`r <= R`。 

のために`n = 2`、2 つのプレートが収まる場合`2r <= R`。 

のために`n >= 3`、等間隔の中心が正多角形を形成し、正確な条件は次のようになります。$$\sin\left(\frac{\pi}{n}\right) \ge \frac{r}{R-r}$$直接ジオメトリを使用するのが最も安全な方法です。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`R`、 そして`r`。 
2. ケースを処理する`n == 1`。 

1 枚のプレートが境界に触れながらテーブルの内側に収まる必要があるだけです。 これはまさに次の場合に可能です`r <= R`。 
3. ケースを処理する`n == 2`。 

2 つのプレートの中心は半径円の反対側になければなりません`R-r`。 それらの間の最大距離は直径です。$$2(R-r)$$少なくともこれがあれば、プレートは重なりを避けます`2r`。 

これは次のように単純化されます。$$R \ge 2r$$4. ケースを処理する`n >= 3`。 

半径円の周囲に中心を均等に配置します`R-r`。 

隣接する中心間の角度は次のとおりです。$$\frac{2\pi}{n}$$隣接する弦間の弦の長さは次のとおりです。$$2(R-r)\sin\left(\frac{\pi}{n}\right)$$この距離が少なくともある場合、プレートは適合します`2r`。 
5. 印刷`"YES"`不等式が成り立つ場合、そうでない場合は出力します`"NO"`。 

### なぜ効果があるのか

 すべての有効なプレートの中心は半径の円上に正確に存在する必要があります`R-r`プレートがテーブルの境界に内部で接触しているためです。 

あらゆるアレンジメントの中で、`n`円上の点の場合、正多角形は隣接する点間の最小距離を最大化します。 最適な対称配置であってもオーバーラップが発生する場合は、不規則な配置はこれ以上の効果はありません。 

アルゴリズムは、この最適な構成を正確にチェックします。 距離条件により、隣接するプレートが交差しないことが保証され、隣接するペアが最も近いため、すべてのペアが重なり合わないことが自動的に保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, R, r = map(int, input().split())

    if n == 1:
        print("YES" if r <= R else "NO")
        return

    if R < 2 * r:
        print("NO")
        return

    if n == 2:
        print("YES")
        return

    lhs = (R - r) * math.sin(math.pi / n)

    eps = 1e-12

    if lhs + eps >= r:
        print("YES")
    else:
        print("NO")

solve()
```プレートが 1 つしかない場合、ジオメトリが完全に変化するため、最初のブランチはシングルトンのケースを個別に処理します。 多くの間違った提出物はこれを忘れて、マルチプレート式を誤って適用します。 

次のチェックでは、不可能な構成を早期に排除します。 もし`R < 2r`、向かい合った2枚のプレートでも収まりません。 

のために`n >= 3`の場合、実装は正多角形の配置から導出される幾何学的不等式を直接評価します。 有効なケースには完全な等価性が含まれる可能性があるため、浮動小数点の精度が重要になります。 イプシロンは、小さな丸め誤差による構成の拒否を回避します。 

表現:```
(R - r) * math.sin(math.pi / n)
```弦の長さの不平等を半分にすることから来ます。 これにより、算術演算が若干すっきりし、不必要な 2 の乗算が回避されます。
