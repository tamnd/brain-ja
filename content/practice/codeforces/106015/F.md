 ## 解決策
 ## 問題の理解

 整数の静的配列が与えられます。各位置は Spirit-Oak とその共鳴値を表します。 配列が修正された後は、多くの独立したクエリに答える必要があります。 各クエリは L から R までのインデックスのセグメントを指定し、そのセグメント内で値の間隔 [X, Y] 内に収まる値の数を数えるように求められます。 

したがって、各クエリは基本的に、L ≤ i ≤ R および X ≤ Ai ≤ Y となる要素 Ai の数を要求します。難点は、インデックス範囲と値範囲の両方が独立して制約されており、クエリが最大 100,000 個あるため、クエリごとに最初から再計算すると時間がかかりすぎることです。 

この制約により、クエリ処理ごとに O((N + Q) log N) に近い値かそれ以上の値が得られます。 クエリごとにセグメントをスキャンするアプローチでは、O(NQ) が発生します。これは、最悪の場合、10^10 の演算に相当し、1.5 秒以内に実行されません。 

値ごとのプレフィックス頻度などの単純な最適化だけでは、値の範囲は処理されますが、任意のサブ配列は効率的に処理されないため、不十分です。 同様に、インデックスごとのプレフィックス合計は値のフィルタリングを処理しません。 主要な問題は、各クエリの 2 次元の性質です。1 つの次元は位置であり、もう 1 つの次元は値です。 

L と R が大きいが値の範囲が非常に狭い場合、またはその逆の場合、微妙なエッジ ケースが発生します。 たとえば、すべての値が同一の場合、多くのクエリは単純な範囲の長さのチェックに集約されますが、単純なアプローチでは依然として不必要に反復される可能性があります。 もう 1 つのエッジ ケースは、X と Y が値の範囲全体にまたがる場合です。この場合、答えは R − L + 1 に等しく、境界が誤って処理されると、フィルター処理が不適切な構造は過小評価される可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。 クエリごとに、L から R まで繰り返し、X と Y の間にある要素の数を数えます。これは、すべての候補要素の条件を直接チェックするため、正しいです。 ただし、最悪の場合、各クエリのコストは O(N) となり、合計作業量は O(NQ) になります。 N と Q が最大 10^5 の場合、これは約 10^10 回の演算となり、許容範囲をはるかに超えています。 

重要な観察は、2 つの独立したフィルター (インデックスに対して 1 つと値に対して 1 つ) を繰り返し実行していることです。 これは、各要素が点 (i, Ai) である 2 次元空間内の範囲カウント クエリとして問題を再解釈することを示唆しており、各クエリは、L ≤ i ≤ R および X ≤ Ai ≤ Y で定義される四角形内に点がいくつあるかを尋ねます。 

これは古典的なオフライン範囲カウントの問題です。 これを効率的に処理する標準的な方法の 1 つは、一方の次元をスイープし、もう一方の次元では構造を維持することです。 ここでは、段階的に処理することで値のディメンションを修正し、インデックスに対してフェンウィック ツリーを使用します。 これを行うには、各クエリを値軸上のプレフィックス クエリの差に変換します。 

[X, Y] の値を直接カウントする代わりに、次のように答えを計算します。 

count(≤ Y in [L, R]) − count(≤ X−1 in [L, R])

 したがって、問題は次の形式のサポート操作に帰着します。範囲 [L, R] 内に Ai ≤ K がいくつあるかを数えます。 これは標準的な 2D オフライン問題で、配列要素とクエリの両方を値で並べ替えて昇順に処理し、フェンウィック ツリーに位置を挿入することで解決できます。 

配列要素とクエリを一緒に処理します。 値のしきい値 K を増やすと、Ai ≤ K であるすべての位置 i がフェンウィック ツリーにアクティブ化されます。 その後、K の各クエリは [L, R] にわたる範囲の合計として答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | お(1) | 遅すぎる |
 | フェンウィック + オフライン スイープ | O((N + Q) log N) | O(N + Q) | 承認済み |

 ## アルゴリズムのチュートリアル

 値ディメンションの包含/除外を使用して、各クエリを 2 つのサブクエリに変換します。 クエリ (L、R、X、Y) は次のようになります。

Ai ≤ Y の [L, R] のカウントから、Ai ≤ X−1 の [L, R] のカウントを差し引きます。 

ここでは、「インデックス範囲 [L, R] 内の値 ≤ K を持つ要素はいくつあるか」という形式のクエリに答えることに焦点を当てます。 

1. すべての配列位置 i とその値 Ai をペアにし、これらのペアを Ai で昇順に並べ替えます。 これにより、しきい値 K までの値を処理するときに、すべての有効な要素を段階的にアクティブ化できることが保証されます。 
2. 各クエリを 2 つのイベントに変換します。1 つは正の符号付きで K = Y を要求し、もう 1 つは負の符号付きで K = X−1 を要求します。 各イベントには（K、L、R、id、sign）が格納されます。 
3. すべてのイベントを配列値に沿って K で昇順に並べ替えます。 これにより、値空間上で 1 回の左から右へのスイープが可能になります。 
4. インデックスに対してフェンウィック ツリーを維持します。 最初はすべてのポジションが非アクティブです。 値 K を処理する場合、Ai ≤ K であるすべての配列位置をフェンウィック ツリーに挿入します。 挿入ごとに位置 i に 1 が追加されます。 この構造により、インデックス範囲内に含まれるアクティブな要素の数をクエリできます。 
5. K の昇順でイベントを処理するため、フェンウィック ツリーが常に Ai ≤ 現在 K の位置を正確に表すことを保証します。各イベントについて、フェンウィック ツリーから sum(R) − sum(L−1) を計算し、その符号を乗じて累積して最終的な答えを求めます。 
6. クエリ ID ごとに結果を保存し、2 つのイベントを最終的な回答に結合します。 

この順序付けが機能する主な理由は、要素を決して削除しないためです。 値が挿入されると、その値はより大きなすべてのしきい値に対して有効なままとなり、条件 Ai ≤ K の単調な性質と一致します。 

### なぜ効果があるのか

 スイープのどの時点においても、フェンウィック ツリーは、値が現在のしきい値 K 以下である一連のインデックスを正確に表します。挿入とクエリの両方が K の非降順で処理されるため、要素が早すぎたり遅すぎたりすることはありません。 各クエリは、そのしきい値がアクティブになった瞬間に評価され、プレフィックス変換の正確性が保証されます。 包含-除外ステップにより、Ai を [X, Y] に制限することが正確であり、過剰カウントが発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    elems = [(a[i], i + 1) for i in range(n)]

    events = []
    for idx in range(q):
        l, r, x, y = map(int, input().split())
        events.append((y, l, r, idx, 1))
        events.append((x - 1, l, r, idx, -1))

    elems.sort()
    events.sort()

    bit = Fenwick(n)
    ans = [0] * q

    j = 0
    for k, l, r, idx, sign in events:
        while j < n and elems[j][0] <= k:
            bit.add(elems[j][1], 1)
            j += 1

        if k >= 0:
            ans[idx] += sign * bit.range_sum(l, r)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```値がソートされると、値のフィルタリングがスイープ条件になるため、フェンウィック ツリーは値ではなくインデックスに対してのみ使用されます。 ポインタ j は、各配列要素が 1 回だけ挿入されることを保証し、並べ替えられた値に対して線形スキャンを行います。 

各クエリは 2 つのイベントに分割されるため、値の範囲の制約がプレフィックスの制約になります。 減算ステップは、符号フィールドを使用して累算に埋め込まれます。 

微妙な実装の詳細は、X = 1 の場合に K = X − 1 を処理することです。その場合、K は 0 になり、すべての Ai ≥ 1 であるため、安全に空のプレフィックスが生成されます。条件 k ≥ 0 はオプションですが、負のしきい値に対する不必要なフェンウィック クエリを防止します。

 ## 特殊なケース

 すべての Ai が等しい場合は、スイープが繰り返しの挿入を正しく処理するかどうか、および包含と除外の両方の部分が正しくキャンセルされるかどうかをテストします。 たとえば、配列 [3, 3, 3, 3, 3] とクエリ [1, 5, 3, 3] の場合、Y と X−1 は両方ともすべての要素をアクティブにし、減算によって正確に 5 が得られる必要があります。両方のイベントが同一のプレフィックス カウントを参照するため、フェンウィックの差分は正しく生成されます。 

クエリ [1,1,1,1] を持つ [1] のような単一要素配列は、インデックス境界処理をテストします。 フェンウィック ツリーは、インデックス 0 に誤ってアクセスすることなく、range_sum(1,1) を正しく解釈する必要があります。 この実装では sum(l−1) を使用しますが、これは安全に sum(0) = 0 になります。 

[5,4,3,2,1] のような減少配列は、要素がインデックス位置の厳密な降順でアクティブ化されることを保証し、インデックスではなく値のスイープ順序が正確さを決定することを確認します。 インデックスは値の順序で非単調に挿入されますが、Fenwick 構造により、クエリは挿入順序ではなく累積カウントのみに依存することが保証されます。
