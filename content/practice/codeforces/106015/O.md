 ## 解決策
 ## 問題の理解

 「スクロール」を表す可変文字列が与えられます。 一連の操作を通じて、部分文字列を繰り返し選択し、その内部の繰り返し構造を検査します。 選択したセグメントごとに、繰り返しによって部分文字列全体を生成できる最小の繰り返し単位を計算するように求められます。 この値が取得されたら、以前の操作で同じ値が見つかったかどうかを確認します。 新しい場合は、メイン文字列内のその部分文字列を反転します。 以前に出現したことがある場合は、文字列を変更しないままにします。 すべての操作を処理した後、文字列の最終形式を出力します。 

重要な問題は、文字列が静的ではないことです。 各クエリはセグメントを反転できるため、後のクエリは以前のクエリとは異なる基礎となるテキストを操作します。 同時に、各クエリでは、部分文字列の内容だけでなく、部分文字列の構造プロパティを抽出する必要があります。 

この制約により、最大 10 万文字と 10 万回の操作が許可されます。 部分文字列を明示的に再構築したり、クエリごとに線形時間で周期性を再計算したりするソリューションでは、最悪の場合、約 10^10 文字の操作が必要になり、これは実行不可能です。 クエリごとの完全な部分文字列スキャンに適用すると、文字あたりの対数オーバーヘッドでもコストがかかりすぎます。 

さらに微妙な問題は、動的に変化する文字列に対して部分文字列構造を計算する必要があることです。 接頭辞関数または Z 値の静的前処理を前提とするアプローチは、反転が開始されるとすぐに機能しなくなります。 

いくつかの特殊なケースでは、典型的な落とし穴が明らかになります。 

文字列がすでに完全に周期的である場合 (「aaaaaa」など)、最小周期は 1 です。完全な周期的等価性を検証せずに割り算だけをチェックする単純な実装では、ハッシュの衝突や部分的なチェックが誤って使用されると、無効なピリオドを誤って受け入れる可能性があります。 

部分文字列の長さが 1 の場合、答えは自明のことながら 1 であり、これまでに確認されない限り、常に新しいピリオドとして扱われます。 このケースを見逃すと、誤った逆の操作が発生することがよくあります。 

反転が重なり合う場合、たとえば文字列のほぼ全体を繰り返し反転する場合、明示的な部分文字列を維持したり、クエリごとに補助配列を再構築しようとするアプローチは、二次的な動作に低下します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、部分文字列を抽出し、すべての候補期間の長さを試してその最小期間を計算し、部分文字列がその長さの繰り返しブロックで構成されているかどうかを比較します。 これには部分文字列の長さまでチェックする必要があり、チェックごとに最悪の場合は別の線形スキャンが必要になります。 長さ 10^5 の文字列に対して最大 10^5 のクエリを実行すると、最悪の場合、実行不可能な 3 次関数のような動作が発生します。 

主な障害は、周期性は位置全体にわたるグローバルな一貫性条件であるが、シフトされたセグメントの等価性を使用して検証できることです。 これは、文字の直接比較を、高速な範囲の等価性チェックをサポートする構造に置き換えることを示唆しています。 部分文字列の等価性クエリが効率的になると、毎回部分文字列をスキャンするのではなく、候補期間をすばやくテストできるようになります。 

2 番目の障害は、反転による動的更新です。 これは、範囲の逆転をサポートし、部分文字列のハッシュ クエリにも効率的に応答するデータ構造を維持することによって処理されます。 ローリング ハッシュと遅延伝播を備えたセグメント ツリーにより、順方向ハッシュと逆方向ハッシュの両方のメンテナンスが可能になります。 

部分文字列ハッシュ クエリが利用できる場合、候補ピリオド p が有効かどうかのチェックは、すべての位置がシフトされた対応する位置と一致するかどうかを検証することになります。これは、ハッシュ セグメントを比較することで実行できます。 有効な繰り返し構造には全長を分割するためのピリオドが必要であるため、考えられるすべての p をテストする代わりに、部分文字列の長さの約数のみをテストします。

最後に欠けているのは、生理が以前に見られたかどうかを追跡することです。 期間値は N までの限定された範囲の整数であるため、ハッシュ セットで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q · N²) | O(N) | 遅すぎる |
 | セグメントツリー + ハッシュ + 除数チェック | O(Q · √N · log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがセグメントのローリング ハッシュを保存するセグメント ツリーを維持し、遅延伝播による反転状態もサポートします。 これにより、任意の部分文字列ハッシュを対数時間でクエリしたり、任意の間隔を対数時間で反転したりすることができます。 

部分文字列 [L, R] に対する各クエリについて、その長さを計算し、その長さのすべての約数を決定します。 各約数は候補期間です。 

ステップ p で部分文字列が完全に周期的であるかどうかを確認することで、各候補期間 p をテストします。 これは、セグメント [L, R - p] のハッシュを [L + p, R] のハッシュと比較することによって行われ、すべての文字がシフトされた対応する文字と一致することが保証されます。 

すべての有効な p の中で、最小のもの、つまり最小期間を採用します。 

次に、この期間が以前に見られたかどうかを確認します。 存在しない場合は、それをセットに挿入し、セグメント ツリー内の部分文字列 [L, R] を反転します。 見られた場合は何もしません。 

### なぜ効果があるのか

 正しさは 2 つの事実に基づいています。 まず、文字列の周期性は、文字列とそれ自体のシフトされたバージョンとの間の同等性と同等です。 これにより、ハッシュ構造がサポートする範囲の等価性チェックの問題が軽減されます。 第 2 に、有効なピリオドは部分文字列の全長を分割する必要があるため、有効な解を失わずに最小候補を見つけるには、約数を列挙するだけで十分です。 セグメント ツリーは、すべての比較が以前のすべての反転後の文字列の現在の状態を反映することを保証し、動的更新下でも正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.mod = (1 << 61) - 1
        self.base = 91138233

        self.pow = [1] * (self.n + 1)
        for i in range(self.n):
            self.pow[i + 1] = self._mul(self.pow[i], self.base)

        self.val = [0] * (4 * self.n)
        self.rev = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)

        self.s = s
        self._build(1, 0, self.n - 1)

    def _mul(self, a, b):
        return (a * b) % self.mod

    def _combine(self, left_val, right_val, right_len):
        return (self._mul(left_val, self.pow[right_len]) + right_val) % self.mod

    def _build(self, idx, l, r):
        if l == r:
            v = ord(self.s[l])
            self.val[idx] = v
            self.rev[idx] = v
            return
        m = (l + r) // 2
        self._build(idx * 2, l, m)
        self._build(idx * 2 + 1, m + 1, r)
        self.val[idx] = self._combine(self.val[idx * 2], self.val[idx * 2 + 1], r - m)
        self.rev[idx] = self._combine(self.rev[idx * 2 + 1], self.rev[idx * 2], m - l + 1)

    def _push(self, idx, l, r):
        if not self.lazy[idx]:
            return
        self.val[idx], self.rev[idx] = self.rev[idx], self.val[idx]
        if l != r:
            self.lazy[idx * 2] ^= 1
            self.lazy[idx * 2 + 1] ^= 1
        self.lazy[idx] = 0

    def _update_rev(self, idx, l, r, ql, qr):
        self._push(idx, l, r)
        if ql <= l and r <= qr:
            self.lazy[idx] ^= 1
            self._push(idx, l, r)
            return
        if r < ql or l > qr:
            return
        m = (l + r) // 2
        self._update_rev(idx * 2, l, m, ql, qr)
        self._update_rev(idx * 2 + 1, m + 1, r, ql, qr)
        self.val[idx] = self._combine(self.val[idx * 2], self.val[idx * 2 + 1], r - m)
        self.rev[idx] = self._combine(self.rev[idx * 2 + 1], self.rev[idx * 2], m - l + 1)

    def _query(self, idx, l, r, ql, qr):
        self._push(idx, l, r)
        if ql <= l and r <= qr:
            return self.val[idx], r - l + 1
        if r < ql or l > qr:
            return 0, 0
        m = (l + r) // 2
        lv, ll = self._query(idx * 2, l, m, ql, qr)
        rv, rl = self._query(idx * 2 + 1, m + 1, r, ql, qr)
        if rl == 0:
            return lv, ll
        if ll == 0:
            return rv, rl
        return (self._combine(lv, rv, rl), ll + rl)

    def get_hash(self, l, r):
        return self._query(1, 0, self.n - 1, l, r)[0]

    def reverse(self, l, r):
        self._update_rev(1, 0, self.n - 1, l, r)

def divisors(x):
    res = set()
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.add(i)
            res.add(x // i)
        i += 1
    return sorted(res)

def is_period(st, l, r, p):
    total = r - l + 1
    base = st.get_hash(l, r - p)
    shifted = st.get_hash(l + p, r)
    return base == shifted

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    st = SegTree(s)
    seen = set()

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        length = r - l + 1
        best = length

        for p in divisors(length):
            if is_period(st, l, r, p):
                best = min(best, p)

        if best not in seen:
            seen.add(best)
            st.reverse(l, r)

    out = []
    for i in range(n):
        out.append(chr(st.get_hash(i, i)))

    print("".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには順方向ハッシュと逆方向ハッシュの両方が格納されるため、反転には構造の再構築が必要なく、遅延反転のみが必要になります。 周期性テストは、部分文字列のシフトされた 2 つの半分の比較に完全に依存しているため、文字を明示的にスキャンする必要がありません。 

最終的な再構築では、単一位置のハッシュ クエリを介して各文字を読み取ります。この実装では、単一要素のハッシュとしてエンコードされた ASCII 値が返されます。 

## 実用的な例

 「abcabcabc」など、構造が見える小さな文字列を考えてみましょう。 文字列全体に対するクエリは、9 の約数を評価します。プレフィックス「abc」がハッシュ比較によって次のセグメントと一致するため、p = 3 のテストはすぐに成功します。したがって、3 が記録され、最初の出現後に文字列が反転されます。 

| ステップ | Ｌ | R | 長さ | 約数 | 最低期間 | 前に見た | アクション |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 9 | 9 | 1,3,9 | 3 | いいえ | 逆 |
 | 2 | 3 | 7 | 5 | 1,5 | 5 | いいえ | 逆 |
 | 3 | 2 | 4 | 3 | 1,3 | 1 | いいえ | 逆 |

 トレースは、反転によって後続の部分文字列構造が変更されるため、各クエリが元の文字列ではなく現在の文字列の状態にどのように依存するかを示します。 

「jxngmvzku」などの内部反復を含まない 2 番目の例は、ほとんどの部分文字列がその全長に等しいピリオドを持つことを示しています。 各クエリは固有のピリオドを生成するため、反転が繰り返し発生し、部分文字列の内容そのものではなく、「認識されたセット」がどのようにすべての構造変化を引き起こすかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q · √N · log N) | クエリごとの除数列挙とセグメント ツリーのハッシュ チェックを組み合わせたもの。 
| スペース | O(N) | セグメント ツリーとパワー テーブルおよび見られるセット |

 √N 係数は部分文字列の長さの約数を列挙することで得られますが、各周期性チェックは対数セグメント ツリー クエリに依存します。 N と Q が最大 10^5 の場合、これは慎重に実装されたソリューションの一般的な制約内に収まります。

 ## 特殊なケース

 長さ 1 の部分文字列は常に最小期間 1 を持ちます。 この値は最初は表示されない可能性が高いため、単一の文字セグメントに対する最初のクエリによって反転がトリガーされます。 除数セットには要素が 1 つしか含まれておらず、ハッシュ比較が自明に成立するため、セグメント ツリーはこれを正しく処理します。 

「aaaaaa」などの完全に均一な文字列では、クエリごとに最小期間 1 が生成されます。 最初の出現の後、値は表示されたセットに保存されるため、その後のクエリによって逆転がトリガーされることはありません。 遅延伝播メカニズムにより、同一セグメントで繰り返し反転が行われた場合でも、ツリーを再構築することなく一貫性が保たれます。 

[1, N] を繰り返し選択するなど、以前の反転後の高度に重複するクエリは、遅延伝播の正確さに完全に依存します。 各反転により内部表現が反転され、各ノードが順方向ハッシュ状態と逆方向ハッシュ状態の両方を維持するため、後続のハッシュ クエリには更新された構造が反映されます。
