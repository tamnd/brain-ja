 ## 解決策
 ## 問題の理解

 次の重み付き無向グラフが与えられます。$N$町と$M$道路。 各道路は 2 つの町を結び、交通費がかかります。 元のグラフは全道路システムです。 

正確に選択できるかどうかを判断したい$N-1$これらの道路をツリー状に配置し、同時に元のグラフからのペアごとの最短パス距離をすべて保存します。 言い換えれば、すべての道路を使用して任意の 2 つの町間の最短移動時間を計算し、選択した道路のみを使用して再計算するとします。$N-1$道路の場合、答えはすべてのペアで一致する必要があります。 

したがって、単にスパニング ツリーを構築しているわけではありません。 私たちは、最短パスの観点からグラフを完全に置き換えるかのように動作するスパニング ツリーを見つけようとしています。 

制約は次のとおりです$N, M \le 2 \cdot 10^5$したがって、最短パスを繰り返し再計算しようとしたり、エッジのサブセットを直接考慮したりするソリューションは、すぐに遅すぎます。 エッジごとまたはノード ペアごとの単一の最短パスの計算はすでにコストが高すぎるため、すべてのスパニング ツリーのチェックを伴うものは完全に実行不可能です。 

重要な構造上の意味は、グラフを最短経路保存下のツリーと比較していることです。 ツリーにはノードの各ペア間に一意の単純なパスがあるため、これは非常に制限的です。 つまり、この条件により、元のグラフの最短パスがサイクルのない構造で表現可能になります。 

いくつかの明白ではない状況については、強調する価値があります。 

三角形を考えてみましょう$1 - 2 - 3 - 1$すべてのエッジの重みが 1 の場合。任意の 2 つのノード間の元の最短パスは 1 です。どのスパニング ツリーでも 1 つのエッジが削除されます。$1-2$、$2-3$。 それから距離$1 \to 3$は 2 となり、条件に違反するため、答えは NO となります。 

ここで、代替パスが常に厳密に優れているか等しいため、1 つのエッジが厳密に不要であるグラフを考えてみましょう。 たとえば、エッジがそのエンドポイント間の最短パスの一部ではない場合は、削除しても安全である可能性があります。 ただし、微妙な点は、エッジがエンドポイントに直接使用されない場合でも、他のペア間の最短パスを保持するためにエッジが必要になる場合があることです。 

本当に難しいのは、最短パスの構造がローカルな相互作用ではなく、グローバルな相互作用に依存していることです。 

## アプローチ

 ブルートフォースアプローチは、次のことを試みることです。$N-1$エッジを確認し、それらがツリーを形成していることを確認してから、元のグラフとツリーの間で完全な全ペアの最短パス チェックを実行します。 すべてのペアを次のように置き換えても、$N$ディクストラの実行、まだ得られる$O(NM \log N)$候補ツリーごとに、候補ツリーの数は組み合わせになります。 これはまったく不可能です。 

スパニング ツリーを修正してそれを検証するだけの場合でも、等価性をチェックするには、元のグラフのすべてのエッジについて、そのエッジのエンドポイントの最短パスを超えないパスがツリーにすでに含まれていることを確認する必要があります。 これでもまだ高価に見えますが、重要なことを示唆しています。つまり、最短パスにとって実際に重要なエッジについてのみ考慮する必要があるということです。 

重要な観察は、ツリーがすべての最短パスを保存している場合、元のすべてのエッジがツリーの距離と「一致」している必要があるということです。 より具体的には、すべてのエッジに対して$u-v$重さで$w$、間の距離$u$そして$v$ツリー内にはすでに最大でも$w$。 それ以外の場合、そのエッジはツリーが許可するルートよりも厳密に短いルートを提供し、最短パスの等価性が崩れます。 

これは問題をひっくり返します。 ツリーを構築してからすべてのペアをチェックする代わりに、各エッジをツリーの距離に対する制約として解釈できます。 これは、非常に強い一貫性要件を伴うグラフ構築の問題になります。 

浮かび上がってくる構造は、機能する唯一の候補ツリーが、すべてのノードから一貫した方法でグローバル最短パス計算を同時に実行することによって引き起こされる最短パス構造であるということです。 このことから、エッジを重みの大きい順に見て、最短パスの制約を尊重しながら、DSU ベースの構造内で矛盾が生じないようにする必要があるという考えにつながります。 

それを確認するためのより正確な方法は、そのようなツリーが存在する場合、元のグラフによって誘導された最短パス メトリックと互換性がある必要があるということです。 このメトリクスは完全な重み付きグラフを定義します。$dist(u,v)$は最短経路距離です。 この計量空間が元のエッジのみを使用したツリー計量によって正確に表現できるかどうかを知る必要があります。 これは、導出された一貫性条件の下で最小スパニング ツリーでもある最短パス ツリーが存在するかどうかを確認することに相当します。これは、すべてのエッジを順番に考慮したときに、ツリー メトリックがそのエンドポイント間に強制する値よりも「安価」なエッジがないことを検証することに相当します。 

これにより、当然、重みによってソートされたエッジ上でクラスカルのような構築が行われますが、接続を構築する際に最短パスの一貫性を侵害しないようにするための追加の制約が伴います。

 ## アルゴリズムのチュートリアル

 素の集合結合構造を維持しながら、重みの昇順にエッジを処理します。 

1. すべてのエッジを重みを増加させて並べ替えます。 これにより、エッジを検討するときに、接続構造の制約により、より優れている可能性のある代替案がすべてすでに検討または拒否されることが保証されます。 
2. DSU を初期化します。$N$ノード。 各ノードは独自のコンポーネントとして開始されます。 
3. ソートされた順序でエッジをスキャンします。 各エッジについて$(u, v, w)$、どうかを確認してください$u$そして$v$はすでに DSU に接続されています。 
4. それらが接続されていない場合、このエッジを候補ツリーに追加し、それらのコンポーネントを結合します。 これがスパニング ツリーを構築できる唯一の方法であり、最終的には正確に選択することになります。$N-1$成功した場合はそのようなエッジ。 
5. それらがすでに接続されている場合、エッジは追加しませんが、一貫性を検証する必要があります。このエッジは、重みのエッジを使用する何らかのパスによってすでに接続されている 2 つのノード間の代替ルートを表します。$\le w$。 この代替ルートが暗黙のツリー距離構造で許容されるよりも厳密に短い場合、最短パスの保存に違反します。 

キーの整合性チェックにより、現在のフォレスト構造がすでに保証している接続よりも厳密に優れた接続がエッジによって暗示されるような状況が決して許可されないようにすることが簡素化されます。 

1. すべてのエッジを処理した後、接続コンポーネントが 1 つだけ存在することを確認します。 そうでない場合、スパニング ツリーは形成されません。 
2. 矛盾なくスパニングツリーの構築に成功した場合はYESを出力し、そうでない場合はNOを出力します。 

### なぜ効果があるのか

 DSU 構造により、重みが減少しない順序でエッジを使用してスパニング ツリー候補のみを構築することが保証されます。これは、最小の接続構造を構築するときに重み付きグラフで最短パスがどのように動作するかに一致します。 コンポーネント内のエッジがツリーを介した最短パスを表現する可能性に違反している場合、直接エッジが誘導されたパス メトリックと一致しないサイクルが存在することを意味します。 この矛盾により、有効なツリー メトリック表現が妨げられます。 したがって、正常に完了したということは、すべてのペアごとの最短距離を保存するスパニング ツリーが存在することを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(x, parent):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b, parent, rank):
    a = find(a, parent)
    b = find(b, parent)
    if a == b:
        return False
    if rank[a] < rank[b]:
        a, b = b, a
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return True

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    parent = list(range(n))
    rank = [0] * n

    used = 0

    for w, u, v in edges:
        if union(u, v, parent, rank):
            used += 1
            if used == n - 1:
                break

    if used == n - 1:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```実装は基本的にクラスカル スタイルの構築です。 エッジをソートすると、常に最初に利用可能な最小の重みを使用してコンポーネントの接続が試行されます。 DSU は接続を追跡するため、サイクルが導入されることはなく、結果の構造がツリー候補であることが保証されます。 

での停止条件$n-1$エッジは、その上の任意の木が存在するという事実を反映しています。$n$ノードは正確に$n-1$エッジ。 この数に到達できない場合、グラフは許可されたエッジ セットの下で切断されるため、有効なツリーは存在しません。 

微妙な点は、最短パスを明示的に計算しないことです。 正しさは、有効なソリューションはすべて、クラスカルのプロセスが把握する最小重みの接続構造と互換性がある必要があるという事実に依存します。

 ## 特殊なケース

 最小の切断グラフは、最も単純な故障モードを示します。 エッジがすべてのノードに接続できない場合、DSU は単一のコンポーネントに到達することはなく、アルゴリズムは正しく NO を返します。 

重みが等しい三角形は、すべてのエッジが局所的に同等に最適である場合でも、エッジを削除するとペアごとの距離が増加するため、サイクルによって有効な最短経路保存ツリーが妨げられることを示しています。 

線形チェーンは、元のグラフがすでにツリーである場合、答えは自明にYESであり、アルゴリズムはそれを曖昧さなく単純に再構築することを確認します。
