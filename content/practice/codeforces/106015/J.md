 ## 解決策
 ## 問題の理解

 グリッドは値のフィールドを表し、各セルには「匂いの強さ」を表す非負の数値が含まれます。 タスクは、単一の最適な四角形を見つけることではなく、グリッドのすべての可能なサブ四角形を検査し、その合計が指定された目標値 k に等しいかどうかを確認することです。 

このような四角形が存在するたびに、その中のすべてのセルが「重要」になります。 最終出力では、合計が正確に k である少なくとも 1 つの有効な四角形にセルが属している場合、そのセルは保存されます。 このような四角形に出現しない場合は、ゼロに置き換えられます。 

主な問題は、長方形が重なり合うため、単一のセルが左上隅と右下隅のさまざまな選択によって検証される可能性があることです。 

制約 n、m ≤ 100 は、各次元の 2 次または 3 次法が通過できるほど十分に小さいですが、すべての四角形を直接列挙しようとすると遅すぎます。 グリッド サイズでは、各操作が非常に安価で適切に最適化されている場合にのみ、合計で約 10^8 セルの作業が可能になります。そうでない場合は、Python でタイムアウトになります。 

単純なアイデアとしては、接頭辞の合計を使用してすべての可能な四角形の合計を計算し、セルにマークを付けることですが、その場合、n と m にわたる 4 つのネストされたループが発生し、約 10^8 の四角形が生成され、各四角形についてその領域をマークする必要があり、実行可能な制限をはるかに超えています。 

2 番目の微妙な問題は、k が 0 に等しい場合に発生します。 すべての値は負ではないため、この場合の有効な四角形は完全にゼロで形成されます。 ウィンドウの縮小または拡張に依存するソリューションでは、長いゼロのセグメントを慎重に処理する必要があります。そうしないと、有効なサブ配列が欠落したり、サブ配列が過剰にカウントされたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、上下の行のすべてのペア、左右の列のすべてのペアを列挙し、事前に計算されたプレフィックス合計テーブルを使用して四角形の合計を計算し、それが k と一致する場合、その四角形内のすべてのセルをマークします。 

O(1) 個の四角形合計クエリを許可するプレフィックス合計を使用しても、四角形の数は依然として O(n^2 m^2) です。 n = m = 100 の場合、これは 10^8 個の長方形になります。 成功した各長方形には、最悪の場合、潜在的に O(nm) セルにわたる追加のマーキング作業が必要になるため、総コストはすぐに実行不能になります。 

重要な点は、実際には任意の 2D 長方形を直接検査する必要がないということです。 上部と下部の行を固定すると、問題は列に関する 1 次元の問題に崩壊します。 各列について、これら 2 つの行間の合計を累積し、圧縮された配列を生成します。 これらの行間のすべての有効な四角形は、合計が k に等しい単なる連続した部分配列になります。 

グリッド内のすべての数値は負ではないため、この 1D 部分配列問題は、2 ポインターのスライディング ウィンドウを使用して効率的に解くことができます。 これにより、ペアごとのハッシュまたはプレフィックス合計ルックアップが回避され、各行ペアの計算が m 単位の線形時間に短縮されます。 

行の固定ペアに対して有効な部分配列をすべて見つけたら、長方形全体を効率的にマークする必要があります。 長方形ごとにすべてのセルを直接埋めると、三次因子が再導入されます。 代わりに、更新を 2D 差分配列に保存して、各四角形が O(1) に寄与するようにし、最終的なプレフィックス合計の再構成によってどのセルがカバーされたかを決定します。 

これにより、問題は、四角形の明示的な列挙から、行バンドの列挙と有効な列間隔の検索へと変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての四角形に対するブルート フォース | O(n^2 m^2 (n+m)) | お(1) | 遅すぎる |
 | 行 + プレフィックスの合計を固定 | O(n^2m^2) | O(nm) | ボーダーラインが遅すぎる |
 | 行を固定 + スライディング ウィンドウ + 2D 差分 | O(n^2m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 上の行のインデックスを固定し、下の行のインデックスを徐々に下に拡張します。 拡張子ごとに、2 つの行間の値の列方向の合計を維持します。 これにより、2D グリッドが現在のバンドの垂直合計を表す 1D 配列に圧縮されます。 
2. 現在の行バンドについて、スライディング ウィンドウを使用して、合計が k に等しい、この 1D 配列内のすべての連続するサブ配列を検索します。 すべての値は負ではないため、右ポインタを拡大すると合計が増加し、左ポインタを縮小すると合計が減少し、線形動作が保証されます。 
3. 合計 k を持つ部分配列が見つかるたびに、それを現在の最上行から最下行、および左列 l から右列 r にまたがる長方形として解釈します。 
4. その長方形内のすべてのセルを直接マークする代わりに、2D 差分更新を適用して、長方形が一定時間で記録されるようにします。 これにより、長方形が大きい場合でも、その寄与は依然として O(1) であることが保証されます。 
5. すべての行ペアとすべての有効な列間隔を処理した後、差分配列をプレフィックス合計グリッドに変換します。 この最終的なグリッドの各セルは、そのセルが含まれる有効な四角形の数を示します。 
6. 正のカバレッジを持つセルの元のグリッド値を維持し、その他をゼロに設定することにより、最終的な答えを生成します。 

正確かどうかは、すべての四角形が行のペアと圧縮された列表現内の有効な部分配列によって一意に決定されるという事実にかかっています。 スライディング ウィンドウは、このようなすべての部分配列を行ペアごとに 1 回だけ列挙し、差分配列により、各四角形内のすべてのセルが、正確さに影響を与える省略や重複がなく、一貫してマークされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    diff = [[0] * (m + 1) for _ in range(n + 1)]

    for top in range(n):
        col_sum = [0] * m

        for bot in range(top, n):
            for j in range(m):
                col_sum[j] += a[bot][j]

            l = 0
            cur = 0

            for r in range(m):
                cur += col_sum[r]

                while l <= r and cur > k:
                    cur -= col_sum[l]
                    l += 1

                if cur == k:
                    diff[top][l] += 1
                    diff[top][r + 1] -= 1
                    diff[bot + 1][l] -= 1
                    diff[bot + 1][r + 1] += 1

    for i in range(n):
        for j in range(m):
            diff[i][j] += diff[i - 1][j] if i > 0 else 0
    for i in range(n):
        for j in range(m):
            diff[i][j] += diff[i][j - 1] if j > 0 else 0

    out = []
    for i in range(n):
        row = []
        for j in range(m):
            if diff[i][j] > 0:
                row.append(str(a[i][j]))
            else:
                row.append("0")
        out.append(" ".join(row))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、行のペアごとに動的な列合計配列を維持し、スライディング ウィンドウを使用してすべての有効な列間隔を列挙します。 各間隔は、2D 差分構造を使用して四角形の更新に変換されます。 最終的なダブル プレフィックスの合計によりカバレッジ カウントが再構築され、出力ステップではセルが有効な四角形に含まれていたかどうかに基づいて元のグリッドをフィルター処理するだけです。 

微妙な点は、スライディング ウィンドウはすべてのグリッド値が負ではない場合にのみ機能することです。 負の値が許可されると、ウィンドウの縮小と拡大に必要な単調性が崩れ、代わりにハッシュ ベースのプレフィックス合計アプローチが必要になります。 

差分配列は、長方形を直接ペイントしようとするよくある間違いも回避します。 これがないと、ソリューションは四角形ごとに O(nm) セルを更新することになり、遅すぎます。 

## 実用的な例

 有効な四角形が少数の領域にのみ存在する小さなグリッドを考えてみましょう。 単一の行バンドとその結果として生じる列圧縮を追跡します。 

行の固定ペアの場合、圧縮された配列が [1, 0, 1, 3] になると仮定します。 

スライディング ウィンドウを追跡します。 

| r | 列合計[r] | cur_sum | l | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | 展開する |
 | 1 | 0 | 1 | 0 | 展開する |
 | 2 | 1 | 2 | 0 | 展開する |
 | 3 | 3 | 5 | 0 | 縮小 l=1 |
 | 3 | 3 | 5 | 1 | 縮小 l=2 |
 | 3 | 3 | 3 | 2 | 一致 |

 r = 3 では、k = 3 のときに有効な部分配列 [2,3] が検出されます。これにより、行 top..bot と列 2..3 をカバーする四角形が生成されます。 

このトレースは、配列内にゼロが出現する場合でも、ウィンドウが有効な合計を正しく保存し、潜在的な一致をスキップしないことを示しています。

 ## 特殊なケース

 k が 0 の場合、有効な四角形はすべて完全に 0 で構成されている必要があります。 合計はゼロから始まり、正の値が発生した場合にのみ拡大するため、スライディング ウィンドウは引き続き正しく動作します。 ゼロの行のような入力の場合、すべての部分配列が有効であり、差分配列は完全なグリッドをマークします。これは、すべてのセルがゼロ和の四角形の中にあるため、これは正しいことです。 

孤立した非ゼロスパイクを持つグリッドの場合、k と完全にバランスがとれた長方形のみが検出されます。 スライディング ウィンドウは合計が k を超えるたびに縮小するため、行バンドの中央に大きな値が表示される場合でも、有効な境界を超えて四角形が誤って拡張されることがなくなります。 

行ペアのループが単一の反復に縮退し、スライディング ウィンドウが唯一の可能な部分配列を直接評価するため、1x1 などの小さなグリッドは自然に処理されます。
