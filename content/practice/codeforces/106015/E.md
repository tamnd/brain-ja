 ## 解決策
 ## 問題の理解

 小文字の長方形グリッドと追加の「ターゲット」文字列が与えられます。 ターゲット文字列は必要な文字数を定義します。文字ごとに、その文字列内にその文字が何回出現するかを知る必要があります。 タスクは、すべての文字がターゲット文字列で必要とされる回数以上その正方形内に出現するように、大きなグリッド内の任意の場所に正方形のサブグリッドを配置することです。 すべての有効な正方形の中で、可能な限り面積が小さいものが必要です。 

重要な問題は、正方形はどこからでも開始でき、そのサイズは固定されていないことです。 すべての可能な位置とすべての辺の長さを効果的に検索し、各候補領域にわたるマルチセット制約をチェックします。 

グリッド サイズは最大 1000 x 1000 なので、セルの数は最大 10^6 です。 すべての正方形のサブグリッドに対する単純なスキャンは、慎重に実行すればすでにおよそ O(n^3) 個の候補を意味しており、正方形ごとの文字数を再計算するアプローチでは、これを最大 26 倍かそれ以上に乗算することになり、これでは遅すぎます。 これにより、領域クエリが O(1) になる、前処理ベースまたは 2 次元のプレフィックス合計ソリューションが求められます。 

ターゲット文字列が大きな領域であってもグリッド内にまったく存在しない場合、微妙なエッジ ケースが発生します。 たとえば、グリッドが```
abc
def
ghi
```そしてターゲットは`"zz"`、正方形は機能せず、答えは -1 でなければなりません。 最初に小さな正方形のみをチェックするソリューションでは、実現可能性を時期尚早に想定していないことを確認する必要があります。 

もう 1 つの特殊なケースは、必要な文字がグリッドの隅に集中している場合です。 単一の点から貪欲に成長する単純なスライディング ウィンドウは、たとえ他の場所に大きなシフトされた正方形が存在していても失敗する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。グリッド内の可能なすべての正方形を試し、その中の文字の頻度を計算し、必要な数がすべて満たされているかどうかを確認します。 各文字の接頭辞の合計を事前に計算すると、O(1) 内の任意の四角形内のカウントをクエリできます。 これにより、単一の正方形を迅速にチェックできるようになります。 

ただし、接頭辞の合計を使用しても、平方数は依然として多くなります。 左上隅は O(n^2) 個あり、辺の長さは最大 O(n) 個まであり、候補となる正方形は O(n^3) 個になります。 最大 10^6 セルでは、最悪の場合、速度が非常に遅くなります。 

重要な観察は、完全な 3D 検索では位置とサイズの両方を独立して修正する必要がないということです。 代わりに、辺の長さを固定し、そのサイズの正方形が機能するかどうかを確認できます。 これにより、問題はサイズごとの実現可能性チェックに変わります。 実現可能性が辺の長さにおいて単調になると、答えを二分探索できます。 

サイズ L の正方形が機能する場合、それより大きな正方形にはより多くの文字しか含めることができないため、これも機能します。 この単調性により、二分探索を使用して最小有効 L を検索することができます。 各候補 L について、すべての L × L の正方形をスキャンし、正方形あたり O(1) の接頭辞の合計を使用して実現可能性をチェックします。 

これにより、問題は O(n^2 log n) に軽減され、許容範囲内になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての平方、カウントを再計算) | O(n^4) | お(1) | 遅すぎる |
 | プレフィックスの合計 + すべての四角形をチェック | O(n^3) | O(26 n^2) | 遅すぎる |
 | 接頭辞の合計 + 辺の長さの二分探索 | O(n^2 log n) | O(26 n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ターゲット文字列内の各文字の頻度を計算します。 これにより、アルファベット上の固定要件ベクトルが得られます。 
2. グリッド内の各文字の 2D プレフィックス合計を作成します。 各文字 c と各セル (i, j) について、(1, 1) から (i, j) までの四角形内に c が出現する回数を保存します。 これにより、任意のサブ四角形に対する定数時間クエリが可能になります。 
3. すべての文字要件を満たす辺の長さ L の正方形がグリッド内のどこかに存在するかどうかをチェックする関数を定義します。 
4. 固定 L の場合、正方形 (i, j) から (i+L-1, j+L-1) がグリッド内に収まるように、考えられるすべての左上隅 (i, j) を反復します。 
5. このような正方形ごとに、接頭語の合計を使用して各文字の頻度を計算します。 必要なカウントがすべて満たされている場合は、L を実行可能としてマークし、この L に対するそれ以上の四角形のチェックを停止します。 
6. 1 から min(n, m) までの L を二分探索します。 L が可能であれば、より小さい値を試してください。 それ以外の場合は、より大きな値を試してください。 
7. 実現可能な L がない場合は、-1 を返します。 それ以外の場合は、L の 2 乗を答えとして返します。 

### なぜ効果があるのか

 正確さは 2 つの特性に依存します。 まず、プレフィックス合計は、各クエリが 2D 累積テーブルに対する正確な包含/除外であるため、すべての正方形の文字数が近似ではなく正確に計算されることを保証します。 第 2 に、L では実現可能性が単調です。正方形を拡大しても文字数を減らすことはできないため、L に有効な正方形が存在すると、それより大きなサイズはすべて有効のままになります。 この単調性により、二分探索が有効になり、中間ケースを見逃すことなく、実行可能な最小の L が確実に見つかるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()

    need = [0] * 26
    for ch in s:
        need[ord(ch) - 97] += 1

    pref = [[[0] * (m + 1) for _ in range(n + 1)] for _ in range(26)]

    for i in range(n):
        row = grid[i]
        for c in range(26):
            prev = pref[c][i]
            for j in range(m):
                pref[c][i + 1][j + 1] = pref[c][i][j + 1] + prev[j + 1] - prev[j]
        for j in range(m):
            c = ord(row[j]) - 97
            pref[c][i + 1][j + 1] += 1

    def get(c, x1, y1, x2, y2):
        p = pref[c]
        return p[x2][y2] - p[x1 - 1][y2] - p[x2][y1 - 1] + p[x1 - 1][y1 - 1]

    def ok(L):
        for i in range(1, n - L + 2):
            for j in range(1, m - L + 2):
                x2, y2 = i + L - 1, j + L - 1
                good = True
                for c in range(26):
                    if need[c] and get(c, i, j, x2, y2) < need[c]:
                        good = False
                        break
                if good:
                    return True
        return False

    lo, hi = 1, min(n, m)
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans * ans if ans != -1 else -1)

if __name__ == "__main__":
    solve()
```この解決策は、ターゲット文字列から必要な文字を数えることから始まります。 プレフィックス合計構造は 26 文字ごとに個別に構築されるため、包含/排他を使用して、四角形内の各文字クエリに一定時間で応答できます。 

の`ok(L)`関数は、考えられるすべての L × L の正方形を列挙し、制約を満たすものがあるかどうかをチェックします。 26 文字は固定で小さいため、26 文字にわたる内部ループは許容されます。 有効な正方形が見つかると、関数は早期に戻ります。 

二分探索は、この実現可能性チェックをラップします。 最小の有効な辺の長さは、指定されたサイズが達成可能かどうかに基づいて検索スペースを繰り返し狭めることによって見つけられます。 

よくある落とし穴は、文字ごとのプレフィックス合計を誤って構築することです。 ここでの構造により、各層が独立し、行と列の寄与が正しく蓄積されることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲットがグリッドのどこにも存在しない文字を必要とする場合です。 その場合、その文字に対するすべてのプレフィックス合計クエリはゼロになるため、`ok(L)`どの L に対しても成功することはありません。二分探索は次のように正しく終了します。`ans = -1`、最終的な出力は -1 です。 

もう 1 つの特殊なケースは、必要な文字が非常に少ない場合です。 たとえば、それぞれの文字が 1 つだけ出現し、反対側の角に散らばっています。 プレフィックスの合計は依然としてそれらを正しくキャプチャしており、両方の領域にまたがる十分な大きさの正方形のみが通過します。 このアルゴリズムは局所性を想定していないため、正しい最小二乗が存在する場合でもそれを見つけます。 

3 番目のケースは、グリッド全体が必要な場合です。 ここでは、min(n, m) に等しい L のみが成功します。 二分探索により、より小さいサイズが拒否され、境界ケースを見逃すことなく最終的な答えが正しく収束します。
