 ## 解決策
 ## 問題の理解

 N 個の魔法の苔のコレクションが与えられ、各部分がランタンで使用されると一定の時間の光に貢献します。 ランタンは単純な直線的な方法で使用されます。各苔片は次々に完全に消費され、ランタンが点灯し続ける合計時間は、個々の燃焼時間をすべて合計したものとなります。 

入力は、単一の整数 N とそれに続く N 個の整数で構成されます。各整数は、特定の苔片がランタンを燃やし続けることができる時間を表します。 タスクは、すべての部分が使用された場合の合計の燃焼時間を計算することです。 

制約の観点から見ると、N は最大 1000 であり、各書き込み時間は 10^9 に達する可能性があります。 これは、配列上の単純な線形パスで十分であることを直ちに意味します。 厳密に 1 秒という制限がある場合でも、1000 回の加算を実行するのは無視できる程度であるため、リストを 1 回スキャンして合計を累積するソリューションが最適です。 

唯一の微妙な問題は、合計が大きくなる可能性があることです。 それぞれ最大 10^9 の値が 1000 個あると、合計は 10^12 に達する可能性があり、これは 32 ビット整数の制限を超えます。 結果を 32 ビット型で格納する実装は、それが重要な言語では静かにオーバーフローします。 Python ではこれは問題になりませんが、他の言語では典型的な隠れた落とし穴になります。 

エッジケースは最小限ですが、それでも具体的に述べる価値があります。 N = 1 の場合、答えはその 1 つの値だけです。 すべての Hi が 10^9 の場合、合計は 10^12 となり、正しく出力される必要があります。 すべての値が同一の場合、結果は N による乗算を反映しており、繰り返しのリセットや部分的な累積ミスではありません。 

## アプローチ

 問題を直接解釈すると、すべての苔片を反復処理し、燃焼時間を累積することで、ランタンの使用プロセスをシミュレートします。 この強引なアプローチは、すでに説明したプロセスと一致しています。つまり、各ピースを順番に取得し、その期間を累計に加算し、すべてのピースが消費されるまで継続します。 

ランタンの動作には苔片間の相互作用がないため、これは正しく機能します。 オーバーラップ、減衰、条件付きロジックはありません。 各部分は、最終的な合計に独立して寄与します。 

ブルートフォースビューは、ループ内で繰り返し追加するという文字通り実装された場合でも、依然として正しいでしょう。 演算の合計数は正確に N 回の加算であり、N の場合は 1000 までは簡単です。 シングルパスを超える最適化は必要ありません。 

重要な観察点は、説明されているプロセスが状態遷移を伴うシミュレーション問題ではなく、純粋な集計問題であるということです。 ランタンの状態が単なる累計であることがわかれば、問題は配列の合計を計算することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N) | お(1) | 承認済み |
 | 直接加算 | O(N) | お(1) | 承認済み |

 ここでは両方のアプローチは事実上同じですが、「直接合計」フレーム化により、不必要な解釈のオーバーヘッドが回避されます。 

## アルゴリズムのチュートリアル

 これまでに蓄積された合計燃焼時間を表す単一のアキュムレータを維持します。 各苔片を正確に 1 回処理し、その値をこのアキュムレータに追加します。 

### ステップ

 1. 存在する苔片の数を示す整数 N を読み取ります。 これにより、処理する値の数が決まります。 
2. 変数 total をゼロに初期化します。 この変数は、これまでに処理されたすべての苔片の累積燃焼時間を表します。 
3. 書き込み時間を表す N 個の整数を繰り返します。 こんにちは、各値を合計に直接加算します。 これは、ランタンが次の苔片に移る前にその苔片を完全に消費していることを反映しています。 
4. すべての値を処理した後、最終的な答えとして合計を出力します。 

### なぜ効果があるのか

反復の各時点で、合計は、これまでに処理されたすべての苔片の合計と等しくなります。 すべての苔片は正確に 1 回処理され、その完全な値が正確に提供されるため、最終的な合計はすべての Hi の合計になります。 要素間に依存関係がないため、並べ替えやグループ化を行っても結果は変わりません。 したがって、アキュムレータはランタンの合計燃焼時間の定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    print(sum(arr))

if __name__ == "__main__":
    main()
```この実装は、入力リストに対して単一の線形パスを実行する Python の組み込み sum に直接依存しています。 これは、アルゴリズムで説明されているように、実行中のアキュムレータを維持することに正確に対応します。 入力の読み取りでは高速 I/O を使用して不要なオーバーヘッドを回避しますが、1000 までの N ではパフォーマンスは重要ではありません。 

他の言語でよくある間違いは、10^12 までの値を保持できない整数型を使用することです。 Python では、これは任意精度の整数を使用して自動的に処理されるため、単一の変数を使用する以外に特別な注意は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各苔片は 1 回のパスで 1 回だけ処理されます。 
| スペース | お(1) | 入力ストレージ以外に必要なアキュムレータは 1 つだけです。 

制約の上限は N の 1000 なので、リニア スキャンは問題なく制限内に収まります。 N がはるかに大きい場合でも、すべての要素を少なくとも 1 回読み取る必要があるため、同じ構造が最適なままになります。

 ## 特殊なケース

 N = 1 の場合、アルゴリズムは単一の値を読み取り、それをすぐに出力します。 たとえば、入力`1 10`合計を 0 に初期化し、10 を追加して、ランタンの燃焼時間の定義に一致する 10 を出力します。 

次のような最大値の場合`1000`のコピー`10^9`、ループは各値を順番に追加します。 アキュムレータは、Python で中間切り捨てなしで 0 から 10^12 まで増加し、正しい最終結果を生成します。 固定幅の整数を使用する言語では、通常、ここでオーバーフローが発生しますが、ロジック自体は正しいままです。 

すべての値が同一の場合、次のようにします。`3 7 7 7`、アルゴリズムは同じ数値の繰り返し加算を実行します。 ループの構造は一意性を想定していないため、最終的な合計は当然 21 となり、予想される集計動作と一致します。
