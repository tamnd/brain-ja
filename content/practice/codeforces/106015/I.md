 ## 解決策
 ## 問題の理解

 交差点がノード、道路が無向エッジであるグラフが与えられています。 各エッジにはパーセンテージで表される成功確率があり、その通りを横断すると、その確率で生き残ることができ、補完的なリスクで失敗することを意味します。 ノード 1 からノード n までの完全なルートの合計成功確率は、そのパスに沿ったエッジ確率の積に等しくなります。 

さらに工夫が 1 つあります。開始する前に、エッジを 1 つだけ選択し、成功確率が 100% になるようにアップグレードすることができます。 これは、元の値に関係なく、乗数が 1.0 になることを意味します。 目標は、ノード 1 からノード n までのパスを選択し、結果として得られる確率の積が最大化されるように、そのパス上のどの単一エッジをアップグレードするかを決定することです。 

グラフには最大 100,000 のノードと最大 200,000 のエッジを含めることができます。 これにより、パスを列挙しようとするソリューションが即座に除外されます。 密なグラフ内のパスの数は指数関数的に増加するため、すべての単純なパスにわたる最短パス スタイルの列挙さえ不可能です。 また、線形または線形に近い複雑さを超えてエッジごとにコストのかかる状態拡張を繰り返す余裕はないため、解決策では問題を少数のグラフ走査に減らす必要があります。 

微妙な問題は、確率が乗算的であり、浮動小数点精度が関係することです。 もう 1 つの微妙な点は、アップグレードする最適なエッジがパス自体に依存するため、グローバルな情報がなければ貪欲にアップグレードを決定できないことです。 

単純ですがよくある間違いは、アップグレードを無視して、単に最良の確率パスを計算することです。 これは、確率の低いエッジが避けられないものの無効化できる場合には失敗します。 

たとえば、エッジが 50% と 50% であるチェーン 1-2-3 を考えてみましょう。 アップグレードしない場合、答えは 25% です。 ただし、どちらかのエッジをアップグレードすると合計が 50% になるため、単純なソリューションでは 50% ではなく 25% が出力されます。 

もう 1 つの落とし穴は、常に最小のエッジをグローバルにアップグレードする必要があると想定していることです。 最適な候補は最適なパス上にどのエッジがあるかによって決まるため、これは失敗します。 

## アプローチ

 主な課題は、単一のエッジに適用される 1 つのオプションの乗算ブーストを使用して、パスに沿ってプロダクトを最適化していることです。 ブーストを無視すると、問題はグラフ内の古典的な最大確率パスになり、対数上のダイクストラによって、または積を直接最大化することによって解決できます。 

そのベースラインから始めましょう。 各エッジの標準重みをその確率として定義すると、1 から n への最適なパスは単に確率の積を最大化するパスになります。 これは、距離を加算する代わりに乗算する修正ダイクストラを使用して計算できます。 これが機能するのは、すべての確率が正で独立しているため、最適な部分構造が成立するためです。 

ただし、これはアップグレードを行わない最適なパスのみを提供します。 アップグレードにより構造が変更されます。選択したパスに沿って、1 つのエッジが p/100 ではなく 1.0 になります。 パスを修正する場合、最小の乗数を置き換えると最大の相対ゲインが得られるため、アップグレードするのに最適なエッジは明らかにそのパス上の最小確率エッジです。 したがって、固定パスの場合、達成可能な最良の値は、すべてのエッジをそのパス上の最小エッジ確率で割った積になります。 

したがって、問題は、積を最小エッジ重みで割った値を最大化するパスを見つけることになります。 

これは 2 次元の最適化に変換されます。つまり、総積において強いと同時にできるだけ大きな弱いリンクを持つパスが必要です。 秘訣は、これを拡張状態空間内の最短パスとして再解釈することです。

ノードごとに 2 つの状態を定義します。1 つはまだアップグレードを使用していない状態、もう 1 つはアップグレードをすでに使用している状態です。 状態 (ノード、未使用) からエッジを走査すると、2 つのオプションがあります。アップグレードを使用せずにその確率を乗算するか、このエッジでアップグレードを使用して 1 を乗算するかのいずれかです。状態 (ノード、使用済み) からは、通常どおり確率を乗算する必要があります。 これは、2n 個の状態を持つ標準的な層状ダイクストラです。 

これが機能するのは、どのエッジをアップグレードするかの決定がトラバース時まで延期され、すべての可能性が一度だけ調査されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスをブルート フォースします。 指数関数 | O(n) | 遅すぎる |
 | 2 状態のダイクストラ | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 最大確率ダイクストラを実行しますが、アップグレードがすでに使用されているかどうかを表す 2 つのレイヤーに各ノードを複製します。 

1. 各エントリ (これまでの確率、ノード、used_flag) を格納する優先キューを初期化します。 確率 1 および used_flag = 0 でノード 1 から開始します。これは、保証された安全なエッジをまだ適用していないことを表します。 
2. その状態に到達する既知の最良の確率を格納する距離配列 dist[node][used_flag] を維持します。 開始状態を除くすべての値は 0 から始まります。 
3. 優先キューが空ではない間に、最も高い確率で状態を抽出します。 これにより、ダイクストラの乗法類似物である最も有望な部分パスを常に最初に展開することが保証されます。 
4. 各出力エッジ (u、v、p) について、used_flag に応じた遷移を考慮します。 

used_flag が 0 の場合、選択肢は 2 つあります。 通常通りに移動して、確率 current * p で状態 0 の v を更新することも、このエッジでアップグレードを使用して、確率 current * 1 で状態 1 に移動することもできます。 2 番目の遷移は、エッジが安全であることが保証される唯一の瞬間です。 

used_flag が 1 の場合、通常通りに移動し、確率 current * p で状態 1 に移動する必要があります。 
5. 状態の新しい確率を計算するたびに、それが保存されている値よりも優れている場合はそれを更新し、優先キューにプッシュします。 
6. 目的地に到着するまでにアップグレードを使用しているか使用していない可能性があるため、答えは dist[n][0] と dist[n][1] の最大値です。 

### なぜ効果があるのか

 重要な不変条件は、各状態が、アップグレードの固定使用状況を持つノードに到達する可能性のある最良の確率を表すということです。 すべての遷移では確率に固定の正の係数が乗算されるため、最適なパスのプレフィックスはそのエンドポイントの状態にも最適になります。 プライオリティ キューにより、状態が確率の降順で処理されることが保証されるため、状態がポップされると、その後の緩和によって状態を改善することはできません。 2 つのレイヤーへの複製により、グローバルな最適性の決定を失うことなく、使い捨て制約が正しくエンコードされます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, p = map(int, input().split())
        prob = p / 100.0
        g[u].append((v, prob))
        g[v].append((u, prob))

    dist = [[0.0, 0.0] for _ in range(n + 1)]
    dist[1][0] = 1.0

    pq = [(-1.0, 1, 0)]

    while pq:
        neg_cur, u, used = heapq.heappop(pq)
        cur = -neg_cur

        if cur < dist[u][used]:
            continue

        for v, w in g[u]:
            # not using upgrade
            nxt = cur * w
            if nxt > dist[v][used]:
                dist[v][used] = nxt
                heapq.heappush(pq, (-nxt, v, used))

            # use upgrade if not used yet
            if used == 0:
                nxt2 = cur * 1.0
                if nxt2 > dist[v][1]:
                    dist[v][1] = nxt2
                    heapq.heappush(pq, (-nxt2, v, 1))

    ans = max(dist[n][0], dist[n][1])
    print(f"{ans * 100:.6f}")

if __name__ == "__main__":
    solve()
```グラフは、浮動小数点乗数に変換された確率を含む隣接リストとして構築されます。 距離テーブルには、両方の状態の各ノードの最良の確率が格納されます。 優先キューは、最大ヒープをシミュレートするために負の値を使用します。 

重要な点は、アップグレードがまだ使用されていない場合の分割遷移です。 これは、最終的なパスに沿った最適なエッジを選択することに正確に対応します。 

最終的な答えは 100 倍されてパーセント形式に変換されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, p = map(int, input().split())
        prob = p / 100.0
        g[u].append((v, prob))
        g[v].append((u, prob))

    import heapq
    dist = [[0.0, 0.0] for _ in range(n + 1)]
    dist[1][0] = 1.0
    pq = [(-1.0, 1, 0)]

    while pq:
        cur_neg, u, used = heapq.heappop(pq)
        cur = -cur_neg
        if cur < dist[u][used]:
            continue
        for v, w in g[u]:
            nxt = cur * w
            if nxt > dist[v][used]:
                dist[v][used] = nxt
                heapq.heappush(pq, (-nxt, v, used))
            if used == 0:
                nxt2 = cur
                if nxt2 > dist[v][1]:
                    dist[v][1] = nxt2
                    heapq.heappush(pq, (-nxt2, v, 1))

    return f"{max(dist[n][0], dist[n][1]) * 100:.6f}"

 ## 特殊なケース

 1 と n の間の直接エッジは、最も単純なストレス ケースです。 入力用`1 2 30`の場合、アルゴリズムは 2 つの状態を考慮します。アップグレードを使用すると、正しく選択された 1.0 がすぐに得られます。 

複数の平行エッジを持つグラフは、アルゴリズムがエッジの一意性を誤って仮定しているかどうかをテストします。 遷移では各エッジが独立して考慮されるため、最適な 100% アップグレードが常に選択されます。 

低確率テストの長い連鎖が蓄積されます。 アップグレードがなければ、確率は乗算的に崩壊します。 すべてのエッジが走査時に適格であるため、アルゴリズムはチェーンに沿って最も影響力のあるエッジにアップグレードを正しく適用します。 

短いパスの確率は低いが、長いパスの構造が高い分割グラフでは、全体的な最適性がテストされます。 2 層のダイクストラにより、両方のパスが一貫して評価され、ルートの長さに関係なく最適なエンドポイントの状態が選択されることが保証されます。
