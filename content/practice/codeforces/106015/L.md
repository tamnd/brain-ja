 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに整数の配列があり、2 つの値の最小公倍数に基づいて特別な条件を生成するインデックスのペアが何組あるかを数えなければなりません。 

位置のペアは、それらの値の最小公倍数が非常に特殊な構造を持っている場合、答えに寄与します。つまり、因数分解に現れるすべての素数は、少なくとも 2 つの指数を持って現れる必要があります。 言い換えれば、LCM には 1 乗のみの素数を含めることはできません。 素数が最小公倍数を割る場合、それを少なくとも二乗で割る必要があります。 

入力サイズにより、テスト ケースごとの二次関数から即座に遠ざけられます。 すべてのテスト ケースにわたる要素の合計数は最大 200,000 であるため、各テスト ケース内のすべてのペアを明示的に検査しようとするソリューションはタイムアウトになります。 単純な O(N²) スキャンでは、最悪の場合でも約 10¹⁰ の操作が実行されますが、これは許容される 2 秒をはるかに超えています。 

個々の要素についてのみ推論しようとすると、微妙な失敗モードが現れます。 たとえば、6 (2・3) や 10 (2・5) のような数値は「単純」に見えますが、これを別の数値と組み合わせると、LCM に一度しか存在しない素数が導入される可能性があります。 この条件は、個々の数値が「平方完全」であることに関するものではなく、LCM 内の結合された素数構造に関するものです。 

別の特殊なケースは、数値が素数を共有しているが指数が異なる場合に発生します。 たとえば、4 (2²) と 2 (2¹) は最小公倍数 4 を生成し、これは有効ですが、4 と 8 は 8 を生成します。23 には素数指数 3 が含まれているため無効ですが、3 ≥ 2 であるため問題はありません。本当の失敗は、素数が最小公倍数内に 1 回だけ出現するときに発生します。これは、両方の数値が指数 1 で寄与する場合にのみ発生します。 

したがって、問題は、組み合わされた素数の動作が LCM に「シングルトン指数」を残さないペアを数えることに帰着します。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのペアを反復処理し、最小公倍数を計算して因数分解し、すべての素数指数が少なくとも 2 であるかどうかを確認します。 LCM の計算は高速でも、ペアごとの因数分解は高速ではありません。 N が最大 10⁵ の場合、最悪の場合、これはおよそ 10¹⁰ のペア チェックになり、それぞれが自明ではない演算を使用します。 これでは実行不可能です。 

重要な観察は、条件が最小公倍数内で指数がちょうど 1 の素数が現れるかどうかのみに依存するということです。 与えられた素数 p について、これは、一方の数値が p¹ に寄与し、もう一方の数値が p⁰ または p¹ に寄与し、そのペアの最大指数が正確に 1 になるときに正確に発生します。 つまり、どちらの数値も「孤立した」素指数の導入を避ける必要があります。 

LCM の観点から直接考える代わりに、視点を反転します。各数値を平方フリー カーネルで分類しますが、因数分解で指数がちょうど 1 になる素数のみを考慮します。 指数 ≥2 で出現する素数は、すでに LCM で個別に条件を満たしているため、無害です。 

したがって、各数値をその中に 1 回だけ出現する素数のセットに圧縮できます。 これを「悪い署名」と呼びます。 ここで、条件は次のようになります。ペアが良好であるためには、それらの悪い署名の対称的な差に現れる素数があってはなりません。 同様に、両方の数値は同一の不良署名を持つ必要があります。不一致があると、指数 1 でちょうど 1 つの数値に現れる素数が作成され、LCM の指数 1 になるからです。 

したがって、タスクは、この署名によって数値をグループ化し、各グループ内のペアを数えるということになります。 

すべての数値について素因数分解を計算し、指数がちょうど 1 の素数を抽出します。 これを正規表現 (たとえば、ソートされたタプルやフローズンセット) としてエンコードします。 次に、頻度をカウントし、各バケット内の組み合わせを合計します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N² √A) | お(1) | 遅すぎる |
 | 最適 | O(N √A + N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての数値を素因数分解し、各素数の指数を記録します。 必要な素数は 10⁶ までなので、√A までの試行除算か、事前に計算されたふるいベースの SPF 配列で十分です。 ここでの目的は、単なる素数性ではなく、正確な指数情報を抽出することです。 
2. 各数値について、指数が正確に 1 である素数で構成される「署名」を構築します。 指数 2 以上の素数は、どの LCM ペアにもシングルトン寄与を作成しないため、無視されます。 
3. この署名をハッシュ可能な表現に変換します。 ソートされた素数タプルは、順序は重要ではありませんが、同一性は保持される必要があるため機能します。 
4. 署名からそれを含む数値のカウントまでの頻度マップを維持します。 各グループは、指数 1 の素数を生成するという点で同じように動作する数値を表します。 
5. サイズ k の各グループについて、k・(k−1)/2 を答えに加算します。 これは、署名が正確に一致するすべてのペアをカウントします。つまり、指数 1 を持つ 1 つの数値にのみ素数が出現しないことを意味します。 

グループ化が機能する理由は、2 つの署名間に不一致があると、指数が正確に 1 つの数値の 1 である素数が少なくとも 1 つ発生するためです。 その素数は LCM では指数 1 になり、条件に違反します。 

### なぜ効果があるのか

 このアルゴリズムは構造的等価性に依存しています。つまり、両方の数値が因数分解で 1 回だけ出現する同一の素数セットを持っている場合に限り、LCM には指数 1 の素数がありません。 偏差があると、指数 1 を持つ最小数が LCM に残ります。 したがって、有効なペアはまさに同一の署名クラス内で形成されたペアであり、カウントは頻度に対する単純な組み合わせの集計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6

# Precompute smallest prime factor
spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXA + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_signature(x):
    sig = []
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        if cnt == 1:
            sig.append(p)
    return tuple(sig)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = {}
        for _ in range(n):
            x = int(input())
            sig = factor_signature(x)
            freq[sig] = freq.get(sig, 0) + 1

        ans = 0
        for k in freq.values():
            ans += k * (k - 1) // 2
        print(ans)

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数を構築するので、各数値はその値に対して対数時間で因数分解できます。 の`factor_signature`この関数は、指数がちょうど 1 の素数のみを抽出し、タプルに格納します。 このタプルは、同一の動作をグループ化するための辞書キーとして使用されます。 

最後のループでは、標準の k 選択 2 式を使用して、各グループ内のペアの組み合わせをカウントします。 

## 実用的な例

 小さなケースを考えてみましょう。`[6, 10, 15]`。 

| 番号 | 因数分解 | 署名 |
 | --- | --- | --- |
 | 6 | 2¹・3¹ | (2, 3) |
 | 10 | 2¹・5¹ | (2, 5) |
 | 15 | 3¹・5¹ | (3, 5) |

 すべての署名は異なるため、ペアはカウントされません。 

これは、すべての数値の構造が「類似」しているにもかかわらず、どの組み合わせでも不一致の素数が生じ、それが最小公倍数の指数 1 になることを示しています。 

ここで考えてみましょう`[4, 8, 9, 16]`。 

| 番号 | 因数分解 | 署名 |
 | --- | --- | --- |
 | 4 | 2² | () |
 | 8 | 23 | () |
 | 9 | 3² | () |
 | 16 | 2⁴ | () |

 すべての署名が空であるため、すべてのペアが有効です。 この表は、指数 ≥2 の素数は署名に寄与しないため、すべての数値が 1 つのグループにまとめられることを示しています。 すべてのペアがカウントされます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log A + A log log A) | 1 回のふるいに加えて要素ごとの因数分解 |
 | スペース | O(N + A) | 周波数マップと SPF 配列 |

 この制約により合計 2×105 までの数値が許可され、各因数分解は事前に計算された SPF ふるいの下で十分に高速になります。 メモリ使用量の大部分はふるいとハッシュ マップですが、どちらも十分に制限内にあります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    MAXA = 10**6
    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factor_signature(x):
        sig = []
        while x > 1:
            p = spf[x]
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            if cnt == 1:
                sig.append(p)
        return tuple(sig)

    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = {}
        for _ in range(n):
            x = int(input())
            sig = factor_signature(x)
            freq[sig] = freq.get(sig, 0) + 1
        ans = sum(k * (k - 1) // 2 for k in freq.values())
        output.append(str(ans))

    return "\n".join(output)

# provided sample (format assumed)
assert run("1\n4\n10 18 29 36\n") == "0", "sample 1"

# all equal, all square-full
assert run("1\n4\n4 8 9 16\n") == "6", "all valid pairs"

# all distinct bad signatures
assert run("1\n3\n6 10 15\n") == "0", "no valid pairs"

# single prime powers
assert run("1\n5\n2 3 5 7 11\n") == "0", "primes only"

# mixed repetition
assert run("1\n5\n4 4 8 9 9\n") == "4", "grouping check"

 ## 特殊なケース

 主なエッジケースは、次のように数値がすべて正方形になっている場合です。`[4, 8, 16]`。 すべての署名は空になるため、アルゴリズムはすべてをグループ化し、すべてのペアを k · (k−1)/2 として正しくカウントします。 単純な実装では、誤って LCM 構造を直接検査しようとし、この場合、指数の動作が完全に消えることを見逃してしまう可能性があります。 

もう 1 つの特殊なケースは、すべての数値が異なる素数の積である場合です。`[6, 10, 15]`。 各署名は一意であるため、ペアは存在しません。 このアルゴリズムは、各数値を独自のグループに正しく分離し、正確な指数 1 構造ではなく gcd または割り算のみをチェックした場合に発生する誤検知を回避します。
