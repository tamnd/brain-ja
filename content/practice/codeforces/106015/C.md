 ## 解決策
 ## 問題の理解

 最大 500,000 個のノードを持つツリーが与えられます。 各ノードには 1 から 9 までの 1 つの数字が格納されます。ツリーはノード 0 をルートとしますが、ルートは構造のみに関係し、トラバースの方向には関係しません。 タスクは、任意の 2 つのノードを選択し、それらの間の一意の単純なパスを検討することです。 このパスに沿って歩きながら、訪問したノードの数字を順番に読み取り、それらを連結して数値を作成します。 考えられるすべてのノードのペアの中で、辞書編集的な意味で得られる最大の数値が必要です。これは、すべての桁がゼロ以外の 1 桁であるため、ここでは標準的な整数比較と同等です。 

キー出力はツリーのカウントやプロパティではなく、単純なパスに沿ってノード値を連結することによって形成される最大の文字列です。 

制約により、すべてのパスの列挙が直ちに除外されます。 n 個のノードを持つツリーには、ノードのペア間に O(n^2) 個の可能なパスがあり、各パスの長さは最大 O(n) になります。 すべてのパスをリストするだけでも、実行可能な制限をすでに超えてしまいます。 n が 5×10^5 までの場合、どの解も線形または線形に近いものでなければならず、おそらく O(n log n) または O(n) になります。 

微妙な特性は、パスが任意のシーケンスではないということです。 ツリー内のすべてのパスは、最下位の共通祖先構造によって完全に決定され、すべてのノードは多くの重複するパス上にあります。 この重複は、最適なパスがグローバルな列挙ではなく、ローカルな最適な選択から構築されるべきであることを示唆しています。 

単純に、連結を最大化するルートからリーフへのパスを見つければよいと仮定するのは単純な間違いです。 これは不正確です。最適なパスは、あるサブツリーから別のサブツリーに進む可能性があり、必ずしもルートを通過したり、リーフで終わるとは限らないからです。 

たとえば、ルート 0 に子 1 と 2 があり、次の値を持つツリーを考えてみます。```
0: 1
1: 9
2: 8
```最適なパスは 1 → 0 → 2 で 9-1-8 = 918 になります。これは、0 → 1 (19) や 0 → 2 (18) のようなルートからリーフへのパスよりも大きくなります。 ルートのみの戦略では、サブツリー間の組み合わせが失われます。 

もう 1 つの特殊なケースは、木が線である場合です。 この場合、最適なパスは単にノードのサブ配列であり、その解はルート化された DP ではなく最大サブパス問題のように動作する必要があります。 

## アプローチ

 ブルート フォースのアプローチは単純です。ノードのすべてのペア (u、v) を考慮し、LCA または親ポインターを使用してそれらの間のパスを計算し、パスに沿って数字を収集し、結果の文字列を辞書編集的に比較します。 これは、考えられるすべての有効なパスを明示的に評価するため、正しいです。 ただし、最悪の場合、各パス抽出には O(n) のコストがかかり、O(n^2) 個のペアが存在するため、O(n^3) の動作が発生します。 LCA の前処理を行ったとしても、各クエリのシーケンスを構築するコストは O (パスの長さ) のままであり、依然として大きすぎます。 

重要な観察は、ツリー構造により、重複するパス全体で計算を再利用できるということです。 各パスを独立して扱う代わりに、ルート分解の観点から考えることができます。 ツリーを任意にルート化すると、パスは完全に 1 つのサブツリー内に存在するか、最高点を通過し、そこで 2 つの下向きのパスに分かれます。 

これは、問題を次のように再構成することを示唆しています。各ノードについて、そのノードから始まる最適な下向きパスを知り、また、そのノードを通る異なる子からの 2 つの下向きパスを結合する必要があります。 数字は走査順序で連結されるため、方向性を考慮します。下向きのパスは、走査方法に応じてプレフィックスまたはサフィックスとして意味を持ちます。 

重要な構造の単純化は、ツリー内のすべての単純なパスに固有の最上位ノード (何らかのルートの下にある LCA) があることです。 したがって、すべての候補パスは、中間点で結合された 2 つの下向きパスとして表すことができます。 これにより、グローバルな問題がノードごとの組み合わせの問題に縮小され、各子からの最適な降順文字列を知るだけで済みます。 

難しいのは、これらは単なる合計やカウントではなく、順序付けられた数字のシーケンスであるため、辞書編集構造を失わずに数値に安全に圧縮できないことです。 代わりに、候補パス間の比較は、完全な文字列の構築を回避する方法で行う必要があり、通常はハッシュまたはヘビーライト スタイルのセグメント比較を使用します。 ただし、ノード値は 1 桁であり、ツリーの高さは制限されている (物語では最大 150 と述べられている) ため、深さが制限されたパスに沿って完全な上向き文字列と下向き文字列を保存し、それらを直接比較する余裕があります。 

この制限された高さが重要な簡素化になります。O(n) 深さのパスの代わりに、ルートからリーフまでのすべてのパスが短いため、二次関数の爆発のリスクなしに文字列を伝播できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | O(n3) | O(n) | 遅すぎる |
 | 深さ制限のある文字列伝播を備えたルート付き DP | O(n · H²) H ≤ 150 | O(n・H) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 0 にルートし、ノードごとに、そこから開始してそのサブツリーに入る最適な下向き文字列を計算する DFS を実行します。

1. 各ノードに対して、そのノードから始まるすべての下向きパスを表す候補文字列のリストを定義します。 この制限を超えるパスはないため、これらの文字列は深さ H までのみ保持します。 これにより、メモリが確実に制御されます。 
2. DFS 中に、子から戻るときに、子の最良の下向き文字列を取得し、現在のノードの数字を先頭に追加して、現在のノードの新しい候補文字列を形成します。 ノードから始まり子に至るパスは、ノードの数字で始まり、その後に有効な子パスが続く必要があるため、この手順は正しいです。 
3. 各ノードで、子からのすべての下位候補とノード自体のみからなる単一ノード パスの中で辞書編集上最大の文字列を維持します。 これは、このノードから始まる最適なパスを表します。 
4. ノードを通過して 2 つの異なるサブツリーに入るパスを考慮するために、上位 2 つの最良の子の寄与を結合します。 子のペアごとに、概念的には、最初の子からの 1 つの下向きパス、ノード桁、および 2 番目の子からの 1 つの下向きパスを逆方向に連結します。 パスには方向性がないため、トラバースの方向に応じて、常に一方をプレフィックスとして、もう一方をサフィックスとして扱うことで一貫性を確保します。 
5. 単一の子の拡張と 2 つの子の組み合わせを含む、そのノードを通過する最適な下向きパスのすべての組み合わせを考慮することにより、すべてのノードでグローバルな答えが更新されます。 
6. DFS は、各ノードの最適な下向き文字列をその親呼び出しに返します。 

中心的な考え方は、すべての最適なパスには最高位のノードがあり、そのようなすべての候補をそのノードで 1 回だけ評価するということです。 

### なぜ効果があるのか

 ツリー内のすべての単純なパスは、最上位のノードとそのノードからの下降する 2 つのチェーンへの一意の分解を持ちます。 このアルゴリズムは、考えられるすべての最上位ノードを列挙します。 このようなノードごとに、そのノードを通過する完全なパスを形成できるすべての有効な下向きの組み合わせが考慮されます。 すべての候補パスはその最上位ノードで正確に生成されるため、有効なパスが失われることはありません。 構築されたすべての文字列は、桁を並べ替えることなく実際のツリー パスに従うため、すべての候補が有効になります。 高さが制限されているため、明示的な文字列の保存と比較が漸近的に爆発しないことが保証され、正確性と実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

best = "0"

def dfs(u, p):
    global best

    down = [str(a[u])]

    child_paths = []

    for v in g[u]:
        if v == p:
            continue
        sub = dfs(v, u)
        child_paths.append(sub)
        cand = str(a[u]) + sub
        down.append(cand)

    # best single downward path starting at u
    best_down = max(down)

    # update global best with single-arm paths
    best = max(best, best_down)

    # combine two children through u (if at least 2 children exist)
    for i in range(len(child_paths)):
        for j in range(i + 1, len(child_paths)):
            left = child_paths[i]
            right = child_paths[j]
            cand = left + str(a[u]) + right
            best = max(best, cand)
            cand2 = right + str(a[u]) + left
            best = max(best, cand2)

    return best_down

dfs(0, -1)

print(best)
```DFS は、ノードごとに、そこから始まる最適な下向き文字列を計算します。 返された値は、パスを上方に拡張するためにその親によって使用されます。 すべてのノードで、1 つのサブツリーで始まり、そのノードを通過し、別のサブツリーに続くすべてのパスが考慮され、候補パスが見逃されないことが保証されます。 

実装の微妙な詳細は、2 つの子パスを結合するときに両方の連結順序を明示的に試行することです。 これが必要なのは、パスに方向性がなく、どちらのサブツリーも選択したエンドポイントの順序付けのどちらの側にも現れる可能性があるためです。 もう 1 つの重要な点は、辞書編集順を使用して文字列を直接比較することです。これは、この構造では数字が 1 文字であり、先頭の比較が等長連結の数値比較と一致するため、有効です。

これらのトレースは、アルゴリズムが最適な下方拡張を正しく蓄積し、正しい分解ポイントでクロスサブツリー結合を評価していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · H²) | 各ノードは子からの文字列を比較して結合します。 H は制限された高さ (~150) であり、比較を管理しやすくします。 
| スペース | O(n・H) | 各ノードは、DFS 再帰中に高さ H までの下向きの文字列を格納します。 

制約では、文字列の爆発を防ぐため、深さの限界について明示的に言及しています。 H が約 150、n が最大 5×10^5 の場合、各ノードが少数の固定数の文字列操作のみを処理するため、解は許容範囲内に留まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import defaultdict

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    best = "0"

    def dfs(u, p):
        nonlocal best
        down = [str(a[u])]
        child_paths = []

        for v in g[u]:
            if v == p:
                continue
            sub = dfs(v, u)
            child_paths.append(sub)
            down.append(str(a[u]) + sub)

        best_down = max(down)
        best = max(best, best_down)

        for i in range(len(child_paths)):
            for j in range(i + 1, len(child_paths)):
                left = child_paths[i]
                right = child_paths[j]
                best = max(best, left + str(a[u]) + right)
                best = max(best, right + str(a[u]) + left)

        return best_down

    dfs(0, -1)
    return best

# star

# equal branching

 ## 特殊なケース

 DFS が最適な下向きパスをノード自体として初期化するため、単一ノード ツリーが処理されます。したがって、答えは自明のことながらノードの数字になります。 

2 ノード ツリーでは、可能なパスはそれらの間のエッジのみです。 このアルゴリズムは、両方の下向き拡張を正しく形成し、1 つのエンドポイントで連結を評価します。 

チェーンでは、すべての最適なパスがフル チェーンであり、DFS は各ノードが最適な子パスを上方に拡張し、断片化することなくシーケンス全体を保持することを保証します。 

星型ツリーでは、最適なパスは常に、ルートを通って最も深い 2 つの葉または最大値の葉の間を通ります。 ルートでの結合ステップでは、子サブツリーのすべてのペアが明示的に列挙され、このケースが確実に捕捉されます。
