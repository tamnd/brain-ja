 ## 解決策
 ## 問題の理解

 それぞれがナッツの「エネルギー」を表す整数のコレクションが与えられます。 タスクは、エネルギーの合計が奇数になるように 2 つの異なるナッツを選択し、そのようなすべての有効なペアの中で可能な最大の合計を返すことです。 奇数の和を生成するペアがない場合、答えは -1 になります。 

出力は、順序や位置ではなく、ペアリングの動作に完全に依存します。 複数の値のセットを効果的に操作しているため、結果の合計を最大化しながらパリティ制約を満たすためにどの 2 つの要素を組み合わせることができるかを推論する必要があります。 

この制約では、それぞれ最大 200,000 個の値を許可します。 これにより、すべてのペアを明示的にチェックする二次アプローチは即座に除外されます。これは、最悪の場合、1 秒の制限をはるかに超える約 4 × 10¹⁰ の演算が必要になるためです。 線形または線形に近い時間で配列を処理するソリューションが必要です。 

すべての数値が同じパリティを共有する場合、微妙なエッジケースが発生します。 すべての値が偶数であれば、すべての合計も偶数になります。 すべてが奇数であれば、すべての合計も偶数になります。 どちらの場合も、有効なペアが存在しません。 

たとえば、入力`2 4 6`奇数の和のペアは生成されないため、答えは -1 になります。 単純なアプローチでは、ペアの最大合計を計算しようとして、誤って 10 を返す可能性があります。 

奇数または偶数が 1 つだけ存在する場合、別のエッジ ケースが発生します。 例えば、`1 2 4 6`には奇数要素が 1 つしかないため、大きな値が存在しても有効な奇数和ペアを形成できません。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのペア (i, j) を試し、Ai + Aj が奇数かどうかをチェックします。 これは簡単です。ペアごとに合計を計算し、合計が奇数であれば最良の答えを更新します。 あらゆる可能性を列挙しているので、正しさは明らかです。 

問題は規模だ。 N が最大 200,000 の場合、ペアの数は約 N(N−1)/2 で、これは最悪の場合でおよそ 2 × 10¹⁰ の演算に相当します。 制限時間内に実行することはできません。 

重要な観察はパリティ構造から得られます。 一方の数値が偶数で、もう一方の数値が奇数である場合に限り、合計は奇数になります。 これにより、問題は「すべてのペア」から「クロスパリティ ペアのみ」に軽減されます。 すべての有効なペアの中で、最大の偶数値と最大の奇数を取ることによって最大合計が得られます。 

これにより、問題は単純なスキャンに変換されます。最大の偶数要素と最大の奇数要素を追跡し、両方が存在する場合はそれらの合計を計算します。

 ## アルゴリズムのチュートリアル

 次に、パリティによって課せられた構造を抽出し、検索スペースを 2 つの候補に削減します。 

1. これまでに確認された最大の偶数値とこれまでに確認された最大の奇数の 2 つの変数を維持しながら、配列を 1 回スキャンします。 たとえば、-1 のようなセンチネルを使用して、両方を不在として初期化します。 
2. 各数値 Ai について、そのパリティを決定します。 Ai が偶数の場合、現在の最良の偶数値と比較し、Ai が大きい場合は更新します。 Ai が奇数の場合は、奇数のトラッカーに対して同じことを行います。 これにより、各パリティ クラスで可能な限り最良の候補が常に保持されるようになります。 
3. すべての値を処理した後、最大偶数値と最大奇数値の両方が存在するかどうかを確認します。 どちらかが欠けている場合、有効なペアは奇数の合計を形成できないため、答えは -1 になります。 
4. 両方が存在する場合は、それらの合計を計算します。 偶数 + 奇数が奇数の結果を生成する唯一の方法であるため、これが奇数を保証する唯一の構造です。 

有効な解は 1 つの奇数と 1 つの偶数をペアにする必要があり、各パリティ グループ内で独立して合計を最大化すると、可能な限り最良のペアが得られるため、最大値のみを保持するという選択は正当化されます。 

### なぜ効果があるのか

 アルゴリズムは常に、観測された最大の偶数と最大の奇数を保存します。 有効な奇数和ペアは、各パリティ クラスの 1 つの要素で構成されている必要があります。 このようなペアのいずれかの要素を同じパリティのより大きな値に置き換えると、合計が増加するだけです。 したがって、最適なペアは、配列内の最大の偶数値と最大の奇数値によって形成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    max_even = -1
    max_odd = -1
    
    for x in arr:
        if x % 2 == 0:
            if x > max_even:
                max_even = x
        else:
            if x > max_odd:
                max_odd = x
    
    if max_even == -1 or max_odd == -1:
        print(-1)
    else:
        print(max_even + max_odd)

if __name__ == "__main__":
    solve()
```この実装では、入力を 1 回スキャンしている間、2 つの実行最大値が維持されます。 センチネル値 −1 は、すべての入力が少なくとも 1 であるため、安全に機能します。そのため、有効な配列値と混同することはできません。 

よくある間違いは、パリティ クラスを分離せずに合計だけを追跡しようとすることです。 これは、奇数和には逆パリティが必要であるという構造的制約を無視しているため、失敗します。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列に偶数のみが含まれる場合です。 入力用`6\n2 4 6 8 10 12`、スキャンは max_even を 12 に設定しますが、max_odd は全体を通して -1 のままです。 相互パリティ ペアリングは不可能であるため、アルゴリズムは最後に -1 を正しく出力します。 

もう 1 つのエッジ ケースは、パリティ クラスの要素が 1 つだけ存在する場合です。 入力用`4\n100 2 3 4`、max_even は 100 になり、max_odd は 3 になります。他のクラスが存在する限り、単一の奇数または偶数があれば十分であるため、アルゴリズムは引き続き機能します。 

3 番目のケースは、最大の偶数と最大の奇数が配列の後半に現れる場合です。 入力用`5\n1 8 3 6 7`、実行中の最大値は、最後に max_even = 8 および max_odd = 7 になるまで進化します。 最後の答え 15 は、順序は正しさに影響を与えず、最大値のみが重要であることを確認しています。
