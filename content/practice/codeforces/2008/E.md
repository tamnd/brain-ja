[CF 2008E - 代替文字列](https://codeforces.com/problemset/problem/2008/E)

 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 交互文字列は非常に特殊な形式を持っています。 

偶数のインデックスにあるすべての文字は同一である必要があり、奇数のインデックスにあるすべての文字は同一である必要があり、最終的な長さは偶数である必要があります。 

2 つのパリティ グループは同じ文字を使用することも、異なる文字を使用することもできます。 例えば、`"aaaa"`すべての偶数位置に含まれるため、交互になります。`'a'`そしてすべての奇数の位置にも次のものが含まれます`'a'`。 

文字を他の文字に変更する置換は、何回でも実行できます。 さらに、文字列から最大 1 文字を削除する場合があります。 目標は、操作の総数を最小限に抑えることです。 

入力には最大で次のものが含まれます$10^4$テスト ケース、すべての文字列の長さの合計は最大で$2 \cdot 10^5$。 この集約境界が実際の制約です。 テスト ケースの長さが 2 次である解は、一定の長さの文字列では非常に遅くなりすぎます。$2 \cdot 10^5$。 周りに何かが必要です$O(n \cdot 26)$または$O(n \log n)$アルファベットのサイズは 26 文字のみなので、テスト ケースごとに異なります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

単一文字の文字列を考えてみましょう。```
1
a
```答えは 1 です。唯一の文字を削除して、偶数長の交互文字列である空の文字列を生成する必要があります。 最後の文字列が空ではないことを前提としたソリューションは失敗します。 

考慮する：```
3
abc
```長さが奇数です。 最終的な長さは偶数でなければならないため、1 つの削除は必須です。 削除を考慮せずに置換のみをカウントするソリューションでは、正しい答えは 1 ですが、誤って 2 が返されます。 

別の微妙なケースは次のとおりです。```
5
ababa
```最初の文字を削除すると、`"baba"`、すでに交互になっています。 答えは 1 です。最も不一致の原因となっている文字を常に削除するという貪欲な戦略では、これを簡単に見逃す可能性があります。 

最も大きな落とし穴は、削除後のパリティ シフトにあります。 で```
5
aabaa
```中央の文字を削除すると、その右側のすべての文字のパリティが変更されます。 このシフトを考慮せずに左右の部分を独立して処理すると、不正確な周波数カウントが生成されます。 

## アプローチ

 まず、総当たりの解決策を想像してみましょう。 

長さが偶数の場合、ターゲット文字列も同じ長さでなければなりません。 偶数の位置には文字を選択し、奇数の位置には文字を選択します。 あるのは$26^2 = 676$可能性。 各ペアについて、すでに一致しているポジションの数と、交換が必要なポジションの数を数えます。 

長さが奇数の場合は、削除が 1 つだけ発生する必要があります。 すべての削除位置を試すことができます。 文字を削除した後、676 個のパリティ文字ペアすべてを再度試して、置換コストを計算します。 

この強引な考えは完全に正しいです。 難点はスピードです。 一定の長さの文字列の場合$n$、すべての削除位置を試し、毎回文字列全体をスキャンするとコストがかかります$O(n^2)$。 と$n = 2 \cdot 10^5$、これは絶望的です。 

重要な観察は、交互文字列はパリティ クラスのみを考慮するということです。 偶数長の文字列の場合、偶数の位置で使用される文字と奇数の位置で使用される文字を選択すると、すべての位置が独立します。 

文字列の長さがすでに偶数であると仮定します。 させて：

-`even[c]`文字の出現数になります`c`偶数の位置で。 
-`odd[c]`文字の出現数になります`c`奇数の位置で。 

文字を選んだ場合`x`偶数の位置と文字の場合`y`奇数の位置の場合、すでに正しい位置の数は次のようになります。$$even[x] + odd[y]$$保持される文字を最大化するには、偶数位置で最も頻繁に使用される文字と、奇数位置で最も頻繁に使用される文字を選択するだけです。 最小限の置換は次のようになります。$$n - \max(even) - \max(odd)$$奇数長の場合はさらに興味深いです。 

ポジション削除後$i$, 前の文字$i$以降の文字は等価性を維持します$i$すべてが 1 つの位置だけ左にシフトするため、パリティを切り替えます。 

これは、削除ポイントの両側で頻度カウントを維持することを示唆しています。 

させて：

-`pref_even`、`pref_odd`削除する前に文字数をカウントします。 
-`suf_even`、`suf_odd`現在の位置から以降の文字数を数えます。 

ポジションを削除する場合$i$:

 - 前の文字$i$普通に貢献する。 
- 以降の文字$i$パリティクラスを交換します。 

各文字について、削除後に新しい偶数位置と新しい奇数位置にその文字が何回出現するかを計算できます。 

その後、最良の代替ターゲットが再び各パリティ クラスで最も一般的な文字を保持します。 

アルファベットのサイズは 26 文字しかないため、1 つの削除位置を評価するにはコストがかかります$O(26)$。 すべてのポジションのスキャンにはコストがかかります$O(26n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \cdot 26^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \cdot 26)$|$O(26)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 偶数長の文字列

 1. 偶数位置にあるすべての文字の頻度を数えます。 
2. 奇数位置にあるすべての文字の頻度を数えます。 
3. 最も頻繁に使用される偶数位置の文字と、最も頻繁に使用される奇数位置の文字を選択します。 
4. 保存される文字の数は、これら 2 つの最大値の合計に等しくなります。 
5. 答えは次のとおりです。`n - preserved`。 

ターゲットの代替文字列は、パリティ クラスごとに 1 文字によって完全に決定されるため、パリティごとに独立して保持される文字を最大化することが最適です。 

### 奇数長の文字列

 1. 頻度表を作成する`suf_even`そして`suf_odd`文字列全体に対して。 
2. 空のプレフィックス テーブルを初期化します。`pref_even`そして`pref_odd`。 
3. すべての位置を反復処理します。`i`削除候補として。 
4. 削除する`s[i]`この文字は削除されるため、適切な接尾辞テーブルから削除されます。 
5. すべての文字について`c`、結果の偶数位置での周波数を計算します。$$pref\_even[c] + suf\_odd[c]$$削除後の文字はパリティを切り替えます。 

1. すべての文字について`c`、結果として得られる奇数の位置でその周波数を計算します。$$pref\_odd[c] + suf\_even[c]$$1. しましょう`best_even`そして`best_odd`それらの配列の最大値になります。 
2. 結果の文字列の長さは次のようになります。`n - 1`。 必要な交換数は次のとおりです。$$(n-1) - best\_even - best\_odd$$1. 削除自体の操作を 1 つ追加します。 
2. すべての削除位置にわたって最小の答えを維持します。 
3. 移動`s[i]`適切なプレフィックス テーブルに入力して続行します。 

### なぜ効果があるのか

 固定の削除位置の場合、残りのすべての文字は、結果の文字列の偶数または奇数のパリティ クラスに属します。 代替文字列には、クラスごとに 1 つの文字を選択するだけで済みます。 他の出現箇所はすべて置き換える必要があるため、最適な選択は常にそのクラス内で最も頻繁に使用される文字です。 

プレフィックス/サフィックス分解により、削除後の正確なパリティ クラスが計算されます。 削除前の文字はパリティを維持しますが、削除後の文字はパリティを交換します。 残りのすべての文字は、新しいクラスで 1 回だけカウントされます。 すべての削除位置が検査されるため、すべての位置の最小値が全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        if n % 2 == 0:
            even = [0] * 26
            odd = [0] * 26

            for i, ch in enumerate(s):
                idx = ord(ch) - 97
                if i % 2 == 0:
                    even[idx] += 1
                else:
                    odd[idx] += 1

            ans = n - max(even) - max(odd)
            print(ans)
            continue

        suf_even = [0] * 26
        suf_odd = [0] * 26

        for i, ch in enumerate(s):
            idx = ord(ch) - 97
            if i % 2 == 0:
                suf_even[idx] += 1
            else:
                suf_odd[idx] += 1

        pref_even = [0] * 26
        pref_odd = [0] * 26

        ans = n

        for i, ch in enumerate(s):
            idx = ord(ch) - 97

            if i % 2 == 0:
                suf_even[idx] -= 1
            else:
                suf_odd[idx] -= 1

            best_even = 0
            best_odd = 0

            for c in range(26):
                best_even = max(
                    best_even,
                    pref_even[c] + suf_odd[c]
                )
                best_odd = max(
                    best_odd,
                    pref_odd[c] + suf_even[c]
                )

            replacements = (n - 1) - best_even - best_odd
            ans = min(ans, replacements + 1)

            if i % 2 == 0:
                pref_even[idx] += 1
            else:
                pref_odd[idx] += 1

        print(ans)

solve()
```均等な長さの枝は簡単です。 両方のパリティ クラスで別々に頻度をカウントし、それぞれで最も一般的な文字を保持します。 

奇数長のブランチは 4 つの周波数アレイを維持します。 サフィックス配列には、最初は文字列全体からのカウントが含まれています。 左から右にスイープすると、現在の文字は削除されたものとして扱われるため、接尾辞側から削除されます。 

数式```
pref_even[c] + suf_odd[c]
pref_odd[c] + suf_even[c]
```削除後にパリティ スワップをエンコードします。 これがソリューションの中核となる詳細です。 スワップを忘れることは最も一般的な間違いです。 

削除位置の答えは 2 つの部分で構成されます。 まず、結果として得られる長さの文字列内で必要な置換をカウントします。`n - 1`。 次に、削除自体の操作を 1 つ追加します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        if n % 2 == 0:
            even = [0] * 26
            odd = [0] * 26

            for i, ch in enumerate(s):
                idx = ord(ch) - 97
                if i % 2 == 0:
                    even[idx] += 1
                else:
                    odd[idx] += 1

            out.append(str(n - max(even) - max(odd)))
            continue

        suf_even = [0] * 26
        suf_odd = [0] * 26

        for i, ch in enumerate(s):
            idx = ord(ch) - 97
            if i % 2 == 0:
                suf_even[idx] += 1
            else:
                suf_odd[idx] += 1

        pref_even = [0] * 26
        pref_odd = [0] * 26

        ans = n

        for i, ch in enumerate(s):
            idx = ord(ch) - 97

            if i % 2 == 0:
                suf_even[idx] -= 1
            else:
                suf_odd[idx] -= 1

            be = 0
            bo = 0

            for c in range(26):
                be = max(be, pref_even[c] + suf_odd[c])
                bo = max(bo, pref_odd[c] + suf_even[c])

            ans = min(ans, (n - 1) - be - bo + 1)

            if i % 2 == 0:
                pref_even[idx] += 1
            else:
                pref_odd[idx] += 1

        out.append(str(ans))

    return "\n".join(out)
