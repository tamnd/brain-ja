 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられ、各数値は黒または白で色付けされます。 任意の開始整数 i から順列を繰り返し適用して、i から p_i にジャンプし、次に p_{p_i} にジャンプするというように行うことができます。 これらのジャンプを有限回繰り返した後に j に到達できる場合、数値 j は i から到達可能であるとみなされます。 各 i について、i から到達可能な黒の整数の総数である F(i) を計算する必要があります。 

入力サイズは大きくなる可能性があります。n は最大 200,000 まで可能ですが、すべてのテスト ケースの n の合計が 200,000 を超えることはありません。 これにより、数値ごとに O(n) 時間で各開始数値のジャンプに明示的に従うソリューションは除外されます。これは、最悪の場合、O(n^2) 回の操作 (およそ 4 * 10^10 回の操作) が発生する可能性があり、2 秒の制限時間には遅すぎます。 

エッジケースは、サイクルが非常に短い場合、または単一の要素で構成される場合に発生します。 たとえば、順列が [1] で唯一の要素が黒の場合、正しい出力は 1 です。サイクルを考慮せずに到達可能なノードを事前計算しようとする不注意なソリューションでは、黒のノードが過大カウントまたは過少カウントされる可能性があります。 サイクルに開始ノードを除くすべての白い要素がある場合、別のエッジ ケースが発生します。 アルゴリズムは、到達可能なセットにどの黒いノードが含まれているかを正確に識別する必要があります。 

## アプローチ

 ブルートフォース手法は単純です。インデックス i ごとに、以前に訪問した番号に到達するまで順列に従い、訪問した番号をそれぞれマークし、遭遇した黒いノードの数を数えます。 到達可能なすべての数値を徹底的に調査するため、これは正しいです。 ただし、最悪の場合、順列が単一の大きなサイクルを形成する場合、各 i は最大 n ステップを移動する可能性があります。 n=2*10^5 の場合、O(n^2) 回の演算が必要になり、遅すぎます。 

重要な洞察は、順列が完全に素なサイクルで構成されているという認識から得られます。 サイクルが検出されると、そのサイクル内のすべての要素は、そのサイクル内のすべてのノードとそのサイクルにつながるすべてのノードという、まったく同じ数値セットに到達する可能性があります。 サイクル内のノードの黒数は、そのサイクル内の黒ノードの総数です。 サイクルに入るノードも、最終的にはサイクル自体と同じ黒カウントに達します。 これは、順列をサイクルに分解し、各サイクルの黒カウントを計算して、そのサイクル内のすべてのノードにカウントを割り当てることができることを意味します。 サイクルにつながるチェーンの場合、チェーンに沿ってサイクルの黒カウントを伝播します。 これにより、すべてのノードが 1 回だけ処理されるため、テスト ケースごとの複雑さが O(n) に軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | サイクル分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`visited`ノードが処理されたかどうかを追跡するためのサイズ n の。 配列も初期化します`F`各ノードの黒カウントを保存します。 
2. 各インデックス i を 1 から n まで繰り返します。 もし`visited[i]`それは本当です、飛ばしてください。 それ以外の場合は、i から順列の追跡を開始し、訪問したすべてのノードを一時リストに保存します。`path`。 
3. トラバースしながら、ノードを追加し続けます。`path`すでに訪問したノードに到達するまで。 このノードが現在のパスの一部である場合、サイクルが検出されました。 サイクルを次のセグメントとして特定します。`path`このノードの最初の出現から最後まで。 
4. カラー文字列を確認して、サイクル内の黒いノードの数を数えます。 サイクル内の各ノードについて、F[node] をサイクルの黒カウントに設定します。 
5. のノードの場合`path`サイクルの外側にあるノード (サイクルに入るノード) には、最終的にサイクルに到達し、サイクル内のすべてのノードに到達できるため、サイクルと同じ F 値を割り当てます。 
6. すべてのノードをマークします。`path`訪問したとおり。 
7. すべてのノードを処理した後、配列 F を出力します。 

機能する理由: 各ノードは 1 つのサイクルに属するか、固有のサイクルにつながります。 サイクルごとに黒ノードをカウントし、そのカウントをサイクルに入るノードに伝播することにより、すべてのノードに、そこから到達可能な黒ノードの数が正しく割り当てられます。 不変条件は、パスまたはサイクルを処理するときに、その中のすべてのノードが 1 回だけ訪問されたとマークされ、正しい F 値を受け取るということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(lambda x: int(x)-1, input().split()))
        s = input().strip()
        F = [0]*n
        visited = [False]*n
        
        for i in range(n):
            if visited[i]:
                continue
            path = []
            current = i
            while not visited[current]:
                path.append(current)
                visited[current] = True
                current = p[current]
            
            # Detect cycle
            if current in path:
                idx = path.index(current)
                cycle = path[idx:]
                cycle_black = sum(1 for x in cycle if s[x]=='0')
                for x in cycle:
                    F[x] = cycle_black
                for x in path[:idx]:
                    F[x] = cycle_black
            else:
                # Entire path leads to an already processed cycle
                cycle_black = F[current]
                for x in path:
                    F[x] = cycle_black
        print(*F)

if __name__ == "__main__":
    solve()
```このソリューションは、ループを使用して複数のテスト ケースを処理します。 配列へのアクセスを容易にするために、順列はゼロベースのインデックスに変換されます。 訪問先のノードが見つかるまでパスが追跡されます。 訪問したノードが現在のパス内にある場合、新しいサイクルを識別します。 黒のノード数が計算され、サイクルと先行ノードの両方に割り当てられます。 サイクル内のノードとそのサイクルに入るノードを注意深く区別することで、ノードの二重カウントや欠落が回避されます。
