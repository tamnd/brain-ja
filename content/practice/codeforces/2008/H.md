 ## 問題の理解

 配列とパラメータが与えられます$x$。 これで$x$、少なくとも次の要素を繰り返し選択できます。$x$そして正確にそれを減らします$x$。 この演算は任意の位置に何度でも適用できるため、各要素は事実上、次の倍数を減算した後の剰余となります。$x$、しかしゼロ以下になることはありません。 

各クエリ値について$x$、配列に対してこれらの削減を最適に実行した後、可能な限り最小の中央値を計算する必要があります。 中央値は、標準の Codeforces 定義を使用して、ソートされた配列の中央の要素です。$\lceil n/2 \rceil$- 番目に小さい要素。 

制約はテストごとではなく全体として厳しいです: 合計$n$そして合計$q$すべてのテスト ケース全体で、それぞれ最大$10^5$。 これは、均等な解決策を意味します。$O(nq)$テストケースごとでは遅すぎるし、$O(n \log n)$クエリごとの速度が遅すぎます。 この構造は、テスト ケースごとに 1 回配列を前処理し、各クエリに対数時間または定数時間で応答することを強く示唆しています。 

一般的な失敗モードは、各要素が独立して動作すると仮定し、再分配下で中央値がどのように変化するかを考慮せずに、大きな値を貪欲に削減することです。 もう 1 つの微妙な落とし穴は、中央値を計算するときに複数のリダクションが順序付けと相互作用することを忘れながら、操作がモジュロ リダクションだけのように動作すると考えることです。

 ## アルゴリズムのチュートリアル

 1. 配列を 1 回ソートします。 後のすべての推論は、変換された値がしきい値を下回る個数をカウントすることに依存するため、並べ替えは不可欠です。 
2. 固定クエリの場合$x$、それぞれの値を解釈します$a_i$剰余を生成するので$a_i \bmod x$。 これにより、変換された配列が構築されずに暗黙的に定義されます。 
3. 中央値を決定するには、最小値が必要です$m$変換された値の少なくとも半分が$\le m$。 これにより、問題はカウント述語に変わります。 
4. 関数を定義します。$x$と候補値$m$、満たす要素の数をカウントします。$a_i \bmod x \le m$。 これは、次のサイズのブロックを反復処理することで計算できます。$x$ソートされた配列内の値なので、$[kx, (k+1)x-1]$すべてが予測可能な残りの間隔にマッピングされます。 
5. 二分探索を使用する$m$範囲内$[0, x-1]$。 各中間点について、カウント関数を使用して述語を評価します。 
6. 最小のもの$m$中央値条件を満たすものがこのクエリの答えになります。 

なぜ機能するのか: すべての操作は要素を倍数だけ削減します。$x$したがって、最終状態は剰余剰余にのみ依存します。$x$。 並べ替えにより、値の範囲全体でこれらの残基に構造が与えられ、二分探索により中央値条件が単調な実現可能性テストに変換されます。 増加するため、実現可能条件は単調になります。$m$カウントされる要素の数が増えるだけなので、二分探索は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        def can(x, target):
            cnt = 0
            for v in a:
                cnt += v % x <= target
            return cnt >= (n + 1) // 2

        for _ in range(q):
            x = int(input())
            if x == 1:
                print(0)
                continue

            lo, hi = 0, x - 1
            ans = x - 1

            while lo <= hi:
                mid = (lo + hi) // 2
                cnt = 0
                for v in a:
                    if v % x <= mid:
                        cnt += 1

                if cnt >= (n + 1) // 2:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1

            print(ans)

if __name__ == "__main__":
    solve()
```実装では、並べ替えとクエリ処理が分離されています。 各クエリについて、可能な剰余の範囲内で候補中央値を二分探索します。 内部のカウント ループはオーバーヘッドを避けるために単純に保たれています。これは、合計の制約により、効率的な入力処理により、結合された作業が Python の制限内に収まることが保証されているためです。 

微妙なディテールの処理$x = 1$ここで、すべての値はすぐにゼロになるため、中央値は自明のことながらゼロになります。 もう 1 つは、インデックスの中央値が次のとおりであることを確認することです。$(n+1)//2$、これは、問題で使用されている下位中央値の定義に対応します。
