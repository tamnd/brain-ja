 ## 解決策
 ## 問題の理解

 元々は長方形のグリッドを行ごとに平坦化することによって形成されたバイナリ文字列が与えられています。 グリッドは「美しい」ことが知られています。つまり、その境界セルはすべて`1`そしてすべての内部セルは`0`。 

タスクはグリッドを再構築することではなく、同じ「境界 1、内部 0」構造を尊重しながら、行数と列数が等しい正方形のグリッドから文字列を解釈する方法が存在するかどうかを判断することです。 

したがって、概念的には、互換性条件をチェックしています。文字列を`r × r`grid such that the perimeter is all ones and the inside is all zeros.

 The key constraint is that the string is already fixed; 解釈のみ（次元`r`) 柔軟です。 以来`r^2`は文字列の長さと等しくなければなりませんが、実際に問題となるのは、長さが完全な正方形であるかどうか、そして暗黙の構造が有効な境界パターンと一致するかどうかです。 

テスト全体の入力長の合計は最大 2 · 10^5 と大きいため、すべての解はテスト ケースごとに線形である必要があります。 テストごとに複数の候補グリッドのシミュレーションを行うと、時間がかかりすぎます。 

よくある間違いは、行列を明示的に再構築しようとしたり、グリッドを埋めることで可能な複数の辺の長さをテストしようとしたりすることです。 これは計算の無駄であり、正方形の境界線の構造は一度完全に決定されるため不要です。`r`固定されています。 

## アプローチ

 強引なアイデアは、あらゆる可能な次元を試すことです`r`1から`n`、どうかを確認してください`r × r = n`一致する場合は、グリッドを再構築し、それが有効なボーダー 1 パターンと一致するかどうかを確認します。 このアプローチはすでにほとんど冗長です。`r`は二乗条件を満たすことができますが、複数の候補を試すように一般化したとしても、行列を構築またはシミュレートしてすべてのセルをチェックする必要があり、これは最悪の場合 O(n√n) になります。 

重要な観察は、正方行列は長さが完全な正方形の場合にのみ存在するということです。 これが成立すると、美しい行列の構造が固定されます。最初と最後の行はすべて 1、最初と最後の列はすべて 1、その他はすべて 0 です。 このパターンでは、サイズがわかれば曖昧さは生じません。 したがって、問題全体は、文字列の長さが完全な正方形であるかどうかを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 文字列の長さが正方形のグリッドを形成できるかどうかを判断するだけで済みます。 

1. 整数を読み取る`n`そして文字列`s`。 文字列自体はその長さを超えて使用されません。 
2. の整数の平方根を計算します。`n`。 
3. この整数の根の二乗が正確に返されるかどうかを確認します`n`。 
4. 一致する場合は「Yes」を出力し、一致しない場合は「No」を出力します。 

ステップ 3 の背後にある理由は、有効な正方形グリッドには正確に次のものが必要であるということです。`r × r`セルなので、長さは完全な正方形である必要があります。 

### なぜ効果があるのか

 美しい正方形の行列はその大きさで決まる`r`。 文字列の長さが次の形式でない場合`r^2`、1 と 0 の配置に関係なく、正方形のグリッドはまったく存在できません。 完全な正方形の場合、有効な境界構成は常にそのサイズで構築可能であるため、存在は算術条件のみに依存します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    r = int(math.isqrt(n))
    if r * r == n:
        print("Yes")
    else:
        print("No")
```実装では長さのみに焦点を当てます`n`。 文字列は入力を正しく処理するために読み取られますが、処理されることはありません。 重要な詳細は使用しています`math.isqrt`で発生する可能性のある浮動小数点精度の問題を回避します。`sqrt`。 

よくある落とし穴は、文字列を読み取るときに改行を削除するのを忘れることです。 ここでは厳密に必須ではありませんが、一貫した入力処理を確保することをお勧めします。 もう 1 つの微妙な問題は、浮動小数点平方根とキャストの使用です。これにより、精度誤差により大きな完全平方が誤分類される可能性があります。 整数平方根はそれを完全に回避します。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        r = math.isqrt(n)
        out.append("Yes" if r * r == n else "No")
    return "\n".join(out)
