 ## 解決策
 ## 問題の理解

 特定の数の 1 と 2 で構成される配列の各要素に、合計がゼロになるように正または負の符号を割り当てることが可能かどうかを判断するように求められます。 各テスト ケースは 2 つの整数を提供します。$a$そして$b$、配列内に 1 と 2 がいくつあるかを表します。 出力は、そのような符号割り当てが存在するかどうかに応じて、単純な「はい」または「いいえ」になります。 

制約を考慮すると、$0 \le a,b < 10$、配列のサイズが非常に小さいことがわかります。 これは、割り当ての合計数が$2^{a+b}$を超えることはできません$2^{18} = 262{,}144$最悪の場合。 ただし、この問題は、割り当てをすべて列挙することなく数学的に推論できる構造になっています。 

エッジケースは、1 種類の数値が欠落している場合、または数量が少ない場合に発生します。 たとえば、次の場合$a=0$そして$b=1$、配列は`[2]`そしてゼロに到達する方法はありません。 もう 1 つの微妙なケースは、次のような組み合わせがある場合です。$a=1$そして$b=1$ここで、配列の合計は奇数 (1+2=3) であり、等しい正の寄与と負の寄与に分割することはできません。 これらの小さな奇数/偶数の合計が解決の鍵となります。 

## アプローチ

 単純な総当たりアプローチでは、各要素の「+」記号と「-」記号の可能なすべての組み合わせを反復処理します。 組み合わせごとに合計を計算し、それがゼロに等しいかどうかを確認します。 これは、考えられるすべての符号の割り当てが考慮されるため機能しますが、配列の長さが短い場合でも、やりすぎで洞察力がありません。 

重要な観察は、合計とパリティの分析から得られます。 各 1 は +1 または -1 のいずれかに寄与し、各 2 は +2 または -2 のいずれかに寄与します。 合計がゼロに達するには、すべての数値が整数であり、符号付き整数の合計が正確に釣り合っている必要があるため、合計が偶数である必要があります。 もし$2b + a$(すべての符号が正の場合の合計) が奇数であるため、2 つの等しい部分に分割する方法はありません。 さらに、2 つある場合、2 の倍数でのみ分割できます。これは、次の場合を意味します。$b$が奇数である場合、ゼロに達するには補正するために少なくとも 2 つの 1 が必要です。 そうでなければ不可能です。 もし$b$が偶数の場合、任意の数の 1 をペアにすることも、ゼロ和で省略することもできます。 

この洞察により、反復することなく即座に答えを決定できるようになります。 これにより、テスト ケースごとに定数時間のソリューションが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(a+b)) | O(a+b) | 正しいが不要 |
 | 数学的パリティチェック | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、整数を読み取ります。$a$そして$b$1 と 2 の数を表します。 
2. すべての数値を合計すると、$a + 2b$、奇数である場合は、すぐに「いいえ」を出力します。 奇数の合計を、プラス記号とマイナス記号を使用して 2 つの等しい合計に分割することはできません。 
3. もし$b$偶数の場合は、「はい」を出力します。 2 であっても、常に +2 と -2 のペアに分割できます。 次に、ゼロサムを維持するために、1 を同様にペアにするか、相補的な方法で追加することができます。 
4. もし$b$奇数です、どうか確認してください$a \ge 2$。 2 つの 1 は、対になっていない 2 つの 1 つを補うことができるため、$a \ge 2" の場合は "Yes" を出力します。そうでない場合は、"No" を出力します。
 5. すべてのテスト ケースに対して繰り返します。 

これが機能する理由は、すべての構成を、合計が偶数であるかどうか、および 1 を使用して不均衡な 2 つをペアにすることができるかどうかに帰着できるためです。 実現可能性はパリティ ルールによって完全に決定されるため、個々の符号の割り当てを列挙する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    total = a + 2 * b
    if total % 2 != 0:
        print("No")
    elif b % 2 == 0:
        print("Yes")
    else:
        print("Yes" if a >= 2 else "No")
```このソリューションでは、まずすべての正の数値の合計を計算します。 この合計が奇数の場合、+ と - を組み合わせてもゼロは得られないため、「No」を出力します。 合計が偶数の場合は、2 の数を確認します。 2 つであっても常に完璧なバランスを保つことができます。 2 の数が奇数の場合、残りの 2 と組み合わせるには少なくとも 2 つの 1 が必要です。そうでない場合、ゼロ和は不可能です。 これは、アルゴリズムのチュートリアルで説明されている正確な推論を実装します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        total = a + 2 * b
        if total % 2 != 0:
            output.append("No")
        elif b % 2 == 0:
            output.append("Yes")
        else:
            output.append("Yes" if a >= 2 else "No")
    return "\n".join(output)

# Provided samples
assert run("5\n0 1\n0 3\n2 0\n2 3\n3 1\n") == "No\nNo\nYes\nYes\nNo", "sample 1"

# Custom cases
assert run("3\n0 0\n1 1\n9 0\n") == "Yes\nNo\nYes", "custom small and boundary"
assert run("2\n0 4\n1 5\n") == "Yes\nNo", "even twos and odd twos with insufficient ones"
assert run("1\n2 1\n") == "Yes", "two ones can balance single two"
```| テスト入力 | 期待される出力 | 検証内容 |

|`1 1`|`No`| 奇数の合計をゼロにすることはできません |

|`0 4`|`Yes`| 2 つでも、何も必要ありません |

 ## 特殊なケース

 入力用`0 0`、合計は 0 です。アルゴリズムは次のように出力します。`Yes`空の配列の合計はゼロになるため、これは正しいことです。 入力用`1 1`、合計は 3 (奇数) であるため、アルゴリズムは次のように出力します。`No`。 のために`2 1`、合計は4(偶数)、12は奇数ですが、`a >= 2`、それで印刷されます`Yes`。 これらすべての例は、パリティ チェックとペアリング ロジックがエッジ ケースを正しく処理することを確認します。
