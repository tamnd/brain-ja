 ## 解決策
 ## 問題の理解

 接続された無向グラフがあります。 すべての頂点には数値が格納されており、エッジを通過すると、その 2 つの端点に書き込まれた数値間の絶対差が計算されます。 頂点から歩く前`1`頂点へ`n`、最大でも の数字を置き換えることができます。`k`選択した任意の値を持つ頂点。 課題は、可能な限り最善の交換を行った後、可能な限り最小限の移動コストを見つけることです。 

入力により、グラフ、すべての頂点の初期値、および値を変更できる頂点の最大数が与えられます。 出力は、変更後の最初の頂点から最後の頂点までのパスの可能な最小コストです。 

主な困難は、変更された頂点が任意の値を取る可能性があるという事実に起因します。 実際の新しい数値を直接決定する必要はありません。 パスから少数の頂点を削除するとどのような影響があるかを理解する必要があります。 

グラフのサイズという点では制限は小さいですが、値はそうではありません。 最大 2000 個の頂点と 2000 個のエッジがありますが、`k`は最大でも 10 です。値が 10 に達する可能性があるため、数値に依存した解は不可能です。`10^9`。 二次グラフ処理によるソリューションは許容されますが、考えられるすべてのパスを含むものは許容されません。 

の小さな値`k`は重要な制限です。 グラフ サイズに小さな係数を乗算するアルゴリズムを使用できます。次のようなものがあります。`O(n * k)`状態を確認したり、周囲の深さの経路を探索したりする`k`。 まばらなグラフであっても、指数関数的に多くのパスが含まれる可能性があるため、すべてのパスを列挙することはできません。 

実装を簡単に破壊してしまういくつかの特殊なケースがあります。 

もし`k = 0`、頂点は変更できないため、答えはエッジの重みを備えた通常の最短パスでなければなりません`|a_u-a_v|`。 例えば：```
2 1 0
5 20
1 2
```唯一のパスにはコストがかかります`15`、したがって、答えは次のようになります。```
15
```少なくとも 1 つの自由な変更を常に前提とするソリューションでは、誤ってゼロが出力される可能性があります。 

開始頂点または終了頂点が変更された頂点の中に含まれる場合があります。 考慮する：```
2 1 2
100 200
1 2
```両方の頂点を同じ値に変更できるため、答えは次のようになります。```
0
```パスの内部頂点の変更のみを許可するソリューションでは、このケースは発生しません。 

パスには以下のものを含めることができます`k`頂点はありますが、それでも中間の変更による恩恵を受けます。 例えば：```
4 3 1
1 100 5 10
1 2
2 3
3 4
```頂点の変更`2`に`5`パスコストは次のようになります`9`。 変更された頂点には、隣接する頂点の元の値の 1 つを割り当てる必要はなく、アルゴリズムは任意の置換を許可する必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべてのパスを試し、そのパス上のどの頂点を変更する必要があるかを決定することです。 これは正しいです。パスが修正されると、残る選択肢は最大でも新しい値だけになるためです。`k`頂点。 ただし、頂点が 2,000 しかないグラフであっても、膨大な数の異なるパスが存在する可能性があるため、このアプローチは指数関数的な動作をするため、使用できません。 

この問題をより良く見るには、変更された頂点に割り当てられた正確な値を忘れることです。 パスに変更する頂点がいくつか含まれているとします。 変更された頂点をパスから削除すると、残りの変更されていない頂点が元の順序で表示されます。 連続する 2 つの変更されていない頂点間では、削除されたすべての頂点に 2 つの元の値の間にある値を割り当てることができるため、セグメント全体のコストは 2 つの変更されていない端点の絶対差に正確に相当します。 

たとえば、パス```
A - X - Y - B
```どこ`X`そして`Y`変更され、最小コストがかかります:```
|a[A] - a[B]|
```なぜなら`X`そして`Y`2 つのエンドポイント値から選択できます。 

これにより、問題は、変更されていない頂点間を移動し、スキップされた頂点ごとに 1 単位の変更バジェットを費やす問題に変換されます。 以来`k`はわずか 10 なので、最大でもスキップするパスを知る必要があるだけです`k`頂点。 

可能な変更されていない頂点間の遷移を作成します。 からの移行`u`に`v`からのグラフ パスがある場合に存在します。`u`に`v`その内部頂点はまさに変更された頂点です。 パスに`d`エッジ、消費します`d-1`改造と費用`|a_u-a_v|`。 

開始と終了はそれ自体を変更できるため、特別な処理が必要です。 2 つの仮想頂点を追加します。 仮想開始は、最初の変更されていない頂点の前のパスのプレフィックスが変更された状況を表します。 仮想終了は、変更されていない最後の頂点が変更された後の接尾辞を表します。 これらの遷移にはコストがかからず、スキップされる頂点の数が消費されます。 

この小さな拡張グラフを作成した後、残る問題は、追加リソースを使用した最短経路の問題、つまり、すでに使用されている変更の数です。 リソースは最大 10 なので、状態に対してダイクストラを実行できます。`(vertex, used_changes)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | パス数の指数関数 | O(n) | 遅すぎる |
 | 最適 | O(n(n+m) + nk^2) | O(nk + n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のすべての頂点から幅優先検索を実行しますが、深さの後で停止します。`k + 1`。 

最大でも次の内容を含むパスのみを考慮します。`k`内部頂点が変更されました。 より長い最短パス セグメントを、変更されていない頂点間の 1 つの遷移として使用することはできません。 
2. 元の頂点のペアごとに`u`そして`v`BFSによって発見された`u`、距離が少なくとも 1 つのエッジの場合にトランジションを作成します。 

距離が`d`、 全て`d - 1`internal vertices can be changed. 移行では、`d - 1`変更がありコストがかかる`|a_u - a_v|`。 
3. 仮想開始頂点を追加します。 

仮想的なスタートから、任意の元の頂点に到達できます`v`前にすべての頂点を変更することで`v`頂点からの何らかのパス上で`1`。 頂点からの距離の場合`1`に`v`は`d`、このトランジションは消費します`d`変更もコストもゼロです。 
4. 仮想終了頂点を追加します。 

元の頂点から`u`、その後すべての頂点を変更することで終了できます`u`頂点へのパス上`n`。 距離が`d`、移行には消費されます`d`変更もコストもゼロです。 
5. Run Dijkstra on states`(vertex, number_of_changes_used)`。 

状態は、頂点に到達した後、まさにその数の変更を費やしながら、最小移動コストを保存します。 移行は、新しい変更の数が以下の場合にのみ受け入れられます。`k`。 
6. 答えは、すべての州における仮想フィニッシュまでの最短距離です。`k`使用された改造。 

なぜ効果があるのか:

 不変条件は、すべてのダイクストラ状態が、変更される前にどの頂点を正確に選択した後、頂点に到達するための最適な方法を表すということです。 変更されたセグメントが交差するときはいつでも、重要な情報は 2 つの変更されていないエンドポイントだけです。これは、セグメントのコストをこれらのエンドポイントの絶対差にするために、すべての内部変更値を選択できるためです。 BFS によって生成されたトランジションは、利用可能な変更バジェットを使用できるすべての可能なセグメントを表します。 ダイクストラはそのようなすべての移行を調査し、使用された予算のすべての量に対して最も安価なコストを維持するため、より有効なソリューションを破棄することはできません。 

## Python ソリューション```python
import sys
import heapq
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    INF = 10**30

    jumps = [[] for _ in range(n)]

    for s in range(n):
        dist = [-1] * n
        q = deque([s])
        dist[s] = 0

        while q:
            v = q.popleft()
            if dist[v] == k + 1:
                continue
            for u in g[v]:
                if dist[u] == -1:
                    dist[u] = dist[v] + 1
                    q.append(u)

        for v in range(n):
            if v != s and dist[v] != -1 and dist[v] <= k + 1:
                jumps[s].append((v, dist[v] - 1, abs(a[s] - a[v])))

    start = n
    finish = n + 1
    total = n + 2

    jumps.extend([[], []])

    # From virtual start to first unchanged vertex.
    dist = [-1] * n
    q = deque([0])
    dist[0] = 0
    while q:
        v = q.popleft()
        if dist[v] == k:
            continue
        for u in g[v]:
            if dist[u] == -1:
                dist[u] = dist[v] + 1
                q.append(u)

    for v in range(n):
        if dist[v] != -1 and dist[v] <= k:
            jumps[start].append((v, dist[v], 0))

    # From unchanged vertex to virtual finish.
    dist = [-1] * n
    q = deque([n - 1])
    dist[n - 1] = 0
    while q:
        v = q.popleft()
        if dist[v] == k:
            continue
        for u in g[v]:
            if dist[u] == -1:
                dist[u] = dist[v] + 1
                q.append(u)

    for v in range(n):
        if dist[v] != -1 and dist[v] <= k:
            jumps[v].append((finish, dist[v], 0))

    # The whole path can consist of changed vertices.
    if dist[0] != -1 and dist[0] + 1 <= k:
        jumps[start].append((finish, dist[0] + 1, 0))

    d = [[INF] * (k + 1) for _ in range(total)]
    d[start][0] = 0

    pq = [(0, start, 0)]

    while pq:
        cur, v, used = heapq.heappop(pq)
        if cur != d[v][used]:
            continue

        for u, add_used, cost in jumps[v]:
            nu = used + add_used
            if nu <= k and cur + cost < d[u][nu]:
                d[u][nu] = cur + cost
                heapq.heappush(pq, (d[u][nu], u, nu))

    print(min(d[finish]))

if __name__ == "__main__":
    solve()
```BFS 前処理は、すべての有用な圧縮パス セグメントを構築します。 深さの限界は、`k + 1`変更されていない頂点間の遷移には最大でも次のものが含まれるため、`k`内部頂点を変更しました。 

展開されたグラフには遷移が次のように保存されます。`(destination, extra changes, cost)`。 ダイクストラ段階では、変更された頂点に割り当てられた実際の値を知る必要はありません。 費やされた変更の数のみを追跡します。 

仮想頂点は、エンドポイントの変更を処理します。 これらがないと、ソリューションは頂点が次のように誤って仮定されてしまいます。`1`そして`n`元の値を維持する必要があります。 

すべての費用はおおよその額に達します`10^9 * n`, したがって、Python の整数は自然に使用されます。 アルゴリズムは決して密集したものを構築しません`n x n`マトリックスを使用して、メモリ使用量を管理しやすくします。

 ## 特殊なケース

 のために`k = 0`の場合、前処理ではスキップされた頂点がゼロのトランジションのみが作成されます。 ダイクストラ状態は通常の最短経路状態に崩壊するため、答えは元の重み付き最短経路になります。

100 200
1 2
```仮想開始から仮想終了への直接の移行には 2 つの変更が必要で、コストはゼロです。 これは、両方の頂点を同じ値に変更することを表します。
