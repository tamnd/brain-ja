 ## 解決策
 ## 問題の理解

 ゼロに等しい開始値と、バイナリで書かれたターゲット数値が与えられます。 2 つの算術演算を使用して、最初のゼロをこのターゲットに変換したいと考えています。現在の値に 1 を加算するか、2 を乗算します。 

各操作は物理マシンに関連付けられます。 倉庫の左側に加算機、右側に乗算機があります。 入口から左へ歩くと機械代がかかります`p`、適切な機械コストへ`q`、マシン間を直接移動するとコストがかかります`p + q`。 すべての作業を終えたら、入り口に戻らなければなりません。 

操作を実行するたびに、まず対応するマシンにアクセスし、その操作コストを支払う必要があります (`a`+1の場合、`b`×2）、また、現在の位置からそこに到達するために必要な歩行コストも支払います。 

ターゲットのバイナリ表現により、算術演算のシーケンスが固定されます。 最上位ビットから最下位ビットまでビットを読み取って、効果的に数値を構築します。次のビットに移動するときに左にシフトし (2 を乗算)、ビットが設定されたときに 1 を加算します。 

主要な問題は、算術演算の順序がバイナリ構造によって固定されている一方で、各演算をどこで実行するかは自由に決定でき、マシン間の移動にはコストがかかることです。 

入力サイズは最大 100000 ビットに達するため、考えられるすべての配線選択を明示的にシミュレートしようとするアプローチは排除されます。 操作ごとに分岐したり、マシン状態間の最短パスを繰り返し再計算しようとするソリューションは、時間制限を超えて爆発的に発生します。 各ビットが一定量の作業に寄与する線形構造が必要です。 

ターゲットがゼロの場合、微妙なケースが発生します。 その場合、操作は必要なく、ゼロのコストのみが返されます。 もう 1 つの重要なケースは、すべてのビットが 1 つのマシン タイプのみを使用して処理される場合です。これは、貪欲なソリューションを 1 か所に留まらせようとする可能性がありますが、移動コストが演算コストの節約を支配する可能性があるため、常に最適であるとは限りません。 

## アプローチ

 直接シミュレーションでは、2 進数を構築する各ステップで、加算マシンまたは乗算マシンのどちらに進むかを決定しようとします。 これにより、考えられる移動パターンの数が指数関数的に増加します。 決定にかかるコストは将来の演算に依存するため、特に長時間の乗算の後に時々加算が行われる場合には、枝刈りさえも役に立ちません。 

重要な観察は、プロセスの算術部分がバイナリ表現によって固定されていることです。 長さのある数値の場合`L`、私たちは常に実行します`L-1`乗算とすべての`1`最初のビットの後に加算を実行します。 唯一の自由は、どのマシンが各操作を実行するかです。 

これにより、問題は非常に小さな状態空間にわたる最短経路に変換されます。 どの瞬間においても、関連する情報は、私たちが現在立っている場所、つまり入り口、足し算機、掛け算機だけです。 そこに至るまでの経緯は問題ではありません。将来のコストは、次に必要なマシンと現在の位置によってのみ決まるからです。 

したがって、バイナリ文字列によって引き起こされる一連の操作に対して動的計画法を計算します。 各ステップでは、操作のプレフィックスを実行した後、各場所に滞在するための最小コストが更新されます。

 ## アルゴリズムのチュートリアル

 数値の構築を、バイナリ文字列から派生した一連の固定演算として扱います。 

1. ターゲットが次の場合`"0"`の場合、操作は必要なく、すでに正しい値になっているため、すぐに 0 を返します。 
2. 入口、加算器、乗算器の 3 つの可能な位置を定義します。 これらの各位置に現在立っている間に、処理された操作のプレフィックスを完了するための最小コストを格納する DP 配列を維持します。 
3. 操作の前に、コスト 0 の入り口から開始します。 
4. 最初のビットを個別に処理します。 数値は正なので、最初のビットは常に`1`。 私たちは単一のことを実行しなければなりません`+1`手術。 現在のどの位置からでも加算機に移動し、その位置からの交通費を支払い、その後支払いを検討します。`a`手術のために。 これにより、最初のステップの DP が初期化されます。 
5. 後続の各ビットに対して、最初に 2 による乗算を実行します。これは常に乗算機に移動し、前の位置からの移動コストに加えて支払うことに相当します。`b`。 
6. 現在のビットが`1`、乗算ステップの後に追加演算を実行します。 その場合は加算機に移動して料金を支払う必要があります`a`。 DP は、そのビットに対する両方の操作を順番に考慮することによって更新されます。 
7. すべてのビットを処理した後、3 つの位置のいずれかで終了できますが、入り口に戻らなければなりません。 したがって、すべての最終 DP 状態の最小値と、入り口まで歩いて戻るコストを計算します。 

重要な構造は、各ビットが固定された小さな一連の操作に寄与し、各操作は前の位置と次に必要なマシンにのみ依存するということです。 

### なぜ効果があるのか

 プロセスのどの時点においても、将来のコストに影響を与える情報は、現在の場所とバイナリ構造内の位置だけです。 同じプレフィックスを処理した後に同じマシンで終了する 2 つの実行履歴は、その後のすべての操作で同じ開始状態が見られるため、同等です。 これにより、最適な下部構造が確立されます。つまり、ある状態に到達するための最良の方法は、どのようにしてそこに到達したかに依存せず、DP が次善の履歴を安全に破棄できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def cost_move(frm, to, p, q):
    if frm == to:
        return 0
    if frm == 0:  # entrance
        return p if to == 1 else q
    if to == 0:
        return p if frm == 1 else q
    # between machines
    return p + q

def solve():
    a, b = map(int, input().split())
    p, q = map(int, input().split())
    s = input().strip()

    if s == "0":
        print(0)
        return

    # states: 0 = entrance, 1 = add machine, 2 = mul machine
    dp = [INF, INF, INF]

    # first bit must be '1' in valid input
    ndp = [INF, INF, INF]
    for frm in range(3):
        ndp[1] = min(ndp[1], dp[frm] + cost_move(frm, 1, p, q) + a)
    dp = ndp

    for ch in s[1:]:
        # multiplication step (always)
        ndp = [INF, INF, INF]
        for frm in range(3):
            ndp[2] = min(ndp[2], dp[frm] + cost_move(frm, 2, p, q) + b)
        dp = ndp

        if ch == '1':
            ndp = [INF, INF, INF]
            for frm in range(3):
                ndp[1] = min(ndp[1], dp[frm] + cost_move(frm, 1, p, q) + a)
            dp = ndp

    ans = min(dp[i] + cost_move(i, 0, p, q) for i in range(3))
    print(ans)

if __name__ == "__main__":
    solve()
```DP 配列は、バイナリ文字列の各プレフィックスを処理した後、最もよく知られているコストを追跡します。 フルパスではなく最後の位置のみが重要であるため、更新のたびに以前の状態が上書きされます。 の`cost_move`関数は、入口コスト構造を介したマシン間の直接遷移を含む、すべてのウォーキング ルールをエンコードします。 

よくある実装上の間違いは、乗算ステップの後、明示的に加算のために再び移動しない限り、乗算マシンに留まらなければならないことを忘れていることです。 もう 1 つの頻繁なエラーは、最終的な入口への戻りコストを無視することです。これは、最後の操作とは独立していますが、最後に一度含める必要があります。

 ## 特殊なケース

 入力用`s = "0"`の場合、アルゴリズムはすぐに 0 を返し、すべての DP ロジックをスキップします。 これは正しいです。算術演算は必要なく、移動コストは無関係です。 

次のような単一ビット文字列の場合`"1"`の場合、加算演算は 1 回だけ実行されます。 DPは入口から直接加算機に行く価値があるのか​​、それとも中間状態を考慮する価値があるのか​​を評価しますが、事前構造がないため、結果は1回の移動+運用コストに減り、最適な経路に一致します。 

交互パターンの場合`"1010..."`、DP は、1 台のマシンの近くに留まり、繰り返し移動コストを支払う方が、操作ごとに切り替えるよりも安いかどうかを継続的に比較します。 状態圧縮により、パスを明示的に列挙することなく、そのようなトレードオフがすべて考慮されるようになります。
