 ## 問題の理解

 アリスとボブは、$n \times n$グリッド。 毎ターン、アリスは最初に次の色を発表します。$\{1,2,3\}$。 次に、ボブは空のセルを選択し、別の色のトークンを配置する必要があります。 

端に隣接する 2 つのセルが同じ色になった場合、ボブは即座に負けます。 彼の目標は、そのような競合を避けながらボード全体を埋めることです。 

オリジナルのインタラクティブ バージョンでは、アリスは適応的に色を選択します。 Codeforces で使用されているハッキングされたバージョンでは、アリスの将来の色の選択肢がすべて事前に与えられています。 ボブの動きの有効なシーケンスを出力するだけで済みます。 

ボードのサイズは最大でも$100 \times 100$, したがって、最大でも$10^4$曲がる。 移動ごとに一定量の作業を実行するソリューションであれば、十分に高速です。 課題は計算の複雑さではなく、アリスの選択に関係なく常に正当な動きを構築することです。 

最初の微妙な点は、Bob は単純に 1 つの固定色で貪欲にセルに色を付けることができないということです。 考慮する$n=2$そしてアリスは何度も色を選びます$1$。 ボブが常に色で応答する場合$2$、隣接するセルは最終的に同じ色を受け取り、競合が発生します。 

もう 1 つの簡単な間違いは、ボードを正しく分割しながら、ボブが選択した色がアリスの現在の色と異なっていなければならないことを忘れることです。 セルが色を受け取るグループに属しているとします。$1$。 アリスも発表したら$1$, ボブはその色を使用できないため、一時的に色を使用する必要があります。$3$その代わり。 

3つ目の落とし穴はゲームの終わり近くに現れる。 一方のパーティションが他方のパーティションより先に空になる場合があります。 優先パーティションから常に再生しようとするソリューションは、そのパーティションのセルがなくなると失敗します。 この戦略では、パーティションが 1 つだけ残っている状況を明示的に処理する必要があります。 

## アプローチ

 強引な考え方とは、すべての動きを独立して扱うことです。 アリスの色を考慮して、すべての空のセルとすべての許可された色を検索し、ボードが競合しないようにする手を探します。 このような動きは常に存在しますが、それを証明し、きれいに実行することは困難です。 たとえ毎ターンボード全体をスキャンしたとしても、複雑さはおよそ$O(n^4)$： がある$n^2$ターンごとに検査することができます$O(n^2)$細胞。 と$n=100$、周りに届く$10^8$操作。 

重要な観察は、グリッド グラフの構造から得られます。 チェス盤の色付けにより、セルが 2 つの独立したセットに分割されます。 すべてのエッジは 1 つの黒セルと 1 つの白セルを接続します。 

色を予約するとします$1$すべての黒のセルと色について$2$すべての白血球に対して。 常にその計画に従うことができれば、隣接するセルは反対側のパーティションに属しているため、隣接するセルは自動的に異なる色を持つことになります。 

アリスは一度に 1 つの色だけを防ぎます。 彼女が言うなら$1$、まだ色を配置できます$2$。 彼女が言うなら$2$、まだ色を配置できます$1$。 唯一の困難な状況は、予約された色が使用可能なパーティションがすでに使い果たされている場合に発生します。 

解決策は、次の 2 つのリストを維持することです。 

- 色に関連付けられた 1 つのチェス盤パリティのセル$1$。 
- 色に関連付けられた他のパリティのセル$2$。 

両方のリストが空でない限り、アリスの選択によってどのパーティションを使用するかが決まります。 アリスが言うなら$1$、色からセルを取得します-$2$分割してペイントする$2$。 アリスが言うなら$2$、色からセルを取得します-$1$分割してペイントする$1$。 アリスが言うなら$3$、どちらのパーティションも機能します。 

最終的に 1 つのパーティションが空になります。 その時点で、残りのすべてのセルは他のパーティションに属します。 彼らの控えめな色は、場合によってはアリスによって禁止される場合があります。 そんなときは色を使います$3$その代わり。 残りのすべてのセルは同じチェス盤パーティション内にあるため、どのセルも互いに隣接していないため、色の導入$3$競合を引き起こすことはできません。

### なぜ効果があるのか

 不変条件は、最初のチェス盤パーティションのすべてのセルがいずれかの色を受け取ることです。$1$または、強制された場合は色を付けます$3$。 2 番目のパーティションのすべてのセルはいずれかの色を受け取ります$2$または、強制された場合は色を付けます$3$。 

どちらのパーティションも利用可能ですが、色は使用しません$3$。 各パーティションはその予約された色のみを受け取るため、隣接するセルは常に異なる色になります。 

1 つのパーティションが空になると、残りのすべてのセルが 1 つのチェス盤パーティションに属します。 同じパーティション内の 2 つのセルが隣接することはありません。 予約した色を色に置き換える$3$そのパーティションには隣接するセルがないため、必要に応じて競合が発生することはありません。 

すべての動きはアリスの選択とは異なる色を使用し、すべてのセルは 1 回だけ使用されます。 したがって、同じ色の隣接するセルを作成することなく、ボードは完全に塗りつぶされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    alice = list(map(int, input().split()))

    p1 = []
    p2 = []

    for i in range(n):
        for j in range(n):
            if (i + j) % 2 == 0:
                p1.append((i + 1, j + 1))
            else:
                p2.append((i + 1, j + 1))

    ans = []

    for a in alice:
        if p1 and p2:
            if a == 1:
                x, y = p2.pop()
                ans.append((2, x, y))
            elif a == 2:
                x, y = p1.pop()
                ans.append((1, x, y))
            else:
                x, y = p1.pop()
                ans.append((1, x, y))

        elif p1:
            x, y = p1.pop()

            if a == 1:
                ans.append((3, x, y))
            else:
                ans.append((1, x, y))

        else:
            x, y = p2.pop()

            if a == 2:
                ans.append((3, x, y))
            else:
                ans.append((2, x, y))

    sys.stdout.write(
        "\n".join(f"{c} {i} {j}" for c, i, j in ans)
    )

solve()
```2 つの配列`p1`そして`p2`2 つのチェス盤パーティションの未使用のセルを保管します。 セルを削除するには`pop()`は$O(1)$, したがって、それぞれの動きには継続的な作業が必要です。 

最初のブランチは、両方のパーティションにまだセルが含まれているメイン フェーズを処理します。 アリスの選択によって、どの予約色が利用可能になるかが決まります。 対応するパーティションのセルをすぐに使用します。 

2 番目と 3 番目のブランチはエンドゲームを処理します。 パーティションは 1 つだけ残っているため、可能な限りその予約された色を使用します。 アリスがその色をブロックしたら、その色に切り替えます`3`。 

問題の出力では、次の番号が付けられた行と列が期待されるため、実装では 1 から始まるインデックスを使用して座標を格納します。`1`。
