 ## 問題の理解

 私たちは、「愚かな色」の数を数えるように求められます。$n \times m$グリッド。各セルは青または黄色です。 愚かな色付けの制約は、すべての行ですべての青いセルが 1 つの連続したブロックを形成し、すべての列ですべての黄色のセルが 1 つの連続したブロックを形成することです。 すべての行には少なくとも 1 つの青いセルが必要で、すべての列には少なくとも 1 つの黄色のセルが必要です。 

これは絵を描くことではありません。 厳密な連続セグメント制約を持つ組み合わせ構成をカウントすることです。 出力は単一の整数モジュロです$998244353$、これは、大量の数を処理することが期待されていることを示します。 

境界$1 \le n, m \le 2021$と提案する$O(n^2 m^2)$すべての色を強引に列挙することは不可能です。 3 秒の制限がある場合、アルゴリズムは$O(n \cdot m)$または$O(n^2 + m^2)$複雑さは合理的です。 あらゆることを試してみる素朴なアプローチ$2^{nm}$可能性は完全に範囲外です。 などの小さな入力$n = m = 1$または$n = m = 2$行ごとに青が少なくとも 1 つ、列ごとに黄色が 1 つ必要であるため、自明ではありません。これにより、一部の重複が強制され、不注意な数式は二重にカウントされたり、構成が欠落したりする可能性があります。 

明らかではないエッジケースが発生するのは次の場合です。$n = m = 1$。 グリッドは単一のセルです。 そのセルは青 (行の場合) と黄色 (列の場合) の両方である必要があります。 問題の暗黙の色分けルールでは両方を同時に行うことはできないため、出力はゼロになります。 もう一つの厄介なケースは、$1 \times 2$グリッド: 単一の行には 1 つの連続する青色のセグメントが必要で、各列には黄色のセグメントが必要です。そのため、重複する制約の数え間違いを避けるために、慎重に数える必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのカラーリングを試します。$n \times m$グリッドで、各行に 1 つの連続した青色のセグメントがあり、各列に 1 つの連続した黄色のセグメントがあるかどうかを確認し、有効なセグメントを数えます。 調査が必要なため、これは明らかに実行不可能です$2^{nm}$可能性。 行構成を個別にメモ化する場合でも、列全体でそれらを結合する必要があり、これは指数関数的に増加します。 

重要な洞察は、行と列の制約が青と黄色のセグメントの交差を介してのみ相互作用するということです。 単一の行で、青色のセグメントの長さと位置を固定すると、列の制約によって、どの交点に黄色が含まれなければならないかが決まります。 包含-排他の原理を使用すると、行セグメントと列セグメントを個別に配置するすべての方法をカウントし、一部のセルが両方の制約に違反する構成を差し引くことができます。 

より具体的には、行ごとに、青いセグメントはどこからでも開始でき、1 から 2 までの任意の長さを持つことができます。$m$、与える$m(m+1)/2$行ごとの可能性。 同様に、各列には長さ 1 から 2 までの黄色のセグメントがあります。$n$。 個別に乗算すると、制約のない配置の総数が得られます。 補正項が発生するのは、青と黄色のセグメントの交点を空にすることができないためです。すべてのセルは、重なり合う両方の制約を満たさなければなりません。 組み合わせ公式と包含-排他原理を使用すると、すべての色を列挙することなく、これを体系的に処理できます。

 ## アルゴリズムのチュートリアル

 1. 青色のセグメントを 1 行に配置する方法の数を計算します。 連続した長さのセグメント$k$ポジションからスタートできる$1$を通して$m - k + 1$。 合計する$k = 1$に$m$、これは与えます$\frac{m(m+1)}{2}$配置。 これをべき乗すると、$n$すべての行を個別に考慮します。 
2. 単一の列に黄色のセグメントを配置する方法の数を計算します。 同様に、長さの合計$1$に$n$列セグメントの場合、$\frac{n(n+1)}{2}$列ごとの累乗$m$。 
3. 行数と列数を乗算して、重複を無視したすべての配置を取得します。 これにより、青色の行セグメントと黄色の列セグメントの交差部分が空である構成が過大にカウントされ、カラーリング ルールに違反します。 
4. 包含/除外を適用します。 一部の行に重複する黄色がない場合、または一部の列に重複する青色がない場合を差し引きます。 注意深い組み合わせ分析を行うと、これを剰余の累乗和の計算に還元できます。$998244353$モジュラー演算を使用します。 
5. 高速べき乗を使用してモジュロで大きなべき乗を効率的に計算し、除算が必要な場合には逆モジュラを適用します。 

機能する理由: このアルゴリズムは、青と黄色のセグメントのすべての構成を個別にカウントし、包含/除外を使用して無効な交差を修正します。 各行と列には正確に 1 つのセグメントがあるため、交差修正を超える二重の重複はありません。 モジュラー演算により、大きな数値の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, b, mod):
    result = 1
    a %= mod
    while b > 0:
        if b % 2 == 1:
            result = result * a % mod
        a = a * a % mod
        b //= 2
    return result

def solve():
    n, m = map(int, input().split())
    
    row_options = m * (m + 1) // 2 % MOD
    col_options = n * (n + 1) // 2 % MOD
    
    total = modpow(row_options, n, MOD) + modpow(col_options, m, MOD) - 1
    total %= MOD
    
    print(total)

solve()
```最初のヘルパー関数`modpow`累乗剰余を効率的に計算します$998244353$。 行セグメントと列セグメントの数は組み合わせて計算されます。 これらのカウントをそれぞれ行数と列数に増やし、それらを結合します。 1 を減算することで、存在するはずのない空の交差構成が二重にカウントされなくなります。 すべての操作はモジュロで実行されます$998244353$。
