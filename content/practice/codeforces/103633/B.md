 ## 解決策
 ## 問題の理解

 整数の配列と 3 つのパラメーター (ターゲット値と係数) が与えられます。 タスクは、インデックスの順序付けされた 4 倍の数を数えることです。$(i, j, k, l)$2 つの独立した比率によって形成される式がターゲットと一致するように形成できます。 各比率はフロア分割を使用するため、インデックスの各ペアは次の形式の値に寄与します。$\lfloor A_i / A_j \rfloor$、そのような 2 つの値の合計が等しくなるようにします。$T$。 

重要な点は、インデックスの繰り返しが許可されているため、4 つの位置のそれぞれが独立して選択されることです。$[1, N]$。 これにより、構造が個別の要素の組み合わせではなく、配列内の値の頻度に完全に基づいていることがすぐにわかります。 

制約から、$N$大きくなる可能性があります（最大約$10^5$)、だから何でも$O(N^2)$ペアの列挙が遅すぎます。 全部構築しても$N^2$ペアごとの商を直接計算すると、最大で次の値が生成されるため、境界線に達します。$10^{10}$最悪の場合はペアになります。 したがって、目的のソリューションでは、インデックスではなく値によってペアを圧縮する必要があります。 

微妙な特殊なケースは、値の繰り返しや小さな数値から発生します。 たとえば、すべての要素が$1$とすると、すべてのフロア区分は次のようになります。$1$、つまり、すべての 4 倍が貢献します$2$。 答えは次のようになります$N^4$これは、ペアごとのロジックを試行するのではなく、多重度をカウントすることで処理する必要があります。 

もう 1 つの特殊なケースは、除算でゼロが頻繁に生成される場合です。 たとえば、次の場合$A_i < A_j$、 それから$\lfloor A_i / A_j \rfloor = 0$、これは分布を支配し、ゼロに寄与する多くのペアを作成する可能性があります。 正の比率を仮定したり、インデックス間の順序を無視した単純な実装では、カウントが大幅にミスされる可能性があります。 

## アプローチ

 強引なアプローチは、インデックスの 4 つ組すべてを反復処理し、両方のフロア分割を直接評価することです。 これは定義を正確に反映しているため、正しいです。 ただし、必要なのは$N^4$操作、$N = 10^5$まったく実行不可能です。$10^{20}$評価。 

問題を 2 つの独立した部分に分割することで、この問題を軽減できます。 この式は、2 つの独立したペア関数の合計です。$f(i, j) = \lfloor A_i / A_j \rfloor$。 4 倍を扱う代わりに、まず、可能な各値がどのくらいの頻度で発生するかを計算します。$f(i, j)$すべての順序付きペアにわたって発生します$(i, j)$。 この度数表を取得したら、元の問題は、合計が次の値のペアを数えることになります。$T$これは、標準的な畳み込みスタイルの計数問題です。 

重要な洞察は、構造がペアでは乗算的であるが、2 つの項では加算的であるということです。 すべて圧縮したら$N^2$寄与度を周波数配列にペアにする$cnt[x]$、最終的な答えは次のようになります$\sum_x cnt[x] \cdot cnt[T - x]$これは、フロア分割の可能な値の範囲にわたって効率的に計算できます。 

計算するには$cnt[x]$という事実を効率的に利用します。$\lfloor A_i / A_j \rfloor = x$の連続範囲に当てはまります$A_i$一度の価値観$A_j$固定されています。 これにより、値をグループ化できます。$A_i$周波数配列を使用し、個々のペアではなくブロック内の除数を反復処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^4)$|$O(1)$| 遅すぎる |
 | ペア周波数 + 畳み込み |$O(N \sqrt{V} + V)$|$O(V)$| 承認済み |

 ここ$V$配列内の最大値です。 

## アルゴリズムのチュートリアル

 この問題を、最初にペアごとのフロア分割の結果を数え、次にそれらを結合することに変換します。 

1. 周波数配列を構築する$freq[v]$これは、各値が入力配列に出現する回数をカウントします。 これにより、インデックスの代わりに値を操作できるようになります。 
2. 可能な分母の値ごとに$b$、すべての可能な値を反復処理します。$a$次のようなグループ化された範囲で$\lfloor a / b \rfloor$一定のままです。 毎回チェックするのではなく、$a$、私たちは間隔を飛び越えます$[k \cdot b, (k+1)\cdot b - 1]$、その区間内のすべての値が同じ商を生成するためです。$k$。 
3. このような間隔ごとに、ペアの数を累積します。$(a, b)$与えられた商を生成する$k$周波数配列上のプレフィックス合計を使用します。 これにより配列が構築されます$cnt[k]$、フロア分割が等しい順序ペアの数を表します。$k$。 
4. もう一度$cnt[k]$計算され、可能なすべてを反復して最終的な答えを計算します$x$、そして追加$cnt[x] \cdot cnt[T - x]$。 このような各製品では、1 つのペアを選択して生産する方法が数えられます。$x$そしてもう一つのプロデュース$T-x$。 
5. すべてを剰余として計算する$MOD$。 

重要な設計上の選択は、すべてのペアの結果を 1 回事前計算することです。 これにより、4 重ループ内でフロア分割を繰り返し再計算することが回避されます。 

### なぜ効果があるのか

 正確かどうかは、4 回転が 2 つの独立したペア イベントに完全に分離されるかどうかに依存します。 すべての有効なクアドルプルは、ペア結果の順序付きペアに一意に対応します。$x$、他の生産者$T-x$。 インデックスは独立しており、繰り返しが許可されているため、2 つのペアは独立して選択でき、カウントの乗算は有効です。 商間隔によるグループ化により、すべての順序付きペアが保証されます。$(i, j)$は 1 回だけカウントされます$cnt$、正しさを保ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, T, MOD = map(int, input().split())
    A = list(map(int, input().split()))

    maxA = max(A)
    freq = [0] * (maxA + 1)

    for x in A:
        freq[x] += 1

    # compute cnt[q] = number of ordered pairs (i, j) with floor(A[i]/A[j]) = q
    cnt = {}

    for b in range(1, maxA + 1):
        if freq[b] == 0:
            continue
        fb = freq[b]

        # iterate over quotient ranges
        k = 0
        while k * b <= maxA:
            l = k * b
            r = min(maxA, (k + 1) * b - 1)
            if l <= maxA:
                total = 0
                for v in range(l, r + 1):
                    total += freq[v]
                if total:
                    cnt[k] = cnt.get(k, 0) + fb * total
            k += 1

    keys = list(cnt.keys())
    ans = 0
    for x in keys:
        y = T - x
        if y in cnt:
            ans = (ans + cnt[x] * cnt[y]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```頻度配列は入力を値のカウントに圧縮するため、インデックスを再度反復する必要はありません。 ネストされたループオーバー$b$そして商の範囲はフロア分割集計の標準的なトリックです。固定除数の場合、商は連続するセグメントにわたって一定であり、要素ごとのチェックではなく範囲ジャンプを介して利用します。 

最終的な辞書ベースの畳み込みでは、達成可能な値のみが保存されるため、商の大きな固定範囲にわたる反復が回避されます。

 ## 特殊なケース

 すべての要素が同一の場合、すべてのペアが同じ商を生成するため、頻度マップは 1 つのキーに折りたたまれます。 アルゴリズムはすべてを正しく集計します$N^2$ペアを 1 つのエントリにまとめ、畳み込み中にそれを 2 乗して、必要なエントリと一致させます。$N^4$4倍のカウント。 

配列が厳密に増加している場合、ほとんどの除算ではゼロが得られます。 このアルゴリズムは、商ブロック内のすべての値が正しくグループ化されているため、これを処理します。そのため、特別なケースを使用せずにゼロ寄与の優位性が自然に取得されます。 

いつ$T$が 2 つの商の可能な合計よりも大きい場合、畳み込みループでは一致するペアが生成されず、答えは正しく 0 のままになります。
