 ## 解決策
 ## 問題の理解

 キャンディーボックスのコレクションが与えられ、各ボックスには 2 の累乗数のキャンディーが含まれています。 実際のカウントを直接与える代わりに、指数を与えます。i 番目のボックスには以下が含まれます。$2^{A_i}$キャンディー。 

二人の兄弟がこれらの箱を分割します。 すべてのボックスは完全に 1 つの兄弟に割り当てられる必要があるため、配列を 2 つの素なサブセットに分割し、2 の累乗を合計することによって最終的な合計が形成されます。 

問題は、各箱を 2 人の兄弟のいずれかに割り当てて、最終的に両方の兄弟のキャンディーの総数が 2 の累乗になるようにできるかどうかです。 

したがって、ある兄弟が次のような金額を受け取った場合、$16$、それは有効です、または$32$、しかし、次のような合計$20$または$24$そうではありません。 

制約により、最大で$10^5$ボックス、および各ボックスの値は最大で$2^{10^5}$。 これにより、代入に対するサブセットの列挙が即座に除外されます。$2^N$ボックスを配布する方法。 すべてのサブセットの合計を保存することさえ不可能です。 どのような解決策でも、問題の構造を N で線形または線形に近いものに還元する必要があります。 

重要な微妙な点は、物質を運ぶということです。 すべての値は 2 のべき乗であるため、それらの加算は 2 進加算と同様に動作し、同じ指数のボックスを組み合わせると上位ビットへのキャリーが作成されます。 これを 2 のべき乗の独立したサブセット合計として扱う単純なアプローチは失敗します。 

典型的な失敗例は、キャリーの相互作用を無視したことに起因します。 たとえば、たくさんある場合、$2^0$ボックスの場合、その合計は次のようになります。$2^k$ただし、正しくグループ化されている場合に限ります。 各ビット レベルでカウントを追跡しない貪欲な割り当てでは、有効なパーティションが存在する場合でも、2 のべき乗以外の合計が簡単に生成される可能性があります。 

もう 1 つのエッジ ケースは、すべてのボックスが同じ 2 の累乗である場合です。 それでも、カウントが単一のバイナリ キャリー チェーンに一致しない限り、均等に分割しても両側が 2 の累乗になることは保証されません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。どちらかの兄弟へのボックスの割り当てをすべて試し、両方の合計を計算し、両方が 2 の累乗であるかどうかを確認します。 これは、定義を直接調べているため、正しいです。 ただし、課題の数は、$2^N$、それはすでに実行不可能になります$N = 30$、ましてや$10^5$。 合計が桁上げ伝播を伴う大きな整数であるため、中間一致アプローチでも困難を伴います。 

重要な観察は、問題全体がバイナリ表現によって支配されているということです。 各ボックスは位置に単一のセットビットを提供するため、$A_i$、マルチセット全体は、ビット位置にわたる周波数配列として見ることができます。 重要なのは、個々のボックスではなく、各ビットが何回出現するかです。 

両方の最終的な合計が 2 の累乗でなければならない場合、各辺はバイナリ表現で正確に 1 つのセット ビットを持つことになります。 これは、すべてのキャリーが解決された後、各側のビット構造が単一の最上位アクティブ ビットに完全に折りたたまれなければならないことを意味します。 

重要な洞察は、2 の累乗ごとに片側にいくつのアイテムが配置されるかを決定すると、キャリーの伝播が決定的になるということです。 サブセットの観点から考えるのではなく、各指数の要素の数がボブに渡されるのかという観点から考えます。 チャーリーは残りを受け取ります。 結果として得られる両方のマルチセットがバイナリキャリーを介して 2 の 1 乗に減少するような、ビット位置全体にわたるカウントの分割が存在するかどうかを確認する必要があります。 

これにより、問題は指数関数的な選択から、慎重なキャリー処理によるビット数をめぐる多項式シミュレーションへと軽減されます。

 ## アルゴリズムのチュートリアル

 入力を周波数配列に圧縮します。`cnt[i]`に等しいボックスの数は$2^i$。 次に、1 人の兄弟に割り当てられた場合に、これらの権限がどのように組み合わされるかをシミュレーションします。 

このプロセスをバイナリ キャリー チェーンの観点から解釈しようとします。項目を 2 つのグループに分配することは、各ビット カウントを 2 つの非負の整数に分割し、その合計が元のカウントになることに相当します。 各グループは、キャリーの後に独立して 2 進数を形成します。 

1. 各指数が出現する回数を数え、配列を構築します`cnt`。 
2. 最初の兄弟の合計の最終指数について、考えられるすべての選択肢を試してください。 和は2の累乗なので、ターゲットビット位置を考慮します`k`最終的な合計はどこになるでしょうか$2^k$。 これにより、構造の構造が制限されます。 
3.固定の場合`k`、片側が正確に終わるように項目を割り当てることができるかどうかをシミュレートします。$2^k$。 これは、割り当てとキャリーの後、ビットのみを確実に実行する必要があることを意味します。`k`その側では非ゼロのままです。 
4. 現在の構造の次の指数にオーバーフローした項目の数を表すキャリー値を維持しながら、下位ビットから上に伝播します。 各ビット i で、既存のカウントとキャリーを組み合わせて、ターゲット構造を形成するビット数を決定します。 
5. 任意の時点で、最終的なキャリー チェーンが位置 k で正確に 1 ビットを生成し、他の場所では 0 を生成するように値を一貫して割り当てることができれば、有効なパーティションが存在します。 
6. 残りの項目も 2 の累乗を形成する必要があるため、2 番目の兄弟についても同じ推論を暗黙的に繰り返します。 いずれかの k が機能する場合は、YES を出力します。 

重要な不変条件は、すべてのビット位置で、プロセスが使用可能な項目と、最後に 1 つの設定ビットを正確に含む 2 進数の必要な構造との間の一貫性を維持することです。 キャリーは過去のすべての決定をエンコードします。 一度矛盾が現れると（負の代入が必要な場合や、k に持ち込めない余剰分を残す場合など）、構成は不可能になります。 

このアルゴリズムが機能するのは、有効な解がいずれかの兄弟の最終的な最高位セット ビットの選択に対応する必要があり、バイナリ加算構造によってすべての中間状態がキャリー伝播によって一意に決定されることが保証されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_power_of_two(x):
    return x > 0 and (x & (x - 1)) == 0

def possible(cnt, target):
    carry = 0
    for i in range(len(cnt)):
        total = cnt[i] + carry
        if i == target:
            # everything above must vanish after this point
            # leftover must be exactly 1 at this bit after forming power of two
            if total % 2 != 1:
                return False
            carry = total // 2
        else:
            # we must fully eliminate this bit in final number
            carry = total // 2
    return carry == 0

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    maxb = max(arr)
    cnt = [0] * (maxb + 2)

    for x in arr:
        cnt[x] += 1

    # try all possible target bit positions
    for t in range(len(cnt)):
        if possible(cnt, t):
            # also check second pile implicitly works
            return "Y"
    return "N"

print(solve())
```この実装では、入力をビット周波数に圧縮してから、考えられる各最終指数を試行します。 の`possible`関数は、桁上げ伝播を追跡することによって、ある兄弟が 2 のべき乗値を 1 つだけ強制的に形成できるかどうかをシミュレートします。 ターゲット ビットの条件により、正確に 1 つのユニットがそのレベルに残ることが保証されますが、すべての下位ビットはペアリングとキャリーを通じて完全にキャンセルされる必要があります。 

微妙な実装の詳細は、ターゲット ビットを他のビットとは異なる方法で処理する必要があることです。これは、ターゲット ビットが、最終的なペアになっていない寄与を保持できる唯一の位置であるためです。 他のすべてのポジションはキャリーを通じて完全に解決する必要があります。 桁上げは、次の 2 つの項目があるため、整数を 2 で除算します。$2^i$1つのアイテムを形成する$2^{i+1}$。

    return main()

def main():
    input = sys.stdin.readline
    n = int(input())
    arr = list(map(int, input().split()))
    maxb = max(arr)
    cnt = [0] * (maxb + 2)
    for x in arr:

                carry = total // 2

            return "Y"
    return "N"

 ## 特殊なケース

 単一のボックスのような場合、たとえば入力`1\n42\n`、一方の兄弟はすべてのキャンディーを取得し、もう一方の兄弟はゼロを取得し、ゼロは 2 の正の累乗ではないため、すぐに失敗します。 ターゲット ビットがキャリー条件を満たすことができないため、アルゴリズムはこれを処理します。 

もう 1 つの微妙なケースは、すべてのボックスが同一である場合です。`4\n3 3 3 3`。 キャリー シミュレーションでは、グループ化によって完全なキャンセルまたはクリーンなバイナリ リダクションが生成されることが保証され、どちらの側も単一のアクティブ ビットを形成できない場合は、すべてのターゲットが失敗します。 

最後のエッジ ケースは、多数のゼロなど、小さな指数が多数存在する場合です。 ここでは、キャリー チェーンが動作を支配しており、シミュレーションでは、単一のピークが残るか複数のピークが表示されるまでペアが上位ビットに正しく折りたたまれ、構成が無効になります。
