 ## 解決策
 ## 問題の理解

 私たちには、線に沿った高さで表される 1 次元の風景が与えられています。 それぞれの位置には高さがあり、どの位置が「優れた視点」、つまり自然の視線の法則に基づいて少なくとも一方向から遮るものなく見える位置であるかを判断したいと考えています。 

ある方向からスキャンしたときに、その位置が以前に見たすべての位置よりも厳密に高い場合、その位置はその方向から見えると見なされます。 言い換えれば、そのスキャンの前に同じ高さ以上の点がその点をブロックしない場合、その点は表示されます。 

タスクは、配列の両端からの可視性を考慮したときに、表示される位置の数をカウントすることです。 左側のスキャンまたは右側のスキャンから見える位置は、優れていると見なされます。 

入力は高さの単一の配列です。 出力は、少なくとも 1 つの方向から見えるインデックスの数を表す単一の整数です。 

このタイプの問題に典型的な制約構造は、配列が大きくなる可能性があることを暗示しているため、どのような解も線形時間または線形に近い時間で実行する必要があります。 各要素を他のすべての要素と比較する二次解は、n の 2 乗比較のオーダーで実行されるため、n が数万を超えると明らかに失敗します。 

すべての要素が等しい場合、微妙なエッジケースが発生します。 たとえば、配列が [5, 5, 5, 5] の場合、左側のスキャンの最初の要素のみが表示され、右側のスキャンの最後の要素のみが表示されるため、答えは n ではなく 2 になるはずです。 「可視」を「以前のすべての位置より厳密に小さいわけではない」ものとして扱う単純な解釈では、すべての位置が可視として誤ってマークされてしまいます。 

もう 1 つのエッジケースは、[5, 4, 3, 2, 1] のような配列を厳密に減少させることです。 左からは最初のもののみが表示され、右からは最後のもののみが表示されます。 正解はやはり n ではなく 2 です。 これは、可視性がローカル比較ではなくプレフィックス最大値に依存することを確認するのに役立ちます。 

## アプローチ

 この強引なアイデアは、各方向からの可視性を個別にシミュレートすることです。 左側のスキャンでは、配列を反復処理して、これまでに確認された最大の高さを維持します。 この最大値よりも厳密に大きい値が見つかった場合は、その値を表示可能としてマークし、最大値を更新します。 右側から同じプロセスを繰り返します。 

このアプローチは、可視性の定義を直接モデル化しているため、正しいです。 ただし、各スキャンは O(n) であり、スキャンは 2 回だけ実行されるため、構造的にはすでに最適化されています。 

真の総当たりの代替手段は、各位置をその左側 (および同様に右側) のすべての要素に対してチェックし、ブロック要素が存在するかどうかを確認することです。 その場合、ポジションごとに O(n) の作業が必要になり、合計で O(n²) の操作が必要になります。 n が大きい場合、最悪の場合の入力で数百億回の比較が実行されるため、これはすぐに実行不可能になります。 

重要な点は、完全な履歴は必要なく、各方向の実行最大値だけが必要であるということです。 可視性は、ポイントがそのスキャンで以前のすべての値を超えるかどうかのみに依存することが理解されると、問題は 2 つのプレフィックス最大値の計算に集約されます。 

プレフィックスの最大配列を左から計算し、サフィックスの最大配列を右から計算します。 その位置でプレフィックスの最大値と一致するインデックスは左側から表示され、サフィックスについても同様です。 最終的な答えは、これら 2 つのセットの和集合のサイズです。

 ## アルゴリズムのチュートリアル

1. 各位置に開始点からそのインデックスまでの最大値が格納されるプレフィックス最大配列を計算します。 これにより、左からの可視性がキャプチャされます。これは、その位置での現在の最大値と等しい場合にポイントが表示されるためです。 
2. 各位置に末尾からそのインデックスまでの最大値が格納されるサフィックス最大配列を計算します。 これは、同じロジックで右側からの可視性をキャプチャします。 
3. すべてのインデックスを反復処理し、その値がそのインデックスのプレフィックスの最大値と等しいか、そのインデックスのサフィックスの最大値と等しい場合、その位置を優良としてマークします。 これは、少なくとも 1 方向からの可視性を直接エンコードします。 
4. そのような位置をすべてカウントし、結果を出力します。 

プレフィックスとサフィックスの最大値で十分な理由は、可視性が方向性スキャンの優位性によって完全に決定されるためです。 特定の側からその位置までの最大点ではない点は、その方向の早い段階でより高いまたは同等の要素によってブロックされ、その側から見えないようになっている必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    pref = [0] * n
    suff = [0] * n

    cur = -10**18
    for i in range(n):
        if a[i] > cur:
            cur = a[i]
        pref[i] = cur

    cur = -10**18
    for i in range(n - 1, -1, -1):
        if a[i] > cur:
            cur = a[i]
        suff[i] = cur

    ans = 0
    for i in range(n):
        if a[i] == pref[i] or a[i] == suff[i]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを直接反映しています。 プレフィックス パスは左側からの実行最大値を維持し、サフィックス パスは右側から同じことを行います。 よくある微妙な点は、最大値を更新するときに厳密な比較を使用することです。 使用して`>`の代わりに`>=`等しい高さによって複数の目に見えるピークが作成されず、平坦なセグメントの正確性が維持されます。 

最後のループでは、いずれかの可視性セットのメンバーシップをチェックします。 この結合ロジックは重要です。両側から見える位置を二重にカウントしません。

 ## 特殊なケース

 次のようなすべてが等しい場合:```
4
2 2 2 2
```接頭辞の最大値は [2, 2, 2, 2] になり、接尾辞の最大値は同一です。 インデックス 0 と 3 のみが、スキャン方向で最初に最大値が発生するという条件に一致します。 すべての内部要素は両方向で以前の等しい値によってブロックされるため、アルゴリズムはこれら 2 つのエンドポイントを正確にカウントします。 

次のような厳密に減少する配列の場合:```
5
5 4 3 2 1
```プレフィックスの最大値は [5, 5, 5, 5, 5] であるため、左からインデックス 0 のみが適格となります。 接尾辞の最大値は [5、4、3、2、1] であるため、すべての要素は接尾辞の最大値になるときにのみ右から修飾されます。 ただし、サフィックス最大値は厳密な更新を必要とするため、右からスキャンする場合はインデックス 4 のみが真の新しい最大値となるため、最終的な答えは 2 になります。これにより、可視性が単に単調なサフィックスの一部ではなく、方向性ピークであることに関連付けられていることが確認されます。
