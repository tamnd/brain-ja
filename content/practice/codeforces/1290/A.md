 ## 問題の理解

 数値の配列と、配列から要素を 1 つずつ削除する人々の列が与えられます。 各人は自分の番になると、現在の配列を見て、一番左または一番右の要素を取得します。 要素を取得した後、その人はプロセスから永久に離脱します。 

あなたは所定の位置に座ります$m$この行にあるので、あなたの番はちょうど後になります$m-1$削除はすでに行われています。 何かが始まる前に、最大で次の動作を「ロックイン」することができます。$k$人々: 選択した各人に対して、何が最適であるかに関係なく、常に左端または右端のいずれかを選択するように強制します。 

他のすべての人は敵対的に行動し、あなたにとって最悪の方法で各ステップでどちらかの結末を選択する可能性があります。 

目標は、選択した値を直接最大化することではなく、保証された下限を最大化することです。 最大の値が必要です$x$人々がどれほど制御不能な行動をとったとしても、最終的に選択される要素は常に少なくとも$x$。 

したがって、核心的な難しさは、単一の試合を予測することではなく、最悪の場合の対戦相手の行動の下で安全を確保しながら、最大の「修正」が許可されることです。$k$事前の決定。 

The constraints are small in total size, with total$n$これは、テスト ケース全体で最大 3500 件のテストが行​​われることを示唆しています。$O(n^2)$あるいは$O(n^3)$テスト ケースごとの動的プログラミング ソリューションは許容されるかもしれませんが、指数関数的なものや、すべての戦略の繰り返しシミュレーションを伴うものは許容されません。 

人々が貪欲に行動すると仮定すると、素朴な推論による微妙な失敗例が現れます。 たとえば、対戦相手が常に大きな側を取ると考えている場合、それは間違いです。対戦相手は積極的に最終結果を減らそうとします。これは、後でより悪い構造を強制するために、早い段階で大きな値を犠牲にすることを意味する可能性があります。

## アプローチ

 ブルートフォースアプローチでは、制御されていないプレイヤーのあらゆる可能な決定をシミュレートしながら、最大の選択方法をすべて試します。$k$プレーヤーを固定し、各固定プレーヤーに方向を割り当てます。 各構成について、ゲーム全体をシミュレートし、得られる値を記録します。 

これはすぐに実行不可能になります。 コントロールの決定がなくても、それぞれの$m-1$対戦相手は左か右を選択できるため、$2^{m-1}$可能性。 どちらの選択肢を追加するか$k$コントロールするプレイヤーは、それに加えて組み合わせ爆発を導入します。 

重要な観察は、重要なのは、自分の番が来たときにまだ答えを含むことができる配列のセグメントだけであるということです。 前のプレイヤーはそれぞれ、現在のインターバル サイズをちょうど 1 だけ減らし、各移動は左または右から実行されます。 それでその後$m-1$移動すると、あなたの位置は常に一部の部分配列になります$[L, R]$長さの$n-(m-1)$ただし、どの部分配列が正確であるかは、左/右の選択の順序に完全に依存します。 

プレイヤーをコントロールすると、このシーケンスの 1 つのステップに関する不確実性が取り除かれます。 プロセスを一連の流れとして考えると、$m-1$二者択一の決定では、最大で修正することが許可されています$k$彼らのうち。 残り$m-1-k$決定は敵対的です。 

ここで、重要な変換は視点を逆転することです。順方向にシミュレーションする代わりに、最悪の場合の動作下でも最終間隔にどのような値を強制できるかを尋ねます。 保証できる最良の保証は、ウィンドウのサイズを選択することによって決まります。$m$せいぜい修正することで敵対的な削除から「保護」できるもの$k$その外に移動します。 

これがスライディングウィンドウスタイルのアイデアにつながります。 あなたの番まで生き残ることができる各候補者間隔について、最大でも次のことを保証できるかどうかを尋ねます。$k$削除は境界を維持しながら境界に影響を与えます。 ターゲット間隔が固定されている場合、それを保護するコストは、攻撃者がその間隔を超えてターゲット間隔を縮小するのを何回阻止する必要があるかになります。

 ## アルゴリズムのチュートリアル

 どの値が最終結果として保証されるかを確認するために問題を再定式化します。 ゲームを直接シミュレートする代わりに、答えの候補を想定します$x$すべての要素が以下の値よりも小さいことを確認できるかどうかをテストします。$x$制御可能な数の敵対的な決定を除いて、私たちのターンの前に削除されます。 

1. 値のしきい値によって要素を並べ替えるか、暗黙的に考慮します。 以下のすべての要素が正しいかどうかを決定するものとして問題を扱います。$x$私たちがコントロールできないものを除いて、私たちの順番の前にインターバルを強制的に終了させることができます。 
2. しきい値を修正する$x$要素が以下の場合は「不良」として分類します。$x$。 ゲームは、敵が少なくとも 1 つの悪い要素を最終セグメントまで確実に生き残らせることができるかどうかの問題になります。 
3. 自分のターンに到達する可能性のあるインターバル内にどれだけの不良要素が残っているかという観点からプロセスをシミュレーションします。 後に残る可能性のあるセグメントを表すスライディング ウィンドウを維持します。$m-1$撤去。 
4. 最終間隔からすべての不良要素を除去するために必要な強制除去の最小数を計算します。 悪い要素が可能な間隔の端に現れるたびに、私たちがその動きを制御しない限り、敵対者はそれを保存することを選択する可能性があります。 
5. あなたの位置に関連して、プレフィックスとサフィックスにそのような「悪い保存機会」がいくつ存在するかを数えてください。 制御されていないそれぞれの機会は、潜在的に悪い要素を継続させる可能性がある 1 つの敵対的な選択に対応します。 
6. そのような機会が最大でも数回ある場合$k$、次にしきい値$x$達成可能です。 そうでなければそうではありません。 
7. 二分探索オーバー$x$実現可能性チェックを使用して、有効な最大値を取得します。 

### なぜ効果があるのか

 重要な不変条件は、すべての偏差が以下の値を維持できることです。$x$は、除去シーケンス内の単一の二値決定点に対応します。 このような決定は、1 人のプレイヤーの行動を修正することによってのみ無力化できます。 したがって、実現可能性は、有害な決定点の数が最大でも以下であるかどうかにのみ依存します。$k$、正確な順序とは独立しています。 これにより、ゲームは指数関数的な決定木から重要な選択肢の線形カウントに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, k, a):
    lo, hi = 1, max(a)
    
    def can(x):
        # We try to ensure all elements < x can be avoided in our path
        bad = [1 if v < x else 0 for v in a]
        
        # prefix and suffix counts simulate worst-case survival pressure
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + bad[i]
        
        total_bad = prefix[n]
        
        # If there are too many bad elements overall, we rely on control
        # We check worst-case window that reaches position m
        # left part: m-1 moves before us, right part: remaining
        
        left_bad = prefix[m - 1]
        right_bad = total_bad - left_bad
        
        # In worst case, adversary can preserve bad elements from both sides
        # We need to "fix" enough decisions to prevent their survival
        # Each control removes one harmful choice
        return min(left_bad, right_bad) <= k
    
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid):
            lo = mid
        else:
            hi = mid - 1
    
    return lo

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(solve_case(n, m, k, a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このコードでは、しきい値を達成する可能性を考慮して、答えに対して二分探索を使用します。$x$単調です: 保証できる場合$x$の場合、より小さい値を保証できます。 

実現可能性チェックの内部で、配列を相対的なバイナリ分類に変換します。$x$。 次に、プレフィックスの合計を使用して、位置の前後に「悪い」要素がいくつあるかを数えます。 考え方としては、敵対的な選択によって悪い要素が自分のターンまで存続できるかどうかについては、これらの領域のみが重要であるということです。 

このチェックにより、ゲームは計数問題に単純化されます。制御されていない決定によってあまりにも多くの悪い要素が保存される場合、失敗となります。 それ以外の場合は、最大でも成功します$k$強制的な決断。
