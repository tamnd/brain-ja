 ## 解決策
 ## 問題の理解

 私たちは、`n × n`グリッド。 一部のセルは使用可能です (`.`)、一部のセルは禁止されています (`E`）。 呪文は使用可能なセルにのみキャストできます。 

セルに呪文を唱えるとき`(r, c)`、行内のすべてのセル`r`列内のすべてのセル`c`浄化されていきます。 目標は、可能な限り最小限の数の呪文を使用してグリッド全体を浄化することです。 

少なくとも 1 つの選択された呪文がその行または列を共有している場合、セルは浄化されます。 呪文は 1 つの行と 1 つの列にのみ影響を与えるため、呪文の位置の選択によって、どの行と列が「カバー」されるかが決まります。 

グリッド サイズは最大 100 であるため、二次アルゴリズムや三次アルゴリズムでも簡単に入手できます。 課題はパフォーマンスではなく、ソリューションが存在する場合の特徴となる構造と、ソリューションを構築する方法を発見することです。 

有益な観察は、どの呪文も以前にカバーされていない行を最大 1 つ導入できるということです。 あるので`n`少なくとも行`n`有効な解決策には呪文が必要です。 同じ議論が列にも適用されます。 正確に使用して解決策を見つけることができれば`n`呪文が自動的に最適化されます。 

最もよくある間違いは、すべての行とすべての列を選択したセルで同時にカバーしなければならないと仮定することです。 これは 2 部マッチングの問題のように聞こえますが、問題が実際に必要とするものよりも強力です。 

考慮する：```
2
..
.E
```選択する`(1,1)`そして`(2,1)`列 1 のみを使用しますが、すべての行がカバーされます。 行 1 のすべてのセルは最初の呪文によって浄化され、行 2 のすべてのセルは 2 番目の呪文によって浄化されます。 列 2 に選択した呪文が含まれていない場合でも、グリッド全体が浄化されます。 

もう 1 つの見落としやすいケースは、行に禁止されたセルのみが含まれている場合です。```
2
EE
..
```最初の列では呪文を唱えることはできません。 その行のすべてのセルは依然として精製される必要があるため、それらに到達するには選択された列が必要になります。 残念ながら、行内の両方のセルが禁止されているため、選択した位置をそこに置くことはできません。 正しい答えは、`-1`。 

列には対称的な状況があります。```
2
E.
E.
```列 1 には禁止されたセルのみが含まれます。 列ごとに使用可能なセルを 1 つ選択するという解決策は不可能ですが、行ごとに使用可能なセルを 1 つ選択することはすぐに機能します。 正しいアルゴリズムでは両方の可能性をチェックする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、使用可能なセルのすべてのサブセットを試し、結果として得られる一連の呪文がグリッド全体を浄化するかどうかをテストします。 まである場合`10000`使用可能なセルの場合、検索スペースは`2^10000`、それは完全に不可能です。 

重要なのは、浄化に実際に何が必要かを理解することです。 

すべての行から使用可能なセルを 1 つだけ選択するとします。 次に、すべての行に呪文が含まれます。 呪文はその行全体を浄化するため、グリッドのすべての行が浄化されます。 すべての行が浄化されると、どの列が選択されたかに関係なく、グリッドのすべてのセルが浄化されます。 

これにより、すべての行に少なくとも 1 つの使用可能なセルが含まれる場合は常に有効な解決策がすぐに得られます。 

同じ推論が対称的に機能します。 すべての列に少なくとも 1 つの使用可能なセルが含まれている場合、各列から使用可能なセルを 1 つ選択すると、グリッド全体も浄化されます。 

次に、どちらの条件も当てはまらない場合を考えてみましょう。 完全に次のもので構成される行が存在します。`E`で構成されている列が存在します。`E`。 

その行と列の交点を求めます。 その行では呪文を唱えることができないため、そのセルをその行から浄化することはできません。 その列では呪文を唱えることができないため、その列から浄化することはできません。 したがって浄化は不可能です。 

これにより、完全な特徴が得られます。 

すべての行に少なくとも 1 つの使用可能なセルがある場合は、行ごとに使用可能なセルを 1 つ選択します。 

それ以外の場合、すべての列に少なくとも 1 つの使用可能なセルがある場合は、列ごとに 1 つの使用可能なセルを選択します。 

それ以外の場合は出力`-1`。 

構造は正確に使用します`n`呪文。 どのソリューションでも少なくとも必要なものがあるので、`n`呪文、それが最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n²)) | O(n²) | 遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. すべての行を確認します。 
3. 各行について、使用可能なセルを見つけます。`.`。 
4. 各行に少なくとも 1 つの使用可能なセルが含まれる場合、各行からそのような位置を 1 つ保存し、出力します。 

すべての行が呪文を受け取り、すべてのセルが精製された行に属するため、この解決策は有効です。 
5. 行に使用可能なセルが含まれていない場合は、行ベースの構造を破棄し、代わりに列をチェックします。 
6. 各列について、使用可能なセルを見つけます。`.`。 
7. すべての列に少なくとも 1 つの使用可能なセルが含まれる場合、各列からそのような位置を 1 つ保存し、出力します。 

すべての列は呪文を受け取るため、すべてのセルは浄化された列に属します。 
8. 一部の列にも使用可能なセルが含まれていない場合、出力`-1`。 

### なぜ効果があるのか

 すべての行に使用可能なセルがある場合、各行から使用可能なセルを 1 つ選択すると、正確に`n`呪文。 すべての行は独自の呪文によって浄化されるため、グリッドのすべてのセルが浄化されます。 同じ議論が列にも対称的に当てはまります。 

どちらの構造も存在しない場合、少なくとも 1 つのすべての構造が存在します。`E`行と少なくとも 1 つのすべて -`E`カラム。 それらの交差セルは、呪文のない行と呪文のない列に属します。 どの位置を選択しても浄化できず、浄化は不可能です。 

このアルゴリズムは、有効な解が存在する場合は常に有効な解を返し、それ以外の場合は不可能であることを正確に報告します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    row_ans = []

    ok = True
    for i in range(n):
        pos = -1
        for j in range(n):
            if grid[i][j] == '.':
                pos = j
                break
        if pos == -1:
            ok = False
            break
        row_ans.append((i + 1, pos + 1))

    if ok:
        print("\n".join(f"{r} {c}" for r, c in row_ans))
        return

    col_ans = []

    ok = True
    for j in range(n):
        pos = -1
        for i in range(n):
            if grid[i][j] == '.':
                pos = i
                break
        if pos == -1:
            ok = False
            break
        col_ans.append((pos + 1, j + 1))

    if ok:
        print("\n".join(f"{r} {c}" for r, c in col_ans))
    else:
        print(-1)

solve()
```最初のブロックは行ごとに検索します。 各行について、最初に使用可能なセルが記録されます。 すべての行に 1 つの候補が含まれている場合、それらの位置によって有効な最適な答えがすぐに形成されます。 

行に障害が発生した場合、アルゴリズムは対称列構築に切り替わります。 各列について、最初に使用可能なセルが記録されます。 

出力形式で要求されるため、実装では回答を保存するときに 1 から始まる座標を使用します。 これはオフバイワンミスの最も一般的な原因です。 

もう 1 つの微妙な点は、行ソリューションが見つかったらすぐに出力する必要があることです。 行の構成はすでに最適化されているため、後で列を調べる必要はありません。
