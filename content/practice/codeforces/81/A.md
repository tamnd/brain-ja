 ## 解決策
 ## 問題の理解

 偶発的に繰り返されたキーストロークを含む可能性のある小文字の文字列が与えられています。 2 つの等しい文字が隣接する場合は、両方の文字を削除する必要があります。 1 つのペアを削除した後、新しい隣接する等しいペアが表示される可能性があるため、それらも削除する必要があります。 

このプロセスは、隣接する等しい文字がなくなるまで継続されます。 最後に残った文字列を出力する必要があります。 

たとえば、次の文字列を考えてみましょう。`abccba`。 

まずはペア`cc`消えます:```
abccba -> abba
```新しいペアになりました`bb`隣接する：```
abba -> aa
```ついに：```
aa -> ""
```重要な点は、除去が後でさらに多くの除去を引き起こす可能性があるということです。 元の文字列に表示されているペアのみを削除する解決策は間違っています。 

入力できる長さは`2 * 10^5`これにより、文字列を最初から繰り返し再構築することが直ちに排除されます。 文字列全体を何度もスキャンするアルゴリズムは、二次関数になる可能性があります。 200,000 文字では、`O(n^2)`このアプローチには、制限時間をはるかに超える数百億回の操作が必要になる可能性があります。 

線形または線形に近い解決策が必要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
aaaa
```不用意に実装すると、最初のペアだけが削除されて停止する可能性があります。```
aaaa -> aa
```でも残りは`aa`も消える必要があるため、正しい結果は空の文字列になります。 

もう 1 つの注意が必要なケースは次のとおりです。```
abccba
```最終的にキャンセルされる等号文字は、元の文字列内で隣接していません。 それらは以前に削除された後にのみ隣接します。 連鎖反応を考慮せずにペアを個別に処理するアプローチは、ここでは失敗します。 

3 番目の重要なシナリオは、キャラクターの交代です。```
abababab
```隣接する等しいペアは存在しないため、出力は変更されないままでなければなりません。 アルゴリズムは、隣接しない等しい文字の削除を回避する必要があります。 

最後に、境界動作が重要です。 入力の場合:```
aaab
```最初の 2 つ`a`文字が消えます:```
aaab -> ab
```残ったシングルは`a`留まらなければなりません。 削除後のインデックスの移動が正しくないと、ここでバグが発生することがよくあります。 

## アプローチ

 最も直接的な解決策は、文字列を繰り返しスキャンして、隣接する等しい文字を探すことです。 ペアが見つかったら、そのペアを削除してスキャンを再開します。 

例えば：```
abbaca
```は次のようになります:```
aaca
```それから：```
ca
```このアプローチは、問題ステートメントを正確にシミュレートするため、正しいです。 

問題は効率です。 文字列の途中から文字を削除するとコストがかかり、スキャンを繰り返し再開すると状況が悪化します。 最悪の場合、削除のたびに文字列のほぼ全体をシフトする必要がある可能性があります。 

入力の長さが次のようになっているとします。`n`。 出演させていただく場合がございます`O(n)`削除、および削除ごとに費用がかかる場合があります`O(n)`文字列のコピーまたは再構築にかかる時間。 全体の複雑さは次のようになります。`O(n^2)`。 

と`n = 200000`、二次関数の動作は遅すぎます。 

重要な観察は、新しい文字を処理するときに重要なのは、最後に生き残った文字だけであるということです。 

最終的な文字列を左から右に構築することを想像してください。 

現在のキャラクターが最後に生き残ったキャラクターと異なる場合、それは当面は残っておかなければなりません。 

それが最後に生き残った文字と一致する場合、それらの 2 つの文字はすぐに互いにキャンセルされます。 

この動作はまさにスタックが提供するものです。 

文字列のプレフィックスを処理した後に現在残っている文字を含むスタックを維持します。 

新しい文字を読むとき:

 それがスタックのトップと一致する場合、ペアが消えるため、トップをポップします。 

それ以外の場合は、キャラクターをプッシュします。 

すべての文字は最大 1 回プッシュされ、最大 1 回ポップされるため、直線的な複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適なスタック ソリューション | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のスタックを作成します。 
2. 文字列を左から右に一度に 1 文字ずつ処理します。 
3. 現在の文字について、スタックが空でないかどうか、およびその最上位要素が現在の文字と等しいかどうかを確認します。 
4. それらが等しい場合は、スタックから一番上の要素を削除します。 

これは、連続する等しいペアの削除をモデル化します。 
5. それ以外の場合は、現在の文字をスタックにプッシュします。 

このキャラクターは現在も生き残っており、将来のキャラクターと対話する可能性があります。 
6. すべての文字を処理した後、スタックには残りの文字列が正確に含まれます。 
7. スタック文字を結合し、結果を出力します。 

### なぜ効果があるのか

 スタックには、これまでに確認されたプレフィックスの完全に処理された結果が常に保存されます。 

最初の処理がすでに完了しているとします。`i`文字が正しく表示されます。 キャラクターのとき`i + 1`が到着すると、このキャラクターと現在最後に生き残っているキャラクターとの間で形成できる新しい隣接ペアは 1 つだけです。 

等しい場合は両方とも消えるので、ポップは正しいです。 

異なる場合は、新しいキャラクターを含む削除はまだ不可能なので、押して正解です。 

すべてのステップでプレフィックスの正しく処理された形式が保存されるため、最終的なスタックは完全に縮小された文字列とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    stack = []

    for ch in s:
        if stack and stack[-1] == ch:
            stack.pop()
        else:
            stack.append(ch)

    print("".join(stack))

solve()
```このソリューションはスタックのアイデアに直接準拠しています。 

の`stack`list には、現在のプレフィックスを処理した後に残った文字が格納されます。 

キャラクターごとに`ch`、スタックトップと比較します。 

両方が等しい場合、現在の縮小文字列内で隣接する等しいペアが形成されるため、次のようにして上部を削除します。`pop()`。 

それ以外の場合は、キャラクターは当面存続するため、それを追加します。 

最後に、スタックにはすでに最終的な答えが順番に含まれているため、`"".join(stack)`結果の文字列を効率的に構築します。 

Python リストをスタックとして使用することが重要です。 末尾からの追加とポップは両方とも行われます。`O(1)`操作。 

よくある間違いは、処理中に文字列を繰り返し連結することです。 Python 文字列は不変であるため、連結を繰り返すと新しい文字列が繰り返し作成され、二次計算量まで低下する可能性があります。 

もう一つの微妙なディテールは、`strip()`入力を読み取るとき。 入力行は改行文字で終わっており、その改行が文字列の一部として処理されることは望ましくありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    stack = []

    for ch in s:
        if stack and stack[-1] == ch:
            stack.pop()
        else:
            stack.append(ch)

    print("".join(stack))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("hhoowaaaareyyoouu\n") == "wre", "sample 1"

# minimum size
assert run("a\n") == "a", "single character"

# all equal
assert run("aaaaaa\n") == "", "all characters removed"

# chain reactions
assert run("abccba\n") == "", "multiple cascading removals"

# no removals
assert run("abababab\n") == "abababab", "alternating characters"

# boundary behavior
assert run("aaab\n") == "ab", "remaining character after deletion"

# large-style pattern
assert run("aabbccddeeff\n") == "", "repeated adjacent pairs"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`|`a`| 最小入力サイズ |
 |`aaaaaa`|`""`| 繰り返されるカスケード削除 |
 |`abccba`|`""`| 中間体除去後の連鎖反応 |
 |`abababab`|`abababab`| 削除は発生しません |
 |`aaab`|`ab`| 部分削除後の正しい取り扱い |
 |`aabbccddeeff`|`""`| 複数の独立した隣接ペア |
