 ## 解決策
 ## 問題の理解

 いくつかの写真アルバムがあります。 アルバム`i`含まれています`a[i]`写真。 正確に含む循環ギャラリーを構築する必要があります。`n`写真。 具体的な写真 ID を選択する代わりに、各位置のアルバム番号を出力するだけで済みます。 

ギャラリーは円形なので、すべての位置に 2 つの隣接位置があります。 位置`1`両方の位置に隣接しています`2`そして`n`。 要件は、隣接する位置が常に異なるアルバムからのものでなければならないということです。 

正確に配置する限り、アルバムから写真のサブセットを自由に選択できます。`n`写真の合計枚数はアルバムの利用可能な枚数を超えることはありません。 

制約は十分小さいため、二次関数を処理することができます。`n ≤ 1000`そして`m ≤ 40`、したがって、`O(n^2)`または`O(n log n)`構築は簡単に十分に速くなります。 可能な巡回配置の数はた​​とえ`n = 20`。 

難しいのは、写真を選択することではなく、最初と最後の位置が異なるように写真を配置することです。 線形に動作するシーケンスでも、周期的に失敗する可能性があります。 

次の例を考えてみましょう。```
n = 5
albums = [3, 2]
```素朴な貪欲な人は次のような結果をもたらすかもしれません。```
1 2 1 2 1
```配列内の隣接するペアはすべて異なりますが、最後の位置と最初の位置は両方とも同じです`1`なので、サイクルは無効です。 

もう 1 つの危険なケースは、1 枚のアルバムが大きすぎる場合です。```
n = 6
albums = [6]
```選択された写真はすべて同じアルバムからのものであるため、同等の隣接写真を避けることは不可能です。 

もっと微妙に：```
n = 7
albums = [4, 3]
```有効なサイクルが存在します。```
1 2 1 2 1 2 1
```待ってください。最初と最後の位置が両方とも同じであるため、これは実際には失敗します。`1`。 

サイクルでは、最大のアルバムが次を超えることはできません`n / 2`。 ここ`4 > floor(7/2)`したがって、有効な取り決めは存在しません。 

線形隣接性のみをチェックする不注意な実装では、そのようなケースが誤って受け入れられてしまいます。 

必要以上に利用可能な写真がある場合、もう 1 つの特殊なケースが発生します。 すべての写真を使用する必要はありません。 

例：```
n = 4
albums = [1, 100]
```合計 4 枚の写真だけを選択する必要があります。 周期的な長さの配列は存在しないため、正解は不可能です。`4`せいぜい必要な`2`同じアルバムのコピーですが、アルバム`2`あまりにも重く支配しすぎるアルバム`1`セパレータは 1 つだけ提供されます。 

写真を破棄する可能性があることを理解することが不可欠です。 構築では、まず各アルバムから何枚の写真を撮るかを決定する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 まず使用する写真を選択し、次にすべての順列を試して、隣接する位置が周期的に異なるかどうかを確認します。 

具体的な写真ではなく、アルバムラベルだけを考えても、アレンジの数は膨大です。 と`n = 1000`、 平`1000!`可能性は数え切れないほどあります。 再帰の非常に深くまで多くのプレフィックスが実行可能なままであるため、枝刈りを伴うバックトラッキング検索は依然として爆発的になります。 

ブルート フォースが概念的に機能する理由は、条件が純粋にローカルであるためです。 隣接する位置のみを考慮します。 残念ながら、ローカル制約では検索スペースが十分に削減されません。 

重要な観察は、これが実際には周波数バランスの問題であるということです。 繰り返されるアルバム ラベルを円の周りに配布するだけです。 どのアルバムも何度も出現すると、いつでも有効なアレンジメントを貪欲に構築できます。 

循環配置の場合、どのアルバムも半分以上の位置を占めることはできません。 そうでない場合は、そのアルバムの 2 つのコピーが鳩の穴の原則に従って隣接する必要があります。 

その条件も十分です。 

したがって、問題は次のようになります。 

1. 各アルバムから正確に合計何枚の写真を撮るかを決定します。`n`。 
2. 選択した最大数が最大以下であることを確認します。`n / 2`。 
3. 循環配置を構築します。 

エレガントな構造は、選択したすべてのアルバム ラベルを並べ替え、交互の位置を使用して回答に配置することに基づいています。 

マルチセットが次のようになっているとします。```
1 1 1 2 2 3
```それらを次の位置に配置します。```
0, 2, 4, 1, 3, 5
```並べ替えられたリスト内の等しい要素が離れたインデックスに分散されるため、繰り返されるラベルは自然に分離されます。 

これにより、問題は指数関数的な探索から決定論的な貪欲な構築に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアルバム サイズを読み取ります。 
2. すべてのアルバムについて、最初はできるだけ多くの写真を撮りますが、それ以上は決して撮らないでください。`n / 2`。 

これは、アルバムが`n / 2`回では、サイクル内に 2 つの隣接するコピーが強制されます。 
3. 選択したカウントを合計します。 
4. 選択した合計数がまだ小さい場合`n`、印刷`-1`。 

これは、すべてのアルバムの最大安全量を使用した後でも、`n`写真。 
5. それ以外の場合は、合計が正確になるまで選択したカウントを減らします。`n`。 

任意の陽性数を減らすことができます。 数を減らしても周波数が下がるだけなので、実現可能性が損なわれることはありません。 
6. 選択した数に従って繰り返される各アルバム インデックスを含む配列を構築します。 

例：```
counts = [2,1,3]
```になる```
[1,1,2,3,3,3]
```7. このリストを並べ替えます。 

等しいラベルが連続するため、次の配置ステップが予測可能になります。 
8. 次のサイズの空の回答配列を作成します。`n`。 
9. 最初に偶数のインデックスを入力し、次に奇数のインデックスを入力します。 

次の順序を使用します。```
0, 2, 4, ..., 1, 3, 5, ...
```並べ替えたラベルを 1 つずつこれらの位置に配置します。 
10. 最終的な配置を出力します。 

### なぜ効果があるのか

 重要な不変条件は、アルバム数が次を超えないことです。`n / 2`。 

ソートされたラベルを交互の位置に配置すると、同じアルバムのコピーが少なくとも 1 つの他の位置によって分離されます。 ソートされたリストには同じラベルが連続して現れるため、ラベルを 2 つ離れた位置に配置すると衝突が防止されます。 

残る唯一の危険は、最後のポジションと最初のポジションの間の循環エッジです。 の`max_count ≤ n/2`この条件により、交互配置によって両端に同じラベルが同時にラップされることがないことが保証されます。 

この構造は、円全体に最大周波数をインターリーブすることと同等です。 実現可能条件は必要かつ十分であるため、アルゴリズムが出力しないときは常に`-1`、作成されたアレンジメントは有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    take = [min(x, n // 2) for x in a]

    total = sum(take)

    if total < n:
        print(-1)
        return

    extra = total - n

    for i in range(m):
        dec = min(take[i], extra)
        take[i] -= dec
        extra -= dec
        if extra == 0:
            break

    vals = []

    for i in range(m):
        vals.extend([i + 1] * take[i])

    vals.sort()

    ans = [0] * n

    pos = []

    for i in range(0, n, 2):
        pos.append(i)

    for i in range(1, n, 2):
        pos.append(i)

    for i in range(n):
        ans[pos[i]] = vals[i]

    for i in range(n):
        if ans[i] == ans[(i + 1) % n]:
            print(-1)
            return

    print(*ans)

solve()
```最初の段階では、各アルバムから使用できる写真の数を計算します。 すべてのアルバムのキャップを`n // 2`実現可能性の条件を構築に直接エンコードします。 

その後、選択した合計金額を超える可能性があります`n`複数のアルバムを一緒にすると、使用できる写真がたくさん保存できるからです。 余分なコピーを任意に削除するだけです。 周波数が小さくなると隣接関係が容易になるだけなので、カウントを減らしても新たな競合が発生することはありません。 

の`vals`配列にはアルバム ラベルのマルチセットが格納されます。 配置戦略では同一のラベルがグループ化されることが前提となっているため、並べ替えは重要です。 

ポジションの順序が重要なトリックです。 まずすべての偶数のインデックスを埋めてから、すべての奇数のインデックスを埋めます。 これにより、等しいラベルが自動的に分散されます。 

推論が正しい場合、最後の検証ループは厳密には必要ありませんが、防御チェックとして役立ち、コストのみがかかります。`O(n)`。 

微妙な点の 1 つは、サイクル チェックではモジュロ インデックスが使用されることです。```
ans[(i + 1) % n]
```モジュロを使用しない場合、コードは線形隣接性のみを検証し、最後の位置と最初の位置の間のエッジを見逃してしまいます。

 ## 特殊なケース

 次のことを考慮してください。```
5 2
3 2
```最大許容周波数は次のとおりです。`2`、 なぜなら`n // 2 = 2`。 

キャッピング後:```
2 2
```合計は次のようになります`4`、より小さい`5`、アルゴリズムは次のように出力します`-1`。 

これは正しいです。 奇数の長さのサイクルでは、何らかのアルバムが少なくとも 3 回出現する必要がありますが、長さ 5 のサイクルで 3 枚のコピーがあると必然的に隣接が強制されます。 

次に、次のことを考えてみましょう。```
6 3
6 1 1
```キャッピング後:```
3 1 1
```合計は`5`、まだ下にあります`6`。 

再びアルゴリズムが出力します`-1`。 

直感的には、主要なアルバムにはすべてのコピーの間に区切り文字が必要です。 追加のアルバム 2 枚ではセパレータが 2 つしか提供されず、6 枚の写真を周期的に配置するには不十分です。 

最後に、次のことを考慮してください。```
8 4
2 2 2 100
```キャッピング後:```
2 2 2 4
```合計は`10`, そのため、余分な 2 つを削除します。 

考えられる最終的なカウントセットの 1 つは次のとおりです。```
0 2 2 4
```この構築により、次のような結果が得られます。```
4 2 4 3 4 2 4 3
```最大のアルバムがちょうど半分の位置を占めていますが、それでも安全です。 すべてのコピーは、周期的な境界を越える場合も含めて、別のアルバムによって区切られます。
