 ## 解決策
 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースは、ちょうど 3 文字の非常に短い文字列で構成されます。 タスクは、大文字と小文字を無視した場合に、この文字列が単語「YES」を表すかどうかを判断することです。 大文字と小文字の混合は許可されているため、「yes」、「Yes」、「YEs」などのすべてのバリエーションを受け入れる必要があります。 

出力もテスト ケースごとです。 各入力文字列について、大文字と小文字を区別しない比較で「YES」に一致する場合は確認を出力し、そうでない場合は拒否します。 

制約は非常に小さく、各文字列の長さは 3 で、テスト ケースは最大 1000 個です。 これは、最も直接的な文字ごとの処理であっても、パフォーマンスの観点からは重要ではないことを意味します。 テスト ケースごとに一定の作業を行うソリューションであればどれでも十分であり、文字列を繰り返し変換したり、複数のバリアントと比較したりするなど、多少無駄なアプローチでも快適に通過できます。 

すべての入力が正確に 3 つのアルファベット文字であることが保証されているため、長さや構造に関して厄介な隠れたエッジのケースはありません。 唯一の微妙な点は、大文字と小文字の正規化です。 大文字と小文字を調整せずにリテラル文字列「YES」と比較して等価性をチェックするような単純な比較は、「yes」や「yEs」などの有効な入力に対して失敗します。 もう 1 つの潜在的な間違いは、最初の文字だけを比較したり、大文字小文字が統一されていると仮定した辞書編集トリックを使用したりするなど、文字を部分的にチェックすることです。 

代表的な失敗例は次のとおりです。 

入力:```
yEs
```正しい出力:```
YES
```をチェックする単純な実装`s == "YES"`概念的には文字が一致していてもケースが異なるため、誤って NO が出力されてしまいます。 

## アプローチ

 この問題を考える強引な方法は、単語「YES」の有効な表現を大文字と小文字を混合してすべて列挙することです。 3 つの文字はそれぞれ独立して大文字または小文字にできるため、次のようになります。$2^3 = 8$考えられるバリエーション:

 はい、はい、はい、はい、はい、はい、はい、はい。 

このセットを保存し、クエリごとにメンバーシップを確認できます。 これは正しく、テスト ケースごとに一定時間で実行されますが、このような小さな変換問題では不必要に間接的になります。 また、セットの構築または保存時に回避可能なオーバーヘッドも発生します。 

より明確な観察は、単一の正規化ステップ (すべての文字を同じ大文字と小文字に変換する) を適用すると、すべての有効な文字列が同一になるということです。 入力文字列を小文字または大文字に変換すると、有効なバリアントはすべて正確に「yes」または「YES」になります。 これにより、問題は 1 つの文字列比較に集約されます。 

したがって、複数のパターンを処理する代わりに、各テスト ケースを次のように削減します。 

s を小文字に変換し、「yes」と比較します。 

これが重要な単純化です。ターゲット単語の構造は固定されており、変化の原因は大文字と小文字だけです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 これにより、実行する独立したチェックの数が定義されます。 
2. テスト ケースごとに、3 文字の文字列を読み取ります。 長さが固定されているため、前処理は必要ありません。 
3. 文字列を正規化された形式 (通常は小文字) に変換します。 これにより、大文字と小文字の区別がすべて削除され、論理的に同一の文字列が同じ表現にマッピングされます。 
4. 正規化された文字列をターゲット「yes」と比較します。 それらが正確に一致する場合、入力は「YES」の大文字と小文字を組み合わせたものである必要があるため、「YES」を出力します。 
5. それ以外の場合は「NO」を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、大文字と小文字の変換が多対 1 のマッピングであり、書式設定の違いを除去しながら文字の同一性を保持するという事実に基づいています。 すべての有効な入力文字列は、大文字と小文字の順序に従って「YES」と同じ文字で構成されているため、正規化後はすべて単一の正規形式に折りたたまれます。 文字が異なる文字列は正規化後に「yes」になることはできないため、誤検知が発生することはありません。 

これにより、クリーンな不変式が作成されます。ステップ 3 の後、元の文字列が大文字と小文字の順列が「YES」である場合に限り、文字列は「yes」と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        if s.lower() == "yes":
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に処理します。 の`.lower()`call は適用される唯一の変換であり、均一な比較が保証されます。 入力から改行文字を削除するには、ストリッピングが必要です。 これを忘れると、誤った比較が発生する可能性が高くなります。 

print ステートメントでは大文字の出力が使用されますが、問題ステートメントごとに大文字と小文字が区別されます。 ロジック自体は厳密に正規化された等価性に基づいています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        s = sys.stdin.readline().strip()
        if s.lower() == "yes":
            output.append("YES")
        else:
            output.append("NO")
    return "\n".join(output) + ("\n" if output else "")

# provided samples

 ## 特殊なケース

 エッジ ケースの 1 つは、入力がすでに正しくフォーマットされているものの、大文字と小文字が混在している場合です (「Yes」など)。 アルゴリズムはそれを「はい」に変換し、正常に一致します。 トレースは次のとおりです。 

入力: 「Yes」 → 小文字が「yes」になる → ターゲットと等しい → YES を出力します。 

もう 1 つのエッジ ケースは、「XyZ」のようなまったく無関係な文字列です。 正規化後は「xyz」となり、「yes」と一致しないため、正しく NO が生成されます。 

この問題では固定長の文字列が保証されているため、長さまたは空の入力に関係する構造的なエッジ ケースはありません。そのため、正確さは完全に正規化後の文字の一致に依存します。
