 ## 問題の理解

 私たちにはパイプシステムが与えられています$n$コンセント、各コンセントのサイズ$s_i$。 アルカディは一定量の水を注ぎます$A$システムにアクセスしますが、その前にコンセントのサブセットをブロックすることは許可されています。 その後、水は、そのサイズに比例して、ブロックされていない出口間でのみ分配されます。 

重要なルールは、ブロックされていないコンセントの合計サイズが$S$、次にアウトレット$i$受け取ります$\frac{s_i}{S} \cdot A$水の単位。 私たちの目標は、最初のアウトレットが少なくとも$B$水の単位。 この状態を達成するには、ブロックするコンセントの数を最小限に抑えることが求められます。 

最初の重要な観察は、ブロッキングによって変更されるのは分数の分母のみで、最初の出口の分子は変更されないということです。 最初のアウトレットが受け取る量は、最初のアウトレットを利用可能な状態に保ちながら、残りのサイズの合計をどれだけ小さくできるかによってのみ決まります。 

以来$n$と同じ大きさにすることができます$100{,}000$、ブロックされた穴のすべてのサブセットを試す解決策は不可能です。 すべてのサブセットをチェックする場合でも、$2^n$これは実行可能な限界をはるかに超えています。 サブセットを並べ替えたり合計を繰り返し計算したりしても、少なくとも$O(n^2)$最悪の場合の動作も遅すぎます。 

の制約$A$そして$B$小さいです($\le 10^4$)、しかしそれらは主な制限要因ではありません。 本当のボトルネックは穴の数です。$O(n \log n)$または$O(n)$解決。 

最初の穴が何もブロックせずにすでに十分な水を提供している場合、微妙なエッジケースが表示されます。 たとえば、次の場合$s_1$他と比べて非常に大きい、または$B \cdot \sum s_i \le A \cdot s_1$、その場合、答えはゼロです。 単純なアプローチでは、要素を不必要に削除しようとする可能性があります。 

もう 1 つのエッジケースは、ほぼすべてをブロックする必要がある場合です。 最初のホールを除いて他のすべてのホールが大きい場合、最適な戦略は、ホール 1 のみを保持し、残りをブロックすることです。 分母の大きな穴の影響を無視した誤った貪欲な順序付けは、ここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。ブロックするホールのすべての可能なサブセットを試し、結果として得られる残りのサイズの合計を計算し、最初のホールが少なくとも受信できるかどうかを確認します。$B$水。 サブセットごとに、合計サイズを再計算します。$S$、次に次のことを評価します。$\frac{s_1}{S} \cdot A \ge B$。 これが機能するのは、問題で説明されているプロセスを直接シミュレートするためです。 

ただし、$2^n$サブセット、そして 1 つのサブセットを評価するだけでも時間がかかります$O(n)$素朴にやれば。 これは、完全に実行不可能な指数関数的なアルゴリズムにつながります。$n = 100{,}000$。 

重要な観察は、最初以外のホールをブロックすることは、分母を減らすことによってのみ役立つということです。$S$。 最初の穴で受け取る水を最大化するには、最小限に抑えたいと考えています。$S$つまり、最初に最大の穴を削除する必要があります。 削除された各穴は、削除操作ごとにできる限り分母を減らします。 

これにより、問題は、不等式が成り立つように、最初以外の最大の要素をいくつ削除するかを選択することに変わります。 他の穴を降順に並べ替えたら、条件が満たされるまで貪欲に 1 つずつ削除していきます。

 ## アルゴリズムのチュートリアル

 最初の穴のサイズは常に保持され、最終的な分数の分子を直接決定するため、このサイズを分離します。 

これは何かをブロックする前の開始分母であるため、すべてのホール サイズの最初の合計を計算します。 

ブロックする必要がないことを確認することで、ブロックが必要かどうかを確認します。$A \cdot s_1 \ge B \cdot S$。 これがすでに成立している場合は、ブロックするだけで効果が減少するため、すぐにゼロを返すことができます。$S$、しかし、私たちはすでに満足しています。 

最初の穴を除くすべての穴を収集し、サイズの降順に並べ替えます。 この順序により、ホールを削除するときに常に可能な限り積極的に分母を減らすことができます。 

次に、ソートされたリストを反復処理して、合計から一度に 1 つずつ穴を削除し、実行した削除の数を数えます。 取り外しのたびに、状態が次のとおりであるかどうかを確認します。$A \cdot s_1 \ge B \cdot S$満足しています。 初めて true になったときに停止し、削除された穴の数を返します。 

### なぜ効果があるのか

 このプロセスでは明確な不変条件が維持されます。どのステップでも、最大のものは正確に削除されています。$k$最初以外のすべてのホールの中のホール。 これにより、現在の合計が$S$を削除することで達成可能な最小の合計です。$k$穴。 条件のみに依存するため、$S$、最小化する$S$固定数の除去の場合、 が最適であるため、最初に不等式が成立するときは、必要な除去の最小数に相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B = map(int, input().split())
    s = list(map(int, input().split()))
    
    s1 = s[0]
    others = s[1:]
    
    total = sum(s)
    
    if A * s1 >= B * total:
        print(0)
        return
    
    others.sort(reverse=True)
    
    removed = 0
    for x in others:
        total -= x
        removed += 1
        if A * s1 >= B * total:
            print(removed)
            return

    print(n - 1)

if __name__ == "__main__":
    solve()
```この解決策は、入力を読み取り、最初の穴を残りの穴から分離することから始まります。 最初の穴は決してブロックされず、その寄与はプロセス全体を通じて一定のままであるため、これは重要です。 

合計を一度計算し、それを分母として使用します。 早期終了チェックにより、初期構成がすでに要件を満たしている場合、不必要な並べ替えと反復が回避されます。 

残りの穴を降順に並べ替えることで、各除去によって分母が最大限に削減されることが保証されます。 反復中、合計を継続的に更新し、浮動小数点エラーを回避するために相互乗算形式で不等式をチェックします。 

最後のフォールバック`n - 1`他のすべての穴を削除しても不十分な場合にのみトリガーされます。これは、最初の穴だけが残っている場合に相当します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, A, B = map(int, input().split())
    s = list(map(int, input().split()))
    
    s1 = s[0]
    others = s[1:]
    total = sum(s)
    
    if A * s1 >= B * total:
        return "0\n"
    
    others.sort(reverse=True)
    removed = 0
    
    for x in others:
        total -= x
        removed += 1
        if A * s1 >= B * total:
            return str(removed) + "\n"
    
    return str(n - 1) + "\n"

 ## 特殊なケース

 エッジケースの 1 つは、ブロッキングが必要ない場合です。 のような入力の場合$n=1$、$s_1$が唯一の穴であり、分母は決して変化しないため、条件は 1 回チェックされ、すぐに 0 が返されます。 アルゴリズムは、初期の不等式チェックを通じてこれを処理します。 

もう 1 つのエッジ ケースは、他のすべての穴が最初の穴と比較して極端に大きい場合です。 このような場合、貪欲ループはそれらをすべて削除します。 たとえば、次の場合$s = [1, 100, 100, 100]$、最初の合計は 301 であり、条件は失敗します。 100 を 3 回取り除くと合計は 1 になり、条件は自明に満たされます。 アルゴリズムは正しく 3 を返します。これは、除去の数が少ないほど分母が大きくなるため最適です。 

最後のエッジケースは、直接実装した場合に浮動小数点エラーが発生する可能性がある場合です。 このソリューションは、不等式の両辺を乗算することでこれを完全に回避し、すべての比較が整数を使用して行われるようにし、最大入力サイズでもロジックを安定させます。
