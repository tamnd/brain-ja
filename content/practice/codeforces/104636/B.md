 ## 解決策
 ## 問題の理解

 一連のカフェ訪問が与えられ、各数字はその時点でヴラドが訪れたカフェのインデックスを表します。 カフェは繰り返すことができます。つまり、ヴラドは同じカフェを複数回訪れる可能性がありますが、私たちが気にするのは訪問の順序だけです。 

タスクは、シーケンスに表示されるすべてのカフェの中で、最近の訪問が最も早いカフェを特定することです。 より簡単に言うと、それぞれのカフェについて、最後に訪問されたのはいつなのかを調べ、最後に訪問されたのが最も過去にあるカフェを探します。 

この制約により、最大 200,000 回の訪問が許可されるため、個別のカフェごとに配列を繰り返しスキャンするソリューションは遅すぎます。 二次アプローチでは、カフェごとに配列全体をスキャンする必要があり、最悪の場合、約 4 × 10^10 の演算にまで低下する可能性があり、これは 2 秒では実現できません。 これにより、私たちは直ちに線形または線形に近い解決策に向かうことになります。 

複数のカフェが 1 回だけ登場する場合、微妙なエッジケースが発生します。 その場合、最後の訪問もその出現であるため、答えは配列内で最も早く出現するカフェになります。 すべての値が同一である場合、別の特殊なケースが発生します。この場合、答えは自明のことですが、そのカフェです。 

よくある間違いは、最後に発生したものではなく、最初に発生したものを追跡しようとすることです。 たとえば、2 1 2 3 のようなシーケンスでは、カフェ 1 は 1 回出現しますが、必ずしも関連性があるわけではありません。一方、カフェ 2 は 2 回出現し、最後に出現するのは後になります。 正解は、初登場ではなく、最後の順位のみに依存します。 

## アプローチ

 ブルートフォース ソリューションでは、それぞれのカフェを考慮し、配列全体をスキャンし、カフェが表示された最後の位置を記録します。 最後に出現したものをすべて計算した後、その中から最小のものを選択します。 このアプローチは正しいですが、すべての固有のカフェに対してフル スキャンを繰り返します。 k 個の異なるカフェがある場合、最悪の場合の時間計算量は O(nk) になり、すべての値が異なる場合は O(n^2) に縮退します。 

重要な観察は、最後の出現を繰り返し再計算する必要がないということです。 配列内でカフェを見つけるたびに、その格納された位置を上書きできます。 スキャンが終了するまでに、各カフェに保存されている値は、まさにその最後の出現インデックスになります。 これにより、問題はアレイを通過する 1 回のパスと、それに続く記録された位置に対する単純な選択ステップに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (最後の出現追跡) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書または配列を作成する`last`これは、各カフェ インデックスをシーケンス内の最新の位置にマップします。 まだカフェが見つかっていないため、空として初期化します。 
2. 訪問シーケンスを左から右に繰り返します。 ポジションごとに`i`、 店`last[a[i]] = i`。 これにより、カフェを見つけるたびにその前のレコードが上書きされ、最新の位置のみが残るようになります。 
3. シーケンス全体を処理した後、少なくとも 1 回出現するすべてのカフェの最後の出現インデックスが得られます。 
4. 記録されたすべてのカフェをスキャンし、保存されているインデックスが最小のものを選択します。 これは、前回の訪問が最も遠いカフェに相当します。 
5. そのカフェのインデックスを出力します。 

実行中の最小値を維持するのではなく、最後に記録されたカフェをすべてスキャンする理由は、完全なシーケンスを処理した後の最終的な最後の位置しか分からないためです。 

### なぜ効果があるのか

 反復のどの時点でも、`last[x]`まさにカフェの最新の位置です`x`これまでに処理されたプレフィックスの中で。 ループが終了すると、この値は配列全体の真の最後の値になります。 最終的な答えはこれらの最後の出現にのみ依存するため、それらの中で最小のインデックスを選択すると、最後に訪問した時間が最も早いカフェが正確に識別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

last = {}

for i, x in enumerate(a):
    last[x] = i

ans = None
best_pos = 10**18

for x, pos in last.items():
    if pos < best_pos:
        best_pos = pos
        ans = x

print(ans)
```配列の最初のパスでは、カフェから最後に確認されたインデックスまでのマッピングが構築されます。 列挙インデックス`i`当然訪問時間を表します。 各割り当ては以前の位置を上書きします。これは正確さを保証するために不可欠です。 

2 番目のループは、保存された最後の位置を比較します。 最適な位置と対応するカフェの両方を追跡します。 大きな初期値を使用すると、最初の比較が常に成功します。 

よくある落とし穴は、1 ベースのインデックス付けと 0 ベースのインデックス付けを一貫性なく使用することです。 ここでは内部的に 0 から始まるインデックスを使用していますが、相対的な順序のみを比較しているため、最終的な答えはインデックスのベースに関係なく正しいままです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 1 回のパスで最後の出現を記録し、1 回のパスで個別のキーを通過します。 
| スペース | O(n) | 個別のカフェごとに最大 1 つのエントリを保存します。 

Python の線形パスでは 200,000 の演算は些細なものであり、辞書演算は定数時間で償却されるため、このソリューションは制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    last = {}
    for i, x in enumerate(a):
        last[x] = i

    ans = None
    best_pos = 10**18
    for x, pos in last.items():
        if pos < best_pos:
            best_pos = pos
            ans = x

    return str(ans)

# provided samples
assert run("5\n1 3 2 1 2\n") == "3"
assert run("6\n2 1 2 2 4 1\n") == "2"

# minimum size
assert run("1\n7\n") == "7"

# all equal
assert run("5\n9 9 9 9 9\n") == "9"

# strictly increasing distinct
assert run("4\n1 2 3 4\n") == "1"

# last is earliest candidate
assert run("5\n5 4 3 2 1\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 同じ要素 | 最小境界の場合 |
 | すべて等しい | その値 | 繰り返しの上書きの正しさ |

 ## 特殊なケース

 ### 1 回の訪問

 入力:```
1
10
```アルゴリズムストア`last[10] = 0`。 他にエントリは存在しないため、最小値は自明のことながら 10 です。定義上、唯一のカフェが最初と最後であるため、出力は正しいです。 

### すべてのカフェは同じ

 入力:```
5
3 3 3 3 3
```反復ごとに上書きされます`last[3]`ですが、値は 3 のままで、最終位置は 4 です。辞書にはキーが 1 つしかないため、それが自動的に選択されます。 これにより、上書きを繰り返しても正確さに影響が及ばないことが確認されます。 

### どれも個性的なカフェ

 入力:```
4
8 1 6 2
```最終的なラストマップは`{8:0, 1:1, 6:2, 2:3}`。 最小インデックスは 0 であるため、カフェ 8 が選択されます。 これは、繰り返しが存在しない場合に最も早い出現を見つけるという解決策が正しく行われていることを示しています。
