 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます`n`これは部分的に解読されたゲノムを表します。 各位置は 4 つのヌクレオチドのいずれかです。`A`、`C`、`G`、`T`、または不明な文字`?`それは交換する必要があります。 

最終的な目標は、この不完全な文字列を、4 つのヌクレオチドがそれぞれまったく同じ回数出現する、完全に指定されたゲノムに変換することです。 全長が固定されているため、これは、デコード後、それぞれの`A`、`C`、`G`、 そして`T`正確に表示されなければなりません`n / 4`回。 もし`n`は 4 で割り切れないので、この条件は最初から不可能です。 

タスクは、そのような補完が存在するかどうかを判断し、存在する場合は、それぞれを置き換えることによって有効な補完を構築することです。`?`。 

入力サイズは非常に小さいため、`n ≤ 255`。 これにより、指数関数的な検索やサブセットに対する複雑な動的プログラミングなどの重い処理が即座に排除されます。 リニアスキャンソリューションで十分です。 

文字列にすでに含まれているヌクレオチドが多すぎる場合、微妙な特殊なケースが発生します。 たとえば、次の場合`n = 8`文字列にはすでに 5 つが含まれています`A`s、それではたとえすべてが`?`非に変わります`A`文字数を減らすことはできないため、回答は不可能です。 もう 1 つの特殊なケースは、数が少なすぎる場合です。`?`4 つのキャラクターすべての不足のバランスをとるため、どのキャラクターも過剰に表現されていない場合でも失敗につながります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの可能なすべての置換を試行します。`?`のそれぞれを割り当てます。`A`、`C`、`G`、 または`T`。 あれば`k`疑問符、これは次のことにつながります`4^k`可能性。 中程度の場合でも`k`、これはすぐに実現可能性を超えてしまいます。 と`n = 255`、最悪の場合は天文学的な規模になります。 

重要な観察は、独立して選択肢を検討する必要がないということです。 重要なのは、各キャラクターの最終的なカウントのみです。 ターゲットが決まっているので、`n / 4`、まず、各ヌクレオチドがすでにいくつ存在するかを計算できます。 これにより、それぞれあと何個必要かが正確に決まります。 

すでに超過しているヌクレオチドがある場合`n / 4`、そのタスクは不可能です。 それ以外の場合は、`?`貪欲に位置を埋めます。割り当てがまだ残っているヌクレオチドを 1 つずつ埋めます。 スロットの合計数は不足の合計と正確に一致するため、有効な解が存在する場合は常に有効な解が生成されます。 

問題の構造は、組み合わせ検索から単純な計算に帰着します。`?`すべてのカウンタが必要な値に達するまで、4 つのカウンタのいずれかに割り当てられる容量の単位にすぎません。

 | --- | --- | --- | --- |
 | ブルートフォース | O(4^k) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各ヌクレオチドがすでにいくつあるか、そしてまだどれだけ必要かを追跡することで問題を解決します。 

1. まず次のことを確認します。`n`4 で割り切れない場合は、すぐに出力します。`===`なぜなら、4 つのシンボルに均等に分配することは不可能だからです。 
2. 次の出現を数える`A`、`C`、`G`、 そして`T`指定された文字列では無視されます`?`。 これにより、ゲノムの現在の部分的な状態が得られます。 
3. ターゲット数を次のように計算します。`target = n / 4`。 これは、最終的な文字列で各ヌクレオチドが到達する必要がある正確な数です。 
4. 各ヌクレオチドについて、その欠損を次のように計算します。`target - current_count`。 欠損が負の場合、つまりヌクレオチドがすでに出現回数が多すぎる場合、出力`===`。 文字の追加は置換によってのみ許可されているため、この状態は修正できません。`?`、既存のものは削除しません。 
5. 文字列を左から右に繰り返します。 私たちが何かに遭遇するたびに、`?`、まだ陽性の欠損があるヌクレオチドに貪欲に割り当てます。 のような自然な秩序`A`、`C`、`G`、`T`動作します。 
6. 割り当て後、対応する不足額を減算します。 これにより、どのヌクレオチドでも必要な数を超えることがなくなります。 
7. すべての文字が処理されたら、結果の文字列を出力します。 

すべての置換は独立した単位であり、唯一の制約は正確な合計を一致させることであるため、貪欲な選択は安全です。 位置の制限や位置間の相互作用はありません。 

### なぜ効果があるのか

 このアルゴリズムは、文字列の接頭辞を処理した後、割り当てられた文字の数と残りの欠損を足したものが各ヌクレオチドに必要なターゲット数に正確に等しいという不変条件を維持します。 それぞれ`?`はまだ容量が残っているヌクレオチドにのみ割り当てられるため、目標を超えることはありません。 総数なので、`?`が不足の合計に等しい場合、すべての不足は最終的に満たされ、不足が存在する場合は完全に有効な割り当てが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    if n % 4 != 0:
        print("===")
        return

    target = n // 4
    cnt = {c: 0 for c in "ACGT"}

    for ch in s:
        if ch != '?':
            cnt[ch] += 1

    for c in "ACGT":
        if cnt[c] > target:
            print("===")
            return

    need = {c: target - cnt[c] for c in "ACGT"}

    for i in range(n):
        if s[i] == '?':
            for c in "ACGT":
                if need[c] > 0:
                    s[i] = c
                    need[c] -= 1
                    break

    print("".join(s))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 最初の実現可能性チェックにより、解決策が構造的に不可能な場合には建設を試行しないことが保証されます。 の`need`辞書は文字ごとの残りの容量を追跡します。 

交換時、スキャン中`A`、`C`、`G`、`T`固定順序では決定論が保証されますが、どのような順序でも機能します。 重要なのは、次の場合にのみ割り当てるということです。`need[c] > 0`、カテゴリの過剰記入を防ぎます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`n`は 4 で割り切れません。たとえば、次のように入力します。`5\nA?G?C`すぐに失敗します。 アルゴリズムは処理の前にこれをチェックするため、正しく出力されます。`===`文字列をスキャンせずに。 

もう 1 つの特殊なケースは過剰表現です。 考慮する`4\nAAAA`。 ここでのカウントは、`A`すでに超えています`1`、ターゲット。 アルゴリズムが検出するのは、`cnt['A'] > target`そして早期終了。 いいえ`?`処理が試行され、誤ったマスキングが回避されます。 

3 番目のエッジケースは、すべての文字が`?`、 のような`4\n????`。 赤字はすべて 1 に等しく、それぞれ`?`貪欲に割り当てられます。 不変式により、4 回の割り当ての後、すべての欠損が正確にゼロに達し、有効なゲノムが生成されることが保証されます。
