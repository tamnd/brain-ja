 ## 解決策
 ## 問題の理解

 グラフは恣意的なものではありません。 これは 3 つの頂点の独立したグループで構成されており、各グループ内で 3 つのペアすべてが接続されて三角形を形成します。 異なるグループ間にはエッジがないため、各三角形を個別に分析でき、各三角形内で行われた決定を組み合わせることで全体的な答えが得られます。 

各エッジには重みがあり、各頂点に 2 つの色のいずれかを割り当てます。 頂点のちょうど半分が赤、半分が青でなければなりません。 エッジの寄与は、その端点が異なる色を持つ場合にのみその重みになります。 それ以外の場合は何も貢献しません。 

タスクは 2 つあります。 まず、すべての有効なカラーリングにおけるそのような「カットエッジの重み」の最大可能合計を決定します。 次に、その最大値に達する色の数を 998244353 を法として数えます。 

という制約が$n \le 3 \cdot 10^5$単位時間制限を使用すると、カラーリングに対する指数関数的な列挙が即座に排除されます。 一つの三角形の中でも$2^3 = 8$割り当てがありますが、世界的には$2^n$、それを探索することは不可能です。 どのような解決策でも、各三角形を少数の意味のある状態に圧縮する必要があります。 

微妙なグローバル制約は、正確に$n/2$赤い頂点。 各三角形は 3 つの頂点を提供するため、三角形の総数は次のようになります。$n/3$、そしてグローバルバランスは三角形全体の決定を結び付けます。 三角形ごとにローカルで貪欲な選択を行うだけでは不十分です。 

典型的な失敗例は、三角形を独立して処理し、それぞれで局所的に最適な色を選択するときに発生します。 たとえば、すべての三角形最適化カラーリングで 2 つの赤と 1 つの青の頂点が使用されているが、一部の三角形がグローバルな半々制約を満たすために反対の構造を必要とする場合、純粋に貪欲なアプローチではカウントしすぎたり、実行不可能な分布が生成されたりします。 

別の失敗は、三角形ごとのカット エッジのみを最大化し、異なる最適な色によって異なる赤カウントが生成される可能性があることを無視した場合に発生します。これは全体的に重要です。 

## アプローチ

 1 つの三角形内には、構造的に異なる色がほんのわずかしかありません。 すべてのカラーリングは、赤色の頂点の数 (0、1、2、または 3) によって分類できます。ケース 0 と 3 は、すべての頂点が同じ色であるため、重みはゼロになります。したがって、すべてのエッジは内部にあります。 興味深いケースは、1-赤-2-青と 2-赤-1-青であり、対称的です。 

強引なアイデアでは、すべてを列挙することになります。$2^3$三角形ごとのカラーリングを実行し、エッジの寄与を計算してから、三角形と赤のカウントに対してグローバル DP を実行します。 これは正しいですが、構造なしで実行すると非効率的です。三角形とすべての可能な赤カウントに対する単純な DP は次のようになります。$O(n^2)$最悪の場合、各三角形はすべての可能な累積赤カウントに遷移を追加するためです。 

重要な観察は、カットウェイトを最大化する場合、各三角形は 2 つの意味のある「最適パターン」のみを提供するということです。赤い頂点が 1 つだけある最適な構成を選択するか、赤い頂点が 2 つだけある最適な構成を選択します。 これら 2 つの状態は相補的な選択肢に対応し、それぞれがベースラインに対して固定ゲインを持ちます。 

したがって、各三角形は二項決定になります。状態 A を選択します (赤い頂点 1 つ、ゲイン$a_i$、方法を数えます$c_i$) または状態 B (2 つの赤い頂点、ゲイン$b_i$、方法を数えます$d_i$）。 グローバル制約は正確に選択されるようになります$n/2$赤い頂点。これは正確に選択することと同じです。$n/6$状態 B の三角形 (それぞれが状態 A と比較して余分な赤に寄与するため)。 

これにより、問題は三角形上のナップザックのような DP に縮小されますが、ひねりが加えられています。完全な重みを追跡する代わりに、「2 つの赤」構成を選択した回数のみを追跡します。 これにより、状態空間が崩壊します。$O(n^2)$に$O(n)$。 

最終的な構造は、三角形の数にわたる 1D DP になり、プレフィックス調整によって暗黙的に最大重みを蓄積しながら、「2-red Choice」の指定数を達成するための方法の数を維持します。

 ## アルゴリズムのチュートリアル

 1. グラフを次のように分割します。$m = n/3$三角形。 各三角形は独立して処理され、2 つの候補構成が抽出されます。1 つはちょうど 1 つの頂点が赤で、もう 1 つはちょうど 2 つの頂点が赤です。 
2. 各三角形について、「1-red」パターンと「2-red」パターンで達成可能な最適な重みを計算します。 これは、選択ごとに異なるカット ウェイトが生じるため、どの頂点がシングルトン カラーであるかを列挙することによって行われます。 
3. 各三角形について、ベースラインに対する赤色カウントの差を保存します。 1 つの赤のパターンをベースライン (0 追加の赤) として扱い、2 つの赤のパターンを +1 の追加の赤として扱います。 
4. ベースライン形式で赤の合計要件を計算します。 すべての三角形が 1-red パターンを使用した場合、赤い頂点の数は次のようになります。$m$。 まさに必要です$n/2 = 3m/2$赤なので正確に追加する必要があります$m/2$追加の赤、つまり 2 つの赤のパターンを正確に選択する必要があります。$m/2$三角形。 
5. DP 配列を定義します。`dp[k]`正確に処理された三角形を使用して達成可能な最大総重量です。$k$特別な赤の選択肢。 
6. 三角形間の遷移: 値を持つ各三角形について`(gain0, gain1)`、DPを右から左に更新します。 状態 0 を選択すると追加されます`gain0`カウントを増やすことなく。 状態 1 を選択すると追加されます`gain1`そしてカウントを 1 増やします。 
7. 最大重み DP とともに、各状態の最大値に達する方法の数を表すカウント DP を維持します。 2 つの遷移が同じ最大重みを生成する場合、それらのカウントは 998244353 を法として合計されます。 

DP が終了した後、答えは、に保存されているウェイの数になります。`dp[m/2]`最大重量構成に対応します。 

### なぜ効果があるのか

 各三角形は、グローバルな赤カウント制約を除いて、独立して寄与します。 各三角形を、すべての最適なローカル動作を完全に捕捉する 2 つの極値構成に圧縮することで、グローバルに最適なソリューションが除外されないようにします。 DP は、残りの唯一の結合、つまり、より高い赤色の構成を使用した三角形の正確な数を強制します。 実行可能なすべてのカラーリングは 1 つの DP パスに正確に対応し、その逆も同様であるため、DP は重複することなくすべての最適なグローバル カラーリングを列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def best_triangle(a, b, c):
    # vertices 0,1,2; edges (0-1)=a, (0-2)=b, (1-2)=c
    # try all 2^3 colorings, but we compress into:
    # (gain, red_count)
    best = {}
    for mask in range(8):
        color = [(mask >> i) & 1 for i in range(3)]
        reds = sum(color)
        cut = 0
        if color[0] != color[1]:
            cut += a
        if color[0] != color[2]:
            cut += b
        if color[1] != color[2]:
            cut += c
        if reds not in best:
            best[reds] = (cut, 1)
        else:
            if cut > best[reds][0]:
                best[reds] = (cut, 1)
            elif cut == best[reds][0]:
                best[reds] = (cut, best[reds][1] + 1)
    # we only care about red=1 and red=2
    return best[1], best[2]

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    m = n // 3

    tris = []
    for i in range(m):
        a, b, c = w[3*i], w[3*i+1], w[3*i+2]
        (w1, c1), (w2, c2) = best_triangle(a, b, c)
        tris.append((w1, c1, w2, c2))

    base = sum(t[0] for t in tris)

    # dp[k] = number of ways
    # we only track counts for optimal weight
    dp = [0] * (m + 1)
    dp[0] = 1

    # value shift tracking not needed explicitly since differences cancel in counting
    # we instead track ways; optimal weight is fixed structure-wise

    for w1, c1, w2, c2 in tris:
        ndp = [0] * (m + 1)
        for j in range(m + 1):
            if dp[j] == 0:
                continue
            # choose type 1 (0 extra red)
            ndp[j] = (ndp[j] + dp[j] * c1) % MOD
            # choose type 2 (+1 extra red)
            if j + 1 <= m:
                ndp[j + 1] = (ndp[j + 1] + dp[j] * c2) % MOD
        dp = ndp

    # we need exactly m/2 extra reds
    print(dp[m // 2] % MOD)

if __name__ == "__main__":
    solve()
```コードは、三角形ごとに、赤い頂点が 1 つと赤い頂点が 2 つだけある構成の間で可能な限り最適なカット ウェイトを計算することから始まります。 内部の野蛮な列挙`best_triangle`各三角形には 8 つの割り当てしかないため、安全です。 

この前処理の後、各三角形は 2 つの選択肢のアイテムになります。1 つのオプションは余分な赤い頂点を 0 つ提供し、もう 1 つは 1 つの追加の頂点を提供します。 DP は、正確に選択できる方法が何通りあるかを数えます。$m/2$2番目のタイプの。 

微妙な点は、実際の重量値が DP 内に保持されていないことです。 これは、各三角形内で各カテゴリの最大達成可能な重みがすでに固定されているため、有効です。 三角形は独立しているため、これらの極大値を合計すると、固定された選択パターンの全体的な最大値が得られます。 

## 実用的な例

 2 つの三角形を持つ小さな合成インスタンスを考えてみましょう。 三角形 1 は 1 つの赤い頂点で最適な構成を好み、三角形 2 は 1 つと 2 つの赤い頂点で同じ最適な構成を持つと仮定します。 

| トライアングル | w1 (赤 1 個) | c1 | w2 (赤2) | c2 |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 2 | 12 | 1 |
 | 2 | 5 | 1 | 5 | 3 |

 DP 状態の進化:

 | ステップ | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | 0 |
 | T1後 | 2 | 1 | 0 |
 | T2後 | 2 | 7 | 1 |

 ここで、 dp[1] は、2-red 構成で 1 つの三角形を正確に選択することに対応します。 もし$m=2$、必要です$m/2=1$, したがって、答えは7です。 

このトレースは、多重度がどのように蓄積されるかを示しています。重みが異なる場合でも、DP 構造は、重みの最大化 (ローカルに処理) と組み合わせ計数 (グローバルに処理) を分離します。

 ## 特殊なケース

 すべてのエッジの重みが等しい縮退三角形は、DP 状態で対称性を発揮します。 このような場合、同じ赤数を持つすべての色は同等になり、アルゴリズムはそれらを正しくグループ化します。`(cut, count)`集約。 

1 つのエッジの重みが他のエッジよりもはるかに大きいなど、極端な不均衡がある場合、最適な構成は特定の頂点分割を強く優先することになります。 内部の列挙`best_triangle`はこれを正しく捕捉し、DP は最適な状態のみを伝播します。 

最後のエッジケースは、すべての三角形が同一である場合に発生します。 次に、DP は効果的に、正確に選択する二項選択肢を数えることになります。$m/2$このアルゴリズムは、DP 遷移に埋め込まれた組み合わせ係数計算に還元され、予想される対称動作と一致します。
