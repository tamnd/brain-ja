 ## 解決策
 ## 問題の理解

 私たちには、それぞれ特定の体力を持つモンスターの列と、2 種類の攻撃が与えられます。1 つは MP ごとにモンスターの体力を 1 減らす基本的な呪文、もう 1 つは任意のパワーで 1 匹のモンスターを対象にできる単回使用の「爆発」です。 体力が呪文のパワー以下の場合、爆発はターゲットを殺し、隣接するモンスターへの連鎖爆発を引き起こします。各二次爆発のパワーは、殺されたモンスターの体力から 1 を引いたものになります。 タスクは、基本的な呪文の詠唱と爆発力の合計である消費 MP の合計を最小限に抑え、最終的に爆発ですべてのモンスターを殺すことです。 

入力は複数のテスト ケースを提供します。 各テストケースはモンスターの数を示します$n$そして彼らの健康状態の数々。 出力は各ケースに必要な最小合計 MP です。 

この制約により、すべてのテスト ケースにわたるモンスターの総数が最大で$3 \cdot 10^5$。 これにより、考えられるすべての基本的な呪文分布を使用して、考えられるすべての爆発ターゲットをシミュレートしようとする単純なアプローチが即座に除外されます。$O(n^2)$あるいはさらに悪い時間の複雑さ。 どのようなソリューションでも、テスト ケースごとのモンスターの数はほぼ線形である必要があり、理想的には$O(n)$、あるいは多分$O(n \log n)$二分探索またはヒープを使用する場合。 

明らかではないエッジケースは、すべてのモンスターの体力が同じである場合、特にモンスターが小さい場合です。 たとえば、すべてのモンスターが 1 の場合、最適な戦略は、基本呪文を 0 回唱え、最後のモンスターを爆発ターゲットとして選択することです。 不用意に貪欲なアプローチをすると、不必要に体力を減らし、MP を過剰に消費しようとする可能性があります。 もう 1 つのトリッキーなシナリオは、中央のピークです: [1, 10, 1]。最適な爆発は中央のモンスターをターゲットにします。 どのモンスターを最初に攻撃するかを間違えると、MP コストが 2 倍になる可能性があります。 

## アプローチ

 強引なアプローチは、モンスターのすべての組み合わせに対して基本的な呪文を唱えてから、考えられるすべての爆発ターゲットをシミュレートし、結果として得られる MP を計算することです。 原理的には正しいですが、オプションの数は、次のように指数関数的に増加します。$n$、制約により完全に実行不可能になります。 たとえば、すべての爆発の単純な線形シミュレーションでも、$n$モンスターはそうでしょう$O(n^2)$最悪の場合、すべての爆発が隣接するすべての爆発に直線的に伝播する場合。 

より迅速な解決策を明らかにする重要な観察は、各モンスターの合計 MP に関連する唯一の寄与は、そのモンスターの体力と、隣接する 2 つのモンスターのうち小さい方との差であるということです。 より正確には、爆発を左右に伝播する波と考えると、爆発はせいぜい隣接するモンスターの体力のうち小さい方の体力から 1 を引いたものを「減算」することができます。 これは貪欲な戦略につながります。モンスターごとに、その爆発によってモンスターを殺し、最大の連鎖を引き起こすように、モンスターを減らすのに必要な MP を計算します。 形式的には、合計 MP は、直前の爆発によるダメージを「吸収」した後の各モンスターの貢献度の合計として表すことができます。これは、各モンスターの max(0, h[i] - min(h[i-1], h[i+1])) の合計を計算することに相当します (エッジで特別な処理が行われます)。 

最適なソリューションでは、シミュレーションを一切回避し、問題をこれらの差を線形時間で計算することに軽減します。 これが機能するのは、爆発の伝播が決定的であるためです。決定するのはどのモンスターをターゲットにするかだけであり、波が始まったら方向転換したり停止したりすることはできないため、隣接する爆発によってまだカバーされていない体力のみを考慮する必要があります。

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、モンスターの数を読み取ります。$n$そして彼らの健康状態$h$。 
2. 変数を初期化する`total_mp`ゼロに。 これで必要なMPが溜まっていきます。 
3. モンスターごとに$i$0から$n-1$、チェーンが到達できるように、爆発前に基本呪文から受ける必要がある実効ダメージを計算します。 有効ダメージは`max(0, h[i] - min(h[i-1], h[i+1]))`。 最初と最後のモンスターの場合、近隣モンスターは 1 つだけ存在するため、その近隣モンスターの体力のみを使用します。 この値を追加します`total_mp`。 
4.全てのモンスターを処理した後、`total_mp`必要な最小 MP を表します。これは、どこでも 1 つの爆発を起こすのに必要なすべての基本呪文の合計です。 現在のテスト ケースに対してこの値を出力します。 

それが機能する理由: 不変条件は、どのモンスターでも、隣接するモンスターからの爆発が最大でカバーできるということです。`neighbor_health - 1`ダメージ。 隣接するモンスターから受ける最大爆発を考慮してモンスターの体力を減らすことで、不必要な基本呪文に MP を浪費することなく、各モンスターが主爆発または伝播爆発によって確実に死亡します。 これにより、すべてのモンスターが確実に死亡すると同時に、最小の合計 MP が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        total_mp = 0
        for i in range(n):
            left = h[i - 1] if i > 0 else 0
            right = h[i + 1] if i < n - 1 else 0
            needed = max(0, h[i] - max(left, right))
            total_mp += needed
        print(total_mp)

solve()
```このソリューションでは、存在しない近傍をゼロとして扱うことでエッジを慎重に処理します。 近隣モンスターから受ける最大ダメージを考慮した上で、各モンスターに必要なMPを計算します。 の使用`max(left, right)`の代わりに`min`いる
