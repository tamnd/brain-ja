 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、次のように接続された非巡回グラフです。`n`頂点。 これらの頂点の一部には最初はチップが含まれており、それぞれが別個の頂点に配置されています。 チップを含むすべての頂点は黒で色付けされ、残りは白で色付けされます。 ゲームはラウンドで進行し、各ラウンドで 1 つのチップを隣接する白い頂点に移動し、その頂点を黒に色付けします。 チップは固定された循環順序で移動します。チップ 1 が最初に移動し、次にチップ 2 というように、チップの後にラップアラウンドします。`k`。 チップに移動できる隣接する白い頂点がない場合、ゲームはチップのために停止します。 目標は、チップが移動できなくなるまで可能な最大移動回数を決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは頂点の数を指定します。`n`、ツリーを形成するエッジ、チップの数`k`、および最初にチップを含む頂点。 出力は、テスト ケースごとに 1 つの整数、つまり可能な最大移動数です。 

制約により、最大で`2 * 10^5`つまり、テスト ケースごとにすべての頂点またはエッジを単純な方法で複数回反復するソリューションは、制限時間を超える可能性があります。 チップを順番に移動する総当りシミュレーションでは、移動ごとに O(n * k) の操作が必要になる可能性があり、これでは遅すぎます。 

明らかではないエッジ ケースには、すべてのチップがリーフまたは隣接する頂点に配置される場合が含まれます。 たとえば、木がパスの場合、`1-2-3-4-5`そして頂点にチップがあります`1`そして`5`、カバレッジを最大化するためにどのチップが次に移動すべきかという最適なシーケンスを考慮しない場合、単純なシミュレーションでは移動が過小評価される可能性があります。 もう 1 つの注意が必要なケースは次のような場合です。`k = n`、すべての頂点にはすでにチップが含まれており、移動は不可能であることを意味します。 単純な解決策では、不必要な動きを試みる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての動きを順番にシミュレートします。 移動ごとに、どのチップが隣接する白い頂点に移動できるかを確認し、ボードの状態を更新します。 これはゲームを忠実に表現しているため、小さな木に適しています。 ただし、チップごとに移動数が O(n) になる可能性があり、テスト ケースごとに O(n*k) 回の操作が行われることになります。 と`n`まで`2*10^5`、これは明らかに非現実的です。 

より迅速な解決策を可能にする重要な観察は、ゲームが基本的にツリー上のマルチソース拡張であるということです。 各チップは波のように広がり、未訪問の頂点を黒く染めます。 チップは周期的に移動するため、各チップは「チップ ターン距離」の点で他のチップよりも近い頂点にのみ到達できます。 ツリー上では、頂点間の距離は一意であるため、すべてのチップから同時に開始する幅優先検索を使用して、どのチップがどの頂点に最初に到達するかを決定できます。 各頂点は、BFS 順序で最初に到達したチップによって色付けされます。 最大移動数は、最終的に黒に着色された白い頂点の総数から最初の頂点の数を引いたものになります。`k`チップス。 

これにより、この問題は、連続的な動きのシミュレーションから、チップの数でスケールされた距離を使用する BFS ベースの色付けの問題に変換されます。 これは、最短パスが一意であるツリー構造を活用し、マルチソース BFS により、最も近いチップがすべての頂点を訪問することが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n*k) | O(n) | n=2*10^5 では遅すぎます |
 | マルチソース BFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定されたエッジを使用してツリーの隣接リストを作成します。 これにより、任意の頂点の近傍を効率的にトラバースできるようになります。 
2. すべてのチップ位置でキューを初期化し、これらの頂点を距離ゼロでマークします。 これは BFS の開始点を表し、その距離によって対応するチップが消費したターン数がカウントされます。 
3. すべてのチップから BFS を同時に実行します。 キューからポップされた各頂点について、未訪問の隣接頂点をすべて考慮します。 現在の頂点の距離に加えた距離に等しい距離を各近傍に割り当てます。`k`(移動のサイクル長) を入力し、キューに入れます。 これは、チップが 1 回に 1 回しか移動できない効果をシミュレートします。`k`曲がる。 
4. 初期チップ位置を除いて、この BFS で到達した頂点の数を数えます。 このカウントは最大移動数を表します。 
5. 各テスト ケースのカウントを返します。 

機能する理由: BFS では、頂点に最初に到達したチップが頂点を訪れます。 グラフはツリーであるため、各頂点への一意のパスがあり、競合は発生しません。 追加`k`移動ごとに、チップ ターンの周期的順序が確実に尊重されます。 移動ルールに基づいて黒く着色できるすべての頂点は、正確に 1 回訪問されます。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u - 1].append(v - 1)
            adj[v - 1].append(u - 1)
        k = int(input())
        chips = list(map(lambda x: int(x) - 1, input().split()))
        
        dist = [-1] * n
        q = deque()
        for c in chips:
            dist[c] = 0
            q.append(c)
        
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + k
                    q.append(v)
        
        moves = sum(1 for d in dist if d > 0)
        print(moves)

if __name__ == "__main__":
    solve()
```隣接リストはツリーを効率的に表します。 デキューを使用すると、BFS の O(1) ポップおよび追加操作が可能になります。 Python リストの頂点インデックスをゼロベースに調整します。 BFS は、ルールに基づいて到達可能なすべての頂点が 1 回だけカウントされることを保証します。 ゼロより大きい距離をカウントすると、初期チップ位置が確実に除外されます。
