 ## 解決策
 ## 問題の理解

 私たちは数直線上の一連の閉区間を扱っており、その一部集合を破棄することができます。 任意の整数座標の場合$x$、そのカバレッジ値を定義します$f(x)$を含む残りのセグメントの数として$x$。 ポイントのカバレッジが他のすべての整数ポイントのカバレッジよりも厳密に大きい場合、そのポイントは独自に最適であると見なされます。 

問題は、選択した座標が一致するようにいくつかのセグメントを削除できるかどうかです。$k$がこの固有の最大点になります。 

より運用上の観点から言えば、オーバーラップ数が$k$は、他のすべての整数位置におけるオーバーラップ数よりも厳密に大きくなります。 

制約は小さいです:両方とも$n$座標値は最大 50 で、テスト ケースは最大 1000 個あります。 これは、全体の座標ドメインが小さく、独立しているため、各テスト ケースの全座標範囲にわたるカバレッジをシミュレートするあらゆるソリューションが実行可能であることを直ちに示唆しています。$n$。 

微妙なエッジケースが現れるのは、$k$最終選択のどのセグメントにも含まれていません。 そのような状況では、$f(k)=0$他のすべてのポイントもカバレッジが少なくとも 0 であるため、$k$厳密には最大値にすることはできません。 したがって、有効なソリューションでは、少なくとも 1 つのセグメントをカバーすることを保証する必要があります。$k$保管されています。 

もう 1 つの重要な観察は、他のポイントでの結合は許可されていないことです。 たとえ$k$他の場所で最高のカバレッジと一致しても、他のすべてを厳密に超えない限り無効です。 

単純な間違いは、適用範囲を最大化するだけでよいと考えることです。$k$。 たとえば、すべてのセグメントをカバーし続けることができます。$k$ただし、これらのセグメントが別のポイントを大きくカバーしており、同等以上のカバー範囲を持つ競合他社が生じる可能性があることを無視してください。 

## アプローチ

 ブルートフォースのアイデアは、セグメントのすべてのサブセットを試し、各サブセットの最大カバレッジ ポイントを計算し、$k$は独自に最適化されています。 これは概念的には簡単です。サブセットごとに、$f(x)$みんなのために$x$かどうかを確認します。$f(k)$厳密に他のすべてよりも優れています。 

ただし、このアプローチにはチェックが必要です$2^n$サブセットごとに、最大 50 個の位置にわたるカバレッジを再計算します。 それはおおよそ次のことにつながります$O(2^n \cdot n \cdot 50)$、それはたとえ小規模であっても実現不可能です。$n$。 

重要な簡素化は、実際に何が妨げになっているかに気づくことから始まります。$k$理想的であることから。 その他のポジションの場合$x \neq k$、次のようなセグメントを保持できる場合$f(x) \ge f(k)$、 それから$k$理想化することはできません。 逆に、すべての競合他社が確実にポイントを獲得できれば、$x \neq k$よりも達成可能なカバレッジが厳密に低くなります$k$、 それから$k$理想的になります。 

以来$k$有効なソリューションの少なくとも 1 つのセグメントでカバーされる必要がある場合、自然な戦略は、どのセグメントを保持するかを修正し、誘発されたカバレッジの違いについて推論することです。 座標は小さいため、すべてのサブセットを反復して実現可能性をチェックすることで、達成可能な最良の構成を直接シミュレートできますが、さらに単純化することもできます。考慮する必要があるのは、次のようなサブセットが存在するかどうかだけです。$k$はカバーされますが、他のすべてのポイントが厳密にカバーされる頻度は低くなります。 

これは、セグメント削除に対してブルートフォースを使用してすべてのサブセットを効率的にチェックすることになりますが、これは制約が少ないため実現可能です。 サブセットごとにカバレッジを計算し、条件を検証します。$O(50n)$、合計を与えます$O(2^n \cdot 50n)$、最悪の場合でもまだ大きいですが、$n \le 50$実際に枝刈りを可能にする。 ただし、より直接的に観察すると、より簡単なチェックが得られます。すべてのセグメントが非影響に寄与するサブセットが存在するかどうかを考慮するだけで済みます。$k$ピークが除去されます。 追加されたセグメントのカバレッジは単調であるため、問題は、誘導された最大カバレッジ ポイントが正確に一致するサブセットが存在するかどうかを確認することになります。$k$これは、制限が小さいため、すべてのサブセットの直接シミュレーションによって効率的に検証できます。 

より明確に受け入れられたソリューションは、各セグメントを保持または破棄するという観点からのみサブセットを列挙し、カバレッジ配列を直接計算できるという事実を利用します。これは、狭い範囲であれば十分に高速です。

## アルゴリズムのチュートリアル

 セグメントの可能なすべてのサブセットを反復処理し、各サブセットを保持するセグメントのセットとして扱います。 

1. Enumerate a bitmask from 0 to$2^n - 1$ここで、各ビットはセグメントが含まれるかどうかを示します。 これは 1 つの候補構成を表します。 
2. 選択したサブセットに対して配列を構築します`cover`サイズ 51 はゼロに初期化されます。 これは、各整数点をカバーする選択されたセグメントの数を保存します。 
3. 選択したセグメントごとに$[l, r]$、増分`cover[x]`みんなのために$x \in [l, r]$。 これは関数を直接計算します$f(x)$現在のサブセットの場合。 
4. かどうかを確認します。$cover[k] > 0$。 そうでない場合は、このサブセットをすぐに破棄します。$k$厳密に最大となる候補となるには、カバーされている必要があります。 
5. すべての値の最大値を計算します。`cover[x]`のために$x \in [1, 50]$。 
6. 次のことを確認します。`cover[k]`はこの最大値に等しく、他の点は同じ最大値に達しないことを意味します。 これにより、厳密な最適化が保証されます。$k$。 
7. いずれかのサブセットがこの条件を満たす場合、YES を出力します。 機能するサブセットがない場合は、NO を出力します。 

正確性は、考えられるすべての削除戦略がセグメントの一部のサブセットに正確に対応するという事実に依存しているため、すべてのサブセットをチェックすることで解空間全体がカバーされます。 

### なぜ効果があるのか

 すべての有効なソリューションはセグメントのサブセットの選択に対応し、カバレッジ関数はそのサブセットによって完全に決定されます。 の条件は、$k$理想的であるかどうかは、整数カバレッジ値間の比較のみに依存し、これらは計算された値によって完全に捕捉されます。`cover`配列。 すべてのサブセットを使い尽くすため、実行可能な構成はすべて列挙内に表示される必要があり、無効な構成は厳密な最大値チェックによって拒否されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(n)]

        ans = False

        for mask in range(1 << n):
            cover = [0] * 51

            for i in range(n):
                if mask & (1 << i):
                    l, r = segs[i]
                    for x in range(l, r + 1):
                        cover[x] += 1

            if cover[k] == 0:
                continue

            mx = max(cover[1:51])

            if cover[k] == mx and cover.count(mx) == 1:
                ans = True
                break

        print("YES" if ans else "NO")

if __name__ == "__main__":
    solve()
```この実装は、サブセット列挙のアイデアを直接反映しています。 各ビットマスクはセグメントの候補選択を構築し、ネストされたループは固定座標範囲にわたるカバレッジを計算します。 

小切手`cover[k] == 0`ターゲット ポイントが少なくとも 1 つの残りのセグメントに含まれている必要があるため、無効なサブセットを早期に削除します。 条件`cover[k] == mx and cover.count(mx) == 1`最大値の厳密な一意性を強制します。 

よくある実装の落とし穴は、エンドポイントが包括的であることを忘れていることです。そのため、ループでは`range(l, r + 1)`。

 ## 特殊なケース

 最初のエッジ ケースは、セグメントがカバーされていない場合です。$k$。 単一セグメントのような入力の場合$[2,2]$と$k=1$、すべてのサブセットは残ります$k$明らかになったので、$f(k)=0$いつも。 アルゴリズムチェック`cover[k] == 0`すべてのサブセットを破棄し、正しく NO を生成します。 

複数の点が常に結合している場合、別のエッジ ケースが発生します。$k$。 周囲の範囲を対称的にカバーするセグメントを考慮します。$k$。 どのサブセットも複数の位置で等しいカバレッジを生成する傾向があり、厳密な一意性条件は満たされません。 列挙は明示的にチェックします`cover.count(mx) == 1`、そのような場合の受け入れを妨げます。 

最後の微妙なケースは、サブセットがより高いピークを生成する場合です。$k$。 たとえ$k$がカバーされている場合でも、別のポイントが同じ最大値に達する場合、サブセットは無効になります。 max-check は、以下の構成のみを保証します。$k$唯一のマキシマイザーが受け入れられます。
