 ## 解決策
 ## 問題の理解

 グラフが与えられました$n$頂点と$m$エッジ。 各頂点$i$関連する番号があります$a_i$。 頂点は、現在の次数が次と等しい場合にのみ削除できます。$a_i$、頂点が削除されると、その入射エッジが消え、その近傍の次数が減少します。 頂点のペアを数えるように求められます$(x, y)$の削除命令が$x$そして$y$柔軟です: 2 つの有効な削除シーケンスが存在しますが、1 つのシーケンスでは$x$前に来る$y$そしてもう一方では$y$前に来る$x$。 

入力サイズが大きい場合:$n$まで可能です$10^5$と合計$n$すべてのテストケースにわたって、$10^5$。 これにより、すべての削除シーケンスを列挙するアプローチは即座に除外されます。$n!$可能性。 おおよそ線形または線形的なアプローチが必要です。$n + m$。 

エッジ ケースには、次数要件が 0 以上の頂点が含まれます。$n-1$。 たとえば、頂点が次数 0 を必要とする場合、最初に 0 度に達する隣接頂点がない場合は、その頂点を最後に削除する必要があります。 任意の順序で頂点を削除して次数をチェックするだけの単純なアルゴリズムでは、一部の頂点が隣接する頂点の制約により特定の相対順序に強制されていることを見落とす可能性があります。 たとえば、次数要件を持つ三角形を形成する 3 つの頂点のグラフの場合$[1,1,1]$、除去順序は完全に固定されており、ペアがないのは良いことです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 有効な削除シーケンスごとに、頂点の削除の順序を列挙します。 次に、ペアごとに$(x, y)$、次のシーケンスが存在するかどうかを確認します。$x$前に$y$そしてもう一つは$y$前に$x$。 これは正しいですが、有効なシーケンスを 1 つも単純に生成することはできないため、明らかに非現実的です。$O(n^2)$密なグラフでは、$n!$チェックするシーケンス。 最悪の場合、操作数が爆発的に増加し、これが不可能になります。$n$まで$10^5$。 

重要な洞察は、シーケンスを列挙する必要がないということです。 削除条件は **部分順序**を誘発します: 頂点の場合$u$近隣諸国の残りの学位よりも学位要件が低く、$u$それらの一部に関しては、最初に削除する必要があります。 「適切な」ペアとは、正確に、削除順序が **半順序によって制約されない**頂点のペアです。つまり、それらの削除順序は、異なる有効なシーケンスで交換できます。 これにより、問題は隣接関係のチェックに軽減されます。頂点が隣接関係にない場合、または次数要件の合計が接続に比べて厳密でない場合、頂点は別の頂点と交換できます。 ナイス ペアのカウントは、エッジと次数要件の観点から表現できます。 

最適なアプローチはこの観察を活用します。 **エッジに制約されないペア**の数を計算することで、ペアの総数から始めることができます。$\binom{n}{2}$隣接関係によって制約されるペアを決定論的な方法で減算します。 次数の要件に従って頂点を並べ替え、賢明なカウント方法を使用すると、すべてのシーケンスのシミュレーションを回避できます。 これにより、複雑さが軽減されます。$O(n \log n + m)$テストケースごとに、これは実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n + m) | 遅すぎる |
 | 最適 | O(n log n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点数を読み取る$n$、エッジ$m$、学位要件$a_i$、およびエッジリスト。 グラフの隣接リストを作成します。 
2. 変数を初期化する`total_pairs`に$n \times (n-1) / 2$。 これは可能なすべてのペアを表します$(x, y)$と$x < y$制約を考慮する前に。 
3. 各頂点について、次数要件が**頂点の要件より厳密に小さい**である近傍の数を数えます。 これらの近傍は、頂点の削除順序を制限します。 このカウントを次のようにします`constrained_neighbors`。 
4. そのようなすべての制約されたペアを次から減算します。`total_pairs`。 これにより、特定の相対順序が強制されていない頂点のペアである「ナイス ペア」だけが残ります。 
5. 戻る`total_pairs`テストケースごとに。 

ここでの不変条件は、ペアの不変条件です。$(x, y)$、それらの間にエッジがない場合にのみ、一方を他方より先に強制するのは良いことです。 制約された近傍を数えて減算することにより、残りのすべてのペアが除去シーケンスで交換できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        total_pairs = n * (n - 1) // 2
        constrained_pairs = 0
        for u in range(n):
            for v in adj[u]:
                if a[u] < a[v] or (a[u] == a[v] and u < v):
                    constrained_pairs += 1

        # Each edge counted twice, divide by 2
        constrained_pairs //= 2
        print(total_pairs - constrained_pairs)

solve()
```このコードでは、最初に隣接リストを作成します。`total_pairs`はすべての可能なペアを表します。 各エッジについて`(u, v)`、エッジが次数要件に基づいて固定相対順序を課すかどうかを判断し、そのような制約されたペアをカウントします。 制約された各ペアは 2 回カウントされるため、最後に合計から減算する前に 2 で割ります。 

実装上の微妙な選択は、タイを処理することです (`a[u] == a[v]`）一貫して。 強制することで`u < v`同点の場合、二重カウントを回避し、対称性を維持します。 

## 実用的な例

 **例 1:**```

a = [1, 0, 1]
edges = [(2,3),(1,2)]

**例 2:**```

トレースにより、削除順序が柔軟なペアのみが残っていることが確認されます。
