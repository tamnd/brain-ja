 ## 解決策
 ## 問題の理解

 以下のすべての整数から始めます。`l`に`r`ボード上に置かれます。 各ステップで、残りのすべての数値を調べ、それらの最大公約数を計算し、それを実行スコアに追加してから、現在のセットの中央値要素を削除します。 中央値は並べ替え順序で中央の要素であり、サイズが偶数の場合は中央の下側を使用します。 番号がなくなるまでこれを繰り返します。 

このプロセスは決定論的です。削除の順序は現在のセットによって完全に決定されるため、すべてのテスト ケースは固定の削除順序をシミュレートし、一連の GCD 値を合計することになります。 

制約により、最大で`10^5`テスト ケース、最大値`2 × 10^9`。 これにより、セットの反復処理やセットの動的維持に依存するシミュレーションが即座に除外されます。これは、単一のテストでも最大で次のような処理が必要となるためです。`2 × 10^9`要素。 ソリューションでは、プロセス全体をクエリごとの定数推論または対数推論に圧縮する必要があります。 

間隔が極端に小さい場合、微妙なエッジケースが現れます。 たとえば、次の場合`l = r`の場合、セットには要素が 1 つあるため、スコアは単にその値となり、プロセスはすぐに終了します。 もう 1 つのコーナーは、間隔が非常に小さいものの、自明ではない場合です。たとえば、`l = 2, r = 3`。 このような場合、削除順序の中央値は対称的ではなく、「すべてが継続的に縮小する間隔のように動作する」という誤った仮定により、単純な推論が崩れる可能性があります。 

さらに危険な落とし穴は、GCD が複雑な方法で進化すると仮定することです。 削除後の gcd の変化を追跡しようとする多くの試みが行われていますが、実際には、連続する整数の構造により、gcd の動作がほぼすべてのステップで一定のパターンに崩れてしまいます。 

## アプローチ

 直接シミュレーションでは、ソートされた構造が維持され、すべての要素の gcd が繰り返し再計算され、中央値が削除されて続行されます。 中央値はバランスのとれたツリーまたは 2 つのヒープで追跡でき、gcd は毎回すべての要素に対して再計算できます。 これは正しいですが、コストが法外に高くなります。縮小するサイズのセットに対して gcd を計算する必要があるからです。`n`費用`O(n)`ステップごとに、`n`につながるステップ`O(n^2)`テストケースごとに、これは制限をはるかに超えています。 

重要な観察は、初期セットが連続した間隔であるということです。 中央値を削除すると、セットが 2 つの小さな連続した区間に分割されます。 各辺は、シフトされただけの完全に連続した整数ブロックのままです。 連続する整数の重要な特性は、ブロックに少なくとも 2 つの要素が含まれている限り、その gcd は常に`1`。 このようなブロックの結合には gcd も含まれます`1`すべてのブロックが単一の要素に折りたたまれていない限り。 これは gcd が維持されることを意味します`1`プロセスのほぼ全体にわたって、重要な値をもたらすのは最後のステップだけです。 

残りのタスクは、すべての中央値の削除でどの要素が生き残るかを特定することです。その要素は、gcd が削除されない唯一の場合であるためです。`1`。

 ## アルゴリズムのチュートリアル

 このプロセスを、gcd 寄与パターンと最後に残った要素の正体という 2 つの独立した観測値に変換します。 

1. しましょう`n = r - l + 1`。 プロセスは正確に実行されます`n`セットが空になるまで、毎回 1 つの要素が削除されるためです。 
2. 少なくとも 2 つの数値が残っている状態では、セットの gcd は常に次のようになります。`1`。 これは、連続する整数の各区間セグメントにはその内部に隣接する数値が含まれており、2 つの連続する整数を含むセットの gcd は次のとおりであるためです。`1`。 分割後でも、構造は連続したブロックの結合であり、それぞれが gcd に寄与します。`1`したがって、全体的な gcd は残ります。`1`。 
3. これは最初のことを意味します`n - 1`それぞれの操作が正確に寄与します`1`スコアに。 
4. 要素が 1 つ残った場合、最後のステップが発生します。 その時点で、gcd はその要素自体と等しくなります。 
5. 問題全体は、中央値を繰り返し削除した後に最後に残った要素を見つけることに帰着します。 
6. 間隔を追跡する`[l, r]`。 各ステップで、中央値の削除は、最初に中央の要素が削除される再帰ツリーを構築するように動作し、プロセスは左右のサブセグメントで独立して続行されます。 
7. 最後に生き残った要素が常に正しいエンドポイントになります`r`。 これは、小規模なケースを追跡し、削除順序によって常に小さい候補が先に削除される一方で、最大の要素がすべての分割を通じて存続することを観察することで検証できます。 
8. したがって、最後の gcd 値は次のようになります。`r`、合計スコアは次のようになります。`(n - 1) * 1 + r`。 
9. 置換`n = r - l + 1`、答えは次のように単純化されます`r - l + r = 2r - l`。 

### なぜ効果があるのか

 すべての中間構成は互いに素な連続セグメントの結合であり、そのような各セグメントには gcd があるため、gcd 不変条件が保持されます。`1`サイズが無い限り`1`。 最終ステップまで少なくとも 1 つのセグメントのサイズが 1 より大きいため、gcd は残ります。`1`。 中央値の削除順序は、常に最後まで最大要素を保持する決定論的な再帰を形成します。`r`最終的に生き残る価値。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        l, r = map(int, input().split())
        # (n-1)*1 + r where n = r-l+1
        # simplifies to 2r - l
        out.append(str(2 * r - l))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、派生した閉じた形式を直接適用します。 唯一の微妙な点は、1 つずつの間違いを避けるために単純化が慎重に行われるようにすることです。操作の数は正確に間隔のサイズであり、最後の操作を除くすべての操作が寄与します。`1`。

 ## 特殊なケース

 いつ`l = r`の場合、プロセスは 1 回の操作ですぐに終了します。 セットは`{l}`、つまり、gcd は`l`中央値の削除では要素のみが削除されます。 式`2r - l`になる`l`、直接的な解釈と一致します。 

非常に短い間隔の場合、`[2, 3]`、セットは非対称的に縮小します: 最初に削除します`2`、その後出発します`{3}`。 gcd シーケンスは次のとおりです。`1, 3`、そして式は次のようになります`2·3 - 2 = 4`、合計と一致します。 

より大きな間隔の場合、内部構造は繰り返し分割されますが、サイズ 1 に縮小されるまで各セグメントには常に連続する整数が含まれるため、最終ステップの前に残りのすべての数値が自明ではない gcd を共有する状態は生成されません。
