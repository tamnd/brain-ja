 ## 解決策
 ## 問題の理解

 各ノードが正または負の数値を保持するツリーが与えられます。 ノード 1 から開始してエッジに沿って歩き、初めてノードを訪問したときにノードの値を収集します。 ノードを再訪問しても追加の報酬は得られませんが、再訪問しても移動は許可されます。 

エッジには 2 つの種類があります。 強力なエッジは通常の無向エッジと同様に動作し、何度でも使用できます。 弱いエッジは制約されます。各弱いエッジは、ウォーク全体で合計で最大 1 回通過できます。 

ウォークはノード 1 から開始してどこで終了することもでき、これらの移動制限の下で収集された個別のノード値の合計を最大化する一連の移動を選択しようとしています。 

重要な張力は、強いエッジはツリーの一部の内部を自由に後戻りできるのに対し、弱いエッジは領域間を横断できる頻度を制限する使い捨ての橋のように機能することです。 

この制約は、すべてのテスト ケースにわたる合計入力サイズにおいて、解が本質的に線形またはほぼ線形である必要があることを示しています。 全体で最大 5 · 10^5 のノードがあるため、ウォークのシミュレーション、パスの列挙、または走査のサブセットの探索を試みるソリューションはすぐに失敗します。 強いエッジ領域内の繰り返しの動きを圧縮し、弱いエッジを唯一の意味のある分岐構造として扱う構造が必要です。 

負の値が存在する場合、微妙な問題が発生します。 「到達可能なすべてを訪問する」という単純な戦略は、弱いエッジを横切ると、トラバースのコストを支払わない低値領域へのエントリを強制される可能性があるため、正しくありません。 

ノード 1 から到達可能なすべてのノードを単純に取得できると考えると、別の失敗ケースが発生します。これでは、弱いエッジが使い捨てであることが無視されるため、領域に到達すると、戻って他の収益性の高い部分を探索できなくなる可能性があります。 

たとえば、ルートが弱いエッジを介して 2 つの大きな正のサブツリーに接続されているが、1 つのサブツリーには負のノードの長いチェーンが含まれており、値の高いリーフに到達するにはこれらのノードを横断する必要があるとします。 両方の弱いエッジを盲目的に横断するナイーブなトラバーサルは、使用した弱いエッジを越えて戻ることができないため、低い値の領域に閉じ込められる可能性があります。 

## アプローチ

 弱いエッジの制限を無視すると、問題はエッジを自由に横断できる標準的なツリー ウォークに陥ります。 その場合、ノードを再訪できるため、いつでもノード 1 からツリー全体を探索してすべての正の寄与を収集できるため、答えは単に到達可能なすべての正のノード値の合計になります。 

この困難はまさに、弱いエッジによって無制限のバックトラッキングが妨げられるために現れます。 弱いエッジを越えると、自由に戻る能力が失われます。これは、移動が完全に接続されたコンポーネント内にいることと同等ではなくなることを意味します。 

最初の構造的観察は、強いエッジは動きの制約には無関係であるということです。 強いエッジのみで形成された接続されたコンポーネントの内部では、自由に移動でき、そのコンポーネントに入れば、最終的にはそのコンポーネント内のすべてのノードを収集できます。 このようなコンポーネント内で内部走査コストや順序をモデル化する理由はありません。 

これは、強力なエッジの接続された各コンポーネントを単一のスーパーノードに縮小することを示唆しています。 各スーパーノードには、その内部のすべての元のノード値の合計に等しい重みがあります。 この収縮の後、残りのエッジはすべて弱くなり、コンポーネント間にツリーを形成します。 

この時点で、問題は次のようになります。ノード 1 を含むコンポーネントをルートとするコンポーネントのツリーがあり、各ノードには重みがあり、各エッジはウォーク中に合計で最大 1 回しか使用できません。

これで、移動の制約は純粋に組み合わせによるものになります。 有効なウォークは、ルートとエッジを反復せずに横断するコンポーネントを含む接続されたコンポーネントのセットを選択することに対応します。 ツリーでは、エッジを繰り返さないウォークは、ノード 1 から始まるオイラー軌跡を許容する接続されたサブグラフを選択することに対応します。この条件は、選択したエッジによって引き起こされる次数のパリティを制御することと同等です。 

問題は、接続されたノードのサブセット (ルートを含む必要がある) を選択し、使用する弱いエッジを選択し、選択したエッジがノード 1 から始まる単一のトレイルで横断できる構造を形成することを保証しながら、合計ノードの重みを最大化することに帰着します。 

これは当然、各ノードがどの子に接続するかを決定し、選択された接続ごとに両方のエンドポイントでトラバーサル パリティを反転するツリー動的プログラミングの定式化につながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 四球に対するブルートフォース | 指数 | O(n) | 遅すぎる |
 | 強成分収縮 + ツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、強いエッジで接続されたノードの最大グループがすべて単一のコンポーネントになるようにグラフを圧縮します。 各コンポーネントの値は、そのコンポーネント内の値の合計です。 これらのコンポーネントは弱いエッジで接続されており、結果として得られるグラフはツリーのままです。 

このツリーをノード 1 を含むコンポーネントにルートします。 

次に、ツリー DP を実行し、各ノードをルートとする有効な接続された部分構造を構築します。 各ノード u について、2 つの状態を維持します。 1 つの状態は、選択された弱いエッジ内で u が偶数次数を持つ構成を表し、もう 1 つの状態は u が奇数次数を持つ構成を表します。 エッジを繰り返すことなく完全に横断できるのはオイラー トレイル構造と一致する構成のみであるため、パリティは重要です。 

1. ルート コンポーネントから DFS を開始し、dp[u][0] を u の値として初期化します。これは、エッジを使用せずに u のみを選択すると偶数次数が 0 になるためです。エッジのない単一ノードは奇数次数を持つことができないため、dp[u][1] 状態は無効として初期化されます。 
2. u の子 v ごとに、v を完全に無視するか、弱いエッジ (u, v) を介して u に接続するかを決定します。 v を無視するということは、そのサブツリーから何も取得しないことを意味します。 v を接続するということは、v 自体を含む有効な構成を v から取得する必要があることを意味します。 
3. u と v を接続すると、エッジは u と v の両方の次数に 1 を与えるため、パリティ状態は両側で反転します。 これは、dp[u][pu] がパリティ切り替えのある dp[v][pv] を使用して遷移できることを意味し、選択した構成の全重みを追加します。 
4. 一時的な DP 配列を使用して子を 1 つずつ結合し、パリティ状態を維持しながら子に対してナップザックのようなマージを効果的に実行します。 
5. すべてのノードを処理した後、答えは dp[root][0] と dp[root][1] の最大値になります。これは、ウォークは任意のノードで終了する可能性があるためです。つまり、ルートは、結果として得られるトレイルのエンドポイントまたは内部ノードのいずれかになる可能性があります。 

これが機能する理由は、有効なウォークが、トレイルを形成する一連の横断された弱いエッジとともに接続されたコンポーネントの選択に正確に対応するためです。 DP は、そのような構造をボトムアップで構築するためのすべての方法を正確にエンコードしており、パリティ状態は、エッジを繰り返さずに構造を横断できることを保証するために必要な唯一のグローバル制約です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        weak = [[] for _ in range(n)]
        
        for _ in range(n - 1):
            u, v, s = map(int, input().split())
            u -= 1
            v -= 1
            if s == 1:
                g[u].append(v)
                g[v].append(u)
            else:
                weak[u].append(v)
                weak[v].append(u)

        # 1) build strong components
        comp = [-1] * n
        comp_id = 0
        stack = []

        for i in range(n):
            if comp[i] != -1:
                continue
            stack = [i]
            comp[i] = comp_id
            total = 0
            while stack:
                u = stack.pop()
                total += a[u]
                for v in g[u]:
                    if comp[v] == -1:
                        comp[v] = comp_id
                        stack.append(v)
            comp_id += 1

        comp_val = [0] * comp_id
        for i in range(n):
            comp_val[comp[i]] += a[i]

        # build tree of components
        cg = [[] for _ in range(comp_id)]
        for u in range(n):
            for v in weak[u]:
                cu, cv = comp[u], comp[v]
                if cu != cv:
                    cg[cu].append(cv)

        # remove duplicates
        for i in range(comp_id):
            cg[i] = list(set(cg[i]))

        root = comp[0]
        INF = -10**30

        dp = [[INF, INF] for _ in range(comp_id)]
        visited = [False] * comp_id

        def dfs(u, p):
            dp[u][0] = comp_val[u]
            dp[u][1] = INF

            for v in cg[u]:
                if v == p:
                    continue
                dfs(v, u)

                ndp0 = dp[u][0]
                ndp1 = dp[u][1]

                for pu in [0, 1]:
                    for pv in [0, 1]:
                        if dp[u][pu] <= INF//2 or dp[v][pv] <= INF//2:
                            continue
                        val = dp[u][pu] + dp[v][pv]
                        if pu == 0 and pv == 0:
                            ndp0 = max(ndp0, val)
                        if pu == 0 and pv == 1:
                            ndp1 = max(ndp1, val)
                        if pu == 1 and pv == 0:
                            ndp1 = max(ndp1, val)
                        if pu == 1 and pv == 1:
                            ndp0 = max(ndp0, val)

                dp[u][0], dp[u][1] = ndp0, ndp1

        dfs(root, -1)
        print(max(dp[root]))

if __name__ == "__main__":
    solve()
```この実装では、まずスタックベースの DFS を使用して強力なエッジ コンポーネントを構築し、次にコンポーネントごとのノード値を合計します。 次に、弱いエッジを使用してコンポーネント ツリーを構築します。 DP はボトムアップで実行され、接続する弱いエッジが使用されるかどうかを反映するパリティ遷移を使用して子状態を親にマージします。 

パリティ状態に対するネストされたループは、反転ロジックを明示的に実装します。 各マージでは、子接続を含めた後、ノードで選択されたインシデント エッジの数が偶数のままであるか、奇数になるかが考慮されます。 

実装の微妙な詳細は、dp[u][1] を負の無限大に初期化することです。 これがないと、無効なパリティ状態が遷移に漏れ込み、答えが誤って増加してしまいます。 

## 実用的な例

 ### 例 1

 ノード 1 が弱いエッジを介してノード 2 およびノード 3 に接続し、すべての値が正である小さなツリーについて考えます。 

| ステップ | ノード | dp[0] | dp[1] |
 | --- | --- | --- | --- |
 | 初期化 | 1 | a1 | -inf |
 | 2以降 | 1 | a1 + a2 | a1 |
 | 3以降 | 1 | a1 + a2 + a3 | a1 + a2 |

 これは、各ブランチを含めるかどうかの選択がパリティと収集された合計値にどのように影響するかを示しています。 

このトレースは、DP がすべてのノードを単純に合計しているのではなく、結果の走査の一貫性が保たれているかどうかに基づいて、含めるブランチを選択的に選択していることを示しています。 

### 例 2

 ここで、1 つの分岐の合計値が負であるチェーンを考えてみましょう。 

| ステップ | ノード | dp[0] | dp[1] |
 | --- | --- | --- | --- |
 | 初期化 | 1 | 5 | -inf |
 | 良い子を追加します | 1 | 15 | 5 |
 | 悪い子を追加します | 1 | 15 | 5 |

 サブツリーに負の寄与がある場合でも、DP はそれを含む遷移をとらないことで、それを完全に回避できます。 

これにより、ソリューションが弱いエッジを通る強制トラバースを正しく回避していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、強いエッジで接続されたすべてのノードが、正と負の両方の値を含む大きなクラスターを形成する場合です。 アルゴリズムはそれらを単一のコンポーネントに正しくマージし、内部トラバースがウィークエッジ ロジックによって制限されないようにします。 

最適なウォークが弱いエッジをまったく使用しない場合、別のエッジ ケースが発生します。 この場合、DP は子遷移をアクティブにすることはなく、答えはルート コンポーネントのみの値になり、これは初期化によって処理されます。 

最後の微妙なケースは、複数の弱いエッジによってパリティ要件が矛盾するサブツリーが生成される場合に発生します。 DP はパリティを明示的に追跡することで一貫性を確保するため、サブツリーの無効な組み合わせを同時に選択することはできません。
