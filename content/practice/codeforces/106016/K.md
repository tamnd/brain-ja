 ## 解決策
 ## 問題の理解

 子供の列が与えられ、各子供には評価が付けられます。 すべての子に正の数の Cookie を割り当てる必要がありますが、割り当てを恣意的に行うことはできません。 唯一の構造要件はローカルです。子が直前の子よりも厳密に高い評価を持つ場合、その子は左隣の子よりも厳密に多くの Cookie を受信する必要があります。 

逆方向には制約はありません。 評価が下がったり、同じままになったり、増加以外の方法で急上昇した場合でも、すべての子供が少なくとも 1 つ持っている限り、クッキーの数は何でもできます。 

タスクは、これらのローカル比較を尊重しながら、すべての子の Cookie の総数を最小限に抑えることです。 

入力サイズは小さく、テスト ケースは最大 100 個で、それぞれのテスト ケースには最大 100 個の子が含まれます。 二次または三次のアプローチでも受け入れられますが、条件の構造は線形の構築が可能であることを示唆しています。 

単純な間違いは、ユーザーが両方の方向に制約を適用しようとしたり、最初の割り当て後にカウントをグローバルに再調整しようとしたりしたときに発生します。 たとえば、評価を考えてみましょう`[1, 3, 2]`。 A careless symmetric rule might give`[1, 2, 1]`、2 番目の子は最初の子を厳密に超える必要があるため、これは失敗します。 もう 1 つの障害モードは、完全なパスの後で違反が検出された場合にのみ調整しようとするもので、変更を後方に繰り返しカスケードする可能性があります。 

主な問題点は、制約が左から右へ前方にのみ伝播し、後方には伝播しないため、一度行われたローカルな決定が最終的なものになってしまうことです。 

## アプローチ

 強引な解釈では、各子の Cookie 数を不等式によって制約された変数として扱います。各子には少なくとも 1 つの Cookie があり、評価が増加する位置ごとに、隣接する変数間に厳密な不等式を課します。 すべての有効な割り当てを検索したり、収束するまで制約を繰り返し緩和したりすることができます。 

考えられる Cookie 配布の数は n とともに指数関数的に増加するため、このようなアプローチはすぐに実行不可能になります。 値を妥当な範囲に制限したとしても、違反を繰り返し修正するには多くのパスが必要になる可能性があり、最悪の場合、各調整が配列全体に複数回伝播し、テスト ケースごとの 2 次またはさらに悪い動作につながります。 

制約の構造は、見た目よりも単純です。 すべての制限は、子をそのすぐ左の隣の子とのみ比較します。 グローバル結合はありません。 これは、前のポジションの値がわかれば、各ポジションの有効な最小値を貪欲に決定できることを意味します。 

重要な観察は、Cookie の増加が強制されるのは、レーティングが厳密に増加する場合のみであるということです。 評価が増加しない場合は、可能な最小値である 1 に自由にリセットできます。これにより、後方修正や全体的な最適化の必要がなくなります。 

最終的には 1 つの左から右へのパスになり、各位置は前のパスによってのみ決定されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 最初の子の答えを 1 として初期化します。すべての子には少なくとも 1 つの Cookie が必要であり、左隣接制約がないため、これは強制されます。 
2. 配列を 2 番目の子から最後の子まで走査します。 各位置 i で、現在の定格を以前の定格と比較します。 
3. 現在の評価が以前の評価より大きい場合、cookies[i] = cookies[i−1] + 1 を割り当てます。これは、合計を最小限に保ちながら厳密な不等式を満たす最小値です。 これより小さい値はルールに違反します。 
4. それ以外の場合は、cookie[i] = 1 を割り当てます。評価が増加しない場合は要件がないため、可能な限り小さい値を選択すると、合計が最小限に抑えられます。 
5. メモリの最適化が必要な場合は、配列全体を保存するのではなく、割り当てられたすべての値の合計を計算しながら累積します。 

### なぜ効果があるのか

 各ポジションでの割り当ては、前のポジションと評価のローカル比較のみに依存します。 cookies[i−1] が固定されると、最小の有効な cookies[i] が完全に決定されます。つまり、制約がトリガーされる場合は 1、または cookies[i−1] + 1 のいずれかになります。 cookies[i] をさらに削減しようとすると、インデックス i に関係する唯一の制約に直ちに違反します。 将来の制約によって以前の位置と比較して減少を強制することはできないため、これらの局所的最小値は大域的最小解に結合されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        r = list(map(int, input().split()))

        cookies = 1
        prev = 1
        total = 1

        for i in range(1, n):
            if r[i] > r[i - 1]:
                prev = prev + 1
            else:
                prev = 1
            total += prev

        out.append(str(total))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、配列全体を保存するのではなく、前の Cookie 値のみを保持します。 各ステップは直前のステップにのみ依存するため、これで十分です。 変数`prev`現在の子に割り当てられた Cookie を表し、評価の比較に従って更新されます。 

The accumulation into`total`最後に配列を再構築することを回避します。 これは貪欲なロジックと直接一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    def solve():
        input = sys.stdin.readline
        t = int(input())
        res = []
        for _ in range(t):
            n = int(input())
            r = list(map(int, input().split()))
            prev = 1
            total = 1
            for i in range(1, n):
                if r[i] > r[i - 1]:
                    prev += 1
                else:
                    prev = 1
                total += prev
            res.append(str(total))
        print("\n".join(res))

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 単一の子の場合、比較する先行クッキーがないため、アルゴリズムはただちに 1 つの Cookie を割り当てます。 ルール セットはそれ以上の制約を課さないため、出力は 1 のままです。 

次のような厳密に増加するシーケンスの場合、`[1, 2, 3, 4]`、アルゴリズムは継続的に増加します`prev`、生産`[1, 2, 3, 4]`。 これにより、後方調整を必要とせずに連鎖増加が正しく伝播されることが確認されます。 

次のような厳密に減少するシーケンスの場合、`[5, 4, 3, 2]`、すべての比較で条件が満たされないため、`prev`各ステップで 1 にリセットされます。 結果は次のようになります`[1, 1, 1, 1]`増加を強制する制約がないため、これは最小限です。
