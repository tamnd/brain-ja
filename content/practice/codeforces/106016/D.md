 ## 解決策
 ## 問題の理解

 私たちには固定の番号が与えられています$x$そして値の長いリスト$a_i$。 それぞれについて$a_i$、最小の正の整数を見つけたいとします。$z$2 つの条件を満たす: 分割する必要がある$x$、そしてそれは分割に失敗する必要があります$a_i$。 すべての約数が$x$も分割します$a_i$、それならそんなことはない$z$存在し、答えは$-1$。 

タスクを読み取る別の方法は、クエリ値ごとに$a_i$のすべての約数をスキャンします。$x$昇順に、除数セット間で最初の「不一致」がどこで起こるかを尋ねます。$x$そして$a_i$。 

制約があるため、構造が重要になります。 配列のサイズは 100 万に達する可能性があり、値は次のとおりです。$10^{12}$。 これにより、各数値を個別に因数分解したり、約数を再計算したりするアプローチは即座に除外されます。$x$クエリごとに繰り返し実行します。 大きな除数セットに対するクエリごとの線形スキャンでさえも重要になります。$10^{12}$病的な症例では依然として約100万人に達する可能性がある。 

微妙な失敗例が現れるのは、$a_i$はすべての約数で割り切れます$x$。 たとえば、次の場合$x = 12$、その約数は$1,2,3,4,6,12$。 もし$a_i = 60$、それぞれが 60 を割るので、答えは次のようになります。$-1$。 早期に停止したり、欠落した除数が常に存在すると仮定した単純なアプローチでは、誤って 1 または別の小さな値が返されます。 

別のエッジケースは、最小の約数が次の場合に発生します。$x$は常に 1 ですが、すでに条件を満たしていません。 1 ですべてが除算されるため、これは不可能であり、スキャンは常に「有効な」除数から開始されます。 最初の意味のある失敗は、1 より大きい何らかの除数で発生する必要があります。 

## アプローチ

 直接的な解決策はすぐに思い浮かびます。 すべての約数を列挙できます$x$、それらを並べ替えて、それぞれについて$a_i$、割り切れないものが見つかるまで、各約数に対して順番に割り算をテストします。$a_i$。 これは正しいです。なぜなら、答えの定義にはそのような最小の除数が明示的に必要とされるからです。 

コストを見積もれば、ボトルネックは明らかです。 もし$x$もっている$D$約数の場合、各クエリには最大で$D$モジュラスチェック。 最悪の場合$D$大きくてもよいし、$n$まで$10^6$、すべてのクエリが大きなプレフィックスをスキャンする場合、これは非常に遅くなります。 

重要な構造の簡素化は、実際にはクエリごとに完全な因数分解を行う必要がないことに気づくことから生まれます。 固定の場合$a_i$、の約数$x$それを分ける$a_i$まさにその約数です$\gcd(x, a_i)$。 これにより、問題は除数セットのメンバーシップのチェックに変わります。$d$有効です$a_i$それが分割しない場合に限り、$\gcd(x, a_i)$。 

したがって、クエリごとに次のように計算します。$g = \gcd(x, a_i)$、次に、の約数をスキャンします$x$昇順で最初の約数を返します$d$そのような$d \nmid g$。 これは、繰り返し行われる完全な可分性チェックに代わるものです。$a_i$より小さい数値に対するチェックを使用します。 

引き続きソートされた除数リストをスキャンしますが、これは事前計算された構造に対する単純な線形パスになります。

 ## アルゴリズムのチュートリアル

 1. すべての約数を計算します。$x$までの整数をチェックすることで$\sqrt{x}$。 有効な除数のペアごとに、両方の値をリストに挿入します。 

目標は、正確な候補者のセットを構築することです。$z$。 
2. 除数リストを昇順に並べ替えます。 

この問題では最小の有効な約数が求められるため、この順序付けは不可欠です。 
3. 各クエリ値について$a_i$、計算する$g = \gcd(x, a_i)$。 

これにより、次の約数に関するすべての情報が圧縮されます。$x$分けることも$a_i$単一の数字にまとめられます。 
4. ソートされた約数を反復処理します。$x$最小から最大まで。 
5. 各約数について$d$、どうかを確認してください$g \bmod d = 0$。 

ゼロ以外の場合、$d$分けない$a_i$、 それで$d$がこのクエリに対する答えです。 
6. そのような除数が見つからずにスキャンが完了した場合、出力$-1$。 

重要な設計上の選択は、割り算を決して再計算しないことです。$a_i$直接。 すべてのメンバーシップのクエリは、約数が$x$も分割します$g$。 

### なぜ効果があるのか

 任意の約数に対して$d$の$x$、条件「$d$分割する$a_i$「」は「」と同等です。$d$分割する$\gcd(x, a_i)$」。この等価性は、$x$それは分ける$a_i$最大公約数を割る必要があります。 

したがって、除数リストはクエリごとに自然に 2 つの部分に分割されます。$g$、そしてそうでないもの。 昇順にスキャンするため、除数セットの外側の最初の除数は、$g$まさに最小の有効な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    # compute divisors of x
    divs = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            divs.append(i)
            if i * i != x:
                divs.append(x // i)
        i += 1
    
    divs.sort()
    
    for ai in a:
        g = gcd(x, ai)
        ans = -1
        for d in divs:
            if g % d != 0:
                ans = d
                break
        print(ans)

if __name__ == "__main__":
    solve()
```最初のステップでは、完全な除数リストを作成します。$x$で$O(\sqrt{x})$。 これは 1 回だけ実行されますが、これは非常に重要です。$x$すべてのクエリ間で共有されます。 

内側のループは gcd を使用して、割り算のチェックを回避します。$a_i$直接。 条件`g % d != 0`の鍵の交換です`ai % d != 0`、これを繰り返し推論するとコストが高くなります。 

早期ブレークにより、最小の無効な除数が見つかるとすぐにスキャンが停止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd
    import sys

    input = sys.stdin.readline

    def solve():
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        divs = []
        i = 1
        while i * i <= x:
            if x % i == 0:
                divs.append(i)
                if i * i != x:
                    divs.append(x // i)
            i += 1

        divs.sort()

        res = []
        for ai in a:
            g = gcd(x, ai)
            ans = -1
            for d in divs:
                if g % d != 0:
                    ans = d
                    break
            res.append(str(ans))

        return " ".join(res)

    return solve()

 ## 特殊なケース

 いつ$a_i$はすべての約数の倍数です$x$、アルゴリズムは次のように計算します。$g = x$、すべての約数がチェックに合格します`g % d == 0`。 スキャンは中断することなく完了し、正しく返されます。$-1$、定義と一致します。 

いつ$x$が素数の場合、約数リストは`[1, x]`。 1 は常に任意の値を割るので、$a_i$、答えはどちらかです$x$（もし$a_i$で割り切れない$x$） または$-1$。 アルゴリズムは最初に 1 をチェックし、次に直接到達するため、これを自然に処理します。$x$。 

いつ$a_i$が非常に小さく、特に 1 である場合、gcd は 1 になります。 1 を割るのは約数 1 のみであるため、1 を除算するすべての約数は 1 になります。$x$はすぐに答えの候補となるため、アルゴリズムは 2 番目に小さい約数を返します。$x$、これは定義と正確に一致します。
