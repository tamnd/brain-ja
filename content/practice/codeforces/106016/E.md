 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられ、最大 1 回の操作を使用して最初の文字列を変更できます。 この操作では、連続したセグメントを選択し、それを反転します。 何もしないか、そのような反転を 1 回だけ実行した後、結果の文字列を辞書順で 2 番目の文字列と比較します。 タスクは、最初の文字列を 2 番目の文字列より厳密に小さくできるかどうかを判断することです。 

辞書編集的な比較は辞書の順序のように動作します。左から右にスキャンし、文字が異なる最初の位置によって結果が決まります。 

すべての文字列の長さの合計が最大 100000 であるという制約により、考えられるすべての反転間隔を試行するソリューションは即座に除外されます。 O(n²) 個の間隔があり、間隔ごとの線形チェックでもすでに制限を超えています。 これにより、各テスト ケースが線形時間で処理される貪欲またはプレフィックス ベースの意思決定プロセスが推進されます。 

微妙な点は、この操作により文字列の一部が悪化する可能性があることです。 セグメントを反転しても「局所的には改善」されません。 ブロックを再配置するので、その効果はローカルな比較だけではなく、辞書編集的な順序によってグローバルに推論される必要があります。 

重要なエッジ ケースの 1 つは、文字列がすでに等しい場合です。 それでも、反転すると最初の文字列が小さくなる可能性があります。 たとえば、次のような文字列がある場合、`ba`、逆転すると与えられます`ab`より小さい`ba`たとえ仮定の意味で目標と同等のスタートを切ったとしても。 最初の不一致がすでに存在するケースのみをチェックする単純な解決策は、ここで失敗します。 

もう 1 つのエッジケースは、反転が使用されない場合です。 元の文字列がすでに辞書編集的に小さい場合、答えはすぐに「はい」になります。 

## アプローチ

 ブルートフォース手法は簡単です。インデックス l と r のすべてのペアを試し、そのセグメントを反転し、結果の文字列をターゲット文字列と比較します。 各反転のコストは O(n) で、セグメントの選択肢は O(n²) あるため、合計の複雑さはテスト ケースごとに O(n³) になります。 ローリング ハッシュを使用して比較コストを O(1) に削減しても、基本的な候補数 O(n²) は修正されないため、これでもまだ遅すぎます。 

重要な観察は、辞書編集上の順序は、改善を強制できる最初の位置によって決定されるということです。 位置 i を固定すると、i より前はすべて元の文字列と同一のままでなければなりません (以前に変更があった場合、比較が支配されるため)。 したがって、反転が役立つ場合は、改善が必要なできるだけ早い位置に影響を与えるように選択する必要があります。 

これにより、問題は、接頭辞の位置 i ごとに、前の文字を妨げない 1 回の反転を使用して、b[i] の対応する文字よりも小さい文字を位置 i に移動できるかどうかを判断することになります。 

セグメント反転内でキャラクターを前方に移動する唯一の方法は、そのキャラクターをセグメントの正しいエンドポイントとして選択することです。 したがって、各位置 i について、a[i..j] を反転すると a[j] が位置 i に配置されるような j ≥ i が存在し、その文字が辞書編集上の順序を改善するのに十分なほど小さいかどうかを知りたいと考えます。 

これにより、すべての接尾辞について、利用可能な最小の文字を維持することになります。これは、今後進められる可能性のある最良の候補であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適な貪欲さ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、元の文字列 a がすでに辞書編集的に b より小さいかどうかを確認します。 「はい」の場合、この操作はオプションであるため、すぐに「はい」と答えることができます。 
2. すべての位置 i について、a[i..n−1] 内の最小の文字が何であるかを知らせる構造を事前計算します。 また、反転セグメントを形成する際に最大限の柔軟性が得られるように、この最小の文字が出現する 1 つのインデックス、できれば右端の出現を追跡します。 
3. 左から右に位置をスキャンします。 位置 i では、以前のすべての位置が b と正確に一致すると仮定します。そうでない場合は、辞書編集上の比較が以前にすでに決定されているためです。 
4. 各位置 i で、位置 i に配置できる最良の文字 (i で始まるサフィックス内の最小文字) を b[i] と比較します。 
5. この最小の接尾辞文字が厳密に b[i] より小さく、その出現インデックス j が少なくとも i である場合、l = i および r = j を選択できます。 このセグメントを反転すると、a[j] が位置 i に移動しますが、それより前の位置はそのまま残ります。 これにより、b との最初の不一致が i で発生し、好ましいものであることが保証されるため、すぐに「はい」と答えることができます。 
6. 最小のサフィックス文字が b[i] に等しい場合、可能な限り最善の手を行っても位置 i を改善できないため、次のインデックスに進みます。 
7. 有効な位置 i が見つからないままスキャンを終了した場合、答えはノーです。 

正確さは、差異を強制できる最も早い位置で辞書編集上の改善が行われなければならないという事実に依存します。 最初の改善可能なインデックスをスキップして後のインデックスを修正しようとする試みは、前の位置が依然として b と一致し、後の利点が問題にならないため、前の等価制約によって支配されます。 

### なぜ効果があるのか

任意のインデックス i において、位置 0 から i-1 が b と等しくなければならないと判断した場合、勝利する唯一の方法は a[i] < b[i] を強制することです。 反転操作では、サフィックスから 1 文字だけを位置 i に進めることができ、そのような最良の文字はそのサフィックスの最小値です。 その文字さえも b[i] より小さくない場合、i 以降で開始する反転によって位置 i の辞書編集順序を改善することはできません。決定を遅らせると、以前の位置が固定されたままになるため、事態は悪化するだけです。 これにより、最初の実現可能な改善が常に最適な改善となる単調な意思決定構造が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        a = input().strip()
        b = input().strip()

        # If already smaller, no need to use operation
        if a < b:
            print("Yes")
            continue

        # suffix minimum character and position
        n = len(a)
        suf_min = [''] * n
        suf_pos = [0] * n

        suf_min[-1] = a[-1]
        suf_pos[-1] = n - 1

        for i in range(n - 2, -1, -1):
            if a[i] < suf_min[i + 1]:
                suf_min[i] = a[i]
                suf_pos[i] = i
            else:
                suf_min[i] = suf_min[i + 1]
                suf_pos[i] = suf_pos[i + 1]

        ok = False

        for i in range(n):
            if suf_min[i] < b[i]:
                j = suf_pos[i]
                if j >= i:
                    ok = True
                    break
            if a[i] != b[i]:
                break

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```コードはまず、操作が必要ない単純なケースをチェックします。 次に、サフィックス最小値を構築して、各ポジションについて、そこから始まる逆転によって前方に引っ張ることができる最適なキャラクターを即座に知ることができます。 スキャンでは、プレフィックスがまだターゲット文字列と一致する位置のみを考慮することが強制されます。そうしないと、辞書編集的な比較がすでに分岐しているためです。 

実装の重要な詳細は、最小文字とそれが出現するインデックスの両方を保存することです。 インデックスがなければ、どの文字を前方に持ってくるかはわかりますが、有効な反転を使用してその文字を実際に位置 i に移動できるかどうかはわかりません。 

## 実用的な例

 ### 例 1

 入力:

 a = "bca"

 b = 「タクシー」

 接尾辞の最小値を計算します。 

| 私 | a[i] | サフィックス分 | 位置 |
 | --- | --- | --- | --- |
 | 0 | b | | 2 |
 | 1 | c | | 2 |
 | 2 | | | 2 |

 i = 0 の場合、サフィックス min は次のようになります。`a`、 そして`a < b[0] = c`, したがって、[0,2] を反転して、`"acb"`より小さい`"cab"`。 

このトレースは、1 回の反転によって世界最小の文字がどのようにして最も早い決定点まで前進するかを示しています。 

### 例 2

 入力:

 a = "ABC"

 b = "ABC"

 接尾辞の最小値:

 | 私 | a[i] | サフィックス分 | 位置 |
 | --- | --- | --- | --- |
 | 0 | | | 0 |
 | 1 | b | b | 1 |
 | 2 | c | c | 2 |

 どの位置でも、サフィックスの最小値が厳密に b[i] より小さいことはありません。 最初に平等を破らなければ、どのポジションでも逆転は厳密な改善を生み出すことはできないため、答えはノーです。 

これは、文字列が等しい場合でも、構造が誤検知を正しく防止していることを示しています。

 ## 特殊なケース

 文字列がすでに等しい場合でも、アルゴリズムは接尾辞文字を前方に移動して厳密な減少を作成できる位置を正しく見つけようとします。 そのような位置が存在しない場合、スキャンが成功することはなく、答えは「いいえ」のままです。たとえば、次のようになります。`a = "abc"`そして`b = "abc"`、すべての接尾辞の最小値は対応する文字に一致するため、どの位置でも逆転によって厳密な利点が得られることはありません。 

のように最初の文字がすでに小さい場合`a = "a..."`そして`b = "b..."`、アルゴリズムは、より深い構造を考慮する必要なく、 i = 0 での成功を即座に検出します。 位置 0 のサフィックスの最小値は次のとおりです。`a[0]`、これはすでに条件を満たすのに十分です。 

改善が文字列の奥深くにのみ存在する場合、スキャンにより、以前の位置が正しくブロックされていることを確認します。 実現可能な改善が行われる前に不一致が発生した場合、ループは早期に中断され、辞書編集上の優先順位を尊重することで正確性が維持されます。
