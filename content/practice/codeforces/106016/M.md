 ## 解決策
 ## 問題の理解

 頂点 1 から n までのラベル付きツリーを操作しています。 すべてのスパニング ツリーの中で、頂点 1 と頂点 n の間の一意のパスがツリーの直径であるものだけを保持します。これは、他の頂点のペアが 1 と頂点 n よりも離れていないことを意味します。 

この制限されたファミリーから、ツリーが均一にランダムに選択されます。 対象となる量は、そのツリー内の頂点 1 と n の間の距離であり、これを D と呼びます。1 と n はすでに直径を実現している必要があるため、D はツリーの直径の長さでもあります。 

タスクは、D の期待値を有理数として正確に計算し、それをモジュラー形式 P · Q⁻¹ mod m で出力することです。ここで、分数は削減され、分母は大きな素数 m を法として反転されます。 

入力サイズでは、n は最大 500、テスト ケースは最大 500 個まで可能です。 これにより、ツリーを列挙したり、テスト ケースごとに独立して三次関数を実行したりするアプローチは即座に除外されます。 構造はすべての n にわたってグローバルに事前計算され、再利用される必要があります。 

非常に小さいサイズでは、微妙なエッジケースがすでに現れています。 n = 1 または n = 2 の場合、ツリーは強制されるため、D は固定されます。 n = 3 の場合、「1-3 は直径」という条件は、より長い代替パスが存在する場合、2 が中央にあるパスを除外しますが、ラベル付け制約までのツリーは 1 つだけであるため、期待は決定的です。 直径の条件を無視する単純なサンプラーは、すべての Cayley ツリーの平均を誤って計算し、1 と n が直径の端点ではない構成を過大にカウントします。 

本当の難しさは、「1 と n が直径を形成する」という条件がグローバルな構造制約とローカルなパス制約を結び付けるため、確率空間がすべてのツリーにわたって均一ではなく、高度に構造化されたサブセットにわたって均一であることです。 

## アプローチ

 直接的な総当たりアプローチでは、プリューファー シーケンスを使用してすべてのラベル付きツリーを生成し、各ツリーをチェックし、1 と n の間のパスが直径であるかどうかを確認し、距離を平均します。 Prüfer シーケンスはすべての n^{n-2} ツリーを均一に列挙し、直径チェックはツリーごとに 2 回の BFS 実行で実行できるため、これは原理的には正しいです。 

ただし、これにはすでに O(n^{n}) 個のオブジェクトが必要であり、n = 15 の場合でも完全に実行不可能になります。 ボトルネックは検証ではなく、ツリーの指数関数的な数です。 

重要な構造的観察は、「1-n は直径である」という条件付けにより、非常に特殊なバックボーン構造が強制されるということです。 すべての有効なツリーにおいて、1 から n までの一意のパスは、ある程度の長さ d の単純なパスである必要があり、他のすべてのノードは、サブツリーとしてこのパスに沿った頂点に接続する必要があり、これらのサブツリーを迂回して d よりも長いパスが作成されないようにする制約があります。 

バックボーンが固定されると、ツリーの残りの部分は、各バックボーン ノードに接続された独立したルート付きツリーに分解されますが、エンドポイントまでのノードの距離に応じて高さ制限があります。 これにより、問題が考えられるバックボーンの長さ d の合計に変換され、各 d の有効な添付ファイルの組み合わせ数が乗算され、期待値が抽出されます。 

この削減は、グローバルな直径制約を、パスに沿って取り付けられた根のある木のローカルな高さ制約に変換するため、強力です。これは、ラベル付きツリーの指数生成関数を使用して処理できます。

 ## アルゴリズムのチュートリアル

 すべてのラベル付きツリーは、1 から n までのバックボーン パスと、このパス上の各頂点に接続されたルート付きサブツリーとして表現できるという事実から始めます。 バックボーンの長さを d とします。これは、パス上に d + 1 個の頂点があることを意味します。

段階的に進めていきます。 

1. 1 と n の間の可能な距離 d を固定します。 これにより、候補となるバックボーンの長さが決定されます。 期待値に寄与するすべての有効なツリーは、まさに 1 つのそのような d の下で 1 回カウントされます。 
2. パス上にある中間頂点を選択します。 {2, …, n − 1} から d − 1 個の頂点を選択し、パスに沿って並べます。 これにより、標識されたバックボーン構造が得られます。 
3. 位置 i (0 ≤ i ≤ d) にあるバックボーン頂点を考えます。 この頂点に接続されたノードはすべて、そのサブツリー内で測定された深さを持ちます。 このようなノードの頂点 1 までの距離は i + 深さに等しく、頂点 n までの距離は (d − i) + 深さに等しい。 直径は正確に d であるため、両方とも最大でも d 以内でなければならず、深さ ≤ min(i, d − i) となります。 これが重要なローカル制約です。 
4. したがって、バックボーン位置 i ごとに、高さが最大でも h_i = min(i, d − i) である残りの頂点のサブセットから形成されるルート付きラベル付きツリーをカウントする必要があります。 各頂点に接続されるノードの数を固定すると、これらのサブツリーは異なるバックボーン頂点間で独立します。 
5. すべての h と k について、k ノード上の高さが最大 ​​h のルート付きラベル付きツリーの数 f[h][k] を計算します。 これは、指数生成関数を使用して行われます。 A_h(x) をそのようなツリーの EGF とします。 ルート付きラベル付きツリーは、ルートに独立したサブツリーのセットを加えたもので、A_0(x) = x で A_h(x) = x · exp(A_{h−1}(x)) に変換されます。 すべての系列を次数 n まで切り捨てます。 
6. すべての f[h][k] がわかったら、固定のバックボーン長 d を処理します。 残りの n − (d + 1) 個の頂点を d + 1 個のバックボーン ノードに分散します。 位置 i が s_i 頂点を受け取る場合、それは f[h_i][s_i] に寄与します。 この d の合計寄与は、残りの頂点のすべての構成にわたる畳み込みです。

8. 最後に、期待値を sum(d * count_d) / sum(count_d) として計算します。 

この正しさは、すべての有効なツリーが 1 と n の間の一意の直径パスを持ち、すべてのアタッチメントが、ノードがいずれかの端点までの距離 d を超えないようにすることによって引き起こされる高さの制約を尊重するという事実から来ています。

def solve():

    t, m = map(int, input().split())
    MOD = m
    ns = [int(input()) for _ in range(t)]
    N = max(ns)

    # factorials
    fact = [1] * (N + 1)
    invfact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD

    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    # f[h][k] = number of rooted trees with height <= h

    for h in range(N + 1):

    # A_h = x * exp(A_{h-1}) in EGF form
    A_prev = [0] * (N + 1)

        res[0] = 1

```この実装は、高さが制限されたルート付きラベル付きツリーの指数母関数恒等式を中心に構造化されています。 配列 A は各高さでの母関数の係数を表し、exp_series はモジュラー演算の下で切り捨てられた級数の指数を構築します。 

重要な点は、ラベル付きツリーには EGF 内で階乗正規化が必要であるということです。そのため、畳み込みではインデックスのモジュール逆関数が使用されます。 よくある間違いは、サブツリーの組み合わせを通常の畳み込みとして扱うことです。これにより、ラベル付きの順列が過小評価されます。 

コード内で 2 番目に欠落している層はバックボーン分布 DP で、直径パス上の位置全体で f[h][k] 値を結合します。 その DP はサブツリー サイズに関する多次元のナップザックであり、ローカルな高さの制約からグローバルなツリーのカウントへの移行を完了するものです。 

## 実用的な例

 n = 3 を考えてみましょう。1 と 3 の間で考えられるバックボーンは d = 1 の 1 つだけです。中央の頂点は高さ 0 のサブツリーとして接続する必要があるため、単一のノードのみにすることができます。 DP は有効なツリーを 1 つだけカウントし、D = 1 を決定的に与えます。 

n = 4 の場合、可能な直径には d = 1、2、または 3 が含まれますが、1 と 4 が最長パスの終点である構成のみが許可されます。 d = 2 の場合、パス 1-x-4 と、高さ制限の下でいずれかの端点に接続する残りの頂点が 1 つあります。 d = 3 の場合、バックボーンは 1-a-b-4 であり、残りの頂点は存在せず、純粋なパスが生成されます。 これらの寄与の加重平均により期待値が得られます。 

最も単純な n = 3 の場合のトレース テーブル:

 | d | バックボーン | 有効な添付ファイル | カウント |
 | --- | --- | --- | --- |
 | 1 | 1-3 | ノード 2 は簡単に接続されました | 1 |

 これにより、直径の条件を満たす構造は 1 つだけであることが確認されます。

 ## 特殊なケース

 n = 1 の場合、エッジがないため、D = 0 になります。アルゴリズムは空のバックボーンを正しく処理する必要があります。 そうしないと、少なくとも 1 つのエッジが存在すると誤って想定され、添付ファイルが過大にカウントされます。 

n = 2 の場合、唯一のツリーは単一のエッジであり、直径の条件を自明に満たします。 ノードをバックボーンに分散する DP 定式化では、中間頂点を作成しようとしてはなりません。 

n = 3 の場合、唯一の有効な構造は 1 と 3 の間の長さ 2 のパスであり、頂点 2 はそのパス上に存在する必要があります。 高さ 0 のアタッチメント サブツリーを許可しながら、それらをオプションとして扱うモデルでは、切断されたバックボーン構成が誤ってカウントされます。
