 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そのタスクは、これらの部分の XOR 値によって定義される制約の下で、それを複数の連続する部分に分割できるかどうかを判断することです。 この問題全体にわたる重要なオブジェクトはセグメントの XOR であり、分割の実現可能性はこれらの XOR 値が相互にどのように関係するかに完全に依存します。 

この問題は、配列全体の XOR に応じて、2 つの根本的に異なる領域で動作します。 すべての要素の XOR がゼロ以外の場合、構造は非常に柔軟です。任意の方法で配列を 2 つのセグメントに分割でき、これら 2 つのセグメントの XOR 値は異なることが保証されます。 興味深い問題は、XOR の合計が 0 の場合にのみ現れます。その場合、一部のパーティションが不可能になり、構造についてより慎重に推論する必要があるためです。 

複雑さの観点から見ると、配列サイズは一般的な競技プログラミングの制限に達しているため、すべての分割点または部分配列の二次または三次探索は直ちに遅すぎます。 すべてのパーティションを明示的にチェックするソリューションでは、O(n²) 以上のセグメント XOR を調べる必要がありますが、これは n が 10⁵ 程度の場合には実現できません。 これにより、プレフィックス XOR 構造とリニア スキャンに依存するソリューションが求められます。 

すべての要素がゼロの場合、微妙なエッジ ケースが発生します。 その場合、すべてのサブ配列の XOR はゼロになるため、意味のあるパーティションはセグメントを区別できません。 もう 1 つのエッジ ケースは、配列に 0 以外の値が 1 つだけ含まれている場合、またはすべての 0 以外の値が単一の繰り返し XOR ID に崩壊する場合であり、パーティション ロジックが縮退します。 

## アプローチ

 ブルートフォースのアイデアは、配列をセグメントに分割し、各セグメントの XOR を計算するあらゆる方法を試してみることです。 候補となるパーティションごとに、必要な XOR 制約が満たされているかどうかを検証します。 2 つまたは 3 つのセグメントに制限したとしても、セグメント XOR を繰り返し計算すると、再計算またはサブ配列のスキャンにより O(n²) 個の作業が発生します。 

この非効率性は、重複するサブ配列に対して XOR を繰り返し再計算することから発生します。 XOR自体は安価ですが、分割候補の数が多すぎます。 重要な点は、プレフィックス XOR を使用して、任意のセグメントの XOR を O(1) で計算できることです。これにより、チェックあたりのコストは削減されますが、チェックの数は削減されません。 

本当の単純化は、有効なパーティションの構造を分析することで実現します。 合計 XOR がゼロ以外の場合、カットの選択を妨げる構造上の制限はありません。 これがゼロの場合、問題は、残りのサフィックスを異なる XOR プロパティを持つ 2 つのセグメントに分割できるプレフィックス構造を見つけられるかどうかをチェックすることになります。 重要な観察は、そのような分割が不可能な場合、サフィックスは非常に制限される必要があるということです。特定のポイント以降のすべてのプレフィックス XOR は 2 つの値しか取れず、すべての要素が非常に制限されたパターンに強制的に崩壊します。 

これにより、問題はパーティションの検索から特定の構造違反のスキャンに変わります。

 ## アルゴリズムのチュートリアル

1. 配列全体の XOR を計算します。 ゼロ以外の場合、この領域には構造的な障害が存在しないため、有効な分割をすぐに受け入れて構築できます。 
2. 合計 XOR が 0 の場合は、左からスキャンして、要素が 0 以外である最初のインデックスを見つけます。 この要素は、すべての有効なセグメント XOR を制約する参照値を定義します。 
3. ゼロ以外の要素が存在しない場合、配列は完全にゼロになり、有効なパーティションを形成できないため、拒否されます。 
4. 最初のゼロ以外の位置をプレフィックスエンドポイントとして固定します。 これにより、配列が左側の部分と右側の部分に分割されます。 左側の部分には、最初の非ゼロ要素によって引き起こされる選択された参照構造と等しい XOR があります。 
5. ここで、サフィックスに対するプレフィックス XOR を計算し、両方の部分が禁止された XOR 値に崩れることを避けるために、それを 2 つの連続する部分に分割する方法を見つけてください。 実際には、これは、最初のサフィックス セグメントの XOR がゼロでも参照 XOR 値にも等しくない、有効なカット位置を検索することを意味します。 
6. そのような分割点が存在する場合、私たちは受け入れます。 それ以外の場合、プレフィックス XOR の構造は、すべてのサフィックス プレフィックス XOR が 2 つの値のみに制限されることを意味し、これによりサフィックス内のすべての要素がゼロまたは参照値のいずれかになることが強制され、有効なパーティションが不可能になります。 

### なぜ効果があるのか

 正確さは、合計ゼロ XOR 制約の下でのプレフィックス XOR の動作に依存します。 合計 XOR がゼロになると、複数のセグメントへの有効なパーティションは、セグメント間で XOR 寄与のバランスを完全にとらなければなりません。 有効な分割が存在する場合は、サフィックス内に、最初の非ゼロ要素の構造によって引き起こされる 2 つの禁止値への崩壊を XOR で回避するプレフィックスが存在する必要があります。 

そのようなプレフィックスが存在しない場合、サフィックス XOR 空間は縮退します。つまり、すべてのプレフィックス XOR はゼロであるか、同じ非ゼロ値に固定されます。 これは、配列が事実上、ゼロと参照 XOR 値の 2 つの値のみで構成されていることを意味しており、これにより、3 つの異なる XOR 一貫性のあるセグメントの形成が妨げられます。 この構造的な剛性により、アルゴリズムが無効な構成を誤って受け入れたり、有効な構成を拒否したりできないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = 0
    for x in a:
        total ^= x

    if total != 0:
        print("YES")
        return

    first_nz = -1
    for i, x in enumerate(a):
        if x != 0:
            first_nz = i
            break

    if first_nz == -1:
        print("NO")
        return

    target = a[first_nz]

    # compute prefix xor on suffix
    seen = set()
    cur = 0

    for i in range(first_nz + 1, n):
        cur ^= a[i]
        # we try to find a prefix XOR that is valid
        if cur != 0 and cur != target:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```このソリューションではまずグローバル XOR をチェックし、簡単なケースを即座に解決します。 次に、最初の非ゼロ要素を識別します。これは、ゼロ XOR 領域の構造的議論のアンカーとして機能します。 サフィックス スキャンは実行中の XOR を維持し、サフィックスのプレフィックスが 2 つの禁止された XOR 値をエスケープしているかどうかをチェックします。 この状態は、有効な 2 番目のカットの存在に直接対応します。 

一般的な注意点は、スキャンが最初の非ゼロ要素の後に厳密に開始されるようにすることです。 これを含めると、アンカーの定義が混同され、サフィックスの構造的解釈が崩れてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
5
1 2 3 0 0
```ここで合計 XOR は`1 ^ 2 ^ 3 = 0`。 最初の非ゼロ要素はインデックス 0 にあり、値は 1 です。ターゲット = 1 に設定し、サフィックスをスキャンします。`[2,3,0,0]`。 

| 私 | a[i] | カーソル XOR | 有効ですか？ |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | はい (2 != 0 および 2 != 1) |

 2 番目の要素自体では、0 でも 1 でもないプレフィックス XOR がすでに見つかっているため、正常に分割できます。 

これは、合計 XOR がゼロの場合でも、「十分に豊富な」サフィックスによって有効なパーティションが直ちに生成されることを示しています。 

### 例 2

 入力:```
4
1 0 1 0
```合計 XOR はゼロです。 最初の非ゼロはインデックス 0 の 1 です。サフィックスは次のとおりです。`[0,1,0]`。 

| 私 | a[i] | カーソル XOR | 有効ですか？ |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | いいえ |
 | 2 | 1 | 1 | いいえ |
 | 3 | 0 | 1 | いいえ |

 サフィックスにプレフィックスがない XOR は回避します`{0,1}`したがって、有効な分割は存在しません。 

これは、すべての値が以下に制限される縮退構造を示しています。`{0, target}`、パーティションの成功を妨げます。

 ## 特殊なケース

 すべての要素がゼロの場合、アルゴリズムは合計 XOR をゼロとして正しく計算し、ゼロ以外のピボットは検出されません。 これは、どのパーティションも個別の XOR セグメントを作成できないという事実と一致して、すぐに NO を返します。 

配列にゼロ以外の要素が 1 つだけある場合、合計 XOR はゼロではないため、アルゴリズムはサフィックス分析を必要とせずにすぐに YES を返します。 これは、ゼロ以外の合計 XOR の下ではどの分割も有効であるという直観と一致します。 

配列がゼロと固定値の間で切り替わる場合、次のようになります。`[1,0,1,0]`、サフィックス スキャンでは外部でプレフィックス XOR が生成されることはありません。`{0,1}`したがって、アルゴリズムは正しく拒否し、有効なパーティションを妨げる制約された XOR 空間を反映します。
