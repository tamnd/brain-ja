 ## 解決策
 ## 問題の理解

 奇数の頂点、または少し調整して偶数の頂点が与えられ、ラベル付きノード間のエッジの構造化リストを明示的に構築する必要があります。 ノードは概念的には円上に配置され、エッジは繰り返される「ブロック」内に生成されます。各ブロックは開始インデックスの周囲の接続のローカル パターンによって定義され、循環的にラップされます。 

タスクは答えを計算することではなく、厳密な幾何学的パターンに従うエッジの特定の構造を出力することです。 各ブロックは正確に k 個のエッジを提供し、すべての有効な開始位置 i を反復し、そのブロックによって定義されたエッジを出力することによって完全な構造が形成されます。 

ステートメントは幾何学的に構成されていますが、根底にある要件は純粋に組み合わせです。循環シフト パターンに従う決定論的なエッジ シーケンスを生成し、偶数の場合には、一貫した方法で接続された追加の中心ノードを組み込みます。 

制約は明示的に指定されていませんが、このスタイルの問題では通常、n を 200000 以上まで許容します。 これにより、動的な接続を維持したり、エッジごとの構造を再計算しようとするシミュレーションは即座に排除されます。 唯一の実行可能なアプローチは、各エッジを O(1) 時間で構築し、線形合計時間で出力することです。 

素朴な推論による微妙な失敗例は、エッジが一意であるか、重複は問題ではないと仮定することです。 この構造では、エッジがブロック間で複数回出現する可能性がありますが、これは想定内のことです。 もう 1 つの問題は、特に i − j が非正になった場合に、巡回インデックスの処理を誤ることです。 モジュラー演算がないと、インデックスは静かに壊れます。 最後に、たとえ n であっても、中心ノードを忘れると対称性が崩れ、意図した構造が完全に無効になります。 

## アプローチ

 単純なアプローチでは、接続性を明示的にシミュレートしようとします。つまり、グラフを維持し、ブロックごとにエッジを追加し、場合によっては構造特性を検証したり、エッジの重複を排除したりすることになります。 この問題では検証が要求されず、構築のみが要求されるため、これはすでに不要です。 それを無視したとしても、動的グラフ構造の維持とコンポーネントのチェックには、O(nk) 個のエッジがあり、k は n に比例するため、最悪の場合でも少なくとも O(n^2) のコストがかかります。 

重要な観察は、その構築が完全に明示的であるということです。 各エッジは、i とオフセット j を含む単純な算術式で記述されます。 巡回インデックス以外のブロック間には依存関係はありません。 各ブロックが独立していることを受け入れると、タスク全体はモジュロ演算に基づいてペア (i − t、i + t + 1) を生成することになります。 

奇数 n の場合は、円だけで十分です。 偶数 n の場合、ブロックごとに 1 つの追加のエンドポイントに接続するセンター ノードを導入し、同じ対称性を維持しながら、同じ接続引数の機能を妨げるパリティの問題を修正します。 

強引なアプローチが「失敗」するのは、それが間違っているからではなく、構築がすでに最適で定型的であることを無視しているからです。 各ブロックが円上の変換されたパターンにすぎないという観察により、すべてが直接の式生成に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(n²) | O(n²) | 遅すぎる |
 | 直接施工 | O(n²) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 両方の場合の構築について説明しますが、実装ロジックは同じであり、算術シフトを使用してエッジを生成します。 

### 奇数 n = 2k + 1

 1. k = (n − 1) // を計算します。 2. これにより、各ブロックがその中心からどれだけ離れているかが決まります。 
2. i を 1 から n まで繰り返します。 各 i は、ノード i を中心とするブロックを定義します。 
3. ブロックごとに、t を 0 から k − 1 まで繰り返します。 
4. 各 t について、(i − t) と (i + t + 1) の間にエッジを作成し、インデックスを法 n として扱います。 
5. 各エッジを即座に出力します。

各ブロックは、ベース エッジ (i, i+1) から外側に広がる k 個の対称エッジを表します。 このペアリングにより、すべてのオフセット t が円に沿って反対方向に等距離にある 2 点を接続することが保証されます。 

### 偶数 n = 2k + 2

 1. k = (n − 2) // 2 を計算します。 
2. ノード 1 ～ 2k+1 をサイクルとして扱い、ノード 2k+2 を特別な中心ノードとして扱います。 
3. i を 1 から 2k + 1 まで繰り返します。 
4. 各 i について、奇数の場合と同じ k 個の循環エッジを生成します。 
5. さらに、「追加のエンドポイント」 i + k + 1 をセンター ノードに接続します。 
6. すべてのエッジをブロックの順序で出力します。 

中央のエッジは、奇数サイクルに存在するパリティ対称性の欠落を補い、各ブロックが正しい構造バランスに寄与することを保証します。 

### なぜ効果があるのか

 各ブロックは、i を中心とした対称オフセットでノードのペアを強制します。 すべてのブロックにわたって、すべてのエッジが制御されたオーバーラップ パターンに参加します。つまり、連続するブロックは、ステートメントで説明されている接続プロパティを保証する方法でエンドポイントを共有します。 周期的対称性により均一なカバレッジが確保され、偶数ケースの中心ノードは構造を破壊する不一致のエンドポイントを吸収することでバランスを回復します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    if n % 2 == 1:
        k = (n - 1) // 2
        for i in range(1, n + 1):
            for t in range(k):
                u = i - t
                v = i + t + 1
                u = (u - 1) % n + 1
                v = (v - 1) % n + 1
                print(u, v)
    else:
        k = (n - 2) // 2
        m = n - 1
        center = n
        for i in range(1, m + 1):
            for t in range(k):
                u = i - t
                v = i + t + 1
                u = (u - 1) % m + 1
                v = (v - 1) % m + 1
                print(u, v)
            print(i + k + 1, center)

if __name__ == "__main__":
    solve()
```奇数の場合は、循環式を直接エンコードします。 モジュロ変換により、概念円上でのラップアラウンド動作が保証されます。 

偶数の場合、最初の n−1 ノードをサイクルとして分離し、最後のノードを固定ハブとして扱います。 k 個の循環エッジを生成した後、最後のエンドポイントを中心ノードに接続します。 i + k + 1 のインデックス付けシフトは安全です。i の範囲は n−1 までのみであり、エンドポイントが範囲内に収まることが保証されます。 

よくある実装上の間違いは、負の数を含む Python モジュロを慎重に正規化する必要があることを忘れていることです。 (x−1) % n + 1 を使用すると、ゼロインデックスの曖昧性が完全に回避されます。 

## 実用的な例

 小さな奇数と偶数の場合の 2 つの例示的なトレースを作成します。 

### 例 1 (奇数 n = 5、k = 2)

 各 i に対して 2 つのエッジを生成します。 

| 私 | t | u (生) | v (生) | u (mod) | v (mod) | エッジ |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 2 | 1 | 2 | (1,2) |
 | 1 | 1 | 0 | 3 | 5 | 3 | (5,3) |
 | 2 | 0 | 2 | 3 | 2 | 3 | (2,3) |
 | 2 | 1 | 1 | 4 | 1 | 4 | (1,4) |

 i = 3、4、5 について同様に続けると、完全な循環オーバーラップが生成されます。 

このトレースは、ラップアラウンドによって境界を「交差する」エッジがどのように自然に生成されるかを示しています。これは円対称に不可欠です。 

### 例 2 (偶数 n = 6、k = 2)

 サイクルノードは1..5、中心は6です。 

| 私 | t | あなた | v | エッジ |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 2 | (1,2) |
 | 1 | 1 | 5 | 3 | (5,3) |
 | 1 | - | - | - | (3,6) |
 | 2 | 0 | 2 | 3 | (2,3) |
 | 2 | 1 | 1 | 4 | (1,4) |
 | 2 | - | - | - | (4,6) |

 これは、各ブロックが正しく閉じることを保証する追加の中央接続を示しています。 

このトレースは、同じ周期パターンを維持しながら、偶数の場合がブロックごとの最終エッジのみでどのように異なるかを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | n 個のブロックのそれぞれが k 個のエッジを出力します。k は n | に比例します。 
| スペース | お(1) | ループ変数以外のストレージはありません |

 この構築は意図的に高密度になっています。合計で Θ(n²) 個のエッジが生成されるため、実行時間は出力サイズによって支配されます。 すべてのエッジを明示的に印刷する必要があるため、これは最適です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    # assume solve() is defined above in actual submission
    # here we inline a minimal wrapper
    n = int(inp.strip())
    out = []

    if n % 2 == 1:
        k = (n - 1) // 2
        for i in range(1, n + 1):
            for t in range(k):
                u = (i - t - 1) % n + 1
                v = (i + t) % n + 1
                out.append(f"{u} {v}")

        k = (n - 2) // 2
        m = n - 1

        for i in range(1, m + 1):

                u = (i - t - 1) % m + 1
                v = (i + t) % m + 1
                out.append(f"{u} {v}")
            out.append(f"{i + k + 1} {center}")

    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、k = 0 であるため、アルゴリズムはエッジを生成しません。ループは決して実行されないため、出力は空になります。これは、単一ノードにはエッジがないという考えと一致します。 

n = 3、k = 1 の場合、各 i は正確に 1 つのエッジ (i, i+1) を生成します。 モジュロにより、(3,1) のような有効な循環エッジが引き続き生成され、ラップアラウンドの正確性が確認されます。 

n = 4、k = 1 の場合、偶数の場合、各ブロックは 1 つのサイクル エッジとノード 4 への接続に寄与します。i = 1 の場合、(1,2) と (3,4) が得られます。これは、中心が最終エンドポイントをどのように吸収するかをすでに示しています。 [1,3] の i について i + k + 1 が 4 を超えることはないため、アルゴリズムは安定しています。
