 ## 解決策
 ## 問題の理解

 有向グラフが与えられます$n$頂点。 各頂点は数値を含む位置を表し、グラフは区別された要素 (「キング」) の許可された移動、または同等の位置間の許可された交換をエンコードします。 

移動は、有向エッジに沿ってのみ可能です。 微妙な点は、エッジを使用できるかどうかが、そのエンドポイントに保存されている現在の値に依存することです。$u$に$v$の値の場合に許可されます。$u$の値より大きいです$v$。 目標は、任意の構成から始めて、最終的に一連の有効な操作を通じて任意の順列に到達できるように要素を再配置できるかどうかを理解することです。 

中心となる疑問は、有向グラフ自体に関する構造的なものに単純化されます。つまり、有向移動によって課される制約によって完全な再配置の自由が許可されるかどうかです。 

制約の観点から見ると、これは大規模な典型的なグラフ問題です。$n$そして$m$十分な大きさにすることができます$O(n^2)$推論は直ちに不可能です。 そのため、深さ優先検索や幅優先検索などの線形または線形に近いグラフ走査手法が推奨され、スワップや順列を明示的にシミュレートする試みから遠ざかることになります。 

よくある失敗例は、ローカル スワップの柔軟性がグローバルな再配置を暗黙的に想定していることに起因します。 たとえば、グラフに長さ 3 の有向サイクルが含まれているが、グローバルに強く接続されていない場合、サイクルだけですべての頂点の完全な置換が可能であると誤って仮定する可能性があります。 実際には、そのサイクルの外側の要素は分離されたままであるため、部分的な再配置のみが可能です。 

到達可能性を対称として扱う場合、別の微妙な失敗が発生します。 グラフでは次からの移動が可能になる場合があります。$u$に$v$しかし、元に戻ることはなく、方向性を無視した解決策では、スワップがグローバルに可能であると誤って結論付けられてしまいます。 

## アプローチ

 単純な考えは、スワップ プロセスを直接シミュレートすることです。 有効な移動を繰り返し適用し、順列を追跡することにより、到達可能なすべての構成を調査することもできます。 順列の数が増えるため、これはすぐに不可能になります。$n!$、さらに到達可能な状態に制限すると、各操作は複数の可能性に分岐します。 状態空間は中程度の場合でもすぐに爆発します$n$、このアプローチは完全に実行不可能になります。 

重要な構造上の観察は、詳細なスワッピング ルールは有向サイクル上で局所的にのみ重要であるということです。 サイクル内では、回転を繰り返すことでサイクルから離れることなく要素を移動できるため、値を任意に並べ替えることができます。 これは、強く接続されたすべてのコンポーネントが、要素を自由に再配置できる完全に柔軟なコンテナのように動作することを意味します。 

これを認識すると、全体的な問題は、すべての頂点が単一の柔軟なコンポーネントに属しているかどうかを理解することに帰着します。 これはまさに強接続有向グラフの定義です。すべての頂点が他のすべての頂点に到達できます。 

したがって、スワップをシミュレートする代わりに、グラフが強く接続されているかどうかを確認するだけで済みます。 そうである場合、サイクルベースの引数は完全な置換機能を保証します。 そうでない場合は、一部の頂点が一方向に到達できないため、一部の交換や再配置は基本的に不可能になります。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 頂点 1 から開始してすべての有向エッジをたどる深さ優先検索を実行します。 これにより、どの頂点が 1 から到達可能であるかがチェックされます。到達できない頂点がある場合、1 はグラフ全体に影響を与えることができないため、グローバルな再配置は不可能になります。 
2. グラフのすべてのエッジを反転し、頂点 1 から別の深さ優先検索を実行します。これにより、元のグラフのすべての頂点が 1 に到達できるかどうかがチェックされます。 このプロパティがないと、受信到達可能性の点で 1 から永久に分離された頂点が少なくとも 1 つ存在します。 
3. 両方の DFS トラバーサルがすべての頂点を訪問する場合、グラフが強く接続されていると宣言し、完全な再配置が可能であると結論付けます。 それ以外の場合は、不可能であると結論付けます。 

全ペアの到達可能性を直接テストする代わりに 2 つのトラバーサルを実行する理由は、強力な接続には古典的な特徴があるためです。つまり、1 つのノードが他のすべてのノードに到達し、他のすべてのノードがそのノードに到達するだけで十分かつ必要です。 

### なぜ効果があるのか

 有向サイクル内の交換引数は、強く接続されたすべてのコンポーネントが完全に並べ替え可能な要素のセットのように動作することを意味します。 グラフ全体が 1 つの強く接続されたコンポーネントである場合、任意の 2 つの頂点は何らかの有向サイクル上にあり、そのサイクル内で要素を任意に効果的に交換できます。 これにより、要素の任意のペアの転置をシミュレートできるようになり、任意の順列を生成するのに十分です。 グラフが強く接続されていない場合、少なくとも 2 つのコンポーネントが一方向のバリアで分離され、一部の要素が両方向に相互作用することができなくなり、完全な再配置がブロックされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj, n):
    vis = [False] * (n + 1)
    q = deque([start])
    vis[start] = True
    cnt = 1

    while q:
        u = q.popleft()
        for v in adj[u]:
            if not vis[v]:
                vis[v] = True
                cnt += 1
                q.append(v)

    return cnt == n

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        radj[v].append(u)

    if bfs(1, adj, n) and bfs(1, radj, n):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```順方向 BFS は、頂点 1 が他のすべての頂点に到達できるかどうかをチェックします。 逆 BFS は、すべての頂点が頂点 1 に到達できるかどうかをチェックします。これらは一緒になって、完全な強接続コンポーネントの明示的な計算を回避する方法で、標準の強接続テストを実装します。 

唯一の微妙な実装の詳細は、入力時に逆の隣接リストを構築することです。 これにより、トラバース中の反転エッジの再計算が回避され、ソリューションが線形に保たれます。 

## 実用的な例

 4 つの頂点とエッジを持つグラフを考えてみましょう。$1 \to 2$、$2 \to 3$、$3 \to 1$、$3 \to 4$。 コンポーネント$\{1,2,3\}$は強く接続されていますが、頂点 4 には頂点 3 からのみ到達できます。 

### BFS を 1 から転送

 | ステップ | キュー | 訪問 |
 | --- | --- | --- |
 | 開始 | [1] | {1} |
 | 訪問 1 | [2] | {1,2} |
 | 訪問 2 | [3] | {1,2,3} |
 | 訪問 3 | [4] | {1,2,3,4} |
 | 訪問 4 | [] | {1,2,3,4} |

 前方到達可能性は成功します。 

### BFS を 1 から反転

 | ステップ | キュー | 訪問 |
 | --- | --- | --- |
 | 開始 | [1] | {1} |
 | 訪問 1 | [3] | {1,3} |
 | 訪問 3 | [2,4] | {1,2,3,4} |
 | 訪問 2 | [ ] | {1,2,3,4} |
 | 訪問 4 | [ ] | {1,2,3,4} |

 逆到達性も成功し、この例では強力な接続が確認されています。 

これは、サイクルがすべてを接続するときに一方向エッジがグローバルな到達可能性を制限しない一方で、サイクルによって完全な相互作用が可能になることを示しています。

 ## 特殊なケース

 両方向の到達可能性は自明であるため、単一の頂点グラフは常に強い接続性を満たします。 どちらの DFS 呼び出しも唯一のノードで開始され、すぐにすべての頂点にアクセスするため、アルゴリズムはこれを処理します。 

エッジがなく複数の頂点があるグラフは、両方の到達可能性チェックに失敗します。 頂点 1 から開始すると、他の頂点には到達しないため、順方向 DFS はすぐに失敗します。 

完全な循環グラフは期待どおりに動作します。両方の DFS トラバーサルは、サイクルを介した相互到達可能性によりすべての頂点をカバーし、スワッピング引数がグローバルに適用されることを確認します。
