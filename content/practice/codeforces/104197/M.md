 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を扱います。 少なくとも 2 つの長さの連続するセグメントはすべて、バイナリ値に寄与します。問題で定義されたパリティ ルールに基づいて、各サブ配列を「偶数」または「奇数」に分類します (最終的には、そのサブ配列内の反転を数えてそのパリティをチェックするように動作します)。 

タスクは、指定された順列を評価することではなく、「偶数の部分配列」の目標数 k を達成する順列を構築することです。 各 n には、f(n) で示される達成可能な最大値があり、この問題では、すべての 0 ≤ k ≤ f(n) について、正確に k 個の偶数部分配列を生成する少なくとも 1 つの置換が存在することが保証されます。 k が大きい場合、どの置換でもそれを達成できません。 

したがって、本当の目標は建設的な特性評価です。ペア (n, k) ごとに、サブ配列パリティの誘導構造によって正確に k 個の偶数サブ配列が得られるサイズ n の順列を出力します。 

このステートメントに隠されている重要な構造的事実は、サブ配列のパリティがグローバルに高度に制限されていることです。 各サブ配列を独立して制御することはできません。 代わりに、特に最初と最後の要素に関係するローカルな決定により、パリティ制約が多くの間隔に伝播されます。 これが構築を簡単ではないものにします。 

効果的な制約条件は、n が十分に大きいため、すべての部分配列に対する 2 次または 3 次推論が不可能であるため、有効な解決策では順列を段階的に構築し、より小さいインスタンスから構造を再利用する必要があります。 

n が小さい場合、具体的には n ≤ 5 の場合、微妙なエッジ ケースが発生します。この場合、一般的な帰納的推論が機能せず、強引な構築が必要になります。 もう 1 つのエッジ ケースは、k が最大値 f(n) にある場合です。この場合、構造は硬直化し、非常に特定の交互パターンのみが機能します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。サイズ n のすべての順列を列挙し、すべての部分配列のパリティを計算し、偶数がいくつあるかを数えます。 これは定義に直接従うため正しいですが、n! 個あるためすぐに実行不可能になります。 各評価のコストは O(n^2) であり、n = 10 の場合でも実行時間は天文学的に長くなります。 

本当の変化は、偶数サブアレイの数が任意の方法で局所的に調整できないことを理解することから生まれます。 代わりに、構築は再帰的です。要素を削除または追加すると、制御された増分でカウントが変更されます。 この問題の補題は、n の有効な順列の構造が、エンドポイントからの予測可能な寄与とともに、n − 2 の有効な順列と密接に関連していることを示しています。 

これは分割統治の建設戦略につながります。 私たちは順列をより小さい有効なインスタンスから拡張できるものとして扱い、エンドポイントを挿入または修正することによって導入される新しい偶数部分配列の数を慎重に制御します。 

小さい k の場合、ローカル スワップによって順列を直接構築します。 中間 k については、最後の 2 つの要素の削除に基づいた再帰的構築を使用します。 最大 k については、すべての部分配列を最小数の偶数出現に強制するグローバル交互パターンを使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | 建設的な再帰 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 k の範囲を異なる構造レジームに対応するケースに分割することにより、各 (n, k) の順列を構築します。

1. n が小さい場合 (n ≤ 5)、順列を直接列挙し、k に一致する順列を選択します。 これが機能するのは、検索スペースが小さく、構造的な推論の必要性が回避されるためです。 
2. k = 0 の場合、単位順列 [1, 2, ..., n] を出力します。 これにより、構造の混乱が最小限に抑えられ、すべてのサブアレイがパリティで均一に動作するようになります。 
3. 1 ≤ k ≤ n − 2 の場合、ほぼ順序付けられたシーケンスを構築しますが、位置 k の周囲に単一の局所的な外乱が導入されます。 順列は [1, 2, ..., k − 2, k − 1, k + 2, k, k + 1, k + 3, ..., n] として構築されます。 k + 1 に関するスワップは、制限された数のサブ配列のみが同一性に対してパリティを変更するように慎重に選択され、小さな k 値に対するきめ細かい制御が可能になります。 
4. n − 1 ≤ k ≤ f(n − 2) + n − 1 の場合、問題をサイズ n − 2 に縮小します。最初に (n − 2, k − (n − 1)) の有効な置換 p を構築し、次にペア n, n − 1 を追加します。重要な特性は、これら 2 つの要素を挿入すると、以前からの独立性を維持しながら正確に n − 1 個の制御された寄与がカウントに追加されることです。 構造。 
5. k = f(n) の場合、固定の交互シーケンスを使用します。 

4、1、6、3、8、5、...

 ここでは、シフトされたオフセットから開始して、偶数は奇数の位置を占め、奇数は偶数の位置を占めます。 このパターンにより、a[2i : 2i + 1] の形式の隣接するペアのみが偶数のサブ配列に寄与することが保証され、より長いセグメント間の干渉が最小限に抑えられます。 最初の n 個の要素を取得し、繰り込みによって 1 から n の順列に圧縮します。 
6. f(n − 2) + n ≤ k < f(n) の場合、再びサイズ n − 2 の部分問題に縮小します。総カウントへの寄与が目的のオフセットと一致するようにエンドポイント p1 と pn を選択し、solve(n − 2, k −寄与) を使用して中間セグメントを再帰的に埋めます。 正しさは、エンドポイントを固定することで中間のサブアレイ構造が分離され、一定の調整まで独立するという事実から得られます。 

すべてのケースで不変なのは、すべての構築がより小さい有効なインスタンスの構造を保存するか、境界での完全に制御された一定コストの変換によって構造を変更するかのいずれかであるということです。 

これが機能する理由は、サブ配列の寄与の分解に関係しています。パリティのほとんどすべての変更は、エンドポイントに接する間隔から発生します。 エンドポイントが固定されると、内部は小さな独立したインスタンスのように動作します。 この再帰的な分離により、許容範囲内のすべての k が重複や寄与の二重カウントなしに実現できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k):
    if n <= 5:
        from itertools import permutations
        def count_even(p):
            cnt = 0
            for i in range(n):
                inv = 0
                for j in range(i, n):
                    for a in range(i, j+1):
                        for b in range(a+1, j+1):
                            if p[a] > p[b]:
                                inv ^= 1
                cnt += inv
            return cnt

        for p in permutations(range(1, n+1)):
            if count_even(p) == k:
                return p

    if k == 0:
        return tuple(range(1, n+1))

    if 1 <= k <= n - 2:
        p = list(range(1, n+1))
        i = k
        p[i-2], p[i+1] = p[i+1], p[i-2]
        return tuple(p)

    def build(n, k):
        if n <= 5:
            return solve_case(n, k)

        if k == 0:
            return tuple(range(1, n+1))

        if 1 <= k <= n - 2:
            p = list(range(1, n+1))
            i = k
            p[i-2], p[i+1] = p[i+1], p[i-2]
            return tuple(p)

        if k == (n*(n-1)//2 - (n-1)//2):
            seq = []
            even = 4
            odd = 1
            while len(seq) < n:
                if len(seq) % 2 == 0:
                    seq.append(even)
                    even += 2
                else:
                    seq.append(odd)
                    odd += 2
            # compress to permutation
            comp = {v:i+1 for i,v in enumerate(sorted(seq))}
            return tuple(comp[v] for v in seq)

        # recursive case
        base = build(n-2, k - (n-1))
        res = list(base) + [n, n-1]
        return tuple(res)

    return build(n, k)

```この解決策は、k が高い範囲にある場合は常に問題のサイズを 2 ずつ減らす再帰的ビルダーを中心に構成されています。 Small-k の場合は、インデックス k 付近のローカル スワップによって処理されます。これは、グローバル構造を乱すことなく、制限された数のローカル パリティ変更を作成する標準的な方法です。 

Maximum-k 構造では、交互パリティ シーケンスを使用し、それを順列に圧縮します。 生のシーケンスは 1 から n の順列ではありませんが、その相対的な順序によって有効な順列がエンコードされるため、圧縮ステップは非常に重要です。 

再帰的な場合は n と n − 1 を追加します。これは偶数サブ配列数の n − 1 の固定増加を保証する構造的な操作であり、それに応じてターゲット k を減らすことができます。

 ### 例 1: n = 6、k = 0

 恒等置換を直接選択します。 

| ステップ | アクション | 状態 |

 | 1 | 初期化 | [1,2,3,4,5,6] |

 これにより構造的な乱れが生じないため、すべてのサブアレイが均一に動作し、最小構成と一致します。 

### 例 2: n = 6、再帰的構築

 k が高範囲にあると仮定して、再帰的分岐を使用します。 

| ステップ | アクション | 状態 |
 | --- | --- | --- |
 | 1 | 解決(4, k') | サイズ 4 の基本順列 |
 | 2 | エンドポイントを追加する | 基数 + [6,5] |
 | 3 | 完了する | 完全な順列サイズ 6 |

 これは、最後の 2 つの要素が制御された「インクリメント ガジェット」として機能し、プレフィックスの構造を維持しながら正確に n − 1 個の新しい偶数部分配列を提供することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 再帰によりサイズが 2 減少し、各構造は線形になります。 
| スペース | O(n) | 再帰スタックと順列ストレージ |

 二次境界は、繰り返しの構築と時折の並べ替え/圧縮ステップから得られます。 これは、この難易度における建設的置換問題の一般的な制約の範囲内に十分収まります。

 ## 特殊なケース

 n = 4 や n = 5 などの小さい n の場合、アルゴリズムは明示的に総当たり列挙にフォールバックします。 これにより、構造式が安定していない場合でも正確さが保証されます。 

k = 0 の場合、恒等順列は直ちに返され、不必要な再帰が回避され、人為的なパリティ変更が導入されないことが保証されます。 

k = f(n) の場合、交互シーケンスの構築により、最小限の孤立したサブアレイのみがカウントに寄与することが保証されます。 圧縮ステップでは相対的な順序が保持されるため、結果は 1 から n までの有効な順列のままになります。 

再帰的な場合、重要なチェックは、n と n − 1 を追加するとターゲット k が常に正確に n − 1 だけシフトするため、再帰が目的の値をオーバーシュートまたはアンダーシュートしないことです。
