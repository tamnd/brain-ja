 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、一連のスワップを通じて変更されます。 変更を加えるたびに、現在の順列の「美しさ」と呼ばれる値を計算する必要があります。 

その美しさは順列の構造的特性に依存しますが、最終的にはいくつかのパリティに基づく条件と単純なグローバル統計に崩壊します。 定義は反転ベースの推論から始まりますが、最終的な決定には明示的に反転をカウントしたり、各スワップ後に反転を再計算したりする必要はありません。 

各クエリは 2 つの位置を交換することによって順列を変更します。 交換のたびに、結果として生じる置換の美しさを出力する必要があります。 

重要な制約の意味は、$n$また、クエリの数が十分に多いため、スワップのたびに反転関連のプロパティを最初から再計算すると時間がかかりすぎます。 線形時間でクエリごとに反転またはサイクルを再評価するソリューションでは、おおよその結果が得られます。$O(nq)$これは、この形式の典型的な Codeforce 制約の許容限界をはるかに超えています。 目的のソリューションでは、スワップごとの更新数を一定または対数に維持する必要があります。 

順列がすでにソートされている場合、微妙なエッジケースが発生します。 その状況では、すべてのサブシーケンスはソートされたままになり、美しさは特別な値に退化します。$-1$。 このケースは明示的に分離する必要があります。そうでないと、パリティ ケースの 1 つとして誤って分類されます。 

もう 1 つのエッジ ケースは、グローバル構造をあまり変更せずに、スワップによって固定点が作成または破壊されたり、パリティ条件に影響を与えたりする場合に発生します。 たとえば、すでに正しい 2 つの位置を交換すると、ローカル構造が変わっていないように見えても、予期せず順列パリティが反転する可能性があります。 

## アプローチ

 直接的なアプローチでは、スワップのたびに必要なプロパティが再計算されます。 毎回反転カウントまたはサイクル分解を再計算しようとすることもできます。 美の定義は反転構造と順列パリティから導かれるため、これは概念的には機能しますが、計算的には失敗します。 

クエリごとの逆変換の再計算コスト$O(n)$または$O(n \log n)$、そしてこれを行うのは$q$オペレーションは～につながります$O(nq)$または$O(nq \log n)$、両方が最大の場合、これは大きすぎます。$2 \cdot 10^5$。 

重要な観察は、最終的な式は 3 つのグローバル プロパティのみに依存するということです。 

順列のパリティ、インデックスの数。$p_i \equiv i \pmod 2$、および固定点の数$p_i = i$。 

これらはそれぞれ段階的に保守できます。 置換のパリティは、スワップの下で予測どおりに変化します。どのスワップも 1 つの転置に対応し、置換パリティが反転します。 パリティは、置換パリティが等しいという古典的な事実を使用して初期化することもできます。$n - \text{cycles}$、または実際には反転パリティを介して 1 回計算されます。 

2 番目の数量、つまりパリティ位置の一致は、各要素のインデックス パリティがその値パリティと一致するかどうかにのみ依存します。 スワップは 2 つのポジションにのみ影響するため、このカウントは次のように更新されます。$O(1)$。 固定点についても同様です。 

これらが維持されると、各クエリは一定時間の分類に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース再計算構造 |$O(nq)$|$O(n)$| 遅すぎる |
 | パリティ + カウンタを段階的に維持する |$O(n + q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 プロセス中に、順列のパリティ、インデックス パリティが値パリティと一致する位置のカウンタ、および固定小数点のカウンタという 3 つの情報を維持します。 

### ステップ

 1. 順列を初期化し、各位置が満たされるかどうかを計算します。$p_i = i$そしてどうか$p_i \bmod 2 = i \bmod 2$。 これにより、2 つのカウンターの初期値が得られます。 
2. 順列の初期パリティを計算します。 これは、反転をカウントするか、サイクル分解を計算して次を使用することによって実行できます。$n - \text{cycles}$。 
3. ポジション間のスワップクエリごとに$a$そして$b$、まず、これら 2 つの位置によって影響を受けるすべてのカウンターを更新します。 これは、交換する前に古い貢献を削除し、交換後に新しい貢献を追加することを意味します。 
4. 置換配列にスワップを適用します。 
5. 単一のスワップは転置でありパリティが変更されるため、置換のパリティを反転します。 
6. スワップを適用した後、順列が奇数かどうか、すべての位置がパリティ アラインメントを満たしているかどうか、すべての位置が固定小数点であるかどうかの 3 つの条件を順番にチェックします。 
7. これらの条件に基づいて、対応する美しさの値を出力します。 

各条件が順列のより制約された構造を表すため、決定ロジックは階層的になります。 

### なぜ効果があるのか

 その正しさは、美しさの値が、置換状態の 3 つの不変条件、つまり置換パリティ、インデックスと値のパリティ アライメント、および非固定構造の存在によって完全に決定されるという事実から得られます。 各スワップはこれらの不変条件の一定数のみを変更し、それらはすべて正確に維持されます。 これらの不変条件の外側に隠された構造特性が最終的な分類に影響を与えることはないため、各更新後の決定は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))

    cnt_eq = 0
    cnt_same_par = 0

    for i in range(n):
        if p[i] == i + 1:
            cnt_eq += 1
        if (p[i] % 2) == ((i + 1) % 2):
            cnt_same_par += 1

    inv_parity = 0
    seen = [0] * (n + 1)
    for x in p:
        seen[x] = 1
    # permutation parity via cycles
    cycles = 0
    vis = [0] * (n + 1)
    for i in range(1, n + 1):
        if not vis[i]:
            cycles += 1
            cur = i
            while not vis[cur]:
                vis[cur] = 1
                cur = p[cur - 1]

    inv_parity = (n - cycles) % 2

    def get_answer():
        if inv_parity == 1:
            return n
        if cnt_same_par != n:
            return n - 1
        if cnt_eq != n:
            return n - 2
        return -1

    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        for i in (a, b):
            if p[i] == i + 1:
                cnt_eq -= 1
            if (p[i] % 2) == ((i + 1) % 2):
                cnt_same_par -= 1

        p[a], p[b] = p[b], p[a]

        for i in (a, b):
            if p[i] == i + 1:
                cnt_eq += 1
            if (p[i] % 2) == ((i + 1) % 2):
                cnt_same_par += 1

        inv_parity ^= 1

        print(get_answer())

if __name__ == "__main__":
    solve()
```この実装では、配列内の順列が維持され、交換された 2 つの位置のみが更新されます。 スワップの前に、両方のカウンターへの寄与を削除し、次にスワップを適用してから、寄与を再度追加します。 これにより、完全な再計算が回避されます。 

各スワップは単一の転置であるため、置換パリティは各スワップの直後に切り替えられます。 

Answer 関数は、推論で説明したとおりに階層ロジックを正確にエンコードします。最初に奇数の順列が優先され、次にパリティのアライメントが優先され、次に固定小数点の完全性が優先されます。 

よくある落とし穴は、スワップする前に寄与分を差し引くのを忘れることです。 スワップ後にのみ更新を行うと、二重カウントエラーが発生します。 

## 実用的な例

 サイズの小さな順列を考慮してください$4$:$[1, 3, 2, 4]$。 

各ステップでカウンターを追跡します。 

### 例 1

 初期状態:

 | 私 | p[i] | 固定点 | パリティマッチ |
 | --- | --- | --- | --- |
 | 1 | 1 | はい | はい |
 | 2 | 3 | いいえ | いいえ |
 | 3 | 2 | いいえ | いいえ |
 | 4 | 4 | はい | はい |

 それで`cnt_eq = 2`、`cnt_same_par = 2`、初期パリティが偶数であると仮定します。 

スワップ (2, 3) 後の順列は次のようになります。$[1, 2, 3, 4]$。 

| 私 | p[i] | 固定点 | パリティマッチ |
 | --- | --- | --- | --- |
 | 1 | 1 | はい | はい |
 | 2 | 2 | はい | はい |
 | 3 | 3 | はい | はい |
 | 4 | 4 | はい | はい |

 今`cnt_eq = 4`、`cnt_same_par = 4`、順列はソートされ、偶数パリティになります。 

出力は次のようになります$-1$、順列が完全にソートされているためです。 

このトレースは、ソートされた場合にのみ、両方のカウンターがどのように完全な位置合わせに収束するかを示しています。 

### 例 2

 順列:$[2, 1, 4, 3]$| 私 | p[i] | 固定点 | パリティマッチ |
 | --- | --- | --- | --- |
 | 1 | 2 | いいえ | はい |
 | 2 | 1 | いいえ | はい |
 | 3 | 4 | いいえ | はい |
 | 4 | 3 | いいえ | はい |

 ここ`cnt_eq = 0`、`cnt_same_par = 4`。 

順列パリティが偶数の場合、条件は`cnt_same_par == n`成り立つが、`cnt_eq != n`、したがって出力は次のようになります$n - 2 = 2$。 

これは、第 2 レベルのフォールバックを示しています。つまり、パリティの調整は満たされていますが、構造は完全には同一ではありません。

 ## 特殊なケース

 最もデリケートなケースは、完全にソートされた順列です。 その状況では、どちらも`cnt_same_par`そして`cnt_eq`は最大のままであり、唯一の有効な出力は$-1$。 カウンタの初期化に誤りがあるか、固定小数点を正しく処理できないと、誤ってエラーが発生します。$n$または$n-1$。 

もう 1 つのエッジ ケースは、両方とも固定点である 2 つの要素を交換することです。 固定小数点のカウンターは 2 減り、その後正しく加算されますが、置換パリティは依然として反転します。 スワップ操作ではなく要素値に基づいてパリティを更新する単純な実装では、この反転を見逃してしまいます。 

3 番目のケースは、パリティ アラインメントがグローバルに保持されるが、固定点が存在しない場合です。 これにより、$n - 2$条件の順序が間違っていると、誤ってこの分岐をスキップしてしまう可能性があります。
