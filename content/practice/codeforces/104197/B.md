 ## 問題の理解

 長さのバイナリ配列を扱っています$n$、各要素は 0 または 1 です。そのような配列から$a$、派生配列$b$固定ウィンドウ サイズにわたるスライド合計によって定義されます$k$。 各ポジション$b_i$の合計を表します$k$の連続要素$a$、分析におけるインデックス関係を通じて暗黙的に循環構造を包み込みます。 

問題は、単一の配列を再構築することではなく、同じ派生配列を生成するバイナリ配列がいくつあるかを数えることです。$b$。 言い換えれば、変換下のバイナリ配列の同値クラスのサイズが必要になります。$k$スライド合計」。 

入力の説明は直接配列変換のように見えますが、重要な問題は、複数の異なるバイナリ配列が同じスライディングサム表現に崩壊する可能性があることです。タスクは、その数を正確に定量化することです。 

(編集構造から暗黙的に示される) 制約は、次のことを示唆しています。$n$サイズが大きくなる可能性があるため、単純な組み合わせ方法で明示的に配列やサイクルを列挙するソリューションは実行不可能です。 指数関数的なものは何でも$n$はすぐに除外され、テスト ケースごとの二次推論ですら遅すぎます。 これにより、インデックスの構造的分解が進められます。 

スライディングサム配列が一定の場合、微妙なエッジケースが発生します。 その場合、要素間の制約は局所的になくなり、変数のグループ全体が自由な選択になります。 単純な再構成では、一意性を誤って仮定し、組み合わせ爆発を見逃してしまいます。 

別の特殊なケースが発生するのは、$k$そして$n$は互いに素ではありません。 インデックスは互いに素なサイクルに分割され、この構造を誤解すると、独立したコンポーネントを過大カウントまたは過少カウントすることにつながります。

 ## アルゴリズムのチュートリアル

 ### 1. 構造パラメータを計算する

 私たちは計算します$g = \gcd(n, k)$。 この値は、繰り返し追加された場合にインデックスがどのように分割されるかを決定します。$k$。 各位置は、繰り返し加算することによって形成される 1 つのサイクルに正確に属します。$k$モジュロ$n$。 

これが重要な理由は、一歩踏み出すことです。$k$インデックスを独立したコンポーネントに分割するため、制約がサイクル境界を越えることはありません。 

### 2. サイクル長と縮小サイズを決定する

 各サイクルには長さがあります$l = \frac{n}{g}$、そして、あります$g$合計サイクル数。 制約では異なるサイクルにわたる要素が混合されないため、各サイクルを個別に扱います。 

この削減により、グローバルな依存関係の問題が、繰り返される同一のローカルな問題に変わります。 

### 3. 制約の強さによってサイクルを分類する

 各サイクル内で、次のような違いが生じた場合、$b$すべてがゼロではない場合、そのサイクル内のすべての値は一意に決定されます。 それ以外の場合、サイクルは「均一」です。これは、そのすべての要素が等しい必要がありますが、すべて 0 またはすべて 1 のいずれかであることを意味します。 

この区別は、サイクルが乗算的に (固定的に) 寄与するか、組み合わせ的に (選択的に) 寄与するかを決定するため、非常に重要です。 

### 4. 均一サイクルの構成をカウントする

 しましょう$t$一様サイクルの数になります。 このような各サイクルはオール 0 またはオール 1 のいずれかになりますが、グローバル構造はスライド和と相互作用するため、合計でオール 1 のサイクルの数のみが重要になります。 

したがって、固定の場合$t$、 がある$t+1$意味のある選択肢は、そのうちの何人が選択肢に貢献したかに応じて決まります。 

### 5. 可能なすべての合計を計算します$t$ここで、すべての方法を合計して、均一なサイクルとその割り当て方法を選択します。 これにより、次の形式の二項和が得られます。$$\sum_{t=0}^{g} \binom{g}{t} (t+1) A^{g-t}$$どこ$A$制約されたサイクルの内部変動をエンコードします。 

この式は、標準の二項恒等式を使用して、次のような閉じた形式に簡略化されます。$(A+1)^g$そして$g(A+1)^{g-1}$、迅速な評価が可能になります。 

### なぜ効果があるのか

 The key invariant is that each cycle behaves independently under the transformation induced by sliding sums. The transformation only connects indices at distance$k$、サイクルから離れることはありません。 したがって、すべての有効な配列は、サイクル分類ごとに行われる独立した選択によって一意に表されます。 カウントは干渉することなく独立した寄与を結合することになり、サイクル全体で過剰カウントが発生しないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, k = map(int, input().split())
    g = 1
    import math
    g = math.gcd(n, k)

    l = n // g

    a = (pow(2, l, MOD) - 2) % MOD
    if a < 0:
        a += MOD

    # final expression: (a+1)^g + g*(a+1)^(g-1)
    base = (a + 1) % MOD

    ans = modpow(base, g)
    ans = (ans + g * modpow(base, g - 1)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は代数的単純化を直接反映しています。 gcd を使用してサイクル数を計算し、問題を閉じた形式の式の評価に落とし込みます。 べき乗剰余演算は、大きな累乗を効率的に処理します。 

計算するときは注意が必要です$2^l - 2$、係数を適用する前に減算すると負の値が生成される可能性があるためです。 第 2 項では、$g \cdot base^{g-1}$、これもモジュロ MOD を減らす必要があります。

 ## 特殊なケース

 いつ$g = \gcd(n,k) = 1$、配列全体が単一サイクルを形成します。 この状況では、アルゴリズムはすべてを 1 つの組み合わせコンポーネントにまとめます。 式は次のようになります$(a+1) + 1$これは、複数のサイクル間に相互作用がないことを反映しています。 複数の独立したコンポーネントを想定した単純な実装では、ここで過大な数が計算されます。 

いつ$k = n$、すべてのスライディング ウィンドウは配列全体です。 これにより、導出されたすべての合計が強制的に同一になり、サイクル構造が完全に退化します。 アルゴリズムは正しく次のように与えます$g = n$つまり、各インデックスは独自の自明なサイクルであるため、組み合わせの爆発は次のべき乗を通じて捕捉されます。$n$独立した二者択一。
