 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$高い位置に座るグリッド$z=1$, ここで、各セルにはすでに色の付いた単位立方体が含まれています。 このベース レイヤーの上の整数座標に色付きの立方体を追加で積み重ねることはできますが、座標平面上のセルの使用はブロックされます。$x=0$、$y=0$、 または$z=0$したがって、構造は常に正の八分円内に存在し、より高い層への成長を介する場合を除いてグリッドの外側に「固定」することはできません。 

目標は、すべての色について、その色のすべての立方体が単一の接続された 3D コンポーネントを形成するようにすることであり、接続性は完全な 3D ラティス内の面の隣接性によって定義されます。 初期構成では、同じ色の複数の切断されたコンポーネントがグリッド内に散在している可能性があるため、戦略的に最大でも追加する必要があります。$4 \cdot 10^5$それらを「配線」するための追加の立方体。 

重要な問題は、接続が飛行機に限定されないことです。$z=1$。 私たちは 3 次元で構築することが許可されており、この自由度により、比較的少数の追加立方体を使用して、複数の切断された平面コンポーネントを結合することが可能になります。 

制約の寸法は小さいですが、許容される構築サイズは大きくなります。 以来$n, m, k \le 50$、入力グリッドには最大 2500 個のキューブがあるため、グリッド上でペア、コンポーネント、または BFS を処理する推論は簡単に実現可能です。 唯一の本当の困難は、追加された立方体が 2 次または 3 次の増加に爆発することなく、潜在的に多くの散在するコンポーネントを接続する、制限されたサイズの構造を構築することです。 

素朴なアイデアは、各色を独立して扱い、グリッド平面内のすべての接続コンポーネントを計算し、3D 空間の最短マンハッタン パスを使用してそれらをペアごとに接続することです。 接続しているため、最悪の場合、これはすぐに失敗します。$t$ペアごとに必要なコンポーネント$\Theta(t^2 \cdot nm)$多くの色が断片化されている場合、制限を簡単に超えてしまいます。 

より微妙な失敗は、貪欲な平面接続によって発生します。 内部でコンポーネントを接続しようとすると、$z=1$レイヤーのみでは、異なる色のパスが互いにブロックしたり、再配線や指数関数的な爆発を強いる形で重なったりする障害物に遭遇する可能性があります。 

具体的な問題となる構成は、すべての色が多数の孤立した単一セルに現れる市松模様のような色分布です。 平面上でそれらを別々に接続しようとすると、回廊が重なり、制御不能な成長が発生します。 

このソリューションでは、代わりに、構造化された再利用可能な構造を使用してすべての色を接続できる共有 3D 「バックボーン」を利用する必要があります。 

## アプローチ

 ブルート フォースの観点では、各カラー クラスを、グリッドの隣接性によって引き起こされるグラフとして表示します。$z=1$層。 まず、その連結成分を計算します。 色がある場合$t$コンポーネントを 1 つに接続する必要があります。 簡単な方法は、コンポーネントごとに代表的なセルを選択し、3D の最短のマンハッタン パスを使用してそれらを順番に接続することです。 

マンハッタンのパスは接続性を維持し、交差しない限り他の色に影響を与えないため、これは原理的には正しいです。 ただし、最悪の場合、異なる色では互換性のない方法でパスをオーバーラップする必要があります。 立方体間の衝突を避けなければならないため、空間を自由に再利用することができず、各パスが迂回を余儀なくされ、構造が大幅に膨張する可能性があります。 

重要な構造的洞察は、色ごとに独立した最短パスが必要ないということです。 代わりに、ユニバーサル ルーティング スペースとして機能する単一のモノトーンの「はしご」構造を 3 次元に構築できます。 すべての色のコンポーネントは平面内で直接接続されるのではなく、制御された垂直方向の拡張を介して接続され、各行または列が異なるレイヤーに持ち上げられ、分離性が確保されます。 

重要な点は、元のグリッドの幾何学的制約を保持する必要はなく、各色内の接続性を保証する必要があるだけであるということです。 これにより、グリッド上の列の固定足場を介してすべての接続をルーティングし、各行または列に固有の垂直「トラック」を割り当てることができるため、干渉することなくマージを行うことができます。 

各行に垂直列を割り当て、行を共通の高さに持ち上げることで、行全体に出現する色のすべてを接続します。 次に、その高さ内でグリッド方向に沿って接続します。 各行は垂直方向の空間で独立して処理されるため、色間または同じ色の異なるコンポーネント間で競合が発生することはありません。 

これにより、二次相互作用の可能性がある問題が、グリッド セル上の線形構成に変換されます。

 ## アルゴリズムのチュートリアル

 私たちは、制御されたリフトを通じてすべての色が確実に接続されるようにするグローバル 3D ルーティング システムを構築します。 

1. 各行を割り当てます$i$専用の高さレベル$z = i + 1$。 これにより、異なる列からの立方体が垂直に持ち上げられたときに干渉することがなくなります。 行を分ける理由は、複数の色が同時に処理される場合の衝突を避けるためです。 
2. すべてのセルについて$(i, j)$入力グリッドの次の位置に垂直立方体を追加します。$(i, j, 2)$ベース層からブリッジを形成する必要がある場合$z=1$行の専用レイヤーに$z=i+1$。 これにより、行レイヤーへのすべてのグリッド位置に制御された「エントリ ポイント」が作成されます。 
3. 各行レイヤー内$z=i+1$、その行内の同じ色のすべてのセルを、線に沿って水平チェーンに接続します。$j$-軸。 これを行うには、同じ色の連続する列間の面の接続を確保する立方体を追加します。 これにより、行内で出現するすべての色の接続が保証されます。 
4. 各行に色ごとに接続されたセグメントが含まれたら、固定列位置で 1 つの追加の垂直スパインを使用して、各色の行を接続します (たとえば、$j=1$）。 各色について、各行の少なくとも 1 つのオカレンスがこのスパインにリンクされていることを確認し、行全体にわたるバックボーンを形成します。 
5. 最後に、すべての色に行背構造を通る接続されたパスが少なくとも 1 つあることを確認します。 行に色が完全に欠落している場合、その色はスキップされます。 接続は、それを含む行を通じて確保されます。 

これが機能する理由は、各色のコンポーネントが最初に行内で接続され、次に行が共有の垂直構造を通じて接続されるためです。 これにより、問題は、任意の平面コンポーネントではなく、木のような足場全体にわたる接続間隔に限定されます。 

### なぜ効果があるのか

 不変条件は、行の処理後です。$i$、その行内の特定の色のすべての出現は、レイヤー内の単一の連結コンポーネントに属します。$z=i+1$、すべての行レイヤーはグローバル垂直スパインに接続されています。 すべての行にはスパインへのパスが保証されており、各行内ですべての色が接続されているため、同じ色の 2 つのキューブは、1 つのキューブからその行レイヤーに移動し、スパインに上ってターゲット行レイヤーに下に移動し、その行内で水平に移動することで接続できます。 これにより、直接ペアごとの構築を必要とせずに完全な接続が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# This is a constructive solution that builds a vertical scaffold
# Each row gets its own z-level, and we connect within rows + vertical spine

def solve():
    n, m, k = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    ops = []

    # Step 1: build vertical connectors from base layer to row layers
    # We assign row i to z = i+2 (shifted to avoid z=1 base)
    for i in range(n):
        z = i + 2
        for j in range(m):
            # connect (i,j,1) to (i,j,z) via vertical chain
            for zz in range(2, z + 1):
                ops.append((i + 1, j + 1, zz, grid[i][j]))

    # Step 2: connect horizontally within each row layer
    for i in range(n):
        z = i + 2
        for j in range(m - 1):
            # bridge between (i,j,z) and (i,j+1,z)
            ops.append((i + 1, j + 1, z, grid[i][j]))
            ops.append((i + 1, j + 2, z, grid[i][j + 1]))

    # Step 3: build a vertical spine at column 1 for each row layer
    for j in range(n):
        for i in range(n - 1):
            ops.append((i + 1, 1, i + 2, grid[i][0]))

    print(len(ops))
    for x, y, z, c in ops:
        print(x, y, z, c)

if __name__ == "__main__":
    solve()
```最初のブロックは、各グリッド セルの上に垂直列を構築し、各位置が高次元の配線に参加できるようにします。 2 番目のブロックは、各行の専用レイヤー内で隣接する列が確実に接続されるようにします。これにより、散在する色の発生が行レベルのセグメントに変換されます。 3 番目のブロックは、最初の列に沿って垂直チェーンを作成し、行間のユニバーサル コネクタとして機能します。 

微妙な点は、補助立方体を配置するときにセルの元の色を再利用していることです。 これにより、追加されたキューブに接続の不変条件を壊す可能性のある異色が導入されることがなくなります。 

主な実装リスクは、レイヤー間の調整管理です。 行インデックスから高さへのマッピングは一貫性を保つ必要があります。そうでないと、接続で行が誤って混合され、分離性が損なわれます。

 ## 特殊なケース

 主なエッジ ケースは、色が行ごとに 1 回だけ表示されるが、多くの行にわたって表示される場合です。 単純な平面ソリューションでは、各出現を孤立したものとして扱い、多くのペアごとの接続を試行しますが、足場は各行が独立して接続されたセグメントに寄与し、スパインが行をまたぐ直接の水平ブリッジを必要とせずにそれらをマージすることを保証します。 

もう 1 つのエッジケースは、色が蛇のような斜めのパターンを形成する場合です。 面内の直接的な隣接性は随所で崩れていますが、この構造は面的な隣接性にまったく依存していません。 各オカレンスはリフトされ、行レイヤーを介して接続され、対角線の断片化を完全にバイパスします。 

接続はアドホックなローカル決定ではなく、常に同じ垂直バックボーンを介して仲介されるため、構造は安定したままになります。
