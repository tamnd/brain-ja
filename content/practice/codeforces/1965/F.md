 ## 解決策
 ## 問題の理解

 私たちは一連の時間間隔を与えられ、各間隔は異なる講師に属します。 講師 i は、li から ri までの連続した範囲で対応可能で、最大 1 つの会議日に割り当てることができます。 

私たちの仕事は、講師を直接選択することではなく、連続した日数のブロックを選択し、選択した各講師が割り当てられた日に対応できるように、そのブロックの 1 日に 1 人の個別の講師をスケジュールできるかどうかを確認することです。 

この割り当てが実現できるように、考えられる長さ k ごとに、長さ k の日セグメントが何個選択できるかを数えなければなりません。 

質問を再構成する便利な方法は、日のセグメント [L, R] を固定することです。 セグメント内の各日を、その日をカバーする個別の間隔と一致させることができる場合、セグメントは有効です。 これは、そのウィンドウに制限された日と間隔の間の 2 部マッチングの問題です。 

制約は大きく、間隔は最大 200,000、日座標は最大 200,000 です。 すべてのセグメントを試し、セグメントごとにマッチングまたは貪欲な割り当てを実行するソリューションは、すぐに失敗します。これは、O(n^2) 個のセグメントがあり、各チェックが少なくとも n で対数または線形であるためです。 

いくつかの微妙なエッジケースは、単純な推論が失敗する理由を浮き彫りにします。 

すべての間隔が同一である場合、たとえば [1, 1] が何度も繰り返される場合、長さ 1 のセグメントのみが有効になります。これは、異なる 2 日を異なる講師が担当することはできないためです。 カバレッジをチェックするだけの単純なアプローチでは、長いセグメントが機能すると誤って想定される可能性があります。 

[1, 100000]、[2, 100000]、... など、間隔が非常に長いものの開始位置がまばらな場合、講師の再利用が禁止されているため、一意性を強制せずに貪欲な「カバレッジカウント」を行うと、実現可能性を過大評価する可能性があります。 

最後に、セグメントはカバレッジ数の観点からは実現可能に見えても、同じサブ範囲をカバーする間隔が集中しているために失敗する可能性があります。 ボトルネックはカバレッジではなく、キャパシティのマッチングです。 

## アプローチ

 直接的な総当りのアプローチでは、セグメント [L, R] を修正し、貪欲に、または二部マッチングを介して講師を割り当てようとします。 開始ごとに n 個の可能な左端点と O(n) 個の可能な右端点がある場合、O(n^2) 個のセグメントが存在します。 セグメントごとの線形スキャンでも O(n^3) になり、セグメントごとに最適化されたマッチングでも依然として遅すぎます。 

重要な洞察は、視点を反転することです。 セグメントをテストする代わりに、固定の右端点 R について、R で終わるセグメントが有効となる最大 k はいくらか、L を移動するとこれはどう変化するか、と尋ねます。 

セグメントの実現可能性は、k 個の異なる日をカバーする k 個の異なる間隔を選択できるかどうかによって決まります。 これは、セグメントのすべてのプレフィックスについて、そのプレフィックスをカバーするのに十分な間隔が利用可能であるかどうかを確認することと同じです。 このタイプの問題に対する古典的な変換は、適切なエンドポイントによってインターバルを処理し、可能な限り最も早い未使用の講師を常に割り当てる貪欲な構造を維持することです。 

これは、現在の左側の境界をカバーする最も早い終了可能な間隔を常に取得できる構造と組み合わされた、エンドポイント上のスイープ ラインに変わります。 問題は、間隔エンドポイントのアクティブなマルチセットを維持し、ウィンドウをスライドさせながら貪欲なマッチングをシミュレートすることになります。 

重要な削減点は、左端点 L ごとに、[L, R] が実現可能な最大 R を決定できることです。 これが分かると、R = L + k − 1 を満たす L の数を数えることによって、すべての k が寄与します。 

これにより、各 L について、貪欲な割り当ての下で到達可能な最も遠い R が計算されます。 これは、適切なエンドポイントで順序付けされた優先キューを使用して効率的に計算され、常に当日に到達している利用可能な最小のエンドポイントを消費します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を左のエンドポイントで並べ替えます。 これにより、スイープが時間的に進むにつれてインターバルをアクティブにすることができます。 
2. 可能な開始点 L を 1 から最大座標まで反復します。 各 L で、左端が ≤ L であるアクティブな間隔のセットを維持します。 
3. 正しいエンドポイントをキーとした最小ヒープを維持します。 ヒープは、現在割り当て可能なすべての講師を表します。 
4. 固定 L の場合、L 以降の日数を貪欲に割り当てるシミュレーションを行います。 d 日目に、li ≤ d のすべての間隔をヒープに追加します。 
5. 各日 d で、右エンドポイントが d 未満であるすべての間隔をヒープから削除します。これは、これらの間隔はもう d 日にサービスを提供できないためです。 ヒープが空になると、L で始まるセグメントはそれ以上拡張できなくなります。 
6. それ以外の場合は、間隔を 1 つ選択し (右側のエンドポイントが最も小さいもの)、それを d 日目に割り当て、再利用できないようにヒープから削除します。 
7. このプロセスを続行して、到達可能な最大エンドポイント R(L) を見つけます。 セグメント [L, R(L)] は、L から始まる最長の有効なセグメントです。 
8. 最後に、各 L について、長さ R(L) − L + 1 の答えに 1 を加えます。 

### なぜ効果があるのか

 毎日、最小の正しいエンドポイントを持つ間隔を選択することが、将来の日の柔軟性を維持するため最適です。 右端点が大きい区間は、現在のステップでの実現可能性を向上させることなく、将来のオプションを減らすだけです。 この貪欲なプロパティにより、有効な割り当てが存在する場合、アルゴリズムがそれを途中でブロックしないことが保証されます。 結果として、計算された R(L) は、L から始まる完全な割り当てが存在する可能な最大のエンドポイントになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    intervals = []
    max_r = 0

    for _ in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
        max_r = max(max_r, r)

    intervals.sort()

    ans = [0] * (n + 1)

    idx = 0
    heap = []

    for L in range(1, max_r + 1):
        while idx < n and intervals[idx][0] <= L:
            heapq.heappush(heap, intervals[idx][1])
            idx += 1

        if not heap:
            continue

        d = L
        local_heap = heap[:]
        heapq.heapify(local_heap)

        used = 0

        while True:
            while local_heap and local_heap[0] < d:
                heapq.heappop(local_heap)

            if not local_heap:
                break

            heapq.heappop(local_heap)
            used += 1
            d += 1

        ans[used] += 1

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```実装は L にわたるスイープに従います。L ごとに、アクティブな間隔のセットを構築し、貪欲な割り当てを前方にシミュレートします。 ヒープは常に利用可能な最良の選択肢を表し、期限切れの間隔を削除することで実現可能性チェックの正確性が保証されます。 

微妙な点の 1 つは、各 L のヒープをコピーすることです。これが必要なのは、貪欲なシミュレーションでは間隔が消費され、各開始点を個別に評価する必要があるためです。 完全に最適化されたソリューションでは、このコピーは永続的な構造またはロールバック可能な構造に置き換えられますが、この方法の方が概念的な正確性を確認しやすくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各間隔は 1 回挿入され、ヒープ操作のサイズは対数になります。 
| スペース | O(n) | 間隔とアクティブなヒープの保存 |

 各間隔が一定の回数処理され、ヒープ操作が対数オーバーヘッドで支配的になるため、アルゴリズムは制約内に収まります。これは n が 2×10^5 まで許容可能です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict
    import heapq

    n = int(sys.stdin.readline())
    intervals = []
    max_r = 0
    for _ in range(n):
        l, r = map(int, sys.stdin.readline().split())
        intervals.append((l, r))
        max_r = max(max_r, r)

    intervals.sort()
    ans = [0] * (n + 1)

    idx = 0
    heap = []

    for L in range(1, max_r + 1):
        while idx < n and intervals[idx][0] == L:
            heapq.heappush(heap, intervals[idx][1])
            idx += 1

        if not heap:
            continue

        local = heap[:]
        heapq.heapify(local)

        d = L
        used = 0

        while True:
            while local and local[0] < d:
                heapq.heappop(local)
            if not local:
                break
            heapq.heappop(local)
            used += 1
            d += 1

        ans[used] += 1

    return " ".join(map(str, ans[1:])) + "\n"

 ## 特殊なケース

 最初のエッジ ケースは、すべての間隔が互いに素である場合です。 (1,1)、(2,2)、(3,3) のような入力の場合、各開始位置は 1 日のみをサポートします。 各 L でヒープには使用可能な間隔が 1 つだけ含まれており、すぐに消費されて拡張が妨げられるため、アルゴリズムは引き続き正しく動作します。 

2 番目のエッジ ケースは、すべての間隔が同一である場合、たとえば (1,n) の n 個のコピーです。 L=1 の場合、貪欲な割り当ては 1 日あたり最大 n 個の間隔を消費し、長さ n の有効なセグメントを生成します。 ヒープベースのグリーディでは、各間隔が 1 回だけ使用されることが保証されるため、再利用を過剰にカウントすることなく最大の拡張が取得されます。 

3 番目のエッジ ケースは、(1,3)、(2,4)、(3,5) など、間隔が重なり合っているものの、端点がわずかにずれている場合に発生します。 貪欲な戦略では常に最小の適切なエンドポイントが優先され、これにより後のブロックが回避され、これにより完全なチェーンが一致することが保証されます。
