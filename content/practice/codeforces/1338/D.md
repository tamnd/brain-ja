 ## 解決策
 ## 問題の理解

 私たちは木を与えられ、問題はその木に対して実行できる幾何学的な構造を考えるように求めます。 各頂点は、平面上で自己交差しない閉じた曲線になります。 これらの曲線は、非常に厳密な方法で相互作用する必要があります。2 つの曲線は、対応する頂点がツリー内のエッジによって接続されている場合にのみ交差します。 それ以上は、隣接しない頂点に対応する曲線は完全に分離されたままでなければなりません。 

この幾何学的モデルに加えて、包含の概念を定義します。つまり、ある曲線がその囲まれた領域内に厳密に存在し、交差しない場合、ある曲線は別の曲線の内側にあると見なされます。 これを使用して、各曲線が次の曲線を厳密に含むような一連の頂点を探します。 

出力は、ツリーの有効な幾何学的実現を自由に設計できると仮定した場合、そのようなネストされたシーケンスの可能な最大長です。 

重要な問題は、ジオメトリが任意ではないことです。 交差ルールはグローバル構造を強制します。つまり、すべてのエッジは必須の交差ですが、非エッジはいかなる相互作用も禁止します。 これにより描画が高度に制限されるため、ネスト動作を頂点ごとに独立して自由に選択できなくなります。 

n が 100000 までの制約は、すべての解が線形または線形に近いものでなければならないことを意味します。 二次関数またはノードごとの n log n アプローチでも合格しません。 これにより、明示的に埋め込みをシミュレートしようとしたり、ネストの実現可能性に関して頂点のすべてのペアをチェックしようとする構築が即座に除外されます。 

いくつかの特殊なケースで、ここで何が微妙であるかを明らかにします。 1 つの中心が他のすべての中心に接続されている星形のツリーでは、隣接制約に違反せずにリーフを相互にネストすることができないため、2 を超える長いネストはできません。 ただし、単純なパスでは、すべての頂点は完全にネストされたチェーンに配置でき、答えがパスの長さに応じて線形に増加することを示唆しています。 これら 2 つの極端な結果は、答えがツリー内に「線形構造」がどれだけ長く存在するかによって決まることをすでに示唆しています。 

単純な誤解は、ネストがサブツリーの深さに関係すると仮定することです。 これは、最も深い根が最も長​​いチェーンの一部ではないツリーでは失敗します。 もう 1 つの間違った考え方は、最も深い葉を貪欲に選択することです。これにより、分岐点を通過する長い交互のパスを見逃す可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、ツリーの有効な幾何学的埋め込みを構築し、考えられるすべての構成の中から最長のネスト チェーンを検索します。 たとえジオメトリを抽象化したとしても、これは事実上、ツリーの埋め込みに対するグローバルな組み合わせ最適化となり、複雑さが爆発的に増加します。 頂点間の可能な包含関係を列挙しようとする試みは、各分岐によって曲線に複数の相対順序付けの可能性が導入されるため、最悪の場合、すぐに指数関数的になります。 

重要な観察は、幾何学的制約によりほとんどすべての自由が排除されるということです。一貫した交差ルールを維持する唯一の方法は、包含という点でパスのように動作する構造内に頂点を配置することです。 頂点が交差することなく別の頂点の中に配置されると、その隣接する頂点はすべて一貫した領域内に留まらなければならず、これが単一のチェーンに沿って伝播します。 兄弟は分離されたままにしなければならず、両方が互いの領域内に異なる順序で存在することを防ぐため、分岐によって独立したネストは許可されません。 

これにより、有効なネストされたシーケンスがツリー内の単純なパスに強制的に対応します。 逆に、パスに沿った隣接性制約を尊重しながら、次の各頂点を前の頂点の内側に徐々に配置することで、単純なパスをネスト チェーンとして実現できます。 

したがって、問題は、ツリー内の最長の単純なパスを見つけることになります。これは、まさに頂点の数で測定されたツリーの直径です。

 | --- | --- | --- | --- |
 | 埋め込みの総当り構築 | 指数 | 指数 | 遅すぎる |
 | 木の直径の計算 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、観察を具体的な計算に変換します。 

1. 入力エッジからツリーの隣接リストを構築します。 
2. 任意のノード (ノード 1 など) から DFS または BFS を実行し、そこから最も遠いノードを見つけます。 これが機能するのは、ツリーでは直径の 1 つの端点が常に開始ノードから最も遠い点であるためです。 
3. その最も遠いノードから開始して 2 番目の DFS または BFS を実行します。 すべてのノードまでの距離を追跡します。 
4. この 2 回目のトラバースで得られる最大距離は、エッジで測定された直径です。 
5. k 個のエッジを持つパスには k + 1 個の頂点が含まれるため、1 を加算して、このエッジベースの直径を頂点数に変換します。 

2 パスのトラバースが機能する理由は、最初のスイープによって最長パスの一方の端に到達することが保証されるためです。 次に、2 番目のスイープはその端から外側に拡張し、必然的に直径の反対側の終点に到達します。 

### なぜ効果があるのか

 最も長いネスト チェーンは、ツリー内の単純なパスに対応します。 ツリーには、頂点の各ペア間に一意の単純なパスがあるため、ネストの長さを最大化することは、そのようなパス上の頂点の数を最大化することと同じです。 最遠点プロパティにより、最初の端の最大値と矛盾することなくパスが存在できないため、直径の任意の端点から開始する 2 番目の BFS が反対側の端点を確実に発見します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    far = start

    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
                if dist[v] > dist[far]:
                    far = v
    return far, dist[far]

def solve():
    n = int(input())
    adj = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    if n == 1:
        print(1)
        return

    any_node = 1
    far, _ = bfs(any_node, adj)
    far2, dist = bfs(far, adj)

    print(dist[far2] + 1)

if __name__ == "__main__":
    solve()
```最初の BFS は直径の終点を見つけることだけを担当しており、まだ答えは生成されていません。 2 番目の BFS では、実際の直径の長さが測定されます。 決勝戦`+1`BFS 距離はエッジをカウントするのに対し、ネスト シーケンスは頂点をカウントするため、これが必要です。 

実装の微妙な詳細は、BFS 中に「これまでで最も遠いノード」を維持することです。 これにより、距離配列の 2 回目のパスが回避され、余分なオーバーヘッドなしでコードが線形に保たれます。

これにより、最も長いチェーンが中心を通るパス 2 から 5 または 2 から 6 をたどることが確認されます。 

### 例 2

 入力:```

```これはもう行列ですね。 最初の BFS はエンドポイントに到達し、2 番目の BFS は距離 4 のエッジで反対側のエンドポイントに到達し、答え 5 が得られます。これは、純粋なパスが可能な限り最大のネストを実現することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各 BFS はすべてのノードとエッジを 1 回訪問します。 
| スペース | O(n) | 隣接リストと距離配列 |

 ツリーには最大 100,000 個の頂点があるため、線形トラバースが最適です。 2 つの BFS パスは、時間とメモリの制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def bfs(start, adj):
        n = len(adj) - 1
        dist = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0
        far = start
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)
                    if dist[v] > dist[far]:
                        far = v
        return far, dist[far]

    n = int(sys.stdin.readline())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, sys.stdin.readline().split())
        adj[a].append(b)
        adj[b].append(a)

    if n == 1:
        return "1\n"

    far, _ = bfs(1, adj)
    far2, dist = bfs(far, adj)
    return str(dist[far2] + 1)

 ## 特殊なケース

 星型ツリーは、ソリューションがネストの深さの過大評価を回避するかどうかをテストします。 任意の 2 つのリーフは中心を介して接続されており、パスは存在しないため、直径は常に 2 です。 

線形チェーンは、すべての頂点が単一のネスト シーケンスに参加できる上限の動作をテストします。 BFS は、タイ処理によってエンドポイントを失うことなく、距離を正しく伝播する必要があります。 

バランスの取れたバイナリ ツリーにより、実際の最長パスはルートを介して最も深い 2 つのリーフを横切るため、局所的な深さがアルゴリズムに、より深いサブツリーが常に長いチェーンを生成するという誤解を与えないようにすることができます。
