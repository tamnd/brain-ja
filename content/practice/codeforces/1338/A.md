 ## 解決策
 ## 問題の理解

 整数配列が与えられ、時間指定された操作を繰り返し実行できます。 で$x$- 番目の秒では、インデックスのサブセットを選択して同じ値を追加できます。$2^{x-1}$選択したすべての位置に。 1 秒ごとに新しい「2 のべき乗」の増分が与えられ、それを任意の位置に個別に適用できます。 

目的は、要素を交換して配列を並べ替えることではなく、選択した要素を増やして、一定の秒数が経過すると配列が減少しなくなるようにすることです。 各秒ごとに可能な限り最良のインデックスのサブセットを選択できると仮定して、それが可能になるまでに必要な最小秒数が必要です。 

この制約は、高度に最適化されたソリューションが必要であることを意味します。 すべてのテスト ケースの合計の長さは最大です。$10^5$したがって、テスト ケースごとに線形または線形以上のアプローチは避けなければなりません。 各要素は指数関数的に増加する増分の影響を受ける可能性があるため、各ステップで追加される値が 2 倍になり、ステップ数が大きくなる可能性があるため、長期にわたる単純なシミュレーションは不可能です。 

重要な問題は、すべての増分を使用する必要がないことです。 代わりに、最終的な値が減少しないように、時間の経過とともにビット (2 の累乗) を位置全体に分散する方法を決定します。 

配列がすでに非減少である場合、微妙なエッジケースが発生します。 この場合、操作は必要ないため、答えはゼロになります。 

別のエッジ ケースは、局所的な減少の大きさは小さいものの、修正するには複数のビットが必要な場合に発生します。 たとえば、以前の修正を破ることなく桁上げ制約を修正するには上位ビットを利用できる必要があるため、配列の初期の小さな違反でも数秒かかる場合があります。 

最後に、よくある落とし穴は、最初の反転を毎秒貪欲に修正すると仮定することです。 操作は累積的であり、将来のすべての制約に影響を与えるため、これは失敗します。 

## アプローチ

 ブルートフォースの観点は、秒単位でシミュレーションすることです。 毎秒ごとに$x$、インデックスのすべてのサブセットを試します。$2^n$選択肢があり、それぞれの選択肢によって配列が変更されます。 単純化して「最適な選択」のみを考慮したとしても、各ビット レベルが順序制約の修正にどのように寄与するかを追跡する必要があります。 秒数が大きくなり、最悪の場合の差を解決するのに必要なビット数に達する可能性があるため、シミュレーションは実行不可能になります。 

重要な洞察は、視点を逆転させることです。 時間と操作の観点から考えるのではなく、各ポジションを付加価値の 2 値表現の蓄積として解釈します。 各秒は、各インデックスに独立して割り当てることができるビットに寄与します。 

つまり、その後$T$秒、各要素はバイナリ表現が収まる任意の数だけ増やすことができます。$T$ただし、各ビットレベルは位置ごとに独立して割り当てることができるという制限があります。 

さて問題は、最小のものは何かということです。$T$割り当てることができるように$T$-bit は各要素を増分して、結果の配列が減少しないようにしますか?

 配列を左から右に処理し、将来のすべての可能な割り当ての後、現在の要素が少なくとも前の要素と同じ大きさになるように「必要な」ビット レベルの数を維持します。 減少が発生するたびに、その不足を補うために必要なビット数を計算します。 答えは、すべてのプレフィックス制約にわたって必要な最大ビット数になります。 

これは、必要なビット容量の貪欲な伝播につながります。各反転では、差が補償されるまで、より高い 2 のべき乗の層を「消費」する必要があります。

 ## アルゴリズムのチュートリアル

 現在の「有効高さ」とこれまでに必要なビット数を表す変数を維持しながら、配列を左から右に処理します。 

1. 変数を初期化する`cur`最後に処理された要素の現在の調整値として、および`T = 0`これまでに要した秒数 (ビット) を表します。 
2. インデックス 1 から開始して配列を左から右に繰り返します。各ステップで、現在の値と以前の有効値を比較します。 
3. 現在の値がすでに以上である場合`cur`、単に設定するだけです`cur`この値に。 新しい制約は導入されないため、追加のビットは必要ありません。 
4. 現在値が以下の場合`cur`、差を計算します$d = cur - a[i]$。 この差は、将来のビット追加を使用してどの程度「上向きにエンコード」できる必要があるかを表します。 
5. 表現するために必要なビット数を決定する$d$。 毎秒新しい 2 の累乗層が追加されるため、少なくとも$\lceil \log_2(d+1) \rceil$このギャップを補えるまでの時間は数秒です。 
6.アップデート$T$現在の値と必要なビットの最大値になります。 その後、アップデートしてください`cur`私たちが今持ち上げることができるという事実を反映するために$a[i]$利用可能なビット容量を使用して、前の値と一致するまで調整されます。 
7. 配列の最後まで続けます。 最終的な答えは、$T$。 

### なぜ効果があるのか

 核となる不変条件は、インデックスの処理後のものです。$i$、必要なビット層の最小数を決定しました。$a[0..i]$位置ごとに独立したビット割り当てのみを使用して、非減少にすることができます。 ポジションの減少$i$ギャップを埋めるために十分なバイナリの「高さ」が存在することを確認する必要がありますが、すべての操作は値を増加させるだけであるため、将来のポジションではこの要件を軽減することはできません。 したがって、すべてのローカル制約に対する最大ビット要件は十分であり、必要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        T = 0
        cur = a[0]

        for i in range(1, n):
            if a[i] >= cur:
                cur = a[i]
            else:
                diff = cur - a[i]
                need = diff.bit_length()
                T = max(T, need)
                cur = cur  # stays as reference level

        print(T)

if __name__ == "__main__":
    solve()
```ソリューションは実行中の基準値を維持します`cur`、これはこれまでで最も高い必要なベースラインを表します。 新しい要素が小さい場合、ギャップを埋めるために必要なバイナリ層の数を次を使用して計算します。`bit_length`に直接対応します。$\lceil \log_2(d+1) \rceil$。 

変数`T`は、そのような最大の要件を追跡します。これは、どこかで特定のビット深度が必要になると、それ以前のすべての秒もグローバルに使用できる必要があるためです。

 ## 特殊なケース

 順序付けの制約がないため、単一要素の配列は常に 0 を返します。 アルゴリズムはすぐに設定されます`cur`訂正状態に入らないため、ビット要件はトリガーされません。 

次のようなすでにソートされた配列の場合`1 2 3 4`、すべての比較は赤字を引き起こすことなく合格するため、`T`全体を通してゼロのままです。 これにより、補正が必要ない場合にアルゴリズムが過大評価を行わないことが確認されます。 

などの急激な下落の場合、`10 1`、差は 9 で、4 ビットが必要です。$9$バイナリでは$1001$。 アルゴリズムは正しく計算します`diff.bit_length()`4 とアップデート`T`それに応じて。 

混合シーケンスの場合、配列が以前に確立された最大値を下回るたびに、必要なビット深度がローカルで再計算され、グローバル最大値により、最終的な答えが遭遇する最も厳しい制約を反映するようになります。
