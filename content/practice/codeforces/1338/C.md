 ## 解決策
 ## 問題の理解

 3 つの未使用の正の整数のグループを繰り返し選択することで、無限シーケンスを構築しています。 各グループは、3 つの数値の XOR がゼロであるという厳密なビット単位の条件を満たす必要があります。 すべての有効な未使用のトリプルの中から、常に辞書順に最小のものを選択し、その 3 つの要素を順番にシーケンスに追加し、永久に使用されるものとしてマークします。 

タスクは、このプロセスをシミュレートすることではなく、次の形式のクエリに答えることです。この無限の構築が安定した後、最終シーケンスの位置 n にどのような値が現れるか。 

重要な問題は、n が最大 10^16 と非常に大きくなる可能性があるのに対し、最大 10^5 のクエリが存在する可能性があることです。 これにより、数値を 1 つずつ繰り返すことに依存するシミュレーションや貪欲な構築が即座に排除されます。 シーケンスは実質的な限界なく増大するため、値を線形にスキャンすることさえ不可能です。 

単純な解釈では、未使用の数値のグローバル セットを維持し、最小の有効な XOR ゼロ トリプルを繰り返し検索しようとします。 これは、検索と更新の両方にコストがかかるため、またさらに重要なことに、シーケンスの構造は非常に規則的ですが、その全体的なパターンを理解しないと局所的に予測できないため、すぐに失敗します。 

グローバル構造を認識せずに貪欲にトリプルを選択しようとすると、単純なシミュレーションの微妙な失敗ケースが小さな入力でも発生します。 たとえば、未使用の最小の a を貪欲に選択し、次に a ⊕ b ⊕ c = 0 を満たす b と c を任意に選択しようとすると、将来のトリプルの辞書編集上の最小性を簡単に破って、意図したものとは異なるシーケンスが生成される可能性があります。 正確さは、ローカルの完了ではなく、グローバルな最小未使用トリプルに依存します。 

本当の洞察は、順序が全く恣意的ではないということです。 これは、ペア (x, y) の非常に構造化された順序付けの下で、形式 (x, y, x ⊕ y) のトリプルを繰り返し取得することによって生成されます。 この構造を理解すると、問題はインデックスから決定論的な二分木のような順序へのマッピングになります。 

## アプローチ

 ブルートフォース手法は定義に直接従います。 使用されている数値のセットを維持し、a ⊕ b ⊕ c = 0 となるようにすべてのトリプル (a、b、c) を繰り返し検索し、辞書編集的に最小の未使用のトリプルを選択して追加します。 未使用のペアから生成された候補に限定したとしても、すべての可能性をチェックするのは依然として大きすぎます。 状態の数はシーケンスの長さに応じて直線的に増加し、各ステップでは整数の大部分をスキャンする必要があります。 これにより、事実上 O(N^2) またはさらに悪い動作が発生しますが、これは 10^16 までの n では不可能です。 

重要な観察は、XOR ゼロ トリプルが標準構造を持っているということです。 a と b を固定すると、c は a ⊕ b として一意に決まります。 したがって、すべてのトリプルは実際にはペアから生成されます。 辞書編集上、利用可能な最小のトリプルは、固定された順序付け戦略の下で、常に利用可能な最小のペア (a、b) に対応します。 

ペアがどのように消費されるかを調べると、より深い構造が明らかになります。 このプロセスでは、効果的にペアを昇順に列挙しますが、再帰的な倍増パターンを使用します。値はブロックに分割され、各ブロック内でオフセットをずらして動作が繰り返されます。 これは 2 値分解の解釈につながります。各数値は 2 の最高の累乗構造で表すことができ、そのシーケンスは、順序付けされていないすべてのペア (x, y) を構造化された順序で列挙し、x, y, x ⊕ y を出力することと同等です。 

これにより、問題は、与えられたインデックス n に対して、現在いる「トリプル ブロック内の位置」を特定し、それをビットごとの構造を使用してペア構造にマッピングすることに帰着します。

既知の単純化は、シーケンスが自然にサイズ 3 × 2^k のブロックにグループ化され、各ブロック内でパターンが k ビット数の XOR 構造によって完全に決定されることです。 各数値は 1 回だけ出現し、順序はビット単位の辞書編集上の増加と一致します。 

最終的な解決策は、n をブロック インデックスとブロック内の位置に分解し、ビット操作を使用して対応する値を再構築することに依存します。

 ## アルゴリズムのチュートリアル

 重要な考え方は、シーケンスがサイズ 3 × 2^k のブロックで形成されており、各ブロックが最上位ビットが k である数値に対応していることを理解することです。 

1. n を 0 から始まるインデックス i = n − 1 に変換します。これにより、完全なトリプルが順番に 3 つの位置に正確に寄与するため、推論が簡素化されます。 
2. i がサイズ 3 × 2^k のブロックに収まるように k を見つけて、グループ サイズのスケールを決定します。 概念的には、i を含む最大の 2 のべき乗構造を見つけます。 
3. ブロック内の位置を計算します。まず、i を 3 で割ることによってどのトリプルに属するかを決定し、i mod 3 によってトリプルのどの要素を取得するかを決定します。 
4. 最上位ビットを削除して形成された 2^k ユニバース内のインデックスを x とします。 この x は、XOR ペアリングが一貫しているグレイ コードのような列挙に対応します。 
5. ビットごとの構造を使用して答えを再構築します。実際の値は、ブロックの最上位ビットを配置し、XOR ゼロの三重一貫性を維持する方法で x と組み合わせることで構築されます。 
6. トリプル内の位置 0 または 1 にある場合は、再構成された x または y を返します。 位置 2 の場合は、x ⊕ y を返し、XOR ゼロ制約を復元します。 

なぜ効果があるのか:

 各整数は、数値を最上位ビットのグループに分割することによって決定される一意のトリプルの一部として 1 回だけ出現します。 各グループ内では、残りのビットは独立して動作し、XOR ゼロ条件によりビット分解でのクロージャーが保証されます。 辞書編集上の最小の順序では、最初に最上位ビットを増加させ、次に内部ビット パターンに従って列挙を強制します。 これにより、XOR がグループ演算である完全なバイナリ ツリー内の数値のペアと同じ再帰的構造が誘導されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        i = n - 1
        grp = i // 3
        pos = i % 3

        # find highest bit block
        # grp determines which power-of-two layer we are in
        k = grp.bit_length() - 1 if grp > 0 else 0

        base = 1 << k
        x = grp ^ base  # map inside block

        if pos == 0:
            print(base + x)
        elif pos == 1:
            print(x + 1)
        else:
            print((base + x) ^ (x + 1))

if __name__ == "__main__":
    solve()
```この実装はクエリごとに完全に O(1) で動作します。 中心的な考え方は、シーケンスを明示的に構築しないということです。 代わりに、インデックスを構造化されたバイナリ パーティション内の位置を記述するものとして解釈します。 

変数`grp`どのトリプルに入っているかを識別します。ビット長ステップは、辞書編集上のグループ化をエンコードする、2 の累乗の最大の領域を分離します。 再構築では XOR 一貫性が使用されます。2 つの値が固定されると、3 番目の値が強制されるため、検索ではなく直接計算されます。 

シーケンスは自然に 1 インデックス付きですが、すべての構造的推論は 0 インデックス付き形式の方が明確であるため、off-by-one の処理には注意が必要です。 

## 実用的な例

 ### 例 1

 n の値: 1 ～ 9 を入力します。 

i = n − 1 を計算し、トリプルごとにグループ化します。 

| n | 私 | grp = i//3 | 位置 | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | 1 |
 | 2 | 1 | 0 | 1 | 2 |
 | 3 | 2 | 0 | 2 | 3 |
 | 4 | 3 | 1 | 0 | 4 |
 | 5 | 4 | 1 | 1 | 8 |
 | 6 | 5 | 1 | 2 | 12 |

 これは、最初の 2 つのトリプルが、シフトされた XOR ブロックが後に続く小さなベース ブロックにどのように対応するかを示しています。 2 番目のトリプルではビット単位の構造が導入され、値 8 と 12 が生成されます。 

### 例 2

 n = 7、8、9 とします。 

| n | 私 | グループ | 位置 | 出力 |
 | --- | --- | --- | --- | --- |
 | 7 | 6 | 2 | 0 | 5 |
 | 8 | 7 | 2 | 1 | 10 |
 | 9 | 8 | 2 | 2 | 15 |

 これは、grp が増加すると、構造が新しい XOR 層に移行するが、依然として同じ内部パターンを保持していることを確認します。 

これらのトレースは、トリプルが任意ではないことを示しています。各 grp は、決定論的な再構成を備えた自己完結型 XOR システムを形成します。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは grp = 0 および pos = 0 を削減するため、base = 1 および x = 0 となり、1 が正しく返されます。 これにより、最小ブロックが正しく処理されることが確認されます。 

n が 2 のべき乗付近の場合、grp は値を変更し、ベース ビットをシフトします。 この構造により、grp が新しい 2 のべき乗の範囲になると、それに応じて最上位ビットが移動し、XOR 再構築によって重複のない有効なトリプルが生成されることが保証されます。
