 ## 解決策
 ## 問題の理解

 数値から得られる固定の複数の桁セットが与えられます$X$、および 2 番目の数字$Y$同じ長さでも時間の経過とともに変化します。 このタスクは別の数値を構築することを中心に展開します$Z$正確に次の数字を使用します$X$ただし、制約の下でいくつかの順序で配置されています。$Z$少なくとも$Y$通常の辞書編集的な数値の意味で、そのようなすべての有効な順列の中で、可能な限り最小の順列が必要です。 

1 桁に更新されるたびに、$Y$、この最適値の特定の桁を求めるクエリに答えることができなければなりません。$Z$、または有効な再配置が存在しないことを報告します。 

重要な難点は、$Z$は固定されていません。 現在の状態にもよりますが、$Y$、 そして$Y$オンラインで変更します。 したがって、移動下限を使用して制約付き順列問題を繰り返し解いています。 

この制約は、両方の数値が最大で次の値を持つことができることを意味します。$10^5$数字まであります$10^5$操作。 再構築するソリューション$Z$クエリごとに直線的な時間で最初から実行すると失敗します。$10^{10}$最悪の場合の運用。 

主な微妙な点は、2 つの貪欲なプロセス間の相互作用にあります。 1 つは、次の数字の並べ替えです。$X$、もう 1 つは、によって課される辞書編集上の制約です。$Y$。 最小の順列を構築し、それを比較する単純なアプローチ$Y$実現可能性はプレフィックスの決定に依存するため、これでは不十分です。$Y$の構造全体を無効にすることができます$Z$。 

一般的な失敗例は、初期の桁が次の場合に発生します。$Y$わずかに増加します。 単純な解決策では、その位置からローカルに調整するだけかもしれませんが、正しい答えには、完全に異なるプレフィックスが必要になる場合があります。$Z$辞書編集上の順序は接頭辞が優先されるためです。 

たとえば、次の場合$X = 1023$そして$Y = 1200$、最適な$Z$から始まるかもしれない$1$、しかし、もし$Y$に変わります$2200$、後の数字だけが異なる場合でも、最初の数字の選択全体を変更する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。 クエリごとに、次の数字のすべての順列を生成します。$X$、少なくとも次のものをフィルタリングします。$Y$、最小値を選択します。 これは桁数の階乗であり、すぐには不可能です。 

より現実的なベースラインは、各クエリを個別に処理して構築することです。$Z$貪欲に。 私たちは次の数字の頻度表を維持します。$X$、ビルドします$Z$左から右へ。 各位置で、最小値から最大値まで数字を試し、その数字を選択しても制約を満たす有効な置換を完了できるかどうかを確認します。$Z \geq Y$。 

重要な洞察は、制約がプレフィックス比較のように動作するということです。 構築中$Z$のプレフィックスとまだ正確に一致しているかどうかを知る必要があるだけです。$Y$、あるいはすでにそれを超えているかどうか。 それを超えると、残りの構築には制約がなくなり、残りの桁を昇順に配置するだけになります。 

これにより、問題はタイトまたはフリーの 2 値状態による貪欲な構造に帰着します。 

ブルート フォースの失敗は、すべてのクエリに対してこの貪欲な構造を完全に再計算することで発生します。 ただし、貪欲プロセス自体の構造は単純で決定的です。$Y$固定されています。

 | クエリごとに貪欲に再構築 |$O(n \cdot Q)$|$O(n)$| 最悪の場合遅すぎる |

 ## アルゴリズムのチュートリアル

 ### 核となるアイデア

 以下の桁のマルチセットを維持します。$X$。 クエリごとに答えを再構築します$Z$現在の状況に基づいて、左から右への貪欲な戦略を使用します。$Y$。 

### ステップ

 1. の各桁の頻度を数えます。$X$。 これは、並べ替える必要がある利用可能な数字のプールを表します。 
2. タイプ 1 クエリの場合、次の 1 桁を更新します。$Y$。 1 つの位置のみが変更されるため、次の文字列表現を直接変更します。$Y$。 
3. タイプ 2 クエリの場合、次のように構築します。$Z$貪欲なプロセスを使用して最初から。 
4. 最初の位置から開始します。 ブール値フラグを維持する`tight`、これは次の接頭辞を意味します。$Z$は依然として次のプレフィックスとまったく同じです$Y$。 
5. ポジションごとに$i$、配置する数字を決定します。 

タイトな場合は、配置しようとします$Y[i]$残りのマルチセットで利用可能な場合。 それが利用できない場合は、厳密に よりも大きい最小の桁を選択して、厳しい条件を突破する必要があります。$Y[i]$それは利用可能です。 

すでにタイトでない場合は、単に残りの最小の桁を配置します。 
6. に等しい数字を選択する場合$Y[i]$、周波数を減らしてタイトモードを継続します。 
7. より大きい桁を選択する場合$Y[i]$、フリーモードに切り替え、それ以降は常に利用可能な最小の桁を配置します。 
8. いずれかの位置で有効な数字が見つからない場合 (たとえば、制約を満たす数字がない場合、または先頭のゼロの規則に違反する場合)、有効な数字は存在しません。$Z$存在します。 

### なぜ効果があるのか

 正確さは辞書編集上の順序の構造から得られます。 有効な解決策は、それが異なる最初の位置を決定する必要があります。$Y$。 その位置の前に一致する$Y$は、実行可能でありながらプレフィックスを最小限に抑えるため、常に最適です。 At the first deviation, choosing the smallest digit greater than$Y[i]$より大きな値を選択しても最終的な数値が増加するだけであるため、これが最適です。 逸脱後の制約は、$Y$完全に消えるため、残りの桁を並べ替えるのが最適です。 

これにより、不変条件が作成されます。つまり、各ステップで、構築されたプレフィックスは、制約を満たす有効な完全な置換をもたらすことができる最小のプレフィックスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_z(y, cnt):
    cnt = cnt[:]  # local copy
    n = len(y)
    res = []
    tight = True

    for i in range(n):
        if not tight:
            for d in range(10):
                if cnt[d]:
                    cnt[d] -= 1
                    res.append(str(d))
                    break
            continue

        cur = int(y[i])

        # try to match current digit
        if cnt[cur] > 0:
            cnt[cur] -= 1
            res.append(str(cur))
            continue

        # otherwise, break tight: pick smallest greater digit
        placed = False
        for d in range(cur + 1, 10):
            if cnt[d] > 0:
                cnt[d] -= 1
                res.append(str(d))
                tight = False
                placed = True
                break

        if not placed:
            return None

    return "".join(res)

def solve():
    X, Y = input().split()
    q = int(input())

    cnt = [0] * 10
    for ch in X:
        cnt[int(ch)] += 1

    y = list(Y)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            i = int(tmp[1]) - 1
            x = tmp[2]
            y[i] = x

        else:
            i = int(tmp[1]) - 1
            z = build_z(y, cnt)
            if z is None:
                print(-1)
            else:
                print(z[i])

if __name__ == "__main__":
    solve()
```このソリューションは懸念事項を明確に分離します。 周波数配列`cnt`固定リソースを表します$X$。 タイプ 1 の各クエリは変更のみを行います$Y$。 タイプ 2 の各クエリは再構築します。$Z$貪欲スキャンを使用します。 

重要な実装の詳細は、構築中に常に周波数配列のコピーに取り組むことです。$Z$利用可能な桁に関しては破壊的です。 もう 1 つの微妙な点は、一度厳しい条件を突破すると、他のものとの比較を二度と繰り返さないことです。$Y$、単純に数字を昇順に排出します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(Q \cdot n)$| 各タイプ 2 クエリは長さを再構築します。$n$位置ごとに定数の数字チェックを使用する文字列 |
 | スペース |$O(n)$| 桁数と電流の保存$Y$|

 このソリューションは、数値演算が非常に安価で定数が小さいという意図された仮定の下でのみ制約に適合します。 各ステップでは位置ごとに 10 個の可能性のみを処理するため、内部ループが最小限に抑えられます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build_z(y, cnt):
        cnt = cnt[:]
        n = len(y)
        res = []
        tight = True

        for i in range(n):
            if not tight:
                for d in range(10):
                    if cnt[d]:
                        cnt[d] -= 1
                        res.append(str(d))
                        break
                continue

            cur = int(y[i])

            if cnt[cur] > 0:
                cnt[cur] -= 1
                res.append(str(cur))
                continue

            placed = False
            for d in range(cur + 1, 10):
                if cnt[d]:
                    cnt[d] -= 1
                    res.append(str(d))
                    tight = False
                    placed = True
                    break

            if not placed:
                return None

        return "".join(res)

    X, Y = sys.stdin.readline().split()
    q = int(sys.stdin.readline())
    cnt0 = [0] * 10
    for c in X:
        cnt0[int(c)] += 1

    y = list(Y)

    out = []
    for _ in range(q):
        parts = sys.stdin.readline().split()
        if parts[0] == "1":

            else:
                out.append(z[int(parts[1]) - 1])

 ## 特殊なケース

 いつ$Y$で使用可能な最小の桁よりも小さい桁で始まります。$X$、アルゴリズムは位置 1 ですぐに中断し、次のグローバル最小の順列を構築します。$X$。 プレフィックスの同等性は維持できないため、これは安全です。 

いつ$Y$の順列に正確に一致します$X$、アルゴリズムは全体を通してタイト モードに留まり、必要に応じて正確に桁を消費します。 この場合、$Z = Y$。 

以前の貪欲な選択により必要な数字が消えた場合、タイト モードでは正確な一致が必要であるため、アルゴリズムは不可能であることを正確に検出します。$Y$の数字が順番に入力され、数字が欠けているとすぐに完了がブロックされます。
