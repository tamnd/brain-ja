 ## 解決策
 ## 問題の理解

 部分的に満たされた長さのシーケンスが与えられます。$N$。 一部の位置は特定の値に固定されていますが、その他は自由でマークされています。$-1$。 固定値は部分的な順列を形成します: からのすべての数値。$1$に$N$は最大 1 回出現し、固定エントリは、隣接する固定値が 1 つだけ異なるというローカル制限も満たします。 

タスクは、このシーケンスを完全な順列に完成させることです。$1 \ldots N$、同時に 2 つの制約を尊重します。 まず、すべての固定位置は変更されない必要があります。 第 2 に、最終的な置換では、隣接する 2 つの位置に連続する整数が含まれていてはなりません。 すべての有効な補完の中で、辞書編集的に最小のものを返さなければなりません。 

ここでの辞書編集上の最小性とは、シーケンスの残りの部分を有効な完全な解に完成させることを可能にしながら、前の位置をできるだけ小さくしたいことを意味します。 

制約は大きく、$N$最大 200,000 で、順列の探索やグローバルなバックトラッキングを試みるソリューションは即座に除外されます。 各ポジションでの貪欲な選択であっても、残りの数字をすべてスキャンすることを避ける方法で検証する必要があります。 

入力の微妙な点は、固定値によってすでに値同士の隣接性の競合が回避されていますが、新しい数値を挿入すると有効性が簡単に失われる可能性があることです。 「利用可能な最小の数値を常に配置する」などの素朴な貪欲な戦略は失敗します。局所的に最適な配置は、強制的に連続した隣接関係を作成することによって将来の配置をブロックする可能性があるためです。 

いくつかの特殊なケースでその難しさを明らかにします。 

もし$N = 2$両方の位置は自由です。有効な置換は次のとおりです。$[2,1]$以来$[1,2]$隣接ルールに違反しています。 素朴な辞書編集的な塗りつぶしは試みます$[1,2]$最後にのみ制約が失敗します。 

固定値によって既に厳密な構造が強制されている場合は、次のようになります。$a = [3, -1, 4]$、次に配置します$1$または$2$どちらの選択も局所的には有効であるように見えても、中央にあるものは残りの番号を即座にブロックする可能性があります。 

主な課題は、実現可能かどうかは、ローカルな隣接関係だけでなく、将来の可用性によって決まることです。 

## アプローチ

 ブルート フォース ソリューションでは、固定位置と一致するすべての順列を試し、隣接ルールをチェックします。 これは原理的には正しいです。未使用の番号をすべて生成し、空きスロットで並べ替えて、制約を検証します。 問題は規模だ。 空きポジションの数は次のとおりです。$O(N)$、検索を減らしても、次の階乗増加につながります。$O(N!)$、それを超えることは完全に不可能です$N \approx 15$。 

前進するために、制限の構造を利用します。$|p_i - p_{i+1}| \ne 1$。 この制約は、連続する整数間の遷移のみを禁止します。 これは、「危険な」構造が値空間における隣接関係であり、任意のペアの競合ではないことを意味します。 これは、配置を避けながら順列を構築するという観点から考えることを示唆しています。$x$の隣に$x-1$または$x+1$。 

重要な洞察は、辞書編集上の最小性により、常に各位置で可能な限り最小の未使用の値を試行する必要があるが、その値を配置することで将来の不可能性が生じないようにする必要があるということです。 将来の結果を完全にシミュレートしようとする代わりに、局所的な制約を伴う貪欲な構築によって実現可能性を維持します。つまり、以前に配置された値との隣接関係に直ちに違反する選択のみを禁止します。 

唯一の依存関係が前の要素にあるため、これは機能します。 隣接するペアが連続していないことを確認すると、将来の配置は可用性を除いて独立したままになります。 固定位置はハード制約として機能しますが、同様にローカルでのみ相互作用します。 

したがって、事前に埋め込まれたアンカーを使用して、禁止された隣接ルールの下で順列を構築するという問題に問題を集約します。 左から右に処理し、以前に配置された値と競合しない最小の有効な未使用の数値を常に選択し、すでに固定されている位置をスキップします。 

固定エントリは、配列を効果的にセグメントに分割します。 各セグメント内で、固定近傍からの境界条件を尊重しながら、制約付きの貪欲な割り当てを解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N!)$|$O(N)$| 遅すぎる |
 | 最適 |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 当社では、利用可能な数値のデータ構造 (通常はバランスの取れたセット) を維持しています。 また、以前に設定された値も追跡します。 

1. 以下のすべての数値を含むソートされた構造を初期化します。$1$に$N$入力で固定されていないもの。 これは、まだ配置できる残りのすべての候補者を表します。 
2. 位置を左から右に移動します。 
3. 現在の位置が固定されている場合、その値を直接取得し、まだ存在する場合は可用性から削除します。 それを受け入れる前に、以前に設定された値で隣接ルールに違反しているかどうかを確認します。 そうなると工事は不可能になります。 
4. 現在の位置が空いている場合は、以前の値にプラスまたはマイナス 1 を加えたものと等しくない、使用可能な最小の数値を割り当てようとします。 これは辞書編集的に最小の有効な選択肢です。 
5. 利用可能な最小値が隣接制約に違反する場合は、次に小さい値が試行されます。 これは順序付けされた構造を使用して行われるため、無効なオプションを効率的にスキップできます。 
6. 有効な値が見つかったら、それを割り当て、使用可能なセットから削除し、前の値を更新します。 
7. ポジションに有効な値が存在しない場合は、失敗して終了します。 

### なぜ効果があるのか

 核となる不変条件は、すべてのステップで、拡張可能な有効な部分順列を維持することです。 唯一の禁止された関係は連続する位置間であるため、ある位置での失敗は決定的です。将来の別の再配置では、すでに壊れた隣接関係を修復したり、すべての候補が枯渇したときに失われた有効な選択肢を回復したりすることはできません。 最小の有効な数値を貪欲に選択すると、辞書編集上の最小性が保証されます。これより大きな値を選択すると、実行可能性が向上することなく辞書編集的に大きな接頭辞が生成されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    used = [False] * (n + 1)
    available = set()

    for x in a:
        if x != -1:
            used[x] = True

    for i in range(1, n + 1):
        if not used[i]:
            available.add(i)

    prev = None
    res = []

    for i in range(n):
        if a[i] != -1:
            val = a[i]
            if val in available:
                available.remove(val)

            if prev is not None and abs(prev - val) == 1:
                print(-1)
                return

            res.append(val)
            prev = val
        else:
            chosen = None
            for v in sorted(available):
                if prev is None or abs(prev - v) != 1:
                    chosen = v
                    break

            if chosen is None:
                print(-1)
                return

            available.remove(chosen)
            res.append(chosen)
            prev = chosen

    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、まず未使用の番号のプールを構築し、固定割り当てを追跡します。 トラバーサル中に、固定値が即座に適用され、隣接関係違反が早期に検出されます。 

自由な位置の場合、実装は使用可能な最小の番号を順番にスキャンし、以前の隣接制約に違反しない最初の番号を選択します。 セットから削除すると、各値が 1 回だけ使用されるようになります。 

実装の重要な詳細は、制約定義と一致する前の値に対して隣接性のみをチェックすることです。 貪欲スキャンにより、辞書編集上の最小限性が保証されます。

```利用可能な {1, 2} から始めます。

 ## 特殊なケース

 エッジ ケースの 1 つは、固定値がすぐに隣接値をブロックする場合です。 たとえば、配列に次のものが含まれている場合、`..., 5, 6, ...`、これは入力制約によってすでに無効になっているため、アルゴリズムがそれを修復する必要はありません。 ただし、構築中に、値を設定すると後で行き詰まりを余儀なくされる点に到達する可能性があります。 貪欲ルールでは、常に最小の実現可能な値を選択し、重要な大きな値の不必要な消費を防ぐため、これを回避します。 

もう 1 つのケースは、残りの利用可能な番号がすべて前の値と連続している場合です。 たとえば、次の場合`prev = 5`そして残った候補者は`{4, 6}`、どちらも無効です。 アルゴリズムは、その位置で障害を即座に正しく検出し、停止します。これは、残りのセットが使い果たされると、グローバルな再配置では隣接性制約を修正できないことを反映しています。
