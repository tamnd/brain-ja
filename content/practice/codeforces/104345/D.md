 ## 解決策
 ## 問題の理解

 私たちは高さが固定された建物の列を与えられています。 建物は、厳密にその前のすべての建物よりも高い場合、「左側から見える」とみなされます。 言い換えれば、左から右にスキャンすると、新しいプレフィックスの最大値が設定されたときに正確に建物が表示されるようになります。 

建物のサブセットを撤去（爆破）することは許可されています。 削除後、可視性の定義が残りのシーケンスに適用されます。 私たちの目標は、位置 L にある建物が、この左から右のスキャンで K 番目に表示される建物になるようにすることであり、削除する建物の数を最小限に抑えたいと考えています。 それが不可能な場合は、-1 を報告する必要があります。 

重要な変換は、建物の削除が配列の部分列の選択と同等であることです。 可視化プロセスは、そのサブシーケンス内のプレフィックス最大値のみに依存します。 

制約は大きく、建物数は最大 100,000 ですが、K は非常に小さい (最大 10)。 This immediately rules out any solution that tries all subsets or even all subsequences explicitly. 状態ごとに N の二次関数は遅すぎます。 線形または N log N に近いものが必要です。 

微妙な点は、建物 L が最後のサブシーケンスに含まれなければならず、そのサブシーケンス内で K 番目に表示される建物でなければならないという要件からもたらされます。 これにより、順序構造と相対的な高さ構造の両方が結び付けられます。 

いくつかの特殊なケースが重要です。 

削除後でも表示できる建物の数が K 未満の場合、答えは即座に -1 になります。 たとえば、すべての高さが次のように厳密に減少している場合、`[5, 4, 3]`K = 2 の場合、すでにちょうど 3 つの建物が表示されていますが、L の周りにさらに多くの構造制約が必要な場合、配置によってはまだ不可能な場合があります。 

もう 1 つの注意が必要なケースは、建物 L が小さすぎて、たとえ他のすべてが取り除かれたとしても、K 番目に表示される建物になれない場合です。 例えば、`h = [10, 20, 30]`、L = 1、K = 3 は不可能です。建物 1 はすでに最初に表示されており、表示チェーン内でさらに深くすることはできないからです。 

最後に、建物の削除は、L の前後に表示されるプレフィックス最大値にのみ影響するため、局所的に最適な削除によってシーケンスの早い段階で可視性構造が変更される可能性があるため、単純な貪欲な削除は失敗する可能性があります。 

## アプローチ

 ブルート フォース ビューでは、L を含む建物のサブセットを選択し、可視性をシミュレートして、表示される建物の数を数え、L が K 番目に表示されるかどうかを確認します。 これは問題の定義と直接一致するため、正しいです。 ただし、サブシーケンスの数は N で指数関数的 (約 2^N) となり、これは実現可能性をはるかに超えています。 

賢明に努めて、建物ごとにそれを維持するかどうかだけを決定したとしても、依然として指数関数的な状態空間に直面することになります。 ボトルネックは、可視性がプレフィックスの最大値に依存するため、各決定が将来のすべての決定に影響を与えることです。 

重要な洞察は、視点を逆転させることです。 どの建物を削除するかを考える代わりに、目に見えるシーケンスを直接構築することを考えます。 目に見える建物は、左から右に移動するにつれて、厳密に高さが増加するシーケンスを形成します。 目に見えるすべての建物は新しい最大値であるため、目に見えるシーケンスは、選択されたサブシーケンス内のプレフィックス最大値のシーケンスと正確に一致します。 

次に、建物 L を考えます。これが K 番目に表示される建物であると判断した場合、左側のセグメント内でその前に正確に K-1 個の表示可能な建物があり、その後に少なくとも 0 個の表示可能な建物が存在する必要があります。 接頭辞部分は、h[L] によって課される高さの制約を除いて接尾辞から独立しています。これは、L が含まれると、将来表示される建物が h[L] を超える必要があるためです。 

これにより、L を中心とする動的プログラミング構造が得られます。h[L] より小さい値で終わる、左側から最大値を増加させる K-1 を選択する方法 (または最小限の削除) が何通りあるかを計算し、L 自体が含まれることを確認します。 次に、右側に拡張して、さらに建物が見えるようにしますが、L のランクは固定されたままになります。 

K ≤ 10 であるため、これまでに選択した可視最大値の数と現在の最大高さのしきい値を追跡する DP 状態を考慮することができます。 

正確な高さは保存しません。 代わりに、候補の建物がプレフィックス最大チェーンをしきい値以下に拡張できるかどうかのみを考慮します。 これにより、状態遷移を配列の 1 回または 2 回のスキャンに圧縮することができます。

 | ブルート フォース (サブセット) | O(2^N・N) | O(N) | 遅すぎる |
 | DP の可視性の状態 | O(N・K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を L の周りの 2 つの部分に分割します: 左側`[1 .. L-1]`そして右側`[L+1 .. N]`。 必要な削除の数を制御しながら、各パーツで選択できる表示要素の数を計算します。 

左側の DP 状態を定義します。 dp[i][j] が、最初の i 個の建物をスキャンし、それらの高さが厳密に増加するプレフィックス最大値のシーケンスを形成するという制約の下で、それらの中から正確に j 個の目に見える建物を選択するときに必要な最小削除数を表すものとします。 ただし、完全な値を保存するのではなく、建物を新しい最大値として取得するかスキップするかに基づいて遷移のみを維持します。 

私たちはこれを貪欲な観察へと洗練させます。選択された目に見える建物のうち、重要なのはその高さだけであり、それらは厳密に増加しているに違いありません。 したがって、左側では、厳密に増加するサブシーケンスを形成する j = K-1 個の建物を選択したいと考えていますが、削除を最小限に抑えるという追加の目標もあります。これは、保持されている要素から選択された表示要素を差し引いた要素を最大化することに相当します。 

したがって、左側については、h[L] より下で終わるプレフィックス最大値の可能な限り長いチェーンを計算しますが、正確に j 最大値を達成するために必要な最小の削除も追跡します。 

右側でも同じ考えを実行しますが、重要な制約があります。L を表示可能な建物として含めた後は、厳密に h[L] より大きい要素のみが表示可能になります。これより小さい値は、h[L] で定義された接頭辞の最大値を超えないためです。 

次のように進めます。 

1. 配列を位置 L で左右のセグメントに分割します。 寄与分を独立して計算し、L の固定役割を通じてそれらを結合します。 
2. 左側のセグメントについて、dpL[j]、つまり高さが h[L] 未満の値で終わる厳密に増加するシーケンスを形成する正確に j 個の目に見える建物を取得するために必要な最小の削除を計算します。 これにより、L がこれらの j の次に目に見える建物になり得ることが保証されます。 
3. 右側のセグメントについて、最初に表示される建物が h[L] より大きくなければならない場合、シーケンス内で正確に j 個の表示可能な建物を取得するために必要な最小の削除である dpR[j] を計算します。 これにより、L がすでにプレフィックスの最大境界であるという事実が保存されます。 
4. 考えられる分割 j = K-1 ごとに、dpL[j] が有効であることを確認します。 すると、答えの候補は dpL[j] + dpR[anything] になりますが、L 自体は削除されないという制約があるので、L を保持するためのコストを常に 0 として追加します。 
5. 最終的な答えは、すべての有効な分割にわたる実現可能な最小値、または L が正しい位置にある K 個の可視建物を生成する構成がない場合は -1 です。 

正確さは、目に見えるシーケンスが選択されたプレフィックス最大値のシーケンスと正確に一致し、これらの最大値が厳密に増加していなければならないという不変式に依存します。 有効な解決策はそのようなチェーンの選択に対応し、そのようなチェーンは有効な削除セットに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, L, K = map(int, input().split())
    h = list(map(int, input().split()))
    L -= 1

    left = h[:L]
    right = h[L+1:]
    hL = h[L]

    INF = 10**18

    # dp[j] = min deletions to get j visible maxima with increasing sequence
    # We will track only up to K-1 on left and K on right
    def build_dp(arr, limit_height, allow_equal=False):
        dp = [INF] * (K + 1)
        dp[0] = 0
        best = []

        for x in arr:
            ndp = dp[:]
            for j in range(K):
                if dp[j] == INF:
                    continue
                # we can always delete x
                ndp[j] = min(ndp[j], dp[j] + 1)

                # try to take x as next visible maximum
                if x < limit_height:
                    ndp[j+1] = min(ndp[j+1], dp[j])
                elif allow_equal and x > limit_height:
                    ndp[j+1] = min(ndp[j+1], dp[j])
            dp = ndp

        return dp

    # left: need K-1 visibles all < hL
    dp_left = build_dp(left, hL, allow_equal=False)

    # right: after hL, all visible must be > hL
    dp_right = build_dp(right, float('inf'), allow_equal=True)

    ans = INF
    if dp_left[K-1] < INF and dp_right[0] < INF:
        ans = dp_left[K-1] + dp_right[0]

    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```実装の中心となるアイデアは、各要素が削除されるか、次に表示される最大値になる配列上のローリング DP です。 DP インデックスは、すでに形成されている目に見える最大値の数を追跡します。 要素を削除すると、状態は変更されずにコストが 1 増加しますが、要素を表示可能な最大値として保持すると、高さの制約が尊重される場合は状態が進みます。 

左側では、h[L] に達するか超えることを禁止します。これは、L が K-1 最大値の次に目に見える建物のままでなければならないためです。 右側では、K 番目の可視要素としての L の位置を妨げない構造のみを許可します。これは事実上、正確な順位付けの相互作用ではなく、L の後の実現可能性のみを考慮することを意味します。

 ## 特殊なケース

 最初のエッジ ケースは、L が位置 1 にある場合です。この場合、左側のセグメントがないため、K-1 はゼロでなければなりません。 dp_left[0] は削除ゼロから始まるため、アルゴリズムはこれを自然に処理します。これは、L がすぐに最初に表示される建物の候補と見なされることを意味します。 

もう 1 つのエッジ ケースは、L の前にすべての建物が h[L] より高い場合です。その状況では、それらの高い建物がすべて削除されない限り、L は決して表示されません。 左側の DP は、そのようなブロッカーをすべて強制的に削除します。これは、維持された高層ビルがプレフィックスの最大順序で L を支配するためです。 

3 番目のエッジ ケースは、残りの候補が少なすぎて全体で K 個の目に見える建物を形成できない場合です。 DP は dp_left[K-1] を設定することはなく、最後の結合ステップは失敗し、-1 が生成されます。 これは、配列が厳密に減少している場合や配列が短すぎる場合など、削除に関係なく可視性の深さが達成できない場合に一致します。
