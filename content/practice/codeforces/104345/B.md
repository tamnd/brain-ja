 ## 解決策
 ## 問題の理解

 各頂点が個別のノードであり、エッジがそれらを循環せずに接続するツリーが与えられます。 選択した頂点のサブセットについては、そのサブセット内の頂点を「歩くこと」のみを許可します。 許可された頂点のみを使用して 2 つの頂点が相互に到達できる場合、それらはそのサブセット内で接続されていると見なされます。 

固定サブセットの場合、この制限の下で、個別の頂点の順序ペアがいくつ接続されるかをカウントする必要があります。 同様に、サブセットによって誘導されたすべての連結コンポーネントについて、そのコンポーネント内のすべての頂点のペアが答えに寄与します。 

重要な隠された構造は、答えはパス自体に関するものではなく、サブセットによって引き起こされる接続コンポーネントに関するものであるということです。 各クエリは、S の頂点のみを取得し、それらの間にエッジを保持する場合、c(c − 1) のサイズ c のすべての成分の合計はいくらになるかを尋ねます。 

制約は大きいです。 ツリーには最大 250,000 個の頂点を含めることができ、すべてのクエリ セットの合計サイズは 1,000,000 に達する可能性があります。 これにより、ツリー全体にわたるクエリごとのグラフの走査や、クエリごとに DSU を最初から再構築することが直ちに排除されます。 100,000 クエリ全体で単純に実行した場合、クエリあたり O(K log N) であっても境界線に達します。 

単純な間違いは、クエリごとに S に制限された BFS または DFS を試行することです。 これにより、最悪の場合、クエリごとに N に比例してエッジが繰り返し走査され、最大 10^10 の操作が生成されます。 もう 1 つの間違った近道は、中間ノードが含まれているかどうかを確認せずに、S の接続が単に元のツリーの距離または LCA グループに基づいていると仮定することです。 これは失敗します。接続性は、完全なツリー内で端点が近いかどうかではなく、すべての中間頂点が S 内にあるかどうかに完全に依存するためです。 

S に 1 つの内部頂点を除く長いチェーンのすべてのノードが含まれる場合、微妙なエッジ ケースが発生します。 元のツリーではその欠落ノードを介してエンドポイントが隣接していても、S では切断されます。S の「穴」を無視するアプローチでは、そのようなケースが過剰にカウントされます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、S 上で誘導サブグラフを構築し、DFS または BFS を実行してすべての接続されたコンポーネントを見つけます。 各コンポーネントのサイズがわかったら、c(c − 1) を合計します。 S 内の接続性は、誘導されたサブグラフ内のグラフ接続性とまったく同じであるため、これは正しいです。 

ただし、これにはエッジを繰り返し探索する必要があります。 S のノードに付随するエッジのみをトラバースする場合でも、ノードは多くのクエリに出現する可能性があります。 最悪の場合、多くのクエリに中心ノードが含まれるスター ツリーによって隣接リストの繰り返しスキャンが発生し、全体的に二次的な動作が発生します。 

重要な洞察は、完全な走査の再計算を回避し、代わりに、異なるコンポーネントを接続する S 内のエッジの数をカウントすることです。 ツリーでは、誘導されたサブグラフの接続コンポーネントは、端点が両方とも S にないエッジ、または削除によって選択されたノードが分離されるエッジを削除することによって形成されます。 S 内のノードを一貫した順序で処理し、それらを動的に結合すると、DSU を使用してクエリごとにコンポーネントを効率的に再構築できますが、接触するのは S 内のノードのみです。 

より効率的なフレーミングは、クエリごとに S のノードのみで DSU を初期化し、両方のエンドポイントが S にあるエッジのペア (u, v) を接続することです。ツリーには正確に N − 1 のエッジがあり、すべてのクエリの合計 K は制限されているため、ハッシュ セットのメンバーシップをチェックすることでクエリごとにエッジを反復することが可能です。 これにより、完全なトラバースが回避され、ツリーのまばらさが利用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(∑N・Q) | O(N) | 遅すぎる |
 | エッジ フィルタリングを使用したクエリごとの DSU | O(∑ K + ∑ K α(K)) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理しますが、そのクエリ内の頂点のみに触れます。

1. セット S を読み取り、O(1) メンバーシップ チェック用のハッシュ セットに保存します。 これは、誘導されたサブグラフ内でエッジがアクティブであるかどうかを迅速に判断できるようにするために必要です。 
2. S 内のノードのみに対して DSU 構造を初期化します。DSU 配列はクエリごとにコンパクトである必要があるため、S 内の各ノードをローカル インデックスにマップします。 これにより、クエリごとにサイズ N の配列を割り当てる必要がなくなります。 
3. 元のツリーのすべてのエッジ (u、v) について、両方のエンドポイントが S にあるかどうかを確認します。S にある場合は、それらの DSU コンポーネントを結合します。 元のグラフはすでにツリーであるため、余分なエッジは存在しないため、このステップでは、誘導されたサブグラフの接続されたコンポーネントが正確に再構築されます。 
4. すべてのエッジを処理した後、各 DSU コンポーネントのサイズを計算します。 各ルートについて、そのコンポーネント サイズ c を取得します。 
5. そのクエリの答えに c(c − 1) を追加します。 同じ接続コンポーネント内のノードのすべてのペアが有効であるため、これにより、各コンポーネント内のすべての順序付きペアがカウントされます。 
6. 蓄積された回答を出力します。 

重要な設計上の選択は、クエリごとに隣接リストを探索するのではなく、ツリーのすべてのエッジを反復処理することです。 グローバルに N − 1 個のエッジしか存在しないため、これにより、反復的な走査爆発が回避されます。 

### なぜ効果があるのか

 ツリーでは、サブセット S の接続性は、どの元のエッジが S の両方の端点を持つかによって完全に決定されます。 S 内のパスはすべて元のツリーのエッジに従う必要があるため、誘導されたサブグラフで 2 つのノードが接続されている場合、それらは維持されたエッジのチェーンを介して接続されます。 逆に、キープエッジ チェーンはすべて S 内の有効なパスです。したがって、「アクティブ エッジ」上の DSU は、誘導されたサブグラフ内の接続されたコンポーネントと正確に一致し、コンポーネント上の c(c − 1) を合計すると、すべての有効な順序ペアがカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

n = int(input())
edges = [tuple(map(int, input().split())) for _ in range(n - 1)]

q = int(input())

for _ in range(q):
    data = list(map(int, input().split()))
    k = data[0]
    nodes = data[1:]

    idx = {v: i for i, v in enumerate(nodes)}
    dsu = DSU(k)

    for u, v in edges:
        if u in idx and v in idx:
            dsu.union(idx[u], idx[v])

    comp_size = {}
    for i in range(k):
        r = dsu.find(i)
        comp_size[r] = comp_size.get(r, 0) + 1

    ans = 0
    for c in comp_size.values():
        ans += c * (c - 1)

    print(ans)
```DSU はクエリごとに再構築されますが、そのクエリの頂点に対してのみ再構築され、メモリが K によって制限された状態に保たれます。ハッシュ マップ IDx により、エッジをスキャンするときに O(1) メンバーシップ チェックが保証されます。 

コンポーネントをカウントするステップでは、DSU 代表に対する 2 回目のパスを使用してサイズを累積します。 最終的な合計には順序付きペアが使用されるため、c * (c − 1) / 2 ではなく c * (c − 1) になります。 

## 実用的な例

 ### 例 1

 小さなチェーン ツリー 1-2-3-4 を考えて、S = {1, 2, 4} をクエリします。 

| ステップ | アクティブエッジチェック | DSU のマージ | コンポーネント |
 | --- | --- | --- | --- |
 | エッジ (1,2) | 両方ともS | ユニオン(1,2) | {1,2}、{4} |
 | エッジ (2,3) | 3 は S ではありません | なし | {1,2}、{4} |
 | エッジ (3,4) | 3 は S ではありません | なし | {1,2}、{4} |

 コンポーネントのサイズは 2 と 1 なので、答えは 2・1 + 1・0 = 2 となります。 

これにより、中間ノード 3 が欠落すると、2 と 4 の間の接続が切断されることが確認されます。 

### 例 2

 1 を中心とし、エッジが (1,2)、(1,3)、(1,4) のツリー スター。 S = {1,2,3,4} をクエリします。 

| ステップ | アクティブエッジチェック | DSU のマージ | コンポーネント |
 | --- | --- | --- | --- |
 | (1,2) | 両方ともS | 組合 | {1,2} |
 | (1,3) | 両方ともS | 組合 | {1,2,3} |
 | (1,4) | 両方ともS | 組合 | {1,2,3,4} |

 最終的なコンポーネントのサイズは 4 なので、答えは 4·3 = 12 となります。 

これは、ハブ ノードを完全に含めると、構造全体が 1 つのコンポーネントに折りたたまれることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑ K + Q · N α(K)) | 各クエリはエッジを 1 回スキャンし、選択されたノードのみを処理します。 DSU の動作はほぼ一定です。 
| スペース | クエリごとに O(K) | DSU とハッシュ マップは現在のクエリに対してのみ構築されます。 

すべてのクエリにわたる合計 K は 1,000,000 によって制限されるため、クエリ入力のスキャンは全体的に線形です。 各エッジ チェックはクエリごとに O(1) であり、制約の下で許容可能なパフォーマンスが得られます。

 ## 特殊なケース

 重大なエッジ ケースは、元のツリーに接続が存在するが、単一の中間頂点を削除することによって接続が破壊される場合です。 たとえば、パス 1-2-3-4 では、S = {1,4} の場合、2 と 3 が欠落しているため有効なパスは存在せず、答えは 0 でなければなりません。アルゴリズムはエッジを正しく処理し、アクティブなエッジを検出せず、2 つの孤立したノードを残します。 

もう 1 つのエッジ ケースは、S が頂点セット全体に等しい場合です。 すべてのエッジがアクティブになり、DSU はすべてをサイズ N の 1 つのコンポーネントにマージし、結果は N(N − 1) になります。 このアルゴリズムは N − 1 個の結合を実行し、完全なツリー構造と正確に一致します。 

3 番目のケースは、葉だけが選択されている星です。 S では両方の端点を持つエッジはないため、すべてのノードが孤立し、答えはゼロになります。 DSU はシングルトン状態のままで、コンポーネントの合計は正しくゼロを生成します。
