 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times M$各セルが部屋を表すグリッド。 各部屋には必要な数の窓があります$w_{i,j}$、各窓はその部屋の 4 つの側面のいずれかに配置されます。 隣接する 2 つの部屋の間の側面には、部屋ごとに最大 1 つの窓を配置できるため、共有の壁を隔てて両側に 1 つずつ、窓が 0、1、または 2 つ存在する可能性があります。 

両方の部屋の共有の壁に窓を設置した場合、それら 2 つの部屋の生徒がお互いを見ることになり、これにより 2 つの部屋の生徒の数の積に等しい不快感が生じます。 不快感の合計は、共有端に相互に窓を配置するすべての隣接する部屋のペアの合計です。 

タスクは、各部屋が必要な数の窓を正確に使用し、全体的な不快感が最小限に抑えられるように、部屋の側面に窓を割り当てることです。 

グリッド構造は、相互作用が水平および垂直の隣接関係に沿ってのみ発生することを意味します。 各部屋には最大 4 つの隣接部屋があるため、各部屋には$w_{i,j}$は小さいですが、部屋の数は最大 2500 になる可能性があるため、すでに指数関数的またはサブセット列挙のアプローチから遠ざけられています。 

直接的な強引な解釈は、各部屋の窓を隣接する端に割り当てるあらゆる方法を試すことです。 最大 4 度、最大 4 つの窓を持つシングル ルームの場合、最大で 4 つの窓があります。$2^4 = 16$セルごとの選択肢が増え、これはすでに$16^{2500}$、これは実行可能な計算をはるかに超えています。 

貪欲にウィンドウをローカルに割り当てようとすると、より微妙な障害モードが発生します。 たとえば、常に最小の隣接母集団に向かってウィンドウを配置することは合理的であるように見えますが、決定が結合されているため失敗します。一方のエッジがコストがかかるのは、両方のエンドポイントがそれを選択した場合のみです。そのため、ローカルで安全な選択は、次数の制約により他の場所でコストのかかる一致を強制する可能性があります。 

## アプローチ

 主な問題は、各ウィンドウが独立していないことです。 ウィンドウは、エッジの両方のエンドポイントがそれを選択した場合にのみ「危険」になります。 したがって、すべてのエッジは 2 つのエンドポイント間の連携を必要とする潜在的な相互作用のように動作し、各頂点にはウィンドウ要件に等しい固定数の「スタブ」があります。 

これにより、問題は当然、隣接するセル間のペアリング スタブに変換されます。 それぞれの細胞$v$もっている$w_v$同一のユニットを隣接ユニットに割り当てる必要があります。 2 つの隣接するセル間の各エッジ$u$そして$v$このようなペアリングは最大でも 1 つしか保持できず、使用するとコストが発生します。$p_u \cdot p_v$。 

したがって、すべての頂点が次のようにエッジを選択しています。$v$まさに偶然です$w_v$選択されたエッジのそれぞれが固定コストに寄与します。 これは、グリッド グラフ上の最小コストの正確次数 b マッチング問題です。 

グリッドは市松模様のカラーリングの下で​​ 2 部構成になっています。 この構造により、問題を流れの定式化に変換できます。 ウィンドウ要件ごとに 1 ユニットのフローを送信し、各頂点がその正確な次数を満たすように強制し、不快感を表すコストを使用してこれらのユニットをエッジを越えてルーティングします。 

各黒セルが送信するフローネットワークを構築します$w_v$単位、各白セルが受け取ります$w_v$各隣接エッジでは、最大 1 つのユニットがコストをかけて通過できます。$p_u p_v$。 次に、最小コストの最大フローの計算により、エッジ容量を考慮しながらすべての要求を満たす最も安価な方法が見つかります。 

ブルート フォースは、セルごとの割り当てを直接エンコードするため機能しますが、エッジ間の一貫性が決定をグローバルに結合するため、失敗します。 流れの定式化は、実現可能性の制約を維持しながら、この結合を正確に捉えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的$NM$|$O(NM)$| 遅すぎる |
 | 最小コスト フロー (2 部マッチング) |$O(F \cdot E \log V)$|$O(E)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、セルに色を付けてグリッドを 2 部グラフに変換します。$(i,j)$のパリティに基づいて$i+j$。 これにより、すべてのエッジが反対の色に接続されます。 

次に、正確なウィンドウの使用を強制し、隣接するペアにコストを割り当てるフロー ネットワークを構築します。 

### アルゴリズムのチュートリアル

 1. 座標のパリティに基づいて、すべてのセルを 2 つのグループに分割します。 これにより、すべての隣接エッジがフロー グラフの 1 つの左側と 1 つの右側を接続することが保証されます。 
2. ソースノードを作成し、それを容量のあるすべての黒いセルに接続します。$w_{i,j}$これは、必要な各ウィンドウがそのセルから発生しているという事実を表します。 
3. シンク ノードを作成し、すべての白いセルを容量のあるシンクに接続します。$w_{i,j}$これにより、白いセルもウィンドウの正確な数を満たさなければなりません。 
4. 隣接するセルのペアごとに$u$そして$v$、容量 1 とコストで黒から白へのエッジ (パリティに応じて) を追加します。$p_u \cdot p_v$。 両側から1つのウィンドウを組み合わせることで、製品と同等の違和感を生み出すモデルです。 
5. 正確に送信する最小コストのフローを実行する$\sum w_{i,j}$ソースからシンクまでのユニット。 
6. 結果として生じるコストは、不快感の合計を可能な限り最小限に抑えます。 

これが機能する理由は、フローの各単位が 1 つのウィンドウ割り当てに対応し、フローがグリッド エッジを使用するたびに、両方のエンドポイントが 1 つのウィンドウをその共有側にコミットすることを意味するためです。 コストは、双方が参加し、不快感の定義に正確に一致する場合にのみ発生します。 

### なぜ効果があるのか

 すべての有効な窓の配置が実現可能なフローに対応し、各部屋が正確に寄与します。$w_{i,j}$各隣接関係は最大 1 回使用され、「各サイドに最大 1 つのウィンドウ」という制約に一致します。 逆に、フロー保存により各セルが必要な数の入射エッジを正確に使用することが保証されるため、すべての実行可能なフローは一貫してウィンドウを割り当てます。 コスト構造では、すべての相互ウィンドウ ペアが目的に 1 回だけ貢献することが保証されるため、フロー コストを最小限に抑えることは、全体的な不快感を最小限に抑えることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque
import heapq

class Edge:
    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, cap, cost, len(self.g[to]))
        rev = Edge(fr, 0, -cost, len(self.g[fr]))
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0]*n
        prevv = [0]*n
        preve = [0]*n

        INF = 10**18
        dist = [0]*n

        while maxf > 0:
            dist = [INF]*n
            dist[s] = 0
            pq = [(0, s)]

            while pq:
                d, v = heapq.heappop(pq)
                if dist[v] < d:
                    continue
                for i, e in enumerate(self.g[v]):
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost + h[v] - h[e.to]:
                        dist[e.to] = dist[v] + e.cost + h[v] - h[e.to]
                        prevv[e.to] = v
                        preve[e.to] = i
                        heapq.heappush(pq, (dist[e.to], e.to))

            if dist[t] == INF:
                break

            for v in range(n):
                if dist[v] < INF:
                    h[v] += dist[v]

            d = maxf
            v = t
            while v != s:
                d = min(d, self.g[prevv[v]][preve[v]].cap)
                v = prevv[v]

            maxf -= d
            res += d * h[t]

            v = t
            while v != s:
                e = self.g[prevv[v]][preve[v]]
                e.cap -= d
                self.g[v][e.rev].cap += d
                v = prevv[v]

        return res

def solve():
    N, M = map(int, input().split())
    p = [list(map(int, input().split())) for _ in range(N)]
    w = [list(map(int, input().split())) for _ in range(N)]

    def id(i, j):
        return i * M + j

    S = N * M
    T = N * M + 1
    mcmf = MinCostMaxFlow(N * M + 2)

    total = 0

    for i in range(N):
        for j in range(M):
            total += w[i][j]
            v = id(i, j)
            if (i + j) % 2 == 0:
                mcmf.add_edge(S, v, w[i][j], 0)
            else:
                mcmf.add_edge(v, T, w[i][j], 0)

    for i in range(N):
        for j in range(M):
            if (i + j) % 2 == 0:
                v = id(i, j)
                for di, dj in [(1,0), (-1,0), (0,1), (0,-1)]:
                    ni, nj = i + di, j + dj
                    if 0 <= ni < N and 0 <= nj < M:
                        u = id(ni, nj)
                        cost = p[i][j] * p[ni][nj]
                        mcmf.add_edge(v, u, 1, cost)

    print(mcmf.flow(S, T, total))

if __name__ == "__main__":
    solve()
```この実装では、各セルをノードとしてエンコードし、パリティを使用して、2 分割の一方の側からすべての隣接エッジを送信します。 ソースとシンクのエッジは正確なウィンドウ数を強制しますが、隣接するエッジはユニット容量を保持するため、各共有壁は最大 1 回しか使用できません。 

min-cost フローは、必要なウィンドウ ユニットがすべて送信されるまで実行されます。 返されるコストはポテンシャルから累積され、アルゴリズム中にマイナスのコストが削減されたにもかかわらず、最短経路計算の正確性が保証されます。 

## 実用的な例

 ### サンプル 1

 私たちは小さなことを考慮します$4 \times 3$各セルに人口とウィンドウの両方の要件があるグリッド。 フローは、最初に必要なすべてのウィンドウ ユニットをソースから黒のセルにプッシュし、次に隣接エッジを経由してルーティングします。 

| ステップ | アクション | 送信されたフロー | 累計コスト |
 | --- | --- | --- | --- |
 | 1 | ソースからの供給を割り当てる | 合計 38 ユニット | 0 |
 | 2 | ルートは安価なエッジ全体で最初に一致します。 部分的 | ゆっくりと増加します |
 | 3 | 必要に応じて高コストのエッジを使用する | 残りの流量 | 最終にジャンプします |

 このアルゴリズムでは低コストのペアリングが優先されますが、次数の制約により一部の高価な接続が強制されます。 最終コスト１７８は、すべてのウィンドウ要件を満たすための最小限の方法に対応する。 

この例は、次数制約を満たすために人口の多い隣接関係を使用する必要があるため、ローカル貪欲性が失敗することを示しています。 

### サンプル 2

 2 番目のサンプルでは、多くのセルに 0 または 1 つのウィンドウ要件があり、その構造により相互のウィンドウ配置を完全に回避できます。 

| ステップ | アクション | 送信されたフロー | 累計コスト |
 | --- | --- | --- | --- |
 | 1 | ソースは必要な単位を割り当てます | 小さな流れ | 0 |
 | 2 | すべてのフローはペアリングの競合なしでルーティングされました。 いっぱい | 0 |

 フローはコストのかかるエッジをアクティブにすることなくすべての要求を満たすことができるため、最終的な答えはゼロになります。 

これは、隣接関係の競合なしにすべての制約を満たすことができる時期をモデルが正しく識別していることを示しています。

 ## 特殊なケース

 例外的なケースは、すべての場合に発生します。$w_{i,j} = 0$。 この状況では、フロー ネットワークには必要なフローがないため、アルゴリズムは隣接エッジを横断せずにすぐにゼロを返します。 

単一のセルが次のような場合には、別のエッジ ケースが発生します。$w_{i,j} = 4$そして隣接するものはすべてゼロになります。 フローはこれらのユニットのルーティングを試行する必要がありますが、隣接するキャパシティが存在しないため、システムは制約が矛盾している場合にのみ実行不可能性を正しく検出します。 有効な入力では、両方の 2 つのパーティションの要求の合計が一致し、実現可能性が保証されます。 

3 番目のケースは、人口の多いセルが人口の少ないセルに囲まれている場合です。 このアルゴリズムにより、たとえコストが高くても、必要なすべてのペアリングが確実に作成されます。これは、正確な次数制約によってフローが利用可能なエッジを強制的に通過するためです。
