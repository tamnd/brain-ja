 ## 解決策
 ## 問題の理解

 入力は重み付きツリーを記述します。 各ノードはインターチェンジを表し、各エッジは走行距離のある道路を表します。 グラフは接続されており、任意の 2 つのノード間には単純なパスが 1 つだけ存在するため、インターチェンジ間のすべての移動は一意に決定されます。 

正確に選択することができます$k$ノードを検索し、ガソリン スタンドとしてマークします。 ドライバーはどこからでも出発し、最短経路に沿って移動し、選択した駅を通過するときにのみ給油することができます。 要件はグローバルです。ツリー内のすべての可能なパスについて、そのパスに沿って遭遇する一連のステーションを確認する場合、パス上の連続するステーション間の距離は、決して一定の値を超えてはなりません。$d$。 同じ制限がパスの始点と終点にも適用されます。つまり、そのパス上の終点から最も近い駅までの距離も考慮されます。 

タスクは、$k$すべてのパスにわたるこの最大の「給油なしのギャップ」が最小化されるようにステーションを最適に配置し、可能な限り最小値を出力します。$d$。 

制約は、私たちが取り組んでいることを意味します$2 \cdot 10^5$最大のノードと大きなエッジの重み$10^9$。 すべてのペアの距離を再計算したり、パスを明示的に評価したりするソリューションは、非常に遅すぎます。 平$O(n^2)$その行動は不可能であり、さらには$O(n \log n)$線形ツリー処理を中心に慎重に構造化する必要があります。 

いくつかの特殊なケースについては、覚えておく価値があります。 いつ$k = 0$、駅がないので、有効なものはどれでも$d$木の直径全体をカバーする必要があります。 そうしないと、一部のパスに無制限のギャップが生じてしまいます。 いつ$k = n$、すべてのノードはステーションであるため、$d = 0$非駅区間間の移動が存在しないためです。 もう 1 つの微妙なケースは、ツリーが直線の場合です。これは、ステーションの最適な配置は、重み付けされたパスをセグメントに分割することに帰着するためです。 

## アプローチ

 直接的な試みとしては、あらゆる選択方法を試してみることです。$k$次に、構成ごとに、すべてのパスに沿った最悪のギャップを計算します。 指数関数的な選択肢の数を無視しても、単一の構成を検証するには、ノードのすべてのペアとそのパスについて推論する必要があり、このアプローチは次のようなものになります。$O(n^2)$あるいはさらに悪いことに。 これは所定の規模ではまったく実現不可能です。 

重要な構造的変化は、経路について明示的に考えるのをやめ、代わりに駅がツリー メトリック内の距離をどのように制限するかを考えることです。 便利な緩和策は、すべてのノードが距離内にあるかどうかを観察することです。$r$ある駅の場合、2 つのノード間の経路に沿って、それ以上の距離を移動することはできません。$2r$駅に遭遇することなく。 これは、道に沿って歩いているときに、あるステーションの「カバー ボール」から出るたびに別のステーションのカバー エリアに入らなければならず、2 つのカバー エリア間を移動するときに最悪のギャップが発生するという事実から来ています。 

これにより、問題は古典的なツリー問題に縮小されます。$k$すべてのノードが距離内にあるように中心を配置します$r$ある中心を最小化し、$r$。 候補半径をテストできるようになったら$r$、二分探索ができます。 

修正の実現可能性チェック$r$ここでツリー構造が重要になります。 ツリーを任意にルート化すると、それをボトムアップで処理し、中心を配置する場所を貪欲に決定できます。 各ノードについて、中心にぶつからずにどこまで下に移動できるかを追跡します。 サブツリーがより大きな距離を「押し出そう」とすると、$r$上向きに進むと、余分な部分をカットするために戦略的なポイントにセンターを配置する必要があります。 この貪欲な配置は、センターを遅らせても必要なセンターの数が減ることはなく、可能な限り低い位置に配置すると常にカバレッジが最大化されるため、最適です。 

したがって、完全な解は次の二分探索になります。$r$、各チェックは線形時間で行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n^2) | 遅すぎる |
 | 二分探索 + ツリー貪欲 |$O(n \log W)$| O(n) | 承認済み |

 ここ$W$ツリー内で可能な最大距離を指します。 

## アルゴリズムのチュートリアル

 元の問題を半径決定問題に変換し、実行可能な最小半径を検索します。 

1. 候補半径を二分探索します$r$、任意のノードからその最寄りのステーションまでの最大許容距離として解釈されます。 元の問題に対する最終的な答えは次のようになります。$d = 2r$。 
2. 固定の場合$r$、すべてのノードが距離内にあることを確認するために必要なステーションの数を確認します。$r$どこかの駅の。 
3. 任意のノードでツリーをルート化し、深さ優先の走査を実行します。 
4. 各ノードについて、そのノードからそのサブツリーに下降して、最も近い既に配置されているステーションまでの最大距離を計算します。 リーフ ノードは距離 0 から始まります。 
5. 子を結合するとき、そのような最大の距離を上向きに伝播します。 子供がそれを超える価値を提供した場合$r$、その子のサブツリー境界にステーションを配置することを強制され、その領域からの距離の寄与がリセットされます。 
6. ステーションを配置するたびに、カウンターが増加します。 
7. ツリー全体を処理した後、使用されたステーションの数を比較します。$k$。 せいぜい使用した場合$k$、半径$r$実現可能です。 それ以外の場合はそうではありません。 

二分探索は範囲を狭め続けています$r$実行可能な最小値が見つかるまで。 

### なぜ効果があるのか

 貪欲な DFS は、ノードから上向きのパスがそれを超えてカバーされていない距離を蓄積できないように強制します。$r$ステーションの配置を強制する必要はありません。 ステーションの配置を延期する代替配置戦略は、一部のサブツリーでカバーされない距離を増加させるだけであり、必要なステーションの総数を減らすことはできません。 これにより不変条件が作成されます。サブツリーの処理後、戻り値は、サブツリー内の最適な配置を想定した、サブツリーの外側のステーションまでのカバーされていない最小距離になります。 この不変条件により、サブツリーをマージする際の正確性が保証され、生成されるステーション数がその半径に対して最小であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
adj = [[] for _ in range(n)]
edges = []

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append((v, w))
    adj[v].append((u, w))

def feasible(r):
    # returns whether we can cover tree with <= k centers
    cnt = 0

    def dfs(u, p):
        nonlocal cnt
        max_down = 0

        for v, w in adj[u]:
            if v == p:
                continue
            d = dfs(v, u) + w

            if d > r:
                cnt += 1
            else:
                max_down = max(max_down, d)

        return max_down

    # final root check: if root still has uncovered branch, place station
    if dfs(0, -1) > 0:
        cnt += 1

    return cnt <= k

lo, hi = 0, 0
for u in range(n):
    for v, w in adj[u]:
        hi += w
hi //= 2  # safe upper bound heuristic (tree diameter upper bound)

# more robust bound: just expand hi until feasible if needed
def check(r):
    return feasible(r)

while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid
    else:
        lo = mid + 1

print(lo * 2)
```実装の中核は実現可能性のチェックです。 DFS は各ノードからカバーされていない最長の下向きパスを返します。これが候補半径を超えると、暗黙的にステーションがその点に配置され、分岐が切断されます。 カウンタは、そのようなカットが何回必要であるかを追跡します。 

二分探索が実行されます$r$各ステーション間のギャップは 2 つの半径スパンに分解できるため、最終的な答えは 2 倍になります。 

微妙な点は、DFS がステーションの場所を明示的に「選択」しようとしないように設計されていることです。 制約に違反した場合にのみ反応するため、最小限性が保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, w))
        adj[v].append((u, w))

    def solve():
        sys.setrecursionlimit(10**7)

        def feasible(r):
            cnt = 0

            def dfs(u, p):
                nonlocal cnt
                best = 0
                for v, w in adj[u]:
                    if v == p:
                        continue
                    d = dfs(v, u) + w
                    if d > r:
                        cnt += 1
                    else:
                        best = max(best, d)
                return best

            if dfs(0, -1) > 0:
                cnt += 1
            return cnt <= k

        lo, hi = 0, 10**9
        while lo < hi:
            mid = (lo + hi) // 2
            if feasible(mid):
                hi = mid
            else:
                lo = mid + 1
        return str(lo * 2)

    return solve()
