 ## 解決策
 ## 問題の理解

 いくつかの独立したクエリが与えられます。 各クエリには 2 つの整数が含まれており、これら 2 つの数値が双子素数のペアを形成するかどうかを判断する必要があります。 ここでの双子素数の概念は非常に特殊です。2 つの数値は、両方とも素数であり、その差がちょうど 2 である場合にのみ適格となります。 

したがって、各ペアのタスクは、素数を超えた複雑な要素を因数分解したり計算したりするのではなく、2 つの値間の単純な関係をチェックするだけです。 出力は、テスト ケースごとの単純な二分決定です。両方の数値が素数で、正確に 2 だけ異なる場合は肯定的な応答を出力し、それ以外の場合は否定的な応答を出力します。 

制約は十分に小さいため、数値ごとに直接素数チェックを行うことができます。 各値は最大 1,000,000 で、テスト ケースは最大 10 個です。 これにより、クエリごとの重い前処理などはすぐに排除されますが、簡単な素数テストが快適に実行できます。$O(\sqrt{n})$または事前に計算されたふるい$O(N \log \log N)$。 素数チェックの合計数が少ないため、クエリごとの遅いアプローチでも容易に制限内に収まります。 

微妙なエッジ ケースのみが、条件をほぼ満たす入力から発生します。 数値のペアには、2 だけ異なっていても (12, 14) のような合成数が含まれている場合があります。または、実際には有効な (11, 13) や同様に有効な (5, 7) のように、両方の数値が個別に素数であっても 2 だけ異なっていない場合もあります。 もう 1 つのエッジ ケースは、一方の数値が素数で、もう一方の数値が素数ではない場合です。たとえば、(3, 5) は有効ですが、(2, 4) は、差が正しいにもかかわらず 4 が素数ではないため失敗します。 単純な実装では違いをチェックするだけで素数性を完全に忘れてしまう可能性があるため、これらのケースは重要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 テストケースごとに、両方の数値が素数であるかどうかを個別にチェックします。 最も単純な素数チェックでは、2 から平方根までのすべての整数で数値を除算します。 どちらの数値にも約数がない場合、その差がちょうど 2 である場合にのみペアを受け入れます。 

素数性が直接定義されており、構造的なトリックが必要ないため、これは正しく機能します。 非効率性は最悪のケースを考慮したときに現れます。100 万までの数の素数チェックには約 1,000 回の分割が必要であるため、1 つのテスト ケースにはおよそ 2,000 回のチェックがかかります。 10 のテスト ケースでは、これはわずか約 20,000 の操作にすぎず、これはすでに些細なことであるため、制約の下ではこの強引なアプローチでも許容されます。 

それでも、ふるいを使用して 100 万までのすべての素数を事前に計算することで、推論をさらに簡素化できます。 配列が構築されると、各クエリは定数時間になります (2 つの検索と 1 つの減算チェック)。 ふるいは作業をクエリ時間から前処理時間にシフトしますが、この制約サイズでは無視できます。 

重要な観察は、問題は純粋に素数のセットのメンバーシップに関するものであり、そのセットはすべてのクエリに対して固定されているということです。 これにより、単純さとクエリの繰り返しの点で、前処理が厳密に優れたものになります。

 ## アルゴリズムのチュートリアル

 ふるいを使用して、100 万までのすべての素数にマークを付けます。 

1. ブール配列を構築する`is_prime`サイズは 1,000,001 で、最初は 0 と 1 を除くすべての数値が素数であると仮定します。これにより、既知の複合値のみを削除するベースラインが確立されます。 
2. 2から順にふるいにかけます。 まだ素数としてマークされている各数値について、その倍数をすべて非素数としてマークします。 このステップにより、すべての合成数が最小の素因数ごとに 1 回だけ削除されるようになります。 
3. 前処理後、各クエリ ペア (a、b) を読み取ります。 
4. 各ペアについて、まず次のことを確認します。`b - a == 2`。 双子素数は正確に 2 つ離れている必要があるため、これが必要です。 
5. 差分条件が失敗した場合、素数性テストは必要ないため、すぐに N を出力します。 
6. 差異条件が成立する場合は、両方が存在するかどうかを確認します。`a`そして`b`ふるい表ではプライムとしてマークされます。 
7. 両方が素数の場合のみ Y を出力し、それ以外の場合は N を出力します。 

### なぜ効果があるのか

 ふるいは、制限値までのすべての整数の正確な分類を保証します。 双子素数は純粋に 2 つの独立した素数条件と固定差分制約によって定義されるため、事前に計算された素数セットのメンバーシップをチェックすることは、完全な素数テストを実行することと同等です。 このアルゴリズムは部分的チェックやヒューリスティック チェックに決して依存しないため、受け入れられたすべてのペアは両方の定義プロパティを正確に満たし、拒否されたすべてのペアはそれらの少なくとも 1 つに違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

# Sieve of Eratosthenes
is_prime = [True] * (MAXN + 1)
is_prime[0] = is_prime[1] = False

p = 2
while p * p <= MAXN:
    if is_prime[p]:
        step = p
        start = p * p
        for x in range(start, MAXN + 1, step):
            is_prime[x] = False
    p += 1

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    if b - a == 2 and is_prime[a] and is_prime[b]:
        print("Y")
    else:
        print("N")
```ふるいは、クエリを処理する前に一度構築されます。 これにより、以降のすべてのチェックが単純な配列検索になることが保証されます。 条件`b - a == 2`明らかな障害が発生した場合に不必要なプライム テーブル アクセスを回避するために、最初にチェックされますが、これは小さな制約を考慮するとほとんどスタイル上のものです。 

中心的な考え方は、素数情報が完全にキャッシュされるため、各クエリが一定時間の検証に削減されるということです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、差分条件は満たされるが、素数性が満たされない場合です。 たとえば、入力 (12, 14) はギャップ チェックに合格しましたが、両方の数値が合成されています。 ふるいは両方を false としてマークするため、アルゴリズムは正しく N を出力します。 

もう 1 つのケースは、両方の数値が素数であるが、ギャップが正確に 2 ではない場合です。たとえば、(11, 13) は有効ですが、(11, 17) は両方とも素数であるにもかかわらず拒否されます。 アルゴリズムは最初に違いをチェックし、不一致のギャップを即座に拒否して、不必要な検索作業を防ぎます。 

最後のケースは最小の素数です。 (2, 3) の場合、差は 1 であるため、両方が素数であっても拒否されます。 (3, 5) の場合、両方の条件が当てはまり、アルゴリズムはそれを双子素数ペアとして正しく識別します。
