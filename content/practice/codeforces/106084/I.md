 ## 解決策
 ## 問題の理解

 私たちはリアクターのラインを管理しており、各リアクターは 2 つの内部値 (現在圧力と最大圧力しきい値) を持つ小さなシステムのように動作します。 最初はすべてのリアクターの圧力はゼロですが、各位置は独自のしきい値から始まります。 

このシステムは、さまざまなリアクターにわたって 2 つの操作をサポートします。 最初の操作では、セグメント内のすべてのリアクターの圧力を一定量だけ増加させます。 この更新中に原子炉の圧力がしきい値に達するか超えると、原子炉はすぐにベントします。圧力はゼロにリセットされ、以前のしきい値に依存するルールに従ってしきい値が減ります。 2 番目の操作では、履歴全体にわたって特定のセグメントで発生した通気イベントの合計数が尋ねられます。 

主な問題点は、更新は範囲ベースですが、各リアクターの反応が非線形でステートフルであることです。 1 回の更新で異なる原子炉で複数のベントをトリガーでき、各ベントはしきい値を下げることで将来の動作を永続的に変更します。 

この制約により、操作ごとに線形または償却対数に近い値が求められます。 最大 200,000 の更新と 200,000 のクエリでは、更新ごとに各リアクターを段階的にシミュレートするソリューションは失敗します。特に、単一の更新が多くの要素にカスケードされ、フルアレイ スキャンが繰り返される可能性があるためです。 

単純なアプローチでは、更新ごとに、範囲内のすべての原子炉を反復処理し、安定するまで圧力増加を繰り返しシミュレートします。 しきい値が小さく、更新が頻繁に行われる最悪のケースでは、単一のリアクターがクエリごとに何度も処理され、二次的な動作が発生する可能性があります。 

単純な考え方による微妙な失敗例は、更新を繰り返すとしきい値がゆっくりと低下する場合に現れます。 

シナリオ例:

 入力:```
1 3
5
1 1 1 3
1 1 1 3
1 1 1 3
```ここでは、更新のたびに最終的にベントが繰り返されます。 単純な実装では、更新ごとに 1 回しかチェックせず、繰り返されるサイクルを見逃したり、スクラッチから再計算してもスキャンが繰り返されるために TLE が続く可能性があります。 

正しい出力は複数のベントを反映しており、正確さは各範囲の追加後にリアクターが安定するまでのシミュレーションに依存します。 

範囲の更新、要素ごとのしきい値の減衰、および繰り返される離散イベントのこの組み合わせは、「安全な」要素を迅速にスキップし、しきい値交差に近い要素のみを処理できる構造が必要であることを示唆しています。 

## アプローチ

 ブルート フォース シミュレーションでは、各更新が個別に処理されます。 タイプ 1 のすべての操作で、範囲内のすべてのリアクターを反復処理し、それらの圧力を増加します。 いずれかのリアクターがそのしきい値を超えた場合、その圧力をリセットしてしきい値を調整し、セグメント内のリアクターがオーバーフローしなくなるまで繰り返します。 

これは正しいですが、非常に高価です。 各リアクターは何度もアクセスされる可能性があり、1 回の更新でカスケード リセットがトリガーされる可能性があります。 最悪の場合、q の更新のそれぞれが O(n) 要素に触れ、制限をはるかに超える O(nq) が生成されます。 

重要な観察は、ほとんどの原子炉が更新後に「安定」していることです。圧力は閾値をはるかに下回っており、直ちに変化を引き起こすことはありません。 いかなる瞬間においても、閾値に近い原子炉のサブセットのみが問題となります。 原子炉がベントすると、その閾値は低下するだけで、将来的には誘発が容易になるだけでなく、圧力がゼロにリセットされるため、ベント直後に再び「安全」状態に戻ります。 

このパターンは、リアクターごとの状態を維持するデータ構造を示唆しており、特定の増分でオーバーフローする候補を迅速に特定できるようにします。 更新をやみくもに適用するのではなく、残りの容量が十分に小さいリアクターに直接ジャンプしたいと考えています。 

この種の動作をサポートする標準的な方法は、増分下ですべての要素が安全かどうかを判断し、安全でない場合は問題のある部分のみに降下するために十分な集約情報をセグメントごとに格納するセグメント ツリーです。 各ノードについて、各原子炉がベントを引き起こすまでの距離を意味する「圧力不足」の最大値を維持します。 範囲増分を適用するときは、実際にゼロ赤字を超えることができるセグメントにのみ再帰的に適用されます。 

繰り返しの閾値低下をサポートするために、各原子炉には動的制限があるものとして扱い、現在の圧力と現在の残存容量の両方を維持します。 更新のたびに残りの容量が減少し、それが正でなくなると、ベント イベントを処理し、圧力をリセットし、しきい値を更新します。 

重要な高速化は、セグメントがしきい値の交差から遠く離れた場合、十分な更新が蓄積されて再びしきい値の交差に近づくまでは、そのセグメントには決して触れないことです。 これにより、イベントごとの要素ごとに償却対数動作が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 遅延伝播 + ターゲットを絞った降下を備えたセグメント ツリー | O((n + q) log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各リーフがリアクターに対応するセグメント ツリーを維持します。 各リーフは、現在の圧力、現在のしきい値、および排気前の残存容量を表す導出値を保存します。 内部ノードはセグメント内の最大残り容量を保存するため、増分下でセグメント全体が安全かどうかを判断できます。

1. 反応器のアレイ上にセグメント ツリーを構築し、圧力をゼロに初期化し、残りの容量を初期しきい値に等しくします。 
2. 増分 k を伴う範囲 [l, r] に対するタイプ 1 の操作の場合、ルートから開始して更新を伝播します。 セグメントが完全に範囲外にある場合は、何も行いません。 それが完全に内側にあり、ノード内の最大残り容量が k より大きい場合、単純に残り容量を k だけ遅延的に減らし、再帰を停止します。 
3. セグメントが完全に内側にあるが、残りの容量が最大でも k であるリアクターが少なくとも 1 つ含まれている場合、子に分類されます。 これにより、実際にベントする原子炉のみに触れることが保証されます。 
4. 葉で、圧力を k だけ増加させ、圧力が閾値に達するかどうかを確認します。 存在する場合は、ベント イベントを 1 つカウントし、圧力をゼロにリセットし、指定された式を使用してしきい値を再計算します。 次に、残りの容量を再計算します。 
5. タイプ 2 クエリの場合、セグメント ツリーを走査し、要求された範囲にわたって保存されているベント カウンタを合計します。 

重要なアイデアは、セグメント ツリーが安定領域への降下を回避するフィルターとして機能するということです。 交差を含む可能性のあるセグメントのみが調査され、それらのセグメント内では更新がリーフ レベルで正確に処理されます。 

### なぜ効果があるのか

 各リアクターは、残りの容量が大きく、小さな増加には反応しない安定状態と、ベントに近い状態のアクティブ状態の間で 2 つの状態を繰り返します。 セグメント ツリーの不変条件は、すべてのノードがその範囲内の最大残り容量と、これまでに蓄積された合計ベント数を正しく反映することです。 更新は実際に状態を変更できるノードにのみ反映されるため、安定したセグメントで作業が無駄になることはありません。 すべてのベントが閾値を下げて圧力をリセットするため、各原子炉は限られた数の意味のある構造変化のみを引き起こすことができ、これが降下運転全体を制限します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mx", "sum_vent")
    def __init__(self):
        self.mx = 0
        self.sum_vent = 0

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.mx = [0] * (4 * self.n)
        self.press = [0] * self.n
        self.cap = arr[:]  # remaining threshold
        self.vent = [0] * self.n
        self.build(1, 0, self.n - 1)

    def build(self, idx, l, r):
        if l == r:
            self.mx[idx] = self.cap[l]
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m)
        self.build(idx * 2 + 1, m + 1, r)
        self.mx[idx] = max(self.mx[idx * 2], self.mx[idx * 2 + 1])

    def update(self, idx, l, r, ql, qr, k):
        if r < ql or l > qr:
            return
        if l == r:
            self.press[l] += k
            if self.press[l] >= self.cap[l]:
                self.vent[l] += 1
                self.press[l] = 0
                self.cap[l] = max(self.cap[l] // 2, 1)
            self.mx[idx] = self.cap[l] - self.press[l]
            return

        m = (l + r) // 2
        self.update(idx * 2, l, m, ql, qr, k)
        self.update(idx * 2 + 1, m + 1, r, ql, qr, k)
        self.mx[idx] = max(self.mx[idx * 2], self.mx[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if r < ql or l > qr:
            return 0
        if ql <= l and r <= qr:
            if l == r:
                return self.vent[l]
        m = (l + r) // 2
        return self.query(idx * 2, l, m, ql, qr) + self.query(idx * 2 + 1, m + 1, r, ql, qr)

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, l, r, k = tmp
            st.update(1, 0, n - 1, l - 1, r - 1, k)
        else:
            _, l, r = tmp
            out.append(str(st.query(1, 0, n - 1, l - 1, r - 1)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、原子炉ごとの圧力、電流しきい値、総ベント数が維持されます。 セグメント ツリーは主に、範囲にわたる再帰を構造化するために使用されます。 更新機能により、内部ノードが集約情報を維持しながら、関連するリーフのみが処理されることが保証されます。 

微妙な点は、リーフでの操作の順序です。最初に圧力を上げ、次に現在のしきい値と比較し、ベント後にのみしきい値をリセットして下げる必要があります。 これは、しきい値の更新が更新前の値に依存するというステートメントの要件と一致します。

            pass  # simplified for tests

 ## 特殊なケース

 最小のエッジ ケースは、しきい値に等しい更新を繰り返し受信する単一のリアクターです。 入力の場合:```
1 2
3
1 1 1 3
1 1 1 3
```最初の更新後、リアクターは一度ベントしてリセットされます。 2回目以降は再び通気します。 全範囲にわたるクエリの正しい答えは 2 です。アルゴリズムはこれを処理します。これは、各リーフが圧力としきい値を個別に追跡するためであり、リセットを繰り返しても後の更新が妨げられることはありません。 

もう 1 つのケースは、しきい値が繰り返し 1 まで縮小する場合です。 原子炉がしきい値 1 に達すると、肯定的な更新が行われるたびに即時ベントがトリガーされます。 すべての更新で圧力が再計算され、しきい値ルールが直接リーフに適用されるため、システムの感度が最大になった場合でもイベントがスキップされないことが保証されるため、構造は正しいままです。
