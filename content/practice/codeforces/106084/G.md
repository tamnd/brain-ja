 ## 解決策
 ## 問題の理解

 重み 1 の重み付きエッジを持つツリーと、2 つの固定頂点を接続するポータルと呼ばれる特別なエッジが 1 つ追加されています。$x$そして$y$。 ポータルは何度でも使用でき、毎回のコストは 0 です。木のエッジに沿った移動には常に横断ごとに 1 コストがかかり、エッジは任意に再利用できます。 任意の頂点で開始し、任意の頂点で終了し、すべての頂点を少なくとも 1 回訪れるウォークを構築する必要があります。 目的は、通過するすべてのツリー エッジの総コストを最小限に抑えることです。 

重要なオブジェクトは単純なパスではなく、単一のゼロコストのショートカットによって強化された木の上を歩くことです。 ポータルがない場合、これは古典的な「ツリー ウォーク内のすべてのノードをカバーする」問題であり、選択した開始点と終了点を除いて、最小の接続サブツリーにあるすべてのエッジを通常 2 回横断する必要があります。 ポータルは、ゼロコストで 2 つの頂点を効果的に識別することで構造を変更します。これにより、ツリーの横断対称性の一部が崩れる可能性があります。 

制約により、最大で$5 \times 10^5$すべてのテスト ケースにわたるノードの合計により、二次関数や偶数関数が即座に除外されます。$O(n \log n)$テストケースごとに、大きな定数を使用した大量の前処理が行われます。 意図したソリューションは、ツリー DP または構造的なカウント引数に依存して、テスト ケースごとに線形である必要があります。 

ポータルがツリーの非常に異なる部分にあるノード、または隣接するノードを接続する場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$x$そして$y$長いチェーンの同じエッジ エンドポイントである場合、ポータルは中央パスの繰り返しの横断を効果的に置き換えることができます。 度数のパリティ効果を無視するか、端点を除いてすべてのエッジが常に 2 倍であると仮定する素朴な解決策はオーバーカウントします。 

別の失敗ケースは、最適なパスが「ポータル接続コンポーネント」内で開始または終了するときに発生します。これは、ポータルを使用して、実際に横断コストを支払うことなく、さまざまなエンドポイントの選択をシミュレートできるためです。 

## アプローチ

 ポータルを使用しない場合、ツリー内のすべてのノードを訪問する最小のウォークはよく知られています。すべてのノードを含む最小のサブツリー (ツリー全体) 内のすべてのエッジをトラバースし、選択した開始頂点と終了頂点の間の単純なパスに沿ったものを除いてすべてのエッジが 2 回使用されます。 同等のコストは、$2(n-1) - \text{diameter contribution}$1 つの道を引き返さずに済むためです。 

ブルート フォース アプローチでは、最適な開始と終了のペアを計算し、ポータルの使用方法のあらゆる可能性をシミュレートし、結果として生じるオイラーのようなトラバース コストを評価しようとします。 エンドポイントを選択するだけでもすでに問題が発生するため、これはすぐに実行不可能になります。$O(n^2)$可能性があり、ポータルでは、サブセットまたは構成にわたる状態空間内の最短パスを必要とする反復的な状態遷移が導入されます。 

重要な観察は、ツリー構造により、どのくらいのエッジを 2 回通過する必要があるかを推論できるということです。 ポータルによって引き起こされる何らかの「ショートカット構造」上にない限り、すべてのエッジは 2 回強制されます。 ポータルは、代替のゼロコスト接続を効果的に作成します。$x$そして$y$したがって、この接続を中心とするサブツリー間のパスは、一方向の料金を支払うことなく通過できます。 

この問題についての正しい考え方は、すべてのノードをカバーする接続されたウォークを構築していると考えることです。これは、すべての頂点がカバーされるスパン マルチグラフ ウォークを実行するのと同じです。 コストは、選択したトラバース構造のエッジ数の 2 倍から最適な「節約パス」の長さを引いたものになります。 

ポータルを使用すると、間の固有のパスに沿って正確にコストを削減できます。$x$そして$y$木の中で。 If we imagine removing that path, the tree splits into components, and the portal lets us jump between the endpoints of that path freely. The optimal saving corresponds to avoiding re-traversal of that path segment when connecting endpoints in the final Euler trail.

 So the problem reduces to computing the length of the simple path between$x$そして$y$、 言う$d(x,y)$、そしてそれをベースラインコストから差し引きます$2(n-1)$なぜなら、ゼロコストのテレポートにより、そのパス全体が一度「ショートカット」できるからです。 

これにより、次のような直接的な式が得られます。$$\text{answer} = 2(n - 1) - d(x, y)$$ツリー内の距離を計算する必要があるだけです。これは、テスト ケースごとに BFS または DFS を使用して実行できます。

 ## アルゴリズムのチュートリアル

 1. 入力エッジからツリー隣接リストを構築します。 この表現により、距離計算の効率的なトラバースが可能になります。 
2. 間の最短距離を計算します。$x$そして$y$から始まるBFSを使用したツリー内$x$。 すべてのエッジの重みが 1 であるため、BFS は最短パス距離を正しく生成します。 
3. しましょう$d$間の距離になります$x$そして$y$。 
4. ショートカットなしでツリー内のすべてのノードにアクセスする場合のベースライン走査コストを計算します。$2(n-1)$。 これは、オイラー ツアーのようなウォークですべてのエッジを 2 回横断することに相当します。 
5. 減算$d$間のパスを横断する必要性を排除するポータルの機能を考慮して、このベースラインから$x$そして$y$一方向に。 
6. 結果の値を出力します。 

明白ではない部分は、なぜ正確に減算するのかということです$d(x,y)$有効です。 ポータルを使用すると、相互間の固有のツリー パスの 1 つのトラバースを効果的に置き換えることができます。$x$そして$y$コストゼロのジャンプで、このパスはまさに$d(x,y)$エッジが長い。 

### なぜ効果があるのか

 すべての頂点を訪問するウォークでは、選択した開始から終了までのパス上にあるエッジを除き、各エッジを各方向に少なくとも 1 回横断する必要があります。 これは、最小のエッジウォークカバーツリーの標準的な特徴付けです。 ポータルは追加のゼロコスト接続を追加します。これは、間に余分なエッジを追加するかのように動作します。$x$そして$y$。 ツリーでは、エッジを 1 つ追加するとちょうど 1 つのサイクルが作成され、最適なオイラー ウォークにより、そのサイクルの片側を逆トレースする必要がなくなります。 したがって、唯一削減可能なコストは、木道を組み合わせて作成される独自の自転車道の長さです。$x$そして$y$ポータルエッジで。 ポータル エッジのコストは 0 であるため、節約効果は、ポータル エッジ間のツリー距離に等しくなります。$x$そして$y$、式が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, x, y = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        dist = bfs(x, adj, n)
        dxy = dist[y]

        ans = 2 * (n - 1) - dxy
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```BFS は、テスト ケースごとに 1 回実行されます。$x$までの距離だけが必要なので、これで十分です。$y$。 グラフはツリーであるため、任意の 2 つのノード間には単純なパスが 1 つだけ存在するため、BFS 距離はそのパスの長さを直接示します。 

式のステップでは、解が完全に決定されます。 残りは標準のツリー トラバーサル インフラストラクチャです。 

## 実用的な例

 小さな木について考えてみましょう。$n = 5$、エッジがチェーンを形成します$1 - 2 - 3 - 4 - 5$、ポータルが接続します$x = 1$、$y = 5$。 

基本コストは$2(n-1) = 8$。 1 と 5 の間の距離は 4 です。 

| ステップ | 値 |
 | --- | --- |
 | n | 5 |
 | ベースライン | 8 |
 | d(1,5) | 4 |
 | 答え | 4 |

 これは、ポータルを使用してチェーン全体を一度遡ることを避けることに対応します。 

ここで、中心 1、葉 2、3、4、5、および葉 2 と 3 の間にポータルがある星のような形をした木について考えてみましょう。 

ベースラインはまた$8$。 2 と 3 の間の距離は、ノード 1 を介して 2 です。 

| ステップ | 値 |
 | --- | --- |
 | n | 5 |

 これは、ポータルが葉を接続する場合でも、節約されるのは中心を通る経路の長さだけであることを示しています。 

これらの例は、ポータルの唯一の構造効果が、そのエンドポイント間の木の距離を差し引くことであることを確認しています。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$x$そして$y$隣接している。 この場合、距離は 1 なので、答えは次のようになります。$2(n-1)-1$。 BFS は依然として正しく 1 を返し、減算は 1 つのトラバーサルのみが保存されていることを反映しています。 

もう 1 つのエッジ ケースは、両方の端点が葉である星形のツリーです。 BFS 距離は中心を正しく通過しており、節約は 2 に等しくなります。リーフが独立したエンドポイントであると仮定する単純なアプローチでは、この間接的なパス構造を見逃してしまいます。 

最後のエッジケースは次のような場合です$n=2$。 ツリーには 1 つのエッジがあり、ベースライン コストは 2、2 つのノード間の距離は 1 で、答えは 1 になります。BFS の初期化では、単一のエッジをスキップすることなく小さなグラフを正しく処理する必要があります。そうしないと、距離が -1 のままになり、式が壊れてしまいます。
