 ## 問題の理解

 多くの独立したクエリが与えられます。 各クエリは 2 つの整数と開始値を提供します。`n`そしてベース`k`。 最小の整数を見つけたい`x`そのような`x ≥ n`そして`x`の個別のべき乗の和として書くことができます。`k`。 

これは、指数を選択できることを意味します`a1, a2, ..., ad`、すべて異なり、次のような数字を形成します`k^a1 + k^a2 + ...`。 それぞれのパワーは最大 1 回しか使用できないため、表現は基本関数のように動作します。`k`すべての数字が 0 または 1 であり、1 を超える数字はありません。 

タスクは、次のことを確認することではありません。`n`それ自体は表現可能ですが、この制限された記数体系で次の表現可能な数値に到達するまで、必要に応じて上に移動します。 

制約は非常に重要です。`10^5`クエリとその両方`n`そして`k`と同じ大きさにすることができます`10^9`。 これにより、有効な数値をすべて構築しようとしたり、クエリごとに指数関数的な検索を実行したりするアプローチは即座に除外されます。 上向きのリニアスキャンでも`n`有効な数値間のギャップが大きくなる可能性があるため、最悪の場合は不可能ですが、それでも多くのチェックが必要です。 

微妙なエッジケースが現れるのは、`k`に比べて大きい`n`。 たとえば、次の場合`k > n`、以下で利用可能な唯一の権限`n`は`1`そして`k`、そのため、表現力は非常に希薄になります。 素朴な貪欲さ「常に分解しようとする」`n`」アプローチは、わずかに上に行くことが許可されていることを見逃す可能性があるため、ここで失敗する可能性があります`n`有効な金額に達するまで。

## アプローチ

 ブルートフォースのアイデアは単純です。`n`、すべての数値をテストします`x = n, n+1, n+2, ...`それが次の個別の累乗の合計として表現できるかどうかを確認します。`k`。 単一の数値を確認するには、繰り返し除算が必要です`k`そしてその基数が 1 を超える数字がないことを保証します。`k`表現。 この小切手は安いです、約`O(log_k x)`ただし、候補者の数に制限はありません。 最悪の場合、有効な整数を見つける前に長い整数をスキャンする可能性があり、このアプローチは制約の下では実行不可能になります。 

重要な観察は、「k の個別のべき乗の合計」という条件は、基底`k`数値の表現には数字のみが含まれます`0`または`1`。 したがって、実際には混合基数システムで作業しているため、数字を避ける必要があります。`2, 3, ..., k-1`。 

線形に増加する代わりに、基数の数字ごとに答えを構築できます。`k`。 アイデアは次のように表現することです`n`基地内で`k`、次に、すべての桁が次のいずれかになるように、最下位桁から上に向かって修復します。`0`または`1`。 桁を超えるたびに`1`、次の位置に持ち込むことで修正します。これは、より高い出力を増加することに対応します。`k`そして低いポジションをゼロにします。 修正後も、依然として以下になる可能性があります`n`, そのため、妥当性を維持しながら最小限の増加を確保する必要があります。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1.変換`n`その基地に-`k`表現、最下位桁から最上位桁まで格納します。 これにより、次の各機能に直接アクセスできるようになります。`k`係数。 有効性は数値ごとではなく桁ごとに定義されるため、この手順が必要です。 
2. 最小インデックスから最大インデックスまで数字をたどります。 数字が`0`または`1`、すでに有効なので変更する必要はありません。 構造は有効な表現と一貫性を保ちます。 
3. 数字が出てきたら`d ≥ 2`、すぐに修正しなければなりません。 この桁のモジュロを削減します`2`、なぜなら、`0`そして`1`許可されています。 余分なもの`d // 2`次の桁に繰り上げられます。 これは、`k^i`より高い権力に置き換える必要があります。 
4. 既存の数字をすべて処理した後でも、元の長さを超えるキャリーが残る可能性があります。 キャリーがなくなるまで、新しい高い位置にキャリーを伝播し続けます。 
5. この時点では、まだ以下の数値が生成されている可能性があります。`n`まれに、高い位置で構造が変化する境界ケースがあります。 最小性を保証するために、調整された桁から数値を再構築し、必要に応じて、残りの桁上げによりより高い電力の選択が強制されることを確認して、次の有効な構成を増分します。 

プロセスをよりわかりやすく表示する方法は、次の値以上の最小の数を見つけることです。`n`誰の基地-`k`数字が入っています`{0,1}`キャリー修復を使用して制約付き増分をシミュレートすることによって。 

### なぜ効果があるのか

 任意の有効な数値は、次の累乗のサブセットに正確に対応します。`k`, したがって、各桁の位置は、その累乗が含まれているかどうかを独立して示します。 桁を超える場合`1`、これはそのパワーを選択しすぎたことを意味します。これは、置き換えることに相当します。`k`のコピー`k^i`1 部のコピーで`k^{i+1}`。 この置換により値が保持され、不正な桁数が厳密に削減されます。 安定するまでこのプロセスを繰り返すと、元の数値を下回らない最小の有効な表現が得られます。これは、さらに小さな調整を行うと上位桁を減らす必要があり、すでに適用されている桁上げ制約に違反するためです。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n, k):
    if k == 1:
        return n  # degenerate case, not actually needed under constraints

    digits = []

    x = n
    while x > 0:
        digits.append(x % k)
        x //= k

    digits.append(0)

    i = 0
    while i < len(digits):
        if digits[i] < 2:
            i += 1
            continue

        carry = digits[i] // 2
        digits[i] %= 2
        digits[i + 1] += carry

        i += 1

    res = 0
    power = 1
    for d in digits:
        if d:
            res += power
        power *= k

    return res

def main():
    q = int(input())
    out = []
    for _ in range(q):
        n, k = map(int, input().split())
        out.append(str(solve_one(n, k)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は拡張から始まります`n`基地に`k`有効性はその表現で定義されているためです。 元の桁長をオーバーフローしたキャリーが安全に処理されるように、センチネル ゼロ桁が追加されます。 

ループは数字を昇順に処理します。 桁を超えるたびに`1`、それは剰余として縮小されます`2`、余った部分はキャリーとして上に押し上げられます。 これは、同じ検出力の複数の出現をより高い検出力に置き換えることを模倣し、有効性を復元しながら値を保持します。 

最後に、クリーンアップされた数字配列から数値が再構築されます。 それぞれ`1`数字はちょうど 1 乗に寄与します`k`、有効な表現の定義と一致します。 

キャリー伝播中に直接数値アキュムレータを維持しないため、再構築ステップが必要です。 これにより、オーバーフローの問題が回避され、ロジックが桁レベルの不変条件に合わせて維持されます。

 ## 特殊なケース

 主なエッジケースは次のような場合です`n`すでにベースで有効です`k`、すべての数字が`0`または`1`。 この状況では、アルゴリズムはキャリー操作を実行しません。 例えば、`n = 13, k = 3`基数3の表現を与える`111`、これはすでに有効であるため、再構築は返されます。`13`変わらない。

最後の微妙なケースは、キャリーの伝播が繰り返されることで、当初の予想よりも長い表現が作成される可能性がある場合です。 追加されたゼロの数字により、完全なオーバーフローであっても、特別なケースを使用せずに有効なより高いべき乗に到達することが保証され、すべてのクエリにわたって均一に正確さが維持されます。
