 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$セルから始まる単一のトークン (「ピース」) を持つグリッド$(r, c)$。 ゲームは個別のラウンドで展開します。 各ラウンドで、コンピューターは最初に数字を発表します。$k$であれば、正確に実行することができます$k$各移動は、隣接する削除されていないセルへの駒のステップです (または、隣接する削除されていないセルが存在しない場合は、事実上何も行われません)。 移動後、コンピュータはまだ存在するセルを 1 つだけ削除します。 その削除されたセルが移動後の駒の位置である可能性がある場合、そのラウンドでの勝利を直ちに宣言することができます。 

重要な点は、単一のポジションを追跡しないことです。 代わりに、正確な動きを観察または制御していないことを前提として、各ラウンド後に駒が存在する可能性のあるすべてのセルのセットを追跡します。 私たちが気にするのは、セルが削除された時点で、以前のすべての削除と一致する一連の有効な動作によってそのセルがまだ到達可能であるかどうかだけです。 

出力は、そのラウンドで削除されたセルがまだピースの到達可能なセット内にあるような、最も古いラウンド インデックスです。 

制約により許可されるのは、$n, m \le 1000$したがって、グリッドには最大$10^6$セル、ラウンド数も最大です。$10^6$。 これは、グリッド上の BFS またはフラッド フィルがすでに存在するため、ラウンドごとに到達可能性を最初から再計算しようとするアプローチは遅すぎることを直ちに示唆しています。$O(nm)$、それを繰り返し行うと、制限を桁違いに超えてしまいます。 

さらに微妙な問題は、ラウンドごとに許可される手の数が変動し、非常に大きくなる可能性があるため、ピースが標準の BFS エージェントではないことです。そのため、削除と削除の間に、ピースはまだ利用可能なセルの接続された領域を効果的に横断することができます。 これにより、問題は、移動ソースとの削除における動的接続に変わります。ここでは、現在の削除が特定のタイミング制約の下で開始セルと同じ「利用可能な領域」にあるかどうかだけを考慮します。 

単純な間違いは、ピースを常に単一の BFS フロンティア セルに配置されているものとして扱うことです。 たとえば、最初から最短経路距離に留まると仮定すると、削除間の連結成分内を任意にさまよえる可能性があることを見逃します。 もう 1 つの失敗モードは、削除によってグリッドが切断され、時間の経過とともに進化する複数のコンポーネントが作成される可能性があることを無視することです。 

特に微妙なエッジ ケースは、開始セルが非常に遅く削除されるセルに囲まれているが、遠く離れたセルが早期に分離される場合です。 正しい答えは、ピースが標準的な最短経路の意味でその領域に物理的に「到達」する前に現れる可能性があります。$k$値を使用すると、残りのコンポーネント内で任意の位置を変更できます。 

## アプローチ

 ブルートフォース解釈では、各ラウンド後に到達可能なセルの完全なセットが明示的に維持されます。 削除するたびに、残りのグリッドで BFS/DFS を使用して、どのセルが最初から到達可能であるかを再計算します。 これは、削除されたセルが到達可能かどうかを正しく答えます。これは、ピースが多くのステップにわたって残りのセルの接続されたコンポーネント内で自由に移動できるためです。 

ただし、この単純なアプローチでは、サイズのグラフの走査が再計算されます。$O(nm)$それぞれ最大で$nm$ラウンド、につながる$O((nm)^2)$、それは約です$10^{12}$最悪の場合の運用。 これは実現可能な限界をはるかに超えています。 

重要な観察は、削除によってグリッドの一部が切断された場合にのみ到達可能性が変化するということです。 効率的にノードを 1 つずつ削除し、残りのグラフで特定のノードが最初からいつ切断されるかを尋ねます。 これは古典的なオフラインの動的接続の問題ですが、逆です。ノードを時間的に前方に削除する代わりに、削除を挿入として後方に処理し、グリッドを徐々に再構築できます。 

プロセスを逆にすると、空のグリッドから開始し、削除とは逆の順序でセルを再追加します。 各ステップで、どのセルが開始位置に接続されているかを維持します。$(r, c)$。 素の集合結合構造を使用して、セルを追加するたびに、すでにアクティブな隣接セルと結合します。 開始セルが、順方向プロセスの削除ステップに対応する新しく追加されたセルに接続された瞬間に、削除がまだ到達可能であった最も早い時間を判断できます。 

これにより、問題は、動的に成長するグリッド上の結合検索接続クエリに変換され、各セルが 1 回アクティブ化され、最大 4 つの隣接セルと結合が実行されます。

 ## アルゴリズムのチュートリアル

 削除シーケンスを逆の順序で処理し、削除をアクティブ化に変換します。 

1. グリッドの寸法、開始位置、削除のリストを順番に読み取ります。 各削除は、順方向プロセスでセルが消える時間に対応します。 
2. セルごとに、削除タイムライン内の位置を保存する構造を作成します。 各セルを、それが削除されるステップにマップします。 
3. すべてのグリッド セルに対して DSU を初期化します。ただし、すべてのセルが非アクティブな状態から開始します。 また、セルが反転プロセスでアクティブ化されたかどうかをマークするブール グリッドも維持します。 
4. 最後の削除から最初の削除までを繰り返します。 ステップで$t$で削除されたセルをアクティブにします$t$前進プロセス中。 
5. セルがアクティブ化されると、その 4 つの隣接セルがすでにアクティブである場合は、セルをその 4 つのセルに接続します。 これにより、残りの (将来アクティブになる) グリッドの接続されたコンポーネントが段階的に構築されます。 
6. アクティブ化するたびに、開始セルがアクティブかどうかを確認します。 そうであり、現在削除されているセルを含むアクティブ化されたばかりの構造に (DSU 内で) 接続されている場合は、回答を更新します。 このような最も早いステップは、その削除されたセルが到達可能であった最も早いラウンドに対応します。 
7. すべてのセルが逆にアクティブになるまで続けます。 最終的な答えは、最小の順方向インデックスであり、その削除はアクティブ化の瞬間に開始点と同じ接続コンポーネント内にまだ存在します。 

### なぜ効果があるのか

 前方プロセスのどの時点でも、ピースは削除されていないセルの接続されたコンポーネント内で任意に移動できます。 したがって、削除されたセルは、削除されたセルの補数グラフの開始点と同じ接続コンポーネント内にある場合に、正確に「到達可能」になります。 

逆の処理では、これらのコンポーネントが可用性の高い順に正確に構築されます。 DSU は、現在利用可能なセル間の接続を表すという不変条件を維持します。 セルをアクティブ化すると、前方の「生きているグリッド」に存在するすべてのエッジが復元されます。 したがって、DSU の接続性は、対応する時点でのフォワード ゲームの到達可能性と一致します。 この等価性により、開始コンポーネントにセルが含まれる最も早いアクティブ化の瞬間が、そのセルがまだ到達可能であった最も早い前方削除ステップに正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m, r, c = map(int, input().split())
_ = input()

t = n * m

cells = []
for _ in range(t):
    k, i, j = map(int, input().split())
    cells.append((i - 1, j - 1))

# DSU
parent = list(range(n * m))
size = [1] * (n * m)

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return
    if size[ra] < size[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    size[ra] += size[rb]

active = [[False] * m for _ in range(n)]

def id(i, j):
    return i * m + j

start = id(r - 1, c - 1)

active[start // m][start % m] = True

ans = 0

dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

for idx in range(t - 1, -1, -1):
    x, y = cells[idx]
    active[x][y] = True
    cur = id(x, y)

    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if 0 <= nx < n and 0 <= ny < m and active[nx][ny]:
            union(cur, id(nx, ny))

    if active[r - 1][c - 1]:
        if find(cur) == find(start):
            ans = idx + 1

print(ans)
```DSU 構造は、現在アクティブなセル間の接続を逆のプロセスでエンコードします。 アクティブ化するたびにノードが追加され、すでにアクティブな隣接ノードに接続され、コンポーネント構造の正確性が維持されます。 

2D 座標と DSU インデックスの間のマッピングにより、定数時間の近隣チェックとユニオン操作が保証されます。 応答は、アクティブ化されたセルが開始セルと同じコンポーネントに属する最も古いインデックスとして追跡されます。

 ## 特殊なケース

 重要なエッジ ケースは、開始セルが非常に遅く削除されたものの、逆プロセスの早い段階で分離された場合です。 接続は将来のアクティブ化ではなく、現在アクティブなネイバーのみに依存するため、DSU はこれを引き続き正しく処理します。 

もう 1 つのケースは、系統が早期に切断されたが、逆に後で接続が回復する場合です。 逆アクティブ化ではエッジが追加されるだけで削除されず、単調な正確性が維持されるため、アルゴリズムはこれを処理します。 

最後のエッジ ケースは、開始セル自体が最後にアクティブ化されたセルである場合です。 接続が開始がアクティブになってからのみチェックされるため、アルゴリズムは依然として機能し、早期接続が報告されないことが保証されます。
