 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、水平方向に何層にも重ねられたコーヒーでできたカップです。 各層には一定の体積（高さ）と一定の「強度」があります。 レイヤーは下から上に積み重ねられ、最初は何も混合されません。 

ドリンクの全体的な強度は、すべての層の加重平均であり、各層の強度にその高さを乗じたものになります。 高さは体積に比例するため、これは単に総「強度質量」を総体積で割ったものになります。 

カップの上部からある程度の深さまで液体を除去できるストローの使用が許可されています。 このような操作を繰り返すことで、層の高さを選択的に減らすことができますが、それは上側からのみ開始することになります。つまり、十分に深いストローを選択した場合にのみ、スタックのプレフィックスから「ボリュームを削除」できることになります。 

クエリ強度の目標 t ごとに、関与する必要がある最上位層の最小数を決定する必要があります。そうすることで、これらの層からのみある程度の量のコーヒーを削除することで、最終的な加重平均を正確に t に調整できるようになります。 最上位層を何層入れても不可能な場合は-1を出力します。 

2・10^5 までの制約 n、q は、クエリごとに削除をシミュレートしたり、レイヤーごとに実現可能性を再計算しようとするソリューションを即座に除外します。 クエリごとにすべてのレイヤーを検査するアプローチでは、時間がかかりすぎます。 

微妙な点は、レイヤー全体を削除する必要がないことです。 上位 k 個のレイヤーのいずれかから、任意の連続量を削除できます。 これにより、問題は離散的ではなく連続的なものになり、凸型実現可能性スタイルの解決策が可能になります。 

重要なエッジ ケースの 1 つは、ターゲット t がすべてのレイヤー強度の範囲外にある場合です。 それでも、異なる強度のレイヤーから削除すると平均が連続的に変化するため、部分的な削除で達成できる場合があります。 したがって、t を最小または最大 p_i と比較するだけでは十分ではありません。 

もう 1 つのエッジ ケースは、すべての p_i が等しい場合です。 この場合、最初の平均は固定されており、削除量によって変化しないため、その値に一致するクエリのみが可能になります。 

## アプローチ

 直接シミュレーションのアプローチでは、クエリごとに、上位層の数を増やしてテストし、目標 t を達成するために除去を操作できるかどうかを確認します。 k 層の固定プレフィックスの場合、結果の加重平均が t に等しくなるような [0, h_i] に除去量 x_i が存在するかどうかを判断する必要があります。 これは、制約付き線形実現可能性問題になります。 

除去の可能性を明示的にシミュレートする場合、状態空間は各層で連続しており、すべての組み合わせを単純に列挙することは不可能です。 プレフィックスごとの実現可能性のチェックに制限したとしても、クエリごとに O(n) の作業が必要となり、O(nq) が大きすぎます。 

重要な観察は、条件が除去されたボリューム内で線形方程式として書き換えられるということです。 元の総強度質量を S 、全高を H とします。ある程度の量を除去すると、条件は、S - tH が、選択した除去の合計 (p_i - t) と除去された高さの合計に等しいという形式の方程式になります。 各層は、達成可能な値の線形セグメントに寄与します。 各層からの除去は独立かつ連続的であるため、各層は間隔に寄与し、独立した間隔の合計が再び連続した間隔になります。 

したがって、k 層の固定プレフィックスの場合、式 S - tH の達成可能な値のセットは、正確に区間 [L_k, R_k] になります。 実現可能性は、必要な値がこの間隔内にあるかどうかを確認することになります。 

k が増加すると、間隔が追加されるだけなので、到達可能な間隔は拡大するだけです。 この単調性により、クエリごとに最小の有効なプレフィックス k をバイナリ検索できるようになります。

残る唯一の問題は、区間の境界が t に依存し、各層の「正の寄与」または「負の寄与」への分類がクエリごとに変わることです。 これには、p_i のしきい値条件の下でプレフィックス合計を高速に計算する必要がありますが、これはソートされた値を格納するセグメント ツリーで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再計算を伴うすべての k に対するクエリごとのブルート フォース | O(n^2 q) | お(1) | 遅すぎる |
 | プレフィックスの実現可能性 + セグメント ツリー + 二分探索 | O(q log^3 n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 t はクエリごとに変化するため、クエリ固有の処理は何も行いません。 すべての構造は静的配列に基づいて構築されます。 

1. グローバル合計 S_p = sum(p_i h_i) および S_h = sum(h_i) を計算します。 クエリターゲット t に対して、必要なシフト値 D = S_p - t * S_h を定義します。 これは、符号付きの意味で「削除」する必要がある正確な量です。 
2. 上位 k 層の固定プレフィックスの場合、各層 i は、そこからどれだけ除去するかに応じて、量 (p_i - t) * x_i に寄与します。 x_i は [0, h_i] で連続的に変化する可能性があるため、各層は可能な値の全間隔に寄与します。 
3. 各層 i に対して、c_i = (p_i - t) * h_i を定義します。 p_i ≥ t の場合、0 と h_i の間で x_i を選択することで、[0, c_i] の任意の値を実現できます。 p_i < t の場合、[c_i, 0] の任意の値を実現できます。 したがって、各層は間隔に寄与します。 
4. プレフィックス k の場合、達成可能な合計範囲はエンドポイントを合計することで得られます。 

L_k = すべての負の寄与の合計 c_i (p_i < t の場合)、

 R_k = すべての正の寄与率 c_i の合計 (p_i ≥ t の場合)。 

実現可能条件は、L_k ≤ D ≤ R_k となります。 
5. 任意の t と k についてこれらの合計を高速に計算するために、インデックスに対してセグメント ツリーを構築します。 各ノードは、p_i でソートされた (p_i, h_i, p_i_h_i, h_i) のリストと、h_i と p_i_h_i の両方のプレフィックスの合計を格納します。 これにより、任意のノードおよびしきい値 t について、対数時間で p_i < t および p_i ≥ t で分割された寄与をクエリすることができます。 
6. クエリに答えるために、k を 0 から n まで二分探索します。 各候補 k について、範囲 [1, k] にわたってセグメント ツリーをクエリして L_k と R_k を計算し、D が範囲内にあるかどうかを確認します。 
7. 条件を満たす最小の k が答えになります。 存在しない場合は、-1 を出力します。 

### なぜ効果があるのか

 核となる不変条件は、任意の固定プレフィックス k について、任意の部分除去後の達成可能な値のセットが、各層の独立した線形寄与によって決定されるまさに凸状の間隔であるということです。 各レイヤーの寄与は連続的かつ独立しているため、レイヤーを結合しても達成可能な値にギャップが生じることはありません。 したがって、実現可能性は間隔メンバーシップに帰着します。 k が大きくなるにつれて間隔は広がるだけなので、最初に成功した k は明確に定義されており、二分探索で見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [[] for _ in range(4 * self.n)]
        self.built = False
        self.arr = arr
        self._build(1, 0, self.n - 1)

    def _build(self, idx, l, r):
        if l == r:
            p, h = self.arr[l]
            self.tree[idx] = [(p, h, p * h, h)]
            return
        m = (l + r) // 2
        self._build(idx * 2, l, m)
        self._build(idx * 2 + 1, m + 1, r)
        self.tree[idx] = sorted(self.tree[idx * 2] + self.tree[idx * 2 + 1])

        p = [x[0] for x in self.tree[idx]]
        h = [x[1] for x in self.tree[idx]]
        ph = [x[2] for x in self.tree[idx]]

        hpref = [0]
        pphref = [0]
        for i in range(len(p)):
            hpref.append(hpref[-1] + h[i])
            pphref.append(pphref[-1] + ph[i])

        self.tree[idx] = (self.tree[idx], hpref, pphref)

    def query(self, idx, l, r, ql, qr):
        if qr < l or r < ql:
            return (0, 0, 0, 0, 0)
        if ql <= l and r <= qr:
            data, hpref, pphref = self.tree[idx]
            return (data, hpref, pphref, 1, 1)
        m = (l + r) // 2
        a = self.query(idx * 2, l, m, ql, qr)
        b = self.query(idx * 2 + 1, m + 1, r, ql, qr)
        return self.merge(a, b)

    def merge(self, a, b):
        data = sorted(a[0] + b[0])
        p = [x[0] for x in data]
        h = [x[1] for x in data]
        ph = [x[2] for x in data]

        hpref = [0]
        pphref = [0]
        for i in range(len(p)):
            hpref.append(hpref[-1] + h[i])
            pphref.append(pphref[-1] + ph[i])

        return (data, hpref, pphref)

def solve():
    n, q = map(int, input().split())
    arr = [tuple(map(int, input().split())) for _ in range(n)]

    S_p = sum(p * h for p, h in arr)
    S_h = sum(h for _, h in arr)

    st = SegTree(arr)

    def check(k, t):
        if k == 0:
            return S_p - t * S_h == 0

        data, hpref, pphref = st.query(1, 0, n - 1, n - k, n - 1)

        D = S_p - t * S_h

        # split by threshold t
        vals = data
        import bisect
        idx = bisect.bisect_left(vals, (t, 0, 0))

        def get_sum(l, r):
            if r < l:
                return 0, 0
            hsum = hpref[r + 1] - hpref[l]
            psum = pphref[r + 1] - pphref[l]
            return psum, hsum

        ps1, h1 = get_sum(0, idx - 1)
        ps2, h2 = get_sum(idx, len(vals) - 1)

        L = ps1 - t * h1
        R = ps2 - t * h2

        return L <= D <= R

    for _ in range(q):
        t = int(input())
        lo, hi = 0, n
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid, t):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、実現可能性の条件を間隔チェックに変換することを中心に構築されています。 セグメント ツリーは、しきい値 t で分割されたプレフィックスの合計を効率的に評価するためにのみ使用されます。 二分探索はこの実現可能性テストをラップして、必要な調整を生成できる最小のプレフィックスを見つけます。 

よくある落とし穴は、p_i と t の比較によって引き起こされる符号の変化を考慮せずに、層が加法的に動作すると仮定することです。 この分割により、問題はプレフィックスごとに 2 つの独立した合計グループに変わります。

1 1
3 7
2 4
1
2

```S_p = 1・1 + 3・7 + 2・4 = 28、S_h = 12 を計算します。 

各クエリについて、k を二分探索します。 t = 2 とします。すると、D = 28 - 24 = 4 となります。 

k = 2 の場合、上位 2 つの層 (3,7) と (2,4) を考慮します。 t = 2 で分割すると、最初の層は非負の部分に寄与し、2 番目の層は中立境界になります。 実行可能な区間には 4 が含まれるため、k = 2 となります。 

トレースは、実現可能性が、t の周りで寄与を分割することによって形成される区間内に D が存在するかどうかに依存することを示しています。 

### 例 2

 すべての層が同じ強度を持つと考えてください。```
3 1
5 1
5 1
5 1
5
```ここで、S_p = 15、S_h = 3 であるため、初期平均は 5 です。すべての層の p_i が同一であるため、任意の k について、任意の量を削除しても加重平均は変化しません。 したがって、D は t = 5 の場合にのみ常に 0 になります。その他のクエリはすべての k に対して即座に失敗し、-1 が返されます。 

これは、すべての寄与がキャンセルされると、間隔のエンドポイントが単一のポイントに折りたたまれることを示しています。

 ## 特殊なケース

 すべての層が同じ強度を持つ場合、t がその強度と一致しない限り、式 S_p - tS_h ではすべての寄与が相殺されます。 このアルゴリズムでは当然、すべての k に対して L_k = R_k = 0 が生成されるため、その値に等しい t のみが間隔条件を満たします。 

t がすべての p_i と比較して極端に大きいか小さい場合、すべての寄与は分割の片側に収まります。 その場合、区間はすべて正のセグメントまたはすべて負のセグメントから完全に構築され、実現可能性は D が単一の累積範囲内にあるかどうかを確認することになります。
