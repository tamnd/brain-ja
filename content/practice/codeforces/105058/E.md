 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには最大 40 人の候補があり、それぞれの候補には、固定数のトピックに関する知識をビットマスクとしてエンコードするラベルが付いています。 2 人の候補者が友人関係で結ばれているかどうかに応じて、一緒に働くことが許可される場合と許可されない場合があります。 

タスクは、サブセット内のすべてのペアが友情エッジによって接続されるように、候補のサブセットを選択することです。 グラフの用語では、友情グラフで派閥を探しています。 そのようなすべてのクリークの中で、私たちはまず可能な限り最大のサイズを優先します。 複数のクリークがその最大サイズに達する場合、選択されたすべての知識値のビットごとの XOR が最大化されるクリークを選択します。 

したがって、各シナリオの出力は 2 つの値、つまり考えられる最大のクリークのサイズと、その中で選択したノード値の達成可能な最大の XOR になります。 

テスト ケースあたりの候補数という点で制約は小さく、ノード数は最大 40 で、すべてのテストの n の合計が 120 を超えません。これは、サブセットに対する指数関数的手法が受け入れられることをすぐに示唆していますが、それは慎重に構造化されている場合に限ります。 すべてのサブセットをチェックしてクリークの状態を直接検証する単純なアプローチでは、最大 2^40 のサブセットをチェックする必要がありますが、これは実行不可能です。 

2 段階の最適化について考えると、微妙な問題が生じます。 クリーク サイズを最大化するだけでなく、最大サイズのクリーク間の XOR も最大化します。 最大次数のノードを選択したり、ローカルで XOR を最大化する貪欲なアプローチは失敗します。これは、両方の制約がグローバルであり、相互作用するためです。 

もう 1 つのエッジ ケースは、エッジがない場合、またはグラフが完成している場合です。 空のグラフでは、単一ノードのみが有効なクリークであるため、答えは純粋にシングルトンの中から最大の XOR 要素を選択することに依存します。 完全なグラフでは、すべてのサブセットがクリークであるため、問題は最大のサブセットを選択し、そのサイズのすべてのサブセットに対する XOR を最大化することになりますが、これはまだ自明ではありません。 

## アプローチ

 ブルートフォース手法では、ノードのすべてのサブセットが列挙されます。 各サブセットについて、選択した頂点のすべてのペアを隣接構造に対して検証することで、クリークを形成しているかどうかを確認します。 有効な場合、そのサイズと XOR 値を計算し、値の最適なペアを保持します。 

1 つのサブセットのクリークの妥当性をチェックするには O(n^2) のコストがかかり、サブセットは 2^n 個あるため、合計の複雑さは O(n^2 2^n) になります。 n = 40 では、これは実現可能な限界をはるかに超えています。 

重要な点は、クリーク制約はサブセット内の隣接関係の一貫性に関するものであり、有効性を維持しながらサブセットを段階的に構築すると、処理がはるかに簡単になるということです。 これは、中間者戦略を示唆しています。つまり、グラフを 2 つの半分に分割し、各半分のすべてのサブセットを列挙し、どのサブセットが内部的にクリークであるかを追跡します。 次に、両方の半分の互換性のあるサブセットを結合し、選択した 2 つのサブセット間でクロス エッジが有効であることを確認します。 

これにより、指数爆発が片側あたり 2^40 から約 2^20 に減少し、管理可能になります。 また、サブセットの有効性だけでなく、マージ中に組み合わせることができるクリークのサイズと XOR 値も追跡する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フルサブセットブルートフォース | O(n^2 2^n) | O(2^n) | 遅すぎる |
 | 半分以上の中間でミート | O(2^(n/2) * 2^(n/2)) | O(2^(n/2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点のセットを左と右の 2 つの部分に分割し、それぞれのサイズは最大 20 です。各辺について、すべてのサブセットを列挙し、その辺全体で有効なクリークを形成するサブセットを決定します。 

また、有効なサブセットごとに 2 つの属性 (サイズとノード値の XOR) を計算します。

次に右側では、互換性を前処理します。 すべての有効なサブセットについて、その中の頂点のビットマスクとその内部有効性情報を保存します。 

結合する場合、左側から各有効なサブセット A を考慮し、右側から各有効なサブセット B を考慮します。 A のすべての頂点が B のすべての頂点に接続されている場合、ペアは有効です。隣接関係のビットマスクを使用してこれを効率的にチェックできるため、ペアごとに O(n^2) 個のチェックを行う必要がなくなります。 

互換性のあるペアごとに、結合サイズを |A| として計算します。 + |B| XOR は xor(A) XOR xor(B) となります。 最初にサイズに基づいて、次に XOR に基づいて最良の答えを維持します。 

### なぜ効果があるのか

 元のグラフ内のすべてのクリークは、左半分と右半分との交差部分に一意に分割できます。 これらの各部分はそれ自体がクリークである必要があり、パーティション全体で相互に互換性がある必要があります。 各ハーフ内のすべての有効なクリークを列挙し、互換性のあるペアのみを結合するため、すべてのグローバル クリークは有効なハーフ クリークのペアとして 1 回だけ表されます。 これにより、有効な候補が見逃されることはなく、無効な候補はすべてマージ段階で除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        adj = [0] * n
        for i in range(n):
            adj[i] = (1 << n) - 1  # start fully connected
        
        # remove non-edges
        for i in range(n):
            adj[i] ^= (1 << i)
        
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u] |= (1 << v)
            adj[v] |= (1 << u)

        # actually we want adjacency as bitmask of edges
        # but input gives friendship edges; clique requires full connectivity,
        # so we build complement-style validity check

        # recompute correct adjacency: we track allowed edges
        ok = [[False] * n for _ in range(n)]
        for i in range(n):
            ok[i][i] = True
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            ok[u][v] = ok[v][u] = True

        # half split
        n1 = n // 2
        n2 = n - n1

        left_ids = list(range(n1))
        right_ids = list(range(n1, n))

        def is_clique(sub, ids):
            for i in range(len(sub)):
                for j in range(i + 1, len(sub)):
                    if not ok[ids[sub[i]]][ids[sub[j]]]:
                        return False
            return True

        left_states = []
        for mask in range(1 << n1):
            nodes = [i for i in range(n1) if mask >> i & 1]
            if is_clique(nodes, left_ids):
                x = 0
                val = 0
                for i in nodes:
                    val ^= a[left_ids[i]]
                left_states.append((nodes, val))

        right_states = []
        for mask in range(1 << n2):
            nodes = [i for i in range(n2) if mask >> i & 1]
            if is_clique(nodes, right_ids):
                x = 0
                val = 0
                for i in nodes:
                    val ^= a[right_ids[i]]
                right_states.append((nodes, val))

        best_size = 0
        best_xor = 0

        for l_nodes, l_xor in left_states:
            for r_nodes, r_xor in right_states:
                valid = True
                for i in l_nodes:
                    for j in r_nodes:
                        if not ok[left_ids[i]][right_ids[j]]:
                            valid = False
                            break
                    if not valid:
                        break
                if not valid:
                    continue
                sz = len(l_nodes) + len(r_nodes)
                xr = l_xor ^ r_xor
                if sz > best_size or (sz == best_size and xr > best_xor):
                    best_size = sz
                    best_xor = xr

        print(best_size, best_xor)

if __name__ == "__main__":
    solve()
```実装は分割と列挙の構造に従います。 隣接行列は、クリーク チェックの正確性のために直接使用されます。 左半分と右半分は独立して列挙され、有効な内部クリークのみが保存されます。 マージ中に、2 つのサブセット間のすべてのペアをチェックすることにより、相互互換性が強制されます。 

サブセットをリストとして明示的に保存するという決定により、ロジックは簡単になりますが、最適ではありません。 より効率的なバージョンでは、サブセットをビットマスクとしてエンコードし、入れ子になったループを回避するために互換性マスクを事前計算します。 

## 実用的な例

 4 つのノードがそれぞれ 2 つのノードの 2 つの半分に分割された小さなグラフを考えてみましょう。 ノード 0 とノード 3 の間に 1 つの欠落エッジを除いてすべてのエッジが存在し、値が任意の小さい整数であると仮定します。 

左半分では、すべてのサブセットが有効なクリークです。 右半分では、欠落しているエッジの両方の端点を含まないサブセットのみが有効です。 

| ステップ | 左のサブセット | 右のサブセット | 有効なクロスエッジ | サイズ | XOR |
 | --- | --- | --- | --- | --- | --- |
 | 1 | {} | {} | はい | 0 | 0 |
 | 2 | {0} | {2} | はい | 2 | a0 XOR a2 |
 | 3 | {0,1} | {2} | はい | 3 | a0 XOR a1 XOR a2 |
 | 4 | {0,1} | {2,3} | いいえ | - | - |

 このトレースは、相互検証ステップによって、2 つの有効な内部クリークを結合することによって形成される無効なクリークをどのように除去するかを示しています。 

次に、サイズ 3 の完全なグラフを考えます。すべてのサブセットが有効であるため、アルゴリズムはフルセットのすべてのパーティションを効果的に評価します。 最適なサイズは 3 で、すべての完全なサブセットの中で、XOR はセット全体で最大化されます。 

| ステップ | 左のサブセット | 右のサブセット | サイズ | XOR |
 | --- | --- | --- | --- | --- |
 | 1 | {0} | {1,2} | 3 | a0 XOR a1 XOR a2 |
 | 2 | {0,1} | {2} | 3 | a0 XOR a1 XOR a2 |

 どちらの分解でも有効な完全なクリークが生成され、アルゴリズムは同等の最大サイズの構造間で XOR 値を正しく比較します。

 ## 特殊なケース

 友情エッジがない場合、すべてのクリークは単一の頂点になります。 各半分はシングルトンのサブセットのみを受け入れ、ほとんどの組み合わせでは片側が空であるためクロスチェックが簡単であるため、アルゴリズムは引き続き機能します。 

グラフが完成すると、すべてのサブセットが内部および半分全体で有効になります。 このアルゴリズムは、左と右のサブセットのすべての組み合わせを列挙し、最大サイズは常に n です。 XOR の最大化は、すべてのフルサイズの選択範囲で正しく処理されます。 

k = 0 の場合、すべての値はゼロになるため、XOR は常にゼロになります。 このアルゴリズムは純粋にクリーク サイズを最大化するものであり、半分の列挙によって解決される標準の最大クリーク問題となり、XOR タイブレークは正確さに影響しません。
