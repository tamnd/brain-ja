 ## 解決策
 ## 問題の理解

 入力は、7 ゲームの卓球試合の最終結果を記述します。 プレーヤー 1 が得点しました`P1`合計ポイント、プレーヤー 2 の得点`P2`合計ポイントが表示され、どのプレイヤーが試合に勝ったかが分かります。 課題は、これらの合計を生み出した可能性のあるゲームのシーケンスを 1 つ再構築することです。 

スコアが 10:10 に達した場合を除き、1 つのゲームは 11 ポイントに到達すると勝利となります。 そこからは勝者が2点リードする必要があるため、12:10や15:13といったスコアも考えられます。 この試合は 7 試合先取方式で行われます。つまり、最初に 4 試合勝ったプレイヤーが試合全体の勝利となります。 

合計は小さく、各プレイヤーの得点は最大でも 1000 ポイントです。 これにより、考えられるすべてのゲーム順序や 7 つのゲーム間でのポイントの配分をすべて試行するアプローチは除外されます。 考えられる合計ポイントの検索スペースは依然として十分に大きいため、ゲームが 7 つしかなく、各ゲームの正当なスコアのセットが非常に制限されているという事実を利用する必要があります。 

厄介なケースは通常、すべてのゲームが 11 ポイントで終了すると仮定することによって引き起こされます。 たとえば、入力```
12 10 1
```正しい出力がある```
1 0
12 10
```11:0 ～ 11:10 のゲーム スコアのみを受け入れるソリューションでは、誤って拒否されてしまいます。 

もう 1 つのエッジケースは、1 人のプレイヤーがポイントを持っていない場合です。 のために```
45 0 1
```答えは`-1`。 プレーヤー 1 は 4 つのゲームに勝つ必要があり、スコアが 0 のプレーヤーとの各ゲームは 11 対 0 でなければならず、44 ポイントしか与えられません。 追加点はどこにも置くことはできません。 

3 番目のケースは、7 試合前に試合が終了した場合です。 例えば、```
44 0 1
```可能です:```
4 0
11 0
11 0
11 0
11 0
```常に 7 つのゲームを作成する不用意な実装は失敗します。誰かが 4 つのゲームに勝つとすぐに試合が停止するためです。 

## アプローチ

 直接的なアプローチでは、合計ポイントを最大 7 つのゲームに分割しようとします。 すべてのゲームについて、正当なスコアを選択し、試合の勝者が 4 回勝利するまで再帰的に続行することができます。 すべての有効な一致はまさにそのようなシーケンスであるため、これは正しいです。 問題は、可能なポイント配布の数が急速に増加することです。 卓球の仕組みを使わずに、考えられるすべてのゲームスコアを試すと、大きな分岐要素が生まれます。 

有益な観察は、ゲームが 7 つしかなく、単純なルールからゲームのスコアを生成できることです。 試合全体を一度に推測する必要はありません。 残りポイントと現在のゲームスコアだけを記憶しながら、ゲームごとに構築できます。 どちらかのプレイヤーが勝ったゲーム数は最大 4 であるため、状態は小さくなります。 

メモ化された深さ優先探索による動的プログラミングは、まさにこれを実現します。 すべての州で、次の試合は合法的に試みられます。 選択によって試合を終了できない状態になった場合、その選択は破棄されます。 必要なゲーム勝利数に達すると、試合はすでに終了しているため、残りのポイントはゼロでなければなりません。 

ブルート フォース検索は、残っている同じ状況を繰り返し探索するため、失敗します。 メモ化によりその繰り返しが削除され、構築が可能な一致状態に対する限定された検索に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | ゲーム数の指数関数的増加 | お(7) | 遅すぎる |
 | 最適なDP検索 | O(到達可能な状態の数 × 可能なゲームスコア) | O(到達可能な状態の数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要なゲーム勝利数を決定します。 試合の勝者は 4 回のゲーム勝利を達成する必要がありますが、他のプレイヤーは最大 3 回の勝利を得ることができます。 
2. 両方のプレーヤーの残りのポイントと各プレーヤーがすでに勝ったゲーム数を状態に保存する再帰関数を使用します。 
3. 残りのポイントを使用してプレイできるすべての合法的な次のゲームを生成します。 プレーヤーは、11 対 10 以下の場合、または両方のプレーヤーが少なくとも 10 点に達した後に 2 点リードでゲームに勝ちます。 
4. 選択したゲームのポイントを減算し、ゲームの勝利数を更新します。 新しい状態から検索を続けます。 
5. プレイヤーが 4 勝したとき、ポイントが残っていない場合にのみその状態を受け入れます。 保存されたゲームのシーケンスは必要な構造です。 

機能する理由: すべての有効な一致は、最初の試合と残りの試合に分割できます。 再帰的遷移では、最初のゲームに対してあらゆる法的な可能性が試されるため、有効な構造を見逃すことはできません。 メモ化は同一の状態の繰り返しを回避するだけであり、受け入れられたすべての状態は正確なポイント合計と一致ルールを満たします。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def build_game_options(a, b):
    res = []

    for x in range(11, a + 1):
        for y in range(0, min(b, 10) + 1):
            res.append((x, y, 1))

    for x in range(10, a + 1):
        y = x + 2
        if y <= b:
            res.append((x, y, 2))

    for y in range(11, b + 1):
        for x in range(0, min(a, 10) + 1):
            res.append((x, y, 2))

    for y in range(10, b + 1):
        x = y + 2
        if x <= a:
            res.append((x, y, 1))

    return res

def solve_case(p1, p2, winner):
    need1 = 4 if winner == 1 else 0
    need2 = 4 if winner == 2 else 0

    options_cache = {}

    def get_options(a, b):
        key = (a, b)
        if key not in options_cache:
            options_cache[key] = build_game_options(a, b)
        return options_cache[key]

    parent = {}

    @lru_cache(None)
    def dfs(a, b, w1, w2):
        if w1 == 4 or w2 == 4:
            return a == 0 and b == 0

        if w1 + w2 >= 7:
            return False

        for x, y, who in get_options(a, b):
            nw1 = w1 + (who == 1)
            nw2 = w2 + (who == 2)

            if nw1 > need1 and winner == 1:
                continue
            if nw2 > need2 and winner == 2:
                continue
            if nw1 >= 4 and winner == 2:
                continue
            if nw2 >= 4 and winner == 1:
                continue

            if dfs(a - x, b - y, nw1, nw2):
                parent[(a, b, w1, w2)] = (x, y, who)
                return True

        return False

    if not dfs(p1, p2, 0, 0):
        return None

    games = []
    state = (p1, p2, 0, 0)

    while state in parent:
        x, y, who = parent[state]
        games.append((x, y))
        state = (
            state[0] - x,
            state[1] - y,
            state[2] + (who == 1),
            state[3] + (who == 2),
        )

    return games

def main():
    p1, p2, w = map(int, input().split())

    ans = solve_case(p1, p2, w)

    if ans is None:
        print(-1)
        return

    g1 = sum(x > y for x, y in ans)
    g2 = len(ans) - g1

    print(g1, g2)
    for x, y in ans:
        print(x, y)

if __name__ == "__main__":
    main()
```この解決策は、残りの合計ポイント内に収まるすべての正当なゲーム スコアを生成することから始まります。 この世代では、デュース前に終了する通常のゲームと、2 ポイントのアドバンテージを必要とする延長ゲームの 2 つのケースを個別に処理します。 

再帰関数は、将来の選択に影響を与える情報のみを保存します。 残りポイントと勝利数がわかれば、前の試合の順番は関係なくなるので、メモ化は有効です。 

の`parent`ディクショナリは、再帰内に完全なシーケンスを保存するのではなく、成功した遷移を記録します。 これにより、メモリの使用量が少なくなります。 再構築は単に開始状態から後退するだけです。 

の境界条件は、`build_game_options`間違いが起こる主な場所です。 11:10 のようなスコアは有効ですが、10:11 は間違った勝者ブランチによって生成された完全なゲームではありません。 デュースゲームは10:10から始まり、2点差を保ったまま双方のスコアを伸ばします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S × G) | S is the number of reachable DP states and G is the number of legal game scores considered from a state |
 | スペース | O(S) | The memo table and parent reconstruction store each visited state once |

 The maximum score totals are only 1000 and the match length is capped at seven games, so the number of meaningful states stays manageable. The search avoids exploring arbitrary length sequences and fits comfortably within the constraints.

 ## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline().split()
    p1, p2, w = map(int, data)

    ans = solve_case(p1, p2, w)
    if ans is None:
        out = "-1\n"
    else:
        g1 = sum(x > y for x, y in ans)
        out = f"{g1} {len(ans)-g1}\n"
        for x, y in ans:
            out += f"{x} {y}\n"

    sys.stdin = old
    return out

 ## 特殊なケース

 のために`12 10 1`、アルゴリズムは拡張ゲームを生成します`(12, 10)`なぜなら、両プレイヤーが 10 ポイントを超えた後、勝者には 2 ポイントのアドバンテージがあるからです。 これらのポイントが減算され、残りの合計がゼロになった後でのみ最終状態に到達します。 

のために`45 0 1`、可能なすべてのゲームでプレイヤー 2 に 0 ポイントを与える必要があります。 唯一合法なゲームスコアは、`11:0`, したがって、4 勝すると 44 ポイントが消費されます。 残ったポイントを終了した一致に割り当てることはできないため、再帰状態が失敗します。 

4 試合で終了する試合の場合、次のように`44 0 1`、アルゴリズムは 4 回目の勝利の直後に停止します。 最終条件では勝者が 4 つのゲームを持ち、すべてのポイントがすでに使用されている必要があるため、人為的なゼロ長ゲームは追加されません。
