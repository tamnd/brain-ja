 ## 解決策
 ## 問題の理解

 この問題では、非常に特殊な意味でバランスの取れたバイナリ ツリーのコレクションを構築することが求められます。 空ではないツリーは 2 つの子ポインターで表されます。 リーフは子のない木であり、1 枚のリーフを提供するため、そのサイズは 1 です。 1 つおきのツリーのサイズは、その 2 つの子のサイズの合計と同じになります。 

2 つの子サブツリーのサイズが等しいか、左側のサブツリーが右側のサブツリーよりちょうど 1 葉大きい場合、ツリーは有効です。 指定されたターゲット数の葉について、そのうちの 1 つにちょうど同じ数の葉が含まれるように、再利用可能な木の小さなセットを出力する必要があります。 出力は最終的なツリー自体ではなく、作成されたすべてのツリーが以前に作成されたツリーを参照できるメモリ表現です。 

目標値は次のように大きくできます。$10^{18}$なので、ツリー全体を構築することは不可能です。 これほど多くの葉を持つ通常のバランスの取れた二分木には、おおよそ次のものが含まれます。$10^{18}$ノード。 作成されるツリーの数が 125 のみという制限は、目的のソリューションでは同一のサブツリーを再利用し、完全なツリーではなく有向非巡回グラフを構築する必要があることを示しています。 

重要な観察は、ツリーを分割するたびに、サイズが元の値の約半分になるということです。 の値$10^{18}$約 60 回の分割後に 1 に達するため、再帰的構造の深さは非常に浅くなります。 課題は深さではなく、サブツリーが出現するたびに個別のオブジェクトを作成しないようにすることです。 

不注意に実装すると、同じサブツリーを複数回構築すると失敗する可能性があります。 たとえば、両方の子を独立して拡張してターゲット値 16 を構築すると、サイズ 8 のツリーのコピーが 2 つ作成され、次にサイズ 4 のコピーが 4 つ作成され、ノードの数は指数関数的に増加します。 正しい出力には、各サイズの表現が 1 つだけ必要です。 入力値 16 の場合、1 つの有効な出力は、サイズ 16 のツリーの両方の子に対して同じインデックスを再利用できます。 

もう 1 つのエッジ ケースは、可能な限り最小のターゲットです。 入力の場合:```
1
```正しい構造は 1 つの葉だけです。```
1
-1 -1
0
```すべてのツリーに 2 つの子ツリーがあると想定するソリューションでは、存在しないノードを誤って参照しようとします。 

2 番目のエッジ ケースは、リーフの数が奇数であることです。 入力の場合:```
5
```ルートはサイズ 3 と 2 に分割する必要があります。サイズ 3 のツリーは 2 と 1 に分割する必要があります。構築では、左側が右側より小さくならないことを考慮する必要があります。 2 と 3 のような分割は、数学的には有効なバランスの取れた二分木を表しますが、子のサイズに必要な順序に違反します。 

## アプローチ

 直接的なアプローチは、バランスのとれたツリー全体を明示的に構築することです。 必要な数の葉から始めて、それを 2 つの半分に分割し、再帰的に左右のサブツリーを構築し、それらを接続します。 これが機能するのは、2 つのサブツリー サイズを現在のサイズの半分の天井と床として選択すると、常にバランス条件が満たされるためです。 

問題は、葉の数が最終的なツリー内のオブジェクトの数になることです。 答えが必要な場合$N$葉、明示的なツリーには$O(N)$ノード。 と$N$到達$10^{18}$、答えを保存することさえ不可能です。 

重要な点は、出力形式により共有が可能であるということです。 サイズ 1000 のツリーには、表示されるたびにサイズ 500 のツリーの新しいコピーを含める必要はありません。 すでに作成されている同じツリーを指すことができます。 バランスのとれた分割は現在のサイズにのみ依存するため、すべてのサイズには 1 つの自然な表現が存在します。 サイズ別に構造をメモできます。 

再帰的分割によって正しいツリーが作成されるため、ブルート フォースは機能しますが、同一のサブツリーが繰り返されるため失敗します。 状態は葉の数だけであるという観察により、構造全体を、2 つの半分を繰り返し取得することによって生成されるすべての個別の値を見つけることに縮小できます。 

サイズ違いの数は少ないです。 再帰呼び出しごとにサイズが約半分に減少するため、最大でも約 60 レベルになります。 各レベルは最大 2 つの異なる値を提供でき、許容される 125 ツリーよりもはるかに少ない値を提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N) | O(N) | 遅すぎる |
 | 最適 | O(log N) | O(log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 目標葉数から始めます。 1 の場合、次のように表される単一のリーフ ノードを作成します。`(-1, -1)`。 リーフはすでに有効なバランスの取れたツリーであるため、これが唯一の基本ケースです。 
2. サイズについて`x`1 より大きい場合は、次のように分割します`left = (x + 1) / 2`そして`right = x / 2`。 サイズが奇数で、有効なツリーの定義と一致する場合、左側は追加のリーフを受け取ります。 
3. の表現を再帰的に構築します。`left`そして`right`。 新しいツリーを作成する前に、このサイズがすでに構築されているかどうかを確認してください。 存在する場合は、そのインデックスを再利用します。 サブツリーの状態は、その葉の数によって完全に説明されます。 
4. 子インデックスのペアを現在のサイズの表現として保存します。 この表現に割り当てられたインデックスは、後で大きなツリーで使用できます。 
5. ターゲット サイズを構築した後、作成されたすべてのツリーとターゲット ツリーのインデックスを出力します。 

なぜ効果があるのか:

 あらゆる施工サイズに対応`x`、アルゴリズムはサイズを持つ子を作成します`ceil(x/2)`そして`floor(x/2)`。 これら 2 つの値の違いは最大で 1 つであり、大きい方が常に左側に配置されるため、作成されたすべてのツリーはバランス ルールを満たします。 より大きなサイズは、より小さなすでに有効なサイズにのみ接続されるため、正確性はリーフの場合から再帰的に続きます。 

共有しても、表現されるツリー構造は変更されません。 すべての参照は依然として、必要な数の葉を持つ有効なサブツリーを指します。 メモ化は重複した定義の印刷を回避するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    memo = {}
    nodes = []

    def build(x):
        if x in memo:
            return memo[x]

        if x == 1:
            idx = len(nodes)
            nodes.append((-1, -1))
            memo[x] = idx
            return idx

        left_size = (x + 1) // 2
        right_size = x // 2

        left = build(left_size)
        right = build(right_size)

        idx = len(nodes)
        nodes.append((left, right))
        memo[x] = idx
        return idx

    root = build(n)

    out = []
    out.append(str(len(nodes)))
    for a, b in nodes:
        out.append(f"{a} {b}")
    out.append(str(root))

    print("\n".join(out))

t = int(input())
for _ in range(t):
    solve()
```の`memo`ディクショナリには、リーフ数から構築されたツリーのインデックスへのマッピングが格納されます。 これが中心的な最適化です。 これがないと、再帰によって同じ半分が繰り返し再構築されてしまいます。 

基本ケースでは、次を使用してリーフ表現を挿入します。`-1`両方の子供にとって。 他の呼び出しでは、最初に小さなツリーが作成され、次にそれらの既存のインデックスを指す新しいノードが追加されます。 

分割では整数演算が慎重に使用されます。`(x + 1) // 2`天井は半分で、`x // 2`床半分です。 これにより、左の子は少なくとも右の子と同じ大きさに保たれます。 

生成されるサイズはターゲットを繰り返し半分にする間に発生する値のみであるため、生成されるノードの数は少ないままです。 最大の入力であっても、一意の状態の数は 125 をはるかに下回ります。 

## 実用的な例

 ターゲットサイズ 5 を考えてみましょう。 

| 現在のサイズ | 左のサイズ | 適切なサイズ | アクション |
 | --- | --- | --- | --- |
 | 5 | 3 | 2 | サイズ 5 のツリーを作成する |
 | 3 | 2 | 1 | サイズ 3 のツリーを作成する |
 | 2 | 1 | 1 | サイズ 2 のツリーを作成する |
 | 1 | - | - | リーフを作成する |

 構築されたサイズ 5 のツリーは、すでに作成されているサイズ 3 およびサイズ 2 のツリーを使用します。 このトレースは、再帰的な分割ごとに値が減少し、重複するサブツリーが必要ないことを示しています。 

ターゲット サイズ 8 の場合、プロセスは次のようになります。 

| 現在のサイズ | 左のサイズ | 適切なサイズ | 再利用? |
 | --- | --- | --- | --- |
 | 8 | 4 | 4 | いいえ |
 | 4 | 2 | 2 | いいえ |
 | 2 | 1 | 1 | いいえ |
 | 1 | - | - | いいえ |

 それぞれの偶数サイズのツリーの 2 つの子は、同じインデックスを指します。 これは、出力を小さく保つ共有を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 最小の場合`N = 1`の場合、アルゴリズムは直ちにリーフ ノードを返します。 子インデックスは必要ないため、出力は有効です。 

次のような奇数の値の場合`N = 5`、ルートはサイズ 3 と 2 の子で作成されます。サイズ 3 のツリーは子 2 と 1 で作成されます。各分割では大きい部分が左側に保持されるため、順序付けの要件は満たされます。 

次のような大きな値の場合、`N = 10^18`、再帰は決して作成しようとしません$10^{18}$ノード。 半分にすることによって生成される異なるサイズのチェーンを作成するだけです。 最終的な構造は、巨大な拡張ツリーではなく、再利用可能なバランスのとれたツリーの小さなグラフです。
