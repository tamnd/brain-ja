 ## 問題の理解

 長さが 2 の累乗である配列が与えられており、最初は 1 から 1 までのすべての整数が含まれています。$2^k$まさに一度。 したがって、配列は単なる順列ですが、最初の順序が重要です。 

ゲームはこのアレイ上でプレイされます。 パラメータ$t$が最初に修正されます。 その後、ゲームは正確に進みます$t$ラウンドします。 各ラウンドで、アリスは任意の 2 つの位置を交換するか、何もしないことが許可され、その後ボブは現在の配列のちょうど半分 (左半分または右半分) を削除します。 この縮小は、残りの配列が常に隣接するもう一方の半分であるという意味で、常に対称的です。 

結局$t$ラウンド、長さは 1 つのセグメントのみ$2^{k-t}$残り、スコアはこの最後のセグメント内の最大値になります。 アリスはこの最終最大値をできるだけ大きくしようとしますが、ボブはそれをできるだけ小さくしようとします。 

このゲームの最終的な価値を、あらゆる可能性について計算する必要があります。$t$1から$k$、双方からの最適なプレーを想定しています。 

主な難点は、アリスは要素をグローバルに再配置できるが、ボブが構造の半分を破壊するまではラウンドごとに 1 回だけであることです。 一方、ボブは要素を直接選択するのではなく、縮小するセグメントのどの半分が生き残るかを選択し、実質的に二分分解ツリー内のパスを選択します。 

制約が意味するのは、$k \le 20$したがって、配列のサイズは最大でも約 100 万です。 すべてのテスト ケースにわたって、配列の合計サイズは次の制限を受けます。$2^{20}$、つまり、大まかに言うとどんな解決策でも$O(n \log n)$または$O(nk)$二次関数は何でも受け入れられますが、$n$不可能です。 

アリスとボブの選択の分岐が指数関数的なゲーム ツリーにつながるため、ゲームの単純なシミュレーションは実現できません。アリスの交換とボブの半分の選択により、巨大な状態空間が作成されます。 アリスの戦略を修正するにも、ボブは$2^t$削除の可能性のある順序があり、アリスはラウンドごとに反応する可能性があるため、直接検索は不可能になります。 

配列が既に昇順にソートされている場合と、高度にシャッフルされている場合には、微妙なエッジ ケースが発生します。 素朴な直観は、半分の内部の相対的な順序のみが重要であると示唆するかもしれませんが、アリスは削除前に値を半分にまたがって移動させることができます。これは、初期の局所性が安定していないことを意味します。 たとえば、ボブがすぐに削除できるセグメントに最大値が配置されている場合、アリスは、最初のパーティションだけでなく、考えられるすべての削除にわたってその値が存続することを積極的に確認する必要があります。 

## アプローチ

 ゲームを直接シミュレートしようとすると、現在の配列を維持し、アリスの交換とボブの削除を再帰的に試行することになります。 アリスを「役立つ場合にのみスワップを使用する」ように制限したとしても、分岐係数は依然として大きすぎます。 各ラウンドは依然としてボブの 2 つの可能性に分岐し、アリスは$O(n^2)$選択肢を交換します。 以上$k \le 20$ラウンドが終わると、これは完全に不可能になります。 

構造的な洞察は、視点を逆転させることで得られます。ボブは半分を恣意的に削除しているだけではなく、深さの完全なバイナリ パーティション ツリー内のパスを選択しています。$k$。 後$t$ラウンド、深さはちょうど 1 つのノード$t$生き残るセグメントを決定します。 したがって、ボブは効果的に次のいずれかを選択します。$2^t$同じサイズのセグメント。 

アリスの力を再解釈してみましょう。 彼女は配列を任意に並べ替えることができます。$t$ただし、各順列の後に、各レベルで半分が強制的に選択されます。 スワップはグローバルであるため、アリスはボブの各決定の前に、制御された方法で現在のセグメント全体に値を確実に分配できます。 

重要な単純化は、時間を逆転させることです。 繰り返し縮小することを考える代わりに、最終セグメントを逆方向に構築することを考えます。ボブはバイナリ ツリー内のパスを選択し、アリスは選択したパスに大きな値が含まれていることを確認しようとします。 アリスは各カットの前に自由に再配置できるため、各深度のどのサブツリーにどの値が表示されるかを効果的に決定できますが、限られた数の「再配置ラウンド」のみで済みます。 

これにより、問題は階層化された課題に変わります。$t$、 がある$2^t$セグメント、それぞれのサイズ$2^{k-t}$。 ボブは 1 つのセグメントを選択します。 アリスは、値をレイヤー間で段階的に再配分できることを前提として、すべてのセグメントにわたって可能な最小値を最大化したいと考えています。 

重要な点は、値の位置ではなく、値の順序のみが重要であるということです。 各レベルで、ボブはブロックのペアの中から選択を強制するため、ゲームはペアの最小値を繰り返し取るように動作しますが、アリスはスワップの自由がまだある限り、すべての「危険な」ブランチに大きな値を注入しようとします。 

これは貪欲な視点につながります。つまり、値を並べ替えた後、アリスがレベル​​全体でいくつの値を「保護」できるかを検討します。 深さで$t$, ボブは事実上、答えがコレクション内の最大値に依存するように強制します。$2^t$代表候補者はいるが、アリスなら確実にトップになれるだろう$t$最大値は、枝刈りシーケンスごとに少なくとも 1 つが残るように分散されます。 

それを確認するためのより具体的な方法は次のとおりです。$t$ラウンド、ボブはパスを選択しました$t$二者択一。 各値は、アリスがそのパスに沿って関連するすべての半分にルーティングできた場合にのみ存続します。 最適な戦略は、実行可能性を維持できる最高値の数を追跡することになります。$t$敵対的なカット。 それぞれの答えは$t$になります$(2^k - (2^k - 2^t + 1))$この保護プロセスの下での次数の統計。これにより、少なくとも 1 つの生き残ったセグメントで保証できる最良の値の選択が簡素化されます。 

これは、古典的な「完全なツリー上のバイナリ パーティション DP」に分解されます。各レベルで候補の数が半分になり、深さごとに可能な限り最高の保証値が維持されます。

 ## アルゴリズムのチュートリアル

 配列を高さの完全なバイナリ ツリーに埋め込まれているものとして再解釈します。$k$ここで、各リーフは値であり、各内部ノードはセグメントを表します。 各レベルは、隣接するセグメントをより大きなセグメントにグループ化します。 

1. レベル 0 が個々の要素で構成され、次のレベルごとにセグメントのペアがマージされる構造を構築します。 各セグメントはその最大値を追跡します。 これは、アリスが何もしなかった場合にボブが生き残るために強制できることを反映しています。 
2. レベル 1 では、隣接する要素のすべてのペアの最大値を計算します。 これにより、サイズ 2 の各セグメントで可能な限り最高の値が得られます。これが機能する理由は、1 回のカットの後、2 つの半分のうちの 1 つだけが残るため、ペアごとの最大値のみが問題となるためです。 
3. 上方向にマージを続けます: レベルで$i$、各セグメントは次のサイズのブロックを表します。$2^i$、その値は、そのブロックだけが後に残った場合に存続できる最大値です。$i$削除。 
4. ただし、アリスのスワップにより、各削除の前にブロック間で値を再分配できるため、生のセグメントの最大値だけを取得するわけではありません。 代わりに、アリスが強制できる最良の保証をシミュレートします。つまり、各レベルで、ボブがすべての候補を同時に排除できないように、上位に残った候補がセグメント全体に分散していることを保証できます。 
5. マルチセットのようなプロセスを維持します。すべての値を降順でソートすることから始めます。 のために$t$ラウンドで、アリスは最大まで「守る」ことができます$2^t$ボブのパス選択によって値が同時に削除されないようにします。 
6. それぞれに$t$、答えはそのうちの最大値になります。$2^t$- 番目に強い保証された生存者。これは、$2^t$- 後に存在する可能性のあるすべてのサブツリーに埋め込むことができる 2 番目に大きい値$t$分割します。 
7.全員の回答を出力する$t = 1 \dots k$。 

### なぜ効果があるのか

 重要な不変条件は、次のとおりです。$t$ラウンドで、ボブの選択により配列が分割されます。$2^t$深さによって決定される互いに素なセグメント -$t$二分決定パス。 アリスのスワップにより、カット間のセグメント間の値を再配置できますが、そのレベルでセグメントに値が割り当てられると、ボブの最終的なパスの選択に影響を与えることはできません。 

したがって、ゲームはカバレッジの問題になります。アリスは、ボブがどのパスを選択しても、選択したセグメント内に少なくとも 1 つの十分に大きな値が残るように、セグメント全体に大きな値を割り当てる必要があります。 各レベルではセグメントの数が 2 倍になるため、アリスが確実に「拡散」できる値の数も、次のように指数関数的に増加します。$t$。 深さとカバレッジの間のこの指数関数的な一致こそが、答えが次の要素のみに依存する理由です。$2^t$完全な順列ダイナミクスではなく、最大の構造的保証。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    tcs = int(input())
    for _ in range(tcs):
        k = int(input())
        n = 1 << k
        a = list(map(int, input().split()))

        # Sort values descending: we care about how many large values can be "protected"
        a.sort(reverse=True)

        # We maintain that after t rounds, Alice can effectively protect 2^t values
        # from being simultaneously eliminated along any Bob path.
        #
        # The answer becomes the (2^t)-th largest value in this protected ordering.
        # Since array is permutation, we directly index.

        # prefix max idea is not enough; we use direct indexing over sorted values
        # mapping protection capacity to reachable rank.

        for i in range(1, k + 1):
            protect = 1 << i
            # Bob can force all but one of each protected group to be eliminated along a path,
            # so the effective guaranteed rank is shifted by (protect - 1)
            idx = protect - 1
            if idx >= n:
                idx = n - 1
            print(a[idx], end=' ')
        print()

if __name__ == "__main__":
    solve()
```解決策は、配列を降順に並べ替えることから始まります。これは、どの値が敵対的な枝刈りにも耐えられるかを推論するときに重要なのは相対的な大きさだけであるためです。 ラウンドごとにボブが識別できるセグメントの数が 2 倍になり、アリスのスワッピング能力により、上位の値をそれらのセグメント全体に効果的に分散できます。 

ループオーバー$i$深さの増加に直接対応します。 それぞれについて$i$、アリスが制御できるポジションの数を計算します。$2^i$そして、それをソートされた配列のインデックスにマッピングします。 選択されたインデックスは、ボブができるだけ多くの大きな値を含むセグメントを一貫して削除するという最悪の場合の枝刈りを反映しています。 

重要な点は、スワップや削除を明示的にシミュレートしないことです。 代わりに、ボブの分岐力の指数関数的な成長によって引き起こされるランクベースの選択問題にゲームを崩壊させます。
