 ## 問題の理解

 順列を構築するように求められます`q`サイズの`n`の反転の合計が`q`そして構成`q ∘ p`指定されたターゲットに等しい`k`。 入力の順列`p`は固定されており、反転は順序が狂っているインデックスのペアの数をカウントします。 構成`q ∘ p`新しい順列の i 番目の要素が`q[p_i]`、効果的に並べ替えます`q`によると`p`。 

課題は規模にあります。`n`300,000 に達する可能性があり、最大 10,000 のテスト ケースが存在する可能性がありますが、すべての合計は`n`テスト ケース全体の上限は 300,000 です。 線形計算よりも時間計算量が劣るあらゆる解法`n`テストケースごとにタイムアウトになる可能性があります。 すべての順列に対する総当たり検索`q`明らかに実行不可能なので、`n!`たとえ小さくても天文学的に成長する`n`。 同様に、反転を繰り返しカウントするためにすべてのペアを反復処理すると O(n²) かかり、遅すぎます。 

微妙なエッジケースが発生する場合`k`可能な最小反転合計よりも小さい。これは、両方の場合に発生します。`q`そして`q ∘ p`ほぼ整理されています。 たとえば、`n = 3`そして`p = [3, 2, 1]`を選択した場合、最小合計は 0 です。`q = [1, 2, 3]`。 もう 1 つのエッジケースは次のような場合です`k`は、達成可能な最大反転数よりも大きいです。これは、次の最大反転数の合計です。`q`そしてのために`q ∘ p`。 不注意なアプローチは、`q`境界をチェックせずに貪欲に実行すると、無効な順列が返されるか、解が存在しないというミスが返されます。 

## アプローチ

 ブルートフォースアプローチでは、すべてが試行されます`n!`の順列`q`、両方を計算します`inv(q)`そして`inv(q ∘ p)`、合計が等しいかどうかを確認します`k`。 これは論理的には正しいですが、`n = 10`の場合、3,628,800 個の順列を評価する必要があります。 明らかにこれは不可能になります`n`300,000まで。 

重要な観察は、選択した場合に反転数を直接制御できるということです。`q`完全にソートされるか、完全に反転されます。 並べ替えられた`q`反転はゼロ、反転はありません`q`の最大反転があります`n * (n-1) / 2`。 同じことが当てはまります`q ∘ p`。 逆変換はある意味で加算的であるため、ターゲットをマッピングできます。`k`並べ替えられたセグメントと反転されたセグメントの組み合わせ。 本質的に、私たちは構築することができます`q`を超えずに反転合計を最大化する位置に残りの最大の数字を貪欲に配置します。`k`。 の構造`p`両方を制御するためにどの位置に高い値を割り当てるかを常に選択できるため、これは妨げられません。`q`そして`q ∘ p`。 

この洞察により、問題を線形時間で解決できるようになります。`n`。 可能な最大反転合計を計算し、次のことを確認します。`k`が達成可能な範囲内にある場合は、塗りつぶします`q`最大の数字から下に向かって、その数字を現在利用可能な左端または右端のどちらの位置に配置するかを各ステップで決定します。`k`。

 ## アルゴリズムのチュートリアル

 1. サイズの順列に対する最大反転合計を計算します。`n`。 単一の順列の最大反転数は次のとおりです。`n*(n-1)/2`。 のために`q ∘ p`、1 から n までの数値の順列はそれを超えることができないため、最大値は同じです。 したがって、世界最大値は`k_max = 2 * n * (n-1)/2 = n*(n-1)`。 
2. もし`k`この最大値を超えるか負の場合、順列がないため「NO」を出力します。`q`条件を満たすことができます。 
3.初期化`q`空のリストとして。 2 つのポインタを維持します。`left`の初めに`q`そして`right`最後に。 から番号を割り当てます`n`まで`1`。 
4. それぞれの数字について`n`まで`1`、どこに配置するかを決めます。 左端の利用可能な位置に配置すると、反転合計は以下を超えることなく増加します。`k`、そこに置きます。 それ以外の場合は、右端の利用可能な位置に配置します。 配置後調整します`k`配置によって寄与された反転の数を差し引くことによって。 インデックスの数値の場合`i`、左側に配置すると、その右側に既に配置された要素の数に等しい反転が寄与します。 
5. すべての数字が配置されるまで続けます。 最後に残ったのは、`k`配置がターゲットの反転合計と正しく一致した場合は、ゼロになるはずです。 
6.「YES」を出力して印刷する`q`。 

不変条件は、各ステップで残りの数値を配置して残りの目標反転合計を達成できることです。 常に最大の残りの数値を反転への寄与を最大化または最小化する位置に配置するため、それを超えることはありません。`k`そして常に問題をより小さなサイズに縮小することができます。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        
        max_inv = n * (n - 1)
        if k > max_inv:
            print("NO")
            continue
        
        q = [0] * n
        left, right = 0, n - 1
        current_num = n
        
        for _ in range(n):
            if k >= current_num - 1:
                q[left] = current_num
                k -= current_num - 1
                left += 1
            else:
                q[right] = current_num
                right -= 1
            current_num -= 1
        
        if k != 0:
            print("NO")
        else:
            print("YES")
            print(" ".join(map(str, q)))

if __name__ == "__main__":
    solve()
```解決策は、テスト ケースの数を読み取ることから始まります。 それぞれの場合において、目標の反転合計が達成可能かどうかをチェックします。 2 ポインター手法を使用すると、残りの必要な反転を追跡しながら、貪欲に数値を配置することができます。 微妙なのは、減算することです`current_num - 1`なぜなら、最大の数値を左端の位置に配置すると、まだ配置されていないすべての小さい数値との反転が生じるからです。 最後に、もし`k`ゼロの場合、順列は目標を満たします。 そうでなければ不可能です。
