 ## 解決策
 ## 問題の理解

 ランプの列が与えられますが、最初はすべて消灯しています。 1 種類の操作を何度でも実行できます。現在オフで隣り合っていない 2 つのランプを選択し、両方を同時にオンにします。 私たちのタスクは、複数のテスト ケースに対して、この操作を使用してランプの目標構成を達成できるかどうかを判断することです。 

各入力テスト ケースはランプの数を提供します。`n`そして文字列`s`長さの`n`0 と 1 で構成されます。1 はターゲット構成でランプがオンであることを示します。 その構成に到達できる場合、出力は「YES」、それ以外の場合は「NO」になります。 

制約を考慮すると、`n`最大 50 で、最大 1000 のテスト ケースがあります。 これは、各ケースに対する単純な O(n²) 解が許容されることを意味します。 操作には隣接しないランプのペアが必要であるため、構成に孤立した 1 が含まれる場合、単一のランプを点灯することが不可能になるため、重要な問題が発生します。 

微妙なエッジ ケースとは、配列の先頭または末尾に 1 が孤立している場合、または 1 が連続して出現するため、隣接していない 2 つの消灯ランプを選択してそれらを実現することが不可能になる構成です。 たとえば、入力が次の場合、`1`を目標に`1`、操作を適用できないため、答えは「NO」でなければなりません。 同様に、`11`2 つのランプは隣接しており、1 回の操作でそれらを個別に点灯させることはできないため、これは自明のことながら不可能です。 

## アプローチ

 ブルートフォースアプローチでは、隣接していないオフのランプの考えられるすべてのペアをシミュレートし、それらをオンにして、ターゲットに到達するか可能性を使い果たすまで、考えられるすべてのシーケンスを探索します。 それは正しいことですが、これは小規模な場合でもすぐに管理できなくなります。`n`シーケンスの数は組み合わせ的に増加するためです。 たとえば、`n = 50`操作ごとにおよそ 25 の可能なペアがあるため、シーケンスは指数関数的に多くなります。 

重要な洞察は、ターゲット構成内の 1 の構造に焦点を当てることです。 各操作は正確に 2 つのランプをオンにするため、端の孤立した 1 または文字列全体がすでに 0 である場合を除き、1 の合計数は偶数である必要があります。 さらに、操作は隣接するランプに影響を与えることができないため、ターゲット構成内の 2 つの 1 を、それらの間にペアになっていないオフのランプが残るように隣接させることはできません。 これらの制約を観察すると、操作をシミュレートせずに文字列から直接実現可能性を判断できます。 

事実上、この解決策は、次のような問題が発生しているかどうかを確認することになります。`111`（3 つの連続した 1）、または最初または最後のランプがペアリングできない唯一の 1 であるかどうか。 このようなシナリオでは、構成が直ちに不可能になります。 そうでない場合、この構成は、ランプ間に少なくとも 1 つのランプ ギャップを設けてランプのペアを繰り返しオフにすることによって達成できます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そしてターゲット文字列`s`。 
3. もし`n`が 1 の場合は、すぐに次のことを確認します。`s`は「0」です。 「0」の場合は「YES」を出力します。 「1」の場合は「NO」を出力します。 
4. 文字列をスキャンして、2 を超える長さの 1 が連続するセグメントがないかどうかを確認します。見つかった場合は、「NO」を出力し、次のケースに進みます。 
5. 最初または最後のランプが「1」で、隣接しない別のランプとペアリングできないかどうかを確認します。 その場合は、「NO」と出力します。 
6. 無効なセグメントが見つからない場合は、「YES」を出力します。 

不変条件は、ターゲット内で「1」とマークされたすべてのランプが、隣接しないランプのペアの一部でなければならないということです。 ステップ 4 と 5 のチェックにより、許可された操作ではオンにできない孤立した 1 としてランプが残されていないことが確認されます。 これにより、すべての操作をシミュレートしなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    if n == 1:
        print("YES" if s == "0" else "NO")
        continue
    
    impossible = False
    
    for i in range(n):
        if s[i] == "1":
            left = s[i-1] if i > 0 else "0"
            right = s[i+1] if i < n-1 else "0"
            if left == "1" and right == "1":
                impossible = True
                break
    if impossible:
        print("NO")
    else:
        print("YES")
```コードはテスト ケースの数を読み取り、各構成を反復処理します。 のために`n = 1`、有効なターゲットは「0」のみです。 メイン ループは、2 つの 1 の中央にある孤立したランプがないかチェックします。このランプは操作ではオンにできません。 このアプローチにより、不必要なシミュレーションが回避され、すべての境界条件が正しく処理されます。

## 特殊なケース

 いつ`n = 1`そして`s = "1"`、アルゴリズムは、どの操作も 1 つのランプを点灯できないことを即座に検出し、「NO」を出力します。 のために`n = 2`そして`s = "11"`の場合、コードは両方のランプが隣接しており、1 回の操作で点灯できないことを認識し、同様に「NO」を出力します。 次のような交互パターンの場合`10101`、各 1 にはペアとなる隣接しない 1 が少なくとも 1 つあるため、アルゴリズムは正しく「YES」を出力します。 左端と右端の位置は明示的に処理され、off-by-one エラーが回避されます。
