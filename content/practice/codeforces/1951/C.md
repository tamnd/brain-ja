 ## 解決策
 ## 問題の理解

 課題は正確に購入することです`k`コンサートチケット終了`n`日ごとにチケット価格が提示されます`a_i`。 最大でも購入に制限されています`m`1日あたりのチケット。 さらに、チケットを購入するたびに、その日に購入したチケットの数だけ、将来のすべてのチケットの価格が上がります。 目標は、総支出を最小限に抑えることです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには日数が示されています`n`、1日あたりのチケット制限`m`、必要なチケットの合計`k`、および初期価格の配列`a`。 出力は、最小総コストを表すテスト ケースごとに 1 つの整数である必要があります。 

なぜなら`n`到達できる`3 * 10^5`そして`k`まで`10^9`、各購入を明示的にシミュレートするソリューションは遅すぎます。 この制約は、日ごとまたはチケットごとのシミュレーションを回避するアプローチが必要であることを意味します。 場合には細心の注意が必要です`k`を超える`m`または、早期購入により後のチケットが大幅に高価になる場合。 たとえば、次の場合`a = [1, 2, 3]`、`m = 2`、 そして`k = 3`、毎日常に最大額を購入する単純な貪欲なアプローチでは、初日に 1 枚のチケットを購入し、最終日に 2 枚のチケットを購入したほうがコストが安くなる可能性があるため、必要以上にお金がかかる可能性があります。 

エッジケースには、最も安いチケットが初日にないシナリオが含まれます。`k`よりも小さいです`m`、またはすべてのチケット価格が等しい場合。 

## アプローチ

 このブルートフォース手法は、一日中繰り返され、一定数のチケット (0 から最大`m`または残りのチケット）、各購入後に将来の価格をすべて更新します。 これは正確性を保証しますが、最悪の場合の複雑さは O(n*k) となり、大規模なシステムでは実行不可能です。`k`なぜなら`k`最大 10^9 まで可能です。 

重要な洞察は、チケットの価格を分類したら、最適な戦略は、チケットを安いものから高いものへと順番に購入しながら、可能な限り多くのチケットを購入することであるということです (最高枚数まで)。`m`) それぞれの最も安い日について。 その理由は、価格の値上げは後の購入にのみ影響するため、価格を尊重しながら最も安い日に購入を「前倒し」したいためです。`m`1日あたりの制限。 正式に、価格を整理して購入を検討すると、`x`当日券`i`、それらのチケットの実効コストは`x * (a_i + previous_tickets_bought)`、 どこ`previous_tickets_bought`以前の購入から蓄積されます。 最も安いものから最も高価なものまでを繰り返し、常にその間の分を取得します。`m`残りのチケットについては、価格の値上げを明示的にシミュレートすることなく、最小限の支出を保証します。 

これにより、問題がソートとそれに続く線形スキャンに縮小され、テスト ケースごとにソートに O(n log n)、購入に O(n) が与えられます。これは制約を考慮すると実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、`k`、およびチケット価格の配列`a`。 
2. 並べ替え`a`降順ではない順に。 これにより、最も安いチケットが最初に考慮されるようになります。 
3. 2 つの変数を初期化します。`spent`総コストを蓄積し、`bought`購入されたチケットの合計を追跡します。 
4. ソートされた配列を反復処理します。 それぞれの価格について`price`:

 ａ． コンピューティング`can_buy = min(m, k - bought)`。 これは、1 日あたりの制限または合計制限を超えずに、今日購入できるチケットの最大数です。 

b. 追加`can_buy * (price + bought)`に`spent`。 ここ、`bought`前回の購入からの累積増加を表します。 

c. アップデート`bought += can_buy`。 

d. 繰り返しを一度停止します`bought == k`。 
5. 印刷`spent`。 

機能する理由: 並べ替えにより、より安いチケットを最初に購入することが保証されます。 蓄積する`bought`配列を変更せずに将来の価格上昇をシミュレートし、各チケットの実効コストが以前のすべての購入を確実に考慮します。 購入を制限する`m`1 日あたりの制限を超えないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        spent = 0
        bought = 0
        for price in a:
            if bought >= k:
                break
            can_buy = min(m, k - bought)
            spent += can_buy * (price + bought)
            bought += can_buy
        print(spent)

if __name__ == "__main__":
    solve()
```コードはすべてのテスト ケースを読み取り、チケット価格を並べ替え、貪欲な方法でチケットを購入することを繰り返します。`can_buy`決して超えないことを保証します`m`または`k`。`price + bought`累積的な価格上昇を説明します。 到達するとループは壊れます`k`チケットを使用して、不必要な計算を回避します。

 ## 特殊なケース

 もし`k`よりも小さいです`m`、アルゴリズムは正確に購入します`k`チケットは一番安い日から。 例えば、`n = 3, m = 5, k = 2, a = [3,1,2]`に並べ替えます`[1,2,3]`。`can_buy = min(5,2-0)=2`で両方のチケットを初日に購入します`spent = 2*(1+0)=2`。 それ以上の購入は発生しません。 これは境界を正しく処理します
