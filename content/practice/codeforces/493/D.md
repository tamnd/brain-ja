 ## 解決策
 ## 問題の理解

 私たちは、$n \times n$ボード。 白の女王は左上隅から始まります$(1,1)$、黒の女王は右上隅から始まります$(1,n)$。 1 マスおきに緑のポーンが入っています。 

移動は必須です。 各ターンで、プレイヤーはクイーンと一緒に何らかのピースをキャプチャする必要があります。 捕獲された駒は緑のポーンまたは反対側のクイーンである可能性があります。 クイーンはチェスの場合とまったく同じように、行、列、または対角線に沿って移動し、駒を飛び越えることはできません。 

プレイヤーは 2 つの状況で負けます。 1 つ目は、合法的な捕獲が利用できない状態でターンを開始した場合です。 2 つ目は、相手の直前の動きでクイーンが捕まったときです。 

入力には基板サイズのみが含まれます$n$。 私たちは完璧なプレーの下でどちらのプレーヤーが勝つかを決定しなければなりません。 白が勝った場合は、白の初手も出力する必要があります。 すべての勝ちの初手の中で、行が最小、列が最小のものが必要です。 

制約は問題の最も明らかな部分です。 ボードのサイズは次のように大きくできます。$10^9$。 基板の構築は不可能です。 1 平方あたり 1 ビットを保存するだけでも、あまりにも多くのメモリが必要になります。 個々のセルについて推論したり、ゲームの動きを一手ごとにシミュレートしたりするソリューションは、直ちに除外されます。 

これは、ゲームが非常に単純な数学的構造を持っている必要があることを示唆しています。 ソリューション全体は、次の要素のみに依存するパターンから導き出す必要があります。$n$。 

最初の自明ではないエッジケースは次のとおりです。$n=2$。 

入力：```
2
```女王は最初の列に沿って直接お互いを攻撃します。 白はすぐに黒の女王を捕まえることができます。 

出力：```
white
1 2
```両方のクイーンがポーンをキャプチャし続ける必要があると仮定する不用意な解決策では、この瞬間的な勝利を逃すことになります。 

もう一つの重要な事例は、$n=3$。 

入力：```
3
```出力：```
black
```一見すると、白は合法的な手を多く持っているように見えます。 実際には、あらゆる安全な行動が強制されます。 両方の女王はそれぞれの列に沿って下に移動し、最終的に白が中央の列に足を踏み入れて捕らえられなければなりません。 手数のみに基づく単純な分析では、間違った勝者を簡単に予測してしまう可能性があります。 

最後の重要なケースは、2 より大きい偶数のボード サイズです。 

入力：```
4
```出力：```
white
2 2
```勝ち手は角打ちではありません。 このステートメントは辞書編集上最小の勝ちの初手を要求するため、正確な平方が重要になります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームの状態を明示的にモデル化します。 両方のクイーンと残りのすべてのポーンの位置を表し、すべての正当な手を生成し、ミニマックスで勝者を計算することができます。 

ある程度のサイズのボードの場合$n$、 がある$n^2$正方形であり、ほとんどすべてに最初はピースが含まれています。 状態の数はキャプチャの数に応じて指数関数的に増加します。 たとえ非常に小さな基板であっても、これは実行不可能になります。 と$n$まで$10^9$、初期位置を単独で構築することは不可能です。 

重要な観察は、ボードが完全に駒で埋め尽くされていることです。 クイーンはピースを飛び越えることができないため、各クイーンは最初は攻撃方向の 1 つに沿って隣接するピースのみをキャプチャできます。 

個々のポジションではなく、ゲームの構造を見てみましょう。 

奇数の場合$n$、中央の柱があります。 そこに入った女王は、反対側の女王に対して脆弱になります。 最適なプレイでは、両方のクイーンができるだけ長く自分のサイド列に留まるよう強制されます。 それらは徐々に下に移動します。 最終的には白が中央列に入らざるを得なかった最初のプレイヤーとなり、その後黒が白の女王を捕まえて勝ちます。 

偶数の場合$n$、中央の柱はありません。 白はすぐにマス目に移動できます$(2,2)$。 この手の後、位置は対称になりますが、黒が最初に応答する必要があります。 白は負けの構成で効果的に手を黒に渡します。 これは、ボードサイズが同じ場合の標準的な勝利戦略です。 

注目すべき結果は、勝者は次の平等性のみに依存するということです。$n$。 

もし$n$奇妙です、黒が勝ちます。 

もし$n$が互角の場合、白が勝ち、必要な手は$(2,2)$。 のために$n=2$、これも$(1,2)$なぜなら、白はすぐに黒のクイーンを捕まえることができ、その動きは可能な限り小さな列を持っているからです。

 ## アルゴリズムのチュートリアル

 1. の値を読み取ります。$n$。 
2. もし$n$奇数です、印刷してください`"black"`。 

奇数のボード サイズの場合、最適なプレイにより 2 番目のプレーヤーが強制的に勝利します。 
3. それ以外の場合は、印刷します`"white"`。 

ボードのサイズさえも、先手プレイヤーにとっては勝ちポジションとなります。 
4. もし$n=2$、動きを印刷します`(1, 2)`。 

白はすぐに黒の女王を捕まえることができます。 
5. それ以外の場合は、移動を印刷します`(2, 2)`。 

これは、すべての偶数に対する辞書編集上最小の勝ちの初手です。$n \ge 4$。 

### なぜ効果があるのか

 ゲームは完全に同等になります。 

奇数のボード サイズの場合、ボードがいっぱいになると、両方のクイーンが対称的にキャプチャされます。 白は、安全なサイド列を離れ、黒が攻撃するマスに入らなければならない最初のプレイヤーです。 白が先に動くので、この負けの瞬間に白が先に到達します。 

ボードサイズが偶数の場合、白は次のように移動できます。$(2,2)$、対称性を維持しながら、黒の奇数サイズの負け構造を作成します。 黒は最終的に強制負け手に直面するプレイヤーになります。 結果の位置はプレイヤーが移動するのに負けなので、白が勝ちます。 

ステートメントでは最小の勝ち手を求めるため、$(2,2)$2 より大きいすべての偶数ボードに対して選択されますが、$(1,2)$が即座に勝利を収めるキャプチャーである場合$n=2$。

# helper: run solution on input string, return output string
import sys, io

def solve():
    n = int(input())

    if n % 2 == 1:
        print("black")
    else:
        print("white")
        if n == 2:
            print("1 2")
        else:
            print("2 2")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
