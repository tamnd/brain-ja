 ## 解決策
 ## 問題の理解

 レスリングの技の時系列の記録が与えられる。 各エントリは、誰が手を実行したか、およびそれが貢献したポイント数の両方を記述する整数です。 正の値は、最初のレスラーがそのポイントに相当する動きを実行したことを意味し、負の値は、2 番目のレスラーがその数値の絶対値に相当する動きを実行したことを意味します。 

このストリームから 2 つのシーケンスを再構築します。1 つは最初のレスラーが出現順に獲得したポイントのシーケンスで、もう 1 つは 2 番目のレスラーが獲得したポイントのシーケンスです。 最終的には3段階で勝者が決まります。 まずは合計点を比較してみます。 1 人のレスラーがより大きな金額を持っている場合、そのレスラーはすぐに勝ちます。 合計が等しい場合は、2 つのシーケンスを辞書順に比較し、大きいシーケンスが優先されます。 両方のシーケンスの値と長さが同じである場合、勝者は入力内で最後の動きを実行したレスラーになります。 

n が 2・10^5 までの制約は、どの解も時間的に線形またはほぼ線形でなければならないことを意味します。 プレフィックスを繰り返し比較したりシーケンスを繰り返し再スキャンしたりする 2 次アプローチでは、最悪の場合 10^10 の演算に達する可能性があるため、時間がかかりすぎます。 入力を単一パスで処理し、繰り返しの比較を避ける必要があります。 

合計が等しいが、シーケンスが最後の異なる要素でのみ異なる場合、微妙なエッジ ケースが発生します。 たとえば、一方のシーケンスが他方のシーケンスのプレフィックスである場合、辞書編集的な比較は長さに依存します。 もう 1 つのエッジ ケースは、シーケンスの値と長さが同じである場合です。この場合、勝者は、どちらかのレスラーに属する可能性のある最後の非ゼロ イベントによってのみ決定されます。 

## アプローチ

 ブルートフォース解釈では、両方のシーケンスを明示的に構築し、次にそれらの合計を計算し、最後にそれらを辞書編集的に比較します。 これは概念的には機能しますが、辞書編集的な比較自体が低下する可能性があります。 最悪の場合、両方のシーケンスに最大 n 個の要素が含まれる可能性があり、すべての決定点またはデータの複数のパスごとにそれらを最初から比較しても線形性は維持されますが、処理中に比較を繰り返しシミュレートしようとすると、実際の非効率が現れます。 

重要な点は、シーケンスを繰り返し比較する必要がないということです。 これらを一度構築し、最後に合計合計比較、辞書編集的比較、および最終移動比較という 3 つの決定的な比較を実行するだけで済みます。 シーケンスの構築はすでに O(n) であるため、残りのすべての操作も比較ごとに O(n) または O(1) である必要があります。 

各レスラーに 1 つずつ、および 2 つの累計を含む 2 つの配列を維持します。 最後の動きのインデックスも追跡します。 入力が完全に処理されたら、合計を比較します。 等しい場合は、Python のネイティブ辞書編集比較を使用してリストを比較します。これは最適であり、C で実装されています。それでも等しい場合は、どのプレイヤーが最後に手を打ったかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 受け入れられるが不要なオーバーヘッド |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. n を読み取り、すべての手を順番に繰り返します。 各値 aᵢ について、その符号を確認して、どのレスラーがそれを実行したかを決定します。 このステップは、両方のスコアリングシーケンスを忠実に再構築するために必要です。 
2. aᵢ が正の場合、それを最初のレスラーのシーケンスに追加し、その時点の合計に加算します。 aᵢ が負の場合、その絶対値を 2 番目のレスラーのシーケンスに追加し、その合計に加算します。 これにより、スコアの蓄積とシーケンスの再構築の両方が 1 つのパスで同期されます。 
3. 最後の動きのインデックスと、どのプレイヤーがそれを実行したかを追跡します。 この情報は、他のすべての比較が同点で終了した場合にのみ必要となります。 
4. すべての手を処理した後、両方の力士の合計を比較します。 どちらかが大きい場合は、配列構造を考慮せずにすぐに勝者を決定できます。 
5. 合計が等しい場合は、2 つのシーケンスを辞書順に比較します。 この比較は標準の辞書順序に従います。つまり、最初に異なる要素が決定され、そうでない場合は、一方が他方のプレフィックスである場合には長いシーケンスが優先されます。 
6. 両方のシーケンスが同一の場合は、最後に手を実行した人に基づいて勝者を返します。 

### なぜ効果があるのか

 このアルゴリズムは、問題の意思決定階層を直接反映しています。つまり、合計の比較が辞書編集的な比較を支配し、辞書編集的な比較が最後の手のタイブレークを支配します。 各情報 (シーケンス、合計、最後の手) は問題で定義されたとおりに正確に保持されるため、変換や近似は導入されません。 正確さは、辞書編集上の順序が最初の異なる位置のみに依存し、完全な配列が保存されるため、比較に必要な情報が失われることがないという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
first = []
second = []
sum1 = 0
sum2 = 0

last = 0  # 1 for first, 2 for second

for _ in range(n):
    x = int(input())
    if x > 0:
        first.append(x)
        sum1 += x
        last = 1
    else:
        x = -x
        second.append(x)
        sum2 += x
        last = 2

if sum1 > sum2:
    print("first")
elif sum2 > sum1:
    print("second")
else:
    if first > second:
        print("first")
    elif second > first:
        print("second")
    else:
        print("first" if last == 1 else "second")
```コードは、入力に対する 1 回のパスで両方のシーケンスの合計を計算しながら、両方のシーケンスを構築します。 変数 last には、誰が最新の手を実行したかが格納されます。これは、両方のシーケンスの値と構造が同じになる場合にのみ使用されます。 

比較`first > second`Python の組み込み辞書編集リスト比較を活用し、問題定義と正確に一致します。 これにより、手動による要素ごとの比較が回避され、実装がコンパクトに保たれ、インデックス付けエラーから安全に保たれます。 

最後のタイブレークでは、保存されている最後のムーバーが使用され、シーケンスが完全に同一である場合の正確性が保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import builtins

    output = []

    def fake_print(*args):
        output.append(" ".join(map(str, args)))

    # backup
    orig_print = builtins.print
    builtins.print = fake_print

    try:
        n = int(input())
        first = []
        second = []
        sum1 = 0
        sum2 = 0
        last = 0

        for _ in range(n):
            x = int(input())
            if x > 0:
                first.append(x)
                sum1 += x
                last = 1
            else:
                x = -x
                second.append(x)
                sum2 += x
                last = 2

        if sum1 > sum2:
            print("first")
        elif sum2 > sum1:
            print("second")
        else:
            if first > second:
                print("first")
            elif second > first:
                print("second")
            else:
                print("first" if last == 1 else "second")

        return "\n".join(output)
    finally:
        builtins.print = orig_print

assert run("""5

""") == "second"

""") == "second"

 ## 特殊なケース

 1 つのエッジ ケースは、両方のシーケンスが同一であるものの、異なる移動順序で構築されている場合に発生します。 入力を考慮してください:```
2
1
-1
```最初のシーケンスは [1]、2 番目は [1] です。 合計は等しく、辞書編集的な比較により等価性が得られます。 アルゴリズムは正しく最後の手 (2 番目) にフォールバックし、「2 番目」を生成します。 

もう 1 つのエッジ ケースは、一方のシーケンスが他方のシーケンスの厳密なプレフィックスである場合です。```
3
1
2
-1
```ここでは、最初 = [1,2]、2 番目 = [1] です。 合計が異なるので、答えは「最初」に決まっています。 変更されたシナリオで合計が人為的に等しくなった場合、Python のリスト比較では問題定義の要求どおりに接頭辞の順序付けが正確に処理されるため、辞書編集的な比較では長いシーケンスが正しく優先されます。
