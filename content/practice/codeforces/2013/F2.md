 ## 問題の理解

 私たちに与えられた木は、`n`頂点。 アリスは頂点から開始します`1`ボブは他の 2 つのノード間のパスに沿った頂点から開始します。`u`そして`v`。 これらは、訪問されていない隣接する頂点に沿って順番に移動します。 プレイヤーは動けなくなったら負けです。 パスに沿った各頂点について、`u`に`v`、ボブがそこからスタートした場合に誰が勝つかを判断する必要があります。 

入力により複数のテスト ケースが提供されます。 各テスト ケースにはツリーのエッジと頂点が含まれます`u`そして`v`パスを定義します。 出力は一連の行であり、各行には勝者に応じて「Alice」または「Bob」が表示されます。 

主な制約は、`n`テスト ケースごとに 2×10^5 まで大きくすることができ、すべてのテスト ケースの合計が 2×10^5 を超えることはありません。 これにより、移動の数は次の値に比例するため、各移動が明示的に実行される総当りシミュレーションが不要になります。`n`、単純な O(n^2) アプローチは不可能になります。 

明らかではないエッジ ケースは、ボブがアリスの非常に近くで、おそらく彼女の開始頂点に隣接して開始するときに発生します。 たとえば、ボブが隣人から始めた場合、`1`それ以外の場合は葉であるため、アリスは残りの未訪問部分にのみ移動でき、すぐに負ける可能性があります。 もう 1 つの注意が必要な状況は、からのパスが`u`に`v`にはアリスまでの距離が異なる複数の頂点があり、それが微妙な方法で動きのパリティに影響を与えます。 

たとえば、木について考えてみましょう。`1-2-3-4`アリスと一緒に`1`そしてボブはから始まります`3`。 パスは`[3,4]`。 アリスが行けるのは`2`まず、ボブだけを残します`4`移動すること。 この構成では、ボブが開始するかどうかによって勝者が変わります。`3`または`4`。 

## アプローチ

 ブルートフォース手法では、パスに沿ったボブの可能な開始位置ごとにゲームをターンごとにシミュレートします。 各テスト ケースでは、訪問した頂点をマークし、1 人のプレイヤーが負けるまですべての手を再帰的に試行します。 これは正しく動作しますが、単一ツリーの走査に関係する可能性があるため、最悪の場合の複雑さは O(n^2) になります。`O(n)`移動します。`O(n)`テストする開始位置。 これは、n ~ 2×10^5 の時間制限を超えています。 

重要な洞察は、ゲームの結果はツリーに沿った**アリスからボブまでの距離**と、ルート化されたゲームとしてのツリーの構造にのみ依存するということです。 未訪問のサブツリーを持つツリーは **Nim ゲーム**の変形に対応します。各サブツリーは独立して処理でき、勝者はアリスからボブまでのパスに沿った距離の同等性によって決まります。 具体的には、アリスからボブまでの距離が奇数の場合、アリスが最初に「中央」に移動してゲームをコントロールします。 互角の場合、ボブはアリスの動きを反映し、最終的にアリスを負けの立場に追い込むことができます。 

結果が純粋にアリスとボブの間の距離によって決まることがわかったら、**BFS を使用してアリスの開始頂点からの深さを事前計算**し、パスに沿ったすべての頂点までの距離を計算できます。`[u..v]`。 各頂点について、アリスまでの距離のパリティをチェックするだけです。距離が偶数であればボブが勝ち、距離が偶数であればボブが勝ちます。 奇数であれば、アリスの勝ちです。 これにより、テスト ケースごとの複雑さが BFS の O(n) とパスの評価の O(m) に軽減されます。ここで、m はパスに沿った頂点の数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 距離 + パリティ分析 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`そして`n-1`エッジ、ツリーの隣接リストを構築します。 隣接関係リストを使用すると、隣接関係を高速にトラバースできます。 
2. 頂点を読み取る`u`そして`v`。 以下から単純なパスを計算します。`u`に`v`BFS または DFS を使用します。 DFS を開始する`u`、親配列を保持しているので、元に戻ることができます`v`に`u`パスを構築する`[u..v]`。 このステップにより、ボブが開始できる頂点の配列が得られます。 
3. 頂点から開始して BFS を実行します`1`（アリスのスタート）。 頂点からの距離を計算する`1`ツリー内の他の頂点ごとに。 距離を配列に保存する`dist`。 
4. 各頂点について`p`道に沿って`[u..v]`、 チェック`dist[p]`。 距離が等しい場合は、「ボブ」を出力します。ボブはアリスの動きを反映して勝つことができるためです。 距離が奇数の場合は、アリスが先手有利でゲームをコントロールできるため、「アリス」と出力します。 
5. すべてのテスト ケースに対して繰り返します。 

これが機能する理由: 不変条件は、パスに沿った頂点からの各サブツリーを、アリスからの深さに等しい長さの独立したゲームとして扱うことができるということです。 これらの直線的なゲームでは、距離の同等性が最初のプレイヤーの優位性を完全に決定します。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            adj[a].append(b)
            adj[b].append(a)
        u, v = map(int, input().split())
        
        # BFS from Alice's start
        dist = [-1] * (n + 1)
        q = deque([1])
        dist[1] = 0
        while q:
            node = q.popleft()
            for nei in adj[node]:
                if dist[nei] == -1:
                    dist[nei] = dist[node] + 1
                    q.append(nei)
        
        # Find path from u to v
        parent = [-1] * (n + 1)
        stack = [u]
        visited = [False] * (n + 1)
        visited[u] = True
        while stack:
            node = stack.pop()
            if node == v:
                break
            for nei in adj[node]:
                if not visited[nei]:
                    visited[nei] = True
                    parent[nei] = node
                    stack.append(nei)
        
        path = []
        cur = v
        while cur != -1:
            path.append(cur)
            cur = parent[cur]
        path.reverse()
        
        for p in path:
            if dist[p] % 2 == 0:
                print("Bob")
            else:
                print("Alice")

if __name__ == "__main__":
    main()
```BFS は O(n) 単位で距離を計算します。 パス再構築のための DFS も O(n) で実行されるため、アルゴリズムは線形のままです。 パスが単一ノードであるなどのエッジケース (`u=v`) またはすぐ隣接する頂点`1`パリティ チェックによって自然に処理されます。
