 ## 解決策
 ## 問題の理解

 Zhan はフルーツをたくさん持っているので、2 つの制約のあるブレンダーを使用して、それらすべてをできるだけ早くブレンドしたいと考えています。 毎秒、最大でも固定数のフルーツをブレンダーに入れることができ、ブレンダーは 1 秒あたり最大数のフルーツを処理できます。 すでにミキサー内にあるフルーツはミキサーの限界まで処理され、残りは次の瞬間まで残ります。 入力により、果物の数、1 秒あたりのブレンダーの容量、および Zhan が 1 秒あたりに与えることができる果物の数がわかります。 出力は、すべてのフルーツのブレンドを完了するのに必要な最小秒数です。 

制約は大きく、最大で$10^9$1 秒あたりの成果と演算数。 これは、毎秒シミュレーションしたり、個々のフルーツを反復したりすることはできないことを意味します。 ソリューションでは、単純な算術演算で必要な時間を計算する必要があります。 

エッジケースには、ブレンダーが 1 秒で処理できる量を超えるフルーツを Zhan が追加できる場合、ブレンダーの容量が Zhan が追加できる量を超える場合、および制限に比べてフルーツが非常に少ない場合が含まれます。 たとえば、フルーツが 1 つだけで、x と y が両方とも大きい場合、答えは 1 になります。不注意な解決策では、ブレンダーの容量と挿入速度の間の最小値を適切に考慮せずに混合するため、過大または過少にカウントされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、毎秒シミュレートされ、合計すると$y$フルーツをミキサーに入れてブレンドする$\min(x, c)$果物。 正しいですが、これには最大で反復処理が必要になります。$n$果物、それは不可能です$n$まで$10^9$。 

重要な観察は、必要な秒数が 2 つの速度のうち速い方、つまりブレンダーの能力に依存するということです。$x$そして挿入率$y$。 毎秒、処理される果物の有効数は、投入および除去の両方が可能な最大数です。 これにより、問題は次の上限を使用した単純な算術計算に縮小されます。$n$の最大値で割った値$x$そして$y$同時に、ブレンダーもザンも 1 つのステップでシステムを完全に飽和状態に保つことができない場合のシナリオも処理します。 大きい方を考慮すると、$x$そして$y$、一定時間に必要な秒数を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n) | お(1) | 遅すぎる |
 | 算術計算 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、フルーツの数を読み取ります。$n$、ブレンダー容量$x$、および挿入制限$y$。 
2. もし$n$がゼロの場合、ブレンドするものが何もないため、答えはゼロ秒です。 
3. 2 つのレートのうち大きい方を特定します。$max\_rate = \max(x, y)$。 これは、1 秒あたりに効果的に処理できる果物の最大数を表します。これは、ブレンダーが処理できる量を超える果物を投入すると無駄になり、ブレンダーの容量が小さいと有効なスループットが制限されるためです。 
4. 最小秒数を次のように計算します。$\lceil n / max\_rate \rceil$。 整数演算を使用すると、これは次のようになります。$(n + max\_rate - 1) // max\_rate$。 この式により、1 秒に満たない部分も完全な 1 秒としてカウントされます。 
5. 計算された秒数を出力します。 

正確さは、毎秒、より速い速度で許可される限り多くのフルーツを処理し、残りは次の秒でカウントされるという不変条件から導かれます。 天井があるので、果物が処理されずに残されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x, y = map(int, input().split())
        
        if n == 0:
            print(0)
            continue
        
        max_rate = max(x, y)
        seconds = (n + max_rate - 1) // max_rate
        print(seconds)

if __name__ == "__main__":
    solve()
```コードはテスト ケースの数を読み取り、それぞれを順番に処理します。 高速 I/O と整数演算を使用して、大量の入力を効率的に処理します。 式`(n + max_rate - 1) // max_rate`最も近い整数への切り上げを正しく処理します。 のような特殊なケース`n=0`除算の問題を回避するために明示的に処理されます。 

## 実用的な例

 サンプル入力: 5 つの果物、ブレンダーは 3 つを処理でき、Zhan は 4 つを追加できます。 

| ステップ | 残りの果物 | アクション | ブレンド |
 | --- | --- | --- | --- |
 | 1 | 5 | min(4,5)=4 | を挿入します。 min(3,4)=3 がブレンドされ、1 が残ります |
 | 2 | 1 | min(4,1)=1 | を挿入します。 min(3,2)=2 ブレンド、0 残り |

 秒: 2

 別の例: 果物 100 個、ブレンダーの容量 4、Zhan が 3 を追加します。`max_rate = max(4,3)=4`→ 秒 = (100 + 4 - 1) // 4 = 103 // 4 = 25。これにより、天井分割が正しく計算されます。

 ## 特殊なケース

 のために`n=0`、ブレンダーは何もしません。 式は引き続き機能しますが、不必要な計算を避けるために明示的なチェックでは 0 秒が返されます。 のために`n`両方よりも小さい`x`そして`y`の場合、この式では 1 秒が生成されますが、これは正しいです。 非常に大きい場合`n`、整数演算により浮動小数点エラーが回避され、正確な上限除算が保証されます。 部分的な最後の 2 秒のブレンディングは、`+ max_rate - 1`トリック。
