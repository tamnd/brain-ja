 ## 解決策
 ## 問題の理解

 一列に並べられた一連の数字が与えられます。 1 回の移動で、ある位置から 1 つのユニットを取得し、それを右側の次の位置に押すことができます。 これは、質量は右方向にのみ流れることができ、逆方向には決して流れることができず、すべての移動が配​​列の合計を保持することを意味します。 

このような移動を何度でも実行した後、最大値と最小値の差が最小限に抑えられるという意味で、最終的な配列が可能な限り「バランスがとれた」状態になることが望まれます。 

重要な問題は、値を再分配することはできますが、方向の制約により、要素を自由に並べ替えることとは大きく異なることです。 初期のポジションは質量を失うだけであり、後期のポジションは伝播を通じて間接的にのみ質量を獲得できます。 

制約は、テスト ケースごとにほぼ線形または線形計算的なソリューションを目指します。 合計で最大 20 万の要素があるため、段階的に再配布をシミュレートしようとしたり、構成を明示的に調査したりするソリューションは、すぐに遅すぎます。 二次的な実現可能性チェックでさえすでに境界線に達しているため、特定のターゲット範囲に対する答えを直接計算できる構造にする必要があります。 

配列がすでに「ほぼソートされている」または「ほぼ一定」になっている場合、微妙なエッジ ケースが発生します。 ローカル平滑化はグローバルな累積効果を無視するため、ローカルで平滑化しようとする単純な貪欲型はここで失敗する可能性があります。 たとえば、次のような配列では、`[5, 1, 1, 1, 1]`、質量を右に押すと、後の位置は改善されますが、最後の要素に過負荷がかかる可能性があり、実現可能性を判断するには、局所的な調整ではなく全体的な推論が必要です。 

すべての値が等しい場合、別の特殊なケースが発生します。 移動する必要がないので、答えはゼロです。 少なくとも 1 つの有益な手が存在すると仮定するメソッドは、実行可能性をチェックするときに厳密な不等式を使用すると、ここで破綻する可能性があります。 

## アプローチ

 強引なアイデアは、これ以上改善できなくなるまで、あらゆる方法で値を再分配するプロセスをシミュレートすることです。 各操作は 1 つの単位を右に 1 ステップ移動するため、各値の単位は効果的に移動距離を選択しますが、各プレフィックスの容量が将来の移動を制限するため、選択肢間に依存性があります。 

これをフローとしてモデル化しようとしても、考えられる一連の操作の数は、最悪の場合には指数関数的に増加します。 たとえば、最初の単一の大きな値が、後のインデックス全体でさまざまな組み合わせでプッシュされる可能性があり、組み合わせ爆発が発生します。 

重要な点は、操作をシミュレートする必要がないということです。 指定された最大値と最小値の差を達成できるかどうかを判断するだけで済みます。 実現可能性がテスト可能になったら、答えを二分探索できます。 

固定限界の実現可能性をチェックするために、すべての最終値が一定の間隔内に収まることを確認できるかどうかを確認しようとします。`[L, L + d]`。 合計は保存され、移動は右方向のみであるため、可能な最小のプレフィックス累積を貪欲に決定し、上限制約に違反するかどうかを確認できます。 

これにより、問題は単調な実現可能性チェックに変わります。`d`、これにより二分探索が適用可能になります。

 ## アルゴリズムのチュートリアル

 この問題を、指定された範囲幅が満たされているかどうかを確認することに変換します。`d`達成可能です。 

1. 回答候補を修正する`d`、つまり、最終値が一定の間隔内にあることを意味します。`[L, L + d]`L についてはまだわかりません。そのため、代わりにプレフィックスの合計に関する制約を考慮して推論します。 
2. プレフィックスを見ると、値は右にのみ移動できることに注目してください。`[1..i]`、元の配列から受け取ることができるのは、最大でもそのプレフィックスの合計だけです。 これは、最終的なプレフィックスの合計が初期の​​プレフィックスの合計を超えることができないことを意味します。 
3. すべての要素を少なくとも`L`、次にプレフィックス`[1..i]`少なくとも合計が必要です`i * L`。 これと上限を組み合わせると`L + d`、プレフィックスの合計も最大で次でなければなりません。`i * (L + d)`。 
4. これにより、次の実現可能条件が得られます。`i`、元のプレフィックス合計は、ある幅の間隔と互換性がある必要があります`d`。 これを再整理して、可能な制約を見つけることができます。`L`。 
5. 各プレフィックスについて、最大下限を計算します。`L`これはプレフィックスの合計を超えないことを意味し、最小上限は低すぎないことを意味します。 これらの制約が一部重複する場合`L`、次に選択した`d`実現可能です。 
6. 最小値を二分探索します`d`実現可能性が保たれます。 

重要な構造は、プレフィックスの合計が左に移動できない「予算」のように機能することです。 有効な最終構成では、すべてのプレフィックス バジェットを同時に尊重する必要があります。 

### なぜ効果があるのか

 このアルゴリズムは正しいです。許可された一連の操作ではプレフィックス合計の上限が保持されます。つまり、質量は左にジャンプできないため、プレフィックスは最初の合計を超える値を得ることができません。 同時に、すべてのプレフィックス制約を満たすターゲット間隔を割り当てることができれば、それを実現するライトフロー分布を構築できます。 実現可能性チェックでは、そのような分布が存在するかどうかを正確に把握し、二分探索を行います。`d`音。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(d, a, n, total):
    # We try to see if there exists L such that all values lie in [L, L+d]
    # Using prefix constraints on possible mass flow.
    
    low = -10**30
    high = 10**30
    
    pref = 0
    for i in range(1, n + 1):
        pref += a[i - 1]
        
        # prefix sum must be between i*L and i*(L+d)
        # i*L <= pref <= i*(L+d)
        # L <= pref/i
        # L >= pref/i - d
        
        # update constraints on L
        # from pref <= i*(L+d): L >= pref/i - d
        low = max(low, pref / i - d)
        
        # from pref >= i*L: L <= pref/i
        high = min(high, pref / i)
        
        if low > high:
            return False
    
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    
    # search range for answer
    lo, hi = 0, max(a)
    
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a, n, total):
            hi = mid
        else:
            lo = mid + 1
    
    print(lo)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```ソリューションは実現可能性関数を定義します`can(d)`の最大値と最小値の差が存在するかどうかをチェックします。`d`達成できる。 現在のプレフィックス合計を維持し、仮説ベースライン値に対する制約を導き出します。`L`。 実現可能性の重なり`L`間隔によって、選択されたかどうかが決まります。`d`動作します。 

二分探索では、そのような最小のものを見つけます。`d`。 検索範囲は次のように安全に制限されます。`0`そして`max(a)`なぜなら、その差は最大の初期値スプレッドを超えることができないからです。 

実装上の微妙な問題は、浮動小数点除算です。 厳密なコンテストの解決策では、精度の問題を回避するために、これを整数を使用した合理的な不等式操作に置き換える必要がありますが、概念的な構造は同じままです。 

## 実用的な例

 確定した候補の実現可能性チェックをトレースします`d = 2`。 

### 例 1

 入力:`[1, 2, 3]`| 私 | プレフィックスの合計 | L | に対する低い制約 L | に対する高い制約
 | --- | --- | --- | --- |
 | 1 | 1 | -∞、1 - 2 = -1 | 1 |
 | 2 | 3 | 最大(-∞、1.5 - 2 = -0.5) | 1.5 |
 | 3 | 6 | 最大(-0.5、2 - 2 = 0) | 2 |

 の間隔`L`空ではないので、`d = 2`実現可能です。 試しています`d = 1`下限を縮小しすぎると、最終的にオーバーラップが壊れてしまいます。 

これにより、答えが一貫したプレフィックス割り当てを可能にする最小幅であることが確認されます。 

### 例 2

 入力:`[4, 2, 3, 1]`| 私 | プレフィックスの合計 | 低い制約 | 高い制約 |
 | --- | --- | --- | --- |
 | 1 | 4 | -∞、4 - d | 4 |
 | 2 | 6 | max(前、3 - d) | 3 |
 | 3 | 9 | max(前、3 - d) | 3 |
 | 4 | 10 | max(前、2.5 - d) | 2.5 |

 のために`d = 1`、制約が競合します。 のために`d = 2`、それらは交差します。 

これは、プレフィックスの動作が厳密であることで、達成可能な最小限の拡散がどのように強制されるかを示しています。

 ## 特殊なケース

 のために`n = 1`の場合、配列には移動先となる隣接配列がないため、操作はできません。 プレフィックス制約はただちに 1 つの値に折りたたまれ、差がゼロになるため、アルゴリズムは依然として有効な間隔を生成します。 

次のようなすでに均一な配列の場合`[7, 7, 7, 7]`、すべてのプレフィックスの合計は一定の密度に完全に一致するため、実行可能な間隔は`L`関係なく壊れることはありません`d = 0`。 二分探索は即座にゼロにロックします。 

次のような非常に偏った入力の場合`[100, 0, 0, 0]`(またはそれに相当する大きな値)、プレフィックス制約が強制されます。`L`非常に小さくなりますが、後のプレフィックスによって上に押し上げられます。 実現可能性チェックでは、境界の重複を通じてこの緊張を捉えます。`L`、有効な最小値`d`一方向の流れによって生み出される縮小不可能な広がりを反映しています。
