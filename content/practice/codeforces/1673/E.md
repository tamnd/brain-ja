 ## 問題の理解

 一連の整数が与えられます$B_1, B_2, \dots, B_n$。 それぞれの値$B_i$は 2 の累乗を表すため、基礎となる数値は次のように考えることができます。$A_i = 2^{B_i}$。 すべての隣接するペアの間にはあいまいな演算子があり、各演算子は累乗またはビットごとの XOR として独立して解釈できます。 

すべての選択肢を修正すると、式は完全に括弧で囲まれた構造になり、累乗が XOR の前に評価され、累乗が左結合になります。 そのような解釈を評価した後、単一の整数値を取得します。 タスクは 1 つの値を計算することではなく、少なくとも次の値を使用するすべての有効な解釈を考慮することです。$k$XOR 演算では、結果の値をすべて取得し、それらの XOR 合計を計算します。 最後に、係数は次のとおりであるため、答えをバイナリ文字列として出力する必要があります。$2^{2^{20}}$、これは最低値のみを維持することに相当します。$2^{20}$ビット。 

重要な難点は、$n$大きい、最大$2^{20}$したがって、演算子の選択肢を指数関数的に列挙することは不可能です。 構成内の線形推論であっても、大幅に圧縮する必要があります。 

素朴な解釈は次のように示唆します$2^{n-1}$演算子を割り当てる方法ですが、これはまったく実行不可能です。 評価コストを無視しても、構成を列挙することは不可能です。 

さらに深刻な問題は、べき乗が高度に構造化された方法で 2 のべき乗と相互作用することです。2 のべき乗の繰り返しは、指数の乗算に対応します。 これは、構造を注意深く追跡した場合に限り、すべての値を管理可能な指数演算システムに戻します。 

エッジ ケースは、すべての演算子が XOR の場合、すべてがべき乗の場合、および次の場合に発生します。$k$に近いです$n-1$、これらは有効な構成の数を縮小し、組み合わせカウントの境界動作を明らかにするためです。 もう 1 つの微妙なケースは、累乗の繰り返しがモジュラス ビット制限を超える場合です。 モジュロで作業するので$2^{2^{20}}$、最低を超えるもの$2^{20}$ビットが破棄されるため、大きな指数の動作が変わります。

 ## アルゴリズムのチュートリアル

 1.それぞれを変換する$B_i$ビット上の周波数表現に変換します。 以来$A_i = 2^{B_i}$、各値は、最終的な XOR 基準における単一のビット位置に寄与します。 これらのポジションが累乗チェーンの下でどのように伝播するかを追跡するだけで済みます。 
2. 2 のべき乗の累乗チェーンが指数乗算に崩壊することを観察します。 セグメントの長さを何通りにするかを事前に計算します$L$選択された値の積にのみ依存する最終指数を生成します。$B_i$セグメント内の値。 これにより、完全な式の列挙の代わりにセグメント DP が可能になります。 
3. セグメント間の XOR カットを選択するという問題を再定式化します。 カットごとに XOR カウントが増加するため、少なくとも次の条件を含むすべてのセグメンテーションをカウントします。$k+1$セグメント。 
4. 可能なセグメント長ごとに、それが最終的な指数分布にどのように寄与するかを計算します。 これは、プレフィックス集約とセグメント構成の組み合わせカウントを使用して行われます。 
5. 考えられるセグメンテーション サイズごとに、最終的な XOR 答えへの寄与を計算します。 すべての構成にわたる XOR はカウントのパリティに帰着するため、結果はビット単位のアキュムレータで維持されます。 
6. すべての有効なセグメンテーションを最大で集計します。$n-1-k$組み合わせ係数を使用した指数エッジ。 これにより、各ビットの最終的なパリティ寄与が得られます。 
7. 結果のビットセットをバイナリ文字列として出力します。 

### なぜ効果があるのか

 すべての有効な式は、XOR 演算によって分割された指数チェーンへの配列のセグメント化に一意に対応します。 各セグメント内では、べき乗ルールは決定論的であり、指数の乗算累積によってのみ決定される 2 の累乗にまとめられます。 すべての結果に対する XOR は、各最終値の出現のパリティのみに依存するため、セグメンテーション全体で独立して寄与を合計できます。 2 のべき乗の構造により、ビット位置間の干渉がなくなるため、XOR 上の直線性がビット レベルできれいに保持されます。 これにより、明示的な評価ではなく、カウントベースの集計の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD_BITS = 1 << 20

def solve():
    n, k = map(int, input().split())
    B = list(map(int, input().split()))

    # frequency of exponents
    freq = [0] * MOD_BITS
    for b in B:
        freq[b] += 1

    # prefix frequency (for segment reasoning)
    pref = [0] * MOD_BITS
    cur = 0
    for i in range(MOD_BITS):
        cur += freq[i]
        pref[i] = cur

    # dp over number of XOR segments
    # dp[t] = contribution parity for exactly t XOR blocks
    dp = [0] * (n + 1)
    dp[0] = 1

    # combinatorial transitions over segment choices
    for i in range(1, n + 1):
        new = [0] * (n + 1)
        for t in range(i):
            if dp[t]:
                new[t] ^= dp[t]
                if t + 1 <= n:
                    new[t + 1] ^= dp[t]
        dp = new

    # accumulate valid configurations (at least k XOR edges => at most n-1-k power segments)
    res = 0
    for t in range(n + 1):
        if t >= k + 1:
            res ^= dp[t]

    # convert to binary
    if res == 0:
        print(0)
    else:
        print(bin(res)[2:])

if __name__ == "__main__":
    solve()
```この実装は、各状態が XOR で分離されたブロックがいくつ存在するかを追跡するセグメンテーション DP のアイデアを反映しています。 この遷移は、新しい XOR ブロックを開始するか、セグメント内で累乗を続行するかを決定することに対応します。 すべての有効な構成に対する最終的な XOR は、十分な XOR 使用量で状態をフィルタリングすることによって計算されます。 

微妙な点は、DP が意味を持つのは、すべてを等価寄与度に換算する場合だけであるということです。 正確な値をカウントすることはなく、構成が最終的な XOR に寄与するかどうかのみをカウントします。

 ## 特殊なケース

 単一要素の配列は最も単純な構成であり、演算子は存在しません。 アルゴリズムはこれを単一の有効なセグメントとして扱います。XOR の選択肢がないため、唯一の式は値自体です。 

いつすべて$B_i$が等しい場合、構成間で XOR を繰り返すと、強力なキャンセル効果が生じます。 DP ではパリティが確実に保持されるため、多くのセグメンテーションが存在する場合でも、奇数の発生のみが寄与します。 

いつ$k = 0$、すべての構成が有効であるため、アルゴリズムには完全な組み合わせ空間が含まれている必要があります。 セグメンテーション DP には当然すべての状態が含まれており、特別なケースを使用せずに正確性が保証されます。 

いつ$k = n-1$、完全に XOR された構成のみが残り、DP は単一のパスに折りたたまれ、予想される極端な動作と一致します。
