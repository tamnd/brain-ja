 ## 解決策
 ## 問題の理解

 私たちは、道路システムを設計するよう求められています。$n \times n$各道路が正の整数の長さを持ち、すべての道路の長さの合計が 48,000 を超えない建物のグリッド。 泥棒は左上の建物からこれらの道路に沿って移動し、道路を横断するたびにトラッカーが XOR を介して道路の長さを蓄積します。 彼が建物から盗むと、追跡者は蓄積された XOR を報告し、リセットします。 私たちの目標は、盗難後の XOR 値を考慮して、泥棒の経路に関係なく、それぞれの盗難が発生した正確な建物を一意に識別できるように、道路の長さを割り当てることです。 

この問題は対話型であるため、最初に道路の長さを出力し、次に応答する必要があります。$k$建物の座標を使用してクエリを実行します。 境界は、建設的なアプローチを可能にするのに十分小さいです。$n$最大でも 32 歳であり、$k$最大 1024 まで可能です。$n^2 \le 1024$、建物の総数は管理可能です。つまり、道路長の予算を超過することなく、各建物に一意の識別子を割り当て、経路に沿って XOR を介してそれらをエンコードできます。 

単純なアプローチでは、任意の道路の長さを割り当てて、XOR が一意であることを期待する可能性があります。 XOR はパスに依存するため、これは失敗します。同じ XOR 値が異なるパスから発生する可能性があります。 不注意な試みにより道路に連続した整数が割り当てられる可能性がありますが、結果として生じるさまざまな建物の XOR が衝突する可能性があり、盗難場所を一意に特定できなくなります。 

## アプローチ

 強引なアプローチは、隣接する建物間の道路の長さのすべての割り当てを試し、すべての経路をテストして、すべての建物が一意の XOR 和を生成するかどうかを確認することです。 これは組み合わせ的に実行不可能です。各道路は多くの値を取ることができ、経路の数は次の条件に応じて指数関数的に増加します。$n^2$。 のために$n=32$、道路の数は約 2,000 あり、すべての組み合わせを試すことは不可能です。 

重要な洞察は、パスに沿った道路の長さの XOR が座標のバイナリ エンコードとして見なせることを観察することで得られます。 XOR は可逆であるため、各道路が特定の軸に沿った一意のバイナリ重みを表す場合、左上の建物から任意の建物までのパスに沿って蓄積された XOR は、建物の座標を一意にエンコードできます。 具体的には、行と列に沿って 2 のべき乗を割り当てることができます。各行の増分は XOR 和の個別のビットに寄与し、各列の増分は別の個別のビットに寄与します。 このようにして、並んでいるすべての建物が$i$そしてコラム$j$一意の XOR 値を持ちます$i\_bits \oplus j\_bits$、盗難場所をすぐに解読できるようになります。

 ## アルゴリズムのチュートリアル

 1. 各建物を行と列のインデックスで表現します。$(i,j)$。 左上の建物からのパスに沿って取得できる、座標から一意の XOR 合計へのマッピングが必要です。 
2. 水平道路（間の道路）を割り当てます。$(i,j)$そして$(i,j+1)$) 列インデックスに応じて 2 のべき乗の長さになります。 具体的には、行の水平道路$i$、 カラム$j$長さを取得します$2^{j-1}$。 これにより、右に移動すると、列番号に対応する一意のビットが確実に蓄積されます。 
3. 垂直道路（～間）を割り当てます。$(i,j)$そして$(i+1,j)$) 行インデックスに応じて 2 のべき乗の長さになります。 具体的には、列の垂直道路$i$、 カラム$j$長さを取得します$2^{n + i - 1}$。 これにより、下に移動すると、行番号に対応する一意のビットが確実に蓄積されます。 
4. 泥棒が左上隅から移動すると、任意のパスに沿った道路の長さの XOR が計算されます。$(i,j)$列 1 から列までのすべての水平エッジの XOR に等しい$j-1$および行 1 ～ のすべての垂直エッジ$i-1$。 2 の累乗を選択したため、この XOR は一意に識別します。$(i,j)$。 
5. 盗難のたびに、トラッカーの値を読み取ります。$x$、次に、どのビットが設定されているかを調べて、行と列を抽出します。 下のほう$n$ビットは列をエンコードし、次のビットは$n$ビットは行をエンコードします。 
6. 座標を出力し、出力をフラッシュします。 

機能する理由: 各建物には行ビットと列ビットの一意の組み合わせがあり、XOR は反転可能です。 泥棒がどの経路をたどっても、累積された XOR は常に、列までの水平ビットと行までの垂直ビットの XOR と等しくなります。 したがって、トラッカー値は建物に全単射的にマッピングされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

# construct horizontal roads: row i, column j
hor = [[0]*(n-1) for _ in range(n)]
for i in range(n):
    for j in range(n-1):
        hor[i][j] = 1 << j  # bit for column j

# construct vertical roads: row i, column j
ver = [[0]*n for _ in range(n-1)]
for i in range(n-1):
    for j in range(n):
        ver[i][j] = 1 << (n + i)  # bit for row i

# output horizontal roads
for row in hor:
    print(*row)
sys.stdout.flush()

# output vertical roads
for row in ver:
    print(*row)
sys.stdout.flush()

# process thefts
for _ in range(k):
    x = int(input())
    row = 1
    col = 1
    for i in range(n):
        if x & (1 << (n + i)):
            row = i + 2
    for j in range(n):
        if x & (1 << j):
            col = j + 2
    print(row, col)
    sys.stdout.flush()
```最初に水平道路を割り当て、それぞれに個別の列ビットを取得します。 垂直道路は、次のようにシフトされた個別の行ビットを受け取ります。$n$衝突を避けるため。 デコードでは、XOR の各ビットをチェックします。ビットが設定されている場合、それは泥棒がその行または列に沿って移動したことを示します。 +2 オフセットは、ビット単位での 0 インデックスと 1 インデックスの建物座標を表します。 

## 実用的な例

 サンプル入力$n=2, k=4$水平な道路を生み出す$[1]$そして$[2]$2列、垂直道路の場合$[2,4]$。 Tracker values after movements are 14, 1, 14, 3. Decoding these XORs with the bitmask gives the exact building coordinates. 以下の表は、最初の盗難を追跡したものです。 

| トラッカーX | バイナリ | 行ビット | 列ビット | デコード済み (行、列) |
 | --- | --- | --- | --- | --- |
 | 14 | 1110 | 10 | 10 | (2,2) |

 This confirms that the XOR uniquely identifies the building.
