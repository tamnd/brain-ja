 ## 解決策
 ## 問題の理解

 記入するよう求められます$r \times c$正の整数を含むグリッドを使用して、特定の値の派生シーケンスがすべて異なるようにすると同時に、それらの値の最大値をできるだけ小さくします。 

各行から単一の数値、つまりその行内のすべての要素の gcd を計算します。 各列から別の数値、つまりその列内のすべての要素の gcd を計算します。 全体的にこれで得られるのは$r + c$価値観。 要件は、これらの gcd 値が繰り返されないことです。 

このタスクは建設的です。実際に、この特性を達成し、すべての行と列の gcd の最大値を最小化する行列を構築する必要があります。 そのような行列が存在しない場合は、ゼロを出力する必要があります。 

制約により許可されるのは、$r, c \le 500$、したがって、次のような解決策はあります$O(rc)$これは問題ありませんが、セルごとの重数理論や広い範囲にわたる検索を伴うものは不要です。 この構造は、ソリューションが動的に何かを計算するのではなく、非常に規則的なパターンで値を割り当てる必要があることを強く示唆しています。 

微妙なエッジケースが現れるのは、$r = c = 1$。 この場合、行と列が 1 つだけあり、両方の gcd は同じ単一セルから計算されるため、常に等しくなります。 これは直ちにすべての要件に違反します。$r + c$価値観が違う。 ブルートフォースまたは構築では、このケースを明示的に拒否する必要があります。 

もう 1 つの潜在的な落とし穴は、一方の次元が 1 に等しいが、もう一方の次元の方が大きい場合です。 行と列の gcd が重なり合うため、制限的であるように見えるかもしれませんが、十分な個別の因子が利用できる限り、慎重に構築すればそれらを分離することができます。 

## アプローチ

 ブルートフォースの試みでは、行列を埋めてすべての gcd をチェックし、すべての値が得られるまで値を微調整します。$r + c$価値観が明確になります。 行列の空間は天文学的に大きく、単一の候補の gcd を計算するだけでもコストがかかります$O(rc)$。 これはすぐに実行不可能になります。なぜなら、最大の値に対する単純な検索ですら、$10^9$不可能です。 

重要な観察は、実際には任意の gcd 動作が必要ないということです。 各行と各列の gcd を個別に制御する必要があるだけです。 これは、行 gcd と列 gcd が事前に「設計」されるように行列を構築し、各行と列が意図した値に正確に折りたたまれるようにすることを示唆しています。 

独立した gcd 構造を強制するきれいな方法は、各行列エントリを行固有のコンポーネントと列固有のコンポーネントの積として表すことです。 各行にすると$i$要因を運ぶ$p_i$そしてそれぞれの列$j$要因を運ぶ$q_j$を設定してから、$$a_{i,j} = p_i \cdot q_j$$すべての行を強制的に割り切れるようにする$p_i$そして割り切れるすべての列$q_j$。 もしすべてなら$p_i$対で互いに素であり、すべて$q_j$がペアごとに互いに素である場合、行の gcd は正確に次のように折りたたまれます。$p_i$、同様に、列の gcd は正確に次のように折りたたまれます。$q_j$。 

これにより、割り当ての問題が軽減されます。$r + c$強力な共素構造を持つ、ペアごとに異なる整数。 最も簡単な方法は、個別の素数を使用することです。 

残る唯一の問題は、最大 gcd 値を最小限に抑えることです。 gcd 値は正確に選択された素数であるため、最大値を最小化することは可能な限り最小値を選択することに相当します。$r + c$素数。 

特別な失敗ケースが 1 つあります。$r = c = 1$、行と列の gcd が等しいことは避けられないため、構造は存在しません。

 ## アルゴリズムのチュートリアル

 1. もし$r = 1$そして$c = 1$、すぐに 0 を出力します。単一のセルでは、行 gcd と列 gcd は定義上同一であるため、区別することは不可能です。 
2.最初の生成$r + c$素数。 これらは、行と列の目的の gcd 値として機能します。 
3. 最初の値を割り当てます$r$行とその次の素数$c$列に素数を付けます。 具体的には、列$i$取得します$p_i$、および列$j$取得します$q_j$。 
4. 各セルを次のように構築します。$a_{i,j} = p_i \cdot q_j$。 これにより、すべてのエントリが 1 つの行要素と 1 つの列要素を確実に保持します。 
5. 結果の行列を出力します。 

ステップ 4 の背後にある重要な考え方は、成分が互いに素である場合に gcd が乗算構造に分散するということです。 選択されたすべての素数は個別であるため、異なる行または列の間に意図しない共有因数が現れることはありません。 

### なぜ効果があるのか

 各行は、すべて割り切れる数値で構成されます。$p_i$したがって、行 gcd は少なくとも$p_i$。 別の要因なので$q_j$列間で異なり、共通の素因数を共有しません。$p_i$、行全体にわたる唯一の公約数は正確に$p_i$。 

同じ理由が列にも対称的に当てはまります。 カラム$j$すべて割り切れる値が含まれています$q_j$、他の列はその素因数を共有しないため、その gcd は正確に$q_j$。 

したがって、すべて$r + c$gcd 値は正確に選択された素数であり、ペアごとの区別性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve_primes(n):
    limit = 8000  # enough for first 1000+ primes
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            for j in range(i * i, limit + 1, i):
                is_prime[j] = False
        if len(primes) >= n:
            break
    
    return primes

r, c = map(int, input().split())

if r == 1 and c == 1:
    print(0)
    sys.exit()

primes = sieve_primes(r + c)

row_primes = primes[:r]
col_primes = primes[r:r + c]

for i in range(r):
    row = []
    for j in range(c):
        row.append(str(row_primes[i] * col_primes[j]))
    print(" ".join(row))
```大きな素数は必要ないため、素数生成ステップには適度な境界のみが必要です。 1000 番目の素数は 8000 をはるかに下回っているため、単純なふるいで十分です。 

構築ループは直接実装します$a_{i,j} = p_i q_j$、行と列の両方の gcd が選択した素数と正確に一致するようにします。 

唯一の明示的な境界処理は、$1 \times 1$不可能な場合は直ちに報告する必要があります。 

## 実用的な例

 ### 例 1:$r = 2, c = 2$最初の 4 つの素数を選択します。$2, 3, 5, 7$。 行素数の割り当て$p = [2, 3]$、列素数$q = [5, 7]$。 

| ステップ | 行 0 | 行 1 | 列 gcds | 行 gcd |
 | --- | --- | --- | --- | --- |
 | 割り当て | 2・5、2・7 | 3・5、3・7 | 5、7 | 2、3 |

 行列は次のようになります。$$\begin{pmatrix}
10 & 14 \\
15 & 21
\end{pmatrix}$$行 gcd は$2, 3$、列の gcd は$5, 7$、すべてが異なります。 最大値は 21 で、最大の製品によって決まります。 

これにより、行要素と列要素の独立性が確認されます。 

### 例 2:$r = 1, c = 3$使用される素数:$2, 3, 5, 7$。 行素数$p_1 = 2$、列素数$q = [3, 5, 7]$。 

| コラム | 値 | 列 gcd |
 | --- | --- | --- |
 | 1 | 2・3 = 6 | 3 |
 | 2 | 2・5 = 10 | 5 |
 | 3 | 2・7 = 14 | 7 |

 行 gcd は 2、列 gcd は 3、5、7 です。4 つの値はすべて個別です。 

これは、列構造が独立したままであるため、単一行であっても構築が機能することを示しています。

 ## 特殊なケース

 の$1 \times 1$本当に不可能なのはグリッドだけです。 アルゴリズムは、構築の前に明示的にそれを処理します。 このチェックがないと、行と列の gcd が一致する単一の値が生成され、ただちに一意性条件に違反します。 

単一行または単一列の場合は、行と列の構造が重なり合うため、問題があるように見える可能性があります。 ただし、列 (または行) は依然として独立したプライム ラベルを受け取るため、その gcd は単一の行 (または列) の gcd とは異なるままであり、そのため、縮退した形状であっても構築は有効で安定したままになります。
