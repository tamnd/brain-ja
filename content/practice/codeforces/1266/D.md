 ## 解決策

 ## 問題の理解

 各頂点が人を表し、各有向エッジがある人から別の人への負債を表す、有向重み付きグラフが与えられます。 エッジ上の値は、送信元の人が宛先の人に借りている金額です。 タスクは負債の数を最小限に抑えることではなく、有効な表現を維持しながらすべてのエッジの重みの合計ができるだけ小さくなるように、2 つの許可された操作を使用してこれらの負債の構造を変換することです。 

最初の操作は 2 つの独立した負債の再ルーティングです。1 人が別の負債を負っていて、無関係な 2 番目の負債が存在する場合、相互接続間でいくらかを再分配できます。 これにより、債務の流れを中間構造を介して転送することが効果的に可能になります。 2 番目の操作は自己負債を削除します。つまり、誰かが自分自身に負債を負うというサイクルが完全に除去されることになります。 

重要な解釈は、負債は中間ノードを介して「再ルーティング」でき、自己ループは無料で破棄できるということです。 目標は、同じ純財務不均衡を等価に表現するが、有向エッジの重みの合計が最小限であるものを見つけることです。 

制約は大きく、最大 100,000 人および 300,000 の負債 (それぞれ最大 10^9) があります。 これにより、二次構造やエッジのペアごとのマージの繰り返しが即座に排除されます。 どの解もエッジの数がほぼ線形である必要があり、おそらく O(n + m) または O(m log m) です。 メモリも十分に不足しているため、密な隣接行列の構築やグラフの繰り返しの展開を避ける必要があります。 

サイクルが存在する場合、微妙な問題が発生します。 単純なアプローチでは、反対側のフローを貪欲にキャンセルしたり、パスをローカルでマージしようとしたりする可能性がありますが、複数のサイクルが相互作用するとこれは失敗します。 もう 1 つの注意が必要なケースは、頂点が複数の入ってくる負債と出ていく負債の一部である場合です。 単純なペアごとのキャンセルでは、依然として不必要な総重みに寄与する最適でない残留サイクルが残る可能性があります。 

たとえば、1→2 に 10、2→3 に 10、3→1 に 10 がある場合、単純にキャンセルすると、サイクル全体を再ルーティングして削除できることを認識できず、自己ループ削除後に正味コストが 0 だけ残る可能性があります。 

中心的な課題は、フローの正確なルーティングではなく、各ノードにおけるネットの不均衡のみが重要であることを認識することです。 

## アプローチ

 強引な解釈では、改善が不可能になるまで 2 つの操作を繰り返し適用しようとします。 これには、エッジのペアの選択、再ルートのシミュレーション、および自己ループの追跡が含まれ、O(m^2) 個の組み合わせを探索する可能性があります。 各操作で複数のエッジが変更される可能性があるため、収束には多くの手順が必要になる可能性があります。 m が最大 300,000 であることを考えると、これは遅すぎます。 

重要な洞察は、正味の流入と流出の制約が維持される限り、この操作によりフローを完全に自由に再分配できるということです。 これは、問題は各ノードがどれだけの純債務者または純債権者であるかを追跡することに帰着することを意味します。 

各ノードの正味残高を計算すると、送金から入金を差し引いたものとして定義され、正のノードは送金し、負のノードは送金を受け取る必要があります。 操作タイプ 1 ではエッジのペア間のフローを任意に再ルーティングできるため、中間エッジの構造は無関係です。 これは事実上、グラフを黒字ノードと赤字ノード間の二部転送問題に圧縮できることを意味します。 

ネット残高によってノードが分類されたら、あとは余剰ノードを不足ノードに貪欲に接続するだけです。 自己ループはノードのバランスの内部キャンセルを表すため、自動的に消えます。 

すべてのプラスの残高とマイナスの残高を並べ替えまたは収集し、ツーポインタ戦略を使用してそれらを照合します。 これにより、最大でも n−1 個のエッジを持つ有効な最小表現が構築されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(m^2) | O(m) | 遅すぎる |
 | ネットバランス + 貪欲なマッチング | O(m + n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 流出債務を加算し、流入債務を減算して、各ノードの純残高を計算します。 これは、すべてのローカルキャンセルが概念的に適用された後、ノード全体が債権者であるか債務者であるかを捕捉します。 
2. ノードを 2 つのリスト (正の残高を持つリストと負の残高を持つリスト) に分割します。 正のノードはお金を支払う必要がある人を表し、負のノードはお金を受け取る必要がある人を表します。 
3. これらのリスト上で 2 つのポインターを使用します。 各ステップで、現在の正のノードと現在の負のノードを一致させます。 送金される金額は、絶対残高の最小値です。 これにより、転送後にそのうちの 1 つが確実に中立になります。 
4. この転送を出力の最終エッジとして記録します。 それに応じて両方の残高を減らします。 
5. ノードの残高がゼロになったときにポインタを移動します。 すべての残高がなくなるまで続けます。 
6. 構築されたすべてのエッジを出力します。 これらは、総額が最小限の有効な連結債務システムを表しています。 

この貪欲なペアリングが機能する理由は、許可された操作の有効なシーケンスは各ノードでのネットバランスのみを維持するためです。 したがって、最終的な構成はこれらのバランスによって完全に決定され、ペア間の再配分は互換性があります。 

### なぜ効果があるのか

 許可された操作では、各頂点での正味のフローが維持されます。 操作 1 では、ノードごとの入出力の合計を変更せずにフローのみを再ルーティングし、操作 2 では、他のノードに影響を与えない内部の自己フローを削除します。 これは、すべてのノードが不変の値、つまり純残高を持っていることを意味します。 

有効な最終構成は、各ノードの送信から受信を差し引いた値が、最初に計算された残高と等しいことを満たさなければなりません。 貪欲なマッチングは、余分な中間循環を導入することなく、これらの制約を正確に満たす最小限のエッジ セットを構築します。 フローのすべての単位が黒字と赤字の間で直接一致するため、冗長なサイクルが形成されず、最終的な構築に自己ループが現れません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    balance = [0] * (n + 1)

    for _ in range(m):
        u, v, d = map(int, input().split())
        balance[u] += d
        balance[v] -= d

    pos = []
    neg = []

    for i in range(1, n + 1):
        if balance[i] > 0:
            pos.append([i, balance[i]])
        elif balance[i] < 0:
            neg.append([i, -balance[i]])

    i = j = 0
    res = []

    while i < len(pos) and j < len(neg):
        u, a = pos[i]
        v, b = neg[j]

        x = min(a, b)
        res.append((u, v, x))

        pos[i][1] -= x
        neg[j][1] -= x

        if pos[i][1] == 0:
            i += 1
        if neg[j][1] == 0:
            j += 1

    print(len(res))
    for u, v, d in res:
        print(u, v, d)

if __name__ == "__main__":
    solve()
```この解決策は、すべての負債を単一の残高配列に圧縮することから始まります。 各エッジは債務者にプラスに寄与し、債権者にマイナスに寄与します。 これにより、グラフの構造上の複雑さがすべて取り除かれます。 

次に、バランスの符号によってノードを分離します。 2 ポインター ループは、エッジの最終セットを明示的に構築する構築フェーズです。 少なくとも 1 つのノードが完全に解決されるため、各ステップで確実に進行します。 

最終出力は、中間サイクルや自己ループを構築することなく、必要最小限の転送を直接エンコードします。

 ## 特殊なケース

 1→2 with 10 や 2→1 with 10 のような純粋な 2 ノード キャンセルのケースでは、アルゴリズムが正しくゼロ出力を生成するかどうかをテストします。 バランスの計算では両方のノードにゼロが与えられるため、両方のリストは空でエッジは生成されません。これは、予想されるすべての負債の除去と一致します。 

1→2→3→…→k→1 などの長いサイクルは、内部循環が誤って存続するかどうかをテストします。 残高配列はすべてゼロになり、アルゴリズムは何も出力せず、サイクルが最終負債に寄与しないことが確認されます。 

1 つのノードに大きな出力エッジと多数の小さな入力エッジがある斜めのスターでは、ポインタの安定性がテストされます。 貪欲なマッチングにより、余分な中間ノードを作成せずに部分転送が正しく分割され、線形の複雑さと正確さが維持されます。
