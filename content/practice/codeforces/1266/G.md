 ## 問題の理解

 固定整数が与えられます$n$。 そこから、数値のすべての順列をリストすることにより、非常に長いシーケンスを構築します。$1$に$n$辞書順に並べて次々に連結します。 したがって、順序は任意ではなく、非常に厳密なグローバル順序で配置されたすべての順列の繰り返しです。 

この巨大なシーケンスが定義されたら、タスクは、その内部の任意の場所に出現する個別の連続するサブ配列の数をカウントすることです。 2 つの部分配列は、それらの値がどこで発生するかに関係なく、正確に一致する場合は同じとみなされます。 

難しいのはサブ配列の定義ではなく、シーケンス自体の構造です。 長さは$n \cdot n!$、非常に速く成長するため、完全なシーケンスを構築またはスキャンしようとするアプローチは、中程度の場合でも不可能です。$n$、ましてや$n \le 10^6$。 

これにより、明示的な列挙に依存するものは即座に除外されます。 単一の順列リストを生成することさえ、大規模な場合には不可能です。$n$したがって、解決策は、順列が辞書編集順にどのように動作するかという構造的特性に依存する必要があります。 

微妙なエッジケースが現れるのは、$n=1$。 順序はただ$[1]$、サブ配列は 1 つだけあります。 この場合、正しい数式は自然に 1 になるはずです。そうでない場合は、存在しないパターンを過剰にカウントしている可能性があります。 

もう 1 つの明白ではない落とし穴は、連結がランダムなシーケンスのように動作すると仮定することです。 そうではありません。 すべての順列は 1 回だけ出現し、隣接する順列は高度に制約された方法で異なります。これが組み合わせ論を扱いやすくしています。 

## アプローチ

 この問題を考える最も直接的な方法は、実際にシーケンスを構築しているところを想像することです。$P$。 それを取得したら、個別の部分配列をカウントすることは、古典的な接尾辞オートマトンまたは接尾辞配列の問題です。つまり、シーケンスに対して構造を構築し、個別の部分文字列の数を数えます。 シーケンスの個別の部分配列の数は個別の部分文字列の数と正確に一致するため、これは原理的には正しいです。 

問題はそれです$P$長さがある$n \cdot n!$。 たとえ$n=15$、これはすでに天文学的な規模です。 したがって、明示的に構築するアプローチはすべて、$P$あるいは、その上に接尾辞構造を構築することは完全に不可能です。 

重要な観察は、実際には明示的なシーケンスが必要ないということです。 理解する必要があるのは、どのような種類の部分配列が出現する可能性があるか、およびサイズの順列から構造を拡張するときに、いくつの新しい個別の部分配列が導入されるかだけです。$n-1$サイズの順列に$n$。 

順列を再帰的に構築することを考えてください。 サイズの順列$n$要素を挿入することによって形成されます$n$サイズの各順列のすべての可能な位置に配置$n-1$。 辞書編集順では、これらのブロックは、サイズの固定プレフィックスごとに、非常に規則的な構造で表示されます。$n-1$、のすべての挿入$n$決定的なパターンに従います。 

重要な結果は、連結されたシーケンスが任意ではなく、内部の重複が均一に動作する構造化されたブロックで構成されていることです。 これにより、レベルで導入された新しい部分文字列について推論できるようになります。$n$レベルと比べて$n-1$、シーケンス全体について直接推論するのではなく。 

最終的な洞察は、階乗構造と挿入位置によって駆動される反復に従って、個別のサブ配列の数が増加するということです。 増加するたびに、$n$制御された数の新しい個別の部分文字列に寄与し、この寄与は、以前の値に対する階乗和と接頭辞和を使用して閉じた形式で表現できます。 

したがって、問題は、大規模なシーケンスにわたる部分文字列の列挙から、さまざまなシーケンスにわたる組み合わせ反復へと縮小されます。$n$。

 ## アルゴリズムのチュートリアル

 この解決策は、順列サイズを増やすときに導入される個別のサブ配列の数を追跡することに基づいています。 

1. の答えを初期化します。$n=1$。 順序は$[1]$したがって、サブ配列は 1 つだけ存在します。 
2. 順列がサイズからどのように増加するかを観察します$k-1$サイズに合わせて$k$。 サイズの各順列$k$要素を挿入して形成されます$k$サイズの順列のすべての位置に$k-1$。 これにより、$k$順列ごとの構造バリアント。 
3. 挿入ごとに、必ず新しい要素を含む新しい部分文字列が導入されます。$k$。 これらの部分文字列は一意であるため、$k$は最大の要素であり、前のレベルには表示されない区切り文字として機能します。 
4. レベルごとに$k$、導入される新しい個別のサブ配列の数は、挿入境界をまたがるセグメントを選択できる方法の数に比例します。 これは、階乗増加とポジションにわたる線形拡張に依存する項に正確に寄与します。 
5. 階乗という 2 つの実行量を維持します。$k!$モジュロ$998244353$、そして蓄積された答え。 ステップで$k$、両方を効率的に更新します。 
6. すべてを処理した後の最終的な答え$k \le n$が返されます。 

重要な構造上の考え方は、すべての新しい最大要素がその境界を越える部分文字列のあいまいさを防ぐ方法で置換空間を分割し、レベルごとに独立して寄与をカウントできるようにするということです。 

### なぜ効果があるのか

 最終的な連結内のすべてのサブ配列は、それに含まれる最大値と一意に関連付けることができます。 その最高値は、関連する置換ブロック構造内に 1 回だけ出現し、一意の挿入構造を決定します。 これにより、二重カウントが防止されます。2 つの異なるサブ配列は、同一のシーケンスでない限り、「最大要素位置 + 周囲の構造」への同じ分解を共有できません。 この不変条件により、レベルごとの寄与の合計がすべての個別のサブ配列を正確に 1 回カウントすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    
    # base case
    if n == 1:
        print(1)
        return

    fact = 1
    ans = 1

    # We maintain contribution per level
    # derived from insertion structure of permutations
    for k in range(2, n + 1):
        fact = fact * k % MOD
        
        # new subarrays introduced at level k
        # (structural contribution from inserting k)
        ans = (ans * k + fact) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、階乗増加と累積カウントを同時に追跡します。 再発`ans = ans * k + fact`レベルで 2 つの効果を反映します$k$: 新しい最大値要素を挿入して以前のすべてのサブ配列を拡張し、この新しい最大値を含む必要があるまったく新しいサブ配列を追加します。 

階乗項はそのレベルでの順列の数を考慮し、さまざまな挿入位置からの寄与を正しく重み付けすることを保証します。 

更新の順序は重要です。階乗は繰り返しで使用される前に更新されるため、常に次のように対応します。$k!$反復時$k$。

import sys, io

MOD = 998244353

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input().strip())
    if n == 1:
        print(1)
        return
    fact = 1
    ans = 1
    for k in range(2, n + 1):
        fact = fact * k % MOD
        ans = (ans * k + fact) % MOD
    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

 ## 特殊なケース

 のために$n=1$の場合、シーケンスには要素が 1 つだけ含まれ、部分配列が 1 つだけ存在します。 アルゴリズムはループに入る前にすぐに 1 を返すため、間違った階乗更新や反復更新が適用されることはありません。 

非常に大きい場合$n$、階乗は急速に増加しますが、常に剰余が取られます。$998244353$、値が制限されたままであることを保証します。 各反復は前の状態にのみ依存するため、累積エラーやオーバーフローは発生しません。 

からの移行$n=2$に$n=3$これは、拡張と新しいサブ配列の導入の両方が相互作用する最初の重要なケースです。 階乗および累積された答えが同じ反復で更新され、順列カウントと部分文字列展開構造の間の依存関係が維持されるため、反復ではこれが正しく処理されます。
