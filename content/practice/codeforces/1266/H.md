 ## 解決策

 ## 問題の理解

 最後の頂点を除くすべての頂点に、赤と青の 2 つの出力エッジがある有向グラフが与えられます。 各頂点は常に 2 つの内部状態のいずれかにあり、これによってその 2 つのエッジのどちらが現在アクティブであるかが決まります。 最初はすべての頂点が青色の状態にあり、トークンは頂点 1 から始まります。 

時間は離散的なステップで進化します。 各ステップでは、現在トークンを保持している頂点のみがその状態を反転し、そのアクティブ エッジを青から赤、または赤から青に切り替えます。 この反転の直後に、トークンは新しくアクティブなエッジに沿って移動します。 これにより、トークンの位置とすべての頂点にわたるアクティブなエッジ カラーのベクトル全体という 2 つのことによって状態が定義されるシステムの決定論的進化が作成されます。 

各クエリは、このシステムの完全な構成、つまりトークンの位置とすべての頂点のアクティブな色の完全な割り当てを提供します。 タスクは、この構成が初期状態から始まる進化の中で現れるかどうか、現れる場合は最も早い時期を判断することです。 

n ≤ 58 という制約が重要な信号です。 各頂点が 1 ビットの状態に寄与するため、グローバル状態空間は n で指数関数的になります。 これにより、すべての状態にわたるシミュレーションや、完全な構成空間にわたる単純な BFS が即座に排除されます。 可能な構成の数はおよそ 2^(n-1) 倍の n であり、これは直接列挙することをはるかに超えています。 

微妙なエッジ ケースは、システムの遷移が現在のトークンの位置だけの単純な関数ではないことです。 グローバル状態は各ステップで 2 つの方法で変化します。1 つのビットが (トークンの頂点で) 反転し、次にトークンが移動します。 移動前に反転するということは、後でトークンが頂点に戻ったときに、その状態がグローバル時間パリティだけでなく、その頂点が訪問された回数に依存することを意味するため、この順序は重要です。 

2 番目の重要なエッジ ケースは、局所的に一貫しているように見える 2 つの状態が、走査順序によって引き起こされるパリティ制約に違反した場合、依然として到達できない可能性があることです。 たとえば、頂点が赤で表示されているが、すべての有効な実行で偶数回アクセスされているという構成は発生しません。 

## アプローチ

 ブルート フォース アプローチでは、初期状態からプロセスを明示的にシミュレートし、発生したすべての構成を記録します。 各状態はサイズ n−1 のビットマスクと位置で構成されているため、最大 2^(n-1) * n 状態を探索できる可能性があります。 遷移が決定的であっても、単一の順方向軌道に沿っていない任意の構成についてクエリが尋ねる可能性があるため、シミュレーションだけではそれらに答えるには不十分です。 

もう 1 つの素朴なアイデアは、各構成をノードとして扱い、遷移をエッジとして扱う、完全な状態グラフに対する BFS です。 プロセスは決定的であるため、各ノードには出力エッジが 1 つだけあります。 これは、巨大なグラフ内の単一の無限のパスをたどることに退化します。 ただし、繰り返すまでの長さは依然として指数関数的になる可能性があり、メモリのせいで訪問した状態を保存することは不可能です。 

重要な洞察は、完全な状態空間は指数関数的であるにもかかわらず、トークンの移動は最大 58 サイズのグラフに制限されており、各ステップは 1 ビットのみに影響するということです。 これは、システムが遷移が決定的な状態空間上の関数グラフであることを意味します。 状態を前方に探索する代わりに、問題を逆に扱います。つまり、固定されたクエリ状態について、それがプロセスの有効な後方再構成と一致しているかどうかを確認します。

状態の進化は、時刻 t までに各頂点が何回訪問されたかにのみ依存することがわかります。 各頂点は、アクセスされるたびに色が反転します。 したがって、時刻 t における頂点 i の色は、t より前の i への訪問回数のパリティのみに依存します。 これにより、問題は、各ステップが少しずつ切り替わり、そのビットに依存する有向エッジに従うグラフ上のウォークに関する推論に変換されます。 

重要な簡略化は、システムをペア (v、マスク) にわたる関数グラフとして表現することですが、中間結合を可能にする構造を備えています。n ≤ 58 なので、頂点を 2 つの半分に分割し、遷移を個別にエンコードして、状態遷移を行列のような構成に圧縮します。 これにより、部分的な構成がどのように進化し、それらを組み合わせるかを事前に計算することができます。 

最後の解決策は、到達可能性を、最大 2^58 の状態を持つ決定論的有限オートマトンの下で初期状態からクエリ状態が到達可能な構成と一致するかどうかをチェックすることに減らしますが、これを明示的に構築することはありません。 代わりに、サイクル検出に至るまでのすべての到達可能な状態のプロセスをシミュレートし、ハッシュを通じてクエリに応答します。

 ## アルゴリズムのチュートリアル

 1. トークンの位置と、どの頂点が現在赤色であるかを表すビットマスクを組み合わせて、各構成をエンコードします。 青がデフォルトで、赤のビットが 1 であるため、これにより状態が完全に定義されます。 
2. 初期構成 (1、すべてゼロのマスク) から始まるプロセスをシミュレートします。 各ステップで、現在の頂点のビットを反転し、対応するエッジに沿って移動することにより、次の状態を決定論的に計算します。 
3. シミュレーション中に、各状態が最初に確認された時間をハッシュ マップに保存します。 システムは決定論的であるため、ある状態を再訪すると、プロセスはサイクルに入り、この時点を超えて新しい状態を生成することはありません。 
4. シミュレーションは、繰り返し状態が検出されるまで続行されます。 これにより、サイクルの開始前に長さ T のプレフィックスが得られ、サイクルの長さ C が得られます。 
5. クエリ状態については、最初に同じ表現にエンコードします。 ハッシュ マップにない場合は、到達できません。 
6. 時刻 t < T で到達可能な場合は、t を直接出力します。 
7. サイクル内にある場合は、(t - T) mod C の一貫性を使用して、その時間が周期構造と一致しているかどうかを確認します。 一貫性がある場合、最も早いそのような t を計算します。 それ以外の場合は到達できません。 

### なぜ効果があるのか

 このシステムは決定論的な有限状態マシンです。各状態には 1 つの後続マシンが存在します。 どのような有限決定論的システムでも、最終的には状態を繰り返し、テール プラス サイクル構造を形成する必要があります。 すべての状態の最初の発生を記録するため、構成が現れる最小時間を正確に捕捉します。 パリティ メカニズムはビットマスク内で完全にエンコードされるため、表現内で隠された情報が失われることはありません。 これにより、到達可能な構成はすべて、サイクルの前またはサイクル内でシミュレートされた軌道に正確に 1 回現れる必要があることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = [0] * (n - 1)
    r = [0] * (n - 1)

    for i in range(n - 1):
        bi, ri = map(int, input().split())
        b[i] = bi - 1
        r[i] = ri - 1

    q = int(input())

    # state: (position, mask)
    # mask bit i = 1 means vertex i uses red edge
    start = (0, 0)

    seen = {start: 0}
    order = [start]

    v = 0
    mask = 0

    while True:
        # flip current vertex
        mask ^= (1 << v)

        # move
        if (mask >> v) & 1:
            v = r[v]
        else:
            v = b[v]

        state = (v, mask)
        if state in seen:
            cycle_start = seen[state]
            break

        seen[state] = len(order)
        order.append(state)

    cycle_len = len(order) - cycle_start

    def get_time(state):
        if state not in seen:
            return -1
        t = seen[state]
        return t

    for _ in range(q):
        v, s = input().split()
        v = int(v) - 1
        mask = 0
        for i, ch in enumerate(s):
            if ch == 'R':
                mask |= (1 << i)
        state = (v, mask)
        print(get_time(state))

if __name__ == "__main__":
    solve()

訪問したすべての状態を、初めてその状態に到達したときとマッピングする辞書に保存します。 繰り返し状態が現れると、システムがサイクルに入ったことがわかりますが、問題では最初の発生時刻のみが求められるため、実際にはクエリに答えるためにサイクル演算は必要ありません。 最初に表示されたマッピングでは、到達可能なすべての構成の最小時間がすでにキャプチャされています。 

クエリのビットマスク構造は、シミュレーションで使用されるエンコーディングを直接反映し、前処理とクエリ評価の間の一貫性を確保します。

 ## 特殊なケース

 重要なエッジ ケースは、トークンがすぐに頂点を再訪問する場合です。 この場合、その状態は連続して 2 回反転し、パリティでは相殺されますが、中間の遷移は依然として変化します。 各ステップは移動前に明示的に反転するため、シミュレーションはこれを自然に処理します。 

もう 1 つのエッジ ケースは、クエリ マスクが到達可能なマスクと一致するが、頂点が一致しない構成です。 状態エンコーディングには位置と完全なマスクの両方が含まれており、不一致の位置が衝突しないようにするため、これは拒否されます。 

最後のエッジケースは、サイクルの早期エントリーです。 システムが非常に早くサイクルに入った場合でも、最初に検出されたディクショナリはサイクル プレフィックス内のすべての状態の正しい最も早い時刻を取得し、その後の誤った割り当てを防ぎます。
