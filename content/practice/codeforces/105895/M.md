 ## 解決策
 ## 問題の理解

 最大 8 × 8 の小さなグリッドが与えられ、各セルが許可または禁止されます。 許可されたセルには猫が含まれており、次のような文字がマークされています。`Y`、禁止されたセルには がマークされています。`N`。 タスクは、配置された 2 つの猫娘が水平方向または垂直方向に隣接しないという制限の下で、許可されたセルにできるだけ多くの猫娘を配置することです。 

これは基本的に、いくつかの頂点が削除されたグリッド グラフ上の最大独立集合問題です。 各セルが使用可能な場合は頂点となり、エッジは直交する隣接セルを接続します。 両方の端点が選択されているエッジがないように、使用可能な頂点の最大のサブセットを選択したいと考えています。 

制約 n、m ≤ 8 が重要な構造シグナルです。 グリッドには最大 64 個のセルがあり、枝刈りを行わずにセルのすべてのサブセットに対する一般的な指数関数的検索が即座に除外されます。 単純なサブセット列挙では最大 2^64 の状態が考慮されますが、これは積極的な枝刈りを行ったとしても大きすぎます。 同時に、幅が小さいことは、行または列にわたるプロファイル動的プログラミングまたはビットマスク DP を強く示唆しています。 

貪欲な直感を打ち破る微妙なケースは、局所的な最適配置が将来の高密度領域をブロックする場合です。 たとえば、2x3 のすべての場合、`Y`グリッドでは、市松模様のパターンで貪欲に配置すると、行間で密度をシフトする構成を見逃す可能性があります。 

もう 1 つの特殊なケースは、すべてのセルが`N`対角線のような疎な構造を除いて。 どのソリューションでも、隣接関係は水平および垂直のみであることを考慮する必要があるため、斜めの配置は干渉せず、すべて許可される必要があります。 

## アプローチ

 ブルート フォース手法では、グリッド セルのすべてのサブセットを試し、すべてのペアをスキャンするか隣接制約をチェックすることで妥当性をチェックします。 これは概念的には単純です。サブセットを選択し、選択した 2 つのセルが隣接していないことを確認し、有効であればサイズをカウントします。 問題の定義を直接エンコードしているため、正確性は簡単です。 

ただし、サブセットの数は 2^(n・m) と増加します。 8×8 グリッドの最悪の場合、これは 2^64 となり、まったく実行不可能です。 たとえ有効性チェックがサブセットごとに O(64) であるとしても、総作業量は天文学的に膨大になります。 

重要な観察は、隣接関係がローカルであり、グリッドが狭いということです。 すべてのセルを個別に決定するのではなく、行ごとに処理し、各行の選択をビットマスクとしてエンコードします。 行の有効な構成は、選択された 2 つのセルが水平方向に隣接しない構成です。 この場合、連続する行間の互換性により、垂直方向に隣接するセルが両方とも選択されなくなります。 

これにより、問題は行にわたるプロファイル DP に変換されます。ここで、各状態は行の有効なビットマスクであり、遷移は隣接する行のみに依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^(nm) · nm) | O(nm) | 遅すぎる |
 | ビットマスク状態を持つ行 DP | O(n · 2^m · 2^m) | O(2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各行を独立して扱い、長さ m のビットマスクを使用して行内の選択を表します。 その列に猫娘を配置すると、ビットは 1 になります。 

1. 各行について、0 から 2^m − 1 までのすべてのビットマスクを列挙し、行内で有効なもののみを保持します。 マスクは、隣接する列に 2 人のキャットガールを配置しない場合、つまり、連続する 2 つのビットが 1 にならない場合に有効であり、次の内容を含むセルにのみキャットガールを配置します。`Y`。 これにより、水平方向の隣接関係に違反したり、禁止されたセルに配置したりすることがなくなります。 
2. すべての行について、どのマスクがその行のグリッド制約と互換性があるかを事前計算します。 各行に有効なマスクのリストと、それに対応する選択されたセルの数を保存します。 
3. DP を定義します。ここで、dp[row][mask] は、この行に構成マスクを選択した場合にこの行まで配置できるキャットガールの最大数です。 
4. dp[0][mask] をすべての有効なマスクのマスク内の設定ビット数に設定して、行 0 の dp を初期化します。 
5. 後続の各行について、すべての有効な前のマスクからすべての有効な現在のマスクに遷移します。ただし、2 つのマスクが垂直方向に重なり合わない場合に限ります。 これは、両方のマスクに 1 を持つ列がないことを意味します。これは、同じ列の隣接する行に猫娘が配置されるためです。 
6. dp[row][cur_mask] を、dp[row-1][prev_mask] と cur_mask の Popcount の互換性のある以前のマスクすべての最大値として更新します。 
7. 答えは、すべての dp[last_row][mask] の最大値です。 

これを効率的に行うことができる理由は、各行が前の行のみに依存するため、状態がすべてのセルにわたって指数関数的になるのではなく、管理可能な 2^m の空間に収まるからです。 

### なぜ効果があるのか

 DP 状態は、将来の決定に必要な唯一の関連履歴 (前の行で選択された構成) を完全にキャプチャします。 以前の行は、すでに DP 値に格納されている合計カウントへの寄与を通じてのみ将来に影響を与えます。 互換性チェックにより、垂直方向または水平方向の隣接性違反が発生しないように強制されるため、すべての遷移の有効性が維持されます。 すべての有効なグローバル配置は行マスクの 1 つのシーケンスに正確に対応し、そのようなシーケンスがすべて考慮されるため、最大値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid_masks(row_str, m):
    masks = []
    for mask in range(1 << m):
        ok = True
        for j in range(m):
            if (mask >> j) & 1:
                if row_str[j] == 'N':
                    ok = False
                    break
                if j > 0 and (mask >> (j - 1)) & 1:
                    ok = False
                    break
        if ok:
            cnt = bin(mask).count("1")
            masks.append((mask, cnt))
    return masks

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    row_masks = [valid_masks(grid[i], m) for i in range(n)]

    prev = {0: 0}

    for i in range(n):
        curr = {}
        for cmask, ccnt in row_masks[i]:
            best = 0
            for pmask, pval in prev.items():
                if pmask & cmask == 0:
                    best = max(best, pval + ccnt)
            curr[cmask] = max(curr.get(cmask, 0), best)
        prev = curr

    print(max(prev.values()))

if __name__ == "__main__":
    solve()
```このソリューションは、行ごとに、水平方向の隣接性を尊重し、禁止されたセルを回避するすべての構成を構築します。 DP辞書`prev`は、前の行の各マスクに対して達成可能な最良の値を保存します。 

移行チェック`pmask & cmask == 0`、垂直隣接制約が列ごとに適用されます。 両方の行に同じ列に猫娘が配置されている場合、それらは垂直方向に隣接することになりますが、これは禁止されています。 

辞書ベースの DP は、無効な状態の反復を完全に回避するため、制約が小さいため実装が単純になります。 m ≤ 8 であるため、マスクの数は 1 行あたり最大 256 であり、非常に管理しやすいです。 

## 実用的な例

 小さな 3×3 グリッドを考えてみましょう。```
YYY
YNY
YYY
```行ごとに DP を追跡します。 

### 行0

 | マスク | 有効 | カウント | DP |
 | --- | --- | --- | --- |
 | 000 | はい | 0 | 0 |
 | 001 | はい | 1 | 1 |
 | 010 | はい | 1 | 1 |
 | 100 | はい | 1 | 1 |
 | 101 | はい | 2 | 2 |
 | 110 | はい | 2 | 2 |

 ### 行 1 (中央の行は中央がブロックされています)

 有効なマスクには、センター ビットが設定されているマスクは含まれません。 

| マスク | 有効 | カウント |
 | --- | --- | --- |
 | 000 | はい | 0 |
 | 001 | はい | 1 |
 | 010 | いいえ | - |
 | 100 | はい | 1 |
 | 101 | はい | 2 |
 | 110 | いいえ | - |

 トランジションは互換性のあるマスクを組み合わせます。 たとえば、行 1 のマスク 101 は、列の重複のため行 0 のマスク 101 とペアにすることはできませんが、制約に応じて 010 または 001 とペアにすることができます。 

DP は、互換性のある合計の最大値を取得することによって進化します。 

### 行 2

 行 0 と同じですが、遷移は行 1 の結果のみに依存します。 

このトレースは、決定が行ごとに局所化されており、競合は列の重複によってのみ発生することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · 4^m) | 各行について、すべての有効なマスクを以前のすべてのマスクに対して試行します (それぞれ最大 2^m | )。 
| スペース | O(2^m) | 前の行の状態についてのみ DP を保存します。 

m ≤ 8、4^m ≤ 65536、および n ≤ 8 であるため、合計作業量は 2 秒の制限に対して十分に小さいです。

 ## 特殊なケース

 すべての行にはマスク 0 のみが有効であるため、完全にブロックされたグリッドはきれいに処理されます。 DP はゼロを超えて増加することはなく、0 を返します。 

単一行グリッドは、行内の隣接しないセルを選択することになります。 行マスクの生成では連続ビットが強制されないため、DP は 1D の最大独立セットに正しく折りたたまれます。 

みたいな斜めの模様```
YNN
NYN
NNY
```垂直隣接が決してトリガーされないようにします。 各行は独立して 1 つの配置を許可し、列の重複は決して発生しないため、DP は 3 つの配置すべてを累積します。
