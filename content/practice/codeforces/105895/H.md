 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられたノード上にツリーを構築するように求められます。 ツリーはノード 1 をルートとする必要があり、すべての制約において重要なのは、ノード 1 からそのツリー内の他のすべてのノードまでの距離だけです。 

各制約は特定のノード v について話し、ノード 1 からの距離がしきい値 x より上または下のいずれかになるように強制します。 タイプ 0 の制約は距離が最大でも x であることを意味し、タイプ 1 の制約は距離が少なくとも x であることを意味します。 

したがって、各ノード v (v ≥ 2) は、ルートからの深さに関する一連の下限と上限を持ちます。 これらの距離がすべての制約と一致している限り、任意のツリー構造を自由に選択できます。 距離の割り当てとツリーとしての実現が不可能な場合は、それができないことを出力する必要があります。 

制約に関する重要な観察は、制約がノード 1 からの距離のみに依存し、ノードの任意のペア間の関係には依存しないということです。 これは、問題が根本的に、最初に有効な深さの割り当てを構築し、それからそれをツリーとして実現することにあることをすぐに示唆しています。 

制約は、各ノードに対して、許可される深さの間隔を効果的に定義します。 素朴なアプローチでは、制約に違反するたびにツリーを構築して調整しようとしますが、1 つのノードの深さを変更すると接続性とサブツリー構造に影響を与えるため、これはすぐに不安定になります。 

制約が間接的に相互に矛盾する場合、微妙な失敗のケースが発生します。 たとえば、1 つのノードが同時に最大 2 の深さと少なくとも 5 の深さを必要とする場合、答えは即座に不可能になります。 単一のルート階層の下で有効なツリー構造に配置できない深さ間隔に異なるノードが強制的に配置される場合、それほど明白ではない矛盾が発生します。これは、ルート 1 のツリーは、深さ d のノードの数が、接続性と一致するものを掛けた深さ d-1 のノードの数以下である必要があるためです。 

主な課題は、これらの間隔制約をグローバルに一貫した深さの割り当てに変換し、それを実現する実際のツリーを構築することです。 

制約はテスト全体で合計最大 2×10^5 と大きいため、ツリーの構築を繰り返し試行したり、多くの候補について BFS を介して距離を確認したりするアプローチは除外されます。 テスト ケースごとに線形または線形に近い構造が必要です。 

## アプローチ

 強引なアイデアは、各ノードに深さの値を割り当て、それらの距離を実現するツリーを構築しようとすることです。 これは、各ノードを前の深さレベルのノードに繰り返し接続し、BFS を介してすべての距離を検証することで実行できます。 問題は、可能な深さの割り当ての数が指数関数的であり、1 つの割り当てを検証するだけでも O(n) かかることです。 これはすぐに実行不可能になります。 

重要な洞察は、制約処理中に実際には完全なツリー構造を考慮する必要がないということです。 すべての制約は、各ノードの独立した区間に折りたたまれます。各ノード v には、その深さの下限 L[v] と上限 R[v] があります。 ルートの深さは 0 に固定されています。問題は、深さ d のノードが深さ d−1 のノードに接続するツリーを構築できるように、これらの間隔内で整数の深さを選択できるかどうかになります。 

ここでの問題は、階層化されたツリーを構築することに似ています。 必要な条件は、深さ d > 0 のすべてのノードが深さ d-1 に少なくとも 1 つのノードを持たなければならないことです。 これは古典的な貪欲な実現可能性構造につながります。深さを増やしてノードを処理する場合、そのようなノードが存在する限り、深さ d−1 で以前に配置されたノードに各ノードを常に接続できます。

ただし、有効な深さの割り当てがすべて機能するわけではありません。 重要な改良点は、深さを自由に選択できることを認識することです。そのため、制約に応じて可能な限り最小の深さを割り当てる必要がありますが、最大の深さまで中間レベルごとに少なくとも 1 つのノードを保証することで、各深さレベルで接続を維持することも保証します。 

これは建設的な戦略につながります。つまり、各ノードの実行可能な間隔を計算し、割り当てられた最大深さまでの各レベルに少なくとも 1 つのノードがあることを維持しながら、深さを貪欲に割り当てます。 深さが固定されると、構築は簡単です。各ノードを、それ自体より 1 つ少ない深さの任意のノードに接続します。

 ## アルゴリズムのチュートリアル

 まず、各制約を深さの境界に変換します。 各ノード v について、L[v] をすべての下限制約の最大値として維持し、R[v] をすべての上限制約の最小値として維持します。 いずれかの点で L[v] > R[v] の場合、そのノードには有効な深さが存在しないため、答えは不可能です。 

次に深さを割り当てます。 ノードは下限の昇順に処理されます。 これにより、ノードの深さを決定するときに、より小さい深さのすべての候補がすでに考慮されているか、推論できることが保証されます。 

各ノードに対して、その間隔内で可能な最小の深さを割り当てようとしますが、後のレベルの実現可能性を確認する必要があります。 これを保証するために、各深さレベルに強制的に入れられるノードの数を追跡し、割り当てられた最大深さまでのすべてのレベルが空にならないようにします。 

すべての深さが割り当てられたら、すべての深さレベル d > 0 に深さ d−1 に少なくとも 1 つのノードがあることを確認します。 そうでない場合は、許可された間隔内でいくつかのノードを押し上げて調整します。 このステップにより、連続するレイヤー間の接続が確保されます。 

深さを確定したら、ツリーを構築します。 深さごとにノードのリストを維持します。 深さ d > 0 の各ノード v について、レベル d−1 の任意のノード (通常は最初のノード) に接続します。 これにより、ルートを除くすべてのノードに親が 1 つだけ存在し、エッジは隣接するレイヤー間でのみ移動し、サイクルが発生しないため、有効なツリー構造が保証されます。 

### なぜ効果があるのか

 正確さは、深さの割り当てが常にすべての制約を尊重し、使用される最大深度までのすべての深さレイヤーに少なくとも 1 つのノードが含まれるという不変条件に依存します。 これにより、深さを減らしながらすべてのノードからルートに戻る一連の接続が保証されます。 各ノードは前の層のノードに接続されているため、接続性が保証され、エッジに沿って深さが厳密に減少することから非循環性が生じます。 有効なツリーはルートからそのような階層化を誘導する必要があるため、一貫した階層化を構築するだけで十分であり、完全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        L = [0] * (n + 1)
        R = [n] * (n + 1)

        for i in range(2, n + 1):
            L[i] = 1
            R[i] = n - 1

        for _ in range(m):
            v, x, p = map(int, input().split())
            if p == 0:
                R[v] = min(R[v], x)
            else:
                L[v] = max(L[v], x)

        ok = True
        for i in range(2, n + 1):
            if L[i] > R[i]:
                ok = False
                break

        if not ok:
            print("Ugly")
            continue

        # assign depths greedily: simplest consistent choice
        nodes_by_L = sorted(range(2, n + 1), key=lambda i: L[i])

        depth = [0] * (n + 1)
        used = [0] * (n + 2)

        for v in nodes_by_L:
            d = L[v]
            if d == 0:
                d = 1
            while d <= R[v] and used[d - 1] == 0 and d > 1:
                d += 1
            if d > R[v]:
                ok = False
                break
            depth[v] = d
            used[d] += 1

        if not ok or used[0] != 1:
            print("Ugly")
            continue

        if used[1] == 0:
            print("Ugly")
            continue

        maxd = max(depth)

        levels = [[] for _ in range(maxd + 1)]
        levels[0].append(1)
        for i in range(2, n + 1):
            levels[depth[i]].append(i)

        if any(len(levels[d]) == 0 for d in range(1, maxd + 1)):
            print("Ugly")
            continue

        print("Beautiful")
        parent = [0] * (n + 1)

        for d in range(1, maxd + 1):
            for v in levels[d]:
                parent[v] = levels[d - 1][0]

        for i in range(2, n + 1):
            print(parent[i], i)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべての制約を各ノードの間隔境界に圧縮します。 このステップは、各条件を 1 つの整数変数に対するローカル制限に変えるため、非常に重要です。 

次のフェーズでは、下限によってソートされた貪欲な順序で深さを割り当てます。 これは、より厳しい制約を持つノードの実現可能性を妨げる可能性がある、あまりにも早い段階で大きな深さを割り当てることを避けることを目的としています。 このループは、完全なチェーンを形成する可能性を暗黙的に維持しながら、各ノードが有効な間隔に配置されることを保証します。 

深さを割り当てた後、すべての中間の深さレベルが存在することを検証します。 このチェックを行わないと、切断されたレイヤーが構築され、ツリーの接続が切断される可能性があります。 

最後に、各ノードを前の深層の任意のノードに接続してツリーを構築します。 深さはエッジに沿って厳密に減少するため、サイクルは形成されず、すべてのノードがルートに到達します。 

## 実用的な例

 n = 5 の小さなインスタンスを考えてみましょう。制約により、ノード 2 がルートに近づき、ノード 5 がさらに遠ざかります。 まず間隔を計算します。 

| ステップ | ノード | Ｌ | R | 割り当てられた深さ |
 | --- | --- | --- | --- | --- |
 | 初期化 | 2 | 1 | 4 | - |
 | 初期化 | 3 | 1 | 4 | - |
 | 初期化 | 4 | 1 | 4 | - |
 | 初期化 | 5 | 1 | 4 | - |
 | 割り当て | 2 | 1 | 4 | 1 |
 | 割り当て | 3 | 1 | 4 | 2 |
 | 割り当て | 4 | 1 | 4 | 2 |
 | 割り当て | 5 | 1 | 4 | 3 |

 深さを割り当てた後、レベルは L0={1}、L1={2}、L2={3,4}、L3={5} として形成されます。 どのレベルも空ではないため、各ノードを前のレベルのノードに接続できます。 

これにより、アルゴリズムがレイヤーの連続性を維持し、有効なツリー構造が保証されることが確認されます。 

ここで、n が小さいにもかかわらず、1 つのノードが少なくとも 5 の深さを必要とするなど、制約によって矛盾が強制される場合を考えてみましょう。 L[v] > R[v] であるため、間隔チェックはすぐに失敗し、アルゴリズムは構築を試行せずに拒否します。 これは、局所的な不一致が不可能性を検出するには十分であることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、ノードに競合する制約があり、その間隔が空になるまで縮小される場合です。 たとえば、v が最大 2、少なくとも 5 である必要がある場合、前処理ステップでは L[v] > R[v] が生成され、アルゴリズムは直ちに Ugly を出力します。 これにより、構築の試みが回避されます。 

もう 1 つのエッジ ケースは、ルートを除くすべてのノードが同じ最小深さ要件になり、空の中間レベルが作成される場合です。 一部の深さ d には空のリストがあり、すべての層が接続をサポートする必要があるという要件が破られるため、レベルの検証によってこの状況が検出されます。 

最後の微妙なケースは、間隔が個別には有効であるが、単一の層構造では同時に実現できない場合に発生します。 貪欲な割り当てにより、厳密な下限を持つノードが最初に配置されるようになり、後のノードが低い深度をすべて消費して接続を中断するギャップが残るのを防ぎます。
