 ## 問題の理解

 一連の整数が与えられており、目的は特定の演算を使用してすべての要素を等しくすることです。 各操作はインデックスを選択して実行されます$i$、次に 3 つのエフェクトから 1 つを選択します。 最初の効果のみが変化します$a_i$2 番目の効果は、次の右側に表示されます。$i$、およびすべての要素は厳密に次の値よりも大きい$a_i$3 番目の効果は の左側にあります。$i$、およびすべての要素は厳密に以下より小さい$a_i$1増加します。 

重要な点は、各操作はある方向ではグローバルですが、選択したピボット値との比較が条件であるということです。$a_i$。 タスクは、各テスト ケースのすべての要素を等しくするために必要なそのような操作の最小数を決定することです。 

入力サイズの制約により、最大で$10^5$すべてのテスト ケースにわたる要素の合計。 これにより、インデックスのペアまたはトリプルに対する 2 次または 3 次の推論が即座に除外されます。 各操作自体が影響を受ける可能性があるため、操作をシミュレートしたり、グローバルな効果を単純に再計算しようとしたソリューションは失敗します。$n$要素、そしてそれを繰り返すだけでも$O(n)$時間が大きくなりすぎる。 

微妙な問題は、操作が純粋にローカルではないことです。 1 回の移動で、相対的な順序に応じて多くの値がシフトされる可能性があるため、貪欲なシミュレーションの信頼性が低くなります。 

よくある失敗例は、操作が選択したインデックスにのみ影響を与えると想定していることに起因します。 たとえば、1 つを除いてすべての要素が等しい場合、外れ値を局所的に修正するのが最適に見えるかもしれませんが、実際には、操作により他の多くの値が意図せずにシフトされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、プロセスを直接シミュレートします。 どの状態からでも、すべてのインデックスとすべての操作タイプを試し、それを配列に適用し、状態全体にわたって最短パス検索を実行できます。 これは理論的には正しいです。各操作には単位コストがあるため、配列空間に対する BFS またはダイクストラは最小ステップ数を見つけます。 ただし、各配列エントリは大きく変化する可能性があり、値の範囲内で状態の数が指数関数的に増加するため、状態空間は膨大になります。 単一の状態を保存するだけでもすでに$O(n)$, したがって、これはまったく実行不可能です。 

重要な洞察は、シーケンスを独立した値として考えるのをやめ、代わりに演算を、選択したしきい値に対する相対的な移動質量として解釈することです。 各操作は基本的に、絶対値だけではなく、配列の順序構造と相互作用します。 目標の最終値を選択することを想像すると$x$に達するには、すべての要素を調整する必要があります。$x$、コストは「上向き」と「下向き」の移動が何回必要かによって決まります。 

重要な観察は、正しい答えは値の位置ではなく、値の分布のみに依存するということです。 方向性操作を正しく構成すると、調整の増加と減少の間の寄与を効果的にキャンセルできます。 演算の効果を再定式化した後、問題は、必要な全体的な調整量と、その調整を配列構造全体にどれだけ効率的に伝播できるかを計算することに帰着します。 

候補の最終値に対する貢献度の観点から書き換えられると、最適な戦略はバランスの問題になります。実質的には純増加分と純減少分を支払うことになりますが、その一部は 2 回目と 3 回目の操作を通じてポジション間で共有できます。 これにより、値が正規化されてグループ化されると、リニア スキャン ソリューションが得られます。

 ## アルゴリズムのチュートリアル

 候補となる最終値を固定することで問題を再構成します$x$。 すべての要素は次のようにならなければなりません$x$、それでそれぞれ$a_i$必要な調整に貢献します$|a_i - x|$ただし、操作は構造化された方法で複数の要素に影響を与える可能性があるため、コストは単純にこの合計ではありません。 

1. 配列をソートして、位置ではなくグローバル構造を推論できるようにします。 ソートにより、増加と減少を単調なシーケンス全体の流れとして解釈できるようになります。 
2. 目標値を検討する$x$。 配列を以下の要素に分割します$x$そしてそれよりも大きい$x$。 上昇需要の合計は次の合計です。$x - a_i$以下の要素の上に$x$、下降需要は次の合計です。$a_i - x$上の要素の上に$x$。 これら 2 つの量は、どれだけの質量を転送する必要があるかを表します。 
3. 各操作は、ピボットの片側にあるすべての要素に影響を与えながら、値を上または下に押し出すものとして解釈できることに注目してください。 これは、それらの調整の方向が一致している場合に限り、1 つの操作で複数のユニット調整を同時に実行できることを意味します。 
4. 重要な構造の簡素化は、選択したときに最適なコストが達成されることです。$x$これらの流れのバランスをとるために。 最高の$x$は既存の配列値の 1 つです。これは、ギャップ間でターゲットを移動しても、共有キャンセルが改善されずに不均衡が増大するだけであるためです。 
5. 各候補者について$x$、指向性伝播によって生じるオーバーラップを考慮した上で、必要な上向きおよび下向きの調整の最大値としてコストを計算します。 最適な答えは、すべての候補の最小値です。 
6. ソートされた配列のプレフィックス合計を事前計算して、各候補が$x$で評価できます$O(1)$、全体的な$O(n \log n)$仕分けによる解決策。 

### なぜ効果があるのか

 このアルゴリズムは不変式に依存しています。つまり、どの操作も一方向に 1 単位の効果的な補正に寄与しますが、選択したピボットの同じ側にある場合は、複数の局所的な不均衡を同時に軽減する可能性があります。 並べ替えと集計により、同じ方向の不均衡に寄与するすべての要素が確実にグループ化されるため、操作の共有効果がプレフィックス合計によって完全に把握されます。 コスト関数は可能なターゲット値に対して凸であるため、配列値に制限すると全体的な最適値が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + a[i]
        
        total = prefix[n]
        ans = float('inf')
        
        for i in range(n):
            x = a[i]
            
            left_cost = x * i - prefix[i]
            right_cost = (total - prefix[i + 1]) - x * (n - i - 1)
            
            ans = min(ans, max(left_cost, right_cost))
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、要素が昇順に構成されるように配列を並べ替えます。 プレフィックス合計配列を使用すると、左側の要素が候補値よりどれだけ下にあるか、右側の要素が候補値よりどれだけ上にあるかを高速に計算できます。 各目標値候補について$x$、左側のコストは、その下の要素をどれだけ増やす必要があるかを測定し、右側のコストは、その上の要素をどれだけ減らす必要があるかを測定します。 演算では制限側までしか両方向のバランスを効率的にとることができないため、答えは最悪の側のすべての候補に対する最小値になります。 

最もデリケートな部分は、プレフィックスとサフィックスの寄与を正しく分割することです。 Off-by-one エラーは通常、ピボット要素自体を含めるか除外するときに発生するため、実装では明示的に除外します。$i$コストを計算する際には、両方の側面から検討してください。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            a.sort()
            prefix = [0]
            for v in a:
                prefix.append(prefix[-1] + v)
            total = prefix[-1]
            ans = float('inf')
            for i, x in enumerate(a):
                left = x * i - prefix[i]
                right = (total - prefix[i + 1]) - x * (n - i - 1)
                ans = min(ans, max(left, right))
            print(ans)

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdout = old_stdout
    return out

 ## 特殊なケース

 単一要素の配列は最も単純な境界です。 他に要素がないため、アルゴリズムは左右のコストの両方をゼロとして計算し、出力は正確にゼロになります。 

すべての値が等しい配列は、別の退化ケースです。 ソート後、すべての候補で左右のコストがゼロになるため、最小値はゼロのままです。 これにより、シーケンスがすでに均一である場合には操作が必要ないことが確認されます。 

次のような非常に偏った配列$[1, 1, 1, 100]$アンバランスな対応を強調しています。 ターゲット 1 では、左側のコストがゼロで右側のコストが大きくなりますが、ターゲット 100 ではその逆が当てはまります。 このアルゴリズムは、最適な戦略が、密なクラスターに向かってシフトすることで大きな外れ値を吸収し、外れ値側での大きさの差に等しいコストを生成することであることを正確に識別します。
