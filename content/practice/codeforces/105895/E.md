 ## 解決策
 ## 問題の理解

 行ごとに生成された詩の韻ラベルを表す一連の整数が与えられます。 任意の数の行を削除することはできますが、残りの行を並べ替えることはできません。 削除後、残りのシーケンスはちょうど 4 行の連続したブロックに分割されます。 各ブロックは、AABB、ABAB、または ABBA の 3 つのタイプのいずれかの有効な韻パターンを形成する必要があります。ここで、ラベルの同等性は A と B を定義し、A と B は一致する可能性があります。 

課題は、形成できる有効な 4 行詩の数を最大化することです。これは、削除後に部分列として抽出できる、長さ 4 の互いに素な有効なブロックの数を最大化することと同じです。 

主要な構造上の制約は、各ブロックは独立していますが、元の順序をグローバルに尊重する必要があるということです。 したがって、各グループが 3 つの等価パターンのいずれかに一致する 4 つのグループに分割できるサブシーケンスを効果的に選択していることになります。 

n ≤ 500 という制約は、3 次動的計画法または適度に最適化された 2 次動的計画法は許容されるが、指数サブセット列挙は許容されないことをすでに示しています。 サブシーケンスの数が指数関数的に増加するため、シーケンスのすべての削除またはグループへのすべての分割を明示的に試行しようとするソリューションは失敗します。 

微妙な障害モードは、貪欲なグループ化によって発生します。 たとえば、有効なクアドルプルをできるだけ早く形成しようと欲張ってしまうと、後でさらに多くのグループを有効にするはずだったキャラクターを消費してしまう可能性があります。 

1 2 1 2 2 1 1 2 3 3 3 3 のようなシーケンスを考えてみましょう。貪欲な選択により、早い段階で 1 2 1 2 が形成される可能性がありますが、パターンの選択によっては、より有効なグループを生成する後の配置がブロックされる可能性があります。 選択肢間の依存関係は、ローカルな決定が安全でないことを意味します。 

もう 1 つの問題は、ペアの頻度を一致させるだけでよいと仮定していることです。 ABAB と ABBA はカウントだけではなく位置に依存するため、順序の制約は非常に重要です。 

## アプローチ

 ブルートフォースの観点は、これを部分列選択問題として扱うことです。インデックスの任意の部分集合を選択し、それを 4 つのグループに分割し、各グループが 3 つのパターンのいずれかに一致するかどうかを確認します。 各グループについて、4 つのインデックスのすべての可能な組み合わせを試すことはできますが、すべての 4 倍数を生成するだけでも O(n^4) であり、それらを有効なパーティションに結合することはサブセットにわたる組み合わせになります。 n = 500 ではすでに n^4 が完全に不可能になるため、これはすぐに実行不可能になります。 

重要な観察は、各グループを構成する 4 つの位置を個別に明示的に選択する必要がないということです。 代わりに、配列を左から右に処理し、ペアまたはパターンにどこまで一致するかを決定し、段階的にグループを構築します。 重要な単純化は、有効な各グループが、その絶対的な同一性ではなく、選択された 4 つの値間の等価関係のみに依存するということです。 

これにより、当然のことながら、プレフィックスに関する動的プログラミングの定式化が行われ、形成された完全なグループの数と、現在完成を待っている部分構造が追跡されます。 各グループのサイズは 4 であり、パターンは位置間の平等性にのみ依存するため、部分的な状態は少数の保留要素によって記述でき、遷移は次に保持されている要素の消費またはスキップに対応します。 

最も効率的な定式化は、有効なグループの構築を長さ 4k のシーケンスを構築するものとして解釈し、DP を使用して新しいグループを開始するか、現在の不完全なグループの空いている位置の 1 つに値を配置するかを決定することです。 開いているスロットは最大 4 つであるため、状態空間は制限されたままであり、最大 500 までの n を管理できます。

 ## アルゴリズムのチュートリアル

 有効なグループを順番に構築するプロセスをモデル化します。 現時点では、配列のいくつかのプレフィックスを処理し、0 ～ 3 個の要素を消費したグループを構築している最中です。 

形成された完全なグループの数と現在アクティブな部分構造をキャプチャする DP 状態を定義します。 部分構造を表現するきれいな方法は、すでに選択されている値のマルチセットを現在の未完成のブロック内に格納することですが、順序が重要であるため (AABB、ABAB、ABBA)、ブロック内の位置を認識する必要があります。 

より実際的な再定式化は、各グループを 0 から 3 のインデックスが付いた 4 つのスロットとして見ることです。各スロットは空であるか、シーケンスの値で満たされており、スロット間の制約によって有効性が定義されます。 部分的な割り当てが 3 つのパターンの少なくとも 1 つと一致するように強制します。 

以下のように進めていきます。 

1. dp[i][j][s] を定義します。ここで、i は配列内のインデックス、j は完了したグループの数、s は現在開いているグループの状態です。 状態は、現在のグループ内のどの位置が埋まっているか、およびそれらの位置に割り当てられている値をエンコードします。 グループには 4 つのポジションしかないため、これは小さいです。 
2. dp[0][0][empty_state] = 0 に初期化します。これは、要素を処理する前に、グループが形成されず、部分的なグループも存在しないことを意味します。 
3. 各位置 i について、現在の値を破棄するか、現在の値を現在開いているグループに配置しようとします。 破棄は、この要素を完全にスキップすることに相当します。 
4. 現在の部分グループのスロットに値を配置する場合、AABB、ABAB、ABBA の少なくとも 1 つの有効なパターンと互換性のある部分割り当てを維持する配置のみが許可されます。 この互換性チェックは現在のグループに対してローカルであり、将来の要素には依存しません。 
5. 要素の配置によって 4 つの塗りつぶされた位置のグループが完成した場合、j をインクリメントし、部分的な状態を空にリセットします。 
6. 完了したグループの最大数を常に取得しながら、dp 遷移を前方に伝播します。 

状態空間を小さく保つ重要な制約は、各部分グループの位置が最大 4 つであるため、可能な構造配置の数は定数によって制限されることです。 値が大きくても (最大 1e9)、グループ内の平等関係のみを考慮します。 

### なぜ効果があるのか

 すべての有効なソリューションは、4 つの要素からなる連続したグループに分解できます。 各グループ内では平等関係のみが重要であり、これらの関係は 4 番目の要素が選択された時点で完全に決定されます。 有効なパターンにつながる可能性のある部分的なグループ構成をすべて維持することで、有効な補完が早期に破棄されることがなくなります。 すべての決定はグループに対してローカルであり、完了するとグループは独立するため、DP は実行可能なすべての分解を重複なく探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

# encode a partial group state as tuple of up to 4 values with placeholders
# we normalize states to reduce symmetry

def normalize(state):
    # compress values by first appearance order
    mp = {}
    nxt = 0
    res = []
    for x in state:
        if x not in mp:
            mp[x] = nxt
            nxt += 1
        res.append(mp[x])
    return tuple(res)

def valid_patterns(vals):
    a, b, c, d = vals
    return (
        (a == b and c == d) or
        (a == c and b == d) or
        (a == d and b == c)
    )

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    # dp: state -> best completed groups
    # state is (partial tuple)
    dp = {(): 0}

    for x in arr:
        ndp = dp.copy()

        for state, val in dp.items():
            # skip x
            ndp[state] = max(ndp.get(state, -10**9), val)

            # try insert into current group
            if len(state) < 4:
                new_state = state + (x,)
                if len(new_state) < 4:
                    key = normalize(new_state)
                    ndp[key] = max(ndp.get(key, -10**9), val)
                else:
                    # complete group
                    if valid_patterns(new_state):
                        ndp[()] = max(ndp.get(() , -10**9), val + 1)

        dp = ndp

    print(max(dp.values()))

if __name__ == "__main__":
    solve()
```このコードは、部分的なグループ構成にわたる辞書を維持します。 各ステップでは、現在の行をスキップするか、現在の未完了のグループに追加するかを検討します。 4 つの要素が収集されると、パターン制約がチェックされ、完了したグループがカウントされます。 

正規化ステップにより、生の値ではなく等価構造のみを追跡することが保証されます。 シンボルの名前変更だけが異なる 2 つの状態は、将来の遷移では同じように動作するため、これは重要です。 

微妙な点は、反復ごとに dp をコピーすることです。 遷移は前のレイヤー状態のみに依存するため、これは安全です。 グループごとの状態の数が制限されているため、複雑さは依然として許容範囲内です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が同一である場合です。 入力用`4k`番号が同じであれば、AABB ではすべてのブロックが有効であるため、答えは次のようになります。`k`。 すべてのパターンが等価に崩壊し、完成したすべてのクアドルプルが妥当性チェックに合格するため、DP は完全なグループを拒否することはありません。 

もう 1 つの特殊なケースは、値が交互に存在するが、実行可能なパターンが 1 つだけである場合です。 例えば`1 2 1 2 1 2 1 2`ABAB ブロックを繰り返し形成します。 DP は、グループが完了したときに状態リセットが正確に行われるため、部分的なグループ化によって連続する有効なブロック間の境界が誤って混在しないことを保証します。 

最後の微妙なケースは、初期の貪欲なグループ化が失敗する場合です。 のために`1 2 1 2 3 3 3 3`の場合、正しい戦略は、最初に 1 つの ABAB グループを形成し、次に 1 つの AABB グループを形成することです。 時期尚早に摂取すると、`3`を部分構造にすると、有効な補完の数が減ります。 DP は、完全なブロックが強制されるまで、互換性のあるすべての部分状態を同時に維持することでこれを回避します。
