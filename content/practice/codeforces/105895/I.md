 ## 解決策
 ## 問題の理解

 完全に接続されたグラフが与えられます。$n$ただし、エッジの重みは任意ではありません。 各頂点$i$価値がある$a_i$、と間のエッジの重み$i$そして$j$は次のように定義されます$\min(a_i, a_j)$。 したがって、都市のすべてのペアは直接接続されており、旅行のコストはより小さいエンドポイントの値にのみ直接依存します。 

システムは2種類の操作によって進化します。 まず、単一の頂点の値を変更して、その頂点を更新します。$a_i$。 次に、2 つの頂点間の最短経路を求められます。$u$そして$v$ただし、ひねりが加えられています。各クエリでは、最大で$k \le 9$特定のエッジは一時的に削除されるため、それらのエッジが存在しないかのように最短パスを計算する必要があります。 これらの削除は一時的なものであり、クエリを超えて持続することはありません。 

削除を無視してもグラフは常に接続されたままであり、次の点に答える必要があります。$10^5$効率的な運用を実現します。 

この制約により、クエリごとに最短パスを最初から再計算するアプローチはすでに除外されています。 密なグラフ上の単一のダイクストラであっても、$10^5$ノードと$O(n^2)$エッジは無理です。 エッジウェイトの構造が問題を軽減する鍵となります。 

ダイレクトエッジが常に最適であると仮定しようとすると、微妙なエッジケースが現れます。 たとえば、次の場合$a_u = a_v = 100$、直接エッジコスト$100$。 ただし、ノードが存在する場合は、$x$と$a_x = 1$、それでは行きます$u \to x \to v$費用$1 + 1 = 2$、劇的に小さくなります。 したがって、グラフは直接エッジに関して局所的に最適ではなく、中間ノードが非常に重要になります。 

もう 1 つの落とし穴は、最大 9 つのエッジを削除しても最短パスがわずかに乱れるだけであると想定していることです。 グラフは完全であるため、削除された 1 つのエッジが最適な 2 ステップのルートをブロックし、完全に異なる中間選択を強いられる可能性があります。 

## アプローチ

 ブルートフォース戦略では、構造を無視して、すべてのクエリの完全なグラフに対してダイクストラを使用して最短パスを計算します。 つまり、$O(n^2)$実行ごとのエッジ、またはせいぜい$O(n^2)$リラクゼーション。 と$10^5$クエリの場合、これは天文学的な規模になります。 

重要な観察は、重み関数が$\min(a_i, a_j)$グラフが非常に構造化されます。 パス コストはエッジに沿った極小値によって決まります。 特に、中間ノードの場合$x$、パス$u \to x \to v$費用がかかる$$\min(a_u, a_x) + \min(a_x, a_v),$$そしてこれはのみに依存します$a_x$、グラフの残りの部分にはありません。 これにより、検索スペースが劇的に崩壊します。 

より深い単純化は、考えられるすべての中間ノードの中で、最良のものは常に最小のノードであるという事実から来ています。$a_x$、減少して以来$a_x$両方の項を減らすことしかできません。 これは、変更されていないグラフでは、最短パスは常に次の 2 つの形式のいずれかであることを意味します。$u \to v$、またはグローバル ミニマムを通過する 2 段階のパス$a$-値ノード。 

したがって、削除がなければ、答えは単純に次のようになります。$$\min(\min(a_u, a_v),\; 2 \cdot \min a).$$複雑なのは、クエリ固有の最大 9 つのエッジの削除です。 これは特定の中間体の実現可能性にのみ影響します。 最適な構造では最大 1 つの中間ノードが使用されるため、最適な中間ノードへの接続がブロックされているかどうかのみを考慮する必要があります。$u$または$v$。 

したがって、各クエリは、小さな禁止セットの中から最良の有効な中間ノードを選択し、さらに直接エッジが削除されているかどうかをチェックすることになります。 

これにより、問題はグラフの問題から、非常に小さな除外セットを使用した動的な「除外を使用して有効な最小値を見つける」問題に縮小されます。

 | --- | --- | --- | --- |
 | クエリごとのブルート フォース ダイクストラ |$O(q n^2)$|$O(n^2)$| 遅すぎる |
 | 構造 + 最適な中間選択 |$O((n+q)\log n + k)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の配列を維持します$a_i$アップデートのサポート付き。 また、グローバルミニマムを迅速に提供できる体制を整備しています。$a_i$そのインデックスとともに。 

各クエリについて、3 つの論理段階で答えを構築します。 

1. クエリエンドポイントを読み取る$u, v$、中間として機能することが禁止されているすべてのノードを収集します。 これらは、いずれかの端点で削除されたエッジに表示されるすべての頂点です。$u$または$v$。 以来$k \le 9$、このセットは小さいです。 
2. ダイレクトエッジかどうかを確認します$u \to v$は禁止されています。 禁止されていない場合は、候補の答えを次のように計算します。$\min(a_u, a_v)$。 これは片エッジ パスとして常に有効です。 
3. 最適な中間ノードを見つける$x$それは禁止されたセットには含まれていません。 We want to minimize$\min(a_u, a_x) + \min(a_x, a_v)$。 この表現は単調なので、$a_x$、最小のノードのみが必要です。$a_x$すべての有効なノード間で。 

このノードを取得するために、禁止されたセットに含まれないノードが見つかるまで、グローバル最小構造から候補を繰り返し抽出します。 禁止されたセットは小さく、クエリごとに少数の無効な候補をスキップするだけであるため、これは依然として効率的です。 

1. このような中間体の場合$x$が存在する場合、そのコストを計算し、答えを更新します。 
2. すべての有効な候補の最小値を出力します。 

本質的な不変条件は、このグラフ内の最短パスは最大 1 つの中間頂点を使用すると仮定できることです。 エッジ コストはエンドポイントの最小値のみに依存するため、検出された最小値を使用して連続するステップをより安価な同等のステップに置き換えることによって、長いパスを圧縮できます。 したがって、直接パスと単一中間パスに注意を限定しても、最適なソリューションが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        heap = [(a[i], i) for i in range(n)]
        heapq.heapify(heap)

        active = a[:]  # current values

        for _ in range(q):
            tmp = input().split()
            op = int(tmp[0])

            if op == 1:
                x = int(tmp[1]) - 1
                val = int(tmp[2])
                active[x] = val
                heapq.heappush(heap, (val, x))

            else:
                u = int(tmp[1]) - 1
                v = int(tmp[2]) - 1
                k = int(tmp[3])

                forbidden = set()

                idx = 4
                for _i in range(k):
                    x = int(tmp[idx]) - 1
                    y = int(tmp[idx + 1]) - 1
                    idx += 2
                    forbidden.add(x)
                    forbidden.add(y)

                ans = float('inf')

                if (u, v) not in set(zip([], [])) and (v, u) not in set(zip([], [])):
                    ans = min(ans, min(active[u], active[v]))

                # find best intermediate
                removed_uv = False
                # direct edge is not actually tracked unless explicitly in forbidden list:
                # we detect it from input pairs
                idx = 4
                for _i in range(k):
                    x = int(tmp[idx]) - 1
                    y = int(tmp[idx + 1]) - 1
                    idx += 2
                    if (x == u and y == v) or (x == v and y == u):
                        removed_uv = True

                if not removed_uv:
                    ans = min(ans, min(active[u], active[v]))

                # get best x
                while heap:
                    val, x = heap[0]
                    if active[x] != val:
                        heapq.heappop(heap)
                        continue
                    if x in forbidden or x == u or x == v:
                        heapq.heappop(heap)
                        continue

                    break

                if heap:
                    val, x = heap[0]
                    cand = min(active[u], val) + min(active[v], val)
                    ans = min(ans, cand)

                print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```実装では、更新をサポートするために頂点値の遅延ヒープが保持されます。 古いエントリが見つかった場合はスキップされます。 クエリごとに、小さな禁止セットのみを再構築し、ヒープの最小値を繰り返しチェックして、最適な有効な中間セットを見つけます。 

微妙な点は、更新によりヒープに古い値が含まれる可能性があることです。 これらは、現在のものと比較することによってフィルタリングされます。`active[x]`。 もう 1 つの微妙な点は、クエリによって明示的に禁止されている端点と頂点の両方を中間候補で除外する必要があることです。これは、これらを使用すると 2 ステップ パスに禁止エッジが強制されるためです。 

## 実用的な例

 値を含む小さなシナリオを検討してください$[5, 1, 4]$、および削除なしで 1 と 3 の間の距離を求めるクエリ。 

| ステップ |$u$|$v$| 最高$x$| 直接 | 経由$x$| 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 3 | 2 (値 1) | 5 | 2 | 2 |

 値 1 の中間ノードがパス内の両方のエッジを削減するため、優先されます。 

ここで、最適な中間者がブロックされた場合を考えてみましょう。 

値を次のようにします$[10, 1, 2]$、1 と 3 の間のクエリですが、エッジ (1,2) は削除されます。 

| ステップ | 禁止 | 最高$x$| 直接 | 経由$x$| 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | {2} | 3 | 10 | 4 | 4 |

 ノード 2 の値が最小であっても、必要なパスが 1 から切断されるため、使用できません。 

これらの例は、正確さが値の最小化とクエリ固有のエッジ除去の尊重の両方に依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、グローバル最小ノードがクエリ内の禁止エッジ リストの一部である場合です。 その状況では、アルゴリズムは、たとえ全体的に最小化するとしても、それを誤って中間として選択してはなりません。$a_x$。 禁止されたセットのチェックはこれを明示的に保証します。$a_x$単独では最適ですが、エッジを強制的に削除する場合は拒否されます。 

もう 1 つのケースは、直接エッジが削除される場合です。 その場合、唯一の有効な答えは中間ノードから得られる可能性があります。 直接エッジ分岐がスキップされ、中間計算のみが残るため、アルゴリズムは依然としてすべての候補を正しく考慮します。 

3 番目のケースは、更新によってグローバル最小値のアイデンティティが継続的に変更される場合です。 遅延ヒープは、すべての候補が使用される前に現在の配列に対して検証されるため、古い値が選択に干渉しないようにします。
