 ## 問題の理解

 リクエストの固定シーケンスと、最大でもサイズの小さな「キャッシュ」が与えられます。$m$、最初は空です。 シーケンスを左から右にスキャンすると、検出される各要素はすでにキャッシュ内にあるかどうかのいずれかになります。 

現在の要素がすでにキャッシュ内にある場合は、1 ポイントを獲得します。 キャッシュにない場合でも、この簡素化されたバージョンでは何も悪いことは起こりませんが、オプションでそれをキャッシュに挿入することができ、場合によっては既存の要素を 1 つ削除することができます。 この簡単なバージョンでは、挿入と削除には何もコストがかかりません。そのため、スコアを獲得する唯一の方法は、将来の要素が出現するときにすでに存在するようにキャッシュを配置することです。 

タスクは、キャッシュ ヒットの総数が最大化されるように、スキャン中にすべてのキャッシュ更新をオンラインで選択することです。 

制約は全体としては小さく、合計すると$n$すべてのテスト ケースで最大 800。これにより、おおよそより悪いソリューションは即座に排除されます。$O(n^2)$ただし、各ステップのキャッシュを検査し、将来の動作をシミュレートする戦略も可能です。 

微妙な点は、挿入はいつでも無料ですが、不注意な戦略は大失敗する可能性があるということです。 たとえば、最も最近見た要素を常に保持することは最適ではありません。 

次のようなシーケンスを考えてみましょう$1, 2, 3, 1, 2, 3$と$m = 2$。 常に最新の 2 つの要素を保持すると、次のような結果になる可能性があります。$\{2, 3\}$最後の 3 つの要素の前に、将来のヒットが欠落しています$1$。 代わりに、最適な戦略は、どの要素がすぐに必要になるかを追跡します。 

重要な問題は、ミスした場合の決定は現在の要素に関するものではなく、後で再び表示される要素へのアクセスを維持するためのものであることです。 

## アプローチ

 強引なアイデアは、すべてのステップの後に、考えられるすべてのキャッシュ内容をシミュレートすることです。 ミスが発生した場合、各位置でどの要素を削除し、どの要素を挿入するかについて考えられるすべての選択肢を試します。 これにより、各状態が最大でもサイズのサブセットである分岐プロセスが形成されます。$m$、遷移は次の要素に依存します。 積極的な枝刈りを行ったとしても、状態の数は組み合わせ的に増加します。$\binom{n}{m}$、これは、たとえ$n = 800$。 

すべてのヒットに同じ報酬が与えられ、ペナルティがないため、構造が簡素化されます。 唯一意味のある決定は、将来のヒットを最大化するためにどの要素をキャッシュに保持するかということです。 これにより、問題は完全な将来の知識を備えた古典的な最適キャッシュの問題に変わります。 

よく知られている最適な戦略は、次に出現するのが最も遠い将来の要素を常に削除することです。 要素が二度と出現しない場合、それは常にエビクションの最適な候補となります。 この貪欲なルールは、すぐに必要になる要素へのアクセスを失うことを先送りし、近い将来の利益を維持するため、最適です。 

これを適用するには、各ステップで、キャッシュされたすべての要素が次にいつ表示されるかを知る必要があります。 値ごとに将来のポジションのリストを維持し、前方にスキャンしながらポインタを進めます。

 ## アルゴリズムのチュートリアル

 キャッシュ セットと、値ごとに、将来の次の出現へのポインタを維持します。 

1. すべての値について、それが出現するすべてのインデックスのリストを事前計算します。 これにより、将来の出来事をすぐに知ることができます。 
2. 各値について、厳密に現在位置の後に最初に出現する位置を示すリストへのポインタを維持します。 配列内を前進するにつれて、オカレンスを渡すときにこれらのポインターを進めます。 
3. 現在のキャッシュを最大でも 1 セットとして維持します。$m$価値観。 
4. 位置処理時$i$、どうかを確認してください$a_i$はすでにキャッシュ内にあります。 一致する場合、これはキャッシュ ヒットであるため、スコアを 1 つ増やします。 
5. もし$a_i$キャッシュにないため、挿入することを検討します。 キャッシュに空き領域がある場合は、それを直接挿入します。 それ以外の場合は、既存の要素を 1 つ削除する必要があります。 
6. 削除する要素を選択するために、現在キャッシュ内にあるすべての要素を調べ、その次の出現インデックスを計算します。 削除する最適な候補は、次に出現するのが最も遠い将来であるか、まったく存在しないものです。 
7. その要素を削除した後、$a_i$キャッシュに入れます。 

これが機能する主な理由は、次に使用されるのが非常に遠い要素は、将来のヒットを保存するために直接の価値が最も低いためです。 削除しても短期的な結果には悪影響はありませんが、以前に再利用された要素を保持しておくと、保証された利益が維持されます。 

### なぜ効果があるのか

 どのステップでも、キャッシュは次の選択肢を表します。$m$将来の利益のために保持することを約束する要素。 要素の置き換えを検討するとします。$x$現在の要素を含むキャッシュ内$a_i$。 もし$x$他のキャッシュされた要素よりも早い段階で使用される$y$、それらを交換することによってのみ、将来のヒットをより安全に遅らせたり保存したりできます。$x$。 これにより、貪欲な交換の議論が確立されます。「最も遠い次の使用は排除される」ルールに違反する構成は、将来のヒットを減らすことなく、スワップによって改善できます。 このやり取りを繰り返すことで、各ステップで最適な構造が導き出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18
    
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        _ = list(map(int, input().split()))  # x_i all 1
        _ = list(map(int, input().split()))  # y_i all 0
        _ = list(map(int, input().split()))  # z_i all 0

        pos = [[] for _ in range(n + 1)]
        for i, v in enumerate(a):
            pos[v].append(i)

        ptr = [0] * (n + 1)

        def next_occ(v, i):
            lst = pos[v]
            while ptr[v] < len(lst) and lst[ptr[v]] <= i:
                ptr[v] += 1
            if ptr[v] < len(lst):
                return lst[ptr[v]]
            return INF

        cache = set()
        score = 0

        for i, v in enumerate(a):
            if v in cache:
                score += 1
            else:
                if len(cache) < m:
                    cache.add(v)
                else:
                    worst = None
                    worst_next = -1
                    for u in cache:
                        nxt = next_occ(u, i)
                        if nxt > worst_next:
                            worst_next = nxt
                            worst = u
                    cache.remove(worst)
                    cache.add(v)

        print(score)

if __name__ == "__main__":
    solve()
```このソリューションは、各ステップで、キャッシュされた要素ごとに将来の正しいビューを維持することを中心に構成されています。 の`pos`リストにはすべての出現が保存され、`ptr`次の発生の計算が効率的に償却されるように、遅延して進行します。 キャッシュ自体はセットであり、ミスが発生するたびにキャッシュのスキャンがトリガーされ、将来の有用性が最も緊急性の低い要素が特定されます。 

重要な実装の詳細は次のとおりです。`next_occ(v, i)`常にインデックスの後に最初に出現したものを返します。`i`、ポインタの前進により、古い位置を繰り返し再スキャンすることがなくなります。

 ## 特殊なケース

 One edge case is when a value never appears again after being inserted. この状況では、次に出現するものは無限大として扱われるため、再利用可能な要素とともにキャッシュ内に存在する場合は常に、それが最適なエビクション候補となります。 アルゴリズムは自然にそれを最初に削除し、キャッシュスペースの無駄を防ぎます。 

もう 1 つのケースは、キャッシュ内のすべての値の次の出現位置が同じである場合です。 その状況では、エビクションの選択はどれも同等であり、それらのどれを置き換えても将来のヒットの可能性が変わらないため、アルゴリズムは依然として正しく動作します。 

最後のケースは、現在の要素がすでにキャッシュ内にあるものの、すぐに再び表示される場合です。 ポインタ メカニズムにより、ヒットをすぐにカウントできるようになり、そのステップでキャッシュを変更することなく、将来のヒットが正しく認識されます。
