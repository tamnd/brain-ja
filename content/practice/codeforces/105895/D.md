 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 各クエリは、この配列の連続したセグメントに焦点を当て、そのセグメントに対して、「ゲーム配列」を形成するために任意のサブシーケンス (必ずしも連続している必要はありませんが、順序は維持されます) を選択することができます。 

選択されたサブシーケンスは 2 人用ゲームで使用されます。 プレイヤーは A から始まる手を交互に動かします。1 つの手で、プレイヤーは厳密に 1 より大きい任意の要素を選択し、それを 1 より大きい非自明な約数の 1 つと置き換えます。最終的には、すべてが 1 になるまで要素を減らすことができます。その時点で手は不可能になり、これから動かそうとしているプレイヤーが負けます。 

問題は、ゲームを直接シミュレートすることではありません。 セグメントごとに、最適なプレイでプレーヤー A が勝てる空ではないサブシーケンスの数を数え、このカウントを 998244353 を法として出力する必要があります。 

制約は大きく、配列の合計長とクエリの合計はテスト ケース全体で最大 10^6 になります。 これにより、クエリごとにサブシーケンスを構築または評価するものは即座に除外されます。 クエリごとに O(n log n) であっても遅すぎます。 前処理後にクエリごとに O(1) または O(log n) が必要です。 

微妙な問題は、サブシーケンスがインデックスの選択によって定義されるため、値が一致していても、異なる位置を選択すると 2 つのサブシーケンスは異なることです。 また、空のサブシーケンスは許可されません。 

選択されたすべての要素が 1 に等しい場合、重要なエッジ ケースが表示されます。その状況では、ゲーム内でいかなる移動も不可能になるため、最初のプレイヤーは即座に負けます。 このケースを無視した単純なカウント手法では、無効な勝ちの構成が誤って含まれてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにセグメントのすべてのサブシーケンスを列挙し、ゲームの結果をシミュレートします。 ゲーム シミュレーションを無視しても、長さ m のセグメントには 2^m 個の部分シーケンスがあり、m が大きくなる可能性があるため、これは不可能です。 

最初の単純化は、ゲーム自体を理解することから始まります。 各移動は 1 より大きい単一の要素に作用し、除数を選択することで要素を減らします。 除数の選択方法に関係なく、唯一重要な事実は、要素が厳密に減少し、最終的には 1 になるということです。各要素は 1 になるまでのみ「使用」でき、それ以降は無関係になります。 

これは、1 より大きいすべての要素が実質的に少なくとも 1 つの移動機会に寄与する一方、1 に等しい要素は何も寄与しないことを意味します。 さらに重要なのは、プレイヤーはいつでも 1 回の動きで選択した要素を直接 1 に減らすことができるため、因数分解の内部構造は最適なプレイに影響を与えません。各有用な要素は、1 回だけ消費できる単一のトークンのように動作します。 

したがって、ゲームは単純なターンベースのプロセスに縮小されます。プレイヤーは 1 より大きい要素を交互に消費します。勝者は、選択したサブシーケンスにそのような要素がいくつ存在するかによってのみ決まります。 

サブシーケンスを定義する場合、k をその内部の 1 より大きい要素の数とします。 ゲームはちょうど k 個の動きで構成されているため、k が奇数の場合にのみ A が勝ちます。 

ここで、問題は純粋に組み合わせの問題になります。 特定のセグメントについて、選択された「良好な」要素 (1 より大きい値) の数が奇数になるようにサブシーケンスをカウントします。 

セグメント内に 1 より大きい c 個の要素と 1 に等しい z 個の要素があるとします。 すべてのサブシーケンスは、各要素を独立して選択するかどうかによって形成されます。 z 要素は乗法的自由度のみに寄与し、c 要素はパリティを決定します。 

c 要素のうち、奇数サイズのサブセットの数は、c > 0 の場合は正確に 2^(c-1) で、c = 0 の場合は 0 です。z 要素を選択するたびに、有効なサブシーケンスの数が 2 倍になり、係数 2^z が寄与します。 

したがって、c > 0 の場合、答えは 2^z * 2^(c-1) = 2^(セグメント長 - 1) になります。 c = 0 の場合、すべての要素は 1 であり、有効な勝ちのサブシーケンスは存在しません。

したがって、各クエリはセグメントに 1 より大きい値が少なくとも 1 つ含まれているかどうかをチェックすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (サブシーケンス + シミュレーション) | クエリごとに O(2^n · n) | O(n) | 遅すぎる |
 | 値のプレフィックス数 > 1 | O(n) 個の前処理後のクエリごとに O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 各要素を分類する

 配列を 1 回スキャンし、すべての要素を 1 より大きい場合は「アクティブ」、1 に等しい場合は「非アクティブ」に分類します。アクティブな要素のみがゲーム パリティに影響します。 

内部除数演算は要素が 1 になるまで再生可能であるという事実に影響を与えないため、この分類で十分です。 

### 2. ビルドプレフィックス情報

 各位置がそのインデックスまでに出現するアクティブな要素の数を格納するプレフィックス合計配列を計算します。 これにより、任意のセグメントについて、一定時間内に含まれるアクティブな要素の数をクエリすることができます。 

これが機能する理由は、サブシーケンスが値とは独立して選択されるため、位置ではなくカウントのみが必要になるためです。 

### 3. セグメント分類を使用して各クエリに回答します

 クエリ [l, r] の場合、プレフィックスの差を使用してその範囲内のアクティブな要素の数 c を計算します。 c が 0 の場合、ゲームにはまったく手がないため、答えはすぐに 0 になります。 

それ以外の場合、セグメントの長さは len = r - l + 1 です。空ではないすべてのサブシーケンスは構造に関して均等に重み付けされ、アクティブな要素のサブセットのちょうど半分が奇数のサイズになります。 非アクティブな要素はカウントに 2^(非アクティブな要素の数) を乗算するだけなので、最終的な答えは len のみに依存します。 

2^(len - 1) モジュロ 998244353 を出力します。 

### なぜ効果があるのか

 不変条件は、選択されたサブシーケンス内の 1 より大きい要素数のパリティのみが勝者を決定するということです。 除数演算によってこのパリティ関連の構造が変更されることはありません。これは、各アクティブ要素が最適なプレイの下で 1 つの避けられない「消耗ユニット」に寄与するためです。 サブシーケンスは要素を独立して処理するため、カウントはパリティが制約されたサブセット数に減り、非アクティブな要素はパリティに影響を与えず、構成の数を拡大するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modexp(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    b = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (1 if b[i] > 1 else 0)

    for _ in range(q):
        l, r = map(int, input().split())
        c = pref[r] - pref[l - 1]
        if c == 0:
            print(0)
        else:
            length = r - l + 1
            print(modexp(2, length - 1))
```プレフィックス配列`pref`配列セグメント内の厳密に 1 より大きい要素の数を追跡します。各クエリは 2 つのプレフィックス値を減算して、O(1) のカウントを取得します。 

べき乗ステップでは、2 進累乗を使用して 998244353 を法とする 2 の累乗を効率的に計算します。 指数は最大 10^6 であるため、これはすべてのクエリにわたって十分に高速です。 

微妙な点は、最終的な式で打ち消されるため、1 の数である z を明示的に計算しないことです。 これにより、ソリューションが大規模な入力に対応できるようになります。 

## 実用的な例

 ### 例 1

 次の配列を考えてみましょう。`[1, 1, 4, 16, 2, 8, 3, 7]`セグメント全体 [1、8] を取得します。 

1 より大きい要素がいくつあるかを計算します。 

| 私 | 値 | >1? | 接頭語 |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 |
 | 2 | 1 | 0 | 0 |
 | 3 | 4 | 1 | 1 |
 | 4 | 16 | 1 | 2 |
 | 5 | 2 | 1 | 3 |
 | 6 | 8 | 1 | 4 |
 | 7 | 3 | 1 | 5 |
 | 8 | 7 | 1 | 6 |

 したがって、c = 6、長さ = 8。c > 0 なので、答えは 2^(8 - 1) = 2^7 = 128 となります。 

これは、大きな数の分布が複雑に見えても、少なくとも 1 つのアクティブな要素が存在すれば、長さのみが重要であることを示しています。 

### 例 2

 たとえば、1 だけで構成されるセグメントを取ります。`[1, 1, 1, 1]`。 

ここで c = 0 です。ゲームではどの要素も使用できないため、A はすべてのサブシーケンスで即座に負けます。 答えは0です。 

「移動なし」条件を無視する単純なサブセット カウント手法では、誤って 2^4 - 1 = 15 が出力されますが、これらのサブシーケンスはゲーム条件を満たしていません。

## テストケース```python
import sys, io

MOD = 998244353

def modexp(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        b = list(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + (1 if b[i] > 1 else 0)

        for _ in range(q):
            l, r = map(int, input().split())
            c = pref[r] - pref[l - 1]
            if c == 0:
                out.append("0")
            else:
                out.append(str(modexp(2, r - l)))
    return "\n".join(out)

""") == "0"

assert solve("""1

""") == str(modexp(2, 2))

""") == "0"

assert solve("""1

""") == "\n".join([str(modexp(2,4)), str(modexp(2,2))])

 | シングル 1 | 0 | すべての要素が死んでいます |
 | すべてアクティブ | 2^(n-1) | フルアクティブセグメントの動作 |
 | すべてのもの | 0 | 空のゲームの有効性 |

 ## 特殊なケース

 セグメントに 1 のみが含まれる場合、プレフィックスの差 c がゼロになり、特殊なケースがトリガーされるため、アルゴリズムは正しく 0 を返します。 これにより、実際のゲームの動きを持たないサブシーケンスを誤ってカウントすることが回避されます。 

セグメントに 1 より大きい要素が 1 つだけ含まれている場合、それを含むすべての有効なサブシーケンスは純粋に包含パリティに基づいた勝利条件に寄与し、式 2^(len-1) は依然として当てはまります。 プレフィックス チェックにより、すべて 1 のセグメントが誤って有効なものとして扱われないことが保証されます。 

セグメントが大きくてもアクティブな要素がまばらな場合でも、アルゴリズムはアクティブな要素の位置にはまったく依存せず、その存在のみに依存するため、正しく動作します。
