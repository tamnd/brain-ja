 ## 問題の理解

 として表されるノイズの多い白黒画像が与えられます。$n \times m$文字のグリッド。 各セルは 0 または 1 のいずれかで、1 は白のピクセルに対応し、0 は黒のピクセルに対応します。 この画像はもともと固定フォントで書かれたクリーンなバイナリ文字列から生成され、その後ランダムなピクセル反転によって破損しました。 

重要な隠れた構造は、グリッドが任意ではないということです。 これはレンダリングされた OCR ストリップです。各列は同じ基礎となる数字または文字パターンの垂直スライスに対応し、元のクリーンなイメージにはバイナリ文字列をエンコードする水平構造が含まれています。 ノイズにより個々のピクセルが低確率で反転されるため、ほとんどの列は依然として実際のパターンに似ています。 

タスクは、イメージを生成した元のバイナリ文字列を復元することです。 

制約の高さは小さいですが、幅は大きくなります。 高さは約 64 ～ 66、幅は最大 1000 です。これは、各列を個別に処理することも、低次元表現に集約できることもすぐに示唆しています。 画像を一般的な 2D パターン マッチング問題としてモデル化しようとするソリューションや、すべてのピクセルに対して高価なグローバル最適化を実行するソリューションは、いずれも合格しますが、それが効果的に列ごとの分類に帰着する場合に限ります。 

単純な読者は、画像を任意のノイズとして解釈し、グリッド全体にわたるパターン マッチングを使用して文字列を再構築しようとする可能性があります。 完全なイメージの組み合わせ論の観点から考えると、状態空間が膨大になるため、このアプローチは失敗します。 

より微妙な失敗のケースは、各行を個別に処理することで発生します。 ノイズはピクセルごとに独立しているため、行ごとの多数決が妥当であるように見えますが、行は文字を独立してエンコードするわけではありません。 文字は垂直方向に一貫したパターンです。 列構造を無視すると信号が破壊されます。 

もう 1 つの間違ったアプローチは、画像全体をグローバルに閾値設定することです。たとえば、列ごとに合計数をカウントし、次のような固定閾値と比較します。$n/2$。 これは期待どおりに機能しますが、文字が構造的に非対称である場合は失敗します。これは、一部の列は、たとえクリーンなデータであっても本質的に白または黒であるためです。 

重要なのは、各列が固定の 64 次元バイナリ ベクトルのノイズを含む観測値であり、基になる信号が同じ文字領域に属するすべての列にわたって一貫していることです。 

## アプローチ

 ブルートフォースの観点は、考えられるすべてのバイナリ文字列を考慮し、フリップ モデルの下で観測されたノイズの多い画像を生成できたかどうかを確認することです。 これは、考えられるすべての文字列を検索し、グリッド全体に対して尤度を計算することと同じです。 妥当な文字列長に制限したとしても、出力文字列の長さは指数関数的に増大し、完全に実行不可能になります。 

2 番目の強引なアイデアは、テンプレート マッチングを試みることです。考えられるすべての文字位置について、候補パターンを位置合わせし、すべての行と列にわたってピクセル単位の類似性をスコアリングしてみます。 これは、大きな部分行列を繰り返しスキャンし、多くの仮説と比較する必要があるため、依然としてコストがかかります。 

転換点は、データがどのように生成されたかを認識することから始まります。 各列は単一の文字スライスの垂直エンコードであり、ノイズはピクセルごとに独立しています。 これは、各出力シンボルの最適な決定は、その列位置のすべての行にわたって集約された証拠のみに依存することを意味します。 

これが確認されると、問題は列方向のノイズ除去に集約されます。 各列について、その列に含まれる白ピクセルと黒ピクセルの数を計算します。 ノイズは低い確率で各ピクセルを反転させるため、列内の多数決の値は、その位置の元のクリーンな列構造と一致する可能性が圧倒的に高くなります。 クリーンなイメージ自体は、同じ文字領域に対応する列全体で一貫した構造を持っているため、再構成された出力は、各列がフォント エンコーディングの「白主体」または「黒主体」のどちらの領域に属するかを決定することになります。 この問題では、それはバイナリ出力文字に直接マッピングされます。 

したがって、ソリューションは、各列の行にわたる単純な集計とその後のしきい値処理になります。

 ## アルゴリズムのチュートリアル

 1. サイズのグリッドを読み取ります$n \times m$、それを文字の行として保存します。 これは、後で列方向のアクセスが必要になるため必要です。 
2. 各列インデックスについて$j$、すべての行にわたる 1 の数を計算します。 これにより、その垂直スライスのすべてのノイズの多い観測値が 1 つの統計に集約されます。 
3. その列の 1 の数と 0 の数を比較します。 1 がより頻繁に発生する場合は、その列を出力で 1 を表すものとして扱います。 それ以外の場合は 0 として扱います。その理論的根拠は、ノイズはピクセルごとに対称的で独立しているため、多数決が真の基礎となる列値の最尤推定量になるということです。 
4. 各列の結果のビットを、左から右の順序で最終出力文字列に追加します。 
5. 再構築されたバイナリ文字列を出力します。 

### なぜ効果があるのか

 各列は次のように表示できます。$n$確率で反転された隠れた真の値の独立したベルヌーイ観測$p = 0.05$。 観測された列の期待値は真のビットに偏っており、測定値が集中しているため、ノイズが大部分を圧倒する確率は指数関数的に小さくなります。$n$。 以来$n \approx 64$、誤った多数決の確率は無視でき、最大 1000 列にわたって再構成は安定しています。 これにより、列方向の多数決が元の信号の一貫した推定量になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

res = []

for j in range(m):
    ones = 0
    for i in range(n):
        if grid[i][j] == '1':
            ones += 1
    zeros = n - ones
    res.append('1' if ones > zeros else '0')

print("".join(res))
```この実装は、列集計のアイデアに直接従っています。 入力がその形式で到着するため、グリッドは行単位で保存され、部分文字列の繰り返しスキャンを避けるために列ごとに反復処理が行われます。 

唯一の微妙な決定は厳密な比較です`ones > zeros`。 これは重要です。なぜなら、タイは一貫して 0 にマップされる必要があるからです。$n \in [64, 66]$、統計的に同点になることはまれですが、ノイズが完全にバランスしている場合は可能性があります。 決定的なタイブレークにより、安定した出力が保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    res = []
    for j in range(m):
        ones = 0
        for i in range(n):
            if grid[i][j] == '1':
                ones += 1
        res.append('1' if ones > n - ones else '0')
    return "".join(res)

# minimal case
assert run("1 1\n1\n") == "1"

# clean columns
assert run("3 3\n111\n000\n111\n") == "101"

# majority with noise
assert run("3 3\n110\n101\n000\n") == "100"

# all zeros
assert run("2 5\n00000\n00000\n") == "00000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1x1 単一ピクセル | 1 | 最小境界の正確性 |
 | 混合クリーン構造 | 101 | 列の正しい解釈 |
 | ノイジーマジョリティの場合 | 100 | 反転に対する堅牢性 |
 | すべてゼロのグリッド | 00000 | 均一な取り扱い |

 列 1 には 1 が 1 つと 0 が 1 つあるため、1 はゼロより大きくなく、出力は 0 になります。列 2 も同様に動作し、列 3 も同様です。出力は次のようになります。`000`。
