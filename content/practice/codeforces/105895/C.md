 ## 解決策
 ## 問題の理解

 正の整数の配列と多くのクエリが与えられます。 各クエリは、この配列の連続したセグメントを選択します。 そのセグメントでは、2 人のプレーヤーが要素の選択されたサブシーケンスでゲームを効果的にプレイします。 

ゲーム内の移動では、1 より大きい要素を 1 つ選択し、1 より大きい適切な約数の 1 つに置き換えます。これは値を厳密に減少させるため、すべての要素は 1 になるまでしか減らすことができません。プレイヤーが移動しようとしていて、すべての数字がすでに 1 になっている場合、移動できず、すぐに勝ちます。 

各クエリ セグメントについて、プレーヤー A は、そのセグメントの空でないサブシーケンスを開始ゲーム配列として選択できます。 A が最初に動くと仮定して、最適なプレイの下でプレーヤー A の勝利を保証するそのようなサブシーケンスが何回あるかを数えなければなりません。 

制約はすべてのクエリにわたって合計サイズが小さく、配列の長さとクエリの合計がテスト ファイルごとに 1000 に制限されます。 これはすぐに次のことを示します。$O(n^2)$あるいは$O(n^2 \log n)$テスト ケースごとのスタイルのソリューションは許容されますが、大規模な構造に対するクエリごとの大量の再計算を伴うものは期待できません。 

実際に勝者を決めるのは微妙なポイントです。 それぞれの数値は独立して動作します。つまり、移動するたびに要素が 1 つだけ減ります。 選択した要素がすべて 1 になるとゲームは終了し、最後に移動したプレイヤーが勝ちとなります。 したがって、このゲームは、各数字が 1 になるまでに減らすことができる回数に等しい一定の移動数を与えるパイル ゲームと同等です。 

値を定義すると$g(x)$回数としては$x$1 になるまで適切な除数に置き換えることができ、その後、選択された各要素が寄与します。$g(x)$動く。 ゲームの合計長は、選択したサブシーケンスにわたるこれらの値の合計です。 プレイヤーは交代するため、合計の手数が奇数である場合に限り、プレイヤー A が勝ちます。 

したがって、タスクは次のようになります。クエリ セグメントごとに、重みの合計が次のようなサブシーケンスをカウントします。$g(b_i)$奇数です。 

単純な誤解は、因数分解シーケンスの構造が重要であると考えることです。 重要なのは有効な除数削減ステップの最大数だけです。各移動は常に 1 つの独立した要素を減少させるためです。 

エッジ ケースは、要素が 1 の場合に発生します。たとえば、セグメント内のすべての要素が 1 の場合、すべての要素が 1 である場合、$g(1)=0$, したがって、すべての部分シーケンスの合計は 0 となり、すべてのケースでプレイヤー A が負けます。 正解は 0 です。 

もう 1 つのエッジ ケースは、セグメントに単一の要素がある場合です。$x>1$。 その場合、答えは 1 になります。$g(x)$唯一のサブシーケンスがその要素を選択しているため、奇数、それ以外の場合は 0 になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリ セグメントについて、空でないすべてのサブシーケンスを列挙し、次の合計を計算します。$g(b_i)$、奇数かどうかを確認します。 これは正しいですが、非常に高価です: ある長さのセグメント$m$もっている$2^m - 1$後続のため、中程度の場合でも$m$これは爆発します。 

重要な単純化は、構造をパリティから分離することによって実現されます。 正確な合計は決して必要ではなく、それが奇数であるかどうかだけが必要です。 つまり、各要素は 2 を法とする 0 または 1 のいずれかに寄与します。$g(b_i)$偶数または奇数です。 各要素をバイナリ パリティ重みに変換すると、問題はバイナリ配列内の合計が奇数のサブシーケンスをカウントすることになります。 

これは古典的な組み合わせ計数問題です。 させて$k$セグメント内のパリティ 1 を持つ要素の数、および$m-k$パリティ 0 の数値。パリティ 0 の要素は、サブシーケンスの合計のパリティには影響しませんが、サブシーケンスの数に係数を乗算します。$2^{m-k}$。 

その中で、$k$関連する要素の場合、すべてのサブセットのちょうど半分が奇数の和を持ちます。$k>0$。 これは、各サブセットを最初のパリティ 1 要素の補数反転とペアにすることから得られます。 

したがって、答えは次のようになります。$$2^{m-k} \cdot 2^{k-1} = 2^{m-1} \quad \text{if } k>0$$そして 0 の場合$k=0$。 

したがって、答えはセグメントに奇数の要素が少なくとも 1 つ含まれているかどうかによってのみ決まります。$g(x)$。 事前計算ができる$g(x)$までのすべての値のパリティ$10^7$、各クエリについて、セグメント内のいずれかの位置に奇数パリティがあるかどうかを確認するだけです。 プレフィックス合計を使用すると、これは次のようになります。$O(1)$クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m)$クエリごと |$O(1)$| 遅すぎる |
 | 最適 |$O(n + q)$テストごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず理解する必要があるのは、$g(x)$は。 1 より大きい約数を選択するたびに、その数を減らし、最終的に 1 に達します。手数は、正確に次の素因数の合計数です。$x$多重度で数えます。 例えば、$12 = 2^2 \cdot 3$与える$g(12)=3$。 各移動は実質的に 1 つの素因数を削除します。 

したがって、次のパリティは$g(x)$は単に次の素因数の総数かどうかです。$x$奇数です。 

配列をバイナリ配列に変換すると、各要素の素因数が奇数の場合は 1、そうでない場合は 0 となり、各クエリは合計が奇数のサブシーケンスをカウントすることになります。 

ここで、次のように答えを計算します。 

1. 可能な最大値までのすべての値の素因数の数のパリティを事前計算します。$b_i$。 これは、素因数の数を累積するふるいのような方法を使用して行われます。 
2. 入力配列をパリティ配列に変換します。$p[i]$、 どこ$p[i]=1$もし$g(b_i)$奇数、それ以外の場合は 0。 
3. プレフィックス合計配列を構築します$p$これにより、各クエリ セグメントに少なくとも 1 つのインデックスが含まれているかどうかをすぐに判断できます。$p[i]=1$。 
4. 各クエリについて$[l, r]$、プレフィックスの合計を使用してセグメント内の 1 の数を計算します。 ゼロの場合は0を出力します。 
5. それ以外の場合は計算します$2^{(r-l+1)-1}$モジュロ$998244353$空でないパリティ 1 要素のセットは、サブセットの半分が奇数和に寄与することを保証するためです。 

### なぜ効果があるのか

 ゲーム全体は総手数と同等になり、各要素は独立してその同等性に貢献します。 各要素を 1 ビットに圧縮すると、サブシーケンスは要素を含めるか除外するかという独立した選択肢になり、パリティは XOR に対して線形に動作します。 重要な唯一の要素は、奇妙な貢献者が少なくとも 1 人存在するかどうかです。 存在しない場合、すべてのサブシーケンスの合計は偶数になります。それ以外の場合は、対称性により、すべてのサブシーケンスのちょうど半分が奇数の合計を生成することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXV = 10**7

# Precompute smallest prime factor up to max value seen in constraints
# We only need parity of number of prime factors (with multiplicity)
# We'll compute omega parity using sieve

spf = list(range(MAXV + 1))
is_prime = [True] * (MAXV + 1)
is_prime[0] = is_prime[1] = False

primes = []
for i in range(2, MAXV + 1):
    if is_prime[i]:
        primes.append(i)
        if i * i <= MAXV:
            for j in range(i * i, MAXV + 1, i):
                is_prime[j] = False

# compute omega parity
omega_parity = [0] * (MAXV + 1)
for i in range(2, MAXV + 1):
    if is_prime[i]:
        omega_parity[i] = 1
    else:
        # factor using primes
        x = i
        cnt = 0
        for p in primes:
            if p * p > x:
                break
            while x % p == 0:
                cnt ^= 1
                x //= p
        if x > 1:
            cnt ^= 1
        omega_parity[i] = cnt

t = int(input())
out = []

for _ in range(t):
    n, q = map(int, input().split())
    b = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + omega_parity[b[i]]

    inv2 = (MOD + 1) // 2

    for _ in range(q):
        l, r = map(int, input().split())
        ones = pref[r] - pref[l - 1]
        length = r - l + 1

        if ones == 0:
            out.append("0")
        else:
            out.append(str(pow(2, length - 1, MOD)))

print("\n".join(out))
```この実装では、最初にふるい分けと試行除算を使用して素因数パリティ テーブルを構築します。 テスト全体の制約の合計が小さいため、これは許容できます。 次に、各クエリは、プレフィックスの合計とべき乗を使用して一定時間内に応答されます。 

微妙な点は、ゲーム内で因子がどのように選択されるかを実際に知る必要はなく、因子除去ステップの合計数の同等性だけを知る必要があるということです。 これは、ゲームを単純な組み合わせ計数問題に崩壊させるものです。 

## 実用的な例

 配列を考えてみましょう$[2, 3, 4]$そしてクエリ$[1, 3]$。 パリティ分類が次のようになると仮定します。$p = [1,1,0]$。 接頭辞の合計から、接頭辞が 2 つあることが分かります。 

すべてのサブシーケンスを暗黙的に計算します。 サブシーケンスには 3 つの位置の要素が含まれている必要があります。 がある$2^3 = 8$サブシーケンスの合計。 パリティ 1 の要素が少なくとも 1 つあるため、組み合わせペアリングの後、すべてのサブシーケンスのちょうど半分が奇数の合計に寄与するため、答えは次のようになります。$2^{3-1}=4$。 

| ステップ | セグメント | パリティ数 | 長さ | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | [2,3,4] | 2 | 3 | 4 |

 これは、パリティ 1 の正確な分布がゼロでないこと以外は重要ではないことを示しています。 

ここで、すべての値が 2 の累乗であるセグメントを考えてみましょう。$[2,4,8]$。 それぞれは指数カウントに応じて偶数または奇数のパリティを持ちますが、すべてが 0 にマップされると仮定します。その場合、どのサブシーケンスも奇数の合計を生成できないため、答えは 0 になります。 

| ステップ | セグメント | パリティ数 | 長さ | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | [2,4,8] | 0 | 3 | 0 |

 これは、すべての値がパリティにおいて中立であるというエッジ ケースを裏付けています。

 ## 特殊なケース

 セグメントに 1 のみが含まれる場合、すべての要素の移動はゼロになるため、すべてのサブシーケンスの合計は均等になります。 このアルゴリズムはプレフィックスの合計をゼロとして正しく計算し、すぐに 0 を出力します。 

セグメントに奇数の素因数パリティを持つ要素が 1 つだけある場合、プレフィックスの合計は 1 となるため、答えは次のようになります。$2^{0}=1$、単一の有効な勝利サブシーケンスと一致します。 

セグメントに多くの 0 と少数の 1 がある場合でも、プレフィックス合計は少なくとも 1 つの寄与要素の存在を正しく検出し、組み合わせ因子は明示的に反復することなく残りの中立要素を自動的に考慮します。
