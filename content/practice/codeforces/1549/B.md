 ## 解決策
 ## 問題の理解

 サイズの正方形のボードが与えられます$n \times n$ただし、重要なのは最初と最後の行だけです。 下の行にはグレゴールのポーンが含まれ、上の行には敵のポーンが含まれています。 これら 2 つの行では、すべての列が空であるか、独立して占有されています。 

グレゴールはポーンを上に動かそうとします。 セルが空の場合、ポーンは常に 1 つのセルを真上に移動できます。 左上または右上に斜めに移動することもできますが、移動先のセルに敵のポーンがいる場合に限り、その場合は敵のポーンは削除されます。 ポーンが一番上の列に到達すると停止します。 

私たちは、グレゴールが任意の順序で動きを選択し、すべてのポーンを最適に調整すると仮定して、最終的に最上列に到達できるポーンの数を最大化したいと考えています。 

主要な構造的制約は、斜めのキャプチャは敵の位置に依存し、それ以外の場合は移動が空のスペースを介して純粋に垂直であるため、ポーンは最上列を介してのみ相互作用することです。 これにより、動的な複数行シミュレーションの問題が、開始位置と頂上までの利用可能なルートの間のマッチング スタイルの割り当てに軽減されます。 

入力サイズが大きいため、合計$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 これにより、ポーンごとのシミュレーションが除外されます。$O(n)$行またはテスト ケースごとの線形よりも悪いペアリング戦略。 ソリューションは各テスト ケースを次のように処理する必要があります。$O(n)$または$O(n \log n)$最悪の場合。 

素朴な考えによる微妙な失敗例は、各ポーンが到達可能な最上位セルへのパスが存在するかどうかを個別にチェックすると仮定することです。 斜めのキャプチャでは敵のポーンが消費されるため、下の 2 つのポーンが同じ敵のスロットをめぐって競合する可能性があるため、これは問題になります。 

たとえば、次のことを考えてみましょう。```
n = 3
top:    010
bottom: 111
```素朴なポーンごとのパス チェックでは、中央の敵のポーンを繰り返し使用することで 3 つすべてが上部に到達できると結論付けるかもしれませんが、敵のポーンはそれを使用する最初のキャプチャによって消費されるため、それは不可能です。 

もう 1 つの落とし穴は、移動を独立した垂直方向の到達可能性として扱うことです。 次のような構成:```
top:    100
bottom: 011
```下のポーンは両方とも上に移動できるように見えますが、左側のポーンには直接の垂直パスがなく、右側によって作成された構造に依存しており、一致する制約が変更されます。 

これらの問題は、問題がパスの存在に関するものではなく、下のポーンと上の行の使用可能な列の間の最適なペアリングに関するものであることを示唆しています。 

## アプローチ

 インタラクションを無視すると、各ポーンは独立してまっすぐ上に移動して最上列に到達しようとします。 これは、各列をスキャンして、明確な垂直通路があるかどうかを確認することを示唆しています。 これは単純です。各ポーンは、ローカルの障害物に基づいて成功するか失敗します。 

ただし、これは斜めのキャプチャを無視します。 垂直にブロックされたポーンでも、敵のポーンを消費できる場合は、左または右に移動することで上部に到達する可能性があります。 これにより、隣接する列間に結合が生じます。 

ブルートフォースアプローチでは、すべてのポーンの動きをシミュレートし、垂直方向と斜め方向の動きのすべての可能なシーケンスを調査し、敵の除去を動的にマークします。 複数のポーンが分岐して同じ敵セルをめぐって競合する可能性があるため、最悪の場合、これは急速に指数関数的になります。 ポーンごとに BFS を実装した場合でも、総作業量は次のようになります。$O(n^2)$、大きすぎます。 

重要な観察は、重要な唯一のインタラクションは、ポーンが最上行の到達可能な列と「ペア」にできるかどうか、つまり真上か、敵のポーンをブリッジとして使用して 1 列分効果的に移動させる単一の対角インタラクションを通じてであるかどうかであるということです。 

動きを注意深く解釈すると、各ポーンは最終的に上の行のいずれかの列で終了します。 列から始まるポーン$j$列でのみ終了できます$j$、$j-1$、 または$j+1$、最後のステップで斜めキャプチャを使用するかどうかに応じて異なります。 これにより、問題は、隣接関係の制約を伴う、下のポーンと上の行の利用可能な「ターゲット スロット」の間の貪欲なマッチングに変わります。 

列をスキャンして、各上位の位置を、そこに到達できる最も利用可能な下位のポーンと貪欲に一致させることを考えることができます。 並べ替えは不要です。 列はすでに順序付けされているため、2 ポインターまたはローカルで貪欲なスイープで十分です。 

最終的な解決策は、単純な左から右への貪欲な割り当ての下で、到達可能な上位の位置に下位のポーンをいくつ一致させることができるかをカウントすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | 貪欲なマッチングスイープ |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボードを列ごとにスキャンし、まだターゲットと一致していない利用可能な Gregor ポーンを追跡します。 私たちが見るたびに、`1`一番下の行では、それを使用可能なポーンのプールに追加します。 このプールは、これまでにその列の可能な限り最高の行に到達したポーンを表します。 
2. 上の行の列を左から右に処理します。 敵のトップポーンに遭遇したとき（`1`)、それに到達できる Gregor ポーンを割り当てようとします。 最良の選択は、シフト制約を回避できるため、可能な場合は同じ列のポーンを使用することです。 
3. 同じ列のポーンが使用できない場合は、斜めの移動でこの位置に到達できる隣接する列のポーンを使用しようとします。 これは、この列に合法的に移動できる最も近い利用可能なプールからポーンを消費することに対応します。 
4. 同じ列オプションも隣接列オプションも存在しない場合、この敵のポーンは最適なマッチングに使用できないため、スキップされます。 
5. 成功したすべての割り当てを、最上列に到達した 1 つのポーンとして数えます。 

この貪欲な順序が機能する理由は、ポーンの使用を遅らせても将来の可用性が向上することはないため、直接一致が存在する場合、前の列を後の列のために犠牲にすべきではないためです。 

### なぜ効果があるのか

 スイープのどの時点でも、関連する状態は各列内またはその近くに利用可能なポーンの数だけです。 ポーンは、それ自体の列または最上部の境界にある隣接する列の結果にのみ影響を与えることができるため、決定が隣接の 1 ステップを超えて広範囲に影響を与えることはありません。 

貪欲な選択は、常に最も近い利用可能なポーンを消費します。これは、代替案が直接一致を無駄にするか、後で対角移動の必要性を押し上げることになり、柔軟性が大幅に低下するためです。 これにより、交換引数が作成されます。つまり、非貪欲な割り当ては、一致の数を減らすことなく貪欲な割り当てに変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    top = input().strip()
    bottom = input().strip()

    # count available pawns
    available = [0] * n
    for i in range(n):
        if bottom[i] == '1':
            available[i] = 1

    ans = 0

    # greedy matching
    for j in range(n):
        if top[j] == '0':
            continue

        # try same column first
        if available[j]:
            available[j] = 0
            ans += 1
        else:
            # try left or right neighbor
            found = False
            if j > 0 and available[j - 1]:
                available[j - 1] = 0
                ans += 1
                found = True
            elif j + 1 < n and available[j + 1]:
                available[j + 1] = 0
                ans += 1

    print(ans)
```この実装では、一番下のポーンは、一番上の敵と一致すると消費できるリソースとして扱われます。 貪欲なスキャンにより、各上位セルが最も近い利用可能なポーンによって満たされることが保証され、将来の一致のために遠くのポーンが保存されます。 境界チェック$j = 0$そして$j = n-1$対角線の試行が無効なインデックスにアクセスしないようにしてください。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    out = []
    for _ in range(t):
        n = int(input())
        top = input().strip()
        bottom = input().strip()

        available = [0] * n

                available[j - 1] = 0
                ans += 1
            elif j + 1 < n and available[j + 1]:
                available[j + 1] = 0
                ans += 1

        out.append(str(ans))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 のような最小限のケース`top = 1, bottom = 0`割り当てるポーンが存在せず、アルゴリズムが正常に一致する分岐に入ることがないため、一致はゼロになります。 

ポーンは存在するが敵が存在しない場合など`top = 000, bottom = 111`、割り当てをトリガーする列がなく、スイープは上からのみ増加するため、結果はゼロになります。`1`s.

 境界が重いケースのような場合`top = 1000, bottom = 0001`エッジの隣接性をテストします。 アルゴリズムは範囲内にある場合にのみ左隣を正しく試行し、ポーンは許可されていない左方向のチェーンなしでは最初の列に到達できないため、最終結果はゼロになります。 

完全に高密度のケースにより、すべてのトップが保証されます`1`一番下のポーンは貪欲に消費され、再利用されることはないため、正確に 1 回一致します。
