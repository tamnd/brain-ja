 ## 解決策
 ## 問題の理解

 私たちには素数が与えられています$P$そして、テストケースごとに 2 つの整数を出力する必要があります$a$そして$b$両方が 2 と の間にあるように$P$、 と$a < b$、割ったときの余り$P$による$a$そしてによって$b$等しいです。 

より具体的に言えば、同じ素数を除算するときに同じ「残りの量」が残る 2 つの異なる約数を探します。 このようなペアをすべて見つける必要はなく、テスト ケースごとに有効なペアを 1 つだけ見つける必要があります。 

制約の値は大きいですが、構造は小さいです。 テストケースの数は最大1000で、それぞれ$P$と同じ大きさにすることができます$10^9$。 これにより、すべてのペアを検索しようとするアプローチは即座に除外されます。$(a, b)$またはすべての値を試してみることもできます$a$そして剰余を繰り返し計算します。 テスト ケースごとの二次スキャンや線形スキャンは不要ですが、理論的には実行可能です。 ただし、実際の制約は、テスト ケースごとに定数時間の構築が必要であるということです。 

微妙なエッジケースは許容される最小の素数です$P = 5$。 どのような建築物であっても尊重する必要があります$2 \le a < b \le P$。 次のようなものを選択しようとする素朴な試み$(P-2, P-1)$順序付けと剰余の等価性が任意のパターンに対して普遍的に成立しない可能性があるため、慎重にチェックしないと小さな値の場合は失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが試行されます$(a, b)$と$2 \le a < b \le P$かどうかを確認してください$P \bmod a = P \bmod b$。 これは条件を直接強制するため、正解です。 ただし、大まかに調べます$O(P^2)$ペアでは不可能ですが、$P$までです$10^9$。 単一のテスト ケースに制限しても、これは実行不可能になります。 

より構造化された観察は、状態が実際に何を意味するかを理解することで得られます。 同じ数値を除算したときに 2 つの剰余が同じ剰余を生成する場合、数値は次の形式で表すことができます。$P = k a + r = \ell b + r$共有された残りの部分について$r$。 重要な単純化は、残りを制御する必要がまったくないことです。 一致させるだけで十分です。 

秘訣は、単純な共有剰余を意図的に強制することです。 奇数の素数について$P$、選択する$a = 2$作る$P \bmod 2 = 1$。 他に見つけられたら$b$そのような$P \bmod b = 1$、終わりました。 最も単純な選択は、$b = P - 1$、分割するので$P$による$P - 1$常に余り 1 が残ります。 

これにより、問題はテスト ケースごとの定数時間の構築に縮小されます。

 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 素数を読み取る$P$。 ケース間に相互作用がないため、各テスト ケースを独立して処理します。 
2.修正$a = 2$。 これは最小の有効な選択であり、奇数の素数に対して予測可能な剰余パターンが保証されます。 
3.セット$b = P - 1$。 この選択により、次のことが保証されます。$b$常に範囲内にあり、すべての値について厳密に 2 より大きくなります。$P \ge 5$。 
4. 出力$a$そして$b$。 

この構造が有効である理由は、除算の算術的性質に由来します。 以来$P$は 2 より大きい奇数の素数であり、2 で割ると常に余り 1 が残ります。$P$による$P - 1$常に商 1 と剰余 1 が生成されます。$P = 1 \cdot (P - 1) + 1$。 これにより、必要な剰余の等価性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        p = int(input())
        print(2, p - 1)

if __name__ == "__main__":
    main()
```構築はテスト ケースごとに一定時間であるため、実装は直接的です。 入力によって次のことが保証されるため、ループ、検索、素数チェックは必要ありません。$P$プライムです。 

唯一の微妙な点は、次のことを保証することです$p - 1$は常に有効です。 以来$P \ge 5$、私たちはいつも持っています$p - 1 \ge 4$したがって、安全に 2 を超え、維持されます。$a < b$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        p = int(input())
        out.append(f"{2} {p-1}")
    return "\n".join(out) + "\n"

# provided samples
assert run("2\n17\n5\n") == "2 16\n2 4\n", "sample case"

# custom cases
assert run("1\n7\n") == "2 6\n", "small prime"
assert run("1\n11\n") == "2 10\n", "medium prime"
assert run("1\n5\n") == "2 4\n", "minimum boundary"
assert run("3\n5\n7\n13\n") == "2 4\n2 6\n2 12\n", "multiple cases"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 最も重要なエッジケースは最小の素数です$P = 5$。 この場合、唯一の有効な構造は厳密な不等式を満たさなければなりません。 アルゴリズムが生成するのは、$(2, 4)$であり、直接チェックすると両方の剰余が 1 に等しいことが示されるため、特別な処理を必要とせずに制約が満たされます。 

もう 1 つの暗黙的なエッジ ケースは、次のような大きな素数です。$10^9$。 そこでさえ、$P - 1$は有効なままであり、2 とは異なるため、オーバーフローや順序付けの問題によって構造が壊れることはありません。
