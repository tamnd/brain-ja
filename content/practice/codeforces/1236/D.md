 ## 解決策
 ## 問題の理解

 いくつかのブロックされたセルを含む長方形のグリッドが与えられます。 ブロックされていないすべてのセルが 1 回だけ訪問されるように、トークンは左上隅から開始してグリッド内を移動する必要があります。 移動には高度な制約があります。トークンには常に現在の方向があり、その方向に 1 ステップ前進します。各セルで方向を右に 1 回回転できますが、開始セルを含むセルごとに 1 回だけ回転できます。 セル内で右折した後、セルは新しい方向に移動し続けますが、後で再びそこに曲がることはできません。 

右、下、左、上の 4 つの方向は一定のサイクルを形成します。 したがって、この動きは、各セルが最大 1 回だけターニングポイントとして機能するグリッド上の歩行であり、その歩行は自由セル上のハミルトニアン パスでなければなりません。 

グリッド サイズは各次元で最大 10^5 に達する可能性があり、最大 10^5 の障害物が存在します。 これにより、すべてのセル上のウォークを明示的にシミュレートしたり、完全なグリッド表現を構築したりするアプローチは即座に除外されます。 正しい解決策は、横断ではなく、障害物によって引き起こされる構造に関する推論に依存する必要があります。 

重要な点は、この歩道が曲がり角が 1 つあるだけの単調な道ではないということです。 トークンは水平方向と垂直方向の動きを複数回切り替えることができますが、それは方向の変化が個別のセルで発生した場合に限られます。 これにより、単純な貪欲シミュレーションが誤解を招くことになります。 

最初の失敗例は、障害物によって狭い廊下で複数のジグザグが強制される場合に発生します。 ブロックされるまで常に真っ直ぐに進み、その後貪欲に方向転換するシミュレーションは、有効な構成であってもスタックする可能性があります。 

2 番目の微妙なケースは、障害物がまばらであるにもかかわらず、孤立した単一セルの「ポケット」を作成し、セルごとに 1 ターンのルールに違反して行または列の再訪問を強制する場合に発生します。 これらはローカルな移動ルールからは明らかではなく、行と列の交差の等価性に関するグローバルな推論が必要です。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての有効な歩行をシミュレートし、セルが 2 回訪問されないようにしながら、各ステップで前進するか右折するかを試行します。 これは、自由セルの数に 4 つの方向を乗じたサイズに比例するサイズの有向状態空間を効果的に検索することになります。 無効な再訪問を削除しても、各セルがターニングポイントになるかどうかのどちらかであり、セルを訪問する順序が重要であるため、検索空間は指数関数的なままになります。 最大 10^5 の空きセルがある場合、このアプローチは不可能です。 

重要な観察は、移動の制約により、有効な完全な横断に非常に厳格な構造が課されるということです。 各セルは一度しか使用できず、回転が制限されているため、パスは水平スイープと垂直スイープが交互に繰り返される一連の単調セグメントのように動作します。 このような各セグメントは、行または列の連続する区間全体を横断する必要があります。そうしないと、ターン制約に違反せずに一部のセルに到達できなくなります。 

これにより、問題は個々のステップについての推論から、障害物のない行と列の間隔がどのように接続されるかについての推論へと軽減されます。 経路はグリッド内を蛇行することを強制され、唯一の自由は蛇が方向を変える順序だけであり、これはブロックされたセルの境界構造によって完全に決定されます。 

これにより、問題は、障害物によって誘発された暗黙のコリドー構造が、再訪問や不正な方向転換を必要とせずに、すべての空きセルを正確に 1 回カバーする、(1,1) から始まる単一の接続された蛇行トラバースを形成するかどうかをチェックすることに変換されます。

 ## アルゴリズムのチュートリアル

グリッドを、障害物によって決定される水平および垂直の交互の強制セグメントとして再構成します。 パスは、境界または前進を妨げる障害物によって方向転換を余儀なくされるまで、常に直線的に移動します。 

1. 障害物を行方向および列方向にソートされた構造に格納すると、ある位置から任意の方向に最も近い障害物をすぐに見つけることができます。 最初のブロッカーが現れるまでは常に真っ直ぐに移動するため、これが必要です。 
2. 開始セル (1,1) から、方向 1 (右) への動きをシミュレートします。 セルごとにステップ実行する代わりに、その行内の最も近い障害物または境界に直接ジャンプします。 これらの点の間のセグメントは、その内部では回転できないため、一意に決定されます。 
3. 移動がブロックされている場合、現在のセルがまだ転換点として使用されていない場合は、そのセルで右折を試みます。 回転不可能な場合、またはすでに使用されている場合は、設定は無効です。 
4. 方向転換後、ユニットステップをシミュレートするのではなく、再び障害物の間をジャンプしながら、新しい方向に移動を続けます。 
5. 各行および列方向で既に使用されている境界を追跡することにより、訪問したセグメントの記録を暗黙的に維持します。 セグメントが反対方向に 2 回横断されると、ウォークはセルを再訪問することになり、これは無効です。 
6. それ以上動けなくなるまで続けます。 走査されたセルの数が空きセルの数と等しい場合、走査は有効です。 

本質的な単純化は、各移動が「方向の次の障害物」によって決定されるため、プロセス全体が O(k) ジャンプのシーケンスになるということです。 

### なぜ効果があるのか

 回転はセルごとに 1 回のみの使用に制限されているため、有効な完全なトラバースは最大の直線セグメントに分解する必要があります。 セグメント内では決定は存在しません。強制的に停止されるまでトークンは継続しなければなりません。 したがって、意味のある状態遷移のみが、障害物または境界によって定義されたセグメントの端点で発生します。 これにより、問題は、これらの強制遷移がセルを再訪問することなく、暗黙的なグリッド グラフの単一のオイラーのような走査を生成できるかどうかを検証することに分解されます。これは、まさにセグメント上のシミュレーションでチェックされることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, m, k = map(int, input().split())
    
    row = defaultdict(list)
    col = defaultdict(list)
    blocked = set()

    for _ in range(k):
        x, y = map(int, input().split())
        row[x].append(y)
        col[y].append(x)
        blocked.add((x, y))

    for r in row:
        row[r].sort()
    for c in col:
        col[c].sort()

    # direction: 0=right,1=down,2=left,3=up
    x, y = 1, 1
    d = 0

    visited_cells = 1
    total_free = n * m - k

    used_turn = set()

    def next_block_in_row(x, y, direction):
        arr = row.get(x, [])
        if direction == 0:
            lo, hi = y + 1, m + 1
            for v in arr:
                if v >= lo:
                    return x, v - 1
            return x, m
        else:
            lo, hi = -1, y - 1
            for v in reversed(arr):
                if v <= hi:
                    return x, v + 1
            return x, 1

    def next_block_in_col(x, y, direction):
        arr = col.get(y, [])
        if direction == 1:
            for v in arr:
                if v > x:
                    return v - 1, y
            return n, y
        else:
            for v in reversed(arr):
                if v < x:
                    return v + 1, y
            return 1, y

    while True:
        if d == 0:
            nx, ny = next_block_in_row(x, y, 0)
        elif d == 1:
            nx, ny = next_block_in_col(x, y, 1)
        elif d == 2:
            nx, ny = next_block_in_row(x, y, 2)
        else:
            nx, ny = next_block_in_col(x, y, 3)

        if (nx, ny) == (x, y):
            break

        visited_cells += abs(nx - x) + abs(ny - y)

        x, y = nx, ny

        if (x, y) in blocked:
            break

        if (x, y, d) in used_turn:
            break
        used_turn.add((x, y, d))

        d = (d + 1) % 4

    print("Yes" if visited_cells == total_free else "No")

if __name__ == "__main__":
    solve()
```このソリューションは、行と列ごとに並べ替えられた隣接リストを構築し、指定された方向の次の障害物の境界に直接ジャンプできるようにします。 その後、シミュレーションは水平方向と垂直方向のスイープを交互に繰り返しながら、常に現在の方向で到達可能な最も遠いセルに進みます。 

実装の微妙な詳細は、移動がセルごとの反復ではなく座標の差を使用して一括でカウントされることです。 グリッドには最大 10^10 のセルを含めることができるため、これは不可欠です。 

方向転換制限は、特定の状態 (セル、方向) が既に右折オプションを使用したかどうかを記憶することによってエンコードされます。 同じ構成が繰り返されると、プロセスがループしたり、無効な再利用が強制されたりするため、終了します。

 ## 特殊なケース

 1 by 1 などの最小限のグリッドは、アルゴリズムが移動を必要とせず、開始セルがトラバース要件をすでに満たしているものとして正しく処理することをテストします。 

障害物のないグリッドでは、シミュレーションが中断のない境界間のスイープを正しく処理するかどうかが重要になります。 トラバースは、障害物停止の欠落による早期終了を強制することなく、長方形全体をカバーする必要があります。 

障害物が連続して単一セルのギャップを形成する場合は、ブロックされたセルを誤って訪問済みとしてカウントしたり、不正な中間位置を作成したりすることなく、ジャンプがブロックされたセルを正しくスキップするかどうかをテストします。
