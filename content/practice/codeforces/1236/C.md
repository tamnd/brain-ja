 ## 解決策
 ## 問題の理解

 1 から 1 までの整数が与えられます。$n^2$、それぞれは高さによって配置されたラボを表しており、数字が小さいほど低く、数字が大きいほど高くなります。 ラボの各ペアの間には、番号の高いラボから番号の低いラボへ 1 単位の流れを許可する有向パイプがあります。 したがって、注文されたすべてのペア$(u, v)$可能な流量の 1 単位に寄与する場合$u > v$。 

これらを分割する必要があります$n^2$研究室に入る$n$それぞれが正確に含むグループ$n$ラベル。 任意の 2 つのグループ間$A$そして$B$と定義します。$f(A, B)$注文されたペアの数として$(u, v)$そのような$u \in A$、$v \in B$、 そして$u > v$。 これは単にグループから「下向きのエッジ」が何本あるかを数えているだけです$A$グループ化する$B$。 

目的は、次の値が最小になるようにパーティションを選択することです。$f(A, B)$グループのすべての個別のペアにわたって、可能な限り大きくします。 言い換えれば、弱いグループのペアを避けて、すべてのグループ間の下向き接続のバランスを可能な限り均等にしたいと考えています。 

入力制約$n \le 300$までを意味します$90{,}000$要素。 パーティションの数は超指数関数的に増加するため、すべてのパーティションを評価しようとするソリューションは不可能です。 単一のパーティションを単純にチェックするだけでもコストがかかります$O(n^4)$グループと要素に対してペアごとに実行すると、遅すぎます。$n=300$。 

貪欲な直感によるよくある失敗例は、連続する数字をグループ化することです。 たとえば、$\{1,2,3\}$、$\{4,5,6\}$、$\{7,8,9\}$いつ$n=3$非常に不均衡な流れが作成されます。大小のすべての相互作用がいくつかの方向に集中し、他の方向は弱くなります。 これは、最小限のグループ間フローを最大化するという目標に違反します。 

もう 1 つの落とし穴は、ランダムなグループ化または行優先の割り当てです。これにより、比較可能な値がクラスタリングされ、一方向のグループ間の反転は減少しますが、反対方向では対称的ではなくなり、再び最小値が低下します。$f(A,B)$。 

重要な難点は、$f(A,B)$は、値の絶対値ではなく、値の相対的な順序にのみ依存します。これは、任意のグループ化ではなく、構造化された並べ替えを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる分割方法が試行されます。$n^2$数字を入力する$n$サイズのグループ$n$、次に計算します$f(A,B)$グループのペアごとに。 たとえ 1 つのパーティションしかなかったとしても、すべてのパーティションを計算すると、$f(A,B)$コストを重視する$O(n^3)$、グループの各ペアを比較する必要があるため$n^2$要素のペア。 パーティションの数により、これは完全に不可能になります。 

構造的な洞察とは、数値を解釈することです。$n \times n$グリッドを作成し、対角線に沿ってグループを割り当てます。 目標は、任意の 2 つのグループについて、双方向で一貫した十分な数の「大企業から小企業へ」の関係が存在するようにすることです。 適切な構成は、各グループが異なる値の範囲に広がるように、循環対角パターンでグリッドを埋めることです。 

この問題で使用される標準的な構成は、行列に列ごとに、列ごとに交互の方向に数値を配置することです。 これにより、すべての行と列の相互作用のバランスが保たれ、単一の値範囲にグループが集中することがなくなります。 

この交互のジグザグ列構造により、グループのどのペアでも両方向に十分な反転が存在し、最小の反転が保証されます。$f(A,B)$最大化されます。

 | ブルートフォース | 指数関数 | O(n²) | 遅すぎる |
 | 柱ジグザグ構造 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、$n \times n$グリッドを作成し、それをグループとして行ごとに読み取ります。 

1. 空の$n \times n$マトリックス。 1から1までの数字を入れていきます$n^2$各行がグループになるように構造化された方法で。 

この構造により、各行には構造のさまざまな「レベル」からの数値が含まれるようになります。 
2. 1 から始まるカウンターを使用して、行列を列ごとに埋めます。 

各列ごとに$c$に応じて、番号を上から下または下から上のいずれかに配置します。$c$偶数または奇数です。 

この交互の方向により、隣接する列が行全体で大きい値と小さい値を異なる方法で分散することが保証され、行が大きい値のみまたは小さい値のみに偏るのを防ぎます。 
3. マトリックスを埋めた後、各行を 1 つのグループとして扱います。 

各行に正確に含まれるようになりました$n$個別の値、および 1 から 1 までのすべての値$n^2$は 1 回だけ使用されます。 
4. 各行をグループとして出力します。 

### なぜ効果があるのか

 列を交互に埋めることで、固定行の要素が制御されたパターンで高値領域と低値領域の両方に分散されるようになります。 任意の 2 つの行は、順序方向で列の少なくとも半分が異なるため、それらの間の安定した反転数が保証されます。 これにより、グループのペアが異常に小さくなることがなくなります。$f(A,B)$あまりにも多くの列にわたって、どちらのグループも他方のグループより一貫して上または下にないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

grid = [[0] * n for _ in range(n)]
num = 1

for col in range(n):
    if col % 2 == 0:
        for row in range(n):
            grid[row][col] = num
            num += 1
    else:
        for row in range(n - 1, -1, -1):
            grid[row][col] = num
            num += 1

for row in grid:
    print(*row)
```この構造では、列ごとに交互の方向で、列優先の順序で行列が埋められます。 これにより、値が行または列に沿って単調増加しないことが保証されます。これは、グループ間の比較のバランスを取るための中心的な要件です。 

各行はグループとして出力され、すべての値が 1 回だけ使用されるため、有効なパーティションが得られます。 

よくある実装上の間違いは、列ではなく行を交互に配置することです。これにより、対称性が崩れ、不均一な分布が生じます。 もう 1 つの間違いは、グループは構築中ではなく、完全に割り当てられた後に形成する必要があることを忘れていることです。

## テストケース```python
import sys, io

def solve():
    n = int(input())
    grid = [[0] * n for _ in range(n)]
    num = 1
    for col in range(n):
        if col % 2 == 0:
            for row in range(n):
                grid[row][col] = num
                num += 1
        else:
            for row in range(n - 1, -1, -1):
                grid[row][col] = num
                num += 1
    for row in grid:
        print(*row)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# samples
assert run("3\n") != "", "sample 1 basic sanity"

# custom cases
assert run("2\n") != "", "minimum size"
assert run("4\n") != "", "small even"
assert run("5\n") != "", "odd size structure"
assert run("10\n") != "", "larger grid"

 ## 特殊なケース

 のために$n=2$、グリッドは次のようになります。```
1 4
2 3
```行0は$\{1,4\}$、行1は$\{2,3\}$。 この構造では、最大の要素 4 と最小の要素 1 が分離されている一方で、中間の値が両方向に交差するため、2 つのグループ間の両方向の反転のバランスが保たれています。 

大型の場合$n$、列方向が交互になるため、行に一貫して大きい値または小さい値が蓄積されることがなくなります。 偶数列は低位から高位の順序を下方に押し出しますが、奇数列はそれを逆転させ、少なくとも半分の列にわたって任意の 2 行の反転構造が異なることを保証します。
