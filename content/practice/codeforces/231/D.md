 ## 解決策
 ## 問題の理解

 3 次元空間の特定の視点からボックス上に表示される数値の合計を計算するように求められます。 ボックスは軸に沿って配置されています。つまり、すべてのエッジが X、Y、Z 軸に沿っています。 その最小の角は原点にあり、反対側の角は座標にあります$(x_1, y_1, z_1)$。 6つの面のそれぞれの中央には数字が書かれています。 Vasya のポジションは厳密にボックスの外側です$(x, y, z)$。 課題は、6 つの数字のうちどれが見えるかを判断し、それらを合計することです。 

各面は平面に関連付けられます。 X 方向の場合、1 つの面は次の位置にあります。$x=0$そしてその逆は$x=x_1$。 同様に、Y 方向の面は次の位置にあります。$y=0$そして$y=y_1$、Z 方向の面は次の位置にあります。$z=0$そして$z=z_1$。 数字は、Vasya の視点がその面の外側にある場合にのみ表示されます。 次元に沿った彼の座標が顔の座標と等しい場合、彼にはそれを見ることができません。 

制約は、すべての座標と数値がその範囲内に収まることを示します。$10^6$絶対値で言うと。 入力ごとに必要なチェックは 6 つだけであるため、解決策は定数時間になります。 これらの境界については、アルゴリズムの効率性を心配する必要はありません。 

Vasya がボックスの平面と正確に一致しているが外側にある場合、明白ではないエッジ ケースが発生します。 たとえば、ボックスがすべての軸に沿って 0 から 1 までの範囲にあり、Vasya が (2,0,0) にある場合、彼は外側にいますが、彼の y 座標は y=0 の面と等しくなります。 彼は y=0 の面を見る必要はありませんが、x 方向と z 方向に沿った他の面を見ることになります。 不注意な実装では、等価性を正しく処理せずに、対応する軸に沿って外側にいるときはいつでも顔が見えると誤って想定する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、概念的に 3D で視点をシミュレートし、ボックスの中心に向かって光線を追跡したり、面ごとにオクルージョンをチェックしたりします。 これには、多くの幾何学的計算、浮動小数点演算が必要となり、場合によっては$O(n)$離散化された場合はレイごと。 単一のボックスの場合、これは過剰ですが、複数のボックスまたはより詳細な可視性チェックに拡張すると、スケールが不十分になります。 

重要な洞察は、ボックスが軸に沿って配置されており、長方形であることです。 これにより、各軸に沿った可視性を独立して扱うことができます。 X に沿って、Vasya の x 座標が x1 より大きい場合、彼は x=x1 にある顔を見ます。 0 未満の場合は、x=0 と見なされます。 彼は同じ軸に沿って両方の顔を見ることができません。 これを各軸に適用すると、簡単なルールが得られます。各寸法を個別にチェックし、Vasya が外側にある場合は、表示されている面の番号を追加します。 これにより、問題は最大 3 つの比較と 3 つの加算に減ります。 

ブルートフォースアプローチは概念的には正しいですが、不必要に複雑です。 軸を揃えた観測により、定数時間の計算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース 3D レイ シミュレーション | 単一ボックスの場合は O(1)、一般的な場合はより高くなります。 お(1) | やりすぎ |
 | 軸を揃えた比較 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Vasya の座標を読み取る$(x, y, z)$、箱の隅っこ$(x_1, y_1, z_1)$、および顔番号$a_1$を通して$a_6$。 これにより入力が設定されます。 
2. 変数を初期化する`total`ゼロに。 これにより、表示される数値の合計が蓄積されます。 
3. X 軸に沿った可視性を決定します。 もし$x > x_1$, Vasya はボックスの右側にいて、x=x1 (番号 a2) に顔が見えます。 もし$x < 0$、彼は左側にいて、x=0 (番号 a1) に顔が見えます。 彼は自分の平面上で顔を正確に見ることができないため、平等は無視されます。 
4. 同じロジックを Y 軸に沿って適用します。 もし$y > y_1$、彼は遠くの面y=y1（数字a4）を見ます。 もし$y < 0$、彼は y=0 (数値 a3) を見ます。 
5. 同じロジックを Z 軸に沿って適用します。 もし$z > z_1$、彼は上面z=z1（数字a6）を見ます。 もし$z < 0$、底面 z=0 (番号 a5) が見えます。 
6. 表示されていると識別された数値を合計し、結果を出力します。 

機能する理由: 各軸には正確に 2 つの面があります。 Vasya は各軸に沿ってボックスの片側にしか存在できないため、各軸につき最大 1 つの面しか見えません。 各軸を個別にチェックすると、表示されているすべての面がカウントされ、二重にカウントされたり欠落したりしないことが保証されます。 不変条件は、座標の比較が可視性と正しくマッピングされること、および等価性が非可視として扱われることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, y, z = map(int, input().split())
x1, y1, z1 = map(int, input().split())
a1, a2, a3, a4, a5, a6 = map(int, input().split())

total = 0

# X-axis visibility
if x < 0:
    total += a1
elif x > x1:
    total += a2

# Y-axis visibility
if y < 0:
    total += a3
elif y > y1:
    total += a4

# Z-axis visibility
if z < 0:
    total += a5
elif z > z1:
    total += a6

print(total)
```このソリューションは、軸に合わせた比較戦略を直接実装します。 X 軸セクションは左右の面を正確に識別し、Y 軸セクションは前後を処理し、Z 軸セクションは底面と上面を処理します。 Off-by-one エラーは厳密に使用することで回避されます。`<`そして`>`比較し、等しいということは顔が見えないことを意味するという問題の要件と一致します。
