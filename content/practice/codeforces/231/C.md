 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 整数の配列と限られた数のインクリメント操作が与えられます。 各操作で 1 つの要素が 1 つずつ増加し、同じ要素が複数回増加する可能性があります。 私たちの目標は、このような操作を最大 _k_ 回実行した後で、配列内にできるだけ多く出現する数値を見つけることです。 複数の数値が同じ最大周波数を達成できる場合は、最小のものを選択する必要があります。 

入力は 2 つの整数 _n_ と _k_ と、その後に続く _n_ 整数の配列で構成されます。 出力は、達成可能な最大周波数と、それを達成する最小の数値です。 

_n_ が 10^5 に達し、_k_ が 10^9 に達する可能性があることを考えると、考えられるすべての数値を反復して発生回数をカウントしたり、演算のあらゆる組み合わせを試行したりするアルゴリズムは遅すぎます。 2 秒の制限内では 10^10 の演算は不可能であるため、複雑度が O(n^2) の単純な総当たりソリューションはタイムアウトになります。 

考慮すべきエッジ ケースには、すべての数値が等しい配列、最適な結果を得るために演算を必要としない配列、周波数を達成する最小の数値が、より多くの演算で同じ頻度を達成できる数値よりも小さいシナリオなどが含まれます。 たとえば、入力の場合`3 3`配列あり`1 2 3`、1 と 2 をそれぞれ 2 回増分すると、3 が 3 回発生しますが、1 と 2 をそれぞれ 1 回増分すると、最大頻度に達する最小数は 2 になります。 

## アプローチ

 ブルート フォース アプローチでは、配列内のそれぞれの一意の番号が潜在的なターゲットとして考慮されます。 ターゲットごとに、すべての要素を反復処理し、このターゲットまで小さな数値を増やすために必要な増分数を計算できます。 操作を合計し、合計が _k_ 以下の場合、達成可能な頻度を記録します。 これが機能するのは、どの候補数値でも、他の数値をその数値と等しくするために必要な増分数が決定的であるためです。 ただし、各数値について配列全体をスキャンする可能性があるため、これは最悪の場合 O(n^2) になります。 

重要な洞察は、配列を並べ替えた後、スライディング ウィンドウ手法を使用して、連続する数値セグメントをウィンドウ内の最大の数値と等しくするために必要な演算数を効率的に計算できることです。 ソートされた配列のプレフィックスの合計を維持することにより、ウィンドウ内のすべての数値を右端の数値まで上げるのに必要な演算を一定時間内に計算できます。 次に、ウィンドウを前方に移動して、より大きなセグメントを検討します。 これにより、一度ソートしてからプレフィックス合計による線形パスを使用するため、複雑さが O(n log n) に軽減されます。 また、ソートすると、ソート順で最初に出現したものが常に最小となるため、複数の数値が同点の場合に最大の頻度を達成する最小の数値を簡単に選択することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | プレフィックス合計付きのスライディング ウィンドウ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を昇順に並べ替えます。 並べ替えにより、後で出現するより小さい数値を心配することなく、任意の連続する部分シーケンスが同じ値に増加する対象として考慮されることが保証されます。 
2. プレフィックス合計配列を構築します。 各インデックス _i_ のプレフィックス合計には、インデックス 0 から _i_ までのすべての要素の合計が格納されます。 これにより、任意の部分配列の合計を定数時間で計算できるようになります。 
3. 2 つのポインタを初期化します。`left`そして`right`、どちらも 0 から始まります。`right`ポインタは、他の数値を等しくすることを目的とした現在の数値を表します。 の`left`pointer defines the start of the segment.
 4. それぞれのポジションについて`right`からすべての要素を引き上げるのに必要な合計増分を計算します。`a[left]`に`a[right]`値に`a[right]`。 プレフィックス合計を使用すると、演算は次のようになります。`operations_needed = a[right] * (right - left + 1) - (prefix_sum[right] - prefix_sum[left-1] if left > 0 else prefix_sum[right])`。 
5. もし`operations_needed`_k_を超える、増分`left`ウィンドウが有効になるまで。 これにより、必要な操作が許可された _k_ 内に収まるまで、ウィンドウが左から効果的に縮小されます。 
6. 最大ウィンドウ長と対応する数値を追跡します。 複数の数値が同じ長さになる場合は、小さい方を選択します。 
7. 配列を走査した後、`right`、最大頻度と関連する数値を報告します。 

このアルゴリズムが機能するのは、並べ替えられた配列により、どのセグメントでも右端の数値が常に最大になることが保証されるためです。 セグメント内のすべての要素をこの値に増やすのに必要な操作は最小限です。 移動`left`操作制限を超えるたびに、常に有効なウィンドウを維持することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

prefix_sum = [0] * n
prefix_sum[0] = a[0]
for i in range(1, n):
    prefix_sum[i] = prefix_sum[i-1] + a[i]

max_freq = 1
best_num = a[0]
left = 0

for right in range(n):
    total = prefix_sum[right] - (prefix_sum[left-1] if left > 0 else 0)
    operations_needed = a[right] * (right - left + 1) - total
    while operations_needed > k:
        left += 1
        total = prefix_sum[right] - (prefix_sum[left-1] if left > 0 else 0)
        operations_needed = a[right] * (right - left + 1) - total
    window_size = right - left + 1
    if window_size > max_freq:
        max_freq = window_size
        best_num = a[right]

print(max_freq, best_num)
```この解決策は並べ替えから始まり、効率的なウィンドウ処理が可能になります。 プレフィックス合計により、必要な演算の定数時間計算が可能になります。 スライディング ウィンドウにより、_k_ 個の操作を決して超えず、有効なセグメントのみが考慮されることが保証されます。 厳密に大きな周波数で最良の数値を更新すると、同点の場合に最小の数値が選択されることが保証されます。 

## 実用的な例

 サンプル 1 入力`5 3`配列あり`[6, 3, 4, 0, 2]`。 

| 右 | 左 | a[右] | 必要な操作 | ウィンドウサイズ | 最大周波数 | ベスト番号 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 1 | 1 | 0 |
 | 1 | 0 | 2 | 2*2-3=1 | 2 | 2 | 2 |
 | 2 | 0 | 3 | 3*3-(0+2+3)=9-5=4>3 | 左=1 | 3*2-(2+3)=6-5=1 | 2 |
 | 3 | 1 | 4 | 4*3-(2+3+4)=12-9=3 | 3 | 3 | 4 |
 | 4 | 1 | 6 | 6*4-(2+3+4+6)=24-15=9>3 | 左=2 | 6*3-(3+4+6)=18-13=5>3 | 左=3 |

 このトレースにより、セグメントが`[2, 3, 4]`に変換できます`[4,4,4]`≤3 の演算を使用し、最小数 4 で周波数 3 を与えます。 

サンプル 2 入力`3 0`配列あり`[5,5,5]`。 スライディング ウィンドウは増分を必要としません。 best_num が 5 の場合、max_freq は 3 になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、プレフィックス合計を持つスライディング ウィンドウは O(n) |
 | スペース | O(n) | 長さ n のプレフィックス合計配列 |

 この解は、n が 10^5 まで、k が 10^9 までの時間とメモリの制限内に収まります。 整数演算以上の演算は必要ないため、64 ビット整数で十分です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    prefix_sum = [0]*n
    prefix_sum[0] = a[0]
    for i in range(1, n):
        prefix_sum[i] = prefix_sum[i-1] + a[i]
    max_freq = 1
    best_num = a[0]
    left = 0
    for right in range(n):
        total = prefix_sum[right] - (prefix_sum[left-1] if left > 0 else 0)
        operations_needed = a[right]*(right-left+1)-total
        while operations_needed > k:
            left += 1
            total = prefix_sum[right] - (prefix_sum[left-1] if left > 0 else 0)
            operations_needed = a[right]*(right-left+1)-total
        window_size = right-left+1
        if window_size > max_freq:
            max_freq = window_size
            best_num = a[right]
    return f"{max_freq} {best_num}"

assert run("5 3\n6 3 4 0 2\n") == "3 4"
assert run("3 0\n5 5 5\n")
```
