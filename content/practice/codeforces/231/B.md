 ## 解決策
 ## 問題の理解

 繰り返された変換の最終結果を考慮して、初期の整数シーケンスを再構築するように求められます。 Vasya には _n_ 枚のカードがあり、各カードには 1 から _l_ までの整数が含まれています。 繰り返し、彼は右端の 2 枚のカードを取り除き、左のカードから右のカードを引いた差を値とする新しいカードと置き換えます。 これはカードが 1 枚だけ残るまで続きます。 すべての操作を行った後、最後のカードの最終番号は _d_ になります。 タスクは、この最終結果を生成する可能性のある整数のシーケンスを見つけることです。 そのようなシーケンスが存在しない場合は、-1 を返します。 

入力制約は中程度です。_n_ は最大 100、各カードの範囲 _l_ は最大 100 です。これは、O(n²) または O(n·l) の複雑さのソリューションが許容されることを意味します。 最後の数値 _d_ の絶対値は最大でも 10⁴ ですが、これは 100 個の数値を超える可能性のある合計に比べて小さいため、Python では整数オーバーフローに直面することはありません。 

_n_ が偶数である場合と奇数である場合に、エッジ ケースが発生します。 減算は交互に行われるため、奇数と偶数の位置にある数値の寄与の符号が交互になります。 このパリティを無視する単純なアプローチでは、合計が _d_ に達する可能性があると誤って想定される可能性があります。 たとえば、_n=3_、_d=3_、_l=2_ の場合、シーケンス [2,1,2] が機能します。 しかし、交互効果を考慮せずに単純に合計を _d_ にする不注意なアルゴリズムでは、[1,1,1] のような不可能なシーケンスが提案される可能性があります。 

_d_ が _n_ と _l_ の可能な範囲外にある場合、別の微妙なケースが発生します。 たとえば、_n=4_、_l=2_、および _d=5_ の場合、取得可能な最大の差は 5 より小さいため、シーケンスは変換を満たすことができません。正しい解決策は、最初に実現可能性をチェックする必要があります。 

## アプローチ

 ブルートフォース手法では、1 から _l_ までの数字を含む長さ _n_ の考えられるすべてのシーケンスを試し、減算演算の繰り返しをシミュレートし、最終的なカードが _d_ に等しいかどうかを確認します。 このアプローチは原理的には正しいですが、非現実的です。シーケンスの数は lⁿ であり、爆発的に増加します。 _n=10_ と _l=10_ であっても、これは 10¹⁰ の可能性を与え、2 秒の制限時間をはるかに超えています。 

重要な洞察は、変換が線形であるということです。 元の各数値は、シーケンス内の位置に応じて +1 または -1 の係数を伴って最終的な数値に寄与します。 具体的には、i 番目の数値の寄与が交互になります。右から再帰的に展開される演算を考慮すると、1 番目、3 番目、5 番目などがプラスに寄与し、2 番目、4 番目、6 番目などがマイナスに寄与します。 したがって、最終的な数値は、単純に元のシーケンスの交互の合計になります。 奇数位置と偶数位置のカードの数がわかれば、交互の合計の最大値と最小値を計算できます。 _d_ がこの範囲内にある場合、解決策が存在します。 

シーケンスを構築するには、すべての数値が最小値 (1) または最大値 (l) であると仮定することから始めます。 この最小シーケンスの交互の合計が小さすぎる場合は、_d_ に達するまで、プラスに寄与する側の数値を増加させます。 この貪欲な構造により、すべての数値が範囲内に収まり、交互の合計が _d_ に等しくなることが保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(lⁿ) | O(n) | 遅すぎる |
 | 交互合計貪欲 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 奇数位置 (_odd_count_) と偶数位置 (_even_count_) の要素の数を計算します。 1 から _n_ までのインデックスが付いているシーケンスの場合、奇数の位置は 1、3、5、... であり、偶数の位置は 2、4、6、... です。 
2. 可能な最小および最大の交互合計を計算します。 最小和は、すべての奇数桁の数値が 1 で、すべての偶数桁の数値が 1 の場合に発生します。 合計の最大値は、奇数桁の数値が 1 で偶数桁の数値が 1 の場合に発生します。明示的に、`min_sum = odd_count * 1 - even_count * l`そして`max_sum = odd_count * l - even_count * 1`。 
3. 実現可能性を確認します。 _d_ が外にいる場合`[min_sum, max_sum]`、どのシーケンスもこの最終的な数値を生成できないため、-1 を出力します。 
4. シーケンスを構築します。 最小合計に向けて移動したい場合は、奇数の位置 (1) で最小の数値から開始し、偶数の位置 (l) で最大の数値から始めます。 _d_ と現在の交流合計の差を計算します。 次に、この差を合計が増加する位置の数値に段階的に分配します。増加する必要がある場合は奇数の位置、減少する必要がある場合は偶数の位置です。 数値は [1, l] 以内に収めてください。 
5. 結果のシーケンスを印刷します。 

機能する理由: 各ステップで、許容範囲内で数値を調整して、交互の合計を _d_ に向けてシフトします。 境界に違反しない調整のみを行い、合計に正しい方向に影響を与える正確な残りの差をポジション間で分配するため、可能であれば _d_ に到達することが保証されます。 シーケンスは制約に対して有効なままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, d, l = map(int, input().split())

odd_count = (n + 1) // 2
even_count = n // 2

min_sum = odd_count * 1 - even_count * l
max_sum = odd_count * l - even_count * 1

if d < min_sum or d > max_sum:
    print(-1)
    sys.exit(0)

# Initialize sequence: odd positions = 1, even positions = 1
seq = [1 if i % 2 == 0 else 1 for i in range(n)]  # 0-indexed
current_sum = sum(seq[i] if i % 2 == 0 else -seq[i] for i in range(n))
diff = d - current_sum

# Adjust odd positions first if we need to increase sum
for i in range(0, n, 2):
    if diff == 0:
        break
    increment = min(diff, l - seq[i])
    seq[i] += increment
    diff -= increment

# Adjust even positions if still needed
for i in range(1, n, 2):
    if diff == 0:
        break
    increment = min(diff, seq[i] - 1)
    seq[i] -= increment
    diff -= increment

print(' '.join(map(str, seq)))
```このソリューションでは、まず交互合計原理を使用して実行可能な合計範囲を計算します。 次に、すべての数値を最小値に初期化します。 の`diff`変数は、現在の合計が目的の _d_ からどれだけ離れているかを表します。 この差を、境界 [1, l] を尊重して、合計を増加できる数値に貪欲に分配します。 奇数の位置では合計がプラスに増加し、偶数の位置ではマイナスの合計が増加します。 両方のループの終わりまでに、`diff`はゼロであることが保証されており、有効なシーケンスが得られます。
