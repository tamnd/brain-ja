 ## 解決策
 ## 問題の理解

 3 人の友人がコンテストの各問題を個別に評価します。 すべての問題に対して、3 つの値が与えられます。それぞれの値は次のいずれかです。`0`または`1`。 

の値`1`友人は問題の解決方法を知っていると確信していることを意味します。 の値`0`彼らは自信がないことを意味します。 

チームには単純なルールがあります。3 人の友人のうち少なくとも 2 人が自信を持っている場合にのみ、問題に挑戦します。 私たちの仕事は、そのルールを満たす問題がいくつあるかを数えることです。 

入力は次から始まります`n`、問題の数。 それからフォローしてください`n`各行には、1 つの問題に対する Petya、Vasya、Tonya の意見を表す 3 つのバイナリ値が含まれています。 出力は単一の整数、つまりチームが解決する問題の数です。 

制約は非常に小さいです。 問題は最大 1000 個あり、各問題に含まれる数字は 3 つだけです。 すべての問題を個別に処理する単純なソリューションであっても、実行される操作はわずか数千回です。 線形時間ソリューションはどれも、2 秒の制限内で十分以上の速度を発揮します。 

よくある間違いは、少なくとも 2 人の友人ではなく、3 人の友人全員が自信を持っているかどうかを確認することです。 

例えば：```
1
1 1 0
```正しい出力は次のとおりです。```
1
```友人 2 人が同意しているので、問題は考慮されるべきです。 を使用した不注意な実装`sum == 3`間違って出力されてしまう`0`。 

もう 1 つの間違いは、少なくとも 1 人の友人が自信を持っているときに問題を数えることです。 

例えば：```
1
1 0 0
```正しい出力は次のとおりです。```
0
```自信を持っている友人は 1 人だけですが、これはチームのルールを満たしていません。 

最後のエッジケースは、ちょうど 2 人の友人が自信を持っている場合です。```
1
0 1 1
```正しい出力は次のとおりです。```
1
```条件は「2 つ以上」ではなく「2 つ以上」です。 

## アプローチ

 最も直接的なアプローチは、すべての問題を個別に検査することです。 特定の問題に対して、3 つのバイナリ値を追加します。 結果の合計から、どれだけの友人が自信を持っているかがわかります。 

合計が 2 以上の場合、答えを増やします。 

問題は 1000 件しかないため、この強引なアプローチでもすでに十分です。 最悪のケースでは、およそ 3000 回の整数読み取りと 1000 回の加算が実行されますが、これは些細なことです。 

重要な観察は、入力値がバイナリであるということです。 3 つの数字の合計が、まさに自信のある友達の数になります。 つまり、複雑なロジックやペアごとのチェックは必要ありません。 1 つの追加によって、チームが問題を解決できるかどうかがすぐにわかります。 

すべての問題は独立して 1 回だけ処理されるため、最適な解決策は入力を介した単純な線形スキャンです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 この問題では、制約が非常に小さく、直接スキャンがすでに最適化されているため、総当たりアプローチと最適アプローチは事実上同じです。 

## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、問題の数。 
2.初期化`answer = 0`。 
3. それぞれについて`n`問題がある場合は、3 つのバイナリ値を読んでください。 
4. それらの合計を計算します。 その合計は、その問題について自信を持っている友人の数に等しくなります。 
5. 合計が少なくとも`2`、増分`answer`。 

これは、少なくとも 2 人の友人が解決策を確信している必要があるというチームのルールと一致します。 
6. すべての問題を処理した後、印刷します。`answer`。 

### なぜ効果があるのか

 あらゆる問題に対して、自信に満ちた友人たちはそれぞれ正確に貢献します`1`合計に。 友達は 3 人だけなので、その合計はまさに自信のあるチーム メンバーの数になります。 

少なくとも 2 人の友人が自信を持っている場合に限り、チームは問題を解決します。 合計が少なくとも以下であるかどうかを確認する`2`したがって、問題の受け入れ条件をチェックすることとまったく同じです。 このテストをすべての問題に適用し、成功した問題をすべてカウントするため、最終的な答えは正しいことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
answer = 0

for _ in range(n):
    a, b, c = map(int, input().split())
    if a + b + c >= 2:
        answer += 1

print(answer)
```プログラムはまず問題の数を読み取ります。 

問題ごとに、3 つのバイナリ値を読み取り、それらの合計を計算します。 価値観はあくまで`0`または`1`, 合計は、自信を持っている友人の数を直接表します。 

合計が少なくとも`2`、カウンターが増加します。 すべての問題が処理されると、カウンターにはチームが挑戦する問題の正確な数が含まれます。 

難しい境界条件はありません。 条件は次のとおりです。`>= 2`、 ない`== 2`, なぜなら、友人3人全員が自信を持っているという問題もカウントされるべきだからです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    answer = 0

    for _ in range(n):
        a, b, c = map(int, input().split())
        if a + b + c >= 2:
            answer += 1

    return str(answer)

assert run(
    "5\n1 1 0\n0 1 1\n1 0 1\n1 1 1\n0 0 0\n"
) == "4", "mixed cases"

 ## 特殊なケース

 ちょうど 2 人の友人が自信を持っている場合を考えてみましょう。```
1
1 1 0
```アルゴリズムは以下を計算します。```
sum = 1 + 1 + 0 = 2
```以来`2 >= 2`、答えは次のようになります`1`。 チームのルールでは少なくとも 2 人の自信のあるメンバーが必要であるため、これは正しいです。 

次に、1 人の友人だけが自信を持っている問題を考えてみましょう。```
1
1 0 0
```アルゴリズムは以下を計算します。```
sum = 1
```以来`1 < 2`、答えは残っています`0`。 チームには問題を解決するのに十分な合意がありません。 

最後に、3 人の友人全員が自信を持っていると考えてください。```
1
1 1 1
```アルゴリズムは以下を計算します。```
sum = 3
```以来`3 >= 2`、問題はカウントされます。 これにより、条件が「正確に 2 つ」ではなく「少なくとも 2 つ」であることが確認されます。
