 ## 解決策
 ## 問題の理解

 頂点サボテンであることが保証されている接続された無向グラフが与えられます。 頂点サボテンでは、すべての頂点は最大でも 1 つの単純なサイクルに属します。 サイクルはアーティキュレーション ポイントを通じてグラフの残りの部分と接触する場合がありますが、2 つの異なるサイクルが頂点を共有することはできません。 

クエリごとに`(x, y)`で始まる個別の単純なパスがいくつあるかを数えなければなりません。`x`そしてで終わります`y`。 エッジのセットが異なる場合、2 つのパスは異なるものとみなされます。 答えは必須です`10^9 + 7`。 

グラフには最大で`10^5`頂点、`10^5`エッジ、および`10^5`クエリ。 グラフを直接探索してクエリを処理するソリューションは、直ちに除外されます。 たとえ`O(n)`クエリごとの計算には約`10^10`最悪の場合の運用。 

サボテンの制限が問題の核心です。 一般的なグラフでは、単純なパスを数えるのは非常に困難です。 サボテンでは、すべてのサイクルが独立して動作し、グラフをツリー状の構造に圧縮できます。 

クエリされた両方の頂点が同じサイクル内にある場合、微妙なケースが発生します。 

例：```
1-2
| |
4-3
```クエリ`(1,3)`には 2 つの単純なパスがあります。```
1-2-3
1-4-3
```パスの一意性を前提とするツリーベースのアプローチでは、誤った結果が返されます。`1`。 

もう 1 つの重要なケースは、2 つの頂点間のルートが複数のサイクルを通過する場合です。 

例：```
cycle A -- bridge -- cycle B
```一方の側からもう一方の側への単純なパスは、サイクル A 内で 1 方向を選択し、サイクル B 内で 1 方向を選択する必要があります。答えは次のようになります。`2 * 2 = 4`。 

エンドポイントのサイクルのみをチェックする不注意な実装では、この乗算効果を見逃してしまいます。 

3 番目のエッジ ケースは、パスがアーティキュレーション頂点を介してサイクルに接触するが、サイクルを横断する必要がない場合です。 そのようなサイクルは何も貢献しません。 エンドポイント間の圧縮ツリー パス上にあるサイクルのみが問題となります。 

## アプローチ

 ブルートフォースのアイデアは、クエリされた頂点間の単純なパスをすべて列挙することです。 

この問題は単純なパスの数を直接求めているため、これは正しいです。 残念ながら、単一のクエリであっても、多くのサイクルを持つグラフ内に指数関数的に多くの単純なパスが存在する可能性があります。 まで`10^5`クエリ、これは絶望的です。 

サボテンの性質は構造を劇的に変化させます。 すべての頂点は最大 1 つのサイクルに属するため、すべての二重接続コンポーネントは単一のエッジまたは単一のサイクルのいずれかになります。 

すべてのサイクルを 1 つの特別なノードに縮小すると何が起こるかを考えてみましょう。 

結果として得られる構造は木になり、しばしばサボテンのブロックカットツリーと呼ばれます。 

元の頂点は 1 種類のノードになります。 

各サイクルは別のタイプのノードになります。 

サイクルに属するすべての頂点は、そのサイクル ノードに接続されます。 

サイクルが重複することはないため、このグラフはツリーになります。 

次にクエリを考えてみましょう。 ツリー内の 2 つの頂点の間には、ルートが 1 つだけ存在します。 そのルートがサイクル ノードを通過するときは常に、対応するサイクルを通過する方法が 2 つあります。 時計回りまたは反時計回りにサイクルを一周することができます。 

異なるサイクルノードが独立して貢献します。 ツリーパスに次の内容が含まれている場合、`c`サイクルノードの場合、答えは簡単です。```
2^c
```したがって、問題は次のようになります。 

1. サボテンブロックツリーを構築します。 
2. クエリごとに、ツリー パス上にあるサイクル ノードの数を数えます。 
3. 戻る`2^(count)`。 

ツリー パス上のサイクル ノードのカウントは、プレフィックス合計に関する標準的な LCA 問題です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O((n+m) log n + k log n) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. すべてのサイクル頂点を検索します。 

DFS を実行し、標準検出時間と低リンク値を計算します。 

DFS がノードからのバックエッジに遭遇するたびに`u`先祖に`v`、DFS スタック上の頂点`u`に戻る`v`サボテンの1つのサイクルを形成します。 

グラフは頂点サボテンであるため、各頂点は最大でも 1 つのそのようなサイクルに属することができます。 

検出されたすべてのサイクルに識別子を割り当てます。 

### 2. ブロックツリーを構築する

 2 種類のノードを作成します。 

最初`n`ノードは元のグラフの頂点に対応します。 

検出されたサイクルごとに 1 つの追加ノードを受け取ります。 

サイクルに含まれる各頂点について、次のように接続します。```
vertex node <-> cycle node
```どのサイクルにも属さない頂点は、サイクル ノードから分離されたままになります。 

結果として得られるグラフはツリーです。 

その理由は、サボテンのすべてのブロックがエッジまたはサイクルのいずれかであり、そのようなグラフの標準的なブロックカット表現が非循環であるためです。 

### 3. サイクルノードをマークする

 重みを割り当てる:```
0 for original vertices
1 for cycle nodes
```後で、パスの合計により、見つかったサイクル ノードの数がカウントされます。 

### 4. LCA の前処理

 ブロック ツリーを任意の場所 (ノードなど) にルートします。`1`。 

計算:```
depth[u]
up[j][u]
pref[u]
```どこ`pref[u]`は、ルートからノードまでのサイクル ノードの数です。`u`パス。 

バイナリリフティングで得られるもの`O(log n)`LCA クエリ。 

### 5. 質問に答える

 しましょう`a`そして`b`元の頂点ノードになります。 

探す：```
l = LCA(a,b)
```ツリー パス上のサイクル ノードの数は次のとおりです。```
cnt =
pref[a] + pref[b]
- 2 * pref[l]
+ weight[l]
```このようなサイクルはすべて、係数 2 に寄与します。 

答えは次のとおりです。```
2^cnt mod MOD
```### なぜ効果があるのか

 すべてのサイクルを専用のサイクル ノードに置き換えると、サボテンは木になります。 元のグラフ内の 2 つの頂点間のルートは、対応するノード間の一意のツリー パスに対応します。 

このツリー パスがサイクル ノードを通過するたびに、元のパスは 1 つのサイクル頂点を通ってサイクルに入り、別のサイクル頂点を通って出ます。 単純なサイクルは、これらの頂点間に、サイクルの各方向に 1 つずつ、合計 2 つの異なる単純なルートを提供します。 

異なるサイクルは頂点を共有しないため、異なるサイクル内で行われる選択は独立しています。 したがって、サイクルが発生するたびに、有効な単純パスの数が 2 倍になります。 

ツリーパスのサイクル数は独立したバイナリ選択肢の数と正確に一致するため、答えは次のようになります。`2^(cycle count)`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

n, m = map(int, input().split())

g = [[] for _ in range(n + 1)]
for _ in range(m):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

tin = [0] * (n + 1)
low = [0] * (n + 1)
parent = [0] * (n + 1)
timer = 0

cycles = []
stack = []

sys.setrecursionlimit(300000)

def dfs(u, p):
    global timer
    timer += 1
    tin[u] = low[u] = timer

    for v in g[u]:
        if v == p:
            continue

        if not tin[v]:
            parent[v] = u
            dfs(v, u)
            low[u] = min(low[u], low[v])
        elif tin[v] < tin[u]:
            low[u] = min(low[u], tin[v])

            cyc = [v]
            cur = u
            while cur != v:
                cyc.append(cur)
                cur = parent[cur]
            cycles.append(cyc)

dfs(1, 0)

tot = n + len(cycles)
tree = [[] for _ in range(tot + 1)]

for idx, cyc in enumerate(cycles, start=1):
    cid = n + idx
    for v in cyc:
        tree[cid].append(v)
        tree[v].append(cid)

LOG = (tot + 1).bit_length()

depth = [0] * (tot + 1)
pref = [0] * (tot + 1)
up = [[0] * (tot + 1) for _ in range(LOG)]
weight = [0] * (tot + 1)

for i in range(n + 1, tot + 1):
    weight[i] = 1

def dfs_tree(u, p):
    up[0][u] = p

    if p:
        pref[u] = pref[p] + weight[u]
        depth[u] = depth[p] + 1
    else:
        pref[u] = weight[u]

    for v in tree[u]:
        if v != p:
            dfs_tree(v, u)

dfs_tree(1, 0)

for j in range(1, LOG):
    prev = up[j - 1]
    cur = up[j]
    for v in range(1, tot + 1):
        cur[v] = prev[prev[v]]

pow2 = [1] * (len(cycles) + 1)
for i in range(1, len(pow2)):
    pow2[i] = (pow2[i - 1] * 2) % MOD

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    diff = depth[a] - depth[b]
    bit = 0

    while diff:
        if diff & 1:
            a = up[bit][a]
        diff >>= 1
        bit += 1

    if a == b:
        return a

    for j in range(LOG - 1, -1, -1):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]

    return up[0][a]

q = int(input())

ans = []

for _ in range(q):
    a, b = map(int, input().split())

    l = lca(a, b)

    cnt = (
        pref[a]
        + pref[b]
        - 2 * pref[l]
        + weight[l]
    )

    ans.append(str(pow2[cnt]))

sys.stdout.write("\n".join(ans))
```すべてのサイクルを見つけた後、コードはサイクルごとに追加のノードを 1 つ作成し、そのノードをサイクルに属するすべての頂点に接続します。 これは重要な圧縮ステップです。 

ブロック ツリー上の DFS は、バイナリ リフティング祖先とサイクル ノードのプレフィックス カウントの両方を計算します。 プレフィックス数により、標準の LCA 式を使用してパスの合計を回復できます。 

微妙な点は、サイクルノード自体が重みを持っていることです。`1`、通常の頂点は重みを持ちますが、`0`。 これにより、パスの合計は発生したサイクル数と等しくなります。 

もう 1 つの詳細は、2 の累乗の事前計算です。 最大サイクル数は最大で`m`したがって、単純な線形事前計算で十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) + (n + c) log n + k log n) | DFS、ツリー前処理、LCA クエリ |
 | スペース | O((n + c) log n) | ブロックツリーとバイナリリフティングテーブル |

 ここ`c`はサイクル数であり、`c ≤ m`。 あらゆる制限がある中で`10^5`、複雑さは 2 秒の制限と 256 MB のメモリ制限内に簡単に収まります。

 ## 特殊なケース

 1 サイクルだけのグラフを考えてみましょう。```
4 4
1 2
2 3
3 4
4 1
1
1 3
```圧縮パスには、サイクル ノードが 1 つだけ含まれます。 アルゴリズムは戻ります`2^1 = 2`、サイクルの 2 つの方向に対応します。 

ここで次のことを考えてみましょう。```
5 5
1 2
2 3
3 1
3 4
4 5
1
5 3
```ブロック ツリー内のパスは次のようになります。```
5 -> 4 -> 3
```サイクルノードは通過されません。 サイクル数はゼロなので、答えは次のようになります。`1`。 これにより、ルートに接触するだけのサイクルが過剰にカウントされるのを防ぎます。 

最後に、ブリッジで接続された 2 つのサイクルを考えてみましょう。```
cycle A -- bridge -- cycle B
```グラフを横切るパスはすべて、サイクル A で方向を選択し、サイクル B で独立して方向を選択する必要があります。ブロックツリー パスには 2 つのサイクル ノードが含まれており、次のようになります。`2^2 = 4`。 乗算構造は、サイクルが決して重なり合わないというサボテンの特性から直接導き出されます。
