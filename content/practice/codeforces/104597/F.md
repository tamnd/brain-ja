 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テストケースには、$n$各カードの両面に 2 つの整数が書かれています。 すべてのカードについて、向きを選択します。片面は上を向いて、もう一方の面は下を向いて配置されます。 すべてのカードの向きを選択した後、すべての数字が上を向いているものと、すべての数字が下を向いている 2 つのマルチセットを調べます。 

要件は、これら 2 つのマルチセットのそれぞれ内で、異なる数値のすべてのペアが互いに素である必要があることです。 同様に、任意の素数に対して$p$、アップセット内で 2 つ以上の数は割り切れません。$p$、同じ制限がダウンセットにも当てはまります。 

タスクは、上向きの数字と下向きの数字の両方がこのペアごとの共素性条件を満たすように、カードの向きを選択する方法が何通りあるかを数えることです。$10^9+7$。 

重要な構造上のポイントは、各カードが正確に 1 つの数字をアップ セットに、1 つの数字をダウン セットに提供し、カードを裏返すとこれらの役割が入れ替わることです。 したがって、すべてのカードには二分決定が導入されますが、グローバル割り当ての有効性は、選択された数値全体に素因数がどのように分布するかによって決まります。 

制約は、強力な組み合わせによる解決策を意味します。 すべてのテスト ケースにわたるカードの合計数は最大で$10^5$、値は最大です$10^5$したがって、数値の因数分解と素数出現の集計は線形に近いか、$O(n \log A)$。 カードのペアを直接考慮するソリューションは、最悪の場合は二次関数となり、すぐに失敗します。 

同じカードの両面にプライムが出現する場合、微妙なケースが発生します。 たとえば、カードが次のような場合$(6, 10)$、両側に素数が含まれています$2$。 これはまだ有効ですが、方向に関係なく、そのカードは常にそのプライムをアップセットとダウンセットの両方に提供することを意味します。 これ自体はルールに違反しませんが、各方向で他のカードの出現が許可されるのは 1 つだけであるため、同じ素数を共有する他のカードに対するプレッシャーが増大します。 

もう 1 つの特殊なケースは、複数のカードが両面で共通の素数を共有する場合です。たとえば、次の倍数のみを含むカードが多数ある場合です。$2$。 カードを個別に処理する素朴な貪欲なアプローチは、競合がカードごとにローカルではなくプライムごとにグローバルであるため、ここでは失敗します。 

## アプローチ

 ブルートフォースソリューションはすべてを試みます$2^n$up と down の配列を構築し、ペアごとの gcd 条件を検証することで、向きを確認し、妥当性をチェックします。 割り当てごとに、両方の配列内のすべての数値を因数分解し、どちらのセットにも素数が 2 回出現しないようにします。 高速ファクタリングであっても、以下の確認が必要です。$O(n \log A)$割り当てごとに、$O(n 2^n)$実行可能な限界をはるかに超えた最悪の場合の動作。 

重要な観察は、制約が完全に素数によって駆動されるということです。 各素数は、アップセットで何回出現するか、ダウンセットで何回出現するかだけを気にするという意味で、独立して動作します。 固定素数の場合$p$、すべてのカードの中で、選択した向きが最大 1 つだけ配置されることを確認する必要があるだけです。$p$アップセットに配置し、ダウンセットに配置するのは 1 つだけです。 

これにより、問題はバイナリ変数 (カードの向き) に関する制約システムに変換されます。 各素数は、それを含むカード間で一連の禁止されたペアの組み合わせを引き起こします。 2 枚の異なるカードがどちらも同じ方向に同じプライムを配置することになった場合、その割り当ては無効になります。 

したがって、数字について考える代わりに、各カードを変数として考え、各素数を、それを含む変数間に矛盾が生じるものとして考えます。 すべてのプライムは、それを含むすべてのカードを接続しますが、それは「同じ方向のアクティベーション」制約によってのみ行われます。 この構造は、カード上の独立した連結コンポーネントに分解されます。2 つのカードは、両側で少なくとも 1 つの素数を共有する場合、同じコンポーネント内にあります。 素数が成分を横切らないため、成分は独立して解くことができます。 

各接続コンポーネントの内部では、制約の構造は、有効な割り当てが非常に単純な空間を形成することを暗示しています。つまり、1 枚のカードの方向を修正すると、他のすべてのカードは共有素数によって引き起こされる一貫性チェックに強制されます。 各コンポーネントは、0 (矛盾が発生した場合) または 2 (コンポーネントごとに 1 つの二者択一が存続する) のいずれかの係数に寄与します。 

これにより、問題は、ノードがカードであり、両側で少なくとも 1 つの素数を共有するカードをエッジで接続するグラフを構築するという問題に軽減されます。 次に、連結成分をカウントし、寄与を乗算します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべてのカードの両側にあるすべての数字を因数分解し、各カードに表示される素数のセットを収集します。 すべての制約が共有素因数によって駆動されるため、これが必要になります。 
2. カード上に和集合検索構造を構築します。 各プライムについて、それが少なくとも片面に表示されるカードのリストを維持します。 これらのカードはすべて、同じ接続コンポーネントに統合されています。 その理由は、そのプライムによって引き起こされる紛争はこのグループ内でのみ発生するため、それらを分離することはできないからです。 
3. すべての素数を処理した後、素集合の各コンポーネントは、選択が相互に依存するカードのグループを表します。 異なるコンポーネントのカードは素数を共有しないため、それらの割り当てが干渉することはありません。 
4. 各接続コンポーネントについて、一貫性をチェックします。 有効なコンポーネントには、自由度が 1 つだけあります。つまり、基本の方向を選択すると、主制約に違反することなく、他のすべての方向が決定されます。 したがって、各コンポーネントは係数 2 に寄与します。 
5. すべてのコンポーネントの寄与を剰余で乗算します。$10^9+7$。 

重要な特性は、カードが共有素数によってグループ化されると、各グループが独立して動作し、各グループ内では制約によって解空間が二項選択に縮小されることです。 

### なぜ効果があるのか

 2 つのカード間の無効な相互作用はすべて、素数の共有によって引き起こされます。 つまり、すべての制約エッジが Union-Find 構造内で完全にキャプチャされます。 コンストレイントがコンポーネントを横断することはできません。これは、すでにコンポーネントをマージしている共有プライムが必要となるためです。 

コンポーネント内では、素数によって引き起こされる制約によって、単一のグローバル フリップ決定を超える分岐は作成されません。 任意の割り当ては 1 枚のカードから伝播することができ、他のすべてのカードの向きは共有素数の一貫性によって決定されます。 矛盾が現れた場合、そのコンポーネントの寄与はゼロになります。 それ以外の場合は、正確に 2 つの対称割り当てが存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def sieve(max_n):
    spf = list(range(max_n + 1))
    for i in range(2, int(max_n**0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, max_n + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factor(x, spf):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    t = int(input())
    maxv = 100000
    spf = sieve(maxv)

    for _ in range(t):
        n = int(input())
        dsu = DSU(n)

        prime_owner = {}

        cards = []
        for i in range(n):
            a, b = map(int, input().split())
            pa = factor(a, spf)
            pb = factor(b, spf)
            cards.append((pa, pb))
            for p in pa | pb:
                if p in prime_owner:
                    dsu.union(i, prime_owner[p])
                else:
                    prime_owner[p] = i

        comp_has = {}
        for i in range(n):
            r = dsu.find(i)
            comp_has[r] = 1

        ans = 1
        for r in comp_has:
            ans = (ans * 2) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```ふるいは、数値を効率的に因数分解するために使用されます。$10^5$、ファクタリングの総コストを管理します。 各カードは 1 回処理され、各素因数を使用して DSU 内のコンポーネントがマージされます。 

DSU は、素数を共有する 2 枚のカードは一緒に解決されなければならないという考えを正確に捉えています。 圧縮後、カウントは独立したコンポーネントの積になります。

 ## 特殊なケース

 重要なエッジケースは、すべてのカードが単一の素数を共有する場合です。たとえば、次のような多くのペアがあります。$(2,3)$、$(4,2)$、$(6,10)$。 この場合、すべてのカードが 1 つのコンポーネントにマージされ、答えは 2 に集約されます。素数が出現するたびに和集合がトリガーされるため、DSU はすべてのノードを正しくマージします。 

もう 1 つのエッジ ケースは、カードが素数で完全にバラバラである場合です。たとえば、$(2,3)$、$(5,7)$、$(11,13)$。 結合は発生せず、各カードは独自のコンポーネントを形成し、結果は次のようになります。$2^n$、アルゴリズムはコンポーネントごとに 2 を乗算することで正しく計算します。 

3 番目のケースは、1 枚のカードの両面に素数が現れる場合です。 例えば$(6,10)$ここで、両側に 2 が含まれます。アルゴリズムは引き続き、2 を含む他のすべてのカードとカードを結合しますが、結合は冪等であり、コンポーネントのサイズは変更されないため、誤って二重にカウントされることはありません。
