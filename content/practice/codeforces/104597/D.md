 ## 問題の理解

 私たちは隠された価値と対話しています$x$間$1$そして$n$。 ～について学ぶ唯一の方法$x$それを順列内に格納された値と比較することです。 

最初は順列が恒等式であるため、位置$i$値が含まれています$i$。 インデックスをクエリするとき$i$、2つのことを順番に行います。 まず、現在位置に格納されている値を比較します。$i$と$x$、それが小さいか、等しいか、大きいかがわかります。 2 番目に、間のセグメントを反転することによって順列が変更されます。$i$そして現在の位置は$x$。 この 2 番目のステップが問題を非標準的なものにします。クエリごとに、値を見つけるために依存する構造が変更されます。 

目標は、実際の数値を決定することです。$x$、その位置ではなく、テスト ケースごとに最大 50 個のクエリを使用します。 

制約$n \le 30000$クエリごとの線形作業を再構築または順列スキャンに費やすアプローチは除外されます。 ただし、50 個のクエリは十分小さいため、各比較を効率的にサポートできれば、値空間に対する対数検索が妥当です。 

主な微妙な点は、クエリは情報を与えるだけでなく、決定論的ではあるが履歴に依存する方法で要素を移動させることもできるということです。 これを無視し、順列が単純なままであると仮定する単純な戦略は、すぐに破綻します。正確に追跡しない限り、いくつかのクエリの後、構造が大幅にスクランブル化されるためです。 

小さいながらも重要なエッジ ケースは、最初のクエリです。 逆転が起こる前は順列がきれいなので、最初の比較は次のとおりです。$x$そしてリテラルのインデックス値。 その後、すべての値が移動した可能性があるため、「位置」を前提とした推論は無効になります。$i$値が含まれています$i$」は、置換状態を明示的に維持しない限り、すぐに無効になります。 

## アプローチ

 ブルートフォース戦略で回復を試みる$x$構造を維持せずに、インデックスを繰り返し調査し、比較のみから推論することによって。 問題は、各クエリの後に、現在の位置を含むセグメントの順列が逆になることです。$x$これは、固定インデックスで表示される値が安定していないことを意味します。 多くのクエリでは、同じインデックスがまったく異なる値を表す場合があり、比較を一貫して解釈することが不可能になります。 各クエリでは状態の分岐構造が導入され、指数関数的に増大するため、すべての可能性をシミュレートしようとしても失敗します。 

重要な観察は、順列は変化しますが、完全に決定論的な方法で変化するということです。 クエリインデックスを制御し、どこに適用されたかを知っているため、どの反転操作が適用されたかを常に正確に把握できます。$x$現在順列中です。 つまり、値から位置への逆マッピングを含め、順列全体を明示的に維持できるということです。 

これが受け入れられると、各クエリは単純になります。つまり、次のクエリ間の比較を求めることができます。$x$既知の値を取得するには、その値が現在存在する位置をクエリします。 これにより、問題は値ドメインでの標準検索に集約されます。$[1, n]$ここで、各ステップは比較のオラクルです。 

これにより、値の二分検索が可能になります。 順列は常に変化しますが、常に現在の位置で値を見つけてクエリを実行し、一貫して構造を更新できます。

 ## アルゴリズムのチュートリアル

 プロセス全体を通じて 2 つの配列を維持します。1 つは順列用で、もう 1 つは値から位置への逆マッピング用です。 現在の位置も追跡します$x$、常に最新のクエリのインデックスになります。 

### ステップ

 1. 順列を恒等として初期化し、各値が次のようになるように逆マップを構築します。$v$位置にあります$v$。 現在の位置も設定します$x$不明として。 
2. 最初に選択したインデックス (通常は範囲の中央の位置、または単純に 1) でクエリを実行します。これにより、次のものが直接比較されます。$x$そして既知の値。 このクエリの後、現在の位置を学習します。$x$、反転が動くので$x$クエリされたインデックスに。 
3. この時点から、常に完全な順列がわかります。 比較したいとき$x$価値のあるもの$v$、インデックスをクエリします。$v$現在位置しています。 
4. 値の範囲に対して二分探索を実行します。$[1, n]$。 中間点に向けて$mid$、逆マップを使用して現在の位置を特定し、クエリします。 応答により、次のことがわかります。$mid < x$、$mid = x$、 または$mid > x$これは、二分探索境界をどのように移動するかを直接決定します。 
5. 各クエリの後、クエリされたインデックスと現在の位置の間のセグメントに必要な反転を適用します。$x$。 これにより、順列と逆マッピングの両方が更新されます。 
6. クエリが等しい値を返した場合、見つかった値をすぐに出力します。 

これが機能する主な理由は、すべての比較が常にクエリされた位置に格納されている真の値と比較され、各値が現在どこに存在するかについての正確な知識が維持されるためです。 順列は変化しますが、不明になることはありません。 

### なぜ効果があるのか

 いつでも、置換状態の正しい表現を維持します。 逆マップにより、テストしたい値の現在位置を一定時間内に見つけることができます。 各クエリは、次のことを正確に比較します。$x$と既知の値が設定され、その後の反転が完全にシミュレートされるため、隠れた状態は残りません。 これにより、バイナリ検索の決定が常に正確な比較に基づいて行われることが保証されます。つまり、検索間隔は常に正確に縮小されます。$x$特定される。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i)
    sys.stdout.flush()
    return input().strip()

def solve_case(n):
    # permutation and inverse map
    p = list(range(n + 1))
    pos = list(range(n + 1))

    def reverse(l, r):
        while l < r:
            vl, vr = p[l], p[r]
            p[l], p[r] = vr, vl
            pos[vl], pos[vr] = r, l
            l += 1
            r -= 1

    # initial query to discover x position movement behavior
    first = 1
    resp = ask(first)
    if resp == "=":
        print("!", 1)
        sys.stdout.flush()
        input()
        return

    # after first query, x is at position first
    x_pos = first

    # binary search over values
    lo, hi = 1, n

    while lo <= hi:
        mid = (lo + hi) // 2
        i = pos[mid]

        resp = ask(i)

        if resp == "=":
            print("!", mid)
            sys.stdout.flush()
            input()
            return

        # current position of x is always last queried index
        j = x_pos

        if i != j:
            reverse(min(i, j), max(i, j))
            x_pos = i

        if resp == "<":
            lo = mid + 1
        else:
            hi = mid - 1

    print("!", lo)
    sys.stdout.flush()
    input()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```この実装では、すべての値の位置が常に分かるように、順列を明示的にシミュレートします。 の`pos`配列は、「値 Mid との比較」を具体的なインデックス クエリに変換できるため、非常に重要です。 

変数`x_pos`非表示の値が現在どこにあるかを追跡します。 この問題により、反転によってクエリされたインデックスと以前の位置が常に移動されることが保証されるため、クエリのたびに更新されます。$x$セグメントの両端に接続します。 

両方を維持するには注意が必要です`p`そして`pos`そうしないと、後のクエリで間違った場所が参照され、二分探索が中断されてしまいます。 

## 実用的な例

 小さな例を考えてみましょう。$n = 5$そして$x = 3$。 最初の順列は$[1,2,3,4,5]$。 

インデックス 2 をクエリした後、比較します$2$と$3$、「<」を取得し、セグメントを反転します$[2,3]$、生産$[1,3,2,4,5]$。 値 3 は位置 2 に移動し、これが現在の位置になります。$x$。 

ここで、位置 4 に移動して値 4 をクエリするとします。$4$と$x=3$、「>」を取得し、セグメントを反転します$[2,4]$、生産$[1,4,2,3,5]$。 の位置$x$再びクエリインデックスに移動します。 

このシーケンスは、順列が変化しているにもかかわらず、各値がどこにあるかを常に正確に知っているため、比較が引き続き意味のあることを示しています。 

2 番目の例は、$n = 4, x = 1$は、インデックス 1 をクエリするときの直ちに等価の場合を示しています。応答「=」は、前の構造に関係なくプロセスを終了し、等価クエリが常に安定したアンカーであることを示しています。

 ## 特殊なケース

 のために$n = 2$、二分探索は単一の比較に退化します。 順列の逆転は依然として発生しますが、値の正しい現在位置を常にクエリするため、逆マッピングにより比較が有効なままであることが保証されます。 

のために$x = 1$または$x = n$、すべての比較はすぐに検索を一方の側に偏らせます。 順列は依然として反転しますが、位置を明示的に追跡するため、境界値の位置を失うことはありません。 

最初のクエリがエンドポイントで発生する場合、反転は完全なプレフィックスに影響を与えるか何もせず、各操作後に順列が完全に既知であるという不変条件が保持されるため、システム全体は引き続き一貫して動作します。
