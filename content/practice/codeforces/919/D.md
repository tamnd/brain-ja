 ## 解決策
 ## 問題の理解

 各頂点が小文字を持つ有向グラフが与えられます。 有効なウォークはノードからノードへ有向エッジをたどります。方向を尊重する限り、ノードとエッジを再訪することができます。 

このようなウォークでは、訪問したノードに沿って遭遇する一連の文字を調べます。 ウォークの値は、そのシーケンスに沿った任意の単一文字の最大頻度として定義されます。 たとえば、ウォークによって文字列「abaca」が生成される場合、最適な文字は 3 回出現する「a」であるため、値は 3 になります。 

タスクは、可能な最大値を持つウォークを見つけることです。 ある文字の出現を無限に蓄積し続けることを可能にするサイクルが存在する場合、答えには制限がなく、-1 を返さなければなりません。 

入力サイズは最大 300,000 のノードとエッジに達します。 これにより、パスを列挙したり指数関数的な探索を実行したりするアプローチは即座に除外されます。 実際には O(n²) でさえ大きすぎるため、線形または線形に近いグラフ走査戦略を余儀なくされます。 

グラフに有向サイクルが含まれる場合、微妙なエッジ ケースが発生します。 そのサイクルが到達可能で、特定の文字に寄与するノードが少なくとも 1 つ含まれている場合、無限にループすることでその文字の数を際限なく増やすことができます。 たとえば、ノード 1 → 2 → 3 → 1 がサイクルを形成し、すべてが文字「a」を持つ場合、答えは -1 になります。 再訪問を検出せずに最良のパス合計を追跡する単純な DFS は、サイクルを誤って有限として扱い、制限された答えを生成します。 

もう 1 つの問題は、サイクルが存在する場合でも、そのすべてが無限を意味するわけではないことです。 サイクルは存在するが、そのサイクルに存在しない文字を数えている場合、そのサイクルはその文字の頻度を増やすのに役立ちません。 正しい推論は、到達可能性だけでなく、文字固有の蓄積を追跡することに依存します。 

## アプローチ

 ブルートフォース戦略では、グラフ内のすべてのパスを探索し、各パスに沿った文字の頻度を計算しようとします。 すべてのノードから DFS を実行し、26 個の長さの周波数配列を維持し、グローバル最大値を更新することを想像することもできます。 これは、小さなグラフでは概念的には正しいですが、各ノードが多くのパスを介して再訪問される可能性があり、サイクルによって無限に多くのウォークが作成されるため、失敗します。 単純なパスに限定したとしても、有向グラフ内のパスの数は指数関数的に増加する可能性があります。 

重要な洞察は、視点を逆転させることです。 パスの観点から考える代わりに、これを DAG 上の最長パスの問題として扱いますが、一工夫あります。文字ごとに 1 つずつ、26 の独立した動的プログラムが必要です。 各文字 c について、各ノードで終わるパスに沿った c の最大出現数を計算したいとします。 

グラフにサイクルがない場合、これは簡単です。 グラフを位相的に並べ替えて遷移を緩和することができます。各エッジ u → v に対して、最良の値を前方に伝播します。 サイクルの存在はこれを破りますが、カーンのアルゴリズムを使用してサイクルを検出できます。 すべてのノードを位相順序で処理できない場合、サイクルが存在します。また、どのサイクルもパスに沿って繰り返し通過できるため、到達可能なサイクルに沿って少なくとも 1 つの文字について任意に大量の蓄積が行われる可能性を意味します。 その場合は -1 を返します。 

したがって、解決策は、DAG 構造に対するサイクル検出とマルチソース動的プログラミングの組み合わせになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース DFS | 指数 | O(n) | 遅すぎる |
 | トポソート + 文字ごとの DP | O(26 · (n + m)) | O(26・n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字を独立して処理し、トポロジカルな順序付けに基づく DP を使用して、可能な限り最良の数を計算します。

1. 隣接リストを作成し、すべてのノードの次数を計算します。 これにより、グラフが非巡回である場合に有効な位相順序でノードを処理するカーンのアルゴリズムの準備が整います。 
2. DP テーブルの初期化`dp[v][c]`文字の最大出現数を意味します`c`ノードで終わる任意のパスに沿って`v`。 最初はすべてゼロです。 If ノード`v`それ自体に文字があります`c`、設定しました`dp[v][c] = 1`。 
3. 次数 0 のすべてのノードをキューにプッシュします。 これらは、あらゆるパスの有効な開始点です。 
4. ノードを繰り返しポップする`u`キューからその DP 値をその近隣に伝播します。`v`。 文字ごとに`c`、更新を試みます:`dp[v][c] = max(dp[v][c], dp[u][c] + (1 if s[v] == c else 0))`。 

この手順により、次で終わる最適なパスが確実に存在します。`u`まで拡張できます`v`。 
5. エッジを緩和するたびに、宛先ノードの次数をデクリメントします。 ゼロになった場合はキューにプッシュします。 これにより、正しいトポロジー処理順序が維持されます。 
6. 処理されたノードのカウンターを保持します。 キューが終了した後、すべてのノードが処理されていない場合、サイクルが存在します。 その場合は、-1 を返します。これは、一部のサイクルを使用して走査を無限に繰り返すことができ、答えが無制限になるためです。 
7. 処理後の答えは、すべての dp[v][c] の最大値になります。 

DP の背後にある理由は、DAG 内の有効なパスはトポロジー順序に従って分解でき、最良のパスを隣接パスに拡張することで最適性が維持されるため、最適な下部構造が保持されるということです。 

### なぜ効果があるのか

 核となる不変条件は、ノードが`u`がキューからポップされ、すべてのパスが次で終わります。`u`DP 値に関してはすでに十分に考慮されています。 これはトポロジカルな順序付けによって保証されます。つまり、すべての入力エッジが`u`すでに処理されたノードから発生したものです。 

したがって、`dp[u][c]`最終的なのはいつですか`u`が処理され、近隣への今後の更新はすべて、完全な部分問題解決策に基づいて正しく構築されます。 すべての非巡回グラフではトポロジカルな順序付けが認められるため、すべての有効なパスを依存関係の順序で 1 回だけ探索することが保証されます。 

サイクルが存在する場合、カーンのアルゴリズムはすべてのノードを処理できません。これは、有効なトポロジー順序付けが存在しないことを意味します。 これはサイクルの存在に正確に対応しており、この問題では、あるパスに沿って無限に繰り返される可能性を意味しているため、-1 を返すのは正しいことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        indeg[y] += 1

    dp = [[0] * 26 for _ in range(n)]

    for i in range(n):
        dp[i][ord(s[i]) - 97] = 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    visited = 0

    while q:
        u = q.popleft()
        visited += 1

        for v in g[u]:
            for c in range(26):
                val = dp[u][c] + (1 if ord(s[v]) - 97 == c else 0)
                if val > dp[v][c]:
                    dp[v][c] = val

            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    if visited < n:
        print(-1)
        return

    ans = 0
    for i in range(n):
        ans = max(ans, max(dp[i]))
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、カーンのアルゴリズムに依存して非周期的な処理順序を強制します。 DP テーブルはエッジ緩和中に適切に更新され、各状態はそのノードまでの各文字について達成可能な最良の頻度を表します。 一般的な実装の落とし穴は、初期化を忘れることです`dp[i][s[i]] = 1`これにより、開始ノードが独自の文字の出現に寄与しないものとして誤って処理されてしまいます。 

もう 1 つの微妙な点はサイクル検出です。ノードが再訪問されているかどうかを単にチェックするだけでは十分ではありません。 正しい基準は、トポロジー処理がすべてのノードを終了するかどうかです。

## 複雑さの分析

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    s = input().strip()

    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        indeg[y] += 1

    dp = [[0] * 26 for _ in range(n)]
    for i in range(n):
        dp[i][ord(s[i]) - 97] = 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    visited = 0

    while q:
        u = q.popleft()
        visited += 1
        for v in g[u]:
            for c in range(26):
                val = dp[u][c] + (1 if ord(s[v]) - 97 == c else 0)
                if val > dp[v][c]:
                    dp[v][c] = val
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    if visited < n:
        return "-1"

    return str(max(max(row) for row in dp))

 ## 特殊なケース

 最小限のノード グラフで初期化動作をテストします。 「a」というラベルが付けられた単一のノードにはエッジがないため、DP は直接 1 を返す必要があります。アルゴリズムは dp[0][a] = 1 を初期化し、すぐに処理して、正しい結果を生成します。 

完全に周期的なグラフは、無制限の増加の検出をテストします。 三角形サイクル 1 → 2 → 3 → 1 では、すべてのノードの度数が 0 になることはないため、カーンのアルゴリズムは n 個未満のノードを処理します。 訪問されたカウンタはこれを検出し、-1 を返し、無限の蓄積の可能性を正しく通知します。
