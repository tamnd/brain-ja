 ## 解決策
 ## 問題の理解

 私たちには、グリッドで表された教室が与えられています。 各セルは空 (`.`) または占有 (`*`）。 

ぴったり座りたい`k`一直線に並んだ生徒たち。 座席は連続していて、完全に 1 つの行内、または完全に 1 つの列内にある必要があります。 選択したセグメントのすべての座席が空である必要があります。 

タスクは、個別の有効なセグメントがいくつ存在するかを数えることです。 

セグメントは、占有されているセルのセットによって識別されます。 たとえば、列に 4 つの連続した空席が含まれている場合、`k = 2`、次に間隔`[1,2]`、`[2,3]`、 そして`[3,4]`3つの異なるアレンジメントです。 

グリッドの寸法は次のように大きくできます。`2000 × 2000`。 つまり、グリッドには最大 400 万個のセルが含まれる可能性があります。 同じセルを繰り返しスキャンしたり、考えられるすべてのセグメントを個別にチェックしたりするソリューションでは、速度が非常に遅くなります。 成功したソリューションでは、各セルが一定の回数だけ処理されるはずです。`O(nm)`仕事。 

注目に値するいくつかの特殊なケースがあります。 

考慮する`k = 1`:```
2 2 1
..
..
```すべての空のセルは、同時に有効な水平セグメントであると同時に有効な垂直セグメントでもあります。 正しい答えは、`4`、 ない`8`。 行と列を個別にカウントすると、空のセルはすべて 2 回カウントされます。 

もう 1 つの重要なケースは、空席が長期間続く場合に発生します。`k`。```
1 5 3
.....
```有効なセグメントは次のとおりです。```
[1,2,3]
[2,3,4]
[3,4,5]
```答えは`3`。 不用意に実装すると、実行ごとに 1 つのセグメントのみがカウントされる可能性があります。 

ブロックされたセルはランを独立した部分に分割します。```
1 5 2
..*..
```左のランは 1 つのアレンジメントに寄与し、右のランは 1 つのアレンジメントに寄与し、合計で`2`。 行全体を 1 回の実行として扱うと、誤って生成される`4`。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべてのセルについて、一定の長さの水平セグメントを開始してみることができます。`k`すべてかどうかを確認してください`k`セルが空です。 垂直方向でも同じことができます。 

これは正しいです。考えられるすべてのセグメントが 1 回だけ検査されるからです。 問題は走行時間です。 がある`O(nm)`可能な開始位置、各チェックは最大で検査することができます`k`細胞。 最悪の場合こうなります`O(nmk)`。 あらゆる次元に到達した状態で`2000`、それは数十億の操作に近づく可能性があります。 

重要な観察は、実際には個々のセルを気にしていないということです。 重要なのは空席の最大連続稼働数です。 

行に一連の長さが含まれていると仮定します。`L`。```
.....   (L = 5)
```必要であれば`k = 3`、その後、同じ長さの連続するブロックごとに`3`この実行の内部は有効です。 そのようなブロックの数は次のとおりです。```
L - k + 1
```提供された`L ≥ k`。 

すべての候補セグメントを個別にチェックするのではなく、行を 1 回スキャンし、空のランをそれぞれ識別し、その寄与をすぐに追加します。 同じ考え方が列にも当てはまります。 

特殊な状況が 1 つあります。`k = 1`。 

大型の場合`k`、水平セグメントと垂直セグメントは別のオブジェクトであるため、行と列を個別にカウントするのは正しいです。 

のために`k = 1`、有効な配置はすべて 1 つの空のセルで構成されます。 行と列を別々にカウントすると、空の各セルが 2 回カウントされます。 その場合は、単に空のセルを 1 回カウントして停止します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nmk) | お(1) | 遅すぎる |
 | 最適 | O(nm) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. もし`k = 1`を含むセルの数を数えます。`.`そしてその値を出力します。 

すべての空のセルは、正確に 1 つの有効な配置を表します。 行と列を別々にカウントすると、二重にカウントされます。 
3. すべての行を左から右にスキャンします。 

現在連続している空のセルの長さを維持します。 
4. いつでも`*`が発生すると、現在の実行は終了します。 

ランレングスが`L ≥ k`、 追加`L - k + 1`答えとしては、長さが長いため、`k`セグメントはラン内に収まります。 
5. 行を終了したら、同様に最後の行を処理します。 

行は空のセルで終了する可能性があるため、最後の実行には別の処理が必要です。 
6. すべての列に対して同じプロセスを繰り返します。 

各列は 1 次元のシーケンスとして扱われます。 あらゆる縦走が貢献する`L - k + 1`手配。 
7. 蓄積された回答を出力します。 

### なぜ効果があるのか

 すべての有効な水平方向の配置は、空のセルの最大の水平方向のランの 1 つだけに属します。 そのランに長さがあるなら`L`、長さの可能な開始位置 -`k`セグメントは次のとおりです。```
1, 2, ..., L-k+1
```これは正確に与えます`L-k+1`手配。 

アルゴリズムは、すべての水平方向の実行とすべての垂直方向の実行について、これらの配置を正確にカウントします。 すべてのセグメントが何らかの実行内にあるため、有効なセグメントが失われることはありません。 セグメントにはランを含む最大値が 1 つだけあるため、セグメントは 2 回カウントされません。 特別な取り扱いは、`k = 1`水平方向と垂直方向のカウントが重複する唯一のケースが削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    if k == 1:
        ans = sum(row.count('.') for row in grid)
        print(ans)
        return

    ans = 0

    # Rows
    for r in range(n):
        run = 0
        for c in range(m):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0

        if run >= k:
            ans += run - k + 1

    # Columns
    for c in range(m):
        run = 0
        for r in range(n):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0

        if run >= k:
            ans += run - k + 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初のブランチは特殊なケースを処理します`k = 1`。 すべての空のセルは有効な配置であるため、空のセルを直接カウントする方が簡単であり、二重カウントを回避できます。 

行スキャンでは、各行を 1 次元配列として扱います。 変数`run`現在の連続する空席のブロックの長さを格納します。 ブロックされた座席が現れるたびに、ランは終了し、貢献します`run - k + 1`長さが十分に大きい場合は、セグメントを分割します。 

列スキャンは、インデックスが垂直方向に走査されることを除いて同一です。 

バグの一般的な原因は、行または列の終了後に最終実行の処理を忘れることです。 実行は境界まで継続する可能性があるため、ループの後にも寄与を追加する必要があります。 

もう一つの簡単な間違いは、取り扱いを誤ることです`k = 1`。 特別な分岐がなければ、すべての空のセルは行スキャンで 1 回、列スキャンで 1 回カウントされます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    if k == 1:
        return str(sum(row.count('.') for row in grid))

    ans = 0

    for r in range(n):
        run = 0
        for c in range(m):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0
        if run >= k:
            ans += run - k + 1

    for c in range(m):
        run = 0
        for r in range(n):
            if grid[r][c] == '.':
                run += 1
            else:
                if run >= k:
                    ans += run - k + 1
                run = 0
        if run >= k:
            ans += run - k + 1

    return str(ans)

# provided sample
assert run("2 3 2\n**.\n...\n") == "3", "sample 1"

# minimum size
assert run("1 1 1\n.\n") == "1", "single empty cell"

# all blocked
assert run("2 2 1\n**\n**\n") == "0", "no valid arrangement"

# long run
assert run("1 5 3\n.....\n") == "3", "L-k+1 counting"

# split runs
assert run("1 5 2\n..*..\n") == "2", "blocked seat splits runs"

# k = 1 double-count trap
assert run("2 2 1\n..\n..\n") == "4", "must not count rows and columns separately"

 ## 特殊なケース

 ### ケース 1:`k = 1`入力：```
2 2 1
..
..
```アルゴリズムは直ちに特別な分岐に入り、空のセルをカウントします。 空のセルが 4 つあるので、答えは次のようになります。`4`。 

行スキャンと列スキャンの両方を実行した場合、各セルは水平方向に 1 回、垂直方向に 1 回寄与し、`8`、これは間違いです。 

### ケース 2: 長い空の実行

 入力:```
1 5 3
.....
```行スキャンにより、長さのある単一のランが検出されます。`5`。 

貢献は次のとおりです。```
5 - 3 + 1 = 3
```アルゴリズムは、有効なセグメントを個別に列挙することなく、すべてのセグメントをカウントします。 

### ケース 3: 障害物により走行が分割される

 入力:```
1 5 2
..*..
```スキャンにより、2 つの別々の長さのランが検出されます。`2`。 

最初の実行は次のことに貢献します。```
2 - 2 + 1 = 1
```2回目の実行はさらに貢献します`1`。 

合計の答え:```
1 + 1 = 2
```障害物によりセグメントが中間位置を横切ることが妨げられ、アルゴリズムは、次の場合に常に現在の実行を終了することで自然にそれを強制します。`*`に遭遇します。
