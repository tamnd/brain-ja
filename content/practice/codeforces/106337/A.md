 ## 解決策
 ## 問題の理解

 オリンピックの参加者のスコアを表す整数の配列が与えられます。 注文された参加者のペアごとに$(i, j)$、どのくらいの「追加」スコアを計算します$j$と比較しました$i$ただし、次の場合に限ります。$j$の方が良いです。 正式には、各ペアについて$\max(a_j - a_i, 0)$、そしてこれをすべてのペアにわたって合計します。 

タスクを確認する別の方法は、参加者を修正することです$i$そして他のみんなを見てください。 あらゆる人にとって$j$よりも高いスコアで$i$、参加者$i$貢献者ゼロと参加者$j$違いに貢献する$a_j - a_i$。 目標は、そのようなすべての比較にわたる合計の累積貢献度です。 

入力サイズによって、ソリューションがどの程度積極的である必要があるかが決まります。 すべてのペアを直接検査する二次アプローチは、一度実行すると実行できなくなります。$n$数千を超えて成長するため、$n^2$操作はすでに一般的な制限を超えています$n \approx 10^5$。 これは、寄与をペアごとに列挙するのではなく集約できるように、式の構造を単純化する必要があることを直ちに示唆しています。 

素朴な推論による一般的な失敗例は、順序の処理を誤ったり、二重にカウントしたりすることです。 たとえば、入力の場合$[1, 3, 2]$、隣接する差分のみを誤って合計したり、両方向の比較が含まれていても max 関数により非対称であることを忘れたりする可能性があります。 正しい答えを得るには、隣接する要素や並べ替えられた近傍だけでなく、すべての順序付きペアを考慮する必要があります。 

もう 1 つの微妙な落とし穴は、対称性を仮定することです。表現には方向性があります。 例えば、$a_j - a_i$は正の場合にのみ寄与するため、インデックスを交換すると、ペアが寄与するかどうかが変わります。 ペアを順序付けされていないものとして扱うアプローチは失敗します。 

## アプローチ

 ブルートフォースアプローチは定義に直接従います。 あらゆるインデックスに対して$i$、すべてを繰り返します$j$、計算する$a_j - a_i$、それが正の場合は追加します。 これは、すべての順序付きペアを明示的にチェックし、定義どおりに式を正確に適用するため、正しいです。 ただし、これには次のことが必要です$n^2$各評価は定数時間であるため、合計作業量は二次関数的に増加します。 入力が大きい場合、これは遅くなりすぎます。 

重要な点は、式が元の配列内の値の位置ではなく、値の相対的な順序にのみ依存するということです。 固定ペアの場合$i, j$、値のみが重要です。$a_i \ge a_j$、貢献はゼロです。 それ以外の場合はそうです$a_j - a_i$。 これにより、等しい値または順序付けされた値をグループ化して計算を再編成することができます。 

値がソートされると、すべてのペアが$i < j$まさに貢献する$a_j - a_i$、注文が保証されるため$a_j \ge a_i$。 これにより、負の値がソート順に表示されることはないため、max 関数の必要性が完全になくなります。 問題は、増加するすべてのペアにわたる差の合計に帰着します。これは、位置ごとに、接頭辞の合計を使用して表すことができます。$i$、どれくらい大きいかを計算します$a_i$これまでのすべての要素よりも優れており、それらの貢献を効率的に蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | ソート + プレフィックスの合計 | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 これにより、どのペアでも$i < j$、 我々は持っています$a_i \le a_j$これにより、合計内の条件チェックが不要になります。 
2. 処理された要素の現在のプレフィックス合計を維持します。 これにより、以前の要素の合計寄与を位置ごとに一定時間で計算できます。 
3. ソートされた配列を反復処理します。 各インデックスで$i$、 扱う$a[i]$すべてのペアのより大きな要素として$(j, i)$どこ$j < i$。 
4. の寄与を計算する$a[i]$として$i \cdot a[i] - \text{prefixSum}$。 この式は、次の間の差の合計を表します。$a[i]$および以前のすべての要素は、以下から代数的に拡張されます。$\sum (a[i] - a[j])$。 
5. この投稿を最終回答に追加します。 
6. 以下を追加してプレフィックスの合計を更新します。$a[i]$、次の反復の準備をします。 

重要な考え方は、各要素がより小さな要素を含むすべてのペアの「正しいエンドポイント」として処理され、そのような寄与がすべて 1 つの算術式に集約されるということです。 

### なぜ効果があるのか

 並べ替えた後、すべての有効な投稿$\max(a_j - a_i, 0)$単純になる$a_j - a_i$いつ$j > i$、順序付けによって非負性が保証されるためです。 各要素$a[i]$前の要素とのすべてのペアの大きい側として 1 回だけ寄与し、プレフィックスの合計により、それらの小さい要素の合計が正しく減算されることが保証されます。 これにより、すべての順序付きペアが正確に 1 回だけ考慮され、正しい符号付きの差が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    res = 0
    pref = 0
    
    for i, x in enumerate(a):
        res += i * x - pref
        pref += x
    
    print(res)

if __name__ == "__main__":
    solve()
```この解決策は、比較が方向性があり単調になるように配列を並べ替えることから始まります。 変数`pref`現在のインデックスの前のすべての要素の合計を格納します。 それぞれのステップで、`i * x`前のすべての要素がゼロに等しい場合の合計寄与度を表し、減算`pref`実際の値を考慮してこれを修正し、差の合計を算出します。 

よくある間違いはアップデートです`pref`寄与を計算する前に実行すると、現在の要素が自身の計算に誤って含まれてしまいます。 ここに示す順序では、最初に寄与を計算し、次にプレフィックスの合計を更新することでこの問題を回避します。

 ## 特殊なケース

 値が等しい場合、ソートされた配列は各ステップで寄与をゼロにします。`i * x`同一の要素にわたってスケーリングされたプレフィックスの合計と完全に一致します。 入力用`5 7 7 7 7 7`、正の差を生み出す厳密に小さいまたは大きい要素はないため、各反復では差がゼロになります。 

などの入力を厳密に減らす場合`4 3 2 1`、ソートすると次のように逆になります。`1 2 3 4`、アルゴリズムはすべてのペアごとの差を正しい方向に 1 回計算します。 で`i = 3`、 価値`4`貢献する`3*4 - (1+2+3) = 12 - 6 = 6`、これは、以前のすべての要素との相違点に対応します。 初期の各ステップでも同様にすべての有効なペアが蓄積され、重複のない完全なカバレッジが保証されます。
