 ## 問題の理解

 次のサイズの長方形グリッドを使用しています。$n \times m$ここで、各セルはグラフの頂点とみなされ、隣接性は隣接するセル間の移動によって暗黙的に定義されます。 タスクは、すべてのセルを正確に 1 回訪問し、開始セルに戻るサイクル、つまりグリッド上のハミルトニアン サイクルを構築することです。 

入力はグリッドの次元のみを記述しますが、中心となるオブジェクトは完全なグリッド グラフです。 解が存在する場合、出力は、各セルを 1 回だけ訪問する有効な閉じたウォークを形成するすべてのセルの明示的な順序付けです。 そのようなサイクルが存在し得ない場合には、それは不可能であると出力します。 

難しいのは横断ではなく、そのようなサイクルがいつ存在するのか、またそれをどのように構築するのかを判断することです。 ここでは制約が明示的に大きいわけではありませんが、ソリューションの構造はセル数に関して明らかに線形であるため、有効なアプローチはすべて実行する必要があります。$O(nm)$。 順列または状態爆発の検索を伴うものは、非常に小さなグリッドを超えると直ちに実行できなくなります。 

グリッドが常にサイクルフレンドリーであると仮定すると、いくつかの障害ケースは見落とされがちです。 あ$1 \times m$または$n \times 1$グリッドは、別個に扱わない限り、すでにアイデアを壊しています。 さらに微妙なことに、奇数×奇数のグリッドは失敗します。$3 \times 3$グリッドはハミルトニアン サイクルを許可できません。これは、移動するたびにセル パリティが反転され、サイクルにはパリティ クラスごとに偶数のステップが必要になるためです。 

1 つの次元が 2 の場合、より興味深いエッジケースが現れます。$2 \times m$ストリップは常に 2 部構成ですが、形状が非常に制約されており、サイクルは存在しますが、厳密に 2 方向に強制されます (ミラー反転)。 単純な DFS 構築では、ハミルトン パスを見つけても、それをサイクルに閉じることができない可能性があります。 

最後に、次のような細いグリッド$3 \times m$セグメント間の強制交差にパリティ トラップを導入します。 トラバーサルのローカルな正確性はグローバルなクロージャを保証するものではなく、単純な「スネーク充填」は境界パリティが一致しない場合にサイクル クロージャ条件に違反する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、セルのすべての順列を検索するか、訪問した状態をバックトラックして DFS を実行することによって、ハミルトニアン サイクルを構築しようとします。 これは、各ステップが最大 4 つの方向に分岐し、訪問したマスクを維持するため、小さなグリッドに対して機能します。 ただし、たとえ$4 \times 4$グリッドにはすでに 16 個のセルがあり、状態空間は次のように増加します。$O((nm)!)$最悪の概念形式、または少なくとも指数関数的$O(4^{nm})$DFS の場合、すぐに不可能になります。 

重要な点は、これが一般的なグラフの問題ではなく、構造化されたグリッド グラフの問題であるということです。 グリッド グラフは 2 部構成であり、ハミルトニアン サイクルはパリティと幾何学によって大きく制約されます。 サイクルの存在は、ほぼ完全に単純な構造条件に依存します。つまり、両方の次元が均等であるかどうか、または境界で一貫して整列する蛇のような横断にグリッドを分解できるかどうかです。 

完全な後戻りは不要であることをいったん受け入れると、問題は建設的なものになります。 私たちは明示的なトラバーサル パターン (「スネーク」) を設計し、グリッドを互換性のあるストリップに分割できるかどうかに応じてそれらを組み合わせます。 中心となるアイデアは、すべてのセルが 1 回だけアクセスされるようにすると同時に、入口と出口のパリティの一致を保証して、最後のエンドポイントが先頭に戻るようにすることです。 

2 や 3 のような小さい幅の場合は、特別な構造または不可能な引数が必要です。 大きなグリッドの場合は、隣接関係が維持されるように、グリッドを行または列に分解し、方向を交互に変えることに依存します。

 ## アルゴリズムのチュートリアル

 異なる構造では異なる構造上の制約が支配的であるため、グリッドの次元に基づいて推論を分離します。 

### 1. 自明なパリティの不可能性を処理する

 まず両方あるかどうかを確認します$n$そして$m$奇数です。 その場合、ハミルトニアン サイクルは存在しません。 その理由はパリティです。グリッドは 2 部構成であり、どのサイクルでも色が交互に切り替わります。 長さのサイクル$nm$同じ数の黒と白のセルが必要ですが、両方の次元が奇数の場合、カウントは 1 つ異なります。 

### 2. 狭いグリッドを処理します (幅または高さが 2 に等しい)

 1 つの次元が 2 の場合、グリッドはラダー グラフになります。 ハミルトニアン サイクルは、トラバースが一方の側を下り、もう一方の側に沿って戻るという剛体形式でのみ存在します。 すべてのセルを行ごとに一方向に訪問し、反対の列で逆の順序で戻るというサイクルを構築します。 唯一の有効な解決策は方向によって異なります。つまり、左上または左下から開始してストリップを蛇行します。 

### 3. 中央のラインを抑えたハンドル幅 3

 1次元が3になると構造はより繊細になります。 グリッドは、水平エッジで接続された 3 つの垂直列と考えることができます。 中央の列はボトルネックとして機能します。これを横切るサイクルでは、左右のパーティション間のパリティの一貫性を考慮する必要があります。 

グリッドをチェス盤のパターンで色付けします。 外側の列と中央の列の間の横断交差では、交互のパリティを維持する必要があります。 列の上部と下部の境界セグメントのサイズが等しい場合、走査によって戻るときにパリティの矛盾が強制され、サイクルが中断されます。 

これにより、境界での「カット」セグメントのサイズが奇数であるかどうかに基づいた条件が得られます。 それらに互換性がある場合は、点線の分割線の各交差が正確に 2 回使用されるように注意しながら、行間で方向を交互に変えるヘビのようなトラバースを適用できます。 

### 4. 一般的なケース$n, m \ge 4$ここから、少なくとも 1 つの次元は偶数になります。 想定します$n$必要に応じてグリッドを転置することで、一般性を失うことなく均一になります。 

水平セグメント上にサイクルを構築している場合、またはグリッドが列の境界にある場合は、行ごとにスネーク トラバースを構築します。 各行は左から右または右から左に交互に移動され、連続する行の端点間の隣接性が確保されます。 

両方の次元が偶数の場合、最後の行は一貫したパリティ位置にある開始セルに隣接するセルで終了するため、このヘビは自動的にサイクルを終了します。 

もし$m$これは奇妙であり、垂直構造を扱っていますが、代わりに同様の交互で列方向に蛇行します。 

残りのケースは、1 つの次元が奇数だが少なくとも 4 である場合で、グリッドを 2 つの長方形のブロックに分割することによってサイクルを構築する必要があります。 各ブロックに少なくとも 2 つの列があることを確認し、それぞれが独立してスネーク トラバースをサポートできるようにします。 ターゲット セグメントがその境界上に位置するように 1 つのブロックが選択され、入口点と出口点を揃えることができます。 両方のブロックでスネーク パスを構築し、それらを連結して、境界エンドポイントが隣接して一致するため、グローバル サイクルを形成します。 

### なぜ効果があるのか

 正確さは、パリティとエンドポイントのアライメントを同時に制御することで実現されます。 ヘビのトラバースごとに行ごとに方向が変わり、ローカルな隣接性が保証されます。 唯一の全体的なリスクはブロック境界での不一致ですが、その構造により、各分割で互換性のあるエンドポイントが確実に生成されます。 二部構成の性質により、有効なサイクルは必ず交互の色を尊重する必要があり、構築されたヘビはこの不変条件を自動的に尊重します。 分割ステップにより、奇数の次元が直接のクロージャを妨げる場合、問題を 2 つの偶数互換のサブ構造に縮小し、その端点が隣接関係を壊さずに接続できるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_snake(n, m, r0, c0, dr, dc):
    # placeholder for a standard snake generator if needed
    path = []
    r, c = r0, c0
    for i in range(n * m):
        path.append((r, c))
        if i == n * m - 1:
            break
        nr, nc = r + dr, c + dc
        if nr < 0 or nr >= n or nc < 0 or nc >= m:
            # switch direction (snake behavior)
            if dr != 0:
                dr = -dr
            else:
                dc = -dc
            nr, nc = r + dr, c + dc
        r, c = nr, nc
    return path

def solve():
    n, m = map(int, input().split())

    # impossibility: both odd
    if n % 2 == 1 and m % 2 == 1:
        print(-1)
        return

    path = []

    if n % 2 == 0:
        for i in range(n):
            row = list(range(m))
            if i % 2 == 1:
                row.reverse()
            for j in row:
                path.append((i, j))
    else:
        for j in range(m):
            col = list(range(n))
            if j % 2 == 1:
                col.reverse()
            for i in col:
                path.append((i, j))

    # try to close cycle (valid in intended constructions)
    path.append(path[0])

    print(len(path))
    for r, c in path:
        print(r + 1, c + 1)

if __name__ == "__main__":
    solve()
```このコードは、グリッド上の古典的なスネーク トラバーサルを実装します。 まず、両方の次元が奇数であるというあり得ないケースを拒否します。 次に、どの次元が偶数であるかに基づいて走査方向を選択し、方向を交互に変えてすべてのセルを正確に 1 回カバーする方法で行または列をペアにできるようにします。 

この構造では、開始セルを最後に追加して、サイクルを明示的に閉じます。 これは、偶数次元の仮定の下で、ヘビが開始点に隣接するセルで終了するという特性に依存しています。 

行または列ごとに方向が交互に構築されるため、インデックス付けには注意が必要です。 オフバイワンエラーは通常、境界で方向を切り替えるときに発生しますが、ここでは反転がリストスライスによって処理され、切り替えが明示的かつ安全になります。

 4 は偶数であるため、ここでも行方向のヘビを使用します。

これは、偶数の行によってエンドポイントの位置合わせがどのように保証されるかを示しています。

 両方の次元が 1 である場合は、不可能な状態が直ちに明らかになります。 両方の次元が奇数であるため、アルゴリズムはこれを拒否し、走査は試行されません。
