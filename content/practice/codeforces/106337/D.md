 ## 解決策
 ## 問題の理解

 高さの配列が与えられます。各インデックスは線上の点を表すため、i 番目の点は水平位置 i と垂直位置 h[i] に位置します。 すべてのクエリセグメントに対して$[l, r]$、このセグメント内にインデックスがある点のみを考慮し、その点から歩くことを想像します。$l$指す$r$インデックスの昇順で選択した点の間の一連の直線ジャンプを使用します。 

このパスの制約は幾何学的なものです。これらの選択された点によって形成されるポリラインは厳密に上に凸でなければなりません。つまり、すべての内部頂点は、点のセグメント全体がポリラインの下に保たれるように回転する必要があります。 同様に、連続して選択した点を接続すると、結果の破線はセグメント内のすべての点の上に位置し、すべての中間点は厳密にその線の下に位置します。 このようなすべての有効な凸上パスの中で、構造は固有であるため、タスクはこの正規チェーンに含まれる頂点の数を決定することになります。 

したがって、各クエリの出力は幾何学オブジェクト自体ではなく、単にこの凸状チェーンの頂点の数になります。$l$に$r$。 

サブ問題全体にわたる制約は、小さな問題からの進歩を示唆しています。$n, q$ここでは、各クエリを多対数時間で応答する必要がある大規模な入力まで、クエリごとの構築が許可されています。 これにより、クエリごとに凸構造を最初から再計算することが直ちに排除されます。$O(n)$両方の場合、クエリごとの速度が非常に遅くなります$n$そして$q$到着$10^5$。 総複雑さの目標は事実上、$O((n + q)\log^2 n)$これは、対数マージと組み合わせた区間にわたる分割統治に典型的なものです。 

複数のポイントが同様の傾きを共有する場合、微妙な問題が発生します。 傾きのみに基づいて次のポイントを単純に貪欲に選択すると、タイブレークに一貫性がない場合は失敗する可能性があります。 たとえば、ポイントが次のような浅い台地を形成している場合、$(1,1), (2,2), (3,2), (4,3)$、グローバル凸性を強制せずに常に局所的に最も急な次のステップを選択すると、正しいハル頂点がスキップされ、非凸チェーンが生成される可能性があります。 正しいソリューションでは、ローカルな角度の選択だけでなく、グローバルな凸構造を強制する必要があります。 

エンドポイントが固定されている場合、別の失敗ケースが発生します。 すべての点の単純な凸包$[l,r]$エンドポイントが異なるチェーンを返す可能性があります$l$そして$r$、これは無効です。 構造は、両方の端点を含むように拘束された上部ハルである必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 セグメントの場合$[l,r]$、凸状の上向きパスの構築をシミュレートします。 から始まる$l$、凸性を維持する次の点を繰り返し選択します。これは、すべての候補に対する角度の比較または外積を使用して確認できます。 各ステップでは最大でスキャンできます$O(n)$ポイント、およびチェーン自体が$O(n)$頂点、につながる$O(n^2)$最悪の場合、クエリごとに。 これは小さな制約では機能しますが、クエリが次のような規模になるとすぐに実行できなくなります。$10^5$。 

重要な観察は、凸構造がクエリごとに任意ではないということです。 これは、静的に順序付けされた点のセットに対する凸包のように動作し、間隔クエリは部分包の抽出に対応します。 これは、グローバル構造を前処理し、部分ハルを効率的にマージすることを示唆しています。 

標準ツールは、インデックス範囲に対する分割統治です。 各セグメントについて、その左半分と右半分の凸包を維持します。 課題は、2 つの凸状チェーンを 1 つの有効な上部ハルにマージすることです。 このマージは、2 ポインタ スタイルの構築またはハル間の接線の二分探索を使用して実行できます。 ハルは傾斜順序において単調であるため、左右のハル間の接点は対数時間で見つけることができ、結果として生じる結合ハルは再び凸状になります。 

クエリをサポートするために、各ノードがその区間の凸包を格納するセグメント ツリーを構築します。 クエリ$[l,r]$集めることで答えられます$O(\log n)$船体を分割し、それらをペアごとに結合します。 各マージには接線位置の二分探索による対数的な時間がかかり、合計$O(\log^2 n)$クエリごとに。

 ## アルゴリズムのチュートリアル

 1. 各インデックスの処理$i$ポイントとして$(i, h[i])$。 これにより、ジオメトリが単調な x 次数に固定されます。これは、凸包構造に不可欠です。 
2. 各ノードが間隔を表すセグメント ツリーを構築します。$[L,R]$そして、その区間内のすべてのポイントの上凸包を左から右の順序で保存します。 この順序により、各ハル内の傾斜の単調性が維持されます。 
3. リーフ ノードの場合、ハルは単なる 1 つの点です。 これがベースの凸構造です。 
4. 内部ノードを構築するには、左右の子のハルを取得してマージします。 マージは、2 つの凸状チェーン間の上接線を計算することによって実行されます。 この接線は、左側のハルからのポイントが寄与を停止し、右側のハルからのポイントが始まる境界を定義します。 
5. 接線を見つけるために、凸包上の傾斜の単調性を利用します。 各ハルで二分探索を行って、凸性を維持する最適な接続ペアを見つけることができます。 これは、傾きの比較が凸状のチェーンに沿って単調であるため機能します。 
6. 接線を見つけた後、左包の有効な接尾辞を右包の有効な接頭辞と連結し、新しい凸状チェーンを生成します。 
7. 質問に答えるには$[l,r]$に分解します。$O(\log n)$セグメントツリーノード。 次に、同じ接線ベースのマージ操作を使用して、ハルを 1 つずつマージします。 
8. 最後のハルはセグメント全体の凸状の上向きチェーンを表し、その長さが答えになります。 

### なぜ効果があるのか

 すべてのノードで、保存されたシーケンスがそのセグメントの上凸包であるという不変条件を維持します。 接線により、左側のハルから右側のハルへの接続線の上に点が存在しないことが保証され、またその逆も同様であるため、マージ操作では凸面が維持されます。 分解はクエリ間隔を正確にカバーし、マージは正確さを維持するため、最終的な構造はクエリされたサブセットの凸包そのものであり、一意であるため、その頂点数は明確に定義されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(a, b, c):
    return (b[0]-a[0])*(c[1]-a[1]) - (b[1]-a[1])*(c[0]-a[0])

def merge(h1, h2):
    if not h1:
        return h2
    if not h2:
        return h1

    # keep upper hull (monotone chain style merge)
    res = h1[:]
    for p in h2:
        while len(res) >= 2 and cross(res[-2], res[-1], p) >= 0:
            res.pop()
        res.append(p)
    return res

class SegTree:
    def __init__(self, pts):
        self.n = len(pts)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.t = [[] for _ in range(2*self.size)]
        for i in range(self.n):
            self.t[self.size+i] = [pts[i]]
        for i in range(self.size-1, 0, -1):
            self.t[i] = merge(self.t[2*i], self.t[2*i+1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left = []
        right = []
        while l <= r:
            if l % 2 == 1:
                left = merge(left, self.t[l])
                l += 1
            if r % 2 == 0:
                right = merge(self.t[r], right)
                r -= 1
            l //= 2
            r //= 2
        return merge(left, right)

def solve():
    n, q = map(int, input().split())
    h = list(map(int, input().split()))
    pts = [(i, h[i]) for i in range(n)]
    st = SegTree(pts)

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        hull = st.query(l-1, r-1)
        out.append(str(len(hull)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核は、凸マージ手順です。 このコードでは、二分探索でタンジェントを明示的に計算する代わりに、クロス積チェックを使用したモノトーン チェーン スタイルのマージを使用します。点はすでにインデックスによって順序付けされているため、これで十分です。 セグメント ツリーにはハルが保存され、単一のハルが残るまでクエリによってハル フラグメントが繰り返しマージされます。 

外積符号には注意が必要です。非厳密な条件を使用すると、同一線上の中間点が削除され、厳密な凸性の要件と一致します。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 重要なエッジケースは、すべての点が同一線上またはほぼ同一線上にある場合です。 For example, heights increasing linearly such as$(1,1), (2,2), (3,3), (4,4)$。 すべての中間点が同じ線上にあり、厳密な凸性に違反するため、正しい凸状の上向きチェーンは端点のみを保持する必要があります。 マージ中にクロス積チェックによって非転換点が削除されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、単一要素のクエリです。$[i,i]$。 ハルには正確に 1 つの点が含まれている必要があり、セグメント ツリーはリーフにシングルトン ハルを正しく格納するため、マージ操作によって余分な頂点が発生することはありません。
