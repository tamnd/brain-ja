 ## 解決策
 ## 問題の理解

 この問題の背後にあるタスクは、指定された整数が、完全な正方形を含む特定の割り算構造を回避する特別な構成要素の合計として表現できるかどうかを判断することです。 より具体的に言えば、数値のリストが与えられ、積が完全な正方形を形成する要素のペアを禁止する制約の下でそれらを分割または処理する必要があります。 ほとんどの場合、出力は実際のパーティションを明示的に構築することに関するものではなく、この制限の下で配列を構造化するための最小限の方法を計算することに関するものです。 

これを再構成する有効な方法は、因子シグネチャの観点から考えることです。 平方係数を削除して、平方のないコアだけを残すことで、すべての数値を減らすことができます。 これらのコアが一致する場合、2 つの数値は禁止されたペアを形成します。これは、それらの積に完全二乗係数が含まれていることを意味するためです。 したがって、問題は、条件に違反する方法で同じ代表の重複がグループに含まれないようにしながら、これらの正方形のない代表に基づいて番号をグループ化することになります。 

入力は単一の整数配列で構成されます。 出力は、各セグメント内で 2 つの要素を乗算したときに完全な正方形を生成しないという制約の下で、有効なセグメントまたはグループの最小数を表す単一の整数です。 

複雑さの観点から見ると、同様の Codeforces 問題では、値の制約は通常、最大 10^5 または 10^6 程度に達しますが、配列の長さは最大 10^5 になる可能性があります。 これにより、O(n^2) のペアごとのチェック戦略が即座に除外されます。 前処理や縮小形式のハッシュを使用して慎重に最適化しない限り、テストあたり O(n sqrt(maxA)) であっても境界線に達する可能性があります。 

すべてのサブ配列を個別にチェックし、条件に違反するペアがあるかどうかを検証する単純なアプローチでは、小規模なストレス テストですでに失敗します。 たとえば、多くの数値が同じ平方フリー カーネルを共有する [2, 8, 18, 50, 98, ...] のような配列を考えてみましょう。 ペアごとのチェックを再計算する単純なスライディング ウィンドウでは、因数分解と比較が繰り返し再計算され、壊滅的な冗長性が生じます。 

もう 1 つの微妙な失敗例は、数値が大きな正方形または正方形に近い場合に発生します。 たとえば、4、9、16、25 などの入力は、二乗係数を削除するとすべて 1 に折りたたまれます。 最初に値を正規化しない単純なグループ化では、値が誤って別のものとして扱われ、有効なグループ化サイズが過大評価されます。 

## アプローチ

 ブルートフォース戦略では、セグメント内のすべてのペアをチェックし、積が完全な正方形であるかどうかを検証することにより、考えられるすべてのセグメントの妥当性を直接テストしようとします。 積が完全な平方であるかどうかを確認するには、数値を完全に因数分解するか、乗算して平方根整数性を確認します。 キャッシュを使用した場合でも、これにより、セグメント数はおよそ O(n^2) になり、セグメントあたりのチェック数は O(n) になり、最悪の場合は O(n^3) になります。 これは、10^5 程度の n では実現不可能です。 

重要な洞察は、「製品が完全な正方形である」という条件は、「正方形のない部分は同一である」と同等であるということです。 これにより、問題は乗法整数論から正準形式上の等価グループ化に変換されます。 

各数値が正方形のないカーネルにマッピングされると、構造ははるかに単純になります。つまり、同一のラベルの出現を効果的に管理することになります。 この制約は、セグメント内で、セグメント ルールに違反する方法で同じラベルが繰り返し出現することを許可しないことを保証することになります。 これは当然、貪欲なセグメンテーション戦略を示唆しています。重複する四角形のない値が表示されるまでセグメントを拡張し、その後切断します。 

これが機能する理由は、セグメント内で繰り返しが発生すると、それ以上拡張しても繰り返し要素の 1 つを削除しない限り違反を修正できないためですが、これは連続したセグメントでは不可能です。 したがって、貪欲なカットが最適です。

 ## アルゴリズムのチュートリアル

 1. 配列内の各数値について、すべての素平方を除算して、その平方フリー コアを計算します。 これにより、各値の正規表現が生成されます。 その目的は、組み合わせたときに完全な正方形を形成できる数値が同一の識別子になるようにすることです。 
2. アクティブ セグメントに現在存在するすべての正方形のないコアを表すセットを維持します。 このセットは、どの値がすでに出現しているかを追跡します。 
3. 配列を左から右に走査します。 各要素について、そのコアがすでに現在のセグメント セット内にあるかどうかを確認します。 
4. 存在しない場合は、セットに挿入し、セグメントの拡張を続けます。 これまでのところ重複する正方形のないコアが存在しないため、これは有効性を維持します。 
5. すでに存在する場合は、前の要素で現在のセグメントを閉じます。 新しいセグメントを開始し、セットをリセットし、現在の要素を新しいセグメントの最初の要素として挿入します。 
6. アレイが終了するまで続行し、形成されたセグメントの数を数えます。 

正確さは、各セグメントに個別の正方形のないコアが含まれるという不変条件から得られます。 違反はコアが繰り返されるときに正確に発生するため、その点を超えてセグメントを拡張すると、直ちに制約に違反します。 したがって、最初の繰り返しで切断すると、セグメント化が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import isqrt

def square_free(x):
    # remove square factors
    i = 2
    while i * i <= x:
        cnt = 0
        while x % i == 0:
            x //= i
            cnt ^= 1
        if cnt == 0:
            pass
        i += 1
    return x

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set()
    segments = 1

    for v in a:
        core = square_free(v)

        if core in seen:
            segments += 1
            seen.clear()

        seen.add(core)

    print(segments)

if __name__ == "__main__":
    solve()
```機能`square_free`素数の偶数乗を取り除き、二乗自由度を決定する成分のみを残すことにより、各値を正規形式に縮小します。 メイン ループは、現在のセグメント内に存在するコアのハッシュ セットを維持します。 繰り返しが発生するたびに、新しいセグメントが直ちに開始され、セットはリセットされます。 この貪欲な再起動により、最小限のセグメント化が保証されます。 

よくある実装の落とし穴は、指数の素数やパリティをチェックするだけでなく、二乗因数を完全に削除することを忘れることです。 もう 1 つの微妙な問題は、カットが発生したときに状態を正しくリセットすることです。 セットをクリアしないと、セグメント数が人為的に増大したり、重複が欠落したりする可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値が完全な平方である場合です。 のような入力の場合`[4, 9, 16, 25]`、すべての値は同じ正方形のないコアに減ります。`1`。 このアルゴリズムは、最初のステップ以降のすべてのステップでカットを即座にトリガーし、4 つのセグメントを生成します。 最初の後のすべての挿入で繰り返しが作成されるため、不変式が成り立ちます。 

もう 1 つのケースは、次のような交互の重複です。`[2, 2, 3, 3, 2]`。 アルゴリズムは次のセグメントを形成します。`[2]`、次に2番目をカットします`2`、新しいセグメントを開始します`[2, 3]`、そして最終的には再びカットされます`2`再び現れる。 各カットは現在のセットで繰り返しが発生したときに正確に強制され、どのセグメントも二乗積条件に違反しないことが保証されます。
