 ## 解決策
 ## 問題の理解

 Polycarpus は自分の製品の最高の通常価格をすでに知っています。`p`。 彼はそれを最大でも減らすつもりだ`d`それが最終価格をより魅力的な結末、具体的にはできるだけ多くの末尾の 9 にする場合、ブール。 

末尾の 9 は数字を意味します`9`番号の最後に。 例えば、`12999`末尾に 9 が 3 つある場合、`9099`接尾辞のみが重要であるため、2 つあります。 

すべての価格の中で`x`次のような:

 -`x <= p`-`p - x <= d`末尾に 9 が最大数あるものが必要です。 複数の価格の末尾に同じ数の 9 がある場合は、そのような最大の価格が選択されます。 

ここで興味深いのは制限です。`p`と同じ大きさにすることができます`10^18`したがって、間隔内のすべての可能な価格を反復することはできません。`[p-d, p]`。 最悪の場合、間隔自体にほとんどの値が含まれる可能性があります。`10^18`1秒の制限時間に収まる数字をはるかに超えています。 

問題の構造から、非常に特定の候補のみが重要であることがわかります。 末尾の 9 で終わる数字は次のようになります。```
...9
```末尾に 9 が 2 つある数字は次のようになります。```
...99
```末尾に 9 が 3 つある数字は次のようになります。```
...999
```等々。 

後続の 9 の考えられるカウントごとに、次を超えない最大の候補が 1 つだけ存在します。`p`。 その観察が問題を小さくするものです。 

誤って処理しやすい特殊なケースがいくつかあります。 

仮定する：```
p = 1000
d = 0
```値下げは一切お断りさせて頂きます。 答えは残るはずだ`1000`、 それでも`999`末尾の 9 がさらに多くなります。 常に小数点以下を切り捨てる不用意な実装`999...`値が誤って出力される`999`。 

もう 1 つの注意が必要なケースは次のとおりです。```
p = 10999
d = 1
```答えは`10999`なぜなら、すでに末尾に 9 が 3 つあるからです。 一部の実装では、最適な答えがすでに次と等しい場合でも、数値を不必要に変更します。`p`。 

より微妙なケースは次のとおりです。```
p = 10000
d = 100
```最良の答えは、`9999`。 末尾に 9 が 4 つあり、コストは 1 つだけです`1`ブール未満`p`。 最初に値を最大化しようと貪欲に試みると、誤って次の値で停止してしまう可能性があります。`9990`または`999`。 

最後の重要な詳細はタイブレークです。 考慮する：```
p = 1999
d = 1000
```両方`999`そして`1999`有効です。 それぞれの末尾に 9 が 3 つあります。 大きい方を選択する必要があります。`1999`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての候補価格を反復処理します`x`から`p-d`まで`p`、各数字の後ろに 9 がいくつあるかを数え、ルールに従って最良のものを保持します。 

末尾の 9 を数えるのは簡単です。 最後の桁が正しいかどうかを繰り返し確認します。`9`、で割る`10`、これが何回成功したかを数えます。 

すべての有効な価格を調べるため、総当り攻撃は正しいです。 問題は探索空間のサイズです。 もし`p = 10^18`そして`d`サイズも大きいので、ほぼ検査する必要があるかもしれません`10^18`数字。 番号ごとに 1 つの操作を実行することさえ不可能です。 

重要な観察は、末尾に 9 が多くある数字は非常に構造化されているということです。 

末尾の 9 の固定数の場合`k`を超えない最大の数`p`最後の部分を置き換えることで得られます`k`数字付き`9`。 

たとえば、次のような場合です。```
p = 543210
```次に:

 - 末尾に 1 が付く最大の数字は 9 です`543209`- 末尾に 9 が 2 つある最大の数値は`543199`- 末尾に 9 が 3 つある最大の数値は`542999`この問題では同点間の最大価格が求められるため、末尾に同じ数の 9 を持つより小さい候補を検査する必要はありません。 

これにより、検索スペースが大幅に減少します。 考えられる接尾辞の長さをそれぞれ試してみるだけです。 以来`p <= 10^18`、最大でも 19 桁なので、候補は 19 個程度しか存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d log p) | お(1) | 遅すぎる |
 | 最適 | O(log p) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下に等しい現在の最良の回答から開始します。`p`。 

これは、価格を下げることが有益ではない、または許可されない場合に対処します。 
2. 10 のべき乗ごとに`10^k`を超えない最大の数を構築します。`p`最後は誰の`k`数字がすべてです`9`。 

次のように計算できます。```
candidate = (p // 10^k) * 10^k - 1
```除算は最後のものを削除します`k`それらの数字を乗算するとゼロに戻り、1 を引くとそれらのゼロが 9 になります。 
3. 候補者が有効かどうかを確認します。 

候補者は以下を満たさなければなりません:```
p - candidate <= d
```そうしないと、必要な割引が大きすぎます。 
4. 候補を現在の最良の回答と比較します。 

候補の末尾に 9 が多い場合、その候補が優先されます。 両方の末尾の 9 の数が同じ場合は、大きい方の数を優先します。 

実際に繰り返すと、`k`小から大までは、後の有効な候補が少なくとも同数の後続 9 を持つことをすでに保証しています。 
5. 続けながら`10^k <= p * 10`。 

以来`p`最大 19 桁の場合、このループは数回しか実行されません。 
6. 最良の回答を印刷します。 

### なぜ効果があるのか

 任意の固定数の末尾の 9 の場合`k`、そのプロパティを持つすべての有効な数値は次のように記述できます。```
some_prefix * 10^k + (10^k - 1)
```このようなすべての数のうち、以下を超えないもの`p`、最大のものは正確に次のとおりです。```
(p // 10^k) * 10^k - 1
```この最大の候補が、大きすぎる割引が必要なために有効ではない場合は、すべての小さい数値が同じになります。`k`末尾の9はさらに遠い`p`, したがって、どれも機能しません。 

つまり、それぞれの最大候補のみをテストすることになります。`k`で十分です。 

末尾の 9 のすべての可能なカウントを調べ、各カウントに対して可能な限り最良の数値をテストするため、アルゴリズムは最適な答えを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def trailing_nines(x):
    cnt = 0
    while x % 10 == 9:
        cnt += 1
        x //= 10
    return cnt

def solve():
    p, d = map(int, input().split())

    ans = p
    best = trailing_nines(p)

    power = 10

    while power <= 10**19:
        candidate = (p // power) * power - 1

        if candidate >= 0 and p - candidate <= d:
            cur = trailing_nines(candidate)

            if cur > best or (cur == best and candidate > ans):
                best = cur
                ans = candidate

        power *= 10

    print(ans)

solve()
```ヘルパー関数は、最後の桁を繰り返しチェックして、末尾の 9 を数えます。 数値は最大 19 桁であるため、この演算は事実上定数時間です。 

メインループは 10 の累乗にわたって反復されます。 各べき乗について、必要な数の 9 で終わる可能な最大の候補を構築します。 

式:```
(p // power) * power - 1
```ソリューションの重要な部分です。 

仮定する：```
p = 543210
power = 1000
```それから：```
p // power = 543
543 * 1000 = 543000
543000 - 1 = 542999
```これは正確に次を超えない最大の数です`p`末尾に 9 が 3 つ付いています。 

条件:```
p - candidate <= d
```過度の割引を必要とする候補を除外します。 

タイブレーク ルールは明示的に実装されます。 2 人の候補者の末尾の 9 の数が同じ場合は、大きい方を保持します。 

ループの上限`10**19`可能なすべての桁長を安全にカバーします`p <= 10^18`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    def trailing_nines(x):
        cnt = 0
        while x % 10 == 9:
            cnt += 1
            x //= 10
        return cnt

    p, d = map(int, input().split())

    ans = p
    best = trailing_nines(p)

    power = 10

    while power <= 10**19:
        candidate = (p // power) * power - 1

        if candidate >= 0 and p - candidate <= d:
            cur = trailing_nines(candidate)

            if cur > best or (cur == best and candidate > ans):
                best = cur
                ans = candidate

        power *= 10

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old_stdout
    return out.getvalue().strip()

# provided sample
assert run("1029 102\n") == "999", "sample 1"

# minimum case
assert run("1 0\n") == "1", "minimum values"

# already optimal
assert run("1999 0\n") == "1999", "already has maximum trailing nines"

# small decrease unlocks many nines
assert run("10000 1\n") == "9999", "single decrement creates four nines"

# tie-breaking
assert run("1999 1000\n") == "1999", "choose larger value among equal suffix counts"

# very large values
assert run("1000000000000000000 1\n") == "999999999999999999", "64-bit boundary"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`10000 1`|`9999`| わずかな割引でサフィックス ナインを最大化できます。
