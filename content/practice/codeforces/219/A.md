 ## 解決策
 ## 問題の理解

 小文字の文字列と整数が与えられます`k`。 文字を自由に並べ替えることができます。 目標は、正確に構成される新しい文字列を構築することです。`k`同じブロックが次々と配置されます。 

たとえば、次の場合`k = 3`の場合、最終的な文字列は次のようになります。```
t + t + t
```ここで、3 つのコピーはすべて同じ文字列です`t`。 

変更できるのは文字の順序だけです。 元の文字列のすべての文字は、最終結果にまったく同じ回数出現する必要があります。 

制約は非常に小さいです。 文字列の長さは最大でも`1000`、そしてそれしかありません`26`小文字の英字。 これは、高度なアルゴリズムが必要ないことをすぐに示します。 たとえ`O(n^2)`溶液は簡単に通過します。 ここで重要なのは、有効な構築を可能にする数学的条件を理解することです。 

重要な観察結果は、頻度カウントから得られます。 最後の繰り返しブロックが次のようになっているとします。`t`、そしてそれを繰り返します`k`回。 この場合、文字列全体のすべての文字数は次の値で割り切れる必要があります。`k`。 

例えば：```
k = 3
string = aaabbbccc
```それぞれの文字が表示されます`3`回なので、次のものを作成できます。```
abcabcabc
```しかし、次のような場合があります。```
k = 2
string = aaabc
```キャラクター`'a'`表示されます`3`2 つの同一のブロックに均等に分割することはできません。 これを再配置しても解決できません。 

一般に、誤った実装を破壊するいくつかのエッジケースがあります。 

考慮する：```
k = 4
s = aaaa
```正しい答えは次のとおりです。```
aaaa
```不用意に実装すると、次の値よりも長いベース ブロックを構築しようとする可能性があります。`1`たとえ最小の有効なブロックが`"a"`。 

もう 1 つの注意が必要なケースは次のとおりです。```
k = 3
s = aabbbb
```周波数は次のとおりです。```
a -> 2
b -> 4
```どちらのカウントも割り切れません`3`、したがって、答えは次のようになります。`-1`。 全長が次の値で割り切れるかどうかだけをチェックする単純なアプローチ`k`解決策が存在すると誤って考えるでしょう。`6 % 3 == 0`。 

もう 1 つの微妙なケースは次のとおりです。```
k = 1
s = codeforces
```すべての文字列は自動的に`1`-弦。 元の文字列自体はすでに有効なので、並べ替えても機能します。 すべての周波数が複数回出現する必要があると想定する実装では、このケースが誤って拒否される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、文字列の順列を生成し、その順列が有効かどうかをテストすることです。`k`-弦。 

候補の順列をテストするには、それを次のように分割します。`k`等しい部分を選択し、すべての部分が同一であるかどうかを確認します。 

このアプローチは、最終的にはあらゆる可能な配置を試行するため、論理的には正しいです。 問題は順列の数です。 長さの文字列`1000`まであります`1000!`想像を絶するほど大きい順列。 長さに関しても`15`, brute force becomes completely impractical.

 ブルート フォースが無駄に感じられる理由は、ほとんどの順列は文字の順序のみが異なり、実際の妥当性条件は完全に文字の頻度に依存するためです。 

That observation leads to the optimal approach.

 Suppose some character appears`cnt`回。 In a valid`k`-string の場合、繰り返されるすべてのブロックには、同じ数のその文字が含まれている必要があります。 これは次の場合にのみ可能です`cnt`で割り切れます`k`。 

すべての周波数が割り切れると、`k`、施工が簡単になります。 キャラクターごとに配置します`cnt / k`ベースブロックにコピーします。 そのブロックを繰り返す`k`回は自動的に元の周波数を再作成します。 

例えば：```
k = 2
s = aazz
```周波数は次のとおりです。```
a -> 2
z -> 2
```各カウントは次のように割り切れます。`2`。 

したがって、ベースブロックは次のようになります。```
az
```これを 2 回繰り返すと次のようになります。```
azaz
```問題は、順列間の検索から、周波数の可分性のチェックにまで縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × n) | O(n) | 遅すぎる |
 | 最適 | O(n + 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`k`そして文字列`s`。 
2. すべての小文字の頻度を数えます。 
3. すべての周波数が次で割り切れるかどうかを確認します。`k`。 

文字数によっては割り切れない場合`k`、印刷`-1`そしてやめてください。 

この条件が必要なのは、同一の反復ブロックがすべての文字を均等に分散する必要があるためです。 
4. 基本ブロック文字列を構築します。 

文字ごとに追加します`frequency / k`その文字をブロックにコピーします。 
5. 基本ブロックを正確に繰り返します`k`回。 
6. 結果の文字列を出力します。 

### なぜ効果があるのか

 このアルゴリズムは 1 つのプロパティに依存します。`k`-string、すべての文字の頻度をすべての文字間で均等に分割する必要があります`k`コピー。 

キャラクターが登場したら`cnt`全体で 3 倍になると、各ブロックには正確に含まれている必要があります。`cnt / k`コピー。 これは次の場合にのみ可能です`cnt`で割り切れます`k`。 

すべての周波数がこの条件を満たしている場合、次を使用してベース ブロックを構築します。`cnt / k`コピーはブロックを繰り返すことを保証します`k`回は元のカウントを正確に復元します。 繰り返されるブロックはすべて同一であるため、最終的な文字列は定義上有効です。`k`-弦。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input())
s = input().strip()

freq = [0] * 26

for ch in s:
    freq[ord(ch) - ord('a')] += 1

base = []

for i in range(26):
    if freq[i] % k != 0:
        print(-1)
        sys.exit()

    base.append(chr(i + ord('a')) * (freq[i] // k))

base_string = "".join(base)

print(base_string * k)
```コードの最初の部分では、サイズの固定配列を使用して文字の頻度をカウントします。`26`。 アルファベットは英小文字に限定されているため、辞書を使用するよりも簡単かつ迅速です。 

可分性チェックは、中心となる正確性条件です。 割り切れない周波数を見つけた瞬間`k`、解決策が存在しないことがわかっているため、プログラムはすぐに出力します。`-1`そして出ます。 

構築ステップはコンパクトですが重要です。 文字が出てきたら`cnt`全体で 3 回になると、繰り返される各ブロックには正確な内容が含まれている必要があります。`cnt // k`コピー。 それだけの文字数を追加すると、`base`1 つの有効なブロックを構築します。 

最後にベースブロックを繰り返します`k`回は、すべての部分が同一であることを保証しながら、元の合計周波数を再作成します。 

実装の微妙な点の 1 つは、割り切れることを確認した後でのみ整数の割り算を使用することです。 そうしないと、切り捨てによって誤った文字数が自動的に生成される可能性があります。 

もう一つの細かい点は、`strip()`文字列を読むとき。 これがないと、改行文字が誤って入力の一部になってしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + 26) | 1 回のパスで文字をカウントし、1 回のパスでアルファベットをカウント |
 | スペース | お(26) | 固定サイズの周波数配列 |

 入力サイズは最大でも`1000`, したがって、この解決策は制限時間を大幅に下回っています。 このアルゴリズムは文字列を 1 回スキャンするだけで、アルファベットに対して継続的な追加作業を実行します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    k = int(input())
    s = input().strip()

    freq = [0] * 26

    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    base = []

    for i in range(26):
        if freq[i] % k != 0:
            print(-1)
            return

        base.append(chr(i + ord('a')) * (freq[i] // k))

    print("".join(base) * k)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("2\naazz\n") == "azaz", "sample 1"

# minimum size
assert run("1\na\n") == "a", "single character"

# impossible because frequencies are not divisible
assert run("3\naabbbb\n") == "-1", "non-divisible frequencies"

# all characters equal
assert run("4\naaaa\n") == "aaaa", "all same letters"

# larger valid construction
assert run("3\naaabbbccc\n") == "abcabcabc", "repeated base block"

# boundary style case
assert run("2\nabcabc\n") == "abcabc", "already valid"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\na\n`|`a`| 可能な最小の入力 |
 |`3\naabbbb\n`|`-1`| Detecting impossible frequency splits |
 |`4\naaaa\n`|`aaaa`| Single repeated character |
 |`3\naaabbbccc\n`|`abcabcabc`| 複数文字の有効な構造 |
 |`2\nabcabc\n`|`abcabc`| すでに有効な繰り返しパターン |
