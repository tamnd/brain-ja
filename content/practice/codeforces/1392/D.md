 ## 解決策
 ## 問題の理解

 各プレイヤーは円上に座り、隣の 2 人のうち 1 人を攻撃します。 以下から構成される循環文字列が与えられます。`L`そして`R`。 

プレイヤーの場合`i`攻撃は左、私たちは書きます`L`。 彼らが正しく攻撃した場合、私たちはこう書きます`R`。 

ゲームのルールに従って、プレイヤーは論理的であると見なされます。 

- ちょうど 1 つの隣人がそれらを攻撃した場合、彼らはその隣人を攻撃し返す必要があります。 
- 0 または 2 つの隣接者がそれらを攻撃する場合、どちらの攻撃方向も許容されます。 

プレイヤーの選択を次から反転することができます`L`に`R`またはから`R`に`L`。 裏返された各プレーヤーには 1 回の操作が必要です。 すべてのプレイヤーが論理的になるために必要なフリップの最小数を見つけなければなりません。 

最初の課題は、論理的な最終構成がどのようなものかを理解することです。 

隣のプレイヤーと攻撃方向が異なるプレイヤーに注目するとします。 たとえば、境界線`RL`が表示されます。 左のプレイヤーは右に攻撃し、右のプレイヤーは左に攻撃するので、お互いに攻撃します。 このような立場はすでに完全に一貫しています。 

興味深いのは、等しい文字の最大ブロック内で何が起こるかということです。```
RRRRR
```または```
LLLL
```このようなブロックの中で問題となるのは中盤の選手だ。 攻撃は 1 回だけ受けますが、反撃はしないため、いくつかの変更が必要です。 

制約は大きいです。 すべての文字列の合計の長さは最大でも`2·10^5`、まであるかもしれません`10^4`テストケース。 考えられるすべてのフリップの組み合わせを検査するような解決策は不可能です。 たとえ`O(n²)`アルゴリズムは次のように実行します`4·10^10`最悪の場合の運用。 直線的な解決策が必要です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
n = 5
RRRRR
```文字列は円形であるため、これは長さ 5 の 1 つの連続であり、5 つの別々の位置ではありません。 円を忘れた線形実行処理アルゴリズムでは、間違った答えが計算されてしまいます。 

別の例は次のとおりです。```
RLRLRL
```すべてのプレイヤーは、自分を攻撃しているユニークなプレイヤーをすでに攻撃し返しています。 答えは`0`。 

3 番目の微妙なケースは次のとおりです。```
RRRLLL
```最初と最後のランは、同じ文字を持つ場合にのみ、円形の境界を通過します。 ここではそうではないので、実際には長さ 3 の 2 つの別々のランが存在します。文字列を 1 つのマージされたランとして扱うのは正しくありません。 

## アプローチ

 ブルートフォースアプローチでは、プレーヤーのすべてのサブセットを反転して、結果の構成が論理的かどうかを確認します。 がある`2^n`考えられる反転パターンは、たとえ`n = 40`、ましてや`n = 200000`。 

有用なものを得るには、有効な構成の構造を理解する必要があります。 

同一の文字の最大の実行を見てください。```
RRRRRR
```ラン内に連続する 3 人のプレーヤーを考えてみましょう。 中央の選手は片側からのみ攻撃されます。 みんなと同じ方向に攻撃してきますので、反撃はしません。 そのようなプレイヤーはルールに違反します。 

1 人のプレーヤーの方向を変更すると、1 回のランで最大 3 つの連続するポジションを修復できます。 これはよく知られたパターンにつながります。つまり、3 つの等しい連続方向のブロックごとに 1 つの変更が必要になります。 

直線的な長さの場合`k`、最小変更数は次のとおりです。```
k // 3
```これは、多くの「ロングランを中断する」問題で使用されるカウント引数とまったく同じです。 

唯一の複雑な点は、円形の構造です。 

次のように、円全体が 1 つの文字で構成されている場合:```
RRRRRRR
```長さのランは 1 つだけです`n`、答えは次のとおりです。```
(n + 2) // 3
```それ以外の場合は、隣接する文字が異なる境界が少なくとも 1 つ存在します。 そのような境界は自然に円を破ります。 文字が異なる任意の位置で円を切ると、問題は直線になります。 すべての最大実行を独立して処理できるため、`length // 3`。 

これにより、単純な線形時間解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 循環文字列内のすべての文字が同一かどうかを確認します。 

そうであれば、円全体が 1 つの長さを形成します。`n`。 答えは`(n + 2) // 3`。 
2. それ以外の場合は、隣接する文字が異なる位置を見つけます。 

すべての文字が等しいわけではないため、このような位置は常に存在します。 
3. この位置が始点となるように概念的に円を回転させます。 

このカットの後、結果のシーケンスの最初と最後の文字は異なります。これは、境界を囲むランが存在しないことを意味します。 
4. 回転されたシーケンスを走査し、等しい文字の最大の連続の長さを計算します。 
5. 長さのランごとに`len`、 追加`len // 3`答えに。 

ラン内の 3 つの連続する同じ方向ごとに 1 つのフリップが必要であり、これらの要件はラン間で独立しています。 
6. 蓄積された回答を出力します。 

### なぜ効果があるのか

 ランに長さがある場合`len`、境界付近のプレイヤーを除くすべてのプレイヤーは同じように動作します。 問題のある位置は、連続する 3 つの同じ方向のグループで発生します。 慎重に選択した 1 つのフリップで修復できるのは、そのようなグループを最大でも 1 つだけですので、少なくとも`len // 3`フリップは必要です。 

逆に、ラン内の 3 番目の位置ごとにフリップを配置すると、正確に達成されます。`len // 3`変化し、すべてのプレイヤーが論理的になります。 異なる実行は方向の変更によって分離されるため、それらの修正は相互作用しません。 合計する`len // 3`すべての実行で全体的な最適値が得られます。 

円全体が 1 つのランである特殊な場合には、自然な境界は存在しません。 円形の長さの連続`n`必要`ceil(n/3)`変化、つまり`(n + 2) // 3`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        if s.count(s[0]) == n:
            print((n + 2) // 3)
            continue

        pos = 0
        while s[pos] == s[(pos + 1) % n]:
            pos += 1

        s = s[pos + 1:] + s[:pos + 1]

        ans = 0
        cnt = 1

        for i in range(1, n):
            if s[i] == s[i - 1]:
                cnt += 1
            else:
                ans += cnt // 3
                cnt = 1

        ans += cnt // 3
        print(ans)

solve()
```最初のブランチは、円全体が 1 回の実行であるという特殊な状況を処理します。 その場合、カットする異なる境界がないため、標準的な実行分解は機能しません。 

他のすべてのケースでは、異なる文字を持つ隣接するペアを見つけます。 このようなペアの直後を切り取ると、回転された文字列の最初と最後の文字が異なることが保証されます。 これにより、円形ラン構造が通常の直線ラン構造に変換されます。 

トラバーサルでは、標準カウンターを使用して最大ランレングスを計算します。 実行が終了するたびに、`run_length // 3`答えに。 ループの後、最後の実行も処理する必要があります。 

よくある間違いは、すべてが等しい場合を忘れることです。 特別な処理を行わないと、回転ステップで有効なカットを見つけることができず、式が不正確になります。 

もう 1 つの起こりやすいエラーは、任意の位置でカットすることです。 カットがランの内側にある場合、円形のランが 2 つの小さなランに分割され、アンダーカウントが発生する可能性があります。

 ## 特殊なケース

 次のことを考慮してください。```
n = 5
RRRRR
```アルゴリズムは、すべての文字が同一であることを検出します。 すぐに次のように返されます。```
(5 + 2) // 3 = 2
```回転は試行されません。 これにより、異なる境界を永遠に検索した場合に発生する失敗が回避されます。 

ここで次のことを考えてみましょう。```
n = 6
RRRLLL
```文字列は均一ではありません。 3 番目の境界の間には異なる境界が存在します。`R`そして最初に`L`。 

実行分解は次のようになります。```
RRR
LLL
```貢献内容は次のとおりです。```
3 // 3 + 3 // 3 = 2
```正しい答えを与えること`2`。 

最後に、次のことを考慮してください。```
n = 8
RLRLRLRL
```どのランにも長さがある`1`。 

アルゴリズムは以下を計算します。```
1 // 3 + 1 // 3 + ...
```合計すると`0`。 

これにより、すでに有効な構成が不必要な変更を加えることなく認識されることが確認されます。
