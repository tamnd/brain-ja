 ## 解決策
 ## 問題の理解

 ここでは、最大 25 x 25 の小さなグリッドを使用しています。このグリッドでは、右または下への移動のみを使用して、左上のセルから右下のセルまでのパスが形成されます。 したがって、各パスは常に正確に$2n-1$訪問したセル。各ステップで行または列のいずれかが増加し、正確に必要となるためです。$n-1$それぞれの方向に動きます。 

クエリの前に、すべてのグリッド セルに負でない重みを割り当てることができます。各重みは最大です。$10^{16}$。 その後、未知の単調パスがクエリごとに固定されます。 各クエリに対して、その隠れたパスに沿った重みの合計のみが与えられるため、訪問したセルの正確なシーケンスを再構築する必要があります。 

主な問題は、クエリごとに 1 つの数値しか表示されないことですが、グリッドが慎重に構築されていない限り、多くの異なるパスで同じ合計が生成される可能性があることです。 

制約が非常に厳しい$n$、これは指数関数的な構造が可能であることを示唆しています。 と$n \le 25$、せいぜいあります$\binom{48}{24}$考えられるパス、それは周囲にあります$10^{13}$、クエリごとに直接区別するには大きすぎます。 これにより、各パスを個別にエンコードしたり、パスの回復を動的にシミュレートしようとする戦略は即座に除外されます。 

インタラクティブな性質によってコア構造は変わりません。すべての有効なパスが一意の合計を生成するように、グリッド内で固定エンコーディングを設計します。また、このエンコーディングはパスに反転できる必要があります。 

対称性について考えると、微妙なエッジケースが現れます。 多くの異なるパスが長いプレフィックスを共有しており、行数または列数のみに依存するエンコードは失敗します。これは、右移動と下移動の異なるインターリーブによって同一の集約寄与が生成される可能性があるためです。 割り当てのような単純なアプローチ$a_{x,y} = x \cdot n + y$また、訪問セルの異なるマルチセットが合計で一致する可能性があるため、このような線形エンコーディングからパス合計を一意に復号できないため、失敗します。 

実際の要件は、和の一意性だけではなく、その和がパスに沿った一連の二分決定をエンコードすることです。 

## アプローチ

 強引な解釈は、ランダムまたは貪欲な重みを割り当てて、すべてのパスが異なる合計を持つことを期待することです。 これは小規模な場合には高い確率で機能する可能性がありますが、$n$、敵対的な構築では何の保証も提供されず、さらに重要なことに、たとえ合計が一意であっても、指数関数的に多くの候補パスの中から検索する必要があるため、それらを解読することは計算上不可能です。 

構造的な洞察は、すべての単調なパスが、$(1,1)$に$(n,n)$まさに次のシーケンスです$2n-2$決定: 各ステップで右または下に移動します。 これは、正確に次の内容を含むバイナリ文字列と等価です。$n-1$ものと$n-1$ゼロ。 問題は、位置システムを使用してこのバイナリ文字列を単一の数値にエンコードすることに帰着します。 

これは、各ステップの選択を、合計に対する 2 の明確な累乗に寄与するものとして扱うことを示唆しています。 ただし、ステップごとの直接エンコードは機能しません。これは、ステップを直接観察するのではなく、グリッド セルの合計のみを観察するためです。 したがって、ステップをエンコードする代わりに、再構成中に各ステップの寄与を分離できるような方法でセルをエンコードします。 

重要なアイデアは、慎重に選択された基準 (対角線の構造に合わせた 2 のべき乗) でセルの線形インデックスのみに依存する重みを割り当てることです。 それぞれの動きの決定が 2 つの素の寄与のうちの 1 つを選択することに対応し、合計が選択の順序を一意に決定するようにしたいと考えています。 

きれいな構造の 1 つは、対角線上のバイナリ分解での位置に基づいて各セルに重みを割り当て、右または下に移動すると制御された方法で正確に 1 ビットが切り替わることを保証することです。 これにより、問題は和のバイナリ表現からパスを復元することに減り、残りの和の一貫性をチェックしながら遷移をシミュレートすることで貪欲にデコードできます。 

より直接的な建設的な解決策、そして通常意図されている解決策は、各ステップの決定をローカルで回復できるように重みを割り当てることです。パスをエンコードして、すべてのノードで、右に進むか下に進むかの違いが残りの合計構造から厳密に検出できるようにします。 これは、1 つの軸に沿って指数関数的に増加する重みを使用し、プレフィックス決定が干渉しないように寄与のバランスを慎重に調整することによって実現されます。 

このようなエンコードが修正されると、デコードは決定論的なウォークになります。各セルで、残りの合計が右または下の移動と一致するかどうかを確認し、唯一の有効な方向を選択します。

 ## アルゴリズムのチュートリアル

 列に合わせて 2 のべき乗を使用してグリッド エンコーディングを構築します。 具体的には、各セルに割り当てます$(i,j)$重り$a_{i,j} = 2^{(i-1)n + (j-1)}$。 これにより、すべてのセルが 2 進数の長さの一意のビット位置に変換されます。$n^2$。 

ただし、すべてのセルが完全に独立している必要はなく、すべての単調パス和が一意にデコード可能であることだけが必要です。 各パスにはステップごとに 1 つのセルが含まれており、正確に訪問するため$2n-1$セルの場合、合計は単に個別のビットにわたる部分集合の合計であり、訪問済みのセットに一意に反転できます。 

次に、からの動きをシミュレートすることで、パスを貪欲に再構築します。$(1,1)$:

 1. から開始します$(1,1)$残りの金額で$k$。 開始セルは常に含まれるため、減算します。$a_{1,1}$から$k$。 
2. 各ステップで、右または下に移動することが有効な継続につながるかどうかを検討します。 次のセル候補を両方チェックします。 
3. 次のセルの場合$(x, y+1)$バイナリ分解と一致する方法で残りの合計を超えない重みを持っている場合、それを取得しようとします。 それ以外の場合は$(x+1, y)$。 
4. 移動後、残りの合計から選択したセルの重みを減算して続行します。 
5. 到達するまで続ける$(n,n)$、残りの合計が未訪問の将来のセルに正確に対応することを常に維持します。 

重要な特性は、すべてのセルが一意の 2 の累乗に対応するため、どの時点でも、残りの合計がパス上に今後どのセルが残るかを正確にエンコードすることです。 パスは単調で固定長であるため、各ステップで 2 つの可能な移動のうちの 1 つだけが残りのビット構造との一貫性を維持します。 

### なぜ効果があるのか

 各セルの重みは個別の 2 の累乗であるため、セルのセットの合計は一意の 2 進数になります。 すべての有効なパスはセルの固定サイズのサブセットに対応するため、パスから合計へのマッピングは単射的です。 再構成中、サブセットは単調パスを形成しなければならないという追加の制約を付けて、既知のサブセット合計構造を効果的にデコードします。 この構造的制約により、各ステップで 2 つの出力エッジのうちの 1 つが残りの合計と一致する有効なサブセットにつながることが保証されるため、貪欲な再構築は発散できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

# assign powers of two to each cell
a = [[0]*n for _ in range(n)]
cur = 0
for i in range(n):
    for j in range(n):
        a[i][j] = 1 << cur
        cur += 1

for row in a:
    print(*row)
sys.stdout.flush()

q = int(input())

for _ in range(q):
    k = int(input())

    x, y = 0, 0
    path = [(x+1, y+1)]
    rem = k - a[0][0]

    while x != n-1 or y != n-1:
        if y + 1 < n:
            if rem & a[x][y+1]:
                y += 1
            else:
                x += 1
        else:
            x += 1

        path.append((x+1, y+1))
        rem -= a[x][y]

    for p in path:
        print(p[0], p[1])
    sys.stdout.flush()
```グリッド構造では、2 つのサブセットが合計で衝突しないように、各セルに一意のビット位置が割り当てられます。 再構築では実行中の剰余が保持され、ビット チェックを使用して、次の移動に残りのサブセットに特定のセルを含める必要があるかどうかが決定されます。 パスは単調であるため、ウォークではセルを再訪問することはなく、訪問した重みを減算することで正確性が維持されます。 

微妙な点は、残りの合計が真のパス サフィックス上の未訪問のセルに正確に対応するという不変条件に常に依存していることです。 これにより、完全なサブセットを明示的に保存していない場合でも、メンバーシップ チェックの信頼性が高まります。 

## 実用的な例

 検討してください$n=2$。 グリッドは次のとおりです。 

| セル | 値 |
 | --- | --- |
 | (1,1) | 1 |
 | (1,2) | 2 |
 | (2,1) | 4 |
 | (2,2) | 8 |

 パスは (1,1) → (1,2) → (2,2) となり、合計は 1 + 2 + 8 = 11 になります。 

開始時、残りの合計は 11 - 1 = 10 です。(1,1) から、(1,2) と (2,1) を比較します。 2 は和分解にあるので、右に移動します。 残りは 10 - 2 = 8 になります。(1,2) のうち、8 個一致するため、(2,2) のみが有効です。 正しく最後まで到達します。 

ここでパス (1,1) → (2,1) → (2,2) を考えます。合計は 1 + 4 + 8 = 13 となります。 

| ステップ | 位置 | 残額 | 決定 |
 | --- | --- | --- | --- |
 | 0 | (1,1) | 12 | 開始 |
 | 1 | 移動 | 8 | 選択済み |
 | 2 | (2,1) | 8 | 強制右 |
 | 3 | (2,2) | 0 | 終わり |

 これは、各ステップで 1 つの移動だけが残りのビット構造との一貫性を保っていることを示しています。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = [[0]*n for _ in range(n)]
    cur = 0
    for i in range(n):
        for j in range(n):
            a[i][j] = 1 << cur
            cur += 1

    out = []
    for i in range(n):
        out.append(" ".join(str(x) for x in a[i]))

    q = int(input())
    for _ in range(q):
        k = int(input())
        x, y = 0, 0
        rem = k - a[0][0]
        path = [(1,1)]
        while x != n-1 or y != n-1:
            if y + 1 < n and (rem & a[x][y+1]):
                y += 1
            else:
                x += 1
            path.append((x+1, y+1))
            rem -= a[x][y]
        for p in path:
            out.append(f"{p[0]} {p[1]}")
    return "\n".join(out)

 ## 特殊なケース

 最小限のグリッド$n=2$エンコーディングが最小数のパスの下で一意性を維持するかどうかを明らかにします。 可能なパスが 2 つしかない場合でも、システムは合計を正確に区別する必要があります。 バイナリ割り当てにより、(1,1) が常に含まれることが保証され、残りの決定は 2 番目のビットが右に対応するか下に対応するかによって解決され、常に一意に検出可能になります。 

特殊なケースは、最初に常に右に移動するなど、強制されるまでパスが常に一方向に移動する場合です。 その状況では、厳密に予測可能な 2 の累乗シーケンスで剰余が減少するため、各ステップで正確に 1 つの隣接ビットが設定されたままになります。 これは、一意のビット エンコーディングではタイは発生しないため、貪欲な再構築がタイブレーク ロジックに依存しないことを確認します。
