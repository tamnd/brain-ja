 ## 解決策
 ## 問題の理解

 左から右に並べられた一連の高さが与えられます。 目標は、このシーケンスを非減少になるように変更することです。つまり、すべての要素が少なくともその前の要素と同じ大きさになることを意味します。 

唯一許可される操作は少し特殊です。高さがすでに減少していない位置の連続ブロックを選択し、そのブロック内のすべての値をちょうど 1 だけ増やします。 これを何度でも繰り返すことができ、配列全体を非減少にするために必要な演算の数を最小限に抑えたいと考えています。 

ここで最も重要な制約は、最大 200,000 までのすべてのテスト ケースにわたる長さの合計です。 これにより、テスト ケースごとに本質的に線形または線形に近いソリューションが強制されます。 操作を明示的にシミュレートしたり、繰り返しセグメントを貪欲に修復しようとするアプローチは失敗します。これは、各操作が多くの要素に影響を与える可能性があり、操作の数も膨大になる可能性があるためです。 

局所的な減少が重なると、微妙な問題が発生します。 たとえば、次のような配列では、`5 1 4 2`、単純な考えでは、各反転を個別に修正しようとするかもしれませんが、1 つの領域を増やすと他の場所で単調性が作成または削除される可能性があるため、操作は相互作用します。 もう 1 つの障害モードは、常に最大の非減少セグメントで動作すると仮定していますが、他の場所での構造の破壊を避けるためにより小さなセグメントを選択する必要がある場合があるため、これは常に最適であるとは限りません。 

## アプローチ

 ブルートフォース戦略では、プロセスをシミュレートしようとします。つまり、配列を繰り返しスキャンし、減少していないサブセグメントを見つけ、増分を適用し、ソートされるまで繰り返します。 各操作は制約を尊重するため、これは原理的には正しいです。 ただし、各操作では値が 1 ずつ増加するだけであり、最大 O(max(a)) の有効な増分レイヤーが存在する可能性があります。 最悪の場合、高さは 10^9 までの大きな値で異なるため、これは完全に不可能になります。 

重要な観察は、実際の操作という観点から考えるのをやめ、代わりに各位置が隣接する位置と比較して何層の「修正層」を必要とするかという観点から考えるべきであるということです。 左から右にスキャンすると、配列がそこから落ちるたびに、`a[i-1]`に`a[i]`、で始まるサフィックス`i`最終的には、少なくともその減少によって生じた赤字に匹敵するまで引き上げられなければなりません。 各滴は、構造化された方法で蓄積される独立した「高さ補正要求」に寄与します。 

これは貪欲な累積につながります。これまでに必要な操作の数を維持し、減少が見られるたびに、累積的な意味でその減少のサイズだけ正確に答えを増やす必要があります。 驚くべき単純化は、答えが連続する要素間の正の差の合計になることですが、特定の方向の方法で計算されます。非減少順序を強制しているため、左から右に移動するときにシーケンスが単調性に違反する場所だけを考慮します。 

ブルート フォースは明示的な操作に基づいて推論するため、失敗します。 最適なソリューションが機能するのは、各減少が必要なグローバルな「レイジング層」の最小数に独立して寄与するためです。

 ## アルゴリズムのチュートリアル

 以前のすべての要素を非減少構造と一致させるために必要な操作の数を維持しながら、配列を左から右に処理します。 

1. カウンターから始める`ans = 0`。 これにより、必要な操作の数が保存されます。 
2. インデックス 1 から n-1 まで配列を反復処理します。 各位置で、現在の高さと前の高さを比較します。 
3. もし`a[i] >= a[i-1]`、この境界では構造的に壊れるものは何もないため、このペアによって新しい操作が強制されることはありません。 
4. もし`a[i] < a[i-1]`、シーケンスが落ちます。 これは、次で始まるサフィックスを意味します。`i`以前のものに比べて低すぎるため、追加の操作が必要です。 増やします`ans`による`a[i-1] - a[i]`。 

この増分が正しい理由は、各減少単位が 1 つの必要な「レイヤー」に対応し、後でそのサフィックスをカバーする非減少セグメント上に適用する必要があるためです。 演算により、減少しない部分配列を 1 ずつ増やすことができるため、各ユニット ギャップは、最適な構成で必要な演算を 1 つだけ提供します。 

### なぜ効果があるのか

 シーケンスが低下するたびに、より小さな要素を含むサフィックスに適用される将来の操作によって補わなければならない欠損が生じます。 操作では単調セグメント上で値を均一に増加させることしかできないため、一貫した方法で調整しない限り、単一の単位増加で複数の独立した低下を修正することはできません。 貪欲な累積により、不足の各単位が正確に 1 回カウントされることが保証され、すでにバランスが取れている領域で無駄な操作が行われないようになります。 

これにより、問題は、隣接するペア全体の下向きの「圧力」の合計を測定することに変わります。これは、必要なグローバル増分レイヤーの最小数に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        for i in range(1, n):
            if a[i] < a[i - 1]:
                ans += a[i - 1] - a[i]
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、前述した左から右への累算を直接実装しています。 唯一の微妙な点は、厳密な減少が発生した場合にのみ貢献を追加するようにすることです。 等しいまたは増加する遷移は、すでに局所的に非減少構造を満たしているため、修正する必要はありません。 

効率を高めるために、答えはテスト ケースごとに蓄積され、最後に出力されます。

 ## 特殊なケース

 重要なエッジケースは、次のような完全に非増加の配列です。`5 4 3 2 1`。 アルゴリズムは隣接するすべてのドロップを合計し、`1 + 1 + 1 + 1 = 4`加えて、初期の差分が累積して合計 10 になります。これは、各ステップで必要な新しい修正レイヤーが導入されるという事実と一致します。 

もう 1 つのケースは、次のようなすでに非減少配列です。`1 2 2 3`。 減少がないため、ループは答えを増分することはなく、出力は 0 です。これは、アルゴリズムがフラット セグメントを過剰にカウントしていないことを確認します。 

より微妙なケースは、次のような交互のピークです。`3 1 4 1 5 1`、ドロップは複数の独立した場所で発生します。 各ドロップは個別にカウントされ、アルゴリズムが各ローカル違反を必要な操作の独立したソースとして扱うことを示しています。これはまさに操作定義によって強制されるものです。
