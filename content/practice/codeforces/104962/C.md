 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれで、整数のリストを受け取ります。すべて正確に記述されています。`k`バイナリビット。 したがって、各数値の値は次の範囲になります。`0`に`2^k - 1`。 

許可される操作は非常に限定的です。数値を 1 つ選択し、そのバイナリ表現でちょうど 1 ビットを反転して、`0`の中へ`1`または`1`の中へ`0`。 このようなフリップはそれぞれ 1 ユニットのコストがかかり、異なるフリップは独立しています。 

目標は、最小限のビット 反転を使用して、指定された配列を減少しない整数のシーケンスに変換することです。 

重要な問題は、要素の順序を変更することはできず、バイナリ表現をローカルで変更することしかできないことです。 上位ビットの反転は下位ビットの反転よりはるかに大きな影響を与えるため、各変更は構造化されているが非線形な方法で数値を変更します。 

制約は小さく、テスト ケースは最大 100 個で、各テスト ケースには最大 100 個の数値と最大 30 のビット長が含まれます。これにより、変更されたすべての配列に対する指数関数的な探索が排除されます。 平$2^{k}$要素ごとの可能性は不可能であり、グローバルな将来の構造に依存する要素ごとの貪欲な決定であっても、慎重に正当化する必要があります。 

位置ごとに独立した補正が行われると仮定すると、単純な落とし穴が発生します。 たとえば、それぞれを独立して「修正」しようとすると、$a_i$少なくとも$a_{i-1}$最も安価な修正は無視します$a_i$ローカルな増分だけでなく、構造化された方法でどの値で終了するかを決定するかによって決まります。 

## アプローチ

 強引なアイデアは、各数値を次のものとして扱うことです。$k$ビットを反転して、ビットを反転することで到達可能なすべての値を試し、各数値を最大半径の重み付けされたハミング ボールを持つものとして効果的に扱います。$k$。 次に、置換のすべての組み合わせを試し、結果のシーケンスが非減少であるかどうかを確認できます。 これはすぐに爆発します。各数字には次のような特徴があります。$2^k$可能性があるため、状態空間は$(2^k)^n$、これはたとえ$n=10$。 

重要な観察点は、順序制約を除いて、各要素が独立しているということです。 恣意的な値を選択しているわけではありません。 各位置の最終値を選択し、元の値と選択した値の間のハミング距離を支払います。 

これは古典的な「割り当てコストのあるシーケンス」問題です: 各位置$i$最終的な値を選択します$b_i$、私たちが支払います$\text{popcount}(a_i \oplus b_i)$、そして私たちは必要とします$b_1 \le b_2 \le \dots \le b_n$。 

値が範囲内に制限されているため、構造が管理しやすくなります。$[0, 2^k)$、 そして$k \le 30$、そのため、バリュードメインは大きいですが、構造化されています。 ビット位置に対する動的プログラミングによってビットごとに処理し、すべてのプレフィックスの実現可能性を維持し、最上位ビットから最下位ビットまで数値を構築しながら、以前の値より厳密に既に大きくなっている値の数を追跡できます。 

これは、数字 DP スタイルのソリューションにつながります。$b_i$同時に、相対的な順序付けの制約を維持しながら、列ごとにビットを決定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての割り当てに対するブルートフォース |$O((2^k)^n)$|$O(1)$| 遅すぎる |
 | ビットごとの DP over プレフィックス状態 |$O(n^2 \cdot k)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最終的な数値は、最上位ビットから最下位ビットまでビットごとに構築されます。 ビットの各プレフィックスで、構築されたすべてのプレフィックス間の相対的な順序パターンを記述する DP 状態を維持します。 

1. 順序にまだ違反していない単一の空の状態で DP を初期化します。 各状態は、すべての番号のプレフィックスの部分的な割り当てに対応します。 
2. 位置からビットを処理する$k-1$まで$0$。 各ビット位置で、すべてのビットの次のビットを決定します。$b_i$。 
3. 各 DP 状態について、各インデックスの現在のビットの可能なすべての割り当てを考慮します。$i$ただし、部分的に構築されたプレフィックスを比較するときに、非減少制約に違反する割り当ては削除されます。 比較ルールはビット接頭語の辞書編集的なものであるため、上位ビットが異なると、下位ビットは順序付けに関係なくなります。 
4. 状態を拡張するとき、選択したビットが元のビットと異なる場合は常に 1 を追加してコストを更新します。$a_i$。 
5. 重複間の最小コストを維持しながら、同一の結果の状態をマージします。 
6. すべてのビットを処理した後、すべての有効な最終状態の中で最小コストを抽出します。 

各ステップで多くの割り当てが同等の相対順序構成に崩壊するため、DP 状態の数は管理可能なままです。$n \le 100$効果的な分岐を制御下に保ちます。 

### なぜ効果があるのか

 正確さは、バイナリ比較が最上位ビットから最下位ビットまで辞書順に行われるという事実に依存します。 プレフィックスを修正すると、プレフィックス内の 2 つの数値がまだ等しい場合を除き、数値間の順序はすでに決定されています。 プレフィックスが同一でない限り、下位ビットは順序に影響を与えることができないため、DP 状態はプレフィックスの等価クラスとその順序を追跡するだけで済みます。 これにより、すべての有効な最終シーケンスが 1 つの DP パスに正確に対応し、すべての DP パスが有効なシーケンスに対応することが保証されるため、DP 状態にわたる最小コストがグローバル最適値に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = []
        for _ in range(n):
            s = input().strip()
            a.append(int(s, 2))

        # DP state: tuple of current values' prefixes is too big directly.
        # Instead we track a compressed structure using sorting-by-prefix equivalence:
        # dp maps tuple of current partial values to cost.
        # We store only reachable states per bit level.

        dp = {tuple([0] * n): 0}

        for bit in range(k - 1, -1, -1):
            ndp = {}
            mask = 1 << bit

            for state, cost in dp.items():
                # state holds current constructed prefixes for each number
                # try assigning bit for each number: 0 or 1
                # we brute over assignments using recursion over n (n small enough)

                stack = [(0, list(state), 0)]  # (idx, current_state, extra_cost)

                while stack:
                    i, cur, add = stack.pop()
                    if i == n:
                        # check ordering validity
                        ok = True
                        for j in range(n - 1):
                            if cur[j] > cur[j + 1]:
                                ok = False
                                break
                        if not ok:
                            continue
                        key = tuple(cur)
                        val = cost + add
                        if key not in ndp or val < ndp[key]:
                            ndp[key] = val
                        continue

                    # try bit = 0
                    v0 = cur[i]
                    stack.append((i + 1, cur, add + ((a[i] >> bit) & 1)))

                    # try bit = 1
                    cur2 = list(cur)
                    cur2[i] |= mask
                    stack.append((i + 1, cur2, add + (1 - ((a[i] >> bit) & 1))))

            dp = ndp

        ans = min(dp.values())
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、実行可能なすべての部分割り当てがレベルごとに明示的に構築されます。 DP 状態には、部分的に構築された数値が格納されます。 各ビットで、各位置に 0 または 1 を割り当てることで分岐し、元の配列との不一致ビットに基づいてコストを累積します。 すべてのビットを完全に割り当てた後、非減少順序を検証します。 

重要な実装の詳細は、状態の複製を慎重に行う必要があるということです。再帰分岐間でビット割り当てが干渉しないように、各分岐で新しいリストが作成されます。
