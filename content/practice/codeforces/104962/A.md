 ## 解決策
 ## 問題の理解

 私たちには次のサイクルが与えられています`n`家々。 各家は円上に配置されているため、どの家もサイクルに沿って左または右に移動するという自然な概念を持っています。 

パラメータを選択できます`k`。 一度`k`固定されているため、すべての家が直結しています。`k`左側に最も近い家と、`k`右側に最も近い家。 これらの接続を構築すると、各ノードから 1 回の移動で近くのノードのブロック全体にジャンプできるため、グラフは単純なサイクルよりもはるかに高密度になります。 

2 つの家の間の距離は、この新しいグラフ内で家の間を移動するために必要なエッジの最小数として定義されます。 タスクは最小のものを選択することです`k`任意の家のペア間の最大可能な最短経路距離が最大で`d`。 

言い換えれば、円に沿った 1 ステップで各ノードがどこまで「見える」かを制御し、結果として得られるグラフの直径が最大になるようにします。`d`。 

制約は非常に大きく、`n`そして`d`まで`10^12`。 これにより、グラフのシミュレーションやテスト ケースごとの BFS スタイルの推論が直ちに除外されます。 隣接関係を保存することさえ不可能であるため、解決策は構造を直接式か、せいぜい対数計算に分解する必要があります。 

微妙なエッジケースは次のような場合です`n`とても小さいです。 たとえば、次の場合`n = 3`、構造はすでにほぼ完全に接続されています。`k`、そして距離を置く行動は些細なものになります。 もう一つのコーナーは、`d`さえ十分に大きい`k = 1`サイクルの直径がすでに範囲内にある小さなサイクルのように、すでに要件を満たしています。 

素朴な誤解は、距離が複雑なグラフのショートカットに依存すると考えることです。 たとえば、加重区間グラフで最短経路をシミュレートしようとするかもしれませんが、接続が非常に剛直な構造を持っているため、それは不要です。つまり、すべてのエッジがサイクル上の有界ジャンプに対応します。 

## アプローチ

 直接的な総当たりアプローチでは、次の値が試行されます。`k`から始まる`1`、グラフを構築し、すべてのノードから BFS を使用してその直径を計算します。 各 BFS は次のようになります。`O(n)`そして繰り返されました`n`回、与える`O(n^2)`あたり`k`。 以来`k`まで行くこともできます`n`、これは中程度のサイズであっても完全に実行不可能になります。`n = 10^12`。 

重要な観察点は、グラフが完全に対称であることです。 すべてのノードは同じ接続構造を持っており、重要なのは 1 つのステップでサイクルに沿ってどこまで移動できるかだけです。 どのノードからでも、1 回の移動で次のノードにジャンプできます。`k`時計回りまたは反時計回りに位置します。 これにより、グラフが 1 次元のメトリクスに変わり、各ステップで残りの円の距離が最大で 1 つ減少します。`k`。 

2 つのノードが円周距離だけ離れている場合`x`の場合、それらの間の最短パスは正確に次のようになります。`ceil(x / k)`。 最悪のケースが起こるのは、`x`できる限り大きい、つまり円上の最も遠い距離です。`floor(n / 2)`。 

したがって、グラフの直径は次のようになります。`ceil(floor(n/2) / k)`。 問題は最小のものを見つけることに帰着します`k`この値が最大でも`d`。 

この不等式は簡単に反転でき、次の式が得られます。`k`。 問題全体は、テスト ケースごとの定数時間演算に集約されます。

 ## アルゴリズムのチュートリアル

 1. サイクル上の関連する最大距離、つまり 2 つのノードが離れ得る最も遠い距離を計算します。 円周上では、これは`floor(n / 2)`。 これは、より長い円弧を反対方向により安価に横断できるためです。 
2. パラメータを使用してそれを観察します`k`、1 つのステップで以下をカバーできます。`k`サイクルに沿ったポジション。 これは、長距離を移動することを意味します`A = floor(n / 2)`かかります`ceil(A / k)`最悪の場合の手順。 
3. グラフの直径は最大でも次のとおりである必要があります。`d`、したがって、私たちは強制します`ceil(A / k) ≤ d`。 
4. この不等式を次の条件に変換します。`k`。 最小の整数`k`満足です`ceil(A / d)`。 
5. この値を各テスト ケースの答えとして返します。 

### なぜ効果があるのか

 すべてのノードは接続性の点で同一に動作するため、最悪の場合の最短パスはノードの ID ではなく純粋に円周距離によって決まります。 各移動ごとに残りの距離は最大で減少します`k`すべてのエッジが同じ有界区間構造を尊重するため、どのパスも貪欲リダクションを上回るパフォーマンスを発揮することはできません。 これにより、最短パスは距離をサイズの塊に分割することと等価になります。`k`、直径はサイクル上の可能な最大距離によって完全に制御されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, d = map(int, input().split())
        A = n // 2
        k = (A + d - 1) // d
        out.append(str(k))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、派生した式が直接適用されます。 唯一の微妙な点はコンピューティングです`ceil(A / d)`整数演算を安全に使用して`(A + d - 1) // d`。 整数の除算を使用すると、浮動小数点エラーが回避されます。浮動小数点エラーはここでは関係ありませんが、それでも競技プログラミングではよくある落とし穴です。 

値`A = n // 2`最悪の場合の円周距離が得られ、他のすべてはその短縮に基づいて計算されます。 グラフの構築は必要ありません。

 ## 特殊なケース

 非常に小さい場合`n`、 のような`n = 3`、サイクルには意味のある距離値が 1 つだけあるため、アルゴリズムは正しく減少します。`n // 2`になる`1`。 計算された`k`常に少なくとも`1`なので、特別な処理は必要ありません。 

非常に大きい場合`d`、 のような`d ≥ floor(n/2)`、式は次のようになります`k = 1`。 これは直感と一致します。なぜなら、基本的なサイクル エッジでも、許可されたステップ数内で最も遠いノードに到達できるからです。 

場合については、`d = 1`、要件により、グラフの直径が 1 回の移動で強制的に縮小されます。 数式は正しく返されます`k = floor(n/2)`これは、すべてのノードが 1 ステップで最も遠いノードから直接到達可能でなければならないことを意味し、これは構築の構造と一致します。
