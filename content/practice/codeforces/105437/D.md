 ## 解決策
 ## 問題の理解

 概念的には左半分と右半分の 2 つの等しい部分に分割された、偶数長の配列が与えられます。 スワップは 1 回だけ実行できますが、スワップには大きな制約があります。 左半分から 1 つのインデックスを選択し、右半分から 1 つのインデックスを選択し、それらの値を交換する必要があります。 

この 1 回の交換を行った後、左半分の合計が右半分の合計と正確に等しくなるようにしたいと考えています。 タスクは、そのようなスワップが存在するかどうかを判断し、存在する場合は有効なポジションのペアを出力することです。 

顕著な制約は、配列サイズが最大 200,000 であることです。 半分にまたがるすべてのペアを試行するソリューションでは、約 (n/2)^2 チェックが必要となり、最悪の場合、およそ 10^10 回の操作となり、2 秒での実行可能な制限をはるかに超えます。 これにより、ブルートフォース ペアリングが即座に排除されます。 

値自体は 10,000 で制限されており、これは周波数ベースの推論またはハッシュ技術が妥当になるほど十分小さい値です。 

微妙な点は、スワップを最大 1 回ではなく、1 回だけ実行する必要があることです。 したがって、配列にすでに等しい半分がある場合でも、何もしないのではなく、等価性を維持するスワップを見つける必要があります。 

素朴な推論の失敗モードは、左側から任意の要素を選択し、それを局所的に合計のバランスをとる右側の要素と貪欲に一致させることができると仮定することです。 たとえば、スワップは両方の半分に同時に影響するため、差分を個別に照合しようとすると、グローバル合計制約が無視されます。 

もう 1 つの罠は、スワップが半分を越える必要があることを忘れていることです。 半分の内部での有効な内部スワップは、たとえ合計が均衡するとしても許可されません。 

## アプローチ

 直接的なアプローチは、左半分に i、右半分に j を含むすべてのペア (i, j) を試し、スワップをシミュレートし、両方の半和を再計算することです。 各チェックのコストは、単純に再計算した場合は O(n)、プレフィックスの合計を維持した場合は O(1) になります。 O(1) チェックを行ったとしても、まだ O(n^2) 個のペアがあり、これは約 10^10 の演算に相当し、遅すぎます。 

改善するために、スワップの効果を代数的に書き直します。 初期の左和を S_L、右和を S_R とします。 左の値 x と右の値 y を交換するとします。 交換後、左側の合計は S_L - x + y になり、右側の合計は S_R - y + x になります。 私たちが望んでいるのは:

 S_L - x + y = S_R - y + x

 並べ替えると次のようになります。 

S_L - S_R = 2(x - y)

 これが重要な削減です。 全体の問題は、その差が半分間の全体的な不均衡によって固定されるようなペア (x, y) を見つけることになります。 

D = S_L - S_R とします。 次に、次のものが必要です。 

x - y = D / 2

 これは、D が偶数でなければならないこと、そうでない場合は解が存在しないことを直ちに意味します。 

ここでのタスクは、y = x - D/2 となるように、左半分で x を見つけ、右半分で y を見つけます。 値には制限があり、メンバーシップのチェックのみが必要なため、右半分をハッシュ セットまたは頻度マップに保存し、左の各要素をテストできます。 

これにより、インデックス上のペア検索の問題が、ポジションの簿記による値のマッチングに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 左半分の合計と右半分の合計を計算します。 すべてのスワップは両方の半分に対称的に影響を与えるため、それらの違いが重要な唯一のグローバル情報です。 
2. D = S_L - S_R を計算します。 D が奇数の場合は、すぐに停止します。 整数のペア (x, y) は x - y = D/2 を満たすことができないため、スワップによって半分のバランスをとることはできません。 
3. 右半分の値からそのインデックスへのマッピングを構築します。 有効な位置は自由に選択できるため、値が存在するかどうか、およびそれがどこで発生するかを知る必要があるだけです。 
4. ターゲットの差 k = D / 2 を計算します。ここで、(x - k) が右半分に存在するような左の要素 x を見つけたいとします。 これは、以前に導出されたスワップ条件を直接エンコードします。 
5. 左半分を繰り返します。 値 x を持つ各位置 i について、右半分のマップに x - k が存在するかどうかを確認します。 存在する場合は、すぐに (i、対応するインデックス) を返します。 これは、導出された等価条件を満たし、スワップ後の平衡和が保証されるため有効です。 
6. 左半分をスキャンした後にそのようなペアが見つからない場合は、NO を出力します。 

### なぜ効果があるのか

 変換により、スワップ効果が、選択された値の単一の線形方程式に縮小されます。 有効なスワップは x - y = D/2 を満たす必要があり、この式を満たすペアは、更新された合計に代入されるときに必ず 2 つの半和が等しくなります。 すべての候補の左の値を、一致する可能性のあるすべての右の値と比較するため、実行可能なスワップを見逃すことはありません。 

正確さは、スワップがスワップされた値を正確に減算および加算することによってのみ合計を変更するという事実に基づいています。 位置間には他に相互作用がないため、方程式は実現可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    mid = n // 2
    left = a[:mid]
    right = a[mid:]
    
    sum_left = sum(left)
    sum_right = sum(right)
    
    diff = sum_left - sum_right
    
    if diff % 2 != 0:
        print("NO")
        return
    
    k = diff // 2
    
    pos_right = {}
    for i, val in enumerate(right):
        if val not in pos_right:
            pos_right[val] = i + 1  # 1-based index in right half
    
    for i, val in enumerate(left):
        need = val - k
        if need in pos_right:
            print("YES")
            print(i + 1, pos_right[need] + mid)
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、配列を半分に分割し、それらの合計を直接計算することから始まります。 重要な実装の詳細は、そのセグメントに対して 1 から始まるインデックスを使用して右半分のインデックスを個別に維持し、次に追加することによってグローバル インデックスに変換し直すことです。`mid`。 

計算された値`k`は合計の差の半分であり、これを使用して条件を検索問題に変換します。 左の要素ごとに、右半分で必要なパートナーの値を計算し、辞書を使用して一定時間で存在を確認します。 

よくある落とし穴は、右側の位置を報告するときにインデックスをシフトするのを忘れることです。 もう1つは間違って計算しています`k`半分ではなく全額の差となり、スワップ効果から導出される方程式が崩れます。 

## 実用的な例

 ### 例 1

 入力:```
6
4 1 2 6 7 6
```左半分は`[4, 1, 2]`、右半分は`[6, 7, 6]`。 

| ステップ | S_L | S_R | 差分 | k | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 7 | 19 | -12 | -6 | 合計を計算する |
 | チェック | 7 | 19 | -12 | -6 | 正しい地図を構築する |
 | スキャン i=1 | 4 | - | - | - | 必要 = 4 - (-6) = 10 見つかりません |
 | スキャン i=2 | 1 | - | - | - | 必要 = 1 - (-6) = 7 が見つかりました |
 | 停止 | - | - | - | - | 出力スワップ |

 左の値 1 と右の値 7 を交換すると、合計のバランスがとれることがわかります。 スワップ後、両方の半分の合計は 13 になり、派生条件が正確に機能することが確認されます。

 ## 特殊なケース

 エッジケースの 1 つは、アレイがすでにバランスが取れている場合です。 たとえば:

 入力:```
4
1 2 2 1
```ここで、両方の半分の合計は 3 になります。アルゴリズムは diff = 0 を計算するため、k = 0 となります。これは、x = y が必要であることを意味するため、同一値のクロスハーフペアはすべて有効です。 右半分のハッシュ マップにより、両側に値が存在する場合、たとえ合計がすでに等しかったとしても、有効なスワップがすぐに見つかることが保証されます。 

もう 1 つのケースは、複数の同一の値が存在する場合です。 マッピングでは値ごとに 1 つのインデックスのみが保存されますが、すべての出現が有効であるため、これで十分です。 複数のスワップが存在する場合でも、方程式は位置ではなく値のみに依存するため、最初に見つかったペアを返すことで条件は満たされます。
