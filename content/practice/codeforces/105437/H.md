 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 その「スコア」は、同一文字の最大の連続セグメントに分割し、各セグメントの長さの二乗を合計することによって計算されます。 二乗することで集中力が得られるため、ロングランは不釣り合いに貢献します。 

隣接する 2 つの文字が異なる位置を 1 つだけ選択して、それらを交換することができます。 この操作は文字列の小さな領域にのみ影響しますが、実行の分割またはマージの方法が変更される可能性があり、合計スコアが大幅に変化する可能性があります。 タスクは、すべての有効な隣接する不等ペアの中で可能な限り最良のスワップを見つけることです。 

入力サイズは最大 200,000 文字であるため、すべてのスワップをシミュレートしてスコアを最初から再計算するソリューションは遅すぎます。 完全な再計算は線形であり、O(n) 個のスワップ位置ごとに再計算を行うと O(n^2) となり、これは実行可能な限界をはるかに超えています。 

重要な構造上の制約は、交換が異なる隣接する文字間でのみ許可されることです。 これは、すべての有効なスワップが、ランレングス分解における 2 つの実行間の境界に正確に位置することを意味します。 これにより、操作の影響範囲が最大 4 つの隣接する実行に即座に制限されます。 

いくつかの危険な状況が重要になります。 

単純な間違いは、スワップによって常に 2 つの実行が 1 つにマージされると想定していることです。 たとえば、`aaabbb`、境界を交換すると、`aababb`、実行をマージするのではなく、実際に分割して再配置します。 もう 1 つの間違いは、文字が境界を越えて一致する場合、スワップによって前または次の実行とのマージが作成される可能性があることを忘れていることです。 たとえば、`aaabac`、真ん中を入れ替える`b`そして`a`隣接するものと結合できる`a`が実行され、予想外に大きな二乗寄与が増加します。 

もう 1 つの微妙なエッジ ケースは、ランの長さが 1 である場合です。交換後、そのランが完全に消える可能性があり、これにより、単に長さを調整するよりも構造が劇的に変化します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのインデックスに対して、`s[i] != s[i+1]`、スワップを実行し、文字列全体のランレングス分解を再構築し、美しさを計算します。 各リビルドは O(n) で、スワップ候補が O(n) 個あるため、合計の複雑さは O(n^2) になります。 n が最大 200,000 の場合、約 4e10 の演算が必要になりますが、これは現実的ではありません。 

重要な観察は、`s[i]`そして`s[i+1]`ランレングス エンコーディングの一定サイズの近傍にのみ影響します。 関係する 2 つの実行以外のすべては変更されません。 構造全体を再計算する代わりに、最大 4 つの実行が境界付近でどのように相互作用するかを再計算するだけで済みます。 

したがって、問題は、ランレングスでエンコードされた文字列をスキャンし、隣接するランのペアごとに、スワップによってこれら 2 つのランがどのように変換され、場合によっては隣接するランとマージされるかを計算することに帰着します。 各候補は O(1) で評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列をランに圧縮し、各ランに文字とその長さを格納します。 これらの実行を`R[0..m-1]`。 

### 1. 初期の美しさを計算する

 合計して初期スコアを計算します`len^2`実行ごとに。 これにより、すべてのスワップを比較するためのベースラインが得られます。 

### 2. 実行間のすべての境界を反復処理します。 

すべての有効なスワップは、実行間の境界に対応します。`k`そして走ります`k+1`、それらの実行には異なる性格があるためです。 その境界の両側から 1 文字を交換することを検討します。 

### 3. ローカル変換をモデル化する

 走ったとしましょう`k`は`(a, x)`そして走ります`k+1`は`(b, y)`と`a != b`。 境界文字を交換すると、ローカル セグメントは次のようになります。`a^(x-1) + b + a + b^(y-1)`。 

この変換により、サイズ 1 のランが削除され、両方の元のランが最大 2 つの部分に分割される場合があります。 

### 4. 可能であれば、隣接するランとマージします。 

次のことを確認します。 

- 左隣のラン`k-1`性格がある`a`、この場合は左側とマージします`a`セグメント
 - 右隣の実行`k+2`性格がある`b`、この場合、右側とマージされます。`b^(y-1)`セグメント

 これらのマージにより二乗寄与が大幅に変化する可能性があるため、結果のランレングスを慎重に計算する必要があります。 

### 5. デルタを効率的に計算する

 影響を受ける実行の寄与を差し引きます (`k-1`、`k`、`k+1`、`k+2`存在する場合)、スワップとマージの後に新しく形成された実行の寄与を追加し直します。 

### 6. 最良の結果を追跡する

 の最大値を維持します。`initial_beauty + delta`あらゆる境界を越えて。 

### なぜ効果があるのか

 すべてのスワップは、接触する 2 つの実行のみを変更し、各側で最大 1 つの実行とマージする可能性があります。 この領域外の実行境界は、境界内で隣接する 2 つの文字を交換しても影響を受けないため、文字列の残りの部分は変更されません。 ビューティー関数は独立した実行に対して加算的であるため、計算をこの一定サイズの近傍に制限することで、正確な正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    runs = []
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        runs.append((s[i], j - i))
        i = j

    m = len(runs)

    base = 0
    for ch, ln in runs:
        base += ln * ln

    def contrib(x):
        return x * x

    ans = base

    for k in range(m - 1):
        a, x = runs[k]
        b, y = runs[k + 1]

        # only boundary swaps allowed, a != b guaranteed
        # affected runs: k-1, k, k+1, k+2

        left_char = runs[k - 1][0] if k - 1 >= 0 else None
        right_char = runs[k + 2][0] if k + 2 < m else None

        # build segments after swap:
        # a^(x-1), b, a, b^(y-1)
        parts = []

        if x - 1 > 0:
            parts.append([a, x - 1])
        parts.append([b, 1])
        parts.append([a, 1])
        if y - 1 > 0:
            parts.append([b, y - 1])

        merged = []

        for ch, ln in parts:
            if ln == 0:
                continue
            if merged and merged[-1][0] == ch:
                merged[-1][1] += ln
            else:
                merged.append([ch, ln])

        if k - 1 >= 0 and merged and merged[0][0] == left_char:
            prev_ch, prev_ln = runs[k - 1]
            merged[0][1] += prev_ln
            left_remove = contrib(prev_ln)
        else:
            left_remove = 0

        if k + 2 < m and merged and merged[-1][0] == right_char:
            next_ch, next_ln = runs[k + 2]
            merged[-1][1] += next_ln
            right_remove = contrib(next_ln)
        else:
            right_remove = 0

        old = contrib(x) + contrib(y) + left_remove + right_remove

        new = 0
        if k - 1 >= 0 and not (merged and merged[0][0] == runs[k - 1][0]):
            new += contrib(runs[k - 1][1])
        if k + 2 < m and not (merged and merged[-1][0] == runs[k + 2][0]):
            new += contrib(runs[k + 2][1])

        for ch, ln in merged:
            new += contrib(ln)

        ans = max(ans, base - old + new)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、後のすべての推論がより小さな構造で機能するように、文字列を run に圧縮することから始まります。 基本スコアはこれらの実行から直接計算されます。 

実行間の境界ごとに、スワップの実行後にローカル構成を明示的に再構築します。 の`parts`配列は、交換された文字の周りの両方の実行を分割することによって作成された 4 つの可能なフラグメントをエンコードします。 次に、隣接する等しい文字のフラグメントをマージして、実行の一貫性を復元します。 

その後、左右の隣接ランとのマージの可能性を考慮します。 通常、最も間違いが発生するのはここです。境界マージが発生した場合、マージされた新しいランレングスを追加する前に、隣接するランの寄与を削除する必要があります。 

最後に、影響を受ける領域の寄与を再計算し、グローバル最大値を更新します。 

## 実用的な例

 ### 例 1

 入力:```
aabaacaabaa
```実行:```
aa | b | aa | c | aa | b | aa
```それぞれの境界スワップを考慮します。 間の境界については、`aa`そして`b`、スワッピングはそれらの実行にのみ影響し、隣接するものに応じてマージされる可能性があります。 

| ステップ | 境界 | ローカルの変更 | マージされた実行 | スコア変更 |
 | --- | --- | --- | --- | --- |
 | 1 | aa-b | 分割 + 挿入 | a + b + a | 中程度 |
 | 2 | ああ | マージの可能性 | b+aa | 増加します |

 最適な構成は、周囲の大きなランを維持しながら中央のランを 1 つ増やすスワップから得られ、最適値 21 になります。 

### 例 2

 入力:```
wwwwz
```実行:```
wwww | z
```境界は 1 つだけ存在します。 スワップすると以下が生成されます。```
wwwzw
```| ステップ | 境界 | ローカルの変更 | | の後に実行されます。 スコア |
 | --- | --- | --- | --- | --- |
 | 1 | w-z | 分割 | www + z + w | 9 + 1 + 1 = 11 |

 これは、この操作では追加の大規模なマージを作成できないため、最善の改善はローカルの再配置に限定されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ランの長さが 1 で、スワップ後に消える場合です。 たとえば、次のようなパターンで`aba`、中央の境界を交換すると、両方のランが 1 つの文字に変更され、マージの可能性が排除されます。 アルゴリズムはこれを正しく処理します。`parts`構築では長さゼロのフラグメントがドロップされるため、ファントムの実行がスコアに寄与しないことが保証されます。 

もう 1 つのエッジ ケースは、スワップ後に両方の隣接する実行が一致し、3 方向のマージが発生する場合に発生します。 たとえば、`aaabaaa`、中央の境界を交換すると、2 つの大きな境界線を接続できます。`a`単一のセグメントをセグメント化する`b`、スコアが大幅に向上します。 ランマージロジックは、隣接する等しい文字を順番に明示的にマージし、これらの拡張マージが正しい二乗寄与を持つ単一の実行としてキャプチャされることを保証します。
