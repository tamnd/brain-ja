 ## 解決策
 ## 問題の理解

 複数のカードのセットが与えられ、各カードは整数値を保持します。 Monocarp は、カードを 1 枚ずつ選んで、カードを取りながらデッキから削除することでシーケンスを構築します。 最初のカードは自由に選ぶことができますが、次のカードはすべて、最後に取ったカードの値によって制限されます。つまり、同じ値または 1 つ大きい値のカードのみを取ることができます。 

シーケンス全体には追加の制限があります。取得したすべてのカードのうち、個別の値の数が k を超えてはなりません。 Monocarp がこれらのルールに基づいて合法的に別のカードを取得できなくなるとすぐに、プロセスは停止します。 課題は、開始カードを選択し、最適なプレイを行うことで、獲得できるカードの枚数を最大化することです。 

制約は n = 200000 まであり、すべての開始点または値のすべてのサブセットに対する二次シミュレーションが除外されます。 アレイを繰り返し再スキャンしたり、考えられるすべての貪欲な開始を個別にシミュレートしようとすると、速度が遅すぎます。 解決策では、前処理後に問題を線形または線形に近いスイープに減らす必要があります。 

値が分散しているにもかかわらず、長く使用可能なチェーンを形成している場合、微妙なエッジ ケースが発生します。 たとえば、k = 2 で配列が次の場合、`[1, 100, 2, 3, 101]`、開始点から貪欲に拡張する単純な戦略は、最適なプレイが元の順序ではなく、ソート後の連続する値の範囲の選択に依存することを認識できない可能性があります。 もう 1 つの失敗例は、常に最小値から開始しなければならないと想定していることから生じます。 +1 だけ上に移動できるため、中間の値から開始すると、使用可能なセグメントが長くなります。 

重要な隠された構造は、取得される値のシーケンスが常に減少せず、ステップごとに最大 1 ずつ増加するため、再生全体が整数値の連続した間隔内で発生する一方で、各値内の実際の順序はカウントを超えて問題にならないということです。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての開始カードを試してから、貪欲に、またはバックトラッキングを使用してゲームをシミュレートします。つまり、選択した開始から、出現した個別の値の数を追跡しながら、値が x または x+1 である利用可能なカードを繰り返し選択します。 次の有効なカードをスキャンしたり、最適化せずにバケットを維持したりすると、各シミュレーションに O(n) 時間がかかる可能性があり、これをすべての開始位置に対して行うと O(n^2) となり、200,000 要素には大きすぎます。 

重要な観察点は、ルールは位置ではなく値のみに依存するということです。 同一の値をグループ化すると、値の頻度と、すべてのカードを取ることをシミュレートする値の連続セグメントの選択が問題になりますが、プロセスの有効なセグメントでは最大で k 個の個別の値しか「使用」できないという制約があります。 

個別の値を並べ替えて圧縮すると、それぞれの値に頻度が生じます。 有効なプレイはすべて連続した値のウィンドウを選択することに対応し、そのウィンドウ内で Monocarp は左から右に移動してすべてのカードを消費できます。 最大 k 個の個別の値という制約は、個別の値に関するウィンドウ サイズが最大 k でなければならないことを意味しますが、移動は x または x+1 の遷移に制限されるため、値 x を含めると、選択した構造内にそれが存在する場合にのみ x+1 に進むことができます。 これにより、連続する整数のセグメントを選択し、それらの頻度を合計するという最適な戦略が効果的に変わります。同時に、通過する個別の値の数を制限することで k 境界を確実に遵守します。 

これは、並べ替えられた一意の値に対する古典的なスライディング ウィンドウに帰着します。隣接関係が有効な連続値のウィンドウを維持し、内部の個別の値の数が k を超えないことを確認してから、そのウィンドウ内の合計頻度を最大化します。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 並べ替え + 値の上でウィンドウをスライド | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、同じ値をグループ化し、その頻度を数えます。 シーケンスの長さを最大化するには、各値のコピーがいくつ存在するかのみが重要となるため、これにより位置情報が削除されます。 
2. 周波数を揃えて、個別の値を昇順に並べ替えます。 遷移は等しい整数間または連続する整数間でのみ許可されるため、ソートが必要です。そのため、値空間内の順序によってすべての有効な移動が定義されます。 
3. ソートされた一意の値に対して 2 つのポインターを使用して、Monocarp が横断できる候補値のウィンドウを維持します。 右ポインタを使用すると、新しい値を昇順に追加してウィンドウを拡張します。 
4. 現在のウィンドウ内のカードの総数を度数の合計として維持します。 これは、Monocarp がこの一連の値にコミットした場合に実行できるステップ数を表します。 
5. ウィンドウがゲームによって引き起こされる制約を遵守していることを確認します。値は連続したままでなければならないため、連続する値間のギャップが 1 を超える場合は、ウィンドウを現在の値からリセットします。 これは、+1 を超えるジャンプが禁止されているため、接続されていない値は有効なシーケンス内に共存できないためです。 
6. Monocarp には最大でも k 個の個別の値しか含めることができないため、サイズが k を超えるたびにウィンドウの左側を縮小します。 これにより、個別の値の数が許容制限内に保たれます。 
7. 各ステップで、有効なウィンドウで観察された最大合計頻度で回答を更新します。 

これが機能する理由は、有効なゲーム パスが連続する整数値のセグメントの選択に正確に対応しており、そのセグメント内で Monocarp がそれらの値のすべてのカードを取得できるためです。 k 制約は、個別の値に関してこのセグメントの幅を制限し、遷移ルール​​は連続する整数に制限します。 したがって、すべての有効なプレイは 1 つの有効なスライディング ウィンドウによって表され、すべてのスライディング ウィンドウは有効なプレイに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = defaultdict(int)
    for x in a:
        freq[x] += 1

    vals = sorted(freq.items())  # (value, count)

    left = 0
    curr_sum = 0
    best = 0

    for right in range(len(vals)):
        if right > 0 and vals[right][0] != vals[right - 1][0] + 1:
            left = right
            curr_sum = 0

        curr_sum += vals[right][1]

        while right - left + 1 > k:
            curr_sum -= vals[left][1]
            left += 1

        best = max(best, curr_sum)

    print(best)

if __name__ == "__main__":
    solve()
```コードは、入力を周波数マップに圧縮することから始まります。 答えは値の位置ではなく、値ごとのカウントのみに依存するため、これは不可欠です。 

値を並べ替えた後、ループは連続する整数に対してスライディング ウィンドウを維持します。 リセット条件`vals[right][0] != vals[right - 1][0] + 1`ゲームでは x から x または x+1 への移動のみが許可されているため、1 より大きいギャップを埋めることはできないというルールが適用されます。 

2 番目の制約は、個別の値の数を制限するもので、k 個の個別の値を超えるとウィンドウを縮小することによって適用されます。 累計`curr_sum`現在の有効なセグメントに何枚のカードがあるかを追跡します。これは、まさに有効なプレイ シーケンスの長さです。

 ## 特殊なケース

 重要なエッジ ケースは、入力内の値が連続していないにもかかわらず、部分的なチェーンが許容される場合です。 入力用`6 2 / 1 100 2 3 101 4`、アルゴリズムは 1 より大きいギャップに遭遇するたびに正しくリセットされます。`[1]`、次にリセットされます`100`、その後ビルドします`[2,3,4]`合計は 3 です。これは、k = 2 の制約の下で最適です。 

もう 1 つのエッジ ケースは、k がすべての個別の連続値を含むのに十分な大きさである場合です。 のために`8 3 / 1 1 2 2 3 3 4 4`、ウィンドウが k を超えることはなく、アルゴリズムはすべての周波数を 1 つのセグメントに累積し、正しく 8 を生成します。 

最後に、すべての値が同一の場合、ウィンドウは自明であり、常に有効になります。 このアルゴリズムはリセットや縮小をトリガーすることはなく、答えは単純に n であり、ルールに違反することなくすべてのカードを連続して取得できるという事実と一致します。
