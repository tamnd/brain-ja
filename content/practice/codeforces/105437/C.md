 ## 解決策
 ## 問題の理解

 赤、黄、緑に色分けされたボールのコレクションとカウントから始めます。`a`、`b`、 そして`c`。 任意の 1 つのボールを繰り返し選択し、それを他の 2 色のいずれかに塗り直すことができます。 各再ペイント操作では 1 つのボールとその色のみが変更され、ボールの総数は固定されます。 

目標は、正確に 2 つの色が存在し、それら 2 つの色が等しい量で表示される構成に到達することです。 言い換えれば、すべての再描画の後、1 つの色は完全に消え、残りの 2 つの色にはそれぞれ全ボールのちょうど半分が含まれなければなりません。 

ボールの総数は次のように固定されます。`N = a + b + c`。 同じ数の正確に 2 つの色を使用することになった場合は、それぞれに次の色が含まれている必要があります。`N / 2`ボール、だから`N`均等でなければなりません。 これにはすでに構造上の制約が導入されています。ボールの総数が奇数の場合、どの再描画シーケンスでも 2 つの等しい整数サイズのグループを生成することはできません。 

境界により、それぞれが許可されます`a`、`b`、 そして`c`100万にもなる。 これにより、ボールの総数が 300 万に達する可能性があるため、再描画をシミュレートしたり、個々のボールに対してすべての構成を試したりするアプローチは不可能になります。 テスト ケースごとに一定時間または対数時間で機能するソリューションが必要です。 

いくつかの微妙な特殊なケースについては、覚えておく価値があります。 すべてのボールが既に 2 つの色に属しているが、次のように不均一な場合`a = 2, b = 5, c = 4`の場合、合計が奇数であるため、答えはまだ不可能である可能性があります。 もう 1 つの微妙なケースは、3 つの色がすべて等しい場合です。この場合、色の削除は自然には起こりませんが、パリティ条件が満たされていれば、1 つの色を強制的に最適に消すことができます。 

## アプローチ

 ブルートフォース戦略は、再描画操作を直接シミュレートすることです。 各ステップで、現在過剰な色からボールを​​選択し、不足している色に向かって再ペイントできます。 可能であれば最終的には有効な構成に到達しますが、可能なシーケンスの数はボールの数に応じて指数関数的に増加します。 数百万個のボールを含む 1 つのテスト ケースでも、これは完全に不可能になります。 

より構造化されたビューは、最終状態を再構成することで得られます。 私たちは操作の順序には興味がなく、最終的な色の割り当てだけに興味があります。 最終的な構成は常に、3 色から 2 色を正確に選択し、すべてのボールをそれらの 2 色に、それぞれが正確に終わるように配分することで構成されます。`N / 2`ボール。 

そこで問題は次のとおりです。各色のペアについて、初期分布をこれら 2 つの色のバランスの取れた分割に変換するために再ペイントする必要があるボールの最小数はいくらでしょうか?

 たとえば赤と黄色のペアを固定し、すべての緑のボールを強制的に赤または黄色のいずれかに再割り当てするとします。 最適な戦略は、既に正しく着色されたボールをできるだけ多く保持することです。 赤に割り当てられた赤いボールはすでに正解であり、黄色に割り当てられた黄色のボールも正解です。 最終構成には緑色が存在しないため、緑色のボールを保持することはできません。 

したがって、選択したペアについて、すでに正しいボールの可能な限り最高の数は、両方の最終色が正確に到達することを条件として、赤いボールが赤のままでいられる数と黄色のボールが黄色のままでいられる数によって決まります。`N / 2`。 

重要な簡素化は、再配布を明示的にシミュレートする必要がないことです。 容量を考慮しながら、元の色を保てるボールの数を数えるだけで済みます。`N / 2`選択した 2 つの色ごとに。 

これにより、問題は、考えられる 3 つの色のペアをすべてチェックして、最良の結果を得るということになります。

 ## アルゴリズムのチュートリアル

 私たちは定義します`N = a + b + c`そして`half = N / 2`。 

1. もし`N`奇数です、戻ります`-1`すぐに。 有効な最終状態には、合計が次のような 2 つの等しい整数グループが必要です。`N`、次の場合は不可能です。`N`奇数です。 
2. 残っている 2 つの色のそれぞれの可能な選択肢を検討します。`(R, Y)`、`(R, G)`、 そして`(Y, G)`。 
3. 固定ペアの場合、元の色を維持できるボールの数を計算します。 たとえば、次のことを選択すると、`(R, Y)`の場合、赤のままの赤いボールと黄色のままの黄色のボールのみが、カウントの変更に寄与しません。 
4. 選択したペアの各色について、最大でも維持できます。`min(original_count, half)`その色のボール。 これは、色がそれ以上のものを持っている場合でも、`half`最初は、これ以上のボールを保持することはできません`half`その色の最終ターゲットはまさに`half`。 
5. これらの寄与を合計して、そのペアのキープボール数を取得します。 必要な再描画操作の回数は、`N - kept`。 
6. 3 つのペアすべての最小再ペイント コストを計算します。 

この貪欲なカウントが機能する理由は、固定容量の制約を除いて、各ターゲット バケットに対する各色の寄与が独立しているためです。`half`。 再塗装はコストが高くなるだけであり、容量がまだ利用可能なときに正しく配置されたボールを別の場所に移動してもメリットがないため、私たちは常にボールを元の色に保つことを好みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    c = int(input())

    n = a + b + c
    if n % 2 == 1:
        print(-1)
        return

    half = n // 2

    def cost(x, y):
        kept = min(x, half) + min(y, half)
        return n - kept

    ans = min(
        cost(a, b),
        cost(a, c),
        cost(b, c)
    )
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、生き残る 2 色の最終的な選択のみが重要であるという観察を直接エンコードします。 ヘルパー関数`cost(x, y)`これら 2 つの色の所定の位置に残ることができるボールの数を数えることによって、固定ペアの最適な再描画数を計算します。 からの引き算`n`保存されたボールを必要な再ペイント操作に変換します。 

微妙な点は、内部の 3 番目の色を明示的に追跡することは決してないことです。`cost`。 これは意図的なもので、除外された色のすべてのボールは分布に関係なく再ペイントされる必要があるため、選択した 2 つの色の間の最適化には影響しません。 

## 実用的な例

 ### サンプル 1

 入力:`a = 2, b = 3, c = 1`ここ`N = 6`、 それで`half = 3`。 

| ペア | 最初から保持 | 2番目から維持 | 合計保存 | コスト |
 | --- | --- | --- | --- | --- |
 | (R,Y) | 最小(2,3)=2 | 最小(3,3)=3 | 5 | 1 |
 | (R、G) | 2 | 1 | 3 | 3 |
 | (Y、G) | 3 | 1 | 4 | 2 |

 最良の選択は`(R, Y)`費用がかかる`1`。 

これは、緑が存在するとしても、それを除去して他の 2 色のバランスを取ることが最適であることを示しています。 

### サンプル 2

 入力:`a = 2, b = 5, c = 4`ここ`N = 11`、これは奇妙です。 

以来`half`は整数ではないため、すべてのボールを 2 つの等しいグループに分割することは不可能です。 一連の再描画によってパリティが変更されることはないため、出力は次のようになります。`-1`。 

このケースは、パリティが再分配ロジックとは独立した厳密な実現可能性制約であることを裏付けています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a = int(sys.stdin.readline())
    b = int(sys.stdin.readline())
    c = int(sys.stdin.readline())

    n = a + b + c
    if n % 2 == 1:
        return "-1\n"

    half = n // 2

    def cost(x, y):
        kept = min(x, half) + min(y, half)
        return str(n - kept) + "\n"

    ans = min(
        int(cost(a, b)),
        int(cost(a, c)),
        int(cost(b, c))
    )
    return str(ans) + "\n"

# provided samples
assert run("2\n3\n1\n") == "1\n"
assert run("2\n5\n4\n") == "-1\n"
assert run("10\n10\n10\n") == "10\n"

# custom cases
assert run("1\n1\n1\n") == "-1\n", "odd total impossible"
assert run("4\n4\n0\n") == "0\n", "already balanced two colors"
assert run("6\n1\n5\n") == "1\n", "optimal elimination of smallest imbalance"
assert run("1000000\n1000000\n1000000\n") == "1000000\n", "max boundary"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1,1,1 | -1 | パリティ障害 |
 | 4,4,0 | 0 | すでに有効な構成 |
 | 6,1,5 | 1 | 重要なバランスの選択 |

 ## 特殊なケース

 3 色すべてが存在し、合計が奇数の場合、次のようになります。`2, 5, 4`の場合、再分配ではパリティを修正できないため、アルゴリズムはそのケースを即座に拒否します。 計算がペアの評価に進むことはないため、誤解を招く最小値が生成される危険はありません。 

たとえば、1 つの色がゼロの場合`4, 4, 0`、ペア`(R, Y)`収量`min(4,4) + min(4,4) = 8`なのでコストはゼロです。 これは、システムが再描画なしですでに要件を満たしていることを正確に反映しています。 

すべての値が等しい場合、たとえば`10, 10, 10`、各ペアは対称的に動作し、結果は容量のみに依存します。`half`。 アルゴリズムは自然に、ボールの 1 つのフルカラー グループに相当するものを再描画することに収束します。これは、最適な再配分戦略と一致します。
