 ## 問題の理解

 2 つのターゲット文字列が与えられ、1 つは最初の画面に表示される必要があり、もう 1 つは 2 番目の画面に表示される必要があります。 どちらの画面も空から始まります。 毎秒、選択した 1 つの画面に 1 つの大文字を追加することも、一方の画面のコンテンツ全体をもう一方の画面にコピーして、そこにあったものを置き換えることもできます。 

タスクは、画面 1 が文字列と等しい最終構成に到達することです。`s`と画面の 2 が文字列に等しい`t`、最小限の操作を使用します。 

重要な点は、コピーは増分ではなく、常にコピー先全体を上書きするということです。 このため、同じプレフィックスを別の画面で再度再構築するのではなく、ある画面ですでに行われた作業を「再利用」することが有益な場合を判断するという問題が生じます。 

制約は小さく、両方の文字列の長さは 100 までです。これにより、多項式時間を超える大規模な最適化の必要性が即座に排除されます。 O(n^3) または O(n^2) に関する解決策は完全に安全ですが、問題の構造は、共有プレフィックスに基づいたより直接的な O(n^2) または O(n) の定式化が存在することを強く示唆しています。 

1 つの文字列が空であるか、両方の文字列が同一である場合、微妙なエッジ ケースが発生します。 もう 1 つは、最初に 1 つの文字列を完全に構築してから、続行する前にそれをコピーすることが最善の戦略である場合です。これは、両方を独立して構築するという観点だけを考えると明らかではありません。 

たとえば、次の場合`s = "A"`そして`t = "ABCD"`両方を別々に構築するのは明らかに最適ではありません。 代わりに、共有構造を作成した後のコピーを利用したいと考えています。 逆に、もし`s`そして`t`プレフィックスをまったく共有しないため、コピーはほとんど役に立ちません。

 ## アルゴリズムのチュートリアル

 2 つの画面間で共有構造を複製する最適な瞬間を選択するという問題を再構成します。 

1. 最長の共通プレフィックス長を計算します。`k`間`s`そして`t`。 これは、競合せずに共有できる最初の文字の最大数です。不一致があると、その時点でコピーの有用性が損なわれるためです。 このステップでは、コピーによって実際に労力を削減できる唯一の領域を特定します。 
2. この共有プレフィックスを構築することを検討してください。 少なくとも必要です`k`空から始めるため、1 つの画面上でこれらの文字を構築するための入力操作。 
3. 最初の画面にこのプレフィックスが含まれたら、2 番目の画面へのコピー操作を実行します。 これにより、両方の画面が確実に長さに合わせて配置されます。`k`。 
4. この時点から、`s`（から`k`以降) は画面 1 にのみ入力する必要があり、接尾辞の`t`画面 2 にのみ入力する必要があります。 再度コピーしても既に正しいプレフィックスが上書きされるだけであるため、これらの操作は独立しています。 
5. 総費用は次のようになります。`k`共有プレフィックスの入力操作、コピー 1 つ、および`(len(s) - k)`仕上げ用`s`、プラス`(len(t) - k)`仕上げ用`t`。 

したがって、最終的な答えは次のようになります。`len(s) + len(t) - k + 1`。 

### なぜ効果があるのか

 正しさは、コピーの有益な使用は、両方の画面に同一のコンテンツが含まれている状態から行われなければならないという事実にかかっています。 コピーすると完全に上書きされるため、プレフィックスではない部分的な重複は保持できません。 したがって、再利用可能な唯一の構造は共通のプレフィックスです。 分岐点よりも前にコピーしようとする戦略では、すぐに間違った文字が導入され、潜在的な利益を支配する再作業が必要になります。 これにより、すべての最適な戦略が単一の同期プレフィックス長を選択することと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    
    k = 0
    for i in range(min(len(s), len(t))):
        if s[i] == t[i]:
            k += 1
        else:
            break
    
    ans = len(s) + len(t) - k + 1
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、最初の不一致が見つかるまで両方の文字列をスキャンして、最長の共通プレフィックスを直接計算します。 これにより、動的プログラミングやシミュレーションが回避されます。 

よくある落とし穴は、単一コピー操作のコストを忘れることです。これは、両方の文字列が空でない場合に常にカウントする必要があります。 もう 1 つの微妙な点は、プレフィックスの比較が最初の不一致ですぐに停止するようにすることです。 継続すると、共有構造を誤って過大評価することになります。

 次のような同一の文字列の場合`s = t = "AAAA"`、アルゴリズムは次のことを見つけます。`k = 4`、そして答えは次のようになります`4 + 4 - 4 + 1 = 5`。 これは、文字列を 1 回入力して 1 回コピーすることに相当し、作業の重複を避けます。
