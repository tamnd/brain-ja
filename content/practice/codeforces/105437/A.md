 ## 解決策
 ## 問題の理解

 1 枚のシートが与えられ、それを全長の直線カットを繰り返し使用して分割します。 すべてのカットは、現在のシート全体で左から右に進むか、現在のシート全体で上から下に進みます。 重要な詳細は、カットが常にシート全体に及ぶため、交差する既存のすべての部分をスライスすることです。 

一連の水平および垂直のカットを実行すると、シートは長方形のピースのグリッドになります。 問題は、結果として得られるピースの数が正確に同じになるように、必要な総カット数がどれだけ少ないかということです。$n$。 

入力は単一の整数を与えます$n$そして、最終的なピース数が次と等しくなるように、必要なフルシートカットの最小数を出力する必要があります。$n$。 

制約$n \le 10^6$カットシーケンスをシミュレートしたり、構成を検索しようとするものは直ちに除外されます。 グリッドを分割するすべての方法のうちのほんの一部を探索するアプローチは、カットの数に応じて組み合わせで増加する可能性のあるカット分布の数が増えるため、爆発してしまいます。 

微妙な点は、カットごとに、現在の状態に応じてピースの数が単なる加算ではなく乗算的に増加することです。 これが、「到達するまで分割するだけ」という素朴な推論を生み出す原因です。$n$「信頼できない。」

 いくつかの特殊なケースは、何が誤解されやすいかを明確にするのに役立ちます。 もし$n = 2$1 回のカットで十分です。1 回の水平方向または垂直方向のカットで、正確に 2 つの部分が得られます。 もし$n = 3$、たとえば、縦に 2 つのカットを 3 つのストリップに分割するなど、2 つのカットで十分です。 もし$n = 100$、対称構造が存在し、両方向に沿って繰り返しカットすると、合計 20 のカットを使用して 10 x 10 のグリッドが生成されます。 

よくある間違いは、貪欲にカットを追加し、ピースの数を常に線形に制御できると仮定することです。 両方の方向が使用されると、すべての新しいカットが既存のセグメントにまたがって増殖するため、これは失敗します。 

## アプローチ

 直接推論しようとすると、グリッドを維持するという観点から考えることができます。 Suppose we make$h$水平方向のカットと$v$縦のカット。 水平方向のカットごとに水平方向のストリップの数が 1 つずつ増加するため、すべての水平方向のカットが完了すると、次のようになります。$h+1$行。 同様に、$v+1$垂直カットからの柱。 すべての行がすべての列と交差するため、ピースの合計数は次のようになります。$(h+1)(v+1)$。 

これにより、問題が動的切断プロセスから純粋な因数分解の問題に縮小されます。$n$それぞれ少なくとも 1 の 2 つの正の整数の積として、最小化します。$(h+v)$どこ$h+1$そして$v+1$それらの要因です。 

させて$a = h+1$そして$b = v+1$。 それから$ab = n$となり、カット数は となります。$h+v = a+b-2$。 したがって、タスクは次の因子ペアを見つけることになります。$n$それは最小限に抑えます$a+b$。 

強引なアイデアは、すべてのペアを試すことです$a, b$そのような$a \cdot b = n$、計算する$a+b$、そして最小限のものを取ります。 これは正しいです。なぜなら、有効な切断戦略はすべて、次の因数分解に正確に対応しているからです。$n$。 問題はパフォーマンスです。次の値までのすべての約数をチェックする必要があります。$n$費用がかかるだろう$O(n)$が遅すぎる$10^6$。 ただし、約数を確認するだけで済みます。$\sqrt{n}$因数のペアは平方根を中心にミラーリングされるためです。 

重要な洞察は、最適なソリューションはバランスの取れた要素を好むということです。 固定積の場合、因子が可能な限り近い場合に合計が最小化されるため、可能な約数をスキャンするだけで済みます。$\sqrt{n}$。

 ## アルゴリズムのチュートリアル

 1. すべての整数を反復処理します。$i$1から$\lfloor \sqrt{n} \rfloor$。 平方根までしか考慮しません。これより大きい係数は存在しないからです。$\sqrt{n}$より小さな範囲ですでに見られる補完的な要因があります。 
2. それぞれについて$i$、どうかを確認してください$i$分割する$n$。 そうでない場合は、有効なグリッド次元を形成できないため、次の候補に進みます。 
3. もし$i$分割する$n$、ペアの因数を計算します$j = n / i$。 これにより有効な分解が得られます$n = i \cdot j$、次のグリッドに対応します。$i$行と$j$列 (またはその逆)。 
4. これらをカットに変換します。行には次のものが必要です。$i-1$水平方向のカットと柱が必要です$j-1$縦のカット。 この因子ペアの合計コストは次のとおりです。$i + j - 2$。 
5. の最小値を追跡します。$i + j - 2$すべての有効な因子ペアにわたって。 これは可能な限り最良の分割構成を表します。 
6. 見つかった最小コストを出力します。 

### なぜ効果があるのか

 水平方向および垂直方向のカットのすべてのシーケンスによってグリッドが作成されます。 行数は順序とは無関係に、水平方向のカットによって完全に決定され、列数は垂直方向のカットによって完全に決定されます。 したがって、最終的な構成はペアに一意に対応します。$(a, b)$と$ab = n$。 このようなペアはすべて除数スキャンを通じて列挙されるため、有効な構成を見逃すことはありません。 すべてのペアにわたるカットを最小限に抑えることで、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

best = float('inf')

i = 1
while i * i <= n:
    if n % i == 0:
        j = n // i
        best = min(best, i + j - 2)
    i += 1

print(best)
```コードは因子ペアの解釈を直接実装します。 ループオーバー$i$潜在的な行数を列挙しますが、$j$は対応する列数です。 有効な各除数のペアは、次を使用してカット カウントに変換されます。$i + j - 2$、これは、ピースをカットに変換するために、次元ごとに 1 つのカットを減算することによって得られます。 

微妙な詳細が初期化中です`best`すべての有効な因子のペアが適切に考慮されるように、無限大まで。 もう 1 つの重要な点は、整数の除算は割り切れる可能性を確認した後でのみ使用することです。これにより、不正確なペアが回避されます。

 ## 特殊なケース

 のために$n = 2$、唯一の因子ペアは$1 \cdot 2$。 アルゴリズムチェック$i = 1$、見つけます$j = 2$、そして計算します$1 + 2 - 2 = 1$。 これは、2 つの部分に分割するために必要な 1 つのカットと一致します。 

次のような素数の場合$n = 3$または近くの大きな素数$10^6$、1 以外の約数は存在しません。 ループは次の場合にのみトリガーされます。$i = 1$、1行の構成を強制し、$n$列。 計算結果は次のようになります$n - 1$これは、すべてのカットを一方向に積み重ねることに対応し、バランスの取れたグリッドを形成することが不可能であることと一致します。 

次のような完全な正方形の場合$n = 100$、除数$i = 10$対称的な構成を生成します。 アルゴリズムは両方を評価します$10 \times 10$および他の非対称ペアもありますが、対称ペアでは最小化されます。$i + j - 2$これにより、除数の検索によって最適なバランス ポイントが正しく取得されたことが確認されます。
