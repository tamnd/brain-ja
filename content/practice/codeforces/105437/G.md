 ## 解決策
 ## 問題の理解

 都市内の既存の店舗の場所を表す、端点 0 と 10^9 を含む数直線上の一連の固定点が与えられます。 これらのすでに占有されている位置の間に、現在空の整数座標に最大 m 個の追加ストアを挿入することができます。 制約は、2 つの店舗が同じ座標を占有することはできないということです。 

すべての店舗が配置されたら、店舗の位置のソートされたリストを見て、連続する店舗のすべてのペアを検討します。 このような各ペアはセグメントを形成し、そのセグメントの長さが隣接する 2 つの店舗間の距離になります。 目標は、これらの隣接距離の最大値ができるだけ小さくなるように新しい店舗を配置することです。 

これは基本的に間隔の最適化の問題です。総距離や平均ギャップを最小化しようとしているのではなく、追加のポイントを挿入した後の最悪のギャップだけを最小化しようとしているのです。 

この制約では、最大 200,000 の既存ストアと 200,000 の追加ストアが許可されるため、挿入を直接シミュレートしたりギャップを繰り返し調整しようとしたソリューションは遅すぎます。 すべてのギャップに対する二次アプローチや、各挿入を個別にシミュレートする優先度構造の貪欲な更新の繰り返しは、O((n+m) log n) かそれ以上のリスクを伴いますが、これは境界線ではありますが、それでも不要です。 重要な要件は、すべての挿入を 1 つずつではなくまとめて推論することです。 

貪欲な直感が間違って適用されると、微妙な失敗例が現れます。 大きなギャップが 1 つと、小さなギャップがいくつかあるとします。 単純な戦略では常に最大の現在のギャップに繰り返し挿入する可能性がありますが、ギャップが分割されるときにギャップがどのように非線形に縮小するかを正しくモデル化しないと、各セグメントが受け取るべきポイント数について誤った決定を下す可能性があります。 

たとえば、サイズ 10 で m = 1 のギャップがある場合、答えは 9 ではなく 5 です。代わりに、サイズ 10 で m = 1 のギャップが 2 つある場合、最適な配置は、個別の局所的な改善ではなく、全体的な比較に依存します。 これは、各ギャップは、貪欲に段階的に修正するものとしてではなく、それに割り当てられるポイントの数の関数として推論する必要があることを示しています。 

## アプローチ

 最初の強引なアイデアは、ストアを 1 つずつ追加するプロセスをシミュレートすることです。 各ステップで、隣接するすべてのギャップを計算し、最大のものを選択し、中央にストアを挿入して分割し、これを m 回繰り返します。 挿入ごとに、すべてのギャップをスキャンするか、ギャップの優先キューを維持する必要があります。 ヒープがあっても、m 回の挿入ごとに対数的な時間がかかり、分割ごとにセグメント長を慎重に再計算する必要があります。 これにより、O((n + m) log n) に関する複雑さが生じますが、これはすでに厳しいものであり、さらに重要なことに、最適な構成はセグメントごとの最終カウントのみに依存する一方で、問題を順次として扱うため、概念的には依然として非効率的です。 

重要な観察は、連続する店舗間の各初期ギャップは、その中に配置される新しい店舗の数を決定すると、独立して進化するということです。 セグメントの長さが g で、その中に k 個の新しいストアを配置すると、セグメントは k+1 個のサブセグメントに分割されます。 可能な限り最良の配置は等間隔であり、その結果得られるサブセグメントの最大長は、g の上限を k+1 で割ったものになります。 これにより問題が切り離されます。正確な位置を決定する代わりに、各ギャップが受け取るインサートの数だけを決定します。

この構造は視点の逆転を示唆しています。 m 個のストアを分散して結果の最大ギャップをチェックする代わりに、最大許容ギャップ L の候補を推測し、すべての最終的な隣接距離が最大でも L であることを保証できるかどうかを尋ねます。元のギャップ g ごとに、サブギャップが L を超えないようにするために必要な新しいポイントの数を計算します。 g が大きすぎる場合は、十分な数の部分に分割する必要があり、この要件はセグメントごとに独立して計算できます。 これらの要件を合計すると、m 店舗で十分かどうかが分かります。 

これにより、問題は L に関する単調な実現可能性チェックに変換され、二分探索を使用して解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シーケンシャル挿入シミュレーション | O((n + m) log n) | O(n) | 遅すぎて不必要 |
 | ギャップ実現可能性のある二分探索 | O(n log 1e9) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 既存の店舗の位置を並べ替えます。 これにより、隣接するペアのみが答えに影響を与えるため、すべてのギャップが意味のある順序で連続した要素間に存在することが保証されます。 
2. 連続するストア間のすべてのギャップを計算します。 各ギャップは、新しいストアを受け取ることができる独立した間隔です。 
3. 候補の最大距離 L が達成可能かどうかをチェックする関数を定義します。 この関数は、ギャップが L を超えないようにするために必要な追加ストアの数を決定します。 
4. 長さ g の各ギャップについて、各セグメントの長さが最大 L になるように分割する必要があるセグメントの数を計算します。必要なセグメント数は ceil(g / L) です。これは、そのギャップ内に ceil(g / L) - 1 個の新しいストアが必要であることを意味します。 これは、k 個の挿入ポイントが k+1 個のセグメントを作成するという事実から来ています。 
5. すべてのギャップにわたるこれらの必要な挿入を合計します。 合計が m 以下の場合、L は実行可能です。 
6. 1 から 10^9 まで L に対して二分探索を実行します。 中間点ごとに、実現可能性チェックを実行します。 可能であれば、より小さい値を試してください。 それ以外の場合は L を増やします。 

二分探索が機能する理由は、実現可能性が L において単調であるためです。最大ギャップ L が達成可能であれば、制約が緩和され、必要な挿入数が決して増加しないため、より大きな値も達成可能です。 

### なぜ効果があるのか

 目標の最大セグメント長 L を固定すると、各ギャップは独立して動作します。k 点を均等以外の場所に分散しても最大セグメント長を ceil(g / (k+1)) より小さくできないため、単一のギャップを分割する貪欲な方法が常に最適です。 したがって、実現可能性チェックでは、ギャップごとに必要な挿入の最小数が正確に取得されます。 この要件はギャップ全体で加法的であり、L では単調であるため、二分探索は実行可能な最小の最大距離を正確に特定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def required_stores(g, L):
    if g <= L:
        return 0
    return (g - 1) // L

def can(L, gaps, m):
    need = 0
    for g in gaps:
        need += required_stores(g, L)
        if need > m:
            return False
    return True

n, m = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

gaps = []
for i in range(n - 1):
    gaps.append(a[i + 1] - a[i])

lo, hi = 1, 10**9
ans = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid, gaps, m):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```並べ替えステップでは、すべての意味のある距離が連続した差分としてキャプチャされることが保証されます。 実現可能性関数は、ギャップごとの分割ロジックをエンコードし、各ギャップが必要な数の挿入ストアに独立して寄与します。 式 (g - 1) // L は、浮動小数点演算を行わずに ceil(g / L) - 1 を計算するコンパクトな方法です。 

二分探索では、提案された最大距離が最大 m 回の挿入でグローバルに適用できるかどうかを繰り返しテストすることで、答えを絞り込みます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    gaps = [a[i+1] - a[i] for i in range(n - 1)]

    def need(g, L):
        if g <= L:
            return 0
        return (g - 1) // L

    def can(L):
        return sum(need(g, L) for g in gaps) <= m

    lo, hi = 1, 10**9
    ans = hi
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return str(ans)

 ## 特殊なケース

 1 つのエッジ ケースは、支配的なギャップに対して m が小さすぎるため、有益な分割が不可能な場合に発生します。 入力用`0 1000000000`m = 0 の場合、アルゴリズムはサイズ 10^9 の 1 つのギャップを生成し、それより小さい L については実現可能性チェックが失敗するため、二分探索は直ちにその値に収束します。 

もう 1 つのケースは、複数の大きなギャップが限られた挿入をめぐって競合する場合です。 たとえば、ギャップがある場合、`[100, 100, 100]`m = 1 の場合、実行可能性チェックでは、必要なすべての挿入がバイナリ項で最初に最大の削減ターゲットに正しく帰属します。 二分探索により、どのギャップを改善するかを決定する必要がなくなりました。 代わりに、一様な限界が達成可能かどうかを検証します。 

最後の微妙なケースは、g が L で正確に割り切れる場合です。`(g - 1) // L`正確な倍数が必要なストアを過大にカウントしないようにします。 たとえば、g = 10 および L = 2 の場合、4 つの挿入が必要で、サイズがちょうど 2 のセグメントが生成されます。これにより、単純な場合に発生する 1 つずつのインフレが回避されます。`ceil(g / L) - 1`浮動小数点演算を使用した実装。
