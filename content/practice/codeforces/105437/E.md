 ## 解決策
 ## 問題の理解

 多くの独立したクエリが与えられます。 各クエリはインデックスのペアを指定します$n$そして$k$、三角テーブルから値を計算するように求められます。$C$それは非標準的な方法で生成されます。 

テーブルは行ごとに構築されます。 各行$n$から始まる$C[n][0] = 1$、で終わります$C[n][n] = 1$、すべての内部値は、同じ行と前の行、具体的には同じ行の左隣と斜め左上のエントリからの値を使用して形成されます。 

これは、各値がそのすぐ上の 2 つのエントリに依存する通常の二項係数テーブルとは異なります。 ここでは、情報は行内でも水平方向に流れ、三角形全体の構造が変化します。 

タスクは計算することです$C[n_i][k_i]$まで$10^5$クエリ、$n_i$まで$10^5$。 各値は大きい可能性があるため、結果はモジュロで返される必要があります。$10^9 + 7$。 

この制約は、テーブルを明示的に構築する解決策が不可能であることを意味します。 完全な DP テーブルには次のものが必要です$O(n^2)$時間と記憶は、実現可能な範囲をはるかに超えています。$n = 10^5$。 単一行を単純に計算するだけでも、$O(n)$、そして多くのクエリに対してそれを行うと、やはり遅すぎます。 

さらに微妙な問題が再発自体に現れます。 繰り返しでは両方を使用するため、$C[n][k-1]$そして$C[n-1][k-1]$、値は行間で繰り返し伝播します。 これは、パスカルの三角形からの素朴な直観が当てはまらず、解釈における小さな間違いがまったく異なる順序につながることを意味します。 

典型的な落とし穴は、これが単なる二項係数であると仮定することです。 たとえば、$n = 4$、$k = 2$、正しい二項係数は次のとおりです。$6$、しかし実際の再発は$4$。 もう 1 つのよくある誤解は、依存しているものだけを想定していることです。$k$ただし、実際には構造を慎重に導き出す必要があります。 

## アプローチ

 ブルートフォースアプローチは、テーブル全体を最大値まで構築することです。$n$指定された繰り返しを使用するクエリで見られます。 行ごとに$n$、すべてを計算します$C[n][k]$から$k = 1$に$n - 1$、質問に直接答えます。 これは簡単であり、定義に忠実です。 

ただし、このアプローチでは多数の操作が実行されます。 外側のループは次まで実行されます。$10^5$、内側のループも次まで実行されます。$10^5$、周りにつながる$10^{10}$最悪の場合はアップデートも。 各更新は一定時間ですが、その規模は依然として実行可能な限界をはるかに超えています。 

重要な洞察は、値が行間でどのように伝播するかを観察することで得られます。 繰り返しを 1 回展開すると、非表示のプレフィックス構造が表示されます。$$C[n][k] = C[n][k-1] + C[n-1][k-1]$$同じ行内で最初の項を繰り返し展開すると、次のようになります。$$C[n][k] = C[n][0] + \sum_{j=1}^{k} C[n-1][j-1]$$以来$C[n][0] = 1$、これは次のようになります。$$C[n][k] = 1 + \sum_{i=0}^{k-1} C[n-1][i]$$これは、各エントリが前の行のプレフィックスの合計によって決定されることを示しています。 その構造は、二次元プロセスを単純なパターンに崩壊させるのに十分な強度を持っています。 いくつかの行を計算すると、安定化が明らかになります。$k$、 一度$n$十分に大きくなると、値は変化しなくなります。 

小さなケースを計算すると、次のことがわかります。 

行 2:$1, 2, 1$行 3:$1, 2, 4, 1$行 4:$1, 2, 4, 8, 1$5行目:$1, 2, 4, 8, 16, 1$すべて有効$k < n$、値は次のようになります$2^k$、独立して$n$。 最後の要素のみ$C[n][n]$に固定されたままです$1$。 

これにより、各クエリが直接的な電力計算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP テーブル |$O(n^2)$|$O(n^2)$| 遅すぎる |
 | 観測された式$2^k$|$O(t \log MOD)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 パターンが特定されると、計算は直接の評価問題になります。 

1. すべてのクエリを読む$n_i, k_i$。 の値$n_i$確認する以外は計算に影響しなくなりました$k_i < n_i$。 
2. 可能な最大値まで 2 の累乗を事前計算します。$k$べき乗剰余演算または反復 2 倍算を使用します。 これにより、クエリごとのべき乗の再計算が回避されます。 
3. 各クエリに対して、出力$2^{k_i} \bmod (10^9 + 7)$。 

これが機能する理由は、繰り返しによってすべての行が前の行の累積和のように動作し、一定の初期構造の累積合計が繰り返されると指数関数的な増加が生じるためです。$k$依存を解消しながら$n$最初の数行の後。 

### なぜ効果があるのか

 反復では、各行の先頭に 1 という固定境界条件を使用して、各行を前の行の接頭辞の合計に変換します。 この繰り返しの接頭辞により、値が増加するたびに値が 2 倍になります。$k$、独立して$n$、 一度$n$その柱を支えるのに十分な大きさです。 その結果、テーブルは列全体で単純な指数シーケンスに安定し、行インデックスは最後の境界要素にのみ影響します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(base, exp):
    result = 1
    while exp:
        if exp & 1:
            result = result * base % MOD
        base = base * base % MOD
        exp >>= 1
    return result

t = int(input())
n = list(map(int, input().split()))
k = list(map(int, input().split()))

for i in range(t):
    print(modpow(2, k[i]))
```この解決策は完全に高速累乗に依存しています。 の配列$n$そして$k$一度だけ読み取られます$k$導出された式により依存性が排除されるため、計算に使用されます。$n$すべての有効な入力に対して。 

べき乗モジュラー関数は、再帰オーバーヘッドを回避し、クエリごとの対数実行時間を確保するために反復的に実装されます。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def modpow(base, exp):
    result = 1
    while exp:
        if exp & 1:
            result = result * base % MOD
        base = base * base % MOD
        exp >>= 1
    return result

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    n = list(map(int, input().split()))
    k = list(map(int, input().split()))

    out = []
    for i in range(t):
        out.append(str(modpow(2, k[i])))
    return "\n".join(out)

# provided samples
assert run("3\n2 5 5\n1 2 3\n") == "2\n4\n8"

# minimum size
assert run("1\n2\n1\n") == "2"

# small varied case
assert run("3\n3 4 5\n1 2 4\n") == "2\n4\n16"

# boundary k close to max
assert run("2\n100000 100000\n99999 1\n") == f"{pow(2,99999,MOD)}\n2"

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$k = 1$。 再発は依然として発生します$C[n][1] = 2$すべて有効な$n \ge 2$、一致します$2^1$。 DP を直接実装すると、この列が誤って初期化されたりスキップされたりする可能性がありますが、派生式はそれを均一に処理します。 

もう 1 つのエッジケースは次のような場合です$k = n - 1$。 境界付近であっても値は追従します$2^{n-1}$。 単純な行ベースの DP は境界伝播を誤って上書きしたり、誤って処理したりする可能性がありますが、閉じた形式は一貫性を保ちます。 

最後に、大きいものについては、$k$、指数関数的な増加は完全にべき乗剰余演算によって処理されるため、オーバーフローや中間配列の爆発のリスクはありません。
