 ## 解決策
 ## 問題の理解

 さまざまなサイズの配列を構築しています$n$、最初はゼロで埋められます。 加工いたします$q$操作を一つずつ。 各操作により 2 つの異なるインデックスが得られます$x_i$そして$y_i$。 各操作では、これら 2 つの位置のうち 1 つを正確に選択し、その選択した位置を 1 つずつ増加または減少させる必要があります。 

すべてを推進する制約は、単一の操作の後で配列要素が負になることが許されないということです。 したがって、「-1」を適用するときは常に、選択したインデックスが現在少なくとも 1 の値を持っていることを確認する必要があります。 すべてのクエリの後、最後に、配列の合計ができるだけ小さくなるようにします。 

出力は、最終的な配列だけではなく、クエリごとに 1 つずつ、決定の完全なシーケンスであり、使用したエンドポイントとエンドポイントを追加または減算したかの両方を指定します。 

重要な問題は、選択はローカルであるが、制約はグローバルであるということです。 「-1」ごとに合計が減少するため、最終的な目的には適していますが、選択した位置の値が不足すると、将来の「-1」操作が不可能になる可能性があります。 

制約$n, q \le 3 \cdot 10^5$これは、どのような解もほぼ線形または線形に近いものでなければならないことを意味します。 ステップごとにグローバルにシミュレーションまたは再最適化する二次戦略は機能しません。 私たちは決断を下さなければなりません$O(1)$または$O(\log n)$クエリごとに。 

単純な落とし穴は、計画を立てずに可能な限り常に「-1」を選択することです。 頻繁に再利用されるペアの両方のエンドポイントを使い果たし、後で不必要な追加が強制され、最終的な合計が増加する可能性があるため、これは失敗する可能性があります。 

2 番目の微妙な障害モードは、常に固定エンドポイントを選択することです (たとえば、常に$x_i$) ロジックを簡素化します。 これにより、1 つのインデックスに過剰な負荷が蓄積され、将来の「-1」操作を満たすことができなくなり、後で追加の「+1」操作が強制されるという不均衡が発生する可能性があります。 

中心的な難しさは、「-1」を選択するたびに安全で将来の実現可能性を損なうことがないように「削除」を分散することです。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての選択シーケンスをシミュレートします。 各クエリでは、最大 4 つの選択肢があります。$x_i$または$y_i$、選択します$+1$または$-1$。 単純な検索では、各ステップ後の非負性を尊重しながら、最終的な合計を最小化しようとします。 

これにより、すぐに指数関数的な分岐が発生します。$4^q$、たとえ小規模であっても完全に実行不可能です。$q$。 状態空間は$O(q^n)$事実上。 

重要な観察は、「決してゼロを下回らない」という制約がローカルのユニットの可用性にのみ依存し、各「-1」は同じ位置で以前に作成された「+1」を消費する必要があるということです。 したがって、各インデックスはリソース プールのように動作します。 

安全に割り当てることができる「-1」演算の数を最大化したいと考えています。 各クエリでは 2 つのインデックスのうちの 1 つを正確に操作する必要があるため、本質的には一連の署名付き操作をエッジのエンドポイントに分散することになります。 

これはグラフ プロセスになります。各クエリはエッジであり、それを符号付きの 1 つのエンドポイントに割り当てます。 制約は、ノードに割り当てられた「-1」の数が現在の累積値を決して超えないことです。 

それについて考えるのに役立つ方法は、貪欲なバランスを取ることです。 可能な限り「-1」を割り当てたいと考えていますが、どのノードも「過剰描画」されないようにする必要があります。 これは、ノードごとの「利用可能な容量」の概念を追跡し、エンドポイント間で責任を動的にシフトすることを示唆しています。 

最適な戦略は、各ノードを現在の残高があるものとして扱い、余剰があるノードには常に「-1」を割り当てることを優先しながら、ノードが後でマイナスの領域に追い込まれるような状況を決して生み出さないようにすることです。 これは、ペアリング ロジックを介して以前の暗黙的な割り当てを調整する、ローカル修正による貪欲なアプローチにつながります。 

私たちは、ノード全体で保留中の黒字/赤字の動作を追跡する構造を維持し、グローバルな実現可能性を維持する方法で各クエリを指向していることを保証します。 これは、現在「-1 を吸収する可能性」が高いエンドポイントを優先する貪欲な選択を使用して実装できます。 

各クエリは 1 回処理され、各決定ではローカル状態の更新のみが使用されるため、結果として得られるアルゴリズムは線形時間になります。

 ## アルゴリズムのチュートリアル

 私たちは単純な考えを維持しています。各ノードには現在の残高があり、最初はゼロです。 私たちは「-」操作を積極的に使用するよう努めますが、それは安全な場合に限ります。 

また、後でデクリメントする必要があるノードに十分な残高がなくなった状態でスタックすることを回避する方法も必要です。 秘訣は、常に柔軟性を保つ方法で操作を割り当てることです。すでにバランスが高いノードでは「-」を使用することを好みます。 

### ステップ

 1. 配列を初期化する`a`サイズの$n$すべてゼロで、ノードの現在の値を表します。 
2. クエリを 1 つずつ処理します。 クエリごとに$(x_i, y_i)$、現在の値を検査します。$a[x_i]$そして$a[y_i]$。 
3. 残高を比較して、どのエンドポイントが操作を受信するかを決定します。 1 つのエンドポイントの現在値が大きい場合は、非負性を侵害せずに値を減らすほうが安全であるため、そのエンドポイントを「-」操作に優先します。 
4. 符号を決めます。 選択したエンドポイントに「-」を割り当てると、その値が減ります。 それ以外の場合は、「+」を割り当てて増分します。 
5. 選択したエンドポイントにアップデートをすぐに適用します。 

微妙な点は、将来のクエリを明示的に計画していないことですが、貪欲なルールにより、後で余裕のないノードから「-」容量を消費することがないことが保証されます。 頻繁に選択されるすべてのノードが将来の「-」をサポートするのに十分な「+」操作を蓄積するため、システムは自然にバランスが取れます。 

### なぜ効果があるのか

 不変条件は、すべてのノードの値が常に、そのノードに割り当てられた一致しない「+」演算の数を表すということです。 「-」を適用するたびに、その一致しないプールが減ります。 貪欲ルールにより、利用可能なプールがゼロのノードに「-」が割り当てられることはありません。 すべての割り当てで一貫してプールが増減し、各操作が 1 つのノードにのみアクセスするため、実現可能性は段階的に維持されます。 過去の決定を再考する必要のある操作は存在しないため、プロセス全体を通じて構築は一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = [0] * (n + 1)
    
    out = []
    
    for _ in range(q):
        x, y = map(int, input().split())
        
        # choose endpoint with larger current value
        if a[x] >= a[y]:
            p = x
        else:
            p = y
        
        # greedy: prefer subtraction if possible
        if a[p] > 0:
            a[p] -= 1
            out.append("xy".replace("x", "x" if p == x else "y") + "-")
        else:
            a[p] += 1
            out.append("xy".replace("x", "x" if p == x else "y") + "+")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はバランス配列を直接維持します。 クエリごとに、エンドポイント値を比較し、現在の残高が大きい方を選択します。 これにより、最も安全な場所での削減が保証されます。 選択したノードのバランスが正の場合は「-」を適用し、そうでない場合は「+」を適用する必要があります。 

出力構造は、選択したかどうかをエンコードします。$x$または$y$、そして増加したのか減少したのか。 唯一の微妙な点は、選択したエンドポイントと印刷される文字の間の一貫性を確保することです。

 ## 特殊なケース

 のような最小限のケース$n=2, q=1$アルゴリズムが 2 つの等しい状態の間で正しく選択することを保証します。 貪欲ルールは 1 つのエンドポイントを選択し、どちらもゼロから始まるため、制約に違反することなく「+」または「-」を安全に適用します。 

多くのクエリなどの繰り返しエッジ$(1,2)$アルゴリズムがバイアスを回避するかどうかをテストします。 各ステップでは、同じノード上で蓄積と減少が交互に行われ、バランス配列により、ゼロを下回る減算が行われないことが保証されます。 

サイクル状のシーケンスにより、ローカルでの貪欲な決定によって 1 つのノードが過剰な負債に陥ることがなくなります。 各ノードが均等に表示されるため、バランスは分散されたままとなり、不可能な負の状態に強制されるノードはありません。
