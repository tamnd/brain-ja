 ## 解決策
 ## 問題の理解

 各テスト ケースでは、プログラミング コンテスト用の簡単なケータリング プランについて説明します。 がある$n$出場者総計。 その通り$x$そのうちの1人はグリルチキンバーガーセットを選び、残りは$n - x$スパイシーチキンバーガーセットを選択。 激辛セットの料金は$a$、焼きセットの値段は、$b$。 課題は、出場者全員の食事の準備にかかる総コストを計算することです。 

この構造は純粋に加算的です。すべての出場者は、選択に応じて 1 つの固定コストを負担するため、総コストは、各カテゴリに該当する数を数え、対応する価格を乗じることによって決定されます。 

制約により、最大で次のことが許可されます。$10^4$テスト ケース。各テスト ケースは最大で次の値を使用します。$10^4$。 これは、どのソリューションもテスト ケースごとに一定時間で実行する必要があることを直ちに意味します。 テスト ケースごとにリニア スキャンを実行する場合でも、不要なオーバーヘッドは発生しますが、それでも技術的には安全です。 ただし、ネストされたループを含むものはすべて$n$もしそうなら限界をはるかに超えているだろう$T$大きいです。 

この形式の問題における唯一の微妙な問題は、固定幅整数を使用する言語での整数オーバーフローですが、Python ではこれは問題になりません。 考えられるもう 1 つの間違いは、カウントを交換したり、どのグループがどの価格に対応するかを誤解したりすることです。 具体的な失敗例としては、$n = 5, x = 5, a = 10, b = 1$。 正しい答えは、$0 \cdot 10 + 5 \cdot 1 = 5$。 誤った実装は誤って適用される可能性があります$a$グリルグループへ、プロデュース$50$、これは明らかに間違っています。 

## アプローチ

 直接的なアプローチは、各出場者を個別にシミュレートすることです。 それぞれについて、$n$出場者がその中にあるかどうかを決定します。$x$グリルしたものとどちらかを加えます$a$または$b$現在の合計に。 これは問題の定義を正確に反映しているため機能します。 ただし、実行します$n$テストケースごとの操作により、$T \cdot n$最悪の場合の運用。 両方の値が最大の場合$10^4$、これは到達できます$10^8$このような単純な算術問題には不要な演算です。 

重要な観察は、個々の出場者の身元を知る必要がまったくないということです。 カウントだけが重要です。 それを正確に認識したら$x$人々が支払う$b$そしてまさに$n - x$人々が支払う$a$、問題全体が 1 つの式にまとめられます。 これにより、すべての反復が削除され、各テスト ケースが一定数の算術演算に減ります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$T$。 各テスト ケースは独立しているため、テスト ケース間で状態が引き継がれることはありません。 
2. テスト ケースごとに、整数を読み取ります。$n, x, a, b$。 これらによってコストの構成が完全に決まります。 
3. スパイシーセットの数を次のように計算します。$n - x$。 これはグリルグループの補完です。 
4. 総コストを次のように計算します。$(n - x) \cdot a + x \cdot b$。 これは、各グループの貢献を合計することから直接得られます。 
5. 次のテスト ケースに進む前に、テスト ケースの計算値をすぐに出力します。 

### なぜ効果があるのか

 このアルゴリズムは、総コストが独立した項目の線形合計であるという事実に基づいています。 各出場者は合計に 1 つの用語を入力します。その用語の値は、スパイシーまたはグリルの 2 つの分類にのみ依存します。 各クラスのカウントは固定されており、互いに素であるため、個々の合計を乗算に置き換えることで、正確な等価性が維持されます。 隠れた依存関係や順序付け効果は存在しないため、カウントへの集計によって情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, a, b = map(int, input().split())
        spicy = n - x
        total = spicy * a + x * b
        print(total)

if __name__ == "__main__":
    solve()
```ソリューションは各テスト ケースを読み取り、派生した式を直接適用します。 重要な実装の詳細は正しく計算することだけです$n - x$スパイシーなグループ向け。 Python では大きな整数がサポートされているため、乗算の順序は関係ありませんが、固定幅の整数言語では 64 ビット整数を使用する必要があります。

 ## 特殊なケース

 いつ$x = 0$、焼きセットを選ぶ人はいません。 式は次のようになります。$n \cdot a$。 アルゴリズムは計算します$n - x = n$、したがって、スパイシーなグループはすべての参加者を正しく吸収し、グリル用語は消えます。 

いつ$x = n$、みんな焼きセットを選びます。 辛さのカウントがゼロになり、合計が$n \cdot b$。 減算ステップにより、特別なケースを使用せずにスパイシーな寄与が正確にゼロになることが保証されます。 

いつ$n = 1$、次のいずれかであるため、式は引き続き一貫して動作します。$x = 0$または$x = 1$、そしてちょうど 1 つの項が寄与します。 このアルゴリズムには分岐が必要ないため、エッジケースの条件が回避され、実装が均一に保たれます。
