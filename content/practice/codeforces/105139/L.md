 ## 解決策
 ## 問題の理解

 頂点が 1 より大きい整数であるグラフ上を移動します。任意の整数から$u$、他の整数に移動することもできます$v$、その移動のコストは$\mathrm{lcm}(u, v)$。 私たちには出発点が与えられています$a$そして終点$b$、 と$a \le b$で始まる一連の動きの最小総コストを見つけなければなりません。$a$そしてで終わります$b$。 

重要な特徴は、隣接する数字や幾何学的構造に制限されないことです。 1 より大きいすべての整数は他のすべての整数に直接接続されますが、エッジの重みは最小公倍数による算術構造に強く依存します。 

制約$b \le 10^7$そして最大$T \le 1000$テスト ケースは、すべての中間ノードまたはすべてのパスを試行するソリューションは不可能であることを意味します。 考えられるすべての中間整数をテスト ケースごとに 1 回繰り返すだけでも、すでに最大で次のことを意味します。$10^7$クエリごとの操作が大きすぎます。 

最も重要な構造上の制限は、2 つのエッジよりも長いパスは非常に疑わしいということです。 追加のステップごとに LCM 値に依存する非負のコストが追加されるため、両方の隣接エッジ コストを大幅に削減しない限り、最適なソリューションでは不要な中間頂点を回避する必要があります。 

微妙だが重要なエッジ ケースは、禁止値 1 から生じます。1 が許可されると、普遍的な低コストの仲介者として機能します。$\mathrm{lcm}(x,1)=x$、パスを簡単にします。 ただし、1は許可されていないため、「無料の橋」として使用することはできません。 これにより、特に次の場合に動作が完全に変わります。$\gcd(a,b)=1$ここで、1 を経由する自然なショートカットは、より単純なバリアントでは最適でした。 

## アプローチ

 直接的な総当たりアプローチでは、すべての整数がモデル化されます。$x \in [2, 10^7]$潜在的な中間ノードとして、最適なパスを計算します。$a$に$b$1 つまたは複数のホップを使用します。 パスの長さを最大 2 に制限しても、クエリごとに二次関数のような構造がすでに得られます。$\mathrm{lcm}(a,x) + \mathrm{lcm}(x,b)$みんなのために$x$、つまり$O(10^7)$テストケースごとに作業します。 

これでは遅すぎます$T=1000$。 平$10^8$に$10^{10}$全体的な操作は範囲外です。 

重要な観察は、LCM コストが割り算によって制御されるということです。 もし$x$～と要素を共有する$a$または$b$、 それから$\mathrm{lcm}(a,x)$または$\mathrm{lcm}(x,b)$乗算的に増加するのではなく、より大きな数に近い値に縮小します。 もし$x$は両方と互いに素であるため、両方のエッジが大きくなります。$\mathrm{lcm}(a,x)=ax$そして$\mathrm{lcm}(x,b)=bx$。 

これは、有用な中間ノードが少なくとも 1 つのエンドポイントとの強力な算術重複を持たなければならないことを直ちに意味します。 特に、考慮に値する候補は、次の素因数から構築された数値です。$a$または$b$, because only they can reduce one of the two LCM terms.

 The second structural simplification is that longer paths are never beneficial compared to a single intermediate node. もし私たちに道があったなら$a \to x \to y \to b$、その後交換します$x \to y$直接接続またはパスを折りたたむことによって、通常はオーバーラップが増加せず、コストが増加するだけです。 最適な構造はどちらかの直接エッジに崩壊します$a \to b$または 2 段階のパス$a \to x \to b$。 

したがって、問題は次のようになります。最小値を求めます。$\mathrm{lcm}(a,b)$そしてすべての価値観$\mathrm{lcm}(a,x) + \mathrm{lcm}(x,b)$ただし、慎重に制限された一連の候補者のみが対象です$x$。 重要な削減点は、次の約数を考慮すれば十分であるということです。$a$、の約数$b$、および素因数や低複合コネクタなどの小さな構造アンカー。$x$可分性構造の少なくとも 1 つの端点と一致する必要があります。 

これにより、検索スペースが折りたたまれます。$10^7$おおよそに$O(\sqrt{n})$因数分解後の数値ごと。

 ## アルゴリズムのチュートリアル

 各テスト ケースに対して候補となる中間ノードの小さなセットを計算し、それらを通る最適な 2 ステップ パスを評価します。 

1. 両方を因数分解する$a$そして$b$。 

これが必要なのは、有用な中間ノードが少なくとも 1 つのエンドポイントと素因数を共有する必要があるためです。 因数分解により、これらの構造的な構成要素に直接アクセスできるようになります。 
2. すべての約数を生成します。$a$とすべての約数$b$、1を除く。 

これらの約数は、LCM の一方の側を小さい値に縮小できるすべての数値を表します。 もし$x \mid a$、 それから$\mathrm{lcm}(a,x)=a$、そのエッジでの乗法的な増加が除去されます。 
3. 候補セットを作成する$C = \{a, b\} \cup \{\text{divisors of } a\} \cup \{\text{divisors of } b\}$。 

エンドポイントを含めることで、直接遷移と縮退 2 ステップ パスもテストできるようになります。 
4. あらゆる人にとって$x \in C$、コストを計算します$$\mathrm{lcm}(a,x) + \mathrm{lcm}(x,b)$$アイデンティティを利用して$\mathrm{lcm}(u,v)=u \cdot v / \gcd(u,v)$。 

さまざまな選択肢にわたって引き継がれる有用な状態がないため、各候補は独立してチェックされます。$x$。 
5. 直接コストも計算します$\mathrm{lcm}(a,b)$すべての評価値の最小値を取得します。 

これにより、中間ノードがパスを改善しない可能性がカバーされます。 

この制限の背後にある本質的な理由は、この除数構造の外側にある中間ノードは、2 つの LCM の少なくとも 1 つを乗法的に拡張することを強制し、これは除数が整列した候補と決して競合しないということです。 

### なぜ効果があるのか

 最適なパスの長さは最大でも 2 であると想定できます。より多くの中間頂点がある場合は、中間ノードが両方のエンドポイントとの共有可分性を高めない限り、LCM ベースのエッジ コストは追加の階層化による恩恵を受けないため、最適な 1 つの中間選択肢を超えてコストを増加させることなく、隣接するステップを繰り返しマージできます。 したがって、最適なソリューションは、直接エッジか、または約数に一致する戦略的に選択された単一の中間ノードである必要があります。$a$または$b$。 このようなアライメントは素因数構造によって完全に決定されるため、約数に制限するとすべての最適な候補が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def divisors(x):
    small = []
    large = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            small.append(i)
            if i * i != x:
                large.append(x // i)
        i += 1
    return small + large[::-1]

def solve():
    T = int(input())
    for _ in range(T):
        a, b = map(int, input().split())

        cand = set()

        for d in divisors(a):
            if d > 1:
                cand.add(d)
        for d in divisors(b):
            if d > 1:
                cand.add(d)

        cand.add(a)
        cand.add(b)

        def lcm(x, y):
            return x // math.gcd(x, y) * y

        ans = lcm(a, b)

        for x in cand:
            ans = min(ans, lcm(a, x) + lcm(x, b))

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、除数構造から厳密に中間候補を構築します。 除数ジェネレータにより、LCM 増加の片側を完全に排除できる数値のみをテストすることが保証されます。 LCM 関数は、オーバーフローを回避し、演算効率を維持するために gcd を通じて実装されます。 

メイン ループは各候補を個別に評価し、直接接続の場合を含む実行最小値を維持します。

 ## 特殊なケース

 いつ$a$そして$b$が互いに素である場合、少なくとも 1 つのエンドポイントとの共有要素を導入しない限り、アルゴリズムは中間ノードから恩恵を受けることはありません。 例えば、$a=3, b=4$最適なパスを強制的に通過させます$x=2$それ以外の場合は、約数の重複が存在しないためです。 候補の生成により、約数を通じて関連する場合には常に 2 が考慮されるようになります。$b$、正しさを保ちます。 

いつ$a$分割する$b$、多くの場合、直接パスが最適ですが、中間の約数は$a$場合によっては、より安価な 2 ステップのパスを生成することもできます。 すべての約数を列挙することにより、これらの候補が見逃されることがなくなり、アルゴリズムによってそれらが直接 LCM エッジと正しく比較されます。
