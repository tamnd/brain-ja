 ## 解決策
 ## 問題の理解

 数直線上に配置された複数の点のセットが与えられます。 各ステップで、任意の 2 つの既存の点を繰り返し選択し、それらを削除し、その中点を挿入します。 これは、ポイントが 1 つだけ残るまで続き、プロセスは停止します。 重要な点は、各ステップで可能なすべてのペアの中から点のペアが均一にランダムに選択されることです。 

タスクは、このプロセスをシミュレートすることではなく、最後に残った点の予想される最終位置を計算することです。 答えは有理数であることが保証されているため、次のようにモジュール形式で出力するように求められます。$p \cdot q^{-1} \bmod 998244353$、 どこ$\frac{p}{q}$縮小された形式の期待値です。 

入力サイズは最大です$n = 10^6$これにより、シミュレーションまたは状態ベースのマルコフ連鎖アプローチが即座に除外されます。 単一の演算でも点の数が 1 つ減少し、各演算にはペアごとの選択の再計算が含まれるため、単純なシミュレーションは最悪の場合でも少なくとも 2 次になります。 それは実現可能な限界をはるかに超えています。 代わりに、解決策はプロセスの構造的不変条件に依存する必要があります。 

微妙な点は、ランダム性がマージの順序にのみ適用され、マージの算術結果には適用されないことです。 これは、最終的な期待値が線形的にランダム性から独立している可能性があることを示唆することがよくあります。 もう 1 つの明白ではない問題は、答えがすべてのポイントに同時に依存するため、ローカル マージに関する貪欲な推論は機能しないことです。 

## アプローチ

 直接シミュレーションでは、複数の点セットを維持し、ランダムなペアを繰り返し選択し、それをそれらの中点に置き換えて続行します。 それぞれのマージは、$O(1)$ですが、ステップ数は$n-1$。 難しいのはランダム性です。各ステップで$\binom{k}{2}$したがって、遷移を列挙したり、すべてのシーケンスの平均を計算したりすると、指数関数的になります。$n$。 中間状態の分布についての推論ですら、すぐに手に負えなくなります。 

重要な観察は、中間点の演算が線形であるということです。 のマージを書くと$x_i$そして$x_j$として$(x_i + x_j)/2$の場合、すべての操作は入力のアフィン組み合わせになります。 期待値は線形であるため、各元のポイントが最終結果にどのように寄与するかを追跡できます。 

位置を追跡する代わりに、係数を追跡します。 最初は各ポイントが重みに寄与します$1$。 2点に係数がある場合$a_i$そして$a_j$が結合されると、新しい点が生成され、その係数は次のようになります。$(a_i + a_j)/2$、元の貢献に還元されて分配されます。 選択のランダム性は対称性に影響しません。すべての順序のないペアはすべての段階で同じ確率で存在するため、すべての点は交換可能です。 この対称性により、すべての元の点が最終結果に対して同一の期待寄与を持つようになります。 

最終点はすべての初期点の凸状の組み合わせであり、すべての係数の期待値が等しいため、各点が重みに寄与します。$1/n$期待して。 したがって、予想される最終位置は、すべての初期座標の単純な平均になります。 

これにより、問題全体がモジュラー算術平均の計算に集約されます。

 ## アルゴリズムのチュートリアル

 1. すべての入力値の合計を計算します。 これにより、マージが発生する前にすべてのポイントの合計質量が取得されます。 すべての変換は線形であるため、期待値を回復するには合計を追跡するだけで十分です。 
2. 合計に次の逆モジュラーを乗算します。$n$これはモジュラー算術で除算を実行し、すべての点にわたって寄与を均等に平均化することに対応します。 
3. 結果を予想される最終座標として出力します。 

### なぜ効果があるのか

 マージごとに 2 つの値が置き換えられます$x_i, x_j$と$(x_i + x_j)/2$。 このプロセスを帰納的に拡張すると、最終的な値は常に元の入力の加重平均になります。 重みはランダム マージ ツリーに依存しますが、ラベル付きリーフ上のすべてのバイナリ マージ ツリーは、一様なランダム ペアリングの対称性により同様に発生する可能性が高くなります。 

この対称性は、各初期要素が最終的な式で期待される重みが同じであることを意味します。 合計の重みは合計 1 になる必要があるため、期待される各重みは次のようになります。$1/n$。 したがって、最終値の期待値は、ランダム プロセスとは無関係に、正確に入力の平均になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    s = sum(arr) % MOD
    inv_n = modinv(n)
    print((s * inv_n) % MOD)

if __name__ == "__main__":
    solve()
```コアとなる洞察によりシミュレーションの必要性がなくなるため、実装は最小限で済みます。 唯一の重要なステップは、次のモジュラー除算です。$n$、係数が素数であるため、フェルマーの小定理を使用して処理されます。 

微妙な点の 1 つは、不必要な増加を避けるために、乗算の前に合計が必ず減算されることです。 もう一つはそれです$n$それ自体は大きいかもしれませんが、モジュラー逆計算は残ります$O(\log MOD)$、制約の下では無視できます。

これは、ランダムなマージにもかかわらず、期待される結果は平均値のみに依存することを裏付けています。 

次に、値が繰り返される 2 番目の例を考えてみましょう。$[5, 5, 5, 5]$。

 これは、対称入力の下での安定性を示しています。すべてのマージは同じ値を決定的に保持します。

 ## 特殊なケース

 次のような単一要素入力`n = 1`マージが行われない唯一のケースです。 合計は要素自体に等しく、1 の逆数は 1 であるため、アルゴリズムはこれを自然に処理し、出力は変更されません。 

すべての等しい配列は、すべての中間点が入力と同一であるため、プロセスの下で決定論的に動作します。 平均は同じ値に等しく、ランダム性は結果に影響を与えないため、アルゴリズムはこれを反映します。 

に近い値を持つ大きな入力$998244353$合計中にモジュラーリダクションが必要です。 この実装では、合計がすぐに減算されるため、オーバーフローが防止され、計算全体を通じて正しいモジュラー演算が保証されます。
