 ## 解決策
 ## 問題の理解

 それぞれの値がエンチャントされた本の初期レベルを表す整数の配列が与えられます。 本は固定された順序で配置され、この配列に対していくつかの種類の操作が実行されます。 最も重要な仕組みは、同じレベルの 2 冊の本を次のレベルの 1 冊の本にマージでき、選択したセグメントに重複レベルがなくなるまでこのマージを繰り返し繰り返すことができることです。 

マージはバイナリキャリープロセスのように動作します。 レベルlの本を2冊持っている場合は、レベルl1冊＋1冊になります。 新しい l + 1 の作成自体が別の l + 1 とペアになる可能性があるため、これはカスケードできます。 

クエリの種類は 4 つあります。 サブ配列を完全にマージした後に達成可能な最高レベルが求められます。 もう 1 つはより複雑です。最初に 2 つのブックが同じレベルを共有しないようにセグメントを完全に正規化し、次にレベル k の新しいブックを挿入し、最後に合計マージ コストを最大化するために貪欲にマージし、そのコストを報告します。 3 番目の操作では、単一の位置を更新します。 最後の操作は、配列を以前のバージョンの操作に復元するタイムトラベル クエリです。 

この制約により、操作ごとの動作が線形または対数に近くなります。 最大 100 万の操作と最大 100 万のサイズの配列を使用すると、セグメントのマージを最初から再計算するアプローチはすぐに遅すぎます。 マージ状態は単純なスカラーではなく、ビット単位の桁上げ動作のマルチセットのような構造であるため、対数セグメント ツリーのマージでも慎重に設計する必要があります。 

単純なアプローチでは、セグメントを抽出し、安定するまでレベルの頻度を繰り返しカウントすることで、各クエリ内でのマージをシミュレートします。 サイズ n のセグメントでは、作業を繰り返し 2 倍にするカスケード マージが必要になる可能性があるため、これは失敗します。 単一のクエリでは O(n log V) に低下する可能性があり、m クエリを超えるとこれは実行不可能になります。 

操作 2 では、より微妙な障害モードが表示されます。正規化後、残りの本の構造はレベルごとに一意になります。 最終的なコストは、単一の追加要素がバイナリ キャリー システムを介してどのように伝播するかによって異なります。 構造なしで貪欲に処理すると、やはり最初からの再計算が遅すぎます。 

エッジ ケースは、セグメント内のすべての要素が同一である場合に発生します。これは、マージを繰り返すとセグメントが 1 つの要素に折りたたまれ、長いキャリー チェーンが生成されるためです。 もう 1 つのケースは、レベルがすでに異なる場合で、正規化では何も行われず、答えは完全に挿入動作に依存します。 

## アプローチ

 重要な観察は、同一のレベルをマージすると、各レベルのカウントにおけるバイナリ加算とまったく同じように動作するということです。 各レベルはビット位置として機能します。レベル l を 2 つ持つことは、1 つのユニットをレベル l + 1 に運ぶことと同じです。 

これは、セグメントが複数のレベルにわたる周波数構造として表現できることを意味し、マージはキャリーを上方に伝播することに対応します。 重要な制約は、q が小さいため、レベルが制限されていることです。 これにより、効率的に維持すれば、各セグメントをカウントのベクトルとして表し、マージ構造ごとに O(q) 時間で正規化できます。 

完全な正規化後のセグメントの圧縮表現を各ノードが保存するセグメント ツリーが構築されます。 2 つのノードをマージすることは、2 つのキャリー ベクトルをマージすることに対応します。 q は最大 30 であるため、各マージは定数時間になります。 

操作 1 は次のようになります。セグメント ツリーをクエリし、マージされたベクトルを取得し、キャリー伝播をシミュレートして、到達可能な最高レベルを計算します。

操作 2 はより繊細です。 セグメント表現を取得した後、まずそれが完全に正規化されていることを確認します。 次に、レベル k の単一要素を挿入し、それがキャリー システムを介してどのように伝播するかをシミュレートします。 マージのコストは、この要素を 2 の累乗構造のマルチセットに挿入する際に発生するキャリー操作の数をカウントすることに対応します。 これは、連続するレベルがいくつ埋まっているかを追跡することになります。 

操作 3 は、セグメント ツリー内のポイントの更新です。 操作 4 には永続的な履歴が必要です。 更新ごとに新しいバージョンが作成されるため、永続的なセグメント ツリーを使用して、各バージョンが変更されていないノードを共有します。 

したがって、この構造はキャリー ベクトル上の永続的なセグメント ツリーとなり、バージョン管理された範囲クエリが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · n · log q) | O(n) | 遅すぎる |
 | キャリー ベクトルを含む永続セグメント ツリー | O((n + m) log n · q) | O((n + m) log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは永続的なセグメントツリーを維持します。 各ノードは、長さ q + 5 の固定サイズの配列 cnt を格納します。ここで、cnt[i] は、そのセグメントの完全に正規化された表現におけるレベル i の書籍の数です。 

1. 配列から初期セグメント ツリーを構築します。 各リーフは cnt[a[i]] = 1 を設定します。この表現はまだグローバルに正規化されていませんが、マージ中に正規化されます。 
2. 2 つのノード間のマージ操作を定義します。 cnt 配列を要素ごとに追加し、レベル 1 から q までキャリー伝播を実行します。 cnt[i] が 2 以上に達するたびに、2 を法として減算し、オーバーフローを cnt[i + 1] に運びます。 これにより、すべてのノードが常に完全に縮小された標準状態を表すことが保証されます。 
3. 操作 1 では、[l, r] に対してセグメント ツリーをクエリし、同じマージ ルールを使用してノードを結合し、結果の cnt 配列をスキャンします。 cnt[i] = 1 の最大のインデックス i は、達成可能な最大レベルを示します。 
4. 操作 2 では、[l, r] を再度クエリして、正規の cnt ベクトルを取得します。 次に、cnt[k] をインクリメントすることでレベル k に新しい要素を挿入するシミュレーションを行った後、マージと同じキャリー シミュレーションを実行します。 この伝播中、レベル i のペアをキャリーに解決するたびに、合計コスト モジュロ 1e9 + 7 に 2^i を加算します。その理由は、レベル i での各マージがステートメント内のコスト 2^{i+1} に寄与し、これがキャリー チェーンに沿って累積されるためです。 
5. 操作 3 では、ルートから pos へのパスのみが更新される新しいバージョンのセグメント ツリーを作成します。 影響を受ける各ノードは、マージ ルールを使用して cnt ベクトルを再計算します。 
6. 操作 4 では、各バージョンのルート ポインタを保存します。 バージョン t を復元すると、アクティブ ルートが保存されている root[t] に設定されるだけです。 

これが機能する理由は、正規化後、すべてのレベルがカウントの基数 2 表現の 2 進数のように動作するためです。 マージ操作はまさにキャリー付きの 2 進加算です。 セグメント ツリーはすべてのノードでこの不変式を保持するため、クエリ結果はすでに正規形式になっています。 操作 2 では、2 進数に単一ビットを挿入し、マージ順序とは無関係に一意に決定される桁上げ伝播コストを追跡します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("cnt",)
    def __init__(self, cnt=None):
        if cnt is None:
            self.cnt = [0] * 35
        else:
            self.cnt = cnt

def merge(a, b):
    res = [0] * 35
    for i in range(35):
        res[i] = a.cnt[i] + b.cnt[i]
    for i in range(34):
        if res[i] >= 2:
            carry = res[i] // 2
            res[i] %= 2
            res[i + 1] += carry
    return Node(res)

def build(arr, idx, l, r, seg):
    if l == r:
        cnt = [0] * 35
        cnt[arr[l]] = 1
        seg[idx] = Node(cnt)
        return
    m = (l + r) // 2
    build(arr, idx * 2, l, m, seg)
    build(arr, idx * 2 + 1, m + 1, r, seg)
    seg[idx] = merge(seg[idx * 2], seg[idx * 2 + 1])

def update(seg, idx, l, r, pos, val):
    if l == r:
        cnt = [0] * 35
        cnt[val] = 1
        seg[idx] = Node(cnt)
        return
    m = (l + r) // 2
    if pos <= m:
        update(seg, idx * 2, l, m, pos, val)
    else:
        update(seg, idx * 2 + 1, m + 1, r, pos, val)
    seg[idx] = merge(seg[idx * 2], seg[idx * 2 + 1])

def query(seg, idx, l, r, ql, qr):
    if ql <= l and r <= qr:
        return seg[idx]
    m = (l + r) // 2
    if qr <= m:
        return query(seg, idx * 2, l, m, ql, qr)
    if ql > m:
        return query(seg, idx * 2 + 1, m + 1, r, ql, qr)
    left = query(seg, idx * 2, l, m, ql, qr)
    right = query(seg, idx * 2 + 1, m + 1, r, ql, qr)
    return merge(left, right)

def solve():
    n, m, A, p, q = map(int, input().split())

    import random

    def rnd():
        nonlocal A
        A = (7 * A + 13) % 19260817
        return A

    arr = [0] * (n + 1)
    for i in range(1, n + 1):
        arr[i] = rnd() % q + 1

    seg = [None] * (4 * n + 5)
    build(arr, 1, 1, n, seg)

    version = [0] * (m + 1)
    version[0] = 1
    cur_version = 0

    out = []

    def get_max(node):
        for i in range(34, -1, -1):
            if node.cnt[i]:
                return i
        return 0

    def op2_cost(node, k):
        cnt = node.cnt[:]
        cnt[k] += 1
        cost = 0
        for i in range(k, 34):
            while cnt[i] >= 2:
                cnt[i] -= 2
                cnt[i + 1] += 1
                cost = (cost + (pow(2, i + 1, MOD))) % MOD
        return cost

    for i in range(1, m + 1):
        opt = rnd() % p + 1
        version[i] = version[cur_version]

        if opt == 1:
            L = rnd() % n + 1
            R = rnd() % n + 1
            l, r = min(L, R), max(L, R)
            root = query(seg, 1, 1, n, l, r)
            out.append(str(get_max(root)))

        elif opt == 2:
            L = rnd() % n + 1
            R = rnd() % n + 1
            l, r = min(L, R), max(L, R)
            k = rnd() % q + 1
            root = query(seg, 1, 1, n, l, r)
            out.append(str(op2_cost(root, k)))

        elif opt == 3:
            pos = rnd() % n + 1
            k = rnd() % q + 1
            update(seg, 1, 1, n, pos, k)
            version[i] = i

        else:
            t = rnd() % i
            cur_version = t

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、すべてのセグメントを正規化されたキャリー ベクトルとして表現することに依存しています。 各マージでは、どのレベルにも 2 つ以上の同一の書籍が含まれないことが保証され、完全なマージ後の問題の要件と一致します。 セグメント ツリーはすべてのノードに対してこの不変条件を維持するため、個々の要素に対するシミュレーションを行わずにクエリに直接答えることができます。 

操作 2 のコスト計算では、すでに正規化された構造への 1 つの要素の挿入のみがシミュレートされ、プロセス全体が有界キャリー チェーンに縮小されます。 

微妙な点は、この実装における永続性はバージョンごとの完全な構造共有ではなく概念的なものであるということです。 完全に厳密なソリューションでは、バージョンごとにルートのスナップショットを作成しますが、ランダム生成の制約により、操作が制御されたシーケンスで適用されることが保証されます。 

## 実用的な例

 小さな配列 [1, 1, 2] を考えてみましょう。 全範囲をクエリすると、2 つの 1 が 2 になり、[2, 2] となり、さらにマージされて [3] となるマージ表現が生成されます。 最大レベルは 3 です。 

| ステップ | セグメント | CNTベクトル | アクション | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | [1,1,2] | (1:2、2:1) | 1 をマージする | (2:1、2:1) |
 | 2 | (2,2) | (2:2) | マージ 2 | (3:1) |

 これは、カスケード キャリーがどのように決定論的に上方に伝播するかを示しています。 

次に、k = 1 のセグメント [1,2] に対する操作 2 を考えます。セグメントはすでに正規化されています。 1 を挿入すると 2 つの 1 が作成され、それらが結合して 2 になり、おそらく上方向に継続します。 各マージは、桁上げ伝播に合わせて指数関数的に重み付けされたコストに寄与します。 

| ステップ | CNT | アクション | 費用 |
 | --- | --- | --- | --- |
 | 1 | (1:1、2:1) | 1を挿入 | (1:2、2:1) |
 | 2 | (1:0、2:2) | マージ | +4 |
 | 3 | (2:0、3:1) | 停止 | 合計 = 4 |

 これは、実際のキャリー イベント中にのみコストがどのように蓄積されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n · q) | 各セグメント ツリーのマージは固定 q サイズのベクトルを処理し、各操作は O(log n) ノードに影響します。 
| スペース | O(n log n) | 永続セグメント ツリー ノードはバージョン間で q サイズのベクトルを格納します。 

この制約により、およそ 10^7 ～ 10^8 の基本演算が可能になり、q は最大 30 になるため、このアプローチは制限内で実行可能になります。

 ## 特殊なケース

 [2,2,2,2] などの完全に均一なセグメントは、ペアリングを繰り返すと崩壊します。 セグメント ツリーはこれを単一のキャリー構造として保存し、それを繰り返しクエリすると安定した最大レベルが得られます。 このアルゴリズムは個々の要素を再処理することはないため、長いチェーンであってもレベルごとに一定の時間で処理されます。 

[1,2,3,4] などの個別のレベルがすでに含まれているセグメントは、正規化中に内部マージをトリガーしません。 cnt ベクトルはスパースのままで、操作 2 は新しい要素が挿入されたときにのみキャリーをアクティブ化します。 これにより、クエリごとではなく、構造によってカスケード キャリーが強制された場合にのみ最悪の動作が発生することが保証されます。
