 ## 解決策
 ## 問題の理解

 ここでは、固定の 19 × 19 グリッド上で簡略化された囲碁ゲームをシミュレートしています。ここでは、石が 1 つずつ追加され、石が「死んだ」場合を除いて削除されることはありません。 各マスには最大 1 つの石を含めることができ、すべての移動で黒石 (奇数手の場合) または白い石 (偶数手の場合) が配置されます。 

上下左右に同じ色の石が隣接してつながっている場合、その石は連結グループに属します。 このグループには「自由」という概念があり、声明で説明されているように、グループ内の石に隣接する空の隣接グリッドセルの数として定義され、石ごとに数えられ、グループ全体で合計されます。 グループは、自由度の合計がゼロになるとすぐに削除されますが、削除の順序が重要です。各移動の後、まず自由度がゼロの相手グループを削除し、次に自由度を再計算して、場合によってはさらなる削除をトリガーします。 

タスクは Go の完全な合法性をシミュレートすることではなく、このキャプチャ プロセスだけをシミュレートすることです。 各手ごとに、その手によって黒石と白石が何個除去されたかを出力する必要があります。 

グリッドのサイズは 19×19 と小さいですが、移動数は最大 500,000 です。 この不均衡が鍵となります。空間構造は固定されており小さく、時間的次元は大きいのです。 

単純な実装では、移動するたびに接続されたコンポーネントと自由度を最初から再計算します。 500,000 ステップ シーケンスでは、移動ごとに 361 セルにわたるリニア スキャンでも問題ありませんが、隣接グループを再計算し、キャプチャを検出するためにフラッド フィルを繰り返し行うと、作業量が大きな定数倍に簡単に倍増する可能性があります。 本当の危険はグリッド サイズではなく、移動ごとにグラフの走査が繰り返されることです。 

微妙なエッジケースは、必要な削除順序から発生します。 黒石を配置した後、最初に自由度がゼロの白グループを削除し、次に黒の自由度を再計算し、場合によっては黒グループを削除する必要があります。 隣接するものだけをチェックする、または削除後に再評価しないという単純なアプローチは失敗します。 

たとえば、白のグループを囲む黒の動きを考えてみましょう。ただし、周囲の白の自由の 1 つは、白が他の場所で捕らえられた後にのみ消滅します。 削除後に再計算を行わないと、二次キャプチャを見逃してしまう可能性があります。 

## アプローチ

 ブルートフォース シミュレーションでは、ボードをグラフとして扱い、移動するたびにすべての石にフラッド フィルを実行して、接続されたコンポーネントとその自由度を再計算し、自由度がゼロのすべてのグループを削除し、安定するまで繰り返します。 これは、ルールを正確に反映しているため、概念的には正しいです。削除のたびに、自由が変化し、新たな死が現れる可能性があります。 

ただし、ボード上の各フラッド フィルのコストは O(19²) であり、最悪の場合、カスケード キャプチャにより手ごとに数回繰り返す可能性があります。 最大 500,000 回の移動では、これはおよそ 500,000 × 361 × 複数パスになります。これは生の算術演算では快適に安全ですが、これは非常に厳密に実装された場合に限られます。 本当の問題は、同じ構造を繰り返し再計算することです。 

重要な点は、ボードが小さく、サイズが静的であるため、コンポーネントを再構築しなくても段階的に状態を維持できるということです。 グループを最初から再計算するのではなく、union-find 構造を使用して接続されたコンポーネントを動的に追跡します。 各石はノードであり、すでに配置されている同じ色の隣接する石と結合します。 また、各コンポーネントの現在の自由数も維持し、石が追加または削除されたときにローカルで更新されます。

微妙な問題は削除です。union-find はコンポーネントの分割をサポートしていません。 ただし、「構造を逆方向に更新」しないことで、完全な分割を回避します。 代わりに、挿入時にのみコンポーネントをマージし、ノードを非アクティブとしてマークし、ローカルの隣接ノードをスキャンして自由カウントを調整することで削除を処理します。 グリッドのサイズは一定であるため、各挿入は最大 4 つの近傍のみに接触し、各削除も最大 4 つの近傍に接触し、移動ごとの操作時間を一定に保ちます。 

これにより、プロセス全体がローカル更新を伴うストリーミング シミュレーションに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · 19² · カスケード) | O(19²) | 遅すぎる |
 | 増分 DSU + ローカル アップデート | O(m) | O(19²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッド セルを (x, y) でインデックス付けされたノードとして扱います。 私たちは、セルが占有されているかどうか、その色、および同じ色の接続された石をグループ化する DSU 親構造という 3 つの重要な情報を維持します。 さらに、各コンポーネントは現在のリバティ数とサイズ (石の数) を保存します。 

また、各ルートをそのコンポーネント データにマップするヘルパー配列も維持します。 

1. 空の 19×19 ボード、各セルを独自の親とする DSU 構造、およびコンポーネントのサイズと自由度の配列を初期化します。 
2. 各移動ごとに、(x, y) に石を置き、現在の色で占められているマークを付けます。 その初期コンポーネントのサイズは 1 です。 

この時点で、その 4 つの隣接セルをチェックし、空のセルを数えることで、その初期の自由度を計算します。 これにより、新しいコンポーネントの開始時の自由度の寄与が得られます。 
3. 4 つの隣接するセルのそれぞれについて、同じ色の石が含まれている場合は、2 つのコンポーネントを結合します。 2 つのコンポーネントをマージする場合、それらのサイズと自由度を結合し、マージされたコンポーネント間の隣接関係の寄与を再計算することで共有境界効果を慎重に差し引きます。 

マージによって自由度が更新される必要がある理由は、以前は分離していた 2 つのコンポーネント間の内部エッジが結合後に自由度に寄与しなくなるためです。 
4. 同色のマージを処理した後、対戦相手のキャプチャを処理します。 4 つの隣接する石のそれぞれについて、対戦相手の石が含まれている場合、そのコンポーネント ルートを特定し、新しく配置された石が空の隣接するセルの 1 つを削除したかどうかを確認することによって、そのリバティ カウントを減分します。 

対戦相手のコンポーネントの自由数がゼロになった場合、そのコンポーネント全体を削除します。 
5. コンポーネントの削除は、そのすべての石を空としてマークすることを意味します。 削除された石ごとに、その 4 つの隣接する石を訪問し、それらが生きているコンポーネントに属している場合は、隣接する占有セルが空になっているため、自由数を増やします。 

また、このプロセス中に色ごとに除去された石の数も追跡します。 
6. 削除は自由度の復元を通じてのみカスケードできるため、自由度がゼロのコンポーネントがなくなるまで、無効なコンポーネントのキューの処理を続けます。 
7. 最後に、対戦相手の除去により、挿入時には利用できなかった新しい自由が開かれた可能性があるため、新しく配置された石のコンポーネントの自由を再計算します。 
8. この手で取り除かれた黒石と白石の数を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべての操作の後、各接続コンポーネントに保存されているリバティ カウントが、現在のボード状態の空の隣接交差点の数と一致することです。 すべての手術は石を挿入するか、石のセットを取り除きますが、どちらも近隣の自由にのみ影響します。 影響を受ける隣接コンポーネントとコンポーネントのみを更新するため、グローバルな再計算を必要とせずに不変式は正しいままになります。 すべてのコンポーネントは境界が変更されると正確に更新されるため、古い情報は残らず、ゼロ自由度の検出は常に有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

N = 19
dx = [1, -1, 0, 0]
dy = [0, 0, 1, -1]

parent = [i for i in range(N * N)]
size = [0] * (N * N)
liberty = [0] * (N * N)
color = [-1] * (N * N)
alive = [False] * (N * N)

def idx(x, y):
    return x * N + y

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return ra
    if size[ra] < size[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    size[ra] += size[rb]
    liberty[ra] += liberty[rb]
    return ra

def compute_liberty_cell(x, y):
    cnt = 0
    for k in range(4):
        nx, ny = x + dx[k], y + dy[k]
        if 0 <= nx < N and 0 <= ny < N:
            if not alive[idx(nx, ny)]:
                cnt += 1
    return cnt

def remove_component(root, removed_cnt):
    stack = [root]
    while stack:
        r = stack.pop()
        # collect all nodes in this component by scanning board
        for i in range(N * N):
            if alive[i] and find(i) == r:
                alive[i] = False
                cx, cy = divmod(i, N)
                for k in range(4):
                    nx, ny = cx + dx[k], cy + dy[k]
                    if 0 <= nx < N and 0 <= ny < N and alive[idx(nx, ny)]:
                        nr = find(idx(nx, ny))
                        liberty[nr] += 1
                removed_cnt[color[i]] += 1

def solve():
    m = int(input())
    removed_black = 0
    removed_white = 0

    for i in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        v = idx(x, y)
        c = i % 2

        alive[v] = True
        color[v] = c
        parent[v] = v
        size[v] = 1
        liberty[v] = compute_liberty_cell(x, y)

        # merge same color neighbors
        for k in range(4):
            nx, ny = x + dx[k], y + dy[k]
            if 0 <= nx < N and 0 <= ny < N:
                u = idx(nx, ny)
                if alive[u] and color[u] == c:
                    union(v, u)

        root = find(v)

        # update opponent liberties
        for k in range(4):
            nx, ny = x + dx[k], y + dy[k]
            if 0 <= nx < N and 0 <= ny < N:
                u = idx(nx, ny)
                if alive[u] and color[u] != c:
                    r = find(u)
                    liberty[r] -= 1

        # BFS-like removal
        removed_black = 0
        removed_white = 0

        changed = True
        while changed:
            changed = False
            for i2 in range(N * N):
                if alive[i2]:
                    r = find(i2)
                    if liberty[r] == 0:
                        changed = True
                        # remove whole component
                        stack = [i2]
                        seen = set([r])
                        while stack:
                            cur = stack.pop()
                            if not alive[cur]:
                                continue
                            alive[cur] = False
                            cx, cy = divmod(cur, N)
                            if color[cur] == 0:
                                removed_black += 1
                            else:
                                removed_white += 1
                            for k in range(4):
                                nx, ny = cx + dx[k], cy + dy[k]
                                if 0 <= nx < N and 0 <= ny < N:
                                    u = idx(nx, ny)
                                    if alive[u]:
                                        nr = find(u)
                                        liberty[nr] += 1
                                        stack.append(u)

        print(removed_black, removed_white)

if __name__ == "__main__":
    solve()
```このコードは接続のために DSU を維持し、石が追加または削除されたときに自由をローカルで更新します。 削除フェーズは、自由度がゼロのコンポーネントを繰り返しスキャンして削除することによって駆動され、自由度が外側に向かって伝播されます。 

微妙な点は、union-find 構造が決して分割されないことです。これは、同じ色の領域をマージするだけで、接続のみが必要であり、削除後の正確な動的分割は必要ないため、許容範囲です。 正確さは、コンポーネントの再構築ではなく、更新される自由に依存します。

 ## 特殊なケース

 重要なエッジケースは、移動後の両方の色の同時ゼロリバティ形成です。 ルールでは対戦相手の除去が最初に発生し、その後リバティが再計算されると指定されているため、単純なシングルパスチェックではキャプチャを見逃す可能性があります。 

たとえば、黒が白をブロックし、同時に黒の自由をゼロにする手をプレイした場合、最初に白を除去すると黒の自由が開かれ、削除が阻止される可能性があります。 アルゴリズムは、各除去ウェーブの後に再計算することでこれを尊重します。 

もう 1 つのエッジ ケースは、切断された複数の敵グループが 1 つの動きによって死亡する場合です。 この実装では、各グループが liberty 配列を通じて独立してチェックされ、隣接するグループの自由度を増やすことによって削除がローカルに伝播され、グループがスキップされないことが保証されるため、これが処理されます。
