 ## 解決策
 ## 問題の理解

 大きなグリッドが与えられていますが、実際に魚が含まれるセルは少数です。 このような各セルには最大 3 匹の魚を含めることができます。 爆弾は任意のグリッド セルに投下でき、その効果は非常に局所的です。選択したセルとその 4 つの直交する隣接セルをカバーし、マンハッタン距離で半径 1 の十字形を形成します。 覆われたセル内のすべての魚はすぐに捕獲され、そのセルが覆われている場合は同じセル内の複数の魚がすべて収集されます。 

タスクは、爆弾の数を最小限に抑えながら、グリッド内のすべての魚を捕まえられるように爆弾の位置を選択することです。 

グリッドは 1000 x 1000 まで大きくできますが、空でないセルは最大 10 個のみです。 これにより、問題はグリッド DP またはすべてのセルにわたるジオメトリ スイープから直ちに移行されます。 すべてのグリッド位置の反復に依存する解決策はすでに不要です。 代わりに、構造は最大 10 個の占有セルによって完全に支配されます。 

微妙な点は、各セルに最大 3 匹の魚を収容できるため、セルをカバーする 1 つの爆弾で一度に最大 3 ユニットの需要を除去できることです。 これは、セルを選択するのではなく、重み付けされた要求をカバーすることを意味するため、重要です。 

主な非明白なエッジ ケースは、複数の魚が同じセルを共有しているが、そのセルがカバー パターンの境界にある場合、単一の爆弾によって部分的にしかカバーされない場合です。 たとえば、単一の爆弾配置が他の魚の要件と互換性のある方法でセルとその隣接をカバーできない場合、単一の魚セルに複数の爆弾が必要になる可能性があります。 もう 1 つの微妙なケースは、2 つの魚の細胞が遠く離れている場合です。この場合、最適な解決策は、相互作用ではなく、単純に独立してカバーすることになります。 

k は最大でも 10 であるため、魚の細胞に対する指数関数またはサブセットに基づく推論は潜在的に実行可能です。 

## アプローチ

 素朴な解釈は、考えられるすべての爆弾位置をセットカバーの候補として扱うことです。 各爆弾位置は最大 5 つのセルに影響を与え、すべての魚ユニットがカバーされるように爆弾位置のサブセットを選択する必要があります。 グリッドには最大 10^6 の位置があるため、すべての爆弾の配置を列挙することは不可能です。 

しかし、重要な観察は、爆弾は占有された少数のセルとどのように相互作用するかによってのみ重要であるということです。 すべての魚の細胞から遠く離れた場所に設置された爆弾は役に立ちません。 より正確に言えば、爆弾は少なくとも 1 つの魚房からマンハッタン距離 1 以内にある場合にのみ問題になります。 つまり、関連する各爆弾の位置は、魚のセルの 1 つ、またはその隣接セルの 1 つです。 フィッシュ セルは最大 10 個あり、それぞれが最大 5 個の爆弾候補位置に寄与するため、有用な爆弾位置の総数は約 50 個に制限されます。 

これにより、問題は小さなセット カバーの変形に変換されます。最大 50 個の候補爆弾があり、それぞれが魚ユニットのマルチセットをカバーし、すべての要求を満たすために最小限の数を選択する必要があります。 

残りの問題は、魚の数がセルごとに最大 3 になると多重度が生じることです。 各魚ユニットを独立した需要としてモデル化することも、より明確に、各セルを容量を必要とするものとして扱い、残りの未カバーの魚数を追跡することもできます。 

k が小さいため、代わりに、各状態が各セル内の残りの魚数を表す状態に対して BFS または DP を実行できます。 各爆弾は、影響を受けるセルごとに特定の座標を最大 1 つ減らし、ゼロでクリップされます。 状態空間の合計は 4^10 (約 100 万) で制限されますが、到達可能な削減のみを考慮するため、遷移は小さく、枝刈りが機能します。 

したがって、各アクションが候補位置の 1 つに爆弾を設置することに対応する、状態にわたる最短経路問題を解決します。

 ## アルゴリズムのチュートリアル

 まず問題を圧縮して、k 個の Fish セルのみが問題になるようにします。 私たちは彼らの座標と魚の数を保存します。 

次に、すべての意味のある爆弾位置のセットを構築します。 (x, y) の各フィッシュ セルについて、マンハッタン距離 1 内のすべての位置を考慮します: (x, y)、(x+1, y)、(x-1, y)、(x, y+1)、(x, y-1) (ただし、それらがグリッド境界内に留まっている場合)。 これらの位置の重複を排除します。 このステップは非常に重要です。最適な解決策では、魚の細胞のカバー範囲が拡大しないため、他の場所に爆弾を設置する必要がありません。 

次に、各爆弾の位置がすべての魚のセルに及ぼす影響を事前計算します。 爆弾の位置 p と魚のセル i について、p が i をカバーしているかどうかを確認します。これは、p と魚のセルの間のマンハッタン距離が 1 以下の場合に当てはまります。そうである場合、その爆弾はそのセル内の残りの魚の数を 1 単位減らすことができます。 

ここで、状態をすべての k 個のセルにわたる残りの魚数のタプルとして定義します。 初期状態は入力カウントのベクトルです。 目標状態はすべてゼロのベクトルです。 

これらの状態に対して幅優先検索を実行します。 状態から、すべての爆弾の位置を試します。 爆弾を適用すると、影響を受けた各セルの残りのカウントが 1 つ減り、ゼロになる新しい状態が生成されます。 各遷移には 1 つの爆弾がかかるため、BFS は最初にゼロ状態に到達するタイミングが最適であることを保証します。 

再計算を避けるために、訪問した状態をハッシュ セットに保存します。 k が小さく、各座標が最大 3 であるため、状態を基数 4 の整数またはタプルとしてエンコードできます。 

### なぜ効果があるのか

 すべての有効な解決策は一連の爆弾の配置に対応し、各配置は状態グラフの遷移に正確に対応します。 あらゆる魚細胞に影響を与える可能性のあるすべての爆弾位置を含めたため、最適な解決策が探索空間から除外されることはありません。 BFS は爆弾の数を増やしながらこの状態グラフを探索するため、初めて完全なカバレッジに到達したときは、最小限の数の爆弾を使用したはずです。 重み付けされていない最短パス設定では状態を繰り返してもコストを改善できないため、状態は再検討されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    xs, ys, cs = [], [], []
    
    for _ in range(k):
        x, y, c = map(int, input().split())
        xs.append(x)
        ys.append(y)
        cs.append(c)

    # generate candidate bomb positions
    cand = set()
    for i in range(k):
        x, y = xs[i], ys[i]
        for dx, dy in [(0,0),(1,0),(-1,0),(0,1),(0,-1)]:
            nx, ny = x + dx, y + dy
            if 1 <= nx <= n and 1 <= ny <= m:
                cand.add((nx, ny))
    cand = list(cand)

    # precompute coverage
    cover = []
    for bx, by in cand:
        mask = [0] * k
        for i in range(k):
            if abs(bx - xs[i]) + abs(by - ys[i]) <= 1:
                mask[i] = 1
        cover.append(mask)

    start = tuple(cs)
    if all(c == 0 for c in start):
        print(0)
        return

    q = deque([start])
    dist = {start: 0}

    while q:
        state = q.popleft()
        d = dist[state]
        if all(x == 0 for x in state):
            print(d)
            return

        for mask in cover:
            nxt = list(state)
            changed = False
            for i in range(k):
                if mask[i] and nxt[i] > 0:
                    nxt[i] -= 1
                    changed = True
            nxt = tuple(nxt)
            if nxt not in dist:
                dist[nxt] = d + 1
                q.append(nxt)

    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、すべての魚のセルを座標とカウントの配列に読み取ることから始まります。 次に、各フィッシュ セルを取得し、それ自体とその 4 つの直交する近傍を追加し、グリッドの外側の位置をフィルター処理して、爆弾の候補位置を構築します。 

次のステップでは、カバレッジ リストを作成します。 各候補爆弾位置はフィッシュ セル上のバイナリ マスクに変換され、どのセルを 1 フィッシュ ユニット減らすことができるかを示します。 

BFS 状態は、残りの魚数のタプルとして表されます。 入力構成を使用して初期化し、各ボムを適用することで到達可能なすべての状態を調査します。 遷移ごとに、一部の座標が最大で 1 つ減少します。 

BFS 距離マップにより、状態を再度訪問することがなくなり、ゼロ ベクトルに到達したときに最小限の爆弾数が保証されます。

 ## 特殊なケース

 重要なエッジケースは、すべての魚が最大カウント 3 の単一セル内にある場合です。アルゴリズムは依然として各爆弾をカバレッジごとに 1 ユニットのみ減少させるものとして扱うため、直感と一致して繰り返し適用する必要があります。 

もう 1 つのエッジケースは、魚の細胞が斜めに隣接している場合です。 最適に配置された爆弾は、正しく配置されていれば両方をカバーでき、BFS はそれらを個別に扱うのではなく、共有されたカバレッジ状態を正しく検出します。 

最後に、複数の候補爆弾位置が同一の効果を誘発する場合は、訪問セットによって自然に重複が排除されます。 たとえ冗長な爆弾位置を生成したとしても、正確性は変わりません。分岐係数が増加するだけです。
