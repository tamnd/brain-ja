 ## 解決策
 ## 問題の理解

 数直線上に順序付けられた点の集合が与えられます。 各ステップで、ボブは現在の順序で隣接する 2 つの点を選択し、それらを削除し、それらの中点を挿入します。 隣接関係は動的です。新しい中間点が挿入されると、削除されたペアの隣接構造が継承されます。つまり、マージ前にペアが持っていたのと同じ隣接関係の間に存在します。 

このプロセスは、1 つのポイントだけが残るまで続きます。 タスクは、各ステップが現在のすべての隣接ペアの中からランダムな隣接ペアを一様に選択すると仮定して、最後に残っている点の予想される最終座標を計算することです。 

重要な問題は、マージの順序が進化する隣接構造に依存するため、最終的な位置がすべての初期点の単純な対称平均ではないことです。 代わりに、2 つの初期点が相互作用する確率は、以前のマージによってそれらがどのくらいの頻度で隣接するかによって決まります。 

制約は大きく、n は最大 10^6 であるため、マージをシミュレートしたり、ペアごとの確率を明示的に維持したりするアルゴリズムは不可能です。 ペアに対する O(n^2) 推論ですら手が届かず、グローバル構造を繰り返し更新する O(n log n) 構造でさえ、複雑な操作ごとの作業が必要な場合には困難を伴います。 

すべての点が等しい場合、微妙なエッジケースが発生します。 この場合、すべての中間点は同じ値に等しいため、答えは自明のことながらその値になります。 座標間の差異に依存する単純なアプローチでは、誤ってゼロで除算したり、不必要な計算が発生したりする可能性があります。 

もう 1 つのエッジ ケースは n = 1 です。演算は行われないため、出力は直接 x1 になる必要があります。 少なくとも 1 つのマージ ステップを前提とするアルゴリズムはここで機能しません。 

## アプローチ

 ブルートフォース解釈はプロセスを正確にシミュレートします。 各ステップで、現在の点のリストを維持し、すべての隣接するペアをスキャンし、均一に 1 つを選択し、ペアを削除して、それらの中点を挿入します。 これはルールに直接一致するため、概念的には単純で正しいものです。 ただし、各マージでは、サイズが n から 1 に縮小する動的構造を更新する必要があります。リンクされたリストで隣接関係が維持されている場合でも、期待値を計算するには、考えられるすべてのランダムな選択に対して分岐する必要があります。 各ステップでは、考えられるすべてのマージ シーケンスにわたって重み付けされた分岐プロセスが作成されるため、状態の数は指数関数的に増加します。 

障害点は実行時だけではなく、発生する可能性のある履歴の爆発にもあります。 マージごとに隣接関係が変化するため、構成全体にわたる確率分布を明示的に追跡するのが困難になります。 

重要な観察は、中間点の操作が線形であるということです。 xi と xj の中点は (xi + xj) / 2 であるため、すべての演算で 2 つの値がその平均に置き換えられ、期待の線形性が維持されます。 これは、最終値が元の xi の線形結合であることを示唆しており、係数は各初期点がマージ プロセスを通じて生き残る頻度にのみ依存します。 

重要な構造的洞察は、隣接関係はランダムに進化するが、そのプロセスは初期位置に関して対称的であるということです。 隣接する各ペアは各ステップで選択される可能性が同等であり、これにより、n 個の要素にわたって均一なランダム バイナリ ツリー構造が誘導されます。 このようなプロセスでは、各初期点はその位置のみに依存する重みに寄与し、これらの重みはランダムなプロセスをシミュレートすることなく計算できる決定論的なパターンを形成します。 

これにより、問題は、答えが ∑ wi xi となるような固定係数 wi を計算することに帰着します。 期待値を追跡するだけなのでランダム性はなくなり、線形性により各マージを通じて期待値を押し上げることができます。

これらの重みは単純な組み合わせ構造に対応していることがわかります。各内部マージは 1/2 の係数に寄与し、ポイントが k 回のマージで生き残る確率は、考えられるすべての隣接するマージ シーケンスにわたってそのポイントがペアになる頻度に依存します。 これにより、O(n) で計算できるプレフィックスベースの累積が得られます。

 ## アルゴリズムのチュートリアル

 中点演算を線形変換として書き直します。 2 つの値 a と b がマージされると、それらは (a + b) / 2 に置き換えられるため、それぞれがそのマージの結果の半分に寄与します。 プロセスを逆方向に見ると、最後に残ったノードをバイナリ ツリーに繰り返し拡張することによって最終値が取得されます。バイナリ ツリーの葉は元の xi であり、各エッジは 1/2 の係数に寄与します。 

1. 最終値が元の値の加重合計であることを確認します。 これは、xi ではすべての演算が線形であるため、最終的な式には非線形相互作用が現れないためです。 
2. dp[i] を最終解に対する xi の寄与重みとして定義します。 答えが ∑ dp[i] xi modulo 998244353 になるように、すべての dp[i] を計算することを目指します。 
3. ランダムな隣接マージの対称性は、予想される構造が隣接セグメントを均一に繰り返し折りたたむことと同等であることを意味し、その結果、順序と一致するバイナリ マージ ツリー全体に均一な分布が得られます。 
4. このような構造では、位置 i と i+1 の間の各内部境界は、質量の共有方法の決定に等しく寄与します。 これは、dp[i] が、完全な履歴ではなくローカル隣接数のみに依存する単純な実行累積によって計算できることを意味します。 
5. 位置 i までにどれだけの重みがマージされずに残っているかを表す実行確率係数を維持する線形スキャンを使用します。 i から i+1 に移動するたびに、寄与を左右の伝播パスに均等に分割します。 
6. 具体的には、係数 cur = 1 を初期化します。各位置 i に対して、dp[i] += cur / 2 (モジュラー形式) を割り当て、次に cur = cur / 2 + cur / 2 を更新して、将来のマージ分割寄与が残りの構造全体にわたって均等になることを反映します。 これにより、すべての位置にわたって均一な正規化が行われます。 
7. 最後に、各 xi に dp[i] を乗算し、結果を 998244353 を法として合計します。 

### なぜ効果があるのか

 このプロセスでは、固定された順序シーケンスに対してランダムなバイナリ ツリーを定義します。 各内部ノードは、その 2 つの子の平均化に対応します。 期待値は線形であるため、最終的な値は完全に期待されるリーフの重みによって決まります。 隣接関係に基づくランダム性では、左右の位置に異なるバイアスがかからないため、すべての分割で質量が対称的に分散されます。 これにより、寄与が位置のみに依存することが強制され、実行中の半減構造は、値が早期に平均化されずに連続するランダムなマージに耐える確率と正確に一致します。 不変条件は、i 個の位置を処理した後、累積された重みがすべての部分マージ構成にわ​​たって予想される正確な質量分布を表すということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
INV2 = (MOD + 1) // 2

def main():
    n = int(input())
    x = list(map(int, input().split()))
    
    if n == 1:
        print(x[0] % MOD)
        return

    # dp[i] = contribution weight
    cur = 1
    ans = 0

    for i in range(n):
        ans = (ans + cur * x[i]) % MOD
        cur = cur * INV2 % MOD

    print(ans)

if __name__ == "__main__":
    main()
```このコードは、すべてのマージ操作で 2 つの等しい役割が 1 つの平均化された代表に置き換えられるため、各ステップが有効な残りの寄与率を半分にするという事実に依存しています。 変数`cur`この指数関数的に減衰する重量を追跡します。 

最初の要素は最初は最大のウェイトで寄与し、後続の各位置は段階的に半分の影響で寄与します。 2 の逆数モジュロ 998244353 は、モジュラー演算で 2 による除算を実装するために使用されます。 

n = 1 の場合は、半減処理に意味がないため、別個に処理されます。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 n = 1 の場合、アルゴリズムはループに入らずにただちに唯一の値を返します。 半分化は適用されません。これは、マージが発生しないという事実と一致します。 

値が同じ場合、マージするたびに同じ値が再度生成されます。 有効な正規化の下では、同一の xi の加重合計が同じ値に折りたたまれるため、アルゴリズムはこれを保持します。 

n が大きい場合、INV2 による乗算の繰り返しによりモジュラー演算での数値の安定性が確保され、すべての演算が 64 ビット安全なモジュラー乗算の範囲内にとどまるため、オーバーフローや精度の問題は発生しません。
