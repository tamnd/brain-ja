 ## 解決策
 ## 問題の理解

 すべての桁が異なる 5 桁の整数が与えられます。 これら 5 桁の順序を任意に並べ替えることはできますが、結果の数値は有効な 5 桁の整数でなければなりません。つまり、ゼロで始めることはできません。 

各テスト ケースのタスクは、そのような並べ替えが少なくとも 1 つ合成数を形成するかどうかを判断することです。 このような並べ替えが存在する場合は、有効な複合順列のいずれかを出力する必要があります。 すべての有効な順列が素数の場合、答えは -1 になります。 

主要な構造は、各入力が正確に 5 つの異なる桁を提供するため、可能な再配置の数は、置換後の 120 から 0 で始まる数を引いた値に固定されます。 この制限されたサイズは、テストごとに順列に対する総当りの実行が可能であることを強く示唆していますが、テスト ケースの数は 100,000 に達する可能性があるため、平方根チェックを使用した単純なテストごとの素数再計算では、集計が遅すぎる可能性があります。 

ゼロが数字の 1 つである場合、微妙なエッジ ケースが発生します。 たとえば、数値が 10234 の場合、01234 などの一部の並べ替えは、数字のマルチセットの有効な並べ替えであっても、無効であるため無視する必要があります。 もう 1 つのエッジ ケースは、すべての順列が素数である場合です。この場合、誤って無効な候補やフィルターされていない候補を返すのではなく、-1 を正しく出力する必要があります。 

2 番目の微妙な問題はパフォーマンスです。順列ごとに素数性を個別にチェックすると、最大 120 × 100000 = 1,200 万回の素数性チェックが行われ、それぞれのチェックが sqrt(99999) 演算に達するため、時間がかかりすぎます。 このため、事前計算を使用した素数テストから生成を分離する必要があります。 

## アプローチ

 直接的な総当たり戦略では、各テスト ケースが個別に考慮されます。 5 桁のすべての順列を列挙し、先頭にゼロがある順列をスキップし、各順列を整数に変換し、平方根までの割り算をテストすることで合成かどうかを確認します。 これは、有効な再配置の全検索スペースを徹底的にチェックするため、正しいです。 問題は計算コストです。 最悪の場合、テストごとに約 120 の順列、最大 100,000 のテストが実行され、1,200 万の候補番号が得られます。 平方根素数チェックには数値ごとに約 300 回の操作が必要となり、合計で数十億回の操作が必要となり、制限をはるかに超えています。 

改善は懸念事項を分離することによってもたらされます。 取り得る値の空間は小さく、99999 で区切られているため、その範囲内のすべての数値の素数はふるいを使用して 1 回事前に計算できます。 その後、各順列は定数時間のルックアップを行うだけで、それが素数であるか複合であるかを判断できます。 これにより、問題は固定桁セットに対する純粋な組み合わせ生成となり、候補ごとに O(1) 分類になります。 

また、120 個の候補は小さく許容できるため、itertools を使用してテストごとに順列を直接生成することで、順列を繰り返し再計算することを避けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列ごとの試行分割) | O(T・120・√N) | お(1) | 遅すぎる |
 | ふるい + 順列列挙 | O(100000 + T · 120) | O(100000) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ふるいを使用して、99999 までのすべての数値の素数を事前計算します。 これにより、後で任意の候補番号を即座に分類できるようになります。 
2. テスト ケースごとに、入力数値の 5 桁をリストに抽出します。 数字を操作すると、文字列解析を繰り返す必要がなくなります。 
3. これら 5 桁のすべての順列を生成します。 
4. 各順列について、最初の桁が 0 であるかどうかを確認します。 有効な 5 桁の数字ではないため、すぐに破棄してください。 
5. 残りの順列を整数に変換します。 
6. 事前計算されたふるいを使用して、この整数が合成であるかどうかを確認します。 複合の場合は、すぐに出力して次のテスト ケースに進みます。 
7. 合成数を生成する順列がない場合は、-1 を出力します。 

早期停止の背後にある理由は、問題では 1 つの有効な複合順列の存在だけが求められるため、有効な答えが見つかったら完全な順列空間を探索する必要がないためです。 

### なぜ効果があるのか

 有効な数字の再配置はすべて、順列列挙に 1 回だけ表示されます。 ふるいは、各候補番号の正確な分類を保証します。 最初に見つかった合成数を受け入れ、すべての候補が有効なセット全体と照合されるため、有効な答えを見逃すことはありません。 複合候補がない場合は、定義上、有効な順列はすべて素数であるため、-1 が正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 100000

is_prime = [True] * MAXV
is_prime[0] = is_prime[1] = False

for i in range(2, int(MAXV ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, MAXV, step):
            is_prime[j] = False

from itertools import permutations

t = int(input())
for _ in range(t):
    s = input().strip()
    digits = list(s)

    found = False

    for p in permutations(digits, 5):
        if p[0] == '0':
            continue
        val = 0
        for ch in p:
            val = val * 10 + (ord(ch) - 48)

        if not is_prime[val]:
            print(val)
            found = True
            break

    if not found:
        print(-1)
```上部のふるいはグローバル テーブルを構築し、後続の素数クエリが単一の配列ルックアップに削減されるようにします。 これは、割り算チェックを繰り返し再計算することを防ぐ重要な最適化です。 

テスト ループ内では、数字が 1 回抽出され、再利用されます。 置換ループは十分小さいため、Python の組み込みジェネレーターで十分です。 整数の構築は、内部ループ内の文字列から整数へのオーバーヘッドを回避するために手動で行われます。 

先行ゼロのチェックは変換前に適用されるため、無効な順列がふるい検索段階に到達することはありません。
