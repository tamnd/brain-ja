 ## 解決策
 ## 問題の理解

 私たちには次のシーケンスが与えられています$n$ゲームラウンド。 各ラウンドの開始時に、ちょうど 1 枚のコインが T0xel のウォレットに追加され、コインは使用される場合を除いて失われることはありません。 ラウンド中$i$、費用がかかります$c_i$: そのラウンドで探知機を購入するたびに、それは消費されます$c_i$すぐにコイン。 彼は、その瞬間までに蓄積されたコインでそれらの代金を支払うことができる限り、ラウンドで任意の数の検出器を購入することができます。 

目標は、すべてのラウンドで購入される検出器の合計数を最大化することです。 

重要なダイナミクスは、時間の経過とともにコインが蓄積されるため、初期のラウンドは経済的に弱く、後のラウンドはより豊かになるということです。 これにより、時間とコストの間に相関関係が生まれます。将来の安いラウンドで購入することは、高価なラウンドや初期のラウンドで購入するよりも価値がありますが、ラウンドごとに生成されるコインは 1 枚だけであることを尊重する必要があります。 

制約$n \le 2 \cdot 10^5$これは、すべての解が演算ごとに基本的に線形または対数である必要があることを意味します。 あらゆる可能な購入分布をシミュレートしようとしたり、過去のラウンドを繰り返しスキャンしようとしたりすると、次のような理由で失敗します。$O(n^2)$行動。 

先を見ずに可能な限り購入する単純な貪欲戦略により、微妙な失敗例が発生します。 たとえば、初期のラウンドのコストが小さい場合、単純なアプローチでは初期の費用が過剰になり、将来の安価なラウンドが枯渇する可能性があります。 

もう 1 つの特殊なケースは、コストがラウンド初期には非常に大きく、その後は小さくなる場合に発生します。 コインが最適に保存されている場合、初期のコインはすべて後の購入のために保存されるはずですが、単純な「可能であればすぐに購入する」戦略ではコインが無駄になってしまいます。 

これらの例は、ラウンド内の局所的な貪欲な決定では十分ではないことを示しています。 グローバルな順序付けの原則が必要です。 

## アプローチ

 ブルートフォースアプローチでは、各ラウンドをシミュレートし、コインの数を追跡し、手頃な価格を条件としてそのラウンドで可能なすべての購入数を試します。 これは、ラウンドごとに次のようになります。$i$、整数を選択します$x_i$そのような$x_i \cdot c_i \le \text{coins available before round } i$、状態を更新して続行します。 

制約を正確に尊重するため、正確性は簡単です。 ただし、ラウンド全体で可能なコインの分配の数は、次のように指数関数的に増加します。$n$また、コインの合計が$O(n)$、につながる$O(n^2)$またはさらに悪い移行。 

重要な構造的洞察は、利用可能なコインの制約を除いて、各検出器の購入が独立しており、いつ獲得したかに関係なく、すべてのコインが同一であるということです。 これにより、プロセスを次のように再解釈できます。各ラウンドで 1 単位の供給が生成され、各購入で消費されます。$c_i$その供給の単位であり、コストは購入を選択したラウンドにのみ依存します。 

時間をシミュレーションする代わりに、世界的な予算の観点から考えて、いつコインを使うのが最も有益かを決定することができます。 最適な戦略は単調な調整で時間の経過とともに貪欲になります。私たちは常に、高価な購入によって将来のより安価な購入が可能になることを確実にしたいと考えています。 

これにより、問題は増大する予算に伴うコストをめぐるストリーミングの最適化の問題に変わります。

 ## アルゴリズムのチュートリアル

 利用可能なコインの総数を維持しながら、ラウンドを順番に処理します。 各ステップで、現在のラウンドで購入する検出器の数を決定しますが、ローカルで取り消し不能な決定を下すのではなく、購入の分布がグローバルに最適な状態を保つようにします。 

1. 変数を初期化する`coins = 0`そして`answer = 0`。 コインは、以前のすべてのラウンドから蓄積された予算の合計を表します。 
2. ラウンドを繰り返す$i = 1$に$n$。 各ラウンドの開始時に増加します`coins`新しく獲得したコインを考慮して 1 ずつ加算されます。 
3. 現在のコストについて$c_i$、現在のコインをすべてこのラウンドに充てた場合、理論的には何個の検出器を購入できるかを計算します。`possible = coins // c_i`。 これは、ここにすべてを割り当てた場合、蓄積された予算を地域で最大限に活用することを表します。 
4.追加`possible`に`answer`、これらの購入はコミットされているためです。 
5.減らす`coins`による`possible * c_i`。 これは、それらの購入に使用された金額を正確に支出することをシミュレートします。 
6. 次のラウンドに進みます。 

微妙な部分は、各ステップですべての手頃な価格の購入をすぐにコミットすることが有効である理由です。 その理由は、支出の機会を順番に解釈した場合、現在使用されていないコインは将来のラウンドでより高価になるか、同じくらい高価になるだけであるということです。 各ラウンドには固定コストがあり、将来のラウンドで遡及的にコストを削減することはできないため、共有予算の下でラウンドごとにコストが個別に考慮される場合、購入を遅らせても利点は生まれません。 

### なぜ効果があるのか

 アルゴリズムは不変条件を維持します: ラウンド処理後$i$、残りのコインは、すでに最適に処理されたものと同じかそれ以下のコストで処理されたラウンドで別の検出器を購入するには不十分です。 将来のラウンドのコストは低いか同等である可能性があり、早期に支出しても後でより安価な機会へのアクセスを向上させることはできないため、残ったコインは将来のラウンドのために保存しておいたほうが良いでしょう。 これにより、すべてのコインが現在のコストレベルで可能な最大の検出器に即座に変換されるか、将来のより安価なコストに備えて保存され、決して無駄にならないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    coins = 0
    ans = 0
    
    for i in range(n):
        coins += 1
        ans += coins // c[i]
        coins %= c[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装はステップバイステップのシミュレーションに正確に従います。 重要な詳細は、`coins %= c[i]`、現在のラウンドで最大限の購入を行った後に残ったコインのみを保持します。 これは減算に相当します`possible * c[i]`ただし、オーバーフローを回避し、状態を最小限に保ちます。 

よくある間違いは、各ラウンドを処理する前にコインを蓄積するのを忘れることで、時間順序が崩れてしまいます。 もう1つは、残りのコインを正しく前に進めずに、ラウンドごとに貪欲に決定しようとすることです。

## 特殊なケース

 のような最小限のケース$n = 1, c_1 = 1$即時変換を示します。1 つのコインが獲得され、すぐに消費され、1 つの検出器が生成されます。 

のようなケースの場合$c = [100, 100, 1]$、アルゴリズムは、最初の 2 ラウンドで何も消費せずに 2 つのコインを蓄積し、最後のラウンドで 3 つのコインすべてを 3 回の購入に最適に変換します。 モジュロ演算により、最後のラウンド後に、以前に誤って割り当てられた可能性のある残りのコインが残らないことが保証されます。 

次のような一律費用の場合$c = [2, 2, 2, 2]$、システムは安定して動作します。2 枚のコインごとに 1 つの検出器に変換され、残りは正しく前方に伝播します。 これにより、どのラウンドでも決定間の非効率性や隠れた相互作用が発生しないことが確認されます。
