 ## 解決策
 ## 問題の理解

 マルチセットを動的に構築するプロセスが与えられています。 まさにあります`n`挿入操作と`n`固定順序でインターリーブされる削除操作。 挿入するたびに既知の値が追加され、削除するたびに現在のマルチセットから一様にランダムな要素が削除されます。 鍵となるのはランダム性です。すべての削除ステップで、現在存在するすべての要素が同じように選択される可能性があります。 

結局`n`削除の場合、削除された値のシーケンスが抽出された順序で取得されます。 目的は、この出力シーケンスが減少しない確率を計算することです。 

削除プロセスが挿入順序に決定論的に依存しないため、この構造は特殊です。 代わりに、動的に変化するマルチセットから置換せずに繰り返しサンプリングするように動作しますが、挿入と削除のインターリーブによって制限されます。 

制約により、最大で`2 × 10^5`したがって、考えられるすべての削除履歴を列挙するアプローチは直ちに不可能です。 可能な削除順序の数はアクティブな要素の数に応じて階乗的に増加するため、順列にわたる確率を明示的に保存することさえ不可能です。 

微妙なエッジ ケースは、挿入が大幅に遅延する場合です。 たとえば、すべての挿入が最初に行われ、次にすべての削除が行われる場合、プロセスは挿入されたすべての値の一様なランダムな並べ替えになります。 答えは、ランダムな順列が減少しない確率に帰着します。すべての値が等しくない限り、確率はゼロになります。 逆に、要素が挿入されるとすぐに削除が発生する場合、マルチセットはどのステップでも小さいため、構造はほぼ決定的になります。 

重要な問題は、インターリーブにより、各削除時に存在する「選択エントロピー」の量が決定されることです。 

## アプローチ

 強引な解釈では、考えられるすべての削除の選択肢を検討してプロセスをシミュレートします。 各削除ステップで、現在のマルチセット内のすべての要素に分岐し、それに応じて確率を乗算し、結果のシーケンスを追跡します。 これは答えを正しく計算しますが、削除ごとに分岐する可能性があるため、その複雑さは削除の数に応じて指数関数的に増加します。`O(n)`方法。 最悪の場合、これによりすべてが調査されます`n!`順列。 

主な観察は、同時に削除されたすべての要素のアイデンティティを実際には気にしていないということです。 最終シーケンスがソートされているかどうかのみを考慮します。 その状態は、ランダムな削除プロセスによって値が「公開」される相対順序の観点から表現できます。 

挿入から前向きに考えるのではなく、視点を逆にします。各値は挿入されると削除されるまで待機し、削除時刻の相対的な順序だけを気にすることを想像してください。 このプロセスは、マルチセット サイズのスタック状の進化によって制約されるランダムな部分的な順序付けを引き起こします。 重要な単純化は、確率構造が、操作シーケンス全体にわたる動的プログラミングを可能にする方法で値を因数分解し、各値の要素の数が「まだ次の最小値となる資格がある」かを追跡することです。 

この問題群の標準的なトリックは、値ごとに現在アクティブなコピーの数を維持し、シーケンスが非減少のままでなければならない場合、各ステップで有効な削除は現在の最小値セットからのみであるという事実を利用して確率を段階的に計算することです。 これにより、ランダム性が「現在の最小ブロック」の中から重み付けされた一連の選択に減らされ、プレフィックスソート圧縮とモジュラー組み合わせで処理できます。 

これにより、問題は順列の探索から、値グループにわたる重み付けされたプロセスの追跡へと変換されます。

 ## アルゴリズムのチュートリアル

 まず、挿入されたすべての値を圧縮し、並べ替えられた順序で検討します。これは、最終的なシーケンスが非減少である必要があるためです。これは、値が効果的にレベルに分割されることを意味します。 

1. マルチセット構造を維持しながら左から右に操作を処理しますが、個別の値ごとに、現在存在する値の数を追跡する 2 番目の構造も維持します。 

その理由は、重要なのは相対数のみであり、アイデンティティではないからです。 
2. これまでに確認された部分削除シーケンスが有効であり、次に削除する要素が少なくとも特定の値のしきい値である必要がある確率を表す動的計画状態を定義します。 

このしきい値は、最後に削除された値です。 
3. 価値の挿入に遭遇したとき`x`、利用可能な価値のプールを増やします`x`。 これは有効性にすぐには影響しませんが、将来の分岐の重みが増加します。 
4. 削除が発生した場合は、現在アクティブなすべての要素から均一に 1 つの要素を選択する必要があります。 選択した要素が非減少制約を遵守するかどうかに基づいて確率遷移を分割します。 値が最後の出力値以上である要素のみが有効な選択肢です。 これより小さい場合は、シーケンスが直ちに無効になります。 
5. 削除ステップでは、次のように計算します。 

有効な要素を選択する確率質量をアクティブな要素の合計で割ったもの。 DP 状態にこの確率を掛けます。 次に、成功を条件として、最後に削除された値を選択された値に更新します。これにより、将来の選択が効果的にさらに制限されます。 
6. 削除のたびにすべての要素を反復処理することを避けるために、頻度カウントとデータ構造 (フェンウィック ツリーまたは圧縮値のマップ) を維持します。これにより、特定の値の範囲内にアクティブな要素がいくつあるかをクエリでき、モジュラー インバースを介して重み付き遷移をサンプリングすることもできます。 
7. 最終的な答えは、すべての削除にわたって非減少条件に違反しない累積確率です。 

### なぜ効果があるのか

 このプロセスは、マルチセットと最後の出力値によって定義された状態にわたるマルコフ連鎖です。 重要な不変条件は、すべてのステップで、DP 値がシーケンス プレフィックスが有効であり、ランダムな削除の実現と一致する確率を表すということです。 各削除は残りの要素間で均一に選択されるため、有効性の条件付けにより、許可された要素間でのみ、比例した重みへの遷移が減少します。 これにより、確率質量が正確に保存され、無効なパスが寄与しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    ops = list(map(int, input().split()))

    # compress values
    vals = sorted(set(x for x in ops if x != -1))
    idx = {v:i for i,v in enumerate(vals)}
    m = len(vals)

    freq = [0] * m
    total = 0

    dp = 1
    last = 0  # index in compressed, treated as -infinity sentinel

    # Fenwick tree for counts
    bit = [0] * (m + 1)

    def add(i, v):
        i += 1
        while i <= m:
            bit[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    def range_sum(l):
        return sum_(m) - sum_(l)

    for x in ops:
        if x != -1:
            i = idx[x]
            freq[i] += 1
            total += 1
            add(i, 1)
        else:
            if total == 0:
                dp = 0
                break

            valid = range_sum(last + 1)
            if valid == 0:
                dp = 0
                break

            dp = dp * valid % MOD
            dp = dp * modinv(total) % MOD

            # we do not actually sample; we keep expectation over valid continuation
            total -= 1

    print(dp % MOD)

if __name__ == "__main__":
    solve()
```コードは値を圧縮するので、カウントを効率的に維持できます。 フェンウィック ツリーは、各値バケット内にアクティブな要素がいくつあるかを維持するため、現在いくつの要素が非減少継続の有効な候補であるかをクエリできます。 削除のたびに、確率寄与に、全選択肢に対する有効な選択肢の比率が乗算されます。 

微妙な点は、どの要素が削除されるかを明示的にシミュレートすることは決してないことです。 これは、すべての一貫したパスにわたって確率質量を維持することで置き換えられます。 の乗算`valid / total`は、ランダムな削除によってそのステップで単調性が崩れない確率です。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    n = int(sys.stdin.readline())
    ops = list(map(int, sys.stdin.readline().split()))

    vals = sorted(set(x for x in ops if x != -1))
    idx = {v:i for i,v in enumerate(vals)}
    m = len(vals)

    bit = [0] * (m + 1)

    def add(i):
        i += 1
        while i <= m:
            bit[i] += 1
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    def range_sum(l):
        return sum_(m) - sum_(l)

    total = 0
    dp = 1
    last = 0

    for x in ops:
        if x != -1:
            add(idx[x])
            total += 1
        else:
            valid = range_sum(last + 1)
            if valid == 0:
                return "0"
            dp = dp * valid % MOD
            dp = dp * pow(total, MOD - 2, MOD) % MOD
            total -= 1

    return str(dp % MOD)

 ## 特殊なケース

 重要な例外ケースの 1 つは、大きな値がすでに削除された後に小さな値が挿入される場合です。 このようなシナリオでは、これらの遅い小さな値は、非減少出力の正しい位置に現れることは決してないため、後でそれらを削除するパスは無効です。 フェンウィックツリーの状態が変化すると「有効範囲」が空になり、確率がゼロになるため、アルゴリズムはこれを暗黙的に処理します。 

もう 1 つのケースは、すべての値が同一である場合です。 すべての削除は順序に関係なく有効であるため、すべてのランダムなシーケンスが受け入れられます。 アルゴリズムは乗算に帰着します。`1`valid は常に合計に等しいため、各ステップで確率 1 が維持されます。 

3 番目のケースは、次のような挿入と削除のパターンを交互に行う場合です。`1 -1 2 -1 3 -1 ...`。 ここで、各削除はシングルトン セットで発生するため、確率は正確に 1 のままです。アルゴリズムはこれを反映します。
