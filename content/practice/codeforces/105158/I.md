 ## 問題の理解

 小文字からなる文字列が与えられており、変更できるのは最大でも$k$文字。 目標は、文字列を非常に硬い周期構造に変えることができるかどうかを判断することです。 

「美しい」文字列を定義する条件は、通常の周期性よりも強いです。 ピリオドを見つけなければなりません$p$すべての文字がその文字と正確に一致するように$p$文字列内で可能な場合はどこでも、前に位置します。 つまり、1周期に1回$p$が選択されている場合、文字列は整列されたすべての位置のモジュロにわたって一貫している必要があります。$p$、最初だけ$p$文字によって文字列全体が決まります。 

これにより、問題は「文字列をグローバルに修正できるか」から「文字列を強制的に長さの繰り返しパターンにできるか」に変わります。$p$編集は限られています。」

 制約があるからこそ、問題は面白くなります。 テスト ケース全体の長さは最大です。$3 \cdot 10^5$、 その間$k$は小さく、最大でも 100 です。これは、次の条件に依存する解決策がすぐに示唆されます。$n^2$あるいは$n \cdot k^2$これは問題ありませんが、テスト ケースごとに 2 次作業を伴うものは問題ありません。 重要なシグナルは、候補構造ごとに線形スキャンを行うことができるが、あらゆる可能性にわたって文字ごとに大規模な最適化を行うことはできないということです。 

微妙なエッジケースは、文字列がすでに周期的である場合です。$p$。 たとえば、文字列がすでに次のように均一である場合、`aaaaaa`、 どれでも$p$動作します。 小さなチェックだけを行う単純なアプローチ$p$失敗するだろう。 もう 1 つの注意が必要なケースは、最適解を得るために、局所的な繰り返しからは明らかではない非自明な期間を選択する必要がある場合です。`ababac`ここで、いくつかの文字を修正すると、小さな期間が明らかになります。 

## アプローチ

 ブルートフォース手法では、可能なすべての期間が試行されます$p$から$1$に$n$。 それぞれについて$p$、すべてのインデックスの一貫性を強制します$i$そして$i+p$一致する必要があるため、各剰余クラスのモジュロ$p$同じ最終文字を共有する必要がある位置の独立したグループを形成します。 

固定の場合$p$、各グループを調べます$r \in [0, p-1]$。 グループ内$r$では、文字の頻度をカウントし、すべての文字を等しくするために必要な変更の数を計算します。 そのグループのコストは、グループのサイズから最も頻繁に使用される文字数を引いたものになります。 すべてのグループを合計すると、その期間に必要な編集の合計が得られます。 

これは正しいです。なぜなら、ピリオドが固定されると、グループは独立しているからです。つまり、1 つの剰余クラスの最後の文字を選択しても、他の剰余クラスに影響を与えることはありません。 

ブルートフォースコストは$O(n^2)$最悪の場合、それぞれの理由で$n$すべての期間をスキャンします$n$文字。 

重要な観察は次のとおりです$k$は小さいため、合計の不一致が最大でも小さい解のみを考慮します。$k$。 これにより枝刈りが可能になり、大掛かりな方法で期間ごとにゼロから再計算するのではなく、不一致構造を効率的に計算する動機にもなります。 すべてのグループが独立して寄与するため、期間ごとに文字を 1 回繰り返すことで不一致が蓄積する可能性があります。これは、与えられた制約を考慮するとすでに十分に最適です。

 ## アルゴリズムのチュートリアル

 中心的な考え方は、考えられる各ピリオドをテストし、そのピリオドの下で文字列の一貫性を保つために変更する必要がある文字数を計算することです。 費用を超える場合は早期に終了します$k$。 

1. 候補期間ごとに$p$1から$n$、文字列が一定の長さのブロックを繰り返すことによって形成されていると仮定します。$p$。 以内に達成できるか検証していきます$k$編集します。 
2. この期間では、剰余モジュロによってインデックスをグループ化します。$p$。 各グループは、最終的な文字列内で単一の繰り返し文字として終わる必要があります。 
3. グループごとに、各キャラクターが何回登場するかを数えます。 変更を最小限に抑えたいため、そのグループにとって最適な選択は最も頻繁に使用される文字です。 
4. グループのコストは、グループ サイズから最大頻度を引いたものです。 このコストを現在の合計に加算します。$p$。 
5. いずれかの時点で合計コストが超過した場合$k$、この期間は有効ではないため、早期に処理を停止します。 
6. すべてのグループを処理した後の合計コストが最大以下の場合$k$の場合は、すぐに「はい」を返します。 
7. ピリオドが機能しない場合は、「No」を返します。 

これが機能する理由は構造的な分解に由来します。つまり、期間が固定されると、すべての位置はその剰余クラスによってのみ制約されます。 これらのクラスは相互作用しないため、最適な編集をクラスごとに独立して計算できます。 このアルゴリズムは、期間の選択によって引き起こされるすべての可能な分解を検索し、分解ごとに最小限の編集を計算することによって実現可能性を正確にチェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n, k, s):
    s = s.strip()
    
    for p in range(1, n + 1):
        changes = 0
        
        for r in range(p):
            freq = [0] * 26
            cnt = 0
            
            for i in range(r, n, p):
                c = ord(s[i]) - 97
                freq[c] += 1
                cnt += 1
            
            if cnt == 0:
                continue
            
            changes += cnt - max(freq)
            if changes > k:
                break
        
        if changes <= k:
            return True
    
    return False

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        out.append("Yes" if solve_one(n, k, s) else "No")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は期間列挙戦略に直接従います。 内側のループは、ストライドでステップすることでインデックスをグループ化します。$p$、各剰余クラスが期間ごとに正確に 1 回処理されるようにします。 サイズ 26 の周波数配列は、文字ごとに一定時間文字カウントを維持します。 

早めの休憩のとき、`changes > k`パフォーマンスには欠かせません。 これがなければ、すでに無効な場合でも常に完全な期間を処理することになります。 

よくある間違いは、各残基クラスが独立していることを忘れ、グループを混合しようとする誤った試みにつながることです。 もう 1 つは、入れ子になったループ内で周波数を非効率的に再計算することです。 ここでは、期間ごとに線形のままです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        res = []
        for _ in range(t):
            n, k = map(int, input().split())
            s = input().strip()

            def ok():
                for p in range(1, n + 1):

                        cnt = 0

                            break
                    if changes <= k:
                        return True
                return False

            res.append("Yes" if ok() else "No")
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 0$。 この状況では、アルゴリズムは、ある期間で完全に一貫性がない文字列を拒否する必要があります。 たとえば、入力`ab`と$k=0$にのみ機能します$p=2$、期間が小さいと不一致が強制されるためです。 すべての重要なグループ化は直ちにプラスのコストに寄与するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、最適な期間が次のような場合です。$p = n$。 この場合、すべての文字が独自のグループを形成するため、文字列に関係なくコストは常にゼロになります。 アルゴリズムは、次の場合に常にこれを直ちに受け入れます。$k \ge 0$、どれも選択できるので、これは正しいです。$p \le n$そして$p=n$制約を課しません。 

3 番目のケースは、次のような繰り返しの多い文字列です。`aaaaaa`。 すべての期間でコストがゼロになるため、アルゴリズムは最初の有効なチェックで受け入れます。 これは、周波数ベースのコスト計算が実際の文字の多様性に依存せず、縮退分布の下でも安定したままであることを確認します。
