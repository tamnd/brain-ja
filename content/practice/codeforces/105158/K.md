 ## 解決策
 ## 問題の理解

 重み付けされたノードを持つツリーが与えられます。 ツリーには方向性がなく、選択した任意のノードにルートを付けることができます。 ルートが固定されると、他のすべてのノードには、ルート化されたツリー構造によって定義された親が 1 つだけ存在します。 

ツリーをルートから離れる方向に向けたときに、親から子へのすべてのエッジがノードの重みに関する特定の制約を満たす場合、そのルートは「有効」と呼ばれます。つまり、子の値は親と比較して十分に大きくなければなりません。具体的には、ステートメントで説明されている意味でその値の少なくとも半分でなければなりません（サンプルの説明のように、条件を「子 ≥ 親 / 2」の形式の親子不平等しきい値として解釈します）。 

タスクは、ルートとして選択されたときに、ルート化されたツリー全体がすべての親子エッジでこの条件を満たすようにするノードの数をカウントすることです。 

各テスト ケースでは、すべてのケース全体で最大 10^5 のノードを持つツリーが得られるため、テストごとに基本的に線形または線形に近い動作が必要です。 すべてのノードでルート化をシミュレートし、制約を個別にチェックしようとするソリューションは、ルート候補ごとにサイズ O(n) のトラバースを繰り返し、結果として O(n^2) になるため、遅すぎます。 

さらに微妙な問題は、ルート化後の制約が方向性を持つことです。 ノードは親としては問題なくても、ルートによっては子として失敗する可能性があるため、グローバル方向を考慮せずにエッジで単純にローカル チェックを行うと失敗します。 

典型的な落とし穴は、エッジが一方向の条件を満たしていれば、すべてのルートに対して安全であると仮定することです。 ルートを変更すると、パスに沿った親子関係が反転するため、これは不正確です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべてのルートに対して、DFS または BFS を実行してルート付きツリーを構築し、すべての有向エッジの親→子に対して制約が適用されることを確認します。 各チェックは O(n) で、考えられるルートは n 個あり、テスト ケースごとに O(n^2) になります。 n が 10^5 までになると、これは完全に不可能になります。 

重要な点は、ルートごとにすべてを最初から再計算する必要がないということです。 ルートをノード u からその隣接ノード v の 1 つに移動すると、エッジ (u, v) に沿った関係のみが方向を変えます。 他のすべては構造的に同じままですが、一貫した再発根効果があります。 これは、DP の視点が再根付くことを示唆しています。 

方向に依存した実現可能性を可能にする方法で、エッジ u-v の条件を再解釈します。 各エッジについて、重みに応じて 1 つの方向のみが「不良」になる可能性があります。 これは、各エッジが禁止された方向制約を引き起こすことを意味します。つまり、ある場合には一方の端点が他方の端点の親ではない可能性があります。 

この問題を、ノードごとに、それをルートとして選択すると、すべてのエッジにわたるすべての禁止された親子方向が回避されるかどうかを識別することに変換します。 これは古典的なツリーの再ルートの実現可能性の問題になります。最初に参照ルートの有効性を計算し、次に 2 つの DFS パスを使用して変更を伝播します。 

最初のパスでは、下方向に制約を計算し、親へのエッジが特定の方向を向いている場合にそのサブツリーが有効であるかどうかをノードごとに追跡します。 2 番目のパスでは、「外部サブツリー」からの有効性寄与を再ルートして維持します。 

これにより、問題はテスト ケースごとに O(n) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | DP を再ルート中 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 固定された任意のルート、たとえばノード 1 を仮定し、制約に基づいてエッジの方向の実現可能性を計算します。

1. すべてのエッジ u-v について、u が v の親になれるか、v が u の親になれるかを判断します。 これは、指定された不等式ルールに従って重みを比較することで直接導出されます。 指示が条件に違反する場合、禁止としてマークされます。 
2. 各エッジで一方または両方の方向が許可されるツリー エッジ上に有向制約グラフを構築します。 
3. 最初のルートから DFS を実行して DP 値を計算します。`down[u]`u がルート方向のすべての子の親である場合に、u のサブツリーが有効かどうかを表します。 計算中に、すべての子 v が u → v の方向が許可され、v のサブツリーも有効であることを確認します。 
4. 計算後`down`、2 回目の DFS を実行して計算します`up[u]`、u をその外部部分のルートとみなした場合に、ツリーの残りの部分 (u のサブツリーの外側) を有効に方向付けることができるかどうかを表します。 
5. 再ルートの場合、ルートを u から子 v に移動するときに、u から v のサブツリーの寄与を削除し、v の親コンテキストとしてツリーの残りの部分の寄与を追加することによって、妥当性状態を更新します。この遷移では、事前に計算されたエッジ方向の妥当性が使用されます。 
6. ノード u は、その下向きサブツリーと上向き補数制約の両方が満たされる場合、有効なルートです。 

### なぜ効果があるのか

 正確さは、ツリーを独立したエッジ制約に分解することにかかっています。 各エッジは、ローカルな方向制限のみを課します。 ルートを修正すると、すべてのエッジの方向が一意に決定され、妥当性は純粋にエッジごとの妥当性チェックの結合によって決まります。 再ルート DP は、既に計算されたサブツリーの実現可能性をエッジ遷移ごとに一定時間で転送することにより、考えられるすべてのルートが確実に評価されるようにします。 両方の DFS パスですべてのエッジが 1 回だけ考慮されるため、構成が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [0] + list(map(int, input().split()))
        
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        # we interpret constraint as: parent p, child c must satisfy a[c] >= a[p] / 2
        # equivalently: 2*a[c] >= a[p]

        def ok_parent_child(p, c):
            return 2 * a[c] >= a[p]

        down = [1] * (n + 1)
        parent = [0] * (n + 1)

        order = []

        stack = [1]
        parent[1] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                parent[v] = u
                stack.append(v)

        for u in reversed(order):
            for v in g[u]:
                if v == parent[u]:
                    continue
                if not ok_parent_child(u, v):
                    down[u] = 0
                if down[v] == 0:
                    down[u] = 0

        up = [1] * (n + 1)
        up[1] = 1

        def dfs(u):
            for v in g[u]:
                if v == parent[u]:
                    continue
                # when rerooting, u becomes child of v, so check v->u direction
                if not ok_parent_child(v, u):
                    up[v] = 0
                else:
                    up[v] = up[u]
                dfs(v)

        dfs(1)

        ans = 0
        for i in range(1, n + 1):
            if down[i] and up[i]:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず条件を各エッジでの単純な方向性の実現可能性テストに変換します。 の`down`配列は、ルート化されたサブツリー内で、親の制約に違反する子がないことを保証します。 の`up`配列は、再ルート時に補完側から実現可能性を伝播します。 最終的な答えは、両方を満たすノードをカウントします。 

主な微妙な点は、制約を方向ルールとして正しく解釈し、両方の DFS パス中に正しい方向でチェックされるようにすることにあります。 親から子に移動する場合、再ルート手順では方向を逆にする必要があります。 

## 実用的な例

 ### 例 1

 値 a = [2, 3, 6] を持つ単純なチェーン 1-2-3 を考えてみましょう。 

各ノードの有効性をルートとしてテストします。 

| ルート | エッジの方向 | 妥当性チェック結果 |
 | --- | --- | --- |
 | 1 | 1→2→3 | 3 ≥ 2/2、6 ≥ 3/2 が成り立ちます |
 | 2 | 2→1、2→3 | 両方向を確認してください |
 | 3 | 3→2→1 | 両方向を確認してください |

 ルート 1 では、子が十分に大きいため、すべての制約が当てはまります。 ルート 2 の場合、不等号の方向によってはエッジ 2→1 が失敗する可能性があります。 ルート 3 についても同様に、逆の制約をチェックします。 

この例では、ルートを変更するとエッジの方向が反転し、有効性がどのように変化するかを示します。 

### 例 2

 中心 1 が 2、3、4 に接続された星形。値は a1 = 10、その他 = 3 です。 

| ルート | 構造 | キー制約 |
 | --- | --- | --- |
 | 1 | 1→(2,3,4) | 3 ≥ 10/2 が成り立ちます |
 | 2 | 2→1→(3,4) | 10 ≥ 3/2 および 3 ≥ 10/2 をチェックしてください。 

ルート 1 のみが有効です。これは、違反方向にある小さいノードの子として大きいノードが存在することを回避するためだけです。 

これらのトレースは、実現可能性がローカル エッジの比較だけではなく、グローバルな方向性に依存することを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべてのノード値が同一である場合です。 その状況では、2・a[child] ≥ a[parent] という形式のすべての不等式が自明に成立するため、すべてのノードが有効なルートになるはずです。 アルゴリズムはこれを処理します。`ok_parent_child`チェックは true を返し、両方とも`down`そして`up`すべてのノードで 1 のままです。 

もう 1 つのエッジ ケースは、厳密に増加するチェーンです。 パスに沿って値が増加する場合、再ルート時に方向を反転すると、内部ノードの制約に違反する可能性があります。 再ルート DP により、大きなノードが小さなノードの子になるときに、`up`伝播によりその設定は即座に無効になり、誤ったカウントが防止されます。 

最後のエッジケースは、中心が葉よりもはるかに大きい星形です。 ルートとしてのリーフが中心を強制的に小さなノードの子にし、違反を引き起こすため、中心のルートのみが機能します。 DFS は、上向きパス中にこれらの再ルートされた状態を無効として正しくマークし、正しいルートのみがカウントされるようにします。
