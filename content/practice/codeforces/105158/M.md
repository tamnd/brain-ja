 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースには、同じ長さの 2 つの整数配列があります。 すべてのインデックスについて、その位置の値を「調整」することができますが、その調整は任意ではありません。 位置として選択する最終的な値$i$元の値を中心とする対称間隔内に留まらなければなりません$a_i$、その間隔の半幅はグローバルパラメータに比例します。$k$乗算$b_i$。 

正式には、インデックスごとに$i$、最終的な値を選択できます$x_i$元の値からの距離が次の範囲内になるようにします。$k \cdot b_i$。 そういったものをすべて選択した上で、$x_i$、すべての最終値が等しくなるようにしたいと考えています。 目標は、最小の非負の整数を見つけることです。$k$これが可能なのです。 

主な難点は、ポジションごとに柔軟性のスケールが異なることです。$b_i$したがって、各要素の到達可能な範囲は次のように異なる速度で増加します。$k$が増加します。 私たちは事実上、すべての調整可能な間隔内に同時に存在する単一の整数点がいつ存在するのかを尋ねているのです。 

制約は大きく、すべてのテスト ケースの合計の長さは最大で$3 \cdot 10^5$。 これにより、考えられるすべての目標値を試したり、すべての選択肢をシミュレートしたりするアプローチは即座に除外されます。$k$。 テストケースごとの二次関数はすべて失敗します。$O(n \log A)$広範囲にわたる繰り返しスキャンを避けるために、慎重に構成する必要があります。 

間隔がほとんど重なっていない場合、または単一の整数点でのみ交差している場合、微妙なエッジ ケースが発生します。 たとえば、すべてが$a_i$等しい場合、$k = 0$有効です。 逆に、1 つの要素が非常に小さい場合は、$b_i$、それがボトルネックとなり、より大きなサイズを強制する可能性があります。$k$たとえ他の要素が非常に柔軟であったとしても。 

もう 1 つの重要なケースは、交差点がすべてから遠く離れた大きな値でのみ空ではなくなる場合です。$a_i$。 「すべてを平均に近づける」という単純な考えは失敗します。最終値は平均値の近くにある必要はなく、拡張されたすべての区間内にあればよいからです。 

## アプローチ

 強引な解釈は修正することです$k$共通の整数が存在するかどうかを確認します$x$あらゆる人にとって$i$、$x$狭間にある$[a_i - k b_i, a_i + k b_i]$。 これにより、問題は次の交差かどうかをテストすることになります。$n$間隔は空ではありません。 

固定の場合$k$、このチェックは単純です。すべての左端点の最大値とすべての右端点の最小値を計算し、左の最大値が右の最小値より大きくないかどうかを確認します。 これは線形時間で実行されます。 

ただし、すべて試してみると、$k$不可能だから$k$と同じ大きさにすることができます$10^9$、各値をチェックすると、次のように機能します。$10^9$。 バイナリ検索でも$k$必要$O(n \log 10^9)$これは許容できますが、実際には、実現可能条件の構造を観察することで二分探索を完全に回避できます。 

重要な観察は、実現可能性は一連の不等式に依存するということです。$$a_i - k b_i \le x \le a_i + k b_i$$全員にとって$i$、これは次と同等です。$$\max_i (a_i - k b_i) \le \min_i (a_i + k b_i)$$左辺は の凸増加関数です$k$区分線形の意味で、右側は凸状の減少関数です。 最小の$k$不等式が成り立つ場所は、まさに最も厳しい制約のペアが満たされる場所です。 検索する代わりに$k$、制約間のペアごとの一貫性をチェックするように条件を再定式化できます。これは、極端な違いのみを考慮することになります。 

より具体的には、最悪のペアによって答えが決まります$(i, j)$、最適な状態で$x$、すべての要素がそれに「到達」できる必要があり、最も難しい制限は、傾きが異なる 2 つの要素のバランスを取ることから生じます。$b_i$距離に比べて最も異なるのは$a$-空間。 これにより、次のような式が得られます。$$k \ge \max_{i,j} \frac{|a_i - a_j|}{b_i + b_j}$$直感的には、2 つの要素が同じ点で交わる必要がある場合、それらの到達可能な間隔は重複する必要があり、まさにこの制約が強制されます。 

したがって、問題を、変換されたペアごとの比率の最大値を計算することに縮小します。 これは、既知のトリックを使用して、テスト ケースごとに線形時間で実行できます。$a_i$隣接しないペアには、より厳しい制約を生み出す中間点があるため、並べ替えられた順序で隣接するペアのみが最大比率を定義できます。

 ## アルゴリズムのチュートリアル

 1. インデックスを次の値で並べ替えます。$a_i$。 これにより、要素の違いがなくなるように配置されます。$a$局所的に構造化されているため、近隣間に最悪の制約が現れます。 
2. ソートされた配列内の隣接するペアをスキャンします。 各ペアごとに$(i, i+1)$、候補値を計算します$$k_{i} = \frac{a_{i+1} - a_i}{b_i + b_{i+1}}$$これは、それらの間隔がある時点でちょうど接触するように強制することによって生じます。 
3. そのようなすべての候補の最大値を追跡します。 この最大値は最小値です$k$これにより、隣接するすべてのペアが重複する到達可能な範囲を持つことができます。 
4. この最大値を、最も近い整数に切り上げて出力します。$k$整数でなければなりません。 

隣接するペアのみをチェックする理由は、ソート順で遠く離れた 2 つの要素には、直接の制約を支配する中間制約がすでに存在するためです。 遠いペアが最悪のケースである場合、それは区間の拡大によって引き起こされる三角形のような構造との矛盾を意味します。 

### なぜ効果があるのか

 最適解では、すべての最終値が単一点に集約されます。$x$。 各インデックスは、次の点を中心とする間隔を定義します。$a_i$半径あり$k b_i$。 実現可能性とは、すべての区間が交差することを意味します。 

で並べ替えると$a_i$、グローバル交差に対する最も厳しい障害物は、この順序でいくつかの隣接する間隔の間に現れる必要があります。 2 つの隣接しない間隔がボトルネックを定義している場合、中央の要素の間隔によって重なりがすでにより厳密に制限されます。 これにより、必要な最大値が確立されます。$k$は隣接する相互作用によって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        arr = sorted(zip(a, b))
        ans = 0.0

        for i in range(n - 1):
            a1, b1 = arr[i]
            a2, b2 = arr[i + 1]
            if a2 == a1:
                continue
            ans = max(ans, (a2 - a1) / (b1 + b2))

        out.append(str(int((ans + 1e-12) // 1 + (1 if ans % 1 > 0 else 0))))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、各テスト ケースを次の基準で並べ替えることから始まります。$a_i$これは、問題をローカル チェックに限定するために不可欠です。 隣接するペアのスキャンにより、間隔の接触条件から導出される制限比率が計算されます。 

計算では浮動小数点演算を使用して比率を推定し、最も近い整数に切り上げます。$k$は積分でなければなりません。 小さなイプシロンは、値が整数に非常に近い場合に精度エラーを回避するために使用されます。 

微妙な問題は平等に扱うことです$a_i$。 その場合、分子はゼロであるため、ペアは制約に寄与しません。$k$ローカルで動作します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、次のような場合です。$a_i$等しいです。 例えば：```
a = [7, 7, 7]
b = [1, 100, 1]
```すべての間隔は同じ点に集中するため、$k = 0$動作します。 このアルゴリズムでは、並べ替えられた隣接する要素間の差分がゼロであるとみなされるため、すべての比率がゼロになり、答えは 0 のままになります。 

もう 1 つのエッジケースは、次のような場合です。$b_i$は非常に小さいです。 例えば：```
a = [1, 100]
b = [1, 1000000]
```小さいもの$b_i$大きな力を強いる$k$1 つの要素がほとんど動かないためです。 隣接比率はこの制約を直接捉えており、アルゴリズムは他の要素の大きな柔軟性に惑わされることなく、タイト ペアを正しく優先します。 

最後のエッジケースには、大きなギャップが含まれます。$a$でも大きい$b$ここで、素朴な直観は制約がないと示唆するかもしれません。 この比率は結合された柔軟性に対して距離のバランスを明示的にとっているため、アルゴリズムは依然としてトレードオフを正確に捉えています。
