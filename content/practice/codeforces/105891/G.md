 ## 解決策
 ## 問題の理解

 私たちは一列の生徒を与えられ、それぞれに固定スコアが割り当てられています。 教師は繰り返し生徒を選択し、その生徒を行から削除できるかどうかを確認します。 学生かどうか`i`は、左側と右側の生徒の相対的な価値観にのみ依存します。`i`その瞬間。 

生徒の周囲のシーケンスが特定の方法で「混合」されている場合、生徒は除去可能になります。 具体的には、2 つの対称パターンのいずれかで、左右に分かれた高得点と低得点の両方の証拠がある場合、生徒は失踪します。 1 つのパターンでは左側に小さくない値、右側にそれ以上の値が必要で、もう 1 つはこれらの役割を交換します。 

教師は任意の順序で削除を選択でき、削除後に残りの生徒が移動するため、条件が動的に評価されます。 目標は、削除できる生徒の数を最大化すること、または同等に、削除順序をどれほど賢く選択しても削除できない生徒の数を最小限に抑えることです。 

制約により、最大で`2 × 10^5`したがって、すべての削除を試行したり、配列全体をスキャンして条件を繰り返し再計算したりするソリューションは、すぐに遅すぎます。 除去に対する二次または二次に近い動的シミュレーションは機能しません。 すべての有効な削除命令の下で、どの要素が本質的に「安定」であるかを特徴付ける必要があります。 

アレイがモノトーンの場合、微妙なエッジケースが現れます。 次のような厳密に増加する配列では`1 2 3 4 5`、すべての中央の要素には、左側の小さな要素と右側の大きな要素の両方があるため、それらの多くは削除可能になります。 ただし、片側が空であるため、条件が満たされないため、エンドポイントの動作が異なります。 正しいソリューションは、境界位置を正しく処理する必要があります。 

もう 1 つの注意が必要なケースは、値が繰り返される場合です。たとえば、`3 1 3 2 3`。 ローカル比較だけでは十分ではありません。 重要なのは、ポジションの反対側に厳密に大きい要素と厳密に小さい要素が少なくとも 1 つ存在するかどうかです。 

## アプローチ

 直接シミュレーションでは、配列を繰り返しスキャンし、現在削除可能な生徒をすべて見つけて 1 人を削除し、それ以上削除できなくなるまで繰り返します。 学生の小切手は両面をスキャンする必要があり、費用がかかります`O(n)`、これは潜在的に起こります`O(n)`につながる`O(n^2)`あるいはさらに悪いことに。 と`n`まで`2 × 10^5`、これは実現可能な限界をはるかに超えています。 

重要な観察は、削除条件は隣接性やローカル構造には依存せず、特定の不平等が各側に存在するかどうかのみに依存するということです。 プレフィックスとサフィックスの情報の観点からすべてを言い換えると、削除をシミュレートすることなく、位置が削除可能かどうかを判断できます。 

生徒は、その値が分割された方法で「挟まれている」場合にのみ削除可能になります。つまり、一方の側に少なくとも同じ大きさの値があり、もう一方の側に最大でも同じ大きさの値があります（または対称的な状況）。 これは、削除可能性が、配列に相対的な位置に分散された大きい値と小さい値の両方が含まれているかどうかに依存することを意味します。`i`。 

決して排除できない生徒とは、接頭辞の最大値、接頭辞の最小値、接尾辞の最大値、または接尾辞の最小値という、少なくとも 1 つの方向性の意味で極端なままである生徒です。 これらの極端な特性の少なくとも 1 つによって保護されていない位置は、適切な削除順序を選択することによって最終的に公開され、削除される可能性があります。 

したがって、削除をシミュレートする代わりに、プレフィックス最大値、プレフィックス最小値、サフィックス最大値、およびサフィックス最小値の 4 つのセットを事前計算します。 これらのセットの少なくとも 1 つに属するインデックスは安全であり、最終構成に残ります。 答えは彼らの組合の規模です。

 | プレフィックス/サフィックスの極度分類 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左から右にスキャンしながらプレフィックスの最大値を計算し、これまでに確認された最大値であるすべての位置をマークします。 これにより、左派から支配できない要素が捕捉されます。 
2. 同じスキャンでプレフィックスの最小値を計算し、これまでに確認された最小の位置をマークします。 これらの要素は、左側から「下に超える」ことはできません。 
3. 右から左にスキャンしながらサフィックスの最大値を計算し、サフィックスの最大値である位置をマークします。 これらを右から支配することはできません。 
4. 同様に右から左にサフィックスの最小値を計算します。 
5. 4 つのカテゴリのいずれかに含まれるすべてのインデックスにマークを付けます。 最終的な答えは、マークされたインデックスの数です。 

各カテゴリが重要である理由は、削除には、相反する方向に大きい値と小さい値の両方が存在する必要があるためです。 位置がプレフィックスの最大値である場合、左側にはそれより大きいものはなく、削除可能性をトリガーできる 2 つの方法のうちの 1 つがブロックされます。 同じ考え方が他の 3 つのケースにも対称的に当てはまります。 

### なぜ効果があるのか

 除去可能条件は、両方の値以上を同時に満たす必要があります。`a[i]`片側で以下の値`a[i]`もう一方の側では、分割構成になっています。 位置が 4 つの方向のいずれかにおいて極端である場合、少なくとも 1 つの側が、その位置を「挟む」ために必要な不等構造を提供できません。 したがって、そのような位置は、一連の欠失によって完全に露出されることはありません。 逆に、これらの極端な制約によって保護されていない位置は、最初にブロック要素を除去することによって取り外し可能にすることができ、最終的には必要な分割構成が作成されます。 これにより、問題は、少なくとも 1 つの方向で極値となるすべてのインデックスを識別することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

pref_max = [False] * n
pref_min = [False] * n
suf_max = [False] * n
suf_min = [False] * n

cur = -10**18
for i in range(n):
    if a[i] >= cur:
        pref_max[i] = True
        cur = a[i]

cur = 10**18
for i in range(n):
    if a[i] <= cur:
        pref_min[i] = True
        cur = a[i]

cur = -10**18
for i in range(n - 1, -1, -1):
    if a[i] >= cur:
        suf_max[i] = True
        cur = a[i]

cur = 10**18
for i in range(n - 1, -1, -1):
    if a[i] <= cur:
        suf_min[i] = True
        cur = a[i]

ans = 0
for i in range(n):
    if pref_max[i] or pref_min[i] or suf_max[i] or suf_min[i]:
        ans += 1

print(ans)
```このコードは、配列全体で 4 つの線形スキャンを計算します。 各スキャンは、対応する方向でこれまでに確認された最良の値を維持し、新しい極値に達する位置をマークします。 

最後のループは、少なくとも 1 つの極値カテゴリに属する​​インデックスを単純にカウントします。 これにより、構造的特徴がわかってしまえば時間がかかりすぎて不必要となる欠失のシミュレーションが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    pref_max = [False] * n
    pref_min = [False] * n
    suf_max = [False] * n
    suf_min = [False] * n

    cur = -10**18
    for i in range(n):
        if a[i] >= cur:
            pref_max[i] = True
            cur = a[i]

    cur = 10**18
    for i in range(n):
        if a[i] <= cur:
            pref_min[i] = True
            cur = a[i]

    cur = -10**18
    for i in range(n - 1, -1, -1):
        if a[i] >= cur:
            suf_max[i] = True
            cur = a[i]

    cur = 10**18
    for i in range(n - 1, -1, -1):
        if a[i] <= cur:
            suf_min[i] = True
            cur = a[i]

    ans = 0
    for i in range(n):
        if pref_max[i] or pref_min[i] or suf_max[i] or suf_min[i]:
            ans += 1

    return str(ans)

# minimum size
assert run("1\n5") == "1", "single element"

# strictly increasing
assert run("5\n1 2 3 4 5") == "5", "increasing"

# strictly decreasing
assert run("5\n5 4 3 2 1") == "5", "decreasing"

# mixed values
assert run("5\n5 1 4 2 3") == "5", "mixed"

# all equal
assert run("4\n7 7 7 7") == "4", "equal values"

 ## 特殊なケース

 次のような単一要素配列の場合`10`、4 つのスキャンすべてで、すべての方向において唯一の位置が極値として即座にマークされます。 左側も右側もないため、アルゴリズムはそれを生存者として正しくカウントします。 

次のような厳密に増加するシーケンスの場合`1 2 3 4 5`、すべての位置はプレフィックスの最大値です。 プレフィックス スキャン中に、各要素が新しい実行最大値になるため、すべての位置がマークされ、完全な生存セットが生成されます。 

次のような等しい値を持つシーケンスの場合`3 3 3 3`、すべての要素は、等価処理に応じて、異なる時点で同時にプレフィックス最大値とプレフィックス最小値になります。 スキャンではすべての位置がマークされ、最終的な結合にはすべてのインデックスが正しく含まれます。
