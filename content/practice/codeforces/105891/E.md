 ## 解決策
 ## 問題の理解

 ターゲット文字列を順番に構築するという非常に制約された入力プロセスをシミュレートするように求められますが、工夫が必要です。現在の文字列の末尾にのみ文字を追加する必要はありません。 代わりに、部分的に構築された文字列内には移動可能なカーソルがあるため、新しい文字を任意の位置に挿入できます。 コスト モデルには 3 つのコンポーネントがあります。指定されたコスト マトリックスで左手の指をある文字から別の文字に変更すること、ステップごとに固定コストで現在の文字列内でカーソルを左右に移動すること、そして同じく固定コストで現在選択されている文字を印刷することです。 

最初は文字列は空で、カーソルは位置 0 にあり、左手の指は文字の上に置かれます。`a`。 目標は、これらの操作のシーケンスを実行して、最終的な文字列が指定されたターゲット文字列と順番に正確に一致するようにすることです。 

重要な微妙な点は、最終的な文字列は固定されていても、それを「構築」する順序は固定されていないことです。 先に文字を挿入するか、または後に文字を挿入するかを選択できますが、これにより文字列が動的に増加するため、カーソルの移動コストが変化します。 指を動かすコストは文字のみに依存しますが、カーソルの移動は現在の部分レイアウトに依存します。 

制約があるため、構造が重要になります。 ターゲット文字列の長さは最大 20 であり、メモ化を行わないすべての挿入シーケンスの順列に対する指数関数的な検索は除外されます。 アルファベットのサイズは最大 26 文字であるため、指の位置の追跡は可能な状態で実行可能です。 コスト行列は三角不等式によりメトリックに似ており、直接遷移を超えた間接的なフィンガー パスを考慮する必要がありません。 

単純に解釈すると、考えられるすべての広告掲載オーダーとカーソル位置をシミュレートすることになります。 n = 20 の場合でも、建設命令の並べ替えの数は天文学的に多いため、これはすぐに不可能になります。 

微妙なエッジケースは、同一の文字と対称的なコストから生じます。 たとえば、すべてのコストがゼロで t がゼロの場合、どの挿入順序も最適ですが、単純な貪欲な戦略では、将来の挿入を考慮せずに早期の位置決定にコミットするため、最適とは言えないカーソル パスに固定される可能性があります。 

文字が繰り返されると、別の失敗モードが表示されます。 文字列が次のような場合`ababa`、貪欲な「常に次のオカレンスを最終順序で挿入する」戦略は、後で挿入するという事実を無視します。`a`まず、中間ステップでのカーソルの移動を減らすことができます。 

## アプローチ

 強引なアプローチでは、各ステップで次に挿入する残りの位置を選択することで文字列を構築するあらゆる可能な方法を列挙し、カーソルの動きと指の動きを正確にシミュレートしようとします。 各挿入ステップは文字列の現在の構造に依存するため、状態は動的に変化します。 最適性を無視して可能性を数えただけでも、最大 n 個あります。 それぞれの広告掲載オーダーに対して最大 n 回のカーソル移動をシミュレートし、実現可能な限界をはるかに超える階乗増加につながります。 

重要な点は、挿入順序は柔軟ですが、文字の最終的な相対順序はターゲット文字列内のインデックスによって固定されるということです。 これは、すべての部分的な構築がすでに挿入されている位置のサブセットの選択に対応し、現在の構造がそのサブセットによって完全に決定されることを意味します。 特に、新しい文字が挿入される位置は、その左側にすでに選択されているインデックスがいくつあるかによって一意に決定されます。 

これにより、問題はインデックスのサブセットにわたる状態空間に変わります。ここで唯一の曖昧さはカーソル位置と指の位置です。 サブセットを修正すると、現在の文字列の構造が暗黙的に定義されるため、カーソルの移動はサブセットの決定的な関数になります。 

したがって、順列に対する指数関数的な検索からサブセットに対する動的プログラミングに移行します。各状態は、どの文字が配置されているか、その誘導された順序でカーソルが現在どこにあるか、指が現在どの文字を保持しているかをエンコードします。 トランジションは、次に挿入する文字を選択し、カーソルと指の両方を適切に移動するコストを支払うことに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | カーソルと指の状態を含むサブセット DP | O(2^n · n^2 · m) | O(2^n・n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を、部分的に構築された文字列のスナップショットとして扱います。 スナップショットは、ターゲット文字列のどのインデックスがすでに挿入されているか、カーソルがこの部分文字列内のどこに現在位置しているか、左手の指がどの文字を保持しているかによって定義されます。 

1. 部分的に構築された文字列はすでに挿入されたインデックスのセットに正確に対応するため、ターゲット文字列内の位置のサブセットごとに DP 状態を定義します。 これが機能するのは、サブセットが固定されると挿入順序は重要ではなくなり、結果として生じる相対順序のみが重要になるためです。 
2. 各サブセットについて、現在の部分文字列内のカーソル位置も追跡します。 サブセットのサイズが k の場合、カーソルは文字間の位置を表す 0 から k までの任意の整数の位置に置くことができます。 すべての有効なカーソル移動はこの線形構造に沿った隣接するスワップであるため、これで十分です。 
3. 文字を変更すると、前の文字に応じてコストが発生するため、現在の指の文字も追跡します。 これがなければ、将来の移行に関する必要な情報が失われることになります。 
4. 空のサブセット、カーソルを位置 0、指を位置 0 に設定して DP を初期化します。`'a'`。 これは、印刷が行われる前の初期構成と一致します。 
5. 状態から、サブセットにまだ存在しないすべての文字インデックスの挿入を試みます。 インデックス i の文字を選択すると、現在の部分文字列内でのその挿入位置が、厳密に i より小さい既に選択されたインデックスの数として計算されます。 これが機能するのは、部分文字列が常に元のインデックスの順序を維持しているためです。 
6. カーソルを現在の位置から挿入位置に移動するには、これら 2 つの位置間の距離に比例したコストを支払います。 移動後は固定の印刷コストを支払い、サブセットを更新します。 
7. また、指を現在の文字からターゲット文字列のインデックス i の文字に移動するコストも支払います。 
8. 新しいサブセット、新しいカーソル位置 (挿入ではカーソルが新しい文字の右側に配置されるため、挿入位置に 1 を加えたものになります)、および新しい指の位置の DP を更新します。 

すべての状態を処理した後、答えはすべての完全なサブセットの中での最小コストになります。 

### なぜ効果があるのか

 正確かどうかは、部分的に構築された文字列の構造が、挿入されたインデックスのサブセットによって一意に決定されるという事実に依存します。 これが修正されると、すべてのカーソル位置は、誘導された順序付けで明確に定義された位置に対応し、すべての挿入位置が決定的になります。 DP は、冗長性を持たずにすべての有効な挿入シーケンスを探索します。また、すべての操作コストはローカル状態情報 (サブセット、カーソル位置、指の位置) のみに依存するため、隠れた依存関係が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, t = map(int, input().split())
    s = input().strip()
    cost = [list(map(int, input().split())) for _ in range(m)]

    INF = 10**18

    # precompute index of each character
    idx = [ord(c) - ord('a') for c in s]

    # dp[mask][pos][c] = min cost
    # mask up to 2^20, pos up to 20, c up to 26
    N = 1 << n
    dp = [[[INF] * m for _ in range(n + 1)] for _ in range(N)]

    dp[0][0][0] = 0  # finger at 'a'

    for mask in range(N):
        k = mask.bit_count()

        # precompute rank positions for each i
        for pos in range(k + 1):
            for c in range(m):
                cur = dp[mask][pos][c]
                if cur == INF:
                    continue

                for i in range(n):
                    if mask & (1 << i):
                        continue

                    # compute insertion position
                    left_count = 0
                    for j in range(i):
                        if mask & (1 << j):
                            left_count += 1

                    new_pos = left_count

                    nmask = mask | (1 << i)

                    move_cursor = abs(pos - new_pos) * t
                    move_finger = cost[c][idx[i]]
                    total = cur + move_cursor + move_finger + t

                    # after insertion cursor is to the right of inserted char
                    dp[nmask][new_pos + 1][idx[i]] = min(
                        dp[nmask][new_pos + 1][idx[i]],
                        total
                    )

    ans = INF
    full = N - 1
    for pos in range(n + 1):
        for c in range(m):
            ans = min(ans, dp[full][pos][c])

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルには、部分的な構築状態に到達するための最小コストが格納されます。 トランジションは、挿入する次の文字を明示的に選択し、すでに挿入されているインデックス間のランクを使用して、現在のシーケンス内でのその位置を計算します。 カーソルの移動は、t でスケールされたこれらのランクの単純な絶対差として処理されます。 

指の動きはコスト マトリックスから直接取得され、印刷コストは挿入ごとに 1 回追加されます。 更新ステップでは、新しいカーソル位置が挿入された文字の右側に慎重に配置されます。そのため、`new_pos + 1`。 

## 実用的な例

 ターゲット文字列が次のような小さなケースを考えてみましょう。`ab`二文字で。 

| ステップ | マスク | カーソル位置 | 指 | アクション | 追加コスト | 状態 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 00 | 0 | | 開始 | 0 | dp[00][0][a] |
 | 1 | 01 | 1 | | 0 に a を挿入 | t | dp[01][1][a] |
 | 2 | 11 | 1 | b | 1 に b を挿入 | コスト(a,b)+t | 最終 |

 このトレースは、自然な順序で挿入すると、必要なシフトを超えてカーソルが移動しないことを示しています。 

ここで考えてみましょう`ba`、最適な戦略が異なります。 

| ステップ | マスク | カーソル位置 | 指 | アクション | 追加コスト | 状態 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 00 | 0 | | 開始 | 0 | dp[00][0][a] |
 | 1 | 10 | 0 | b | 最初に b を挿入 | コスト(a,b)+t | dp[10][0][b] |
 | 2 | 11 | 1 | | を前に挿入します | t | 最終 |

 これは、広告掲載オーダーによってカーソルのコスト構造が変化し、DP が両方の可能性を捉えていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^n · n^2 · m) | 各サブセットは最大 n 個の遷移を考慮し、それぞれが単純形式で O(n) のランクを計算します。 
| スペース | O(2^n・n・m) | DP はカーソルと指の状態を含むすべてのサブセットを保存します。 

n ≤ 20 という制約により 2^n が実現可能になり、定数が小さく、アルファベットのサイズが制限されているため、追加の係数は許容範囲内に収まります。

 ## 特殊なケース

 のような文字列の場合`aaaa`、最適な戦略では、指を離れる必要はありません。`a`したがって、すべての DP 移行では不必要なコストを回避する必要があります。 サブセット DP はこれを自然に処理します。なぜなら、`a`に`a`。 

次のような反転文字列の場合`cba`の場合、アルゴリズムは両方の広告掲載オーダーを正しく評価します。 最初に挿入すると`c`、 それから`b`、 それから`a`、カーソルの位置が大幅に変わりますが、DP は両方の注文を調べて、安い方を選択します。 

t = 0 の場合、カーソルの動きが自由になり、最適解は指の動きのみを最小限に抑えることになります。 カーソル コストがトランジションから消え、指のトランジションのみが関連するため、DP は引き続き機能します。
