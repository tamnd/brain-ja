 ## 解決策
 ## 問題の理解

 n 個の連続するセグメントに分割されたストリップが与えられます。 各セグメントにはすでに初期色が設定されていますが、その開始構成は、構造のソースとしての役割を除いて、最終目標にとってはあまり重要ではありません。 私たちが実行できる実際の操作は、連続した区間を選択し、それを完全に単一の色 c に再描画することです。 これを行うには、その色の固定価格に加えて、再描画する間隔の長さに等しい追加コストがかかります。 

このタスクは、1 から n までのすべての色 c について独立して、すべてのセグメントが色 c になるようにストリップ全体を再描画するために必要な最小総コストを計算することです。 

n が 2 × 10^5 までの制約により、すべての区間を明示的に試行する解は即座に除外されます。 可能な再描画操作の数は O(n^2) であり、すべてのセグメント パーティションを暗黙的に考慮するアプローチは失敗します。 繰り返されるサブ構造のコストの再計算を回避する構造が必要です。 

微妙な点は、初期カラーが重要なのは、追加の再ペイント コストを支払わずに同じターゲット カラーのセグメントをマージできる方法のみであるということです。 この構造を無視し、1 回の操作ですべてを直接再描画すると仮定する単純なアプローチは、初期設定にターゲット カラーの有用な連続ブロックが既に含まれている場合には間違っている可能性があります。 

典型的な失敗例の 1 つは、ストリップが 1 つの不一致を除いてすでにほぼ均一になっている場合です。 たとえば、配列が次の場合、`[1, 1, 2, 1, 1]`そして私たちは色が欲しいのです`1`、単純な解決策では、コスト範囲全体を再描画する可能性があります。`w1 + 5`ただし、最適解では中央のブロックのみが再描画されます。`[3,3]`とコスト`w1 + 1`。 重要なアイデアは、ターゲット カラーと既に一致しているセグメントを有用な操作間の区切り文字として扱うことで、再描画を選択的に回避できるということです。 

## アプローチ

 強引な戦略は、ターゲット カラー c を固定し、配列を再描画操作に分割するあらゆる可能な方法を試すことです。 各操作では間隔が選択され、間隔は複雑に重なる可能性があるため、状態空間は指数関数的になります。 「互いに素な間隔のサブセットを選択する」という単純化でも、状態ごとに O(n^2) 個の遷移が発生し、セグメントに対する動的プログラミングを介して実装すると、最悪の場合、合計で O(n^3) 近くの複雑さになります。 

ターゲットの色の観点から問題を再解釈すると、この構造は管理可能になります。 最終的な配列を完全にカラー c にしたいとします。 初期配列に既に色 c が含まれているセグメントは再描画する必要がありません。さらに重要なのは、これが自然なセパレーターとして機能することです。これらの位置にまたがって再描画する必要はありません。再描画するとコストが増加するだけでメリットがありません。 

これにより、配列がまだカラー c ではないセグメントの最大ブロックに分割されます。 このような各ブロック内で、再描画操作を実行して、すべてを c に変換する必要があります。 ここで重要な観察は、ブロック内ではコストは長さと操作の数のみに依存し、各操作には固定のオーバーヘッド wc と長さの線形コストが含まれるということです。 この構造により、基本的に各非 C ブロックを個別に扱い、最適なコストを合計する貪欲または間隔 DP の簡略化が可能になります。 

最適な解決策は、配列を色ごとに 1 回スキャンし、その色ではない連続セグメントからの寄与を蓄積することです。 このような各セグメントは、その長さに基づいたコストに加え、セグメント ブロックごとに wc を 1 回アクティブ化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | インターバルにわたるブルート フォース / DP | O(n^3) 以上 | O(n^2) | 遅すぎる |
 | カラーごとのリニアスキャン | O(n^2) 最悪の場合の合計、再利用によって最適化 | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 ターゲットカラー c を固定し、配列全体を c に変換するための最小コストを計算します。 

1. 配列を左から右にスキャンし、現在の色が c ではない最大の連続セグメントを特定します。 これらのセグメントは、ある時点で再描画する必要がある領域を表します。 1 回の操作でセグメントを再描画することがすでに最適な場合、セグメント内で分割する必要はありません。分割すると、長さのコストが削減されずに余分な WC コストが発生するためです。 
2. 長さ len の各セグメントについて、1 回の操作で再描画すると wc + len のコストがかかることがわかります。 複数の作業に分割すると、各作業でトイレが追加されるため、分割すると総コストが増加するだけです。 これにより、「セグメントごとに 1 つの操作」が最適化されます。 
3. すべての非 c セグメントの合計長を sumLen として累積し、そのようなセグメントがいくつ存在するかを blockCnt としてカウントします。 
4. 色 c の合計コストは、wc × blockCnt + sumLen になります。 
5. このプロセスをすべての色 c に対して個別に繰り返し、すべての結果を出力します。 

これが機能する主な理由は、ターゲットの色がすでに存在する場合は常に、初期配列が作業を独立したコンポーネントに分割するためです。 これらの位置は再ペイントする価値がないため、固定境界として機能します。 各コンポーネント内では線形コストが支配的であり、マージ操作は常に有益です。 

### なぜ効果があるのか

 このアルゴリズムは、c に等しくない位置の最大連続間隔はすべて、少なくとも 1 回の再ペイント操作で完全にカバーされなければならないという不変条件に依存しています。また、それを複数の操作でカバーすると、ペイントの合計の長さを減らすことなく追加の WC が追加されるため、厳密にコストが増加します。 したがって、最適なソリューションは常に、そのような最大間隔ごとに 1 つの操作を正確に選択し、これらの間隔への分解は初期構成によって固定されるため、ソリューションは決定的で最適なものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    w = list(map(int, input().split()))

    # precompute positions of each color
    pos = [[] for _ in range(n + 1)]
    for i, c in enumerate(a):
        pos[c].append(i)

    res = [0] * (n + 1)

    for c in range(1, n + 1):
        if not pos[c]:
            # if color doesn't exist, we must repaint everything in one segment
            res[c] = w[c - 1] + n
            continue

        cost = 0
        prev = -2
        segments = 0

        for i in pos[c]:
            if i != prev + 1:
                segments += 1
            prev = i

        # sum lengths of non-c positions
        # total non-c length = n - len(pos[c])
        cost = w[c - 1] * segments + (n - len(pos[c]))
        res[c] = cost

    print(*res[1:])

if __name__ == "__main__":
    solve()
```このコードでは、最初に各色の位置をグループ化して、元の配列内でその色の連続したランを迅速に検出できるようにします。 各色 c について、その出現を繰り返し、連続するブロックの数を数えます。 現在の位置が前のブロックに隣接していない場合は常に、新しいブロックが開始されます。 

再描画する必要がある作業の総量は、単純に c に等しくないインデックスの数です。 これは、n から c の周波数を引いたものとして計算されます。 各連続ブロックはちょうど 1 つの wc コストに寄与するため、wc にブロックの数を掛けます。 

ここでよくある実装上の間違いは、周波数とブロック数を混同することです。 散在する色の出現は単一の空き領域を形成しないため、頻度だけでは十分ではありません。 連続した出現のみが重要です。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [1, 3, 2, 3, 5]
w = [5, 5, 5, 5, 5]
```c = 3 として計算します。 

3の位置は、`[1, 3]`(0 からインデックスが付けられます)。 これらは隣接していないため、2 つのブロックがあります。 3 以外のポジションの合計は 3 です。 

| ステップ | c | の位置 ブロック数 | C 以外の長さ | コスト |
 | --- | --- | --- | --- | --- |
 | 初期化 | [1、3] | 0 | 0 | 0 |
 | スキャン | [1、3] | 2 | 3 | 0 + 2×5 + 3 |

 最終コストは13です。 

これは、ターゲット カラーのまばらな出現であっても、連続していなければコストをマージしないことを示しています。 

### 例 2

 入力:```
n = 3
a = [1, 1, 1]
w = [1, 10, 2]
```c = 1 の場合、位置は次のようになります。`[0, 1, 2]`、ブロックは 1 つ、非 C ポジションはありません。 

| ステップ | ポジション | ブロック | 非c | コスト |
 | --- | --- | --- | --- | --- |
 | スキャン | [0,1,2] | 1 | 0 | 1×1 |

 コストは1です。 

これにより、配列がターゲット カラーですでに均一である場合、支払う操作コストは 1 つだけであり、再描画の長さのコストはかからないことが確認されます。

 ## 特殊なケース

 特殊なケースの 1 つは、色が配列内にまったく表示されない場合です。 この状況では、空き位置がないため、配列全体が 1 つの再描画ブロックになります。 このアルゴリズムは、ゼロの発生を正確にカウントし、ブロック数を 1 に設定し、wc + n を請求します。 

もう 1 つのエッジ ケースは、すべての位置がすでにターゲット カラーである場合です。 ここで、位置リストは 1 つの連続ブロックを形成し、非 c の長さはゼロであるため、コストは単一の wc に縮小されます。 このアルゴリズムは、余分なブロックを決して導入しないことで、過剰なカウントを回避します。 

3 番目のケースは、次のような高度に断片化された発生パターンです。`[c, x, c, x, c, x]`。 隣接性チェックにより、ギャップによって分離されたすべての出現が新しいブロックを形成することが保証されます。これは、最適な戦略において各ギャップが新しい再描画操作を強制するという事実と一致します。
