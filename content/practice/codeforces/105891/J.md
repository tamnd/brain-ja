 ## 問題の理解

 固定の小文字文字列が与えられており、最大で`k`文字はどこにでもあります。 挿入は柔軟です。位置と文字の両方を毎回自由に選択できます。 

これらの挿入を実行した後、結果の文字列を確認し、特定のパターンが何回出現したかを数えます。`"lose"`連続した部分文字列として表示されます。 タスクは、この数が最大になるように挿入を選択することです。 

重要な詳細は、部分列ではなく部分文字列を数えているということです。 これは、4 つの文字が最終文字列内で隣り合って配置され、正確に綴られなければならないことを意味します。`"lose"`。 

制約サイズ (文字列長は最大)`10^5`そして最大まで`10^5`挿入の場合、考えられるすべての挿入位置または結果として得られるすべての文字列を明示的にシミュレートしようとするアプローチは直ちに除外されます。 各挿入後にすべてのウィンドウを二次スキャンすることさえ不可能です。 解は、入力のサイズが線形または線形に近いものでなければなりません。 

微妙な点は、挿入によって隣接関係が変更される可能性があることです。 元の文字列に似た構造がない場合でも、`"lose"`、挿入によって完全に作成できます。 逆に、貪欲なローカル決定により、後でさらに多くのオカレンスが形成される可能性がある挿入が誤って無駄になる可能性があります。 

重要なエッジ状況の 1 つは、文字列にパターンへの部分的な進行が既に含まれている場合です。 

たとえば、次のことを考えてみましょう。 

入力:```
k = 1
s = "lxe"
```結成したいと思います`"lose"`。 挿入できます`'o'`そして`'s'`そして`'e'`既存の文字の周りに配置しますが、挿入が 1 つしかないため、1 つも完成できません`"lose"`部分文字列。 正しい答えは、`0`。 

ここでの単純な間違いは、`"lose"`どこかに出現する場合、その出現は常に 1 つだけ実現可能です。 これは、連続性要件と挿入バジェット制限を無視します。 

もう 1 つの失敗例は、重複する可能性を過大にカウントすることです。```
k = 0
s = "loselose"
```これにはすでに 2 つの出現が含まれていますが、文字を数える不注意なアプローチでは、文字を再結合することによって誤ってさらに多くの値を推定する可能性がありますが、これは挿入なしでは不可能です。 

## アプローチ

 この強引なアイデアは、挿入を最終的な文字列の構築の一部として明示的に扱うことです。 まで挿入するためのあらゆる方法を試してみます。`k`文字列を生成し、候補文字列を生成し、出現回数をカウントします。`"lose"`それぞれに。 文字を挿入する場所だけを考慮した場合でも、可能性の数は組み合わせ的に増加し、各候補では部分文字列をカウントするために線形スキャンが必要になります。 これは、入力が非常に小さい場合でも完全に実行不可能になります。 

重要な観察は、挿入は複雑な構造を作成しているのではなく、固定パターンのコピーを構築するために欠落している文字を「修復」または「完成」させるのに役立つだけであるということです。`"lose"`。 目標の出現数を固定したら、その数のコピーを順番に構築することを考えることができます。 

最終的な文字列を明示的に構築する代わりに、パターンを貪欲に「生成」できる回数をシミュレートします。`"lose"`元の文字列を左から右にスキャンします。 次に必要な文字が現在の位置にない場合は、1 回の挿入を使用してそれを供給します。 挿入枚数がなくなると、それ以上のコピーを完了することはできなくなります。 

これにより、問題は繰り返しのマッチングに帰着します。`"lose"`元の文字列から文字を消費するか、必要な文字を作成するために 1 回の挿入を費やすことができるストリームに対して。

 ## アルゴリズムのチュートリアル

 私たちはプロセスを繰り返しパターンを構築するものとして扱います`"lose"`元の文字列の文字を使用して左から右に、必要に応じて挿入します。 

1. ポインタを初期化する`i`文字列の先頭とカウンター`k`残りの挿入については。 満杯数のカウンターも維持しています`"lose"`私たちが構築することに成功したパターン。 
2. 次の 1 つのオカレンスを構築してみます。`"lose"`文字を順番に処理することによって。 

の各キャラクターごとに、`"lose"`、入力文字列内の現在の文字が一致するかどうかを確認します。 一致する場合は、前進して消費します`i`。 一致しない場合は、代わりに 1 回の挿入を費やして必要な文字を作成します。 この挿入は進みません`i`、それは人工的に配置されているためです。 

ここでの理由は、元の文字列をパターンをサポートするシーケンスに整列させており、挿入がフィラーとして機能するということです。 
3. どこかの時点で挿入が必要であるが、挿入が残っていない場合は、それ以上完全なパターンを完成させることができないため、構築プロセスは直ちに停止します。 
4. 1回`"lose"`が完了したら、答えをインクリメントし、同じプロセスを使用してすぐに次の答えの構築を開始します。 
5. 文字列が使い果たされて先に進めなくなるか、挿入がなくなるまで続行します。 

### なぜ効果があるのか

 このプロセスでは、ソース文字列と繰り返し出現する文字列との間の貪欲な位置合わせが強制されます。`"lose"`。 元の文字列の各文字は順番に使用され、次に必要な文字が一致しない場合にのみ挿入が行われます。 これにより、部分文字列形成の固定された順次構造を考慮すると、順序を変更しても将来の一致の可能性が向上しないため、別のパターンで以前に使用できた可能性のある後の機会に挿入が無駄にならないことが保証されます。 

それぞれ完成しました`"lose"`は、展開中の文字列へのそのパターンの最小コストの埋め込みに対応するため、挿入予算内で完了した埋め込みの数を最大化すると、最適な部分文字列の出現数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input().strip())
    s = input().strip()
    target = "lose"
    
    i = 0
    n = len(s)
    ans = 0
    
    while True:
        used = k
        j = i
        
        ok = True
        for c in target:
            if j < n and s[j] == c:
                j += 1
            else:
                if used == 0:
                    ok = False
                    break
                used -= 1
        
        if not ok:
            break
        
        k = used
        i = j
        ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装はポインタを維持します`i`元の文字列と残りの挿入バジェットに変換します`k`。 各反復では、1 つのノードを構築しようとします。`"lose"`ブロック。 ループオーバーの内側`"lose"`、一致する文字を消費します。`s`または、一致しない場合は挿入を 1 回費やします。 

微妙な点は、挿入によってポインタが移動しないことです。`s`、挿入された文字は元の文字列から独立しているためです。 一致した場合のみポインタが進みます。 完全なパターンが構築されると、更新されたポインターと削減されたバジェットの両方が次の反復に引き継がれます。 

完全なパターンを完了できなくなるとすぐにループが停止します。
