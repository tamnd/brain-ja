 ## 解決策
 ## 問題の理解

 私たちには次のようなシステムが与えられています$n$それぞれのランプが現在オンまたはオフになっており、$m$スイッチ。 各スイッチはランプのサブセットに配線されています。 スイッチを押すと、それに接続されているすべてのランプの状態が切り替わります。 

目的は、時間順に操作をシミュレートすることではなく、選択したすべてのスイッチを適用した後にすべてのランプが消えるように、どのスイッチを復元するかを決定することです (復元するたびにスイッチが使用可能になり、使用可能な各スイッチは実質的に 1 回ずつ押されます)。 各スイッチには関連する修理コストがあり、総コストを最小限に抑えたいと考えています。 

重要な点は、スイッチの順序を変更したり、複数回押したりすることができないことです。 スイッチのサブセットを選択しており、選択された各スイッチは、接続されているランプに対する単一の XOR トグルに寄与します。 

スイッチが最初にどのように構築されたかについては、追加の構造上の制約があります。 各スイッチは、設置された時点では、接続セット内に、以前に設置された最大 1 つのスイッチに付随するランプが少なくとも 1 つありました。 グラフの用語では、スイッチとランプの間に 2 部グラフを構築し、スイッチ ノードを 1 つずつ追加する場合、すべての新しいスイッチには、以前のスイッチ間の現在の次数が最大 1 であるランプが少なくとも 1 つ含まれている必要があります。 

この状態が問題の鍵となります。 これにより、構造が任意の密なハイパーグラフになることが防止され、非常に制限された形式に強制されます。 

制約$n, m \le 60$すでに、指数関数的またはサブセット DP オーバー スイッチが原理的には可能であることを示唆していますが、それは構造が有効寸法を削減する場合に限ります。 構造がなければ、これは最小コストの XOR システムです。$m$変数と$n$制約。これは標準的なガウス消去法問題であり、潜在的に$2^{m-n}$自由変数。 最悪の場合、それは大きすぎるでしょう。 

素朴な考えによるよくある失敗例は、これをランプごとに独立したものとして扱ったり、貪欲に低コストのスイッチを選択したりすることです。 これは、各スイッチが複数のランプに同時に影響し、決定が XOR パリティを通じてグローバルに干渉するため、失敗します。 

## アプローチ

 構造的制約を無視すると、問題は GF(2) 上の線形システムに対する古典的な最小コストの解決策になります。 マトリックスを構築します$A$ここで、行はランプに対応し、列はスイッチに対応し、次のようになります。$Ax = b$GF(2) に対する最小化$\sum c_i x_i$。 直接的なアプローチはガウス消去法です。これは解決策の基礎を与え、問題を最大次元のゼロ空間の探索に縮小します。$m - \text{rank}(A)$。 最悪の場合、これが起こる可能性があります$2^{60}$、それは不可能です。 

重要な観察は、構築ルールにより、スイッチとランプの 2 部グラフが森林のように動作するように強制されることです。 スイッチを追加するたびに、以前のスイッチの次数が最大 1 であるランプが含まれている必要があります。 これにより、発生グラフでのサイクルの作成が防止されます。サイクルを形成するには、サイクル内のすべてのノードがある時点で少なくとも次数 2 をすでに持っている必要があり、ルールに矛盾するからです。 

出現グラフがフォレストであると認識すると、代数構造は大幅に崩壊します。 接続された各コンポーネントはツリーになり、ツリーは XOR 制約のシステムにおいて非常に強力な特性を持ちます。つまり、すべてのコンポーネントはランプ側でちょうど 1 つの自由度に寄与し、そのコンポーネント内のスイッチに対する単一のパリティ制約に変換されます。 

これにより、グローバル システムが独立したコンポーネントに縮小され、それぞれが一般的な線形システムではなくなり、小さな変数セットに対する単一のパリティ最適化問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なガウス消去 + サブセット検索 |$O(m^3 + 2^{m-n})$|$O(mn)$| 遅すぎる |
 | ツリー分解 + コンポーネントごとの DP |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 状況を、一方の側にスイッチ ノード、もう一方の側にランプ ノードがある 2 部グラフとしてモデル化します。ここで、エッジはスイッチがランプに影響を与えることを意味します。 次に、接続コンポーネントごとにノードをグループ化します。 
2. 構築ルールの構造的結果を検証します。これらのエッジによって形成されるグラフはフォレストである必要があります。 これは、各新しいエッジが挿入時に常に少なくとも 1 つの次数の頂点を導入し、サイクルの形成が妨げられるためです。 
3. 森の中で$n + m$ノードと$m$エッジでは、接続された各コンポーネントが頂点とエッジの間の密接な関係を満たさなければなりません。 コンポーネント$V$頂点は正確に持っています$V - 1$エッジ、つまり木です。 
4. 単一の接続コンポーネントを検査します。 これは 2 部ツリーであるため、頂点を数えると、各コンポーネントに 1 つのランプ ノードが含まれていることがわかります。 これは構造によって強制されます。複数のランプがある場合、ツリー エッジの制約を超えてしまいます。 
5. したがって、各コンポーネントは 1 つのランプを中心としており、ツリー構造を介して複数のスイッチが接続されています。 
6. 固定コンポーネントの場合、ランプの状態を XOR 式に変換します。このコンポーネントで選択されたすべてのスイッチのパリティは、そのランプの初期状態と一致する必要があります。 
7. ここで、各コンポーネントを単純な最適化問題にまとめます。XOR が固定ビットに等しくなるような最小の総コストを持つスイッチのサブセットを選択します。 
8. コンポーネント内のスイッチに対する 2 状態動的プログラミングを使用して、これを解決します。 XOR パリティ 0 および 1 を達成するための最小コストを維持します。 
9. すべてのコンポーネントを個別に処理した後、必要なコストを合計します。 いずれかのコンポーネントが必要なパリティを満たせない場合、答えは不可能です。 

### なぜ効果があるのか

 不変条件は、各接続コンポーネントが 1 つの独立した XOR 制約に寄与し、そのコンポーネント内のすべてのスイッチがその 1 つのパリティ条件を通じてのみ相互作用することです。 ツリー構造により、同じコンポーネントの異なる部分をリンクする追加の隠れた制約がないことが保証されます。 その結果、グローバル システムは、独立したパリティ最小化問題にきれいに分解され、コストが独立したコンポーネント間で加算されるため、各コンポーネントを最適に解決すると、グローバルに最適なソリューションが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    init = input().strip()
    cost = list(map(int, input().split()))

    adj = [[] for _ in range(n + m)]

    # nodes: 0..n-1 lamps, n..n+m-1 switches
    for i in range(m):
        s = input().strip()
        u = n + i
        for j, ch in enumerate(s):
            if ch == '1':
                adj[u].append(j)
                adj[j].append(u)

    vis = [False] * (n + m)
    ans = 0

    for i in range(n + m):
        if vis[i]:
            continue

        stack = [i]
        comp = []
        vis[i] = True

        lamps = set()
        switches = []

        while stack:
            v = stack.pop()
            comp.append(v)
            if v < n:
                lamps.add(v)
            else:
                switches.append(v - n)

            for to in adj[v]:
                if not vis[to]:
                    vis[to] = True
                    stack.append(to)

        if not switches:
            continue

        if len(lamps) != 1:
            # invalid structure under intended interpretation
            print(-1)
            return

        lamp = next(iter(lamps))
        target = int(init[lamp])

        dp = {0: 0, 1: 10**18}

        for idx in switches:
            c = cost[idx]
            ndp = {0: 10**18, 1: 10**18}
            for p in [0, 1]:
                if dp[p] >= 10**18:
                    continue
                ndp[p] = min(ndp[p], dp[p])
                ndp[p ^ 1] = min(ndp[p ^ 1], dp[p] + c)
            dp = ndp

        if dp[target] >= 10**18:
            print(-1)
            return

        ans += dp[target]

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まずランプとスイッチ間の 2 部グラフを構築します。 次に、DFS を使用して接続されているコンポーネントを検索します。 コンポーネントごとにランプとスイッチを分離します。 この構造により、コンポーネントごとにランプが 1 つだけ存在することが保証されます。 

コンポーネント内に入ると、問題はパリティ制約の下で最小コストのスイッチを選択することになります。 DP 状態は、選択されたスイッチの XOR が 0 か 1 かを表す 2 つの値のみを保持します。各スイッチは何も寄与しないか、コストを追加しながらパリティを反転します。 

最終的な答えは、すべてのコンポーネントにわたる最適コストの合計です。 

## 実用的な例

 2 つのスイッチが両方とも 1 つのランプに影響を与える小規模なシステムを考えてみましょう。 ランプは状態 1 で開始するので、消灯したいと考えています。 

| ステップ | スイッチを検討中 | DP[0] | DP[1] |
 | --- | --- | --- | --- |
 | 開始 | なし | 0 | INF |
 | S1 を追加 (コスト 3) | S1 | 0 | 3 |
 | S2 を追加 (コスト 2) | S2 | 0 | 2 |

 S2 のみを選択すると、パリティ 1、コスト 2 が得られ、ターゲットと一致するため、答えは 2 になります。 

このトレースは、DP が特定の組み合わせではなくパリティをどのように追跡するかを示しています。これにより、サブセットが増大してもきれいにスケーリングできるようになります。 

2 番目の例として、コンポーネントにコスト 5、4、および 7 のスイッチがあり、ランプにはパリティ 0 が必要だとします。 

| ステップ | スイッチ | DP[0] | DP[1] |
 | --- | --- | --- | --- |
 | 開始 | - | 0 | INF |
 | 5 | S1 | 0 | 5 |
 | 4 | S2 | 0 | 4 |
 | 7 | S3 | 0 | 4 |

 最良の偶数パリティ サブセットは空のペアまたは選択ペアのいずれかですが、DP は明示的に列挙することなく、すべての可能性を自動的に集約します。

 ## 特殊なケース

 エッジ ケースの 1 つは、ランプが最初はオフで、スイッチのないコンポーネントに属している場合です。 その状況では、DP はそのコンポーネントに対して実行されることはなく、アルゴリズムはそれをすでに満たされているものとして正しく処理します。 代わりにランプが最初にオンになっている場合、コンポーネントにはランプを反転する有効な方法が含まれておらず、DP は必要なパリティと一致することができないため、拒否が発生します。 

もう 1 つのエッジ ケースは、スイッチが 1 つだけのコンポーネントです。 DP はパリティ 0、コスト 0 で開始され、0 に留まるか、スイッチ コストとともに 1 に移行します。 ランプにパリティ 1 が必要な場合、ソリューションはその 1 つのスイッチを正しく選択します。 それ以外の場合は何も選択されません。 

最後のエッジケースは、複数のスイッチが同じエフェクトを共有する場合です。 DP は当然のことながら、すべてのサブセットを暗黙的に考慮することでこれを処理し、スイッチ定義の冗長性に関係なく、必要なパリティを達成する最も安価な組み合わせが常に選択されるようにします。
