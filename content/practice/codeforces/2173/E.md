 ## 解決策
 ## 問題の理解

 私たちは次の順列を維持します`1..n`。 

クエリは 2 つのインデックスを選択します`x`そして`y`。 次に裁判官はコインを投げます。 どちらかの立場`(x,y)`交換されるか、ミラーリングされた位置`(n-x+1, n-y+1)`交換されます。 スワップ後、どのペアが実際に交換されたのかが通知されるため、現在の順列を常に正確に知ることができます。 

課題は、配列のどちら側が影響を受けるかを直接選択できないことです。 すべての操作は、位置のペアまたはその鏡像のいずれかに作用します。 

すべての合計`n`だけです`2·10^4`、だからどれでも`O(n^2)`処理は計算的には問題ありません。 実際の制限はクエリのバジェットです。 程度しか受け取っていません`2.5n`つまり、私たちは着実に前進しなければならず、世界的な再編を繰り返す余裕はないのです。 

最初の観察は、位置とそのミラーが自然なペアを形成しているということです。```
i <-> n-i+1
```そのようなペアの一方の側が関与するスワップを要求するときはいつでも、ジャッジは代わりにもう一方の側で対応するアクションを実行する場合があります。 

単純な並べ替え戦略では、各値を正しい位置に繰り返し配置します。 問題は、すべての試みが確率的にのみ成功することです`1/2`そのため、不用意に実装すると、許容される操作数をはるかに超えて消費する可能性があります。 

特に危険なのは、片側だけを直そうとする場合です。 

たとえば、```
n = 6
[2,1,3,4,5,6]
```配置しようとしています`1`所定の位置に`1`代わりに、ミラーリングされた側に繰り返し影響を与える可能性があります。 進歩を制御することが難しくなります。 

重要なのは、ミラー化されたペアを一緒に作業することです。 ポジションを確認したら`i`そして`n-i+1`単一のユニットとして、裁判官のランダムな選択は障害ではなくなり、有用な対称性になります。 

## アプローチ

 強引なアイデアは、通常の順列を並べ替えるのとまったく同じように並べ替えることです。 仮定値`i`現在その位置にいます`pos[i]`。 私たちは繰り返し交換をリクエストします`pos[i]`そして`i`。 

問題は、クエリの半分だけが目的の場所に影響を与えることです。 残りの半分はミラーリングされた位置に影響します。 1 つの要素を修正するために予想される試行回数は一定ですが、異なる要素間の相互作用により分析が複雑になり、操作の総数が簡単に制限を超える可能性があります。 

重要な観察は、裁判官が決して恣意的なスワップを選択しないということです。 スワップとそのミラーのどちらかを選択します。 

ターゲット値のミラーリングされたペアを考えてみましょう。```
l = i
r = n-i+1
```仮定値`l`定位置にない`l`。 

クエリを実行します:```
(pos[l], l)
```ジャッジが選択したスワップを実行する場合、値`l`すぐに正しい位置に到達します。 

ジャッジがミラースワップを実行した場合、値の位置は`r`代わりに正しい側に移動します。 

いずれにせよ、ミラーリングされたペアの 2 つのメンバーのうちの 1 つが修正に近づきます。 

これは、外側から内側に順列を処理することを示唆しています。 ミラーリングされたペアごとに`(l,r)`、両方の位置に正しい値が含まれるまでクエリを続けます。 

素晴らしい点は、すべてのクエリが 2 つの位置のうち少なくとも 1 つを予想どおりに修正することです。 編集部の分析によると、1 つのミラーリング ペアの予想コストは最大でも 5 回の操作であり、全体的な予想コストはおよそ`2.5n`操作。 追加の`800`制限内にあると、大きな安全マージンが得られます。

 ## アルゴリズムのチュートリアル

 1. 現在の順列と配列を維持します。`pos[v]`すべての値の位置を保存します。 
2. もし`n`奇数である場合は、まず中央の要素を修正します。 

中央の位置は独自のミラーです。 ペアに対して繰り返しクエリを実行する`(pos[mid_value], mid_position)`中央の値が中心に達するまで。 
3. ミラーリングされた位置を外側から内側に処理します。 

させて```
l = i
r = n-i+1
```4. どちらかの位置が正しくない場合でも、このペアで操作を続けます。 
5. 値の場合`l`現在その位置にありません`l`、クエリ```
(l, pos[l])
```ミラーリングされていないスワップが発生すると、`l`すぐに正しくなります。 
6. それ以外の場合は、位置`l`すでに正しいので、反対側で作業してクエリを実行します```
(r, pos[r])
```7. ジャッジが応答するたびに、順列と`pos`配列。 
8. 現在のミラーリングされたペアの両方の位置が正しくなったら、内側に向かって次のペアに移動します。 
9. すべてのペアが処理されると、順列がソートされます。 

### なぜ効果があるのか

 ミラーリングされたペアを修正する`(l,r)`。 

いつでも`l`は正しくないため、クエリを実行します`(l,pos[l])`、2つのことのいずれかが起こります。 

選択したスワップが直接実行される場合、値`l`最終位置に到達します。 

ミラーリングされたスワップが実行される場合、その操作は配列のミラーリングされた側にのみ影響します。これはまさに値の場所です。`r`生きています。 ペアのもう一方のメンバーの修正に向けて進歩が見られます。 

クエリを実行するときにも同じ推論が当てはまります。`r`。 

プロセス全体を通じて、現在のミラーリングされたペアの外側の位置を再検討する必要はありません。 ペアが正しくなると、以降のクエリには厳密にそのペア内の位置のみが含まれるため、その後の操作でペアを壊すことはできません。 

最も外側のペアから中心に向かって帰納することにより、すべての位置が最終的に正しい値に到達し、最終的な順列がソートされます。 

## Python ソリューション

 これは、受け入れられている対話型ソリューション構造です。```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i in range(1, n + 1):
        pos[p[i]] = i

    def query(x, y):
        print("?", x, y)
        sys.stdout.flush()

        u, v = map(int, input().split())
        if u == -1:
            sys.exit(0)

        p[u], p[v] = p[v], p[u]
        pos[p[u]] = u
        pos[p[v]] = v

    if n % 2 == 1:
        mid = (n + 1) // 2
        while p[mid] != mid:
            query(pos[mid], mid)

    for l in range(1, n // 2 + 1):
        r = n + 1 - l

        while p[l] != l or p[r] != r:
            if p[l] != l:
                query(l, pos[l])
            else:
                query(r, pos[r])

    print("!")
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```裁判官が実際に起こった正確な交換を教えてくれるので、順列自体は保存されます。 受け取り後`(u,v)`、配列と逆位置配列の両方を一定時間で更新します。 

奇数長の順列の中間位置は、それ自身のミラーであるため特別です。 最初にこれを修正すると、残りのロジックが簡素化されます。 

すべてのミラーリングされたペアについて、アルゴリズムは常に左側の位置を固定することを優先します。 左側が正しくなると、右側に切り替わります。 これにより、完成した外側のペアに再び注目する必要がなくなることが保証されます。 

最も一般的な実装ミスは更新を忘れることです`pos`交換後。 戦略全体は、すべての値の現在位置を知ることに依存します。

 ## 特殊なケース

 検討してください`n = 1`。```
[1]
```ミラーリングされたペアはなく、中心はすでに正しいです。 アルゴリズムはすぐに出力します`!`。 

中心だけが間違っている奇数長の順列を考えてみましょう。```
n = 5
[1,2,4,3,5]
```中心位置は、`3`。 中心位置はそれ自体をミラーリングするため、繰り返しクエリを実行します。`(pos[3],3)`最終的に価値を置く`3`真ん中に。 その後、外側のペアは通常どおり処理されます。 

一方がすでに正しいペアを考えてみましょう。```
[1,4,3,2]
```ペア用`(1,4)`、 位置`1`はすでに正しいです。 このアルゴリズムは、左側で無駄な操作を行わずに、右側ですぐに機能します。 だからこその条件```
if p[l] != l:
    ...
else:
    ...
```必要です。 

最後に、意図したものではなくミラー化されたバージョンが実行されるクエリを考えてみましょう。 それがこの問題の中心的な課題です。 すべてのクエリはミラーリングされたペアを中心に設計されているため、アルゴリズムがこれを処理します。 左側が改善されない場合は、右側が改善されます。 ペアの進行状況が消えることはありません。これはまさに、予想される操作数を線形に保つ特性です。
