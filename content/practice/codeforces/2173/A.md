 ## 解決策
 ## 問題の理解

 私たちは一連の授業にわたって睡眠スケジュールを計画するように求められますが、それぞれの授業が重要かどうかはわかりません。 日はバイナリ文字列として表され、「1」は重要なクラスを示し、「0」は重要でないクラスを示します。 重要な授業に出席するたびに、その授業だけでなく次の授業も起きていなければならないというルールです。`k`クラス。 この強制覚醒ルールが適用されない限り、重要でないクラスは自由にスリープ状態にすることができます。 私たちの目標は、寝て過ごすことができる授業の数を最大化することです。 

各テスト ケースはクラスの総数を示します`n`、睡眠回復ウィンドウ`k`、およびどのクラスが重要かを表す文字列。 出力は各テスト ケースの単一の整数、つまりアウェイク制約を尊重しながらスリープできるクラスの数である必要があります。 

制約は小さい: 両方とも`n`そして`k`最大 100 まで、最大 500 のテスト ケースを作成できます。 つまり、単純な場合でも、`O(n^2)`テスト ケースごとのソリューションはおそらく機能しますが、次のことを目指すこともできます。`O(n)`ロジックはシーケンシャルなので解決策です。 明らかではないエッジ ケースには、連続する重要なクラス、または文字列の終わり近くの重要なクラスが含まれます。`k`ウィンドウが端を越えて広がる可能性があります。 

たとえば、次のように考えてみましょう`n = 5, k = 2, s = "10101"`。 重複を無視する単純なアプローチでは、覚醒ウィンドウが 2 倍にカウントされる可能性がありますが、正しい戦略では、重複する覚醒期間を効率的に処理する必要があります。 もう 1 つのエッジケースは次のような場合です`k`残りのクラスよりも大きいです。`n = 3, k = 5, s = "100"`。 ここでクラス 1 に出席すると、最後まで起きていなければなりません。 

## アプローチ

 ブルートフォース手法では、文字列を反復処理し、重要なクラスごとに次のクラスをマークします。`k`強制覚醒としてのクラス。 マークを付けた後、マークされていないゼロがいくつあるかを数えて、最大スリープ カウントを取得します。 これはルールを直接シミュレートするため機能します。 と`n`最大 100、最大マーク`k`'1' あたりのクラスは、テスト ケースごとに最大 100 × 100 = 10,000 の操作を提供します。これは、500 のテスト ケースを考慮すると許容されます。 

最適なアプローチでは、マーキングに補助配列が必要ないことがわかります。 インデックスを表す単一のポインタを維持でき、それまで強制的に起動されます。 クラスを反復処理するときに、現在のクラス インデックスがこのポインターより小さい場合は、起きていなければなりません。 クラスが重要な場合は、ポインタを次のように更新します。`i + k + 1`(配列のインデックスは 0 から始まるため)。 強制覚醒ウィンドウの外にある重要でないクラスはスリープスルーされ、スリープ カウンターが増加します。 これにより簿記が軽減され、ソリューションがシンプルかつ直線的になります。`n`。 

重要な洞察は、重複する覚醒ウィンドウが自然にマージされるということです。前の覚醒ウィンドウ内にある間に重要な授業に出席しても、現在のポインタよりもさらにプッシュされた場合にのみ、覚醒期間が延長されます。 これにより、覚醒中のクラスを過小評価したり過大評価したりすることがなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k) | O(n) | 制約が少ないため許容可能 |
 | 最適 | O(n) | お(1) | 受け入れられ、クリーンです |

 ## アルゴリズムのチュートリアル

 1.初期化`awake_until`に`-1`。 この変数は、強制的に起きていなければならないクラス インデックスを追跡します。 
2.初期化`sleep_count`に`0`。 これには、睡眠可能なクラスの数が保存されます。 
3. 各クラスのインデックスを反復処理します。`i`から`0`に`n-1`。 
4. もし`i`より大きい`awake_until`そしてクラスは重要ではありません(`s[i] == '0'`)、増分`sleep_count`なぜなら、あなたはそれを通して眠ることが許されているからです。 
5. クラスが重要な場合 (`s[i] == '1'`）、 アップデート`awake_until`に`max(awake_until, i + k)`。 これにより、長時間起きていられます`k`重要なクラスの後にクラスが追加されますが、すでに以前の起動ウィンドウにある場合は、より長い起動期間が保持されます。 
6. 反復が終了したら、`sleep_count`睡眠可能なクラスの最大数が含まれています。 

それが機能する理由: 不変条件は、各クラスで次のとおりです。`i`、`awake_until`は、起きていなければならない最後の授業を正しく表しています。 アップデートすることで`awake_until`使用して`max`、重複する覚醒期間は自然に統合されます。 睡眠は次の場合にのみ許可されます`i > awake_until`クラスは重要ではないため、強制アウェイク制約に違反しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    awake_until = -1
    sleep_count = 0
    for i in range(n):
        if i > awake_until and s[i] == '0':
            sleep_count += 1
        if s[i] == '1':
            awake_until = max(awake_until, i + k)
    print(sleep_count)
```このコードは、強制覚醒ポインタとスリープ クラスのカウンタを初期化します。 文字列を反復処理して、クラスが安全にスリープ可能になるたびにスリープ カウンタをインクリメントし、重要なクラスに遭遇するたびに強制覚醒ウィンドウを拡張します。 使用する`max`重複する起動中のウィンドウが縮小しないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        awake_until = -1
        sleep_count = 0
        for i in range(n):
            if i > awake_until and s[i] == '0':
                sleep_count += 1
            if s[i] == '1':
                awake_until = max(awake_until, i + k)
        print(sleep_count)
    return output.getvalue().strip()

# Provided samples
assert run("4\n4 1\n1001\n3 3\n000\n3 1\n001\n8 2\n01000101\n") == "1\n3\n2\n2"

# Custom cases
assert run("1\n3 5\n100") == "2", "large k extends past end"
assert run("1\n5 0\n10101") == "2", "k=0 only important classes prevent sleep"
assert run("1\n5 2\n00000") == "5", "all classes non-important"
assert run("1\n6 1\n111111") == "0", "all classes important"
assert run("1\n1 1\n0") == "1", "single non-important class"
