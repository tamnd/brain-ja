 ## 解決策
 ## 問題の理解

 一連のターンを処理します。 現在のスコアは 0 から始まります。 

順番に`i`、次の 2 つの可能な変換が与えられます。 

レッドカードを取った場合、新しいスコアは次のようになります。`k -> k - a[i]`青いカードを取った場合、新しいスコアは次のようになります。`k -> b[i] - k`毎ターン、正確に 1 つの変換を選択する必要があります。 結局`n`ターンでは、達成できる最大の最終スコアが必要です。 

最も直接的な解釈は、ターンごとに 2 つのアフィン変換のいずれかを現在のスコアに適用するというものです。 難しいのは、今行った選択によって、その後のすべてのターンで見られるスコアが変わることです。 

重要な制約は合計です`n`すべてのテスト ケース全体で最大でも`10^5`。 考えられるすべての決定シーケンスを探索するアルゴリズムは不可能です。`2^n`カードのさまざまな選択方法。 平`O(n^2)`線形解が可能であれば、ここでは必要ありません。 状態を大幅に圧縮する動的プログラミングまたは貪欲な観察を期待する必要があります。 

この問題の微妙な側面は、スコアがマイナスになる可能性があることです。`a[i]`そして`b[i]`マイナスになることもあります。 スコアが常に増加することを前提とした推論は失敗します。 

考慮する：```
n = 1
a = [5]
b = [-10]
```考えられる最終スコアは次の 2 つです。`-5`そして`-10`、したがって、答えは次のとおりです`-5`。 

もう 1 つの簡単な間違いは、各ターンの後に最大スコアだけを維持すれば十分であると想定することです。 

例：```
Current possible scores: {100, -100}

Next turn:
a = 0
b = 0
```から`100`私たちは得ることができます`{100, -100}`。 

から`-100`私たちは得ることができます`{-100, 100}`。 

将来の最大の結果は、どちらの極端からもたらされる可能性があります。 中間値は状態を説明するのに十分ではありません。 

3 番目の落とし穴は、固定幅の整数を使用する言語での整数オーバーフローです。 スコアは最大までの変更を蓄積できます`10^5`ターン、それぞれに最大の値が含まれます`10^9`。 答えは 32 ビットの範囲を簡単に超える可能性があります。 Python はこれを自動的に処理しますが、C++ ソリューションでは次を使用する必要があります。`long long`。 

## アプローチ

 ブルートフォースソリューションでは、あらゆるターンに両方のカードの選択が試行されます。 

スコアから始める`0`、各ターンで到達可能なスコアの数が 2 倍になります。 後`n`ターンは最大まで可能です`2^n`州。 ブルート フォースは、考えられるすべてのプレイ シーケンスを明示的に検査するため、正しいのですが、`n = 100000`絶望的に大きいです。 

より良いアプローチを見つけるには、ターンが可能なスコアのセットをどのように変換するかを理解する必要があります。 

ターンの前に、到達可能なスコアのセットが以下であると仮定します。`S`。 

どのようなスコアでも`x`で`S`、2 つの遷移は次のとおりです。```
x - a[i]
b[i] - x
```どちらも次の一次関数です`x`。 

すべてのターン後に達成可能な最大スコアのみに興味があります。 これは、セット全体ではなく、到達可能なセットの概要を追跡することを示唆しています。 

重要な観察は、ターンの前に到達可能なスコアが間隔を形成している場合、`[mn, mx]`、その後、その区間内のすべての値にいずれかの変換を適用すると、別の区間が生成されます。 

赤の操作の場合:```
x -> x - a[i]
```のイメージ`[mn, mx]`は```
[mn - a[i], mx - a[i]]
```青色の操作の場合:```
x -> b[i] - x
```画像は```
[b[i] - mx, b[i] - mn]
```これら 2 つの間隔を結合すると、再び 1 つの間隔になります。 その理由を確認するには、次のことに注目してください。```
(mx - a[i]) - (b[i] - mx)
= 2*mx - (a[i] + b[i])

(b[i] - mn) - (mn - a[i])
= (a[i] + b[i]) - 2*mn
```以来`mn <= mx`、これらの量の少なくとも 1 つは負ではありません。 したがって、2 つの区間は常に重なり合うか接触するため、それらの結合は連続区間となります。 

最初に到達可能なセットは次のとおりです。`{0}`、これは間隔です。 誘導により、各ターンの後、到達可能なセットは一定の間隔のままになります。 

これがわかれば、必要なのはその最小値と最大値だけです。 

現在の間隔を次のようにします`[mn, mx]`。 

次の間隔にはエンドポイントがあります。```
new_mn = min(mn - a[i], b[i] - mx)
new_mx = max(mx - a[i], b[i] - mn)
```すべてのターンを処理し、最終的な最大エンドポイントを出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方を初期化します`mn`そして`mx`に`0`なぜなら、どのターンの前でも、到達可能な唯一のスコアは次のとおりです。`0`。 
2. プロセスは左から右に回転します。 
3. For the current turn, compute the smallest value reachable after applying either operation:```
new_mn = min(mn - a[i], b[i] - mx)
```赤い間隔の最小値がその左の端点です`mn - a[i]`。 青色の間隔の最小値がその左端点です`b[i] - mx`。 
4. いずれかの操作を適用した後に到達可能な最大値を計算します。```
new_mx = max(mx - a[i], b[i] - mn)
```赤い区間の最大値は次のとおりです。`mx - a[i]`。 青色の区間の最大値は次のとおりです。`b[i] - mn`。 
5. 交換する`(mn, mx)`と`(new_mn, new_mx)`。 
6. 全ターン終了後、出力`mx`。 

### なぜ効果があるのか

 不変条件は、ターンの接頭辞を処理した後、到達可能なすべてのスコアが区間内にあることです。`[mn, mx]`、その間隔内のすべての値に到達可能です。 

最初の到達可能なセットは次のとおりであるため、基本ケースは即時です。`{0}`。 

ターンの前に不変式が成立すると仮定します。 赤の操作を間隔全体に適用すると 1 つの間隔が作成され、青の操作を適用すると別の間隔が作成されます。 これら 2 つの間隔は常にオーバーラップするため、それらの結合自体が間隔になります。 その共用体の最小値と最大値は、まさに以下に使用される式です。`new_mn`そして`new_mx`。 

したがって、不変式はターンごとに true のままになります。 最後に、`[mn, mx]`は正確にすべての達成可能な最終スコアのセットであるため、答えはその最大エンドポイントです`mx`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        mn = mx = 0
        
        for i in range(n):
            new_mn = min(mn - a[i], b[i] - mx)
            new_mx = max(mx - a[i], b[i] - mn)
            mn, mx = new_mn, new_mx
        
        print(mx)

solve()
```実装は間隔 DP に直接続きます。`mn`そして`mx`処理されたプレフィックスの後に到達可能な最小および最大のスコアを表します。 ターンごとに、変換された 2 つの間隔の両端点を計算し、現在の間隔を更新します。 

よくある実装ミスは更新です`mn`計算する前に`new_mx`。 どちらの式も前の間隔を使用する必要があるため、一時変数が必要です。 

もう 1 つの詳細は、全体で整数演算を使用することです。 すべてのトランジションは加算と減算であるため、精度の問題は発生しません。
