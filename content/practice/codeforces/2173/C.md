 ## 解決策
 ## 問題の理解

 数値の複数セットが与えられ、すべて 1 から大きな限界 k までの範囲内にあります。 この配列から、同様に 1 から k までの別個の整数のセット B を構築する必要がありますが、自明ではない方法で相互作用する 2 つの同時制約の下にあります。 

最初の制約は、B を入力配列に結び付けます。各配列要素 a_i について、B 内の少なくとも 1 つの数値がそれを分割するという意味で、配列内のすべての値は B によって「カバー」される必要があります。 したがって、各 a_i は、選択した何らかの除数に割り当てられます。 

2 番目の制約は逆方向です。B で選択されたすべての数値 b が配列によって「サポート」されなければなりません。 b から k までのすべての倍数を見ると、それらの倍数はすべて入力配列に少なくとも 1 回出現する必要があります。 言い換えれば、 b は、入力配列がその倍数をすべて含むのに十分な密度がある場合にのみ許可されます。 

したがって、B は同時に、割り切れない配列のカバー集合であると同時に、多重閉包全体が配列内に存在する妥当性フィルターをかけられた数値のサブセットでもあります。 

目標は、B をできるだけ小さくするか、そのようなセットが存在しないことを報告することです。 

制約はソリューションを強力に形作ります。 テスト ケース全体の配列要素の合計数は最大 2 · 10^5 であるため、n がほぼ線形または線形に近い解であれば、どのような解でも許容されます。 ただし、k は 10^9 まで大きくすることができるため、k までの全範囲にわたって反復するアプローチは除外されます。 有効なソリューションは、配列内に実際に現れる値のみを操作し、列挙ではなく除数の関係に依存する必要があります。 

重要な微妙な点は、B は集合ではなく集合であり、その妥当性は単一要素の局所的な割り算だけではなく、倍数の大域的な頻度条件に依存することです。 これにより、素朴で貪欲な選択が危険になります。 

いくつかのエッジケースは、典型的な障害モードを示しています。 配列に 2 などの単一の値が含まれており、k が大きい場合、B={2} が機能すると思われるかもしれませんが、4、6、8 など k までの倍数がすべて表示されるとは限らないため、失敗します。 逆に、配列が 1 から k までのすべての数値のように非常に密である場合は、1 ですべてが除算され、すべての倍数条件が自明に満たされるため、B={1} が機能します。 

もう 1 つの失敗例は、数値が構造的に欠落している場合に発生します。 たとえば、 a に素数のみが含まれている場合、合成 b は存在しない倍数を必要とするため、 B では有効になりません。 要素ごとに除数を貪欲に選択しようとする単純な解決策では、このグローバルな乗法制約をチェックできません。 

## アプローチ

 ブルートフォースアプローチでは、配列内に現れる個別の値のすべての候補サブセット B を検討し、両方の制約を検証しようとします。 各候補 B について、すべての a_i をスキャンして可分性をテストすることでカバレッジをチェックし、k までの各 b の倍数をスキャンして配列内の存在を検証することによって妥当性をチェックします。 B を a の個別の値に制限したとしても、サブセットの数は n で指数関数的となり、各検証ステップには少なくとも線形か、複数のチェックによるさらに悪い作業が含まれます。 n が小さな制限を超えて大きくなると、これはすぐに実行不可能になります。 

重要な洞察は、条件 2 の視点を逆転させることです。 B を自由に選択するものとして考える代わりに、条件 2 が非常に制限的であることがわかります。つまり、値 b は、k までの b の倍数がすべて配列内に出現する場合にのみ適格となります。 これは、そのような b が配列の構造に「完全に適合」する必要があること、特に b のすべての倍数が入力値の中にすでに存在している必要があることを直ちに意味します。

有効な候補をすべて特定したら、条件 1 は配列値に関するカバー問題になります。すべての a_i は、選択された少なくとも 1 つの b で割り切れなければなりません。 これは、明らかにされていない要素の代表を貪欲に選ぶことで自然に解決されますが、重要なのは、有効な候補からのみ選択することです。 

2 番目の重要な観察は、値 x が有効な場合、x の倍数は自動的には有効ではなく、実際、配列が非常に密でない限り、通常は無効であるということです。 これは、有効な要素がまばらであり、個別の値に対する頻度カウントを使用して効率的に事前フィルタリングできることを意味します。 

配列の頻度マップを計算し、個別の値 x ごとに、現在の最大値までの x の倍数がすべて配列に含まれているかどうかを検証します。 既存の値の倍数を反復処理するだけなので、全体の複雑さは管理可能です。 

有効なセットを入手したら、カバレッジを確保する必要があります。 まだカバーされていない各 a_i について、有効なセットから約数を選択します。 最適な戦略は、カバーされていない各値をその最小の有効な約数 (または任意の有効な約数) に割り当て、過剰選択を避けることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n √A log A) (約数に対して実質的に線形) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての値の度数表を作成します。 これにより、数値が存在するかどうかの O(1) チェックが可能になります。 
2. これらのみが B の要素になる可能性があるため、配列から個別の値のセットを抽出します。 
3. 個別の値 x ごとに、k 未満のすべての倍数 x、2x、3x、... が度数表に存在することを確認することで、x が「有効」かどうかを確認します。 複数の値が欠落している場合、x は拒否されます。 このステップにより、保持するすべての候補について問題の 2 番目の条件が満たされることが保証されます。 
4. すべての有効な値を候補リストに収集します。 これらは、B に配置できる唯一の数字です。 
5. 有効な候補がまったくない場合、すべての a_i が少なくとも 1 つの約数でカバーされなければならず、どの約数も安全に選択できないため、答えは不可能です。 
6. アレイをスキャンして貪欲に B を構築します。 どの値がすでにカバーされているかを示すブール配列またはセットを維持します。 
7. 各 a_i について、すでに説明されている場合はスキップします。 それ以外の場合は、a_i のすべての約数を試し、候補にある約数を選択します。 それを B に追加し、その選択した約数のすべての倍数を対象としてマークします。 
8. 出力B。 

中心となる考え方は、有効性は候補ごとにグローバルに決定され、カバレッジはカバーされていない要素ごとにローカルに処理されるということです。 このアルゴリズムが機能するのは、一部の a_i に対して有効な約数が選択されると、多重完全性の制約に違反することなく、その約数クラス全体を安全に表現できるためです。 

### なぜ効果があるのか

 正確さは 2 つの結合された不変条件に依存します。 まず、B に追加されるすべての要素はグローバル多重条件を満たすため、2 番目のルールに違反することはありません。 第 2 に、要素を B に追加するたびに、カバーされていない配列要素を分割し、すべての a_i をカバーする進行を保証するため、特にその要素を選択します。 挿入のたびにカバーされる要素のセットが厳密に増加し、B は必要な場合にのみ増加するため、冗長または無効な構築が生じることはありません。 残りのカバーされていない要素には、候補に少なくとも 1 つの有効な約数が含まれている必要があります。 そうしないと、実現可能性と矛盾してしまいます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    d = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            d.append(i)
            if i * i != x:
                d.append(x // i)
        i += 1
    return d

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    vals = sorted(freq.keys())

    valid = set()

    for x in vals:
        ok = True
        m = x
        while m <= k:
            if m not in freq:
                ok = False
                break
            m += x
        if ok:
            valid.add(x)

    covered = set()
    B = []

    for x in a:
        if x in covered:
            continue

        found = False
        for d in get_divisors(x):
            if d in valid:
                B.append(d)
                found = True
                break

        if not found:
            print(-1)
            return

        # mark coverage
        b = B[-1]
        for m in range(b, k + 1, b):
            covered.add(m)

    print(len(B))
    print(*B)

if __name__ == "__main__":
    solve()
```頻度マップを使用すると、複数を検証するときに定数時間のメンバーシップ チェックが可能になります。 妥当性ループは x のステップで進み、範囲全体をスキャンするのではなく、関連する倍数のみに触れることを保証します。 

有効な解はその要素の少なくとも 1 つの約数を選択する必要があるため、カバーされていない各要素の約数の列挙は安全です。そのため、候補が存在する場合は必ず見つけることができます。 

カバレッジの更新は意図的に広範囲に行われます。b を選択すると、b のすべての倍数がカバーされると見なされます。これは、これらがまさに将来の選択を強制するために関連する要素であるためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、k が大きいにもかかわらず、配列に含まれる数値が小さい場合です。 たとえば、a = [2] および k = 100 の場合、アルゴリズムは 100 までのすべての倍数の存在を検証することによって 2 の有効性をチェックします。それらが欠落しているため、2 は拒否され、2 番目の条件を満たす有効な b がないため、アルゴリズムは正しく -1 を返します。 

もう 1 つのケースは、a = [1,2,3,4,5,6] のような密な構造化配列です。 ここでは、k までのすべての倍数が配列内に出現するため、すべての数値が有効です。 1 が選択されるとすでにすべてがカバーされ、冗長な追加が防止されるため、アルゴリズムは依然として小さなサブセットのみを選択します。 

最後の微妙なケースは、要素に対して複数の約数が可能な場合に発生します。 たとえば、a_i = 12 では、除数 2、3、4、6 が許可される可能性があります。これらの一部のみが有効であり、アルゴリズムは無効な除数を誤って選択しないようにする必要があります。 除数スキャンは、選択前に事前に計算された有効なセットと除数を交差させることによってこれを強制します。
