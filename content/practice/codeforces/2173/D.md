 ## 問題の理解

 タイガには正の整数が与えられます`n`そして正確に実行できる`k`動く。 それぞれの動きで、彼女は 2 の累乗を選択します。`2^ℓ`に追加します。`n`。 各移動のスコアは、加算中に発生するバイナリ キャリーの数です。 タイガはすべてのキャリーの合計数を最大化したいと考えています`k`動く。 

たとえば、次の場合`n = 7`(`111`バイナリで）そして彼女は付け加えた`2^0 = 1`、追加`111 + 001`結果として`1000`そして 3 つのキャリーが生成されます。 もし`k = 1`、合計スコアは 3 です。`k > 1`、キャリーはすでに 1 を持つビットを介して伝播する可能性があるため、連続する動きでの 2 の累乗の選択は、将来発生するキャリーの数に影響します。 

入力により複数のテスト ケースが提供されます。 各テスト ケースには、`n`ほぼまで`2^30`そして`k`まで`10^9`。 こんなに大きなもので`k`、すべての動きを繰り返すか、すべての選択肢を試します。`ℓ`実現不可能です。 ビット数にほぼ比例して時間内に機能する戦略が必要です。`n`、 ない`k`。 

次の場合、微妙なエッジケースが発生します。`n`バイナリ形式では末尾に 1 が多数あります。 追加`2^0`これらの 1 を伝播する複数のキャリーを繰り返し生成します。 例えば、`n = 3`(`11`バイナリ）と`k = 2`: 追加`2^0`最初に生成する`11 + 01 = 100`、2つのキャリー。 次の動きでは、新しいバイナリ状態を考慮する必要があります`100`。 次にどのビットを追加するかを追跡しない単純なアプローチでは、合計キャリーが過小評価されてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な手を試みます。 移動のたびに、すべての項目をチェックします。`ℓ`0 から設定された最上位ビットまで`n`そしてキャリー数を計算します。 これはすべてのオプションを検討するので正しいですが、次の場合には失敗します。`k`大きいです。 演算の数は O(k * ビット数) となり、これは法外です。`k = 10^9`。 

重要な洞察は、キャリーの数は、連続する末尾の 1 にのみ依存するということです。`n`。 追加`2^0`の数字に`m`末尾の 1 によって生成される`m + 1`運ぶ。 スコアを最大化するには、常に最小ビットに加算する必要があります。`ℓ`そのような`n`これは最長のキャリーチェーンを生成するため、その位置以下に 1 があります。 このような加算を実行すると、後続の値が単一の 0 に変わり、その後にゼロまたは次の 1 が続き、プロセスが繰り返されます。 

事実上、問題は、末尾の数を繰り返し見つけることになります。`n`、それをスコアに追加してからインクリメントします`n`対応する 2 のべき乗によって計算されます。 このアプローチは、バイナリの長さのみに依存します。`n`、大きなものを扱うことができます`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. テストケースごとに初期化します。`total_score`ゼロに。 
2. その間`k > 0`、現在の末尾にある連続する 1 の数を決定します。`n`。 これは次を使用して実行できます`n & -n`または最下位ビットから始めてビットを数えます。 
3. しましょう`m`末尾の数になります。 追加のスコア`2^0`この状態では`m + 1`。 
4. インクリメント`total_score`による`m + 1`。 
5.アップデート`n`追加することで`2^0 << m`(同様に、`n += 2^0`ただし、キャリーを伝播した後、後続のキャリーが反転されます)。 
6. デクリメント`k`1までに。 
7.すべてになるまで繰り返します`k`動きが使われます。 
8. 出力`total_score`このテストケースでは。 

これが機能する理由: 利用可能な最下位ビットでの各加算により、そのステップで可能な最大のキャリーが生成されます。 後続のものによってキャリー チェーンが決定されるため、それらを順番に処理することで、それぞれの動きが最適化されることが保証されます。 各移動は後続の移動を厳密に削減またはリセットするため、プロセスは収束し、最大で`log n`たとえ反復しても`k`大きいです。 もし`k`後続のすべての移動が処理された後に残っている場合、残りの移動ごとに 1 つのキャリーが追加されます。これは直接追加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_carries(n, k):
    total = 0
    while k > 0:
        if n == 0:
            total += k
            break
        # count trailing ones
        trailing_ones = 0
        temp = n
        while temp & 1:
            trailing_ones += 1
            temp >>= 1
        total += trailing_ones + 1
        n += 1 << trailing_ones
        k -= 1
    return total

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    print(max_carries(n, k))
```解決策は次のようになります`t`テストケース。 それぞれについて、移動をループします。 重要な操作は後続のものをカウントすることです。これにより、追加によって生成されるキャリーの数が決まります。`2^0`。 アップデート後`n`そして減少します`k`、ループが続きます。 もし`n`ゼロに達すると (すべてのビットがクリアされます)、残りの移動はそれぞれ 1 つのキャリーに寄与します。

 ## 特殊なケース

 もし`n = 0`そして`k > 0`、各手ごとにキャリーが 1 つ追加されます。 アルゴリズムは即座に検出します`n == 0`そして追加します`k`不必要な計算を行わずに合計スコアを返します。 

もし`n`次のように、末尾に 1 が連続しています。`n = 7`(`111`） そして`k = 1`、最初の動きは追加します`2^0`そして 3 つのキャリーが生成されます。 ループは後続のものを正確にカウントし、更新します`n`に`1000`バイナリで。 

のために`k`後続の動きを使い果たすために必要以上に大きい場合、残りの動きはそれぞれ合計スコアに 1 を加えます。 例えば、`n = 1`、`k = 5`、最初の動きで 2 つのキャリーが追加され、次の 4 つの動きでそれぞれ 1 が追加され、合計 6 になります。アルゴリズムはこの動作を自然に捕捉します。
