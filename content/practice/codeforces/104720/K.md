 ## 解決策
 ## 問題の理解

 それぞれが 2 つの半径で記述されるいくつかの「ドーナツ」が与えられます。 内側の半径は穴を定義し、外側の半径はドーナツの全範囲を定義します。 ドーナツの外側の境界がその穴の中に完全に収まる場合、ドーナツは別のドーナツの穴の中に配置できます。 この入れ子は継続し、次のドーナツが前のドーナツの穴の中に収まるチェーンを形成します。 

有効な「ドーナツ リング」は、入れ子になったドーナツのチェーンです。 チェーンを取る場合、合計の寄与は半径にのみ依存します。各ドーナツはその面積に寄与しますが、最も外側の構造の穴は領域を空きスペースとして削除します。 ジオメトリを単純化した後、目的は、有効なネスト順序で選択されたドーナツの二乗半径に線形に依存する数量を最大化することに減ります。 

具体的には、各ドーナツの最終価値への寄与度は次のように表すことができます。$R_i^2 - r_i^2$一方、ネストすると制約が導入されます。ドーナツ A がドーナツ B の中にある場合、$R_A \le r_B$。 目標は、ネスト制約を考慮して、これらの値から導出されるグローバル スコアを最大化するチェーンを選択することです。 

入力サイズ$n \le 10^5$これよりも悪い解決策があることを意味します$O(n \log n)$タイムアウトになる危険性があります。 すべてのペアまたはすべてのチェーンをチェックする 2 次解は、最大で次の時間が必要となるため、直ちに実行不可能です。$10^{10}$操作。 

いくつかの微妙な特殊なケースが重要です。 

1 つのドーナツは正しく扱われなければなりません。 それが唯一の選択肢である場合、答えは単純です$R^2 - r^2$、マイナスになる可能性があります。 たとえば、次のようなドーナツ$r = 5, R = 10$貢献する$100 - 25 = 75$。 

もう 1 つのエッジ ケースは、すべてのドーナツがネストに「互換性がない」場合です。つまり、満足できるドーナツが 2 つもない場合です。$R_i \le r_j$。 その場合、答えは最大の単一値であり、ゼロや空のチェーンではありません。 例えば、$(r,R) = (1,10), (2,3)$ベストアンサーを与える$\max(100-1, 9-4)$。 

3 番目のケースは、多くのドーナツが同一またはほぼ同一の半径を共有する場合です。これにより、等価性を慎重に処理せずに厳密な順序付けを前提とする素朴な貪欲なアプローチが破られる可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのネスト チェーンを構築しようとします。 各ドーナツについて、それを開始点として試し、外側の半径が現在の内側の半径に適合するドーナツを再帰的に追加することができます。 これにより、各ノードが他の多くのノードに分岐できる可能性のある DAG が形成されます。 最悪の場合、すべてのドーナツが他の多くのドーナツに適合し、探索されたチェーンが指数関数的に増加する可能性があります。 有効なチェーンの数が依然として非常に多い可能性があるため、枝刈りを行ってもあまり役に立ちません。 

重要な観察は、ネストには厳密な順序条件が課されるということです。つまり、ドーナツ A がドーナツ B の中に入る場合、$R_A \le r_B$。 これにより、問題は半径によって順序付けられた有向非環状構造に変換され、遷移はより小さな外半径からより大きな内半径へのみ進みます。 意味のあるキーでドーナツを並べ替えると、問題を有効な先行データに対する 1 次元の最適化に変換できます。 

各ドーナツをセグメントの制約と値として再解釈します。 タスクは、次の各要素が単調な実現可能性条件を満たし、値に寄与するシーケンスを選択することになります。 これは、ソートされたエンドポイントに対する動的プログラミングの古典的な設定であり、各ドーナツについて、互換性のある以前のドーナツをすべて使用して、そのドーナツで終わる最適なチェーンを計算します。 

遷移は、外半径が現在の内半径に適合する、以前の最適なドーナツを見つけることに依存します。 内側の半径で並べ替えると、外側の半径の圧縮された座標に対して二分探索またはフェンウィック ツリーを使用できるようになります。 これにより、互換性チェックが線形スキャンから対数クエリに削減されます。 

したがって、チェーンを列挙する代わりに、ドーナツを昇順に処理し、指定された外側半径のしきい値に対して達成可能な最良の値を保存する構造を維持します。

 ## アルゴリズムのチュートリアル

 各ドーナツを座標のペア (制約の終点と値) に変換します。 

## ステップ 1: 表現を正規化する

 各ドーナツについて、その貢献値を計算します$v_i = R_i^2 - r_i^2$。 また、互換性の境界も維持します。外側の半径が最大でも次のドーナツのみを追跡できます。$r_i$。 

これにより、各ドーナツは同時に「状態」と「制約」になります。 

## ステップ 2: 制約による並べ替え

 内側の半径を大きくしてドーナツを並べ替えます$r_i$。 これにより、ドーナツを処理するときに、すべての潜在的な先行処理 (外側半径の要件が小さいか等しい) がすでに考慮されることが保証されます。 

これが機能する理由は、実現可能性は一方の外半径と他方の内半径の比較のみに依存するため、内半径でソートすると自然な処理順序が作成されるためです。 

## ステップ 3: 外側半径の座標圧縮

 全部集める$R_i$値を取得して圧縮します。 これにより、フェンウィック ツリーまたはセグメント ツリーでインデックスを作成できるようになります。 

圧縮が必要な理由は、$R_i$まで可能です$10^9$、直接インデックス作成が不可能になります。 

## ステップ 4: 動的プログラミングの構造

 構造を維持する`best[x]`最後のドーナツの外半径が圧縮座標以下である有効なチェーンの達成可能な最大の美しさを表現します。$x$。 

これにより、互換性がプレフィックス最大クエリに変わります。 

## ステップ 5: ソートされた順序でドーナツを処理する

 ドーナツごとに$i$、それに先行できる最適なチェーンをクエリします。 満たさなければいけないので、$R_{prev} \le r_i$、外側半径が最大のすべての状態をクエリします。$r_i$。 

次に、次のように計算します。$$dp_i = v_i + \max(dp \text{ among valid predecessors})$$このドーナツだけで新たなチェーンを始めることも検討しています。 

計算後$dp_i$に対応する位置の構造を更新します。$R_i$。 

## ステップ 6: 最終的な答え

 答えはその中の最大値です$dp_i$。 

### なぜ効果があるのか

 重要な不変条件は、インデックスまでのすべてのドーナツを処理した後、$i$、構造体は、有効な以前のドーナツのみを使用して、実行可能なすべての外側半径境界に対して可能な限り最良のチェーン値を格納します。 処理順序は内側半径の増加に従うため、すべての有効な先行処理がすでに含まれていることが保証されます。 遷移では実現可能性が維持され、常に最良の先行遷移が採用されるため、最適なチェーンが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [-10**30] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = -10**30
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def main():
    n = int(input())
    donuts = []
    Rs = []

    for _ in range(n):
        r, R = map(int, input().split())
        donuts.append((r, R))
        Rs.append(R)

    Rs_sorted = sorted(set(Rs))
    comp = {v: i + 1 for i, v in enumerate(Rs_sorted)}

    donuts.sort()

    fw = Fenwick(len(Rs_sorted))

    ans = -10**30

    for r, R in donuts:
        v = R * R - r * r
        # best chain ending with R_i <= r
        # need all previous with outer radius <= r
        # find index of r in compressed Rs
        # upper bound
        import bisect
        idx = bisect.bisect_right(Rs_sorted, r)
        best_prev = fw.query(idx)

        if best_prev < 0:
            best_prev = 0

        cur = best_prev + v
        ans = max(ans, cur)

        fw.update(comp[R], cur)

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションは、圧縮された外側半径にわたってプレフィックスの最大値を維持することに依存しています。 フェンウィック ツリーは最大クエリにのみ使用されるため、更新では合計ではなく最大値が保存されます。 微妙な点は、ソートによって実現可能性をプレフィックス条件に変換し、次に二分探索を使用して内半径制約を圧縮座標系と位置合わせすることです。 

簡単な間違いの 1 つは、チェーンはどのドーナツからでも開始できるため、先行値にはゼロを許可する必要があることを忘れていることです。 これは、拡張前に負の結果をゼロにクランプすることで処理されます。
