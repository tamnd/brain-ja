 ## 解決策
 ## 問題の理解

 一連のハンバーガーが左から右に一列に配置され、各ハンバーガーにはフレーバー値が与えられます。 あらゆるポジションについて`i`、以前のポジションが何個あるかを数える必要があります`j`とペアリングできます`i`非常に特殊な条件下で。 

有効な`j`の左側にある必要があります`i`フレーバー値が小さくなります。 それを超えて、`j`単調な意味でも「見える」必要があります。`j`そして`i`より大きい要素があってはなりません`f_j`。 同様に、候補者を選択すると、`j`から見ると`j`右に示すように、厳密に よりも大きい値が初めて確認されたとき`f_j`、それはその向こうにあるものすべてに対する可視性をブロックします。 

したがって、それぞれについて`i`では、局所領域で支配的な以前の要素をすべて削除した後でも、関連性が残る以前の小さな要素をカウントしています。 

制約`N ≤ 10^5`本質的に二次関数である解は、`N^2`、遅すぎます。 すべてのペアを徹底的に比較するには、約`10^10`最悪の場合のチェックを実行しますが、これは 1 秒では実行できません。 これにより、スタックまたは単調なメンテナンスが使用される可能性が最も高く、線形または線形に近い構造にすぐに移行することになります。 

値が等しい場合、微妙なエッジケースが発生します。 条件は厳密に小さくする必要があるため、`f_j < f_i`、等しい値が寄与することはありませんが、構造の維持方法によっては可視性を妨げる可能性があります。 もう 1 つの特殊なケースは、配列が厳密に減少している場合に発生します。この場合、すべての要素が前のすべての要素に表示され、カウントが最大化されますが、厳密に増加し、すべての答えが 0 になります。 

## アプローチ

 直接的なアプローチは、各ペアを調べることです。`(j, i)`と`j < i`、どうかを確認してください`f_j < f_i`、次に間隔をスキャンします`(j, i)`どの要素も超過しないようにするため`f_j`。 これは定義上正しいですが、3 番目の条件により追加のスキャンが導入され、各ペアのチェックが直線的な作業に変わります。 完全な複雑さは、最悪の解釈では 3 次、よくても前処理を使用すると 2 次になりますが、これは限界をはるかに超えています。 

重要な観察は、「間に障害となる要素は存在しない」ということです。`j`そして`i`それはより大きい`f_j`” は、前の要素に対する支配的な構造を定義します。各要素は、後のより大きな値によって覆い隠されるまでのみ「アクティブ」のままです。これはまさに単調スタックの動作です。要素は減少する構造を形成し、新しい要素は有効なアンカーとして機能しなくなった弱い候補を削除します。 

値が減少する候補インデックスのスタックを維持すると、各新しい要素は以前の「生き残った」要素の少数のセットとのみ対話できます。 ポジションごとに`i`、有効な`j`値は正確に、以下より小さいスタック要素です。`f_i`なぜなら、それより大きいか等しいものは無関係であり、以前に削除されたものは間にあるものによってブロックされているため寄与できないからです。 

したがって、フレーバー値の単調減少スタックを維持しながら、左から右に処理できます。 それぞれについて`i`、厳密に以下の要素をスタックからすべて削除します。`f_i`、 なぜなら`i`今後、同じロールで可視化できるように、それらをブロックするようになりました。 残りのスタック構造は有効な貢献者を表し、そのうちの何人が条件を満たすかを数えます。 

これにより、問題は償却定数スタック操作による単一パスに変換されます。

 ## アルゴリズムのチュートリアル

 私たちは、フレーバー値が降順になるように配置された、以前のバーガーのインデックスを格納するスタックを維持します。 

1. 空のスタックと配列を初期化する`ans`サイズの`N`。 
2. 各インデックスを反復処理します。`i`左から右へ。 
3. スタックが空ではなく、スタックの一番上のフレーバーが以下の場合`f[i]`、ポップしてください。 これらの要素は、次のものに支配されているため、もはや関連性がありません。`i`。 
4. ポップした後、スタックにはフレーバー以上の要素のみが含まれます。`f[i]`つまり、背後にある弱い要素がさらに寄与するのをブロックします。 
5. 現在のポジションの答え`i`まだ満たしているスタック内の残りの要素の数です。`f_j < f_i`。 この構造では、これらはステップ 3 で削除された、まだ表示されている候補の要素に正確に対応します。`i`。 
6. 計算されたカウントを記録します。`i`。 
7. インデックスを押す`i`将来のポジションの新たな潜在的候補者としてスタックに追加されます。 

重要なのは、各要素がスタックに出入りするのは最大 1 回であるため、合計の作業は線形であるということです。 

### なぜ効果があるのか

 どの時点でも、スタックは、各要素が将来の要素に対する潜在的な「最後のブロッカー」を表す構造を維持します。 新しい価値観が生まれるとき`f[i]`到着すると、より小さい値はすべて削除されます。これは、それらが再び意味のある境界として機能することができないためです。その代わりに、それらを使用するであろう将来の要素は、次の影響を受けます。`i`初め。 これにより、スタックは常に、値の降順に並べられた有用な先行処理の最小セットであるという不変条件が保持され、スタックをカウントすることで有効な先行処理が正確にキャプチャされることが保証されます。`j`それぞれの値`i`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    f = list(map(int, input().split()))
    
    stack = []
    ans = [0] * n
    
    for i in range(n):
        # pop all strictly smaller values
        while stack and f[stack[-1]] < f[i]:
            stack.pop()
        
        # remaining stack elements are >= f[i], they do not count as valid j
        # valid j are exactly those removed in this step, but we don't need to
        # explicitly count them via another structure because the structure
        # ensures each element contributes exactly once when it gets popped
        ans[i] = 0  # will be adjusted conceptually via contributions below
        
        stack.append(i)
    
    # second pass idea correction: we instead compute contributions directly
    stack = []
    ans = [0] * n
    
    for i in range(n):
        count = 0
        while stack and f[stack[-1]] < f[i]:
            stack.pop()
            count += 1
        
        ans[i] = count
        stack.append(i)
    
    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションでは、概念的にはコード内で配列を 2 回処理しますが、実際に正しいカウント メカニズムとなるのは 2 番目のループだけです。 それぞれについて`i`、厳密に小さい以前の要素をすべてポップし、各ポップは 1 つの有効な要素に対応します。`j`このために`i`。 これらのポップされた要素はまさに、`i`それらの間には中間のより大きな要素が存在しないため、`i`、単調なスタック構造によって強化されます。 

重要な点は、スタックによって、以前のより大きな値によってブロックされていない要素のみが考慮されることが保証されることです。 したがって、ポップするたびに、左から右の順序と可視性の制約という両方の条件を同時に確認することになります。

 ## 特殊なケース

 次のような単一要素入力`[7]`結果は空のスタックになるため、答えは次のようになります。`0`、その後要素がプッシュされます。 アルゴリズムは、特別なケースを使用せずにこれを処理します。 

次のような厳密に減少するシーケンスでは、`[5,4,3,2,1]`、現在の値より小さいものはないため、どの要素もポップをトリガーすることはなく、各答えはゼロのままです。 以前の要素が有効になることがないことを反映して、スタックは単純に増加します。`j`後でより大きな値にします。 

次のような厳密に増加するシーケンスでは、`[1,2,3,4]`、すべての新しい要素は正確に 1 つの先行要素をポップし、各位置が正確に 1 つの有効なペアに寄与するチェーンを与えます。 スタックにより、より大きな値が出現したときに各要素が 1 回だけ削除され、予想されるカウントの線形累積と一致することが保証されます。
