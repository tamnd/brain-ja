 ## 解決策
 ## 問題の理解

 2 つの一連の料理が与えられ、各料理は 1 つの大文字で表されます。 最初のシーケンスはテーブル上の現在の配置であり、2 番目のシーケンスは希望する最終的な配置です。 許可される唯一の操作は、2 つの隣接するディッシュを交換することです。このような交換をできるだけ少なくして、最初のシーケンスを 2 番目のシーケンスに変換したいと考えています。 まったくできない場合は、不可能であることを報告しなければなりません。 

重要な制約は、スワップは隣接のみであるということです。そのため、基本的には、反転を使用してある文字列を別の文字列に変換するという古典的な概念を使用しています。 ただし、スワップではディッシュを作成または破壊できないため、これは 2 つのシーケンスにまったく同じ文字のマルチセットが含まれている場合にのみ機能します。 いずれかのキャラクターの出現回数が異なる場合は、すぐに変身することはできません。 

入力サイズは小さく、最大でも 100 皿です。 これは、二次アルゴリズムや三次アルゴリズムでも受け入れられることを意味します。 スワップをシミュレートしたり、すべての並べ替えを試行したりするソリューションはまだ合格しますが、既知の構造への完全な縮小を目指す必要があります。 

いくつかの特殊なケースが重要です。 

2 つの文字列間で文字の頻度が異なる場合、部分的な位置合わせが可能であっても、答えは -1 でなければなりません。 たとえば、変形する`AAB`の中へ`ABC`無いから無理だよ`C`ソースで。 

文字列がすでに等しい場合、答えは 0 です。 

すべての文字が同一の場合、どのような並べ替えも有効であり、答えは単に同一のシーケンスを整列させるために必要な隣接スワップの数になります。これらは区別できないため、常に 0 になります。 

## アプローチ

 強引なアイデアは、プロセスを直接シミュレートすることです。 文字列を繰り返しスキャンして不一致の位置を見つけ、隣接する文字を交換して正しい文字を所定の位置に押し込むことができました。 各スワップにより局所的な乱れが軽減され、文字列がターゲットと一致するか、進行が不可能になるまで続行できます。 

これは正しいです。各操作は有効であり、目標に到達した場合にのみ停止するからです。 問題は、単純にスワップをシミュレートするには、O(n) 個の位置にわたってキャラクターを移動する必要がある可能性があり、これを O(n) 個のキャラクターに対して実行すると、O(n²) 以上の動作が発生することです。 n が 100 までであればこれでも問題ありませんが、最も明確な推論方法ではありません。 

より構造化された観点は、これを反転計数問題として扱うことですが、ひねりが加えられています。任意の数値を並べ替えているのではなく、重複と固定されたターゲットの順序でシーケンスを整列させています。 ソース文字列を左から右にスキャンし、位置ごとに、一致する必要のある文字の出現を決定します。 そのペアリングを修正すると、必要なスワップの数は、その発生を所定の位置に移動することによって引き起こされる反転の数とまったく同じになります。 

重要な観察は、ターゲット内の各文字が特定のターゲット位置を決定し、出現したものを順番に照合できるということです。 このマッチングが修正されると、隣接スワップの最小数は、ソース注文とターゲット注文で選択されたポジション間のペアごとのクロスの数になります。 これは、シミュレーションの問題ではなく、カウントの問題に帰着します。

 ## アルゴリズムのチュートリアル

 1. まず、両方の文字列の文字数が同じであることを確認して、実現可能性を検証します。 不一致が存在する場合、スワップでは文字マルチセットが変更されないため、変換を完了できません。 
2. ソース文字列内の各文字について、その位置のリストを作成します。 ターゲット文字列に対しても同じことを行います。 これにより、出現間の決定論的なマッピングが得られます。`A`ソース内の最初の部分に対応する必要があります`A`ターゲット内、2 番目から 2 番目など。 
3. 配列を構築する`p`どこ`p[i]`現在ソース位置にある文字のターゲット インデックスです。`i`。 これにより、問題は、ソース順列がターゲット順列からどれだけ離れているかを測定することに変換されます。 
4. 配列内の反転の数を計算します`p`。 各反転は、2 つの要素の相対的な順序を固定するために必要な 1 つの隣接するスワップに正確に対応します。 
5. 反転回数を返します。 

反転解釈が機能するのは、隣接するすべてのスワップが 1 つの反転を正確に修正し、矛盾する他の構造を作成または破壊しないためです。 

### なぜ効果があるのか

 同一の文字間の組み合わせを修正することで曖昧さがなくなり、どちらを選択する必要がなくなりました。`A`どちらと一致しますか`A`、出現インデックスによって順序の一貫性を強制します。 このマッピングが確立されると、変換はインデックスの順列になります。 ある順列を別の順列に変換するために必要な隣接するスワップの最小数は、それらの間の反転距離とまったく同じです。これは、各隣接するスワップによって反転カウントが 1 つだけ変更され、残らなくなるまで常に貪欲に反転を減らすことができるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if sorted(s) != sorted(t):
        print(-1)
        return

    pos_s = {}
    pos_t = {}

    for i, c in enumerate(s):
        pos_s.setdefault(c, []).append(i)

    for i, c in enumerate(t):
        pos_t.setdefault(c, []).append(i)

    p = [0] * n
    for c in pos_s:
        for i, idx in enumerate(pos_s[c]):
            p[idx] = pos_t[c][i]

    inv = 0
    for i in range(n):
        for j in range(i + 1, n):
            if p[i] > p[j]:
                inv += 1

    print(inv)

if __name__ == "__main__":
    solve()
```解決策は、両方の文字列に同じ複数の文字セットが含まれていることを確認することから始まります。 n が小さく、直接等価性チェックが行われるため、ソートで十分です。 

次に、両方の文字列の各文字の出現インデックスを記録します。 重複は一貫して一致する必要があるため、これは不可欠です。 そうしないと、ペアリングが異なるとスワップ数が異なる可能性があります。 

配列`p`各ソース位置がターゲットの順序で終了する必要がある場所をエンコードします。 この順列が構築されると、残りの問題は純粋に組み合わせの問題、つまり逆数のカウントです。 

n が 100 にすぎないため、反転カウント ループは最も単純な方法で実装されます。フェンウィック ツリーも機能しますが、ここでは不要です。

 ## 特殊なケース

 主なエッジケースは、文字が頻繁に繰り返される場合です。 例えば`AAAAAB`に`BAAAAA`。 アルゴリズムはオカレンスを順番に正しく割り当てます。`B`は一貫して一致し、すべての反転はその固定されたアイデンティティに対して相対的にカウントされます。 単純な貪欲なスワップは誤って同一のものを扱う可能性があります`A`は交換可能であり、それでも正しい答えが得られますが、一貫したマッピングがないと、より複雑なミックスで交換のカウントを間違えやすくなります。 

もう 1 つの特殊なケースは、文字が欠落しているために完全に不可能であることです。 実現可能性チェックでは、頻度の比較によってこれを即座に検出し、部分的な一致によって不正確な数値回答が発生しないことを保証します。
