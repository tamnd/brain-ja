 ## 解決策
 ## 問題の理解

 私たちには、固定された選択肢のセットから 1 つの選択肢を正確に選択することで各質問に答えるクイズ システムが与えられます。 すべての選択肢には数値があり、クイズの合計結果は、すべての質問で選択された値の合計にすぎません。 重要なのは、すべての質問が可能な値の同じリストを共有するため、構造が均一であるということです。n 個の質問のそれぞれに対して同じ選択プロセスを独立して繰り返します。 

合計スコアが形成されると、それがいくつかの素の数値間隔と照合され、各間隔は特定の食品に対応します。 すべての食品について、結果の合計がその食品の範囲内に収まるようにクイズに答える方法が少なくとも 1 つ存在するかどうかを判断する必要があります。 

したがって、中心となる計算タスクは、すべての答えを明示的に構築することではなく、同じ値の複数セットから n 回独立して選択した後にどの合計が達成可能かを理解し、指定された範囲内でそれらの合計のメンバーシップを確認することです。 

制約は、状態空間動的プログラミング ソリューションを強く示唆するのに十分小さいです。 n と m が両方とも最大 20 である場合、選択の合計数は最大 20 ステップとなり、各ステップには最大 20 の選択肢が提供されます。 すべての m^n の可能性を指数関数的に列挙すると、20^20 まで増加しますが、これは実現可能な限界をはるかに超えています。 ただし、可能な最大合計は厳密に制限されています。各値は最大 20 であるため、最大合計は 400 になります。これにより、小さな整数範囲にわたる到達可能性を追跡することが可能になります。 

間違った解を引き起こす可能性がある微妙な問題は、異なるシーケンスが同じ合計をもたらす可能性があることを忘れていることです。 シーケンスを別のものとして扱うのは不必要であり、コストがかかります。 達成可能な合計のセットのみが重要です。 もう 1 つのよくある間違いは、貪欲な構築作業を想定することです。たとえば、質問ごとに常に最小値または最大値を選択するなどです。 これは失敗します。中間の組み合わせでは、純粋な極端な値では到達できない合計をアンロックできるからです。 たとえば、値 [1, 10] と n = 2 の場合、合計 11 は達成可能ですが、質問ごとに局所的に推論する場合、貪欲な戦略ではそのような組み合わせを誤って見逃す可能性があります。 

## アプローチ

 素朴なアプローチは、クイズに答えるためのあらゆる方法を列挙することです。 n 個の質問にはそれぞれ m 個の選択肢があるため、完全な解答用紙の総数は m^n になります。 それぞれについて合計を計算し、到達可能としてマークします。 これはあらゆる可能性を明示的に構築するため正しいですが、実行時間は指数関数的に増加します。 m と n が両方とも 20 までの場合、これは 20^20 の組み合わせになり、実行可能な計算をはるかに超えています。 

重要な観察は、質問の順序は合計には関係なく、すべてのステップで同じ値セットが再利用されるということです。 これにより、問題は繰り返しの合計集合の構築に変換されます。つまり、0 のみを含む集合から開始して、v の各値を以前に到達可能なすべての合計に追加するもう 1 つの層を繰り返し追加します。 n 層後、達成可能なすべての合計が得られます。 最大合計は 400 のみであるため、合計に対してブール値 DP を安全に維持し、n 回反復することができます。 

これにより、問題はシーケンスにわたる指数列挙から、有界状態空間にわたる多項式時間伝播へと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n・n) | お(1) | 遅すぎる |
 | 最適なDP | O(n · m · S) ただし、S ≤ 400 | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## 最適な DP 構造

1. ブール配列 dp を初期化します。ここで dp[s] は、いくつかの質問を処理した後に合計 s が達成可能かどうかを示します。 質問に答える前は合計がゼロになるため、 dp[0] = true と設定します。 
2. 次のプロセスを質問ごとに 1 回、正確に n 回繰り返します。 各反復は、合計に選択した値をもう 1 つ追加することを表します。 
3. 反復ごとに、false に初期化された新しい配列 next_dp を作成します。 この配列には、もう 1 つの質問に答えた後に到達可能なすべての合計が格納されます。 
4. dp[s] が true となるすべての合計 s について、すべての可能な値 v_i を使用してそれを拡張してみます。 next_dp[s + v_i] を true としてマークします。 これは、現在の質問に対して回答 v_i を選択することに対応します。 
5. すべての合計と値を処理した後、dp を next_dp に置き換えます。 これにより、各レイヤーが以前の数の質問の結果のみを使用するようになり、同じステップ内での誤った再利用が回避されます。 
6. n 回の反復をすべて完了した後、dp は考えられるすべての最終スコアをエンコードします。 
7. 各食物間隔 [l, r] について、dp[s] が true となるような s がこの範囲内に存在するかどうかを確認します。 そのような合計が存在する場合、答えは「YES」です。 それ以外の場合は「いいえ」です。 

各間隔を独立して安全にスキャンできる理由は、各食品の決定は、そのような合計がいくつ存在するか、またはそれらが他の間隔とどのように重なるかではなく、少なくとも 1 つの有効な合計の存在にのみ依存するためです。 

### なぜ効果があるのか

 DP は、i 回の反復後、dp は i 個の質問選択を使用して達成可能なすべての合計を正確に表すという不変条件を維持します。 各遷移では、許可された値のセットから 1 つの選択肢が正確に追加され、長さ i + 1 の有効なシーケンスはすべて、長さ i に最終的な選択肢を 1 つ加えた有効なシーケンスに分解できるため、正確性が保たれます。 逆に、構築されたすべての遷移は実際の選択シーケンスに対応します。 遷移と有効な応答シーケンスの間のこの全単射により、完全性と健全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    q = int(input())
    intervals = [tuple(map(int, input().split())) for _ in range(q)]

    max_sum = n * max(v)
    dp = [False] * (max_sum + 1)
    dp[0] = True

    for _ in range(n):
        ndp = [False] * (max_sum + 1)
        for s in range(max_sum + 1):
            if not dp[s]:
                continue
            for val in v:
                if s + val <= max_sum:
                    ndp[s + val] = True
        dp = ndp

    for l, r in intervals:
        ok = False
        for s in range(l, r + 1):
            if 0 <= s <= max_sum and dp[s]:
                ok = True
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この実装は DP 構造を直接反映しています。 dp 配列は、異なる質問数からの状態が混在するのを防ぐために、各ステップで再割り当てされます。 境界チェックにより、可能な最大合計 n · max(v) を超えるインデックスが作成されないことが保証されます。 合計範囲が十分に小さいため、完全な走査さえ簡単ではないため、間隔チェックは単純なスキャンによって行われます。 

よくある落とし穴は、dp をその場で更新しようとすることです。 これにより、同じ質問の複数回の使用が誤って許可されてしまいます。
