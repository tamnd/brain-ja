 ## 解決策
 ## 問題の理解

 円形に配置されたシェフが与えられ、それぞれのシェフの「味覚指数」を表す固定値が関連付けられています。 最初のシェフを選択し、順番に円を移動し、時計回りのサイクルですべてのシェフを正確に 1 回訪問します。 おもしろいのは、訪問の順序が重要であるということです。最初に訪問したシェフはその値に 1 を乗算し、2 番目に訪問したシェフには 2 を乗じて、n 番目のシェフが n を乗算するまで続けます。 

タスクは、すべての可能な開始位置に対してこの加重合計を計算し、可能な最大値を返すことです。 

入力サイズは最大 100,000 人のシェフになる可能性があります。 すべての回転を試して完全な重み付き合計を最初から再計算するソリューションでは、O(n^2) 操作が必要となり、これでは遅すぎます。 線形時間に近づけるアプローチが必要です。 

重要なエッジケースは、すべての値が等しい場合です。 その場合、すべての回転で同じ結果が生成され、正しい解が回転インデックス付けの間違いにより誤って誤って再計算されてはいけません。 もう 1 つの微妙なケースは、非常に大きな値が 1 つ存在する場合です。 より高い乗数 (後の位置) に対する相対的な位置が答えを支配するため、回転処理は正確でなければなりません。 

## アプローチ

 素朴な考えは単純です。 各開始位置 k について、円の周りを歩くことをシミュレートし、i 番目に訪問した要素の i 倍の合計を累積し、最良の結果を追跡します。 各シミュレーションのコストは O(n) で、開始点が n 個あるため、合計の複雑さは O(n^2) になります。 n が最大 100,000 の場合、約 10^10 の演算が必要になりますが、これは実行不可能です。 

式の構造は、より効率的な観点を示唆しています。 1 つの回転を固定すると、重み付けされた合計は、その回転順序での配列の線形関数になります。 開始点を 1 ステップ移動しても、シーケンスが最初から再構築されるわけではありません。 すべての要素のウェイト位置を 1 つだけシフトします。 つまり、答えを再計算するのではなく、段階的に更新できるということです。 

現在の配置を、固定開始ローテーションにおける A[0]、A[1]、...、A[n-1] とします。 この配置の加重合計がすでにわかっていると仮定します。 配列を 1 ステップ回転すると、最後の要素が前に移動し、他の要素は 1 つずつ右に移動します。 このシフトにより、加重合計の連続する値の間に明確な代数関係が作成され、回転間の O(1) 遷移が可能になります。 

これにより、問題は 1 つの初期重み付き合計を計算し、回転効果から導出された漸化式を使用して n 回更新することに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての要素の合計を計算します。 この値は、回転間の移行で再利用されます。 
2. 配列がインデックス 0 から始まり、位置 i が (i+1) * A[i] に寄与すると仮定して、初期の加重合計を計算します。 これにより、ベースライン構成が得られます。 
3. 回転ごとに、前の重み付き合計から次の重み付き合計を導出します。 配列が右に 1 位置回転すると、すべての要素の重みが 1 ずつ増加します。ただし、前に移動する要素は重み n から重み 1 になります。この不均衡により、決定的な調整が行われます。 
4. 漸化式を使用します。現在の加重合計が S、合計合計が T、配列サイズが n の場合、1 回回転すると、新しい合計は S' = S + T - n * A[n - 1 - k] になります (回転の方向に応じて)。 実装では、インデックスの混乱を避けるためにスライディング ウィンドウの解釈を維持します。 
5. n 回すべての回転を繰り返し、結果を更新し、確認された最大値を追跡します。 

### なぜ効果があるのか

回転するたびに、インデックスが構造化された方法で並べ替えられます。つまり、ラップアラウンドする要素を除き、すべての要素の寄与が合計で均一に増加します。 これにより、加重和の変化は総和と 1 つの境界要素のみに依存します。 この更新ルールはすべての回転ステップに対して正確であるため、個々の位置を再計算する必要はなく、アルゴリズムはすべての有効な開始位置を 1 回だけ探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = input().strip().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    
    if len(n_and_rest) == n + 1:
        arr = list(map(int, n_and_rest[1:]))
    else:
        arr = list(map(int, input().split()))
    
    n = len(arr)

    total = sum(arr)

    cur = 0
    for i in range(n):
        cur += (i + 1) * arr[i]

    best = cur

    for i in range(1, n):
        cur = cur + total - n * arr[n - i]
        if cur > best:
            best = cur

    print(best)

if __name__ == "__main__":
    solve()
```コードはまず配列を読み取り、その合計を計算します。 次に、問題の定義を使用して初期の加重合計を直接計算します。 

キーの繰り返しがループ内に表示されます。各反復では、開始点を円形配列内で 1 位置ずつ前方に移動することをシミュレートします。 用語`total`は重みの一様な変化を考慮しますが、`- n * arr[n - i]`端から前まで折り返す要素の過剰にカウントされた寄与を削除します。 インデックス作成`arr[n - i]`各回転後にどの要素が新しい最初の要素になるかを追跡することに対応します。 

変数`best`すべての回転にわたる最大の加重合計を追跡します。 

よくある落とし穴は、左回転と右回転の規則を混合することです。 反復は一貫した方向を想定しており、インデックス付けが間違っていると、一見有効に見えても間違った答えが静かに生成されます。

 ## 特殊なケース

 単一のシェフの場合、アルゴリズムは初期の加重合計を値の 1 倍として計算し、回転ループによって何も変更されないため、出力はすぐに正確になります。 

次のような等しい値の場合`5 5 5 5`、すべての回転で同じ合計が得られます。 繰り返しても同じ値が生成されます。`total`等しい`n * value`、調整を正確にキャンセルします。 

次のような支配的な要素の場合`[1000000000, 1, 1, 1, 1]`、大きな値を早めに設定すると、乗数の露出が最大になります。 回転更新により、すべての位置でこの値が正しく移動され、各順列を明示的に再構築しなくても最大値が確実に見つかります。
