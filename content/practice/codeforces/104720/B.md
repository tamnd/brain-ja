 ## 問題の理解

 私たちには、決まった順序で捨てなければならない一連の装身具が与えられています。 各装身具には重さがあり、最大容量が 100 グラムの同一のゴミ袋もあります。$K$。 合計重量が超えない限り、1 つのバッグに複数の連続した装身具を入れることができます。$K$。 現在のバッグの使用を中止すると決めたら、そのバッグは捨てられ、新しい空のバッグが使用されます。 途中で充填されたバッグを常に 1 つ以上保持することは許可されていません。つまり、プロセスは厳密に順番に行われます。バッグを左から右に充填し、続行するか、バッグを閉じて新しいバッグを開始します。 

目標は、シーケンス全体を廃棄するために使用される袋の数を最小限に抑えることです。 

入力により得られるのは、$N$、装身具の数、重量が順に続きます。 出力は、順序を維持する必要があり、各バッグの容量があるという制約の下で、すべての装身具を梱包するために必要なバッグの最小数です。$K$。 

制約は十分に大きいため、二次次式または偶数次式を適用できます。$O(N \log N)$戦略には不必要なオーバーヘッドがかかります。 と$N \le 10^5$、$O(N)$貪欲スキャンは、1 秒の制限内で唯一安全なターゲットです。 以前のグループ化の決定を再検討したり、すべてのパーティション ポイントをシミュレートしようとするアプローチにはリスクが伴います。$O(N^2)$最悪の場合の動作は、許容範囲をはるかに超えています。 

単一の装身具が以下とまったく同じである場合、微妙なエッジケースが発生します。$K$。 その場合は専用のバッグを占有する必要があります。 たとえば、次のように入力します。```
3 5
5 1 1
```正しい出力は次のとおりです`2`。 等価性を慎重にチェックせずに常に「最初に適合し、後で分割」しようとする不注意な実装では、誤って結合しようとしたり、フルキャパシティ後にリセット ロジックを誤って処理したりして、間違ったグループ化につながる可能性があります。 

もう 1 つのケースは、すべての装身具が非常に小さく、合計が複数のバッグにぴったり収まる場合です。```
5 3
1 1 1 1 1
```正しい動作は、順番にパックし、次の要素を追加するときに容量を超える場合にのみリセットすることです。 

## アプローチ

 ブルートフォース戦略では、シーケンスを有効な連続グループに分割するためのすべての可能な方法をシミュレートします。 各グループの合計重量は以下でなければなりません$K$。 これは、装身具間のカット ポイントを選択し、各セグメントが有効かどうかを確認することと考えることができます。 がある$N-1$潜在的なカット位置があるため、$2^{N-1}$スプリットの選び方。 たとえ線形時間で分割を検証するだけだとしても、このアプローチは指数関数的になり、次の時点ではすぐに実行不可能になります。$N = 10^5$。 

もう少し構造化されたブルート フォース アプローチでは、動的プログラミングを使用します。$dp[i]$初めて必要な最低限のバッグです$i$小物。 それぞれについて$i$、以前のすべての位置を試します$j < i$セグメントが$(j+1..i)$1つのバッグに収まります。 これは正しく機能しますが、それでも問題が発生します$O(N^2)$最悪の場合、たとえば、すべての重みが小さく、すべてのプレフィックスが有効な場合、各状態は以前のすべての状態を強制的にスキャンします。 

重要な観察点は、順序が固定されており、各バッグが厳密な容量制限のあるスライド ウィンドウのように動作することです。 バッグに詰め始めると、次のアイテムが適合しなくなるまで、有効な部分セグメントを早めに分割してもメリットがないため、以前の選択を再検討する必要はありません。 これにより、問題は貪欲な梱包プロセスに変わります。次の装身具を追加すると容量を超えるまで蓄積し続け、その後バッグを閉じて新しいものを開始します。 

この貪欲な戦略は、同じ連続セグメントの異なる有効なパッキング間にコストの差がないため機能します。 唯一の目的はセグメントの数を最小限に抑えることであり、セグメントを可能な限り拡張すると、必要なセグメントの数は常にわずかに減少します。

 ## アルゴリズムのチュートリアル

 現在のバッグの累積重量と開封したバッグの数を維持しながら、装身具を順番に処理します。 

1. バッグのカウンターをゼロに初期化し、現在のバッグの累計をゼロに初期化します。 アクティブなバッグがない状態から始めます。 
2. 各装身具の重みを順番に繰り返します。 
3. 各装身具について、現在のバッグに追加すると超過するかどうかを確認します。$K$。 このチェックがアルゴリズムにおける唯一の決定点です。 
4. 適合する場合は、現在のバッグ合計に重量を追加して続行します。 これにより、制約に違反することなく、現在のバッグが可能な限り満たされた状態に保たれます。 
5. 適合しない場合は、現在のバッグが確定しているため、バッグカウンターをインクリメントします。 次に、この装身具を最初のアイテムとして新しいバッグを始めます。 
6. すべての装身具を処理した後、部分的に充填されたバッグがある場合、それは最後の開封ステップによってすでに暗黙的にカウントされているため、追加の調整は必要ありません。 

常に貪欲に充填することの背後にある理由は、容量が固定され順序が必須になると、将来の決定は独立して行われるため、袋の閉鎖を遅らせても将来の要素には決して役に立たないということです。 

### なぜ効果があるのか

 アルゴリズムは常に、容量内に収まる残りのシーケンスの最大のプレフィックスを含む単一のアクティブなバッグを維持します。$K$。 これは不変条件です。現在のバッグには、その開始点から始まる可能な限り最長の有効な連続セグメントが常に含まれます。 新しい要素が適合しない場合、現在のバッグを拡張することはできないため、新しいバッグの開始が強制されます。 

袋を早く閉じる代替ソリューションは、装身具の再配置や並べ替えを可能にすることなく有効なセグメントのサイズを縮小するため、袋の数を増やすだけです。 したがって、貪欲な構築では可能な限り最小限の数のセグメントが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    bags = 0
    cur = 0
    
    for w in arr:
        if cur + w > k:
            bags += 1
            cur = w
        else:
            cur += w
    
    if n > 0 and cur > 0:
        bags += 1
    
    print(bags)

if __name__ == "__main__":
    solve()
```実装は累計を保持します`cur`現在のバッグに。 次の重量を追加できない場合は、現在のバッグを増分して完成させます。`bags`そして蓄積を再開します。 微妙な点の 1 つは、最終的な未完成のバッグです。インクリメントするだけなので、`bags`いっぱいになったバッグを閉じるとき、現在のバッグの中に装飾品が入っていた場合は、最後にもう 1 つ追加する必要があります。 

このロジックにより、すべての装身具が正確に 1 つのバッグに属し、各バッグが容量の制約を遵守することが保証されます。

 ## 特殊なケース

 重要なエッジケースは、すべての装身具が容量と正確に一致する場合です$K$。 例えば：```
3 5
5 5 5
```アルゴリズムは最初のアイテムのバッグを開始し、次のアイテムが収まらない場合はすぐにバッグを閉じ、これを繰り返します。 各要素が独自のバッグとなり、出力を生成します`3`。 すべての加算がオーバーフロー状態を引き起こすため、貪欲なロジックはこれを自然に処理します。 

もう 1 つのケースは、多くの小さなアイテムが積み重なってバッグがいっぱいになる場合です。```
6 3
1 1 1 1 1 1
```累計は 3 になり、リセットされ、(1,1,1) と (1,1,1) の 2 つのバッグが生成されます。 各バッグが最大限に満たされるという不変条件により、早期の分割が発生しないことが保証されます。 

最後に、次のような混合ケースがあります。```
5 4
3 1 2 2 1
```アルゴリズムが局所的に最適な選択肢を再配置しようとしないことを示しています。 各決定は純粋に次の項目が適合するかどうかに基づいて行われます。順序は固定されており、早く分割するメリットはないため、これで十分です。
