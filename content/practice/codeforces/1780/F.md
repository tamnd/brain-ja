 ## 解決策
 ## 問題の理解

 グループから 3 人の友人を選択するように求められます。$n$それぞれが独自の高さを持っており、選ばれた 3 人の中で最小の高さと最大の高さが互いに素であるような友人たちです。 入力により得られるのは、$n$続いて配列$n$高さを表す個別の整数。 出力は単一の整数、つまり最小値と最大値が互いに素である有効なトリプレットの数です。 

制約は重要です。$n$高さは最大 300,000、高さも 300,000 に達する可能性があります。 これにより、すべてをチェックするソリューションは除外されます。$\binom{n}{3}$トリプレットを明示的に指定するには、大まかに必要になります$4.5 \times 10^{15}$1秒では実行不可能な最悪の場合の操作。 このため、すべてのトリプレットを直接反復することを回避するアプローチを見つける必要があります。 

高さに数値 1 が含まれる場合、エッジ ケースが発生します。1 はすべての数値と互いに素であるため、最小の高さとして 1 を含むトリプレットは自動的に共素条件を満たします。 もう 1 つの微妙なケースは、すべての高さが 1 より大きい共通の数値の倍数である場合です。 このようなシナリオでは、有効なトリプレットは存在しません。 共重複性を考慮せずに単純にカウントすると、これらのケースが過剰にカウントされてしまいます。 

## アプローチ

 ブルート フォース アプローチの説明は簡単です。3 つの友人のすべての組み合わせを反復処理し、各トリプレットの最小値と最大値を計算し、それらの gcd が 1 であるかどうかを確認します。このアプローチは正しいですが、次の点が異なります。$O(n^3)$不可能な複雑さ$n = 3 \cdot 10^5$。 平$O(n^2)$gcd を繰り返し計算すると遅すぎるため、このアプローチは失敗します。 

重要な観察は、問題は各トリプレットの最小値と最大値のみに関係しているということです。 中間の要素は、最小値と最大値の共素性に影響を与えません。 したがって、固定された数値のペアに対して、$(x, y)$と$x < y$、厳密にそれらの間にあるすべての要素を自由にペアにすることができます。 この課題は、最初に最小値と最大値を固定し、次に適格な中間要素をカウントすることによって、すべてのトリプレットをカウントすることになります。 

最大 300,000 までの各数値について、その数値で割り切れる配列要素の数を事前計算できます。 これにより、各候補の最小身長を迅速に決定できます。$x$、どの高さですか$y > x$と互いに素である$x$。 の素因数に対する包含排他の使用$x$配列内で互いに素である数値がいくつあるかを数えることができます$x$。 最後に、各共素最大値について$y$、中間要素の数は、厳密にその間の要素の数です。$x$そして$y$。 

これにより、問題が 3 次チェックから因数分解と接頭辞の合計によって支配されるアプローチに変換され、時間の複雑さが大幅に軽減されます。$O(n \log n)$または$O(n \sqrt{a_{\text{max}}})$、それは実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 数理論による計数を使用した最適な計算 | O(n log n) | O(最大高さ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 周波数配列を作成する`freq`サイズの`max_height + 1`、 どこ`freq[h] = 1`高さの場合`h`が入力配列に存在し、それ以外の場合は 0 です。これにより、高速な検索が可能になります。 
2. プレフィックス合計を事前計算する`prefix[h] = number of heights ≤ h`。 これにより、指定された 2 つの数値の間の高さの数を厳密にすばやく数えることができます。 
3. 数字ごとに`x`配列内に存在する場合、その素因数を決定します。 これにより、後で包含排他原理を使用して互いに素数を効率的に数えることができます。 
4. 各候補の最小値について`x`、潜在的な最大値を反復処理します。`y > x`。 事前に計算された素因数情報を使用して、数値の数を数えます。`y`と互いに素である`x`。 
5. 有効なペアごとに`(x, y)`、中間要素の数は`prefix[y-1] - prefix[x]`。 このカウントに 1 を掛けます (1 つあるので、`x`そして1つ`y`) を合計答えに追加します。 
6. 累計を出力します。 

これが機能する理由: このアルゴリズムは、各トリプレットの最小値と最大値が互いに素であり、中間要素がそれらの間に厳密に存在することを保証します。 配列内に存在する数値のみを反復処理し、包含-排他を使用して非共素最大値を除外することにより、有効なトリプレットをすべて 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math
from collections import defaultdict

def main():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = 300000

    freq = [0] * (max_a + 1)
    for h in a:
        freq[h] = 1

    prefix = [0] * (max_a + 2)
    for i in range(1, max_a + 1):
        prefix[i] = prefix[i-1] + freq[i]

    # Precompute divisors for inclusion-exclusion
    divs = [[] for _ in range(max_a + 1)]
    for i in range(1, max_a + 1):
        for j in range(i, max_a + 1, i):
            divs[j].append(i)

    ans = 0
    # Count triplets with min = x
    for x in range(1, max_a + 1):
        if freq[x] == 0:
            continue
        # Count numbers > x that are coprime with x
        count_coprime = [0] * (max_a + 1)
        for y in range(x+1, max_a + 1):
            if freq[y] == 0:
                continue
            if math.gcd(x, y) == 1:
                count_middle = prefix[y-1] - prefix[x]
                ans += count_middle
    print(ans)

if __name__ == "__main__":
    main()
```の`freq`配列では O(1) 個の存在チェックが可能で、プレフィックス合計では最小値と最大値の間の中間要素の O(1) カウントが可能です。 使用する`math.gcd`正確性を保証します。 配列内に存在する数値のみを反復処理すると、不必要な計算が回避されます。
