 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 私たちのタスクは、この配列を少なくとも 2 つの連続するサブセグメントに分割し、各サブセグメントの合計を計算し、これらの合計の最大公約数 (GCD) を取得することです。 考えられるすべての有効な分割の中で、可能な限り最大の GCD を生成する分割が必要です。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、配列と配列自体の長さを提供します。 出力はテスト ケースごとに 1 つの整数、つまり有効な分割を使用して達成可能な最大 GCD です。 

配列の長さが最大であるとすると、$2 \cdot 10^5$すべてのテスト ケースの合計も次のようになります。$2 \cdot 10^5$、考えられるすべての分割を素朴に検査するソリューションは遅すぎます。 単純なアプローチでは、すべてのセグメントの左右の境界のすべてのペアを試行する可能性があります。これには、$O(n^2)$さらに悪いことに、制限時間を大幅に超えてしまう場合もあります。 

配列にすべて同一の要素がある場合、微妙なエッジ ケースが発生します。 ここでは多くの分割が可能であり、慎重に選択すれば GCD が連続ブロックの合計と等しくなる可能性があります。 もう 1 つの注意が必要なケースは、配列に約数を共有しない素数または数値が含まれている場合です。 何らかの割り算特性を仮定する不用意なアプローチは、最大 GCD を過小評価する可能性があります。 例えば、`[1, 1, 1, 3]`に最適に分割します`[1, 1, 1]`そして`[3]`GCD が 1 ではなく 3 になるようにします。 

## アプローチ

 ブルートフォースアプローチでは、配列の可能な分割をすべて列挙します。$k$サブセグメントを分割し、それらの合計を計算してから、GCD を計算します。 これが機能するのは、少数の数値では GCD の計算が高速ですが、分割の数が指数関数的に増加するためです。 のために$n = 2 \cdot 10^5$、これは不可能です。 

重要な洞察は、最大 GCD が配列の合計を除算する必要があるということです。 させて$S = a_1 + a_2 + \dots + a_n$。 分割により合計が生成されると仮定します。$s_1, s_2, \dots, s_k$。 これらの合計の GCD と呼びます。$g$、ごとに分割する必要があります$s_i$、したがってまた$S = s_1 + s_2 + \dots + s_k$。 したがって$g$の約数でなければなりません$S$。 これにより、検索スペースが約数に縮小されます。$S$、最大でも$O(\sqrt{S})$。 

次に、各約数候補について$d$、各セグメントの合計が次の倍数である連続セグメントに配列を分割できるかどうかを貪欲にチェックできます。$d$。 左から右にスキャンして、累計を蓄積します。 合計が倍数に達するたびに、$d$、セグメントをカットします。 この方法で少なくとも 2 つのセグメントを形成できれば、$d$は有効な GCD です。 有効な最大のもの$d$すべての約数にわたるものが答えです。 

このアプローチは複雑さを大幅に軽減し、制約を考慮した場合に適しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 (除数チェック + 貪欲) | O(n * sqrt(S)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$、合計を計算します$S$。 
3. すべての約数を生成します。$S$。 数字なので$x$多くても$O(\sqrt{x})$これは効率的です。 
4. 約数を降順に並べ替えます。 まず大きな除数をチェックすると、有効な分割が見つかったときに早期終了できます。 
5. 各約数について$d$、配列を貪欲に分割しようとします。 

1. 累計の初期化`current = 0`そしてカウンター`segments = 0`。 
2. 配列を走査し、各要素を`current`。 
3. いつ`current`の倍数に達する$d$、増分`segments`そしてリセット`current`0にします。 
6. もし`segments >= 2`アレイをスキャンした後、`d`実現可能です。 それを最大 GCD として記録し、より小さい約数のチェックを停止します。 
7. このテスト ケースの最大 GCD を出力します。 

機能する理由: 貪欲な累積は、セグメントの合計が次の倍数を超える場合に機能します。$d$カットの前に次の要素を含めると、複数条件に違反します。 したがって、正確に倍数でカットすると、すべてのセグメントの合計が確実に割り切れます。$d$。 すべての約数をチェックすると、$S$降順では、最初の実現可能な約数が可能な最大の GCD であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def divisors(x):
    res = set()
    for i in range(1, int(x**0.5) + 1):
        if x % i == 0:
            res.add(i)
            res.add(x // i)
    return sorted(res, reverse=True)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    S = sum(a)
    max_gcd = 1
    for d in divisors(S):
        current = 0
        segments = 0
        for num in a:
            current += num
            if current % d == 0:
                segments += 1
                current = 0
        if segments >= 2:
            max_gcd = d
            break
    print(max_gcd)
```この解決策は、最初に合計のすべての約数を生成します。`S`テストケースごとに。 次に、次の倍数になるまで合計を累積することで貪欲な分割を試みます。`d`に達します。 最初`d`少なくとも 2 つのセグメントを許可することが最適な答えです。 除数のコレクションにセットを使用すると重複が回避され、並べ替えによりより大きな候補が最初に試行されるようになります。 

## 実用的な例

 **例 1:**

 入力:`[2, 2, 1, 3]`合計額:`8`。 約数:`[8, 4, 2, 1]`。 

| ステップ | 現在 | セグメント | アクション |
 | --- | --- | --- | --- |
 | 番号=2 | 2 | 0 | 続ける |
 | 番号=2 | 4 | 1 | カット、電流 = 0 |
 | 数値=1 | 1 | 1 | 続ける |
 | 番号=3 | 4 | 2 | カット、電流 = 0 |

 セグメント数 >=2、実現可能な GCD = 4。 

**例 2:**

 入力:`[1, 2]`合計額:`3`。 約数:`[3, 1]`。 

- チェック 3: 2 つ以上のセグメントに分割できません。 
- チェック1：分割できる`[1]`そして`[2]`。 最大 GCD = 1。 

これらの例では、貪欲パーティショニングが除数条件を正しく尊重し、最大 GCD を見つけていることを確認します。
