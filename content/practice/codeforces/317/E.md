 ## 解決策
 ## 問題の理解

 森林を表す 2 次元の整数グリッドがあります。 各セルは空にすることも、ツリーを含めることもできます。 プリンセスはセル (vx、vy) から始まり、彼女のシャドウは (sx、sy) から始まります。 各ターンで、プリンセスは 4 つの基本的な方向 (左、右、上、または下) のいずれかに 1 歩ずつ移動します。 同時に、影も王女の動きを真似して同じ方向に移動しようとしますが、木のある部屋には移動できません。 プリンセスもシャドウも木のセルに入ることができません。 目標は、最終的にプリンセスをシャドウと同じセルに導く一連の動きを決定するか、それが不可能であると報告することです。 

入力により、プリンセス、シャドウ、および最大 400 本の木のセットの座標が提供されます。 すべての座標は [-100, 100] の範囲内にあります。 グリッドが小さいため (すべての整数座標を考慮した場合、最大 201 × 201)、可能な位置に対する網羅的な検索が可能です。 一連の移動は 10^6 ステップを超えることはできないため、有限である限り長いパスでも許容されます。 

明らかではないエッジケースには、プリンセスの移動方向にある周囲の木によってシャドウが完全にブロックされる状況が含まれます。 たとえば、シャドウがプリンセスの 1 マス北にあるが、シャドウのすぐ北に木がある場合、単純な「プリンセスが動くたびにミラーリングする」アプローチは失敗します。シャドウは移動できず、永久に捕獲を回避する可能性があるためです。 もう 1 つのトリッキーなシナリオは、シャドウが狭い廊下にいて、プリンセスが行き止まりの方向から近づいているときに発生します。 解決策は、プリンセスが影を捕まえながら障害物を回避できることを保証する必要があります。 

## アプローチ

 ブルートフォースアプローチは、プリンセスがシャドウに到達するか、すべての可能性を使い果たすまで、各ステップで両方の位置を追跡しながら、プリンセスの動きのすべての可能なシーケンスをシミュレートすることです。 各状態には 4 つの可能な動きがあり、約 O(201×201 × 201×201) 位置の状態空間になります。 これは約 1.6×10^8 であり、枝刈りを考慮すれば管理可能ですが、慎重な最適化が必要になります。 単純な深さ優先検索では、状態が繰り返されるため、すぐに遅くなりすぎます。 

重要な洞察は、この問題がプリンセスとシャドウの位置を組み合わせた状態空間における最短経路探索としてモデル化できるということです。 各状態はタプル ((vx, vy), (sx, sy)) であり、移動は ((vx', vy'), (sx', sy')) に遷移します。ここで、(vx', vy') はプリンセスの空の隣人であり、(sx', sy') は目的地が木でない場合は同じ方向に移動し、それ以外の場合はその場に留まるシャドウです。 プリンセスの動きを考慮するとシャドウの動きは決定的であるため、分岐係数はわずか 4 であり、BFS を実行してシャドウを捕まえるための最小限の動きのシーケンスを見つけることができます。 BFS は最小限のステップを保証し、同じ状態に再びアクセスしないようにして、無限ループを回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(4^(ステップ)) | O(歩数) | 遅すぎる |
 | 結合状態の BFS | O(201㎡ × 201㎡ × 4) | O(201 ㎡ × 201 ㎡) | 承認済み |

 BFS アプローチは、プリンセスとシャドウの可能な位置の数がそれぞれ最大 201 平方メートルであり、およそ 1.6×10^8 の状態が得られるため、実現可能です。 注意深い記憶と訪問状態の追跡により、これは制約内に収まります。 

## アルゴリズムのチュートリアル

1. 入力を読み取ります: プリンセスの座標 (vx、vy)、シャドウ (sx、sy)、木の数 m、および木の位置のリスト。 O(1) ルックアップ用にツリーの位置をセットに保存します。 
2. BFS 状態をプリンセスとシャドウの位置のタプルとして表します: ((vx, vy), (sx, sy))。 また、状態の再訪問を避けるために、訪問済みセットを維持します。 
3. 開始状態と一連の移動を表す空の文字列を使用して BFS キューを初期化します。 
4. キューが空でない間に、状態 ((vx, vy), (sx, sy), path) をポップします。 プリンセスの位置がシャドウの位置と等しい場合は、パスを戻します。 これにより、シャドウが捕らえられたらすぐに終了することが保証されます。 
5. プリンセスの 4 つの可能な動き (左、右、上、下) のそれぞれについて、新しいプリンセスの位置 (nvx、nvy) を計算します。 この位置が木の場合はスキップします。 
6. 同時に、シャドウの新しい位置 (nsx、nsy) を計算します。 同じ方向にあるシャドウのターゲットセルが空いている場合は、そこにシャドウを移動します。 それ以外の場合、シャドウはその場に留まります。 
7. 結果の状態 ((nvx, nvy)、(nsx, nsy)) が訪問されていない場合は、訪問済みとしてマークし、更新されたパス (パス + 移動文字) とともにキューに追加します。 
8. プリンセスがシャドウをキャッチする状態が見つからないまま BFS が完了した場合、-1 を出力します。 

機能する理由: BFS は、プリンセスの移動数が増加する順に状態を探索します。 私たちは訪問した状態を追跡し、シャドウは決定論的に移動するため、すべての状態は一意であり、再訪問することはできません。 したがって、プリンセスが最初にシャドウに到達するときは、最小限の有効なパスに相当します。 障害物は、ツリーセルへの移動を拒否することで自然に処理されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    vx, vy, sx, sy, m = map(int, input().split())
    trees = set()
    for _ in range(m):
        x, y = map(int, input().split())
        trees.add((x, y))
    
    directions = {'L': (-1, 0), 'R': (1, 0), 'U': (0, 1), 'D': (0, -1)}
    
    start = (vx, vy, sx, sy)
    visited = set()
    visited.add(start)
    
    queue = deque()
    queue.append((vx, vy, sx, sy, ""))
    
    while queue:
        vx, vy, sx, sy, path = queue.popleft()
        if vx == sx and vy == sy:
            print(path)
            return
        
        for move, (dx, dy) in directions.items():
            nvx, nvy = vx + dx, vy + dy
            if (nvx, nvy) in trees:
                continue
            nsx, nsy = sx + dx, sy + dy
            if (nsx, nsy) in trees:
                nsx, nsy = sx, sy
            state = (nvx, nvy, nsx, nsy)
            if state not in visited:
                visited.add(state)
                queue.append((nvx, nvy, nsx, nsy, path + move))
    
    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、プリンセスとシャドウの開始位置で BFS キューを初期化します。 考えられるすべての動きをループして両方の位置を更新し、状態が再確認されないようにします。 移動シーケンスは文字列として段階的に構築されます。 解決策が存在しない場合は、-1 が出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(201㎡ × 201㎡ × 4) | プリンセス×シャドウ×技の最大可能状態 |
 | スペース | O(201 ㎡ × 201 ㎡) | すべての一意の位置を格納する訪問済み状態セット |
