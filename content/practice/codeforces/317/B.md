 ## 解決策
 ## 問題の理解

 アリの分散を 2 次元の整数グリッド上でシミュレーションするように求められます。 最初は、すべての _n_ 個のアリが原点 (0, 0) に配置されます。 時間は分刻みで進み、4 匹以上のアリを含むセルは毎分ごとに 4 匹のアリのグループを放出し、4 つの主要な隣のアリ (左、右、上、下) のそれぞれに 1 匹のアリを送ります。 アリの数が 4 匹未満のセルは移動しません。 移動が不可能になった後、指定された座標におけるアリの数を決定するように求められます。 

入力により _n_ (開始時のアリの数) クエリと _t_ クエリが提供され、各クエリは特定のグリッド セルにおける最終的なアリの数を尋ねます。 グリッド座標は最大 ±10^9 と非常に大きくなる可能性があるため、グリッド全体を明示的に表すことができません。 アリの数は 30,000 で制限されており、これは控えめであり、アクティブなセルの総数が管理可能なサイズを超えて爆発的に増加することはないことを示唆しています。 クエリは重複する可能性があるため、同じセルに複数回回答する必要がある場合があります。 

エッジ ケースには、アリがゼロである場合 (すべてのクエリが 0 を返す必要がある場合)、またはアリが非常に少ない場合 (セルが 4 つのアリに到達しない場合) が含まれます。 もう 1 つの微妙なケースは、すべてのアリが最終的に原点近くに定住するため、遠くにあるクエリ ポイントが有効な座標であってもゼロになるはずである場合です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。1 分ごとに段階的にシミュレーションします。 現在の状態を、座標をアリの数にマッピングする辞書に保存できます。 各反復ですべてのセルをスキャンし、アリが 4 匹以上いるセルについては、4 の倍数を減算し、各隣接セルに 1 を加算します。 このアプローチは問題の記述を反映しているので正しいですが、最悪のシナリオでは 30,000 匹のアリが複数の反復にわたって広がり、影響を受けるセルの数が急速に増加します。 各アリがさまざまな方向に移動できる場合、更新の数は簡単に 10^7 を超える可能性があり、これは 1 秒の制限時間としては遅いです。 

重要な洞察は、このプロセスが基数 4 の「キャリー」システムに似ているということです。 各セルはアリを 4 の倍数でしか分散できず、余りは 0 ～ 3 の間になります。グリッドは無限であるため、隣接するアリから提供されたアリに基づいて、任意の位置のアリの数を再帰的に計算し、分散を 4 による繰り返し除算として扱うことができます。 これにより、毎分シミュレーションするのではなく、メモ化を使用したトップダウンの再帰的シミュレーションを実装できるようになり、計算数が大幅に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | n=30,000 では遅すぎる |
 | メモ化による再帰 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アリの初期数を原点に保存します。 他のすべてのセルはアリがゼロの状態から始まります。 
2. 再帰関数を定義する`ants_at(x, y)`セルにあるアリの最終的な数を返します`(x, y)`。 値が以前に計算されている場合は、メモ化辞書から値を返します。 
3. もし`(x, y)`が原点なので、そこにアリの総数を考慮してください。 原点における最後のアリは、4 匹のグループを繰り返し除去した後の残りです。`n % 4`。 
4. 他のセルの場合`(x, y)`、最終的なアリの数は、4 つの近隣から流入してくるアリの数の合計です。 近隣住民それぞれが貢献できる`floor(ants_at(neighbor)/4)`アリを現在のセルに追加します。 
5. 計算された値をキャッシュします。`(x, y)`そしてそれを返します。 
6. を呼び出して各クエリに答えます。`ants_at(x_i, y_i)`。 

これが機能する理由: 不変条件は、考えられる 4 匹のグループがすべて分散した後、すべての細胞が最終的に残り 0 ～ 3 匹のアリで安定するということです。 再帰的計算では、隣接するセルからの寄与が考慮され、メモ化なしにセルを再訪問することはありません。 各アリは 4 の倍数でしか伝播できないため、再帰の深さと合計計算量はアリの総数によって制限されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000000)

def main():
    n, t = map(int, input().split())
    queries = [tuple(map(int, input().split())) for _ in range(t)]
    
    memo = {}
    
    def ants_at(x, y):
        if (x, y) in memo:
            return memo[(x, y)]
        if x == 0 and y == 0:
            memo[(x, y)] = n % 4
            return memo[(x, y)]
        total = 0
        for dx, dy in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
            nx, ny = x - dx, y - dy
            if abs(nx) + abs(ny) > 30000:  # pruning far cells
                continue
            total += ants_at(nx, ny) // 4
        memo[(x, y)] = total
        return total
    
    for x, y in queries:
        print(ants_at(x, y))

if __name__ == "__main__":
    main()
```の`memo`辞書は再計算を防ぎます。 セルはセル自体ではなく隣接するセルからアリを受け取るため、再帰は常に座標を 4 方向にオフセットします。 プルーニングはオプションですが、アリを受信できない非常に離れたセルのクエリを高速化できます。 再帰制限を設定すると、Python のデフォルトの深さエラーを確実に回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | メモ化により、各セルは隣接するセルからの寄与を最大 1 回処理します。 アリの数に比例する合計操作 |
 | スペース | O(n) | メモ化では、到達可能なセルの最終カウントのみが保存されます。 

n ≤ 30,000 であるため、アルゴリズムは 1 秒の制限とメモリ境界内に簡単に収まります。

 ## 特殊なケース

 n = 0 の場合、原点には 4 つのアリが存在しないため、すべてのクエリは 0 を返します。再帰はすぐに停止します。 

n = 4 の場合、origin はゼロを残してすべてのアリを分配し、近隣のアリはそれぞれ 1 つを受け取ります。 (0,0) をクエリすると 0 が返されますが、近隣のクエリでは 1 が返されます。 

遠くにある大きなクエリ、たとえば x = 10^9 の場合、アリのコロニーはそのような離れたセルに到達できないため、再帰は正しく 0 を返します。メモ化は到達不可能な位置を効果的に排除します。
