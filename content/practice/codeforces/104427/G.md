 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times M$各セルが黒または白のボード。 タスクは、すべてのセルに 3 つの操作のうち 1 つを正確に割り当てることです。 これらの操作は、グリッド上で色が反転する方法を定義します。何もしないとグリッドはローカルに変更されず、操作 2 はセルの 4 つの隣接セルすべてを反転し、操作 3 はセル自体とその 4 つの隣接セルすべての両方を反転します。 2 つのセルはエッジを共有する場合にのみ相互作用するため、各操作は選択したセルを中心とする小さな十字型の領域に影響します。 

目標は、すべての効果が適用された後にすべてのセルが白になるように、すべてのセルに操作を選択することです。 

グリッド サイズは最大 2000 x 2000 なので、最大 400 万個のセルが存在できます。 各セルには 3 つの選択肢があるため、演算の組み合わせを明示的に探索しようとするソリューションはすぐに実行不可能になります。$3^{4 \cdot 10^6}$構成。 構造を利用せずにセルごとに独立して推論しても、グローバルな更新を繰り返す必要がある場合は遅すぎます。 

重要な点は、操作が大きく重複していることです。 1 つのセルは、選択された最大 5 つの異なる操作の影響を受けます。2 回反転すると打ち消されるため、これらの相互作用は純粋にパリティ ベースです。 この構造は、問題が線形であることを強く示唆しています。$\mathbb{F}_2$、組み合わせではありません。 

素朴なアプローチは、操作を行ごとまたはセルごとに貪欲に割り当て、各選択の後にグリッドを更新することです。 これは、後方に伝播する後の反転によって以前の決定が無効になる可能性があるため、失敗します。 たとえば、単一行では次のようになります。```
B B B
```中央のセルで操作 2 または 3 を選択すると、両方の隣接セルが反転します。つまり、局所的な修正により、すでに修正されたセルが破損する可能性があります。 依存関係は非循環的ではありません。 

2 番目の障害モードは、異なるパリティ クラスのセル間の独立性を仮定することで発生します。 各操作はセルとその隣接セルの両方に影響を与えるため、グリッドは結合システムを形成し、すべての制約には個々のセルではなくローカルな隣接セルが関係します。 

したがって、本当の課題は、大規模な XOR 制約システムを効率的に解決することです。 

## アプローチ

 それぞれのセルの選択は、セルの小さな固定パターンを反転することに貢献します。 2 回反転するとキャンセルされるため、各操作をバイナリ ベクトルをグローバル状態に追加するものとして扱うことができます。 

演算を変数としてエンコードし、各セルの最終的な色をモジュロ 2 (黒 = 1、白 = 0) で追跡すると、各制約は XOR 上の線形方程式になります。 システムのサイズは巨大ですが、構造が私たちを救ってくれます。各方程式はローカルな 3 x 3 の近傍にのみ依存し、グリッドは通常のステンシルを備えた平面です。 

ブルート フォースの観点では、各セルを 3 つの状態を持つ変数として扱い、すべての相互作用をシミュレートします。 そのためには、グリッド全体に効果を繰り返し伝播する必要があり、コストがかかります$O((NM)^2)$最悪の場合は、緩和または繰り返しの更新によって行われます。 

重要な洞察は、操作が独立した自由度ではないということです。 代わりに、決定論的な構造を使用して行ごとに処理し、依存関係を排除できます。つまり、最初の行の操作を修正すると、後続のすべての行が強制されます。 これは、行内の各セルが$i$行内の操作のみに依存します$i-1$、$i$、 そして$i+1$、トップダウンを排除することができます。 

問題を最初の行の選択と制約を下方に伝播し、一貫性をチェックすることに落とし込みます。 各行には$M$セルと各行の遷移が線形である場合、ソリューションは検索ではなく構造化されたシミュレーションになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースシミュレーション |$O((NM)^2)$|$O(NM)$| 遅すぎる |
 | 行消去による線形伝播 |$O(NM)$|$O(NM)$| 承認済み |

 ## アルゴリズムのチュートリアル

 We first convert the problem into a binary system where black is 1 and white is 0, and each operation corresponds to XOR flips.

 演算配列を定義します$op[i][j]$最初は空です。 このアイデアは、最初の行を固定し、決定論的に下方に伝播することです。 

1. 最初の行では、行 2 がどのように動作する必要があるかに制約をエンコードすることによって、すべての可能性を暗黙的に試します。 分岐の代わりに、行 1 の操作を、後で一貫性によって解決されるパラメーターとして扱います。 
2. 前の行までの選択されたすべての操作を適用した後、現在の色の状態を表す作業グリッドを維持します。 このグリッドは段階的に更新されるため、最初から再計算することはありません。 各操作は一定数のセルにのみ影響するため、これは重要です。 
3. 各行について$i$上から下まで、行が確実に配置されます$i-1$真っ白になります。 行を処理するとき$i$、行を修正できる唯一の操作$i-1$列に並んでいる人たちはいますか$i-1$、 行$i$、行$i+1$、でも下に進んでるので漕ぎます。$i+1$まだ決まっていない。 これにより、列内に残っている黒セルを排除する独自の方法が強制されます。$i-1$行を使用する$i$。 
4. 具体的には、セルごとに$(i-1, j)$、前の操作後に黒になっている場合は、次の操作を選択する必要があります。$(i, j)$それはそれを反転します。 での操作のみなので、$(i, j)$影響を与えることができる$(i-1, j)$この段階では、色を修正するためにそれを決定的に割り当てます。 
5.列を固定した後$i$、行の効果を更新します$i$そして漕ぐ$i+1$、影響を受ける行のローリング ウィンドウを維持します。 
6. 最後を除くすべての行を処理した後、すでに固定された構造を使用して最後の行を一貫して白にできることを確認します。 いずれかのセルが黒のままであれば、不可能であると結論付けます。 

### なぜ効果があるのか

 行の各セル$i-1$行を処理するときに正確に修正されます$i$、その後のステップでは行は変更されません$i-1$。 これにより、厳密な依存関係の方向が作成されます: 行$i$行を修正する責任があります$i-1$。 各補正はローカルパリティのみに依存し、後方影響を導入しないため、システムは三角形になります。 三角形 XOR システムには、固有の解が存在する場合にはそれがあり、最後の行を満たすことができない場合は、選択された伝播パスに一貫性がないことを示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]
    
    # convert to 0/1
    a = [[1 if c == 'B' else 0 for c in row] for row in g]
    
    # operations: 0,1,2 where 1=type2, 2=type3
    op = [[0]*m for _ in range(n)]
    
    # copy of grid we mutate
    cur = [row[:] for row in a]
    
    def flip(i, j):
        if 0 <= i < n and 0 <= j < m:
            cur[i][j] ^= 1
    
    def apply(i, j, t):
        if t == 0:
            return
        if t == 1:
            # flip neighbors
            flip(i-1, j)
            flip(i+1, j)
            flip(i, j-1)
            flip(i, j+1)
        else:
            # flip self + neighbors
            flip(i, j)
            flip(i-1, j)
            flip(i+1, j)
            flip(i, j-1)
            flip(i, j+1)
    
    for i in range(n-1):
        for j in range(m):
            if cur[i][j] == 1:
                # we must fix this using row i+1 cell (i+1, j)
                # choose operation 3 so that it flips (i, j)
                op[i+1][j] = 2
                apply(i+1, j, 2)
    
    # check last row
    if any(cur[n-1][j] for j in range(m)):
        print(-1)
        return
    
    # fill remaining ops with 0
    for i in range(n):
        for j in range(m):
            if op[i][j] == 0:
                op[i][j] = 0
    
    print(1)
    for i in range(n):
        print(''.join(str(op[i][j]) if op[i][j] != 0 else '1' for j in range(m)))

if __name__ == "__main__":
    solve()
```実装はライブグリッドを維持します`cur`that tracks the effect of chosen operations. ヘルパーさん`apply`各操作の正確なフリップ パターンをエンコードし、アルゴリズムは行内のセルごとに貪欲なトップダウンの削除を強制します。$i$黒の場合、行内の操作を強制します$i+1$それはすぐに修正されます。 これにより、以前の行に再度アクセスする必要がなくなります。 

微妙な点の 1 つは内部の境界処理です。`flip`グリッドの外側のセルは無視されるためです。 もう 1 つは、操作を次の行にのみ割り当てるため、構築中に矛盾する方法でセルが 2 回変更されることがないことです。

 ## 特殊なケース

 黒のセルを含む 1×1 グリッドは、最も単純なストレス ケースです。 このアルゴリズムは行 0 を処理しますが、すぐには修正を割り当てる行 1 がないため、演算の解釈に応じて不可能性を正確に検出するか、境界ロジックを介して処理します。 重要な詳細は、隣接セルが存在しないため、どの操作もセルを反転できないことです。 

完全に白いグリッドは、アルゴリズムが不必要な操作を回避しているかどうかをテストします。 どの行にも黒のセルはないため、伝播はトリガーされず、出力はすべてデフォルトの操作のままとなり、条件を満たします。 

色が交互に並ぶ 1 つの列は、カスケード動作を示します。 各黒いセルは次の行での操作を強制し、このチェーンは分岐することなく下方向に続きます。 最後の行で実現可能性が決まり、不一致があると正しく拒否されます。
