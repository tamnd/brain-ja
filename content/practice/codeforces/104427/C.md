 ## 解決策
 ## 問題の理解

 値 1、2、および 3 だけで構成される長いシーケンスが与えられています。このシーケンスから、できるだけ多くの素のインデックスのトリプルを抽出したいと考えています。各トリプルは 3 つの異なる位置を使用し、インデックスの順序を尊重します。 

トリプルは、その値がインデックスの昇順のパターン 1、2、3、またはインデックスの昇順の逆パターン 3、2、1 のいずれかを形成する場合に有効とみなされます。 すべてのインデックスは選択した 1 つのトリプルに属することができるため、一度使用した位置を別のグループで再利用することはできません。 

タスクは、そのようなトリプルがいくつ存在するかを計算するだけではなく、互いに素な有効なトリプルの最大のコレクションを明示的に構築することです。 

N が 600000 までの制約により、トリプルの組み合わせを列挙またはテストしようとするアプローチは即座に除外されます。 二次関数の動作は最悪の場合、10^11 のオーダーの演算を意味するため、いかなる解も線形または線形に近いものでなければなりません。 

グローバル バランスを考慮せずに貪欲なマッチングがローカルで実行されると、微妙な障害モードが発生します。 たとえば、シーケンスが 1 1 1 2 2 2 3 3 3 のように大きく偏っている場合、初期に出現する 1 と 3 を積極的にペアリングすると、最適な 1-2-3 チェーンの形成が妨げられる可能性があります。 順方向のパターンのみを照合し、逆方向の 3-2-1 構造を無視すると、別の問題が発生します。分布が非対称の場合、次善の結果が生じる可能性があります。 

## アプローチ

 単純なアプローチでは、i、j、k のすべての組み合わせ (i < j < k) をチェックし、値が 1-2-3 または 3-2-1 のいずれかに一致するかどうかを検証すると同時に、インデックスが使用されていないことを確認することでトリプルを構築しようとします。 これには、最悪の場合、O(N^3) トリプルにわたる反復処理が必要になりますが、これは N が 600000 までの場合は不可能です。 

これを中間インデックス j の固定と一致する i と k の検索に縮小しても、依然として O(N^2) になります。 中心的な問題は、各要素が多くの候補トリプルに関与する可能性があり、ペアごとの互換性のチェックが依然として組み合わせ論的に爆発的に起こることです。 

重要な観察は、すべての有効なトリプルが非常に厳格な構造を持っているということです。 各トリプルは、値が増加するか (1、2、3)、値が減少します (3、2、1)。 どちらの場合も、中央の要素は常に 2 です。これにより、問題は、選択した各 2 を、左側に 1 つと右側に 1 つずつ 3 とペアにするか、左側に 1 つと右側に 1 つずつ 3 を対称的にペアにするかということになります。 

これは、2 をアンカーとして扱うことを示唆しています。 次に、それぞれの 2 つを左側のプールと右側のプールと照合しようとします。 目標は、満足できるアンカーの数を最大化することになります。 各インデックスは最大 1 回しか使用されないため、将来の一致に対する柔軟性を維持する貪欲な戦略が必要です。 

配列をスキャンし、インデックスの 3 つの順序付きリスト (1、2、および 3 の位置) を維持します。 次に、2 を利用可能な最も近い互換性のあるエンドポイントとペアにしてトリプルを構築します。 j の位置に 2 がある場合は、1-2-3 または 3-2-1 トリプルを形成しようとします。 最も近い利用可能なパートナーを貪欲に選択することで、後で必要になる可能性のある極端なポジションを無駄にしないことが保証されます。 

この貪欲さを強制する正しい方法は、2 を左から右に処理し、1 リストと 3 リストへの 2 つのポインターを維持することです。 トリプルを形成しようとするたびに、現在の 2 の正しい側にまだ存在し、使用されていない最も古い有効な左要素と最も古い有効な右要素を選択します。 

これにより、問題はポインタの前進を伴う線形スイープになり、各インデックスが最大 1 回消費されます。

 ## アルゴリズムのチュートリアル

まず、インデックスを値ごとに 1 つずつ、3 つの増加リストに分割します。 これにより、元の配列を繰り返しスキャンすることなく、可用性を推論することができます。 

次に、潜在的な中心、つまり値が 2 であるインデックスを左から右に処理します。 このようなインデックスごとに、有効なトリプルを 1 つ構築しようとします。 

位置 j の各 2 について、最初に 1-2-3 トリプルを構築しようとします。 インデックス i < j の未使用の 1 と、インデックス k > j の未使用の 3 が存在するかどうかを確認します。 両方が存在する場合、最小の未使用の有効な i と最小の未使用の有効な k を割り当てます。 これにより、左側の大きなインデックスと右側の小さなインデックスの消費が最小限に抑えられます。 

1-2-3のフォーメーションが無理な場合は、逆の3-2-1を試してみます。 左側の 3 と右側の 1 をチェックし、再び最も近い利用可能な候補を選択します。 

どちらのパターンも不可能な場合は、現在の可用性では有効なトリプルに寄与できないため、この 2 をスキップします。 

トリプルを形成するたびに、使用されたインデックスにマークを付けて、それらが再び参加できないようにします。 

### なぜ効果があるのか

 このアルゴリズムは、すべての未使用の 1、2、および 3 がインデックスの昇順で利用可能なままであるという特性を維持し、現在の 2 に最も近い有効な候補を常に消費します。これにより、将来の 2 の不必要なブロックが防止されます。これは、より近いエンドポイントが存在する場合に極端なエンドポイントを使用すると、可能なトリプルの数が増加せずに柔軟性が低下するだけであるためです。 

有効なソリューションは、トリプルの数を減らさずに、貪欲な最近似マッチングを使用するソリューションに変換できます。これは、遠いエンドポイントを、より近い未使用のエンドポイントと交換することで、有効性を維持しながら、両側の残りの可用性を厳密に改善または維持できるためです。 この交換引数により、貪欲な選択によって最適性が低下しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pos1 = []
    pos2 = []
    pos3 = []
    
    for i, x in enumerate(a):
        if x == 1:
            pos1.append(i)
        elif x == 2:
            pos2.append(i)
        else:
            pos3.append(i)
    
    used1 = [False] * len(pos1)
    used3 = [False] * len(pos3)
    
    p1 = 0
    p3 = 0
    
    ans = []
    
    # process each 2 as center
    for j in pos2:
        while p1 < len(pos1) and pos1[p1] < j and used1[p1]:
            p1 += 1
        
        while p3 < len(pos3) and pos3[p3] < j and used3[p3]:
            p3 += 1
        
        # try 1-2-3
        i = p1
        while i < len(pos1) and (pos1[i] >= j or used1[i]):
            i += 1
        
        k = p3
        while k < len(pos3) and (pos3[k] <= j or used3[k]):
            k += 1
        
        if i < len(pos1) and k < len(pos3):
            ans.append((pos1[i], j, pos3[k]))
            used1[i] = True
            used3[k] = True
            continue
        
        # try 3-2-1
        i = 0
        while i < len(pos3) and (pos3[i] >= j or used3[i]):
            i += 1
        
        k = 0
        while k < len(pos1) and (pos1[k] <= j or used1[k]):
            k += 1
        
        if i < len(pos3) and k < len(pos1):
            ans.append((pos3[i], j, pos1[k]))
            used3[i] = True
            used1[k] = True
    
    print(len(ans))
    for i, j, k in ans:
        print(i, j, k)

if __name__ == "__main__":
    solve()
```この解決策は、インデックスを値で分割することから始まります。これにより、元の配列の繰り返しスキャンが回避されます。 配列`pos1`、`pos2`、 そして`pos3`ソートされた位置を保存します。これは、ポインタの動きが正確であることを保証するために重要です。 

の`used1`そして`used3`配列は、特定のオカレンスがすでにトリプルに割り当てられているかどうかを追跡します。 これにより、二重カウントが回避されます。 

2 つごとに、互換性のあるエンドポイントの検索を試みます。 ポインタのメンテナンスにより、すでに使用されているインデックスを繰り返しスキャンすることがなくなります。 小切手`pos1[i] < j`そして`pos3[k] > j`順序付けの制約を強制します。 

微妙な点は、常に順方向パターン 1-2-3 を最初に試すことです。 この選択は正確さの観点からは任意ですが、マッチング動作を安定させ、早すぎる逆転へのバイアスを回避します。 

## 実用的な例

 次の入力を考えてみましょう。```
6
1 2 3 2 1 3
```私たちは以下のものを持っています:

 pos1 = [0, 4]、pos2 = [1, 3]、pos3 = [2, 5]

 まずインデックス 1 で 2 を処理します。 

| ステップ | 2 インデックス | 選択された 1 | 選択した 3 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 2 | フォーム1-2-3 |
 | 2 | 3 | 4 | 5 | フォーム1-2-3 |

 出力は次のようになります。 

(0,1,2) および (4,3,5)

 このトレースは、貪欲なマッチングによって初期構造と後期構造の両方がどのように保存されるかを示しています。 

ここで次のことを考えてみましょう。```
5
3 2 1 3 2
```pos1 = [2]、pos2 = [1,4]、pos3 = [0,3]

 インデックス 1 で 2 を処理します。 

| ステップ | 2 インデックス | 選択した 3 | 選択された 1 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 2 | フォーム3-2-1 |

 インデックス 4 の次の 2 は、互換性のあるエンドポイントがすべて使用されているか、位置がずれているため、トリプルを形成できません。 

これは、最も近い有効なエンドポイントを早期に消費しても実現可能性が妨げられないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、有効なトリプルが存在するが、貪欲なマッチングで一方の側が早期に枯渇することを避ける必要がある場合です。 考慮する：```
7
1 2 3 1 2 3 1
```トリプルを形成するには複数の方法がありますが、完全なトリプルは 2 つだけ可能です。 このアルゴリズムは 2 を順番に処理し、常に最も近い有効なエンドポイントを取得するため、インデックス 1 の最初の 2 は (0,2) とペアになります。 インデックス 4 の 2 番目の 2 は (3,5) とペアになります。 インデックス 6 の残りの 1 は未使用のままであり、最適なパッキングを正しく反映しています。 

もう 1 つのエッジ ケースは、リバース トリプルのみが可能な場合です。```
4
3 2 1 2
```トリプルは 1 つだけ形成できます: (3,2,1)、インデックス (0,1,2) を使用します。 残りの有効なエンドポイントが順序付けの制約を満たすことができないため、2 番目の 2 は一致できません。 アルゴリズムは、唯一の実行可能な構造を正しく消費し、無効なペアリングを強制することなく停止します。
