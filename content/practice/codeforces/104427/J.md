 ## 解決策
 ## 問題の理解

 私たちは生徒の列を与えられ、各生徒にはクラス番号が付けられています。 このプロセスでは、同じクラスの 2 人の生徒が繰り返し削除され、削除されるたびに、削除直前のライン内の現在の位置間の距離が計算されます。 ペアを削除すると、線が圧縮されるため、残りの生徒の位置が左に移動してギャップを埋めます。 

このプロセスは、どのクラスにも少なくとも 2 人の生徒が残るまで続きます。 すべてのクラスは、その頻度の半分に等しい複数の削除操作を独立して提供します。難点は、以前の削除は圧縮によって後の位置を変更するため、各削除の値がいつ実行されるかに依存することです。 

タスクは、合計の累積距離が最大になるように、各クラス内の生徒のペアと、これらのペアを削除する順序の両方を選択することです。 

制約は大きく、すべてのテスト ケースにわたる生徒の総数は 700 万人に達する可能性があります。 これにより、動的プロセスのシミュレーションが即座に除外されます。 リストを繰り返し更新したり、位置を明示的に維持したり、操作ごとに距離を再計算したりするアプローチは、非常に遅すぎます。 解決策は本質的に、問題を入力全体の線形または線形に近いスイープに減らす必要があります。 

相互作用を考慮せずに各クラスを独立して処理できると仮定すると、微妙な失敗例が発生します。 たとえば、次のような混合シーケンスでは、`1 2 1 2`、クラス 1 とクラス 2 内のペアリングは独立して正しいペアリングを提供しますが、削除の順序によって最終スコアが変わります。 最初にクラス 1 を削除すると、クラス 2 の位置は、最初にクラス 2 を削除した場合とは異なる方法で圧縮され、異なる合計になります。 したがって、正しいソリューションは、クラスごとの構造だけでなく、クラス間の干渉を考慮する必要があります。 

## アプローチ

 単純な解決策では、プロセスを明示的にシミュレートします。 現在のリストを維持し、少なくとも 2 つの出現が残っているクラスを繰り返し選択し、ペアを削除し、現在の距離を計算して、構造を更新します。 バランスの取れたツリーまたはリンク リストを使用する場合でも、削除のたびに位置を更新したり、順序統計を維持したりする必要があります。 最大 700 万の要素と潜在的に数百万の削除を伴うこのアプローチは、インデックスの更新と範囲のシフトが繰り返されるため、実際には少なくとも 2 次の動作に低下します。 

重要な観察は、立場は変化しますが、その変化の方法は高度に構造化されているということです。 削除するたびに 2 つの要素が削除され、削除された位置の右側にあるすべての要素は 2 つだけ左に移動します。 これは、残りの要素の相対的な順序は決して変更されず、均一な圧縮効果のみが適用されることを意味します。 

スコアを別の方法で再解釈することもできます。 各ペアは、元のインデックス作成におけるエンドポイント間の距離に等しい基本値を提供しますが、以前の削除が厳密に 2 つのエンドポイント間で発生するたびに、この値は減少します。 このような早期の削除ごとに、寄与分がちょうど 2 ずつ減少します。 したがって、最終スコアは、固定間隔の長さの合計から、除去を表す間隔間の交差によって引き起こされるペナルティを差し引いたものとみなすことができます。 

この再構成により、問題は各クラスのペアリングの選択と、交差ペナルティが最小限に抑えられる処理間隔の順序の選択に変換されます。 明らかな構造は、クラス内の最適なペアリングは、最初と最後、2 番目と最後というように、常に対称的な出現の間で行われるということです。 対称性からの逸脱は、相互作用構造を改善することなく、総スパンを減らすだけです。交差が長くなると、ペナルティが増大するだけで、それを補う利点は得られないからです。 

間隔が固定されると、残りの問題は間隔にわたる順序付けの問題になります。 最適な戦略は、正しいエンドポイントの昇順で間隔を処理することです。 これにより、間隔が処理されるときに、効率的にカウントできる制御された方法で、以前のすべての間隔が完全に左側に配置されるか、部分的に重複することが保証されます。 ペナルティは、間隔エンドポイントの位置にわたるフェンウィック ツリーを使用して追跡できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 直接シミュレーション | O(N²) | O(N) | 遅すぎる |
 | インターバル短縮 + スイープ + フェンウィック | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クラスごとに、配列内で出現するすべてのインデックスを収集します。 左から右にスキャンするため、これらのインデックスは自然にソートされます。 
2. 最初の出現と最後、2 番目の出現と最後から 2 番目の出現などを照合することにより、各クラス内の出現をペアにします。 これにより、クラスごとに素の間隔のセットが生成されます。 その動機は、極値のペアリングにより固定されたエンドポイントのセット内の距離が最大化されるため、総塩基寄与を減らすことなく、あらゆる最適解をこの構造に変換できることです。 
3. 各ペアを間隔として扱います$(l, r)$、 どこ$l$そして$r$は配列内の元の位置です。 
4. 右端点を増加させてすべての間隔を並べ替えます。 この順序は、間隔を処理するときに、以前のすべての間隔が現在の間隔より早く終了するように選択されます。 
5. この順序で間隔をスイープします。 位置全体にわたってフェンウィック ツリーを維持し、処理された間隔の左端点を挿入します。 
6. 現在の間隔について$(l, r)$、以前に処理された間隔のうち、エンドポイントが厳密に内側に残された間隔の数を計算します。$(l, r)$。 このような各間隔は、正確に 1 単位の干渉に寄与し、最終スコアを固定量だけ減少させます。 
7. 基本寄与を追加する$r - l$答えを計算し、Fenwick クエリから取得した干渉カウントを 2 倍引きます。 
8.挿入$l$フェンウィックの木に入り、さらに進みます。 

### なぜ効果があるのか

 エンドポイントを修正した後、各クラスは独立したペアを提供するため、異なるクラス間の唯一の結合は、方向性を持って重複する間隔間の相互作用として現れる圧縮効果から生じます。 対称的なペアリングは、クラスごとの最大の塩基寄与を保証し、代替ペアリングは、有益な方法で相互作用数を減らすことなく、少なくとも 1 つの間隔を短縮するだけです。 

右端点を増加させることによるスイープにより、間隔を処理するときに、以前にアクティブだったすべての間隔が完全に決定され、その左端点が、ペナルティを生成する方向に現在の間隔と何回交差するかを計算するために必要なセットを正確に形成することが保証されます。 フェンウィック ツリーはこのセットを効率的に維持し、すべてのインタラクションが正しい符号で正確に 1 回カウントされるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v=1):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i, v in enumerate(a, 1):
        pos[v].append(i)

    intervals = []

    for v in range(1, n + 1):
        lst = pos[v]
        l, r = 0, len(lst) - 1
        while l < r:
            intervals.append((lst[l], lst[r]))
            l += 1
            r -= 1

    intervals.sort(key=lambda x: x[1])

    fw = Fenwick(n)
    ans = 0

    for l, r in intervals:
        inside = fw.range_sum(l + 1, r - 1)
        ans += (r - l) - 2 * inside
        fw.add(l, 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、まず位置を値でグループ化し、次にクラスごとに対称ペアを構築します。 これらは間隔になります。 適切なエンドポイントで並べ替えることで、一貫した処理順序が保証されます。 フェンウィック ツリーには、すでに処理された間隔の左端点が保存され、新しい間隔ごとに、その中に厳密に含まれる間隔の数がカウントされます。 このような各交差は、現在のペアの実効寄与を正確に 2 だけ減らす以前の除去に対応します。 

よくある間違いは、インデックスの動的なシフトをシミュレートしようとすることです。 このソリューションは、すべての相互作用を元の座標に関して固定し、全体を通して安定したままにすることで、この問題を完全に回避します。 

## 実用的な例

 簡単な例を考えてみましょう。`1 2 1 2`クラス 1 は間隔 (1, 3) を生成し、クラス 2 は間隔 (2, 4) を生成します。 右のエンドポイントでソートした後、(1, 3)、次に (2, 4) を処理します。 

| ステップ | 間隔 | フェンウィックアクティブ | インサイドカウント | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (1, 3) | {} | 0 | 2 |
 | 2 | (2, 4) | {1} | 1 | (2) - 2 = 0 |

 合計は 2 です。 

これは、左側の 1 つの端点がその内側にあり、構造的干渉を表すため、重複によって 2 番目の間隔の寄与が直接減少することを示しています。 

ここで次のことを考えてみましょう。`1 1 2 2 3 3`間隔は (1,2)、(3,4)、(5,6) です。 重複がまったくないため、すべての寄与は単純に距離 1 + 1 + 1 = 3 となり、Fenwick クエリは常に 0 を返します。 これは、重複しない構造が可能な限り最大のスコアを達成することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、クラスのすべての出現がすでに連続している場合です。 例えば、`1 1 1 1`。 このペアにより、間隔 (1,4) と (2,3) が生成されます。 フェンウィック ツリーは最初は空であるため、両方の寄与は純粋にその長さになります。 他のクラスが干渉しないため、順序は重要ではなく、合計は最大になります。 

別のケースは、次のような完全に交互のシーケンスです。`1 2 1 2 1 2`。 ここでは、すべての間隔が他の間隔と大きく重なります。 このアルゴリズムは、Fenwick 構造を通じて各オーバーラップを正確にカウントし、現在の間隔内で以前に挿入された左エンドポイントがすべて 1 回だけ考慮され、以前の削除によって引き起こされた圧縮ペナルティと一致することを保証します。
