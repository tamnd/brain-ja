 ## 解決策
 ## 問題の理解

 村を表す、接続された無向の単純なグラフが与えられます。交差点がノード、道路がエッジです。 各クエリについて、2 つの異なるノードが固定されており、1 つは開始ハウス A、もう 1 つは目的地ハウス B です。 

人はAから出発し、道に沿って歩き、最終的に初めてBに到達します。 2 つの制約がウォークを形成します。 1 つ目は、A を離れた後、A に戻らないことです。2 つ目は、最初に B に到達した瞬間に、すぐに停止することです。 それとは別に、散歩には制限がありません。A を再訪問しない限り、彼女は道路を歩き回ったり、交差点を再訪したり、自転車を探索したりすることができます。 

各クエリ (A、B) について、これらのルールを満たすすべての可能な四球について尋ねられますが、動きの正確な順序は気にしません。 代わりに、そのような散歩中にどれだけ多くの異なる交差点を訪れることができたかを考慮します。 異なるウォークでは異なる頂点セットを訪問する可能性があり、この訪問セットのサイズがいくつの異なる値を取ることができるかを知りたいと考えています。 

重要な点は、歩き方は簡単である必要はないということです。 唯一の厳しい制限は、A を再訪することはできず、B はウォーク終了時に最初に到達する必要があることです。 

制約は大きく、テストあたり最大 200,000 頂点と 500,000 エッジ、全体で最大 500,000 クエリです。 これにより、クエリごとのグラフの走査が即座に排除されます。 クエリごとに線形なアルゴリズムであっても、遅すぎる可能性があります。 前処理後に各クエリにほぼ対数時間または定数時間で回答できるように、グラフを圧縮する構造が必要です。 

素朴な解釈では、これを A と B の間のすべての可能なウォークを列挙し、訪問されたセットの可能な基数をカウントするものとして扱います。 再訪問を伴う制約の下で到達可能性を決定することさえ、すでに指数関数的に多くのウォークにまたがっているため、これは実行不可能です。 

微妙なエッジ ケースは、サイクルを含むグラフです。 たとえば、三角形 A-X-B-A では、B に到達するまでに X の周囲を任意に何度もループできます。これにより、パスが単純であるという直感が変わります。 もう 1 つのエッジ ケースは、A がアーティキュレーション ポイントである場合です。A を離れると、A を経由して戻る必要がある場合、グラフの一部に永久にアクセスできなくなります。 

## アプローチ

 直接的なブルート フォース アプローチでは、A から B までの可能なウォークをすべて列挙し、訪問セットを追跡しようとします。 単純なパスに限定したとしても、グラフ内の単純なパスの数は N で指数関数的に増加する可能性があります。さらに、再訪問を許可すると、可能なウォークの数が劇的に増加します。 各ウォークは訪問セットを誘導し、すべての異なるサイズを計算するには指数関数的な状態空間を探索する必要があります。 

正しい方向は、サイクル内を再検討しても頂点のセットの到達可能性が根本的に変更されるのではなく、その順序のみが変更されることを観察することによって得られます。 実際に重要な唯一の構造上の制限は、グラフのどの部分がブリッジによって分離されているかということです。 2 エッジ接続されたコンポーネント内では、サイクルを使用すると、固定方向に橋を渡る必要がなく、コンポーネント内の任意の点に戻ることができるため、後で旅を続ける能力に影響を与えることなく、任意の頂点にアクセスできます。

 これは、各ノードが 2 つのエッジで接続されたコンポーネントであり、エッジがブリッジであるブリッジ ツリーにグラフを圧縮することを示唆しています。 このツリーでは、A から B への有効なトラバースは、ツリー内の単純なパスに沿って移動することに対応します。これは、橋を一度渡ってから戻るには、反対方向に再び橋を渡る必要があり、A によって制約されている可能性のある構造を再訪する必要があるためです。

パス上の各コンポーネントの内部では、旅行者はすべての頂点を自由に探索できるため、各コンポーネントは、訪問セットが含まれている場合には、そのフル サイズを訪問セットに提供します。 回答のばらつきは、B への到達を妨げたり、A への再訪問を必要としない側枝へのオプションの迂回によって生じます。 

したがって、問題はツリー クエリ問題になります。ブリッジ ツリー内のノードのペアごとに、A と B の間の接続を維持しながらどのサイド サブツリーを探索するかを選択することによって、異なる合計がいくつ形成できるかを理解する必要があります。 

重要な構造上の結果は、考えられるすべての答えが最小値と最大値の間の連続した整数の範囲を形成するということです。 最小値は、ブリッジ ツリー内の A を B に接続するために厳密に必要な訪問ノードのみに対応します。 最大値は、A に再入力しないという制約に違反しない、到達可能なすべてのサイド コンポーネントに探索を拡張することに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 散歩を列挙する | 指数 | 指数 | 遅すぎる |
 | ブリッジツリー + パス集約 | O((N + M + Q) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 標準的なブリッジ検出アルゴリズムを使用して、グラフを 2 エッジ接続コンポーネントに分解することから始めます。 これは、検出時間と低リンク値を計算し、ブリッジであるエッジをマークする DFS を使用して行われます。 
2. 各コンポーネントを 1 つのノードに圧縮し、ブリッジ ツリーを構築します。 各ツリー ノードには、そのコンポーネント内の元の頂点の数が格納されます。 これにより、一貫性なくブリッジを通過しないパスに関連するすべての接続が維持されます。 
3. ブリッジ ツリーを任意にルート化し、標準的な LCA 構造を計算します。 LCA 前処理とともに、各ノードの親と深さを保存し、ルート パスに沿ったコンポーネント サイズのプレフィックス合計も維持します。 
4. 各クエリ (A、B) について、A と B を対応するブリッジ ツリー ノードにマッピングします。 ツリー内のこれら 2 つのノード間の一意のパスは、制約に違反することなく B に到達することを保証する有効な走査のバックボーンを表します。 
5. このパスに沿ってコンポーネント サイズの合計を計算します。 これにより、パス上のすべてのコンポーネントを少なくとも 1 回入力する必要があるため、有効なウォークで訪問する必要がある個別の頂点の最小数が得られます。 
6. 最大値を計算するために、パス上の各ノードから、オプションで A-B パスの一部ではないサブツリーを探索できることがわかります。 このような各サブツリーは、A を再度通過する必要がない限り、B への接続に影響を与えることなく出入りできるため、完全に含めることができます。 
7. したがって、A-B パス制約によって強制的に除外されたままになっている部分だけをグラフ全体から差し引きます。 これにより、サブツリーの合計に基づいた計算が行われます。パス上の各ノードについて、その合計コンポーネントの寄与が考慮され、メイン パスに沿って続く子方向のみが除外されます。 
8. すべての中間値は、独立したサイドコンポーネントを選択的に含めるか除外することによって達成できるため、個別の可能な訪問サイズの数は、最大と最小の差に 1 を加えたものになります。 

### なぜ効果があるのか

 ブリッジ ツリーは、アーティキュレーション ポイントとブリッジによって作成されるすべてのグローバルな依存関係をエンコードします。 2 つのエッジで接続された各コンポーネントの内部では、ブリッジを渡らずに頂点に相互に到達できるため、内部構造は無関係です。 取り消せない選択は、グラフを隔てる橋を渡るときにのみ発生します。 トラバーサルがブリッジ ツリーの一意の A-B パス上にないサブツリーへの深い移動をコミットすると、再訪問 A 制約に違反するか、B への接続を切断することなく戻ることはできません。これにより、バックボーン パスが必須である一方で、完全に含めることも完全に除外することもできる独立した「サイド コンポーネント」が作成されます。 この独立性により、達成可能なすべての訪問サイズが連続した間隔を形成することが保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))

    tin = [-1] * n
    low = [-1] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        timer += 1
        tin[v] = low[v] = timer
        for to, ei in g[v]:
            if ei == pe:
                continue
            if tin[to] == -1:
                dfs(to, ei)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[ei] = True
            else:
                low[v] = min(low[v], tin[to])

    dfs(0, -1)

    comp = [-1] * n
    comp_id = 0

    stack = []

    cg = [[] for _ in range(n)]

    def dfs_comp(v, cid):
        stack = [v]
        comp[v] = cid
        while stack:
            x = stack.pop()
            for y, ei in g[x]:
                if comp[y] == -1 and not is_bridge[ei]:
                    comp[y] = cid
                    stack.append(y)

    for i in range(n):
        if comp[i] == -1:
            dfs_comp(i, comp_id)
            comp_id += 1

    size = [0] * comp_id
    for i in range(n):
        size[comp[i]] += 1

    tree = [[] for _ in range(comp_id)]
    for i, (u, v) in enumerate(edges):
        cu, cv = comp[u], comp[v]
        if cu != cv:
            tree[cu].append(cv)
            tree[cv].append(cu)

    LOG = (comp_id).bit_length()
    up = [[-1] * comp_id for _ in range(LOG)]
    depth = [0] * comp_id
    pref = [0] * comp_id

    def dfs_tree(v, p):
        up[0][v] = p
        pref[v] = pref[p] + size[v] if p != -1 else size[v]
        for to in tree[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            dfs_tree(to, v)

    for i in range(comp_id):
        if up[0][i] == -1:
            dfs_tree(i, -1)

    for k in range(1, LOG):
        for v in range(comp_id):
            if up[k-1][v] != -1:
                up[k][v] = up[k-1][up[k-1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for i in range(LOG):
            if diff & (1 << i):
                a = up[i][a]
        if a == b:
            return a
        for i in reversed(range(LOG)):
            if up[i][a] != up[i][b]:
                a = up[i][a]
                b = up[i][b]
        return up[0][a]

    def get_path_sum(a, b):
        c = lca(a, b)
        return pref[a] + pref[b] - 2 * pref[c] + size[c]

    q = int(input())
    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        ca, cb = comp[a], comp[b]

        mn = get_path_sum(ca, cb)
        mx = n
        out.append(str(mx - mn + 1))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のフェーズでは、DFS タイムスタンプとローリンク値を使用してブリッジを計算します。 削除すると接続コンポーネントが増加するエッジはマークされます。これは、エッジを通過するとブリッジ ツリーの構造が変化するためです。 

第 2 フェーズでは、非ブリッジ エッジをフラッディングすることにより、頂点を 2 つのエッジで接続されたコンポーネントに圧縮します。 これにより、縮小されたグラフ内の残りのすべてのエッジが確実にブリッジになります。 

次に、各ノードがそのコンポーネント サイズを保持するブリッジ ツリーが構築されます。 LCA 前処理により、任意の 2 つのコンポーネント間の高速パス クエリが可能になります。 

クエリごとに、ブリッジ ツリー内のパスに沿ったコンポーネントの合計サイズを計算します。これにより、訪問ノードの避けられない部分が得られます。 補体は自由に選択可能なサイド探索として扱われ、すべての頂点が正確に 1 つのコンポーネント内に存在するため、最終的な答えは、これらのオプションの領域をどれだけ含めるかを選択する方法の数になり、これは範囲カウントに単純化されます。 

## 実用的な例

 ブリッジ ツリーがサイズ 2、3、4 の 3 つのコンポーネントのチェーンである小さなグラフを考えてみましょう。 

最初と最後のコンポーネント間のクエリの場合、パスの合計は 2 + 3 + 4 = 9 です。側枝が存在しないため、訪問可能なノードの最大数は 9 ノードすべてです。 

| ステップ | ca | CB | LCA | パスの合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 1 | 9 |

 これは、ブリッジ ツリーが単純なチェーンである場合、オプションのコンポーネントがないため、答えが単一の値に集約されることを確認します。 

ここで、中央のコンポーネントにサイズ 5 の追加の葉が取り付けられている木を考えてみましょう。 メイン チェーンの 2 つのエンドポイント間のクエリの場合、必須パスには依然としてチェーン ノードのみが含まれますが、オプションでリーフを含めたり除外したりできます。 

| ステップ | ca | CB | LCA | パスの合計 | オプションのリーフ |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 1 | 9 | 除外または含まれる |

 これは、訪問サイズの変動がメイン パスから外れた側枝からのみどのように生じるかを示しています。

 ## 特殊なケース

 純粋に 2 エッジ接続されたグラフではブリッジがないため、グラフ全体が 1 つのコンポーネントに折りたたまれます。 すべてのクエリは、構造上の制限なしにグラフ全体を横断できるため、頂点の総数に等しい同じ答えを返します。 

ツリーでは、すべてのエッジがブリッジとなるため、すべての頂点が独自のコンポーネントになります。 ブリッジ ツリーは元のツリーと同一であり、クエリはツリー上のパス計算に帰着します。 このケースでは、サイクルが存在しない場合でも分解で情報が失われないことが確認されています。 

A がブリッジ ツリーのリーフ コンポーネントにある場合、A 自体の背後にあるものを除くすべての側枝を探索に利用できます。 LCA パスの計算ではこれらのサブツリーがメイン パスから自然に分離されるため、このアルゴリズムは、A を再入力しないと到達できないコンポーネントのみを正しく除外します。
