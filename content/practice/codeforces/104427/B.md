 ## 解決策
 ## 問題の理解

 私たちは弁護士間に指示された関係を与えられています。 それぞれの関係は、ある弁護士が別の弁護士を信頼していることを示しており、この信頼には非常に具体的な運用上の意味があります。つまり、弁護士 B が弁護士 A を信頼する場合、A は B の弁護を行います。 

したがって、入力は、エッジ A → B が A が B を弁護することを意味する有向グラフを定義します。弁護士は他の多くの弁護士を弁護することができ、少なくとも 1 人の他の弁護士が弁護した場合、その弁護士は無罪と見なされます。これは、この有向グラフに少なくとも 1 つの入力エッジがあることを意味します。 

有効性の構造を変更するグローバル例外が 1 つあります。 2 人の弁護士が同時にお互いを弁護する場合、つまり、弁護士間に長さ 2 の指示されたサイクルがある場合、それらの弁護士は、他の弁護が受けられるかどうかに関係なく、自動的に有罪と宣告されます。 

課題は、すべての信頼関係が固定されており変更できないことを前提として、これらの規則に基づいてすべての弁護士が無罪になることが可能かどうかを判断することです。 

制約は最大 20 万人の弁護士と 20 万人の関係者に及びます。 これは、どのような解もグラフのサイズが線形または線形に近いものでなければならないことを直ちに意味します。 O(NM) または O(N^2) スタイルのアプローチは実現可能な限界をはるかに超えていますが、O(N + M) または O(M log N) のアプローチは許容されます。 

ここでの単純な間違いは、「少なくとも 1 つの受信防御」条件のみに焦点を当て、相互防御ルールを無視することです。 たとえば、1 ↔ 2 および 3 ↔ 4 のようなグラフでは、すべてのノードに少なくとも 1 つの入力エッジがありますが、相互防御のため両方のペアが無効であるため、答えは NO になります。 

もう 1 つの微妙な失敗ケースは、ノードに入力エッジがまったくない場合です。 たとえグラフが密集していても、そのようなノードが 1 つあると、普遍的な無罪は不可能になります。 

## アプローチ

 直接的な強引な解釈では、各弁護士の状態を個別にシミュレートすることになります。 すべてのノードについて、すべての入力エッジをスキャンして、少なくとも 1 つが存在することを確認します。 その後、ノードのすべてのペアをスキャンして相互防御ペアが存在するかどうかを検出し、それらのノードを無効にします。 

これは定義に正確に従っているため、概念的に機能します。 ただし、相互関係についてすべてのペアをスキャンするコストは、最悪の場合、二次関数になります。 最大 200,000 ノードの場合、ペアワイズ チェックでは最大 4 × 10^10 の比較が必要になりますが、これは現実的ではありません。 

重要な観察は、両方の条件がエッジに対してローカルであるということです。 ノードに入力エッジがあるかどうかは、単純な度数カウンターによって追跡できます。 相互防御が存在するかどうかは、ハッシュ セットまたは隣接セット内の有向エッジをマークし、逆エッジが既に存在するかどうかを確認することによって、入力処理中にチェックできます。 

これにより、問題はすべてのペアにわたるグローバルな推論からエッジごとの定数時間チェックに軽減されます。

 | ブルートフォース | O(N² + M) | O(N + M) | 遅すぎる |
 | 最適 | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 各信頼関係が有向エッジとなる有向グラフとして状況をモデル化します。 

### ステップ

 1. すべてのエッジを読み取り、有向グラフの表現を構築します。 

各エッジ A → B は、A が B を防御することを示します。 
2. 配列を維持する`indegree`どこ`indegree[v]`弁護士対弁護士を弁護する弁護士が何人いるかを数えます。 

エッジ A → B を読み取るたびにインクリメントします`indegree[B]`。 

これは、各弁護士が少なくとも 1 回の弁護を受けているかどうかを直接把握します。 
3. 同時に、すべての有向エッジをセットに保存します。 

これにより、逆エッジが存在するかどうかを一定時間チェックすることができます。 
4. 各エッジ A → B について、逆エッジ B → A が存在するかどうかを確認します。 

存在する場合、相互防御ペアが存在することがすぐにわかり、構成が無効になります。 
5. すべてのエッジを処理した後、すべての弁護士の次数が少なくとも 1 であることを確認します。 

弁護士が次数 0 を持っている場合、無罪になることはできません。 
6. 両方の条件が満たされる場合、YES を出力します。 それ以外の場合は、NO を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、問題ルールによって暗示される両方の必要な条件を直接エンコードします。 一次条件により、すべての弁護士が少なくとも 1 回の弁護を受けることが保証されます。 相互エッジ チェックでは、相互防御のペアが両方の参加者を自動的に無効にするというルールが適用されます。 

どちらの条件もローカル エッジ情報にのみ依存し、すべてのエッジが 1 回だけチェックされるため、隠れたグローバルな依存関係はありません。 有効な構成はこれらの条件を満たす必要があり、これらの条件に違反する場合は、問題ステートメントのルール違反に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    indeg = [0] * (n + 1)
    edges = set()
    
    bad = False
    
    for _ in range(m):
        a, b = map(int, input().split())
        # a defends b => a -> b
        indeg[b] += 1
        edges.add((a, b))
    
    # check mutual defense
    for a, b in edges:
        if (b, a) in edges:
            bad = True
            break
    
    if bad:
        print("NO")
        return
    
    for i in range(1, n + 1):
        if indeg[i] == 0:
            print("NO")
            return
    
    print("YES")

if __name__ == "__main__":
    solve()
```このソリューションでは、2 つの制約が明確に分離されます。 度数配列は入力ループ内で更新されるため、その部分に隣接リストを 2 回渡す必要はありません。 エッジ セットは純粋に相互ペアを検出するために使用されます。 セットを使用すると、平均検索時間が O(1) になります。 

実装の微妙な詳細は、相互エッジが挿入中ではなくすべての入力を読み取った後にチェックされることです。 どちらのアプローチでも機能しますが、後処理によりロジックが単純になり、入力の後半で両方向が現れるケースの欠落を回避できます。

 ## 特殊なケース

 最小のエッジ ケースは、N = 1 および M = 0 の場合です。単一の弁護士は弁護を受けられないため、アルゴリズムは、次数が 0 であるため、正しく NO を出力します。 

1 → 2 のような 2 ノードのシングルエッジの場合、ノード 2 が適切に防御されている場合でも、ノード 1 の次数は 0 になります。 indegree スキャンはこれを即座に検出し、NO を生成します。 

1 ↔ 2 のような対称ペアでは、両方のノードに少なくとも 1 つの次数があるため、単純な解では誤って YES が返される可能性があります。 相互エッジ検出はこれを捕捉し、構成を正しく拒否します。 

エッジが長いチェーンを形成する疎なグラフでは、正確さは完全に次数 0 を持つチェーン内の最初のノードを検出することに依存します。 入次数累積はすぐ隣を越える構造から独立しているため、アルゴリズムはこれを自然に処理します。
