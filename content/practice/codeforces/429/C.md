 ## 解決策
 ## 問題の理解

 この問題では、各ノードのサブツリーのサイズに制約を与えて、ルート付きツリーを再構築するように求められます。 配列が与えられます`c`長さの`n`、 どこ`c[i]`ノードをルートとするサブツリー内のノードの総数を表します`i`。 子を持つ各ノードには少なくとも 2 つの子が必要です。 タスクは、これらの特性を満たすツリーが存在するかどうかを判断することです。 

入力サイズが小さいので、`n ≤ 24`、したがって指数関数的に拡張するアルゴリズム`n`実現可能です。 それぞれ`c[i]`せいぜい`n`, したがって、有効範囲外の値はありません。 厄介な部分は、次の値が`c`は任意の順序で現れる可能性があるため、最後の要素がルートであると仮定したり、値がツリーに沿って単調に増加すると仮定したりすることはできません。 

単純なアプローチでは、考えられるすべてのツリーを試して、そのサブツリーのサイズをチェックする可能性があります。 のために`n = 24`、根を張った木の数が超指数関数的に増加するため、これは実行不可能です。 ノードが 1 つしかない場合、別の微妙なエッジ ケースが発生します。 もし`n = 1`そして`c = [1]`の場合、単一のノードはサイズ 1 のサブツリーとしてカウントされるため、解決策は自明に「YES」になります。 もう一つの落とし穴は、`c[i] = n`複数のノードの場合。 ツリー全体のサイズでは、ツリーに 2 つのルートを持つことはできません。 

さらに、すべての場合、`c[i] = 1`、唯一の有効な構成はリーフ ノードのフォレストですが、これは不可能です。`n > 1`内部ノードには少なくとも 2 つの子が必要なためです。 たとえば、入力`[1,1,1]`「いいえ」を返す必要があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのルートツリーが生成され、それぞれがサブツリーのサイズと照合されます。 のために`n`ノードの数に応じて、ルートを持つ可能性のあるツリーの数は指数関数的に増加します。`n`。 各ツリーのサブツリー サイズを確認するには、`O(n^2)`、したがって、`n = 15`、このアプローチは実行不可能になります。 この強引な方法の正しさは、すべての構造を徹底的に検証することで得られますが、遅すぎます。 

重要な洞察は、問題が組み合わせ分割問題に帰着できるということです。 ノードをサブツリー サイズで降順に並べ替える場合、最大値がルートに対応する必要があります。 次に、各内部ノードには、そのサブツリー サイズに 1 を加えた合計が親のサブツリー サイズと等しくなるように子を割り当てる必要があります。 これは再帰的サブセット合計問題に似ています。 なぜなら`n ≤ 24`、ビットマスク動的プログラミングを使用して、残りのノードの考えられるすべてのグループ化を効率的に探索できます。 ビットマスクは、どのノードがまだ割り当てられていないかを表します。 現在のノードの有効な子のセットを再帰的に形成しようとし、作業の繰り返しを避けるために結果をメモ化します。 これにより、検索スペースが大幅に減少します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(木数 × n^2) | O(n) | 遅すぎる |
 | ビットマスク DP / 再帰的構築 | O(2^n × n^2) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートする`c`降順で。 最大の要素はルートでなければなりません。そうでない場合は、すべてのサブツリー サイズを満たすツリーは存在しません。 
2. 再帰関数を使用する`can_build(mask)`どこ`mask`はツリーにまだ配置されていないノードを表します。 もし`mask`がゼロの場合、すべてのノードが正常に割り当てられました。 
3. 現在のノードの場合`u`、残りのノードのサブセットを子として割り当てようとします。 有効なサブセット`S`満足する`sum(c[i] for i in S) + 1 = c[u]`。 次の場合、各内部ノードには少なくとも 2 つの子が必要です。`c[u] > 1`。 
4. 有効なサブセットごとに`S`、残りのノードのツリーの構築を再帰的に試みます。`mask - S`。 いずれかの分岐が成功した場合は true を返します。 
5. メモ化を使用してそれぞれの結果を保存します`mask`というのは、残りのノードの同じセットが複数回出現する可能性があるためです。 
6. 現在のノードとマスクに有効な割り当てが存在しない場合は、false を返します。 

機能する理由: このアルゴリズムは、現在のマスク内のすべてのノードが割り当てられていないという不変条件を維持します。 各再帰により、サブツリーのサイズ制約が正確に満たされることが保証されます。 ノードをソートすると、最大のサブツリー サイズが常に最初に割り当てられ、ルートが有効であることが保証されます。 メモ化により、同じ構成の再チェックが回避されます。 アルゴリズムが true を返した場合、指定されたルールを満たすすべてのノードに有効な割り当てが存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from functools import lru_cache

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    c.sort(reverse=True)

    @lru_cache(None)
    def can_build(mask):
        if mask == 0:
            return True
        # pick the first node in mask
        u = mask.bit_length() - 1
        size_needed = c[u]
        # if it's a leaf
        if size_needed == 1:
            return can_build(mask ^ (1 << u))
        # try all subsets of remaining nodes to be children
        submask = mask ^ (1 << u)
        subset = submask
        while subset:
            total = sum(c[i] for i in range(n) if (subset >> i) & 1)
            if total + 1 == size_needed:
                if bin(subset).count("1") >= 2 and can_build(submask ^ subset):
                    return True
            subset = (subset - 1) & submask
        return False

    full_mask = (1 << n) - 1
    if can_build(full_mask):
        print("YES")
    else:
        print("NO")

solve()
```コードは、ルートが最初に処理されることを保証するためにノードをソートすることから始まります。 再帰関数はビットマスクを使用して残りのノードを追跡します。 サブセット生成では、考えられるすべての子の組み合わせを効率的にチェックします。`(subset - 1) & submask`トリック。 リーフノード (`c[i] = 1`）は自動的に処理されます。 メモ化により、指数関数的な作業が繰り返されることがなくなります。

 ## 特殊なケース

 単一ノード入力の場合`1\n1\n`、マスクは次のように始まります`1`。 ルート ノードのサイズは 1 で、再帰によりそれが削除され、マスクは次のようになります。`0`。 アルゴリズムは正しく YES を返します。 

入力用`[1,1,1,1]`、 マスク`1111`、最大のノードのサイズは 1 です。各ノードはリーフですが、子を持つにはルートのサイズが 1 以上である必要があります。 残りのノードのサブセットは、内部ノードの 2 つ以上の子という子要件を満たしていません。 アルゴリズムはすべてのサブセットを調査し、NO を返します。 これにより、オールリーフ シナリオの処理が確認されます。
