 ## 解決策
 ## 問題の理解

 数直線上のセグメントの集合が与えられます。 各セグメントは左の端点から右の端点まで広がっており、各セグメントに 2 つの色のいずれかを割り当てる必要があります。 

カラーリングを選択したら、線上の任意の点を選択し、その点をカバーするすべてのセグメントを見ることを想像してください。 これらのアクティブなセグメントの中には、赤色のセグメントと青色のセグメントがあります。 要件は、すべての点で、それをカバーする赤と青のセグメントの数の差が絶対値で 1 を超えてはいけないことです。 

この条件は、実際の座標ごとに当てはまらなければならないという意味でローカルですが、セグメント自体はエンドポイントでのアクティブ セットのみを変更します。 したがって、問題の実際の構造は、間隔がどのように重なり合うか、そして重なり部分に一貫して色を割り当てる方法に関係します。 

入力サイズは 10 万セグメントに達するため、セグメントのすべてのペアを比較したり、ポイントごとのオーバーラップ情報を再計算したりするアプローチは、直ちに遅すぎます。 セグメント数が 2 次の場合は、10¹⁰ 回の演算が必要となり、制限時間内に合格しません。 すべてのセグメントにわたって動的構造を維持する必要があるため、O(n log n) であっても、各操作が軽量である場合にのみ許容されます。 

微妙なエッジケースは、密集した重なりから生じます。 多くのセグメントが大きな共通の交差点を共有している場合、それらすべてがある時点で同時にアクティブになります。 このような領域では、アクティブな色のマルチセットが常にバランスを保たなければならないため、色の制約が最も強くなります。 

例として、セグメント [0, 10]、[1, 9]、[2, 8] があり、すべて重なり合っている場合、グローバルな重なり構造を追跡せずに端点だけを調べる単純な貪欲により、5 つの赤と 1 つの青が重なり合う瞬間が簡単に生成され、以前の決定が局所的に問題がないように見えた場合でも、制約に違反する可能性があります。 

もう 1 つの特殊なケースは、間隔が厳密に含まれる [0, 10]、[1, 9]、[2, 8]、... などのネストです。 ここで、オーバーラップ セットは徐々に変化しますが、長時間にわたって大きなままであり、ペアごとの相互作用のみが重要であると仮定するアルゴリズムにストレスを与えます。 

## アプローチ

 この問題を考える直接的な方法は、考えられるすべての色の割り当てを試してみることです。 可能性は 2ⁿ あり、割り当てごとに数直線をスキャンし、アクティブなセグメントを追跡し、すべての重要な点でのバランス状態を確認します。 各チェックにはエンドポイントの並べ替えや行のスイープが必要で、コストは O(n log n) となるため、完全な総当たり攻撃は O(2ⁿ · n log n) となり、これは実現可能性をはるかに超えています。 

色分けを修正したとしても、有効性のチェックだけならスイープ ラインで管理できます。すべてのセグメントのエンドポイントを並べ替え、セグメントの出入りをシミュレートし、現在の赤と青の数を維持します。 失敗点は検証ではなく、割り当ての検索にあります。 

重要な構造的観察は、制約は常にアクティブなセグメントのセットのみに関するものであるということです。 任意の固定 x で、x を含むすべてのセグメントが区間オーバーラップ グラフ内でクリークを形成します。 要件では、そのようなすべてのクリーク内で色の違いが 1 以内に収まらなければならないと規定されています。 これは、グラフの任意の色付けを扱っているのではなく、区間が終点を通る全体的な順序を課す構造を扱っていることを示唆しています。 

これを利用する便利な方法は、現在アクティブなすべてのセグメントを右エンドポイントの順に維持しながら、左エンドポイントの昇順でセグメントを処理することです。 この順序は任意ではありません。同時にアクティブな間隔の間で、右のエンドポイントでソートすると、左から右にスイープするにつれてスムーズに展開する一貫した構造が得られます。

重要なアイデアは、この順序付けられたアクティブ セットで交互の色を維持することです。 新しい間隔が入ると、その右端に従って構造内に配置し、この順序で隣接する間隔に基づいて色を割り当てます。 このソートされた構造では、間隔グラフの重なりが連続したブロックのように動作するため、全体的なバランス状態を確保するには、交互を局所的に保存するだけで十分です。

 | スイープ + 順序付きアクティブ セット | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを左の端点で並べ替えます。 アクティブになる順に処理するため、セグメントが他のセグメントと重なり始める瞬間を見逃すことはありません。 
2. 現在アクティブなセグメントのバランスのとれた順序構造を維持し、適切なエンドポイントでソートします。 この構造は、現在のスイープ位置での「ライブ」間隔を表します。 
3. 左端の昇順でセグメントをスイープします。 セグメントがアクティブになったら、そのセグメントをその右端の位置で順序付けられた構造に挿入します。 
4. 挿入したら、順序付けられた構造内の先行するものに基づいて色を割り当てます。 順序の直前にセグメントがある場合は、反対の色を割り当てます。 先行する色がない場合は、任意の色 (たとえば赤) を割り当てます。 
5. 順序付けられた構造は、色が交互になる一連の間隔を暗黙的に形成します。 新しい間隔はそれぞれその直近の間隔にのみ依存するため、挿入ルールはこの変更をローカルに保存します。 
6. すべての挿入が完了すると、カラーリングが完全に決まります。 

### なぜ効果があるのか

 不変なのは、どの瞬間でも、右のエンドポイントでソートされたアクティブなセグメントを見ると、その順序に沿って色が交互になるということです。 任意の点 x は、この順序付けで連続ブロックを形成するアクティブな間隔のセット内にあります。これは、x をカバーする間隔の中で、間隔の順序付けプロパティに違反することなく別の間隔を「スキップ」できるものがないためです。 交互シーケンスの連続ブロック内では、2 色のカウントの差は最大 1 です。 これは、すべての x について、必要なバランス条件が成立することを直接意味します。 

正しい終点による順序付けにより、挿入時に構造が安定します。 新しい間隔は、その順序でそのすぐ隣にのみ影響するため、グローバルな再計算を行わずに変更を維持できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i))
    
    segs.sort(key=lambda x: x[0])

    import bisect

    # active list sorted by r: store (r, id)
    active = []
    color = [-1] * n

    for l, r, i in segs:
        pos = bisect.bisect_left(active, (r, i))
        
        # predecessor determines color
        if pos == 0:
            c = 0
        else:
            prev_id = active[pos - 1][1]
            c = 1 - color[prev_id]
        
        color[i] = c
        active.insert(pos, (r, i))

    print(" ".join(map(str, color)))

if __name__ == "__main__":
    solve()
```このコードは、セグメントがアクティブになったときにのみ間隔を挿入できるように、最初にセグメントを左端で並べ替えます。 の`active`リストは常に正しいエンドポイントでソートされ、アルゴリズムで記述された順序構造をシミュレートします。 

新しい間隔ごとに、二分探索を使用してこの順序での位置を特定します。 色は、この順序のすぐ左側の間隔によって決まります。交互を維持するために色を反転します。 先行処理が存在しない場合、その間隔で新しい交互シーケンスが開始されます。 

重要な点は、以前のセグメントの色を決して再計算しないことです。 この構造では、後で挿入しても交互のシーケンスがローカルに拡張されるだけであるため、一度割り当てられた色は有効なままであることが保証されます。 

## 実用的な例

 | --- | --- | --- |
 | [0,2]を挿入 | [0,2] | 前任者なし、カラー 0 |

```これは、間隔が接触しているものの、深い重なりは生じていない単純なケースを示しています。 代替ルールは有効な割り当てを直接生成します。

2 6
3 7

 ## 特殊なケース

 最小の単一セグメントは、アクティブな構造内に先行セグメントがないため、デフォルトの色を割り当てることによって処理されます。 このアルゴリズムは新しい交互シーケンスを初期化するため、結果は自明に有効です。 

[0, 10]、[1, 9]、[2, 8] などのネストされた間隔の場合、各挿入は右エンドポイントによる順序で前の挿入の内側に配置されます。 新しいセグメントはそれぞれ、前のセグメントの反対の色を選択し、安定した交互のチェーンを生成します。 最も深い重なり部分では、構造が完全に交互になっているため、色の違いは最大でも 1 色です。 

[0,1]、[2,3]、[4,5] などの互いに素なセグメントの場合、すべての挿入で空の先行セグメントが参照されるため、すべてのセグメントが同じ色を受け取ります。 複数のセグメントでカバーされる点はないため、条件は直ちに成立します。 

右エンドポイントを厳密に増加させる場合、アクティブな順序付けは単純な成長チェーンになり、新しいセグメントごとに前のセグメントと比較して色が反転し、スイープのすべてのプレフィックスでバランスが維持されます。
