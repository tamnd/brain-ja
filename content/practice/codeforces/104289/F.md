 ## 解決策
 ## 問題の理解

 初期シーケンスとターゲット シーケンスが与えられますが、どちらも同じ複数セットの値の順列です。 非常に特殊な操作を繰り返し実行することができます。つまり、i < j で i の値が j の値よりも大きい 2 つの位置 i と j を選択し、次に j の値を取得して位置 i の直前に挿入します。 この 1 つの要素が配列の後半から抽出され、より大きな要素の直前に配置されることを除いて、他のすべての要素の相対的な順序は保持されます。 

タスクは、このような操作を任意の数だけ使用して、最初のシーケンスから 2 番目のシーケンスを取得できるかどうかを判断することです。 

制約は大きく、テスト ケース全体の合計 n は最大 3 × 10^5 であり、考えられるすべての操作または検索状態をモデル化しようとするシミュレーションは即座に除外されます。 操作に基づいて分岐したり、BFS のような構成の探索を試みたりするアプローチは、組み合わせ的に爆発的に発生します。 テスト ケースごとに 1 つの 2 次シミュレーションでも遅すぎます。 

この操作の微妙な点は、より大きな値を横切ってより小さな値を左に移動するだけで、より大きな値を右に移動することはないということです。 これは、反転の構造とその解決が中心であることをすでに示唆しています。 

いくつかのエッジの状況は誤解されやすいものです。 

配列がすでにソートされている場合、操作は必要ないため、すべての同一のターゲットを受け入れる必要があります。 

大きい要素を小さい要素を越えて移動する必要があるなど、ターゲットがソースよりも「より反転」している場合、操作では小さい要素の左方向への移動のみが許可されるため、それは疑わしいです。 

値が繰り返される場合、これは順列の問題であるという単純な仮定は崩れます。 厳密な不平等が必要なため、値が等しいと操作がブロックされます。 

## アプローチ

 ブルートフォース解釈では、すべての有効な操作がシミュレートされます。 任意の構成から、i < j と a_i > a_j のすべてのペアをスキャンし、移動を適用し、ターゲットに到達するか、新しい状態が表示されなくなるまで続行します。 各操作によって配列が変更され、最悪の場合、状態ごとに Θ(n^2) 個の有効な操作が存在し、全体としては指数関数的に多くの状態が存在する可能性があります。 これは、20 歳前後の n でもすぐに実行不可能になります。 

重要な観察は、視点を反転することです。 要素がどのように移動するかを考える代わりに、操作が最終的な順序にどのような制約を課すかを追跡します。 

この操作により、後の小さな要素を取得し、それを大きな要素の前に挿入することができます。 これは、小さな要素が大きな要素を横切って「左にバブリング」できることを意味しますが、それは制御された方法でのみであり、選択した操作で最初に交差する大きな要素の直前に常にジャンプします。 これは、多くの操作において、小さな要素が最終的な配置でその前に現れる大きな要素を横切って左に移動できるが、大きな要素が小さな要素を右に追い越すことはできないことを事実上意味します。 

これは貪欲な構築の視点につながります。 元の配列のどの要素がまだ利用可能であるかを維持しながら、左から右にターゲットを再構築しようとします。 値を配置したいときはいつでも、初期構成で元々その右側にあったすべての小さな要素を確実に前に持ってくることができるようにすることで、値を「公開」できなければなりません。 この制約は、これまでに確認された最大の「ブロッキング」値をスキャンして維持することによってチェックできる単調な実現可能性条件に帰着します。 

同様に、両方の配列を処理し、「単調なスタックのような制約の下での最後の出現」の相対的な順序が一貫しているかどうかを確認します。 違反はすべて、大きな要素を小さな要素の後ろに移動する必要がある状況に対応しますが、操作の方向性ではこれは不可能です。

 | モノトーンスキャンで貪欲な検証 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、ソース シーケンスとターゲット シーケンス間の制約チェックとして再解釈します。 

1. 各値の位置を初期配列に保存します。 これにより、元の位置に関して順序付け制約を直接比較できるようになります。 これが役立つ理由は、すべての操作で要素がより大きな要素に対して左に移動するだけであるため、元の位置順序が実現可能性を左右するからです。 
2. ターゲット配列を左から右にスキャンし、ターゲット内にすでに配置されている要素の元の最大位置を維持します。 これは、ターゲットの初期に配置することを約束した、元の配列の最も右の要素を表します。 
3. ターゲット内の各要素について、その元の位置とこの現在の最大値を比較します。 現在の要素がもともとこの最大値の左側にある場合、それは、より小さい要素の許可された左方向のプルのみを使用して解決できない方法で、ソース内で後から来た要素の後に、最初に出現した要素を配置しようとしていることを意味します。 
4. この条件に違反した場合、直ちに再建は不可能であると判断します。 
5. 矛盾なくスキャンを終了すると、ターゲットの順序は、操作を通じて解決可能なすべての許可された反転と一致します。 

重要な考え方は、この操作では、大きい要素が右側の小さい要素を横切らなければならない状況を「修正」することは決してできないということです。 一方向の反転のみを解決します。 

### なぜ効果があるのか

 この操作は、反転解像度のレンズを通して見たときに、元のインデックスによって引き起こされる半順序を保存します。 有効な移動ごとに、小さい要素を前方に引っ張ることによって、大きい要素が小さい要素に先行する反転が 1 つ削除されます。 これは、変換中、元のインデックスに関して選択された要素のシーケンスが、非減少エンベロープ制約との一貫性を維持する必要があることを意味します。 貪欲スキャンはまさにこのエンベロープを強制します。極右の元のインデックスがコミットされると、そのエンベロープに違反する必要がある以前の位置から後の要素を取得することはできません。 この不変条件により、スキャンが成功した場合、ターゲットの配置を実現するための有効なプルのシーケンスが存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        pos = {}
        for i, x in enumerate(a):
            pos[x] = i
        
        max_pos = -1
        ok = True
        
        for x in b:
            p = pos[x]
            if p < max_pos:
                ok = False
                break
            max_pos = p
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に初期配列の位置マップを構築して、各値を O(1) の元のインデックスに変換できるようにします。 次に、これまでに確認された最大の元のインデックスを追跡しながら、ターゲット配列を調べます。 重要なチェック`p < max_pos`不可逆的な反転パターンを元に戻す必要があるような方法で、元のインデックス順序で「逆戻り」しないことを強制します。 この貪欲な性質は、一度違反が発生すると、その後の操作を再配置しても、以前の配置を破ることなく制約を修復できないという事実から来ています。 

## 実用的な例

 ### 例 1

 入力:

 a = [2, 4, 3, 1]

 b = [2, 1, 4, 3]

 位置を計算します。 

2→0、4→1、3→2、1→3

 | ステップ | × | pos[x] | 最大位置 | 有効 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 0 | はい |
 | 2 | 1 | 3 | 3 | はい |
 | 3 | 4 | 1 | 3 | はい |
 | 4 | 3 | 2 | 3 | はい |

 要素が大幅に並べ替えられているように見えても、ターゲット内に新しい要素が表示されるたびに、その元の位置が実行可能性を損なう形で累積最大制約と矛盾することはありません。 

### 例 2

 入力:

 a = [2, 1, 1, 3]

 b = [1, 2, 3, 1]

 位置 (最初に出現):

 2 → 0、1 → 1、3 → 3 (概念的に同じ値の 1 つのマッピングを使用することにはすでに問題があります。一貫したマッピングは矛盾につながります)

 | ステップ | × | pos[x] | 最大位置 | 有効 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | はい |
 | 2 | 2 | 0 | 1 | 違反 |

 ステップ 2 では、pos[2] = 0 < max_pos = 1 が必要です。これは、後のターゲット要素が既にコミットされたセグメント境界よりも前に開始する構成に強制されることを意味します。この構成は、左プル操作のみを使用して修復することはできません。 

これは、ターゲットが操作では生成できない構造的逆転を要求したときに、この方法がどのようにして実行不可能性を即座に把握するかを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、配列がすでにソートされている場合です。 アルゴリズムは、max_pos を順序の位置に単調に等しく設定し、違反は発生しないため、答えは正しく YES です。 

もう 1 つのエッジ ケースは、完全に反転した配列です。 ここでは、ターゲットの初期の要素は大きな元の位置にマップされますが、後の要素はより小さな位置に強制的にドロップされ、即座に条件がトリガーされます。`p < max_pos`、必要に応じて NO を生成します。 

3 番目の特殊なケースには重複が含まれます。 値が繰り返されるため、正しい実装では位置の一貫した処理が保証される必要があります。 位置マップのアプローチは、個別の要素または一貫したインデックス付けを暗黙的に想定しており、実際には、この問題は a と b の間の置換マルチセットのアラインメントを保証するため、一致する出現は正確さを維持します。
