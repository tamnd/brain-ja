 ## 解決策
 ## 問題の理解

 指定された範囲内で 2 つの整数の最大 XOR 値を見つけるように求められます。$[l, r]$。 より具体的には、すべてのペアに対して$a$そして$b$そのような$l \le a \le b \le r$の最大の結果が必要です。$a \oplus b$。 入力は 2 つの整数で構成されます$l$そして$r$、次のように大きくすることができます$10^{18}$つまり、すべてのペアを列挙することはできません。これには、最大で$10^{36}$最悪の場合の運用。 出力は単一の整数、つまりすべての有効なペア間の最大の XOR です。 

ここでの重要な観察は、数値が最上位ビットで可能な限り異なる場合に XOR が最大化されるということです。 もし$l$そして$r$最上位ビットが異なる場合、すべての下位ビットを 1 に設定するペアが存在し、大きな XOR が生成されます。 もし$l = r$、任意の数値 XOR 自体が 0 であるため、最大の XOR は 0 です。すべてのペアをチェックする単純な実装では、大きな入力またはメモリのオーバーフローに対して静かに失敗するため、総当たりではなく数学的またはビット単位のアプローチが必要です。 

エッジケースには、以下の範囲が含まれます。$l = r$、すべての数値は 2 のべき乗、または$r = l + 1$。 たとえば、次の場合$l = 1$そして$r = 1$の場合、正しい出力は 0 です。$l = 1$そして$r = 2$、最大 XOR は 3 です。$1 \oplus 2 = 3$。 不注意なアプローチでは、ペアを反復しようとして最大の XOR を見逃したり、時間が足りなくなる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのペアを試すことです$(a, b)$と$l \le a \le b \le r$、計算する$a \oplus b$、最大値を追跡します。 これは小さな入力に対しては正しく機能しますが、最大の制約に対しては機能します。$r - l \approx 10^{18}$、大まかに必要です$(r-l+1)^2 / 2$XOR 演算。これは完全に実行不可能です。 

重要な洞察は、最大 XOR は最上位ビットの位置に依存するということです。$l$そして$r$異なる。 最上位ビットを特定すると、$l$そして$r$異なる場合は、その位置から下方向のすべてのビットを 1 に設定して数値を構築できます。これが機能するのは、2 つの数値間の XOR が異なるビットを反転するためです。 したがって、範囲内の最大の XOR は次の形式の数値になります。$2^k - 1$、 どこ$k$は、最大の異なる位置にあるビットの数です。 

たとえば、$l = 5$(2進数で101)および$r = 6$(2 進数で 110)、最も重要な異なるビットは右から 2 番目のビットです。 その位置から下方向のすべてのビットを 1 に設定すると、2 進数で 111、つまり 7、つまり正しい最大 XOR が得られます。 

この観察により、問題は、最も重要な異なるビットの位置を見つけて、下位ビットをすべて設定して数値を構築することになり、非常に高速な解決策が得られます。$O(\log r)$時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((r-l+1)^2) | お(1) | 遅すぎる |
 | 最適 | O(log r) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$l$そして$r$。 この範囲内の数値の最大 XOR を計算する必要があります。 
2. 次の XOR を計算します。$l$そして$r$で示される$x = l \oplus r$。 この数値は、範囲内の最小値と最大値の間で異なるビットを正確に強調表示します。 
3. に設定されている最上位ビットの位置を見つけます。$x$。 これはシフトを繰り返すことで実現できます$x$0 になるまで右にシフトし、シフト数をカウントします。 この位置をこうしよう$k$。 
4. 最大の XOR は、この位置から下方のすべてのビットを 1 に設定することで実現されます。2 進数では、これは次の数値になります。$k$もの。 数学的には、これは$2^k - 1$。 
5. 結果を印刷します。 これは、範囲内の 2 つの数値間で取得できる最大の XOR です。$[l, r]$。 

機能する理由: XOR は、2 つのオペランドが異なるすべてのビット位置で 1 を生成します。 XOR を最大化するには、可能な限り最高位のビットを 1 にする必要があります。$l$そして$r$範囲内で、そのビットと、場合によってはすべての下位ビットが異なる 2 つの数値を選択できることが保証されます。 したがって、その数は、$2^k - 1$可能な最大の XOR を正確にキャプチャします。 この構造の外で数値を選択しようとすると、より小さな XOR が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l, r = map(int, input().split())

x = l ^ r
max_xor = 0
while x:
    max_xor = (max_xor << 1) | 1
    x >>= 1

print(max_xor)
```コードは最初に計算します$l \oplus r$異なるビットを見つけるために。 次に、左シフトと OR 演算を使用して、最も重要な異なるビットの下のすべてのビットを 1 に設定することで、最大の XOR を構築します。 異なるビットがすべて処理されるとループは停止し、範囲の最大の XOR が生成されます。 これにより、速度が遅すぎる範囲自体の反復を回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    l, r = map(int, input().split())
    x = l ^ r
    max_xor = 0
    while x:
        max_xor = (max_xor << 1) | 1
        x >>= 1
    return str(max_xor)

# provided sample
assert run("1 2\n") == "3", "sample 1"

# custom cases
assert run("5 6\n") == "3", "small range"
assert run("1 1\n") == "0", "l equals r"
assert run("8 15\n") == "7", "range crossing power of two boundary"
assert run("0 1023\n") == "1023", "full range of 10 bits"
assert run("123456789 987654321\n") == "939524095", "large numbers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 6 | 3 | 隣接する小さな数字 |
 | 1 1 | 0 | 同一のエンドポイント |
 | 8 15 | 7 | 2 のべき乗の境界を越える範囲 |
 | 0 1023 | 1023 | 10 ビットの小さい数値の全範囲 |

 ## 特殊なケース

 のために$l = r$の場合、XOR は常に 0 です。たとえば、次のように入力します。`42 42`生成する$x = 42 ^ 42 = 0$の場合、ループは実行されず、max_xor は 0 のままになります。 

2 のべき乗の境界にまたがる範囲の場合、次のようになります。`8 15`、最初に異なるビットは右から 3 番目です。 それ以下のすべての 1 を構築すると 7 が得られます。これは、範囲内で達成可能な正しい最大 XOR です。 

大勢が近づいてくる場合$10^{18}$、アルゴリズムは 60 ビットのみを反復し、オーバーフローすることなく正しい最大 XOR を生成します。
