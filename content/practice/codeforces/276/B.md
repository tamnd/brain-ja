 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられ、2 人のプレイヤーが順番に 1 文字を削除します。 プレーヤーは、自分のターンの直前に、現在の文字を回文に並べ替えることができれば勝ちです。 私たちの仕事は、両方のプレイヤーが最適にプレーすると仮定して、どちらのプレイヤーが勝つかを決定することです。 

文字列の長さは最大 1000 で、各文字を複数回検査するソリューションを実現するには十分な長さですが、シーケンスの数が指数関数的に増加するため、考えられるすべての削除シーケンスの総当りシミュレーションには長すぎます。 すべての削除パスを試すのではなく、文字数を検査するソリューションが必要です。 

微妙なのは、文字列を回文に再配置できる理由を理解することです。 最大 1 つの文字が奇数回出現する場合、文字列を回文に置き換えることができます。 たとえば、「aba」は「aba」自体を形成できますが、「aabbc」は奇数の数の文字が 3 つあるため、回文を形成できません。 将来の最適な動きを考慮せずに現在の文字列だけを単純にチェックすると、間違った答えが得られる可能性があります。 

特殊なケースの 1 つは、すべての文字が偶数回出現する場合です。 たとえば、「aabb」はすでに回文なので、最初のプレーヤーがすぐに勝ちます。 もう 1 つは、すべての文字が一意である「abc」のような文字列です。 最初の移動で 1 文字を削除すると回文は許可されませんが、その後の削除では回文が許可されます。 これらのケースは、各手をシミュレートするのではなく、文字数のパリティについて推論する必要があることを示しています。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての削除シーケンスをシミュレートしようとします。 シーケンスごとに、残りの文字列を回文に再配置できるかどうかを確認します。 これは原理的には正しいですが、シーケンスの数は文字列の長さの階乗に応じて変化するため、現実的ではありません。 n = 1000 の場合、これは天文学的に大きく、妥当な時間内に実行することはできません。 

重要な洞察は、ゲームが完全にキャラクター数の同等性に依存しているということです。 文字が偶数回出現する場合、回文の奇数カウント条件に影響を与えることはできません。 奇数回出現する文字は重要です。回文内に存在できる奇数文字は最大 1 つです。 

奇数に出現する文字の数を次のように定義します。`odd_count`。 もし`odd_count`が 0 または 1 の場合、文字列はすでに回文順列であるため、最初のプレーヤーがすぐに勝ちます。 もし`odd_count`が 1 より大きい場合、プレイヤーは交代で交代します`odd_count`文字を削除することで。 移動するたびに減少します`odd_count`プレイヤーが奇数カウントで文字を削除した場合は 1 増加し、偶数カウントから削除した場合は増加します。 このゲームでの最適なプレイは、単純なパリティ チェックに帰着します。`odd_count`これは奇妙で、最初のプレイヤーはいつでも強制的に勝利をもたらすことができます。 もし`odd_count`が偶数の場合、2 番目のプレーヤーは動きを反映して勝利を強制することができます。 これにより、問題は奇数周波数のカウントとパリティのチェックに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 文字列内の各文字の頻度を数えます。 これにより、奇数と偶数の発生数が取得され、ゲームの結果が完全に決まります。 
2. 奇数の頻度を持つ文字が何文字あるか数えます。 この値を呼び出します`odd_count`。 奇数文字のそれぞれは、回文の形成に対する潜在的な障害を表します。 
3. もし`odd_count`が 0 または 1 の場合、最初のプレイヤーは文字を削除せずにすぐに回文を作成できます。 「First」を出力して停止します。 
4. それ以外の場合は、次のパリティを調べます。`odd_count`。 奇数の場合、最初のプレーヤーはいつでも、2 番目のプレーヤーが偶数に直面する状態にゲームを縮小できます。`odd_count`、最終的に最初のプレイヤーに勝ち手を残します。 偶数の場合、2 番目のプレーヤーは最初のプレーヤーの動きを反映して、最後の動きまでコントロールを維持できます。 次の場合は「最初」を出力します`odd_count`奇数である場合、「Second」を出力します。 

なぜ機能するのか: 不変式は次のパリティです。`odd_count`。 それぞれの動きは変化する`odd_count`どの文字が削除されるかに応じて、1 ずつ増加または減少します。 最適なプレーにより、プレーヤーは互角の状況に直面することが保証されます。`odd_count`自分の番が来ても、プレイヤーが奇数に直面している間は勝つことができません。`odd_count`勝利を強制することができます。 このロジックは、移動ツリー全体をシミュレートすることなく、すべてのケースをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
freq = [0] * 26

for ch in s:
    freq[ord(ch) - ord('a')] += 1

odd_count = sum(1 for f in freq if f % 2 == 1)

if odd_count <= 1 or odd_count % 2 == 1:
    print("First")
else:
    print("Second")
```このソリューションでは、各小文字を表す長さ 26 の配列を使用して文字の頻度をカウントします。 奇数の頻度で文字の数を計算し、パリティ ロジックを使用して勝者を決定します。 微妙な部分はパリティ チェックです。奇数カウントの文字が 1 つだけまたは奇数の場合、最初のプレイヤーが勝ちます。 「odd_count == 1」の場合を忘れると、すでに回文になっている文字列に対して不正確な答えが生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - ord('a')] += 1
    odd_count = sum(1 for f in freq if f % 2 == 1)
    if odd_count <= 1 or odd_count % 2 == 1:
        return "First"
    else:
        return "Second"

# provided samples
assert run("aba\n") == "First", "sample 1"
# custom cases
assert run("aabb\n") == "First", "all characters even"
assert run("abc\n") == "First", "all characters odd, odd_count > 1"
assert run("aabbcc\n") == "Second", "all even, even length"
assert run("a\n") == "First", "single character"
assert run("ab\n") == "First", "two different characters, odd_count = 2, second wins"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | "aabb" | 最初 | すでに回文、カウントさえあります |
 | "ABC" | 最初 | 奇数のカウントが 1 を超えると、最初のプレイヤーが強制的に勝利することができます |
 | "aabbcc" | 2番目 | すべて偶数カウント、偶数パリティ、2 番目の勝ち |
 | "a" | 最初 | 単一キャラクター、最初のプレイヤーが即勝ち |
 | "アブ" | 2番目 | 2 つの異なるキャラクターであっても、`odd_count`、2 番目のプレーヤーが勝ち |

 ## 特殊なケース

 「a」のような長さ 1 の文字列の場合、`odd_count`は 1 です。アルゴリズムはすぐに「First」を出力します。 「aabbcc」のように、すべての文字が偶数回繰り返される文字列の場合、`odd_count`は 0 なので、最初のプレーヤーは減らすことができないため、2 番目のプレーヤーが勝ちます。`odd_count`奇数に。 パリティ チェックは、複数の奇数文字を含む文字列を正しく処理し、次の場合に最初のプレイヤーが勝つことを保証します。`odd_count`奇数で偶数の場合は負けます。
