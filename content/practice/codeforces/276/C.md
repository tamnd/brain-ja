 ## 解決策
 ## 問題の理解

 数値の配列と、その配列内の位置に対する一連の間隔クエリが与えられます。 各クエリは、連続したセグメント内の要素の合計を要求します。 クエリに答える前に、配列を自由に並べ替えることができます。 再配置後、すべてのクエリはこの新しい配置に基づいて評価され、すべてのクエリ結果を組み合わせた合計を最大化したいと考えています。 

タスクを再解釈する便利な方法は、クエリを別個の操作として考えることを忘れ、代わりに配列内の各位置がすべてのクエリで何回「使用」されるかを考えることです。 位置が多くのクエリ範囲に含まれる場合、そこに配置した値が何であれ、最終的な合計に何度も追加されます。 ポジションがめったにカバーされない場合、そのポジションの価値はほとんど寄与しません。 

制約は最大 200,000 個の要素と 200,000 個のクエリに達し、順列またはクエリ シミュレーションごとに合計を再計算するソリューションは即座に除外されます。 任意の二次関数または偶数$O(n \log n)$順列ごとのアプローチは遅すぎます。 理想的には、ソートと線形スイープを主体としたソリューションが必要です。$O(n \log n)$。 

素朴だが魅力的なアイデアは、位置の頻度を注意深くカウントせずに、すべての順列を試したり、貪欲に値を割り当てたりすることです。 これは失敗します。要素の値は、要素自体ではなく、その最終位置をカバーするクエリ間隔の数に完全に依存するからです。 

具体的な障害モードは、各クエリを独立して処理することです。 たとえば、配列の場合`[1,2,3]`そしてクエリ`[1,2]`そして`[2,3]`、重複をカウントせずに「中間」または「端」に大きな数値を割り当てると、最適ではない配置につながります。 正しい戦略は、クエリごとの推論ではなく、累積的なカバレッジに依存します。 

もう 1 つの微妙な落とし穴は、エンドポイントが同等に重要であると想定していることです。 実際には、上記の例の位置 2 は両方のクエリに出現するのに対し、位置 1 と 3 は 1 回しか出現しないため、より価値があります。 

## アプローチ

 ブルート フォース アプローチでは、配列のすべての並べ替えを試行し、各配置の結果として得られるクエリの合計を計算します。 順列ごとに、すべてのクエリのコストを評価する$O(q)$、そして、あります$n!$順列。 要素をローカルで交換するなどの制限を行っても、最悪のケースは有意義に改善されません。 アレンジメントのスペースが広すぎます。 

重要な観察は、その位置をカバーするクエリの数を決定すると、各配列位置の寄与は独立しているということです。 位置の場合$i$に含まれています$c_i$クエリを実行し、値を配置します$x$そこが貢献する$x \cdot c_i$最終的な金額まで。 これにより、問題はマッチング タスクに変わります。つまり、カバレッジ数が大きい位置に大きな値を割り当てたいと考えます。 

したがって、問題は、各インデックスがクエリによってカバーされる頻度を計算し、最大の配列値と最大のカバレッジ数を組み合わせることに帰着します。 これは、貪欲な最適割り当てを直接適用したものです。両方のシーケンスを同じ順序でソートすると、ドット積が最大化されます。 

カバレッジを効率的に計算するために、差分配列を使用します。 クエリごとに$[l, r]$で増分します。$l$で減少します$r+1$、次にプレフィックス合計を付けて、インデックスごとのカバレッジを回復します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot q)$|$O(n)$| 遅すぎる |
 | 最適 (頻度 + ソート) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`freq`サイズの`n + 2`ゼロ付き。 これにより、範囲更新を通じて間接的に各位置をカバーするクエリの数が追跡されます。 
2. クエリごとに$[l, r]$、増分`freq[l]`1 ずつ減分`freq[r+1]`by 1. これは、カバレッジが次から始まるという考えをエンコードしています。`l`そしてその後終了します`r`。 
3. プレフィックスの合計を計算します`freq`左から右へ。 このステップの後、`freq[i]`インデックスを含むクエリの数を表します`i`。 
4. 元の配列をソートする`a`降順で。 直感的には、より頻繁に使用される位置には、より大きな値を割り当てる必要があると考えられます。 
5. 並べ替える`freq`配列も降順で並べられます (パディングは無視されます)。 これで、両方の配列が整列され、最大値が最も頻繁に使用される位置とペアになり、2 番目に大きい値が 2 番目に頻繁に使用される位置とペアになり、以下同様になります。 
6. 対応する要素を掛け合わせて合計し、最終的な答えを求めます。 

### なぜ効果があるのか

 カバレッジを計算した後、各ポジションは最終的な合計に独立して寄与します。 位置への値の割り当てを修正すると、合計スコアは積の合計になります。$a[i] \cdot c[i]$。 これはまさに順列における最大内積問題であり、並べ替えの不等式により、両方のシーケンスを同じ順序で並べ替えることで可能な最大の和が得られることが保証されます。 より大きな値とより小さなカバレッジの位置をずらすスワップでは内積が減少するため、他の置換によって合計を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

freq = [0] * (n + 2)

for _ in range(q):
    l, r = map(int, input().split())
    freq[l] += 1
    freq[r + 1] -= 1

for i in range(1, n + 1):
    freq[i] += freq[i - 1]

freq = freq[1:n + 1]

a.sort(reverse=True)
freq.sort(reverse=True)

ans = 0
for x, c in zip(a, freq):
    ans += x * c

print(ans)
```このソリューションでは、まず差分配列を使用して各インデックスの頻度プロファイルを構築し、各クエリが一定時間内に寄与することを保証します。 プレフィックスの蓄積ステップでは、それを実際の位置ごとのカウントに変換します。 

両方の配列のソートは、貪欲な割り当てが行われる重要なステップです。 最大の値と最大の頻度を組み合わせると、合計の寄与が最大になります。 

最後のループは、これらの整列されたシーケンスの内積を単純に計算します。

## 複雑さの分析

 | Measure | 複雑さ | Explanation |
 | --- | --- | --- |
 | Time |$O(n \log n + q)$| 並べ替えが優先され、プレフィックスとクエリの処理は線形です。 
| スペース |$O(n)$| 周波数配列と入力ストレージ |

 制約では最大 200,000 の要素とクエリが許可されるため、線形または対数線形のソリューションが必要です。 このアルゴリズムは、クエリと 2 つのソートに対して 1 回のパスのみを実行するため、制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 2)

    for _ in range(q):
        l, r = map(int, input().split())
        freq[l] += 1
        freq[r + 1] -= 1

    for i in range(1, n + 1):
        freq[i] += freq[i - 1]

    freq = freq[1:n + 1]

    a.sort(reverse=True)
    freq.sort(reverse=True)

    ans = sum(x * c for x, c in zip(a, freq))
    return str(ans)

""") == "25"

""") == "5"

 ## 特殊なケース

 重要なエッジ ケースは、すべてのクエリが同一である場合です。たとえば、すべてのクエリが$[1, n]$。 この状況では、すべての位置が同じ周波数を持ち、どの順列でも同じ結果が得られるはずです。 周波数配列が一定になり、並べ替えによって均一性が維持されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、クエリが 1 つの領域に大きく偏っている場合です。たとえば、単一のインデックスを中心とした重複する間隔が多数ある場合です。 プレフィックス周波数の計算により、そのインデックスにピークが正しく生成され、ソートにより最大の配列値がそこに割り当てられるようになります。 

最後に、いつ$n = 1$、可能な配置と可能な貢献は 1 つだけです。 差分配列は引き続き問題なく機能し、インデックス 1 をカバーするクエリの数に等しい単一の頻度値を生成し、ドット積は単純な乗算に減ります。
