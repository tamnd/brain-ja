 ## 解決策
 ## 問題の理解

 同じサイズの 2 つの正方形のグリッドが与えられ、各セルには整数の色が含まれています。 最初のグリッドで許可される唯一の操作は、その中心を中心に時計回りまたは反時計回りに 90 度回転することです。この操作は複数回適用できます。 タスクは、すべてのセル位置で最初のグリッドを 2 番目のグリッドとまったく同じにするために必要な回転の最小回数を決定することです。 どの回転シーケンスも最初のグリッドを 2 番目のグリッドに変換できない場合は、-1 を出力する必要があります。 

重要な観察は、変換空間が非常に小さいということです。 正方形上の 90 度回転のシーケンスは、最大 4 つの異なる状態を循環します。 これは、答えが時計回りに 0、1、2、または 3 回転の 4 つの可能性のうちの 1 つだけであることを直ちに示唆しています (または同等に、時計回りと反時計回りのステップの組み合わせは、これら 4 つの正味回転のいずれかになります)。 これにより、最適化問題のように見えるものが有限比較問題に分解されます。 

制約は非常に小さく、N は最大 20、T は最大 100 です。これは、O(N²) の比較を一定の回数繰り返しても、わずかに高速であることを意味します。 回転されたグリッドを明示的に構築し、それらを比較するソリューションは、問題なく合格します。 ハッシュ、大規模な状態空間にわたるシミュレーション、または高度なデータ構造は必要ありません。 

主な微妙なエッジケースは、回転の等価性を誤解していることです。 単純な間違いは、時計回りと反時計回りのステップを独立したシーケンスとして扱うことであり、不必要な探索や誤ったカウントにつながります。 もう 1 つは、回転後の部分一致は拡張性を意味すると仮定していますが、各回転がグローバル構造を保持する必要があるため、これは誤りです。 

たとえば、次のことを考えてみましょう。 

入力:```
1
2
1 2
3 4
3 1
4 2
```ここで、2 番目のグリッドは最初のグリッドを回転させたものですが、回転しないと位置合わせされていません。 左上からの単純な要素ごとの貪欲なチェックは、有効な回転が存在する場合でも、早期に失敗します。 正しい答えは、ローカルの一致ではなく、グローバルな位置合わせによって決まります。 

もう 1 つの特殊なケースは、グリッドが同一である場合です。 4 回転を適用すると恒等状態に戻りますが、答えは 0 でなければなりません。 負でない最小回転数を確実に選択する必要があります。 

## アプローチ

 ブルート フォース パースペクティブは、考えられるすべての回転シーケンスをシミュレートすることから始まります。 最初のグリッドから 0、1、2、3、またはそれ以上の回転を適用できますが、4 回転ごとにグリッドが繰り返されます。 したがって、それより長いシーケンスは、最初の 4 つの状態のいずれかに相当します。 回転状態の候補ごとに、結果のグリッドがターゲット グリッドと一致するかどうかを確認します。 各チェックのコストは O(N²) で、状態は 4 つしかないため、ブルート フォースはすでに非常に小さくなっています: O(4N²)。 

重要な構造的洞察は、回転操作が次数 4 の循環グループを形成するということです。これは、可能性のツリーを検索しているのではなく、回転中の初期グリッドの小さな固定軌道を評価していることを意味します。 この問題は、最大 4 つの決定論的変換を計算し、それらを比較することに帰着します。 

すべてのシーケンスは正味回転モジュロ 4 になるため、シーケンスを探索したり、時計回りと反時計回りの動きを別々に混合したりすることに利点はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (シーケンスをシミュレート) | O(4・N²) | O(N²) | 受け入れられますが冗長です |
 | 最適 (4 回転を確認) | O(4・N²) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 最初のグリッドの 4 つの可能な方向をすべて明示的に生成し、それぞれを 2 番目のグリッドと比較します。 

1. サイズ N × N の 2 つのグリッド A と B を読み取ります。目的は、B が A の回転と一致するかどうかをテストすることです。 
2. グリッドを時計回りに 90 度回転する関数を定義します。 各セル (i, j) について、(j, N − 1 − i) に移動します。 このマッピングにより構造が保存され、マトリックスの正確な固定回転が保証されます。 
3. A に等しい作業グリッドから開始し、それを回転状態 0 とみなします。 
4. 現在のグリッドを B と比較します。正確に一致する場合は、現在の回転数を回答候補として記録します。 
5. 90 度回転を 1 回適用して、次の状態を取得します。 このプロセスを合計 3 回繰り返して、グリッドのすべての異なる方向を作成します。 
6. 4 つの状態をすべて生成した後、B に一致したものの中から最小の回転数を選択します。一致する状態がない場合は、-1 を出力します。 

B を A に戻すのではなく、すべての状態を明示的に生成する理由は、順方向回転の方が正しく実装するのが簡単で、逆マッピング エラーを回避できるためです。 

### なぜ効果があるのか

 許可された操作のすべてのシーケンスは、4 を法とする整数 k による回転に対応します。A から到達可能な構成のセットは、まさにこの巡回グループの下での A の軌道です。 軌道には最大 4 つの異なる要素が含まれるため、それらを網羅的に列挙すると、B が到達可能であれば、これらの状態の中で 1 回だけ出現することが保証されます。 このアルゴリズムは、回転下ですべての可能な同値クラスをチェックするため完全であり、構築された各状態は元のグリッドの有効な回転であるため健全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rotate(mat):
    n = len(mat)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            res[j][n - 1 - i] = mat[i][j]
    return res

def same(a, b):
    n = len(a)
    for i in range(n):
        for j in range(n):
            if a[i][j] != b[i][j]:
                return False
    return True

t = int(input())
for _ in range(t):
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]
    b = [list(map(int, input().split())) for _ in range(n)]

    cur = a
    ans = None

    for k in range(4):
        if same(cur, b):
            ans = k if ans is None else min(ans, k)
        cur = rotate(cur)

    print(-1 if ans is None else ans)
```このソリューションは、現在の行列を維持し、決定論的な回転関数を繰り返し適用します。 比較関数は O(N²) の等価性をチェックします。これは制約を考慮すると効率的です。 k を介したループにより、アイデンティティのケースを含む 4 つの可能な方向すべてがテストされることが保証されます。 

よくある間違いは、A の代わりに B を一貫性なく回転させたり、4 回転後に行列が元の状態に戻ることを忘れたりすることです。 実装では厳密に 4 回反復することでこれを回避します。

 ## 特殊なケース

 主なエッジケースは、グリッドがすでに同一である場合です。 この状況では、正解は 0 であり、アルゴリズムは不必要な回転を実行することなく、k = 0 でこれを即座に取得します。 

もう 1 つのエッジ ケースは、1 回だけではなく複数回回転させないとターゲットに到達できない場合です。 たとえば、3×3 グリッドでは、多くの場合、すべての中間状態をチェックする必要があります。 回転はグローバルな変換であるため、1 つの不一致の後で早期に停止することは正しくありません。 

最後のエッジ ケースは、ローカル パターンは共有するものの、グローバルには異なる可能性がある到達不可能なグリッドです。 各回転状態の行列全体にわたって等価性がチェックされ、部分構造が誤って一致をトリガーすることがないことが保証されるため、アルゴリズムはそれらを正しく拒否します。
