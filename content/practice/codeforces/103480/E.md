 ## 解決策
 ## 問題の理解

 いくつかの配列が与えられており、各配列から値を 1 つだけ選択する必要があります。 その選択の後、概念的にはサイズ n のマルチセットが得られます。 次に、この問題は、2 つの値を繰り返し選択し、それらの絶対差を累積コストに加算し、そのうちの 1 つを破棄し、1 つの値だけが残るまで継続するマージ プロセスを定義します。 

プロセスは動的に記述されていますが、重要な点は、総コストが配列から選択された数値のみに依存し、シミュレーションの任意の選択には依存しないということです。 配列ごとに選択した値を 1 つ固定したら、任意の順序で自由にマージを実行できます。 

目標は、各配列から 1 つの要素を選択して、絶対差分の合計を最小限に抑える一連のマージが存在するようにすることです。 

制約から、n は最大 10 ですが、すべての配列の要素の合計数は最大 10^6 です。 これは、選択範囲に対する指数関数的な検索を避けるべきであることを直ちに示唆していますが、要素の総数が線形または線形に近いアルゴリズム (おそらく n が関与する係数) を使用できることを示唆しています。 

重要な構造上の困難は、各配列が制約に影響を与えることです。各リストから要素を 1 つだけ選択し、選択されたすべての値に対してグローバル目標を最適化する必要があります。 

すべての配列に大きく分離された値が含まれている場合、微妙なエッジ ケースが発生します。 たとえば、ある配列に小さな値のみが含まれ、もう 1 つの配列に大きな値のみが含まれている場合、どの選択を行っても最終的な範囲が大きくなり、答えはリスト間の極端な値によって支配されます。 各リストを個別に最適化する単純な欲張りは、リスト間の相互作用が重要であるため、ここでは失敗します。 

もう 1 つの特殊なケースは、複数の配列に重複または同一の値が含まれる場合です。 その場合、最適なソリューションは、選択したすべての値を非常に近くに揃えることから得られる可能性があり、ローカル中央値を個別に選択する単純なアプローチでは、グローバルにタイトな構成を簡単に見逃してしまう可能性があります。 

## アプローチ

 最初のステップは、マージ プロセスを再解釈することです。 選択した値を修正したら、2 つの数値を繰り返し選択し、その絶対差を支払い、一方を破棄し、もう一方を保持します。 これは、数直線上の一連の点を結合して徐々に減らすことに相当します。 

これを推論する便利な方法は、選択された固定セット S の最小コストがいくらであるかを尋ねることです。演算の順序を無視し、代わりに、各マージが 2 つの値の間のエッジに対応する構造にすべての数値を接続し、コストが絶対的な差に等しいことを考えるとします。 これにより、総重みがすべてのマージ コストの正確な合計となる S 上のツリーが生成されます。 

ここで重要な観察は、1 次元では、点のセットの最小スパニング ツリーは、それらを並べ替えて隣接する点を接続することによって単純に取得されるということです。 このツリーの合計の重みは連続する差分の合計であり、S の最大要素と最小要素の差にまで拡張されます。 

したがって、配列ごとに 1 つの要素を固定的に選択する場合、可能な限り最良のコストは、選択した値の範囲に等しくなります。 

これにより、問題はより明確な形式に縮小されます。各配列から値を 1 つ選択して、選択した値の最大値と最小値の差を最小限に抑えます。 

ここで、問題は古典的な「k リストをカバーする最小範囲」問題になります。 各配列は並べ替えられたリストであり、選択された値ができるだけ近くなるように、各リストから 1 つの要素を選択する必要があります。 

ブルート フォース ソリューションでは、配列ごとに 1 つの要素のあらゆる組み合わせが試行されます。 各配列に m 個の要素がある場合、m^n 個の可能性が生じますが、これは n = 10 の場合でも完全に不可能です。

最適な洞察は、任意の組み合わせを探索する必要がないということです。 代わりに、リストの和集合に対してスライディング ウィンドウを維持し、いつでも各配列から要素を 1 つだけ選択し、現在の最小値と最大値を追跡します。 次に、現在最小値に寄与している配列内を前方に移動して、範囲を縮小しようとします。 

これが機能するのは、各配列がアクティブな要素を 1 つだけ提供するという制約を維持しながら、範囲を縮小できる可能性がある唯一の方法が最小値を増やすことであるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての選択) | O(m^n) | O(n) | 遅すぎる |
 | 最適 (ヒープ + ポインター) | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各配列をソートされたリストとして扱い、その配列から現在選択されている要素を表す各リストへのポインターを維持します。 

また、現在選択されている値が最小であることと、その値がどの配列から来たのかをすぐに知ることができるデータ構造も維持します。 

1. すべての配列のポインターをインデックス 0 に初期化します。これは、最初に各配列から最小の要素を選択することを意味します。 
2. 選択したすべての値を構造に挿入すると、選択した値の中で現在の最大値を追跡しながら、現在の最小値を効率的に取得できるようになります。 現在の範囲は、最大値から最小値を引いたものとして計算されます。 
3. 現在の構成を繰り返し検討し、改善を試みます。 各ステップで、現在選択されている要素がすべての選択要素の中で最小である配列を特定します。 
4. その配列のポインタを 1 つ前に移動し、選択した値をその配列内の次の要素に置き換えます。 この方向が正しい理由は、最小値を増やすことが全体の範囲を潜在的に縮小する唯一の方法だからです。 他のポインタを移動しても、最小側の現在のボトルネックを取り除くことはできません。 
5. ポインタを更新した後、新しく導入された値が以前の最大値より大きい場合は現在の最大値を更新し、範囲を再計算します。 
6. ポインタが配列の末尾に到達するまでこのプロセスを続けます。その後、その配列から有効な要素を選択できなくなるためです。 

### なぜ効果があるのか

 常に、各配列からアクティブな選択肢を 1 つだけ維持します。 現在の範囲は、これらの選択された値の最小値と最大値によって決まります。 範囲を狭めたい場合は、最大値を減らすか、最小値を増やす必要があります。 ただし、最大値を下げることは、現在最大値ではない値を変更せずに行うことは不可能であり、そうすることは、他の場所で範囲が広がる危険を冒すだけです。 ローカルで有効な唯一の改善手順は、現在最小値を保持しているポインタを上に移動することです。これが、有効性を維持しながら範囲の下限を増加させる可能性がある唯一の操作だからです。 

この貪欲な動きにより、ポインターが進むにつれてすべての可能な候補範囲が暗黙的に考慮され、観察された最良の範囲が全体最適となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m = map(int, input().split())
    a = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        arr.sort()
        a.append(arr)

    ptr = [0] * n

    heap = []
    current_max = -10**18

    for i in range(n):
        val = a[i][0]
        heapq.heappush(heap, (val, i))
        current_max = max(current_max, val)

    ans = current_max - heap[0][0]

    while True:
        current_min, i = heapq.heappop(heap)

        if ptr[i] + 1 >= len(a[i]):
            break

        ptr[i] += 1
        new_val = a[i][ptr[i]]

        heapq.heappush(heap, (new_val, i))

        if new_val > current_max:
            current_max = new_val

        current_min_new = heap[0][0]
        ans = min(ans, current_max - current_min_new)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ポインタを進めると常に厳密に大きい候補に移動するように各配列がソートされます。 ヒープには各配列の現在選択されている要素が格納され、グローバル最小値を効率的に抽出できます。 変数`current_max`各ステップが一定時間で範囲を計算できるように、現在のピックの最大値を追跡します。 

よくある落とし穴は、最大値を上方のみに更新するのを忘れることです。 各ステップを最初から再計算しても機能しますが、不必要に遅くなります。 もう 1 つの微妙な問題は、リストが使い果たされたときに確実に終了することです。これを超えると、有効な選択を維持できなくなるからです。

def run(inp: str) -> str:

    import sys

        arr.sort()

        heapq.heappush(heap, (a[i][0], i))

 ## 特殊なケース

 すべての配列に同じ値が含まれている場合、選択するたびにゼロの範囲が生成されます。 このアルゴリズムはすべてのポインターがインデックス 0 にある状態で開始され、すぐにゼロの範囲を確認します。ポインターを移動しても改善できないため、正しく 0 が出力されます。 

1 つの配列に非常に大きな値が含まれ、もう 1 つの配列に非常に小さな値が含まれている場合、初期範囲は大きくなり、アルゴリズムは最小値を上方に移動しようとします。 それぞれの移動により、達成可能な最良のオーバーラップが見つかるまで、極度に小さい値への依存が減少し、最終的な答えは、すべての配列にわたる最も緊密な交差領域に対応します。 

配列の間隔が重複していない場合 (たとえば、配列が完全に別の配列の下にある場合)、アルゴリズムは、最も近い領域に到達するまで下位の配列を効果的に上に押し上げ、その後 1 つのリストを使い果たします。 枯渇する前の最後の有効な構成によって、最適な境界範囲が得られます。これはまさにヒープ プロセスがキャプチャするものです。
