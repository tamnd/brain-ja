 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、正の整数の配列を受け取ります。タスクは、合計が 7777 に正確に等しいサブ配列がいくつあるかを数えることです。サブ配列は、2 つのインデックスを選択することによって定義されます。$l$そして$r$と$l \le r$、それらの間のすべての要素を包括的に合計します。 最大値や最小値を見つけることは求められません。目標の合計を生成する異なる連続セグメントの数を数えるだけです。 

制約は非常に直接的な意味で重要です。 配列の長さは最大です$10^5$、最大 10 個のテスト ケースを含めることができます。 すべての部分配列の単純な 2 次列挙には、約$10^{10}$最悪の場合、1 秒で実行できる処理をはるかに超えた処理が行われます。 これにより、エンドポイントのペアごとに合計を最初から再計算するアプローチは即座に除外されます。 

重要になる構造上の制約があります。すべての要素が正であり、最大 5000 です。これにより、プレフィックスの合計が厳密に増加し、負の補正を気にすることなくスライディング ウィンドウの動作が明確に定義されることが保証されます。 

素朴な実装の微妙な失敗例は、部分配列の合計を繰り返し再計算することです。 たとえば、左のエンドポイントを修正し、繰り返し合計しながら右のポインタを拡張しても、最終的には次のようになります。$O(n^2)$追加。 もう 1 つの落とし穴は、複数のサブ配列が重なり合う可能性があることを無視し、適切なプレフィックス アラインメントを行わずに合計のハッシュを使用した場合に、それらのサブ配列を誤ってカウントすることです。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのペアを列挙します。$(l, r)$、部分配列の合計を計算し、それが 7777 に等しいかどうかを確認します。これは、問題の定義に直接従うため、正しいです。 ただし、それぞれの合計を最初から計算するとコストがかかります$O(n)$、そして、あります$O(n^2)$ペア、につながる$O(n^3)$時間。 プレフィックス合計配列を使用して各サブ配列の合計を最適化し、各クエリを$O(1)$、まだあります$O(n^2)$テスト ケースごとのサブ配列の合計数は大きすぎます。$n = 10^5$。 

重要な観察は、すべての要素のポジティブさから来ています。 すべての数値は正であるため、右に移動するにつれてプレフィックスの合計は厳密に増加します。 これにより、スライディング ウィンドウを維持できるようになります。右のエンドポイントごとに、合計がターゲットを超えている間、左のエンドポイントを前方に移動できます。 不変条件は、現在のウィンドウの合計が常に効率的に維持され、有効な部分配列がスキップされたり二重にカウントされたりしないことです。 

これにより、問題は配列に対する 2 つのポインタのスキャンに変換され、各ポインタは最大でも前方にしか移動しません。$n$回、$O(n)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 引き違い窓を維持しております$[l, r]$とその現在の合計。 

1. 2 つのポインタを初期化する$l = 0$、$r = 0$これは、要素を処理する前の空のウィンドウを表します。 
2. 右ポインタを左から右に段階的に移動します。 各ステップで、現在の要素を累計に加算します。 これによりウィンドウが拡張され、次で終わるすべての可能なサブ配列が確実に考慮されます。$r$。 
3. 現在の合計が 7777 を超えている間に、左ポインタを前方に移動し、ウィンドウから出る要素を減算します。 すべての要素が正であるため、これは有効です。したがって、左から縮小しても合計は減少するだけであり、増加することはありません。 
4. ウィンドウを調整した後、合計が 7777 に等しい場合は、答えをインクリメントします。 これは、現在の配列で終わる一意のサブ配列をカウントします。$r$その合計が目標と一致します。 
5. 右ポインタが配列の末尾に到達するまで続けます。 

正しさは、各位置で次のことが行われるという事実に依存します。$r$、アルゴリズムはすべての有効な左境界を見つけます$l$部分配列の合計は正確に 7777 になります。配列には正の数値のみが含まれるため、有効な調整シーケンスは 1 つにつき 1 つだけです。$r$、有効な部分配列はスキップされません。 

### なぜ効果があるのか

 重要な不変条件は、各ステップでウィンドウが$[l, r]$は、合計が 7777 を超えない、現在の右端点の可能な最小の左境界です。要素は正であるため、移動します。$l$forward は合計を単調に減少させるため、各ポインタは最大で次のように移動します。$n$回。 次で終わるすべての有効なサブ配列$r$は、過大な合計から縮小した後にウィンドウ合計が 7777 になったときに正確に表示される必要があるため、すべての解は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    target = 7777
    l = 0
    s = 0
    ans = 0
    
    for r in range(n):
        s += arr[r]
        
        while l <= r and s > target:
            s -= arr[l]
            l += 1
        
        if s == target:
            ans += 1
    
    return ans

t = int(input())
out = []
for _ in range(t):
    out.append(str(solve()))
print("\n".join(out))
```このコードは、スライディング ウィンドウ プロセスを直接反映しています。 変数`s`現在のウィンドウの合計と左ポインタを追跡します`l`合計を範囲内に保つために必要な場合にのみ移動されます。 条件`s == target`実行可能性を復元した後にのみチェックされ、正確性が保証されます。 テスト ケースごとに 1 つのパスを使用することで、実装の効率性とシンプルさが維持され、プレフィックス合計辞書やハッシュ化が回避されます。 

## 実用的な例

 配列を考慮してください`[2000, 3000, 2777, 1000]`。

| r | l | 窓 | 合計 | アクション |
 | --- | --- | --- | --- | --- |

 | 2 | 0 | [2000、3000、2777] | 7777 | 一致が見つかりました |
 | 3 | 0 | [2000、3000、2777、1000] | 8777 | 左に縮小 |

 到着したら$r = 2$の場合、合計は 1 回だけ一致するため、部分配列を 1 つと数えます。 で$r = 3$の場合、合計がターゲットを超えているため、縮小する必要がありますが、完全に一致するものは表示されません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単一の要素が 7777 に等しい場合です。`[7777]`、アルゴリズムは次から始まります`r = 0`、要素を追加し、すぐに検索します`s == 7777`したがって、正確に 1 つのサブ配列をカウントします。 

もう 1 つのケースは、すべての要素が小さく、どの組み合わせも 7777 に達しない場合です。たとえば、`[1, 2, 3]`ウィンドウの合計がターゲットを超えることはなく、7777 に等しくなることはないため、答えはゼロのままになります。 

より微妙なケースは、合計が一時的に目標を超え、有効なウィンドウが再び見つかる前に縮小する必要がある場合です。 で`[7777, 1, 7776]`の場合、ウィンドウは最初にインデックス 0 で一致し、次にターゲットを超えて拡張し、次に縮小し、後で別の有効な部分配列を見つけます。 スライディング ウィンドウは、等価性を再度チェックする前に常に実行可能性を復元するため、これを正しく処理します。
