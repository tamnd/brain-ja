 ## 解決策
 ## 問題の理解

 単一の整数 n が与えられ、固定メッセージを正確に n 回、それぞれの行に出力するように求められます。 メッセージ自体は常に同一であり、n 以外の入力には依存しません。 

計算の観点から見ると、入力は定数文字列を何回繰り返すかを決定するだけです。 変換や条件付きロジックはなく、繰り返しを数えることを超える状態の蓄積はありません。 これにより、問題は線形出力生成のカテゴリに確実に分類されます。出力サイズは Θ(n) であり、アルゴリズムは結果を書き込むだけで少なくとも Θ(n) 時間を費やす必要があります。 

制約 1 ≤ n ≤ 100 は非常に小さいです。 最も素朴な繰り返し印刷アプローチでも簡単に十分であり、パフォーマンスやメモリに関する懸念はここでは無関係です。 

構造の観点からは意味のあるエッジケースはありませんが、同様のタスクで発生する、正確性に関する小さな落とし穴がまだいくつかあります。 出力間に改行文字を含めるのを忘れると、すべてのメッセージが 1 行に連結される可能性があります。 もう 1 つの間違いは、余分な末尾の空白行や各行の終わりに余分なスペースを出力することです。これにより、目に見える出力は似ているにもかかわらず、厳密な出力比較が失敗します。 たとえば、n = 3 の場合、正しい出力は 3 行に分かれていますが、バグのある解決策では「HZNU へようこそHZNU へようこそ HZNU へようこそ」のような 1 行が生成される可能性があります。 

## アプローチ

 この問題を解決する最も直接的な方法は、要件を文字通りにシミュレートすることです。 n を読み取り、n 回実行されるループ内で必要な文字列を出力します。 各反復では同じ定数行が出力されます。 

ここでは、総当たり的な解釈と最適な実装は事実上同一です。 ブルート フォース ビューは単に「1 から n までのカウントごとに文字列を出力する」というものです。 これが機能するのは、各出力行が独立しており、前の反復のメモリや派生値の計算を必要としないためです。 

このパターンが他の問題で興味深い唯一の理由は、n が大きい場合 (10^7 や 10^9 など) です。この場合、生の出力が実行時間の大半を占め、慎重な I/O 最適化が必要になります。 ここで、n は最大 100 であるため、Python の標準の印刷でも十分に高速です。 

利用できる代替のアルゴリズム構造はありません。 出力自体には明示的に n 行が必要となるため、数式によって印刷行数が削減されることはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | n 回のプリントにわたるブルート フォース反復 | O(n) | お(1) | 承認済み |
 | 最適 (上記と同じ) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、出力を構築するために使用される正確な手順について説明します。 

1. 標準入力から整数 n を読み取ります。 この値により、出力行を何回生成する必要があるかが決まります。 
2. ループを正確に n 回繰り返します。 各反復は、1 つの必要な出力行に対応します。 
3. 各反復で、文字列「Welcome to HZNU」とその後に改行を出力します。 各繰り返しは別の行に表示する必要があるため、改行は必須です。 

アルゴリズムは追加の状態を維持しません。 繰り返しを制御するには、ループ カウンタ自体で十分です。 

### なぜ効果があるのか

 正確さは、ループの反復と必要な出力行との間の直接的な 1 対 1 の対応から得られます。 各反復では、固定文字列のコピーが 1 つだけ生成され、反復間に相互作用はありません。 出力仕様には正確に n 個の同一の行が必要であるため、n 回の繰り返しで反復ごとに 1 回文字列を出力するシーケンスは仕様と正確に一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    out = "Welcome to HZNU"
    for _ in range(n):
        print(out)

if __name__ == "__main__":
    main()
```このソリューションでは、高速入力を使用して整数を読み取り、出力文字列を変数に格納して、ループ内で繰り返し再構築されることを回避します。 これは、このような小さな制約には厳密には必要ありませんが、標準的な競技プログラミングの衛生状態を反映しています。 

このループでは単純な範囲反復を使用し、正確に n 個の出力を保証します。 print を呼び出すたびに、必要な書式設定に一致する改行が自動的に追加されます。 

同様の問題でよくある微妙な間違いは、文字列を手動で連結して一度出力することです。これにより、改行区切り文字が欠落したり、n が大きい場合にメモリを超過したりする危険があります。 ここでは、出力を 1 行ずつストリーミングすることでこれを回避します。 

## 実用的な例

 入力 n = 3 を考えてみましょう。 

| 反復 | 印刷された文字列 |
 | --- | --- |
 | 1 | HZNUへようこそ |
 | 2 | HZNUへようこそ |
 | 3 | HZNUへようこそ |

 各反復は独立して同じ出力行を生成します。 3 回目の反復の後、プログラムは終了します。 

これにより、アルゴリズムが以前の状態に依存せず、反復ごとに必要な定数文字列を一貫して出力することが確認されます。 

ここで、n = 1 について考えてみましょう。 

| 反復 | 印刷された文字列 |
 | --- | --- |
 | 1 | HZNUへようこそ |

 1 回の反復では、出力は正確に 1 行で構成され、余分なスペースや改行の欠落の問題もなく要件を満たします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | ループは必要な出力行ごとに 1 回実行されます。 
| スペース | お(1) | 定数文字列とループ変数のみが格納されます。 

印刷自体が実行の大半を占めるため、時間計算量は出力サイズに直接一致します。 n ≤ 100 の場合、これは Python では自明に速く、一般的な時間制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sysio

    buf = sysio.StringIO()
    with redirect_stdout(buf):
        main()
    return buf.getvalue()

def main():
    n = int(input().strip())
    for _ in range(n):
        print("Welcome to HZNU")

 ## 特殊なケース

 主なエッジ ケースは、下限 n = 1 です。この状況では、ループは 1 回だけ実行され、出力には依然として改行が含まれている必要があります。 ループでは小さな値を特別に処理しないため、実装はこれを自然に処理します。 

たとえば、次の入力を使用します。```
1
```実行では 1 回の反復が実行され、次のように出力されます。```
Welcome to HZNU
```余分な行や改行の欠落はありません。 ループ境界は包括的であり、n によって直接制御されるため、off-by-one のリスクはありません。 

同様の問題におけるもう 1 つの微妙なケースは、セパレータを使用せずに出力を誤って連結することです。 ここで、各 print 呼び出しは独立して改行を発行するため、n = 100 の場合でも、構造は個別の行のシーケンスとして正しいままです。
