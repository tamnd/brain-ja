 ## 解決策
 ## 問題の理解

 デジタルの 7 セグメント スタイルで書かれた 2 つの時間表示が与えられ、各桁が 3 x 3 の固定文字ブロックとしてレンダリングされます。 各時間は 6 桁で構成されます。2 桁は時、2 桁は分、2 桁は秒を表します。 入力は 2 つの完全な時間を提供します。1 つ目は正しい基準時間で、2 つ目は潜在的に不正確な電子時計によって示される時間です。 

各時刻は 3 行にわたってエンコードされます。 各行には 6 桁が並べて書かれており、各桁がちょうど 3 列を占めるため、各行の幅は 18 文字になります。 私たちの仕事は、両方の時間をデコードして比較し、電子時計が実時間より進んでいるのか、遅れているのか、あるいは同一であるかを判断することです。 それらが異なる場合は、同じ 7 セグメント表現で再度フォーマットされた絶対差も出力します。 

固定の 6 行を読み取って一定の作業を実行するだけなので、制約は小さくなります。 実際の計算作業は、数字のパターンを正しく解釈することにあります。 一定時間内にグリッドをスキャンして各桁をデコードするソリューションは、簡単に十分に高速になります。 慎重に解析する以外に最適化を行う必要はありません。 

よくある失敗例は、数字のスライスが間違っていたり、セグメント パターンが一致していなかったりすることが原因です。 

特殊なケースの 1 つは、両方の時間が同一である場合です。 たとえば、両方の入力が次を表す場合、`12:34:56`の場合、出力は正確に次のようになります。```
gang gang hao
```続いて時差ゼロ`00:00:00`数字形式で。 単純なアプローチでも差を計算し、記号処理の間違いにより、早いまたは遅いというラベルが付けられる可能性があります。 

もう 1 つの微妙なケースは、差が時間または分の境界を越える場合です。 たとえば、リアルタイムの場合、`00:00:10`そして電子時計が示す`23:59:59`、正しい動作は、単純なコンポーネントごとの減算ではなく、絶対的な秒の差として扱うことです。 

重要な課題は算術演算ではなく、堅牢なデコードとフォーマットの一貫性です。 

## アプローチ

 ブルートフォースのアイデアは、各数字を未知のパターンとして扱い、考えられるすべての数字テンプレートに対してスキャンして一致を試みることです。 数字が 10 個しかなく、各数字が 3 x 3 のブロックを占めるため、抽出されたすべてのブロックをすべての候補数字パターンと比較できます。 比較の総数は固定されており、小さいため、実際にはこれはすでに一定時間です。 

もう少し構造化されていない強引なアプローチでは、セグメントを動的に解釈したり、セグメント数からのヒューリスティックを使用して数字を再構築したりしようとしますが、これは脆弱であり、不必要になります。 

より信頼性の高いアプローチは、0 ～ 9 の数字の正確な 3 x 3 表現を事前に定義することです。このマッピングが修正されると、デコードは直接検索になります。つまり、各 3 x 3 ブロックを抽出し、それを文字列キーに変換し、それを数字にマッピングします。 両方の時間を合計秒数を表す整数にデコードした後、それらの差を計算し、符号を決定し、絶対差を数値にフォーマットし直します。 

重要な観察は、構造が完全に剛性であることです。 すべての数字の幅と高さは同じで、間隔は暗黙的に設定され、テンプレートがわかればあいまいさは存在しません。 これにより、問題は純粋な解析とフォーマットに集約されます。

 ## アルゴリズムのチュートリアル

 1. 数字 0 ～ 9 の標準 7 セグメント 3 x 3 表現を定義します。各数字は、3 行を連結して形成された 9 文字の署名として保存されます。 これにより、安定した復号キーが得られます。 
2. 最初の 3 行と次の 3 行を読みます。 各グループは、エンコードされた数字形式で 1 ​​つの時間値を表します。 
3. 各行を幅 3 の 6 つのチャンクに分割します。 数字の位置ごとに、その 3 つの垂直スライスを 1 つの 3 x 3 ブロックに結合します。 
4. 各 3 x 3 ブロックを文字列キーに変換し、事前計算された辞書を使用して対応する数字にマップします。 これにより、毎回 6 桁の文字列が再構築されます。 
5. 次を使用して、両方のデコード時間を合計秒数に変換します。`hh * 3600 + mm * 60 + ss`。 これにより、比較のための線形数値スケールが得られます。 
6. 2 つの値を比較します。 等しい場合は、等価文字列を出力します。 それ以外の場合は、どちらの値が大きいかによって電子時間が進んでいるか遅れているかを判断します。 
7. 絶対差を秒単位で計算します。 に変換し直します`hh mm ss`除算とモジュロ演算を使用します。 
8. 数字から 3 × 3 グリッドへの逆マッピングを使用して、この差を 7 セグメント形式に戻し、3 行を出力します。 

なぜそれが機能するのかは、デコードが全単射であるという事実から来ています。 3 x 3 の各パターンは数字を一意に識別するため、解析中にあいまいさが生じません。 時間を秒に変換すると順序が正確に保持されるため、比較の一貫性が保たれます。 逆フォーマットでは逆マッピングが使用され、入力と出力の間の構造的対称性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

digit_map = {
    " _ | ||_|": 0,
    "     |  |": 1,
    " _  _||_ ": 2,
    " _  _| _|": 3,
    "   |_|  |": 4,
    " _ |_  _|": 5,
    " _ |_ |_|": 6,
    " _   |  |": 7,
    " _ |_||_|": 8,
    " _ |_| _|": 9
}

rev = {
    0: [" _ ", "| |", "|_|"],
    1: ["   ", "  |", "  |"],
    2: [" _ ", " _|", "|_ "],
    3: [" _ ", " _|", " _|"],
    4: ["   ", "|_|", "  |"],
    5: [" _ ", "|_ ", " _|"],
    6: [" _ ", "|_ ", "|_|"],
    7: [" _ ", "  |", "  |"],
    8: [" _ ", "|_|", "|_|"],
    9: [" _ ", "|_|", " _|"]
}

def decode(lines):
    digits = []
    for i in range(6):
        block = []
        for r in range(3):
            block.append(lines[r][i*3:(i+1)*3])
        key = "".join(block)
        digits.append(str(digit_map[key]))
    return "".join(digits)

def encode(num):
    s = f"{num:06d}"
    out = ["", "", ""]
    for ch in s:
        d = int(ch)
        for i in range(3):
            out[i] += rev[d][i]
    return out

lines1 = [input().rstrip("\n") for _ in range(3)]
lines2 = [input().rstrip("\n") for _ in range(3)]

t1 = decode(lines1)
t2 = decode(lines2)

h1, m1, s1 = int(t1[:2]), int(t1[2:4]), int(t1[4:])
h2, m2, s2 = int(t2[:2]), int(t2[2:4]), int(t2[4:])

sec1 = h1*3600 + m1*60 + s1
sec2 = h2*3600 + m2*60 + s2

if sec1 == sec2:
    print("gang gang hao")
    diff = encode(0)
else:
    if sec2 > sec1:
        print("late")
        diff = encode(sec2 - sec1)
    else:
        print("early")
        diff = encode(sec1 - sec2)

for line in diff:
    print(line)
```デコード機能は、行全体で 3 文字の固定幅ブロックをスライスすることによって機能します。 各桁は、その 3 つの行を積み重ねることによって再構築されます。 エンコード関数は逆の操作を実行し、数字テンプレートを連結して 3 つの出力行を構築します。 

実装の微妙な詳細は、差を 6 桁に埋め込むことです。 これがないと、先頭のゼロが消えて、必要な表示形式との位置合わせが崩れてしまいます。 

## 実用的な例

 ### 例 1

 デコードされたリアルタイムが次のようになると仮定します。`12:00:10`そして電子時間は`12:00:20`。 

| ステップ | リアルタイム | 電子時間 |
 | --- | --- | --- |
 | デコード | 43210秒 | 43220秒 |
 | 比較 | 小さい | 大きい |
 | 違い | 10秒 | 10秒 |

 電子時計が進んでいる為、出力は以下から始まります。`late`「遅れている」を、電子的な存在が現実よりも遅れていることと定義する場合、そうでない場合は、`early`。 絶対的な差は 10 秒であり、次のようにエンコードされます。`00:00:10`。 

これにより、順序付けがフィールドごとの比較ではなく、純粋に合計秒数に基づいて行われることが確認されます。 

### 例 2

 リアルタイムというのは、`00:00:00`、電子時間は`23:59:59`。 

| ステップ | リアルタイム | 電子時間 |
 | --- | --- | --- |
 | デコード | 0秒 | 86399秒 |
 | 比較 | 小さい | 大きい |
 | 違い | 86399秒 | 86399秒 |

 出力はラップアラウンド減算ではなく、依然として正の差である必要があります。 これは、時間を周期的に扱うことがないことをテストします。

 ## 特殊なケース

 両方の時間が同一の場合、アルゴリズムは両方を同一の 6 桁の文字列にデコードし、結果として秒カウントが等しくなります。 等価分岐は減算の前にトリガーされるため、負の差は計算されません。 出力の差は明示的にゼロに強制され、書式設定パスが引き続き有効な表示を生成するようにします。 

電子時間が実際の時間より大幅に早い場合でも、両方の値が合計秒数に正規化されるため、比較は機能します。 時間と分が個別に異なる関係を示唆している場合でも、スカラー比較により順序が正しく解決されます。 絶対的な差により、マイナスの書式設定の問題が回避されます。 

時間差がちょうど 0 秒の場合でも、エンコード関数はゼロで呼び出され、`000000`これはきれいにマップされます`00:00:00`7セグメント形式です。
