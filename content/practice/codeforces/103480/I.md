 ## 解決策
 ## 問題の理解

 私たちには曲のコレクションが与えられており、各曲には独自の人気値と固有の名前が付いています。 人気の値は厳密なランキング キーのように機能します。同じスコアを共有する曲は 2 つなく、値が高いほど、その曲がより求められていることを意味します。 

この課題は、すべての曲を人気の降順に並べ替えることを想像することです。 最も人気のある曲のいくつかはすでに他のユーザーによって使用されています。 上位の選択肢のうち、たとえば k 個がすでになくなっていることが正確にわかります。 私たちの仕事は、利用可能な次に最適な曲、つまり、ソート順で k + 1 の位置に表示される曲を決定することです。 

入力サイズは最大 100,000 曲まで可能です。 これにより、削除のたびにリストを線形に繰り返しスキャンしたり、ループ内で繰り返しソートを使用したりするアプローチは即座に排除されます。 O(n log n) の解は許容されますが、二次関数は 1 秒の制限を下回ると失敗します。 

k が 0 の場合、微妙なエッジ ケースが発生します。 この場合、曲は選択されないため、答えは単純に世界で最も人気のある曲になります。 もう 1 つの特殊なケースは、k が n − 1 の場合です。この場合、1 つの曲だけが有効であり、位置に関係なくそれを返さなければなりません。 

単純な間違いは、昇順に並べ替えて、誤って k 番目に大きいものではなく、k 番目に小さいものを選択してしまうことです。 たとえば、「最も望ましい」を誤って解釈した場合、並べ替えが正しくても、ランキングが逆転し、一貫して間違った曲が返されてしまいます。 

## アプローチ

 最も簡単なアイデアは、すべての曲を人気度の値に基づいて降順に明示的に並べ替えることです。 ソートしたら、k 番目の位置に直接インデックスを付けます。 

これが機能するのは、並べ替えにより、好みを定義するまったく同じ比較ルールに従って、すべての項目がグローバルに順序付けされるためです。 並べ替え後、最初の k 項目を削除することは、概念的には、それらを無視して次の項目を取得することと同じです。 

ブルートフォースの代替方法は、リストを繰り返しスキャンして現在の最大値を見つけ、それを削除し、これを k + 1 回繰り返すことです。 各スキャンのコストは O(n) で、k 回実行すると O(nk) になり、最悪の場合は O(n²) になります。 n が最大 10⁵ であるため、これは実現可能な限界をはるかに超えています。 

重要な点は、動的削除が必要ないということです。 最終的なランキングは 1 回だけ必要です。 これにより、問題は静的な順序付けの問題に変わります。これは、まさに並べ替えによって効率的に解決されるものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返し最大抽出 | O(n²) | お(1) | 遅すぎる |
 | 値で並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての曲を (人気、名前) のペアとしてリストに読み込みます。 これにより、ランキングキーと出力する必要がある識別子の両方が保存されます。 
2. リストを人気の降順に並べ替えます。 これにより、最初の要素が最も望まれている曲となり、次の各要素が前の要素よりも厳密に望ましくないというグローバル ランキングが作成されます。 人気の一意性により、結びつきがないことが保証されるため、順序は決定的になります。 
3. すでに取得されている上位の曲の数を表す整数 k を読み取ります。 
4. ソートされたリストのインデックス k の要素に直接アクセスします。 これは、1 ベースのランキングで (k + 1) 番目に人気のある曲に相当します。 
5. その要素に関連付けられた名前を出力します。 

### なぜ効果があるのか

 ソート後のリストは、人気が高い順に曲を合計した順になります。 人気の値はすべて異なるため、この順序は厳密で安定しています。 上位 k 個の要素を削除しても、残りの要素の相対的な順序は変更されないため、最初に残った要素は、ゼロベースのインデックス付けでは正確に k 番目のインデックスになります。 このアルゴリズムは中間の更新や削除に依存しないため、状態の破損や並べ替えは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    songs = []
    
    for _ in range(n):
        w, s = input().split()
        w = int(w)
        songs.append((w, s))
    
    k = int(input())
    
    songs.sort(reverse=True)
    
    print(songs[k][1])

if __name__ == "__main__":
    solve()
```実装の中核はソート呼び出しです。これは、次の理由により、最初の要素によってタプルを降順に並べ替えます。`reverse=True`。 Python はタプルを辞書順に比較するため、名前は 2 次キーとしてのみ使用されますが、重みは一意であることが保証されているため、問題にはなりません。 

直接インデックス作成`songs[k]`k は 0 ≤ k < n を満たすことが保証されているため、これは安全です。 入力制約を信頼すること以外に境界チェックは必要ありません。

 ## 特殊なケース

 k が 0 の場合、アルゴリズムはソート後の最初の要素を直接返します。 たとえば、次の入力を使用します。```
3
5 A
2 B
9 C
0
```ソートすると、(9, C)、(5, A)、(2, B) が得られます。 インデックス 0 は C ですが、どの曲も使用されていないとみなされるため、これは正しいです。 

k が n − 1 に等しい場合、最小の要素のみが残ります。 入力の場合:```
3
5 A
2 B
9 C
2
```ソートされたリストは (9, C)、(5, A)、(2, B) です。 インデックス 2 は (2, B) で、上位 2 曲を削除した後に最後に残った選択肢です。 

アルゴリズムは並べ替え後にリストを変更しないため、これらのエッジケースには特別な処理は必要ありません。 同じインデックス付けルールが、k のすべての有効な値に一貫して適用されます。
