 ## 問題の理解

 の行が与えられています`n`セル、最初はすべて白です。 弊社では塗装工事を2件行っております。 最初の操作はペイントします`a`連続するセルは赤、任意の位置から開始`x`赤いブロックが行内に完全に収まるようにします。 2回目のペイント操作`b`連続するセルは青色、任意の位置から開始`y`、また行内に収まるように制約されます。 セルを赤で塗ってから青で塗ると、最終的には青になります。 両方の操作の後、すべてのセルについて、結果の色付けが対称になる可能性があるかどうかを知りたいと考えます。`i`、その色は位置のセルの色と一致します。`n+1-i`。 

入力は複数のテスト ケースで構成され、それぞれが指定します`n`、`a`、 そして`b`。 次の選択肢がある場合、出力は「YES」です。`x`そして`y`対称的なカラーリングが生成され、それ以外の場合は「NO」になります。 

境界はかなり大きいです:`n`最大 10^9 にすることができ、`t`これにより、長さの配列を明示的に構築するソリューションは即座に除外されます。`n`なぜなら、単一のテスト ケースでもメモリ制限を超える可能性があり、すべての位置を反復処理すると遅すぎるためです。 解決策はシミュレーションではなく算術推論に依存する必要があります。 

エッジケースは、ブロックが相対的に極端な長さを占める場合に発生します。`n`。 たとえば、次の場合`a`または`b`等しい`n`、絵は列全体を覆っています。 の小さな値`a`または`b`適切に中心に配置できれば、対称性を維持できる可能性があります。 赤と青の重なりと、赤に対する青の優先順位が組み合わされて、慎重に配置しないと非対称が生じる可能性があります。 たとえば、`n = 3, a = 2, b = 1`、赤いブロックはセル 1 ～ 2 をカバーし、単一の青色のセルは 1 つのセルのみをカバーできます。 青いセルを中央のセルに配置すると、対称が可能になります。 それ以外の場所に配置すると、対称性が崩れる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効な位置を試行しようとします。`x`そして`y`、ペイントをシミュレートし、結果の配列が対称かどうかを確認します。 のために`x`、 がある`n-a+1`オプション、および`y`がある`n-b+1`オプション。 対称性をチェックする`O(n)`。 したがって、最悪の場合の操作数は次のようになります。`(n-a+1)*(n-b+1)*O(n)`。 以来`n`10^9 にすることもできますが、これは実行不可能です。 

重要な洞察は、対称性は長さのみに依存するということです。`a`そして`b`、実際の位置ではありません`x`そして`y`。 赤いブロックの長さの場合`a`と青いブロックの長さ`b`満足する`a + b <= n + 1`, 赤と青のブロックを中心を中心に対称に配置することが常に可能です。 青のブロックが行の半分より長い場合は、赤のブロックが上書きされるため、対称性が支配的になります。 最終的なカラーリングを対称にする能力を捉える条件は、次のことをチェックすることを簡素化します。`a + b <= n + 1`。 これは、必要に応じて赤いブロックを左端近くから開始し、青いブロックを右端近くから開始することができ、青が赤をオーバーライドすることで重複を解決できるためです。 もし`a + b > n + 1`、非対称を避けるにはブロックが長すぎるため、対称が不可能になります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、整数を読み取ります。`n`、`a`、 そして`b`。 
3. 次のことを確認します。`a + b <= n + 1`。 この条件により、青のブロックが意図した長さを完全にカバーしながら対称性を崩さないように、赤と青のブロックを配置できることが保証されます。 直感的に合計すると、`a+b`これらのブロックが占めるセルの総数を表します。`n+1`奇数および偶数長の行の対称ピボットを考慮します。 
4. 条件が真の場合、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

なぜ機能するのか: 不変条件は次のとおりです。`a + b <= n + 1`、いつでも赤いブロックをインデックス 1 から開始し、青いブロックをインデックスで終了するように配置できます。`n`、必要に応じて青が赤を上書きして、左右のミラーリングされたセルの色が一致するようにします。 もし`a + b > n + 1`、どのような配置でも、片面の青または赤がミラーよりも多くなり、対称性が崩れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b = map(int, input().split())
    if a + b <= n + 1:
        print("YES")
    else:
        print("NO")
```最大 500 個のテスト ケースがあるため、ソリューションは高速 I/O を使用して入力を読み取ります。 各テスト ケースの単純な算術条件を評価し、結果をすぐに出力します。 配列の構築は必要ないため、大規模なメモリの問題を回避できます。`n`。 また、コードが単純であるため、ブロック長の観点から直接推論するため、インデックス作成時の off-by-one エラーも回避されます。 

## 実用的な例

 検討してください`n = 5, a = 3, b = 1`。 合計`a + b = 4`そして`n + 1 = 6`。 以来`4 <= 6`、答えは「YES」です。 赤いブロックを 2 ～ 4 の位置に、青いブロックを 3 の位置に配置できます。行は次のとおりです。`[white, red, blue, red, white]`、青が赤をオーバーライドした後は対称になります。 

のために`n = 7, a = 7, b = 4`、 我々は持っています`a + b = 11`そして`n + 1 = 8`。 以来`11 > 8`、対称性は不可能です。 長さ 7 の赤いブロックと長さ 4 の青のブロックをどのように配置しても、左半分と右半分は不均等になります。 アルゴリズムは正しく「NO」を返します。

 これらのトレースは、合計の比較によって対称配置の実現可能性がどのように直接的に把握されるかを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        print("YES" if a + b <= n + 1 else "NO")
    return out.getvalue().strip()
