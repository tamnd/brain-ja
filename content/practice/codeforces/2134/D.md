 ## 解決策
 ## 問題の理解

 ツリーと非常に具体的なローカル再配線操作が与えられています。 操作により頂点が選択されます$b$二人の著名な隣人と$a$そして$c$。 その後、他のすべての隣人は、$b$から切り離されています$b$そして再び取り付けられました$c$。 直感的には、次の隣人の 1 人は、$b$残りのすべてのサブツリーを吸収する新しいハブになります。$b$、 その間$b$2 つの入射エッジを除いてすべてが失われます。 

目標は、ツリーをパスに変換することです。つまり、すべての頂点の次数は最大 2 になります。 変換全体をシミュレートするように求められるわけではありません。 代わりに、最適なシーケンスの最初の操作を出力するか、ツリーがすでにパスである場合は操作が必要ないことを報告する必要があります。 

制約$n \le 2 \cdot 10^5$テスト全体にわたるということは、テスト ケースごとにソリューションが線形またはほぼ線形である必要があることを意味します。 操作のグローバル シミュレーションを繰り返したり、頂点のトリプルをすべて試したりすることは、直ちに実行不可能になります。 操作自体は一度に多くのエッジを変更するため、単純なシミュレーションではすでにステップあたりのコストが高くつき、最悪の場合の変換のステップ数は総当たりできるほど小さくありません。 

重要な構造上の観察は、ツリーが 1 より大きい次数の頂点を最大 2 つ持っている場合、そのツリーはすでにパスであるということです。 実際には、これは、パスの終点を除くすべてのノードの次数が最大 2 であることを意味します。 

いくつかの危険な状況は、素朴にアプローチすると間違いやすいものです。 よくある間違いは、高次のノードを選択して貪欲に折りたたむと常に最適な最初の動きが得られると想定することです。 この操作は接続性を維持しますが、他の場所の分岐ノードの数を増減する方法で次数を再分配できるため、これは失敗します。 

たとえば、中心が 1 で、隣接する星が 2、3、4、5 であると考えてください。これは明らかにパスではありません。 選ぶような不用意な選択$b = 1$そして任意の$a, c$は有効ですが、選択を誤ると、残りの操作の数を最小限に抑えることができない可能性があります。 正しい戦略では、最初の手が構造的に意味のある「分岐点」を確実にターゲットにする必要があります。 

## アプローチ

 ブルートフォースの観点では、すべての有効なトリプルが試行されます。$(a, b, c)$、スライディング操作をシミュレートし、パスに到達するために必要な最小操作数を再帰的に計算します。 各操作はすでに変更される可能性があるため、これは直ちに実行不可能です。$\Theta(n)$エッジがあり、状態の数は組み合わせ的に増加します。 最初の動きだけを探索する場合でも、$O(n \cdot d_b^2)$すべての頂点にわたってチェックします。これは、密な分岐の場合は 2 次です。 

重要な構造的洞察は、答えが長い操作シーケンスではなく、ツリーのグローバルな分岐構造のみに依存するということです。 スライド操作は基本的に、頂点を中心とした「ブランチ圧縮」です。$b$。 問題のある高次の頂点の数を減らすのは、次の場合に限られます。$b$は、パス構造とまだ互換性のない分岐ノードです。 

ツリーがすでにパスである場合、操作は必要ありません。 それ以外の場合、次数が 3 以上の頂点が少なくとも 1 つ存在します。最適な最初の移動では、次のような頂点を選択する必要があります。$b$なぜなら、分岐頂点だけが構造の複雑さを有意義に軽減できるからです。 

高次の頂点を選択したら$b$、選びたい。$a$そして$c$2つの異なる隣人として$b$。 残りの隣人は、$b$に移行します$c$、分岐構造を効果的に再分配します。 重要な観察は、必要な有効な最適な最初の移動は 1 つだけであり、分岐ノードの 2 つの異なる隣接ノードを選択すると、最適な開始が得られるということです。これは、すべての最適な戦略が最初に分岐頂点を解決することから始まるためです。 

したがって、問題は、次数が少なくとも 3 の頂点を見つけて、それを 2 つの異なる近傍とともに出力することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 隣接リストからすべての頂点の次数を計算します。 これにより、ツリー内のすべての分岐点が識別されます。 
2. すべての頂点の次数が最大 2 の場合、ツリーはすでにパスであるため、出力$-1$。 この条件はパス構造にとって必要かつ十分です。 
3. それ以外の場合は、任意の頂点を検索します。$b$そのような$\deg(b) \ge 3$。 この頂点は、ツリーがパスから外れる最初の点です。 
4. 任意の 2 つの異なる近傍を選択します$a$そして$c$の$b$。 これら 2 つの頂点は、周囲の「保持された構造」を定義します。$b$、他のすべての近隣ノードは に転送されます。$c$操作によって。 
5. 出力$(a, b, c)$。 

複数の選択肢の中からさらに最適化を行わない理由は、この問題では、最適なシーケンスに属する最初の動きのみが必要であるためです。 少なくとも 1 つの有効な分岐頂点が存在することで、実現可能性が保証されます。 

### なぜ効果があるのか

 ツリーに分岐頂点がない場合、ツリーはまさにパスです。 少なくとも 3 次の頂点は非パス構造の証明書です。 スライディング操作は、次数 2 の頂点に適用しても分岐の複雑さが軽減されず、次数 1 の頂点では無効であるため、このような頂点に適用された場合にのみ意味のある効果を持ちます。 

すべての最適なシーケンスは、分岐頂点をアドレス指定することから開始する必要があります。これは、少なくとも 1 つの分岐頂点が変更されるまで、ツリーはパス構成に近づくことができないためです。 任意の分岐頂点とその隣接頂点の任意の 2 つを選択すると、操作によって結果のグラフがツリーのままであることが保証され、その頂点でのエッジの集中が軽減されるため、正確さが保たれます。 

したがって、有効な値を返す$(a, b, c)$次数が少なくとも 3 のノードを中心とすることは、最適な最初のステップと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    if n == 1:
        print(-1)
        continue

    b = -1
    for i in range(1, n + 1):
        if len(adj[i]) >= 3:
            b = i
            break

    if b == -1:
        print(-1)
    else:
        a = adj[b][0]
        c = adj[b][1]
        print(a, b, c)
```このソリューションは、線形時間で隣接リストを構築します。 次に、次数が少なくとも 3 の頂点をスキャンします。 何も存在しない場合、ツリーはすでにパスであるため、出力します。$-1$。 

有効な分岐ノードが見つかったら、その最初の 2 つの隣接ノードを安全に次のように取得します。$a$そして$c$。 順序は、両方が明確に隣接する必要があるという意味でのみ重要です。 操作定義は隣接関係を超える制約を課さないため、どのペアでも機能します。$b$。 

微妙な点は扱い方$n=1$。 この場合、グラフは単なるパスであり、操作は存在しません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        b = -1
        for i in range(1, n + 1):
            if len(adj[i]) >= 3:
                b = i
                break

        if b == -1:
            out.append("-1")
        else:
            a = adj[b][0]
            c = adj[b][1]
            out.append(f"{a} {b} {c}")

    return "\n".join(out)

 ## 特殊なケース

 単一の頂点入力にはエッジがなく、すでにパスになっています。 アルゴリズムチェック$n=1$次数 ≥ 3 ノードが存在しないことにより暗黙的に、正しく出力されます。$-1$。

スター グラフでは、すべての度数が 1 つのノードに集中します。 アルゴリズムは即座にそのノードを次のノードとして選択します。$b$そして、2 つの任意の近傍を出力します。これは、操作定義ではすべての近傍が同等であるため有効です。 

複数の分岐ノードがあるツリーでも、最初の移動にはいずれか 1 つで十分であるため、機能します。 この問題では標準的なシーケンスではなく、1 つの最適な最初のステップのみが求められるため、正確さはどの分岐頂点が選択されるかには依存しません。
