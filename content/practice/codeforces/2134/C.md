 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられているので、最小限の操作を実行してそれを「良好」にする必要があります。 少なくとも 2 の長さのすべての部分配列について、偶数のインデックス (元の配列の 1 から数えて) の要素の合計が奇数のインデックスの要素の合計と少なくとも同じであれば、配列は良好です。 1 つの操作は、負でない限り、任意の要素を 1 つ減らすことで構成されます。 

入力は複数のテスト ケースで構成され、それぞれに最大の配列が含まれます。$2 \cdot 10^5$要素。 すべてのテスト ケースの要素の総数は次の制限を受けます。$2 \cdot 10^5$、各要素の大きさは次のようになります。$10^9$。 2 秒の時間制限により、すべてのサブ配列を検査するブルートフォース ソリューションが除外されます。$n$-要素配列は$\frac{n(n+1)}{2}$、到達できる$2 \cdot 10^{10}$最悪の場合。 線形または線形算術による解が必要です。$n$テストケースごとに。 

重要なエッジ ケースは、奇数インデックスの要素が周囲の偶数インデックスの要素より大きいためにサブ配列が条件に違反する場合に発生します。 たとえば、配列$[0,2,4,1]$サブアレイなので良くありません$[2,4,1]$偶数のインデックス合計を持つ$2+1=3$と奇数インデックスの合計$4$。 最初の 2 つの要素が条件を満たしているため、隣接するペアのみを調べる単純なアプローチでは、この配列が良好であると誤って報告されてしまいます。 

もう 1 つの微妙な点は、複数の大きな奇数インデックス要素が、その前の偶数インデックス要素の累積和によってバッファリングされる可能性があるため、すべての部分配列に対して明示的に反復処理を行わずに、これらの制約を効率的に伝播する方法が必要であることです。 

## アプローチ

 ブルートフォースアプローチは、少なくとも 2 の長さのすべてのサブ配列をチェックし、奇数のインデックスが付いた要素の合計が偶数のインデックスが付いた要素の合計を超える場合は常に、条件が満たされるまで奇数の位置にある要素をデクリメントすることです。 これは原理的には正しいですが、サブ配列の数は二次関数的に増加するため、大規模なシステムでは完全に非現実的になります。$n$。 
最適な解決策につながる洞察は、偶数インデックスと奇数インデックスの配列の _ 接頭辞の合計 _ に個別に焦点を当てることです。 させて`even[i]`そして`odd[i]`インデックスまでの偶数位置と奇数位置にある要素の接頭辞の合計になります。`i`。 部分配列の条件$[l, r]$それなら`even[r] - even[l-1] >= odd[r] - odd[l-1]`。 並べ替えると`odd[r] - even[r] <= odd[l-1] - even[l-1]`。 これは、奇数から偶数のプレフィックス合計の最大差を追跡する必要があるだけであり、現在の差がその最大を超えるたびに、それを下げるために十分なデクリメントを実行する必要があることを示しています。 

したがって、最適な解決策は、累積和の差を維持しながら配列を 1 回反復し、現在の差が最小許容差を超えるたびに演算数を更新することになります。 これにより、テスト ケースごとに O(n) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの変数を初期化します。`even_sum`そして`odd_sum`、配列を走査するときに偶数および奇数のインデックスでの累積合計を追跡します。 初期化もする`min_ops`ゼロにすると、必要な操作の合計が累積されます。 
2. インデックスによって配列を反復処理します。 インデックスが偶数 (1 から始まるインデックス) の場合、要素を`even_sum`。 それ以外の場合は、に追加します`odd_sum`。 
3. 各ステップで、電流の差を計算します。`odd_sum - even_sum`。 これは、この時点までに奇数要素の合計が偶数要素の合計をどれだけ超えているかを表します。 
4. もし`odd_sum - even_sum > 0`、先頭から始まるサブ配列の「良好な」条件に違反します。 インクリメント`min_ops`この差を調整して`odd_sum`同じ金額を引くことによって。 これは、状態を復元するのに十分なだけ奇数のインデックスが付いた要素を減らすことをシミュレートします。 
5. 最後まで配列の反復処理を続けます。 ループ後は、`min_ops`配列を良好にするために必要な最小限のデクリメント数が含まれています。 
6. 出力`min_ops`現在のテストケースの場合。 

機能する理由: 重要な不変条件は、各反復後に配列のすべてのプレフィックスが「良好な」条件を満たすことです。 必要な調整のみを前方に伝播することにより、現在のインデックスで終わるすべてのサブ配列が有効であることが保証されます。 不変式を復元するために常に必要な最小量を減分するため、解は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        min_ops = 0
        even_sum = 0
        odd_sum = 0
        for i in range(n):
            if (i+1) % 2 == 0:
                even_sum += a[i]
            else:
                odd_sum += a[i]
            diff = odd_sum - even_sum
            if diff > 0:
                min_ops += diff
                odd_sum -= diff
        print(min_ops)

if __name__ == "__main__":
    solve()
```このソリューションでは、`even_sum`そして`odd_sum`1 ベースのインデックス ルールに従ってプレフィックスの合計を蓄積します。 変数`diff`奇数の合計が偶数の合計をどれだけ超えているかを測定します。 いつでも`diff`が正の場合、それを追加します`min_ops`そして減少します`odd_sum`不変を保つため。 プレフィックス合計を使用すると、すべての部分配列をチェックする二次コストが回避されます。
