 ## 解決策
 ## 問題の理解

 ラテン文字の小文字で構成される文字列が与えられます。 少なくとも一定の長さの単一の連続ブロックに何らかの文字が出現すると、その文字列は「不良」になります。`m`。 私たちの目標は、同一文字のすべての最大ブロックの長さが厳密に以下になるように文字列を変換することです。`m`。 

2 種類の編集が許可されています。 コスト 1 の文字を削除すると、文字列が縮小され、残りの部分が結合されます。 コストに応じて任意の位置に任意の文字を挿入することもできます`k`、長いブロックを別の文字で分割することで分割するために使用できます。 

タスクは、文字列を「良好」にするための最小総コストを計算することです。つまり、同じ文字の連続が長さに達しないことを意味します。`m`。 

この制約により、文字列の長さは最大 200,000 まで許可され、部分文字列に対する 2 次または 3 次動的計画法が即座に除外されます。 テストごとにリニアスキャンまたはリニアに近いスキャンが必要です。 

重要な点は、操作によって構造がローカルに変更される可能性があることです。 ブロック内で削除するとブロックの長さが直接短縮されますが、挿入すると文字を削除せずにブロックを複数の小さなブロックに分割できます。 分割と削除を考慮せずに各ブロックを個別に調べるだけの単純な貪欲な戦略は失敗する可能性があります。 

一般的な失敗例は、長いブロックが制限をわずかに超えている場合に発生します。 たとえば、次の場合`m = 4`ブロックの長さは 7 で、3 文字を削除するとコストは 3 になりますが、代わりに 1 文字を挿入して長さ 3 と 4 の 2 つのブロックに分割することは無効です。2 番目のブロックはまだ制限に違反しているためです。 これは、結果として得られるすべてのセグメントが制約を遵守する場合にのみ分割が機能することを示しています。 

実際の決定はブロックごとに行われます。削除してサイズを減らすか、すべての文字を保持して区切り文字を挿入して有効なセグメントに分割します。 

## アプローチ

 構造を無視して、文字列全体に挿入と削除を適用するあらゆる方法を試みると、すぐに指数関数的な爆発に見舞われます。 同一の文字からなる単一の連続ブロックに限定しても、削除と挿入のすべての組み合わせを試してみると、多くの可能性の中から最終的な構成を選択することになり、ブロック間のグローバルな相互作用が問題をさらに悪化させます。 

重要な観察は、文字列が自然に等しい文字の最大セグメントに分解され、1 つのセグメント内の操作が他のセグメントに有益な影響を与えないことです。 異なる文字がより長い有効なランにマージされることはありません。これは、マージは同一の文字が隣接する場合にのみ発生し、別個の初期ブロック間では発生しないためです。 

したがって、各最大ブロックは独立して最適化できます。 

ある長さのブロックを考えます`L`。 それぞれのサイズが最大のブロックのシーケンスで終了したいと考えています。`m-1`。 私たちには 2 つの自然な戦略があります。 1 つは、ブロック自体が有効になるまで文字を削除し、料金を支払う方法です。`L - (m-1)`もし`L >= m`。 もう 1 つは、ブロックがいくつかの有効なチャンクに分割されるように、すべての文字を保持し、区切り文字を挿入することです。 に分かれたら`t`チャンクが必要です`t-1`挿入回数と各挿入コスト`k`。 拘束力`t = ceil(L / (m-1))`。 

これですでに有力な答えの候補が得られます。 微妙な点は、削除と挿入の中間的な混合も存在しますが、それらは小さなケース群に分類されるということです。`q`セグメントの場合、私たちができる最善のことは、できるだけ多くの元の文字を保持することです。つまり、正確に保持しながら削除を最小限に抑えることを意味します。`q`セグメント。 これにより、セグメント数に関する直接的な計算式が得られます。 

## アルゴリズムのチュートリアル

 連続する等しい文字をグループ化することで文字列を処理します。 

長さのブロックごとに`L`、最小コストを独自に計算します。 

1. 何も削除しない場合に必要なセグメントの数を計算します。 これは`q = ceil(L / (m - 1))`。 すべての文字を保持すると、次のように分割する必要があります。`q`有効なチャンク。 費用は`(q - 1) * k`。 
2. ブロックが分割されずに有効になるように文字を削除するコストを計算します。 最大でも最終的な長さが必要です`m - 1`、したがってコストは`max(0, L - (m - 1))`。 
3. 必要に応じて、中間の分割レベルを検討します。 固定数のセグメントの場合`q`、私たちができる最善のことは、せいぜい維持することです`q * (m - 1)`文字なので削除は`L - min(L, q * (m - 1))`、および挿入は`(q - 1) * k`。 
4. 可能な限り最小値を取る`q`価値観。 実際に繰り返すと、`q`1から`ceil(L / (m - 1))`で十分です。 
5. すべてのブロックにわたるこれらの最小コストを合計します。 

最終的な答えは合計です。 

この分解が機能する理由は、ブロックに影響を与えるすべての操作はそのブロックの内部セグメンテーションのみを変更し、どの操作も異なる文字にまたがる新しい長いランを作成できないため、ブロックは独立しているためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1

        L = j - i
        lim = m - 1

        # case 1: pure deletions to make single valid block
        best = max(0, L - lim)

        # case 2: splitting into q segments with insertions
        q = 1
        while (q - 1) * lim < L:
            kept = min(L, q * lim)
            cost = (L - kept) + (q - 1) * k
            best = min(best, cost)
            q += 1

        ans += best
        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず 2 つのポインターを使用してスキャンすることにより、文字列をランに圧縮します。 実行ごとに、その長さを計算し、考えられるコストを評価します。 

変数`best`純粋な削除戦略から始まります。これは実行がしきい値未満に縮小することが保証されるため、常に有効です。 次に、可能な数のセグメントを反復処理します。`q`。 それぞれについて`q`では、セグメント制限を尊重しながら保持できる文字数を計算し、分割のための挿入コストと余分な文字をトリミングするための削除コストの両方を支払います。 

ループオーバー`q`一度なので制限されています`q * (m - 1)`を超える`L`、意味のあるセグメント数はすべてすでにカバーしました。

 ## 特殊なケース

 主なエッジケースは、ブロック長が正確に次の倍数である場合です。`m-1`。 この場合、分割はクリーンであり、削除は必要なく、挿入のみが必要です。 アルゴリズムは正しく評価します`q = L / (m-1)`そしてコストを割り当てます`(q-1)*k`、均等に分割されたセグメントの最適な構造と一致します。 

もう一つのケースは次のような場合です。`k`非常に大きいです。 その場合、挿入は常に悪化し、アルゴリズムは自然に削除のみのオプションを選択します。`best`から始まります`L - (m-1)`挿入コストは増加するにつれて増加します`k`。 

最後の微妙なケースは非常に小さいです`m`、 特に`m = 2`、隣接するすべての重複が禁止されます。 ここ`m-1 = 1`したがって、すべてのブロックを完全に分離するか、単一の文字に減らす必要があります。 このアルゴリズムは、ブロックごとに 1 文字を除くすべての文字を削除するか、すべてのペアの間に区切り文字を挿入するかのいずれかに正しく縮退し、実行ごとに常に最小値が一貫して選択されます。
