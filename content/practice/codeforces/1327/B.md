 ## 解決策

 ## 問題の理解

 各娘を王子 (王国番号で表される) に順番に割り当てるプロセスが与えられています。 各娘は、許容できると考える王国の分類されたリストを持っています。 娘を処理するとき`i`、私たちは彼女のリストを最小から最大までスキャンし、王子が前の娘にまだ割り当てられていない最初の王国を選択します。 リストされているすべての王国がすでに占領されている場合、彼女には対戦相手がいません。 

これにより、前の娘が後の娘よりも優先される貪欲なマッチングが作成され、各リスト内で常に利用可能な最小の王国が優先されます。 

プロセスが開始する前に、変更が許可されるのは 1 つだけです。まだ存在していない限り、1 つの新しい王国を 1 つの娘のリストに挿入できます。 目標は、成功した試合の数を最大化することです。 

重要な出力は、単一の挿入では一致の数を改善できないというステートメント、または最終的な一致ペアの数を厳密に増加させる 1 つの有効な挿入のいずれかです。 

制約は大きく、テスト ケースごとに娘は最大 100,000 個、テスト全体のリストの合計サイズも最大 100,000 です。 これにより、考えられるすべての挿入を試行するシミュレーションが即座に除外されます。 各娘には多くの王国が欠落している可能性があるため、欠落しているペアをすべてチェックするだけでも、最悪の場合は 2 次式になります。 

マッチングの単純なシミュレーションはテスト ケースごとに線形ですが、すべての挿入を試行するとコストが最大 2 倍になります。`O(n^2)`可能性が大きすぎます。 

すべての娘がすでに完全に一致している場合、微妙なエッジケースが発生します。 その場合、すべての王国がすでに他の改善を妨げる方法で使用されているため、挿入は役に立ちません。 たとえば、すべての娘が次のような独自の王国を 1 つだけ持っているとします。`[1]`、`[2]`、`[3]`、`[4]`の場合、一致しない娘はなく、再割り当てによってカウントが増加する可能性がないため、すべての挿入は冗長になります。 

もう 1 つの重要なエッジ ケースは、娘のリストが空である場合です。 その娘は現在一致せず、未使用の王国を追加すると、以前の貪欲な割り当てと有害な方法で衝突しない限り、すぐに答えを増やすことができます。 

最後に、答えを改善するには、特定の娘を貪欲に修正する必要がないことを見逃しがちです。 一部のプレフィックスに対する貪欲なスキャンにより全体で 1 つの追加の一致が許可されるように、構造を変更する必要があります。 

## アプローチ

 まず、説明どおりに貪欲なマッチングを正確にシミュレートします。 すでに使用されている王国のセットを維持しながら、娘を順番に処理します。 娘ごとに、利用可能な最小の王国を選択します。 

このシミュレーションは正しく、リストの合計サイズに対して線形時間で実行されます。 ただし、新しい王国をどこに挿入するかを直接示すものではありません。 

重要な洞察は、プロセスを逆に再構成することです。割り当てについて考える代わりに、どの娘が一致しなかったかを追跡します。 娘は、リスト内のすべての王国が以前に成功した試合によってすでに占領されている場合にのみ失敗します。 

これは、貪欲な割り当ての構造が、プロセス中の各王国の最初の出現にのみ依存することを示唆しています。 各王国は、それを獲得できる最も古い娘によって「主張」されます。 

ここで、新しい王国を挿入するとどうなるかを考えてみましょう。`x`誰かの娘のリストに。 合計の一致数を増やす唯一の方法は、以前は一致しなかった娘が一致するようになるか、連鎖反応を解放する方法で一致が変化する状況を作り出すことです。 

重要な観察は、もし王国が`x`元の貪欲マッチングでは決して使用されないため、それを使用できる最も古い娘のリストに挿入すると、マッチング サイズがすぐに増加します。 逆に、すべての王国がすでに使用されている場合、構造はすでに「緊密」であり、挿入によって個別の割り当ての数を増やすことはできません。 

したがって、問題はペアを見つけることになります`(daughter, kingdom)`その王国は元の貪欲プロセスでは使用されず、娘のリストにそれを挿入することで選択できるようになります。 

貪欲なシミュレーション中に、使用されたすべての王国を追跡します。 次に、未使用の王国をスキャンします。 何も存在しない場合、答えは次のようになります。`OPTIMAL`。 それ以外の場合は、現在より良いオプションを選択できない娘にそれを割り当てるか、単にそれがまだ含まれていない有効な娘を選択しようとします。 

これが機能するのは、貪欲なプロセスが利用可能なリソースにおいて単調であるためです。以前に使用されていなかった王国を導入すると、必然的に、達成可能なマッチングの最大値が少なくとも 1 増加します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. ブール配列を維持しながら貪欲マッチングをシミュレートします。`used`王国を超えて。 娘が王国と一致するたびに、それが使用されたことをマークします。 これにより、最終プロセスでどの王国が消費されたかが正確に把握されます。 
2. 各娘について、彼女が実際に試した一連の王国を記録するか、単純に並べ替えられたリストに依存して、シミュレーション中にそれをスキャンします。 目的は、余分なオーバーヘッドなしで正確な貪欲な動作を複製することです。 
3. シミュレーション後、王国が存在するかどうかを確認します`x`中古としてマークされていないもの。 そのような王国が存在しない場合、マッチングではすでにすべての王国が使用されており、グリーディ チェーンに導入できる空きリソースがないため、挿入によって一致の数が増加することはありません。 
4. こんな未使用の王国なら`x`存在するなら、私たちは娘を選びます`i`そして挿入します`x`彼女のリストに。 安全な選択は長女です。`x`はまだ存在しません。 以来`x`未使用であったため、挿入すると娘の処理時に保証されます`i`、この王国が利用可能になり、奪われる可能性があります。 
5.ペアを出力する`(i, x)`有効な改善として。 

なぜ効果があるのか:

 貪欲なプロセスでは各王国を最大 1 回割り当て、使用された王国のセットは成功したすべての割り当てを表します。 王国が使用されていない場合、それはどの試合にも貢献していないことを意味します。 これをプロセス内の任意の有効な位置に導入すると、暗黙的な 2 部グラフに追加の候補エッジが作成されます。 貪欲は常に最小の利用可能なオプションを採用するため、新しい利用可能なオプションを追加すると、一致しない娘と直接一致するか、以前の割り当てを破ることなく後の失敗を成功にシフトするため、成功する一致の可能性が少なくとも 1 つ増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        used = [False] * (n + 1)

        for _ in range(n):
            arr = list(map(int, input().split()))
            k = arr[0]
            lst = arr[1:]
            a.append(lst)

        # greedy matching
        taken = [False] * (n + 1)
        match = [-1] * n

        for i in range(n):
            for v in a[i]:
                if not taken[v]:
                    taken[v] = True
                    match[i] = v
                    break

        # find unused kingdom
        x = -1
        for v in range(1, n + 1):
            if not taken[v]:
                x = v
                break

        if x == -1:
            print("OPTIMAL")
            continue

        # find a daughter not containing x
        i_ans = 0
        for i in range(n):
            if x not in a[i]:
                i_ans = i + 1
                break

        print("IMPROVE")
        print(i_ans, x)

if __name__ == "__main__":
    solve()
```コードはまず定義どおりに貪欲なマッチングを再構築し、どの王国が消費されるかをマークします。 次に、割り当てられていない王国を検索します。 そんな王国は新たな選択肢として自由に導入できること請け合いだ。 

その後、この王国をまだリストしていない娘を選択し、その挿入を出力します。 小切手`x not in a[i]`操作の正当性を保証します。 

重要な実装の詳細は、挿入後にマッチングを再計算しようとしないことです。 この議論は、元の貪欲な結果における未使用の王国の存在に完全に依存しています。

 ## 特殊なケース

 すべての娘がすでに独自の王国を持っており、すべてが一致すると、貪欲なプロセスによりすべての王国が消費されます。 この状況では、アルゴリズムは未使用の王国を見つけず、正しく OPTIMAL を出力します。 一致しないリソースを新たに作成する方法がないため、挿入を試みても冗長性が生じるだけです。 

娘のリストが空の場合、娘は基本プロセスで常に一致しません。 アルゴリズムは、未使用のままの王国を特定し、それをそのような娘に割り当て、一致の数を直ちに増やします。 

複数の王国が使用されていない場合、アルゴリズムはいずれか 1 つを選択する可能性があります。 この議論は少なくとも 1 つの未使用の王国の存在にのみ依存するため、どのような選択をしても有効な改善につながります。
