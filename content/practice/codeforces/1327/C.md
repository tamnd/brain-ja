 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$セル上にいくつかのチップが配置されています。 各チップは、上、下、左、または右の 4 つの方向のいずれかに 1 つのグローバル移動を適用することで、他のチップと同時に移動できます。 移動すると、すべてのチップがその方向に 1 セルずつ移動します。ただし、チップがすでに境界上にあり、外側に移動する場合は除きます。この場合、チップは単にその位置に留まり、他のチップはまだ移動します。 

各チップには、このチップが一連のグローバル移動中に少なくとも 1 回訪問する必要があるターゲット セルも与えられます。 チップの動きは区別できませんが、それぞれのチップには、その特定のチップの軌道が通過する必要がある独自の「チェックポイント」セルがあります。 

出力は最大でも次のシーケンスです。$2nm$移動、またはそのようなシーケンスが存在しないという宣言。 

重要な問題は、すべてのチップが同じ移動シーケンスを共有しているため、各チップを独立して配線していないことです。 代わりに、すべてのチップが割り当てられたターゲットを一度に通過することを保証する、グリッド全体の単一ウォークを設計しようとしています。 

制約は小さいです。$n, m, k \le 200$。 これは直ちに、次のような解決策が考えられることを示唆しています。$O(nm)$または$O(nmk)$推論は実行可能であり、二次関数は何でも可能です。$k$まだ受け入れられるかもしれない。 ただし、考えられるすべての移動シーケンスの単純なシミュレーションは指数関数的であり、不可能です。 

微妙な点は、境界の動作が重要であるということです。 端に詰まったチップはグローバルな動きに「遅れる」可能性があり、これはチップを個別に明示的に制御せずに効果的に再配置するパスを構築するために重要です。 

一般的な障害ケースは、各チップが独立してターゲットに配線できると想定した場合に発生します。 単一の動きはすべてのチップに同時に影響を与えるため、これは誤りです。 もう 1 つの間違いは、貪欲に各チップをターゲットに順番に移動させようとすることです。 以前のチップはすでに要件を満たしている可能性がありますが、慎重に構造化されていない場合、後の動きは進行状況の仮定を誤って無効にする可能性があります。 

## アプローチ

 強引なアイデアは、一連の動きを構築して、すべてのチップが最終的にターゲット セルを通過するかどうかをシミュレートすることです。 長さのシーケンスに制限しても$2nm$、分岐係数はステップごとに 4 であるため、検索空間は次のようになります。$4^{2nm}$、それはまったく実行不可能です。 

すべてのチップ位置の状態に対する BFS など、より構造化されたブルート フォースですら不可能です。これは、各状態がエンコードしているためです。$k$位置、サイズの状態空間を与える$(nm)^k$、やはり大きすぎます。 

重要な点は、チップを個別に制御する必要がないということです。 グリッドのグローバル スイープにより、制御された方法ですべての行または列を「カバー」でき、すべてのチップが基板の大部分を強制的に横断するようになります。 

自然なアイデアは、ある時点でグリッドのすべてのセルが「アクティブな境界」になることを保証し、まだターゲットに到達していないチップがそのターゲットと軌道が一致する構成を強制されるようにすることです。 このタイプの問題における標準的な建設的なトリックは、グリッドを行ごと、列ごとに繰り返しスイープすることです。 ヘビのような横断パターンで移動することで、構造化された方法でグローバル座標系がすべてのセルを訪問することを保証でき、チップは壁に対する相対的な変位により関連するすべての位置を強制的に通過します。 

中心となる洞察は、制御されたパターンでグリッド境界を完全に横断するだけで十分であるということです。グリッドを掃引する方向に繰り返しチップを押すことで、すべてのチップが最終的に到達可能な領域内のすべてのセルに到達することを保証できます。また、グリッドは有限であるため、必要なすべてのターゲット訪問を保証できます。$O(nm)$動きます。 

より正確な建設的な戦略は、下向きの遷移を伴う交互の右-左スイープを使用して、ハミルトン パスのような方法でグリッド全体を歩くことです。 これにより、すべてのセルが体系的な方法でグローバルな動きに「影響」されることが保証され、境界クリッピングによってチップの遅れが確実に確保され、カバレッジが普遍的になります。

 ## アルゴリズムのチュートリアル

 私たちは、ボードを系統的に一掃する決定的な動きのシーケンスを構築します。 

1. 概念的には左上隅から開始し、最初の行を完全に水平方向にスイープします。 右に進みます$m-1$回。 これにより、境界条件によってオーバーフローが防止されながら、すべてのチップが行全体に水平に押し込まれることが保証されます。 
2. 一度下に移動して、次の行に遷移します。 この下向きの動きにより、チップが既に最下位にある場合を除き、すべてのチップが下に移動します。その場合、チップは固定されたままとなり、下位の列に向けて制御された圧縮が行われます。 
3. を適用して 2 行目を右から左にスイープします。$m-1$左が動きます。 この交互方向は、冗長な発振を防止し、線形時間で完全なカバレッジを保証するため、不可欠です。 
4. すべての行に対してこのパターンを繰り返します。各行で水平方向に交互に移動し、行間に下向きの移動を挿入します。 
5. すべての行を完了した後、必要に応じて最終クリーンアップ スイープを実行し、最終行の位置合わせを確保します。ただし、構築されたパスはすでに完全なカバレッジを保証しています。 

直感的には、各行は交互のレイヤーを水平両方向に完全に移動し、垂直方向の移動によりすべての行を確実に移動できるようになります。 すべてのチップはグリッド構造上で完全な投影を経験することを強制されます。これは、スイープのある時点でその行内のすべてのセルを通過する必要があることを意味します。 

### なぜ効果があるのか

 不変条件は、各行スイープの完了後、すべてのチップがその行のすべてのセルをすでに訪問しているか、将来の行スイープに確実に参加できるように制御された方法で垂直方向にシフトされているかのいずれかであるということです。 水平方向のスイープは各行のすべての列位置をカバーし、垂直方向の移動はすべての行の進行を保証するため、すべてのチップがトラバーサル中のある時点でターゲット セルと一致することが保証されます。 最大でも制限された移動数$2nm$、行セグメントごとに 2 回の水平移動と、行境界ごとに 1 回の垂直遷移が続きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    for _ in range(k):
        input()
    for _ in range(k):
        input()

    res = []

    for i in range(n):
        if i % 2 == 0:
            res.append("R" * (m - 1))
        else:
            res.append("L" * (m - 1))
        if i != n - 1:
            res.append("D")

    ans = "".join(res)
    if len(ans) > 2 * n * m:
        print(-1)
    else:
        print(len(ans))
        print(ans)

if __name__ == "__main__":
    solve()
```構造は個々のチップの位置に依存しないため、コードは最初にチップ情報を読み取り、破棄します。 移動シーケンスは、水平方向に交互に行ごとに構築されます。 各行は正確に寄与します$m-1$移動し、最後の行の後を除いて、各トランジションは 1 つの下方向への移動に寄与します。 

丈チェックもさりげないポイントです。 工事保証は最大でも$n(m-1) + (n-1) \le 2nm$したがって、チェックは冗長ですが、安全のために含まれています。 

交互の方向が重要です。 これがなければ、境界近くのチップは対称カバレッジを経験せず、暗黙的なトラバーサル引数は失敗します。

 ## 特殊なケース

 1×1 グリッドは最も単純な境界です。 動きは必要ないため、アルゴリズムは空のシーケンスを生成します。 すべてのチップはすでにその唯一の可能なセルを占有しているため、要件は簡単に満たされます。 

1×m グリッドの場合、アルゴリズムは右方向の移動のみを生成します。 下向きの遷移がないため、シーケンスの長さは正確に$m-1$。 チップは行から離れることができず、完全なスイープにより、移動フレームがすべての列を訪問することが保証されます。 

n×1 グリッドの場合、この構造は下方への移動のみに退化します。 水平方向の動きは無関係であり、垂直方向のスイープは必要なすべての位置をカバーするため、各チップはすべての行を強制的に通過します。 

これらのケースでは、構造が動きの限界を破ることなく縮退次元で正しく折りたたまれることが確認されています。
