 ## 問題の理解

 概念的には、からのすべての整数を書き留めています。$0$に$10^n - 1$、ただし、各数値が正確になるように強制します$n$先頭にゼロを埋め込んで数字を並べます。 これにより、それぞれの長さの異なる数字列の巨大なマルチセットが作成されます。$n$、以下のすべての可能な数字の組み合わせをカバーします。$000\ldots0$に$999\ldots9$。 

任意の固定数の内部で、その数字シーケンスを同じ連続数字の最大セグメントに分割できます。 このような各セグメントはブロックと呼ばれ、その長さは値が変化する前に同じ数字が何個連続して出現するかを単純に表します。 

タスクは、個々の番号を直接検査することではありません。 代わりに、私たちはすべてを数えなければなりません$10^n$数値、長さのブロックの正確な数$i$あらゆる人に現れる$i$から$1$に$n$。 答えはモジュロで計算する必要があります$998244353$。 

制約$n \le 2 \cdot 10^5$すべての数値を反復したり、数値ごとに桁の遷移をシミュレートしたりするアプローチは直ちに除外されます。 明示的に構築または反復しようとするメソッド$10^n$文字列は無理です。 線形時間における数値ごとの推論でも、$O(n \cdot 10^n)$、それは天文学的な大きさです。 

単純な代替案は、ランダムな数字シーケンスを生成し、実行をカウントするという観点から考えることですが、それでも同じ指数関数的な爆発が隠されています。 問題の構造は、数値を列挙せずに位置単位またはブロック単位で推論し、寄与を集計する必要があることを示唆しています。 

すべての桁が等しい場合、微妙なエッジケースが発生します。たとえば、$000\ldots0$。 この場合、ちょうど 1 つの長さのブロックがあります。$n$、それより小さいブロックはありません。 このような場合、数値ごとに複数のブロックを想定する誤った分解戦略はオーバーカウントになります。 もう 1 つのデリケートなケースは、次のような数字を交互に使用する場合です。$010101\ldots$ここで、すべてのブロックの長さは 1 であり、ブロックの数は最大になりますが、サイズは最小になります。 これらの極端な結果は、ブロック長の分布が特定の数値ではなくランレングス構造のみに依存することを示唆しています。 

## アプローチ

重要な観察は、隣接する位置間の等しいか不等号を除いて、数字の値は無関係であるということです。 重要なのは、桁間の遷移がどこで発生するかです。 各位置は前のブロックを継続するか、新しいブロックを開始します。 これにより、問題は文字列の列挙から、隣接する位置間の等しいパターンの分析に軽減されます。 

この問題を、隣接する位置間のブレークポイントを選択することによって形成されたセグメントからの寄与をカウントするものとして再解釈します。 一定の長さのブロック$i$の最大間隔に相当します$i$異なる数字または数値の境界によって境界が定められた、連続する等しい数字。 文字列を構築する代わりに、長さのブロックが何通りあるかを数えます。$i$境界を修正し、数字の一貫性を確保することで表示できます。 

重要な単純化は、遷移に関して各位置を独立して処理でき、組み合わせ論を使用して、指定された位置で指定されたサイズのブロックを生成する構成の数をカウントできることです。 すべての位置を合計すると、最終結果が得られます。 これにより、ポジションとランレングスに関する DP の定式化が行われ、トランジションは継続するか新しいブロックを開始するかによってのみ決まります。

 ## アルゴリズムのチュートリアル

 数字列構造を位置ごとに処理しますが、実際の数字を追跡する代わりに、現在のブロックの長さとその状態に至る構成の数を追跡します。 

1. 特定の長さのブロックが特定の位置で終了できる方法の数を累積する動的プログラミング状態を定義します。 これにより、すべての数字が対称的に動作するため、数字の値を完全に区別することがなくなります。 
2. 各位置について、前のブロックを継続するか、新しいブロックを開始するかを検討します。 続行すると現在のブロックの長さが 1 ずつ増加しますが、新しいブロックを開始すると長さが 1 にリセットされます。 
3. 一定の長さのブロックの場合$i$位置で終了$p$、長さに対する回答への貢献を記録します$i$。 これは、そのブロックがそのエンドポイントで最大であるためです。 
4. 現在のランレングスを生成する構成の数を維持しながら、ポジション間で遷移を伝播します。 桁の選択肢の数が重要になるのは、新しいブロックを開始する場合のみで、前の桁とは異なる 9 つの選択肢がありますが、対称性により、この効果を乗算係数として集約することができます。 
5. 1 から 1 までのすべての位置を繰り返します。$n$、DP 状態を更新し、ブロック長ごとに応答配列に寄与を蓄積します。 

中心となる考え方は、すべてのブロックは開始位置と終了位置によって一意に識別され、そのブロックと互換性のある桁割り当ての数は、実際の桁ではなく、境界が一致するか異なるかによってのみ決まるということです。 

### なぜ効果があるのか

 このアルゴリズムは、すべての位置で、DP 状態が、最後のブロックの長さによってのみ分類される最大の等しいブロックへのプレフィックスの固定分割と一致する数字シーケンスの数を表すという不変条件に依存します。 数字の ID は交換可能であり、等価性制約のみが重要であるため、すべての有効な数字の割り当ては DP 内の 1 つの遷移パスに正確に対応します。 各ブロックの長さ$i$は、右側の境界で閉じられたときに正確に 1 回カウントされ、過大または過少カウントが保証されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    
    # dp[len] = number of ways current run has length len
    dp = [0] * (n + 1)
    dp[0] = 1
    
    # ans[i] = number of blocks of length i
    ans = [0] * (n + 1)
    
    for pos in range(1, n + 1):
        new_dp = [0] * (n + 1)
        
        for length in range(0, pos):
            val = dp[length]
            if val == 0:
                continue
            
            # continue same digit -> extend block
            if length + 1 <= n:
                new_dp[length + 1] = (new_dp[length + 1] + val) % MOD
            
            # start new block -> previous block ends at length
            if length > 0:
                ans[length] = (ans[length] + val) % MOD
            
            # starting new block from scratch (position boundary)
            new_dp[1] = (new_dp[1] + val * 9) % MOD
    
        dp = new_dp
    
    # last position contributions
    for length in range(1, n + 1):
        ans[length] = (ans[length] + dp[length]) % MOD
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```コードは、位置をスイープしながら、現在のランレングスにわたって DP を維持します。 の`dp[length]`値は、現在のサフィックス ブロックのサイズを生成する部分的な構築の数を表します。`length`。 ブロックを拡張するときは、その長さを増やします。 ブロックが終了すると、その寄与を次のように追加します。`ans`。 要因`9`新しいブロックを開始すると、前の桁とは異なる任意の桁を選択できるため、 が表示されます。 

最後のスイープでは、番号の末尾に達する残りの開いているブロックが追加されます。 

主な微妙な点は、すべてのブロックが延長された位置または文字列の末尾で終了するときに、そのブロックが正確にカウントされるようにすることです。
