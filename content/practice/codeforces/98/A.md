 ## 解決策
 ## 問題の理解

 6 つの宝石があり、それぞれに 6 つの色のいずれかが含まれています。 6 つの宝石は立方体の 6 つの面に配置されなければなりません。 一方を回転させて他方に配置できる場合、2 つの配置は同一とみなされます。 

入力は単純に長さ 6 の文字列です。 各文字は 1 つの宝石の色を表します。 等しい文字は区別できない宝石を意味します。 たとえば、入力`RGBRGB`は、赤い宝石が 2 つ、緑の宝石が 2 つ、青い宝石が 2 つあることを意味します。 

根本的に異なる立方体の色がどれだけ形成できるかを数えなければなりません。 立方体を回転させても新しい答えは生まれません。 

入力サイズは小さいです。 立方体には位置が 6 つしかないため、強引な並べ替えアプローチも実行可能です。 生アレンジが最も多いのは、`6! = 720`、非常に小さいです。 本当の課題は、回転の等価性を正しく処理することです。 

この問題の危険な点は、立方体の回転が過小評価されやすいことです。 単純な実装では、同じ装飾を表している場合でも、回転された 2 つの立方体を別々にカウントする可能性があります。 

次の入力を考えてみましょう。```
RGBYOV
```すべての色が独特です。 不注意な解決策が原因となる可能性がある`720`、あるからです。`6!`順列。 それは間違いです。 すべての物理立方体には 24 の回転対称性があるため、多くの順列は同じ同値クラスに分類されます。 正しい答えは、`720 / 24 = 30`。 

もう 1 つの簡単な間違いは、重複した色が存在する場合に発生します。 

例えば：```
RRGGGG
```機械的に 24 で割るだけでは、色を繰り返すと重複する構成が作成されるため、ナンセンスになります。 組み合わせ公式に依存するのではなく、回転中の実際の立方体の状態を比較する必要があります。 

もう 1 つの微妙なケースは、すべての色が同じ場合です。```
YYYYYY
```有効な装飾は 1 つだけです。 すべての順列とすべての回転により、同じ立方体が生成されます。 重複排除を行わない順列ベースのソリューションでは、カウントが大幅に過剰になります。 

## アプローチ

 最も直接的なアイデアはブルートフォースです。 6 つの宝石のすべての順列を生成し、各順列を立方体の面の色として解釈し、立方体の回転の下で同等であるすべての順列をグループ化します。 

これが機能するのは、総検索スペースが小さいためです。 すべての色が異なる場合でも、順列は 720 しかありません。 各順列について、24 個の立方体の回転すべてをテストできます。 総作業量は数万回未満に収まります。 

本当の問題は、回転をどのようにきれいに表現するかということです。 

立方体には正確に 24 の異なる方向があります。 面に 0 から 5 までの番号を付けると、すべての回転はこれらのインデックスの順列になります。 これら 24 の順列を事前に計算すると、これらの順列のいずれかを使用して一方を他方に変換できる場合、2 つのカラーリングは同等になります。 

ブルートフォース バージョンでは、24 回転すべてを使用して、すべての順列を以前に確認されたすべての順列と比較できます。 入力が非常に小さいためそれでも問題はありませんが、よりクリーンにすることができます。 

重要な観察は、すべての等価クラスには正規の代表があるということです。 どのような色付けでも、24 個の回転バージョンをすべて生成し、辞書順に最小のものを選択します。 同じ回転クラス内のすべての立方体は、同じ標準形式にマップされます。 

これにより、問題は単純なセットの重複排除に変わります。 

状態空間が小さいため総当り攻撃は機能しますが、ペアごとの等価性を繰り返しチェックする場合は扱いにくくなります。 正準形式の観察により、タスク全体が次のように削減されます。 

1. すべての個別の順列を生成します。 
2. 各順列を正規化します。 
3. 固有の正規化された状態をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアワイズ比較 | O(720㎡×24) | お(720) | 承認済み |
 | 正規表現 | O(720×24) | お(720) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 6 つの立方体の面に 0 から 5 までの番号を付けます。 

必要なのは一貫性だけです。 一般的な規則の 1 つは次のとおりです。 

- 0 = トップ
 - 1 = 最下位
 - 2 = フロント
 - 3 = 戻る
 - 4 = 左
 - 5 = 右
 2. 24 個の立方体回転すべてを事前計算します。 

各回転は、6 つの面インデックスの順列として表されます。 たとえば、1 回回転すると、上面が前面に移動し、前面が下面に移動することが考えられます。 

ソリューション全体の正確性は、24 個の物理的な立方体の向きを正確に生成するかどうかに依存します。それ以上でもそれ以下でもありません。 
3. 入力色のすべての異なる順列を生成します。 

同じ色は区別できないため、セットを使用して重複する順列を自動的に削除します。 
4. 順列ごとに、24 個の回転バージョンすべてを生成します。 

回転を適用するとは、回転順列に従って 6 つの面の色を再配置することを意味します。 
5. 辞書順に最小の回転バージョンを選択します。 

これは、立方体カラーリングの標準形式になります。 

回転的に等価なカラーリングはすべて、同じ 24 個の回転状態のセットを生成するため、同じ標準形式を生成します。 
6. 標準形式をセットに挿入します。 

セットは重複を自動的に削除します。 
7. セットのサイズを印刷します。 

その数は、個別のキューブ装飾の数と等しくなります。 

### なぜ効果があるのか

 2 つの立方体のカラーリングは、一方をもう一方に回転できる場合、正確に同じ回答クラスに属します。 私たちの正規化プロセスは、立方体カラーリングのすべての可能な回転を明示的に列挙し、一意の代表、つまり辞書編集上最小の回転状態を選択します。 

2 つのカラーリングが回転的に同等である場合、それらの回転された状態のセットは同一であるため、同じ標準形式が得られます。 

2 つのカラーリングが回転的に等価でない場合、それらの回転セットは決して交差しないため、それらの標準形式は異なります。 

したがって、正規形式のセットには同値クラスごとに 1 つの要素が含まれており、これがまさに必要な答えになります。 

## Python ソリューション```python
import sys
from itertools import permutations
from collections import deque

input = sys.stdin.readline

def compose(a, b):
    return tuple(a[b[i]] for i in range(6))

def solve():
    s = input().strip()

    # Face order:
    # 0 = top
    # 1 = bottom
    # 2 = front
    # 3 = back
    # 4 = left
    # 5 = right

    # Basic cube rotations
    rot_x = (2, 3, 1, 0, 4, 5)
    rot_y = (0, 1, 4, 5, 3, 2)
    rot_z = (4, 5, 2, 3, 1, 0)

    rotations = set()
    q = deque()

    identity = (0, 1, 2, 3, 4, 5)
    rotations.add(identity)
    q.append(identity)

    # Generate all 24 cube rotations
    while q:
        cur = q.popleft()

        for rot in (rot_x, rot_y, rot_z):
            nxt = compose(rot, cur)

            if nxt not in rotations:
                rotations.add(nxt)
                q.append(nxt)

    rotations = list(rotations)

    canonicals = set()

    for p in set(permutations(s)):
        best = None

        for rot in rotations:
            transformed = tuple(p[rot[i]] for i in range(6))

            if best is None or transformed < best:
                best = transformed

        canonicals.add(best)

    print(len(canonicals))

if __name__ == "__main__":
    solve()
```最初の重要な部分は、立方体の回転の生成です。 24 方向すべてを手動でハードコーディングする代わりに、ソリューションは恒等方向から開始して、座標軸の周りの 3 つの基本的な回転を繰り返し適用します。 幅優先拡張では、最終的に 24 個すべての固有の立方体の向きが検出されます。 

の`compose`関数は 2 つの順列を組み合わせます。 これは、単純な回転から複雑な回転を構築できる核となる操作です。 

順列生成ステップでは以下を使用します。```
set(permutations(s))
```これは不可欠です。 入力に繰り返しの色が含まれている場合、通常の`permutations`多くの重複が生成されます。 

正規化ステップはアルゴリズムの中心です。 すべての配置に対して、24 回転すべてを適用し、最小のタプルを辞書編集的に保持します。 文字列の代わりにタプルを使用すると、比較が簡単かつ効率的になります。 

よくある実装上の間違いは、順列の方向を誤って逆にしてしまうことです。 式:```
tuple(p[rot[i]] for i in range(6))
```「今顔に現れている色」を意味します`i`顔から来た`rot[i]`"。一貫性は正確な規則よりも重要です。

 ## 特殊なケース

 完全に対称な場合を考えてみましょう。```
YYYYYY
```明確な順列は 1 つだけです。 回転するたびに同じ配置が生成されます。```
YYYYYY
```正規セットは要素を 1 つだけ受け取るため、アルゴリズムは次のように出力します。`1`。 

ここで次のことを考えてみましょう。```
RBBBBB
```一見すると、赤い宝石はどの面を占める可能性があるため、6 つの可能性があるように見えます。 回転はこの区別を破壊します。 立方体上の任意の面を回転して他の面にすることができます。 

正規化中、6 つの生の順列すべてが同じ正規化された状態にマッピングされます。 アルゴリズムは正しく出力します`1`。 

最後に、次のことを考慮してください。```
RRRGGG
```単純な組み合わせアプローチでは、すべての配置が同等であると仮定する可能性がありますが、それは誤りです。 実際には、根本的に異なる 2 つの構造があります。 

1. 角で出会った三人の真っ赤な顔。 
2. 1 つの面を周期的に囲む 3 つの赤い面。 

立方体の回転によって一方の構造をもう一方の構造に変換できないため、正規化プロセスではこれらが自動的に区別されます。 最終的な答えはこうなります`2`。
