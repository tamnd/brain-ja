 ## 解決策
 ## 問題の理解

 あります`m + n + 1`合計で異なるカード。 シュレックは最初は自分のことを知っていました`m`ロバは自分のカードを知っています`n`カードが1枚テーブルに隠されています。 隠されたカードを直接知る人は誰もいません。 

プレイヤーは交互にターンを行い、シュレックが最初に動きます。 各ターンで、プレイヤーは隠されたカードをすぐに推測するか、対戦相手が特定のカードを所有しているかどうかを尋ねることができます。 対戦相手がそれを持っている場合、そのカードは公開され、ゲームから永久に削除されます。 そうでなければ、相手は単に「ノー」と答えるだけです。 

間違った推測は即座に負けます。 正しい推測は即座に勝ちます。 両方のプレーヤーが完璧にプレーし、お互いが相手も完璧にプレーしていることを知っています。 シュレックが勝つ確率とドンキーが勝つ確率を計算する必要があります。 

唯一の入力は、`(m, n)`、シュレックとドンキーが保持するカードの初期数。 出力は 2 つの確率であり、その合計は次のようになります。`1`。 

制約は次のとおりです`1000`これは二次動的計画法にとっては小さいですが、明示的なカード構成に基づく状態空間にとっては大きすぎます。 カードの可能な分布は指数関数的に多く存在するため、ゲームをはるかに小さい数学的状態に圧縮する必要があります。 

重要な点は、カードの ID は重要ではないということです。 カウントだけが重要です。 どの時点でも、ゲームの状態は各プレイヤーがまだ未知のカードを何枚持っているかによって完全に決まります。 これにより、問題は約 100 万の州に減り、対処可能になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

プレイヤーの 1 人がカード 0 枚でスタートした場合でも、自動的に負けになるわけではありません。 例えば：```
0 3
```シュレックは何も知りませんが、彼の視点から考えられる隠されたカードは 4 枚だけです。 あらゆる推測は確率的に成功します`1/4`、これはサンプル出力と一致します。 

別の微妙なケースは次のとおりです。```
0 0
```カードは合計 1 枚だけあり、隠されています。 シュレックはすぐに推測し、確率で勝ちます`1`。 

よくある間違った考えは、推測するよりも質問する方が常に良いと考えることです。 プレイヤーがすでに隠されたカードを確実に知っている場合、これは失敗します。 例えば：```
1 0
```シュレックは自分のカードを知っているので、隠されたカードが唯一残っているはずです。 彼は確率ですぐに勝つ`1`。 

さらに危険な間違いは、ゲームをランダムな質問としてモデル化することです。 プレイヤーはランダムではなく最適です。 すべての質問は勝利確率を最大化するように選択され、最適な手は将来の再帰状態に依存します。 

## アプローチ

 ブルートフォース方式では、各プレイヤーがまだ保持しているカードの正確なセットを追跡し、あらゆる法的な質問と推測を再帰的にシミュレートします。 これは正しいです。なぜなら、ゲームは状態に確率が含まれると完全な情報の 1 つになるからです。 

問題は状態空間のサイズです。 まで`2001`カードの合計、隠された配布の数は天文学的なものになります。 30 枚のカードでも、状態グラフはすでに実行不可能です。 

重要な観察は対称性です。 カードの名前は決して重要ではなく、どれだけの可能性が残されているかだけが重要です。 

あなたの番が来て、現在次のものがいるとします。 

-`a`相手だけが持つ可能性のあるカード、
 -`b`あなただけが持っているかもしれないカード、
 -`1`隠しカード。 

あなたの視点から見ると、未知のカードはすべて同じように隠されている可能性があります。 カードについて尋ねると、可能性が 1 つ取り除かれるか、カウントを変更する情報が明らかになります。 同じステータスの 2 枚のカードは交換可能です。 

つまり、ゲームの状態は次のように崩壊します。`(a, b)`誰の番かと一緒に。 

これで、動的プログラミングの状態を定義できます。`dp[a][b]`= 現在のプレイヤーが知ったときに最終的に勝つ確率`b`カードと相手は知っているかもしれない`a`カード。 

州から`(a, b)`、現在のプレイヤーには 2 種類のアクションがあります。 

彼らはすぐに推測するかもしれません。 あるので`a + 1`彼らの視点から見た隠されたカードの可能性、成功確率は次のとおりです。$$\frac{1}{a+1}$$あるいは、対戦相手の考えられるカードの 1 つについて尋ねることもできます。 

相手が本当にそれを持っている場合、それは確率で起こります`a / (a+1)`、そのカードは削除され、同じプレイヤーが再びその状態に移動します。`(a-1, b)`。 

カードが実際に隠されている場合 (確率的に発生します)`1 / (a+1)`の状態で相手にターンが移ります。`(b, a-1)`。 

この再帰的な構造がゲーム全体です。 

ブルートフォース手法は、カードの ID を不必要に区別するため失敗します。 対称性の観察により、状態空間がわずか約 100 万状態に縮小され、メモ化された DP が可能になります。

 ## アルゴリズムのチュートリアル

 1. 定義する`dp[a][b]`対戦相手が所有している可能性があるときに現在のプレーヤーが勝つ確率として`a`未知のカードと現在のプレイヤーが知っている`b`カード。 
2. ベースケースを取り扱う`dp[0][b] = 1`。 

対戦相手にプライベートカードの候補が残っていない場合、隠しカードは完全に決定されるため、現在のプレイヤーは即座に正しく推測します。 
3. すべての州について`(a, b)`と`a > 0`、すぐに推測するというオプションを検討してください。 

隠しカードは均等に分配されます。`a + 1`可能性があるため、即座に推測すると確率が得られます。$$\frac{1}{a+1}$$1. 対戦相手の考えられるカードの 1 つについて尋ねることを検討してください。 

確率的に:$$\frac{a}{a+1}$$相手が実際にカードを持っている。 それは削除され、現在のプレーヤーは次から続行します。`(a-1, b)`。 

1. それ以外の場合、質問されたカードは非表示になります。 

これは確率で起こります。$$\frac{1}{a+1}$$順番が変わり、役割が入れ替わります。 相手の勝率は`(b, a-1)`は`dp[b][a-1]`, したがって、現在のプレイヤーの確率は次のようになります。$$1 - dp[b][a-1]$$1. 次の質問の 2 つの結果を組み合わせます。$$\frac{a}{a+1} dp[a-1][b] + \frac{1}{a+1}(1 - dp[b][a-1])$$1. 現在のプレイヤーは、推測して尋ねるより良い方を選択します。$dp[a][b]=\max\left(\frac1{a+1},\frac{a}{a+1}dp[a-1][b]+\frac1{a+1}(1-dp[b][a-1])\right)$1. 昇順に表に記入します。`a + b`。 すべての遷移はより小さい状態のみを参照するため、この順序により、依存関係がすでに計算されていることが保証されます。 
2. 最終的な答えは次のとおりです。`dp[n][m]`最初にシュレックが見ているからです`n`ロバのものである可能性があり、自分のカードを知っているカード`m`カード。 

なぜ効果があるのか:

 州`(a, b)`将来の意思決定に関連するすべての情報を完全に取得します。 残りの未知のカードはすべて対称であるため、カードのアイデンティティに依存する戦略は存在しません。 繰り返しでは、最適な最初の手をすべて列挙します。すぐに推測するか、質問してください。 要求遷移は、正確な確率によって重み付けされて、可能な 2 つの結果に分割されます。 その後、両方のプレイヤーが最適にプレイするため、再帰状態にはすでに正しい継続値が含まれています。 誘導により`a + b`、すべての DP エントリーは真の最適な当選確率に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

m, n = map(int, input().split())

MAX = max(m, n)

dp = [[0.0] * (MAX + 1) for _ in range(MAX + 1)]

for b in range(MAX + 1):
    dp[0][b] = 1.0

for s in range(1, 2 * MAX + 1):
    for a in range(1, min(MAX, s) + 1):
        b = s - a

        if b < 0 or b > MAX:
            continue

        guess = 1.0 / (a + 1)

        ask = (
            (a / (a + 1)) * dp[a - 1][b]
            + (1.0 / (a + 1)) * (1.0 - dp[b][a - 1])
        )

        dp[a][b] = max(guess, ask)

shrek = dp[n][m]
donkey = 1.0 - shrek

print(f"{shrek:.12f} {donkey:.12f}")
```DP テーブルには、すべてのペアの確率が保存されます。`(a, b)`最大入力サイズまで。 

基本行`dp[0][b] = 1`は、現在のプレイヤーが既に隠されたカードを確実に知っている位置を表します。 

外側のループは増加することによって反復されます。`a + b`。 繰り返しは以下に依存するため、この順序は重要です。`(a-1, b)`そして`(b, a-1)`、どちらも合計サイズが小さくなります。 

移行では、2 つの法的戦略が個別に計算されます。 推測確率は簡単です。 質問トランジションは、質問が失敗した後の役割の交換を慎重に処理します。 値`dp[b][a-1]`はターンが変わった後の相手の勝率を表すので、から引きます。`1`。 

よくある実装上の間違いは、2 番目のブランチがプレイヤーの視点を交換することを忘れていることです。 使用する`dp[a-1][b]`どちらの分岐でも不正確な答えが生成されます。 

もう 1 つの微妙な点は、浮動小数点の精度です。 必要な誤差許容度は次のとおりです。`1e-9`、つまりPython`float`で十分です。

 ## 特殊なケース

 次のことを考慮してください。```
0 0
```ゲーム全体にカードは 1 枚だけあり、それは隠されています。 DP は基本ケースをすぐに使用します`dp[0][0] = 1`。 シュレックは唯一可能なカードを推測し、確実に勝ちます。 

ここで次のことを考えてみましょう。```
1 0
```シュレックは 1 枚のカードを所有し、ドンキーは 1 枚も所有していないため、隠されたカードは一意に決定されます。 アルゴリズムは再び到達します`dp[0][1] = 1`。 常に最初に質問しようとする不注意な実装は失敗します。質問する人がいないためです。 

最後に次のことを考慮してください。```
0 3
```繰り返しは次のようになります。$$dp[3][0] = \max\left( \frac14, \frac34 dp[2][0] + \frac14 (1 - dp[0][2]) \right)$$以来`dp[0][2] = 1`、質問しているブランチは次のように折りたたまれます。$$\frac34 \cdot \frac12 + \frac14 \cdot 0 = \frac38$$しかし`dp[2][0]`それ自体が最適になる`1/2`、最終的には`dp[3][0] = 1/4`。 

重要な点は、質問に失敗するとすぐに相手に勝利状態が与えられるということです。 繰り返しでは、次の用語を通じてこれを処理します。$$1 - dp[b][a-1]$$役割の交換がなければ、確率は過大評価されてしまいます。
