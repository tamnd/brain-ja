 ## 解決策
 ## 問題の理解

 キューの一連のスナップショットが与えられます。 各スナップショットは、ある時点で現在キューにいるすべての生徒の完全な順序付きリストであり、これらのスナップショットは時系列で表示されます。 時間の経過とともに、学生はキューに入るだけであり、一度入ったら、すでにキューに入っている人々に対する相対的な順序を変更することはありません。 唯一の例外は、学生が入場するとき、必ずしも最後尾ではなく、キューのどこにでも参加できることです。 

課題は、すべての生徒について、最後尾ではない位置から列に入ったことがあるという証拠があるかどうかを判断することです。 学生が初めて登場したときに常に現在のキューの最後に参加していた場合、またはスナップショットにまったく登場しなかった場合、その学生は有効とみなされます。 それ以外の場合、スナップショット内の既存のキューの途中に強制的に挿入される位置にそれらが表示された場合、それらは行を切断したものとしてマークされます。 

制約は大きく、結合された要素の合計で最大 100,000 個のスナップショット、および最大 100,000 人の異なる生徒が存在できます。 これにより、スナップショットのすべてのペアを比較したり、単純なリスト操作で挿入をシミュレートしようとしたりするソリューションは即座に除外されます。 要素の合計数が 2 次であるアプローチは、10^5 の 2 乗でもすでに 10^10 の演算になるため、遅すぎます。 

微妙な問題は、挿入イベントが直接表示されることはなく、複数の挿入後の最終状態のみが表示されるという事実から生じます。 つまり、エントリのタイムスタンプには依存せず、連続するスナップショット間の一貫性のみに依存します。 

素朴な考えを打ち破ることが多いエッジケースの 1 つは、生徒が初めて登場するときです。 たとえば、最初のスナップショットが`[3, 5, 1]`、生徒 1 が「割り込んできた」ように見えるかもしれませんが、実際には事前の状態がないため、不正行為を証明する方法はありません。 正しい解決策では、最初のスナップショットを非難のない基本状態として扱う必要があります。 

もう 1 つのエッジ ケースは、学生がどのスナップショットにもまったく登場しない場合です。 これらはキューに入った形跡がまったくないため、0 として出力される必要があります。 

## アプローチ

 強引なアイデアは、キューの進化の歴史全体を再構築してみることです。 スナップショット間のすべての可能な挿入ポイントをシミュレートし、一貫性をチェックすることを想像することもできます。 もう 1 つの単純な試みは、各スナップショットを前のスナップショットと比較し、スキャンまたはリストへの挿入を行う配列操作を使用して、どの要素がどこに挿入されたかを検出しようとすることです。 

これらのアプローチの問題は、Python リストの途中に挿入すると O(n) となり、スナップショット全体で最大 10^5 の要素に対して挿入すると、最悪の場合 O(n^2) の動作が発生することです。 同様に、スナップショットごとに位置を最初から再計算すると、すでに処理された構造を繰り返しスキャンすることになります。 

重要な観察は、実際にはすべての有効な履歴を再構成する必要はないということです。 維持される「現在のキューの状態」と受信する各スナップショットの間の不一致を検出することだけが必要です。 学生は一度存在すると相対的な順序を変更しないため、キューの既存の部分は安定したバックボーンのように動作します。 このバックボーンと次のスナップショットの間の不一致は、現在のポインター位置の前に新入生が挿入されることによってのみ説明できます。これはまさに「ラインを切る」条件です。 

これにより、問題は、維持されたキューと次のスナップショットという 2 つの順序付けされたシーケンス間の制御されたマージに変わります。 不一致が見つかった場合は常に、スナップショットの要素をその位置に新たに挿入する必要があります。その位置が現在のキューの最後にない場合は、すぐに切断の証拠となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再構築 | O(N²) | O(N) | 遅すぎる |
 | リンクされた構造による増分マージ | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 一定時間内に要素を中間に挿入する必要があるため、現在の既知のキューを二重リンク リストとして維持します。 また、各スナップショットの処理中にこのリストをたどるポインターも保持します。 

ブール配列も維持します`bad[i]`学生かどうかを示す`i`一線を画したことが証明された。 

1. 空のリンク リストから開始し、すべての生徒が悪くないとマークされます。 
2. すべての要素をリンク リストに順番に挿入して、最初のスナップショットを処理します。 比較する前の状態がないため、ここでは不良とマークされる生徒はいません。 
3. 後続のスナップショットごとにポインタを設定します。`cur`現在のリンク リストの先頭に移動し、スナップショットを左から右にスキャンします。 
4. 生徒一人ひとりに対して`x`スナップショットで、それと比較してください`cur`：

もし`cur`存在し、`cur.value == x`、その後、両方の代表者がこの立場に同意するため、次へ進みます。`cur`フォワード。 

それらが異なる場合は、`x`現在のキューの位置の前に新しく挿入された生徒である必要があります`cur`。 この場合、マークします`x`悪いので直前に挿入してください`cur`リンクされたリストにあります。 私たちは動かない`cur`、現在のバックボーンの位置がまだ一致していないためです。 
5. もし`cur`が null になると、スナップショットの残りの部分が完全に新しい生徒で構成されていることを意味するため、不良のマークを付けずに最後に追加します。 

すべてのスナップショットを処理した後、`bad[i]`学生かどうかを直接表します`i`終端以外の位置に挿入されたことがある。 

重要な不変条件は、どの時点においても、リンクされたリストは、すでに検証されているすべての学生の現在既知の安定した順序を表し、ポインタが表されることです。`cur`は常に、受信スナップショットと一致する必要がある次に必要な位置を示します。 不一致は、前に新しいノードを挿入することによってのみ説明できます。`cur`既存のノードの相対的な順序は変更できないためです。 

この不変条件により正確さが保証されます。つまり、既存のノードを並べ替えることはなく、不一致によって強制された場合にのみ新しいノードを正確に導入します。 したがって、悪いとマークされた生徒は、スナップショットですでに修正されている生徒の前に配置されている必要があります。これはまさにラインを切るという定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

def append(head_tail, node):
    head, tail = head_tail
    if head is None:
        return (node, node)
    tail.next = node
    node.prev = tail
    return (head, node)

def insert_before(head_tail, cur, node):
    head, tail = head_tail
    if cur is None:
        return append(head_tail, node)
    prev = cur.prev
    node.next = cur
    node.prev = prev
    cur.prev = node
    if prev:
        prev.next = node
        return (head, tail)
    else:
        return (node, tail)

def solve():
    N, M = map(int, input().split())
    bad = [0] * (M + 1)
    pos = [None] * (M + 1)

    head = None
    tail = None

    first = True

    for _ in range(N):
        k = int(input())
        arr = list(map(int, input().split()))

        if first:
            first = False
            for x in arr:
                node = Node(x)
                pos[x] = node
                head, tail = append((head, tail), node)
            continue

        cur = head
        i = 0
        while i < k:
            x = arr[i]

            if cur is not None and cur.val == x:
                cur = cur.next
                i += 1
            else:
                if pos[x] is None:
                    node = Node(x)
                    pos[x] = node
                else:
                    node = pos[x]

                if bad[x] == 0:
                    bad[x] = 1

                head, tail = insert_before((head, tail), cur, node)
                i += 1

    print(" ".join(map(str, bad[1:])))

if __name__ == "__main__":
    solve()
```このソリューションは、キューの変更可能なリンク表現を構築します。 の`pos`配列により、各生徒が単一のノード オブジェクトに対応することが保証されるため、ノードが重複することはありません。 の`cur`ポインターは各スナップショットとの一貫性を強制します。一致する場合は先に進みます。 それ以外の場合は、その正確な位置に新しいノードを挿入します。 矛盾する以前の構造がないため、最初のスナップショットは初期化として扱われます。 

実装の重要な詳細は、二重リンク構造により挿入が O(1) 時間で発生することです。 ここで Python リストを使用すると、シフトが繰り返され、制約を満たせなくなります。

 ## 特殊なケース

 最初の重要なエッジ ケースは、スナップショットが 1 つだけ存在する場合です。 このような状況では、比較の基準がないため、たとえ注文が「カット」のように見えても、それを証明することはできません。 アルゴリズムは、最初のスナップショットの構築中にスチューデントを不良としてマークせずに構造を初​​期化することでこれを処理します。 

もう 1 つのエッジ ケースは、すべての新入生がスナップショットの最後にのみ表示される場合です。 例えば、`[1,2]`に続く`[1,2,3,4]`。 ポインタ`cur`新しい要素を処理する前に最後に到達するため、それらはすべて追加され、不良としてマークされることはなく、すべてゼロが正しく生成されます。 

さらに微妙なケースとしては、同じ位置で不一致が繰り返される場合があります。 安定したバックボーン要素の前に、スナップショットで複数の新入生が紹介されているとします。 それぞれの不一致により、前に挿入がトリガーされます。`cur`、 しかし`cur`既存のノードと一致するまで固定されたままになります。 これにより、そのようなスチューデントはすべて、同じスナップショット内ですでに確立された注文ポジションの前に表示されるため、カット済みとして正しくマークされることが保証されます。
