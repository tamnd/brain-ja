 ## 解決策
 ## 問題の理解

 それぞれが 2 つの数字で表される一連の問題が与えられます。 最初の数字はしきい値要件です。ベラルドは、現在のオーラが少なくともその値である場合にのみ、その問題を解決できます。 2 番目の数字は報酬です。問題を解決すると、オーラがその量だけ増加します。 彼は初期のオーラ値から開始し、問題を解決する任意の順序を選択できますが、各問題は最大 1 回しか使用できません。 

課題は、解決可能な問題を繰り返し選択し、その報酬を適用した後、最終的に得られる最大のオーラを決定することです。 

主な難点は、問題を解決すると、利用できる問題のセットが変わることです。 最初は難しすぎる問題でも、後で解決できるようになる可能性があり、初期に間違った問題を選択すると、後でより良い成長へのアクセスが妨げられる可能性があります。 

この制約では最大 100,000 の問題が許容されるため、すべての順列を試行したり、すべてのサブセットをシミュレートしたりする解決策は不可能です。 各ステップで残りの問題をすべてスキャンする二次シミュレーションでも、最悪の場合は約 10^10 の演算が必要となり、これは 1 秒の制限をはるかに超えています。 これにより、効率的な簿記を行わない、単純な貪欲な注文戦略や繰り返しスキャン戦略が即座に排除されます。 

微妙な失敗のケースは、問題によって大きな報酬が得られるものの要件が高い場合に現れますが、報酬が小さい問題ではその問題へのアクセスが解除されます。 たとえば、低いオーラから始めて、目先の最大の報酬を貪欲に選択すると、後でさらに大きな利益を獲得するシーケンスを見逃してしまう可能性があります。 順序はローカルではなくグローバルに重要です。 

利用可能なすべての問題が最初に私たちが持っている以上のオーラを必要とする場合、別のエッジケースが発生します。 そのような状況では、進歩は不可能であるため、答えは単純に開始オーラです。 

## アプローチ

 ブルートフォースアプローチでは、問題を解決するすべての可能な順序をシミュレートします。 与えられたオーラから、すべての未解決の問題をチェックし、現在利用可能な問題を試し、その報酬を適用した後に再帰し、最大の結果を追跡します。 これにより、有効なアクションのシーケンスがすべて調査されるため、問題が正しくモデル化されます。 

ただし、各ステップの分岐係数は最大 N で、深さも最大 N です。これにより、最悪の場合、およそ N 階乗の動作が発生します。これは、100,000 どころか、20 程度の小さな N であっても完全に実行不可能です。 

重要な観察は、各ステップでの決定は、全履歴ではなく、どの問題が現在手頃な価格であるかによってのみ決まるということです。 現在解決可能なすべての問題の中で、より高い報酬のオプションがすでに利用可能な場合、より高い報酬のオプションの代わりに低い報酬のオプションを選択することは決して有益ではありません。 その理由は単調性です。オーラは増加するだけなので、問題が利用可能になると、解決されるまで利用可能なままになります。 

これは、貪欲なプロセスを示唆しています。要件が最大でも現在のオーラであるすべての問題のセットを維持し、その中から最大の報酬を持つものを常に選択します。 選択するたびにオーラが増加し、新たな問題が解決される可能性があります。 これは、ソートと最大ヒープを使用して効率的に実装できます。 

まず、必要なオーラごとに問題を分類します。 次に、現在のオーラが成長するにつれてそれらを一掃し、新しくロック解除されたすべての問題を報酬によってキー設定された最大ヒープに押し込みます。 利用可能な最高の報酬を獲得するたびに、オーラが増加して続行します。 これにより、価値の高い問題が到達可能になったときに、その問題を取り上げる機会を無駄にすることがなくなります。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの構造を維持しています。必要なオーラによってソートされた問題のリストと、現在解決可能な問題の報酬を含む最大ヒープです。

1. すべての問題を要件値 Ai の降順に並べ替えます。 これにより、オーラが増加するにつれて問題がどの順序で利用可能になるかを知ることができます。 
2. ソートされたリストに対するポインタを初期化し、現在のオーラを K に設定します。また、空の最大ヒープも初期化します。 
3. 次の問題の要件が最大でも現在のオーラである間にポインタを前方に移動し、その報酬をヒープにプッシュします。 このステップでは、新しくアクセスできる問題をすべて収集します。 
4. この時点でヒープが空の場合は、現在のオーラでは解決できる問題が残っていないことを意味するため、プロセスは停止します。 
5. それ以外の場合は、ヒープから最大の報酬を持つ問題を抽出し、その報酬を現在のオーラに追加します。 これは、利用可能な最も収益性の高いアクションを選択することを表します。 
6. これ以上進めなくなるまでステップ 3 ～ 5 を繰り返します。 

選択する前に常にヒープを拡張する理由は、1 つの問題を解決すると他の多くのロックが解除される可能性があるためであり、選択にコミットする前に、現在到達可能なすべてのオプションが確実に考慮されるようにしたいためです。 

### なぜ効果があるのか

 アルゴリズムは常に、要件が最大でも現在のオーラであるすべての未解決の問題の報酬がヒープに正確に含まれるという不変条件を維持します。 オーラは増加するだけなので、一度対象となる問題が対象外になることはありません。 したがって、起こり得るアクションを見逃すことはありません。 

現在利用可能なすべてのアクションの中で、最大の報酬を選択するのが安全です。これより小さい報酬を選択すると、その後のオーラが低下するか同等になるため、より高い報酬を選択するよりも多くの問題を解決することはできません。 この単調性により、局所的な最適な選択が将来の機会を妨げないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    problems = []
    for _ in range(n):
        a, b = map(int, input().split())
        problems.append((a, b))
    
    problems.sort()
    
    i = 0
    aura = k
    heap = []
    
    while True:
        while i < n and problems[i][0] <= aura:
            heapq.heappush(heap, -problems[i][1])
            i += 1
        
        if not heap:
            break
        
        aura += -heapq.heappop(heap)
    
    print(aura)

if __name__ == "__main__":
    solve()
```コードは最初に問題を分類し、オーラが成長するにつれて段階的に問題をアクティブ化できるようにします。 ポインタ`i`各問題が確実に 1 回だけヒープにプッシュされるため、ソート後の前処理が線形に保たれます。 

ヒープには負の値が格納され、Python の最小ヒープ実装を使用して最大ヒープをシミュレートします。 各反復では、最適な報酬を選択する前に、現在到達可能なすべての問題が挿入されていることを確認します。 

よくある実装上の落とし穴は、オーラを増やした後に新しくロック解除された問題を再チェックするのを忘れることです。 そのため、外側のループはヒープの拡張とヒープからの消費を交互に行います。

 ## 特殊なケース

 重大なエッジケースとは、最初は解決できる問題がない場合です。 入力の場合:```
3 1
10 5
20 10
30 100
```このアルゴリズムはすべての問題をソートしますが、ポインターが決して進まないため、ヒープには何も挿入しません。 ヒープはすぐに空のままになるため、ループは終了して 1 を出力します。アクションは実行できないため、これは正しいことです。 

もう 1 つのケースは、ロック解除がチェーンで発生する場合です。 例えば：```
3 1
1 2
3 3
5 10
```オーラ 1 では、最初の問題だけがヒープに入って取得され、オーラが 3 に増加します。これにより、すぐに 2 番目の問題のロックが解除され、次に問題が取得され、3 番目の問題のロックが解除されます。 ゲインのたびにヒープ拡張が繰り返され、新たに到達可能なすべての問題が各段階で確実に考慮されるため、アルゴリズムはこれを自然に処理します。
