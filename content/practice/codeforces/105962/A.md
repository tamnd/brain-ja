 ## 解決策
 ## 問題の理解

 私たちはサッカーのパフォーマンスに関連した簡素化された財務モデルを検討しています。 がある$P$教師はそれぞれが毎月固定の給料をもらっています$R$。 ネイマールの得点$G$月ごとの目標、および目標ごとに固定金額$X$各教師の給与から差し引かれ、ネイマールに送金されることになっている。 

重要な制限は、教師の給与がマイナスになることはできないということです。 控除を繰り返すと教師の給与がゼロ以下になる場合は、給与がゼロになるように控除に上限が設けられます。 

結局のところ、課題はネイマールが受け取る総額を計算することだ$G$すべての教師に集計された目標。 

制約から、$P$と同じ大きさにすることができます$10^8$、 その間$R$せいぜい$3000$、$G$せいぜい$40$、 そして$X$せいぜい$2000$。 これは、教師を反復するアプローチは不可能であることを直ちに示唆しています。$P$一人で作る$O(P)$操作不可能。 

重要な構造は、どの教師も行動が同じであるということです。 それぞれが独立して貢献するため、答えは次のようになります。$P$一人の教師の貢献の倍です。 

ゼロの上限を無視すると、単純な間違いが発生します。 たとえば、次の場合$R = 10$、$G = 5$、 そして$X = 3$、その後、単純な乗算は次のようになります$15$教師ごとに控除されますが、給与で許容されるのは$10$取られること。 したがって、教師ごとの正しい貢献度は次のようになります。$10$、 ない$15$。 

もう 1 つの微妙な失敗は、目標ごとにキャップが誤って適用された場合に発生します。 たとえば、$R = 10$、$G = 2$、$X = 7$、単純なアプローチでは減算される可能性があります$7$合計2回$14$、次にキャップを付けます$10$、ここでは問題ありませんが、概念的に正しい推論は、控除の合計は次のとおりです。$G \cdot X = 14$、次に上限を設定します$R$。 

## アプローチ

 強引な解釈では、各教師の目標をシミュレートし、給与を段階的に減らし、給与がゼロになった時点で停止します。 これは、下限を伴う反復演繹のルールに直接従うため、概念的には簡単です。 ただし、これにはすべてを繰り返す必要があります$P$先生もみんなも$G$目標につながる$P \cdot G$操作。 最悪の場合こうなる$10^8 \cdot 40 = 4 \cdot 10^9$これは実行可能な限界をはるかに超えています。 

重要な点は、すべての教師が同一であり、独立しているということです。 シミュレーションの代わりに、教師ごとの控除総額を閉じた形式で計算できます。 どの先生も負ける$X$ゴールごとなので、以上です$G$目標の合計は$G \cdot X$。 ただし、考えられる最大損失には次の制限があります。$R$、給与がゼロを下回ることはできないため。 したがって、各教師は正確に貢献します$\min(R, G \cdot X)$。 乗算$P$最終的な答えを出します。 

これにより、問題は定数時間の演算に縮小されます。

 | ダイレクトフォーミュラ | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値を読み取る$P$、$R$、$G$、 そして$X$。 これらは、同一の貢献者の数、そのサラリーキャップ、イベントの数、およびイベントごとの控除を定義します。 
2. 教師ごとの予定控除額の合計を次のように計算します。$G \cdot X$。 これは、給与制限がなかった場合に何が起こるかを表しています。 
3. この値を次と比較します。$R$, なぜなら、教師は給料全額を超えて寄付することはできないからです。 取る$\min(R, G \cdot X)$。 
4. 教師ごとの貢献度を乗算します。$P$ネイマールが受け取る総額を取得します。 
5. 結果を出力します。 

中心となる推論は、各教師は独立して同一に動作するため、教師ごとの貢献度がわかれば、母集団全体へのスケーリングは線形かつ正確であるということです。 

### なぜ効果があるのか

 各教師の給与の推移は自分の控除のみに依存しており、他の教師とはまったく関係ありません。 以上$G$同一の操作を行った場合、試行される控除の合計は加算されます。 唯一の制約は、次の厳密な上限です。$R$、教師ごとの合計貢献額が切り捨てられます。 これにより、教師ごとの寄与が 1 回の min 操作で完全に決定され、相互依存関係がないため、すべての教師を合計すると正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    P = int(input())
    R = int(input())
    G = int(input())
    X = int(input())

    per_teacher = min(R, G * X)
    print(P * per_teacher)

if __name__ == "__main__":
    solve()
```実装は導出された式に直接に従います。 唯一の微妙な点は、乗算を確実にすることです。$G \cdot X$上限は目標ごとではなく累積控除の合計に適用されるため、最小値の前に発生します。 Python は大きな整数をサポートしているため、次のような場合でもオーバーフローは問題になりません。$P$大きいです。 

## 実用的な例

 次の入力を考えてみましょう。$P = 3$、$R = 10$、$G = 2$、$X = 3$。 教師ごとに予定されている控除額は、$G \cdot X = 6$, これはサラリーキャップを下回っています。 

| ステップ | 値 |
 | --- | --- |
 | P | 3 |
 | R | 10 |
 | G・X | 6 |
 | 教師ごと | min(10, 6) = 6 |
 | 合計 | 18 |

 これはサラリーキャップが発動されない無制限のケースを示しています。 

ここで考えてみましょう$P = 2$、$R = 8$、$G = 3$、$X = 5$。 教師ごとに予定されている控除額の合計は次のとおりです。$15$, しかし、給与には制限があります。 

| ステップ | 値 |
 | --- | --- |
 | P | 2 |
 | R | 8 |
 | G・X | 15 |
 | 教師ごと | min(8, 15) = 8 |
 | 合計 | 16 |

 これは、サラリーキャップに拘束力がある場合の飽和動作を示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、意図した控除額が給与よりも小さい場合です。 たとえば、$P = 5$、$R = 100$、$G = 2$、$X = 10$、教師ごとの合計は$20$。 アルゴリズムは計算します$\min(100, 20) = 20$と乗算すると、$100$。 上限は適用されず、すべての教師が計算された金額を全額寄付します。 

もう 1 つのエッジケースは、意図した控除額が給与を大幅に超える場合です。 例えば、$P = 4$、$R = 7$、$G = 3$、$X = 10$与える$G \cdot X = 30$、ただし、各教師の上限は次のとおりです。$7$。 結果は次のようになります$28$。 このアルゴリズムは、繰り返されるオーバーフローを 1 つのキャップ操作に正しく折りたたみます。 

最後のエッジケースは次のような場合です$P$など非常に大きいです$10^8$。 min 演算後の計算は 1 回の乗算に減るため、教師に対する反復はなく、結果は正確かつ効率的なままになります。
