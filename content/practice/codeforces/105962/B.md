 ## 解決策
 ## 問題の理解

 長い文字列が与えられました`S`スペースは含まれていません。これは、元のテキストのノイズの多い転写です。 転写プロセスが破損している可能性があります`K`個々の文字、最大の意味`K`元のテキスト内の位置は別の文字に置き換えられました。 

私たちが気にする唯一の特性は、元のテキストに次のフレーズが含まれていたかどうかです。`"tamo competindo"`連続した部分文字列として。 入力ではスペースが削除されるため、このターゲットフレーズは実質的に次のようになります。`"tamo competindo"`元の形式のスペースを含む文字のパターンとして考えられますが、入力の世界では、スペースを削除した後に表示されるシーケンスとして考える必要があります。 したがって、検索しているパターンは正確な文字列です`"tamocompetindo"`。 

タスクは、次の部分文字列が存在するかどうかを判断することです。`S`に変えることができます`"tamocompetindo"`せいぜい変えるだけで`K`合計文字数。 同様に、このパターンの配列が内部に存在するかどうかを尋ねています。`S`最大でもハミング距離`K`。 

制約は大きいです:`|S|`最大 50,000 まで可能ですが、`K`これにより、すべての部分文字列とパターンの間の 2 次比較が即座に除外されます。すべての開始位置をチェックするには、最大 50,000 回の比較 (それぞれ最大約 14 文字) が必要になるためです。これだけでは問題ありませんが、多くの場合に非効率的に実行すると問題が生じます。 ただし、パターンの構造は短く固定されているため、スライディング ウィンドウまたは直接の位置合わせチェックで十分であることがわかります。 

置換のみではなく、任意の挿入または削除を許可しようとすると、単純な間違いが発生します。 たとえば、スペースの問題には編集距離が必要だと考える人もいるかもしれませんが、このステートメントでは文字の変更のみが許可されており、構造の変更は許可されていません。 もう 1 つの微妙な問題は、すべての出現ではなく、1 つの有効なウィンドウの存在のみを考慮していることを忘れていることです。 

エッジ ケースには、必要な長さのウィンドウが存在しない非常に短い文字列が含まれます。たとえば、`S = "abc"`これはすぐに失敗する必要があり、文字列にパターンがすでに正確に含まれているものの、周囲にノイズが含まれている可能性がある場合もあります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。パターンと同じ長さのウィンドウを文字列全体にスライドさせます。`S`。 各位置について、部分文字列を次と比較します。`"tamocompetindo"`そして、いくつの位置が異なるかを数えます。 いずれかのウィンドウに最大でも不一致数がある場合`K`、それは可能であるとすぐに結論付けることができます。 

これが機能するのは、破損モデルが純粋に位置置換であるため、各配置が独立して元のテキストの可能な再構成を記述するためです。 

1 つのウィンドウの総当たりチェックにはコストがかかります`O(14)`パターンの長さが固定されているため。 がある`O(n)`Windows なので、全体の複雑さは次のようになります。`O(14n)`、実際には線形です。 でさえ`n = 5 * 10^4`、これは約 700,000 文字の比較であり、十分に高速です。 

重要な観察点は、パターンが非常に小さく、`K`小さいです。 ローカルの不一致をチェックするだけで済みます。 制約`K ≤ 14`早期停止条件も提供します: 不一致が次の値を超えた場合`K`窓を眺めながら、早めに休憩できます。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. ターゲット パターンを次のように定義します。`"tamocompetindo"`そしてその長さを計算します`m = 14`。 これは比較する唯一の文字列であるため、すべてのチェックはこの固定テンプレートとの一致に限定されます。 
2. 入力文字列が`S`よりも短い長さがあります`m`、すぐに出力`NAO`。 より長いパターンと一致する部分文字列はありません。 
3. すべての開始インデックスを反復処理します。`i`から`0`に`|S| - m`。 
4. それぞれについて`i`、 比較する`S[i:i+m]`パターンに対して文字ごとに不一致を数えます。 
5. 不一致のカウント中、カウントが超過した場合は早期に停止します`K`。 これにより、すでに無効になっているウィンドウでの不必要な比較が回避されます。 
6. いずれかのウィンドウが最大でも不一致カウントで終了した場合`K`、出力`SIM`すぐに。 
7. 全位置スキャン後、条件を満たすウィンドウが存在しなかった場合は出力`NAO`。 

早期停止の背後にある理由は、次のとおりです。`K`位置が異なる場合、有効な変換では許可された編集回数内でそのウィンドウを修正できないため、比較を継続しても結果は変わりません。 

### なぜ効果があるのか

 それぞれの潜在的な開始位置は、パターンを次の部分文字列に揃えて元のテキストの再構築候補を定義します。`S`。 置換のみが許可されるため、その部分文字列をパターンと等しくするコストは、まさに不一致の位置の数になります。 その費用が範囲内であれば`K`、破損したテキストがどのようにしてその語句を含む有効なテキストから生じたのかについての有効な説明が得られました。 すべてのウィンドウをスキャンすることで完全性が保証され、より多くの文字を検査するほど不一致数が増加するだけであるため、早期終了プルーニングによって正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

S = input().strip()
K = int(input().strip())

pattern = "tamocompetindo"
m = len(pattern)
n = len(S)

if n < m:
    print("NAO")
    sys.exit(0)

for i in range(n - m + 1):
    mismatches = 0
    for j in range(m):
        if S[i + j] != pattern[j]:
            mismatches += 1
            if mismatches > K:
                break
    if mismatches <= K:
        print("SIM")
        break
else:
    print("NAO")
```このコードは、スライディング ウィンドウのアイデアを直接実装しています。 外側のループは候補アライメントを選択し、内側のループは置換コストを測定します。 早めの休憩により、絶望的な調整に時間を無駄にすることがなくなります。 決勝戦`else`ループ上は印刷に使用されます`"NAO"`有効なウィンドウが見つからなかった場合のみ。 

実装の微妙な詳細は、Python の使用です。`for-else`これにより、明示的なフラグ変数が必要なくなります。 もう 1 つの重要な点は、ループに入る前に長さチェックを処理することです。これにより、負の反復限界が回避されます。
