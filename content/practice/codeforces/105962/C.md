 ## 問題の理解

 私たちに与えられているのは、$N \times N$バイナリ行列。 行と列を個別に何度でも自由に並べ替えることができます。 これらの順列を行った後、1 のみで構成される可能な限り最大の「C 字型」パターンを見つけたいと考えています。 

サイズの有効な C$x$左上のアンカーを選択し、3 つのセグメントの長さを要求することによって定義されます。$x$左上のアンカーから下に向かう垂直セグメント、その垂直セグメントの上部から右に向かう水平セグメント、および垂直セグメントの下部に整列する別の水平セグメントです。 行と列は任意に並べ替えることができるため、絶対的な位置ではなく、行列のマルチセット構造のみが重要になります。 

この自由が最大の困難です。 固定サブグリッドを選択しているわけではありません。 構造化されたパターンを最大化するために行と列を再配置しています。 したがって、タスクは、最適な順列の後に、どれだけの大きさの 1 の構造化された配置を組み立てることができるかを決定することに帰着します。 

制約$N \le 500$を暗示します$O(N^2)$または$O(N^2 \log N)$このソリューションは問題ありませんが、行と列のペアにわたる単純な意味での立方体は境界線に達しますが、慎重に最適化すれば許容できる可能性があります。 すべての順列を試すようなことは、階乗増加のため直ちに不可能になります。 

微妙な問題は、C シェイプが単なる 1 の長方形ではないということです。 単純なアプローチでは、誤って完全な値を最大化しようとする可能性があります。$x \times x$行を個別にブロックまたは処理します。 このパターンでは、異なるレベルに配置された 1 つの垂直チェーンと 2 つの水平チェーンの間の調整が必要となるため、これは失敗します。 

もう 1 つの落とし穴は、行を独立して処理でき、多くの行を含む行を貪欲に選択できると仮定していることです。 列も並べ替えることができるため、構造は個々の密度だけでなく、行と列がどのように相互作用するかによって決まります。

核となる単純化は、行ごとの次数の観点から考えることです。行ごとに、その行にある次数がいくつあるかを数えます。 この数で行を並べ替えると、最も「有用な」行から C を構築することができます。 ただし、列構造を行間で共有する必要があるため、それだけでは不十分です。

 ## アルゴリズムのチュートリアル

 1. 各行の 1 の数を計算します。 これにより、各行が単一の構造値に圧縮され、水平コンポーネントの形成における柔軟性が反映されます。 
2. この数の降順で行を並べ替えます。 直観的には、最適な構成では、並べ替え後の列の位置合わせがより可能になるため、1 が多い行が優先されると考えられます。 
3. 関数を定義する`can(x)`サイズの C を構築できるかどうかを確認します$x$上を使って$x$行。 
4. 内部`can(x)`、最初のものだけを考えてみましょう$x$行。 各列について、その列に 1 が含まれる行がいくつあるかを計算します。 これにより、選択した行にわたる列サポート プロファイルが得られます。 
5. 有効な構築のためには、少なくとも次のものが必要です。$x$積み重ねられた構造全体の水平アームに参加するのに十分なサポートを備えた柱。 列は並べ替えることができるため、位置ではなくサポート数のみが重要になります。 
6. 以上のサポートを持つ列の数を数えます。$x$。 この数値が少なくとも$x$、次にサイズの C$x$形成することができる。 
7. 二分探索を使用する$x$から$0$に$N$、実現可能な最大値を採用します。 

### なぜ効果があるのか

 行と列の置換により、再順序付けの下でも問題が不変になるため、重要なのは出現構造のみです。 行を並べ替えると、常に最も柔軟な候補が最初に考慮されます。 固定の場合$x$、実現可能性は、十分な重なりを持つ十分な列を集合的にサポートできる十分な行が存在するかどうかによってのみ決まります。 実現可能性の単調性$x$二分探索の正確さを保証します: C のサイズの場合$x$が可能であれば、制約が緩和されるため、さらに小さいサイズも可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]

    row_sum = [sum(row) for row in a]
    order = sorted(range(n), key=lambda i: row_sum[i], reverse=True)
    a = [a[i] for i in order]

    def can(x):
        if x == 0:
            return True

        col_cnt = [0] * n

        for i in range(x):
            row = a[i]
            for j in range(n):
                col_cnt[j] += row[j]

        good = 0
        for j in range(n):
            if col_cnt[j] >= x:
                good += 1

        return good >= x

    lo, hi = 0, n
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、各行を単純なスコア (そこに含まれる 1 の数) に圧縮することから始まります。 これは、置換後に大規模な構造に寄与する可能性が高い行を優先するためにのみ使用されます。 

の`can(x)`機能は実現可能性のチェックの核となります。 列の投稿を上から集計します$x$行を作成し、各列に 1 が含まれる行の数のヒストグラムを作成します。 列は、少なくとも$x$これにより、再配置後の垂直方向の十分な一貫性が保証されるためです。 

二分探索は、答えの単調性を利用して、この実現可能性チェックをラップします。

 ## 特殊なケース

 完全にゼロの行列は、素朴で貪欲な思考にとって最も単純な失敗モードです。 入力の場合:```
2
0 0
0 0
```すべての行と列にはサポートがありません。 このアルゴリズムは、任意の列のゼロ列サポートを正しく計算します。$x \ge 1$、 それで`can(1)`失敗し、バイナリ検索は 0 を返します。少なくとも 1 つの行が常に最小構造を形成できると仮定する単純なアプローチでは、誤って 1 が返されます。 

2 番目のエッジ ケースは、ちょうど 1 行が 1 で埋められた行列です。```
3
1 1 1
0 0 0
0 0 0
```並べ替えると行全体が最初に配置されますが、$x=2$、2 行目のブロックの列サポートはゼロであるため、実行可能性チェックはすぐに失敗します。 これにより、アルゴリズムが単一の強力な行を複数のスタックされたレイヤーに過度に拡張することがなくなります。 

3 番目のケースは、複数の行の合計が同様の対称密行列です。 実現可能性は行の同一性ではなく、集計された列の重複に依存するため、ソート手順によって正確性が損なわれることはありません。 すべての上位サブセットは置換の自由のもとで同等であるため、アルゴリズムは引き続き正しく評価されます。
