 ## 解決策
 ## 問題の理解

 私たちには 1 つの石の山が与えられ、Yvens から始めて交互にターンする 2 人のプレイヤーが与えられます。 各ターンで、現在のプレイヤーは山から 1 つまたは 2 つの石を取り除かなければなりません。 最後の石を取ったプレイヤーが負けとなるため、目標は、山を空にする最後の動きをするプレイヤーにならないようにすることです。 

入力するのは初期の石の数だけです。 出力は、最適なプレイで勝利をもたらすことができるプレーヤーの名前です。 

この制約により、石の数を 1e9 まで増やすことができるため、ゲーム状態に関するシミュレーションが即座に除外されます。 1 から n までのすべての位置を探索しようとしたり、全範囲にわたって動的プログラミングを使用したりするアプローチは、時間とメモリの両方で遅すぎます。 ソリューションでは、ゲームを入力ごとの一定時間の決定に折りたたむ必要があります。 

このゲームを誤って読みがちな落とし穴は、最後の石を取ったプレイヤーに負け条件が適用され、最後の石を取った方が勝ちという通常のルールではないことを忘れていることです。 この 1 つの反転により、すべての基本ケースが反転します。 たとえば、n = 1 の場合、Yvens はすぐに最後の石を奪われて負けるため、Esteche が勝ちます。 n = 2 の場合、イヴェンスは石を 2 つ取ることができ、またすぐに負けます。 n = 3 の場合、イヴェンスは 1 つまたは 2 つの石を取り、どちらの場合もエステシュに負けの立場を残すため、イヴェンスが勝ちます。 基本ケースの仮定が間違っていると、後で定期的な推論が壊れる傾向があります。 

もう 1 つの微妙なケースは、両方の手が利用可能であるものの、すぐに損失につながる値が小さい場合です。 たとえば、n = 2 は特に欺瞞的です。なぜなら、両方の正当な手がゲームを即座に終了させるためです。つまり、2 つの選択肢があるにもかかわらず、最初のプレイヤーには勝ち手がないことを意味します。 

## アプローチ

 ルールから直接推論しようとすると、それぞれの石の数を、プレイヤーが動くことによって勝ったか負けたかのゲーム状態として見ることができます。 プレイヤーは状態 n から n − 1 または n − 2 に進むことができ、これらの遷移の少なくとも 1 つが対戦相手の負け状態につながる場合、現在の状態は勝ちです。 ブルート フォース アプローチでは、動的プログラミングを使用して 1 から n までのすべての値に対してこの分類を計算します。 

ゲームには最適な下部構造があるため、これはきれいに機能します。つまり、ポジションの結果はより小さなポジションにのみ依存します。 ただし、ブルート フォース アプローチでは O(n) 状態と状態ごとの一定の遷移が必要なため、直線的な時間とメモリが必要になります。 n が 1e9 までの場合、すべての状態を反復することは不可能です。 

重要な観察は、再発が非常に早く繰り返しパターンに安定することです。 小さな値を計算すると、次のことがわかります。 

n = 1 は負けです

 n = 2 は負けています

 n = 3 が勝ちます

 n = 4 が勝ちます

 n = 5 は負けています

 n = 6 は負けています

 n = 7 が勝ちです

 n = 8 が勝ちです

 このパターンは、負け、負け、勝ち、勝ちという 4 つの状態ごとに繰り返されます。 これは、ゲームが減算ゲームの変形に相当し、移動によって {1, 2} から要素が削除され、負け条件が通常の Nim 終了とは逆になるために発生します。 この構造により、合同なモジュロ 4 の位置が同じように動作するようになります。 

この周期性が認識されると、問題は n mod 4 を計算し、剰余を分類することになります。

 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n) | O(n) | 遅すぎる |
 | モジュラーパターン | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ゲームを小さな剰余での動作に還元し、それを周期性を使用してすべての n に拡張します。

1. r = n mod 4 を計算します。これにより、状態空間全体が 4 つの同値クラスの 1 つに圧縮されます。これは、遷移構造が 4 つの値ごとに繰り返されるためです。 
2. r が 1 または 2 の場合、プレイヤーが移動できる位置は負けです。 これは、何らかの手が即座に相手に勝ちの構成を与える状況に対応します。 
3. r が 0 または 3 の場合、プレイヤーが移動する位置が勝ちです。 このような場合、相手を負け残りに追い込む手が少なくとも 1 つ存在します。 
4. イヴェンスは必ずスタートするため、スタート位置が勝利の場合は「イヴェンス」、そうでない場合は「エステシュ」を出力します。 

### なぜ効果があるのか

 不変条件は、位置 n の結果が n mod 4 にのみ依存するということです。これは、勝利状態の漸化関係、W(n) = W(n−1) または W(n−2) ではなく、最初のいくつかの基本ケースの後で周期的なシーケンスを生成することをチェックすることによって正当化されます。 サイクルが安定すると、すべてのステップで 4 つずつシフトされた同じ構造が維持されます。 したがって、同じ剰余クラスのすべてのポジションは同じ勝敗ステータスを共有し、モジュラー分類はすべての n に対して正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

r = n % 4

# losing positions are 1 and 2 modulo 4
if r == 1 or r == 2:
    print("Esteche")
else:
    print("Yvens")
```コードは初期パイル サイズを読み取り、それをモジュロ 4 に減算します。その剰余は、現在のプレーヤーが強制的に勝利するかどうかを直接決定します。 重要な実装の詳細は、分類がすべての n に対して完全に対称であるため、ループや事前計算が必要ないことです。 

残基と結果のマッピングは、基本パターンを観察した後にハードコーディングされます。 決定は一定時間内に行われます。 

## 実用的な例

 ### サンプル 1: n = 1

 r = 1 mod 4 = 1 を計算します。 

| n | r | ポジションタイプ | 結果 |
 | --- | --- | --- | --- |
 | 1 | 1 | 負ける | エステシュ |

 n = 1 から、Yvens は最後の石を取らなければなりませんが、すぐに負けるので、Esteche が勝ちます。 

### サンプル 2: n = 7

 r = 7 mod 4 = 3 を計算します。 

| n | r | ポジションタイプ | 結果 |
 | --- | --- | --- | --- |
 | 7 | 3 | 優勝 | イブンス |

 n = 7 から、Yvens は 6 または 5 に移動できます。6 と 5 はどちらもポジションを失っているため、どのような動きでも Esteche は負け状態になり、Yvens の勝利が確定します。 

これら 2 つのケースは、2 つの連続する値のグループ内で勝ちブロックと負けブロックが交互に現れることを示しています。

 ## 特殊なケース

 n = 1 の場合、r = 1 になります。アルゴリズムはこれを負けとして分類するため、Esteche が出力されます。 これは、イヴェンスが最後の石を取り、すぐに負けるという強制的な動きと一致します。 

n = 2、r = 2 の場合。どちらの可能な手もゲームは即座に終了するため、開始プレイヤーは最後の石を取ることを避ける方法がありません。 モジュラー ルールは依然としてこれを損失として正しく分類します。 

n = 4、r = 0 の場合、アルゴリズムは勝ちの位置を予測します。 実際、Yvens は n = 3 に移行することができ、これは相手にとって負けの状態であり、Esteche の反応に関係なく強制勝利を確実にします。 

n = 5、r = 1 の場合、アルゴリズムはそれを負けとしてマークします。 5 からのどの手も 4 または 3 につながり、どちらも次のプレイヤーの勝ちとなるため、最適なプレイの下ではイヴェンスは敗北を避けることができません。
