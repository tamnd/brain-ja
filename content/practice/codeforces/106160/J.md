 ## 解決策
 ## 問題の理解

 このタスクでは、正の整数を表現するように求められます。`n`立方体の合計として。 間の整数のリストを出力する必要があります。`-10000`そして`10000`、その立方体の合計は正確に次のようになります`n`。 有効な分解はすべて受け入れられ、印刷される用語の数は以下を超えることはできません。`10000`。 

入力は、ターゲット値を表す単一の整数です。 出力では、最初に分解された整数の数が示され、次にそれらの整数自体が続きます。 

という制約が`n`せいぜい`9241`が重要な詳細です。 直接構築では、次の事実を利用できます。`1³ = 1`。 印刷したら`n`番号のコピー`1`、それらの立方体の合計は次のようになります`n`。 可能な限り大きいので、`n`は`9241`、これにより生成されるのは最大でも`9241`これは安全に次の制限を下回ります。`10000`。 

これにより、数論の検索、動的計画法、事前計算の必要性が即座に排除されます。 より短い表現を見つけようとするアプローチは、求められている問題よりも難しい問題を解決することになります。 

主なエッジケースは、出力サイズと可能な最小値の処理に関連しています。 のために`n = 1`、出力には 1 つの用語が含まれている必要があります。```
Input
1

Output
1
1
```不注意な実装では、空の応答を初期化しようとして、最小値に何かを追加するのを忘れる可能性があります。 

最大許容値については、次のようになります。```
Input
9241

Output
9241
1 1 1 ... 1
```と`9241`のコピー`1`、答えはまだ有効です。 項の数が少ないと仮定したソリューションでは、多くの不必要な値を作成しようとすると、誤って出力制限に違反する可能性があります。 

もう 1 つのよくある間違いは、元の整数の代わりに立方体を出力することです。 たとえば、`n = 3`、正しい出力は次のとおりです。```
Input
3

Output
3
1 1 1
```なぜならチェックされる合計は`1³ + 1³ + 1³`、 ない`1 + 1 + 1`単純な値として。 

## アプローチ

 強引な解釈では、3 乗の和が となる数値の組み合わせを検索します。`n`。 考えられるすべての立方体値を試したり、再帰を使用したり、考えられる合計に対して動的プログラミング ソリューションを構築したりすることができます。 これらのアプローチは有効な分解を探索するため正しいですが、寛大な出力制限を完全に無視しています。 探索空間は、その小さな境界に比べて膨大です。`n`。 

ブルート フォース検索は、可能な限り単純な形式ですでに存在する分解を検出するのに時間がかかるため、失敗します。 という観察`1³ = 1`問題は完全に変わります。 ターゲットがこれより大きくなることはありませんので、`9241`、繰り返します`1`その通り`n`回は常に合計条件と最大項数条件の両方を満たします。 

最適な解決策は単に出力することです`n`のコピー`1`。

 ## アルゴリズムのチュートリアル

 1. ターゲット番号を読み取ります`n`。 値自体は、必要な項の数を示します。`1`まさに貢献する`1`立方和にします。 
2. 以下を含む分解を作成します。`n`整数のコピー`1`。 結果の立方和は次のようになります。`n × 1³`、まさにその通りです`n`。 
3. 印刷`n`項の数として、その後に項のリストが続きます。 可能な用語の最大数は次のとおりです。`9241`, したがって、出力制限を超えることはありません。 

なぜ機能するのか: 不変条件は、選択した後に`k`のコピー`1`、部分立方和は正確に`k`。 選択後にアルゴリズムが終了したとき`n`コピーの合計は正確に`n`。 選択された値はすべて許容範囲内にあり、選択された値の数は有効です。`n ≤ 9241 < 10000`。
