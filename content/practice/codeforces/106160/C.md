 ## 解決策
 ## 問題の理解

 各モデルは非常に大きなボード上の円で表されます。 入力により、円の中心座標とその直径が得られます。 

2 つのモデルは、ベースの端の間の距離が最大 2 インチである場合、直接接続されているとみなされます。 すべての座標と直径はミリメートルで指定されるため、2 インチは 50.8 mm に相当します。 

すべてのモデルが頂点であり、直接接続されているすべてのペアがエッジであるグラフを構築する場合、2 つの条件が成立する場合、コレクションは一貫性があります。 

まず、グラフを接続する必要があります。 すべてのモデルは、直接接続のチェーンを通じて他のすべてのモデルからアクセス可能である必要があります。 

次に、ユニットに少なくとも 7 つのモデルが含まれる場合、すべてのモデルには少なくとも 2 次数が必要です。 1 つの近隣ノードのみに接続されているモデルでは十分ではありません。 

入力サイズが主な課題です。 最大 200,000 のモデルが存在する可能性があります。 すべてのペアを単純にチェックするには、大まかに必要になります$$\frac{200000 \cdot 199999}{2} \approx 2 \cdot 10^{10}$$距離の計算は完全に不可能です。 

重要な幾何学的観察は、底面が小さいということです。 最大直径はわずか 160 mm なので、中心間の接続可能な最大距離は$$80 + 80 + 50.8 = 210.8 \text{ mm}.$$中心が 210.8 mm より離れているモデルをエッジで接続することはできません。 

この制限されたインタラクション半径により、空間分割ソリューションが可能になります。 

2 つのモデルが許容距離に正確にある場合、微妙なエッジ ケースが発生します。 例えば：```
2
13 13 25
88 13 25
```中心距離は75mmです。 半径の合計は 25 mm です。 ベース間のギャップはちょうど 50 mm、つまり 50.8 mm 以内なので、答えは次のようになります。`yes`。 

厳格な`<`比較すると、そのようなケースが誤って拒否されてしまいます。 

もう 1 つの重要なケースは、1 つの頂点が次数 1 を持つ 7 つ以上のモデルを含む接続されたグラフです。```
7
...
```たとえグラフがつながっていても、答えは`no`ユニットサイズが 7 に達すると、学位要件が有効になるためです。 

間違いの 3 番目の原因は、浮動小数点の精度です。 しきい値は 50.8 mm です。 浮動小数点の距離を直接比較すると、境界線のエラーが発生する可能性があります。 最も安全なアプローチは、二乗距離を使用して条件を整数比較に変換することです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 モデルのすべてのペアについて、それらが直接接続されているかどうかを計算します。 エッジが存在する場合は常に、それをグラフに追加し、次数を更新し、DSU 内のエンドポイントをマージします。 すべてのペアが処理された後、接続性と次数の条件を確認します。 

これが機能するのは、コヒーレンシーの定義が文字通りグラフのプロパティであるためです。 問題はペアの数です。 モデルが 20 万個あるため、ペア数は約 200 億個となり、制限時間をはるかに超えています。 

私たちがより良い結果を出せる理由は、エッジが非常に局所的であるためです。 モデルが 100 km ボード上のどこにあるかに関係なく、中心が 210.8 mm 以内にあるモデルにのみ接続できます。 

これは、平面を正方形のセルに分割することを示唆しています。 セルの辺の長さが接続可能な最大半径より大きい場合、どのモデルも、それ自体のセルまたは 8 つの隣接セルの 1 つのモデルにのみ接続できます。 

すべての可能なエッジの長さは最大 210.8 mm であるため、211 mm のセル サイズを使用すれば十分です。 

これで、各モデルを近隣の少数のモデルと比較するだけで済みます。 塩基が重なり合うことはないため、中心をどれだけ近づけることができるかには下限があります。 一定サイズの近傍内には、一定数のモデルのみが存在できます。 実際には、幾何学的パッキングの議論において、比較の総数は線形になります。 

有効なエッジが見つかるたびに、次数カウントを更新し、DSU 内のエンドポイントをマージします。 すべての近くのペアを処理した後、すべてのモデルが 1 つのコンポーネントに属しているかどうか、およびすべての次数が少なくとも 2 であるかどうかを確認します。$n \ge 7$。

 ## アルゴリズムのチュートリアル

 1. すべてのモデルを読み取り、その座標と直径を保存します。 
2. モデルごとに 1 つのノードを持つ DSU を作成します。 
3. 211 mm のグリッド セル サイズを選択します。 これは、可能な最大中心間接続距離よりわずかに大きくなります。 
4. モデルを 1 つずつ処理します。 モデルの場合`(x, y)`、そのセル座標を計算します。$$(x // 211,\; y // 211)$$5. モデルをグリッドに挿入する前に、それ自体のセルと隣接する 8 つのセルで構成される 9 つのセルを検査します。 

それより遠いモデルは、セル サイズがすでに最大エッジ長を超えているため、接続できない可能性があります。 
6. これらのセルで見つかった以前に保存されたすべてのモデルについて、エッジが存在するかどうかをテストします。 

直径を次のようにします`d1`そして`d2`。 

接続条件は、$$\text{center distance}
\le
\frac{d_1+d_2}{2}+50.8$$浮動小数点演算を避けるには、次のように書き換えます。$$100 \cdot \text{dist}^2
\le
(5(d_1+d_2)+508)^2$$7. 条件が満たされるたびに、両方の次数を増加させ、DSU 内の 2 つの頂点をマージします。 
8. 現在のモデルをグリッド セルに挿入します。 
9. すべてのモデルが処理されたら、すべてのモデルが同じ DSU コンポーネントに属していることを確認します。 
10. もし`n >= 7`、すべての次数が少なくとも 2 であることを確認します。 
11. 出力`"yes"`両方のチェックに合格した場合、そうでない場合は出力`"no"`。 

### なぜ効果があるのか

 グリッドはエッジを見逃すことはありません。 すべての有効なエッジの長さは最大 210.8 mm ですが、各セルの辺の長さは 211 mm です。 いずれかの座標でセルが 1 つ以上異なる 2 点は、少なくとも 1 つの軸で 211 mm よりも離れていなければならず、エッジは不可能になります。 

実際のエッジはすべて、後のエンドポイントが処理されるときに 1 回だけテストされます。 問題定義に従ってエッジが存在する場合、アルゴリズムはそれを DSU に追加し、次数カウントを更新します。 

したがって、DSU はコヒーレンス グラフの接続コンポーネントを正確に表し、次数配列にはグラフの次数が正確に含まれます。 最終チェックは、まさにコヒーレント ユニットの定義からの 2 つの条件です。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

CELL = 211

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return

        if self.sz[a] < self.sz[b]:
            a, b = b, a

        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n = int(input())

    models = []
    for _ in range(n):
        x, y, d = map(int, input().split())
        models.append((x, y, d))

    dsu = DSU(n)
    deg = [0] * n

    grid = defaultdict(list)

    for i, (x, y, d) in enumerate(models):
        cx = x // CELL
        cy = y // CELL

        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                cell = (cx + dx, cy + dy)

                for j in grid.get(cell, []):
                    x2, y2, d2 = models[j]

                    dist2 = (x - x2) * (x - x2) + (y - y2) * (y - y2)

                    rhs = 5 * (d + d2) + 508

                    if 100 * dist2 <= rhs * rhs:
                        deg[i] += 1
                        deg[j] += 1
                        dsu.union(i, j)

        grid[(cx, cy)].append(i)

    root = dsu.find(0)

    for i in range(1, n):
        if dsu.find(i) != root:
            print("no")
            return

    if n >= 7:
        for d in deg:
            if d < 2:
                print("no")
                return

    print("yes")

solve()
```DSU は、グラフを明示的に保存せずに接続を追跡します。 検出されたすべてのエッジは、そのエンドポイントを即座にマージします。 

幾何学的検索はハッシュ グリッドによって処理されます。 モデルは、隣接するセルに既に挿入されているモデルとのみ比較されるため、重複したチェックが回避されます。 

距離の比較は完全に整数ベースです。 表現```
rhs = 5 * (d + d2) + 508
```しきい値を 10 倍することで得られます。$$10 \cdot \left(\frac{d_1+d_2}{2}+50.8\right)
=
5(d_1+d_2)+508$$両辺を二乗すると、精度の問題なく正確な整数比較が行われます。 

接続性チェックでは、単一の代表ルートが使用されます。 いずれかの頂点が別の DSU コンポーネントに属している場合、グラフは切断されます。 

次の条件は次の場合にのみチェックされます。`n >= 7`、問題のステートメントと正確に一致します。

import sys
from collections import defaultdict

def run(inp: str) -> str:

    input = sys.stdin.readline
    CELL = 211

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
            self.sz = [1] * n

        def find(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x

            a = self.find(a)
            b = self.find(b)
            if a == b:
                return
            if self.sz[a] < self.sz[b]:
                a, b = b, a
            self.p[b] = a
            self.sz[a] += self.sz[b]

    n = int(input())
    models = [tuple(map(int, input().split())) for _ in range(n)]

    dsu = DSU(n)
    deg = [0] * n

        cy = y // CELL

        if dsu.find(i) != root:
