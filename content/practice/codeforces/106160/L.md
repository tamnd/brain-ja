 ## 解決策
 ## 問題の理解

 ちょうど 3 行のグリッドがあり、`W`列。 3つのセルは特別です。 

最初のプレイヤーは次から開始します`A = (1, a)`、2番目のプレーヤーはから開始します`B = (3, b)`、そして両方が到達したいと思っています`X = (2, 1)`。 

ゲームが始まる前に、以下のセルに障害物を置くことができます。`A`、`B`、 そして`X`。 障害物を配置した後の開始セルからの距離`X`ブロックされていないセルを通る有効な最短パスの長さです。 

タスクは距離を計算することではありません。 代わりに、最短経路距離が次の条件を満たす迷路を構築する必要があります。`dist(A, X) = dist(B, X) < ∞`。 

そのような迷路が存在しない場合は、次のように出力します。`Impossible`。 

幅は最大 100 であるため、複雑さの点でアルゴリズム上の課題はありません。 本当に難しいのは、どのような構成が可能かを理解し、単純な構築的なパターンを見つけることです。 

開始位置の 1 つがすでに列 1 にある場合は、微妙なケースが発生します。 

たとえば:```
W = 3
a = 3
b = 1
```細胞`B`に直接隣接しています`X`。 障害物はセルを削除しますが、生き残った 2 つの隣接するセル間のエッジを削除することはできないため、からの最短距離は`B`に`X`永続的です`1`。 他のプレイヤーも距離を持つことはできません`1`, したがって、答えは不可能です。 

もう 1 つの見落としやすい状況はパリティです。 

考慮する：```
W = 4
a = 3
b = 2
```ステートメントのサンプルでは、​​これは不可能であると宣言されています。 

からの任意のパス`(1,a)`に`(2,1)`マンハッタン距離と同等です。 迂回するたびに、グリッド内に偶数のステップが追加されます。 したがって、からのあらゆる可能なパスは、`A`に`X`パリティがある`a`、およびからのすべての可能なパス`B`に`X`パリティがある`b`。 

もし`a`そして`b`パリティが異なると、等しい距離は不可能です。 

最後に、両方の開始点が既に隣接している場合、`X`:```
W = 1
a = 1
b = 1
```両方の距離はすでに`1`、したがって空の迷宮は機能します。 

## アプローチ

 ブルートフォースの考え方では、すべての障害物の配置を検索し、BFS で最短経路を確認しようとします。 あ`3 × W`ボードには最大 300 個のセルが含まれるため、障害物構成の数はおよそ`2^300`、それは完全に不可能です。 

重要な観察は、問題はほぼ完全にジオメトリによって決定されるということです。 

最初の有益な事実はパリティです。 からの任意のパス`(1,a)`に`(2,1)`に等しいパリティを持つ`a`、マンハッタンの距離は`a`そして、迂回するたびに長さが均等に変化します。 同様に、からのすべてのパスは、`(3,b)`に`(2,1)`に等しいパリティを持つ`b`。 

等しい距離には等しいパリティが必要です。`a`そして`b`同じパリティを持つ必要があります。 

2 番目の有用な事実は列 1 に関するものです。`a = 1`、 それから`A`～に永久に隣接している`X`、 それで`dist(A,X) = 1`私たちがどんな障害物を置いても。 同じことが当てはまります`b = 1`。 

つまり:

 正確に次の 1 つである場合、`a`そして`b`等しい`1`、答えは不可能です。 

これらの不可能なケースを除去した後、両方の位置が厳密に列 1 の右側にあり、同じパリティを持つと仮定します。 

させて```
t = (a + b) / 2
```パリティが一致しているので、`t`は整数です。 

木の形をした回廊を作ります。 

列から行 1 の水平セグメントを開きます`a`列へ`t`。 

列から行 3 の水平セグメントを開きます`b`列へ`t`。 

列から行 2 を開きます`1`コラムを通して`t`。 

それ以外はすべてブロックします。 

これで、開始点から終了点までのすべてのパスが`X`最初に列に到達する必要があります`t`、次に行 2 に沿って列 1 に移動します。 

からの距離`A`になる```
|a - t| + 1 + (t - 1)
```そしてからの距離`B`になる```
|b - t| + 1 + (t - 1)
```なぜなら`t`は正確に中点であり、2 つの絶対値が等しいため、距離は等しくなります。 

結果として得られるグラフはツリーであるため、代替のショートカットはありません。

 ## アルゴリズムのチュートリアル

 1. もし`a = 1`そして`b = 1`、マークされた 3 つの特別なセルのみを含む空のグリッドを出力します。 
2. 次のいずれかの場合`a`そして`b`等しい`1`、出力`Impossible`。 

列 1 から開始するプレーヤーは常に距離を置いています`1`から`X`、他のプレイヤーはそうではありません。 
3. もし`a`そして`b`パリティが異なる、出力`Impossible`。 

からのすべてのパス`A`に`X`パリティがある`a`、およびからのすべてのパス`B`に`X`パリティがある`b`。 等しい長さは等しいパリティを持たなければなりません。 
4. コンピューティング```
t = (a + b) / 2
```パリティが一致するため、これは整数になります。 
5. 障害物で満たされたグリッドから始めます。 
6. 行 2 のすべてのセルを列から開きます`1`コラムを通して`t`。 

ここが共用廊下となります。`X`。 
7. 列間の行 1 のセルを開きます。`a`そして`t`、包括的。 

これにより、以下を含むブランチが作成されます。`A`。 
8. 行 3 の列間のセルを開きます。`b`そして`t`、包括的。 

これにより、以下を含むブランチが作成されます。`B`。 
9. キャラクターを配置する`A`、`B`、 そして`X`必要なセルに入力し、グリッドを印刷します。 

### なぜ効果があるのか

 建設によって木が生まれます。 どちらかの出発点から`X`列の一意のジャンクションを通過する必要があります`t`。 

からのパスの長さ`A`等しい```
|a - t| + 1 + (t - 1).
```からのパスの長さ`B`等しい```
|b - t| + 1 + (t - 1).
```以来`t`の中間点です`a`そして`b`、 我々は持っています```
|a - t| = |b - t|.
```したがって、2 つの距離は同一です。 

不可能な条件も必要です。 パリティが異なると同じ長さが妨げられ、正確に 1 つのスタートが列 1 にある場合、一方のプレーヤーは永続的に距離 1 にいますが、もう一方のプレーヤーはそうではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

W, a, b = map(int, input().split())

if a == 1 and b == 1:
    print("Possible")
    print("A")
    print("X")
    print("B")
    sys.exit()

if (a == 1) ^ (b == 1):
    print("Impossible")
    sys.exit()

if (a - b) & 1:
    print("Impossible")
    sys.exit()

t = (a + b) // 2

g = [['*' for _ in range(W)] for _ in range(3)]

for c in range(1, t + 1):
    g[1][c - 1] = '.'

for c in range(min(a, t), max(a, t) + 1):
    g[0][c - 1] = '.'

for c in range(min(b, t), max(b, t) + 1):
    g[2][c - 1] = '.'

g[0][a - 1] = 'A'
g[1][0] = 'X'
g[2][b - 1] = 'B'

print("Possible")
for row in g:
    print(''.join(row))
```最初のブロックは、パリティまたは固定距離 1 の隣接関係によっては不可能な特殊な状況を処理します。`X`。 

中間点`t`建築の核心です。 2列目は共用廊下となります。 1 行目と 3 行目はそれぞれ 1 つの分岐を提供し、列で終了します。`t`。 

この実装では、最初にボードを障害物で満たし、目的のツリーに属するセルのみを開きます。 これにより、誤ってショートカットを別の場所に残してしまうことを避けられます。 

間隔ループで使用されるのは、`min`そして`max`、したがって、それらは機能しますか`a < t`、`a > t`、 または`a = t`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    data = io.StringIO(inp)
    out = io.StringIO()

    W, a, b = map(int, data.readline().split())

    if a == 1 and b == 1:
        return "Possible\nA\nX\nB\n"

    if (a == 1) ^ (b == 1):
        return "Impossible\n"

    if (a - b) & 1:
        return "Impossible\n"

    t = (a + b) // 2

    g = [['*' for _ in range(W)] for _ in range(3)]

    for c in range(1, t + 1):
        g[1][c - 1] = '.'

    for c in range(min(a, t), max(a, t) + 1):
        g[0][c - 1] = '.'

    for c in range(min(b, t), max(b, t) + 1):
        g[2][c - 1] = '.'

    g[0][a - 1] = 'A'
    g[1][0] = 'X'
    g[2][b - 1] = 'B'

    out.write("Possible\n")
    for row in g:
        out.write("".join(row) + "\n")

    return out.getvalue()

# sample-style checks
assert run("1 1 1\n") == "Possible\nA\nX\nB\n"

assert run("4 3 2\n") == "Impossible\n"

assert run("3 3 1\n") == "Impossible\n"

# custom cases
assert run("5 2 4\n").startswith("Possible")
assert run("10 5 5\n").startswith("Possible")
assert run("7 1 5\n") == "Impossible\n"
assert run("100 99 99\n").startswith("Possible")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1`| 可能 | 最小サイズ |
 |`4 3 2`| 不可能 | パリティの不一致 |
 |`3 3 1`| 不可能 | 距離 1 で固定された 1 つのスタート |
 |`5 2 4`| 可能 | 典型的な中間点の構造 |
 |`10 5 5`| 可能 | 中間点は両方の開始点に等しい |
 |`100 99 99`| 可能 | 最大幅範囲 |

 ## 特殊なケース

 次のことを考慮してください。```
3 3 1
```プレーヤー`B`から始まります`(3,1)`、真下`X`。 

間のエッジ`(3,1)`そして`(2,1)`どちらのエンドポイントもブロックされない可能性があるため、常に存在します。 

それで：```
dist(B, X) = 1
```永遠に。 

プレーヤー`A`列 3 から始まり、距離 1 にも到達できません。アルゴリズムは、列 1 に開始点が 1 つだけあることを検出し、出力します。`Impossible`。 

次に、次のことを考えてみましょう。```
4 3 2
```可能なすべてのパリティ`A → X`パスは奇数ですが、可能なすべてのパリティは同じです`B → X`パスは均等です。 

等しい整数が同時に奇数と偶数になることはできません。 アルゴリズムは最初にパリティをチェックし、すぐにレポートします。`Impossible`。 

最後に、次のことを考慮してください。```
5 3 3
```それから：```
t = 3
```両方の分岐が同じジャンクション列に直接接続されます。 いずれかの開始点から終了点までの一意のパス`X`の長さは 3 であり、この構造は特別な処理を行わなくても有効なままです。
