 ## 解決策
 ## 問題の理解

 各グラフの頂点には一意の識別子があります。 頂点の 1 つに識別子があります`1`。 

エッジを削除することはできますが、エッジを追加することはできません。 いくつかのエッジを削除した後、識別子が次の頂点を含む接続コンポーネントを確認します。`1`。 

エレベーターのマニュアルでは、そのコンポーネントに表示される識別子が正確に一致している必要があります。`1, 2, 3, ..., k`一部の人にとっては`k`。 

課題はこれを最大化することです`k`。 

問題を言い換える便利な方法は次のとおりです: すべての候補値について`k`、コンポーネントには識別子を持つ一意の頂点が含まれている必要があります`1`、識別子を持つ一意の頂点`2`、などまで`k`、より大きな識別子を含めることはできません。`k`。 

グラフには最大で`2 · 10^5`頂点と`4 · 10^5`エッジ。 の多くの異なる値に対してグラフの走査を繰り返し実行するソリューション`k`高すぎるでしょう。 たとえば、すべてのプレフィックスについて接続性を最初からチェックすると、おおよそのコストがかかります。`O(n(n+m))`、それは限界をはるかに超えています。 

最初の微妙な点は、識別子が連続していることが保証されていないということです。 識別子が次のとおりであるとします。```
1 2 4
```サイズの順列を取得する方法はありません`3`、識別子なので`3`グラフのどこにも存在しません。 

もう 1 つの簡単な間違いは、許可された識別子セット内ではなく、元のグラフ内で接続をチェックしてしまうことです。 

考慮する：```
ids: 1 2 3
edges:
1-3
3-2
```識別子の場合`3`候補より大きい`k = 2`、次に頂点`1`そして`2`識別子のみを使用して接続されていない`≤ 2`。 識別子を介したパス`3`その頂点もコンポーネントに属するため、使用できません。 

2 番目のエッジ ケースは、必要な識別子が存在するにもかかわらず、複数のコンポーネントに分割されている場合に発生します。```
ids: 1 2 3
edges:
(1,2)
```識別子`1..3`は存在しますが、それらの頂点上の誘導グラフは接続されていないため、`k = 3`不可能です。 

## アプローチ

 ブルートフォースアプローチでは、実行可能なすべての値を試します。`k`。 

固定の場合`k`、識別子が最大で次の頂点を持つすべての頂点を取得します。`k`、誘導グラフを構築し、それらの頂点が連結成分を形成しているかどうかを確認します。 存在する場合は、このセットから外の世界に向かうすべてのエッジを削除することで、識別子を含むコンポーネントが削除されます。`1`正確に識別子になります`1..k`。 

これは正しいですが、遅すぎます。 まであります`2 · 10^5`の候補値`k`、各接続チェックはグラフ全体をスキャンする場合があります。 

重要な観察は、テストするセットが入れ子になっているということです。 

させて`S_k`識別子が属する頂点になります`1..k`。 

から移動するとき`k`に`k+1`、新しい頂点を 1 つだけ追加します。その頂点の識別子は`k+1`。 頂点を削除することはありません。 

これは、頂点が識別子の昇順でアクティブ化される動的な接続の問題になります。 この状況には、Disjoint Set Union 構造が最適です。 

新しい頂点がアクティブになったら、それをすでにアクティブな隣接頂点に接続するだけで済みます。 アクティブな頂点間で接続されたコンポーネントの数を維持すると、次のようになります。```
S_k is connected
⇔
the number of active components equals 1
```唯一残っている詳細は、識別子にギャップがある可能性があるということです。 識別子の場合`k+1`が存在しない場合、集合が存在しないため、これ以上の置換は不可能です。`1..k+1`決して形成することはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n+m)) | O(n+m) | 遅すぎる |
 | 最適な DSU | O((n+m) α(n)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての識別子を読み取り、各識別子に対応する頂点を見つけます。 
2. グローバルに存在する最大の識別子の連続プレフィックスを計算します。 から始まる`1`、次の識別子が存在する間は増加し続けます。 この限界を`L`。 
3. グラフ隣接リストを作成します。 
4. 識別子の順序で頂点をアクティブ化します`1, 2, ..., L`。 
5.識別子付き頂点を活性化する場合`k`、そのための新しい DSU コンポーネントを作成し、アクティブなコンポーネントの数を 1 つ増やします。 
6. その頂点のすべての近傍について、その近傍がすでにアクティブであるかどうかを確認します。 これは、識別子が以下の場合に正確に発生します。`k`。 
7. 2 つの頂点が異なる DSU セットに属している場合は常に、2 つの頂点を結合します。 結合が成功するたびに、アクティブなコンポーネントの数が 1 つずつ減少します。 
8. 識別子のすべての共用体を処理した後`k`、有効成分の数が次と等しいかどうかを確認します。`1`。 
9. そうであれば、識別子を持つすべての頂点`1..k`接続された誘導グラフを形成するので、`k`達成可能です。 回答を更新します。 
10. 識別子まで続行します`L`処理されます。 

### なぜ効果があるのか

 固定の場合`k`、アクティブな頂点は、その識別子が属する頂点とまったく同じです。`1..k`。 

DSU には、後のエンドポイントがアクティブになるときに結合が実行されるため、両方のエンドポイントがアクティブであるエッジが正確に含まれます。 

結果として、DSU は識別子上の誘導グラフの接続されたコンポーネントを表します。`1..k`。 

有効成分数が`1`、その誘導グラフが接続されます。 次に、より大きな識別子を持つ頂点までのセットからすべてのエッジを削除し、識別子が正確に一致するコンポーネントを残すことができます。`1..k`。 

有効成分数がより大きい場合`1`、削除によって新しいパスが作成されることはないため、エッジの削除によってそれらの部分を接続することはできません。 

したがって、値`k`有効成分の数が次の場合に正確に実行可能です`1`、そしてそのような最大のものを取ります`k`最適な答えを与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    for i, x in enumerate(a):
        pos[x] = i

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    L = 1
    while L + 1 in pos:
        L += 1

    dsu = DSU(n)
    active = [False] * n
    components = 0
    answer = 0

    for ident in range(1, L + 1):
        v = pos[ident]

        active[v] = True
        components += 1

        for to in g[v]:
            if active[to]:
                if dsu.union(v, to):
                    components -= 1

        if components == 1:
            answer = ident

    print(answer)

solve()
```最初の部分では、すべての識別子をその頂点にマッピングします。 これにより、頂点を識別子の順序で直接アクティブ化できるようになります。 

変数`L`は、入力内に実際に存在する識別子の連続する最大のプレフィックスです。 数値が欠落すると、より大きな順列はすべて不可能になるため、それ以上の識別子を処理する必要はありません。 

DSU は、アクティブな頂点間の接続のみを維持します。 頂点は、その識別子が現在のプレフィックスに入ったときにアクティブになります。 

コンポーネント カウンターは、実装の詳細の重要な部分です。 頂点をアクティブにすると、1 つの新しいコンポーネントが作成されます。 ユニオンが成功するたびに 2 つのコンポーネントがマージされ、カウンターが 1 つ減ります。 処理後の識別子`k`、カウンターは識別子の誘導グラフ内の連結成分の数に等しくなります。`1..k`。 

非アクティブな頂点につながるエッジには特別な処理は必要ありません。 これらの頂点は、現在の頂点よりも大きな識別子に対応します。`k`, したがって、それらは意図的に無視されます。

 ## 特殊なケース

 識別子について考えてみましょう。```
3 1 4
```識別子`2`存在しません。 

アルゴリズムは計算します`L = 1`、連続するプレフィックスが直後に停止するため、`1`。 識別子のみ`1`が処理され、答えは`1`。 

サイズの順列があるため、これ以上の答えはありません`2`識別子が必要です`2`。 

次に、次のことを考えてみましょう。```
3 1
1 2 3
1 2
```いつ識別子`1`がアクティブ化されている場合、コンポーネントは 1 つあります。 

いつ識別子`2`エッジがアクティブになると、`(1,2)`2 つの頂点を 1 つのコンポーネントにマージします。 

いつ識別子`3`がアクティブ化されると、アクティブなグラフに接続するエッジがないため、2 番目のコンポーネントが形成されます。 

コンポーネント数は次のようになります。`2`、 それで`k = 3`拒否され、答えはそのままです`2`。 

最後に、次のことを考慮してください。```
3 2
1 2 100
1 3
2 3
```識別子`1`そして`2`直接接続されていませんが、両方とも識別子を介して接続されています`100`。 

のために`k = 2`、頂点`100`は非アクティブなので、誘導グラフに参加できません。 アクティブなグラフには識別子間のエッジが含まれていません`1`そして`2`, したがって、切断されます。 

アルゴリズムは正しく拒否します`k = 2`これは、最終コンポーネントには より大きな識別子が含まれない可能性があるという事実を反映しています。`k`。
