 ## 解決策
 ## 問題の理解

 私たちは製粉工場のコレクションを持っています。 各製粉所には、1 時間あたりに処理できる小麦の量と、工場から何時間離れているかという 2 つの特性があります。 小麦を製粉所に出荷し、小麦粉を持ち帰るには、所定の移動時間の 2 倍かかります。 工場が受け取った場合`x`キログラム、粉砕部分はかかります`x / p`何時間、どこで`p`はその処理速度です。 

課題は、小麦の総量を製粉所間で分割して、最後の出荷ができるだけ早く戻るようにすることです。 出力は、浮動小数点精度の最小終了時間です。 

入力サイズが大きいです。 まであります`100000`したがって、考えられるすべての分布をチェックすることは不可能です。 到達できる小麦の量`10^9`、速度と移動時間も非常に大きくなる可能性があるため、ソリューションではプロセスをシミュレートするのではなく、答えを対数検索する必要があります。 に近い解決策`O(n)`または`O(n log C)`が必要ですが、どこで`C`可能な回答の範囲です。 

いくつかの特殊なケースは見落とされがちです。 処理速度が非常に高いミルであっても、出荷時間の関係で早期に使用できなくなる可能性があります。 例えば：```
2 100

1000 100
1 1
```2 番目のミルは十分に迅速に処理できますが、最初の出荷だけでも粉砕が開始されるまでにすでに 200 時間かかっています。 処理速度だけを比較する不注意な解決策は、間違った工場を選択する可能性があります。 

もう 1 つのケースは、複数の工場がまったく同時に終了する場合です。 例えば：```
3 7

1 1
1 1
1 1
```答えはそうではありません`7`, 小麦は3等分できるからです。 各ミルで取り扱う`7/3`キログラム、必要な`7/3`研削時間プラス`2`移動時間は次のとおりです。```
13/3 = 4.333333333333
```すべての小麦を 1 つの製粉所に割り当てるソリューションでは、並列処理ができません。 

## アプローチ

 直接的なアプローチは、各製粉所が受け取る小麦の量を決定することです。 選択した金額に対して`x_i`、ミル`i`次の後に終了します:```
2 * t_i + x_i / p_i
```何時間も。 目標は、これらの値の最大値を最小限に抑えることです。 強引なアプローチでは、製粉所間で小麦の異なる配分を試し、最良の仕上がり時間を維持することになります。 整数のキログラム分割のみを表すだけでも、すでに膨大な数の可能性が得られます。 あれば`n`工場と`w`キログラムの場合、可能な分布の数は次の組み合わせになります。`w + n`、両方の値が大きい場合、これは完全に不可能です。 

有益な観察は、質問を逆転させることです。 「最速のスケジュールは何ですか?」と尋ねる代わりに、「もしそうしていたら」と尋ねてください。`T`時間はありますが、どれくらいの小麦を食べきることができますか?」

 決まった終了時間の場合`T`、ミルは往復の配送時間が経過した後にのみ使用できます。 もし`T <= 2*t_i`、その工場では小麦を仕上げることができません。 それ以外の場合、残り時間は次のようになります。```
T - 2*t_i
```そして工場は以下を処理できます:```
p_i * (T - 2*t_i)
```キログラム。 

これをすべての製粉所に加算すると、時間までに完成できる小麦の総量が求められます。`T`。 この値は次の場合にのみ増加します。`T`が増加するので、最小のものを二分探索することができます`T`すべてを処理できるもの`w`キログラム。 

ブルート フォースはディストリビューション自体を構築しようとするため失敗します。 上記の観察により、分布を知る必要がなくなります。 特定の期限までに十分な容量が存在するかどうかをテストするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 可能な分布の数の指数関数 | お(1) | 遅すぎる |
 | 最適 | O(n log C) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのミルを読み取り、その処理速度と移動時間を保存します。 検索中に必要な情報は、各工場が候補終了時間にどれだけの能力を寄与しているかということだけです。 
2. 答えの下限と上限を見つけます。 下限はゼロにすることもできます。 上限については、その時点までにすべての製粉所が一緒にすべての小麦を処理できるほど十分な大きさになるまで、値を繰り返し 2 倍にします。 これにより、未知の最大値に依存することが回避されます。 
3. 終了時刻の二分探索`T`。 中間点については、処理できる小麦の総量を計算します。 
4. 各工場について、次の場合にのみその寄与分を追加します。`T > 2*t_i`。 その貢献は、`p_i * (T - 2*t_i)`。 蓄積容量が上限に達した場合`w`, 今回は実現可能です。 
5. 現在の時間が実行可能な場合は、より早い完了時間でも機能する可能性があるため、小さい方の半分を検索します。 それ以外の場合は、大きい方の半分を検索します。 
6. 十分な反復の後、下限を出力します。 浮動小数点二分探索では正確な停止点は必要ありません。なぜなら、必要なエラーは`10^-6`。 

効果がある理由: 一定時間`T`, どの製粉所にも、その期限までに仕上げることができる小麦の最大量が定められています。 までに終了する有効なスケジュール`T`この容量を超えることはできず、この容量内の任意の量を工場間で個別に割り当てることができます。 したがって、`T`これらの容量の合計が少なくとも小麦の総量以上の場合に可能です。 実現可能性は単調であるため、二分探索により可能な限り最小の終了時間を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    mills = []

    for _ in range(n):
        p, t = map(int, input().split())
        mills.append((p, t))

    def can(x):
        total = 0.0
        for p, t in mills:
            remain = x - 2.0 * t
            if remain > 0:
                total += p * remain
                if total >= w:
                    return True
        return False

    lo = 0.0
    hi = 1.0

    while not can(hi):
        hi *= 2.0

    for _ in range(100):
        mid = (lo + hi) / 2.0
        if can(mid):
            hi = mid
        else:
            lo = mid

    print("{:.12f}".format(hi))

if __name__ == "__main__":
    solve()
```の`can`機能はソリューションの中核です。 特定の期限で十分かどうかに答えます。 工場ごとに出荷時間がかかります`2*t`最初は数時間なので、粉砕時間は残りの部分だけです。 答えが必ずしも整数であるとは限らないため、容量の計算では浮動小数点値が使用されます。 

上限は動的に構築されます。 2 倍にすることにより、最大の答えを推測することが回避され、不可能な 1 つの終点と可能な 1 つの終点から二分探索が開始されることが保証されます。 

二分探索では、小さな間隔で比較するのではなく、固定回数の反復を使用します。 約 100 回の反復は倍精度に必要な回数をはるかに超えており、実装は単純に保たれます。 

容量は非常に大きくなる可能性がありますが、Python の整数と浮動小数点値は必要な範囲を安全に処理します。 早期の復帰は、`can`小麦の目標量がすでに達成された後は、不必要な作業を回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log C) | 各二分探索反復ではすべてのミルがスキャンされ、約 100 回の反復が使用されます。 
| スペース | O(n) | ミルのリストが保存されます |

## テストケース```python
import sys
import io

def solve_data(inp):
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    n, w = map(int, input().split())
    mills = [tuple(map(int, input().split())) for _ in range(n)]

    def can(x):
        total = 0.0
        for p, t in mills:
            rem = x - 2 * t
            if rem > 0:
                total += p * rem
        return total >= w

    lo, hi = 0.0, 1.0
    while not can(hi):
        hi *= 2

    for _ in range(100):
        mid = (lo + hi) / 2
        if can(mid):
            hi = mid
        else:
            lo = mid

    sys.stdin = old
    return hi

80 3

""") - 11) < 1e-6

# sample 2

""") - 3) < 1e-6

# minimum size

1 1
""") - 3) < 1e-6

# all equal values
