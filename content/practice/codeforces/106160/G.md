 ## 解決策
 ## 問題の理解

 迷路はセルのグリッドであり、各セルには放射能レベルを表す数字が含まれています。 旅行者は左上のセルから開始し、隣り合うセル間のみを移動しながら下のセルに到達したいと考えています。 選択したルートの危険性は、そのルート上で訪問する最も放射性の高いセルによって決まります。 タスクは、すべてのルートの中で可能な限り最小の危険値を見つけることです。つまり、最高セル値ができるだけ低いパスが必要です。 

グリッドの寸法はどちらも 100 未満であるため、セルの数は最大でも約 10,000 です。 迷路が大きくなるにつれて、可能な歩行数が指数関数的に増加するため、これにより、経路を列挙するアルゴリズムが除外されます。 O(nm) または O(nm log V) (V は可能な放射能値の範囲) 付近の解は、容易に十分に高速です。 

この問題の微妙な部分は、パスに沿った値の合計を最小化しようとしていないことです。 多くの小さな値を含むパスは、その中程度の値が訪問する最大のセルである場合、1 つの中程度の値を含むパスよりも悪くなる可能性があります。 これは、加算を使用する通常の最短経路アルゴリズムは直接適用できないことを意味します。 

もう 1 つの特殊なケースは、答えが開始セル自体である場合です。 例えば：```
1 1
7
```正しい出力は次のとおりです。```
7
```移動後のセルのみをチェックする不注意な実装では、誤って小さい値が返されるか、移動がないために失敗します。 

もう 1 つのエッジ ケースは、値の高いセルを経由しないと宛先に到達できない場合です。 例えば：```
3 3
111
999
111
```正しい出力は次のとおりです。```
1
```一番上の行が高いセルの周りに接続しているためです。 最小の隣接セルを貪欲に選択するアプローチは、中央付近でトラップされ、答えが 9 であると誤って信じてしまう可能性があります。 

最後によくある間違いは、セルの再訪問が許可されていることを無視することです。 最適なルートとは、制限内での到達可能性に関するものであり、特定の単純なパスを構築するものではありません。 

## アプローチ

 直接的な総当たりのアイデアは、左上隅から目的地までの可能なすべてのルートを生成し、各ルートの最大値を計算し、最小の最大値を維持することです。 考えられるすべてのルートが考慮されているため、これは正しいです。 問題は路線数です。 小さなオープングリッドであっても、すべてのポジションが複数の選択肢に分岐し、可能な四球の数が指数関数的に増加する可能性があります。 最大許容グリッド サイズに達するずっと前に、完全な検索は不可能になります。 

重要な観察は、答えが閾値であるということです。 最大許容放射能が X であると仮定します。その場合、最大でも X の値を持つすべてのセルが使用可能となり、それより大きなセルはすべてブロックされます。 元の質問ははるかに単純になります。使用可能なセルだけを使用して目的地に到達できるでしょうか?

 これにより、問題は到達可能性チェックに変換されます。 しきい値 X が機能する場合、より大きなしきい値もセルを追加するだけなので、すべて機能します。 X が機能しない場合、より小さなしきい値はすべて失敗します。 この単調な特性により、答えに対する二分探索が可能になります。 

候補しきい値ごとに、グリッド上でグラフの走査を実行します。 BFS または DFS は、値がしきい値を超えないセルを介して到達可能なすべてのセルをマークします。 考えられるセル値は 9 つだけであるため、すべてのしきい値を試すこともできますが、二分探索はより一般的なパターンであり、どのような値の範囲でも機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(nm) | 遅すぎる |
 | 最適 | O(nm log C) | O(nm) | 承認済み |

 ここで、C は可能な最大セル値範囲です。 この問題では、セルに数字が含まれているため C は非常に小さくなりますが、値がはるかに大きい場合でも同じ方法が機能します。 

## アルゴリズムのチュートリアル

 1. グリッド内に存在する最小値と最大値を見つけます。 有効なパスは、アクセスするすべてのセルより小さい最大値を持つことはできず、最大グリッド値を使用すると常にすべてのセルを使用できるため、答えはこの間隔のどこかにあるはずです。 
2. 候補しきい値 X を二分探索します。この値については、X より大きい値を持つすべてのセルをブロックされているものとして扱います。 
3. 開始セルから BFS を実行します。 隣接するセルがグリッド内にあり、訪問されておらず、その値が最大でも X である場合にのみ、隣接するセルを追加します。トラバーサルにより、現在の制限の下にパスが存在するかどうかがわかります。 
4. BFS が宛先に到達した場合、X を可能な答えとして保存し、より小さいしきい値を検索します。 しきい値が成功した場合、真の答えはこれよりも低い可能性があることを意味します。 
5. BFS が宛先に到達できない場合は、より多くのセルが使用可能になる必要があるため、より大きなしきい値を検索します。 

これが機能する理由: 重要な不変条件は、BFS の結果がしきい値に関して単調であることです。 しきい値でルートが許可されると、しきい値が大きくなるたびにそのルートも許可されます。 しきい値によってすべてのルートがブロックされると、しきい値が小さくなるたびにそれらのルートもブロックされます。 二分探索では、到達可能性が false から true に変化する最小のしきい値が見つかります。これは、まさにパス上で可能な最小の最大値です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().strip())) for _ in range(n)]

    low = min(min(row) for row in grid)
    high = max(max(row) for row in grid)

    def can_reach(limit):
        if grid[0][0] > limit:
            return False

        visited = [[False] * m for _ in range(n)]
        q = deque([(0, 0)])
        visited[0][0] = True

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while q:
            r, c = q.popleft()

            if r == n - 1 and c == m - 1:
                return True

            for dr, dc in directions:
                nr, nc = r + dr, c + dc

                if 0 <= nr < n and 0 <= nc < m:
                    if not visited[nr][nc] and grid[nr][nc] <= limit:
                        visited[nr][nc] = True
                        q.append((nr, nc))

        return False

    answer = high
    while low <= high:
        mid = (low + high) // 2

        if can_reach(mid):
            answer = mid
            high = mid - 1
        else:
            low = mid + 1

    print(answer)

if __name__ == "__main__":
    solve()
```グリッドは整数として保存されるため、BFS 中の比較は直接的です。 二分探索境界は実際のグリッド値から初期化されるため、不可能なしきい値の不必要なチェックが回避されます。 

の`can_reach`関数は、アルゴリズムのウォークスルーからのグラフの走査を表します。 しきい値ごとに使用可能なセルの異なるグラフが作成されるため、訪問済み行列は BFS ごとに再作成されます。 

BFS が開始される前に、開始セルがチェックされます。 これにより、単一セルの場合が処理され、開始値より小さいしきい値が有効であるとみなされることも防止されます。 

二分探索では、標準の下限パターンが使用されます。 しきい値が成功すると、そのしきい値は保存され、検索は左に移動してより小さい有効な値を見つけます。 失敗すると、制限を増やす必要があるため、検索は右に進みます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm log C) | 二分探索は O(log C) 個の BFS 実行を実行し、各 BFS は各セルを最大 1 回訪問します。 
| スペース | O(nm) | グリッドと訪問行列は両方ともセルの数に比例したスペースを使用します。 

グリッドのセルは 10,000 未満であるため、完全な走査を繰り返しても簡単に制限内に収まります。 このアプローチは、値の範囲が大きくなった場合にも適切に拡張できます。 

## テストケース```python
import sys
import io
from collections import deque

def solution(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [list(map(int, input().strip())) for _ in range(n)]

    def can_reach(limit):
        if grid[0][0] > limit:
            return False

        q = deque([(0, 0)])
        visited = [[False] * m for _ in range(n)]
        visited[0][0] = True

        while q:
            r, c = q.popleft()
            if r == n - 1 and c == m - 1:
                return True

            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < m:
                    if not visited[nr][nc] and grid[nr][nc] <= limit:
                        visited[nr][nc] = True
                        q.append((nr, nc))

        return False

    lo = min(map(min, grid))
    hi = max(map(max, grid))
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can_reach(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return str(ans) + "\n"

## 特殊なケース

 単一セルグリッドの場合:```
1 1
7
```二分探索では、最終的にしきい値 7 がテストされます。BFS は唯一のセルから開始され、それが宛先であることがすぐに確認されるため、答えは 7 になります。アルゴリズムは、少なくとも 1 つの手が存在することを想定しません。 

グリッドの場合:```
3 3
111
999
111
```しきい値 1 は、9 値のセルすべてをブロック済みとしてマークします。 BFS は一番上の行を横切って右側を下に移動し、ブロックされたセルに入ることなく目的地に到着します。 このアルゴリズムは、局所的に魅力的ではあるが中心に向かう誤ったルートをたどるのではなく、1 を返します。 

完全に均一なグリッドの場合:```
2 2
99
99
```開始セル自体が使用できないため、9 未満のしきい値はすべて失敗します。 しきい値 9 では、BFS はオープン グリッドを介して目的地にすぐに到達するため、最小の有効な答えは 9 として正しく検出されます。
