 ## 解決策
 ## 問題の理解

 同じ長さの小文字文字列が 2 つあります。`S`そして`T`。 

1 回の操作で接尾辞が選択されます。`S`そして値`k`1 ～ 25 の間。そのサフィックス内のすべての文字は、次のように前方にシフトされます。`k`アルファベットの位置、ラップアラウンドあり`z`に戻る`a`。 

課題は変革することです`S`の中へ`T`できるだけ少ない操作で。 

この問題を考えるのに役立つ方法は、実際の文字を忘れて、各位置をどれだけシフトする必要があるかだけを追跡することです。 あらゆるインデックスに対して`i`、 定義する$$d_i = (T_i - S_i) \bmod 26$$これはその位置の合計シフトです`i`受け取らなければなりません。 

文字列の長さは次のとおりです。`2 · 10^5`したがって、位置のすべてのペアを考慮したり、文字ごとに操作をシミュレートしたりするアルゴリズムは遅すぎます。 線形または線形に近いものが必要です。 

厄介な点は、操作が単一の位置ではなく接尾辞に影響を与えることです。 以前に適用された変更は、その後のすべての位置に引き続き影響します。 

小さな例を考えてみましょう。```
S = aaa
T = bbb
```どのポジションにもシフトが必要`1`、 それで```
d = [1, 1, 1]
```文字列全体に対する 1 つの操作`k = 1`十分です。 

不注意なアプローチでは、ゼロ以外のシフトを持つ 3 つの位置をカウントして答えを返す可能性があります。`3`、これは間違いです。 

もう 1 つの興味深いケースは次のとおりです。```
S = aaa
T = aba
```それから```
d = [0, 1, 0]
```位置 2 は 1 シフトする必要があり、位置 3 は最終的にゼロに戻る必要があります。 接尾辞の操作は右側に伝播するため、次のものが必要です。```
+1 starting at position 2
+25 starting at position 3
```正しい答えは、`2`。 

これは、重要なのは価値観ではないことを示しています`d_i`それ自体ではなく、隣接する位置間でどのように変化するか。 

## アプローチ

 ブルートフォースの観点は、操作を明示的に構築することです。 

位置を左から右に処理するとします。 各インデックスで、これまでに蓄積されたシフトとその位置で必要なシフトを比較し、差を修正する演算を追加します。 これはすでに正しい構造を示唆していますが、実際にサフィックスを更新して実装すると、各操作が影響を受ける可能性があります。`O(n)`ポジション。 最悪の場合こうなります`O(n^2)`が遅すぎます。`n = 2 · 10^5`。 

重要な観察は、接尾辞の操作によって、その接尾辞内の 2 つの位置の差が変化しないことです。 接尾辞が始まる位置のみが変更されます。 

させて$$d_i = (T_i - S_i) \bmod 26$$そして定義します$$d_0 = 0.$$操作が 位置 で開始されると仮定します。`i`そして次のようにシフトします`k`。 その後は毎回増えていきます`d_j`のために`j ≥ i`による`k`これは、「離散微分値」が変化する唯一の場所が位置間であることを意味します。`i-1`そして`i`。 

定義する$$\Delta_i = (d_i - d_{i-1}) \bmod 26.$$のシフト`k`位置から開始`i`まさに貢献する`k`に`Δ_i`そして他にはどこにもありません。 

つまり、差分配列内の各位置は完全に独立しています。 

もし`Δ_i = 0`、そこでは操作は必要ありません。 

もし`Δ_i ≠ 0`、位置から始まる単一の操作`i`と`k = Δ_i`必要な変更を正確に作成します。 

1 回の演算で 1 から 25 までの任意の値を実現できるため、0 以外のすべての値が実現されます。`Δ_i`費用はちょうど 1 回の操作です。 

答えは単にインデックスの数です。$$(d_i - d_{i-1}) \bmod 26 \ne 0.$$| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サフィックス シミュレーション | O(n²) | O(n) | 遅すぎる |
 | 差分配列観察 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`S`、 そして`T`。 
2. ポジションごとに`i`、計算する$$d_i = (T_i - S_i) \bmod 26.$$これは、その位置で必要なシフトの合計です。 
3. しましょう`prev = 0`を表します。`d_0`。 
4. 位置を左から右に移動します。 
5. コンピューティング$$\Delta = (d_i - prev) \bmod 26.$$これは、この位置で正確に開始する必要がある新しいシフトの量です。 
6. もし`Δ ≠ 0`、答えを 1 つ増やします。 

シフトを使用した単一サフィックス操作`Δ`この変化を生み出すことができます。 
7.セット`prev = d_i`そして続けます。 
8. 最終的なカウントを出力します。 

### なぜ効果があるのか

 すべての接尾辞操作は、その開始点以降のすべての位置に影響します。 必要なシフトの配列内`d`、そのような操作は 1 つの境界、つまり位置間の遷移のみを変更します。`i-1`そして`i`。 

数量$$\Delta_i = (d_i - d_{i-1}) \bmod 26$$位置でどのくらいのシフトを開始する必要があるかを正確に記録します`i`。 

ゼロ以外の`Δ_i`他の場所で開始される操作では生成できないため、少なくとも 1 つの操作が必要です。 逆にシフトでワンオペレーション`Δ_i`まさにその要件を生み出します。 

したがって、ゼロ以外のすべての`Δ_i`正確に 1 つの操作とすべてのゼロに貢献します`Δ_i`何も貢献しません。 ゼロ以外の差をカウントすると、可能な限り最小限の操作数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()
t = input().strip()

ans = 0
prev = 0

for i in range(n):
    cur = (ord(t[i]) - ord(s[i])) % 26
    delta = (cur - prev) % 26
    if delta != 0:
        ans += 1
    prev = cur

print(ans)
```変数`cur`現在の位置に必要な合計シフトを保存します。 

変数`prev`前の位置の必要なシフトを保存します。 コンピューティング```
(cur - prev) % 26
```差分配列の値を与える`Δ`。 

その値がゼロ以外の場合は常に、現在の位置から開始する操作が 1 回だけ必要になります。 

モジュロ演算は必須です。 たとえば、必要なシフトからの移動`1`必要なシフトまで`0`に対応する```
0 - 1 = -1
```これは次のように解釈されるべきです`25`モジュロ 26 算術で。 モジュロを忘れると、この遷移が誤って負として扱われてしまいます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()
    t = input().strip()

    ans = 0
    prev = 0

    for i in range(n):
        cur = (ord(t[i]) - ord(s[i])) % 26
        delta = (cur - prev) % 26
        if delta != 0:
            ans += 1
        prev = cur

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue()

# provided samples
assert run("4\naaaa\naaaa\n") == "0\n"
assert run("9\naaaaaaaaa\naaabbbaaa\n") == "2\n"

# minimum size
assert run("1\na\nb\n") == "1\n"

# all positions need same shift
assert run("3\naaa\nbbb\n") == "1\n"

# alternating requirements
assert run("3\naaa\naba\n") == "2\n"

# wraparound case
assert run("2\nba\nab\n") == "2\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a -> b`|`1`| 自明でない最小のケース |
 |`aaa -> bbb`|`1`| 1 つの操作で多くのポジションに影響を与える可能性があります。 
|`aaa -> aba`|`2`| 操作の開始とキャンセルの両方が必要 |
 |`ba -> ab`|`2`| 正しいモジュロ 26 の処理 |

 ## 特殊なケース

 次のことを考慮してください。```
3
aaa
aba
```必要なシフトは次のとおりです。```
[0, 1, 0]
```アルゴリズムは以下を計算します。```
Δ = [0, 1, 25]
```ゼロ以外のエントリが両方ともカウントされ、答えが得られます。`2`。 

一回の操作で始まります`+1`ポジション 2 でシフトします。別の操作でシフトが開始されます。`+25`位置 3 でシフトし、文字列の残りのエフェクトをキャンセルします。 

次に、次のことを考えてみましょう。```
3
aaa
bbb
```必要なシフト:```
[1, 1, 1]
```違い:```
Δ = [1, 0, 0]
```ゼロ以外のエントリは 1 つだけ存在するため、答えは次のようになります。`1`。 これは、文字列全体に対する 1 つのサフィックス操作が 3 つの位置すべてに同時に影響を与えることを正確に捉えています。 

最後に、ラップアラウンド遷移を検討します。```
2
ba
ab
```必要なシフト:```
[25, 1]
```違い:```
Δ1 = 25
Δ2 = (1 - 25) mod 26 = 2
```どちらもゼロではないので、答えは次のようになります。`2`。 モジュロ演算は、アルファベットの境界を越える遷移を正しく処理します。
