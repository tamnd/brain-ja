 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれが正の整数の配列で構成されます。 タスクは、新しい配列を最初から構築することではなく、結果として得られるシーケンス内の隣接する要素のすべてのペアの合計が同じになるように、指定された要素を並べ替えることができるかどうかを判断することです。 つまり、再配置後、最初の要素と 2 番目の要素の合計は 2 番目と 3 番目の要素の合計と等しくなければならず、この等価性は配列全体で継続する必要があります。 

重要な制約は、配列を任意に並べ替えることができるため、構造が固定されていないことです。 隣接合計条件を満たす順序が存在するかどうかのみを考慮します。 

入力サイズは小さく、テスト ケースあたりの要素数は最大 100 個、テスト ケースの数は最大 100 個です。 これは、テスト ケースごとにおよそ 2 次までの解法はすでに十分に高速であることを意味しますが、問題の構造により直接的な特徴付けが可能であるため、ケースごとに定数または線形チェックを目指す必要があります。 

単純なアプローチでは、配列のすべての順列を試して条件をチェックします。 これは複雑さの階乗であり、n が 10 の場合でも不可能になります。 

より巧妙で間違ったアプローチは、ソートが直接役立つと仮定し、たとえば、ソートされた配列が条件を満たすかどうかをチェックすることです。 この条件は次数ではなく隣接構造に依存するため、これは失敗します。 

典型的な誤解を招くシナリオは、値が繰り返される場合に現れます。 たとえば、1、1、4、5 のような配列は、柔軟性を示す可能性のある重複が含まれている場合でも、有効にすることはできません。 貪欲な再配置の試みは、ローカルな修正によって隣接する合計のグローバルな等価性が崩れるため、失敗することがよくあります。 

中心的な問題は、制約がすべての隣接するペアを結合するため、ローカルな一貫性により非常に厳格なグローバル構造が強制されることです。 

## アプローチ

 ブルートフォースを試みる場合は、配列のすべての順列を生成し、隣接するすべての合計が等しいかどうかを確認します。 各順列について、n から 1 を引いた合計を計算するため、合計の複雑さは O(n! · n) になります。 n が 10 であっても、これはすでに実現可能な限界を超えています。 

重要な観察は、条件が何を意味するかを代数的に書き留めることから得られます。 有効な取り決めが存在すると仮定します。 次に、すべてのインデックス i について、b[i] + b[i+1] が同じ定数 k に等しくなければなりません。 連続する等値を比較すると、b[i] + b[i+1] = b[i+1] + b[i+2] が得られ、これはすぐに b[i] = b[i+2] に単純化されます。 これは、シーケンスが 2 つの値の間で厳密に交互になる必要があることを意味します。 

この点に到達すると、構造全体が非常に単純なパターンに崩壊します。 有効な配列は、x、y、x、y、x、y など、またはその逆の開始点のようになっている必要があります。 したがって、配列には最大 2 つの異なる値を含めることができます。 3 つ以上の異なる値が存在する場合、どの順列も条件を満たすことはできません。 

正確に 2 つの値が存在する場合、たとえば、周波数 c1 と c2 を持つ x と y の場合、残る唯一の問題は、それらを交互の位置に配置できるかどうかです。 位置は、インデックス 1、3、5 などとインデックス 2、4、6 などの 2 つのグループに分割されます。 これらのグループの 1 つは完全に x であり、もう 1 つは完全に y である必要があります。 これにより、カウントのマルチセットが配列長のパリティ分割と一致するように強制されます。 

長さ n の場合、1 つのグループのサイズは ceil(n/2) で、もう 1 つのグループのサイズは Floor(n/2) です。 したがって、周波数はこれらのサイズをある順序で正確に一致させる必要があります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 周波数分析 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. テスト ケースの配列を読み取り、それぞれの個別の値の頻度を計算します。 このステップでは、順序が暗黙的に構築されるため、要素の順序付けからカウントに関する推論まで問題が軽減されます。 
2. 個別の値の数が 2 より大きい場合は、有効な配置が存在しないと直ちに結論付けます。 これは、有効なシーケンス内で 2 つの値のみを許可するという代替要件に従うものです。 
3. 異なる値が 1 つだけある場合、隣接するすべての合計が同一であるため、配列はすでに自明に有効です。 
4. 正確に 2 つの異なる値がある場合は、それらの周波数 c1 と c2 を抽出します。 必要な 2 つのグループ サイズ、floor(n/2) と ceil(n/2) を計算します。 
5. 周波数のマルチセットがこれら 2 つのグループ サイズと一致するかどうかを確認します。 c1 と c2 がまさにこれら 2 つの値であり、任意の順序であれば、有効な交互配置が存在します。 
6. それ以外の場合は、有効な取り決めが不可能であることを返します。 

これらのステップの背後にある推論は、強制的な等価 b[i] = b[i+2] に基づいています。 これにより、有効な構成はすべて位置の厳密な 2 色分けに集約され、残された唯一の自由は、どの値を奇数のインデックスに割り当て、どの値を偶数のインデックスに割り当てるかということになります。 

### なぜ効果があるのか

 隣接する合計条件では、2 つおきの要素間の等価性が強制されます。これは、合計が等しいと、連続する制約を減算するときに中間項が削除されるためです。 これにより、第 2 周期の剛な周期構造が作成されます。 この構造が分かれば、問題は完全に、指定されたマルチセットをその交互パターンの固定位置カウントに一致する 2 つのグループに分割できるかどうかを確認することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    
    if len(freq) == 1:
        print("Yes")
        return
    
    if len(freq) > 2:
        print("No")
        return
    
    vals = list(freq.values())
    vals.sort()
    
    n1 = n // 2
    n2 = n - n1
    
    if (vals[0] == n1 and vals[1] == n2) or (vals[0] == n2 and vals[1] == n1):
        print("Yes")
    else:
        print("No")

t = int(input())
for _ in range(t):
    solve()
```このソリューションでは、配列を周波数マップに圧縮します。これは、置換推論をカウント推論に置き換える重要な変換です。 1 つまたは 2 つ以上の個別の値の特殊なケースは、以前に導出された構造的制約を直接エンコードします。 最終チェックでは、周波数をインデックスの強制パリティ分割に合わせて調整します。 

よくある実装上の落とし穴は、2 つの値がどちらのパリティ クラスにも割り当てられることを忘れていることです。 これが、両方の割り当てが対称的にチェックされる理由です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    
    t = int(input())
    
    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        if len(freq) == 1:
            out.append("Yes")
            return
        
        if len(freq) > 2:
            out.append("No")
            return
        
        vals = list(freq.values())
        vals.sort()
        
        n1 = n // 2
        n2 = n - n1
        
        if (vals[0] == n1 and vals[1] == n2) or (vals[0] == n2 and vals[1] == n1):
            out.append("Yes")
        else:
            out.append("No")
    
    for _ in range(t):
        solve()
    
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、配列にちょうど 2 つの要素がある場合です。 隣接する合計は 1 つだけであるため、2 つの数値の順序は自明に条件を満たします。 周波数のサイズが 1 と 1 の必要な分割に一致するため、アルゴリズムはこれを暗黙的に処理します。 

もう 1 つの特殊なケースは、すべての要素が同一である場合です。 その状況では、周波数マップのサイズは 1 になり、アルゴリズムはすぐに成功を返します。 これは、どの置換でも一定の隣接和が維持されるという事実と一致します。 

さらに微妙なケースは、正確に 2 つの異なる値が存在するが、パリティ分割と一致しない形でカウントが不均衡である場合に発生します。 たとえば、長さ 5 の配列で、カウントが 4 と 1 の場合、交互に配置しても位置 1、3、5、および 2、4 に値を正しく分配できません。 ソートされた周波数ペアが 3 と 2 に一致しないため、アルゴリズムはこれを拒否します。 

これらのケースは、周波数ベースの条件が隣接合計要件によって課せられるすべての構造的制約を完全に捉えていることを確認します。
