 ## 解決策
 ## 問題の理解

 個別の整数のコレクションが与えられます。 現在のコレクションから 1 より大きい数値を選択し、それを削除し、適切な約数の 1 つに置き換える操作を繰り返し実行できます。 置換値は、削除された数値よりも厳密に小さくする必要があり、また、すべてのステップでコレクション全体に重複がないようにする必要があります。 このような交換ごとに 1 単位のエネルギーが得られ、目標は、実行できる操作の数を最大化することです。 

このプロセスは基本的に、厳格なグローバル一意性制約を維持しながら、除数チェーンに沿って数値を分解する制御された方法です。 追跡しているのは重複が許可されるマルチセットではなくセットであるため、すべての中間値はグローバルに一意である必要があります。 

n ≤ 300 および ai ≤ 10^9 という制約は、すべての可能な変換の直接シミュレーションが不可能であることを示唆しています。 多くの約数があるため、数値からの分岐要素が大きくなる可能性があり、単純に状態を探索すると組み合わせ論的に爆発してしまいます。 値空間が大きく連続しているため、状態をフルセットとして表すことさえ不可能です。 

複数の数値が除数構造を共有する場合、微妙な特殊なケースが発生します。 たとえば、12 と 18 のような値がある場合、両方とも 6 または 3 に減らすことができますが、セット内の衝突により任意の選択ができなくなります。 数値を常に最小の係数に置き換えるなどの単純な貪欲な選択は、たとえシーケンスが異なるとより多くの操作が発生する場合でも、システムを早期にロックし、それ以降の動作をブロックする可能性があります。 

数値が素数の場合、別の注意が必要なシナリオが発生します。 たとえば、セットに素数のみが含まれている場合、それらには有効な適切な約数がないため、まったく演算ができません。 

## アプローチ

 ブルート フォース アプローチでは、すべての有効な操作シーケンスが試行されます。 現在のセットから、すべての要素 x > 1 について、x のすべての適切な約数 d を列挙し、d がまだ存在しない場合は x を d に置き換える新しいセットを形成し、再帰的に続行します。 これは、あらゆる法的変革の道筋を検討しているため、正しいです。 

ただし、到達可能な状態の数は急速に増加します。 各数値の約数が少数しかない場合でも、シーケンスが長くなる可能性があり、さまざまな選択が一意性制約を通じてグローバルに相互作用します。 状態空間は事実上、除数遷移を通じて到達可能な整数のすべてのサブセットであり、n および因子連鎖の深さでは指数関数的になります。 

重要な観察は、各数値が可能な分解経路に関して独立して寄与しているということです。 すべての整数は、一意性を侵害するか 1 に達することなく削減できない点に達するまで、段階的に削減できます。この構造は、シーケンスをシミュレートするのではなく、「各数値を何回削減できるか」という観点から考える必要があることを示唆しています。 

各数値は、ノードが整数であり、エッジが数値からその適切な約数に向かう有向グラフ内のチェーンとして見ることができます。 問題は、各中間ステップでの一意性を尊重しながら、これらのチェーン全体で互いに素な動きのコレクションを選択することになります。 これは当然、マッチング スタイルまたは代入スタイルの最適化ですが、各ノードにはどのステップでも出力操作が 1 つしかないため、それを除数チェーン上の貪欲なサイズの構築に単純化できます。 

重要な洞察は、数値を昇順に処理し、各数値を除数階層内の利用可能な最小の「スロット」に常に割り当てることです。 より小さい値が最初に要求されるようにすることで、将来の競合を回避し、有効な置換の数を最大化します。

 ## アルゴリズムのチュートリアル

適切な除数ステップを繰り返すことで、各数値を減らすことができるすべての値によって各数値をモデル化します。 逆に考えると、プロセスは簡単になります。操作を実行するたびに、数値をより小さい約数に置き換えるので、事実上、各数値に厳密に減少する一連の値を、グローバルにすべて異なる値に割り当てることになります。 

1. 入力数値ごとに、その適切な約数をすべて計算します。 すべての演算で x が d < x に置き換えられるため、チェーン内におそらく現れる可能性のある約数のみが必要です。 このステップでは、遷移の隣接可能性を構築します。 
2. すべての最初の数値を昇順に並べ替えます。 数値が小さいと使用できるターゲットが少なくなり、後で割り当てると柔軟性が低下するため、この順序は不可欠です。 小さな値を処理すると、最初に重要な低スロットが予約されます。 
3. すでに使用されている値のグローバル セットを維持します。 このセットは、想像上の最適なシーケンスの任意の段階における魔法のセットの現在の内容を表しますが、実際のステップではなく最終的な割り当てのみをシミュレートします。 
4. 各数値 x を昇順に、その除数チェーン内のまだ使用されていない可能な限り最小の値に割り当ててみます。 より小さい代表を選択すると、その上の他の数値のための余地がより多く残るため、約数を昇順に試します。 
5. 有効な割り当て値 y が選択されたら、y を使用済みとしてマークし、(x から y までのステップ数) を答えに貢献します。 ステップ数は、有効な除数遷移を介して x から y に厳密に減少するチェーンの長さであり、事前に計算するか、繰り返し因数分解することで導出できます。 
6. 競合を回避できる x より小さい約数が利用できない場合、その数値はゼロ演算に寄与します。 
7. すべての数値の寄与を合計して、最大の合計エネルギーを取得します。 

### なぜ効果があるのか

 重要な不変条件は、選択されたすべての割り当てが除数閉包グラフ内で一意のエンドポイントを予約し、常に最小の実現可能なエンドポイントを最初に割り当てるということです。 除数チェーンは単調減少するため、より大きなエンドポイントに割り当てても、到達可能な合計ステップは増加せずに、他の数値の柔軟性が低下するだけです。 これにより、貪欲な最適な部分構造が作成されます。利用可能な最小の有効な除数への局所的な最適な割り当ては、より優れたグローバル ソリューションをブロックすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    divs = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            j = x // i
            if i != x:
                divs.append(i)
            if j != i and j != x:
                divs.append(j)
        i += 1
    divs.sort()
    return divs

def count_chain(x, target):
    # count steps from x down to target via repeated best reductions
    # greedy: each step pick smallest divisor still >= target
    steps = 0
    cur = x
    while cur > target:
        nxt = None
        i = 1
        while i * i <= cur:
            if cur % i == 0:
                if i < cur and i >= target:
                    nxt = i
                    break
                j = cur // i
                if j < cur and j >= target:
                    nxt = j
            i += 1
        if nxt is None:
            return 0
        cur = nxt
        steps += 1
    return steps

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    used = set()
    a.sort()
    
    ans = 0
    
    for x in a:
        divs = get_divisors(x)
        chosen = None
        
        for d in divs:
            if d not in used:
                chosen = d
                break
        
        if chosen is not None:
            ans += count_chain(x, chosen)
            used.add(chosen)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、数値自体を除く、各数値のすべての適切な約数を生成することから始まります。 これにより、各要素の可能な置換の候補セットが形成されます。 

配列をソートすると、小さい数値が最初に低い値を予約するようになります。 貪欲な選択では、除数を昇順にスキャンし、最も保守的な割り当てに対応する最初の未使用の除数を選択します。 

機能`count_chain`選択したエンドポイントまでの数値から、実行可能な操作の数を推定します。 ターゲット以上の約数に繰り返し移動するシミュレーションを行います。 これは、すべてのグローバル状態を列挙するのではなく、除数構造が直接利用される部分です。 

グローバルな`used`set は、最終代入レベルで一意性制約を強制し、2 つの数値が同じ中間値に重複しないようにします。 

## 実用的な例

 インプットを考慮する`a = [4, 6]`。 

約数を計算します。 

4 → [1、2]

 6 → [1、2、3]

 ソート順は[4,6]です。 

| × | 約数 | 選ばれた | 中古セット | チェーン貢献 |
 | --- | --- | --- | --- | --- |
 | 4 | 1、2 | 1 | {1} | 4 → 2 → 1 は 2 を与えます |
 | 6 | 1、2、3 | 2 | {1、2} | 6 → 3 → 2 は 2 になります |

 4 の場合、1 を選択すると 4 → 2 → 1 が可能になります。6 の場合、1 はすでに使用されているため、2 を選択し、6 → 3 → 2 となります。総エネルギーは 4 です。 

ここで考えてみましょう`[12, 18]`。 

約数:

 12 → [1、2、3、4、6]

 18 → [1、2、3、6、9]

 ソート順は[12, 18]です。 

| × | 約数 | 選ばれた | 中古セット | チェーン貢献 |
 | --- | --- | --- | --- | --- |
 | 12 | 1、2、3、4、6 | 1 | {1} | 12 → 6 → 3 → 1 は 3 を与えます |
 | 18 | 1、2、3、6、9 | 2 | {1、2} | 18 → 9 → 3 → 2 で 3 |

 このトレースは、小さいエンドポイントを早期に割り当てることで、長いチェーンを維持しながら後の要素に適応を強制する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n √A) | 各数値は最大 √A までの約数を計算し、さらに約数にわたる線形スキャンを計算します。 
| スペース | O(n) | 除数リストと使用済みセットのストレージ |

 √A は約 31600 で、300 個の数値のみが処理されるため、境界 n ≤ 300 および A ≤ 10^9 により、これが効率的になります。

 ## 特殊なケース

 次のような単一のプライム入力の場合`7`の場合、約数リストには有効な適切な約数が含まれていないため、アルゴリズムは何も割り当てず、答えはゼロのままになります。 

のために`7`:

 ループは 7 を処理し、使用可能な除数を見つけず、代入をスキップします。 使用されたセットは空のままであり、チェーンはカウントされません。 

のために`[2, 3, 5]`、それぞれの数値は独立して動作しますが、それでも適切な約数はありません。 各反復では選択したエンドポイントの割り当てに失敗するため、最終的なエネルギーはゼロになります。 これは、アルゴリズムがすべての数値を削減できると誤って仮定していないことを確認します。 

次のような高度に重複する除数セットの場合`[12, 18]`、最初に処理された番号は 1 を要求し、2 番目の番号はそれを回避するように強制されます。 このシミュレーションは、貪欲な順序付けによって要素ごとの最大チェーン長を抽出しながら衝突を防止する方法を示しています。
