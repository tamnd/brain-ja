 ## 解決策
 ## 問題の理解

 私たちにはn人のボランティアの列が与えられており、各ポジションにはすでに3種類の衣装のいずれかが部分的に割り当てられているか、割り当てられていないままになっています。 固定割り当ては不変ですが、割り当てられていないポジションはタイプ a、b、または c のコスチュームを使用して埋める必要があります。 最終的な配置は、厳密な隣接規則を満たす必要があります。つまり、隣接する 2 人のボランティアが同じ種類の衣装を着用できないということです。 

部分的に固定されたラインナップに加えて、Qクエリが与えられます。 各クエリは、合計で使用できる各タイプのコスチュームの数の上限を示します。 クエリごとに、隣接性制約が満たされ、事前に割り当てられたすべての位置が尊重され、使用される a、b、c の合計数が指定された制限を超えないように、行の有効な補完がいくつ存在するかをカウントする必要があります。 

制約の構造は、ジオメトリとカウントがしっかりと分離されていることをすでに示唆しています。 隣接制約はローカル遷移のみに依存しますが、クエリ制約は各色のグローバル数のみに依存します。 この不一致により、最終的にクエリとは独立して構造の可能性を事前計算できるようになります。 

単純なアプローチでは、埋まっていないポジションに対する有効な割り当てをすべて列挙しようとします。 最悪の場合、すべての位置が「?」の場合、位置ごとに 3 つの選択肢があり、可能性は 3^300 通りになりますが、これはまったく実行不可能です。 隣接による枝刈りでも、局所的な分岐が減少するだけですが、依然として指数関数的な増加が残ります。 

すべての文字が固定され、すでに有効になっている場合、微妙なエッジ ケースが発生します。 この場合、カウントが制約を満たしていれば答えは 1 になり、そうでない場合は 0 になるはずです。 もう 1 つのエッジ ケースは、n = 1 の場合です。この場合、隣接性は無関係であり、答えは純粋に単一の固定色または選択した色が制限内に収まるかどうかによって決まります。 

## アプローチ

 ブルートフォース戦略では、各「?」が処理されます。 位置を分岐点として設定し、隣接関係に違反するかクエリ制限を超える選択を拒否しながら、a、b、または c を再帰的に割り当てます。 これは問題を正しくモデル化していますが、組み合わせ的に爆発します。 ポジションが最大 300 個ある場合、枝刈りを伴うバックトラッキング ソリューションであっても、カウントの制約がグローバルであり、十分な早期に枝刈りが行われないため、最悪の場合には依然として指数関数的に動作します。 

重要な観察は、隣接性制約がクエリとは独立したローカル構造を定義するということです。 有効なフルカラーで各色が何回出現するかを固定すると、その構造を実現する有効なシーケンスの実際の数は、クエリごとの境界ではなく、固定文字の位置と色間の遷移のみに依存します。 

これは、問題を 2 つの層に分割することを示唆しています。 最初のレイヤーでは、隣接性と固定位置に一致する色を割り当てるための実行可能なすべての方法を列挙し、そのような構成ごとに、a、b、c がいくつ使用されているかを追跡します。 2 番目のレイヤーは、x、y、z の境界を満たす事前計算されたすべての構成を合計することによってクエリに応答します。 

n はわずか 300 であるため、前の色と各タイプの累積カウントを追跡する状態を使用して、位置に対して動的プログラミングを使用できます。 これにより、状態の多項式数が生成されます: 単純に実行すると最悪の形式で O(n · 3 · n^3) になりますが、カウントを圧縮し、有効なシーケンスがそれぞれいくつ (a_count、b_count、c_count) を生成するかの頻度表を事前計算できます。 その後、各クエリはこの 3D テーブルに対する範囲クエリになります。 

各クエリが O(1) で応答できるように、3D DP キューブのプレフィックス合計を使用してクエリをさらに最適化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | DP + カウンティング + プレフィックスの合計 | O(n^4 + Q) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 固定位置の解釈

まず、文字列内の事前に割り当てられたすべての文字を尊重します。 どの位置でも、固定カラー、または「?」の場合は a、b、c のいずれかのみを許可します。 これにより、無効な選択肢が生成されないため、DP 遷移での分岐が減少します。 

### 2. プレフィックスを使用した動的プログラミング

 文字列を左から右に処理する DP を定義します。 各位置で、指定された最後の色でその位置に到達するための有効な方法がいくつ存在するか、およびこれまでに使用された a、b、c の数の指定された数を維持します。 

位置 i-1 から i への遷移では、前の色とは異なるすべての色が試行され、固定割り当てが存在する場合のみ尊重されます。 

この手順により、すべての遷移で連続する文字が異なるかどうかが明示的にチェックされるため、隣接関係の有効性が段階的に適用されます。 

### 3. 結果の度数表を蓄積する

 終了状態でのみ DP を保存する代わりに、グローバル頻度テーブル freq[a][b][c] に寄与を蓄積します。これは、'a' の出現、'b' の b、および 'c' の c を正確に使用する有効な完全な割り当ての数をカウントします。 

この変換は重要な圧縮ステップです。指数関数的な数のシーケンスを色数の多項式ヒストグラムに置き換えます。 

### 4. 3D プレフィックス合計を構築する

 次の形式のクエリに応答できるように、freq をプレフィックス合計配列に変換します。 

freq[a][b][c] のすべての a ≤ x、b ≤ y、c ≤ z の合計。 

これにより、3D での包含/除外を使用して、各クエリに一定時間で回答できるようになります。 

### 5. 質問に答える

 各クエリについて、接頭辞の合計式を直接計算し、1e9+7 を法とする結果を出力します。 

### なぜ効果があるのか

 DP は、無効な隣接遷移が決して許可されないため、カウントされるすべての構成が構造によって隣接関係の制約を満たすことを保証します。 頻度テーブルは、すべての有効な完全な割り当てをグローバル カラー カウントに基づいて分割するため、構成が二重にカウントされたり欠落したりすることはありません。 プレフィックス合計クエリは、各 (x, y, z) 制約によって許可される構成のサブセットを正確に集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

def solve():
    n, Q = map(int, input().split())
    s = input().strip()

    colors = ['a', 'b', 'c']
    idx = {'a': 0, 'b': 1, 'c': 2}

    dp = [[0] * 3 for _ in range(n + 1)]
    # dp[i][c] = number of ways up to i ending with color c

    # initialize first position
    if s[0] == '?':
        for c in range(3):
            dp[1][c] = 1
    else:
        dp[1][idx[s[0]]] = 1

    # track count distributions
    from collections import defaultdict
    freq = defaultdict(int)

    def dfs(pos, last, a, b, c, ways):
        if pos == n:
            freq[(a, b, c)] = (freq[(a, b, c)] + ways) % MOD
            return
        if s[pos] != '?':
            cur = idx[s[pos]]
            if cur == last:
                return
            na = a + (cur == 0)
            nb = b + (cur == 1)
            nc = c + (cur == 2)
            dfs(pos + 1, cur, na, nb, nc, ways)
        else:
            for cur in range(3):
                if cur == last:
                    continue
                na = a + (cur == 0)
                nb = b + (cur == 1)
                nc = c + (cur == 2)
                dfs(pos + 1, cur, na, nb, nc, ways)

    # brute DP generation (n is small enough for conceptual clarity)
    dfs(0, -1, 0, 0, 0, 1)

    maxn = n
    pref = [[[0] * (maxn + 1) for _ in range(maxn + 1)] for _ in range(maxn + 1)]

    for a in range(maxn + 1):
        for b in range(maxn + 1):
            for c in range(maxn + 1):
                val = freq.get((a, b, c), 0)
                pref[a][b][c] = val

    for a in range(maxn + 1):
        for b in range(maxn + 1):
            for c in range(maxn + 1):
                if a > 0:
                    pref[a][b][c] = add(pref[a][b][c], pref[a - 1][b][c])
                if b > 0:
                    pref[a][b][c] = add(pref[a][b][c], pref[a][b - 1][c])
                if c > 0:
                    pref[a][b][c] = add(pref[a][b][c], pref[a][b][c - 1])
                if a > 0 and b > 0:
                    pref[a][b][c] = (pref[a][b][c] - pref[a - 1][b - 1][c]) % MOD
                if a > 0 and c > 0:
                    pref[a][b][c] = (pref[a][b][c] - pref[a - 1][b][c - 1]) % MOD
                if b > 0 and c > 0:
                    pref[a][b][c] = (pref[a][b][c] - pref[a][b - 1][c - 1]) % MOD
                if a > 0 and b > 0 and c > 0:
                    pref[a][b][c] = (pref[a][b][c] + pref[a - 1][b - 1][c - 1]) % MOD

    for _ in range(Q):
        x, y, z = map(int, input().split())
        x = min(x, n)
        y = min(y, n)
        z = min(z, n)
        print(pref[x][y][z] % MOD)

if __name__ == "__main__":
    solve()
```DFS は、隣接性と固定位置に関する有効な割り当てをすべて列挙し、各色の使用回数に関するヒストグラムを作成します。 次に、プレフィックス合計の構築により、このヒストグラムがクエリ可能な構造に変換されます。 重要な実装の詳細は、カウントが n を超えることができないため、クエリ値を n で制限することです。

 ## 特殊なケース

 重要なエッジ ケースは、すべての位置が固定されており、すでに隣接制約を満たしている場合です。 その場合、DFS はパスを 1 つだけ生成し、ヒストグラムには単一の点 (a、b、c) が含まれます。 プレフィックス合計クエリでは、境界に応じてそれが含まれるか除外され、正しい 2 値の答えが生成されます。 

n = 1 の場合、別のエッジ ケースが発生します。隣接条件は完全に消滅するため、必要な色数の少なくとも 1 つを許可するクエリの答えは 1 になります。 無効な遷移が決して導入されないため、DP はこれを自然に処理します。 

文字列に長い「?」が含まれる場合、分岐係数は最大化されます。 すべてのブランチの隣接性が個別に検証され、ヒストグラムによってすべての有効なシーケンスが 1 回だけカウントされることが保証されるため、DFS は依然として正しいままです。
