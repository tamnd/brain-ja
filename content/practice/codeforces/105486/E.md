 ## 解決策
 ## 問題の理解

 ツリーが与えられているため、ノードのすべてのペアは 1 つの単純なパスによって接続されています。 この構造に加えて、接続されている可能性のある多くのサブグラフを考慮します。これは、すべてが接続されたままになるように、ツリーからノードとエッジのセットを選択することを意味します。 

各クエリに対して、2 つのノード u と v が与えられます。「通信」は、これら 2 つのノード間の一意のパスに沿って進むと想定されます。 選択された接続されたサブグラフは、u から v へのパス上に少なくとも 1 つのノードを含む場合、この通信を「中断」します。 

したがって、クエリごとに、何も構築する必要はありません。 元のツリーの接続されたサブツリーの数が u と v の間のパスと交差する数をカウントし、このカウントのモジュロ 998244353 を出力する必要があります。 

一般に、ツリー内の接続されたサブツリーの数はすでに指数関数的であるため、適度な n の場合でも出力は大きくなります。 n がテスト ケースごとに最大 10^5 で、合計 n、q が最大 3·10^5 であるため、クエリごとの列挙は不可能です。 クエリごとに O(n) であっても遅すぎます。 前処理後のクエリごとに O(log n) または O(α(n)) に近いものが必要です。 

u が v に等しい場合、微妙なエッジ ケースが発生します。その場合、「パス」は単一のノードにすぎないため、そのノードを含む接続されたサブツリーはすべて有効です。 答えは、特定のノードを含む接続されたサブツリーの数になります。これらのサブツリーは、同じフレームワークから自然に抜け出す必要があります。 

もう 1 つの重要な微妙な点は、誘導されたサブグラフを扱っていないことです。 選択した構造が接続されている限り、ノードとエッジを選択します。 接続されたサブツリーのカウントは、誘導されたエッジではなく、ルート付きツリー DP の親子構造のみに依存するため、この区別は重要です。 

素朴な間違いは、DP の再ルートまたは再構築によってクエリごとに「パスを回避するすべてのサブツリー」のようなものを再計算する必要があると考えることです。ただし、パスはクエリごとに変更されるため、クエリごとの再計算は制約の下では失敗します。 

## アプローチ

 私たちは直接的な視点から始めます。 ツリー内の接続されたサブグラフは、接続されたサブツリーです。 このようなオブジェクトをカウントする古典的な方法は、ツリーをルート化し、各ノード u について、u を含み、そのルート化されたサブツリー内に完全に存在する接続されたサブツリーの数を計算することです。 この値を dp[u] と呼ぶことにします。 

u がルート ツリーに子 v1、v2、... を持っている場合、u を含む接続されたサブツリーは、子サブツリーごとに、その子サブツリーから何も含めないか、その子から始まる接続されたサブツリーを含めるかを独立して選択できます。 これにより、標準的な繰り返しが得られます。 

dp[u] = ∏(1 + dp[子])

 すべての u について dp[u] を合計すると、ツリー内の接続されたサブツリーの総数が得られます。 

次に、クエリ条件を再解釈します。 サブツリーが u と v の間のパス上のすべてのノードを回避する場合、クエリ (u, v) には適していません。したがって、答えは次のようになります。 

接続されたサブツリーの合計から、パス上のすべてのノードを回避する接続されたサブツリーを差し引いたもの。 

重要な観察は、u から v へのパス上のすべてのノードをツリーから削除すると、残りのノードは互いに素なコンポーネントに分割され、それぞれが依然としてツリーであるということです。 パスを回避する接続されたサブツリーはすべて、そのようなコンポーネントの 1 つの内部に完全に存在する必要があります。 

このような各コンポーネント内では、接続されたサブツリーの数は、そのコンポーネント内のノード x にわたる dp[x] の合計となります。これは、dp[x] がその下位構造内で「x をルートとする」接続されたサブツリーをカウントし、これは、削除されたパスへの接続が切断されても有効なままであるためです。 

したがって、パスの補数は、単純に、u から v へのパス上にないすべてのノード x にわたる dp[x] の合計として寄与します。 

これにより、すべてのクエリが次のように削減されます。 

答え = total_dp_sum − sum(パス(u, v)上のxのdp[x])

 したがって、問題全体は、ノードの重み dp[x] に対するツリー パス合計クエリになります。ここで、dp[x] は前処理後に固定されます。

1 つの DFS で dp を計算します。 次に、標準的な重光分解または LCA ベースのパス分解構造である高速パス合計クエリが必要になります。 

したがって、ボトルネックは、サブツリーの列挙から重み付けされたパス合計の応答まで軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース列挙 | 指数 | O(n) | 遅すぎる |
 | HLD を介したツリー DP + パス合計クエリ | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、ポストオーダー トラバーサルを使用してすべてのノードの dp[u] を計算します。 各ノードの dp[u] は、(1 + dp[v]) の子の積です。 これは、u のサブツリーに完全に含まれ、u を含むすべての接続されたサブツリーをエンコードします。 
2. dp を計算するときに、すべてのノードにわたる total_dp = dp[u] の合計も累積します。 これは、ツリー全体内のすべての接続されたサブツリーを表します。 
3. ツリーの重光分解を構築します。 各ノードは、任意のパスを O(log n) セグメントに分解できるように、基本配列内の位置に割り当てられます。 
4. dp[u] 値を格納するこの基本配列に対してセグメント ツリー (またはフェンウィック ツリー) を構築します。 これにより、HLD セグメントに対する効率的な範囲合計クエリが可能になります。 
5. 各クエリ (u, v) について、HLD を使用して、u と v の間の一意のパス上のすべてのノード x にわたる dp[x] の合計を計算します。 これは、より深いチェーン ヘッドから LCA に向かって繰り返しジャンプし、途中でセグメント範囲を合計することによって行われます。 
6. 出力の答え = total_dp − path_sum(u, v)、998244353 を法として取得され、非負になるように正規化されます。 

### なぜ効果があるのか

 ノードの dp 値は、ルート化されたサブツリー構造に対して純粋にローカルであり、クエリには依存しません。 ノードのセット (パス) を削除しても、そのセットの外側のノードに対する dp の定義方法は変更されません。 最終合計のカウントから一部のノードを削除するだけです。 

除外される唯一の接続されたサブツリーは、パス上に少なくとも 1 つのノードを含むサブツリーです。 パスを回避するサブツリーは残りのフォレストに完全に含まれており、その寄与はパスの外側のノードの dp を合計することによって正確に取得されます。 これにより、接続されたすべてのサブツリーが 2 つの互いに素なグループ (パスと交差するグループとそうでないグループ) に分割され、減算が正確になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n, q = map(int, input().split())
    parent = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]

    for i, p in enumerate(map(int, input().split()), start=2):
        parent[i] = p
        g[p].append(i)
        g[i].append(p)

    # DP for connected subtrees
    dp = [0] * (n + 1)

    order = []
    stack = [1]
    parent[1] = -1

    # build order (iterative DFS)
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    # postorder DP
    for u in reversed(order):
        res = 1
        for v in g[u]:
            if v == parent[u]:
                continue
            res = res * (1 + dp[v]) % MOD
        dp[u] = res

    total = sum(dp) % MOD

    # HLD prep
    sys.setrecursionlimit(10**7)
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    head = [0] * (n + 1)
    sz = [0] * (n + 1)
    heavy = [0] * (n + 1)
    depth = [0] * (n + 1)

    def dfs_sz(u, p):
        sz[u] = 1
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs_sz(v, u)
            sz[u] += sz[v]
            if sz[v] > sz[heavy[u]]:
                heavy[u] = v

    cur = 0
    def dfs_hld(u, h, p):
        nonlocal cur
        head[u] = h
        tin[u] = cur
        cur += 1
        if heavy[u]:
            dfs_hld(heavy[u], h, u)
        for v in g[u]:
            if v == p or v == heavy[u]:
                continue
            dfs_hld(v, v, u)

    dfs_sz(1, 0)
    dfs_hld(1, 1, 0)

    arr = [0] * n
    for i in range(1, n + 1):
        arr[tin[i]] = dp[i]

    class SegTree:
        def __init__(self, a):
            self.n = len(a)
            self.t = [0] * (4 * self.n)
            self.build(1, 0, self.n - 1, a)

        def build(self, i, l, r, a):
            if l == r:
                self.t[i] = a[l]
                return
            m = (l + r) // 2
            self.build(i*2, l, m, a)
            self.build(i*2+1, m+1, r, a)
            self.t[i] = (self.t[i*2] + self.t[i*2+1]) % MOD

        def query(self, i, l, r, ql, qr):
            if ql > r or qr < l:
                return 0
            if ql <= l and r <= qr:
                return self.t[i]
            m = (l + r) // 2
            return (self.query(i*2, l, m, ql, qr) +
                    self.query(i*2+1, m+1, r, ql, qr)) % MOD

        def range_query(self, l, r):
            if l > r:
                return 0
            return self.query(1, 0, self.n - 1, l, r)

    seg = SegTree(arr)

    def path_sum(u, v):
        res = 0
        while head[u] != head[v]:
            if depth[head[u]] < depth[head[v]]:
                u, v = v, u
            res += seg.range_query(tin[head[u]], tin[u])
            res %= MOD
            u = parent[head[u]]
        if depth[u] > depth[v]:
            u, v = v, u
        res += seg.range_query(tin[u], tin[v])
        return res % MOD

    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        s = path_sum(u, v)
        ans = (total - s) % MOD
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のフェーズでは dp 値をボトムアップで計算し、各ノードをルートとする接続されたサブツリーの数をエンコードします。 2 番目のフェーズでは、パス クエリが範囲クエリになるように、これらの dp 値をヘビー-ライト順序付けで静的配列に変換します。 

セグメント ツリーは高速合計をサポートするためにのみ使用されます。 前処理後に動的に変更されるものは何もないため、静的な構造で十分です。 

path_sum 関数は唯一のクエリ依存部分です。 両方のノードが同じ重いパスで出会うまで、より深いチェーン ヘッドを繰り返し持ち上げ、各セグメントに沿って dp 値を蓄積します。 これはまさに、パス集約を対数的な複雑さまで軽減するものです。 

最後に、このパス合計をグローバル合計から減算すると、通信パスと交差するサブツリーが正確に分離されます。 

## 実用的な例

 小さな木を考えてみましょう。 

入力:

 n = 5

 エッジ: 1-2、1-3、3-4、3-5

 DP の計算後、各ノードの dp 値を取得すると仮定します。 次に、(2, 4) などのパスでクエリを処理します。 

### クエリトレース

 | ステップ | あなた | v | アクション | 累計額 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 4 | 2からチェーンを登る | 部分的な dp[2] |
 | 2 | 1 | 4 | 4から鎖を登る | 部分 dp[4] + dp[3] |
 | 3 | 1 | 1 | LCA に達しました | 最終的なパスの合計 |

 重要な観察は、u-v パス上にあるノードのみが減算に寄与するということです。 

2 番目のクエリ (4、5) では、両方のノードが 3 の同じサブツリー内にあるため、パスは完全にその領域内にあります。 収集される合計は dp[4] + dp[3] + dp[5] で、そのパス上のノードを正確に反映します。 

これらのトレースは、path_sum 関数が通信コリドーを正確に分離していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | DP は線形であり、HLD では各クエリを対数のセグメントに分解できます。 
| スペース | O(n) | 隣接リスト、dp 配列、およびセグメント ツリーのストレージ |

 この制約により、ノードとクエリの合計は最大 3·10^5 まで許可されるため、クエリごとに O(log n) のソリューションが必要になります。 前処理は線形であり、制限内に快適に収まりますが、重光分解により各クエリの効率性は維持されます。

 ## 特殊なケース

 1 つのエッジ ケースは、u が v に等しい場合です。この場合、パスには単一のノードが含まれます。 アルゴリズムの path_sum 関数は、そのノードの dp 値をクエリするだけで正しく処理されます。 答えは total から dp[u] を引いたものになります。これは、u を含むすべてのサブツリーを除外し、それを避けるサブツリーのみを残すという事実と一致します。 

もう 1 つのエッジ ケースは、チェーン内の 2 つのリーフ間のクエリなど、パスがほぼツリー全体に及ぶ場合です。 この場合、HLD 分解は完全なセグメントのシーケンスに縮小され、チェーン上のすべてのノードが減算合計に 1 回だけ含まれます。 dp 値は固定されており、クエリ構造とは独立しているため、減算は引き続き機能します。 

3 番目のエッジ ケースは、多くのノードがルートに直接接続されている星型ツリーで発生します。 2 つのリーフ間のクエリではルートを経由するパスが強制されるため、dp[root] は常に減算に含まれます。 HLD パスにはルートが 1 回だけ含まれるため、アルゴリズムはこれを正しく考慮します。
