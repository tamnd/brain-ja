 ## 解決策
 ## 問題の理解

 順列が与えられています`p`サイズの`n`。 タスクは別の順列を構築することです`q`どの位置も元の値を保持しないように、すべてのインデックスを意味します。`i`、値`q[i]`とは異なっていなければなりません`p[i]`。 このようなすべての有効な順列の中で、絶対偏差の合計を最小にするものが必要です。`∑ |p[i] − q[i]|`。 これらの最適な順列はセットを形成します。最終的な要件は、それらのうちの 1 つを見つけるだけでなく、それらを辞書順にリストし、k 番目に小さいものを出力することです。`-1`未満の場合`k`存在する。 

ここでの重要なオブジェクトは、単なる乱れではなく、元の順列までの L1 距離の下で全体的に最適な乱れです。 このことから、ローカル スワップは重要であるが、その相互作用は最適性によって制約されることがすぐにわかります。 

制約は大きいです。 合計`n`テスト ケース全体では最大 10^6 のテストがあり、最大 10^4 のテストがあります。 すべての順列、さらにはすべての乱れを生成しようとする解決策は不可能です。 テストごとに O(n log n) であっても境界線にありますが、許容されます。 これにより、各要素が本質的に一定時間または対数時間で処理される構造へと私たちは追い込まれ、最適解の構造は非常に厳格でなければなりません。 

各位置で可能な限り最小の有効な値を貪欲に割り当てようとすると、単純な故障モードがすぐに現れます。 たとえば、次の場合`p = [1,2,3,4]`、貪欲に割り当てる`q[i] != p[i]`また、ローカルコストを最小限に抑えると、グローバルに分散する複数の選択肢が生成される可能性があり、すべてが最適なグローバル合計につながるわけではありません。 もう 1 つの失敗例は、どのような乱れも同等に良好であると仮定した場合ですが、これは誤りです。これは、遠く離れた値を交換すると絶対差が不必要に増加するためです。 

より微妙なエッジケースは次のような場合です。`p[i] = i`。 その場合、いかなる混乱も値をその同一位置から遠ざける必要があり、最適な構造は隣接する値をペアにする傾向があります。 もし`p = [1,2,3]`、有効な混乱は次のとおりです。`[2,3,1]`そして`[3,1,2]`、どちらも同じコストですが、辞書編集上の順序は k の選択にとって重要です。 

## アプローチ

 ブルートフォース戦略では、すべての順列を列挙します。`q`、すべての位置が次と異なるかどうかを確認します。`p[i]`、コストを計算します`∑ |p[i] − q[i]|`、最小コストの順列のみをフィルタリングし、辞書順に並べ替えます。 これは、検索空間全体を探索するため、原理的には正しいですが、すぐには実行不可能です。 がある`n!`順列、さらには`n = 10`、これはすでに大きすぎます、ましてや`n = 2 * 10^5`。 

重要な構造観察は、何がコストを最小限に抑えるのかを理解することから生まれます。 コストは、位置に割り当てられた値のペアにのみ依存し、値が並べ替えられた順序で近くの値に割り当てられる場合、絶対的な差は最小化されます。 以来`p`はすでに次の順列です`1..n`、強制中に絶対的な動きの合計を最小限に抑える唯一の方法`q[i] != p[i]`恣意的な再配置ではなく、タイトなサイクルでスワップを実行することです。 

これは中心的なアイデアにつながります。つまり、インデックスを独立したローカル構造に分割することによって最適な混乱が形成され、そこで値が小さなグループ間で交換され、各グループが辞書編集的に順序付けられたソリューションに独立して貢献します。 実際には、この構造は、ソートされた順序で隣接する値の間で強制的に交換されるセットに崩壊します。`p`。 

この構造が特定されたら、残りのタスクは、存在する選択肢の数を数え、各ステップでどのスワップ構成を選択するかをローカルに決定することによって、辞書編集的に最小の k 番目の選択肢を構築することです。

 ## アルゴリズムのチュートリアル

 まずインデックスを次の値で並べ替えます。`p[i]`これにより、各値の ID が昇順で得られます。 させて`pos[x]`値が含まれるインデックスになります`x`に登場する`p`。 順列を構築しているので、`q`値を超える`1..n`では、ソートされた順序でターゲット値を割り当てるという観点から考えます。 

重要な構造上の事実は、最適なソリューションでは、値空間の小さな連続セグメント内でのみ値を再割り当てする必要があるということです。 重要なセグメントは、値のソート順にある連続したブロックのみです。 各ブロック内では、元の位置に値が残っていないことを確認する必要があります。これは、最小の変位を維持しながらそのブロックの乱れを見つけることと同じであり、スワップ構造を強制します。 

以下の値を処理します。`1`に`n`、それらを最大セグメントにグループ化し、乱数制約に違反することなく連続した値を並べ替えることができます。 各セグメント内で、最適な構成は隣接するペアを交換することに対応します。 セグメントに長さがある場合`L`、その後、`L`偶数であれば、完全にペアリングできます。 もし`L`が奇数の場合、1 つの値は隣接するセグメントにシフトしてパターンを破らなければなりません。これにより、有効なグローバル構造の数が減少します。 

セグメントが特定されたら、セグメントごとに有効な構成がいくつ存在するかを計算し、それらを乗算して合計数を取得します。 これにより、k をガイドとして使用できるようになります。セグメントを左から右に繰り返し、各セグメントで、k と各ブランチ内の構成の数を比較して、どのローカル構成を選択するかを決定します。 

最後に、構築します`q`各セグメント内で選択したスワップを適用し、要素が元の位置に残らないようにします。 

### なぜ効果があるのか

 不変条件は、最適性が連続する値ブロックに対して局所的な最適性を強制することです。 隣接する実行可能なブロックの外に値を移動しようとすると、必要以上に大きなギャップが生じるため、絶対偏差が厳密に増加します。 これにより、グローバル最適化が独立したセグメントレベルの決定に分解され、辞書編集上の順序付けが左から右のセグメント解像度に合わせて行われるため、すべての解を生成せずに分割をカウントすることで k 番目の選択が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i

        # build value order structure
        used = [False] * (n + 1)
        q = [0] * n

        i = 1
        ways = 1

        # compute structure in value space
        segments = []
        start = 1

        while start <= n:
            end = start
            while end < n:
                # extend segment if adjacent values are "safe"
                if abs(pos[end] - pos[end + 1]) == 1:
                    end += 1
                else:
                    break
            segments.append((start, end))
            start = end + 1

        # each segment has 2 choices if length >= 2, otherwise impossible
        total = 1
        for l, r in segments:
            length = r - l + 1
            if length == 1:
                total = 0
                break
            total *= 2

        if k > total or total == 0:
            print(-1)
            continue

        # decide per segment lexicographically
        res = [0] * n

        for l, r in segments:
            length = r - l + 1
            take_first = (k <= (total // 2)) if length > 1 else False

            if length > 1:
                total //= 2
            else:
                continue

            if take_first:
                for x in range(l, r + 1, 2):
                    a, b = x, x + 1
                    res[pos[a]] = b
                    res[pos[b]] = a
            else:
                k -= total
                for x in range(l, r + 1, 2):
                    a, b = x, x + 1
                    res[pos[a]] = b
                    res[pos[b]] = a

        print(*res)

if __name__ == "__main__":
    solve()
```この解決策は逆位置配列を構築するので、インデックス空間ではなく値空間で推論できるようになります。 値の昇順で割り当てを決定すると、辞書編集上の順列の順序付けが簡単になるため、これは不可欠です。 

セグメンテーション ステップでは、元の位置が隣接している連続する値をグループ化します。これは、ローカル スワップが最小限の変位を維持することを特徴とします。 各セグメントは、ペアの形成方法に対応する二者択一の選択肢に寄与します。 

k 選択は、各セグメントを 2 つの選択肢の係数に寄与するものとして扱い、バイナリ パーティション方式で k を消費することによって行われます。 選択が決定したら、セグメント内でスワップを直接適用します。 

実装の微妙な詳細は、セグメントは値空間内で厳密に定義する必要があるが、位置の隣接性を使用して検証する必要があることです。 そうしないと、互換性のない値が誤ってマージされ、混乱の制約に違反してしまいます。

### 例 2

 入力:```
n = 4, p = [2,1,4,3], k = 1
```ポジション:`pos[1]=1, pos[2]=0, pos[3]=3, pos[4]=2`。 

セグメントは`[1,2]`そして`[3,4]`。 

| セグメント | 長さ | 残りの選択肢 | k 状態 |
 | --- | --- | --- | --- |
 | [1,2] | 2 | 2 | k = 1 |

 セグメント用`[1,2]`、最初の辞書編集を行い、次のようになります。`(1↔2)`。 のために`[3,4]`、最初のスワップも行います。 

最終的な順列:```

```このトレースは、独立したセグメントの決定が全体的な結果を完全に決定することを示しています。

 ## 特殊なケース

 最小限のエッジケースは次のような場合です`n = 2`。 考えられる唯一の混乱は、2 つの値を交換することです。 アルゴリズムは単一のセグメントを形成します`[1,2]`、2 つの対称構造を数え、それに基づいて選択します。`k`。 もし`k > 1`、正しく拒否されます。 

すべての値が既に連続した隣接位置にある場合、別のエッジ ケースが発生します。`p`、 のような`p = [1,2,3,4,5]`。 ここでは、配列全体が 1 つのセグメントになります。 このアルゴリズムは問題を隣接するスワップの繰り返しに軽減し、辞書編集上の順序付けは純粋にセグメントの選択によって解決され、一貫したグローバルな順序付けが保証されます。 

3 番目のエッジ ケースは、セグメンテーションによって単一要素ブロックが生成される場合です。 これらのブロックを混乱させることはできず、即時拒否を強制されます。 例えば`p = [1]`不可能ですが、より大きな配列であっても、構造内のシングルトン セグメントはすべての構造を無効にします。 アルゴリズムはカウントをゼロにして返し、これを検出します。`-1`。
