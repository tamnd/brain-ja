 ## 解決策
 ## 問題の理解

 私たちには、10×9 のチェス盤と、中国のチェスからインスピレーションを得た 6 つの動きタイプのいずれかに属する隠し駒が与えられます。 その種類や位置はわかりません。 代わりに、候補となる位置の小さなセットが与えられ、敵は真の位置がこのセットの中にあることを保証します。 

セルに質問することでボードと対話できます。 各クエリ セルについて、非表示のピースが移動ルールを使用していると仮定して、そのセルに到達するために必要な最小移動数を受け取ります。セルに到達できない場合は -1 を受け取ります。 攻撃者は事前に固定されていません。攻撃者は、クエリのたびに、可能な限り私たちを遅らせるために、以前のすべての回答に一致する一貫した隠れ状態 (許可されたセットからの駒の種類と位置) を選択する可能性があります。 

私たちの仕事は、できるだけ少ないクエリを使用してピースの種類を決定することであり、重要なことは、クエリの数を事前に発表する必要があることです。 

すべてを動かす重要な制約は、取締役会が小さく、候補セットのポジションが最大 90 であることです。 これは、隠れ状態空間が十分に小さいため、タイプと候補位置のすべての組み合わせの実現可能性を追跡する推論ができることを意味します。 私たちが求めているのは、大きなグリッドにわたる漸近的な最適化ではなく、動きのメトリクスを区別する慎重に選択された「プローブ」のセットです。 

微妙なエッジ ケースは、敵対者の対話型の動作です。 固定された隠れた位置を前提とする素朴なアプローチは、論理的に破綻します。 たとえば、単一の位置を想定し、それを最初に再構築しようとすると、敵対者はいつでも、他のピース タイプで同じ距離が得られる候補セット内の別の位置から回答が来たものとして再解釈する可能性があります。 このため、単一の位置を再構成するのではなく、すべてのタイプと位置のペアにわたる一貫性の観点から推論する必要があります。 

## アプローチ

 ブルートフォースのメンタルモデルは単純です。 与えられたセット内のすべての駒の種類とすべての候補位置について、その仮想状態が隠れた状態である可能性があるかどうかをシミュレートします。 各クエリには距離の制約が与えられ、これまでのすべての回答と一致する状態のみが維持されます。 インタラクターは常に少なくとも 1 つの有効な状態で一貫して応答するように制約されているため、このアプローチは正しいです。 

しかし、「状態を直接特定」しようとすると、最大 540 個の可能性 (6 種類×最大 90 個の位置) が残ることになります。 最悪の場合、各クエリは未知のメトリックの下でスカラー距離のみを提供するため、任意の点をクエリしてそれらを区別するには多くの適応ステップが必要になる可能性があります。 

重要な観察は、実際には位置を特定する必要がまったくないということです。 固定された小さな領域上でピース タイプによって引き起こされる 6 つの距離関数を区別するだけで済みます。 ボードは固定されており小さいため、各クエリにより、すべての候補状態に対するラベル付き関数の評価が効果的に得られます。 6 つのメトリクスは 10×9 グリッド上で基本的に異なる幾何学的な特徴を引き起こすため、慎重に選択された少数のプローブ セルで 6 つのメトリクスすべてを分離するのに十分です。 

したがって、適応的に検索する代わりに、さまざまな動きの構造を「刺激」するクエリ ポイントの小さなセットを修正し、どのタイプがすべての応答と一貫性を保っているかを分類します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 多くの適応クエリを使用したブルート フォース状態除去 | O(クエリごとに 6·n、多数のクエリ) | O(n) | 遅すぎる/不必要 |
 | プローブクエリの修正 + 一貫性フィルタリング | O(6・n・m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

クエリするボードポジションの小さなセットを事前に選択します。 これらの位置の目的は、ピースを見つけることではなく、対称と非対称の動き、パリティの制約、マンハッタンのような到達可能性とジャンプベースの到達可能性など、動きのルール間の構造的な違いを明らかにすることです。 

次に、次のように進めます。 

## アルゴリズムのチュートリアル

 1. 候補位置の数を読み取り、保存します。 これらは、隠された部分の唯一の有効な開始点であるため、検討するすべての仮説はこのセットから得られる必要があります。 
2. コーナーや中心点など、ボード全体に広がるクエリ セルの小さなセットを修正します。 直観的には、極端な位置では、列に応じて異なる動きをするポーンのような境界効果が検出され、中央の位置では純粋な動きのジオメトリが明らかになります。 
3. 選択したクエリ セルごとに、クエリを出力し、応答を読み取ります。 各応答は、非負の整数の距離、または到達不能な位置の場合は -1 です。 
4. すべての応答を収集した後、指定されたセットからピース タイプと候補位置で構成されるすべての仮説ペアをシミュレートします。 仮説ごとに、その移動ルールに基づいて同じクエリ セルに対してどのような応答が生成されるかを計算します。 
5. 仮説が、到達不可能なケースを含む、観察されたすべての応答と正確に一致する場合にのみ、仮説を有効としてマークします。 この整合性チェックにより、敵の戦略の下でまだ隠されている可能性のある状態のみを保持することが保証されます。 
6. フィルタリング後、すべての有効な仮説にわたって、正確に 1 つの部分タイプが一貫したままになります。 その型を答えとして出力します。 

これが機能する理由は、ピース タイプが異なると、グリッド上で基本的に異なる最短パス メトリクスが定義されるためです。 位置が不明であっても、この相互作用により、どの計量ファミリーが少数のサンプリングされた距離評価と互換性があるかを特定するという問題が軽減されます。 候補セットが小さいため、位置の曖昧さは状態空間に吸収され、区別できるのはタイプだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Board size
R, C = 10, 9

def inb(r, c):
    return 0 <= r < R and 0 <= c < C

# Precompute moves for each type as adjacency rules
def build_graph(piece, sr, sc):
    vis = [[-1] * C for _ in range(R)]
    from collections import deque
    q = deque()
    q.append((sr, sc))
    vis[sr][sc] = 0

    while q:
        r, c = q.popleft()
        d = vis[r][c]

        if piece == 'J':  # King
            dirs = [(1,0),(-1,0),(0,1),(0,-1)]
            for dr, dc in dirs:
                nr, nc = r + dr, c + dc
                if inb(nr, nc) and vis[nr][nc] == -1:
                    vis[nr][nc] = d + 1
                    q.append((nr, nc))

        elif piece == 'S':  # Mandarin (diagonal king)
            dirs = [(1,1),(1,-1),(-1,1),(-1,-1)]
            for dr, dc in dirs:
                nr, nc = r + dr, c + dc
                if inb(nr, nc) and vis[nr][nc] == -1:
                    vis[nr][nc] = d + 1
                    q.append((nr, nc))

        elif piece == 'C':  # Rook-like (row/col anywhere in 1 move)
            # generate all same row/col in 1 step
            for nc in range(C):
                if nc != c and vis[r][nc] == -1:
                    vis[r][nc] = d + 1
                    q.append((r, nc))
            for nr in range(R):
                if nr != r and vis[nr][c] == -1:
                    vis[nr][c] = d + 1
                    q.append((nr, nc))

        elif piece == 'M':  # Knight
            jumps = [(2,1),(2,-1),(-2,1),(-2,-1),
                     (1,2),(1,-2),(-1,2),(-1,-2)]
            for dr, dc in jumps:
                nr, nc = r + dr, c + dc
                if inb(nr, nc) and vis[nr][nc] == -1:
                    vis[nr][nc] = d + 1
                    q.append((nr, nc))

        elif piece == 'X':  # Bishop-like (2,2 jumps)
            for dr in [2, -2]:
                for dc in [2, -2]:
                    nr, nc = r + dr, c + dc
                    if inb(nr, nc) and vis[nr][nc] == -1:
                        vis[nr][nc] = d + 1
                        q.append((nr, nc))

        elif piece == 'B':  # Pawn-like
            moves = [(1,0),(0,1),(0,-1)]
            if r <= 4:
                moves.append((1,0))
            for dr, dc in moves:
                nr, nc = r + dr, c + dc
                if inb(nr, nc) and vis[nr][nc] == -1:
                    vis[nr][nc] = d + 1
                    q.append((nr, nc))

    return vis

def query(r, c):
    print(f"? {r} {c}")
    sys.stdout.flush()
    return int(input())

def main():
    n = int(input())
    A = [tuple(map(int, input().split())) for _ in range(n)]

    queries = [(0,0), (0,8), (9,0), (9,8), (4,4)]
    answers = []

    for r, c in queries:
        answers.append(query(r, c))

    candidates = set(['J','S','C','M','X','B'])

    for t in list(candidates):
        ok = False
        for sr, sc in A:
            dist = build_graph(t, sr, sc)
            if all(dist[r][c] == answers[i] for i, (r, c) in enumerate(queries)):
                ok = True
                break
        if not ok:
            candidates.remove(t)

    print("! " + list(candidates)[0])
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```この実装は、すべての (タイプ、位置) ペアを仮説として扱うという考えに従います。 各仮説について、その駒の移動ルールを使用してボード上の BFS を使用して完全な距離マップを計算します。 各クエリは制約に寄与し、すべての制約に正確に一致する仮説のみを保持します。 最後に残ったタイプが答えです。 

重要な実装の詳細は、到​​達不可能な状態を無限または -1 として扱う必要があるため、到達可能な値との不一致があれば、仮説が直ちに無効になるということです。 

## 実用的な例

 隠し駒がルークのような駒であるシナリオを考えてみましょう。 候補セットに複数の行と列にわたる位置が含まれているとします。 四隅と中央をクエリした後、ルーク仮説は一貫した行/列距離を生成しますが、ナイト仮説とビショップ仮説はパリティとジャンプ構造の不一致により失敗します。 

| クエリ | (0,0) | (0,8) | (9,0) | (9,8) | (4,4) |
 | --- | --- | --- | --- | --- | --- |
 | 応答 | 2 | 3 | 4 | 5 | 2 |

 行 4、列 4 に整列した候補位置から始まるルークの仮説の場合、これらすべての値を同時に一致できるのはルーク メトリクスのみですが、キングまたはナイトの距離はステップの制約により失敗します。 

このトレースは、フィルタリング メカニズムがピースの位置を特定することに依存しているのではなく、互換性のない動作ジオメトリを除去することに依存していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(6・n・R・C) | タイプと候補位置ごとに、10×9 ボード上の BFS を計算します。 
| スペース | O(R・C) | 仮説ごとに再利用された距離グリッド |

 基板サイズと候補セットの両方が小さいため、計算は十分に制限内に収まります。 完全なシミュレーションを行ったとしても、状態の総数はクエリ フェーズごとに数千操作未満です。

 ## 特殊なケース

 重要なエッジ ケースは、あるピース タイプに対するすべてのプローブ クエリの下で、複数の候補位置が同じように動作する場合です。 たとえば、クエリ セットに対して対称な位置により、同一の距離ベクトルが生成される可能性があります。 アルゴリズムは位置を区別せず、タイプのみを区別しようとするため、これを正しく処理します。 対称的な曖昧さは、単一タイプの仮説空間内に残ります。 

もう 1 つの特殊なケースは、到達不能なクエリです。 ピースがクエリされたセルに到達できない場合、応答は -1 になります。 これは厳密な制約として扱う必要があります。 よくある間違いは、-1 を無視して大きな数として扱うことであり、ビショップのようなパリティ制約とルークのような無制限の動きを誤って結合してしまいます。 ここでは、到達可能性の平等を明示的に要求します。これにより、すべての動作ファミリーにわたって正確さが維持されます。
