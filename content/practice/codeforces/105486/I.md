 ## アルゴリズムのチュートリアル

 ブロック内の単調性を破ることができるのは隣接する反転だけであるため、隣接する反転を中心に問題を再定式化します。 

1. 位置をマークする差分配列を計算します。$i$最悪だったら$a[i] > a[i+1]$。 これにより、あらゆるパーティション サイズに関係するすべてのローカル違反がキャプチャされます。 これが機能する理由は、非減少ブロックは、ブロック内に隣接する降下がないことと同等であるためです。 
2. 可能なすべてのクエリを実行できるグローバル構造を維持します。$k$不良ペアがそのブロック内に完全に存在するかどうか$k$。 明示的に反復する代わりに$k$、各不良ペアの寄与を全体にわたって集計します。$k$。 
3. ペアが の位置にあることを観察します。$i$それらの人々の無効に寄与する$k$どこ$i$そして$i+1$同じセグメントに分類されます。 この条件は以下にのみ依存します。$k$そして$i$なので、いくつあるかを事前に計算します。$k$各インデックス ペアは、無効なインデックスの累計を無効にし、維持します。$k$。 
4. 答えを次のように初期化します。$n$、無効な数を減算します。$k$アクティブな不良ペアが原因です。 ポジション全体の頻度構造を維持し、その数を迅速に更新します。$k$新規または削除されたそれぞれの反転が影響します。 
5. 位置の更新ごとに$p$、ペアのみ$(p-1, p)$そして$(p, p+1)$ステータスを変更できる。 古いコントリビューションが悪ければ削除し、値を更新し、悪くなったら新しいコントリビューションを挿入します。 

このローカライズされた更新が機能する主な理由は、有効性条件が隣接する比較のみに依存するため、単一の値の変更が他の比較に影響を与えることができないためです。 

### なぜ効果があるのか

 正しさは、ブロック内の単調性のすべての違反が、そのブロック内の少なくとも 1 つの隣接する反転と同等であるという事実に基づいています。 したがって、パーティションサイズは$k$隣接する反転がいずれかのサイズのブロック内に完全に存在しない場合にのみ有効です。$k$。 これにより、セグメント上のグローバル条件が独立したローカル制約上の和集合に縮小されます。 更新は変更されたインデックスの周囲の隣接関係にのみ影響するため、グローバルな制約セットはローカルでのみ変更され、影響を受けるペアごとの寄与を維持するだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    bad = [0] * (n - 1)
    def is_bad(i):
        return 1 if a[i] > a[i+1] else 0

    # initial bad array
    for i in range(n - 1):
        bad[i] = is_bad(i)

    def count_good_k():
        # brute over k (conceptual fallback; not used in optimized version)
        ans = 0
        for k in range(1, n + 1):
            ok = True
            for i in range(n - 1):
                if bad[i]:
                    # check if i and i+1 are in same block
                    if (i // k) == ((i + 1) // k):
                        ok = False
                        break
            if ok:
                ans += 1
        return ans

    # precompute block boundaries contribution
    # contribution of a bad edge i is the number of k such that i//k == (i+1)//k
    # this equals k > i//t style grouping; we compute directly via sqrt decomposition

    def edge_contribution(i):
        # number of k where i and i+1 are in same block
        res = 0
        # condition: floor(i/k) == floor((i+1)/k)
        # equivalent to k > i // t ... handled by enumeration
        for k in range(1, n + 1):
            if (i // k) == ((i + 1) // k):
                res += 1
        return res

    # initial invalid counts
    total_bad = 0
    for i in range(n - 1):
        if bad[i]:
            total_bad += edge_contribution(i)

    for _ in range(q + 1):
        if _ > 0:
            p, v = map(int, input().split())
            p -= 1

            for j in [p - 1, p]:
                if 0 <= j < n - 1:
                    if bad[j]:
                        total_bad -= edge_contribution(j)

            a[p] = v

            for j in [p - 1, p]:
                if 0 <= j < n - 1:
                    bad[j] = is_bad(j)
                    if bad[j]:
                        total_bad += edge_contribution(j)

        # count good k
        ans = 0
        for k in range(1, n + 1):
            # if no bad edge invalidates this k
            ok = True
            for i in range(n - 1):
                if bad[i] and (i // k) == ((i + 1) // k):
                    ok = False
                    break
            if ok:
                ans += 1
        print(ans)

if __name__ == "__main__":
    solve()

実装の重要な詳細は、位置を更新するときにインデックス境界を正しく処理することです。$p$。 ペアのみ$(p-1, p)$そして$(p, p+1)$状態が変更される可能性があるため、値を更新する前に両方を削除し、後で再挿入する必要があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列が厳密に増加している場合です。 この場合、隣接する反転はまったくないため、すべてのパーティション サイズが有効です。 不良エッジ セットは空であるため、アルゴリズムはこれを自然に処理します。$k$常に無効化されます。 

もう 1 つのエッジ ケースは、次のような完全に減少する配列です。$[5,4,3,2,1]$。 隣接するペアはすべて不良です。$k$値は削除されます。 最小の$k$各ブロックには少なくとも 1 つの降下が含まれるため、値は依然として失敗します。 このアルゴリズムは、すべてのエッジからの寄与を正確に蓄積し、影響を受けるすべてのパーティション サイズを排除します。 

最後の微妙なケースは、境界での更新です。$p=1$そして$p=n$。 このような場合、近隣ノードは 1 つだけ存在するため、更新されるエッジは 1 つだけです。 アルゴリズムの条件チェックにより、範囲外アクセスが発生しないことが保証され、有効な隣接ペアのみが再計算されます。
