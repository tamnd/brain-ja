 ## 解決策
 ## 問題の理解

 整数のリストから開始し、隣接するペアを取得し、ビット単位の演算 (AND、OR、または XOR) を使用してそこから導出された値を挿入することで、リストを繰り返し拡張できます。 挿入された値は選択された 2 つの要素の間に配置され、プロセスは新しく形成された配列上で無期限に続行できます。 

目標は、配列自体を追跡することではなく、最終的に配列内のどこにでもどのような値が出現する可能性があるかを理解し、具体的には合計で作成できる個別の値の数を最大化することです。 

制約の重要な部分は、最大 100,000 要素、最大約 2³⁰ の値を持つ配列のサイズです。 これにより、配列は際限なく増大する可能性があるため、挿入をシミュレートしたり、進化する配列を明示的に維持したりするアプローチは即座に排除されます。 代わりに、ソリューションでは値の「終り」、つまり演算の順序に関係なく、最終的にどの数値セットに到達できるかを推論する必要があります。 

素朴な思考による微妙な失敗例は、元の値とその直接のペアごとの結果のみが重要であると仮定することです。 たとえば、与えられた`[1, 2, 3]`のような組み合わせしか考えられないかもしれません。`1 & 2`、`2 | 3`、などが重要です。 ただし、新しい値が挿入されると、その値は他の要素に隣接してさらなる操作に参加し、元の配列には直接存在しない 2 次および高次の組み合わせが作成されます。 

これにより、ビット単位の AND、OR、および XOR を繰り返し適用して一連の数値を閉じるときにどのような構造が生成されるかを理解することが根本的に問題になります。 

## アプローチ

 ブルートフォースパースペクティブでは、プロセスを文字通りシミュレートします。配列を維持し、可能なすべての隣接ペアを選択し、3 つの派生値すべてを挿入し、新しい値が表示されなくなるまで続行します。 各演算により配列サイズが増大し、可能な演算シーケンスの数が爆発的に増加するため、これはすぐに実行不可能になります。 値の重複を排除しようとしても、新しく挿入された要素間の相互作用により、時間とメモリの両方で組み合わせ爆発が発生します。 

重要な観察は、挿入の「順序」や配列の構造には興味がなく、値が存在できる配列のみに興味があるということです。 値を作成したら、他の値と同様に使用できます。 これは、3 つのビットごとの操作で初期セットの閉包を効果的に研究していることを意味します。 

ここで、これらの操作の動作を少しずつ詳しく見ていきます。 数値の各ビットは、AND、OR、XOR に従って個別に進化します。 単一のビット位置を分離すると、各数値はその位置で 0 または 1 のいずれかになり、演算はビットに対して次のように動作します。 

ビットの任意のペアから:

 - AND は両方が 1 の場合にのみ 1 を返します。 
- 少なくとも 1 つが 1 の場合、OR は 1 を返します。 
- XOR は、ちょうど 1 つが 1 の場合に 1 を返します。 

ここで、到達可能な値の同じビット位置で 0 と 1 の両方が利用可能になった場合に何が起こるかを考えてみましょう。 ペア (0,1) から、0 と 1 の両方をすでに生成できます。 (1,1) から、XOR は 0 を生成し、欠損値が再導入されます。 (0,0) 以降はすべて 0 のままなので、そのビットは永続的に固定されます。 

これは、各ビットが独立して動作することを意味します。初期配列の特定のビット位置に少なくとも 1 つの 0 と少なくとも 1 つの 1 が含まれている場合、そのビットはクロージャで完全に制御可能になります。 それ以外の場合は、到達可能なすべての値にわたって一定のままになります。 

このようにビットが独立すると、自由に制御可能なビットの任意の組み合わせを中間値の構築を繰り返すことで実現できます。これは、各空きビット位置で 0 または 1 を独立して合成し、その後、さらなる演算を通じてそれらを組み合わせることができるためです。 

したがって、問題は、入力内で「混合」されているビット位置、つまりその位置に初期数値の中に 0 と 1 の両方が含まれている数をカウントすることに帰着します。 k ビットが混合されている場合、最終的に到達可能なセットにはそれらのビットの 2^k 個の組み合わせがすべて含まれますが、固定ビットは一定のままです。

 ## アルゴリズムのチュートリアル

 1. すべての数値をスキャンし、ビット位置ごとに、0 が見られたかどうか、1 が見られたかどうかを記録します。 

これにより、クロージャ内のビットが固定されているか解放されているかを判断するために必要な情報が正確に取得されます。 
2. 0 ～ 30 の各ビット位置について、入力数値に両方の状態が発生するかどうかを確認します。 存在する場合は、このビットを「空き」としてマークします。 

その理由は、両方のビット状態が共存する場合にのみ、XOR および AND/OR 相互作用を介して両方の値を再生成できるからです。 
3. 空きビット数をカウントし、このカウントを k として示します。 

このような各ビットは、到達可能な値で独立して変化できます。 
4. 2^k を答えとして返します。 

これは、空きビットのすべての可能な組み合わせを表しますが、固定ビットは変動に影響しません。 

### なぜ効果があるのか

このアルゴリズムは構造的不変式に依存しています。つまり、各ビット位置は許可された操作の下で独立して進化しますが、ビットの完全な柔軟性を妨げる唯一の障害は、初期セットの均一性です。 最初にビットに 0 と 1 の両方が存在すると、AND、OR、および XOR を繰り返し適用すると、各操作で両方の状態が保存または再導入されるため、どちらの値も永久に失われることはありません。 これにより、制限されたサブセットへの崩壊が防止され、そのビットに対するクロージャが完全なバイナリの選択になります。 ビットは他のビットの変化能力を制限するような形で相互作用しないため、グローバル状態空間は独立したビットの自由度のデカルト積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    has0 = [True] * 31
    has1 = [True] * 31

    # initialize: we will refine by checking actual presence
    has0 = [False] * 31
    has1 = [False] * 31

    for x in a:
        for b in range(31):
            if x & (1 << b):
                has1[b] = True
            else:
                has0[b] = True

    free_bits = 0
    for b in range(31):
        if has0[b] and has1[b]:
            free_bits += 1

    print(1 << free_bits)

if __name__ == "__main__":
    solve()
```この実装ではビット統計のみを追跡し、配列の拡張をシミュレートすることはありません。 数値ごとに、どのビットが 0 として表示され、どのビットが 1 として表示されるかを更新します。最後のループでは、混合された位置の数をカウントします。 答えはビット シフトを使用して 2 のべき乗として計算されますが、指数は最大 31 であるため安全です。 

よくある実装の落とし穴は、両方のプレゼンス配列を正しく初期化し忘れたり、ビット チェックを誤って解釈したりすることです。 すべての数値の両方の状態について、各ビットを独立してテストする必要があります。 

## 実用的な例

 インプットを考慮する`a = [1, 2]`。 

ここで 1 は`01`そして2は`10`。 各ビット位置には 0 と 1 の両方が表示されます。 私たちは以下を追跡します:

 | ビット | は0 | has1 |
 | --- | --- | --- |
 | 0 | はい | はい |
 | 1 | はい | はい |

 すべてのビットが空いているため、k = 2、答えは 4 になります。 

これは、2 つの相補的な値がどのようにして完全なビットの柔軟性を即座に解放するかを示しています。 

ここで考えてみましょう`a = [7, 3]`。 

バイナリ:

 - 7 = 111
 - 3 = 011

 | ビット | は0 | has1 |
 | --- | --- | --- |
 | 0 | いいえ | はい |
 | 1 | いいえ | はい |
 | 2 | はい | はい |

 ビット 2 のみが空いているため、k = 1 となり、答えは 2 になります。 

これは、ほとんどのビットが固定されている場合でも、単一の混合ビットによって到達可能なスペースがすでに 2 倍になることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · 31) | 各数値が 1 回スキャンされ、各ビットがチェックされます。 
| スペース | お(1) | ビット追跡には固定サイズの配列のみが使用されます。 

このアルゴリズムは、最大入力サイズであっても数百万ビットの演算のみを実行するため、制約内に容易に適合します。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。 たとえば、入力`a = [8, 8, 8]`。 すべてのビットは常に 0 または常に 1 のいずれかであるため、ビット位置が混在することはありません。 アルゴリズムは空きビットをマークしないため、k = 0 となり、答えは 1 になります。両方の入力が同一の場合、どの演算も新しい値を導入できないため、これは現実と一致します。 

もう 1 つのエッジ ケースは、配列全体で 1 ビットだけが異なる場合です。 例えば、`a = [0, 1, 1, 1]`。 最下位ビットのみが混合されるため、k = 1 となり、答えは 2 になります。アルゴリズムを確認してみると、そのビット位置のみ has0 と has1 の両方が設定されており、他のすべてのビットは固定されたままであり、最終的なクロージャーには 1 つの自由度のみが存在することが確認されます。
