 ## 解決策
 ## 問題の理解

 テストケースごとに開始番号が与えられます。`x`そして整数`k`。 10 進数の合計が次の値で割り切れる場合、その数値は美しいとみなされます。`k`。 

タスクは最小の整数を見つけることです`y`そのような`y ≥ x`と次の桁の合計`y`で割り切れます`k`。 

アルゴリズムの観点から見ると、制約は驚くほど小さいです。 の値`x`到達できる`10^9`、 しかし`k`せいぜい`10`。 テスト ケースの数は次のように大きくなります。`10^4`したがって、単一のテスト ケースのソリューションは非常に安価になるはずです。 

制約から分かる重要な点は、桁の合計が小さいということです。 周りの数字でも`10^9`、桁の合計は最大で`9 × 10 = 90`。 以来`k ≤ 10`、有効な答えを見つける前に、それほど遠くまで検索する必要はありません。 これにより、直接検索が実用的になります。 

簡単な間違いの 1 つは、答えが厳密に次の値より大きくなければならないと仮定することです。`x`。 考慮する：```
x = 777, k = 3
```桁の合計は`7 + 7 + 7 = 21`、これはすでに割り切れます`3`。 正しい答えは次のとおりです。```
777
```もう 1 つのよくある間違いは、桁の合計ではなく、数値自体の割り算をチェックすることです。 例えば：```
x = 17, k = 8
```番号`17`で割り切れない`8`、ただし、その桁の合計は`1 + 7 = 8`で割り切れます。`8`。 正しい答えは次のとおりです。```
17
```3 番目の微妙なケースは、最初の有効な番号が表示される前に、いくつかの連続する番号が失敗した場合に発生します。```
x = 1, k = 10
```桁の合計は次のとおりです。```
1 -> 1
2 -> 2
...
18 -> 9
19 -> 10
```答えは次のとおりです。```
19
```近くの少数の数値のみをチェックする不注意な実装では、最初の有効な候補を見逃す可能性があります。 

## アプローチ

 最も直接的なアプローチは、以下から始めることです。`x`そして、番号を 1 つずつ繰り返しテストします。 

候補番号については`cur`、その桁の合計を計算します。 その合計が次で割り切れる場合`k`、数値を昇順にチェックしたため、最小の有効な答えが見つかりました。 それ以外の場合は増分します`cur`そして続けます。 

すべての数値が次の値以上であるため、ブルート フォースは正しいです。`x`は順番に検査され、最初に見つかった美しい数値が可能な限り最小の答えになるはずです。 

通常、整数に対する線形検索は危険です。 有効な回答間のギャップが非常に大きい場合、最悪の場合の実行時間は許容できなくなります。 

重要な観察は、`k ≤ 10`。 桁の合計は頻繁に変化し、かなり狭い範囲の数値の中で、次のいずれかの値で割り切れる桁の合計に遭遇します。`1`に`10`。 実際には、検索が遠くまで進むことはありません。 これはまさにこの問題に対する意図した解決策です。 

数値は最大でも 10 桁であるため、桁の合計の計算には数回の操作しかかかりません。 たとえ`10^4`テストケースの場合、総作業量はわずかです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース検索 | O(g・d) | お(1) | 承認済み |
 | 最適 (同じ観察結果) | O(g・d) | お(1) | 承認済み |

 ここ`g`は答えが見つかるまでチェックされた候補の数です、そして`d`桁数です。 以来`k ≤ 10`、`g`非常に小さいままです。 

## アルゴリズムのチュートリアル

 1.読む`x`そして`k`。 
2.セット`cur = x`。 
3. 次の桁の合計を計算します。`cur`。 
4. 桁の和が割り切れる場合`k`、出力`cur`このテスト ケースの処理を停止します。 
5. それ以外の場合は増加します`cur`1つずつ。 
6. 手順 3 から繰り返します。 

検索は昇順に進みます。 最初に見つかった有効な数値が、自動的に最小の有効な答えになります。 

### なぜ効果があるのか

 すべての反復で、次のすべての整数が`x`を通して`cur - 1`桁の合計が次の値で割り切れないため、すでにチェックされ拒否されています。`k`。 

アルゴリズムがある値で停止したとき`cur`、その桁の合計は次で割り切れます。`k`。 以下のすべての小さな数値以上であるため、`x`はすでに調査されて無効であることが判明しました。これより小さい有効な答えは存在しません。 したがって`cur`正確に最小の美しい数です。`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    s = 0
    while n:
        s += n % 10
        n //= 10
    return s

t = int(input())

for _ in range(t):
    x, k = map(int, input().split())

    cur = x
    while True:
        if digit_sum(cur) % k == 0:
            print(cur)
            break
        cur += 1
```ヘルパー関数は、モジュロ演算と除算演算を繰り返して桁の合計を計算します。 これにより、数値を文字列に変換する必要がなくなりますが、どちらの方法でも十分に高速です。 

テスト ケースごとに、プログラムは次のように開始されます。`x`そして候補者を一人一人チェックします。 ループは、桁の合計が次の値で割り切れるとすぐに終了します。`k`が見つかりました。 

微妙な境界条件は次のような場合です。`x`それ自体はすでに美しいです。 アルゴリズムはこれを自然に処理します。`cur`から始まります`x`, したがって、最初のチェックには開始番号が含まれます。 

Python の整数には制限がなく、問題の値は競技プログラミング標準から見てすでに非常に小さいため、オーバーフローの懸念はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    def digit_sum(n):
        s = 0
        while n:
            s += n % 10
            n //= 10
        return s

    t = int(input())
    ans = []

    for _ in range(t):
        x, k = map(int, input().split())
        cur = x

        while True:
            if digit_sum(cur) % k == 0:
                ans.append(str(cur))
                break
            cur += 1

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue()
