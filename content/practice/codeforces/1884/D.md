 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a[1..n]`、それぞれ 1 から n の間です。 ペアの数を数える必要があります`(i, j)`と`i < j`ないように`k`どちらも`a[i]`そして`a[j]`で割り切れます`a[k]`。 言い換えれば、ペアの両方の要素を分割する公約数が配列内にない場合、そのペアは「良好」です。 

入力には複数のテスト ケースを含めることができ、その合計は`n`すべてのテスト ケースでは最大 100 万件になります。 これにより、すべてのペアを明示的にチェックするソリューションが即座に除外されます。`i < j`なぜなら、それは O(n^2) 演算であり、最悪の場合は最大 10^12 演算に達する可能性があるからです。 

重要な微妙な点は、たとえ`a[i]`そして`a[j]`互いに素であっても、いくつかの要素が存在する場合には依然として「悪い」可能性があります。`a[k]`両方の数値を除算する配列。 たとえば、次の場合`a = [2, 4, 4]`、 それから`(2, 3)`はどちらも次で割り切れるので良くありません。`2`（それでも`a[2] = 4`そして`a[3] = 4`等しい）。 

単純な実装が失敗する可能性のあるエッジ ケースには、すべての要素が等しい配列、または一部の要素が 1 である配列が含まれます。たとえば、すべての数値が次の場合です。`1`、すべての数値は次で割り切れるため、どのペアも適切ではありません。`1`。 同様に、素数の倍数である合成値の横に素数がある場合、割り算を誤って数えると間違った結果が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。`(i, j)`そしてすべてをチェックしてください`k`かどうか`a[i] % a[k] == 0`そして`a[j] % a[k] == 0`。 これは正しいですが、最悪の場合は O(n^3) 回の操作が必要となり、n が 10^6 までの場合は遅すぎます。 

重要な観察は、ペアが`(i, j)`数値が存在する場合にのみ悪いです`x`両方を除算する配列内`a[i]`そして`a[j]`。 ペアをチェックする代わりに、それぞれで割り切れる数の数を数えることができます。`x`配列内で。 させて`cnt[x]`で割り切れる数のカウントになる`x`。 すると、以下の理由で良くないペアの数が`x`は`cnt[x] * (cnt[x] - 1) // 2`。 

計算できる`cnt[x]`ふるいのようなアプローチを効率的に使用します。 それぞれの番号について`v`配列では、次の値に 1 を加えます。`cnt[d]`すべての約数に対して`d`の`v`。 これにより、すべてのペアを明示的にチェックする必要がなくなります。 最後に、不良ペアの総数はすべての約数の合計であり、良好なペアの数は次のようになります。`total_pairs = n * (n - 1) // 2 - bad_pairs`。 

これにより、問題はペアごとのチェックから計数問題に変換され、除数累積手法を使用すると O(n log n) 時間で実行可能になります。

 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 約数を数える | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`そして配列`a`。 
2. 周波数配列を初期化する`freq`サイズの`n+1`各数字が何回出現するかを数える`a`。 
3. 数字ごとに`v`で`a`、増分`freq[v]`。 
4.初期化`cnt`サイズの配列`n+1`ゼロに。 これは、各インデックスで割り切れる数値の数を保存します。 
5. すべての数字について`i`1 から n まで、複数回繰り返します`j = i, 2*i, 3*i, ...`まで`n`そして追加します`freq[j]`に`cnt[i]`。 これは、配列内で割り切れる数値がいくつあるかを数えます。`i`。 
6. それぞれについて`i`1 から n まで、次の原因による不良ペアの数を計算します。`i`として`cnt[i] * (cnt[i] - 1) // 2`そしてそれらを合計します。 
7. ペアの総数を計算します。`total_pairs = n * (n - 1) // 2`。 
8. 良好なペアの数は`total_pairs - bad_pairs`。 
9. 各テストケースの結果を出力します。 

**機能する理由:** このアルゴリズムは、公約数を共有するすべてのペアを正しくカウントします。`i`それぞれの約数があるため、二重に数えることはありません`i`は、それで割り切れるペアのみを提供します。 すべての約数を合計すると、不良ペアの総数が得られます。 合計ペアから減算すると、良好なペアだけが残ります。 ふるいのような数え方により、ペアを見逃さないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1

        cnt = [0] * (n + 2)
        for i in range(1, n + 1):
            for j in range(i, n + 1, i):
                cnt[i] += freq[j]
        
        bad_pairs = sum(c * (c - 1) // 2 for c in cnt[1:n+1])
        total_pairs = n * (n - 1) // 2
        print(total_pairs - bad_pairs)

if __name__ == "__main__":
    solve()
```最初のループでは、数値の頻度表を作成して、各値が何回出現するかを調べます。 ネストされたループはふるいのようなものです。`i`で割り切れるすべての数値を加算します。`i`に`cnt[i]`。 の`bad_pairs`浮動小数点エラーを避けるために、合計は整数除算を使用して慎重に計算されます。 これにより、ペアごとの反復が完全に回避されます。 サイズの配列のみが必要です`n+1`、制約を考慮すると安全です。
