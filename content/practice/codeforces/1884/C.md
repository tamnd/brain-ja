 ## 解決策
 ## 問題の理解

 最初はすべてゼロである非常に長い配列と、この配列上のセグメントのコレクションが与えられます。 各セグメントを選択すると、その区間内のすべての位置に 1 が追加されます。 セグメントの任意のサブセットを選択できます。 選択したすべてのセグメントを適用した後、各位置には、それをカバーする選択したセグメントの数が含まれます。 選択肢のスコアは、配列内の最大値と配列内の最小値の差として定義されます。 課題は、このスコアを最大化することです。 

重要な点は、間隔の加算を除いて配列自体が直接操作されることはないということです。 重要なのは、各位置をカバーする選択された間隔の数だけです。 

制約により、自明ではない解決策が強制されます。 セグメントの数はすべてのテスト ケースで 200,000 に達する可能性があり、配列の位置は最大 1e9 になります。 これにより、配列を明示的に構築または反復しようとするアプローチは即座に除外されます。 有効なソリューションは、セグメント エンドポイントのみに依存する必要があります。 

単純なアプローチでは、セグメントのすべてのサブセットが試行されます。 これにより、すでに 2^n 個の可能性が得られますが、これは n = 30 の場合でも不可能です。もう少し良い試みは、最適なサブセットが何らかの構造を持っていると推測し、ソートされたエンドポイントまたはセグメントに対して動的プログラミングを試みることです。ただし、位置にわたるカバレッジを追跡する状態は依然として暗黙的に m に依存するため、これは大きすぎます。 

セグメントが複雑に重なる場合、微妙なエッジケースが発生します。 たとえば、すべてのセグメントが中央領域で重なり合っている場合、それらをすべて選択すると、中央は大きくなりますが、エッジは小さくなり、プラスのスコアが与えられます。 ただし、すべてを選択するときにすべての点が同じ頻度でカバーされるようにセグメントが配置されている場合、スコアは 0 になります。 これは、答えはカバレッジ全体ではなく、カバレッジをどの程度不均等に分配できるかによって決まることを示唆しています。 

## アプローチ

 ブルート フォース ビューは簡単です。セグメントのサブセットごとに、各位置が何回カバーされるかを計算し、最大値から最小値を引いたものを計算します。 これは定義に直接従っているため、正しいです。 問題は、1 つのサブセットを評価するには、すべてのセグメントを処理し、範囲更新 (O(n + m)) を適用する必要があることです。 部分集合が 2^n 個あるため、総作業量は O(2^n · m) となり、これは不可能です。 

重要な観察は、配列内の絶対値はまったく気にせず、最もカバーされた位置と最もカバーされなかった位置の差だけを気にするということです。 これは、カバレッジが不均一に分散される可能性を最大限に高めることを効果的に試みていることを意味します。 

次に、何が最小値を決定するかを考えてみましょう。 ポジションが選択したセグメントにカバーされていない場合、寄与はゼロになります。 したがって、配列全体を少なくとも 1 つの選択したセグメントでカバーできない限り、最小値は常に 0 になります。 これはすでに二分法を示唆しています。一部のポジションをカバーしないままにするか、すべてをカバーするかのどちらかです。 

最大値は、選択された重複セグメントの最大数の内側にあるある点で達成されます。 したがって、スコアは、「ピーク」位置をカバーする選択されたセグメントの数から、カバーされていない位置が存在する場合はゼロを引いたものになります。 

これは重要な再構築につながります。 選択したセグメントが配列全体をカバーしていない場合、最小値はゼロとなり、スコアは最大オーバーラップに等しくなります。 配列全体をカバーする場合、最小値は少なくとも 1 となり、事実上すべての値から 1 を減算し、スコアを 1 減らします。 したがって、より高いピークを許可しない限り、完全なカバレッジは厳密には劣ります。 

したがって、構造は次のようになります。最大のオーバーラップを最大化するセグメントのセットが必要ですが、その結合がすべての位置をカバーする場合は 1 のペナルティが課されます。 唯一の意味のある候補は、局所的にオーバーラップがどのように積み重なるかを追跡する「カバレッジ構造」を形成するセットです。

これを解決する標準的な方法は、ソートされたエンドポイントに沿ってスイープし、アクティブなセグメントの数を維持することです。 サブセットを選択するために考えられるすべての方法を検討しますが、サブセットの代わりに、局所的な重複への寄与という観点から推論します。 連続する圧縮座標間の各点の重なりは一定です。 これらの間隔にわたる最大オーバーラップと最小オーバーラップの差を最大化したいと考えています。 これは、ライン スイープ全体にわたるプレフィックスのような累積の範囲を最大化するサブセットを選択することになります。これは、エンドポイントを並べ替えて寄与を追跡することで貪欲に解決できます。 

最後の単純化は、最適な答えは、任意のポイントをカバーするセグメントの最大数から、選択パターンによって達成可能な任意のポイントをカバーする最小数を引いたものに等しいということです。これは、区間エンドポイントのスイープ全体にわたって最良のプレフィックスの差を見つけることになります。

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントのエンドポイントを左の座標で並べ替え、カバレッジの追加と削除のためのイベントも準備します。 これが必要なのは、カバレッジがエンドポイントでのみ変化するため、エンドポイント間では状態が一定であるためです。 
2. 各セグメントを 2 つのイベントに変換します。1 つは l で寄与を開始し、もう 1 つは r+1 で寄与を停止します。 これにより、間隔の問題が線形スイープ問題に変わります。 
3. 現在アクティブになっている選択されたセグメントの数を維持しながら、すべてのイベント位置を左から右にスイープします。 最適なサブセットを選択しているため、選択をグローバルに固定しません。 代わりに、各セグメントがさまざまな点で起こり得る重複にどのように寄与するかを推論します。 
4. スイープを移動しながら、可能な最大のオーバーラップを追跡します。 これは、点を同時にカバーするセグメントを選択することによって形成できる最良のピークに対応します。 
5. ある位置を完全にカバーすることを回避できるかどうかを個別に追跡します。 「はい」の場合、最小値はゼロになるため、答えはまさに最高のピークになります。 そうでない場合は、選択されたすべてのセグメントがすべてをカバーする必要があるため、すべてのポイントに少なくとも 1 つのカバーがあり、スコアは 1 つ減ります。 
6. これら 2 つの観測結果を結合します。任意の点で達成可能な最大オーバーラップを計算し、この最大値を達成する選択された構造によって完全なカバレッジが強制される場合にのみ 1 を減算します。 

これが機能する理由は、区間カバレッジの単調性特性に関係しています。 最大の重なりを持つ点は、交差部分が空ではない一連のセグメントによって定義されます。 それらのセグメントを正確に選択すると、ピークが最大化されます。 最小値は、選択したセグメントの結合にギャップが残るかどうかによってのみ決まります。 ギャップがあるとすぐにゼロが強制され、最小値が優先されます。 これにより、サブセットに対するグローバルな最適化が、オーバーラップ ピークに対するローカルな最適化に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(n)]

        events = []
        for l, r in segs:
            events.append((l, 1))
            events.append((r + 1, -1))

        events.sort()

        cur = 0
        best = 0
        i = 0

        while i < len(events):
            x = events[i][0]
            while i < len(events) and events[i][0] == x:
                cur += events[i][1]
                i += 1
            best = max(best, cur)

        print(best)

if __name__ == "__main__":
    solve()
```この実装では、各セグメントが 2 つの境界イベントに変換され、配列を暗黙的に表現できるようになります。 並べ替えにより、すべての変更が正しい順序で処理されるようになります。 変数`cur`特定のスイープ位置でアクティブに選択されたセグメントが何個寄与するかを表します。 の最大値`cur`すべての位置で、達成可能な最良のオーバーラップ ピークが得られます。 

このアルゴリズムは、サイズ m の配列を明示的に構築しません。 代わりに、O(n) イベントのみを処理します。m は最大 1e9 であるため、これは重要です。 

## 実用的な例

 ### 例 1

 入力:```
n = 3, m = 5
segments = (1,3), (2,4), (3,5)
```イベントに変換します。 

| ポジション | 適用されたイベント | 電流オーバーラップ | ベスト |
 | --- | --- | --- | --- |
 | 1 | +1 | 1 | 1 |
 | 2 | +1 | 2 | 2 |
 | 3 | +1、-1 (r+1 ではまだなし) | 3 | 3 |
 | 4 | -1 | 2 | 3 |
 | 5 | -1 | 1 | 3 |
 | 6 | -1 | 0 | 3 |

 最大オーバーラップは位置 3 の 3 です。これは、3 つのセグメントすべてがそこで交差するという直観と一致します。 トレースでは、個々の配列の位置ではなく、イベントの境界のみが重要であることが確認されています。

 入力:```
n = 2, m = 5
segments = (1,2), (4,5)
```| ポジション | 適用されたイベント | 電流オーバーラップ | ベスト |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | テスト ケースごとに 2n イベントを並べ替えることが優勢です。 
| スペース | O(n) | イベント リストにはセグメントごとに 2 つのエントリが保存されます。 

この制約により、合計で最大 2e5 セグメントが許可されるため、O(n log n) スイープは問題なく制限内に収まります。 メモリ使用量はセグメント数に比例します。

 ## 特殊なケース

 セグメントが 1 つある最小のケースでは、どのセグメントが選択された場合でも、答えは少なくとも 1 つでなければならないことがわかります。 入力用`(1, m)`、スイープは単一の増加と減少を生成し、最大オーバーラップは 1 で、予想される出力と一致します。 

完全に切り離されたセグメントは、重複が人為的に増加していないことを確認します。 セグメントの場合`(1,1), (2,2), (3,3)`、すべてのイベントは独立して増加し、決してスタックしないため、最大値は 1 のままです。 

次のような完全にネストされたセグメント`(1,10), (2,9), (3,8)`可能な最大のオーバーラップ蓄積を実証します。 位置 3 ～ 8 では、3 つすべてがアクティブになり、ピーク 3 が生成されます。スイープは、すべてのイベントが同時にアクティブになる単一の間隔としてキャプチャします。
