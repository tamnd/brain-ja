 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$各ノードは固定の美味しさの値を持つおやつを表します。 2 人のプレイヤー、ボブとチャーリーは、現在の木から 2 枚の葉を繰り返し取り除きます。 選択した葉のペアごとに、チャーリーは 1 枚を選んで食べ、ボブはもう 1 枚を手に入れます。 どちらのプレイヤーも完璧に戦略的で、食べるものの総合的な美味しさを最大化したいと考えています。 

このプロセスは、おやつがなくなるまで続きます。つまり、最終的にはすべてのノードが 1 回だけ削除され、削除ステップごとに 1 対の葉が消費されます。 

出力は、両側からの最適なプレイの下でのボブの最終的な総合的な美味しさです。 

重要な構造は、除去には常に葉が含まれるため、ゲームはノードの任意のペアではなく、時間の経過とともにツリーがどのように縮小するかによって制限されます。 

制約$N \le 20$非常に小さいです。 これは、指数関数または階乗探索が実行可能であることを直ちに示唆しています。 ノードまたはマッチングのサブセットの状態を列挙するソリューションは、潜在的に受け入れられます。 ただし、難しいのは列挙ではなく、最適な敵対的な選択の下でゲームのダイナミクスを正しくモデル化することです。 

複数のリーフが同一または極端な値を持つ場合、微妙なエッジ ケースが発生します。 たとえば、1 つの中心がすべての葉を接続する星形の木について考えてみましょう。 利用可能な最良のリーフをローカルでペアにする単純な貪欲なアプローチは失敗します。リーフを削除するとどのノードがリーフになるかが変わり、ローカル ペアリングではなくグローバル構造に依存する形で将来の有効な動きが変更されるためです。 

別の障害ケースがパスで発生します。 チェーンでは、リーフは常にエンドポイントであるため、初期の選択は将来利用可能なペアを大きく制限します。 貪欲な「常に最大のリーフを 2 つ取得する」アプローチは、ノードの削除によって将来のラウンドに影響を与えるリーフの機会が作成または破壊される可能性があることを無視しているため、失敗します。 

## アプローチ

 直接的な総当たりアプローチでは、ゲームを段階的にシミュレートします。 いつでも、すべての葉を識別し、そのうちの 2 つを選択し、どのプレイヤーがどの葉を取るかで分岐します。 ツリーが空になるまで再帰的に続行します。 これは、有効な動きと結果の考えられるあらゆるシーケンスを調査するため、原則として正しいです。 

ただし分岐要素は大きい。 小さなツリーでも複数の葉がある場合があり、各ステップでペアを選択し、2 つの方法でそれらを割り当てます。 州の数は超指数関数的に増加します$N$削除するたびにツリー構造とリーフセットが変更されるためです。 たとえ$N = 20$、一連の削除に対する単純な再帰は、実行可能な限界を超えて爆発的に増加します。 

重要な観察は、どの時点でも重要なのは現在の残りのノードのセットであり、そのターンの効果を選択順序を通じて暗黙的に評価しているということです。 以来$N$が小さい場合、残りのノードをビットマスクとして表すことができます。 ツリー構造は前処理することができ、どの状態でもアクティブな隣接ノードがまだ 1 つしかないかどうかを確認することで、どのノードが葉であるかを計算できます。 

状態を修正したら、次の動きは明確に定義されます。つまり、現在のリーフの順序のないペアを選択し、どの値がボブに送られ、どの値がチャーリーに送られるかを選択します。 これにより、自然にサブセット全体にわたるミニマックス DP が得られます。 ボブは合計ゲインを最大化していますが、チャーリーはペア割り当ての現在の選択に対してボブのゲインを最小限に抑えています。 

残りのノードのサブセットをメモ化します。 各状態は、すべての有効なリーフ ペアを計算し、両方の割り当てをシミュレートし、再帰します。 

これにより、問題は、敵対的なペアリングの決定を伴う標準的なサブセット DP に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シーケンスに対するブルート フォース シミュレーション | 指数関数的に効果的に$O((N!)^2)$| O(N) | 遅すぎる |
 | リーフペア ミニマックスを使用したサブセット DP |$O(2^N \cdot N^3)$|$O(2^N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接関係情報を事前計算し、高速近隣チェック用のビットマスクとして保存します。 これにより、ノードが特定のサブセットの下のリーフであるかどうかを一定時間またはほぼ一定時間でテストできます。 
2. ノードのサブセットごとに関数を定義します。$dp(mask)$ボブが残りのノードから得られる最大の合計の美味しさを表します。`mask`。 これにより、ゲームが独立したサブ問題に圧縮されます。 
3. 計算するには`dp(mask)`、まず、内のすべてのノードを特定します。`mask`それは葉っぱです。 ノードに隣接するノードが 1 つだけまだ存在する場合、そのノードはリーフです。`mask`。 この状態は、アクティブな近隣の数をカウントすることによって評価されます。 
4. 残りのノード数が 0 の場合は 0 を返します。これは、これ以上おいしさを収集できない終末状態です。 
5. 順序付けされていない個別の葉のペアをすべて列挙します。$(u, v)$。 このような各ペアは、1 つの正当な手を表します。 
6. ペアごとに$(u, v)$、両方の割り当てを検討してください: ボブはとります$u$そしてチャーリーは$v$、またはボブが取る$v$そしてチャーリーは$u$。 削除後、新しいサブセットに移行します`mask' = mask without u and v`。 
7. チャーリーは敵対的であるため、各ペアについて、チャーリーがボブの将来の合計を最小化する割り当てを選択すると仮定します。 したがって、各ペアについて、ボブの観点から 2 つの割り当てのうち悪い方を採用します。 
8. ボブは、考えられるすべてのリーフ ペアのうち、結果として得られる合計ゲインを最大化するペアを選択します。 この値を次の場所に保存します`dp(mask)`。 

### なぜ効果があるのか

 すべての状態は、有効な中間ツリー構成を完全に記述します。 ゲームにおける唯一の決定点は、次にどの 2 枚の葉を選択するかということです。これは、ペアが選択されると他のすべてのアクションが強制されるためです。 DP は、そのような選択の将来の有効なシーケンスをすべて調査します。 ミニマックス構造は、チャーリーのローカルな割り当て選択とボブのグローバルなペア選択の選択を正確にモデル化します。 各遷移によってノードの数が厳密に削減されるため、サイクルは存在せず、メモ化によって正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    
    adj = [0] * n
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    @lru_cache(None)
    def dp(mask):
        nodes = [i for i in range(n) if (mask >> i) & 1]
        if len(nodes) == 0:
            return 0

        # compute degrees inside mask
        deg = [0] * n
        for i in nodes:
            deg[i] = bin(adj[i] & mask).count("1")

        leaves = [i for i in nodes if deg[i] <= 1]

        if len(leaves) < 2:
            return 0

        best = 0

        m = len(leaves)
        for i in range(m):
            for j in range(i + 1, m):
                u = leaves[i]
                v = leaves[j]

                nxt = mask & ~(1 << u) & ~(1 << v)

                # Bob takes u, Charlie takes v
                bob1 = t[u] + dp(nxt)

                # Bob takes v, Charlie takes u
                bob2 = t[v] + dp(nxt)

                best = max(best, min(bob1, bob2))

        return best

    full = (1 << n) - 1
    print(dp(full))

if __name__ == "__main__":
    solve()
```この実装では、ビットマスクを使用して残りのトリートの各サブセットを表します。 隣接関係もビットマスクに圧縮されるため、リーフの検出はビットごとの交差と個体数のカウントに減ります。 

DP 関数は現在のリーフを明示的に列挙します。これは、リーフのみが選択可能であるため有効です。 リーフの各ペアは正確に 1 つのゲームの手を生成し、再帰呼び出しによって結果の構成が評価されます。 

微妙なディテールは、`min(bob1, bob2)`表現。 これは、ボブがペアを選択した後のチャーリーの選択をエンコードします。チャーリーは、より悪い結果をボブに割り当てるため、どちらかのエンドポイントを受け取るボブの最小値を取得します。

 ## 特殊なケース

 ミニマルなケース付き$N=2$の移動は 1 つだけなので、両方のプレイヤーはそれぞれ 1 つのノードを選択するだけです。 このアルゴリズムは、単一の葉のペアを評価することに帰着し、チャーリーの選択後に可能な最大の結果をボブに正しく割り当てます。`min(t1, t2)`ボブのゲインを直接決定します。 

スター グラフでは、最初はすべての外側のノードがリーフです。 DP はすべてのリーフ ペアを評価しますが、削除ごとにどのノードがリーフに残るかが変わります。 このアルゴリズムは縮小されたマスクから次数を正しく再計算し、新たに露出した葉が将来のトランジションに確実に含まれるようにします。 

パス グラフでは、最初はエンドポイントのみが葉ですが、それらを削除すると新しいエンドポイントが露出する可能性があります。 リーフ計算は事前に計算された静的構造ではなく現在のマスクから派生するため、サブセット DP はこれを自然に捉えます。
