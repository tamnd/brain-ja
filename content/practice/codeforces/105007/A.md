 ## 解決策
 ## 問題の理解

 グリッドは、長方形のセルとしてレイアウトされたドッグ パークを表します。 各セルは空であるか、ドットでマークされているか、その位置での犬の身長を表す 1 から 9 までの 1 つの数字が含まれています。 公園内のすべての犬の中で、最も背の高い犬が 1 匹だけいます。そのタスクは、その位置を特定し、1 から始まるインデックスを使用してその行と列を報告することです。 

入力が単純​​なリストよりわずかに多いのは、データが空間的であるためです。 最大値を抽出するだけでなく、2D 構造内のどこで最大値が発生するかも追跡します。 したがって、出力は値そのものではなく、最大桁を含むセルの座標になります。 

制約は小さく、両方の次元が最大 100 です。つまり、最大 10,000 個のセルが存在します。 各セルを一定の回数スキャンするソリューションは、簡単に十分に高速です。 グリッドの単純なフル スキャンでさえ、問題なく制限内に収まりますが、必要以上に賢くしようとしても、意味のあるパフォーマンス上の利点は得られません。 

微妙な間違いは、入力解析によって発生することがよくあります。 各行は文字列であり、スペースで区切られた値ではありません。 これを整数のリストとして扱ったり、分割を誤ったりすると、列が移動したり行がマージされ、不正確な座標が生成される可能性があります。 もう 1 つのよくある問題は、プログラミング言語のインデックスは通常 0 から始まるため、答えは 1 から始まる必要があることを忘れていることです。 

ここで問題となるエッジケースは、アルゴリズムではなく構造的なものがほとんどです。 サイズ 1×1 のグリッドは有効であり、(1, 1) を返す必要があります。 すべての犬の高さが 1 つの最大値を除いて同じであるグリッドは一意であることが保証されますが、厳密に大きいのではなく「以上」で答えを更新する不注意な実装では、最初に見つかった最大値が誤って上書きされる可能性があります。 多くのドットと 1 つの数字を含むグリッドでは、解析で犬以外のセルが正しくスキップされるかどうかもテストされます。 

## アプローチ

 最も直接的なアプローチは、グリッド内のすべてのセルをスキャンして、数字が含まれているかどうかを確認することです。 存在する場合は、これまでに確認された最良の高さと比較し、より大きな値が現れたときに、保存されている最良の値と座標を更新します。 これが機能するのは、グリッドが小さく、各セルが 1 回だけ検査されるためです。 

ブルート フォースの亜種では、概念的に各セルを回答候補として試し、グリッド全体を再度スキャンして、それが最大値であるかどうかを確認します。 これには、セルのすべてのペアを比較する必要があり、最悪の場合、およそ O((NM)^2) の演算が必要になります。 N と M が最大 100 である場合、これは不必要なオーバーヘッドであり、より制約されたバージョンの問題では非効率になる危険性があります。 

重要な観察は、この問題では、位置追跡を使用した有限の値セットにわたるグローバル最大値のみが必要であるということです。 セル間の依存関係や順序の制約はなく、前処理も必要ありません。 これにより、タスクが単一パスの累積問題に縮小されます。つまり、グリッドを 1 回横断する間に、これまでに観察された最良の状態を維持するということです。

 ## アルゴリズムのチュートリアル

1. 次元 N と M を読み取り、グリッドを行ごとに文字列として読み取ります。 これにより空間構造が保持されるため、各文字がグリッド内の 1 つのセルに正確に対応します。 
2. これまでに見つかった最大の高さを格納する変数を初期化します。 有効な犬がすぐに置き換えられるように、可能な限り最小の桁よりも小さい値に設定します。 
3. これまでに見つかった最適な位置の座標を保存する 2 つの変数を初期化します。 
4. 各行インデックス i を 0 から N-1 まで反復します。 
5. 各行内で、各列インデックス j を 0 から M-1 まで反復します。 
6. 現在のセルにドットではなく数字が含まれている場合は、それを整数に変換し、現在の最大値と比較します。 それが大きい場合は、最大値を更新し、(i, j) を新しい最適な位置として記録します。 
7. すべてのセルをスキャンした後、1 から始まるインデックスを使用して保存された座標を出力します。 

厳密に大きな値が確認された場合にのみ更新する理由は、最も背の高い犬が一意であるという保証に関係しています。 これにより、タイブレーク ロジックが必要なくなります。 最初に発生した最大値が正しいものであり、安定したままになります。 

### なぜ効果があるのか

 スキャンの各ステップで、アルゴリズムは、保存された位置が、これまでに処理されたグリッドの部分で遭遇した最も背の高い犬に対応するという不変条件を維持します。 すべてのセルが正確に 1 回訪問され、比較は高さに関して単調であるため、この不変式により、グリッド全体が処理されると、保存された位置がグローバル最大値に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    best_val = -1
    best_i = 0
    best_j = 0

    for i in range(n):
        row = input().strip()
        for j in range(m):
            c = row[j]
            if c != '.':
                val = ord(c) - ord('0')
                if val > best_val:
                    best_val = val
                    best_i = i
                    best_j = j

    print(best_i + 1, best_j + 1)

if __name__ == "__main__":
    solve()
```この解決策は、グリッド上の 1 回のパスに依存します。 変換`ord(c) - ord('0')`整数解析の速度が低下することを回避し、入力が 1 桁の数値を保証するため安全です。 座標は計算中に 0 ベースのインデックスで保存され、出力時にのみ 1 ベースに変換されるため、更新中のオフバイ 1 エラーが防止されます。 

よくある実装上の間違いは、値が厳密に大きいかどうかを確認する前に座標を更新するか、`>=`の代わりに`>`。 これにより、以前に発生した最大値が誤って上書きされてしまいますが、これは不必要であり、正確さに関する推論が複雑になる可能性があります。 もう 1 つの微妙な問題は、各行から改行文字を削除するのを忘れることです。これにより、インデックス付けが変更されたり、無効な文字が導入されたりする可能性があります。

 ## 特殊なケース

 1×1 グリッドは最も単純な構造です。 このアルゴリズムは有効な数字よりも下の最適な値を初期化するため、単一のセルが即座に選択され、(1, 1) として返されます。 この結果を誤って上書きする可能性のある反復はありません。 

最初のセルで最大値が発生するグリッドは、後の比較によってすでに最適な答えが誤って置き換えられるかどうかをテストします。 更新は厳密に大きな値に対してのみ発生するため、最初の最大値が保存されると、より大きな値が表示されない限り変更されません。これは正しい入力では発生しません。 

グリッドの大部分がドットで埋められているため、数字以外の文字は安全に無視されます。 スキャンではこれらのセルが単純にスキップされ、数字が見つかるまで最適な値は変更されません。
