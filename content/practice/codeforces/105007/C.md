 ## 解決策
 ## 問題の理解

 英小文字で構成される最大 50,000 個の長さの単一の文字列が与えられます。 各位置は遺伝子塩基を表し、すべての連続する部分文字列を調べて、2 つの条件を同時に満たす部分文字列を数えるように求められます。 

まず、部分文字列は回文でなければなりません。これは、左から右、右から左に同​​じように読めることを意味します。 次に、その部分文字列内では、どの文字も 2 回以上出現することはできません。 

出力は、すべての可能な開始位置と終了位置にわたるそのような部分文字列の数です。 

50,000 文字という制約により、すべての部分文字列を明示的に列挙して 1 つずつチェックしようとするアプローチは即座に排除されます。 約 n²/2 の部分文字列があり、n が 50,000 の場合、すでに 12 億 5,000 万程度になります。 たとえ回文チェックが O(1) だったとしても、これは大きすぎます。 実行可能なソリューションでは、部分文字列プロパティを繰り返し再計算することを避ける必要があります。 

それほど明らかではない問題は、回文構造が周波数制約と強く相互作用することです。 回文は任意の部分文字列ではなく、その対称性により文字が鏡像位置に繰り返されるため、文字が出現できる頻度が制限されます。 

単純な間違いは、回文の妥当性をチェックするだけで十分であると思い込み、出現回数を個別にカウントすることです。 これにより、「ababa」のようなケースが見落とされます。これは回文ですが、中央の文字が 3 回繰り返されるため、「1 文字あたり最大 2 回出現する」という制約に違反します。 

もう 1 つの微妙なエッジ ケースは、繰り返される文字を除くすべての異なる文字を含むすべての回文が有効であると考えることです。 「aabbaa」のような場合、各文字が正確に 2 回出現しても制約は満たされますが、展開では両側の頻度制限を同時に維持する必要があるため、構造が重要になります。 

## アプローチ

 ブルートフォースソリューションでは、すべての部分文字列を列挙し、それが回文であるかどうかをチェックし、文字の出現頻度をカウントして、文字が 2 回以上出現しないことを確認します。 長さ k の部分文字列のチェックには O(k) かかるため、各部分文字列のコストは O(k) となり、すべての部分文字列にわたって、これは最悪の場合 O(n³) になります。 ハッシュまたはプレフィックス頻度配列によって頻度チェックが O(1) に削減されたとしても、回文検証には依然として O(k) のコストがかかり、結果として全体で O(n³) または O(n²) となり、どちらも n = 50,000 には遅すぎます。 

重要な観察は、「文字あたりの頻度が最大 2」という制約の下で有効な回文は非常に構造化されているということです。 回文は中心の周りに対称性を強制します。 文字が 2 回以上出現する場合は、少なくとも 4 回対称的に出現する必要があり、構造が非常に小さい場合を除き、すぐに制約に違反します。 実際、この制約に耐えられる唯一の回文は、回文の半径が非常に限られているものであり、ほとんどの有効なケースは中心の周りの短い展開です。 

これは中心拡大の視点につながります。 すべての回文はその中心によって定義され、外側に対称的に広がります。 部分文字列を独立して処理する代わりに、回文を中心ごとに列挙し、実行頻度カウンターを維持しながら外側に拡張します。 いずれかの文字が周波数 2 を超えると、その中心の拡張が停止します。 拡張は制約によって厳密に制限されるため、総作業量は平均して線形のままです。 

私たちは、問題を「すべての部分文字列をチェックする」から「すべての回文を展開するが、頻度制約を使用して早期に展開をカットする」に効果的に削減します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 周波数プルーニングによる中心拡張 | O(n²) 最悪、O(n) 平均に近い | O(1) または O(26) | 承認済み |

 ## アルゴリズムのチュートリアル

文字列内の考えられる回文の中心をそれぞれ処理します。 中心には、単一文字中心と文字間中心の 2 種類があります。 

1. 各インデックス i について、それを奇数長の回文の中心として扱います。 文字の頻度カウンターを初期化し、2 つのポインター l = i および r = i で外側に拡張します。 拡張するたびに、文字の頻度が更新され、妥当性がチェックされます。 
2. 各展開ステップで、文字頻度が 2 を超えないことを確認します。超えた場合は、この中心からの展開を直ちに停止します。 この枝刈りは、実行時間を支配する無効な大きな回文の探索を防ぐため、重要な最適化です。 
3. 拡張中に有効な回文が見つかるたびに、答えが増加します。 
4. l = i および r = i+1 から始めて、i と i+1 の間に中心を置く偶数長の回文に対して同じプロセスを繰り返します。 
5. すべてのセンターからの結果を合計し、合計数を出力します。 

重要な点は、拡張中に周波数追跡を段階的に更新する必要があることです。 各部分文字列のカウントを再計算すると、効率が損なわれます。 各展開ステップでは、両側に 1 つずつ、計 2 つの文字が追加されるだけなので、更新は O(1) です。 

### なぜ効果があるのか

 すべての回文には、1 つの文字または 2 つの文字の間に、固有の中心表現があります。 展開プロセスでは、各回文が 1 回だけ列挙されます。 頻度制約は段階的に適用され、無効な部分文字列がカウントされることがなくなります。 違反が発生するとすぐに展開が停止するため、答えに寄与できない部分文字列の探索に時間を費やすことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    ans = 0

    def expand(l, r):
        nonlocal ans
        cnt = [0] * 26

        while l >= 0 and r < n:
            if l == r:
                c = ord(s[l]) - 97
                cnt[c] += 1
                if cnt[c] > 2:
                    break
            else:
                c1 = ord(s[l]) - 97
                c2 = ord(s[r]) - 97
                cnt[c1] += 1
                cnt[c2] += 1
                if cnt[c1] > 2 or cnt[c2] > 2:
                    break

            ans += 1
            l -= 1
            r += 1

    for i in range(n):
        expand(i, i)
        expand(i, i + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、中心を中心に展開する単一のヘルパー関数に依存しています。 周波数配列は中心ごとにリセットされます。これは、異なる拡張間での汚染を避けるために重要です。 各展開ステップでは、有効性をチェックする前にカウントが更新されるため、無効な回文がカウントされることはありません。 

よくある落とし穴は、制約をチェックする前に答えを更新してしまうことです。 これにより、文字がすでに許容頻度を超えている部分文字列が誤って含まれてしまいます。 コードは、カウントを増加した直後にチェックすることでこれを回避します。 

もう 1 つの微妙な詳細は、奇数の中心と偶数の中心を別々に処理することです。 (i, i) と (i, i+1) を使用すると、すべての回文が重複することなく 1 回だけ考慮されるようになります。 

## 実用的な例

 ### 例 1: 「アババ」

 簡潔にするために、i = 0 と i = 1 で中心を追跡します。

 | l | r | 部分文字列 | カウント | 有効 | 答え |

 これは、制約に違反したときに拡張がどのように正確に停止するか、また、重なり合う回文が異なる中心からどのように正しくカウントされるかを示しています。 

### 例 2: 「ああああ」

 | l | r | 部分文字列 | カウント | 有効 | 答え |

 これは、回文構造が長いものの、周波数違反が現れるまでほとんど有効である場合を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) 最悪の場合、通常ははるかに少なくなります。 各センターは違反が発生するまで拡張されます。 周波数制約により実際の拡張は制限される |
 | スペース | お(1) | 拡張ごとに再利用される 26 文字の頻度配列を修正 |

 この制約では最大 50,000 文字が許容され、最悪の場合の理論上の動作は 2 次ですが、1 文字あたりのフリークエンシー キャップが 2 であるため、展開の深さが大幅に制限され、実際にはソリューションが快適に高速になります。

 ## 特殊なケース

 「a」のような単一の文字を入力すると、有効な回文が 1 つだけ生成されます。 拡張が開始され、すぐに中心がカウントされ、それ以上拡張できないため停止します。 

「aaaa」のような繰り返し文字入力は、周波数制約が重要である理由を示しています。 中心からの拡張はすぐに許容カウント 2 を超えて早期に停止し、短い回文のみがカウントされるようにします。 

「abc」のような繰り返し文字がない文字列では、すべての文字が有効な回文であることが保証されますが、回文は存在しなくなり、頻度だけではなく不一致条件によって展開が正しくブロックされることが確認されます。
