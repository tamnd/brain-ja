 ## 問題の理解

 ボタンが2つ付いたウォータークーラーがあります。 赤いボタンを押すと正確に`a`水のミリリットル`100°C`、青いボタンを押しながら、正確に`b`ミリリットル`0°C`。 タンタンは正確に水を集めたいと考えています`x°C`水を捨てずに1000ミリリットルのボトルに入れます。 課題は、ボトルに収まる最大量の正しく調整された水を見つけることです。 

タンタンが赤いボタンを押したとします。`i`時間と青いボタン`j`回。 お湯の量は、`a * i`、冷水の体積は`b * j`、総量は`a * i + b * j`。 結果として得られる温度は、

 [
 \frac{100ai}{ai+bj}。 
】

 中間温度の場合、この式により、温水と冷水の量の正確な比率が決まります。 したがって、問題全体はシミュレーションの問題ではなく、整数の割り算の問題になります。 

制約はわずかですが、`a`そして`b`最大でも1000、`x`ボトルの容量は 1000 ミリリットルに固定されているため、ボタンを押す可能性を直接検索することも原理的には実行可能ですが、意図したソリューションははるかに単純で、一定時間で実行されます。 元の問題には 1 秒の時間制限と 512 MB のメモリ制限があります。 

不注意な実装が失敗する可能性がある境界ケースがいくつかあります。 もし`x = 0`、冷水のみ使用可能です。 たとえば、```
10
20
0
```答えは`1000`青いボタンを50回押すとちょうど1000ミリリットルが出るからです。 盲目的に除算する式`x`ここで失敗するだろう。 

同様に、`x = 100`、お湯のみ使用可能です。 のために```
300
200
100
```答えは`900`, 赤いボタンを3回押すと900ミリリットルが出るからです。 したがって、一般的な比率の公式はゼロ係数を正しく処理する必要があります。 

中間の温度を得ることがまったく不可能な場合もあります。 のために```
100
101
10
```答えは`0`。 必要な温水と冷水の比率は、これら 2 つの固定ボタンの量からは形成できないため、端数のボタンを押すことが可能であるかのように装うことは、無効な肯定的な答えを生成することになります。 

最後に、有効な混合物を 1 つ取得しても、そこで終了する必要はありません。 最小の有効な混合物に体積がある場合`250`たとえば、次のようにすることができます`250`、`500`、`750`、 または`1000`同じ混合物の繰り返しコピーを使用してミリリットル。 答えは、ボトルの容量を超えない最大の倍数です。 

## アプローチ

 単純な総当たりアプローチは、赤ボタンと青ボタンを可能な限り押して、その結果の温度を計算し、有効な最大音量を記憶することです。 ボトルには 1000 ミリリットルしか入らないため、使えるプレス機の数には限りがあります。 1 つの実装ですべてのペアを検査できます`(i, j)`と`1 <= i, j <= 1000`、最大 100 万の候補ペアが与えられます。 私たちが評価するすべてのペアについて

 [
 \frac{100ai}{ai+bj}
 】

 それが等しいかどうかを確認してください`x`。 

これが機能するのは、すべての候補ペアが直接テストされ、最終的には実行可能な混合物が見つかるためです。 問題は、検索が構造で必要とされるよりもはるかに多くの作業を行っていることです。 また、浮動小数点比較も奨励しますが、正確な整数が等しい場合には不必要であり、潜在的に危険です。 

重要な観察は、目標温度によって温水と冷水の比率が決まるということです。 ホットボリュームを`H`そしてコールドボリュームは`C`。 のために`0 < x < 100`、

 [
 \frac{100H}{H+C}=x。 
】

 乗算すると得られる

 [
 (100-x)H=xC。 
]

以来`H = ai`そして`C = bj`を取得します。 

[
 a(100-x)i = bxj。 
】

 現在、問題は次の形式の標準方程式になりました。`A*i = B*j`。 しましょう

 [
 A=a(100-x)、\qquad B=bx。 
]

もし`g = gcd(A, B)`、最小の正の解は次のようになります。 

[
 i=\frac{B}{g}、\qquad j=\frac{A}{g}。 
】

 対応する最小有効水量は次のとおりです。 

[
 M=a\frac{B}{g}+b\frac{A}{g}
 =\frac{100ab}{g}。 
】

 他の有効な解はすべて、この最小の解の単なる整数倍です。 それで一度`M`が知られているが、1000 ミリリットルのボトルに収まる最大量は単純に

 [
 \left\lfloor\frac{1000}{M}\right\rフロア M.
 】

 興味深いことに、同じ式で次のことも処理できます。`x = 0`そして`x = 100`。 のために`x = 0`、gcd は次のようになります`gcd(0, 100a) = 100a`、与える`M = b`。 のために`x = 100`、それは与えます`M = a`。 したがって、実装には特別なケースは必要ありません。

 | --- | --- | --- | --- |
 | ブルートフォース | O(10^6) | お(1) | 原則として受け入れられますが、不必要に大きい |
 | 最適 | O(log(max(a, b))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`a`、`b`、 そして`x`。 定義する`A = a * (100 - x)`そして`B = b * x`。 これらは正確な方程式の 2 つの係数です`A * i = B * j`。 
2. コンピューティング`g = gcd(A, B)`。 両方の係数を gcd で割ると、温度方程式を満たす最小の整数比が得られます。 
3. 有効な最小混合物体積を次のように計算します。 

[
 M=\frac{100ab}{g}。 
】

 ここでのキャンセルは最小の解決策から直接得られます。`i = B/g`、`j = A/g`。 それらの総水量は正確に`100ab/g`。 
4. コンピューティング

 [
 \left\lfloor\frac{1000}{M}\right\rフロア M.
 】

 すべての実行可能な混合物は次の体積に等しい`kM`何らかの正の整数の場合`k`したがって、これはまさにボトルに収まる実行可能な最大量です。 
5. その金額を印刷します。 もし`M > 1000`、商はゼロであり、有効な混合物をボトルに注ぐことができないことを正しく示しています。 

重要な不変条件は次のとおりです`M`は、高温成分と低温成分が正確に必要な温度比を持つ最小の正の体積です。 なぜなら、次のすべての整数解は`A*i = B*j`は縮小された解の倍数で​​あり、実現可能な総体積はすべて の倍数です。`M`。 したがって、最終的なフロア操作では、あらゆる実現可能な容量が考慮され、ボトルの容量を下回る最大の容量が選択されます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

a = int(input())
b = int(input())
x = int(input())

g = gcd(a * (100 - x), b * x)
minimum = 100 * a * b // g

answer = (1000 // minimum) * minimum
print(answer)
```二つの表現`a * (100 - x)`そして`b * x`温度方程式を整理すると直接得られます。 計算を完全に統合することで、浮動小数点精度の問題を回避できます。`math.gcd`ゼロも正しく処理されます。 いつ`x = 0`、2 番目の引数がゼロであり、`x = 100`、最初の引数はゼロです。 これが、実装で 2 つの極端な温度に対して個別の分岐を必要としない理由です。 

表現`100 * a * b // g`最小の有効な総量を計算します。 Python の整数はオーバーフローしません。また、最大の中間値はとにかく小さいです。`a`そして`b`最大でも 1000 です。 

最後に、`1000 // minimum`gives the number of complete copies of the smallest mixture that fit in the bottle. 乗算して戻す`minimum`単なるコピー数ではなく、実際のボリュームを示します。

def solve():
