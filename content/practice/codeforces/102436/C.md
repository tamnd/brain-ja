 ## 解決策
 ## 問題の理解

 数直線上には (n) 個のセグメントがあります。 元のエンドポイントはペアとして失われています。 配列 (x_1 < x_2 < \dots < x_{2n}) にソートされたすべて (2n) 個の終点座標のみがわかり、元のセグメントの和集合の全長が正確に (k) であることがわかります。 

(2n) 個の座標のペアを、結合の長さが (k) である (n) 個のセグメントに再構築する必要があります。 出力では、座標自体ではなく、ソートされたエンドポイント配列のインデックスが使用されます。 必要な共用体長を生成するペアがない場合は、次のように出力します。`No`。 それ以外の場合は印刷します`Yes`その後に (n) 組のインデックスが続きます。 元のステートメントは、すべての座標が異なることを保証します。 

制約は、意図したソリューションの鍵となります。 セグメントは 7000 個まで存在するため、エンドポイントは 14000 個になります。 ターゲットの結合長 (k) は最大 30000 です。状態が現在位置と (k) までの長さにのみ依存する DP は妥当ですが、(n) で指数関数的なものは直ちに不可能です。 意図したソリューションでは、ソートされたエンドポイントの構造を使用して再構築をナップザック スタイルの DP に変換し、大きな状態次元はビットセットで処理されます。 

最初のエッジ ケースは、可能な最小和集合よりも小さいターゲットです。 例えば、```
2 1
0 1 2 3
```4 つのエンドポイントは ([0,1]) および ([2,3]) としてペアにすることができ、和集合長は (2) になります。 他のすべてのペアでは長さ (2) 以上の和集合が生成されるため、正しい出力は次のようになります。`No`。 (k) が座標間の任意の差として形成できるかどうかだけをチェックする不注意な実装では、それが誤って受け入れられる可能性があります。 

2 番目のエッジ ケースは、まさに最小結合長です。 のために```
2 2
0 1 2 3
```隣接するペア ([0,1])、([2,3]) は和集合の長さ (2) を与えるので、答えは次のようになります。`Yes`。 いくつかの間隔が交差する必要があると想定するソリューションでは、この完全に切り離された構成が見逃される可能性があります。 

3 番目のエッジ ケースは、完全にネストされた構成です。 のために```
2 3
0 1 2 3
```セグメント ([0,3]) と ([1,2]) の和集合長は (3) です。 エンドポイントは ((1,4)) と ((2,3)) としてペアにする必要があります。 隣接する端点をペアリングすると長さ (2) が得られるため、最小限のペアリングを取得するだけでは十分ではありません。 

4 番目のエッジ ケースは (k=0) です。 すべての座標は個別であるため、すべてのセグメントは正の長さを持ち、1 つのセグメントの結合であっても正の長さになります。 したがって```
1 0
0 1
```生産しなければならない`No`。 すべてのエンドポイントが最終的に使用される必要があることを確認せずに、ゼロを空の DP 状態として扱う実装では、この問題が発生します。 

## アプローチ

 最も直接的な総当たりアプローチは、(2n) 個のエンドポイントの可能なすべてのペアを試行することです。 ((2n-1)!!) 異なる組み合わせがあります。 各ペアについて、結果の間隔を左端点でソートし、(O(n)) での結合の長さを計算できます。 したがって、合計作業量は (O(n(2n-1)!!)) となります。 実際の制約は (n=7000) ですが、(n=20) でさえすでに実用的な限界をはるかに超えています。 ブルートフォースは文字通りあらゆる可能な再構成をチェックするので正しいのですが、その検索スペースはあまりにも急速に増大します。 

ソートされたエンドポイントを確認するためのより強力な方法があります。 

すべての隣接するペアを一時的にペアリングするとします。 

[
 (x_1,x_2),(x_3,x_4),\ldots,(x_{2n-1},x_{2n})。 
】

 これらの間隔は互いに素であり、これらのエンドポイントの最小和集合が得られます。 彼らの長さを呼び出す

 [
 a_i=x_{2i+2}-x_{2i+1}
 】

 ゼロベースのインデックスを使用します。 

ここで、連続する 2 つのペアについて考えてみましょう。 保管する代わりに

 [
 (x_{2i},x_{2i+1}),\quad(x_{2i+2},x_{2i+3}),
 】

 4 つのエンドポイントをネストされた順序でペアにすることで、それらの結合を 1 つの接続コンポーネントにマージできます。 

[
 (x_{2i},x_{2i+3}),\quad(x_{2i+1},x_{2i+2})。 
】

 したがって、結合は単に最初のエンドポイントから最後のエンドポイントまでの間隔になります。 次のペアが吸収されるときに拠出される追加金額は、

 [
 b_i=x_{2i+1}-x_{2i-1}
 】

 (i>0) の場合。 

これは特に便利な表現になります。 最終結合のすべての連結コンポーネントには、終点座標の連続したブロックが含まれます。 各エンドポイントは 1 回だけ使用されるため、(2m) 個のエンドポイントを含むコンポーネントは、それらのエンドポイントをネストすることによって表現できます。 したがって、再構成全体は、(n) 個の隣接するエンドポイントのペアを連続したブロックに分割するものとみなすことができます。 

ペアのインデックス (l) ～ (r) をカバーするブロックの場合、その和集合は次のようになります。 

[
 [x_{2l},x_{2r+1}],
 】

 その長さは

 a_l+b_{l+1}+b_{l+2}+\cdots+b_r。 
】

 したがって、ペアのインデックスを左から右にスキャンすると、正確に 2 つの選択肢があります。 (a_i) を支払って新しいコンポーネントを開始することも、(b_i) を支払って現在のコンポーネントを拡張することもできます。 

これは 0/1 のナップザック形式の問題になりました。 位置 (i) では、DP は到達可能な全長を記録します。 ターゲット容量は (k) で、最大 30000 です。公開されたソリューションでは、まさにこの理由から C++ ビットセットを使用しています。 

最後の難関は再建です。 通常のブール型 DP は、位置と長さのペアごとに先行するものを記憶する必要があります。これは、(O(nk)) 個のメモリです。 代わりに、どの位置に到達可能な状態がそのビットセットを使用したかを示す 1 つのビットセットを位置ごとに保持します。`extend`遷移。 Python では、任意精度の整数がコンパクトなビットセットとして機能するため、1 つの整数ですべての (k+1) 状態を一度に表すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n(2n-1)!!)) | (O(n)) | 遅すぎる |
 | 普通のDP | (O(nk)) | (O(nk)) 再構築用 | Python では遅すぎる、メモリを大量に消費する |
 | ビットセット DP | (O(nk/W)) ワード演算 | (O(nk/W)) 再構成用 | 承認済み |

 ここで (W) は、1 回のマシンワードレベルのビットセット演算で処理されるビット数です。 Python では、同じアイデアが任意精度の整数によって実装され、そのシフトとビット単位の演算により多くの DP 状態が同時に処理されます。 

## アルゴリズムのチュートリアル

 1. 位置 (i) の基本隣接ペアの長さ (a_i=x_{2i+1}-x_{2i}) を計算します。 また、すべての (i>0) について (b_i=x_{2i+1}-x_{2i-1}) を計算します。 コンポーネントを (i) コスト (a_i) で開始し、コンポーネントを (i) コスト (b_i) まで拡張します。 
2. 到達可能な DP 状態を 1 つの整数として表現します。`dp`。 ビット (複数可) は、現在のプレフィックスの処理後に共用体長の合計が取得できるときに正確に設定されます。 最初は長さ 0 のみに到達できるため、`dp = 1`。 
3. (i) の位置でシフト`dp`(a_i) の左側は、(i) で新しいコンポーネントを開始することを表します。 (b_i) だけ左にシフトすることは、前のペアのコンポーネントを (i) に拡張することを表します。 これら 2 つのビットセットを結合すると、新しい到達可能な状態が得られます。 
4. 新しく到達可能な状態がどの状態から来たのかを保存します。`b_i`遷移。 両方の遷移が同じ状態に到達できる場合は、`a_i`遷移。 この任意のタイブレークは、再構築中に先行ビットを識別するのに 1 つの保存ビットで十分であることを意味するため、便利です。 
5. すべて (n) の位置が処理された後、ビット (k) を検査します。 設定されていない場合は、エンドポイント シーケンスの有効なパーティションが存在しないため、次のように出力します。`No`。 
6. ビット (k) が設定されている場合は、DP を後ろ向きに歩きます。 位置 (i) で、保存されているかどうかを確認します。`b_i`ビットは現在のターゲット長に設定されます。 そうであれば、現在のコンポーネントが拡張されているため、(b_i) を減算します。 それ以外の場合は、ここで開始されたため、(a_i) を減算します。 
7. 復元された選択肢は、(n) 個の隣接するエンドポイントのペアを連続したブロックに分割します。 すべてのブロック ([l,r]) について、そのエンドポイントをネストされた順序でペアにします。 最も外側のセグメントは位置 (2l) と (2r+1) を使用し、次のセグメントは (2l+1) と (2r) を使用します。 
8. ゼロベースのエンドポイント位置を必要な 1 ベースのインデックスに変換し、結果の (n) セグメントを出力します。 

### なぜ効果があるのか

 中心となる不変条件は、ソートされたエンドポイント シーケンスの連続した接続コンポーネントを使用して、元のセグメントのあらゆる可能な結合を表現できるということです。 1 つのコンポーネント内でエンドポイントをネストすると、そのコンポーネントの間隔が正確に生成されますが、異なるコンポーネントは互いに素なままです。 したがって、有効な再構成は、(n) 個の隣接するエンドポイントのペアを連続したブロックに分割することと同じです。 

(l) で始まり (r) で終わるブロックの場合、その和集合の長さは正確に (a_l+\sum_{i=l+1}^{r}b_i) になります。 DP は、すべての位置で 2 つの可能性、つまり新しいブロックの開始または前のブロックの拡張を正確に考慮します。 したがって、すべての DP パスは有効なブロック パーティションに対応し、すべての有効なブロック パーティションは 1 つの DP パスに対応します。 ビット (k) が到達可能な場合、再構築された選択肢は正確に (k) の和集合を生成します。 到達できない場合は、有効な再構築が存在しません。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))

    # a[i] is the length of the basic adjacent pair.
    a = [x[2 * i + 1] - x[2 * i] for i in range(n)]

    # b[i] is the cost of extending the current component
    # from pair i-1 through pair i.
    b = [0] * n
    for i in range(1, n):
        b[i] = x[2 * i + 1] - x[2 * i - 1]

    # Bit s of dp means that total length s is reachable.
    dp = 1

    # For each i, bit s of extend[i] means that state s
    # was reached by taking the b[i] transition.
    extend = [0] * n

    mask = (1 << (k + 1)) - 1

    for i in range(n):
        from_start = dp << a[i]

        if i == 0:
            from_extend = 0
            chosen_extend = 0
        else:
            from_extend = dp << b[i]

            # If both transitions reach the same state, prefer
            # starting a new component.
            chosen_extend = from_extend & ~from_start

        dp = (from_start | from_extend) & mask
        extend[i] = chosen_extend & mask

    if not ((dp >> k) & 1):
        print("No")
        return

    # Reconstruct whether each position extends the previous block.
    used_extend = [False] * n
    cur = k

    for i in range(n - 1, -1, -1):
        if i > 0 and ((extend[i] >> cur) & 1):
            used_extend[i] = True
            cur -= b[i]
        else:
            cur -= a[i]

    # Convert the sequence of choices into consecutive blocks.
    blocks = []
    start = 0

    for i in range(1, n):
        if not used_extend[i]:
            blocks.append((start, i - 1))
            start = i

    blocks.append((start, n - 1))

    # Construct nested pairs inside every block.
    answer = []

    for l, r in blocks:
        while l <= r:
            # Zero-based endpoint positions:
            # 2*l and 2*r+1.
            answer.append((2 * l + 1, 2 * r + 2))
            l += 1
            r -= 1

    print("Yes")
    for u, v in answer:
        print(u, v)

if __name__ == "__main__":
    solve()
```最初の部分の構成`a`そして`b`。 値`a[i]`ペア (i) を別個の連結コンポーネントにするコストです。 値`b[i]`ペア (i) をその直前のコンポーネントに接続するコストです。 

表現`dp << a[i]`到達可能なすべての合計をコンポーネントの起動コストによってシフトします。 同じく、`dp << b[i]`現在のコンポーネントを拡張することを表します。 すべてのコストは正であるため、(k) より大きい状態は後で役に立ちません。そのため、マスクはそれらを安全に破棄します。 

表現`from_extend & ~from_start`拡張機能が有効な先行要素であるが、新しいコンポーネントの開始は有効ではない状態のみを記録します。 両方の選択が可能な場合、実装は意図的に開始遷移を選択するため、再構築にはこれで十分です。 

逆方向再構築では、現在の状態を作成した遷移が正確に減算されます。 値`cur`したがって、ゼロに達するまで有効な先行状態を通過します。 

ブロック構築では、内部的にゼロベースのエンドポイント位置が使用されます。 ペア (l) からペア (r) までのブロックの場合、最も外側のセグメントはエンドポイント位置 (2l) と (2r+1) を接続します。 両方の位置に 1 を加算すると、必要な 1 ベースのインデックスが得られます。 内側に移動すると、残りのネストされたセグメントがすべて作成されます。 

Python では整数オーバーフローは発生しません。 C++ では、元の制約は、座標とターゲットの長さの通常の 32 ビット整数にも快適に適合します。 Python 実装のメインメモリのコストは次のとおりです。`extend`最大 (k+1) ビットの (n) 個の任意精度ビットセットを含む配列。

    for i in range(1, n):
        if not used_extend[i]:
            blocks.append((start, i - 1))
            start = i

    blocks.append((start, n - 1))

    answer = []

    for l, r in blocks:
        while l <= r:
            answer.append((2 * l + 1, 2 * r + 2))
            l += 1
            r -= 1

    out = ["Yes"]
    out.extend(f"{u} {v}" for u, v in answer)
    return "\n".join(out) + "\n"

def run(inp: str) -> str:
    data = list(map(int, inp.split()))
    n, k = data[0], data[1]
    x = data[2:2 + 2 * n]
    return solve_instance(n, k, x)

def verify(inp: str, out: str):
    data = list(map(int, inp.split()))
    n, k = data[0], data[1]
    x = data[2:2 + 2 * n]

    lines = out.strip().splitlines()

    if lines[0] == "No":
        return

    assert lines[0] == "Yes"
    assert len(lines) == n + 1

    used = [False] * (2 * n)
    intervals = []

    for line in lines[1:]:
        u, v = map(int, line.split())
        assert 1 <= u <= 2 * n
        assert 1 <= v <= 2 * n
        assert u < v

        u -= 1
        v -= 1

        assert not used[u]
        assert not used[v]

        used[u] = True
        used[v] = True
        intervals.append((x[u], x[v]))

    assert all(used)

    intervals.sort()

    total = 0
    left, right = intervals[0]

    for l, r in intervals[1:]:
        if l > right:
            total += right - left
            left, right = l, r
        else:
            right = max(right, r)

    total += right - left

    assert total == k

 ## 特殊なケース

 最小結合よりも小さいターゲットの場合、DP は当然そのインスタンスを拒否します。 考慮する```
2 1
0 1 2 3
```基本隣接コストは (a=[1,1]) ですが、拡張コストは (b_1=2) です。 到達可能な合計は (1)、(2)、(3) のみであるため、両方のペアの処理後にビット (1) は設定されません。 アルゴリズムは出力します`No`。 

最小和集合と正確に等しいターゲットについては、次のように考慮します。```
2 2
0 1 2 3
```DPは選択できる`start`2 回実行すると (a_0+a_1=1+1=2) となります。 再構築されたブロックは ([0,0]) と ([1,1]) で、インデックスを持つセグメントが生成されます。`(1,2)`そして`(3,4)`。 それらの結合の長さは (2) です。 

ネストされた構成の場合は、次のことを考慮してください。```
2 3
0 1 2 3
```DPは選択できる`start`最初のペアと`extend`2番目のペア用。 費用は

 [
 a_0+b_1=1+2=3。 
】

 結果のブロックは ([0,1]) です。 その入れ子構造により、`(1,4)`そして`(2,3)`、([0,3]) および ([1,2]) に対応します。 それらの結合は正確に ([0,3])、長さは (3) です。 

(k=0) の場合、次のように考えます。```
1 0
0 1
```利用可能な移行コストは (1) のみであるため、すべてのエンドポイントが処理された後、到達可能な状態は長さ (0) ではなく、長さ (1) だけになります。 その結果、アルゴリズムは次のように出力します。`No`。 すべてのエンドポイントは 1 つのセグメント内でのみ使用する必要があるため、初期 DP 状態にゼロが含まれていても、空の構造が有効な答えであることを意味するわけではありません。 

最後に、最大サイズのケースでは、ビットセットを使用する理由が強調されます。 (n=7000) の場合、通常の Python ループは最大 (7000\cdot30001)、つまり約 2 億 1,000 万の DP 状態を検査します。 ビットセット表現は、整数シフトとビット単位の演算を使用して、考えられるすべての長さを同時に処理します。これは、完全な制約を実用的なものにする中心的な最適化です。 元の問題では、(n) と (k) の最大値を正確に設定します。
