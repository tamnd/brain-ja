 ## 解決策
 ## 問題の理解

 すべての式が正の整数のリストを生成する、小さな言語で書かれた 2 つのプログラムが与えられています。 プログラムには、固定リスト、連結、ランダム シャッフル、およびソートが含まれる場合があります。 タスクは、プログラムのテキストを比較することではなく、考えられるすべての出力リストにわたってまったく同じ確率分布を生成するかどうかを判断することです。 

難しさは、操作によって情報が隠蔽される可能性があるという事実に起因します。 シャッフルされたリストでは元の順序は考慮されませんが、連結では 2 つの部分間の境界が維持されます。 たとえば、ランダムにシャッフルする`[1,2,1,2]`2 つの独立したシャッフルを連結するのとは異なります。`[1,2]`2 番目のバージョンには常に非表示の分割ポイントが含まれるためです。 

入力文字列には最大 100 万文字を含めることができます。 これにより、考えられるすべての出力の評価が即座に除外されます。これは、短いリストでも階乗的に多くの順列が存在する可能性があるためです。 また、大規模な中間ディストリビューションの構築も除外されます。 アルゴリズムは構文をほぼ線形に処理し、結果の分布の簡潔な記述のみを保持する必要があります。 

主なエッジケースは、似たような混乱を招く操作から生じます。 のようなプログラム`shuffle([1,2,3])`と同等ではありません`concat(shuffle([1,2]),[3])`最後の要素が 2 番目のプログラムで固定されているためです。 のようなプログラム`shuffle([1])`決定論的なリストとして扱う必要があります`[1]`そうでない場合、同等のプログラムが異なる表現を受け取る可能性があります。 重複した値は別の罠です。 最終的な各シーケンスの確率は多重度に依存するため、リストをセットとして扱うと間違った答えが得られます。 

## アプローチ

 直接的なアプローチは、すべての式の確率分布をシミュレートすることです。 長さの一覧はこちら`n`、これは最大まで保存することを意味します`n!`シャッフル後の可能な並べ替え。 異なる位置が 15 個しかないリストの場合でも、これは不可能になり、最大入力サイズは何桁も大きくなります。 

重要な観察は、シャッフルがその引数の内部構造を完全に忘れているということです。 保持する唯一の情報は、値の複数セットです。 ソート操作でもマルチセットのみが必要ですが、その出力は決定的です。 他のものはすべて、これら 2 種類の部分のシーケンスとして表現できます。 

ブルートフォース手法は、言語のセマンティクスが小さいため機能しますが、可能な出力の数が指数関数的に増加するため失敗します。 すべての式が決定論的なセグメントと独立したシャッフルされたセグメントに還元できるという観察により、代わりにコンパクトな正規形を比較できるようになります。 

正規化中、決定論的セグメントにはその正確なシーケンスが保存されます。 ランダム セグメントには、各値のカウントのみが保存されます。 隣接する決定的セグメントをマージしたり、値を 1 つだけ含むランダムなセグメントを決定的セグメントに変換したりできます。 

結果として得られる表現は正規です。 2 つの正規化された表現が異なる場合、境界、値、または確率の動作の一部が異なります。これは、元のプログラムが同等であることができないことを意味します。

 | 正規形の構築 | O(n) が予想されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 式を再帰的に解析し、その正規化された形式とその複数の値セットを返します。 マルチセットが必要なのは、両方の理由からです。`shuffle`そして`sorted`注文情報を破棄します。 
2. リスト リテラルを決定的ブロックに変換します。 そのマルチセットは数値の読み取り中に計算されます。 
3. のために`concat(a,b)`、両方の子の正規化されたブロック シーケンスを連結します。 2 つの隣接するブロックが決定的である場合は、2 つの固定シーケンスの間に目に見える境界がないため、それらをマージします。 
4. のために`shuffle(x)`、のブロック構造を破棄します。`x`そして、すべての値のマルチセットのみを含むランダムなブロックを 1 つ作成します。`x`。 長さ 1 のランダム ブロックは、決定的ブロックに単純化されます。 
5. のために`sorted(x)`、のすべての値を含む決定的ブロックを作成します。`x`昇順で。 元の注文情報は無関係です。 
6. 2 つのプログラムの正規化されたブロック シーケンスを比較します。 すべての決定的ブロックは同じシーケンスを持つ必要があり、すべてのランダム ブロックは同じマルチセットを持つ必要があります。 

不変条件は、すべての正規化された式が元の式とまったく同じ分布を表すということです。 決定的ブロックは正確な位置に強制的に表示される値を表し、ランダム ブロックはマルチセットの一様な順列を表します。 上記の操作ではこの意味が保たれているため、等しい正規化形式は等しい分布を意味し、異なる正規化形式は異なる分布を意味します。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline
sys.setrecursionlimit(3000000)

def merge_blocks(a, b):
    if not a:
        return b
    if not b:
        return a
    if a[-1][0] == 'D' and b[0][0] == 'D':
        return a[:-1] + [('D', a[-1][1] + b[0][1])] + b[1:]
    return a + b

def normalize_block(kind, data):
    if kind == 'R':
        if sum(data.values()) == 1:
            x = next(iter(data))
            return [('D', (x,))]
        return [('R', tuple(sorted(data.items())))]
    return [('D', tuple(data))]

def parse(s):
    n = len(s)
    pos = 0

    def dfs():
        nonlocal pos

        if s[pos] == '[':
            pos += 1
            vals = []
            cnt = Counter()
            while s[pos] != ']':
                start = pos
                while s[pos].isdigit():
                    pos += 1
                x = int(s[start:pos])
                vals.append(x)
                cnt[x] += 1
                if s[pos] == ',':
                    pos += 1
            pos += 1
            return [('D', tuple(vals))], cnt

        start = pos
        while s[pos].isalpha():
            pos += 1
        op = s[start:pos]
        pos += 1

        if op == 'concat':
            left, c1 = dfs()
            pos += 1
            right, c2 = dfs()
            pos += 1
            return merge_blocks(left, right), c1 + c2

        child, cnt = dfs()
        pos += 1

        if op == 'shuffle':
            return normalize_block('R', cnt), cnt

        arr = []
        for x, c in sorted(cnt.items()):
            arr.extend([x] * c)
        return [('D', tuple(arr))], cnt

    return dfs()[0]

a = input().strip()
b = input().strip()

print("equal" if parse(a) == parse(b) else "not equal")
```パーサーは文法に直接に従います。 リスト リテラルは、その値を収集し、同時に出現回数をカウントすることによって処理されます。 シャッフルされた結果は個別の値だけではなく多重度に依存するため、カウンターが必要です。 

の`merge_blocks`連結後に必要となる単純化は関数のみです。 2 つの決定的隣接ブロックは 1 つのより大きな決定的ブロックと区別できませんが、ランダム ブロックはそれらの間の独立性によって分布が変化するため、分離されたままにする必要があります。 

の`normalize_block`関数は微妙なシングルトンの場合を処理します。 1 つの値のシャッフルではランダム性を導入できないため、それをランダム ブロックとして保持すると、同じ動作に対して複数の表現が作成されます。 

文法は自然に再帰的であるため、パーサーは再帰を使用します。 深くネストされた式をサポートするために、再帰制限が増加しました。 

## 実用的な例

 最初のサンプルについては、以下を比較してください。`concat(shuffle([1,2]),shuffle([1,2]))`そして`shuffle([1,2,1,2])`| ステップ | 最初のプログラム | 2番目のプログラム |
 | --- | --- | --- |
 | 最初のシャッフルを解析する | ランダムブロック`{1:1,2:1}`| |
 | 2 番目のシャッフルを解析する | 2 つの独立したランダム ブロック | |
 | 外側のシャッフルを解析する | | ランダムブロック`{1:2,2:2}`|
 | 標準形 |`R(1,2), R(1,2)`|`R(1,1,2,2)`|
 | 結果 | 違う | 違う |

 トレースは、ランダムなブロック境界を維持することが重要である理由を示しています。 2 つの式の合計マルチセットは同じですが、確率が異なります。 

2 番目のサンプルの場合:`sorted(concat([3,2,1],[4,5,6]))`そして`[1,2,3,4,5,6]`| ステップ | 最初のプログラム | 2番目のプログラム |
 | --- | --- | --- |
 | リテラルを読む | マルチセット`{1,2,3,4,5,6}`| 順序`(1,2,3,4,5,6)`|
 | 並べ替えて適用 | 決定論的`(1,2,3,4,5,6)`| 決定論的`(1,2,3,4,5,6)`|
 | 結果 | 等しい | 等しい |

 この例は、並べ替えによって以前の順序情報がすべて削除されることを示しています。

 ## 特殊なケース

 のために`shuffle([5])`と比較して`[5]`の場合、アルゴリズムは 1 つの要素を含むランダムなブロックを作成し、それをすぐに決定論的なブロックに変換します。 どちらも正規化すると、`D(5)`したがって、出力は正しくなります`equal`。 

のために`shuffle([1,1,2])`と比較して`concat([1],shuffle([1,2]))`、どちらの式にも同じ値が含まれていますが、正規化された形式は異なります。 最初のものはカウント付きの 1 つのランダムなブロックになります`{1:2,2:1}`、2番目は決定的なブロックになり、その後にランダムなブロックが続きます。 非表示の分割により可能な出力が変更されるため、アルゴリズムは次の値を返します。`not equal`。 

重複した値の場合、次のようになります。`sorted([9,9,1])`対`[1,9,9]`、マルチセット カウンタには 2 つのコピーが保存されます。`9`そして1部のコピー`1`。 ソートにより正確な決定的なシーケンスが生成されるため、両方のプログラムは同じ正規表現を受け取ります。
