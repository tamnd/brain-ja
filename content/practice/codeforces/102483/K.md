 ## 解決策
 ## 問題の理解

 タスクは、暗号化された文字列から元の日記テキストを復元することです。 暗号ではオートキー メカニズムが使用されます。最初の`n`キーの文字は不明ですが、それ以降、キーは平文の先頭からの文字を繰り返します。 メアリーは最後を知っている`n`平文の文字と完全な暗号文も含まれています。 この情報を使用して、平文全体を再構築する必要があります。 

暗号化は、0 ～ 25 の数字に変換された文字に対して機能します。各位置の暗号文の値は、平文の値とキー値のモジュロ 26 の合計になります。`n`キー文字は隠しキーワードであり、残りのキー文字は以前の平文の位置からコピーされます。 出力は、元の順序のプレーンテキスト文字列です。 

テキストの長さは最大 100 文字で、既知のサフィックスの長さは最大 30 文字です。これらの小さな境界により、いくつかの可能なアプローチが可能になりますが、暗号の構造により直接的な線形解が得られます。 たとえ限界がはるかに大きかったとしても、ほぼ解決策はあります。`O(m)`平文のすべての文字を判定する必要があるため、依然として自然なターゲットとなります。 

厄介な点は、既知の平文文字がメッセージの最後にあるのに対し、未知のキー プレフィックスがメッセージの先頭に影響を与えることです。 不注意なアプローチでは、左から右に復号化しようとする可能性がありますが、最初の`n`位置には既知のキー値がありません。 もう 1 つのよくある間違いは、既知のサフィックスが、未知のキーを回復するために必要な、欠落している平文の値を正確に提供することを忘れることです。 

たとえば、次のようになります。```
1 3
a
bac
```正しい出力は次のとおりです。```
aaa
```最後の平文文字は次のように呼ばれます。`a`。 最後のキー文字は最初の平文文字であるため、最後の暗号文文字は次の方程式を与えます。`c = a + a`、最初の平文文字を決定します。 キープレフィックスが既知の文字であると想定するメソッドは失敗します。これは、既知の文字がキーではなく平文であるためです。 

既知の接尾辞の長さが文字列のほぼ全体である場合、別の特殊なケースが発生します。```
2 3
ab
bbc
```正しい出力は次のとおりです。```
abc
```先頭には未知の文字が 1 つだけあり、アルゴリズムは引き続き最後の文字とそれ以前の平文の位置との関係を使用する必要があります。 多くの文字が不明な場合にのみ機能するソリューションでは、ここで不正確なインデックスが作成される可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、考えられる長さのすべての秘密キーワードが試行されます。`n`。 それぞれのキーワードには、`26^n`可能性があり、それぞれについてキーを生成し、暗号文を復号化し、結果の平文が既知のサフィックスで終わるかどうかを確認できます。 実際のキーワードがテストされた候補の中に含まれることが保証されているため、このアプローチは正しいです。 ただし、小さな値でも不可能になります。`n`。 と`n = 30`、候補者の数は`26^30`, これは処理できる範囲をはるかに超えています。 

ブルート フォースが不要な理由は、既知のサフィックスによって平文に依存するキーの部分が修正されるためです。 最初以降のポジションについては、`n`、キー文字は、まさに位置する平文文字です。`n`前の位置。 最後`n`平文文字はすでにわかっているので、最後の文字を使用できます。`n`未知の文字を最初に復元するための暗号文文字`n`主要なキャラクター。 

隠されたキーのプレフィックスが判明すると、メッセージ全体を復号化できます。 重要な点は、サフィックスは単なる検証条件ではないということです。 これは、オートキー関係を元に戻すために必要な欠落情報を提供します。 

ブルート フォースは、考えられるすべてのキーが考慮されるため機能しますが、検索スペースが指数関数的に増大するため失敗します。 既知の平文サフィックスからキー プレフィックスが明らかになるという観察により、問題は文字列上の数回の線形パスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^n * m) | O(m) | 遅すぎる |
 | 最適 | O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 暗号文と既知の最終暗号文を保存する`n`平文文字。 既知のサフィックスは応答の終わりを表し、未知のキー プレフィックスを回復するために使用されます。 
2.最初のを回復する`n`最後の文字を使用する主要な文字`n`暗号文の位置。 位置の暗号文文字の場合`i`、対応する平文文字はサフィックスに含まれているため、すでにわかっています。 方程式は`cipher[i] = plain[i] + key[i] (mod 26)`、したがって、キー文字は次のように計算できます。`key[i] = cipher[i] - plain[i] (mod 26)`。 

これは、最終的な理由で機能します。`n`位置は、平文と暗号文の両方が利用できる唯一の場所です。 
3. 完全なキーを構築します。 最初`n`文字は回復されたシークレットプレフィックスです。 以降のすべてのキー文字は平文文字からコピーされます`n`前の位置。 
4. 生成されたキーを使用して完全な暗号文を復号化します。 すべての位置について、26 を法とする暗号文値からキー値を減算して、平文値を取得します。 
5. 再構築された平文を出力します。 

アルゴリズムの背後にある不変条件は、生成されたすべてのキー文字が暗号のキー定義と一致することです。 最初`n`文字は平文が既知の位置から復元され、その後のすべての文字は既に再構築された平文からコピーされます。 キーはどの位置でも正しいため、逆暗号化式を適用すると、唯一可能な平文が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    suffix = input().strip()
    cipher = input().strip()

    key = [''] * m
    plain = [''] * m

    for i in range(n):
        plain[m - n + i] = suffix[i]

    for i in range(n):
        pos = m - n + i
        key[pos] = chr((ord(cipher[pos]) - ord(plain[pos])) % 26 + ord('a'))

    for i in range(n):
        key[i] = key[m - n + i]

    for i in range(n, m):
        key[i] = plain[i - n]

    for i in range(m):
        plain[i] = chr((ord(cipher[i]) - ord(key[i])) % 26 + ord('a'))

    print(''.join(plain))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずプレーンテキストとキーの配列を作成して、位置を独立して埋めることができるようにします。 既知のサフィックスは、平文配列の末尾に直接配置されます。 

キーを回復するループでは、最後のキーが使用されます。`n`ポジション。 この式ではモジュロ 26 が使用されます。これは、アルファベットでの減算は、回復などでラップアラウンドする可能性があるためです。`z`負の中間値から。 

キー プレフィックスが復元された後、キー アレイの先頭にコピーされます。 後のキーの位置は平文の位置から埋められます。`n`もっと前の場所。 キーは平文に依存し、それらの平文文字は使用前に既知である必要があるため、順序が重要になります。 

最後のループでは、逆暗号化操作が実行されます。 Python の整数はオーバーフローしないため、モジュロ計算ではアルファベットの折り返しのみが処理されます。

## テストケース```python
import sys
import io

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    suffix = input().strip()
    cipher = input().strip()

    key = [''] * m
    plain = [''] * m

    for i in range(n):
        plain[m - n + i] = suffix[i]

    for i in range(n):
        pos = m - n + i
        key[pos] = chr((ord(cipher[pos]) - ord(plain[pos])) % 26 + ord('a'))

    for i in range(n):
        key[i] = key[m - n + i]

    for i in range(n, m):
        key[i] = plain[i - n]

    for i in range(m):
        plain[i] = chr((ord(cipher[i]) - ord(key[i])) % 26 + ord('a'))

    return ''.join(plain)

assert solve("5 16\nagain\npirpumsemoystoal\n") == "marywasnosyagain"
assert solve("1 12\nd\nfzvfkdocukfu\n") == "shortkeyword"

assert solve("1 3\na\nbac\n") == "aaa"
assert solve("2 3\nab\nbbc\n") == "abc"
