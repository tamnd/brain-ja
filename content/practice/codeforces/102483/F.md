 ## 解決策
 # 問題の理解

 とゲームがあります`n`レベル。 仕上げレベル`i`永久にアイテムを与えてくれます`i`。 いかなる瞬間においても、通常のゲームプレイにとって重要なアイテムは、収集した最大の番号のアイテムだけです。なぜなら、大きなアイテムはすべて小さなアイテムよりも劣ることはありません。 

レベルごとに 2 種類の完了時間がわかります。 通常時`a[i][j]`レベルを終了する時間です`i`アイテムを持ちながら`j`。 ショートカットタイム`s[i]`特定のショートカット項目をすでに所有している場合にのみ使用できます`x[i]`。 目標は、すべての完了時間の合計ができるだけ小さくなるように、レベルを完了する順序を選択することです。 

制約`n <= 2500`が重要な制限です。 あたりのアルゴリズム`n^2`操作は許容され、約 600 万の遷移が行われます。 可能な状態の数が指数関数的に増加するため、順序を列挙したり、任意のサブセットを維持したりするアプローチは不可能です。 すべての可能な有向エッジで動作する多くのグラフ アルゴリズムでも、二次関数以上の作業が必要な場合はコストが高くなりすぎます。 

主な隠された構造は、現在の在庫が単一の数字、つまり最大の取得アイテムによって要約できることです。 現在の最大値よりも小さいインデックスでレベルを完了しても、将来の可能性が向上することはありません。 このようなレベルではコストがかかるだけであり、遅延する可能性があります。 将来のオプションを変更する唯一のレベルは、現在の最大アイテムを増やすレベルです。 

不注意な解決策は、いくつかの点で失敗する可能性があります。 次の入力を考えてみましょう。```
2
2 1 10 10 1
2 11 11 11 11
```最適な答えは`12`。 まず時間内にレベル 2 を完了します`11`、アイテム 2 を使用して時間内にレベル 1 を完了します`1`。 常に現在最も安いレベルを終了する貪欲な戦略は、最初にレベル 1 を選択し、支出します。`10`、その後支払います`11`レベル 2 の場合、与える`21`。 間違いは、少し高価なレベルが将来のはるかに安価なレベルのロックを解除できることを無視していることです。 

もう 1 つのよくある間違いは、インデックスが小さいすべてのレベルが利用可能になったらすぐに完了する必要があると想定していることです。 例えば：```
2
0 5 5 5 5
0 7 7 7 7
```答えは`12`。 レベル 1 を先に完了するか、レベル 2 を先に完了するかは、どちらも他方にとってより良いアイテムを作成するため、どちらも機能します。 アルゴリズムでは、アイテムの最大数を増やさないレベルの任意の順序を許可する必要があります。 

## アプローチ

 直接的なアプローチでは、可能な限りの仕上げレベルの順序を試します。 すべての有効な注文はスピードランの可能性を表すため、これは正しいですが、`n!`注文は可能ですが、非常に小さい場合でも注文は不可能になります`n`。 

より合理的な試みは、現在完了しているセットから次のレベルを選択するプロセスをモデル化することです。 これではまだ重要な構造が抜けています。 完成したセットには多くのレベルを含めることができますが、最大アイテム以下のすべてのレベルは、将来の進行の観点からは同等です。 唯一意味のある状態情報は、これまでに取得された最大のアイテムです。 

現在の最大アイテムが`m`。 以下のインデックスを持つ未完了のレベル`m`最大値を増やすことはできないため、それより早く完了しても何もロックを解除できません。 そのようなレベルはすべて最後まで延期できます。 唯一重要な決定は、どの大きなインデックスをどの順序で取得するかということです。 

これにより、問題はインデックスの最短経路問題に変換されます。 最大アイテムからの移行`m`より大きなレベルへ`i`そのレベルを意味します`i`は次の新しい最大値です。 移行コストはレベルを完了するのに必要な時間と同じです`i`アイテムを持っている間`m`。 以来`i`より大きくなければなりません`m`、すべてのトランジションが前進し、DAG が作成されます。 

最大アイテム到達後`n`、それ以上進むことはできません。 残りのレベルはアイテムを使用して完了します`n`、常に最強のアイテムです。 最終的なクリーンアップ コストは、最大ステップとしてまだ選択されていないすべてのレベルのコストの単純な合計です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 命令に対するブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最大項目の増加に関する動的プログラミング | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大項目間のすべての移行の最小コストを計算します。 あらゆる可能な最大電流に対して`j`そしてあらゆるレベル`i > j`、移行コストはレベルを完了するのに必要な時間です`i`アイテムを所有している間`j`。 ショートカットは次の場合にのみ含まれます。`x[i] <= j`なぜなら、そのとき初めて、その必要なアイテムがすでに利用可能になるからです。 
2. 以下の場合に動的プログラミングを使用します。`dp[i]`項目が次の状態に達するまでに必要な最小時間です。`i`入手アイテムの中で最大のものです。 初期状態は`dp[0] = 0`, なぜなら、アイテム0は最初から入手可能だからです。 
3. 小さいインデックスから大きいインデックスまで最大項目を処理します。 州から`j`、より大きなレベルごとに試してください`i`次の最大アイテムとしてリラックスしてください`dp[i]`と`dp[j] + cost(j, i)`。 すべての遷移は小さいインデックスから大きいインデックスに移動するため、この順序は有効です。 
4. アイテムに到達するための最小コストを見つけた後`n`、最大増加ステップとして使用されなかったすべてのレベルを終了するコストを追加します。 より簡単な方法は、到達したアイテムを観察することです`n`常に最適なパスの一部であり、最終的な移行パスはレベルに対してすでに支払われています`n`。 他のレベルはアイテムを使用して完了できます`n`実費で`min(a[i][n], s[i] if x[i] <= n)`。 以来のアイテム`n`が常に利用可能である場合、これが残りの各レベルで可能な最小コストになります。 

機能する理由: 最大取得アイテムは、将来の進行状況を完全に説明します。 現在の最大値を下回るレベルは時間を消費するだけであり、使用可能なアイテムを変更することはできないため、それを早めても解決策は改善されません。 すべての最適なスピードランは、最大アイテムを増やすレベルのみが最初に考慮されるものに変換できます。 これらの最大増加レベルは厳密に増加するシーケンスを形成し、動的プログラミングではそのようなすべてのシーケンスが考慮されます。 最大のアイテムを取得すると、残りの各レベルの完了時間がそれぞれ最短になるため、最終的なクリーンアップが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    x = [0] * (n + 1)
    s = [0] * (n + 1)
    a = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        x[i], s[i] = data[0], data[1]
        for j in range(n + 1):
            a[i][j] = data[2 + j]

    dp = [10**30] * (n + 1)
    dp[0] = 0

    for cur in range(n):
        if dp[cur] == 10**30:
            continue
        for nxt in range(cur + 1, n + 1):
            cost = a[nxt][cur]
            if x[nxt] <= cur:
                cost = min(cost, s[nxt])
            if dp[nxt] > dp[cur] + cost:
                dp[nxt] = dp[cur] + cost

    ans = dp[n]
    used = [False] * (n + 1)
    cur = n
    while cur != 0:
        found = False
        for prev in range(cur):
            cost = a[cur][prev]
            if x[cur] <= prev:
                cost = min(cost, s[cur])
            if dp[prev] + cost == dp[cur]:
                used[cur] = True
                cur = prev
                found = True
                break
        if not found:
            break

    for i in range(1, n + 1):
        if not used[i]:
            cost = a[i][n]
            if x[i] <= n:
                cost = min(cost, s[i])
            ans += cost

    print(ans)

if __name__ == "__main__":
    solve()
```項目番号がレベル番号と一致するため、入力は 1 から始まるインデックスを使用して保存されます。 動的プログラミング配列は、完了したレベルのコレクション全体ではなく、現在の最大項目のみを表します。 

遷移ループは試行のみを行います`nxt > cur`。 これがソリューションの中心的なプロパティです。 レベルは、そのインデックスが現在の最大値よりも大きい場合にのみ新しい最大値になることができるため、有用な進行状況はすべて増加シーケンスを形成します。 

ショートカットチェックでは以下を使用します。`x[nxt] <= cur`。 この状態は、ショートカット アイテムがすでに収集されていることを意味します。 現在の状態では最大の項目のみが保存されているため、インデックスが小さいすべての項目も使用可能であることが保証されます。 

再構成ステップでは、最大値を増やすために使用されたレベルをマークします。 残りのレベルはアイテムを使用して最後に追加されます`n`、アイテムなので`n`他のすべての項目を支配します。 Python の整数は任意の精度であるため、考えられる大きな答えには特別な処理は必要ありません。
