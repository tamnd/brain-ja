 ## 解決策
 ## 問題の理解

 容量のある風船もあります`1, 2, ..., n`整数のヘリウムが入ったガスボンベ。 各キャニスターは 1 つのバルーンにのみ割り当てる必要があり、キャニスター内のヘリウムの量を分割することはできません。 風船はその容量を超えるヘリウムを受け取ることはできません。 

目標はヘリウムの総量を最大化することではありません。 代わりに、割り当てを選択した後、容量の最小部分まで満たされている風船を確認します。 私たちは、その最悪の状態の風船をできるだけいっぱいにしたいと考えています。 

入力により、風船の数とすべてのキャニスター内のヘリウムの量がわかります。 出力は可能な最大値です`f`すべての風船が少なくとも`f`容量がいっぱいになりました。 爆発を回避する有効な割り当てが 1 つでも存在しない場合、答えは次のようになります。`-1`。 

制約`n <= 2 * 10^5`多くの割り当てを試みるものはすべて除外されます。 がある`n!`バルーンとキャニスターの間で可能な組み合わせがあるため、非常に小さな入力であっても直接検索することは不可能です。 有効な解決策が必要です`O(n log n)`または同様の場合、数十万の値の並べ替えは許容されますが、二次作業は許容されないためです。 

最初のエッジ ケースは、あらゆる一致を実現するには大きすぎるキャニスターです。 例えば：```
1
2
```唯一の気球には容量があります`1`、しかしキャニスターには次のものが含まれています`2`単位。 正しい出力は次のとおりです。```
-1
```最小部分のみを最適化する不注意なソリューションでは、キャニスターが「満杯」であるため、正の値が出力される可能性がありますが、爆発の制約は無視されます。 

もう 1 つの注意が必要なケースは、空のキャニスターです。```
3
0 2 3
```分類後のキャニスターは次のようになります`0, 2, 3`。 最初のバルーンは空のキャニスターを取得するため、最小の部分は次のようになります。`0`。 正しい出力は次のとおりです。```
0.0
```すべての風船が何らかのプラスの量を受け取ることができると仮定した解決策は、ここでは失敗します。 

3 番目のケースは、大きなキャニスターを大きなバルーンと組み合わせる必要がある場合です。```
3
1 1 3
```ソートされた代入により分数が得られます`1/1`、`1/2`、 そして`3/3`、したがって、答えは次のとおりです`0.5`。 最小のバルーンに最大のキャニスターを配置する貪欲なアプローチでは、すぐに無効な割り当てが行われてしまいます。 

## アプローチ

 ブルートフォース ソリューションでは、キャニスターのあらゆる可能な組み合わせが試行されます。 割り当てごとに、風船が破裂するかどうかを確認し、最小の充填率を計算します。 このアプローチは、考えられるすべての配置を検討するため正しいですが、割り当ての数は`n!`、ほぼすぐに使用できなくなります。 

それほど極端ではないバージョンでは、答えを二分探索し、考えられる各分数に対して照合アルゴリズムを実行します。 固定分数の場合`x`、各バルーンのサイズ`s`～を含むキャニスターが必要です`x*s`そして`s`ヘリウム。 一般的なマッチング アルゴリズムでも機能しますが、バルーンは非常に特殊な構造をしているため、そのアルゴリズムは必要ありません。 

重要な観察点は、バルーンの容量がすでにソートされていることです。`1, 2, ..., n`。 キャニスターが次のように分類されていくと、`c1 <= c2 <= ... <= cn`、可能な限り最良の割り当ては、最小のキャニスターと最小のバルーン、2 番目に小さいキャニスターと 2 番目に小さいバルーン、というようにペアにすることです。 

その理由は、より大きなキャニスターをより小さなバルーンに割り当てると、容量制限がさらに厳しくなる一方、より小さなキャニスターをより小さなバルーンに移動させると、すべての下限と上限を満たす可能性が高まるためです。 並べ替えた後は、各位置を個別に確認するだけで済みます。 

バルーン用`i`、割り当てられたキャニスターは以下を満たす必要があります。```
x * i <= ci <= i
```上限は風船が破裂するかどうかをチェックします。 下限により、可能な最小の分数が決まります。 最良の答えは単に次の最小値です。`ci / i`並べ替え後、すべての上限が有効である場合。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのキャニスターの量を降順でない順に並べ替えます。 最小のキャニスターは最小のバルーンに移動する必要があるため、ソートされた順序は考慮する必要がある唯一の割り当てを表します。 
2. 分類されたキャニスターの位置を確認します`i`風船に対して`i + 1`。 キャニスターに以上のものが入っている場合、`i + 1`ヘリウムの場合、その風船は爆発してしまい、有効な割り当てが存在しません。 
3. 有効なすべてのバルーンについて、分数を計算します。`canister / capacity`。 目的は最も充填されていないバルーンを最大化することであるため、答えはこれらの分数の最小値になります。 
4. 最小の分数を十分な精度で出力します。 

機能する理由: 分類後、キャニスターのすべてのプレフィックスに利用可能な最小量が含まれます。 最小の場合`k`キャニスターは最小のものを充填できます`k`バルーンをソート順に並べる場合、他の割り当てを行っても最も弱いバルーンを改善することはできません。これは、大きなキャニスターを小さなバルーンに移動しても、より有用性の低いリソースを消費するだけであるためです。 したがって、ソートされたペアリングにより、可能な最大の最小部分が得られます。 この組み合わせの最小比率はまさに制限バルーンです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    c = list(map(int, input().split()))
    c.sort()

    ans = 1.0
    for i, x in enumerate(c, start=1):
        if x > i:
            print(-1)
            return
        ans = min(ans, x / i)

    print("{:.10f}".format(ans))

if __name__ == "__main__":
    solve()
```このコードは、貪欲なペアリングが可能になるように、最初にキャニスターをソートします。 ループは使用します`start=1`バルーンの容量は`1`を通して`n`、 ない`0`を通して`n-1`。 

条件`x > i`爆発ルールをチェックします。 風船が溢れると割り当て全体が不可能になるため、これは答えを計算する前に行う必要があります。 

変数`ans`これまでに確認された最も弱いバルーン部分を保存します。 必要な誤差許容度は次のとおりであるため、ここでは Python 浮動小数点精度で十分です。`1e-6`。 

Python では整数オーバーフローの懸念はありません。 固定幅の整数を使用する言語では、元の値が次のように大きくなる可能性があるため、比較は慎重に行う必要があります。`200000`。

 ## 特殊なケース

 あふれたキャニスターケースの場合:```
1
2
```ソートされたリストには、値を持つ 1 つのキャニスターが含まれています`2`。 アルゴリズムはそれを風船の容量と比較します`1`そして検出します`2 > 1`、したがって、それは返されます`-1`分数を計算する前に。 

空のキャニスターの場合:```
3
0 2 3
```ソート順は変更されません。 分数は`0/1`、`2/2`、 そして`3/3`。 最小値は`0`1 つのバルーンは空のままにしておく必要があるため、これが可能な限り最良の答えです。 

順序が重要な場合:```
3
1 1 3
```ソートされた割り当てによりバルーンの容量が得られます`1, 2, 3`ヘリウム入り`1, 1, 3`。 分数は`1`、`0.5`、 そして`1`。 アルゴリズムは戻ります`0.5`。 最初に最大のキャニスターを最小のバルーンに割り当てても、最小部分は改善されず、より複雑な入力で無効な状態が作成される可能性があります。
