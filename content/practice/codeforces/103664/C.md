 ## 解決策
 ## 問題の理解

 いくつかの独立した整数のトリプルが与えられます。 各トリプルについて、2 つの非負の整数を構築できるかどうかを判断する必要があります。$x$そして$y$3 つの条件が同時に成立するように、それらのビットごとの AND が指定された値に等しい$a$、それらのビットごとの OR は指定された値に等しい$b$、およびそれらの算術差$x - y$指定された値と等しい$c$。 そのようなペアが存在する場合は、有効なペアを出力する必要があります。$x, y$; それ以外の場合は出力します$-1$。 

主な難点は、ビットごとの制約がビットごとの関係を定義するのに対し、減算制約はキャリー (2 進減算での借用) を通じてすべてのビットを結合することです。 この相互作用は、AND と OR がビットごとの構造を示唆しているとしても、ビットを独立して扱うことができないことを意味します。 

この制約により、最大 1 万のトリプルが許可され、各値は最大約 10 億になります。 これは、各数値が 30 ～ 31 ビットの範囲内に快適に収まることを意味します。 各トリプルをビット単位で線形時間で処理するソリューションであればどれでも十分ですが、割り当てをビット単位で指数関数的に探索しようとするものはすぐに失敗します。 

よくある失敗例は、減算を考慮せずにビットごとの制約を処理した場合に発生します。 たとえば、次の場合$a = 0$、$b = 1$、 そして$c = 0$を割り当てようとするかもしれません$x = y = 0$または$x = y = 1$ビットごとに一貫性がありませんが、減算によりグローバルな一貫性が強制されます。 もう 1 つの微妙なケースは、減算にボロー チェーンが必要な場合です。 借用が複数のビットに伝播すると、ローカルで有効なビット選択がグローバルに不可能になる可能性があります。 

## アプローチ

 減算制約を無視すると、問題は簡単になります。 から$a = x \& y$そして$b = x | y$、各ビットは独立して動作します。 少しでも$b$両方ともゼロです$x$そして$y$その位置にはゼロがなければなりません。 少しでも$a$は 1 つであり、両方とも 1 つでなければなりません。 ビットが 1 の場合$b$そしてゼロイン$a$の場合、そのビットのペアは次のいずれかである必要があります。$(1,0)$または$(0,1)$、自由を与えます。 

ブルートフォースアプローチでは、あいまいなビットに対するすべての代入を試み、結果の整数が次の条件を満たすかどうかを確認します。$x - y = c$。 最悪の場合、多くのビットがあいまいな場合、組み合わせの数が指数関数的に増加します。$2^k$、次の場合は不可能です$k$30に近づく。 

重要な観察は、グローバル結合のみが減算から得られるということです。 一度解釈してみると$x - y = c$バイナリ減算として、借用状態を追跡しながら、最下位ビットから最上位ビットまで処理できます。 各ビットは、現在のボロー、選択されたペアを含むローカル方程式に寄与します。$(x_i, y_i)$、および結果として得られるビット$c$。 これにより、問題はビットと単一のバイナリ状態に関する動的プログラミング プロセスに変換されます。 

AND/OR 制約は各ビットで許可されるペアを制限し、減算制約はそれらのペアの中から一貫して選択します。

 ## アルゴリズムのチュートリアル

 各トリプルを個別に処理します。 固定トリプルの場合$(a, b, c)$、3 つの数値すべてのバイナリ表現を最大 31 ビットで構築します。 

1. ビット位置と借用に関する動的プログラミング状態を定義します。 状態は、有効なプレフィックスを構築できるかどうかを表します。$x$そして$y$特定のボローによる減算制約を維持しながら、指定されたビットまで。 
2. ボローを 0 に設定してビット 0 (最下位ビット) で初期化します。これは減算の開始に対応します。$x - y$借り入れなしで。 
3. 各ビット位置について、どの割り当てを行うかを決定します。$(x_i, y_i)$AND/OR 制約によって許可されます。 OR ビットが 0 の場合、両方のビットが 0 である必要があります。AND ビットが 1 の場合、両方のビットが 1 である必要があります。それ以外の場合は、両方の混合割り当てが行われます。$(1,0)$そして$(0,1)$可能です。 
4. 許可された割り当てごとに、このビットでのバイナリ減算をシミュレートします。 私たちは計算します$x_i - y_i - \text{borrow}_{in}$。 この結果は次のビットと一致する必要があります。$c$これに 2 の倍数を加え、これにより借入額が決まります。 この一貫性が失われると、遷移は無効になります。 
5. DP 状態を前方に遷移させ、次のビットの特定のボロー状態に到達できるかどうかを記録します。 
6. すべてのビットを処理した後、最終的なボローがゼロであることが必要です。 そうでない場合は、有効な整数が存在しません。 
7. 有効なパスが存在する場合、再構築します。$x$そして$y$移行中に行われた決定を保存することによって。 

減算の整合性チェックは、グローバルな相互作用が発生する唯一の場所です。 他のすべての制約はビットごとにローカルです。 

### なぜ効果があるのか

 このアルゴリズムは、次のすべての有効なプレフィックスをエンコードします。$(x, y)$これは、ビットごとの制約と部分的な減算の一貫性の両方を尊重します。 借用状態は、バイナリ減算における上位ビットに対するすべての下位ビットの影響を完全に捕捉します。 バイナリでの減算にはボロー以外に隠れた状態がないため、メモリのこの 1 ビットを維持するだけで正確性を保証できます。 無効なグローバル割り当てはすべて、許可されたビット パターンに違反するか、ボロー状態で減算式が満たされない場合、あるビットで失敗する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a, b, c):
    MAXB = 31

    # dp[bit][borrow] -> store predecessor info
    dp = [[False, False] for _ in range(MAXB + 1)]
    parent = [[None, None] for _ in range(MAXB + 1)]

    dp[0][0] = True

    def allowed_pairs(ai, bi):
        if bi == 0:
            return [(0, 0)]
        if ai == 1:
            return [(1, 1)]
        return [(0, 1), (1, 0)]

    for i in range(MAXB):
        ai = (a >> i) & 1
        bi = (b >> i) & 1
        ci = (c >> i) & 1

        for borrow in [0, 1]:
            if not dp[i][borrow]:
                continue

            for xbit, ybit in allowed_pairs(ai, bi):
                val = xbit - ybit - borrow
                out_bit = val & 1
                out_borrow = 1 if val < 0 else 0

                if out_bit == ci:
                    if not dp[i + 1][out_borrow]:
                        dp[i + 1][out_borrow] = True
                        parent[i + 1][out_borrow] = (i, borrow, xbit, ybit)

    if not dp[MAXB][0]:
        return None

    x = 0
    y = 0
    bit = MAXB
    borrow = 0

    while bit > 0:
        i, pb, xb, yb = parent[bit][borrow]
        if xb:
            x |= (1 << i)
        if yb:
            y |= (1 << i)
        borrow = pb
        bit -= 1

    return x, y

def main():
    n = int(input())
    for _ in range(n):
        a, b, c = map(int, input().split())
        res = solve_case(a, b, c)
        if res is None:
            print(-1)
        else:
            print(res[0], res[1])

if __name__ == "__main__":
    main()
```このソリューションは、各トリプルを個別に処理し、最大 31 位置にわたるビット単位の動的プログラムを構築します。 DP テーブルは、ビットのプレフィックスが特定の借用状態で形成できるかどうかを追跡します。 親配列には、最終的な数値を再構築するために使用される遷移が格納されます。 

許可されたペア ジェネレーターは、算術推論の直前に AND/OR 制約を強制します。 次に、減算チェックにより、これらの候補が必要なビットと一致するかどうかに基づいてフィルタリングされます。$c$現在の借入のもとで。 

再構築は最上位ビットから逆方向に進み、有効な最終状態を導いた正確なビット選択を回復します。 

## 実用的な例

 次の場合を考えてみましょう$a = 2$、$b = 7$、$c = 3$。 2 進数では、これは両方の数値で 1 つのビットだけが 1 に固定され、他のビットは柔軟な小規模システムに相当します。 

説明のために、いくつかの最下位ビットのみを追跡します。 

| ビット | あい | バイ | ci | で借りる | 選択された (x,y) | 借ります | 有効 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 1 | 0 | (1,0) | 0 | はい |
 | 1 | 1 | 1 | 1 | 0 | (1,1) | 0 | はい |
 | 2 | 0 | 0 | 0 | 0 | (0,0) | 0 | はい |

 このトレースは、ローカル制約と減算の一貫性を組み合わせることで、有効な割り当てがどのように強制されるかを示しています。 各ステップでは、ビットごとのルールと算術伝播の両方が確実に一致するようにします。 

ここで、失敗したケースを考えてみましょう。$a = 1$、$b = 1$、$c = 2$。 ここでは両方とも$x$そして$y$ビット 0 では 1 でなければなりませんが、減算ではボロー制約に違反せずに上位ビットで正の結果を生成することはできません。 DP は、最終ビットで有効な状態が得られずに終了します。

 ## 特殊なケース

 重要なエッジ ケースは、OR 制約により柔軟性が得られるものの、減算によってすぐにボロー チェーンが強制される場合に発生します。 たとえば、下位ビットがすべて 0 の場合、$c$ただし、有効なビット割り当てのみがゼロ以外の中間差分を作成するため、DP は次のビットですべてのパスを正しく拒否します。 

もう一つのケースは次のような場合です。$a = b$。 これにより、$x = y = a$、減算はゼロになります。 アルゴリズムは、ビットごとに 1 つの遷移のみを許可することでこれを処理し、借用状態は決してアクティブになりません。 

3 番目のケースは次の場合です。$c$可能なビット割り当てに対して実質的に負の値になります。 入力が負ではない場合でも、十分な上位ビットが下位ビット構造を補償する場合にのみ減算を実現できます。 DP は、ボロー一貫性のあるパスが最終状態に到達しない場合に、不可能であることを正しく検出します。
