 ## 解決策
 ## 問題の理解

 情報を共有できる可能性のある一連の人々が、無向グラフとして表されます。 各人はノードであり、2 つのノード間のエッジは彼らが知人であることを意味します。 

探偵は、1 から n までの決まった順序で人々を呼び出します。 人が呼ばれると、その人が個人的に知っていることだけでなく、知人コンポーネント全体、つまり友情エッジを通じて到達可能なすべてのノードによって知られているすべてのことも明らかにされます。 接続されたコンポーネントがそのメンバーのいずれかを呼び出して「アクティブ化」されると、そのコンポーネント全体の情報が知られるようになります。 

タスクは、多数の通話を処理した後、すべての人の情報が少なくとも 1 回収集されるように、通話順序の最も早い位置を決定することです。 

グラフ用語では、インデックスの昇順でノードを処理します。 ノードに到達したときに、接続されているコンポーネント全体がこれまでに表示されていない場合は、そのコンポーネントを検出済みとしてマークします。 すべての連結成分をカバーする順列 1 から n の最初の接頭辞が必要です。 

この制約では、最大 100,000 のノードとエッジが許可されます。 これにより、伝播をシミュレートしたり、BFS または DFS を使用して呼び出しごとの到達可能性を最初から再計算しようとするソリューションは即座に除外されます。 ノードごとにグラフ走査を実行する単純なアプローチでは、最悪の場合は二次関数となり、制限をはるかに超えてしまいます。 

グラフに孤立したノードがある場合、微妙なエッジ ケースが発生します。 分離された各ノードは独自のコンポーネントを形成し、それを呼び出して明示的に「アクティブ化」する必要があります。 もう 1 つのエッジ ケースは完全に接続されたグラフで、最初のノードを呼び出すとすぐにすべてがカバーされます。 

たとえば、エッジのない n = 3 を考えてみましょう。 各ノードは分離されているため、3 つのノードすべてを呼び出す必要があり、答え 3 が得られます。呼び出し間の伝播を想定しようとすると、誤って呼び出し数が少なくなることが示唆されます。 

一方、すべてのノードが接続されている場合 (たとえば 1-2-3)、ノード 1 を呼び出すとすでにすべてのノードがカバーされているため、答えは 1 になります。 

## アプローチ

 強引な解釈では、プロセスを直接シミュレートします。 訪問した配列をノード上で維持します。 1 から n までの呼び出し i ごとに、ノード i から BFS または DFS を実行し、接続されているコンポーネント内のすべてのノードを訪問済みとしてマークします。 各呼び出しの後、すべてのノードが訪問されたかどうかを確認します。 

これは情報伝播ルールを正確に反映しているため、これは正しいです。 ただし、各 DFS/BFS はコール全体で合計 O(n) 個のノードと O(m) 個のエッジを通過する可能性があり、最悪の場合は O(n(n + m)) になります。 n、m が 100,000 までの場合、これは不可能です。 

重要な観察は、グラフ構造が呼び出しの順序に依存しないことです。 接続された各コンポーネントは単一の原子単位として動作します。 唯一の問題は、与えられた順序で各コンポーネントをいつ最初に触るかということです。 

単一の DFS または DSU を使用して、グラフを接続コンポーネントに前処理できます。 各ノードにはコンポーネント識別子が割り当てられます。 次に、ノードを 1 から n までスキャンし、どのコンポーネントがすでに「アクティブ化」されているかを記録します。 新しいコンポーネントのノードを初めて確認すると、検出されたコンポーネントの数が増加します。 答えは、この数がコンポーネントの総数と等しくなる最初のインデックスです。 

これにより、グラフの走査を繰り返すという問題が、単一の前処理ステップと線形スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | コールごとに繰り返される DFS | O(n(n + m)) | O(n + m) | 遅すぎる |
 | コンポーネント + スキャン | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、グラフを連結コンポーネントに圧縮し、各コンポーネントが指定された順序で最初に出現するタイミングを追跡することで解決します。

1. 指定されたエッジからグラフの隣接リストを作成します。 この表現により、すべての知り合いを効率的に調べることができます。 
2. すべてのノードで DFS または BFS を実行し、各ノードにコンポーネント ID を割り当てます。 未訪問のノードからトラバーサルを開始するたびに、コンポーネント カウンタをインクリメントし、到達可能なすべてのノードにそのコンポーネント ID のラベルを付けます。 このステップでは、相互に連絡可能な証人を単一の情報共有単位にグループ化します。 
3. 前処理の後、接続されたコンポーネントが合計でいくつ存在するかがわかります。 
4. コンポーネントに対してブール配列を作成し、コンポーネントが以前の呼び出しによってすでに「アクティブ化」されているかどうかを追跡します。 
5. ノード 1 から n までを順番に繰り返します。 各ノードについて、そのコンポーネント ID を確認します。 そのコンポーネントがこれまでに検出されたことがない場合は、そのコンポーネントを検出済みとしてマークし、検出されたコンポーネントの数を増やします。 
6. 検出されたコンポーネントの数がコンポーネントの総数と等しくなったらすぐに停止し、現在のインデックスを出力します。 このインデックスは、接続されているすべてのグループが少なくとも 1 回タッチされた、呼び出しシーケンスの最も早い時点を表します。 

### なぜ効果があるのか

 接続された各コンポーネントは情報の伝播の下で閉じられます。つまり、その内部の単一ノードを呼び出すと、そのコンポーネント内のすべてが表示され、その外部には何も表示されません。 したがって、すべての情報を収集するには、すべてのコンポーネントをカバーすることが必要かつ十分です。 スキャンではノードが順番に処理されるため、最初にすべてのコンポーネントから少なくとも 1 つの代表を選択したとき、それはまさにグラフ全体をカバーする最も古いプレフィックスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    comp = [0] * (n + 1)
    comp_id = 0

    # iterative DFS to avoid recursion depth issues
    for i in range(1, n + 1):
        if comp[i] == 0:
            comp_id += 1
            stack = [i]
            comp[i] = comp_id

            while stack:
                v = stack.pop()
                for to in g[v]:
                    if comp[to] == 0:
                        comp[to] = comp_id
                        stack.append(to)

    seen = [False] * (comp_id + 1)
    got = 0

    for i in range(1, n + 1):
        c = comp[i]
        if not seen[c]:
            seen[c] = True
            got += 1
            if got == comp_id:
                print(i)
                return

    print(n)

if __name__ == "__main__":
    solve()
```隣接リストの構築では、友情グラフを直接キャプチャします。 DFS フェーズでは、グラフを連結コンポーネントに圧縮し、各ノードが相互到達可能性の正しい同値クラスでラベル付けされるようにします。 2 番目のパスは固定順序での貪欲スキャンであり、ブール配列により各コンポーネントが 1 回だけカウントされることが保証されます。 

反復 DFS を使用すると、大規模なチェーンの Python で発生する可能性のある再帰の深さの問題が回避されます。 すべてのコンポーネントが確認された瞬間に早期に終了し、正しい最小プレフィックス長が保証されます。

 ## 特殊なケース

 単一ノード グラフの場合、DFS は 1 つのコンポーネントを正確に割り当て、スキャンによってインデックス 1 にあるように即座にマークが付けられます。答えは 1 で、最初の呼び出しですでにすべてが完了しているという直感と一致します。 

エッジのないグラフの場合、すべてのノードが独自のコンポーネントを形成します。 各インデックスには新しいコンポーネントが導入されるため、スキャンは最後のノードに到達した後でのみ完了します。 このアルゴリズムは、n 個の個別のアクティベーションを正確にカウントします。 

複数の切断されたクラスターを含むグラフの場合、アルゴリズムにより、各クラスターが正確に 1 回カウントされることが保証されます。 最初に出現する順序によって答えが決まり、コンポーネントの圧縮により、クラスター内での二重カウントがないことが保証されます。
