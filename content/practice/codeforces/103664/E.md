 ## 問題の理解

 ジョンとポールの 2 人のプレイヤーが、ジョンから始めて交互に言葉を発します。 プレイヤーが話すたびに、個人の範囲内で整数の強さを選択します。 John は 1 から最大までの任意の値を選択できます。$R_J$、ポールは1から$R_P$。 すべての話された強さの現在までの合計があります。 この合計が初めて所定のしきい値に達するか超えた瞬間$h$、ゲームはすぐに停止し、今話したプレイヤーが負けます。 

重要な点は、どちらのプレイヤーもしきい値を超える人になりたくないため、合法的に回避する方法がある場合は、どちらも自分の手でゲームを終了させないようにすることです。 ジョンの目標はさらに強力です。彼は、ポールがどのようなプレーをしても、最終的に合計が少なくとも達成できるようにポールを強制できることを保証したいと考えています。$h$。 それが可能であれば、ジョンが話すべき最初の値も出力する必要があります。 

入力サイズは最大に達します$10^{18}$、一度に 1 つの動きを処理するシミュレーションは即座に除外されます。 平$10^9$操作は 1 秒では遅すぎるため、解決策は動きのブロックについて推論するか、プレーの決定論的な構造を導き出す必要があります。 

唯一の微妙なケースは、残り距離が少なくなったゲームの終了近くに発生します。$h$小さくなる。 たとえば、誰かのターンの開始時に残りの必要な合計が 1 である場合、そのプレイヤーは、何らかのプラスの動きがしきい値に達するか、しきい値を超えるため、すでに即時に負けることを余儀なくされています。 別のエッジケースは、プレイヤーが 1 回の動きで最後まで正確に「ジャンプ」できる場合、たとえば残りの要件が最大筋力プラス 1 である場合に発生します。 その状況では、相手を即座に負けの立場に追い込むような手を選択することができます。 

単純なステップバイステップのシミュレーションでは、毎ターン常に何らかの正当な値を選択し、合計を更新します。 これは正確さのためではなく、ターン数が線形になる可能性があるために失敗します。$h$、これは大きすぎます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ゲームの動きを一手ごとにシミュレートします。 各ターンで、現在のプレイヤーは有効な強さを選択し、合計を更新し、しきい値に達しているかどうかを確認します。 両方のプレイヤーに対して考えられるすべての選択肢を試してみると、ジョンが先手で勝利を収めているかどうかを確認できます。 

ゲームには完全な情報と有限の分岐があるため、このアプローチは原理的には正しいです。 ただし、分岐は不要です。 実際には、両プレイヤーは非常に制約された方法で最適に行動します。回避できれば自発的に負けることはありません。 この観察は、決定の余地を劇的に崩壊させます。 

重要な構造的洞察は、どの時点でも、プレーヤーは常にすぐに失うことなく追加した金額を最大化しようとするということです。 残りの距離が$h$値が大きい場合は、常に最大許容強度を選択します。これより小さい値は、後で対戦相手にとって容易になるだけであるためです。 残り距離が短く、相手を直接不利な立場に追い込むことができる場合、彼らはすぐにそうします。 

これにより、ゲームから実際の選択肢がすべて削除されます。 プロセス全体が決定的になります。どの状態からでも、両プレイヤーの行動は残りの距離と最大許容体力によって決まります。 問題は、戦略を模索するのではなく、進化する単一の数値を追跡することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 残りの必要額から開始します$rem = h$、そしてジョンが最初に動きます。 移動によって累計額がその額に達するかそれを超えると、ゲームは終了します。$h$、これは運転に相当します。$rem$0以下にまで下がります。 
2. 価値が残っているプレイヤーのターン$rem$、すぐに相手を不利な状況に追い込むことができるかどうかを確認します。 これは次のような場合に起こります。$rem \le R + 1$、プレイヤーが選択できるため、$rem - 1$、相手に正確に残します$rem = 1$、これは彼らのターンでの強制的な損失です。 
3. ジョンが始めたら、$h \le R_J + 1$、ジョンはすぐに選択できます$W_J = h - 1$。 これにより、ポールは確実に直面することになります。$rem = 1$そして彼のターンで負けます。 
4. そうしないと、ジョンは 1 つの手で終了できず、最大安全値をプレイすることになります。$R_J$。 これにより、残りの要件は次のように減ります。$rem = h - R_J$。 
5. 次はポールの番です。 同じロジックを対称的に適用します。$rem \le R_P + 1$, ポールは退場することですぐに勝利を強制することができます。$rem = 1$ジョンのために。 
6. どちらのプレイヤーもすぐに終了できない場合は、両方とも最大限の安全な手を繰り返し実行します。 これは、各ラウンド (ジョン、ポール) ごとに、残りの値が ずつ減少することを意味します。$R_J + R_P$。 
7. 残りの値が十分小さくなり、プレイヤーの 1 人が$rem \le R + 1$状態。 その時点で、同じルールを使用して最後の 1 つか 2 つの手を直接解決します。 

### なぜ効果があるのか

 すぐにフィニッシュが不可能なすべての状態において、最大の安全な手よりも小さい手は、どちらのプレイヤーもすぐにフィニッシュできないという事実を変えることなく、対戦相手の残りの値を増やすだけです。 どちらのプレイヤーも即時の損失を避けることを好み、残りの値をできる限り減らすという対称的なインセンティブを持っているため、唯一の安定したプレイは各ターンの最大の安全な減少です。 これにより、ゲームは決定的なカウントダウンになり、次の場合に時折ターミナル ジャンプが発生します。$rem$1人のプレイヤーのフィニッシュ圏内に入る。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

h, RJ, RP = map(int, input().split())

def can_finish(rem, R):
    return rem <= R + 1

# If John can finish immediately
if h <= RJ + 1:
    print("John")
    print(h - 1)
    sys.exit()

rem = h
turn = 0  # 0 = John, 1 = Paul

while True:
    if turn == 0:
        if rem <= RJ + 1:
            print("John")
            print(rem - 1)
            break
        rem -= RJ
    else:
        if rem <= RP + 1:
            print("Paul")
            break
        rem -= RP
    turn ^= 1
```コードは、決定論的削減プロセスを直接実装します。 最初のチェックは、ジョンが 1 つの手でゲームを終了できる唯一の状況を処理します。 その後、ループではプレイヤーが交代し、即座に負けを強いられるほど最後まで近づいていない限り、安全貢献度を全額減算します。 状態変数`rem`閾値からどれだけ離れているかを追跡し、`turn`誰の動きであるかをエンコードします。 

実装の詳細で重要なのは、1 つの動きにつき複数の選択肢を決して検討しないことです。 貪欲な減算は、これより小さな減算では現在のプレーヤーの結果を改善することはできず、順位を遅らせたり悪化させたりするだけであるため、有効です。

 ## 特殊なケース

 重大なエッジケースの 1 つは次のような場合です。$h \le R_J + 1$。 たとえば、入力の場合$h = 6, R_J = 7, R_P = 8$, ジョンはすぐに5を選択し、去ります。$rem = 1$。 アルゴリズムはループの前にこれを処理し、それ以上の動きをシミュレートすることなく John を正しく出力するようにします。 

もう 1 つのエッジ ケースは、両方のプレーヤーの制限が非常に小さい場合です。$h = 10, R_J = R_P = 1$。 このループは、プレイヤーのターンで残りの値が 1 になるまで単一ユニットを交互に減少させることで問題を軽減します。 決定論的な減算により、結果に曖昧さがなくなります。 

最後の微妙なケースは、一方のプレイヤーがもう一方のプレイヤーよりもはるかに広い範囲を持っている場合です。 たとえば、次の場合$R_J \gg R_P$, ジョンはもっと早くフィニッシュウィンドウに直接飛び込むことができるかもしれません。 条件$rem \le R_J + 1$はこれを正確に捉え、中間状態をシミュレートすることなく、この機会を正しい瞬間に確実に検出します。
