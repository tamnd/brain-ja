 ## 解決策
 ## 問題の理解

 線路に沿った順番の駅のシーケンスとして記述された鉄道ルートが与えられます。 これらの駅の一部は停車駅ですが、残りは停車せずに通過します。 アナウンサーが停車駅を説明する方法は 3 つあります。列車がどこでも止まると主張するか、すべての停車駅を明示的に列挙するか、代わりに停車しない駅をすべて列挙し、その他の場所では停車すると言います。 

アナウンスのコストは、純粋にテキスト内の文字数として定義されます。 句読点、スペース、および定型語は固定量に寄与し、駅名のみがケースごとに異なります。 ここでの課題は、3 つの形式のうちどれが生成する文字の総数が最も少ないかを判断することです。 

主な問題点は、最適な選択がルート内の順序ではなく、一連の停車駅の構造のみに依存することです。 変数部分がすべての測点のリスト、選択された測点のリスト、または除外された測点のリストのいずれかである 3 つの式を効果的に比較しています。 

この制約では、最大 10^4 のステーションと 10^4 の名前の合計長が許可されます。これは、複数の大きな連結文字列を明示的に繰り返し構築するソリューションは、各ステーションが一定の回数処理される場合にのみ許容されることを直ちに示唆しています。 ステーション数の 2 次関数や大きなプレフィックスにわたる文字列連結の繰り返しは、Python では遅すぎます。 

微妙な特殊なケースは、非常に長い名前の駅にあります。 単純な実装では、ステーションの数のみが重要であると想定する可能性がありますが、コストは合計文字長に依存するため、各名前を個別に考慮する必要があります。 

別の特殊なケースは、停車駅のセットがすべての駅または 1 つの駅だけの場合に発生します。 このような場合、1 つ以上の形式が空のリストに変質し、慎重に扱わないと、区切り文字に関する 1 つずつ異なる推論により、誤ったコストが発生する可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられる 3 つのアナウンスすべてを文字列として明示的に構築し、その長さを計算します。 「すべての停留所を除く」バージョンでは、補集合を計算して駅名を結合する必要もあります。 これは、ステーションの数が十分に少ないため、繰り返しスキャンすることも可能ですが、完全な文字列の構築には繰り返しの連結とメンバーシップ チェックが含まれるため、Python では不用意に実行すると O(n^2) の動作に低下する可能性があります。 最悪の場合、すべてのステーション名が長く、文字列の再構築を繰り返し行うと、速度が非常に遅くなります。 

重要な観察は、実際には完全な文を構築する必要がないということです。 固定プレフィックス構造は 3 つのケースすべてで同一であるため、コストを比較すると相殺されます。 異なるのは、駅名の長さの合計と区切り文字の数だけです。 

したがって、文字列を構築する代わりに、すべての駅名の合計の長さ、選択された駅の合計の長さ、および除外された駅の合計の長さという 3 つの量を計算します。 除外されたステーションは単なる補数であるため、その全長は合計から選択されたものを差し引いたものになります。 

これにより、問題は一定数の算術式に縮小されます。

 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この値はすべての比較で再利用されるため、すべてのステーション名の合計の長さを事前に計算します。 また、マークされた停車駅のリストを読み取り、名前から長さまでの辞書検索を使用して停車駅の長さの合計を計算します。 

次に、考えられる 3 つのアナウンスコストを評価します。

まず、「全停留所」形式では、定型句に加えて、すべての停留所名の合計、およびそれらの間の区切り文字がかかります。 区切り文字は最初の駅を除いて駅ごとに一定であるため、これは停車駅の数の一次項に寄与します。 

2 番目に、「すべての駅を除く」形式では、すべての駅が使用されますが、停車駅は除外されます。 その変動コストは除外されたステーション名の合計であり、総計から選択された合計を引いたものとして計算されます。また、区切り文字は除外されたステーションの数に依存します。 

第三に、「オール ストップ」の縮退形式にはリストがなく、定型文だけが含まれます。 

3 つのコストをすべて計算し、最小値を取得します。 

## なぜ機能するのか

 各アナウンスは、固定プレフィックスと、固定句読点ルールで区切られた一連のステーション名で構成されます。 プレフィックスは比較全体で同一であるため、どのオプションが最小であるかには影響しません。 したがって、全長を最小限に抑えることは、ステーション名の長さと区切り文字数に関する一次式を最小限に抑えることになります。 包含と除外の両方がステーション名の同じユニバースを分割するため、必要な合計はすべて入力の 1 回のパスから導出できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    names = []
    total_len = 0

    for _ in range(n):
        s = input().strip()
        names.append(s)
        total_len += len(s)

    name_len = {s: len(s) for s in names}

    m = int(input())
    chosen = []
    chosen_len = 0

    for _ in range(m):
        s = input().strip()
        chosen.append(s)
        chosen_len += name_len[s]

    # cost components
    # separators: ", " between names, but punctuation irrelevant constant offset per choice
    # we only need relative comparisons, but we compute full expression for clarity

    # option 1: list chosen stations
    cost1 = chosen_len

    # option 2: list excluded stations
    excluded_len = total_len - chosen_len
    cost2 = excluded_len

    # option 3: all stops
    # equivalent to chosen == all stations, but as a separate form it is just total
    cost3 = total_len

    print(min(cost1, cost2, cost3))

if __name__ == "__main__":
    solve()
```このコードは、各ステーション名をその長さにマッピングし、単一パスで合計を集計します。 辞書を使用すると、選択したセットを合計するときに定数時間の検索が可能になります。 3 つの候補コストは、純粋にこれらの集計から計算されます。 

実装の微妙な詳細は、長さを計算する前にステーション名から改行文字を削除することです。 もう 1 つのポイントは、補完リストを明示的に構築する必要がないことです。 合計から減算すれば十分です。

 ## 特殊なケース

 主なエッジケースは、すべての駅が停止している場合です。 その場合、「除外リスト」は空になり、料金は定型句とゼロの駅名のみに依存します。 除外された長さは合計から合計を引いた値 (ゼロ) になるため、アルゴリズムはこれを処理します。そのため、比較では自然に正しい分岐が優先されます。 

もう 1 つのケースは、1 つのステーションのみが選択されている場合です。 次に、「リストストップ」形式には区切り文字のない単一の名前が含まれますが、補完リストにはほぼすべてのステーションが含まれます。 減算ベースの計算は、特別なケースを使用せずに、この不均衡を正確に捕捉します。 

最後のケースは非常に長い駅名です。 コストはステーション数だけでなく文字数に依存するため、アルゴリズムは要素をカウントするのではなく、文字列の長さを直接累積することでコストを正確に考慮します。
