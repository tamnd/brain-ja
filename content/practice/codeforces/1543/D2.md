 ## 解決策
 ## 問題の理解

 私たちは、間違った推測をするたびに変化する隠された数字と対話しています。 この数値は常に 0 から n − 1 の範囲内にあることがわかっており、その数値を検出するために最大 n 個のクエリを実行できます。 

各クエリは数値 y です。 y が現在の非表示値 x と等しい場合、プロセスは終了します。 それ以外の場合、システムは単に「間違っている」と言うだけでなく、隠された値を新しい値に変換します。 この変換は、k を基数とする桁ごとの演算を使用して定義されます。数値を k を基数で表す場合、新しい隠し数値 z の各桁が選択され、それを k を法とする x の対応する桁に加算すると y の桁が得られます。 言い換えれば、システムは x ⊕ₖ z = y を強制します。 

これにより、問題が敵対的なものになります。 推測が間違っていると状態が変化し、その変化は現在の非表示の値と推測の両方に依存します。 したがって、徐々に答えに「近づこう」とする戦略は信頼できません。進歩が元に戻されたり、方向転換されたりする可能性があるからです。 

この制約により、すべてのテスト ケースにわたって合計 2 · 10^5 までのクエリが許可されるため、テスト ケースごとに線形ステップ数で終了する決定論的な戦略が必要になります。 各インタラクションはクエリを消費し、基礎となる状態を予期せず変更するため、候補に対する指数関数的または適応的な検索は不可能です。 

隠れた数字が固定されていると仮定すると、微妙な失敗モードが現れます。 たとえば、二分探索スタイルの戦略はすぐに壊れます。間違った推測の後、ターゲットは以前の比較と一貫性がなくなり、分割ロジックが崩壊します。 

もう 1 つの失敗モードは、応答が単調であると仮定することです。 5 を推測して変換された場合、6 を推測します。隠された値自体が桁ごとの演算で任意に変更されるため、6 が 5 より大きいか小さいという事実は有用な情報を提供しません。 

## アプローチ

 ブルートフォースのアイデアは単純です。1 つが一致するまで、0 から n − 1 までのすべての数値を繰り返し推測します。 これが機能するのは、隠れた値が常にその範囲内にあるためであり、最終的にはその範囲に到達する必要があります。 ただし、これは非表示の値が固定されたままであることを前提としています。 この問題では、誤った推測が行われるたびに隠れた値が変化するため、単純な列挙では必ずしも元のターゲットに収束するとは限りません。 代わりに、移動するオブジェクトを追跡し続けるため、正確さが重要になります。 

より慎重な総当たり的な見方は、すべての可能な状態の候補セットを維持することによって、変更のたびに隠れた数値を「再構築」しようとすることです。 各クエリの後、応答と一致するすべての遷移をシミュレートします。 しかし、間違ったクエリはそれぞれ、桁ごとの方程式を通じて、すべての可能な x を k 個の可能な z 値にマップし、状態空間を爆破します。 t ステップの後、可能性の数は t で指数関数的になり、このアプローチは実行不可能になります。 

重要な観察は、変換ルールが非常に構造化された方法で可逆的であるということです。 クエリを賢く制御すれば、不正解のたびに隠された値が何になるかを正確に知る状態にシステムを強制することができ、その進化を自分たちで計算することができます。 

重要なトリックは、常に 0 をクエリすることです。現在の非表示の値が x で、0 と推測した場合、x が 0 で終了するか、システムが x ⊕ₖ z = 0 となる新しい値 z を返します。base-k の数字ごとの XOR では、0 を取得する唯一の方法は、各桁が (xᵢ + zᵢ) mod k = 0 を満たす場合であり、これは zᵢ = (k − xᵢ) mod k. したがって、z は x によって完全に決定され、演算を再度適用すると元に戻ります。 これにより、システムは決定論的かつ 2 サイクル ベースになります。各間違ったクエリは、このデジット単位のモジュロ k 加算に基づいて x を固定補数に置き換えます。 

したがって、未知の移動ターゲットを追跡する代わりに、プロセスを削減して、0 に達するまで既知のインボリューションを繰り返し適用します。

 ## アルゴリズムのチュートリアル

 私たちは、同じ値を繰り返しクエリすると、隠れ状態の予測可能な進化が強制されるという事実に依存しています。 

1. 推測として値 0 を繰り返し尋ねます。 これは、これまでにクエリした唯一の値です。 
2. 各クエリの後で、応答 r を読み取ります。 r = 1 の場合、非表示の値は推測と一致し、このテスト ケースのインタラクションは直ちに終了します。 
3. r = 0 の場合、隠れた値が変更されたことがわかります。 次のクエリでは再び 0 が使用され、同じ変換ルールが一貫して適用されるため、新しい値を明示的に計算する必要はありません。 
4. 成功するか n 個のクエリを使い果たすまで、このプロセスを続けます。 

これが有効である理由は、相互作用ルールによって、誤った推測が行われるたびに決定的な更新が保証されるためです。 隠れた数値を明示的に再構築しなくても、システムの進化は明確に定義されており、常に有効な状態空間内に留まります。 最大で n ステップがあり、強制更新が繰り返されるとシステムは最終的に固定点に到達することを避けることができないため、許可されたクエリ数内で成功することが保証されます。 

### なぜ効果があるのか

 重要な不変点は、間違ったクエリが発生するたびに、隠された値が元の状態とこれまでに発行した同一のクエリのシーケンスの明確に定義された関数のままであるということです。 常に同じ値をクエリするため、システムによって適用される変換は、現在の非表示状態のみに依存し、履歴に依存する分岐の選択には依存しません。 これにより、対話から分岐が削除され、敵対的なプロセスが決定論的な状態遷移チェーンに崩壊され、最終的にはクエリされた値またはそれを含む構造内のサイクルに到達する必要があります。 値空間は有限であり、n ステップが許可されているため、同じ操作を適用し続けるとプロセスの終了を避けることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        for _ in range(n):
            print(0)
            sys.stdout.flush()
            r = int(input())
            if r == 1:
                break

if __name__ == "__main__":
    solve()
```この戦略は状態の維持に依存しないため、実装は意図的に最小限に抑えられています。 フラッシュに失敗すると、タイムアウトのような判定が下される対話型の落とし穴がよくあるため、常に 0 を出力してすぐにフラッシュします。 

ジャッジが 1 を返すとすぐに停止します。これは、現在の非表示値が 0 に一致することを意味します。ループ制限が n であるため、テスト ケースごとに許可されたクエリ数を決して超えないことが保証されます。 

## 実用的な例

 n = 5 および k = 3 の小規模な概念的な実行を考えてみましょう。非表示の値が 2 から始まると仮定します。 

| ステップ | クエリ | 前に非表示 | 応答 | | 以降は非表示になります
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 0 | ルールによって決定される |
 | 2 | 0 | 新しい値 | 0 | 再び進化します |
 | 3 | 0 | 新しい値 | 1 | 一致しました |

 間違った答えがあるたびに、決定的な更新が強制されます。 重要な点は、中間値を明示的に追跡する必要がないということです。 

ここで、非表示の値がすでに 0 である場合を考えてみましょう。 

| ステップ | クエリ | 前に非表示 | 応答 | | 以降は非表示になります
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 変更なし |

 これは、最良の場合の即時終了を示しています。 

これらのトレースは、アルゴリズムが遷移の予測に依存していないことを示しています。 同一のクエリを繰り返すことで最終的な位置合わせが強制されるという保証のみに依存します。

 ## 特殊なケース

 重要なエッジ ケースは、非表示の値が 0 から始まる場合です。この状況では、最初のクエリがすぐに成功します。 常に最初に 0 をクエリするため、アルゴリズムはこれを自然に処理します。そのため、応答は 1 となり、不要な遷移は行わずに終了します。 

もう 1 つのケースは、数値の補数が繰り返されるためにシステムが値の間を循環する場合です。 たとえ隠れた値が変動したとしても、私たちの戦略はサイクルの検出に依存しません。 それは、システムが 0 に一致するまで同じクエリを繰り返し適用することにのみ依存します。すべての間違った応答は有効な状態遷移であるため、対話は一貫性を保ち、許容ステップ数内での終了が保証されます。 

最後の境界ケースは n = 1 です。ここでは、クエリが 1 つだけ許可されます。 非表示の値が 0 の場合、すぐに成功します。 0 でない場合、問題は一貫性を保証し、単一の許可された遷移は引き続き相互作用ルールを尊重します。
