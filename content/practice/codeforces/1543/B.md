 ## 解決策
 ## 問題の理解

 負ではない整数のリストが与えられます。各値は、道路のセグメントに何台の車が停まっているかを表します。 構成全体の「コスト」は、セグメントのすべてのペアを比較し、それらの車両数の絶対差を合計することによって定義されます。 したがって、2 つのセグメントのトラフィックが大きく異なる場合、全体の不便さに大きく影響します。 

私たちは個々の車を利用して、何度でも自由にセグメント間を移動することができます。 これは、元の位置には制約されず、車両全体の総数のみに制約されることを意味します。 タスクは、最終的な構成でペアごとの絶対差の合計が最小になるように、これらの車両をセグメント全体に再配分することです。 

重要な制約は、すべてのテスト ケースの要素の合計数が最大 200,000 であることです。 これにより、繰り返し動きをシミュレートしたり、操作ごとにペアごとのコストを再計算しようとするソリューションは即座に除外されます。$O(n^2)$テストケースごとの計算はすでに遅すぎます。 

すべての値が同一の場合、微妙なエッジケースが発生します。 その場合、不便さはすでにゼロであり、再分配によって推論の間違いによって誤って不便さが増加することはありません。 もう 1 つの重要なエッジ ケースは、配列が大きく偏っている場合 (たとえば、単一の大きな値と多数のゼロ) です。 素朴な直感は、局所的にバランスをとることを示唆するかもしれませんが、目的は、隣接するものではなく、すべてのペアごとの違いに依存します。 

## アプローチ

 ブルート フォース ビューでは、状態の観点から考えることになります。移動ごとに 1 つのユニットが 1 つのインデックスから別のインデックスに転送され、新しい構成が生成されます。 各構成について、ペアごとの絶対差の合計を計算できます。 プレフィックスの合計を使用して評価を最適化したとしても、可能な再配布の数は天文学的に多くなります。$10^9$ユニットは独立して移動できます。 これにより、直接検索が不可能になります。 

構造的な洞察は、操作で許可される内容を書き換えることから得られます。 車を任意に動かすことができるので、唯一不変なのはすべての要素の合計です。 事実上、長さの負でない整数配列を自由に構築できます。$n$同じ合計額で。 問題は次のとおりです。$n$値の合計は$S$最小限に抑える$\sum_{i<j} |b_i - b_j|$。 

目的はスプレッドにペナルティを課します。 均一性からの逸脱はペアごとのギャップを増加させます。 これは、最適な構成は可能な限りバランスがとれている必要があること、つまりすべての値が等しいか、完全性を考慮すると可能な限り近い値である必要があることを示唆しています。 

させて$S = \sum a_i$。 もし$S$で割り切れます$n$、すべての位置を正確に割り当てることができます$S/n$、すべてのペアごとの差がゼロになります。 そうでない場合、一部のポジションは追加のユニットを 1 つ運ぶ必要があります。 したがって、最適な構造は次のとおりです。$r = S \bmod n$要素は$q+1$そして残りの$n-r$は$q$、 どこ$q = S // n$。 

残りのタスクは、そのような構成のコストを計算することです。 貢献は、間に形成されたペアからのみ発生します。$q$そして$q+1$、それぞれが正確に 1 に寄与します。

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 これにより、再配布が許可された後に残る唯一のグローバル制約が決まります。 
2. コンピューティング$q = S // n$そして$r = S \% n$。 これにより、最適なターゲットが可能な限り最大の均一なベースと、配布する必要がある追加ユニットの数に分割されます。 
3. 暗黙的な最適マルチセットを構築します。$n-r$に等しい値$q$そして$r$に等しい値$q+1$。 集計カウントのみが重要であるため、明示的には構築しません。 
4. 不便さへの寄与を計算します。 等しい値間のペアは、その差がゼロであるため、寄与はゼロになります。 間のペアのみを交差させます$q$そして$q+1$貢献すると、そのような各ペアは正確に 1 つを追加します。 
5. クロスペアの数は$r(n-r)$, これが最終的な答えになります。 

これが機能する理由は、この 2 レベルの構造から逸脱すると、さらなる広がりが生じるためです。 3 つの異なる値が表示される場合、中央の値をその近傍に向かって平滑化すると、合計を維持しながらペアごとの絶対差の合計が厳密に減少するため、最適化により、解は最大でも 2 つの連続する整数レベルに収められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        s = sum(a)
        q = s // n
        r = s % n
        
        print(r * (n - r))

if __name__ == "__main__":
    solve()
```実装は、2 値マルチセットへの削減の直後に行われます。 唯一重要な計算は積です$r(n-r)$、2 つのグループ間のすべてのペアをカウントします。 最終的な構造は合計とサイズによって完全に決定されるため、並べ替えや要素ごとのシミュレーションは必要ありません。 

## 実用的な例

 場合を考えてみましょう$n=4$、$a=[0,1,1,0]$。 合計は$2$、 それで$q=0$そして$r=2$。 最適なマルチセットは 2 つの 0 と 2 つの 1 です。 

| ステップ | 合計 | q | r | 構造 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 2 | 0 | 2 | [0,0,1,1] |

 クロスペアは$2 \times 2 = 4$したがって、答えは 4 です。これは、元の配列がローカルですでにバランスがとれているように見えても、グローバルな再配分によって、コストを決定するより明確な 2 レベルの構造が作成されることを示しています。 

ここで考えてみましょう$n=3$、$a=[1,2,3]$。 合計は$6$、 それで$q=2$、$r=0$。 

| ステップ | 合計 | q | r | 構造 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 6 | 2 | 0 | [2,2,2] |

 すべての値が等しいため、クロスペアは存在せず、結果は 0 になります。これは、完全な割り算によりすべての変動が解消されることを確認します。

 ## 特殊なケース

 いつ$n=1$、ペアがまったく存在しないため、再配布に関係なく不都合は常にゼロです。 式$r(n-r)$正しくゼロに評価されるため、$r=0$。
