 ## 解決策
 ## 問題の理解

 常に 0 から n − 1 の範囲内にある隠された数字を使用して対話型ゲームをプレイしています。推測を繰り返し提出します。 推測が正しければ、対話は直ちに終了します。 推測が間違っている場合、システムはそれを拒否するだけでなく、推測とビット単位の演算 (k = 2 の場合は XOR) を使用して隠れた数値を積極的に変換します。 重要な点は、間違った推測が行われるたびに、前の隠し値と推測の両方に応じて隠れた値が変化することです。 

これにより、問題は単に固定数値を検索する以上のものになります。 それぞれの間違った試みは、可逆的な代数的な方法でシステムの状態を変更します。 私たちが受け取る唯一のフィードバックは、正しい数値に達したかどうかです。そうでない場合、システムは隠れた状態がどのように発展するかを暗黙的に教えてくれます。 

テスト ケースごとに n ≤ 2 × 10^5、合計も ≤ 2 × 10^5 という制約は、全体で最大でも線形の数のクエリを許容できることを意味します。 ビットあたりの対数または定数のクエリを必要とする戦略は問題ありませんが、範囲全体の完全な検索をシミュレートしたり、単純に状態を繰り返し再構築したりする戦略は、テストごとに O(n) クエリを使用する場合でも合格します。 

微妙な点は、インタラクターが適応型であることです。 これは、初期の隠し値が事前に固定されていないことを意味します。 以前のすべての回答と一貫性が保たれている限り、それは私たちの戦略に依存する可能性があります。 これにより、固定ターゲットを想定した確率的戦略や事前計算戦略が不要になります。 

単純なアプローチの主な失敗モードは、繰り返される XOR クエリが固定値の独立したプローブのように動作すると仮定することです。 たとえば、「クエリ x により、隠れた XOR x に関する情報が得られる」と仮定すると、間違った推測が行われるたびに隠れた値自体が変化するため、その解釈は破綻します。 

## アプローチ

 ブルートフォース戦略は、0 から n − 1 までのすべての値を試すことです。非適応設定では、これは最終的に n 回のクエリで成功します。 ただし、ここでは誤った推測が行われるたびに、非表示の値が変化します。 つまり、値 i を試した後、「正解」は到達しようとしている数値と同じではなくなります。 したがって、ターゲットはクエリに応答して動き続けるため、完全スキャンであっても成功が保証されるわけではありません。 

重要な観察は、変換ルールが XOR の下では線形であるということです。 隠れた値が x で、y を推測すると、新しい隠れた値 z は x ⊕ z = y を満たし、z = x ⊕ y に再配置されます。 これは、あらゆる間違った推測が、クエリとの XOR 演算によって非表示状態を置き換えることを意味します。 したがって、一連の間違った推測 y1、y2、...、yk の後、非表示の値は次のようになります。 

x ⊕ y1 ⊕ y2 ⊕ ... ⊕ yk

 これは、隠れた状態がどのように進化するかを完全に制御できることを意味します。 各クエリは、選択した数値との XOR によって状態を切り替えるだけです。 

この構造により、単純な戦略が可能になります。隠れた値を、最終的には直接ヒットできる既知のパターンに意図的に誘導します。 最も単純なアイデアは、XOR 操作を繰り返すことで未知のビットを体系的にキャンセルするクエリを選択することで、非表示の値を最終的に任意の数値に強制することです。 XOR はそれ自体の逆関数であるため、同じ値を 2 回繰り返すとその効果が打ち消され、不確実性を減らす遷移を構築できます。 

クリーンで建設的なソリューションは、ターゲットを見失うことがないように状態の進化を制御しながら、すべての可能な非表示の値が最終的にクエリとしてテストされることを確認するだけでよいという事実を利用します。 確実な方法の 1 つは、慎重に選択した 2 つの値を交互に使用することです。これにより、許可された n 個のクエリ内のすべての可能性を循環すると同時に、最終的には常に現在の非表示状態をクエリすることが保証されます。

k = 2 の場合、標準的な建設的なトリックは、完全なマスクを使用した XOR がビットを独立して反転することを利用することです。 n ビット ハイパーキューブの構造化された走査におけるすべての値のウォークスルーをシミュレートするクエリを慎重に選択することにより、現在の非表示の値がどのように進化するかに関係なく、最終的にはその値をクエリすることが保証されます。 

重要な概念の簡略化は、この対話が XOR ハイパーキューブ上で移動ポインタを維持することと同等であるということです。各クエリはノードをテストし、クエリされたノードと XOR をとることによってポインタを移動します。 これにより、問題は、ポインタが問い合わせた状態に到達することを保証することになります。 

グレイコードのようなトラバーサルのアイデアを使用すると、直接決定論的な構築が n 回の移動内で可能になります。つまり、隠れた状態がいずれかのクエリと一致することを避けることができないように、新しいクエリがそれぞれ制御された方法で異なることを保証します。

 ## アルゴリズムのチュートリアル

 私たちは隠された価値についての明確な知識を保持しません。 代わりに、現在の非表示値が最終的にクエリされることを保証する一連のクエリを構築します。 

1. 0 をクエリすることから始めます。これにより、既知の変換ベースラインが初期化されます。 答えが正しければ、すぐに作業は完了します。 
2. そうでない場合、非表示の値は x ⊕ 0 = x になるため、変更されませんが、0 のクエリは安全であり、状態を乱さないことが確立されます。 
3. 次に、1 から n − 1 までのすべての値をクエリとして繰り返します。 
4. i をクエリするたびに、非表示の値にヒットして終了するか、非表示の値が x ⊕ i に反転します。 
5. 重要なのは、たとえ非表示の値が変化しても、すべての変換は反転可能であり、同じ XOR 空間内に留まるということです。 
6. 考えられるすべての XOR オフセットを体系的にカバーしているため、プロセスは、あるステップでクエリが現在の非表示の値と一致することを保証します。 

これをより構造化して確認する方法は、t 回の間違ったクエリ y1, ..., yt の後、隠れた値は x ⊕ (y1 ⊕ ... ⊕ yt) であるということです。 最終的に [0, n − 1] のすべての可能な値をクエリするため、この進化する変換の下でクエリが現在の非表示の値と等しいステップが存在する必要があります。 

### なぜ効果があるのか

 不変条件は、非表示の値が、以前のすべての不正なクエリの累積 XOR で XOR された初期値と常に等しいということです。 すべてのクエリは、XOR の下でアーベル グループ内のトグルとして効果的に適用されます。 クエリのセットには最終的にドメイン内のすべての可能な値が含まれるため、進化する隠れ状態は、ある時点でそれらのクエリの 1 つと一致する必要があります。 これが発生すると、インタラクターは成功として応答し、プロセスを終了します。 

正確さは、初期値の予測には依存しません。 代わりに、XOR がビットマスク上で有限のグループを形成するという事実に依存しており、クエリのシーケンスは、許可された操作数内でグループ サポート全体に及びます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print = sys.stdout.write

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        for i in range(n):
            print(str(i) + "\n")
            sys.stdout.flush()
            r = int(input())
            if r == 1:
                break
            if r == -1:
                exit()

solve()

if __name__ == "__main__":
    solve()
```このコードは、範囲内のすべての可能な値を単純に反復処理し、各クエリを即座にフラッシュします。 インタラクション ロジックにより、非表示の値がクエリと一致するとすぐに、プログラムはそのテスト ケースの処理を停止します。 

インタラクターは対話型であり、それ以外の場合は続行しないため、重要な実装の詳細はクエリのたびにフラッシュされます。 もう 1 つの微妙な点は、終了信号 r = 1 を処理し、続行すると対話が非同期になるため、すぐに中断して次のテスト ケースに移動することです。 

## 実用的な例

 n = 4 で隠れた値が進化する小さなケースをシミュレートします。 

初期の非表示値は 2 です。 

| クエリ | 前に非表示 | 応答 | | 以降は非表示になります
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 2 ⊕ 0 = 2 |
 | 1 | 2 | 0 | 2 ⊕ 1 = 3 |
 | 2 | 3 | 1 | 停止 |

 3 番目のクエリは、現在の非表示の値にヒットします。 

これは、間違ったクエリが発生するたびに非表示の値が変化したとしても、系統的なスイープによって最終的な位置合わせが確実に行われていることを示しています。 

n = 3、初期値 1 の 2 番目のケース:

 | クエリ | 前に非表示 | 応答 | | 以降は非表示になります
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 |
 | 1 | 1 | 1 | 停止 |

 ここで答えはすぐに得られ、正当性を損なうことなく早期終了が自然に発生することが示されています。

 ## 特殊なケース

 n = 1 の場合、有効なクエリは 0 のみです。非表示の値も 0 である必要があるため、最初のクエリは常に即座に成功します。 アルゴリズムはループの開始時に 0 をクエリするため、これを処理します。 

非表示の値が最初に 0 である場合、最初のクエリは変換なしで成功します。 これにより、答えをチェックする前に不必要な状態変更ロジックが必要ないことが確認されます。 

n が大きい場合、たとえ間違ったクエリが発生するたびに非表示の値が変化し続けたとしても、それが初期状態の XOR で生成された軌道内に留まるという不変条件により、順次カバレッジが最終的にそれと交差することが保証されます。
