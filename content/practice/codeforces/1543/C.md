 ## 解決策
 ## 問題の理解

 私たちは、3 つの結果にわたる小さな確率分布を進化させる確率的プロセスを繰り返し実行しています。 常に最大 3 つの「アクティブな」スリップがあり、そのうちの 1 つは最終的な成功状態 (ピンクのスリップ) で、他の 2 つは一時的な状態です。 各レースは現在の分布からの 1 回の抽選に対応し、毎回の抽選後に、どのアイテムが抽選されたか、およびその現在の確率質量に応じて、分布が決定論的な方法で変更されます。 

初めてピンクのスリップが引き出された時点でプロセスは終了します。 タスクは、この終了までの予想される描画数を計算することです。 

システムは 3 つの確率で開始されますが、ルールは、確率の質量がゼロに押し上げられるとアイテムが永久に消える可能性があることを暗示しています。 それが起こると、残りの確率質量が生き残ったアイテム間で再分配されるか、しきい値パラメーター v に応じて比例的に調整されます。これは、システムの状態が固定されていないことを意味しますが、アイテムのどのサブセットがアクティブのままであるか、およびその現在の確率によって完全に決定されます。 

キー入力のサイズは一定です。 初期状態は最大 3 つ、テスト ケースは最大 10 個あるため、どのソリューションでも、消去と再分布によって引き起こされる可能な分布に対して指数関数的手法または状態列挙手法を使用できます。 これにより、漸近的に効率的なグラフ走査や大規模な動的プログラミングの必要性が即座に排除されます。 状態空間が正しく制御されている場合、状態に対するブルートフォースは実行可能です。 

微妙な問題は、確率が小さな整数グリッド上で離散的にではなく、連続的に進化することです。 生の浮動小数点トリプルを使用して状態をメモ化しようとする単純な試みは、精度の不安定性と状態の爆発により失敗します。 もう 1 つのよくある落とし穴は、遷移を描画される確率から独立したものとして扱うことです。 再分配ルールは、単純な線形期待分解を打ち破る方法で、遷移確率と次の状態を結合します。 

主なエッジ ケースは、非終端確率の 1 つが v に対して非常に小さくなり、即座に消去が行われる場合、または消去が繰り返されてシステムが 2 状態または 1 状態のチェーンに縮小される場合に発生します。 これらの状況では、プロセスはすぐに崩壊しますが、単純な再帰シミュレーションでは、ステップをカウントしすぎたり、除去後に確率質量を正しく伝播できなかったりする可能性があります。 

## アプローチ

 直接的な総当たりアプローチは、連続状態にわたるマルコフ連鎖としてプロセスをシミュレートします。 与えられた状態から、アクティブなアイテムのそれぞれを描画することを検討し、ルールに従って確率を更新し、予想される残りのステップ数を再帰的に計算します。 これは概念的に正しいものです。なぜなら、期待値は、遷移確率によって重み付けされたすべての可能な次の状態にわたる反復を満たすからです。 

ただし、難しいのは、引くたびに確率が決定論的ではあるが値に依存して変化することです。 これは、単純に追跡すると、同じ構造状態が無限に多くの数値バリアントを生成する可能性があることを意味します。 実数の可能なすべてのトリプルを個別の状態として処理しようとすると、再帰は状態をマージすることはなく、メモ化された意味で終了することはありません。 

重要な観察点は、システムが非常に小さく、高度に構造化されていることです。 常に、唯一の意味のある状態は、項目のどのサブセットがまだアクティブであるか、およびその現在の確率によって決まります。 確率をゼロに設定することによってのみ消去が行われるため、構造状態の数には制限があります。 さらに重要なのは、どの状態でも、最大 3 つの遷移に対する期待値を考慮するだけでよく、次の状態は単純な算術変換によって一意に決定されることです。

これにより、現在の確率ベクトルに対する再帰関数を定義できます。 値の連続的な性質にもかかわらず、再帰の深さは制限されています。これは、それぞれの削除によってアクティブな項目の数が厳密に減少し、固定されたアクティブなセット内では、直接評価によって解くことができる線形期待方程式を通じて再帰が収束するためです。 

したがって、長いシーケンスをシミュレートする代わりに、関数方程式を使用して期待値を計算します。状態 (c, m, p) から、期待値は 1 に、考えられる各描画を条件とした次の状態の重み付き期待値を加えたものになります。ここで、重みは現在の確率です。 

最適解は、各遷移後に確率が正規化される状態に対するメモ化を使用して、この繰り返しを直接評価します。到達可能な状態は少数しか存在しないため、浮動小数点許容誤差で十分です。

 ## アルゴリズムのチュートリアル

 再帰関数を定義します`solve(c, m, p)`現在の確率分布からピンクのスリップに到達するまでの予想歩数を返します。 

1. ピンクスリップ確率が事実上 1 の場合、プロセスはすでに終了しているため、期待値は 0 になります。 これが再発の基本的なケースです。 
2. それ以外の場合、各ドローには 1 ステップのコストがかかるため、期待値を 1 から開始します。 
3. 確率 c で現金伝票を引き出すことを考えます。 引き分けられた場合は、ルールに従って分布を更新します。 c が v 以下の場合、項目は削除され、その確率質量は残りの項目に均等に再分配されます。 c が v より大きい場合、c から v を減算し、除去された質量を均等に再分配します。 
4. 同じ変換ルールを適用して、確率 m の中央のスリップについても同じことを行います。 
5. ピンクスリップも確率 p で考慮します。 描画されるとプロセスが停止するため、それ以上の期待はありません。 
6. これらの遷移を線形に結合します。期待値は、1 に現金を引き出した後の状態の期待値の c 倍、m を引き出した後の状態の期待値の m 倍、およびゼロの p を加えたものになります。 
7. 状態空間は非常に小さいため、繰り返しの再計算を避けるために浮動小数点値を正規化した後、各トリプル (c、m、p) の計算された期待値をメモ化します。 

正確さは、マルコフ過程の期待値が最初のステップの遷移にわたる線形分解を満たすという事実に依存します。 各状態は次の状態の分布を完全に決定し、最初の描画を拡張することによって、将来のすべての可能な軌道が正確に 1 回キャプチャされます。 状態値が連続的であっても、再帰構造により、消去と再分配ルールによって引き起こされる有限個の個別の構成のみを評価することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

@lru_cache(None)
def solve(c, m, p, v):
    # if pink slip dominates
    if p > 0.999999:
        return 0.0

    res = 1.0

    # cash
    if c > 1e-12:
        if c <= v:
            nc, nm, np = 0.0, m + c / 2, p + c / 2
        else:
            nc, nm, np = c - v, m + v / 2, p + v / 2
        res += c * solve(nc, nm, np, v)

    # middle
    if m > 1e-12:
        if m <= v:
            nc, nm, np = c + m / 2, 0.0, p + m / 2
        else:
            nc, nm, np = c + v / 2, m - v, p + v / 2
        res += m * solve(nc, nm, np, v)

    return res

def main():
    t = int(input())
    for _ in range(t):
        c, m, p, v = map(float, input().split())
        ans = solve(c, m, p, v)
        print(f"{ans:.12f}")

if __name__ == "__main__":
    main()
```このソリューションは、最初のステップの期待値の再帰を直接実装します。 機能`solve`各描画を独立して処理し、問題の再分配ルールに従って確率ベクトルを更新します。 メモ化により、繰り返される状態が再計算されなくなります。 

小さなイプシロンを使用した浮動小数点比較により、確率が事実上ゼロになったときに数値ノイズによって引き起こされる無限再帰が防止されます。 各遷移は明示的に次の状態を構築し、少なくとも 1 つの確率集合が最終状態に向かって削除または再分配に向かうため、再帰的構造によって終了が保証されます。 

## 実用的な例

 最初のサンプル入力をトレースします`(c, m, p, v) = (0.2, 0.2, 0.6, 0.2)`。 

初期状態では、期待値を 1 に各非最終描画からの寄与を加えたものとして計算します。 

| ステップ | 状態 (c,m,p) | アクション | 次の状態 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (0.2,0.2,0.6) | 開始 | 同じ | +1 |
 | 2 | (0.2,0.2,0.6) | Cを描く | (0,0.3,0.7) | 0.2 * E(0,0.3,0.7) |
 | 3 | (0.2,0.2,0.6) | 描く (0.3,0,0.7) | 0.2 * E(0.3,0,0.7) |

 これは、各分岐が 1 つのアクティブなコンポーネントを削除するか、質量を終端状態に向けてシフトすることによって、状態空間を即座に縮小する方法を示しています。 

2 番目の例として、次のように 1 つの確率が v を下回る場合を考えてみましょう。`(0.1, 0.2, 0.7, 0.2)`。 

| ステップ | 状態 | アクション | 次の状態 |
 | --- | --- | --- | --- |
 | 1 | (0.1,0.2,0.7) | Cを描く | c → (0,0.25,0.75) | を削除
 | 2 | (0,0.25,0.75) | 描く 通常どおり更新します |

 これは、小さな確率がどのように早期に消滅し、収束を加速するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    from functools import lru_cache

    def solve_all():
        @lru_cache(None)
        def solve(c, m, p, v):
            if p > 0.999999:
                return 0.0
            res = 1.0
            if c > 1e-12:
                if c <= v:
                    nc, nm, np = 0.0, m + c/2, p + c/2
                else:
                    nc, nm, np = c - v, m + v/2, p + v/2
                res += c * solve(nc, nm, np, v)
            if m > 1e-12:
                if m <= v:
                    nc, nm, np = c + m/2, 0.0, p + m/2
                else:
                    nc, nm, np = c + v/2, m - v, p + v/2
                res += m * solve(nc, nm, np, v)
            return res

        t = int(input())
        out = []
        for _ in range(t):
            c, m, p, v = map(float, input().split())
            solve.cache_clear()
            out.append(f"{solve(c,m,p,v):.12f}")
        return "\n".join(out)

    return solve_all()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、確率が正確にしきい値 v にある場合です。この状況では、アイテムは部分的に削減されるのではなく、完全に削除されます。 アルゴリズムはチェックすることでこれを処理します。`c <= v`そして`m <= v`これにより、ゼロ化と再分配動作が強制されます。 たとえば、`(c,m,p,v) = (0.1,0.2,0.7,0.2)`、図 c はそれを完全に削除し、`(0,0.25,0.75)`。 その後、再帰は 2 つのアクティブな状態にわたってのみ継続され、小さな確率質量が誤って保持されるのを防ぎます。 

もう 1 つのエッジ ケースは、再分配を繰り返すと浮動小数点誤差が蓄積し、確率が 1 への合計からわずかにずれてしまう場合に発生します。実装では、次の各状態を正確な算術式から構築し、ヒューリスティックに再正規化しないことでこれを回避します。 これにより、各遷移が有効な確率分布を表すという不変条件が保持され、実行を通じて期待値の反復が一貫したままであることが保証されます。
