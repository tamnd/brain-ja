 ## 解決策
 ## 問題の理解

 から、非常に大きな整数の間隔が与えられます。$L$に$R$、 どこ$R$と同じ大きさにすることができます$10^{18}$。 タスクは、この範囲内の数字が数字ベースのプロパティを満たす数を数えることです。数字の 10 進表現を見るとき、隣接する数字のすべてのペア間の絶対差は正確に 1 でなければなりません。すべての 1 桁の数字は自動的にこの規則を満たします。 

したがって、6、10、21、3210、または 4567 のような数値は、隣接する各数字のペアが 1 つずつ変化するため有効です。 112 のような数値は、最初の 2 桁が 0 異なるため失敗します。12332 は、2 ～ 3 は問題ありませんが、3 ～ 3 はルールに違反するため失敗します。555 は、隣接するすべての差が 0 であるため、直ちに失敗します。 

入力は単一の間隔であり、出力はその間隔内の有効な整数の数です。 

主な難点は範囲の大きさです。 すべての数値を直接チェック$L$に$R$間隔は次の範囲に及ぶ可能性があるため、不可能です$10^{18}$、これは最大を意味します$10^{18}$最悪の場合の候補者も。 1 つの番号を確認するだけでもコストがかかる$O(\text{digits})$, したがって、総当たりは完全に範囲外です。 

2 番目の微妙な点は、先頭桁の構造です。 この条件は隣接する数字にのみ依存するため、数字は数字グラフ内のパスのように動作し、数値範囲内にある最大 18 桁までの有効な数字列をすべてカウントする必要があります。 

素朴な推論を打ち破るエッジケースには、次のようなものがあります。 

次のような 1 桁の間隔$L=1, R=9$ここで、すべての答えは有効であり、解は計算を複雑にしすぎてはなりません。 

みたいな境界線$L=10, R=10$、ここで、数値は 1 つだけ存在し、それが最小の 2 桁の場合であっても、正しく数えられる必要があります。 

間隔$L$そして$R$長さが違う、など$L=9, R=1000$ここで、数字 DP ソリューションはすべての長さをシームレスに処理する必要があります。 

最大 18 桁までのすべての有効な数値を生成し、範囲でフィルター処理する単純なアプローチでも、潜在的に数百万の状態を生成する必要がありますが、より重要なのは、境界を超えたオーバーフローを避けるために慎重な枝刈りを必要とすることです。これはまさに DP がきれいに処理できるように設計されている桁です。 

## アプローチ

 ブルートフォース戦略では、すべての数値を反復処理します。$[L, R]$、それを文字列に変換し、隣接する数字がちょうど 1 だけ異なっているかどうかを確認します。 この条件は各数値に対してローカルであり、候補ごとに線形スキャンのみを必要とするため、これは論理的に機能します。 番号あたりのコストは、$O(d)$、 どこ$d \leq 18$。 ただし、候補者数は、$R - L + 1$、最悪の場合は$10^{18}$、このアプローチは不可能になります。 

重要な観察は、数値に対して関数を個別に評価しているのではなく、局所的な遷移制約を満たす数字列を数えているということです。 有効な各数値は、数字がシーケンスを形成し、各ステップが ±1 ずつ移動するパスとして見ることができます。 これにより、問題は境界制約の下で有効な数字列を数えるという問題に変わります。これはまさに数字動的計画法の設定です。 

数値を列挙する代わりに、指定された範囲以下の有効な数字シーケンスがいくつあるかを数えます。$X$、次のように答えを計算します。$$\text{count}(R) - \text{count}(L-1)$$計算するには$\text{count}(X)$、前の桁を追跡する状態と、プレフィックスにまだ厳密であるかどうかを示す位置に対して DP を使用します。$X$。 これにより、数値の明示的な生成が回避され、実行可能な桁の遷移のみを通過することが保証されます。

 ## アルゴリズムのチュートリアル

 関数を定義します$f(X)$有効な数値がいくつあるかを数えます$[1, X]$。 最終的な答えは、$f(R) - f(L-1)$。 

1.変換$X$数値配列に変換して、位置ごとに処理できるようにします。 これにより、部分的なプレフィックスを境界と比較できるようになります。 
2. DP 状態を定義する$dp[pos][prev][tight]$、 どこ`pos`現在の数字のインデックス、`prev`は選択された最後の数字であり、`tight`これまでのプレフィックスが次のプレフィックスと等しいかどうかを示します。$X$。 の役割`prev`有効性は隣接する桁の違いに依存するため、これは必須です。 
3. 前の桁を選択せず​​に、DP を位置 0 で初期化します。 特別なセンチネル値 (10 や -1 など) を使用して、まだ数字が配置されていないことを示します。 この段階では、1から最初の1桁までのすべての桁が$X$数値が正確にゼロでない限り、先頭のゼロは有効な数値とみなされないため、許可されます。 
4. 各位置で、次の可能なすべての桁を繰り返します。 まだ数値を開始していない場合は、「まだ空」の継続として 0 を選択できますが、数値が開始されると、先頭のゼロは通常の数字として扱われます。 これにより、10 や 100 などの数値を正しく処理できるようになります。 
5. 候補数字ごとに、隣接規則を適用します。前の数字がすでにある場合、絶対差は正確に 1 でなければなりません。この条件が失敗した場合、遷移はスキップされます。 
6. を更新します。`tight`flag: タイトであり、現在バインドされている桁と等しい桁を選択した場合、タイトなままになります。 そうしないと、緊張感が失われます。 
7. 最後の位置に到達したら、有効な補完をすべて合計します。 少なくとも 1 つの数字が選択されている状態は有効な数値となります。 
8. プレフィックス数に対する包含/除外を使用して最終的な答えを計算します。 

### なぜ効果があるのか

 各位置決定は前の桁制約を介して次の状態を一意に決定するため、すべての有効な数値は桁位置にわたる DP 内の 1 つのパスに正確に対応します。 DP は、そのような各パスを正確に 1 回カウントすることを保証します。`tight`制約により、上限を超えないことが保証されます。 すべての遷移では隣接する差分条件が強制されるため、無効な数値が構築されることはありません。また、考えられるすべての有効な数字シーケンスが探索されるため、見逃されるものはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_upto(x: int) -> int:
    if x <= 0:
        return 0

    digits = list(map(int, str(x)))
    n = len(digits)

    # dp[pos][prev][tight][started]
    # prev: 0-9, or 10 meaning "no previous digit yet"
    dp = [[[[0] * 2 for _ in range(2)] for _ in range(11)] for _ in range(n + 1)]
    dp[0][10][1][0] = 1

    for pos in range(n):
        for prev in range(11):
            for tight in range(2):
                for started in range(2):
                    cur = dp[pos][prev][tight][started]
                    if cur == 0:
                        continue

                    limit = digits[pos] if tight else 9

                    for d in range(limit + 1):
                        ntight = 1 if (tight and d == limit) else 0

                        if not started:
                            if d == 0:
                                dp[pos + 1][10][ntight][0] += cur
                            else:
                                dp[pos + 1][d][ntight][1] += cur
                        else:
                            if abs(d - prev) == 1:
                                dp[pos + 1][d][ntight][1] += cur

    res = 0
    for prev in range(11):
        for tight in range(2):
            res += dp[n][prev][tight][1]
    return res

def solve():
    L, R = map(int, input().split())
    print(count_upto(R) - count_upto(L - 1))

if __name__ == "__main__":
    solve()
```この実装では、カウント ロジックをヘルパー関数に分割し、プレフィックス カウントを計算します。$X$。 DP は、数値の構築が開始されたかどうかを明示的に追跡します。これは、隣接制約を誤って強制することなく先行ゼロを正しく処理するために必要です。 

センチネル値`10`前の数字が存在しないことを表すために使用されます。 これにより、実数と「未設定」状態の混合が回避され、遷移ロジックがクリーンな状態に保たれます。 

減算ステップ`count_upto(R) - count_upto(L - 1)`特別なケースを使用せずに間隔がきれいに処理されるようにします。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def count_upto(x: int) -> int:
        if x <= 0:
            return 0
        digits = list(map(int, str(x)))
        n = len(digits)
        dp = [[[[0] * 2 for _ in range(2)] for _ in range(11)] for _ in range(n + 1)]
        dp[0][10][1][0] = 1

                    for started in range(2):
                        cur = dp[pos][prev][tight][started]
                        if cur == 0:
                            continue
                        limit = digits[pos] if tight else 9

 ## 特殊なケース

 境界ケースは次のような場合です$L = 1$。 この状況では、減算は次のようになります。$L - 1 = 0$、DP は非正入力に対して正しくゼロを返し、アンダーフローや負のカウントが発生しないようにします。 

2 番目のケースは次のような場合です。$X$は一桁です。 DP では、1 ～ 9 の任意の桁で新しい番号を開始できます。前の桁がないため、隣接制約がトリガーされることはありません。 これにより、すべての 1 桁の数値が特別なケースなしでカウントされることが保証されます。 

3 番目のケースは、101 や 210 などの数値に内部ゼロが含まれる場合です。数値が開始されると、ゼロは他の数字と同様に扱われ、前の桁に対する ±1 制約を満たす必要があるため、これらは正しく処理されます。
