 ## 解決策
 ## 問題の理解

 ちょうど 3 つの整数のシーケンスが与えられます。 任意の 2 つの位置間の交換を使用して、これら 3 つの値を再配置することができます。その結果、結果の配置が非常に特殊なパターンを満たすようにする必要があります。つまり、最初の要素は 2 番目の要素よりも厳密に大きくなければならず、2 番目の要素は 3 番目の要素よりも厳密に小さくなければなりません。 言い換えれば、中間要素は厳密な局所最小値でなければなりません。 

シーケンスの長さは 3 に固定されているため、重要なのは 3 つの数値のどの順列になるかだけです。 位置間で任意の数のスワップを行うと、任意の順列が生成されるため、この操作により到達可能性がまったく制限されることはありません。 本当の質問は純粋に組み合わせに関するものです。中央が両端よりも厳密に小さくなるような、3 つの値のマルチセットの順列が存在するかどうかです。 

入力サイズは一定であるため、漸近的な懸念はありません。 考えられるすべての順列を完全に列挙することさえ簡単ではありません。 さらに重要なのは、平等を正しく扱うことです。 いずれかの 2 つの値が等しい場合、特に重複が極端な位置を占めている場合、構造によっては厳密な不平等を達成することが不可能になる場合があります。 

すべての値が等しい場合、微妙なエッジケースが発生します。たとえば、入力`1 1 1`。 すべての順列は同一であり、条件は`a1 > a2 < a3`厳密な不平等はどこでも成立するため、絶対に成立しません。 もう 1 つのケースは、2 つの値が等しく、3 番目の値の方が大きい場合です。`1 1 2`。 置けるのに`2`どこかで、等しいペアが中間での厳密な最小値の形成を妨げます。 例えば、`2 1 1`中央が両端よりも厳密に小さいわけではなく、置換によって厳密性が破られる形で等しい値の 1 つが隣接したままになるため、この関数は失敗します。 

単純な間違いは、並べ替えや最小値の選択が常に機能すると仮定することです。 たとえば、最小値を中央として取り、他の値を任意に配置すると、最小値が重複すると失敗します。これは、両側で厳密な不等式が必要であるためです。 

## アプローチ

 要素が 3 つだけの場合、総当たり戦略は、入力配列の 6 つの順列をすべて列挙し、中央の要素が両方の隣接要素よりも厳密に小さいという条件を満たす順列があるかどうかをチェックすることです。 そのような順列が見つかった場合は、すぐに出力します。 それ以外の場合は不可能であると判断します。 

これが機能するのは、検索スペースが完全でサイズが一定であるためです。 これら 6 つの配置を超えて、可能性の数を減らしたり拡張したりする隠れた構造はありません。 

ただし、条件は 3 つの値間の順序関係のみに依存するため、順列を列挙する必要はありません。 重要な点は、中央の要素が 3 つの要素のうちの一意の最小値でなければならないということです。 最小値が複数回出現する場合、隣接値の 1 つが等しく、厳密な不等号に違反するため、その値を他の両方の値より厳密に同時に下に置く方法はありません。 最小値が一意である場合は、常にその最小値を中央に配置し、残りの 2 つの値をいずれかの順序で配置できます。 

これにより、問題は順列検索から単純な頻度と比較チェックに減ります。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取り、リストに保存します。 スワップでは任意の並べ替えが可能であるため、この段階では順序については何も想定されていません。 
2. 3 つの数値の最小値を計算します。 中央は両端よりも厳密に小さくなければならないため、この値が中間位置の唯一の可能な候補です。 
3. この最小値がリストに何回出現するかを数えます。 この数によって実現可能性が決まります。 最小値が複数回出現する場合、その最小値を配置すると、少なくとも 1 つの等しい値がそれに隣接して配置され、厳密な不等式に違反します。 
4. 最小値が少なくとも 2 回出現する場合は、出力します。`-1`。 これは、最小要素の重複を持つマルチセットで厳密な局所最小値を作成することが不可能であることに直接対応します。 
5. それ以外の場合、最小値は一意になります。 真ん中の位置に置きます。 
6. 残りの 2 つの値を 1 番目と 3 番目の位置に任意の順序で配置します。 どちらも厳密に最小値より大きいため、相対的な順序に関係なく、両方の不等式条件が満たされます。 
7. 構築された順列を出力します。 

### なぜ効果があるのか

 条件`a1 > a2 < a3`力`a2`厳密に両方よりも小さいこと`a1`そして`a3`。 つまり、`a2`3 つの値のうちの一意の最小値でなければなりません。 最小値が一意でない場合、厳密な不等式を維持しながら、再配置によって両側に等しい最小値を分離することはできません。 逆に、最小値が一意の場合、それを中央に配置すると、残りの値が両方とも厳密に大きくなることが保証されるため、両側でそれらを順序付けしても正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = list(map(int, input().split()))

mn = min(a)
cnt = a.count(mn)

if cnt >= 2:
    print(-1)
else:
    a.remove(mn)
    # remaining two elements can be in any order
    print(a[0], mn, a[1])
```この解決策は、リストの削除によって最小値が 1 つだけ削除されるという事実に基づいています。これは、すでに一意であることが確認されているため安全です。 削除後、ちょうど 2 つの要素が残り、それらの間に最小値を配置します。 

ここでよくある落とし穴は、次のことを忘れることです`remove`最初に出現したもののみを削除します。 一意性を検証した後でのみ問題ありません。 このチェックを行わないと、重複がある場合に削除すると間違ったインスタンスが暗黙的に削除され、間違った配置が生成される可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    a = list(map(int, input().split()))
    mn = min(a)
    cnt = a.count(mn)
    if cnt >= 2:
        return "-1"
    a.remove(mn)
    return f"{a[0]} {mn} {a[1]}"

# provided samples
assert run("3 1 6") == "3 1 6"
assert run("1 2 3") in ["2 1 3", "3 1 2", "2 1 3"]  # any valid answer is fine
assert run("1 1 1") == "-1"

# custom cases
assert run("2 1 2") == "-1"
assert run("10 9 8") == "10 8 9"
assert run("5 1 7") == "5 1 7"
assert run("1 3 2") in ["2 1 3", "3 1 2"]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 1 6 | 3 1 6 | 基本的な有効な構造 |
 | 1 1 1 | -1 | 全てが等しいという不可能性 |
 | 2 1 2 | -1 | 重複最小エッジケース |

 ## 特殊なケース

 最も重要なエッジケースは、最小値が複数回発生する場合です。 入力用`2 1 2`、最小値は`1`そしてそれはユニークであるため、構築は成功し、成果が得られます`2 1 2`条件を満たすもの。 ただし、`1 1 2`、最小値は`1`しかし、これは 2 回出現し、少なくとも一方の辺がそれに等しくなり、厳密な不平等が破られるため、これを中央に配置しようとする試みは失敗します。 アルゴリズムは、出力を作成する前に最小値の周波数をチェックすることでこれを処理します。 

もう 1 つのエッジ ケースは、入力が厳密に減少している場合です。`10 5 1`。 最小値は一意であるため、`1`真ん中と出力`10 1 5`または`5 1 10`。 厳密な不等式は、外部要素間の相対的な順序ではなく、大きいことのみに依存するため、どちらも条件を満たします。
