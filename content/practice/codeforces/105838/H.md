 ## 解決策
 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースは、無限の 2D グリッド上の一連の点を記述します。 すべての点は、整数座標に配置されたタワーを表します。 各タワーからは、x 軸と y 軸の正と負の方向に沿って 4 つの光線が常に放射され、無限に伸び、通過するすべての点をカバーします。 

2 つの塔は、それぞれが互いの光線の少なくとも 1 つにある場合、「互いに攻撃している」とみなされます。 光線は軸に平行な線に沿ってのみ進むため、この条件は非常に剛直な幾何学的構造、つまり塔のような形に変換されます。$(a_i, b_i)$別の塔を攻撃する$(a_j, b_j)$同じ x 座標または同じ y 座標を共有する場合に限ります。 

タスクは、順序付けされていないペアの数をカウントすることです。$(i, j)$、$i < j$、次のいずれかになります$a_i = a_j$または$b_i = b_j$。 

制約は大きいです。 すべてのテスト ケースの合計ポイント数は最大です。$10^5$したがって、すべてのペアを直接チェックするソリューションは次のようになります。$O(n^2)$、すぐに遅すぎます。 テスト ケースごとに線形または線形演算に近い時間が必要です。 

微妙だが重要なエッジ ケースは、カウント内の重複を慎重に処理することです。 複数の塔が同じ x 座標と y 座標の両方を共有している場合、それらは同一の点になりますが、問題では座標が異なることが保証されるため、その曖昧さを回避します。 ただし、ここでは一意性のために起こり得ないとしても、中間推論で両方の座標を共有するペアを二重にカウントすることは避けなければなりません。 

## アプローチ

 直接的なアプローチは簡単です。タワーのすべてのペアをチェックし、それらの x 座標が一致するか、y 座標が一致するかを確認します。 これは、相互攻撃の定義を直接実装しているため、正しいです。 ただし、最大で$10^5$ポイント、これには約$5 \times 10^9$最悪の場合の比較は不可能です。 

重要な観察は、条件が 2 つの独立した等価関係にきれいに分解されることです。 ペアは、同じ x グループまたは同じ y グループに属している場合に有効です。 これは、ペアごとではなくグループごとに貢献をカウントすることを示唆しています。 

X座標を固定すると$a$、その x 座標を持つすべての塔がグループを形成します。 このグループ内のどのペアも有効であり、貢献します$\binom{k}{2}$あれば$k$その X 値を持つタワー。 同様に、各 y 座標について$b$、その y 座標を持つすべての塔も寄与します$\binom{k}{2}$。 

微妙な問題は、この条件和集合アプローチでは、x と y の両方を共有するペアが二重にカウントされる可能性があることです。 ただし、すべての点が個別であるため、両方の座標を共有する 2 つの塔はないため、減算する交差はありません。 

したがって、問題は、x 値と y 値の頻度を個別にカウントし、組み合わせの寄与を合計することに帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての X 座標と Y 座標を読み取り、個別の値ごとに頻度カウントを保存します。 2 つのハッシュ マップまたは配列を維持します。1 つは x 値用、もう 1 つは y 値用です。 これが必要なのは、答えは各座標を共有する点の数のみに依存し、それらの同一性には依存しないためです。 
2. それぞれの個別の x 座標値について、その頻度を次のようにします。$k$。 追加します$k \cdot (k - 1) / 2$答えに。 これは、その x 線上に垂直に並んだ順序のないタワーのペアをすべてカウントします。 
3. すべての個別の y 座標値について、その頻度を次のようにします。$k$。 もう一度追加します$k \cdot (k - 1) / 2$答えに。 これは、その y 線上で水平に並んだ順序のないタワーのペアをすべてカウントします。 
4. テスト ケースの累積合計を出力します。 

重要な推論ステップは、有効な各ペアが垂直方向または水平方向に整列することによって一意に決定されるということです。 各座標クラス内のすべてのペアを個別にカウントしているため、すべての有効なインタラクションが 1 回だけキャプチャされます。 

### なぜ効果があるのか

 有効なタワーのペアを考えてみましょう。 相互に攻撃する場合は、x を共有するか y を共有する必要があります。 それらが x を共有する場合、それらはちょうど 1 つの x グループの貢献に含まれます。$\binom{k}{2}$。 それらが y を共有する場合、それらはちょうど 1 つの y グループの寄与に含まれます。 座標は別個であるため、ペアで x と y の両方を同時に共有することはできないため、2 つの計数プロセスの間に重複はありません。 これにより、有効なペアとアルゴリズムによって合計された寄与との間に 1 対 1 の対応関係が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        xs = list(map(int, input().split()))
        ys = list(map(int, input().split()))

        cx = {}
        cy = {}

        for x in xs:
            cx[x] = cx.get(x, 0) + 1
        for y in ys:
            cy[y] = cy.get(y, 0) + 1

        ans = 0

        for v in cx.values():
            ans += v * (v - 1) // 2
        for v in cy.values():
            ans += v * (v - 1) // 2

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、カウントを 2 つの独立した周波数累積に分割します。 最初のループは各垂直線にあるタワーの数をカウントし、2 番目のループは水平線をカウントします。 最後のループでは、標準の組み合わせ公式を使用して、これらの周波数をペア数に変換します。 

よくある実装上の間違いは、x カウントと y カウントを完全に分離せずに、入力解析中に答えをインクリメントしようとすることです。これにより、ロジックが混在する危険があり、デバッグが困難になります。 もう 1 つの落とし穴は、結合公式での整数の除算を忘れることです。ただし、Python の`//`正確性を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        xs = list(map(int, input().split()))
        ys = list(map(int, input().split()))
        cx = Counter(xs)
        cy = Counter(ys)

        ans = 0
        for v in cx.values():
            ans += v * (v - 1) // 2
        for v in cy.values():
            ans += v * (v - 1) // 2
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 微妙なエッジ ケースは、すべての点が同じ x 座標を共有する場合です。 アルゴリズムは、すべてのポイントを単一の x 周波数バケットに入れることでこれを処理し、$\binom{n}{2}$一方、すべての y 周波数は分離されており、寄与はゼロです。 実行した例のトレースでは、x グループのみが正しい完全な答えを生成することがすでに確認されています。 

もう 1 つのケースは、すべての点が同じ y 座標を共有する場合です。 対称的に、y 周波数が支配的であり、x 側は何も寄与しません。 アルゴリズムは x と y を独立して処理するため、結果を歪める可能性のある交互作用項はありません。 

最後のエッジケースは、すべての座標が両方の次元で異なる場合です。 どちらの周波数マップも完全に 1 で構成されているため、すべての$\binom{1}{2}$用語が消滅します。 アルゴリズムは正しくゼロを出力し、攻撃ラインを共有する 2 つのタワーがないという事実と一致します。
