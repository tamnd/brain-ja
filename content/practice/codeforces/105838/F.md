 ## 解決策
 ## 問題の理解

 すべてのペアのグリッドに取り組んでいます$(i, j)$どこ$1 \le i \le n$そして$1 \le j \le m$。 各ペアについて、次の最大公約数を調べます。$i$そして$j$。 その gcd 値から$g$、の約数の数を計算します。$g$、と書かれています$d(g)$。 この関数は、次の場合にのみこの値を提供します。$d(g)$指定されたしきい値を超えない$v$; それ以外の場合は寄与はゼロになります。 

クエリの最終出力は合計ではなく、全体の積になります。$n \cdot m$ペア。 つまり、グリッド内のどこかに 1 つのゼロがあると、答え全体がすぐにゼロになりますが、それ以外の場合は、すべてのペアにわたる gcd の除数カウント値を掛け合わせます。 

この制約は、クエリごとの二次推論を禁止するほど厳しいものです。 と$n, m, v \le 2 \cdot 10^5$そして最大$2 \cdot 10^3$クエリでは、クエリごとにすべてのペアを暗黙的に反復することさえ不可能です。 クエリごとの Linear-in-grid-size ですら大きすぎるため、gcd 繰り返しの構造を大幅に活用する必要があります。 

微妙な失敗例は、「インジケーターをゼロにする」メカニズムからすぐに現れます。 任意のペアが存在すると仮定します。$(i, j)$そのような$d(\gcd(i, j)) > v$。 そうすれば、たとえ 1 つのペアだけが原因であっても、積はゼロになります。 

たとえば、次の場合$n = m = 6$そして$v = 2$、 それから$\gcd(4,4)=4$そして$d(4)=3>2$したがって、答え全体がゼロになる必要があります。 値を乗算するだけで初期ゼロの伝播を無視する単純な実装では、すべてを計算するのに時間がかかり、正しい答えがすでに決定されているという事実を見逃してしまう可能性があります。 

2 番目の明白ではない問題は、ゼロが現れない場合、問題は gcd グリッド上のグローバル乗算関数となり、構造がなければセルごとに独立して分解できないことです。 

## アプローチ

 ブルートフォースアプローチはすべてのペアを直接評価します$(i, j)$、計算します$\gcd(i,j)$、除数の数を評価し、しきい値をチェックし、結果をアキュムレータに乗算します。 これは簡単で正しいですが、パフォーマンスは良好です。$n \cdot m$クエリごとの gcd 計算には対数時間がかかり、次の時点ではまったく実行不可能になります。$2 \cdot 10^5$規模。 

重要な観察は、値は次のもののみに依存するということです。$\gcd(i,j)$、オンではありません$i$そして$j$彼ら自身。 これにより、gcd 値によってペアをグループ化できます。 グループ化したら、ペアを反復処理する代わりに、各 gcd を生成するペアの数を数えます。$g$、そして上げます$d(g)$製品のその周波数に合わせて。 

残りの課題は、プレフィックス グリッド内に gcd を持つペアが正確にいくつあるかを数えることです。$g$。 これは標準的な数論的変換問題です。まず、gcd が次で割り切れるペアを数えます。$g$、メビウス反転を使用して修正します。 ただし、これをクエリごとに単純に実行すると、まだ時間がかかりすぎます。 

2 番目の構造の単純化は、合計の順序を反転することから得られます。gcd を固定してペアをカウントする代わりに、サイズ パラメーターを固定します。$t$そしてそれに寄与する倍数の数を見てください。 これにより、計算が、大まかに評価できる除数伝播システムに変わります。$O(n \log n)$-type は、事前に計算されたメビウス値と除数の反復を使用してクエリごとに動作しますが、実際には、除数に対して慎重に実装された調和ループに依存しています。

 ## アルゴリズムのチュートリアル

 ### 1. 算術関数を事前計算する

 除数カウント関数を事前計算します$d(x)$までのすべての値について$2 \cdot 10^5$。 メビウス値も事前計算します$\mu(x)$これは、gcd 制限ペアをカウントする際の包含と除外に必要であるためです。 

このステップはクエリとは独立しており、基本的な数理論量の再計算を回避します。 

### 2. ゼロ回答に対する早期の不可能性チェック

 クエリごとに$(n, m, v)$, まず、グリッド内の gcd 値がしきい値に違反する可能性があるかどうかを確認します。 危険な価値観はすべて$g \le \min(n,m)$なぜなら、そのような数値はすべて、何らかのペアの gcd として現れるからです。 

存在するかどうかを確認します$g \le \min(n,m)$そのような$d(g) > v$。 そのような値が存在する場合は、すぐにゼロを返すことができます。 

これが機能する理由は、どんな場合でも$g \le \min(n,m)$、少なくとも 1 つのペアを構築できます$(g, g)$したがって、すべての候補 gcd はグリッド内のどこかで実際に実現されます。 

### 3. gcd 分解に関する作業

 禁止された gcd が存在しない場合、すべてのペアが貢献します$d(\gcd(i,j))$。 gcd に従ってペアをグループ化して積を書き直します。 

私たちが欲しいのは$$\prod_{i=1}^n \prod_{j=1}^m d(\gcd(i,j)).$$させて$C(g)$gcd とのペアの正確な数になります$g$。 すると答えはこうなります$$\prod_{g=1}^{\min(n,m)} d(g)^{C(g)}.$$したがって、問題はすべてを計算することに帰着します$C(g)$。 

### 4. メビウス反転による gcd-exact カウントの計算

 まず、gcd が次で割り切れるペアの数を定義します。$g$、つまり:$$F(g) = \left\lfloor \frac{n}{g} \right\rfloor \cdot \left\lfloor \frac{m}{g} \right\rfloor.$$正確な gcd カウントは次のようになります。$$C(g) = \sum_{k \ge 1} \mu(k) \cdot F(gk).$$この式は、「g で割り切れる gcd」から「g にぴったりの gcd」への標準逆変換を表します。 

### 5. インデックスの約数による計算を再構成する

 直接コンピューティング$C(g)$あらゆる人にとって$g$クエリごとの速度が遅すぎます。 代わりに、合計を逆にします。 

以下を定義します。$$F(t) = \left\lfloor \frac{n}{t} \right\rfloor \cdot \left\lfloor \frac{m}{t} \right\rfloor.$$それぞれ$F(t)$すべての約数に寄与する$g \mid t$、重み付き$\mu(t/g)$。 

そこで、それぞれからの寄付を分配します$t$そのすべての約数に。 これにより、計算がすべての反復処理に変わります。$t$から$1$に$\min(n,m)$、それぞれについて$t$、約数を反復処理します。 

### 6. 指数マップを作成し、積を完成させる

 配列を維持します`cnt[g]`の指数を格納する$d(g)$最終製品では。 貢献ごとに、以下を追加します。$$cnt[g] += \mu(t/g) \cdot F(t).$$最後に、答えは次のとおりです。$$\prod_g d(g)^{cnt[g]} \bmod (10^9+7).$$### なぜ効果があるのか

 正しさは 2 層のアイデンティティから生まれます。 まず、すべてのペアはその gcd によって一意に分類されるため、gcd によってグループ化すると積が正確に保存されます。 第 2 に、メビウス反転により、割り切れる gcd カウントから正確な gcd カウントに変換するときに、各ペアが 1 回だけカウントされることが保証されます。 除数の再分配ステップは、合計の順序を変更するだけであるため、すべての寄与が重複または省略されることなく保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 200000

# precompute divisor count
d = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    for j in range(i, MAXN + 1, i):
        d[j] += 1

# mobius
mu = [1] * (MAXN + 1)
is_prime = [True] * (MAXN + 1)
primes = []
for i in range(2, MAXN + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i, MAXN + 1, i):
            is_prime[j] = False

# recompute mu properly (linear style simplified)
mu = [1] * (MAXN + 1)
vis = [0] * (MAXN + 1)
mu[0] = 0
for i in range(2, MAXN + 1):
    if vis[i] == 0:
        for j in range(i, MAXN + 1, i):
            vis[j] += 1
        for j in range(i * i, MAXN + 1, i * i):
            mu[j] = 0
for i in range(2, MAXN + 1):
    if mu[i] != 0:
        mu[i] = -1 if vis[i] % 2 else 1

def solve():
    q = int(input())
    for _ in range(q):
        n, m, v = map(int, input().split())
        lim = min(n, m)

        # early zero check
        ok = True
        for i in range(1, lim + 1):
            if d[i] > v:
                ok = False
                break
        if not ok:
            print(0)
            continue

        cnt = [0] * (lim + 1)

        # compute contributions
        for t in range(1, lim + 1):
            a = (n // t) * (m // t)
            if a == 0:
                break
            if mu[t] == 0:
                continue
            for g in range(1, t + 1):
                if t % g == 0:
                    cnt[g] += mu[t // g] * a

        ans = 1
        for g in range(1, lim + 1):
            if cnt[g]:
                ans = ans * pow(d[g], cnt[g], MOD) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず除数のカウントとメビウスの値をグローバルに構築します。 各クエリは、禁止された gcd が存在するかどうかを検出する高速な実行可能性チェックから始まります。 そうでない場合は、すべての乗算器からの除数伝播を使用して、考えられる各 gcd の指数寄与を構築します。$t$。 最後に、モジュラー演算で除数のカウントをべき乗します。 

実装の微妙な詳細は、メビウス値により寄与が負になる可能性があるため、指数配列は途中でモジュール化せずに署名する必要があることです。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$v$非常に小さいです、例えば$v=1$。 その状況では、1 に等しい gcd 値のみが許可されます。$d(g)=1$のためだけに$g=1$。 アルゴリズムは、すべての$g>1$は禁止されていますが、すべてのグリッドには gcd が 1 より大きいペアが多数含まれているため、初期のチェックでは正しくゼロの結果がトリガーされます。 

別のエッジケースが発生するのは次の場合です。$n=m=1$。 ちょうど 1 ペアあります$(1,1)$、そして答えは次のようになります。$d(1)=1$。 除数の累積はまだ機能します。$t=1$が寄与しており、この場合メビウス反転は自明です。 

最後の微妙なケースは次のような場合です。$n$そして$m$大きいが非常にアンバランスである、など$n=200000, m=1$。 この場合、gcd は常に 1 なので、答えは次のようになります。$1^{nm}=1$。 アルゴリズムはこれを効率的に処理します。$t=1$ゼロ以外のフロア積があるため、より大きなループでは即座に崩壊が発生します。$t$価値観。
