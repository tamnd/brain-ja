 ## 解決策
 ## 問題の理解

 ノード 1 がルートであるルート付きツリーが与えられます。 各ノードはスキルを表し、各スキルにはパワーと呼ばれる値があります。 スキルのアクティブ化は、その親がすでにアクティブ化されている場合にのみ許可されるため、アクティブ化されたノードの選択されたセットは、常にルートを含み、親関係の下で閉じられた接続構造を形成します。 

ノードをアクティブ化すると、ルートからそのノードまでのパスに沿った値のみから計算されたスコアが得られます。 そのパス上のすべての値を取得して並べ替え、特定の順序統計を選択します。位置 Floor(x / 2) + 1 の要素 (x はパス上のノードの数)。 これは、ノードの寄与がそのルート パス上の値のマルチセットにのみ依存し、より多くの祖先が含まれるにつれて非線形的に増加することを意味します。 

合計で最大 m 個のノードをアクティブ化できますが、アクティブ化されたノードからの寄与の合計が最大になる有効なアクティブ化順序を選択する必要があります。 

主な問題は、1 つのノードをアクティブ化すると、そのルート パス内のすべてのノードの寄与が変化することです。これは、より深いノードほど、ソートされたプレフィックス マルチセットに含まれる値が増えるためです。 したがって、これは単純なノードごとの、または独立した選択の問題ではありません。 

n が 2 × 10^4 まで、m が 2 × 10^3 までという制約は、O(nm) または O(n m log n) スタイルの動的プログラミングは妥当であるが、状態ごとに完全なパス構造を再計算するものは遅すぎることを示しています。 ルートからノードへのパスを個別に繰り返しソートするソリューションは、最悪の場合、ノード間の合計パス長が 2 次になる可能性があるため、直ちに実行不可能になります。 

微妙な落とし穴は、各ノードが選択されたセットとは独立して固定の寄与を持つと仮定していることです。 これは失敗します。中間ノードをスキップしたり、別のブランチを選択した場合、パス上のマルチセットは影響を受けませんが、どのノードをアクティブにするかの選択により、アクティブな構造内にどのパスが存在するかさえも制約されるためです。 

別の障害モードは、各ノードの寄与を個別に計算し、最適な m 個のノードをグローバルに選択しようとすることです。 これは親の制約を無視し、共有プレフィックスを介して寄与が重複することも無視します。 

## アプローチ

 直接総当り戦略では、サイズが最大 m の有効なアクティベーション セットをすべてシミュレートしようとします。 各候補サブセットについて、それが親制約の下で閉じているかどうかを確認し、ルートまで歩いて各パスをソートすることによって、選択したすべてのノードの寄与を計算します。 検証を最適化したとしても、サイズ m のサブセットを列挙するにはすでにコストがかかります$\binom{n}{m}$これは、n が 20000 の場合、実行可能な限界をはるかに超えています。 

もう少し素朴なアイデアは、ツリー上での動的プログラミングです。この場合、ノードごとに、サブツリー内で選択したノードの数に対する DP を維持し、ルート パスに沿った値の分布を追跡しようとします。 問題は、ノードの寄与がサブツリーだけでなくルート パス全体のソートされたマルチセットに依存するため、サブツリーの DP 状態が独立していないことです。 

重要な観察は、寄与関数がルート パスに沿った値の複数セットにのみ依存し、子を追加してパスを拡張する場合、ソートされた構造に新しい値が 1 つだけ挿入されることです。 これは、ルートから現在のパスへのトラバーサルに沿ってグローバル構造を維持し、各ノードをその構造の「スナップショット」を取得する機会として扱うことを示唆しています。 

現在のルートからノードへのパス上の値のマルチセットを表すデータ構造を維持しながら、ルートから DFS を実行できます。 ノードに入ると、その値がこの構造に挿入されます。 この時点で、注文統計を維持していれば、その寄与を対数時間で計算できます。 次に、このノードを m 個の選択したアクティベーションの 1 つとして採用するかどうかを決定します。 ノードを離れると、その値は削除されます。 

ここで残る問題は、合計選択数が m に制限されているため、すべてのノードを貪欲に取得できないことです。 これは古典的な「DFS 中に最適なノードを m 個選択する」問題になり、各ノードのパスのコンテキストで値が定義されます。 

すべての候補者の貢献をグローバルプールに維持し、上位 m を選択します。 DFS は、各ノードの寄与が正確なパス マルチセットに基づいて計算されることを保証します。 

正しさは、ノードの寄与がそのパスのみに依存し、将来の選択には依存しないという事実に左右されるため、現在のパスが固定されれば独立して評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | 指数関数 | O(n) | 遅すぎる |
 | 順序統計 + 上位 m 選択を使用した DFS | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、DFS を使用してそれを走査します。 走査中に、挿入、削除、および k 番目に小さい要素のクエリをサポートする動的に順序付けられた構造が維持されます。 この構造は常に、現在のルートからノードへのパス上の値の複数セットを正確に表します。 

各ノードで、その値を構造に挿入した後、そのノードの寄与を計算します。 パス長 x は構造のサイズとして暗黙的にわかります。 k を Floor(x / 2) + 1 として計算し、k 番目に小さい値をクエリします。 その値がこのノードの貢献度です。 

この投稿を候補者のリストに保存します。 将来のノードがより大きな貢献をもたらす可能性があり、ピックの予算が m 個しかないため、ノードを採用するかどうかをすぐには決定しません。 

DFS を子に継続し、構造が常に現在のパスと一致するようにします。 すべての子を終了した後、戻る前にノードの値を削除します。 

DFS が完了すると、ノードごとに 1 つずつ、n 個の候補値が得られます。 有効なアクティベーション セットは、それぞれが明確に定義された寄与を持つノードで構成されている必要があり、ノードをアクティブにしてもそれ自体の計算値は変更されないため、問題は、これらの寄与の最大合計を持つ最大 m 個のノードを選択することになります。 

すべての候補の貢献を降順に並べ替え、最初の m を取得します。 

これが機能する理由は、各ノードの寄与がルート パス上の値のマルチセットによって完全に決定され、他の選択されたノードに関係なく一意に定義されるためです。 DFS は、各ノードが正しいコンテキストで評価されることを保証します。また、独立性は、ノードを選択しても他のノードのパス マルチセットが変更されないという事実から生まれます。

import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
val = [0] + list(map(int, input().split()))

g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

# coordinate compress values for BIT
coords = sorted(set(val[1:]))

idx = {v: i + 1 for i, v in enumerate(coords)}
N = len(coords)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def kth(self, k):
        res = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = res + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                res = nxt
            bitmask >>= 1
        return res + 1

bit = BIT(N)
ans = []

```DFS は、現在のルート パスに沿ってノード値を挿入および削除できるように、圧縮された値に関するフェンウィック ツリーを維持します。 Fenwick ツリーは頻度クエリのみをサポートしているため、現在のパスのサイズは dfs.sz で明示的に追跡されます。 各ノードについて、k = Floor(x/2) + 1 を計算し、フェンウィック ツリーに対する標準的なバイナリ リフティングを使用して k 番目の最小値をクエリします。 

すべてのノードの貢献を収集した後、サイズ m までのノードのサブセットを自由に選択できるため、それらを並べ替えて最適な m を取得します。 

微妙な点は、DFS 中に寄与度が計算されても、最終的にどのノードを選択するかには依存しないことです。 これらは、固定されたパス構造のみに依存します。

このトレースは、ルート パス構造が中央値のような統計を支配するため、異なるブランチが同じ寄与を生成できることを示しています。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    val = [0] + list(map(int, input().split()))
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    coords = sorted(set(val[1:]))
    idx = {v:i+1 for i,v in enumerate(coords)}
    N = len(coords)

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0]*(n+1)

        def add(self,i,v):
            while i<=self.n:
                self.bit[i]+=v
                i+=i&-i

        def kth(self,k):
            res=0
            bitmask=1<<(self.n.bit_length())
            while bitmask:
                nxt=res+bitmask
                if nxt<=self.n and self.bit[nxt]<k:
                    k-=self.bit[nxt]
                    res=nxt
                bitmask>>=1
            return res+1

    bit = BIT(N)
    ans = []
    sys.setrecursionlimit(10**7)
    dfs_sz = 0

    def dfs(u,p):
        nonlocal dfs_sz
        bit.add(idx[val[u]],1)
        dfs_sz+=1
        k=dfs_sz//2+1
        ans.append(coords[bit.kth(k)-1])
        for v in g[u]:
            if v==p: continue
            dfs(v,u)
        bit.add(idx[val[u]],-1)
        dfs_sz-=1

    dfs(1,-1)
    ans.sort(reverse=True)
    return str(sum(ans[:m]))

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのノードが 1 つのチェーン上にある、完全に歪んだツリーです。 その状況では、ノード i のパスには以前のすべての値が含まれるため、寄与は決定論的に変化します。 フェンウィック ツリー パスは常に完全なプレフィックス マルチセットを反映し、k 番目のクエリは必要な中央値のような定義に直接一致するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、ルート 1 の星型ツリーで、他のすべてのノードはルートの子です。 各子にはサイズ 2 のパスがあるため、すべてのリーフに対して k = 2 となり、寄与は {v1, vi} の最大値のみに依存します。 各サブツリーの挿入と削除によって構造が正確に復元されるため、DFS は正しいパス状態を使用して各リーフを独立して計算します。 

最後のエッジケースは、すべての値が等しい場合です。 すべての k 次統計は深さに関係なく同じ値を返すため、すべての寄与は同一になります。 このアルゴリズムは依然として、n 個の同一の値を正確に収集し、それらの任意の m 個を選択し、予想される最大合計と一致します。
