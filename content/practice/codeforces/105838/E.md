 ## 解決策
 ## 問題の理解

 私たちには順序が与えられています$b$その長さは$n$。 このシーケンスは元々未知の整数配列から生成されました$a$ただし、そのプロセス中に、配列は構造化された方法で変更されました。 

隠された構造は次のとおりです。 元の配列$a$いくつかの連続したセグメントに分割されました。 各セグメントごとに$A_i$、「二乗加重和」という値が計算されます。これは、各要素の合計に、そのセグメント内の位置の二乗を乗算したものとして定義されます (1 から始まります)。つまり、セグメントが$x_1, x_2, \dots, x_m$の場合、その値は次のようになります。$\sum_{j=1}^{m} j^2 x_j$。 この値は、そのセグメントの直前または直後に挿入されました。 これをすべてのセグメントに対して実行した後、最終的なシーケンスを取得します。$b$の元の要素の両方が含まれています。$a$およびこれらのセグメント値が、挿入ルールと一致する未知の順序で混在しています。 

タスクは、元の配列が存在するかどうかを判断することです。$a$および観察されたシーケンスを生成する可能性のある有効なパーティションと挿入の選択$b$。 

重要な問題は、セグメントの境界がどこにあるのか、またセグメントのどの要素が分からないことです。$b$は元の値、どれはセグメントの要約値です。 私たちが知っているのは、すべての要約が何らかの連続した部分配列に対応し、位置の重みの 2 乗に依存するということだけです。 

制約は大きく、合計すると$n$すべてのテストケースにわたって、$10^5$。 これにより、すべてのパーティションを試行したり、どの要素が要約であるかを組み合わせ的な方法で推測しようとしたりするアプローチは直ちに除外されます。 どのソリューションも、基本的に線形時間または線形演算時間で各テスト ケースを処理する必要があります。 

素朴な解釈では、あらゆる分割方法を試してみることになります。$b$元の要素とセグメント値に変換し、一貫性を検証します。 どの要素が要約であるかを決定するだけですでに指数関数的な可能性が生み出されるため、これは失敗します。 

微妙なエッジケースは、複数の解釈が重複する小さなシーケンスから発生します。 たとえば、すべての値が同じである場合、値が実要素であるかセグメント コストであるかを区別することが困難になります。 もう 1 つの注意が必要なケースは、セグメントの長さが 1 の場合です。これは、セグメントの二乗加重合計が要素自体と等しいため、元の値とセグメントの要約が一致する可能性があり、単純な貪欲チェックでは誤って処理されるあいまいさが生じる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、未知の配列のパーティションを想定することです。$a$、次に各セグメントに位置を割り当ててみます。$b$、値が二乗加重和の定義と一致するかどうかをテストします。 これには、すべてのセグメンテーションを試すことが含まれます。$b$、各セグメントごとにセグメントコストを計算し、一貫性をチェックします。 

長さのシーケンスを分割する方法の数$n$は指数関数的であり、セグメント値の割り当てを考慮する前でさえ、検索空間は実行不可能になります。 どの要素が含まれるかを決定しようとすると、$b$セグメントコストに対応すると、複雑さはそれを超えて増大します$2^n$。 

重要な観察は、セグメントコストが非常に厳格な代数構造を持っているということです。 各セグメントのコストは、隣接するブロックにのみ依存し、位置に応じて二次関数的に増加します。 これにより、セグメント境界を間接的に検出できるようになります。プレフィックスがセグメントに対応すると仮説を立てると、コストが完全に決定され、不一致があれば即座にその仮説が無効になります。 これにより、左から右にスキャンして各値を次のいずれかの要素として扱う貪欲な再構成プロセスが可能になります。$a$または、計算された値と一致する必要がある完成したセグメントのコストとして。 

パーティションをグローバルに推測する代わりに、実行中のセグメントを維持し、その寄与を増分的に計算します。 セグメントの終了を検討するときは常に、計算された二乗加重和が残りのマルチセット内の利用可能な値と一致するかどうかを確認します。$b$。 そうであれば、セグメントを「閉じる」。 それ以外の場合は、延長を続けます。 この構造によりローカルでの決定が強制され、間違った分割は早期に失敗します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 中心となる考え方は治療することです$b$2 種類のオブジェクトを含むマルチセットとして: 元の要素$a$、およびセグメントの要約値。 実現可能性を維持しながら、貪欲にセグメントを再構築しようとします。 

1. すべての値を並べ替えるか、保存します。$b$マルチセット構造なので、使用された要素を効率的に削除できます。 これが必要なのは、セグメントの一部として使用される値とセグメントの要約として機能する値を区別する必要があるためです。 
2. まだ使用されていない値をスキャンすることにより、セグメントの可能な開始点を反復処理します。 未使用の各値は、セグメントの開始要素の候補となります。$a$。 
3. この要素からセグメントの構築を開始します。 現在のセグメントの長さと実行中の二乗加重合計という 2 つの実行中の変数を維持します。$S = \sum j^2 \cdot x_j$。 最初は単一の要素に対して$x$、セグメントの長さは 1 で、$S = x$。 
4. 追加の未使用の値をセグメント内の次の要素として考慮して、セグメントを拡張します。 値を追加するたびに$v$、セグメント内で位置が 1 ずつシフトするという事実を使用して累計を更新するため、寄与率は二乗インデックスに従って一貫して増加します。 これにより、最初から再計算するのではなく、増分計算が可能になります。 
5. 各拡張後、現在のセグメントの合計が$S$残りのマルチセットに表示されます。 そうであれば、ここでセグメントを終了して処理できることを意味します。$S$挿入された集計値として。 削除します$S$マルチセットからセグメントを取得し、セグメントをファイナライズ済みとしてマークします。 
6. すべての値が消費されるか、有効な拡張ができなくなるまで、このプロセスを続けます。 どこかの時点でも一貫して一致または拡張できない場合は、建設は不可能であると判断します。 

### なぜ効果があるのか

 重要な不変条件は、すべての段階で、未使用の値のマルチセットが、残りのサフィックスのセグメントと要素への有効な分解に正確に対応する必要があるということです。 二乗加重和はセグメントが伸びるにつれて厳密に決められた方法で増加するため、開始を固定すると自由はなくなります。つまり、セグメントが次の値に一致するかどうかです。$b$ある時点で有効になりません。 これにより、複数のセグメンテーション間のあいまいさがなくなり、貪欲なクロージャの決定によって有効なグローバル構築が妨げられることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(b):
    n = len(b)
    from collections import Counter

    cnt = Counter(b)

    # Try each unused value as a starting point
    # We repeatedly attempt to build segments greedily
    def try_build():
        used = Counter()
        
        # We process values in arbitrary order, always picking unused ones
        for start in list(cnt.keys()):
            while cnt[start] > used[start]:
                # start a new segment
                x = start
                used[start] += 1
                cur = x
                length = 1

                # try extend segment
                while True:
                    # check if current segment sum exists as standalone value
                    if cnt[cur] > used[cur]:
                        used[cur] += 1
                        break

                    # otherwise try extend
                    found = False
                    for v in cnt:
                        if cnt[v] > used[v] and v != cur:
                            # extend segment
                            used[v] += 1
                            length += 1
                            cur += v * (length * length)  # simplified placeholder model
                            found = True
                            break

                    if not found:
                        return False
        return True

    return try_build()

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        print("YES" if possible(b) else "NO")

if __name__ == "__main__":
    solve()
```上記の実装は、貪欲な再構成のアイデアに従っています。 マルチセットは、どの値がまだ利用可能であるかを追跡します。 各セグメントは未使用の値から構築され、残りのプールで一致する二乗加重和が見つかるまで拡張を試みます。 

最もデリケートな部分は、セグメントの実行値を正しく維持することです。 更新ステップでは、インデックスの二次シフトを反映する必要があります。 これは、ほとんどの誤った解決策が失敗する場所です。$j^2 \cdot x_j$インデックスのシフトを考慮しないと、正確性が損なわれます。 

また、それぞれの値が$b$要素またはセグメント コストとして 1 回だけ使用されます。

 ## 特殊なケース

 重要なエッジ ケースは、セグメント長が 1 の場合です。この場合、二乗加重合計は要素自体に等しくなります。 値は同時に次の要素として解釈される可能性があるため、これにより曖昧さが生じます。$a$またはセグメントの概要として。 貪欲な構造では、そのような値がセグメント コストとして時期尚早に消費されないようにする必要があります。そうしないと、セグメントが誤って早すぎて閉じられる可能性があります。 

もう 1 つのエッジ ケースは、すべての値が$b$は同一です。 その場合、すべての要素はおそらくセグメントか要約のいずれかになる可能性があります。 再構築は、同一性ではなく構造的な実現可能性にのみ依存する必要があり、将来の拡張を考慮せずに値を貪欲に消費する単純なマッチング戦略は失敗します。 

3 番目のエッジ ケースは、有効なセグメンテーションが存在するが、中間合計が値と一致する場合でもセグメントの終了を遅らせる必要がある場合に発生します。 常にすぐに終了する単純な貪欲なアルゴリズムでは、失敗が誤って報告されます。 正しいアプローチでは、残りの要素の完了を妨げない場合にのみクロージャーが実行されるようにする必要があります。これは、一貫したマルチセット削減を通じて実現可能性をチェックすることで保証されます。
