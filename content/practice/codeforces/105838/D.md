 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、$n$1 から 1 までのラベルが付いた洞窟$n$、および一連の$n$計画された検査。各検査は 1 つの洞窟を対象とします。 順序は固定されており、事前にわかっています。 

プレイヤーは洞窟を 1 つだけ選択する必要があります$x$非表示にし、後で変更することはできません。 目標は、シーケンス全体で決して検査されない洞窟を選択することです。 言い換えれば、値が必要です$x$1との間$n$配列内のどこにも出現しないようにします。 

各テスト ケースの出力は、そのような有効な洞窟番号が存在する場合はその番号になります。それ以外の場合は、1 から 2 までのすべての洞窟が存在する場合に -1 を出力します。$n$少なくとも 1 回は表示されます。 

この制約により、合計で最大 1000 のテスト ケースが許可されます。$n$すべてのテストにわたって、$2 \cdot 10^5$。 これは、テスト ケースごとにほぼ線形の解は問題ありませんが、テスト ケースごとに 2 次の解は遅すぎることを意味します。$10^{10}$最悪の分布での運用。 

配列が次の順列である場合、微妙なケースが発生します。$1..n$。 この場合、すべての数値が 1 回だけ存在するため、有効な選択肢はなく、答えは -1 でなければなりません。 もう一つのエッジケースは、$n = 1$。 唯一の値が 1 の場合、答えは -1 です。 何らかの理由で 1 でない場合 (制約によりこのようなことは起こりません)、1 になります。 

単純な間違いは、存在を適切に追跡せずに、答えは常に最小の欠損数であると仮定すること、または全範囲を考慮する必要があることを忘れることです。$1..n$シーケンス内に現れる値だけではありません。 

## アプローチ

 最も直接的なアイデアは、候補となる洞窟をすべて試してみることです。$x$1から$n$、それぞれについてシーケンス全体をスキャンして、それが表示されるかどうかを確認します。 何か見つかったら$x$表示されない場合は、すぐに出力します。 

これは、問題の状態を明示的に検証するため機能します。 ただし、コストが高い。 それぞれについて$n$候補者の場合、最大でスキャンする場合があります$n$要素、$O(n^2)$テストケースごとに。 合計あり$2 \cdot 10^5$、これでは非常に遅くなります。 

重要な観察は、各候補を個別にテストする必要がないということです。 どの値が少なくとも 1 回出現するかだけを考慮します。 現在値のセットがわかったら、1 から 1 までの任意の数$n$そのセットに含まれていないものは有効です。 これにより、問題は単一パスのマーキング構造に縮小されます。 

サイズのブール配列を維持できます$n$、表示された各値をマークし、一度スキャンしてマークされていないインデックスを見つけます。 これにより、ソリューションはテスト ケースあたりの線形時間に短縮されます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | マーキング / ブール配列 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$。 1 から 1 までの値を記録したいと考えています。$n$現れる。 
2. ブール配列を作成する`seen`サイズの$n+1$、 false に初期化されます。 これにより、各洞窟番号が検査シーケンスに表示されるかどうかが追跡されます。 
3. 配列を走査する$a$。 それぞれの値について$a_i$、 マーク`seen[a_i] = true`。 このステップでは、シーケンスに関するすべての情報をプレゼンス データに圧縮します。 
4. すべての要素を処理した後、1 から 2 までを繰り返します。$n$。 最初のインデックス$x$そのような`seen[x]`is false はシーケンス内に出現しないため、有効な答えです。 
5. そうでない場合$x$存在する場合、出力 -1。 これは、1 から 2 までのすべての数値が一致したときに発生します。$n$マークが付けられました。これは、シーケンスに考えられるすべての洞窟が含まれていることを意味します。 

機能する理由: このアルゴリズムにより、問題はセット内のメンバーシップのチェックに軽減されます。 唯一の要件はシーケンスに存在しないことであるため、存在するとマークされていない値はすべて自動的に有効になります。 すべての値がマークされている場合、シーケンスはドメイン全体をカバーし、有効な選択肢は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        
        seen = [False] * (n + 1)
        for x in a:
            seen[x] = True
        
        ans = -1
        for i in range(1, n + 1):
            if not seen[i]:
                ans = i
                break
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はマーキング戦略に直接に従います。 の`seen`配列はテスト ケースごとにリセットされ、ケース間でリークが発生しないようにします。 最初のループでは、入力をプレゼンス情報に圧縮します。 2 番目のループでは、線形スキャンを実行して欠損値を見つけます。 

微妙な点は、有効な答えであれば何でも受け入れられるため、すべての欠損値を収集するのではなく、最初の欠損値で停止することです。 これにより、ロジックが最小限に保たれ、不必要な作業が回避されます。

 ## 特殊なケース

 重要なエッジケースは、配列が以下の完全な順列である場合です。$1..n$。 例えば：```
1
4
1 2 3 4
```マーキング配列は、すべてのインデックス 1 ～ 4 に対して完全に true になります。スキャンでは誤ったエントリは検出されず、アルゴリズムは正しく -1 を出力します。 

もう 1 つのケースは、シーケンスに繰り返される値が 1 つだけ含まれている場合です。```
1
5
2 2 2 2 2
```ここではインデックス 2 のみが true とマークされています。 スキャンでは、最初の欠損値として 1 がすぐに検出され、それが返されます。 これは、頻度ではなく存在のみを考慮しているため、重複が正確さに影響を与えないことを示しています。
