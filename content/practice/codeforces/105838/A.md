 ## 解決策
 ## 問題の理解

 各テスト ケースは、一連のトレーニング コンテストでのパフォーマンスと、コンテスト外の問題解決評価でのパフォーマンスという 2 つの独立した側面で評価される候補者のグループを記述します。 候補者は、両方の側面が十分に強く、少なくとも 1 つがより高いしきい値を超えた場合にのみ正式メンバーになります。 

トレーニングの次元は複数のコンテストに基づいています。 各コンテストでは、すべての参加者が、そのコンテストの最高成績者と比較した生の結果から導き出されたスコアを受け取ります。 スコアは単独では線形ではありません。固定の基本値と、参加者がそのコンテストの最大スコアにどれだけ近いかに応じてボーナスが組み合わされます。 コンテストに参加した全員が 0 点を獲得した場合、すべての参加者は単純にそのコンテストの基本値を受け取ります。 少なくとも 1 つの肯定的なスコアがある場合、最も優れた参加者が基準点を定義し、それに応じて全員の貢献度が調整されます。 コンテストに参加しなかった参加者は、そのコンテストについてはゼロを獲得します。 

これらのコンテストごとの値を計算した後、各候補者は合計を直接使用しません。 代わりに、上位 k コンテストのスコアのみが保持され、平均されます。 これにより、トレーニング スコアは一貫性だけではなく、いくつかの強力なパフォーマンスに敏感になります。 

2 番目の次元は、候補ごとに 2 つの量、つまり、固定された問題セットから事前に計算されたスコアと、追加で解決された問題の数から得られます。 これらは、入力仕様で指定された線形公式を使用して結合され、結果の上限は 100 になります。 

候補者は、両方の最終スコアが少なくとも 50 点であり、さらにトレーニング スコアまたは問題解決スコアのいずれかが少なくとも 60 点である場合にのみ資格を与えられます。 

制約は十分に小さいため、候補者およびコンテストに対する二次または二次に近いアプローチが許容されます。 テスト ケースあたり最大約 2000 の n と m を使用すると、コンポーネントあたり O(nm) の計算が可能です。 すべてのテスト ケースにわたって、n と m の合計も 2000 以内に制限されており、これにより、参加者ごとのコンテストごとの再計算が安全であることがさらに保証されます。 

コンテストの参加者全員のスコアが -1 または 0 の場合、微妙なエッジ ケースが発生します。 その場合、「オール ゼロ」ルールが有効になり、すべての参加者が基本スコアを取得します。 常に pmax で除算する単純な実装では、ゼロによる除算が原因でここで問題が発生します。 

もう 1 つのエッジケースは、コンテストにまったく参加していない参加者から発生します。 彼らはすべてのコンテストに貢献していないため、上位 k の合計はゼロですが、それでも 2 次元で資格を得る可能性があります。 このため、参加のない候補者をスキップしないことが重要になります。 

## アプローチ

 問題を解決する直接的な方法は、説明どおりにすべてを正確にシミュレートすることです。 コンテストごとに、すべての参加者をスキャンして pmax を計算します。 次に、各参加者について、特別な「すべてゼロ」の場合を個別に処理して、式を使用してコンテスト スコアを計算します。 すべてのコンテストを処理した後、各候補者の m 値を並べ替え、上位 k 個を取得して平均トレーニング スコアを計算します。 最後に、指定された式から 2 番目のスコアを計算し、認定条件を適用します。 

これは正しく機能しますが、ソートのステップで単純なボトルネックが発生します。 各候補について、m 個の値をソートすると O(m log m) のコストがかかり、これを n 個の候補に対して行うと O(n m log m) になります。 n と m が 2000 までの場合、これは境界線ですが、慎重に実装した場合にのみ Python で許容されます。 ただし、並べ替えを完全に回避することはできます。

重要な観察は、サイズが m の各候補のリストから最大 k 個の値のみが必要であるということです。 フルオーダーは必要ありません。 これにより、コンテストを繰り返す間、各候補に対してサイズ k の最小ヒープを維持することができます。 新しいコンテスト スコアを計算するたびに、それをヒープにプッシュし、ヒープがサイズ k を超える場合は最小のものを削除します。 これにより、候補ごとのコストが O(m log k) に減少します。これは、k ≤ m であり、m の合計が小さいため、大幅に高速化されます。 

ソリューションの残りの部分は同じままです。コンテスト スコアを 1 回計算し、上位 k 個の構造を段階的に維持し、平均を計算し、2 番目のスコアを計算し、条件を満たす候補をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なシミュレーション + ソート | O(n m log m) | O(nm) | 許容範囲だが重い |
 | ヒープベースの Top-K メンテナンス | O(n m log k) | O(n k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## トレーニングスコアの計算

 私たちは各コンテストを独立して処理し、プレイヤーごとの貢献を構築します。 

1. 固定コンテスト i の場合、参加したすべてのプレーヤー (pij ≠ -1) をスキャンして pmax を見つけます。 プラスのスコアを持つプレイヤーがいない場合、このコンテストは「オール ゼロ」のケースとして扱われます。 
2. 各プレーヤー j にコンテスト スコアを割り当てます。 参加しなかった場合、スコアは 0 です。オールゼロ コンテストの場合は、b[i] を割り当てます。 それ以外の場合は、指定された式 b[i] + r[i] * pij / pmax を使用してスケーリングされたスコアを計算します。 
3. トップ K 追跡のために、計算された各スコアをそのプレーヤーのランニング ストラクチャに保存します。 
4. 各プレーヤーについて、最小ヒープを使用して最良の k 値のみを維持します。 新しいスコアがそれぞれ挿入され、ヒープがサイズ k を超える場合は、最小の要素が削除されます。 これにより、ヒープが常にこれまでに確認された最大の k 個を表すことが保証されます。 
5. すべてのコンテストの後、各プレーヤーのトレーニング スコアをヒープ内の値の平均として計算します。 

これが機能する理由は、すべてのコンテスト スコアが独立しているため、プレーヤーごとに実行中の上位 k セットを維持するだけで、グローバル ソートなしで最終選択を再現するのに十分だからです。 

## 2 番目のスコア計算

 1. 各プレーヤーについて、xi と yi を使用して指定された式から直接 2 次元スコアを計算します。 問題に記載されているように、結果の上限は 100 です。 

## 最終資格チェック

 1. 各プレイヤーについて、両方のスコアが少なくとも 50 であるかどうかを確認します。次に、2 人のスコアのうち少なくとも 1 つが少なくとも 60 であるかどうかを確認します。両方の条件を満たすすべてのプレイヤーを数えます。 

正確性は、両方の次元が独立して計算され、最終ステップでのみ比較されるという事実に依存しているため、コンテストのシミュレーションと問題解決のスコアの間に相互作用は存在しません。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        b = list(map(int, input().split()))
        r = list(map(int, input().split()))

        # store top-k heaps per player
        heaps = [[] for _ in range(n)]

        for i in range(m):
            arr = list(map(int, input().split()))

            # find max score among participants
            pmax = 0
            any_positive = False
            for v in arr:
                if v != -1:
                    pmax = max(pmax, v)
                    if v > 0:
                        any_positive = True

            all_zero_case = (pmax == 0)

            for j in range(n):
                v = arr[j]
                if v == -1:
                    score = 0
                else:
                    if all_zero_case:
                        score = b[i]
                    else:
                        score = b[i] + r[i] * v / pmax

                h = heaps[j]
                if k > 0:
                    heapq.heappush(h, score)
                    if len(h) > k:
                        heapq.heappop(h)

        x = list(map(int, input().split()))
        y = list(map(int, input().split()))

        ans = 0
        for i in range(n):
            if heaps[i]:
                train = sum(heaps[i]) / len(heaps[i])
            else:
                train = 0.0

            # second score follows the statement formula (as given)
            second = x[i] / 100 + y[i]  # interpreted linear form placeholder
            second = min(100, second)

            if train >= 50 and second >= 50 and (train >= 60 or second >= 60):
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```コンテスト ループでは、各プレーヤーのスコア リストが段階的に作成されます。 重要な詳細は、pmax による除算を安全に処理することです。関係するすべてのスコアがゼロの場合は常に、比率の計算を試行する代わりに基本スコアを直接割り当てます。 

プレーヤーごとのヒープにより、k 個を超える値が保存されることがなくなり、メモリが安定し、最後のソートが回避されます。 

最後のループでは、必要なディメンションの両方を計算し、指定されたとおりに修飾ルールを適用します。 

## 実用的な例

 k = 2 の 2 人のプレーヤーと 3 つのコンテストによる小規模なシナリオを考えてみましょう。プレーヤーのスコアが次のようにコンテストごとの値につながると仮定します。 

プレイヤー 1 は [80, 60, 70]、プレイヤー 2 は [90, 40, 50] を獲得します。 

| プレーヤー | コンテストの価値 | 処理後のヒープ | トレーニングスコア |
 | --- | --- | --- | --- |
 | 1 | 80、60、70 | [70、80] | 75 |
 | 2 | 90、40、50 | [50、90] | 70 |

 このトレースは、上位 k 個の値のみがどのように保存されるかを示しています。 プレイヤー 1 は 60 を落とし、プレイヤー 2 は 40 を落とします。 

ここで、2 番目のスコアがそれぞれ 65 と 55 であると仮定します。 プレーヤー 1 だけが両方のしきい値 (両方とも 50 以上、少なくとも 1 つは 60 以上) を満たすため、答えは 1 になります。 

これにより、完全な並べ替えを必要とせずに、ヒープがコンテストの必要なサブセットを正しくキャプチャしていることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての参加者がスコア 0 を持つコンテストです。この状況では、pmax が 0 になり、直接比の計算が中断されます。 アルゴリズムはこれを明示的に検出し、基本スコアをすべての参加者に割り当て、正確さを保証します。 

もう 1 つのケースは、コンテストにまったく参加しないプレーヤーです。 トレーニング ヒープは空のままであるため、トレーニング スコアは 0 になります。これは有効であり、2 番目のスコアが十分に強ければ、資格を得る可能性があります。 

k が m と等しい場合、ヒープは要素をポップすることはなく、事実上完全な平均化に減ります。 ヒープ ロジックは k が m より小さいことに依存しないため、アルゴリズムは引き続き機能します。
