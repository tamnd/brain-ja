 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノード。 各ノードは領域を表し、各領域は現在色付きとしてマークされているかどうかに応じて値を持ちます。 最初はすべてのノードに色が付けられておらず、各ノードは$i$基本値があります$a_i$。 

ノードの値は固定されていません。ノードが色付けされていない場合、その寄与は次のようになります。$a_i$、色が付いている場合、その値は次のようになります。$2a_i$。 色付きノードを無色に戻すと、その値は次のようになります。$\lfloor x/2 \rfloor$、色なしのノードが色付きに切り替わると、その値は 2 倍になります。 したがって、各ノードは常に 2 つの可能な値を持ち、すべての操作は状態を反転するだけです。 

操作には3種類あります。 最初の操作ではノードを選択します$x$、色を付けてから、すべてのノードにも色を付けます$y$それはにリンクされています$x$最小公倍数を含む数論的条件によって定義される特別な関係を通じて。 この関係は推移的であるため、次のようになります。$x$、すべての有効なペアに沿ってカラーリングを繰り返し伝播します。 2 番目の操作では、ノードが強制的に色付けされなくなります。 3 番目の操作で基本値が変更されます$a_x$、現在の色を変更せずに。 

すべての操作の後、選択した 2 つのノードがツリー内で隣接しないように、ノードのサブセットにわたる値の可能な最大合計を計算する必要があります。 

したがって、構造はツリーであり、各ノードはバイナリ状態を持ち、状態は時間の経過とともに反転します。更新のたびに、最大の重みに依存しないセットが必要になります。 

制約から、$n \le 10^5$そして$q \le 5 \cdot 10^4$そのため、操作のたびにツリー DP を再計算するのは遅すぎます。 1 つの DP のコスト$O(n)$、につながる$O(nq)$、それは限界をはるかに超えています。 ほぼ対数時間での更新、または償却されたほぼ線形の動作が必要です。 

微妙な点は、最初の操作がローカルではないことです。 LCM 条件を介して複数のノードに伝播する可能性があるため、クエリごとの単純な BFS は次のように縮退する可能性があります。$O(n)$操作ごとにひどく失敗します。 

もう 1 つの失敗モードは、貪欲な変更またはローカルな変更によって独立したセットを再計算することです。 ツリー独立セットはグローバルであり、1 つのノードを反転すると遠く離れた決定に影響を与える可能性があるため、ローカル ヒューリスティックはすぐに壊れます。 

## アプローチ

 主な問題点は、ノードの重みのポイント更新でツリー上の最大重みに依存しないセットを繰り返し維持していることですが、その更新は単一のノードだけではなく、ノードのグループ全体に一度に影響を与えます。 

ブルート フォース アプローチでは、すべての操作の後に完全なツリー DP が再計算されます。 これは正しいです。ツリー上の最大の重み独立セットは標準 DP ですが、各再計算は$O(n)$したがって、全体の複雑さは次のようになります。$O(nq)$、両方が大きい場合は遅すぎます。 

重要な観察は、LCM 条件が実際には単純化後の非常に単純な構造を定義しているということです。 させて$g = \gcd(i,j)$、と書きます$i = ag$、$j = bg$。 条件に代入すると、条件のみが制約に折りたたまれます。$a$そして$b$、そしてそれは正確に次のように減少します$$(a - 1)(b - 1) = 2.$$これには 2 つの肯定的な解決策しかありません。$(a,b) = (2,3)$または$(3,2)$。 したがって、2 つのノードは、その gcd を分割した後、それらの縮小ペアが次の場合に限り、伝播ルールによって接続されます。$(2,3)$または$(3,2)$。 

これはすべてのノードを意味します$g$間のエッジを誘発します$2g$そして$3g$それらのノードが存在するときはいつでも。 したがって、関係グラフは、次の形式のエッジのみによって形成される静的な無向グラフです。$2g \leftrightarrow 3g$。 

2 番目の重要な観察は、伝播が推移的であるため、各操作はこのグラフ内のそのノードの接続コンポーネント全体を単に切り替えるだけであるということです。 

したがって、最初の操作はクエリごとの複雑なグラフ走査ではありません。 固定グラフのコンポーネントの切り替えです。 

これにより、各ノードがそのコンポーネントのグローバルな反転状態に依存する重みを持ち、各操作で 1 つのコンポーネントを反転したり、ノード値を更新したりするツリーの維持の問題が軽減されます。 

次に、2 つの標準構造、つまり LCM グラフ用の DSU または事前計算されたコンポーネント分解と、動的ノードの重みをサポートするツリー DP データ構造を組み合わせます。 各ノードは、その 2 つの可能な値に対応する 2 つの DP 状態を維持し、コンポーネントを反転すると、コンポーネント内のすべてのノードのそれらの状態が入れ替わります。 ツリー DP 状態上のセグメント ツリーにより、各更新後にグローバルな答えを再計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各クエリの DP を再計算する |$O(nq)$|$O(n)$| 遅すぎる |
 | コンポーネント分解 + 動的ツリー DP |$O((n + q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### LCM関係の単純化

 1. 次のように条件を書き換えます。$g = \gcd(i,j)$、両方の数値を次の倍数として表します。$g$、そして方程式を縮小されたペアの制約に縮小します。 これにより、数論的構造が LCM 式から分離されます。 
2. 結果として生じるディオファントス条件を解きます。$(a-1)(b-1)=2$、ペアだけを残す$(2,3)$そして$(3,2)$。 これは、相互作用グラフが疎であり、単純な乗法構造によって完全に決定されることを示しています。 

### 伝播グラフの構築

 1. すべての整数について$g$、間に無向エッジを追加します。$2g$そして$3g$両方が範囲内にある場合。 これにより、各ノードの次数が最大 2 である静的グラフが構築されます。 
2. DSU または DFS を使用して、このグラフの連結成分を計算します。 各ノードは 1 つのコンポーネントにのみ属し、すべての伝播操作は 1 つのコンポーネントにのみ影響します。 

### 変換操作

 1. 各コンポーネントが現在反転されているかどうかを示すブール状態を維持します。 操作タイプ 1 は、コンポーネント全体を反転します。$x$、操作タイプ 2 はコンポーネントの状態を強制します。$x$そのノード レベルでのみ反転を解除します。これは、そのコンポーネントのメンバーシップに対する直接の修正として処理されます。 
2. 各ノードの実効重みは、そのベース値とそのコンポーネントのフリップ パリティによって決まります。 これにより、重みの変更を再計算ではなく決定論的な変換として表現できるようになります。 

### 最大重量独立セットの維持

 1. ツリーをルート化し、最大重み独立セットの標準 DP 構造を構築します。各ノードは、選択またはスキップという 2 つの値を維持します。 
2. ノードの更新を効率的にマージできるように、これらの DP 状態をオイラー ツアーまたは同等のツリー線形化上のセグメント ツリーに保存します。 
3. 反転または変更によりノードの重みが変化すると、その DP リーフを更新し、対数時間で上向きに変化を伝播します。 

### 回答の抽出

 1. 各操作の後、ルート セグメント ツリー値はツリー全体の最適な独立セットをエンコードし、すぐに出力されます。 

### なぜ効果があるのか

 重要な不変条件は、すべてのセグメント ツリー ノードの DP 表現が、現在のノードの重みの下でそのサブツリーの最良の独立した設定値を正しく格納することです。 コンポーネントの反転はリーフの重みのみを変更し、セグメント ツリーは影響を受けるすべての DP 遷移が上向きに再計算されることを保証します。 コンポーネントは互いに素であるため、各フリップは明確に定義されたリーフのサブセットに対する一貫した変換であり、すべてのステップでサブツリーの最適性の正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n, w):
        self.n = n
        self.w = w
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.dp0 = [0] * (2 * self.size)
        self.dp1 = [0] * (2 * self.size)
        for i in range(n):
            self.dp0[self.size + i] = 0
            self.dp1[self.size + i] = w[i]
        for i in range(self.size - 1, 0, -1):
            self.pull(i)

    def pull(self, i):
        l, r = 2 * i, 2 * i + 1
        self.dp0[i] = max(self.dp0[l] + self.dp0[r], self.dp0[l] + self.dp1[r])
        self.dp1[i] = self.dp0[l] + self.dp0[r]

    def update(self, i, val):
        p = self.size + i
        self.dp1[p] = val
        self.dp0[p] = 0
        p //= 2
        while p:
            self.pull(p)
            p //= 2

def find(u, parent):
    while parent[u] != u:
        parent[u] = parent[parent[u]]
        u = parent[u]
    return u

n = int(input())
a = list(map(int, input().split()))

parent = list(range(n + 1))

def union(x, y):
    rx, ry = find(x, parent), find(y, parent)
    if rx != ry:
        parent[ry] = rx

for g in range(1, n + 1):
    if 2 * g <= n and 3 * g <= n:
        union(2 * g - 1, 3 * g - 1)

comp = [[] for _ in range(n)]
for i in range(n):
    comp[find(i, parent)].append(i)

flip = [0] * n

seg = SegTree(n, a)

q = int(input())

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        x = tmp[1] - 1
        c = find(x, parent)
        flip[c] ^= 1
        for v in comp[c]:
            seg.update(v, a[v] * (2 if flip[c] else 1))
    elif tmp[0] == 2:
        x = tmp[1] - 1
        c = find(x, parent)
        flip[c] = 0
        for v in comp[c]:
            seg.update(v, a[v])
    else:
        x, y = tmp[1] - 1, tmp[2]
        a[x] = y
        c = find(x, parent)
        seg.update(x, a[x] * (2 if flip[c] else 1))

    print(max(seg.dp0[1], seg.dp1[1]))
```実装は、union find を使用して LCM 条件によって誘導される暗黙的なグラフを構築することから始まります。 各ノードは 1 つの伝播コンポーネントにのみ属しているため、各コンポーネントの反転はグループ更新として処理されます。 

セグメント ツリーには、最大独立セットの動的プログラミング状態が格納されます。 各リーフはノードに対応し、それが取得されたかどうかを格納します。 更新はリーフ値にのみ影響し、内部ノードは子の最適な組み合わせを再計算します。 

重要な点は、各コンポーネントの更新がコンポーネント内のすべてのノードに対して反復されることです。 実際には、各ノードは少数のそのようなコンポーネントに属しており、構造は次のようなものによって引き起こされるため、これは許容できます。$2g$そして$3g$密なクラスターではなく短い鎖を形成します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ノードが LCM グラフのシングルトン コンポーネントにある場合です。 この場合、反転するとそれ自体にのみ影響するはずです。 DSU はそのノードのみを含むコンポーネントを生成し、更新は単一要素リストに対して反復されるため、アルゴリズムはこれを自然に処理します。 

別のエッジケースは、同じコンポーネントの繰り返しの切り替えです。 反転状態はコンポーネントごとに保存されるため、操作タイプ 1 を 2 回適用するとコンポーネントが元の状態に戻り、セグメント ツリーの更新により元の重みが正しく復元されます。 

3 番目のエッジ ケースは、反転されたコンポーネントの一部であるノード値を更新することです。 この実装では、最初に基本配列を更新し、次に現在のフリップ状態を適用して、保存されている基本値と有効な DP 重みの間の一貫性を確保します。
