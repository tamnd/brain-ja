 ## 問題の理解

 正確に次のマルチセットから始めます$k$数字。 このうち、$k-1$コピーはある値と等しい$x$、単一の要素は以下に等しい$y$。 したがって、最初の構造は、1 つの「障害」を除いて非常に均一です。 

各操作では任意の 2 つの要素を選択します$a$そして$b$、それらを削除し、平均を計算して切り捨て、この切り上げられた値のコピーを 2 つ挿入します。 実際、ペアは以下に等しい 2 つの同一の値に置き換えられます。$\left\lfloor \frac{a+b}{2} \right\rfloor$。 マルチセットのサイズは決して変わりませんが、値は小数部分を失いながら徐々に互いに近づいていきます。 

このプロセスは任意に何度も繰り返されます。 最終的には、すべての要素が等しくなる状態に常に到達することが可能です。 タスクは、この最終的な共通値の可能な最小値を決定することです。$S$。 

制約は非常に大きいです。$k$まで行くことができます$10^9$、値は到達可能です$10^{18}$。 これにより、プロセスのシミュレーションが即座に除外されます。 マルチセットを保存することさえ不可能であるため、ソリューションではダイナミクス全体を操作の不変式から導出される閉じた形式の式に圧縮する必要があります。 

微妙なエッジケースは、平均化のフロアから発生します。 もし$a+b$が奇数の場合、結果として得られる 2 つの要素の合計は厳密に次よりも小さくなります。$a+b$、合計が保持されないことを意味します。 これにより、単純な平均に基づいた議論では見逃す可能性のある「損失」の可能性が生じます。 たとえば、値の場合$1$そして$2$、この操作により 2 つの値が生成されます。$1$s、合計を減らす$1$。 合計の保存を前提とした推論は直ちに失敗します。 

## アプローチ

 ブルートフォース シミュレーションでは、ペアを繰り返し選択し、変換を適用し、システムが収束することを期待します。 州のコストを表すことさえ$O(k)$、それぞれの操作は$O(1)$、ただし、安定化するまでの操作の数には原則的に制限がなく、値の大きさに応じて簡単に拡張できます。 と$k$まで$10^9$、このアプローチは完全に実行不可能です。 

重要な構造上の観察は、制御された丸め損失を除いて、演算が線形に動作することです。 マルチセットの合計を定義すると、各演算は次のように変換されます。$(a,b)$2つのコピーに分けて$\left\lfloor \frac{a+b}{2} \right\rfloor$なので、合計はちょうど だけ減少します。$(a+b) \bmod 2$。 これは、選択したペアの合計が奇数の場合に、合計が変わる唯一の方法は、1 単位を失うことであることを意味します。 

これにより、個々の値の追跡から総和の削減の追跡へと視点が変わります。 最終状態にはすべての要素が等しいため、$S$、最終的な合計は$kS$。 したがって、問題は、パリティが許可する場合にのみ、操作ごとに最大 1 ユニットしか損失できないという制約を尊重しながら、最終的な合計をどれだけ小さくできるかを理解することになります。 

初期構成の構造から、ベースラインを超える「過剰質量」の合計$x$単一の要素に集中している$y$。 このプロセスにより、この余剰分がすべての組織に再分配されるようになります。$k$位置が異なり、パリティの不一致が生じるような方法で再分配されるたびに、1 ユニットが失われる可能性があります。 最適な戦略は余剰を可能な限り均等に効果的に分配し、避けられない下限は合計を平均することによって決まります。$k$要素。 

これにより、閉じた形式が得られます。達成可能な最良の最終値は、平均合計の下限によって決定され、この特定の 2 つの値の構成では、きれいに単純化されます。

 ## アルゴリズムのチュートリアル

 操作をシミュレートするのではなく、グローバル不変式から直接答えを導き出します。 

1. すべての要素の初期合計を計算します。 配列には以下が含まれます$k-1$のコピー$x$そして1部のコピー$y$、つまり合計は$(k-1)x + y$。 
2. すべての操作で要素の数が保持されるため、最終的な構成は正確に構成されている必要があることに注意してください。$k$同一の値$S$、合計を与える$kS$。 
3. 操作中に合計がどのように変化するかを追跡します。 交換中$a, b$2枚のコピーで$\left\lfloor \frac{a+b}{2} \right\rfloor$合計を減らす$(a+b) \bmod 2$、これは 0 または 1 のいずれかです。 
4. ペアを繰り返し選択できるため、値を可能な限り均等に分散する一連の操作を常に実現できます。 唯一の不可逆的な影響は、パリティの不一致によって引き起こされる累積損失であり、合計が増加することはありません。 
5. したがって、可能な最小の最終合計は次の最大倍数になります。$k$合計は単位ステップでしか減らすことができず、残りの質量を均等に分配することはできないため、初期合計を超えることはありません。 
6. これを最終的な答えに変換します$S = \left\lfloor \frac{(k-1)x + y}{k} \right\rfloor$。 

以来$(k-1)x + y = kx + (y-x)$、これを単純化すると、$S = x + \left\lfloor \frac{y-x}{k} \right\rfloor$。 

### なぜ効果があるのか

 不変条件は、固定カーディナリティと合計の制御された単調減少の組み合わせです。 すべての操作は合計を保存するか、ちょうど 1 だけ減らすかのいずれかであり、合計を増やす操作はありません。 最終状態は繰り返される単一の値によって完全に決定されるため、$k$合計は、終了時のシステムを完全に特徴づけます。 唯一の自由は、均一な構成に到達する前に、初期合計のうちどれだけをパリティ損失によって「消費」できるかということです。 その自由は、総和限界と一致する最大の可能な均一値を取ることによって正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k, x, y = map(int, input().split())
        s = (k - 1) * x + y
        print(s // k)

if __name__ == "__main__":
    solve()
```実装は不変引数を直接エンコードします。 操作をシミュレートする代わりに、最初の合計を計算し、次の値で除算します。$k$、プロセスは均一な構成に達するまで整数ステップでのみ合計を減少させることができるという事実に依存しています。 

重要な詳細は整数の除算です。最終値は整数でなければならず、合計は減少することしかできないため、答えは正確に平均合計の下限になります。

## テストケース```python
import sys, io

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        k, x, y = map(int, input().split())
        out.append(str(((k - 1) * x + y) // k))
    return "\n".join(out)

 ## 特殊なケース

 最も重要なエッジケースは、すべての値がすでに等しい場合です。$k=5, x=y=7$。 この操作は引き続き適用されますが、同じ数値を平均することで値が保持されるため、値を変更することはできません。 合計は次のとおりであるため、アルゴリズムはこれを直接処理します。$5 \cdot 7$、除算が返されます$7$、不変条件と一致します。 

もう 1 つのエッジケースは次のような場合です$y$よりわずかに大きいだけです$x$、 例えば$k=4, x=10, y=11$。 ここでは余分な質量は 1 だけですが、4 つの位置に分散されているため、最終的な均一な状態ではどの要素も 1 つ増やすことができません。 数式は正しく返されます$10$、すべての要素の平均化に耐えられないため、追加ユニットを「拡散」しようとする試みは失敗します。 

最後のエッジ ケースは、制約制限に近い大きな値で発生します。$y-x$に近いです$2k-1$。 この極端な状況でも、すべてが単一の整数除算に還元されるため、計算は安定したままであり、オーバーフローや反復不安定性が回避されます。
