 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付いたノードを持つルート付きツリーが与えられます。 各ノードには色があります。 ツリーのルートはノード 1 であるため、すべてのノードには、それ自体とそのすべての子孫で構成される明確に定義されたサブツリーがあります。 

私たちにもいくつかの問い合わせが寄せられています。 各クエリはノード u と距離制限 k を指定します。 このクエリでは、u のサブツリー内を調べますが、ツリーの距離の点で u に十分近いノードのみを考慮します。 より正確には、v が u のサブツリー内にあり、u から v へのパス上のエッジの数が最大でも k であるような、ノード v に現れるすべての個別の色を数えます。 

各クエリの出力は 1 つの整数、つまりツリーのその制限された領域内のすべてのノードに表示される異なる色の数です。 

主な問題は、サブツリー制限と距離制限の両方を同時に適用する必要があり、クエリが多数になる可能性があるため、クエリごとに答えを最初から再計算するのは現実的ではないことです。 

制約の観点から見ると、これは一般的な設定であり、n とクエリの数が十分に大きいため、クエリごとに二次関数を実行することは即座に不可能になります。 クエリごとの単純な走査では、大きなサブツリーを繰り返しスキャンすることになり、O(nq) 付近で最悪の動作が発生しますが、これは許容範囲をはるかに超えています。 クエリが多数の場合、クエリあたり O(n log n) のアプローチでも遅すぎるため、目的のソリューションではツリーを前処理し、クエリ間で計算を再利用する必要があります。 

微妙な問題は、「あなたからの距離」が奥行きと相互作用するという事実から生じます。 木はルート化されているため、u から子孫 v までの距離は単に深さ[v] − 深さ[u] となります。 これは、すべてのクエリが実際に、サブツリーの包含を尊重しながら、深さが特定の間隔 [深さ[u], 深さ[u] + k] にある u のサブツリー内のノード v を要求することを意味します。 この変換が重要な構造の簡素化です。 

よくある間違いは、クエリを純粋なサブツリー カラーカウント問題として扱い、深さの制約を無視したり、クエリを純粋な深さフィルタリング問題として扱い、サブツリーの境界を無視したりすることです。 どちらの間違いも、サブツリーの外側のノードを数えすぎたり、距離 k 以内にないノードを数えたりすることにつながります。 

## アプローチ

 最も直接的なアプローチは、DFS または BFS を使用して u のサブツリーを走査し、距離 k 内のすべてのノードを収集することによって、各クエリを独立して処理することです。 訪問したノードごとに、その色をセットに挿入します。 これは定義に直接従っているため、正しいです。 ただし、最悪の場合、サブツリーに O(n) 個のノードが含まれ、O(n) 個のクエリが存在し、O(n²) 個の動作が発生する可能性がありますが、これは現実的ではありません。 

この非効率性は、ツリーの重複領域を繰り返し再計算することから生じます。 サブツリーは大部分を共有しており、多くのクエリでは同様の深さの範囲について質問されます。 重要な観察は、答えはサブツリーのメンバーシップと深さの範囲という 2 つの構造特性のみに依存するということです。 サブツリー メンバーシップはオイラー ツアー順序付けを使用して処理でき、深さは追加の次元として処理できます。 

この問題は、サブツリー内のアクティブなノードの動的なセットを維持することと考えることができ、そのアクティブなセットについて、各深度で表示される異なる色の数を数えたいと考えます。 深度ごとに、その深度のアクティブなノード間に現在いくつの異なる色が存在するかを維持できれば、各クエリは深度にわたる範囲の合計になります。 

これは、ツリー上の DSU (小規模から大規模) のような技術を使用したオフライン戦略を示唆しています。 ツリーをボトムアップで処理し、ノードの追加と削除をサポートする現在のサブツリーのデータ構造を維持します。 深度ごとに、色の周波数マップを維持し、さらに、その深度にいくつの異なる色が存在するかを示す構造も維持します。 その後、深さの間隔を合計することで各クエリに答えることができます。

重要な改善点は、サブツリーを最初から再計算しないことです。 代わりに、子サブツリーを親サブツリーにマージし、色情報を段階的に追跡します。 これにより、プロセス全体で各ノードの追加と削除が O(log n) 回だけ行われるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | 深さをカウントするツリー上の DSU | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題をオフラインのサブツリー集約タスクに変換します。 

まず、ルートからの DFS を使用してすべてのノードの深さを計算します。 これにより、距離の制約を深さの間隔に置き換えることができます。 

また、各ノード u に関連付けられたクエリのリストも作成します。 各クエリには、出力用の k とインデックスが格納されます。 

次に、各ノードがそのサブツリーを表す共有構造を維持するツリー (小規模から大規模) 手順で DSU を実行します。 

1. DFS を実行してサブツリーのサイズを計算し、各ノードの重い子を特定します。 重い子は、最大のサブツリーを持つ子です。 この選択により、ほとんどのマージ操作がツリー全体で低コストになります。 
2. 最初にすべてのライトの子を再帰的に処理します。 軽い子を処理した後、現在のノードの構造にマージした後、そのデータ構造を破棄します。これは、重いサブツリーに比べて小さいためです。 これにより、合計マージコストが制限されます。 
3. 重い子を再帰的に処理し、そのデータ構造を現在のノードの基本構造として再利用します。 これは、再構築の繰り返しを防ぐための核となる最適化です。 
4. 深さによってインデックス付けされた構造を維持します。 各深さ d について、色からその深さのアクティブなノードの数までの周波数マップを保存します。 それと並行して、深度にわたって BIT (フェンウィック ツリー) を維持します。ここで、BIT[d] は、深度 d に現在存在する個別の色の数に等しくなります。 
5. 現在アクティブな構造にノード v を追加するとき、d = Depth[v] および c = color[v] を計算します。 これが深さ d での色 c の最初の出現である場合、BIT[d] をインクリメントします。 次に、周波数カウンターを増やします。 
6. ノード v を削除するとき (ライト サブツリーのクリーンアップ中)、同じ操作を逆に実行します。周波数をデクリメントし、周波数がゼロになった場合は BIT[d] をデクリメントします。 
7. ノード u の構造を構築した後、u に関連付けられたすべてのクエリに答えます。 各クエリは、深さ[v]が[深さ[u],深さ[u] + k]となるようなサブツリー(u)内のノードvを要求します。 これを BIT にわたる範囲の合計として計算します。 
8. 最後に、軽いサブツリー コンテキストにいる場合は、兄弟サブツリーが干渉しないようにその寄与をクリーンアップします。 

正確さは、各ノード u で、DSU 構造が u のサブツリー内のノードのマルチセットを正確に表すという事実に依存します。 深度インデックス付き BIT は深度ごとの個別の色の数をエンコードするため、深度間隔にわたって合計すると、必要な距離範囲内の個別の色が正確にカウントされます。 

## なぜ機能するのか

 DSU 処理中のどの時点でも、アクティブな構造は元のツリーの 1 つのサブツリーに正確に対応します。 そのサブツリー内のすべてのノードは、深度-色の周波数構造内で 1 回だけ表されます。 BIT は、深度ごとに、その深度でアクティブなノード間で表示される個別の色の数を集計します。 

各ノードの寄与は、そのサブツリーが含まれるときに正確に追加され、破棄されるときに正確に削除されるため、無関係なサブツリーに影響を与えるノードはありません。 小から大への戦略では、各ノードが対数回だけ移動されることが保証されるため、正確なカウントを維持しながら頻度更新の効率性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    color = list(map(int, input().split()))
    color = [0] + color

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    queries = [[] for _ in range(n + 1)]
    ans = [0] * q

    qs = []
    for i in range(q):
        u, k = map(int, input().split())
        queries[u].append((k, i))

    depth = [0] * (n + 1)
    parent = [0] * (n + 1)
    sz = [0] * (n + 1)

    def dfs(u, p):
        sz[u] = 1
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            parent[v] = u
            dfs(v, u)
            sz[u] += sz[v]

    dfs(1, 0)

    max_depth = max(depth)

    from collections import defaultdict

    bit = [0] * (max_depth + 2)

    def bit_add(i, v):
        i += 1
        while i <= max_depth + 1:
            bit[i] += v
            i += i & -i

    def bit_sum(i):
        s = 0
        i += 1
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    cnt = [defaultdict(int) for _ in range(max_depth + 2)]

    def add_node(u):
        d = depth[u]
        c = color[u]
        if cnt[d][c] == 0:
            bit_add(d, 1)
        cnt[d][c] += 1

    def remove_node(u):
        d = depth[u]
        c = color[u]
        cnt[d][c] -= 1
        if cnt[d][c] == 0:
            bit_add(d, -1)

    heavy = [0] * (n + 1)

    def dfs_sz(u, p):
        sz[u] = 1
        maxc = 0
        for v in g[u]:
            if v == p:
                continue
            dfs_sz(v, u)
            sz[u] += sz[v]
            if sz[v] > maxc:
                maxc = sz[v]
                heavy[u] = v

    dfs_sz(1, 0)

    def add_subtree(u, p):
        add_node(u)
        for v in g[u]:
            if v != p:
                add_subtree(v, u)

    def remove_subtree(u, p):
        remove_node(u)
        for v in g[u]:
            if v != p:
                remove_subtree(v, u)

    def dsu(u, p, keep):
        for v in g[u]:
            if v != p and v != heavy[u]:
                dsu(v, u, False)

        if heavy[u]:
            dsu(heavy[u], u, True)

        for v in g[u]:
            if v != p and v != heavy[u]:
                add_subtree(v, u)

        add_node(u)

        for k, idx in queries[u]:
            L = depth[u]
            R = depth[u] + k
            if R > max_depth:
                R = max_depth
            ans[idx] = bit_sum(R) - bit_sum(L - 1)

        if not keep:
            remove_subtree(u, p)
            remove_node(u)

    dsu(1, 0, True)

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```この解決策は、ツリーに DSU を適用できるように、深さとサブツリーのサイズを計算することから始まります。 サブツリーをマージするときの繰り返し作業を最小限に抑えるために、重い子が選択されます。 

中心的な考え方は、すべてのアクティブなサブツリーが、深さによってインデックス付けされた頻度構造によって表されるということです。 フェンウィック ツリーは、深さごとの個別の色のカウントを、高速範囲クエリをサポートする形式に圧縮します。 

各クエリは、DSU 構造がクエリされたサブツリー ルートに正確に対応する時点で応答されるため、追加のトラバーサルを必要とせずに正確さが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、k が十分に大きく、ツリー内の最大深さを超えてしまう場合です。 その場合、アルゴリズムは深さの範囲を利用可能な最も深いノードに固定し、範囲クエリが無効なフェンウィック インデックスにアクセスしないようにしながら、すべての有効なノードをカウントします。 

もう 1 つのケースは、すべてのノードが同じ色を共有する場合です。 周波数マップにより、各色が深度ごとに 1 回だけカウントされることが保証されるため、同じ深度に多数のノードが存在する場合でも、BIT は深度ごとに色ごとに 1 回だけ増加します。 これにより、密集したサブツリーでの過剰カウントが防止されます。 

最後のケースは、すべてのノードが 1 つのパス内にある縮退チェーン ツリーです。 ここでは、サブツリーと深さの範囲が重なり合っており、単純な再計算では同じノードを繰り返し走査することになります。 ツリー上の DSU では、各ノードの移動回数が少ないことが保証され、効率を維持しながら正しい範囲カウントが生成されます。
