 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$、すべての要素は負ではない整数です。 この配列から、すべての連続するサブ配列を考慮します。各サブ配列には、その要素の合計に等しい重みがあります。 

すべての部分配列の合計をリストし、降順でない順に並べ替えると、複数のクエリに答えるように求められます。 各クエリは整数を返します$k$の値を出力する必要があります。$k$-そのソートされたリスト内の最小の部分配列の合計。 

重要な隠された構造は、$O(n^2)$サブ配列の場合、配列にはゼロと正の値のみが含まれるため、ウィンドウを拡張または縮小すると、サブ配列の合計は単調に動作します。 この単調性により、チェックごとにほぼ直線的な時間で問題を解決できるようになります。 

もし$n$大きい、最大まで言う$2 \times 10^5$、すべての部分配列を列挙すると、すでに約$2 \times 10^{10}$合計を明示的に並べ替えることは不可能です。 保管することさえ不可能です。 これにより、すべての間隔の合計を明示的に構築または並べ替えるアプローチは即座に除外されます。 

単純な間違いは、プレフィックスの合計を仮定し、差異を直接ソートすることです。 ただし、プレフィックス インデックスのすべてのペアを生成する必要があり、これも二次関数です。 もう 1 つの微妙な失敗例は、区間を拡張することで部分配列の合計のヒープを維持しようとすることですが、それでも二次関数の動作に退化します。 

たとえば、配列が次の場合、$[1, 2, 3]$、部分配列の合計は次のとおりです。$[1, 2, 3, 3, 5, 6]$。 正しいソリューションでは、3 が 2 回出現するような重複を正しく処理する必要があります。これは、単純な「貪欲に次の拡張機能を選択する」という考えをすでに打ち破っています。 

## アプローチ

 ブルートフォース手法は簡単です。 左の端点を固定し、右の端点を拡張することによってすべての部分配列の合計を計算し、すべての合計をリストに蓄積してから、リストを並べ替えて、インデックス付けによってクエリに答えます。 これは、必要なマルチセットを直接構築するため、正しいです。 ただし、実行します$O(n^2)$部分配列の構築とそれらの並べ替えには時間がかかります$O(n^2 \log n^2)$、これは中程度の人でも限界をはるかに超えています$n$。 と$n = 2 \times 10^5$、サブアレイの数だけでは、このアプローチは実行不可能になります。 

重要な点は、すべての合計を明示的に構築したり並べ替えたりする必要がないということです。 代わりに、値が与えられた場合に、決定に関する質問をすることができます。$x$、合計が以下の部分配列がいくつあるか$x$? これを効率的に計算できれば、二分探索を行うことができます。$x$少なくとも次のような最小値を見つけます。$k$部分配列には合計があります$\le x$。 これにより、問題は、巨大な暗黙的な配列のソートから、単調な述語に対する繰り返しのカウントへと変換されます。 

すべての配列値が負ではないため、カウント手順が効率的になります。 これにより、左側の境界を固定した場合、右側の境界を拡張しても合計が増加するだけであることが保証されるため、線形時間で 2 つのポインターを持つスライディング ウィンドウを維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \log n^2)$|$O(n^2)$| 遅すぎる |
 | 二分探索 + 2 つのポインター |$O(n \log S)$|$O(1)$| 承認済み |

 ここ$S$は配列の合計であり、すべての部分配列の合計を制限します。 

## アルゴリズムのチュートリアル

 問題を、応答空間での二分探索を使用して、部分配列の合計に対する複数の k 次の統計クエリに答えるというものにまとめます。 

1. 可能な最大の部分配列の合計、つまり配列の合計を計算します。 これが二分探索の上限になります。 下限はゼロです。 
2. 関数を定義する`count(x)`合計が以下の部分配列の数を返します。$x$。 この機能はソリューションの中核です。 
3. コンピューティング`count(x)`2 つのポインターを使用します。 スライディングウィンドウを維持する$[l, r]$とその合計。 右端ごとに$r$、合計を増やします。 合計額を超える場合$x$、 動く$l$合計が再び有効になるまで前進します。 それぞれのポジションで$r$、で終わるすべてのサブ配列$r$そして、次の任意のインデックスから開始します。$[l, r]$有効である、貢献している$r - l + 1$サブアレイ。 これが機能するのは、すべての数値が負ではないため、ウィンドウを縮小しても合計が増加することはありません。 
4. 各クエリについて$k$、値の範囲に対して二分探索を実行します。$[0, S]$。 それぞれの中間点で$mid$、計算する`count(mid)`。 少なくともそれであれば$k$、左に移動できます。 それ以外の場合は、右に進みます。 
5. 最終的なバイナリ検索結果は、少なくとも$k$部分配列の合計はそれ以下です。これはまさに$k$- 番目に小さい部分配列の合計。 

### なぜ効果があるのか

 正確さは、述語「合計 ≤ x の部分配列の数」の単調性によって決まります。 として$x$増加しても、以前に有効だったサブ配列はすべて有効のままであるため、このカウントは減少しません。 これにより、応答空間に対して二分探索が有効になります。 

内部`count(x)`、正確さは、すべてのステップでウィンドウが不変であるスライディング ウィンドウから得られます。$[l, r]$ウィンドウの合計が ≤ となる最小の左境界です。$x$。 すべての要素が非負であるため、拡張されます。$r$合計を増やすことしかできず、移動します$l$減らすことしかできません。 したがって、次で終わるすべての有効なサブ配列は、$r$まさに、以下の間で始まるものです$l$そして$r$、有効な部分配列が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_subarrays_leq(arr, x):
    n = len(arr)
    l = 0
    s = 0
    res = 0
    for r in range(n):
        s += arr[r]
        while l <= r and s > x:
            s -= arr[l]
            l += 1
        res += (r - l + 1)
    return res

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    q = int(input().strip())
    queries = [int(input().strip()) for _ in range(q)]

    total = sum(arr)

    def kth(k):
        lo, hi = 0, total
        ans = total
        while lo <= hi:
            mid = (lo + hi) // 2
            if count_subarrays_leq(arr, mid) >= k:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    for k in queries:
        print(kth(k))

if __name__ == "__main__":
    solve()
```機能`count_subarrays_leq`引き違い窓のカウンターです。 重要な実装の詳細は次のとおりです。`l`ウィンドウ合計が決して超過しないようにする`x`。 これにより、呼び出しごとの線形的な複雑さが保証されます。 

機能`kth`可能な部分配列の合計に対して二分探索を実行します。 上限は、サブ配列がそれを超えることができないため、安全に合計に設定されます。 

## 実用的な例

 配列を考慮してください$[1, 2, 3]$。 部分配列の合計は次のとおりです。$[1, 3, 6, 2, 5, 3]$、ソートされたものは次のようになります$[1, 2, 3, 3, 5, 6]$。 

のために$k = 4$の場合、答えは 3 であると予想されます。 

### 二分探索トレース$k = 4$| ミッド | カウント(中間) | 決定 |
 | --- | --- | --- |
 | 3 | 5 | 左に行く |
 | 1 | 1 | 右に行きます |
 | 2 | 3 | 右に行きます |
 | 3 (最終候補) | 5 | 有効 |

 count ≥ 4 の最小値は 3 です。 

このトレースは、カウント関数には一意の値ではなくすべての出現が含まれるため、重複合計がどのように自然に処理されるかを示しています。 

ここで考えてみましょう$[0, 0, 1]$。 部分配列の合計は次のとおりです。$[0, 0, 1, 0, 1, 1]$、次のように並べ替えられます$[0, 0, 0, 1, 1, 1]$。 

のために$k = 2$、答えは0です。 

### 二分探索トレース$k = 2$| ミッド | カウント(中間) | 決定 |
 | --- | --- | --- |
 | 1 | 6 | 左に行く |
 | 0 | 3 | 左に行く |
 | 0 | 3 | 停止 |

 このアルゴリズムは、入力にゼロが含まれる場合に一般的な、多くのゼロサム部分配列を正しく処理します。

 ## 特殊なケース

 次のようなすべてゼロの配列の場合$[0, 0, 0]$、すべての部分配列の合計は 0 になります。カウント関数`count(x)`任意の部分配列の完全な数を返します。$x \ge 0$0 が唯一の値であるため、バイナリ検索はすべてのクエリで 0 に正しく収束します。 

次のような厳密に増加する配列の場合$[1, 2, 3]$、部分配列の合計はすべて別個であるか、わずかに重複していますが、やはり単調です。 スライディング ウィンドウは常に必要な場合にのみ縮小し、すべてのサブ配列は 1 回だけカウントされます。`count(x)`これは、各右エンドポイントが有効な開始の連続ブロックに寄与するためです。 

次のような内部ゼロがある場合$[1, 0, 1]$, 1 のような合計は、異なる部分配列から複数回現れます。 このアルゴリズムは構造を区別せず、合計のみを区別するため、重複も自然にカウントに含まれ、ランクベースのクエリの正確性が維持されます。
