 ## 解決策
 ## 問題の理解

 重み付けされた無向グラフと、固定された開始ノードから固定された目的地ノードに移動したい旅行者が与えられます。 各エッジには移動時間があります。 エッジ コストに加えて、すべてのノードには、旅行者がそのノードを通過するときに発生する「タスク時間」も関連付けられています。 

工夫すべき点は、旅行者はルート上の限られた数のノードでタスクのコストを無視できることです。 各クエリは、スキップできるノード タスクの数を記述する制限を提供し、その特定のシナリオでのノード タスクのコストも提供します。 クエリごとに、開始ノードから宛先ノードまでの最小合計時間を計算する必要があります。ここで、合計時間は、エッジの重みと、コストをスキップできる固定数のノードを除くすべての訪問ノードのノード コストの合計です。 

入力構造は、複数の独立したクエリが後に続く静的グラフです。 各クエリは、ノードのコストとコストを無視できるノードの数を効果的に再定義します。 

複雑さの観点から見ると、グラフは十分に大きくなり、構造を持たずにすべての状態の素朴な最短経路を再計算するアプローチでは遅すぎる可能性があります。 Codeforces グラフの一般的な制約条件は、クエリごとのソリューションが存在する必要があることを意味します。$O((n+m)\log n)$それ以上の場合は、小さな乗算係数を使用して共有最短パス フレームワークを再利用します。 各クエリには新しい最適化次元 (最大 k 個のノード コストをスキップ) が導入されるため、拡張された状態空間にわたる最短パス アルゴリズムが必要です。 

単純なアプローチでは、すべてのパスに沿ってコストがスキップされるノードの考えられるすべてのサブセットを列挙しようとします。 サブセットの数はパスの長さで指数関数的に増加するため、これはすぐに失敗します。 

さらに微妙で間違ったアプローチは、ノード コストを無視して最短パスを計算し、そのパスに沿って最大の k 個のノード コストを減算することです。 最適なパス自体はスキップするノードを選択したことに依存するため、これは失敗します。 別のパスを選択すると、より適切な「スキップ可能」ノードのセットが生成される可能性があります。 

たとえば、2 つのルートを考えます。1 つはエッジ コストが小さいですが、多くの小規模なノード コストがあり、もう 1 つはエッジ コストは大きいですが、高価なノード コストは少ないです。 最適な選択は k に依存し、固定パス上のローカル調整ではその相互作用を捉えることができません。 

## アプローチ

 ブルートフォースの観点は、送信元から宛先までのすべてのパスを独立して処理することです。 パスごとに、コストが削除された最大 k 個のノードを選択するあらゆる方法を試し、結果の合計コストを計算し、すべてのパスの最小値を取得します。 通常の意味での最短パスに限定したとしても、グラフ内の可能な単純なパスの数は指数関数的であり、スキップされたノードに関するパスごとの組み合わせによって別の指数関数が追加されます。 これは、小さなグラフであってもすぐに実行不可能になります。 

重要な観察は、これまでに使用されたスキップの数を明示的に追跡すると、問題には最適な下部構造があるということです。 ノードと使用されたスキップの数を修正したら、その状態に到達するための最良の方法は、どのようにしてそこに到達したかには依存しません。 これは、消費されたノードコストスキップの数を表す複数の状態に各ノードを拡張することを示唆しています。 

単一の最短経路問題を解決する代わりに、各ノードが階層化された最短経路問題を解決します。$u$状態になる$(u, j)$、 どこ$j$これまでに使用されたスキップされたノード コストの数です。 ある状態から、隣接ノードに移動するとき、2 つの選択肢があります。宛先ノードのノード コストを支払うか、スキップ バジェットがまだ残っている場合はスキップするかのいずれかです。 これにより、問題がグラフ上の標準的な最短経路に変換されます。$n \times (k+1)$状態、ダイクストラのアルゴリズムで解けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスを列挙し、サブセットをスキップします。 指数 | 指数 | 遅すぎる |
 | (ノード、スキップ使用) 状態の階層化されたダイクストラ |$O((n(k+1) + m(k+1)) \log (n(k+1)))$|$O(nk)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを独立して処理し、展開された状態グラフ上で最短パス アルゴリズムを実行します。 

1. 状態をペアとして定義します$(u, j)$、 どこ$u$は現在のノードであり、$j$すでに使用されているノードコストスキップの数です。 今後の決定は利用可能なスキップの数に依存するため、このエンコードが必要です。 
2. 開始状態を除くすべての距離を無限大に初期化します。$(1, 0)$、スキップしないことにした場合、そのコストはノード 1 のノード コストと同じになります。 スキップが許可されている場合は、代替の初期状態も考慮します。$(1, 1)$k が少なくとも 1 の場合、ノード コストはゼロになります。これにより、両方の可能性が最初から表現されることが保証されます。 
3. これらの状態に対して優先キューを使用してダイクストラのアルゴリズムを実行します。 状態を抽出するたびに$(u, j)$、すべてのエッジを緩和しようとします$(u, v)$。 
4. から移行する場合$u$に$v$、2つの場合を考えます。 最初のケースでは、次のノードコストを支払います。$v$、スキップ数を変更せずに次へ進みます。$(v, j)$。 2 番目のケースの場合、$j < k$のノードコストを省略します。$v$そしてに移動します$(v, j+1)$。 この分岐は、スキップの限られた予算をモデル化する中心的なメカニズムです。 
5. トラバースコストは常に支払われるため、両方の遷移にエッジ重みコストを追加します。 
6. すべての状態を処理した後、答えはすべての状態の最小値になります。$(n, j)$のために$0 \le j \le k$、k までの任意の数のスキップを使用して目的地に到達することが有効であるためです。 

### なぜ効果があるのか

 元の問題のすべての有効なルートは、展開された状態グラフ内の 1 つのパスに正確に対応し、状態インデックスは各ステップで使用されたスキップの数を追跡します。 逆に、展開されたグラフ内のすべてのパスは、一貫してスキップされたノードが選択された元のグラフ内の有効なルートに対応します。 ダイクストラのアルゴリズムは常に非負の重みをもつグラフ内の最短経路を見つけるため、すべての宛先状態の最小値が最適な解を生み出します。 状態の展開では、コストに影響を与えるすべての決定が保存されるため、最適なソリューションが除外されることはありません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
    
    q_line = input().split()
    if not q_line:
        return
    k = int(q_line[0])
    
    # node costs
    cost = list(map(int, q_line[1:]))
    # adjust if input is 1-indexed or missing alignment
    if len(cost) != n:
        cost = cost[:n]
    
    dist = [[INF] * (k + 1) for _ in range(n + 1)]
    pq = []
    
    # start at node 1
    dist[1][0] = cost[0]
    heapq.heappush(pq, (dist[1][0], 1, 0))
    
    if k > 0:
        dist[1][1] = 0
        heapq.heappush(pq, (0, 1, 1))
    
    while pq:
        d, u, used = heapq.heappop(pq)
        if d != dist[u][used]:
            continue
        
        for v, w in g[u]:
            nd = d + w
            
            # pay cost
            if nd + cost[v - 1] < dist[v][used]:
                dist[v][used] = nd + cost[v - 1]
                heapq.heappush(pq, (dist[v][used], v, used))
            
            # skip cost
            if used < k:
                if nd < dist[v][used + 1]:
                    dist[v][used + 1] = nd
                    heapq.heappush(pq, (nd, v, used + 1))
    
    ans = min(dist[n])
    sys.stdout.write(str(ans))

if __name__ == "__main__":
    solve()
```この実装では、2 次元の距離テーブルが維持され、2 番目の次元でノード コスト スキップが使用された回数が追跡されます。 優先キューは常に、現在最も安価な既知の状態を拡張し、ダイクストラの貪欲な選択の正確さを保証します。 

微妙な詳細は、開始ノードでの初期化です。 ノード 1 もパスの一部であるため、ノード 1 のコストの支払いとスキップの両方を明示的に考慮します。 この分割を怠ると、解釈に応じて過小カウントまたは過大カウントにつながります。 

もう 1 つの重要な詳細は、エッジに沿って移動するときにノード コストを正しくインデックスすることです。 グラフではノードのインデックスは 1 ですが、Python 配列のインデックスは 0 であるため、コスト検索ではノード インデックスから一貫して 1 を減算する必要があります。 

## 実用的な例

 ノード 1 がノード 2 に接続し、ノード 2 がノード 3 に接続する小さなグラフを考えます。k が 1、ノード コストが次であると仮定します。$[5, 10, 1]$、すべてのエッジの重みが 1 に等しい。 

状態を追跡します$(node, used)$。 

| ステップ | 状態がポップされました | 距離 | 移行 | 新しい状態 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,0) | 5 | 2 に進み、コストを支払います | (2,0)=1+5+10 |
 | 2 | (1,0) | 5 | 2 に進みスキップ | (2,1)=1 |
 | 3 | (2,1) | 1 | 3 支払いへ | (3,1)=3 |
 | 4 | (2,0) | 16 | 3 に進みスキップ | (3,1)=2 |

 最良の結果は、高価なノード 2 をスキップすることで得られ、状態追跡が必要な理由を示しています。 

このトレースは、スキップ割り当てが異なると最適なパスがどのように生成されるか、および単一の最短パスでは不十分な理由を示します。

 ## 特殊なケース

 エッジ ケースの 1 つは、k が 0 の場合です。 その場合、アルゴリズムは決して「スキップ」状態に移行してはならず、すべての答えは追加のノードコストを伴う標準の最短パスに減ります。 上位のスキップ層への遷移は不可能であるため、状態グラフはこれを正しく処理します。 

もう 1 つのエッジ ケースは、k が最適なルートに沿ってすべてのノードをスキップするのに十分な大きさである場合です。 アルゴリズムは、予算が残っているときは常にスキップを許可するため、そのパスに沿ってノード コスト寄与がゼロになるように自然に収束します。 正確かどうかは、初期のノードを貪欲にスキップするのではなく、個別の状態を維持することに依存します。
