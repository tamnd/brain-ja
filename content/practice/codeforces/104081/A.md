 ## 問題の理解

 私たちは、それぞれの重みが固定された人々の列と、列の先頭にいる人々を繰り返し比較するゲームを与えられます。 各ラウンドでは、キューの最初の 2 人が競い合います。 重い方がラウンドに勝ちます。 勝者は先頭に留まり、今後のラウンドでも競技を続けますが、敗者は列の最後尾に送られます。 また、連続勝利も追跡します。誰かがラウンドに勝つたびに、その人の現在の連勝数は増加し、参加者のいずれかが必要な連続勝利数に達した時点で、ゲームは直ちに終了し、その参加者が全体の勝者として宣言されます。 

入力により、キューの最初の順序と、ゲームを終了するために必要な連続勝利数が決まります。 出力は、元の順序での最終的な勝者の位置です。 

ソリューションを推進する重要な制約は、直接シミュレートした場合、キューが非常に多くのラウンドにわたって展開される可能性があることです。 各ラウンドは O(1) ですが、最悪の場合、特に有力な候補者がはるか後ろからスタートした場合、勝者が決定する前に大量のスワップと比較が実行される可能性があります。 これにより、長期的な動作を洞察せずにプロセス全体を繰り返しシミュレーションするアプローチは除外されます。 

微妙なエッジケースは、連続勝利の定義から生じます。 すべての参加者に対してストリーク リセットを明示的にシミュレートする必要があるとプロセスを解釈すると、状態が過度に複雑になりやすくなります。 もう 1 つの落とし穴は、勝者がキュー内の初期のランダムな対話に依存する可能性があると想定していることです。 実際には、プロセスには決定論的な支配的な要素があります。 

## アプローチ

 直接シミュレーションは文字通りルールに従います。 キューを維持し、最初の 2 つの要素を繰り返しポップし、それらの重みを比較し、敗者を後方に押し込みます。 また、現在の連勝記録のマップも管理します。 誰かが勝つたびに、その連勝記録は増加し、相手の連勝記録はリセットされます。 ストリークが必要なしきい値に達するとすぐに停止します。 

このアプローチはプロセスを正確に反映しているため、正しいです。 ただし、ひどく劣化する可能性があります。 最も強い人が後方付近からスタートした場合、前方に到達するまでに多くの敵をかわす必要があるかもしれません。 各インタラクションは一定時間ですが、インタラクションの総数は非常に大きくなる可能性があり、このアプローチでは大規模な入力に対して遅すぎる可能性があります。 

重要な観察は、プロセスがグローバルな最大重みによって支配されていることです。 最大値よりも弱い人は決してそれを倒すことはできず、最大値がキューの先頭に到達すると、その後のすべてのラウンドで勝利します。 その瞬間から、必要なしきい値に達するまで、連勝は決定的に増加します。 したがって、プロセス全体は、中間比較の完全なシーケンスではなく、最大要素がいつ先頭に到着するかのみに依存します。 

これにより、初期配列内の最大要素のインデックスを見つける問題が軽減されます。 この要素は、最終的に必要な連続勝利を蓄積することが保証されています。

 | 最大要素の観測 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての比較において必然的に支配的な要素を特定することで問題を解決します。 

1. 元の配列内の最大値とその位置を追跡しながら、重みのリストをスキャンします。 位置は最終的に出力する必要があるものです。 
2. 現在の最大値より大きい値が見つかるたびに、最大値とそのインデックスの両方を更新します。 これにより、世界最強の参加者を常に覚えておくことができます。 
3. スキャンが終了したら、保存されている最大要素のインデックスを答えとして返します。 

### なぜ効果があるのか

このプロセスでは隣接する要素のみが比較されますが、グローバル最大値よりも弱い要素は決して削除できません。 繰り返しのローテーションによって最大値がキューの先頭に到達すると、他の要素はそれを打ち負かすことができないため、勝ちは無限に蓄積されます。 他のすべての参加者は直接比較の連鎖で最終的に負けるはずなので、途切れることのない連勝記録の成長を保証する最初の要素はグローバル最大値です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

max_val = -10**18
max_idx = -1

for i, v in enumerate(a, 1):
    if v > max_val:
        max_val = v
        max_idx = i

print(max_idx)
```この実装では、元の 1 から始まるインデックスの位置を維持しながら、最大値を追跡するだけです。 2 番目のパラメータ`k`最大要素がキューの先頭を支配すると、最終的には必要な連続勝利しきい値に達するため、最終結果には影響しません。 

ここでよくある間違いは、キューのダイナミクスを明示的にシミュレートしようとすることです。 それは不必要な複雑さをもたらし、勝者の身元が最初から固定されているという事実が曖昧になります。 

## 実用的な例

 重みが次のような入力を考えます。`[1, 3, 2, 5, 4]`。 最大値は`5`の位置にあります`4`。 中間の比較に関係なく、他のすべての要素は最終的に負けます。`5`、一度前線で活躍できるようになると勝ち続けます。 

| ステップ | 現在の最大値 | 最大インデックス |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 3 | 2 |
 | 3 | 3 | 2 |
 | 4 | 5 | 4 |
 | 5 | 5 | 4 |

 このトレースは、グローバル最大値のみが重要であり、それ以前のローカル最大値は最終結果に影響を与えないことを示しています。 

別の例として、`[7, 1, 6, 2]`、最大値はすでに前面にあります。 答えはすぐにインデックス`1`、キュー内でのインタラクションがそれを変更することはできません。

このソリューションは、入力に対して単一の線形スキャンを実行するため、制約内に簡単に適合します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    mx = -10**18
    idx = -1
    for i, v in enumerate(a, 1):
        if v > mx:
            mx = v
            idx = i
    return str(idx)

# sample-like checks
assert solve("6 3\n1 1 4 5 1 4\n") == "4"

# minimum size
assert solve("1 10\n5\n") == "1"

# already maximum at front
assert solve("4 2\n9 1 2 3\n") == "1"

# maximum at end
assert solve("4 2\n1 2 3 9\n") == "4"

# all equal
assert solve("5 100\n7 7 7 7 7\n") == "1"

 | --- | --- | --- |
 | 単一要素 | 1 | 最小境界の場合 |
 | フロントの最大値 | 1 | 早期優位性 |
 | 最後の最大値 | n | インデックス作成の正確性 |
 | すべて等しい | 1 | 安定したタイブレーク動作 |
