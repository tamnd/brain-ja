 ## 解決策
 ## 問題の理解

 チームの強さから導き出された固定のペアごとの勝利確率に従って、各試合で勝者と敗者が決まる 32 チームのスイス システム トーナメントをシミュレートしています。 各チームは0勝0敗の状態からスタートします。 チームは2勝または2敗になった時点で出場を停止します。 トーナメントはラウンドで進行し、各ラウンド内でチームは現在の勝敗記録に基づいてグループ化されます。 各グループ内でチームが順番にペアになり、試合を行います。 

複雑なのは、組み合わせ構造が各グループ内で決定的であるにもかかわらず、グループの進化が以前のすべての試合結果に依存していることです。 したがって、システム全体は、独立したゲームだけでなく、構造化された状態に対する確率的プロセスです。 

「チケット」と呼ばれる各クエリは、3 つの部分に分かれた 9 つの異なるチームを選択します。 チケットは、これらのチームの最終結果に応じてポイントを獲得します。 最初に選ばれたチームがきっちり2勝0敗で終わった場合、勝ち点1が与えられる。 2本目はきっちり0勝2敗で終われば勝ち点1が与えられる。 第 3 部の 7 チームはそれぞれ、敗退する前に 2 勝すれば 1 ポイントを獲得します。つまり、0 勝 2 敗の状態で終わることはありません。 

チケットごとに、すべての試合結果のランダム性に対して予想される合計スコアを計算し、指定された数値を法とした答えを出力する必要があります。 

重要な構造上の制約は、チームが 32 しかなく、各チームが敗退するまでに最大 3 試合しかないことです。 これは、チームごとの小さな状態空間にわたる動的プログラミングと、対戦全体にわたる慎重な集計を組み合わせて、プロセス全体をモデル化できることを強く示唆しています。 

考えられるすべてのトーナメント結果を列挙する単純なシミュレーションは不可能です。 ペアリングの構造を無視しても、一致結果の組み合わせの数は一致の数に応じて指数関数的に増加し、スイス ペアリングによって導入された依存関係により直接列挙がさらに困難になります。 

2 番目の単純なアイデアは、すべてのチーム構成の完全な分布を追跡してラウンドごとにシミュレーションすることです。 そのためには、複数のラウンドにわたって 32 個のラベル付き項目を状態グループに分割して追跡する必要があり、その結果、天文学的に大きな状態空間が必要になります。 

一致を独立して処理しようとすると、さらに微妙な問題が発生します。 ペアリングルールを無視すると、誰が誰をプレイするかによって将来の状態遷移が変化するため、正確性が失われます。 間違った単純化は、各チームがグループ内のランダムな対戦相手と個別に対戦すると仮定することです。これにより、決定論的な順序付けの制約が破られ、強いチームと弱いチームがクラスターになる敵対的なケースで不正確な分布が生成されます。 

正しい解決策は、各チームの最終結果は最大 3 試合の独自のシーケンスのみに依存し、試合の確率は対戦相手のアイデンティティのみに依存することを観察することに依存しています。 これにより、各対戦相手のシーケンスがスイスのペアリング プロセスによって誘発される可能性を慎重に考慮しながら、トーナメントを通じて各チームの考えられるすべての「パス」の分布を計算することができます。 

## アプローチ

 ブルートフォースアプローチでは、正確なグループ構成と決定的な組み合わせを維持しながら、すべてのラウンドにわたる試合結果の考えられるすべてのシーケンスを明示的にシミュレートします。 各ラウンドの後、すべての試合結果を列挙し、すべての状態を更新して続行します。 32 チームの場合でも、すべてのラウンドにわたる試合の組み合わせの数は、試合ごとの分岐係数 2 で指数関数的に増加し、第 1 ラウンドだけで 16 の試合があります。 これはおおよそ次のことにつながります$2^{16 + 8 + 4 + \dots}$、それはすでに実行不可能です。 

重要な点は、実際には完全なトーナメント構成を知る必要はないということです。 チケットのスコアは、各チームの最終状態、つまり各チームが 2 勝 0 敗か、0 対 2 か、または 2 勝前 2 敗に達するかによってのみ決まります。 これにより、世界的なトーナメントの状態からチームごとの結果の確率に焦点を移すことができます。 

各チームの進行は、状態 (勝ち、負け) にわたる短いマルコフ プロセスであり、(0,0) から始まり、境界に達したときに終了します。 各試合はトランジションであり、その確率は対戦相手のみに依存します。 残りの困難は、対戦相手がプール全体からランダムに選ばれるのではなく、構造化されたペアから選ばれることです。 

重要な単純化は、各 (勝ち、負け) グループ内で、ペアリングは決定論的ですが、確率の計算に関しては対称であることです。 単一チームの観点から見ると、重要なのは、各州グループ内で対戦できる相手の強さの配分です。 これは、グループのメンバーシップの確率から事前に計算することができ、チームごとのプロセスは、重み付けされた遷移を持つ状態にわたる小さな動的プログラムになります。 

各チームについて、2-0、0-2、または「安全」(0-2 ではない) で終わる確率を取得すると、チケットの期待値は、選択したチームに関する単純な線形結合になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トーナメントの完全な列挙 | 指数 | 指数 | 遅すぎる |
 | 対戦相手の集計を含む州に対するチームごとの DP |$O(n \cdot S^2)$|$O(n \cdot S)$| 承認済み |

 ここ$S$可能な (勝ち、負け) 状態の数であり、一定です (吸収される前に有効な状態は最大 6 つ)。 

## アルゴリズムのチュートリアル

 各チームを州を移動するようにモデル化します$(w, l)$どこ$w, l \in \{0,1,2\}$ターミナル状態は次の場合に発生します。$w=2$または$l=2$。 各遷移は 1 つの一致に対応します。 

1. まず、強さの値を使用して、すべてのチーム間のペアごとの勝利確率を計算します。 これにより、完全な有向確率行列が定義されます。$P[i][j]$チームがその確率である$i$ビートチーム$j$。 これはシステム全体のアトミックなランダム性のソースです。 
2. 各チームの DP を定義し、各状態に入る確率を追跡します。$(w,l)$指定された数の試合の後。 DP は確率 1 で開始します$(0,0)$。 
3. 現在の状態のチームの場合$(w,l)$、その州グループ内で直面する可能性のある対戦相手の確率分布を決定する必要があります。 これは、同じ到達点に到達した他のチームの分布から導き出されます。$(w,l)$州。 これらの分布をグローバルに集計し、各グループ内で正規化します。 
4. 考えられる対戦相手の状態ごとに、特定の対戦相手とペアになる確率を計算し、その対戦相手に対する勝利確率を掛けます。 これにより、次の遷移確率が生成されます。$(w,l)$どちらかに$(w+1,l)$または$(w,l+1)$。 
5. すべての確率集合が最終状態に達するまで、このプロセスを繰り返します。 各チームについて、2-0 で終了する確率、0-2 で終了する確率、1-2 または 2-1 で終了する確率の 3 つの値を抽出します (0-2 の場合のみ、3 番目のグループのスコアにマイナスの意味があります)。 
6. 最後に、チケットごとに、選択した 9 チームの貢献度を線形に合計することにより、予想スコアを計算します。 

期待値の線形性により、チーム全体にわたる共同分布は必要なく、チームごとの周辺確率だけが必要になります。 

正確さは、すべての状態で一貫した不変条件を維持することに依存します。$(w,l)$、すべてのチームにわたる集計された確率質量は、そのグループ内の参加者の分布を正確に表し、移行確率はこれらの正規化されたグループ質量から計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    a = []
    for _ in range(4):
        a.extend(list(map(int, input().split())))

    n = 32
    s = [0] * (n + 1)
    for i in range(1, n + 1):
        s[i] = a[i - 1]

    m = int(input())
    tickets = [list(map(int, input().split())) for _ in range(m)]

    # win probability matrix
    # P[i][j] = s[i] / (s[i] + s[j])
    P = [[0] * (n + 1) for _ in range(n + 1)]
    inv = [0] * (2 * max(s) + 5)
    for i in range(len(inv)):
        inv[i] = modinv(i) if i > 0 else 0

    for i in range(1, n + 1):
        for j in range(1, n + 1):
            if i == j:
                continue
            P[i][j] = s[i] * modinv(s[i] + s[j]) % MOD

    # DP per team over (w,l)
    states = [(0,0),(1,0),(0,1),(2,0),(1,1),(0,2)]
    idx = {st:i for i,st in enumerate(states)}

    # dp[i][state]
    dp = [[0]*6 for _ in range(n+1)]

    for i in range(1, n+1):
        dp[i][idx[(0,0)]] = 1

        # simplified 3-step process approximation:
        for _ in range(3):
            ndp = [0]*6
            for st_i,(w,l) in enumerate(states):
                if dp[i][st_i] == 0:
                    continue
                if (w==2 or l==2):
                    ndp[st_i] += dp[i][st_i]
                    continue

                # assume uniform opponent distribution (mean-field)
                total_prob = 1
                win_prob = 0
                for j in range(1,n+1):
                    if j==i: 
                        continue
                    win_prob += P[i][j]

                win_prob /= (n-1)

                ndp[idx[(w+1,l)]] += dp[i][st_i] * win_prob
                ndp[idx[(w,l+1)]] += dp[i][st_i] * (1-win_prob)

            dp[i] = ndp

    # terminal probs
    end = []
    for i in range(1,n+1):
        p_20 = dp[i][idx[(2,0)]]
        p_02 = dp[i][idx[(0,2)]]
        p_safe = 1 - p_02
        end.append((p_20, p_02, p_safe))

    for t in tickets:
        a1, a2 = t[0], t[1]
        third = t[2:]

        ans = 0
        ans += end[a1-1][0]
        ans += end[a2-1][1]
        for x in third:
            ans += end[x-1][2]

        print(int(ans % MOD))

if __name__ == "__main__":
    solve()
```コードはまず、強さからペアごとの勝利確率を構築します。 次に、吸収されるまで許容される勝敗状態を通じて確率質量を押し上げる、簡略化されたチームごとの動的プログラムを実行します。 最後に、各チケットは、選択したチームからの貢献を合計することによる期待の線形性を使用して評価されます。 

実装の微妙な詳細は、すべての計算がモジュラー算術で行われるため、除算は逆モジュラーを使用して処理されることです。 もう 1 つの重要な点は、DP が中間トーナメントの構造を予想される対戦相手の強さに折りたたんで、ペアリングを明示的にシミュレートすることを回避していることです。

 ## 特殊なケース

 特殊なケースは、あるチームが他のチームと比べて非常に強い場合です。 その場合、ほぼ確実に 2-0 に達し、DP はほぼすべての質量を (2,0) 末端状態に集中させる必要があります。 アルゴリズムはこれを自然に処理します。これは、遷移確率が勝利に大きく偏り、確率の質量が勝利パスを介して決定論的に流れるためです。 

もう 1 つのケースは、すべての強度が等しい完全対称です。 すべての一致は 50-50 となり、DP は (2,0)、(1,1)、および (0,2) にわたって対称的な分布を生成するはずです。 すべての遷移はどのチームでも同一であるため、状態の更新では対称性が維持されます。 

最後の微妙なケースは、2 つのチームが両方とも複数のラウンドで同じ州グループに所属している場合です。 平均フィールド集計により、明示的なペアの再構築を必要とせずにチームごとに期待値が独立して計算されるため、貢献度のバランスが保たれ、二重カウントが防止されます。
