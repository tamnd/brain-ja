 ## 解決策
 ## 問題の理解

 次の 2 行のテーブルが与えられます。$n$列間の数値が各セルに含まれています。$1$そして$n$。 各列では、2 つの値をそのままにすることも、それらを交換することもでき、各列は最大 1 回交換できます。 目標は、両方の行を個別に次の順列にできるかどうかを決定することです。$1 \ldots n$はいの場合は、スワップを最小限に抑えながら、どの列がスワップされるかを出力します。 

操作を再解釈する便利な方法は、各列にその数値の配置に関する 2 つの「選択肢」が含まれていることです。 何もしなければコラム$i$貢献する$a_{1,i}$1行目と$a_{2,i}$2行目へ。入れ替えると列$i$貢献する$a_{2,i}$1行目と$a_{1,i}$タスクは、両方の行が順列になるように各列の方向を選択することです。 

制約は大きくなります。$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 テスト ケースごとに線形以上または線形に近いソリューションは合格しません。 これにより、すべてを試すものは除外されます$2^n$テスト ケースごとに構成を交換したり、二次グラフの構築を行ったりすることもできます。 

いくつかの失敗例は見落とされがちです。 

表全体に数字が 2 回以上出現する場合、答えは即座に不可能になります。方向を選択した後でも、各出現を 2 行のうちの 1 つに配置することしかできず、順列には行位置ごとに 1 つの出現が必要であるためです。 

たとえば、次の場合$n=3$:```
1 1 1
2 2 3
```数字 1 は 3 回出現するため、1 行には重複が含まれている必要があります。 どんな戦略も失敗します。 

もう 1 つの微妙なケースは、ローカルな決定は可能であるように見えても、パリティ制約によりグローバルな一貫性が失われる場合です。 例えば：```
1 2
2 1
```これは解決可能ですが、列ごとの貪欲な推論では、両方の行が同時に順列のままであることを保証する必要があります。 

本当の難しさは、各値が、それが表示されるすべての列にわたってどの行に属するかを一貫して決定する必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、列のすべてのサブセットの交換が試行されます。 構成ごとに、結果として得られる両方の行が順列であるかどうかを確認します。 テイクをチェックする$O(n)$、合計は$O(2^n \cdot n)$、でもそれは不可能です$n=30$。 

重要な観察点は、それぞれの値が$x$実現可能な解決策として、テーブル全体にちょうど 2 回出現します。1 回はスワップ前の行 1 または 2 行に、1 回はスワップ後に最後の各行に 1 回出現する必要があります。 したがって、各数値は、その 2 つの出現が行に割り当てられる方法に関する制約を引き起こします。 

各列を二者択一の選択肢 (保持するか交換する) としてモデル化できます。 値が出現するたびに、そのバイナリ変数に制約が課されます。 値が 2 つの位置に出現する場合、その 2 つの位置は、一方が行 1 に、もう一方が行 2 に割り当てられる必要があります。これはまさに、列間の依存関係のグラフにおける制約伝播の問題です。 

各列はブール状態のノードになります。 各値は、それが表示される 2 つの列を接続し、元のテーブルの同じ行に表示されるか異なる行に表示されるかに応じて、「同じ方向」または「反対方向」のいずれかを強制します。 これにより、問題は 2 つの色分け (2 部チェック) とコンポーネントごとの最小反転数のカウントによるグラフの一貫性チェックに集約されます。 

各連結コンポーネント内には、正確に 2 つの有効なカラーリングがあり、スワップを最小限に抑える 1 つを選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | グラフ+2色塗り |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各列をグラフ内のノードとして扱います。ノードの状態は、その列を交換するかどうかを表します。 

それぞれの数字$x$たとえば列内に正確に 2 回出現します$i$そして$j$。 これら 2 つの出現により、列間に制約が作成されます。$i$そして$j$。 

次の 2 つのケースを区別します。 

もし$x$が両方の列の同じ行にある場合、そのうちの 1 つだけを交換すると、両方のコピーが同じ行に移動することになり、これは無効です。 したがって、両方の列のスワップ状態が同じである必要があります。 

もし$x$が 2 つの列にわたって異なる行に表示される場合、2 つの列のうち 1 つだけを交換する必要があります。つまり、それらの状態が異なる必要があります。 

これにより、問題は、各エッジがエンドポイント間の平等または不平等のいずれかを強制するグラフに変わります。 

次に、コンポーネント上の DFS を使用して一貫性を解決します。 

1. 列の隣接リストを作成します。 

各エッジには、等しいか異なる制約タイプが保存されます。 これは、交換の選択肢がどのように関係しなければならないかを示しています。 
2. まだ状態が割り当てられていないすべての列に対して DFS を実行します。 

初期状態、たとえば 0 を割り当てます。 
3. エッジをトラバースしながら、制約に従って隣接する状態を割り当てます。 

エッジが等しい必要がある場合は、同じ値を伝播します。 不等号が必要な場合は、反転してください。 

このステップにより、すべての制約がローカルで満たされることが保証されます。 
4. ノードが 2 つの異なる状態を取る必要があるという競合に遭遇した場合、インスタンスは不可能になります。 

これは、制約における奇数の矛盾サイクルに対応します。 
5. 各接続コンポーネントについて、考えられる両方の初期割り当てに必要なスワップ数を DFS を通じて暗黙的に計算します。 

コンポーネント内のすべての状態を反転すると別の有効な解決策が得られるため、スワップの少ない方向を選択します。 
6. 最終状態が答えとして 1 であるすべての列を収集します。 

これが機能する理由は、すべての値が 2 つの列間に 1 つのバイナリ制約を正確に定義しているという事実に帰着します。 最終的な割り当ては、このようなペアごとの制約をすべて同時に満たす必要があり、それらの制約により、実現可能性がパリティ エッジを持つ正確に二部性であるグラフが形成されます。 各接続コンポーネントは独立しており、その中にはグローバル フリップによって異なる 2 つの一貫した割り当てが存在します。そのため、コンポーネントごとにスワップを最小限に抑えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i in range(n):
        pos[a[i]].append((i, 0))
        pos[b[i]].append((i, 1))

    adj = [[] for _ in range(n)]
    # each edge: (neighbor, type)
    # type = 0 means same, 1 means different

    for v in range(1, n + 1):
        if len(pos[v]) != 2:
            print(-1)
            return
        (i1, r1), (i2, r2) = pos[v]
        if r1 == r2:
            adj[i1].append((i2, 0))
            adj[i2].append((i1, 0))
        else:
            adj[i1].append((i2, 1))
            adj[i2].append((i1, 1))

    color = [-1] * n
    ans = []

    for i in range(n):
        if color[i] != -1:
            continue

        stack = [i]
        color[i] = 0
        comp = []

        while stack:
            u = stack.pop()
            comp.append(u)
            for v, t in adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ t
                    stack.append(v)
                else:
                    if color[v] != (color[u] ^ t):
                        print(-1)
                        return

        cnt = sum(color[u] for u in comp)
        # try flip or not
        if cnt > len(comp) - cnt:
            for u in comp:
                color[u] ^= 1

    res = [i + 1 for i in range(n) if color[i] == 1]
    print(len(res))
    if res:
        print(*res)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```構築ステップでは、各値の出現から直接制約を構築します。 各値は 2 つの列を正確に接続し、エッジ タイプは、オカレンスが同じ行に配置されているかどうかに応じて、スワップ状態が一致するか異なるかをエンコードします。 

DFS はバイナリ状態を各列に割り当て、制約を伝播します。 トラバース中に矛盾が発生すると、テスト ケースは直ちに終了します。 

コンポーネント レベルの最適化では、接続されたコンポーネント内のすべての状態を反転すると有効性が維持されるという事実を利用します。 現在の向きで使用されるスワップの数を計算し、その数が減少した場合は反転します。 

## 実用的な例

 小さなケースを考えてみましょう。```
1 2 1
2 3 3
```私たちにはエッジがあります:

 1 は異なる行の列 0 と列 2 を接続するため、制約は等しくありません。 

2 は、異なる行の列 0 と列 1 を接続しており、等しくありません。 

3 は、異なる行の列 1 と列 2 を接続しており、等しくありません。 

DFS をトレースします。 

| ステップ | ノード | 割り当て済み | 理由 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 開始 |
 | 2 | 1 | 1 | エッジ 0-1 の不等式 |
 | 3 | 2 | 1 | エッジ 0-2 の不等号は 1 を強制します |

 すべての制約が満たされています。 コンポーネントの色は [0,1,1] であるため、スワップは列 2 と列 3 になります (解釈に応じて 1 からインデックスが付けられます)。 

これは、すべての制約が一貫したパリティ割り当てにどのように集約されるかを示しています。 

次に、不可能なケースを考えてみましょう。```
1 1
1 1
```各値が 4 回出現し、各値が 2 つの列を正確に接続する必要があるという要件に違反しています。 前処理ステップはそれを即座に拒否します。

 ## 特殊なケース

 主なエッジ ケースは、値が同じ行に 2 回出現する場合です。 その状況では、両方のエンドポイントが同じスワップ状態をとる必要があります。 DFS がすべてのエッジを誤って「異なる」ものとして扱うと、誤って矛盾が強制されてしまいます。 

例えば：```
1 2
1 2
```ここでは、値 1 が行 1 に 2 回表示されます。 その列間の制約は平等です。 DFS は列 0 を 0 として割り当て、列 1 を 0 として伝播し、値 2 についても同様に伝播します。スワップは必要なく、予想される答えと一致します。 

もう 1 つの微妙なケースは、等価エッジと不等価エッジが混在する制約のサイクルです。 サイクル全体のパリティ伝播によって一貫した色が返されるか、矛盾が検出されるため、DFS はこれを自然に処理します。
