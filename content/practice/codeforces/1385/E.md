 ## 解決策
 ## 問題の理解

 すべてのエッジがすでにその端点を知っているグラフが与えられていますが、すべてのエッジが方向を自由に選択できるわけではありません。 一部のエッジはすでに方向が設定されているため、そのままの状態にする必要がありますが、残りのエッジは方向が設定されていないため、任意の向きに設定できます。 タスクは、最終的な有向グラフに有向サイクルが含まれないように、すべての無向エッジに方向を割り当てることです。 

出力は単に「はい/いいえ」の決定ではありません。 可能であれば、結果として得られる有向グラフが非巡回となるように、すでに有向になっているエッジも含めて、すべてのエッジの完全な向きも出力する必要があります。 

制約の構造は、どのような解もグラフのサイズが線形に近くなければならないことをすでに示唆しています。 すべてのテスト ケースにわたって最大 2 · 10^5 の頂点とエッジがあるため、各エッジの割り当て後にサイクルを繰り返しチェックしたり、すべての方向を試したりするなど、二次関数はまったく実行不可能です。 ソリューションは基本的に、テスト ケースごとに 1 つまたはいくつかのグラフ走査を実行する必要があります。 

主な問題点は、有向エッジは頂点間に厳密な順序制約を課すのに対し、無向エッジは柔軟性がありますが、それらの制約に従って一貫して割り当てる必要があることです。 素朴な直観では、最初に有向エッジを無視し、基礎となる無向グラフの位相順序を構築し、それからそれに応じてエッジの方向を設定するかもしれません。 有向エッジが単純な DFS 順序と競合する部分的な順序付けをすでに強制している場合、これはすぐに失敗します。 

たとえば、すでに有向になっている 3 つのノード 1 → 2 → 3 と、3 と 1 の間に無向エッジがあるとします。有向チェーンを無視してトポロジー順序を割り当てようとすると、順序が 3 を 1 の前に置く場合、またはその逆の場合、最終的に矛盾が生じます。 有向エッジは、グローバルに尊重される必要がある厳密な部分順序を定義します。 

したがって、中心的な問題は、非循環性を維持する方法で、固定の有向制約を柔軟な無向エッジとマージする方法です。 

## アプローチ

 強引なアプローチは、すべての無向エッジを 2 つの可能な方向があるものとして扱い、サイクルをチェックしながら方向の割り当てを試みることです。 DFS でバックトラッキングを使用する場合でも、最悪の場合、2^(m0) 個の可能性があります。ここで、m0 は無向エッジの数です。 m が 2・10^5 までの場合、これはまったく不可能です。 

もう 1 つの素朴なアイデアは、有向エッジのみの位相順序を計算し、すべての無向エッジをその順序で前から後へ向けるというものです。 問題は、有向エッジがすべての頂点にわたって完全な順序を定義できない可能性があること、そしてさらに重要なことに、有向エッジはそもそも非巡回ではない可能性があることです。 有向エッジに既にサイクルが含まれている場合、解は存在しないため、これを検出する必要があります。 

重要な観察は、すでに方向付けられているすべてのエッジと一致するトポロジカルな順序付けのみが必要であるということです。 このような順序を取得すると、すべての無向エッジをその順序で前から後へ安全に向けることができます。これにより、後方エッジが出現しないことが保証され、したがってサイクルが作成されなくなります。 

これにより、問題は、有向部分グラフが非巡回かどうかをチェックし、非巡回であれば、それに対して位相順序を構築することに帰着します。 その後、順序付けフェーズでは無向エッジを無視し、その後でのみ方向を割り当てます。 

唯一の微妙な点は、有向エッジだけではトラバーサルによってすべてのノードに到達できない可能性があるため、トポロジー ソートにすべての頂点を含める必要があることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 有向グラフの位相ソート + 無向エッジの方向 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 有向エッジのみを使用してグラフを構築し、隣接リストとして保存し、次数も追跡します。 このグラフは固定制約を表します。 
2. この有向グラフに対してトポロジカル ソート (カーンのアルゴリズム) を実行します。 度数 0 のノードを繰り返し選択して削除し、頂点の順序を生成します。 
3. すべての頂点を位相順序に含めることができない場合、有向辺に循環が含まれることになり、要件を満たすことができなくなります。 即座にNOを出力します。 その理由は、固定エッジによって形成されたサイクルは、無向エッジの向きを変えても破ることができないためです。 
4. トポロジー順序の取得に成功したら、この順序での位置に基づいて各頂点にランクを割り当てます。 
5. すべてのエッジを処理します。 すべての有向エッジについて、変更しないままにします。 すべての無向エッジ (u、v) について、それらのランクを比較します。 ランク[u] < ランク[v]の場合は u → v に指示し、それ以外の場合は v → u に指示します。 
6. 最終的な有向枝リストを出力します。 

ステップ 5 が機能する理由は、トポロジー的順序により、すべての有向エッジがその順序で前方に進むことが保証されるためです。 したがって、この順序に従って無向エッジの方向を一貫して設定すると、確実に前方に進むようになります。 

### なぜ効果があるのか

 トポロジカルな順序は、すでに方向付けられたエッジによって課されるすべての制約の線形拡張です。 元のグラフ内の有向パスは、厳密にこの順序で増加する必要があります。 すべての無向エッジは、これと同じ順序を尊重するように配向されているため、最終グラフ内のすべてのエッジは、下位ランクの頂点から上位ランクの頂点に進みます。 有向サイクルでは、最終的に開始ノードに戻る厳密に増加するランクのシーケンスが必要ですが、これは不可能です。 

したがって、構築されたグラフは非周期的であり、固定有向辺に周期が存在する場合は、ステップ 3 で正しく検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        
        adj = [[] for _ in range(n + 1)]
        indeg = [0] * (n + 1)
        edges = []
        
        for i in range(m):
            tpe, x, y = map(int, input().split())
            edges.append((tpe, x, y))
            if tpe == 1:
                adj[x].append(y)
                indeg[y] += 1
        
        q = deque([i for i in range(1, n + 1) if indeg[i] == 0])
        topo = []
        
        while q:
            u = q.popleft()
            topo.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)
        
        if len(topo) != n:
            out.append("NO")
            continue
        
        pos = [0] * (n + 1)
        for i, v in enumerate(topo):
            pos[v] = i
        
        res = []
        for tpe, x, y in edges:
            if tpe == 1:
                res.append((x, y))
            else:
                if pos[x] < pos[y]:
                    res.append((x, y))
                else:
                    res.append((y, x))
        
        out.append("YES")
        for x, y in res:
            out.append(f"{x} {y}")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```有向エッジは、制約グラフを構築するために最初に分離されます。 カーンのアルゴリズム セクションは、有効な線形順序を構築するか、キューが早期に空になった場合のサイクルを検出します。 

位置配列は、無向エッジの端点間の比較が O(1) になるように最終的な順序をエンコードします。 これにより、エッジ処理中の順序付けロジックの再計算が回避されます。 

最後のループでは、有向エッジを保持し、計算された順序に従って厳密に無向エッジの方向を設定し、すべての制約との一貫性を確保します。 

## 実用的な例

 有向エッジが明確なチェーンを強制し、無向エッジがそれに従う必要がある小さなグラフを考えてみましょう。 

入力：```
1
3 3
1 1 2
1 2 3
0 3 1
```有向グラフ 1 → 2 → 3 を構築します。カーンのアルゴリズムは、topo = [1, 2, 3] を生成します。 

| ステップ | キュー | ポップ | トポ | 角度変化 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [1] | - | [] | 2:1、3:1 |
 | 1 | [2] | 1 | [1] | 2:0 |
 | 2 | [3] | 2 | [1,2] | 3:0 |
 | 3 | [] | 3 | [1,2,3] | - |

 pos[1] < pos[3] なので、3 → 1 の向きは、ルールに応じて 3 → 1 または 1 → 3 になります。 1 は 3 の前にあるため、1 → 3 を代入します。 

出力エッジは次のようになります。```
1 2
2 3
1 3
```これは、すべてのエッジが順番に前進し、サイクルが作成されないことを示しています。 

サイクル検出がトリガーされる 2 番目の例:

 入力:```
1
3 3
1 1 2
1 2 3
1 3 1
```カーンのアルゴリズムはすべてのノードを処理できません。これは、すべてのノードが最初に次数 1 を持っているため、キューが空であるためです。 トポ リストのサイズは、初期化順序に応じて 0 または 1 ですが、3 ではありません。 

これは、固定制約における有向サイクルによる不可能性を裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点とエッジは、カーンのアルゴリズムで 1 回処理され、最終的な方向パスで 1 回処理されます。 
| スペース | O(n + m) | 隣接リストとエッジ ストレージ |

 ## 特殊なケース

 微妙なケースとしては、グラフに有向エッジがまったくない場合があります。 この状況では、有向サブグラフは空であるため、すべての頂点は次数 0 から始まります。 トポロジカルな順序は、キューの順序によって生成される任意の順列になります。 すべての無向エッジがこの任意の順序で一貫して方向付けられ、サイクルがないことが保証されるため、アルゴリズムは引き続き機能します。 

もう 1 つのケースは、さまざまなコンポーネントが独立した有向制約を持つ、切り離されたグラフです。 カーンのアルゴリズムは、コンポーネントを任意の有効な順序で自然にインターリーブします。 無向エッジは常にグローバルな順序に従って方向付けられるため、コンポーネント間のエッジはコンポーネント間でサイクルを形成できません。 

失敗シナリオは、完全なトポロジー順序を確立する前に、無向エッジの方向を設定しようとすることです。 たとえば、グローバル順序付けを行わずに DFS 中に方向を貪欲に割り当てようとすると、後でサイクルを形成するバックエッジが簡単に作成されます。 グローバルな順序付けでは、最初に完全な線形構造を修正してからローカルな決定を行うことで、これを回避します。
