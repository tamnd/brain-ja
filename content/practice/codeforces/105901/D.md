 ## 解決策
 ## 問題の理解

 非常に長い整数シーケンスが与えられていますが、明示的には提供されていません。 代わりに、同じ値の連続として圧縮形式で与えられます。 実行ごとに、値が示されます。`v`繰り返される`l`回であり、隣接する実行は常に異なる値を持ちます。 すべての実行を展開するとシーケンスが得られます`A`長さの`k`。 

この完全なシーケンスを正確に分割する方法を検討することが求められています。`r`連続した空ではないサブ配列。 分割ごとに、すべての部分配列に合計があり、その合計が偶数であるか奇数であるかによって各部分配列を分類します。 させて`p`合計が奇数の部分配列の数になり、`q`和が偶数になるので、`p + q = r`。 

クエリごとに`r`、最適な分割を 1 つだけ構築するわけではありません。 代わりに、配列を次のように分割する可能なすべての方法を検討します。`r`奇数和セグメントの可能な最大数と、独立して偶数和セグメントの可能な最大数という 2 つの別々の極端な質問をします。 

主な問題点は、配列の長さと拡張された合計サイズの両方が非常に大きくなり、最大で`2 × 10^5`まで実行されます`2 × 10^5`クエリ、展開された合計の長さも潜在的に大きくなる可能性があります。 明示的に配列を構築したり、すべてのパーティション ポイントを試したりする解決策は、直ちに不可能になります。 実行の構造とパリティのみが重要であるという事実は、実際の値が奇数であるか偶数であるかを超えて無関係であることを示唆しています。 

単純なアプローチでは、配列を拡張し、パーティション数を超えてクエリごとに動的プログラミングを使用しますが、単一の DP でさえもオーバーするため、これでは遅すぎます。`k`最悪の場合、クエリごとの値は 2 次になります。 

ランが大きく、値のパリティが頻繁に切り替わる場合、微妙なエッジ ケースが発生します。 たとえば、次のようなシーケンス`1,1,1,2,2,3,3,3`パリティ遷移のみに依存する複数の最適な分割戦略を持つことができ、プレフィックスの合計を注意深く追跡しない限り、実行境界での貪欲な分割は必ずしも十分とは限りません。 

## アプローチ

 強引な解釈では、シーケンスを拡張し、考えられるすべての配置方法を試します。`r-1`間のカット`k-1`ポジション。 結果として得られる分割ごとに、セグメントの合計を計算し、奇数または偶数の数を数えます。 これは本質的に組み合わせ的なものであり、次のように成長します`O(C(k, r))`分割を列挙するだけでなく、各分割コストを計算することもできます。`O(k)`。 これはたとえ`k = 200000`。 

パリティのみが重要であることに気づくと、大幅に単純化できます。 各要素は次のいずれかに寄与します`0`または`1`モジュロ 2。セグメントの要素の XOR が 1 の場合、セグメントの合計は奇数になります。これにより、すべてのセグメントの評価がプレフィックス パリティの差に還元されます。 

ここで問題が発生します。バイナリ配列を切り取っており、各セグメントはそのエンドポイントの XOR によってラベル付けされています。 重要な観察は、奇数セグメントの数は、プレフィックス パリティの反転を生成するカット位置の数にのみ依存するということです。 

これにより、標準的な圧縮が行われます。実行に伴うパリティ構造のみを考慮します。 一連の同一の値の内部では、値が奇数の場合はパリティが予測どおりに切り替わり、値が偶数の場合は安定したままになります。 したがって、各実行は、展開せずに要約できるパリティ変更の構造化されたブロックに寄与します。 

パリティ ランに圧縮し、ラン境界上のプレフィックス パリティを追跡すると、問題は、目的のパリティのセグメントを最大化するために配置できるカットの数を決定することになります。 最適な戦略は実行境界で貪欲になります。パリティがターゲットと一致するセグメントを開始できるたびに開始し、パリティの制約により避けられない「不良」セグメントがどれだけ残っているかを追跡します。 

最終的な解決策は、基本的に、パリティを選択するときに各パリティのセグメントをいくつ強制できるかをカウントすることです。`r`これは、等しいプレフィックス パリティ状態間の遷移が何回存在するかによって決まります。 

主な高速化は、各実行で O(1) の状態遷移が発生し、プレフィックス パリティ構造を前処理した後、各クエリに O(1) で応答できることです。

 ## アルゴリズムのチュートリアル

 1. 合計には奇数/偶数のみが重要であるため、各値をそのパリティで置き換えます。 これにより、配列が各要素が 0 または 1 になるバイナリ シーケンスに変わります。 
2. 概念的には展開された配列に対してプレフィックス パリティを構築しますが、実行に対して直接計算します。 スキャンの実行中は、各実行後に累積パリティを拡張せずに維持します。 偶数の値が連続してもパリティは変わりません。 奇数の値が連続するとパリティが反転します`l mod 2`。 
3. 実行構造を一連の「有効なパリティ フリップ」に変換します。 各ランは、その値が奇数であるか、長さが奇数であるかに応じて、反転するか反転しないかのいずれかに寄与します。 これにより、問題は圧縮されたパリティ遷移シーケンスに帰着します。 
4. この圧縮された構造に対して 2 つの配列を事前計算します。1 つは奇数和セグメントを最大化しようと貪欲に試みた場合に作成できるセグメントの数を記述し、もう 1 つは偶数和セグメント用です。 これは、プレフィックス パリティが目的のセグメント パリティと一致する位置で何回カットできるかを追跡することによって行われます。 
5. 各クエリについて`r`、可能な限り最良のものを計算します`p`できるだけ多くの「良い」カットの機会を利用することで、`r`、構造上の制約によって制限されます。 次に計算します`q = r - p`。 同様に、可能な限り最良の値を計算します`q`対称推論を独立して使用します。 
6. 各クエリに対して両方の値を出力します。 

これが機能する理由は、すべてのセグメントがプレフィックス パリティ配列内のエンドポイント間のパリティの差によって完全に決定されるという不変条件に関係しています。 プレフィックス パリティはシーケンスによって固定されているため、各カットはパリティがターゲットと一致するプレフィックス インデックスを使用するかどうかのみを決定します。 実行圧縮ではすべてのプレフィックス パリティ遷移が正確に保存されるため、最適な分割が失われることはありません。 各セグメントの決定はローカル プレフィックス パリティの可用性にのみ依存し、以前の選択によって、事前計算された構造で既に考慮されている以上に将来の可用性が増加することはないため、貪欲な選択は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix_info(runs):
    # runs: list of (value_parity, length)
    # convert each run into parity flip contribution
    flips = []
    for val, length in runs:
        if val % 2 == 0:
            flips.append(0)
        else:
            flips.append(length % 2)

    # prefix parity after each run boundary
    pref = [0]
    cur = 0
    for f in flips:
        cur ^= f
        pref.append(cur)

    # count how many times each parity occurs at run boundaries
    cnt0 = sum(1 for x in pref if x == 0)
    cnt1 = len(pref) - cnt0
    return cnt0, cnt1

def solve():
    n, m = map(int, input().split())
    runs = []
    for _ in range(n):
        v, l = map(int, input().split())
        runs.append((v, l))

    cnt0, cnt1 = build_prefix_info(runs)

    # In a binary prefix parity array, best number of segments of parity X
    # is bounded by number of prefix positions with that parity minus 1
    max_odd = max(cnt0, cnt1) - 1
    max_even = len(runs) - max_odd

    out = []
    for _ in range(m):
        r = int(input())
        # split r segments between odd and even
        # maximize independently under global cap
        p = min(r, max_odd)
        q = min(r, max_even)
        out.append(f"{p} {q}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、パリティ フリップに寄与するかどうかに各実行を圧縮することから始まります。 パリティを変更できるのは奇数の値の実行のみであり、偶数長の奇数の実行は内部でキャンセルされるため、各実行は単一のバイナリ トグルになります。 実行境界上のプレフィックス パリティ配列は、重要なすべての可能なセグメント エンドポイントをキャプチャします。 

0 または 1 のプレフィックス パリティのカウントにより、奇数または偶数のセグメントを生成できるセグメント エンドポイントの数が決まります。 各セグメントは、パリティ差のある 2 つのプレフィックス インデックスを選択することに対応するため、特定のタイプのセグメントの最大数は、正しいパリティのエンドポイントがいくつ存在するかによって制限されます。 

各クエリはクランプによって回答されます。`r`達成可能な奇数または偶数の最大セグメント数に独立して設定されます。 これは、特定のパリティ クラスの利用可能なエンドポイントをすべて使い果たすと、分割方法に関係なく、そのタイプの追加のセグメントを作成できないという事実を反映しています。 

## 実用的な例

 展開されたシーケンスが含まれるサンプル入力を考えてみましょう。`5, 5, 5, 2, 2, 7`。 

パリティのみを扱うので、次のようになります。`1,1,1,0,0,1`。 

要素に対するプレフィックスパリティ:

 | 私 | 値 | プレフィックスパリティ |
 | --- | --- | --- |
 | 0 | - | 0 |
 | 1 | 1 | 1 |
 | 2 | 1 | 0 |
 | 3 | 1 | 1 |
 | 4 | 0 | 1 |
 | 5 | 0 | 1 |
 | 6 | 1 | 0 |

 のために`r = 2`、最良の奇数セグメント構造は、両方のセグメントが XOR 1 を持つようにプレフィックス パリティを揃えるカットを選択することに対応します。これは構造内で 2 回可能です。 偶数セグメントの場合、プレフィックス パリティが一致するカットを選択し、2 つの偶数セグメントも生成します。 

次に、より単純なケースを考えてみましょう。`A = [1, 2, 3]`、拡張パリティ`[1,0,1]`。 

プレフィックスパリティ:

 | 私 | 接頭辞 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 0 |

 のために`r = 2`、インデックス 1 または 2 で分割できます。1 で分割を選択するとセグメントが得られます。`[1]`そして`[2,3]`パリティ 1 と 1 を使用します。これは、カット位置を選択すると、両方の値がどのように変化するかを示しています。`p`そして`q`プレフィックスパリティの違いを直接介して。 

これらのトレースは、セグメント パリティが要素値自体ではなく、プレフィックス パリティ アラインメントによって完全に制御されていることを確認します。

 ## 特殊なケース

 奇数の値を使用して 1 回実行すると、すべての分割が強制される最小構造をプレフィックス パリティ ロジックが正しく処理するかどうかがテストされます。 要素が 1 つだけあるため、1 つのセグメントに分割すると、値が奇数の場合は 1 つの奇数の合計が生成され、偶数のセグメントは 0 になります。 

次のような全偶数シーケンス`2,2,2,2`パリティ フリップはまったく生成されません。 プレフィックス パリティ配列は一定のままであるため、どのセグメント化でも偶数の合計のみが生成されます。 この場合、アルゴリズムはファントム奇数セグメントを誤ってカウントしてはなりません。 

次のような厳密に交互のパリティ パターン`1,2,1,2,1,2`最大のパリティ変動を生み出します。 ここでは、カット位置ごとにプレフィックス パリティ構造が変更され、アルゴリズムは、遷移を二重にカウントすることなく奇数セグメントと偶数セグメントを構築するために、有効なエンドポイントがいくつ存在するかを正確にカウントする必要があります。 

最後に、ケース`r = k`すべての要素を強制的に個別のセグメントにします。 この状況では、答えは個々の要素のパリティをカウントすることになり、実行圧縮で間違いがあれば、すぐに不正確な合計が生成されます。
