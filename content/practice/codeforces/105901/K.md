 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、複数のカジノと複数の既存のプレーヤーが存在します。 すべてのカジノについて、既存のプレーヤーはそれぞれ、負でない数のサイコロをすでにコミットしています。 私たちは最後のプレイヤーであり、各カジノに配置するサイコロの数を選択する必要があります。 

カジノのすべての選択肢が決まると、ゲームは単純に最大値を選択するわけではありません。 代わりに、フィルタリング ステップが最初に行われます。少なくとも 2 人の異なるプレーヤーに表示されるサイコロ カウント値は、そのカジノの考慮事項から完全に削除されます。 重複したカウントをすべて削除した後、削除されなかった残りの値が比較され、最も高い残りの数値を持つプレーヤーがそのカジノに勝ちます。 重複を削除した後に何も残らない場合、そのカジノは勝者を生み出しません。 

私たちの決定は、カジノごとに 1 つの値のベクトルです。 カジノごとに、10^9 までの任意の非負の整数を選択できます。 すべてのカジノが独立して評価された後、各プレーヤーは勝利したカジノの数を持ちます。 私たちの目標は、勝利するカジノの数を最大化することですが、既存のすべてのプレーヤーに対してタイブレーク ルールが適用されます。つまり、私たちの勝利数は、少なくとも他のすべてのプレーヤーの勝利数と同じでなければなりません。 このような有効な戦略の中で、配置するサイコロの総数を最小限に抑えたいと考えています。 

重要な構造的事実は、プレーヤー間の勝利数に対するグローバルな制約を除いて、各カジノが独立しているということです。 出力は単に選択したサイコロの値の配列です。 

制約は小さく、n と m は最大 50 なので、テスト ケースごとに最大 2500 個の値 ai,j になります。 これは、テスト ケースごとに O(nm) または O(nm log m) の推論を行う余裕があるが、n または m の 3 次のものは依然として安全であることを強く示唆しています。 各 Bi は 10^9 まで無制限であるため、カジノごとの選択肢に対する指数関数的な検索は不可能です。 

重複削除ルールを無視すると、微妙な失敗のケースが発生します。 たとえば、カジノでプレーヤーの値が [5、5、4] の場合、5 は両方とも消え、4 だけが残ります。 単純な「最大値を超えるだけ」戦略では 6 を選択しますが、これは不必要であり、生の最大値ではなく、生き残っている最も強い固有値を超えるだけでよいため、全体的には次善の策となる場合があります。 

もう 1 つの微妙な問題は、プレイヤー間の対称性です。勝利はプレイヤーごとにカウントされ、複数のプレイヤーが勝利数を同数にする可能性があります。 私たちの戦略は、最強の敵だけでなく、どの敵よりも劣っていないことを保証する必要があります。 

## アプローチ

 ブルートフォースビューでは、カジノごとに、どのような結果を望むかを決定しようとします。つまり、自分が勝つか、他の人に勝たせるか、勝者がいないかのいずれかで、それに応じて bi を割り当てます。 ただし、重複の削除と最大選択の間の相互作用により、直接の列挙が複雑になります。 カジノごとに目標の勝者を固定したとしても、それを強制する Bi を選択するには慎重な制約が必要です。意図した勝利のためには、そのカジノの最終的に生き残る最大値よりも厳密に大きくする必要があります。あるいは、他の誰かに勝たせたい場合はすべての重要な値を厳密に回避する必要があります。 

重要な観察は、視点を逆転させることです。 biを直接決定するのではなく、単一のカジノで勝つために何が必要かを検討します。 重複を削除した後は、プレイヤー間で一意の値のみが重要になります。 したがって、各カジノで、関連する対戦相手の値は、その行に 1 回だけ出現する ai、j だけになります。 これらの固有の値の中で最大のものは、そのカジノで勝ちたい場合に超えなければならないしきい値です。 重複した値は、選択に関係なく削除されるため、無関係です。 

したがって、各カジノは単純な構造に帰着します。つまり、対戦相手の間で 1 回だけ発生する値のセットを計算します。 そのセットが空の場合、私たち自身で一意の値を導入しない限り誰も勝つことはできませんが、私たちがそれを配置する唯一のプレイヤーであるため、私たちが選択した値はすべて一意になります。 その場合、常に 0 を選択すれば勝つことができます。

一意の対戦相手の値のセットが空でない場合、mx をその最大値とします。 カジノで勝つには、厳密に mx より大きい bi を選択する必要があります。 そのような最小の選択は、mx + 1 です。カジノに勝ちたくない場合は、bi = 0 を選択するだけで十分です。0 は常に安全であるためです。それは複製される (対戦相手が 0 を持っていて 2 番目の 0 を導入する場合) か、何も勝とうとしていない場合は無関係です。 

現在、グローバル制約は、対戦相手ごとの勝利数によってカジノを結合します。 各対戦相手 j について、勝利数が少なくとも、選択の結果 j が勝者となるカジノの数であることを確認する必要があります。 しかし、各カジノの勝者はローカルのしきい値にのみ依存するため、各対戦相手を独立して扱うことができます。つまり、私たちが介入しない限り、特定の対戦相手が唯一の勝者となるすべてのカジノで確実に勝利したいと考えています。 

これは貪欲な調整につながります。カジノごとに、固有の最大値が他のすべての対戦相手の固有の最大値よりも厳密に大きい対戦相手が存在するかどうかを確認します。 そうであれば、私たちが彼らを倒さない限り、その対戦相手が勝つことになります。そして、すべてのプレイヤーにわたって実行可能性を維持する最も安価な方法は、可能な限りそのようなカジノを制御することです。 

n が小さいため、各カジノの候補しきい値を直接計算し、そのカジノで勝つことが有益か、それとも他の人に取られる方が有益かを個別に決定できますが、自分の勝利数がすべてのプレイヤーの最終的な勝利数を上回る必要があるという要件によって制限されます。 最適な構造は最終的に次のようになります。他の場所では補うことができない「クリティカルな」勝利アドバンテージを一部の対戦相手が獲得するすべてのカジノで勝利する必要があり、それらの強制的な勝利の中で最小限の bi = mx + 1 を使用します。 

したがって、最終的な解決策は、カジノごとに固有の値の最大値を計算し、0 または mx+1 を選択することになりますが、この選択により、すべての対戦相手と少なくとも等しい勝利数が得られることが保証されます。 より多くの勝利を選択するとコストが増加するだけであるため、支配制約を満たすために必要な場合を除いて、私たちが自発的にカジノに勝つことは決してありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グローバル シミュレーションによるブルート フォースのカジノごとの割り当て | n の指数 | O(nm) | 遅すぎる |
 | 最適な固有価値の削減 + カジノごとの貪欲な決定 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. カジノごとに、m 人の既存プレーヤーの中で各値が何回出現するかを数えます。 これにより、そのカジノ内でどの値が一意であるかを特定できます。 削除フェーズでは一意の値のみが残るため、この手順が必要です。 
2. カジノごとに、1 回だけ出現するすべての値を収集します。 これらは、フィルタリング ステップ後に既存のプレーヤーの中で勝者を決定できる唯一の値です。 
3. カジノに固有の値がない場合は、bi = 0 を設定します。その理由は、すべての対戦相手の貢献は重複除去後に消滅するため、固有の数値を導入しない限り、既存のプレーヤーは勝利値を主張できないということです。 0 を選択しても、私たちに有利な状況は生まれず、カジノは中立な状態に保たれます。 
4. それ以外の場合は、そのカジノ内の固有の値の最大値である mx を計算します。 これは、生き残った最も強力な対戦相手の貢献を表します。 
5. bi = mx + 1 と設定します。これにより、私たちの値がすべての生き残った対戦相手の値よりも厳密に大きいことが保証されるため、重複を除去した後、私たちがこのカジノの勝者になります。 
6. この構造の下でどのカジノが勝ったかを記録し、すべての対戦相手 j について、彼らが勝ったカジノの数が私たちのカジノの数を超えないことを確認します。 対戦相手が私たちを上回っている場合は、勝利したカジノの可能な限り最小のサブセットを bi = 0 に変えて調整し、mx が最も小さいカジノを優先します。これらのカジノは犠牲にすべき勝利が最も安いためです。 

勝ちを減らすことはその 1 つのカジノにのみ影響し、常に最も制御された方法でコストと勝利数を同時に削減するため、貪欲な調整は安全です。 

### なぜ効果があるのか

重複を除去した後、各カジノは一連の個別の効果的な対戦相手の強さに減ります。 勝者は、このセットの最大値と、導入した値の合計によってのみ決定されます。 したがって、各カジノはしきい値の問題のように動作します。しきい値を下回ったままで負けるか、しきい値を超えて勝つかのどちらかです。 しきい値はカジノ間で独立しているため、実行可能なグローバル ソリューションは、最小の勝利値のみを選択し、それ以外の場合は 0 を選択するソリューションに変換できます。 この変換によりコストが増加することはなく、勝利の関係が維持されるため、必要な勝利の貪欲な選択が最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        res = []
        win_threshold = []

        # compute per-casino threshold
        for i in range(n):
            freq = {}
            for j in range(m):
                v = a[i][j]
                freq[v] = freq.get(v, 0) + 1

            uniq_max = 0
            has_uniq = False

            for v, c in freq.items():
                if c == 1:
                    has_uniq = True
                    if v > uniq_max:
                        uniq_max = v

            if not has_uniq:
                res.append(0)
                win_threshold.append(-1)
            else:
                res.append(uniq_max + 1)
                win_threshold.append(uniq_max)

        # compute opponent wins under this construction
        opp_wins = [0] * m
        my_wins = 0

        for i in range(n):
            if res[i] == 0:
                continue

            freq = {}
            for j in range(m):
                v = a[i][j]
                freq[v] = freq.get(v, 0) + 1

            uniq_max = -1
            for v, c in freq.items():
                if c == 1:
                    uniq_max = max(uniq_max, v)

            # we win this casino if res[i] > uniq_max
            if uniq_max == -1 or res[i] > uniq_max:
                my_wins += 1

        # compute opponents wins
        for i in range(n):
            freq = {}
            for j in range(m):
                v = a[i][j]
                freq[v] = freq.get(v, 0) + 1

            uniq_vals = {v for v, c in freq.items() if c == 1}
            if not uniq_vals:
                continue

            mx = max(uniq_vals)

            # winner is max unique value holder
            for j in range(m):
                if a[i][j] == mx:
                    opp_wins[j] += 1
                    break

        # adjust if needed (greedy reduction of wins)
        for i in range(n):
            if my_wins >= max(opp_wins):
                break
            if res[i] > 0:
                res[i] = 0
                my_wins -= 1

        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各カジノを周波数マップに圧縮して、重複排除後にどの値が生き残るかを検出します。 次に、一意の値が存在するかどうかに応じて、最小勝利値 mx+1 または 0 を割り当てます。 その後、私たちとすべての対戦相手の両方の勝利数を明示的に計算し、最終的に対戦相手が私たちの勝利数を超える可能性がある場合に制御された削減ステップを実行します。 

実装の微妙な詳細は、周波数マップを複数回再計算することです。 n、m ≤ 50 の場合、これは許容可能であり、事前に計算された共有構造を維持するよりもコードが単純になります。 調整段階は、勝ちカジノを負けカジノに変えるだけです。 値を増やす必要がないため、正確さが保たれます。

 ## 特殊なケース

 エッジケースの 1 つは、カジノ内のすべての対戦相手の値が重複する場合です。 [5, 5, 5] のような入力の場合、フィルタリング フェーズ中にすべての値が削除されます。 意味のあるしきい値がないため、アルゴリズムは正しく bi = 0 を割り当てます。 正の値を指定しても唯一の生き残るエントリになりますが、合計を最小化するため、0 が最適です。 

もう 1 つのケースは、一意の値が 1 つだけ存在し、それが非常に大きい場合です。 たとえば、[100000000、100000000、1]。 1 つだけが生き残るので、mx = 1 となり、2 を選択します。単純なアプローチでは、100000000 と誤って比較され、そのスケール付近の値が選択される可能性がありますが、これは不必要です。 

最後の微妙なケースは、複数のカジノが同じしきい値を持っている場合です。 各カジノは独立しているため、最小限の勝利値を選択しても隠れた依存関係が作成されることはありません。 2 つのカジノがどちらも値 10 を超える必要がある場合でも、両方に 11 を割り当てることは安全であり、カジノ間で相互作用することはありません。
