 ## 解決策
 ## 問題の理解

 数値属性のリストが与えられます。各属性は初期値で始まります。 これに加えて、いくつかの制約があります。 各制約は特定の属性インデックスをターゲットにしており、変更後にそのインデックスの値が指定された包含範囲内に収まることを要求します。 

属性値を 1 ずつ増減させることを繰り返して調整することができ、各単位の変更には 1 時間単位のコストがかかります。 タスクは、すべての属性にわたる総コストを最小限に抑えながら、すべての制約が満たされるように初期配列を変更することです。 すべての制約を同時に満たすことが不可能な場合、答えは不可能であると報告する必要があります。 

入力形式から得られる重要な点は、同じ属性インデックスを共有することを除いて、制約が独立しているということです。 つまり、コンストレイントは異なる位置間では相互作用しません。 それらは同じインデックス内でのみ交差します。 

制約の数は少なく、テスト ケースごとに最大 100 個の属性と 100 個の制約があります。 これにより、考えられるすべての最終配列を試したり、値に対してグローバル検索を実行したりするようなことは直ちに除外されます。 最大 10^9 の範囲内のすべての可能な値を反復処理することさえ完全に不可能です。 

すべての制約を繰り返しチェックしながら、各属性を個別に調整しようとする単純なアプローチはまだ許容されますが、ステップバイステップのユニット変更をシミュレートするものは、たとえ最適化されていたとしても概念的に遅すぎます。 

同じインデックスに対する制約が矛盾しているが、明らかに矛盾しているわけではない場合、微妙な失敗ケースが発生します。 たとえば、属性が 1 つの制約に従って [1, 5] に存在し、別の制約に従って [6, 10] に存在する必要がある場合、両方を満たす値はありません。 最後に確認された制約のみを適用する単純なソルバーは、実現可能性を誤って仮定することになります。 

もう 1 つの特殊なケースは、属性に制約がまったくない場合です。 その場合、初期値に関係なく変更されないため、コストには影響しません。 

## アプローチ

 ブルート フォース パースペクティブでは、各インデックスに対して 1 から 10^9 までをスキャンし、それがすべての制約を満たすかどうかを確認するなど、妥当な範囲内で考えられるすべての最終値を試して、各属性値を調整しようとします。 各候補値について、元の値からの距離を計算し、最小の有効な値を選択します。 実現可能性を明示的に検証するため、これは原理的には機能しますが、複雑さが法外になります。 単一の属性であっても、最大 10^9 の値をスキャンすることは不可能であり、これに最大 100 の属性を乗算すると、まったく実行不可能になります。 

構造の簡素化は、固定インデックスに対する制約が、そのインデックスが区間の交点内に存在するように制限するだけであることを認識することで実現します。 多くの候補値を考慮する代わりに、そのインデックスに影響を与えるすべての範囲の交差部分のみが必要になります。 交差が得られると、その属性の問題は、セグメント内の固定数に最も近い点を選択することになります。これは、直線上の標準的な投影問題です。 

これにより、グローバル最適化がインデックスごとの独立した 1 次元問題に変換されます。 実現可能な間隔が判明すると、各属性は独立して総コストに寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 10^9) | お(1) | 遅すぎる |
 | 最適 | O(nq) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 各属性インデックスについては、制限がないと仮定することから始めます。 実行可能な間隔を無限幅として表します。これは、最初は任意の値が許可されることを意味します。 
2. すべての制約を反復します。 各制約 (p、l、r) について、属性 p を [l, r] と交差させることで、その実行可能な間隔を制限します。 これは、下限を max(現在の下限、l) に更新し、上限を min(現在の上限、r) に更新することを意味します。 このステップにより、制約を失うことなくすべての要件を確実に蓄積できます。 
3. すべての制約を処理した後、各属性の間隔を確認します。 いずれかのインデックスの下限が上限よりも大きくなった場合、交差部分は空になり、すべての制約を満たす値はありません。 この場合、答えはすぐに -1 になります。 
4. 間隔が有効な場合、初期値をこの間隔に移動するための最小コストを計算します。 初期値がすでに入っている場合、コストはゼロです。 間隔を下回っている場合は、下限まで移動します。 それを超えている場合は、上限まで下に移動します。 このコストはすべての属性にわたって累積されます。 
5. 最後に、累積コストの合計を出力します。 

中心的な考え方は、各属性を、固定値までの距離を最小にするセグメント内の点を選択することに帰着するということです。 

### なぜ効果があるのか

 各インデックスについて、すべての制約は間隔内のメンバーシップのみを制限し、複数の間隔内のメンバーシップはそれらの交差内のメンバーシップと同等です。 有効な最終値はすべてこの交差の内側に存在する必要があり、その内側のすべての値は制約に関して同様に有効です。 したがって、コストを最小化すると、閉区間上の最近点問題に帰着します。 直線上の距離は凸状であるため、最も近い有効な点は常に元の値 (内側の場合) または間隔境界の 1 つになります。 これにより、属性ごとに独立して最適性が保証され、属性間の独立性により、これらの局所的な最適値を合計すると全体的な最適性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    L = [-INF] * n
    R = [INF] * n

    for _ in range(q):
        p, l, r = map(int, input().split())
        p -= 1
        if l > L[p]:
            L[p] = l
        if r < R[p]:
            R[p] = r

    ok = True
    for i in range(n):
        if L[i] == -INF:
            L[i] = 1
            R[i] = 10**9

        if L[i] > R[i]:
            ok = False
            break

    if not ok:
        print(-1)
        continue

    ans = 0
    for i in range(n):
        if a[i] < L[i]:
            ans += L[i] - a[i]
        elif a[i] > R[i]:
            ans += a[i] - R[i]

    print(ans)
```この実装では、各属性の実行可能な範囲を表す 2 つの配列が維持されます。 これらの範囲を狭くすることで制約が適用されます。 微妙な点は、制約なしで属性を処理することです。 これらは、広い間隔で初期化し、後で未使用のものを完全に許可されたドメインに変換することによって、完全に無料のものとして扱われます。 

交差点の妥当性をチェックする前に距離を計算すると、作業が無駄になったり、不可能なケースが隠蔽されたりする可能性があるため、コストの計算は実現可能性が確認された後に行われます。 

## 実用的な例

 次の 3 つの属性を持つケースを考えてみましょう。 

入力:```
n = 3, q = 3
a = [20, 25, 4]
constraints:
1: (3, 5, 7)
2: (1, 10, 15)
3: (3, 2, 6)
```インデックスごとに間隔を追跡します。 

| インデックス | 初期間隔 | 制約 1 の後 | 制約 2 の後 | 制約 3 の後 | 最終間隔 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [-inf、inf] | 変更なし | [10、15] | 変更なし | [10、15] |
 | 2 | [-inf、inf] | 変更なし | 変更なし | 変更なし | [1、1e9] |
 | 3 | [-inf、inf] | [5、7] | 変更なし | [5、6] | [5、6] |

 次にコストを計算します。 

インデックス 1 の場合、20 は [10, 15] より大きいため、コストは 5 です。 

インデックス 2 の場合、25 は自由範囲内にあり、コストは 0 です。 

インデックス 3、4 の場合、[5、6] より下にあるため、コストは 1 です。 

合計コストは6です。 

このトレースは、制約が間隔に圧縮され、最終的な調整が純粋に幾何学的距離であることを示しています。 

ここで、実現可能性が失敗した場合を考えてみましょう。```
n = 1
a = [10]
constraints: [1, 1, 5], [1, 6, 8]
```| ステップ | 間隔 |
 | --- | --- |
 | 開始 | [-inf、inf] |
 | 最初の後 | [1、5] |
 | 2 番目以降 | [6、5] |

 下限が上限を超えるため、間隔は無効になるため、出力は -1 になります。 これは、矛盾検出が単純な区間交差チェックに帰着することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに O(n + q) | 各制約は 1 つの間隔を 1 回更新し、各インデックスは 1 回処理されます。 
| スペース | O(n) | 2 つの配列には属性ごとの間隔境界が格納されます。 

n と q が両方とも最大 100 で、テスト ケースが最大 100 であることを考えると、これは制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    INF = 10**18

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        L = [-INF] * n
        R = [INF] * n

        for _ in range(q):
            p, l, r = map(int, input().split())
            p -= 1
            L[p] = max(L[p], l)
            R[p] = min(R[p], r)

        ok = True
        for i in range(n):
            if L[i] == -INF:
                L[i], R[i] = 1, 10**9
            if L[i] > R[i]:
                ok = False
                break

        if not ok:
            out.append("-1")
            continue

        ans = 0
        for i in range(n):
            if a[i] < L[i]:
                ans += L[i] - a[i]
            elif a[i] > R[i]:
                ans += a[i] - R[i]

        out.append(str(ans))

    return "\n".join(out)

# minimal feasible
assert run("""1
1 0
10
""") == "0"

# contradiction
assert run("""1
1 2
10
1 1 5
1 6 8
""") == "-1"

# already satisfied
assert run("""1
2 2
5 7
1 1 10
2 6 8
""") == "0"

# needs adjustment both sides
assert run("""1
2 2
0 20
1 5 10
2 0 15
""") == "15"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一属性、制約なし | 0 | 自由変数にはコストがかかりません。 
| 矛盾する制約 | -1 | 実行不可能な交差点の検出 |
 | すでに満たされている間隔 | 0 | 無駄な動きはしない |
 | 混合調整 | 15 | 正しい距離と間隔のロジック |

 ## 特殊なケース

 属性にまったく制約がない場合、アルゴリズムはその属性に完全な有効なドメインを割り当てます。 初期値は常にそのドメイン内にあるため、計算されたコストはゼロのままであり、これは変更を強制する制約がないという事実と一致します。 

同じインデックス上の互いに素な間隔など、制約が矛盾している場合、交差部分は処理中に即座に崩壊します。 このアルゴリズムは、値をシミュレートする必要がなく、純粋に間隔の境界によってこれを検出し、-1 を正しく出力します。 

初期値が最終区間の境界上に正確に位置する場合、厳密に外側にある場合にのみ移動が必要となるため、両方の不等式分岐でコストの追加が回避されます。 これにより、境界が隣接する場合でも、距離の計算でオフバイワンのエラーが発生しないことが保証されます。
