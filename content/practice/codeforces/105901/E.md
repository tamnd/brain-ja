 ## 解決策
 ## 問題の理解

 次のような無向グラフが与えられます。$n$頂点と$m$エッジ。 各エッジには、次のラベルが付いた色を使用して色を割り当てる必要があります。$1$に$m$、色はエッジ全体で再利用できます。 

制限は頂点に対してローカルです: 任意の頂点に対して$u$に付随するすべてのエッジを見ると、$u$の場合、固定色はそれらの入射エッジの中で最大 2 回現れる可能性があります。 したがって、頂点が同じ色に 1 回か 2 回接触することは許可されますが、3 回以上接触することはできません。 

頂点ごとに$u$、 定義する$f_u$入射エッジ間に現れる異なる色の数として。 目標は、すべての頂点にわたるこれらの値の合計が最小になるようにエッジに色を割り当てることです。 

制約は大きく、すべてのテスト ケースにわたる頂点とエッジの合計数は最大です。$2 \cdot 10^5$。 これにより、二次関数は即座に除外されます。$n$または$m$、また、テスト ケースごとに線形または線形に近い構造が必要であることも明確にします。 色ごとに隣接リストを繰り返し処理したり、頂点ごとに大量のブックキーピングを使用して色の割り当てをシミュレートしたりするソリューションは生き残れません。 

微妙な問題は、「頂点ごとにカラーごとに最大 2 つのエッジ」という制約が標準のエッジのカラーリングやマッチングのように動作しないことです。 グローバル構造を持たずにエッジごとに色を割り当てる単純な貪欲なやり方では、各色がローカルで有効であるにもかかわらず、頂点に個別の色があまりにも多く蓄積される状況に陥りやすくなります。 

たとえば、頂点を中心とする星の場合$u$次数 5 で、すべてのエッジに異なる色を割り当てると、次のようになります。$f_u = 5$ただし、この制約により、単一の色で 2 つの入射エッジをカバーできるようにエッジをペアにすることができるため、可能な限り最善の方法は次のとおりです。$f_u = 3$。 センターでの再利用を避ける貪欲な人は、この改善を完全に見逃してしまうでしょう。 

本当の課題は、エッジ間の一貫性を損なうことなく、各頂点ができるだけ「ペアで色を再利用」するように構造を強制することです。 

## アプローチ

 各頂点の下限は制約によってすでに決定されています。 各色は 1 つの頂点に最大 2 回出現できるため、次の場合、$d_u$エッジタッチ$u$、それでは少なくとも$\lceil d_u / 2 \rceil$色が必要になるのは$u$。 これをすべての頂点で合計すると、目的のグローバル下限が得られます。 

そこで問題は、すべての頂点が正確にこの境界を達成するようなエッジ カラーリングを構築できるかということです。 これは、すべての頂点で入射エッジを完全にペアリングし、各ペアが色を共有することを意味します。 

難しいのは一貫性です。 頂点でエッジを任意にペアにする場合、同じエッジが両方の端点のペアに参加し、有効なカラー クラスを形成するには、それらのペアがグローバルに一致する必要があります。 

重要なアイデアは、まず色の観点から考えるのをやめ、代わりにエッジに基づいた構造を構築することです。 エッジを連結コンポーネントにグループ化し、各コンポーネントが後で単一の色になるようにしたいと考えています。 各コンポーネント内では、制約が自動的に満たされるように、すべての頂点の次数は最大 2 でなければなりません。 

これは、エッジをパスとサイクルに分解することを示唆しています。 この分解の各連結コンポーネントがパスまたはサイクルの場合、コンポーネントごとに 1 つの色を割り当てると機能します。どの頂点でも、各コンポーネントは最大 2 つの入射エッジに寄与するため、制約が当てはまります。 

ここでの目標は、各頂点で入射エッジが最適にペアになるようにしながら、そのような分解を構築することになります。 これを強制する標準的な方法は、すべての頂点でエッジをローカルに任意にペアにし、各ペアを 2 つのエッジ間の接続として解釈することです。 これをすべての頂点で実行した後、奇数次数で作成された端点を除き、この「エッジ間」構造では各エッジの次数がちょうど 2 になります。 これにより、エッジを越えて自然にばらばらのトレイルが分割されます。 

結果として得られる各トレイルは、正確に 1 つのカラー クラスです。 すべての頂点は、下限に一致するインシデント ペアと同数のトレイルに属します。$\lceil d_u / 2 \rceil$, したがって、目的は最小化されます。 

各エッジはペアを形成してコンポーネントを抽出する際に一定回数処理されるため、構造は線形になります。

 | エッジごとに貪欲 |$O(m \cdot n)$最悪の場合 |$O(m)$| 遅すぎる / 間違った構造 |
 | ペアリング + トレイルへの分解 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 頂点でのローカルペアリングを使用してエッジが徐々にチェーンに接続される構造を構築し、それらのチェーンをカラークラスとして抽出します。 

1. グラフの隣接リストを保存しますが、まだ使用されていないエッジも追跡します。 

これは、ペアにするときにエッジを徐々に「消費」するため必要です。 
2. 頂点ごとに$u$、入射エッジのリストを取得し、それらを任意にペアにします。最初のエッジと 2 番目のエッジ、3 番目のエッジと 4 番目のエッジなどです。 

このペアリングは、最適性が強制される唯一の場所です。 各頂点は、そのエッジをできるだけ多くのペアにグループ化して、後で各ペアが色を共有できるようにしようとします。 
3. エッジの各ペアについて$(e_1, e_2)$頂点で形成された 2 つのエッジを、ノードが元のエッジである 2 次グラフで接続します。 

このステップでは、問題を頂点ベースの制約から、各エッジ ノードの次数が最大 2 であるエッジ グラフに変換します。 ペアリングにより、各エッジがエンドポイントごとに最大 1 つの接続に参加することが保証されます。 
4. すべての頂点を処理した後、エッジ グラフは互いに素なパスに分解され、エッジ上を循環します。 

各接続コンポーネントは、連続するエッジが頂点ペアを共有する一連のエッジに対応します。 
5. 各コンポーネントを調べて、一意のカラー ID を割り当てます。 

コンポーネントは独立しているため、どのようなラベル付けも有効です。 制約は構造によってすでに保証されています。 
6. オリジナルの各エッジに割り当てられた色を出力します。 

### なぜ効果があるのか

 各頂点$u$は入射エッジのペアに寄与するため、すべてのペアが通過する個別の「エッジ グループ」の数を減らします。$u$。 各グループは、エッジ分解における 1 つの連結成分、つまり 1 つの色に正確に対応します。 

次数の頂点$d_u$正確に形成できる$\lfloor d_u / 2 \rfloor$ペアになり、最大でも 1 つのペアになっていないエッジが残ります。 各ペアはトレイルの一部となり、残ったエッジは追加のエンドポイントを形成します。 したがって、接触するトレイルの数は、$u$まさに$\lceil d_u / 2 \rceil$、これは可能な最小値です。$f_u$。 

各カラー クラスはエッジ上のパスまたはサイクルであるため、どの頂点も同じ色の入射エッジを 2 つ以上持つことができず、制約が自動的に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    edges = []
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        g[u].append((v, i))
        g[v].append((u, i))
    
    used_edge = [False] * m
    adj_edge = [[] for _ in range(m)]
    
    # pair edges at each vertex
    for u in range(n):
        lst = []
        for v, eid in g[u]:
            lst.append(eid)
        
        for i in range(0, len(lst) - 1, 2):
            e1 = lst[i]
            e2 = lst[i + 1]
            adj_edge[e1].append(e2)
            adj_edge[e2].append(e1)
    
    visited_edge = [False] * m
    color = [0] * m
    cur_color = 0
    
    for i in range(m):
        if not visited_edge[i]:
            cur_color += 1
            stack = [i]
            visited_edge[i] = True
            color[i] = cur_color
            
            while stack:
                e = stack.pop()
                for ne in adj_edge[e]:
                    if not visited_edge[ne]:
                        visited_edge[ne] = True
                        color[ne] = cur_color
                        stack.append(ne)
    
    print(*color)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```最初のフェーズでは、ノードがエッジである暗黙的なグラフを構築します。 各頂点は、その入射エッジに対する局所的な完全なマッチングに貢献します。これは、頂点を順番にペアにするだけで実装されます。 2 番目のフェーズでは、このエッジ グラフに対して DFS を実行して接続されたコンポーネントを識別し、各コンポーネントが 1 つの色になります。 

重要な実装の詳細は、「パス」を明示的にシミュレートする必要がないことです。 エッジ間の隣接関係が構築されると、エッジを越える標準的なグラフの走査で十分です。 もう 1 つの微妙な点は、各エッジが最大 2 つのペアリング接続に追加されるため、補助グラフのサイズは線形のままであることです。 

## 実用的な例

 ### 例 1

 三角形のエッジを考えてみましょう。$(1,2), (2,3), (3,1)$。 

各頂点には 2 つの入射エッジがあるため、各頂点はそれらを直接ペアにします。 これにより、3 つのエッジすべてにわたってサイクルが作成されます。 

| ステップ | アクション | エッジ接続 |
 | --- | --- | --- |
 | 1でペアリング | (1,2)-(1,3) | e1 が e2 に接続されました |
 | 2でペアリング | (1,2)-(2,3) | e1 が e3 に接続されました |
 | 3でペアリング | (2,3)-(1,3) | e3 を e2 に接続 |

 すべてのエッジが 1 つのコンポーネントに接続されるため、すべてのエッジが同じ色を受け取ります。 

これは、サイクルが自然に単一のカラー クラスに集約されることを示しています。 

### 例 2

 パスを考えてみましょう。$1 - 2 - 3 - 4$。 

エッジは$e1=(1,2), e2=(2,3), e3=(3,4)$。 

| 頂点 | ペアリング |
 | --- | --- |
 | 1 | なし |
 | 2 | (e1、e2) |
 | 3 | (e2、e3) |
 | 4 | なし |

 これにより、すべてのエッジに単一のチェーンが作成されるため、やはり 1 つの色が使用されます。 

重要な観察は、エッジが異なる頂点でローカルに 2 回ペアになっているにもかかわらず、一貫性により自然に 1 つのトレイルが形成されるということです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    
    def solve():
        n, m = map(int, input().split())
        g = [[] for _ in range(n)]
        edges = []
        for i in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            edges.append((u, v))
            g[u].append(i)
            g[v].append(i)

        adj = [[] for _ in range(m)]
        for u in range(n):
            lst = g[u]
            for i in range(0, len(lst) - 1, 2):
                a, b = lst[i], lst[i + 1]
                adj[a].append(b)
                adj[b].append(a)

        vis = [False] * m
        col = [0] * m
        cid = 0

        for i in range(m):
            if not vis[i]:
                cid += 1
                stack = [i]
                vis[i] = True
                col[i] = cid
                while stack:
                    e = stack.pop()
                    for ne in adj[e]:
                        if not vis[ne]:
                            vis[ne] = True
                            col[ne] = cid
                            stack.append(ne)

        return " ".join(map(str, col))

    return solve()

 ## 特殊なケース

 重要なエッジケースは、頂点の次数が奇数である場合です。 このような状況では、1 つの入射エッジがその頂点でペアになっていないままになります。 そのエッジは他のエンドポイントでのペアリングに引き続き参加しているため、グローバルにトレイルのエンドポイントになります。 これにより、結果のコンポーネントが一貫性を損なうことなく、依然として有効なパスであることが保証されます。 

もう 1 つの特殊なケースは、接続されていないグラフです。 ペアリングは頂点ごとに純粋にローカルで行われるため、コンポーネントは接続されたコンポーネント間で相互作用することはなく、各コンポーネントは独立して有効なトレイルを形成し、特別な処理を行わずに独自の色を受け取ります。 

最後の微妙なケースは、複数の頂点が矛盾しているように見える重複するペアを作成する場合です。 この構築では、エッジが同じ頂点で 2 回ペアになることはなく、エッジ グラフ内の各隣接関係が対称であるため、競合が回避されます。 これにより、エッジ上の DFS では、方向の競合ではなく、一貫した無向構造が常に認識されることが保証されます。
