 ## 解決策
 ## 問題の理解

 木が与えられます$n$すべてのエッジは黒で始まります。 その後、パフォーマンスを行います$n-1$操作。 で$i$- 回目の操作では、特定のエッジが黒から赤に色変更されるため、黒いエッジのセットはツリーに黒いエッジがなくなるまで徐々に縮小します。 

各操作の後、残っている黒いエッジだけを見て、それらによって形成される森を考慮します。 ノードのペア間のすべての単純なパスのうち、それらのパスのうち正確に含まれるものがいくつあるかを数えたいとします。$k$黒いエッジ。 

パスは通常のツリーの意味で定義され、構造は最初はツリーであるため、ノードのすべてのペアは一意の単純なパスを持ちます。 削除後は黒いエッジが森を形成するため、パスは黒と赤の両方のエッジを通過する可能性があります。 私たちは、そのユニークな木道に黒いエッジがいくつあるかに特に興味があります。 

キー出力は動的です。 エッジを削除するたびに、パスが正確に使用するノード ペアの数を再計算する必要があります。$k$まだ黒いエッジ。 

制約は次のとおりです$2 \cdot 10^5$ノード、一方$k \le 10$。 これにより、更新のたびにすべてのペアの距離を再計算するソリューションは即座に除外されます。 すべての距離の 1 回の再計算はすでに行われています。$O(n)$または$O(n \log n)$、そしてそれをしていると$n$回になる$O(n^2)$、これは実現不可能です。 

の小さな値$k$中心的な構造上のヒントです。 有効なソリューションでは、経路長に関する情報を最大 10 までに圧縮し、完全な距離情報を維持することを避ける必要があります。 

微妙な問題は、エッジを削除するとコンポーネントが分割されるという事実から生じます。 エッジが削除されてツリーが切断されると、接続が静かに失敗することを前提とした単純なアプローチです。 たとえば、エッジを削除すると木が 2 つの部分に分割される場合、そのエッジを横切るパスはまったく考慮されなくなりますが、単純な距離ベースの方法では依然としてエッジが正しくカウントされません。 

## アプローチ

 直接シミュレーションでは、現在のフォレストが維持され、削除のたびにすべてのノードから BFS/DFS が実行されて、ブラックエッジ グラフ内の距離が計算されます。 これにより、有効なパスが正しくカウントされますが、次のことが必要です。$O(n^2)$各更新はほぼすべてのノードに影響を与える可能性があるため、最悪の場合でもすべての操作にわたって機能します。 

重要な観察は、エッジの削除を逆に処理する方が簡単であるということです。 完全なツリーから開始してエッジを削除する代わりに、操作を逆方向に処理できます。つまり、空のグラフ (すべてのエッジが赤) から開始し、逆の順序でエッジを 1 つずつ追加します。 すべてのエッジを処理すると、最初の完全なツリーに到達します。 

ここで、タスクはエッジ挿入による動的接続になります。 各ステップで 2 つのコンポーネントがマージされ、現在のフォレスト内の距離が正確に一致するノード ペアの数を更新する必要があります。$k$。 

木の中で、離れたところからペアを数える$k$は古典的なツリー DP 問題です。 コンポーネントが静的な場合、各ノードが深さのヒストグラムを維持するルート DP を使用してすべての距離を計算できます。$k$。 問題は、コンポーネントが時間の経過とともにマージされ、マージのたびに DP を最初から再計算すると時間がかかりすぎることです。 

重要な構造は、$k$とても小さいです。 これにより、接続されたコンポーネントごとに距離のコンパクトな分布を維持し、コンポーネントが結合するときに小さい方のみを再計算することができます。 小規模から大規模への戦略を使用して、各ノードは次のことだけに関与します。$O(\log n)$償却された意味でマージされ、各再計算にはコストのみがかかります$O(k \cdot size)$、これは管理可能な状態を維持します。$k \le 10$。 

このアイデアは、各コンポーネントをルート付きツリーとして維持し、より大きなコンポーネントにマージされるたびにその内部距離 DP を再計算し、常に小さい側を再構築することです。 これにより、大規模な構造の繰り返しの再計算が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 問題を逆に処理し、削除ではなくエッジの追加を扱います。 

1. エッジのないグラフを初期化します。 各ノードは独自のコンポーネントです。 答えは最初は 0 です。 
2. 削除とは逆の順序でエッジを処理します。 2 つのコンポーネント間にエッジを追加するたびに、それらは 1 つのコンポーネントにマージされます。 
3. マージする前に、各コンポーネントの寄与、つまり、距離が正確に一致するコンポーネント内のノードのペアの数を計算します。$k$。 この値はコンポーネントの状態の一部として維持されます。 
4. 2つのコンポーネントの場合$A$そして$B$エッジによってマージされます$(u, v)$、長さの任意の有効なパス$k$完全に内側にあるかのどちらかです$A$、完全に内側$B$、または新しいエッジを 1 回だけ交差します。 コンポーネント間の寄与は、エンドポイントからの距離プロファイルを使用して計算されます。$u$そして$v$。 
5. これを効率的にサポートするために、各コンポーネントは、選択されたルートの DP テーブルを維持します。$r$、ノードごとに保存します$x$各距離にある最大ノード数$k$そのサブツリー内で。 これにより、サブツリーを高速に組み合わせることができます。 
6. 2 つのコンポーネントをマージする場合、小さい方のコンポーネントを大きい方のコンポーネントにアタッチした後、その DP を常に再構築します。 マージされたコンポーネントを一貫したルートに再ルートし、影響を受けるノードのすべての距離テーブルを再計算します。 
7. マージされたコンポーネントを更新した後、答えに対するその内部寄与を再計算し、それに応じてグローバルな答えを更新します。 

逆のプロセスにより、各ステップの答えが生成されます。 出力を反転すると、各削除後に必要なシーケンスが得られます。 

### なぜ効果があるのか

 逆のプロセスのどの時点でも、各コンポーネントは有効なツリーであり、ノードのすべてのペアは完全に 1 つのコンポーネント内にあります。 コンポーネントごとに維持される DP は、距離にあるすべての内部ペアを正確にカウントします。$k$これは、そのコンポーネント内の完全なツリー構造を使用して計算されるためです。 コンポーネント間の寄与は、新しいエッジが 2 つのコンポーネントをマージする場合にのみ導入され、一貫した距離の集計を使用してマージ時に 1 回だけ計算されます。 各マージでは内部 DP の正確性が維持され、すべての新しいクロス パスが考慮されるため、ペアが見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, k = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(n - 1)]
    q = [int(input()) for _ in range(n - 1)]

    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    # adjacency for current reverse graph
    adj = [[] for _ in range(n + 1)]

    # dp[u][d]: number of nodes at distance d from u in its component (recomputed per merge)
    dp = {}

    def build_component(root, comp_nodes):
        # BFS to compute distances within component
        from collections import deque
        dist = {root: 0}
        dq = deque([root])
        order = []

        while dq:
            u = dq.popleft()
            order.append(u)
            for v in adj[u]:
                if v not in dist:
                    dist[v] = dist[u] + 1
                    dq.append(v)

        # tree DP: f[u][d]
        f = {u: [0] * (k + 1) for u in comp_nodes}

        for u in reversed(order):
            f[u][0] = 1
            for v in adj[u]:
                if dist[v] == dist[u] + 1:
                    for d in range(k):
                        f[u][d + 1] += f[v][d]

        # compute internal pairs
        res = 0
        def dfs(u, p):
            nonlocal res
            for v in adj[u]:
                if v == p:
                    continue
                dfs(v, u)
                for d1 in range(k):
                    for d2 in range(k - d1):
                        if d1 + d2 + 1 == k:
                            res += f[v][d1] * (f[u][d2] - f[v][d2 + 1])

        dfs(root, -1)
        return res

    comp_nodes = [{i} for i in range(n + 1)]
    comp_ans = [0] * (n + 1)

    ans = 0
    res = []

    # process edges in reverse
    for i in reversed(range(n - 1)):
        u, v = edges[i]
        u += 1
        v += 1

        ru, rv = find(u), find(v)
        adj[u].append(v)
        adj[v].append(u)

        if ru != rv:
            # merge smaller into larger
            if size[ru] < size[rv]:
                ru, rv = rv, ru

            parent[rv] = ru
            size[ru] += size[rv]

            nodes = list(comp_nodes[ru] | comp_nodes[rv])
            comp_nodes[ru] = set(nodes)

            ans = build_component(u, nodes)

        res.append(ans)

    print("\n".join(map(str, reversed(res))))

if __name__ == "__main__":
    solve()
```この実装は逆プロセスの考え方に従います。つまり、エッジが 1 つずつ追加され、DSU を使用してコンポーネントがマージされます。 各マージの後、影響を受けるコンポーネントは、サブツリー DP を深さまで計算する完全なツリー トラバーサルを使用して再構築されます。$k$、有効なペアの数が再計算されます。 

重要な実装上の選択は、グラフ全体ではなくマージされたコンポーネントのみを再計算することです。 DP は深度で切り詰められます$k$これにより、各再計算が制限されます。 

処理の順序には注意が必要です。回答は逆方向に収集され、最後に元の削除順序と一致するように逆方向に収集されます。

 ## 特殊なケース

 主なエッジケースは、ツリーが単純なパスである場合です。 各マージは 2 つの長いチェーンを接続し、すべての再計算では距離が正確に一致するペアのみを正確にカウントする必要があります。$k$。 各追加では新しく追加されたエッジを横切るパスのみが導入されるため、逆のプロセスにより正確さが保証されます。 

別のケースは、木がスターである場合です。 各マージは 1 つのリーフをアタッチし、そのリーフに関係するすべての有効なパスは 1 回だけカウントされる必要があります。 DP はマージされたコンポーネント全体を再計算するため、複数のマージにわたってパスが二重にカウントされることはありません。 

最後のケースは次のような場合です。$k = 1$。 答えは単純に、現在の黒い森のエッジの数になります。 これは健全性チェックとして機能します。アルゴリズムは各マージ後にエッジのカウントを減らし、マージごとに新しく接続されたペアの答えが 1 つずつ増加します。
