 ## 解決策

 ## 問題の理解

 整数のシーケンスが与えられ、隣接する要素間をカットすることで、それを連続したセグメントに分割することができます。 各セグメントは構造上の制約を満たす必要があります。つまり、セグメント内の偶数値の数は奇数値の数と等しくなければなりません。 

潜在的なすべてのカットには、分割された 2 つの数値の絶対差によって局所的に決定されるコストがあります。 予算が与えられているので、総コストをこの予算内に抑え、結果として得られるすべてのセグメントの妥当性条件を維持しながら、実行するカットの数を最大化したいと考えています。 

重要な制約は、シーケンス全体に同数の偶数と奇数の値がすでに含まれているということであり、これにより、少なくとも 1 つの有効なフルシーケンス セグメンテーションがカットなしで存在することが保証されます。 

境界は小さく、n は最大 100、予算は最大 100 です。これは、二次または三次動的計画法が受け入れられることをすぐに示唆しています。 すべてのセグメンテーションを直接列挙しようとするソリューションは本質的に指数関数的です。これは、n−1 個のギャップがすべてカットされるかカットされないかのどちらかであり、2^(n−1) 個の可能性が生じるためです。 最悪の場合、これは約 10^30 となり、実行可能な計算をはるかに超えています。 

「安く見えたらいつでもカットする」といった単純で貪欲な戦略は失敗します。なぜなら、安価な早期カットはより良い世界的取り決めを妨げる可能性があるからです。 たとえば、少額のコスト削減を行った結果、後でセグメントの平衡を再調整するために高額な削減費用を費やさなければならない場合、その局所的な決定は誤解を招きます。 

もう 1 つの微妙な失敗例は、セグメントのバランスが取れている有効な場所が複数ある場合に発生します。 可能な限り早い段階でのカットを選択すると、全体的によりバランスのとれたセグメントを生み出す、後のカットに必要な予算が無駄になる可能性があります。 

本当の難しさは、カットが独立していないことです。1 つのセグメントがどこで終了するかを決定することで、その後のすべてのセグメントの構造が決まります。 

## アプローチ

 ブルートフォース手法では、n-1 個の可能なカット位置のすべてのサブセットが考慮されます。 サブセットごとに、結果として得られるすべてのセグメントの偶数カウントと奇数カウントが等しいかどうかを確認し、選択したカットの合計コストを計算します。 これは、すべての可能性を明示的に検証するため、正しいです。 

ただし、これには 2^(n−1) 個のサブセットを反復する必要があり、サブセットごとに O(n) でセグメントをスキャンする可能性があるため、合計の複雑さは指数関数的に増加します。 n = 100 であっても、これは完全に不可能です。 

重要な観察は、実際にはすべてのサブセットをグローバルに推論する必要はないということです。 代わりに、配列を左から右に処理し、現在のセグメントで発生した偶数と奇数の数を追跡できます。 セグメントのバランスが取れた瞬間に、カットが許可される候補位置が得られます。 

このようなカット候補のそれぞれの位置で、ここでカットするかスキップするかの選択に直面します。 カットするとコストが消費され、カット数が 1 つ増えますが、スキップするとセグメントを開いたままにし、将来の有効なエンドポイントをマージする可能性があります。 これはまさに古典的な「予算内でカウントを最大化する」動的プログラミングの問題です。 

ポジションと残りの予算によって DP 状態を定義し、すべての有効なカット ポイントを試します。 有効なカットポイントを事前に計算できるため、遷移が管理しやすくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 州を越えたDP | O(n^2・B) | O(n・B) | 承認済み |

 ## アルゴリズムのチュートリアル

1. カットが許可されるすべての位置を事前計算します。 偶数要素と奇数要素の数の差を維持しながら配列をスキャンします。 この差がゼロになると、ここで終わるプレフィックスが有効なセグメント境界を形成することができます。 
2. これらの有効なカット位置を昇順に保存します。 有効なセグメンテーションでは各セグメントがそのようなバランス ポイントで終了する必要があるため、これらの位置でのカットのみを考慮します。 
3. 動的プログラミング テーブル dp[i][b] を定義します。ここで、i はこれまでに検討した有効なカット位置の数を表し、b は残りの予算を表します。 保存される値は、達成可能なカットの最大数です。 
4. カット位置の前ではカットが行われないため、すべての b に対して dp[0][b] = 0 を初期化します。 
5. 有効なカット位置 i ごとに、そこでのカットのコスト、abs(a[pos] - a[pos+1]) を計算します。 このコストは固定されており、他の決定とは独立しています。 
6. 各バジェット値について、遷移を伝播します。i でカットせずに dp[i−1][b] を前方に運ぶか、b が十分な場合はカットして dp[i][b] = max(dp[i][b], dp[i−1][b −cost] + 1) を更新します。 
7. 最終的な答えは、すべての b ≤ B にわたる dp[last][b] の最大値です。 

### なぜ効果があるのか

 重要な不変条件は、dp[i][b] が最初の i 個の有効なカット位置のみを使用し、最大 b 予算を使用して達成可能な最良のカット数を表すということです。 これらの位置のみがバランスのとれたセグメントを保持するため、すべての有効なセグメンテーションはこのセットからカット境界を選択する必要があります。 各状態遷移には固定された有効な境界でのカットが含まれるか除外されるため、構造的に有効なセグメンテーションをすべて冗長性なく列挙し、予算は DP 次元を通じて正確に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, B = map(int, input().split())
    a = list(map(int, input().split()))

    # find valid cut positions (prefix balanced in parity sense)
    valid = []
    diff = 0  # evens - odds

    for i in range(n - 1):
        if a[i] % 2 == 0:
            diff += 1
        else:
            diff -= 1

        if diff == 0:
            cost = abs(a[i] - a[i + 1])
            valid.append(cost)

    # dp[i][b]: using first i cuts, budget b
    m = len(valid)
    dp = [[0] * (B + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        cost = valid[i - 1]
        for b in range(B + 1):
            dp[i][b] = dp[i - 1][b]
            if b >= cost:
                dp[i][b] = max(dp[i][b], dp[i - 1][b - cost] + 1)

    print(max(dp[m]))

if __name__ == "__main__":
    solve()
```この実装では、まず問題をプレフィックスのバランスが取れている候補カット位置のリストに圧縮します。 構造がポジション間の独立性を保証しているため、各候補はそこにカットのコストのみを保存します。 

DP テーブルは、これらの候補に対して行ごとに構築されます。 各ステップで、残りの予算を考慮してスキップするか、または削減を行います。 すべての予算の最終的な最大値は、達成可能な最良のカット数を取得します。 

微妙な点は、有効なプレフィックス境界でのみコストを計算することです。 これにより、パリティ要件を破る違法なカットの考慮が回避され、DP 状態空間が正しいことが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
6 4
1 2 5 10 15 20
```有効なカット位置は、パリティ バランスを追跡することで見つかります。 

| 私 | a[i] | 差分 | バランスがとれた？ | 費用 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | -1 | いいえ | - |
 | 1 | 2 | 0 | はい | 3 |
 | 2 | 5 | -1 | いいえ | - |
 | 3 | 10 | 0 | はい | 5 |
 | 4 | 15 | -1 | いいえ | - |

 したがって、有効なコストは [3, 5] です。 

現在、DP は予算 4 の下でこれらの削減のサブセットを検討しています。最初の削減のみが手頃な価格であるため、結果は 1 になります。 

### 例 2

```ここでは、偶数と奇数のカウントが等しいプレフィックスは存在しないため、有効なカット位置は存在しません。 DP テーブルはずっとゼロのままで、答えは 0 です。 

これは、有効なバランス ポイントが存在しないとすべてのカットが正しく禁止されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、シーケンスが終了前にバランスの取れたプレフィックスを形成しない場合です。 その状況では、有効なリストは空であり、DP は決して遷移しません。 入力用`1 3 5 7`の場合、アルゴリズムは候補を生成しないため、dp は 0 のままで、出力は正しく 0 になります。 

もう 1 つのケースは、バランスのとれたプレフィックスが多数存在するものの、そのコストが予算を超える場合です。 構造的には多くの削減が可能ですが、DP は予算の制約によりそれらを正しく拒否し、無効な過剰カウントが発生しないようにします。
