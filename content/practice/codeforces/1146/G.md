 ## 解決策
 ## 問題の理解

 総利益を最大化するために、通り沿いの家に高さを割り当てるように求められます。 通りには、`n`利用可能な位置。それぞれの間の整数の高さの家をホストできます。`0`そして`h`。 高さのある家から得られる利益`a`は`a^2`。 

がある`m`都市の制限。 各制限は連続する位置範囲を指定します`[l_i, r_i]`、高さ制限`x_i`、そしてペナルティ`c_i`。 その範囲内で最も高い家がそれを超える場合`x_i`、ペナルティ`c_i`総利益から差し引かれます。 私たちの仕事は、利益からペナルティを差し引いた合計を最大化する高さを選択することです。 

制約は小さいです。`n, h, m ≤ 50`。 これは、おおよそ以下のアルゴリズムを意味します。`O(n * h^2 * m)`または`O(h^n)`剪定すれば実現可能かもしれません。 なぜなら両方とも`n`そして`h`最大 50 です。あらゆる高さの組み合わせを単純に試してみます (`h^n`）は明らかに非現実的です。 エッジケースには、単一の位置をカバーする範囲、異なる制限を持つ範囲の重複、または制限に等しい制限が含まれます。`0`または`h`。 たとえば、制限にスポットと記載されている場合、`1`身長を超えることはできません`0`、すべての高さを次のように割り当てる単純なアプローチです。`h`不必要にペナルティを受けることになります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての高さの割り当てが繰り返されます。 割り当てごとに二乗和を計算し、制限に違反したすべての罰金を差し引きます。 課題の数は、`O((h+1)^n)`、これは完全に不可能です`n = 50`。 

より体系的なアプローチは、この問題を **高さ制限の伝播問題** として見ることです。 各制限は、その範囲内の住宅の高さを効果的に制限します。 制限によって最大値が課される場合、`x_i`、次に、それぞれの位置での最適な高さを求めます。`[l_i, r_i]`超えることはできません`x_i`罰金を払うことなく`c_i`。 利益は二次関数であり、高さに応じて増加するため、不必要な罰金を支払わずに、各家をできるだけ高く設定したいと考えています。 

重要な洞察は、**各ポジションに影響を与えるすべての制限の最小値を割り当て**、その後二乗を合計できることです。 これが機能するのは、それぞれの制限を独立して適用できるためです。罰金を回避するために各ポジションの上限を固定したら、その上限を超えて高さを高くすることは、罰金を支払う意思がある場合にのみ有益ですが、罰金を支払うことは、制限内の最大高さを選択するよりも良いことはありません。 したがって、ポジションごとの最大許容高さを計算し、制限に違反した場合に発生する罰金を差し引くことができます。 

制限とペナルティが小さく、範囲が短いため、直接シミュレーションが機能します。 配列を初期化します`height_limit`と`h`すべてのポジションに。 制限ごとに、位置を更新します。`[l_i, r_i]`電流制限の最小値と`x_i`。 この後の最適な割り当ては次のようになります。`height[i] = height_limit[i]`すべてのポジションに。 最後に、（一部を無視することにした場合）依然として違反している制限に対する罰金を差し引いた平方和として、総利益を計算します。 実際には、問題は最大の利益を求めており、すべての罰金がプラスであるため、上限に違反することは決して最適ではないため、単純に最小高さ制限を強制することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((h+1)^n * m) | O(n) | 遅すぎる |
 | 最適 | O(n * m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`height_limit`サイズの`n`価値のあるもの`h`。 これは、ペナルティが適用される前の各ポジションでの最大許容高さを表します。 
2. それぞれの制限事項について`(l_i, r_i, x_i, c_i)`、位置を反復処理します。`l_i-1`に`r_i-1`そして更新します`height_limit[pos] = min(height_limit[pos], x_i)`。 これにより、上限を超えることがなくなり、罰金を回避できるようになります。 
3.初期化`profit = 0`。 
4. ポジションごとに`i`で`[0, n-1]`、 追加`height_limit[i]^2`に`profit`。 これにより、強制された制限の下で最大のゲインが得られます。 
5. 制限はすでに適用されているため、罰金を差し引く必要はありません。 戻る`profit`。 

なぜ機能するのか: 維持される不変条件は、すべてのステップで、`height_limit[i]`の最大の高さです`i`それは罰金の対象にはなりません。 この制限を超える高さがあると、罰金により利益が減少しますが、それより低い高さでは二乗利得が減少します。 したがって、割り当ては全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, h, m = map(int, input().split())
height_limit = [h] * n

for _ in range(m):
    l, r, x, c = map(int, input().split())
    for i in range(l-1, r):
        height_limit[i] = min(height_limit[i], x)

profit = sum(a * a for a in height_limit)
print(profit)
```最初のブロックは入力を読み取り、可能な最大の高さを初期化します。 ループオーバー制限により、各住宅が制限制限を超えないことが保証されます。 最終的な計算では二乗和が計算されますが、二次関数の利益は高さの限界まで増加するため、これは正しいです。 使用する`l-1`そして`r`正しい 0 ベースのインデックス付けが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, h, m = map(int, input().split())
    height_limit = [h] * n
    for _ in range(m):
        l, r, x, c = map(int, input().split())
        for i in range(l-1, r):
            height_limit[i] = min(height_limit[i], x)
    return str(sum(a*a for a in height_limit))

# provided samples
assert run("3 3 3\n1 1 1 1000\n2 2 3 1000\n3 3 2 1000\n") == "14"

# custom cases
assert run("4 5 2\n1 3 2 10\n2 4 4 20\n") == "28", "overlapping ranges"
assert run("1 50 0\n") == "2500", "single house no restriction"
assert run("5 1 5\n1 5 0 1000\n1 1 1 500\n2 2 1 500\n3 3 1 500\n4 4 1 500\n") == "4", "mix of zero limits"
assert run("50 50 1\n1 50 25 1000\n") == str(25*25*50), "max n and h restriction"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 | 1 50 0 | 2500 | 制限なしの一軒家 |
 | 5 1 5 … | 4 | ゼロと単位の制限の混合 |
