 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。`n`ノード、ここでノード`1`根です。 ルート以外の各ノードには親が指定されています。 リーフは子のないノードです。 このタスクは、グループを含む最小サブツリーが他のグループの最小サブツリーと重ならないように、すべてのリーフを空ではないグループに分割することです。 このようなパーティションの総数を 998244353 を法として数えたいとします。 

入力は、ツリーを定義する親リストで構成されます。 各要素`p[i]`そのノードを示します`i+2`の子供です`p[i]`。 ツリーは最大 200,000 ノードになる可能性があるため、二次関数のアルゴリズムはすべて`n`ほぼ確実に遅すぎるでしょう。 これは、パーティションが指数関数的に多く存在する可能性があるため、すべてのリーフ パーティションを総当たりで列挙することは不可能であることを意味します。 したがって、アルゴリズムはツリー構造を利用して、線形または線形に近い時間で可能性を集約する必要があります。 

エッジケースは微妙です。 ツリーにはリーフが 1 つしかない場合があり、その場合は有効なパーティションが 1 つだけ存在します。 ルートがすべての葉に直接接続している星形のツリーでは、ルートの下にある葉のすべての組み合わせによって異なるサブツリー構造が生成されるため、パーティションを慎重にカウントする必要があります。 このような対称構造では、パーティション数をツリー内でボトムアップに慎重に伝播しないと、数え間違いが簡単に発生します。 

## アプローチ

 素朴なアプローチは、リーフのすべてのパーティションを列挙し、各パーティションについて各グループの最小サブツリーを計算し、重複をチェックすることです。 これは原理的には正しいですが、パーティションの数が異なるため、完全に非現実的です。`k`ベルの数に応じて葉が成長します。`k`、超指数関数的です。 のために`k = 20`葉には 5×10^13 を超えるパーティションがあり、処理できる範囲をはるかに超えています。 

重要な洞察は、ツリー上で動的プログラミングを使用して問題をボトムアップで解決することです。 任意のノードを検討してください`v`。 もし`v`は葉であるため、それ自体を含む単一のグループのみを形成できます。 もし`v`が内部ノードである場合、その子は個別のグループを形成することも、親のサブツリー内で重複しないあらゆる方法で結合することもできます。 DP は、ノードごとに、ノード自体が何らかのグループに含まれるか含まれないサブツリー内のリーフを分割する方法の数を保存する必要があります。 これは当然、乗法式に変換されます。内部ノードに複数の子がある場合、そのノードの有効なパーティションの数は、子のサブツリーの積 (子サブツリーを別のグループとして含める方法の数と、このノードで子サブツリーをより大きなグループにマージする方法の数を足したもの) になります。 これをリーフからルートまで再帰的に計算することで、明示的に列挙することなく、すべての有効なパーティションをカバーします。

 ## アルゴリズムのチュートリアル

 1. 親リストからツリーを構築します。 ノードごとに、その子のリストを維持します。 これにより、動的プログラミングでツリーをボトムアップに移動できるようになります。 
2. 再帰関数を定義する`dfs(v)`ノードをルートとするサブツリー内のリーフを分割する方法の数を返します。`v`。 もし`v`単一のリーフは単一のグループしか形成できないため、リーフである場合は 1 を返します。 
3. 内部ノードの場合、各子を反復処理します。`c`そして再帰的に計算します`dfs(c)`。 増殖する稼働中の製品を維持する`(dfs(c) + 1)`それぞれの子供たちにとって。 の`+1`これは、子のリーフを別のグループとして分離せず、効果的に親のグループにマージするオプションを考慮しています。 
4. すべての子に対する積を計算した後、1 を減算して、すべての子が何も結合されないオプション (葉の空のセットに相当します) を除外します。 結果は、ノードの下にあるリーフの有効なパーティションの数になります。`v`。 
5. の結果を返します。`dfs(1)`モジュロ 998244353。 

機能する理由: 各ノードでは、基本的に各子に対して、その葉を独自のグループに形成させるか、親を含むより大きなグループに結合するかを選択します。 乗算原理により、すべての組み合わせがカウントされ、1 を減算すると無効な空の組み合わせが削除されます。 ツリーを 1 回だけ走査し、ノードごとに一定の時間で子の結果を結合するため、アルゴリズムは正確かつ効率的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

MOD = 998244353

def solve():
    n = int(input())
    parents = list(map(int, input().split()))
    tree = [[] for _ in range(n + 1)]
    for i, p in enumerate(parents, start=2):
        tree[p].append(i)

    def dfs(v):
        if not tree[v]:  # leaf
            return 1
        res = 1
        for c in tree[v]:
            res = res * (dfs(c) + 1) % MOD
        return (res - 1) % MOD

    print(dfs(1))

if __name__ == "__main__":
    solve()
```最初の部分では、親配列からツリーの隣接リストを構築します。 の`dfs`この関数はノードがリーフかどうかをチェックし、その場合は 1 を返します。 内部ノードの場合は、乗算します。`(dfs(c) + 1)`すべての子供たちの上に`c`空の組み合わせをカウントしないように、最後に 1 を減算します。 モジュロ演算により、問題の制約が確実に尊重されます。 深いツリーは Python のデフォルトの再帰の深さを超える可能性があるため、再帰の制限を増やします。
