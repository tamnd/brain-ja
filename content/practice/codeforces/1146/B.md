 ## 解決策
 ## 問題の理解

 ボブが非常に特殊な構築プロセスを経て生成した最終的な文字列が与えられます。 ボブはもともと隠し文字列を持っていました`s`。 この文字列から、すべての文字列を削除して 2 番目の文字列を作成しました。`'a'`残りの文字を順番に保ちながら、文字を削除します。 次に、元の文字列を連結しました`s`このフィルタリングされたバージョンを使用して、最終的な文字列を生成します`t`。 

それで`t`は 2 つの部分で構成されています。最初の部分は未知の文字列です。`s`、そして2番目の部分は`s`みんなで`'a'`文字が削除されました。 

タスクは、有効な元の文字列を再構築することです。`s`それは生み出すことができる`t`。 そのような文字列が存在しない場合は、失敗を報告する必要があります。 

制約`|t| ≤ 100000`これは、すべての解が文字列の長さにおいて線形またはほぼ線形でなければならないことを意味します。 すべての分割点を試したり、フィルタリングされた文字列を再計算して各候補を検証したりするような 2 次的な処理は、次のオーダーの処理が必要になる可能性があるため、遅すぎます。$10^{10}$最悪の場合の運用。 

間の分割方法が曖昧であることから、微妙な問題が発生します。`s`そして`s'`決まっている。 分割を誤って推測すると、ルールによって実際には生成できない文字列が受け入れられる可能性があります。 もう 1 つのエッジケースは次のような場合です`s`含まれていません`'a'`全然キャラクター。 その場合`s' = s`、最終的な文字列は次のようになります`t = ss`、完璧な重複です。 多くの単純なソリューションは、この対称性を正しく処理しないために失敗します。 

後半になると別のコーナーケースが現れます。`t`削除によってのみ得られる文字が含まれています`'a'`しかし、前半の構造はその削除パターンと一致しません。 この不一致は、アルゴリズムが検出する必要があるものです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのスプリットポジションを試します。`i`文字列の中で`t`、治療`t[:i]`の候補として`s`連結しているかどうかを確認する`s`と`s`マイナス`'a'`生成する`t`。 分割ごとに、`s'`には O(n) がかかり、サフィックスとの比較にも O(n) がかかり、単純な実装では分割ごとに O(n²) 時間、合計で O(n³) かかります。 と`n = 10^5`、これは不可能です。 

重要な観察点は、次のような構造です。`t`分割が発生する場所を強く制限します。 の第 2 部`t`まさに`s`みんなで`'a'`削除されたため、何も含まれていません`'a'`文字を保持し、他のすべての文字の相対的な順序を保持します。 これは次の接尾辞を意味します`t`含むことはできません`'a'`フィルタリングされたバージョンのプレフィックスと一致する必要があります。 

恣意的に推測するのではなく、構築ロジックを逆にします。 候補プレフィックスを選択するとします`s = t[:i]`。 決定論的に計算できるのは`s'`すべて削除する必要があります`'a'`からのキャラクター`s`、そして、次のことを確認します。`t[i:]`まさにそれと一致します。 接尾辞の長さは非接尾辞の数に依存するため、`'a'`文字の場合、長さが一貫している位置のみを試すことで、正しい分割を見つけることができます。 

これにより、問題は線形スキャンに帰着し、慎重に決定されたいくつかの位置での実現可能性をテストします。

 ## アルゴリズムのチュートリアル

 再構築します`s`可能な分割点を制御された方法で反復することによって。 

1. 非の数を計算します。`'a'`文字列全体の文字`t`。 この値は、フィルタリングされた部分の大きさを決定します。`s'`でなければなりません。 以来`s'`等しい`s`みんなで`'a'`削除された場合、その長さは非`'a'`の文字`s`、また、接尾辞の長さと一致する必要があります。`t`。 
2. しましょう`k`非の数になります`'a'`の文字`t`。 接尾語`s'`まさにそれらで構成されている必要があります`k`文字を順番に並べるので、接尾辞と揃える必要があります。`t`長さの`k`。 
3. 分割候補位置を設定する`i = len(t) - k`。 これにより、次の接尾辞が強制されます。`t`を表すのにちょうど十分な長さです`s'`。 
4.テイク`s = t[:i]`元の文字列の候補として。 
5. 構築する`s'`スキャンすることで`s`そしてすべてを削除します`'a'`。 
6. 生成されたこれを比較します`s'`と`t[i:]`。 一致する場合は返します`s`。 
7. そうしないと、有効な再構成が存在しません。 

正しさは、サフィックスが非依存性によって完全に決定されるという事実から来ます。`'a'`の構造`s`。 非の数を修正したら、`'a'`文字が存在すると分割位置が固定され、曖昧さがなくなります。 

### なぜ効果があるのか

 このアルゴリズムは構造的不変式、つまり接尾辞に依存します。`t`正確に次のシーケンスでなければなりません`t`すべての非から成る`'a'`隠れたキャラクターたち`s`。 の除去のため、`'a'`順序を保持し、1 つの文字タイプのみを削除します。他のすべての文字の相対的な順序は変更されず、完全に保持されます。`s'`。 したがって、有効な解決策はすべて、次の接尾辞を揃える必要があります。`t`非`'a'`接頭辞の投影。 この位置合わせが失敗した場合、分割を変更するとプレフィックスとサフィックスの長さの両方が変更され、必要な等価性が損なわれるため、代替の分割では問題を修正できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = len(t)

    # count non-'a' characters in t
    k = sum(1 for c in t if c != 'a')

    # suffix must be exactly the non-'a' projection
    i = n - k
    if i < 0:
        print(":(")
        return

    s = t[:i]
    expected = []

    for c in s:
        if c != 'a':
            expected.append(c)

    if "".join(expected) == t[i:]:
        print(s)
    else:
        print(":(")

if __name__ == "__main__":
    solve()
```コードはまず、次の文字数を測定します。`t`生き残るだろう`'a'`除去。 それによってサフィックスの長さが決まります。 その後、それに応じて分割ポイントを修正します。 

フィルタリングステップは明示的に再構築します。`s'`候補プレフィックスから抽出し、それをサフィックスと比較します。 これにより、推測が回避され、文字が繰り返される場合や、`s`含まれていません`'a'`。 

唯一のデリケートな点は計算です`i = n - k`。 これが機能するのは、サフィックスには、非すべての文字が正確に含まれている必要があるためです。`'a'`文字数は次のようにグローバルに固定されます。`t`。

 ## 特殊なケース

 エッジケースの 1 つは、文字列全体が次のもので構成されている場合です。`'a'`。 アルゴリズムセット`k = 0`, したがって、分割ポイントは完全な文字列になります。 フィルタリングされたプレフィックスは空であり、サフィックスと一致し、正しい出力が生成されます。 

もう一つのケースは、`'a'`全然キャラクター。 それから`s' = s`、 それで`t`まさにそうでなければなりません`ss`。 アルゴリズムは、プレフィックスとサフィックスの長さが等しいことを要求することでこれを自動的に強制し、文字列が完全に複製された場合にのみ成功します。 

3 番目のケースは、そうでない場合です。`'a'`文字がインターリーブされます`'a'`調整を壊すような形で。 たとえば、サフィックスが単に削除するだけでは取得できない文字のシーケンスを予期している場合、`'a'`どのプレフィックスからでも、再構築されたものを比較すると、等価性チェックはすぐに失敗します。`s'`接尾辞に追加して、誤った受け入れを防ぎます。
