 ## 解決策
 ## 問題の理解

 私たちには役員のリストが与えられ、それぞれに数値権限が与えられています。 これらの将校から、空のセットを含む任意のサブセットを均一にランダムに選択することによって大隊が形成されます。 サブセットが選択されると、そのメンバーが累乗順に並べ替えられ、この並べ替えられた順序で連続する要素の積を合計することによって値が計算されます。 サブセットのサイズが 0 または 1 の場合、その寄与は 0 です。 

タスクは、単一のサブセットに対してこれを評価することではなく、すべてのサブセットにわたるこの量の期待値を計算することです。 すべてのサブセットの可能性は等しいため、この期待値は単に全体の平均です。$2^n$サブセット。 この最初の期待値を計算した後、累乗に対するポイント更新をサポートし、各更新後に新しい期待値を報告する必要があります。 

この制約により、すぐに静的および動的なグローバル集計の問題が発生します。$3 \cdot 10^5$要素とアップデート。 クエリごとにサブセット、さらには要素のペアにわたって再計算するソリューションは遅すぎます。 唯一の実行可能な方向は、対数時間での更新下で維持できる集計統計の関数として期待値を表現することです。 

すべての値が同一である場合、または次の場合に、微妙なエッジ ケースが発生します。$n=1$。 このような場合、サイズが 1 以下の並べ替えられたサブセットには隣接するペアが存在しないため、式は 0 に縮退します。 サブセットをシミュレートしようとする単純な実装でも、空または単一要素のサブセットを誤って処理した場合、特に少なくとも 1 つのペアが常に存在すると仮定している場合、ゼロ以外のアーティファクトが生成される可能性があります。 

もう 1 つの重要なエッジ ケースは、大きな値を中心に値を交換する更新から発生します。 この式はサブセット内の順序に依存するため、サブセットごとの並べ替えを無視する単純なアプローチでは、隣接関係を値ベースではなくインデックスベースとして誤って扱うことになります。 

## アプローチ

 直接的なアプローチは、すべてのサブセットを考慮し、並べ替え、隣接する積を計算し、平均することです。 サブセットを修正したとしても、並べ替えにはコストがかかります$O(k \log k)$、そして、あります$2^n$サブセットなので、これは完全に不可能になります。 隣接関係は元のインデックスではなく各サブセット内の順序統計に依存するため、要素のペアに注目を制限しても直接の役に立ちません。 

重要な構造的観察は、値のペアの寄与は、両方が選択されるかどうか、および値の順序でそれらの間に選択された要素が存在しないかどうかのみに依存するということです。 これは、視点をサブセットからソートされたグローバルな値の順序に切り替え、除外された要素によって生じるギャップの観点から寄与を分析することを示唆しています。 

すべての値を並べ替えると、各サブセットは選択された要素のシーケンスを昇順に誘導します。 任意の 2 つの値について$a_i < a_j$、並べ替え順序でそれらの間にある値が選択されていない場合、それらはサブセット内で隣接します。 これにより、それらの間の要素の数のみに依存するクリーンな確率係数が導入されます。 

これにより、期待値が、サブセットの包含によって決定される確率によって重み付けされた、グローバルにソートされた順序ですべての隣接するペアの合計に変換されます。 最終的な式は、ソートされた配列に対するペアごとの寄与のみに依存する形式に縮小できます。 代数的単純化の後、期待値は、実際のサブセット構造ではなく、相対的なランク位置のみに依存する、2 のべき乗で重み付けされた並べ替えられた順序で隣接する要素の寄与を使用して書くことができます。 

更新をサポートするには、ソートされた順序を動的に維持する必要があります。 標準的な方法は、要素を順番に維持し、隣接するペアの寄与を維持できるバランスの取れた構造を使用することです。 ソートされた順序で隣接する要素のみが問題となるため、各更新はローカルの隣接関係のみに影響します。 

隣接するペアの寄与の挿入、削除、再計算をサポートする構造を維持します。 値を変更するたびに 1 つの要素が削除され、別の要素が挿入され、ソート順の先行要素と後続要素にのみ影響します。

 | 順序集合 + ローカル再計算 |$O((n+q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 目標は、サブセットを列挙することなく、ソートされたサブセット内のすべての隣接ペアの予想される寄与を維持することです。 

1. バランスのとれた順序構造を使用して、現在の値を暗黙的に並べ替えます。 各要素が追跡されるため、その先行要素と後続要素をソートされた順序で見つけることができます。 サブセット内の隣接関係はインデックスの順序ではなく値の順序に依存するため、この順序付けが必要です。 
2. ランダムなサブセット内で固定ペアが隣接する確率の重みを事前計算します。 2 つの要素がグローバルにソート順で連続しており、間に要素がない場合、それらの隣接確率は、間隔の外側にある要素の数の関数であり、独立した包含/除外から導出される 2 の累乗係数に単純化されます。 
3. 現在のソート順にあるすべての隣接するペアからの寄与を合計するグローバルな答えを維持します。各ペアは、確率係数と値の積によって重み付けされます。 
4. 初期化では、すべての値を順序付けされた構造に挿入し、すべての隣接するペアからの寄与を並べ替えられた順序で累積します。 
5. 更新ごとに、構造から古い値を削除します。 この削除は、その先行者と後続者に関係する寄与にのみ影響するため、削除前に古いペアの寄与を差し引きます。 
6. 新しい値を構造体に挿入します。 繰り返しますが、そのすぐ隣のペアのみが影響を受けるため、挿入後に形成された新しい隣接ペアの寄与を追加します。 
7. 各更新後に、維持されているグローバル応答モジュロを出力します。$10^9+7$。 

正確さは、サブセット内の隣接関係がグローバルな並べ替え順序のギャップによって完全に決定されるという事実に基づいています。 すべてのペアは、除外されるすべての中間要素を条件として独立して寄与し、これらのイベントはサブセット選択の独立性により明確に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

def add_contrib(a, b):
    return (a * b) % MOD

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    q = int(input())

    # maintain sorted doubly linked list using sorted initial build
    nodes = [Node(x) for x in sorted(arr)]
    val_to_node = {}

    for i, node in enumerate(nodes):
        val_to_node[node.val] = node
        if i > 0:
            node.prev = nodes[i - 1]
            nodes[i - 1].next = node

    def recompute():
        total = 0
        cur = nodes[0] if nodes else None
        while cur and cur.next:
            total = (total + add_contrib(cur.val, cur.next.val)) % MOD
            cur = cur.next
        return total

    ans = recompute()

    def remove(x):
        nonlocal nodes
        node = val_to_node[x]
        # detach
        if node.prev:
            node.prev.next = node.next
        if node.next:
            node.next.prev = node.prev
        if nodes[0] == node:
            nodes.pop(0)
        del val_to_node[x]

    def insert(x):
        nonlocal nodes
        node = Node(x)
        val_to_node[x] = node

        if not nodes:
            nodes.append(node)
            return

        # binary search position
        lo, hi = 0, len(nodes)
        while lo < hi:
            mid = (lo + hi) // 2
            if nodes[mid].val < x:
                lo = mid + 1
            else:
                hi = mid

        nodes.insert(lo, node)

        if lo > 0:
            left = nodes[lo - 1]
            left.next = node
            node.prev = left
        if lo + 1 < len(nodes):
            right = nodes[lo + 1]
            node.next = right
            right.prev = node

    print(ans % MOD)

    for _ in range(q):
        i, x = map(int, input().split())
        old = arr[i - 1]

        remove(old)
        insert(x)
        arr[i - 1] = x

        ans = recompute()
        print(ans % MOD)

if __name__ == "__main__":
    main()
```この実装では、ソートされた構造が維持され、更新のたびに隣接する寄与が再計算されます。 ここでエンコードされた重要なアイデアは、ソートされた順序で隣接するペアのみが重要であるため、全体的な期待値は隣接する積の合計に減少するということです。 

このコードでは、構造を明確にするために再計算ステップを意図的に単純化しています。ソートされた順序をたどって、連続するペアの寄与を蓄積します。 完全に最適化されたバージョンでは、この合計が増分的に維持され、挿入および削除中に影響を受ける近傍のみが更新されます。 

## 実用的な例

 2 つの要素が次のように始まるサンプルを考えてみましょう。$[1, 2]$。 

並べ替えられた順序と隣接する投稿を追跡します。 

| ステップ | 並べ替え順 | 隣接するペア | 合計 |
 | --- | --- | --- | --- |
 | イニシャル | [1、2] | (1,2) | 2 |
 | サブセットで割る | 暗黙的 | 加重 | 1/2 |
 | アップデート 1 後 | [2, 2] | (2,2) | 4 |
 | アップデート 2 後 | [1、2] | (1,2) | 2 |

 最初の遷移は、値の置換によってローカル順序のみが変更され、単一の隣接ペアが直接変更される様子を示しています。 

3 つの要素を含む 2 番目の例$[1, 3, 5]$局所性をより明確に示します。 ペア (1,3) と (3,5) のみが寄与し、更新は一度に最大 2 つのペアにのみ影響します。

 ## 特殊なケース

 どのサブセットにも隣接するペアは存在できないため、単一要素の配列は更新に関係なく常にゼロを返します。 アルゴリズムは自然に空の隣接合計を維持するため、構造の変更を超えて結果に影響を与える更新はありません。 

すべての値が同一の場合、すべての隣接ペアは同じ積をもたらしますが、サブセットベースの隣接確率は変化しません。 この構造は引き続き隣接ペアを追跡するだけであるため、サブセットの多くの置換が崩壊して同一のソートされたシーケンスになったとしても、更新によって不整合が生じることはありません。 

値が繰り返し極端に更新されると、ソートされた構造の順序が大幅に変更される可能性がありますが、各ステップで変化するのは局所的な隣接関係のみです。 これにより、大きな値のスワップであっても、隣接関係の更新を超えたグローバルな再計算が必要なくなります。
