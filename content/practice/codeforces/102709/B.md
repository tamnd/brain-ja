 ## 解決策
 ## 問題の理解

 この問題は、TA のオフィスアワー中に待機する学生の列について説明しています。 デジャはそこにあることを知っている`n`学生たちは列に並んでいたが、彼女は自分の正確な位置を覚えていない。 彼女が知っているのは少なくともそれだけだ`x`生徒たちは彼女の前に立っていて、せいぜい`y`学生たちが彼女の後に立っています。 タスクは、キュー内でこれら 2 つの条件を満たすことができる位置がいくつあるかをカウントすることです。 

キュー内の位置には 1 つのインデックスが付けられます。 デジャがポジションにいる場合`p`、それから、`p - 1`彼女の前の人たちと`n - p`彼女の後に続く人々。 のすべての値をカウントする必要があります`p`両方の条件が成り立つ場合:`p - 1 >= x`そして`n - p <= y`制約`n <= 1,000,000`入力サイズが十分に大きいため、複雑な条件を繰り返し確認する必要がないことがわかります。 100 万回の演算は小さいため、線形スキャンは既に許容されますが、不等式の構造により、さらに単純な定数時間の解が可能になります。 キューをシミュレートしたり、考えられるすべての配置を生成しようとするアプローチは、必要以上に大きな問題を解決することになります。 

主なエッジ ケースは、キューの終わりに近い位置から発生します。 前方に近いポジションは前にいる生徒が少なすぎるため失敗する可能性があり、後方に近いポジションは後ろにいる生徒が多すぎるために失敗する可能性があります。 

例えば：```
4 2 1
```可能なポジションは 3 と 4 です。ポジション 2 にはデジャの前に生徒が 1 人しかいないため、無効です。 後ろの人数を確認するだけの不用意なソリューションでは、誤って数えてしまう可能性があります。 

別のケースは次のとおりです。```
5 1 4
```2 から 5 までのすべての位置が有効であり、次の出力が得られます。```
4
```デジャの前に誰もいないため、位置 1 は拒否されなければなりません。 後ろの生徒の上限だけをチェックするソリューションでは、最初の位置が誤って含まれてしまいます。 

## アプローチ

 簡単なアプローチは、あらゆる可能なポジションを試してみることです。`1`に`n`。 ポジションごとに`p`、デジャの前に何人いるか、デジャの後に何人いるかを計算します。 両方の値が要件を満たしている場合、答えを増やします。 これが機能するのは、すべての有効な位置が 1 回だけチェックされるためです。 

問題は、これが不必要な作業であることです。 キューには最大 100 万個の位置が含まれる可能性があるため、スキャンはすでに必要以上の作業であり、より複雑なブルートフォース解釈は状況を悪化させるだけです。 2 つの条件は単純な不等式なので、有効な位置の間隔を直接求めることができます。 

最初の条件は次のようになります。`p - 1 >= x`つまり:`p >= x + 1`2 番目の条件は次のようになります。`n - p <= y`つまり:`p >= n - y`どちらの条件もポジションの下限です。 有効な位置は、これら 2 つの下限のうち大きい方から、`n`。 

観察によると、回答はキュー内に分散されていません。 デジャをさらに後方に移動すると、前の人の数が増え、後ろの人の数が減るだけなので、これは 1 つの連続した間隔を形成します。 ポジションが有効になると、その後のポジションもすべて有効になります。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 前方の生徒に関する条件から最も早い位置を計算します。 少なくともあるはずなので、`x`デジャの前の生徒、彼女の立場は少なくとも`x + 1`。 
2. 後ろの生徒に関する条件から、可能な限り早い位置を計算します。 せいぜいあるかもしれないので、`y`彼女の後の生徒にとって、彼女の立場は少なくとも次のとおりである必要があります`n - y`。 
3. これら 2 つの値のうち大きい方を最初の有効な位置とします。 この位置は両方の下限を満たします。 
4. この最初の有効な位置からキューの最後までに残っている位置の数を数えます。 答えは`n - first_valid + 1`。 

なぜ効果があるのか:

 有効な位置は、位置インデックスの下限によってのみ決定されます。 計算された開始点より小さい位置は、少なくとも 1 つの要件に違反します。 それ以上のポジションには、デジャより前に十分な数の生徒がおり、それ以上の生徒はいない`y`彼女の後には学生が続くため、この最後の間隔のすべての位置が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())

    first_valid = max(x + 1, n - y)

    print(n - first_valid + 1)

if __name__ == "__main__":
    solve()
```プログラムは 3 つの値を読み取り、2 つの要件をデジャの位置の境界に変換します。 変数`first_valid`作業可能な最初の位置を保存します。 

の使用`max`が中心的なステップです。 ポジションは両方の制限を満たす必要があるため、2 つの下限のうち厳しい方を満たす必要があります。 

最後の式は位置を包括的にカウントします。 最初の有効な位置が`first_valid`、位置は次のとおりです。`first_valid, first_valid + 1, ..., n`含まれている`n - first_valid + 1`価値観。 の`+1`ここは、1 つ違いの間違いが発生する可能性がある一般的な場所です。

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, x, y = map(int, sys.stdin.readline().split())
    first_valid = max(x + 1, n - y)
    ans = str(n - first_valid + 1)

    sys.stdin = old_stdin
    return ans

# provided samples
assert solve_io("4 2 1\n") == "2", "sample 1"
assert solve_io("6 1 3\n") == "4", "sample 2"

# custom cases

assert solve_io("10 9 9\n") == "1", "only last position works"
assert solve_io("10 1 9\n") == "10", "all positions work"
assert solve_io("1000000 500000 500000\n") == "500001", "large input boundary"

 ## 特殊なケース

 入力の場合:```
4 2 1
```最初の条件では、位置が少なくとも`3`。 2 番目の条件では、位置が少なくとも`3`同じように。 アルゴリズムは位置 3 からカウントを開始し、有効な位置 3 と 4 に一致する 2 を返します。 

入力の場合:```
5 1 4
```最初の条件では、位置が少なくとも`2`。 2 番目の条件は次のようになります。`5 - 4 = 1`, ただし、最初の条件の方が厳しいです。 アルゴリズムは位置 2 を選択し、位置 2、3、4、および 5 をカウントし、正解の 4 を生成します。 

入力の場合:```
2 1 1
```唯一可能な位置は 2 番目の位置です。 アルゴリズムは計算します`max(2, 1)`最初の有効な位置として返されます`2 - 2 + 1 = 1`。 これにより、包括的なカウント式が最小間隔を正しく処理していることが確認されます。
