 ## 解決策
 ## 問題の理解

 この問題は、Zoom 通話中の人々の列について説明しています。 全員が選択した方向を見た後、各人は次のいずれかで表されます。`L`または`R`、スクリーンショットで顔が向いているように見える方向に応じて。 クランプとは、すべてが同じ方向を向いている最大の連続した人々のグループです。 タスクは、最終行にそのようなグループが何個出現するかを数えることです。 

入力すると、人の数とその方向が左から右の順に表示されます。 出力は、文字が一定である連続セグメントの数です。 

到達できる人数は$10^5$これは、解が線形に近い必要があることを意味します。 すべての位置のペアをチェックするか、ラインの大部分を繰り返しスキャンするアプローチでは、次のようなパフォーマンスが得られます。$10^{10}$これは、一般的な競技プログラミングの制限時間よりもはるかに長いものです。 すべての人の方向を隣の人と比較するだけでよいため、ラインを 1 回通過するだけで十分です。 

主なエッジケースは、変更を正しく処理し、個々の人数を誤ってカウントしないことから発生します。 例えば：```
Input
1
L

Output
1
```一人の人は常にちょうど 1 つの塊を形成します。 近隣間の変化が見つかった後にのみカウントを開始するソリューションでは、誤ってゼロを返す可能性があります。 

別のケースは次のとおりです。```
Input
5
L
L
L
L
L

Output
1
```ライン全体がひとつの塊です。 すべての発生をカウントする不用意な実装`L`1 つではなく 5 つを返します。 

最後のケースは次のとおりです。```
Input
4
L
R
L
R

Output
4
```隣接するペアはすべて異なるため、すべての人が新しい塊を開始します。 1 種類の方向のみをカウントする実装、または最後の位置を忘れる実装では、一部のグループが欠落する可能性があります。 

## アプローチ

 直接的な力ずくのアプローチでは、各位置から開始して、方向は同じまま右に拡大することによって、すべての塊を識別しようとします。 すべての最大セグメントは最初の要素から拡張することで見つけることができるため、これは正しいです。 ただし、最悪の場合、`L`キャラクター、最初の拡張訪問$N$要素、2 回目の訪問$N-1$、 等々。 合計作業量は次のようになります。$$N + (N-1) + \dots + 1 = O(N^2)$$のために$N = 100000$、これはおよそ 50 億件の比較になります。 

重要な観察は、前の人から方向が変わったときにのみ塊が始まるということです。 塊の全体の長さを知る必要はありません。 現在の人が前のグループを継続するか、新しいグループを開始するかを知る必要があるだけです。 これにより、問題は、隣接する各ペアが 1 回ずつ検査される単純なスキャンに軽減されます。 

ブルート フォースはすべてのセグメントを明示的に検出するため機能しますが、同じ情報が何度も繰り返されます。 塊間の境界がまさに隣接する方向が異なる位置であるという観察により、それらの境界を直接数えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一連の指示を読みます。 最初の人は常に最初の塊を開始するため、答えを 1 に初期化します。 
2. 2番目以降の人物をスキャンします。 現在の方向を以前の方向と比較します。 
3. 2 つの方向が異なる場合は、新しい連続グループが開始されているため、クランプ数を増やします。 
4. 行全体を処理した後、カウントを出力します。 

これが機能する理由は、新しい塊が現れる唯一の方法は、隣り合う 2 人の人が異なる方向を向いていることだからです。 前の塊の正確なサイズは関係ありません。 

なぜ効果があるのか:

 スキャン中、答えは常に、すでに処理されたラインの部分によって形成された塊の数と等しくなります。 最初に、最初の人は塊を 1 つ作成します。 方向が変わるたびに、現在の人は前のクランプに属することができないため、新しいクランプを開始する必要があります。 スキャンが終了すると、考えられるすべての境界がチェックされるため、カウントはライン全体のクランプの数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    directions = [input().strip() for _ in range(n)]

    ans = 1
    for i in range(1, n):
        if directions[i] != directions[i - 1]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```比較では前の方向にアクセスする必要があるため、入力はリストとして保存されます。 しかないので、$10^5$文字の場合、このメモリ使用量はわずかです。 空ではない行には常に少なくとも 1 つのグループがあるため、アルゴリズムは 1 つの塊から開始します。 

最初の方向には比較する前に隣接する方向がないため、ループはインデックス 1 から始まります。 現在のキャラクターが前のキャラクターと異なるたびに、現在の人物が新しいクランプの最初のメンバーになります。 

ここでは、難しい境界計算や整数のサイズに関する懸念はありません。 実装の詳細で重要なのは、制約により少なくとも 1 人が保証されるため、空の入力仮定を避けることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | すべての人が一度は検査を受けます。 |
 | スペース | O(N) | 方向リストには入力シーケンスが格納されます。 |

 時間計算量は次の条件に適合します。$10^5$一人あたりの作業量が一定であるため、制限がかかります。 メモリ使用量も制限内です。 入力をオンラインで処理することでアルゴリズムの追加スペースを O(1) に減らすことができますが、シーケンスを保存することで実装が単純になります。
