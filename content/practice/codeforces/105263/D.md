 ## 解決策
 ## 問題の理解

 私たちには友人に対する有向関数グラフが与えられています。 各友達は同じアイテムの山から始まり、各アイテムはその所有者と同じタイプを持ちます。 だから友達$i$最初は保持されます$n_i$活字のコピー$i$。 

プロセスはラウンドで実行されます。 ラウンドでは、各友達は現在自分の手元にあるすべてのアイテムを確認します。 各タイプのアイテムを最大 1 つ保持でき、常に可能な限り多くの異なるタイプを保持します。 すでに保持することに決めたタイプの残りの重複は、指定された親友に送信されます。$a_i$。 これは、誰も手にアイテムを持たなくなるまで繰り返されます。 

主な効果は、ラウンドごとにアイテムが有向エッジに沿って移動することです。$i \to a_i$、各ノードは、そのラウンドで受け取るタイプごとに最大 1 つのアイテムを「吸収」します。 重複はすぐにフィルタリングされるため、重要なのは個々の項目ではなく、グラフに沿って繰り返されるフィルタリングを通じて、あるタイプの異なる「ウェーブ」がどれだけ生き残れるかということです。 

入力サイズが大きく、最大$10^5$テストごとのノード数と最大値$10^{12}$。 これにより、アイテムやラウンドに関するシミュレーションは除外されます。 チェーンの長さが長いため、ノード上のラウンドをシミュレートしても遅すぎます。$n$情報を繰り返し伝播する可能性があり、単純な伝播は二次関数になります。 

エッジケースの主な困難はサイクルです。 サイクルを無視すると、ツリー状の構造に沿った単純な伝播が可能に見えるかもしれませんが、サイクルにより値が循環し、自明ではない定常状態で蓄積することが可能になります。 もう 1 つの微妙な問題は、「タイプごとに最大 1 つを保持する」ルールが飽和効果を生み出すことです。ノードが一度タイプを認識すると、そのタイプのそれ以降のコピーは事実上区別できなくなり、そのタイプを前進させることにしか寄与しません。 

簡単な故障例は 2 サイクルです。 仮定する$0 \to 1$、$1 \to 0$、両方とも大きい$n_i$。 単純な順方向累積では、繰り返し全体で繰り返し 2 倍のカウントが行われ、無制限の増加が予測されますが、実際には、各サイクルはタイプごとに固定された転送パターンに達します。 

## アプローチ

 ブルートフォース解釈はラウンドをシミュレートします。 各ラウンドで、すべてのノードについて、マルチセット内のすべてのタイプを追跡し、各タイプを 1 つの保持項目に制限し、残りをエッジに沿ってプッシュします。 各項目は、吸収されるまで機能グラフに沿って移動するように見えます。 各アイテムは最大まで横断する可能性があるため、$O(n)$ステップは次のとおりです。$O(n)$最初の項目では、これは次のことにつながります$O(n^2)$最悪の場合の行動。 

失敗点は項目が独立していないことです。 ノードが一度タイプを認識すると、そのタイプのそれ以降のコピーはすべて同じように動作します。 これは、各タイプを単一の「アクティベーション シグナル」に圧縮し、グラフ内を伝播することを示唆しています。 

重要な観察点は、各ノードについて$i$重要なのは、転送を繰り返すことでどれだけ多くの異なるタイプが到達できるかということです。 各ノードはそのタイプを受信者に 1 回だけ提供しますが、トラバーサルが繰り返されるため、サイクル内で複数回出現する可能性があります。 この構造は関数グラフであるため、すべてのノードは最終的にサイクルに入ります。 サイクルに入ると、寄与は安定し、サイクル内の各ノードはステップごとに均一な流入を効果的に蓄積します。これは、サイクルの合計と入ってくるツリーの寄与を分析することで解決できます。 

これにより、パスに沿って重複が抑制されている場合に、機能グラフ内でノードごとにいくつの異なる開始ノードがそのノードに到達できるかを計算するという問題が軽減されます。 これは、強く接続されたコンポーネントの凝縮に基づいて到達可能性のサイズを計算することに相当しますが、ここでの SCC は単なる単純なサイクルです。 

グラフをサイクルに分解し、ツリーがサイクルにフィードされることでノードを処理します。 各ツリー ノードは、その固有のパスに沿って 1 回だけサイクルに寄与します。 各サイクルは、そのノード全体に貢献を均等に再分配します。

 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | 関数グラフ + サイクル分解 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 標準のトポロジカル プルーニング プロセスを使用して、次数を計算し、サイクル内にないノードを特定します。 

度数 0 のノードを繰り返し削除します。 すべてのノードが出次数 1 を持つため、残りのノードは互いに素な有向サイクルを形成します。 
2. 枝刈り後に残ったすべてのノードをサイクル ノードとしてマークします。 

このステップでは、蓄積が直線的に終了しない部分のみを分離します。 
3. 各ツリー ノード (非サイクル) について、それが最終的に流入するサイクルに割り当てます。 

これを行うには、親リンクを保存し、サイクル エントリに到達するまで貢献を前方に伝播します。 
4. 各ノードが発信隣接ノードに送信する合計寄与を計算します。 

各ノードはそのすべてを貢献します$n_i$パスに沿って 1 回実行されますが、重複が折りたたまれるため、タイプ グループごとにノードごとに 1 つのフロー ユニットのように動作します。 
5. 各サイクルを走査し、その総流入フローを計算します。 

すべてのサイクル ノードがコントリビューションを交換するため、サイクルは質量の回転コンテナのように動作します。 
6. 定常状態で各ノードが訪問された回数に応じて、サイクル ノード間でサイクル合計を均等に分配します。これは機能サイクルでは均一です。 
7. サイクル アンカーからの逆走査を使用して、最終的な回答をツリー ノードに伝播します。 

重要な不変条件は、サイクル外のすべてのノードが固有の最終的な宛先サイクルを持ち、異なる開始ノードからの寄与が分割されることがなく、常に決定論的なパスをたどることです。 サイクル内では、各ノードが 1 つの出力エッジを持ち、サイクル自体から 1 つの入力エッジを正確に受け取るため、唯一可能な定常状態の解決策は、入力コントリビューションを均一に分散することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        n_i = list(map(int, input().split()))

        # convert to 0-based
        # a[i] is best friend of i
        # functional graph
        g = a

        indeg = [0] * n
        for v in g:
            indeg[v] += 1

        from collections import deque
        q = deque(i for i in range(n) if indeg[i] == 0)

        in_cycle = [True] * n

        while q:
            u = q.popleft()
            in_cycle[u] = False
            v = g[u]
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

        # collect cycles
        vis = [False] * n
        ans = [0] * n

        # first, assign tree nodes their direct contribution upward
        for i in range(n):
            ans[i] = n_i[i]

        # propagate tree contributions toward cycle
        # reverse graph is a forest
        rg = [[] for _ in range(n)]
        for i in range(n):
            rg[g[i]].append(i)

        from collections import deque

        # start from cycle nodes
        q = deque(i for i in range(n) if in_cycle[i])

        # cycle nodes initially hold their own + incoming from tree
        while q:
            u = q.popleft()
            for v in rg[u]:
                if not in_cycle[v]:
                    ans[u] += ans[v]
                    q.append(v)

        # for cycles, equalize along cycle
        for i in range(n):
            if in_cycle[i] and not vis[i]:
                cycle = []
                u = i
                while not vis[u]:
                    vis[u] = True
                    cycle.append(u)
                    u = g[u]

                total = sum(ans[x] for x in cycle)
                for x in cycle:
                    ans[x] = total

        print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、次数枝刈りを使用してグラフをサイクル コアに縮小します。 の`in_cycle`配列は、枝刈り後に生き残ったノードを正確にキャプチャします。 その後、ツリー ノードからの寄与を上方に押し上げることができるように、逆隣接リストが構築されます。 

の`ans[i] = n_i[i]`初期化は、各ノードが独自のパイルを一度だけ提供するという考えをエンコードします。 逆伝播ステップでは、最終的にサイクル ノードに流入するノードからの寄与が蓄積され、各ツリー ノードがそのパスに沿って正確に 1 回カウントされるようになります。 

最後のサイクル処理ステップでは、各サイクルを明示的に実行し、値をサイクル合計に置き換えます。 これにより、定常状態の特性が強制されます。つまり、サイクルに入ると、寄与は完全に混合されます。 

微妙な点は、ラウンドを明示的にシミュレートする必要がないということです。 グラフ構造は、ツリーの高さに 1 サイクルの走査を加えたものに等しい、制限されたステップ数での終了を保証します。 

## 実用的な例

```ここでは、ノード 1→2→3 が 2→3→2 のサイクルを形成し、ノード 4 が 2 にフィードします。 

| ステップ | ノード | 受信累積 | サイクル状態 |
 | --- | --- | --- | --- |
 | 初期化 | 4 | 4 | サイクルが空 |
 | 伝播する | 2 | 2 + 4 | 部分的 |
 | サイクルビルド | 2,3 | (2+4, 3) | 合計 = 9 |

 サイクル ノードは均等化された合計 9 で終了しますが、ノード 4 はサイクルに 1 回だけ参加します。 

これは、サイクル等化の前にツリーの寄与がどのように吸収されるかを示しています。

 ## 特殊なケース

 自己ループは最も単純なサイクルです。 ノードがそれ自体を指している場合、そのノードはすぐに長さ 1 のサイクルの一部になります。 アルゴリズムは、枝刈り後のサイクルとしてマークします。 それにフィードするツリー ノードがないため、その答えは独自の値のままになります。 これは、すべての貢献が再分配されずに同じノードに返される動作と一致します。 

サイクルにフィードされる長いチェーンは、ツリーの伝播がノードごとに 1 回だけ適用されるかどうかをテストします。 チェーン上の各ノードは上向きに 1 回だけ寄与し、枝刈りによって累積が繰り返されることはありません。 逆隣接トラバーサルでは、親が展開されるときに各ノードが 1 回処理されることが保証されます。 

純粋なサイクルは、外部流入が存在しない場合でもイコライゼーションが正しいことを確認します。 すべてのノードはサイクル内の初期値の同じ合計で終了します。これは、すべての貢献が無限に循環し、完全に共有されるという考えと一致します。
