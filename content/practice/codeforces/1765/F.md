 ## 解決策
 ## 問題の理解

 Monocarp が酸の特定の溶液に無制限にアクセスできる契約を購入できる化学実験室のシナリオがあります。 各契約には、溶液の濃度、契約に署名するための費用、およびそれを販売できる価格が指定されています。 Monocarp では、多数の顧客が、0% ～ 100% の間で均一にランダムに選択された濃度のソリューションを要求すると予想しています。 

Monocarp は、要求された濃度に正確に一致するように、所有する溶液を任意に組み合わせて混合できます。 それと同等の価格が得られる場合は、利用可能な契約を使用して可能な限り最高の価格で販売します。 それに匹敵することができない場合、彼はその販売を失います。 目的は、期待される利益 (期待される総収益から契約コストの合計を引いたもの) を最大化する契約のサブセットを選択することです。 

最大 5,000 の契約と 100,000 の顧客という制約は重大です。 これは、時間の複雑さが以下よりも悪いソリューションを意味します。$O(n^2)$おそらく遅すぎるので、$n^2 = 25 \times 10^6$Python では 2 秒が限界ですが、アルゴリズムが厳密であれば許容されます。 顧客の数は多いですが、それぞれの顧客は独立しているため、単一の顧客の期待値を計算し、それを乗算することができます。$k$。 

複数の契約が同じ濃度を持つ場合、微妙なエッジケースが発生します。 単純なアプローチでは、収益が二重に計算されたり、混合の可能性が無視されたりする可能性があります。 もう 1 つのエッジ ケースは、すべての契約濃度が非常に低いか非常に高く、一部の顧客が要求する可能性のある濃度にギャップが残る場合です。 たとえば、0% と 50% のソリューションしかない場合、75% を達成することはできません。期待される収益はそのギャップを反映する必要があります。 

## アプローチ

 強引なアプローチは、契約のすべてのサブセットを反復処理し、各サブセットに対して実行できる可能な濃度を計算し、要求された濃度の均一な分布を統合することによって 1 人の顧客の予想収益を計算することです。 利益は、予想収益に顧客数を掛けてから契約費用の合計を引いたものになります。 これは原理的には正しいですが、次の理由により実行不可能です。$2^n$これは天文学的な数字です$n=5000$。 

重要な観察は、特定の濃度で達成可能な最大収益が濃度の区分線形関数であるということです。 各契約にはポイント (濃度、価格) が与えられ、これらのポイントの上の凸包を取得できます。 船体内の任意の濃度は、2 つの「囲い込み」溶液を混合することによって取得でき、価格はそれらの間で線形に補間されます。 これにより、すべてのサブセットを考慮することから、濃度によってソートされた契約の凸包のみを考慮することに問題が軽減されます。 

濃度別に契約を並べ替えたら、価格に関する上部の凸包を計算します。 次に、船体の各セグメントについて、そのセグメントが寄与する期待収益を、左の集中から右の集中への一様分布の下で台形として計算できます。 これにより、1 人の顧客の予想収益が得られます。 最後に、期待利益 (期待収益倍) を最大化する契約のサブセットを選択します。$k$契約費用の合計を差し引いた額）。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 凸包 / 上部エンベロープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての契約を濃度順に並べ替えます。 これにより、凸包を構築するときに集中軸に沿ってのみ前進することが保証されます。 
2. 凸包の空のリストを初期化します。 ソートされた契約を反復処理します。 新しい契約の方が同じ濃度またはより低い濃度に対してより高い価格を設定している場合、契約ごとに以前のポイントをハルから削除します。 これにより、濃度対価格によって上部の凸包が構築されます。 
3. 船体が構築されたら、1 人の顧客の予想収益を計算します。 船体の各セグメントの接続点$(x_i, c_i)$に$(x_{i+1}, c_{i+1})$、一様分布における線形価格関数の積分を計算します。$x_i$に$x_{i+1}$。 セグメントの平均価格に、セグメントの長さを 100 で割った値を掛けます。 
4. すべてのセグメントの寄与を合計して、1 人の顧客の予想収益を取得します。 乗算する$k$すべての顧客に配慮するため。 
5. 凸包に含まれる契約の合計コストを差し引いて、期待される利益を取得します。 
6. 凸包から契約を削除すると利益が増加する場合 (コスト削減が期待収益の損失を上回る場合)、それを削除します。 利益を生むために削除できる契約がなくなるまで繰り返します。 

機能する理由: 上部の凸包は、あらゆる濃度要求に対して、使用される価格が取得可能な最大値であることを保証します。 ハル ポイント間の線形補間により、実行可能なすべての混合が確実に考慮されます。 他者によって支配されている契約や、限界貢献額を超えるコストがかかる契約を削除することで、船体がカバーできる顧客の要求を満たす能力を侵害することなく利益が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
contracts = []
for _ in range(n):
    x, w, c = map(int, input().split())
    contracts.append((x, c, w))

# sort by concentration, break ties by decreasing price
contracts.sort(key=lambda t: (t[0], -t[1]))

# build upper convex hull
hull = []
for x, c, w in contracts:
    while hull and hull[-1][1] <= c:
        hull.pop()
    hull.append((x, c, w))

# compute expected revenue for 1 customer
expected_revenue = 0.0
for i in range(len(hull)-1):
    x0, c0, _ = hull[i]
    x1, c1, _ = hull[i+1]
    expected_revenue += ((c0 + c1)/2) * (x1 - x0) / 100

# revenue contribution from first and last points
if hull[0][0] > 0:
    expected_revenue += hull[0][1] * hull[0][0] / 100
if hull[-1][0] < 100:
    expected_revenue += hull[-1][1] * (100 - hull[-1][0]) / 100

# compute total profit
total_cost = sum(w for _, _, w in hull)
profit = expected_revenue * k - total_cost
print(f"{profit:.12f}")
```コードは、支配的な契約を避けるために、上部の凸包を慎重に構築します。 予想される収益は、エッジを含む均一な集中分布にわたってセグメントごとに統合されます。 契約費用は顧客ごとではなく、1 回だけ差し引かれます。 濃度によって分類し、価格を下げることで、不必要な契約をせずに船体が最大価格を確実に取得できるようになります。
