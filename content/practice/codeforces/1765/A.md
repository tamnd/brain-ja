 ## 解決策
 ## 問題の理解

 各ドキュメントには、開発者がどのドキュメントを開くことができるかが記述されています。 したがって、入力行列のすべての列は開発者のサブセットです。値が 1 である行は、そのドキュメントの「承認済みセット」を形成します。 

このバイナリ行列を少数のアクセス グループに圧縮することができます。 各グループ内で、すべてのドキュメントにしきい値を割り当て、すべての開発者に数値を割り当てます。 開発者は、ドキュメントのグループ内で開発者の値がドキュメントのしきい値以上であれば、ドキュメントにアクセスできます。 

主要な構造上の制約は、単一のグループ内では、すべてのドキュメントが開発者の 1 つの共有ランキングと互換性を持たなければならないということです。 文書はそのランキングのカットオフによって表されます。カットオフを超えた全員が合格し、下位の全員が不合格になります。 したがって、各ドキュメントは、同じ順序の単一のしきい値分割に対応します。 

出力では、すべての列を正確に実現するために必要な共有順序グループ​​の最小数が求められます。 

n、m ≤ 500 という制約は、行と列の両方が O(m^2) または O(m^3) の構造に対して十分小さいことを意味します。 ドキュメントのペアごとの比較を伴うものはすべて許容されますが、サブセットに対する指数推論は許容されません。 

微妙な失敗例は、3 つ以上の文書がサブセット関係で循環的な「非比較性」を形成する場合に発生します。 たとえば、ドキュメント A の行 {1,2} に、ドキュメント B の行 {2,3} に、ドキュメント C の行 {1,3} に 1 がある場合、相互のサブセットとなる 2 つは存在しないため、単一の順序付けでチェーン内の 1 つ以上を実現することはできません。 ドキュメントをサイズまたは最初の適合に従ってパックしようとする素朴な貪欲さは、必要なセットが単一のしきい値順序と互換性がないにもかかわらず、ドキュメントのうち 2 つを誤って一緒に配置することになります。 

## アプローチ

 この強引なアイデアは、k 個のグループへのドキュメントのすべての可能な割り当てを試し、しきい値を使用した開発者の順序付けによって各グループが実現できるかどうかを確認することです。 1 つのグループの実現可能性をチェックすることは、そのすべての列が 1 つの順列の接尾辞として表現できるかどうかをテストすることに帰着します。これは、何らかの順序付けの後にセットが包含によってネストされているかどうかをチェックすることと同じです。 m 個のドキュメントのすべてのパーティションを試行すると、m では指数関数的となり、m = 500 の場合でも、これは完全に不可能になります。 

重要な観察は、各グループが包含されるセットのチェーンに正確に対応しているということです。 開発者の順序を修正すると、各ドキュメントはその順序の接尾辞になるため、同じグループ内の 2 つのドキュメントにはネストされたドキュメントのセットが必要になります。 逆に、ネストされたセットのチェーンは、開発者に包含と一致する順序を割り当て、別個のカット ポイント間にしきい値を配置することによって実現できます。 

したがって、問題は、サブセット関係の下ですべてのドキュメントセットを最小数のチェーンに分割することに帰着します。 これは古典的なポセット問題です。最小チェーン分解のサイズは最大アンチチェーンのサイズに等しいです。 これを直接計算するには、ドキュメント間の包含関係から構築された 2 部グラフ上の最大マッチングを介して実行できます。 

u 内の 1 のセットが v に厳密に含まれる場合、ドキュメント u をドキュメント v に接続するグラフを構築します。マッチングは、各ドキュメントを、チェーン内でその後に出現する可能性のあるより大きなドキュメントにリンクすることに対応します。 最大のマッチングにより最小のチェーン分解が得られ、そのサイズによって答えが決まります。

 ## アルゴリズムのチュートリアル

 私たちは各ドキュメントを開発者に対するビットセットとして扱います。

1. すべてのドキュメントについて、開発者がアクセスを必要とするセット表現を構築します。 これにより、行列が n 要素ユニバースの m 個のサブセットに変換されます。 
2. ドキュメント u と v のすべてのペアについて、S_u が厳密に S_v に含まれているかどうかを判断します。 これは、ペアごとに O(n) が含まれていることを確認することで行われます。 
3. ドキュメント セットの 2 つのコピーを使用して 2 部グラフを構築します。 S_u ⊂ S_v の場合、左側の u から右側の v までエッジを追加します。 これは、同じチェーン内で u を v の前に配置する可能性をエンコードします。 
4. この 2 部グラフで最大マッチングを計算します。 一致した各エッジは、1 つのドキュメントを同じチェーン内のより大きなドキュメントにリンクしていることを表します。 
5. 標準再構成によるマッチングから最小チェーン分解を導き出します。左側で一致しないドキュメントがチェーンを開始し、一致したエッジに続いて各チェーンが構築されます。 
生成されるチェーンの数はｋであり、各チェーンが１つのアクセスグループに対応する。 
7. 各グループ (チェーン) に、チェーン順序内の位置に従って開発者の値を割り当てます。 開発者は包含性が尊重されるようにランク付けされ、各ドキュメントはチェーン内で必要なドキュメントを他のドキュメントから分離するしきい値を受け取ります。 

この構造により、チェーン内ではセットが厳密にネストされているため、すべてのドキュメントがそのグループ内のクリーンなしきい値カットとして実現されることが保証され、開発者の単一の順序ですべてのカット ポイントを一貫して分離できます。 

### なぜ効果があるのか

 有効なグループでは、その中のすべてのドキュメントが開発者のネストされたサブセットに対応するように強制されます。これは、それらのドキュメントが固定順序で単一のしきい値によって分離可能でなければならないためです。 これは、各グループがサブセット ポセット内のチェーンであることを意味します。 

逆に、サブセットのチェーンは、包含順序が尊重されるように開発者に順序を付け、連続する別個のセット間にしきい値を割り当てることによって実装できます。 したがって、実行可能なグループは正確にチェーンであり、問​​題はすべての要素をカバーするチェーンの数を最小限に抑えることになります。ディルワースによれば、これはアンチチェーンの最大サイズに等しく、二部マッチングによって計算可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [input().strip() for _ in range(n)]

# build sets: documents as bitsets over developers
docs = []
for j in range(m):
    s = set()
    for i in range(n):
        if g[i][j] == '1':
            s.add(i)
    docs.append(s)

# inclusion check
def subset(a, b):
    if len(a) >= len(b):
        return False
    for x in a:
        if x not in b:
            return False
    return True

# build bipartite edges
adj = [[] for _ in range(m)]
for i in range(m):
    for j in range(m):
        if i != j and subset(docs[i], docs[j]):
            adj[i].append(j)

# Kuh for matching
mt = [-1] * m

def dfs(v, vis):
    for to in adj[v]:
        if not vis[to]:
            vis[to] = True
            if mt[to] == -1 or dfs(mt[to], vis):
                mt[to] = v
                return True
    return False

match = 0
for i in range(m):
    vis = [False] * m
    if dfs(i, vis):
        match += 1

# build chains
used = [False] * m
nxt = [-1] * m
for j in range(m):
    if mt[j] != -1:
        nxt[mt[j]] = j

for j in range(m):
    if mt[j] == -1:
        cur = j
        while cur != -1:
            used[cur] = True
            cur = nxt[cur]

chains = []
for j in range(m):
    if mt[j] == -1:
        cur = j
        chain = []
        while cur != -1:
            chain.append(cur)
            cur = nxt[cur]
        chains.append(chain)

# assign groups
k = len(chains)
group = [0] * m
thr = [0] * m

for idx, ch in enumerate(chains):
    for pos, doc in enumerate(ch):
        group[doc] = idx + 1
        thr[doc] = pos + 1

# developer values per group
dev_val = [[0] * k for _ in range(n)]

for g_id, ch in enumerate(chains):
    for i in range(n):
        val = 1
        for doc in ch:
            if g[i][doc] == '1':
                val += 1
        dev_val[i][g_id] = val

print(k)
print(*group)
print(*thr)
for i in range(n):
    print(*dev_val[i])
```マッチング部分では、すべてのドキュメントがチェーン内の最大 1 つの後継者に割り当てられるように強制され、チェーンのフォレストが生成されます。 各チェーンインデックスはグループになります。 しきい値は単にチェーン内の位置であり、同じチェーン内の後のドキュメントには厳密に強力な条件が必要になります。 

開発者の値は、それらが満たすチェーン内のドキュメントの数を数えることによってグループごとに構築されます。これにより、チェーンの順序に沿った単調性が保証されます。 

## 実用的な例

 ### 例 1

 入力:```
3 2
01
11
10
```まずセットを形成します。 

ドキュメント 0 には {1,2} があり、ドキュメント 1 にはゼロベースのインデックス付けで {0,1,2} があります。 

| ステップ | ドキュメントセット | エッジビル | 一致する |
 | --- | --- | --- | --- |
 | 初期化 | {1}、{0,1,2} | 0 ⊂ 1 | 0→1に一致 |

 マッチング後、両方のドキュメントは 1 つのチェーンを形成するか、方向に応じて分割され、有効な分解では k = 2 チェーンになります。 

このトレースは、どちらの順序も単一のチェーン内の両方の必要なカットを満たすことができないため、包含構造が分離を強制していることを示しています。 

### 例 2

 入力:```
2 2
01
10
```セットは素であり、比較できません。 

| ステップ | ドキュメントセット | 包含エッジ | 一致する |
 | --- | --- | --- | --- |
 | 初期化 | {1}、{0} | なし | なし |

 エッジが存在しないため、すべてのドキュメントが独自のチェーンになります。 これは、比較できない集合がグループを分離することを強制することを裏付けています。

 ## 特殊なケース

 重大なエッジケースは、すべてのドキュメントがペアごとに比較できない場合です。 その状況では、すべての包含テストが失敗し、マッチングは空になり、各ドキュメントは独自のチェーンになります。 チェーンにはサブセット構造に違反することなく複数の要素を含めることはできないため、アルゴリズムは当然 k = m を返します。 

もう 1 つの特殊なケースは、すべてのドキュメントが同一である場合です。 すべてのセットは他のセットのサブセットでもスーパーセットでもあるため、グラフは両方向に完全に接続されます。 マッチングではドキュメントを長いチェーンにペアにし、再構築ではすべてを 1 つのグループにマージし、k = 1 を生成します。
