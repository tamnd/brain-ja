 ## 問題の理解

 与えられた整数を分割するように求められます`n`2 つのポジティブな部分に分割`a`そして`b`その合計が固定されるようにする`n`。 このようなすべての分割の中で、次の最小公倍数となるペアが必要です。`a`そして`b`できるだけ小さいもの。 

したがって、入力は単なるテスト ケースのシーケンスであり、それぞれが単一の数値を提供します。`n`。 それぞれについて`n`、概念的に壊れるカットを配置します。`n`を 2 つの正の整数に変換し、LCM を使用してペアがどの程度「互換性」があるかを測定します。 目標は、この互換性の尺度が最小限に抑えられる分割を見つけることです。 

制約`n ≤ 10^9`これは、単一のテスト ケースに対して考えられるすべての分割を素朴な方法で試行することはできないことを意味します。`n/2`そして、分割ごとに何か高価なものを実行した場合、最悪の場合でも合格することを期待します。 テスト ケースごとの線形スキャンは、複数のケースにわたってすでに 10^9 の境界線に達していますが、より重要なのは、解決策が問題を因数分解や対数チェックのようなものに削減する必要があることを示していることです。 

微妙なエッジケースは次のような場合です`n`特に小さいです`n = 2`。 その場合、唯一の分割は、`1 + 1`したがって、約数または最大の適切な約数に依存する式は、「最良の約数」が次のようなものである可能性があるという事実を処理する必要があります。`1`。 もう 1 つの特殊なケースは、次のような奇数です。`n = 9`、直感的には次のようなバランスのとれた分割が示唆されるかもしれません。`4 + 5`ただし、これらは LCM の下では必ずしも最適であるとは限りません。 実際、次のようなより構造化されたペア`3 + 6`パフォーマンスが向上します。 これは、対称性だけが正しいヒューリスティックではないことを示しています。 

## アプローチ

 直接的なアプローチは、すべてのペアを試してみることです`(a, b)`そのような`a + b = n`、計算する`lcm(a, b)`、そして最小限のものを取ります。 おおよそありますので、`n`～の選択肢`a`、これは次のことにつながります`O(n)`テストケースごとに作業します。 と`n`まで`10^9`、これはまったく不可能です。 

キー構造は、LCM 式を書き直すことで得られます。 どのペアでも`(a, b)`、表現できます`a = g x`そして`b = g y`、 どこ`g = gcd(a, b)`そして`x`そして`y`は互いに素である。 合計制約は次のようになります。`g(x + y) = n`、 それで`g`分けなければなりません`n`。 これにより、問題はすべての分割の検索から約数の検索に変わります。`n`。 

金額が確定したら、`x + y = n / g`、製品`x * y`LCM は次のように決定されます。`lcm(a, b) = g * x * y`。 定額の場合、積`x * y`1 つの値が次の場合に最小化されます。`1`そしてもう一つは`k - 1`。 これにより、LCM は次のようになります。`g * (k - 1)`これを単純化すると`n - g`。 

これで、目的は非常にシンプルになりました。最大化することです。`g`という制約のもとで`g`はの適切な約数です`n`。 可能な限り最高の`g`より小さい最大の約数です`n`を除算して得られます。`n`最小の素因数で計算します。 

ブルート フォースはすべての分割を列挙することで機能しますが、除数構造を無視するため失敗します。 LCM が gcd と sum に依存するという観察により、問題は単一の素因数を見つけることに帰着します。

 ## アルゴリズムのチュートリアル

 ここで、推論を直接的な手順に変換します。 

1. 各テスト ケースについて、次の内容を読んでください。`n`。 目標は、暗黙的な gcd 構造が最大化される分割を決定することです。 
2. 最小の素因数を見つける`p`の`n`。 分割なのでこれで十分です`n`による`p`の最大の適切な約数を与える`n`。 
3. コンピューティング`g = n / p`。 この値は、有効なペアの可能な最良の gcd を表します。`(a, b)`。 
4. 次のようにペアを構築します。`a = g`そして`b = n - g`。 これにより、次のことが保証されます`a + b = n`また、gcd 構造が最適な因数分解と一致していることもわかります。 
5. 出力`(a, b)`任意の順序で。 

この構造が機能する理由は、一度修正すると、`g`の約数として`n`、残りの合計は次のように分割されます。`(1, k - 1)`削減された変数のレベルで、内積が最小化され、したがって最小公倍数が最小化されます。 

### なぜ効果があるのか

 有効なペアは次のように記述できます。`(g x, g y)`と`x + y = n / g`。 LCM は次のようになります。`g x y`。 固定用`g`、LCM を最小化すると、最小化されます。`x y`、極端な不均衡では最小化されます`(1, k - 1)`。 残された自由は選択することだ`g`。 最終的な式は次のように単純化されるため、`n - g`、最大化する`g`最適解と最大の適切な約数を与えます。`n`まさに`n`最小の素因数で割ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def smallest_prime_factor(n: int) -> int:
    if n % 2 == 0:
        return 2
    d = 3
    while d * d <= n:
        if n % d == 0:
            return d
        d += 2
    return n

t = int(input())
for _ in range(t):
    n = int(input())
    p = smallest_prime_factor(n)
    g = n // p
    a = g
    b = n - g
    print(a, b)
```ヘルパー関数は、最大の割り算をチェックすることにより、最小の素因数を効率的に計算します。`sqrt(n)`。 それが見つかったら、すぐに最適な gcd 候補を導き出します。`g`。 

建設`b = n - g`これは意図的です。相補構造の再計算を回避し、合計制約を直接強制します。 

よくある間違いは、返品することです`(g, g)`、しかしそれは次の場合にのみ機能します`n`均等であり、`g = n/2`。 正しい数式では、減算を通じて常に合計条件が保持されます。

これらの例は、アルゴリズムが、対称分割と非対称分割の間で自然にシフトするかどうかに応じて、`n`には小さな素因数があります。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def spf(n):
        if n % 2 == 0:
            return 2
        d = 3
        while d * d <= n:
            if n % d == 0:
                return d
            d += 2
        return n

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = spf(n)
        g = n // p
        out.append(f"{g} {n - g}")
    return "\n".join(out)

# power of two
