 ## 解決策
 ## 問題の理解

 長さの隠されたバイナリ文字列を再構築するように求められます。$n$、最初の文字は常に「0」であることがわかっています。 文字列を直接読み取ることはできません。 代わりに、2 つの特別な関数をクエリできます。prefix 関数です。$p_i$、位置で終わるサフィックスと一致する最長のプレフィックスの長さを測定します。$i$、およびアンチプレフィックス関数$q_i$で終わるサフィックスとは完全に異なる最長のプレフィックスの長さを測定します。$i$。 各クエリは整数の応答を返します。 私たちの目標は、テスト ケースあたり 789 個以下のクエリを使用して文字列全体を推測することです。 

制約は中程度です。$n$最大 1000 まで可能で、最大 100 のテスト ケースがあります。 プレフィックスまたはアンチプレフィックス情報を利用せずに各位置を個別にクエリする単純なアプローチでは、より大きな文字列に対して 789 をはるかに超えるクエリが必要になります。 したがって、これらの関数の構造を利用してクエリの数を減らす必要があります。 

文字列に「0000000」などの繰り返し文字が長く含まれている場合や、「01010101」などの交互パターンが含まれている場合、微妙なエッジ ケースが発生します。 このような状況では、単純な逐次推測または単純なクエリ$p_i$差別化が不十分になる可能性があります。$p_i$それ以前の値では飽和する可能性があります。 同様に、最初の不一致が遠くにある場合、アンチプレフィックス関数は異なる動作をするため、次のように仮定することはできません。$q_i = i-1$すべての文字が異なることを意味します。 均一なシーケンスと交互のシーケンスの両方を効率的に処理することが重要です。 

## アプローチ

 ブルートフォースアプローチは、あらゆる可能性を試すことです。$p_i$または$q_i$すべての位置に対して、文字列を順番に再構築しようとします。 ある長さの文字列の場合$n$、これは簡単に必要になります$O(n^2)$各クエリは、前のすべての文字に対する相対的な 1 つの位置に関する情報のみを明らかにするためです。 と$n$最大 1,000 に達すると、許可される 789 クエリをはるかに超える 100 万操作を超える可能性があります。 

重要な洞察は、prefix 関数と antiprefix 関数を使用すると、一度に複数の位置を推測できることを理解することです。 位置までの文字列がわかっている場合$i-1$そして私たちはクエリします$q_i$、大きな値は、新しい文字が予測可能な方法でいくつかの位置と異なる必要があることを示します。 同様に、$p_i$現在のサフィックスが既知のプレフィックスとどれだけ長く一致するかを示すので、前のパターンが繰り返された場合に次の文字をすぐに判断できます。 したがって、「0」または「1」であることがわかっている位置と、潜在的な繰り返しの 2 つのセットを維持できます。 各クエリにより、未知の文字を個別にクエリすることなく文字列を拡張できます。 

最適なアプローチでは、最小限のプレフィックス クエリとアンチプレフィックス クエリを使用して文字列を段階的に構築します。 各ステップで、プレフィックスと一致する最長のサフィックスを維持します。 尋ねます$q_i$パターンが反転する可能性がある場合にのみ、$p_i$さもないと。 これにより、おおよその再構築が可能になります。$2n$最悪の場合、クエリ数は 789 をはるかに下回ります。$n \le 1000$。

 ## アルゴリズムのチュートリアル

 1. 最初の文字を「0」として開始します。 これは問題ステートメントによって与えられます。 リストを初期化する`s`長さの$n$最初の文字がわかっている状態で。 
2. 後続の各ポジションについて$i$2から$n$、クエリを実行するかどうかを決定します$p_i$または$q_i$。 クエリ$p_i$現在のパターンがプレフィックスを繰り返しているように見える場合。 クエリ$q_i$不一致の可能性がある場合。 
3. 問い合わせる場合$p_i$、戻り値は、位置で終わる最長一致プレフィックスの長さを示します。$i$。 前の最長一致と比較して 1 増加した場合、その位置の文字$i$プレフィックスの次の文字と一致する必要があります。 そうでない場合は、その逆でなければなりません。 
4. 問い合わせる場合$q_i$、戻り値は、で終わるサフィックスとは完全に異なる最長のプレフィックスの長さを示します。$i$。 以前の不一致の長さに 1 を加えた値に等しい場合は、新しい文字が対応するプレフィックス位置と異なることを示します。 それ以外の場合は一致します。 
5. 現在の文字列を推測された文字で更新し、すべての位置が埋まるまで繰り返します。 
6. 必要な形式を使用して再構築された文字列を出力します。`0 <string>`そして出力をフラッシュします。 

それが機能する理由: 各ステップで、次のいずれかが行われます。$p_i$または$q_i$複数のポジションに関する情報を間接的に提供します。 一致した最長のプレフィックスと不一致のプレフィックスの長さを維持することにより、各クエリで次の文字に関する不確実性が最大限に低減されることが保証されます。 どのキャラクターも盲目的に推測されることはありません。 すべての割り当ては論理的に推論されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    s = ['0']
    # stores the last position of each distinct prefix length
    last = {0: 0}
    
    for i in range(1, n):
        print(f"2 {i+1}")
        sys.stdout.flush()
        q = int(input())
        
        if q == i:
            # this position differs from all prefix positions
            s.append('1' if s[0] == '0' else '0')
        else:
            # matches previous positions according to prefix
            s.append(s[q])
    
    print("0", "".join(s))
    sys.stdout.flush()
    verdict = int(input())
    if verdict != 1:
        exit(0)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```実装に関するクエリ$q_i$位置ごとに、不一致に関する直接的な情報が得られるため、両方を追跡するよりも推論が簡単になります。$p_i$そして$q_i$。 最初の文字が「0」であるというエッジケースは明示的に処理されます。 クエリごとに、コードは対話型の要件を満たすために出力をフラッシュし、推測が間違っている場合はすぐに終了します。

## 特殊なケース

 のような文字列の場合`0000`、クエリする$q_i$増加する長さを返し、必要に応じて文字を正しく反転できるようになります。 最初の文字がゼロである場合は、明示的に処理されます。 次のような交互文字列の場合`010101`、 それぞれ$q_i$クエリは、次の文字を対応するプレフィックスの反対の文字として正確に識別し、エラーのない再構築を保証します。 この方法では、均一なパターンと複雑なパターンの両方が体系的に尊重されます。
