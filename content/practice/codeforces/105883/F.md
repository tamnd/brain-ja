 ## 解決策
 ## 問題の理解

 私たちはペアの動的なコレクションを維持します$(v, w)$。 各操作は、ペアを挿入するか、ペアの 1 つの出現を削除するか、または数値を使用してクエリを実行します。$k$。 

クエリの場合、現在存在するすべてのペアを調べ、最初のコンポーネントが含まれるペアのみを考慮する必要があります。$v$～と素因数を共有しない$k$、 意味$\gcd(v, k) = 1$。 これらの有効なペアのうち、最大値を返します。$w$。 該当するものがない場合、答えはゼロです。 

重要な点は、有効性は次の関係に依存するということです。$v$とクエリ値$k$、一方、最適化する値は$w$、挿入と削除の両方が完全に動的です。 

制約により、最大で$2 \cdot 10^5$操作、$v, k \le 5 \cdot 10^5$。 これにより、クエリごとに答えを最初から再計算することが直ちに排除されます。クエリごとにマルチセット全体をスキャンすると、$4 \cdot 10^{10}$最悪の場合のチェック。 慎重に枝刈りをしなければ、クエリごとにソートされた構造を維持しても存続できません。 

微妙な落とし穴は、削除を正しく処理することです。 同じペア$(v, w)$は複数回出現する可能性があり、削除操作ごとに 1 つのコピーのみを削除する必要があります。 もう 1 つの問題は、ペアはグローバル構造内に残る可能性がありますが、gcd 制約によりクエリに対して無効になるため、古いエントリが応答に影響を与えてはいけないことです。 

素朴なアプローチを打ち破る小さな例を次に示します。 

入力:```
+ 6 10
+ 4 7
? 3
```6 と 4 はどちらも 3 と互いに素であるため、正しい答えは 7 です。単純な間違いは、割り算だけをチェックするか、最大値だけを追跡することです。$w$グローバルに実行すると、gcd 制約が誤って無視され、常に 10 が返されます。 

別のエッジケースは次のとおりです。```
+ 2 5
+ 3 9
? 6
```ここで、2 と 3 はどちらも 6 と因数を共有しているため、正解は 0 です。$k$または、gcd の計算が完全に失敗すると、不正なゼロ以外の値が返されます。 

## アプローチ

 直接的な解決策では、すべてのアクティブなペアのコンテナを維持し、クエリごとにすべての要素をスキャンして、$\gcd(v, k) = 1$そして最大値を追跡する$w$。 挿入と削除は、$O(1)$ただし、各クエリにはコストがかかります$O(n)$、につながる$O(n^2)$全体的に遅すぎます$2 \cdot 10^5$操作。 

重要な点は、実際にはグループ化する必要がないということです。$v$クエリごとに構造化された方法で。 必要なのは、大規模な候補を迅速に検索できることだけです。$w$無効なものを効率的に破棄しながら。 これは、次の順序でグローバル構造を維持することを示唆しています。$w$、要素がアクセスされたときに要素がまだ有効であるかどうかを遅延チェックします。 

挿入されたすべてのペアを、次のキーを持つ max-struction に保存します。$w$、削除を処理するために頻度マップを保持します。 クエリごとに、現在の最大値を繰り返し検査します。$w$。 そのペアが削除されるか、gcd 条件に失敗した場合は、そのペアを破棄して次に進みます。 各要素は考慮から一度だけ削除されるため、償却された複雑さは演算数に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | 遅延削除による最大ヒープ |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 注文された最大ヒープを維持します$w$、およびそれぞれのコピー数を追跡する頻度マップ$(v, w)$ペアは現在存在します。 

1.挿入の場合$(v, w)$、それをヒープにプッシュし、その頻度を増やします。 これにより、すべてのアクティブなペアが今後のクエリの候補として利用できるようになります。 
2. 削除の場合$(v, w)$、その周波数を減少させます。 ヒープ内に配置するとコストがかかるため、ヒープからすぐには削除しません。 
3. 値を含むクエリの場合$k$、ヒープの最上部を繰り返し検査します。 最上位のペアの頻度がゼロの場合、以前の削除により古くなっているため、削除されます。 まだ存在していればですが、$\gcd(v, k) \ne 1$、このクエリでは無効であるため、同様に破棄されます。 
4. ヒープによって最大のペアが保証されているため、両方のチェックを生き残った最初のペアがこのクエリの最適な答えになります。$w$残った候補者の中に。 
5. このプロセス中にヒープが空になった場合、答えはゼロになります。 

これが機能する理由は、すべてのペアが特定のクエリに対して永続的に有効か永続的に無効であり、クエリ中にペアが破棄されると、同じクエリに対して再度再検討する必要がないためです。 周波数追跡と組み合わせると、各ペアは制限された回数だけ検討に参加および退場します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

n = int(input())

heap = []
cnt = {}

def key(v, w):
    return (v, w)

for _ in range(n):
    parts = input().split()
    if parts[0] == '+':
        v = int(parts[1])
        w = int(parts[2])
        heapq.heappush(heap, (-w, v))
        cnt[(v, w)] = cnt.get((v, w), 0) + 1

    elif parts[0] == '-':
        v = int(parts[1])
        w = int(parts[2])
        cnt[(v, w)] -= 1

    else:
        k = int(parts[1])

        while heap:
            negw, v = heap[0]
            w = -negw

            if cnt.get((v, w), 0) == 0:
                heapq.heappop(heap)
                continue

            if gcd(v, k) != 1:
                heapq.heappop(heap)
                continue

            print(w)
            break
        else:
            print(0)
```ヒープには、次の順序でペアが格納されます。$w$、負の値を使用して最大ヒープをシミュレートします。 頻度ディクショナリにより、高価なヒープ更新を必要とせずに削除が確実に尊重されます。 

クエリ中に、無効なエントリは遅延して削除されます。 gcd チェックは、候補ごとにコストがかかる唯一の操作ですが、各要素はすべてのクエリにわたって最大 1 回チェックされるため、合計の作業量が制限されます。 

よくある間違いは、ごとに別々の構造を維持しようとすることです。$v$または素因数ごとに$v$、動的削除により複雑になります。 レイジー ヒープ アプローチでは、そのような複雑さはすべて回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 各挿入とヒープ操作には log n のコストがかかり、各要素は最大 1 回削除されます。 
| スペース |$O(n)$| ヒープと周波数マップはすべてのアクティブな要素を保存します。 

制約により、最大で$2 \cdot 10^5$操作、および対数ヒープ操作は問題なく制限内に収まります。 gcd チェックは、遅延削除中に各ペアが 1 回だけ評価されるため、十分に安価です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    def solve():
        n = int(input())
        heap = []
        cnt = {}

        def gcd(a, b):
            while b:
                a, b = b, a % b
            return a

        out = []
        for _ in range(n):
            parts = input().split()
            if parts[0] == '+':
                v, w = int(parts[1]), int(parts[2])
                heapq.heappush(heap, (-w, v))
                cnt[(v, w)] = cnt.get((v, w), 0) + 1
            elif parts[0] == '-':
                v, w = int(parts[1]), int(parts[2])
                cnt[(v, w)] -= 1
            else:
                k = int(parts[1])
                while heap:
                    wneg, v = heap[0]
                    w = -wneg
                    if cnt.get((v, w), 0) == 0:
                        heapq.heappop(heap)
                        continue
                    if gcd(v, k) != 1:
                        heapq.heappop(heap)
                        continue
                    out.append(str(w))
                    break
                else:
                    out.append("0")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 すべての要素がクエリに対して無効な場合は、アルゴリズムがヒープを適切に使い果たす必要があることを示しています。 

入力:```
+ 2 10
+ 3 20
? 6
```クエリ中に、2 と 3 は両方とも 6 と因子を共有するため、両方とも終了前にポップされます。 ヒープは空になり、正しい出力は 0 になります。遅延削除ループにより、古い最大値が返されないことが保証されます。 

別の特殊なケースには、同じペアの繰り返し挿入が含まれます。```
+ 5 10
+ 5 10
- 5 10
? 2
```削除後にアクティブなコピーが 1 つだけ残ります。 頻度マップは、削除されたコピーが誤って有効であるとみなされるのを防ぎます。
