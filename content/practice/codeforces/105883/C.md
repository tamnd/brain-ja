 ## 解決策
 ## 問題の理解

 1 から n までラベル付けされた頂点のグラフを維持していますが、n 自体が非常に大きくなる可能性があり、頂点によってインデックス付けされたものを直接保存することさえ考えられないほど大きくなります。 最初はエッジがなく、一連のクエリを受け取ります。 各クエリは、指定された 2 つの頂点間に単一の無向エッジを追加するか、指定された間隔内の頂点のすべてのペアを接続して、その間隔を効果的にクリークに変換します。 

すべてのクエリの後に、いくつかのパスによって接続されている順序のない頂点のペアがいくつあるか、つまり同じ接続コンポーネント内にペアがいくつあるかを報告する必要があります。 同様に、各連結成分を取得し、そのサイズ s を数えると、答えに s・(s−1)/2 が寄与し、すべての成分の合計が維持されます。 

重要な困難は 2 つの方向から生じます。 まず、n は最大 10^9 であるため、位置によってインデックス付けされた配列またはセグメント ツリーで頂点を明示的に表すことはできません。 第 2 に、間隔操作は少数のエッジを追加するのではなく、その範囲内の最大 O(n) 頂点に完全なグラフを追加しますが、これを拡張すると致命的なコストがかかります。 

オンライン要件により、構造を段階的に更新する必要があり、各クエリの後に出力する必要があります。 

単純なアプローチは、さまざまな点ですぐに失敗します。 たとえば、範囲 [l, r] のすべてのエッジを明示的に追加しようとすると、そのようなクエリが 1 つだけでも O((r−l)^2) エッジが追加される可能性があります。 r−l が大きい場合、たとえば最悪の場合 10^9 の場合、これは不可能です。 隣接関係リストを維持することさえ、メモリのせいで不可能です。 

微妙なエッジケースとして、範囲のマージが繰り返されることがあります。 最初に [1, 5] を接続し、その後 [2, 4] を接続するとします。 2 番目の操作は接続性の点で冗長ですが、単純なエッジベースのアプローチでは、依然として膨大な数のエッジを再度追加しようとします。 

正しいアプローチでは、頂点を明示的に反復することを避け、代わりにコンポーネントと間隔のレベルで機能する必要があります。 

## アプローチ

 最初の観察は、私たちが気にしているのは接続性だけであり、個々のエッジではないということです。 これは、各コンポーネントにサイズがあり、コンポーネントがマージされるときに接続されたペアの総数を維持する Union-Find 構造 (DSU) を示唆しています。 

タイプ 1 クエリのみがある場合は、DSU で十分です。 サイズ a と b の 2 つのコンポーネントをマージするたびに、コンポーネント間のすべてのペアが接続されるため、答えは a・b ずつ増加します。 

難しいのは、[l, r] のすべての頂点を接続するタイプ 2 のクエリです。 この範囲内のすべての頂点を列挙できれば、それらを 1 つのコンポーネントにマージすることになりますが、n が巨大で r−l が大きくなる可能性があるため、頂点をリストすることさえできません。 

構造上の重要な洞察は、完全に接続された区間がクリークになった後は、その内部の個々の頂点を実際に扱う必要がないということです。 区間 [l, r] が処理されると、その範囲内のすべての頂点が相互に接続されるようになります。つまり、区間全体を正しくマージすると、区間全体が 1 つのコンポーネントに折りたたまれます。 ただし、将来のクエリは部分的にそれと重複する可能性があるため、これらのマージされた領域を効率的に表現できなければなりません。 

これは、現在接続されているコンポーネントを通じてのみグラフを維持し、DSU ルートに対応する頂点ラベルの「アクティブ セグメント」の互いに素なセットを追跡するという考えにつながります。 範囲内のすべてのポイントを反復処理する代わりに、すでに処理されたセグメントを飛び越えて、代表的なエンドポイントのみをマージできる構造を維持します。

これを機能させる標準的な方法は、インデックス空間全体で DSU を維持することですが、同じ代表区間にすでに属している連続したインデックスを圧縮します。 さらに、すでに使用されている位置をスキップできるようにする「ネクスト ポインター」構造 (多くの場合、マップまたはバランス ツリーで実装されます) を維持します。 間隔を完全に接続するたびに、すべての整数ではなく、その間隔内で現在生きている代表のみをスイープします。 

2 番目の重要なアイデアは、区間をクリークにマージした後、以降の操作ではその区間内のすべての頂点が単一のブロックのように動作するということです。 これらのブロックは、DSU と範囲内の残りの代表に対する高速な反復を可能にする構造を使用して動的に維持されます。 

[l, r] を処理するたびに、最初のまだ処理されていない代表 ≥ l を繰り返し見つけ、それを区間内の最初の代表とマージし、アクティブな構造から削除します。 これにより、各頂点がアクティブな考慮事項から最大 1 回だけ削除されるようになります。 

複雑さは、除去ごとに対数的に償却されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 範囲クエリごとに O(n²) | O(n²) | 遅すぎる |
 | 最適 (DSU + インターバルスキップ) | O((n + q) α(n) log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 接続用の DSU と、次の未使用の代表的な頂点位置 (通常はインデックスからそれ自体へのマップ) を保存する構造を維持します。 

また、現在の答えをコンポーネントの寄与の合計として維持します。 

1. 各頂点がそれ自体の親であり、サイズが 1 である DSU を初期化します。エッジが存在しないため、答えは 0 から始まります。 
2. 現在「アクティブ」な頂点をすべて含む順序付けされた構造を維持します。 最初は、すべての頂点がアクティブになっています。 n は巨大なので、すべてを明示的に保存するわけではありません。 代わりに、必要に応じてエントリを遅延作成し、より大きな構造に吸収されるとエントリを削除します。 
3. タイプ 1 クエリ (u、v) の場合、その DSU ルートを見つけます。 それらが異なる場合は、サイズ寄与の増加を sz[u]・sz[v] として計算し、それを答えに追加して、それらを結合します。 
4. タイプ 2 クエリ (l, r) の場合、[l, r] 内の最小のアクティブな頂点 x を繰り返し見つけます。 存在しない場合は停止します。 
5. [l, r] 内の x の次のアクティブな頂点 x と次のアクティブな頂点 y を取得します。 x と y を結合し、アクティブな構造から y を削除します。 sz[x]・sz[y]も答えに追加します。 

その理由は、[l, r] 上にクリークを構築することは、その範囲内のすべての頂点を単一のコンポーネントに繰り返しマージすることと同じであるということです。 常に成長する代表にマージし、吸収された頂点を削除することでこれをシミュレートします。 

1. [l, r] にアクティブな頂点がなくなるまで続けます。 この時点で、区間全体が 1 つの連結コンポーネントになっているため、すべての内部構造が圧縮されています。 

### なぜ効果があるのか

 いつでも、DSU コンポーネントはグラフの真の接続コンポーネントを表します。 各結合操作では、2 つのコンポーネントを接続するエッジが導入されたときに、2 つのコンポーネントが正確にマージされます。 接続されたペアの総数は、マージされるコンポーネント サイズの積によって正確に更新され、新しく接続されたペアを一意にカウントします。 

間隔クエリの場合、マージ プロセスを繰り返すことで、間隔内のすべての頂点が最終的​​に 1 つのコンポーネントに接続され、すべてのマージが接続されるクロスコンポーネント ペアの 1 つの新しいバッチに正確に対応します。 コンポーネントを分割することはなく、マージ後にアクティブな反復から頂点を削除するだけなので、ペアが二重にカウントされることはなく、接続が失われることはありません。 不変条件は、これまでのすべてのクエリを処理した後、DSU コンポーネントが常にグラフ接続と一致することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self):
        self.parent = {}
        self.size = {}
    
    def add(self, x):
        if x not in self.parent:
            self.parent[x] = x
            self.size[x] = 1
    
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    
    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        gain = self.size[a] * self.size[b]
        self.size[a] += self.size[b]
        return gain

class NextSet:
    def __init__(self):
        self.s = {}
    
    def add(self, x):
        self.s[x] = True
    
    def remove(self, x):
        if x in self.s:
            del self.s[x]
    
    def next_ge(self, x):
        # brute over dict keys for simplicity (conceptual DS; CF would use ordered map / sortedcontainers)
        cand = None
        for k in self.s:
            if k >= x and (cand is None or k < cand):
                cand = k
        return cand

def solve():
    n, q = map(int, input().split())
    dsu = DSU()
    active = NextSet()
    answer = 0

    def ensure(x):
        dsu.add(x)
        active.add(x)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, u, v = tmp
            ensure(u)
            ensure(v)
            answer += dsu.union(u, v)

        else:
            _, l, r = tmp
            x = l
            while True:
                x = active.next_ge(x)
                if x is None or x > r:
                    break
                ensure(x)
                y = active.next_ge(x + 1)
                if y is None or y > r:
                    break
                answer += dsu.union(x, y)
                active.remove(y)

        print(answer)
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```DSU はコンポーネントのサイズを追跡し、各マージが新しく接続された頂点ペアの数に正確に寄与することを確認します。 ヘルパー構造は、範囲内でまだアクティブな次の頂点を見つける役割を果たします。そのため、完全な数値区間を反復することはなく、まだ吸収されていない代表部分のみを反復することができます。 

インタラクションのオンラインの性質により、すべてのクエリ後のフラッシュが必要です。そうしないと、ジャッジが出力を待って停止する可能性があります。 

頂点が出現した場合にのみ動的に頂点を追加するという実装の選択により、不可能であるサイズ n の配列を割り当てる試みが回避されます。 

## 実用的な例

 n = 6 の小規模な実行を考えてみましょう。 

最初のクエリはエッジ (1, 5) を追加します。 最初はすべての頂点は個別のコンポーネントです。 1 と 5 を結合すると、接続されているペアは 1 つだけなので、答えは 1 になります。 

| ステップ | 操作 | 影響を受けるコンポーネント | ゲイン | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | (1,5) を追加 | {1}、{5} | 1 | 1 |

 2 番目のクエリは区間 [2, 4] を接続します。 これにより、2、3、4 が 1 つのコンポーネントにマージされ、3 つのペアが提供されます。 

| ステップ | 操作 | 影響を受けるコンポーネント | ゲイン | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | ユニオン2-3 | {2}、{3} | 1 | 2 |
 | 2 | 和集合 (2,3)-4 | {2,3}、{4} | 2 | 4 |

 最後に、(1, 6) を接続すると、以前の状態に応じて 2 つの大きなコンポーネントがマージされます。 

| ステップ | 操作 | 影響を受けるコンポーネント | ゲイン | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 和集合 (1,5)-(6) | {1,5}、{6} | 2 | 6 |

 これらのトレースは、2 つのコンポーネントがマージされるたびに、その寄与が形成された新しいクロス ペアの数と一致することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q α(n) log q) 償却 | 各頂点は一度非アクティブになり、各結合/検索はほぼ一定に償却されます。 
| スペース | O(q) | クエリに出現する頂点のみが保存されます。 

この制約により、全範囲 [1, n] の頂点ごとのスキャンを回避する必要があります。 DSU ベースのマージにより、意味のある各イベントが 1 回ずつ発生することが保証され、ソリューションは 2 · 10^5 クエリまで拡張可能になります。

 ## 特殊なケース

 重大なエッジケースは、範囲クエリが大きく重複する場合です。 [1, 1000000000] を処理し、後で [2, 3] のような部分範囲を再度処理するとします。 単純な解決策では、すべての内部エッジを再追加しようとしますが、DSU ベースの方法では、すべての頂点がすでに 1 つのコンポーネント内にあることがわかり、新しい結合は発生せず、答えは変わりません。 

もう 1 つのエッジ ケースは、既に接続されているコンポーネントを接続する単一エッジ マージの繰り返しです。 たとえば、(1,2) を追加し、次に (2,3) を追加し、さらに (1,3) を追加します。 DSU 実装では、検索操作により 1 と 3 がすでにルートを共有していることが検出されるため、共用体はゲイン 0 を返し、二重カウントを回避します。 

最後の微妙なケースはスパース アクティベーションです。クエリに少数の頂点しか出現しない場合、構造はそれを超えて拡張されることはなく、すべての操作は n ではなく実際に使用される頂点の数に比例したままになります。n が 10^9 であることを考えると、これは重要です。
