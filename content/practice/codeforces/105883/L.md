 ## 解決策
 ## 問題の理解

 整数の配列が与えられるので、サブセグメントに対するクエリに繰り返し答える必要があります。 選択した任意の部分配列について、その要素を 2 つのグループに分割することができます。 1 つのグループはその要素のビットごとの OR を提供し、もう 1 つのグループはその要素のビットごとの AND を提供します。 スプリットのスコアはこれら 2 つの結果の合計であり、可能な限り最高のスプリットが必要です。 

クエリでは配列のセグメントが与えられ、各要素を OR 側または AND 側に割り当てるすべての可能な方法で達成可能な最大スコアを計算する必要があります。 

主な問題点は、各要素が OR と AND の両方に非線形的に影響を及ぼし、すべてのクエリが最大 100 万クエリの任意の範囲に及ぶことです。 これにより、最悪の場合の作業が約 10^11 の演算に達するため、セグメントに対するクエリごとの線形再計算やさらには対数再計算が即座に除外されます。 

この制約は、各要素が何らかの事前計算された構造に寄与する必要があり、各クエリが対数時間または定数時間で応答される必要があることを強く示唆しています。 

いくつかのエッジの動作は過小評価されがちです。 

すべての要素が 0 の場合、グループ化に関係なく OR と AND の両方が 0 になるため、どのパーティションでもスコアは 0 になります。 

セグメントに 1 つの要素 x がある場合、どちらの側でも取れるため、答えは max(x, x) になります。 したがって、答えはただ×です。 

すべての要素が x > 0 に等しい場合、すべてを S1 に配置すると、OR = x、AND = 0、スコア x が得られます。 すべてを S2 に配置すると、OR = 0、AND = x、スコア x になります。 OR と AND の両方が同時に x を超えることはできないため、混合パーティションは x を超えません。 したがって、答えは常に×です。 

これらのケースは、答えの構造が、組み合わせによる分割ではなく、グローバル ビットの動作に密接に結びついていることを示唆しています。 

## アプローチ

 ブルート フォース ソリューションでは、サブ配列の考えられるすべてのパーティションが考慮されます。 長さ m のセグメントの場合、2^m 個の割り当てがあります。 割り当てごとに、一方のサブセットの OR ともう一方のサブセットの AND を計算します。 各スコアの計算は単純に実行すると O(m) 時間がかかるため、単一のクエリは O(m 2^m) になります。これは m が 20 を超える場合にはすでに実行不可能です。 

事前計算されたマスクを使用してパーティションあたりの評価を O(1) に改善したとしても、指数関数的なパーティション数がボトルネックのままです。 

重要な観察は、目的関数がビットごとに分解されるということです。 OR と AND は異なるビット位置間で相互作用することなくビット単位で動作するため、各ビット位置は独立して動作します。 これは、各ビットを個別に考えて、寄与を合計できることを示唆しています。 

b.少し修正します。 各要素には、このビットが設定されているかどうかのどちらかです。 ビット b が設定された要素を S1 に配置すると、OR 側に 2^b が寄与します。 これを S2 に配置すると、S2 内のすべての要素にビット b が設定されている場合にのみ AND に寄与し、それ以外の場合は AND はそのビットを完全に失います。 

これにより、明確な構造上の制約が作成されます。特定のビットについて、S2 にはそのビットをすべて共有する要素のみが含まれるか、そのビットは AND に何も寄与しません。 

これにより、問題は、セグメント内の各ビットを含む要素の数と、それらの要素をどのようにグループ化できるかについての推論に集約されます。 

最後の簡略化は、ビットごとに最適な戦略がローカルであることを理解することで得られます。ビットを持つすべての要素を S1 に配置して OR 寄与を最大化するか、慎重に選択したサブセットを S2 に配置して AND 寄与を維持しようとします。これは、そのサブセットにセグメント内のそのビットを運ぶすべての要素が含まれている場合にのみ有益です。 

これにより、最適な値はセグメント全体の各ビットの周波数パターンにのみ依存し、ビットごとのプレフィックス数を使用して事前計算できるという結論につながります。 

したがって、ビット数を前処理し、O(30) 時間でビットごとの最適な構成を評価することで各クエリに答えます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(m · 2^m) | お(1) | 遅すぎる |
 | ビット分解 + プレフィックス数 | クエリごとに O(30 · 1) | O(30n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列全体の 0 から 29 までのすべてのビット位置のプレフィックスの合計を事前計算します。 これにより、セグメント内の特定のビットが設定されている要素の数をすぐに知ることができます。 
2. 各クエリ セグメント [l, r] について、各ビット b を含むセグメント内の要素の数を計算します。 このカウントを cnt[b] とします。 
3. 各ビット b について、2 つの候補寄与を計算します。 まず、ビット b を持つすべての要素を S1 に代入すると、cnt[b] > 0 の場合、OR は 2^b になります。 次に、AND を保持しようとする場合、AND でビット b が生き残る唯一の方法は、S2 内のすべての要素にビット b が設定されている場合です。これにより、S2 は、セグメント内でビット b が設定されているすべての要素の正確なサブセットになります。 これは、少なくとも 1 つのそのような要素を S2 に配置し、一貫性を確保した場合にのみ 2^b に寄与します。 
4. ビット間の混合戦略が独立していることに注目してください。そのため、各ビットについて、その寄与を OR 経由で取得するか、潜在的な AND 保存経由で取得するかを単純に決定します。 
5. 最終的な答えは、すべてのビットにわたる寄与を合計することによって得られます。ここで、cnt[b] > 0 の場合、各ビットは 2^b に寄与します。すべてのビットは、それを運ぶ少なくとも 1 つの要素を適切に配置することで最適に実現できるため、分割によるさらなるペナルティはありません。 

### なぜ効果があるのか

 OR と AND はビットを混合しないため、各ビット位置は独立しています。 固定ビットの場合、それを AND 側で保持しようとすると S2 が大幅に制限されますが、OR は、そのビットを運ぶ少なくとも 1 つの要素を S1 に含めることによって常に最大化されます。 要素ごとにパーティションを自由に選択できるため、要素を適切に割り当てることで、常にすべてのビットの最適条件を同時に満たすことができます。 これにより、問題が 30 の独立した 2 値決定 (ビットごとに 1 つ) に分離され、その寄与が単純に加算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

B = 30

pref = [[0] * (n + 1) for _ in range(B)]

for i in range(n):
    x = a[i]
    for b in range(B):
        pref[b][i + 1] = pref[b][i] + ((x >> b) & 1)

out = []

for _ in range(q):
    l, r = map(int, input().split())
    res = 0
    for b in range(B):
        if pref[b][r] - pref[b][l - 1] > 0:
            res += (1 << b)
    out.append(str(res))

print("\n".join(out))
```前処理ステップでは、各行がビット位置に対応し、各列がそのインデックスまでにそのビットが何回出現したかを追跡するバイナリ プレフィックス テーブルを構築します。 これにより、クエリ セグメント内の特定のビットを含む要素の数を定数でカウントできるようになります。 

各クエリは単純に 30 ビットすべてをスキャンし、範囲内に少なくとも 1 回出現するビット値を追加します。 そのロジックは、分離可能性により、現在のビットは他のビットからの干渉なしに最適なパーティションで実現できるというものです。 

微妙な点は、パーティションを明示的に構築しないことです。 正確さは、スコアリング関数がセグメント内のビットの配置ではなく、セグメント全体のビットの有無のみに依存するという事実から得られます。 

## 実用的な例

 配列を考慮する`[5, 4, 2]`そしてクエリ`[1, 3]`。 

| ビット | 範囲内のカウント | 貢献 |

 | 0 | 1 | 1 |

 答えは7です。 

これは、複数の要素にわたるビットの重なりが寄与を妨げないことを示しています。 各ビットは独立して寄与します。

| ビット | カウント | 貢献 |
 | --- | --- | --- |
 | 0 | 3 | 1 |

 答えは 1 で、繰り返しによって値が増幅されないことが確認されています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    B = 30
    pref = [[0] * (n + 1) for _ in range(B)]

    for i in range(n):
        x = a[i]
        for b in range(B):
            pref[b][i + 1] = pref[b][i] + ((x >> b) & 1)

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        res = 0
        for b in range(B):
            if pref[b][r] - pref[b][l - 1]:
                res += (1 << b)
        out.append(str(res))

    return "\n".join(out)

# minimal
assert run("1 1\n5\n1 1\n") == "5"

# all equal
assert run("3 1\n7 7 7\n1 3\n") == "7"

# mixed bits
assert run("3 2\n5 4 2\n1 3\n2 3\n") == "7\n6"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 5 | 基本ケースの正確性 |
 | すべて等しい値 | 7 | 重複時の安定性 |
 | 混合ビット | 7 / 6 | 正しいプレフィックス集約 |

 ## 特殊なケース

 単一要素配列の場合`[x]`の場合、プレフィックス ロジックは x に設定されたすべてのビットに対して cnt[b] = 1 を生成し、答えは x になります。 各ビットが正確に 1 回カウントされるため、アルゴリズムは当然正しい結果を返します。 

すべての要素が同一であるセグメントの場合、値に存在するすべてのビットがすべての位置に表示されます。 プレフィックスの差分はゼロ以外のカウントを正しく報告し、合計はインフレなしで同じ数値を再構築し、正しいパーティション動作と一致します。 

次のような互いに素なビット パターンを持つセグメントの場合`[1, 2, 4]`、各ビットはセグメント全体で 1 回だけ出現します。 アルゴリズムはすべての寄与を加算して 7 を生成します。これは、各要素がその固有のビット寄与を維持するために配置される、達成可能な最良の分割に対応します。
