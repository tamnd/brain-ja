 ## 解決策
 ## 問題の理解

 レベルの垂直スタックが与えられ、各レベルには左、中央、右に配置された 3 つの色のブロックが含まれています。 タワーには物理的な制約があります。最上層以外のすべてのレベルに少なくとも 1 つのブロックが残っている場合にのみ安定します。さらに、レベルが中間のブロックではない 1 つのブロックに縮小されると不安定になります。 最上レベルは特別で、ブロックを配置できますが、そこから削除することはできません。 

1 分ごとにサイコロが振られます。 確率 2/3 では緑のブロックを削除することを示唆し、確率 2/3 では青を示唆し、確率 1/6 では赤を示唆し、確率 1/6 では黒を示唆します。 結果が色の場合、可能であればその色のブロックを削除する必要があります。それ以外の場合は何も行いません。 黒は常に何もしないという結果になります。 削除後、ブロックはすぐに最上位に戻され、レベルが完了するか、新しいレベルが開始される可能性がありますが、最上位の構築ルールは厳密に適用されます。 

プレイヤーは、必要な色のどの有効なブロックを削除するかを選択することができ、ゲームの予想される残り時間を最小限に抑えるために常に最適な選択をします。 タワーを安定に保つ合法的な動きが存在しない場合、プロセスは停止します。 

目的は、最適なプレイで終了までの予想される分数を計算することです。 

主要な制約は構造面で非常に厳しく、n は最大 6、各レベルの位置は 3 つだけです。 これは、状態空間が指数動的計画法や構成に対するメモ化された検索に十分小さいことを直ちに示唆しています。 ただし、難しいのは、トランジションが決定的ではないことです。トランジションは、サイコロのランダム性と、複数の取り外し可能なブロックからの戦略的な選択の両方に依存します。 

レベル間でブロックが再配置される方法と組み合わせて状態の数が増加するため、考えられるすべての一連の動きをすぐにシミュレートする単純なアプローチは実行不可能になります。 n が小さい場合でも、各レベルは削除されるブロックに応じて複数の方法で進化する可能性があり、レベルの中央以外の最後のブロックを削除すると不安定になる可能性があるため、順序が重要になります。 

レベルに残りのブロックがちょうど 2 つあり、両方がサイド ブロックである場合、微妙なエッジ ケースが発生します。 どちらかを削除するとレベルが崩壊し、そのレベルからのそれ以上の削除は無効になります。 「中央のみ最後のブロック」ルールを適用しない単純な貪欲シミュレーションでは、誤って無効な状態が許可されてしまいます。 もう 1 つの失敗例は、同じ色の複数の取り外し可能なブロックが異なるレベルに存在する場合です。これは、間違ったブロックを選択すると、初期のデッド ステートにつながり、期待が大きく変わる可能性があるためです。 

## アプローチ

 ブルート フォース ソリューションでは、タワーのすべての構成を状態として扱い、ゲームを再帰的にシミュレートします。 与えられた状態から、考えられるすべてのサイコロの出目とすべての有効な除去の選択肢を列挙し、結果として生じるすべての状態に分岐し、再帰によって期待値を計算します。 これは原理的には正しいですが、各ブロックはレベル間で繰り返し移動でき、上部の構造により自由度が追加されるため、到達可能な構成の数は爆発的に増加します。 メモ化であっても、削除するブロックの選択による分岐要素は大きくなる可能性があり、状態は残りのブロックだけでなく、部分的なトップレベルの構築状態によっても異なります。

重要な観察は、ブロックは移動しますが、合法性にとって重要なのは、レベルごとに残っているブロックの複数セットと、レベルが「危機的な状態」（1 つのブロックが残っており、中間ではない）かどうかだけであるということです。 n ≤ 6 であるため、各レベルは構造的に独立しており、各レベルを 3 ビット マスクとしてエンコードできます。 これにより、各レベルは 8 つの可能性に減らされ、タワー全体のサイズは最大 8^6、つまり約 260,000 のステートになり、DP には十分小さいです。 

次に、状態に対する期待値 DP として問題を組み立てます。この場合、遷移は削除する有効なブロックの選択に依存します。 各状態と各色について、プレイヤーは期待される最良の継続につながるブロックを選択します。 これにより、期待値内にミニマックスのようなレイヤーが導入されます。各色のイベントについて、有効な選択肢の最小値を取得し、サイコロの確率を平均します。 

これにより、問題は、遷移に埋め込まれた最適なアクション選択を備えた有限状態グラフ上の決定論的な DP に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 構成に対するブルート フォース シミュレーション | 指数関数的、無制限 | 指数関数 | 遅すぎる |
 | ミニマックス遷移によるレベル状態上の DP のマスク | O(8^n · 遷移) | O(8^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各レベルを 3 ビットのマスクとして表します。ビット 0 が左、ビット 1 が中央、ビット 2 が右です。 1 は、ブロックがまだ存在していることを意味します。 完全な状態は、n 個のマスクのタプルです。 

関数を定義します`solve(state)`これは、その構成から開始される予想される残りの分数を返します。 

1. この状態で正当な手が存在しない場合は、0 を返します。移動後の削除が安定性ルールに違反しないブロックが少なくとも 1 つある場合、正当な手が存在します。 
2. 状態ごとに、色ごとにグループ化された有効なアクションのセットを計算します。 色 c について、最上位以外のすべてのレベルを有効に保ちながら、削除できるその色のすべてのブロックを識別します。 ブロックを削除した後、影響を受けるすべてのレベルにまだ少なくとも 1 つのブロックがあり、単一の非中間ブロックになるレベルがない場合、削除は有効です。 
3. 各色 c について、除去後の最良の結果の期待値を計算します。 プレーヤーが最適な選択をするため、その色のすべての有効なブロックの最小値を取得します。 

結果として得られるすべての状態を評価し、予想される残り時間が最小のものを選択します。 
4. 期待値の繰り返しはサイコロから構築されます。 

赤の確率は 1/6、緑は 1/3、青は 1/3、黒は 1/6 です。 黒の場合、状態は変化しません。 

それで:

 期待値 = 1 + (1/6) * E(赤のアクション後の状態)

 + (1/3) * E(緑のアクション後の状態)

 + (1/3) * E(青のアクション後の状態)

 + (1/6) * E(現在の状態)

 黒は自己ループを導入するため、この方程式を整理して E(state) を分離します。 
5. 結果として得られる線形方程式を状態ごとに解きます。 

E(状態) = (1 + 次の状態の加重合計) / (1 - 1/6)
 6. アクセスされたキャッシュを持つ DFS を使用して、再計算を避けるために結果をメモ化します。 

実装の重要な詳細は、期待方程式を作成する前に「色ごとの最適なアクション」を計算する必要があることです。 期待内でアクションの選択を混在させると、不正確な平均化が発生します。 

### なぜ効果があるのか

 すべての状態で、このプロセスは、黒の結果による割引のような自己ループを伴う有限マルコフ決定プロセスを定義します。 状態空間は有限であり、すべての遷移は制御された方法で最終的にブロック数を削減または維持するため、期待方程式は一貫したシステムを形成します。 DP は、最適なポリシーの選択に基づいて、これらの方程式の一意の固定点を計算します。 アクションの最小化により、プレーヤーは常に予想される残り時間を最小限に抑えるトランジションを選択できるようになり、メモ化により部分問題解決策の一貫した再利用が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

# encode levels as masks
# bit 0 = left, bit 1 = mid, bit 2 = right

from functools import lru_cache

n = int(input())
levels = []
for _ in range(n):
    s = input().strip()
    mask = 0
    if s[0] != '.': mask |= 1
    if s[1] != '.': mask |= 2
    if s[2] != '.': mask |= 4
    levels.append(mask)

# color mapping per position is fixed in input
# we precompute positions by color per level
colors = []
for _ in range(n):
    s = input().strip()
    colors.append(s)

# actually input already encodes colors directly per position

def get_color(level, pos):
    return colors[level][pos]

# check stability constraint for a level mask
def valid_level(mask):
    if mask == 0:
        return False
    if mask in (1, 2, 4):
        return False
    return True

def ok_state(state):
    # all non-top levels must be valid
    for i in range(n):
        if i == n - 1:
            continue
        if not valid_level(state[i]):
            return False
    return True

@lru_cache(None)
def dp(state):
    # state is tuple of masks bottom..top or top..bottom depending consistency
    st = list(state)

    # check terminal: no valid move
    moves_exist = False
    for i in range(n):
        for j in range(3):
            if not (st[i] >> j) & 1:
                continue
            # simulate removal
            new = st[:]
            new[i] ^= (1 << j)
            if ok_state(new):
                moves_exist = True
                break
        if moves_exist:
            break

    if not moves_exist:
        return 0.0

    # expected transitions per color
    best = {'R': float('inf'), 'G': float('inf'), 'B': float('inf')}

    for c in best:
        # try all removals of color c
        for i in range(n):
            for j in range(3):
                if st[i] >> j & 1 and get_color(i, j) == c:
                    new = st[:]
                    new[i] ^= (1 << j)
                    if ok_state(new):
                        best[c] = min(best[c], dp(tuple(new)))

    # probabilities
    pR, pG, pB, pK = 1/6, 1/3, 1/3, 1/6

    exp_next = 0.0
    exp_next += pR * best['R'] if best['R'] < float('inf') else 0
    exp_next += pG * best['G'] if best['G'] < float('inf') else 0
    exp_next += pB * best['B'] if best['B'] < float('inf') else 0
    exp_next += pK * dp(tuple(st))

    return (1 + exp_next) / (1 - pK)

initial = tuple(levels)
print(dp(initial))
```DP は、ビットマスク状態に対するメモ化された再帰を中心に構築されています。 各レベルはコンパクトにエンコードされ、ビットを反転することで遷移が生成されます。 安定性チェックでは、移動後に無効になるレベルがないように強制され、特に単一の非中間ブロックが防止されます。 

微妙な点は、色ごとに最適な手を選択することと、その後サイコロの確率を適用することとの間の分離です。 コードは最初に計算します`best[c]`色の移動後に達成可能な最小期待値として`c`、次にそれらの値を期待方程式に代入します。 

による除算`(1 - pK)`黒の結果によって発生した自己ループを解決します。これにより、状態は変更されないままになりますが、依然として時間がかかります。

 ## 特殊なケース

 クリティカルなエッジケースは、削除後にちょうど 1 ブロックになるレベルです。 たとえば、レベルに左右のブロックしか残っていない場合、そのうちの 1 つを削除すると、その状態はすぐに無効になります。 の`ok_state`check はこれを強制し、DP が不正な設定に入るのを防ぎます。 

もう 1 つのエッジ ケースは、要求された色のブロックが存在しない場合です。 その場合、期待値は確率によって正しく重み付けされた「何もしない」分岐に戻らなければなりません。 再帰化では、黒の自己ループ項をそのまま維持しながら、不可能な手に対する寄与をゼロに割り当てることでこれを処理し、期待方程式の一貫性を確保します。
