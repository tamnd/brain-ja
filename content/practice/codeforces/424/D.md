 ## 解決策
 ## 問題の理解

 各セルに高さがある長方形のグリッドが与えられます。 バイアスロン トラックはサブ長方形の境界でなければならず、アスリートはこの境界に沿って時計回りに走ります。 すべての移動は周囲の隣接するセル間で行われるため、総コストは長方形の境界線に沿った高さの変化に完全に依存します。 

境界線に沿った各ステップにかかる時間は、アスリートが上がるか、下降するか、または平らに留まるかによって異なります。 より高いセルコストへの移行`t_u`、より低いコストに移行する`t_d`、同じ高さで移動するとコストがかかります`t_p`。 長方形の合計時間は、時計回りの順序ですべての連続する周囲の移動にわたるこれらのコストの合計です。 

左上隅と右下隅が有効な部分行列を定義する長方形を選択する必要があります。 各辺には少なくとも 3 セルの長さが必要です。これにより、周囲が意味のある構造を持つことが保証され、縮退ループが回避されます。 すべての有効な長方形の中で、走査時間がターゲット値に最も近い長方形が必要です。`t`。 

重要な点は、グリッド サイズが 300 x 300 まで大きくなり、約 90,000 個のセルが存在する可能性があるということです。 すべての長方形の単純な列挙はすでに約 O(n^2 m^2) と大きく、これはおよそ 10^10 個の候補に相当します。各長方形の周囲コストを計算すると、別の係数 O(n + m) が乗算されますが、これはまったく実行不可能です。 

微妙な問題は、周囲に、上の行、下の行、左の列、右の列という繰り返し構造が含まれていることです。 不注意ですべての四角形の高さの差を最初から再計算すると、中程度の入力を処理する前にソリューションがタイムアウトになってしまいます。 

もう 1 つの落とし穴は境界制約にあります。 各辺の長さは少なくとも 3 でなければならないため、幅 1 または 2、高さ 1 または 2 の長方形は除外する必要があります。 この制約を忘れると、人為的に短い周囲長により、無効な候補が最適と誤って表示される可能性があります。 

最後に、方向が重要です。時計回りに移動するため、コーナーに沿った遷移は 1 回だけ含まれます。 実装を不注意にすると、コーナー遷移を二重にカウントしたり、エッジ間の隣接関係を誤って処理したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 左上隅と右下隅を選択して、考えられるすべての長方形を列挙します。 各長方形について、その周囲に沿って歩き、連続する各セルのペアを比較することによって総コストを計算します。 これはパスの定義に直接従うため、正しいです。 

ただし、長方形の数は O(n^2 m^2) です。 各長方形の周囲の長さは O(n + m) であるため、合計の複雑さは O(n^2 m^2 (n + m)) になります。これは、n、m の許容限界をはるかに超えています (最大 300)。 

重要な洞察は、境界コストを最初から再計算することは避けるべきだということです。 代わりに、2 つの行を修正し、問題を列にわたる 1D 構造に圧縮します。 行の固定ペアの場合、列ごとにこれらの行間の垂直エッジの寄与を事前計算し、行に沿った水平遷移を個別に維持できます。 これにより、長方形のコストが、長方形を水平に拡張するときに効率的に更新できる関数に変換されます。 

重要な考え方は、上部と下部の行を固定する場合、長方形を l 列から r 列に拡張すると、2 つの垂直エッジ (l と r の位置) と 2 つの水平セグメント (上部と下部の行) が追加されるだけであるということです。 これらの寄与は O(1) 単位で段階的に更新できるため、行ペアごとに O(m^2) 単位ですべての間隔をスキャンできます。 これにより、完全な解は O(n^2 m^2) に減りますが、定数ははるかに小さくなり、全周の再計算は行われません。 

次に、コストがターゲットに最も近い長方形を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 m^2 (n + m)) | お(1) | 遅すぎる |
 | 固定行 + スライド列 | O(n^2m^2) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 行を固定します`top`そして`bottom`そのような`bottom - top + 1 ≥ 3`。 これにより、長方形の高さが有効になることが保証されます。 
2. 各列について、次の間の垂直遷移コストを事前計算します。`(top, col)`そして`(bottom, col)`。 これは、その列境界でこれらの行にまたがる四角形の 2 つの垂直エッジを表します。 
3. 行の固定ペアの場合、列に対するスライディング ウィンドウを初期化します。 現在の長方形にまたがるコストを維持します。`[left, right]`。 
4. 拡張するにつれて`right`、以下からの貢献を追加します。 

からの上端の動き`(top, right-1)`に`(top, right)`、

 からの下端の動き`(bottom, right-1)`に`(bottom, right)`、

 列の垂直エッジ`right`。 

これらはそれぞれ、高さの比較と指定されたコスト ルールを使用して計算されます。 
5. 幅が有効になったら (`right - left + 1 ≥ 3`)、コストとターゲットを比較することで現在の長方形を評価します。`t`, 絶対的な差が改善された場合は、ベストアンサーを更新します。 
6. 必要に応じて、左側から縮小してすべての間隔を調査し、列を削除するときに対称的に更新を維持することもできます。`left`。 
7. すべての有効な行ペアに対して繰り返し、常に見つかった最良の四角形を追跡します。 

### なぜ効果があるのか

 すべての四角形は、上行、下行、左列、右列によって一意に定義されます。 このアルゴリズムは、すべての有効な上下行ペアと各ペアのすべての有効な列間隔を列挙します。 このような構成ごとに、境界コストは再計算ではなく増分更新を使用して 1 回だけ計算されます。 すべての境界エッジはスライド プロセスで 1 回だけ考慮されるため、長方形が見逃されることも、遷移が二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost(a, b, tp, tu, td):
    if a == b:
        return tp
    return tu if b > a else td

n, m, T = map(int, input().split())
tp, tu, td = map(int, input().split())
h = [list(map(int, input().split())) for _ in range(n)]

best_diff = 10**30
ans = (1, 1, 3, 3)

for top in range(n):
    for bottom in range(top + 2, n):

        col_vert = [0] * m
        for j in range(m):
            col_vert[j] = cost(h[top][j], h[bottom][j], tp, tu, td)

        cur = 0

        for left in range(m):
            cur = 0
            right = left
            while right < m:
                if right > left:
                    cur += cost(h[top][right - 1], h[top][right], tp, tu, td)
                    cur += cost(h[bottom][right - 1], h[bottom][right], tp, tu, td)

                cur += col_vert[right]

                if right - left + 1 >= 3:
                    diff = abs(cur - T)
                    if diff < best_diff:
                        best_diff = diff
                        ans = (top + 1, left + 1, bottom + 1, right + 1)

                right += 1

    # vertical edges are independent of left-right window, no reset needed

print(*ans)
```この実装では、行のペアを固定し、それらの行間の垂直遷移の列方向のコストを計算します。 内側のループは、右側の境界を拡張し、寄与を蓄積することによって長方形を構築します。 機能`cost`移動ルールをクリーンにエンコードし、分岐ロジックの繰り返しを回避します。 

スライディング プロセスは単純な展開ループで処理されます。これは完全な 2 ポインター構造よりも単純ですが、行ペアの境界ごとに O(m^2) が尊重されます。 

幅が少なくとも 3 になり、問題の制約に一致した場合にのみ長方形の評価を開始するように注意する必要があります。 行インデックスは、最後に 1 から始まるインデックスに変換されます。

 ## 特殊なケース

 重要なエッジケースは、すべての高さが等しい場合です。 この状況では、あらゆる移動にコストがかかります`t_p`したがって、最良の長方形とは、単純に周囲長の合計が最も近い長方形になります。`t`。 アルゴリズムはこれを自然に処理します。`cost`call は同じ値を返すため、特殊な場合のロジックは必要ありません。 

もう 1 つのケースは、高さまたは幅が正確に 3 に等しい最小の有効な長方形です。アルゴリズムは明示的にチェックします。`right - left + 1 >= 3`したがって、これらの四角形はウィンドウが有効になると含まれ、スキップされたり二重にカウントされたりしません。 

3 番目のケースは、すべてのエッジが上りか下りのいずれかである急勾配です。 各遷移が隣接するセルに対してローカルであるため、増分更新は引き続き機能します。そのため、極端な高さの違いであっても、オーバーフローや再計算エラーが発生することなく処理されます。
