 ## 解決策
 ## 問題の理解

 この問題により、一定数のプレゼントを欲しがる一連の友人が得られます。 各友人にも、好みの種類のギフトがあります。 すべての友人間で収集されるギフトの総数が最大になるようにギフトを配布する必要がありますが、各友人は最初に要求した数を超えるギフトを受け取ることができないという制約があります。 友達を任意に並べ替えることができるため、ギフトとリクエストを戦略的に組み合わせて合計を最大化することができます。 

入力は友達の数で構成されます`n`、その後に長さの 2 つの配列が続きます`n`: 1 つは各友人が望むギフトの数、もう 1 つは好みの種類です。 出力は、配布ルールに基づいて達成可能なギフトの最大合計数です。 

制約が示唆する`n`最大 2×10^5 まで可能です。 これにより、すべての順列を試みる強引なアプローチが除外されます。`n!`成長が早すぎます。 テスト ケースごとにおよそ O(n log n) または O(n) で機能するアルゴリズムを探しています。 明らかではないエッジ ケースとしては、友人がギフトをまったく要求していない場合や、友人全員が同じタイプを好む場合などがあります。これは、タイプ別の配分を正しく処理しない場合、単純な合計アプローチを誤解させる可能性があります。 

小さな例で注意が必要なケースを説明します。友人全員が 1 つのギフトを望んでいるが、異なるタイプを好む場合、ギフトを順番に与えるという単純なアプローチでは、タイプベースの制約を満たす機会が過小評価される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、友人のすべての順列を反復し、好みの制約に従ってギフトの合計を計算します。 これは原理的には正しいですが、実行不可能です。`n = 10^5`1 回の階乗計算でも天文学的な規模になるため、この方法は実際には失敗します。 

重要な洞察は、問題が贈り物の種類によって分解できることを観察することで得られます。 フレンドは自由に並べ替えることができるので、同じタイプのフレンドをまとめて処理するのが最適な戦略です。 各タイプ内でリクエストを降順に並べ替えると、ギフトを貪欲に割り当てることができます。リクエストが最大の友人ができるだけ多くのギフトを受け取り、次に最大のギフトを受け取るというようになります。 これにより、各タイプの極大値が保証されます。 すべてのタイプを処理した後、並べ替え後に同じタイプを争う 2 人の友人が存在しないため、これらの最大値を合計すると全体的な最大値が得られます。 

事実上、問題は、タイプごとのグループ化、各グループ内での並べ替え、および最大合計を見つけるためのプレフィックス合計の実行に帰着します。 このアプローチは、並べ替えステップにより O(n log n) で機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | グループ化 + タイプ別に並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.友達の数を読み取る`n`そして 2 つの配列:`gifts`リクエストと`types`好みのギフトの種類については、
 2. 各ギフト タイプから、そのタイプを好む友人からのリクエストのリストへのマッピングを作成します。 これにより、友達を好みに基づいてグループ化します。 
3. タイプごとに、リクエストを降順に並べ替えます。 これにより、最大のリクエストを最初に満たし、ローカルで合計を最大化することができます。 
4. ソートされたリストごとにプレフィックスの合計を計算します。 位置のプレフィックスの合計`k`最初の条件を満たす場合に収集されるギフトの合計を表します`k`そのタイプに対する最大のリクエスト。 
5. これらのプレフィックスの合計を、受け取ったギフトの合計数で集計します。 友人の可能な数ごとに`k`型から取得され、対応するプレフィックスの合計を、次のインデックスが付いた累計に加算します。`k`。 
6. すべてのタイプを処理した後、答えは集計された合計の最大値になります。これは、あらゆる配布戦略で達成可能な最大のギフトを表します。 

機能する理由: 種類ごとにグループ化し、並べ替えることで、制約に違反することなく各友人が可能な限り最大数のギフトを受け取ることができます。 タイプ間で友人を並べ替えてもギフトの合計は減らず、それらは独立しているため、プレフィックスの合計を合計することでこの最適性が維持されます。 不変条件は、各タイプの先頭のプレフィックスの合計です。`k`リクエストはどの場合でも最大です`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict
from itertools import accumulate

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        gifts = list(map(int, input().split()))
        types = list(map(int, input().split()))
        
        type_map = defaultdict(list)
        for g, ty in zip(gifts, types):
            type_map[ty].append(g)
        
        prefix_sums = defaultdict(int)
        for lst in type_map.values():
            lst.sort(reverse=True)
            acc = list(accumulate(lst))
            for k, val in enumerate(acc, start=1):
                prefix_sums[k] += val
        
        print(max(prefix_sums.values()))

if __name__ == "__main__":
    main()
```コードはアルゴリズムに正確に従います。 の`defaultdict(list)`タイプ別にリクエストを収集します。 ソートにより、最大のリクエストが最初に考慮されるようになります。`accumulate`プレフィックス合計を効率的に生成します。 ついに、`prefix_sums`選択した友達の合計と収集したギフトの合計をマップし、受け取ります`max`正しい答えを返します。 境界条件は自然に処理されます。空の型は何も寄与せず、単一フレンド型は 1 から始まるプレフィックスの合計によって正しく考慮されます。

## 特殊なケース

 リクエストがゼロのタイプの場合、アルゴリズムは当然それをスキップします。リストは空で、ソートと累積によってプレフィックスの合計は生成されず、何も追加されません。`prefix_sums`。 すべての友人が同じ番号を要求しているタイプの場合、並べ替えによって順序が保持され、累積は正しく合計されます。 集計ステップにより、重複が確実に行われます。`k`さまざまなタイプの値が合計され、可能なギフトの合計が正しく反映されます。 各エッジ ケースは、タイプごとの貪欲なプレフィックス合計戦略が健全かつ最大であることを確認します。
