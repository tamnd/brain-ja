 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられ、これらの点を単一のシーケンスで接続して折れ線を描くように求められます。 各点は、描画されたポリラインの頂点として 1 回だけ使用する必要があり、結果として得られるセグメントは、問題の幾何学的規則に従って無効な自己交差を作成してはなりません。 出力は数値ではなく構造であり、通常は点の順序や点の接続方法の説明です。 

概念的には、このタスクは点を単純な多角形のチェーンに配置することです。 重要な問題は、ポイントを任意に順序付けるとほとんどの場合セグメントの交差が発生するため、中心となる制約が入力形式ではなくジオメトリに隠されてしまうことです。 

制約が十分に大きいため、すべての順列を試行する解決策は直ちに不可能になります。 n が中程度の値であっても、階乗探索は使用できなくなります。2e5 付近の n はすでに天文学的に大きな探索空間を意味するからです。 これにより、およそ O(n log n) または O(n) で実行される決定論的な構築が強制されます。 

いくつかの特殊なケースでは、素朴なアプローチが崩れる傾向があります。 複数のポイントが同じ x 座標を共有する場合、純粋に水平方向の並べ替え戦略は、重複する垂直セグメントに崩壊する可能性があり、ジオメトリ ルールの厳密さによっては無効と解釈される可能性があります。 点が同一線上にある場合、恣意的な順序付けにより縮退オーバーラップが発生する可能性があり、解釈によっては依然として不正確と見なされます。 もう 1 つの微妙なケースは、点が「ジグザグ」形状を形成する場合です。この場合、1 つの座標だけでソートすると、局所的な構造ではすぐに明らかではないものの、グローバルに現れる交差が生じます。 

## アプローチ

 ブルートフォースの考え方は単純です。考えられるすべての点の順序を試し、その順序で点を接続し、セグメントの交差が発生するかどうかを確認します。 これは条件を直接強制するため機能しますが、正確さには n 個の階乗順列すべてを列挙するという犠牲が伴います。 n = 10 の場合でも、これはすでに非現実的であり、それを超えるとまったく実行不可能になります。 

重要な観察は、実際にはすべての順列を検索する必要はないということです。 交差しない多角形チェーンを保証する順序を 1 つだけ必要とします。 これにより、問題は組み合わせ検索から幾何学的構造化に縮小されます。 このような問題における標準的なトリックは、1 つの座標系での単調順序付けを利用することです。 点を x 座標で辞書編集的に並べ替え、y 座標を使用して同点を解消すると、左から右に着実に進むシーケンスが得られます。 この単調性により、単純な順序付けにおける交差の主な原因であるエッジが x 方向に「ループバック」しないことが保証されます。 

このようにポイントが並べ替えられると、連続するポイントを接続すると、平面内でグローバルな順序を尊重するチェーンが生成されます。 交差の可能性がある場合は、ソート順序の違反を意味しますが、これは不可能です。

 ## アルゴリズムのチュートリアル

1. 出力の再構築に必要な場合は、すべてのポイントを読み取り、元のインデックスとともに保存します。 これが必要なのは、この問題では通常、インデックスまたは座標を特定の順序で出力することが求められるためです。 
2. 点を X 座標で並べ替えます。 2 つの点が同じ x 座標を共有する場合は、y 座標を使用して結合を解除します。 これにより、平面内のすべての点にわたって厳密な合計順序付けが保証されます。 
3. ソートされたリストを左から右にたどって、その順序で点を必要な多角形チェーンとして出力します。 連続する各ペアがセグメントを形成します。 
4. 順番に描かれたこれらのセグメントを概念的に解釈します。 この構造により、交差の主な原因となる、以前に使用された X 領域をまたがってセグメントが「折り返す」必要がないことが保証されます。 
5. 結果のシーケンスを問題で必要な形式 (通常はインデックスまたは座標) で出力します。 

機能する理由: 並べ替えられた順序により、x 方向に単調なチェーンが生成されます。 2 つのセグメント間の交差は、2 つの点のペアが x 軸に沿ったグローバル順序に違反していることを意味し、並べ替えと矛盾します。 これにより、構築されたポリラインが必要な意味で単純であることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append((x, y, i + 1))

    pts.sort()  # lexicographic by x, then y

    # output order of indices
    print(*[p[2] for p in pts])

if __name__ == "__main__":
    solve()
```実装の中核は辞書編集的なソートです。 Python のタプル順序付けは、追加のコードを必要とせずに、必要なタイブレークを自然に処理します。 唯一の微妙な点は、元のインデックスを確実に保持することです。これは、ほとんどの構成的なジオメトリ問題では、座標を出力するのではなく、元の入力点を参照する必要があるためです。 

## 実用的な例

 ### 例 1

 入力ポイントが次のとおりであるとします。 

(2, 3)、(1, 5)、(3, 1)

 x、y の順に並べ替えると、順序は次のようになります。 

| ステップ | 並べ替え順 |
 | --- | --- |
 | 並べ替え後 | (1,5) → (2,3) → (3,1) |

 あとはこの順番で接続していきます。 各ステップは X 座標で厳密に右方向に移動するため、セグメントが交差することはありません。そのため、チェーンが水平方向に 2 倍になることはありません。 

これは、ポリラインが x 内で単調に進行するという不変式を裏付けます。 

### 例 2

 共有の x 座標を持つ点を考慮します。 

(1, 1)、(1, 4)、(2, 2)、(2, 5)

 並べ替え後:

 | ステップ | 並べ替え順 |
 | --- | --- |
 | 並べ替え後 | (1,1) → (1,4) → (2,2) → (2,5) |

 垂直方向の配置が存在する場合でも、y によるタイブレークにより一貫した順序が保証されます。 結果として得られるチェーンは、方向を反転することなく x = 1 から x = 2 に移動するため、交差は発生しません。 

これは、等しい x 値が構造を壊さないことを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    n = int(input())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append((x, y, i + 1))
    pts.sort()
    return " ".join(str(p[2]) for p in pts)

# minimum size
assert run("1\n0 0\n") == "1"

# simple increasing
assert run("3\n1 1\n2 2\n3 3\n") == "1 2 3"

# same x coordinates
assert run("3\n1 3\n1 1\n1 2\n") == "2 3 1"

# mixed coordinates
assert run("4\n2 1\n1 5\n3 2\n2 0\n") == "4 1 2 3"
```| テスト入力 | 期待される出力 | 検証内容 |

 | シングルポイント | 1 | 最小境界の場合 |

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が同じ x 座標を共有する場合です。 このような状況では、二次ソートを無視する単純なアプローチでは、それらを任意の順序で出力し、縮退した重複が発生する可能性があります。 辞書編集的ソートでは、順序は y 座標によって完全に決定されるため、チェーンは有効で一貫したままになります。 

(1,0)、(3,1)、(2,2)、(4,3) など、点が x 座標で左右に交互に配置される場合、別のエッジ ケースが発生します。 入力順序に従って単純に貪欲なウォークを行うと、前後のジグザグが発生し、交差が発生する可能性があります。 ソートは、x に単一のグローバルな方向を強制することでこの不安定性を排除するため、構築されたチェーンは入力の順序に関係なく単調で安全になります。
