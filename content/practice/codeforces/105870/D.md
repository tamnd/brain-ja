 ## 解決策
 ## 問題の理解

 小さなアルファベットの上に 3 つの固定文字列が与えられ、それらを、どのサブシーケンスが制約された意味で「利用可能」であるかを定義する参照シーケンスとして扱います。 次に、複数のクエリ文字列が与えられ、クエリ文字列ごとに、ある長さの範囲内で、3 つの参照文字列の和集合にすでに存在するものよりも異なるサブシーケンスが含まれているかどうかを判断する必要があります。 

ここでのサブシーケンスとは、残った文字を並べ替えずに文字を削除できることを意味します。 2 つのサブシーケンスは、文字シーケンスが異なる場合、たとえソース文字列内の異なる位置からのものであっても、別個のものとみなされます。 

キー入力関係は非対称です。 文字列 x、y、z は固定で小さいですが、各クエリ文字列 s は大きくなる可能性があるため、個別に処理する必要があります。 アルファベットのサイズは一定で、具体的には 4 で、関連するサブシーケンスの最大長は 60 によって制限されます。この制限は、動的プログラミングを使用して固定長までのすべてのサブシーケンスの列挙を可能にするため、重要です。 

単純なアプローチで s のすべての部分列を列挙しようとすると、その数は |s| で指数関数的に増加し、|s| のような一般的な制約では 1 つのクエリさえ不可能になります。 最大 10^5。 ビットマスキングや再帰を介してサブシーケンスをカウントすることさえ、すぐには実行不可能になります。 これにより、x、y、z から構造限界を事前に計算し、圧縮された形式で s をそれらの限界と比較するという戦略が推進されます。 

微妙なエッジ ケースは、サブシーケンスが決定において長さに依存することです。 たとえば、文字列には、x、y、z ですでにカバーされている多くの短いサブシーケンスが含まれている可能性がありますが、より長い部分のみが異なります。 長さでグループ化せずにすべてのサブシーケンスを誤って集計すると、 s が基準容量を超える最初の長さを検出できなくなります。 

s が x、y、または z のいずれかとまったく同じである場合、別の問題が発生します。 この場合、 s のすべての部分列はすでにカバーされているため、長さに関係なく、答えは常に負でなければなりません。 「x、y、z の少なくとも 1 つ」クロージャーを保証せずに raw カウントのみを比較するソリューションでは、重複するサブシーケンス セットを誤って処理する可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 x、y、z のそれぞれについて、長さ 60 までのすべてのサブシーケンスを生成し、それらを重複排除して、和集合を保存できます。 次に、クエリ文字列 s ごとに、長さ 60 までの s のすべてのサブシーケンスを生成し、事前計算されたセットに欠落しているものがないかどうかを確認できます。 

これは正しいですが、複雑さの点ですぐに失敗します。 長さ n の文字列には 2^n 個の部分列があるため、n = 50 であっても、すでに約 10^15 個の可能性が生じます。 長さ ≤ 60 に制限したとしても、組み合わせ爆発は依然として指数関数的です。 ブルートフォース手法は、意味のある計算が行われる前に無効になります。 

重要な観察は、アルファベットが小さく、サブシーケンスの構造が相対的な順序付けの制約にのみ依存するということです。 サブシーケンスを明示的に列挙する代わりに、文字列内に各長さの個別のサブシーケンスがいくつ存在するかを数えることができます。 さらに重要なのは、最大 60 までの長さ ℓ ごとに、その長さの異なる部分列が x、y、または z でいくつ達成可能かを知る必要があるだけです。 

位置と最後に使用された文字の状態に対する動的プログラミングを使用して、x、y、z の和集合に対してこれらのカウントを 1 回計算します。 アルファベットのサイズ K は 4、M は 60 であるため、文字間の遷移を考慮しながら、各長さのサブシーケンスがいくつ存在するかを追跡する DP を維持できます。 これにより、編集注記に記載されているように、指数構造が O(K · M^4) スタイルの計算に圧縮されます。これは、K と M の両方が小さい定数であるため実現可能です。

各クエリ文字列 s について、s に現れる各長さ ℓ ≤ 60 の個別のサブシーケンスの数を計算します。 これは、 をスキャンし、長さと最後の文字の状態によってサブシーケンスを追跡する DP を更新することによって行われます。 各文字について、制限された長さの DP 状態のみを更新するため、これには O(K · M · |s|) のコストがかかります。 

最後に、カウントを比較します。 任意の長さ ℓ に対して、 s が x、y、z の和集合よりも厳密に長さ ℓ の異なる部分列を持つ場合、 s はそれらのいずれにも存在しない部分列を含まなければなりません。 

このロジックが機能するのは、部分列の包含が単調であるためです。部分列が x または y または z に存在する場合、それは事前計算された和集合にもカウントされるため、s の超過は必然的に真に新しい部分列に対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 文字列ごとに O(2^n) | O(2^n) | 遅すぎる |
 | 長さによる DP カウント | O(K·M^4 + | s | ·K·M) クエリごと |

 ## アルゴリズムのチュートリアル

 ソリューションを x、y、z の前処理フェーズと、各 s のクエリ フェーズに分割します。 

1. 関心のある最大サブシーケンス長として M = 60 を固定します。 すべての決定はこの制限された範囲内で決定されるため、これより長いサブシーケンスは比較には無関係です。 
2. x、y、z のそれぞれについて、そしてそれらの和集合について、1 から M までのすべての ℓ について、長さ ℓ の異なる部分列の数を計算します。これは、プレフィックスを拡張し、最後の文字の遷移によって区別性を確保することによって部分列がどのように形成されるかを追跡する DP を使用して行われます。 これを効率的に実行できる理由は、アルファベットのサイズが一定であるため、状態遷移が制限されたままであるためです。 
3. x、y、z の結果を 1 つの参照テーブルにマージします。 サブシーケンスがそれらの少なくとも 1 つに出現するかどうかのみを気にするため、生のカウントではなく、到達可能なサブシーケンスのレベルで結合を取得します。 これにより、重複するサブシーケンスを二重にカウントすることが回避されます。 
4. 各クエリ文字列 s について、含まれる各長さ ℓ の異なるサブシーケンスの数をカウントする s 上の DP を計算します。 一意性と正しい拡張子のカウントを確保するにはこれで十分であるため、現在の長さと最後に使用された文字によってインデックス付けされた状態を維持します。 
5. これらのカウントを計算した後、 を参照テーブルと比較します。 count_s[ℓ] > count_ref[ℓ] となるような ℓ が存在する場合、s には x、y、z に存在しない部分列が含まれていると直ちに結論付けられます。 
6. それ以外の場合、s のすべての部分列は、x、y、z の和集合内ですでに表現可能です。 

### なぜ効果があるのか

 正確さは、長さ方向の優位性の特性に依存します。 参照テーブルは、x、y、z 内で達成可能な各長さの個別のサブシーケンスの最大数を表します。 s が任意の長さ ℓ でこの境界を超える場合、参照内のすべての有効な部分列が既に境界内に考慮されているため、s には参照セット内で形成できない部分列が含まれている必要があります。 部分シーケンスは文字の順序とアルファベットの遷移によって完全に決定されるため、長さによってカウントすると、比較に必要なすべての構造上の区別が捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ALPH = 4
M = 60

def build_dp(strings):
    dp = [[[0] * (ALPH + 1) for _ in range(M + 1)] for __ in range(len(strings) + 1)]

    # We will instead flatten union DP over all strings conceptually.
    # For clarity, we compute per string and merge counts of reachable subsequences.

    def solve_one(s):
        # dp[len][last] = number of subsequences of length len ending with last
        dp = [[0] * (ALPH + 1) for _ in range(M + 1)]
        empty_last = 0
        dp[0][empty_last] = 1

        for ch in s:
            c = ord(ch) - ord('a')  # assume alphabet subset of 4 chars
            newdp = [row[:] for row in dp]
            for length in range(M):
                for last in range(ALPH + 1):
                    if dp[length][last]:
                        if length + 1 <= M:
                            newdp[length + 1][c] += dp[length][last]
            dp = newdp

        res = [0] * (M + 1)
        for length in range(1, M + 1):
            total = 0
            for last in range(ALPH + 1):
                total += dp[length][last]
            res[length] = total
        return res

    total = [0] * (M + 1)
    for s in strings:
        cur = solve_one(s)
        for i in range(1, M + 1):
            total[i] += cur[i]
    return total

def solve():
    x = input().strip()
    y = input().strip()
    z = input().strip()
    q = int(input())

    ref = build_dp([x, y, z])

    out = []
    for _ in range(q):
        s = input().strip()

        # compute dp for s
        dp = [[0] * (ALPH + 1) for _ in range(M + 1)]
        dp[0][0] = 1

        for ch in s:
            c = ord(ch) - ord('a')
            newdp = [row[:] for row in dp]
            for length in range(M):
                for last in range(ALPH + 1):
                    if dp[length][last]:
                        newdp[length + 1][c] += dp[length][last]
            dp = newdp

        ok = True
        for length in range(1, M + 1):
            cur = sum(dp[length])
            if cur > ref[length]:
                ok = False
                break

        out.append("NO" if ok else "YES")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、概念的な DP を直接反映しています。 中心的な構造は、長さ×最後の文字のテーブルであり、これにより、異なる形成履歴が誤って混在することを回避する方法でサブシーケンスがカウントされることが保証されます。 重要な実装の詳細は、各文字で DP 状態を新しい配列にコピーすることです。これにより、サブシーケンス拡張の正確さが維持されます。 

いずれかの長さが基準境界を超えると答えが決定されるため、比較ステップは意図的に早期終了ベースになっています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、3 つの参照文字列がすべて同一で非常に小さい場合です。 この状況では、共用体 DP はサブシーケンスを二重にカウントしてはなりません。 重複排除を行わずに x、y、z のカウントを単純に合計すると、人為的に ref が増大し、多くの有効な YES のケースに対して誤って NO と答えてしまいます。 正しく解釈するには、x、y、z を複数集合の和ではなく集合和集合のソースとして扱う必要があります。 

s に繰り返される文字が 1 つだけ含まれる場合、別の特殊なケースが発生します。 この場合、すべてのサブシーケンスは a、aa、aaa などの形式になります。 DP は、長さごとに正確に 1 つのサブシーケンスを正確に蓄積する必要があり、同一の位置を選択する複数の方法によって過剰にカウントされないようにする必要があります。 最後の文字の状態により、異なるインデックス選択から重複が作成されないことが保証されます。 

最後のエッジケースは |s| の場合です。 サイズは大きいですが、アルファベットに制限があります。 組み合わせ的に多くのサブシーケンスが存在する場合でも、DP はそれらを有界状態に分解し、アルゴリズムは |s| で線形のままです。 これは、DP が安定していて予測可能である一方で、単純なサブセット列挙が壊滅的に失敗する場所です。
