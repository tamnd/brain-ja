 ## 問題の理解

 バイナリ配列と、セグメントを最小値または最大値のいずれかに置き換えながら配列を縮小する 2 種類のリダクション演算が与えられます。 このプロセスは配列が単一の値になるまで継続され、最終的な値が単一の値になるかどうかを判断することが目的です。`1`。 

2 つの操作は、バイナリ データに対してまったく異なる動作をします。 2 つの隣接する要素に対する最小限の操作により、次の結果が得られます。`1`両方の場合にのみ`1`、それ以外の場合は生成されます`0`。 これは、それが人にとって「破壊」作戦であることを意味します。 ある長さのブロックに対する最大の操作`k`生成する`1`少なくとも 1 つある場合`1`ブロック内にあるため、情報を拡散または保存する方法として機能します。`1`。 

配列はさまざまな方法で変換できますが、制約はわずかです。`n ≤ 50`。 これにより、配列の状態に対する複雑な動的プログラミングの必要性が排除されます。 正しい解決策は、すべての変換をシミュレートするのではなく、どの情報が保存されるかを推論することから導き出される必要があります。 

重要なエッジケースは、配列に何も含まれていない場合です。`1`全然。 その場合、すべての操作でゼロが保持されるため、結果は常に次のようになります。`[0]`。 もう少し微妙な状況としては、単一の構成が存在するかどうかが挙げられます。`1`操作によって「閉じ込められる」可能性がありますが、実験により、少なくとも 1 つのトラップが存在することがすぐに示唆されます。`1`通常、成功を強制するには十分です。 

たとえば、次の場合`a = [0, 0, 0, 1]`そして`k = 4`、単一の max 演算により、配列全体が次のようになります。`[1]`。 もし`k = 2`、引き続き max 操作を使用して、`1`、および min 操作は、隣接する要素を分離する可能性を排除せずに折りたたむだけです。 本当に不可能な唯一のケースは、`1`まず始めに。 

## アプローチ

 ブルートフォース解釈では、可能なすべてのセグメントに対して可能なすべての操作をシミュレートしようとします。 各操作により配列サイズは減少しますが、すべての中間配列構成が他の多くの配列構成に分岐できるため、状態の数は非常に急速に増加します。 たとえ`n ≤ 50`の場合、一連の操作の数が指数関数的に増加するため、これは実行不可能になります。 

重要な観察は、どちらの操作も新しいものを作成しないことです。`1`ゼロから。 唯一の方法は、`1`元の配列に少なくとも 1 つがすでに含まれている場合、最終的な配列に含めることができます。`1`。 一回`1`存在する場合、max 操作は、それを含む選択されたウィンドウ内でそれを保持できることを保証します。 その後、リダクションを繰り返すと、少なくとも 1 つの要素を保持したまま、配列を 1 つの要素に折りたたむことができます。`1`生きている。 

最小限の操作では創造や普及には役立たない`1`しかし、それはまた、`1`との組み合わせを避ければ生き残れなくなる`0`破壊的な方法で。 操作とセグメントを自由に選択できるため、いつでもシーケンスを配置できます。`1`最後まで保存されます。 

これにより、問題全体が 1 つの質問に集約されます。配列には少なくとも 1 つ含まれていますか?`1`?

 ## アルゴリズムのチュートリアル

 問題を、`1`配列内に存在します。 

1. 配列を左から右に 1 回スキャンし、等しい要素があるかどうかを確認します。`1`。 このステップでは、成功に必要な唯一の条件が得られます。`1`これを導入できる操作はありません。 
2. 少なくとも 1 つある場合`1`が見つかった場合は、すぐに到達可能であると結論付けます。`[1]`。 その理由は、`1`配列は常に max 操作を通じて保存でき、後でいつでも折りたたむことができます。 
3. いいえの場合`1`存在する場合、答えは不可能であると結論付けます。 ゼロに対するすべての演算は常にゼロを生成するため、最終的な配列は次のようにする必要があります。`[0]`。 

### なぜ効果があるのか

 どちらの操作も、次の存在に関して単調です。`1`。 最小限の操作では作成できません`1`、最大の操作では既存の`1`選択したセグメント内に既に存在する場合。 これは、「配列には少なくとも 1 つの要素が含まれている」という述語を意味します。`1`” は false で始まる場合は決して true にはならず、一度 true になると、配列のサイズが 1 に縮小されるまで維持できます。`1`必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    if any(x == 1 for x in a):
        print("YES")
    else:
        print("NO")
```ソリューションは、派生した条件を直接実装します。 の`any`check は配列を 1 回スキャンし、テスト ケースごとに線形時間を与えます。 操作の構造により、初期設定なしの構成は保証されないため、操作のシミュレーションは必要ありません。`1`いつでも生み出すことができます。 

よくある間違いは、操作を明示的にモデル化しようとすることですが、制約によりそれが不要になります。 変換プロセス全体は、単一の不変チェックにまとめられます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append("YES" if any(x == 1 for x in a) else "NO")

 ## 特殊なケース

 配列にゼロのみが含まれている場合、すべての操作ですべてゼロの構造が保持されます。 例えば、`[0, 0, 0, 0]`min 演算と max 演算の両方ですべて 0 のままであるため、常に次のように終了します。`[0]`。 

ちょうど 1 つだけある場合`1`、 のような`[0, 0, 1, 0]`、アルゴリズムはすぐに受け入れます。 任意の操作シーケンスを配置して、セグメントに`1`配列が縮小されるまで、max 操作によって保存されます。 中間マージにゼロが含まれる場合でも、`1`選択したセグメント内に常に保持できることを保証します。 

すべての要素が揃っているとき、`1`、どの操作でも生成されます`1`、したがって、次のように削減されます`[1]`関係なく単純です`k`。 

いつ`k = n`、単一の max 演算により、配列全体が単一の値に折りたたまれます。`1`もしあれば`1`存在します。 これは、一般的な引数によって導出された同じ条件と一致します。
