 ## 問題の理解

 ナトラン地域内の最初の都市から最後の都市までの個別のパスの数を数えるように求められます。各都市には魅力度の値があります。 パスは単純なルールに従っています: 都市から$i$都市に旅行することができます$j$もし$i < j$そして$\gcd(a_i, a_j) \neq 1$。 これにより、基礎となる構造が有向非巡回グラフ (DAG) になります。これは、すべてのエッジがインデックスの低い都市からインデックスの高い都市を指しているため、循環が不可能であるためです。 入力は都市の数で構成されます$n$そして魅力の価値観$a_i$。 出力は、都市 1 から都市までの個別のパスの数です。$n$、モジュロ$998\,244\,353$。 

制約は厳しいです。 と$n$まで$2 \cdot 10^5$そしてそれぞれ$a_i$まで$10^6$、GCD をチェックするために考えられるすべての都市のペアを反復処理するには、約$2 \cdot 10^5 \cdot 2 \cdot 10^5 / 2 \approx 2 \cdot 10^{10}$これは 4 秒の制限時間内に収まる範囲をはるかに超えています。 これにより、単純なペアごとのアプローチが排除されます。 また、パスの数は急速に増加する可能性があるため、オーバーフローを避けるためにモジュロ演算を慎重に処理する必要があります。 

すべての都市がペアごとに互いに素である場合、微妙なエッジケースが発生します。 たとえば都市の場合$[2, 3, 5]$、場合によっては都市 1 から都市 2 までを除いてエッジは存在しません。$\gcd(2,3) \neq 1$、それはそれです。 この場合、単純な反復によりパスが 2 重にカウントされるか、エッジが存在しない場所にエッジが存在すると想定され、パスのカウントが不正確になる可能性があります。 もう 1 つのエッジ ケースは、複数の都市が同じ魅力を持っており、同じ都市のペアを接続する有効なパスがいくつか作成される場合です。 

## アプローチ

 ブルート フォース アプローチでは、都市を DAG としてモデル化し、各ペア間のエッジを明示的に計算します。$i < j$もし$\gcd(a_i, a_j) \neq 1$。 DAG が構築されると、深さ優先検索 (DFS) または都市 1 から都市までの動的プログラミングが実行されます。$n$すべてのパスをカウントできます。 これは原理的には機能しますが、確認すると$\gcd$すべてのペアは$O(n^2)$、 について$4 \cdot 10^{10}$最大の入力に対する操作。 DFS メモ化でも DAG を構築する必要があるため、現実的ではありません。 

重要な観察は、2 つの数値が素因数を共有する場合にのみ、2 つの数値の GCD が 1 より大きくなるということです。 それぞれの魅力値をその素因数に因数分解することができ、それぞれの素因数に対して、$p$で割り切れる魅力を備えた最新の都市を追跡します。$p$。 これにより、すべてのペアをチェックすることなく、パスの数を動的に伝播することができます。 具体的には、動的プログラミング配列を維持します。`dp[i]`都市に到達する道の数を数える$i$。 それぞれの素因数について$p$の$a_i$、私たちは最新の都市を知っています`last[p]`係数あり$p$前に$i$; 辿り着くどんな道でも`last[p]`都市まで続けられる$i$。 すべての素因数の寄与を合計して計算します`dp[i]`。 

これにより、問題が因数分解と線形探索に変換され、複雑さが大幅に軽減されます。 素因数分解にふるいを使用する$10^6$各都市が確実に処理されるようにする$O(\log a_i)$なぜなら、次の数の場合、異なる素因数の数は最大でも約 7 であるからです。$10^6$。 このアプローチは実現可能かつ効率的です。

 ## アルゴリズムのチュートリアル

 1. 以下の値までのすべての数値の最小素因数 (SPF) を事前計算します。$10^6$ふるいを使って。 これにより、任意の数値を素早く因数分解することができます。$O(\log a_i)$最小の素因数で繰り返し除算して時間を計算します。 
2. 配列を初期化する`dp`サイズの$n+1$すべてゼロで。 セット`dp[1] = 1`、都市 1 から始まるパスが 1 つだけあるためです。 
3. 辞書の初期化`last`各素因数の最後の都市インデックスを追跡します。 これにより、パスを効率的に伝播することができます。 
4. インデックス 1 からインデックス 1 までの都市を反復処理します。$n$。 都市ごとに$i$：

- 要素`a[i]`SPF 配列を使用してその素因数に変換します。 
- 各素因数について$p$の`a[i]`、 追加`dp[last[p]]`に`dp[i]`モジュロ$998\,244\,353$、 どこ`last[p]`以前の最も新しい都市です`i`係数あり$p$。 もし`last[p]`はまだ存在しないため、貢献度はゼロです。 
- アップデート後`dp[i]`、 アップデート`last[p] = i`すべての素因数に対して$p$。 
5. 最終的な答えは次のとおりです。`dp[n]`、都市に到達する個別のパスの数$n$。 

なぜ機能するのか: 都市 1 から都市までのすべてのパス$i$パスに沿った都市の素因数によって一意に分解できます。 各素因数により、その因数を共有する後続の都市への接続が保証されます。 不変条件は、都市の処理後です。$i$、`dp[i]`で終わるすべての個別のパスを正しくカウントします。$i$有効なエッジのみを使用します。 素因数にわたる寄与を合計することで、パスの欠落や二重カウントがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX_A = 10**6 + 1

# Sieve to compute smallest prime factors
spf = list(range(MAX_A))
for i in range(2, int(MAX_A**0.5) + 1):
    if spf[i] == i:
        for j in range(i*i, MAX_A, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    factors = set()
    while x > 1:
        factors.add(spf[x])
        x //= spf[x]
    return factors

def main():
    n = int(input())
    a = list(map(int, input().split()))
    dp = [0] * n
    dp[0] = 1
    last = dict()

    for i in range(n):
        primes = factorize(a[i])
        for p in primes:
            if p in last:
                dp[i] = (dp[i] + dp[last[p]]) % MOD
        for p in primes:
            last[p] = i

    print(dp[n-1] % MOD)

if __name__ == "__main__":
    main()
```ふるいは最小の素因数を効率的に事前計算します。 の`factorize`関数は、任意の数の異なる素因数を生成します。 動的プログラミング配列`dp`各都市へのパスの数を累積します。 の`last`辞書は、寄与が少なくとも 1 つの素因数を共有する以前の都市からのみ得られることを保証します。 更新中`last[p]`貢献を追加した後は、パスを複数回カウントしないことが保証されます。 境界処理は、Python のゼロベースのインデックス作成によって自然に処理されます。
