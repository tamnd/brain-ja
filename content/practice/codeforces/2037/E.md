 ## 解決策
 ## 問題の理解

 私たちは、次の長さの隠されたバイナリ文字列を再構築するという任務を負っています。$n$関数をクエリすることによって$f(l, r)$、インデックスからの部分文字列内の部分シーケンス「01」の数をカウントします。$l$に$r$。 サブシーケンスとは、元の順序を維持した文字の選択です。 2 つのサブシーケンスは、同じ文字列を生成する場合でも、異なる位置で文字を使用している場合、別個のものとみなされます。 

チャレンジはインタラクティブです: あらゆるクエリに対して$l, r$と$1 \le l < r \le n$、システムは戻ります$f(l, r)$。 私たちが尋ねることができるのはせいぜい$n$テストケースごとのクエリ。 クエリを実行した後、再構成された文字列を出力するか、文字列を一意に決定することが不可能であることを宣言する必要があります。 

重要な洞察は次のとおりです$f(l, r)$0 と 1 を数えることによって決定されます。 具体的には、$c_0$ゼロと$c_1$部分文字列内の「01」部分列の数は$c_0 \times c_1$各ゼロとその後に来る各ゼロの組み合わせを考慮するとき、その部分文字列内で。 以来$f(l, r)$はカウントと順序のみに依存するため、連続する部分文字列をクエリし、カウントを慎重に組み合わせることでローカル情報を推定できます。 

制約が教えてくれる$n$まで可能です$10^4$そしてすべての合計$n$テストケース全体の限界も次のとおりです$10^4$。 これにより線形時間アルゴリズムが可能になりますが、すべての部分文字列の二次または単純な総当たり探索は遅すぎます。 エッジケースは、すべての文字が同じ場合に発生します。たとえば、$s = "00"$または$s = "11"$、 なぜなら$f(l, r) = 0$どちらの場合も、単一のクエリではそれらを区別することはできません。 パターンが繰り返される文字列も曖昧さを生み出す可能性があるため、不確実性を慎重に排除する戦略が必要です。 

## アプローチ

 ブルートフォース手法では、長さ 2 以上のすべての可能な部分文字列をクエリし、0 と 1 の数を計算し、文字列の再構築を試みます。 各「01」サブシーケンスがキャプチャされるため、これは正しいですが、それには次のことが必要です。$\Theta(n^2)$クエリを実行するため、遅すぎます。 

最適なアプローチは、「01」サブシーケンスが線形構造に従っているという観察を活用します。つまり、位置の右側にある 1 の数がわかっている場合、各 0 がその数の「01」サブシーケンスに寄与します。 これにより、貪欲なアプローチまたは 2 ポインター アプローチが可能になります。つまり、ますます大きなプレフィックスとサフィックスをクエリして、0 と 1 の累積カウントを計算します。 を使用することで$n-1$クエリを実行して連続する位置間の「01」カウントの違いを判断すると、線形時間で文字列を一意に再構築できます。 クエリの総数があいまいさを解決するには不十分な場合 (たとえば、長さ 2 の部分文字列に「01」サブシーケンスがゼロである場合)、「IMPOSSIBLE」と報告します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n^2)$| 遅すぎる |
 | プレフィックス数 / 貪欲 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列全体をクエリする$f(1, n)$「01」サブシーケンスの総数を取得します。 これをそのままにしておきます`total`。 
2. 左から見たものの連続数を維持します。 初期化する`ones = 0`。 
3. 左から右に位置を反復します。$i = 1 \dots n$。 各ポジションについて:

 1. クエリ$f(i, i+1)$部分文字列が「01」サブシーケンスに寄与しているかどうかを確認します。 
2. 答えが 0 で、残りの「01」カウントがこの位置に 1 を必要としない場合は、「0」とマークします。 
3. それ以外の場合は、「1」としてマークし、値を増やします。`ones`1までに。 
4. 残りの「01」部分列の合計を減算して更新します。`ones`残りの位置にゼロを乗算します。 
4. すべての位置を埋めた後、累積「01」カウントが初期合計と一致することを確認します。 「はい」の場合、再構築された文字列を出力します。 
5. 残りのサブシーケンスが複数の構成に一致する可能性がある場合は、「IMPOSSIBLE」を出力します。 

重要な不変条件は、各位置を処理した後、残りの「01」サブシーケンスの合計が、未処理のサフィックス内の「01」サブシーケンスの数と等しいということです。 これにより、各ステップでの決定がグローバル カウントに違反しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        res = ['?'] * n

        def query(l, r):
            print(f"? {l} {r}")
            sys.stdout.flush()
            return int(input())
        
        # query total 01 subsequences
        total = query(1, n)
        remaining = total
        ones_so_far = 0
        zeros_so_far = 0

        for i in range(n):
            if i == n-1:
                # last position, assign remaining zeros/ones
                if remaining == 0:
                    res[i] = '0'
                else:
                    res[i] = '1'
                break
            val = query(i+1, i+2)
            if val == 0:
                # no 01 from this pair
                res[i] = '0'
                zeros_so_far += 1
            else:
                res[i] = '1'
                ones_so_far += 1
                remaining -= zeros_so_far
        
        # verify total
        counted_total = 0
        zeros_count = 0
        for ch in res:
            if ch == '0':
                zeros_count += 1
            else:
                counted_total += zeros_count
        if counted_total != total:
            print("! IMPOSSIBLE")
        else:
            print(f"! {''.join(res)}")
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションでは、最大でもクエリが実行されます$n$回。 各クエリは単一のペアに対して行われ、「01」サブシーケンスを検出し、残りのサブシーケンスを反映するためにカウントが更新されます。 最後の位置は残りカウントから推測されます。 出力をフラッシュし、対話型クエリを正しく処理するように注意が必要です。
