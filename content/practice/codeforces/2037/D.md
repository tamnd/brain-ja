 ## 解決策
 ## 問題の理解

 位置 1 から位置までの一次元パスに沿ったサーフボードの旅をモデル化するように求められます。$L$。 ムアラニはジャンプ力 1 から開始し、現在の位置から移動できるようになります。$x$の任意の位置に$[x, x+k]$、 どこ$k$現在のジャンプ力です。 パスには 2 種類の障害物が含まれています。 まず、ハードルがあり、それぞれのハードルが一定の間隔を占めています。$[l, r]$、彼女は飛び込むことも通り抜けることもできません。 第二に、特定の位置にパワーアップがあり、収集するとジャンプ力が固定値だけ増加します。 私たちの目標は、パスの終点に到達するために必要なパワーアップの最小数を決定することです。 無理なら戻ります$-1$。 

制約は重要です。 1 つのテスト ケースには、最大 200,000 のハードルと 200,000 のパワーアップが存在できます。$L$と同じ大きさにすることができます$10^9$。 これにより、パスに沿ったすべての位置を反復したり、各ジャンプを個別にシミュレートしようとするソリューションは除外されます。$O(L)$というアプローチは不可能でしょう。 代わりに、ハードルとパワーアップを直接処理する必要があります。理想的には直線的なパスで、または貪欲な戦略を使用します。 

明らかではないエッジケースは、ハードルが手の届かないところにある場合、または複数のパワーアップが同じ位置にある場合に発生します。 たとえば、最初のハードルがポジション 5 から始まり、ムアラニのジャンプ力が 1 である場合、ポジション 1 ～ 4 でパワーアップを集めなければ、彼女はそのハードルに到達することさえできません。もう 1 つのトリッキーなシナリオは、いくつかの小さなパワーアップが存在するが、それらの値の合計がハードルを越えるのに十分である場合です。 単純な貪欲なアプローチでは、ハードルのサイズを考慮しない場合、必要なパワーアップよりも少ないパワーアップしか必要としない可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、各ポジションで考えられるすべての選択肢をシミュレートします。 位置 1 から開始して、各パワーアップを収集または無視してから、各ジャンプで到達可能なすべての位置を確認して、オプションを再帰的に探索できます。 このアプローチは、ジャンプとパワーアップ コレクションのすべての組み合わせを調査するため正しいですが、次の場合にはすぐに失敗します。$L$大きいです。 たった数百のパワーアップであっても、組み合わせの数は指数関数的に増加し、$t = 10^4$大規模なテストケース$n$そして$m$。 

重要な洞察は、すべての立場を考慮する必要はないということです。 重要なポジションはハードルのエンドポイントとパワーアップポジションだけです。これらのポイントはムアラニの前進能力を変える可能性があるからです。 問題は、一連のセグメント、つまりハードル間のギャップに還元できます。 各セグメントで、ムアラニが現在のジャンプ力でどこまでジャンプできるかが正確にわかります。 ギャップの長さが現在のジャンプ力を超える場合、ジャンプを試みる前にいくつかのパワーアップを選択する必要があります。 これにより、問題はパワーアップの貪欲な選択に変換され、最大値を持つものを優先して収集される数を最小限に抑え、ソートされたパワーアップに対する 2 つのポインタ アプローチを使用して各ハードルを順番に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(L) | 遅すぎる |
 | 最適な貪欲 / ツーポインター | テスト ケースあたり O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期ジャンプ力 1 で位置 1 から開始します。収集されたパワーアップの数のカウンターを保持します。 現在のセグメントで利用可能なパワーアップの最大ヒープを維持し、必要なときに最大値をすばやく選択します。 
2. ハードル間隔ごとに$[l, r]$、現在の位置からハードルの開始点までのギャップの長さを計算します。`gap = l - current_position`。 もし`gap <= current_jump_power`, ムアラニは追加のパワーアップなしでハードルに到達できます。 それ以外の場合は、ギャップをカバーするために彼女のジャンプ力を伸ばすのに十分なパワーアップを収集する必要があります。 
3. 現在のジャンプ力ではギャップを越えるのに不十分ですが、インターバル内にすべてのパワーアップを押します。`[current_position, l-1]`最大ヒープに格納します (値でソート)。 ヒープから最大値をポップし、それをジャンプ力に追加し、収集されたカウントを増分します。 ヒープが空でジャンプ力がまだ不十分な場合はリターンします。`-1`ハードルが届かないから。 
4.ハードルを越えたらアップデート`current_position = r + 1`、ムアラニはハードル内に着地できないため、次のハードルでも同じプロセスを繰り返します。 
5. 最後のハードルを越えた後、現在の位置からのギャップを考慮します。$L$。 同じロジックを適用します。到達するために必要な残りのポジションでパワーアップを収集します。$L$。 
6. Mualani が位置に到達した場合に収集されたパワーアップの総数を返します。$L$。 

機能する理由: 各ハードルで、ジャンプ距離の不足をカバーするために、利用可能な最大のパワーアップを選択するという貪欲な選択をします。 目標はパワーアップの数を最小限に抑えることなので、最大のものを選択すると、必要なパワーアップの数が確実に少なくなります。 維持される不変条件は、ギャップを試みる前に、到達可能な間隔内のすべてのパワーアップが選択可能であり、ジャンプ力は収集されたパワーアップの累積効果を常に反映するということです。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, L = map(int, input().split())
        hurdles = [tuple(map(int, input().split())) for _ in range(n)]
        powerups_raw = [tuple(map(int, input().split())) for _ in range(m)]

        # Group power-ups by position for easier access
        powerups_by_pos = {}
        for x, v in powerups_raw:
            if x not in powerups_by_pos:
                powerups_by_pos[x] = []
            powerups_by_pos[x].append(v)

        powerup_positions = sorted(powerups_by_pos.keys())

        pos = 1
        jump = 1
        collected = 0
        i = 0  # index for powerup_positions
        heap = []

        # process each hurdle
        for l, r in hurdles + [(L, L)]:  # add virtual hurdle at the end
            gap = l - pos
            while jump < gap:
                # push all power-ups in [pos, l-1] to max-heap
                while i < len(powerup_positions) and powerup_positions[i] < l:
                    for val in powerups_by_pos[powerup_positions[i]]:
                        heapq.heappush(heap, -val)
                    i += 1
                if not heap:
                    collected = -1
                    break
                jump += -heapq.heappop(heap)
                collected += 1
            if collected == -1:
                break
            jump -= gap
            pos = r + 1

        print(collected)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずパワーアップを位置ごとにグループ化し、セグメント内のすべてのパワーアップに効率的にアクセスします。 max-heap により、パワーアップの収集が強制されたときに常に最大値が選択されることが保証されます。 最後のギャップのロジックを統一するための最後の「仮想ハードル」として、最後に到達することを扱います。 境界条件は慎重に処理されます。ハードルと更新の前にパワーアップのみが厳密に考慮されます。`pos`ハードルを飛び越えた後。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n + m) | 各ハードルとパワーアップは最大 1 回処理されます。 最大ヒープ操作は、現在のセグメントのパワーアップ数の対数になります。 |
 | スペース | O(m) | Max-heap は、テスト ケース内のすべてのパワーアップを保存できます。 |

 これは、問題の制限内で問題なく適合します。$n + m \le 2 \cdot 10^5$ヒープ操作も効率的になります。
