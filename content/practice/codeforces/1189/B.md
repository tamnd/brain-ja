 ## 解決策
 ## 問題の理解

 複数の数値セットが与えられ、すべての要素が隣接する 2 つの要素の合計より厳密に小さくなるように、それらすべてを円の周りに配置できるかどうかを尋ねられます。 隣接関係は循環的であるため、最初と最後の要素も隣接要素になります。 

条件はローカルであり、各値は隣接する 2 つの値に対してのみチェックされますが、配置はグローバルです。 単一の要素を再配置すると、2 つの不等式が同時に影響を受ける可能性があるため、これは重要です。 

制約により、最大で次のことが許可されます。$10^5$までの値を持つ数値$10^9$。 すべての順列を試すような解決策は直ちに不可能です。$n!$たとえ実現可能な限界をはるかに超えて成長する$n = 20$。 これにより、私たちは次のような方向に向かって進みます。$O(n \log n)$または$O(n)$戦略。 

1 つの要素が他の要素と比べて非常に大きい場合、微妙なエッジ ケースが発生します。 たとえば、`[100, 1, 1, 1]`、どのような配置でも、合計が 2 以下になる 2 つの小さな値の間に 100 が収まることになり、条件に違反します。 円の構築中に部分的なローカル妥当性のみをチェックする単純な貪欲型では、最終的なラップアラウンド制約を考慮していない場合、そのようなケースを誤って受け入れる可能性があります。 

値がほぼ等しい場合、別の注意が必要なシナリオが発生します。 例えば`[3, 3, 3, 3]`動作しますが、`[3, 3, 3, 2]`も機能しますが、`[10, 3, 3, 3]`失敗します。 違いは局所的な隣接性ではなく、最大要素の相対的な優位性です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。数値のすべての順列を試し、すべての循環隣接制約が成立するかどうかを確認します。 それぞれのアレンジメントについて、すべてをスキャンします$n$位置を決めて確認する$a_i < a_{i-1} + a_{i+1}$。 これは条件を直接テストするので正しいですが、次のことが必要です。$O(n \cdot n!)$たとえ限界をはるかに超えた操作$n = 10$。 

重要な洞察は、実際に状態を打破する可能性があるものに焦点を当てることから得られます。 一部の要素が大きすぎる場合、隣接する要素も大きい場合を除き、順序に関係なく隣接する要素に対して失敗する可能性があります。 これは、最大の要素が実現可能性を支配していることを示唆しています。 

分類すると構造が明らかになります。 配列をソートするとします。 最大の要素が 2 番目および 3 番目に大きい要素に比べて大きすぎる場合、どのような配置でもそれを修正することはできません。円内では、最大の要素には常に 2 つの隣接要素が存在するため、その保護を最大化するには、その隣に次に大きな数字を配置する必要があります。 それさえ不足していれば答えられません。 

条件が満たされる可能性がある場合、次のアイデアは、少数の「サポート」が不足するような形で多数の数字を隣接して配置することを避けることです。 このような「近傍和」問題の標準的な構成は、円の周りにジグザグまたは交互のパターンで数値を配置することです。これにより、大きな値が分離され、各位置が適度に大きな近傍によってサポートされます。 

ソート後、配列を分割し、半分をインターリーブします。 これにより、大きな要素が間隔をあけて配置され、単一の大きな値が 2 つの非常に小さな値に隣接することがなくなります。 この構造は、すべての要素を隣接する要素の合計よりも厳密に小さく保つためにまさに必要なものです。

 ## アルゴリズムのチュートリアル

 有効な配置が存在する場合は、ソートとインターリーブを使用してそれを構築します。 

1. 配列を降順でない順に並べ替えます。 これにより、隣接効果を制御するために必要な、小さい要素から大きい要素までの明確な順序が得られます。 
2. ソートされた配列を 2 つの部分、小さい半分と大きい半分に分割します。 その目的は、大きな要素が互いに密集するのを防ぐことです。 
3. 2 つの半分から要素をインターリーブし、大きい方の側と小さい方の側を常に交互に配置します。 これにより、大きな値が円の周囲に均等に分散され、すべての大きな要素が小さな要素に隣接するようになります。 
4. 円を構築した後、循環形式ですべてのインデックスの条件を検証します。 インデックスに違反している場合$a_i < a_{i-1} + a_{i+1}$、アレンジメントは無効です。 
5. チェックに合格した場合は、配置を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 正確さは、最大の要素のローカル環境を制御することに依存します。 有効な解決策では、最大値は十分に大きな隣接値によって「保護」される必要があります。 並べ替えることにより、どの値がそのサポートを提供できるかを確実に知ることができます。 インターリーブにより、大きな要素が分離されたままでありながら、小さな要素だけで囲まれた大きな要素がないことが保証されます。 

重要な不変条件は、構築後、すべての要素がソートされた配列の反対側の半分の少なくとも 1 つの要素に隣接することです。 これにより、大きな値が 2 つの小さな値の間に挟まれるという病的な構成が防止されます。これが、不等式が最上位で失敗する唯一の方法です。 最大の要素が安全になると、隣接する要素に少なくとも適度に大きな値が含まれるため、小さな要素は自動的に条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # interleave halves
    left = a[:n//2]
    right = a[n//2:]
    
    res = []
    
    i = 0
    j = 0
    
    while i < len(right) or j < len(left):
        if i < len(right):
            res.append(right[i])
            i += 1
        if j < len(left):
            res.append(left[j])
            j += 1
    
    # verify circular condition
    for k in range(n):
        if res[k] >= res[(k-1) % n] + res[(k+1) % n]:
            print("NO")
            return
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```コードはまず配列を並べ替えて、要素間の構造的関係を明確にします。 次に、配列を 2 つの半分に分割してインターリーブし、上半分に大きい値を、下半分に小さい値を交互に配置します。 これにより、大きな値が隣接しないことが保証されます。 

構築後、検証ループにより循環状態が直接チェックされます。 モジュロインデックスにより、最初と最後の要素間のラップアラウンド隣接性が保証されます。 構築は意図的に単純になっており、配置中にローカルな修正を試みるのではなく、構造を強制するソートに依存しています。

 ## 特殊なケース

 重大なエッジケースは、1 つの要素が他のすべての要素よりも大幅に大きい場合です。 入力中`[10, 1, 1]`、アルゴリズムは依然として円形の配置を生成しますが、最大の要素の近傍の合計が 2 にすぎないため、検証ではそれが正しく拒否されます。これは、最終的な検証ステップがなければ構築だけでは不十分である理由を示しています。 

もう 1 つの微妙なケースは、すべての要素が等しい場合です。 のために`[5, 5, 5, 5]`の場合、すべての値が隣接する値の合計より厳密に小さいため、任意の円形配置は条件を満たします。 アルゴリズムはインターリーブを構築しますが、チェックは簡単にパスし、特別な処理が必要ないことが確認されます。 

3 番目のケースには、次のような境界線の合計が含まれます。`[1, 2, 3]`。 ソートとインターリーブの後、この構造により、1 つの要素が等価に近い場合でも、各要素の合計がその要素を超える隣接要素が存在することが保証されます。 検証ループは正確さを確認し、無効な順列が誤って受け入れられることを防ぎます。
