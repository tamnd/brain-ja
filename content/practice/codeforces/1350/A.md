 ## 解決策
 ## 問題の理解

 数値から始めて、非常に具体的な変換を繰り返し適用します。つまり、1 より大きい最小の約数を見つけて、その値を数値に加算します。 この操作では数値自体が変更されるため、使用する除数はステップごとに変わる可能性があります。 これを正確に実行した後、`k`場合によっては、最終的な値を求められます。 

重要なオブジェクトは関数です`f(n)`、これは単に次の最小の素因数です。`n`。 もし`n`プライムです、`f(n) = n`。 もし`n`複合的であり、`f(n)`それを割る最小の素数です。 

それぞれの操作が私たちを`n`に`n + f(n)`。 以来`k`と同じ大きさにすることができます$10^9$、段階的にシミュレーションすることはできません。 ただし、すべての合計は、`n`オーバーテストケースは最大でも$10^6$これは、その範囲までの数値に関する何かを前処理し、それを効率的に再利用することが期待されていることを示唆しています。 

単純なアプローチでは、クエリごとに各ステ​​ップをシミュレートします。 次のような場合、これはすぐに失敗します。`n = 10^6, k = 10^9`1 つのテスト ケースでも数十億の遷移が必要になります。 

次の場合、微妙なエッジケースが発生します。`n`素数であるか、プロセス中に素数になります。 たとえば、次のような素数から開始します。`3`、次のようになります。`3 → 6 → 8 → 10 → 12 ...`ここでは、数値が偶数になると最小の約数が維持されるため、動作はすぐに安定します。`2`永遠に。 毎回除数を最初から再計算しようとする不用意な実装はタイムアウトになります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ステップごとに、次からスキャンして現在の数値の最小の約数を再計算します。`2`上に向かって追加し、繰り返します。 これは定義に直接従うため、正しいです。 問題は、約数を見つけるのに最大で時間がかかることです。$O(\sqrt{n})$、これを次まで実行します$k$クエリあたりの所要時間$O(k \sqrt{n})$、これは大きすぎます。`k`到達する$10^9$。 

重要な観察は、このプロセスには強力な安定化動作があるということです。 唯一の時間の値は、`f(n)`ではありません`2`いつですか`n`奇数です。 奇数の最小素因数を加算すると、結果は偶数になります。 その時点から、すべての数字は偶数のままですので、`f(n)`いつもです`2`。 

これは、プロセスでは奇数ごとに「高価な」遷移が最大 1 つしかないことを意味します。奇数状態から偶数状態にジャンプし、その後のシーケンスは一定の増分で線形になります。`2`。 したがって、段階的にシミュレーションするのではなく、次のいずれかが完了するまでのみシミュレーションします。`k`足りなくなるか偶数に到達すると、残りは 1 回の算術ジャンプで終了します。 

までのすべての数値の最小の素因数を事前計算します。$10^6$ふるいを使って。 その後、各クエリは、多くても数ステップで貪欲に処理されます。

 ## アルゴリズムのチュートリアル

 まず、すべての整数の最小の素因数を可能な最大値まで前処理します。`n`ふるいを使って。 

その後、各クエリは独立して処理されます。 

1. 現在の値を次のように初期化します。`x = n`そして保管してください`k`残りの操作。 
2. その間`k > 0`そして`x`奇数です、計算してください`f(x)`事前に計算された配列を使用して更新します`x = x + f(x)`、次に減分します`k`。 
3. 1回`x`均等になると (または操作がなくなると)、ステップバイステップのシミュレーションを停止します。 
4. 操作が残っている場合は、追加します。`2 * k`に`x`そしてすぐに終了します。 

ステップ 4 の背後にある重要な理由は、数値が偶数になると、その最小の約数は常に`2`したがって、残りのすべての操作が正確に寄与します。`2`。 

### なぜ効果があるのか

 このプロセスは自然に 2 つのフェーズに分かれます。 最初のフェーズでは、値が奇数になる可能性があり、最小の約数は因数分解によって異なります。 このような各ステップでは厳密に数値が増加し、多くの場合パリティが反転されます。 数が偶数になると、その数は永遠に偶数領域に留まり、最小の約数は不変になります(`2`）。 これにより、安定した線形領域への移行が 1 回だけの単調システムが作成され、貪欲なシミュレーションが正しく、制限されたものになることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6 + 5

spf = list(range(MAXN))

# sieve for smallest prime factor
for i in range(2, int(MAXN**0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXN, i):
            if spf[j] == j:
                spf[j] = i

def solve(n, k):
    x = n
    
    while k > 0:
        if x % 2 == 0:
            break
        x += spf[x]
        k -= 1
    
    if k > 0:
        x += 2 * k
    
    return x

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    print(solve(n, k))
```ふるいは最小の素因数テーブルを構築します。`f(x)`クエリは O(1) です。 シミュレーション ループは数値が奇数の間のみ実行され、テスト ケースごとに最大でも数回の反復が保証されます。 偶数に到達すると、最小の約数が 2 に固定されるという不変条件を利用して、残りのステップを定数時間でジャンプできるようにします。

 ## 特殊なケース

 重要なエッジケースは、数値が偶数で始まる場合です。 例えば、`n = 2`。 最小の約数は常に`2`したがって、すべての操作で正確に加算されます。`2`。 アルゴリズムはシミュレーションを直ちにスキップし、次の直接乗算を適用します。`k`、真のプロセスと一致します。 

もう 1 つのケースは、数値が大きな素数として始まる場合です。 のために`n = 999983`, 最初のステップで約2倍になり、その後は均等になります。 安定レジームへの移行は 1 回の反復で発生し、線形公式に切り替える前にループがそれを捕捉します。 

最後の微妙なケースは、`k = 0`。 演算は適用されないため、答えは元の値と等しくなければなりません`n`。 This is handled naturally because the loop and final addition both depend on`k > 0`。
