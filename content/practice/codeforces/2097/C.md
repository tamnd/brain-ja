 ## 問題の理解

 平面は、角がある直角三角形の内側を移動します。$(0,0)$、$(n,0)$、 そして$(0,n)$。 航空機は厳密にこの三角形の内側から出発します。$(x,y)$等速ベクトルで移動します$(v_x, v_y)$。 三角形の辺のいずれか (頂点を除く) に触れると、ビリヤードの球のように反射します。その辺に垂直な速度の成分は符号を反転しますが、平行な成分は変化しません。 

軌道が 3 つの頂点のいずれかに正確に着地すれば、飛行は正常に終了します。 私たちは 2 つのことを尋ねられます。これが実際に起こるかどうか、そしてもし起こった場合、頂点に到達するまでに境界反射が何回発生するかです。 

主な難点は、モーションが連続的であり、傾斜したジオメトリでの反射があることです。 関心のあるイベントが発生する前に座標が非常に大きくなる可能性があり、軌道に多くの反射が含まれる可能性があるため、直接シミュレーションは不可能です。 以来$t$まで可能です$10^4$そして$n$まで$10^9$、 平$O(n)$テストケースごとに実行することは完全に不可能です。 

単純なシミュレーションでは、三角形の辺との交差を繰り返し計算し、方向を更新します。 各ステップは低コストですが、特に軌道が周期的に動作する場合、反射の数が膨大になる可能性があります。 隠れた主な問題は、変換された空間ではシステムが決定論的かつ周期的であるため、ブルート シミュレーションが無限にループしたり、頂点に到達するまでに時間がかかりすぎる可能性があることです。 

微妙な失敗例は、軌道が頂点に到達せず、三角形のエッジに平行な不変バンドに沿って循環する場合に発生します。 このような場合、単純なシミュレーションは最終的に脱出するか、永久に実行されると誤って想定する可能性があります。 正しいソリューションでは、ジオメトリを明示的にシミュレートするのではなく、格子整合条件が満たされているかどうかを検出する必要があります。 

## アプローチ

 重要な観察は、直角三角形の反射は「展開」できるということです。 境界でパスを反映するのではなく、三角形自体をエッジ全体に反映します。 展開後、軌道は直角三角形を無限に並べた直線になります。 

この展開空間では、元の問題は、次の点から始まる直線かどうかを問うことに帰着します。$(x,y)$方向性あり$(v_x,v_y)$三角形タイリングの頂点に対応する格子点に到達することはありません。 これらの頂点は線によって拘束された格子を形成します$x=0$、$y=0$、 そして$x+y=n$各タイルのコピーで。 

重要な還元は、頂点に到達するということは、時間の経過とともに線形合同系を解くことに相当するということです。$t$:$$x + t v_x \equiv 0 \pmod{n}$$

$$y + t v_y \equiv 0 \pmod{n}$$または同様に、どの頂点がターゲットになるかに応じて、3 つの頂点タイプから派生した合同システムの小さなセットの 1 つになります。 これは古典的な中国の剰余定理の構造です。単一のパラメータが存在するかどうかを尋ねています。$t$は 2 つのモジュラー一次方程式を同時に満たします。 

ジオメトリを追跡する代わりに、これらの合同の実現可能性をテストします。 解が存在する場合、最小の正の値$t$最初の頂点のヒット時間を示し、境界ヒットは軌道がラインを横切る回数をカウントすることに対応します。$x=0$、$y=0$、 そして$x+y=n$その前に。 各交差は、展開された線に沿った線形不等式交差イベントに対応し、これは 1D における線形方程式の解を数えることに帰着します。 

ブルートフォース手法では、反射イベントを 1 つずつシミュレートします。 各イベントでは、3 つの辺のうちの 1 つとの次の交点を計算する必要があり、コストがかかります。$O(1)$。 ただし、軌道は最大まで反映できます。$O(n)$病理学的な場合には、これが不可能になることがあります。 

最適化された方法では、ジオメトリをモジュラー算術制約に変換し、交差を分析的にカウントすることにより、すべてのシミュレーションが回避されます。

 ## アルゴリズムのチュートリアル

 展開された三角形のタイリング内の動きを直線に落とし込み、それがいつラティスの頂点に当たるかを分析します。 

1. まず、反射を除去した展開空間での軌跡を解釈します。 ポイントは次のように移動します$(x + t v_x, y + t v_y)$。 これは、各反射がモーションの変更ではなく座標系のミラーリングに対応するため、有効です。 
2. 3 種類の頂点ヒットを特定します。 展開されたタイリングでは、頂点は座標が三角形の角と一致する点に対応し、モジュロの線形合同条件に変換されます。$n$。 考えられる各エスケープ頂点は、線形軌道に合同のペアを課します。 
3. 候補頂点タイプごとに、「軌道がその頂点に当たる」という条件をシステムに変換します。$$x + t v_x \equiv a \pmod{n}, \quad y + t v_y \equiv b \pmod{n}$$どこ$(a,b)$タイリング内の三角形の頂点パターンの 1 つに対応します。 重要なのは、そのようなシステムはすべて、線形ディオファントス システムに解があるかどうかを確認することに帰着するということです。 
4. 逆モジュラーと拡張ユークリッド アルゴリズム ロジックを使用して各システムを解きます。 いずれかの系が解ける場合は、最小の正の時間を計算します。$t$頂点に到達した時点。 
5. 1回$t$既知であるため、時間の前に境界ヒットをカウントします$t$。 各境界は線形条件に対応します。 

- 打撃$x=0$- 打撃$y=0$- 打撃$x+y=n$展開された座標では、それぞれが次の線形方程式を解くことになります。$t$、 のような$x + t v_x \equiv 0 \pmod{n}$、そして、解決策がいくつあるかを数えます。$(0, t)$。 
6. すべての有効な境界交差を厳密に合計します。$t$。 これらは時間の等差数列であるため、カウントはフロア除算を使用して計算されます。 

### なぜ効果があるのか

 反射された三角形の動きは、周期的にミラーリングされたタイリングの直線の動きと同等です。 これにより、エッジとの交差イベントと正確な頂点ヒットの両方が保持されます。 すべての反射は、展開平面内の境界線との交差に 1 対 1 で対応するため、展開システム内の交差をカウントすると、元のシステム内の反射の数が正確に再現されます。 頂点条件は時間の単一の線形関数に対する同時モジュラー制約に帰着するため、存在とタイミングは CRT スタイルのシステムの可解性に帰着し、これが脱出動作を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def extended_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = extended_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inv(a, mod):
    g, x, _ = extended_gcd(a, mod)
    if g != 1:
        return None
    return x % mod

def solve_case(n, x, y, vx, vy):
    # We check only 3 vertex targets in unfolded lattice interpretation
    # Each corresponds to solving:
    # x + t*vx ≡ 0 (mod n)
    # y + t*vy ≡ 0 (mod n)

    def solve(a, da, b, db):
        # a + t*da ≡ 0 (mod n)
        # b + t*db ≡ 0 (mod n)
        # => t ≡ -a/da mod n and t ≡ -b/db mod n
        inv_da = mod_inv(da % n, n)
        inv_db = mod_inv(db % n, n)
        if inv_da is None or inv_db is None:
            return None
        t1 = (-a % n) * inv_da % n
        t2 = (-b % n) * inv_db % n
        if (t1 - t2) % n != 0:
            return None
        return t1 % n

    # candidate systems corresponding to triangle vertices in unfolding
    candidates = [
        (x, vx, y, vy),
        (x, vx, n - y, -vy),
        (n - x, -vx, y, vy),
    ]

    best_t = None
    for a, da, b, db in candidates:
        t = solve(a, da, b, db)
        if t is not None and t != 0:
            if best_t is None or t < best_t:
                best_t = t

    if best_t is None:
        return -1

    # boundary hit counting (each boundary crossing is periodic in t mod n)
    def count_hits(a, da, limit):
        inv = mod_inv(da % n, n)
        if inv is None:
            return 0
        first = (-a % n) * inv % n
        if first == 0:
            first = n
        if first > limit:
            return 0
        return (limit - first) // n + 1

    res = 0
    res += count_hits(x, vx, best_t - 1)
    res += count_hits(y, vy, best_t - 1)
    res += count_hits(x + y, vx + vy, best_t - 1)

    return res

def main():
    t = int(input())
    for _ in range(t):
        n, x, y, vx, vy = map(int, input().split())
        print(solve_case(n, x, y, vx, vy))

if __name__ == "__main__":
    main()
```実装では、頂点の到達可能性と境界カウントを分離します。 の`solve`ルーチンは、展開された格子構造から導出された同時合同性の CRT チェックをエンコードします。 境界カウント ルーチンは、各エッジを線形モジュール条件として扱い、等差数列構造を使用してエスケープ タイムより前の出現をカウントします。 

微妙な点は、時間が剰余として扱われることです。$n$、関連するすべての境界条件と頂点条件がピリオドで繰り返されるため、$n$展開された格子の中で。 これにより、カウントが有限になり、無制限の動きのシミュレートが回避されます。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、軌道の方向が展開システム内の三角形のエッジの 1 つに平行な場合に発生します。 このような場合、モジュラー方程式の 1 つで逆関数が失われるため、解ではそれを正しく拒否するか、逆関数を縮退したものとして扱う必要があります。 たとえば、次の場合$v_x \equiv 0 \pmod{n}$、x 座標はモジュロで変化しません。$n$、とても当たる$x=0$開始位置に応じて、不可能または即時になります。 

もう 1 つのエッジ ケースは、解決時間がちょうど の倍数である場合です。$n$。 この状況では、問題では境界ヒットが頂点に到達する前にのみ厳密に定義されるため、境界カウントでは脱出の瞬間自体を除外する必要があります。 これには注意して使用する必要があります$limit = t - 1$カウント機能で。 

3 番目の微妙なケースは、複数の頂点候補が有効な解を生成する場合です。 最初の到着のみが物理的脱出イベントを決定するため、アルゴリズムは最小の正の時間を取得する必要があります。 これにより、エスケープが発生すると、その後の頂点の位置合わせは無関係になるため、正しい反射カウントが保証されます。
