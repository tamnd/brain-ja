 ## 問題の理解

 順列が与えられます。これは、すべてのノードが出ていくエッジを 1 つだけ持つ有向グラフとして見ることができます。 このような構造は、互いに素な有向サイクルに分解されます。 各サイクルは、相互に循環するポジションのグループを表します。 

この順列の上にレーシング ゲームの解釈が加えられています。 1 つのサイクルを 2 つの小さなサイクルに効果的に分割する操作を実行できます。 重要な自由度は、開始位置を含むサイクル内の特別なチェックポイントを選択できるという事実から来ています。これにより、分割が発生する場所を制御できるため、長さのサイクルを中断できます。`L`合計が以下になる限り、より短いサイクル長の任意の組み合わせに変換できます。`L`。 

目標は、すべてのレーサーが一定のステップ数を経て同時にゴールすることです。`x`。 これをサイクルの観点から解釈すると、すべてのサイクルを正確な長さのサイクルに変換する必要があることを意味します。`x`、長さのサイクルのため`x`正確に最初に戻ります`x`ステップであり、同期にはすべてのコンポーネントがこの期間を共有する必要があります。 

したがって、入力は順列を記述し、出力はすべてのサイクルを同期終了を可能にする共通サイズのサイクルに変換するために必要な最小限の操作数になります。 

制約の観点から見ると、順列サイズは通常大きく、最大で約`2 × 10^5`Codeforces スタイルの問題で。 これにより、二次関数は即座に除外されます。`n`また、リニア スキャンでも、各要素が一定の回数だけ処理されるように慎重に構造化する必要があります。 単一サイクルが大きくなり、何度も中断される可能性があるため、分割サイクルを繰り返しシミュレートするアプローチは実行不可能です。 

順列がすでに単一サイクルである場合、微妙なエッジ ケースが発生します。 その場合、サイクル長は 1 つだけであるため、同期はそのサイズによって自明に制約されます。 もう 1 つのエッジ ケースは、すべてのサイクルがすでに同じ長さである場合です。 そうすれば、実現可能性を検証する以外に分割は必要なくなり、答えはゼロ操作になります。 

たとえば、順列が長さのサイクルで構成されている場合、`[3, 3, 3]`、決定したら操作は必要ありません。`x = 3`。 不注意なアプローチでは、条件がすでに満たされている場合に分割が必要ないことを認識せず、サイクルを不必要に「調整」しようとする可能性があります。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 順列を素のサイクルに分解し、その長さを計算します。 各要素は正確に 1 つの周期軌道に属するため、これはシステムの自然な表現です。 
2. すべてのサイクル長の最大公約数を計算します。 これにより、すべてのサイクルを一貫して分割できる最大のサイクル サイズが取得され、すべてのコンポーネントにわたって均一な分割が可能になります。 
3. サイクル長ごとに`l`、サイズのセグメントの数を計算します`g`に分割できます。`l / g`。 このような各サイクルには次のことが必要です`l / g - 1`最後のパーティションに到達するまで、各操作によってそのサイクル内のセグメント数が 1 つずつ増加するためです。 
4. すべてのサイクルにわたるこれらの値を合計して、システムを長さのサイクルに完全に正規化するために必要な操作の合計数を取得します。`g`。 
5. 合計を出力します。これは、すべてのサイクルを同期するために必要な操作の最小数を表します。 

ステップ 2 が有効である理由は、有効なターゲット サイズはすべてのサイクル長を分割する必要があり、そのようなすべての除数のうち、値が大きいほど、サイクルごとに必要な分割数が厳密に減少するためです。 

### なぜ効果があるのか

 各サイクルは、許可された操作の下で独立して展開します。つまり、すべての最終サイクル長が一致する必要があるというグローバル制約を除いて、1 つのサイクル内の操作は他のサイクルに影響を与えません。 長さのサイクル`L`同じサイズの部分にのみ分解できます`x`もし`x`分割する`L`、そして分割プロセスは常にサイズのサイクルを縮小します`k·x`2 つのサイクルに分割され、そのサイズの合計は`k·x`。 繰り返し適用すると、まさにそれがわかります`k - 1`到達するには分割が必要です`k`サイズのサイクル`x`。 したがって、コストの式はサイクルごとに正確であり、独立性があるためサイクル全体の合計が有効です。 最大化`x`サイクルごとのすべてのコストを同時に最小化します。すべてのサイクルにわたって実現可能性を維持できる唯一の候補は、その長さの gcd です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    vis = [False] * n
    cycles = []

    for i in range(n):
        if not vis[i]:
            cur = i
            cnt = 0
            while not vis[cur]:
                vis[cur] = True
                cur = p[cur] - 1
                cnt += 1
            cycles.append(cnt)

    g = 0
    for c in cycles:
        g = math.gcd(g, c)

    ans = 0
    for c in cycles:
        ans += c // g - 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、未訪問のノードをたどることによってサイクル長を抽出します。 これにより、各要素が 1 つのサイクルに属するため、各要素が 1 回だけ処理されることが保証されます。 

gcd 計算ではサイクル制約が集約され、実現可能な最大の均一セグメント サイズが確実に選択されます。 最後のループでは、整数除算を使用してサイクルごとの分割コストを計算します。これは理論上の値と一致します。`(li / g - 1)`式。 

よくある実装上の間違いは、サイクルごとに 1 を減算するのを忘れることです。これにより、サイクル数が過剰にカウントされます。 もう 1 つの微妙な問題は、サイクル トラバーサル中のインデックス付けです。1 ベースのインデックス付けから 0 ベースのインデックス付けへの変換を忘れると、サイクルの再構築が中断されます。

これは、長さ 4 のサイクルのみが 1 つの分割を必要とするのに対し、長さ 2 のサイクルはすでにターゲット構造と位置合わせされていることを示しています。

 ## 特殊なケース

 完全に固定小数点で構成される順列では、すべて 1 に等しいサイクル長が生成されます。gcd は 1 であり、すべてのサイクルが寄与します。`1/1 - 1 = 0`、したがって、合計の答えはゼロになります。 アルゴリズムは、特別なケースを使用せずにこれを直接処理します。 

次のような単一の大きなサイクル`n = 10`長さ 10 の 1 サイクルでは、gcd は 10 に等しく、やはり演算はゼロになります。 これは、構造がすでに最大限に位置合わせされている場合に、アルゴリズムが誤って不必要な分割を試行しないことを確認します。 

サイクルのような混合構造`[6, 4, 2]`は、gcd 選択の重要性を示しています。 gcd は 2 であり、この値を選択することによってのみ、すべてのサイクルが等しいセグメントに分割可能になり、置換構造全体にわたる一貫性が保証されます。
