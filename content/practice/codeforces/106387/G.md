 ## 解決策
 ## 問題の理解

 都市が道路で結ばれており、各道路には関連する危険値があるグラフが与えられています。 一部の都市はマイルストーン都市としてマークされています。 タスクは、危険がそのしきい値を超えない道路のみを使用する場合、すべてのマイルストーン都市が同じ接続コンポーネント内で接続されるように、可能な限り最小の危険しきい値を決定することです。 

言い換えれば、パスや重みの合計を最適化しようとしているわけではありません。 重要なノードのサブセットを相互に到達可能にするエッジの重みのカットオフ値を見つけようとしています。 

入力は、無向重み付きグラフとして解釈できます。 各エッジは、その重みレベルを許可する場合にのみ接続に寄与し、許可されるしきい値を増やすと、より多くのエッジが使用可能になり、接続されたコンポーネントがマージされます。 出力は、すべての特殊ノードが 1 つの接続コンポーネントに属する最小しきい値です。 

複雑さの観点から見ると、グラフの構造とエッジの数は、クエリごとに単純な方法ですべてのエッジを繰り返しスキャンするソリューションは高価であることを示唆しています。 最大 10^5 のノードとエッジを想定すると、何度も繰り返される線形スキャンでも問題が発生します。 ただし、この問題を解決しやすくする重要な制約は、エッジの重みが小さいか順序付け可能であり、接続性がしきい値に関して単調であることです。 

素朴なアプローチは、考えられる各しきい値を試し、グラフ全体を走査してマイルストーン ノード間の接続をチェックすることです。 これは論理的に機能しますが、重みの範囲が大きい場合は遅くなります。 

微妙なエッジ ケースは、マイルストーン ノードがしきい値 0 ですでに接続されている場合、または最大エッジ ウェイトまで分離されている場合に発生します。 もう 1 つの重要なケースは、マイルストーン都市が 1 つしかない場合です。 その場合、すでにそれ自体に「接続」されているため、答えは自明にゼロになります。 最後のコーナーケースは、すべてのエッジが許可された後でもマイルストーン ノードが別のコンポーネントに存在する場合です。この場合、しきい値は十分ではありませんが、この問題の一般的なバージョンでは、完全なグラフ レベルで接続が保証されていると想定されます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。候補となる危険しきい値 V を選択し、V より大きい重みを持つすべてのエッジを破棄し、BFS または DFS を実行して、すべてのマイルストーン都市が同じ接続コンポーネント内にあるかどうかを判断します。 意図した制約では V の範囲は 1 ～ 100 であるため、すべての値に対してこれを繰り返すだけで十分です。 

これが機能するのは、接続が単調であるためです。 すべてのマイルストーン ノードが最大 V の重みのエッジを使用して接続されている場合、それらはより大きなしきい値に対して接続されたままになります。 故障状態は逆方向にも伝播します。V で切断されている場合、より小さい値では切断されたままになります。 

このアプローチのコストは、考えられる各 V に対してグラフ全体の走査を実行することによって大きく左右されます。各走査のコストは O(N + M) で、それを最大 100 回実行すると O(100(N + M)) になりますが、これは許容範囲内です。 

重みの範囲が大きい場合、すべての値を反復処理するのは非効率的になります。 重要な観察は、述語が true となり、その述語が単調になるような最小値 V を効果的に検索していることです。 これは、V に対する二分探索、またはエッジの重みの増加順に接続性を構築する構造的アプローチのいずれかを即座に示唆します。 

二分探索では O((N + M) log W) が得られますが、より直接的でクリーンな解決策は、クラスカルのアルゴリズムをシミュレートすることです。 エッジを重みでソートし、それらを徐々にアクティブ化すると、素のセット和集合構造を使用して接続されたコンポーネントを維持できます。 コンポーネントをマージするときに、各コンポーネントに含まれるマイルストーン ノードの数も追跡します。 1 つのコンポーネントにすべてのマイルストーン ノードが含まれる瞬間、現在のエッジの重みが答えとなります。

これは、最小スパニング フォレストの構築とまったく同じロジックですが、ノードのサブセット上のグローバル接続条件が満たされたときに早期に停止する点が異なります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (V ごとの DFS) | O(100(N + M)) | O(N + M) | 承認済み |
 | クラスカル + DSU | O(M log M) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 危険度の高い順にエッジを処理する際に、接続されたコンポーネントを維持する素集合結合構造を使用します。 

1. グラフを読んで、どのノードがマイルストーン都市であるかをマークします。 これがターゲット コンポーネント サイズになるため、合計でマイルストーン ノードがいくつ存在するかを数えます。 
2. 各ノードが最初は独自のセットに含まれる DSU を初期化します。 各セットについて、現在含まれているマイルストーン ノードの数を維持します。 最初に、各マイルストーン ノードは、自身のセット カウントに 1 つ寄与します。 
3. 危険値を増加させてすべてのエッジを並べ替えます。 これにより、コンポーネントをマージするときに、常に可能な限り小さいエッジが最初に使用され、しきい値を徐々に緩和するという考えが反映されます。 
4. ソートされた順序でエッジを繰り返します。 u と v を重み w で接続する各エッジについて、その DSU 代表を見つけます。 すでに同じセット内にある場合は、接続を変更しないため、スキップしてください。 
5. 異なるセットにある場合は、それらをマージします。 マージするときは、両方のコンポーネントから新しいルートへのマイルストーン数を合計します。 
6. マージするたびに、結果のコンポーネントにすべてのマイルストーン ノードが含まれているかどうかを確認します。 そうである場合、現在のエッジの重み w はすべてのマイルストーン都市を接続する最小のしきい値であるため、すぐに w を返します。 
7. すべてのマイルストーン ノードを含むコンポーネントに到達せずにすべてのエッジの処理を終了した場合、すべてのマイルストーンが利用可能なエッジの下で完全に接続されることはなく、問題の保証に応じて答えは未定義になります。 

これが機能する理由は、ソートされたエッジ挿入下での接続コンポーネントの単調増加に由来します。 どの時点でも、DSU は、現在処理されているしきい値以下の重みを持つエッジに限定されたグラフの接続性を正確に表します。 エッジを昇順に処理するため、最初にすべてのマイルストーン ノードが 1 つのコンポーネントに表示される時点が、そのような接続が可能になる最小しきい値に対応します。 前のすべてのエッジは厳密に小さいか等しいため、後のステップでより小さい有効なしきい値を生成することはできず、すでに考慮されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, is_milestone):
        self.parent = list(range(n))
        self.size = [1] * n
        self.milestones = [1 if is_milestone[i] else 0 for i in range(n)]
    
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return ra
        
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.milestones[ra] += self.milestones[rb]
        return ra

def solve():
    n, m, k = map(int, input().split())
    milestones = [False] * n
    ms = list(map(int, input().split()))
    for x in ms:
        milestones[x] = True

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((w, u, v))

    dsu = DSU(n, milestones)
    total_ms = sum(milestones)

    edges.sort()

    for w, u, v in edges:
        root = dsu.union(u, v)
        if dsu.milestones[root] == total_ms:
            print(w)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```DSU 構造は、コンポーネントごとの接続性とマイルストーン ノードの数の両方を維持します。 ユニオン操作はサイズとマイルストーン数の両方を更新します。停止条件はマージされたコンポーネント内に特別なノードがいくつあるかを追跡することに依存するため、これは不可欠です。 

ソートのステップにより、マイルストーン ノードの完全なカバレッジに初めて到達した時点が、可能な最小限のしきい値に対応することが保証されます。 後のマージには、それ以上の重みを持つエッジのみが含まれるため、早期の終了は安全です。 

よくある実装の落とし穴は、結合後のルートでのみマイルストーン数を更新するのを忘れることです。 もう 1 つは、入力が 1 ベースの場合にノード インデックスを正規化しないことです。 

## 実用的な例

 4 つのノードと 3 つのエッジを持ち、ノード 1 と 4 がマイルストーンであるグラフを考えてみましょう。 

エッジ:

 (1-2、w=2)、(2-3、w=3)、(3-4、w=5)

 マイルストーン: {1、4}

 ### トレース

 | ステップ | エッジ | 結合後のコンポーネント | マイルストーン数 | 全部繋がってる？ |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2,2) | {1,2}、{3}、{4} | 1、0、1 | いいえ |
 | 2 | (2,3,3) | {1,2}、{2,3}、{4} が結合されました -> {1,2,3}、{4} | 1、1 | いいえ |
 | 3 | (3,4,5) | {1,2,3,4} | 2 | はい |

 重み 5 でエッジを処理した後でのみ、両方のマイルストーン ノードが同じ連結成分になるため、答えは 5 です。 

このトレースは、DSU が接続を徐々に拡張する様子と、グローバル要件に達するまでマージ全体でマイルストーン カウンターがどのように集計されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M log M) | ソートエッジが支配的で、DSU 操作はほぼ一定に償却されます。 
| スペース | O(N + M) | DSU アレイとエッジ ストレージ |

 複雑さは、N と M が最大 10^5 である一般的な制約内に簡単に収まります。 ソートが優先され、DSU 操作はすべての結合と検索に対して実質的に線形になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、マイルストーン ノードが 1 つしかない場合です。 その場合、DSU は、必要なマイルストーンをすべて含むという条件をすでに満たしているノードで初期化されます。 単一のノードをそれ自体に接続するのにエッジは必要ないため、正しい動作は直ちにゼロを返すことです。 

もう 1 つのケースは、マイルストーンが高重みエッジを介してのみ接続されている場合です。 DSU は最初に小さいコンポーネントをマージしますが、最後に必要なエッジが処理されるまで、マイルストーン カウンタは合計に達しません。 これにより、最小の接続構造内の最大のエッジが正しく反映された答えが得られます。 

最後のケースは、複数のコンポーネントにマイルストーン ノードのサブセットが含まれている場合です。 マイルストーン数はユニオン中に集計され、すべてのマイルストーンをカバーするコンポーネントを最初にユニオンが作成した場合にのみ、答えがトリガーされるため、アルゴリズムはこれを自然に処理します。
