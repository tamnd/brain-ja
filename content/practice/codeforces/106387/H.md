 ## 解決策
 ## 問題の理解

 各要素がノードであり、各ルールが 1 つのノードから別のノードにどのように移動できるかを記述する有向エッジである有向システムが与えられています。 各ノードは何らかの値を提供し、有向パスに沿って歩くと、訪問したノードの値が収集されます。 重要な点は、サイクルによって制限されないということです。サイクルに入ると、そのサイクルを自由に移動できるため、実現可能性を変えることなく、循環構造内のすべてのノードを必要なだけ効果的に訪問できます。問題となるのはコンポーネントの固有の寄与のみです。 

このタスクは、指定されたノードから開始して有向エッジを任意の回数たどることによって取得できる最大合計値を計算することです。 

パスは任意の長さにすることができますが、ノードを再訪問しても、強く接続された構造内で最初の意味のある訪問を超えて価値が増加することはありません。 これは、強く接続された各コンポーネントが単一の原子単位として動作するようにグラフを圧縮する必要があることを直ちに示唆しています。 

複雑さの観点から見ると、このタイプの一般的な定式化では、入力には最大約 200,000 個のノードとエッジが含まれる可能性があります。 これにより、二次またはサブセット列挙アプローチが除外されます。 単一のサイクルでも既に無限に多くのウォークが作成されるため、パスを明示的に探索しようとするソリューションは失敗します。 唯一実現可能なアプローチは、グラフのサイズを線形またはほぼ線形にすることです。 

サイクルが圧縮なしで通常のノードとして扱われる場合、微妙な失敗のケースが発生します。 たとえば、3 つのノードがサイクルを形成し、それぞれが正の重みを持つ場合、走査に沿って値を合計する単純な DFS はサイクルを複数回カウントする可能性があります。 

入力例：```
3 3
1 2 3
1 2
2 3
3 1
1
```正しい出力は`6`なぜなら、3 つのノードはすべて相互に到達可能であり、一度グループとして考えることができるからです。 単純な走査では、実装によっては誤って値を繰り返し蓄積する可能性があります。 

別のエッジ ケースは、開始ノードが、合計の重みがより高い他のコンポーネントに接続するサイクル内にある場合に発生します。 サイクルが圧縮されていない場合、単純な DAG 構造を前提とするアルゴリズムは最適な遷移を正しく伝播できません。 

## アプローチ

 直接的なアプローチは、開始ノードから検索を実行し、可能なパスをすべて試し、途中でノード値を蓄積することです。 これはすべての有効なウォークを探索するため、原理的には正しいですが、サイクルによって無限に多くのウォークが生成され、メモ化を使用しても同じ状態が異なるコンテキストで再訪される可能性があるため、すぐに破綻します。 個別のパスの数は、グラフ サイズに応じて指数関数的に増加します。 

重要な観察は、強く接続されたコンポーネント内では、すべてのノードが相互に到達可能であるということです。 このようなコンポーネントを入力すると、内部順序を気にせずにそのすべてのノードの値を収集できます。 これにより、各 SCC を、そのメンバーの合計が重みとなる単一のスーパーノードに折りたたむことができます。 

この圧縮後、コンポーネント間のすべてのエッジが有向非巡回グラフを形成します。 各サイクルが単一の SCC 内に完全に含まれるため、元のグラフ内のサイクルはすべて消えます。 この DAG では、問題は開始ノードを含む SCC から始まる古典的な最長パスの問題になります。 

次に、圧縮されたグラフの位相順序を計算し、動的プログラミングを実行して、各コンポーネントから到達可能な最大合計を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 | 指数 | 指数 | 遅すぎる |
 | SCC 圧縮 + DAG DP | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、グラフを標準の動的計画法が有効となる構造に変換します。 

1. Tarjan または Kosaraju のアルゴリズムを使用して、強く接続されたすべてのコンポーネントを特定します。 このステップでは、双方向で相互に到達できるノードをグループ化します。 これが必要な理由は、そのようなグループ内ではすべてのノードが相互にアクセスできるため、走査順序は重要ではないためです。 
2. 各ノードにコンポーネント識別子を割り当てます。 その後、元のすべてのエッジがコンポーネント間のエッジに変換され、同じコンポーネント内にあるエッジは無視されます。 これにより、ノードが SCC である新しいグラフが作成されます。 
3. 各 SCC 内のすべてのノードの値を合計することにより、各 SCC の合計重みを計算します。 これにより、元の各ノードが最終計算に 1 回だけ寄与することが保証されます。 
4. SCC の要約グラフを作成します。 SCC が最大であるため、このグラフは非周期的である必要があります。 どのサイクルもコンポーネントの最大値と矛盾します。 
5. 凝縮されたグラフのトポロジカル順序付けを実行します。 この順序により、コンポーネントを処理するときに、そのコンポーネントに到達できるすべてのコンポーネントが確実に処理されるようになります。 
6. DAG 上で動的プログラミングを実行します。 定義する`dp[c]`コンポーネントから開始して取得可能な最大合計値として`c`。 すべての値を SCC 重みに初期化します。 
7. 逆のトポロジー順序でコンポーネントを処理します。 各コンポーネントについて、すべての発信エッジを試し、到達可能な最適な合計を更新します。`dp[c] = max(dp[c], weight[c] + dp[next])`。 
8. 答えは次のとおりです。`dp[start_component]`。 

これが機能する理由は、SCC 圧縮後、すべてのパスが DAG 内の単純なパスに対応するためです。 DP は、状態を再検討することなく、各ノードから最適な継続を正確に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    order = []
    vis = [False] * n

    def dfs1(v):
        vis[v] = True
        for to in g[v]:
            if not vis[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not vis[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    n, m = map(int, input().split())
    val = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        gr[v].append(u)

    start = int(input()) - 1

    comp, cnum = kosaraju(n, g, gr)

    comp_sum = [0] * cnum
    for i in range(n):
        comp_sum[comp[i]] += val[i]

    cg = [[] for _ in range(cnum)]
    indeg = [0] * cnum

    for u in range(n):
        for v in g[u]:
            cu, cv = comp[u], comp[v]
            if cu != cv:
                cg[cu].append(cv)
                indeg[cv] += 1

    from collections import deque
    q = deque()
    for i in range(cnum):
        if indeg[i] == 0:
            q.append(i)

    topo = []
    while q:
        x = q.popleft()
        topo.append(x)
        for to in cg[x]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)

    dp = comp_sum[:]

    for x in reversed(topo):
        for to in cg[x]:
            dp[x] = max(dp[x], comp_sum[x] + dp[to])

    print(dp[comp[start]])

if __name__ == "__main__":
    solve()
```コードの最初の部分では、Kosaraju のアルゴリズムを使用して強結合成分を計算します。 第 2 フェーズでは、要約グラフを構築し、コンポーネントごとの重みを集計します。 3 番目のフェーズでは、indegrees を使用してトポロジカル ソートを実行し、非循環的な順序付けを保証します。 最後に、DP ステップは各 SCC から達成可能な最良の値を計算し、結果を DAG に沿って逆方向に伝播します。 

よくある実装の落とし穴は、SCC 構築内の自己エッジを無視することを忘れることです。これにより、度数が人為的に膨張し、トポロジカルな順序が崩れてしまいます。 もう 1 つの微妙な問題は、DP の前にノードの重みを集計しないことです。これは、寄与の過少カウントにつながります。

 ## 特殊なケース

 すべてのノードが両方向に接続されているサイクルの多いグラフは、すべてを 1 つのコンポーネントに折りたたむことで処理されます。 その後、DP はすべてのノードの重みの合計に等しい単一の値に減少し、遷移は必要ありません。 

開始ノードに出力エッジがないグラフは、その SCC には圧縮グラフ内の出力エッジがないため、自明に処理されます。そのため、DP はそのコンポーネントの重みを正確に返します。 

複数の切断されたコンポーネントを含むグラフは、開始ノードから到達可能なコンポーネントのみが DP 伝播に影響を与えるため、安全です。 DP は開始コンポーネントからのみ評価されるため、到達不能な SCC は未使用のままになります。
