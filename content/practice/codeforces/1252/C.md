 ## 解決策
 ## 問題の理解

 この問題のグリッドは明示的に指定されていません。$N \times N$マトリックス。 代わりに、すべてのセル値は単純な加算構造、つまり位置の値によって決定されます。$(i, j)$は$R_i + C_j$。 これは、各行が固定オフセットに寄与することを意味します$R_i$、各列は固定オフセットに寄与します。$C_j$。 すべての移動は、グリッド上の 4 方向の隣接に制限されます。 

パスは標準的なグリッド ウォークであり、各ステップで 1 つのセルが上下左右に移動します。 ただし、値が偶数のセルのみが使用可能です。 クエリは、両方とも偶数値であることが保証されている 2 つの指定されたセルを、偶数値のセルのみを使用して接続できるかどうかを尋ねます。 

重要な難点は、$N$そして$Q$どちらも最大です$10^5$そのため、グリッドを構築したり、クエリごとにグラフ検索を実行したりすることはできません。 クエリごとに BFS または DFS を試行するソリューションは、すぐに次のように縮退します。$O(N^2)$または$O(N^2 Q)$最悪の場合、限界をはるかに超えてしまいます。 

主な構造上の制約は、グリッドが任意ではないということです。 各セルのパリティは以下にのみ依存します。$R_i + C_j \bmod 2$これにより、偶数セルのグラフの動作が強く制限されます。 

微妙なエッジ ケースは、セルが複数の行と列に存在する場合でも、すべてが接続されているとは限らないという事実から発生します。 たとえば、すべての偶数セルがチェッカーボード パターン内にあり、一部のコンポーネントが分離されている場合、有効な隣接セルがグローバルに多数存在しても、接続は失敗します。 

もう 1 つの潜在的な間違いは、移動は 4 方向であるため、接続性は座標のパリティのみに依存すると考えることです。 パリティは位置ではなく値に依存するため、これは誤りです。 

## アプローチ

 ブルート フォース アプローチでは、グリッドを明示的に構築し、すべての偶数値セルにマークを付け、クエリごとに BFS または DFS を実行します。 グリッド グラフの接続性はトラバーサルによって自然に解決されるため、これは概念的に機能します。 ただし、グリッドの構築にはすでにコストがかかります$O(N^2)$メモリと時間、そしてクエリごとに走査を行うと、別の要素が追加されます。$O(N^2)$、完全に実行不可能になります。 

重要な観察は、セルが均一になるように条件を書き換えることから得られます。 細胞$(i, j)$次の場合に使用できます。$$(R_i + C_j) \bmod 2 = 0$$これは次と同等です。$$R_i \bmod 2 = C_j \bmod 2$$これにより、構造的なことがすぐにわかります。各行にはパリティ ラベルがあります。$p_i = R_i \bmod 2$、各列にはパリティ ラベルがあります。$q_j = C_j \bmod 2$。 セルは次の場合にのみ有効です。$p_i = q_j$。 したがって、有効なセルは、一致するパリティ クラスの交差点にのみ存在します。 

次に動きを考えてみましょう。 有効なセルから$(i, j)$、水平方向に移動すると、列インデックスのみが変更されます。 それで$(i, j)$に接続します$(i, j \pm 1)$両方が有効な場合にのみ。 それには次のことが必要です。$$p_i = q_j \quad \text{and} \quad p_i = q_{j \pm 1}$$したがって、水平方向の移動は、同じパリティを持つ隣接する列間でのみ可能です。$C$。 同様に、垂直方向の移動には、同じパリティを持つ隣接する行が必要です。$R$。 

これにより、グリッドが 2 つの独立した 1D 隣接構造に縮小されます。1 つは行上にあり、$R_i$指定されたパリティを持ち、列全体で 1 つあります。$C_j$所定のパリティを持ちます。 連結コンポーネントは、どのパリティ クラスに属するか、および一致するパリティ セグメントがどの程度連続しているかによって完全に決定されます。 

これは、同じパリティを持つ連続する行をセグメントに圧縮し、列に対しても同じことを行うという標準的なトリックにつながります。 そうすれば、動きを行セグメントと列セグメントの二部構成のような構造の上を歩くものとして扱うことができます。 各セルは一意のペアに属します$(\text{row segment}, \text{column segment})$、接続性は、このような 2 つのペアがこの誘導グラフの同じ接続コンポーネントに存在するかどうかに帰着します。 これは、すべての行セグメントと列セグメントにわたる素集合結合を使用して効率的に処理されます。 

より単純ですが同等の観点は、上に DSU を構築することです。$2N$各行と各列がノードです。 列を繋ぎます$i$そしてコラム$j$もしセルが$(i, j)$は有効であり、パリティが一致することを意味します。 次に、各クエリは、2 つのセルの行と列の両方が、行と列の交互接続を通じて同じ接続構造内にあるかどうかを確認します。 

### 比較

 ## アルゴリズムのチュートリアル

 1. 行と列のパリティ配列を計算します。各行は$i$店$R_i \bmod 2$そしてそれぞれの列$j$店$C_j \bmod 2$。 これにより、すべての値情報が 1 ビットに圧縮され、セルの有効性が完全に決定されます。 
2. 互いに素な集合共用体構造を作成します。$2N$ノード、インデックス$1 \ldots N$行を表し、$N+1 \ldots 2N$列を表します。 行と列の制約の間で移動が交互に行われるため、この分離は不可欠です。 
3. すべてのセルについて$(i, j)$、どうかを確認してください$R_i \bmod 2 = C_j \bmod 2$。 この条件が成立した場合、ノードを結合します$i$(行) ノードあり$N + j$（カラム）。 その理由は、有効なセルでは行と列の間の走査が許可されるため、それらは同じ接続コンポーネントに属している必要があるからです。 
4. すべての結合が実行された後、各行と列は、交互の有効な移動によって到達可能なすべての位置を表す DSU コンポーネントに属します。 
5. 質問に答えるため$(r_a, c_a, r_b, c_b)$, 2つの条件を確認してください。 まず、両方のエンドポイントが有効であることが保証されています。 次に、クエリは次の場合にのみ有効です。$$\text{find}(r_a) = \text{find}(r_b) = \text{find}(N + c_a) = \text{find}(N + c_b)$$これにより、両方のセルが行と列が交互に切り替わる同じ接続構造内に存在することが保証されます。 

### なぜ効果があるのか

 DSU は、左側が行、右側が列である 2 部グラフで到達可能性をモデル化します。 有効な各セルは行ノードと列ノードの間にエッジを作成し、グリッド内のすべての移動はこれらの行と列の接続に沿った移動に対応します。 グリッド内のパスは行と列を交互に繰り返すため、有効なパスはすべてこの 2 部グラフのウォークに対応します。 このグラフの接続性は、元のグリッド内の偶数パスの存在と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    N, Q = map(int, input().split())
    R = list(map(int, input().split()))
    C = list(map(int, input().split()))

    Rpar = [x % 2 for x in R]
    Cpar = [x % 2 for x in C]

    dsu = DSU(2 * N)

    for i in range(N):
        for j in range(N):
            if Rpar[i] == Cpar[j]:
                dsu.union(i, N + j)

    out = []
    for _ in range(Q):
        ra, ca, rb, cb = map(int, input().split())
        ra -= 1
        ca -= 1
        rb -= 1
        cb -= 1

        if (dsu.find(ra) == dsu.find(rb) ==
            dsu.find(N + ca) == dsu.find(N + cb)):
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、行と列を Union-find 構造にエンコードし、有効なセルが存在するたびにそれらを接続します。 クエリ チェックが機能するのは、有効な移動が行ノードと列ノードの間で交互に行われる必要があるためです。そのため、到達可能なすべてのセルが両方の次元にわたって共通の DSU 代表を共有します。 

実装の微妙な詳細は、列のインデックスのシフトです。 行が占有$[0, N-1]$、列は にマップされます。$[N, 2N-1]$。 これらのインデックスを混在させると、サイレントコレクトネスバグの一般的な原因になります。

    import sys

        def __init__(self, n):
            self.p = list(range(n))
            self.r = [0] * n
        def find(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x
        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a == b:
                return
            if self.r[a] < self.r[b]:
                a, b = b, a
            self.p[b] = a
            if self.r[a] == self.r[b]:
                self.r[a] += 1

    N, Q = map(int, input().split())
    R = list(map(int, input().split()))
    C = list(map(int, input().split()))

    Rpar = [x % 2 for x in R]
    Cpar = [x % 2 for x in C]

    dsu = DSU(2 * N)

        ra -= 1
        ca -= 1
        rb -= 1
        cb -= 1

        ok = (dsu.find(ra) == dsu.find(rb) ==
              dsu.find(N + ca) == dsu.find(N + cb))
        out.append("YES" if ok else "NO")

    return "\n".join(out)

 ## 特殊なケース

 まれなケースは、行と列の間に 1 つのパリティ アライメントのみが存在する場合に発生します。 このような状況では、DSU は単一の大きなコンポーネントに折りたたまれ、すべての有効なセルが相互に到達可能になります。 すべての共用体が 1 つのルートにマージされるため、アルゴリズムはこれを自然に処理します。そのため、有効なセル間のクエリはすべて YES を返します。 

もう 1 つのエッジ ケースは、有効なセルは存在するが、切断されたバンド内に配置されている場合です。 たとえば、交互の行のみが交互の列と一致する場合、接続は複数の DSU コンポーネントに分割されます。 結合ステップでは、実際に接続された行と列のペアのみがマージされるため、バンド全体のクエリは正しく NO を返します。
