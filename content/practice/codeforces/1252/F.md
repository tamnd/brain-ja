 ## 解決策
 ## 問題の理解

 最大 4000 個のノードを持つツリーが与えられ、単一のノードを選択して削除することができます。 ノードを削除すると、ツリーが複数の接続されたコンポーネントに分割され、各コンポーネント自体がツリーになります。 コンポーネントの数は、削除されたノードの次数に等しくなります。 

重要な条件は非常に強力です。選択したノードを削除した後、結果として得られるすべてのコンポーネントは構造的に同一のツリーでなければなりません。 同じサイズであるだけでなく、根付きのラベルのない木と同型です。つまり、隣接性を維持する頂点間に全単射が存在します。 

このようなノードが存在する場合、それを有効な切断点と呼びます。 すべての有効な切断点の中で、作成されるコンポーネントの最大数が必要です。 有効なノードが存在しない場合は、-1 を出力します。 

入力は単なるツリーであるため、サイクルはなく、正確に N-1 個のエッジが存在します。 この課題は純粋にノードを中心としたツリー構造の対称性に関するものです。 

N ≤ 4000 という制約は、O(N³) または頻繁に繰り返されるサブツリー比較を伴うものは危険である一方、ハッシュを伴う O(N² log N) または O(N²) は許容されることを示唆しています。 各ノードについて多くのサブツリーを比較する必要がある場合があるため、コンポーネントのすべてのペア間の単純な同型性チェックは、再利用またはハッシュなしでは非常に遅くなります。 

ノードに同じように見えるサブツリーがあるが、その形状がより深いところでわずかに異なる場合、微妙な失敗のケースが発生します。 サイズや程度だけを比較する単純なアプローチでは、そのようなケースを誤って受け入れることになります。 別の失敗例は、2 つの子のサブツリーがローカルで一致する場合、フォレスト全体がより深い構造をチェックせずにグローバルに一致すると仮定することです。 

## アプローチ

 強引なアイデアは、すべてのノードを潜在的なカットポイントとして試すことです。 各ノード u について、それを削除し、その近傍をルートとする k 個のサブツリーを取得します。 次に、これらの k ツリーのすべてのペアを比較して同型性を確認します。 すべてが同一の場合、k を記録します。 

2 つのツリーが同型であるかどうかの確認は、ハッシュまたは標準エンコーディングによって実行できますが、ハッシュを使用した場合でも、すべてのペアおよびすべてのノードに対してこれを最初から行うと、ペアごとに約 O(N²) ノードと O(N) の比較が必要になり、最悪の場合には時間がかかりすぎます。 

重要な観察は、すべての候補について完全にルートを変更した比較を行う必要はないということです。 本当に必要なのは、ツリー内のすべてのルート化されたサブツリーの正規表現です。 ツリーをどこかにルートすると、すべてのノードにそのサブツリーの構造を表すハッシュを割り当てることができます。 

次に、ノード u を削除することを検討すると、u の各近傍 v は、v をルートとして u を除外することによって得られるルート付きサブツリーに対応します。 そのサブツリーの構造は、まさに v でルート化されたサブツリーから親 u が削除されたものであり、親子 DP から計算できます。 

したがって、問題は次のようになります。すべてのノード u について、そのすべての隣接サブツリーのハッシュを収集し (各隣接ノードが 1 つのサブツリーに寄与します)、すべてのハッシュが同一かどうかを確認します。 「はい」の場合、u の次数が答えの候補になります。 

サブツリー ハッシュを効率的に計算するために、リルートまたは親認識ハッシュを使用してツリー DP を実行します。 標準的なアプローチは、ルート ツリーを 1 で計算し、子のハッシュをボトムアップで計算し、各ノードが各隣接方向に進むときに形成されるコンポーネントのハッシュを認識できるように情報を伝播することです。 

リルート DP を使用して方向性ハッシュを計算できます。ノードごとに、子ハッシュのマルチセットを維持し、その親からの「上向き」寄与も計算します。 次に、各エッジ (u, v) は、u が削除されたときに v を含むコンポーネントのハッシュを生成します。 

最後に、各ノード u について、すべての隣接方向ハッシュを調べます。 それらがすべて等しい場合、u は有効であり、degree(u) に寄与します。 最大値を取ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ノードごとのブルートフォース同型性 | O(N3) 最悪の場合 | O(N) | 遅すぎる |
 | 再ルートを伴うツリーのハッシュ | O(N) から O(N log N) | O(N) | 承認済み |

## アルゴリズムのチュートリアル

 ノード 1 でツリーを任意にルートします。 

1. 子から親へのハッシュを使用して、各ノードのサブツリーのルート表現を計算します。 各ノード u について、u をルートとするサブツリーの構造を表すハッシュを計算します。 このボトムアップ パスにより、すべてのサブツリーに正規の署名があることが保証されます。 
2. 隣接関係ベースの情報を構築して、有向エッジ u → v ごとに、u を削除した後に v を含むコンポーネントのハッシュを計算できるようにします。 u を削除すると、固定されたルート方向で子をルートとするサブツリーだけでなく、ツリーが複数のルート部分に分割されるため、これが必要です。 
3. リルートトラバーサルを実行します。 親 u から子 v に移動するとき、u のサブツリー ハッシュから v の寄与を削除し、それを「外部」の寄与に置き換えます。これにより、u が削除されたときに v をルートとするコンポーネントの正しいハッシュを計算できるようになります。 
4. すべてのノード u について、各近傍 v (つまり、u を削除した後に形成された各コンポーネント) に対応するハッシュを収集します。 これらのハッシュがすべて同一かどうかを確認します。 
5. それらが同一であり、少なくとも 2 つの近傍がある場合、u は有効な切断点であり、そのスコアはdegree(u) です。 そのようなすべてのノードの最大値を追跡します。 
6. 見つかった最大値を出力します。条件を満たすノードがない場合は -1 を出力します。 

機能する理由: リルート DP は、すべてのエッジ (u, v) について、計算されたハッシュが、u を削除した後に v に接続されたままのコンポーネントの完全な構造に正確に対応することを保証します。 ツリーの同型性は正規ハッシュによって完全にキャプチャされるため、すべての隣接方向ハッシュが等しいことは、結果として得られるすべてのコンポーネントのペアごとの同型性と同等です。 これにより、グローバルな構造比較の問題が、事前に計算された正規署名のローカルな等価性チェックに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

N = int(input())
g = [[] for _ in range(N)]

for _ in range(N - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

# we will compute rooted subtree hashes with two-direction DP

parent = [-1] * N
order = []

# build parent order
stack = [0]
parent[0] = -2
while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if parent[v] == -1:
            parent[v] = u
            stack.append(v)

parent[0] = -1

# subtree hash (bottom-up)
MOD = (1 << 61) - 1

import random
base = [random.randrange(10**9, 10**18) for _ in range(N)]

sub = [1] * N

for u in reversed(order):
    h = 3
    for v in g[u]:
        if v == parent[u]:
            continue
        h += sub[v] * base[v]
        h %= MOD
    sub[u] = h

# compute "up" hashes via rerooting
up = [1] * N

ans = -1

def dfs(u, p):
    global ans
    # collect child contributions including parent direction
    vals = []
    for v in g[u]:
        if v == p:
            vals.append(up[u])
        else:
            vals.append(sub[v])

    # check if all equal and degree >= 2
    ok = True
    if len(vals) >= 2:
        for i in range(1, len(vals)):
            if vals[i] != vals[0]:
                ok = False
                break
        if ok:
            ans = max(ans, len(vals))

    # reroot to children
    prefix = []
    suffix = []

    children = []
    for v in g[u]:
        if v != p:
            children.append(v)

    for v in children:
        prefix.append(sub[v])
        suffix.append(sub[v])

    # prefix/suffix not strictly needed; we recompute per child simply
    for v in children:
        # compute contribution from u when moving root to v
        total = up[u]
        for w in children:
            if w == v:
                continue
            total += sub[w] * base[w]
            total %= MOD
        up[v] = (3 + total) % MOD
        dfs(v, u)

dfs(0, -1)

print(ans)
```このコードは、まず DFS 順序を使用して親配列を構築します。 次に、各サブツリーのボトムアップ ハッシュを計算します。 その後、各有向エッジが対応する「外側のサブツリー」ハッシュを持つようにツリーを再ルートします。 

DFS 内では、各ノード u について、インシデント エッジごとに 1 つのハッシュが収集されます。子はサブツリー ハッシュを提供し、親は再ルートされた「アップ」ハッシュを提供します。 これらの値がすべて一致する場合、そのノードは有効な切断点です。 答えはその程度に応じて更新されます。 

微妙な実装の詳細は、ルートを下に渡すときに、再ルート化ステップで子自身の貢献を除外する必要があることです。 これにより、「上」の値がエッジを削除した後に残るコンポーネントを正確に表すことが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N²) 最悪の場合 | rerooting は最悪の場合にエッジごとの寄与を再計算します。 
| スペース | O(N) | 隣接関係、ハッシュ、親、DP 配列 |

 制約により N は最大 4000 まで許容されるため、O(N²) アプローチが安全です。 ハッシュのオーバーヘッドは一定の係数で小さく、各ノードは隣接するノードを制限された回数だけ処理し、実行時間を制限内に十分に保ちます。

 ## 特殊なケース

 重要なエッジ ケースは、ノードの次数が 2 であるが、結果として得られる両方のコンポーネントが同一ではない場合です。 たとえば、長さ 3 のパスで、非対称に拡張すると中間ノードを削除すると、異なる構造の 2 つのパスが作成されますが、隣接するハッシュが異なるため、アルゴリズムはそれを正しく拒否します。 

もう 1 つのエッジ ケースは、複数のサブツリーのサイズは同じだが同型ではない場合です。 ハッシュ化により構造的な差異が確実に捕捉されるため、等しいサイズが等価性チェックに誤って合格することがなくなります。 

最後に、星やバランスの取れた繰り返しパターンなどの対称性の高いツリーは、すべての隣接方向ハッシュが同じ正規値に折りたたまれるため、自然に処理され、アルゴリズムが最大の有効次数を正しく識別できるようになります。
