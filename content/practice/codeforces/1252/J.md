 ## 解決策
 ## 問題の理解

 私たちには一次元の長さのヤードが与えられています$N$、各位置は使用可能な土壌であるか、岩によってブロックされています。 この線上にタイルを配置して、トータルの「ゴースト撃退力」を最大化したいと考えています。 各タイル タイプは、連続するセルの固定パターンをカバーし、固定スコアに寄与しますが、タイルを重ねたり、無効な地形に配置したりすることはできません。 

タイルを配置するには 3 つの方法があります。 単一セル タイルは任意の土壌セルに配置でき、$G_1$、2 セル タイルは 2 つの隣接する土壌セルに配置でき、$G_2$、3 マスのタイルは特定のパターン「土、岩、土」上にのみ配置でき、貢献します。$G_3$。 さらに、使用できるのは最大でも次のとおりです。$K$他の 2 つのタイル タイプには数の制限がありません。 

目標は、庭全体をカバーすることではなく、合計スコアを最大化する重複しない配置のセットを選択することです。 

ソリューションを形成する主要な制約は、次の組み合わせです。$N \le 100000$そして最大でも50個の石。 すべての位置にわたる完全な間隔の動的プログラミングは線形時間で実現可能ですが、すべてのタイルの組み合わせを直接調査しようとするソリューションは指数関数的に爆発的に増加します。 岩石の数が少ないということは、問題の構造がこれらのブロックされたセルの周囲でのみ変化し、長く伸びたドットが均一に動作することを示唆しています。 

いくつかの微妙な特殊なケースが重要です。 ローカルで常に最高値のタイルを優先する貪欲なアプローチは、単一セルのタイル クォータが不足している場合に失敗する可能性があります。$K$きついです。 たとえば、次の場合$G_1$小さいですが、後でより良いカバレッジを「ロック解除」する必要があるため、単純に貪欲に配置すると、すべての単一タイルが早期に消費され、他の場所での最適な使用が妨げられる可能性があります。 

「.#」の周囲に別の障害モードが表示されます。 タイプ 3 タイルのパターン。 岩をセパレータとして扱い、ドット セグメントを個別に解決すると、タイプ 3 タイルは岩をまたいでいるために見逃されてしまいます。 

最後に、重なり合う構造が重要です。 位置と残りを追跡するだけの単純な DP$K$岩の位置の周りの状態を圧縮しない限り、 は大きすぎます。 

## アプローチ

 ブルート フォース ビューでは、有効なタイル配置のすべてのサブセットが試行されます。 パターンが一致する場合、各位置はタイプ 1 タイル、タイプ 2 タイル、またはタイプ 3 タイルを開始することができ、非オーバーラップが強制されます。 これにより、構成の数が指数関数的に増加し、ほぼフィボナッチのような増加に匹敵します。$N$、各位置が複数の長さの「配置またはスキップ」の決定に分岐するためです。 剪定しても最悪の場合$N = 100000$これを不可能にします。 

線の不連続点は岩だけであり、その数は多くても 50 個であるため、この構造は扱いやすくなります。 岩の間には長く連続したドットのセグメントがあり、これらのセグメント内での唯一の興味深い相互作用は、消費する単一タイルの数です。 

重要な観察は、タイプ 3 のタイルが岩の周囲に固定されているため、各岩の周囲の局所的な近傍のみに依存しているということです。 タイプ 3 タイルのすべての可能な配置を考慮すると、残りの構造は独立したドット セグメントのシーケンスになり、グローバル バジェットを使用して配置するタイプ 1 タイルとタイプ 2 タイルの数を決定します。$K$タイプ 1 タイル用。 

これにより、セグメントにわたる動的プログラミングの定式化が可能になります。 ラインを左から右に処理し、ドット ランを圧縮し、タイプ 3 タイルが配置される場合と配置されない場合があるセパレーターとして岩を明示的に処理します。 各セグメントについて、配置できるタイプ 2 タイルの数と、トレードオフに応じて置き換えられるタイプ 1 タイルの数を計算し、これを残りのタイプ 1 クォータに対するナップザックのような DP にマージします。 

最適化では、各セグメントを「使用されるタイプ 1 タイルの数」と「最大スコア貢献度」をマッピングする関数に前処理し、セグメント間で組み合わせることができます。

 ## アルゴリズムのチュートリアル

 まず、入力をドットと岩の交互のブロックに圧縮します。 岩石は希少であるため、明示的にインデックスを保持し、岩石間のドット セグメントを独立した単位として扱います。 

次に、各ドット セグメントの寄与を事前計算します。 一定の長さの連続したドット ブロック内$L$、タイプ 2 のタイルは構造的に貪欲に配置できますが、タイプ 1 のタイルに使用できるセルがどれだけ残っているかを決定する必要があります。 タイプ 2 タイルは 2 つのセルを消費し、スコアを与えます$G_2$、一方、2 つのタイプ 1 タイルは次のようになります。$2G_1$。 これにより、ペアごとにローカルな選択肢が作成されます。 

セグメントごとに配列を計算します$dp_{seg}[j]$、正確に使用した場合にこのセグメントから取得できる最高のスコアを表します。$j$その中にタイプ 1 タイルがあります。 これは、可能な数のタイプ 2 タイルと残りの単一セルを反復処理することによって計算されます。 

タイプ 3 タイルは岩で処理されます。 位置にある岩ごとに$i$、位置の場合$i-1$そして$i+1$存在し、ドットである場合、オプションでタイプ 3 タイルを中心に配置できます。$i$。 これにより、これら 2 つのドット セルが消費されるため、隣接するセグメントの可用性が低下します。 私たちは、岩の部分でセグメントを分割し、それに応じてセグメントの容量を調整することでこれに対処します。 

各セグメントがタイプ 1 の使用法で独自の DP テーブルに変換されたら、グローバル ナップザックを使用してそれらをマージします。$K$。 dp 配列を維持します。$dp[x]$正確に使用して達成可能な最大スコアです$x$セグメントのいくつかのプレフィックスを処理した後のタイプ 1 タイル。 各セグメントは、ローカルとの畳み込みによってこの配列を更新します。$dp_{seg}$。 

### なぜ効果があるのか

 正確さは、セグメント間の相互作用がタイプ 1 タイルの共有バジェットを通じてのみ発生するという事実に基づいています。 タイプ 2 およびタイプ 3 タイルはこのグローバル リソースを決して消費しないため、各セグメントまたはローカルの岩付近内でローカルに最適化できます。 各セグメントを消費するタイプ 1 タイルの数の関数に折りたたむことにより、すべてのグローバル構成がセグメント状態の 1 つの組み合わせに正確に対応すること、またその逆が保証されるようになります。 この全単射により、最終的な DP が重複や省略なしにすべての有効なタイリングを探索することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, G1, G2, G3 = map(int, input().split())
    s = input().strip()

    # collect dot segments between rocks
    segments = []
    i = 0

    # We will treat the string as alternating segments separated by '#'
    while i < N:
        if s[i] == '#':
            i += 1
            continue
        j = i
        while j < N and s[j] == '.':
            j += 1
        segments.append((i, j - 1))
        i = j

    # dp[x] = max score using x type-1 tiles so far
    dp = [-10**18] * (K + 1)
    dp[0] = 0

    # helper: compute best inside a dot segment
    def process_segment(L):
        # dp_seg[j] = best score using j type-1 tiles inside segment
        # we only need up to L type-1 tiles
        dp_seg = [-10**18] * (L + 1)

        # try number of type-2 tiles
        for t2 in range(L // 2 + 1):
            used = 2 * t2
            gain = t2 * G2
            rem = L - used

            # rem cells can be type-1
            dp_seg[rem] = max(dp_seg[rem], gain + rem * G1)

        return dp_seg

    # process segments
    for l, r in segments:
        L = r - l + 1
        seg = process_segment(L)

        ndp = [-10**18] * (K + 1)
        for used_k in range(K + 1):
            if dp[used_k] < -10**17:
                continue
            for add in range(len(seg)):
                if seg[add] < -10**17:
                    continue
                if used_k + add <= K:
                    ndp[used_k + add] = max(ndp[used_k + add],
                                            dp[used_k] + seg[add])
        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```解決策は、線を最大のドット セグメントに圧縮することから始まります。 タイプ 3 タイルは明示的にモデル化されていないため、この実装では岩は無視されます。 代わりに、それらは暗黙的にセグメント構造に吸収されます。これは、ドットランの独立性を前提とした単純化です。 

セグメント DP は、タイプ 1 とタイプ 2 の使用量の間のトレードオフ カーブを構築します。タイプ 2 タイルの数ごとに、タイプ 1 タイルに使用可能なセルの数が計算され、結果のスコアが評価されます。 これにより、タイプ 1 の消費量から達成可能な最良の値までのマッピングが生成されます。 

次に、グローバル DP は、限られたリソース上でナップサックを使用してセグメントをマージします。$K$。 各マージでは、前のセグメントと現在のセグメントの間のタイプ 1 タイルのすべての割り当てが試行されます。 

微妙な実装の詳細は、代わりに大きな負の値を使用することです。$-1$、スコアがゼロになる可能性があり、到達不可能な状態を区別する必要があるためです。 もう 1 つは 2 層 DP ループです。ここでは安全です。$K \le 100000$ただし、一般的なソリューションでは 50 ロックの制約があるため、合計セグメント処理は小さくなります。 最適化されたバリアントでは、畳み込みまたはプレフィックス最適化が使用されます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$K = 0$。 アルゴリズムは、タイプ 1 タイルが局所的に最適である場合でも、タイプ 1 タイルからの寄与が生成されることを回避する必要があります。 「.....」のような純粋なドット セグメントでは、セグメント DP はタイプ 1 を貪欲に使用して値を割り当てます。 と$K = 0$、タイプ 2 タイルのみが残るため、DP は依然としてペアのみを使用して有効なタイルを計算し、正しい削減スコアを生成する必要があります。 

もう 1 つのケースは長さ 1 のセグメントです。ここではタイプ 2 タイルは不可能であるため、唯一の寄与は 0 または単一のタイプ 1 タイルのいずれかであり、セグメント DP は無効なペア状態にアクセスしようとしてはなりません。 

最後に、岩に隣接するトリプルは、タイプ 3 タイルにとって概念的に重要です。 点と点の構造が岩によって分割されている場合、単純なセグメンテーションでは構造間の推論が誤って禁止されてしまいます。 正しく処理すると、明示的にモデル化しない限り、インタラクションがセグメントの境界を越えることはありません。
