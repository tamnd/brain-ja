 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$ジャンクションと$N-1$それらを繋ぐ道路。 ツリーは、すべてのジャンクションのペアが 1 つのパスによって接続されていることを意味します。 この問題では、各ロボットがノードの接続されたパスを掃除し、2 台のロボットがノードを共有せず、2 台のロボットのタスクがより長いパスにマージされないように、ジャンクションのサブセットに「掃除ロボット」を割り当てる方法の数を数えるよう求められます。 

別の言い方をすると、ツリーを「既約パス」に分割したいと考えています。ここで、既約とは、2 つのパスをマージするとパス プロパティが壊れることを意味します。 出力は、有効なパーティションの合計数を法的に表したものになります。$10^9 + 7$。 

与えられた$N \le 10^5$1 秒の制限、これより悪いアプローチ$O(N \log N)$が遅すぎる可能性があります。 これにより、可能なパス分割の数が指数関数的に増加するため、すべてのサブセットの単純な列挙やすべてのパスにわたる再帰的試行が除外されます。 

ツリーがスターである場合、微妙な特殊なケースが発生します。 例えば、$N = 4$エッジ付き$1-2, 1-3, 1-4$。 ここで、中央ジャンクション 1 は単独でも、ロボットごとに 1 つのリーフと組み合わせてもかまいませんが、ロボット間でリーフを組み合わせることは禁止されています。 すべてのノードが自由にパスを形成できると想定する不注意な DP は過剰にカウントし、無効なマージされたパスが生成されます。 

もう 1 つのエッジ ケースは直線ツリーです。 ラインに沿ったすべてのノード シーケンスは有効なパスを形成しますが、既約要件により、どの連続セグメントが 1 つのパーティション内に共存できるかが厳しく制限されます。 この制限を怠ると、誤ったカウントが生成されます。 

## アプローチ

 ブルートフォース手法では、ノードのすべてのパーティションを列挙して接続されたパスに分割します。 パーティションごとに、パスが削減不可能かどうかを確認します。 これは原理的には正しいですが、実際には絶望的です。$N$- パスへのノード ツリーは組み合わせであり、簡単に超えます$2^N$。 のために$N = 10^5$、これは不可能です。 

重要な観察は、各ノードがその次数に基づいた役割を持っているということです。 ツリーでは、次数 1 のノードは葉、次数 2 のノードはチェーンを形成し、次数 3+ のノードは分岐点になります。 分岐ノードを越えて 2 つのパスをマージすると既約性に違反するため、既約プラン内のパスは複数の分岐点を通過できません。 したがって、問題はツリー上の動的プログラミングに帰着します。そこでは、各ノードについて、ノードがパスを開始するか、パスを終了するか、内部ノードであるかなど、さまざまな「アタッチメント」状態でそのサブツリーをカバーする方法の数を追跡します。 

もう 1 つの洞察は、ノードのサブツリーが 1 つのパスに結合されるか、複数のパスに分割されるかを考慮するだけでよいということです。 これにより、DP が大幅に簡素化されます。各ノードについて、そのサブツリーの有効なカバーの数は、その子のカバーの積から計算できます。 リーフ ノードはカウントに 1 を与え、内部ノードは既約性を尊重する方法で子のカウントを結合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N) | 遅すぎる |
 | ツリーDP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを任意に (たとえばノード 1 で) ルート化します。ツリーには方向性がなく、DP には親子構造が必要であるため、ルート化は安全です。 
2. 各ノードについて$u$、 定義する`dp[u]`をルートとするサブツリーをカバーする方法の数として$u$パスが既約であるように。 
3. ポストオーダートラバーサルを使用して計算します`dp[u]`。 リーフノードの場合、`dp[u] = 1`単一のノードがそれ自体で有効なパスを形成するためです。 
4. 内部ノードの場合$u$子供たちと一緒に$c_1, c_2, ..., c_k$、計算します`dp[u]`2 つのケースを考慮して:

 - ノード$u$新しい道を歩み始めます。 この場合、すべての子のサブツリーを個別にカバーする必要があります。 方法の数は次の積です。`dp[c_i]`すべての子供たちの上に。 
- ノード$u$1 つの子から既存のパスを拡張します。 同じパスにマージできる子は 1 つだけです$u$（既約性を維持するため）。 マージするために選択された子ごとに、乗算します。`dp[child]`の製品で`dp`残りの子供たちは独立して治療を受けました。 すべての選択肢を合計します。 
5.モジュロを適用する$10^9 + 7$オーバーフローを防ぐために、乗算と加算のたびに。 
6. 戻る`dp[root]`削減不可能なロボット導入の総数として。 

機能する理由: すべてのサブツリー DP は、既約制約を尊重しながら、すべての有効なパーティションを正しくカウントします。 ポストオーダートラバーサルにより、子が親より前に計算されることが保証されるため、常に有効な子の数が得られます。 マージ ロジックにより、2 つのパスが結合してより長いパスになり、問題の条件が満たされることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

MOD = 10**9 + 7

def solve():
    N = int(input())
    tree = [[] for _ in range(N)]
    for _ in range(N-1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        tree[u].append(v)
        tree[v].append(u)
    
    dp = [0] * N
    
    def dfs(u, parent):
        res = 1
        child_dp = []
        for v in tree[u]:
            if v == parent:
                continue
            dfs(v, u)
            child_dp.append(dp[v])
            res = res * dp[v] % MOD
        
        # res is case when u starts a new path
        total = res
        
        # case when u extends path from one child
        for vdp in child_dp:
            extend = vdp
            for wdp in child_dp:
                if wdp != vdp:
                    extend = extend * dp[child_dp.index(wdp)] % MOD
            total = (total + extend) % MOD
        
        dp[u] = total
    
    dfs(0, -1)
    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```DFS は、各サブツリーが 1 回だけ処理されることを保証します。 独立したパスを考慮して、子の DP カウントの積を計算します。 次に、子ごとに、そのパスを現在のノードとマージすることを検討します。 残りの子を個別に乗算すると、既約性が強制されます。 モジュロは、大きな数値を処理するために一貫して適用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各ノードは 1 回アクセスされ、子の積は O(子の数) で処理され、ツリー全体で合計 O(N) になります。 |
 | スペース | O(N) | ツリー隣接リストと DP 配列には線形空間が必要です。 |
