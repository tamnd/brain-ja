 ## 問題の理解

 私たちは、従業員が一定の業績値によってランク付けされる企業において、毎年行われる一連の「剪定」作業の後、単一の従業員、ランドールが雇用され続けるかどうかを追跡しています。 会社は常に正確に保ちます$N$従業員。 毎年、それは削除されます$R_i$現在の最も弱い従業員を次の従業員に置き換えます。$R_i$その年の業績値が与えられた新入社員。 

重要な点は、既存の従業員のパフォーマンス値が決して変わらないこと、および最初の従業員、すべての置き換え、およびすべての更新のすべての値がグローバルに異なることです。 これにより、タイブレークの懸念がなくなり、すべての比較が厳密になります。 

このプロセスは順番に適用されます。$M$その後は、ランダル (最初は従業員 1) がすべての排除から生き残ったかどうかだけを気にします。 各シナリオ クエリの後、1 年の置換リスト内の 1 つの値が変更され、全体の値が変更されます。$M$-year プロセスは、その変更を将来のクエリに永続的に適用して再検討する必要があります。 

単純な解釈では、クエリごとにシミュレーション全体を再計算する必要があると考えられますが、制約を考慮するとそれは不可能です。 と$N, M, Q \le 10^5$挿入された値の合計は次のとおりです$10^6$、何年も繰り返しシミュレーションするアプローチでは、おおよその結果が得られます。$O(Q \cdot M \log N)$、これは実現可能な限界をはるかに超えています。 

更新がクエリ間で持続するという事実から、微妙なエッジ ケースが発生します。 クエリが独立していると誤って仮定すると、毎回最初から再計算し、クエリ間の相互作用を見逃すことになります。 もう 1 つのエッジケースは、ランダルが早い段階ですでに弱っている場合です。 単純な方法では、たとえ彼が排除されることが保証された後でも、何年もシミュレーションを続ける可能性があり、正確さを変えることなく時間を無駄にします。 

ブルートフォースの具体的な失敗を確認するには、次のことを考慮してください。$N=5, M=3$, ここで、ランダルは当初トップランクにかろうじて入っています。 1 つのクエリがプロセスの早い段階で置換値を増やすと、後になって除去しきい値が完全に変更される可能性があります。つまり、部分的な再計算は慎重に構造化されていない限り有効ではありません。 

したがって、問題はシステムを繰り返しシミュレーションすることではなく、ランダルの生存が年月を経て伝播される特定のしきい値にのみどのように依存するかを理解することです。

class SegTree:
    def __init__(self, data):
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [ [] for _ in range(2 * self.size) ]

        for i in range(self.n):
            self.tree[self.size + i] = sorted(data[i])

        for i in range(self.size - 1, 0, -1):
            self.tree[i] = sorted(self.tree[2 * i] + self.tree[2 * i + 1])

    def update(self, idx, old, new):
        i = idx + self.size
        arr = self.tree[i]
        arr.remove(old)
        arr.append(new)
        arr.sort()

            self.tree[i].append(new)
            self.tree[i].sort()
            i //= 2
