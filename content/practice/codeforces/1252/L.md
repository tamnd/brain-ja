 ## 解決策
 ## 問題の理解

 各都市が候補となる道路を 1 つだけ提案している一連の都市が与えられています。 市$i$特定の他の都市に接続したい$A_i$、したがって、各提案は無向エッジです$(i, A_i)$。 労働者に関するすべての制約を無視した場合、これらの提案されたエッジはすでに接続されたグラフを形成しているため、すべての提案を使用して任意の 2 つの都市間を移動する方法が少なくとも 1 つ存在します。 

提案された各エッジは自由に構築可能ではありません。 にリストされている特定の許可された材料を使用してのみ構築できます。$B_i$。 一方、各労働者は非常に専門的であり、道路の材料が自分の材料と正確に一致する場合にのみ道路を建設できます。$C_j$、各労働者は最大でも 1 つの道路を建設できます。 労働者は何もしないこともあります。 

タスクは、選択されたエッジによって形成されるグラフがすべての都市にわたって接続されたままになるように、マテリアルの互換性と一意性の制約を考慮して、提案されたエッジのいくつかに作業者を割り当てることです。 エッジをスキップしたり、ワーカーを未使用のままにすることはできますが、最後に選択したエッジはすべての都市を接続する必要があります。 

中心的な問題は、エッジを最大化したり、すべてのワーカーを使用したりする必要がないことです。 エッジのサブセットを選択し、接続を維持する方法でワーカーをそれらに割り当てる必要があります。 

制約はソリューションを強力に形作ります。 と$N, K \le 2000$そして合計$\sum M_i \le 10000$、私たちは次のような体制にいます。$O(NK)$または$O(M \log N)$タイプのソリューションは許容されますが、都市上での立方体に近いものや繰り返しのフロー構築は遅すぎます。 すべてのマテリアル リストの合計サイズがまばらであることから、大きな配列を繰り返しスキャンするのではなく、エッジとマテリアルの関係を明示的に扱う必要があることがわかります。 

微妙な問題は、選択したエッジのみを使用して接続を維持する必要があることです。 単純なアプローチでは、利用可能なワーカーを任意のエッジに貪欲に割り当てる可能性がありますが、これによりグラフが簡単に切断されてしまう可能性があります。 もう 1 つの失敗モードは、すべての提案がつながっているにもかかわらず、グラフの 1 つの領域から多くのエッジを選択し、別の領域を分離したままにすることです。 

隠れた構造は、提案によって形成されたグラフがまさに$N$ノードと$N$各ノードが正確に 1 つのエッジを提案するためです。 これは、構造がコンポーネントごとに正確に 1 サイクルを持つ接続された擬似フォレストであることを意味しますが、グラフは全体的に接続されているため、構造推論コンテキスト全体に正確に 1 つのサイクルが含まれます。 これは非常に重要です。選択するだけで済みます。$N-1$接続を維持するためのエッジと、ワーカーを使用して実現できれば提案グラフのスパニング ツリーで十分です。 

## アプローチ

 強引なアイデアは、提案された各エッジを候補として扱い、スパニング ツリーを形成するサブセットの選択を試みると同時に、各エッジで許可されているマテリアルに一致するワーカーを割り当てることです。 サイズのエッジのすべてのサブセットを試してみることもできます$N-1$、スパニング ツリーを形成しているかどうかを確認し、ワーカーが一致するかどうかを確認します。 エッジサブセットの数は指数関数的であるため、これはすぐに実行不可能になります。$N$、割り当ての実現可能性を確認する場合でも、2 部マッチング問題を繰り返し解く必要があります。 

より構造化されたアプローチは、事前にスパニング ツリーを選択する必要がないことを確認することです。 代わりに、ワーカーを同時に割り当てながらスパニング ツリーを構築することを考えることができます。 含めることを決定した各エッジは、互換性のある材料の利用可能なワーカーによってサポートされている必要があり、各ワーカーは 1 回しか使用できません。 これはエッジとワーカー間のマッチングの問題になりますが、選択されたエッジが接続された構造を形成する必要があるという追加の制約が伴います。 

重要な洞察は、Disjoint Set Union (DSU) を使用して接続を維持しながらエッジを処理することです。 プロポーザル グラフ上にスパニング ツリーを構築しようとしますが、ワーカーを割り当てることができるエッジのみをアクティブにします。 各エッジについて、マテリアルがエッジの許可セットに含まれる未使用のワーカーが存在するかどうかを知る必要があります。 合計以来$M_i$が小さい場合は、エッジをマテリアルごとに、ワーカーをマテリアルごとに事前にインデックス付けできます。 

次に、コンポーネントの接続を貪欲に試みます。エッジが 2 つの異なる DSU コンポーネントを接続し、利用可能なワーカーがある場合は常に、それを使用します。 これはクラスカルのアルゴリズムを彷彿とさせますが、重みがなく、実現可能性は材料ごとの労働者の利用可能性に依存します。 正確かどうかは、どのスパニング ツリーでも十分であるという事実に依存しているため、必要なのは 1 つのスパニング ツリーを実現できることを確認することだけです。 

微妙な点は、物質的な制約が単純な貪欲な選択を妨げる可能性があるということです。 正しい戦略は、エッジを任意の順序で処理しますが、可能であれば常にエッジを使用してコンポーネントをマージし、有効なマテリアルの未使用のワーカーを慎重に割り当てることです。

 | 最適 (DSU + 貪欲な割り当て) | O((N + M) log K) | O(N + K + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 ワーカーにコミットしながらエッジにワーカーを割り当てながら、都市のグラフ上にスパニング ツリーを段階的に構築することで、ソリューションを構築します。 

1. 各都市を独自のコンポーネントに含めて DSU 構造を初期化します。 これは、選択した道路によってどの都市がすでに接続されているかを表します。 
2. 従業員を材料ごとにグループ化する$C_j$、マテリアルごとにマルチセットまたはキューを保存します。 これにより、特定のマテリアルを構築できる未使用のワーカーを迅速に取得できます。 
3. 各エッジについて$i$、エンドポイントのペアを保存します$(i, A_i)$およびその許可された材料リスト$B_i$。 「素材ごとに使用可能なワーカー」の隣接性も用意しています。 
4. エッジを任意の順序で処理し、各エッジを使用して 2 つの異なる DSU コンポーネントを接続しようとします。 エンドポイントがすでに接続されている場合は、サイクルが発生し、接続には不要であるため、スキップします。 
5. エッジについて$(u, v)$、私たちはあらゆる資料を見つけようとします$B_i$未使用のワーカーがまだ残っています。 存在しない場合は、このエッジを使用できないため、次に進みます。 
6. そのようなマテリアルが存在する場合、そのマテリアルのワーカーを 1 つ選択し、このワーカーをエッジの構築に割り当てます。$(u, v)$、ワーカーを使用済みとしてマークします。 
7. DSU コンポーネントを結合します。$u$そして$v$。 これは、建設された道路が 2 つの地域を接続していることを反映しています。 
8. すべての都市が 1 つの接続されたコンポーネント内に収まるか、すべてのエッジが処理されるまで続行します。 

処理後、DSU に単一の接続コンポーネントが表示されない場合、またはすべてのノードを接続するのに十分なエッジを割り当てなかった場合は、-1 を出力します。 それ以外の場合は、ワーカーごとに割り当てられたエッジを出力し、未使用のワーカーは「0 0」を生成します。 

なぜそれが機能するのかは、接続の構造に由来します。 以前に切断された 2 つのコンポーネントを接続するエッジのみを追加するため、サイクルは必要ありません。 元のグラフは接続されているため、提案エッジから構成されるスパニング ツリーが常に存在します。 唯一の問題は、それらのエッジに労働者を割り当てることができるかどうかです。 各エッジには 1 ユニットのリソース (有効なマテリアルのワーカー) のみが必要であり、エッジをコミットするときにワーカーを消費するだけであるため、プロセスはローカルの容量制約の下で実行可能なスパニング ツリーを選択することになります。 貪欲な DSU 構造により、有用なエッジをスキップすると、ワーカーの可用性の観点から実現可能性が低い可能性のある後のエッジを使用せざるを得なくなるため、以前にコンポーネントの接続に使用できたであろうエッジを無駄にすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

def solve():
    N, K = map(int, input().split())
    edges = []
    for i in range(N):
        arr = list(map(int, input().split()))
        a = arr[0] - 1
        m = arr[1]
        B = arr[2:]
        edges.append((i, a, B))

    workers = list(map(int, input().split()))

    mat_to_workers = {}
    for idx, c in enumerate(workers):
        mat_to_workers.setdefault(c, []).append(idx)

    ans = [(-1, -1)] * K

    dsu = DSU(N)

    for u, v, B in edges:
        if dsu.find(u) == dsu.find(v):
            continue

        chosen_worker = -1
        chosen_mat = -1

        for c in B:
            if c in mat_to_workers and mat_to_workers[c]:
                chosen_worker = mat_to_workers[c].pop()
                chosen_mat = c
                break

        if chosen_worker == -1:
            continue

        dsu.union(u, v)
        ans[chosen_worker] = (u + 1, v + 1)

    root = dsu.find(0)
    if any(dsu.find(i) != root for i in range(N)):
        print(-1)
        return

    for u, v in ans:
        if u == -1:
            print("0 0")
        else:
            print(u, v)

if __name__ == "__main__":
    solve()
```DSU は、接続に寄与するエッジのみを確実に受け入れるために使用されます。 ワーカー プールはマテリアルごとにインデックス付けされるため、エッジの実現可能性のチェックはその小さな許可リストのスキャンに減ります。$B_i$。 エッジを受け入れるたびに、すぐにワーカーを消費してコンポーネントをマージし、有効な部分フォレストを確実に維持します。 

微妙な実装の詳細は、エッジを受け入れるとすぐにワーカーを割り当てることです。 割り当てが遅れると、後でバックトラッキングまたは照合する必要があり、正確さが大幅に複雑になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフ構造により接続が可能であるものの、マテリアルの分布が重要なブリッジ エッジをブロックする場合です。 そのような状況では、DSU ベースの貪欲なアプローチはエッジを順番に試行します。ブリッジ エッジが遅れて表示され、必要なマテリアルがすでに消費されている場合はスキップされ、コンポーネントが切断されたままになります。 これは、実現可能性が純粋に構造的なものではなく、リソースにも制約があるという事実を反映しています。 

もう 1 つのケースは、多くのエッジがすでに接続されているコンポーネントを接続する場合です。 DSU チェックはこれらが無視されることを保証し、重要な接続の可用性を低下させる不必要なサイクルでのワーカーの無駄を防ぎます。
