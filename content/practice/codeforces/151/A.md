 ## 解決策
 ## 問題の理解

 友人のグループが、ソフトドリンク、ライムスライス、塩という 3 つのリソースを使って同じトーストを作りたいと考えています。 すべてのトーストは、固定量の各リソースを消費します。 タスクは、少なくとも 1 つのリソースがなくなる前に、各友人が何回完全なトーストを行うことができるかを決定することです。 

入力により、友人の数、ドリンクボトルの数とサイズ、ライムとライムごとのスライスの数、塩の量、および 1 回のトーストに必要な各材料の量が得られます。 これらの値から、各リソースから個別に生成できるトーストの合計数を計算し、制限リソースを決定する必要があります。 

制約は小さく、すべての値は最大 1000 です。非効率なソリューションであっても、制限内であれば快適に実行できます。 高度なアルゴリズム、データ構造、最適化のコツは必要ありません。 課題は、単に文言を正しい算術に変換することです。 

最も一般的な間違いは、最終的な答えが何を表しているのかを誤解することです。 トーストの合計回数は尋ねられません。 各友達が平等に乾杯できる回数を尋ねられます。 

次の入力を考えてみましょう。```
3 1 3 1 1 100 3 1
```飲み物のみ許可されています`1 * 3 / 3 = 1`合計乾杯。 不用意な解決策は印刷される可能性があります`1`, ただし、これはグループ全体の乾杯の合計数です。 友達は3人なので、それぞれ友達を作ることができます`1 / 3 = 0`乾杯。 正しい出力は次のとおりです。```
0
```もう 1 つの微妙なケースは、1 つのリソースが他のリソースよりもはるかに小さい場合です。```
5 100 100 1 1 1 1 1
```ドリンクとライムは豊富ですが、塩はトースト1枚分しかありません。 友達5人で分けるともらえる`0`。 すべてのリソースにわたって最小値を取ることを忘れたソリューションは、ここで失敗します。 

整数の除算も必須です。 乾杯は完了する必要があります。 端数のトーストは許可されません。```
2 1 5 1 1 100 6 1
```飲み物は5ミリリットルしかなく、トースト1枚につき6ミリリットル必要です。 ドリンクベースの乾杯の正しい回数は次のとおりです。`0`、 ない`0.833...`。 

## アプローチ

 ブルートフォースアプローチでは、一度に 1 人ずつ乾杯することをシミュレートします。 各ステップでは、リソースが不足するまで、必要な飲み物、ライム 1 スライス、および必要な塩が差し引かれます。 最後に、成功した乾杯の数を友達の数で割ります。 

これが機能するのは、トーストごとに固定量のリソースが消費されるためです。 シミュレーションは推論が容易で、常に正確です。 最悪の場合でも、トーストできる回数は制限時間内に十分収まる程度に少ないです。 

それでもシミュレーションは不要です。 問題の構造により、直接的な数学的ショートカットが得られます。 

各リソースは、合計トーストの最大数を個別に決定します。 

この飲み物は以下を提供します：```
(k * l) / nl
```合計乾杯。 

ライムは次のような効果をもたらします。```
(c * d)
```各トーストには正確に 1 つのスライスが必要なので、トーストの合計が必要になります。 

塩は以下を提供します。```
p / np
```合計乾杯。 

最初にリソースが枯渇すると生産が停止するため、実際の合計トースト数はこれら 3 つの値の最小値になります。 すべての友人は同じ数のトーストを受信する必要があるため、合計を均等に分割します。`n`友達。 

これにより、問題は少数の算術演算と整数の除算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T) | お(1) | 承認済み |
 | 最適 | お(1) | お(1) | 承認済み |

 ここ、`T`シミュレートされたトーストの数です。 

## アルゴリズムのチュートリアル

 1. 入力から 8 つの整数を読み取ります。 
2. 利用可能な飲み物の総量を計算します。```
total_drink = k * l
```これは、ボトルの数を合計ミリリットルに変換します。 

1. ドリンクがサポートできるトーストの合計数を計算します。```
drink_toasts = total_drink // nl
```部分的なトーストは無効であるため、整数の除算が必要です。 

1. ライムスライスの合計数を計算します。```
lime_toasts = c * d
```各トーストはちょうど 1 つのスライスを消費するため、この値はすでにライムから可能なトーストの数と等しくなります。 

1. ソルトがサポートできるトーストの合計数を計算します。```
salt_toasts = p // np
```ここでも、整数除算によって不完全なトーストが削除されます。 

1. 3 つのトースト数の中から最小のものを見つけます。```
total_toasts = min(drink_toasts, lime_toasts, salt_toasts)
```制限リソースにより、合計トーストの最大可能数が決まります。 

1. すべての友達に平等に分けます。```
answer = total_toasts // n
```1. 結果を印刷します。 

### なぜ効果があるのか

 トーストごとに、一定量のドリンク、ライム、塩が消費されます。 つまり、各リソースがトーストの総数に個別に上限を課すことになります。 これらの境界の 1 つを超えようとすると、存在するリソースよりも多くのリソースが必要になります。 

3 つの境界の最小値を取ると、合計トーストの実現可能な最大数が得られます。 友達の数で割ると、友達ごとの最大同数のトーストが得られます。 すべての計算では整数の除算が使用されるため、アルゴリズムは不完全なトーストをカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k, l, c, d, p, nl, np = map(int, input().split())

drink_toasts = (k * l) // nl
lime_toasts = c * d
salt_toasts = p // np

total_toasts = min(drink_toasts, lime_toasts, salt_toasts)

print(total_toasts // n)
```最初の行は、1 つのステートメント内の 8 つの整数すべてを読み取ります。 この問題にはテスト ケースが 1 つしかないため、ループはありません。 

飲み物の計算では、ボトルの数にボトルあたりのミリリットルを乗じてから、トーストごとに必要な量で割ります。 この順序を逆にすると、整数の除算では情報が失われるのが早すぎるため、正しくありません。 

各トーストにはちょうど 1 つのスライスが必要なので、ライムの計算はより簡単です。 分割は必要ありません。 

塩の計算では飲み物の計算と同じ理由で整数の除算が使用され、不完全なトーストは許可されません。 

の`min`電話をかけることが重要なステップです。 2 つのリソースが多くのトーストをサポートできる場合でも、最小のリソースがボトルネックになります。 

最後に、再度整数除算を使用して、答えをすべての友達に均等に分配します。 これにより、人に端数のトーストを割り当てることがなくなります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, k, l, c, d, p, nl, np = map(int, input().split())

    drink_toasts = (k * l) // nl
    lime_toasts = c * d
    salt_toasts = p // np

    total_toasts = min(drink_toasts, lime_toasts, salt_toasts)

    print(total_toasts // n)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 4 5 10 8 100 3 1\n") == "2\n", "sample 1"

# minimum values
assert run("1 1 1 1 1 1 1 1\n") == "1\n", "minimum case"

# not enough drink for one toast per friend
assert run("3 1 3 1 1 100 3 1\n") == "0\n", "group division case"

# salt is the bottleneck
assert run("5 100 100 100 100 4 1 2\n") == "0\n", "salt bottleneck"

# maximum values
assert run("1000 1000 1000 1000 1000 1000 1 1\n") == "1000\n", "maximum values"

print("All tests passed.")
