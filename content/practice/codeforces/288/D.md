 ## 解決策
 ## 問題の理解

 _n_ 個のノードを含むツリーが与えられます。各ノードには 1 から _n_ までの番号が付けられ、それらを接続する _n_-1 個のエッジがあります。 Polo は、ノードを共有しないノード間のパスのペアをカウントしたいと考えています。 具体的には、各パスは 2 つのノード _a_ と _b_ によって定義され、ツリーのエッジに沿った最短パスが決定されます。 _a_ から _b_ へのパスと _c_ から _d_ へのパスが交差しないように、すべての 4 つ組 (_a_、_b_、_c_、_d_) をカウントする必要があります。 

制約は重要です。 _n_ は 80,000 に達する可能性があるため、O(_n_ log _n_) よりも複雑なソリューションはほぼ確実にタイムアウトになります。 すべてのパスのペアを列挙する素朴なアプローチは最悪の場合 O(_n_^4) となり、これは実行不可能です。 すべてのパスに関する情報を明示的に保存するには O(_n_^2) スペースが必要であり、これは許容できないため、メモリ使用量も考慮する必要があります。 

微妙なエッジ ケースには、パス ペアが存在しない _n_ = 1 のような非常に小さなツリーや、パスが重なり合う傾向がある完全に線形のツリーが含まれます。 考慮すべきもう 1 つの状況は、1 つの中心ノードが他のすべてのノードに接続する星型ツリーです。 5 つのノードを持つスターでは、ほぼすべてのパスが中心で交差するため、互いに素なパス ペアの数は、すべての 4 つの単純な合計よりもはるかに小さくなります。 

## アプローチ

 ブルートフォース手法では、各ペア (_a_、_b_) を選択してすべてのパスを生成し、その後、他のすべてのペア (_c_、_d_) について、ツリーに沿って歩いて交差するかどうかを確認します。 これには O(_n_^4) 回の操作が必要ですが、_n_ = 80,000 の場合は実現可能をはるかに超えています。 LCA クエリを使用してパスを事前計算する最適化でも、クエリごとの時間が O(log _n_) に短縮されますが、全体では O(_n_^2 log _n_) のままで、依然として遅すぎます。 

より高速なソリューションに対する重要な洞察は、互いに素なパス ペアの数が組み合わせで計算できることを観察することで得られます。 木の端を考えてみましょう。 そのエッジを削除すると、ツリーが 2 つの接続されたコンポーネントに分割されます。 1 つのコンポーネント内に完全にあるパスは、他のコンポーネント内に完全にあるパスと交差することはできません。 これにより、すべての 4 つ組を列挙するのではなく、エッジ カットによってパスを数えることができるという観察が得られます。 

エッジの 2 つのコンポーネントのサイズを _x_ と _y_ とします。 1 つのコンポーネント内のパスの数はchoose(_x_, 2)とchoose(_y_, 2)です。 異なるコンポーネントからのノードのみを使用するすべての素なパス ペアは、これらの数を正確な式で結合します。 すべてのエッジを慎重に合計し、組み合わせカウントのプロパティを使用することで、O(_n_) で素のパス ペアの総数を効率的に導き出すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | 組み合わせエッジ分割 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリー入力を読み取り、隣接リスト表現を構築します。 DFS トラバーサルのために近隣への高速アクセスが必要になります。 
2. DFS を使用して、すべてのノードの各サブツリーのサイズを計算します。 任意のルート (通常はノード 1) から開始します。ノード _u_ の場合、そのサブツリー サイズは 1 にそのすべての子のサブツリー サイズの合計を加えたものになります。 これらのサイズにより、エッジがツリーをどのように分割するかを計算できます。 
3. すべてのエッジ (_u_、_v_) を反復処理します。 _v_ が _u_ の子であると仮定します。 エッジを削除すると、ツリーが一定のサイズのコンポーネントに分割されます。`subtree[v]`そして残りのサイズ`n - subtree[v]`。 
4. 各コンポーネントに完全に含まれるパスの数を数えます。子コンポーネントの場合はchoose(subtree[v], 2)、もう一方のコンポーネントの場合はchoose(n - subtree[v], 2)です。 これらのカウントの積により、このエッジによって分離された互いに素なパスのペアの数が求められます。 すべてのエッジにわたるこの寄与を合計します。 
5. 総和を出力します。 これにより、互いに素なパスのペアの総数が得られます。 

機能する理由: 切り離されたパスのすべてのペアは、エッジ カットによって作成された完全に別個のコンポーネント内に存在するか、少なくとも 1 つのエッジを共有する必要があります。 エッジ全体のすべての組み合わせをカウントすることで、有効な各ペアが 1 回だけカウントされます。 DFS サブツリーの計算により、各コンポーネントの正確なサイズが効率的に分かることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def main():
    n = int(input())
    edges = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        edges[u - 1].append(v - 1)
        edges[v - 1].append(u - 1)
    
    size = [0] * n

    def dfs(u, parent):
        sz = 1
        for v in edges[u]:
            if v != parent:
                sz += dfs(v, u)
        size[u] = sz
        return sz

    dfs(0, -1)

    result = 0
    for u in range(n):
        for v in edges[u]:
            if size[v] < size[u]:
                a = size[v]
                b = n - a
                result += a * (a - 1) // 2 * b * (b - 1) // 2
    print(result)

if __name__ == "__main__":
    main()
```DFS は各サブツリーのサイズを正確に計算します。 エッジの反復中は、二重カウントを避けるために、親から子へのエッジのみが考慮されます。 組み合わせ公式はchoose(a, 2)とchoose(b, 2)を乗算して、エッジを横切る素なパスのペアを取得します。 整数除算により、浮動小数点エラーのない正確さが保証されます。

## 特殊なケース

 単一ノード ツリーにはパスがないため、DFS はサイズ = 1 を設定し、エッジ ループは実行されません。 予想どおり、出力は 0 です。 スター ツリーでは、すべてのパスが中心ノードを共有します。 サブツリーのサイズは [n,1,1,...] であるため、各リーフに対してchoose(a,2) = 0となり、寄与はゼロになります。 線形ツリーは、パスをほぼ均等な半分に分割する中間エッジからのみ寄与を生成します。 アルゴリズムはオフバイワンの問題を正しく処理します。`size[v] < size[u]`子エッジを識別します。
