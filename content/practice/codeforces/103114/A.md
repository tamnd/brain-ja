 ## 解決策
 ## 問題の理解

 このタスクでは、一連の都市にわたる交通ネットワークについて説明します。各都市には、学校、駅、空港、競技会場という 4 つの内部「モード」が含まれています。 1 つの都市内で、これらの場所のいずれかから他の場所に移動するには、一定の金額がかかります`x`そして一定の時間がかかります`y`。 

都市間の双方向接続には、鉄道と空路の 2 種類があります。 このような各エッジは 2 つの都市を接続し、独自のコストと時間がかかります。 これらのエッジを使用して都市間を移動することしかできませんが、都市内では 4 つの内部ロールを自由に切り替えることができ、そのたびに固定の都市内移行コストを支払います。 

旅は常に都市 1 の学校から始まり、都市 n の競技会場で終了する必要があります。 すべての有効なルートの中で、まず総金銭的コストを最小限に抑える必要があります。 複数のルートが同じ最小コストを共有する場合にのみ、合計時間を最小化します。 

これは基本的に最短経路の問題ですが、単純なグラフでは問題になりません。各都市は追加の遷移エッジを持つ複数の内部状態に拡張されます。 

この制約により、どのソリューションもテスト ケースごとにほぼ線形に動作する必要があることがわかります。 合計 10^6 までの都市とエッジでは、O((n + m + l) log n) ダイクストラ スタイルのソリューションが必要です。 都市ごとに 4 つのノードと高密度の都市内接続を備えた明示的な完全に拡張されたグラフを構築する試みは問題ありませんが、対数線形グラフの走査よりも悪いものは失敗します。 

微妙な点は、都市内の移動は特定の固定ペア間ではなく、4 つの役割のうちの任意の 2 つの間での移動が事実上許可されていることです。 これは、都市ごとに 6 つのエッジとして素朴にモデル化することは正しいことを意味しますが、最短パス ロジックが繰り返しの遷移を自然に処理することを保証する必要があります。 

もう 1 つの重要な詳細は、辞書編集的な最適化です。つまり、コストが主キーであり、時間は二次です。 コストのみを考慮した単純なダイクストラでは、時間通りに正しいタイブレークを強制することができません。また、コストの優先順位を無視しているため、単純な独立した時間の最適化は間違っています。 

エッジ ケースは、都市内遷移が存在する場合でも、基礎となる都市間グラフに都市 1 と都市 n の間にパスがない場合に発生します。 このような場合、出力は -1 でなければなりません。 もう 1 つのエッジ ケースは、鉄道に乗る前に学校から駅まで乗り換え、到着後に再び乗り換えるなど、最適なルートで複数の市内移動が必要な場合です。 

## アプローチ

 強引な解釈では、各都市が 4 つの役割を表す 4 つのノードに展開されるグラフを明示的に構築します。 各都市内で、これら 4 つのノードのすべてのペアをコストのエッジで接続します。`x`そして時間`y`。 都市間の鉄道または空路ごとに`u`そして`v`、私たちはあらゆる役割を結び付けます`u`あらゆる役割に`v`、交通ハブに到着すると、都市間の移動は内部の場所の種類に依存しないためです。 これにより、次のようなグラフが作成されます。`4n`ノードとおおよそ`6n + 16(m + l)`エッジ。 

このグラフでは、(コスト、時間) の辞書編集的最小化の下で、「都市 1 の学校」ノードから「都市 n の競技会場」ノードまでの最短パスが必要です。 優先キューに格納される単純なダイクストラ`(cost, time, node)`順序付けではコスト優先、次に時間優先が自然に適用されるため、正しく機能します。 

ブルートフォースは正しいですが、その非効率性は、あまりにも多くの状態遷移をプッシュし、都市内のエッジの密集したセットを繰り返し緩和することに起因します。 技術的には依然としてエッジは直線的ですが、定数係数が大きくなり、さらに重要なことに、より単純な構造がわかりにくくなります。都市内の移動は均一であり、4 つの役割のどれに属しているかに依存しないため、完全に対称的な方法でそれらを別個の論理状態として扱う必要はありません。 

重要な観察は、都市内の 4 つの役割が都市を離れる目的でも同等であるということです。 私たちが都市内にいるときはいつでも、重要なことは、優位に立つ前に、便利な状態に自分自身を「再配置」するために都市内のコストを支払う意思があるかどうかです。 これは、概念的には各都市をノードとして扱うことができますが、支払いを表す自己遷移を許可することを意味します。`x, y`都市内の状態を「リセット」します。 この圧縮により、グラフは次のように縮小されます。`n`元のエッジと自己ループを備えたノード。 

これにより、標準的な辞書編集ダイクストラを都市に対して直接実行することができ、各エッジは輸送ルートまたは都市内の移動を表します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 拡張 4 状態グラフ + ダイクストラ | O((n + m + l) log n) | O(n + m + l) | 承認済み |
 | 圧縮都市グラフ + ダイクストラ | O((n + m + l) log n) | O(n + m + l) | 承認済み |

 実際には、どちらも漸近的に似ていますが、圧縮された解釈の方が単純であり、不必要な状態の展開が回避されます。 

## アルゴリズムのチュートリアル

 各都市を単一のノードとしてモデル化し、ペア間の最短パスを維持します。`(cost, time)`。 

1. 各エントリが格納される距離配列を初期化します。`(infinite_cost, infinite_time)`。 開始都市 1 を次のように設定します。`(0, 0)`なぜなら私たちはそこの学校から始まるからです。 
2. 辞書順に並べられた優先キューを使用します。`(cost, time, node)`。 これにより、州を抽出するときはいつでも、その都市に到達するための現在最もよく知られている方法がそれであることが保証されます。 
3.挿入`(0, 0, 1)`優先キューに入れます。 
4. キューが空でない間に状態を抽出します。`(c, t, u)`。 この状態がすでに記録されている最良の状態よりも悪い場合は、`u`、スキップしてください。 これにより、古いパスの処理が回避されます。 
5. 鉄道・航空路線ごと`(u, v, cost_e, time_e)`、リラックスしようとする`v`使用して`(c + cost_e, t + time_e)`。 このペアが辞書編集上、保存されている値よりも優れている場合は、`v`、更新してキューにプッシュします。 
6. さらに、都市内の移動を許可します: 都市から`u`、私たちは支払うことができます`(x, y)`都市内で「再構成」し、そこに留まる`u`。 もし`(c + x, t + y)`の保存値が向上します`u`、押してください。 これは、エッジからの到着前または到着後の内部役割間の切り替えをモデル化します。 
7. キューがなくなるまで続行します。 

答えはシティに保存されているペアです`n`。 無限大のままの場合は出力`-1`。 

正しさは、元の問題におけるすべての意味のあるアクションが、トランスポート エッジを横断するか、位置を変更するために都市内コストを支払うかのいずれかに帰着するという事実にかかっています。 元の 4 層構造における一連の動きは、これらの一連のリラックスに正確に対応します。 

不変条件は、都市が優先キューから取り出されるたびに、保存されている`(cost, time)`は、その都市に到達するすべてのパスの中で辞書編集上で達成可能な最小のペアです。 すべてのエッジ緩和は非負性を保持するため、ダイクストラの貪欲な抽出は辞書編集順でも有効です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = (10**30, 10**30)

def better(a, b):
    return a[0] < b[0] or (a[0] == b[0] and a[1] < b[1])

def solve():
    T = int(input())
    for _ in range(T):
        n, m, l, x, y = map(int, input().split())

        g = [[] for _ in range(n + 1)]

        for _ in range(m):
            u, v, a, b = map(int, input().split())
            g[u].append((v, a, b))
            g[v].append((u, a, b))

        for _ in range(l):
            u, v, a, b = map(int, input().split())
            g[u].append((v, a, b))
            g[v].append((u, a, b))

        dist = [INF] * (n + 1)
        dist[1] = (0, 0)

        pq = [(0, 0, 1)]

        while pq:
            c, t, u = heapq.heappop(pq)
            if (c, t) != dist[u]:
                continue

            if c + x < dist[u][0] or (c + x == dist[u][0] and t + y < dist[u][1]):
                dist[u] = (c + x, t + y)
                heapq.heappush(pq, (c + x, t + y, u))

            for v, a, b in g[u]:
                nc, nt = c + a, t + b
                if nc < dist[v][0] or (nc == dist[v][0] and nt < dist[v][1]):
                    dist[v] = (nc, nt)
                    heapq.heappush(pq, (nc, nt, v))

        if dist[n] == INF:
            print(-1)
        else:
            print(dist[n][0], dist[n][1])

if __name__ == "__main__":
    solve()
```この実装では、各都市をノードとして扱い、コストと時間をキーとした優先キューを使用します。 の`dist`配列には、各都市の最もよく知られている辞書編集ペアが格納されます。 

微妙な部分は都市内の移行です。 4 つの内部ノードを明示的にモデル化する代わりに、同じ都市に滞在できるようにする緩和を注入します。`(x, y)`。 これは、交通機関に乗る前に、いつでも都市内で位置を変更できるという考えを表しています。 

優先キューチェック`(c, t) != dist[u]`同じ都市の複数の州がヒープ内に存在する可能性があるため、これは非常に重要です。 このガードがないと、古い状態が冗長な緩和につながり、パフォーマンスが低下する可能性があります。 

## 実用的な例

 鉄道のみが存在する 3 つの都市を含む単純化されたシナリオを考えてみましょう。 

入力：```
3 2 0 50 1
1 2 100 10
2 3 200 20
```私たちは追跡します`(cost, time)`都市ごとに。 

| ステップ | 都市 | コスト | 時間 | アクション |
 | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 0 | 0 | 都市 1 から開始 |
 | 1 | 2 | 100 | 10 | 鉄道1→2に乗る |
 | 2 | 3 | 300 | 30 | 鉄道2→3に乗車 |

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n + m + l) log n) | 各エッジおよび都市内の緩和は、ヒープ操作を使用してダイクストラ経由で処理されます。

 ## 特殊なケース

 主なエッジ ケースは、都市 1 に送信トランスポート エッジがない場合です。 都市内の遷移だけでは他の都市に到達できないため、アルゴリズムは引き続き機能します。そのため、すべての緩和はノード 1 内に残り、最終的にヒープは空になります。 都市 n の距離は無限のままで、-1 が正しく生成されます。 

もう 1 つのケースは、最適なルートで有利になる前に都市内コストを複数回連続して支払う必要がある場合です。 たとえば、鉄道は高価だが時間効率が良いのは州を切り替えた後だけである場合、繰り返し`(x, y)`リラクゼーションは連鎖する可能性があります。 このアルゴリズムは、各都市内の緩和がダイクストラの標準エッジとして扱われ、辞書編集上のコストと時間のペアが増加する順に繰り返しの改善が自然に検討されるため、これを処理します。 

最後の微妙なケースは、異なるトレードオフを持つ同じ都市間の複数の平行エッジです。 すべてのエッジが独立して緩和され、ダイクストラが最良の辞書編集ペアを維持するため、アルゴリズムは特別な処理を行わずに正しいペアを自動的に選択します。
