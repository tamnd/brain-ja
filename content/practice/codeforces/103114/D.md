 ## 解決策
 ## 問題の理解

 平面上に一連の点が与えられ、それぞれが友人の家を表します。 新しい家の位置として解釈される単一の点を選択し、その家からすべての友人を訪問するのに関連する交通費も計算する必要があります。 

この物語に隠された重要な制約は、選択した家がすべての友人から「等距離」にあることになっているということです。 これにより、すでにジオメトリが大幅に制限されています。そのような点が存在する場合、すべてのフレンド ポイントはその位置を中心とする円上になければなりません。 言い換えれば、問題は、指定された点が共円であるかどうかを判断し、そうであればそれらの共通の中心を見つけることに帰着します。 

このようなセンターが存在すると、2 番目の部分ですべての友人を訪問するための最小合計距離が求められます。 サンプルから、このコストはポイントの数と円の共通半径の両方に線形に比例します。 

したがって、実際のタスクは 2 つの部分になります。 まず、すべての点が単一の円上にあるかどうかを判断します。 次に、それらが存在する場合は、その円の中心と半径を計算し、それらの値から導出される合計コストを出力します。 そのような円が存在しない場合、答えはまったく不可能です。 

制約はポイント数の点で大きく、最大 100 万です。 これにより、すべてのトリプル間の距離のペアごとの幾何学的チェックや再計算が即座に除外されます。 どのようなソリューションでも、少量の固定量の前処理の後、ジオメトリを定数検証または対数検証に削減する必要があります。 

すべての点が同一線上にある場合、微妙なエッジ ケースが発生します。 その場合、それらを通過する有限円は存在せず、外接円を構築しようとする試みは退化します。 もう 1 つの故障モードは、座標は整数ですが結果が必ずしも整数ではないため、浮動小数点演算を使用して円の中心を計算する際の数値の不安定性です。 

## アプローチ

 直接的なアプローチでは、可能なすべての点のトリプルをチェックし、各トリプルの外接円を構築し、他のすべての点がその上にあるかどうかを検証することによって、「すべての点が円上にある」という条件を強制しようとします。 これは原理的には正しいです。同一線上にない 3 つの点は一意に円を定義します。 

ただし、このアプローチは遅すぎます。 トリプルを選択すると、最悪の場合でもすでに O(n^3) 個の候補が得られ、単一の円を検証する場合でも O(n) 回のチェックが必要です。 n が 10^6 までの場合、これは完全に不可能です。 

重要な観察は、すべての点を含む有効な円が存在する場合、それを一意に決定するには同一線上にない 3 つの点で十分であるということです。 最初の 3 つの非同一線上の点だけから円を計算したら、他の点はすべてその円上に正確に存在する必要があります。 これにより、問題は 1 つの有効な幾何学的オブジェクトを見つけて、それを 1 回のパスで検証するだけになります。 

したがって、問題の構造は「すべてのサブセットの検索」から「一定サイズのサブセットから構築してグローバルに検証する」に崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースでポイントを 3 倍にする | O(n^4) | お(1) | 遅すぎる |
 | 3 点から円を作成 + 検証 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのポイントを読み取り、保存します。 
2. 同一線上にない 3 つの点を見つけます。 すべての点が同一線上にある場合は、停止し、有効な解が存在しないことを出力します。 これは、無限に多くの円が有限平面内の 3 つの同一線上の点を通過できないためです。 
3. これら 3 つの同一線上にない点を使用して、一意の外接円を計算します。 これには、垂直二等分線の交点を解くことが含まれ、一意の中心が得られます。 
4. 中心が計算されたら、中心から 3 つの定義点のいずれかまでの距離を使用して半径を計算します。 
5. すべての点を反復処理し、中心までの二乗距離が等しいことを確認して、各点が同じ円上にあることを確認します。 どこかがずれていると設定が無効となり、解決策がありません。 
6. すべての点が円上にある場合、最終的な答えは半径の n 倍として計算されます。 

最終的な n の乗算が有効である理由は、サンプルの動作の構造に由来します。つまり、すべてのポイントが合計コストに等しく寄与し、コストは訪問数と中心からの固定移動半径の両方に比例して増加します。 

### なぜ効果があるのか

 3 つの同一線上にない点が、一意の円を定義します。 すべての点がその中心までの同じ距離制約を満たす場合、それらはすべてその円上に正確に存在する必要があります。 平方距離を比較するときに、偏差があるとすぐに等価条件が崩れてしまいます。 3 つの定義点が決まれば円は一意に決定されるため、検証は必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def circumcenter(ax, ay, bx, by, cx, cy):
    d = 2 * (ax*(by-cy) + bx*(cy-ay) + cx*(ay-by))
    if d == 0:
        return None

    a2 = ax*ax + ay*ay
    b2 = bx*bx + by*by
    c2 = cx*cx + cy*cy

    ux = (a2*(by-cy) + b2*(cy-ay) + c2*(ay-by)) / d
    uy = (a2*(cx-bx) + b2*(ax-cx) + c2*(bx-ax)) / d
    return ux, uy

n = int(input())
pts = [tuple(map(int, input().split())) for _ in range(n)]

# find 3 non-collinear points
p1 = pts[0]
p2 = None
p3 = None

for i in range(1, n):
    if pts[i] != p1:
        p2 = pts[i]
        break

if p2 is None:
    print(-1)
    sys.exit()

for i in range(1, n):
    a = p1
    b = p2
    c = pts[i]
    if (b[0]-a[0])*(c[1]-a[1]) != (b[1]-a[1])*(c[0]-a[0]):
        p3 = c
        break

if p3 is None:
    print(-1)
    sys.exit()

cx, cy = circumcenter(p1[0], p1[1], p2[0], p2[1], p3[0], p3[1])
if cx is None:
    print(-1)
    sys.exit()

r2 = (pts[0][0]-cx)**2 + (pts[0][1]-cy)**2

eps = 1e-6
for x, y in pts:
    if abs((x-cx)**2 + (y-cy)**2 - r2) > 1e-6:
        print(-1)
        sys.exit()

import math
r = math.sqrt(r2)
ans = n * r

print(f"{cx:.10f} {cy:.10f}")
print(f"{ans:.10f}")
```この実装では、まず基点を選択して 2 番目の個別の点を検索し、次に最初の 2 点と同一線上にない 3 番目の点をスキャンします。 これにより、外接円が明確に定義されます。 

外心の計算には、垂直二等分線の交点から導出される標準の行列式が使用されます。 ここでは浮動小数点演算が避けられないため、検証は許容差のある二乗距離に依存します。 

最後に、すべての点が計算された半径に対してチェックされます。 この検証後にのみ、最終的なスケールコストを計算します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | トリプルを定義するために 1 回のスキャン、すべてのポイントを検証するために 1 回のスキャン |
 | スペース | O(n) | 入力ポイントの保存 |

 前処理後のすべての操作はポイントごとに一定時間であるため、リニア スキャンは最大 100 万ポイントまでで十分です。 ジオメトリの計算自体は O(1) であるため、解は時間制限内に問題なく収まります。 

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sqrt

    # inline solution for testing
    input = sys.stdin.readline
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    def cc(ax, ay, bx, by, cx, cy):
        d = 2*(ax*(by-cy)+bx*(cy-ay)+cx*(ay-by))
        if d == 0:
            return None
        a2 = ax*ax+ay*ay
        b2 = bx*bx+by*by
        c2 = cx*cx+cy*cy
        ux = (a2*(by-cy)+b2*(cy-ay)+c2*(ay-by))/d
        uy = (a2*(cx-bx)+b2*(ax-cx)+c2*(bx-ax))/d
        return ux, uy

    p1 = pts[0]
    p2 = None
    for i in range(1, n):
        if pts[i] != p1:
            p2 = pts[i]
            break
    if p2 is None:
        return "-1"

    p3 = None
    for i in range(1, n):
        if (p2[0]-p1[0])*(pts[i][1]-p1[1]) != (p2[1]-p1[1])*(pts[i][0]-p1[0]):
            p3 = pts[i]
            break
    if p3 is None:
        return "-1"

    res = cc(*p1, *p2, *p3)
    if res is None:
        return "-1"

    cx, cy = res
    r2 = (pts[0][0]-cx)**2 + (pts[0][1]-cy)**2

    for x, y in pts:
        if abs((x-cx)**2 + (y-cy)**2 - r2) > 1e-6:
            return "-1"

    r = math.sqrt(r2)
    return f"{cx:.10f} {cy:.10f}\n{n*r:.10f}"

 ## 特殊なケース

 共線的ケースは主な構造的欠陥です。 すべての点が 1 つの直線上にある場合、外接円を計算しようとすると、式にゼロの行列式が生成されます。 その場合、アルゴリズムは有効な 3 番目の非共線点の不在を明示的に検出し、すぐに -1 を返します。 

重複した点やほぼ同一の点は通常安定性を脅かしますが、この問題では明確な座標が保証されるため、唯一の懸念は最終検証ステップでの数値精度です。 二乗距離を使用すると、検証フェーズで平方根エラーが発生することが回避され、最終出力のみが浮動小数点演算に依存することが保証されます。
