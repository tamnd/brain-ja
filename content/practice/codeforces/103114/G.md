 ## 解決策
 ## 問題の理解

 1 から n までの数値の隠された順列が与えられ、位置 1 から n にわたって保存されます。 私たちの仕事は、順列全体を復元することです。つまり、すべての位置で正確な値を決定する必要があります。 

情報を取得する唯一の方法はクエリです。 各クエリでインデックスのサブセットを選択すると、判定者はそれらの位置に格納されている、ソートされた値を返します。 返された配列はソートされているため、サブセット内の位置の対応関係は取得されず、そこに含まれる値の複数セットのみが取得されます。 

このようなクエリは最大 10 件まで行うことができますが、これがソリューションを推進する中心的な制約となります。 n が 1000 までの場合、位置を 1 つずつ検査する方法は不可能です。 リニア スキャンでも最大 1000 個のクエリが必要となり、制限をはるかに超えています。 これにより、順列全体を少数のグローバルな観測値に圧縮することが直ちに強制されます。 

サブセットをクエリするとメンバーシップを超えた構造が明らかになると仮定すると、微妙なエッジ ケースが発生します。 たとえば、2 つのインデックスをクエリしてソートされたペアを確認した場合、それらの間の順序を誤って推測しようとする可能性がありますが、ソートによってサブセット内の位置情報が破壊されるため、それは不可能です。 唯一信頼できる事実は、値がクエリされたインデックスのセットに属しているかどうかです。 

これは、各クエリが基本的に、選択したインデックスと観測値の間のメンバーシップ テストであることを意味します。 

## アプローチ

 単純な戦略は、各インデックスを個別にクエリすることです。 インデックス i のみをクエリすると、その位置の単一の値が返され、a[i] がすぐに明らかになります。 これは正しいですが、n 個のクエリを使用します。これは最大 1000 個であり、許可されている 10 個をはるかに超えています。このアプローチは純粋にクエリ バジェットが原因で失敗します。 

重要な観察は、各クエリがインデックスに対するバイナリ分類子として解釈できることです。 サブセット S を選択し、各値 v について、その位置が S にあるという意味で v が S に属するかどうかを観察します。したがって、各クエリは、すべての位置に対して、インデックスではなく値に対して Yes または No のラベルを与えます。 サブセットを慎重に設計すると、最大 10 個のクエリにわたって各位置に一意の署名を割り当てることができます。 

このアイデアは、各インデックスに 0 から n-1 までの 10 ビットの識別子を事前に割り当てることです。 各クエリはこの識別子の 1 ビットに対応し、その識別子の j 番目のビットが 1 の場合、インデックス i をクエリ j に含めます。すべてのクエリを実行した後、すべての値 v はその真の位置のビット パターンを継承します。これは、その位置がインデックス セットに含まれるクエリに正確に現れるためです。 

したがって、位置を直接見つける代わりに、各値の署名を回復し、それを反転して順列を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各インデックスを個別にクエリする | O(n) クエリ | O(1) おまけ | 遅すぎる |
 | 10 ビット署名の構築 | O(n log n) 処理 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 慎重に設計された 10 個のインデックス サブセットを構築し、それらを使用してすべての位置をエンコードします。

1. 1 から n までの各インデックス i に、i-1 のバイナリ表現に対応する 10 ビットのバイナリ ラベルを割り当てます。 1000 までの n には 2^10 = 1024 で十分であるため、このラベルは各インデックスを一意に識別します。 
2. 0 ～ 9 のビット位置 j ごとに、ラベルの j 番目のビットが 1 であるすべてのインデックス i を含むクエリ セット S_j を構築します。これにより、10 個の異なるインデックス サブセットが作成されます。 
3. 各サブセット S_j について、審査員にクエリを送信し、それらのインデックスに位置する値のソートされたリストを受け取ります。 セットのメンバーシップのみを考慮しているため、ソートは無関係です。 
4. クエリ j への応答に現れるすべての値 v について、ビット j が v の署名の一部であることをマークします。 これは、位置インデックスが S_j にあるときに v がクエリ j に正確に現れるため、機能します。 
5. 10 個のクエリをすべて処理した後、すべての値 v には、その位置のバイナリ ラベルと一致する 10 ビットの署名が蓄積されます。 
6. 各値 v について、その署名を整数インデックス i に変換します。 a[i] = v を設定して順列を再構築します。 

重要な設計上の選択は、値ではなくインデックスをエンコードすることです。 値がインデックス署名を継承すると、反転は直接的になります。 

### なぜ効果があるのか

 各クエリは、含まれるインデックスと除外されるインデックスのパーティションを定義します。 値 v は、その位置インデックスが選択されたサブセットに含まれている場合に、クエリ応答に表示されます。 したがって、各値は、その真のインデックスのビット表現に等しい一貫したメンバーシップ ベクトルを蓄積します。 すべてのインデックスには個別のビット パターンがあるため、2 つの位置が同じ署名を生成することはなく、値と再構築されたインデックスの間の全単射が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(indices):
    print(len(indices), *indices)
    sys.stdout.flush()
    res = list(map(int, input().split()))
    return res

n = int(input())

# build 10 bit masks
bits = 10
where = [[] for _ in range(bits)]

for i in range(1, n + 1):
    for b in range(bits):
        if (i - 1) >> b & 1:
            where[b].append(i)

sig = [0] * (n + 1)

for b in range(bits):
    res = ask(where[b])
    for v in res:
        sig[v] |= (1 << b)

ans = [0] * (n + 1)
for v in range(1, n + 1):
    pos = sig[v] + 1
    ans[pos] = v

print("!", *ans[1:])
sys.stdout.flush()
```コードはまず、インデックスのバイナリ分解に基づいて 10 個のインデックス グループを構築します。 各クエリは 1 ビットに対応し、そのビットが設定されている位置にあるすべての値を返します。 値ごとにビットマスクを蓄積します。 

微妙な部分は、返された数値を値として解釈し、どのクエリがそれらを生成したかに基づいてビットを付加することです。 最後に、各値のビットマスクはその位置を直接エンコードします。 

最後の再構成ステップでは、各値をその署名によって示される位置に配置するだけです。 

## 実用的な例

 n = 4 および順列 [3, 1, 4, 2] の小さな概念的な例を考えてみましょう。 

2^2 < 4 ≤ 2^3 であるため、3 ビットを使用します。 

ビット 0 の場合、LSB 1 のインデックスは {1, 3} です。 クエリは値 {3, 4} を返します。 値 3 と 4 のビット 0 をマークします。 

ビット 1 の場合、インデックスは {2, 3} です。 クエリは {1, 4} を返します。 値 1 と 4 のビット 1 をマークします。 

ビット 2 の場合、インデックスは {3} です。 クエリは {4} を返します。 ビット 2 を値 4 としてマークします。 

署名を要約します。 

| 値 | ビット0 | ビット 1 | ビット 2 | 署名 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 | 010 |
 | 2 | 0 | 0 | 0 | 000 |
 | 3 | 1 | 0 | 0 | 001 |
 | 4 | 1 | 1 | 1 | 111 |

 署名をデコードすると、次の位置が得られます。 

| 値 | 署名 | ポジション |
 | --- | --- | --- |
 | 1 | 010 | 2 |
 | 2 | 000 | 1 |
 | 3 | 001 | 3 |
 | 4 | 111 | 4 |

 これにより、順列が正しく再構築されます。 

このトレースは、値が独立したクエリ全体で一貫して位置情報を蓄積し、最終的なビットマスクが各位置を一意に識別することを示しています。

| スペース | O(n) | ビット署名と再構成配列のストレージ |

 n が最大 1000 で、それぞれに線形処理が含まれるクエリが 10 個だけ使用されるため、このソリューションは制約内に簡単に適合します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    input = sys.stdin.readline

    # simulate offline version of logic (no interaction)
    n = int(input())
    a = list(map(int, input().split()))

    bits = 10
    sig = [0] * (n + 1)

    for b in range(bits):
        res = []
        for i in range(1, n + 1):
            if (i - 1) >> b & 1:
                res.append(a[i - 1])
        for v in res:
            sig[v] |= (1 << b)

    ans = [0] * (n + 1)
    for v in range(1, n + 1):
        ans[sig[v] + 1] = v

    return " ".join(map(str, ans[1:]))

# custom cases (offline simulation)

assert run("1\n1") == "1", "minimum size"

assert run("5\n5 4 3 2 1") == "5 4 3 2 1", "reverse permutation"
assert run("8\n3 8 1 6 4 2 7 5") == "3 8 1 6 4 2 7 5", "random permutation"

 ## 特殊なケース

 重要なエッジ ケースは n = 1 です。この場合、原則としてビット構築は必要ありませんが、単一インデックスの署名が 0 で位置 1 に直接マップされるため、アルゴリズムは引き続き機能します。再構築ステップは変更せずに有効なままです。 

もう 1 つのエッジ ケースは n = 2^k − 1 で、最大 10 ビットのすべてのビット パターンが使用されるわけではありません。 この構築では引き続き一意の署名が割り当てられ、インデックス 1 から n のみを考慮するため、未使用のパターンは干渉しません。 

さらなるケースは、順列がソートまたは反転される場合です。 どちらの場合でも、プロセスは値の順序ではなくインデックスの包含のみに依存するため、値は依然として正しいビットマスクを蓄積します。 応答内の位置順序に依存しないため、クエリ応答の並べ替えは正確さに影響しません。
