 ## 解決策
 ## 問題の理解

 チーズ片のコレクションが与えられ、それぞれに初期鮮度値が設定されています。 時間は日単位で進みます。 毎日、残りのすべての部分が同時に 1 単位の鮮度を失います。 トライナさんは毎日、多くても 1 切れを食べることが許されていますが、彼は好き嫌いが多く、その日はその日の鮮度が 2 で割り切れる量の 1 切れだけを食べることができます。 

目標は、これらのルールに従ってすべてのチーズ片が食べられるようになるまでに必要な最小日数を決定することです。 

重要な点は、鮮度は時間の経過とともに一様に低下するため、食べられるかどうかはその価値だけでなく、食べる日にも左右されるということです。 したがって、問題は削除のスケジュールを設定することだけではなく、時間依存のパリティ制約の下で削除をスケジュールすることにもあります。 

この制約により、鮮度値は 1000000 までの 100000 個までが許可されます。これにより、日々の食事のシミュレーションは即座に除外されます。 何日も繰り返して有効なチーズを選択しようとする単純なアプローチでは、最大鮮度値まで実行される可能性があり、これは大きすぎます。 有効な解決策は、問題を線形時間での計数と組み合わせ論に還元する必要があります。 

単純な貪欲シミュレーションの一般的な失敗例は、将来のパリティ制約を考慮せずに、現在食べられるチーズを常に選択する場合に発生します。 

たとえば、初期の選択が最初に「柔軟な」アイテムを消費する場合、その後の特定のパリティにのみ適合するアイテムのスケジュールをブロックする可能性があります。 鮮度の同等性は毎日変わるため、品物を遅らせると、翌日には食べられるかどうかさえ変わる可能性があるため、貪欲な地元の選択は黙って失敗する可能性があります。 

## アプローチ

 最初の直感は、プロセスを毎日シミュレーションすることです。 毎日、すべての鮮度値を更新し、現在の鮮度が偶数である有効なアイテムをスキャンします。 可能であれば1つを削除します。 これは正しいですが、毎日最大 n 項目のスキャンが必要であり、最悪の場合は最大 O(max(ai)) 日かかる可能性があるため、非常に遅くなり、最悪のシナリオでは約 10^11 の操作が必要になります。 

重要な観察は、鮮度の同等性が非常に構造化された方法で進化するということです。 最初の鮮度が a のチーズは、d 日後には a ～ d になります。 d 日に食べられる条件は、a - d が偶数であることです。これは、d を減算すると d に応じてパリティが反転するため、a と d が逆のパリティを持つことと同等です。 

この制約を書き直すと、より明確な解釈が得られます。各チーズは大きさにはまったく依存せず、奇数日に食べなければならないか偶数日に食べなければならないかのみに依存します。 これにより、問題は 2 種類のジョブと 2 種類のタイムスロットを伴うスケジュールの問題に変換されます。 

私たちは、各チーズを個別の日に割り当てることに問題を落とし込みます。この場合、毎日のパリティは固定されており、各チーズには特定の日のパリティが必要です。 残る唯一の制約は、毎日扱うことができるチーズは 1 つだけであるということです。 

そこで問題は次のとおりです。奇数日に移動する必要がある項目と偶数日に移動する必要がある項目の 2 つのグループがあり、すべての項目が収まるように最小の日付のプレフィックスが必要です。 

奇数日を必要とするアイテムの数と偶数日を必要とするアイテムの数を計算し、T までの利用可能な奇数スロットと偶数スロットが十分であるような最小の T を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 日々のシミュレーション | O(n · max(ai)) | O(n) | 遅すぎる |
 | パリティのカウントとスケジューリング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各チーズをいつ食べられるかに基づいて単純なパリティ要件に変換します。 次に、各パリティ クラスに属するチーズの数を数えます。 最後に、両方のパリティ クラスが利用可能な日数スロットに収まるように必要な最小日数を計算します。

1. 初期鮮度 a のチーズごとに、その日のどの日に食べなければならないかを決定します。 鮮度は毎日 1 ずつ減少するため、鮮度のパリティは毎日交互に変化します。そのため、この条件は、a と日インデックスの間のパリティの一致のみに依存します。 
2. 各チーズを、奇数日が必要なものと偶数日が必要なものの 2 つのグループのいずれかに分類します。 k_odd と k_even をそれらのカウントとします。 
3. T 日というプレフィックスを考慮します。 奇数日の数は (T + 1) // 2、偶数日の数は T // 2 です。 
4. k_odd <= (T + 1) // 2 と k_even <= T // 2 の両方が同時に成立する必要があります。 
5. T の 2 つの構造的なケースを試してみます。T が偶数の場合、T = 2m、奇数日も偶数日も m なので、m >= max(k_odd, k_even) が必要です。 これにより、候補 T = 2 * max(k_odd, k_even) が得られます。 
6. T が奇数の場合、T = 2m + 1、奇数日は m + 1、偶数日は m になります。 m >= k_even および m + 1 >= k_odd が必要です。これは、m >= max(k_even, k_odd - 1) を意味します。 これにより、候補 T = 2 * max(k_even, k_odd - 1) + 1 が得られます。 
7. 答えは、これら 2 つの有効な構造の最小値です。 

これが機能する理由は、長さ T を固定すると、奇数スロットと偶数スロットがいくつ存在するかだけがスケジュールの構造になるからです。 各チーズは独立しており、パリティ制約のみがあるため、カウントが一致する限り、どのような割り当ても実行可能です。 スロットの可用性を超える相互作用はないため、問題を 2 部構成のカウント制約に縮小することは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    k_odd = 0
    k_even = 0
    
    for x in a:
        # determine required parity of day
        # x - (d-1) even => parity(d) = parity(x+1)
        if (x + 1) % 2 == 1:
            k_odd += 1
        else:
            k_even += 1
    
    # even T = 2m
    t_even = 2 * max(k_odd, k_even)
    
    # odd T = 2m + 1
    m = max(k_even, k_odd - 1)
    if m < 0:
        m = 0
    t_odd = 2 * m + 1
    
    print(min(t_even, t_odd))

if __name__ == "__main__":
    solve()
```このコードは、まず各チーズをパリティ要件に落とし込み、各クラスに該当するチーズの数をカウントします。 次に、最適なスケジュール長の 2 つの可能な構造形式 (偶数と奇数) を評価し、最小値を採用します。 重要な詳細は、奇数日の場合、偶数日と比較してスロットが 1 つ多い、奇数長の場合の非対称制約の処理です。 

実装上の微妙な点は、k_odd が 0 または 1 の場合に k_odd - 1 が負にならないようにすることです。これは、その範囲内では制約 m >= k_odd - 1 が自動的に満たされるためです。 

## 実用的な例

 ### 例 1

 入力:```
4
500001 500002 500003 500004
```パリティ要件を計算します。 

| ステップ | 値 | (a+1)%2 | カテゴリー |
 | --- | --- | --- | --- |
 | 1 | 500001 | 偶数 | 偶数日 |
 | 2 | 500002 | 奇数 | 奇数日 |
 | 3 | 500003 | 偶数 | 偶数日 |
 | 4 | 500004 | 奇数 | 奇数日 |

 したがって、k_odd = 2、k_even = 2となります。 

次に、以下を評価します。 

| T型 | 式 | 値 |
 | --- | --- | --- |
 | 偶数 | 2 * 最大(2,2) | 4 |
 | 奇数 | 2 * 最大(2,1) + 1 | 5 |

 最小値は 4 です。 

これは、バランスのとれた分散が余分な余裕を必要とせずに交互のパリティ スロットに完全に適合することを示しています。 

### 例 2

 入力:```
3
500001 500003 500004
```パリティ分類:

 | 値 | カテゴリー |
 | --- | --- |
 | 500001 | 偶数日 |
 | 500003 | 偶数日 |
 | 500004 | 奇数日 |

 したがって、k_even = 2、k_odd = 1 となります。 

ここで次を計算します。 

| T型 | 値 |
 | --- | --- |
 | 偶数 | 2 * 2 = 4 |
 | 奇数 | 2 * 最大(2,0) + 1 = 5 |

 答えは4です。 

これは、1 つのパリティ クラスが優勢な場合でも、制限パリティの十分なスロットが存在するまで最適なスケジュールが単純に拡張されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

このソリューションは、単一の線形スキャンとその後の定数時間演算を実行するため、制約内に簡単に適合します。

 ## 特殊なケース

 チーズが 1 つしかない場合、アルゴリズムはそれを 1 つのパリティ バケットに分類し、実現可能性に応じて 1 または 2 をすぐに返します。これは、常に少なくとも 1 日が必要であるという事実と一致します。 

すべてのチーズが同じパリティ クラスに属している場合、式はそのパリティの十分なスロットを強制することになり、単純な 2 倍パターンになります。 偶数長の構造が優先され、正しい線形スケーリングが得られます。 

パリティ クラス間の不均衡が大きい場合、奇数長の場合は 1 つのパリティ タイプのスロットが 1 つ追加されるため、奇数長のケースが重要になります。 アルゴリズムは両方の構造を正しくテストし、均等な長さのスケジュールにオーバーコミットするのではなく、最小限の拡張が選択されるようにします。
