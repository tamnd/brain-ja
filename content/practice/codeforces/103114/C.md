 ## 解決策
 ## 問題の理解

 島 1 から島 n までの番号が付けられた島の行が与えられています。 どの島 j からでも、Chtholly は利用可能な「ステップ サイズ」のセットから 1 つの値を追加することで前にジャンプできます。これは、彼女が j から j + x に移動することを意味します。x は彼女の現在の能力リストから選択されます。 

彼女は島 1 から開始し、正確に島 n に到達したいと考えています。 「ウェイ」とは、単なる最終的な経路長やステップのセットではなく、選択されたステップ サイズの完全に順序付けられたシーケンスであり、異なるシーケンスは、異なる方法で同じ位置に到達する場合でも、異なるものとみなされます。 

クエリに答える前に、2 種類のステップ サイズがあります。 初期セット a は常に使用可能です。 さらに、別のセット b があり、クエリごとに、b のどのサブセットがアクティブ化され、使用可能なステップ セットにマージされるかが通知されます。 各クエリについて、最終的に 1 から n に移動する順序付けされたステップのシーケンスの数をカウントする必要があります。 

重要な構造は、各クエリがコインの釣銭形式の計数問題、つまり、許容されるステップ サイズを使用して n − 1 の順序付けされた構成をいくつ形成できるかを定義することです。 

制約は、個別のステップ タイプの数が少なく、最大 10 の初期ステップと 10 のオプション ステップです。 ただし、n は最大 10^4 にすることができ、クエリの数も最大 10^4 にすることができます。 これは、クエリごとに動的プログラムを最初から再計算するのは単純に実行すると遅すぎることを直ちに示唆しています。クエリごとの単純な DP はステップ サイズ数の n 倍のコストがかかり、最大 10^4 回繰り返されるからです。 

微妙な点の 1 つは、ステップ値にゼロが含まれる可能性があることです。 ゼロステップは同じアイランドに留まるという意味で、位置は変わらないが任意に挿入できるシーケンスが無限に作成されます。 厳密に解釈すると、方法の数は無限になります。 正しい解決策は、ゼロ ステップが無関係であると仮定するか、有効な進行に寄与することから暗黙的に除外されるかのどちらかでなければなりません。そうしないと、有限パスをカウントするための問題が明確に定義されていないからです。 

もう 1 つの微妙な点は、答えが組み合わせではなく順序付けられたシーケンスに依存することです。 この区別は順序が重要であることを意味し、部分集合の合計数ではなく順列形式の DP を解いているため、重要です。 

## アプローチ

 自然な総当たりアプローチは、各クエリを独立して処理することです。 与えられた許可されたステップ サイズのセットに対して、dp[i] がアイランド 1 からアイランド i に到達する方法の数である DP を定義します。2 から n までの各 i について、すべてのステップ サイズ x を試し、dp[i − x] を dp[i] に加算します。 これにより、各ステップが前の有効なシーケンスに 1 つの移動を追加するため、すべての順序付けされたシーケンスが正しくカウントされます。 

単一のクエリの場合、これには O(n · s) のコストがかかります。s はアクティブなステップ サイズの数で、最大 20 です。ただし、最大 10^4 のクエリがあるため、最悪の場合は O(q · n · s)、約 10^4 · 10^4 · 20 となり、これは大きすぎます。 

重要な観察は、可能な個別のステップ セットの数が少ないということです。 基本セット a は固定されており、オプションで最大 10 個の追加要素のみを含めることができます。 つまり、すべてのクエリは 10 要素セットのサブセットに対応するため、最大 2^10 = 1024 個の個別の構成が存在します。 これは、すべてのサブセットに対する事前計算を示唆しています。 

DP を個別に再計算するのではなく、ビットマスク上で段階的に DP を計算します。 各マスクは追加のステップのサブセットを表します。 a のみを使用してベース DP から開始し、次に b 要素を 1 つずつ追加します。 新しいステップ サイズ x を追加するときは、標準のコイン追加遷移として dp を更新します: dp_new[i] += dp_old[i − x]。 

これにより、以前に計算された状態の再利用が可能になるため、各サブセットは O(n) 内の別のサブセットから構築され、総作業量はサブセット ラティス全体の遷移の数に比例します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに DP を再計算する | O(q · n · (m + k)) | O(n) | 遅すぎる |
 | サブセット上の DP (ビットマスク増分ビルド) | O(2^k · n · k) | O(2^k · n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、許容されるステップ サイズの変数セットを使用して、値 n − 1 の順序付けられた合成の数をカウントするものとして再解釈します。 各クエリはオプションのステップ サイズのサブセットをアクティブにするため、各サブセットの DP を効率的に評価する必要があります。 

### アルゴリズムのチュートリアル

 1. 1 から開始し、ステップ サイズだけ前に進むため、ターゲットを距離 N = n − 1 として正規化します。 これにより、問題は、合計が正確に N になるシーケンスを数えるという問題に軽減されます。その理由は、すべてのパスが、合計変位が N であるジャンプのシーケンスに一意に対応するためです。 
2. ゼロに等しいステップ サイズを無視して、配列 a から基本セット S0 を構築します。 ゼロ ステップは新しいアイランドへの到達には寄与せず、ゼロ ステップを含めると、位置が決して変わらない非終了シーケンスが導入されます。 
3. 基本セット S0 の DP 配列を事前計算します。ここで、dp_base[i] には、S0 のみを使用して距離 i に到達する順序付けされたウェイの数が格納されます。 これは、各 dp 状態がすべてのステップ サイズからの寄与を蓄積する、標準の無制限の順序付けされたナップザック遷移を使用して行われます。 
4. オプションのセット b を最大 10 個の要素のリストとして表し、これらの各サブセットが 0 ～ 2^k − 1 のビットマスクに対応するようにインデックス付けされます。各マスクは、追加の能力の個別の選択を表します。 
5. インクリメンタル構築を使用して、すべてのマスクの dp[mask] を事前計算します。 マスク 0 は追加の能力がないことを意味するため、dp[0] を dp_base として初期化します。 
6. 0 から k − 1 までの各ビット i について、dp[prev_mask] を取得し、b[i] に 1 つの追加のコイン遷移を適用することにより、ビット i を含むマスクの dp を事前計算します。 この遷移では、有効なインデックス j に対して寄与 dp_new[j] += dp_old[j − b[i]] を追加することで、すべての dp 値を更新します。 これにより、サブセット ラティスに沿ってすべてのサブセットが 1 回だけ構築されます。 
7. 選択したサブセットをそのビットマスクに変換し、dp[mask][N] を直接出力することで、各クエリに応答します。 

### なぜ効果があるのか

 DP 状態 dp[mask][i] は、単一の独立したステップ サイズの追加による、より小さなマスクにのみ依存します。 順序が重要であるため、新しいステップ サイズを追加するたびに、そのステップを既存のシーケンスの可能なすべての位置に挿入することに正確に対応します。 インクリメンタル畳み込みにより、すべての有効な順序付けされたシーケンスが 1 回だけカウントされ、マスクの構築順序で最後に追加されたステップ タイプの最後の出現によってすべてのシーケンスを分解できるため、シーケンスが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_dp(steps, n):
    dp = [0] * (n + 1)
    dp[0] = 1
    for x in steps:
        if x == 0:
            continue
        for i in range(x, n + 1):
            dp[i] = (dp[i] + dp[i - x]) % MOD
    return dp

n, m, k = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

target = n - 1

base_steps = [x for x in a if x > 0]
base_dp = build_dp(base_steps, target)

# precompute dp for all masks
size = 1 << k
dp_mask = [None] * size
dp_mask[0] = base_dp

b = [x for x in b]

for mask in range(1, size):
    # pick lowest set bit
    lsb = mask & -mask
    i = (lsb.bit_length() - 1)
    prev = mask ^ lsb

    prev_dp = dp_mask[prev]
    x = b[i]

    cur = prev_dp[:]  # start from previous
    if x != 0:
        for j in range(x, target + 1):
            cur[j] = (cur[j] + cur[j - x]) % MOD

    dp_mask[mask] = cur

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    c = tmp[0]
    mask = 0
    for i in range(1, c + 1):
        mask |= 1 << (tmp[i] - 1)
    print(dp_mask[mask][target] % MOD)
```DP は 2 層構造になっています。 最初の層は、常に利用可能なステップ サイズを使用して基本トランジションを構築します。 2 番目の層は、以前に計算された DP 配列を再利用することによってオプションのステップ サイズのすべての組み合わせを構築し、各サブセットが最初から再計算するのではなく作業を再利用するようにします。 

微妙な点は、サブセットの構築です。各マスクは、前のマスクを取得し、新しいステップ サイズを 1 つだけ追加することによって構築されます。 これにより、各 dp 配列がサブセットごとに 1 回だけ計算されることが保証され、再計算サイクルが回避されます。 

内部 DP 遷移は、標準的な順序付けされたコイン変更の繰り返しであり、シーケンスはステップ適用の順序によって異なるため、これは適切です。 

## 実用的な例

 n = 5、基本ステップ a = [1]、およびオプションのステップ b = [2] という小さなケースを考えてみましょう。 

ターゲット N = 4 を計算します。 

### 基本DP

 | 私 | dp_base[i] |
 | --- | --- |
 | 0 | 1 |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 ステップ サイズ 1 のみが存在するため、各値は 1 になります。 

次に、ステップ 2 を追加することを検討します。 

| 私 | dp_with_2[i] | 投稿説明 |
 | --- | --- | --- |
 | 0 | 1 | 空のシーケンス |
 | 1 | 1 | [1] のみ |
 | 2 | 2 | [1,1]、[2] |
 | 3 | 3 | [1,1,1]、[1,2]、[2,1] |
 | 4 | 5 | 1 と 2 を使用したすべての順序付けされた構成 |

 これは、単一のステップ サイズを導入すると、新しい挿入位置が可能になり、組み合わせ分岐がどのように増加するかを示しています。 

トレースでは、[1,2] と [2,1] のような順列は両方とも別々に寄与するため、DP が組み合わせだけでなく順序付けされたシーケンスを正しくカウントしていることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、ステップ サイズがゼロの場合です。 これを含めると、同じ島に無限に留まることができるため、状態が変化しないシーケンスが無限に多くなります。 正しい処理は、ゼロ ステップを DP から完全に除外することです。ゼロ ステップは新しい位置への到達に寄与せず、カウント問題の有限性を壊すためです。 

もう 1 つのエッジ ケースは、n = 1 の場合です。この場合、Chtholly はすでに宛先にあるため、唯一の有効なシーケンスは空のシーケンスです。 DP は dp[0] = 1 を正しく初期化し、このケースでは利用可能なステップに関係なく 1 が返されるようにします。 

さらに、すべてのステップ サイズが大きい (n − 1 より大きい) 場合も考えられます。 この状況では、遷移は不可能であり、n = 1 でない限り、答えはゼロでなければなりません。到達不能なインデックスに対して dp 遷移はトリガーされないため、DP は自然にこれを処理します。
