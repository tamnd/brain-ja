 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられています。$n$頂点。 各エッジは 2 つの頂点を接続し、正の長さを持ちます。 タスクは、パスに正確に含まれるように、このツリー内の単純なパスを選択することです。$k$このようなすべてのパスの中で、可能な限り最大の合計エッジ重みを持つパスが必要です。 

ここでの単純なパスは、頂点を再訪できないことを意味するため、構造はツリー内の常に直線のパスになります。 グラフはツリーであるため、任意の 2 つの頂点が一意の単純なパスを定義します。問題は、それらの間のパス上の頂点の数が正確に一致するように 2 つの端点を選択することになります。$k$。 

制約により、最大で$10^5$頂点と$10^5$のために$k$これにより、頂点のすべてのペアを試行したり、すべてのパスを明示的に列挙したりするアプローチは直ちに除外されます。 二次関数または偶数$O(n \cdot k)$単純な動的プログラミングは、最悪の場合、$10^{10}$トランジション。 

これが単なる直径の問題であると考えるのは単純な間違いです。 たとえば、5 つのノードの直線チェーンのようなツリーの場合、$k = 3$、直径は長さ 5 ノードの完全なチェーンですが、使用するノードが多すぎるため無効です。 もう 1 つの失敗例は、常にグローバルに最長のパスを選択してそれを切り捨てることができると想定している場合ですが、最大重みのパスを切り詰めても固定ノード数に対する最適性が保証されないため、これは誤りです。 

もう 1 つの微妙な問題は、最適なパスがツリーの中心または重心を通過する必要があると仮定していることです。 これは偽です。最適な長さの制約されたパスは、重心から遠く離れた 1 つのサブツリー内に完全に存在する可能性があるからです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての頂点のペアを考慮します$(u, v)$、LCA を使用してそれらの間の一意のパスを計算し、そのパス上の頂点の数を数え、それが等しいかどうかを確認します。$k$、その総重量を計算します。 これが機能するのは、ツリー内ではすべてのペアが 1 つの単純なパスを定義しており、列挙によってすべての可能性がカバーされるためです。 

問題は、これには次のことが必要であるということです$O(n^2)$ペアであり、各クエリには少なくとも次のコストがかかります$O(\log n)$または$O(k)$評価する必要がありますが、これは実現可能な限界をはるかに超えています。 

重要な観察は、任意のエンドポイントの観点から考える代わりに、ツリーをルート化し、下向きのパスの結合の観点から考えることができるということです。 有効なパスには、方向が変わる最高点 (「ピーク」) があります。これは、パスがそのピークから 2 つの下向きのチェーンに分解できることを意味します。 このピークをどこかのノードで修正すると$u$の場合、パスは 1 つのサブツリーへの 1 つの下向きチェーンと、別のサブツリーへの別の下向きチェーンで構成されます。または、パスが で始まる場合は片側のみで構成される可能性があります。$u$。 

これにより、問題がツリー動的プログラミング タスクに変換され、ノードごとに、可能なすべての数のノードについて知りたいとなります。$t$、正確に使用した、そのノードから始まる下向きパスの最適な重み$t$頂点。 これらの値を取得したら、各ノードで 2 つの子の寄与を組み合わせて、そのノードを通過するパスの候補の答えを形成できます。 

問題は、各ノードが潜在的に一定のサイズの配列を維持することです。$k$、子のマージはナップサックスタイルの畳み込みのように見えます。 すべての子を直接マージすると、次のようになります。$O(nk)$最悪の場合、ノードあたりの最大数が大きすぎます。 ただし、各エッジは親と子の間でのみ構造に寄与するため、子の寄与を段階的にマージし、サイズごとに最適な値のみを維持できます。 

これにより、各ノードがサブツリー サイズに応じて DP テーブルを維持し、子を 1 つずつマージする標準のツリー ナップザック動的プログラミング ソリューションが実現します。

 ## アルゴリズムのチュートリアル

 任意のノード (ノード 1 など) でツリーをルート化し、下向きのパスをキャプチャする DP 状態を定義します。 

1. 定義します$dp[u][t]$ノードから始まる下向きの単純なパスの最大合計重みとして$u$、そのサブツリーにのみ入り、正確に使用します$t$頂点。 この定義により、すべての状態が単一のチェーンを表すことが強制されます。これは、分岐構造による曖昧さを回避するために不可欠です。 
2. リーフ ノードの場合、有効なパスはノード自体だけであるため、$dp[u][1] = 0$。 エッジは使用されず、より大きな値$t$不可能です。 
3. 事後 DFS を実行します。 ノードを処理するとき$u$基本ケースから始めます$dp[u][1] = 0$、各子を処理します$v$。 
4.子供のために$v$、まず保証します$dp[v]$が計算されます。 それから合併します$v$の中へ$u$。 からの下降パス$u$サイズの$t$それは通る$v$～から下向きのパスを取ることによって形成されます$v$サイズの$t-1$そしてエッジウェイトを追加します$w(u,v)$。 そこで、次の形式の遷移を考えます。$$dp[u][t] = \max(dp[u][t], dp[v][t-1] + w(u,v))$$このステップは、チェーンの長さを上向きに拡大するコアです。 
5. すべての下向き DP 値を計算した後、$u$、最高点を持つパスの答えを計算します。$u$。 このために、分割を検討します$k$ノードを 2 つの下向きチェーンに分割$u$。 1つのチェーンが使用する$t$ノードとその他の用途$k - t + 1$ノード、なぜなら$u$は 1 回としてカウントされます。 有効な分割をすべて試し、異なる子からの値を結合して、2 つの分岐が互いに素であることを確認します。 
6. グローバルな答えをすべてのノードの最大値として維持します$u$およびすべての有効な分割$k$2 つの下向きパスにわたるノード。 

正確さは、ツリー内の任意の単純なパスがルートに関して一意の最上位ノードを持っているという事実に依存します。 このノードはパスの 2 つの方向の合流点として機能するため、そのノードを処理するときにすべての有効なパスが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b, c = map(int, input().split())
    g[a].append((b, c))
    g[b].append((a, c))

NEG = -10**18

# dp[u][t] will be stored as a dict-like list (sparse optimization not applied here)
dp = [None] * (n + 1)

def dfs(u, p):
    # dp for current node
    cur = [NEG] * (k + 1)
    cur[1] = 0

    for v, w in g[u]:
        if v == p:
            continue
        child = dfs(v, u)

        # temporary array for merging child into cur
        new = cur[:]

        for t in range(2, k + 1):
            if child[t - 1] != NEG:
                new[t] = max(new[t], child[t - 1] + w)

        cur = new

    dp[u] = cur
    return cur

dp[1] = dfs(1, -1)

ans = 0

# combine two branches at each node
def reroot(u, p):
    global ans
    cur = dp[u]

    # single chain case already included in dp, but we still consider it
    ans = max(ans, cur[k])

    # try combining two children branches via dp tables
    child_vals = []

    for v, w in g[u]:
        if v == p:
            continue
        child_vals.append((v, w))

    # combine pairs of children
    m = len(child_vals)
    for i in range(m):
        v1, w1 = child_vals[i]
        for j in range(i + 1, m):
            v2, w2 = child_vals[j]

            c1 = dp[v1]
            c2 = dp[v2]

            for t1 in range(1, k + 1):
                if c1[t1] == NEG:
                    continue
                t2 = k - t1 + 1
                if 1 <= t2 <= k and c2[t2] != NEG:
                    ans = max(ans, c1[t1] + c2[t2] + w1 + w2)

    for v, w in g[u]:
        if v != p:
            reroot(v, u)

reroot(1, -1)

print(ans)
```DFS は、すべてのノードの下向きチェーン値を計算します。 主要な実装の詳細は、子を親に接続するエッジを考慮して子の寄与を 1 つずつシフトすることによって、各マージが DP テーブルを更新することです。 2 番目のトラバーサルでは、2 つの独立した子サブツリーを結合して完全なサブツリーを形成しようとします。$k$-node ノードを通過するパス。 

最もデリケートな部分はインデックス作成です。$t$子からのノードは、次のパスに寄与します。$t+1$このシフトを忘れると、正確性を損なう off-by-one エラーが発生します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、純粋に線形のツリーです。 この場合、すべての有効なパスが強制され、DP はインデックスを正しく配置して、同じ長さの連続したセグメントのみが配置されるようにする必要があります。$k$が考慮されます。 各ノードは単一の子コントリビューションのみを継承するため、アルゴリズムはこれを自然に処理し、誤った分岐の組み合わせは発生しません。 

もう 1 つのエッジ ケースは、最適なパスが存在する星型ツリーです。$k$ノードは中心を介して複数の葉を選択する必要があります。 センター ノードが独立した子コントリビューションを集約し、結合ステップによりサイズの合計が次の 2 つのブランチを選択できるため、DP はこれを正しく処理します。$k$、中心を通る有効な独立したパスが形成されることを保証します。
