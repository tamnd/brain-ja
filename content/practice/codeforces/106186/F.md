 ## 解決策
 ## 問題の理解

 からの数値の順列が与えられます。`1`に`n`。 タスクは、インデックスの順序付けられた選択肢をカウントすることです`i`そしてもう一つのインデックス`j`ここでの値は`j`ジャンプの長さとして使用でき、そのジャンプを行った後、`i`、そこで見つかった値は、開始値とジャンプ長の正確な合計です。 

つまり、位置の値が`j`は`x`、次のものが必要です。`a[i + x] = a[i] + x`位置`i + x`配列内に存在する必要があります。 答えは、そのような有効な選択肢の数です。`i`そして`j`。 

順列プロパティはキーの制限です。 からのすべての番号`1`に`n`は 1 回だけ出現するため、可能なすべてのジャンプ長さ`x`は、それが発生する位置が 1 つだけあります。 

と`n`まで`200000`、インデックスのすべてのペアをチェックするには、約`n² / 2`, これは最悪の場合でも約 200 億小切手になります。 これは、一般的な競技プログラミングの時間制限をはるかに超えています。 条件を線形時間でカウントできるものに変換する必要があります。 

主なエッジケースは、変換されたビュー内の有効なペアが必ずしも同じインデックスのペアであるとは限らないという事実から来ています。`(i, j)`発言より。 

例えば：```
5
3 4 1 2 5
```有効な答えは、`2`。 有効な元のペアの 1 つは、`(3, 3)`、 なぜなら`a[3] = 1`そして`a[4] = 2`、与える`1 + 1 = 2`。 インデックスが異なるペアのみをチェックする不用意なソリューションでは、このケースを見逃してしまいます。 

もう 1 つのエッジ ケースは、多くのインデックスが同じ変換された値を持つ場合です。 例えば：```
4
1 2 3 4
```答えは`6`。 配列がちょうど 1 ずつ増加するため、すべてのペアが機能し、すべてのインデックスが同じ値になります。`index - value`。 隣接する位置のみをカウントすると、誤って小さい答えが返されてしまいます。 

## アプローチ

 直接的な解決策は定義に従います。 考えられるすべてのインデックスのペアに対して`(i, j)`、ジャンプの長さを計算します`a[j]`、どうかを確認してください`i + a[j]`が配列内にあり、比較します`a[i + a[j]]`と`a[i] + a[j]`。 

これは、必要な条件を正確にテストするため、正しいです。 ただし、`n²`可能な順序ペア。 いつ`n = 200000`、これにより約 400 億の操作が作成されますが、これは不可能です。 

方程式を書き直すと、有益な観察が得られます。 させて：```
x = a[j]
q = i + x
```条件は次のようになります。```
a[q] = a[i] + x
```以来`q - i = x`、次のようになります。```
a[q] - a[i] = q - i
```並べ替え:```
q - a[q] = i - a[i]
```したがって、特別なジャンプ値を探す代わりに、同じ値を持つ位置のペアを数えるだけで済みます。`index - value`。 

同じ変換値を持つ位置の各ペアは、正確に 1 つの有効な元のペアに対応します。 ポジションの場合`p < q`満足する：```
p - a[p] = q - a[q]
```それから：```
a[q] - a[p] = q - p
```距離`q - p`間の数字です`1`そして`n`、配列は順列であるため、その数値は次のようにどこかに表示されます。`a[j]`。 それを選ぶのは`j`必要な元のペアを提供します。 

問題は、次の等しい値をグループ化することに帰着します。`index - value`そして各グループ内のペアの数を加算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | インデックス値の差によるグループ化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての位置を反復処理します。`i`そして値を計算します`i - a[i]`。 ステートメントでは位置をそのように記述するため、1 ベースのインデックスを使用します。 
2. 変換された各値が何回出現するかを保存します。 同じ変換値を持つ位置は、互いに有効なペアを形成できます。 
3. 変換後の値がすでに出現している場合`cnt`何度も繰り返しますが、新しい立場が形成されます`cnt`新しいペア。 追加`cnt`頻度を増やす前に答えを調べてください。 
4. 累積カウントを出力します。 

カウントが機能する理由は、位置を左から右に処理する場合、以前に出現した同じ変換値はすべて、現在のインデックスと有効なペアを形成する以前のインデックスであるためです。 

なぜ効果があるのか:

 変換では、必要な条件が正確に保持されます。 有効な元のペアは 2 つの位置を生成します`i`そして`i + a[j]`値が等しいを満たす`index - value`。 逆に、等しい 2 つの位置`index - value`それらの値の差に等しい距離があり、配列は順列であるため、その距離は何らかの配列値として存在します。 したがって、カウントされたすべてのペアは、元の問題からの 1 つだけの有効な選択肢に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    ans = 0

    for i, x in enumerate(a, start=1):
        key = i - x
        ans += freq.get(key, 0)
        freq[key] = freq.get(key, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```ループは、開始によって 1 から始まる位置を使用します。`enumerate`から`1`。 これにより、ゼロベースの Python インデックスと問題からの数学的位置の間の変換が回避されます。`freq`の各値を持つ以前の位置の数を格納します。`i - a[i]`。 同じ値が再び出現する場合、以前の出現ごとに 1 つの新しい有効なペアが作成されるため、現在の位置を挿入する前に現在の頻度を追加します。 

Python の整数は任意の精度であるため、ペアの数が 32 ビット整数の制限を超える可能性がある場合でも、答えには特別な処理は必要ありません。 

代数変換にはジャンプが配列内にとどまるという条件がすでに含まれているため、実装には境界チェックがありません。 カウントされたすべてのペアの 2 番目の位置は、置換における実際の位置です。 

## 実用的な例

 次のことを考慮してください。```
5
3 4 1 2 5
```変換された値は次のとおりです。 

| ポジション | 値 | 位置 - 値 | 現在の答え |
 | --- | --- | --- | --- |
 | 1 | 3 | -2 | 0 |
 | 2 | 4 | -2 | 1 |
 | 3 | 1 | 2 | 1 |
 | 4 | 2 | 2 | 2 |
 | 5 | 5 | 0 | 2 |

 グループは`{-2: 2}`、`{2: 2}`、 そして`{0: 1}`。 サイズ 2 の 2 つのグループがそれぞれ 1 つのペアを提供し、最終的な答えを出します。`2`。 

このトレースは、アルゴリズムがどの位置にジャンプ長が含まれるかを知る必要がないことを示しています。 順列プロパティはその接続を自動的に処理します。 

次に、次のことを考えてみましょう。```
4
1 2 3 4
```| ポジション | 値 | 位置 - 値 | 現在の答え |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 0 | 1 |
 | 3 | 3 | 0 | 3 |
 | 4 | 4 | 0 | 6 |

 すべての位置は同じ変換値を共有するため、すべてのペアがカウントされます。 結果は`4 * 3 / 2 = 6`。 

この例では、ソリューションが近くの位置だけをチェックするのではなく、大規模なグループを正しく処理することを検証します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各配列要素は 1 回処理され、各辞書演算は O(1) であることが期待されます。 |
 | スペース | O(n) | 最悪の場合、すべての位置が異なる変換値を持ちます。 |

 このソリューションは順列に対して 1 回のパスのみを実行するため、必要な制限を簡単に満たすことができます。`n = 200000`。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    ans = 0
    for i, x in enumerate(a, start=1):
        key = i - x
        ans += freq.get(key, 0)
        freq[key] = freq.get(key, 0) + 1

    sys.stdin = old_stdin
    return str(ans)

# provided sample
assert run("5\n3 4 1 2 5\n") == "2", "sample"

# minimum size
assert run("1\n1\n") == "0", "single element"

# all pairs are valid
assert run("5\n1 2 3 4 5\n") == "10", "increasing permutation"

# catches missing same-index cases
assert run("3\n2 1 3\n") == "1", "self jump case"

# many equal transformed values
assert run("6\n1 2 3 4 5 6\n") == "15", "all equal keys"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`0`| 最小サイズと可能なペアはありません |
 |`5 / 1 2 3 4 5`|`10`| すべてのペアは 1 つの変換されたグループに属します。 
|`3 / 2 1 3`|`1`| オリジナルのペア`i`そして`j`一致する可能性があります |
 |`6 / 1 2 3 4 5 6`|`15`| 大きな周波数グループのカウント |

 ## 特殊なケース

 この場合の場合:```
5
3 4 1 2 5
```アルゴリズムは変換された値を計算します。```
-2, -2, 2, 2, 0
```繰り返される値により 2 つのペアが作成されます。 これらは、元のペアの両方の部分として同じインデックスが使用される場合を含む、2 つの有効な元の選択肢に対応します。 

のために：```
4
1 2 3 4
```変換された値はすべてゼロです。 アルゴリズムは以前の出現回数を加算し続け、次の結果を生成します。```
0 + 1 + 2 + 3 = 6
```これにより、考えられるすべてのペアが 1 回だけカウントされます。 

変換された値が繰り返されない順列の場合、すべての周波数は 1 のままであるため、答えは 0 のままです。 以前のポジションが現在のポジションと一致することはないため、このようなケースは自然に処理されます。
