 ## 問題の理解

 与えられた正の整数の配列では、すべての数値が少数の固定素数セットからのみ構築されます。 言い換えれば、各値は、指定された素数が因数分解で何回出現するかによって完全に決定されます。 

インデックスの空でないサブセットについては、対応する要素の gcd を取得します。 その gcd 値を直接使用することはありません。 代わりに、繰り返される素数べき乗を削除し、少なくとも 1 回出現する素数のみを保持することで圧縮します。 これは平方のない部分であり、各素数は指数に関係なく最大 1 つのコピーに寄与することを意味します。 

タスクは、インデックスの空でないすべてのサブセットにわたってこの平方フリー値を合計し、結果のモジュロを出力することです。$10^9 + 7$。 

入力サイズにより、明示的なサブセット列挙ではなく、組み合わせビューが強制されます。 と$n$まで$10^5$サブセットの数が膨大であるため、サブセットを反復したり、サブセットのすべてのペアまたはタプルを直接処理したりするアプローチは、直ちに実行不可能になります。$2^n$。 平$O(n^2)$大きすぎます。 唯一実行可能な戦略は、共有構造特性、この場合は制限された素数空間内の gcd 構造によってサブセットをグループ化するものです。 

すべての数値が 1 の場合、微妙なエッジ ケースが現れます。すべてのサブセットの gcd は 1 で、1 の平方のない部分も 1 です。答えは単純です。$2^n - 1$これは、空の gcd 状態を一貫して処理しないため、単純な gcd 列挙では決して正しく計算されません。 

もう 1 つの特殊なケースは、サブセット内の要素に素数が含まれていないため、一部の素数がサブセットにとって無関係である場合です。 その場合、それらの素数は gcd には決して現れないため、正方形のない部分には何も寄与しません。 各素数がすべてのサブセットに独立して寄与していると仮定する単純な「すべてを組み合わせる」アプローチは、ここでは失敗します。これは、gcd 選択が加算的なプロセスではなくフィルター処理であるためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。空ではないすべてのサブセットを列挙し、その gcd を計算し、正方形のない部分を抽出して、それを答えに追加します。 サイズのサブセットに対する gcd の計算$k$費用$O(k)$、そして、あります$2^n$サブセットなので、合計の作業量は次のとおりです。$O(n \cdot 2^n)$。 たとえ$n = 25$、これが境界線になり、$10^5$それは全く不可能です。 gcd 値が大量に繰り返されるにもかかわらず、サブセットが独立して処理されるため、この失敗は非効率性だけではなく構造的なものです。 

重要な観察は、gcd の動作はどの要素が存在するかによってのみ依存しますが、より重要なのは、固定値の場合に依存するということです。$x$、「サブセットの gcd が で割り切れる」という条件$x$」は、値が の倍数であるインデックスに対するクリーンなカウント条件に変換されます。$x$。 これは標準的な反転ポイントです。サブセットを合計して gcd を導出する代わりに、視点を反転し、可能な gcd 値によってサブセットをグループ化します。 

すべての数字のみを使用するため、$m \le 20$素数の場合、各数値はその中に素数が現れるビットマスクとして表すことができます。 gcd の正方形のない部分は、サブセットに対するこれらのマスクのビット単位の AND です。 これにより、問題は次のようになります。マスクの AND のすべてのサブセットを合計します。 

これで構造がより明確になりました。 サブセットを明示的に追跡する代わりに、考えられる各 AND 結果マスクを生成するサブセットの数を数えます。 固定マスクの場合、すべての要素に少なくともこれらの素数が含まれるサブセットをカウントする必要があります。 これは、フィルタリングされた要素をカウントする標準的なサブセットになります。 

マスクごとに、そのマスクを「含む」配列要素の数を計算し、それらの要素の空でないすべてのサブセットは、その gcd がそれらの素数を失わない場合にのみ、候補 gcd マスクとしてそのマスクを提供します。 これを処理する標準的な方法は、スーパーセットをカウントする SOS DP スタイルを使用したマスクの包含/除外です。これは次の理由により実現可能です。$2^m \le 2^{20}$。

 ## アルゴリズムのチュートリアル

 各数値をビットマスクとしてエンコードします。$m$素数。 

1. それぞれについて$a_i$、どこにビットがあるかマスクを構築します$j$プライムの場合に設定されます$p_j$分割する$a_i$。 このマスクは、まさに数値の正方形を含まない表現です。 
2. 各マスクが配列内に出現する回数を数えます。 
3. すべてのマスクについて、そのマスクのスーパーセットを持つ配列要素の数を事前計算します。 これは、要素にマスクに必要なすべての素数が含まれていることを意味します。 これは、ビットマスク上のスーパーセット DP を使用して計算されます。 
4. 各マスクについて、有効な要素から形成される空でないサブセットの数は次のとおりです。$2^{cnt[mask]} - 1$。 これらのサブセットには、少なくともそのマスクを含む gcd-squarefree がありますが、スーパーセット間でオーバーカウントが発生します。 
5. 各サブセットがその真の gcd マスクに正確に関連付けられるように、マスクの格子に対して包含/除外を使用します (逆に SOS DP)。 
6. 各マスクに割り当てられたサブセットの数を乗算し、累積して答えを求めます。 

これが機能する主な理由は、指数空間の gcd が座標方向の最小値になり、自乗自由投影がそれを素数存在ベクトルのブール AND に変換するためです。 これにより、問題全体がブール格子上のサブセット畳み込みに変換されます。 

### なぜ効果があるのか

 すべてのサブセットは、その要素のマスクのビット単位の AND に対応します。 固定された結果のマスクの場合$M$、サブセットが寄与する$M$まさにそのすべての要素に少なくとも素数があるとき$M$、AND 中にこれらの素数を削除する要素はありません。 SOS DP は、各サブセットが正しい最小結果マスクに対して 1 回だけカウントされることを保証し、スーパーセット全体での過剰カウントを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    primes = list(map(int, input().split()))
    a = list(map(int, input().split()))

    # map each number to bitmask of primes
    idx = {p:i for i,p in enumerate(primes)}

    cnt = [0] * (1 << m)

    for x in a:
        mask = 0
        for i, p in enumerate(primes):
            if x % p == 0:
                mask |= (1 << i)
        cnt[mask] += 1

    # superset DP: for each mask, compute how many elements have superset mask
    sup = cnt[:]
    for i in range(m):
        for mask in range(1 << m):
            if mask & (1 << i):
                sup[mask ^ (1 << i)] += sup[mask]

    # f[mask] = number of non-empty subsets whose gcd mask is exactly mask
    f = [0] * (1 << m)

    for mask in range(1 << m):
        if sup[mask]:
            f[mask] = (pow(2, sup[mask], MOD) - 1) % MOD

    # inclusion-exclusion (zeta inversion over subset lattice)
    for i in range(m):
        for mask in range(1 << m):
            if mask & (1 << i):
                f[mask ^ (1 << i)] = (f[mask ^ (1 << i)] - f[mask]) % MOD

    ans = 0
    for mask in range(1 << m):
        # square-free value = product of primes in mask
        val = 1
        for i in range(m):
            if mask & (1 << i):
                val = (val * primes[i]) % MOD
        ans = (ans + val * f[mask]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装は自然に 3 つのフェーズに分割されます。数値をマスクにエンコードし、gcd サポートの下限として各マスクを実現できるサブセットの数を計算し、次にサブセット DP 反転によるオーバーカウントの修正です。 最もデリケートな部分は、反転ではブール格子に対する加算的な寄与が想定されるため、反転の前にサブセットのカウントが確実に行われるようにすることです。 

よくある実装の落とし穴は、「数の素数のスーパーセット」と「サブセットマスク関係」を混同し、DP の方向を反転させることです。 もう 1 つは、サブセット数が必要であることを忘れていることです。$2^k - 1$、 ない$2^k$空のサブセットは除外されるため。

 ## 特殊なケース

 すべての数値が 1 の場合、すべてのサブセットの gcd は 1 になり、正方形のない部分も 1 になります。マスク 0 のみがゼロ以外の周波数を持ち、すべてのサブセットがその状態に崩壊するため、アルゴリズムはこれを処理します。$2^n - 1$サブセットカウント後。 

すべての数値が単一の素数を共有する場合、その素数を除くすべてのマスクはゼロになるため、すべてのサブセットが同じマスクに寄与します。 スーパーセット DP はすべての要素を正しく集約し、反転するとアクティブなマスクが 1 つだけ残ります。 

マスクがすべて異なる単素数の値である場合、各サブセットの gcd は交差動作によって完全に決定されます。 SOS DP は、交差部分が単一の素数のままであるサブセットのみがそれに割り当てられるようにし、混合サブセットはマスク 0 に分類されます。
