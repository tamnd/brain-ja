 ## 解決策
 ## 問題の理解

 直線上に位置する複数の目的地があります$a_1,a_2,\dots,a_n$、すべて厳密にポジティブで明確です。 ルートは、これらの目的地の単純な並べ替えです。 観光客は位置 0 から開始し、選択された順序で目的地を訪れ、最後の目的地を訪れた後に停止します。 

ルートの場合$p_1,p_2,\dots,p_n$、移動距離は$$a_{p_1} + \sum_{i=2}^{n} |a_{p_i}-a_{p_{i-1}}|.$$課題は最適なルートを見つけることではありません。 すべての平均距離を計算する必要があります$n!$可能なルートを抽出し、その平均を既約分数として出力します。 

制約$n \le 10^5$順列の列挙を伴うものはすべて即座に除外されます。 平$n=15$すでに作るだろう$n!$絶望的に大きい。 すべてのルートにわたる各宛先ペアの寄与を集計する式が必要です。 

ポジションは次のように大きくすることができます$10^7$、最後の分子は次のようになります。$n^2 \cdot 10^7$したがって、64 ビット演算が必要です。 Python の整数はこれを自動的に処理します。 

微妙なエッジケースが現れるのは、$n=2$。 

入力：```
2
1 10
```2つのルートには長さがあります$10$そして$19$。 彼らの平均は$29/2$。 

ペアの遷移のみをカウントし、位置 0 からの最初の動きを忘れる不用意な解決策では、次のような問題が発生します。$9$、それは完全に間違っています。 

もう 1 つの簡単な間違いは、隣接する特定のペアを含む順列の数を数え間違えることです。 

入力：```
3
2 3 5
```ペア$(2,5)$ちょうど隣接して見える$2\cdot (n-1)! = 4$順列、全部ではない$6$。 この組み合わせ係数を間違えると、平均値が不正確になります。 

3 番目の落とし穴は、最後の分数を減らすのを忘れることです。 

入力：```
2
1 3
```平均距離は$(3+5)/2 = 4$したがって、正しい出力は次のようになります。```
4 1
```印刷`8 2`要件を満たさないことになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 宛先のすべての順列を生成し、そのルート長を計算し、すべてのルート長を合計して、次で割ります。$n!$。 

これが機能するのは、答えの定義が文字通りすべての順列の平均であるためです。 残念ながら、$n!$ルート。 のために$n=10^5$、番号を書き留めても$n!$すべての順列を繰り返すことはおろか、不可能です。 

重要な観察は、すべての順列の平均は、多くの場合、各コンポーネントの出現頻度を数えることによって計算できるということです。 

路線長は 2 種類の項から構成されます。 

第 1 項は 0 から最初に訪れた目的地までの距離です。 

残りの項は、順列における連続する目的地間の距離です。 

ルート全体について推論するのではなく、すべての順列にわたる各宛先と各宛先ペアの寄与をカウントします。 

開始位置では、すべての目的地が正確に最初に表示されます。$(n-1)!$順列。 したがって、スタートの合計貢献度は次のようになります。$$(n-1)! \sum a_i.$$連続した遷移の場合は、2 つの宛先を検討してください$x$そして$y$。 それらを隣り合わせる順列は何回ありますか?

 扱う$(x,y)$ブロックとして。 ブロックは 2 つの方法で注文できます。$n-2$私たちが持っている目的地$n-1$並べ替えるオブジェクト。 

したがって、カウントは次のようになります$$2\cdot (n-1)!.$$このような各順列が貢献します$|x-y|$。 

したがって、すべての隣接項の合計寄与度は次のようになります。$$2(n-1)! \sum_{i<j} |a_i-a_j|.$$両方の部分を組み合わせると、$$\text{Total over all permutations} = (n-1)! \left( \sum a_i + 2\sum_{i<j}|a_i-a_j| \right).$$で割る$n!$階乗をキャンセルします。$$\text{Average} = \frac{ \sum a_i + 2\sum_{i<j}|a_i-a_j| }{n}.$$さて、問題全体はコンピューティングに帰着します$$\sum_{i<j}|a_i-a_j|.$$位置を並べ替えると、すべての差が負ではなくなります。$$\sum_{i<j}(a_j-a_i).$$この古典的な量は、接頭辞の合計を使用して並べ替えた後、線形時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!\cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n\log n)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 位置を読み取り、並べ替えます。 

並べ替えを行うと、絶対値を通常の差に置き換えることができます。$i<j$、 我々は持っています$a_j \ge a_i$。 
2. すべてのポジションの合計を計算します。 

これは、組み合わせの単純化後の開始手の寄与です。 
3. コンピューティング$\sum_{i<j}(a_j-a_i)$。 

現在のプレフィックス合計を維持します。 

加工時$a_i$、以前のすべての値が寄与します$$a_i \cdot i - \text{prefix}.$$これは等しい$$\sum_{j<i}(a_i-a_j).$$4. しましょう$D$は、前のステップで取得したペアごとの差の合計になります。 
5. コンピューティング$$\text{numerator} = \sum a_i + 2D.$$平均は分子を次の値で割ったものです$n$。 
6. 分子と分母を最大公約数で割って分数を減らします。 
7. 換算された分子と分母を出力します。 

### なぜ効果があるのか

 すべてのルートの長さは、1 つの開始寄与と複数の隣接寄与の合計です。 すべての順列にわたって、各目的地が正確に最初に表示されます$(n-1)!$回、という用語を与える$\sum a_i$。 同様に、順序付けされていない宛先のペアはすべて正確に隣接します。$2(n-1)!$回、という用語を与える$2\sum_{i<j}|a_i-a_j|$。 

これらのカウントは正確であり、すべての順列におけるすべての距離の寄与を 1 回だけカバーします。 順列の総数で割った後$n!$、平均ルート長は次のようになります。$$\frac{\sum a_i + 2\sum_{i<j}|a_i-a_j|}{n}.$$sorted-prefix-sum の計算ではペアごとの差分合計が正確に評価されるため、アルゴリズムは近似を行わずに目的の平均を計算します。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    total_positions = sum(a)

    prefix = 0
    pair_sum = 0

    for i, x in enumerate(a):
        pair_sum += x * i - prefix
        prefix += x

    numerator = total_positions + 2 * pair_sum
    denominator = n

    g = gcd(numerator, denominator)

    print(numerator // g, denominator // g)

solve()
```最初のステップでは座標をソートします。 並べ替えると、すべてのペアの寄与は次のようになります。$a_j-a_i$の代わりに$|a_j-a_i|$、これにより集計が可能になります。 

変数`pair_sum`店$$\sum_{i<j}(a_j-a_i).$$現在値を処理する場合`x`インデックスで`i`、まさにあります`i`以前の要素。 彼らの貢献度の合計は、$$(x-a_0)+(x-a_1)+\cdots+(x-a_{i-1}),$$これを単純化すると`x * i - prefix`。 

最終的な式は、組み合わせカウント引数から直接得られます。$$\text{average} = \frac{\sum a_i + 2\,\text{pair\_sum}}{n}.$$階乗は計算されません。 これは問題を実現可能にする重要な単純化です。 

Python の任意精度の整数は、中間値が非常に大きくなった場合でもオーバーフローの問題を回避します。

## テストケース```python
import sys
import io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    a.sort()

    prefix = 0
    pair_sum = 0

    for i, x in enumerate(a):
        pair_sum += x * i - prefix
        prefix += x

    numerator = sum(a) + 2 * pair_sum
    denominator = n

    g = gcd(numerator, denominator)
    return f"{numerator // g} {denominator // g}"

# provided sample
assert run("3\n2 3 5\n") == "22 3", "sample 1"

# minimum n
assert run("2\n1 2\n") == "5 2", "minimum size"

# reducible fraction becoming integer
assert run("2\n1 3\n") == "4 1", "fraction reduction"

# unsorted input
assert run("3\n5 2 3\n") == "22 3", "sorting correctness"

# larger gaps
assert run("3\n1 10 20\n") == "79 3", "pairwise contribution"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のことを考慮してください。```
2
1 10
```ソート後のペアごとの差の合計は次のようになります。$9$。 式は次のようになります$$\frac{1+10+2\cdot 9}{2} = \frac{29}{2}.$$このアルゴリズムには、最初に訪問した目的地の寄与が正しく含まれています。 この用語を省略すると、誤って生成されます。$9$。 

考慮する：```
3
5 2 3
```並べ替えると配列は次のように変換されます。$[2,3,5]$。 ペアごとの合計は次のようになります$6$、生産$22/3$。 これにより、答えは入力内の順序ではなく、位置のみに依存することが確認されます。 

考慮する：```
2
1 3
```式は次のようになります$$\frac{1+3+2(2)}{2} = \frac{8}{2} = 4.$$gcd ステップにより、分数は次のように減算されます。`4 1`、出力が既約であるという要件を満たします。 

考慮する：```
4
1 2 3 10000000
```ペアごとの差の合計は非常に大きくなりますが、すべての計算は整数演算のままです。 Python は結果の値を安全に処理し、組み合わせ式は階乗サイズの数値を回避します。
