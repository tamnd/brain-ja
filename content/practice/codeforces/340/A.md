 ## 解決策
 ## 問題の理解

 特定の範囲内で Iahub と Floyd の両方によってペイントされたレンガの数を数えるように求められます。 レンガには 1 から始まる連続した整数が付けられます。Iahub はレンガ _x_ から始めて _x_ 番目のレンガごとにペイントしますが、Floyd はレンガ _y_ から始めて _y_ 番目のレンガごとにペイントします。 私たちは、_a_ と _b_ (両方を含む) の間の番号が付けられ、両方によって塗装されたレンガのみに興味があります。 

入力は、_x_、_y_、_a_、_b_ の 4 つの整数で構成されます。 出力は、両方によってペイントされたレンガの数を表す単一の整数です。 

制約により、_x_ と _y_ は最大 1000 であることがわかり、これらを直接ステップ サイズとして使用するアルゴリズムはどれも実行可能です。 範囲 [_a_, _b_] は最大 2・10⁹ までになる可能性があるため、区間全体にわたる総当たりシミュレーションは非現実的になります。 [_a_, _b_] 内のすべてのブリックに対する単純なループには、潜在的に 2·10⁹ の反復が必要になりますが、これは 1 秒の実行時間をはるかに超えています。 

_a_ が _x_ と _y_ の両方より小さい場合、エッジ ケースが発生します。 たとえば、_x_ = 5、_y_ = 7、_a_ = 1、_b_ = 10 の場合、[1, 10] に該当する 5 と 7 の最初の倍数を正しく含める必要があります。 不用意に床を分割したり丸めたりすると除外される可能性があります。 もう 1 つのエッジ ケースは、_x_ = 3、_y_ = 3、_a_ = 6、_b_ = 6 など、_a_ が _b_ に等しい場合です。アルゴリズムは、両方によってペイントされた単一のレンガを正確にカウントする必要があります。 

## アプローチ

 ブルートフォースアプローチを説明するのは簡単です。 _a_ から _b_ までの番号が付けられたすべてのレンガを反復処理します。 各ブリックについて、それが _x_ と _y_ の両方で割り切れるかどうかを確認します。 そうであれば、カウンターをインクリメントします。 これは正しいです。レンガの数が両方のステップ サイズで割り切れる場合にのみ、両方の方法でペイントされるからです。 このアプローチの問題は最悪のケースです。_b - a_ が 2·10⁹ 程度の場合、ループは数十億回の反復を実行することになり、これでは遅すぎます。 

最適なソリューションの重要な洞察は、レンガが _x_ と _y_ の最小公倍数 (LCM) の倍数である場合とその場合に限り、レンガがペイントされるということです。 LCM (たとえば _z_) がわかったら、問題は区間 [_a_, _b_] 内の _z_ の倍数を数えるということになります。 これは、各ブリックを反復処理することなく数学的に行うことができます。 範囲内の _z_ の倍数をカウントするには、_b_ までの倍数を計算し、厳密に _a_ より小さい倍数を引き、その差が [_a_, _b_] のカウントになります。 このアプローチでは、ブリックごとのシミュレーションが回避され、一定時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(b - a + 1) | お(1) | 大きな b-a には遅すぎる |
 | 最適 | O(log(max(x, y))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. _x_ と _y_ の最大公約数 (GCD) を計算します。 これは、LCM を効率的に計算するために必要です。 数式を使用する`LCM(x, y) = x * y // GCD(x, y)`乗算前に除算することで、整数のオーバーフローを確実に回避します。 
2. _x_ と _y_ の最小公倍数を計算します (これを _z_ と呼びます)。 レンガは、その数が _z_ の倍数である場合にのみ、両方の画家によって塗装されます。 
3. _b_ 以下の _z_ の倍数がいくつあるかを数えます。 これを行うのは、`b // z`。 
4. _a_ よりも厳密に小さい _z_ の倍数を数えます。 これを行うのは、`(a - 1) // z`。 これら 2 つのカウントを減算すると、[_a_, _b_] 内の _z_ の倍数が得られます。 
5. 結果を印刷します。 

不変条件は、区間 [_a_, _b_] 内の _z_ の倍数がすべて 1 回だけカウントされるということです。 間隔内の他の数値は _x_ と _y_ の両方の倍数ではないため、カウントは正確です。 このアルゴリズムは個々のレンガを検査する必要がないため、非常に広い範囲に対しても効率的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

x, y, a, b = map(int, input().split())

def lcm(u, v):
    return u * v // gcd(u, v)

z = lcm(x, y)
count = b // z - (a - 1) // z
print(count)
```最初の部分は入力を読み取り、`gcd`Python の数学ライブラリの関数。 の`lcm`関数は最小公倍数を効率的に計算します。 計算`b // z - (a - 1) // z`～の倍数を数える`z`_a_ 自体が倍数である場合は、_a_ を含めるように注意して、目的の範囲内に入力します。 引き算`(a - 1) // z`_a_ 自体が倍数である場合に過小カウントにならないようにします。

## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x, y, a, b = map(int, input().split())
    z = x * y // gcd(x, y)
    return str(b // z - (a - 1) // z)

# Provided sample
assert run("2 3 6 18\n") == "3", "sample 1"

# Custom cases
assert run("5 7 1 10\n") == "0", "no overlap"
assert run("3 3 6 6\n") == "1", "single brick"
assert run("1 1 1 1000000000\n") == "1000000000", "every brick"
assert run("2 3 1 1\n") == "0", "range below first multiple"
assert run("2 3 1 6\n") == "1", "include first multiple only"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 7 1 10 | 0 | 範囲内で両方がペイントしたレンガはありません。 
| 3 3 6 6 | 1 | 単一のブリックは倍数 | に等しい
 | 1 1 1 1000000000 | 1000000000 | すべてのレンガは両方によって塗装されました。 
| 2 3 1 1 | 0 | 最初の倍数より下の範囲 |
 | 2 3 1 6 | 1 | 境界に最初の倍数を含める |

 ## 特殊なケース

 範囲が最初の倍数よりも下で始まる場合、減算は`(a - 1) // z`過少カウントがないことを保証します。 たとえば、x = 2、y = 3、a = 1、b = 5、z = 6。倍数 ≤ b = 0、倍数 < a = 0、count = 0。_a_ 自体が a = 6、b = 6 などの倍数の場合、倍数 ≤ b = 1、倍数 < a = 0、count = 1 (レンガも正しく含まれます)。 このアルゴリズムは、算術カウント方式のおかげで、長さ 1 の範囲、倍数で始まる範囲、および大きな範囲を自然に処理します。
