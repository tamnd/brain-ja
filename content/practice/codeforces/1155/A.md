 ## 解決策
 ## 問題の理解

 英語の小文字で構成される単一の文字列が与えられます。 この文字列内の連続するセグメントを 1 つ選択し、そのセグメントを 1 回だけ反転することができます。 この 1 回の反転を実行すると、新しい文字列が得られます。 タスクは、結果の文字列を元の文字列よりも辞書編集的に小さくするような逆転が存在するかどうかを判断することです。 存在する場合は、有効なセグメントを出力する必要があります。 それ以外の場合は不可能であると報告します。 

ここでの辞書編集的な順序は、辞書の比較のように動作します。2 つの文字列が異なる最初の位置によって、どちらが小さいかが決まります。 これは、改善が文字列のできるだけ早い段階で現れる必要があり、より小さなプレフィックスが達成されれば、その後に何が起こっても無関係であることを意味します。 

文字列の長さは最大 300,000 になる可能性があるため、すべての部分文字列を試したり、各反転をシミュレートしたりするソリューションは非常に遅すぎます。 部分文字列に対する二次または三次スキャンには、最悪の場合でも 10¹⁰ 程度の操作が必要になりますが、これは 2 秒では実現できません。 これにより、エンドポイントのすべてのペアに対するブルート フォースが即座に排除されます。 

微妙な制約は、結果を最小化する必要はなく、辞書編集上の順序を改善する単一の反転を見つけるだけでよいということです。 これは、文字列の先頭付近に有益な不一致を生み出す可能性のあるローカル構造を探していることを強く示唆しています。 

単純な間違いは、文字列内の最小の文字を含むセグメントを常に反転する必要があると想定することです。 反転の効果は文字値だけではなく位置に依存するため、これは失敗します。 もう 1 つの失敗モードは、セグメントを反転して後の位置を改善しますが、前の位置を損なうことです。これは辞書編集的に役に立ちません。 

より具体的なエッジ状況は、改善を妨げる意味で文字列がすでに減少していない場合です。 たとえば、次のような文字列`aaaa`または`abcde`部分文字列を反転すると、文字列が変更されないままになるか、最初の文字が大きくなるかのどちらかであるため、反転によって改善することはできません。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのインデックスのペアを試してください。$l$そして$r$、その部分文字列を反転し、結果を元の文字列と比較します。 これは、許可されているすべての操作を調査し、辞書編集的な比較が決定的であるため、正しいです。 ただし、部分文字列を反転するには、$O(n)$時間もあるし$O(n^2)$選択肢、与えること$O(n^3)$全体的な複雑さ。 スライストリックを使用して反転を最適化したとしても、依然として次のような問題に直面します。$O(n^2)$比較は 300,000 文字には大きすぎます。 

重要な観察は、辞書編集上の改善は、文字を減らすことができた最も早いインデックスで決定されるということです。 反転は 1 回だけ許可されるため、初期の位置を変更する唯一の方法は、文字列の後ろにある小さい文字を前の位置に移動することです。 

ここで、反転が実際に何を行うかを考えてみましょう。選択したセグメントの接尾辞を取得し、それをそのセグメントの先頭に移動します。 したがって、ポジションを選択すると$l$そして$r$、位置の文字$r$位置に移動します$l$。 これは、右からの文字がセグメント内の最初の位置に影響を与えることができる唯一の方法です。 

したがって、問題はインデックスを見つけることに帰着します$l < r$そのような$s[r] < s[l]$。 逆にしたら$s[l..r]$、キャラクター$s[r]$所定の位置に移動します$l$、その位置を小さくし、索引で即座に辞書編集上の改善を保証します$l$、以前の位置はすべて変更されないためです。 

最初の改善点以降は何も考慮する必要さえありません。そのようなペアが見つかったら、答えは有効です。

 | 最適 |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 中心的なタスクは、反転によって後の小さい文字が前の大きい文字を置き換えることができる 2 つのインデックスを見つけることです。 

1. 考えられるすべてのインデックスのペアをスキャンします$(l, r)$と$l < r$。 各ペアについて、次のことを確認します。$s[r] < s[l]$。 この条件により、部分文字列を反転した後、$[l, r]$、位置の文字$l$以前よりも厳密に小さくなります。 
2. そのようなペアが見つかるとすぐに出力して停止します。 元の文字列が辞書編集的に変更される最初の位置はすぐに改善されるため、それ以上の検証は必要ありません。 
3. すべての可能性を調べた結果、そのようなペアが存在しない場合は、「NO」を出力します。 

正確かどうかは、辞書編集上の改善には最初の異なる位置を減らす必要があるという事実に依存します。 ポジションを下げる唯一の方法$l$1 回の反転を使用することは、より小さいキャラクターを後の位置から次の位置に持ってくることです。$l$、それはまさに次のときに起こります。$s[r] < s[l]$。 

### なぜ効果があるのか

 反転は順序を逆にすることでセグメントに影響を与えますが、新しい文字は導入されません。 辞書編集上の順序を改善する唯一の方法は、文字列が変更される可能性のある最も古いインデックスを減らすことです。 固定位置の場合$l$、置換できる唯一の文字$s[l]$1回の反転により、ポジションにあるものになります$r > l$に移動できます。$l$セグメントを選択して$[l, r]$。 そうでない場合$r$あらゆるもののために存在する$l$の場合、すべての接尾辞文字は、それより前の位置のすべての接頭辞文字以上になります。これは、文字列が減少せず、反転によって改善できないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

for l in range(n):
    for r in range(l + 1, n):
        if s[r] < s[l]:
            print("YES")
            print(l + 1, r + 1)
            sys.exit()

print("NO")
```このソリューションは、すべてのペアに対して直接スキャンを実行します。 最適な改善ではなく、有効な改善のみが必要なため、ネストされたループで十分です。 条件`s[r] < s[l]`反転により小さい文字が所定の位置に配置されるという要件を正確にエンコードします`l`。 

出力での 1 ベースのインデックスの使用は、問題ステートメントで必要とされるため、両方のインデックスに 1 を追加することで処理されます。 最初の有効なペアが見つかった後、プログラムはすぐに終了し、不必要な計算が続行されないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        # solution
        n = int(sys.stdin.readline())
        s = sys.stdin.readline().strip()
        for l in range(n):
            for r in range(l + 1, n):
                if s[r] < s[l]:
                    print("YES")
                    print(l + 1, r + 1)
                    return out.getvalue()
        print("NO")
    return out.getvalue()

# provided sample
assert run("7\nabacaba\n") == "YES\n2 5\n"

# all equal characters
assert run("5\naaaaa\n") == "NO\n"

# strictly increasing
assert run("5\nabcde\n") == "NO\n"

# simple improvement
assert run("3\ncba\n") == "YES\n1 2\n"

# edge minimum size
assert run("2\nba\n") == "YES\n1 2\n"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列に繰り返しの文字が含まれているが、厳密にそれ以降の小さい文字が含まれていない場合です。 例えば、`aabbaa`。 このアルゴリズムはすべてのペアをスキャンし、等しい文字のペアがあっても、等価であると辞書編集上の順序が改善されないため、それらは無視されます。 厳密に小さい文字が役立つ位置の後には表示されないため、出力は正しく「NO」になります。 

別のケースは、次のような減少する文字列です。`dcba`。 ここでは、最初の有効なペアがすぐに表示されます。$l = 1, r = 2$、 なぜなら`c < d`。 より長いセグメントを反転することもできますが、アルゴリズムは全体的な推論を必要とせずに最小限の証人を正しく見つけます。 

最後の微妙なケースは、改善は可能だが隣接していない場合です。`abdc`。 有効な動きは、$l = 2, r = 3$、 以来`b > d`は誤りですが、`d > b`逆方向にすると改善が得られます。 スキャンは最終的に見つけます`b`とペアになった`d`、チェックの局所性が最初の改善の機会を捉えるのに十分であることを確認します。
