 ## 解決策
 ## 問題の理解

 いくつかのイベント時間が与えられており、すでに昇順にソートされています。 Ivan は、定期的に鳴る目覚まし時計を設定したいと考えています。 最初の呼び出し音が 1 分に鳴ったら`y`、時計は時々鳴り続けます。`y, y + p, y + 2p, y + 3p, ...`開始時間`y`任意の整数を指定できますが、ピリオドは`p`許可される期間の指定されたリストから選択する必要があります。 

私たちの仕事は、すべてのイベント時間が呼び出し音シーケンスに属するような許容期間が存在するかどうかを判断することです。 そのような期間が存在する場合は、有効な開始分と選択した期間のインデックスを出力する必要があります。 

制約は、解が線形に近い必要があることを直ちに示唆します。 両方`n`そして`m`到達できる`3·10^5`したがって、すべてのイベントをすべての期間に対してチェックするアルゴリズムでは、約`9·10^10`最悪の場合の操作は完全に不可能です。 

イベントの時間と期間は次のとおりです。`10^18`。 これにより、値によってインデックス付けされた配列や呼び出しプロセスのシミュレーションに依存するアプローチは除外されます。 純粋に算術プロパティを操作する必要があります。 

微妙な点は、イベント時間ではない追加の時間にアラームが鳴る可能性があることです。 すべてのイベント時間が呼び出し音の中に含まれることだけを要求します。 この区別は非常に重要です。 

考慮する：```
x = [3, 12, 18]
p = 3
```から始まる呼び出し音シーケンス`3`は：```
3, 6, 9, 12, 15, 18, ...
```余分な音が鳴るのは、`6`、`9`、 そして`15`完全に受け入れられます。 

もう 1 つの簡単な間違いは、連続した差異のみに注目することです。 

例：```
x = [1, 7, 13]
```違いは次のとおりです。```
6, 6
```の期間`6`動作します。 

ただし、次の場合:```
x = [1, 7, 19]
```違いは次のとおりです。```
6, 12
```の期間`6`すべてのイベント時間が一致するモジュロであるため、まだ機能します`6`。 

重要な対象は個人差ではなく、その最大公約数です。 

最後のエッジ ケースは、必要な構造を分割する許可されたピリオドがない場合に発生します。 

例：```
x = [1, 7, 13]
allowed periods = [4, 5]
```すべてのイベント時間は合同モジュロです`6`、しかしどちらでもない`4`または`5`それらはすべて生成できるので、答えは次のとおりです。`NO`。 

## アプローチ

 最も直接的なアイデアは、許可されたすべての期間を試してみることです。 選択した期間について`p`、すべてのイベント時間が同じ剰余クラスのモジュロに属しているかどうかを確認できます。`p`。 

すべてのイベントが次の条件を満たす場合:```
xi ≡ x1 (mod p)
```それから選択する`y = x1`動作します。 

すべての呼び出し時間が生成されるため、このテストは正しいです。`x1`ピリオド付き`p`同じ剰余モジュロを持ちます`p`。 

問題はコストです。 まであります`3·10^5`候補期間以降`3·10^5`イベントの時間。 すべてのペアをテストするには以下が必要です。```
O(nm)
```操作が大きすぎます。 

重要な観察は、合同条件を書き直すことで得られます。 

すべてのイベント時間が次を満たす必要がある場合:```
xi ≡ x1 (mod p)
```それから：```
p | (xi - x1)
```あらゆる人にとって`i`。 

コレクション内のすべての値を除算する数値は、その最大公約数を除算する必要があります。 させて```
g = gcd(x2 - x1, x3 - x1, ..., xn - x1)
```したがって、有効な期間は分割する必要があります`g`。 

これにより問題は完全に変わります。 

すべてのイベントをすべての期間に対してテストする代わりに、最初に単一の数値を計算します。`g`。 次に、許容される期間分割があるかどうかを確認するだけで済みます。`g`。 

許可された期間であれば`pj`を満たす:```
g % pj == 0
```それからあらゆる違い`(xi - x1)`で割り切れます`pj`、すべてのイベント時間が一致するモジュロであることを意味します`pj`。 選択:```
y = x1
```すぐに機能します。 

これにより、問題は 1 回の gcd 計算後の線形スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. イベント時間と許可期間を読んでください。 
2. 以下を計算します。```
g = gcd(x2 - x1, x3 - x1, ..., xn - x1)
```これにより、イベント時間によって課されるすべての割り算制約が捕捉されます。 
3. 許可された期間を入力順序で繰り返します。 
4. 各期間ごと`pj`、次のことを確認します。```
g % pj == 0
```これが当てはまるなら、`pj`あらゆる違いを分割します`(xi - x1)`。 
5. そのような期間が見つかるとすぐに、次のように出力します。```
YES
x1 j
```どこ`j`期間の 1 から始まるインデックスです。 
6. 許可された期間分割がない場合`g`、出力:```
NO
```### なぜ効果があるのか

 しましょう```
g = gcd(x2 - x1, ..., xn - x1).
```期間の場合`p`が有効な場合、すべてのイベント時間は次の条件を満たす必要があります。```
xi ≡ x1 (mod p).
```同様に、```
p | (xi - x1)
```あらゆる人にとって`i`。 

以来`p`すべての差を除算すると、gcd を除算する必要があります`g`。 

逆に、許可された期間であれば、`p`分割する`g`、その後、すべての差を除算します`(xi - x1)`。 したがって、次のようになります。```
xi ≡ x1 (mod p)
```みんなのために`i`。 

選択する`y = x1`すべてのイベント時間を含む呼び出しシーケンスを生成します。 したがって、条件は`p | g`必要かつ十分です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))
    p = list(map(int, input().split()))

    g = 0
    for i in range(1, n):
        g = gcd(g, x[i] - x[0])

    for idx, period in enumerate(p, start=1):
        if g % period == 0:
            print("YES")
            print(x[0], idx)
            return

    print("NO")

solve()
```最初の部分では、最初のイベントに対するすべての差の gcd を計算します。 初期化中`g`ゼロを使​​用すると次の理由で便利です。```
gcd(0, a) = a
```したがって、最初の差が自動的に開始値になります。 

2 番目のループでは、許可された期間をスキャンします。 約数となる瞬間`g`が見つかった場合、答えはわかっているので、すぐに終了できます。 

使用する`x[0]`すべてのイベント時間は選択した期間を法とした同じ剰余を持つため、開始時間で十分です。 検索はありません`y`必要です。 

Python の整数は最大の値を処理します`10^18`オーバーフローの心配なし。

import io
from math import gcd

def run(inp: str) -> str:

    input = sys.stdin.readline

    x = list(map(int, input().split()))
    p = list(map(int, input().split()))

    g = 0

        g = gcd(g, x[i] - x[0])

    for idx, period in enumerate(p, start=1):

 ## 特殊なケース

 次のことを考慮してください。```
3 2
1 7 19
6 12
```違いは次のとおりです。`6`そして`18`、与える:```
g = 6
```アルゴリズムチェック期間`6`そしてそれを受け入れます。 よくある間違いは、連続するすべての差が選択した期間と等しいことを要求することです。 ここでは差は等しくありませんが、それでも一定期間は`6`すべてのイベント時間が同じ剰余モジュロを共有するため、これは完全に有効です`6`。 

考慮する：```
3 2
1 7 13
4 5
```以下を取得します。```
g = 6
```どちらでもない`4`または`5`分割する`6`したがって、アルゴリズムは次のように出力します。`NO`。 これは、イベント構造では有効な期間が認められているが、許可されているオプションのどれも有効な期間を提供していない状況に対処します。 

考慮する：```
2 3
10 25
3 5 15
```gcd は次のとおりです。```
g = 15
```アルゴリズムは次のことを発見しました`3`分割する`15`そして出力:```
YES

```一部のソリューションでは、誤って完全な差異の一致を検索し、のみを受け入れます。`15`。 すべてのイベント時間はその除数を法として一致するため、gcd のどの除数も有効です。
