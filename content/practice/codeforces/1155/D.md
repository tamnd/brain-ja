 ## 解決策
 ## 問題の理解

 We are given a sequence of integers and allowed to optionally pick exactly one contiguous segment and multiply every element inside it by a fixed value`x`。 これを行った後、結果の配列のすべての連続する部分配列を調べ、それらの部分配列の可能な最大の合計を取得します。ここで、合計が 0 である空の部分配列を選択することもできます。 

The task is to choose the modified segment, or choose to do nothing, in a way that makes the best possible subarray sum as large as possible.

 制約`n ≤ 3 · 10^5`可能なすべての部分配列を乗算に試すような解決策は直ちに除外されます。 各選択肢の最大部分配列合計を再計算する 3 次または 2 次のアプローチには、最大で約`10^10`最悪の場合、許容される 2 秒をはるかに超えて操作が行われなくなる可能性があります。 これにより、各位置が一定時間で処理される線形または線形に近い動的プログラミング ソリューションが強制されます。 

微妙な問題は、変更後の最適なサブアレイが変更されたセグメントと明らかに一致しない可能性があることです。 最適な部分配列は、乗算されたセグメントの前で開始することも、その後で終了することも、完全にセグメント内に存在することもできます。 「最適な部分配列を選択してから、それを乗算するかどうかを決定する」などの素朴な貪欲なアイデアは失敗します。最適な部分配列は乗算自体に依存するためです。 

もう 1 つのよくある失敗例は、合計にプラスの影響を与えるセグメントを常に乗算する必要があると想定していることです。 もし`x`が負またはゼロの場合、乗算により以前の正の寄与が破壊される可能性があるため、決定は局所的に選択するのではなく、全体的に最適化する必要があります。 

## アプローチ

 強引なアイデアは簡単です。考えられるすべてのセグメントを試してください。`[l, r]`Kadane のアルゴリズムを使用して、乗算し、配列をシミュレートし、部分配列の最大合計を計算します。 1 つの構成コストで Kadane を計算する`O(n)`、そして、あります`O(n^2)`～の選択肢`[l, r]`、につながる`O(n^3)`総仕事量。 前処理のトリックを使用したとしても、すべてのセグメントを列挙するだけではすでに実行不可能になります。 

重要な観察は、問題の構造が依然として基本的に 1 次元であり、連続的であるということです。 すべてのインデックスにおいて、乗算されたセグメント内でその演算が現在使用されていないのか、それとも既に使用が終了しているのかを知る必要があるだけです。 これにより、問題は Kadane のアルゴリズムに似た 3 状態動的計画法システムに変換されますが、「1 回の変換フェーズ」が拡張されています。 

最初にセグメントを選択することを考える代わりに、配列を左から右に処理し、次の 3 つの条件下で各位置で終わる可能な限り最良の部分配列の合計を維持します。乗算がまだ使用されていない、現在乗算されたセグメント内にある、乗算がすでに終了している。 これにより、セグメントの列挙が完全に回避されます。これは、考えられるすべてのセグメントが、「アクティブな乗算」状態への遷移とそこからの遷移の 1 回に正確に対応するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適な DP (3 つの状態) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列をスキャンしている間、3 つの実行値を維持します。 

1 つ目は、乗算演算をまだ使用していないときの、現在の位置で終了する最適な部分配列の合計を表します。 

2 番目は、乗算されたセグメント内での現在の位置で終わる最良の部分配列の合計を表します。 

3 番目は、乗算セグメントがすでに終了した後の現在の位置で終了する最良のサブ配列合計を表します。 

また、ベースライン候補としてゼロを保持することにより、空の部分配列を暗黙的に許可します。 

### ステップ

 1. 最初の要素で 3 つの状態を初期化します。 「操作なし」状態は、新たに開始するか、要素のみを取得するかのいずれかです。 「内部操作」状態は、要素に次の要素を乗算したものです。`x`。 「操作後」状態は、要素自体として開始されます。 
2. 次の要素ごとに、前の非操作サブ配列を拡張するか、現在の要素から新たに開始することによって、「操作なし」状態を更新します。 これは、変更が適用される前の標準的な Kadane のロジックを反映しています。 
3. 3 つの可能な方法で「内部操作」状態を更新します。 現在の要素で正確に演算を開始したり、演算のない部分配列からその要素に移行したり、以前に乗算されたセグメントから乗算を継続したりすることができます。 各オプションは、乗算されたセグメントの開始位置の選択に対応します。 
4. 3 つの可能な方法で「操作後」の状態を更新します。 後処理部分配列を続行することも、1 ステップ前に乗算を終了して通常どおり拡張することも、現在の位置で新しい後処理部分配列を開始することもできます。 
5. 3 つの状態すべておよびすべてのポジションにわたって見られる最高の値を追跡します。 

### なぜ効果があるのか

 すべてのインデックスで、各状態は、乗算セグメントが使用されているかどうかに関する正確な制約の下で、そのインデックスで終了する部分配列の可能な限り最良の合計を表します。 単一の連続する乗算セグメントのすべての有効な選択は、まさに 1 つの遷移シーケンス、つまり「内部操作」状態に入るポイントと、その後の状態から抜けるポイントに対応します。 このようなすべての遷移が考慮され、各状態は常に現在のインデックスで終わる最適な部分構造を格納するため、有効な構成が見逃されることも、無効な構成がカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    NEG = -10**30

    dp0 = 0
    dp1 = NEG
    dp2 = NEG

    ans = 0

    for v in a:
        ndp0 = max(0, dp0 + v)

        ndp1 = max(v * x,
                   dp1 + v * x,
                   dp0 + v * x)

        ndp2 = max(v,
                   dp2 + v,
                   dp1 + v)

        dp0, dp1, dp2 = ndp0, ndp1, ndp2

        ans = max(ans, dp0, dp1, dp2)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、DP を配列ではなくローリング変数に圧縮します。`dp0`演算を使用せずに、ここで終了する最良の部分配列合計を追跡します。`dp1`乗算されたセグメント内にあるトラック、および`dp2`トラックはその後にあります。 トランジションは、フェーズを開始、延長、または切り替えるかどうかを直接エンコードします。 変数`ans`配列が終了する前に最適なサブ配列が終了する場合も含め、任意の位置で最良の値を確実に取得します。 

大きな負の定数を使用すると、状態がまだ初期化されていないときに無効な遷移が優勢になるのを防ぎます。 空のサブ配列が許可され、負の合計と競合する必要があるため、ゼロ ベースラインは必須です。

    import sys
    input = sys.stdin.readline

    a = list(map(int, input().split()))

    NEG = -10**30

    dp0 = 0
    dp1 = NEG
    dp2 = NEG

    for v in a:

 ## 特殊なケース

 重要なエッジケースは、すべての要素が負の場合です。 明示的なゼロのベースラインを持たない貪欲な Kadane バリアントは誤って負の数値を返しますが、空のサブ配列オプションにより正しい答えはゼロになります。 DP は明示的にゼロを転送するため、アルゴリズムが有害なサブ配列にコミットすることはありません。 

もう一つの微妙なケースは次のような場合です。`x`は負の値であり、以前は不良だったセグメントが有益になる可能性があります。 スリーステート DP はこれを自然に処理します。乗算ステートへの移行はどのインデックスでも常に許可されているため、アルゴリズムは単純な「正のゲインのみ」のヒューリスティックでは決して選択されない最適なセグメントを発見できます。 

最後のエッジ ケースは、最適解が乗算をまったく使用しない場合に発生します。 これは次の事実によって処理されます。`dp0`は常にグローバル最大値で直接競合するため、有害な場合にはアルゴリズムが操作を完全に無視できるようになります。
