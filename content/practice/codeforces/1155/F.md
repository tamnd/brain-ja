 ## 解決策
 ## 問題の理解

 すでに 2 辺が接続されている単純な無向グラフが与えられています。 メンガーの定理によれば、これは頂点のすべてのペアがそれらの間に 2 つのエッジの切り離されたパスを持つことを意味します。これはまさに 2 つの配送会社が要求する条件です。 

政府は、その性質を維持しながら、できるだけ多くの道路を削除したいと考えています。 誘導グラフが依然として 2 エッジ接続されている元のエッジの可能な限り最小のサブセットを出力する必要があります。 

グラフが小さいですね。 頂点の数は最大 14 個ですが、エッジの数は完全なグラフと同じくらい多くなることがあります。 頂点が 14 個あるグラフには、最大でも$2^{14}=16384$頂点サブセット。ビットマスク動的プログラミング ソリューションを強く示唆しています。 一方、エッジ サブセットの数は次のように大きくなる可能性があります。$2^{91}$したがって、エッジを直接検索するアプローチは絶望的です。 

主な問題は、2 エッジ接続がグローバルなプロパティであることです。 スパニング ツリーは接続されていますが、ツリーのすべてのエッジがブリッジであるため、2 つのエッジ接続からは可能な限り離れています。 接続を追跡するだけの単純な DP では、非常に多くの情報が失われます。 

よくある間違いは、新しく追加されたすべての頂点が、現在のソリューション内で直ちに次数 2 以上を持たなければならないと考えることです。 考慮する：```
1 -- 2 -- 3 -- 4
 \___________/
```最終的なグラフはサイクルであり、2 つのエッジが接続されていますが、作成中に、まだ接続されていない頂点が一時的に 2 回導入される場合があります。 

もう 1 つの落とし穴は、最適な答えが常にすべての頂点を通る 1 つのサイクルであると仮定していることです。 元のグラフにハミルトニアン サイクルが含まれていない場合、最小の 2 エッジ接続スパニング サブグラフには、$n$エッジ。 

例えば：```
1-2-3
|   |
4---5
```適切な追加エッジを使用して、元のグラフの 2 エッジ接続を保証します。 最適に保存されたサブグラフは、必ずしも単純なサイクルであるとは限りません。 

の小さな値$n$が本当の手がかりです。 2 エッジ接続性をサブセット DP に変換する構造特性評価が必要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 エッジのすべてのサブセットを列挙し、それがすべての頂点にまたがっており、2 つのエッジ接続が維持されているかどうかをテストし、最小の有効なサブセットを保持します。 

候補グラフのテストはブリッジ検索を使用すれば簡単ですが、検索空間はそうではありません。 たとえ$m=40$、 がある$2^{40}$エッジサブセット。 ここでの最悪のケースは、$m=91$、まったく手の届かないところにあります。 

このブレークスルーは古典的な定理から来ています。つまり、すべての 2 辺が接続されたグラフは耳の分解を許容します。 単一の頂点から始めて、繰り返し「耳」を追加します。 耳は、2 つのエッジによって既存のグラフに接続された 1 つの新しい頂点、または内部頂点が新しく、2 つの端点がすでに構築された部分に接続されているパスのいずれかです。 

その説明は、受け入れられた解決策とほぼ完全に一致します。 

すでに頂点セットを構築していると仮定します。$S$。 耳は次のことを追加できます。 

1. 1 つの頂点$u\notin S$少なくとも2人の隣人がいる$S$。 
2. 内部の頂点がすべて外側にあるパス$S$、両方のエンドポイントには隣接するエンドポイントがありますが、$S$。 

各耳は既知の数のエッジに寄与します。 以来$n\le14$、頂点サブセット上の DP を使用して、最適な耳の分解を再構築できます。 

残りのタスクは、候補となる耳を効率的に列挙することです。 なぜなら$n$が小さい場合、頂点セットによってすべての単純なパスを事前計算します。 これにより、DP は 1 回の遷移でパス全体を接続できるようになります。 

結果として生じる複雑さはおおよそ次のようになります$O(3^n)$、これは簡単に実現可能です$n=14$。 承認された提出物で使用されるソリューションは、まさにこの戦略に従っています。

 ## アルゴリズムのチュートリアル

 ### 事前計算

 頂点ごとに$i$すべてのサブセット マスクについて、次を計算します。$$\text{vtomask}[i][mask]$$これは隣接するものの数を数えます$i$に属する`mask`。 

これにより、現在構築されているパーツに頂点をアタッチできるかどうかを即座に確認できます。 

単純なパスも事前計算します。 

させて`road[mask][u][v]`からの 1 つの単純なパスを保存します$u$に$v$頂点セットが正確に`mask`。 

単一の頂点から開始して、一度に 1 つの頂点ずつパスを拡張します。 

### DP 状態

 しましょう:$$dp[mask]$$頂点セットが正確に一致する有効な部分耳分解を構築するために必要なエッジの最小数になります。`mask`。 

頂点 0 を開始頂点として固定します。 

最初に:$$dp[1<<0]=0.$$### トランジション

 1. 新しい頂点を 1 つ追加します$u$。 

もし$u\notin mask$そして$u$すでに少なくとも 2 つの隣人が内部にいます`mask`、その後、追加してもよいでしょう$u$1つの頂点の耳として。 

コストの増加: 2.
 2. パスの耳を追加します。 

2 つの頂点を選択してください$u,v\notin mask$。 

内部頂点が外部にある単純なパスを見つける`mask`。 

その頂点セットを次のようにします`tmask`。 

もし$u$に隣人がいます`mask`そして$v$に隣人がいます`mask`、パスを既存のグラフに接続し直すことができます。 

を含むパス$L$頂点が寄与する$L-1$内部エッジに加えて 2 つの取り付けエッジ。 

合計増加量:$$(L-1)+2=L+1.$$これはまさに、受け入れられたソリューションで使用される遷移です。 
3. 宛先の状態を緩和します。$$dp[mask\cup tmask].$$### 再建

 すべての DP 更新について、以下を保存します。 

- 前のマスク、
 - 選択したエンドポイント$u$、
 - 選択したエンドポイント$v$（または$-1$1 つの頂点の耳の場合)。 

完全なマスクに到達した後、保存されているトランジションを逆方向に進み、選択した耳に使用されているすべてのエッジを出力します。 

### なぜ効果があるのか

 Ear 分解は、2 エッジ接続グラフのクラスを正確に特徴付けます。 すべての有効な解は、1 つの頂点から始まる一連の耳として記述することができます。 逆に、DP によって生成されるすべてのグラフは、有効な耳を繰り返し接続することによって取得されるため、2 エッジ接続されます。 

DP は、内部頂点が新しい、考えられるすべての耳を考慮します。 すべての耳分解は、新しく導入された頂点が 1 回だけ出現するように順序付けできるため、すべての最適解は DP 遷移のあるシーケンスに対応します。 

DP はそのようなシーケンスすべてのエッジの総数を最小化するため、最終状態では最小サイズの 2 エッジ接続のスパニング サブグラフが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 9

def solve():
    n, m = map(int, input().split())

    g = [[0] * n for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u][v] = g[v][u] = 1

    N = 1 << n

    vtomask = [[0] * N for _ in range(n)]
    for i in range(n):
        for mask in range(N):
            c = 0
            mm = mask
            while mm:
                b = mm & -mm
                j = b.bit_length() - 1
                if g[i][j]:
                    c += 1
                mm ^= b
            vtomask[i][mask] = c

    road = [[[None for _ in range(n)] for _ in range(n)] for _ in range(N)]

    for i in range(n):
        road[1 << i][i][i] = [i]

    for mask in range(N):
        for u in range(n):
            for v in range(n):
                p = road[mask][u][v]
                if p is None:
                    continue

                for z in range(n):
                    if (mask >> z) & 1:
                        continue
                    if not g[v][z]:
                        continue

                    nmask = mask | (1 << z)
                    if road[nmask][u][z] is not None:
                        continue

                    road[nmask][u][z] = p + [z]

    dp = [INF] * N
    pre_mask = [-1] * N
    pre_u = [-1] * N
    pre_v = [-2] * N

    dp[1] = 0

    for mask in range(1, N):
        if dp[mask] >= INF:
            continue

        for u in range(n):
            if (mask >> u) & 1:
                continue

            if vtomask[u][mask] >= 2:
                nmask = mask | (1 << u)
                nd = dp[mask] + 2
                if nd < dp[nmask]:
                    dp[nmask] = nd
                    pre_mask[nmask] = mask
                    pre_u[nmask] = u
                    pre_v[nmask] = -1

            if vtomask[u][mask] == 0:
                continue

            for v in range(u + 1, n):
                if (mask >> v) & 1:
                    continue
                if vtomask[v][mask] == 0:
                    continue

                amask = (N - 1) ^ mask ^ (1 << u) ^ (1 << v)

                smask = amask
                while True:
                    tmask = smask | (1 << u) | (1 << v)

                    path = road[tmask][u][v]
                    if path is not None:
                        nmask = mask | tmask
                        nd = dp[mask] + len(path) + 1

                        if nd < dp[nmask]:
                            dp[nmask] = nd
                            pre_mask[nmask] = mask
                            pre_u[nmask] = u
                            pre_v[nmask] = v

                    if smask == 0:
                        break
                    smask = (smask - 1) & amask

    full = N - 1
    print(dp[full])

    ans = []

    mask = full
    while mask != 1:
        pmask = pre_mask[mask]
        u = pre_u[mask]
        v = pre_v[mask]

        if v == -1:
            need = 2
            for x in range(n):
                if need and ((pmask >> x) & 1) and g[u][x]:
                    ans.append((u + 1, x + 1))
                    need -= 1
        else:
            tmask = mask ^ pmask
            path = road[tmask][u][v]

            for i in range(1, len(path)):
                ans.append((path[i - 1] + 1, path[i] + 1))

            for x in range(n):
                if ((pmask >> x) & 1) and g[u][x]:
                    ans.append((x + 1, u + 1))
                    break

            for x in range(n):
                if ((pmask >> x) & 1) and g[v][x]:
                    ans.append((x + 1, v + 1))
                    break

        mask = pmask

    for u, v in ans:
        print(u, v)

solve()
```パスの事前計算は、実装の中で最も特殊な部分です。`road[mask][u][v]`頂点が正確に一致する 1 つの単純なパスを保存します。`mask`。 以来$n$は 14 だけなので、サブセットごとにパスを保存することは可能です。 

民進党は橋について直接論じることは決してない。 代わりに、完全に耳の分解トランジションを通じて機能します。 それは、難しいグラフのプロパティをサブセット DP に還元する構造的な洞察です。 

再構築中に、コードは各耳によって提供された正確なエッジを再作成します。 パス イヤーは、その内部パス エッジに加えて、各エンドポイントの 1 つのアタッチメント エッジを提供します。 単一の頂点の耳は 2 つの取り付けエッジに寄与します。
