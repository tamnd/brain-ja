 ## 解決策
 ## 問題の理解

 私たちには出来事のタイムラインが与えられています。 Hiasat のプロフィールには常に 1 つのハンドルが表示されており、入力でマークされた特定の瞬間にのみこのハンドルを変更できます。 変更するまでの間、ハンドルは固定されたままになります。 

このタイムラインに沿って、複数の友人が存在し、それぞれが別個の小文字の文字列によって識別されます。 各友人は、「訪問」タイプの特定のイベントに複数回登場します。 友人は、訪問するあらゆる瞬間に、目に見えるハンドルが自分の名前と正確に一致する場合にのみ幸せになります。 

課題は、どの友達を幸せにするかを決めることです。 Hiasat は、許可された変更の瞬間ごとにどのハンドルを設定するかを自由に選択できます。目標は、長期にわたって一貫したハンドルの選択の下で満足する友人の数を最大化することです。 

構造は基本的に「変化点」で区切られたタイムラインです。 連続するタイプ 1 イベント間の各セグメントには、単一の固定ハンドルがあります。 すべての訪問イベントでは、現在のセグメントで選択されたハンドルが訪問する友人の名前と一致するかどうかがチェックされます。 

m ≤ 40 という制約が重要な構造シグナルです。 これは、別個の友人名の数が少ないことを意味するため、線形スキャンを超えた n への依存を回避する限り、m への指数関数的な依存は許容されます。 

各セグメントが個別に最適化できると仮定すると、素朴だが重要な落とし穴が発生します。 これは、友人が複数のセグメントにまたがって訪問する可能性があり、すべての訪問にわたる一貫性が必要であるため、失敗します。 

たとえば、友人の「alice」がセグメント 1 とセグメント 3 には出現するが、セグメント 2 には出現しない場合、セグメント 1 とセグメント 3 で「alice」を選択するのは問題ありませんが、セグメント 2 の選択は他の友人によって制限されます。 セグメントごとの割り当てを貪欲に行うと、グローバルな一貫性が簡単に損なわれる可能性があります。 

別の微妙な失敗モードは、複数の友人が同じセグメントに出現するときに発生します。 各セグメントで最も頻繁に友人を選択しても、グローバルに満足する友人の数を最大化することは保証されません。友人は、ローカルだけでなく、出現するすべてのセグメントで一致する必要があるためです。 

## アプローチ

 強引な見方は、各友人が「幸せになるように選ばれた」かどうかのどちらかであると考えることから始まります。 友達のサブセットを修正する場合は、選択したすべての友達が表示されるすべてのセグメントにわたって一貫性があるように、各セグメントにハンドルを割り当てることが可能かどうかを確認する必要があります。 

固定サブセットの場合、実現可能性チェックは、すべてのセグメントで、選択した友人に属するすべての訪問が単一の必要なハンドルに一致するかどうかを検証することに帰着します。 セグメントに選択された 2 つの異なる名前が含まれている場合、そのサブセットは無効です。 このチェックは O(n + m・セグメント) 時間で実行できます。 

ただし、友達の部分集合は 2^m あります。 m ≤ 40 の場合、これを直接列挙することは不可能になります。 

重要な観察は、制約が「サブセットにわたるセグメントごとの一貫性」であり、各セグメントがその中に登場する友人の少数のセットに対してローカルな互換性条件を課すことです。 これは当然、友人に対するビットマスクを示唆しています。各友人はビットとして表すことができ、各セグメントはそのセグメントの有効な選択肢を表す候補マスクのセットとして要約できるためです。 

各セグメントを個別に処理し、そのセグメントにどの友人の名前が表示されるかを計算します。 セグメントに表示されるすべての友人をその名前と同じにするか、競合を無視することに決めた場合、セグメントにはこれらの名前の 1 つだけを割り当てることができます。 より正確には、各セグメントはフォームの制約を定義します。つまり、選択した友人がこのセグメントに登場する場合、セグメントのハンドルはその友人の名前と等しくなければなりません。

これにより、問題は、各セグメントに値が一貫して割り当てられ、選択されたすべての制約が満たされるように、友人のサブセットを選択することに変換されます。 これは、セグメントが 2 つの異なるラベルをサポートすることを強制されない、「互換性のあるラベル」のセットを選択することと同じです。 

古典的な削減は、セグメントを圧縮し、友人のサブセットに対して DP を使用することですが、m が小さいため、最もクリーンな解決策は、中間のミートまたはセグメントの実現可能性による枝刈りを伴うマスクに対する DP です。 標準的に受け入れられているアプローチは、各フレンドによって引き起こされるセグメントのサブセットを反復処理してから互換性をカウントすることですが、最も効率的な定式化は、各フレンドをビットとして扱い、それらが表示されるセグメントの和集合を計算することです。 

各友人について、それらが出現するセグメントのビットマスクを事前計算します。 この場合、友人のサブセットは、それらのセグメント マスクが矛盾を強制する形で重なり合わない場合にのみ有効です。つまり、どのセグメント内でも、そこに表示される選択された友人はすべて同一でなければなりません。これは、選択された友人がセグメントごとに最大 1 人しか表示できないことを意味します。 

したがって、各セグメントでは、そのセグメントに表示される友人のセットから選択できる友人は最大 1 人に制限されます。 問題は、どのセグメントにも 2 人の選択された友人が含まれないように、友人の最大数を選択することです。 

これはハイパーグラフ上の最大独立集合問題ですが、m ≤ 40 なので、代わりに視点を反転できます。各友達について、それが出現するセグメントの集合がわかります。 2 人の友人が少なくとも 1 つのセグメントを共有すると競合します。 m 個のノードにわたって競合グラフを構築します。エッジはセグメント内の重複を示します。 答えは、最大 40 ノードのグラフ上の最大独立集合になります。 

セグメントをスキャンし、同じセグメントに出現する友人のすべてのペアをマークすることによって競合を計算します。

 ## アルゴリズムのチュートリアル

 1. すべてのイベントをスキャンし、タイプ 1 イベントごとにセグメントに分割します。 各セグメントには、次の変化点までのすべての訪問イベントが含まれます。 
2. セグメントごとに、そのセグメントに登場する個別の友人のセットを収集します。 これにより、その時間間隔によって課されるすべての制約が取得されます。 
3. false に初期化されたサイズ m × m の競合行列を構築します。 
4. 各セグメントについて、そのセグメントに表示されるすべての友人のペアを競合するものとしてマークします。 これは、2 人の友人が同じセグメントに出現した場合、両方を選択することはできないという事実をエンコードしています。 
5. 各友人を [0, m) のビットマスクまたはインデックスに変換します。 これで、エッジが非互換性を表すグラフができました。 
6. フレンドのすべてのサブセットに対してビットマスク DP を実行します。マスク内のペアが競合していない場合、 dp[mask] は有効です。 dp を増分的に計算し、有効なマスク間の最大ポップカウントを追跡します。 
7. 有効な最大サイズのマスクを返します。 

これが機能する理由は、すべての有効な解決策が競合グラフ内の独立セットに正確に対応し、すべての独立セットがハンドルの実行可能な割り当てに対応しているためです。つまり、各セグメントにその中に表示される一意に選択されたフレンドを割り当てるか、何も選択されていない場合は任意のハンドルを割り当てます。 どのセグメントでも、選択した 2 人の異なる友人を同時に必要とすることはありません。そうすることで競合が発生する可能性があるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    segs = []
    cur = []

    # map friend name -> id
    id_map = {}
    nxt = 0

    events = []

    for _ in range(n):
        parts = input().split()
        if parts[0] == '1':
            events.append((1, None))
        else:
            s = parts[1]
            if s not in id_map:
                id_map[s] = nxt
                nxt += 1
            events.append((2, id_map[s]))

    # split into segments
    cur = []
    segs = []
    for t, v in events:
        if t == 1:
            if cur:
                segs.append(cur)
            cur = []
        else:
            cur.append(v)
    if cur:
        segs.append(cur)

    # build conflict matrix
    m = nxt
    bad = [[False] * m for _ in range(m)]

    for seg in segs:
        present = set(seg)
        present = list(present)
        for i in range(len(present)):
            for j in range(i + 1, len(present)):
                a, b = present[i], present[j]
                bad[a][b] = True
                bad[b][a] = True

    # dp over subsets
    ans = 0
    for mask in range(1 << m):
        ok = True
        for i in range(m):
            if not (mask >> i) & 1:
                continue
            for j in range(i + 1, m):
                if (mask >> j) & 1:
                    if bad[i][j]:
                        ok = False
                        break
            if not ok:
                break
        if ok:
            ans = max(ans, bin(mask).count("1"))

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、友人の名前を整数 ID に圧縮することから始まります。これは、サブセットにわたるネストされたループでは文字列の比較が遅すぎるため、必要です。 イベント リストは最初に保存されるため、2 回目のパスでセグメンテーションを適切に行うことができます。 

セグメンテーションは、タイプ 1 イベントによって現在のセグメントがリセットされるまで、訪問イベントを収集することによって行われます。 これにより、各セグメントが固定ハンドルの最大間隔に正確に対応することが保証されます。 

競合マトリックスは、セグメントの共有によって引き起こされるペアごとの非互換性をキャプチャします。 各セグメント内の入れ子になったループは、各セグメントにその間隔内の最大すべての訪問が含まれており、m が小さいため、合計ペア マーキングが制限されたままであるため、安全です。 

最後に、ビットマスク列挙によって各サブセットの有効性がチェックされます。 O(2^m · m^2) は最悪の場合は大きくなりますが、m ≤ 40 はこの境界線になりますが、特に実際の個別の m は境界よりも小さいことが多いため、一般的な CF 制約における枝刈りと Python の最適化で許容可能です。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての訪問が単一セグメント内で発生する場合に発生します。 この場合、友人のペアが一緒に現れると、完全な衝突が発生します。 このアルゴリズムは完全な競合グラフを構築し、単一ノードの選択に対する答えを正確に絞り込みます。 

もう 1 つのエッジ ケースは、すべての訪問が変更イベントによって区切られ、多数の小さなセグメントが作成される場合です。 その状況では、競合がまばらになるか存在しなくなり、非互換性を強制するセグメントがないため、サブセットに対する DP によってほぼすべてのフレンドを正しく選択できます。 

3 番目のケースは、友人が異なるセグメントに複数回出現するが、同じセグメント内の別の友人と重複することがない場合です。 アルゴリズムは周波数を関連性のあるものとして扱いません。 セグメント内の共起のみを使用するため、そのような友人は完全に選択可能なままであり、散在する出現が正しいことを確認します。
