 ## 解決策
 ## 問題の理解

 長さの配列がいくつあるかを数えるように求められます$n$すべての要素が一定の間隔内に収まるように形成できます$[l, r]$、すべての要素の合計は 3 で割り切れます。 

問題は特定の配列を構築することではなく、位置ごとの値の制限と合計に関するグローバルなモジュラー制約という 2 つの制約の下ですべての有効な構成を一度にカウントすることです。 

制約は大きいです:$n$まで可能です$2 \cdot 10^5$配列内の値は次のような大きさにすることができます。$10^9$。 これにより、可能なすべての配列、さらにはすべての可能な合計を反復するアプローチは即座に排除されます。 有効な解決策は、問題を小さな固定状態空間に縮小する必要があり、通常は実際の値ではなくモジュラー演算に基づいています。 

範囲を考えると微妙な難しさが出てくる$[l, r]$。 値が大きい場合でも、3 で割り切れるかどうかで重要なのは、3 を法とする剰余のみです。特に区間の長さが 3 で割り切れない場合、区間内の剰余の分布は必ずしも均一ではありません。 

よくある落とし穴は、境界を処理せずに各剰余クラスが同じ頻度で現れると仮定することです。 たとえば、次のような狭い範囲で$[1, 3]$、各残基は 1 回だけ出現しますが、$[1, 4]$、残留カウントが不均一になります。 これを無視するソリューションでは、有効な配列のカウントが間違ってしまいます。 

もう 1 つのエッジケースは次のような場合です$n = 1$。 答えは単純に、次の数字がいくつあるかです。$[l, r]$は 3 で割り切れるため、単純な DP 定式化では、グローバル合計制約を強制せずに位置を独立して処理することにより、誤って過大数をカウントする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。長さのすべての配列を生成します。$n$、各要素が範囲内にあるかどうかを確認します$[l, r]$、その合計を計算し、3 で割り切れるかどうかを確認します。配列の数は次のとおりです。$(r-l+1)^n$、これは小さな入力でも天文学的に大きく、これは完全に実行不可能です。 

重要な観察は、この条件が 3 を法とする合計にのみ依存するということです。各要素は、最終的な合計には 3 を法とする剰余のみを寄与します。 これにより、各配列要素が潜在的に巨大な整数空間から、0、1、または 2 を法とする 3 に一致する数値という 3 つのカテゴリに縮小されます。 

この削減が行われると、問題は長さを超える典型的な DP になります。$n$および累計のモジュロ状態。 唯一欠けている部分は、次の整数の個数を決定することです。$[l, r]$各残基クラスに分類されます。 その後、遷移は純粋に組み合わせ的なものになります。各位置で剰余クラスを選択し、3 を法とする和を更新します。 

これにより、問題は指数列挙から一定状態サイズの線形 DP に軽減されます。

 ## アルゴリズムのチュートリアル

 まず、入力範囲を 3 を法とする剰余のカウントに圧縮します。 

1. の数字がいくつあるかを計算します。$[l, r]$は 3 を法とする 0、1、2 に合同です。 

これは等差数列カウントを使用して行われます。 各剰余クラスについて、その剰余の区間内の最初の数値を見つけて、サイズ 3 のステップが何ステップ適合するかを数えます。$r$。 範囲を直接反復できないため、このステップが必要です。 
2. これらのカウントを次のようにします。$c_0, c_1, c_2$。 配列内の各位置は、これらの剰余クラスの 1 つを効果的に選択します。 
3. DP 配列を定義します。$dp[i][m]$最初の選択方法の数です$i$3 を法とする和が次と等しくなるような要素$m$。 

私たちはただ気にするだけです$m \in \{0, 1, 2\}$。 
4.初期化$dp[0][0] = 1$なぜなら、合計が 0 で何も選択しない方法が 1 つだけあるからです。 
5. 1 から 1 までの各位置について$n$、新しい DP 状態を更新します。 

剰余 0、1、または 2 の数字を配置してみます。 

それぞれの選択が貢献します$c_0$、$c_1$、 または$c_2$それぞれの方法を選択し、それに応じてモジュロ状態をシフトします。 

たとえば、剰余 1 要素を配置すると状態が移動します。$m$に$(m+1) \bmod 3$。 
6. すべての位置を処理すると、答えは次のようになります。$dp[n][0]$, 3で割り切れる合計が必要なためです。 

### なぜ効果があるのか

 すべてのステップで、DP 状態は、すべての有効なプレフィックスにわたる 3 を法とする部分和の分布を正確にキャプチャします。 すべての配列プレフィックスは 3 つの剰余クラスの 1 つを追加することによって一意に形成され、各クラスは間隔から正確に正しい数の値を提供するため、遷移によって正確さが保たれます。 モジュロ加算は閉じていて決定論的であるため、2 つの異なる構築パスが誤って干渉することはなく、すべての配列が正確に 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_residues(l, r):
    cnt = [0, 0, 0]
    for rem in range(3):
        # first number >= l with value ≡ rem (mod 3)
        start = l + (rem - l % 3) % 3
        if start > r:
            cnt[rem] = 0
        else:
            cnt[rem] = (r - start) // 3 + 1
    return cnt

def solve():
    n, l, r = map(int, input().split())
    
    c0, c1, c2 = count_residues(l, r)
    
    dp = [0, 0, 0]
    dp[0] = 1
    
    for _ in range(n):
        ndp = [0, 0, 0]
        for m in range(3):
            if dp[m] == 0:
                continue
            ndp[m] = (ndp[m] + dp[m] * c0) % MOD
            ndp[(m + 1) % 3] = (ndp[(m + 1) % 3] + dp[m] * c1) % MOD
            ndp[(m + 2) % 3] = (ndp[(m + 2) % 3] + dp[m] * c2) % MOD
        dp = ndp
    
    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```コードは、値の範囲を 3 つのカウント (残差クラスごとに 1 つ) に圧縮することから始まります。 DP 配列は、合計モジュロ 3 に対応する 3 つの状態のみを追跡します。各反復では、1 つの配列要素の配置をシミュレートし、事前計算されたカウントを使用してすべての可能なモジュロ遷移を更新します。 最終的な答えは、合計が 3 で割り切れる全長シーケンスの数です。 

実装の微妙な詳細は、剰余カウントの式です。 の表現`start`慎重に位置を合わせます`l`正しいモジュロで次の数値に上向きに計算され、3 による除算は等差数列のフル ステップをカウントします。 

## 実用的な例

 ### 例 1

 入力:```
2 1 3
```最初に残基カウントを計算します。$[1, 3]$: 残基 0、1、2 にそれぞれ 1 つの数値、つまり$c_0 = c_1 = c_2 = 1$。 

| ステップ | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 1 | 1 |
 | 2 | 3 | 3 | 3 |

 最終的な答えは、$dp[2][0] = 3$、配列に対応$[1,2], [2,1], [3,3]$。 

このトレースは、剰余クラス間の対称性がバランスの取れた遷移をどのように生成するか、および複数のパスが同じモジュロ状態でどのように終了するかを示します。 

### 例 2

 入力:```
1 2 4
```残留物$[2,4]$は$2 \equiv 2$、$3 \equiv 0$、$4 \equiv 1$、それではまたまた$c_0 = c_1 = c_2 = 1$。 

| ステップ | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 1 | 1 |

 答えは$dp[1][0] = 1$、単一の有効な配列に対応します$[3]$。 

これは、長さ 1 が 3 で割り切れる有効な要素のカウントに直接減少する基本ケースの動作を示しています。

 ## 特殊なケース

 1 つのエッジ ケースは、区間に指定された剰余クラスの数値が含まれない場合に発生します。 たとえば、次の場合$l = 1$そして$r = 1$、残基 1 のみが表示されます。 その後、DP は崩壊して、1 種類のトランジションのみを繰り返し追加します。 他の剰余カウントはゼロであるため、アルゴリズムはこれを正しく処理し、遷移に寄与することはありません。 

もう 1 つのケースは、範囲が非常に大きいが、残基全体に均等に分布している場合です。$[1, 10^9]$。 計数式は反復することなく各剰余クラスのほぼ等しい計数を正確に計算しており、個別の値ではなく集計された計数のみを使用するため、DP は安定したままです。 

3つ目のケースは、$n = 1$ここで、答えは単に区間内の 3 で割り切れる要素の数でなければなりません。 DP は次から始まります$dp[0][0]$、1 回の反復の後、直接遷移のみが適用され、残差 0 要素の数が正確に生成され、期待される結果と一致します。
