 ## 解決策
 ## 問題の理解

 私たちは、非常に大きなサイズのグリッド上に定義された隠れた「山」を操作しています。$n \times m$。 このグリッドのどこかに 1 つの特別なセルがあります$(x_0, y_0)$、ピーク。 他のすべてのセルの高さは厳密に小さくなり、高さはセルがこのピークからどれだけ離れているかによってのみ決まります。 2 つのセルがピークから異なる距離にある場合、それらの高さは異なり、近い方の方が常に高くなります。 

情報を取得する唯一の方法はセルにクエリを実行することです$(x, y)$、高さを実数として返します。 これから、できるだけ少ないクエリを使用してピークの正確な座標を決定する必要があります。 

制約$n, m \le 10^6$グリッドのごく一部以上を検査する戦略は直ちに除外してください。 1 行を完全にスキャンしただけでも、すでに大きすぎます。 このため、通常は単調性または単峰性を利用することで、すべてのクエリで不確実性を有意義に低減するアプローチが必要になります。 

微妙だが重要な特性は、高さは方向ではなく、頂上までの距離のみに依存するということです。 これは、1 つの座標を固定すると、次のようになります。$x$、およびさまざまです$y$、関数は次の点を中心とする単一ピーク曲線のように動作します。$y_0$。 修正した場合も同様です$y$そして変化します$x$。 この構造により、対数探索で問題を解決できるようになります。 

単純な考えとしては、ランダムなポイントまたはローカル検索を試してみることです。 ただし、グリッドが巨大であるため、ランダム サンプリングでは、徐々に優れたポイントがすぐに見つかるという保証はありません。 貪欲な隣人クライミングでも、最悪のレイアウトでは歩数が多すぎる可能性があります。 

重要な隠れエッジのケースは、ピークが境界近くにある場合です。 このような場合、局所的な移動や単純な山登りでは、頂上に到達する前に端に沿って長距離を歩くことになり、クエリが無駄になる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべてのセルに対してクエリを実行し、検出された最大の高さを追跡します。 ピークは一意のグローバル最大値であるため、これは正しいです。 ただし、これには次のことが必要です$n \cdot m$クエリ、最大で$10^{12}$、完全に不可能です。 

重要な観察は、関数は 2 次元に存在しますが、他の座標が固定されている場合、各座標で単峰性であるということです。 直したら$x$、その後、進んでいくと$y$、ピークまでの距離は減少します。$y_0$、その後増加します。 したがって、その線に沿った高さには単一の最大値があります。 これはまさに三項検索に必要な構造です。 

これにより、2D 問題が 2 つの独立した 1D 検索に縮小されます。 まず正しい行を見つけます$y_0$三項検索により$y$、任意の固定を使用$x$。 一度$y_0$が見つかったら、同じアイデアを繰り返します。$x$- 配置する軸$x_0$。

 ## アルゴリズムのチュートリアル

 インタラクティブ関数を各座標のブラックボックス単峰関数として扱います。 

1. 修正します$x$、便宜上、$x = 1$。 ここで関数を考えてみましょう$f(y) = \text{height}(1, y)$。 高さは頂上までの距離のみに依存するため、この関数の最大値は次のとおりです。$y = y_0$。 
2. 間隔で三項検索を実行します。$[1, m]$見つける$y_0$。 各ステップで 2 つの中点を選択します$mid_1$そして$mid_2$、クエリ$(1, mid_1)$そして$(1, mid_2)$、高さを比較します。 機能が高ければ$mid_1$の場合、ピークは左側のセグメントにあり、それ以外の場合、ピークは右側のセグメントにあります。 これが機能するのは、単峰性では二次的な最大値がないことが保証されるためです。 
3. 絞り込んだ後、残りのいくつかの候補を直接テストして、正確な結果を決定します。$y_0$。 
4. ここで修正します$y = y_0$。 考慮する$g(x) = \text{height}(x, y_0)$、これも単峰性であり、次の点に単一のピークがあります。$x_0$。 
5. 三項検索を実行します$[1, n]$同様に、クエリを実行すると、$(mid, y_0)$ピーク位置まで$x_0$が見つかりました。 
6. 出力$(x_0, y_0)$そして終了します。 

### なぜ効果があるのか

 正確さは、ピークまでの距離が厳密に最小化されるという事実に依存します。$(x_0, y_0)$であり、いずれかの方向に遠ざかるにつれて厳密に増加します。 したがって、固定された水平または垂直スライスは、単一の最大値を持つ厳密に単峰関数を形成します。 このような関数の三分探索では、真のピークが破棄されることはありません。これは、2 点間の比較により、どちらの側に最大値が含まれているかが常に正確に示されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x, y):
    print(f"? {x} {y}")
    sys.stdout.flush()
    return float(input().strip())

def ternary_search_fixed_x(x, m):
    l, r = 1, m
    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        v1 = ask(x, m1)
        v2 = ask(x, m2)
        if v1 < v2:
            l = m1
        else:
            r = m2

    best_y = l
    best_val = ask(x, l)
    for y in range(l + 1, r + 1):
        v = ask(x, y)
        if v > best_val:
            best_val = v
            best_y = y
    return best_y

def ternary_search_fixed_y(y, n):
    l, r = 1, n
    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        v1 = ask(m1, y)
        v2 = ask(m2, y)
        if v1 < v2:
            l = m1
        else:
            r = m2

    best_x = l
    best_val = ask(l, y)
    for x in range(l + 1, r + 1):
        v = ask(x, y)
        if v > best_val:
            best_val = v
            best_x = x
    return best_x

def solve():
    n, m = map(int, input().split())
    y0 = ternary_search_fixed_x(1, m)
    x0 = ternary_search_fixed_y(y0, n)
    print(f"! {x0} {y0}")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、2 つの座標検索が明確に分離されます。 ヘルパー関数`ask`これは対話型の問題では必須です。 

各三項検索ループは、2 つの内部点の比較に基づいて間隔を縮小します。 間隔が小さくなると、線形スキャンによって正確な最大値が安全に解決され、狭い範囲での浮動小数点比較の不安定性が回避されます。

 ## 特殊なケース

 特殊なケースは、ピークがちょうど境界上にある場合に発生します。$(1, 1)$。 この場合、関数は両方の軸に沿って依然として単峰性ですが、最大値は検索間隔の端にあります。 比較は常にピークを含む境界方向を優先し、それに向かって徐々に縮小するため、三分探索は引き続き機能します。 

もう一つのケースは次のような場合です。$n = 1$または$m = 1$。 問題は純粋な 1D 三分探索にまで発展します。 同じロジックが適用されますが、必要なフェーズは 1 つだけです。 単峰性の仮定が有効なままであるため、アルゴリズムは依然として正しく動作します。 

最後に、ピークが中心にある場合、対称点間の比較によりほぼ同一の縮小パターンが生成されますが、高さが厳密に不等であるため、振動することなく中心に向かう決定的な動きが保証されます。
