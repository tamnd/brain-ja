 ## 問題の理解

 整数が与えられます`a`、負、ゼロ、または正の値を指定できます。 負でない整数を追加することができます`x`それに。 目標は、結果の数字を作ることです`a + x`デジタル時計に表示される有効な時刻のように見えます。 

解釈としては、結果の数値は、次の形式で有効な 24 時間に分割できる一連の数字として読み取られます。`HH:MM`。 したがって、先頭にゼロを付けて記述する場合、数値は正確に 4 桁である必要があり、それらの桁は有効な時刻を形成する必要があります。`00`に`23`から数分`00`に`59`。 

私たちはあらゆる可能性を試しているわけではありません`x`、最小の非負の値が必要です。`x`そのような`a + x`有効な時刻としてフォーマットできます。 そうでない場合`x`存在する場合は出力します`-1`。 

の制約`a`から行く`-10^9`に`10^9`, したがって、追加後の結果の値は`x`は依然として一般的な 32 ビット整数の範囲内にあります。 Python ではオーバーフローの問題を心配することなく、候補を安全にブルートチェックできるため、これは重要です。 

単純な間違いは、生の値だけをチェックすることです。`a`先行ゼロを考慮せずに数値として。 例えば、`0`に対応する`00:00`、 そして`500`に対応する`05:00`これは、埋め込まれない限り数字が「時間のように見えない」場合でも有効です。 

もう 1 つの微妙なエッジ ケースは、負の数です。 のような数字`-128`十分に大きな値を追加した後に有効になる可能性があります`x`ですが、中間値は時間として意味を持ちません。 最終的な非負の値のみを考慮します。 

## アプローチ

 直接的なアプローチは、次の値を増やしてみることです。`x`ゼロから始めて計算する`a + x`、先頭にゼロが付いた 4 桁の文字列として解釈されたときに有効な時刻を形成するかどうかを確認します。 

これは正しいです。なぜなら、最小値を明示的に検索しているからです。`x`、そして増加しています`x`の値が増加することを保証します`a + x`。 各候補値について、検証は定数時間で行われます。文字列に変換し、4 桁に埋め込み、時と分の部分が有効かどうかを確認します。 

ただし、ブルートフォース手法では、有効な値を見つける前に多くの値をスキャンする可能性があります。 最悪の場合、車間距離まで確認させていただく場合がございます。`a`次の有効な 24 時間表現ですが、検索スペースは最大でも次のオーダーです。`10^9`シフトの場合でも、各チェックが単純で早期終了が実際にすぐに起こることを考えると、Python ではまだ許容されます。 

重要な観察点は、24 時間形式の有効時間の範囲は次のとおりであるということです。`0000`に`2359`、1440 個の値のみが存在します。 したがって、任意の整数の観点から考える代わりに、事実上、最も近い数値を探すことになります。`a`最後の 4 桁が有効な時刻を形成します。 これにより、問題は、次の候補に位置合わせした後、小さな固定範囲のみをチェックするようになります。 

さらに単純化することもできます。チェックする必要があるのは、次の最大 1440 個の連続する値だけです。`a`なぜなら、丸 1 日のサイクル内に、考えられるすべての時間パターンが 1 回出現するからです。 したがって、その境界のあるウィンドウをスキャンするだけで十分です。

 ## アルゴリズムのチュートリアル

 1.指定された番号から開始します`a`そして候補者を検討します`a + x`の値を増やすために`x`。 目標は、最初の有効なものを見つけることです。 
2. 各候補値について`v = a + x`、ゼロ埋め込みを使用して 4 桁の表現に変換します。 これにより、次のような数値が保証されます`5`なる`0005`、これは時間を正確に解釈するために必要です。 
3. 4 桁の文字列を 2 つの部分に分割します。最初の 2 桁は時間、最後の 2 桁は分です。 これは構造と一致します`HHMM`。 
4. 時間の値が次の範囲内であるかどうかを確認します。`00`そして`23`、分の値は次の範囲にあります。`00`そして`59`。 両方の条件が当てはまる場合、候補は有効な時刻です。 
5. 有効な候補が見つかるとすぐに出力します。`x`昇順でスキャンしているため、これは可能な最小値です。 
6. 1440 個の値の全サイクルをチェックした後で有効な候補が見つからない場合、出力`-1`24 時間の時間パターンに到達できないため、`a`。 

### なぜ効果があるのか

 すべての有効な時間は、範囲内の 1 つの値に正確に対応します。`0000`に`2359`。 1 ずつ増加すると、最終的には時間に対応するすべての可能な数字パターンを通過することになります。 有効な時間の空間は有限であり、1440 値のサイクル内に完全に含まれているため、十分に大きなシフトは、到達可能な場合には最終的に有効な構成に到達する必要があります。 昇順でスキャンすることで最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_valid(v: int) -> bool:
    if v < 0 or v > 2359:
        return False
    h = v // 100
    m = v % 100
    return 0 <= h <= 23 and 0 <= m <= 59

def solve():
    a = int(input().strip())

    for x in range(0, 1441):
        v = a + x
        if is_valid(v):
            print(x)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```ソリューションは可能な増分を繰り返します`x`ゼロからのスタート。 候補値ごとに計算します。`v = a + x`そして、時間と分への直接分解を使用して有効性をチェックします。 

条件`v <= 2359`これは簡単なプルーニング ステップです。これより大きい数値は HHMM 形式で有効な時間を表すことができないため、すぐに破棄されます。 時と分のチェックにより正確さが保証されます。 

ループの限界`1441`24 時間サイクル全体で考えられるすべての遷移を安全にカバーし、さらにエッジ位置合わせの場合の検出を保証するための追加ステップを 1 つ追加します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、初期値が負の場合です。 例えば`a = -1`。 アルゴリズムは以下をチェックします。`x = 0 -> v = -1`無効`x = 1 -> v = 0`有効 （`00:00`)

 したがって、正しく返されます`1`。 

もう一つのケースは次のような場合です。`a`はすでに有効な時間です`0`または`1100`。 からループが始まるので、`x = 0`、すぐに有効性を検出して返します。`0`。 

3 番目のケースは、次のような無効な分エンコーディングです。`a = 59`。 値`59`に対応する`00:59`これは有効なので、アルゴリズムは正しく返します。`0`それ以上の増分は試行せずに。 これは、検証が生の数字パターンではなく分割構造に依存していることを強調しています。
