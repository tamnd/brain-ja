 ## 解決策
 ## 問題の理解

 一定の瞬間に直線道路に沿って配置された 2 つの順序付けられた車のグループが与えられます。 1 つのグループは原点から遠ざかり、もう 1 つのグループは原点に向かって移動し、すべて同じ速度で移動します。 2 台の車が出会うとき、つまり道路ですれ違うとき、マルセルの不快感は、その出会いの瞬間に関与する車のペアごとに 1 ずつ増加します。 

重要な点は、複数の車が同時に衝突する可能性があるということです。 ある時点で複数の車が同じ地点で出会った場合、それらの車の各ペアは別々に寄与します。 したがって、k 台の車が同時に出会った場合、寄与はこのグループ内のペアの数、つまり k(k−1)/2 になります。 

入力により、右に移動する n 台の車両と左に移動する m 台の車両の初期位置が得られます。 すべての速度が等しいため、各グループ内の車の順序が変わることはなく、反対方向から来た車の各ペアは 1 回だけ出会います。 

出力は、さまざまな方向からのすべての車両ペアにわたるそのような会議の合計数です。 

制約は各方向に最大 3x10^5 台の車両に及ぶため、すべてのペアにわたる二次シミュレーションは不可能です。 O(nm) の直接ペアリングでも、最悪の場合約 9×10^10 演算に達するため、大きすぎます。 

微妙なエッジケースは、同時衝突によって発生します。 複数の右走行車と左走行車がまったく同じ地点で出会う場合、カウントでは多重度を正しく処理する必要があります。 

たとえば、位置が次の場合:```
n = 2, m = 2
a = [1, 3]
b = [2, 4]
```その後、ペアは異なる時間に集まり、それぞれが独立して貢献します。 しかし、複数の交差が同時に発生するように値をシフトすると、グループ化せずにペアごとの順序のみをカウントする単純なマージ ロジックでは、実装に応じて過小カウントまたは過大カウントされます。 

もう 1 つの注意が必要な状況は、あるグループ全体が他のグループよりも厳密に前にある場合です。たとえば、次のとおりです。```
a = [1, 2, 3]
b = [10, 11]
```ここではすべてのペアが交差しており、答えは単純に n × m です。 最近傍のみを照合しようとするソリューションは失敗します。 

## アプローチ

 強引なアイデアは簡単です。最初のグループのすべての車について、その動きをシミュレートし、それが出会う 2 番目のグループの車の数を数えます。 すべての車は一定の速度で移動するため、2 台の車は、最初の順序がそれらの経路が交差することを意味するときに正確に出会います。 これは、すべてのペア (i, j) をチェックし、適切なタイミングで i 番目の右走行車が j 番目の左走行車の左側にある場合に答えをインクリメントすることになります。 これは正しいですが、コストは O(nm) であり、限界をはるかに超えています。 

改善するには、動きが均一であるため、時間があまり重要ではないことを観察します。 重要なのは相対的な順序です。 位置 a[i] で開始する右走行車は、位置 b[j] で開始するすべての左走行車と、それらの経路が時間の経過とともに交差するように出会います。これは、一貫した方向インデックスで解釈される場合、a[i] < b[j] と同等です。 

ただし、直接カウントしても O(nm) のように見えるため、問題はソートされた配列内のすべてのペアの単純な比較だけではありません。 重要な洞察は、状況を線に沿ったスイープとして解釈することです。 ある地点を左から右に横切るたびに、視点に応じて、その地点の先または前に反対方向からの車が何台あるかが累積されます。 

両方の配列はソートされているため、2 ポインター スイープで処理できます。 私たちはポジションを上げて進み、反対方向から何台の車が現在の車に出会うかを維持します。 それぞれの新しい車は、以前に見たすべての反対方向の車に寄与するか、将来何台の車に出会うかを決定します。 これにより、カウントが線形時間に短縮されます。 

本質的な構造は、すべてのペアがマージされたソートされたシーケンス内の相対的な順序によって決定されるため、2 つの配列間の相互反転をカウントできるということです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 2 ポインタ スイープ | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 これを、車が正確に 1 回すれ違う必要があるという条件を満たすインデックス (i, j) のペアが何組あるかを数えるものとして扱います。 すべての速度は同じであるため、これは、ソートされた 1 つのリストの要素が、最終的にマージされた順序で他のリストの各要素の反対側にいくつあるかを数えるという問題になります。 

ソートとスイープを活用します。 

1. 配列 a と b の先頭にある 2 つのポインター i と j から始めます。 また、最初のグループと比較して、2 番目のグループの何台の車がスイープですでに「見られた」かを追跡するカウンターも維持します。 
2. a[i] と b[j] を比較します。 小さい位置は、道路に沿って左から右の順序で次の車を表します。 
3. a[i] < b[j] の場合、最初のグループの車が現在空間順序で次になります。 これは、処理が完了すると、まだ注文が進んでいる 2 番目のグループの残りのすべての車両に対応できることを意味します。 それに応じて、すでに処理された反対方向の車両の数を追加し、i を前に進めます。 
4. それ以外の場合、b[j] < a[i] の場合、最初に 2 番目のグループの車を処理します。 この車は、すでに処理されているすべての第 1 グループの車と一致するため、これらの貢献を蓄積して j を前進させます。 
5. 両方のアレイが使い果たされるまで続行します。 1 つのアレイが終了すると、もう 1 つのグループの残りの要素が、スイープですでにカウントされているすべての反対方向の車両に寄与します。 
6. 最終的な累積値は、ペアごとのミーティングの合計数です。 

この順序付けが機能する理由は、ソートされた順序の後の要素が処理される時点で、すべてのペアが 1 回だけ考慮されるためです。 スイープにより、各クロス ペアが処理済みセグメントと未処理セグメント間の正しい境界でカウントされることが保証されます。 

### なぜ効果があるのか

スイープのどの時点でも、ソートされた順序で「処理されたプレフィックス」と「未処理のサフィックス」への行のパーティションが維持されます。 すべてのペア (a[i]、b[j]) は、2 つの位置のうち大きい方が処理される時点で一意に識別されます。 この時点で、もう一方の要素は、処理されたプレフィックスまたは残りのサフィックスのいずれか内にすでに完全に分類されているため、そのペアの寄与は 1 回だけ追加されます。 どちらのエンドポイントも処理されていないため、以前にペアをカウントすることはできません。また、両方のエンドポイントがすでにスイープ境界の後ろにあるため、後でカウントすることもできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = j = 0
    cnt_a = 0
    cnt_b = 0
    ans = 0
    
    while i < n or j < m:
        if j == m or (i < n and a[i] < b[j]):
            ans += cnt_b
            cnt_a += 1
            i += 1
        else:
            ans += cnt_a
            cnt_b += 1
            j += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 つのソートされた配列に対して古典的な 2 ポインターのマージ構造が使用されます。 変数`cnt_a`そして`cnt_b`スイープですでに処理された各グループの要素の数を表します。 一方のグループの要素を処理するとき、反対側のグループのすでに処理された要素の数を追加します。これは、その要素が以前に処理された要素と寄与する有効な交差の数に正確に対応します。 

比較`a[i] < b[j]`すべての位置が異なるため、同点が発生しないという問題ステートメントと一致する厳密な順序付けが保証されます。 最後のループ条件により、1 つの配列が使い尽くされると、他のグループの残りの要素がすべて、反対側のカウンターからの完全な寄与で処理されることが保証されます。

 ## 特殊なケース

 重大なエッジ ケースは、一方の配列のすべての要素がもう一方のすべての要素よりも小さい場合です。 例えば：```
n = 3, m = 2
a = [1, 2, 3]
b = [10, 11]
```スイープ中に、次のすべての要素が`a`が最初に処理されるため、`cnt_b`消費を始めるまでは常にゼロです`b`。 到着したら`b`、各要素が貢献します`cnt_a`したがって、寄与は 3 + 3 = 6 となり、完全なデカルト ペアと一致します。 

別のケースは厳密な代替です。```
a = [1, 4, 7]
b = [2, 5, 8]
```ここでは各ステップがインターリーブされます。 それぞれ`a[i]`以前に処理されたもののみが表示されます`b`、そしてそれぞれ`b[j]`以前に処理されたものを参照`a`、各クロスペアが正確に 1 回カウントされるようにします。 すべての新しい要素は、反対のタイプの以前のすべての要素を即座に考慮するため、スイープではペアがスキップされないことが保証されます。
