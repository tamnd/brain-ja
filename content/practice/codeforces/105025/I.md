 ## 問題の理解

 2 人のプレイヤーが交互にブロックを上に置き、1 つのタワーを構築します。 各ブロックには、次の範囲の整数の重みがあります。$l$そして$r$、両方のプレイヤーは好きなだけウェイトを再利用できます。 

タワーは総重量から始まります$0$。 移動するたびに、選択したブロックの重みが累計に追加されます。 総重量が少なくとも以上になるとゲームは直ちに終了します$k$。 に達するかそれを超える動きをしたプレイヤー$k$負けるのは人です。 

この質問は純粋に戦略的なものです。両方のプレーヤーが最適にプレーし、ステートメントの 2 番目のプレーヤーが開始者であると仮定すると、最初の手がすでにゲームを決定しているのか、それとも 2 番目のプレーヤーが正しく応答することで勝利を強制できるのかを判断する必要があります。 したがって、出力は勝者のプレイヤーに関する二者決定です。 

制約$k, l, r \le 10^9$合計の状態に関するシミュレーションを除外します。 考えられるすべてのタワーの高さにわたる単純な動的プログラミング$k$必要になるだろう$O(k)$完全に不可能な状態です。 到達可能な金額を追跡しようとするさらに洗練された DP は、依然として以下に依存します。$k$、大きすぎます。 

ゲームの構造は、残りの「ギャップ」のみに到達することを示唆しています$k$重要なのは動きの正確な順序ではありません。 このギャップは、選択した重みを減算することによって決定論的に発展し、手がしきい値を超えると負け条件がトリガーされます。 これは、問題が単一の整数に関する古典的な減算ゲームに崩壊するはずであることを直ちに示唆します。 

残りのギャップが より小さい場合、微妙なエッジ ケースが表示されます。$l$。 この状況では、考えられるすべての手がしきい値をオーバーシュートし、現在のプレイヤーは即座に負けを強いられることになります。 別のコーナー状況が発生するのは、$k$よりわずかに大きいだけです$l$、たった 1 つの行動でゲームが即座に終了する可能性があり、最初の決定が決定的になります。 

## アプローチ

 直接シミュレーションでは、現在の合計を追跡し、考えられるすべてのブロックの重みを再帰的に試行します。$l$に$r$。 和のある状態から$s$、すべての州に分岐します$s+x$。 これにより、最大分岐係数を持つゲーム ツリーが形成されます。$r-l+1$、深さまで$k/l$。 重複する状態を無視したとしても、これは合理的な複雑さをはるかに超えています。 

重要な観察は、到達できるのは残りの容量だけであるということです。$k$重要です。 定義すると$N = k - s$、その後、移動するたびに値が減算されます$x \in [l, r]$。 移動は制限を超えない場合にのみ合法です。つまり、$x \le N$。 すべての手がこれに違反した場合、プレイヤーは即座に負けます。 これにより、問題は標準的な持ち帰りゲームに変換されます。サイズが山積みになります。$N = k-1$、プレイヤーはその間を削除します$l$そして$r$石。 動けなくなったプレイヤーが負けとなります。 

これは、連続した移動間隔を持つ単一ヒープ上の古典的な公平なゲームです。 構造は周期的です: 結果は次のもののみに依存します。$N \bmod (l+r)$。 この周期性は、最適な再生によってラインが一定の長さのブロックに分割されるために現れます。$l+r$、最初の$l$各ブロック内の位置は、残りの位置とは異なる動作をします。$r$。

 ## アルゴリズムのチュートリアル

 1. 問題を残りの容量に換算する$N = k - 1$。 これはタワーが強制的に破壊される前に利用可能な総量であるため、すべての動きは減少することに相当します。$N$ある程度の量で$[l, r]$。 
2. 次のことを観察します。$N < l$、最小のブロックでも残りの容量を超えるため、合法的な手は存在しません。 この場合、現在のプレイヤーは即座に負けます。 
3. サイクル長を計算する$l + r$これは、減算プロセスで「安全」な間隔と「危険な」間隔が交互に現れる自然な周期構造を表します。 
4. を使用して位置を減らします。$N \bmod (l + r)$。 これは、すべての長さの完全なセグメントの後に機能するため、$l+r$、ゲーム状態は勝ち負けの構造上繰り返されます。 
5. 余りが区間内にある場合$[0, l-1]$、考えられるすべての手がすぐにオーバーシュートするか、相手の勝利状態に移行するため、その位置は負けています。 
6. それ以外の場合、相手を負けの残留クラスに押し込む手が少なくとも 1 つ存在するため、そのポジションは勝ちです。 

### なぜ効果があるのか

 ゲームは整数行を同じサイズの繰り返しセグメントに分割します。$l+r$。 各セグメント内の最初の$l$位置は、あらゆる動きが不正になるか、相手にとって有利な配置への移行を強制される状態に対応します。 これにより、サイクルごとに繰り返される損失状態の固定パターンが作成されます。 移動するたびに残りの容量が最大で減少するため、$r$、常に次の構造化セグメント内に配置され、この周期的な分類が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, l, r = map(int, input().split())
    n = k - 1

    if n < l:
        print(2)
        return

    cycle = l + r
    rem = n % cycle

    if rem < l:
        print(2)
    else:
        print(1)

if __name__ == "__main__":
    solve()
```解決策は、勝利のしきい値を標準的な減算ゲーム サイズに変換することから始まります。$n = k-1$。 累積合計が次の値に達すると負け条件がトリガーされるため、このシフトは不可欠です。$k$、これは、サイズのリソースを使い果たすことに相当します$k-1$。 

小切手`n < l`法的な動きが存在しない強制的な損失の状況に対処します。 これにより、無効な状態でモジュラー ロジックに依存することが回避されます。 

表現`n % (l + r)`状態を繰り返し構造の正規表現に圧縮します。 と比較すると、$l$負けと勝ちの残基を分離し、プレイヤーがサイクルの強制敗北プレフィックスに閉じ込められているかどうかをエンコードします。

## 特殊なケース

 いつ$k-1 < l$、プレイヤーはしきい値を破らなければ、たとえ小さな動きでさえも行うことができません。 アルゴリズムは条件を通じてこれを直接捕捉します。`n < l`、すぐに損失を返します。
