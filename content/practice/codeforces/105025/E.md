 ## 解決策
 ## 問題の理解

 バナナの価格を一列に並べたシーケンスが与えられます。 各ポジションは 1 つの値を保持し、正確に実行できます。$k$操作。1 つの操作で 2 つの隣接する要素が交換されます。 

これらの交換を実行した後、最終的な配列を確認し、隣接する位置のすべてのペアを評価します。 隣接するペアごとに、それらの値の絶対差を計算し、その差の最大値を考慮します。 目標は、配列を正確に配置することです。$k$この最大隣接差ができるだけ大きくなるように隣接スワップを行います。 

重要な問題は、スワップがローカルであることです。 配列を自由に並べ替えることはできますが、各スワップでは要素が 1 位置ずつ移動するだけであるため、値の移動にかかるコストは値がどのくらい離れているかによって異なります。 

制約は、$O(n)$または$O(n \log n)$解決。 配列の長さは次のとおりです$10^5$、 その間$k$と同じ大きさにすることができます$10^{18}$これは、スワップのシミュレーションが不可能であることを直ちに意味します。 各スワップを明示的に扱うアプローチは失敗します。 

微妙なエッジケースが現れるのは、$k = 0$。 この状況では、配列をまったく変更することはできず、答えは単純に最初の隣接するペアの最大絶対差になります。 もう 1 つのエッジケースは次のような場合です$k$非常に大きいです。 この体制では、配列はほぼ完全に再配置可能になるため、多くの交換を行った場合でもどのような構造的制限が残るかを理解する必要があります。 

## アプローチ

 最も直接的な解釈から始めます。 すべてのシーケンスをシミュレートできます。$k$隣接するスワップを計算し、その結果の最適な構成を計算します。 これは原理的には正しいです。なぜなら、各状態は正確に到達できるからです。$k$swaps corresponds to a valid arrangement. The problem is the branching factor. それぞれの構成には、$O(n)$可能な交換とその後$k$これは指数関数的に増加します。 小さいものでも$n$、これはまったく不可能です。 

次のステップは、スワップのシーケンスという観点から考えるのをやめ、代わりに要素がどこまで移動できるかという観点から考えることです。 各スワップでは、正確に 2 つの要素の位置が 1 ステップずつ変更されます。 隣接させたい 2 つの要素を追跡する場合、関連する唯一の質問は、それらを隣り合わせるために何回のスワップが必要かということです。 

位置に 2 つの値を取るとします。$i$そして$j$、 と$i < j$。 それらを隣接させるには、それらの間の隙間をなくす必要があります。 スワップごとに、このギャップは最大で 1 つずつ減少します。 したがって、それらを隣接させるために必要なスワップの最小数は次のとおりです。$j - i - 1$。 この観察により、問題は、距離が十分に小さいインデックスのペアを選択することに変換されます。 

最終的な隣接ペアとして、任意の値のペアを自由に選択できます。 だから私たちは最大化したいのです$|c_i - c_j|$の対象となる$j - i - 1 \le k$、または同等の$j - i \le k + 1$。 

この再定式化により構造が完全に変わります。 順列について推論する代わりに、制限されたインデックス距離内にあるペアを考慮するだけで済みます。 有効なペアごとに、それらを統合するためにスワップを費やすことを想像します。配列の残りの部分は、実現可能性に影響を与えることなく、常にそれらを中心に調整できます。 

This leads to a sliding window perspective. Any pair of indices inside a segment of length$k + 2$距離制約を自動的に満たします。 逆に、有効なペアはそのようなセグメント内に存在する必要があります。 したがって、問題は、任意のサイズのウィンドウ内の任意の 2 つの値間の最大差を見つけることになります。$k + 2$。 

固定ウィンドウ内では、最適なペアは単にそのウィンドウ内の最小値と最大値です。 したがって、すべてのサイズのウィンドウにわたって移動ウィンドウの最小値と最大値を維持する必要があります。$k + 2$。

 ## アルゴリズムのチュートリアル

 1. 有効ウィンドウ サイズを計算します。$w = k + 2$。 もし$w \ge n$, treat the entire array as one window. これは、許可されたスワップ内で任意の 2 つの要素を隣接させることができる場合に対応します。 
2. 配列上でスライディング ウィンドウを使用して、現在のウィンドウの最大値と最小値を維持します。 これは、2 つの単調デキューを使用して効率的に実行されます。1 つは最大値の減少値を維持し、もう 1 つは最小値の増加値を維持します。 
3. ウィンドウの右端ごとに、単調な順序を維持しながら新しい要素を両方の両端キューに挿入します。 単調性に反する要素は後ろから削除されます。 
4. Once the window size exceeds$w$、各両端キューの先頭から左側の境界から外れる要素を削除します。 
5. 各ウィンドウ調整後、最大デクの前と最小デクの前の差を計算します。 すべてのウィンドウにわたってそのような最大の差を追跡します。 

これが機能する理由は、どの最適解も、最大で 2 つの要素が隣接する 2 つの要素を選択することに相当するためです。$k$交換します。 これら 2 つの要素はもともと距離以内にある必要があります$k+1$これにより、あるサイズのウィンドウ内でそれらが一緒に表示されることが保証されます。$k+2$。 そのウィンドウ内では、ウィンドウ制約内で許可されたスワップを使用してこれら 2 つの値を常に隣り合わせに配置できるため、再配置後の最大の隣接差は、正確にその最小値と最大値の差になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    w = k + 2
    if w >= n:
        print(max(a) - min(a))
        return

    maxdq = deque()
    mindq = deque()
    ans = 0

    l = 0
    for r in range(n):
        while maxdq and a[maxdq[-1]] <= a[r]:
            maxdq.pop()
        maxdq.append(r)

        while mindq and a[mindq[-1]] >= a[r]:
            mindq.pop()
        mindq.append(r)

        if r - l + 1 > w:
            if maxdq[0] == l:
                maxdq.popleft()
            if mindq[0] == l:
                mindq.popleft()
            l += 1

        if r - l + 1 == w:
            ans = max(ans, a[maxdq[0]] - a[mindq[0]])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ウィンドウからスライドアウトする要素を効率的に削除できるように、値ではなく両端キューにインデックスが保持されます。 単調プロパティにより、各両端キューの先頭が常に現在のウィンドウの極値を表すことが保証されます。 唯一のデリケートな部分は、ウィンドウのサイズを正確に維持することです。ウィンドウは$k+2$リダクション引数には無効です。 

## 実用的な例

 ### 例 1

 入力:```
4 0
1 3 2 4
```ここでのウィンドウサイズは$k+2 = 2$。 隣接するペアのみを調べます。 

| ウィンドウ | 要素 | 分 | マックス | 違い |
 | --- | --- | --- | --- | --- |
 | [1,3] | 1,3 | 1 | 3 | 2 |
 | [3,2] | 3,2 | 2 | 3 | 1 |
 | [2,4] | 2,4 | 2 | 4 | 2 |

 最大値は 2 で、これは元の配列内の最良の隣接差に一致します。 

これは、スワップが許可されない場合、アルゴリズムが隣接するペアのスキャンに限定されることを確認します。 

### 例 2

 入力:```
4 2
1 3 2 4
```今$w = 4$したがって、配列全体が 1 つのウィンドウになります。 

| ウィンドウ | 要素 | 分 | マックス | 違い |
 | --- | --- | --- | --- | --- |
 | [1,3,2,4] | 1,3,2,4 | 1 | 4 | 3 |

 結果は 3 です。これは、2 つのスワップで 1 と 4 を隣り合わせて、可能な最大のスプレッドを達成できるという事実に対応します。 

これは、配列がグローバルに柔軟になり、極値のみが重要になる状況を示しています。

 ## 特殊なケース

 いつ$k = 0$、アルゴリズムセット$w = 2$、したがって、隣接するペアのみが考慮されます。 これは、スワップが許可されていないという事実と一致するため、答えは元の構成から直接得られる必要があります。 

いつ$k \ge n - 2$、ウィンドウ サイズは少なくとも$n$したがって、アルゴリズムはコンピューティングに組み込まれます。$\max(c) - \min(c)$。 この体制では、配列全体にわたって要素を移動する十分な自由があるため、任意のペアを隣接させることができます。 

すべての値が等しい場合、各ウィンドウの差はゼロになり、両端キューは同一の最大値と最小値を正しく維持します。 このアルゴリズムは引き続きフルパスを実行しますが、すべてのウィンドウの両端が同一であるため、過大評価することはありません。
