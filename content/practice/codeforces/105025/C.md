 ## 解決策
 ## 問題の理解

 屋根の連続したセグメントを表す一連の高さが与えられます。 各セグメントの高さは固定されており、これらのセグメントの連続した間隔にソーラー パネルを配置したいと考えています。 唯一の制約は、選択した間隔内で高さが単調で、完全に減少しない、または完全に増加しないことです。 

タスクは、そのような最長の連続間隔を見つけて、そのエンドポイントを出力することです。 

入力サイズは最大 100 万要素まで可能です。 これにより、すべてのサブ配列を明示的に検査するアプローチは即座に除外されます。 エンドポイントのすべてのペアにわたる二次スキャンには、約 10^12 の操作が必要ですが、これは制限時間をはるかに超えています。 キュービックまたはネストされたスキャン手法でさえ明らかに不可能です。 

線形または線形に近いスキャンが必要です。つまり、単調性の局所構造を維持しながら配列を単一パスで処理するソリューションを期待する必要があります。 

最適なセグメントが同じ値の長い範囲にまたがる場合、微妙なエッジ ケースが発生します。 たとえば、5 5 5 5 5 のような配列は、非減少としても非増加としても有効であるため、配列全体を返す必要があります。 勾配の変化において等しい要素を一貫性なく扱うソリューションは、このケースを破る危険があります。 

もう 1 つのエッジ ケースは、1 3 2 4 3 5 のように、配列が厳密に交互である場合です。その場合、最長の単調セグメントは長さ 2 のみになる可能性があり、方向が変化するたびに解が正しくリセットされる必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。エンドポイント l と r のすべてのペアを試し、セグメントが減少していないか増加していないかを確認し、最大長を追跡します。 各セグメントの単調性の検証には O(n) 時間がかかり、O(n^2) 個のセグメントがあり、全体で O(n^3) になります。 プレフィックス比較を使用してチェックを最適化したとしても、最終的には O(n^2) になり、10^6 までの n には遅すぎます。 

重要な観察は、単調性は局所的な特性であるということです。 一度方向性を確立したら、それは崩れるまで続けます。 これは、配列を最大の単調ランに分解でき、答えはこれらのランの 1 つ、または転換点を共有する 2 つのランの組み合わせである必要があることを意味します。 

より正確に言うと、各ポジションを「転換点」の可能性として捉えると、非減益・非増益のどちらかの状態を維持したまま、左右に拡大することが可能です。 l ごとに最初から再計算する代わりに、近隣からの情報を再利用し、実行中のセグメントを維持できます。 

これにより、増加と減少の 2 種類の単調セグメントを動的に追跡するリニア スキャン ソリューションが得られます。 できるだけ長く延長し、状態が崩れたらリセットします。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列をトラバースするときに 2 つの連続長を維持します。位置 i で終了する非減少セグメントの現在の長さと、位置 i で終了する非増加セグメントの現在の長さです。 また、これまでに確認された最高のセグメントも追跡します。

1. 最初の要素で長さの増加と減少の両方を 1 に初期化します。 この時点では、単一の要素は自明に有効です。 
2. インデックス 1 から開始して配列を左から右に繰り返します。 
3. 現在の高さが前の高さ以上の場合、減少しないセグメントを延長できます。 それ以外の場合は、単調性が壊れているため、長さ 1 にリセットします。 
4. 現在の高さが以前の高さ以下の場合、増加しないセグメントを拡張できます。 それ以外の場合は、長さ 1 にリセットします。 
5. 両方の状態を更新した後、i での現在の最良の終了をグローバル最良の回答と比較します。 いずれかの単調方向により長いセグメントが生成される場合は、それに応じて保存されている最良のエンドポイントを更新します。 
6. 各実行の開始場所を覚えておくことで、常に正しいセグメント境界を維持しながら、配列の最後まで続行します。 

重要な詳細は、長さだけでなく、現在の各実行の開始インデックスも追跡する必要があるということです。これは、答えには長さだけでなくエンドポイントが必要であるためです。 

### なぜ効果があるのか

 すべての位置 i で、i で終わる有効な単調部分配列は、i で終わる最大の非減少ラン、または i で終わる最大の非増加ランの一部でなければなりません。 これらの実行はローカル比較によって一意に決定されるため、単調性に違反することなくさらに拡張することはできません。 すべての有効な解はこれらの最大実行の 1 つに含まれるため、すべての実行をチェックすると暗黙的にすべての候補がカバーされます。 すべての有効な間隔は、これらの維持された単調セグメントのいずれかの接尾辞であるため、アルゴリズムは候補を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = input().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    h = list(map(int, input().split()))
    
    if n == 1:
        print(1, 1)
        return

    best_len = 1
    best_l = 1
    best_r = 1

    inc_start = 0
    dec_start = 0
    inc_len = 1
    dec_len = 1

    for i in range(1, n):
        if h[i] >= h[i - 1]:
            inc_len += 1
        else:
            inc_len = 1
            inc_start = i

        if h[i] <= h[i - 1]:
            dec_len += 1
        else:
            dec_len = 1
            dec_start = i

        if inc_len > best_len:
            best_len = inc_len
            best_l = inc_start + 1
            best_r = i + 1

        if dec_len > best_len:
            best_len = dec_len
            best_l = dec_start + 1
            best_r = i + 1

    print(best_l, best_r)

if __name__ == "__main__":
    solve()
```この実装では、2 つの独立したスライディング ウィンドウが維持されます。 次の要素が小さくない場合、増加するウィンドウは拡張されます。それ以外の場合はリセットされ、現在のインデックスから開始されます。 減少するウィンドウは対称的に動作します。 

実装の重要な詳細は、リセットが発生すると、開始インデックスが前の位置ではなく現在の位置に設定されることです。 これにより、セグメントがそれぞれ 3 と 2 で再開する必要がある 1 3 2 のような厳密な反転の正確性が保証されます。 

また、最適なインデックスを 1 ベースの形式で維持し、出力時にのみ 0 ベースのインデックスから変換します。

 ## 特殊なケース

 7 7 7 7 7 のような定数配列の場合、両方の単調条件が常に当てはまります。 このアルゴリズムは、inc_len と dec_len の両方を継続的に拡張し続け、リセットをトリガーすることはありません。 最良のセグメントは最終インデックスで更新され、範囲全体をカバーし、1 5 が正しく生成されます。 

1 3 2 4 のような鋭いジグザグの場合、増加するセグメントは 2 と 4 でリセットされ、減少するセグメントは 3 でリセットされます。有効な最長ランは方向に応じて 1 3 または 3 4 で、アルゴリズムは長さ 2 のセグメントを最適なものとして正確に識別します。 

5 4 3 2 のような厳密に単調減少する入力の場合、減少カウンタは中断することなく各ステップで増加します。 増加するカウンターは各ステップでリセットされますが、減少する実行が支配的であるため、最終的な答えには影響しません。
