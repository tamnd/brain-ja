 ## 解決策
 ## 問題の理解

 1 から m までの番号が付けられた位置の行と、重み付けされたセグメントのコレクションが与えられます。 各セグメントはこれらのポジションの連続した間隔をカバーしており、それを使用することを選択した場合はコストがかかります。 セグメントを使用すると、そのコストを支払い、その区間内のすべてのポジションがカバーされることになります。 

通常、1からmまでのあらゆるポジションを最小のトータルコストでカバーしたいと考えます。 これは、最適化問題をカバーする標準的な間隔です。 ここでの工夫は、ちょうど 1 つの位置をカバーしないままにしておくことができ、残りの m − 1 位置を最小限のコストでカバーできるように、どの位置をスキップするかを選択したいことです。 

出力は、単一のカバーされていないポジションのすべての選択肢に対する可能な最小コスト、または 1 つのポイントを削除する選択肢がなく残りのポイントがカバー可能になる場合は -1 です。 

制約は最大 300,000 セグメントと 300,000 位置まで適用されます。 削除されたポイントごとに最適なカバーを個別に再計算しようとするソリューションでは、長間隔の DP または貪欲チェックをおよそ m 回実行する必要があり、最悪の場合、少なくとも 10^10 の操作が必要になります。 それは制限時間をはるかに超えています。 これにより、グローバル構造を前処理し、削除されたすべての候補位置にわたってそれを再利用するソリューションが強制されます。 

カバレッジが「ほぼ完全」だが脆弱な場合、微妙な失敗例が発生します。 たとえば、すべての位置が 1 つの高価なセグメントのみでカバーされている場合、間違ったポイントを削除すると、完全なカバレッジが存在していてもカバレッジが不可能になる可能性があります。 もう 1 つの失敗ケースは、最適なソリューションが重複するセグメントを多用しており、最適なソリューションはどの点が除外されるかによって決まるため、貪欲なプレフィックス構築だけでは不十分な場合です。 

## アプローチ

 単純な考えは、削除された点 x を修正し、考慮から削除し、残りのすべての位置をカバーするための最小コストを計算することです。 これは、直線上の古典的な加重区間カバー問題であり、DP またはスイープベースの構造で解決できます。 ただし、これを x ごとに独立して実行すると、おおよそ O(n log n) または O(n) の解に m が乗算されますが、指定された制限ではこれは不可能です。 

重要な観察は、点を削除しても区間の構造を実際に変更しているわけではないということです。 1 つを除くすべてのポジションのカバーを要求しています。これは、少なくとも 1 つのポジションがカバーされていない完全なセグメント [1, m] のカバーを要求するのと同じですが、そのカバーされていないポジションはどこでも選択できます。 

点を削除するという観点から考えるのではなく、視点を反転します。 各位置 x について、x は必ずしもカバーされないが、他のすべてがカバーされるように、すべての間隔の最小コスト カバーが必要です。 これは、プレフィックスとサフィックスをカバーする最良の方法に関する情報を維持し、それらを「穴」に合わせて組み合わせるということを示唆しています。 

これにより、当然のことながら、両面の動的プログラミング構造が生まれます。 各位置で終わるプレフィックスをカバーするための最小コストを事前に計算し、同様のサフィックス情報も計算すると、必ずしも x をカバーする必要のない間隔で、x の左側の最適なカバーと x の右側の最適なカバーの組み合わせとして点 x をスキップするコストを評価できます。 

高速計算をサポートするために、ソートされた順序でセグメントを処理し、dp[i] がプレフィックス [1, i] をカバーする最小コストである位置にわたる DP を維持します。 これは、有効な開始点から最良の dp 値を取得できる構造を使用して、i を 1 から m までスキャンし、i で終わるすべてのセグメントを緩和することによって計算されます。 対称 DP は右から計算されます。 

最後に、スキップされる可能性のある位置 x ごとに、[1, x − 1] と [x + 1, m] をカバーする最適な方法を計算し、分離を無効にする方法で x をカバーするセグメントが強制的に発生しないようにします。 答えはすべての x の最小値です。

 | --- | --- | --- | --- |
 | 削除されたポイントごとに DP を再計算する | O(m · n log n) | O(n) | 遅すぎる |
 | スイープ最適化によるプレフィックス/サフィックス DP | O(n log n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP をカバーする標準の加重間隔を中心にソリューションを構築し、それを拡張して 1 つの「穴」を許可します。 

1. すべてのセグメントを正しいエンドポイントで並べ替えます。 これにより、カバレッジを左から右に段階的に処理できるようになります。 
2. dp[i] が 1 から i までのすべての点をカバーする最小コストである DP 配列を維持します。 dp[0] = 0 とその他すべてを無限として初期化します。 
3. 1 から m までの各位置 i について、i で終わるすべてのセグメントを考慮します。 コスト c のセグメント [l, i] は、プレフィックス [1, l − 1] の有効なカバーを [1, i] のカバーに拡張できます。 したがって、 dp[i] = min(dp[i], dp[l − 1] + c) を更新してみます。 これは、i に到達するために使用される最後のセグメントは i で終了する必要があるという考えを捉えています。 
4. ステップ 3 を高速化するために、正しいエンドポイントごとにセグメントを事前にグループ化します。 これにより、各位置ですべてのセグメントをスキャンすることが回避されます。 
5. 次に、右側から 2 番目の DP を計算します。 suf[i] を i から m までのすべての位置をカバーする最小コストとする。 m から 1 までの位置を処理し、セグメント [i, r] を同様に使用して、suf[i] = min(suf[i], suf[r + 1] + c) を更新します。 
6. これら 2 つのパスの後、各位置 x を削除することを検討できます。 x が削除された場合、[1, x − 1] と [x + 1, m] を処理するカバーが必要になります。 左側の部分は dp[x − 1] に寄与し、右側の部分は suf[x + 1] に寄与します。 
7. ただし、これは両方の部分が独立してカバー可能な場合にのみ機能します。 dp[x − 1] または suf[x + 1] のいずれかが無限大の場合、その分割は無効です。 
8. dp[x − 1] + suf[x + 1] のすべての x の最小値として答えを計算します。 有限値を生成する x がない場合は、-1 を出力します。 

### なぜ効果があるのか

 dp 配列は、特定の境界で終了する間隔を使用してプレフィックスをカバーする最適なコスト構造を取得します。 プレフィックスの最適なソリューションは、その最後の間隔によって分解できます。 同じ構造が接尾辞にも対称的に当てはまります。 単一の点 x を削除すると、有効な解は x で 2 つの独立した区間カバーに分割されなければなりません。これは、実現可能性を変える方法で x を橋渡しする区間が必要ないためです。 したがって、最適解は常に、左の最適なプレフィックス カバーと右の最適なサフィックス カバーとして表現可能であり、すべての分割点を試すことで、省略された位置の可能なすべての選択肢がカバーされます。

| 私 | i で終わるセグメント | dp[i] の計算 | dp[i] |
 | --- | --- | --- | --- |
 | 1 | (1,1,3) | dp[0] + 3 = 3 | 3 |
 | 2 | (1,2,8)、(2,2,4) | min(dp[0]+8, dp[1]+4) = min(8,7) | 7 |
 | 3 | (3,3,2) | dp[2] + 2 = 9 | 9 |

x = 1 を削除すると、コスト = dp[0] + suf[2] = 0 + 5 = 5 (最適なサフィックス構造から)。 

x = 2 を削除すると、コスト = dp[1] + suf[3] = 3 + 2 = 5 となります。 

x = 3 を削除すると、コスト = dp[2] + suf[4] = 7 + 0 = 7 となります。 

最小値は 5 です。 

これは、最適なホールが必ずしもエンドポイントにあるわけではなく、答えはグローバルな分割に依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、1 つのポイントを除くすべてをカバーする唯一の方法が、そのポイントを横切るセグメントの使用を避けることである場合です。 このような場合、分割は dp と suf の両方が有限のままである位置に正確に位置合わせする必要があります。 無効な分割は少なくとも片側で INF を生成するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、x = 1 や x = m など、境界に点を残す場合です。 次に、片側が空になり、dp[0] = 0 または suf[m + 1] = 0 が空のカバレッジ コストを正しく表します。 この式は特別な場合を除いて適用されます。 

3 番目のエッジ ケースは、完全なカバレッジが存在するにもかかわらず、任意のポイントを削除すると実現可能性が損なわれる場合に発生します。 その場合、すべての x について、dp[x − 1] または suf[x + 1] のいずれかが無限になります。 有効な分割が有限候補に寄与しないため、アルゴリズムは正しく -1 を返します。
