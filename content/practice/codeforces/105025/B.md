 ## 解決策
 ## 問題の理解

 2 つの正の整数が与えられます$k$そして$n$。 それらはコインの価値の隠されたペアを記述します$A$そして$B$同時に 2 つの制約の下で。 まず、一方のコインの価値はもう一方の価値の乗算スケーリングです。$A = k \cdot B$。 次に、同じ 2 つの値が加法的に関連します。$A = B + n$。 

タスクは、正の整数が存在するかどうかを判断することです$A$そして$B$両方の方程式を同時に満たします。 そのようなペアが存在する場合は、1 つの有効な解を出力する必要があります。 それ以外の場合は出力します$-1$。 

このステートメントは 2 つの方程式系のように見えますが、重要な難しさは、代数を単独で解くことではなく、結果の値が整数であり、制約の下で正の値を維持することを保証することです。 

制約により許可されるのは、$k, n \le 10^9$したがって、どのソリューションもテスト ケースごとに一定時間で実行する必要があります。 可能性のある総当たり検索$A$または$B$値は次のように大きくなる可能性があるため、これは不可能です$10^9$、その境界まで反復しても時間制限を超えてしまいます。 

よくある間違いは、方程式を独立して扱うことから生じます。 たとえば、$B = n$または$A = k + n$両方の方程式が同時に成り立つ必要があることを無視します。 別の微妙な問題が発生する場合、$k = 1$なぜなら、システムは退化しており、次のように分割する多くのアプローチがあるからです。$k - 1$壊す。 

具体的なエッジケースは、$k = 1, n = 3$。 それから$A = B$最初の方程式からだけでなく、$A = B + 3$2番目からは不可能です。 盲目的に計算するソリューション$B = n / (k - 1)$ゼロで割ると失敗します。 

## アプローチ

 問題は、隠れた一次方程式の直接系です。 強引なアイデアは、可能な値をすべて試してみることです。$B$両方の方程式が同じ結果をもたらすかどうかを確認します$A$。 それぞれについて$B$、計算します$A_1 = kB$そして$A_2 = B + n$、等価性を確認します。 これは正しいですが、すぐには実行不可能です。$B$まで行くことができます$10^9$、最悪の場合は直線的な時間につながります。 

重要な点は、検索する必要がまったくないということです。 の 2 つの表現$A$は等しい必要があるので、それらを直接同等にします。$$kB = B + n$$並べ替えると次のようになります。$$(k - 1)B = n$$これで構造はシンプルになりました。 もし$k = 1$、方程式は次のようになります$0 \cdot B = n$、これは次の場合にのみ可能です$n = 0$、 しかし$n \ge 1$, したがって、解決策はありません。 それ以外の場合は、$B = \frac{n}{k - 1}$、この値は整数である必要があります。 一度$B$決まっている、$A = kB$。 

これにより、問題全体が一定数の算術チェックに減ります。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$k$そして$n$。 これらは、間の比例関係と加算関係を定義します。$A$そして$B$。 
2. かどうかを確認します。$k = 1$。 そうであれば、両方の方程式は次のようになります。$A = B$ただし、2 番目の方程式には次のことが必要です。$A = B + n$、これはどんなポジティブなことでも不可能です$n$。 この場合、出力$-1$。 
3. もし$k \ne 1$、計算する$k - 1$。 この値は、等価性を超えるスケーリングがどの程度適用されるかを表します。$B$。 
4. かどうかを確認します。$n$で割り切れます$k - 1$。 これにより、$B = \frac{n}{k - 1}$は整数です。 割り切れない場合は、有効な整数解が存在しないため、出力$-1$。 
5. 割り切れる場合は計算する$B = n // (k - 1)$。 これは、両方の制約を満たす唯一の候補値です。 
6. コンピューティング$A = k \cdot B$。 これにより、乗算方程式と加算方程式の両方が同時に成り立つことが保証されます。 
7. 出力$A$そして$B$。 

### なぜ効果があるのか

 両方の制約が同じ変数の一次式を定義します$A$。 このアルゴリズムは、それらを等式化することで一貫性を強制し、問題を単一の線形ディオファントス方程式に還元します。 置換後の未知数は 1 つだけであるため、整数解が 1 つだけ存在するか、まったく存在しないかのどちらかです。 すべてのステップで等価変換が維持されるため、生成される解は元の方程式の両方を満たさなければならず、有効な解は導出された割り切り条件を満たさなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k, n = map(int, input().split())

if k == 1:
    # A = B and A = B + n => impossible for n > 0
    print(-1)
else:
    if n % (k - 1) != 0:
        print(-1)
    else:
        b = n // (k - 1)
        a = k * b
        if b > 0 and a > 0:
            print(a, b)
        else:
            print(-1)
```コードは導出された方程式に直接続きます。 特別な場合$k = 1$ゼロ除算を避けるために明示的に処理されます。 可分性チェックにより、整数解のみが構築されることが保証されます。 陽性チェックは制約の下では技術的に冗長です$k, n \ge 1$ただし、不正な派生から保護され、ロジックが明示的に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    k, n = map(int, input().split())

    if k == 1:
        return "-1\n"
    if n % (k - 1) != 0:
        return "-1\n"

    b = n // (k - 1)
    a = k * b

    if b > 0 and a > 0:
        return f"{a} {b}\n"
    return "-1\n"

# provided samples
assert run("6 15\n") == "18 3\n"
assert run("1 3\n") == "-1\n"

# custom cases
assert run("2 2\n") == "2 1\n"   # smallest non-trivial solution
assert run("3 0\n") == "-1\n"    # impossible since n >= 1 in statement
assert run("5 20\n") == "25 5\n"  # clean divisible case
assert run("4 7\n") == "-1\n"     # non-divisible case
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 ## 特殊なケース

 ### ケース$k = 1$入力`1 3`力$A = B$乗算制約から、そして$A = B + 3$加法的制約から。 アルゴリズムはすぐに分岐します$k = 1$そして出力$-1$演算を行わないため、ゼロ除算の状況が防止されます。 

### 割り切れない$n$入力`4 7`につながる$B = 7 / 3$、これは整数ではありません。 アルゴリズムはこれを次のように検出します。`n % (k - 1) != 0`そしてその訴訟を拒否します。 そうしないと端数のコイン価値が誤って受け入れられてしまうため、これは不可欠です。 

### 最小の有効なシステム

 入力`2 2`与える$B = 2 / 1 = 2$、$A = 4$。 このアルゴリズムは有効なペアを正しく構築して出力し、可算性と正数性を超える追加の制約が必要ないことを確認します。
