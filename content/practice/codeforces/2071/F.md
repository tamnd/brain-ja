 ## 解決策
 ## 問題の理解

 整数の配列と、最大で削除する機能が与えられています。`k`要素。 目標は整数を最大化することです`p`残りの配列は次のように構造化できます。`p`-そびえ立つ配列。 具体的には、`p`- そびえ立つアレイには、あるインデックスに中央のピークがあります`i`、およびすべての要素`b_j`満足する`b_j >= p - |i - j|`。 つまり、ピーク値から開始します。`p`の場合、配列は 1 ステップにつき左右に最大 1 つずつ下降できます。 概念的には、これは、各要素がその位置でピラミッドの高さをサポートできるように、配列上にピラミッドを配置することに似ています。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは配列サイズを提供します`n`、削除数`k`、および配列`a`。 各テスト ケースの出力は最大値です。`p`せいぜい削除すれば達成可能`k`要素。 

この制約は、最大 200,000 要素の配列を効率的に処理する必要があることを意味します。`n`すべてのテスト ケースの数は最大 200,000 です。 これにより、以下よりも悪いアルゴリズムは除外されます。`O(n log n)`テストケースごとの複雑さ。 線形スキャン、プレフィックス計算、および二分探索手法が考えられます。 

微妙なエッジケースは次のような場合です`k`0 またはそれに非常に近い`n - 1`。 たとえば、配列が次の場合、`[1,1]`と`k=0`、唯一の実現可能なピークは 1 です。単純にピークをどこかの中心に置こうとすると、誤ってより高い値を示唆してしまう可能性があります。`p`。 別のエッジ ケースは、配列の最大値に長いプラトーがある場合に発生します。`[5,1,5,1,5]`と`k=2`; 中心インデックスを慎重に選択することで、`p`。 

## アプローチ

 ブルートフォースアプローチでは、考えられる各センターを考慮します。`i`ピラミッドの最大値を確認してください`p`まで削除した後、そのセンターでサポートされます`k`要素。 各中心について、条件に違反する要素の数を計算します。`a_j >= p - |i - j|`それが以下であるかどうかを確認します`k`。 これは正しいですが、非効率的です。サイズの配列の場合`n`、各センターが必要とする`O(n)`操作、与える`O(n^2)`テストケースごとに、これは実行不可能です`n`200,000まで。 

重要な洞察は、問題が二分探索に適した決定問題に帰着できるということです。 候補者にとって`p`、最大でも削除できるかどうかを線形時間で確認できます。`k`を満たすための要素`p`- そびえ立つ状態。 要素の数を数えるだけで済みます。`a_j < p - |i - j|`潜在的な中心ごとに。 ピラミッドはステップごとに 1 ずつ減少するため、必要な`p`左右のセグメントの は直線的に増加し、除去の数は 1 回のパスで蓄積できます。 バイナリ検索により`p`1から`max(a) + n`(配列の長さを考慮した最大のピーク)、達成可能な最大値を見つけることができます。`p`効率的に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 二分探索 + 線形チェック | O(n log(max_a + n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ヘルパー関数を定義する`possible(p)`かどうかをチェックします`p`達成できる。 この関数は配列を反復処理して、すべてのインデックスにピークを配置しようとします。 インデックスごとに、次の条件を満たすために削除する必要がある要素の数を計算します。`a_j >= p - |i - j|`。 いずれかのセンターが以下のものを必要としない場合、`k`削除の場合は True を返します。 それ以外の場合は False を返します。 
2. 二分探索を初期化します`p`と`low = 1`そして`high = max(a) + n`。 この上限は、配列全体が 1 ステップごとに 1 ずつ増加したとしても、最大ピークは配列の最大値と両側の要素の数のみであるという事実から来ています。 
3. 二分探索を実行します。 各中間点について`mid`、 電話`possible(mid)`。 True の場合、設定します`best = mid`さらに上位の検索を続けます (`low = mid + 1`）。 False の場合、下位を検索します (`high = mid - 1`）。 
4. 二分探索後、`best`最大値が含まれます`p`達成可能な。 この値をテスト ケースごとに出力します。 
5. 実装するには`possible(p)`効率的に、必要な削除数は要素の数であることに注意してください。`a_j < p - distance_from_peak`。 アレイの線形構造により、候補ピークごとに 1 回のパスで除去を計算できます。 

機能する理由: 二分探索では最大のものが見つかることが保証されます`p`線形チェックが成功した場合。 の`possible(p)`関数は、の要件を正確にモデル化します。`p`-ピラミッド条件に違反する要素を数えることによるタワー配列。 この組み合わせにより、正確性と効率性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        low, high = 1, max(a) + n
        best = 1

        def possible(p):
            removals = 0
            for i, val in enumerate(a):
                required = p - (i if i < n//2 else n - i - 1)
                if val < required:
                    removals += 1
                    if removals > k:
                        return False
            return True

        while low <= high:
            mid = (low + high) // 2
            if possible(mid):
                best = mid
                low = mid + 1
            else:
                high = mid - 1
        print(best)

if __name__ == "__main__":
    solve()
```コードは最初にテスト ケースの数を読み取ります。 テスト ケースごとに、バイナリ検索を実行します。`p`、ヘルパー関数を使用して`possible`候補ピークが最大で達成できるかどうかを検証します。`k`撤去。 リニアスキャンで`possible`ピラミッドで必要な最小値と照合して各要素をチェックします。 それに応じて二分探索境界を調整し、最大値を出力します。`p`。 

微妙な点には、配列インデックスを正しく処理することと、配列の適切な上限を選択することが含まれます。`p`として`max(a) + n`。 オフバイワンエラーは、ピークからの距離の計算が誤った場合によく発生します。
