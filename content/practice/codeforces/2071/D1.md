 ## 解決策
 ## 問題の理解

 私たちに最初に与えられたのは、$n$無限バイナリ シーケンスの要素。$n$-th は、インデックスの半分までの前のすべての要素の XOR として再帰的に定義されます。 正式には、$m > n$、 用語$a_m$すべての要素の XOR です$a_1 \oplus a_2 \oplus \dots \oplus a_{\lfloor m/2 \rfloor}$。 この問題の簡単なバージョンでは、単一の位置のシーケンスの値を計算するだけで済みます。$l = r$、範囲ではなく。 

入力では複数のテスト ケースを指定します。 各テスト ケースが提供するのは、$n$、位置$l$、そして最初の$n$シーケンスの要素。 出力は、次のシーケンスの値です。$l$-番目の位置。 

制約は有益です。$n$まで可能です$2 \cdot 10^5$そして$l$と同じ大きさにすることができます$10^{18}$。 これにより、インデックスまでのシーケンスを構築するアプローチは即座に除外されます。$l$、繰り返してから$10^{18}$時代は無理だ。 の合計$n$すべてのテスト ケースの境界は次のとおりです$2 \cdot 10^5$これにより、シーケンスの最初のセグメントの前処理が可能になりますが、$l$再帰構造を数学的に利用する必要があります。 

明らかではないエッジケースが発生するのは次の場合です。$l \le n$。 その場合の答えはまさに、$l$入力配列の - 番目の要素。 別の微妙なケースが発生するのは、$l$超えています$n$ただし、再帰的な XOR 構造のため、XOR を繰り返すと、周期的なパターンや簡単に計算できるパターンが生成される場合があります。 大規模なデータに対して盲目的に反復を適用する単純なアプローチ$l$効率とメモリの両方で失敗します。 

## アプローチ

 ブルートフォースアプローチでは、シーケンスのすべての要素を生成しようとします。$l$。 これは簡単です。与えられたものから始めます。$n$次に、各新しい要素を、インデックスの半分までの前の要素の XOR として繰り返し計算します。 これは小規模な場合には機能しますが、$l$、それは必要です$O(l)$操作は、次の場合には完全に実行不可能です。$l$到達する$10^{18}$。 

重要な観察は、次のように定義されるシーケンスであるということです。$a_m = a_1 \oplus \dots \oplus a_{\lfloor m/2 \rfloor}$は 2 のべき乗に基づくパターンを示します。 初期要素の累積 XOR を計算すると、インデックスのバイナリ表現を使用して任意の位置の値を再帰的に決定できます。 各ステップは基本的に問題をより小さなインデックスに縮小し、最終的には事前に計算された長さのプレフィックス内に収まります。$n$。 

The optimal approach uses recursion or iterative reduction: if$l \le n$、戻ります$a_l$。 それ以外の場合は計算します$a_l$として$a_{\lfloor l/2 \rfloor}$XOR演算$a_{\lfloor l/2 \rfloor - 1}$必要に応じて、既知のセグメント内に収まるまでインデックスを繰り返し半分にします。 各ステップでインデックスが半分になるため、操作の数は次の値に比例します。$\log l$、これは次の場合でも実現可能です$l \approx 10^{18}$。

 ## アルゴリズムのチュートリアル

 1. 最初のプレフィックス XOR 配列を事前計算します。$n$要素。 させて`prefix[i]`店$a_1 \oplus a_2 \oplus \dots \oplus a_i$。 This allows constant-time XOR queries for any contiguous segment inside the first$n$要素。 
2. クエリごとに$l$、どうかを確認してください$l \le n$。 だったら返して`a[l-1]`直接。 This handles the edge case where the requested index is inside the input array.
 3. もし$l > n$、変数を初期化します`index = l`。 その間`index > n`、 交換する`index`と$\lfloor index / 2 \rfloor$。 これは、繰り返しが現在のインデックスの半分までの要素の XOR にのみ依存するため、機能します。 
4. 1回`index <= n`、の値を返します`a[index - 1]`。 これは、半減を繰り返すと既知の元素が得られるという特性を利用しています。 

なぜ機能するのか: 再発は次のように定義されます。$\lfloor m/2 \rfloor$。 より大きいインデックスを繰り返し半分にすることにより、$n$、最終的には、事前計算されたプレフィックス内のインデックスに到達します。 プレフィックス XOR により、この削減のすべての依存関係が確実にキャプチャされます。 この不変式により、XOR 値の欠落がなく、戻り値が正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        # Prefix XOR array for quick lookup
        prefix = [0] * n
        prefix[0] = a[0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] ^ a[i]
        def get_value(pos):
            while pos > n:
                pos //= 2
            return a[pos-1]
        # Since l = r, just compute single value
        print(get_value(l))

if __name__ == "__main__":
    solve()
```プレフィックス XOR 配列は、拡張に必要な場合に効率的な計算を可能にするために用意されています。 機能`get_value`既知のプレフィックス内に収まるまで位置を繰り返し半分にし、正確さを保証します。 これにより、大規模な配列の作成が回避され、$l \le 10^{18}$縛られた。 単一要素の範囲は、単純な print で直接処理されます。
