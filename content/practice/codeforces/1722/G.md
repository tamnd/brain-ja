 ## 解決策
 ## 問題の理解

 各テスト ケースに対して、厳密に以下のような個別の非負の整数のシーケンスを構築するように求められます。$2^{31}$、非常に特殊なバランス条件があります。 位置パリティに基づいて配列を 2 つのグループに分割する場合、一方のグループの要素の XOR は、もう一方のグループの要素の XOR と一致する必要があります。 

位置のインデックスは 1 であるため、奇数のインデックスは 1、3、5 などとなり、偶数のインデックスは 2、4、6 などとなります。 この制約は純粋にグローバルです。プレフィックス構造や順序に関する要件はなく、2 つの XOR 集合体が一致し、すべての値が異なることのみが必要です。 

制約はテスト ケース全体で合計サイズが大きいため、テスト ケースごとに線形以上の作業を行うソリューションは困難になります。 全部を合計したので、$n$までです$2 \cdot 10^5$、意図したソリューションは本質的に次のようにする必要があります$O(n)$非常に小さな定数で、テストごとまたはそれ以上のパフォーマンスを実現します。 二次関数やサブセットの繰り返し検索やバックトラックを伴うものは、直ちに実行不可能になります。 

素朴な方向性としては、両側間の XOR の差を追跡しながら、貪欲に値を割り当ててみることです。 ただし、難しいのは、一度数字を配置すると再利用できず、将来の選択によって以前のバランスが無効になる可能性があることです。 もう 1 つの素朴なアイデアは、等しい XOR を持つサブセットを検索することですが、個別の制約に対するサブセット XOR 問題は組み合わせ的に爆発的です。 

微妙なエッジケースが現れるのは、$n$とても小さいです。 のために$n = 3$、3 つの異なる数値が必要なため、条件は厳しいです$a_1, a_2, a_3$そのような$a_1 \oplus a_3 = a_2$。 ペアリングの対称性を前提とした不用意な構築は、暗黙的に重複を使用したり、個別性を侵害したりすると失敗する可能性があります。 のために$n = 4$、インデックスがパリティ グループ間で不均一に分散されている場合、多くの単純な対称構造は壊れます。 

中心的な課題は、厳密な制限の下で区別性を維持しながら、XOR のグローバルなバランスをとらなければならないことです。 

## アプローチ

 ブルートフォース手法では、奇数位置と偶数位置の間の XOR の差を追跡しながら、数値を 1 つずつ割り当てようとし、各ステップで、ある制限の下ですべての未使用の整数を試します。 候補者を中程度の範囲に限定したとしても$0 \ldots 2n$、各配置は検索になります$O(n)$オプション、大まかに作成$O(n!)$または少なくとも指数関数的な動作。 これでは遅すぎる$2 \cdot 10^5$合計要素。 

重要な構造的観察は、XOR が線形に動作し、ペアでキャンセルできることです。 要素を対称 XOR キャンセル グループに構築できれば、パリティ分割は無関係になります。つまり、各グループの正味の不均衡はゼロになります。 

特に有用なアイデアは、XOR が結合的かつ可換であるという事実を利用し、各パリティ クラスの 1 つを除くすべての要素を制御すれば、最後の要素に不均衡を修正させることができるという事実を利用することです。 ただし、区別性を維持し、値を維持する必要があります。$2^{31}$これは、適応検索ではなく構造化セットを使用する必要があることを示唆しています。 

実際に使用されるクリーンな構造は、大きなオフセットから開始して連続する整数を取得し、慎重に選択した 1 つの要素を調整して XOR の等価性を強制することです。 ほとんどの数値を任意に割り当ててから、必要な最後の値を計算することで、バランスを確保できます。 唯一の複雑な点は、最終値が明確であり、範囲内であることを確認することですが、これは安全な上位ビット範囲を予約することで保証できます。 

これにより、問題は、全体的な制約を満たす問題から、決定論的なフィルと 1 つの XOR 修正に縮小されます。

 ## アルゴリズムのチュートリアル

 奇数位置と偶数位置の間の XOR の差を制御する方法で配列を構築します。 

1. 概念的にインデックスを奇数と偶数の位置に分割します。 値を順番に割り当てますが、各インデックスがどのパリティに属しているかを追跡します。 目標は、両方の XOR アキュムレータが最後に同じになるようにすることです。 
2. 最初の値を割り当てます$n-1$たとえばシーケンスを使用して、個別の値を貪欲に数値化する$1, 2, 3, \dots, n-1$。 割り当て中、2 つの実行中の XOR 値を維持します。1 つは奇数の位置用、もう 1 つは偶数の位置用です。 まだ条件を満たすつもりはなく、最終的な修正を準備しているだけなので、このステップは安全です。 
3.配置後$n-1$値の XOR の差を計算します。$$\Delta = (\text{XOR of odd positions}) \oplus (\text{XOR of even positions})$$この値は、不均衡を修正するために最後の要素が貢献する必要があるものを正確に表します。 
4. 最後の要素を所定の位置に配置します$n$として$\Delta$、ただし、それがまだ使用されていないことを確認した後でのみ。 衝突する場合は、より高い開始オフセットを確保して構築をわずかに変更し、構築されたすべての数値が XOR 結果と区別されるようにします。 
5. 構築された配列を出力します。 

微妙な考え方は、XOR は可逆であるということです。2 つの XOR が等しいことを望み、1 つの要素を除くすべての要素がわかっている場合、最後の要素は一意に決定されます。 これにより、最終的に計算された値の実現可能性を確保するという問題が軽減されます。 

### なぜ効果があるのか

 しましょう$X_o$奇数のインデックスにある要素の XOR であり、$X_e$最後の値を配置する前に、偶数のインデックスにある要素の XOR を計算します。 私たちが欲しいのは$X_o = X_e$。 最後の要素は、インデックス パリティに応じて、これら 2 つの XOR のいずれかにのみ影響します。 XOR は可逆であるため、最後の要素を現在の不均衡に正確に設定すると、差がキャンセルされます。 

以前のすべての要素は個別で固定されているため、十分に大きな初期範囲またはシフトを選択した場合、最終的に計算される値も一意になります。 維持される不変条件は、最後のものを除く各割り当ての後、すべての値が個別であり、XOR の不均衡が単一の値で完全にキャプチャされることです。$\Delta$、最終ステップで解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        # We construct numbers 1..n-1 first
        a = list(range(1, n))
        
        xor_odd = 0
        xor_even = 0
        
        # simulate placement
        for i, val in enumerate(a, start=1):
            if i % 2 == 1:
                xor_odd ^= val
            else:
                xor_even ^= val
        
        # determine last value needed
        last = xor_odd ^ xor_even
        
        # ensure distinctness: if collision, shift construction
        if last == 0 or last < n:
            # safe shift: use large offset
            offset = 1 << 20
            a = [x + offset for x in a]
            
            xor_odd = 0
            xor_even = 0
            for i, val in enumerate(a, start=1):
                if i % 2 == 1:
                    xor_odd ^= val
                else:
                    xor_even ^= val
            last = xor_odd ^ xor_even
            a.append(last)
        else:
            a.append(last)
        
        print(*a)

if __name__ == "__main__":
    solve()
```この構築は単純な逐次代入から始まるため、区別性は重要ではありません。 次に、XOR の差がパリティ位置から直接計算されます。 最後の値は、その差を正確にキャンセルするために選択されます。 

唯一のデリケートな部分は、計算された最終的な XOR 値と既に使用されている数値の間の衝突を回避することです。 コードは、大きなオフセットを使用してシフトされた構造にフォールバックすることでこれを処理し、すべての初期値が互いに素な高範囲内に存在するようにし、最終的な XOR 結果が構築されたセットと衝突する可能性が非常に低くなります。 

## 実用的な例

 2 つの代表的な入力の構築を追跡します。 

### 例 1: n = 4

 初期割り当ての用途$a = [1, 2, 3]$、次に最後の要素を計算します。 

| 私 | 値 | パリティ | xor_odd | xor_even |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 奇数 | 1 | 0 |
 | 2 | 2 | 偶数 | 1 | 2 |
 | 3 | 3 | 奇数 | 2 | 2 |

 最初の後$n-1$要素、$xor_odd = 2$、$xor_even = 2$。 

だからアンバランスというのは、$\Delta = 0$。 最後の要素が 0 になり、配列が生成されます$[1, 2, 3, 0]$。 

これにより、単純なキャンセルの場合でも XOR の等価性が維持されることが確認されます。 

### 例 2: n = 5

 から始める$a = [1, 2, 3, 4]$。 

| 私 | 値 | パリティ | xor_odd | xor_even |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 奇数 | 1 | 0 |
 | 2 | 2 | 偶数 | 1 | 2 |
 | 3 | 3 | 奇数 | 2 | 2 |
 | 4 | 4 | 偶数 | 2 | 6 |

 今$xor_odd = 2$、$xor_even = 6$、 それで$\Delta = 4$。 

最後の要素は 4 で、すでに表示されており、実装内でオフセット シフトをトリガーします。 

シフト後の値は次のようになります。$[1+2^{20}, 2+2^{20}, 3+2^{20}, 4+2^{20}]$、再計算により、衝突しない新鮮な有効な最後の要素が生成されます。 

これは、XOR の正確さを維持しながら区別性を維持する際のオフセット メカニズムの役割を示しています。

def run(inp: str) -> str:

 ## 特殊なケース

 のために$n = 3$、アルゴリズムは次のように割り当てます。$a = [1, 2]$、XOR の不均衡を計算し、それに応じて最後の値を設定します。 不均衡が 0 の場合、最後の要素は 0 になり、次のような有効なトリプルが生成されます。$[1, 2, 0]$。 これは直接満たします$1 \oplus 0 = 2$。 

小型用$n$、計算された XOR 結果が小さな初期範囲内に収まることが多いため、衝突の可能性が高くなります。 オフセット メカニズムにより、単純な構築で既存の値が再利用される場合でも、すべての基本要素が大きく離れてシフトされるため、最終的な XOR 結果は一意のままになります。 

大型用$n$の場合、XOR の累積は大きさや順序には依存せず、パリティの配置のみに依存するため、構築は安定したままになります。 最終的な修正ステップでは、さらなる調整を必要とせずに常に全体的な不均衡を解決します。
