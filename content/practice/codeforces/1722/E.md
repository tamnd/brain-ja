 ## 解決策
 ## 問題の理解

 それぞれの高さと幅によって定義される、軸に揃えられた長方形のコレクションが与えられます。 すべてのクエリに対して、「小さな内側の制約」長方形と「大きな外側の制約」長方形という 2 つの境界長方形も与えられます。 

パラメータを含むクエリの場合$(h_s, w_s, h_b, w_b)$、それらの長方形のみを考慮する必要があります$(h_i, w_i)$この長方形は、両方の次元で小さい制約よりも厳密に大きく、両方の次元で大きい制約よりも厳密に小さくなります。 それらの有効な長方形の面積を合計します。$h_i \cdot w_i$。 

したがって、各クエリは四角形に対する 2D 範囲フィルターを要求し、続いてその領域の集計を要求します。 

重要な問題は、両方とも$n$そして$q$と同じ大きさにすることができます$10^5$、最大 100 個のテスト ケースがあります。 これにより、クエリごとに各四角形をチェックするソリューションは即座に除外されます。これには、最大で$10^{10}$最悪の場合の運用。 

追加の構造上の制約が重要です。高さと幅は両方とも 1000 で制限されます。これは、長方形の数が多くても、座標空間が小さくて離散的であることを意味します。 これは、固定グリッド上の事前計算を強く示唆しています。 

素朴だが微妙な間違いは、長方形をソートし、高さと幅を独立してバイナリ検索を実行しようとすることです。 このアプローチは制約が分離可能ではないため失敗します。長方形は高さの条件を満たしても幅の条件を満たさない可能性があり、その逆も同様です。 たとえば、次のような長方形$h=10, w=1$そしてもう一つは$h=1, w=10$どちらも 1 次元フィルターを通過しますが、結合された 2D フィルターは通過しません。 ジョイント構造を使用せずに寸法を独立して扱うアプローチでは、不正確な結果が生成されます。 

もう 1 つの特殊なケースは、等価性の処理です。 厳密な不等式が必要なため、次の高さの長方形は次のようになります。$h_s$または$h_b$除外しなければなりません。 よくある間違いは、特に接頭辞の合計に変換する場合に、これを誤って包含境界にしてしまうことです。 

## アプローチ

 ブルート フォースのアプローチは簡単です。クエリごとに、すべての四角形を反復処理し、高さと幅の両方が厳密にクエリの範囲内にあるかどうかを確認します。 もしそうなら、その面積を答えに加えてください。 これは妥当性の定義に直接従うため、正しいです。 

ただし、これには費用がかかります$O(n)$クエリごとに、$O(nq)$全体。 と$n = q = 10^5$、これはあまりにも大きくなりすぎます。 

重要な観察は、長方形の寸法が小さいことです。 高さと幅の両方が収まります$[1, 1000]$、のみを与えます$10^6$可能なペア。 長方形を非構造化リストとして扱う代わりに、長方形を 2D 頻度表に集約できます。 

これを行うと、各クエリは 2D グリッド上の四角形の合計クエリになります。 これは古典的なプレフィックス合計の問題です。合計面積寄与の 2D プレフィックス合計を事前計算すると、包含-除外を使用して各クエリに一定時間で答えることができます。 

アイデアは、セルごとに保存することです$(h, w)$、正確にその寸法を持つすべての長方形が占める合計面積。 次に、O(1) 内の任意の長方形領域の合計をクエリできるように、このグリッド上で 2D プレフィックス合計を構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(1)$| 遅すぎる |
 | 2D プレフィックス合計 |$O(n + 1000^2 + q)$|$O(1000^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 高さと幅が 1000 で制限されるという事実を利用して、固定グリッドを構築します。 

1. 2D 配列を初期化する`grid[h][w]`サイズは 1001 × 1001 で、ゼロが付きます。 各エントリは、その正確な高さと幅を持つ長方形によって占められる合計面積を累積します。 これにより、入力リストが小さな領域にわたる構造化された周波数マップに変換されます。 
2. 長方形ごとに$(h_i, w_i)$、 追加$h_i \cdot w_i$に`grid[h_i][w_i]`。 このステップでは、すべての同一の長方形を 1 つのコントリビューションに圧縮し、総面積を正確に保存します。 
3. 2D プレフィックス合計配列を構築する`pref`、各セルには四角形内のすべての値の合計が格納されます。$[1..h][1..w]$。 これは、グリッド上の標準的な包含/除外反復を使用して行われます。 これが機能する理由は、長方形のクエリを重複するプレフィックス領域に分解できるためです。 
4. 各クエリについて$(h_s, w_s, h_b, w_b)$、厳密な長方形の合計を計算します。$$(h_s, h_b) \times (w_s, w_b)$$厳密な不等式を包括的な接頭辞インデックスに変換することによって、次のようになります。$$h \in [h_s+1, h_b-1], \quad w \in [w_s+1, w_b-1]$$5. プレフィックス合計テーブルの包含/除外式を使用してクエリに答えます。 これにより、クエリごとの定数時間におけるすべての有効な四角形の合計面積が得られます。 

重要な構造上の決定は、四角形のリストに対してクエリを実行する代わりに、各座標が次元ペアを表す圧縮グリッドに対してクエリを実行することです。 

### なぜ効果があるのか

 正しさは 2 つの不変条件に基づいています。 まず、すべての四角形は対応するグリッド セルに 1 回だけ寄与するため、圧縮中に情報が失われることはありません。 第 2 に、プレフィックス合計変換では、軸に合わせたサブ四角形全体の正確な合計が保存されます。 すべてのクエリ条件は、厳密な境界によってシフトされた後の高さと幅のグリッド内の正確な長方形領域であるため、有効な長方形はすべて含まれ、無効な長方形はすべて除外されます。 変換はクエリ条件とグリッド サブ領域間で全単射であるため、重複または欠落のケースは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 1000

def solve():
    n, q = map(int, input().split())
    
    grid = [[0] * (MAX + 1) for _ in range(MAX + 1)]
    
    for _ in range(n):
        h, w = map(int, input().split())
        grid[h][w] += h * w
    
    pref = [[0] * (MAX + 1) for _ in range(MAX + 1)]
    
    for h in range(1, MAX + 1):
        row_sum = 0
        for w in range(1, MAX + 1):
            row_sum += grid[h][w]
            pref[h][w] = pref[h - 1][w] + row_sum
    
    def get(h1, w1, h2, w2):
        if h1 > h2 or w1 > w2:
            return 0
        return (
            pref[h2][w2]
            - pref[h1 - 1][w2]
            - pref[h2][w1 - 1]
            + pref[h1 - 1][w1 - 1]
        )
    
    out = []
    for _ in range(q):
        hs, ws, hb, wb = map(int, input().split())
        h1, h2 = hs + 1, hb - 1
        w1, w2 = ws + 1, wb - 1
        out.append(str(get(h1, w1, h2, w2)))
    
    print("\n".join(out))

t = int(input())
for _ in range(t):
    solve()
```この解決策は、すべての長方形を高さと幅でインデックス付けされた固定グリッドに圧縮することから始まります。 これにより、クエリ中に個々の四角形を処理する必要がなくなります。 

プレフィックス合計の構築は行ごとに行われ、各セルが左上の部分行列からのすべての寄与を確実に蓄積します。 中間者`row_sum`変数は、水平合計を繰り返し再計算することを避けるために必要です。そうしないと、不必要に 1000 という余分な係数が追加されてしまいます。 

クエリ関数は、厳密な制約が空の間隔に崩れる無効な範囲を慎重に処理します。 これにより、負のインデックス作成エラーが防止され、境界での正確さが保証されます。 

各クエリは、接頭辞の合計式を適用する前に、厳密な不等式から包含境界に変換されます。

 ## 特殊なケース

 厳密な境界を適用した後にクエリ ウィンドウが折りたたまれる場合、微妙なケースが発生します。 たとえば、次の場合$h_b = h_s + 1$の場合、有効な高さの間隔は空になります。 アルゴリズムは次のようにこれを処理します。$h_1 = h_s + 1$そして$h_2 = h_b - 1$、それは次のことにつながります$h_1 > h_2$。 の`get`関数はこの条件を明示的にチェックし、すぐにゼロを返し、無効なプレフィックス合計インデックス作成を防ぎます。 

もう 1 つのケースは、長方形がクエリの境界上に正確に存在する場合です。 どちらの不等式も厳密であるため、高さが等しい長方形は次のようになります。$h_s$または$h_b$貢献してはなりません。 グリッドベースの表現では、これらのセルが単にプレフィックス範囲から除外されるため、これが自然に保証されます。$[h_s+1, h_b-1]$したがって、インデックスのシフト以外の特別な処理は必要ありません。
