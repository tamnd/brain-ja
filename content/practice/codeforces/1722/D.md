 ## 解決策
 ## 問題の理解

 私たちは人々の列を与えられ、それぞれが左または右を向いています。 人の貢献は、その人が見ている方向に何人の人が横たわっているかによって決まります。 右を向いている人は厳密に右側に人数を寄与し、左を向いている人は厳密に左側に人数を寄与します。 ラインの合計値は、これらの寄与の合計です。 

このタスクは単一の最適化ではなく、一連の最適化です。 すべての整数に対して$k$1から$n$、最大でも方向を反転することができます$k$そして、それを行った後の合計価値を可能な限り最大化したいと考えています。 

重要な問題は、1 回のフリップが 2 つの相反する方法で貢献に影響を与えることです。つまり、人は「線の一方側」の貢献から反対側の貢献に変わりますが、この変化はその人の立場によって異なります。 これは、人を反転させる利点は位置に依存し、独立した反転は有用性によって順序付けできることを直ちに示唆しています。 

制約が意味するのは、$n$まで可能です$2 \cdot 10^5$すべてのテスト ケースにわたるため、すべてのサブセットを試行するか、各サブセットの完全な値を再計算するソリューション$k$遅すぎるでしょう。 素朴なアプローチには以下が含まれます$O(n^2)$または、テスト ケースごとにさらに悪い動作が発生します。これは 2 秒の制限では許容されません。 

有益なフリップがすべてすでに使用されている場合、微妙なエッジケースが表示されます。 たとえば、文字列が既に一方向に最適化されている場合、追加の反転によって答えが増加することはありません。つまり、あるプレフィックスの後に出力が一定になる必要があります。$k$。 単純な再計算によると、$k$飽和を認識せずに、誤って寄与度を変更または再計算し続ける可能性があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての選択肢をシミュレートします。$k$反転します。 それぞれについて$k$、サイズのすべてのサブセットを試すことができます$k$、それらの位置を反転し、完全な寄与を再計算します。$O(n)$、最大値を取ります。 最適なサブセットの選択に限定したとしても、カウントが指数関数的な組み合わせを評価する必要があり、さらに、すべての候補を試行する簡易バージョンも必要です。$k$につながる$O(n^2)$あるいはさらに悪いことに。 

重要な観察は、1 人の人物を反転させる効果は、他の反転とは独立して定量化できるということです。 ポジションを固定すれば$i$、その寄与は方向と端からの距離によって異なります。 キャラクターを反転すると、その貢献度が反対側の貢献度に置き換えられるため、純利益は次の要素のみに依存する固定値になります。$i$そしてその現在の方向性。 

これにより、問題はベースライン値と各ポジションの反転による潜在的なゲインのリストを計算することになります。 各ポジションは、反転した場合にプラスまたはマイナスの改善に貢献します。$k$各プレフィックスの最適な改善点$k$。 これらのゲインを降順に並べ替えると、最適な改善順序がすぐに得られます。 

残る唯一の微妙な点は、ゲインを効率的に計算することです。 ポジションのために$i$、「L」の場合、現在貢献しています$i$(0 から始まるインデックスが貢献$i$または 0 インデックス調整)、それを「R」に反転すると寄与が得られます$n-1-i$。 ゲインは$(n-1-i) - i$。 「R」の場合、ゲインは$i - (n-1-i)$。 すべてのゲインを計算した後、それらを並べ替えてプレフィックスの合計を構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) から O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 反転を行わずに文字列の初期寄与を計算します。 各位置は、その方向と関連する側までの距離に基づいて寄与します。 これにより、後で調整する固定ベースラインが得られます。 
2. ポジションごとに$i$、反転すると合計値がどれだけ変化するかを計算します。 これは、「L」としての貢献と「R」としての貢献の違いです。 これにより、考えられる各操作の利点が分離されます。 
3. 計算されたすべてのゲインをリストに保存します。 各ゲインは 1 つの独立した操作の選択肢を表し、フリップの選択はそのゲインの取得に正確に対応します。 
4. 最も収益性の高いフリップが最初に考慮されるように、ゲインを降順に並べ替えます。 この順序により、どのような場合でも、$k$、サイズの最適なサブセット$k$は常に、このソートされたリストの接頭辞になります。 
5. ソートされたゲインに対してプレフィックス合計配列を構築します。 の$k$-th プレフィックスの合計は、最良のものを反転することによって得られる合計の改善を表します。$k$ポジション。 
6. それぞれについて$k$、出力ベースラインとプレフィックスの合計は次のようになります。$k$、最大でも選択できるという事実を利用して$k$反転するため、最大でもサイズの利用可能な最良のサブセットを取得します。$k$。 

### なぜ効果があるのか

 各フリップは、その寄与の変化が他のフリップに依存しないという意味で独立しています。 問題を利益に変換すると、目的は以下を選択することになります。$k$合計が最大の要素。 ソートにより、最適な選択は利用可能な最大のゲインで構成されていることが保証されます。これは、選択した小さいゲインを未使用の大きいゲインに置き換えることで常に合計が改善または維持されるためです。 この交換引数は、貪欲な順序付けの正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        gains = []
        base = 0
        
        for i, ch in enumerate(s):
            if ch == 'L':
                base += i
                gains.append((n - 1 - i) - i)
            else:
                base += (n - 1 - i)
                gains.append(i - (n - 1 - i))
        
        gains.sort(reverse=True)
        
        pref = 0
        res = []
        
        for k in range(n):
            if k < len(gains):
                if gains[k] > 0:
                    pref += gains[k]
            if k < len(gains) and gains[k] <= 0:
                # once gains become non-positive, adding more won't help
                pass
            res.append(str(base + pref))
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはまず、反転がないと仮定してベースライン寄与を計算します。 次に、反転した場合に各インデックスがどれだけ答えを改善するかを表すゲイン配列を構築します。 ソートにより、常に最良のフリップを最初に考慮することができます。 プレフィックスの蓄積により、許容されるフリップ数ごとに達成可能な最良の改善が構築されます。 

微妙な点は、依然としてすべての値を計算していることです。$k$たとえ利益がマイナスになったとしても。 これらの負の値は、ソートされたゲインのプレフィックス合計には必要な場合にのみ含まれるため、正しい実装では当然選択されなくなります。 

## 実用的な例

 インプットを考慮する`LLR`。 

インデックスごとの寄与と利益を計算します。 

| 私 | 文字 | 貢献 | 反転投稿 | ゲイン |
 | --- | --- | --- | --- | --- |
 | 0 | Ｌ | 0 | 2 | +2 |
 | 1 | Ｌ | 1 | 1 | 0 |
 | 2 | R | 0 | 2 | +2 |

 ベースラインは 1 です。ソートされたゲインは [2, 2, 0] です。 プレフィックスの合計:

 | k | 選択されたゲイン | 合計 |
 | --- | --- | --- |
 | 1 | [2] | 3 |
 | 2 | [2,2] | 5 |
 | 3 | [2,2,0] | 5 |

 これは、十分な反転の後、値が安定するサンプルの動作と一致します。 

ここで考えてみましょう`LRRLL`。 

| 私 | 文字 | ゲイン |
 | --- | --- | --- |
 | 0 | Ｌ | +4 |
 | 1 | R | +2 |
 | 2 | R | +0 |
 | 3 | Ｌ | +0 |
 | 4 | Ｌ | -2 |

 ソートされたゲインは [4,2,0,0,-2] です。 プレフィックスの合計:

 | k | 合計 |
 | --- | --- |
 | 1 | 基数 + 4 |
 | 2 | 基数 + 6 |
 | 3 | 基数 + 6 |
 | 4 | 基数 + 6 |
 | 5 | 基数 + 4 |

 これは、ある点を超えるとマイナスのゲインがどのように回避されるべきかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートのゲインが支配的で、他のすべての操作は線形です。 
| スペース | O(n) | ポジションごとに 1 つのゲインを保存します。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$合計文字数は$O(n \log n)$ソリューションは時間制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジケースは、すべてのフリップが最終的に有害になる場合です。 のような文字列の場合`RRRRR`、任意のキャラクターを反転すると貢献度が減ります。 その場合、ゲインはすべてマイナスになります。 アルゴリズムは引き続きそれらを並べ替えますが、接頭辞の合計には最初の数個 (正の値がある場合) のみが使用されるため、すべての$k$同じベースライン値を生成します。 

もう 1 つのケースは、次のような交互パターンです。`LRLRLR`。 ここでは、ゲインは位置に応じて正と負の間で切り替わります。 並べ替えにより、たとえそれらが遠く離れていたとしても、すべての強く肯定的な改善が最初に実行されるようになり、局所的な貪欲な決定が次善のフリップに固定されるのを防ぎます。 

最後の微妙なケースは、複数のゲインが等しい場合です。 ソートによりそれらは交換可能に保たれ、等しいゲインの順序によって同じ累積値が生成されるため、プレフィックス合計は安定したままになります。
