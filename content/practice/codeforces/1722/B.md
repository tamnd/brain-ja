 ## 解決策
 ## 問題の理解

 ちょうど 2 つの水平ストリップといくつかの垂直列を持つ非常に小さなグリッドが与えられます。 各セルには 3 つの色のいずれかが含まれていますが、観察者は特定の点で色盲です。緑と青は区別できませんが、赤は両方とも区別されます。 

タスクは、列ごとに比較したときに、この色盲の観察者にとって 2 つの行が同一に見えるかどうかを判断することです。 つまり、緑と青を単一の知覚色にマージするルールを適用した後、すべての列の両方の行に同じ知覚色のペアがあるかどうかを確認します。 

各テスト ケースは独立しているため、この比較を複数回繰り返します。 

制約は小さく、テスト ケースは最大 100 個、テスト ケースごとに最大 100 列です。 これにより、高度なデータ構造やリニア スキャンを超える最適化の必要性が即座に排除されます。 実際にはテストあたり O(n²) であっても許容されますが、構造はテスト ソリューションあたり O(n) であることを強く示唆しています。 

重要な微妙な点は、「緑と青を区別できない」ということが実際に何を意味するのかを理解することにあります。 赤くなったり消えたりするわけではありません。 それは、それらが単一の同値クラスに崩壊することを意味します。 どのような比較でも、その同等性を尊重する必要があります。 

よくある間違いは、文字列を変換せずに直接比較できるものとして扱うことから発生します。 たとえば、比較すると、`G`そして`B`異なる文字は、等しいとみなされるべきケースを誤って拒否してしまうためです。 

もう 1 つの潜在的な落とし穴は、各文字のカウントのみを比較しようとすることです。 位置が重要であるため、これは失敗します。 例えば、`RGB`対`BRG`同一の複数の文字セットを持ちますが、色盲マッピングの下で​​も明らかに異なります。 

エッジケースは最小限ですが、有益です。 

1 つのケースは、両方の行が完全に緑と青で構成されている場合です。次に例を示します。```
GBG
BGB
```これらは色盲ルールの下ではすべて同等であるため、マッピング後に位置が揃っていれば一致するはずです。 単純な周波数ベースのソリューションでは、不一致の配置に対して誤って「YES」と判断する可能性があります。 

別のケースは単一列グリッドです。```
G
B
```どちらも同じ知覚される色にマッピングされるため、これらは同一であると見なす必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。両方の行に対して色盲変換を明示的にシミュレートし、結果の文字列を比較します。 各セルについて、緑と青を共有シンボルにマッピングします。`X`, 赤が残っているうちに`R`。 変換後、結果の 2 つの文字列を 1 文字ずつ比較します。 

これが機能するのは、問題を標準の文字列等価性チェックに帰着させるためです。 コストはテスト ケースごとの列数に比例し、グリッドは 2 行のみであるため、追加のオーバーヘッドはありません。 

遷移の追跡やパターンの照合など、より複雑なことを試みると、基本的には正規化と比較のタスクである問題を過剰にエンジニアリングすることになります。 

この設定では、ブルート フォースはすでに最適化されています。 重要な観察は、唯一の意味のある変換は文字ごとの定数時間マッピングであるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 正規化なしの直接比較 | テストあたり O(n) | お(1) | 不正解 |
 | 正規化してから比較 | テストあたり O(n) | O(n) (または O(1) ストリーミング) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各グリッドは独立しており、個別に評価する必要があるため、テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、整数 n と行を表す 2 つの文字列を読み取ります。 
3. 0 から n - 1 までの各列インデックスを繰り返します。 
4. 各列について、同じルールを使用して両方の文字を変換します。`G`そして`B`同等のものとして維持しながら、`R`明確な。 便利な実装は、両方をマップすることです。`G`そして`B`たとえば、同じシンボルに`0`、および地図`R`に`1`。 
5. 各列の変換された文字を比較します。 変換後に列が異なる場合は、色盲の観察者にとって行が同一ではないと直ちに結論付けます。 
6. 変換後にすべての列が一致する場合、行は同一であると判断されます。 

いずれかの列の不一致によって答えが完全に決まるため、ステップ 5 の早期終了が重要です。 違いが見つかったら、スキャンを続ける必要はありません。 

### なぜ効果があるのか

 このアルゴリズムは、観察者が色に関する等価関係を定義するという事実に依存しています。`G ≡ B`そして`R`は両方とは異なります。 したがって、知覚される行の同等性は、点ごとに適用されるこの等価性マッピングに基づく画像の同等性と同等です。 マッピングは各セルに独立して適用され、比較は位置に基づいて行われるため、列ごとに等価性を維持することで、行全体の比較の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def norm(c):
    # map green and blue to same class
    return 0 if c != 'R' else 1

t = int(input())
for _ in range(t):
    n = int(input())
    a = input().strip()
    b = input().strip()

    ok = True
    for i in range(n):
        if norm(a[i]) != norm(b[i]):
            ok = False
            break

    print("YES" if ok else "NO")
```このソリューションは、各テスト ケースを個別に読み取り、単一パスで 2 つの行を処理します。 ヘルパー関数`norm`色盲ルール全体を、文字ごとに 1 回の定数時間操作でエンコードします。 不一致が見つかるとループはただちに終了するため、最悪の場合の入力でも最適な動作が保証されます。 

よくある実装上の間違いは、入力文字列から改行文字を削除するのを忘れることです。これにより、インデックス作成ロジックが暗黙的に変更される可能性があります。 もう 1 つは、生の文字を直接比較しようとするもので、特に次の場合に失敗します。`G`対`B`。

 ## 特殊なケース

 単一列グリッドは、自明ではない最も単純なケースです。 このアルゴリズムは 1 組の文字のみを比較し、両方が同じ等価クラスに属している場合は YES を返します。 例えば、`G`対`B`は同一の正規化値にマッピングされるため、結果は正しいものになります。 

すべてのような完全に均質なグリッド`R`両方の行の は、特別なロジックなしで処理されます。 すべての比較は等しいと評価されるため、ループは早期終了をトリガーすることなく完了します。 

緑と青の値だけが異なるパターンで混在しているケースでは、位置比較の重要性が強調されます。 このアルゴリズムはカウントに依存せず、正規化後の整列された等価性のみに依存するため、不一致の順序を正しく拒否します。 

最後の微妙なケースは、入力トリミングが正しく行われていることを確認することです。 改行文字が削除されていない場合、比較に誤って改行文字が含まれる可能性があります。`\n`、これは等価性チェックに違反します。 の`.strip()`call を使用すると、このようなことが起こらないことが保証されます。
