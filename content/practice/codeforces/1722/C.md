 ## 解決策
 ## 問題の理解

 各テスト ケースは、3 人のプレーヤーによる小規模な単語提出ゲームを説明します。 すべてのプレイヤーは独立して、同じ数の短い文字列を書き留めます。各文字列の長さは正確に 3 です。 すべての単語が書かれた後、スコアはそれぞれの単語を何人の人が含めたかによって決定されます。 

1 人のプレイヤーのリストにのみ表示される単語はそのプレイヤー専用であるため、そのプレイヤーは 3 ポイントを獲得します。 ちょうど 2 人のプレイヤーのリストに出現する単語は、その 2 人のプレイヤーにそれぞれ 1 ポイントを与えます。 3 つのリストすべてに含まれる単語は誰にもポイントを与えません。 

タスクは、すべてのテスト ケースについて各プレーヤーの最終スコアを計算することです。 

制約は十分に小さく、すべてのプレーヤーでテスト ケースごとの合計単語数が最大 3000 語になります。 これにより、テスト ケースごとの線形または線形に近い処理よりも重い処理は直ちに除外されます。 入れ子になったループ内で単純にリストを繰り返し比較したりメンバーシップをチェックしたりするアプローチは理論的には合格しますが、すべてのワードにわたる二次関数は不必要なオーバーヘッドであり、不注意に実装すると Python でタイムアウトする危険性があります。 

主な微妙な点は、単語がプレイヤー間でペアごとに比較されるだけでなく、セット全体で共有されることです。 単語は 2 つまたは 3 つのリストに出現する可能性があり、スコアは 1 つの比較に存在するかどうかだけでなく、3 つのセット全体にわたる正確な頻度によって決まります。 単純な間違いは、プレーヤーのペアごとに独立してオーバーラップをカウントし、二重にカウントするか、「3 つすべて」のケースを見逃すことです。 

たとえば、ある単語が 3 つのリストすべてに含まれており、ペアごとにのみ比較する場合、3 人のプレイヤー全員に 0 点ではなく誤ってポイントを与える可能性があります。 もう 1 つのよくある間違いは、一意の単語ごとではなく出現ごとにスコアを更新することです。各リストには内部的には異なる単語が含まれていますが、リスト間の重複はグローバルに問題となるため、正確性が損なわれます。 

## アプローチ

 ブルートフォース ソリューションでは、各プレイヤーのリスト内の各単語を処理し、他の 2 つのリストにその単語がいくつ含まれているかを確認します。 各リストには最大 n 個の単語があるため、リスト スキャンとして実装されたメンバーシップ チェックを使用して、単語ごとに最大 2n 個の他の単語をスキャンします。 これにより、最悪の場合のコストはテスト ケースごとに n² に比例し、ハッシュなしで実装すると t 個のテスト ケース全体で非常に遅くなります。 

問題の構造は、集合の和集合に対する頻度の集約を示唆しています。 メンバーシップを繰り返し確認する代わりに、各単語が何人のプレイヤーに出現するかをカウントします。そのカウントがわかれば、固定ルールに従ってポイントを直接配分できます。 

これが機能するのは、スコアリングが各単語の所有者のセットの基数にのみ依存するためです。 この数を超える順序やペアの関係は必要ありません。 単語を 3 ビットのプレゼンス マスクにマッピングする辞書、または単純なカウンターは、1 回のパスですべての寄与を再構築するのに十分です。 

メンバーシップ チェックは概念的に単純であるため、ブルート フォースは機能しますが、スキャンの繰り返しが実行時間を支配する場合は失敗します。 各単語が独立して寄与しているという観察により、問題を単一パス周波数の累積に縮小することができます。

 | 最適 (ハッシュカウント) | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、3 つのプレーヤーにわたる単語のグローバル頻度マップを構築します。

1. 最初のプレーヤーからすべての単語を読み取り、プレゼンスの値 1 を使用して辞書に記録します。 これは、これまでにちょうど 1 人のプレイヤーがこの単語を投稿したことを表します。 
2. 2 番目のプレーヤーの単語を読みます。 各単語について、既に辞書に存在する場合は、そのカウントを 2 に増やします。そうでない場合は、値 1 を挿入します。このステップは、これまでに各単語を見たプレイヤーの数を効果的に追跡します。 
3. 3 人目のプレーヤーから単語を読み取り、同様に辞書を更新し、各単語の値が 3 人のプレーヤーのうち何人がその単語を含んでいたかを反映していることを確認します。 最終的な値は常に 1、2、または 3 です。 
4. 各プレーヤーに 1 つずつ、3 つのスコア変数をゼロに初期化します。 
5. 各プレイヤーのリストを再度繰り返します。 単語ごとに、最終的な頻度カウントを使用します。 

- カウントが 1 の場合、そのプレイヤーに 3 点を追加します。 
- カウントが 2 の場合、そのプレイヤーに 1 点を追加します。 
・カウントが3の場合は0点を加算します。 
6. 3 つの累積スコアを出力します。 

重要な考え方は、問題を 2 つのフェーズに分けるということです。まず、グローバルな所有権数を決定し、次にそれらの数を使用してプレーヤーごとのスコアをローカルに計算します。 

### なぜ効果があるのか

 すべての単語について、プレイヤーのスコアへの寄与は、その単語が含まれているプレイヤーの数のみに依存し、他のどの単語が存在するか、またはその単語が中間チェックでどのくらいの頻度で出現するかには依存しません。 辞書にはその情報が正確に保存されます。 各単語は独立して処理され、プレーヤーごとに 1 回だけ追加されるため、最終的なカウントは所有権セットのサイズを正確にエンコードしたものになります。 スコアはそのサイズの決定論的な関数であるため、異なる単語間の相互作用が正しさに影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        a = input().split()
        b = input().split()
        c = input().split()

        cnt = {}

        for w in a:
            cnt[w] = 1
        for w in b:
            if w in cnt:
                cnt[w] = 2
            else:
                cnt[w] = 1
        for w in c:
            if w in cnt:
                cnt[w] = 3
            else:
                cnt[w] = 1

        res = [0, 0, 0]

        for w in a:
            if cnt[w] == 1:
                res[0] += 3
            elif cnt[w] == 2:
                res[0] += 1

        for w in b:
            if cnt[w] == 1:
                res[1] += 3
            elif cnt[w] == 2:
                res[1] += 1

        for w in c:
            if cnt[w] == 1:
                res[2] += 3
            elif cnt[w] == 2:
                res[2] += 1

        print(*res)

if __name__ == "__main__":
    solve()
```実装ではまず、各単語を含む個別のプレーヤーの数を記録する辞書を構築します。 これは、プレーヤーごとに 1 回ずつ、3 回の連続したパスで行われ、プレーヤー間での繰り返しの発生に応じて、保存されているカウントが 1、2、3 と更新されます。 

スコアリング フェーズは、カウント ロジックとスコアリング ロジックが混在することを避けるために分離されています。 各プレイヤーのリストが再度調べられ、事前に計算された頻度によって正確なスコア貢献度が決まります。 この分離により、中間更新によってカウントが歪められる可能性がある間違いを防ぐことができます。 

微妙な点は、一度設定されたカウントを減分したり再計算したりすることはないということです。 各プレイヤーは各単語を最大 1 回ずつ投稿するため、カウントを昇順に上書きしても安全であり、正確性が保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = input().split()
        b = input().split()
        c = input().split()

        cnt = {}

        for w in a:
            cnt[w] = 1
        for w in b:
            cnt[w] = 2 if w in cnt else 1
        for w in c:
            cnt[w] = 3 if w in cnt else 1

        res = [0, 0, 0]
        for w in a:
            if cnt[w] == 1: res[0] += 3
            elif cnt[w] == 2: res[0] += 1
        for w in b:
            if cnt[w] == 1: res[1] += 3
            elif cnt[w] == 2: res[1] += 1
        for w in c:
            if cnt[w] == 1: res[2] += 3
            elif cnt[w] == 2: res[2] += 1

        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、単語が 3 つのリストすべてに含まれる場合です。 アルゴリズムはカウント 3 を割り当てるため、各プレーヤーは`cnt[w] == 3`そして何も貢献しない。 たとえば:

 入力:```
1
1
abc
abc
abc
```辞書は次のように進化します`abc=1`、 それから`abc=2`、 それから`abc=3`。 得点の際、各プレーヤーは単語をチェックし、カウント 3 を見つけたので、ポイントは追加されません。 出力は`0 0 0`、ルールに一致します。 

もう 1 つのケースは、単語が 2 人のプレイヤー間で異なる組み合わせで分割される場合です。 辞書は引き続き正しくエンコードされます`cnt[w] == 2`どちらのペアがそれを所有しているかに関係なく、両方の所有者は 1 ポイントを受け取り、3 番目の所有者は何も受け取りません。 これは、ペアの同一性は無関係であり、頻度のみが重要であることを示しており、これはまさにアルゴリズムが保持するものです。
