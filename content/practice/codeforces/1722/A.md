 ## 解決策
 ## 問題の理解

 各テスト ケースには短い文字列が与えられており、それが非常に特殊なスペル ルールの下で「Timur」という名前の並べ替えとして解釈できるかどうかを判断する必要があります。 

ルールは文字が一致するだけではありません。 文字列は、「Timur」に出現する 5 つの文字を同じ多重度で正確に使用する必要があり、大文字の構造も一致する必要があります。文字 T は 1 回だけ出現し、大文字である必要があります。一方、残りの文字は小文字の i、m、u、および r であり、それぞれ 1 回ずつ出現する必要があります。 

したがって、各テスト ケースは基本的に、入力文字列が固定ケース制約を持つマルチセット {T, i, m, u, r} の有効な置換であるかどうかを尋ねます。 

入力サイズは非常に小さく、文字列あたり最大 10 文字、最大 1000 のテスト ケースです。 これは、単純なテストごとのスキャンや比較を行うソリューションでも、十分に高速であることがすぐにわかります。 テスト ケースごとに O(10) チェックを行うだけでも簡単なので、高度なデータ構造や前処理は必要ありません。 

主な微妙な点は、大文字と小文字の区別と正確な一致です。 ここでいくつかのよくある間違いが発生します。 大文字が重要であることを忘れているため、文字が一致しても「timur」は失敗するはずです。 もう 1 つは、「Timuur」などの文字の繰り返しを許可するもので、これにより重複が生じ、順列要件が破られます。 3 つ目は、「Timr」など、文字は正しいが長さが正しくない文字列を受け入れることです。これは文字が欠落しているため、直ちに拒否する必要があります。 

## アプローチ

 この問題を考える強引な方法は、文字列「Timur」のすべての順列を生成し、入力文字列がそれらのいずれかに一致するかどうかを確認することです。 名前には 5 つの異なる文字があるので、5 つあります。 = 120 の順列。 各テスト ケースについて、120 個の候補すべてと比較できます。 これは機能しますが、不必要な過剰行為であり、問​​題の構造が隠蔽されます。 

「有効なスペル」が 5 つの文字列の固定セットのメンバーにすぎないことに気づくと、構造がより明確になります。 すべての有効な回答には、大文字と小文字が固定された必須文字が 1 つだけ含まれている必要があります。 順列を生成する代わりに、入力の並べ替えられた表現または頻度表現が参照パターンと一致するかどうかを直接比較できます。 

より単純な見方は、正解を制約のあるマルチセットとして扱うことです。 長さが正確に 5 であることを確認し、必要な各文字が大文字と小文字が正しく 1 回だけ出現することを確認します。 これにより、問題はテスト ケースごとの一定時間のチェックに軽減されます。 

重要な洞察は、私たちは取り決めについて調べているわけではないということです。 大文字と小文字の制約がある固定マルチセットに対して等価性を検証しています。

 ## アルゴリズムのチュートリアル

 1. 名前の正確に有効な構造を周波数マップとして事前定義します: 1 つの「T」、1 つの「i」、1 つの「m」、1 つの「u」、および 1 つの「r」。 これはターゲット署名として機能します。 
2. 各テスト ケースについて、まず文字列の長さを確認します。 有効なスペルには正確に 5 文字を使用する必要があるため、5 でない場合はすぐに拒否できます。 
3. 入力文字列内の文字の頻度カウンターを構築します。 文字列は小さいため、単純な辞書または直接カウントで十分です。 
4. この周波数マップをターゲットと比較します。 必須の文字はすべて 1 回だけ出現する必要があり、余分な文字は許可されません。 
5. すべての条件が一致する場合、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

この順序が重要な理由は、効率性と正確性の明確さです。 長さチェックにより、多くの無効なケースが即座に排除され、必要な文字がすべて含まれているにもかかわらず、文字が繰り返されている文字列を誤って受け入れないようにすることができます。

### なぜ効果があるのか

 このアルゴリズムは、名前の有効なスペルが固定された複数の文字セットの順列に正確に対応するという不変式に依存しています。 2 つの文字列は、同じ文字頻度を共有する場合に限り、互いの順列になります。 大文字と小文字を区別する要件はマルチセット定義に直接埋め込まれているため、頻度比較によって問題のすべての制約が完全に把握されます。 文字列の他の構造特性は重要ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

TARGET = {'T': 1, 'i': 1, 'm': 1, 'u': 1, 'r': 1}

def ok(s: str) -> bool:
    if len(s) != 5:
        return False
    cnt = {}
    for c in s:
        cnt[c] = cnt.get(c, 0) + 1
    return cnt == TARGET

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        print("YES" if ok(s) else "NO")

if __name__ == "__main__":
    solve()
```この解決策では、まず、有効な名前に対して予想される頻度辞書を修正します。 各テスト ケースは独立して処理され、指定された長さは無視されます。`n`実際の文字列の長さが直接測定されるため、一貫性チェックとしては除きます。 

頻度の比較は正確であるため、大文字小文字の違い、文字の欠落、文字の繰り返しなどの逸脱は直ちに失敗します。 

微妙な実装の詳細は、`strip()`文字列を読むとき。 これにより、コンテスト設定で隠れたバグの一般的な原因となる、改行文字による比較の干渉が防止されます。

 ## 特殊なケース

 一般的なエッジ ケースは、「timur」など、必要な文字がすべて存在するにもかかわらず大文字と小文字が間違っている場合です。 小文字の「t」は必須の大文字の「T」ではないため、周波数マップは構造的には一致しますが、正確なキーでは一致しません。 辞書の等価性では大文字と小文字が区別されるため、アルゴリズムはこれを正しく拒否します。 

もう 1 つの特殊なケースは、「Timuur」のような文字が繰り返されることです。 他の文字がどこかに欠けている場合でも長さは 5 のままである可​​能性がありますが、頻度を比較すると不均衡がすぐに明らかになります。 「u」のカウントは 2 になり、ターゲットとの完全一致は失敗します。 

最後のエッジ ケースは、「Timurx」などの余分な文字を含む文字列です。 最初の 5 文字は有効ですが、追加の文字は長さの条件と頻度の等価性の両方を破ります。 アルゴリズムは長さチェックの段階でそれを拒否し、不必要な計算を防ぎます。
