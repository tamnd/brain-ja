 ## 問題の理解

 サイズの異なる 2 つのギアをご用意しています`a`そして`b`。 同じ負でない数の歯を追加する必要があります`x`両方のギアに。 これらの歯を追加した後、最初の新しいサイズ`a + x`元の 2 番目のサイズで割り切れる必要があります`b`、そして 2 番目の新しいサイズ`b + x`元の最初のサイズで割り切れる必要があります`a`。 

タスクは可能な限り最小のものを見つけることです`x`。 

入力には 2 つの整数が含まれています`a`そして`b`、それぞれ最大`10^9`。 これにより、可能な値の検索が即座に除外されます。`x`なぜなら、答えは非常に大きくなる可能性があるからです。 何百万もの候補者をチェックするループさえも信頼性が低く、アプローチは次のようなものに比例します。`a`または`b`不可能です。 問題をいくつかの算術演算に減らす必要があります。 

主なエッジケースは、2 つの数値間の関係から生じます。 歯車のサイズがすでに同じである場合、両方の割り切り条件がすでに満たされているため、答えはゼロになります。 たとえば、入力`123 123`出力を与える`0`両方の値を盲目的に増加させようとするソリューションでは、これが見逃される可能性があります。 

もう 1 つの注意が必要なケースは、一方の数字がもう一方の数字を割る場合です。 入力用`8 1`、答えは`7`、 ない`0`、新しいサイズになるため、`15`そして`8`、 そして`15`で割り切れます`1`その間`8`で割り切れます`8`。 一方の元の値がもう一方の値を割るかどうかだけをチェックする不注意なアプローチでは、誤って早期に停止してしまう可能性があります。 

3 番目のエッジ ケースは、最小公倍数が 2 つの元の値の合計より小さい場合に発生します。 入力用`3 4`、最小公倍数は`12`、有効な最終ギア サイズの最小調整には追加が必要です。`5`、 ない`0`または`1`。 答えは`5`最終的なサイズは`8`そして`9`、必要な可分性を満たします。 

## アプローチ

 直接的なアプローチでは、次の値を試します。`x`ゼロから開始して、両方の条件が満たされるかどうかをテストします。 テストに合格した最初の値は正確に最小値であるため、これは正しいです。 ただし、答えはそれに近いかもしれません`10^18`, そのため、膨大な数の候補者をチェックすることさえ不可能です。 

有益な観察は、最終的なギアのサイズを見ることで得られます。 番号`a + x`の倍数でなければなりません`b`、 そして`b + x`の倍数でなければなりません`a`。 これは、2 つの最終値が反対の元の値の倍数である一方で、その差は固定されたままであることを意味します。`(a + x) - (b + x) = a - b`。 

より明確な方法は、最初の条件を表現することです。 させて：`a + x = k * b`。 

それから：`b + x = b + k*b - a = (k + 1)b - a`。 

これが割り切れるには`a`、値`(k + 1)b`で割り切れる必要があります`a`。 次の倍数を作る最小の乗数`b`の倍数にも対応`a`最小公倍数に関係します。 

最終的な共通の整列点は次の倍数です。`lcm(a, b)`。 両方の最終値は元の値と同じ量だけ異なるため、可能な最小の追加値は、少なくとも次の最小公倍数の最小倍数を見つけることによって取得されます。`a + b`。 

させて`L = lcm(a, b)`。 答えは次のとおりです。`smallest_multiple_of_L_not_less_than_(a+b) - a - b`。 

なぜなら`L`少なくとも両方です`a`そして`b`、必要な倍数は次のいずれかです`L`または`2L`ただし、整数上限除算を使用すると、あらゆるケースが直接処理されます。

 ## アルゴリズムのチュートリアル

 1. の最大公約数を計算します。`a`そして`b`。 最小公倍数は次のように取得できます。`a * b / gcd(a, b)`、そして最初に gcd を使用すると、より小さい整数型を持つ言語での不必要なオーバーフローが防止されます。 
2. しましょう`L`2 つのギア サイズの最小公倍数になります。 次の最小倍数が必要です`L`それより小さくない`a + b`。 
3. 上限除算を使用して乗数を計算します。`(a + b + L - 1) // L`。 乗算する`L`この値により、最小の有効な位置合わせ点が得られます。 
4. 減算`a + b`この整列点から。 残りの数は、両方の歯車に追加する必要がある歯の数と同じです。 

なぜ機能するのか: 最終的な値`a + x`そして`b + x`それぞれが他方の可分性構造に到達するように配置する必要があります。 これら 2 つの値の間の距離は固定されており、公約数の要件により、整列は次の値の倍数で発生するように強制されます。`lcm(a, b)`。 アルゴリズムは、現在の合計サイズの後の最初のそのような配置を選択します。`a + b`、したがって、より小さい値は`x`最初の有効な位置に到達する前にギアを離れることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    g = math.gcd(a, b)
    lcm = a // g * b

    target = ((a + b + lcm - 1) // lcm) * lcm
    print(target - a - b)

if __name__ == "__main__":
    import math
    solve()
```このソリューションでは、まず 2 つのギア サイズを読み取り、それらの最大公約数を計算します。 gcd は、乗算せずに最小公倍数を構築するために使用されます。`a`そして`b`早すぎる。 

変数`target`より小さくない最小公倍数の最初の倍数を表します`a + b`。 天井除算式は、次の場合にオフバイワンエラーを回避します。`a + b`はすでに次の倍数です`lcm`。 

最後の減算では、両方のギアの元の寄与が除去されます。 残るのは、各ギアに追加する必要がある歯の数だけです。 

Python の整数は大きな値を自動的に処理するため、最小公倍数に使用される乗算には特別な処理は必要ありません。

## テストケース```python
import sys
import io
import math

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    a, b = map(int, input().split())
    g = math.gcd(a, b)
    lcm = a // g * b
    target = ((a + b + lcm - 1) // lcm) * lcm
    return str(target - a - b) + "\n"

assert solution("10 5\n") == "0\n", "sample-like divisible case"
assert solution("8 1\n") == "7\n", "one divides the other"
assert solution("3 4\n") == "5\n", "different coprime values"
assert solution("123 123\n") == "0\n", "equal gears"
assert solution("1 1\n") == "0\n", "minimum values"
assert solution("1000000000 999999999\n") == "999999998999999999\n", "large values"
assert solution("6 9\n") == "3\n", "common divisor case"

 ## 特殊なケース

 等しいギアの場合、次のようになります。```
123 123
```gcdは`123`、最小公倍数も`123`。 合計`a + b`はすでに次の倍数です`lcm`、したがってターゲットは残ります`246`、の答えを生成します`0`。 アルゴリズムは、特別な場合を除き、これを自然に処理します。 

分割の場合:```
8 1
```最小公倍数は`8`。 合計は`9`, したがって、次の最初の倍数は`8`それに達するか、それを超えるのは`16`。 答えは`16 - 9 = 7`、最終ギアのサイズを示します`15`そして`8`。 最初のものは次のように割り切れます。`1`、2 番目は次で割り切れます。`8`。 

共素ペアの場合:```
3 4
```最小公倍数は`12`。 現在のサイズの合計は`7`したがって、最初の有効な位置合わせは次のようになります。`12`。 アルゴリズムは戻ります`5`、最終的なサイズを生成します`8`そして`9`、 どこ`8`で割り切れます`4`そして`9`で割り切れます`3`。 

非常に大きな値の場合、アルゴリズムは gcd と算術演算のみを実行します。 考えられる答えを反復することは決してないので、必要な加算の大きさに対して実行時間は一定のままです。
