 ## 解決策
 ## 問題の理解

 挿入後に最終的な順列を構築するように求められることはありません。 代わりに、与えられた`n`、順列を構築する必要があります`p`の`1..n`したがって、前の問題「挿入」`n+1`どこかですべてのプレフィックスの合計をモジュロにします`n+1`ペアごとに個別」には、少なくとも 1 つの有効な挿入位置があります。 

このような順列であれば`p`存在する場合は、それらのいずれかを出力します。 それ以外の場合は出力します`-1`。 

すべての合計`n`テストケース全体で最大`10^6`したがって、テスト ケースごとに線形時間で答えを構築するソリューションは、簡単に十分に高速です。 二次関数は最悪の場合、遅すぎる可能性があります。 

微妙な部分は、直接構築しているわけではないということです。`p`。 条件は挿入後に定義されます`n+1`したがって、最初に長さの順列を理解する必要があります。`n+1`個別のプレフィックス条件を満たします。 

よくある間違いは、複雑な挿入戦略を探すことです。 有効な最終順列の構造を理解すると、生成バージョンははるかに単純になります。 

考慮する`n = 2`。 唯一の順列は、`[1,2]`そして`[2,1]`。 挿入後`3`、結果として得られるすべての置換には長さがあります。`3`。 長さ 3 の順列では、すべての接頭辞の和を法とすることはできないことがわかります。`3`異なるため、正しい答えは次のとおりです。```
-1
```すべてのオブジェクトに対して盲目的に順列を出力する構造。`n`ここで失敗します。 

もう一つ見逃しやすいケースは、`n = 1`。 

次のように出力できます。```
1
```なぜなら挿入後は`2`前に私たちは得ます`[2,1]`、その接頭辞の和が剰余である`2`は`0`そして`1`、それらは区別されます。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。`n!`の順列`1..n`、各順列についてすべてを試してください`n+1`挿入位置。 結果の順列を構築した後、そのプレフィックスの合計が剰余であるかどうかを確認できます。`n+1`はすべて異なります。 

これは正しいですが、たとえ`n = 10`すでにあります`3,628,800`順列。 階乗増加により、このアイデアは使用できなくなります。 

重要な観察は、挿入ステップを逆にできることです。 

させて`m = n + 1`。 有効な最終順列がすでにあると仮定します。`q`の`1..m`プレフィックスの和を法とするもの`m`はペアごとに区別されます。 要素を削除すると`m`、残りのシーケンスは順列です`p`の`1..n`。 再挿入`m`同じ位置に再作成します`q`、 それで`p`は自動的に有効な回答になります。 

問題は次のようになります。 

「どの値に対して、`m`の順列は存在しますか`1..m`プレフィックスの和を法とするもの`m`全部違うの？」

 これは、スーパーパーミュテーションとも呼ばれるよく知られた構造です。 このような順列は次の場合にのみ存在します。`m = 1`または`m`は均等です。 奇数の場合`m > 1`、それらは存在しません。 

以来`m = n + 1`、存在は以下と同等です。`n`奇数である、または`n = 0`(入力には表示されません)。 

だから毎晩`n`不可能です。 

偶数の場合`m = 2k`、簡単な構造は次のとおりです。```
m, 1, m-2, 3, m-4, 5, ..., 2, m-1
```たとえば、次のようなとき`m = 8`:```
8 1 6 3 4 5 2 7
```そのプレフィックスの和を剰余する`8`は：```
0 1 7 2 6 3 5 4
```これは正確にすべての剰余を法とするものです`8`、それぞれ1回ずつ出現します。 

必要な順列を取得するには`p`、単に先頭を削除するだけです`m`。 

つまり、次のようになります。```
1, m-2, 3, m-4, 5, ...
```これは次の順列です`1..n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 最適な構造 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`。 
2. もし`n`偶数、出力`-1`。 

いつ`n`均等です、`m = n + 1`奇数で、より大きい`1`。 長さの有効な最終的な並べ替えがありません`m`存在するので有効ではありません`p`どちらかが存在します。 
3. それ以外の場合は設定します`m = n + 1`。 
4. 以下から最初の要素を削除して得られる順列を構築します。```
m, 1, m-2, 3, m-4, 5, ...
```5. 結果のシーケンスを出力します。 

### なぜ効果があるのか

 偶数の場合`m`、 定義する：```
q = [m, 1, m-2, 3, m-4, 5, ...]
```最初のプレフィックス和モジュロ`m`は`0`。 

追加後`1`、残留物は`1`。 

追加`m-2`に変更します`-1 (mod m)`、つまり`m-1`。 

追加`3`に変更します`2`。 

追加`m-4`に変更します`m-2`。 

このように続けると、剰余は次のようになります。```
0, 1, m-1, 2, m-2, 3, m-3, ...
```すべての剰余モジュロ`m`は 1 回だけ出現するため、すべてのプレフィックスの合計は異なります。 

要素の削除`m`順列を生成します`p`の`1..n`。 再挿入`m`正面で再構築する`q`、それを証明しています`p`は有効な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        if n % 2 == 0:
            ans.append("-1")
            continue

        m = n + 1
        res = []

        l = 1
        r = m - 2

        while l <= r:
            res.append(str(l))
            if l != r:
                res.append(str(r))
            l += 2
            r -= 2

        ans.append(" ".join(res))

    sys.stdout.write("\n".join(ans))

solve()
```最初のブランチは不可能なケースを処理します。 いつ`n`均等です、`m = n + 1`は奇数であり、有効なスーパー順列が存在しません。 

奇数の場合`n`、私たちは生成します:```
1, m-2, 3, m-4, 5, ...
```より大きな順列を構築することなく、直接的に`q`。 

ポインタ`l`そして`r`奇数を昇順に生成し、一致する大きな数を降順に生成します。 なぜなら`m`が偶数の場合、シーケンスには次のすべての整数が含まれます。`1`に`m-1`まさに一度。 

条件`if l != r`2 つのポインターが中央で交わる場合に、同じ数値が 2 回出力されることを回避します。

 ## 特殊なケース

 のために`n = 2`、 我々は持っています`m = 3`、これは奇妙です。 理論によれば、長さの超順列は存在しない`3`存在します。 アルゴリズムは即座に以下を出力します。```
-1
```それは正しいです。 

のために`n = 1`、 我々は持っています`m = 2`。 この構築により以下が生成されます。```
p = [1]
```再挿入`2`先頭では次のようになります。```
2 1
```プレフィックスの和を剰余する`2`は：```
0, 1
```これらは異なるため、答えは有効です。 

より大きな奇数の場合、次のようになります。`n = 9`、 我々は持っています：```
m = 10
p = 1 8 3 6 5 4 7 2 9
```再挿入`10`先頭では長さのスーパーパーミュテーションが生成されます。`10`, したがって、必要な挿入位置は構造上存在します。
