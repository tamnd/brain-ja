 ## 解決策
 ## 問題の理解

 時間依存の迷路のように動作する長方形のグリッドが与えられています。 プレーヤーはグリッドの右上隅からスタートし、左下隅に到達したいと考えています。 移動は段階的に行われ、各段階でプレイヤーは 1 つのセルを 4 方向のいずれかに移動するか、その場にとどまることができます。 

困難は移動の危険から来ます。 各列には水平に前後に巡回するトラが含まれています。 各トラは単位時間ごとに 1 歩移動し、境界で方向を反転します。この動きは完全に決定的です。 この跳ね返り動作により、すべてのトラの位置は時間の経過とともに周期的となり、列の数から導き出される固定期間の後にグリッド全体の構成が繰り返されます。 

移動は、移動直後とトラが次のタイム ステップに向けて位置を更新した後の両方で、プレイヤーがトラとセルを共有していない場合にのみ有効です。 課題は、安全に出口に到達する一連の動きが存在するかどうかを判断することです。 

入力サイズは最大 100 x 100 のグリッドを意味するため、最大 10,000 個の位置が存在します。 トラの位置は時間の経過とともに変化するため、時間も関係しますが、その周期はグリッド幅の小さな関数によって制限されます。 これは、時間の経過に伴う単純な最短経路は実現可能ですが、時間の経過とともに指数関数的に変化するものは不可能であることを直ちに示唆しています。 

メモ化せずに考えられるすべてのパスをシミュレートする単純な試みでは、同じタイムフェーズで同じ構成を繰り返し再利用することになり、指数関数的な爆発につながります。 もう 1 つのよくある間違いは、時間を無視してトラの位置を静的なものとして扱ったり、現在のステップのみをチェックしたりすることです。安全なセルが次の瞬間には危険になる可能性があるために失敗します。 

プレイヤーが現在安全なセルで「待機」しようとすると、次のティックで占有される場合に、微妙なエッジ ケースが発生します。 たとえば、トラが振動して定期的に柱に到達する場合、プレイヤーは局所的には安全に見えても、時間を無視すると次のステップで閉じ込められる可能性があります。 

## アプローチ

 この強引なアイデアは、開始セルからすべての可能な移動シーケンスを探索し、すべてのステップでトラの動きをシミュレートすることです。 これはすべてのパスを試行するため、原理的には正しいですが、指数関数的に分岐します。 ステップごとに 5 つの移動が可能で、深さが最大 ​​10,000 回であっても、これはまったく実行不可能です。 

重要な観察は、システムの状態空間が真に無限ではないということです。 時間に関する唯一の関連情報は、その瞬間のトラの位置であり、トラの動きは周期的であるため、時間はサイクル長を法として短縮できます。 これにより、問題は、各層が時間相に対応する層状グラフ上の最短経路に変換されます。 

これを受け入れると、問題は位置と時間のモジュロ期間によって定義される状態にわたる BFS になります。 各状態には最大 5 つの遷移があるため、全体の複雑さは管理可能になります。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(1)-O(パス) | 遅すぎる |
 | BFS オーバー (r, c, t mod T) | O(n m T) | O(n m T) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. トラのモーションを事前計算する

 各行について、パターンが繰り返されるまで、時間の経過とともにトラの位置をシミュレートします。 この動きは列間の単純な跳ね返りであるため、周期は次のようになります。`2m - 2`。 この期間のすべての行と時間のモジュロごとにタイガー列を保存します。 

これにより、セルが特定の時相で占有されているかどうかを O(1) で答えることができます。 

### 2. BFS 状態空間を定義する

 状態は次のように表されます`(row, col, time_mod)`。 タイガーの位置は`time_mod`。 

から始めます`(1, m, 0)`。 

### 3. セルの有効性をチェックする

 セルは常に安全です`t`もしトラがそこに居なかったら`t`。 各行にはちょうど 1 つのトラがあるため、そのトラの列を確認するだけで済みます。 

どちらの場合でも安全を確保する必要があります`t`そして`t+1`、タイガーアップデートの前後に動きが発生するためです。 

### 4. BFS の移行

 州から`(r, c, t)`上、下、左、右、そして留まるという 5 つの動きを試します。 各候補セルについて`(nr, nc)`、計算します`t_next = (t + 1) % period`。 

次の場合にのみ移動を受け入れます。 

現在のセル`(nr, nc)`時間は空いています`t`同じセルが同時に占有されることはありません`t_next`。 

これにより、完全な移行全体にわたって安全性が確保されます。 

### 5. 訪問追跡

 マークします`(r, c, t_mod)`同じ構成を再度訪問することを避けるために、訪問したとおりにします。 これにより、サイクルの待機によって引き起こされる無限ループが防止されます。 

### 6. 終了

 到達したら`(n, 1, any time)`YESを出力します。 BFS がすべての状態を使い果たす場合は、NO を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、システムの到達可能な各構成を有限グラフ内のノードとして扱います。 トラの位置は期間ごとに繰り返されるため、すべての無限のタイムラインは有限の一連の時間相に崩壊します。 BFS は、この有限状態グラフにわたる最短の到達可能性探索を保証し、安全条件により無効な遷移が決して行われないことを保証します。 すべての有効なパスがこのグラフ内のウォークに対応し、すべてのグラフ ウォークが調査されるため、結果は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    # precompute tiger position for each row over time
    period = 2 * m - 2 if m > 1 else 1
    
    tiger = [[0] * period for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        # simulate one full cycle
        path = []
        pos = 1
        dir = 1
        for t in range(period):
            path.append(pos)
            if m > 1:
                if pos + dir > m or pos + dir < 1:
                    dir *= -1
                pos += dir
        tiger[i] = path
    
    def safe(r, c, t):
        return tiger[r][t] != c
    
    sr, sc = 1, m
    tr, tc = n, 1
    
    dist = [[[-1] * period for _ in range(m + 1)] for _ in range(n + 1)]
    q = deque()
    
    dist[sr][sc][0] = 0
    q.append((sr, sc, 0))
    
    moves = [(1,0), (-1,0), (0,1), (0,-1), (0,0)]
    
    while q:
        r, c, t = q.popleft()
        if r == tr and c == tc:
            print("YES")
            return
        
        nt = (t + 1) % period
        
        for dr, dc in moves:
            nr, nc = r + dr, c + dc
            
            if not (1 <= nr <= n and 1 <= nc <= m):
                continue
            
            if not safe(nr, nc, t):
                continue
            if not safe(nr, nc, nt):
                continue
            
            if dist[nr][nc][nt] != -1:
                continue
            
            dist[nr][nc][nt] = 1
            q.append((nr, nc, nt))
    
    print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各トラの決定論的な動きを行ごとに構築し、時相ごとにトラの列位置を保存します。 これにより、BFS 中の再計算が回避されます。 

BFS 状態空間は 3D 訪問済み配列を使用して、同一の構成が再び使用されないようにします。 遷移ロジックは境界条件を明示的に強制するため、プレーヤーはグリッドから離れることがありません。 重要な正確性の詳細は、移動の前後の両方の時間層をチェックすることです。これにより、遷移直後に安全でなくなるセルに足を踏み入れることを防ぎます。 

## 実用的な例

 ### 例 1

 最初から最後まで斜めのパスにトラが到達しない小さなグリッドを考えてみましょう。 BFS は次から始まります`(1, m, 0)`そしてレイヤーごとに展開していきます。 

| ステップ | ポジション | 時間 | アクション |
 | --- | --- | --- | --- |
 | 1 | (1,m) | 0 | 開始 |
 | 2 | (1, m-1) | 1 | 左に移動 |
 | 3 | (2、m-1) | 2 | 下に移動 |
 | 4 | (n, 1) | k | 到達しました |

 このトレースは、単純な単調降下を示しています。 BFS は、サイクルを待つ必要なく、到達可能性を確認します。 

### 例 2

 次に、トラが中央の柱を振動して直接降下を妨げた場合を考えてみましょう。 

| ステップ | ポジション | 時間 | 安全？ | 決定 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,m) | 0 | はい | 開始 |
 | 2 | (1, m-1) | 1 | はい | 移動 |
 | 3 | (1, m-1) | 2 | いいえ (将来の衝突) | 拒否されました |
 | 3 代替 | (2、m-1) | 2 | はい | 下に移動 |

 ここで、BFS はフェーズに応じて迂回または待機を余儀なくされます。 これは、時間が状態の一部でなければならない理由を示しています。

 ## 特殊なケース

 重大なエッジケースは、トラが交互に目的地のセルを占有する場合です。 将来の占有を無視する単純な BFS では、誤ってステップインが許可されてしまいます。`(n, 1)`到着時は安全でも、到着直後は危険な場合。 

もう一つのケースは、その場で待機する必要がある場合です。 「滞在」移動がないと、トラが通過するまで移動を遅らせなければならない場合、アルゴリズムは失敗します。 

最後に、いつ`m = 1`、周期式は縮退します。 この場合、水平方向の動きはなくトラは静止しているため、ゼロ除算や無効なインデックス付けを避けるために、ピリオドを 1 として扱う必要があります。
