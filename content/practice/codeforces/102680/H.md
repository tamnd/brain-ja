 ## 解決策
 ## 問題の理解

 この問題は、同盟色の無限のシーケンスを定義します。 それは単一の赤いチームから始まります。 シーケンスの次のバージョンを作成するには、現在のシーケンスをコピーし、コピー内のすべての色を交換し、そのコピーを最後に追加します。 パターンを明らかにするにはシーケンスの最初の位置だけで十分ですが、シーケンスは指数関数的に増加するため、非常に大きなランクのチームの色を求めるクエリに答える必要があります。 

入力には複数のチーム ランキングが含まれています。 各ランキングの規模は次のとおりです。$10^{18}$これにより、シーケンスを直接構築することが直ちに除外されます。 最初の保存でも$10^9$文字を配置することはすでに不可能であり、実際の構築には無限に多くの位置が必要です。 クエリの数が少ないため、目的の解は約対数時間で各位置に独立して応答する必要があります。 

難しいケースはシーケンスのサイズに関するものではなく、インデックス付けと再帰境界に関するものです。 シーケンスのインデックスは 1 ですが、ほとんどの実装はインデックスが 0 の位置でも当然動作します。 

たとえば、入力```
1
1
```出力があります```
Red
```ゼロインデックスに誤って変換するソリューションでは、間違ったビットが検査され、Blue が返される可能性があります。 

別のケースは次のとおりです。```
3
2
3
4
```シーケンスは次のように始まります。```
Position: 1 2 3 4
Color:    r b b r
```正しい出力は次のとおりです。```
Blue
Blue
Red
```よくある間違いは、ブロック内の位置を調整せずに、各ブロックの後半が単に前半の逆であると想定することです。 後半は、同じ相対インデックスでの反転コピーです。 

最後のエッジケースは、次のような非常に大きなポジションです。```
1
10000000000000000
```シーケンスは部分的であっても生成できません。 建設をシミュレートしようとするアプローチでは、時間またはメモリが不足します。 

## アプローチ

 簡単なアプローチは、要求された最大のランクに達するまでシーケンスを構築することです。 現在の長さが次の場合$L$、次の建設では2倍になるので、その後$k$反復の長さは$2^k$。 近くの質問に答えるには$10^{18}$、60以上の拡張が必要になります。 その展開数は問題ではありませんが、最終的に保存される文字列には約$10^{18}$文字、それは不可能です。 

直接構築に不要な作業が含まれる理由は、シーケンス全体が必要ではなく、1 つの位置だけが必要だからです。 この構造は再帰的な構造になっています。 一定の長さのブロック$2^k$前半とその前半の反転コピーで構成されます。 位置が前半にある場合、答えは小さいブロック内の対応する位置と同じになります。 後半の場合、答えは前半の対応する位置の反対の色になります。 

これにより、問題は、現在位置が 2 のべき乗ブロックの前半にあるか後半にあるかを繰り返し尋ねることに帰着します。 このプロセスでは各ステップで 1 ビットの情報が削除されるため、操作の数はインデックス内のビット数のみになります。 

生成されたシーケンスは必要なルールに正確に従っているため、ブルート フォースは機能しますが、要求されたランクが大きくなると失敗します。 すべての後半が反転コピーであるという観察により、シーケンスの生成を位置のバイナリ分解に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$最大ランクごと |$O(n)$| 遅すぎる |
 | 最適 |$O(\log n)$クエリごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. チームのランキングを 1 インデックスから 0 インデックスに変換します。 最初の文字がインデックス 0 に対応するため、この方法で再帰的な構造を説明するのが簡単になります。 
2. 現在の色が奇数回反転されたかどうかを表すフラグを保持します。 最初の文字は赤であるため、最初はフラグは false です。 
3. 現在位置を含むブロックの 2 の最大累乗を見つけます。 一定の長さのブロック$2^k$より短い長さのブロックで形成されます$2^{k-1}$次にその反転コピーが続きます。 
4. 位置がブロックの前半にある場合は、現在の反転状態を維持し、小さいブロック内の同じ位置を続行します。 
5. 位置が後半にある場合は、位置から前半のサイズを減算し、反転状態を切り替えます。 後半に進むということは、反転したコピーを見ていることを意味します。 
6. 1 つの位置だけが残るまでブロックの縮小を続けます。 最終的な反転状態によって答えが決まります。 false 状態は赤を意味し、true 状態は青を意味します。 

なぜ効果があるのか:

 すべてのステップで、現在のブロックは、より小さいブロックとその小さいブロックの反転コピーによって正確に表されます。 アルゴリズムは、位置がこれら 2 つのケースのどちらに属するかを追跡します。 反転コピーに移動するたびに、色の状態が切り替わり、現在の位置の意味が維持されます。 ブロックサイズが1になると元の文字が赤くなり、反転の積み重ねが実際の答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_position(n):
    n -= 1
    flipped = False

    while n > 0:
        length = 1
        while (length << 1) <= n:
            length <<= 1

        if n >= length:
            n -= length
            flipped = not flipped

    return "Blue" if flipped else "Red"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        ans.append(solve_position(n))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```この関数はまずランクを 0 から始まるインデックスに変更します。 これにより、数学的シーケンス定義と実装オフセットの混合が回避されます。 

変数`flipped`再帰ブロックの反転された半分に入った回数を格納します。 重要なのはパリティのみであるため、ブール値で十分です。 

ループは、現在位置を超えない最大の 2 のべき乗を繰り返し見つけます。 位置がその境界を越えている場合、その位置は現在のブロックの後半に属します。 前半を削除すると、小さいブロック内の対応する位置が得られ、切り替えます。`flipped`反転を説明します。 

ランキングには次の制限があるため、2 のべき乗を見つけるためのネストされたループは最大約 60 回実行されます。$10^{18}$。 Python 整数はこのサイズを直接処理するため、オーバーフロー処理は必要ありません。

## テストケース```python
import sys
import io

def solve_position(n):
    n -= 1
    flipped = False
    while n > 0:
        length = 1
        while (length << 1) <= n:
            length <<= 1
        if n >= length:
            n -= length
            flipped = not flipped
    return "Blue" if flipped else "Red"

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        out.append(solve_position(int(sys.stdin.readline())))
    sys.stdin = old
    return "\n".join(out) + "\n"

3
8

Blue
""", "sample"

""") == """Red
""", "minimum position"

4
""") == """Red

Red
""", "first block boundary"

9
""") == """Red

""", "power of two boundary"

Blue

 元のシーケンスは赤で始まるため、最初の位置は特別です。 入力の場合:```

新しいブロックの開始位置に正確に位置する場合は、後半のロジックを慎重に適用する必要があります。 入力の場合:```

Position 3: Blue
