 ## 解決策
 ## 問題の理解

 この問題は、接続された方向のない道路網について説明しています。 各交差点は頂点であり、各道路はエッジです。 3 人のレーサーは、開始交差点と終了交差点を選択したいと考えています。 すべてのレーサーは常にこれら 2 点間の可能な最短ルートを選択するため、レース ルートは選択したペアの最短パスの 1 つになるように強制されます。 目標は、最短経路ができるだけ長い交差点のペアを選択することです。 

グラフの用語では、任意の 2 つの頂点間の最大最短経路距離を見つける必要があります。 この値はグラフの直径です。 答えは、訪れた交差点の数ではなく、通過した道路をカウントします。 5 つの交差点を含むパスは、4 本の道路を使用するため、長さは 4 になります。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、交差点と道路の数が示され、その後に方向のない道路の接続が示されます。 グラフは接続されていることが保証されているため、すべての交差点は他のすべての交差点に到達できます。 

制限は十分に小さいため、頂点数が 2 次程度またはわずかに上回るアルゴリズムを使用できます。 すべてのテスト ケースの交差の合計数は最大 1000 で、個々のグラフの交差の数は最大 500 であるため、すべての頂点から幅優先検索を実行するのが実用的です。 頂点と検索パスのすべてのペアを個別に列挙しようとするソリューションでは、多くの作業が繰り返され、不必要にコストがかかります。 

不適切な実装が失敗する可能性があるエッジケースがいくつかあります。 1 つの交差と 1 つの自己ループを持つグラフでは、異なる点の間で移動する必要がないため、答えはゼロになります。```
1
1 1
1 1
```正しい出力は次のとおりです。```
0
```答えを 1 つに初期化するソリューションや、すべてのパスに少なくとも 1 つの道路が含まれると仮定するソリューションでは、間違った結果が生成されます。 

最長の最短経路が単純に見えるチェーンではないグラフもよくある間違いです。 例えば：```
1
4 4
1 2
2 3
3 4
1 4
```正しい出力は次のとおりです。```
2
```1 から 4 までの直線道路により、直径が 3 になるのを防ぎます。 最長の最短パスではなく、可能な限り最長の歩行を検索する不用意なアプローチでは、パス 1-2-3-4 が誤って選択されてしまいます。 

並行道路やセルフループについても特別な場合を除き対応する必要があります。 すべての道路のコストは同じであるため、2 つの交差点間の最短距離は変わりません。 BFS 実装では、当然ながら、繰り返されるエッジと自己ループは無視されます。 

## アプローチ

 直接的な総当たりの解決策では、交差のすべてのペアが考慮されます。 各ペアに対して、最短経路アルゴリズムを実行してそれらの距離を見つけ、見つかった最大値を保持します。 グラフは重み付けされていないため、各最短パス クエリには BFS で十分です。 と$n$頂点、あります$O(n^2)$ペアと各 BFS コスト$O(n+m)$、全体の複雑さは次のようになります。$O(n^2(n+m))$。 と$n=500$、これはすでにテスト ケースごとに約 1 億 2,500 万の頂点エッジ処理ユニットに達しており、回避できる作業を繰り返しています。 

重要な点は、1 つの開始交差点から他のすべての交差点までの最短距離を一度に計算できることです。 BFS はグラフをレイヤーごとに探索するため、1 つの BFS の後、1 つの頂点から他のすべての頂点までの距離がわかります。 グラフは重み付けされていないため、ダイクストラ検索やペアごとの検索を繰り返す必要はありません。 

最適な方法は、すべての交差点から BFS を 1 回実行することです。 各 BFS はその発生源からのすべての距離を示し、それらの最大値が直径の候補となります。 エンドポイントの 1 つが BFS ソースとして使用される場合、考えられるすべてのペアが表示されるため、すべてのソースの最大の候補を取ると答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²(n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての交差点の隣接リストを作成します。 どちらの方向への移動も許可されるため、各道路は両方向に追加されます。 
2. すべての交差点から BFS を実行します。 BFS 中に、選択したソースから他のすべての交差点までの最短距離を保存します。 
3. 各 BFS が終了した後、その発信元から到達した最大距離を検査し、グローバル最大値を更新します。 この値は、現在の交差点から始まる最長の最短ルートを表します。 
4. すべての交差点が BFS ソースとして使用された後、記録された最大距離を出力します。 これらの BFS 実行の 1 つを通じて、考えられるすべての開始と終了のペアが検討されました。 

なぜ効果があるのか:

 アルゴリズムの背後にある不変条件は、頂点からの BFS の後、保存されるすべての距離は、その頂点から対応する目的地までの可能な最短の道路数であるということです。 BFS は距離の小さい順に頂点を訪問するため、この特性を持っています。 すべての頂点がソースとして使用されるため、すべての交差ペアの最短距離が少なくとも 1 回計算されます。 これらすべての最短距離の最大値が、まさにグラフの直径になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def bfs(start, graph):
    n = len(graph)
    dist = [-1] * n
    dist[start] = 0
    queue = [start]
    head = 0

    while head < len(queue):
        u = queue[head]
        head += 1
        for v in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                queue.append(v)

    return max(dist)

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        graph = [[] for _ in range(n)]

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            graph[a].append(b)
            graph[b].append(a)

        diameter = 0
        for i in range(n):
            diameter = max(diameter, bfs(i, graph))

        ans.append(str(diameter))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```各道路は各方向で 1 回処理されるため、隣接リストにはグラフが効率的に保存されます。 BFS 関数は、最初の要素を繰り返し削除する代わりに、リストをインデックスとともにキューとして使用し、次のような操作の線形コストを回避します。`pop(0)`。 

距離配列は次で始まります`-1`、まだ到達していない交差点を表します。 BFS は、未訪問の近隣ノードを見つけると、親の距離に 1 を加えた値を割り当てます。 BFS はレイヤーに拡張されるため、最初に割り当てられる距離は常に最短距離になります。 

外側のループはすべての交差点から BFS を実行します。 BFS によって返される最大距離は、最終的な直径です。 グラフは接続されていることが保証されているため、すべての BFS はすべての頂点に到達し、`max(dist)`は常に有効です。 

Python の整数はオーバーフローせず、キューの最大サイズは交差の数によって制限されます。 この実装では再帰も回避され、再帰の深さの問題のリスクが排除されます。

## 特殊なケース

 BFS は距離 0 から開始し、それ以上の頂点を検出しないため、自己ループのみを持つ単一の交差は正しく処理されます。 最大距離はゼロのままで、道路を通過する必要がないという事実と一致します。```
1
1 1
1 1
```BFS キューには、開始交差のみが含まれます。 自己ループはすでに訪問した頂点を指すため、距離配列はそのまま残ります。`[0]`。 

ショートカットを含むグラフでは、可能な限り最長のルートではなく、最短距離を使用する必要があります。 例では:```
1
4 4
1 2
2 3
3 4
1 4
```交差点 1 からの BFS からの距離`[0,1,2,1]`。 2 と 3 を経由するルートは存在しますが、直接エッジ 1 ～ 4 の方が短いため、4 への最短ルートではありません。 アルゴリズムは距離 2 を最大値として記録しますが、これは正しいです。 

並行道路や自己ループでは追加の処理は必要ありません。 BFS は、近隣が既に訪問されているかどうかのみを考慮します。 複数の同一のエッジは依然として同じ最短距離を生成し、自己ループは既知の距離を短縮できません。
