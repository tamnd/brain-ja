 ## 解決策
 ## 問題の理解

 この問題は、次から番号が付けられた一連の位置を記述しています。`1`に`n`。 位置の一部の範囲は削除されます。これは、欠落しているオブジェクトを含めることができないことを意味します。 指定された範囲がすべて削除された後、可能性のある位置は 1 つだけ残ります。 課題は、残りの位置を見つけることです。 

入力により、位置の合計数と削除された範囲の数が得られ、その後に削除された各間隔の開始と終了が続きます。 間隔が重なる場合があるため、同じ位置を複数回削除することができます。 出力は、どの間隔にも含まれない単一の位置です。 元の制約により、`n`と同じくらい大きくなる`2,000,000,010`最大間隔の数`1000`したがって、すべての位置を反復処理することは不可能です。 すべての位置にわたるループには数十億回の操作が必要ですが、間隔の数は十分に小さいため、主に間隔に依存するアルゴリズムが意図した方向になります。 

直接シミュレーションにも隠れたメモリの問題があります。 長さの配列の作成`n`削除された位置にマークを付けることは不可能です。`n`約20億になる可能性があります。 ソリューションは、指定された間隔とそれらの間のギャップでのみ機能する必要があります。 

最初のエッジケースは、答えがすべての削除された範囲の前にある場合です。 例えば：```
10 1
3 10
```正しい出力は次のとおりです。```
1
```間隔のペア間のギャップのみをチェックする不注意なアプローチでは、最初の間隔の前のプレフィックスを見逃してしまいます。 

2 番目のエッジ ケースは、答えがすべての削除された範囲の後にある場合です。```
10 1
1 9
```正しい出力は次のとおりです。```
10
```最後の間隔の後にサフィックスをチェックするのを忘れた実装は、ここで失敗します。 

3 番目のエッジ ケースは、重複する間隔です。```
10 3
3 5
5 8
7 10
```正しい出力は次のとおりです。```
1
```カバーされた最も遠い位置をマージしたり追跡したりせずに間隔が独立して処理される場合、重複する範囲によって実際には存在しない偽のギャップが作成される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての位置の表現を次から作成します。`1`に`n`、すべての間隔内のすべての位置を削除済みとしてマークし、唯一残っている位置をスキャンします。 これは、答えの定義に直接従うため、正解です。 

問題は次の値です。`n`。 最大のケースでは、スキャンだけで約 20 億の操作が必要となり、配列の保存には数十億のエントリが必要になります。 更新間隔を考慮する前でさえ、表現自体が大きすぎます。 

有益な観察は、間隔の数が座標範囲に比べて小さいことです。 削除された位置は次のようにのみ記述されます。`u`間隔、ここで`u`せいぜい`1000`。 すべての位置を調べる代わりに、カバレッジが変化する場所を調べることができます。 

開始位置で間隔を並べ替え、重複する間隔をマージすると、マージされたすべての間隔は、削除された位置の連続ブロックを表します。 失われたオブジェクトは、マージされた 2 つの間隔の間のギャップ内、または最初の間隔の前、または最後の間隔の後にある必要があります。 カバーされていないポジションが 1 つだけ存在することが保証されているため、そのギャップを見つけるだけで十分です。 

個々の位置がすべてチェックされるため、総当たり攻撃は機能しますが、座標空間が膨大であるため失敗します。 間隔の境界のみが重要であるという観察により、問題のサイズを小さくすることができます。`n`間隔の数に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n + カバーされる全長) | O(n) | 遅すぎる |
 | 最適 | O(u ログ u) | O(u) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を読み取り、左側のエンドポイントで並べ替えます。 並べ替えると、間隔が近いものが隣り合って配置されるため、1 回のパスで重複検出が可能になります。 
2. ソートされた間隔を結合します。 現在カバーされているセグメントを保持します。 次の間隔が現在のセグメントの前または終わりから始まる場合は、必要に応じて現在のセグメントを延長します。 そうしないと、2 つのセグメント間にギャップが生じます。 
3. 最初のマージされた間隔を受け入れる前に、それが位置の後に始まるかどうかを確認します。`1`。 そうなった場合、それ以前のすべてのポジションが明らかになり、有効なポジションは 1 つだけであるため、そのポジションが答えになります。 
4. すべての間隔を処理した後、連続するマージされた間隔の間のギャップを確認します。 1 つのマージされた間隔が次の時点で終了する場合、`a`そして次はから始まります`b`、その後、からのすべての位置`a + 1`に`b - 1`が明らかになります。 残るポジションは1つだけなので、`a + 1`が答えです。 
5. 以前のギャップが見つからなかった場合、残りの可能性は、最後にマージされた間隔の後のサフィックスです。 答えは終了から 1 つ後の位置です。 

なぜ効果があるのか:

 マージ後、削除されたすべての位置は 1 つのマージされたセグメントにのみ属し、マージされた 2 つのセグメントが重なったり接触したりすることはありません。 これは、これらのセグメント内にないすべてのポジションが実際に利用可能であることを意味します。 アルゴリズムは、そのような位置が存在する可能性のあるすべての領域 (プレフィックス、セグメント間のすべてのギャップ、およびサフィックス) をチェックします。 入力では利用可能な位置が 1 つだけ保証されるため、最初に見つかったカバーされていない位置が必要な答えとなる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, u = map(int, input().split())
    intervals = []

    for _ in range(u):
        l, r = map(int, input().split())
        intervals.append((l, r))

    if u == 0:
        print(1)
        return

    intervals.sort()

    merged = []
    cur_l, cur_r = intervals[0]

    for l, r in intervals[1:]:
        if l <= cur_r + 1:
            if r > cur_r:
                cur_r = r
        else:
            merged.append((cur_l, cur_r))
            cur_l, cur_r = l, r

    merged.append((cur_l, cur_r))

    if merged[0][0] > 1:
        print(1)
        return

    for i in range(len(merged) - 1):
        left_end = merged[i][1]
        right_start = merged[i + 1][0]
        if right_start - left_end > 1:
            print(left_end + 1)
            return

    print(merged[-1][1] + 1)

if __name__ == "__main__":
    solve()
```コードは最初に間隔のみを保存し、個々の位置は保存しません。 これにより、範囲の数に比例したメモリが維持されます。 

マージループはセグメントを維持します`[cur_l, cur_r]`これは、接続されている現在既知のすべての削除された位置を表します。 次の間隔がこのセグメントの内側または直後に始まるとき、右の端点を拡張することで表現がコンパクトに保たれます。 の`+1`で`l <= cur_r + 1`これは意図的なものであり、接触する間隔によってそれらの間に覆われていない位置が残らないためです。 

マージ後、チェックは座標順に実行されます。 プレフィックス チェックでは、最初に削除されたセグメントより前の回答が処理されます。 ループは内部ギャップをチェックします。 最後の出力では、最後に削除されたセグメントの後の接尾辞が処理されます。 答えが存在することが保証されているため、最終行には常に有効な位置が出力されます。 

Python の整数はオーバーフローしないため、大きな値は`n`特別な取り扱いは必要ありません。 この実装では再帰も回避され、間隔の小さなリストのみが使用されます。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, u = map(int, data().split())
    intervals = []

    for _ in range(u):
        intervals.append(tuple(map(int, data().split())))

    if u == 0:
        ans = 1
    else:
        intervals.sort()
        merged = []
        l, r = intervals[0]

        for nl, nr in intervals[1:]:
            if nl <= r + 1:
                r = max(r, nr)
            else:
                merged.append((l, r))
                l, r = nl, nr

        merged.append((l, r))

        if merged[0][0] > 1:
            ans = 1
        else:
            ans = merged[-1][1] + 1
            for i in range(len(merged) - 1):
                if merged[i + 1][0] - merged[i][1] > 1:
                    ans = merged[i][1] + 1
                    break

    sys.stdin = old_stdin
    return str(ans)

 ## 特殊なケース

 プレフィックスの場合:```
10 1
3 10
```マージされたリストには、`(3,10)`。 最初のマージされた間隔は、position で始まりません。`1`、したがってアルゴリズムはすぐに戻ります`1`。 ここではスキャンベースのソリューションが機能しますが、間隔ベースのソリューションはこの境界を明示的に処理する必要があります。 

接尾辞の場合:```
10 1
1 9
```統合されたリストは、`(1,9)`。 内部ギャップがないため、最終チェックが返されます。`9 + 1 = 10`。 これにより、間隔の前または間隔の間のスペースのみを検査するソリューションが捕捉されます。 

重複する間隔の場合:```
10 3
3 5
5 8
7 10
```ソートされた間隔は次のようにマージされます。`(3,10)`。 アルゴリズムは、繰り返しのカバレッジを余分な空きポジションの作成として扱うことはありません。 プレフィックスがカバーされていないため、返されます。`1`、これが唯一の有効な答えです。
