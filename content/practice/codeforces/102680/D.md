 ## 解決策
 ## 問題の理解

 タスクは、与えられたそれぞれの自然数を分類することです。 正の約数が 1 とその数値だけである場合、その数値は素数になります。 少なくとも 1 つの追加の除数がある場合、それは複合です。 特別な値 1 は、正の約数が 1 つしかないため、どちらのカテゴリにも属しません。 

入力には複数の独立した数値が含まれています。 各数値について、その分類を説明する 1 つの単語を正確に出力します。 

主な問題は、入力量ではなく、値のサイズです。 数値は 100 個までしか指定できませんが、各数値は 2,000,000,000 まで大きくなる可能性があります。 2 から数値自体までのすべての可能な約数をチェックするには、1 つの値に対して最大 2,000 億回のチェックが必要となり、利用可能な時間をはるかに超えています。 多くの大きなケースを線形にチェックすることさえ現実的ではありません。 約数の数学的構造を利用する必要があります。 

有効な除数の検索制限の最大値は数値の平方根です。 数値の約数が平方根より大きい場合、一致する約数は平方根より小さくなります。 これにより、検索スペースが最大値で約 44,721 チェックに減少し、100 個のテスト ケースを容易に管理できます。 

最初のエッジ ケースは番号 1 です。入力の場合:```
1
1
```正しい出力は次のとおりです。```
Neither
```約数が見つかったかどうかだけをチェックする不注意な実装では、2 以降の約数が見つからないため、誤って 1 を素数としてラベル付けする可能性があります。 

もう 1 つのエッジケースは完全な正方形です。 入力の場合:```
1
49
```正しい出力は次のとおりです。```
Composite
```平方根が数値の平方根よりも厳密に小さい場合にのみ約数をチェックするプログラムでは、誤って約数 7 を見逃し、49 を誤って分類する可能性があります。 

最後のエッジ ケースは、制限に近い大きな素数です。```
1
2000000000
```これには多くの要素があるため、これは素数ではありません。 少数の小さな約数だけをテストしたり、不完全な素数テーブルを使用したりすると、不正確な結果が得られる可能性があります。 

## アプローチ

 直接的なアプローチは、2 から (q-1) までの可能な約数をすべて試してみることです。 何らかの値が (q) を割る場合、その数値は合成されます。 それ以外の場合はプライムです。 1 を除くすべての非素数には 1 とそれ自体以外の約数があるため、これは正しいです。 

問題は走行時間です。 (q = 2,000,000,000) の場合、総当たり法は 1 つの数値に対してほぼ 20 億回のモジュロ演算を実行する可能性があります。 最大 100 個の入力では、最悪の場合、約 (2 \cdot 10^{11}) 回の演算に達します。 

重要な観察は、約数がペアで表示されることです。 (a \times b = q) の場合、(a) と (b) の少なくとも 1 つは最大でも (\sqrt q) になります。 約数を検索するときは、平方根までの候補をテストするだけで済みます。 1 を見つけた場合はその数が合成であることを意味し、最後に到達した場合はその数が素数であることを意味します。 

ブルートフォース手法は、考えられるすべての要素をチェックするため機能しますが、多くの不必要なチェックが繰り返されます。 平方根観測では、除数のペアの小さい方のメンバーになり得ないすべての候補が削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 数値ごとの O(q) | お(1) | 遅すぎる |
 | 最適 | 数値あたり O(sqrt(q)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各数値を個別に読み取り、値が 1 である特殊なケースを処理します。1 には正の約数が 1 つだけあるため、すぐに「どちらでもない」として分類する必要があります。 
2. 2 から数値の平方根までのすべての整数の約数を試します。 約数が均等に除算される場合、その数値には 1 とそれ自体とは異なる因数のペアがあるため、その数値は複合になります。 
3. 約数が見つからないままループが終了した場合、その数値を素数として分類します。 考えられるすべての因子ペアには、すでにテストされた小さな因子が含まれているはずです。 

なぜ効果があるのか:

 このアルゴリズムは、現時点までにすべての候補約数をテストした後、数値の小さい因数が見逃されていないという不変条件を維持します。 どの合成数にも因数ペアがあります。 そのペアの小さい方の要素は平方根を超えることができないため、検索では常に合成数の約数が見つかります。 素数にはそのような約数がないため、完全な検索でも生き残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def classify(x):
    if x == 1:
        return "Neither"

    d = 2
    while d * d <= x:
        if x % d == 0:
            return "Composite"
        d += 1

    return "Prime"

def solve():
    n = int(input())
    ans = []

    for _ in range(n):
        x = int(input())
        ans.append(classify(x))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`classify`関数は数学的決定を分離します。 最初の条件は、素数でも合成でもない数値のみを削除します。 

ループは使用します`d * d <= x`浮動小数点の平方根を計算する代わりに。 これにより、大きな整数の精度の問題が回避され、完全二乗も当然含まれます。 

除数が見つかると、それ以上のチェックでは答えを変えることができないため、関数はすぐに戻ります。 ループが終了すると、平方根までの約数はなくなり、素数であることが証明されます。 

Python の整数はオーバーフローしないため、ループ条件での乗算は安全です。 最大値はわずか 20 億で、Python の整数制限をはるかに下回ります。

 ## 特殊なケース

 値 1 は、除数ループが開始される前に処理されます。 入力の場合:```
1
1
```アルゴリズムはすぐに「どちらでもない」を返します。 素数チェック ロジックには決して入らないため、約数が発見されていない数値を素数として扱うというよくある間違いを防ぐことができます。 

次のような完全な正方形の場合:```
1
49
```ループは継続します`d * d <= x`、許可します`d = 7`テストされること。 約数が見つかり、答えは複合になります。 厳密な不等式を使用すると、このケースはスキップされます。 

次のような大きな値の場合:```
1
2000000000
```アルゴリズムは、すべての小さい数値をスキャンしようとはしません。 候補を平方根までチェックするだけで、約数をすばやく見つけて実行時間を予測可能に保ちます。
