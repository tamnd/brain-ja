 ## 問題の理解

 ノーバートは多くの説明要求に答えなければなりません。 すべての回答は空ではない文字列である必要があり、2 つの回答が同じであってはなりません。 競技ごとに、彼は正確に含む言語を選択します。`n`可能なキャラクターと作成する必要がある`q`それらの文字を使用して別の文字列を作成します。 目標は、すべての回答にわたって入力される文字の合計数を最小限に抑えることです。 

入力には、いくつかの独立したコンテストが含まれています。 それぞれが与える`q`、必要な個別の応答の数、および`n`、アルファベットのサイズ。 競技ごとに、すべての競技の長さの最小の合計を出力します。`q`選んだ弦。 

この制約により、文字列の明示的な生成を回避する必要があります。 リクエストの数は次のとおりです$10^{11}$したがって、応答ごとに 1 回反復することさえ不可能です。 アルファベットのサイズは次のように大きくできます。$10^5$これは、使用可能な文字数に応じたソリューションや生成された文字列の保存が適合しないことを意味します。 唯一の実際的なアプローチは、考えられる長さごとに文字列がいくつ存在するかを推論することです。 

いくつかのケースでは、誤って処理されやすいものがあります。 リクエストよりも 1 文字の文字列が少ない場合、長さ 1 を使用し続けることはできません。 例えば：```
1
5 2
```正しい出力は次のとおりです。```
9
```キャラクターが2人いると、`2`長さ 1 の文字列。 残りの 3 つの応答の長さは 2 である必要があり、合計は次のようになります。`1 + 1 + 2 + 2 + 2 = 8`? この計算は、長さ 2 のすべての文字列を別個のグループとして扱うという間違いを示しています。 利用可能な長さ 2 の文字列は次のとおりです。`4`したがって、実際には最小値は 2 つの 1 文字の文字列と 3 つの 2 文字の文字列になります。```
1 + 1 + 2 + 2 + 2 = 8
```したがって、正しい出力は次のようになります。```
8
```長さ 2 から開始する不注意な実装や、文字列の数が直線的に増加すると仮定した実装は、ここで失敗します。 

もう 1 つの特殊なケースは、必要な回答がすべて最短の長さに収まる場合です。 例えば：```
1
3 10
```正しい出力は次のとおりです。```
3
```1 文字の回答は 10 通りあるため、3 つのリクエストに必要なのは合計 3 文字だけです。 常に少なくともいくつかの長い文字列を追加するアプローチでは、答えが過大評価されてしまいます。 

最後の境界ケースは、アルファベットが小さく、多くの長さが必要な場合に発生します。```
1
14 3
```正しい出力は次のとおりです。```
27
```がある`3`長さ 1 の文字列と`9`長さ 2 の文字列、残り`2`長さ 3 でなければならない文字列。 合計は`3 * 1 + 9 * 2 + 2 * 3 = 27`。 

## アプローチ

 直接的な総当たりの解決策では、考えられるすべての文字列をリストし、長さで並べ替えて、最初の文字列を取得しようとします。`q`文字列。 これは正しいです。短い文字列は常に合計への寄与が少ないため、最適なセットには長い文字列を取得する前に、利用可能な短い長さの文字列がすべて含まれている必要があります。 

問題は、文字列の数が指数関数的に増加することです。 アルファベットがあれば、`n`キャラクター、あります$n^k$一定の長さの文字列`k`。 たとえ小さなアルファベットであっても、取り得る文字列の数は膨大になり、最大リクエスト数は$10^{11}$。 文字列の生成または保存はリモートでは実行できません。 

重要な点は、実際の文字列は気にしていないということです。 それぞれの長さの文字列が何本あるかを知る必要があるだけです。 まさにあります$n^1$長さ 1 の文字列、$n^2$長さ 2 の文字列など。 同じ長さのすべての文字列は同じコストに寄与するため、要求されたすべての応答が割り当てられるまで、これらのグループを最短の長さから最長の長さまで使用できます。 

唯一の課題は、非常に大きな電力を処理することです。 残りのリクエスト数よりも大きな累乗を計算する必要はありません。答えを完成させるのに十分な文字列が長さになれば、それ以上の長さは意味を持たなくなるからです。 乗算の上限は次のとおりです。`q`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1.読む`q`そして`n`一つの競技のために。 変数`remaining`は、まだ割り当てる必要がある個別の回答の数を表します。 
2. 回答の長さから始めます`1`。 がある`n`この長さの文字列は可能です。 可能な限り、次の値のうち小さい方の値を選択します。`n`そして`remaining`、そしてその貢献度の合計を結果に加えます。 選択された各回答は、その長さに正確に影響します。 
3. リクエストがまだ残っている場合は、長さを 1 つ増やします。 新しい長さの利用可能な文字列の数が次のように乗算されます。`n`。 長さを増やして、文字列の完全なグループを取得し続けます。 
4. すべてが終わったらすぐに停止します`q`答えが割り当てられています。 常に短い文字列を最初に消費するため、累積合計は最小限になります。 

これが機能する理由: 不変条件は、現在の長さよりも小さいすべての長さを処理した後、アルゴリズムがそれらの長さの中で可能な限り最も安価な応答を正確に選択することです。 処理された長さから選択されなかった文字列は、今後のすべての文字列よりも短くなります。そのため、選択した長い文字列をそれに置き換えても、合計を減らすか維持することしかできません。 短いグループがすべて使い尽くされると、同じ引数が現在の長さのグループに適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        q, n = map(int, input().split())

        remaining = q
        length = 1
        ans = 0
        count = n

        while remaining > 0:
            take = min(remaining, count)
            ans += take * length
            remaining -= take
            length += 1

            if remaining > 0:
                count = min(remaining, count * n)

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```変数`count`現在の長さで利用可能な文字列の数を格納します。 長さを処理した後、次のグループは`count * n`既存の文字列はすべて、次のいずれかを使用して拡張できるためです。`n`文字。 

乗算の上限は次のとおりです`remaining`。 これにより、不必要な非常に大きな整数の作成が回避されます。 未回答のリクエストよりも多くの文字列が存在する可能性がある場合は、リクエストの数のみが重要になります。 

空の文字列は許可されないため、ループは長さ 1 から始まります。 更新の順序も重要です。次の長さに移動する前に、現在のグループが回答に貢献する必要があります。
