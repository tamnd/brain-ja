 ## 解決策
 ## 問題の理解

 この問題のプログラムは非常に小さな人工機械です。 8 ビット レジスタが 1 つあります`r`したがって、レジスタには次の値のみを含めることができます。`0`に`255`。 実行は最初の命令から開始されます。`r = 0`。 各命令はレジスタを変更して次の命令に移動するか、レジスタをチェックして別の命令にジャンプする可能性があります。 プログラムは、実行が最後の命令を超えた場合にのみ停止します。 

タスクは、指定されたプログラムが最終的にこの停止点に到達するか、それとも永遠に実行し続けるかを判断することです。 

制約は、言語の特殊な構造に基づいて設計されています。 通常のプログラムには最大で`10^4`すべてのテスト ケースの命令の合計数は最大で`10^5`。 未知の時間にわたって任意のプログラムをシミュレートすることは一般に不可能ですが、この言語には有限の状態空間があります。 現在の命令には次のものを含めることができます`n + 1`可能な位置があり、レジスタには 256 個の可能な値しかありません。 これにより得られるのはせいぜい約`256 * n`異なる実行状態。 のために`n = 10^4`、これは約 256 万州であり、一度訪れるには十分な規模です。 

主なエッジケースは、レジスタを変更せずにループするプログラムです。 例えば：```
2
add 0
beq 0 1
```正しい出力は次のとおりです。```
No
```最初の命令の後、レジスタはまだゼロです。 2 番目の命令は最初の命令に永久に戻ります。 サイクル検出のない単純なシミュレーションは決して完了しません。 

もう 1 つのケースは、レジスタがラップアラウンドするため、最終的に新しい状態に到達するループです。 例えば：```
3
add 252
add 1
bgt 252 2
```正しい出力は次のとおりです。```
Yes
```レジスタは 8 ビットなので、255 に達すると 0 にラップされます。レジスタを無制限の整数として扱うソリューションでは、値が増加し続けると誤って認識され、停止パスを見逃してしまいます。 

3 番目のよくある間違いは、命令ポインターが状態の一部であるという事実を無視することです。 考慮する：```
3
add 1
bne 252 1
beq 252 1
```正しい出力は次のとおりです。```
No
```レジスタ値だけでは繰り返しを検出するのに十分ではありません。 異なる命令における同じレジスタ値は、異なる将来の動作を表します。 

## アプローチ

 直接的なアプローチは、プログラムを命令ごとに実行することです。 実行が指示に到達した場合`n + 1`、プログラムは停止し、答えは次のようになります。`Yes`。 実行が永遠に続く場合、このシミュレーションは決して終了しないため、無限実行を認識する方法が必要です。 

ブルート フォース バージョンでは、任意のステップ数だけプログラムを実行できます。 これは不正解です。有効なプログラムでは、停止するまでにさらに多くのステップが必要になる場合があります。 最悪のケースにはあらゆる可能性が含まれる可能性があります`(instruction, register)`繰り返す前の状態。`256 * n`州。 と`n = 10^4`、これは約 256 万回のトランジションであるため、完全な境界付きシミュレーションで十分ですが、境界なしのシミュレーションでは十分ではありません。 

重要な観察は、このマシンが決定論的であるということです。 現在の命令とレジスタ値がわかれば、次の状態は完全に固定されます。 有限数の状態にわたる決定論的なプロセスは、停止状態に到達するか、最終的には状態を再訪する必要があります。 状態が再訪されるということは、将来同じ実行が永久に繰り返されることを意味します。 

状態空間が有限であるという観察により、問題を暗黙的なグラフ上のグラフ走査に縮小することができます。 グラフを構築する必要はありません。 単一の実行パスをたどっている間にどの状態がすでに出現したかを覚えておく必要があるだけです。

| 最適 | O(256n) | O(256n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての命令を使いやすい表現で保存します。 アン`add`命令はその値のみを保存しますが、分岐命令は条件、宛先、およびタイプを保存します。 
2. 命令から実行を開始する`0`レジスタ値付き`0`。 命令の位置とレジスタ値によってインデックス付けされた訪問済みテーブルを使用します。 
3. 命令を実行する前に、現在の状態かどうかを確認してください。`(instruction, register)`ペアはすでに訪問されています。 そうであった場合、マシンは以前の状況を繰り返しているため、プログラムは決して停止しません。 
4. 現在の状態を訪問済みとしてマークし、命令を実行します。 算術命令の場合、レジスタには 8 ビットしかないため、モジュロ 256 を使用してレジスタを更新します。 
5. 分岐命令の場合は、レジスタと保存された値を比較します。 条件が真の場合、宛先の命令にジャンプします。 それ以外の場合は、次の指示に進みます。 
6. いずれかの指示が出るまで繰り返します`n + 1`に達するか、繰り返される状態が見つかります。 

これが機能する理由は、実行が決定的であるためです。 状態は、実行中の命令と現在のレジスタ値によって完全に記述されます。 同じ状態が 2 回現れると、その後のすべての遷移も同じになり、無限サイクルが作成されます。 状態が繰り返されない場合、実行は最終的に停止位置に到達して有限状態空間を離れる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        prog = []

        for _ in range(n):
            parts = input().split()
            if parts[0] == "add":
                prog.append(("add", int(parts[1])))
            else:
                prog.append((parts[0], int(parts[1]), int(parts[2]) - 1))

        visited = [[False] * 256 for _ in range(n)]
        pc = 0
        r = 0

        while pc < n:
            if visited[pc][r]:
                ans.append("No")
                break

            visited[pc][r] = True
            ins = prog[pc]

            if ins[0] == "add":
                r = (r + ins[1]) % 256
                pc += 1
            else:
                op, v, k = ins
                ok = False

                if op == "beq":
                    ok = (r == v)
                elif op == "bne":
                    ok = (r != v)
                elif op == "blt":
                    ok = (r < v)
                elif op == "bgt":
                    ok = (r > v)

                if ok:
                    pc = k
                else:
                    pc += 1
        else:
            ans.append("Yes")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラム表現では、操作名とその操作に必要なパラメーターのみが保持されます。 ジャンプ ターゲットはすぐに 0 から始まるインデックスに変換されるため、シミュレーション中に繰り返し 1 を減算する必要がなくなります。 

の`visited`配列には命令ごとに 1 行があり、すべての可能なレジスタ値に対して 256 列があります。 レジスタの更新では、`% 256`8 ビット レジスタがオーバーフローすると上位ビットが破棄されるためです。 

ループは、命令を実行する前に繰り返し状態をチェックします。 実行後のチェックも機能しますが、実行前にチェックすると不変条件がより明確になります。実行ポイントに到達するすべての状態は、一度処理されるか、サイクルとして検出されます。 

Python の整数はオーバーフローしないため、カウンターやインデックスに対して特別な処理は必要ありません。

 ## 特殊なケース

 未変更レジスタの無限ループは、状態が次のとおりであるため処理されます。`(instruction, register)`すぐに繰り返します。 のために：```
2
add 0
beq 0 1
```州`(1,0)`そして`(2,0)`繰り返し訪問されます。 いつ`(1,0)`再び表示されると、アルゴリズムは出力します。`No`永遠にシミュレーションするのではなく。 

レジスタのオーバーフローは、すべての値を範囲内に保つことで処理されます。`0`に`255`。 のために：```
3
add 252
add 1
bgt 252 2
```レジスタシーケンスは最終的に次からラップされます。`255`に`0`。 アルゴリズムは実際のマシンの動作を確認し、停止命令に到達します。 

同じレジスタ値が異なる命令で現れる場合は、命令インデックスを状態の一部として保存することで処理されます。 同じレジスタ値を持つ 2 つの命令が異なるフューチャーを持つ可能性があるため、レジスタのみのビジット セットはサイクルが早すぎると誤って報告します。 ペア`(program counter, register)`は完全なマシン状態であるため、アルゴリズムは実際の実行が繰り返される場合にのみ停止します。
