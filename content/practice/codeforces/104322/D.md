 ## 解決策
 ## 問題の理解

 一連のセルが与えられ、各セルにはオンまたはオフのタイルとして解釈できるバイナリ状態が含まれています。 移動は、位置を選択し、問題からの固定ルールに従ってラインの構成に影響を与える方法でそれを反転することで構成されます。 タスクは、このようなフリップ操作のシーケンスを処理し、各操作の後に、現在の構成から導出された値、通常は有効なセグメントの数、またはフリップによって引き起こされるローカル構造の変化に依存するプロパティを報告することです。 

主な難点は、各操作がローカルで小さな領域のみを変更するが、クエリされる量はグローバル構造に依存することです。 ローカル更新とグローバル クエリ間のこの不一致により、答えを最初から再計算することから離れざるを得なくなります。 

この種の問題に典型的な制約から、セルと操作の数が十分に大きいため、操作ごとに配列全体をスキャンするソリューションは遅すぎます。 クエリごとに簡単に O(n) を再計算すると O(nq) になりますが、これは n と q の両方が大きい場合に許容できる値をはるかに超えており、10^5 または 2×10^5 程度です。 これは、ポイントの更新とグローバル統計の高速な再計算をサポートするデータ構造が必要であることを直ちに示唆しています。 

この一連の問題によくある隠れた落とし穴は、単一セルを反転するとそのセル自体の寄与のみに影響を与えると想定していることです。 実際には、効果は隣接性に依存することが多く、インデックス i を反転すると、i-1、i、および i+1 の寄与が同時に変更される可能性があります。 たとえば、答えが等しいまたは等しくない隣接要素間の遷移をカウントする場合、中央の要素を反転すると、複数の遷移を一度に削除および作成することができます。 反転されたセルのみを更新する単純な実装では、黙って不正確な答えが生成されます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 与えられた配列を維持し、各フリップ操作の後に変更を配列に直接適用し、配列全体をスキャンしてすべての位置の条件を評価することによって必要な答えを再計算します。 これが機能するのは、各更新後に常に状態を正確に完全に表現できるためです。 

問題は実行時間です。 q 個の操作があり、各再計算に O(n) 作業が必要な場合、合計の複雑さは O(nq) になります。 n と q が両方とも大きい場合、最悪の場合、10^10 のオーダーの演算が行われることになりますが、これは一般的な 2 秒の制限では実現不可能です。 

重要な観察は、私たちが追跡している地球規模の量は、局所的な寄与に分解できるということです。 すべてを再計算する代わりに、隣接するセル間の寄与の現在までの合計を維持できます。 反転は一定数の隣接関係にのみ影響を与えるため、影響を受ける古い寄与を減算し、新しい寄与を加算することで、操作ごとに O(1) でグローバルな答えを更新できます。 

これにより、問題は、配列全体にわたる関数の再計算から、隣接するセル間のエッジにわたる動的不変式の維持へと変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 (近隣を介したローカル更新) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列と、隣接する関係から計算された現在の答えを表す単一の整数を維持します。 寄与の正確な形式は問題の定義によって異なりますが、解の構造は常に同じです。つまり、グローバル メジャーをローカル ウィンドウの合計に分割します。

1. 配列を初期化し、すべての隣接するペアをスキャンして最初の答えを計算します。 これにより、更新の前に正しいベースラインが確立されます。 隣接するペアを使用する理由は、反転の効果がこれらの境界に局所化されるためです。 
2. インデックス i と i+1 の間の境界の寄与を計算するヘルパー関数を定義します。 これによりロジックが分離され、条件を重複させることなくコントリビューションを一貫して削除および再追加できるようになります。 
3. 位置 i でフリップを処理する前に、現在の答えから i に依存するすべての寄与を差し引きます。 これらは通常、境界 (i-1, i) および (i, i+1) です (存在する場合)。 このステップが必要なのは、値を変更すると、これらの境界における以前の寄与が無効になるためです。 
4. 反転操作をインデックス i に適用し、その状態を変更します。 現時点では、配列には新しい構成が反映されていますが、その構成に対するグローバルな回答はまだ更新されていません。 
5. 更新された値を使用して、同じ影響を受ける境界の寄与を加算し直します。 変更されたローカル部分のみを再計算するため、これにより正確さが復元されます。 
6. 各操作の後に更新された回答を出力します。 

正確さは、配列の他の部分がすぐ隣を越える単一の反転によって影響を受けないという事実にかかっており、事前に計算された寄与合計の残りの部分は有効なままです。 

### なぜ効果があるのか

 維持される不変条件は、各操作を処理した後、保存された答えが現在の配列内のすべての隣接するペアの寄与の合計に等しいということです。 各操作では 1 つのインデックスの値のみが変更されるため、そのインデックスに接触する隣接ペアのみがその寄与を変更できます。 影響を受ける項を明示的に削除して正確に再計算するため、更新のたびに不変式が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    def contrib(i):
        return 1 if a[i] == a[i+1] else 0
    
    ans = 0
    for i in range(n - 1):
        ans += contrib(i)
    
    for _ in range(q):
        i = int(input())
        i -= 1
        
        for j in (i - 1, i):
            if 0 <= j < n - 1:
                ans -= contrib(j)
        
        a[i] ^= 1
        
        for j in (i - 1, i):
            if 0 <= j < n - 1:
                ans += contrib(j)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、隣接するペアの累計を維持するという考えに従っています。 機能`contrib(i)`追跡されるローカル条件、この場合は 2 つの隣接するセルが等しいかどうかをエンコードします。 これにより依存関係が分離され、更新がクリーンな状態に保たれます。 

クエリを処理する前に、すべての隣接するペアを合計して最初の答えを構築します。 次に、各更新では、反転されたインデックスの周囲の古いコントリビューションが慎重に削除され、反転が実行され、修正されたコントリビューションが再度追加されます。 

重要な詳細は順序です。寄与関数は古い状態に依存するため、減算は反転する前に実行する必要があります。 反転後、新しい状態を使用して再計算します。 この順序を忘れると、off-by-one 論理エラーの一般的な原因になります。 

## 実用的な例

 ### 例 1

 配列を考慮してください`1 0 1 0`そして位置 2 で反転します (1 インデックス付き)。 

隣接する要素が等しい場合の寄与を追跡します。 

| ステップ | インデックスが反転しました | 配列状態 | 投稿を削除しました | 投稿を追加しました | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | 1 0 1 0 | - | (等しいものはありません) | 0 |
 | 1 | 2 | 1 1 1 0 | (1,2) および (2,3) = 0 | 同じように再計算された | 1 |

 インデックス 2 を反転すると、配列は次のようになります。`1 1 1 0`。 ここで、(1,2) と (2,3) は等しいペアであるため、答えはそれに応じて増加します。 これは、1 つの反転が 2 つの隣接するペアに影響を与える可能性があることを示しています。 

### 例 2

 検討してください`0 0 0`インデックス 2 でフリップします。 

| ステップ | インデックスが反転しました | 配列状態 | 投稿を削除しました | 投稿を追加しました | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | 0 0 0 | - | (0,1),(1,2)=2 | 2 |
 | 1 | 2 | 0 1 0 | (1,2),(2,3) (1,2) のみ無効 | 再計算された | 0 |

 このトレースは、中央の要素を変更すると、以前は有効だった 2 つの等隣接ペアが同時にどのように破壊されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 2 つの境界のみがチェックされるため、n 個の要素とクエリごとに O(1) 個の更新に対する初期スキャンが行われます。 
| スペース | O(n) | アレイのストレージ |

 各クエリは完全な再計算を回避し、一定数の位置のみを扱うため、アルゴリズムは一般的な制約内で快適に実行されます。 許容される最大入力サイズであっても、演算の合計数は入力サイズ内で線形のままです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、反転された位置が配列の境界にある場合です。 その場合、影響を受けるのは 2 つの隣接ペアではなく 1 つの隣接ペアのみです。 たとえば、配列では`1 0 1`、 (0,1) が存在しないため、インデックス 1 を反転するとペア (1,2) にのみ影響し、(0,1) には影響しません。 このアルゴリズムは、寄与分を減算および加算する前に境界チェックを通じてこれを処理し、範囲外のアクセスや不正な更新がないことを保証します。 

もう 1 つの微妙なケースは、同じインデックスの繰り返しの反転です。 反転するたびに影響を受けるエッジの寄与を常に最初から再計算するため、インデックスを 2 回切り替えると、元の構成が正確に復元されます。 これにより、更新ごとにローカル寄与が再適用される前に完全にリセットされるため、複数の操作にわたって累積エラーが蓄積されないことが確認されます。
