 ## 解決策
 ## 問題の理解

 小文字で構成される 1 つの文字列が与えられ、そのセグメントの長さの半分以上に現れる単一の文字が存在しないように、この文字列の連続するセグメントを見つけるように求められます。 そのようなセグメントが存在する場合、それらのいずれかを出力してもよい。 存在しない場合は、不可能であることを報告する必要があります。 

キー オブジェクトは完全な文字列ではなく、その部分文字列です。 各部分文字列について、頻度条件をチェックしています: 部分文字列の長さがあるかどうか$L$、その場合、すべての文字は最大でも出現する必要があります$L/2$回。 これは、部分文字列の大部分が 1 つの繰り返し文字で構成されることはできないと言っているのと同じです。 

制約$n \le 1000$ということを意味します$O(n^3)$頻度カウントによる部分文字列に対するブルート フォースは限界に達しますが、最適化された Python では依然として通過する可能性があります。$O(n^2)$ソリューションは快適に安全です。 これは、複雑なグローバル構造ではなく、小さな構造化された部分文字列について推論しようとする必要があることを強く示唆しています。 

微妙な点は、答えが長くなったり、最大限に長くなったりする必要はないということです。 これにより、長さを最適化する必要がなくなります。 有効な部分文字列であればどれでも十分であり、多くの場合、検索の代わりに構築引数が許可されます。 

文字列が一様である場合、エッジケースが発生します。 たとえば、次の場合$s = "aaaa"$、すべての部分文字列も均一であるため、多数決条件は常に違反されます。 このような場合、正しい出力は「NO」です。 完全な文字列の多様性のみをチェックする素朴なアプローチは、完全な文字列が失敗しても、より短い部分文字列はまだ機能する可能性があるため、ここでは失敗しますが、この特定のケースではどれも機能しません。 

もう 1 つの重要なエッジ ケースは、文字列に文字が混在しているにもかかわらず、依然としてローカルで優勢な場合です。 たとえば、「aaab」には有効な答え「ab」または「ba」がありますが、「aaa」単独には有効な部分文字列がまったくありません。 これは、私たちが世界的な多様性ではなく、地域的なバランスを求めていることを強調しています。 

## アプローチ

 ブルートフォース戦略は、すべての部分文字列を列挙し、文字の頻度を数えることによってそれぞれをチェックすることです。 各部分文字列について$s[l:r]$、26 個のカウントを計算し、長さの半分を超えるカウントがあるかどうかを検証します。 これは定義と直接一致するため、正しいです。 

問題は複雑さです。 がある$O(n^2)$部分文字列と各チェックのコスト$O(n)$カウントを最初から再計算すると、$O(n^3)$。 プレフィックス合計によってチェックが減少しても、$O(1)$キャラクターごとに、まだあります$O(26n^2)$、これは境界線ですが許容範囲です$n=1000$。 ただし、問題の構造によりはるかに簡単に観察できるため、これは不要です。 

重要な洞察は、有効な部分文字列が存在する場合、長さ 2 までの文字列を常に見つけることができるということです。隣接する 2 つの異なる文字を取得した場合、各文字が 1 回だけ出現し、かつ長さ 2 の部分文字列はすでに条件を満たしています。$1 \le 2/2$文字が複数回出現する場合にのみ false になります。 したがって、異なる隣接する文字の任意のペアは有効です。 

これにより、問題全体がインデックスのスキャンに軽減されます。$i$そのような$s[i] \ne s[i+1]$。 そのようなペアが存在する場合は、それを出力します。 そのようなペアが存在しない場合、文字列は均一であり、有効な部分文字列はまったく存在しません。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$または$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右にスキャンして、隣接する文字のペアをそれぞれ調べます。 
2. 位置で$i$、 比較する$s[i]$そして$s[i+1]$。 
3. 異なる場合は、すぐに部分文字列を出力します。$s[i:i+2]$そして終了します。 
4. 異なる隣接ペアが見つからずにスキャンが完了した場合は、すべての文字が同一であると結論付けます。 
5. その場合は「NO」を出力します。 

ステップ 3 で十分な理由は、任意の 2 つの異なる文字が部分文字列を形成し、どの文字も複数回出現できないため、多様性条件が自動的に満たされるためです。 

### なぜ効果があるのか

 不変条件は、有効な部分文字列が文字列内のどこかに存在する場合、隣接する不一致があるか、文字列が完全に均一であるかのいずれかであるということです。 一様な文字列では、すべての部分文字列に同じ文字が繰り返されているため、どの部分文字列も条件を満たすことはできません。 不均一な文字列では、少なくとも 1 つの隣接するペアが異なっている必要があり、そのペア自体が有効な解を形成します。 したがって、隣接するペアをスキャンすることは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

for i in range(n - 1):
    if s[i] != s[i + 1]:
        print("YES")
        print(s[i:i+2])
        sys.exit(0)

print("NO")
```この解決策は、異なる文字間の最初の遷移を検出することに完全に依存しています。 早期終了により、有効な答えが見つかった後に不必要にスキャンすることがなくなります。 スライス`s[i:i+2]`Python は境界をきれいに処理し、次までしか反復しないので安全です。`n-2`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

最悪の場合、隣接する不一致が存在するかどうかを判断するためにすべての文字を少なくとも 1 回検査する必要があるため、リニア スキャンが最適です。 と$n \le 1000$、これは些細な速さです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys

    out = io.StringIO()
    with redirect_stdout(out):
        n = int(input().strip())
        s = input().strip()
        for i in range(n - 1):
            if s[i] != s[i + 1]:

                print(s[i:i+2])

 ## 特殊なケース

 次のような単一文字の文字列`"z"`部分文字列の長さは 1 であり、唯一の文字が半分以上出現するため、これは自動的に無効になります。 検査する隣接ペアがないため、アルゴリズムは正しく「NO」を出力します。 

次のような完全に均一な文字列`"kkkkk"`同様に動作します。 スキャンでは不一致は検出されず、出力は正しく「NO」になります。 すべての部分文字列は同じ不均衡を継承します。 

のような混合文字列`"ba"`は、最小の長さでポジティブなケースを示しています。 最初の比較ですでに不一致が生じており、部分文字列`"ba"`両方の文字が 1 回出現し、どちらも 2 の半分を超えないため、すぐに有効になります。
