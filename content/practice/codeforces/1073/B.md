 ## 解決策
 ## 問題の理解

 私たちには、それぞれの本に固有のラベルが付いている本の束が与えられます。 スタック順序は重要です。最初の配列はどの本が一番上にあるかを示し、最後の要素は一番下にあります。 また、Vasya が特定の本を手に取ろうとする固定順序を説明する 2 番目のシーケンスも受け取ります。 

各ステップで、Vasya は現在のスタック内で要求された本を探します。 それがまだ存在する場合、彼はその本をスタック内のその上にあるすべてのものとともに削除し、削除されたすべての本はバックパックに移動されたとみなされます。 リクエストされた書籍がすでに削除されている場合、そのステップでは何も起こりません。 

タスクは、各ステップで、その操作中に削除される本の数を計算することです。 

制約は最大 200,000 冊までです。 これにより、クエリごとに単純にスタック操作を繰り返しスキャンまたはシミュレートするソリューションは即座に除外されます。 現在のスタック内でリクエストされた各書籍を検索し、要素を物理的に削除する単純なシミュレーションでは、制限時間に対して遅すぎる二次関数の動作に低下する可能性があります。 

複数のクエリがすでに削除された書籍を参照している場合、微妙な問題が発生します。 このような場合、答えはゼロであり、適切な「すでに削除された」構造を維持しない単純な実装では、誤って古い位置を処理しようとしたり、削除されたセグメントを二重にカウントしようとしたりする可能性があります。 

不注意なシミュレーションによる具体的な失敗例は、毎回リストを再構築または縮小する場合です。 たとえば、スタックが`[1, 2, 3, 4]`そしてクエリは`[4, 3, 2, 1]`、削除後にインデックスが更新されていない場合、スキャンとスライスを繰り返し行うと、誤って位置が誤って再計算される可能性があります。 正しい出力は次のとおりです`4 0 0 0`最初の操作ではスタック全体が削除され、その後のすべてのリクエストでは何も行われないためです。 

## アプローチ

 直接シミュレーションでは、現在のスタックがリストとして保持されます。 クエリごとに、要求された書籍を検索し、その位置を見つけて、その位置までのすべてを削除します。 これは問題の定義と正確に一致するため、正しいです。 ただし、各書籍の検索には直線的な時間がかかり、プレフィックスの削除にも直線的な時間がかかります。 すべてのクエリにわたって、毎回ごく一部のみが削除される場合、最悪の場合、二次的な複雑さが生じます。 

重要な観察は、スタックは上から下にのみ縮小し、各本は 1 回だけ削除できることです。 繰り返し検索する代わりに、初期スタック内のすべての本の位置を事前に計算できます。 次に、スタックのどのくらい下まですでに処理したかを示すポインタを維持します。 クエリで書籍が要求された場合、その位置がまだ現在のポインタより上にある場合にのみ、書籍が削除されます。 新しい最低到達位置を削除するたびに、ポインタを進めます。 各本は実質的に 1 回触れられます。 

これにより、繰り返しのスキャンが、削除イベントの昇順でスタック位置を通過する 1 回のパスに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos`どこ`pos[x]`本の索引を付けます`x`初期スタック内。 これにより、各クエリが検索ではなく直接位置検索に変換されます。 
2. 変数を維持する`ptr`すでに削除されたスタック内の最上位のインデックスを表します。 初期状態では本は削除されないため、`ptr = 0`。 
3. リクエストされた書籍ごとに`b_i`、位置を確認してください`p = pos[b_i]`。 
4. もし`p <= ptr`、本は前の操作の一部としてすでに削除されているため、出力`0`。 
5. もし`p > ptr`、それからこの本はまだ存在します。 この操作により、すべての書籍がインデックスから削除されます`ptr + 1`まで`p`。 削除された本の数は、`p - ptr`。 
6.アップデート`ptr`に`p`、上記のすべてとそれを含むため、`p`今後の検討対象から外されました。 
7. すべてのクエリに対して繰り返します。 

正しさは次の事実から生まれます`ptr`すでに消費されているスタックの最も深いプレフィックスを常に追跡します。 削除するたびにこのプレフィックスは単調に拡張され、削除されたセグメントが再検討されることはありません。 

## なぜ機能するのか

 いつでも、残りのスタックは正確に次から始まるサフィックスになります。`ptr + 1`。 各クエリは、この接尾辞の内側または外側の書籍を参照します。 外側にある場合は、以前の削除にすでに含まれているため、答えはゼロでなければなりません。 それが内部にある場合、削除はその本までの残りの接尾辞の接頭辞を正確に取得します。これは、未使用の本の連続したセグメントです。 なぜなら`ptr`前方にのみ進むため、各インデックスは最大 1 回処理され、直線的な合計作業量が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, x in enumerate(a):
        pos[x] = i + 1

    ptr = 0
    res = []

    for x in b:
        p = pos[x]
        if p <= ptr:
            res.append("0")
        else:
            res.append(str(p - ptr))
            ptr = p

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```の`pos`配列は 1 から始まるインデックスを使用して構築されるため、スタック位置は削除長に合わせて自然に整列します。 これにより、計算時に 1 ずつずれる調整が回避されます。`p - ptr`。 

の`ptr`変数は、ソリューションの中心的な状態です。 ゼロ以外のクエリに答えるたびに、新しく削除された本の位置までクエリを正確に拡張します。 これにより、セグメントを二重にカウントしないことが保証されます。 

ループ内で印刷を繰り返すと実行速度が低下するため、出力は効率化のために文字列として蓄積されます。 

## 実用的な例

 ### 例 1

 入力スタックは`[1, 2, 3]`、クエリは`[2, 1, 3]`。 

| ステップ | 本 | ポジション | 前 | のptr アクション | 削除されました |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 0 | 2 へのプレフィックスを削除 | 2 |
 | 2 | 1 | 1 | 2 | すでに削除されました | 0 |
 | 3 | 3 | 3 | 2 | プレフィックスを 3 から削除します | 1 |

 出力は`2 0 1`。 

これは、一度`ptr`ある位置を超えて移動すると、その本は操作をトリガーできなくなります。 

### 例 2

 スタック`[3, 1, 4, 2, 5]`、クエリ`[4, 2, 5, 1, 3]`。 

| ステップ | 本 | ポジション | 前 | のptr アクション | 削除されました |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | 3 | 0 | 3 に削除 | 3 |
 | 2 | 2 | 4 | 3 | 4 に拡張 | 1 |
 | 3 | 5 | 5 | 4 | 5 まで拡張 | 1 |
 | 4 | 1 | 2 | 5 | すでに削除されました | 0 |
 | 5 | 3 | 1 | 5 | すでに削除されました | 0 |

 これはその方法を示しています`ptr`単調に増加し、最終的にはスタック全体をカバーします。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, x in enumerate(a):
        pos[x] = i + 1

    ptr = 0
    ans = []
    for x in b:
        p = pos[x]
        if p <= ptr:
            ans.append("0")
        else:
            ans.append(str(p - ptr))
            ptr = p
    return " ".join(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run("""3

""") == "2 0 1"

# minimum size
assert run("""1
1
1
""") == "1"

""") == "5 0 0 0 0"

""") == "3 1 1 0 0"

 ## 特殊なケース

 主なエッジ ケースは、前のステップですでに削除された書籍をクエリが参照している場合です。 この状況では、ゼロを出力し、状態を変更しないのが正しい動作です。 アルゴリズムは、保存された位置が以下であるかどうかをチェックすることでこれを処理します。`ptr`。 

たとえば、スタックの場合`[1, 2, 3, 4]`そしてクエリ`[3, 4, 2, 1]`、加工後`3`、ポインタは次のようになります`3`。 加工時`4`にまで及びます`4`。 その時点では両方とも`2`そして`1`以下またはそれと等しい`ptr`したがって、さらに変更を加えなくても、正しくゼロが生成されます。
