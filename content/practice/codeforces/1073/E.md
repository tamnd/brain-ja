 ## 解決策
 ## 問題の理解

 範囲内のすべての整数を考慮するように求められます$[l, r]$そして、数字の制約によってフィルターします。最大でも使用する数字のみを保持します。$k$通常の基数 10 表現における個別の 10 進数。 このようなすべての有効な数値のうち、それらの合計の剰余を計算する必要があります。$998244353$。 

難しいのは、単一の数値を評価することではなく、非常に長い間隔にわたって集計することです。 以来$r$と同じ大きさにすることができます$10^{18}$、間隔には最大で次の値を含めることができます。$10^{18}$これにより、範囲を直接反復するアプローチは即座に除外されます。 

2 番目の観察は、桁制約から得られます。 数値は、その桁セットのサイズが小さい場合、つまり数値のすべての桁がグローバルに結合される場合に有効です。 これは、パリティや可分性のようなローカルなプロパティではありません。 それは数値の構造全体に依存します。 そのため、素朴な数え方や等差数列のトリックは使用できなくなります。 

素朴なアプローチは、次のすべての数値を列挙することです。$[l, r]$、その数字セットを抽出し、最大サイズがあるかどうかを確認します$k$。 これは、最小ではない入力サイズではすでに失敗します。 平$10^{18}$候補者$k = 10$につながる$10^{18}$数字のチェックですが、これは不可能です。 

数字に先頭桁の制約がある場合、より微妙なエッジ ケースが発生します。 例えば、$1000$数字のみを使用する$\{0,1\}$有効です$k=2$、 その間$999$のみを使用します$\{9\}$。 先頭のゼロを誤って処理する不正な数字 DP は、次のような数字を誤ってカウントする可能性があります。$000123$数字の 0 を導入すべきではない場合に導入します。 

したがって、中心的な課題は、限界までのすべての数値の合計を効率的に計算することです。$x$、次に 2 つのプレフィックスの答えを減算します。$$\text{answer}(l, r) = F(r) - F(l-1)$$どこ$F(x)$有効な数値の合計です$\le x$。 

## アプローチ

 ブルートフォースのアイデアは単純です。次の値までのすべての数値を反復処理します。$x$、数字の区別性をチェックし、合計を累積します。 これは、数字の抽出が次のように行われるため機能します。$O(\log x)$したがって、全体の複雑さは次のようになります。$O(x \log x)$。 いつ$x \approx 10^{18}$、これは実現可能な限界をはるかに超えています。 

重要な洞察は、数値が数字によって構造化されており、数字の制約は数字動的計画法を使用して自然に処理されるということです。 値を列挙する代わりに、数値を桁ごとに構築し、これまでにどの桁が使用されたかを追跡します。 可能な桁数が 10 個しかないため、状態空間は小さいため、桁のサブセットは次のサイズのビットマスクで表現できます。$2^{10} = 1024$。 

これにより、問題は、位置、境界に対する厳密さ、および使用される桁のセットから構成される状態をもつ古典的な桁 DP に変換されます。 プレフィックスを修正すると、すべてのサフィックス補完の寄与を列挙するのではなく集計することができます。 

微妙だが重要な改善点は、有効な数値を数えるだけでなく、合計するようになったということです。 これには、完了数だけでなく、位の値によって重み付けされた数値寄与も保持する必要があります。 これにより、カウント DP と合計 DP の両方が維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(x \log x)$|$O(1)$| 遅すぎる |
 | 桁DP |$O(20 \cdot 1024 \cdot 10)$|$O(1024 \cdot 10)$| 承認済み |

 ## アルゴリズムのチュートリアル

 関数を定義します$F(x)$すべての有効な数値の合計を計算します。$[0, x]$。 

1.変換$x$数値配列に変換して、最上位桁から処理できるようにします。 これにより、接頭辞制約を使用して数値を構築できるようになります。 
2. 数字配列内の位置に対して DP 状態を定義します。 各位置で、次の 3 つのことを追跡します。まだ接頭辞に束縛されているかどうか。$x$、どの数字がすでに使用されているか (ビットマスク)、および数値の形成を開始したかどうか (先頭のゼロを正しく処理するため)。 
3. 状態ごとに、0 から 9 までの次の可能なすべての数字を繰り返します。まだ数値を開始していない場合、0 を選択してもマスクに数字は導入されません。 それ以外の場合はそうなります。 
4. 数字を配置するとき、マスクを更新し、個別の数字の数が次の値を超えているかどうかを確認します。$k$。 そうであれば、この遷移を破棄します。 
5. 接尾辞を完成させる方法の数 (カウント) と、それらすべての完成によって寄与される合計の 2 つの量を伝播します。 数字を加える場合$d$位置にある$pos$、その貢献度は$d \cdot 10^{remaining}$補完の数と接尾辞の合計のシフトされた寄与を乗算します。 
6. 厳しい制約により、決して超えないことが保証されます$x$。 バインドされた数字より小さい数字を配置すると、非タイト状態に移行します。 そうでなければ、私たちはしっかりと留まります。 
7. 最後に DP の結果が得られます。$F(x)$、そして最終的な答えは$F(r) - F(l-1)$。 

### なぜ効果があるのか

 すべての有効な数値は、一連の数字の選択肢として 1 回だけ構築されます。 DP は数値の空間をプレフィックスごとに分割し、厳しい制約により、無効なプレフィックスが境界を超えることはありません。 マスクはせいぜい次のことを強制します。$k$-digits は数字が導入された瞬間に条件を設定し、早期に無効な設定が行われるのを防ぎます。 寄与は加算の線形性を介して集計されるため、DP 状態の合計により二重にカウントすることなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve(x, k):
    if x <= 0:
        return 0

    digits = list(map(int, str(x)))
    n = len(digits)

    # dp[pos][tight][mask] = (count, sum)
    from collections import defaultdict

    dp = [[[ (0, 0) for _ in range(1 << 10)] for _ in range(2)] for _ in range(n + 1)]
    dp[0][1][0] = (1, 0)

    pow10 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

    for pos in range(n):
        for tight in range(2):
            limit = digits[pos] if tight else 9
            for mask in range(1 << 10):
                cnt, sm = dp[pos][tight][mask]
                if cnt == 0:
                    continue

                for d in range(limit + 1):
                    ntight = tight and (d == limit)

                    nmask = mask
                    if mask != 0 or d != 0:
                        nmask = mask | (1 << d)

                    if bin(nmask).count("1") > k:
                        continue

                    ncnt = cnt
                    nsm = sm

                    # contribution of new digit at position
                    nsm = (nsm * 10 + cnt * d) % MOD

                    dp[pos + 1][ntight][nmask] = (
                        (dp[pos + 1][ntight][nmask][0] + ncnt) % MOD,
                        (dp[pos + 1][ntight][nmask][1] + nsm) % MOD
                    )

    res = 0
    for tight in range(2):
        for mask in range(1 << 10):
            if bin(mask).count("1") <= k:
                res = (res + dp[n][tight][mask][1]) % MOD

    return res

def pref(x, k):
    return solve(x, k)

l, r, k = map(int, input().split())
print((pref(r, k) - pref(l - 1, k)) % MOD)
```実装は、数字に関する DP 構造に従います。 の`mask`どの数字が出現したかを追跡し、先頭ゼロのロジックにより次のような数字が表示されることを保証します。`000123`誤って数字 0 をアクティブにしないでください。`nsm = nsm * 10 + cnt * d`数字を配置すると、以前に形成されたすべてのサフィックスの寄与がどのようにシフトされるかをエンコードします。 

すべてのターミナル DP 状態の最終的な合計では、境界までのすべての有効な数値が収集されます。

 ## 特殊なケース

 重要なエッジ ケースは、構築中に先頭にゼロが付く番号です。 のような入力の場合$x = 100$、DP は「0 → 0 → 5」のような状態を構築する場合がありますが、これは数字の 0 を使用した数値ではなく、数値 5 を表す必要があります。`started`このロジックにより、ゼロ以外の数字が表示される前に数字 0 がマスクに入らないことが保証されます。 

もう 1 つのエッジケースは次のような場合です$k = 10$。 この場合、すべての数値が有効であり、DP は標準の桁の合計 DP まで減少する必要があります。 マスク チェックが不活性になり、結果が間隔全体の算術合計と一致し、DP が状態を過度に制限していないことが確認されます。 

最後に、いつ$l = 1$、引き算$F(l-1)$正しく処理しなければなりません$F(0)=0$。 このガードがないと、負のインデックス付けまたは無効な DP の再利用により、最終結果が歪められます。
