 ## 問題の理解

 並んでいます`n`それぞれのメガネに 1 から 1 までの一意のインデックスが付いています。`n`。 ビー玉はガラスの下の位置から始まります`s`。 Petya は、シャッフル中にメガネがどのように同時に移動されるかを決定する位置の順列を定義します。 ガラスの場合`i`現在その位置にいます`i`、シャッフル後、位置に移動します`p[i]`。 Vasya は所定の位置で大理石を観察します`t`いくつかのシャッフルの後。 タスクは、ビー玉が到達するまでに必要なシャッフルの最小回数を決定することです。`t`、またはレポート`-1`それが不可能な場合。 

重要な観察は、各シャッフルがすべての位置に固定の順列を適用することと、ビー玉がガラスと一緒に動くことです。 したがって、大理石の軌道は、次から始まる順列を繰り返し適用することによって決定されます。`s`。 

制約は次のことを示します`n`最大 10^5 までの大きさになる可能性があります。 各シャッフルでは、順列に従ってすべてのグラスを移動する必要があります。 考えられるすべてのシャッフル シーケンスをシミュレートする単純なソリューションでは、操作の数が指数関数的に複雑になるため、実行不可能です。 大理石の軌道に沿って単独で歩くソリューションは、サイクルが繰り返される前に各ガラスに最大 1 回アクセスでき、線形 O(n) アルゴリズムが得られるため、実現可能です。 

明らかではないエッジケースとしては、次のような場合があります。`s`等しい`t`。 その状況では、たとえ順列が自明ではない場合でも、ゼロシャッフルが必要になる場合があります。 もう 1 つの微妙なケースは、次のサイクルを含む順列です。`t`。 たとえば、次の場合`s`決して到達しないサイクルにある`t`、答えは次のようになります。`-1`。 不用意に実装すると、サイクルが検出されずに無限ループする可能性があります。 

## アプローチ

 強引なアプローチでは、ビー玉の動きを段階的にシミュレートします。 から開始`s`、順列を繰り返し適用し、ビー玉が到達するまでのステップ数を数えます。`t`。 これは正しいです。シャッフルするたびにビー玉が独自の軌道に沿って決定的に移動するからです。 ただし、最悪の場合、シャッフルの回数は O(n) になる可能性があり、訪問した位置を追跡しないと、サイクルに入り、無限にループする可能性があります。 操作回数は最大です`n`順列は全単射であるため。 ポジションが繰り返されると、その後の動きは循環するだけです。 

最適なアプローチを可能にする重要な観察は、大理石が単一サイクルの順列に沿って移動するということです。 行全体をシミュレートする必要はありません。 ビー玉の現在位置を追跡し、カウンターをインクリメントし、ビー玉が到達した時点で停止します。`t`または、繰り返される位置を検出します。 これにより、ガラスの数の線形解が保証され、制約を考慮すると十分です。

 | 軌道追跡 (大理石のみ) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`pos`に`s`ビー玉とカウンターの現在位置を表す`steps`これにより、シミュレーションの開始点が設定されます。 
2. もし`pos`等しい`t`、すぐに戻ります`steps`これは、シャッフルが必要ない簡単なケースを処理します。 
3. それ以外の場合は、次のいずれかになるまで継続するループを開始します。`pos`等しい`t`またはサイクルを検出します。 各反復で:

 ａ． セット`pos`に`p[pos]`、順列に沿ってビー玉を移動します。 

b. インクリメント`steps`1までに。 

c. もし`pos`等しい`t`、 戻る`steps`。 

d. もし`pos`等しい`s`繰り返しますが、これは含まれないサイクルを示します。`t`; 戻る`-1`。 
4. ループの終了。 戻らずに出たら戻る`-1`不可能であることを示すこと。 

なぜ機能するのか: 不変条件は次のとおりです。`pos`は常に大理石の現在の位置を表します。 順列は全単射であるため、ビー玉は一定の周期で移動します。 サイクルに含まれるいずれか`t`、その場合は最長で 30 日以内に到着します。`n`ステップを実行するか、ステップを実行しない場合は、もう一度検討します。`s`不可能を知らせます。 サイクル内のポジションをスキップしたり、到達したりする方法はありません`t`別の道で。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, s, t = map(int, input().split())
p = [0] + list(map(int, input().split()))  # 1-indexed

if s == t:
    print(0)
    sys.exit()

pos = s
steps = 0
visited = set()

while pos not in visited:
    visited.add(pos)
    pos = p[pos]
    steps += 1
    if pos == t:
        print(steps)
        break
else:
    print(-1)
```このコードでは、1 から始まるインデックスを使用して、問題のステートメントと一致します。 些細な事件でも対応いたします`s == t`すぐに。 あ`visited`トラックの位置を設定してサイクルを検出し、無限ループを防ぎます。 各ステップでビー玉の位置を更新し、ビー玉が到達したかどうかを確認します。`t`。 到達せずにポジションを再訪した場合`t`、目標は達成不可能であると結論付けます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()

 ## 特殊なケース

 いつ`s == t`の場合、アルゴリズムはすぐに 0 を返します。 たとえば、入力`5 3 3`ループに入らずに 0 を返します。 

順列が次の要素を含まないサイクルを形成する場合`t`、訪問されたセットはそれを検出します`pos`以前の位置を再訪し、アルゴリズムは正しく戻ります`-1`。 入力用`3 1 3`と`p = [2,1,3]`、ビー玉は 1→2→1 と移動しますが、3 には到達せず、else 分岐がトリガーされます。 

このアルゴリズムは、ビー玉の軌道に沿った線形移動により最大入力サイズを正しく処理し、無関係なガラスのシミュレーションを回避します。
