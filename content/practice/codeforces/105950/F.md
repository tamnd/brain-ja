 ## 解決策
 ## 問題の理解

 岩石の種類の 2 つの並列シーケンスが与えられ、各シーケンスは同じラベルのセットの順列です。 プレーヤーは、両方のシーケンスを左側からのみ、および右側からのみトリミングできます。 フロドは各シーケンスからプレフィックスを削除し、サムは各シーケンスからサフィックスを削除します。 これらの除去後、残りの両方の中間セグメントはまったく同一になる必要があります。これは、それらが同じ順序で同じ一連の岩石タイプを表すことを意味します。 

手術の費用は破壊された岩石の数によって決まります。 フロドは左側から除去された岩ごとに支払い、サムは右側から除去された岩ごとに支払います。単位あたりのコストは F と S が異なります。目標は、総破壊コストを最小限に抑えながら、結果として得られる中央のセグメントが一致し、少なくとも 1 つの岩が残るように切断する場所を選択することです。 

それぞれの有効な解決策は、長さが同じで内容が同じである P の連続セグメントと Q の連続セグメントを選択することに対応します。 このようなセグメントのペアが選択されると、それらのセグメントの外側にあるものはすべて削除されます。 最適化の問題は、削除コストを最小限に抑える最も一致するセグメントのペアを選択することになります。 

制約では最大 100,000 個の要素が許可されるため、すべてのサブセグメントにわたる二次比較は不可能です。 O(N^2) 個の部分文字列一致でも制限をはるかに超えています。 これは、LCP 推論と組み合わせたサフィックス配列やローリング ハッシュなど、線形または線形に近い文字列処理をサポートする構造に問題を帰着させる必要があることを直ちに示唆しています。 

正確性について考えると、微妙な問題が生じます。たとえ長い共通セグメントが見つかったとしても、その長さを最大化するだけでは十分ではありません。 コストは、そのセグメントが両方の順列のどこに発生するかによっても異なります。 フロドにとっては初期のセグメントの方が安く、後半のセグメントはサムにとっては安価であるため、同じセグメント長が 2 回発生すると、異なるコストが発生する可能性があります。 

オーバーラップの長さを最大化するだけの単純なアプローチは、わずかに短いセグメントがはるかに安い位置に表示される場合に失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、P と Q の開始位置のすべてのペアを試し、文字が一致する間に拡張し、一致ごとにコストを計算します。 これにより、すべての共通サブ配列が正しく検出されますが、各比較には直線的な時間がかかる可能性があり、最悪の場合は O(N³) となり、100000 までの N では使用できなくなります。 

より構造化された見方は、問題は基本的に 2 つのシーケンス間の最良の共通部分文字列を見つけることであり、「最良」とは位置に依存するコスト関数の下で最長であるだけでなく、最も安価であることを認識することです。 

重要な観察は、すべての有効な解が P と Q の共通の部分文字列に対応し、すべての共通の部分文字列が P の一部の接尾辞と Q の接尾辞の接頭辞として現れるということです。したがって、部分文字列を直接列挙する代わりに、接尾辞を使用できます。 

P と Q をセパレータで連結してサフィックス配列を構築することにより、隣接するサフィックス間の最長の共通プレフィックスを計算できます。 共通の部分文字列は、いずれかの隣接するペアの LCP として出現する必要があります。ここで、1 つの接尾辞は P からのもので、もう 1 つは Q からのものです。これにより、すべての部分文字列ペアからの検索スペースが O(N) 個の候補ペアに減少します。 

このようなペアごとに、2 つのサフィックスの正確な位置とその LCP 長を使用して最適なコストを計算します。 その候補部分文字列のコスト式を評価し、最小値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3) | お(1) | 遅すぎる |
 | サフィックス配列 + LCP | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. P と Q を単一の配列に連結し、どちらの順列にも現れない一意の区切り文字で区切ります。 これにより、異なる側からのサフィックスが確実に区別できるようになります。 
2. LCP 配列とともに、結合されたシーケンスのサフィックス配列を構築します。 これにより、並べ替えられた順序で任意の 2 つの隣接するサフィックス間の最長の共通プレフィックスを計算できます。 
3. サフィックス配列内の隣接するペアを反復処理します。 一方の接尾辞が P に由来し、もう一方の接尾辞が Q に由来する場合、共通部分文字列の候補が特定されます。 
4. i を P の開始位置、j を Q の開始位置とする。L をこれらのサフィックス間の LCP 値とする。 これは、P[i..i+L-1] が Q[j..j+L-1] と一致することを意味します。 
5. 候補ごとに、選択したセグメントの外側をすべて削除する場合の総コストを計算します。 コストは、両方の配列の左側と右側から削除される要素の数によって異なります。 これは、i、j、L に基づく直接算術式になります。 
6. 最終セグメントを空にすることはできないため、L を少なくとも 1 として、すべての有効な候補にわたる最小コストを追跡します。 

### なぜ効果があるのか

 すべての有効な最終構成は、P と Q の共通の部分文字列に対応します。そのようなすべての部分文字列は、ある接尾辞ペアの接頭辞として表示され、接尾辞配列は、辞書編集順で少なくとも 1 つの隣接するペアが、その接尾辞のペアに対して可能な最大の共有接頭辞を取得することを保証します。 すべての隣接する配列間ペアを評価するため、すべての最大の共通部分文字列が考慮され、より短い部分文字列はサフィックス構造での出現によって暗黙的にカバーされます。 コスト関数は選択された部分文字列の端点のみに依存するため、各候補を個別に評価することで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = s[:]
    tmp = [0] * n

    def key(i):
        return (rank[i], rank[i + k] if i + k < n else -1)

    while True:
        sa.sort(key=key)
        tmp[sa[0]] = 0
        for i in range(1, n):
            tmp[sa[i]] = tmp[sa[i - 1]] + (key(sa[i - 1]) < key(sa[i]))
        rank = tmp[:]
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa, rank

def build_lcp(s, sa, rank):
    n = len(s)
    h = 0
    lcp = [0] * n
    for i in range(n):
        r = rank[i]
        if r == 0:
            continue
        j = sa[r - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[r] = h
        if h:
            h -= 1
    return lcp

def solve():
    n, f, s = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    sep = 0
    arr = p + [sep] + q
    n1 = len(p)

    sa, rank = build_suffix_array(arr)
    lcp = build_lcp(arr, sa, rank)

    INF = 10**30
    ans = INF

    total_const = 2 * n * s - 2 * f

    for i in range(1, len(sa)):
        a, b = sa[i - 1], sa[i]
        if (a < n1) == (b < n1):
            continue

        L = lcp[i]
        if L <= 0:
            continue

        if a < n1:
            ip = a
            iq = b - (n1 + 1)
        else:
            ip = b
            iq = a - (n1 + 1)

        L = min(L, n - ip, n - iq)
        if L <= 0:
            continue

        val = (f - s) * (ip + iq) - 2 * s * (L - 1)
        ans = min(ans, val)

    print(ans + total_const)

if __name__ == "__main__":
    solve()
```サフィックス配列は、反復ランキング 2 倍化を使用して構築されます。これは、実際には 200,000 個の要素には十分です。 LCP 配列は、標準的な Kasai メソッドを使用して計算されます。 

隣接する各サフィックス ペアは、一方が P から来て、もう一方が Q から来ている場合にのみチェックされます。それらの LCP は、それらの位置から始まる最大共有セグメントを与え、コスト式を直接評価します。 最終的な答えの一定のシフトは、選択されたセグメントの外側の完全な削除を説明します。 

よくある微妙な点は、連結された配列と元の Q 位置の間のインデックス変換であり、セパレータとプレフィックスの長さを正しく減算する必要があります。 

## 実用的な例

 P と Q がすでに完全に一致している単純なケースを考えてみましょう。 サフィックス配列は同一のサフィックスを隣接して配置し、N に等しい大きな LCP を生成します。アルゴリズムはセグメント全体を選択するため、セグメント内の削除はゼロとなり、境界の削除のみが最適になります。 

一致するセグメントが異なるオフセットに現れる 2 番目のケースでも、サフィックス配列は対応するサフィックスをペアにします。 LCP はオーバーラップ長を正確に取得し、コスト比較により、わずかに短いが先に発生したセグメントが、より長くても高価な位置のセグメントに勝つことができることを確認します。 

| ステップ | SAペア | LCP | 私(P) | j(Q) | セグメントの長さ | コスト貢献 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | クロスペア | Ｌ | 私 | j | Ｌ | 計算値 |
 | 2 | 次のペア | L' | 私は | j' | L' | 計算値 |

 各行は、1 つの候補部分文字列の評価に対応します。 すべての行の最小値が最終的な答えになります。

 ## 特殊なケース

 エッジ ケースの 1 つは、最も一致する部分文字列が非常に短いにもかかわらず、非常に有利な位置に出現する場合に発生します。 素朴な最長共通部分文字列アプローチでは、それを見逃してしまいます。 これは、隣接する接尾辞ペアの LCP として現れるため、接尾辞配列ベースの評価でも考慮されます。 

もう 1 つのエッジ ケースは、P と Q が同じ長さで異なる位置にある複数の同一の部分文字列を共有する場合です。 コストは長さだけではなく i と j に依存するため、アルゴリズムはそれらを正しく区別します。 

最後のエッジ ケースは、唯一の一致が長さ 1 を持つ場合です。この最小限のオーバーラップ シナリオでも、LCP ≥ 1 を持つすべての配列間サフィックス ペアが考慮されるため、アルゴリズムは依然として正しく評価します。
