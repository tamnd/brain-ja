 ## 解決策
 ## 問題の理解

 単一の小文字文字列が与えられ、実行できる操作は 2 つの位置を選択し、それらの位置で文字を交換するという 1 つまでです。 このオプションの交換の後、文字列は概念ライブラリに戻され、すべての有限の小文字文字列が辞書順に並べられます。目標は、文字列がその順序でできるだけ早く表示されるようにすることです。 

実際には、これは純粋な文字列の問題になります。2 つの文字列間の辞書編集上の順序は、最初の異なる位置を比較して、辞書の順序とまったく同じように決定されます。 すべての有限文字列は同じ順序で存在するため、「ライブラリ位置」は辞書編集順での文字列自体と同等です。 したがって、位置を最小化することは、0 または 1 つのスワップで達成可能な辞書編集上の最小の文字列を生成することと同じです。 

入力は 1 つの文字列だけです`S`までの長さ$10^5$。 出力は、次から取得された同じ長さの別の文字列です。`S`何もしないか、1 組の文字だけを交換します。 

すべてのペアを試行すると、$O(n^2)$それは大きすぎます$n = 10^5$。 実行可能なソリューションでは、すべてのスワップを線形または線形に近い時間で推論する必要があります。 

単純な貪欲なアイデアによる微妙な失敗例は、サフィックスに複数の同一の最高の文字が存在する場合に発生します。 

たとえば、次のように考えてみましょう`bcaac`。 単純なアプローチでは、スワッピングが発生する可能性があります。`b`と`a`文字列を改善し、最初の文字列を選択します`a`それは見つかります。 ただし、間違ったオカレンスと交換すると、次のような問題が発生する可能性があります。`acabc`の代わりに`aacbc`、両方とも有効な単一スワップであるにもかかわらず、辞書編集的にはさらに悪いことになります。 これは、スワップするかどうかだけではなく、どの文字とスワップするかを慎重に選択する必要があることを示しています。 

もう 1 つのエッジ ケースは、スワップを行わないと文字列が改善される場合です。`abcde`。 交換すると、辞書編集上の順序が維持されるか、悪化します。 正しい出力は元の文字列です。 

## アプローチ

 ブルートフォース戦略ではすべてのペアを試します$(i, j)$、スワップを実行し、結果の文字列を計算し、辞書編集的に最小値を取得します。 それぞれの比較にかかる費用$O(n)$、につながる$O(n^3)$直接実装された場合、またはせいぜい合計$O(n^2)$と交換します$O(n)$それぞれの比較。 これは不可能です$10^5$。 

重要な観察は、文字列を改善できる最も早い位置のみが重要であるということです。 辞書編集上の順序は左から右に決定されるため、より良い改善が以前に存在する場合、前の位置を変更せずに後の位置を改善しても無駄です。 

これは貪欲な構造につながります。左から右にスキャンして、位置を決定します。`i`後で登場する小さなキャラクターと交換することで改善できます。 これを効率的に行うために、すべての位置について、そのサフィックスで利用可能な最小の文字と、それが出現する場所を事前に計算します。 次に、現在の文字のサフィックスがまだ可能な限り最小ではない最初の位置で、最良の改善をもたらす交換を実行します。 

残りの微妙な点はタイブレークです。 最小の文字が接尾辞に複数回出現する場合は、最も右に出現した文字と交換するのが最適です。これは、以前の接尾辞の構造をそのままにしつつ、最小の値を可能な限り前方に引っ張り、辞書編集上のゲインを最大化するためです。

 | --- | --- | --- | --- |
 | すべてのペアをブルート フォース スワップ |$O(n^3)$または$O(n^2)$|$O(1)$| 遅すぎる |
 | サフィックス付きの貪欲な最小追跡 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスごとに、格納する配列を計算します。`i`、で始まるサフィックスの最小文字`i`、それが発生する位置とともに。 これにより、あらゆるポジションに最適なスワップパートナーが誰であるかを即座に知ることができます。 
2. 文字列を左から右にスキャンします。 位置で`i`、 比較する`S[i]`の最小文字で`S[i:]`。 それらが等しい場合、この位置にあるものは辞書編集上の順序を改善できないため、続行します。 
3. 最初の位置`i`どこ`S[i]`接尾辞の最小値よりも大きい場合は、アクションを実行するのに最適な場所です。 以前のインデックスは改善できず、後のインデックスは辞書編集上の順序付けに与える影響が小さくなります。 
4. サフィックス内の最小文字のすべての出現のうち、右端の位置を選択します。`j`。 
5. スワップ`S[i]`そして`S[j]`、その後停止します。 スワップは 1 回のみ許可されます。 
6. そのような位置が存在しない場合は、元の文字列を変更せずに出力します。 

### なぜ効果があるのか

 辞書編集的な比較は、2 つの文字列が異なる最初のインデックスで決定されます。 したがって、何らかの改善を行うには、文字列がサフィックスに対してまだ最小になっていない可能な限り最も早い位置を変更する必要があります。 後で小さい文字が存在する最初のインデックスを見つけたら、それより前に何かを変更することは不可能であり、後で何かを変更することはこの改善を支配することはできません。 

サフィックスで最小の文字を選択すると、最も早い異なるインデックスで最大の削減が保証されます。 右端の出現を選択すると、交換後もサフィックスのプレフィックスが可能な限り小さく保たれ、後の比較で偶発的に劣化することが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)

    if n <= 1:
        print("".join(s))
        return

    # suffix_min_char[i] = smallest character from i..n-1
    # suffix_min_pos[i] = rightmost position of that smallest character
    suffix_min_char = [''] * n
    suffix_min_pos = [0] * n

    suffix_min_char[-1] = s[-1]
    suffix_min_pos[-1] = n - 1

    for i in range(n - 2, -1, -1):
        if s[i] < suffix_min_char[i + 1]:
            suffix_min_char[i] = s[i]
            suffix_min_pos[i] = i
        elif s[i] > suffix_min_char[i + 1]:
            suffix_min_char[i] = suffix_min_char[i + 1]
            suffix_min_pos[i] = suffix_min_pos[i + 1]
        else:
            suffix_min_char[i] = s[i]
            suffix_min_pos[i] = i  # prefer rightmost for same char

    for i in range(n):
        if s[i] > suffix_min_char[i]:
            j = suffix_min_pos[i]
            s[i], s[j] = s[j], s[i]
            break

    print("".join(s))

if __name__ == "__main__":
    solve()
```この解決策は、各位置を一定時間で評価できるように、サフィックス最小値を事前計算することに依存しています。 左から右へのスキャンにより、最初の有益なスワップが辞書編集上の順序にとって最も重要なものであることが保証されます。 

実装の微妙な詳細は、タイ内の最小文字の右端の出現を追跡することです。 これが処理されない場合、スワップによって以前の出現が選択され、さらに右側の小さい文字が未使用のまま残される可能性があり、より詳細な比較で得られる辞書編集順序が悪化する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    s = list(sys.stdin.readline().strip())
    n = len(s)

    suffix_min_char = [''] * n
    suffix_min_pos = [0] * n

    suffix_min_char[-1] = s[-1]
    suffix_min_pos[-1] = n - 1

    for i in range(n - 2, -1, -1):
        if s[i] < suffix_min_char[i + 1]:
            suffix_min_char[i] = s[i]
            suffix_min_pos[i] = i
        elif s[i] > suffix_min_char[i + 1]:
            suffix_min_char[i] = suffix_min_char[i + 1]
            suffix_min_pos[i] = suffix_min_pos[i + 1]
        else:
            suffix_min_char[i] = s[i]
            suffix_min_pos[i] = i

    for i in range(n):
        if s[i] > suffix_min_char[i]:
            j = suffix_min_pos[i]
            s[i], s[j] = s[j], s[i]
            break

    print("".join(s))

# minimal
assert run("a\n") == "a", "single char"

# already optimal
assert run("abcde\n") == "abcde", "no improvement"

# simple swap
assert run("ba\n") == "ab", "basic swap"

# repeated letters
assert run("baca\n") == "a bca".replace(" ", ""), "best improvement early"

# all equal
assert run("aaaa\n") == "aaaa", "no effect"

# later improvement
assert run("cab\n") == "acb", "swap first char with best suffix"

 ## 特殊なケース

 のような機会が減少しない文字列の場合、`abcde`の場合、アルゴリズムはサフィックスの最小値が現在の文字より小さい位置を見つけることができないため、交換は実行されず、元の文字列が返されます。 

接尾辞に最小文字が繰り返される文字列の場合、次のようになります。`bcaac`、最初の位置の接尾辞の最小値は次のとおりです。`a`、右端の出現が選択されます。 一番右と入れ替える`a`残りの部分で最適な構造を維持しながら、最小の文字をできるだけ早く配置することで、辞書編集上の最良の結果が保証されます。 

最適な改善が大きな文字の最初の出現ではなく、改善が可能な最初のインデックスである場合。`harrypotter`、スキャンにより、後の位置を時期尚早に交換することがなくなり、辞書編集上の縮小が弱くなる可能性があります。
