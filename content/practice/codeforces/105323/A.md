 ## 解決策
 ## 問題の理解

 すべてのノードに最大 2 つの子を持つルート付きツリーが与えられます。 ルートはノード 1 であり、各ノードには関連する重みがあります。 最初はルートのみが赤く色付けされ、他のすべてのノードは白になります。 

このプロセスは個別のラウンドで進行します。 各ラウンドでは、何か他のことが起こる前に、ツリーから 1 つのエッジだけを削除することができます。 この削除後、色が広がります。すでに赤いノードに直接接続されているすべてのノードが赤になります。 これは、赤が常にノード 1 から開始して残りのエッジに沿って成長することを意味します。 

このプロセスは、新しいノードが赤色でなくなるまで繰り返されます。 最終的に、すべてのノードは赤になるか、永遠に白のままになります。 スコアは、白いノードの合計重みから赤いノードの合計重みを引いたものとして定義されます。 すべての重みの合計は固定されているため、スコアを最大化することは、赤になるノードの合計重みを最小化することと同じです。 

プレーヤーが持つ重要なコントロールは、スプレッドが発生する前にラウンドごとに 1 つのエッジを削除できることです。 それぞれの削除により、サブツリー全体がルートから到達できなくなる可能性がありますが、これは感染がツリーのその部分に到達する前に、十分に早い段階で削除された場合に限られます。 

n ≤ 10000 という制約は、およそ O(n log n) または O(n) 個の解が必要であることを示唆しています。 O(n^2) かかるプロセスを単純にラウンドごとにシミュレートすると、各ラウンドが多くのエッジや伝播ステップに触れる可能性があるため、遅すぎます。 

非常に早い段階でサブツリーに到達できるようになる場合、微妙なエッジ ケースが発生します。 その瞬間までに接続エッジを切断しなければ、サブツリー全体が永久に失われます。 たとえば、ディープ ノードが後になってブロックされただけの場合、そのノードは以前にすでに感染しており、最終的にカットが実行されたとしても役に立たない可能性があります。 

もう 1 つのエッジ ケースは、複数の高重みサブツリーが存在するが、ラウンドごとに 1 つのエッジしかカットできない場合です。 サブツリーのサイズと同じくらいタイミングの制約も重要であるため、常に最大の直接サブツリーをカットするような貪欲なローカル決定は、必ずしも最適であるとは限りません。 

## アプローチ

 プロセスを直接シミュレートする場合、各ラウンドで現在のレッド フロンティアを追跡し、どのエッジをカットするかを決定します。 その後、赤い領域を拡大します。 最悪の場合、これには O(n) ラウンドがかかる可能性があり、各ラウンドではスプレッドをシミュレートしてカットを評価するために多くのエッジをスキャンする必要がある可能性があります。 これにより O(n^2) の動作が発生し、n が 10000 までの場合は遅すぎます。 

重要な観察は、エッジが削除されない場合、拡散プロセスは決定論的であるということです。深さ d の各ノードは、時間 d で赤になります。 ノードが赤くなるのを防ぐ唯一の方法は、時間 d よりも前にノードをその親に接続しているエッジを切断することです。 これにより、問題は、タイミング制約の下でカットするエッジのセットを選択することに変わります。 

親 u から子 v までの各エッジは、v に到達する時間 (その深さ) に等しい期限を持つ「ジョブ」として扱うことができます。 そのエッジをカットすると、v をルートとするサブツリー全体が赤くなるのを防ぎます。 それを切断することによる利益は、そのサブツリーの総重量です。 

ここで古典的なスケジューリングの問題が生じます。それぞれに期限と利益が設定された単位時間のジョブがあり、総利益を最大化したいと考えています。 ラウンドごとに最大 1 カットをスケジュールできるため、これは期限を伴う単一マシンのスケジュールの問題です。 

このブルートフォースは、切断と拡散を直接シミュレートしているため機能しますが、感染時間が深さによって固定されているという事実を利用していないため、失敗します。 その構造を認識すると、問題はサブツリーの合計を計算し、貪欲なスケジューリング問題を解決することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 締め切りスケジュール + 貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

問題をツリーエッジ上のスケジューリングタスクに変換します。 

1. ノード 1 でツリーをルートし、すべてのノードの深さを計算します。 深さは、何もカットされなかった場合にそのノードが赤くなる時間を表します。 
2. 各サブツリーの重みの合計を計算します。 これは重要です。親からノードまでのエッジをカットすると、サブツリー全体が赤くなるのを防ぐことができるため、保存される値は正確にサブツリーの合計になります。 
3. ルートを除くすべてのノードについて、その親からそれ自体までのエッジに対応する「ジョブ」を定義します。 各ジョブには、サブツリーの合計に等しい利益と、その深さに等しい期限があります。 
4. ここで、時間単位ごとに 1 つ以上のジョブが選択されず、選択された各ジョブが期限前にスケジュールされるように、これらのジョブのサブセットを選択する必要があります。 選択した仕事の総利益は最大化されるべきです。 
5. すべてのジョブを利益の降順に並べ替えます。 それらを繰り返して、ジョブごとに、締め切りの直前かそれと同じ時点で、利用可能な最新のタイムスロットにジョブを割り当てるようにしてください。 スロットが利用可能な場合は、それをスケジュールします。 それ以外の場合は破棄します。 
6. スケジュールされたジョブの利益の合計は、白のままであるノードの合計の重みになります。 最終的な答えは、解釈に応じて total_sum - 2 * red_sum、または同等の total_sum - 2 * Saved_white_subtrees ですが、red = total - Saved を介して直接計算するのが最も簡単です。 

これが機能する理由は、単一の構造的不変条件から来ています。すべてのサブツリーは完全に感染しているか、完全に保存されており、唯一の制御メカニズムは、サブツリーにつながるエッジがその深さの期限前に切断されるかどうかです。 カットはラウンドごとに 1 つにグローバルに制限されているため、問題は独立したジョブの独立したスケジューリングとなり、タイムスロットの競合を除いてサブツリー間に相互作用は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = [0] * (n + 1)

    vals = list(map(int, input().split()))
    for i in range(2, n + 1):
        w[i] = vals[i - 2]

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    order = []

    stack = [1]
    parent[1] = -1
    depth[1] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

    sub = [0] * (n + 1)
    for i in range(1, n + 1):
        sub[i] = w[i]

    for u in reversed(order):
        for v in g[u]:
            if parent[v] == u:
                sub[u] += sub[v]

    jobs = []
    for v in range(2, n + 1):
        jobs.append((sub[v], depth[v]))

    jobs.sort(reverse=True)

    maxd = n
    used = [False] * (maxd + 1)
    saved = 0

    for val, d in jobs:
        for t in range(min(d, n), 0, -1):
            if not used[t]:
                used[t] = True
                saved += val
                break

    total = sum(w)
    # nodes saved correspond to white remaining subtrees;
    # red = total - saved, score = white - red = total - 2*red = 2*saved - total
    print(2 * saved - total)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、ルート付きツリーを構築し、明示的なスタック トラバーサルを使用して深さを計算します。 これにより、再帰の深さの問題が回避され、線形な時間の移動が保証されます。 

サブツリーの計算は走査の逆の順序で実行され、子の寄与分が親に蓄積されます。 これにより、各ノードに、それが制御するサブツリーの正確な重みが与えられます。 

ルートを除く各ノードがスケジューリング ジョブになります。 期限はその深さであり、利益はそのサブツリーの合計です。 

貪欲なスケジューリング ループは、各ジョブを締め切り前の最新の空きタイム スロットに割り当てます。 ジョブをできるだけ遅く配置すると、より厳しい締め切りに備えて早いスロットが確保されるため、これは非常に重要です。 

最後に、スコア変換では、保存された重みと最終目標の間の同一性が使用されます。つまり、白から赤を引いた最大化は、保存されたサブツリーの重みの寄与を最大化することになります。 

## 実用的な例

 ノード 1 が 2 と 3 に接続し、2 と 3 の両方が葉である小さなツリーを考えてみましょう。 重みを w2 = 4、w3 = 5 とします。 

サブツリーの合計を計算します: sub(2)=4、sub(3)=5。 深さは両方とも 1 です。ジョブは (4,1) と (5,1) です。 

| ステップ | 検討中の仕事 | 予定されているスロット | 保存済み |
 | --- | --- | --- | --- |
 | 1 | (5,1) | t=1 | 5 |
 | 2 | (4,1) | 利用可能なものはありません | 5 |

 時間 1 では 1 つのカットのみが可能であるため、より利益の高いサブツリーを選択します。 

これは、競合する同じ期限のサブツリーが最大のサブツリーのみを強制的に選択することを示しています。 

次に、重みがそれぞれ 1、10、100、1000 であるチェーン 1-2-3-4 を考えてみましょう。 

サブツリーの合計は累積されます: sub(4)=1000、sub(3)=1010、sub(2)=1020。 深さはそれぞれ 3、2、1 です。 

| ステップ | 仕事 | 締め切り | 決定 |
 | --- | --- | --- | --- |
 | 1 | (1020,1) | 1 | 予定 |
 | 2 | (1010,2) | 2 | 予定 |
 | 3 | (1000,3) | 3 | 予定 |

 ここでは、チェーンに沿って期限が増加するため、すべてのジョブが適合し、タイミング制約が十分に緩い場合には競合が発生しないことが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、複数の大きなサブツリーが同じ深さを共有する場合に発生します。 この場合、単位時間当たり 1 つのカットしか実行できないため、そのうちの 1 つだけを保存できます。 すべてに同一の期限があり、実現可能性を区別するのは利益のみであるため、貪欲な利益の順序付けにより、最大のサブツリーが選択されることが保証されます。 

別のケースは、大きなサブツリーがツリーの奥深くにあるものの、時間内に切断されない浅い祖先によってブロックされている場合に発生します。 この状況では、サブツリー自体は価値がありますが、そのジョブは期限までにスケジュールできません。そのため、感染が避けられないことを反映して、スケジューリング ループによって正しく破棄されます。 

最後のケースは、すべてのノードの深さの期限が増加する長いチェーンです。 ここでは、すべてのジョブが実行可能であり、アルゴリズムは、競合することなくカットを時間の経過とともに分散できるという事実に合わせて、すべてのジョブをスケジュールします。
