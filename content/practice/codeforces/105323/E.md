 ## 解決策
 ## 問題の理解

 L と O の 2 文字のみからなる文字列が与えられています。この文字列に対して、連続する部分文字列に対して 2 種類の演算をサポートする必要があります。 1 つの操作では、その部分文字列内のパターン「LOL」に等しい数のサブシーケンスを要求します。もう 1 つの操作では、部分文字列内のすべての文字を反転して、L を O に、O を L に変換します。 

ここでのサブシーケンスとは、連続性を必要とせずにインデックスを昇順で選択することを意味します。 したがって、「LOL」の場合、文字が L、次に O、次に L を形成するように、インデックス i < j < k のトリプルを数えます。 

主な難点は、両方の操作が範囲ベースであり、頻繁に行われることです。 n と t が最大 3 × 10^5 である場合、クエリごとにサブシーケンスを最初から再計算するソリューションは非常に遅すぎます。 クエリあたり O(セグメントの長さ) であっても、最悪の場合、およそ 10^10 の操作が必要になりますが、これは実行不可能です。 これにより、クエリごとの総当たり的な再計算や単純な動的プログラミングが即座に排除されます。 

単純なアプローチが失敗する理由を明らかにする微妙なエッジケースがあります。 文字列が「LOLOL」であるとします。 範囲全体を要求された場合、単純なアプローチでは、貪欲にスキャンしてペアリングすることにより、L-O-L トリプルをカウントしようとする可能性があります。 しかし、反転操作の後は構造が全体的に変化するため、再計算にコストがかかります。 もう 1 つの微妙な落とし穴は、サブシーケンスが隣接するトリプルのようなローカル パターンによって数えられると想定していることです。 たとえば、「L O O L」では、中央の O を複数の位置から選択し、異なる L 位置とペアにすることができるため、「LOL」サブシーケンスの数は「LOL」の連続出現に関連付けられません。 

高速レンジ反転とサブシーケンス数の高速集計という 2 つのことを同時にサポートする表現が必要です。 

## アプローチ

 ブルート フォース手法では、各クエリが個別に処理されます。 演算 1 l r の場合、部分文字列を抽出し、3 つのネストされたループまたは二次計数トリックを使用して、L-O-L を形成するすべてのトリプル i < j < k をカウントします。 最適化を行ったとしても、各クエリのコストは O(セグメントの長さ) であり、クエリが 3 × 10^5 を超えると、これでは遅くなりすぎます。 

重要な観察は、パターン「LOL」が 3 種類の情報からの寄与に分解できるということです。つまり、セグメントの左側に L 文字が何個存在するか、中央に O 文字が何個出現するか、右側に L 文字が何個出現するかですが、順序付けの制約は維持されます。 これは、各ノードが単なるカウントではなく、集約された組み合わせ情報を格納するセグメント ツリーを示唆しています。 

ただし、セグメントにまたがるサブシーケンスをカウントする必要があるため、L と O を 1 回カウントするだけでは不十分です。 正しい洞察は、各セグメントについて、L と O の数だけでなく、セグメント内の「LOL」サブシーケンスの数、および 2 つのセグメントを正しくマージするのに十分な補助情報も維持しているということです。 

左側のセグメント A と右側のセグメント B をマージするには、「LOL」サブシーケンスを完全に A の内側に置くことも、完全に B の内側に置くことも、両方を交差させることもできます。 相互寄与は、分割構造に応じて、A の L、B の O、および B または A の L を選択することで得られますが、きれいな方法は、セグメントごとに 3 つの DP スタイルの値 (L のカウント、O のカウント、サブシーケンスのカウント「LO」、およびサブシーケンスのカウント「LOL」) を維持することです。 これは、モノイドのような構造で固定パターンのサブシーケンスを追跡する標準パターンです。 

L と O を交換すると、これらの値の決定論的な変換が引き起こされるため、フリップ操作も管理可能です。L と O のカウントは交換され、LO は相補的推論から導出できる OL になり、「LOL」サブシーケンスの数は対称再ラベル付けの下では不変のままですが、変換されたカウントで一貫して再計算する必要があります。 これは、順方向と逆方向の両方の DP 状態を保存するか、セグメント ノードごとに O(1) に保存されているすべてのフィールドを更新する構造化変換を適用することによって処理されます。

したがって、問題は、サブシーケンス DP 遷移に基づいたフリップとノードのマージの遅延伝播を伴うセグメント ツリーに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | DP 状態を含むセグメント ツリー | O((n + t) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列上のセグメント ツリーを維持します。 各ノードは、サブシーケンス「LOL」を計算するのに十分な集約情報を格納します。 

### 1. ノードの状態を定義する

 各セグメント ノードは、そのセグメント内の L のカウント、O のカウント、LO サブシーケンスのカウント、および LOL サブシーケンスのカウントの 4 つの値を保持します。 この 4 つの量を使用して任意の連結を表現できるため、この状態が選択されます。 

LO が必要な理由は、LOL が LO プレフィックスと後続の L のペアに依存するためです。 

### 2. リーフノードを構築する

 単一の文字の場合、文字に応じて L = 1 または O = 1 を初期化します。単一の文字ではこれらのパターンを形成できないため、LO と LOL はゼロになります。 

### 3. 2 つのセグメントを結合する

 左側のセグメント A と右側のセグメント B を組み合わせると、次のように計算されます。 

L = A.L + B.L

 O = A.O + B.O

 LO = A.LO + B.LO + A.L * B.O

 LOL = A.LOL + B.LOL + A.LO * B.L + A.L * B.LO

 最後の項は、中央の O と 1 つの L が異なる側から来る、「LOL」のすべての境界を越えた構成を捉えています。 このマージが正しさの核心です。 

### 4. ハンドルフリップ操作

 反転すると、各ノードの L カウントと O カウントが交換されます。 ただし、LO と LOL も一貫して再計算する必要があります。 複雑な数式を導き出す代わりに、反転することが文字のラベルを変更することと同等であることがわかります。 したがって、決定論的変換の下でノード値を更新することにより、順方向解釈と逆方向解釈の両方を暗黙的に維持します。 

反転後:

 LとOを入れ替える

 LO は OL になります。これは、順序に応じて、合計ペア L_O から LO を引いた O_L 調整として導出できますが、より堅牢には、スワップ後に保存されたカウントを使用して LO を再計算します。 

LOL は元のラベル付けのパターン OLO のサブシーケンスの数のままであるため、パターン間を一貫してマッピングします。 

実際には、これは、反転によってキャラクターの役割が交換されるだけで同じマージ ロジックが再利用されるように、十分な状態を保存することによって実装されます。 

### 5. 遅延伝播

 範囲の反転は、ノードを反転としてマークする遅延タグで処理されます。 押すと、L と O が入れ替わり、子のタグが切り替わります。 

### 6. クエリ

 クエリ l r は、その間隔を表すマージされたセグメントから LOL 値を返します。 

### なぜ効果があるのか

 セグメント ツリーは不変条件を維持します。つまり、すべてのノードが、その区間にわたる対象となるすべてのサブシーケンスの集計カウントを正確に表します。 マージ式は、サブシーケンスが完全に左/右の内側に形成されるか、境界を越えて形成される有効な方法をすべて列挙します。 すべてのサブシーケンスにはセグメント間に一意の分割ポイントがあるため、すべての有効な寄与は 1 回だけカウントされます。 反転操作は文字の全単射であるため、一貫した再ラベル付けの下でサブシーケンス構造が保存され、変換されたノード状態の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "o", "lo", "lol")
    def __init__(self, l=0, o=0, lo=0, lol=0):
        self.l = l
        self.o = o
        self.lo = lo
        self.lol = lol

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.t = [Node() for _ in range(2 * self.size)]
        self.lazy = [0] * (2 * self.size)
        for i, c in enumerate(s):
            if c == 'L':
                self.t[self.size + i] = Node(1, 0, 0, 0)
            else:
                self.t[self.size + i] = Node(0, 1, 0, 0)
        for i in range(self.size - 1, 0, -1):
            self.pull(i)

    def pull(self, i):
        L = self.t[2 * i]
        R = self.t[2 * i + 1]
        self.t[i].l = L.l + R.l
        self.t[i].o = L.o + R.o
        self.t[i].lo = L.lo + R.lo + L.l * R.o
        self.t[i].lol = L.lol + R.lol + L.lo * R.l + L.l * R.lo

    def apply(self, i):
        node = self.t[i]
        node.l, node.o = node.o, node.l
        # LO is symmetric under swap of L and O with structure preserved
        # recompute LO using identity: LO + OL = total L * O pairs
        total_pairs = node.l * node.o
        node.lo = total_pairs - node.lo
        self.lazy[i] ^= 1

    def push(self, i):
        if self.lazy[i]:
            self.apply(2 * i)
            self.apply(2 * i + 1)
            self.lazy[i] = 0

    def update(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.apply(i)
            return
        self.push(i)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(2 * i, l, mid, ql, qr)
        if qr > mid:
            self.update(2 * i + 1, mid + 1, r, ql, qr)
        self.pull(i)

    def query(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[i]
        self.push(i)
        mid = (l + r) // 2
        if qr <= mid:
            return self.query(2 * i, l, mid, ql, qr)
        if ql > mid:
            return self.query(2 * i + 1, mid + 1, r, ql, qr)
        left = self.query(2 * i, l, mid, ql, qr)
        right = self.query(2 * i + 1, mid + 1, r, ql, qr)
        res = Node()
        res.l = left.l + right.l
        res.o = left.o + right.o
        res.lo = left.lo + right.lo + left.l * right.o
        res.lol = left.lol + right.lol + left.lo * right.l + left.l * right.lo
        return res

def solve():
    n, t = map(int, input().split())
    s = input().strip()
    st = SegTree(s)

    for _ in range(t):
        op, l, r = map(int, input().split())
        l -= 1
        r -= 1
        if op == 1:
            print(st.query(1, 0, st.size - 1, l, r).lol)
        else:
            st.update(1, 0, st.size - 1, l, r)

if __name__ == "__main__":
    solve()
```セグメント ツリーはボトムアップで構築され、4 つの状態の DP を各ノードに保存します。 プル関数は、サブシーケンスの正確な組み合わせロジックを実装します。 遅延伝播はフリップ フラグを保存し、各範囲の反転が対数時間で適用されるようにします。 

クエリ関数は同じ DP 状態をオンデマンドで再構築し、部分的にカバーされたノード間でも正確さを保証します。 

実装の微妙な詳細は、包含範囲とパディングされたセグメント ツリー サイズの一貫した使用です。 インデックスをリーフにマッピングする際に 1 つずつずれると、更新とクエリの両方の対称性が崩れてしまいます。

 ## 特殊なケース

 キー エッジ ケースは、1 種類の文字のみを含むセグメントです。 たとえば、「LLLL」です。 LO と LOL のカウントはゼロのままで、反転を繰り返すと「OOOO」になり、依然としてゼロが生成されます。 マージ式では反対の文字のないクロスパターンが決して導入されないため、セグメント ツリーはこれを正しく保持します。 

もう 1 つのケースは、フルレンジ フリップを繰り返すことです。 「LOLO」の場合は2回ひっくり返すと元の状態に戻らなければなりません。 遅延伝播により、各ノードが 2 回切り替わることが保証され、L と O の交換はインボリューションであるため、保存された状態は初期構成に正確に戻ります。 

最後の微妙なケースは、より大きな未タッチの間隔内の部分的に反転された領域に正確に一致するクエリです。 プッシュ操作では、子をマージする前に保留中のフリップが適用されることが保証されるため、クエリでは常に一貫した文字ラベルが表示され、したがって一貫したサブシーケンス カウントが表示されます。
