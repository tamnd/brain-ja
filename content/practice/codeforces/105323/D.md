 ## 解決策
 ## 問題の理解

 それぞれがデーモンを表すノードのセットが与えられています。 すべてのノードには、必要な強度のしきい値、報酬の強度の増加、および前提条件となる「キー」のセットがあります。 ノードは 2 つの条件が同時に満たされた場合にのみ試行できます。つまり、その前提条件となるキーがすべて以前に敗北したノードからすでに取得されており、現在の強度が少なくともその要件を満たしていることです。 

ノードが敗北すると、そのノードは考慮から外され、他のノードのロックを解除できるキーとしてそのインデックスに貢献し、その報酬値によって現在の強さが増加します。 このプロセスは最初の強さから開始され、それ以上ノードを倒すことができなくなるまで貪欲に継続されます。 

重要な構造上の制約は、キー依存グラフが有向非巡回グラフであることです。 これにより、循環ロックの可能性が排除されるため、キーに関してノードが利用可能になると、そのノードは再び無効化されることはなくなります。 

制約は最大 20 万のノードと合計 20 万の依存関係エッジに達します。 すべてのノードを繰り返しスキャンしたり、ステップごとに実行可能性を最初から再計算したりするソリューションは、最悪の場合二次的な動作につながるため、失敗します。 これにより、ソリューションは増分構造 (通常は優先キューまたは DAG 上の BFS のような伝播) を維持する方向にすぐに推進されます。 

複数のノードが同時に利用可能になったものの、現在は強度の関係で一部のノードしか利用できない場合、微妙な障害が発生するケースが発生します。 任意の順序で選択すると、行き止まりにつながる可能性があります。 

次のシナリオを考えてみましょう。現在の強度が 10 で、2 つのノードが利用可能になります。1 つは強度 10 を必要とし +1 を与え、もう 1 つは強度 1 を必要とし +100 を与えます。 誤って +1 ノードを最初に選択すると、より適切な順序付けが存在するにもかかわらず、後でわずかに高いしきい値を必要とするノードに到達できない可能性があります。 これは、実現可能性だけでは不十分であり、次に処理する利用可能なノードを慎重に選択する必要があることを示しています。 

## アプローチ

 直接シミュレーションは説明が簡単です。 すべてのノードを繰り返しスキャンし、ノードがすべてのキーを収集し、その要件が現在の強度で満たされるたびに、ノードを破って強度を更新し、これを繰り返します。 これはルールに正確に従っているため、これは正しいです。 

このアプローチの問題はパフォーマンスです。 敗北するたびに、有効な候補を見つけるために n 個のノードすべてをスキャンする必要がある場合があります。 最大 200,000 ノードでは、ステップごとに約 n 回、最大 n ステップの操作が発生し、制限をはるかに超える二次関数の複雑さになります。 

重要な観察は、主要な依存関係が DAG を形成するため、「利用可能になる」ということは、次数削減によって駆動される単調なイベントであるということです。 ノードの前提条件が満たされると、そのノードを候補のプールに 1 回だけ挿入できます。 その時点から、残る唯一の制約は、必要な強度が満たされるかどうかです。 

これにより、問題が 2 つの独立したフィルターに分離されます。 最初のフィルターは構造的なもので、トポロジカル ロック解除によって処理されます。 2 番目のフィルターは数値フィルターであり、強度しきい値によって処理されます。 ロックされていないノードのプールを維持し、現在要件が満たされているノードの中から動的に選択できます。 

選択を効率的に行うために、私たちは 2 つの優先順位構造を維持しています。 1 つはロック解除されたノードを要件ごとに並べて保存するため、新しく手頃な価格のノードをアクティブなプールにすぐに移動できます。 2 番目には、現時点で手頃な価格のノードが報酬強度の増加順に格納されているため、現時点で実行可能なものの中から最も有益な次のステップを常に選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n + m) | 遅すぎる |
 | デュアル プライオリティ キューの最適化 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

現在到達可能で手頃なノードのセットを継続的に維持しながら、依存関係グラフを処理します。 

1. 主要な要件に基づいて各ノードの次数を計算します。 各キーからロックを解除するノードまでの隣接リストを作成します。 次数が 0 のノードは、最初はロック解除されています。 
2. 最初にロック解除されたすべてのノードを、必要な強度の順に並べた構造に挿入します。 これらのノードは構造的には入手可能ですが、必ずしも手頃な価格ではありません。 
3. 初期値から開始して、現在の強度を変数として維持します。 
4. 必要な強度が最大でも現在の強度であるノードを、ロック解除された構造から報酬獲得順に並べられた 2 番目の構造に繰り返し移動します。 これにより、現時点で実際に倒すことができるノードのみを考慮することが保証されます。 
5. 手頃な構造が空の場合、現在の強さでは残りのノードを倒すことができないため、プロセスは終了します。 
6. それ以外の場合は、最も高い報酬獲得を持つノードを選択し、それを倒し、それを回答に記録し、現在の強さを増加させます。 
7. 依存するノードごとに、次数を減らします。 いずれかの従属ノードが 0 度に達した場合は、そのノードをロック解除された構造に挿入します。 
8. これ以上進めなくなるまでステップ 4 から繰り返します。 

正しさは、ノードが一度ロック解除されると (すべてのキーが収集されると) 永久にロック解除されたままになり、一度手頃な価格になると、強度が増すだけで手頃な価格のままであるという事実にかかっています。 

### なぜ効果があるのか

 アルゴリズムは常に、構造上の前提条件が満たされているノードと、その中の強度要件が満たされているノードの 2 つのセットを維持します。 元の問題における有効な次の一手は、それらの交差部分から得られる必要があります。 

このプロセスでは、有効な候補が無視されることはありません。すべてのノードは、構造的に可能になったときにロック解除セットに正確に入力し、数値的に可能になったときに正確に手頃なセットに入力します。 手頃な価格のノードの中から選択する場合は、即時的な強さの増加を最大化するものが常に選択されます。強さは単調であるため、より高い報酬を持つノードを遅らせても、それが手頃な価格になると決して有益ではありません。 

これにより、特定の状態から有効な敗北のシーケンスが存在する場合、アルゴリズムは、その後同じ状態またはより強力な状態に到達することをブロックしないことが保証されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n, p = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]
indeg = [0] * n

for i in range(n):
    parts = list(map(int, input().split()))
    k = parts[0]
    for x in parts[1:]:
        x -= 1
        g[x].append(i)
        indeg[i] += 1

ready = []
for i in range(n):
    if indeg[i] == 0:
        heapq.heappush(ready, (a[i], i))

affordable = []
visited = [False] * n
ans = []

while True:
    while ready and ready[0][0] <= p:
        ai, i = heapq.heappop(ready)
        heapq.heappush(affordable, (-b[i], i))

    if not affordable:
        break

    negb, i = heapq.heappop(affordable)
    if visited[i]:
        continue

    visited[i] = True
    ans.append(i + 1)
    p += b[i]

    for to in g[i]:
        indeg[to] -= 1
        if indeg[to] == 0:
            heapq.heappush(ready, (a[to], to))

print(len(ans))
print(*sorted(ans))
```実装は、キーの関係から依存関係グラフを構築することから始まり、各キーをエッジの前提条件の関係として扱います。 Indegrees は、各ノードでまだ不足しているキーの数を追跡します。 

の`ready`ヒープには、主要な条件が満たされたノードが、必要な強度順に並べて保存されるため、強度が増加するにつれて使用可能になる可能性のある候補を効率的に抽出できます。 

の`affordable`heap は、構造的にロックが解除されており、現在勝利可能なノードを、最大ヒープとして動作するように負の報酬順に格納します。 これにより、最も有益な即時アップグレードが常に選択されるようになります。 

メイン ループは、まず新しく手頃なノードを促進し、次に、敗北する最適な候補を選択します。 敗北するたびに、キーのロック解除を伝播し、システムに新しいノードを導入する可能性があります。 

選択順序が数値であることが保証されていないため、最終的な回答を並べ替える必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各ノードはヒープに 1 回出入りし、各エッジは度数を 1 回減少します。 
| スペース | O(n + m) | グラフと 2 つの優先キュー |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, p = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    indeg = [0] * n

    for i in range(n):
        parts = list(map(int, input().split()))
        k = parts[0]
        for x in parts[1:]:
            x -= 1
            g[x].append(i)
            indeg[i] += 1

    import heapq
    ready = []
    for i in range(n):
        if indeg[i] == 0:
            heapq.heappush(ready, (a[i], i))

    affordable = []
    visited = [False] * n
    ans = []

    while True:
        while ready and ready[0][0] <= p:
            ai, i = heapq.heappop(ready)
            heapq.heappush(affordable, (-b[i], i))

        if not affordable:
            break

        negb, i = heapq.heappop(affordable)
        if visited[i]:
            continue

        visited[i] = True
        ans.append(i + 1)
        p += b[i]

        for to in g[i]:
            indeg[to] -= 1
            if indeg[to] == 0:
                heapq.heappush(ready, (a[to], to))

    return str(len(ans)) + "\n" + " ".join(map(str, sorted(ans)))

assert run("1 5\n1\n0\n") == "1\n1"

# sample-like chain
assert run("3 1\n1 2 3\n1 1 1\n0\n1 1\n1 2\n") == "3\n1 2 3"

# no progress
assert run("2 0\n5 5\n1 1\n0\n0\n") == "0\n"

# independent choices
assert run("2 10\n1 2\n5 1\n0\n0\n") == "2\n1 2"

 ## 特殊なケース

 重要なエッジケースは、ノードが早期に構造的にロック解除されても、かなり後になるまで利用可能にならない場合に発生します。 このアルゴリズムは、そのようなノードが確実に`ready`ヒープに移動されるだけです。`affordable`強度のしきい値に達するとヒープに保存されるため、失われたり、途中で破棄されることはありません。 

もう 1 つのケースは、複数のノードが同時にロック解除され、1 つのノードのみが残りのノードのロックを解除するのに十分な強度の増加につながる場合です。 選択は手頃な価格のノード間での報酬の最大化によって行われるため、アルゴリズムは常に成長パスを優先し、遅延したが必要なロック解除チェーンが最終的にアクティブ化されるようにします。 

最後のエッジケースは、残りのノードがすべてロック解除されているが、どれも手頃な価格ではない場合です。 この状況では、レディ ヒープにはまだノードが含まれている可能性がありますが、強度フィルターを通過するノードは存在しないため、アルゴリズムは無効な遷移を試みることなく正しく終了します。
