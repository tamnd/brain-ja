 ## 問題の理解

 グリッドが与えられています$k$行と$n$列。 各細胞にはミネラルが含まれていることもあれば、含まれていないこともあります。 グリッドを直接観察する代わりに、スキャナーの出力が与えられます。 

各列ごとに$p$、スキャナは列から始まる「三角形」領域を定義します。$p$列を上に進むにつれて左に拡大します。 具体的にはコラム$p$すべてに貢献します$k$列のセル$p$、 カラム$p-1$トップのみを提供します$k-1$セル、列$p-2$トップのみを提供します$k-2$セルなど、寄与がなくなるまで続きます。 スキャナ出力$b_p$は、単にこの三角形領域内の鉱物細胞の数です。 

タスクは、1 つの有効なグリッドを再構築することではなく、すべての列に対して指定されたスキャナー出力を正確に生成する、異なるバイナリ グリッド (各セル内のミネラルまたは空) がいくつあるかをカウントすることです。 答えは必須です$10^9+7$。 

制約はすぐに問題を形成します。 行数は非常に少なく、最大 7 ですが、列数は最大 200 です。この非対称性は、行を主要な指数次元として扱うソリューションは許容できるが、列または完全なグリッド構成で指数関数的なものは不可能であることを示唆しています。 この構造は、各セルが複数のスキャナーの応答に寄与していることも示唆しているため、独立した列ではなくグローバル制約システムを扱っています。 

スキャナ出力が一貫していない場合、微妙なエッジケースが発生します。 たとえば、次の場合$k=2$、$n=3$、 そして$b=[0, 3, 0]$の場合、列 2 だけでも、三角形の領域で物理的に可能な量を超えるミネラルがすでに必要となります。 この場合、正解は 0 です。重複制約をチェックせずに列を個別に扱うアプローチでは、不可能な構成が誤ってカウントされます。 

もう 1 つの注意が必要な状況は、複数の構成が存在するが、単純な列ごとの推論では区別できない場合です。 各セルは複数の機能に寄与するため、$b_p$、列内のローカルな決定は、将来の列を考慮せずに最終決定することはできません。

 ## アルゴリズムのチュートリアル

 列を左から右に処理します。 重要な考え方は、どの列でも$p$、最後に開始された間隔のみ$k$可能な最長の間隔の長さは次のとおりであるため、列は引き続きアクティブにすることができます。$k$。 これにより、残りの長さによってグループ化されたアクティブな間隔を記述する小さな状態を使用してシステム全体を表すことができます。

2. 各列で、アクティブな間隔の合計が指定された値に等しいことを確認することで、実現可能性を検証します。$b_p$。 一致しない場合、この状態は破棄されます。 

このステップにより、スキャナ出力とのローカル一貫性が強制されます。 
3. 列の各状態から$p$、列内の新しいセルをアクティブ化するすべての可能な方法を検討します。$p$。 各行$r$固定長の潜在的な間隔に対応します$L = k - r + 1$したがって、各行は、そのセルをアクティブにするかアクティブにしないかという二者択一の決定に寄与します。

4.列から開始する間隔を選択した後$p$、コラムに移ります$p+1$。 すべてのアクティブなインターバルは残りの長さを 1 減らすため、`cnt[t]`に移行します`cnt[t-1]`。 ゼロに達した間隔は消えます。

### なぜ効果があるのか

 この状態は、どの間隔がまだアクティブであり、どれくらいの期間影響を与え続けるかなど、将来の遷移に影響を与える情報を正確に取得します。 すべての間隔は開始されると独立して動作し、システムの残りの部分との唯一の相互作用は列ごとの合計を介して行われます。 すべての間隔には有効期間が制限されているため、$k$、より古い情報はありません$k$常にステップが必要です。 これにより、同じ結果に至る 2 つの歴史が保証されます。`cnt`状態は将来のすべての列で区別できないため、それらを DP にマージすると正確さが維持されます。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline
MOD = 10**9 + 7

def encode(cnt):
    # tuple form for hashing
    return tuple(cnt)

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    # dp[state] = number of ways
    # state: (cnt1, cnt2, ..., cntk)
    dp = defaultdict(int)
    dp[tuple([0] * k)] = 1

    for i in range(n):
        ndp = defaultdict(int)

        bi = b[i]

        for state, ways in dp.items():
            cnt = list(state)

            # check current coverage constraint
            if sum(cnt) != bi:
                continue

            # try all subsets of k rows (2^k choices)
            for mask in range(1 << k):
                # build next state
                nxt = [0] * k

                # decay old intervals
                for t in range(k - 1):
                    nxt[t] = cnt[t + 1]

                # add new intervals from current column
                for r in range(k):
                    if mask & (1 << r):
                        L = k - r
                        nxt[L - 1] += 1

                ndp[tuple(nxt)] = (ndp[tuple(nxt)] + ways) % MOD

        dp = ndp

    print(sum(dp.values()) % MOD)

if __name__ == "__main__":
    solve()
```DP ディクショナリには、各列の到達可能な間隔設定のみが保存されます。 各構成は、将来の列に保持されるアクティブなコントリビューションの数を記録します。 この遷移では、論理的に別個の 2 つのアクションが実行されます。1 つ目は、すべての既存の寄与が 1 ステップずつ減少し、2 つ目は、現在の列で選択されたセルに対応する新しい寄与をオプションで導入します。 

よくある実装の落とし穴は、減衰順序と挿入順序を混合することです。 新しい間隔が古い間隔と​​同じステップですぐに減衰すると、その有効期間が 1 つ不正確になり、すべての寄与がシフトされ、一貫性が失われます。$b_p$。 コードでは、最初に減衰配列を構築し、その後で新しい間隔を挿入することでこれを回避します。 

もう 1 つの微妙な問題は、状態の爆発です。 理論上の状態の数は多くなりますが、実際には、アクティブな間隔の合計が一致する必要があるという制約により、多くの状態に到達できません。$b_p$各ステップで。 この剪定は制限内で合格するために不可欠です。

 ## 特殊なケース

 主なエッジケースは、すべてのスキャナ出力がゼロの場合です。 この状況では、すべての列にわたってすべての状態が空のままでなければなりません。 DP は空の構成から開始され、すべてゼロの状態だけが各ステップで残り、有効な構成が 1 つだけ生成されます。 

もう 1 つのエッジ ケースは、列が物理的に存在できるよりも多くのアクティブな間隔を必要とする場合です。 たとえば、次の場合$k=2$そして$b_p=3$の場合、どの状態も制約を満たすことができません`sum(cnt) == b_p`、DP はすべての構成を即座に削除し、出力 0 を生成します。 

3 番目の微妙なケースは、間隔の重複により寄与が遅延する場合です。 列での単一のアクティベーション$c$まで影響する可能性があります$k$したがって、正確性はアクティブな総数だけではなく、残りの長さのベクトル全体を維持することに依存します。 DP 状態はこの減衰を明示的に追跡し、長距離の依存関係があいまいなく正しく処理されることを保証します。
