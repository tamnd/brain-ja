 ## 問題の理解

 2 つの非常に大きな整数が与えられました$l$そして$r$、10 進数の文字列として書かれており、その範囲に含まれる整数の数を数える必要があります。$[l, r]$特殊な数字のプロパティを満たします。 

数値は、その 10 進数のすべての桁の積が素数である場合に有効であるとみなされます。 素数には非常に制限があるため、この条件により数値の桁構造が高度に制限されます。 タスクは、指定された間隔内に有効な数値がいくつあるかをカウントすることです。 

この制約により、入力を組み込みの整数型に変換できないことが明らかになるため、すべての演算は文字列に対して実行する必要があります。 範囲の長さは最大です$10^{100000}$したがって、どのような解決策も、桁数においてほぼ直線的な時間で機能する必要があります。 

素朴なアプローチは、次のすべての数値を反復処理することです。$[l, r]$、数字の積を計算し、素数性をテストします。 たとえ桁の乗算が安価であっても、範囲のサイズによりこれは不可能です。 

微妙な特殊ケースの 1 つは、数字の 0 を含む数値です。 たとえば、数値 105 にはすぐに桁積 0 が含まれますが、これは素数ではありません。 もう 1 つの特殊なケースは、111 や 1 など、1 のみで構成される数値であり、積は 1 であり、これも素数ではありません。 これらの失敗は、有効な数値が単に数値的に制約されているだけでなく、構造的に非常にまれである必要があることを示しています。 

最後のエッジケースは 1 桁の数字です。 たとえば、2、3、5、および 7 は、それらの数字の積が素数であるため、有効です。 対照的に、4、6、8、および 9 は、その桁の積が素数ではないため無効です。 

## アプローチ

 ブルートフォース ソリューションでは、次のすべての数値がスキャンされます。$l$に$r$、それを数字に変換し、数字の積を計算し、それが素数であるかどうかを確認します。 積が急速に増大することに注意して素数検査を最適化したとしても、範囲内の整数の数は膨大になる可能性があり、アプローチは基本的に区間のサイズにおいて線形です。 潜在的に最大数を持つ数字$10^5$数字ごとに 1 回繰り返すことさえ不可能です。 

重要な観察は、数字の積が素数であることが何を意味するかを分析することから得られます。 素数には素因数が 1 つだけあります。 すべての数字は小さな素数のみを提供します$2, 3, 5, 7$、そして合成数字はすぐに複数の素因数を導入します。 数字 0、1、4、6、8、9 はすべて、余分な要素を導入するか、素数性を完全に破壊します。 これにより、有効な数値にはセット内の 1 桁だけが含まれるようになります。$\{2, 3, 5, 7\}$、他のすべての数字は 1 でなければなりません。0 の出現は禁止されています。 

この構造の崩壊により、問題は任意の算術から制約された桁パターンの計数問題に縮小されます。 数値を反復する代わりに、範囲内の単純な条件を満たす数字の文字列がいくつあるかを数えます。これは数字の動的プログラミングに適しています。 

関数を定義します$f(x)$以下の有効な数値をカウントします。$x$、最終的な答えを次のように計算します。$f(r) - f(l - 1)$, where subtraction is performed on big integers represented as strings.

 ## アルゴリズムのチュートリアル

 The problem reduces to counting numbers whose decimal representation contains exactly one digit from$\{2, 3, 5, 7\}$、数値の開始後にゼロは含まれず、他のすべての桁は 1 に等しくなります。 

上限の文字列表現に対して数字 DP を使用します。 

1. 位置に対する DP 状態、厳しい制約、番号を開始したかどうか、および特殊な素数をすでに使用したかどうかを定義します。 位置は、どの桁を配置しているかを追跡します。 タイト フラグにより​​、境界のプレフィックスを超えないことが保証されます。 開始済みフラグにより​​、先頭のゼロが無視されます。 used フラグにより​​、特殊な数字が 1 つだけ選択されることが保証されます。 
2. 各位置で、0 から 9 までのすべての数字を試しますが、無効な遷移は早期に削除されます。 すでに数字が始まっている場合、数字の積が 0 になるため、数字 0 は禁止されます。 開始する前に、先頭のパディングを表すためにゼロを使用できます。 
3. 数字を配置すると、開始フラグが更新されます。 開始されていないときにゼロ以外の数字を配置すると、数字はこの位置から始まります。 
4. に数字を入れた場合にのみ使用済みフラグを更新します。$\{2, 3, 5, 7\}$。 2 番目のそのような数字を配置しようとすると、遷移は無効になります。 
5. 1 に等しい数字は使用フラグに影響せず、数字の開始後に常に許可されます。 
6. DP は、すべての有効な補完のカウントを累積し、最後に、数値が開始され、特殊な数字が 1 つだけ使用されている状態のみを受け入れます。 
7. 範囲の答えを計算するには、次のように評価します。$f(r)$そして引きます$f(l - 1)$ここで、大きな整数文字列のデクリメントは個別に処理されます。 

正確さは、すべての DP 状態が固定構造分類による境界の有効なプレフィックスの数を正確に表すという不変条件から得られます。つまり、数値が開始されているかどうか、およびその単一の許容される 1 以外の数字がすでに配置されているかどうかです。 すべての無効な数字の選択はローカルに除外されるため、無効な数字は決して構築できません。また、この DP ではすべての有効な数字が 1 つの表現を持つため (先頭のゼロが強制されるため、あいまいさがなくなります)、カウントは正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def dec_str(s: str) -> str:
    s = list(s)
    i = len(s) - 1
    while i >= 0 and s[i] == '0':
        s[i] = '9'
        i -= 1
    if i >= 0:
        s[i] = str(int(s[i]) - 1)
    # strip leading zeros
    res = ''.join(s).lstrip('0')
    return res if res else "0"

def solve(x: str) -> int:
    n = len(x)
    primes = {'2', '3', '5', '7'}

    @lru_cache(None)
    def dp(pos: int, tight: int, started: int, used: int) -> int:
        if pos == n:
            return 1 if started and used == 1 else 0

        limit = int(x[pos]) if tight else 9
        res = 0

        for d in range(limit + 1):
            nd = str(d)

            ntight = 1 if (tight and d == limit) else 0

            if not started:
                if d == 0:
                    res += dp(pos + 1, ntight, 0, used)
                else:
                    if nd in primes:
                        res += dp(pos + 1, ntight, 1, 1)
                    elif nd == '1':
                        res += dp(pos + 1, ntight, 1, 0)
            else:
                if d == 0:
                    continue
                if nd in primes:
                    if used:
                        continue
                    res += dp(pos + 1, ntight, 1, 1)
                elif nd == '1':
                    res += dp(pos + 1, ntight, 1, used)
                else:
                    continue

        return res

    return dp(0, 1, 0, 0)

def main():
    l = input().strip()
    r = input().strip()

    def less_or_equal(a, b):
        if len(a) != len(b):
            return len(a) < len(b)
        return a <= b

    if l == "0":
        left_val = 0
    else:
        left_val = solve(dec_str(l))

    right_val = solve(r)
    print(right_val - left_val)

if __name__ == "__main__":
    main()
```DP は、数値が始まっているかどうかを追跡することに重点を置いています。そうでないと、先行ゼロによって同じ整数の複数の表現が作成されてしまうからです。 移行ルールでは、主要な構造制限が適用されます。次のとおりです。$\{2,3,5,7\}$、数字が始まるとゼロは付きません。 

数字 DP は自然に数値をカウントするため、減算ステップが必要です。$[0, x]$, 一方、問題は閉じた間隔を求めています。

 ## 特殊なケース

 次のような入力の場合$l = 1, r = 1$の場合、DP は素数を使用しないため番号を正しく拒否し、終了時に使用済みフラグは 0 のままになります。 

次のような入力の場合$l = 2, r = 2$の場合、数字 2 は素数であり、その数字は正確に 1 つの制約を満たすため、DP はすぐに受け入れます。 

101 などのゼロを含む数値を含む範囲の場合、数値の開始後にゼロを配置しようとする遷移は拒否され、無効な製品がカウントされなくなります。 

次のような大きな均一文字列の場合$111\ldots111$の場合、DP はすべての桁を調べますが、使用済みフラグを設定することはなく、1 の桁制限を満たしている場合でもこれらの桁が確実に除外されます。
