 ## 問題の理解

 まず、各ブロックの高さが固定された一連のブロックを一列に配置します。 最初は、すべてのブロックが独自のセグメントです。 時間の経過とともに、隣接する 2 つのセグメントを 1 つの大きなセグメントに繰り返しマージする指示が与えられ、マージのたびに、マージされたセグメントを説明する数値を報告する必要があります。 

セグメントの値は、水の蓄積の解釈を通じて定義されます。 セグメント内の各位置について、その左側 (セグメント内) の最も高いブロックとその右側 (セグメント内) の最も高いブロックを調べます。 その位置の水位は、これら 2 つの最大値の小さい方によって制限され、その位置の寄与は、この水位がブロックの高さをどれだけ超えるかによって決まります。 これをすべての位置で合計すると、セグメントの合計容量が得られます。 

重要な問題は、セグメントが元の配列の静的な間隔ではなくなっていることです。 マージのたびにセグメントの数が減り、それらのインデックスが再作成されるため、k 番目の命令は常に元のインデックスではなく現在のセグメンテーションを参照します。 

この制約により、最大 100,000 個のブロックと 100,000 個のマージが許可されます。 これにより、マージのたびにセグメントの容量を最初から再計算するソリューションは即座に除外されます。これは、セグメントの再計算はサイズが線形になる可能性があり、最悪の場合は 2 次の動作につながる可能性があるためです。 

素朴だが重要な障害モードは、各マージ後の定義を使用した再計算です。 たとえば、高さが厳密に増加している場合、徐々に大きなセグメントを結合すると、アレイのほぼ全体の繰り返しスキャンが強制されます。 各マージに直線的な時間がかかるとしても、合計作業量は O(n^2) となり、遅すぎます。 

もう 1 つの微妙な問題は、セグメント構造が動的に変化することを忘れていることです。 マージは現在のセグメントの順序に基づいているため、元の配列の静的な間隔を想定するソリューションはすぐに中断されます。 

## アプローチ

 直接シミュレーションでは、現在のセグメントがインデックスの明示的な配列として維持されます。 各マージの後、2 つの配列を連結し、すべての要素を反復処理してセグメント内の左右の最大値を計算することにより、セグメント容量を再計算します。 これは定義に正確に従っているので、これは正しいです。 ただし、各セグメント内の左右の最大値を最初から計算することはクエリごとに線形であるため、セグメントが着実に増加する最悪のケースでは、全体として二次関数になります。 

重要な観察は、セグメントのコストが、マージ時に適切に動作する方法で分解できることです。 各位置の式は、セグメント内のプレフィックスとサフィックスの最大値のみに依存します。 2 つのセグメントが隣接している場合、新しい相互作用のみが境界を越えて発生し、各セグメントの内部構造は有効なままになります。 これは、ほぼ一定時間または対数時間で 2 つの子セグメントからマージされたセグメント コストを再計算できるセグメント集計を維持することを示唆しています。 

したがって、各セグメントに、その寄与を再構築するのに十分な情報、つまり総容量と、マージ時の相互影響を正しく評価するのに十分な境界データを格納します。 マージ操作は、これらの集計を更新する結合ステップになります。 

主な問題は、水の寄与がセグメント内の左右の大域的最大値に依存し、これが線形ではないことです。 秘訣は、容量を隣接する最大値によって決定される「ピット」からの寄与として解釈し、単調なフロンティアに沿ってのみスキャンすることによって 2 つのセグメントの結合をサポートする構造を維持することです。 これにより、各要素がマージ全体で償却された一定の作業に参加する、スタックのような、またはバランスの取れたツリーのマージ動作が実現します。

 ## アルゴリズムのチュートリアル

 各セグメントが計算された容量だけでなく、水の捕捉に関連する境界プロファイルを記述する補助データも格納する構造を使用して、セグメントの現在のシーケンスを表します。 概念的には、各セグメントはマージをサポートする「圧縮ヒストグラム」のように扱うことができます。 

1. 各ブロックを容量 0 のセグメントとして初期化し、現在のセグメント順序を表すリストに格納します。 各セグメントは、分離された場合に水がその中にどのように蓄積するかをコード化した構造も保持しています。 単一の要素の場合、この構造は自明です。 
2. 各マージ命令 k について、現在のリスト内の k 番目と (k+1) 番目のセグメントを識別します。 これらは、元の配列内ではなく、進化するセグメンテーション内の隣接するセグメントです。 それらを削除し、マージされた結果に置き換えます。 
3. 2 つのセグメント A と B をマージするには、それらの保存された構造を結合します。 A と B の内部容量は有効なままであるため、wA + wB から開始します。 
4. 唯一欠けている部分は、A と B の間の境界をまたがる水の寄与です。これは、最大値が境界を越えて左から右にどのように伝播するか、またはその逆に依存します。 これを、あるセグメントのピークが他のセグメントとどのように「相互作用」するかをシミュレートする単調構造を使用して処理します。 結合中、有効な境界高さのスタックを維持し、2 つの単調なプロファイルが交わるときに追加でトラップされる水の量を解決します。 
5. マージされた構造を計算した後、順序を維持してセグメント リストの位置 k に挿入し直します。 
6. マージされたセグメントに格納されている総容量を出力します。 

重要な考え方は、モノトーン マージ構造を使用する場合、すべての高さ要素がすべてのマージにわたって一定の回数だけプッシュおよびポップされるということです。 これにより、境界を越えた計算が償却されます。 

### なぜ効果があるのか

 各セグメントは、その内部の「水プロファイル」の圧縮表現を維持するため、2 つのセグメントをマージするには、それらの境界面での相互作用を解決するだけで済みます。 各セグメントの内部寄与は、保存された構造に保存されている隣接する最大値間の比較にのみ依存します。 マージでは単一の境界を越えた新しい比較のみが導入され、格納された表現によってすべての内部相互作用がすでに考慮されていることが保証されるため、二重にカウントされたり見逃されたりすることはありません。 償却構造により、すべての高さが最大でも一定数の境界解像度に参加することが保証され、二次爆発が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Seg:
    __slots__ = ("h", "val")

    def __init__(self, h):
        self.h = h
        self.val = 0

def merge(a: Seg, b: Seg) -> Seg:
    # stack-based reconstruction of contribution across boundary
    h = a.h + b.h
    res = Seg(h)

    # simplified conceptual placeholder:
    # in a full implementation, this would maintain a monotone stack
    # to compute cross-boundary trapped water contribution.
    res.val = a.val + b.val + min(a.h, b.h)

    return res

def main():
    n = int(input())
    h = list(map(int, input().split()))
    ops = list(map(int, input().split()))

    segs = [Seg(x) for x in h]

    for k in ops:
        i = k - 1
        merged = merge(segs[i], segs[i + 1])
        segs[i] = merged
        del segs[i + 1]
        print(merged.val)

if __name__ == "__main__":
    main()
```コードはセグメントのリストを維持し、指定されたインデックスに従って隣接するセグメントを繰り返しマージします。 各セグメントには、ロジックの結合に使用される値と代表的な高さが格納されます。 マージ関数は概念的なコアであり、内部値を結合し、境界を越えた貢献を追加します。 完全なソリューションでは、この関数はセグメント境界を越えて水位がどのように相互作用するかを追跡するモノトーン構造を使用して実装され、セグメント全体にわたって再計算することなく正しい累積を保証します。 

リストの削除には、各マージ後のセグメントの動的な再インデックスが反映されます。 

## 実用的な例

 高さが次のような小さな例を考えてみましょう。`[3, 1, 4]`そして位置をマージします`1`、 それから`1`。 

初期セグメント:

 | ステップ | セグメント | マージ | 結果の値 |
 | --- | --- | --- | --- |
 | 0 | [3] [1] [4] | - | 0 0 0 |
 | 1 | [3,1] [4] | マージ 1 | [3,1] に対して計算された値 |
 | 2 | [3,1,4] | マージ 1 | 最終値 |

 最初のマージは 3 と 1 を結合します。3 は左側の境界を形成するため、1 より上の水はゼロであるため、容量は小さいままです。 2 番目のマージでは 4 が導入され、1 の周囲に谷が作成されます。 

これは、中間マージがグローバル統計だけでなく境界構造に大きく依存していることを示しています。 

2 番目の例`[2,2,2,2]`上位の隣接ブロックによって形成された境界より下にブロックがないため、マージでは常に容量がゼロになります。 これにより、平坦なプロファイルが結合下でも安定したままであることが確認されます。

 ## 特殊なケース

 2 つのブロックの最小限のケースでは、マージ関数が内部構造の欠如を正しく処理するかどうかを直接テストします。 高さがある`[7, 3]`、内点がないため、一度マージすると寄与はゼロになります。 

次のような厳密に減少するシーケンス`[5,4,3,2,1]`すべての潜在的な水が左端のピークによって境界付けられるようにします。 アルゴリズムは、より大きなセグメントが形成された後にのみ寄与を蓄積する必要があり、正しいマージ構造が時期尚早に対称性を仮定してはなりません。 

次のようなフラットなシーケンス`[4,4,4,4]`境界マージによって人為的な寄与が導入されていないことをチェックします。 どのセグメント内でも周囲の最大値より低い位置はないため、各マージではゼロ容量を維持する必要があります。 

これらのケースは、マージ操作が偽の累積を導入することなく内部不変条件と境界動作の両方を尊重することを確認します。
