 ## 解決策
 ## 問題の理解

 正確に実行されるプロセスが与えられています$X$分。 最初は電球が点灯しています。 ジョーは毎分、電球を切り替えるか、正確に続くスリープ段階に入らなければなりません$L$分。 スリープ中は電球には何も起こらず、時計は通常どおり進みます。 追加の構造上の制約があります。すべての分を「使用」する必要があります。つまり、トグル アクションまたはスリープ アクションのいずれかが各ステップで消費され、スリープではブロック全体が消費されます。$L$連続した分。 

スリープを選択すると次の睡眠がコミットされるという意味で、スリープはアトミックです。$L$電球が完全に非アクティブになるまでの時間は数分であり、たとえそれが複数分にわたる場合でも、出力では 1 つの決定としてカウントされます。 目標は、正確に続く有効なトグルとスリープのシーケンスが存在するかどうかを判断することです。$X$分が経過し、電球がオンの状態で終了します。 このようなシーケンスが存在する場合は、トグルの数とスリープ セグメントの数を出力する必要があります。 

主な問題点は、スリープは時間を大量に消費するのに対し、トグルは 1 分を消費し、そのたびに状態が切り替わることです。 これにより、トグルのパリティとタイムラインのどの程度がスリープ ブロックによって占有されるかの間に組み合わせの制約が作成されます。 

制約は大きく、最大で$10^5$テストケースと最大値$10^9$したがって、どのような解決策であっても、次のようにする必要があります。$O(1)$またはテストケースごとの償却定数。 分ごとにシミュレーションするアプローチは直ちに不可能です。 

微妙なエッジケースは、パリティと実現可能性の相互作用から発生します。 たとえば、次の場合$L = 5$そして$X = 5$、一度スリープするか、切り替えを試みることができます。 1 回スリープすると切り替えがゼロになり、同じ状態で終了するため、有効です。 しかし、もし$X = 5$5 回切り替えを試みると、電球はオフになるため、これは無効です。 多くの誤った解決策は、次のことを確認するだけでは失敗します。$X$の線形結合として表すことができます$1$そして$L$、トグルのパリティを無視します。 

もう 1 つの失敗ケースは、パリティを考慮せずにスリープの貪欲な減算が試行された場合に発生します。スリープが多すぎると、トグルに不可能な残留パリティが強制される可能性があります。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべてのアクション シーケンスを検討します。$X$分。各分は、トグルまたは一定の長さのスリープ ブロックの開始のいずれかです。$L$。 これは、タイムラインのすべてのパーティションをサイズ 1 (トグル) とサイズ 2 のセグメントに探索することと同等です。$L$（寝る）。 各位置で 2 つの選択肢に分岐し、睡眠が複数の段階にジャンプするため、これはすぐに指数関数的になります。 

簡素化は、プロセスをカウントに圧縮することで実現します。 を使用するとします$N$睡眠セグメント。 彼らは消費する$N \cdot L$分。 残り時間はトグルで埋められるため、トグルの数は$M = X - N \cdot L$。 これにより直ちに強制的に$M \ge 0$。 

残る唯一の条件は、電球の最終状態です。 トグルごとに電球が切り替わり、ON から開始します。$M$次の場合に限り、電球をオンに切り替えます。$M$は均等です。 したがって、問題全体は、非負の整数を見つけることに帰着します。$N$そのような$X - N L \ge 0$そして$X - N L$は均等です。 

これは単純なモジュール式制約です。 あらゆるものを検索します$N$満足のいく$X \equiv NL \pmod{2}$。 重要なのはパリティのみであるため、すべてを 2 を法として削減します。$L$偶数であれば、$NL$常に偶数なので、$X - NL$と同じパリティを持っています$X$。 つまり、必要があるのです$X$平。 もし$X$奇妙、不可能です。 もし$X$均等です、私たちは取ることができます$N = 0$そして$M = X$。 

もし$L$それは奇妙です、それでは$NL \equiv N \pmod{2}$。 だから必要なのです$X - N \equiv 0 \pmod{2}$、つまり$N \equiv X \pmod{2}$。 実現可能なものはどれでも選択できます$N$範囲内$0 \le N \le X / L$一致するパリティ付き。 もし$X / L$十分な大きさです、そのような$N$範囲が小さすぎてパリティ調整に対応できない場合を除いて、常に存在します。 

可能な限り大きいものを選択します$N = \lfloor X/L \rfloor$パリティを修正するには、最大 1 ずつ下方調整します。 次に計算します$M = X - NL$。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理し、有効なペアを構築します$(M, N)$。 

1. 完全なスリープ ブロックがいくつ収まるかを計算します。$X$、設定$N = \lfloor X / L \rfloor$。 これにより、時間を超過することなくスリープの可能な最大数が得られます。 
2. を使用しているかどうかを確認します$N$スリープすると有効なトグル数が得られます$M = X - N \cdot L$。 もし$M \ge 0$かどうかを確認するだけで済みます。$M$は均等です。 
3. もし$M$が偶数である場合、出力します$(M, N)$直接。 プロセスは時間どおりに終了するため、これは機能します$X$、パリティ条件により電球が確実にオンになります。 
4. もし$M$それは奇妙です、私たちは削減しようとします$N$1 までに提供される$N > 0$。 これはパリティを反転します$M$いつ$L$は奇数であり、まだ合計時間内に収まっているため、実現可能性は保たれています。 
5. デクリメント後の場合$N$私たちはまだ得ています$M < 0$の場合、解決策は存在しません。 これは、単一の有効なスリープ調整でも時間とパリティの両方の制約を満たすことができない場合に対応します。 
6. 調整がうまくいかない場合は、出力します。$-1 -1$。 

スリープはバルブ状態を反転しない唯一のメカニズムであるため、この構造では常に最初にスリープの使用量を最大化しようとします。 その後、トグルは残りの時間を埋めるように強制されるため、実際の制約はパリティだけになります。 

### なぜ効果があるのか

 システム全体は 2 つの不変条件に分割されます。合計消費時間は等しくなければなりません。$X$、電球の状態はトグル数のパリティのみに依存します。 スリープは状態には影響しませんが、固定チャンクの時間に影響します。 有効なスケジュールはすべてペアに一意に対応します$(M, N)$、そのようなペアは状態に依存しないセグメントであるため、すべてのスリープを最初に配置するか任意の順序で配置することによって有効なスケジュールを決定します。 このアルゴリズムは、重要な自由度、つまり相互間のパリティ互換性のみを検索します。$X - NL$そしてゼロ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        L, X = map(int, input().split())

        n = X // L
        m = X - n * L

        if m % 2 == 0:
            out.append(f"{m} {n}")
            continue

        if n > 0:
            n -= 1
            m = X - n * L
            if m >= 0 and m % 2 == 0:
                out.append(f"{m} {n}")
                continue

        out.append("-1 -1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、できるだけ多くのスリープ ブロックを取得し、必要に応じて 1 つのスリープを減らすことでパリティを修正するという貪欲な選択を直接実装しています。 重要な詳細は、調整後の残りのトグル数を再計算することです。$N$、スリープ数を変更すると残り時間が変更され、したがってトグルのパリティが変更されるためです。 

すべての演算はテスト ケースごとに一定時間であり、大きな制約を考慮するとこれが必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    res = []
    for _ in range(T):
        L, X = map(int, input().split())
        n = X // L
        m = X - n * L

        if m % 2 == 0:
            res.append(f"{m} {n}")
        else:
            if n > 0:
                n -= 1
                m = X - n * L
                if m % 2 == 0 and m >= 0:
                    res.append(f"{m} {n}")
                else:
                    res.append("-1 -1")
            else:
                res.append("-1 -1")

    return "\n".join(res)

# sample-like checks
assert run("1\n4 10\n") == "2 2"
assert run("1\n5 5\n") == "0 1"

# edge: minimal
assert run("1\n1 1\n") == "1 0"

# parity impossible
assert run("1\n2 1\n") == "-1 -1"

# large simple
assert run("1\n3 1000000000\n")  # just sanity run

 ## 特殊なケース

 いつ$X < L$、スリープは不可能であり、解決策は完全にトグルに依存する必要があります。 アルゴリズムは正しく設定します$N = 0$、作る$M = X$、パリティを直接チェックします。 もし$X$が奇数の場合、電球がオフになってしまうため、このケースは正しく拒否されます。 

いつ$L = 1$、すべてのスリープは、時間粒度の点でノーオペレーションと同等であり、問​​題は、どれだけのスリープを選択するかということになります。$X$分はスリープとトグルとして扱われます。 パリティ条件は依然として実現可能性を支配しており、貪欲な調整は$N$自然に処理します。 

いつ$X$は非常に大きく、次で割り切れます。$L$、アルゴリズムは最初に最大化します$N$、その後、最大 1 ステップで調整するだけで、複数の候補に対する反復を必要とせずに正確性が保証されます。
