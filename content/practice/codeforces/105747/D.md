 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、少なくとも 2 つの長さの連続するすべての部分配列を調べるように求められます。 このような各サブ配列について、そのサイズとその 2 つの最小要素に基づいて値を計算します。 具体的には、部分配列の場合、その長さを取得し、その長さに、その中の最小値と 2 番目に小さい値の合計を乗算します。 タスクは、すべての有効な部分配列にわたってそのような最大値を見つけることです。 

したがって、問題は合計クエリやプレフィックス クエリに関するものではなく、すべての間隔内の小さな要素のペアを識別し、それを間隔の長さと組み合わせることにあります。 この難しさは、すべての部分配列がその内部順序統計に依存しており、2 番目の最小値が必要であるという事実から来ていますが、これはすでに標準範囲の最小値の問題よりも微妙です。 

入力サイズの制約は、すべてのテスト ケースにわたる要素の合計数が最大 200,000 であることを意味します。 すべての部分配列を列挙しようとするソリューションでは、およそ N 個の 2 乗の候補が考慮されます。これは、最悪の場合で約 4 × 10^10 の演算に相当し、完全に実行不可能です。 O(N^2 log N) アプローチですら遅すぎます。 

より微妙な制約は、答えがすべての間隔にわたるグローバルな最大値に依存するということです。そのため、位置ごとに答えを列挙する必要はなく、すべての最適な間隔形状が考慮されることを確認するだけです。 これは多くの場合、単調な構造、または「重要な」間隔のみを考慮することへの縮小を示しています。 

単純な間違いは、最良の部分配列が常に大域的最小値を含むものであると仮定することです。 この式は、選択した範囲内の最小値と 2 番目の最小値の両方に依存するため、これは false です。 もう 1 つの微妙な失敗は、サブ配列を拡張すると常に最小ペアの寄与が減少すると仮定することです。値は同じままですが、乗算の長さが増加するため、これは必ずしも当てはまりません。 

具体的な反例は次のとおりです。 

配列: [5、1、4、2]

 部分配列 [1, 4, 2] は長さ 3 で、その 2 つの最小値は 1 と 2 で、3 × 3 = 9 となります。 

しかし、部分配列 [1, 4] は 2 × 5 = 10 を与えます。これは、より短く、同じ 3 番目の要素が含まれていないにもかかわらず、より大きくなります。 したがって、最適な間隔は必ずしも最大値であるわけではなく、全体的な最小値を中心とするものでもありません。 

これは、単なる最小値ではなく、範囲内の 2 番目の最小値がどこで形成されるかを注意深く追跡する必要があることを示しています。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのサブ配列をチェックし、それをスキャンして最小値と 2 番目に小さい値を見つけて、スコアを計算します。 各サブ配列のスキャンには O(N) がかかり、O(N^2) 個のサブ配列があるため、テスト ケースごとに O(N^3) になります。 2 つの最小値を維持するためにデータ構造を使用してスキャンを改善しても、合計は O(N^2) になりますが、テスト全体で N が 2 × 10^5 に達した場合でも、これはまだ大きすぎます。 

重要な観察は、任意の間隔の観点から考えるのをやめ、代わりに 2 番目の最小値がどのように動作するかを考えることです。 どの部分配列でも、2 番目の最小値は、その区間内の 2 つの特定の要素、つまり同じ区間内の最小要素とそれより厳密に大きい最小要素によって決まります。 これは、2 番目に小さい要素を固定的に選択する場合、内側に小さい要素が存在できる境界値となる範囲を見つけるだけでよいことを示唆しています。 

これをより構造化して考える方法は、部分配列内の 2 番目の最小要素の位置を固定することです。 選択した区間内で 2 番目に小さい値の位置としてインデックス j を選択するとします。 次に、最小値は j のいずれかの側から取得され、厳密に A[j] より小さくなければなりませんが、区間内の他のすべての要素は少なくとも A[j] でなければなりません。 これにより、区間の境界が即座に制限されます。A[j] より小さい要素に到達するまで左右に拡張します。そのような要素は、A[j] が 2 番目の最小値であるという条件に違反するためです。

この制約されたセグメント内では、A[j] を 2 番目の最小値として使用する最適な部分配列が、セグメント内の最小値とペアになります。長さを最大化したいため、A[j] が 2 番目に小さいという制約を維持しながら、可能な限り拡張します。 

これにより問題は、インデックス j ごとに、A[j] より小さい要素が拡張をブロックしない最も遠い有効な間隔を見つけ、同時にその間隔内に A[j] より小さい要素が少なくとも 1 つ存在することを確認するというものになります。 2 番目の要件は、j の両側に最も近い小さな要素も必要であることを意味します。 

この構造は、各位置について、左右に最も近い厳密に小さい要素を計算する単調スタックを使用して自然に処理されます。 これらの境界は、A[j] が 2 番目に小さい位置の最小候補である最大セグメントを定義します。 そのセグメント内で、最小値に対する最適なパートナーは、A[j] よりも厳密に小さいセグメント内の最小の要素です。これは、必要に応じてプレフィックス/サフィックスの前処理またはセグメント ツリー クエリを使用して追跡できます。 

これらの観察により、サブ配列を列挙することはなくなりました。 代わりに、各インデックスを潜在的な「2 番目の最小アンカー」として評価し、償却定数時間でその周囲の最適な間隔を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3) | お(1) | 遅すぎる |
 | 最適 (単調 + 境界拡張) | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての位置 j について、A[j] を最適な部分配列の 2 番目に小さい値の候補として解釈します。 これは、すべての間隔を列挙することを避ける構造的なピボットです。 
2. j の左側および j の右側で最も近い厳密に小さい要素を計算します。 これらの位置は、A[j] が意図した構造の外側の小さな要素によって無効にされることなく 2 番目の最小値として機能できる最大間隔を定義します。 
3. j の有効ウィンドウを、最も近い 2 つの小さい要素間の間隔として定義します。 このウィンドウ内では、j を含み、A[j] よりも小さい要素が少なくとも 1 つ含まれるサブ配列は、潜在的に A[j] を 2 番目の最小値として使用できます。 
4. このウィンドウ内で、A[j] より厳密に小さい最小の要素を特定します。 この要素は部分配列の最小値として機能します。2 番目の最小値は A[j] に固定されているため、最適なパートナーは最小の有効な候補になります。 
5. (ウィンドウの長さ) に (最小の有効な要素 + A[j]) を乗算して候補の答えを形成し、グローバル最大値を更新します。 
6. 少なくとも 1 つの小さな要素を含む有効なウィンドウのみが考慮されるように注意しながら、すべての j に対してこれを繰り返します。 

これが機能する理由は、最適な部分配列には明確に定義された 2 番目に小さい要素が必要であり、その要素を固定することで、2 番目の最小の単位を変更するより小さな値を導入することなく、部分配列がどこまで拡張できるかを一意に決定できるためです。 単調スタック境界により、そのようなすべての有効な構成が 2 番目の最小アンカーまで 1 回だけ考慮され、この構成ではすべてのサブ配列に 2 番目に小さい要素として機能する位置が 1 つだけ存在するため、有効な間隔が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # nearest smaller to left
    left = [-1] * n
    st = []
    for i in range(n):
        while st and a[st[-1]] >= a[i]:
            st.pop()
        left[i] = st[-1] if st else -1
        st.append(i)
    
    # nearest smaller to right
    right = [n] * n
    st = []
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] > a[i]:
            st.pop()
        right[i] = st[-1] if st else n
        st.append(i)
    
    # prefix minimums
    pref = [10**18] * n
    cur = 10**18
    for i in range(n):
        cur = min(cur, a[i])
        pref[i] = cur
    
    # suffix minimums
    suff = [10**18] * n
    cur = 10**18
    for i in range(n - 1, -1, -1):
        cur = min(cur, a[i])
        suff[i] = cur
    
    ans = 0
    
    for j in range(n):
        l = left[j] + 1
        r = right[j] - 1
        
        if r - l + 1 < 2:
            continue
        
        # smallest element in [l, r] excluding A[j]
        best_min = min(pref[r], suff[l])
        if best_min >= a[j]:
            continue
        
        length = r - l + 1
        ans = max(ans, length * (best_min + a[j]))
    
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、単調スタックを使用して最も近い小さな境界を計算することから始まります。 これらの境界により、各セグメント内で、選択したアンカー A[j] よりも小さい要素が区間の外側に現れないことが保証されるため、A[j] は安全に 2 番目の最小候補として機能できます。 

次に、プレフィックスとサフィックスの最小値を使用して、一定時間内にセグメント内の最小要素をクエリします。 これにより、セグメント ツリーの必要性が回避され、同時に各アンカーの最適なパートナーを効率的に抽出できるようになります。 

各インデックスは 2 番目の最小値の候補として扱われ、その最大有効間隔が 1 回評価されます。 最終的な答えは、そのようなすべての構成にわたる最高のスコアを集計したものです。 

## 実用的な例

 配列 [5, 1, 4, 2] について考えてみましょう。 

j = 2 (値 4) の場合、最も近い小さい境界は l = 1 および r = 3 になります。セグメントは [1, 4, 2] です。 このセグメントの最小要素は 1 で、2 番目に最小の候補は 4 です。値は 3 × (1 + 4) = 15 になります。 

j = 3 (値 2) の場合、境界は l = 1 および r = 3 を与えます。セグメントは [1, 4, 2] です。 最小要素は 1 のままなので、値は 3 × (1 + 2) = 9 になります。 

| j | A[j] | セグメント | セグメント内の最小値 | 長さ | スコア |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 4 | [1,4,2] | 1 | 3 | 15 |
 | 3 | 2 | [1,4,2] | 1 | 3 | 9 |

 最大値は 4 を 2 番目の最小アンカーとして固定することで得られ、2 番目の最小位置が最適な構造をどのように制御するかを示しています。 

2 番目の例は [2, 2, 2] です。 長さが少なくとも 2 のすべてのサブ配列には、最小値と 2 番目の最小値が 2 に相当します。最良のサブ配列は、3 × (2 + 2) = 12 を与える完全な配列であり、すべての位置が対称的に動作するため、これは任意のアンカーによってキャプチャされます。

 ## 特殊なケース

 微妙なケースは、すべての要素が厳密に増加している場合です。 [1, 2, 3, 4] では、2 番目の最小値は常に、選択した区間内で 2 番目に小さい値であり、左側の境界から来る傾向があります。 単調スタックにより、各位置が引き続き有効なセグメントを取得できるようになり、プレフィックスの最小値によって最小のパートナーが正しく識別されます。 

もう 1 つのケースは、重複が存在する場合です。 [3, 3, 1, 3] では、等しい要素が「厳密に小さい」仮定に干渉する可能性があります。 スタック構築で非厳密な比較を使用すると、等しい値が 2 番目の最小順序に違反するセグメントを誤って展開することがなくなります。 

境界ケースは、選択したアンカーに対して有効なパートナーが存在しない場合、つまりセグメント内のすべての要素がそれ以上であるか等しい場合に発生します。 そのような状況では、小切手`best_min >= a[j]`構成を正しく破棄し、無効なサブ配列が答えに寄与するのを防ぎます。
