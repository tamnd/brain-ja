 ## 解決策
 ## 問題の理解

 1週間に何日でも入るカレンダーがあります。`1`に`r`。 選択した週の長さに対して`k`、カレンダーは次の行として描画されます。`k`細胞。 絵を描きます`n`連続した日を観察して、それらの細胞が形成する接続された形状を観察します。 2 つの絵画は、回転したり形状を変更したりせずに、一方を移動して他方の絵画に重なることができる場合、同一とみなされます。 

タスクは、可能なすべての週の長さを試した後、接続された異なる図形が何個現れるかを数えることです。`1`に`r`。 

制約により許可されるのは、`n`そして`r`と同じくらい大きくなる`10^9`。 可能なすべての週の長さにわたるシミュレーションは不可能です。`10^9`値の処理はすでに遅すぎるため、カレンダーのセルを構築するにはさらに多くの作業が必要になります。 解決策は、問題を一定数の算術演算に減らす必要があります。 

難しいのは、週の長さが異なると実際に異なる形状がいつ生じるかを理解することです。 よくある間違いは、考えられるすべての開始位置や週の長さによって常に新しい形状が得られると想定することです。 それは多くのケースを超えています。 

考慮する`n = 3, r = 4`。 正しい答えは、`4`。 1週間程度の場合`1`、`2`、`3`、 そして`4`、可能な形状は 4 つあります。 考えられるすべての開始セルをカウントする不用意なアプローチでは、複数の開始セルが同じ変換された形状を生成するため、カウントがさらに大きくなります。 

もう 1 つの特殊なケースは、週の長さが少なくともペイントされた日数である場合です。 例えば、`n = 3, r = 5`そして`k = 5`。 ペイントされた 3 つのセルは、開始位置に関係なく、常に 1 行に配置されます。 この一週間の長さがもたらす答えはたった一つの形です。 すべての開始位置をカウントすると、誤って 5 つの図形が追加されてしまいます。 

最小のケースも重要です。 のために`n = 1`、すべての有効なカレンダー幅で、まったく同じ単一セルの形状が生成されます。 答えは`1`、 ない`r`。 

## アプローチ

 直接的なアプローチは、考えられるすべての週の長さを調べることです`k`。 それぞれについて`k`、その週のすべての開始位置を試して、結果として得られるペイントされたセルのセットを構築し、それを以前に確認した形状と比較できます。 これは文字通りあらゆる可能性を列挙しているため、これは正しいです。 ただし、最大で`10^9`～の選択肢`k`, そのため、外側のループだけでも遅すぎます。 

重要な点は、実際にはカレンダーを描画する必要がないということです。 重要なのは、週の長さとペイントされた日数の関係だけです。 

週の長さが次のようになっているとします。`k`。 

もし`k < n`、ペイントされた領域は複数の行に及びます。 この状況では、有効な開始オフセットごとに異なる形状が作成され、正確に`k`可能な形状。 

もし`k >= n`、描かれた日は 1 つの行に収まります。 考えられるすべての開始位置は、同じ行のシフトされたコピーにすぎないため、形状は 1 つだけです。 

すべての週の長さの貢献は数学的にカウントできます。 のために`k = 1`に`min(r, n - 1)`、追加します`k`形。 もし`r >= n`、からのすべての幅に対して追加のシェイプを 1 つ追加します。`n`これからも。 これは単純な等差数列になります。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`r`現在のテストケースの場合。 

答えはこれら 2 つの値のみに依存するため、カレンダーを構築する必要はありません。 
2. しましょう`x = min(r, n - 1)`。 

これらは、以下より短い週の長さです。`n`。 それぞれが、それ自体の値に等しい数の形状を提供します。 
3. 合計を加算します`1 + 2 + ... + x`答えに。 

これは、描画された日が複数の行にまたがるすべてのケースをカウントします。 
4. もし`r >= n`、 追加`1`答えに。 

すべての週の長さから`n`それ以降は、同じ真っ直ぐな水平形状を作成するため、一緒に追加される形状は 1 つだけです。 
5. 結果を出力します。 

最大の中間値は約`5 * 10^17`、これは Python 整数内に快適に収まります。 

なぜ効果があるのか:

 考えられるすべての週の長さに対して、ケースは 2 つだけです。 週がペイントされたセグメントより短い場合、最初にペイントされたセルがその週のすべての位置を占めることができ、各位置は固有の形状を与えます。 週がペイントされたセグメントと少なくとも同じ長さの場合、ペイント全体は 1 行になり、変換により開始位置の影響が除去されます。 これらのケースでは、可能なすべてのカレンダー幅が 1 回だけカバーされるため、合計では重複することなくすべての有効な形状がカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, r = map(int, input().split())

        x = min(r, n - 1)

        cur = x * (x + 1) // 2

        if r >= n:
            cur += 1

        ans.append(str(cur))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`x`は、描画された長さよりも厳密に短いすべての週の長さを表します。 表現`x * (x + 1) // 2`は、それらの寄与の等差数列の合計です。 

条件`r >= n`は、大きなカレンダーがすべて 1 つの水平形状に折りたたまれる 2 番目のケースを処理します。 ここで使用すると、1 つ違いの間違いを犯しやすくなります。`r > n`、 しかし`k = n`はすでに単一行のケースに属しているため、含める必要があります。 

Python の整数では、乗算が約`10^18`。

 ## 特殊なケース

 のために`n = 1`そして`r = 100`、アルゴリズムセット`x = min(100, 0) = 0`, したがって、算術合計は何も寄与しません。 以来`r >= n`、シェイプを 1 つ追加します。 これにより、すべての可能なカレンダーが同じ単一のペイントされたセルを生成するという事実が正しく処理されます。 

のために`n = 3`そして`r = 4`、アルゴリズムは使用します`x = 2`そして数えます`1 + 2 = 3`複数行の形状。 次に、幅が異なるため、形状をもう 1 つ追加します。`3`そして`4`どちらも、ペイントされたすべてのセルを 1 行に収めます。 結果は`4`、すべての開始位置を一意として扱うことによる重複カウントエラーを回避します。 

のために`n = 5`そして`r = 5`、ペイントされた長さと正確に等しい週の長さは、`r >= n`状態。 最初の 4 つの幅が影響します`1 + 2 + 3 + 4 = 10`、幅`5`1 つの水平形状に貢献し、`11`。 使用する`r > n`ここではこの境界ケースを見逃してしまいます。
