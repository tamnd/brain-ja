 ## 解決策
 ## 問題の理解

 小屋が並んでいて、それぞれの小屋にはある程度の人が住んでいます。 小屋は等間隔に配置されており、入力により各小屋の人口が得られます。 既存のアイスクリーム店も同じ線上の指定された座標に配置されます。 

新しいお店のコーディネートを 1 つ選択する必要があります。 人は、新しい店が既存のどの店よりも自分の小屋に厳密に近い場合にのみ、新しい店から購入します。 目標は、新しい店舗に最適な位置を選択して、捕捉できる小屋の最大総人口を見つけることです。 

小屋と既存の店舗の数は両方とも20万に達する可能性があります。 新しい店舗の実際の座標は無限にあるため、すべての可能な位置をチェックしてすべての小屋と比較することは直ちに不可能になります。 小屋や店をすべてチェックするのにも時間がかかりすぎます。 線形または並べ替えベースに近いソリューションが必要です。$O(n \log n)$。 

重要な問題は「厳密に」という言葉です。 新しい店が小屋から既存の店とまったく同じ距離にある場合、その人はカウントされません。 間隔を閉じた間隔として扱う解決策は、答えを過大評価します。 

例えば：```
Input
2 1
5 7
100

Output
7
```小屋は 0 と 100 の位置にあり、既存の店は 100 にあります。2 番目の小屋は既存の店までの距離が 0 であるため、勝つことはできません。 攻略できるのは最初の小屋のみ。 同点を許可する不用意な実装は、両方の小屋を誤ってカウントする可能性があります。 

もう 1 つのエッジ ケースは、複数の小屋が同じ最適な領域を持っている場合です。```
Input
3 1
2 5 6
169

Output
7
```最初の小屋と二番目の小屋はどちらも左側付近に新しいお店を置くことで攻略できます。 3番目の小屋は無理です。 既存の店舗の隣の場所のみをチェックするソリューションでは、最適な場所が連続した間隔内のどこにでも存在する可能性があるため、最適なポイントを見逃す可能性があります。 

## アプローチ

 直接的なアプローチは、新しいショップで重要なポジションをすべて試してみることです。 連続する 2 つの既存の店舗の間では、新しい店舗を好む人の集合は、どこかの小屋が結ばれる地点を越える場合を除いて、連続的に変化することはありません。 多くの候補ポイントを生成し、すべての候補をすべての小屋に対してテストし、最大値を維持することができます。 

答えは距離の比較によって作成された領域の 1 つから得られる必要があるため、これは概念的に機能します。 ただし、候補の数が膨大になる可能性があるため、すべての小屋に対して各候補をチェックすると、許可されている操作をはるかに超えてしまう可能性があります。 最悪の場合、これは二次関数以上になります。 

有益な観察は、視点を逆転させることです。 選択した店舗の場所がどの小屋を占領できるかを尋ねる代わりに、選択した小屋が新しい店舗を配置できる場所を尋ねます。 

小屋が座標にあると仮定します$c_i$。 させて$d_i$この小屋から最も近い既存の店舗までの距離になります。 新しいショップがこの小屋を獲得するのは、次の場合とまったく同じです。$$|x-c_i| < d_i$$つまり:$$c_i-d_i < x < c_i+d_i$$したがって、すべての小屋は、新しいショップがその小屋を占領する位置の開いた間隔に貢献します。 問題は、重なり合う開いた区間の最大合計重みを見つけることになります。 

これは加重スイープ ラインの問題です。 間隔の開始時にイベントを作成し、間隔の終了時に別のイベントを作成します。 唯一の微妙な点は、開いた間隔を正しく処理することです。 同じ座標では、どちらにも境界自体が含まれていないため、そこで終了する間隔は、そこから始まる間隔がアクティブになる前に消えます。 ある座標ですべてのイベントを処理した後、現在の合計はその座標の直後のカバレッジを表します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$それより悪い |$O(n)$| 遅すぎる |
 | 最適 |$O((n+m)\log m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 既存のすべてのアイスクリーム ショップの座標を並べ替えます。 すべての小屋について、その小屋に最も近い店を知る必要があります。これは、ソートされたリストで二分検索で見つけることができます。 
2. すべての小屋について、最も近い既存の店舗までの距離を求めます。 小屋の座標が$c$そしてその距離は$d$、新しいショップは、オープンインターバル内でのみこの小屋をキャプチャできます$(c-d,c+d)$。 
3. 小屋は無視してください。$d=0$。 既存の店舗がすでに小屋の位置に正確に位置しているため、それらの間隔の長さはゼロです。 
4. 開始イベントを追加します。$c-d$そして終了イベント$c+d$。 イベントの重みはその小屋にいる人の数です。 
5. すべてのイベント座標を並べ替えます。 すべての座標について、最初にそこで終了する間隔を削除し、次にそこから始まる間隔を追加します。 その座標でのすべてのイベントが処理された後、現在の重みは、次の開いたセグメントでキャプチャされた人の数になります。 
6. スイープ中に確認された最大現在の重量を追跡します。 

なぜ効果があるのか:

 各小屋は、新しいショップがその小屋の既存のすべてのショップに勝つすべてのポジションのセットに正確に貢献します。 選択した位置によってキャプチャされた人の総数は、その位置を含むすべての間隔の重みの正確な合計です。 スイープ ラインは、連続するイベント座標間のすべての可能な領域についてこの合計を維持します。 値はイベント座標でのみ変更できるため、そのような領域をすべてチェックして最適な位置を見つけます。 

## Python ソリューション```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    people = list(map(int, input().split()))
    shops = list(map(int, input().split()))
    shops.sort()

    events = []

    for i in range(n):
        pos = i * 100
        idx = bisect.bisect_left(shops, pos)

        best = 10**18
        if idx < m:
            best = min(best, abs(shops[idx] - pos))
        if idx > 0:
            best = min(best, abs(shops[idx - 1] - pos))

        if best > 0:
            events.append((pos - best, 1, people[i]))
            events.append((pos + best, -1, people[i]))

    events.sort()

    ans = 0
    cur = 0
    i = 0
    while i < len(events):
        x = events[i]

        while i < len(events) and events[i][0] == x[0] and events[i][1] == -1:
            cur -= events[i][2]
            i += 1

        j = i
        while j < len(events) and events[j][0] == x[0]:
            j += 1

        while i < j:
            cur += events[i][2]
            i += 1

        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```店舗の座標が最初にソートされるのは、線上の最近傍クエリは二分探索で答えることができるためです。 小屋の座標は別個に保存する必要はありません。$i$常に座標にあります$100i$ゼロベースのインデックスを使用する場合。 

間隔の生成が変換の核心です。 最も近い既存の店舗までの距離によって、新しい店舗が優先されながらどれだけ遠くに移動できるかが決まります。 間隔が開いているため、距離がゼロの場合は有効な位置が作成されず、スキップされます。 

スイープ順序は、オフバイワン ミスを引き起こす可能性が最も高い部分です。 終了イベントは、同じ座標で開始イベントの前に適用する必要があります。 開始が最初に処理された場合、次のような 2 つのタッチ間隔$(-1,0)$そして$(0,1)$座標 0 で重なっているように誤って表示されます。 

Python の整数は任意の精度であるため、母集団の合計が大きくなる可能性がある場合でも特別な処理は必要ありません。

import sys, io, bisect

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        import sys, bisect
        input = sys.stdin.readline
        n, m = map(int, input().split())
        people = list(map(int, input().split()))
        shops = sorted(map(int, input().split()))

        events = []
        for i, p in enumerate(people):
            pos = i * 100
            k = bisect.bisect_left(shops, pos)
            d = 10**18
            if k < m:
                d = min(d, abs(shops[k] - pos))
            if k:
                d = min(d, abs(shops[k-1] - pos))
            if d:
                events.append((pos-d, 1, p))
                events.append((pos+d, -1, p))

        events.sort()
        cur = ans = 0
        i = 0
        while i < len(events):
            x = events[i][0]
            while i < len(events) and events[i][0] == x and events[i][1] == -1:
                cur -= events[i][2]
                i += 1
            while i < len(events) and events[i][0] == x:
                cur += events[i][2]
                i += 1
            ans = max(ans, cur)

        return str(ans) + "\n"

    out = solve()
    sys.stdin = old
    return out

 ## 特殊なケース

 既存の店舗がまさに小屋にある場合、最も近い店舗までの距離はゼロになります。 間隔は空になり、アルゴリズムはそれを無視します。 例えば：```
2 1
5 7
100
```2 番目の小屋は、既存の店舗までの距離がすでにゼロであるため、占領できません。 スイープは最初の小屋からの間隔のみを受け取り、5 を返します。 

2 つの間隔が境界で接触する場合、アルゴリズムは両方を同時にカウントしてはなりません。 たとえば、ある小屋では次のような位置に配置できる場合があります。$(-10,0)$一方、もう 1 つは$(0,10)$。 座標ゼロ自体はどちらの区間も満たさないため、答えに両方の重みを含めることはできません。 開始イベントの前に終了イベントを処理すると、このルールが維持されます。 

同じ地域で多くの小屋を占領できる場合、スイープでは自然にその重みが蓄積されます。 最初のサンプルでは、​​最初の 2 つの小屋の間隔が重なっているため、それらの母集団は結合されて最終的な答えは 7 になります。
