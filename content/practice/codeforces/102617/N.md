 ## 解決策
 ## 問題の理解

 いくつかのパイ タイプがあり、行内のすべてのパイは 1 つのタイプにのみ属します。 2 人でパイを分割する必要がありますが、分割は個々のパイではなく種類ごとに行われます。 ある人が何らかの種類のパイを 1 つ受け取った場合、その人はその種類のすべてのパイを受け取らなければなりません。 

人それぞれ、好みのタイプのリストを持っています。 1 人の人のリストにのみ表示されるタイプは、強制的にその人に属します。 両方のリストにあるタイプは、どちらの方法でも割り当てることができます。 割り当ての後、両方のパイが同じ人に属している場合、列内の隣接するパイのペアごとにキャンディーが与えられます。 目標は、キャンディーの総数ができるだけ多くなるように、柔軟なタイプの所有権を選択することです。 

入力の重要な部分は、円の行によって型間の関係が作成されるということです。 隣接する 2 つのパイのタイプが異なる場合、それら 2 つのタイプを別の人に割り当てると、その境界に関連付けられているキャンディーの値が失われます。 所有者が同じ場合、その値が得られます。 問題は個々のパイに関するものではなく、できるだけ多くの貴重な接続を維持しながら 2 つのグループに型を割り当てることです。 

タイプの数は 500 に達し、パイの数は 1000 に達する可能性があります。タイプの可能な割り当てをすべて試行するソリューションでは、最大で 8 までを調べる必要があります。$2^K$可能性。 と$K=500$, this is far beyond what any time limit can support. We need an approach that works close to polynomial time. The number of pies is small enough that building relationships between types directly is practical.

 The main edge cases come from forced assignments and from types that occur multiple times in the row. たとえば、次のことを考えてみましょう。```
2 2 1 1
1
2
1 2
5
```最初のタイプは Joaozao のみに属し、2 番目のタイプは Nicoleta のみに属します。 二人を隔てる唯一の境界線、答えは`0`。 設定を尊重せずに型を貪欲に割り当てる不注意なソリューションでは、両方の型が誤って一緒に配置され、境界がカウントされる可能性があります。 

もう 1 つのケースは、型が何度も出現する場合です。```
3 5 2 2
1 2
2 3
1 2 1 3 2
1 10 10 1
```タイプ 2 はどちらの人にも属しますが、繰り返し出現するため、タイプ 1 とタイプ 3 の両方に関連付けられます。タイプ 1 の出現のみを見ると、誤った決定につながる可能性があります。 ソリューションでは、タイプに関係するすべての境界を結合する必要があります。 

最後の境界ケースは、すべての型がすでに強制されている場合です。```
3 3 1 2
1
2 3
1 2 3
7 8
```決定はありません。 答えは単純に、強制所有者が一致する境界の合計値です。 少なくとも 1 つの柔軟な型が存在することを前提とするアルゴリズムは、この場合も処理する必要があります。 

## アプローチ

 直接的なアプローチは、すべてのフレキシブル パイ タイプを 2 人のうちの 1 人に割り当て、その割り当てに対するキャンディーの合計を計算することです。 これが機能するのは、すべての有効なソリューションがすべてのタイプに対して 1 つの所有権の選択に正確に対応しているためです。 あれば$F$柔軟なタイプ、これを確認する必要があります$2^F$課題。 最悪の場合、すべてのタイプを自由に選択できます。$2^{500}$可能性、それは不可能です。 

有益な観察は、何が得られるかではなく、何が失われるかに注目することから生まれます。 すべての境界のキャンディーの合計値は固定されています。 隣接する 2 つのタイプが異なる人に割り当てられない限り、境界はその値に寄与します。 したがって、キャンディーを最大化することは、2 つのタイプのグループ間でカットされる境界の総重量を最小化することと同じです。 

これにより、問題は最小カット問題に変わります。 各円グラフの種類が頂点になります。 異なるタイプの隣接するペアはすべてエッジに寄与し、その重みはこれら 2 つのタイプが分離された場合に失われるキャンディーの数になります。 Joaozao に強制されたタイプはソースに接続され、Nicoleta に強制されたタイプはシンクに接続されます。 最小限のソース/シンク カットでは、分離された境界を正確に支払いながら、すべての柔軟なタイプの側を選択します。 

最大のキャンディーは、すべての境界値の合計から最小カット値を引いたものです。 グラフには頂点が約 500 個しかなく、有用なエッジが 1000 個しかないため、標準の最大フロー アルゴリズムでも十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^K \cdot N)$|$O(K)$| 遅すぎる |
 | 最小カット |$O(V^2E)$このグラフ サイズで Dinic のアルゴリズムを使用した場合 |$O(V+E)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 設定を読み、すべてのタイプの所有者の制限を決定します。 Joaozao のリストにのみ表示されるタイプはソース側に配置する必要があり、Nicoleta のリストにのみ表示されるタイプはシンク側に配置する必要があります。 両方のリストに表示されるタイプは未定のままです。 
2. すべての円タイプがノードとなるグラフを作成します。 その境界のキャンディー値に等しい容量を持つ、隣接するタイプ間に両方向の有向​​エッジを追加します。 容量を追加すると、同じタイプのペア間の複数の境界が自然に蓄積されます。 
3. ソース ノードとシンク ノードを追加します。 すべての強制ジョアオザオ タイプを非常に大容量のソースに接続します。 すべての強制ニコレータタイプを同じ大容量のシンクに接続します。 値が大きいため、強制タイプを必要な側から分離することは、キャンディーが失われる可能性がある場合よりもコストが高くなります。 
4. ソースからシンクまでの最大流量を計算します。 最大フロー最小カット定理により、この値は 2 人の所有者を分ける境界の最小合計重みになります。 
5. すべての境界報酬の合計から最小カット値を引きます。 残りの値はまさに取得できるキャンディーの最大量です。 

なぜ効果があるのか:

 カットにより、タイプ頂点が 2 つのグループに分割されます。 ソース側は Joaozao のタイプを表し、シンク側は Nicoleta のタイプを表します。 強制タイプは、無限の容量エッジによりそのようなカットを最適化することが不可能になるため、カットを横切ることができません。 カットを横切る通常のエッジはすべて、所有者が異なる隣接するパイのペアを表すため、その容量はまさにその境界で失われるキャンディーの価値となります。 交差しないすべてのエッジはキャンディー値を保持します。 最小カットにより失われたキャンディーの値がすべて最小限に抑えられるため、結果の割り当てにより獲得したキャンディーが最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        self.level[s] = 0
        q = [s]
        for u in q:
            for v, c, _ in self.g[u]:
                if c and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        while self.it[u] < len(self.g[u]):
            e = self.g[u][self.it[u]]
            v, c, rev = e
            if c and self.level[v] == self.level[u] + 1:
                ret = self.dfs(v, t, min(f, c))
                if ret:
                    e[1] -= ret
                    self.g[v][rev][1] += ret
                    return ret
            self.it[u] += 1
        return 0

    def flow(self, s, t):
        ans = 0
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, 10**18)
                if not pushed:
                    break
                ans += pushed
        return ans

def solve():
    k, n, a, b = map(int, input().split())

    jo = list(map(int, input().split()))
    ni = list(map(int, input().split()))

    owner = [0] * k
    for x in jo:
        owner[x - 1] |= 1
    for x in ni:
        owner[x - 1] |= 2

    pies = list(map(int, input().split()))
    pies = [x - 1 for x in pies]
    g = list(map(int, input().split()))

    total = sum(g)

    s = k
    t = k + 1
    dinic = Dinic(k + 2)

    inf = total + 1

    for i in range(k):
        if owner[i] == 1:
            dinic.add_edge(s, i, inf)
        elif owner[i] == 2:
            dinic.add_edge(i, t, inf)

    for i, w in enumerate(g):
        u = pies[i]
        v = pies[i + 1]
        if u != v:
            dinic.add_edge(u, v, w)
            dinic.add_edge(v, u, w)

    cut = dinic.flow(s, t)
    print(total - cut)

if __name__ == "__main__":
    solve()
```実装では、各円タイプをフロー グラフ内の 1 つのノードとして表します。 Dinic 構造は残余エッジを保存するため、アルゴリズムが拡張パスを繰り返し見つけて残りの容量を更新できるようになります。 

優先処理では 2 ビット表現が使用されます。 の値`1`Joaozao が型と値を受け入れることを意味します`2`ニコレータがそれを受け入れることを意味します。 価値観`1`そして`2`は強制されますが、値は`3`柔軟です。 

無限の容量が選択されるのは、`sum(g) + 1`。 通常の境界をすべてカットしてもせいぜいコストがかかるため、最適なカットではそれほど多くの容量が犠牲になることはありません。`sum(g)`。 これにより、フロー アルゴリズムが強制タイプを間違った側に割り当てることを防ぎます。 

エッジが必要なのは、異なるタイプ間の境界のみです。 2 つの隣接するパイが同じタイプを持つ場合、それらは常に同じ所有者を持つため、境界が失われることはなく、最適化に影響を与えません。

import sys, io

def solve_io(inp):
    sys.stdin = io.StringIO(inp)
    import collections

    class Dinic:
        def __init__(self, n):
            self.n = n
            self.g = [[] for _ in range(n)]

        def add_edge(self, u, v, c):
            self.g[u].append([v, c, len(self.g[v])])
            self.g[v].append([u, 0, len(self.g[u]) - 1])

        def bfs(self, s, t):
            self.level = [-1] * self.n
            self.level[s] = 0
            q = [s]
            for u in q:
                for v, c, _ in self.g[u]:
                    if c and self.level[v] == -1:
                        self.level[v] = self.level[u] + 1
                        q.append(v)
            return self.level[t] != -1

        def dfs(self, u, t, f):
            if u == t:
                return f
            while self.it[u] < len(self.g[u]):
                e = self.g[u][self.it[u]]
                v, c, rev = e
                if c and self.level[v] == self.level[u] + 1:
                    r = self.dfs(v, t, min(f, c))
                    if r:
                        e[1] -= r
                        self.g[v][rev][1] += r
                        return r
                self.it[u] += 1
            return 0

        def flow(self, s, t):
            ans = 0
            while self.bfs(s, t):
                self.it = [0] * self.n
                while True:
                    x = self.dfs(s, t, 10**18)
                    if not x:
                        break
                    ans += x
            return ans

    def run():
        k, n, a, b = map(int, input().split())
        jo = list(map(int, input().split()))
        ni = list(map(int, input().split()))
        own = [0] * k
        for x in jo:
            own[x - 1] |= 1
        for x in ni:
            own[x - 1] |= 2
        p = [x - 1 for x in map(int, input().split())]
        w = list(map(int, input().split()))
        d = Dinic(k + 2)
        total = sum(w)
        inf = total + 1
        for i, x in enumerate(own):
            if x == 1:
                d.add_edge(k, i, inf)
            elif x == 2:
                d.add_edge(i, k + 1, inf)
        for i, x in enumerate(w):
            if p[i] != p[i + 1]:
                d.add_edge(p[i], p[i + 1], x)
                d.add_edge(p[i + 1], p[i], x)
        return str(total - d.flow(k, k + 1)) + "\n"

    return run()
