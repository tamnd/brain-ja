 ## 解決策
 ## 問題の理解

 この問題では、長方形の天板の中に収まる必要がある一連の円形のクッキーについて説明します。 各クッキーには、座標平面上の中心と半径があります。 パンの側面は座標軸に平行でなければならず、すべてのクッキーを完全に含む長方形の可能な限り小さな領域が必要です。 

中心のあるクッキー`(x, y)`と半径`r`到達する`r`中心から左右上下の単位。 つまり、1 つのクッキーを含む最小の長方形には水平範囲があるということです。`[x - r, x + r]`と垂直範囲`[y - r, y + r]`。 答えは、これらすべての個々の範囲をカバーする長方形の面積です。 

入力サイズは以下に達します`100000`したがって、アルゴリズムは各 Cookie を一定の回数処理する必要があります。 Cookie のすべてのペアを比較する二次アプローチでは、約`10^10`通常のコンテストの制限時間よりもはるかに長い、最大のケースでの作戦。 制約は線形スキャンを指します。 

主なエッジケースは、パンにクッキーの中心だけでなく全体を入れなければならないことを忘れていることから起こります。 単一の Cookie ですでに答えが決まります。 例えば：```
1
0 0 5
```正しい出力は次のとおりです。```
100
```パンには幅が必要です`10`と高さ`10`。 中心のみを追跡するアプローチでは、誤って領域が返されてしまいます。`0`。 

もう 1 つのよくある間違いは、負の座標を間違って処理することです。 考慮する：```
2
-10 -5 2
4 3 1
```水平方向の限界は、`[-12, -8]`そして`[3, 5]`したがって、合計幅は次のようになります。`17`。 垂直方向の限界は、`[-7, -3]`そして`[2, 4]`, したがって、高さは`11`。 正しい出力は次のとおりです。```
187
```正の値のみを使用したり、絶対値を座標に適用したりする不注意な実装では、真の最小位置と最大位置が失われる可能性があります。 

最後の境界ケースは、すべての Cookie が重複する場合です。```
3
0 0 1
0 0 1
0 0 1
```正しい出力は次のとおりです。```
4
```クッキーを繰り返すためにパンを大きくする必要はありません。 極端な境界だけが重要です。 

## アプローチ

 強引なアイデアは、可能な長方形を試し、すべての Cookie がそれぞれの長方形の中に収まるかどうかを確認することです。 最終的には最適な四角形が考慮されるため、これは正しいですが、考えられるすべての四角形を列挙する便利な方法はありません。 可能な座標の数は入力値とともに増加するため、適度な数の Cookie であってもこのアプローチは不可能になります。 

より自然なブルート フォース解釈は、すべての Cookie を他のすべての Cookie と繰り返し比較することによって、Cookie の左端、右端、最小値、および最大値の境界を見つけることです。 このアプローチは、答えが極値のみに依存するため機能します。 ただし、ある場合は、`n`クッキーを使って極限を繰り返し探索すると、作品は次のようになります。`O(n^2)`、つまり約`10^10`の比較`n = 100000`。 

重要な観察は、最終的な長方形が 4 つの数値によって完全に決定されるということです。 左辺は最小値です`x - r`、右側はの最大値です。`x + r`、下辺は の最小値です。`y - r`、上辺は の最大値です。`y + r`。 各 Cookie はこれら 4 つの値を個別に更新できます。 

ブルートフォース手法は最終的にこれら 4 つの境界を見つけるため機能しますが、同じ比較を何度も繰り返します。 すべての Cookie が境界候補を 4 つだけ提供するという観察により、繰り返しの検索を 1 回のパスに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のパン境界を表す 4 つの変数を初期化します。 より小さい値を検索しているため、左と下の境界は正の無限大から始まります。 より大きな値を検索しているため、右側と上の境界は負の無限大から始まります。 
2. 各 Cookie を読み取り、その 4 つの極座標を計算します。`x - r`、`x + r`、`y - r`、 そして`y + r`。 これらは、最終的なパンに影響を与えることができる唯一の値です。 
3. これら 4 つの値を使用して現在の境界を更新します。 最小の左エッジと下エッジが新しい下限となり、最大の右エッジと上エッジが新しい上限になります。 
4. すべての Cookie が処理された後、幅を次のように計算します。`right - left`そして高さは`top - bottom`。 彼らの製品は可能な限り小さな鍋面積です。 

機能する理由: Cookie のプレフィックスを処理した後、保存された 4 つの境界は、これまでに確認されたすべての Cookie を含む最小の長方形を正確に表します。 新しい Cookie が追加される場合、考えられる唯一の変更は、これら 4 つの側面の 1 つを拡張することです。 すべての Cookie が処理され、考えられるすべての拡張子が考慮されるため、最終的な境界にはすべての Cookie が含まれ、これ以上減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    left = float('inf')
    right = -float('inf')
    bottom = float('inf')
    top = -float('inf')
    
    for _ in range(n):
        x, y, r = map(int, input().split())
        
        left = min(left, x - r)
        right = max(right, x + r)
        bottom = min(bottom, y - r)
        top = max(top, y + r)
    
    width = right - left
    height = top - bottom
    
    print(width * height)

if __name__ == "__main__":
    solve()
```コードでは、現在の回答の 4 つの境界線のみが保持されます。 価値観`x - r`そして`x + r`クッキーの左点と右点を記述します。`y - r`そして`y + r`一番下の点と上の点を説明します。 

使用する`float('inf')`負の無限大を指定すると、最初の Cookie に対する特別な処理が必要なくなります。 すべての入力値は、同じ更新ロジックを通じて処理されます。 

Python の整数には任意の精度があるため、最終的な乗算には特別なオーバーフロー処理は必要ありません。 領域は個々の Cookie ではなく Cookie の完全なセットに依存するため、幅と高さの計算はすべての更新後に実行する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各 Cookie は 4 つの境界を 1 回更新します。 |
 | スペース | お(1) | 4 つの境界変数のみが保存されます。 |

 アルゴリズムは Cookie の数に直接応じて調整されます。 のために`100000`Cookie を使用する場合、実行される算術演算は数十万回のみであり、一般的なコンテストの制限に簡単に適合します。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    data = inp.strip().split()
    if not data:
        return ""
    
    it = iter(data)
    n = int(next(it))
    
    left = float('inf')
    right = -float('inf')
    bottom = float('inf')
    top = -float('inf')
    
    for _ in range(n):
        x = int(next(it))
        y = int(next(it))
        r = int(next(it))
        left = min(left, x - r)
        right = max(right, x + r)
        bottom = min(bottom, y - r)
        top = max(top, y + r)
    
    return str((right - left) * (top - bottom))

2 -4 3
-5 2 6
-8 -1 4
""") == "270", "sample"

assert solution("""1
0 0 5
""") == "100", "single cookie"

assert solution("""3
0 0 1
0 0 1
0 0 1
""") == "4", "all equal cookies"

assert solution("""2
-10 -5 2
4 3 1
""") == "187", "negative coordinates"

assert solution("""2
10000000 10000000 10000000
-10000000 -10000000 10000000
""") == "1600000000000000", "large coordinates"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 | 3 つの同じクッキー | 4 | Cookie を繰り返しても境界線は変わりません。 |

 ## 特殊なケース

 単一 Cookie の場合:```
1
0 0 5
```アルゴリズムは空の境界から始まります。 唯一のクッキーは 4 つの面すべてを次のように変更します。`-5`そして`5`。 結果として得られる長方形には面積があります`100`、可能な限り小さな鍋です。 

負の座標の場合:```
2
-10 -5 2
4 3 1
```最初のクッキーは左端に寄与します`-12`そして下端`-7`。 2 番目のクッキーは右端に寄与します`5`そして上端`4`。 最後の長方形は、`17`ユニット幅と`11`高さの単位なので、答えは次のようになります。`187`。 負の位置は比較によって自然に処理されるため、アルゴリズムは負の位置を特別に扱いません。 

重複する Cookie の場合:```
3
0 0 1
0 0 1
0 0 1
```すべてのクッキーは同じ境界線を生成します。 最小値と最大値の演算では、最初の Cookie の後も四角形は変更されず、次の正しい答えが得られます。`4`。 これは、解決策が Cookie の数ではなく極端な値に依存する理由を示しています。
