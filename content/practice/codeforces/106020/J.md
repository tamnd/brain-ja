 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースは 2 つの整数を提供します。$n$そして$k$、長さの配列を構築する必要があります$n$正の整数で構成され、その合計が正確に$k$。 このようなすべての配列の中で、隣接するペアによって定義されるコストを最小化したいと考えます。つまり、連続するすべてのペアについてです。$(a_{i-1}, a_i)$、これら 2 つの値のビットごとの AND を追加し、可能な限り最小の合計を求めます。 

したがって、タスクは配列自体を構築することではなく、正数と固定合計の制約の下で、この隣接する AND 合計の達成可能な最小値を決定することだけです。 

制約は非常に大きいです。$n$まで行くことができます$10^6$テストケースごとに最大で$5000$テストケース、合計$n$すべてのテストにわたって、厳密に制限されていません。 これにより、二次関数は除外されます。$n$、テスト ケースごとの線形作業であっても、細心の注意を払う必要があります。 ソリューションは基本的に、最適な配列をシミュレートするのではなく、式を計算するか、最適な配列の構造特性に依存する必要があります。 

重要なエッジケースは次の場合に発生します。$n = 1$。 隣接するペアがないため、コストは常にゼロです。$k$。 以下の一般式を適用しようとするあらゆるアプローチ$n-1$条件はこれを明示的に処理する必要があります。 

別の微妙な状況が発生するのは、$k = n$。 したがって、すべての要素は正確に一致する必要があります$1$, すべての値は正の整数であるためです。 費用は$(n-1) \cdot (1 \& 1) = n-1$。 値を異なる値に「分割」できると仮定した誤った貪欲な構築は、ここでは失敗します。 

3 番目のコーナーケースは次のような場合です。$k$よりもわずかに大きいです$n$、 例えば$n = 4, k = 5$。 その場合、配列は大部分が単一の追加増分がどこかに分散されたもので構成されている必要があります。 これはまさに、合計を集中させたり均等に分散させたりしようとする素朴な貪欲な戦略が異なるビット パターンを生成し、AND の寄与を予期せず増加させる可能性がある場所です。 

## アプローチ

 強引なアイデアは、すべての有効な配列を試すことです。 配布する必要があります$k$の中へ$n$正の整数。これは、を選択するのと同じです。$n$正の整数の合計$k$。 そのような構成の数は$\binom{k-1}{n-1}$、これは小さな入力でも天文学的に大きくなります。 配列ごとに計算します$\sum (a_{i-1} \& a_i)$、原価計算$O(n)$, したがって、このアプローチは完全に実行不可能です。 

本当の単純化は、ビットごとの AND コストが実際に何を測定しているのかを理解することから生まれます。 2 つの数値の AND は、少なくとも 1 つの共通ビットを共有する場合にのみ正になります。 すべての数値は正であるため、すべての要素には少なくとも最下位ビットがありますが、重複の大きさは値をどのように分配するかによって異なります。 

重要な観察は、隣接する要素間のバイナリ表現の重複を回避することで、ほとんどの AND 寄与をゼロに保つ配列を常に構築できるということです。 唯一避けられない構造は、すべてのユニットを超えてどれだけの「追加ユニット」を配布する必要があるかによって引き起こされます。 

すべての要素が含まれるベースライン配列から開始します。$1$。 これは合計を使用します$n$。 残り$k-n$単位は、いくつかの要素に配置する必要がある追加の増分です。 要素を増やすたびに、隣接要素との共有ビットが導入され、AND の寄与が増加する可能性があります。 最適な戦略は、すべての余分な値を単一の要素にローカライズすることです。 それを拡散すると、隣接するペアが両方とも非自明になり、AND 寄与が生成される可能性が高まるだけです。 

余分な質量がすべて集中すると、構造は単一の大きな数になります。$x = k-n+1$ものに囲まれています。 ゼロ以外の寄与は、この大きな数値が接触する境界でのみ発生します。$1$、そしてそれらの寄与は、大きな数がビットを共有するかどうかによってのみ決まります。$1$。 以来$1$には最下位ビットしかないため、AND の寄与は、大きい数が奇数であるかどうかと正確に一致します。 

これにより、問題全体がパリティのチェックに集約されます。$k-n+1$。 奇数の場合、各境界が寄与します$1$、それ以外の場合は両方の寄与がゼロになります。 境界は最大 2 つであるため、答えは次のいずれかになります。$0$または$1$かどうかに応じて$k-n+1$偶数または奇数です。 これは、直接パリティ式にさらに単純化されます。

 ## アルゴリズムのチュートリアル

 1. すべての有効な配列には少なくとも次の要素が必要であることに注意してください。$1$各ポジションにありますので、ご予約ください$n$すぐに合計の単位を表示します。 残った余剰金は、$k - n$。 これにより、強制構造が柔軟な部分から分離されます。 
2. すべて 1 のベースライン配列を検討します。 そのコストはゼロであるため、$1 \& 1 = 1$、ただし、隣接するペアを合計しているため、各ペアが貢献します$1$。 これは、最も単純な構成であっても自動的にコストがかからないわけではないため、生の値よりも構造が重要であることを示しています。 
3. 余剰を複数のポジションに分配するのではなく、単一の要素に集中させます。 これにより、バイナリ表現で重複して AND の寄与が増加する複数の「重い」近傍の作成が回避されます。 
4. 1 つの位置を値に置き換えます$x = k - n + 1$、他のすべての要素を次と等しく保ちます$1$。 現在、自明でない相互作用のみが、の 2 つのエッジで発生します。$x$。 
5. 各境界のコスト寄与を計算します。 以来$1 \& x$どちらかです$1$または$0$、どうかに応じて$x$が奇数でも偶数でも、両方の境界は同じように動作します。 
6. 2 つの境界からの寄与を合計します。 もし$x$は偶数、両方の AND はゼロ、総コストは$0$。 もし$x$奇数、各境界が寄与する$1$ただし、構造を最適な方向に配置できるため、達成可能な最小合計は 1 つの単位コストに減ります。 

### なぜ効果があるのか

 不変条件は、コストを増加させることなく、あらゆる最適な構造をすべての余剰質量が 1 つの要素に集中する構造に変換できるということです。 これは、剰余を分割すると非 1 値の追加の隣接ペアが作成され、そのようなペアは 1 つのブロックにマージする場合と比較してビット単位のオーバーラップを維持または増加させることしかできないためです。 したがって、最適解はオールワン配列の 1 ブロックの摂動内に存在し、コストはそのブロックのパリティのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    if n == 1:
        print(0)
        continue
    extra = k - n
    # cost depends only on parity of (extra + 1)
    if (extra + 1) % 2 == 0:
        print(0)
    else:
        print(1)
```隣接するペアがないため、コードは最初に縮退した単一要素のケースを個別に処理します。 次に、合計がベースラインのすべて 1 の配列をどれだけ超えるかを計算します。 その余剰によって、最適な構造における単一の重元素のパリティが決まります。 最後の条件は、その構造が避けられない AND 寄与を生成するかどうかを直接評価します。 

微妙な点は、配列を明示的に構築しないことです。 この推論では、明示的な構築ではコストが増加するだけかコストが変わらないことが保証されているため、パリティ チェックで十分です。 

## 実用的な例

 次の場合を考えてみましょう$n = 2, k = 3$。 ベースラインは$[1, 1]$合計付き$2$。 ユニットが 1 つ余っているので、集中配列は次のようになります。$[2, 1]$または$[1, 2]$。 

| ステップ | 配列 | 番外編 | 境界 AND | コスト |
 | --- | --- | --- | --- | --- |
 | 開始 | [1, 1] | 0 | 1 & 1 = 1 | 1 |
 | 調整 | [2, 1] | 1 | 2 & 1 = 0 | 0 |

 これは、この場合、余分なものを集中させるとオーバーラップがゼロになることがわかります。 

ここで考えてみましょう$n = 4, k = 5$。 ベースラインは 4 つの 1 で、追加ユニットを 1 つ追加して 1 つの 2 を取得します。 

| ステップ | 配列 | 番外編 | キーペア | コスト |
 | --- | --- | --- | --- | --- |
 | 開始 | [1,1,1,1] | 0 | すべて 1 & 1 | 3 |
 | 配置後 | [1,2,1,1] | 1 | 1&2、2&1 | 0 |

 これは、単一の重い要素を導入すると、一様な隣接関係を破壊することで AND 寄与を完全に排除できることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        if n == 1:
            out.append("0")
        else:
            extra = k - n
            out.append("0" if (extra + 1) % 2 == 0 else "1")
    return "\n".join(out)

# provided samples (if any)

assert run("1\n2 2\n") == "1", "all ones case"
assert run("1\n3 3\n") == "0", "uniform minimal structure"
assert run("1\n3 4\n") == "1", "one extra unit"
