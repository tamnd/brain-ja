 ## 解決策
 ## 問題の理解

 問題は順列ベースのゲームです。 入力は順列によって接続されたポジションのボードを記述します。これは、すべてのポジションが次の 1 つのポジションを正確に指すことを意味します。 2 人のプレーヤーが異なる位置からスタートします。 各ターンで、プレイヤーは現在の位置に保存されている値を取得し、そこに留まるか、順列によって指定された位置に移動することができます。 一定のターン数が経過した後、より多くの累積スコアを獲得したプレイヤーが勝利します。 課題は、ボディア、サーシャ、または両方が最適にプレイしたときに、最終スコアが同じになるかどうかを判断することです。 元の問題は Codeforces に表示されます。 [Codeforces](https://codeforces.com) ゲーム構造は順列ゲーム ファミリーのものです。 

キー入力の難しさはターン数が非常に多いことです。 ポジションの数はすべてのテスト ケースで約 200,000 に達する可能性があり、手の数は 10^9 にもなる可能性があります。 これにより、毎ターンのシミュレーションが除外されます。 k だけで演算数が 10^14 以上に達する可能性があるため、O(nk) のアイデアでも不可能です。 順列がサイクルに分割され、各サイクルの関連部分のみを処理するという事実を利用する必要があります。 

プレイヤーがサイクルに到達し、サイクルの長さを超えるターンを行うと、微妙なエッジ ケースが発生します。 不注意な解決策は、サイクルを永久に移動することが常に最適であると仮定する可能性があります。 たとえば、値が [100, 1, 1] で、プレイヤーのターンが 2 であるサイクルを考えてみましょう。 値 100 の位置から開始すると、滞在すると 200 のスコアが与えられ、移動すると 101 のスコアが与えられます。正しい出力は、プレイヤーが滞在するか移動するかを選択できるかどうかによって決まります。 

もう 1 つのエッジ ケースは、考えられるすべてのサイクル ステップを完了する前に最高のスコアが達成される場合です。 値が [5、4、100] で 2 ターンのみのサイクルを考えてみましょう。 最善の選択は、最初の 2 つの位置を獲得し、それ以上の移動を停止することです。 常に全サイクルの寄与を計算し、それを繰り返すソリューションでは、誤った結果が生成される可能性があります。 

3 番目のよくある間違いは、k より短いサイクルの処理を誤ることです。 たとえば、サイクルの長さが 1 で k が大きい場合、唯一の位置が永久に繰り返されます。 プレイヤーは毎ターン同じ値を収集するため、答えは単一の値ではなく、その値の k 倍になります。 

## アプローチ

 ブルートフォースアプローチは、ゲームをシミュレートすることです。 各プレイヤーについて、k ターンの間、滞在と移動の可能なすべてのシーケンスを試し、最大スコアを計算し、2 つの結果を比較できます。 これは、考えられるすべての戦略を直接検討するため、正しいです。 問題は、選択肢の数が指数関数的に増加し、ターンごとに到達可能なすべての位置をチェックする単純なシミュレーションですら O(k) のコストがかかることです。 k が 10^9 までの場合、プレイヤーが 1 人でもシミュレートできません。 

より良い最初の試みは、開始位置からサイクルをたどり、可能なすべての移動数を実行した後でスコアを計算することです。 プレイヤーは順列エッジに沿ってのみ移動できるため、到達可能なすべての位置は同じサイクルに属します。 プレイヤーはいつでも移動を停止できるため、i 回移動した後、残りのターンを現在の位置の値の収集に費やすことができます。 これにより、ゲームはサイクル上の最適な停止ポイントを確認するだけになります。 

これを高速化する観察結果は、サイクルの複数の走査を処理する必要がないということです。 プレーヤーがサイクルの位置を確認したら、それ以上の動きは同じ順序を繰り返すだけです。 サイクルの各プレフィックスのスコアを計算し、残りのターンで最後に訪問した位置に留まる寄与を追加できます。 十分なサイクル情報を収集した後は、ターン数は問題になりません。

あらゆる可能な移動シーケンスが検査されるため、総当たり攻撃が機能します。 k が大きすぎるため失敗します。 順列グラフにはサイクルのみが含まれているため、サイクルの観察が機能します。そのため、将来の状態はすべて、制限されたステップ数の後に繰り返されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | プレーヤーあたり O(k) | お(1) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次のポインタに従って暗黙的に順列サイクルを構築します。 開始位置ごとに順列をたどり、訪問した位置の順序を記録します。 これにより、プレイヤーが値を収集できる順序が決まります。 
2. サイクルを歩きながら、最初の i ポジションを取った後のスコアを維持します。 k 回の手が尽きる前に到達したすべての位置について、プレイヤーがその位置に移動し、そこに留まる戦略を検討します。 
3. i が移動した後に到達した位置については、その位置の値に残りのターン数を掛けた値を加算します。 これは、サイクルを継続するのではなく、とどまることを表します。 
4. 考えられるすべての停止点の中で最大スコアを維持します。 これにより、1 人のプレイヤーに最高のスコアが与えられます。 
5. Bodya のスタートと Sasha のスタートのベスト スコアを別々に計算します。 2 つの値を比較し、勝者を出力します。 

それが機能する理由: すべての有効な戦略は、サイクルの中で動きが停止するポイントを選択することに相当します。 その時点までは、移動することが新しい位置に到達する唯一の方法であり、その時点以降は、プレイヤーが将来のターンを失うことを避けることができるため、滞在することは継続することよりも悪いことはありません。 アルゴリズムはあらゆる停止位置をチェックし、最適な戦略を検討します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def best_score(start, p, a, k):
    cur = start
    score = 0
    ans = 0
    step = 0

    while step < k:
        score += a[cur]
        step += 1

        ans = max(ans, score + a[cur] * (k - step))

        cur = p[cur]

    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, k, pb, ps = map(int, input().split())
        p = [0] + list(map(int, input().split()))
        a = [0] + list(map(int, input().split()))

        bodya = best_score(pb, p, a, k)
        sasha = best_score(ps, p, a, k)

        if bodya > sasha:
            out.append("Bodya")
        elif sasha > bodya:
            out.append("Sasha")
        else:
            out.append("Draw")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```の`best_score`機能はソリューションの中核です。 1 人のプレイヤーの位置から始まるサイクルに従います。 変数`score`すでに訪問した位置から収集した値を保存します。 現在の位置を追加した後、アルゴリズムはプレーヤーが移動を停止したと想定し、残りのすべてのターンの現在の値を収集します。 

ループ条件では、`step < k`k ターン後はそれ以上の移動は許可されないためです。 順列配列と値配列は、元の 1 から始まる位置を直接使用できるように、インデックス 0 にダミーの 0 を付けて保存されます。 

各呼び出しには指定された開始位置から到達可能なサイクルのみが必要であり、k ステップ後に停止するため、実装では訪問済みノードを明示的にマークしません。 すべてのテスト ケースにわたる位置の合計数は制限されているため、これは引き続き効率的です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各プレイヤーは最大で k 個の位置を追跡しますが、有効なトラバースの合計は、すべてのテスト ケースにわたる順列サイズによって制限されます。 |
 | スペース | O(n) | 順列と値を格納する配列には線形メモリが必要です。 |

 この解は、k の巨大な値に直接依存することを避けるため、制約に適合します。 実行される操作のみが、処理される位置の数に比例します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    import sys
    input = sys.stdin.readline

    def best_score(start, p, a, k):
        cur = start
        score = 0
        ans = 0
        step = 0
        while step < k:
            score += a[cur]
            step += 1
            ans = max(ans, score + a[cur] * (k - step))
            cur = p[cur]
        return ans

    t = int(input())
    res = []

    for _ in range(t):
        n, k, pb, ps = map(int, input().split())
        p = [0] + list(map(int, input().split()))
        a = [0] + list(map(int, input().split()))

        b = best_score(pb, p, a, k)
        s = best_score(ps, p, a, k)

        if b > s:
            res.append("Bodya")
        elif s > b:
            res.append("Sasha")
        else:
            res.append("Draw")

    sys.stdin = old
    return "\n".join(res)

## 特殊なケース

 単一ノード サイクルの場合:```
1
1 1000000000 1 1
1
8
```アルゴリズムは位置 1 を 1 回訪問し、8 を追加してから、残りのターンに留まるかどうかを検討します。 両方のプレーヤーが同じスタートをするため、両方とも同じスコアを獲得します。 

早期停止の場合:```
1
3 2 1 2
2 3 1
100 1 1
```Bodya はすぐに 100 を集めて滞在でき、200 ポイントを与えます。 移動するとスコアは下がりますが、アルゴリズムは最初のステップの後に停止の選択肢をチェックし、より大きな結果を保持します。 

繰り返しサイクルの場合:```
1
4 5 1 2
2 1 4 3
5 7 1 1
```プレイヤーは 5 つのターンすべてをシミュレーションする必要はありません。 サイクルが検出された後、アルゴリズムは、最初の位置の後で停止するか、2 番目の位置の後で停止するかという、唯一の意味のある選択肢をすでに知っています。 残りのターンは、現在の値を乗算することによって処理されます。
