 ## 解決策
 ## 問題の理解

 無向木が与えられています。$n$頂点。 タスクは、各頂点に 3 つのラベルのいずれかを割り当てることです。$a$、$b$、 または$c$、同じラベルを持つ 2 つの頂点を接続するエッジが存在しないようにします。 このようなすべての有効な割り当ての中で、頂点のラベルを次の順序で連結して形成される辞書編集上最小の文字列を生成するように求められます。$1$に$n$。 

ツリー構造は、隣接性の制約によってのみ重要になります。 この要件はエッジ上で純粋にローカルですが、辞書編集上の順序は文字列全体に依存するため、目的はグローバルです。 この組み合わせにより、将来の競合を意識して貪欲にラベルを選択する必要があります。 

制約により、最大で$2 \cdot 10^5$これにより、すべてのラベル付けに対する指数関数的なバックトラッキングや頂点ごとのブルート フォース チェックが排除されます。 枝刈りをせずにノードごとに 3 つの選択肢を試しても、$3^n$、それは完全に不可能です。 有効なソリューションはすべて、基本的に線形または線形に近い時間で実行される必要があります。$O(n)$または$O(n \log n)$。 

ツリー構造を尊重せずに素朴な貪欲戦略が使用されると、微妙な障害モードが発生します。 たとえば、親の制約を考慮せずに常に最小のラベルをローカルで割り当てると、後になって行き詰まる可能性があります。 

単純なパスを考えてみる$1 - 2 - 3$。 割り当てれば$s_1 = a$、次に貪欲に割り当てます$s_2 = a$また、局所的に最小であるため、すぐに制約に違反しますが、たとえ局所的に妥当性を強制したとしても、$s_2 = b$その後$s_3 = a$「aba」が表示されますが、これは正しいです。 ただし、1 をルートとして隣接する 2、3、4 を持つ星のような分岐構造では、不注意なアプローチにより、すべての子が独立して処理される場合に貪欲に「a」として割り当てられ、「aaa?」などの無効な出力が生成される可能性があります。 これはすべてのエッジで制約に違反します。 

もう 1 つの微妙な問題は、走査順序から発生します。 親から最初の依存関係を修正せずに DFS 順序でノードを処理すると、一部の誤った実装では、親の最終ラベルを知る前に子を割り当てる可能性があります。 そのため、一貫性のない決定や無効な結果が生じます。 

## アプローチ

 強引なアイデアは、次のすべての割り当てを生成することです。$\{a,b,c\}$に$n$頂点を削除し、エッジ制約を満たす頂点のみを保持します。 有効な割り当てごとに、その辞書編集値を計算し、最小値を保持します。 

これは、可能なすべてのラベル付けを明示的にチェックするため機能しますが、スケールの点ですぐに失敗します。 課題の数は、$3^n$、各検証コスト$O(n)$すべてのエッジをチェックするには、$O(n \cdot 3^n)$、でも使用できなくなります。$n = 20$、ましてや$2 \cdot 10^5$。 

重要な構造観察は、木が二部構成であるが、追加の色が 1 つ追加されていることです。 2 色に制限されている場合、解決策は交換に限られます。 3 つの色を使用すると、柔軟性が得られます。各ノードでは、親のラベルを回避するだけで済み、構造の残りの部分には、隣接関係を超える追加の直接制約が課されません。 

これは貪欲な構築を示唆しています。 ツリーを任意の場所にルートする場合、ノードに対する唯一の制約は、その親と、DFS 内で既に割り当てられている隣接ノードだけになります。 事前順序トラバーサルでノードを処理するとき、子はまだ割り当てられていないため、親の色を避けるだけで済みます。 これにより、各決定は最大でも 2 つの有効な選択肢に減ります。 各ステップで最小の有効なラベルを選択すると、前の位置が順序付けを支配するため、辞書編集上の最小性が保証されます。 

正確かどうかは、ノードが一度割り当てられると再検討する必要がないという事実にかかっています。 ツリー構造ではサイクルが保証されないため、逆方向の制約の伝播はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 3^n)$|$O(n)$| 遅すぎる |
 | 貪欲なDFSカラーリング |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートを頂点 1 にします。目標は、常に可能な限り小さいラベルを優先しながら、親子制約を尊重する方法でラベルを割り当てることです。 

1. 任意のルート (通常は頂点 1) を選択し、ツリーの隣接リスト表現を構築します。 これにより、近傍を再計算することなく効率的な走査が可能になります。 
2. DFS をルートから開始します。 ルートに最小のラベルを割り当てます。これは常に$a$。 この選択は、競合する祖先が存在せず、結果の文字列の最初の文字が最小化されるため安全です。 
3. すべてのノードについて$v$、子を処理するときは、親のラベルに基づいて各子のラベルを個別に決定します。 制約は隣接するノードが異なることだけであるため、子は親のラベルを回避する必要があります。 
4. 以下の中で可能な限り小さいラベルを割り当てます。$\{a, b, c\}$それは親のラベルと等しくありません。 この貪欲な選択は、文字列内の現在位置にのみ影響するため、有効です。 後の割り当ては、前の辞書編集上の順序に影響を与えません。 
5. DFS を再帰的に続行し、選択したラベルをより深いノードの親制約として渡します。 

これが機能する理由は、ツリーの構造と辞書編集の性質に由来します。 各ノードのラベルは、最終文字列内のその位置にのみ影響し、共有親制約を超えて兄弟を制限しません。 常に各位置で利用可能な最小のラベルを選択するため、後で修正を行っても、そのノードでのエッジ制約に違反することなく辞書編集的に小さいプレフィックスを生成できません。 依存関係グラフは非巡回であるため、割り当てはローカルに最適であり、グローバルに一貫性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    res = [''] * (n + 1)

    def dfs(u, parent):
        for c in "abc":
            if c != res[parent]:
                res[u] = c
                break
        for v in g[u]:
            if v != parent:
                dfs(v, u)

    res[0] = '#'  # dummy parent so root can take 'a'
    res[1] = 'a'
    for v in g[1]:
        dfs(v, 1)

    return "".join(res[1:])

print(solve())
```この実装は、単純な DFS トラバーサルに依存しています。 ルートは最小のラベルを確実に取得するために個別に初期化されます。 ルートが制約されないように、ダミー値がその親に使用されます。 

主な微妙な点は、初期化されていない親ラベルと決して比較しないようにすることです。 使用する`res[parent]`すべてのノードはその子が処理される前に割り当てられるため、直接的に機能します。 

もう 1 つのポイントは再帰の深さです。 ツリーは長いチェーンになる可能性があるため、Python のデフォルトの再帰制限では不十分であるため、制限が増加します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 各頂点とエッジは DFS 中に 1 回アクセスされます。 
| スペース |$O(n)$| 隣接リストと再帰スタックは線形情報を格納します。 

時間とメモリの両方が頂点の数に比例して増加するため、このソリューションは制約内に快適に収まります。 たとえ$2 \cdot 10^5$、単一の DFS トラバーサルは効率的です。

 ## 特殊なケース

 単一の頂点ツリーが最も単純なシナリオです。 アルゴリズムはルート「a」を即座に割り当て、それ以上の走査は発生しません。 エッジがないので、これは自明に有効です。 

2 ノード ツリーは、親制約が適切に適用されているかどうかをテストします。 ルートは「a」を取得し、子は「b」を取得する必要があります。 子に「a」を割り当てようとするとエッジ ルールに違反するため、これによりフィルタリング ロジックが正しいかどうかがチェックされます。 

星型ツリーは、兄弟の独立性が正しく処理されているかどうかをテストします。 各子は個別に処理されますが、すべてルートのラベルを回避する必要があります。 アルゴリズムはそれらにすべて「b」を割り当てますが、兄弟は直接制約されないため、これは有効なままです。 

ディープ チェーンは、DFS が制約を複数のレベルに正しく伝播するかどうかをテストします。 各ノードはその親にのみ依存し、追加の簿記を必要とせずに交互の割り当てが自然に発生します。
