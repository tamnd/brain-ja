 ## 問題の理解

 高さの長方形のウィンドウが与えられます`H`と幅`W`。 2つのカットが行われます。 

まず、整数の位置で垂直カットを選択します。`A`、ウィンドウを幅の左側の長方形に分割します。`A`そして、幅の右側の長方形`W - A`。 

次に、右側の長方形の内側のみ、高さで水平方向のカットを選択します。`B`、高さの上下の長方形に分割します。`B`そして`H - B`。 

これにより、正確に 3 つの長方形が生成されます。 

左の部分、右上の部分、右下の部分です。 彼らのエリアは、`S1 = H * A`、`S2 = B * (W - A)`、`S3 = (H - B) * (W - A)`。 

目標は整数を選択することです`A`そして`B`これら 3 つの領域のうち最小の領域ができるだけ大きくなるようにします。 

制約は小さく、どちらの次元も最大 1000 です。これはすでに、`O(HW)`または`O(W)`テストごとのアプローチは完全に安全ですが、立体的なものは不要です。 

単純な間違いは、すべてを試してみることです`(A, B)`直接ペアリングします。 これはせいぜい 100 万の州であり、これでも問題ありませんが、構造が隠蔽され、誤って最適化しようとすると誤った推論につながる可能性があります。 

3 つの領域を独立して処理しようとすると、さらに微妙な落とし穴が発生します。 たとえば、各領域を個別に最大化しようとしたり、3 つすべてのバランスを一度に調整したりすることができます。 それは失敗します。`S2`そして`S3`同じ要素を通じて結合されている`(W - A)`そして対称的に`B`。 

隠れたエッジ制約もあります。`A`少なくとも 1、最大でも 1 でなければなりません`W-1`、同様に`B`の間にある必要があります`1`そして`H-1`。 これにより、1 つの領域が消失するという縮退のケースが防止され、どのソリューションでもそれを尊重する必要があります。 

## アプローチ

 直接的な総当たり戦略により、すべての有効なペアが選択されます`(A, B)`そして 3 つの領域を計算します。 これは正確な目的関数を評価するため正しいですが、大まかに繰り返す必要があります。`(W-1)(H-1)`最悪の場合、約 100 万回の操作が必要になります。 これは制約の下では許容されますが、無駄であり、式の構造を使用しません。 

重要な観察は、固定垂直カットの場合です。`A`、右側は のサイズの長方形になります`(W - A) × H`。 その中で私たちは選択します`B`水平に分割します。 左側のエリア`S1`から独立しています`B`、 その間`S2`そして`S3`高さを分割する方法のみに依存します。 

固定用`A`、問題は最大化に帰着します`min(B, H - B)`なぜなら両方とも`S2`そして`S3`同じ係数を掛けます`(W - A)`。 2 つの対称線形関数の最小値を最大化する最良の方法は、できるだけ均等に分割することです。`B`にできるだけ近いはずです`H/2`できるだけ。 これにより、可能な限り最高の値が得られます`floor(H/2)`小さい方用。 

したがって、それぞれについて`A`、以下の中で達成可能な最良の最小値`S2`そして`S3`になる`(W - A) * floor(H/2)`。 今度は 3 番目の値です`S1 = H * A`はこの量と競合するため、問題を 1 つの変数の最適化に縮小します。`A`。 

この時点で、問題は次の 1 次元の最大値になります。`min(H*A, C*(W-A))`どこ`C = floor(H/2)`。 この機能は次のように増加します`A`第 1 項では が減少し、第 2 項では減少するため、最適値はそれらの交点の近くにあります。 以来`W ≤ 1000`、可能な限りすべてを安全に評価できます`A`。

 ## アルゴリズムのチュートリアル

 問題を段階的に単一変数の最適化に変換します。 

1. コンピューティング`C = floor(H / 2)`。 

これは、可能な限り最高の値を表します。`min(B, H - B)`有効な水平分割の場合。 
2.垂直カット位置を固定する`A`から`1`に`W - 1`。 

それぞれの選択により、左の長方形と右の長方形の幅が決まります。 
3. それぞれについて`A`、2 つの競合する量を計算します。`S1 = H * A`そして`S23 = C * (W - A)`。 

値`S23`最適に選択した後の右上と右下の長方形の間の最良の最小値を表します。`B`。 
4. このために`A`、達成可能な最良の答えは`min(S1, S23)`。 

これは、3 つの領域すべてが少なくともこの大きさでなければならないことを反映しているため、それらの中で最も小さい領域が制限要因となります。 
5. この式の最大値を全体にわたって追跡します。`A`。 

最終的な答えは、左側の領域と右側の最適な最小値が可能な限り近づく、最良のバランス ポイントです。 

### なぜ効果があるのか

 固定の場合`A`、右辺は因数を除いて左辺から独立しています。`(W - A)`。 右側の長方形内の水平分割問題は対称かつ線形であるため、最適な戦略は常に可能な限り均等に分割することです。 これにより、二次元の決定が減少します`(A, B)`単一のパラメータに`A`最適性を失うことなく。 あらゆる実現可能な構成はいくつかの方法で表現されるため、`(A, B)`、それぞれについて`A`私たちは最適なものを選択します`B`、この削減以外にこれより良い解決策は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    H, W = map(int, input().split())

    C = H // 2
    best = 0

    for A in range(1, W):
        s1 = H * A
        s23 = C * (W - A)
        best = max(best, min(s1, s23))

    print(best)

if __name__ == "__main__":
    solve()
```実装は、縮小された定式化に直接続きます。 ループオーバー`A`有効な垂直カットをすべて調査します。 それぞれについて、`s1`は左側のエリアであり、`s23`水平カットを最適に配置した後、右側から達成可能な最良のボトルネックです。 の`min`3 つの領域すべてが、その中の最小領域と少なくとも同じ大きさであることが強制されます。 

よくある実装上の間違いは、最適な設定を忘れることです。`B`明示的に反復する必要はありません。 もう一人が使っているのは`H/2`の代わりに`floor(H/2)`、次の場合に整数の正確性が損なわれます。`H`奇数です。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`H = 2`。 それから`C = 1`、水平カットは強制的に 2 つの高さ 1 のストリップに分割されます。 アルゴリズムはこれを正しく処理します。`min(B, H-B)`は常に 1 なので、右辺は次のようになります。`(W - A)`正確に、そして最適化はバランスを取ることに帰着します`2A`そして`W - A`。 

もう 1 つのエッジケースは次のような場合です`W = 2`。 この場合、有効な垂直カットは 1 つだけです`A = 1`したがって、ループは 1 つの構成だけを評価します。 結果は`min(H, floor(H/2))`、これは右の長方形の強制構造と一致します。 

最後の微妙なケースは次のような場合です。`H`奇数です。 使用する`H // 2`分割によって達成可能な最小値が過大評価されないようにします。 浮動小数点除算を使用しようとすると、無効な非整数領域の仮定により、誤った比較が生成されます。
