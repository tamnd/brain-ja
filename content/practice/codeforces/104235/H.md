 ## 解決策
 ## 問題の理解

 すべての頂点に 2 つの出力エッジ (赤いエッジ 1 つと青いエッジ 1 つ) がある有向グラフが与えられます。 移動は、開始頂点からのエッジ トラバーサルの固定パターンの繰り返しで構成され、そのパターンを何度も適用した後にどこに到達するかを決定する必要があります。 

各クエリは開始頂点とコンパクトな命令文字列を提供します。 命令文字列は、「動きブロック」を何回繰り返すか、およびそのブロックを定義する色ベースのエッジ トラバーサルのシーケンスの 2 つを同時にエンコードします。 移動ブロック自体は、文字列で指定された順序で赤と青のエッジをたどることによって得られる短い歩行です。 

タスクは、クエリごとにこれらの繰り返されるウォークをシミュレートし、最終的な頂点を出力することです。 

この制約により、私たちは各ステップの直接的なシミュレーションから遠ざけられます。 最大 100,000 個の頂点と最大 50,000 個のクエリがあり、クエリ内で非常に多くの繰り返し回数がエンコードされる可能性があるため、すべての動きを明示的に拡張すると、実行可能な制限をはるかに超える多数の遷移が発生します。 単一のクエリでも、最大 10^8 回の繰り返しでウォークを記述することができるため、ステップごとのシミュレーションは即座に除外されます。 

命令文字列に繰り返し回数は多くてもパターンが非常に短い場合、微妙なエッジ ケースが発生します。 たとえば、頂点が指定されたパターンでサイクルを形成する場合、たとえ最終結果が繰り返しの関数合成によって決定されるとしても、単純なシミュレーションは無限にループするか、時間制限を超えてしまいます。 

## アプローチ

 各頂点は、赤のサクセサーと青のサクセサーという 2 つの決定的な遷移を定義します。 色のシーケンスは、頂点から頂点への関数に対応します。 色の文字列で関数を定義しましょう$f$、適用される場合$f(v)$から始まることを意味します$v$そして色の順序を一度たどります。 

各クエリでは計算が求められます。$f^M(v)$、この関数を適用することを意味します$M$回。 

ブルートフォース手法では、次の 1 つのアプリケーションを計算します。$f$カラーシーケンスをシミュレートし、それを繰り返すことによって$M$回。 1回の申請にかかる費用$O(L)$、 どこ$L \le 8$、 しかし$M$まで可能です$10^8$それ以上。 これは最悪の事態を招きます$O(M \cdot L)$が遅すぎます。 

重要な観察は、同じ関数を繰り返し作成しているということです。 関数の合成は結合的であるため、バイナリ リフティングを使用して関数のべき乗を事前に計算できます。 変換を一度に 1 ステップずつ適用する代わりに、事前計算を行います。$f^{2^k}$各頂点および各 2 のべき乗に対して。 次に、任意の指数$M$2 の累乗に分解できるため、対数時間への繰り返し適用が削減されます。$M$。 

関数自体は小さいですが、その領域は大きいため、遷移テーブルを保存します。頂点ごとに、移動ブロックの 1、2、4、8、... の適用後にどこに行くかを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot M \cdot L)$|$O(n)$| 遅すぎる |
 | バイナリリフティング |$O(q \cdot L + q \cdot \log M)$|$O(n \log M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各クエリの命令文字列をグラフ上の単一ステップの遷移関数として解釈します。 

1. クエリごとに、整数を抽出します。$M$そして色の順番$s$。 色は、1 つの移動ブロックの後の任意の頂点から別の頂点への決定的なマッピングを定義します。 
2. 固定クエリの場合、「ベース遷移」配列を計算します。`next[v]`、すべての頂点から開始してカラー シーケンスを適用することをシミュレートします。 これが機能するのは、各頂点に出力される赤のエッジが 1 つと、出力される青のエッジが 1 つずつあるためであり、結果として生じる宛先は明確に定義されます。 
3. バイナリリフティングテーブルを構築する`up[k][v]`、 どこ`up[0][v] = next[v]`、 そして`up[k][v] = up[k-1][up[k-1][v]]`。 各レベルは移動ブロックの適用を表します$2^k$回。 
4.分解する$M$バイナリに変換します。 最初の頂点から開始して、ビットが入るたびに事前計算されたジャンプを適用します。$M$が設定され、それに応じて現在の頂点が更新されます。 
5. 設定されたすべてのビットを処理した後、最終頂点を出力します。 

事前計算が効率的である理由は、グラフの遷移が決定的で関数的であるため、繰り返しの合成が分岐することがなく、コンパクトに保存できるためです。 

### なぜ効果があるのか

 このアルゴリズムは、各移動ブロックを頂点の関数として扱います。 関数の合成は結合的であるため、同じ関数を繰り返し適用すると、べき乗として書き直すことができます。 バイナリ リフティング テーブルはこの関数のすべてのべき乗をエンコードし、あらゆる指数が 2 のべき乗の合計として 1 回だけ表現されるようにします。 各ステップで構成の正確さが維持されるため、最終的な頂点は元の繰り返しプロセスを適用した結果と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_once(v, s, r, b):
    for ch in s:
        if ch == 'R':
            v = r[v]
        else:
            v = b[v]
    return v

def solve():
    n, q = map(int, input().split())
    r = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    for _ in range(q):
        parts = input().split()
        v = int(parts[0])
        s = parts[1]

        # extract M and pattern
        i = 0
        while i < len(s) and s[i].isdigit():
            i += 1
        M = int(s[:i])
        pattern = s[i:]

        # compute base transition
        nxt = [0] * (n + 1)
        for u in range(1, n + 1):
            cur = u
            for ch in pattern:
                if ch == 'R':
                    cur = r[cur]
                else:
                    cur = b[cur]
            nxt[u] = cur

        # binary lifting
        LOG = M.bit_length()
        up = [nxt]
        for k in range(1, LOG):
            prev = up[k - 1]
            cur = [0] * (n + 1)
            for u in range(1, n + 1):
                cur[u] = prev[prev[u]]
            up.append(cur)

        ans = v
        bit = 0
        while M:
            if M & 1:
                ans = up[bit][ans]
            M >>= 1
            bit += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装は、赤と青のエッジの 2 つの固定隣接配列を解析することから始まります。 クエリごとに、命令文字列が繰り返し回数とカラー パターンに分割されます。 の`nxt`配列は、基本関数を形成するすべての頂点からパターンを 1 回シミュレートすることによって計算されます。 

昇降テーブル`up`この関数の繰り返し構成を保存します。 各レイヤーはそれ自体で前のレイヤーを構成するため、`up[k]`パターンの適用に対応します$2^k$回。 最後に、次のバイナリ表現をたどることによって答えが構築されます。$M$、対応するビットが設定されている場合にのみ現在の頂点を更新します。 

重要な詳細は、各クエリが異なる関数を定義するため、リフティングがクエリごとに構築され、共有構造がなければクエリ間でテーブルを再利用することは不可能であるということです。

| あなた | B、次に R |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、パターンが 1 回の適用後に自己ループ変換を生成する場合です。 このような状況では、間違った構成により繰り返し累乗がずれてはなりません。 

入力：```
n=2
v=1
M=10
r=[1,2]
b=[1,2]
pattern="RB"
```両方のエッジは常に自己ループにつながります。 1 つのアプリケーションがすでにすべての頂点をそれ自体にマップしているため、すべてのリフティング レベルで同一性が維持されます。 アルゴリズムの構築`nxt[u] = u`、そしてすべてのより高い累乗は同一性を保つため、繰り返し適用すると同じ開始頂点が得られます。 

もう 1 つのエッジケースは次のような場合です$M = 0$これは制約内に明示的には表示されませんが、バイナリ分解ロジックによって暗黙的に処理されます。 ビットが設定されていないため、初期頂点は変更されずに返され、ゼロ アプリケーションのアイデアと一致します。
