 ## 解決策
 ## 問題の理解

 隠された整数のペアを操作しています$A$そして$B$、どちらも～の範囲内$0$に$10^9$。 私たちはそれらを直接見ることはできません。 代わりに、クエリ値を送信できます。$X$、システムは値を返します$(A \oplus X) + B$、 どこ$\oplus$ビット単位の XOR です。 

各クエリは、次の XOR である数値を返します。$A$選択した値を使用して、同じ未知のオフセットだけ上にシフトします$B$。 このようなクエリを最大 5 回実行した後、両方の隠れた数値を正確に決定する必要があります。 

出力形式により、インタラクティブな再構成の問題が発生します。すべてのクエリで、変換されたビューが明らかになります。$A$、ただし常に同じ加法定数と混合$B$。 重要な問題は、XOR が加算の下で非線形であることと、未知の$B$絶対スケールを非表示にします。 

制約は、入力サイズではなく、インタラクション数の点で非常に小さいです。 許可されるクエリは 5 つだけなので、プローブを繰り返してビットを 1 つずつ学習しようとする戦略は即座に除外されます。 孤立させるあらゆるアプローチ$A$定期的なクエリで慎重に代数キャンセルを行ってこれを行う必要があります。 

素朴な考えは、次の複数の値を試してみることです。$X$そして方程式を直接解いてみます。 ただし、すべての応答の形式は次のとおりです。$A \oplus X + B$したがって、応答を減算すると、$B$しかし、依然として非線形である XOR の差が残ります。 構造化クエリを慎重に選択しないと、これは不明確になります。 

微妙なエッジケースは次のような場合です$A = 0$。 すると、応答は次のようになります$X + B$、これは線形に見え、貪欲な再構築を誘惑する可能性があります。$B$, しかし、これは XOR 構造を完全に隠すため、誤解を招きます。 もう 1 つの注意が必要なケースは次のような場合です。$A$には上位ビットのみが設定されているため、応答間の減算によってキャリーが発生するため、単純な低ビット推論が失敗します。 

## アプローチ

 ブルートフォース戦略は、考えられるすべての値を推測することです。$A$、対応する計算$B$単一のクエリから検証し、他のクエリに対して検証します。 候補者ごとに$A$、計算できます$B = \text{response} - (A \oplus X)$。 これは一貫したチェックですが、範囲は$A$までです$10^9$、これは完全に実行不可能です。$10^9$候補と候補ごとに複数のクエリ。 

重要な観察は、XOR がビットの違いに対して線形に動作し、分離できることです。$A$排除することで$B$2 つのクエリ応答の減算によって計算されます。 2 つの異なる値をクエリすると$X_1$そして$X_2$、次のようになります。$$R_1 = (A \oplus X_1) + B,\quad R_2 = (A \oplus X_2) + B$$減算すると次のようになります。$$R_1 - R_2 = (A \oplus X_1) - (A \oplus X_2)$$今$B$完全に排除されます。 これにより、問題は回復にまで減ります$A$XOR の違いのみから。 

古典的なトリックは、次のような構造化クエリを選択することです。$0$、$2^k - 1$、および制御された方法でキャリーを明らかにするいくつかのビットマスク。 特にクリーンなアプローチは、まず回復することです。$A$3 つのクエリを使用して回復する$B$あらゆる応答から直接。 

以下を送信して続行します。 

最初のクエリ$X = 0$、与える$R_0 = A + B$。 

2 番目のクエリ$X = C$、 どこ$C = 2^{30} - 1$, したがって、下位 30 ビットがすべて設定されます。 これにより、XOR がすべての下位ビットを反転します。$A$、相補的なパターンを生成します。 

次のように計算します。$$R_C - R_0 = (A \oplus C) - A$$以来$C$下位ビットはすべて 1、$A \oplus C$その範囲内でビット単位の補数になり、再構築が可能になります。$A$差分の既知の固定構造を使用してビットごとに処理します。 

一度$A$回復され、$B$は次のように取得されます。$$B = R_0 - A$$原則として必要なクエリは 2 つだけですが、5 つまで許可されているため、より安全な実装では、検証や対話型環境でのオーバーフローのエッジ ケースを回避するために 3 番目のクエリを使用することがよくあります。

 ## アルゴリズムのチュートリアル

 1. クエリ$X = 0$、 受け取る$R_0 = A + B$。 これにより、XOR 歪みなしで両方の未知数を組み合わせたベースラインが得られます。 
2. クエリ$X = 2^{30} - 1$、 受け取る$R_1 = (A \oplus (2^{30}-1)) + B$。 これにより、下位 30 ビットが反転されます。$A$、予測可能な変換を生成します。 
3. 差を計算します$D = R_1 - R_0 = (A \oplus C) - A$。 これにより削除されます$B$を含む純粋な XOR ベースの式のみが残ります。$A$。 
4. 再構築$A$という事実を利用して少しずつ$C$すべての下位ビットを反転します。 各ビット位置について、既知の反転パターンの下で差がどのように変化するかを比較して、元のビットが正しいかどうかを判断します。$A$0か1でした。 
5. 1回$A$既知である、計算する$B = R_0 - A$。 これは有効です。$R_0$正確に含まれている$A + B$。 
6. 出力$A$そして$B$。 

### なぜ効果があるのか

 不変条件は、すべてのクエリ応答が次の純粋な XOR 変換の線形シフトであるということです。$A$。 2 つの応答を減算することで、$B$完全に、決定論的な関数を残して、$A$一人で。 選んだマスク$2^{30}-1$XOR が固定範囲の完全なビット単位の補数として機能することを保証し、曖昧さなくビットごとに変換を反転できるようにします。 以来$A$中にある$10^9$、30 ビット以内に収まるため、上位ビットの破損は発生しません。 これにより、独自の再構築が保証されます。$A$したがって、ユニークな$B$。

    return int(input().strip())

    r0 = ask(0)
    r1 = ask(C)

    # r0 = A + B
    # r1 = (A xor C) + B
    # so:
    # r1 - r0 = (A xor C) - A

    diff = r1 - r0

    # Reconstruct A bit by bit using complement structure
    A = 0
    for i in range(30):
        bit = 1 << i

        # try setting bit and test consistency via XOR behavior
        # since C flips bits, A xor C = (~A) within 30 bits
        # so A + (A xor C) = C
        # => A + (~A) = C (within 30 bits)

        # so we directly reconstruct using known identity:
        # A xor C = C - A
        #
        # thus r1 - B = C - A and r0 - B = A
        # => (r1 - B) + (r0 - B) = C
        # => r1 + r0 - 2B = C

        # A = r0 - B, B = r0 - A (circular)
        #
        # So we instead compute:
        # A = (C + r0 - r1) // 2

    A = (C + r0 - r1) // 2
    B = r0 - A

最終的な式は、ビットごとの再構成を回避し、代わりに対称性を使用します。$A \oplus C = C - A$したがって、応答を減算すると、解決可能な線形システムが分離されます。 

よくある落とし穴は、XOR の違いを独立したビットごとの演算として解釈しようとすることです。 減算からのキャリーは、そのようなアプローチを壊すことになります。 線形アイデンティティはその問題を完全に回避します。

 ## 特殊なケース

 いつ$A = 0$の場合、XOR 演算は最初のクエリから完全に消えます。$0 \oplus X = X$。 システムは単純な線形オフセット モデルのように動作するため、ビット単位の構造に依存するソリューションでは情報が欠落していると誤って想定されてしまいます。 線形恒等式は、ビット間の XOR 変動に依存しないため、引き続き機能します。 

いつ$A$に近いです$2^{30} - 1$、とのXOR$C$生成される数値は非常に小さいため、大量のキャンセルによりビットベースの再構成戦略が誤解される可能性があります。 減算ベースの導出では、個々のビットを決して検査しないため、これを完全に回避します。 

いつ$A$そして$B$どちらも次のような大きな中間値です$r_0 - r_1$マイナスになる可能性があります。 非負の中間値を仮定するビットごとの再構築アプローチはここで機能しません。 最終的な式は、ビットごとの推論ではなく対称線形システムから派生しているため、符号付きの差分を安全に処理します。
