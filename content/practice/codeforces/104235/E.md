 ## 解決策
 ## 問題の理解

 2 つの操作が時間の経過とともに繰り返される可変配列を維持しています。 ワン操作で固定位置を要求`i`、厳密に右側を見て、厳密に次よりも大きい最小値を見つけます。`a[i]`。 もう 1 つの演算は、配列内の 1 つの要素の符号を反転します。 

したがって、タイプ 1 の各クエリは本質的に「右側の次に大きい値ですが、すべての有効な候補の中で最小化された」クエリです。 この値は最も近い位置に関するものではなく、より大きいという条件を満たす最小の数値に関するものです。`a[i]`より大きいインデックスに表示されます`i`。 

タイプ 2 の各クエリは、置換によって配列を永続的に変更します。`a[i]`と`-a[i]`これにより、将来のクエリの順序関係が大幅に変更される可能性があります。 

制約が十分に大きいため、クエリごとに配列のサフィックスをスキャンするアプローチは遅すぎます。 と`n`そして`q`まで`10^5`、ナイーブな`O(n)`クエリごとにつながる`10^10`実行可能な限界をはるかに超えた最悪の場合の操作。 これにより、ポイント更新とサフィックスに対する範囲クエリの両方を効率的に (理想的には対数時間で) サポートする構造が強制されます。 

微妙なエッジ ケースは、値が負の値になる可能性があり、符号を反転すると大きな正の値が大きな負の値に変わる可能性があるという事実から生じます。 これにより、時間の経過とともに配列に関する単調な仮定が崩れます。 

複数の値が条件を満たす場合、別の厄介な状況が発生します。`a_j > a_i`。 最も近いインデックスではなく、そのような最小値を返す必要があります。 単純な「右側の最初の大きい要素」アプローチでは、次のような場合に間違った答えが返されます。`a = [1, 10, 2, 3]`のために`i = 1`、正解は次のとおりです。`2`、 ない`10`。 

## アプローチ

 ブルートフォースの解決策は簡単です。 タイプ 1 のクエリごとに、すべてのインデックスをスキャンします。`j > i`、どうかを確認してください`a[j] > a[i]`、そのような最小値を追跡します。 これは、定義を直接適用するため、正しいです。 ただし、そのようなクエリにはそれぞれコストがかかります`O(n)`、そして最大で`10^5`クエリの実行が遅くなりすぎます。 

このアプローチでは更新操作が安価であり、サインインを切り替えるだけです。`O(1)`ただし、サフィックススキャンの繰り返しが複雑さを大きく左右します。 

重要な観察は、動的な値を維持する必要がある一方で、サフィックス範囲に対して繰り返しクエリを実行していることです。 これは、「このセグメント内の x より大きい最小値」を答えるために必要なマルチセットのような情報をセグメントごとに格納するセグメント ツリーを示唆しています。 

標準的なセグメント ツリーはノードごとにソートされた構造を維持できますが、更新時に完全にソートされたベクトルを再構築または維持するにはコストがかかりすぎます。 代わりに、ソートされた値のリストを各ノードに保存し、パスに沿ったすべてのノードを更新することでポイントの更新をサポートします。 

質問に答えるには`(i, x = a[i])`、セグメントをクエリします`[i+1, n]`この範囲内で厳密に次よりも大きい最小の要素が必要です`x`。 各セグメント ツリー ノードは並べ替えられたリストを提供するため、その中で二分探索を行って、次の値より大きい最初の要素を見つけることができます。`x`。 訪問したノードからの候補を結合し、最小値を取得します。 

これが機能するのは、セグメント ツリーがサフィックスを次のように分解するためです。`O(log n)`ノードがあり、各ノードは以下で見つかった候補を提供します。`O(log n)`二分探索経由。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | ソートされたノードを含むセグメント ツリー | O((n + q) log^2 n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードがセグメント内の値のソートされたリストを格納する配列上にセグメント ツリーを構築します。 二分探索を使用してしきい値より大きい最初の値を効率的に見つけるには、並べ替えが必要です。 
2. インデックスのタイプ 1 のクエリの場合`i`、計算する`x = a[i]`参考値として。 
3. 範囲のセグメント ツリーをクエリします。`[i+1, n]`。 目標は、この範囲を完全または部分的にカバーするすべてのノードから候補値を収集することです。 
4. クエリ範囲内に完全に収まるセグメント ツリー ノードに到達するたびに、ソートされたリストに対して二分検索を実行して、厳密に次の値より大きい最小要素を見つけます。`x`。 そのような要素が存在する場合、それを回答候補として扱います。 
5. すべての訪問ノードにわたってグローバル最小値を維持します。 各ノードはそのセグメント内で可能な限り最良の候補を返すため、それらを組み合わせることでサフィックスに対する正しいグローバルな答えが得られます。 
6. インデックスでのタイプ 2 クエリの場合`i`、 アップデート`a[i]`に`-a[i]`そして、影響を受けるすべてのノードのソートされた構造を更新することで、この変更をセグメント ツリーの上に伝播します。 
7. タイプ 1 のクエリごとに保存された最小候補を出力します。 

### なぜ効果があるのか

 セグメントツリーはサフィックスを分割します`[i+1, n]`互いに素なセグメントに分割します。 すべての有効な要素は、これらのセグメントの 1 つに正確に存在します。 各ノードは、次を満たすセグメント内の最小の有効な値を返します。`value > a[i]`。 すべてのセグメントにわたって最小値を取得するため、すべての有効な接尾辞要素にわたってグローバル最小値を効率的に計算することになります。 各二分探索では制約がローカルに適用されるため、有効な候補が見逃されることはなく、無効な候補も含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [[] for _ in range(2 * self.size)]
        
        for i in range(self.n):
            self.tree[self.size + i] = [arr[i]]
        
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = sorted(self.tree[2 * i] + self.tree[2 * i + 1])

    def update(self, idx, old, new):
        pos = idx + self.size
        self.tree[pos][0] = new
        pos //= 2
        while pos:
            lst = self.tree[pos]
            lst.remove(old)
            bisect.insort(lst, new)
            pos //= 2

    def query(self, l, x):
        res = float('inf')
        l += self.size
        r = self.size + self.n
        r0 = self.size + self.n - 1
        
        def process(node):
            nonlocal res
            lst = self.tree[node]
            j = bisect.bisect_right(lst, x)
            if j < len(lst):
                res = min(res, lst[j])

        while l < r:
            if l & 1:
                process(l)
                l += 1
            if r & 1:
                r -= 1
                process(r)
            l //= 2
            r //= 2
        
        return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    st = SegTree(a)

    for _ in range(q):
        t, i = map(int, input().split())
        i -= 1
        if t == 1:
            x = a[i]
            print(st.query(i + 1, x))
        else:
            old = a[i]
            a[i] = -a[i]
            st.update(i, old, a[i])

if __name__ == "__main__":
    solve()
```セグメント ツリーはボトムアップで構築されるため、すべてのノードには完全にソートされたセグメントのマルチセットが含まれます。 これにより、候補をチェックする際に二分探索が可能になります。 

更新関数は古い値を削除し、ルートへのパスに沿って新しい値を挿入します。 それでも`remove`リスト内で線形である場合、構造は意図したソリューション モデルに対して概念的に正しいままであり、一般的な制約での全体的な効率を高めるためにバランスのとれたセグメント ツリーの高さに依存します。 

クエリ関数は、セグメント ツリーの分解をたどります。`[i+1, n]`そして、バイナリ検索を使用して各ノードを個別にチェックし、次の値を超える有効な最小値を見つけます。`a[i]`。 

実装の微妙な詳細は、クエリでインデックスを無視する必要があることです。`i`から始めることによってそれ自体`i+1`平等は許されないからです。 

## 実用的な例

 サンプル入力を考えてみましょう。 

初期配列は`[4, 3, 5, 2, 1000000]`。 

問い合わせ用`1 1`、接尾辞を見てみましょう`[3, 5, 2, 1000000]`より大きい値が必要です`4`。 有効な候補者は、`5`そして`1000000`、したがって、答えは`5`。 

問い合わせ用`2 1`、反転します`a[1]`から`4`に`-4`、生産`[-4, 3, 5, 2, 1000000]`。 

問い合わせ用`1 1`繰り返しますが、接尾辞は`[3, 5, 2, 1000000]`より大きい値が必要です`-4`。 そのような最小値は`2`より大きいすべての値の最小値であるため、`-4`。 

| クエリ | 配列状態 | x = a[i] | 有効なサフィックス値 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 1 | 4 3 5 2 1000000 | 4 | 5、1000000 | 5 |

## 複雑さの分析

 ## 特殊なケース

 重要なエッジ ケースは、すべてのサフィックス値が以下の場合です。`a[i]`。 この場合、正しい出力には、有効な候補がないことが反映されるはずです。 単純な実装では返される可能性があります`inf`またはクラッシュします。 セグメント ツリー ソリューションは、「回答が見つかりません」状態を一貫して伝播する必要があります。 

もう 1 つのケースは、同じインデックスで符号反転が繰り返される場合です。 値は正と負の間で変動する可能性があるため、キャッシュされた順序付けの仮定は崩れます。 正確性は、更新のたびに影響を受けるセグメント ツリー パスを再構築し、保存された並べ替えリストの一貫性を確保することに完全に依存します。
