 ## 問題の理解

 配列の長さが与えられます$n$そして素数$k$そのような$n$で割り切れます$k$。 インデックス$1..n$順列を形成する$P$、そしてそのような順列を構築するように求められます。 

この制約により、2 番目の非表示オブジェクト、つまり別の順列が導入されます。$B$の$1..n$、有効なキーと呼ばれる$P$、すべてのポジションの場合$i$、製品$P_i \cdot B_i$同じ剰余モジュロを持ちます$k$として$i$。 つまり、位置の値$i$で$P$そして位置の値$i$で$B$積がインデックスの剰余クラスを「尊重」するように、乗算的に相互作用する必要があります。 

重要な点は、有効な値を 1 つも見つけないことです。$B$ただし、有効な順列の数を確保するためです。$B$まさに$((n/k)!)^k$。 以来$n = mk$、このターゲットは次のように単純化されます。$(m!)^k$、つまり、解空間を明確に考慮する必要があります。$k$独立したサイズのグループ$m$。 

制約$n \le 3 \cdot 10^5$そして$k$素であるということは、いかなる解も本質的に線形または線形に近いものでなければならないことを意味します。 順列の列挙や、すべての位置間のグローバルな一致を伴うものはどれも遅すぎます。 この構造は、答えが剰余クラスのモジュロのみに依存することを強く示唆しています。$k$、これらはモジュラスと互換性のある唯一の自然なパーティションであるためです。 

インデックスまたは値が次の値で割り切れる場合、微妙なエッジ ケースが発生します。$k$剰余がゼロの場合はモジュロ算術の動作が異なるためです。 すべての値のモジュロに対して逆乗が存在すると仮定する素朴なアプローチ$k$ここで静かに休憩します。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を構築しようとします。$P$そしてそれぞれについて、順列の数を数えます$B$モジュラー条件を満たします。 候補者ごとに$P$、単一のチェック$B$は$O(n)$、すべてを列挙すると、$B$は$O(n!)$、それは完全に不可能です。 すべてについて推論しようとしても$P$すでに階乗複雑性が生じています$n$, なので、この方向性はすぐに崩れてしまいます。 

重要な観察は、条件がインデックスごとにローカルであるということです。 固定の場合$P$、各ポジション$i$制限する$B_i$特定の剰余クラスのモジュロへの$k$、 以来$$P_i \cdot B_i \equiv i \pmod{k}$$力$B_i$によって決定される剰余の中に存在する$i$そして$P_i$。 これにより、問題は、各位置に次のいずれかが割り当てられる制約システムに変わります。$k$剰余クラス、および$B$これらのクラス クォータを尊重する順列でなければなりません。 

有効枚数については$B$等しい$(m!)^k$、制約は完全に次のように分割する必要があります。$k$独立したブロック、それぞれのサイズ$m$、ブロック間の相互作用はありません。 これは、残基クラスの代入が次のように行われた場合にのみ発生します。$P$～の残留物のみに依存する$i$、各クラスが同一かつ独立して動作するようにします。 

これにより、タスクが順列の構築に減ります。$P$剰余クラス間のきれいな対称性を維持するモジュロ$k$、誘発された制約が確実に$B$完全に切り離します。

 ## アルゴリズムのチュートリアル

 私たちは建設します$P$剰余クラスを法として尊重することを強制することによって$k$。 

## アルゴリズムのチュートリアル

 1. 分割インデックス$1..n$の中へ$k$剰余モジュロに応じたグループ$k$。 各グループは正確に$m = n/k$要素。 
2. 分割値$1..n$同じに$k$剰余剰余によるグループ化$k$。 繰り返しますが、各グループには正確に次のものが含まれます。$m$価値観。 
3. 各残基クラスについて$r$、クラスから値を割り当てます$r$クラス内のポジションに$r$の任意の順列を使用して、$m$要素。 
4. 結果の順列を出力します。$P$ここで、すべてのインデックスは独自の残差クラスから値を受け取ります。 

この構造により、位置がその剰余クラス内でのみ一致することが保証されます。これは、インデックス間の制約間の独立性を維持できる唯一の構造です。 

### なぜ効果があるのか

 各ポジション$i$とのみ対話します$P_i$そして$B_i$乗算モジュロを介して$k$。 インデックスと割り当てられた値の両方が同じ剰余クラス内に留まるため、誘導された制約システムは次のように分解されます。$k$サイズの異なるシステム$m$。 各システム内で選択する$B$並べ替えと同等です$m$要素を自由に組み合わせて、$m!$。 システムが独立しているため、有効なシステムの総数は$B$は$(m!)^k$、要件に正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
m = n // k

groups = [[] for _ in range(k)]

for i in range(1, n + 1):
    groups[i % k].append(i)

# build permutation P
p = [0] * (n + 1)

for r in range(k):
    vals = groups[r]
    # assign within same residue class
    for i in range(len(vals)):
        p[vals[i]] = vals[i]

print("YES")
print(*p[1:])
```### コードの説明

 まずインデックスを剰余モジュロでグループ化します$k$。 次に、数値については同じグループ化を再利用します。$1..n$すでに残基全体に均等に分散されています。 各インデックスに独自の残基グループからの値を割り当てます。 ここに示す実装では、各要素をそのグループ内でそれ自体にマップするだけですが、必要な構造分解が保持されるため、これで十分です。 重要な特性は、各クラス内の特定の順列ではなく、残基境界を越える要素がないという事実です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    groups = [[] for _ in range(k)]
    for i in range(1, n + 1):
        groups[i % k].append(i)

    p = [0] * (n + 1)

        for i in range(len(vals)):

 ## 特殊なケース

 次のような最小限の入力$n = k$すべての剰余クラスをサイズ 1 に折りたたみます。この場合、構築により固定恒等順列が生成され、各クラスが寄与します。$1!$、必要な数と一致します。 

いつ$k = 2$、残基はインデックスを奇数位置と偶数位置に分割します。 アルゴリズムはこれら 2 つのグループ内で独立して割り当てを行い、相互作用を回避します。 たとえ 2 を法とする乗算が縮退しているとしても、各グループが依然として孤立した置換空間を形成しているため、この構造は有効なままです。 

いつ$n$が大きい場合、唯一のリスクは残基クラス間で要素を混合することです。 この構造はこれを明示的に防止するため、オーバーフローや不一致は発生しません。
