 ## 問題の理解

 私たちは木を使って作業しています$n$頂点 1 と頂点 2 が特別な方法で固定されている頂点: それらの間の距離は正確に$m$、ツリー内の頂点のペアはこれよりも離れていません。$m$。 So the tree has diameter at most$m$、頂点 1 と頂点 2 は、その上限と正確に等しい距離に強制的に配置されます。 

A vertex$v$同時に遠くにある場合は「遠い」と呼ばれます$m$頂点 1 から、そして離れたところからも$m$タスクは、制約を満たすすべての可能なツリーに対して、そのような頂点がどれだけ少ないか、どれだけ多く存在できるかを決定することです。 

制約は次のとおりです$n = 10^5$これにより、樹木を列挙したり、すべての構造物の距離を評価しようとする構造が直ちに除外されます。 二次関数の何か$n$失敗します。 解決策は、明示的な列挙ではなく、木の構造特性と距離ジオメトリに依存する必要があります。 

微妙な点は、「すべての距離が最大で$m$” と “dist(1,2)=m” を組み合わせると、非常にタイトな構造が強制されます。1 と 2 は、直径パスの両端のように動作します。1 と 2 の周りで任意に分岐すると想定する単純な試みは、グローバルな直径制約に違反することになり、ここで多くの誤った構築が失敗します。

 よくある間違いの 1 つは、問題を 1 と 2 から独立した BFS レイヤーとして扱い、レイヤーを交差させることです。 これは、同じ頂点が 2 つの独立したメトリックではなく、単一のツリー構造を尊重する必要があることを無視しています。 

エッジケースは小さい場合にすぐに現れます$n$。 たとえば、次のようなとき$n=3, m=2$の場合、ツリーは強制的にパスになるため、頂点が同時に両端から距離 2 に存在することはできず、出力 0 0 が得られます。もう 1 つの微妙なケースは次のような場合です。$m$に近いです$n$、そこでは木はほぼ強制的に長い鎖になり、分岐が大幅に制限されます。 

## アプローチ

 ブルートフォースの観点では、すべてのラベル付きツリーを生成します。$n$頂点 (ケイリーの公式は次のように示唆しています)$n^{n-2}$有効なツリーごとに、すべてのペアの最短パスを計算し、「遠い」条件を満たす頂点を数えます。 これは明らかに不可能です$n=20$、ツリーの数が超指数関数的に増加し、各チェックに少なくともコストがかかるため$O(n)$。 

重要な観察は、「すべての距離が最大で$m$」は木の直径を正確に計算します$m$、1 と 2 は何らかの直径パスの終点である必要があります。 これが修正されると、すべての頂点は、1 と 2 の間のパスに対する相対的な位置によって決定される、制約された幾何学的領域内に配置されます。 

任意の頂点$v$それは満足する$dist(1,v)=m$は、非常に特殊な方法で 1 つのエンドポイントに接続されたサブツリー上に存在する必要があります。つまり、1 からできるだけ遠くにある必要があります。2 についても同様です。両方を同時に満たす唯一の方法は、1-2 パスの両方のエンドポイントから「残りの距離バジェット」の観点から等距離にある領域に接続することです。 

これにより、問題は、バックボーンが長さのパスであるツリー内の 2 つの距離シェルの交点にいくつの頂点を配置できるかについての推論に帰着します。$m$。 この交差を最大化および最小化する構造は、残りの部分をどのように分配するかによって決まります。$n-m-1$直径パスに沿った枝としての頂点。 

最適な構築では、追加のすべての頂点を 1-2 パスの 1 つの内部ノードに接続することも、離れたところに追加の頂点が作成されることを避けるために分散させることもできます。$m$両端から。 

結果として得られる動作は、明確な組み合わせの事実に単純化されます。「遠い」頂点の数は、少なくとも 1 つの交点を作成する方法で追加の頂点を配置できるかどうか、および重なりを最大化するためにすべての頂点を集中できるかどうかにのみ依存します。

 ## アルゴリズムのチュートリアル

 有効なツリーの構造は、頂点 1 と頂点 2 の間の一意のパスによって固定されます。このパスは次の長さを持ちます。$m$。 私たちはこの道をバックボーンとして考えています。$m+1$頂点。 

1. 単純なパスを修正する$1 \rightarrow \dots \rightarrow 2$長さの$m$。 1 と 2 の間の距離が正確であるため、これは強制されます。$m$、ツリー内ではそれ以上の距離は許可されないため、このパスが直径になります。 
2. 残りすべて$n-(m+1)$頂点は、このバックボーンに沿って頂点にサブツリーとして接続する必要があります。 アタッチメントはパス上のどこに配置されるかに応じて、両方の終点までの距離を増加させます。 
3. 頂点$v$距離に達すれば遠い$m$両方のエンドポイントから。 これは、バックボーンへの投影が両方の距離が同時に最大化されるようにする必要があることを意味します。 具体的には、 位置に頂点を付けると$i$パスに沿って、1 までの距離は$i + depth(v)$、そして 2 は$(m-i) + depth(v)$。 
4. 両方が等しいために$m$、次のものが必要です。$$i + d = m \quad \text{and} \quad (m - i) + d = m$$減算すると$i = m-i$、 それで$i = m/2$。 それから$d = m/2$。 これは、遠い頂点が次の場合にのみ存在できることをすぐに示しています。$m$は偶数であり、バックボーンの中点をルートとするサブツリーに存在する必要があります。 
5. したがって、次の場合$m$は奇数であり、両方の方程式を同時に満たす頂点はないため、答えは次のようになります。$0\ 0$。 
6. もし$m$は均一であり、バックボーン上に独特の中間頂点があります。 サブツリーの深さの頂点のみ$m/2$が候補です。 
7. 遠い頂点の数を最大化するには、中間点をルートとする完全なツリーを形成するように残りの頂点をすべて接続し、正確な深さでのノードの数を最大化します。$m/2$。 最良のケースは、すべての余分なノードを、深さの制約を保持する完全な星形の構造に配置し、すべてのノードを許可することです。$n-(m+1)$頂点は、正しく配置された場合に寄与する可能性があります。 
8. 数を最小限に抑えるには、頂点が正確な深さに達しないようにアタッチメントを分散します。$m/2$、すべての余分な頂点を間違った深さまたは間違ったバックボーン位置に効果的に押し込み、ゼロを達成します。 

### なぜ効果があるのか

 1 および 2 までのすべての頂点の距離は、固定直径パス上の接続点と接続されたサブツリー内の深さによって完全に決定されます。 遠距離の方程式系は、アタッチメント インデックスと深さの両方を同時に固定する単一の制約に崩壊します。 この剛性により自由が失われます。中点がそのようなサブツリーをサポートするか、サポートしないかのどちらかです。 この構造が特定されると、すべてのグローバル ツリー構成は、実現可能性の条件を変更することなくノードの再配布に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    # If m is odd, midpoint does not exist as integer position
    if m % 2 == 1:
        print("0 0")
        return

    # number of nodes outside backbone
    extra = n - (m + 1)
    
    # if no extra nodes, only backbone exists and no far vertices
    if extra <= 0:
        print("0 0")
        return

    # In even case, at most one configuration creates far vertices
    # minimum is 0, maximum is all extra nodes + possibly midpoint itself
    print(0, extra)

if __name__ == "__main__":
    solve()
```コードはまずパリティをチェックします。$m$。 いつ$m$が奇数の場合、端点間の対称性を揃えることはできないため、両方の距離制約を同時に満たす頂点は存在しません。 いつ$m$が偶数の場合、強制直径パスの一部ではない頂点の数を計算します。 これらの頂点は、潜在的に遠くの頂点になるように配置できる唯一の頂点です。 最小値は、重要な深さ構成を回避する方法でそれらを配置することによって達成され、最大値は、すべての余分な頂点が遠方の状態に寄与するように中間点の周りに構造を集中させることによって達成されます。 

バックボーンのサイズには注意が必要です$m+1$ここでのオフバイワンエラーは、負の追加カウントまたは不正確な実現可能性の仮定につながるためです。

 ## 特殊なケース

 いつ$m$が奇数の場合、バックボーンには整数の中点がないため、両方の端点までの等しい残り距離を同時に満たすことができる頂点はありません。 たとえば、入力の場合$5\ 3$の場合、直径パスには 4 つの頂点があり、候補頂点は常に一方の端点に他方の端点よりも近いため、遠い条件を満たすことができません。 

いつ$n = m+1$、ツリーは正確にパスになるように強制されます。 追加の頂点をどこにも配置できないため、中点が存在する場合でも、必要な深さに頂点を作成する方法はありません。 例えば、$5\ 4$yields a straight chain and no far vertices.

 追加の頂点が存在するものの、中点から離れて接続されている場合、バックボーンに沿った距離の不均衡が同時均等性を妨げるため、それらの頂点は 2 つの距離制約のうちの 1 つを直ちに満たせなくなります。 これは、最大化するには分散した分岐ではなく中心への集中が必要である理由を説明します。
