 ## 問題の理解

 長さのランダムな配列を生成します$n$、各位置は整数から独立して均一に選択されます。$1$に$k$。 それぞれの$k^n$配列も同様の可能性があります。 

このタスクは、結果の配列に、厳密に増加するチェーンを形成する 4 つの連続する位置が含まれない確率を計算することです。 言い換えれば、インデックスが存在してはなりません。$i$そのような$$a_i < a_{i+1} < a_{i+2} < a_{i+3}.$$連続した要素のみが重要です。 非連続的に増加するサブシーケンスは無関係です。 

出力は実数であるため、この問題は基本的には次の数で割った計数問題になります。$k^n$。 有効な配列の数が必要であり、それを正規化します。 

制約$n, k \le 50$どちらの次元も、次の値を含む状態に対する動的プログラミングに十分小さいことを意味します。$1$に$k$。 しかし、$k^n$成長が非常に速いため、直接列挙することは不可能です。 平$50^{50}$-スケール推論により、慎重に選択された状態表現に対して多項式 DP が強制されます。 

最後の 3 つの値を直接記憶している単純な状態では、すでに次のような状態になります。$O(n \cdot k^3 \cdot k)$トランジション、これは Python の境界線です。 さらに悪いことに、この条件は最後の 3 つの値の正確な形状ではなく、4 つの連続した増加比較のチェーンを形成したかどうかにのみ依存するため、このような状態は不要です。 

微妙なエッジケースが現れるのは、$n < 4$。 その場合、連続する 4 つの要素を当てはめることさえ不可能なので、答えは常に次のようになります。$1$。 DP 式を盲目的に適用する実装は引き続き機能しますが、正規化が慎重に処理されないと、計算が無駄になったり、除算の問題が発生したりする可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、長さのあらゆるシーケンスが生成されます。$n$、長さ 4 のウィンドウをすべてチェックし、厳密に増加しているウィンドウがあるかどうかを確認します。 各小切手にかかる費用$O(n)$、そして、あります$k^n$シーケンスにつながる$O(n \cdot k^n)$、これは最小の制限であっても実現可能性をはるかに超えています。 

重要な観察は、禁止パターンがローカルの連続比較のみに依存するということです。 シーケンスを 1 つの要素だけ拡張する場合、新たなリスクは 3 つの連続する「増加ステップ」 (連続する 4 つの厳密に増加する値に対応する) を作成したかどうかだけです。 

これは、最後の 3 つの値をすべて記憶する必要がないことを意味します。 現在厳密に増加している隣接比較の実行の長さを追跡する必要があるだけです。 以前の値が現在の値より小さい場合、実行を延長します。 それ以外の場合はリセットされます。 ランレングスが 4 に達することは禁止されているため、ランレングスが 3 を超える必要はありません。 

これにより、問題は、位置、最後の値、および現在の増加ラン長に関する動的プログラミングに帰着します。 遷移はローカルであり、残りの履歴とは独立しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot k^n)$|$O(n)$| 遅すぎる |
 | ランレングス状態の DP |$O(n \cdot k^2)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、形成された禁止パターンを検出するのに十分な情報を維持する DP を定義します。 

1. 特定の値で終了し、現在厳密に増加する比較のサフィックスの既知の長さを持つ、指定されたプレフィックス長のすべての有効なシーケンスを表す状態を定義します。 このサフィックスの長さは、連続した回数を表します。$a_{i-1} < a_i$現在の位置で終了します。 
2. 位置 1 の場合、次のすべての値$1$に$k$は可能ですが、比較する前の要素がないため、増加するランレングスは常に 1 になります。 これにより、DP 基本層が初期化されます。 
3. 次の位置ごとに、次の値を選択して、以前に有効だったすべての状態を拡張しようとします。$x$から$1$に$k$。 これにより、前の値からの遷移が作成されます$v$。 
4. 新しい値の場合$x$より大きい$v$、次に、現在増加しているランレングスを 1 だけ延長します。 それ以外の場合、増加する連続は長さ 1 にリセットされます。これは、厳密な不平等連鎖が継続するかどうかを正確にモデル化します。 
5. 結果のランレングスが 4 になる場合、この遷移は禁止されている 4 つの連続した厳密に増加する要素を形成するため、この遷移を破棄します。 
6. すべての有効な遷移を次の DP 層に蓄積します。 
7. すべての位置を処理した後、すべての終了値とランレングスにわたるすべての有効な状態を合計し、次で割ります。$k^n$確率を取得します。 

### なぜ効果があるのか

 DP 状態は、禁止パターンを検出するために必要な唯一の情報、つまり最後の値と、現在の位置で終了する連続増加比較の数だけをエンコードします。 ルール違反は、3 回連続して増加が発生したかどうかのみに依存し、ランレングスが 4 に達することで完全に把握されます。すべての遷移がこのローカル履歴の正確さを保持するため、禁止されたシーケンスは決してカウントされず、すべての許可されたシーケンスには DP を介した対応するパスが 1 つだけあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

# dp[v][l] = number of ways where last value is v and current increasing run length is l
# l in {1,2,3}
dp = [[0] * 4 for _ in range(k + 1)]

for v in range(1, k + 1):
    dp[v][1] = 1

for _ in range(2, n + 1):
    ndp = [[0] * 4 for _ in range(k + 1)]
    for v in range(1, k + 1):
        for l in range(1, 4):
            if dp[v][l] == 0:
                continue
            cur = dp[v][l]
            for x in range(1, k + 1):
                if x > v:
                    nl = l + 1
                else:
                    nl = 1
                if nl <= 3:
                    ndp[x][nl] += cur
    dp = ndp

total = 0
for v in range(1, k + 1):
    for l in range(1, 4):
        total += dp[v][l]

prob = total / (k ** n)
print(prob)
```DP テーブルには、有効なシーケンスの数が、最後の値と増加する隣接比較の現在の連続数によってグループ化されて保存されます。 遷移は、可能なすべての次の値を明示的に反復し、連続増加が継続するかリセットするかを更新します。 

実装の微妙な詳細は、現在の DP 層と次の DP 層の分離です。 同じ配列を再利用すると、単一ステップ内の遷移が汚染されてしまいます。 

## 実用的な例

 ### 例 1:`3 50`以来$n = 3$、シーケンスに 4 つの連続した要素を含めることはできません。 DP は引き続き実行されますが、禁止状態はトリガーされません。 

| ポジション | 状態の概要 |
 | --- | --- |
 | 1 | ランレングス 1 の 50 個の値すべて |
 | 2 | すべてのペアが有効で、増加遷移と非増加遷移に分割されます。 
| 3 | まだ無効な遷移は可能ではありません |

 最終的なカウントはすべてに等しい$50^3$これにより、制約が空虚に真である短いシーケンスを DP が正しく処理することが確認されます。 

### 例 2:`4 4`ここで失敗する唯一の方法は、次のような厳密に増加するシーケンスを選択することです。$1,2,3,4$。 

| ステップ | 観察 |
 | --- | --- |
 | 長さ 4 のシーケンスを構築 | 合計$4^4 = 256$|
 | 無効なシーケンス | 厳密に増加するチェーンは 1 つだけ |
 | 有効なシーケンス | 255 |

 DP は、ランレングス 4 に到達するパスを 1 つだけカウントし、それを破棄し、分析結果と一致します。 

これは、状態空間が小さい場合でも、DP が単一の禁止パターンを正しく分離していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    n, k = map(int, sys.stdin.readline().split())

    dp = [[0] * 4 for _ in range(k + 1)]
    for v in range(1, k + 1):
        dp[v][1] = 1

    for _ in range(2, n + 1):
        ndp = [[0] * 4 for _ in range(k + 1)]

            for l in range(1, 4):

                for x in range(1, k + 1):

                    if nl <= 3:
                        ndp[x][nl] += cur
        dp = ndp

    total = sum(dp[v][l] for v in range(1, k + 1) for l in range(1, 4))
    return str(total / (k ** n))

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは状態の単一層を初期化し、それらを即座に集約し、遷移が発生しないため確率 1 を生成します。 DP は無効な状態チェックを正しく回避します。
