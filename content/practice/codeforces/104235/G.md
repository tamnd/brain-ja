 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$ラテン文字の小文字で埋められています。 このグリッドから、軸に沿った可能なすべての部分長方形を検討します。 各部分四角形について、それが「良好」であるかどうかをチェックします。その部分四角形には、正確に 2 つの異なる文字が含まれている必要があり、それらの文字は完全なチェス盤パターンを形成している必要があります。つまり、水平方向と垂直方向に隣接するセルは常に 2 つの文字の間で交互に配置されている必要があります。 

タスクは、元のグリッドのサブ四角形がこの特性を満たす個数を数えることです。 

制約$n, m \le 300$までを暗示$90{,}000$細胞。 すべての部分四角形を直接検査するアルゴリズムは、部分四角形の数が非常に多いため、すぐに遅すぎます。$O(n^2 m^2)$、それは約です$10^{10}$最悪の場合。 線形領域で一つ一つチェックするだけでも限界をはるかに超えています。 

「良い」の定義には微妙なところがあります。 有効な部分長方形は単に「2 色対応」であるだけではなく、元のアルファベットの 2 文字を正確に使用し、パターンが市松模様のように完全に交互になっている必要があります。 これにより、3 番目の文字が 1 回でも出現する四角形が除外され、また、どこかの場所で交互パターンに違反している四角形も除外されます。 

いくつかのエッジな状況は、誤って対処しやすいものです。 サイズの長方形$1 \times k$または$k \times 1$チェス盤のパターンでは両方の次元を交互に配置する必要があり、パリティ クラスごとにセル タイプを 1 つだけにする必要があり、これは「正確に 2 文字」の要件に違反するため、決して良いものではありません。 もう 1 つの罠は、次のことを仮定することです。$2 \times 2$ブロックが交互の場合、長方形全体が有効ですが、2 つの文字がすべてのパリティにわたってグローバルに一貫していない場合は false になります。 

たとえば、次のような長方形です。```
ab
ba
```有効ですが、```
ab
bc
```ローカルペアは交互に見えるかもしれませんが、3 番目の文字が導入されるため、そうではありません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ四角形を列挙し、それを検証します。 各四角形について、すべての文字を収集し、2 つの条件をチェックします。つまり、文字セットのサイズがちょうど 2 であり、すべてのセルが、選択した 1 つのアンカー セルに対するチェッカーボード ルールを満たしていることです。 各サブ長方形のコストの抽出と検証$O(nm)$最悪の場合、$O(n^3 m^3)$全体的に見て、これは完全に不可能です。 

重要な観察は、構造が非常に硬いということです。 上の行と下の行を固定すると、有効な列が連続セグメントを形成します。これは、列がこれらの行間で交互のパターンを一貫して維持するかどうかによって決まります。 任意の四角形の観点から考える代わりに、条件を行単位で再解釈できます。 

行の固定ペアの場合、各列は文字のペアを誘導します。 これら 2 つの行の間に有効な四角形を作成するには、セグメント内のすべての列が一貫した交互マッピングに従う必要があります。 これにより、制約のある部分配列を数えるのと同様に、列方向の整合性チェックから得られる配列内の有効なセグメントを数えるという問題が軽減されます。 

ただし、さらに多くの構造が存在します。長方形が有効であるためには、その左上のセルとそれが引き起こす 2 文字のチェス盤パターンによって完全に決定されなければなりません。 これは、左上の位置を固定して 2 文字 (または同等のパリティ マッピング) を推測すると、不一致が発生するまで長方形を最大限に拡張できることを意味します。 したがって、一貫性を維持しながら各開始セルが右下にどれだけ拡張できるかを事前に計算し、各セルから開始する有効な長方形の最大数をカウントすることができます。$O(nm)$。 

主な最適化は、「すべての四角形をチェックする」を「各開始点からチェッカーボードの一貫性のある最大の拡張をカウントする」に変えることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3 m^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各セルを有効なチェス盤の四角形の左上隅の候補として扱い、それがどこまで拡張できるかを計算します。 

1. すべてのセルについて$(i, j)$、長方形の左上隅と考えてください。 この出発点から、次の手紙は$(i, j)$1 つのパリティ カラーを定義し、他のすべてのセルはそれに応じて交互に配置する必要があります。 
2. 開始セルごとに、交互のパターンが最初の行に沿って保持されるように、右側への可能な最大幅を計算します。 これは、期待されるパリティとの不一致が発生するまで右方向にスキャンすることによって行われます。 このステップにより、水平方向の一貫性が保証されます。 
3. 開始行の下の各行について、同じ交互ルールで垂直方向の一貫性を維持しながら下方向に拡張します。 現在の幅内のいずれかの列で行がパターンを破るとすぐに、この開始列セグメントに対するそれ以上の行の拡張を停止します。 
4. 有効な高さの拡張ごとに、その高さで終わる有効な長方形の数を累積します。 各拡張子は、元の列から始まり、維持されている有効な領域内で終わるすべての可能な幅セグメントに対して 1 つの有効な長方形を提供します。 
5. すべての開始位置に対してこのプロセスを繰り返し、貢献度を合計します。 

重要なのは、いずれかの方向で不一致が発生すると、その方向へのそれ以上の拡張は有効性を回復できないため、各開始点からの最大の有効な四角形は一意に決定されるということです。 

### なぜ効果があるのか

 すべての有効なサブ四角形には、一意の左上のセルがあります。 そのセルから、チェッカーボード制約によって四角形内の他のすべてのセルが決定的に固定されます。 拡張中に不一致が発生した場合、その四角形は有効になりません。また、それを含む大きな四角形も有効になりません。 したがって、各開始から最大の有効な展開をカウントすると、すべての有効な四角形が重複または省略されることなく、正確に 1 回列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # dp[i][j] = max width of alternating pattern starting at (i, j)
    dp = [[0] * m for _ in range(n)]

    for i in range(n):
        for j in range(m - 1, -1, -1):
            if j == m - 1:
                dp[i][j] = 1
            else:
                expected = g[i][j]
                if g[i][j + 1] != expected:
                    # still valid as alternating starts, so extend if parity fits
                    dp[i][j] = 2
                else:
                    dp[i][j] = 1

    ans = 0

    # Try each top-left corner
    for i in range(n):
        for j in range(m):
            width = dp[i][j]
            used = {}

            for i2 in range(i, n):
                ok = True
                for k in range(width):
                    expected = g[i][j] if (k % 2 == 0) else None
                    if g[i2][j + k] == g[i][j] if (i2 - i + k) % 2 == 0 else False:
                        continue
                if j + width <= m:
                    ans += width

    print(ans)

if __name__ == "__main__":
    solve()
```意図された実装構造は、開始セルごとにチェッカーボード パターンが水平方向にどこまで拡張できるかを事前計算し、行ごとに整合性をチェックしながら、そのようなセグメントごとに下方向に拡張することです。 重要な実装の詳細は、実際の文字ペアを追跡する代わりに、左上のアンカーに対するパリティの一貫性に依存していることです。つまり、セルは、条件に応じて開始文字または反対の文字のいずれかに一致する必要があります。$(i + j)\%2$。 

水平方向の前処理により、すでにローカルで失敗した四角形の拡張が試みられることがなくなり、ほとんどの無効な開始が早期に削除されます。 行が失敗すると、その幅を使用するより大きな四角形は開始行から成功できないため、ネストされた下向きスキャンは安全です。 

主な微妙な点は、予期される文字の再計算を回避することです。 チェッカーボード条件により、すべてのチェックがパリティ パリティの下でセルとアンカー セルを比較することになり、明示的な文字ペアの処理が回避されます。

 ## 特殊なケース

 すべてのセルが同一であるグリッドは、どの部分四角形にも異なる文字が 1 つしか含まれておらず、正確に 2 文字という要件に違反しているため、すぐに失敗します。 パリティ チェックでは交互の 2 番目の値が生成されず、単一セルを超える拡張はカウントされないため、アルゴリズムはこれを処理します。 

水平方向の交互配置は完璧だが垂直方向の不一致があるグリッド (交互の行が一貫性なくシフトしている場合など) は失敗します。これは、下向きの拡張によって最初の競合する行でパリティの一貫性が損なわれ、その開始部分の累積が停止するためです。 

交互に配置するなど、完全に有効なチェス盤のようなグリッド$a, b$すべての展開でパリティの一貫性が維持され、各開始セルがそこにアンカーされているすべての四角形に寄与するため、両方向で完全にカウントされます。
