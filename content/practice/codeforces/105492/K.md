 ## 解決策
 ## 問題の理解

 一連の歌詞を表す単一の文字列が与えられます。 圧縮操作は 1 回だけ実行できます。 この操作では、文字列から空ではない部分文字列 t を 1 つ選択し、元の文字列内のすべての t を、文字列内に以前に出現しなかった新しい文字に置き換えます。 これらの置換は、すべての出現に対して同時に実行されますが、選択された部分文字列と完全に一致する出現に対してのみ実行されます。 

この圧縮の後、新しい文字列 s' が得られるため、元の文字列を保持する必要はなくなります。 代わりに、選択した部分文字列 t 自体と圧縮文字列 s' の 2 つを保存します。 選択のコストは全長 |t| です。 + |s'|。 課題は、この合計を最小化する方法で t を選択することです。 

ここでの重要な構造は、より長い部分文字列を選択すると t のコストが高くなりますが、より長いパターンの出現回数が減ったり、異なる形で重なり合ったりするため、s' はさらに削減される可能性があるということです。 逆に、短い部分文字列は安価ですが、多くの場合あまり圧縮されません。 

入力の長さは最大 5000 で、3 次またはそれより悪いアプローチは除外されます。 O(n^2 log n) または O(n^2) を中心とした解決策は考えられますが、慎重にカウントせずにすべての部分文字列の文字列を繰り返し再構築するとタイムアウトになります。 

微妙な点は、オーバーラップがどのように動作するかです。 文字列内で t がそれ自体と重複する場合でも、置換では動的に変化する文字列ではなく、元の文字列内の出現を考慮する必要があります。 たとえば、「aaaaa」では、t = "aaa" を選択すると、元の文字列の位置 1 と 2 で重複が発生し、一致する場合は両方を置き換えることができます。 左から右に処理して文字列を変更する単純なアプローチでは、重複する一致が誤ってブロックされてしまいます。 

もう 1 つのエッジ ケースは、有益な圧縮が存在しない場合です。 たとえば、「abcabd」は部分的にのみ繰り返される構造を持ち、場合によっては最適な戦略が事実上まったく圧縮されないこともあります。これは、置換によってコストを補うほど最終的な長さが短縮されない部分文字列を選択することを意味します。 

最後に、t が 1 回しか出現しない場合、|t| を追加する間 s' は同じ長さを保つため、圧縮は常に有害になります。 料金。 このようなケースでは、つまらない答えが大半を占めるに違いありません。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての部分文字列 t が試行されます。 t ごとに文字列をスキャンし、出現するすべての t を単一の文字に貪欲に置き換え、結果の文字列を構築してその長さを計算します。 O(n^2) 個の部分文字列があり、各スキ​​ャンのコストが O(n) であるため、時間は O(n^3) になります。これは、n = 5000 の場合には遅すぎます。これは、約 1,250 億文字の比較に相当します。 

重要な観察は、固定部分文字列 t の場合、すべての有効な開始位置での出現を数えた場合に、重要なのは文字列内でその部分文字列が何回出現するかだけであるということです。 置換をシミュレーションする必要はありません。 必要なのは、置換できるオカレンスの数と、文字列がどの程度縮小するかを知ることだけです。 

t の長さが L で、K 回出現する場合、出現するたびに L 文字が 1 文字に置き換えられ、全体の長さが K・(L−1) だけ減少します。 したがって、圧縮された文字列の長さは n − K · (L−1) になります。 総コストは L + n − K・(L−1) です。 単純化すると、n + L − K・(L−1) が得られます。 n は固定なので、K・(L−1) − L を最大化することが目標となります。 

これにより、問題は、すべての部分文字列について、文字列内で何回出現するかを見つけるという問題に再構成されます。 これは古典的なパターン カウントの問題であり、接尾辞ベースの構造または事前計算された度数表を使用したローリング ハッシュを使用して効率的に実行できます。

LCP 構造を持つ接尾辞オートマトンまたは接尾辞配列を使用して、すべての部分文字列の出現数を計算できます。 n ≤ 5000 の場合のより単純な競争プログラミング アプローチは、接尾辞配列と LCP を使用して、接尾辞配列内の間隔を拡張することで合計 O(n^2) 内のすべての部分文字列の出現をカウントすることです。 それぞれの個別の部分文字列は間隔に対応し、その頻度はその間隔のサイズになります。 

O(1) または償却された O(1) 内の任意の部分文字列の頻度を計算できたら、すべての部分文字列を反復処理し、それらの寄与を計算し、最良のものを取得します。

 ## アルゴリズムのチュートリアル

 構造化された方法ですべての個別の部分文字列を列挙し、その頻度を計算するには、サフィックス配列と LCP 配列を利用します。 

1. 文字列のサフィックス配列を構築します。 これにより、すべての接尾辞が辞書順に並べられ、連続した範囲で共有接頭辞を表すことができるようになります。 
2. 隣接するサフィックス間に LCP 配列をこの順序で構築します。 LCP 値は、2 つの隣接するサフィックスが共有する文字数を示します。これは、繰り返される部分文字列を識別するために不可欠です。 
3. サフィックス配列内の各位置について、そのサフィックスから始まる部分文字列が解釈されます。 すべての新しい部分文字列は、前の部分文字列を拡張するか、新たに開始することに対応します。 LCP 情報を使用すると、重複の再カウントが回避され、それぞれの異なる部分文字列が 1 回だけ考慮されるようになります。 
4. 候補の各部分文字列について、その長さ L と頻度 K を計算します。頻度は、連続範囲内のいくつの接尾辞が少なくともこの接頭辞を共有するかによって決まります。頻度は、LCP 境界上の単調スタックを使用して導出できます。 
5. 各部分文字列について、ゲイン値 K・(L−1) − L を計算します。すべての部分文字列の最大値を追跡します。 
6. 答えは、n にこの最大ゲイン寄与の負の値を加えたもの、つまり n − best_gain です。 

重要な部分はステップ 4 で、LCP はサフィックス全体にわたる同一のプレフィックス部分文字列の最大間隔を定義するバリアとして機能します。 これにより、各部分文字列が正確に 1 回、正しい多重度でカウントされることが保証されます。 

### なぜ効果があるのか

 各部分文字列は、それを接頭辞として共有する一連の接尾辞に一意に対応します。 サフィックス配列では、これらのサフィックスは連続したセグメントを形成します。 LCP 配列により、部分文字列が隣接するサフィックスに共通でなくなる場所を正確に特定できることが保証されます。 これらの境界を維持することにより、すべての部分文字列が正確に 1 回表現され、その頻度は接尾辞間隔のサイズと正確に一致します。 コストの計算式は長さと頻度のみに依存するため、そのような間隔をすべて列挙することで、考えられるあらゆる圧縮の選択肢を重複や省略なく評価することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = [ord(c) for c in s]
    tmp = [0] * n

    while True:
        sa.sort(key=lambda i: (rank[i], rank[i + k] if i + k < n else -1))
        tmp[sa[0]] = 0
        for i in range(1, n):
            prev = sa[i - 1]
            cur = sa[i]
            tmp[cur] = tmp[prev] + (
                (rank[cur], rank[cur + k] if cur + k < n else -1)
                != (rank[prev], rank[prev + k] if prev + k < n else -1)
            )
        rank, tmp = tmp, rank
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1
    return sa

def build_lcp(s, sa):
    n = len(s)
    rank = [0] * n
    for i, v in enumerate(sa):
        rank[v] = i

    h = 0
    lcp = [0] * (n - 1)
    for i in range(n):
        r = rank[i]
        if r == 0:
            continue
        j = sa[r - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[r - 1] = h
        if h:
            h -= 1
    return lcp

def solve():
    s = input().strip()
    n = len(s)

    if n == 1:
        print(2)
        return

    sa = build_suffix_array(s)
    lcp = build_lcp(s, sa)

    stack = []
    best = 0

    for i in range(n):
        length = n - sa[i]
        cur_lcp = lcp[i] if i < n - 1 else 0

        width = 1
        while stack and stack[-1][0] >= cur_lcp:
            prev_lcp, prev_width = stack.pop()
            width += prev_width

            gain = prev_lcp * (width) - prev_lcp
            best = max(best, gain)

        stack.append((cur_lcp, width))

    while stack:
        prev_lcp, width = stack.pop()
        gain = prev_lcp * (width) - prev_lcp
        best = max(best, gain)

    print(n - best)

if __name__ == "__main__":
    solve()
```サフィックス配列の構築は、2k の長さのランクで繰り返しソートする 2 倍法によって行われます。 LCP 構築では、Kasai のアルゴリズムを使用して、ソートと比較して線形時間で最長の共通プレフィックスを計算します。 

スタック ロジックは、LCP 値をヒストグラムとして処理します。 各エントリは、潜在的な部分文字列の長さの境界を表します。 幅は、少なくともそのプレフィックス長を共有するサフィックス間隔の数に対応します。 LCP が低下すると、それ以上拡張できない部分文字列の寄与を確定します。 

最後にスタックをフラッシュするときは、境界を慎重に処理する必要があります。そうしないと、最後のサフィックスまでの部分文字列が失われます。

これは、ゲインが周波数に対して線形にスケールするが、長さに関しては線形にしか減算しないため、より長い繰り返しブロックが短いブロックよりも優勢であることを確認します。

 ## 特殊なケース

 「a」などの 1 文字の文字列を使用すると、アルゴリズムは圧縮を完全に回避します。 サフィックス配列にはサフィックスが 1 つだけ含まれており、スタック ロジックはゲインを生成しないため、解釈に応じて出力は 2 のままになるか、事実上変更されません。 実装ではこのケースを明示的に処理します。 

「aaaaa」などの完全に繰り返しの文字列では、LCP 値の重複が最大限に生じます。 スタックは増加する幅を蓄積し、「a」、「aa」、「aaa」などの部分文字列のゲインを正しく集計します。 このアルゴリズムでは、単純なスキャンではなく間隔幅を通じて重複する発生がカウントされるため、二重カウントが回避されます。 

「abcabd」などの繰り返しのない文字列では、LCP 値はすべて 0 になります。 スタックは意味のある幅を蓄積することはなく、すべての候補ゲインはゼロであるため、圧縮では改善できないため、ソリューションは元の長さを正しく出力します。
