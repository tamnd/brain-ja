 ## 解決策
 ## 問題の理解

 ゲームのスコアボードから一連のスナップショットを受け取ります。各スナップショットには、その時点での 2 つの競合チームのスコアを表す 2 つの整数が含まれています。 これらのスナップショットは到着順に送信されましたが、その順序は試合が進行した実際の時系列順序を反映していない可能性があります。 

タスクは、指定されたシーケンスが実際の試合の有効なタイムラインを表すことができるかどうかを判断することです。 有効なタイムラインとは、あるスナップショットから次のスナップショットまで、どちらのチームのスコアも決して減少しないことを意味します。 どちらのスコアも同じまままたは増加する可能性がありますが、時間の経過とともに減少することはありません。 

したがって、タイムラインを再構築したり、何かを並べ替えたりすることはありません。 指定された順序が両方の座標の単調性制約を同時に遵守しているかどうかを確認しているだけです。 

制約は小さく、スナップショットは最大 100 個で、各スコアは 0 から 100 の間です。これにより、二次関数さえあれば問題なく安全であり、線形スキャンで十分であることがすぐにわかります。 高度なデータ構造や検索は必要ありません。 

この問題の主な微妙な点は、「時系列の順序」が何を意味するのかを理解することです。 明示的に時刻で並べ替えたり、タイムスタンプを比較したりするものではありません。 私たちが持っている唯一の手がかりは、スコアは時間の経過とともに増加するだけであるということです。 この 1 つのルールによって有効性が完全に決まります。 

いくつかの危険な状況が素朴な思考を打ち破る可能性があります。 

合計点が上がることだけを確認すると失敗する可能性があります。 たとえば、(2, 5) の後に (3, 4) が続く場合、合計 7 の後に 7 が続くため、合計は減りませんが、2 番目のチームのスコアは 5 から 4 に下がり、無効になります。 これは、不注意な解決策によって誤って受け入れられてしまいます。 

各スナップショットが最大順序または最小順序など、部分的な意味で「以上」であることのみをチェックする場合も失敗します。 たとえば、(1, 10) から (2, 0) までの最大値は増加しますが、両方の成分で単調性に違反します。 

したがって、正しい状態が連続するスナップショット間でコンポーネントごとにチェックされる必要があります。 

## アプローチ

 ブルートフォースの考え方では、スナップショットのすべてのペアを考慮し、単調性制約をグローバルに満たす一貫した順序が存在するかどうかを確認することで、一貫性を検証しようとする可能性があります。 これは、半次数グラフを構築し、有効な線形拡張を確認することに似ています。 これは理論的には正しいですが、入力順序は固定されており、順序を変更することはできないため、ここではまったく必要ありません。 

代わりに、シーケンスが時間順に有効である場合、隣接するすべての遷移が両方のチームの非減少値を保持する必要があることがわかります。 逆に、隣接するすべてのペアがこの条件を満たす場合、単調性は推移的であるため、シーケンス全体が有効である必要があります。どのステップもいずれかの座標を減少させなければ、前のスナップショットは後のスナップショットを侵害することはできません。 

これにより、問題は配列に対するシングル パス チェックに削減され、各ステップで単純な不等式条件が検証されます。

 | --- | --- | --- | --- |
 | ブルート フォース (グローバル一貫性推論) | O(n²) 以上 | O(n) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 1. すべてのスナップショットを指定された順序で読み取り、整数のペアとして保存します。 
2. 2 番目のスナップショットから最後のスナップショットまでを繰り返します。 
3. 位置 i の各スナップショットについて、位置 i-1 の前のスナップショットと比較します。 
4. いずれかのチームのスコアが i-1 から i に減少した場合、直ちにシーケンスが無効であると結論付けます。 
5. 減少が見つからずにループが終了した場合、シーケンスは有効であると結論付けます。 

単調性の違反は、何らかの即時遷移で最初に現れる必要があるため、各ステップは隣接性に焦点を当てます。 ドロップが発生した場合、複数のステップにわたって「非表示」にすることはできません。 

### なぜ効果があるのか

重要な不変条件は、各位置 i を処理した後、両方のスコア シーケンスが減少しないという意味で、0 から i までのすべてのスナップショットが一貫していることです。 どこかの時点で減少が検出された場合、不変式が破られ、シーケンスが正しく拒否されます。 

隣接するペアが単調性に違反しない場合、インデックス i < j について、非減少特性を繰り返し適用することで、a[i] ≤ a[j] と b[i] ≤ b[j] の両方が保証されます。 これにより、シーケンス全体が一時的に有効であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
prev_a, prev_b = map(int, input().split())

ok = True

for _ in range(n - 1):
    a, b = map(int, input().split())
    if a < prev_a or b < prev_b:
        ok = False
    prev_a, prev_b = a, b

print("yes" if ok else "no")
```このソリューションでは、前方スキャン中に前のスナップショットのみを保持します。有効性は連続する遷移のみに依存するため、これで十分です。 変数`prev_a`そして`prev_b`タイムラインで最後に確認された有効な状態を表します。 

条件チェック`a < prev_a or b < prev_b`どちらのスコアも減少できないというルールを直接エンコードします。 以前の値を無条件に更新すると、違反が検出された後でも完全なシーケンスのチェックが継続されますが、早期に中断する可能性もあります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各スナップショットを 1 回だけ処理し、一定時間の比較を実行します。 
| スペース | お(1) | 前のスコアのペアのみが保存されます。 

制約により最大 100 個のスナップショットが許可されますが、これがはるかに大きい場合でも、リニア スキャンの効率は維持されます。 すべての入力値を少なくとも 1 回読み取る必要があるため、このソリューションは最適です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    prev_a, prev_b = map(int, input().split())

    ok = True

    for _ in range(n - 1):
        a, b = map(int, input().split())
        if a < prev_a or b < prev_b:
            ok = False
        prev_a, prev_b = a, b

    return "yes" if ok else "no"

# provided samples
assert run("4\n1 0\n2 0\n4 0\n4 1\n") == "yes"
assert run("3\n0 0\n1 0\n0 2\n") == "no"

# minimum size
assert run("1\n5 7\n") == "yes"

# monotone increase both
assert run("3\n0 0\n0 1\n2 3\n") == "yes"

# single drop in second coordinate
assert run("3\n0 0\n1 2\n2 1\n") == "no"

# flat sequence
assert run("4\n2 2\n2 2\n2 2\n2 2\n") == "yes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 スナップショット | はい | 最小限のエッジケース |
 | 厳密に増加 | はい | 通常の有効な進行 |
 | 2 番目の座標ドロップ | いいえ | 無効な減少を検出します |
 | 定数値 | はい | 等価性は許可されます |

 ## 特殊なケース

 単調性に違反する以前の状態がないため、単一のスナップショットを含む最小限の入力は常に有効なタイムラインを表します。 アルゴリズムは最初のペアを読み取り、ループに入らずにすぐに「yes」を出力します。 

すべてのスコアがスナップショット間で同一のままであるフラット シーケンスも有効です。 それぞれの比較`a < prev_a or b < prev_b`等価性が許可されるため、 false と評価されます。 不変式はすべてのステップで自明に成り立ちます。 

微妙な失敗例としては、一方の座標が大幅に増加しているのに、もう一方の座標がわずかに減少している場合があります。 たとえば、(1, 10) の後に (5, 3) が続くと全体的な進行のように見えますが、2 番目の座標の低下により直ちに無効になります。 アルゴリズムは、最初の違反遷移でこれを捕捉し、正しく拒否します。
