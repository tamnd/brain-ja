 ## 解決策
 ## 問題の理解

 各ノードが処理ステップを表す有向グラフとしてモデル化されたファクトリーが与えられます。 すべてのステップは、指定された確率で独立して失敗します。 これらの固有の障害に加えて、有向依存関係もあります。ステップが失敗すると、それに依存するすべてのステップも同様に失敗し、この影響は依存関係グラフを通じて伝播します。 

実際に答える必要がある唯一の質問は、カスケード自体に関するものではなく、選択に関するものです。 すべてのステップの中で、失敗する可能性が最も低いステップを選択します。 出力は、選択したステップが失敗しない確率です。つまり、失敗確率を引いた値を出力します。 

グラフ構造と依存関係の伝播は中心的なもののように思えますが、要求された量の最終的な計算には使用されません。 これらは、問題が伝播中のノードの到達可能性や生存確率をまったく求めていないことがわかれば、無関係な障害カスケードを定義するだけです。 選択は純粋に与えられた独立した確率に基づいて行われます。 

制約は大きく、最大 100,000 ノードと 100,000 エッジです。 カスケードをシミュレートしたり、ノードごとにグラフの閉包を計算しようとしたソリューションは、遅すぎます。 ノードあたり 1 つの BFS または DFS であっても、最悪の場合は O(n(n + m)) に達しますが、これは不可能です。 

素朴な推論による微妙な失敗例は、依存関係を考えすぎて、伝播後の「有効な失敗確率」を計算しようとすることです。 たとえば、ノード A が B に依存し、B が A に依存する場合、問題で計算が求められていないにもかかわらず、サイクルの同時故障確率を誤って計算しようとする可能性があります。 

もう 1 つのエッジ ケースは、すべての確率が等しい場合です。 答えは、いずれか 1 つを選択し、1 からその値を引いた値を出力する必要があります。 すべてが 0.999 の場合、出力は 0.001 になります。 

最後に、確率には 0 や 1 などの値が含まれます。最小確率が 0 の場合、答えは 1 です。1 の場合、答えは 0 です。 

## アプローチ

 ブルートフォース解釈は、グラフを文字通りに考慮することから始まります。 各ノードについて、依存関係をカスケードした後に最終的に障害が発生する確率を計算しようとする場合があります。 これには、サイクルを含む有向グラフを介した障害の伝播のモデル化が含まれます。基本的に、強く接続されたコンポーネントにわたる計算が必要となり、凝縮された DAG に沿って確率を伝播します。 

独立性の仮定を単純化したとしても、閉包効果を判断するにはエッジを繰り返し走査する必要があります。 到達可能な障害ノードをノードごとに再計算すると、グラフの走査が繰り返されることになり、密なグラフでは実際にはこれが二次関数になります。 

ただし、重要な観察は、カスケードが出力に無関係であるということです。 この問題では、ステップが依存関係を存続する確率は決して求められません。 すべてのステップの中で、指定された失敗確率が最小のものを選択し、その生存確率を出力するだけです。 

したがって、グラフ構造全体は無視できます。 必要なのは確率に対する 1 回の線形スキャンだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ノードごとのグラフ伝播) | O(n(n + m)) | O(n + m) | 遅すぎる |
 | 最適 (最小スキャン) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を配列内の最小値の選択とそれの変換に要約します。 

1. すべての失敗確率を配列に読み取ります。 エッジは選択基準に影響を与えないため、まったく処理しません。 
2. 変数を維持する`best`2.0 など、考えられる確率よりも大きい値に初期化されます。 これにより、これまでに確認された最小失敗確率が保存されます。 
3. 各確率を繰り返します。 それぞれの値について、次と比較します。`best`そして更新します`best`それが小さい場合。 これにより、1 回のパスの後、`best`システム内の最小故障確率に等しい。 
4. 答えを次のように計算します。`1 - best`。 これは、選択したステップが失敗しない確率を表します。 
5. 十分な精度で結果を出力します。 

エッジを無視する背後にある理由は、依存関係に起因する障害は、確率的障害の伝播下でのすべてのステップの存続または到達可能性について質問された場合にのみ問題になるということです。 ここでは、確率的イベントの前に選択が行われるため、依存関係の構造がどのノードが選択されるかに影響を与えることはありません。 

### なぜ効果があるのか

 この問題は、固有の故障確率のみに基づいて決定論的な選択ルールを定義します。 依存関係はこれらの所定の確率を変更せず、選択基準の一部ではないため、最適なステップは、まさに提供されたリストの全体的な最小値になります。 失敗確率から生存確率への変換は直接の補数であるため、正しさは定義から直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    probs = list(map(float, input().split()))
    
    best = 2.0
    for p in probs:
        if p < best:
            best = p
    
    ans = 1.0 - best
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、依存関係エッジはステップの選択とは無関係であるため、完全に無視されます。 唯一の微妙な点は数値の安定性です。Python の float 減算に依存していますが、必要な精度が 1e-6 相対または 1e-200 絶対であることを考慮すると、これで十分です。 

の初期化`best`2.0 に設定すると、すべての確率が [0, 1] 内にある場合でも正確さが保証されます。 最後の減算では生存確率を直接計算します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, sys.stdin.readline().split())
    probs = list(map(float, sys.stdin.readline().split()))
    
    best = 2.0
    for p in probs:
        best = min(best, p)
    
    return str(1.0 - best)

# provided samples
assert abs(float(run("2 2\n0.600 0.300\n1 2\n2 1\n")) - 0.7) < 1e-9
assert abs(float(run("2 1\n0.300 0.600\n1 2\n")) - 0.7) < 1e-9

# custom cases
assert abs(float(run("1 0\n0.000\n")) - 1.0) < 1e-9
assert abs(float(run("3 0\n0.999 0.999 0.999\n")) - 0.001) < 1e-9
assert abs(float(run("3 0\n1.000 0.500 0.800\n")) - 0.0) < 1e-9
assert abs(float(run("4 2\n0.2 0.9 0.1 0.3\n1 2\n3 4\n")) - 0.9) < 1e-9
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1、p=0 | 1 | 最小サイズと障害ゼロ |
 | すべて0.999 | 0.001 | 均一な値 |
 | 1.0を含む | 0.0 | 境界完全失敗 |
 | 混合値 | 正しい最小値の選択 | 一般的な正しさ |

 ## 特殊なケース

 1 つのエッジ ケースは単一ノードです。 入力用`1 0`確率的に`0.000`、アルゴリズムセット`best = 2.0`、次にそれを更新します`0.0`。 出力は次のようになります`1.0`、唯一のステップが決して失敗しないため、これは定義と一致します。 

もう 1 つの特殊なケースは、すべての確率が等しいということです。 のために`0.999 0.999 0.999`、最小限が残ります`0.999`順序やエッジに関係なく。 出力は`0.001`、補体の定義と一致します。 

最後のエッジケースは、次のような極端な値です。`1.000`。 アルゴリズムは正しく維持します`best = 1.0`、出力は次のようになります`0.0`、解釈と一致する確実な失敗を意味します。
