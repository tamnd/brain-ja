 ## 解決策
 ## 問題の理解

 私たちには何日かのタイムラインが与えられており、その日に美術館を訪れることを選択した場合、毎日の「不快コスト」がわかっています。 これに加えて、複数の展示会があり、各展示会は連続した範囲の日に渡って開催されます。 その範囲内のいずれかの日に訪問すれば、その展示を鑑賞したとカウントするのに十分です。 

タスクは、一連の訪問日を選択することです。 すべての展示間隔には、選択した日が少なくとも 1 つ含まれている必要があり、合計コストは、選択したすべての日の不快感値の合計になります (複数の展示会を対象とする場合でも、1 日あたり 1 回カウントされます)。 目標は、この総コストを最小限に抑えることです。 

これは基本的にライン上のカバー問題です。すべての間隔に少なくとも 1 つの選択された点が含まれるように、最小コストの点のサブセットを選択する必要があります。 

この制約では、最大 200,000 日および 200,000 の間隔が許可されます。 日のサブセットをテストしたり、間隔ごとにカバレッジを単純に再計算しようとしたソリューションは失敗します。 平$O(nm)$のオーダーになるので推論は不可能です$4 \cdot 10^{10}$操作。 

微妙なエッジ ケースは、ローカルな選択が相互作用する重複する間隔から発生します。 たとえば、次のことを考えてみましょう。```
n = 5
cost = [5, 4, 3, 2, 1]
intervals: [1,3], [2,4], [3,5]
```世界的に最も安い日 (5 日目) を常に選択するという欲張った選択は、5 日目はそれより前の期間をカバーしていないため、失敗します。 間隔ごとに最も安い日を個別に選択するという別の単純なアイデアは、冗長な日を選択して共有構造を見逃す可能性があるため、失敗します。 

正しいソリューションでは、日を選択すると、その日が多くの間隔にわたって最適に再利用され、各間隔が以前の選択を認識して処理されることが保証されなければなりません。 

## アプローチ

 この強引なアイデアは、日の各サブセットを候補解として扱い、それがすべての間隔をカバーしているかどうかをテストすることです。 各サブセットについて、すべての間隔をスキャンし、選択した日がその中に少なくとも 1 つあるかどうかを確認します。 意味のあるサブセットのみを考慮するようにプルーニングしたとしても、組み合わせの数は指数関数的に増加します。$n$, したがって、これは実行できません。 

もう少し構造化された総当り的なアプローチは、間隔を 1 つずつ処理し、カバーされていない間隔が見つかった場合は常に、その間隔内の日を選択することです。 間隔内で利用可能な最も安い日を常に選択すると、戦略は局所的に最適になります。 ただし、難しいのは、後の間隔が以前の選択によってすでにカバーされている可能性があるため、カバレッジを動的に追跡する必要があることです。 

重要な構造的観察は、区間は独立した制約であり、少なくとも 1 つの選択された点が区間内に存在するかどうかのみを考慮するということです。 日を選択すると、多くの間隔を同時に提供できます。 これは、正しいエンドポイントによってソートされた間隔に対する貪欲な戦略を示唆しています。つまり、間隔に遭遇した場合、できるだけ遅くその間隔がカバーされるようにし、以前の制約との干渉を最小限に抑えます。 

これを効率的にサポートするには、間隔に選択した日がすでに含まれているかどうかを確認し、含まれていない場合はその間隔内で最も安い日を見つけるという 2 つの操作が必要です。 どちらもセグメント ツリーで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(2^n \cdot n \cdot m)$|$O(n)$| 遅すぎる |
 | セグメントツリーによるインターバル貪欲 |$O((n+m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つのセグメント ツリーを数日間にわたって保守します。 1 つは、日付がすでに選択されているかどうかを保存します。 他の店舗の日のコストを表示し、範囲内で最小コストの日を見つけることをサポートします。 

1. すべての間隔を右のエンドポイントで昇順に並べ替えます。 これにより、間隔を処理するときに、より早く終了する以前のすべての間隔が確実に解決されます。 
2. インターバルごとに$[s, e]$、以前に選択した日にすでにカバーされているかどうかを確認します。 これは、カバレッジ セグメント ツリーにその範囲内に選択されたポイントがあるかどうかを問い合わせることによって行われます。 
3. 間隔がすでにカバーされている場合は、すでに少なくとも 1 つの選択された日があるため、何もせずに次に進みます。 
4. カバーされていない場合は、内側の日を選択する必要があります$[s, e]$。 コスト セグメント ツリーをクエリして、その範囲内で最小コストの日のインデックスを見つけます。 
5. 選択した日を、補償範囲構造で選択されたものとしてマークします。 この 1 つの選択により、将来の複数の間隔が満たされる可能性があります。 
6. すべての間隔が処理されるまで続行します。 

この貪欲な順序が重要である理由は、正しいエンドポイントでは初期の間隔が小さいか等しいためです。 後のインターバルに到達するまでに、私たちはすでに以前の必要な選択にコミットしているため、実現可能性を損なう可能性のある決定を再検討することを避けます。 

### なぜ効果があるのか

 現在カバーされていない間隔を処理する瞬間を考えてみましょう。 有効なソリューションには、この間隔内に少なくとも 1 つの選択された日が含まれている必要があります。 すべての可能な選択肢の中で、同じ間隔内でより高価な有効な選択肢をより安価な選択肢に置き換えても、すでに処理された間隔の範囲を無効にすることはできないため、間隔内で最も安い日を選択することによって実現可能性が悪化することはありません。 右のエンドポイントを増やして処理するため、以前の間隔は将来の間隔に依存することはなく、すべての決定はカバレッジを削除せずに追加するだけです。 これにより、最小限の増分コストで各間隔が確実に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTreeMin:
    def __init__(self, arr):
        self.n = len(arr)
        self.inf = (10**30, -1)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [self.inf] * (2 * self.size)
        for i, v in enumerate(arr):
            self.data[self.size + i] = (v, i)
        for i in range(self.size - 1, 0, -1):
            self.data[i] = min(self.data[2 * i], self.data[2 * i + 1])

    def range_min(self, l, r):
        l += self.size
        r += self.size
        res = self.inf
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.data[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.data[r])
                r -= 1
            l //= 2
            r //= 2
        return res

class SegTreeSum:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.data = [0] * (2 * self.size)

    def update(self, i, v):
        i += self.size
        self.data[i] = v
        i //= 2
        while i:
            self.data[i] = self.data[2 * i] + self.data[2 * i + 1]
            i //= 2

    def range_sum(self, l, r):
        l += self.size
        r += self.size
        s = 0
        while l <= r:
            if l % 2 == 1:
                s += self.data[l]
                l += 1
            if r % 2 == 0:
                s += self.data[r]
                r -= 1
            l //= 2
            r //= 2
        return s

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    intervals = [tuple(map(int, input().split())) for _ in range(m)]
    intervals.sort(key=lambda x: x[1])

    seg_min = SegTreeMin(c)
    seg_cov = SegTreeSum(n)

    total = 0

    for s, e in intervals:
        s -= 1
        e -= 1
        if seg_cov.range_sum(s, e) > 0:
            continue
        val, idx = seg_min.range_min(s, e)
        total += val
        seg_cov.update(idx, 1)

    print(total)

if __name__ == "__main__":
    solve()
```最初のセグメント ツリーには、任意の範囲内の最も安い日がそのインデックスとともに格納されます。 2 番目のセグメント ツリーは、その日が少なくとも 1 回選択されているかどうかを追跡します。 間隔を処理するとき、以前に選択した日がまだその間隔と交差していない場合にのみコストが発生します。 それ以外の場合は、既存の選択内容を再利用します。 

よくある間違いは、選択した同じ日までに複数の間隔を満たすことができることを忘れていることです。 だからこそ、私たちは 1 日を特定の間隔だけに「割り当てる」ことはありません。 代わりに、カバレッジが存在することを確認するだけです。 

もう 1 つの微妙な点は、右のエンドポイントによって間隔を並べ替えることです。 この順序付けがないと、遅い間隔により、以前の重複する制約を最初に処理していれば回避できたはずの選択が強制される可能性があります。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + m)\log n)$| 各間隔で最大 1 つの範囲クエリと 1 つの更新がトリガーされます。 
| スペース |$O(n)$| 日配列上の 2 つのセグメント ツリー |

 ## 特殊なケース

 重要なエッジ ケースは、すべての間隔が小さな領域で大きく重なっているが、最も安い日がその領域の外側にある場合に発生します。 その状況では、アルゴリズムは外側の点を決して考慮しません。これは、各間隔が独立して制約されるため、すべての選択がその間隔内に留まることを強制されるためです。 貪欲なステップにより、グローバルな優先順位ではなく、制約ごとの実現可能性が保証されます。 

もう 1 つのケースは、間隔がネストされている場合です。 例えば：```
(1, 10), (2, 9), (3, 8)
```適切なエンドポイントによる処理により、最も深い間隔が最初に処理され、中心の低コスト日が選択されると、自然に外側の間隔がすべてカバーされます。 カバレッジ構造により、すでに満たされた範囲内での繰り返し選択が防止されるため、ネストされた制約は 1 つの決定にまとめられます。
