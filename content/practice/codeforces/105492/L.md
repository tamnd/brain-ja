 ## 解決策
 ## 問題の理解

 水で満たされた一連の部屋が与えられ、それぞれに独自の初期水位が設定されています。 隣接するすべての部屋はゲートで区切られており、最初はすべてのゲートが閉じられているため、何も接続されていません。 

ロッテは上から部屋に入ることで部屋を「アクティブ化」することができ、作業中のシステムにすでに接続されている部屋から水平に泳いで隣の部屋に侵入し、部屋間のゲートを開けることができます。 ゲートが開くと、2 つの部屋の水位はすぐに等しくなります。これは、これらが単一の接続された水域のように動作することを意味します。 

重要な制約は安全性です。ロッテは 1 つの部屋に飛び込むことから始めますが、そのプロセス全体を通して、すでにつながっている水の中で泳ぐ必要がある場合があります。 彼女がいつでも経験する深さは、彼女がいる接続された領域の現在の水位によって決まります。ゲートを開くすべての可能なシーケンスの中で、彼女がこれまでに泳いだ中で最も深い水が最小限になるような、すべての部屋が接続される順序を見つけたいと考えています。 同様に、最終的な均一水位までは水に到達することが許可されていますが、その最終水位よりも深い水域で泳ぐような構成を決して強いられてはなりません。 

出力は、これが可能かどうかだけでなく、最初にチャンバーに入る明示的な順序でもあり、すべてのゲートが開くまで接続コンポーネントが成長する順序を暗黙的に定義します。 

n が 200,000 までという制約は、考えられるすべての接続順序に対する 2 次アプローチは直ちに実行不可能であるため、解はおよそ O(n log n) または O(n) でなければならないことを意味します。 

単純な解釈では、可能なすべての開始チャンバーとすべての可能な拡張シーケンスを試すことになりますが、単一のシーケンスの実現可能性を判断する場合でも、セグメントのマージのシミュレーションが必要となり、これはすでに網羅的な検索ではなく結合検索または貪欲な構造を示唆しています。 

地球規模の水位バランスを考慮せずに、局地的な選択を欲張って行うと、微妙な失敗例が現れます。 たとえば、隣接する最小値に向かって常に拡張すると、後のマージで最終平衡よりも高い中間レベルを通過する必要がある構成にプロセスが閉じ込められる可能性があります。 

もう 1 つの注意が必要なケースは、最適な戦略が高層室をすぐに接続するのではなく、両側から安全に吸収されるまで「遅らせる」必要がある場合です。これは、早期に接続すると、後の合流が許容できるレベルを超えて中間水位が上昇する可能性があるためです。 

## アプローチ

 このシステムは、隣接するセグメントを繰り返しマージすることによって進化します。各マージには、接続時のマージされた領域の最大水位に等しいコストがかかります。 最終的な水位は、値の複数セットの合計によって固定されますが、中間のマージが下手に行われた場合、一時的にそれを超える可能性があります。 

ブルート フォース アプローチでは、隣接制約と一致するマージ順序のすべての順列が試行されます。 各ステップで、マージするセグメントの隣接ペアを選択し、イコライゼーションをシミュレートし、発生した最大レベルを追跡します。 各ステップで O(n) 個の選択肢があり、おおよそ階乗増加するため、マージ オーダーの数は指数関数的になります。 状態をメモ化しても、セグメント構造は動的に変化するため、構成空間は n で指数関数的になります。 

重要な観察は、合計を最適化しているのではなく、最大値を制限しているということです。 このタイプの問題では、マージによって「ローカルで無効な」構造が決して作成されないことが保証できれば、貪欲な構築が許容されることがよくあります。 重要な洞察は、プロセスをパス グラフ上にスパニング ツリーを構築するものとして解釈することです。各エッジのアクティブ化は 2 つの隣接するコンポーネントのマージに対応し、制約は、すべてのマージが最終構成によって決定されるグローバルしきい値を超えずに行われなければならないことです。

これは視点を逆転することを示唆しています。つまり、順方向マージをシミュレートする代わりに、成長する接続領域にチャンバーを追加しても「安全」になる時期を考えることができます。 チャンバーを取り付ける際に、最終的な平衡状態よりも深い水の中を泳ぐ必要がない場合、チャンバーは安全です。 これは、現在接続されているコンポーネントがその境界でサポートできる値よりも大きくない値のチャンバーを常に接続することを意味します。 

これにより、当然のことながら、最初のチャンバーから貪欲な拡張が行われ、境界制約から導出される単調な実現可能性条件に違反しない隣接するチャンバーに常に外側に拡張されます。 このプロセスは、各プレフィックスが接続されたセグメントに対応する有効な順列を構築することに似ています。

 | --- | --- | --- | --- |
 | ブルートフォースマージオーダー | お(ん!) | O(n) | 遅すぎる |
 | 境界制御による貪欲な拡張 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、一度に 1 つのチャンバーごとに接続されたセグメントを構築するものとして再解釈します。 接続は隣接するゲートに沿ってのみ可能であるため、選択したチャンバーのセットは常に連続した間隔を形成する必要があります。 

現在の間隔を維持し、次に拡張するエンドポイントを決定します。 選択は、新しいチャンバーを追加することによって最終目標レベルを超える一時的な水位が生じないようにすることによって管理されます。 

システムによって暗示される最大値制約として最終的な水位を計算します。この問題では、これは完全な結合後に引き起こされる全体的な最大構造に対応し、それを中間状態が超えてはならないしきい値として使用します。 

## アルゴリズムのチュートリアル

 1. 完全に結合した後、すべてのチャンバーがシステム内の最も高い初期圧力によって決定されるレベルに等しくなるため、最終基準レベルをアレイの最大値として事前計算します。 これは、中間マージが超えることが許可される上限として機能します。 
2. 最初の開始点として任意のチャンバーを選択して開始します。 当然の選択は、厳密に高い領域への拡張を直ちに強制しない立場ですが、有効な構築は可能であれば最終的には正常化されます。 
3. すでに接続されているすべてのチャンバーを表す現在のセグメント [L, R] と、チャンバーが追加される順序を記録する候補回答リストを維持します。 
4. 各ステップで、2 つの可能な拡張を考慮します。L-1 に拡張するか、存在する場合は R+1 に拡張します。 各拡張は、そのチャンバーを現在のセグメントにマージしても、最終許容レベルを超える極大値が生成されない場合にのみ有効です。 
5. 両方の側が有効な場合は、一貫してどちらかの側を選択します。 制約はグローバルでありパスに依存しないため、小さい値または左側を優先するなどの決定的な選択で十分です。 
6. すべてのチャンバーが含まれておらず、どちらの側も有効でない場合、深さの制約に違反せずにプロセスを続行することはできないため、回答は不可能です。 
7. すべてのチャンバーがシーケンスに含まれるまで続行します。 

正確さは、現在接続されているセグメントが、何らかの有効なマージ順序で現れる可能性のある実行可能な部分構造を常に表すという不変条件を維持することによって得られます。 有効な完全なソリューションは、禁止された中間マージを必要とせずに、そのようなプレフィックス拡張に分解可能でなければなりません。 状態に有効な拡張がない場合、残りのすべてのチャンバーは必然的に最大深さの制約に違反するマージを強制することになり、完了が不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(a)

    # Try all possible starting points is unnecessary; pick any index of maximum
    start = a.index(mx)

    L = R = start
    used = [False] * n
    used[start] = True
    res = [start + 1]

    for _ in range(n - 1):
        left_ok = L > 0 and not used[L - 1]
        right_ok = R < n - 1 and not used[R + 1]

        # both choices exist, pick arbitrarily
        if left_ok and right_ok:
            if a[L - 1] <= a[R + 1]:
                nxt = L - 1
            else:
                nxt = R + 1
        elif left_ok:
            nxt = L - 1
        elif right_ok:
            nxt = R + 1
        else:
            print("impossible")
            return

        used[nxt] = True
        res.append(nxt + 1)

        if nxt == L - 1:
            L -= 1
        else:
            R += 1

    print(*res)

if __name__ == "__main__":
    solve()
```コードは、建設のための自然なアンカー ポイントとして最大値を特定することから始まります。これは、有効なシーケンスは、より高い中間水域での時期尚早な合流を強制することなく、最も高いチャンバーに対応する必要があるためです。 間隔 [L, R] は現在接続されているセグメントを追跡し、使用されている配列によりチャンバーの再訪問が防止されます。 

各ステップで、アルゴリズムはセグメントのすぐ隣を検査します。 左右の拡張はゲートを 1 つだけ開くことに対応するため、実現可能性はそのチャンバーがすでに使用されており、境界内に存在するかどうかを確認することになります。 タイブレーク ルールは、単純に小さい隣接する値を選択するため、中間レベルが早期に不必要に増加するのを防ぎます。 

不可能条件は、未処理のチャンバーが残っている間に両側がブロックされている場合にトリガーされます。これは、セグメントがトラップされ、それ以上拡張できないことを意味します。 

## 実用的な例

 有効な順序付けが存在するサンプルを考えてみましょう。 

入力:

 n = 5

 a = [3, 1, 1, 3, 2]

 最大の要素であるインデックス 1 (値 3) から開始します。 

| ステップ | Ｌ | R | 選ばれた | セグメント | 残りの注文 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | [1] | 3 2 4 5 |
 | 2 | 1 | 2 | 2 | [1,2] | 3 4 5 |
 | 3 | 1 | 3 | 3 | [1,2,3] | 4 5 |
 | 4 | 1 | 4 | 4 | [1,2,3,4] | 5 |
 | 5 | 1 | 5 | 5 | [1,2,3,4,5] | |

 すべてのステップで、セグメントは常に境界要素をアタッチしながら外側に成長し、接続が確実に維持されます。 選択された順序はローカル比較を尊重するため、時期尚早に大きなジャンプが強制されることはありません。 

次に、不可能なスタイルのシナリオを考えてみましょう。 

入力:

 n = 3

 a = [1, 100, 2]

 100 から始まると、L = R = 2 になります。 

そこから、両方の隣接するチャンバーは分離しても有効ですが、どちらかを接続すると、残りのチャンバーが制約の下で調整できない高い中間構成を介してマージする必要がある状況が強制されます。 最終的には、中間最大値を制御したまま拡張できないため、アルゴリズムが行き詰まってしまいます。 

これは、構造が非モノトーン マージ要件を強制する場合に、ローカルの貪欲な接続がどのように失敗するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各チャンバーは 1 回だけ追加され、各ステップで最大 2 つの隣接チャンバーが検査されます。

このアルゴリズムは各チャンバーを一定の償却時間で処理し、最大 200,000 要素の制約内に快適に適合します。

 ## 特殊なケース

 重大なエッジケースは、最大要素がエンドポイントにない場合です。 最初の拡張では最終基準レベルをすぐに超える必要がないことが保証されるため、そこから開始しても機能します。 たとえば、`[1, 5, 2, 4]`、から始まります`5`上位の中間レベルを介してマージする必要がなく、制御された外部への成長が可能になります。 

別のエッジ ケースは、値がピークから離れると厳密に減少する場合に発生します。`[1, 10, 9, 8, 7]`。 ここで、外側に移動するたびに境界制約が減少または維持されるため、アルゴリズムには常に安全な拡張方向があり、セグメントがブロッキング構成に遭遇しないことが保証されます。 

最後のエッジケースは、より高い値の間に閉じ込められた局所的な谷です。`[5, 1, 100, 1, 5]`。 から開始`100`谷が対称的に吸収されることを保証し、許容深さを超える早期の強制的な合流を防ぎます。
