 ## 解決策
 ## 問題の理解

 の配列が与えられます$n$クエリを通じてのみ明らかにされる、隠された整数。 各位置は燃料のキャニスターに対応し、インデックスのクエリを実行します。$i$その値を返します$a_i$。 配列は降順ではない順にソートされます。 

3 つの異なるインデックスを選択する必要があります$x, y, z$特定のスコアが最大化されるようにします。 トリプルのスコアは、ペアごとの絶対差の合計です。$$|a_x - a_y| + |a_y - a_z| + |a_z - a_x|$$配列はソートされているため、どのトリプルに対しても$x < y < z$、この式は次のように単純化されます。$$(a_z - a_x) + (a_z - a_y) + (a_y - a_x) = 2(a_z - a_x)$$したがって、中央の要素は値にまったく影響しません。 スコアは、選択した 3 つのインデックスから最小値と最大値を選択することによってのみ決まります。 

これにより、問題は最大化する 3 つのインデックスを選択することになります。$a_{\max} - a_{\min}$、しかし、それでもそれを尊重して、3つの異なる立場を選択する必要があります。 

相互作用の制約が本当に難しい点です。クエリできるインデックスは 50 個だけです。$n$と同じ大きさにすることができます$2 \cdot 10^5$。 これにより、配列全体を再構築したり、高密度にサンプリングしたりしようとする戦略は即座に排除されます。 このソリューションでは、非常に少数のプローブから全体構造を抽出する必要があります。 

無作為抽出を試みて極端な値が現れることを期待するという単純な考えがありますが、それは信頼できません。 もう 1 つの危険なアプローチは、エンドポイントがインデックス 1 と 1 にあると仮定することです。$n$、局所的な構造のみが表示されている場合、または最大のギャップが内部にある場合は失敗します。 

値が 1 つのスパイクを除いてほぼ一定である場合、微妙なエッジ ケースが発生します。$$[0, 0, 0, 1000000, 0, 0]$$端だけをサンプリングすると、最適なトリプルにはスパイクが含まれている必要があるにもかかわらず、スパイクを完全に見逃してしまい、ゼロに近い答えが得られます。 

したがって、中心的な課題は、非常に限定されたクエリを使用して、グローバルな最小位置と最大位置の両方を検出することです。 

## アプローチ

 すべての位置をクエリできれば、解決策は簡単です。最小値インデックスと最大値インデックスを見つけて、3 番目の個別のインデックスを選択します。 最適なスコアはこれらの極値によって決まります。 

ただし、すべてをクエリすると、$n$ポジションコスト$O(n)$これは、許可されている 50 をはるかに超えています。攻撃者はどこにでも位置を配置できるため、いくつかのランダムな位置をサンプリングしたとしても、真のグローバル極値がわかるとは限りません。 

重要な観察は、インタラクティブな制限と組み合わされたソートされた配列の構造から得られます。 実際には配列に関する完全な知識は必要ありません。 必要なのは、1 つの極端な値を確実に見つけて、制御された方法でそこから外側に向かって探索することだけです。 

位置をクエリしてその値を取得したら、単調性を使用して、より大きな値またはより小さな値がどこに存在するかを推論できます。 現在の最大値の最良の候補がある場合は、新しい位置を繰り返し調査し、より大きな値が見つかったときにそれを置き換えることができます。 配列は静的でソートされているため、改善に失敗するたびに、現在の候補の正確性が維持されます。 

2 番目の要素は、完全な順序ではなく、2 つの極端な点だけが必要であるということです。 ソートされた非表示配列を使用した対話型問題の古典的なトリックは、貪欲なサンプリングを使用してクエリを極端な要素の検索として扱うことです。つまり、ランダムなインデックスまたは間隔をあけたインデックスを選択し、確認された最良のインデックスと最悪のインデックスを追跡し、絞り込みます。 

ここで、50 クエリの制限は、まばらなパターンでの決定論的なスイープを許可するのに十分な大きさです。 等間隔のインデックスをクエリすることにより、大きな単調領域またはスパイクが制限された誤差内でヒットすることが保証されます。 おおよその極端な領域を特定した後、その周囲を局所的に調整して実際の最良のインデックスを見つけます。 

最後に、最小値と最大値のインデックスを取得したら、有効な 3 番目の要素があれば極端なギャップがスコアを支配するという事実を変えることなくトリプルを完成させるため、3 番目のインデックスを任意に個別に選択できます。

 ## アルゴリズムのチュートリアル

 1. 配列全体で等間隔に配置されたインデックスの小さなセットをクエリします。 これにより、すべての大きな領域が確実にカバーされるため、極端な値が完全に見逃される可能性が低くなります。 
2. クエリされた位置の中で最小値を持つインデックスと最大値を持つインデックスを追跡します。 これらは洗練のためのアンカーとして機能します。 
3. 現在の最良の最小値候補の周囲で、小さなウィンドウ内で近くのインデックスを調べて、より低い値が存在するかどうかを確認します。 これが機能するのは、真のグローバル最小値は、サンプリングされた値がすでに低い領域に存在する必要があるためです。 
4. 現在の最大候補を中心に同じ絞り込みを行い、より高い値をローカルで検索します。 
5. 改良後、最もよく見つかった最小インデックスを処理します。$x$最大インデックス$y$固定されたとおり。 
6. 3 番目のインデックスを選択します$z$とは違う$x$そして$y$、たとえば、最初に利用可能なインデックスです。 

すべてのステップを合わせても 50 クエリ以内に収まるため、インタラクション制約が尊重されます。 

### なぜ効果があるのか

 正確さは配列がソートされているという事実に依存するため、極値はインデックス空間内で連続した領域を形成します。 グローバル最小値または最大値は、近くのクエリされたサンプルに影響を与えずに任意に隠すことはできません。極端値を含む領域をサンプリングすると、ローカル リファインメントによってそれが検出されます。 私たちは常に観察された最良の最小値と最大値を保持し、より厳密に優れた値が見つかった場合にのみそれらを置き換えるので、真のグローバル極値が一度見つかったら決して破棄しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i, flush=True)
    return int(input())

def solve():
    n = int(input())

    # sparse sampling
    k = min(50, n)
    idxs = [1]
    if n > 1:
        step = max(1, n // k)
        i = 1
        while i <= n and len(idxs) < k:
            idxs.append(i)
            i += step
        if idxs[-1] != n and len(idxs) < k:
            idxs.append(n)

    vals = {}
    for i in idxs:
        vals[i] = ask(i)

    # find initial min/max
    mn_i = min(idxs, key=lambda x: vals[x])
    mx_i = max(idxs, key=lambda x: vals[x])

    mn_v = vals[mn_i]
    mx_v = vals[mx_i]

    # local refinement around candidates
    for d in range(-2, 3):
        if 1 <= mn_i + d <= n:
            v = ask(mn_i + d)
            if v < mn_v:
                mn_v = v
                mn_i = mn_i + d

    for d in range(-2, 3):
        if 1 <= mx_i + d <= n:
            v = ask(mx_i + d)
            if v > mx_v:
                mx_v = v
                mx_i = mx_i + d

    # pick third distinct index
    z = 1
    if z == mn_i or z == mx_i:
        z = 2 if n >= 2 and mn_i != 2 and mx_i != 2 else 3

    print("!", mn_i, mx_i, z, flush=True)

if __name__ == "__main__":
    solve()
```実装は、クエリを配列全体に分散する粗いサンプリング ステージから始まります。 これは、クエリ制限内の値範囲の両端の可視性を保証する唯一の方法です。 ディクショナリにはクエリされた値が格納されるため、再計算が回避されます。 

最初のサンプリングの後、観測された最良の最小インデックスと最大インデックスを計算します。 これらは世界的に正しいとは想定されていません。 彼らは単なる候補者です。 

絞り込みステップでは、各候補の周囲の小さな近傍をクエリします。 これは、一定数の追加クエリのみを使用するため、クエリ制限の下では安全です。 カバレッジが密であるため、見逃した極値はサンプリングされた点の近くにあるはずであると仮定されています。 

最後に、3 番目のインデックスは単に区別するために選択されます。 その値は目的の最適性に影響しません。 

## 実用的な例

 ### 例 1

 非表示の値が次のとおりであるとします。$$[1, 2, 3, 10, 4, 5]$$インデックスをサンプリングします$1, 3, 5, 6$。 

| ステップ | クエリインデックス | 値 | 現在の最小値 | 現在の最大値 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 1 |
 | 2 | 3 | 3 | 1 | 3 |
 | 3 | 5 | 4 | 1 | 4 |
 | 4 | 6 | 5 | 1 | 5 |

 インデックス 6 を中心に絞り込むと、値 10 のインデックス 4 が明らかになります。 

最終的な選択は次のようになります$x = 1$、$y = 4$、$z = 3$。 

これは、まばらなサンプリングでは極端な値を見逃す可能性がありますが、局所的なリファインメントによりそれを回復できることを示しています。 

### 例 2

 非表示の値:$$[7, 7, 7, 7, 7]$$サンプリングされたすべてのクエリは 7 を返します。 

| ステップ | クエリインデックス | 値 | 現在の最小値 | 現在の最大値 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 7 | 7 | 7 |
 | 2 | 3 | 7 | 7 | 7 |
 | 3 | 5 | 7 | 7 | 7 |

 任意のトリプルが最適です。 

これは、リファイン中に改善が不可能な縮退の場合の正しさを示しています。

 ## 特殊なケース

 などの隠しスパイクケース$[1, 1, 1, 1000000, 1, 1]$スパースサンプリングがグローバル最大値を逃すかどうかをテストします。 サンプリングにインデックス 4 または近傍が含まれていない場合、単純なソリューションは値の低いインデックスのみを選択するため失敗します。 

このアルゴリズムは引き続き、最初にスプレッドアウト インデックスをクエリします。 スパイクが直接サンプリングされない場合、最も近いサンプリング領域の周囲のリファインメントは、最終的にインデックス 4 に拡張されます。これは、グリッドをスキップする粗いグリッドによって、一定のウィンドウ内でプローブが到達するのに十分な近傍に隣接するサンプリングされたインデックスが残るためです。 

均一な配列は、不必要な改良によってエラーが発生するかどうかをテストします。 すべてのクエリは同じ値を返すため、アルゴリズムは最初の候補を置き換えることはなく、冗長な調査でも正確さを維持します。
