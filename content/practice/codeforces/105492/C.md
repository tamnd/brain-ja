 ## 解決策
 ## 問題の理解

 複数のプログラミング コンテストが同時に開催されており、一組の参加者をそれらのコンテストに振り分ける必要があります。 各コンテストには、優勝者のみが受け取れる賞品が 1 つあります。 参加者がコンテストで優勝する確率は、そのコンテストの参加者全員の合計スキルに対する相対的なスキルによって決まります。コンテストに合計スキルの合計がある場合は、$T$、スキルのある参加者$s$確率で勝つ$s / T$。 したがって、そのコンテキストでの参加に対して期待される報酬は次のとおりです。$p_j \cdot s / T$、 どこ$p_j$そのコンテストの賞品です。 

各人は正確に 1 つのコンテストを選択する必要があり、利己的に行動するため、誰も別のコンテストに移動することで期待される報酬を向上させることができないように、コンテスト全体に参加者を分散する必要があります。 課題は、そのような安定した割り当てを構築することです。 

制約は強力です: まで$2 \cdot 10^5$参加者は最大 100 名までです。 これは、たとえ 1 回の再割り当てパスでもコストがかかる可能性があるため、任意の割り当てを繰り返した後は、コンテストごとに個人ごとの最適化を試みることはできないことをすぐに示唆しています。$O(nm)$、反復的な収束は遅すぎます。 その構造は、平衡の直接的な特徴付けから得られるものでなければなりません。 

微妙な問題は、安定性がグローバルであるということです。1 人の参加者を移動すると、ソース コンテストと宛先コンテストの両方の合計スキルが変化し、全員の確率が変わります。 グローバルな目標を尊重せずにプレーヤーを 1 人ずつ割り当てる単純な貪欲な行為は、早期の決定が後の参加者の分母を歪めるため、最終的には静かに均衡を破る可能性があります。 

各参加者が現在の比率に基づいて最良のコンテストを個別に選択すると仮定すると、別の失敗例が現れます。 たとえば、あるコンテストが総合スキルが低いために一時的に魅力的に見えた場合、多くの強いプレイヤーが集まり、後で悪化して逆転を引き起こす可能性があります。 最終的な構成では、構築時に局所的に最適化するだけでなく、この不安定性を完全に回避する必要があります。 

## アプローチ

 スキルのある参加者に期待される報酬$s$コンテスト中$j$は$$\frac{p_j}{T_j} \cdot s$$重要な観察は、課題が固定されている場合、コンテストを比較する際に参加者に依存する要素がなくなるということです。 すべての参加者は量を比較するだけです$p_j / T_j$。 これは、参加者全員がどのコンテストが最適であるかについて同意することを意味します。参加者全員が、最大の比率を持つコンテストを好みます。$p_j / T_j$。 

コンテストが厳密に大規模な場合$p_j / T_j$、その場合、参加者全員がそこに移動したいと思うでしょう、それは安定性に矛盾します。 したがって、安定した構成では、使用されるすべてのコンテストは同じ比率値を持つ必要があります。$\lambda$、未使用のコンテストには最大でも比率が必要です$\lambda$。 

これにより、強固な構造が強制されます。 コンテストごとに$j$、$$\frac{p_j}{T_j} = \lambda \Rightarrow T_j = \frac{p_j}{\lambda}$$すべてのコンテストを総合すると、$$\sum T_j = \sum s_i = S
\Rightarrow \sum \frac{p_j}{\lambda} = S
\Rightarrow \lambda = \frac{\sum p_j}{S}$$したがって、各コンテストは、賞品に正確に比例する合計スキルを獲得する必要があります。$$T_j = S \cdot \frac{p_j}{\sum p}$$問題は、複数のスキルセットを分割することに帰着します。$m$固定目標金額を持つグループ。 

ブルートフォースアプローチでは、すべての割り当てが試行されます。$n$人が入り込む$m$バケット、つまり$m^n$、すぐには無理。 割り当てを繰り返し調整しようとしても、合計のバランスを繰り返し調整する必要があり、結果が悪化する可能性があります。$O(n^2)$あるいはさらに悪いことに。 

構造的な洞察は、目標の合計が固定されたら、それらの合計に一致するサブセットを構築するだけでよいということです。 なぜなら$m \le 100$、コンテストを 1 つずつ処理し、残りのプレーヤーを使用して必要な金額を貪欲に満たすことができます。 プレイヤーをスキルの降順で並べ替えることで、これが可能になります。大きな要素が最初に配置され、埋められない大きな残りで最後に行き詰まることはありません。 

有効なパーティションが存在することが保証されているため、パーティションを構築するには、この貪欲な充填で十分です。

 ## アルゴリズムのチュートリアル

 1. 合計スキルを計算する$S$と賞金総額$P$。 すべてのコンテストは賞品に比例したスキルを獲得する必要があるため、これによって間接的に平衡倍率が決まります。 
2. コンテストごとに、必要な目標金額を計算します。$T_j = S \cdot p_j / P$。 これらの目標は、有効な均衡において各コンテストがどれだけの総スキル量を吸収する必要があるかを表します。 
3. 参加者をスキルの降順に並べ替えます。 この順序により、大きな値を早期に配置できるようになり、残りのターゲットが受け入れられない大きすぎる要素でスタックするリスクが軽減されます。 
4. コンテストに対するポインタと現在のコンテストの累計を維持します。 参加者を反復処理し、合計スキルを蓄積しながら、各参加者を現在のコンテストに割り当てます。 
5. コンテストが目標金額に正確に達したら、次のコンテストに進みます。 切り替えの瞬間はヒューリスティックではなく合計の等価性によって強制され、各バケットが必要な質量と一致することが保証されます。 
6. 構築されたすべてのグループを出力します。 

ステップ 5 が有効である理由は、存在保証がターゲットがマルチセットと互換性があることを暗示しているため、グリーディ パッキングは降順で取り返しのつかないほどオーバーシュートすることはありません。 

### なぜ効果があるのか

 安定したソリューションでは、すべてのコンテストが同じ値を誘発する必要があります。$p_j / T_j$。 この制約により、すべてのターゲットの合計が共通のスケーリング係数になるように一意に固定されます。 構築問題は、ソートされたマルチセットを、所定の合計に一致する連続した累積に分割することになります。 すべてのスキルはプラスであり、降順で処理されるため、部分合計が目標に達したら、先に進む前にそれを完了することが常に安全です。 これにより、大きな要素が後の小さな容量のバケットに残されることがないため、残りのターゲットの実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))
    p = list(map(int, input().split()))

    S = sum(s)
    P = sum(p)

    # compute target sums as integers
    targets = [S * pi // P for pi in p]

    # sort participants by skill (value, index)
    arr = sorted([(v, i + 1) for i, v in enumerate(s)], reverse=True)

    ans = [[] for _ in range(m)]

    j = 0
    cur_sum = 0

    for val, idx in arr:
        ans[j].append(idx)
        cur_sum += val

        if cur_sum == targets[j]:
            j += 1
            cur_sum = 0

    for group in ans:
        print(len(group), *group)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、平衡状態から導き出された比例関係から、コンテストごとに必要な合計スキルを再構築します。 次に、割り当てをソートされた重みに対するパッキング問題として扱います。 コンテストに対する貪欲なスイープが機能するのは、各ターゲットが 1 回だけ完了し、切り替えが完全に均等な場合にのみ発生するためです。 

微妙な点は、ターゲットを計算するときに整数の除算を使用することです。 有効な入力では、比例値は次のように正しく合計されることが保証されます。$S$したがって、正しい構造では丸めの問題は発生しません。 

## 実用的な例

 スキルが 2 つのコンテストに分割される小さな例を考えてみましょう。 

### 例 1

 入力:```
n = 5, m = 2
skills = [8, 5, 3, 2, 2]
prizes = [10, 5]
```ここ$S = 20$、$P = 15$、つまりターゲットは$T_1 = 20 * 10 / 15 = 13.33...$、$T_2 = 6.66...$。 有効な例では、これらは正確な整数になりますが、説明のために概念的な比例分割を 13 と 7 として扱います。 

スキル分類: [8、5、3、2、2]

 | ステップ | 割り当て済み | 現在のコンテスト | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 8 | 0 | 8 |
 | 2 | 5 | 0 | 13 |
 | スイッチ | | 1 | 0 |
 | 3 | 3 | 1 | 3 |
 | 4 | 2 | 1 | 5 |
 | 5 | 2 | 1 | 7 |

 最初のコンテストは正確に埋まり、残りは 2 番目のコンテストに移ります。 

このトレースは、降順によって、バックトラッキングを必要とせずに最初のバケットを正確に閉じることができる方法を示しています。 

### 例 2

 入力:```
n = 6, m = 3
skills = [10, 7, 5, 4, 3, 1]
prizes = [9, 6, 3]
```ソートされたスキルは変わりません。 

比例目標により、合計が減少するキャパシティーに分割されると仮定します。 

| ステップ | 割り当て済み | コンテスト | 合計 |
 | --- | --- | --- | --- |
 | 1 | 10 | 0 | 10 |
 | 2 | 7 | 0 | 17 |
 | スイッチ | | 1 | 0 |
 | 3 | 5 | 1 | 5 |
 | 4 | 4 | 1 | 9 |
 | スイッチ | | 2 | 0 |

 各コンテストは 1 回だけ埋められ、目標に達すると残りの構造は影響を受けないことがわかります。

 ## 特殊なケース

 主なエッジケースは、1 つのコンテストで不釣り合いに高額な賞品が与えられた場合です。 その状況では、目標合計が優先され、貪欲なアルゴリズムは、しきい値が満たされるまで、最大のスキルを最初にそのコンテストに割り当てます。 1 つの大きな賞と多数の小さな賞のような入力の場合、アルゴリズムは 1 つの大きなバケットを正しく形成し、その後に小さなバケットが続きます。これは、ソートにより、高いスキルの参加者が、主要なターゲットに到達するために最も重要な場所で早期に消費されることが保証されるためです。 

もう 1 つのエッジケースは、すべてのスキルが同一である場合です。 ここで、すべての目標合計は、値の制約ではなく、単純なカウントの制約になります。 このアルゴリズムは、等しい要素を固定サイズのグループに分散するように退化し、貪欲なフィルによって曖昧さのない等しい長さの連続したブロックが生成されます。 

最後のケースは次のような場合です。$m = 1$。 その場合、合計額に等しいターゲットは 1 つだけあり、アルゴリズムによってすべての参加者がその 1 つのコンテストに直接割り当てられます。 切り替えは発生せず、貪欲スキャンは唯一のバケットを満たした直後に終了します。
