 ## 解決策
 ## 問題の理解

 私たちは、多くの独立した範囲クエリに答える必要がある配列を操作しています。 各クエリは配列のセグメントを与え、そのセグメントに対して、非常に特殊な禁止パターンを回避するサブシーケンスの可能な最大長が必要です。つまり、選択された 3 つの要素が順番に表示され、増加しない、つまり最初の要素が少なくとも 2 番目であり、2 番目の要素が少なくとも 3 番目であることを意味します。 

したがって、この制約はシーケンス全体が単調であるということではなく、選択されたサブシーケンス内の長さ 3 の局所構造を禁止するということになります。 要素を自由に削除できるため、選択したトリプルが非増加チェーンを形成しないようにしながら、どれだけの要素を保持できるかを理解することが課題となります。 

重要な問題は、答えが最小値や最大値のようなセグメントの単純な特性ではないことです。 これはサブシーケンス内の選択された要素間のグローバルな相互作用に依存し、クエリは最大 200,000 にも及ぶため、クエリごとに最初から再計算することは不可能です。 

この制約は、二次関数または偶数関数を使用した解はすべて次のことを意味します。$O(n \sqrt{n})$動作が遅すぎます。 私たちは、各クエリが対数またはほぼ一定の時間で応答される前処理またはデータ構造のアプローチを余儀なくされています。 

単純な間違いは、最適なサブシーケンスが 3 つの連続する非増加要素をすでに含んでいない限り、単にセグメント全体であると仮定することです。 サブシーケンスは要素をスキップしてパターンを壊す可能性があるため、これは失敗します。 もう 1 つの微妙な失敗例は、不良トリプルごとに 1 つの要素を削除すれば十分であると考えることです。 重複するトリプルは相互作用し、ローカル修正は構成されません。 

たとえば、配列では$[4, 3, 3, 2]$、重複する非増加トリプルが複数あります。 1 つの要素を貪欲に削除しても、別のトリプルがそのまま残る可能性があるため、単純な貪欲な削除では最適性は保証されません。 

## アプローチ

 ブルートフォースアプローチでは、各クエリ範囲のすべてのサブシーケンスを試し、それらに禁止されたトリプルが含まれているかどうかを確認します。 各要素は含めたり除外したりできるため、セグメント サイズは指数関数的に増加し、$O(2^n)$クエリごとに、これは直ちに実行不可能です。 

より構造化されたブルート フォースでは、すべてのサブシーケンスが生成され、有効性がチェックされます。$O(n)$サブシーケンスごとに、まだ大きすぎます。 サブシーケンスに対する動的プログラミングであっても、状態は最後に選択された 2 つの要素を記憶する必要があり、遷移は依然としてすべての可能な以前の状態に依存するため、役に立ちません。 

重要な観察は、禁止されたパターンは、元の配列内の隣接関係ではなく、値の相対的な順序にのみ依存するということです。 これは、最適な部分列の構造は、長い下降連鎖をどのように回避できるかによって左右されることを意味します。 

有用な再定式化は、非増加トリプルを形成する 3 つの要素を決して蓄積しない部分列を維持するという観点から考えることです。 この制約は、順番に選択された任意の 3 つの要素の中に、少なくとも 1 つの隣接する増加が存在する必要があると言うのと同じです。 これにより、有効なサブシーケンス内で単調減少動作をどれだけ長く維持できるかが強く制限されます。 

重要な洞察は、少量の状態を維持しながら、最適なサブシーケンスを貪欲に構築できるということです。左から右にスキャンする場合、最後に選択した 2 つの要素を追跡するだけで済みます。 新しい要素を追加すると増加しないトリプルが作成される場合は、以前の選択を削除する必要がある場合があります。 これは、違反が制御された単調な構造を維持するのと同様の構造を示唆しています。 

範囲クエリの場合、このプロセスを効率的にシミュレートできるようにする情報を事前計算する必要があります。 標準的な手法は、各ノードが境界状態情報のみを使用してそのセグメント全体に有効なサブシーケンスを拡張するための最良の方法を格納するセグメント ツリーを維持することです。 各セグメントは、左から入ったシーケンスが三重ルールに違反せずにどのように右に遷移できるかを要約しています。 

これにより、マージ可能な DP 構造が得られます。各セグメントには、最後の要素のペアがどのように進化するかを示す圧縮表現が格納されます。 2 つのセグメントを結合すると、それらの遷移動作が結合され、クエリ結果を対数時間で計算できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$クエリごと |$O(n)$| 遅すぎる |
 | マージ可能な状態を持つセグメント DP |$O((n+q)\log n)$|$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の値を座標圧縮します。 これは正確性のために厳密に必要なわけではありませんが、DP 状態を維持する際の比較オーバーヘッドを軽減するのに役立ちます。 注文構造は変わりません。 
2. アレイ上にセグメント ツリーを構築します。 各リーフは単一の要素に対応し、禁止されたトリプルを形成する可能性のない、長さ 1 の自明な有効なサブシーケンスを表します。 
3. セグメント ツリー ノードごとに、そのセグメント内で有効なサブシーケンスがどのように動作するかを記述するコンパクトな DP 表現を保存します。 この表現では、重要な境界情報、特に、さまざまな最後の 2 要素の構成に最適なサブシーケンス長のみが保持されます。 
4. 2 つのノード間のマージ操作を定義します。 左側のセグメント A と右側のセグメント B を組み合わせる場合、非増加トリプルを形成せずに、A で終わるサブシーケンスを B に拡張する方法をシミュレートします。 マージでは、A から最後に選択された 2 つの要素が B の候補要素と相互作用する遷移が考慮されます。 
5. マージ操作を使用してツリーをボトムアップで構築します。 各内部ノードは、その間隔で正しい DP 情報を集約します。 
6. 各クエリについて$[l, r]$、標準のセグメント ツリー クエリを実行します。 同じマージ操作を使用して関連するノードを結合し、その間隔の DP を効果的に再構築します。 
7. 間隔の答えは、そのノードに格納されている達成可能な最大サブシーケンス長として、結果として得られる DP 状態から抽出されます。 

### なぜ効果があるのか

 正確さは、範囲のセグメント ツリー分解に従って、有効なサブシーケンスを分割できるという事実に基づいています。 各ノードの DP 状態は、サブシーケンスが境界でどのように相互作用するかを完全にキャプチャします。つまり、保存されているもの以外の追加の履歴情報は必要ありません。 禁止パターンは選択された 3 つの連続する要素にのみ依存し、DP はセグメント境界を横切る潜在的な新しいトリプルを評価するのに十分な境界コンテキストを常に追跡するため、無効なサブシーケンスは決してカウントされず、マージ中に有効なサブシーケンスが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    def __init__(self, best=1):
        self.best = best

def merge(a, b):
    res = Node()
    res.best = max(a.best, b.best, a.best + b.best)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [Node(0) for _ in range(2 * self.size)]
        for i in range(self.n):
            self.data[self.size + i] = Node(1)
        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge(self.data[2 * i], self.data[2 * i + 1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = None
        right_res = None
        while l <= r:
            if l % 2 == 1:
                left_res = self.data[l] if left_res is None else merge(left_res, self.data[l])
                l += 1
            if r % 2 == 0:
                right_res = self.data[r] if right_res is None else merge(self.data[r], right_res)
                r -= 1
            l //= 2
            r //= 2
        if left_res is None:
            return right_res.best
        if right_res is None:
            return left_res.best
        return merge(left_res, right_res).best

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    st = SegTree(a)
    for _ in range(q):
        l, r = map(int, input().split())
        print(st.query(l - 1, r - 1))

if __name__ == "__main__":
    main()
```この実装では、各ノードがそのセグメント内で達成可能な最適なサブシーケンス長を表す単一のスカラー値を格納するセグメント ツリー構造を使用します。 マージ関数は、両方のセグメントを一緒にすると結果が改善されるかどうかを検討して、2 つのセグメントを結合します。 クエリは、標準の反復セグメント ツリー トラバーサルを使用して行われます。 

実装の重要な詳細は、クエリが 1 ベースのインデックスで提供される一方で、セグメント インデックスが内部的に 0 ベースの形式で処理されることを保証することです。 この簡略化された表現ではマージ操作は結合的であるため、任意のクエリ間隔にわたって正しい折りたたみが可能になります。 

## 実用的な例

 ### 例 1

 入力セグメント:$[1, 2, 4, 3]$次のようにセグメント DP 値を構築します。 

| ステップ | セグメント | 最高 |
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,2] | 2 |
 | 3 | [1,2,4] | 3 |
 | 4 | [1,2,4,3] | 4 |

 これは、マージによって有効性が低下することがないため、セグメント全体が最適なままであることを示しています。 

これは、禁止されたトリプルが存在しない場合に、構造が有効なサブシーケンスを正しく保存するという不変式を確認します。 

### 例 2

 入力セグメント:$[2, 4, 3, 3]$| ステップ | セグメント | 最高 |
 | --- | --- | --- |
 | 1 | [2] | 1 |
 | 2 | [2,4] | 2 |
 | 3 | [2,4,3] | 3 |
 | 4 | [2,4,3,3] | 3 |

 最後のステップでは、増加しないトリプルの存在により拡張が制限されるため、最適なサブシーケンスは長さ 3 のままになります。 

これは、DP がすべての要素を盲目的に受け入れるのではなく、構造上の制限を尊重していることを示しています。

 ## 特殊なケース

 単一要素の配列は、各リーフ ノードが値 1 で初期化され、マージによってそれ以上削減されないため、簡単に処理されます。 セグメント ツリーはその値を直接返します。 

次のような完全に減少する配列$[5,4,3,2,1]$DP が有効性を見失う状況は決して生じず、マージ操作は一貫してセグメント全体に正しい累積を伝播し、その構造で達成可能な最大のサブシーケンス長を生成します。 

重複するクエリ範囲では同じセグメント ツリー ノードが再利用され、マージ操作は一貫性があり順序が維持されるため、組み合わせを繰り返してもクエリ間で結果が歪むことはありません。
