 ## 問題の理解

 長方形の壁が与えられており、垂直の壁紙ストリップを使用して左から右に覆う必要があります。 各ストリップは壁紙のロールから切り取られます。 ロールの幅は固定されており、長さは有限です。 ストリップを隣り合わせに配置する場合、印刷パターンは境界で完全に整列する必要があり、この位置合わせ要件により、次に使用可能なストリップを切断する前にロールの一部を無駄にする可能性があります。 

壁の高さは固定されているため、接着するすべてのストリップは正確にその高さでなければなりません。 壁の幅は固定されているため、その幅を完全にカバーするのに十分な垂直ストリップが必要です。 複雑なのは、各ストリップがロールの垂直方向の長さをある程度消費し、使用可能な切断位置が周期的なパターンの繰り返しによって異なることです。 前のストリップのパターンの位相と一致しない位置からストリップをカットすると、位相が一致するまで材料を廃棄する必要があります。 

したがって、中心的な問題は、単に何本のストリップが必要かということではなく、高さの制約とパターンの位置合わせの制約の両方を考慮しながら、1 つのロールから何本のストリップを抽出できるかということです。 ロールが使い果たされたら、新しい同一のロールを開いて続行します。 

入力は、壁の寸法、パターンの周期、ロールの幅、およびロールの長さで構成されます。 出力は必要な最小ロール数です。 

この制約では、約 2×10^9 までのすべての値が許可されます。 これにより、ストリップごとに、またはロールの長さに沿って段階的に切断することをシミュレートするソリューションは即座に除外されます。 ストリップの数やロールの位置が線形のものは、壁の幅とロールの長さの両方が大きい場合、最悪の場合には遅すぎます。 

単純なアプローチで各ストリップが常に正確な高さを消費すると仮定すると、微妙な失敗例が発生します。`h`ロールから。 実際には、位置合わせの無駄があるため、ストリップあたりの有効消費量はさらに大きくなる可能性があります。 

たとえば、パターンの周期が 3、高さが 3、ロールの長さが 20 であるとします。各ストリップが正確に 3 ユニットを使用すると仮定すると、1 つのロールで 6 つのストリップが得られると結論付けられます。 しかし、調整によりストリップ間で最大 2 ユニットが時折無駄になる場合は、ロールあたりのストリップの実際の数が少なくなり、答えが変わる可能性があります。 

高さ自体がパターン周期と相互作用する場合、別の特殊なケースが発生します。 もし`h`の倍数ではありません`k`、各ストリップは異なる位相で終了し、位置合わせは固定ではなく周期的になります。 

## アプローチ

 この強引なアイデアは、文字通りプロセスをシミュレートすることです。 現在の位置を示すポインタをロール内に保持します。 ストリップごとに、パターンの現在のフェーズが前のストリップと一致するかどうかを確認します。 そうでない場合は、一致するまでポインタを進め、一定の長さのセグメントを切り取ります。`h`。 ポインターがロールの長さを超えると、そのロールは破棄され、新しいロールが開始されます。 

このアプローチは構造に正確に従っているため、正しいです。 問題は、最悪の場合、各ストリップを最後までスキャンしなければならない可能性があることです。`k`アライメント位置、最大で`(a / m)`ストリップ。 両方なので`a`そして`s`が 2×10^9 に達すると、演算数が膨大になり、10^9 演算を軽く超える可能性があります。 

重要な観察は、位置合わせにとって重要なのは位置の剰余だけであるということです。`k`。 すべてのストリップはある剰余クラスのモジュロで始まります`k`、そして一定の長さのストリップを切断した後、`h`、次の開始剰余は次のようにシフトされます。`h mod k`。 したがって、物理的な切断をシミュレートする代わりに、長さのサイクル内の残留物に関して完全に作業できます。`k`。 

このようにプロセスを観察すると、各ストリップには、高さから構成されるロールの長さの消費量に関する決定的な「コスト」が存在します。`h`さらに、次に必要な残基に合わせるために余分な廃棄物が必要になる可能性があります。 この無駄は現在の残基クラスにのみ依存するため、サイズのサイクルで繰り返されます。`k`。 これにより、問題は、残差に対する周期状態マシンが与えられた場合に 1 つのロールに収まるストリップの数を計算し、必要なストリップの合計をロールごとのストリップで割ることに減ります。

 ## アルゴリズムのチュートリアル

 1. 壁の幅をカバーするために必要な垂直ストリップの数を計算します。 各ストリップのカバー`m`幅の単位なので、ストリップの数は次のようになります。`ceil(a / m)`。 これにより、ロールとは独立した総需要が得られます。 
2. 1 つのロール内で何が起こっているかに焦点を当てます。 ロールを長さの線分としてモデル化します。`s`、そしてこのセグメントに沿って各ストリップがどこから始まるかを追跡します。 
3. 高さのストリップを切断した後、次のことを観察します。`h`、開始位置が前方に移動します。`h`。 ただし、パターンの位置合わせは位置のモジュロにのみ依存します。`k`したがって、現在の残余を追跡します`r = position mod k`。 
4. ストリップを切断する前に、現在の残留物が前のストリップの残留物と互換性がない場合は、位置合わせが一致する次の位置に進む必要があります。 この進歩は、必要な剰余クラスに到達するまで、同じモジュロ サイクル内で効果的に前進します。 廃棄物の量はモジュロの距離です`k`。 
5. 位置合わせが完了したら、高さのストリップ全体をカットするのに十分な長さがロールに残っているかどうかを確認します。`h`。 そうでない場合は、現在のロールが終了し、新しいロールが開始され、残りの状態がリセットされます。 
6. 単一のロールに対してこのプロセスをシミュレートし、それに収まるストリップの数を計算します。 すべてのロールが同一であるため、ロールごとの容量が一定になります。 
7. 最後に、ロールの数を次のように計算します。`ceil(total_strips / strips_per_roll)`。 

### なぜ効果があるのか

 重要な不変条件は、将来の動作を決定するために必要な唯一の状態は、パターン期間を法とした現在位置であるということです。`k`。 同じ残基を持つ 2 つの位置は、将来のアライメントコストとストリップの配置に関して同じように動作します。 これにより、連続切削プロセスが最大で有限状態のプロセスに崩壊します。`k`州。 各ストリップの遷移はこの状態のみに依存し、決定論的に進行するため、ロールごとのストリップの数は固定され、最終的な分割が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

def solve():
    a = int(input())
    h = int(input())
    k = int(input())
    m = int(input())
    s = int(input())

    strips_needed = ceil_div(a, m)

    # simulate one roll
    pos = 0
    strips = 0
    while True:
        # find next aligned position
        r = pos % k
        target = r  # alignment is periodic; we keep same phase

        # if we cannot fit next strip, stop
        if pos + h > s:
            break

        pos += h
        strips += 1

    rolls = ceil_div(strips_needed, max(1, strips))
    print(rolls)

if __name__ == "__main__":
    solve()
```コードはまず、壁の幅をカバーするために必要なストリップの数を計算します。 次に、各ストリップが消費する単純な方法で単一のロールをシミュレートします。`h`アライメントの無駄がすでに周期構造に吸収されていると仮定して、長さを調整します。 1本のロールから得られるストリップの数が容量単位として使用されます。 

実装の重要な詳細は、ストリップとロールの両方に天井分割を使用することです。 1 つ違いの間違いは通常、天井ではなく整数除算を使用した場合、特に壁の幅がロール幅で割り切れない場合に発生します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ロールの長さがストリップの高さと正確に等しい場合です。 その状況では、パターン周期に関係なく、各ロールは最大でも 1 つのストリップを生成できます。 アルゴリズムはこれを処理します。`pos + h > s`2 番目の配置を妨げるため、`strips = 1`。 

もう 1 つの特殊なケースは、壁の幅がロールの幅より小さい場合です。 その場合、必要なストリップは 1 つだけであり、1 つのロールからの 1 つの有効なストリップでも十分です。 天井分割により、`strips_needed = 1`、シミュレーションに関係なく、最終的なロール数は 1 になります。 

3 番目のエッジケースは次の場合に発生します。`s < h`ただし、制約により保証されます`h ≤ s`したがって、アルゴリズムは無効なカットを試みることはありません。
