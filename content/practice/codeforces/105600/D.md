 ## 解決策
 ## 問題の理解

 一度に 1 つの要素が増加する一連の数値が与えられます。 最初の k 個の要素を読み取った後、マーシャとグレブはその接頭辞でゲームを行い、数字が 1 つだけ残るまで、選択した 2 つの要素を単一の新しい値に繰り返し結合します。 正確なマージ ルールは決定的です。2 つの数値が選択されると、それらは削除され、その合計から導出された 1 つの数値に置き換えられ、2 で割った後に切り捨てられ、さらに 2 倍になります。 この演算により、結果が元の合計を超えない偶数になることが効果的に強制されます。 

ゲームは敵対的です。 マーシャとグレブは交互にターンし、それぞれが反対の目標を持つペアを選択します。 マーシャは最終的に残った値をできるだけ大きくしたいと考えていますが、グレブはそれをできるだけ小さくしたいと考えています。 長さ k のすべてのプレフィックスについて、両側からの最適な再生の下で最終値を決定する必要があります。 

出力は一連の回答であり、k 番目の値は最初の k 要素に限定されたゲームの結果に対応します。 

すべてのテスト ケースの合計 n が最大 10^5 であるという制約は、すべての解がテスト ケースごとに線形または線形演算に近くなければならないことを意味します。 すべてのマージ選択肢の 3 次または 2 次シミュレーションは不可能です。各ゲーム ステートには複数の要素が含まれており、各移動によってサイズが 1 つ減少するため、単純なシミュレーションではプレフィックスごとに O(n^2) の演算が発生し、すぐに制限を超えてしまいます。 

微妙な問題は、操作自体がパリティ動作を隠蔽することです。 マージ結果は常に偶数であるため、奇数の寄与は構造化された方法で体系的に切り捨てられます。 算術平均を 2 倍したものとして扱う単純な実装では、正確な値ではなく、中間合計のパリティのみが重要であるということを見逃してしまう可能性があります。 

素朴な推論を打ち破るエッジケースは、小さな接頭辞から発生します。 k が 1 または 2 の場合、実際の戦略的な選択はなく、派生した式を直接適用すると、些細な結果が一致する必要があります。 すべての数値が等しい場合、別の特殊なケースが発生します。 貪欲なマージ戦略は安定性を誤って仮定する可能性がありますが、最終的な答えが単純なパターンに崩れたとしても、パリティ調整はペアリングの順序に応じて異なる方法で累積されます。 

## アプローチ

 この問題を解決する強引な方法は、各プレフィックスに対してゲームを明示的にシミュレートし、両方のプレイヤーにとって最適な選択を交互に行いながら、可能なすべてのマージ シーケンスを試すことです。 サイズ k の固定プレフィックスの場合、(k − 1) 回の手があり、プレイヤーは各手で O(k^2) 通りの可能性の中からペアを選択します。 ゲーム ツリーの変更を無視したとしても、要素を組み合わせてリダクション シーケンスにする方法の数は階乗的に増加し、完全なミニマックス検索は指数関数的に増加します。 

すべての貪欲なペアリング シーケンスを試す単純なブルート フォースでも、プレフィックスごとにせいぜい O(k^2) であり、全体では O(n^3) になります。 n が 10^5 までの場合、これは完全に不可能です。 

重要な点は、この演算では完全な数値構造が保持されないことです。 変換では常に、正確な値ではなく、順序とパリティの累積のみに依存するものに情報が圧縮されます。 マージを再解釈すると、すべての操作が 2 つの数値の合計を取得し、最も近い偶数の整数に切り捨てるように動作することがわかります。 これは、すべてのマージで事実上最大 1 単位の値が失われ、その損失は合計が奇数であるかどうかによってのみ決まることを意味します。 

この構造は、ゲームを組み合わせペアリングの問題から貪欲な会計問題に変えます。重要なのは、各ステップに奇妙な貢献がいくつ存在するか、そしてプレイヤーがそれらの貢献をどのように強制または回避できるかだけです。 最適なプレイとは、総和と敵対者によって強制される奇妙なインタラクションの数によって決定される修正を追跡するグローバル値を維持することです。

最後の簡略化は、マージをシミュレートする代わりに、累計とパリティの不一致を反映する二次調整を維持することです。 要素を 1 つ追加すると小さなローカル パリティ状態が変更されるだけなので、新しいプレフィックスの更新はそれぞれ O(1) で処理できます。

 ## アルゴリズムのチュートリアル

 1. これまでに確認されたすべての要素の合計を維持します。 これは、マージによる丸め効果が適用される前の基本値を表します。 
2. 現在のプレフィックス内で奇数の要素がいくつあるかを追跡します。 これが必要なのは、選択したペアの合計が奇数である場合にのみ、すべてのマージ操作で丸めが導入され、奇数はパリティによって完全に決定されるためです。 
3. 新しい要素 a[i] ごとに、累計を追加して即座に更新します。 
4. パリティ カウンタを更新します。a[i] が奇数の場合はインクリメントします。 これにより、システム内に潜在的な「奇妙な相互作用」がいくつ存在するかを知ることができます。 
5. 導出された不変式を使用してプレフィックス i の答えを計算します。最終的な値は、合計から避けられないパリティ損失の数を引いたものに等しくなります。これは、最適な敵対的ペアリングの下で​​ペアにならない奇数要素の数によって異なります。 

この補正の正確な形式は、floor(odd_count / 2) を減算することを単純化します。 奇数の各ペアは、丸め動作により正確に 1 単位を失うマージを強制される可能性があり、最適なプレイにより、敵対的構造の下でこれらのペアが最大化されることが保証されます。 

### なぜ効果があるのか

 マージのたびに、2 つの数値が、その合計が最も近い偶数の整数に切り捨てられて置き換えられます。 これは、2 で割る前に和のパリティを減算することと同じです。 情報損失の唯一の原因はパリティであるため、プロセス全体は、2 つの奇数が強制的に結合される回数を追跡するだけで済みます。 敵対的な性質により、そのような損失は可能な限り確実に実現され、どの戦略もペアのオッズを超えて追加の損失を生み出すことはできません。 これにより安定した不変条件が確立されます。つまり、k 個の要素を処理した後、答えは配列や履歴ではなく、合計と奇数要素の数のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        s = 0
        odd = 0
        res = []

        for x in a:
            s += x
            if x % 2:
                odd += 1

            # each pair of odds causes one unavoidable loss
            loss = odd // 2
            res.append(s - loss)

        print(*res)

if __name__ == "__main__":
    solve()
```この実装では、奇数要素の累計とカウンタが維持されます。 各プレフィックス更新後、奇数の完全なペアがいくつ存在するかを計算します。これは、そのような各ペアが最適な再生の下で強制的なパリティ損失を表すためです。 減算は即座に適用されるため、各プレフィックス応答を一定時間内に生成できます。 

唯一の微妙な点は、損失が個々のマージの追跡ではなく、奇数カウントの 2 による整数除算に依存することです。 これにより、ゲーム構造を直接シミュレートする必要がなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out_lines = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = 0
        odd = 0
        res = []
        for x in a:
            s += x
            if x % 2:
                odd += 1
            res.append(str(s - odd // 2))
        out_lines.append(" ".join(res))

    return "\n".join(out_lines)

 ## 特殊なケース

 単一要素のプレフィックスは、マージが発生しないため自明であり、そのため、答えは要素自体と等しくなる必要があります。 奇数カウントは 0 または 1 のいずれかであり、整数除算により損失が適用されないことが保証されるため、アルゴリズムはこれを処理します。 

すべての数値が偶数の場合、奇数カウンタはずっとゼロのままであるため、補正が減算されることはありません。 これにより、マージ操作はパリティ駆動の場合にのみ影響することが確認されます。 

すべての数値が奇数の場合、最終的に 2 つの要素ごとに強制ペアが形成され、1 単位の損失に寄与します。 このようなケースを追跡すると、補正が正確に Floor(k/2) として増加し、敵対的ペアリング プロセスの構造と一致していることがわかります。
