 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられます。 各テスト ケースは、ロボットであるかどうかにかかわらず、システムによって生成される状態または応答シーケンスを表す文字で構成される短い文字列を記述します。 

あなたのタスクは、テスト ケースごとに、指定された文字列が有効な「非ロボット」動作に対応するかどうか、またはロボット生成パターンとして分類されるべきかを判断することです。 各テスト ケースの出力は、その文字列の構造から派生した単一の値です。 

重要な考え方は、入力が数値計算ではなく、一連の記号に対するパターン認識であるということです。 出力は、算術解釈ではなく、文字がどのように繰り返されるか、または遷移するかによって完全に決まります。 

制約により多くのテスト ケースが許可されるため、ソリューションでは各文字列をその長さに対して線形時間で処理する必要があります。 合計入力サイズが大きい場合 (全体で最大 10^5 または 10^6 文字など)、部分文字列間のネストされた比較やループ内での繰り返しスキャンが遅くなりすぎます。 これにより、すべての部分文字列ペアを比較したり、変換を繰り返しシミュレートしたりするアプローチが除外されます。 

実装が固定フォーマットを前提としている場合、または最小限の入力を正しく処理できない場合、微妙な失敗のケースが発生します。 たとえば、入力に次のような単一の文字列が含まれている場合、`"A"`、隣接する遷移を常にチェックする単純なアプローチでは、存在しない隣接ノードにアクセスしようとし、範囲外エラーが発生する可能性があります。 別の特殊なケースは、すべての文字が同一である場合に発生します。`"RRRRR"`ここで、遷移ベースのロジックでは、バリエーションがないために文字列を誤って分類してはなりません。 

## アプローチ

 直接的な総当たりアプローチでは、すべての部分文字列をチェックするか、各位置から妥当性を再計算することによって、文字列の考えられるすべての解釈を評価しようとします。 各テスト ケースで、遷移が繰り返し再計算されると、O(n²) の動作に低下する可能性があります。 論理的には単純ですが、文字列の長さがテスト ケースごとに数千文字を超えると実行できなくなります。 

重要な洞察は、分類がグローバルな構造には依存せず、連続する文字間のローカルな遷移のみに依存するということです。 これが認識されると、問題は文字列を 1 回スキャンして、単純な一貫性ルールを満たしているかどうかを確認することになります。 これにより、再計算やバックトラッキングの必要がなくなります。 

ブルートフォース手法は、考えられるすべての違反パターンを明示的にチェックするため機能しますが、重複する情報を何度も再計算するため失敗します。 最適化されたアプローチでは、これを 1 つのパスに圧縮し、前の文字またはトランジションに関する最小限の状態のみを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n²) | お(1) | 遅すぎる |
 | 最適 (シングルスキャン) | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各文字列を個別に処理します。 各ケースは分離されているため、それらの間で状態は伝達されません。 
2. 現在の文字列が必要なパターン ルールに違反しているかどうかを追跡するために変数を初期化します。 このレベルでは、ルールは再計算されるのではなく段階的に評価されます。 
3. 文字列を左から右に繰り返し、各文字を前の文字と比較します。 これが機能する理由は、この問題で重要な構造特性がローカル遷移制約として表現されるためです。 
4. 許可された条件に違反する遷移が発生した場合は、その文字列を直ちに無効としてマークします。 1 つの違反で十分であるため、正当性の証明のためにスキャンを続ける必要はありません。 
5. スキャンが終了したら、文字列の分類結果を出力します。 

### なぜ効果があるのか

 正確さは、チェックされるプロパティが文字間の隣接関係のみに依存するという事実から得られます。 グローバル パターン違反は、隣接する位置間の少なくとも 1 つのローカルな不一致として現れる必要があります。 考えられるすべての欠陥はローカル遷移を通じて観察できるため、すべての無効なケースを検出するには、前の文字のみを維持するだけで十分です。 この不変式により、1 回の左から右へのトラバーサル中に、隠れた構成が検出を逃れることはできなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        if not s:
            print("NO")
            continue

        ok = True
        for i in range(1, len(s)):
            if s[i] == s[i - 1] and s[i] == "?":
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この実装はシングルパスの考え方に直接従っています。 ループ構造は中核となる決定ロジックを反映しています。つまり、各文字はその先行文字に対してのみチェックされ、スキャンの繰り返しが回避されます。 の`ok`flag は、違反が検出されたときに評価を短縮するために使用され、すでに無効になっている長い文字列に対する不必要な作業を防ぎます。 

空の文字列の境界処理は防御的に含まれていますが、一般的なテスト データには含まれていません。 安全なアクセスを確保するために、インデックスは 1 から始まります。`s[i - 1]`。

 ## 特殊なケース

 次のような単一文字入力`"A"`遷移が存在しない境界を実行します。 1 から n−1 へのループは決して実行されず、初期状態が変更されないままであるため、アルゴリズムはこれを正しく処理します。 

次のような均一な文字列`"RRRRR"`繰り返される同一の遷移に誤ってフラグが立てられるかどうかをテストします。 各比較では等価性が得られますが、違反条件は得られないため、アルゴリズムは有効性を維持します。 

次のような完全にあいまいな文字列`"????"`ロジックが未知のシンボルが異なる動作をするに違いないと誤って想定しているかどうかをテストします。 隣接する各ペアが独立して処理され、違反ルールがすべての位置に均一に適用されるため、スキャンは依然として一貫して動作します。
