 ## 解決策
 ## 問題の理解

 企業名の固定参照リストが威信順に与えられており、1 位が最も権威のある企業に対応します。 各クエリは会社名で構成されており、その名前が参照リストに表示されるかどうかを判断する必要があります。 存在する場合、そのリスト内の 1 から始まる位置を出力します。 それ以外の場合は -1 を出力します。 

重要な特性は、検索では大文字と小文字が区別されないことです。つまり、大文字または小文字だけが異なる名前は同一として扱われる必要があります。 入力サイズは控えめで、クエリは最大 1000 件、各名前は最大 1000 文字であるため、かなり直接的な検索戦略も実行可能ですが、リストが大きい場合、クエリごとに大きなリストを繰り返しスキャンするのは非効率的になります。 

主な重要なエッジケースは正規化です。 保存されたリストとクエリ文字列の両方で大文字と小文字を一貫して正規化できなかった場合、有効な一致が失われます。 たとえば、リストに「Google」が含まれており、クエリが「goOGle」である場合、大文字と小文字を区別した比較では誤って -1 が返されます。 正しい出力は、リスト内の「Google」のインデックスです。 

もう 1 つの特殊なケースは、クエリが繰り返されたり、会社名が異なる形式で繰り返されたりすることです。 クエリは独立しているため、副作用なしに同じ固定データセットに対してそれぞれのクエリに応答する必要があります。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理し、企業のリスト全体をスキャンし、大文字と小文字を区別しない比較を使用して、保存されている各名前とクエリを比較することです。 これは、一致する可能性のあるものをすべてチェックするので正しいですが、そのコストは、リスト内の企業の数とクエリの数の両方に比例して増加します。 リストに N 個のエントリがある場合、各クエリには O(N) 個の文字列比較が必要となり、合計作業量は O(TN) になります。 非表示リストが大きい場合、これはすぐに遅くなりすぎます。 

重要な観察は、企業リストが静的であるということです。 これはクエリ間で決して変更されないため、正規化された企業名からそのランクまでのハッシュ マップに一度前処理することができます。 これにより、各クエリが単一の辞書検索に減ります。 重要なステップは正規化です。すべての会社名をマップに挿入する前に小文字に変換し、大文字と小文字を区別しない一致がクエリ比較ごとではなくグローバルに 1 回処理されるようにします。 

前処理後、辞書検索はリスト サイズに依存しないため、各クエリの予想時間は O(1) になります。 これにより、繰り返しのスキャンにかかるコストが 1 回限りの前処理ステップに変わります。

 ## アルゴリズムのチュートリアル

 ### ステップ

 1. 企業ランキングリスト全体を読み、順番に保管します。 

このリストのインデックスは各一致に必要な出力であるため、順序は重要です。 
2. リスト内のすべての会社名を小文字に変換して正規化します。 

これにより、計算を繰り返すことなく、今後のすべての比較で大文字と小文字が区別されなくなります。 
3. 正規化された各企業名を 1 から始まるインデックスにマッピングする辞書を構築します。 

重複が存在する場合 (可能性は低いですが、安全に処理できます)、最初に出現したものが最高のランクに対応するため保持されます。 
4. 各クエリ文字列について、同じ小文字変換を使用して正規化します。 

これにより、保存されたキーと受信クエリの間の一貫性が保証されます。 
5. 正規化されたクエリが辞書に存在するかどうかを確認します。 

存在する場合は、保存されたインデックスを出力します。 それ以外の場合は -1 を出力します。 

### なぜ効果があるのか

このアルゴリズムは、すべての企業名が辞書内で正確に 1 つの正規形式 (小文字バージョン) で表現されるという不変条件に依存しています。 データセットとクエリの両方が同じ関数を使用して変換されるため、元の文字列の同等性は、正規化された文字列の同等性となります。 したがって、辞書は、メンバーシップおよびランク情報の完全かつ損失のない表現になります。 正規化されたキーを共有せずに有効なエントリと一致するクエリはなく、元のリストに明示的に存在しない限り、無効なクエリは辞書に表示されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# The problem refers to an external list of companies.
# In a real contest setting, this would be provided as input or preloaded.
# For this solution, we assume it is available as a static list called companies.

def solve():
    # Since the actual list is external, we simulate structure:
    # Replace this with the actual parsed list from the problem source.
    companies = sys.stdin.readline().strip().split(",")

    # Build mapping from lowercase name to rank
    rank = {}
    for i, name in enumerate(companies, start=1):
        key = name.strip().lower()
        if key not in rank:
            rank[key] = i

    t_line = sys.stdin.readline().strip()
    if not t_line:
        return
    t = int(t_line)

    out = []
    for _ in range(t):
        q = sys.stdin.readline().strip().lower()
        out.append(str(rank.get(q, -1)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核は辞書です`rank`、正規化後の各企業名の最初の出現インデックスが格納されます。 の`.lower()`呼び出しはデータセット エントリとクエリの両方に一貫して適用され、大文字と小文字を区別しない一致が保証されます。 

実装上の微妙な懸念の 1 つは、空白の削除です。 入力行には末尾のスペースや CSV 解析による隠れた書式設定アーティファクトが含まれる場合があるため、`strip()`正規化の前に適用されます。 もう 1 つの重要な詳細は、各正規化された名前の最初の出現のみを保存し、重複があった場合に最適なランクを維持することです。

 ## 特殊なケース

 重要な特殊ケースの 1 つは、企業リスト内で正規化された名前が繰り返されることです。 「Google」と「GOOGLE」など、大文字と小文字だけが異なる同じ会社の複数のバリアントが入力に含まれている場合は、最初に出現したもののみがランクを定義する必要があります。 辞書の構築では、挿入前にキーがすでに存在するかどうかをチェックすることでこれを保証します。 

もう 1 つの特殊なケースは、一貫性のない空白です。 「 google 」のようなクエリは、リスト内の「Google」と一致する必要があります。 申請中`.strip().lower()`両方の側で、そのような形式の違いが正確さに影響を与えないようにします。 

最後のエッジ ケースは、有効な会社名とプレフィックスまたはサブストリングを共有しているが、正規化後は等しくないクエリです。 たとえば、「google」は「google」と一致してはなりません。 辞書検索ではキーが正確に一致する必要があるため、そのような部分一致では正しく -1 が返されます。
