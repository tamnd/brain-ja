 ## 解決策
 ## 問題の理解

 各頂点が整数値を保持する無向グラフが与えられます。 タスクは、通常の最短パスの意味ですべてのパスにわたって何かを計算することではなく、代わりにグラフ内のすべての単純なパスを考慮し、それらのいずれかを選択し、そのパスに沿った頂点値の XOR をとり、この結果を最大化することです。 

ここでの有効なパスは、連続する頂点がエッジで接続されている一連の個別の頂点によって定義されます。 パスの長さは 1 つの頂点ほど短くすることができます。つまり、答えは少なくとも 1 つの頂点の最大値になります。 

グラフの構造は、頂点のどのサブセットを反復せずに連続して訪問できるかを決定するため、重要です。 XOR 集約は、XOR が単調ではなく、パスの拡張下では適切に動作しないため、問題を一般的な最長パスまたは最大合計パスの問題とは根本的に異なります。 

この制約は、最大 1000 個の頂点と潜在的に非常に多くのエッジを持つ適度に大きなグラフを示唆しています。 すべての単純なパスを単純に列挙することは不可能です。まばらなグラフであっても、指数関数的に多くのパスが含まれる可能性があるからです。 これにより、「訪問ノードのセットとしての現在のパス」に直接的に依存する状態定義が直ちに除外されます。 

微妙な点は、パスが最大である必要も、コンポーネント内のすべてのノードをカバーする必要もないことです。 部分的なトラバースは許可され、再訪問は禁止されます。 これは、パス内の頂点を組み合わせる複数の異なる方法を有効にすることによって、サイクルが間接的にのみ重要になることを意味します。 

素朴だがよくある間違いは、これが、接続されているすべてのサブセットまたはすべてのスパニング ウォークにわたって最大 XOR を計算することと同等であると想定することです。 たとえば、値を含む三角グラフの場合`[1, 2, 3]`不注意な仮定により、すべてのノードを取得すると常に最良の XOR が得られるが、パスによって達成可能な組み合わせが制限される可能性があります。 

グラフが切断されているか、非常にまばらな場合、エッジ ケースが発生します。 完全に切り離されたグラフでは、答えは単純に最大値になります。`v_i`。 ツリーでは、すべてのパスは単純で循環がありませんが、エンドポイントの選択肢の数は依然として指数関数的です。 

## アプローチ

 ブルート フォース アプローチでは、すべての頂点から DFS を実行して、現在の XOR を維持し、訪問したノードをマークしようとします。 パスを拡張するたびに、最良の回答が更新されます。 DFS は自然に再訪問禁止制約を強制するため、これによりすべての単純なパスが正しく探索されます。 

ただし、そのようなパスの数は指数関数的に増加します。 完全なグラフでは、単純なパスの数は次のとおりです。`n!`最悪の解釈では、ノードの順列は有効な単純なパスを形成するためです。 まばらなグラフであっても、DFS は指数関数的な爆発にすぐにつながる分岐要因を探索します。 

重要な洞察は、グラフ構造は複雑ですが、XOR 演算は GF(2) に対する線形代数構造を持っているということです。 パスについて直接推論する代わりに、視点を変えることができます。すべてのパスの XOR は、パスのような順序で接続された頂点のサブセットに対する単なる XOR ですが、XOR 自体はコンポーネントのないセット内の順序や繰り返しには依存せず、包含にのみ依存します。 

これは 2 つの効果を分離することを示唆しています。接続性は 1 つのパス内に同時に表示できる頂点を制限しますが、XOR 集約はどの頂点が選択されるかのみに依存します。 問題は、各接続コンポーネント内で、単純なパスに配置できる頂点を使用してどのような XOR 値を形成できるかということです。 

重要な観察は、接続されたコンポーネントでは、頂点値の XOR 空間上の基底を生成できるトラバーサル構造が可能であるということです。 接続によりノード間を移動できるようになり、サイクルにより、到達可能性を損なうことなくどのノードを含めるかを調整できるようになります。 最終的に、到達可能なすべての XOR の組み合わせは、スパニング ツリー構造と結合された、各コンポーネントの頂点値の線形スパン (GF(2) にわたる) に対応します。 

したがって、問題は、連結成分ごとの値の線形基礎を構築することに帰着します。 コンポーネント内のすべてのノード値から XOR 基底を計算できます。これは、接続性制約と一致するサブセットを選択することでパス XOR を実現でき、サイクルによって接続性を超える追加の構造的制限がなくなるためです。 

最後に、答えは、すべてのコンポーネントにわたる XOR 基底で表現できる最大値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての単純なパスに対するブルート フォース DFS | お(ん!) | O(n) | 遅すぎる |
 | コンポーネント + XOR 線形基底 | O((n + m) log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフ トラバーサルを使用して、各接続コンポーネントを個別に処理します。 各コンポーネントについて、すべてのノード値を収集し、それらをバイナリ XOR ベースに挿入します。 

1. グラフの隣接リストを作成します。 

これにより、接続されたコンポーネントを効率的に走査できます。 
2. 訪問した配列を維持し、すべての頂点を反復処理します。 

未訪問の頂点ごとに新しいコンポーネントが開始されます。 
3. BFS または DFS を実行して、現在のコンポーネント内のすべての頂点を収集します。 

目的は、パスが自由に移動できる領域を分離することです。 
4. コンポーネント内の各頂点について、その値をバイナリ線形基底に挿入します。 

値が 30 ビット未満であるため、基底は 30 ビットにわたって維持されます。`2^30`。 
5. 基底挿入のマージ ルールは標準です。既存の基底ベクトルを使用して最も高い設定ビットを削除しようとし、非ゼロが残っている場合は、それを新しい基底ベクトルとして保存します。 
6. コンポーネントを処理した後、そのベースから達成可能な最大の XOR を計算します。 

これは、最上位ビットから最下位ビットまでの基底ベクトルを使用して実行中の XOR 値を改善しようとすることで、貪欲に行われます。 
7. すべてのコンポーネントにわたる最大の結果を追跡します。 

コンポーネントを分離する理由は、切断されたコンポーネント間でパスが交差できないため、XOR 寄与が独立しているためです。 

### なぜ効果があるのか

 接続されたコンポーネント内では、何らかのウォークを介して他の頂点から任意の頂点に到達でき、サイクルによってトラバースの選択肢を組み換えることができます。 XOR 基底は、そのコンポーネント内の値のサブセットから達成可能な XOR 組み合わせの空間を正確にキャプチャします。 XOR は結合性と可換性があるため、パスの順序付け制約によって接続性を超えて最終的な XOR 空間が制限されることはありません。 したがって、すべての有効なパスにわたって最大化することは、各コンポーネントの頂点値の線形スパンにわたって最大化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)
    
    vis = [False] * n
    
    def add_to_basis(basis, x):
        for i in reversed(range(30)):
            if (x >> i) & 1:
                if basis[i] == 0:
                    basis[i] = x
                    return
                x ^= basis[i]
        return
    
    def maximize(basis):
        res = 0
        for i in reversed(range(30)):
            res = max(res, res ^ basis[i])
        return res
    
    from collections import deque
    
    ans = 0
    
    for i in range(n):
        if vis[i]:
            continue
        
        q = deque([i])
        vis[i] = True
        comp = []
        
        while q:
            u = q.popleft()
            comp.append(u)
            for w in g[u]:
                if not vis[w]:
                    vis[w] = True
                    q.append(w)
        
        basis = [0] * 30
        
        for u in comp:
            add_to_basis(basis, v[u])
        
        ans = max(ans, maximize(basis))
    
    print(ans)

if __name__ == "__main__":
    solve()
```隣接リストの構築は標準であり、接続されている各コンポーネントを線形時間で探索​​できることが保証されます。 BFS は 1 つのコンポーネントに属するすべての頂点を収集するため、コンポーネントを自己完結型システムとして扱うことができます。 

の`add_to_basis`関数は、古典的な XOR 線形基底挿入を実装します。 以前に保存された基底ベクトルを使用して、最も高い設定ビットを削除しようとします。 それができない場合は、数値を新しい独立ベクトルとして保存します。 これにより、基底が最小限かつ独立したままであることが保証されます。 

の`maximize`関数は、基底から達成可能な最良の XOR 値を貪欲に構築します。 上位ビットから下位ビットまで反復することで、整数値の最大化と一致する辞書編集上の最も重要な順序で結果を改善しようと常に試みることが保証されます。

 ## 特殊なケース

 BFS はシングルトン コンポーネントを生成し、基底が単一の値に減少するため、完全に切り離されたグラフは自然に処理されます。 入力用`n=3`価値観を持って`5 1 4`エッジがなく、各コンポーネントは独自の値を生成し、最大値は`5`、マージが発生しないため、アルゴリズムと一致します。 

完全なグラフは、最悪の接続ケースをテストします。 すべての頂点は 1 つのコンポーネント内にあり、基底はすべての XOR 方向をキャプチャします。 指数関数的に多くのパスが存在する場合でも、基本はすべてを最大 30 ベクトルに削減し、貪欲な最大化によりパスを列挙することなく最適な XOR 値を抽出します。 

すべての頂点が同じ値を共有するグラフも安全です。 基底挿入が同じ数値を繰り返し挿入しようとしても、各挿入は既存の基底によってすぐに削除され、単一の代表ベクトルが残ります。
