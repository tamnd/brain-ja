 ## 解決策
 ## 問題の理解

 体力値を持つモンスターが 3 人います`a`、`b`、 そして`c`。 

通常の大砲の射撃は、生きているモンスター 1 体に 1 ダメージを与えます。 7 番目のショットはすべて特別です。 単一のモンスターをターゲットにする代わりに、その時点でまだ生きているすべてのモンスターに1ダメージを与えます。 

目的は単にすべてのモンスターを倒すことではありません。 3 匹のモンスターはすべて、同じ強化ショットで一緒に死ぬ必要があります。 そのショットの前には、すべてのモンスターがまだ生きている必要があり、その強化されたショットの直後に、3 つの健康値すべてが初めてゼロになります。 

入力には最大で次のものが含まれます`10^4`テストケース。 各健康値は次のように大きくなります。`10^8`, そのため、個々のショットに基づいたシミュレーションは不可能です。 1 つのテスト ケースで数億のショットが必要になる場合があり、その場合は線形シミュレーションが即座に除外されます。 一定時間でチェックできる数学的条件が必要です。 

巧妙な罠は、全体的な健康状態のみが重要であると仮定することです。 

例えば：```
1
10 1 7
```健康状態の合計は 18 で、9 で割り切れますが、答えはまだ変わりません。`NO`。 1 匹のモンスターは他のモンスターに比べて弱すぎるため、最後の強化ショットの前に死んでしまいます。 

もう 1 つの簡単な間違いは、すべてのモンスターは最後の強化ショットまで生き残らなければならないことを忘れていることです。 

例えば：```
1
1 1 7
```合計の健康状態は 9 であり、9 ダメージの完全な 1 サイクルを示唆しています。 ただし、最後の強化ショットの後、各モンスターは強化されていないダメージ割り当ての少なくとも 3 分の 1 を受けなければなりません。 体力 1 の 2 匹のモンスターは、それを可能にするのに十分なダメージを吸収できないため、答えは次のとおりです。`NO`。 

すべてのモンスターが等しい場合、別のエッジケースが発生します。```
1
3 3 3
```合計体力は9で、各モンスターは最後の強化ショットに簡単に参加できます。 正しい答えは、`YES`。 

これらの例が異なる理由を理解することは、重要な観察に直接つながります。 

## アプローチ

 ブルートフォースアプローチでは、戦闘をシミュレートしようとします。 通常のショットごとにどのモンスターが受けるかを繰り返し選択し、7 ショットごとに強化効果を適用することができます。 最終的には、3 匹のモンスターがすべて一緒に死ぬかどうかを確認します。 

このアプローチはゲームを正確にモデル化するため、原則として正しいです。 問題は、健康値が次の値に達することです。`10^8`。 ダメージの合計は最大で`3 × 10^8`したがって、1 つのテスト ケースでも数億回の操作が必要になります。 

重要な観察は、通常のショットの正確な順序は重要ではないということです。 問題となるのはダメージの総額だけです。 

モンスターが死んだとしましょう`k`- 番目の強化ショット。 

7 つのショットの各グループには、6 つの通常のショットと 1 つの強化されたショットが含まれています。 したがって、各完全なサイクルは以下に寄与します。```
6 targeted damage
3 enhanced damage
```合計9ダメージ。 

すべてのモンスターが最後の強化ショットで死亡した場合、与えられるダメージの合計は体力の合計と等しくなければなりません。```
a + b + c = 9k
```したがって、合計は 9 で割り切れる必要があります。 

次に、各モンスターが強化されたショットによってどのくらいのダメージを受けるかを考えてみましょう。 最後の強化ショットが彼らを殺すものであるため、すべてのモンスターはそれまで生き残らなければなりません。 したがって、各モンスターは正確に受け取ります`k`全体的にダメージが強化されました。 

それらを削除した後、`k`ポイント、モンスターに必要な残りダメージ`i`通常のショットから来ている必要があります。 

通常撮影可能枚数は`6k`。 

これを可能にするためには、どのモンスターもこれより少ない量を必要とすることはできません。`k`完全な健康。 そうしないと、すべてを受け取る前に死んでしまいます`k`強化されたヒット。 

それは次のようになります:```
min(a, b, c) >= k
```以来```
k = (a + b + c) / 9
```問題全体は 2 つの簡単なチェックに集約されます。 

ブルートフォースは文字通りゲームに従うため機能しますが、健康値が膨大であるため失敗します。 成功するすべての戦闘は完全な 9 ダメージ サイクルで構成されているという観察により、シミュレーションを算術演算に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(a+b+c) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 総合的な健康状態を計算します。```
s = a + b + c
```2. かどうかを確認します。`s`は9で割り切れます。 

そうでない場合は、印刷してください`NO`。 

強化されたショットで終了した戦闘の成功`k`サイクルは常に正確に処理します`9k`ダメージ。 
3. 以下を計算します。```
k = s / 9
```これは強化ショットが発生する必要がある数です。 
4. 最小の健康値を見つけます。```
m = min(a, b, c)
```5. もし`m < k`、印刷`NO`。 

すべてのモンスターはすべての状況を乗り越えなければなりません`k`強化されたショット。 体力が以下のモンスター`k`最終的な強化ショットの前にゼロに達します。 
6. それ以外の場合は印刷します`YES`。 

### なぜ効果があるのか

 答えは次のようになると仮定します`YES`。 

モンスターたちが一緒に死んだ場合`k`- 番目の強化ショット、正確に`k`完全なショットサイクルが発生します。 各サイクルは合計 9 のダメージを与えるため、合計の健康状態は次の値に等しくなければなりません。`9k`。 これは9で割り切れることを証明します。 

また、生きているモンスターはすべて、強化されたショットごとに 1 ポイントのダメージを受けます。 すべてのモンスターは最後の強化ショットまで生き残るため、各モンスターは少なくとも吸収する必要があります`k`ダメージ。 したがって、`min(a,b,c) ≥ k`。 

ここで、両方の条件が当てはまると仮定します。 させて`k = (a+b+c)/9`。 

各モンスターが消費できるのは、`k`ダメージ強化時のヘルスポイント。 これらの寄与分を取り除いた後、残りの必要なダメージは次のようになります。```
(a-k) + (b-k) + (c-k)
= (a+b+c) - 3k
= 9k - 3k
= 6k
```その通り`6k`通常のショットが存在します。 すべての残りの量は負ではないため、これらの通常のショットはそれに応じて分配できます。 したがって、すべてのモンスターは最後の強化ショットの直前に体力 1 に達し、そのショットで一緒に死にます。 

この 2 つの条件は必要十分条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        a, b, c = map(int, input().split())
        
        s = a + b + c
        
        if s % 9 != 0:
            print("NO")
            continue
        
        k = s // 9
        
        if min(a, b, c) < k:
            print("NO")
        else:
            print("YES")

solve()
```解決策は証明に直接続きます。 

最初の条件は、合計ヘルスが 9 ダメージ サイクルの整数として表現できるかどうかをチェックします。 そうでない場合、強化されたショットで終了する可能性はありません。 

その後、`k`は一意に決まります。 サイクル数は総ヘルスによって決まるため、検索する必要はありません。 

2 番目の条件は、すべてのモンスターがどんな状況でも生き残ることができることを確認します。`k`強化されたショット。 使用する`min(a,b,c)`最小のモンスターが生き残れば、より大きなモンスターも確実に生き残るので、これで十分です。 

すべての計算は標準の整数型内に快適に収まります。 Python ではオーバーフローの心配はありませんが、64 ビット整数であっても最大合計は`3 × 10^8`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        s = a + b + c

        if s % 9 != 0:
            print("NO")
            continue

        k = s // 9
        print("YES" if min(a, b, c) >= k else "NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample

 ## 特殊なケース

 次のことを考慮してください。```
1
1 4 4
```合計は9なので、`k = 1`。 最小の健康状態も 1 です。`1 ≥ 1`、アルゴリズムの出力`YES`。 1 匹のモンスターは、強化されたショットを 1 回だけ生き残ることができ、最後のショットで死ぬ可能性があります。 平等は許可されますが、これは一般的なオフバイワンの罠です。 

考慮する：```
1
10 1 7
```合計は18なので、`k = 2`。 最小の健康状態は 1 です。`1 < 2`、アルゴリズムの出力`NO`。 体力 1 のモンスターは強化 2 発で生き続けることができないため、同時キルは不可能です。 

考慮する：```
1
1 1 1
```合計は 3 です。`3 % 9 != 0`、アルゴリズムはすぐに出力します`NO`。 合計ヘルスに一致する完全な 9 ダメージ サイクルの整数は存在しません。 

考慮する：```

2 2 5
```合計は9なので、`k = 1`。 最小健康状態は 2 であり、これは次の条件を満たします。`2 ≥ 1`。 アルゴリズムの出力`YES`。 これにより、1 つの完全なサイクルが存在し、すべてのモンスターが最後の強化されたショットに参加できる境界が検証されます。
