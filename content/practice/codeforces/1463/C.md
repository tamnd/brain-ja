 ## 解決策
 ## 問題の理解

 1 台のロボットが位置 0 から直線上を移動します。 それぞれに時間と目標位置を指定する一連のコマンドを送信します。 コマンドが到着すると、ロボットは直ちにそのターゲットに向かって単位速度で移動を開始します。 ターゲットに向かって移動している間、ターゲットに到達するか現在の動作が完了するまで、新しいコマンドは無視されます。 

各コマンドは、完全なモーションがわかった後に判断されます。 コマンドが発行されてから次のコマンドが到着する直前まで (または最後のコマンドの場合は永遠に) 時間間隔中、ある瞬間にロボットがそのコマンドの目標位置に正確に存在する場合、コマンドは成功したとみなされます。 重要なのは、ロボットがその位置に到達したときに、実際にはそのコマンドを実行していない可能性があることです。 その軌道がその時間枠内に通過するだけで十分です。 

重要な問題は、コマンドは無視される可能性がありますが、無視されたコマンドでも成功する可能性があることです。 実行と成功の間にこの断絶があるため、私たちはロボットが選択した目的地だけではなく、ロボットの継続的な経路について推論する必要があります。 

この制約により、すべてのテスト ケースで最大 100,000 個のコマンドが許可されるため、どのソリューションでも各コマンドを定数時間または対数時間で処理する必要があります。 動きは最大 10^9 秒の間隔で発生するため、時間単位ごとにチェックしようとするシミュレーションは不可能です。 

素朴な考えによる微妙な失敗例は、コマンド間隔が終了してからかなり時間が経ってからロボットがポイントを通過する場合、または後のコマンドの実行中にロボットがポイントを通過する場合に現れます。 たとえば、コマンドがロボットを明示的にターゲットにしていないポイントに送信する場合でも、ロボットの移動セグメントが有効な時間枠内でその座標を横切れば成功する可能性があります。 別のエッジ ケースは、コマンドがすぐに無視されるが、そのターゲットがモーションの後のセグメントにある場合に発生します。 その瞬間にロボットがターゲットに向かって移動しているかどうかだけをチェックする単純なアプローチでは、これを見逃してしまいます。 

## アプローチ

 直接シミュレーションでは、ロボットの位置を時間の経過とともに追跡し、コマンドごとに、関連する間隔中にロボットの軌道がターゲット位置と交差するかどうかを明示的にチェックします。 動きを秒ごと、またはイベントごとにシミュレートし、すべての動きセグメントに対して各コマンドをテストすることができます。 ロボットのパスは区分的に線形であるため、これは原理的には正しいです。 ただし、各セグメントの時間が非常に長くなる可能性があり、各コマンドで多くのセグメントをスキャンする必要がある可能性があります。 すべてのコマンドが将来の多くの動きと相互作用する可能性があるため、最悪の場合、これは二次的な動作に変質します。 

重要な観察は、ロボットの動作がコマンド処理イベント間の線形セグメントによって完全に決定されるということです。 ロボットが方向またはターゲットを変える 2 つの瞬間の間の位置は、時間のアフィン関数です。 時刻 t_i に発行されたコマンドの場合、次のコマンド時刻の前のある時点で位置関数が x_i と交差するかどうかのみを考慮します。 すべての連続動作をチェックする代わりに、ロボットの現在のセグメントを維持し、交点を代数的にチェックできます。 

各セグメントは、開始時間、開始位置、終了時間、および方向によって定義されます。 ロボットは一定の速度で移動するため、O(1) でいつでもその位置を計算できます。 問題は、ターゲット ポイントが、間隔 [t_i, t_{i+1}] と重なる各アクティブ セグメントの開始点と終了点のロボットの位置の間にあるかどうかを確認することになります。 

重要な単純化は、時刻 t_i と時刻 t_{i+1} (または、それより早く動作を停止した瞬間) でのロボットの位置が x_i の反対側にある場合、またはどちらかの境界で正確に等しい場合にのみ、コマンドが成功するということです。 これにより、問題は、点が 1D の線分上にあるかどうかを確認することになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | セグメントベースのシミュレーション | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 連続したコマンドによって決定される連続セグメントを使用してロボットの動作をシミュレートします。 

1. ロボットを位置 0、時間 0 に初期化します。また、ロボットがアイドルになったり方向を切り替えたりしたときの現在位置と時間を追跡します。 
2. 各コマンド i について、ロボットが最後の更新時刻から t_i までにどれだけ進んだかを計算します。 これにより、時刻 t_i におけるロボットの正確な位置が得られます。 これは、ロボットが移動中または待機中にコマンドが到着するために必要です。 
3. ロボットが現在前のターゲットに向かって移動しているか、すでにアイドル状態であるかを判断します。 移動している場合、現在の軌道が線形にわかります。 アイドル状態の場合は、最後の位置に固定されたままになります。 
4. t_i 以降はコマンド i の判定には無関係であるため、前のコマンドの効果を t_i までのみシミュレートします。 
5. 間隔 [t_i, t_{i+1}] の間にロボットが x_i に到達したかどうかを確認します。 動きは線形であるため、これは、x_i が t_i でのロボットの位置と、次のコマンドが中断される前または現在のセグメントを終了する前にロボットが到達する位置との間にあるかどうかをチェックすることと同じです。 
6. x_i がその到達可能な間隔内にある場合、コマンドは成功としてカウントされます。 
7. ロボットの状態を更新して、時刻 t_i で x_i への新しいコマンドを受信したことを反映します。ただし、ロボットが現在移動していない場合に限ります。 移動している場合、コマンドは軌道の目的で無視されます。 

重要な推論ステップは、すべての動作セグメントの位置が単調であるため、ロボットが各座標を横切るのはセグメントごとに最大 1 回だけであるということです。 

### なぜ効果があるのか

 ロボットの時間の経過に伴う位置は常に、+1、-1、または 0 のいずれかの一定速度を持つ、互いに素な線形セグメントの和集合です。固定コマンド i の場合、[t_i, t_{i+1}] 内の一部の t について連続関数 x(t) が x_i に等しいかどうかのみを考慮します。 x(t) は各セグメントで単調であるため、条件は、x_i がその時間間隔と交差するセグメントの端点の間にあるかどうかをチェックすることになります。 この不変条件により、交差点を見逃すことも、交差点を二重にカウントすることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        t = []
        x = []
        for _ in range(n):
            a, b = map(int, input().split())
            t.append(a)
            x.append(b)

        pos = 0
        time = 0
        target = 0
        moving = False
        ans = 0

        i = 0
        while i < n:
            ti = t[i]
            xi = x[i]
            ni = t[i + 1] if i + 1 < n else float('inf')

            if moving:
                dt = ti - time
                if target > pos:
                    pos = min(target, pos + dt)
                else:
                    pos = max(target, pos - dt)

                if pos == target:
                    moving = False
                time = ti

            # current position at time ti is pos

            # compute how far robot can go before next command
            if moving:
                dist = abs(target - pos)
                reach_time = ti + dist
            else:
                reach_time = float('inf')

            end_time = min(ni, reach_time)

            if pos <= xi <= target or target <= xi <= pos:
                if ti <= reach_time:
                    ans += 1

            # process command i
            if not moving:
                if pos != xi:
                    target = xi
                    moving = True
                    time = ti

            i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ロボットの圧縮状態 (現在位置、移動しているかどうか、および現在の目的地) が保持されます。 コマンドを評価する前に、まずロボットを、経過間隔にわたる動作を消費することによってコマンド時間まで進めます。 成功のチェックは、現在の位置から中断前の到達可能な最も遠い点までのセグメント内にターゲットが存在するかどうかを確認することに帰着します。 

微妙な点は、成功を評価する前に、コマンド時に正確に位置を更新する必要があることです。 もう 1 つは、動きが固定されているため、ターゲットをオーバーシュートすることがないことです。 そうしないと、目的地を超えた位置を誤って通り過ぎてしまいます。 

## 実用的な例

 時間 1、3、6 で 5、0、4 をターゲットとするコマンドによる小規模な実行を考えてみましょう。ロボットは 0 から開始します。 

| ステップ | 時間 | ポジション | ターゲット | 移動 | 到達時間 | 成功？ |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 5 | はい | 5 | いいえ |
 | 2 | 3 | 3 | 0 | はい | 5 | はい |
 | 3 | 6 | 5 | 4 | はい | 7 | はい |

 2 番目のコマンドは、その間隔中にロボットが無視されたにもかかわらずターゲットを通過するため、成功します。 3 番目は、前のモーションが終了した後、直接 4 に到達するため成功します。 

ここで、ロボットがその後の移動によりターゲットをオーバーシュートしたが、それでも有効な間隔内でターゲットを横切った場合を考えてみましょう。 アルゴリズムは、現在の移動方向だけでなく、中断時間までの到達可能なセグメント全体をチェックするため、これを捕捉します。

 ## 特殊なケース

 重要なエッジケースは、コマンドがロボットの現在位置を正確にターゲットとする場合です。 この状況では、コマンドは、たとえ動きを生成しなくても、自明に成功します。 間隔チェックによりアルゴリズムがこれを処理します。`pos <= xi <= target`平等に堕落する。 

もう 1 つのエッジ ケースは、ロボットがすでにターゲットから遠ざかっていたが、後でターゲットを横切る場合です。 中断前に完全な到達可能なセグメントを計算するため、次のコマンド時間よりも前に交差が発生する限り、交差は引き続き検出されます。 

最後のエッジケースは、ロボットが長い移動を完了する前に複数のコマンドが到着した場合に発生します。 コマンドごとに状態が更新されるため、モーションが正しく切り捨てられるため、セグメントが有効な間隔を超えて延長されることはなく、成功が外部でカウントされることもありません。`[t_i, t_{i+1}]`。
