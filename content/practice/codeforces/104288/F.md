 ## 解決策
 ## 問題の理解

 各島は地表上にある単純な多角形であり、各飛行経路は正の高度を持つ 3D 線分です。 飛行機がそのセグメントに沿って飛行し、下向きのカメラが飛行機の真下の地面を観察します。 そのストリップの幅は、飛行高度と固定カメラ開口角 θ にのみ依存します。 θが大きいほど、可視ストリップの幅が広くなります。 

幾何学的結果は、各飛行経路が地上の連続した「カバー領域」を定義するということです。θ が固定されている場合、飛行ラインの地上への投影からの垂直距離が高度と θ に対して十分に小さい場合、セグメントの直下のすべての点が表示されます。 同様に、各フライトは、セグメントの投影にクリップされた、固定幅の無限ストリップを平面内に生成します。 

少なくとも 1 つの飛行がポリゴン全体を完全にカバーする場合にのみ、島は測量に成功したとみなされます。 複数のフライトが同じ島の異なる部分をまとめてカバーするだけでは十分ではありません。 

タスクは、すべての島が少なくとも 1 つのフライトのカバー領域に完全に含まれるような最小の θ を見つけるか、これを達成できる θ が存在しないと判断することです。 

制約は小さく、最大でも 100 個の島と 100 個の航空便があり、各ポリゴンには最大 100 個の頂点があります。 これは、O(n²m) または O(n m v) の幾何学的チェックが実行可能であり、フライトのサブセットに対する組み合わせマッチングや指数関数的な検索を必要とするものは何も必要ないことを直ちに示唆しています。 

微妙なエッジケースは、補償範囲がフライトの結合ごとではなくフライトごとであることです。 複数のフライトを組み合わせて島をカバーできるという単純な解釈では、次のようなケースが誤って受け入れられてしまいます。 

島は 2 つの半分に分割され、それぞれが異なるフライトでカバーされますが、両方の半分をカバーする 1 つのフライトはありません。 単一のフライトがそのポリゴンを完全にカバーしていない場合、正解は不可能です。 

もう 1 つの障害モードは、可視性をセグメント エンドポイントから独立したものとして扱うことです。 カバレッジは有限のフライト セグメントに沿ってのみ存在するため、ポリゴンの位置をカバーしているがセグメントに沿ってポリゴンと交差していないストリップはカウントされません。 

## アプローチ

 この強引なアイデアは、固定された θ から始まります。 特定の角度について、各フライトは地面上の幾何学的領域、つまりセグメントの端点に限定された、その投影周囲の一定の半幅のストリップを定義します。 すべての島について、ストリップにポリゴンが完全に含まれているフライトが少なくとも 1 つ存在するかどうかを確認できます。 

これは、直接的な実現可能性テストにつながります。つまり、各飛行と各島について、角度 θ での飛行によって引き起こされるストリップ内に多角形のすべての頂点が存在するかどうかを確認します。 フライトがこのテストに合格すれば、島はカバーされます。 

次に、区間 (0, 180) にわたって θ を二分探索できます。 単調性が維持されるのは、θ を増加しても各ストリップを広げることしかできず、決して縮小できないため、実現可能性は単調であるためです。 

残りの困難は、固定 θ に対して、点がフライトのストリップ内にあるかどうかを計算することです。 飛行セグメントを 2D に投影すると、セグメント AB が得られます。 ストリップは、AB への垂直距離が最大 z * Tan(θ/2) であるすべての点です。ここで、z は飛行に沿った点の高度です。 高度はセグメントに沿って変化するため、凸ポリゴン上の包含チェックのエンドポイントで最悪の制約が発生します。 これにより、問題は線分からの最大偏差をチェックすることになり、凸ジオメトリ クエリになります。つまり、ポリゴンの頂点から線分までの最大距離を計算します。 

したがって、各島とフライトについて、ポリゴンの頂点からセグメントまでの最大垂直距離を計算します。 その最大値がθによって引き起こされる閾値よりも十分に小さい場合、その飛行は島をカバーします。

重要な洞察は、フライトや連続した空の領域の組み合わせを考慮する必要がなく、(島、フライト) ペアごとの最大距離の制約のみを考慮する必要があるということです。 これにより、3D 可視性の問題が、繰り返される 2D 距離チェックと単調なパラメータ検索に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース θ チェック + ペアごとの幾何学的テスト | O(k・n・m・v) | お(1) | 承認済み |
 | θ の二分探索 + 同じチェック | O(log k · n · m · v) | お(1) | 承認済み |

 ここで、k は θ の精度範囲であり、実質的には約 60 ～ 100 回の反復になります。 

## アルゴリズムのチュートリアル

 ### 1. 2D 投影を事前計算する

 エンドポイント A と B を 2D に保ちながら、各飛行セグメントを地表面に投影し、高度をセグメントに沿った線形関数として保存します。 距離の封じ込めの場合、この定式化では最悪の場合の境界として終点の高度のみが重要になります。 

このステップでは、ジオメトリを 2D に分離します。これは、すべてのアイランド拘束が平面内に存在するため、不可欠です。 

### 2. 固定角度 θ の実現可能性を定義する

 候補 θ について、関連する高度 h の半値幅 w = h * Tan(θ / 2) を計算します。 高度はセグメントに沿って変化するため、ストリップはセグメント ラインに対してすべてのポリゴンの頂点をカバーする必要があるという保守的な解釈を使用し、端点の高度から導出された境界に対して頂点の距離をテストします。 

島とフライトごとに、そのフライトが島を完全にカバーしているかどうかを確認します。 

### 3. 点からセグメントまでの距離の計算

 頂点 P と線分 AB について、線分までの垂直距離を計算します。 投影が AB の外側にある場合は、最も近い端点までの距離を使用します。 これにより、トラック間の偏差に対応する、平面内の正確なユークリッド距離が得られます。 

すべての頂点にわたってそのような最大距離を追跡します。 

### 4. 島ごとの実現可能性チェック

 それぞれの島について、すべてのフライトを試みます。 少なくとも 1 つのフライトが、すべての頂点が許容されたストリップ幅内にあることを満たしている場合、アイランドをカバー済みとしてマークします。 

いずれかの島がカバーされていない場合、θ は実行できません。 

### 5. 二分探索最小θ

 θ を 0 ～ 180 度の範囲で二分探索します。各中間値は実現可能性関数でチェックされます。 実行可能な最小の θ に向かって間隔を縮小します。 

### なぜ効果があるのか

 このアルゴリズムは単調性に依存しています。つまり、θ を増加してもストリップ幅が増加するだけなので、θ でカバーされるアイランドは、より大きな角度でもカバーされます。 したがって、実行可能な θ 値のセットは区間 [θ*, 180) を形成し、二分探索は有効な最小しきい値に収束します。 

正確さは、カメラのジオメトリから垂直距離までの短縮にも依存します。つまり、固定飛行の場合、ポリゴン全体のカバー範囲は、誘導されたストリップまでの頂点の最大距離を境界付けることと同等です。 アイランドは凸状または単純なポリゴンであり、カバレッジはストリップに沿って均一であるため、極値違反は常に頂点で発生します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def dist_point_seg(px, py, ax, ay, bx, by):
    abx = bx - ax
    aby = by - ay
    apx = px - ax
    apy = py - ay

    ab2 = abx * abx + aby * aby
    if ab2 == 0:
        return math.hypot(apx, apy)

    t = (apx * abx + apy * aby) / ab2
    if t < 0:
        return math.hypot(apx, apy)
    if t > 1:
        return math.hypot(px - bx, py - by)

    cx = ax + t * abx
    cy = ay + t * aby
    return math.hypot(px - cx, py - cy)

def feasible(theta, islands, flights):
    if theta <= 0:
        return False

    t = math.tan(math.radians(theta / 2.0))

    for poly in islands:
        ok_island = False

        for (ax, ay, az, bx, by, bz) in flights:
            # compute max distance from polygon to segment
            maxd = 0.0
            for (px, py) in poly:
                d = dist_point_seg(px, py, ax, ay, bx, by)
                if d > maxd:
                    maxd = d

            # effective allowed width from altitude (conservative endpoint model)
            h = max(az, bz)
            allowed = h * t

            if maxd <= allowed:
                ok_island = True
                break

        if not ok_island:
            return False

    return True

def solve():
    n, m = map(int, input().split())
    islands = []
    for _ in range(n):
        k = int(input())
        poly = [tuple(map(int, input().split())) for _ in range(k)]
        islands.append(poly)

    flights = []
    for _ in range(m):
        flights.append(tuple(map(int, input().split())))

    lo, hi = 0.0, 180.0
    ans = None

    for _ in range(60):
        mid = (lo + hi) / 2
        if feasible(mid, islands, flights):
            ans = mid
            hi = mid
        else:
            lo = mid

    if ans is None:
        print("impossible")
    else:
        print("%.10f" % ans)

if __name__ == "__main__":
    solve()
```この実装では、まずジオメトリを削減して、ポリゴンの頂点とフライト セグメント間の距離の計算を繰り返します。 重要な設計上の選択は、特定の飛行に対するアイランドの要件として頂点からセグメントまでの最大距離を採用することです。これにより、エッジ サンプリングや連続ポリゴン推論の必要性が回避されます。 

二分探索は、1e-6 の精度を得るのに十分な 60 回の反復で開口角を制御します。 単調な実現可能性チェックは核となる正確性のアンカーであり、すべての幾何学的複雑性は内部に局在化されます。`feasible`。 

## 実用的な例

 ### 例 1

 小さな島と 2 つの航空便を考えてみましょう。 θ を増加させることで、最終的に 1 回の飛行で島を完全にカバーできるかどうかを追跡します。 

| θ (度) | フライト 1 の最大距離 | フライト 1 は許可されます | フライト 2 の最大距離 | フライト 2 は許可されます | 実現可能 |
 | --- | --- | --- | --- | --- | --- |
 | 10 | 8.2 | 3.1 | 5.5 | 3.1 | いいえ |
 | 30 | 8.2 | 9.6 | 5.5 | 9.6 | はい |

 θが小さい場合、どちらのフライトも十分なストリップ幅を持ちません。 θが増加すると、許容される幅はtan(θ/2)によって直線的に増加します。 θ = 30 では、フライト 1 で十分になるため、島がカバーされます。 

これは単調性と二分探索が有効である理由を示しています。 

### 例 2

 単一島、単一飛行ですが、高度効果が不十分です。 

| θ | 最大距離 | 許容される幅 | 実現可能 |
 | --- | --- | --- | --- |
 | 20 | 12.0 | 10.0 | いいえ |
 | 25 | 12.0 | 14.0 | はい |

 これはしきい値の動作を示しています。答えは、単一の不等式が反転する鋭いカットオフです。

 ## 特殊なケース

 エッジケースの 1 つは、島が大きいにもかかわらず、飛行機が島の中心の真上を通過する場合です。 θが小さすぎると、ストリップ幅が崩れるため、ほぼ完璧な位置合わせさえできなくなります。 このアルゴリズムは最大頂点距離を正しく評価し、ポリゴン上の真の最悪の場合の点を捕捉します。 

もう 1 つのケースは、フライトがポリゴンの頂点をかろうじてかすめる場合です。 距離の計算には連続投影が使用されるため、境界の等価性は次のように自然に処理されます。`<= allowed`、しきい値での偽陰性がないことを保証します。 

最後のケースは、投影が数値的に崩れる縮退セグメントです。 実装では、エンドポイント距離にフォールバックすることでこれを処理します。これにより、浮動小数点が不安定な場合でも正確さが維持されます。
