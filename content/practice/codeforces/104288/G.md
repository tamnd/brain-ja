 ## 解決策
 ## 問題の理解

 モチーフと呼ばれる小さなパターンのグリッドと、モザイクと呼ばれる大きなグリッドが与えられます。 各セルには色の値が含まれていますが、モチーフ内の一部のセルは空であり、ワイルドカードのように動作します。 

タスクは、すべての空でないモチーフ セルが対応するモザイク セルと正確に一致するように、モチーフを長方形のサブグリッドとして配置できるモザイク内のすべての位置を見つけることです。 空のモチーフセルには制約がありません。 

オカレンスは、モチーフがモザイク内に完全に収まり、制約されたすべてのセルの色が一致するように、モザイク内の左上の位置を選択することによって定義されます。 出力は、行、列の順に辞書順に並べ替えられた、有効な左上のすべての位置のリストです。 

重要な問題はスケールです。 どちらの寸法も 1000 に達する可能性があるため、モザイクには最大 100 万個のセルを含めることができ、モチーフは非常に大きくなる場合もあります。 最大 100 万の候補配置があり、各チェックでモチーフの大部分をスキャンする必要がある可能性があるため、位置ごとの単純なチェックはすぐにコストが高くなりすぎます。 

微妙なエッジケースは、モチーフ内の空のセルから生まれます。 これらは完全に無視する必要があります。 これらを実際の色 (ゼロなど) として扱う不注意なアプローチは、有効な一致を誤って拒否します。 

もう 1 つの問題は、密集したモチーフが許可されていることです。 モチーフのほぼすべてのセルが空ではない場合、空ではないセルのみを反復するアプローチは、位置ごとのスキャンを完全に回避しない限り、最悪の場合でも潜在的に二次関数になる可能性があります。 

## アプローチ

 直接的なアイデアは、モザイク内の左上の可能なすべての位置にモチーフをスライドさせ、すべてのモチーフ セルを比較することです。 これは定義を正確に適用するため正しいですが、そのコストは配置数とモチーフのサイズの積になります。 最悪の場合はこれくらいです$10^6 \times 10^6 = 10^{12}$比較は実現可能な限界をはるかに超えています。 

重要な観察は、これがワイルドカードを使用した 2D パターン マッチングの問題であるということです。 正確な 2D マッチングは通常、畳み込みまたはハッシュを使用して解決され、すべてのアライメントが 1 つずつではなく同時に評価されます。 

条件を再定式化する便利な方法は、すべての配置について、すべてのモチーフの制約が同時に満たされるようにすることです。 ウィンドウ全体での集約を可能にする方法で各色をエンコードできれば、前処理後に各候補位置を一定時間でチェックできます。 

これは標準的な削減につながります。つまり、色のランダム化されたハッシュを使用して、問題をモチーフ マスクとモザイクの間の 2D 相関に変換します。 各色にはランダムな 64 ビット値が割り当てられ、モザイクの各セルはそのカラー ハッシュに置き換えられます。 モチーフは空でない位置でのみ寄与します。 次に、すべてのアライメントにわたる寄与を合計する単一の 2D 畳み込みを計算します。 すべての位置が一致する場合、結果の合計は事前に計算されたモチーフ ハッシュと等しくなります。 そうしないと、少なくとも 1 つの立場が異なる値に寄与するため、偶発的に平等が成立する可能性は圧倒的に低くなります。 

これにより、問題全体が 1 つの 2D 畳み込みと線形スキャンに削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(rq・rp・cp) | お(1) | 遅すぎる |
 | ハッシュ + 2D 畳み込み | O(RCログRC) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 モザイクサイズを次のように表します。$RQ \times CQ$モチーフのサイズは$RP \times CP$。 

1. ランダムな 64 ビット整数を可能な各色の値に割り当てます。 これにより、実際には衝突確率が無視できる程度に、各色に固有のフィンガープリントが与えられます。 
2. 各セルがランダムなカラー ハッシュで置き換えられるモザイクのグリッドを構築します。 これにより、問題が整数比較から算術集計に変換されます。 
3. どのセルがアクティブな制約であるかを示すモチーフのバイナリ マスクを構築します。 各アクティブ セルについて、対応するランダム ハッシュ寄与も計算します。 
4. すべてのアクティブなモチーフ セルのランダム値の合計として、合計モチーフ ハッシュを計算します。 これは、正しい一致が有効な配置で再現される必要があるものを表します。 
5. モチーフマスクを垂直方向と水平方向に反転して、畳み込み位置合わせの準備をします。 これにより、ある位置での畳み込みがモザイク上のモチーフのオーバーレイに正確に対応することが保証されます。 
6. モザイク ハッシュ グリッドと反転モチーフ マスクの間で 1 回の 2D 畳み込みを実行します。 これにより、各候補位置で、すべてのアクティブなモチーフ セルの下のモザイク値の合計が生成されます。 
7. モチーフが適合するモザイク内の左上の位置ごとに、畳み込み結果をモチーフのハッシュと比較します。 それらが一致する場合、その位置を有効な出現として記録します。 

これが機能する理由は、コンボリューションがすべてのモチーフ位置にわたって整列した積を一度に集計するためです。 アクティブなモチーフ セルのみが寄与するため、空のセルは自動的に無視されます。 ランダムなエンコーディングにより、集計された合計の等しい値が、基礎となるすべての色の一致の等しい値と非常に高い確率で等しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import numpy as np

def fft_convolve2d(a, b):
    # convolution via FFT using numpy (fast enough in PyPy / CPython with pypy preferred)
    fa = np.fft.rfft2(a)
    fb = np.fft.rfft2(b)
    return np.fft.irfft2(fa * fb, s=(a.shape[0], a.shape[1]))

def main():
    rp, cp = map(int, input().split())
    
    motif = []
    active = []
    colors = []
    for i in range(rp):
        row = list(map(int, input().split()))
        motif.append(row)
        for j, v in enumerate(row):
            if v != 0:
                active.append((i, j, v))

    rq, cq = map(int, input().split())
    mosaic = [list(map(int, input().split())) for _ in range(rq)]

    rng = np.random.default_rng(123456)

    max_color = 101
    color_hash = rng.integers(1, 2**63 - 1, size=max_color, dtype=np.int64)

    A = np.zeros((rq, cq), dtype=np.float64)
    for i in range(rq):
        for j in range(cq):
            A[i, j] = color_hash[mosaic[i][j]]

    B = np.zeros((rq, cq), dtype=np.float64)
    target = 0.0

    for i, j, v in active:
        B[i, j] = color_hash[v]
        target += color_hash[v]

    # reverse kernel
    B = B[::-1, ::-1]

    conv = fft_convolve2d(A, B)

    res = []
    for i in range(rq - rp + 1):
        for j in range(cq - cp + 1):
            val = conv[i + rp - 1, j + cp - 1]
            if abs(val - target) < 1e-3:
                res.append((i + 1, j + 1))

    print(len(res))
    for r, c in res:
        print(r, c)

if __name__ == "__main__":
    main()
```FFT ライブラリは自然に浮動小数点値で動作するため、実装では両方のグリッドが浮動小数点配列に変換されます。 モザイクは色ごとにランダムなハッシュを使用して一度エンコードされ、モチーフは空ではないセルのみを含む疎なカーネルになります。 

カーネルは、アライメントが 2D 相関の標準定義と一致するように、畳み込みの前に反転されます。 畳み込みを計算した後、有効な左上の各位置は、出力配列内の 1 つのエントリに対応します。 

FFT では浮動小数点誤差が生じるため、最後の比較では小さい許容差までの等価性が使用されます。 正確さは、完全に一致すると非常に安定したターゲット値が生成される一方、不一致はほとんどの場合徐々に消えていくという事実に依存します。 

## 実用的な例

 モチーフにいくつかの拘束されたセルといくつかの空のセルが含まれる小さなモチーフとモザイクを考えてみましょう。 このアルゴリズムは、まずランダムな値を色に割り当て、次にエンコードされたグリッドを構築します。 

| ステップ | 説明 | キー値 |
 | --- | --- | --- |
 | 1 | アクティブセルから計算されたモチーフハッシュ | H |
 | 2 | ランダムな色の重みでエンコードされたモザイク | あ |
 | 3 | すべてのアライメントに対して計算された畳み込み | conv(i,j) |
 | 4 | 各シフトでの比較 | conv(i,j) == H |

 有効な配置では、すべての制約されたモチーフ セルが同一のモザイク カラーと整列するため、すべての寄与が正確に一致し、畳み込みの合計がモチーフ ハッシュと等しくなります。 

無効な配置では、少なくとも 1 つの制約されたセルが異なるため、合計がランダムな量だけ変化し、等価性が崩れます。 

密なモチーフを含む 2 番目の例は、空のセルはカーネルに含まれないため、畳み込み合計に寄与しないため、何の影響も与えないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(RCログRC) | モザイク グリッド上の 2D FFT が優勢 |

 ## 特殊なケース

 重要なエッジケースは、モチーフに空のセルしか含まれていない場合です。 この状況では、モザイク内のすべての位置が有効です。 カーネルが空になり、どこでもゼロ畳み込みが生成され、ターゲット ハッシュもゼロになるため、アルゴリズムはこれを自然に処理します。そのため、すべての配置が一致します。 

もう一つのエッジケースは、モザイクと同じ大きさのモチーフです。 畳み込みによって正確に 1 つのアライメントが生成され、正確性はフルグリッド比較にまで低下します。 出力セルが 1 つだけチェックされるため、アルゴリズムは引き続き機能します。 

ほぼすべてのセルがアクティブである高密度モチーフは、コンボリューション カーネル サイズに重点を置きますが、カーネルは最大でも残るため、複雑さは変わりません。$10^6$これらのエントリは、アライメントごとではなく、FFT 前処理内で 1 回処理されます。
