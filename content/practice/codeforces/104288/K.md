 ## 解決策
 ## 問題の理解

 入力は、葉が 2D 点として表される初期ミームであるルート付きツリーを記述します。 すべての内部ノードは、その子を新しいミームにマージする「投票」を表します。 

葉っぱではミームは点として固定される$(x, y)$。 内部ノードでは、投票の勝者として子を 1 人だけ選択します。 この選択の後、ノードはすべての子ポイントを非常に特殊なルールで結合することによって新しいポイントを生成します。つまり、勝者はプラスに寄与し、他のすべての子はマイナスに寄与します。 具体的には、子どもの場合$i$ポイントがある$p_i = (x_i, y_i)$、そして勝者を選びます$w$の場合、結果の点は次のようになります。$$\sum_{i=1}^k w_i p_i,\quad w_i =
\begin{cases}
1 & i = w \\
-1 & i \ne w
\end{cases}$$この変換はすべての内部ノードで発生し、結果として得られるポイントは、ルートが最終的なミームを生成するまで上方に渡されます。 目標は、すべての内部ノードで勝者を選択して、最終点の二乗ユークリッド ノルムを最大化することです。$x^2 + y^2$根元にある。 

制約は 2 つの点で重要です。 まず、最大です。$10^4$したがって、ツリー全体で選択肢を指数関数的に列挙することは直ちに不可能になります。 第 2 に、各ノードには最大 100 個の子があるため、ローカル分岐は大きくなりますが、ツリーの高さは最大 10 です。これは、深さではなく幾何学的組み合わせによって複雑さが増大するボトムアップ動的プログラミング構造を強く示唆しています。 

単純なアプローチでは、考えられるすべての勝者の割り当てをシミュレートしようとします。 サブツリーの変動を無視しても、各ノードはすでに$k$選択肢があり、その構造はレベル間で乗算的に複合します。 高さ10ともなると天文学的な大きさになります。 

さらに微妙な問題は、ノードで勝者を固定したとしても、結果のポイントは勝者だけでなくすべての子に同時に依存することです。 この結合は、組み合わせがどのように相互作用するかを注意深く追跡しない限り、純粋に加算的な方法でサブツリーを独立して扱うことができないことを意味します。 

いくつかの特殊なケースは、素朴な思考のもろさを示しています。 すべての葉が同一である場合、すべての点は次のようになります。$(1,1)$の場合、すべてのサブツリーは依然として勝者の選択に応じて複数の可能なベクトルを生成し、貪欲な「常に最良の子を選択する」戦略は失敗します。敗者の減算が勝者からの利益を支配する可能性があるためです。 もう 1 つの失敗ケースは、1 つの子が大きくてポジティブである一方で、多数の小さなネガティブが存在する星型ノードです。 局所的に最良の葉を選択することは、残りからの減算効果を減らすために別の勝者を戦略的に選択することよりも悪い可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、すべてのノードについて、サブツリー内で勝者を割り当てることによって取得できるすべての可能な結果ベクトルを計算することです。 各内部ノードについて、勝者のすべての選択肢を試し、子からのすべての可能な構成を再帰的に結合します。 ノードに$k$子と各サブツリーは生成できます$S$状態では、マージ ステップはすでに次のように動作しています。$S^k$独立したサブツリー選択による組み合わせ。 深さが最大 ​​10 になると、中程度の分岐であってもすぐに実行できなくなります。 

重要な観察は、ノードで実行されるすべての演算が子ベクトル内で線形であるということです。 各子サブツリーから 1 つのベクトルの選択を固定すると、結果のベクトルはそれらのベクトルのアフィン結合になります。 したがって、ノードで達成可能なすべてのベクトルのセットは、子セットのミンコフスキー和と線形変換から構築されます。 2 次元では、凸集合のミンコフスキー和は凸性を維持し、さらに重要なことに、点を列挙する代わりに凸包によって解空間全体を表現できるようになります。 

これにより、問題は、指数関数的に多くの構成を追跡することから、ノードごとの幾何学的オブジェクト (そのサブツリー内のすべての達成可能なベクトルの凸包) の維持に軽減されます。 各内部ノードは、ミンコフスキー和と、選択された勝者に応じたアフィン変換を使用して子ハルを結合します。 しかないので、$k$勝者に選択肢がある場合、各選択肢の候補ハルを構築し、結合を取得します。 

最後のステップでは、答えはセット全体ではなく、次の最大値のみになります。$x^2 + y^2$最終的な包の上に、凸包の頂点に位置する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての構成に対するブルート フォース | 指数 | 指数 | 遅すぎる |
 | 凸包 + ミンコフスキー DP |$O(n \cdot m)$償却済み |$O(n \cdot m)$| 承認済み |

 ここ$m$維持される船体の合計サイズです。木の高さに制限があるため、管理可能なサイズのままです。 

## アルゴリズムのチュートリアル

 ツリーをボトムアップで処理し、各ノードでそのノードが生成できるすべてのベクトルの凸包を維持します。 

1. ノードがリーフの場合、そのハルには単一の点が含まれます。$(x, y)$。 仕方がないので、これが民進党の基本です。 
2. 内部ノードの場合、まず、すべての子の凸包をすでに計算していると仮定します。 各ハルは、そのサブツリーの考えられるすべての出力を表します。 
3. 一人ひとりの子どもたちに配慮します$w$潜在的な勝者として。 この固定の選択については、投票ルールによって暗示される変換を適用して結果セットを構築します。 代数的に、ノードの出力は次のようになります。$$p_w - \sum_{i \ne w} p_i$$それぞれどこで$p_i$子ハルから独立して選択されます$S_i$。 
4. 固定勝者のセットを構築する$w$、から始めます$S_w$。 他のすべての子供たちに対して$i \ne w$、否定されたハルを追加します$-S_i$。 これは凸集合のミンコフスキー和であるため、結果は凸のままであり、段階的に構築できます。 
5. 可能性のある各勝者に対してこのハルを計算した後$w$、これらすべての包の結合を取得し、その結合の凸包を計算します。 これが現在のノードに保存されているハルになります。 
6. すべてのノードを処理した後、ハル内のすべての頂点を反復して評価することにより、ルートでの答えを計算します。$x^2 + y^2$、最大値を取ります。 

これが機能する理由は、すべてのサブツリーが達成可能なベクトルの凸セットを表し、内部ノードでのすべての演算が線形変換とミンコフスキー和の合成であるためです。 どちらの操作でも凸性が維持されます。$\mathbb{R}^2$したがって、船体の境界だけを維持しても最適な解決策が失われることはありません。 最終的な目的は平面上の凸関数であるため、凸多角形上の最大値は常に頂点で達成されるため、ハルの頂点のみを保存すれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def minkowski_sum(A, B):
    # naive O(nm) merge of convex hulls (A, B are convex and ordered)
    i = j = 0
    n, m = len(A), len(B)
    res = []
    for a in A:
        for b in B:
            res.append((a[0] + b[0], a[1] + b[1]))
    return convex_hull(res)

def negate_hull(H):
    return [(-x, -y) for x, y in H]

def add_hulls(base, hulls):
    res = base[:]
    for h in hulls:
        tmp = []
        for p in res:
            for q in h:
                tmp.append((p[0] + q[0], p[1] + q[1]))
        res = convex_hull(tmp)
    return res

def solve():
    n = int(input())
    children = [[] for _ in range(n)]
    leaf = [False] * n
    value = [None] * n

    for i in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        if k == 0:
            leaf[i] = True
            value[i] = (arr[1], arr[2])
        else:
            children[i] = [x - 1 for x in arr[1:]]

    sys.setrecursionlimit(10**7)

    from functools import lru_cache

    def dfs(u):
        if leaf[u]:
            return [value[u]]

        child_hulls = [dfs(v) for v in children[u]]
        best = []

        k = len(child_hulls)
        for w in range(k):
            base = child_hulls[w]
            others = child_hulls[:w] + child_hulls[w+1:]

            cur = base[:]
            for h in others:
                nh = negate_hull(h)
                tmp = []
                for p in cur:
                    for q in nh:
                        tmp.append((p[0] + q[0], p[1] + q[1]))
                cur = convex_hull(tmp)

            best = convex_hull(best + cur)

        return best

    hull = dfs(0)

    ans = 0
    for x, y in hull:
        ans = max(ans, x*x + y*y)
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、DFS を使用して各サブツリーの凸包を構築します。 葉は 1 つのポイントを返します。 内部ノードは勝者の選択を列挙し、ハルを否定してミンコフスキー スタイルのマージを繰り返し実行することで、他のすべての子を結合します。 各マージ ステップの後には、表現をコンパクトに保つ​​ために凸包の再計算が行われます。 最後にルート ハルをスキャンして、最大二乗ノルムを計算します。 

最もデリケートな部分は、凸包のメンテナンスを繰り返すことです。 それがなければ、ミンコフスキー和は爆発的に大きくなってしまうでしょう。 これにより、各サブツリーはその極点のみで表現されたままになります。 

## 実用的な例

 根元に 2 枚の葉がある小さな木を考えてみましょう。$(1, 0)$そして$(0, 1)$。 

| ステップ | ノード | 勝者 | 選ばれた子のベクトル | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 葉A | - | (1,0) | {(1,0)} |
 | 2 | 葉B | - | (0,1) | {(0,1)} |
 | 3 | ルート | あ | Ａ～Ｂ | (1,0) - (0,1) = (1,-1) |
 | 4 | ルート | B | B - A | (0,1) - (1,0) = (-1,1) |

 根殻には以下が含まれます$(1,-1)$そして$(-1,1)$、最大二乗ノルムは 2 です。 

ここで、1 つのサブツリーにすでに複数の達成可能なベクトルがある、もう少し大きなケースを考えてみましょう。 

| ノード | サブツリーの選択 | 船体 |
 | --- | --- | --- |
 | 葉A | 修正済み | (2,0) |
 | 葉B | 修正済み | (0,2) |
 | 葉C | 修正済み | (1,1) |
 | ルート (勝者を選択) | A/B/C | 1 つは正、もう 1 つは負の組み合わせ |

 A が勝者の場合、結果は次のようになります。$A - B - C = (2,0) - (0,2) - (1,1) = (1,-3)$。 他の勝者についても同様の計算を行うと、複数の極点が生成され、凸包は外側の境界のみを保持します。 

これは、構造がどのようにして対称的な極端な構成を自然に生成するのか、そしてなぜ中間表現が単一の最良のベクトルではなく完全な幾何学的境界を保持しなければならないのかを示しています。

 ## 特殊なケース

 単一のリーフ入力は、アルゴリズムが何も結合しようとせず、その点の二乗ノルムを直接返すことをテストします。 船体は単一点のままであり、最終的な答えはすぐに得られます。 

すべて同じ点に等しい多くの子を持つノードは、繰り返される否定とミンコフスキー和が対称性を維持するかどうかをテストします。 すべてのサブツリーが同一であるため、すべての勝者の選択は幾何学的に同等の結果を生成し、凸包は原点の周りの対称多角形に折りたたまれ、実装順序による偏りがないことが保証されます。 

ノードの深いチェーンは、繰り返されたアフィン変換が正しく蓄積されるかどうかをテストします。 各レベルでは、サブツリーの寄与の加算と減算が交互に行われ、ハル表現により、再計算の損失なく中間の選択がルートに至るまで有効なままであることが保証されます。
