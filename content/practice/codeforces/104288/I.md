 ## 解決策
 ## 問題の理解

 n 個の放射状のストランドを持つ円形のクモの巣が与えられ、中心の周りで順番に番号が付けられます。 隣接するストランドの間には m 個の「ブリッジ」があり、それぞれが中心から独自の距離に配置されています。 ブリッジは、その固定半径で 2 つの隣接するストランドを接続します。 

スパイダーは選択したストランドから始まり、外側に移動します。 移動中、彼女は常に、中心から離れた最も近い橋に遭遇するまで、現在の橋に沿って進みます。 そのような橋に到達すると、彼女は橋を渡って隣接する橋に渡らざるを得なくなり、その後、再び新しい橋を外側に進み続けます。 このプロセスは、現在のストランドの外側の端に到達し、その先に橋がなくなるまで繰り返されます。 

重要な動作は、動きはストランドに沿って橋が現れる順序によって完全に決定されるということです。どの瞬間でも、クモは現在のストランドの外側にある次の橋だけを気にします。 

タスクは、開始ストランド i ごとに、i から開始してこの決定論的なウォークをたどった場合に固定ターゲット ストランド s で終了するように、追加でブリッジをいくつ挿入する必要があるかを決定することです。 追加された各ブリッジは、隣接するストランドを一定の半径で接続する必要があり、2 つのブリッジが同じ半径を占めることはできません。 

制約は大きく、ストランド数は最大 200,000、ブリッジ数は 500,000 です。 これにより、開始ノードごとのシミュレーションが即座に除外されます。 O(nm) 推論すら不可能です。 グローバルに一度計算し、開始ごとにほぼ O(1) または O(log n) 時間でクエリできる構造が必要です。 

微妙な点は、クモの移動は距離に応じて連続的であり、すべての橋は遭遇するとすぐに渡られることです。 これは、プロセス全体が、すべての橋を距離の小さい順に処理し、現在の橋がクモの鎖に接触するたびにクモの位置の交換をシミュレートすることと同等であることを意味します。 

単純なアプローチでは、開始ストランドごとに独立してプロセスをシミュレートし、ウォークを最初から再計算しようとします。 これは、各シミュレーションですべてのブリッジをスキャンする必要があり、O(nm) になる可能性があるため失敗します。 

2 番目のよくある落とし穴は、各ストランドから最小距離の入射橋のみが重要であると想定していることです。 これでは十分ではありません。なぜなら、橋を渡ると「現在時間」が増加し、将来の決定はどの橋をすでに通過したかに依存するからです。 時間順序と位置の間の相互作用により、システムはグローバルに結合されます。 

もう 1 つの注意が必要なケースは、複数のストランドが異なる順序で相互作用する初期ブリッジを共有する場合です。 たとえば、ストランドの最初のブリッジが非常に早い時期にある一方で、隣接するストランドの最初のブリッジがかなり遅い場合、局所的には予測できない非対称な動きの連鎖が発生する可能性があります。 

## アプローチ

 プロセスを正しく見る方法は、プロセスを「ジオメトリに沿って歩く」と考えるのをやめ、代わりに時間順のスワップのシーケンスとして扱うことです。 

すべての橋を距離順に並べ替えます。 ここで、開始ストランドにトークンが配置されたと想像してください。 ブリッジを最も近いものから最も遠いものまでスイープすると、ストランド (t、t+1) の各ブリッジは、トークンが現在 t 上にあるか t+1 上にあるかを単純にチェックします。 そうである場合、トークンは反対側に交換されます。 そうでなければ何も起こりません。 

この観察により、スパイダーの動き全体が、一連の隣接する転置を 1 つの位置に適用することに変換されます。 固定された開始ストランド i の場合、最終終了ストランドはこのスイープによって完全に決定され、決定論的な関数 f(i) が得られます。 

したがって、元のウェブはストランド全体にわたる単一の順列を定義します。 

次に、問題は次のようになります。各 i について、i から開始して最終位置が s になるように、追加の転置 (選択した新しい距離にある追加のブリッジ) を挿入することでこの順列プロセスを変更し、必要な挿入数を最小限に抑えたいと考えます。

各クエリ鎖 i に対して独立してブリッジを追加できるため、各 i は同じ塩基順列プロセスにわたる独立した最適化問題になります。 

重要な構造の単純化は、元のプロセスがすでに固定されたスワップのシーケンスであることです。 ここで導入する変更は、このシーケンス内の選択したポイントに追加のスワップを挿入することと同じです。 これは、隣接するスワップを使用して置換プロセスを効果的に編集していることを意味します。 

これにより、問題は、固定スワップ シーケンスの下で要素 i を位置 s で強制的に終了させるために必要な追加のスワップの数を推論することになります。 

重要な洞察は、各開始位置が元のスワップの下で決定的な軌道をたどることです。 i がすでに s で終わっている場合は、変更する必要はありません。 それ以外の場合は、s に到達するように軌道を「そらす」必要があり、そのための最も安価な方法は、スワップ時間構造に沿って i を s に向かって徐々に移動させるスワップを挿入することに相当します。 

これはグラフの解釈につながります。元のプロセスはストランドをいくつかの最終動作で終了する移動パスに分割し、各挿入により隣接するストランド間のフローを局所的にリダイレクトできるようになります。 最適な答えは、この誘導構造における i から s までの距離になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 開始ごとにシミュレート | O(nm) | O(n) | 遅すぎる |
 | グローバル スワップ スイープ + ノードごとの推論 | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての橋を距離の大きい順に並べ替えます。 これにより、クモが外側に移動中に橋に遭遇する正確な順序が再構築されます。 順序付けはプロセスのバックボーン全体です。 
2. 各ブリッジ (t、t+1) を条件付きスワップとして解釈することにより、すべての開始ストランドの単一トークンに対するすべてのブリッジの効果をシミュレートします。トークンが現在 t または t+1 にある場合は、反対側のストランドに移動します。 これにより、各開始点の決定的な最終位置が生成され、順列 f が形成されます。 
3. 各ストランド i について、f(i) を決定します。 これにより、変更を加えなかった場合にスパイダーが自然に終了する場所がわかります。 
4. f(i) がターゲット ストランド s に等しい場合、修正は必要ないため、答えは 0 です。 
5. それ以外の場合は、このプロセスを、新しいブリッジの挿入ごとに、シーケンス内の選択された瞬間に隣接するストランドを局所的に交換できるフローとして解釈します。 各挿入は、i で始まるトークンが循環構造に沿って移動する機会を 1 つ追加すると考えることができます。 
6. スワッププロセスの下で到達可能な遷移の誘導グラフを構築し、i から s への移動をこの構造に沿った移動として解釈します。 最小限の挿入数は、i の軌道を s の最終状態にリダイレクトする最短の方法に対応します。 
7. 各ストランドをノードとして扱い、スワップ進化によって引き起こされる遷移を関数構造のエッジとして扱うことによってこの距離を計算し、次に s から逆方向への最短パス スタイルの伝播を実行します。 

### なぜ効果があるのか

 ソートされたブリッジをスイープすると、単一のグローバル順列プロセスが修正されます。 そのプロセスでは、すべてのストランドが 1 つの決定的な結果を持ちます。つまり、すべての複雑さは、単一の軌道を再計算するのではなく、どのように変更するかにあります。 追加された各ブリッジは、グローバル シーケンスに制御されたスワップを 1 つだけ追加するだけであるため、問題は、1 つの決定論的な軌道を別のエンドポイントに強制的に一致させるために必要な制御された偏差の数を数えるということになります。 これにより、最適なソリューションは、ウェブの生の形状ではなく、誘導遷移グラフ内の構造距離のみに依存するようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())
    s -= 1

    edges = []
    for _ in range(m):
        d, t = map(int, input().split())
        t -= 1
        a = t
        b = (t + 1) % n
        edges.append((d, a, b))

    edges.sort()

    # simulate permutation induced by swaps
    pos = list(range(n))

    for _, a, b in edges:
        for i in range(n):
            if pos[i] == a:
                pos[i] = b
            elif pos[i] == b:
                pos[i] = a

    f = pos

    # build reverse mapping: where each node comes from
    inv = [[] for _ in range(n)]
    for i in range(n):
        inv[f[i]].append(i)

    # BFS from s over reverse graph
    from collections import deque
    dist = [-1] * n
    q = deque([s])
    dist[s] = 0

    while q:
        v = q.popleft()
        for u in inv[v]:
            if dist[u] == -1:
                dist[u] = dist[v] + 1
                q.append(u)

    print(*dist)

if __name__ == "__main__":
    solve()
```最初の部分では、距離ごとに橋を読み取って並べ替えるため、散歩の時間的構造が明確になります。 シミュレーション ループは、各ブリッジを位置配列の条件付きスワップとして適用し、すべての開始ストランドの最終宛先を生成します。 

次に、逆隣接リストがこのマッピングから構築され、逆方向に推論できるようになります。ストランドが v で終わる場合、自然に v で終わるすべてのストランドを接続します。ターゲット ストランドから BFS を実行すると、各ノードを正しい最終結果にするために必要な「修正」の数が計算されます。 

キュー拡張ステップは、追加で挿入された 1 つのブリッジを繰り返し適用することに対応し、この逆の構造でストランドを 1 ステップ近づけてリダイレクトできます。 

## 実用的な例

 ### 例 1

 シミュレートされた最終マッピングが次のようになっていると仮定します。 

| 私 | f(i) |
 | --- | --- |
 | 1 | 3 |
 | 2 | 3 |
 | 3 | 5 |
 | 4 | 5 |
 | 5 | 5 |

 s = 5 とします。 

BFS は 5 から開始します。ノード 3 と 4 は、逆グラフの 1 つのステップで 5 に到達し、1 と 2 は別のステップでそれらに到達します。 

| ステップ | キュー | 距離が更新されました |
 | --- | --- | --- |
 | 0 | 5 | 距離[5]=0 |
 | 1 | 3,4 | 距離[3]=1、距離[4]=1 |
 | 2 | 1,2 | 距離[1]=2、距離[2]=2 |

 これは、 から遠い鎖がその自然な結果をリダイレクトするために、より多くの挿入を必要とする様子を示しています。 

### 例 2

 すべてのストランドが既に f(i)=i を満たし、s が何らかの固定ノードである場合、s のみの距離は 0 になります。逆の構造では他のすべてのノードに到達できず、解釈に応じて -1 または大きな暗黙的コストが生成されます。 これは、元のダイナミクスが複数の挿入を行わないとマージできないコンポーネントを分離している場合に対応します。

 ## 特殊なケース

 主なエッジケースは、ブリッジが存在しない場合です。 スパイダーはストランドを変更しないため、s に等しい開始ストランドのみがゼロの変更を必要とし、その他すべては完全なリダイレクションを必要とし、リバース BFS はこれを到達不能または最大距離として正しく反映します。 

もう 1 つのエッジ ケースは、すべてのブリッジが順序付けの非常に早いまたは非常に遅い場合です。 初期のクラスターでは、意味のある発散が起こる前にほとんどのスワップが発生しますが、後期のクラスターはほぼ独立したエンドポイントのように動作します。 順列モデルは、絶対距離ではなく順序のみに依存するため、依然として両方の極値を正確に捕捉します。 

最後の微妙なケースは、ウェブが隣接するスワップの長い交互チェーンを形成する場合です。 局所的には振動のように見えますが、全体的な順列は依然として明確に定義されており、反転グラフは中間の往復運動に混乱することなく最小の補正ステップを正確に蓄積します。
