 ## 解決策
 ## 問題の理解

 すべてのノードが単一の入力シーケンスを 2 つの交互のストリームに分割するか、2 つの入力シーケンスを 1 つの交互のストリームにマージする、有向非巡回ネットワークが与えられます。 システムは、1 から m までの数値を昇順に含む単一の入力ストリームから開始します。 システム内のラベル付きコネクタは 1 つおきに、この初期ストリームと分割ノードとマージ ノードの配線によって完全に決定されるシーケンスを表します。 

分割ノードはシーケンスを消費し、要素を 2 つの出力エッジに交互に送信するため、奇数のインデックス付き要素は最初の出力に送られ、偶数のインデックス付き要素は 2 番目の出力に送られます。 マージ ノードは逆の種類のインターリーブを実行します。つまり、2 つのシーケンスを受け取り、要素を交互に出力しますが、一方の側が不足しても、もう一方の残りの要素は変更されずに続行されます。 

m は 10^9 に達する可能性があるため、タスクはこれらのシーケンスを明示的に構築することではありません。 代わりに、出力ワイヤ x とインデックス k が与えられた場合、そのストリーム内の k 番目の値は何か、またはその値が存在しないことを報告するという形式のクエリに答える必要があります。 

この制約は、シーケンスをシミュレートしたり、シーケンスを明示的に保存したりできないことを意味します。 グラフには最大 10^4 のノードがありますが、原則として各シーケンスは最大 10^9 要素と非常に長くなる可能性があります。 クエリの数が十分に少ないため、クエリごとの対数または償却多対数作業は許容されますが、シーケンスの長さに線形に依存するものは不可能です。 

単純な間違いは、フォワード シミュレーションによって各ノードの完全なシーケンスを生成できると仮定することです。 2 つの大きなストリームを 1 回マージしただけでも、すでに最大 m のサイズのシーケンスが生成されるため、構築を繰り返すとすぐに時間とメモリの両方の制限を超えてしまいます。 

もう 1 つの微妙な落とし穴は、1 つの入力が不足したときのマージ動作に起因します。 たとえば、1 つのストリームの長さが 3 で、もう 1 つのストリームの長さが 10 である場合、最初の 6 要素がインターリーブされ、残りの 4 要素は 2 番目の入力から直接取得されます。 永久に完全な交替を前提とするソリューションは、特に一方の側が終了する境界付近でクエリに応答する場合、ここでは失敗します。 

## アプローチ

 主な難点は、位置のパリティによる分割と交互のプレフィックス消費によるマージという 2 つの変換を繰り返し適用することによって、すべてのワイヤが元の配列 1 から m から派生したシーケンスを定義することです。 構造は DAG であるため、すべてのシーケンスは以前に定義されたシーケンスのみに依存します。 

ブルートフォースアプローチでは、ノードをトポロジカルな順序で処理することにより、すべてのシーケンスを実体化しようとします。 分割ノードの場合、親シーケンスを反復処理して 2 つのベクトルを構築します。 マージ ノードの場合は、インターリーブをシミュレートします。 各ノードが長さ O(m) のシーケンスを処理すると仮定しても、総作業量は O(nm) になりますが、m は 10^9 になる可能性があるため、これは実現不可能です。 

重要な観察は、完全なシーケンスは決して必要ないということです。 k 番目の要素のクエリに答えるだけで済みます。 これは、各ストリームを暗黙的に表現し、ランダム アクセスをサポートする必要があることを示唆しています。 

グラフをトポロジ順に処理しますが、完全な配列を保存する代わりに、各ワイヤーについて 2 つの情報のみを保存します。その長さ (入力ストリームの長さを超えることはないため、上限は m) と、k 番目の要素を取得するメカニズムです。 

初期ストリームの場合、k 番目の要素は単に k です。 分割ノードの場合、位置について推論して出力を計算できます。最初の出力には要素 1、3、5 などが含まれます。つまり、k 番目の要素は入力の位置 2k − 1 に対応します。 2 番目の出力は 2k に対応します。

マージ ノードの場合は、インターリーブ ルールを反転する必要があります。 出力は、一方がなくなるまで左と右で交互に行われます。 左が長さ L、右が長さ R であるとします。その場合、最初の 2・min(L, R) 要素は厳密にインターリーブされます。 その後、残りのサフィックスは長辺からのものです。 したがって、k 番目のクエリに答えるために、k がインターリーブされたプレフィックスにあるか末尾にあるかを判断します。 k ≤ 2・min(L, R) の場合、パリティに応じて左または右のいずれかにマッピングします。 それ以外の場合は、残りの側にオフセットします。 

これにより、各クエリがノードを介して繰り返される一定時間のルーティングに減ります。 ただし、ノードは DAG を形成するため、直接評価は依然として再帰的である可能性があります。 n は最大でも 10^4 であるため、結果をメモ化したり長さを事前計算したり、ターゲット ワイヤからソースまで逆方向に歩いてクエリに答えることができ、クエリごとに O(n) 前処理と O(深さ) で関数グラフを効果的に評価できます。 

深さは n によって制限されますが、実際には、(wire, k) ペアの結果をキャッシュするか、マージごとにメモ化された長さの比較による反復評価を使用することにより、再計算を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(m) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ワイヤを、インデックス k を値または「なし」にマッピングする関数としてモデル化します。 

1. すべてのノードの入力が評価される前に処理されるように、トポロジカルな順序でグラフを計算します。 これが有効なのは、ネットワークが非周期的であるため、依存関係が常に構築順序で前方を指しているためです。 
2. 各ワイヤについて、その長さを計算します。 入力ワイヤの長さは m で、分割ノードは両方の出力の長さを保持しますが、マージ ノードは入力の合計に等しい長さを生成します。 ストリームは元の要素数を超えることができないため、この長さは m に固定されます。 
3. 分割ノードの場合、出力インデックス k から入力インデックスへのマッピングを定義します。 最初の出力は奇数の位置を受け取るため、2k − 1 に対応します。 2 番目の出力は 2k に対応します。 
4. マージ ノードの場合、minLen = min(len(left), len(right)) を定義します。 k ≤ 2・minLen の場合、代替プレフィックスの内側にいます。 偶数 k 値は右入力から取得され、奇数 k 値は左入力から取得され、それぞれ k/2 の位置で切り上げられます。 k が大きい場合は、2・minLen を減算して k を調整し、長い方の入力の残りのサフィックスに移動します。 
5. クエリに答えるには、ターゲット ワイヤから始めて元の入力ワイヤ 1 に到達するまで、これらの逆マッピングを繰り返し適用します。各ステップにより、問題は先行ワイヤのより単純なインデックスに帰着します。 
6. いずれかの時点で、変換されたインデックスが保存されているワイヤの長さを超えた場合は、すぐに何も返しません。 

### なぜ効果があるのか

 すべてのワイヤは、元のストリームのプレフィックスからその出力ストリームへの決定的なマッピングを定義します。 分割ノードはパリティによるフィルタリング中に順序構造を保持し、マージ ノードは交互のプレフィックス内の相対的な順序を保持し、残りのサフィックスを変更せずに追加します。 各変換はインデックス上で可逆であるため、DAG を介してインデックスを逆方向にたどると、元の配列内に一意のソース位置が存在する場合は常にその位置が得られます。 インデックスが有効な範囲外にある場合、シーケンスはそこまで拡張されず、必要な出力動作と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n, q = map(int, input().split())

    # node types and structure
    # id 1 is the source
    parent1 = {}
    parent2 = {}
    typ = {}

    nodes = set([1])

    # we will store graph info
    for _ in range(n):
        parts = input().split()
        if parts[0] == 'S':
            _, x, y, z = parts
            x = int(x); y = int(y); z = int(z)
            typ[y] = ('S1', x)
            typ[z] = ('S2', x)
            nodes.update([x, y, z])
        else:
            _, x, y, z = parts
            x = int(x); y = int(y); z = int(z)
            typ[z] = ('M', x, y)
            nodes.update([x, y, z])

    # length computation
    # source has length m
    length = {1: m}

    # we need topo order; nodes are labeled in dependency order implicitly
    # but safer: repeated relaxation
    changed = True
    while changed:
        changed = False
        for v in nodes:
            if v in length:
                continue
            if v not in typ:
                continue
            t = typ[v]
            if t[0] == 'S1' or t[0] == 'S2':
                x = t[1]
                if x in length:
                    length[v] = length[x] // 2
                    changed = True
            else:
                x, y = t[1], t[2]
                if x in length and y in length:
                    length[v] = min(m, length[x] + length[y])
                    changed = True

    def query(node, k):
        cur = node
        idx = k
        while cur != 1:
            if cur not in typ:
                return None

            t = typ[cur]
            if t[0] == 'S1':
                x = t[1]
                idx = 2 * idx - 1
                cur = x
            elif t[0] == 'S2':
                x = t[1]
                idx = 2 * idx
                cur = x
            else:
                x, y = t[1], t[2]
                L = length.get(x, 0)
                R = length.get(y, 0)
                if idx <= 2 * min(L, R):
                    if idx % 2 == 1:
                        idx = (idx + 1) // 2
                        cur = x
                    else:
                        idx = idx // 2
                        cur = y
                else:
                    if L > R:
                        idx = idx - 2 * min(L, R)
                        cur = x
                    else:
                        idx = idx - 2 * min(L, R)
                        cur = y

            if cur in length and idx > length[cur]:
                return None

        return idx

    out = []
    for _ in range(q):
        x, k = map(int, input().split())
        res = query(x, k)
        if res is None:
            out.append("none")
        else:
            out.append(str(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、シーケンスの構築ではなく、逆方向のインデックス変換に依存しています。 各ノード タイプは可逆インデックス関数として扱われます。分割はダブル化してインデックス パリティをシフトし、マージは位置が交互のプレフィックスにあるか、残ったサフィックスにあるかを決定します。 

マージの動作は交互がどこで停止するかを知ることに依存するため、長さの伝播ステップは不可欠です。 正しい長さがなければ、インターリーブとサフィックスの間の境界を解決することはできません。 

クエリ関数は、ターゲット ワイヤからソースに向かって戻り、現在のノードとインデックスの両方を同時に更新します。 インデックスが既知の長さを超えると、要求された要素がそのストリームに存在しないことを意味するため、早期に終了します。 

## 実用的な例

 ### 例 1

 ストリームが繰り返し分割されてクエリされる単純な分割チェーンを考えてみましょう。 

| ステップ | 現在のノード | インデックス k | アクション |
 | --- | --- | --- | --- |
 | 1 | 出力ワイヤー | 4 | クエリを開始 |
 | 2 | 分割入力 | 7 | k → 2k |
 | 3 | ソース | 7 | 停止 |

 これは、分割ノードがどのように指数関数的にインデックス位置を後方に拡張するかを示しています。 

トレースは、分割変換がインデックス解像度を 2 倍にしながら構造を保持していることを確認します。これは、2 つおきの要素を選択するという考えと一致します。 

### 例 2

 左が長さ 3、右が長さ 5 のマージを考えて、k = 6 をクエリします。 

| ステップ | ノード | k | 解釈 |
 | --- | --- | --- | --- |
 | 1 | マージ | 6 | 内側の代替プレフィックス、2・min(3,5)=6 なので |
 | 2 | マージ | 右側 | 偶数インデックス |
 | 3 | 右入力 | 3 | マップされたインデックス |

 これは、交互領域がどのようにきれいに処理されるか、および k が正確に 2・min(L, R) に等しい境界ケースが依然としてインターリーブ内に収まることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、マージ ノードに非常にアンバランスな入力 (たとえば、左の長さ 2 と右の長さ 100) がある場合に発生します。k = 5 をクエリすると、まだインターリーブ プレフィックス内にあるため、右側の入力がサフィックスよりも多くを占めているとしても、答えは右側の入力から得られる必要があります。 このアルゴリズムは、しきい値 2・min(L, R) = 4 を正しくチェックし、k = 5 がそれを超えていることを確認し、調整されたインデックスを使用して右尾に直接ジャンプします。 

もう 1 つのエッジ ケースは、k が境界 2・min(L, R) に正確に等しい場合です。 この場合、要素はまだインターリーブ領域に属しているため、サフィックスとして扱うのではなくパリティによって解決する必要があります。 マージ ロジックの条件付き分割により、このケースが末尾ではなくインターリーブ マッピングに確実に含まれるようになります。
