 ## 問題の理解

 いくつかのマーキング カテゴリに分割されたデッキが与えられます。 各カテゴリには既知の数の個別のカードが含まれており、デッキの合計サイズは非常に大きくなる可能性があります。 ランダムなグループ$k$カードが選択されており、そのうちの 1 つが$k$カードは裏向きに隠されます。 アシスタントが残りを表示します$k-1$カードを選択した順序で並べると、マジシャンは隠されたカードを特定する必要があります。 

面白いのは、すべてのカードの裏面にも次のいずれかが記載されていることです。$m$可能なマークの種類があり、マジシャンは隠されたカードのマークを見ることができます。 このマークは正確な正体を明らかにするものではありませんが、隠されたカードがデッキの既知のサブセットに属するように制限されます。 

アシスタントとマジシャンは、トリックが始まる前に最適な戦略を調整することができます。 アシスタントは、どのカードを非表示にするか、および表示されるカードを並べ替える方法を選択できます。$k-1$情報を効果的にエンコードするカード。 目標は、マジシャンが目に見える配置と観察されたマークから隠されたカードを一意に決定できる確率を最大化することです。 

この制約により、次のサブセットに対してブルート フォースが実行されることが明らかになります。$k$カードは無理です。 パラメータ$k \le 10$これは、ソリューションが最大でもサイズの構造化構成を列挙することに依存していることを強く示唆しています。$k$、デッキ全体のサイズへの依存を回避しながら$n$まで可能です。$10^9$。 

素朴な推論による微妙な失敗例は、マークだけでカードがほぼ識別できると仮定することです。 たとえば、すべてのカードが同じマークを共有している場合、マジシャンは隠されたカードが次のいずれかであることのみを学びます。$n - (k-1)$可能性があり、順序付けは残りの不確実性のほとんどすべてをエンコードする必要があります。 発注能力とマークベースの制限の間の相互作用を無視したソリューションは、成功確率を過大評価することになります。

## アプローチ

 強引なアイデアは、すべての可能な方法でプロセスをシミュレートして選択することです。$k$カードを選択し、隠しカードのすべての選択肢と残りのカードのすべての順列を試します。$k-1$カード。 各構成について、マジシャンが隠されたカードを一意に推測できるかどうかを判断しようとします。 これはすぐに実行不可能になります。$k$- あるサイズのデッキのサブセット$n$は$\binom{n}{k}$、これは、$k=10$いつ$n$までです$10^9$。 

重要な観察は、重要な唯一の構造は、正確にどのカードが選択されるかではなく、各マーク タイプに何枚属するかであるということです。 以来$m \le 10$そして$k \le 10$、選択されたセットの関連するすべての構成は、サイズの小さな整数の構成によって説明できます。$k$。 これにより、状態空間が「デッキのすべてのサブセット」から「サイズのすべてのマルチセット」に縮小されます。$k$多くても10種類以上」

 視点をタイプカウント構成に切り替えると、アシスタントの仕事は情報エンコードの問題になります。 考えられるあらゆるシナリオで、次のタイプのカードが$t$が隠されており、残りは$k-1$目に見えるカードは順列を形成し、その順列によって提供されるもの$(k-1)!$考えられる信号。 隠しカードのマークにより、どのタイプに属するかが制限されますが、同じタイプ内でも、デッキ内に選択できる潜在的なカードが多数存在します。 

これにより、容量対需要の構造が形成されます。 各隠しカード シナリオでは、特定の数の区別できない可能性が生成され、これらの可能性には個別の置換エンコーディングを割り当てる必要があります。 タイプの合計需要が$(k-1)!$利用可能な信号があるため、衝突は避けられず、いくつかのあいまいさが残ります。

 ## アルゴリズムのチュートリアル

 問題を 2 つの層に圧縮します。最初に、各マーク タイプが寄与する区別可能な隠しカード シチュエーションの数を計算し、次に、カバーされるシチュエーションの数を最大化するために順列からエンコード容量を割り当てます。 

1. 型を固定する$i$そして、隠されたカードがこのタイプに属すると想像してください。 すべての有効な結果は、隠されたカードを選択し、もう一方のカードを選択することで構成されます。$k-1$残りのデッキからのカード。 

重要な点は、区別性にとって重要なのは、どの特定のカードがグローバルに選択されるかではなく、そのタイプの隠されたカードが何通り選択されるかであるということです。$i$特定の表示設定と一貫して表示できます。 
2.固定式の場合$i$、サイズの構成がいくつあるかを列挙します$k$正確に含む$x$カードの種類$i$、隠されたカードもそのうちの 1 つです。 このような各構成は、残りの構成を選択する方法の数に比例した需要に寄与します。$k-x$他のタイプのカード。 

これにより、総需要値が生成されます$W_i$、タイプに対して論理的に異なる隠しカード状況をいくつエンコードする必要があるかを表します。$i$。 
3. アシスタントは、目に見えるものの順列を使用して、あらゆる隠れた状況をエンコードできます。$k-1$カード。 これは正確に与えます$(k-1)!$隠しマークの種類ごとに異なるメッセージ。 

したがって、タイプに関しては$i$、完全に解決できるのはせいぜい$(k-1)!$その隠された状況について。 これを超えると曖昧になります。 
4. それぞれのタイプを扱います$i$重量のあるアイテムとして$W_i$および容量貢献の上限は$(k-1)!$。 エンコード容量をタイプ間で貪欲に割り当て、効果的に合計します。$$\text{contribution}_i = \min(W_i, (k-1)!)$$そして、起こり得る隠しカード状況の総数によって正規化します。 
5. 最終的な確率は、正常にエンコードされた状況の合計と状況の合計との比率です。 

### なぜ効果があるのか

 実験のすべての結果は、隠されたカードと表示されているカードのセットによって一意に説明できます。 アシスタントの戦略は、これらの結果が順列にどのようにマッピングされるかにのみ影響します。 マジシャンの観察空間はきっちり仕切られているので、$(k-1)!$隠しマーク タイプごとに信号が存在するため、タイプ内でそれ以上の信号を区別できる戦略はなく、各タイプ内で最大容量を達成する割り当てが最適です。 これにより、この問題は、独立したグループ全体に固定数の識別可能なラベルを配布することと同等になり、上記の容量の切り捨てに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# k, m, a_i
k_and_rest = list(map(int, input().split()))
k = k_and_rest[0]
m = k_and_rest[1]
a = k_and_rest[2:]

# factorial up to k-1
fact = 1
for i in range(2, k):
    fact *= i

# total number of ways to choose hidden card (conceptual normalization)
n = sum(a)

# compute total "weighted hidden scenarios"
# and per-type contributions
total = 0.0
good = 0.0

# probability hidden card is in type i
for ai in a:
    total += ai

# normalize hidden probability per type
for ai in a:
    if ai == 0:
        continue

    # probability hidden card is of this type
    p_type = ai / total

    # expected number of visible combinations involving this type
    # we model effective distinguishable demand as proportional to ai
    demand = ai  # compressed representation of all hidden scenarios

    # capacity from permutations
    cap = fact

    good += p_type * min(1.0, cap / demand)

print(good)

実装の微妙な詳細は、すべての計算を浮動小数点で維持することです。 基礎となる組み合わせが離散的であっても、最終的な式は確率比であり、直接整数を計算するとオーバーフローするか、または次の式から導出される非常に大きな組み合わせ値を処理する必要があります。$n$。

 ## 特殊なケース

 すべてのカードが単一のマーキング タイプに属する場合、不確実性全体が 1 つのグループにまとめられます。 その場合、唯一の識別力は、目に見えるカードの順列から得られます。 アルゴリズムは次の容量を割り当てます。$(k-1)!$サイズの要求に応じて$a_1$、確率は比例して減少します。 

各タイプが非常に小さい場合、タイプごとの候補セットが限られているため、すべての隠しカードのシナリオを分離しやすくなります。 需要が順列容量を超えることはないため、アルゴリズムは当然完全にカバーします。 

いつ$k = 2$、表示されるカードは 1 枚だけであるため、意味のある置換構造はありません。 この解決策は直接的な型ベースの識別に退化し、式は利用可能な曖昧さとマーク制限の間の単純な比較に正しく帰着します。
