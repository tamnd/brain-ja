 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられます。 すべてのクエリは、プレイヤーが 1 つの部屋から開始し、別の部屋にある特別なキーを収集する必要があり、キーが収集される前にトラップ ルームに入って永久に失敗することを回避する必要があるというシナリオを記述します。 その制約が満たされた後、プレイヤーはツリー内のすべての部屋を少なくとも 1 回訪問するまで自由に探索できます。 各クエリの目的は、これらのルールに基づいてすべての部屋を訪問するのに必要な最小合計移動時間を計算するか、それが不可能であることを報告することです。 

基礎となる構造は木であるため、2 つの部屋の間には単純なパスが 1 つだけ存在します。 この特性により、問題は扱いやすくなります。すべての移動パターンは固有のルートによって制約されるため、タイミングの問題はすべてツリー上の距離に換算されます。 

入力の規模は重要です。 ノードの数は最大 2000 ですが、クエリの数は 200000 に達する可能性があります。これは、クエリごとのグラフの走査に近いものは遅すぎることを直ちに示唆しています。 クエリごとに 1 つの BFS または DFS はすでに限界に達しており、これ以上高価なものは不可能です。 唯一の実行可能な方向は、ノード間のすべての距離を事前におよそ O(n^2) で事前計算し、一定時間内に各クエリに答えることです。 

重要な点はトラップの状態です。 これがなければ、問題は、特定のノードから開始してツリー内のすべてのノードを訪問する最短のウォークを見つけることになります。 トラップを使用すると、たとえトラバース コストが最適であっても、一部のシナリオが無効になります。 主な失敗ケースは、有効な移動のたびに、その構造によってプレイヤーがキーの前でトラップに遭遇することを強制される場合に発生します。 

具体的なエッジ ケースは、1-2-3-4 という線状のツリーです。 開始が 1、キーが 4、トラップが 2 であるとします。1 から 4 に到達するトラバースは、4 に到達する前に 2 を通過する必要があります。つまり、キーが収集される前にトラップが必然的にトリガーされます。 これにより、ツリーが完全に接続されていても、このシナリオは不可能になります。 

## アプローチ

 トラップ制約を無視すると、問題は古典的なツリー ウォークの最小化になります。 ノードから開始して重み付きツリー内のすべてのノードを訪問するには`s`、単純なアイデアは、すべてのエッジを 2 回 (前方に 1 回、後方に 1 回) 歩く DFS トラバーサルをシミュレートすることです。 これには費用がかかります`2 * total_edge_weight`。 ただし、最終パスでは開始点に戻る必要がないため、さらに改善することができます。 どこかのノードで終了する場合`x`、次にパスに沿ったエッジ`s`に`x`2 回ではなく 1 回だけ通過する必要があります。 これにより、総コストが正確に削減されます`dist(s, x)`。 したがって、制約のない最適な答えは次のようになります。`2 * W - max_x dist(s, x)`どこ`W`エッジの重みの合計です。 

クエリごとのブルート フォース アプローチでは、最短パスが再計算され、考えられるすべてのエンドポイントがシミュレートされるため、クエリごとに O(n^2) となり、200,000 クエリには大きすぎます。 

重要な観察は、ツリー内のすべての距離が、各ノードから 1 回ずつ、n 回の BFS 実行を使用して事前計算できることです。 n はわずか 2000 であるため、O(n^2) の前処理ステップが発生し、その後の距離クエリは O(1) になります。 これにより、残りの作業は、トラップがいつ最適なトラバーサル構造を無効にするかについて純粋に推論することになります。 

トラップは、避けられない順序違反を強制するような形で、スタートとキーの間の一意のパス上にある場合にのみ問題になります。 最適なトラバーサルは、開始点をルートとする DFS のようなウォークと見なすことができるため、各ノードが最初にアクセスされるタイミングは、距離を超えたエッジの重みではなく、ツリー構造のみに依存します。 これにより、制約が距離を使用した単純なパス包含チェックに減らされます。 

次のことをチェックすることで、トラップがスタートとキーの間のパス上にあるかどうかをテストします。`dist(s, t) + dist(t, k) = dist(s, k)`。 true の場合、トラップは一意のパス上にあります。 追加でしたら`dist(s, t) < dist(s, k)`、すると、そのパスに沿って鍵の前にトラップが表示され、最初に鍵を回収することができなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(n^2) | O(n) | 遅すぎる |
 | すべてのペアの距離を事前計算する | O(n^2 + q) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. ツリー内のすべてのエッジの重みの合計を計算します。 この値は、完全なオイラー ツアー スタイルのウォークですべてのエッジを 2 回横断するベースライン コストを表します。 
2. ノードのすべてのペア間の最短パス距離を事前計算します。 グラフはツリーであるため、各ノードから BFS またはダイクストラを実行することで効率的に実行できます。 
3. クエリごとに、開始ノードを読み取ります。`s`、キーノード`k`、トラップノード`t`。 
4. トラップが次の間の一意のパス上にあるかどうかを確認します。`s`そして`k`かどうかを確認することで`dist(s, t) + dist(t, k) == dist(s, k)`。 
5. トラップがこのパス上にある場合、`dist(s, t) < dist(s, k)`の場合、ツリー構造と一致する可能性のある走査でキーに到達する前にトラップに遭遇するため、このシナリオは不可能です。 
6. それ以外の場合は、トラップを無視して最適な走査コストを計算します。`2 * total_weight - max(dist(s, x)) over all x`。 
7. 計算されたコストを出力します。 

### なぜ効果があるのか

 ツリーの有効な完全な探索は、次から始まると見なすことができます。`s`、DFS のような構造でエッジを歩き、いくつかのエンドポイントで終了します。`x`。 すべてのエッジは、最終パス上のエッジを除き、効果的に 2 回横断されます。`s`に`x`、これらは 1 回横断されます。 この構造により、総コストが次の形式になることが保証されます。`2W - dist(s, x)`いくつかのエンドポイントの場合`x`を選択し、この保存された距離を最大化するエンドポイントを選択すると、制約のない最適なソリューションが得られます。 

唯一の追加の制限は、最初の訪問の間に注文することです。`k`そして`t`。 ツリーでは、強制的な順序付けを強制する唯一の方法は、一方が最初から他方への一意のパス上にある場合です。 トラップが途中にある場合は、`s`に`k`そしてより近いのは`s`の場合、キーへのすべてのルートが最初にトラップを通過する必要があり、要件を満たすことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
adj = [[] for _ in range(n)]
edges = []

total_w = 0

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append((v, w))
    adj[v].append((u, w))
    total_w += w

# all-pairs distances via BFS (tree so unique paths)
dist = [[0] * n for _ in range(n)]

from collections import deque

for src in range(n):
    dq = deque([src])
    dist[src][src] = 0
    vis = [False] * n
    vis[src] = True

    while dq:
        u = dq.popleft()
        for v, w in adj[u]:
            if not vis[v]:
                vis[v] = True
                dist[src][v] = dist[src][u] + w
                dq.append(v)

for _ in range(q):
    s, k, t = map(int, input().split())
    s -= 1
    k -= 1
    t -= 1

    # trap lies on path s-k?
    on_path = (dist[s][t] + dist[t][k] == dist[s][k])

    if on_path and dist[s][t] < dist[s][k]:
        print("impossible")
        continue

    best = 0
    for x in range(n):
        best = max(best, dist[s][x])

    ans = 2 * total_w - best
    print(ans)
```隣接リストにはツリーが保存され、すべてのクエリで再利用されるため、合計の重みが 1 回だけ累積されます。 距離行列は、各ノードから BFS を実行することによって埋められます。 グラフは重み付けされたエッジを持つツリーであるため、各パスが一意で貪欲に蓄積されるため、これでも機能します。 

各クエリの重要なステップは、距離等価条件を使用したパス チェックです。 これにより、LCA 構造が不要になります。 制約が実現可能性を妨げない場合、答えは標準のツリー走査式に帰着します。 

唯一の微妙な実装ポイントは、距離行列と入力解析全体で 0 ベースのインデックス付けの一貫性を確保することです。 もう一つはコンピューティングです`best`ただし、ここでは n が小さいため、クエリごとの O(n) スキャンは許容されます。 

## 実用的な例

 小さな木を考えてみましょう。```
1 -2- 2 -2- 3 -2- 4
```総重量は6です。 

クエリ: スタート 1、キー 4、トラップ 2。 

1 からの距離を計算します。 

| ノード | dist(1, ノード) |
 | --- | --- |
 | 1 | 0 |
 | 2 | 2 |
 | 3 | 4 |
 | 4 | 6 |

 1 から最も遠いノードは 4 なので、最適な節約は 6 です。基本コストは次のとおりです。`2 * 6 = 12`、したがって、答えは次のようになります`6`。 

ここでトラップ条件を確認します。1 から 4 までのパスにはノード 2 が含まれており、`dist(1,2) < dist(1,4)`したがって、トラップはキーの前に表示されます。 これではシナリオが不可能になります。 

次のクエリ: 開始 3、キー 1、トラップ 4。 

3からの距離:

 | ノード | dist(3, ノード) |
 | --- | --- |
 | 1 | 4 |
 | 2 | 2 |
 | 3 | 0 |
 | 4 | 2 |

 3 から最も遠いノードは 1 で、最良の節約は 4 となるため、基本的な答えは次のようになります。`12 - 4 = 8`。 

トラップ チェック: ノード 4 は 3 から 1 へのパス上にないため、制約は干渉しません。 トラバースは有効です。

 ## 特殊なケース

 重要なエッジケースは、トラップがスタートとキーの間のパス上に正確に存在する場合です。 その状況では、開始からキーまでの可能なルートのみが必然的にトラップを通過します。 トラップが開始点に近い場合、プレイヤーはキーに到達する前にトラップに入らざるを得なくなり、シナリオが無効になります。 アルゴリズムは、距離の等価条件と厳密な不平等チェックを通じてこれを検出します。 

もう 1 つのエッジ ケースは、トラップがスタートとキーの間のパス上にない場合です。 トラップが開始点に非常に近い場合でも、キー制約が満たされるとツリー構造により柔軟な探索が可能になるため、最適なトラバーサルでは、別の DFS 順序を選択することで早期にトラップを通過することを簡単に回避できます。
