 ## 解決策
 ## 問題の理解

 各生徒を次のいずれかに割り当てる必要があります`k`それぞれのバス`d`日々。 

すべての生徒にとって、課題は一連の長さとして考えることができます。`d`。 たとえば、次の場合`d = 3`、学生はバスに乗るかもしれません`(2, 1, 2)`3日間にわたって。 

2 人の生徒は、配列全体が同一であれば親友になります。 日によってはバスに乗り合わせることができますが、毎日同じバスに乗り合わせると順番が一致してしまい、取り決めが無効となります。 

課題は、次の課題を作成することです。`n`すべての生徒が固有のシーケンスを持つようにします。 それが不可能な場合は、印刷する必要があります`-1`。 

この制約は、検索の問題に対処していないことをすぐに示唆しています。 両方`n`そして`d`1000 に達する可能性がありますが、`k`と同じ大きさにすることができます`10^9`。 可能なスケジュールの数は指数関数的に増加するため、割り当てを総当たりで検索することは絶望的です。 出力自体には次のものが含まれているため、`n × d`数値的には、受け入れられているソリューションは、答えを直接生成することにほとんどの時間を費やす可能性があります。 

中心的な問題は、私たちがすべてを捧げることができるかどうかです`n`学生は異なる長さのシーケンスを学習します`d`、各ポジションは次のいずれかをとることができます。`k`価値観。 

まさにあります`k^d`長さの異なるシーケンス`d`アルファベット以上の大きさ`k`。 もし`n > k^d`、その場合、可能な限り最良の配置であっても、十分な個別のシーケンスが存在しないため、一部の生徒のペアが同じシーケンスを受け取る必要があります。 鳩の穴の原理によれば、答えは不可能です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3 1 2
```バスは1台しかありません。 すべての学生は毎日 1 番バスに乗らなければなりません。 すべての生徒が同じシーケンスを受け取ります`(1,1)`したがって、正しい答えは次のとおりです。```
-1
```一意性の要件を無視した不用意な構築では、代入が誤って出力される可能性があります。 

考慮する：```
1 1 1
```生徒は一人だけです。 学生のペアがないため、一意性は自動的に得られます。 正しい出力は次のとおりです。```
1
```一部の実装では、すべてのケースが誤って拒否されます。`k = 1`。 

別の微妙なケースは次のとおりです。```
8 2 3
```以来`2^3 = 8`、まったく十分な数の異なるシーケンスがあります。 正しい解決策は、考えられるすべてのシーケンスを使用する必要があります。 番号付けシステムにオフバイワンの間違いがある実装では、7 つの異なる割り当てのみが生成され、失敗が誤って報告される可能性があります。 

## アプローチ

 この問題を考える最も直接的な方法は、すべての生徒にシーケンスを割り当て、すべてのシーケンスが異なるかどうかを確認することです。 

強引なアプローチでは、毎日課題を生成し、すべての生徒のペアを比較し、すべての競合がなくなるまでスケジュールを変更し続けます。 検索スペースには次のものが含まれるため、このような戦略はすぐに実行不可能になります。`k^(n·d)`可能なスケジュール。 入力が非常に小さい場合でも、徹底的な探索は不可能です。 

重要な観察は、生徒は個別のシーケンスのみを必要とするということです。 

各生徒のスケジュールは長さがあります。`d`サイズのアルファベットを超える文字列`k`。 可能なスケジュールの数は正確に`k^d`。 これにより、問題は番号付けの問題に変換され、各生徒に異なるコードワードが割り当てられます。 

個別のコードワードを生成する自然な方法は、base にスチューデント インデックスを記述することです。`k`。 

学生に番号を付けるとします。`0`に`n-1`。 

学生`0`以下に対応します:```
000...
```学生`1`以下に対応します:```
001...
```学生`2`以下に対応します:```
002...
```など、正確に使用して`d`ベース-`k`数字。 

もし`n ≤ k^d`の場合、すべての生徒指数は次のようになります。`d`ベース-`k`数字。 個別の番号には個別の数字表現があるため、すべての生徒は自動的に固有のスケジュールを受け取ります。 

ステートメント内のバス番号には次の番号が付けられます。`1`に`k`、ベースながら-`k`桁の範囲は～`0`に`k-1`。 印刷時に 1 つ追加するだけです。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`k`、 そして`d`。 
2. 少なくとも`n`異なるスケジュールが存在します。 

計算能力`k`長さまで`d`、値がその値に達するかそれを超えると早期に停止します`n`。 
3. 後であれば`d`乗算しても値はまだ小さい`n`、印刷`-1`。 

これはつまり`k^d < n`したがって、すべての生徒にとって十分な個別のシーケンスはありません。 
4.`d × n`回答マトリックス。 

行`i`その日の課題を表します`i`。 
5. すべての生徒のインデックスについて`s`から`0`に`n-1`、 書く`s`基地内で`k`。 

正確に抽出する`d`数字。 欠落している上位桁はゼロとして扱われます。 
6. 抽出した数字を回答マトリックスに保存します。 

の`i`-番目の桁はその日に使用されるバスを決定します`i`。 
7. すべての生徒を処理した後、印刷時に保存されているすべての数字に 1 を加えます。 

これは数字を変換します`0..k-1`バス番号に`1..k`。 

### なぜ効果があるのか

 すべての生徒には拠点が割り当てられています。`k`間の異なる整数の表現`0`そして`n-1`。 

ベースだから-`k`表現は一意であるため、2 人の生徒が同じ数字のシーケンスを受け取ることはありません。 したがって、どの生徒のペアでも、割り当てられたバスが異なる日が少なくとも 1 日は存在します。 

構造は正確に使用します`d`数字。 このような表現は、まさに次の場合にすべての学生指数に対して存在します。`n ≤ k^d`。 もし`n > k^d`、学生よりも可能な順序が少ないため、有効な配置は存在できません。 したがって、このアルゴリズムは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())

    cnt = 1
    for _ in range(d):
        if cnt >= n:
            break
        cnt *= k

    if cnt < n:
        print(-1)
        return

    ans = [[0] * n for _ in range(d)]

    for student in range(n):
        x = student
        for day in range(d):
            ans[day][student] = x % k
            x //= k

    out = []
    for day in range(d):
        out.append(" ".join(str(ans[day][student] + 1) for student in range(n)))

    sys.stdout.write("\n".join(out))

solve()
```最初の部分では、十分な個別のスケジュールが存在するかどうかを確認します。 の正確な値は決して必要ありません`k^d`それを超えると`n`, そのため、乗算が早期に停止する可能性があります。 

必要な出力形式では 1 行に 1 日が印刷されるため、マトリックスは生徒ごとではなく日ごとに構成されています。 これにより、後の転置操作が回避されます。 

生徒一人ひとりに合わせて繰り返し受講していきます。`x % k`で割ります`k`。 これにより塩基が抽出されます。`k`最下位から最上位までの数字。 生徒のインデックスはそれぞれ異なるため、桁ベクトルも異なります。 

よくある間違いは、バス番号が から始まることを忘れることです。`1`。 内部表現には数字が使用されます`0..k-1`, そのため、印刷時にのみ 1 つを追加します。 

もう 1 つのよくあるバグは、計算を試行することです。`k^d`直接。 Python は大きな整数を処理できますが、その必要はありません。 早期に停止すると、チェックが簡単かつ効率的になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 The largest possible output already contains one million numbers because both`n`そして`d`1000 にすることもできます。`O(n·d)`構造は出力サイズに一致しており、制限内に快適に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, k, d = map(int, input().split())

    cnt = 1
    for _ in range(d):
        if cnt >= n:
            break
        cnt *= k

    if cnt < n:
        return "-1"

    ans = [[0] * n for _ in range(d)]

    for student in range(n):
        x = student
        for day in range(d):
            ans[day][student] = x % k
            x //= k

    return "\n".join(
        " ".join(str(ans[day][student] + 1) for student in range(n))
        for day in range(d)
    )

# minimum case
assert run("1 1 1\n") == "1"

# impossible case
assert run("3 1 2\n") == "-1"

# boundary n = k^d
out = run("8 2 3\n")
assert out != "-1"

# sample-sized case
out = run("3 2 2\n")
assert out != "-1"

# another impossible boundary
assert run("9 2 3\n") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1`|`1`| 最小の有効なインスタンス |
 |`3 1 2`|`-1`| 使用可能なシーケンスは 1 つだけ |
 |`8 2 3`| 任意の有効なスケジュール | 正確な容量境界`n = k^d`|
 |`3 2 2`| 任意の有効なスケジュール | 基本構造 |
 |`9 2 3`|`-1`| 容量を超える最初の不可能な値 |
