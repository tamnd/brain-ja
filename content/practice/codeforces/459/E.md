 ## 解決策
 ## 問題の理解

 すべてのエッジに重みがある有向グラフが与えられます。 エッジの数で測定される可能な限り長いパスが必要ですが、1 つの制限があります。あるエッジから次のエッジに移動するときは常に、新しいエッジの重みが前のエッジより厳密に大きくなければなりません。 

パスは単純である必要はありません。 頂点を再検討することもできます。 グラフ内ではサイクルが許可されます。 重要なのは、選択したパスに沿ったエッジの重みのシーケンスが厳密に増加していることだけです。 

有向エッジごとに`(u → v, w)`で終わる、以前に構築されたパスの拡張の可能性があると考えることができます。`u`ただし、そのパスで使用される最後のエッジの重みが より小さい場合に限ります。`w`。 

グラフには最大で次のものを含めることができます`3 · 10^5`頂点と`3 · 10^5`エッジ。 パスを明示的に探索するアルゴリズムは直ちに不可能です。 たとえ`O(m²)`動的計画法ソリューションには大まかに必要なものが必要です`9 · 10^10`最悪の場合の運用。 線形に近いものが必要です。`O(m log m)`。 

最も危険なケースは、同じ重みを共有するエッジから発生します。 

考慮する：```
3 2
1 2 5
2 3 5
```正しい答えは次のとおりです。```
1
```重みを厳密に増加させる必要があるため、2 つのエッジをチェーンすることはできません。 ウェイトのエッジの処理中に即時に実行される不注意な DP 更新`5`長さが誤って生成される可能性があります`2`。 

もう 1 つの重要なケースは、重みが増加するサイクルです。```
3 3
1 2 1
2 3 2
3 1 3
```正しい答えは次のとおりです。```
3
```グラフにはサイクルが含まれていますが、重みを増やすと無限パスが回避されます。 次のすべてのエッジの重みが大きくなる必要があるため、答えは有限です。 

3 番目の微妙なケースは、同じ重みの複数の入力エッジです。```
3 3
1 2 1
1 3 1
2 3 2
```正しい答えは次のとおりです。```
2
```両方の重み 1 エッジは長さ 1 のパスを作成します。重み 2 エッジは頂点 2 で終わる最適なパスを延長する必要があります。DP は各頂点の最大値を保持する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、有効なウェイト増加パスをすべて構築しようとします。 すべてのエッジから開始して、より大きな重みを持つすべての発信エッジを再帰的に追跡できます。 これは、問題によって許可されているパスを正確に列挙しているため、正しいです。 

問題は、そのようなパスの数が指数関数的に増加する可能性があることです。 頂点あたりの分岐選択肢がわずかしかないグラフでも、膨大な数の増加シーケンスが生成される可能性があります。 まで`3 · 10^5`エッジでは、徹底的な探索は完全に不可能です。 

重要な観察は、実際のパス構造は、エンドポイントや最後に使用された重みよりもはるかに重要ではないということです。 

重みの大きい順にエッジを処理するとします。 エッジを考えるとき`(u → v, w)`、で終わるすべての有効なパス`u`最後のエッジの重みが厳密に小さい`w`この端を通って延長することができます。 

させて`dp[x]`頂点で終わる最適なパスの長さを示します`x`すでに処理された重みのみを使用します。 

それからエッジ`(u → v, w)`次の長さのパスを作成できます。```
dp[u] + 1
```複雑さは均等な重みです。 

2 つのエッジの重みが同じ場合、パスは厳密な増加を必要とするため、相互に影響を及ぼしてはなりません。 一つ一つ処理して更新する`dp`すぐに同じ重みのエッジを連鎖させることを誤って許可してしまう可能性があります。 

修正するには、同じウェイトのすべてのエッジを一緒に処理します。 

重量のあらゆるエッジに対応`w`、まず、重み付けの前に存在していた DP 状態を使用して候補値を計算します。`w`始めました。 重量がすべてエッジに達した後のみ`w`評価されているので、更新をコミットします。 

これにより、小さいウェイトと現在のウェイトが明確に分離されます。 

エッジを重みでソートした後、すべてのエッジが 1 回処理され、`O(m log m)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(m log m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、次のように保存します。`(weight, from, to)`。 
2. エッジを重量別に分類します。 

選別により、重量を処理する際に次のことが保証されます。`w`、すべての小さい重みはすでに DP 状態に寄与しています。 
3. 配列を維持する`dp[v]`。`dp[v]`頂点で終了する有効な増加重みパスの最大長を表します`v`、現在処理されているグループよりも厳密に小さい重みのみを使用します。 
4. 等しい重みでグループ化されたエッジを処理します。 

同じ重みを持つすべてのエッジは、互いに拡張できないように一緒に処理する必要があります。 
5. あらゆるエッジに`(u → v)`現在の体重グループで次を計算します。```
candidate = dp[u] + 1
```これが次で終わる最適なパスです`u`現在のエッジによって拡張された、より小さい重みを使用します。 
6. これらの候補の更新を直接書き込むのではなく、一時的に保存します。`dp`。 

これにより、同じ重みのエッジが互いに影響を与えることがなくなります。 
7. グループ内のすべてのエッジが評価されたら、次を適用します。```
dp[v] = max(dp[v], candidate)
```保存されているすべてのアップデートに対して。 
8. 次の体重グループに進みます。 
9. 答えは、次の値に存在する最大値です。`dp`。 

### なぜ効果があるのか

 不変条件は、重みグループを処理する前の条件です。`w`、`dp[v]`で終わる有効なパスの最大長と等しくなります。`v`最後のエッジの重みが厳密に小さい`w`。 

エッジを評価するとき`(u → v, w)`、値`dp[u] + 1`は、このエッジに合法的に先行できるすべての有効なパスを表します。これは、そのようなパスはすべて、より小さい重みで終了するためです。 

グループ全体が完了するまで更新は遅れます。 その結果、重量のエッジがありません`w`ウェイトの別のエッジを使用できる`w`その前身として。 これは厳密な不等式の要件に正確に一致します。 

重みの増加に対する帰納により、すべての有効なパスが表現され、表現されたすべてのパスが有効になります。 したがって、最終的な最大 DP 値は、最も長く増加する重みパスの長さになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u, v))

    edges.sort()

    dp = [0] * (n + 1)

    i = 0
    while i < m:
        j = i
        updates = []

        while j < m and edges[j][0] == edges[i][0]:
            _, u, v = edges[j]
            updates.append((v, dp[u] + 1))
            j += 1

        for v, val in updates:
            if val > dp[v]:
                dp[v] = val

        i = j

    print(max(dp))

if __name__ == "__main__":
    solve()
```最初のステップでは、すべてのエッジをその重みとともに保存し、リストをソートします。 これにより、小さい重みから大きい重みへの自然な処理順序が与えられます。`dp[v]`頂点で終わる最適なパスの長さを保存します`v`。 最初はエッジが使用されていないため、すべての値はゼロです。 

最も重要な実装の詳細は一時的なものです。`updates`配列。 体重グループを調査する際に変更を加えることはありません`dp`直接。 すべての候補値は古い DP 状態から計算されます。 グループ全体が処理された後でのみ、更新がコミットされます。 

この分離がないと、2 つの等しい重みのエッジが互いに拡張され、厳密な増加条件に違反する可能性があります。 

最終的な答えは、単に DP 配列内のどこかに格納されている最大のパス長です。 

## 実用的な例

 ### サンプル 1

 入力:```
3 3
1 2 1
2 3 1
3 1 1
```ソート後、すべてのエッジは同じ重みグループに属します。 

| エッジ | 前の dp | 候補者 | 保存された更新 |
 | --- | --- | --- | --- |
 | 1→2 | dp[1]=0 | 1 | (2,1) |
 | 2→3 | dp[2]=0 | 1 | (3,1) |
 | 3→1 | dp[3]=0 | 1 | (1,1) |

 | 頂点 | DP |

```この例は、等しい重みのエッジが相互作用できない理由を示しています。 たとえそれらがサイクルを形成していても、重みはすべて同一であるため、どれも別のサイクルを拡張することはできません。

import io

def run(inp: str) -> str:

    input = sys.stdin.readline

    n, m = map(int, input().split())

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u, v))

        for v, val in updates:

        i = j

 ## 特殊なケース

 2 つの等しい重みのエッジを考えます。```
3 2
1 2 5
2 3 5
```両方のエッジは同じ重みグループに属します。 評価中に、アルゴリズムは古い DP 状態を使用して候補を計算します。```
(2,1)
(3,1)
```両方の候補が収集された後でのみ、更新が適用されます。 2 番目のエッジには最初のエッジの効果が反映されないため、答えは残ります。`1`、それは正しいです。 

ここでサイクルを考えてみましょう。```
3 3
1 2 1
2 3 2
3 1 3
```重みグループは順番に処理されます`1`、`2`、`3`。 DP 値は次のようになります。```
dp[2] = 1
dp[3] = 2
dp[1] = 3
```アルゴリズムの出力`3`。 頂点を再訪することは許可されていますが、ウェイトを増やすと無限の成長が妨げられます。 

最後に、同じ頂点に収束する複数のパスを考慮します。```
4 4
1 3 1
2 3 2
3 4 3
1 4 10
```重みの処理後`1`そして`2`、頂点`3`可能な限り最適なパス長を保存します。 体重のとき`3`エッジは加工されています`3 → 4`利用可能な最も強力なパスを延長します。 DP アップデートでは、`max`したがって、より弱い代替案がより優れた代替案を上書きすることはありません。 結果として得られる答えは、`2`、いずれかに対応`1→3→4`または`2→3→4`。
