 ## 解決策
 ## 問題の理解

 配列が与えられています`a[1..n]`。 

あらゆるポジションについて`i`、値を定義します`L[i] = number of occurrences of a[i] in the prefix [1..i]`。 

あらゆるポジションについて`j`、 定義する`R[j] = number of occurrences of a[j] in the suffix [j..n]`。 

タスクはペアを数える事です`(i, j)`と`i < j`そのような`L[i] > R[j]`。 

元のステートメントでは、関数を通じてこれらの値を説明しています。`f(l,r,x)`ですが、これら 2 つの配列を事前計算すると、問題全体がより明確になります。 

次のサンプルを考えてみましょう。```
1 2 1 1 2 2 1
```プレフィックス周波数は次のとおりです。```
L = [1,1,2,3,2,3,4]
```接尾辞の頻度は次のとおりです。```
R = [4,3,3,2,2,1,1]
```さて、問題は単純に次のとおりです。 

ペアを数える`(i,j)`と`i < j`そして`L[i] > R[j]`。 

制約があるからこそ、問題は面白くなります。 配列の長さは 100 万に達する場合があります。 二次アルゴリズムでは、大まかに次のものが必要になります。```
10^12
```比較することは完全に不可能です。 たとえ`O(n√n)`ソリューションが大きすぎる可能性があります。 に近いものが必要です`O(n log n)`。 

見落としやすいケースがいくつかあります。 

すべての値が異なると仮定します。```
3
1 2 3
```それから```
L = [1,1,1]
R = [1,1,1]
```どのペアも満たされない`1 > 1`、したがって、答えは次のとおりです`0`。 を使用した不用意な解決策`>=`の代わりに`>`すべてのペアを間違ってカウントしてしまいます。 

考慮する：```
4
5 5 5 5
```ここ```
L = [1,2,3,4]
R = [4,3,2,1]
```答えは単純にすべてのペアではありません。 不等式を満たすペアもあれば、満たさないペアもあります。 条件は配列に格納されている数値ではなく出現回数に依存するため、値自体のみに基づくショートカットは失敗します。 

もう 1 つの微妙なケースは、多くの異なる値が同じ周波数を生成する場合です。 例えば：```
4
1 2 1 2
```取得します```
L = [1,1,2,2]
R = [2,2,1,1]
```この問題は、元の配列値ではなく、頻度についての数え方の問題になります。 等しい値を別々に扱うと、有効なペアが失われます。 

## アプローチ

 直接解では最初に計算が行われます`L`そして`R`。 

次に、ペアごとに`(i,j)`と`i<j`かどうかをテストします。```
L[i] > R[j]
```そして、それが成立する場合、答えをインクリメントします。 

これは定義を文字通りにチェックするので、これは正しいです。 残念ながら、あります```
n(n-1)/2
```ペア。 のために`n = 10^6`、それは約です`5 × 10^11`処理できる範囲をはるかに超えています。 

重要な観察は、計算後、`L`そして`R`、元の配列値は重要ではなくなります。 ペアを数えるだけで十分です```
i < j
L[i] > R[j]
```これは、反転計数に似た古典的な計数問題です。 

通常の反転計数では、ペアを数えます。```
i < j
A[i] > A[j]
```マージソートを使用します。 ここで右側は異なる配列からのものですが、構造はほぼ同じです。 

分割統治プロセス中に、インデックス範囲を左半分と右半分に分割するとします。 

有効なペアはすべて、次の 3 つのカテゴリのいずれかに分類されます。 

1. 左半分の両方のインデックス。 
2. 右半分の両方のインデックス。 
3.`i`左半分と`j`右半分にあります。 

最初の 2 つのカテゴリは再帰的に処理されます。 

3 番目のカテゴリについては、次のように計算する必要があります。```
L[i] > R[j]
```と`i`左側の部分からと、`j`右部分から。 

左半分を次のように並べ替えると、`L[i]`値と右半分による`R[j]`値を取得すると、マージ ステップの線形時間で 2 ポインター スキャンを使用して、これらのクロス ペアをカウントできます。 

これにより、反転カウントと同じ複雑さが生じます。```
O(n log n)
```これは十分に速いです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適な分割統治 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 周波数配列の計算

 最初の計算`L`。 

周波数のハッシュ マップを維持しながら、左から右に移動します。 位置ごとに、周波数を増加させます。`a[i]`そして結果をに保存します`L[i]`。 

次の計算`R`。 

別の周波数マップを右から左に移動します。 周波数を増加させます`a[i]`サフィックスに入力し、結果を保存します`R[i]`。 

### 分割統治カウンティング

 あらゆるポジションについて`i`、ペアを保存します。```
(L[i], R[i])
```インデックス範囲に対してマージソートスタイルの再帰を実行します。 

### アルゴリズムのチュートリアル

 1. アレイを構築する`L`そして`R`周波数マップを使用します。 
2. 位置の配列を作成します。 再帰中、各セグメントはその順序でソートされた状態で維持されます。`L`価値観。 
3. 左半分を再帰的に解きます。 
4. 右半分を再帰的に解きます。 
5. クロスペアを数えます。`i`左半分に属し、`j`右半分に属します。 

左側のセグメントは次のようにソートされているため、`L`そして右側のセグメントは次の基準でソートされます`L`、個別にアクセスできます`L`そして`R`値を設定し、満たす残りの要素の数をカウントします。`L[i] > R[j]`。 
6. 現在のセグメントを次の基準で並べ替えます。`L`マージステップ中。 
7. 左ペア、右ペア、および交差ペアの合計を返します。 

よりクリーンな実装は、標準の Codeforces ソリューションに従います。 インデックス範囲自体を再帰的に調べます。 マージ ステップ中、元の配列では左側のインデックスが右側のインデックスの前に残るため、カウントされたすべてのクロス ペアは自動的に次の条件を満たします。`i < j`。 

クロスペアを効率的にカウントするために、次の基準で並べ替えます。`L`。 右半分の要素ごとに、左半分の要素の数を数えます。```
L > R[right]
```移動ポインタを使用します。 

### なぜ効果があるのか

 再帰では、すべてのインデックス ペアが 3 つのグループ (完全に左、完全に右、または中間点を横切る) のいずれかに分割されます。 再帰呼び出しでは、最初の 2 つのグループが正しくカウントされます。 マージ ステップ中、すべての交差ペアの左端は左半分に、右端は右半分にあるため、`L[i] > R[j]`で十分です。 半分は次のように並べ替えられるため、`L`、2 ポインター スキャンでは、そのようなすべてのペアが省略や重複なくカウントされます。 すべての有効なペアは、そのエンドポイントが最初に異なる半分に分類される再帰レベルで 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = {}
    L = [0] * n
    for i in range(n):
        x = a[i]
        cnt[x] = cnt.get(x, 0) + 1
        L[i] = cnt[x]

    cnt.clear()
    R = [0] * n
    for i in range(n - 1, -1, -1):
        x = a[i]
        cnt[x] = cnt.get(x, 0) + 1
        R[i] = cnt[x]

    idx = list(range(n))
    temp = [0] * n

    def dc(l, r):
        if r - l <= 1:
            return 0

        m = (l + r) // 2

        ans = dc(l, m) + dc(m, r)

        p = l
        for j in range(m, r):
            while p < m and L[idx[p]] <= R[idx[j]]:
                p += 1
            ans += m - p

        i, j, k = l, m, l
        while i < m and j < r:
            if L[idx[i]] <= L[idx[j]]:
                temp[k] = idx[i]
                i += 1
            else:
                temp[k] = idx[j]
                j += 1
            k += 1

        while i < m:
            temp[k] = idx[i]
            i += 1
            k += 1

        while j < r:
            temp[k] = idx[j]
            j += 1
            k += 1

        for t in range(l, r):
            idx[t] = temp[t]

        return ans

    print(dc(0, n))

if __name__ == "__main__":
    solve()
```最初の部分では、プレフィックスの出現数を計算します。`L`および接尾辞の出現数`R`。 

分割統治ルーチンは、マージ ソートを反映します。 いつでも、`idx[l:r]`そのセグメントのインデックスがそのセグメントの順序でソートされて含まれます。`L`価値観。 

クロスペアのカウントは微妙な部分です。 左半分と右半分はすでにソートされています`L`。 固定された右要素の場合、すべての左要素は```
L > R[right]
```ソートされた左半分のサフィックスを形成します。 ポインタ`p`は前方にのみ移動するため、マージ全体でカウント ステップが線形になります。 

答えはおおよその範囲で構いません`n²/2`したがって、64 ビット整数が必要です。 Python の整数はこれを自動的に処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | レベルごとの線形作業によるマージソート再帰 |
 | スペース | O(n) | 周波数配列、インデックス配列、およびマージ バッファ |

 と`n`100万まで、`O(n²)`不可能です。`O(n log n)`は、約 2,000 万回の原始的な操作を実行します。これは、最適化された実装の制限内に問題なく収まり、意図されたソリューションです。

 ## 特殊なケース

 次のことを考慮してください。```
1
7
```以下を取得します。```
L = [1]
R = [1]
```ペアがまったくありません。 再帰はすぐに基本ケースに到達し、戻ります。`0`。 

考慮する：```
2
1 1
```ここ：```
L = [1,2]
R = [2,1]
```唯一のペアは、`(1,2)`そしてテストします:```
1 > 1
```それは誤りです。 答えは`0`。 を使用した実装`>=`間違って戻ってきます`1`。 

考慮する：```
4
1 2 3 4
```すべての周波数は 1 に等しくなります。```
L = [1,1,1,1]
R = [1,1,1,1]
```条件を満たすペアはありません。 すべてのマージ ステップ中、カウント ポインタは左側の要素をすべて通過して進みます。`L <= R`どこにでもあり、答えへの寄与はゼロです。 

考慮する：```
4
5 5 5 5
```配列は次のようになります。```
L = [1,2,3,4]
R = [4,3,2,1]
```分割統治プロセスでは、ペアを正確にカウントします。`(2,4)`そして`(3,4)`。 注文`i < j`クロスペアはインデックス間隔の左半分と右半分の間でのみカウントされるため、自動的に保証されます。
