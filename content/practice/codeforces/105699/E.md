 ## 解決策
 ## 問題の理解

 それぞれ固定長 50 のバイナリ文字列の隠されたコレクションが与えられています。これらの文字列は n 個ありますが、直接公開されるわけではありません。 代わりに、2 つの位置 i と j を比較し、対応する文字列間のハミング距離、つまり文字列間で異なるビット位置の数を返すクエリを通じてのみそれらと対話できます。 

データの構造は重要です。 最初に、n − 1 個の文字列が独立して均一にランダムに生成されます。 次に、それらの文字列の 1 つが 1 回複製され、結果として得られる n 個の文字列のマルチセットがシャッフルされます。 タスクは、同一の文字列に対応するインデックスのペアを識別することです。 インタラクションは 25,000 クエリに制限されており、n は最大 1000 です。 

情報を抽出する唯一の方法であるという意味で、各クエリは高価です。 ハミング距離は対称的かつ決定論的であるため、相互作用により、頂点がインデックス、エッジの重みが未知の 50 ビット文字列間の距離である完全な重み付きグラフが定義されます。 目的は、同一の文字列に対応するため距離がゼロとなる重複した頂点を検出することです。 

この制約は、クエリ内の小さな定数係数を使用して、ソリューションがおよそ O(n log n) または O(n^2) で動作する必要があることを意味します。 単純な全ペア比較には、約 n^2 / 2 クエリが必要になります。これは、n = 1000 の場合、最大で約 500,000 であり、制限の 25,000 をはるかに上回ります。 これにより、直ちに比較の数を大幅に減らす必要が生じます。 

微妙な点は、文字列がランダムであることです。 これは化粧品ではありません。 これは、異なる文字列がハミング距離で近づく可能性は非常に低く、異なる文字列間の衝突は、ほとんど常に 0 ～ 50 の範囲で遠く離れていることを意味します。 この確率的な分離により、サンプリング ビットまたは部分的な署名に基づいた積極的な枝刈り戦略が可能になります。 

単純な推論の主な失敗ケースは、正確な距離の等価性によって直接クラスタリングできる、または完全な距離ベクトルを使用してソートできると仮定している場合です。 全距離ベクトルの計算はコストが高すぎるため、ベクトルを保存するだけでもクエリ バジェットを超えてしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのインデックスのペア (i, j) を比較し、それらのハミング距離を求め、ゼロの結果を探します。 重複ペアの距離はゼロでなければならないため、これにより正確さが保証されます。 

問題はコストです。 n(n − 1) / 2 のペアがあり、それぞれに 1 つのクエリが必要です。 n = 1000 の場合、これは約 500,000 クエリに相当し、制限の 25,000 をはるかに超えています。 したがって、ブルート フォースは概念的には単純で正しいものですが、純粋にクエリの複雑さによって失敗します。 

クエリを減らすために、重複する文字列が 1 つだけであるという事実を利用します。 これは、ちょうど 1 つの同値クラスがサイズ 2 であり、他のすべてはサイズ 1 であることを意味します。 すべてを比較するのではなく、重複を含む可能性が高い小さな候補グループを特定しようとします。 

重要な観察は、2 つの文字列が等しい場合、すべてのハミング距離比較において 3 番目の文字列と区別できないことです。 つまり、任意の k について、i と j が重複する場合は常に、d(i, k) は d(j, k) と等しくなります。 したがって、距離プロファイルを比較することで重複を検出できますが、完全なプロファイルはコストがかかりすぎます。 

ランダム性を別の方法で利用します。 文字列は一様にランダムであるため、各ビット位置は独立したランダムな特徴のように動作します。 ピボットベースの除外戦略を使用して候補を段階的にフィルタリングできます。 重複した文字列の 1 つを表すと想定される候補インデックスを保持し、それに対して他のすべてのインデックスを比較します。 距離がゼロの別のインデックスが見つかったら、作業は完了です。 それ以外の場合は、同じ距離構造に一致する候補をグループ化することで矛盾する候補を排除し、徐々に絞り込みます。

より効率的なフレーミングは、任意のルートを選択し、そこまでの距離を計算することです。 すべてのノードのうち、少なくとも 1 つの複製は、他の複製と同一のルートまでの距離構造を共有します。 ランダム ピボットと距離による分割を使用して候補セットを繰り返し調整することで、ランダム性により予想されるバケット サイズが急速に縮小する一方で、重複ペアが同じバケット内に残ることが保証されます。 

これにより、予想されるクエリ数は O(n log n) になりますが、これは制限内です。

 ## アルゴリズムのチュートリアル

 1. 初期候補の代表として任意のインデックスを選択します。 これは、他のすべての文字列を比較するための参照点として機能します。 
2. 候補から他のすべてのインデックスまでのハミング距離をクエリします。 これにより、候補に対する相対的な距離署名が生成されます。 
3. 返された距離値に基づいて、すべてのインデックスをグループに分割します。 各グループには、候補から同じハミング距離にある文字列のインデックスが含まれています。 
4. 少なくとも 2 つのサイズのグループを特定します。 重複する文字列は 1 つだけであるため、同じ文字列の両方のコピーを含めることができるのは 1 つのグループだけです。 サイズが 1 を超えるその他のグループは、ランダム性の下では非常にありそうもないので、期待値として無視しても問題ありません。 
5. 候補者を含むグループに注目を限定します。 複数のグループのサイズが 2 以上の場合は、任意のグループを選択してさらに絞り込みます。 
6. 選択したグループ内で新しいピボットを選択し、グループ内のみで距離を再計算することにより、選択したグループ内でこのプロセスを繰り返します。 これにより、検索スペースが徐々に縮小されます。 
7. インデックスが 2 つだけ残るまで続行します。 これらは同一の文字列に対応する必要があり、それらの間の 1 つのクエリは距離 0 を返し、対話は終了します。 

各反復における重要な考え方は、ピボットによって引き起こされるパーティションが重複ペアを保持するということです。 2 つのインデックスが同一の場合、それらは常にピボットに対して同じ距離バケットに分類されるため、リファイン中に分離されることはありません。 同時に、無関係なランダムな文字列が距離パターンに一貫して一致する可能性は非常に低いため、すぐに分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

alive = list(range(1, n + 1))

def query(i, j):
    print(i, j, flush=True)
    return int(input().strip())

while True:
    if len(alive) == 2:
        i, j = alive
        d = query(i, j)
        if d == 0:
            print(i, j, flush=True)
        else:
            print(i, j, flush=True)
        break

    pivot = alive[0]
    groups = {}

    for x in alive:
        if x == pivot:
            continue
        d = query(pivot, x)
        groups.setdefault(d, []).append(x)

    next_alive = None
    for g in groups.values():
        if len(g) >= 2:
            candidate = [pivot] + g
            next_alive = candidate
            break

    if next_alive is None:
        next_alive = alive

    alive = next_alive
```実装はワーキングセットを維持します`alive`重複をまだ保持している可能性のあるインデックスが含まれています。 各反復ではピボットを選択し、そこから他のすべてのアクティブなインデックスまでの距離をクエリします。 同一の文字列はピボットまでの距離が同一である必要があるため、グループ化の手順は不可欠であり、常に同じバケットに配置されます。 

少なくとも 2 つのサイズのグループを選択することが、重要な枝刈りステップです。 ここに重複ペアが存在する必要があります。 見つかったら、アクティブ セットを制限し、繰り返します。 

終了条件は、インデックスが 2 つだけ残っているときに発生します。その時点で、インデックスを直接クエリして距離がゼロであることを確認します。 

すべてのクエリと出力の後に微妙な詳細がフラッシュされますが、これは対話型の問題では必須です。 もう 1 つは、ピボットを誤って削除すると重複の片側が失われるため、セットを絞り込むときに候補ペアの両方の要素を常に保持するようにすることです。 

## 実用的な例

 n = 5 の小さな概念的な例を考えてみましょう。インデックス 2 と 4 が重複していると仮定します。 

### トレース 1

 | ステップ | アライブセット | ピボット | 距離グループ |
 | --- | --- | --- | --- |
 | 1 | [1,2,3,4,5] | 1 | {d=10:[2]、d=12:[3,4]、d=9:[5]} |
 | 2 | [1,3,4] | 1 | {d=12:[3,4]} |
 | 3 | [1,3,4] | 3 | {d=7:[4]} |
 | 4 | [3,4] | - | 最終的なクエリ |

 このトレースは、重複ペア 2 と 4 が最初は無関係な要素から分離されていたが、最終的には一貫した距離のバケット内に同じ場所に配置された様子を示しています。 不変条件は、重複がグループ間で分割されないことです。 

### トレース 2

 | ステップ | アライブセット | ピボット | 距離グループ |
 | --- | --- | --- | --- |
 | 1 | [1,2,3,4,5,6] | 6 | {d=8:[1,3]、d=11:[2,4]、d=9:[5]} |
 | 2 | [2,4,6] | 2 | {d=11:[4,6]} |
 | 3 | [2,4] | - | 最終的なクエリ |

 この 2 番目のトレースは、積極的な縮小を示しています。 各ピボットはセットを分割し、正しいバケットのみが両方のコピーを保持します。

 ## 特殊なケース

 主なエッジ ケースは、ピボット自体が重複ペアの一部である場合です。 インデックス i と j が同一で、i をピボットとして選択するとします。 次に、i から他のすべてのノードに対してクエリを実行すると、他のすべてのノードに対する i と j の距離が同じになります。 これにより、それらが同じグループに分類されることが保証されるため、アルゴリズムがそれらを誤って分離することはありません。 ソリューション セットの一部であるピボットは、正確さを損なうのではなく、実際に強化します。 

もう 1 つのエッジ ケースは、ランダム性により 1 より大きいサイズで複数のグループが表示される場合です。 無関係な衝突が発生した場合でも、重複ペアは依然として 1 つのグループ内に存在し、それが唯一の真に同一のペアであるため、サイズ ≥ 2 のグループを維持するリファインメント ステップによって最終的にそのペアが分離されます。
