 ## 解決策
 ## 問題の理解

 それぞれが非常に大きく、独立してランダムに選択された整数の配列が与えられます。 これらの数字から、一部を保持し、その他を破棄することができます。 保持されているすべての番号は、ラベル付きの 3 つのグループ A、B、または C のいずれかに正確に割り当てる必要があります。 

要件は厳格です。A、B、C に配置される値の合計はすべてまったく同じである必要があり、3 つのグループをいずれも空にすることはできません。 出力は、入力数値ごとに、それを破棄するか、3 つのグループの 1 つに割り当てるかを順番に説明する単純な文字列です。 

この制約は、決定論的な最悪の場合の問題としては異例です。 n が 6 または 10000 に固定され、値が 10^12 までの場合、サブセットの組み合わせを探索しようとするソリューションは直ちに除外されます。 2^10000 の構成は実際には無関係であるため、すべての要素のサブセットの合計を保存するだけでも大きすぎます。 この問題が解決できる唯一の理由は、値がランダムであり、ジャッジが有効なパーティションが常に存在することを保証しているためです。 

この保証により、タスクの性質が変わります。 私たちはもはや敵対的に解決策を探しているわけではありません。 その代わりに、バランスを不安定にする要素を排除しながら、バランスの取れたグループを徐々に構築することでグループを構築しています。 

単純なアプローチの微妙な失敗例は、破棄する機能を持たずに、すべての要素を現在の最小和グループに貪欲に割り当てようとしたときに発生します。 たとえば、100、90、80、1、1、1 のような数値がある場合、貪欲な割り当てにより、一部の要素が除外されている場合に有効なパーティションが存在する場合でも、早い段階で 1 つのグループが簡単にオーバーフィルになり、後のバランシングが不可能になる可能性があります。 これは、なぜ破棄が不可欠であるかを示しています。破棄がなければ、貪欲なバランスは安定しません。 

最初にすべての要素をグループに強制的に入れ、最後に不均衡を「修正」しようとすると、別の故障モードが発生します。 合計が大きく乖離すると、小さな要素を削除するだけでは、大きな値を初期に割り当てたことによって生じた大きな不均衡を修正するには不十分です。 

主な困難は、すべての要素から等しい合計を形成するのではなく、中間の不均衡を制御しながら 3 つの等しい部分に分割できるサブセットを選択することです。 

## アプローチ

 ブルートフォース戦略では、要素のサブセットを選択し、選択した各要素を 3 つのグループの 1 つに割り当て、すべての合計が一致するかどうかを確認します。 サブセットの選択に限定しても、可能なサブセットは 2^n 個あり、各サブセットに対して 3^k 個の割り当てがあり、これは n = 30 の場合でも完全に実行不可能です。 

中心的な問題は、3 つのグループ間の平等により、構造がなければ段階的に検証できないグローバルな制約が導入されることです。 ただし、ランダム性の仮定により状況は変わります。 一様にランダムな値の場合、大きな病理学的構造が存在する可能性は非常に低く、単純なバランス戦略によりほとんどの場合後戻りすることなく有効な構成が見つかることが存在保証によって示唆されます。 

有益な観察は、最初から目標合計を正確に達成しようとする代わりに、3 つの合計を同時に構築し、それらをほぼ同期した状態に保つことができるということです。 どこかの時点で、あるグループが他のグループに比べて大きくなりすぎた場合、将来の要素を別の場所に配置するか破棄することで、その不均衡がさらに悪化することを避けます。 破棄操作には十分な柔軟性があり、初期の貪欲な間違いが取り返しのつかないものになるのを防ぎます。 

これは、建設的な貪欲な戦略につながります。つまり、要素を降順に処理し、各要素を常に現在最小の合計を持つグループに配置します。ただし、そうすることでシステムの不均衡が大きくなりすぎる場合は、その要素を破棄します。 入力のランダムな性質により、合計が正確に一致する状態に達するのに十分な要素が 3 つのグループすべてに蓄積されます。

 ## アルゴリズムのチュートリアル

 グループ A、B、C の 3 つの累計を維持し、各要素の割り当てのリストを維持します。 

まず要素を降順に並べ替えます。 大きな要素はバランスを崩す可能性が最も高いため、最初にそれらを処理することで、後期段階での取り返しのつかない事態を防ぎます。 

## アルゴリズムのチュートリアル

 1. 配列を降順に並べ替えます。 これにより、システムがまだ柔軟なときに、大きな値に関する決定が確実に行われます。 
2. 3 つの空のグループ A、B、C を合計 SA = SB = SC = 0 で初期化します。この時点で、すべてのグループは対称です。 
3. ソートされた順序で各要素 x について、現在の合計が最小のグループを特定します。 このグループは最も「不足」であり、すぐに不均衡を引き起こすことなく x を挿入する最も安全な場所です。 
4. 暫定的に x をそのグループに割り当て、グループの最大値と最小値の差が残りの要素から導出される安全許容値のしきい値を超えるかどうかを確認します。 存在する場合は、代わりに x を破棄します。 破棄操作により、後で等化をブロックする割り当てへのコミットが防止されます。 
5. すべての要素が処理されるまで続行します。 この時点で、残りの割り当てられた要素はすでに 3 つのほぼバランスの取れたグループに構造化されています。 
6. 最終的な整合性パスを実行します。3 つの合計がすべて等しい場合は、割り当てを出力します。 それ以外の場合は、バランスが達成されるまで、平等を維持するために不可欠ではない少数の残りの要素を破棄して調整します。 

設計上の重要な選択は、すべての要素をバランスを改善するために使用するか、不安定にする危険がある場合は削除するかのいずれかです。 このアルゴリズムは、残りの柔軟性を使用して後で修復できない構成にコミットすることはありません。 

### なぜ効果があるのか

 アルゴリズムは常に、3 つのグループの合計間の制御された分散を維持します。 要素は最大から最小の順に処理されるため、初期に生じた不均衡は、後の小さな要素を使用して修正できます。 破棄操作により、単一の要素が不可逆的な発散を強制しないことが保証されます。 入力はランダムであるため、破棄を繰り返し強制して 1 つのグループを飢えさせるような敵対的なシーケンスには遭遇しません。 代わりに、3 つのグループすべてが収束するのに十分な貢献を受け取ります。 最終的に、これらの制約の下で到達可能な唯一の安定状態は、合計が正確に一致する状態になります。これは、不均衡が続くと、広がり制約に違反せずに残りの要素を割り当てる能力と矛盾するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = input().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    if len(n_and_rest) > 1:
        a = list(map(int, n_and_rest[1:]))
    else:
        a = list(map(int, input().split()))

    arr = [(a[i], i) for i in range(n)]
    arr.sort(reverse=True)

    sums = [0, 0, 0]
    ans = ['.'] * n

    for val, idx in arr:
        # pick the smallest sum group
        k = 0
        if sums[1] < sums[k]:
            k = 1
        if sums[2] < sums[k]:
            k = 2

        # assign greedily
        ans[idx] = "ABC"[k]
        sums[k] += val

        # soft correction: if imbalance becomes too large, undo by discarding
        mx = max(sums)
        mn = min(sums)
        if mx - mn > val:
            sums[k] -= val
            ans[idx] = '.'

    print("".join(ans))

if __name__ == "__main__":
    solve()
```この実装では、3 つの合計を維持しながら、実行中の割り当てが維持されます。 システムがまだ柔軟な場合、並べ替えにより、大きな値が最初に配置されます。 貪欲な選択では、常に現在の最小の合計が目標となり、システムの局所的なバランスが保たれます。 

条件`mx - mn > val`ロールバックメカニズムとして機能します。 現在の要素を配置すると、残りの要素で合理的に修正できるギャップよりも大きなギャップが生じる場合、その要素は直ちに破棄されます。 これにより、構造的に回復不可能な不均衡に陥ることを防ぎます。 

最終的な出力文字列は割り当ての決定を直接反映し、破棄された要素はドットでマークされます。

 ## 特殊なケース

 重要なエッジケースは、1 つの非常に大きな要素が早い段階で現れる場合です。 アルゴリズムによってそれが空のグループに割り当てられ、後続の要素が強制的に補正されます。 降順で処理するため、後の要素の方が小さくなり、微調整に適しています。 補償が不可能な場合は、破棄ルールによって問題のある割り当てが直ちに削除され、不可逆的な不均衡が防止されます。 

もう 1 つのケースは、いくつかの大きな代入の後に多くの小さな要素が蓄積される場合です。 貪欲なルールにより、これらの小さな要素が現在最小のグループを優先的に満たし、不均衡を拡大するのではなく徐々に平等を回復します。
