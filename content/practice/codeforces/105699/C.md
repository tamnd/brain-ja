 ## 解決策
 ## 問題の理解

 まずはコレクションから始めます$n$シングルトン セット、設定される場所$i$最初は要素のみが含まれます$i$。 この後、加工していきます$q$操作。 各操作には、既存の 2 つのセットが必要です$X_i$そして$Y_i$、それらの 2 つのセットを正確に結合した要素を持つ新しいセットを形成し、それに新しいインデックスを割り当てます。$n + i$。 各操作で出力を求められるのは、正確な値ではなく、この新しく作成されたセットのおおよそのサイズだけです。 

重要な制約は、正確な正しさは必要ないということです。 結合の実際のサイズが$A$、任意の整数$B$そのような$0.5A \le B \le 2A$受け入れられます。 これにより、問題は正確なセットの維持から近似的なカーディナリティの追跡へと即座に移行します。 

隠れた重要な問題は、結合を繰り返すことでセットが重なり合う可能性があるため、未知で正確に計算するにはコストがかかる交差を何らかの方法で考慮しない限り、サイズを合計するという単純な考えが間違っていることです。 

境界は構造的に重要です。 まで$5 \cdot 10^5$操作では、セットの共用体を明示的に再計算したり、セットごとに完全な要素を保存したりすることは不可能です。 明示的なビットセットを維持する場合でも、単純に行うとメモリと時間の両方で大きすぎます。 私たちは集合を要約に圧縮する表現を強いられています。 

オーバーラップが極端な場合、微妙なエッジケースが発生します。 2 つのセットが同一である場合、それらの和集合のサイズは 2 倍になるはずはありませんが、単純合計では 2 倍になります。 もう 1 つの問題のあるケースは連鎖の繰り返しで、各ステップでの近似が不十分であると誤差が蓄積します。 

たとえば、セット 1 = {1,2,3} およびセット 2 = {2,3,4} の場合、和集合は {1,2,3,4}、サイズ 4 になります。単純合計では 3 + 3 = 6 が得られますが、これはすでに許容範囲外です。$2 \cdot 4 = 8$問題はありませんが、連鎖を繰り返すと歪みが予期せず増幅される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのセットをハッシュ セットまたはソートされたコンテナとして明示的に維持します。 クエリごとに、2 つの参照セットの和集合を計算し、すべての要素を新しい構造に挿入し、そのサイズをカウントします。 これは定義を正確にモデル化しているため、これは正しいです。 ただし、最悪の場合、各セットのサイズが大きくなる可能性があります。$O(n)$、そして、あります$O(q)$労働組合。 各結合には、マージされるセットのサイズに応じて直線的な時間がかかる可能性があり、全体の複雑さが次のようになります。$O(nq)$、これは実現不可能です$5 \cdot 10^5$。 

重要な観察は、正確な構造は決して要求されず、定数因数内の基数の近似値のみが要求されるということです。 これは、要素をまったく追跡するのではなく、和集合の下で副加法または最大支配量とほぼ同様に動作する各セット サイズの数値推定を維持する必要があることを強く示唆しています。 

重要なトリックは、共用体演算の場合、実際のサイズは次の条件を満たすことを理解することです。$$|A \cup B| = |A| + |B| - |A \cap B|.$$交差を計算することはできませんが、正確に交差する必要もありません。 乗算スラックを受け入れる場合、安定したヒューリスティックは、無制限に増加する方法で非常に類似した大きさを二重にカウントしないようにすることで繰り返しのインフレを防止しながら、和集合をおおよその加算として扱うことです。 

これを実現するきれいな方法は、各セット サイズを対数スケールで表し、増加を制御した最大のようなルールを使用してマージし、各マージが真の和集合の定数係数内の値を返すようにすることです。 受け入れ条件では係数 2 が許可されているため、ランダム化または丸められた対数近似で十分です。 

特に効果的な決定論的戦略の 1 つは、各セット サイズを最も近い 2 の累乗バケットに丸めた整数として維持することです。 2 つのセットをマージする場合、結合は合計を超えることができず、常に少なくとも大きいセットになるため、結合サイズは最大バケット サイズに小さな定数係数を掛けたものとして推定されます。 これにより、バケットが適切に定義されている場合、出力は係数 2 以内に収まります。 

実際の要素ではなく、保存されたサイズのみを比較および結合するため、各操作は O(1) に削減されます。

 ## アルゴリズムのチュートリアル

 配列を維持します`sz`どこ`sz[i]`セットのおおよそのサイズを保存します$i$、乗算精度を維持する粗い表現を使用します。 

1. 各セットの初期化$i$と`sz[i] = 1`, すべての初期セットには要素が 1 つだけ含まれているためです。 これは正確であり、後のすべての近似の基礎となります。 
2. クエリごとに$(X_i, Y_i)$、2 つの候補サイズを計算します$a = sz[X_i]$そして$b = sz[Y_i]$。 これらは、セットに関して入手可能な唯一の情報です。 
3. 制御された組み合わせとして出力サイズを計算します。$a$そして$b$、具体的には以下に比例する値を取ります。$\max(a, b)$限定されたインフレ係数を使用します。 その理由は、和集合はより大きなセットよりも小さくすることはできず、それらの合計を超えることはできないためです。$\max(a,b) \le |A \cup B| \le a + b \le 2\max(a,b)$。 
4. この計算された値を次の値に割り当てます。`sz[n + i]`新しいセットは将来のクエリの一部になるためです。 
5. 各クエリの値を直ちに出力し、インタラクション制約の要求に応じて 50 個の出力ごとにフラッシュします。 

重要な設計上の決定は、正確な追加動作を決して保持しようとしないことです。 代わりに、保存されたすべての値が定数係数内の実際のサイズを追跡する厳密な乗法エンベロープを保存します。 

### なぜ効果があるのか

 すべてのステップで、それぞれが保存されます`sz[i]`は、真のセット サイズの定数乗算範囲内に収まることが保証されます。 共用体を形成すると、真の値は 2 つのオペランドの最大値とその合計の間に制限されます。 両方のオペランドはすでに近似していますが、定数係数内で一貫しているため、和集合をそれらの最大値に比例する関数に置き換えることで、その不変条件が保持されます。 各ステップでスケールが制限された範囲に再正規化されるため、誤差は深さ全体にわたって乗算的に増加しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    sz = [0] * (n + q + 5)
    for i in range(1, n + 1):
        sz[i] = 1

    out = []
    for i in range(1, q + 1):
        x, y = map(int, input().split())
        
        a = sz[x]
        b = sz[y]

        # safe multiplicative approximation within factor 2
        # union is between max(a,b) and a+b <= 2*max(a,b)
        res = max(a, b) * 2

        sz[n + i] = res
        out.append(str(res))

        if i % 50 == 0:
            sys.stdout.write("\n".join(out) + "\n")
            sys.stdout.flush()
            out = []

    if out:
        sys.stdout.write("\n".join(out) + "\n")
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、おおよそのサイズの配列のみが保持されます。 新しいセットはそれぞれ、前の 2 つの値からのみ導出されるため、実際の要素は保存されません。 インタラクターは 50 個の固定バッチでクエリを処理し、出力が遅延すると同期が中断される可能性があるため、フラッシュ ロジックは不可欠です。 

重要な微妙な点は、次の選択です。`2 * max(a, b)`。 これは、重複に関する情報を必要とせずに正確性を保証する最も厳密な均一境界です。 使用する`a + b`これも機能しますが、連鎖を考慮すると許容係数を超える可能性があるため不要です。 最大ベースの境界により、値が安定します。 

## 実用的な例

 小さなシーケンスを考えてみましょう。$n = 4$。 

クエリを処理します:$(1,2), (2,3), (5,6)$ここで、インデックスは以前に作成されたセットを参照します。 

### トレース

 | ステップ | X | や | sz[X] | sz[Y] | 計算された解像度 | 新しいセット |

 | 1 | 1 | 2 | 1 | 1 | 2 | 5 |

 最初の 2 つの操作の後、おおよそのサイズ 2 の 2 つのセットが作成されました。3 番目の操作ではそれらがマージされ、4 が生成されます。これは、サイズが 2 倍になる、互いに素なシングルトンの結合の予想される増加パターンと一致します。 

トレースは、同様のサイズのセットを繰り返しマージしても表現の一貫性が保たれていることを示しています。

 ## 特殊なケース

 重要なエッジケースは、同じセットとそれ自体のマージが繰り返されることです。 のような入力の場合`1 1`クエリ付き`(1,1)`、正しいセット サイズは依然として 1 です。アルゴリズムの出力は次のとおりです。`2`、これは許容範囲内です。$0.5 \cdot 1 \le 2 \le 2 \cdot 1$。 これは、近似が意図的に粗いものの、制約の下では有効であることを示しています。 

もう 1 つのケースは、インデックスが新しく作成されたセットを参照する連鎖マージです。 値が指数関数的に増加する場合でも、各ステップは 2 つの保存された近似値にのみ依存します。 各値は常に実際のサイズの一定係数内にあるため、次のマージでは乗算エンベロープが保存され、許容しきい値を超えるエラーの爆発が防止されます。
