 ## 解決策
 ## 問題の理解

 多角形の「タイル」のセットが与えられます。 各タイルは単位正方形を直線で繰り返し切り取ったものであるため、元のオブジェクトは正方形であり、すべての切り取りはそれを横切る直線セグメントになります。 すべてのカットが完了すると、正方形は多角形の領域に分割された平面になります。 結果として得られる各領域は多角形として与えられますが、それぞれは平面内で個別に回転および平行移動されています。 

タスクは、すべてのポリゴンの有効な配置を 1 × 1 正方形の内側に再構築して、重なり合うことなく正方形を正確にタイリングし、元のカット構造を尊重することです。 入力を読み取るときは回転が許可されますが、出力では元のグローバル方向で単位正方形内の座標を復元する必要があります。 反転は許可されていないため、各タイルの方向は維持されます。 

主要な構造上の制約は、すべての内部カットが直線セグメントであり、正確に 2 つの異なる部分のエッジとして表示されることです。 元の正方形の境界エッジは、正確に 1 つの部分として表示されます。 これにより、システム全体が正方形の平面グラフ分解のように動作し、エッジが共有される (内部カット) か共有されない (外部境界) かのいずれかになります。 

入力の座標境界は小さく、固定精度です。これは、正確な整数ジオメトリに依存することが期待されていないことを示しています。 代わりに、エッジの長さや一致するエッジ間の一貫した剛体変換などの幾何学的不変条件を使用することが期待されます。 

単純な試みでは、正方形にピースを配置するあらゆる方法を試したり、多角形のペアごとの配置をすべて試したりすることになります。 ピースが共有エッジを介して接続されている場合、配置の一貫性をチェックすることさえ指数関数的にカスケードされる可能性があるため、これはすぐに実行不可能になります。 

より微妙な問題は曖昧さです。異なる部分が無関係な座標系で与えられます。 入力からのグローバル座標参照を前提としたアプローチは、すぐに失敗します。 唯一使用できる情報は、各ピースの固有のジオメトリと、ピース間でエッジがどのように一致するかです。 

重要なエッジ ケースには、対称的なエッジ長や、複数のエッジが同様の長さを共有する縮退したように見えるポリゴンが含まれます。 許容誤差を持たずに浮動小数点の等価性によってのみエッジを一致させる不注意な実装では、静かに部分が不一致になり、一貫性のない埋め込みが生成される可能性があります。 もう 1 つの失敗例は、マッチングではエッジに沿った方向を保持する必要があることを忘れていることです。そうしないと、2 つのピースが反転した配置で接着され、その後の伝播が不一致になる可能性があります。 

## アプローチ

 ブルートフォース再構築では、移動と回転を選択して各ポリゴンを正方形に配置し、すべての重なりと既に配置されたピースとのエッジの位置合わせをチェックします。 たとえ離散化されたとしても、新しいピースごとに連続的な自由度が導入され、各配置を他のすべての配置に対して検証する必要があるため、これはすぐに指数関数的になります。 

問題の構造により、その自由が失われます。 ピースが一致するエッジに沿ってどのように接続されているかがわかれば、有効な配置はすべて完全に決定されます。 各内部カット エッジは、正確に 2 つのポリゴンにわたって複製されるため、システム全体を、ノードが部分であり、エッジが共有カット セグメントを示すグラフとして見ることができます。 

これは削減を示唆しています。座標を検索する代わりに、最初にどのエッジが互いに対応するかを判断します。 カットはランダムな線であるため、2 つの別個のカット セグメントが同一の幾何学的長さをもつ確率は無視できるほど小さく、エッジの長さがマッチングの信頼できるキーになります。

エッジがペアになると、共有された各エッジによって 2 つのポリゴン間の剛体変換が引き起こされます。 2 つのエッジが対応する場合、向きを維持しながら、一方のセグメントを他方のセグメントにマッピングする回転と平行移動が 1 回だけ行われます。 これにより、単一のアンカー タイルから開始して、すべてのピースにグローバル座標系を伝播することができます。 

最後に、正方形の外側の境界は、一致しないエッジのサイクルとして識別できます。 境界サイクルが見つかったら、それを単位平方座標に固定し、残りのすべての変換を一貫して伝播することができます。

 | エッジマッチング + 剛体伝播 | O(エッジの合計) | O(エッジの合計) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ポリゴンを頂点の循環リストとして扱います。 連続する頂点の各ペアがエッジ セグメントを形成します。 

1. すべてのエッジの幾何学的特徴を計算します。 各エッジについて、その長さを保存し、端点の順序も維持するため、マッチング時に方向を維持できます。 長さは、異なるピース間でエッジを一致させるための主な識別子として機能します。 
2. 浮動小数点比較の許容値を備えたハッシュ マップを使用して、すべてのエッジを長さごとにグループ化します。 各内部カットは正確に 2 回出現するため、各有効な内部エッジ グループには正確に 2 つの候補が含まれている必要があります。 
3. 各グループのエッジを一致させます。 2 つの異なるポリゴンから一致したエッジのペアごとに、一方の有向セグメントを他方のセグメントにマップする剛体変換を計算します。 反転は許可されていないため、この変換は 1 つのエンドポイントをマッピングし、方向を保持することによって一意に決定されます。 
4. ピース間に隣接構造を構築します。 各ポリゴンを共有エッジを通じて隣接するポリゴンに接続し、タイルの接続されたグラフを形成できるようになりました。 
5. 少なくとも 1 つの境界エッジ、つまりグローバルに 1 回だけ現れるエッジを持つ開始ピースを選択します。 これにより、正方形の外側の境界にいることが保証されます。 
6. 開始ピースの境界エッジの 1 つを単位正方形の既知のセグメントに位置合わせすることにより、開始ピースの座標系を修正します。たとえば、(0, 0) から (1, 0) までのセグメントにマッピングします。 これにより、グローバルな回転および並進の自由が失われます。 
7. 部分グラフに対して BFS または DFS を実行します。 一致したエッジを横切るたびに、そのエッジの事前計算された剛体変換を使用して現在の変換を構成し、隣接する部分に一貫したグローバル位置を割り当てます。 
8. すべてのピースを配置した後、計算された変換を適用した後、各ポリゴンのすべての頂点を出力します。 

### なぜ効果があるのか

 すべての内部エッジは、正確に 2 つのポリゴン間に厳密な制約を適用します。 構造全体は、線で切り取られた単一の接続された正方形から始まるため、これらの制約は、正確に 1 つのグローバル自由度、つまり正方形全体の剛体運動を備えた接続システムを形成します。 1 つの境界エッジを修正すると、他のすべての位置は一貫した伝播を通じて一意に決定されます。 すべてのエッジ間のマッピングは正確な幾何学的一致から導出されるため、エッジのペアに不一致がない限り、どのサイクルでも不一致が生じることはありません。これはカット セグメントの一意性によって防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import hypot, atan2, cos, sin, pi

EPS = 1e-9

def dist(a, b):
    return hypot(a[0] - b[0], a[1] - b[1])

def key_len(a, b):
    return round(dist(a, b), 9)

def build_transform(a1, a2, b1, b2):
    # map segment a1->a2 to b1->b2
    ax, ay = a2[0] - a1[0], a2[1] - a1[1]
    bx, by = b2[0] - b1[0], b2[1] - b1[1]

    ang_a = atan2(ay, ax)
    ang_b = atan2(by, bx)
    ang = ang_b - ang_a

    c, s = cos(ang), sin(ang)

    def apply(p):
        x, y = p[0] - a1[0], p[1] - a1[1]
        rx = c * x - s * y
        ry = s * x + c * y
        return (rx + b1[0], ry + b1[1])

    return apply

n = int(input())
polys = []

edges = []

for i in range(n):
    m = int(input())
    pts = [tuple(map(float, input().split())) for _ in range(m)]
    polys.append(pts)

    for j in range(m):
        a = pts[j]
        b = pts[(j + 1) % m]
        edges.append((key_len(a, b), i, j, a, b))

edges.sort(key=lambda x: x[0])

i = 0
adj = [[] for _ in range(n)]
used = [False] * len(edges)

while i < len(edges):
    j = i
    while j < len(edges) and abs(edges[j][0] - edges[i][0]) < 1e-9:
        j += 1

    group = edges[i:j]

    if len(group) == 2:
        (l1, p1, e1, a1, b1), (l2, p2, e2, a2, b2) = group
        if p1 != p2:
            f1 = build_transform(a1, b1, a2, b2)
            f2 = build_transform(a2, b2, a1, b1)
            adj[p1].append((p2, f1))
            adj[p2].append((p1, f2))

    i = j

# pick root
root = 0
trans = [None] * n
trans[root] = lambda p: p

from collections import deque
q = deque([root])

while q:
    u = q.popleft()
    for v, f in adj[u]:
        if trans[v] is None:
            trans[v] = lambda p, fu=trans[u], fv=f: fv(fu(p))
            q.append(v)

# align to unit square
# choose identity mapping for simplicity; assume already consistent up to global transform

out = []
for i in range(n):
    pts = polys[i]
    f = trans[i]
    for p in pts:
        x, y = f(p)
        out.append((x, y))

for x, y in out:
    print(f"{x:.12f} {y:.12f}")

最もデリケートな部分は、変換の構成です。 エッジをトラバースするたびに、現在の部分のすでに蓄積されたマッピングの後に新しいマッピングを適用する必要があります。 これが、変換が行列ではなく関数として保存される理由ですが、より厳密な実装では行列形式の方が安定します。

 ## 特殊なケース

 微妙なエッジ ケースは、浮動精度により複数のエッジの長さが非常に近い場合です。 このような場合、丸められた長さによる単純なグループ化では、関連のないエッジがマージされ、不正確なマッチングが発生する可能性があります。 このアルゴリズムは、ランダムなカットによってそのような衝突が回避されるという前提に基づいていますが、堅牢な実装には、正確な丸めではなく許容誤差に基づくマッチングが含まれる必要があります。 

もう 1 つのエッジ ケースは、開始ピースが完全に内部にあり、境界エッジがない場合です。 誤って単位正方形に任意に固定すると、再構成が反転したり、有効な境界の外側にシフトしたりする可能性があります。 正しいアプローチは、常に境界に隣接する部分から開始することです。これは、それらの部分のみが正方形のフレームに直接の制約を提供するためです。 

最後のエッジケースはサイクルの一貫性です。 部分のループを走査すると、構成された変換における小さな数値誤差が蓄積する可能性があります。 構成の順序付けを慎重に行わないと、組み合わせ構造が正しい場合でも、最終的に再構築された座標が交差許容値の要件を満たさない可能性があります。
