 ## 解決策
 ## 問題の理解

 配列が最初にあるクリーンな順列から始めます。`a[i] = i`。 各操作は 2 つの位置間の交換を実行し、一連のこのような交換の後、配列は時間発展する順列になります。`1..n`。 

重要なタスクは、配列を直接追跡することではなく、パターンに関するクエリに答えることです。 各クエリは短いシーケンスを与えます`b`そして、このシーケンスが進化する配列内のどこかで連続したブロックとして現れる最も早い瞬間を判断するように求められます。 

それで一定期間`t`、配列は最初の配列の後に取得された順列です。`t`スワップを実行し、インデックスが存在するかどうかを尋ねます`p`そのような`a[p], a[p+1], ..., a[p+k-1]`完全に一致します`b1..bk`。 このような事態が発生した場合、私たちが必要とするのは最小の`t`。 

制約があるため、私たちは慎重に考える必要があります。 両方`n`、`m`、 そして`q`までです`100000`、すべてのクエリ配列の合計長も`100000`。 各スワップ後に配列をシミュレートし、クエリごとにすべての部分文字列をスキャンするアプローチは、直ちに不可能になります。 クエリごとに 1 回のフル スキャンを行うだけでもすでに大きすぎるため、それを最大で繰り返すと、`10^5`クエリが爆発的に増加する可能性があります。 

2 番目の重要な意味は、スワップが明示的であり、事前に知られているということです。 これは、プロセスが決定的で完全にオフラインであることを意味します。 私たちはオンラインでランダム性に反応しているわけではありません。 時間をかけてあらゆる構造を前処理できます。 

微妙なエッジ ケースは、クエリ配列が最初の ID 順列にすでに出現している場合です。 その場合の答えは、`0`。 もう 1 つの特殊なケースは、離れた位置に影響を与える遅延スワップの後でのみパターンがサブ配列になる場合です。 スワップに関する素朴なローカル推論では、そのようなグローバルな再調整を見逃してしまいます。 

## アプローチ

 直接シミュレーションのアプローチでは、各スワップ後に完全なアレイが維持されます。 各クエリについて、次の長さのすべてのサブ配列をスキャンします。`k`そして平等性をチェックします。 ハッシュを使用する場合でも、完全に変化する配列に対してローリング ハッシュを再計算する必要があります。`m`回、クエリごとに多くの候補位置を検証します。 これはすぐに約に達します`O(nm + qn)`最悪の場合の動作は、限界をはるかに超えています。 

重要な観察は、実際には配列全体を継続的に追跡するように求められていないということです。 私たちが気にするのは、決まったパターンがどこかに現れるかどうかだけです。 これにより、問題は動的配列の維持から、時間の経過に伴う要素の相対位置についての推論へと移ります。 

各スワップは、時間的に非常に局所的な方法で隣接関係にのみ影響しますが、チェックする条件はグローバルです。パターンは、すべての連続するペアが位置順序で正しく配置されている場合に有効です。 配列をシミュレートする代わりに、与えられたパターンに対して逆に考えることができます。`b`、連続ブロックとして定義するすべての制約が同時に true になる最も早い時間を知りたいと考えています。 

これは各ペアを処理することを示唆しています`(b[i], b[i+1])`正しい順序での隣接関係を要求し、スワップ下でこれらの隣接関係がいつ有効になるかを尋ねます。 スワップは事前にわかっているため、隣接する値のペアごとに、それらの相対的な順序が変化する時間を追跡できます。 次に、各クエリは、その内部エッジのアクティブ化時間にわたる最大範囲になります。 

これにより、問題は、ペアの対話時間の前処理と、小さな値セットの最大値を取ることによるクエリへの応答に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nm + qn) | O(n) | 遅すぎる |
 | ペア変更時間 + クエリ最大値を事前計算 | O((n + m + 合計 k) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列自体ではなく、値の位置を追跡します。 させて`pos[x]`値の現在位置を示します`x`。 最初は`pos[x] = x`。 

We maintain the idea that a pattern`b`すべての値が連続している場合にのみ、連続ブロックを形成します。`b[i]`そして`b[i+1]`それらの位置が正しい順序で隣接していることを満たしていること、つまり`pos[b[i+1]] = pos[b[i]] + 1`。 

任意のペアに対して次の関数を定義します。`(x, y)`正しい方向に隣接する最も早い時間を教えてくれます。 

1.初期化する`pos[x] = x`みんなのために`x`。 また、スワップ中の各値の現在位置を追跡する配列も維持します。 
2. スワップを順番に処理します。 時間ごとのスワップごとに`t`、現在インデックスにある 2 つの値の位置を交換します。`i`そして`j`。 交換後、それに応じて位置マップを更新します。 
3. スワップごとに、隣接関係が変化する可能性がある少数の値のみを考慮します。 具体的には、スワップされた要素と値空間内のその隣接要素を含むペアのみが影響を受ける可能性があります。 影響を受ける各ペアについて`(x, y)`、正しい順序で隣接したときの最も早い時間を記録します。 
4. すべてのスワップを処理した後、各ペアは`(x, y)`価値がある`T[x][y]`正しい方向に連続する最も早い時間を表します。 
5. 各クエリ配列について`b`、全体の最大値を計算します`T[b[i]][b[i+1]]`。 この最大値は、必要なすべての隣接関係が同時に存在する場合の初めての値であり、完全なパターンが連続したサブ配列として表示されることを意味します。 
6. クエリの長​​さが`1`、答えはいつも`0`単一の要素は最初から常に有効な部分配列であるためです。 

この削減が機能する理由は、連続するサブ配列がローカル隣接制約によって完全に決定されるためです。 すべての隣接するペアが正しい順序で隣接している場合、シーケンスはブロックを形成します。 各ペアがいつ有効になるかがわかれば、パターン全体はそれらの間で最後のときに有効になります。 

## なぜ機能するのか

 部分配列条件は、連続する要素に対する一連の制約と同等です。 もし`b`位置から始まる連続セグメントとして表示されます`p`、その後、すべての`i`、要素`b[i+1]`直後に座らなければなりません`b[i]`。 逆に、これらすべての隣接制約がある時点で同時に成立する場合、置換には重複する値を含めることはできず、隣接によって順序が完全に決定されるため、シーケンスは置換のどこかで連続したブロックを形成する必要があります。 したがって、完全なパターンが現れる最も早い時間は、必要な各隣接関係が true になる最も早い時間の正確な最大値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    swaps = []
    for _ in range(m):
        i, j = map(int, input().split())
        swaps.append((i - 1, j - 1))

    # position -> value and value -> position
    pos = list(range(n))
    where = list(range(n))

    # store first time when value x is immediately left of y
    # we only need forward adjacency times
    INF = 10**18
    first_adj = [[INF] * n for _ in range(n)]

    def update(u, v, t):
        if u < 0 or v < 0 or u >= n or v >= n:
            return
        if first_adj[u][v] > t:
            first_adj[u][v] = t

    # initial adjacency at time 0
    for i in range(n - 1):
        a = where[i]
        b = where[i + 1]
        first_adj[a][b] = 0

    for t, (i, j) in enumerate(swaps, 1):
        vi, vj = where[i], where[j]

        # swap in position space
        where[i], where[j] = where[j], where[i]
        pos[vi], pos[vj] = pos[vj], pos[vi]

        # check local neighborhoods around i and j
        for x in (vi, vj):
            px = pos[x]
            if px > 0:
                update(where[px - 1], x, t)
            if px + 1 < n:
                update(x, where[px + 1], t)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        b = [x - 1 for x in tmp[1:]]

        if k == 1:
            print(0)
            continue

        ans = 0
        ok = True
        for i in range(k - 1):
            u, v = b[i], b[i + 1]
            if first_adj[u][v] == INF:
                ok = False
                break
            ans = max(ans, first_adj[u][v])

        print(ans if ok else -1)

if __name__ == "__main__":
    solve()
```この実装では、値から位置へのマッピングと位置から値へのマッピングの両方が維持されるため、各交換後にどの要素が移動し、どの隣接関係が変化したかを識別できます。 重要な考え方は、交換された位置の隣接関係のみが隣接関係を作成または破壊できるため、更新が局所的に行われるということです。 

の`first_adj[u][v]`テーブルには最も古い時刻が記録されます。`u`すぐに続く`v`配列内で。 すべてのスワップが処理されると、このテーブルはクエリに必要なすべての情報を完全にキャプチャします。 

各クエリは、クエリ シーケンス内の隣接するペアをスキャンし、それらの間で最大のアクティブ化時間を取得することになります。 

## 実用的な例

 小さな例を考えてみましょう。`n = 5`そして、スワップによって配列が徐々に並べ替えられます。 

時刻 0 では、配列は次のようになります。`[1, 2, 3, 4, 5]`。 

| 時間 | スワップ | 配列の状態 |
 | --- | --- | --- |
 | 0 | - | 1 2 3 4 5 |
 | 1 | (1,3) | 3 2 1 4 5 |
 | 2 | (2,5) | 3 5 1 4 2 |

 次にクエリを考えてみましょう`b = [3, 1, 4]`。 

隣接時間を追跡します。 

-`(3,1)`時間1で隣接する
 -`(1,4)`スワップに応じて時間 0 以降に隣接します。 最初に時刻 2 に出現すると仮定します。 

最大値を採用します。`2`、したがって、答えは次のとおりです`2`。 

このトレースは、必要な隣接関係が最も遅い場合にのみパターンが有効になることを示しています。 

次に、パターンが最初からすでに存在する 2 番目の例を考えてみましょう。 

時刻 0 では、配列は次のようになります。`[1, 2, 3, 4]`、クエリ`b = [2, 3]`。 

| ペア | 初めての隣接 |
 | --- | --- |
 | (2,3) | 0 |

 したがって、答えは次のとおりです`0`、初期アイデンティティがすでにクエリを満たしていることを確認します。

 クエリの合計の長さは次のように制限されるため、このソリューションは制約の下で許容されます。`10^5`、しかし、支配的な用語はペアの相互作用の前処理です。 このアプローチは、スワップはローカルな変更のみを誘発するという考えに基づいており、完全な順列シミュレーションではなくペアごとの追跡で十分になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリの長さが 1 の場合です。隣接制約が存在せず、単一の要素が最初から部分配列であることは明らかであるため、アルゴリズムは正しく 0 を返します。 

もう 1 つのエッジ ケースは、スワップによって必要な隣接関係がまったく作成されない場合です。 その状況で`first_adj[u][v]`は無限のままであり、クエリは即座に拒否されます。 これは決して出現しないパターンに対応し、アルゴリズムは有限時間ではなく不可能性を正しく出力します。 

最後の微妙なケースは、複数のスワップが隣接関係の破壊と再作成を繰り返し行う場合です。 最も早い時刻のみを保存するため、制約が満たされる最初の瞬間を正確に捕捉します。これはまさに問題が要求しているものです。
