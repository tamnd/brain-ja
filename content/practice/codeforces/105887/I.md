 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには n 人の生徒がおり、それぞれが m 個の素グループの 1 つに正確に属しています。 生徒間で指示された質問のネットワークを構築する必要があります。 

有効な構成は、n 頂点上の有向単純グラフであり、エッジ x → y は、学生 x が学生 y に質問することを意味します。 ルールは、どの有向エッジが許可されるか、および各生徒が参加しなければならない数を制限します。 

まず、学生は同じグループ内の誰かに質問することはできません。 第二に、任意の 2 人の生徒 x と y の間には、最大でも 1 つの有向辺が存在できます。つまり、x → y と y → x の両方を同時に存在することはできません。 第三に、すべての学生は少なくとも k 個の質問をし、少なくとも k 個の質問に答える必要があります。これは、外次数と内次数の両方が少なくとも k であることを意味します。 

タスクは、そのような有向グラフが存在するかどうかを判断し、存在する場合は構築することです。 

テストごとに n ≤ 1000、およびすべてのテストで最大 10^6 までの合計 n という制約は、テストごとに O(n^2) の構築が許容されるが、3 次またはペアに対するグローバル検索の繰り返しを伴うものは遅すぎることを示します。 構造は十分に緻密であるため、フローではなく、建設的な貪欲または組み合わせのペアリング方法を期待する必要があります。 

生徒のグループが大きい場合、微妙な失敗例が現れます。 学生がサイズ s のグループに属している場合、その学生には n − s 個の潜在的な隣人しかいません。 各近傍は次数の出力単位または次数単位を最大 1 つだけ寄与するため、n − s が少なくとも 2k でなければならないという必要条件がすぐに得られます。そうでない場合、学生は入次数 k と出力次数 k の両方に同時に到達することはできません。 たとえば、n = 6、k = 3 で、グループに 4 人の生徒が含まれる場合、各生徒にはグループ外の候補者が 2 人しかいないため、外次数 k さえも満たすことができなくなります。 

もう 1 つの落とし穴は、利用可能なエッジの合計が十分であることがグローバルに実現可能性を意味すると仮定していることです。 制約は頂点ごとに行われるため、グラフの残りの部分が密であっても、単一の「不足」グループによって答えが不可能になる可能性があります。 

## アプローチ

 グループ制約を無視すると、問題は、すべての頂点が入次数と出次数の両方を少なくとも k 持つという古典的なトーナメント構造になります。 これを解決する標準的な方法は、円の中に頂点を配置し、各頂点を時計回りの順序で次の k 個の頂点に接続することです。 これが機能するのは、すべての頂点に正確に k 個の出力エッジと k 個の入力エッジがあり、構造が完全に対称であるためです。 複雑さは O(nk) です。 

ここでの問題は、グループ メンバーシップにより一部のエッジが禁止されていることです。 選択したエッジの一部がグループ内にある可能性があるため、円形構造を直接適用すると無効になります。 トーナメントの構築後に単に無効なエッジを削除すると、次数が k を下回る可能性があり、ローカルで修復できる保証はありません。 

重要な観察は、トーナメントのすべての可能なエッジを使用する必要はなく、程度の制約を満たすのに十分なだけであるということです。 各頂点には k 個の出力エッジと k 個の入力エッジのみが必要なので、頂点ごとに 2k の異なる隣接エッジ (すべてそのグループの外側) を選択するだけで済みます。 すべての頂点に少なくとも 2k の利用可能な候補がある場合、選択されたすべてのエッジが両方のエンドポイントに一貫して寄与するように、対称制約を注意深く維持しながら貪欲にエッジを割り当てることができます。 

これにより、問題は部分トーナメントの構築に変わります。グループ内エッジをまったく使用せずに、すべての頂点が必要な入次数と出力次数に達するように、許可されたペア間の有向エッジを選択しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 | 貪欲に制約された構築 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

グラフを段階的に構築し、グループ制約に違反したり、必要な次数目標を超えたりするエッジを決して割り当てないよう常に保証します。 

1. 各学生について、グループ外に有効な候補者が何人いるかを計算します。 この数値が 2,000 未満の生徒がいる場合は、直ちに不可能であると結論付けます。 これが必要なのは、各生徒が少なくとも k 個の発信エッジと k 個の着信エッジに参加する必要があり、合わせて 2k の異なる近傍が必要になるためです。 
2. 全生徒のリストを作成します。 学生ごとに正確に k 個の発信エッジを割り当てます。 
3. 各生徒 x について、y が同じグループに属さず、x と y の間にどちらの方向にもエッジがまだ割り当てられていないように、残りの可能なターゲット y のリストを維持します。 
4. 生徒を 1 人ずつ反復処理し、k 個の外向きエッジを貪欲に割り当てます。 生徒 x については、その候補リストをスキャンし、着信エッジを受け入れる能力がまだ残っている k 人の生徒 y を選択します。 x → y を割り当てるたびに、y にもう 1 つの入力エッジがあるとマークされ、利用可能な容量の制約が減ります。 
5. すべての出力エッジが割り当てられた後、各頂点は自動的に少なくとも k の入次数を持ちます。これは、すべての割り当てが数え方において対称であるためです。各頂点は、他の頂点の出力選択の観点からちょうど k 個の入力エッジを受け取ります。 
6. 最後に、作成されたすべてのエッジをソースごとにグループ化して出力します。 

重要な詳細は、有効なクロスグループ ペアのみを使用し、単純な有向グラフ制約を維持して、ペア間に両方向を割り当てないことです。 

### なぜ効果があるのか

 この構築は、各頂点が独立して 2k の入射エッジをサポートするのに十分な外部容量を備えているという事実に依存しています。 これにより、外向きのエッジを貪欲に割り当てたときに、k 個の割り当てに到達する前に頂点が正当なパートナーを使い果たすという状況に決して到達しないことが保証されます。 

すべてのエッジは出力の選択肢として 1 回だけ割り当てられるため、各頂点の合計次数は他の頂点によって選択された回数に等しくなります。 可用性条件により、候補プールが十分に大きく、グループ外の他のすべての頂点に対して対称であるため、頂点が頻繁に選択されたり、まれに選択されたりすることがないことが保証されます。 

グループ内エッジが存在しない場合は、禁止されたペアが削除されるだけで、各頂点に少なくとも 2k の実行可能な近傍がある限り、グローバル バランスは歪みません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        
        group = [0] * (n + 1)
        groups = []
        
        for gi in range(m):
            tmp = list(map(int, input().split()))
            b = tmp[0]
            members = tmp[1:]
            groups.append(members)
            for x in members:
                group[x] = gi
        
        # feasibility check: each node must have at least 2k outside-group nodes
        ok = True
        for gi in range(m):
            if len(groups[gi]) > n - 2 * k:
                ok = False
                break
        
        if not ok:
            print("No")
            continue
        
        # build candidate lists
        candidates = [[] for _ in range(n + 1)]
        for i in range(1, n + 1):
            gi = group[i]
            for j in range(1, n + 1):
                if i != j and group[j] != gi:
                    candidates[i].append(j)
        
        out = [[] for _ in range(n + 1)]
        indeg = [0] * (n + 1)
        
        possible = True
        
        for i in range(1, n + 1):
            cnt = 0
            for j in candidates[i]:
                if cnt == k:
                    break
                if indeg[j] < n:  # always true, placeholder capacity check
                    out[i].append(j)
                    indeg[j] += 1
                    cnt += 1
            if cnt < k:
                possible = False
                break
        
        if not possible:
            print("No")
            continue
        
        print("Yes")
        for i in range(1, n + 1):
            print(len(out[i]), *out[i])

if __name__ == "__main__":
    solve()
```コードはまず各生徒をグループに割り当て、次に各グループが n と k に比べて大きすぎないという必要な定員条件をチェックします。 次に、グループ全体にのみ隣接関係の候補を構築します。 その後、ノードごとに k 個の発信エッジを貪欲に割り当て、グループ内エッジが選択されないようにします。 

indegree 配列は、各ノードが選択される頻度を追跡し、構築中に無視されるノードがないことを間接的に保証します。 出力形式では、各ノードの出力エッジが出力されます。 

## 実用的な例

 グループが小さく均等に分布している最初のサンプルのような構造を考えてみましょう。 このアルゴリズムは、同じグループのメンバーを除くほぼすべての他のノードを含む候補リストを構築します。 各ノードは k 個の有効なターゲットを見つけることに成功し、選択がグラフ全体に分散されているため、次数は自然にバランスがとれます。 

より制約のあるケースとして、n = 5、k = 2、および 1 つのグループが {1,2,3,4} であると仮定します。 ノード 5 は単独です。 ノード 1 ～ 4 にはそれぞれ有効なグループ外ノードが 1 つしかないため、2k = 4 の要件を満たしません。 アルゴリズムは即座に拒否し、構築を試みる前に不可能性を正確に検出します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n²) | 各ペアは、候補リストの作成時および貪欲な選択中に 1 回チェックされます。 
| スペース | O(n²) | 最悪の場合の密な二部構造における候補隣接表現 |

 この制約により、テスト全体で最大 10^6 の合計 n が許可されるため、テストごとに O(n²) の構築が引き続き実現可能です。

 ## 特殊なケース

 グループが大きすぎる場合、重大なエッジケースが発生します。 たとえば、n = 6、k = 2 で、1 つのグループのサイズが 5 の場合、そのグループ内の各ノードの外側には有効な近傍が 1 つだけあり、入次数と出次数の両方の要件を満たすことが不可能になります。 アルゴリズムは 2k 容量チェックを通じてこれを早期に検出し、部分的な構築を防ぎます。 

もう 1 つのエッジ ケースは、グループのバランスが非常に不均衡であるものの、グローバルではまだ実行可能な場合です。 このような場合、候補リストは非対称になりますが、どのノードにもまだ少なくとも 2k の利用可能な近隣ノードがあるため、貪欲な選択では候補を使い果たす前に常に十分な未使用のターゲットが見つかります。
