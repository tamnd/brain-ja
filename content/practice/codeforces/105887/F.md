 ## 解決策
 ## 問題の理解

 各テストでは、次の 3 つの値間の単純な比較ゲームについて説明します。 アリスの強さ`a`、ボブの強さ`b`、そしてキャンディの強さ`c`。 出力は、これらの比較に優先順位ルールを適用することによって選択された文字列です。 

決定プロセスは順番に行われます。 まず、アリスはボブを直接倒すかどうかを判断しようとします。これは、`a > b`。 これが成り立つ場合、答えは次のように決まります。`"Win"`そしてそれ以上の推論は必要ありません。 

アリスがボブに直接勝てない場合、ゲームは間接的な解釈に切り替わります。つまり、キャンディがボブより強い場合、ボブは弱いと見なされます。`c > b`。 その場合、出力は次のようになります`"WIN"`。 

どちらの条件も当てはまらない場合、つまりアリスがボブに勝てず、キャンディもボブに勝てない場合、結果は次のようになります。`"nowin"`。 

入力は複数の独立したテスト ケースで構成されます。 各テスト ケースには 3 つの整数が含まれており、それぞれを同じロジックに基づいて評価する必要があります。 制約は十分に小さいため、各テストを一定時間で処理できます。 最大 100 のテスト ケースでも、O(T) または O(T log T) ソリューションで十分であり、前処理やデータ構造は必要ありません。 

主な微妙な点は、条件の順序が厳密であることです。 よくある間違いは、`c > b`前に`a > b`これは、アリスがすでに直接的に勝っているケースを誤って分類することになります。 もう 1 つのエッジ ケースは、特に値が等しい場合です。`a == b`または`c == b`、どちらもそれぞれの厳密な不等式の失敗として扱われなければなりません。 

たとえば、次のようなとき`a = 6, b = 6, c = 100`、アリスはボブに勝ちませんが、キャンディは勝ちます。そのため、正しい出力は次のようになります。`"WIN"`。 もし`a = 10, b = 5, c = 0`、正しい出力は次のとおりです。`"Win"`キャンディは関係ないのに。 もし`a = 5, b = 10, c = 7`、どちらの条件も当てはまらないため、出力は次のようになります。`"nowin"`。 

## アプローチ

 強引な解釈では、文字通り物語をモデル化しようとします。比較をシミュレートし、場合によっては登場人物間の推移的な「勝ち」について推論することさえあります。 あるノードが他のノードに勝った場合、または Candy を通じて間接的に強かった場合に、そのノードが勝利したと見なされる関係グラフを構築しようとするかもしれません。 ルールは 2 つの直接比較のみに分割されるため、このようなモデルは不要です。 たとえ実装されたとしても、このシミュレーションはテストごとに一定数のエッジを評価しますが、利点のない複雑さが生じます。 

重要な単純化は、ゲーム全体が固定の優先順位決定ツリーによって定義されることを認識することです。 最初の条件`a > b`true の場合、結果が完全に決定されます。これは、その分岐ではそれ以上の推論が無関係であることを意味します。 失敗した場合にのみ 2 番目の条件をチェックします`c > b`。 両方とも失敗した場合は、デフォルトで最終状態になります。 

これにより、問題はあらゆる形式の関係推論から厳密に順序付けされた条件チェックに軽減されます。 この構造は本質的に 2 レベルの決定関数です。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`。 各テスト ケースは独立しているため、反復間で状態が引き継がれることはありません。 
2. 各テスト ケースについて、3 つの整数を読み取ります。`a`、`b`、 そして`c`。 これらは固定の強度を表しており、変換は適用されません。 
3. かどうかを確認します。`a > b`。 この条件が当てはまる場合は、すぐに出力します`"Win"`。 このステップは、問題によって最も優先度の高いルールとして定義されているため、最初に実行されます。 
4. もし`a > b`false であるかどうかを確認してください`c > b`。 この条件が成立する場合、出力します。`"WIN"`。 これは、キャンディがボブの喪失を決定づける二次的な解釈を表しています。 
5. どちらの条件も満たさない場合、出力`"nowin"`。 これは、ボブがアリスにもキャンディにも負けない残りの領域に対応します。 

### なぜ効果があるのか

 ロジックは空間全体を分割します。`(a, b, c)`厳密な不等式によって定義される 3 つの互いに素な領域に分割されます。 最初の条件は、アリスがボブを支配するすべてのケースを完全に捕捉し、代替ルールがそれをオーバーライドしないように最初にチェックされます。 2 番目の条件は、アリスが失敗した場合にのみ有効になり、キャンディとボブの比較のみに依存します。 両方のチェックは実行順序において相互に排他的であり、最終フォールバックと組み合わせると集合的に網羅的になるため、すべての入力は曖昧さなく正確に 1 つの出力にマップされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        if a > b:
            print("Win")
        elif c > b:
            print("WIN")
        else:
            print("nowin")

if __name__ == "__main__":
    solve()
```このソリューションはすべてのテスト ケースを 1 回読み取り、それぞれを個別に処理します。 分岐構造はデシジョン ツリーを直接反映し、条件の優先順位が指定どおりに正確に保持されるようにします。 

実装の重要な詳細は、`elif`。 これにより、一度は`a > b`が満たされる場合、プログラムは 2 番目の条件を誤って評価しません。 この構造がなければ、別個の`if`のために`c > b`正しい出力を誤って上書きする可能性があります。

 ## 特殊なケース

 すべての値が等しい場合、1 つのエッジ ケースが発生します。 入力用`a = b = c = 10`、アルゴリズムがチェックします`a > b`失敗したらチェックします`c > b`これも失敗し、`"nowin"`。 アリスもキャンディも厳密にはボブを超えないため、これはルール構造と一致します。 

もう 1 つのケースは、平等だけが結果を分ける場合です。`a = 5, b = 5, c = 6`。 ここでは、最初の条件は等しいため失敗しますが、2 番目の条件はキャンディがボブを厳密に上回っているため成功し、次の結果が得られます。`"WIN"`。 これにより、平等によって勝利条件がトリガーされないことが確認されます。 

最後のケースは、キャンディに関係なくアリスが厳密に強い場合です。`a = 100, b = 1, c = 0`。 アルゴリズムは最初のチェックですぐに停止し、戻ります。`"Win"`これは、Candy がこのブランチでは決して評価されないことを示しています。
