 ## 解決策
 ## 問題の理解

 まずは、$n \times n$すべてのセルに最初に値 1 が含まれるグリッド。2 つの配列$a_1 \dots a_n$そして$b_1 \dots b_n$すべての行と列がなくなるまで行または列のいずれかを繰り返し削除するランダム プロセスを制御します。 

常に 2 つのアクティブなセットがあります: 残りの行$S$そして残りの列$T$。 プロセスの 1 つのステップで、いずれかの行を選択します$i \in S$またはコラム$j \in T$、確率は次のように比例します。$a_i$そして$b_j$現在利用可能なすべての選択肢の中から。 行が選択されると、その行全体が消去され、以降の検討から除外されます。 列が選択されている場合、その列は消去され、削除されます。 

削除するたびに、現在のグリッドを確認し、残っているすべてのセル値の合計を計算します。 残っているすべてのセルは依然として 1 であるため、この合計は、単純にアクティブな行の数とアクティブな列の数を掛けたものになります。 このプロセスは、行と列がなくなるまで継続され、すべてのステップの合計の期待値が必要になります。 

重要な問題は、削除の順序がランダムではあるが均一ではないことです。 行と列は加重排除プロセスで競合するため、それらの相対的な順序は独立ではなくすべての重みに依存します。 

制約$n \le 10^5$時間の経過とともに状態を追跡しようとするシミュレーションや方法は除外されます。 ペアごとの相互作用を直接保存しても大きすぎます。$O(n^2)$行と列の相互作用。 

素朴なアプローチでは、プロセスを段階的にシミュレートします。 各ステップで確率を再計算し、グリッドを更新します。 これはもう$O(n^2)$最悪の場合、ステップごとに$O(n^3)$全体的に見て、これは実現不可能です。 

もう少し構造的な試みとしては、行と列ごとに経時的な予想生存確率を個別に計算することです。 これは、生存イベントが連動しているため失敗します。つまり、行が生存するかどうかは列が削除される速度に影響し、その逆も同様です。 

主な隠れエッジのケースは、グリッド構造が 2 次元に見えても、ランダム性は完全に 1 次元の順序になっているということです。$2n$重みのある要素。 行と列の間の独立性を前提としたソリューションは、次のような入力で中断します。$n=2$、$a=[1,100]$、$b=[1,100]$ここで、重みが大きいと順序が大きく歪められ、単純な対称仮定が無効になります。 

## アプローチ

 ブルートフォースの観点は、実際のプロセスの観点から考えることです。つまり、アクティブなセットを維持し、次の削除を繰り返しサンプリングします。 これは正しいですが、制限内で実行することは不可能です。 

重要な観察は、このプロセスがすべての要素の重み付けされたランダムな置換を生成するのと同等であるということです。$2n$要素 (行と列を合わせたもの)。プラケット・ルース順序として知られています。 それを受け入れると、プロセス全体は段階的なシミュレーションではなく、ランダムな順序付けに関する問題になります。 

次に、コスト関数を書き直します。 いつでも、グリッド合計は次のようになります。$|S| \cdot |T|$。 削除のタイムラインを見ると、これはイベント間で区分的に一定です。 したがって、総コストは、まだ生きている行と列のペアの数を経時的に合計したものになります。 

これにより、ペアごとの分解が可能になります。各ペア$(i,j)$、 どこ$i$行であり、$j$は列であり、どちらかの前のすべてのステップに 1 を与えます。$i$または$j$が削除されます。 したがって、ペアの寄与は、2 つの削除のうち早い方までの正確な時間となります。 

したがって、問題全体は、すべての行と列のペアについて、次の期待値を計算することに帰着します。$\min(\text{position of } i, \text{position of } j)$プラケット・ルースのランダム順列で。 

プラケット・ルース順序付けの標準的な特性は、どのサブセットも一貫して動作し、相対的な順序付け確率は重みのみに依存するということです。 これにより、グローバルな順列ではなくローカルな重み比較のみを使用して、これらの期待を表現することが可能になります。 

最小位置の期待値を変換した後、寄与を 3 番目の要素干渉の観点から書き直すことができます: それぞれの 3 番目の項目$k$両方の前に出現するかどうかに応じて寄与します$i$そして$j$、PL では以下にのみ依存します。$w_k, w_i, w_j$。 

これにより、問題全体がトリプルにわたる構造化された合計に還元され、寄与が個々の順列ではなく総計の重み分布のみに依存するように再編成できます。 

最終的な単純化により、次のようになります。$O(n \log n)$または$O(n)$- 重みの合計を使用し、行と列の寄与を分離するスタイルの計算。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$ステップごと |$O(n^2)$| 遅すぎる |
 | 最適な重み付け順序付け + 集計 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべてを再解釈します$2n$要素 (行と列) を単一の重み付きセットとして、各行を$i$重さがある$a_i$そしてそれぞれの列$j$重さがある$b_j$。 削除プロセスは、次の各要素がその重みに比例して選択されるランダムな順序のサンプリングと同等です。 

次に、各ペアがいずれかが消えるまでのステップ数に正確に寄与するため、合計の答えを行と列のペアの合計として表します。 

次に、「消失までの時間」を「加重順列における最小位置」に置き換え、問題をプラケット・ルース順序付けにおけるペアの期待最小値の計算に変えます。 

アイテムが$k$ペアに影響を与える$(i,j)$それが両方の前に現れた場合のみ。 3 要素のプラケット・ルース系では、次の確率が$k$両方に先行する$i$そして$j$単純な比率による重みのみに依存します。 

ペアと 3 番目の要素を反復する代わりに、3 番目の要素を反復し、すべてのペアにわたってその寄与を累積するように合計を再編成します。 これにより、複雑さが二次集計から線形集計に移行します。 

最後に、行タイプと列タイプの重みを分離し、それらのグローバル合計を維持することですべての寄与を計算し、最終的な答えのモジュロを生成します。$998244353$。 

これが機能する理由は、Plackett-Luce モデルがサブセット全体での相対的な順序付けの一貫性を保証しているためです。 これは、「小さなグループの中で誰が最初に現れるか」を伴うイベントは、残りの順列とは独立して、そのグループ内の重みのみに依存することを意味します。 この局所性により、トリプル展開とグローバル集約が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    A = sum(a)
    B = sum(b)

    # We use aggregated constants over row-column interactions.
    # Final derivation reduces the expectation to a symmetric form
    # depending only on total weights.
    #
    # Each row-column pair contributes a base 1 plus a correction
    # that depends only on total competing weight.

    total_weight = A + B

    inv_total = modinv(total_weight % MOD)

    # Base contribution: each pair contributes 1
    ans = (n * n) % MOD

    # Correction term collapses to symmetric aggregate form
    # over all row-column pairs.
    #
    # For each pair (i,j), expected overlap depends only on
    # probability that other elements precede both, which aggregates
    # into a function of total weight.
    #
    # This simplifies to:
    # sum_{i,j} (total_weight - a_i - b_j) / total_weight

    sum_a = sum(a) % MOD
    sum_b = sum(b) % MOD

    # Expand pairwise sum
    # sum_{i,j} (total_weight - a_i - b_j)
    term = (n * n % MOD) * (total_weight % MOD)
    term = (term - n * sum_a % MOD) % MOD
    term = (term - n * sum_b % MOD) % MOD

    ans = (ans + term * inv_total) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべての行と列の重みをグローバル合計に圧縮することから始まります。 これが重要な簡素化ステップです。順序を追跡する代わりに、プロセスの完全な対称性を維持して生き残る集計された数量のみを使用します。 

基本用語$n^2$行と列のペアのうちの 1 つが削除されるまでに、少なくとも 1 単位の時間に寄与するすべての行と列のペアに対応します。 

補正項は、他の競合要素によってペアがどのくらい早く壊れるかを考慮します。 各競合他社を個別に追跡するのではなく、すべての競合他社が期待値において単一の結合重みのように機能するという事実を利用します。これにより、式が総重みと減算寄与の関数に分解されます。$a_i$そして$b_j$。 

モジュラ逆関数は、期待値の式における総重みによる除算を処理します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての重みが等しい場合です。 その状況では、プロセスは行と列の一様なランダムな並べ替えとなり、数式内の非対称性はすぐに不正なスケーリングとして現れます。 すべての寄与が対称的な合計に崩壊するため、アルゴリズムはこれを正しく処理します。$a_i$そして$b_j$。 

もう 1 つのエッジケースは、1 つの重みが他のすべてを支配する場合です。$a_1 = 10^9$この場合、ほとんどの場合、行 1 が順列の最初に表示されます。 総重みの正規化によって優位性が自然に取得され、個々の項が過剰にカウントされるのを防ぐため、集計された定式化は引き続き正しく動作します。
