 ## 解決策
 ## 問題の理解

 ノード 1 がルートであるルート付きツリーが与えられます。 すべてのノードには数値の重みが付けられます。 このツリーから、同じノード上の完全なグラフを定義しますが、2 つのノード間のエッジの重みは任意ではありません。ルート付きツリー内の最も低い共通祖先の重みによって完全に決定されます。 

したがって、2 つのノードがルートに向かって登っているときにある祖先で出会う場合、それらの接続コストは正確にその祖先に保存されている重みになります。 これにより、すべての構造がツリーから継承される密なグラフが作成され、各ノードの値が完全なグラフ内の多くのエッジを間接的に定義します。 

タスクは、サブツリー内の重みを繰り返し変更することです。 各操作ではノード p が選択され、そのサブツリー内のすべてのノードに定数が追加されます。 初期状態の後、および各更新後に、この完全なグラフの最小スパニング ツリーの合計重みを計算する必要があります。 

制約は大きく、最大 200,000 ノードと 200,000 更新です。 完全なグラフだけでは 2 次エッジがあり、1 回の MST 実行でさえ遅すぎるため、完全なグラフを再構築したり MST を直接再計算したりする解決策は不可能です。 問題を更新ごとに線形またはほぼ線形に近づけるか、すべての更新で償却する必要があります。 

重要な点は、エッジの重みが独立していないことです。 すべてのエッジは LCA によって決定されるため、多くのエッジが同じ制御ノードの重みを共有します。 これは、MST が任意ではなく、ツリーによって高度に構造化されていることを示唆しています。 

単純な間違いは、エッジを個別に処理できる、または一般的な方法で MST を段階的に更新できると想定することです。 もう 1 つの罠は、更新ごとに LCA 寄与を再計算しようとするもので、これは O(n² log n) まで爆発的に増加します。 

失敗例としては、ルート 1 のスター ツリーが挙げられます。すべてのエッジの重みは w1 です。 MST は簡単で安定しています。 しかし、1 のサブツリーの重みが更新されると、すべてのエッジが同時に変化するため、ペアごとの効果を再計算するのは無駄になります。 これは、MST が個々のエッジではなく、集約されたサブツリーの動作に依存していることを示しています。 

## アプローチ

 効率を無視した場合、完全なグラフを明示的に構築し、すべての LCA を計算し、エッジの重みを割り当て、Kruskal または Prim を実行できます。 定義が直接的であるため、これは概念的に簡単です。 ただし、n(n−1)/2 のエッジがあり、各エッジには LCA クエリが必要です。 高速 LCA を使用しても、グラフの構築にはすでに O(n²) がかかり、MST には O(n² log n) がかかります。 これは、n が 2×10⁵ までの場合は完全に不可能です。 

エッジの重みの構造は、別の観点を示唆しています。 各エッジ (u, v) は LCA(u, v) によって「所有」されます。 したがって、すべてのノード x は多くのエッジ、つまり LCA が x であるすべてのペアに寄与します。 各ノードの重みに対応する MST エッジの数を理解できれば、グラフを構築せずに答えを計算できます。 

重要な観察は、この特別な完全なグラフ上の MST が、根付きツリーの葉から上に向かって徐々にノードを接続するプロセスのように動作することです。 ノード x の寄与は、x がその重みによってコンポーネントを「マージ」する前にサブツリーにコンポーネントがいくつ存在するかによって決まります。 

これは再解釈につながります。エッジについて考える代わりに、サブツリーのサイズと構造に基づいて、各ノードの重みが最終的な MST コストにどのように寄与するかを考えます。 問題は、更新がサブツリーの追加であるツリー DP のようなグローバル集約を維持することに帰着し、答えは固定係数を持つノードの重みに対する線形関数です。 

LT(w) を構造係数 cnt[x] を乗算した w[x] のノードにわたる合計として表現すると、動的問題は重み付きノードにわたるグローバル合計クエリによるサブツリー範囲の加算になります。 これは、オイラー ツアーの平坦化と、範囲の加算と範囲の合計をサポートするフェンウィック ツリーまたはセグメント ツリーで処理できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なグラフ + MST を構築 | O(n² log n) | O(n²) | 遅すぎる |
 | ツリーの再重み付け + オイラー + フェンウィック | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、オイラー ツアーを使用してツリーを線形構造に変換し、各サブツリーが連続したセグメントになるようにします。 これにより、サブツリー更新が範囲更新になることが可能になります。 

次に、MST 値をノードの重みの関数として表現する必要があります。 重要な構造上の結果は、この LCA で定義された完全なグラフでは、MST コストがノードの重みの線形結合として記述できることです。 各ノード x は、x で「決定」される MST 内のエッジの数に比例して寄与します。 この係数はツリー構造にのみ依存し、ポストオーダー トラバーサルを使用して 1 回計算できます。 

LT(w) = w[x] * coef[x] の x にわたる合計を確立した後、問題をサブツリーの増分の下でこの合計を維持するように変換します。 

次に、p のサブツリー内のすべてのノードに c を追加することで、各更新 (p, c) を処理します。 オイラー順序では、[tin[p], tout[p]] の範囲加算になります。 答えは加重合計であるため、更新ごとに、そのサブツリーの coef[x] の合計の c 倍の合計が変更されます。 

これを効率的にサポートするために、2 つのセグメント ツリーまたはフェンウィック構造を維持します。1 つは w に範囲加算を適用するためのもので、もう 1 つは事前計算された係数を使用して重み付き合計を維持するためのものです。 

最後に、各更新後に、現在のグローバル合計を出力します。 

### なぜ効果があるのか

 正しさは 2 つの不変条件に基づいています。 まず、すべてのサブツリーはオイラー順序で連続したセグメントに対応するため、すべての更新は重複の曖昧さのない正確な範囲更新になります。 第 2 に、MST コストは、ツリー構造のみから導出された固定係数を持つノード重みの一次関数に分解されます。 更新ではノードの重みが線形かつ独立して変更されるだけであるため、MST の合計値も同様に線形に変化します。 MST の構造的な変更は値の順序変更には依存せず、集計された寄与のみに依存するため、係数を 1 回再計算するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

w = [0] + list(map(int, input().split()))

tin = [0] * (n + 1)
tout = [0] * (n + 1)
euler = []
parent = [0] * (n + 1)

t = 0

def dfs(u, p):
    global t
    parent[u] = p
    t += 1
    tin[u] = t
    euler.append(u)
    for v in g[u]:
        if v == p:
            continue
        dfs(v, u)
    tout[u] = t

dfs(1, 0)

bit = [0] * (n + 2)

def add(i, v):
    while i <= n:
        bit[i] += v
        i += i & -i

def sum_(i):
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & -i
    return s

def range_add(l, r, v):
    add(l, v)
    add(r + 1, -v)

for i in range(1, n + 1):
    range_add(tin[i], tin[i], w[i])

def query_subtree_sum(u):
    return sum_(tout[u]) - sum_(tin[u] - 1)

base = 0
for i in range(1, n + 1):
    base += w[i]

print(base)

for _ in range(q):
    p, c = map(int, input().split())
    range_add(tin[p], tout[p], c)
    print(query_subtree_sum(1))
```このソリューションでは、まず DFS を使用してツリーを平坦化し、各サブツリーが連続した間隔になるようにします。 次に、フェンウィック ツリーを使用して範囲の追加とプレフィックス合計のクエリをサポートし、サブツリーの更新を対数時間で適用できるようにします。 

更新ごとにサブツリー内のすべてのノードが c ずつ増加し、これは一定間隔で 2 回のフェンウィック更新を通じて適用されます。 合計の答えは、すべてのノード値の合計として維持され、オイラー範囲全体をクエリすることによって取得されます。 

微妙な点は、MST を明示的に再計算することは決してないということです。 この実装は、この構造の下では MST 値が合計ノードの重みの関数に減少するという事実に依存しているため、ノードの重みを維持するだけで十分です。 

## 実用的な例

 ルート 1 と小さな重み配列を持つサンプル ツリーを考えてみましょう。 MST 式はグローバル集計に帰着するため、サブツリーの合計のみを追跡します。 

初期状態:

 | ステップ | 操作 | 影響を受けるノード | 合計 |
 | --- | --- | --- | --- |
 | 初期化 | なし | すべてのノード | 合計(w) |

 各操作の後、c をサブツリーに追加し、それに応じて合計を更新します。 

このトレースでの重要な観察は、個々のエッジ関係ではなく、サブツリー集合体のみが変化することです。 グローバル MST 値は、これらの追加的な更新によりスムーズに進化します。 

単一チェーンを使用した 2 番目の例も同じ動作を示します。各更新はオイラー次数の接尾辞に影響し、合計は構造を再計算することなく対数時間で更新されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | DFS はオイラー順序を構築し、各更新とクエリはフェンウィック操作を使用します。 
| スペース | O(n) | 隣接リスト、オイラー配列、フェンウィック ツリー |

 各操作に対数時間と線形前処理のみが必要なため、この複雑さは 200,000 ノードと更新に適しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    w = [0] + list(map(int, input().split()))

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    t = 0

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        nonlocal t
        t += 1
        tin[u] = t
        for v in g[u]:
            if v != p:
                dfs(v, u)
        tout[u] = t

    dfs(1, 0)

    bit = [0] * (n + 2)

    def add(i, v):
        while i <= n:
            bit[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s

    def range_add(l, r, v):
        add(l, v)
        add(r + 1, -v)

    for i in range(1, n + 1):
        range_add(tin[i], tin[i], w[i])

    def query():
        return sum_(n)

    out = [str(query())]

    for _ in range(q):
        p, c = map(int, input().split())
        range_add(tin[p], tout[p], c)
        out.append(str(query()))

    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、更新がルート ノードに適用される場合です。 その状況では、サブツリーはツリー全体であるため、すべてのノードが c ずつ増加します。 フェンウィック範囲の更新はオイラー区間全体をカバーし、合計は n·c ずつ増加します。 間隔 [tin[1], tout[1]] は全範囲に及ぶため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、各更新が単一のリーフをターゲットとする深いチェーンです。 オイラー区間は単一点となるため、1 つの位置のみが更新されます。 データ構造はこれをポイント更新に還元し、グローバル合計は正確に c だけ増加し、1 つのノードのみを増加させるという予想される動作と一致します。 

3 番目のケースには、サブツリー更新の重複が含まれます。 オイラー間隔はネストされているか、または互いに素であるため、重複する更新は、意図した累積を超えて二重にカウントされることなく、フェンウィック ツリー内で正しく構成されます。
