 ## 問題の理解

 長さの円形配列が与えられます$n$ここで、各位置はビットマスクを表す整数値を保持します。 配列は個別のラウンドで進化します。 で$i$-第 ラウンド、すべてのポジション$j$シフトされた別の位置とのビット単位の OR をとることで、その値を同時に更新します。$i$円の上で前に進みます。 正式にはそれぞれ$A_j$になる$A_j \,\mathrm{OR}\, A_{(j+i)\bmod n}$。 

ラウンド内のすべての更新は同時に行われ、後のラウンドはすでに更新された配列に対して実行されます。 

このようなラウンドをいくつか順番に実行した後、異なるオフセットの OR マージを繰り返すことによって、値がサイクル全体に伝播し始めます。 このプロセスにより、情報 (ビット) が位置全体に徐々に分散されます。 タスクは最小ラウンド数を決定することです$T$その後、配列内のすべての要素が等しくなります。 

出力は結果の配列そのものではなく、すべての位置に同じ値が含まれるまでに必要な最小ラウンド数のみです。 

制約により許可されるのは、$n \le 10^5$これにより、明示的に実行されるシミュレーションが即座に除外されます。$O(n)$ラウンドごとに可能な限りの作業を行う$T$、さえ$O(n^2)$全体的な動作が遅すぎるでしょう。 正しいソリューションは、プロセスを閉じた形式、またはテスト ケースごとのほぼ一定の計算に削減する必要があります。 

微妙なエッジケースが現れるのは、$n$とても小さいです。 たとえば、次の場合$n = 2$、1 回のラウンドですでに両方の位置が互いに OR され、即座に等しくなります。 のために$n = 3$、動作は異なります。各ラウンドでは固定ステップ サイズのみが導入され、オーバーラップには複数のラウンドが必要となるため、値の拡散はより遅くなります。 これは、答えが値自体ではなく、情報がサイクル全体にどれだけ早く伝播するかによって決まることを示しています。 

もう 1 つのよくある間違いは、OR が冪等で可換であるため、単一ラウンドまたは少数の固定ラウンド数で十分であると想定することです。 それが失敗するのは、$n$が大きく、ラウンドごとの伝播距離が制限されます。 

## アプローチ

 素朴な解釈は、文字通りプロセスをシミュレートすることです。 各ラウンドで$i$、すべての位置を反復して新しい配列を計算します$j$、取る$A_j$または$A_{j+i}$、剰余インデックス付き$n$。 これを繰り返すと、$T$ラウンドコスト$O(nT)$。 最悪の場合、$T$の順序です$n$、これは次のようになります$O(n^2)$、これは許容範囲をはるかに超えています。$n = 10^5$。 

重要な点は、配列の値がプロセスの構造に影響を与えないことです。 「到達可能性」の伝播のみが重要です: 位置からの値が一度だけ$x$位置に到達$y$、OR の単調な性質により、すべてのビットを永続的にそこに提供できます。 

したがって、値を追跡する代わりに、どの位置がその後の他の位置に影響を与えるかを追跡します。$T$ラウンドします。 

伝播の観点から考えると、プロセスはサイクル上のグラフ到達可能性の問題になります。 ラウンド中$i$、長さのエッジを効果的に追加します$i$。 後$T$ラウンドでは、どのポジションも、次から選択されたステップ サイズの合計によって到達可能なポジションに影響を与える可能性があります。$1$に$T$、ラウンドを繰り返すことでこれらのシフトが構成されるためです。 

したがって、到達可能な距離のセットは、次の要素のすべての合計です。$\{1,2,\dots,T\}$、までの任意の距離を意味します$$1 + 2 + \dots + T = \frac{T(T+1)}{2}.$$それでその後$T$ラウンド中、各ポジションは最大距離内のすべてのポジションから情報を収集できます。$\frac{T(T+1)}{2}$サイクルに沿って。 このスパンがサイクル全体をカバーすると、すべての位置が他のすべての位置から寄与を受け取り、すべての値が配列のグローバル OR と同一になります。 

したがって、問題は最小のものを見つけることに帰着します$T$次のような:$$\frac{T(T+1)}{2} \ge n - 1.$$これは単純な二次しきい値です。

 ## アルゴリズムのチュートリアル

 伝播距離がサイクル全体をカバーするために必要な最小ラウンド数を計算します。 

1.読む$n$テストケースごとに。 OR は情報を蓄積するだけであり、伝播速度には影響しないため、配列の値は最終的な答えには無関係です。 
2. プロセスをサイクル上の拡散半径問題として解釈します。 後$T$ラウンドごとに、情報は各ラウンドで導入されたステップ サイズの合計に等しい最大距離を移動できます。 
3. 三角数を計算する$S(T) = \frac{T(T+1)}{2}$、これは到達可能な最長距離を表します。$T$ラウンドします。 
4. 最小値を見つける$T$そのような$S(T) \ge n-1$。 これにより、すべての位置が最大で他のすべての位置に到達できるようになります。$T$ラウンドします。 
5. 二次公式を使用して不等式を直接解きます。 必要なものは次のとおりです。$$T^2 + T - 2(n-1) \ge 0.$$正の根は次のようになります。$$T = \left\lceil \frac{-1 + \sqrt{1 + 8(n-1)}}{2} \right\rceil.$$6. この値をテスト ケースごとに出力します。 

### なぜ効果があるのか

 このプロセスは循環シフトを通じてのみ情報を拡張し、各ラウンドで一連の可能な動きに新しい固定ステップ サイズを追加します。 ラウンドの構成は、これらのステップ サイズの合計に対応します。 OR は単調で不可逆であるため、ポジションがビットを受信すると、そのビットを失うことはありません。そのため、唯一の制限要因は、到達可能なシフトのグラフが完全に接続されるかどうかです。 三角形の境界は、累積シフト範囲がサイクル全体をカバーするときを正確に特徴づけ、すべてのノードが他のすべてのノードから寄与を受け取ることを保証し、平等を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        # We only need n
        if n <= 1:
            print(0)
            continue
        
        target = n - 1
        disc = 1 + 8 * target
        root = int(math.isqrt(disc))
        if root * root < disc:
            root += 1
        
        T = (-1 + root) // 2
        if T * (T + 1) // 2 < target:
            T += 1
        
        print(T)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 のために$n = 2$、伝播グラフは 1 ラウンド後にすでに完全に接続されています。 アルゴリズムは計算します$n-1 = 1$、および条件$T(T+1)/2 \ge 1$収量$T = 1$、直接シミュレーションと一致します。 

のために$n = 3$、必要です$n-1 = 2$。 2 に達する最小の三角数は$3$、に対応$T = 2$。 これは、1 ラウンドで隣接性のみが提供されるのに対し、完全な混合には 2 番目の伝播層が必要であることを反映しています。 

大型用$n$、 のような$n = 10^5$、計算された$T$周りにいる$\sqrt{2n}$に比べて小さいままです。$n$により、アルゴリズムの効率が維持され、線形シミュレーションの落とし穴が回避されます。
