 ## 解決策
 ## 問題の理解

 問題は配布です`n`さまざまな長さのニンジン`k`ウサギがウサギを食べるための総労力が最小限に抑えられるような方法でウサギに与えます。 各ニンジンは複数の部分に分割できますが、結果として得られる各部分の長さは正の整数でなければなりません。 ウサギがニンジンを食べるのに費やす時間はその長さの二乗に比例するため、ニンジンが大きくなると合計時間が不釣り合いに長くなります。 目標は、ニンジンを正確にカットする方法を決定することです`k`それらの部分の二乗和を最小化します。 

入力は、ニンジンの数、ウサギの数、およびニンジンの長さで構成されます。 出力は、可能な最小の総食事時間を表す単一の整数です。 制約は重要です。`n`そして`k`それぞれ最大で可能です`10^5`個々のニンジンの長さは次のとおりです`10^6`。 これは、考えられるすべての分布を列挙しようとするアルゴリズムは非常に遅すぎることを意味します。 ニンジンの長さの合計は少なくとも次の値であることが保証されます`k`常に生産できることを保証します。`k`正の整数部分。 

エッジケースは、すべてのニンジンがすでに小さい場合に発生します。`n = k`各ニンジンが正確に 1 匹のウサギに対応する場合、または 1 つのニンジンが他のニンジンよりもはるかに大きく、何度も分割する必要がある場合。 不注意に実装すると、分割が不均等になると時間が最適化されない可能性があるため、二乗和を最小化できない可能性があります。 たとえば、長さ 5 のニンジンが 3 つの部分に分割されるとすると、次のように分割されます。`[3,1,1]`合計時間は`11`として分割しますが、`[2,2,1]`収量`9`、厳密にはこれの方が優れています。 

## アプローチ

 素朴なアプローチは、ニンジンを正確に分割するあらゆる方法を試すことです。`k`部分を分割して二乗和を計算します。 ニンジンの長さごとに`a_i`、それをあらゆる可能な数の部分に分割することを検討できます。`1`まで`a_i`。 方法の数は組み合わせによって増加するため、中程度の場合でも`n`そして`k`、合計の操作ははるかに多くなります`10^9`、このアプローチは実行不可能になります。 

重要な観察は、この問題は本質的に貪欲であるということです。 ニンジンをより多くの部分に分割すると平方和は減少しますが、利益は減少します。 与えられた長さのニンジンに対して`x`に分割します`p`Pieces は次のように計算された平方和を生成します。`x`で割り切れない`p`、分割は可能な限り均等に行われます。`x % p`サイズの部分`ceil(x/p)`そして`p - (x % p)`サイズの部分`floor(x/p)`。 平方和の合計は次のようになります。```
(x % p) * ceil(x/p)^2 + (p - (x % p)) * floor(x/p)^2
```これにより、任意のニンジンについて、ピースの数を 1 つ増やした場合の二乗和の減少を計算できます。 最大ヒープを使用すると、さらに分割することで合計時間を最大に短縮できるニンジンをいつでも選択できます。 正確に完了するまで続けます`k`個。 これにより、問題は徹底的な列挙ではなく、優先順位に基づいた貪欲な手順に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(可能な分割の積) | O(n) | 遅すぎる |
 | ヒープに貪欲 | O((k - n) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大ヒープを初期化して、各ニンジンのピース数を増やすことによる潜在的な利点を追跡します。 二乗和の減少の負の値を格納します。`heapq`デフォルトでは最小ヒープです。 各ニンジンについて、1 本から始めて、2 本に分割した場合の削減量を計算します。 
2. 現在の個数のカウントを維持します。 もともと、これは、`n`にんじんは1本としてカウントされるためです。 
3. 合計個数が以下の場合`k`、さらに分割した場合に合計時間が最大短縮されるヒープからニンジンを抽出します。 個数を1つ増やします。 再度分割してヒープに戻す場合の新しいリダクションを計算します。 
4.合計個数に達したら`k`、各ニンジンの最終的な個数を使用して平方和の合計を計算します。 上記の式を使用して、各ニンジンの平方和を効率的に計算します。 
5. 合計を最小合計時間として出力します。 

機能する理由: 削減を最大化するニンジンを常に選択するという貪欲なステップにより、追加の各部分を最大限の限界利益が得られる場所で確実に使用することができます。 二乗和関数は凸関数であり、ピースが増加するにつれて限界減少が減少するため、この戦略は最小の総二乗和を生成することが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def sum_squares(x, p):
    q, r = divmod(x, p)
    return r * (q + 1) ** 2 + (p - r) * q ** 2

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    heap = []
    pieces = [1] * n
    total_pieces = n
    
    for i in range(n):
        if a[i] > 1:
            gain = sum_squares(a[i], 1) - sum_squares(a[i], 2)
            heapq.heappush(heap, (-gain, i))
    
    while total_pieces < k:
        gain, i = heapq.heappop(heap)
        pieces[i] += 1
        total_pieces += 1
        if pieces[i] < a[i]:
            new_gain = sum_squares(a[i], pieces[i]) - sum_squares(a[i], pieces[i] + 1)
            heapq.heappush(heap, (-new_gain, i))
    
    result = sum(sum_squares(a[i], pieces[i]) for i in range(n))
    print(result)

solve()
```このコードは、各ニンジンを 1 つのピースで初期化し、それを 2 つに分割する潜在的なゲインを計算し、最大ヒープを使用して各ステップで最大のゲインを持つニンジンを選択します。 Each heap operation is`O(log n)`、そして私たちは実行します`k - n`分割され、全体的に複雑になります。`O((k - n) log n)`。 最終的な合計は、除算ベースの式を使用して効率的に計算されます。 オフバイワンエラーは慎重に計算することで回避されます`ceil`そして`floor`と分割する`divmod`。 

## 実用的な例

 入力例:```
3 6
5 3 1
```| ステップ | ニンジン片 | ヒープトップゲイン | 合計個数 | コメント |
 | --- | --- | --- | --- | --- |
 | 0 | [1,1,1] | (-16,0) | 3 | ニンジン 5 を分割した場合の初期ゲイン |
 | 1 | [2,1,1] | (-7,0) | 4 | にんじん5本を2等分にします。 
| 2 | [3,1,1] | (-1,1) | 5 | にんじん5本を3等分にします。

 最終的なピース数:`[3,2,1]`。 平方和 =`3^2 + 2^2 + 1^2 + ... = 15`。 

これは、ヒープベースの貪欲な選択が、合計時間を最大化する分割を正確に識別することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((k - n) log n) | それぞれの`k - n`分割にはヒープのプッシュ/ポップが必要です`O(log n)`|
 | スペース | O(n) | 個数の配列と最大サイズのヒープを保存します。`n`|

 までの制約を考慮すると、`10^5`ニンジンとウサギのように、このソリューションは時間とメモリの制限内にうまく収まります。
