 ## 解決策
 ## 問題の理解

 バイナリ文字列として表現された果物のシーケンスが与えられます。`1`リンゴを表し、`0`オレンジの場合。 目標は、考えられるすべての連続する部分文字列にわたって、その部分文字列内の最も長い連続したリンゴの長さを計算し、これらの値を合計することです。 たとえば、部分文字列が次の場合、`01110`、最も長く連続したリンゴは`3`、それが貢献します`3`合計額に。 

制約は重要です: 文字列の長さ`n`最大 500,000 に達する可能性があります。 これは、すべての部分文字列を個別に検査する単純なアプローチは実用的ではないことを意味します。 おおよそあります$n(n+1)/2$部分文字列。$n = 5 \cdot 10^5$譲る$10^{11}$部分文字列。 各部分文字列の線形スキャンでも、$O(n^3)$2秒の制限時間では実行不可能な最悪の場合の操作。 線形または線形時間に近いアプローチが必要です。 

エッジ ケースには、すべてがリンゴまたはすべてがオレンジであるシーケンスが含まれます。 文字列全体が 1 の場合、すべての部分文字列の最大シーケンスはその長さに等しいため、誤って二重にカウントすることを避ける必要があります。 逆に、文字列にゼロのみが含まれている場合は、すべての部分文字列がゼロに寄与するため、アルゴリズムがクラッシュしたり計算ミスをしたりしてはなりません。 

## アプローチ

 ブルートフォースの解決策は簡単です。 考えられるすべての開始インデックスを反復処理します`l`そして終了インデックス`r`、部分文字列を抽出し、それをスキャンして、最も長く連続するものを見つけます。 正しいのですが、これには次のことが必要です$O(n^3)$操作があるため、$O(n^2)$部分文字列と各スキャンにかかる時間$O(n)$時間。 これは明らかに制限時間を超えています$n = 5 \cdot 10^5$。 

より高速なソリューションのための重要な洞察は、**連続するブロック**を処理することです。 1 の最大の実行がすべて、構造化された方法で複数の部分文字列に寄与していることに注目してください。 1ブロックあたり`k`連続する場合、多くの部分文字列に完全または部分的に現れます。 すべての部分文字列を調べるのではなく、組み合わせ論を使用して各ブロックの寄与を直接カウントすることで、線形時間を実現できます。 

文字列を 0 と 1 の交互のシーケンスとして扱います。 同じ長さの連続するブロックごとに`k`を含むすべての部分文字列にわたるその寄与の合計を計算できます。 具体的には、可能なサブ長ごとに`i`(1から`k`)、このブロックが正確に寄与する部分文字列の数`i`は`(k - i + 1)`隣接するゼロを越えて左右に拡張する方法の数の倍。 ブロックを反復処理することで、合計を累積できます。`O(n)`時間。

 ## アルゴリズムのチュートリアル

 1. 総和変数の初期化`ans`ゼロに。 これにより、すべての部分文字列の最大値の合計が累積されます。 
2. 文字列を左から右に 1 回スキャンして、連続する 1 のブロックを識別します。 カウンターを維持する`count`1 に遭遇すると増加し、0 になると 0 にリセットされます。 ゼロが出現するたびに、ゼロでない場合は前のブロックの長さを記録します。 
3. 連続した長さのブロックごとに`k`、すべての部分文字列にわたる合計の寄与を計算します。 貢献度は最初の合計として導出できます。`k`正の整数:$1 + 2 + \dots + k = k(k+1)/2$。 この公式は、長さのブロックが存在するために生じます。`k`生成できる`k`長さ 1 の部分文字列、`k-1`長さ 2 の部分文字列、最大 1 個の長さの部分文字列`k`、それぞれ完全に 1 で構成されます。 
4. ブロックの寄与分を合計に加算します。`ans`。 文字列の終わりまでスキャンを続けて、すべてのブロックをキャプチャします。 
5. 最後の文字を処理した後、文字列が 1 で終わる場合は、最後のブロックを考慮してください。 
6. 合計金額を出力します。`ans`。 

これが機能する理由: 連続したブロックの各ブロックは、そのブロックの少なくとも一部を含む部分文字列の数とまったく同じ回数、合計に寄与します。 ブロックのみを考慮し、算術合計の公式を使用することにより、各部分文字列の列挙を回避しながら、各寄与を正確に 1 回カウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

ans = 0
count = 0

for ch in s:
    if ch == '1':
        count += 1
    else:
        ans += count * (count + 1) // 2
        count = 0

# add the last block if the string ends with ones
ans += count * (count + 1) // 2

print(ans)
```このコードは文字列を 1 回スキャンします。 ゼロが見つかるたびに、前のブロックが確定され、その寄与が追加されます。 算術合計の公式は、ブロック内の可能なすべての連続する長さの合計を効率的に計算するために使用されます。 ループ後の最後の追加は、文字列が 1 のブロックで終わる場合を処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()
    ans = 0
    count = 0
    for ch in s:
        if ch == '1':
            count += 1
        else:
            ans += count * (count + 1) // 2
            count = 0
    ans += count * (count + 1) // 2
    return str(ans)

# provided sample
assert run("4\n0110\n") == "12", "sample 1"

# custom cases
assert run("3\n111\n") == "10", "all ones"
assert run("3\n000\n") == "0", "all zeros"
assert run("1\n1\n") == "1", "single one"
assert run("1\n0\n") == "0", "single zero"
assert run("5\n10101\n") == "9", "alternating ones and zeros"
assert run("6\n111000\n") == "21", "block of ones followed by zeros"

 ## 特殊なケース

 すべて 1 の文字列の場合、次のように`11111`、アルゴリズムは長さ 5 の単一ブロックを識別し、合計を計算します。$5*6/2 = 15$。 これは、長さ 1 ～ 5 の部分文字列からの寄与を含む、すべての部分文字列の合計と一致します。 

すべてゼロの文字列の場合、次のようになります。`0000`、すべてのブロックの長さはゼロであるため、アルゴリズムは何も累積せず、合計がゼロになり、連続する部分文字列が含まれていないことが正しく反映されます。 

単一文字列の場合は、次のいずれかです。`1`または`0`、アルゴリズムは正しくカウントします`1`キャラクターが 1 人の場合、`0`それ以外の場合は、最小限の入力の適切な処理を示します。
