 ## 解決策
 ## 問題の理解

 文字のみで構成される文字列が与えられます。`A`そして`B`。 以下に等しい隣接する部分文字列を繰り返し削除することがあります。`AB`または`BB`。 このようなペアを削除すると、文字列の残りの部分が結合し、新しい取り外し可能なペアが作成される可能性があります。 

テスト ケースごとに、有効な削除を任意の数実行した後の文字列の最小可能長を決定する必要があります。 

すべての文字列の合計の長さは最大でも`2 × 10^5`、これが重要な実際の制約です。 文字列を繰り返しスキャンして文字を物理的に削除するアルゴリズムは、簡単に二次関数になる可能性があります。 二次関数の解法には大まかに次のものが必要になります。`4 × 10^10`限界をはるかに超えた最悪の場合の動作。 各文字を一定の回数だけ処理する、線形時間アプローチが必要です。 

いくつかの状況は判断を誤りやすいものです。 

次の文字列を考えてみましょう。```
AB
```答えは`0`1 回の操作で文字列全体を削除できるためです。 

ここで次のことを考えてみましょう。```
BA
```答えは`2`。 ありません`AB`または`BB`部分文字列なので何も削除できません。 数を数えるだけのソリューション`A`そして`B`文字がこれら 2 つの文字列を誤って同じものとして扱う可能性があります。 

別の微妙な例は次のとおりです。```
ABB
```考えられるシーケンスの 1 つは次のとおりです。```
ABB → A → 1
```まず最後のものを削除します`BB`、出発`A`。 あるいは:```
ABB → B → 1
```取り除く`AB`初め。 演算順序が異なると、生成される中間文字列も異なりますが、達成可能な最小長は同じです。 解決策は、特定の削除順序の選択に依存してはなりません。 

最後の厄介なケースは次のとおりです。```
BBB
```1 つ削除できます`BB`ペア：```
BBB → B
```答えは`1`、 ない`0`。 ブロックに奇数の`B`文字といいえ`A`最後の1つ、1つをキャンセルすることができます`B`生き残る。 

## アプローチ

 直接シミュレーションでは、次の現象が発生するかどうかを繰り返し検索します。`AB`または`BB`、そのうちの 1 つを削除し、残りの部分を連結し、移動がなくなるまで続行します。 

このアプローチは文字通りゲームのルールに従っているので正しいです。 問題は効率です。 削除するたびに、文字列のほぼ全体をシフトする必要がある場合があり、最大で`O(n)`削除。 長さの文字列`n`したがって、要求することができます`O(n²)`仕事。 

重要な観察は、両方の取り外し可能なパターンが次で終わっていることです。`B`。 

文字列を左から右に処理し、現在の非還元文字列を維持するとします。 新しい文字を読むとき:

 そうであれば`A`、すぐに取り外し可能なペアを形成できないため、今のところはそのままにしておく必要があります。 

そうであれば`B`の場合、前の文字は削除できます。```
AB → removed
BB → removed
```重要なのは、現在の縮小文字列の直前に文字が存在するかどうかだけです。 ある場合は、新しい`B`その文字を削除します。 存在しない場合は、`B`生き残る。 

この動作はまさにスタックが提供するものです。 

現在の縮小されていない文字をスタックに保存します。 

読むとき`A`、押してください。 

読むとき`B`:

 スタックが空でない場合は、1 文字をポップします。 ポップなキャラクターはこれと合わせて`B`のいずれかに対応します`AB`または`BB`削除。 

スタックが空の場合は、`B`、それと一緒に削除できるものがないためです。 

文字列全体を処理した後、スタックには削除できない文字が正確に含まれます。 そのサイズが答えです。

 ## アルゴリズムのチュートリアル

 1. 空のスタックを作成します。 
2. 文字列を左から右にスキャンします。 
3. 現在のキャラクターが`A`、それをスタックにプッシュします。 

アン`A`どちらの取り外し可能なパターンも、単独では完成させることができません。 
4. 現在のキャラクターが`B`スタックが空ではない場合は、最上位の要素をポップします。 

ポップされたキャラクターと現在のキャラクター`B`どちらかを形成します`AB`または`BB`、どちらも取り外し可能です。 
5. 現在のキャラクターが`B`スタックが空の場合はプッシュします`B`。 

前に使用できる文字がないため、削除できません。 
6. すべての文字が処理された後、スタック サイズを出力します。 

### なぜ効果があるのか

 スタックは常に、これまでに処理されたプレフィックスの可能な限り短い残存文字列を表します。 

新しいとき`B`到着すると、既存のトップキャラクターとすぐにペアリングできます。 そのトップキャラクターは`A`または`B`、ペアは消えます。 どちらかの文字を保持しても、最終結果が短くなることはありません。`AB`そして`BB`は有効な削除です。 

スタックが空の場合、`B`パートナーがいないので、留まらなければなりません。 以降の操作では、最初に別の文字をその前に配置せずにその文字を削除することはできません。文字は元の順序で処理されるため、これは不可能です。 

処理されたプレフィックスに対する帰納法により、スタックはそのプレフィックスの完全に縮小された形式のままになります。 スキャンが終了すると、その長さは達成可能な最終的な最小長になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        s = input().strip()

        stack = []

        for ch in s:
            if ch == 'A':
                stack.append('A')
            else:
                if stack:
                    stack.pop()
                else:
                    stack.append('B')

        answers.append(str(len(stack)))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```この解決策は、上で説明したスタック シミュレーションに従います。 

スタックには、これまでに処理されたプレフィックスの縮小形式が格納されます。 毎`A`すぐに削除に参加できないため、プッシュされます。 

とき`B`と表示される場合、可能性は 2 つだけです。 スタックが空でない場合、最上位の要素と現在の要素`B`一緒に消える。 これは、許可されている両方の操作に一致します。 スタックが空の場合、`B`存続するため、保管する必要があります。 

よくある間違いは、最上位かどうかを明示的にチェックすることです。`A`または`B`。 どちらもそうなのでそれは不要です`AB`そして`BB`取り外し可能です。 重要なのはキャラクターが存在するかどうかだけです。 

もう 1 つの簡単なバグは、生き残っていることを忘れることです。`B`スタックが空のときにプッシュする必要があります。 その手順がなければ、次のようなケースが発生します。`"B"`または`"BBB"`不正確な答えを生み出します。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        stack = []

        for ch in s:
            if ch == 'A':
                stack.append('A')
            else:
                if stack:
                    stack.pop()
                else:
                    stack.append('B')

        ans.append(str(len(stack)))

    return "\n".join(ans)
