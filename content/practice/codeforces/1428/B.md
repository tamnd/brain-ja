 ## 解決策
 ## 問題の理解

 部屋はサイクルを形成します。 連続した部屋の各ペアの間にはベルトコンベアがあり、各ベルトは時計回りに向けることができます (`>`)、反時計回り (`<`)、または両方向で使用可能 (`-`）。 

その部屋で開始したヘビが部屋を出て、後で許可されたベルトの指示に従って部屋に戻ることができる場合、その部屋はリターナブルと呼ばれます。 

有用なグラフ解釈は、各部屋を有向グラフの頂点として扱うことです。 すべてのベルトは、1 つの有向エッジまたは 2 つの有向エッジのいずれかに寄与します。 ある有向サイクルに属する頂点の数を数えなければなりません。なぜなら、部屋を通過する有向サイクルが存在するとき、ヘビは正確に出て行って、後で戻ってくる可能性があるからです。 

すべてのテスト ケースにわたる部屋の合計数は最大 300,000 です。 これにより、すべての部屋からグラフ検索を実行するアルゴリズムが即座に除外されます。 素朴なアプローチでは、大まかに次のことが必要になります。$O(n^2)$最悪の場合は動作します。$9 \times 10^{10}$操作時の操作$n = 300000$。 直線的な解決策が必要です。 

いくつかの状況は判断を誤りやすいものです。 

考慮する：```
1
5
>>>>>
```正しい答えは次のとおりです。```
5
```一見したところ、グラフは完全に一方向に見えますが、すべての部屋は円の周りの同じ方向のサイクルに属しています。 ヘビはどの部屋からでも、ぐるりと回って戻ってくることができます。 

考慮する：```
1
2
<>
```正しい答えは次のとおりです。```
0
```部屋 0 は部屋 1 にのみ移動でき、部屋 1 は部屋 0 にのみ移動できます。どちらの部屋にも、部屋から出て後で戻ることができる発信パスはありません。 グラフには有向サイクルが含まれていません。 

別の微妙なケースは次のとおりです。```
1
3

```正しい答えは次のとおりです。```
3
```不注意な解決策は、グローバルなサイクルの方向のみに焦点を当てる可能性があります。 ここで二人は`-`ベルトは局所的な双方向の動きを生み出し、すべての部屋がサイクルに参加できます。 

## アプローチ

 最も直接的な解決策は、有向グラフを構築し、すべての部屋を個別にテストすることです。 部屋ごとに DFS または BFS を実行して、部屋を出て最終的に戻ってくることができるかどうかを判断できます。 これは、返品可能性の定義を明示的にチェックするため、正しいです。 

問題はコストです。 グラフ検索には時間がかかります$O(n)$時間をかけて、そしてそれを全員に繰り返す$n$部屋に必要なもの$O(n^2)$。 と$n$300,000 に達すると、これは制限をはるかに超えます。 

何かをより速く見つけるには、グラフを任意の有向グラフとして扱うのではなく、グラフの構造を調べる必要があります。 

重要な観察は、世界的な状況が 2 つだけ考えられるということです。 

すべての有向ベルトが同じ円方向を向いている場合、つまりストリングに何も含まれていないことを意味します。`<`または何も含まれていません`>`の場合、円全体自体が有向サイクルになります。 どのお部屋も返品可能です。 

それ以外の場合は両方とも`<`そして`>`どこかに現れる。 その場合、円を周回するグローバルなサイクルは存在しません。 確実にサイクルに属することができる唯一の部屋は、サイクルに隣接する部屋です。`-`ベルト。 

なぜ？ あ`-`ベルトは、隣接する 2 つの部屋の間で両方向の動きを生み出します。 これら 2 つの部屋は、長さ 2 の有向サイクルを直ちに形成します。そのようなベルトに接触する部屋はどれも復帰可能です。 

両方のとき`<`そして`>`の一部ではないすべての有向エッジが存在します。`-`ベルトは世界的に一貫性のない方向性を持っています。 グラフにはこれより大きなサイクルを含めることはできません。 有向サイクルのみがこれらの双方向エッジから生じます。 

これにより、問題は少なくとも 1 つのエンドポイントである部屋を数えるという問題に軽減されます。`-`円全体が一貫して方向を向いていない限り、ベルトを使用しないでください。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ベルト構成文字列を読み取ります。 
2. 文字列に次のものが含まれているかどうかを確認します。`>`文字。 
3. 文字列に次のものが含まれているかどうかを確認します。`<`文字。 
4. これらの方向の少なくとも 1 つが欠けている場合、円全体はリングの周囲を単一の方向に移動できます。 すべての部屋は同じ有向サイクルに属しているため、出力`n`。 
5. それ以外の場合は、配列を作成します`good`長さの`n`、最初はすべて false です。 
6. ベルト位置ごとに`i`、 もし`s[i] == '-'`、マークルーム`i`そして部屋`(i + 1) mod n`良いです。 
7. 良好とマークされた部屋の数を数え、その数を出力します。 

ステップ 6 が機能する理由は、`-`ベルトは、その 2 つのエンドポイント ルーム間で両方向の移動を可能にします。 これらの部屋は移動してすぐに戻ることができ、定義を満たします。 

### なぜ効果があるのか

 円に 1 つの方向のみが含まれている場合は、すべてのベルトが実質的に時計回りであるか、すべてのベルトが実質的に反時計回りであるかのいずれかです。 サークルをたどると最終的には最初の部屋に戻るため、どの部屋も戻ることができます。 

さて両方とも仮定してみます`<`そして`>`現れる。 有向サイクルは、部屋の循環順序に従う必要があります。 2 部屋よりも長いサイクルでは、リングの全周にわたって一貫した方向を維持する必要がありますが、両方の方向が現れるため、これは不可能です。 残りのサイクルは、次のように作成された長さの 2 サイクルだけです。`-`ベルト。 このような各ベルトは、2 つの隣接する部屋を両方向に接続し、両方のエンドポイントを返却可能にします。 触れない部屋はない`-`ベルトはどのサイクルにも属すことができます。 

したがって、アルゴリズムは返却可能な部屋を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        has_left = '<' in s
        has_right = '>' in s

        if not has_left or not has_right:
            print(n)
            continue

        good = [False] * n

        for i, ch in enumerate(s):
            if ch == '-':
                good[i] = True
                good[(i + 1) % n] = True

        print(sum(good))

solve()
```最初の部分では、両方の方向が存在するかどうかを確認します。 1 つの方向が存在しない場合、すべての部屋がすぐにカウントされます。 

2 番目の部分では、混合方向のケースを処理します。 配列`good`部屋が何らかの双方向ベルトに隣接しているかどうかを記録します。 

表現`(i + 1) % n`部屋は円を形成するため、必須です。 いつ`i = n - 1`、次の部屋は部屋です`0`。 

ブール配列を使用すると、二重カウントが回避されます。 部屋は 2 つの異なるものに触れる可能性があります`-`ベルトですが、最終的な答えに貢献するのは 1 回だけです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    out = []

    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        has_left = '<' in s
        has_right = '>' in s

        if not has_left or not has_right:
            out.append(str(n))
            continue

        good = [False] * n

        for i, ch in enumerate(s):
            if ch == '-':
                good[i] = True
                good[(i + 1) % n] = True

        out.append(str(sum(good)))

    return "\n".join(out)
