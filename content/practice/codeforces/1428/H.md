 ## 解決策
 ## 問題の理解

 円形のロックを解除するように求められます。`n`車輪。 各ホイールには次の番号が付いています。`0`に`m-1`。 ロックには隠されたターゲットの組み合わせがあり、提案された一連の車輪位置を使用してロックをクエリできます。 ロックは、各ホイールから正しいターゲットまでの時計回りの最小回転距離を示します。 目標は、できるだけ少ないクエリを使用して完全な組み合わせを決定することです。 

正式には、価値のあるホイールの場合`x`そしてターゲット`t`、応答は`(t - x + m) % m`。 クエリを繰り返し行うことができ、このフィードバックのみを使用して非表示の配列を再構築する必要があります。 この問題は対話型です。つまり、各クエリは前の応答に依存します。 

制約は大きいです:`n`まで可能です`10^5`、 そして`m`まで可能です`10^9`。 組み合わせの合計空間は天文学的なものとなるため、これにより、考えられるすべての組み合わせをクエリするような総当り戦略が排除されます。 課題は、ロックの構造を使用して正しい数値を推測しながら、クエリの数を最小限に抑えることにあります。 

エッジケースには以下が含まれます`n = 1`、単一のクエリで十分な場合があります、そして`m = 1`、すべての車輪は自明です`0`。 もう 1 つの微妙なシナリオは、複数のホイールが同じターゲット値を持つ場合であり、各ホイールが一意であると仮定する単純な戦略を混乱させる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての組み合わせが試行されます。 クエリごとに、すべてのホイールの回転距離を受け取ります。 これは概念的には機能しますが、複雑さは次のとおりです。`O(m^n)`、それはたとえ小さくても実行不可能です`n`または中程度の`m`。 

最適なアプローチでは、**各ホイールで個別にバイナリ検索**を活用します。 単一ホイールの場合、ロックからの応答により正確なオフセットモジュロが得られます。`m`。 クエリを慎重に選択し、返された距離を解釈することで、毎回検索スペースを半分にできます。 ホイールはフィードバックにおいて独立しているため、各ホイールが独自の範囲を狭めることを可能にする賢いエンコーディング スキームを使用して、すべてのホイールを同時にクエリできます。 

重要な洞察は、各車輪の位置が単純なオフセットであるシーケンスをクエリすると、応答が各車輪がターゲットからどれだけ離れているかに直接対応するようになるということです。 応答の算術演算を使用して、各ホイールの二分探索を実行できます。`O(log m)`クエリ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n) | O(n) | 遅すぎる |
 | ホイールごとの二分探索 | O(n log m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`lo`長さの`n`すべてゼロと`hi`長さの`n`みんなで`m-1`。 これらは、各ホイールの現在の検索範囲を表します。 
2. すべてのホイールが収束するまで繰り返します (`lo[i] == hi[i]`みんなのために`i`):

 ａ． 各ホイールについて、現在の範囲の中点を選択します。`mid[i] = (lo[i] + hi[i]) // 2`。 これらすべての中間点を使用してクエリを構築します。 

b. クエリをロックに送信します。 回転距離の配列を受け取ります。 各距離は、推定値がターゲットモジュロからどれだけ離れているかを示します。`m`。 

c. ホイールごとに、検索範囲を更新します。 返された距離がターゲットが時計回りに通過していることを示している場合`mid[i]`、 セット`lo[i] = mid[i] + 1`; それ以外の場合は、設定します`hi[i] = mid[i]`。 
3. すべてのホイールが収束すると、アレイは`lo`正確なターゲットの組み合わせが含まれています。 

**機能する理由:** 各クエリにより、各ホイールの可能な値が約半分に減ります。 ホイールの応答は円モジュラー空間の推定値に対して単調であるため、二分探索は有効です。 この不変条件により、次の収束が保証されます。`O(log m)`ホイールごとのクエリ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    lo = [0] * n
    hi = [m-1] * n
    
    while True:
        mid = [(lo[i] + hi[i]) // 2 for i in range(n)]
        print("?", *mid, flush=True)
        resp = list(map(int, input().split()))
        
        if all(lo[i] == hi[i] for i in range(n)):
            break
        
        for i in range(n):
            if lo[i] != hi[i]:
                # distance modulo m
                target = (mid[i] + resp[i]) % m
                if target > mid[i]:
                    lo[i] = target
                else:
                    hi[i] = target
    print("!", *lo, flush=True)

if __name__ == "__main__":
    solve()
```この実装では、`mid[i]`が現在の範囲の中点として選択されます。 応答`resp[i]`を表します`(target[i] - mid[i]) % m`。 更新中`lo`そして`hi`ターゲットが時計回りかどうかに応じて、二分探索の不変性が保証されます。 フラッシュを使用すると、インタラクティブなフィードバックが正しく処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log m) | 各ホイールは独立して二分探索され、`log m`ホイールごとにクエリを実行し、すべてのホイールを並列に実行します。 |

 ## 特殊なケース

 のために`n=1, m=1`、アルゴリズムはすぐに設定します`lo=hi=0`。 クエリの戻り値`0`距離、ターゲットを確認します。 ターゲット ホイールが繰り返される場合、各ホイールは独立して収束します。 非常に大きい場合`m`、二分探索は依然として次のように収束します。`O(log m)`クエリ制限を決して超えないようにします。 循環の性質は、モジュロ演算によって正しく処理されます。`(mid + resp) % m`。 

このアプローチは堅牢で、インタラクティブに安全であり、最大の制約に合わせて拡張できます。
