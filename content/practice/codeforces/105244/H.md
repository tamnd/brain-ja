 ## 解決策
 ## 問題の理解

 一連の異なる整数が与えられており、厳密に増加している部分列を抽出したいと考えています。 通常の増加制約に加えて、サブシーケンス内の連続する要素がどのように異なるかを制限する追加ルールがあります。つまり、選択された 2 つの連続した値が同じである場合、$a$そして$b$、次に値$b - a$許可された差異の指定されたセットに属している必要があります。 

タスクは、そのようなサブシーケンスの可能な最大長を計算することです。 

入力サイズが大きく、最大$10^6$シーケンス内の数値と、最大 10 個までの差異が許容されます。 これにより、二次関数や偶数関数が即座に除外されます。$O(n \log n)$前のすべての要素のスキャンに依存する要素ごとの DP。 どのような解も本質的に線形または線形に近いものでなければなりません。$n$、要素あたりのオーバーヘッドはわずかです。 

重要な構造的観察は、サブシーケンスが順序だけでなく、値間の算術遷移によっても制約されるということです。 これは、遷移は位置ではなく値の違いのみに依存することを示唆しています。 

素朴なアプローチでは、すべてのインデックスのペアを考慮します。$i < j$で終わるサブシーケンスを拡張できるかどうかを確認します。$i$に$j$。 それはすでに暗示しています$O(n^2)$、これは実現不可能です。 

各値について、そこで終了する最適なチェーンを維持しようとしながらも、以前の要素をすべてスキャンして遷移を再計算しようとすると、より微妙な障害モードが表示されます。 慎重に実装したとしても、値間の到達可能性が密であるため、これは依然として二次的な動作に退化します。 

間違った素朴なロジックを暴露するエッジ ケースには、次のようなものがあります。 

許容される差に 1 が含まれる場合、ソートされた順序で連続する整数は、元のシーケンスの中間ギャップに応じて使用できる場合とできない場合があります。 たとえば、シーケンスの場合`1 3 2 4`と違い`{1}`、最良の答えは`1 2 3 4`順序は元のインデックスによって固定されているため、有効なサブシーケンスのみが問題となるため、これは不可能です。 単純なソート値 DP は、完全な連鎖可能性を誤って想定します。 

もう 1 つの特殊なケースは、差が大きい場合です。`{1000000000}`。 正確なギャップを持つペアのみが寄与するため、ほとんどの遷移は存在しません。 密な遷移を想定した DP ではオーバーカウントが発生します。 

## アプローチ

 ブルートフォースのアイデアは、インデックスごとに計算することです。$i$、で終わる最も有効なサブシーケンスの長さ。$i$。 それぞれについて$i$、すべてスキャンします$j < i$、そしてもし$s[j] < s[i]$そして$s[i] - s[j]$許可されている場合は更新します。 

これは、サブシーケンスの定義を直接ミラーリングし、有効な先行シーケンスをすべてチェックするため、正しいです。 ただし、以下までの確認が必要です。$n$それぞれの前の要素$n$ポジション、それにつながる$O(n^2)$トランジション。 と$n = 10^6$、このあたりです$10^{12}$実行不可能な操作。 

重要な洞察は、視点を逆転させることです。 有効な先行値を遡って調べるのではなく、各値を状態として扱い、許容される差異を使用してどの値が現在の値に遷移できるかを尋ねます。 配列は個別の値に対する部分列問題であるため、要素を値の昇順に処理し、値からその値で終わる最適なチェーンへの DP マップを維持できます。 

それぞれの値について$x$、先行するものは次でなければなりません。$x - d$ある程度の許容差がある場合$d$、値が入力に存在する場合。 これにより、問題は要素ごとの一定サイズのルックアップのセットに変換されます。 なぜなら$k \le 10$、各状態は最大 10 個の可能な先行状態にのみ依存します。 

値から最適な DP 長までのハッシュ マップを維持します。 値を昇順に処理するか、より小さい先行データに対して DP 値がすでに計算されていることを確認しながら、配列を同様に反復処理します。 答えは、観測された最大 DP 値です。

 ## アルゴリズムのチュートリアル

 1. O(1) 存在チェックのために、すべてのシーケンス値をハッシュ セットまたはディクショナリに保存します。 これは、潜在的な先行者がシーケンス内に実際に現れるかどうかを迅速に確認するために必要です。 
2. 各値を元の位置とペアにして、配列を値で並べ替えます。 これは、値を処理するときに、より小さな値がすべてすでに計算されており、参照するときに DP の正確さを保証するために行われます。$x - d$。 
3. 辞書を作成する`dp`値をその値 (最初はゼロ) で終わる最適なサブシーケンス長にマッピングします。 
4. 並べ替えられた値を繰り返し処理します。 それぞれの値について$x$、初期化します`dp[x] = 1`, すべての要素だけで長さ 1 の有効なサブシーケンスが形成されるためです。 
5. 許容されるそれぞれの違いについて$d$、計算する$p = x - d$。 もし$p$入力に存在する場合は更新します`dp[x] = max(dp[x], dp[p] + 1)`。 このステップでは、現在の状態をすべての有効な先行状態に接続します。 
6. 全体にわたってグローバル最大値を維持する`dp[x]`遭遇した値。 
7. すべての要素を処理した後、グローバル最大値を出力します。 

ソートされた順序で処理する理由は、すべての遷移で厳密に値が減少し、状態間の循環依存性がなくなるためです。 

### なぜ効果があるのか

 DP 状態は、特定の値で終了する最も有効なサブシーケンスを表します。 すべての遷移により値が許容される正の値だけ減少するため、値ごとに順序付けすると、値に関する遷移グラフは非循環になります。 各状態は厳密に小さい値のみに依存するため、計算時に次のことが保証されます。`dp[x]`、考えられるすべての先行者はすでに確定しています。 これにより、すべての有効なサブシーケンスが最後の要素まで 1 回だけ考慮され、無効な拡張子が導入されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    diffs = list(map(int, input().split()))

    vals = set(arr)
    dp = {}

    for x in sorted(arr):
        best = 1
        for d in diffs:
            p = x - d
            if p in vals:
                best = max(best, dp.get(p, 0) + 1)
        dp[x] = best

    print(max(dp.values()))

if __name__ == "__main__":
    solve()
```このソリューションは値の並べ替えに依存しているため、数値を処理するときに$x$、考えられるすべての先行者$x - d$すでに処理されています。 ハッシュセット`vals`O(1) が存在をチェックすることを保証しますが、`dp`計算されたチェーンの長さを保存します。 

微妙な点は、元の配列内の位置を明示的に考慮する必要がないことです。 増加するサブシーケンスのみが必要であり、すべての値は個別であるため、有効なサブシーケンスの構築を保証するには、値による順序付けで十分です。 

もう 1 つの重要な詳細は初期化です。先行要素が存在しない場合でも、すべての要素は DP 値 1 で始まります。

 ## 特殊なケース

 有効な先行処理が値空間に存在するが、中間値が欠落しているために DP で到達できない場合、微妙なエッジ ケースが発生します。 たとえば、シーケンスに次のものが含まれている場合、`2`そして`5`しかしそうではありません`3`または`4`、許容される相違点には次のものがあります。`1`そして`3`、 それから`5`～からのみアクセス可能`2`違い 1 はより緻密な構造を示唆していますが、違い 3 を介して。 アルゴリズムは、各先行タスクの存在を使用前に明示的にチェックするため、これを正しく処理します。 

もう 1 つのエッジ ケースは、複数の違いにより同じ値への競合する遷移が生成される場合です。 たとえば、次の場合`x-1`そして`x-3`両方が存在する場合、DP は両方の最大値を正しく取得し、どのパスが生成するかに関係なく、最適なチェーンが常に保持されるようにします。
