 ## 解決策
 ## 問題の理解

 長さのスタート抽選券を渡されます$n$。 すべての位置には、最初は数字の 1 が含まれています。各位置について$i$、必要な目標値があります$b_i$。 なんとか作ることができれば、$i$- 番目の位置に等しい$b_i$、私たちは稼ぎます$c_i$コイン。 

限られた数の操作を使用して、各位置を個別に変更できます。 1 回の操作でインデックスを選択します$i$と正の整数$z$、現在の値を増加させます$a_i$による$\lfloor a_i / z \rfloor$。 すべての位置は 1 から始まり、最大でも 1 から始まります。$k$すべてのインデックスにわたる合計オペレーション。 目標は、一部のポジションのサブセットが対応するポジションに到達するようにオペレーションを選択することです。$b_i$、完了したポジションからのコインの合計を最大化します。 

制約の規模は中程度ですが、運用予算は大きくなります。$n \le 1000$、$k \le 10^6$、 そして$b_i \le 1000$。 これは、私たちが、$k$操作スペースが大きすぎるため。 代わりに、各ポジションがどのくらいの速さで成長するかの構造を理解する必要があります。 

微妙な点は、運営は共有予算を通じてのみ相互作用するということです。$k$、各インデックスは独立して進化します。 各目標を達成するためのコストがわかった場合、その独立性は通常、ナップサック型の選択問題を示唆します。 

明らかではないエッジケースは、次のような状況から発生します。$b_i = 1$。 これらは操作を必要とせず、常に貢献します$c_i$。 もう一つのコーナーは、$k = 0$, ここで、すでに値 1 にあるもののみを取得できます。 

重要な問題は、1 を特定の値に変換するのにどれだけの操作が必要かを理解することです。$b_i$これは、操作定義が線形または標準の増分ベースではないためです。 

## アプローチ

 まず、単一のポジションがどのように進化するかを分析します。 

現在値から$x$、1 回の操作で次の場所に移動できます。$$x \rightarrow x + \left\lfloor \frac{x}{z} \right\rfloor$$誰にとっても$z \ge 1$。 可能な限り最善の選択は、添加量を最大化することです。 以来$\lfloor x/z \rfloor$最大化されるのは$z = 1$、最良の操作は常に次のとおりです。$$x \rightarrow x + x = 2x$$どれでも$z > 1$増分を減らすだけなので、目標に到達するために必要なステップ数を減らすことには役立ちません。 これにより、プロセスが純粋な 2 倍化に減ります。 

1から始めて、その後$t$操作で達成可能な最大値は$2^t$。 これもすべてのステップで最適であるため、これに達するか、それを超えるために必要な操作の最小数は$b_i$は：$$w_i = \lceil \log_2 b_i \rceil$$各位置が独立したアイテムになります: 位置の選択$i$費用$w_i$操作して価値を生み出す$c_i$。 合計コストが最大以下のサブセットを選択する必要があります$k$、合計価値を最大化します。 

これはまさに 0/1 のナップサック問題です。 唯一の問題は、$k$と同じ大きさにすることができます$10^6$、しかし実際の重さは$w_i$によって制限されています$\log_2(1000)$、これは最大でも 10 です。したがって、アイテム間のすべての重量の合計は最大でも約 10000 です。合計重量の合計を超えても安全にナップザックを実行できます。$k$、容量を切り捨てます。 

ブルート フォースの代替手段では、インデックスごとにすべてのサブセットとすべての可能な操作シーケンスが試行されます。これは指数関数的です。$n$そして指数関数的にも$k$、それはまったく実行不可能です。 最適な成長が常に 2 倍であるという観察により、オペレーティング システム全体が標準的な重み付き選択問題に崩壊します。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア: 各ポジションをコストと価値のペアに変換する

 1. 各ポジションごと$i$に到達するために必要な最小操作数を計算します。$b_i$1から始めます。 

これは次のように計算されます$w_i = \lceil \log_2 b_i \rceil$。 

このステップにより、複雑な操作システムがシンプルなコストで置き換えられます。 
2. もし$b_i = 1$、 セット$w_i = 0$。 

操作は必要ないので、このアイテムはいつでも無料で利益を得ることができます。 
3. すべての合計を計算します。$w_i$。 すべてのアイテムを合わせた以上の金額を費やすことはできないため、これが意味のあるナップザックの最大容量です。 
4. DP 配列を定義します。`dp[x]`正確に使用して取得できる最大コインです$x$操作。 
5.初期化`dp[0] = 0`他のすべての状態は負の無限大になります。 
6. 各位置の処理$i$そして標準の 0/1 ナップザック トランジションを適用します。 

容量ごとに$x$現在の最大値から$w_i$、 アップデート：$$dp[x] = \max(dp[x], dp[x - w_i] + c_i)$$7. 答えは全体の最大値です$dp[x]$のために$x \le k$ただし、重量の合計に制限されます。 

逆の反復$x$0/1 ナップザックの正確性を維持しながら、各アイテムが最大 1 回使用されるようにします。 

### なぜ効果があるのか

 どの状態からでも変換ステップは有効です。$x$の場合、演算には常に 2 倍という支配的な選択肢があります。 成長が遅い戦略では、しきい値に到達するまでのステップ数を減らすことができません。$b_i$2 倍と比較して、すべてのステップで厳密に小さな値が得られるためです。 したがって、到達までの最短時間は、$b_i$はまさに必要な倍加数です。 

各項目が他から独立した固定コストを持つと、問題は 1 つの制約を持つリソース割り当て問題になり、まさにナップザックになります。 DP の不変条件は、最初の$i$アイテム、`dp`は、それらのアイテムのみを使用して、考えられるすべての運用予算に対して達成可能な最高の値を保存します。 各遷移は実現可能性を維持し、項目を再利用しないため、無効な組み合わせは導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    weights = []
    for bi in b:
        if bi <= 1:
            weights.append(0)
        else:
            w = 0
            x = 1
            while x < bi:
                x *= 2
                w += 1
            weights.append(w)

    max_w = sum(weights)
    max_w = min(max_w, k)

    NEG = -10**18
    dp = [NEG] * (max_w + 1)
    dp[0] = 0

    for wi, ci in zip(weights, c):
        if wi == 0:
            for j in range(max_w + 1):
                if dp[j] != NEG:
                    dp[j] += ci
            continue

        for j in range(max_w, wi - 1, -1):
            if dp[j - wi] != NEG:
                dp[j] = max(dp[j], dp[j - wi] + ci)

    print(max(dp))

if __name__ == "__main__":
    solve()
```前処理ループは、各目標値を、その目標値に到達するために必要な 2 倍の数に変換します。 DP 配列は、これらの導出された重みに対する標準の 0/1 ナップサックになります。 コストがゼロの項目は常に含まれるため、すべての状態にその寄与を追加することによって個別に処理されます。 

重要な実装の詳細は、DP サイズを切り詰めることです。$\min(k, \sum w_i)$、次の場合でもソリューションを高速に保ちます。$k$大きいです。 

## 実用的な例

 小さな例を考えてみましょう。 

入力:```
n = 3, k = 3
b = [2, 3, 4]
c = [1, 1, 1]
```導出された重みは次のとおりです。 

- 2 には 1 倍加が必要です
 - 3 には 2 回の倍加が必要です
 - 4 には 2 回の倍加が必要です

 したがって、アイテムがあります:

 (1,1)、(2,1)、(2,1)

 DPの進化：

 | アイテム | 容量 0 | 1 | 2 | 3 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | -∞ | -∞ | -∞ |
 | (1,1) | 0 | 1 | -∞ | -∞ |
 | (2,1) | 0 | 1 | 1 | -∞ |
 | (2,1) | 0 | 1 | 2 | 2 |

 最良の結果は 3 回の操作で 2 コインです。 

これは、アルゴリズムが自然に安価なターゲットを最初に選択することを好みながらも、アイテムを最適に組み合わせることでメリットが得られることを示しています。 

2 番目の例:

 入力:```
n = 2, k = 1
b = [1, 2]
c = [5, 10]
```重み:

 - 1 → 0
 - 2→1

 DP は dp[0] = 0 から始まります。 

項目 (1,5) は無料で、どこにでも 5 が追加されます。 

dp = [5, 5]

 項目 (1,10) は 10 を加算します。 

dp = [15, 15]

 最初の項目には何も必要ないため、操作が 1 つだけでも答えは 15 になります。 

これにより、コストゼロの項目が常に自動的に含まれることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot \sum w_i)$| 各項目は、達成可能なすべての操作予算にわたって DP を更新し、総予算は対数重みによって制限されます。 
| スペース |$O(\sum w_i)$| 実行可能な操作数を超える 1D DP 配列のみが保存されます。 

それぞれなので$w_i \le 10$、合計 DP サイズは最大でも約$10^4$。 と$n \le 1000$、これは 1 秒のソリューションの制限内に十分収まります。

 ## 特殊なケース

 重大なエッジケースは、次のような場合です。$b_i = 1$。 この状況では、すべての重みがゼロになるため、DP はすべての重みを合計するように縮退します。$c_i$。 すべてのゼロコストアイテムがすべての状態に即座に適用され、容量を消費することなくすべての報酬を効果的に蓄積するため、アルゴリズムはこれを処理します。 

もう一つのケースは次のような場合です。$k = 0$。 重みがゼロのアイテムのみがアクティブのままになります。 DP はゼロ容量のみで初期化されるため、正の重みの項目は到達できず、何も寄与せず、要件と一致します。 

ような小さなターゲットの場合、$b_i = 2$、重みはちょうど 1 です。DP はこれらを単価項目として正しく処理し、限られた予算内で公平に競争できるようにします。 

変換ステップでは大規模な処理も可能$b_i$正しく。 たとえ$b_i = 1000$、計算された重みは最大 10 であるため、オーバーフローや過剰な DP 拡張は発生せず、パフォーマンスの安定性が維持されます。
