 ## 解決策
 ## 問題の理解

 記入するよう求められます$N \times m$2種類のピースを備えたグリッド。 1つは、$1 \times 1$コインタイル、もう1つは$1 \times 2$水平にも垂直にも置くことができるドル紙幣。 グリッドのすべてのセルを 1 回だけカバーする必要があるため、配置は完全なタイリングになります。 このようなすべてのタイリングの中で、正確に使用するタイリングのみを考慮します。$K$コインタイル。 タスクは、存在する有効なタイリングの数を数え、その結果を剰余として出力することです。$2^{32}$。 

重要な構造は次のとおりです$N$まで大きい$10^5$、 その間$m$これは、グリッドが高くて狭いことを直ちに示唆しているため、グリッドを行ごとに処理し、行全体で少量の状態のみを維持する必要があります。 タイリングを強引に列挙することは不可能です。$2 \times 4$グリッドにはすでに多くの構成があり、ウェイの数はエリアとともに指数関数的に増加します。 

単純なアプローチでは、タイルを再帰的に配置し、コインの使用量をカウントしようとします。 このアプローチは、すべてのセルが複数の配置選択肢に分岐し、垂直ドミノによって行間に依存関係が生じ、再帰がきれいに分離されないため、爆発的になります。 

重要な暗黙的なエッジ条件もいくつかあります。 もし$N \cdot m < K$、各コインが 1 つのセルを占めるため、答えはすぐにゼロになります。 もし$(N \cdot m - K)$が奇数である場合、残りの領域を完全にカバーすることはできません。$1 \times 2$タイルなので、答えもゼロでなければなりません。 正しい解決策は、このパリティ制約を尊重する必要があります。そうでないと、不可能なタイリングがカウントされてしまいます。 

## アプローチ

 ブルートフォースの観点では、各セルをコインまたはドミノの一部として扱い、カバレッジを確保しながらすべての配置を再帰的に試行します。 有効なタイリングはすべて最終的に生成されるため、これは概念的には機能しますが、検索ツリーは大きく分岐します。 垂直方向の制約を無視しても、各行は指数関数的なタイリングを持ちます。$m$、そして向こう側$N$これは完全に不可能になります。$10^{10^5}$可能性。 

重要な観察は次のとおりです$m \le 4$したがって、各行は、タイルが次の行とどのように相互作用するかを記述する小さなビットマスクで表すことができます。 これにより、問題はプロファイル DP に変わり、行ごとにスイープし、どのセルが前の行からの垂直ドミノによってすでに占有されているかを維持します。 

各行について、入力マスクが与えられた場合にそれを埋める方法を列挙し、出力マスクへの遷移を生成し、その行に配置されたコインの数を数えます。 コインの配置はローカルであり、残りのコイン予算による場合を除いて将来の制約に影響を与えないため、各遷移に重みを付けることができます。 

これにより、固定ステートマシンが生成されます。$2^m \le 16$マスク。各遷移には多項式の重みが付けられます。$x^c$、 と$c$その行で使用されるコインの数です。 加工後$N$行では、コインの指数の合計が正確に等しい場合の合計貢献度が必要です。$K$。 これは、エントリが次数で切り捨てられた多項式である遷移行列を生成することと同等です。$K$。 

解は小さな行列の累乗になります。$16 \times 16$行列。コイン数の畳み込みを使用して乗算が行われます。

 ## アルゴリズムのチュートリアル

 サイズのビットマスクによって各行をモデル化します。$m$ここで、ビットは、セルが前の行からの垂直ドミノによってすでに占有されているかどうかを示します。 このマスクは、タイリングを正しく続行するために必要な唯一の情報です。 

次に、単一行の遷移を定義します。 受信マスクから始めて、行を左から右に埋めようとします。 各位置には 3 つの可能性があります。コインを置く (セルを 1 つ消費し、コインの数を 1 つ増やす)、水平ドミノを置く (同じ行内の 2 つの隣接するセルを覆う)、または垂直ドミノを置く (現在のセルを覆い、次の行のセルを予約し、出力マスクを更新する) です。 行を完全に有効に埋めると、結果として出力マスクとその行で使用されるコインの数が生成されます。 

1. すべての状態をマスクとして列挙します。$0$に$2^m - 1$。 各状態は、行に入る保留中の垂直カバレッジを表します。 
2. マスクの各ペアについて$(a, b)$、受信マスクから開始して 1 行を埋めるすべての方法を計算します。$a$そして送信マスクで終わります$b$、使用されたコインの数を追跡します。 これにより、コイン数の分布が生成されます。 
3. これらの遷移をマトリックスに保存します$T$、各エントリは$T[a][b]$サイズの配列です$K+1$、単一行の変換によって正確にその数のコインが生成される方法が何通りあるかを数えます。 
4. この行列をべき乗します$N$。 行列の乗算は、コイン カウントの畳み込みとして定義されます。2 つの遷移を組み合わせると、コイン カウントが加算されます。 
5. 初期状態マスクから開始する$0$コインゼロで。 
6.べき乗後、マスクで終わるすべての方法を合計します。$0$(保留中の垂直ドミノはありません)$K$コイン。 

これが機能する主な理由は、各行が垂直ドミノ マスクを通じてのみ次の行と対話するためです。 行が処理されると、内部配置の詳細は無関係になり、送信マスクとコイン数のみが問題になります。 これにより、行が独立して構成され、コイン数が遷移全体で追加的に蓄積されるマルコフ スタイルのシステムが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 2**32

def build_transitions(m, K):
    from collections import defaultdict

    size = 1 << m
    trans = [[None for _ in range(size)] for _ in range(size)]

    def dfs(pos, cur_mask, next_mask, coins, incoming_mask, res):
        if pos == m:
            res[(next_mask, coins)] += 1
            return

        if cur_mask & (1 << pos):
            dfs(pos + 1, cur_mask, next_mask, coins, incoming_mask, res)
            return

        dfs(pos + 1, cur_mask, next_mask, coins + 1, incoming_mask, res)

        if pos + 1 < m and not (cur_mask & (1 << (pos + 1))):
            dfs(pos + 2, cur_mask, next_mask, coins, incoming_mask, res)

        dfs(pos + 1, cur_mask, next_mask | (1 << pos), coins, incoming_mask, res)

    for a in range(size):
        for b in range(size):
            trans[a][b] = [0] * (K + 1)

        res = defaultdict(int)
        dfs(0, a, 0, 0, a, res)

        for (b, c), cnt in res.items():
            if c <= K:
                trans[a][b][c] = cnt % MOD

    return trans

def mat_mul(A, B, K):
    size = len(A)
    C = [[ [0]*(K+1) for _ in range(size)] for _ in range(size)]

    for i in range(size):
        for k in range(size):
            if A[i][k] is None:
                continue
            for j in range(size):
                if B[k][j] is None:
                    continue
                for c1 in range(K+1):
                    if A[i][k][c1] == 0:
                        continue
                    for c2 in range(K - c1 + 1):
                        val = B[k][j][c2]
                        if val:
                            C[i][j][c1 + c2] = (C[i][j][c1 + c2] +
                                                 A[i][k][c1] * val) % MOD
    return C

def mat_pow(M, N, K):
    size = len(M)
    res = [[ [0]*(K+1) for _ in range(size)] for _ in range(size)]
    for i in range(size):
        res[i][i][0] = 1

    while N:
        if N & 1:
            res = mat_mul(res, M, K)
        M = mat_mul(M, M, K)
        N >>= 1
    return res

def solve():
    N, m, K = map(int, input().split())

    if (N * m - K) < 0 or ((N * m - K) % 2 != 0):
        print(0)
        return

    trans = build_transitions(m, K)
    M = mat_pow(trans, N, K)

    ans = 0
    for i in range(1 << m):
        ans = (ans + M[0][i][K]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、左から右にスキャンする DFS を使用して、すべての有効な行遷移を構築します。 マスクは垂直ドミノの制約を制御し、再帰はコイン、水平ドミノ、垂直ドミノのいずれを配置するかを決定します。 完了した各行は送信マスクとコイン カウントを生成し、それらは遷移構造に記録されます。 

次に、これらの遷移にわたって行列乗算が定義されます。 スカラー乗算の代わりに、各エントリはコイン数に関する多項式であるため、2 つの遷移を組み合わせる場合は畳み込みが必要です。 べき乗ステップでは、この行列を繰り返し 2 乗して処理をシミュレートします。$N$同じ行。 

微妙な点は、コイン数制限を適用するのは次のとおりです。$K$、これにより DP が制限されます。 もう 1 つの重要な詳細は、最終的な有効な構成は空のマスクで終了する必要があるため、保留中の垂直ドミノはすべて完全に解決されることです。 

## 実用的な例

 小さなケースを考えてみましょう$N = 2, m = 2, K = 1$。 マスクを 0 から 3 まで追跡します。 

簡略化されたトレースは、1 行の遷移がどのように動作するかに焦点を当てています。 

| ステップ | マスクの入荷 | 送信マスク | コイン | 意味 |
 | --- | --- | --- | --- | --- |
 | 1 | 00 | 00 | 2 | 2 枚のコインが列を埋めます |
 | 2 | 00 | 01 | 1 | 縦型ドミノを 1 つ使用 |
 | 3 | 01 | 00 | 0 | 縦型ドミノの完成 |

 2 行後、これらのトランジションの合成によってコイン カウントが蓄積されます。 最終的な DP テーブルでは、合計がちょうど 1 コインになるパスのみがカウントされます。 

これは、マスクによって隣接する行間の構造的妥当性が保証される一方で、コイン数が行全体でどのように蓄積されるかを示しています。

 ## 特殊なケース

 いつ$K = 0$、ソリューションは純粋なドミノ タイリングに退化しますが、コインの遷移が単に選択されないため、DP は引き続き機能します。 行列の累乗では、ドミノのみのタイルのみが正しくカウントされます。 

いつ$K = N \cdot m$、すべてのセルはコインである必要があるため、ドミノ配置を試みるすべてのトランジションは、複数のセルをカバーする必要があるため無効になります。 この場合、DFS 構造では当然、行ごとに有効な充填が 1 つだけ生成され、累乗によってそれが一貫して繰り返されます。 

パリティの場合$(N \cdot m - K)$が奇数の場合、アルゴリズムは DP の前にすぐに 0 を返し、不必要な計算を回避し、残りのセルをドミノにペアにすることが不可能であることを反映します。
