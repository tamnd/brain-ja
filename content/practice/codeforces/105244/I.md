 ## 解決策
 ## 問題の理解

 入力は、1 から n までの番号が付けられた頂点を持つツリーを表します。 最初の頂点を除くすべての頂点には、指定された親が 1 つだけあり、これにより各ノード i とその親 p_i の間の無向エッジが暗黙的に定義されます。 各ノードはインデックスが小さい親を指すため、構造はルート 1 の有効なツリーであることが保証されます。 

タスクは、u が v に等しいペアを含む、頂点 u と v のすべてのペアを考慮し、エッジ内のそれらの間の距離を計算し、それらの距離をすべて合計することです。 両方の端点が同じ頂点である場合、単一のペアはゼロに寄与し、それ以外の場合は一意の単純なパス上のエッジの数に寄与します。 

n が 300000 までの制約により、ペアごとに距離を計算しようとするソリューションからは遠ざけられます。 単純な全ペアの最短パス スタイルのアイデアでは、O(n^2) ペアを暗黙的に検査することになります。これは、最悪の場合でもすでに約 9e10 の演算であり、実行可能な制限をはるかに超えています。 すべてのペアを保存したり反復したりすることさえ、時間的にもメモリ的にも不可能です。 

すべてのノードからの単純な BFS または DFS では、さらに微妙な問題が発生します。 各走査は線形ですが、それを n 回繰り返すとコストが O(n^2) に増加しますが、これも制約の下で崩壊します。 

エッジケースは、数値的なものではなく構造的なものがほとんどです。 n が 1 の場合、エッジは存在しないため、ゼロ以外のパスも存在しないため、答えはゼロでなければなりません。 もう 1 つの特殊なケースは、非常に歪んだツリーです。これは、最大 300,000 の深さのために単純な再帰実装に重点を置き、反復的な走査または慎重な再帰処理を必要とします。 

## アプローチ

 ブルートフォース手法では、頂点の各ペア間の距離が明示的に計算されます。 開始頂点 u ごとに、BFS または DFS を実行して他のすべての頂点 v までの距離を計算し、それらの距離を累積します。 各走査のコストは O(n) で、n 個の開始点に対して繰り返されると、合計作業量は O(n^2) になります。 n が 300000 の場合、これには 10^10 のオーダーの操作が必要になりますが、これはリモートでは実行できません。 

重要な観察は、実際には個々の距離は必要ないということです。 すべてのパスにわたる各エッジの合計寄与のみが必要です。 2 つの頂点間のすべての単純なパスは、特定のエッジのセットをそれぞれ 1 回だけ交差します。 これにより、視点を頂点のペアからエッジに移すことができます。 

たとえばノードとその親の間のエッジを修正すると、このエッジを削除するとツリーが 2 つの接続されたコンポーネントに分割されます。 一方のコンポーネントのノードからもう一方のコンポーネントのノードに向かうパスは、このエッジを 1 回だけ通過する必要があります。 したがって、最短パスがこのエッジを使用するペアの数は、結果として得られる 2 つのコンポーネントのサイズの積となります。 

これにより、問題はサブツリー サイズの計算に変換されます。 ノード 1 でツリーをルートにすると、すべてのエッジがノードをその親に接続し、ノードをルートとするサブツリーのサイズから、そのエッジの片側にいくつの頂点があるかが直接わかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、親配列を隣接リストとして解釈します。 2 から n までの各ノード i は p_i に接続され、無向ツリーを形成します。

1. 2 から n までのすべての i に対して i と p_i の間にエッジを追加することにより、親表現から隣接リストを構築します。 これにより、サブツリーのサイズを正確に計算するために必要な両方向のトラバースが可能になります。 
2. ノード 1 でツリーをルートし、深さ優先探索を使用してサブツリーのサイズを計算します。 サイズ配列を維持します。ここで、size[v] は、v 自体を含む、v のサブツリーに存在するノードの数を表します。 
3. DFS 中に、ノードにアクセスし、そのすべての子のサイズを再帰的に計算します。 子 c を処理した後、size[c] を size[v] に追加します。 この集約ステップは、サブツリー情報を上方に蓄積するものです。 
4. すべてのサブツリーのサイズを計算した後、元の親リストの各エッジを評価します。 i と p_i の間のエッジについては、i をルートとするサブツリーがそのエッジの「子側」であると仮定します。 パスがこのエッジと交差するペアの数は、size[i] に n を掛けてから size[i] を引いた値になります。 
5. 2 から n までのすべての i にわたるこれらの寄与を合計して、最終的な答えを取得します。 

微妙な点は、距離を明示的に計算しないことです。 各エッジは独立して合計に寄与し、サブツリーのサイズによってそのエッジを使用するパスの数が完全に決まります。 

### なぜ効果があるのか

 頂点の各ペアには、ツリー内の固有の単純なパスがあります。 そのパスはエッジに分解でき、各エッジはそれを使用するペアごとに 1 回だけカウントされます。 エッジが削除されると、ツリーは 2 つの互いに素な頂点セットに分割されます。 ペアは、そのエンドポイントがその分割の異なるコンポーネントにある場合に限り、合計距離の合計に寄与します。 DFS 計算により、エッジごとに 1 つのコンポーネントのサイズが確実にわかります。これは、そのようなすべてのペアをエッジごとに 1 回正確にカウントするのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input().strip())
    if n == 1:
        print(0)
        return

    p = list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for i in range(2, n + 1):
        par = p[i - 2]
        g[i].append(par)
        g[par].append(i)

    size = [0] * (n + 1)

    def dfs(v, parent):
        size[v] = 1
        for to in g[v]:
            if to == parent:
                continue
            dfs(to, v)
            size[v] += size[to]

    dfs(1, -1)

    ans = 0
    for i in range(2, n + 1):
        s = size[i]
        ans += s * (n - s)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、親表現から隣接リストを構築することから始まります。 入力が有向親関係をエンコードしている場合でも、サブツリーの計算には双方向のトラバーサルが必要なため、これは不可欠です。 

DFS は、ノード 1 から開始して 1 回のパスでサブツリーのサイズを計算します。各ノードはそのサイズを 1 に初期化し、その子からのサイズを累積します。 親パラメータにより、前のノードに再度アクセスすることができなくなります。 

最後の累積ループは、各エッジ (i, p_i) が子側としてノード i に一意に関連付けられているという事実を使用するため、size[i] はまさにそのエッジ分割の 1 つのコンポーネントになります。 

一般的な実装の落とし穴は、再帰制限を増やさずに再帰を使用することです。これは、チェーン状のツリーでは失敗します。 もう 1 つの微妙な点は、親配列が p2 から始まるため、親配列に正しくインデックスが付けられていることを確認することです。 

## 実用的な例

 1 が 2 に、2 が 3 に、3 が 4 に接続された 4 つのノードの単純なチェーンを考えてみましょう。 

この入力の場合、親配列は次のとおりです。`1 2 3`。 ノード 1 から計算されたサブツリーのサイズを以下に示します。 

| ノード | 親 | サブツリーのサイズ |
 | --- | --- | --- |
 | 1 | - | 4 |
 | 2 | 1 | 3 |
 | 3 | 2 | 2 |
 | 4 | 3 | 1 |

 各エッジの寄与は、size[i] の n から size[i] を引いたものとして計算されます。 

i=2 の場合、寄与率は 3 × 1 = 3。i=3 の場合、寄与率は 2 × 2 = 4。i=4 の場合、寄与率は 1 × 3 = 3。合計は 10 です。 

これは、チェーン内のすべてのペアごとの距離の直接の列挙と一致します。この場合、距離は中間エッジにわたって自然に蓄積されます。 

次に、ノード 1 を中心とし、ノード 2、3、4 がすべて 1 に直接接続されているスターについて考えます。 

| ノード | サブツリーのサイズ |
 | --- | --- |
 | 1 | 4 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 各葉は 1 × 3 = 3 に寄与するため、合計の答えは 9 になります。これは、距離 2 を持つ葉のすべてのペアと、距離 1 を持つ葉と中心のすべてのペアに対応し、計算された合計と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードとエッジは、DFS および最終的な蓄積中に一定の回数処理されます。 
| スペース | O(n) | 隣接リストとサブツリー配列は線形サイズの構造を格納します。 

線形の複雑さは、最大 300000 までの n の制約内に快適に収まります。メモリ使用量も線形であり、隣接リストによって支配されており、512 MiB の制限内で許容されます。

 ## 特殊なケース

 n が 1 に等しい場合、アルゴリズムは構造を構築する前にすぐに 0 を返します。 これは、異なる頂点のペアが存在しないという事実と一致します。 

線形チェーンでは、再帰の深さは n に達します。 DFS は再帰的に書き込まれるため、スタック オーバーフローを避けるために再帰制限を増やす必要があります。 入力について`1 2 3 ... n-1`、サブツリーのサイズはルートからリーフに向かって厳密に減少し、各エッジの寄与は依然として size[i] の n から size[i] を引いたものとして正しくキャプチャされます。 

星型ツリーでは、中心を除くすべてのノードのサブツリー サイズは 1 です。このような各エッジは n マイナス 1 に寄与し、各エッジは親表現内の子ノードによって一意に識別されるため、すべての葉を合計すると二重にカウントされることなく正しい合計が得られます。
