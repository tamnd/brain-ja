 ## 解決策
 ## 問題の理解

 宇宙探検家は、一定の順序で天体を訪れます。 それぞれの物体は、研究すれば何らかの科学的価値をもたらしますが、エネルギーと時間という 2 つの限られたリソースも消費します。 探索者は、指定された順序でオブジェクトを処理し、それぞれについて調べるかスキップするかを決定する必要があります。 オブジェクトを選択すると、必要なエネルギーと時間を完全に消費します。 

目標は、合計の科学的価値を最大化しながら、使用される合計エネルギーが K を超えず、合計時間が M を超えないように、固定順序を尊重してこれらのオブジェクトのサブシーケンスを選択することです。 

出力は 2 つあります。 まず、達成可能な最大値を報告します。 次に、選択したオブジェクトのインデックスを訪問の昇順で出力します。 

制約は動的プログラミングのアプローチを示唆するのに十分厳しいものです。 N が最大 100 で、両方のリソース制限も最大 100 であるため、オブジェクトのプレフィックスごとにどれだけのエネルギーと時間が使用されたかを追跡する状態空間は小さいままです。 単純なサブセット列挙では、すべての 2^N サブセットを調べる必要がありますが、これは N=40 付近ですでに実行不可能になり、ここでは N が 100 に達するため、指数関数的な検索は直ちに除外されます。 

順序の制約から微妙な問題が発生します。 これは、アイテムを自由に並べ替えることができる標準的なナップザックではありませんが、決定は依然として各アイテムを順番に取得するかスキップするかのみに依存し、古​​典的な DP 構造が維持されます。 

エッジケースは、制約内にオブジェクトを取得できない場合に発生します。 たとえば、K=5 および M=5 で、すべてのオブジェクトが少なくとも 6 エネルギーまたは 6 時間を必要とする場合、どの選択も有効ではありません。 この場合、正しい出力は単一のゼロであり、空のシーケンスや空の行が続くゼロ値ではありません。 シーケンス ヘッダーを常に出力する単純な再構築アプローチでは、このケースの形式が簡単に崩れる可能性があります。 

もう 1 つの特殊なケースは、複数の最適なソリューションが存在する場合です。 有効なシーケンスはどれでも受け入れられるため、DP は辞書編集的な順序付けを強制する必要はありませんが、再構築は保存された決定と一貫性を保つ必要があります。 

## アプローチ

 ブルートフォース戦略は、包含マスクをチェックすることで暗黙的に順序を維持しながら、オブジェクトのすべてのサブセットを試すことです。 サブセットごとに、エネルギー、時間、価値を合計し、実現可能性を検証します。 これは問題の定義と直接一致するため概念的には機能しますが、2^N のサブセットを評価する必要があります。 N=100 の場合、これはおよそ 10^30 の候補を意味し、計算の限界をはるかに超えています。 

問題の構造から、決定間の相互作用は累積的なリソース使用によるものだけであることがわかります。 各オブジェクトは独立して価値、エネルギー、時間に寄与し、一度処理されると、残りの容量を除いて将来の移行には影響しません。 この独立性は、プレフィックスやリソース バジェットを考慮した動的プログラミングの定式化を示唆しています。 

各オブジェクトで、それをスキップするか取得するかを決定し、取得した場合は両方の残りの容量を減らします。 これにより、インデックス、使用エネルギー、使用時間に関する 3 次元の DP が自然に得られます。 N、K、M はいずれも最大 100 であるため、状態の総数は約 100 万個となり、それぞれの状態遷移は一定時間で行われるため効率的です。 

選択したシーケンスを再構築するために、DP 遷移中に決定を保存し、状態が現在の項目の取得とスキップのどちらから来たのかを記憶します。 最大値を持つ最終状態からバックトラックすると、必要なシーケンスが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 最適なDP | O(N・K・M) | O(N・K・M) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[i][j][k] を、最初の i 項目を使用して正確に j 個のエネルギーと k 時間を費やすか、または到達不可能な状態を負の無限大として扱うことで達成可能な最大値として定義します。

1. ゼロである dp[0][0][0] を除き、すべての dp 状態を到達不能として初期化します。 これは、アイテムもリソースも使用しない状態で開始することを表します。 
2. 1 から N までの項目を繰り返します。項目ごとに、前の層の到達可能なすべての状態からの遷移を伝播します。 
3. 各状態 dp[i−1][j][k] について、まず現在の項目をスキップすることを検討します。 結果が改善される場合は、dp[i][j][k] を同じ値で更新します。 これにより、リソースを消費せずに実現可能性が維持されます。 
4. また、j + Energy[i] ≤ K および k + time[i] ≤ M を条件として、現在の項目を取得することも検討します。 dp[i−1][j][k] + V[i] で dp[i][j + F][k + T] を更新します。 これは、アイテムを含めるかどうかの決定をエンコードします。 
5. dp 更新と並行して、状態がスキップまたはテイクから来たのか、およびその状態がどの前の (j, k) から発生したかを記録する親ポインターを保存します。 
6. すべての項目を処理した後、すべての dp[N][j][k] をスキャンして、最大値とそれに対応する状態を見つけます。 
7. i = 0 に達するまで保存された親ポインターを逆方向に移動し、項目を取得することが決定されたすべてのインデックスを収集することによってパスを再構築します。 

これが機能する理由は、すべての状態 (i、j、k) が、最初の i 項目を使用してそのリソース使用量を正確に達成するためのすべての可能な方法を要約しているという事実から来ています。 最適な解決策は、この空間の有効な状態に対応する必要があり、遷移には、すべての法的決定が省略や重複なく列挙されます。 各遷移では累積値の正確性が維持され、制約が尊重されるため、最終層の最大値は全体的に最適である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, M = map(int, input().split())
    items = []
    for _ in range(N):
        v, f, t = map(int, input().split())
        items.append((v, f, t))

    NEG = -10**18
    dp = [[[NEG] * (M + 1) for _ in range(K + 1)] for _ in range(N + 1)]
    parent = [[[-1] * (M + 1) for _ in range(K + 1)] for _ in range(N + 1)]
    take = [[[-1] * (M + 1) for _ in range(K + 1)] for _ in range(N + 1)]

    dp[0][0][0] = 0

    for i in range(1, N + 1):
        v, f, t = items[i - 1]
        for j in range(K + 1):
            for k in range(M + 1):
                if dp[i - 1][j][k] == NEG:
                    continue

                if dp[i][j][k] < dp[i - 1][j][k]:
                    dp[i][j][k] = dp[i - 1][j][k]
                    parent[i][j][k] = (j, k)
                    take[i][j][k] = 0

                nj, nk = j + f, k + t
                if nj <= K and nk <= M:
                    if dp[i][nj][nk] < dp[i - 1][j][k] + v:
                        dp[i][nj][nk] = dp[i - 1][j][k] + v
                        parent[i][nj][nk] = (j, k)
                        take[i][nj][nk] = 1

    best_val = 0
    bj = bk = 0
    for j in range(K + 1):
        for k in range(M + 1):
            if dp[N][j][k] > best_val:
                best_val = dp[N][j][k]
                bj, bk = j, k

    if best_val == 0:
        print(0)
        return

    res = []
    i, j, k = N, bj, bk
    while i > 0:
        pj, pk = parent[i][j][k]
        if take[i][j][k] == 1:
            res.append(i)
        j, k = pj, pk
        i -= 1

    res.reverse()
    print(best_val)
    print(*res)

if __name__ == "__main__":
    solve()
```DP テーブルは項目にわたってレイヤーごとに構築され、各状態が前の項目インデックスのみに依存することが保証されます。 スキップ遷移は前の値を前方にコピーしますが、テイク遷移は値を追加して両方のリソース カウンタを増加します。 

親配列とテイク配列には、選択したサブシーケンスを再構築するのに十分な情報が保存されます。 再構築は、最良の最終状態から空のプレフィックスに到達するまで逆方向に進み、テイク フラグが設定されているインデックスを収集します。 

微妙な点は、dp[0][0][0] のみを初期化し、その他はすべて到達不能として扱うことで、無効な部分状態が遷移に影響を与えるのを防ぎます。 

## 実用的な例

 3 つのオブジェクトと中程度の制約を持つ小さなインスタンスを考えてみましょう。 最適な解決策として、最初と 3 番目のオブジェクトを取得するが、リソース不足のため 2 番目のオブジェクトをスキップすることが含まれるとします。 

1 つの有効なパスについて概念的に dp 状態を追跡します。 

| ステップ | アイテム | 状態（エネルギー、時間） | 値 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | - | (0, 0) | 0 | 開始 |
 | 1 | 1 | (20, 3) | 100 | 取る |
 | 2 | 2 | (20, 3) | 100 | スキップ |
 | 3 | 3 | (30, 7) | 160 | 取る |

 このトレースは、スキップによってどのように状態が保存され、前の項目で容量がブロックされていた場合でも後の項目を取得できるようにする方法を示しています。 

ここで、すべての項目が制約を超えた場合を考えてみましょう。 

入力：```
2 5 5
10 6 1
20 1 6
```ここでは、どちらのアイテムも単独では適合しません。 DP は dp[0][0][0] から改善されないため、最良の値はゼロのままであり、再構築は不可能です。 

| ステップ | アイテム | 状態 | ベストバリュー |
 | --- | --- | --- | --- |
 | 0 | - | (0,0) | 0 |
 | 1 | 1 | 無効 | 0 |
 | 2 | 2 | 無効 | 0 |

 これにより、アルゴリズムが実行不可能な項目の選択を正しく回避していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・K・M) | N 個の項目のそれぞれが、定数遷移を使用してすべての K・M 状態を 1 回処理します。 
| スペース | O(N・K・M) | 完全な DP および再構成テーブルには、各プレフィックスの状態が保存されます。 

合計操作数は約 100 万で、N、K、M の制限 (最大 100) 内に問題なく収まります。また、数百万の整数が所定の 512 MiB 制限内に収まるため、メモリの使用も安全です。

 ## 特殊なケース

 すべてのアイテムがエネルギーまたは時間のいずれかにおいて高価すぎる場合、DP は初期状態を超えて進むことはありません。 最良の値はゼロのままであり、取得された項目の親ポインターが存在しないため、アルゴリズムはこれを正しく検出します。 出力は単一のゼロとなり、必要な形式と一致します。 

複数の最適パスが存在する場合、たとえば、同一の制約の下で同じ最大値を生成する 2 つの異なるサブセットなど、再構築は DP テーブルに最後に書き込まれた遷移に従います。 この問題では有効な答えが許容されるため、この非決定性は許容され、依然として正しい部分列が生成されます。 

K または M がゼロの場合、リソース消費がゼロのアイテムのみが選択可能になります。 制約により F ≥ 1 および T ≥ 1 が保証されるため、考えられる唯一の結果はゼロ値であり、アルゴリズムは初期化状態を通じて自然にこれを処理します。
