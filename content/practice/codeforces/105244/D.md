 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$m \times n$各セルには、そこに生えている木の数を表す負ではない数値が含まれています。 キリンは左上のセルから始まります$(1,1)$右下のセルに到達したいと考えています$(m,n)$。 

移動ルールは制約があり、異例です。 現在のどのセルからでも、キリンは一方向へのロングジャンプと垂直方向へのショートステップからなる動きを実行します。 あるタイプの動きでは、次のように下がります。$k$セルと 1 セル右に進み、もう一方のセルでは右に進みます$k$セルが 1 セル分減ります。 各移動は新しいセルに正確に着地し、キリンはその目的地のセルから葉を集めます。 

最初のセルは値を提供しません。 移動 1 から開始して、すべての移動に順番にラベルが付けられます。 奇数番目の動きではキリンは正確に餌を食べる$t$目的のセルから離れますが、偶数番目の移動では食べます。$3t$葉、どこ$t$はそのセル内の木の数です。 

タスクは、正確に終了する有効な一連の動きを選択することです。$(m,n)$、または、この交互得点ルールの下で食べた葉の総数を最大化しながら、それは不可能であると報告します。 

グリッドのサイズは最大です$100 \times 100$、 そして$k$も最大でも 100 です。 これにより、適度な数のステップでも組み合わせ爆発が発生するため、パス上の指数関数的な検索が即座に除外されます。 解決策では、これを最大でも数百万の状態を含む状態空間上の構造化された最短経路または最長経路問題として扱う必要があります。 

微妙な問題は、移動数のパリティによってすべてのセルの重みが変化することです。 つまり、セルを訪問する価値は固定されておらず、奇数のステップで到着するか偶数のステップで到着するかによって決まります。 パリティを無視し、各セルを単一の値を持つものとして扱うソリューションでは、誤った結果が生成されます。 

もう 1 つの明白ではないエッジ ケースは、到達可能性です。 移動するたびに両方の座標が変化しますが、ステップ サイズが非対称であるため、$(m,n)$構成に到達できません。 たとえば、次の場合$k$寸法に比べて大きい場合、ターゲットに正確に着地する一連の正当な動きは存在しない可能性があります。 このような場合、答えは次のようになります。$-1$たとえ部分的な移動が可能であっても。 

## アプローチ

 自然な最初の試みは、これを、からのすべてのパスにわたる総当たり検索として扱うことです。$(1,1)$に$(m,n)$。 各セルからは最大 2 つの可能な移動が存在するため、現在の位置と移動インデックスのパリティを維持しながら再帰的に探索します。 各パスの長さはおよそ次のとおりです。$O(m+n)$ステップ サイズ効果で除算されますが、依然として指数関数的な分岐が優勢です。 たとえ$100 \times 100$グリッドでは、境界に達するまで各ステップで 2 つの方向に分岐するため、可能なパスの数は実行可能な制限を超えて増加します。 

このブルート フォースが正しい理由は簡単です。すべての有効なパスを列挙し、パリティ ルールに従ってそのスコアを正確に評価します。 失敗のポイントは、正確さではなくスケールです。 分岐係数 2 が数十のステップにわたる可能性がある場合、状態の数は天文学的に多くなります。 

重要な観察は、問題はパスに関するものではなく、位置と移動カウントのパリティによって定義される状態に関するものであるということです。 特定のセルに到達し、次の動きが奇数か偶数かを知ると、その後のすべての動作はこの状態のみに依存し、どのようにしてそこに到着したかには依存しません。 これにより、問題は 2 つのレイヤー (奇数手用と偶数手用) を持つ階層化グリッド上のグラフ最短経路問題に変換されます。 

各州$(i,j,p)$、 どこ$p \in \{0,1\}$次の動きのパリティを表し、垂直方向に重い動きを適用するか水平方向に重い動きを適用するかに応じて、最大 2 つの状態に遷移します。 移行のコストは、パリティに応じて、宛先セルの値に 1 または 3 を乗じた値になります。 

これは現在、有向非巡回のような層状グラフ上の最長経路問題ですが、サイクルはインデックス空間に存在する可能性があるため、状態に対する標準の DP として扱い、収束するまで遷移を繰り返し緩和するか、BFS のような緩和を使用します。 州の数はこれだけなので、$2mn \le 20000$、これは効率的です。

 | ブルートフォース DFS | 指数 | O(mn) 再帰 | 遅すぎる |
 | 状態 (i、j、パリティ) の DP | O(mn) | O(mn) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルを定義します。$dp[i][j][p]$セルに到達したときに取得できる最大の葉を格納します$(i,j)$そして次の動きのパリティを持つ$p$、 どこ$p=0$次の手が奇数であることを意味し、$p=1$次の手が偶数であることを意味します。 このエンコーディングが選択されるのは、スコア乗数がムーブ インデックス パリティのみに依存するためです。 
2. 開始状態を除くすべての状態を非常に負の値に初期化します。$dp[1][1][0] = 0$、移動 1 を実行する前に最初から開始し、そこでは何も収集しないためです。 
3. 各状態から、2 つの移動タイプに対応する 2 つの遷移を試みます。$k$そして右に 1、または右に移動します$k$有効な移動ごとに、宛先セルを計算します。 
4. 宛先セルに遷移するときに、ゲインを計算します。 現在の移動パリティが奇数 (1 番目、3 番目など) の場合、追加します。$t$。 偶数の場合は追加します$3t$。 この重みは到着時に適用されるため、目的の状態に関連付けられます。 
5. 奇数の手が偶数になり、またその逆になるため、各手の後にパリティを反転します。 これにより、DP が交互のスコアリング ルールを正しく追跡できるようになります。 
6. すべての状態を複数回反復し、改善が得られなくなるまで遷移を緩和するか、単に次の範囲内で固定回数の反復を実行します。$2mn$、それぞれの緩和により経路長の次元が増加し、無限に改善することはできないためです。 
7. 答えは、セルの両方のパリティ状態の最大値です。$(m,n)$。 両方が負の無限大のままの場合、出力$-1$。 

### なぜ効果があるのか

 DP は、到達可能なすべての状態に対して次の不変条件を維持します。$(i,j,p)$、正しいパリティを持つセルで終了するすべての有効な動きのシーケンスの中で可能な限り最高のスコアが保存されます。 すべての遷移は、すでに有効なパスを 1 回の正当な移動によって拡張するだけであり、正しいパリティ依存の重みを 1 回だけ適用するため、正確さを維持します。 状態へのすべてのパスは前の状態と 1 つの移動に分解できるため、緩和を繰り返すと、最終的には到達可能なすべての状態に最適な値が伝播されます。 パリティ分割により、ムーブ インデックス アラインメントのみが異なる 2 つのパスが誤ってマージされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -10**18

def solve():
    m, n = map(int, input().split())
    k = int(input())
    grid = [None] + [[0] + list(map(int, input().split())) for _ in range(m)]

    dp = [[[INF] * 2 for _ in range(n + 1)] for _ in range(m + 1)]
    dp[1][1][0] = 0

    for _ in range(m * n * 2):
        changed = False
        for i in range(1, m + 1):
            for j in range(1, n + 1):
                for p in range(2):
                    if dp[i][j][p] == INF:
                        continue

                    cur = dp[i][j][p]
                    np = 1 - p

                    ni, nj = i + k, j + 1
                    if ni <= m and nj <= n:
                        gain = grid[ni][nj]
                        if p == 1:
                            gain *= 3
                        if dp[ni][nj][np] < cur + gain:
                            dp[ni][nj][np] = cur + gain
                            changed = True

                    ni, nj = i + 1, j + k
                    if ni <= m and nj <= n:
                        gain = grid[ni][nj]
                        if p == 1:
                            gain *= 3
                        if dp[ni][nj][np] < cur + gain:
                            dp[ni][nj][np] = cur + gain
                            changed = True

        if not changed:
            break

    ans = max(dp[m][n])
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```正しいスコアリングにはパリティが不可欠であるため、DP テーブルは 3 次元になっています。 各緩和ステップでは両方の動作タイプを試し、より良いスコアが見つかった場合は次の状態を更新します。 すべての改善は厳密に優れたパス スコアに対応し、有限状態空間によって終了が保証されるため、繰り返しの緩和は安全です。 

よくある実装上の落とし穴は、偶数の手でのみ 3 を掛けるのを忘れることです。これはここではパリティに相当します。$p=1$移動前に。 もう 1 つは、開始セルの初期化が間違っていることです。開始セルには、ツリーが含まれている場合でも、値を提供してはなりません。

 ## 特殊なケース

 主なエッジケースは、グリッドが小さすぎて移動できない場合です。 たとえば、$1 \times 1$グリッドでは、キリンは決して動かず、決して食べないため、答えはゼロでなければなりません。 

もう 1 つのエッジケースは次のような場合です$k$最初のステップの後、使用可能な寸法を超えます。 たとえば、次の場合$m=3, n=3, k=3$、ほとんどの移動はすぐに範囲外になり、目的地への有効なパスが残りません。 DP はすべての状態を到達不能に正しく保ち、最終的な答えは次のようになります。$-1$。 

より微妙なケースは、複数のパスが同じセルに到達するがパリティが異なる場合です。 DP は両方を明示的に保存するため、両方の寄与が保存されます。 これにより、わずかに長いパスによってより良い最終的な乗算器構造が得られる最適なソリューションが失われることが回避されます。
