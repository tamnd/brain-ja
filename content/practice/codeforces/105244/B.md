 ## 解決策
 ## 問題の理解

 n 個の頂点を持つツリーが与えられ、すべての頂点が数値を持ちます。 このツリーの接続コンポーネントを取得すると、そのコストは少し変わった方法で定義されます。つまり、そのコンポーネントの頂点の数に、それらの頂点に格納されている値の合計を乗算します。 

ツリーから頂点 u を 1 つだけ削除することができます。 u を削除すると、頂点とそれに接触するすべてのエッジが削除され、ツリーがいくつかの切り離されたコンポーネントに分割されます。 結果として得られる各コンポーネントには、上記のルールを使用して計算された独自のコストがあり、それらのコストを合計します。 目標は、この総コストができるだけ大きくなるように u を選択することです。 

入力構造はツリーのルート付きスタイルの親エンコーディングですが、概念的には単なる無向ツリーです。 制約は最大 3x10^5 頂点までであり、削除された頂点の候補ごとにコンポーネント構造を最初から再計算するソリューションは即座に除外されます。 二次関数やノードあたり O(n log n) であっても遅すぎるため、目的のソリューションは線形または線形に近いものでなければなりません。 

素朴な推論における微妙な問題は、削除された頂点にコンポーネントがどれほど強く依存しているかに気づかずにコンポーネントを独立して扱うことです。 たとえば、星形のツリーでは、中心を削除すると多数の単一ノード コンポーネントが生成されますが、葉を削除すると大きなコンポーネントが残ります。 サブツリーのサイズを追跡せずにローカル ノードの値のみを考慮する単純なアプローチでは、このようなケースの評価が誤ってしまいます。 

小さな例を考えてみましょう。 

入力:

 n = 4

 値 = [1、2、3、4]

 エッジ: 1-2、1-3、1-4

 頂点 1 を削除すると、3 つの孤立したノードが得られます。 合計コストは 1・2 + 1・3 + 1・4 = 9 となります。 

頂点 2 を削除すると、1 つのコンポーネント {1,3,4} が得られます。 コストは3・(1+3+4)=24です。 したがって、最適な選択はローカルでは明らかではありません。 それはグローバル構造に依存します。 

このコンポーネントのサイズと合計への依存が、問題を自明ではないものにしています。 

## アプローチ

 直接的な総当たり戦略は容易に想像できます。 すべての候補頂点 u について、それを削除し、DFS または BFS を実行して結果として得られるすべてのコンポーネントを見つけ、各コンポーネントのサイズと値の合計を計算し、コストを累積します。 各削除にはツリーの大部分を走査する必要があるため、頂点あたりの作業量が O(n) となり、最悪の場合には全体の操作が O(n^2) になり、これは最大 3×10^5 の n の制限をはるかに超えます。 

重要な点は、頂点を削除しても任意の構造が作成されるわけではないということです。 ルート付きツリーでは、u を削除すると、グラフが u を基準とした近傍のサブツリーに正確に分割されます。 各近傍は、完全なサブツリーまたは u のサブツリーの補数のいずれかを提供します。 これは、再計算されたコンポーネントではなく、サブツリーのサイズとサブツリー値の合計のみが必要であることを意味します。 

ツリーをルート化すると、すべてのエッジで親子関係が定義されます。 ノード u の場合、子へのすべてのエッジは、まさにそれらの子サブツリーであるコンポーネントに対応します。 残っている唯一のコンポーネントは「ツリーの残りの部分」です。これは、u のサブツリーを除いたツリー全体です。 

これにより、問題は 2 つの標準ツリー DP 配列 (サブツリー サイズとサブツリー合計) を事前計算することになります。 その後、各候補ルート削除は O(deg(u)) 時間で評価でき、すべての頂点にわたってこれは線形のままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適なツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 便宜上、任意のルートを頂点 1 に固定し、ツリーをそこから離れるように扱います。 

1. DFS を使用してルートからサブツリーのサイズとサブツリーの合計を計算します。

各ノード u について、サブツリー内のノードの数として size[u] を計算し、そのサブツリー内の値の合計として sum[u] を計算します。 この前処理により、「下位」コンポーネントに関する完全な情報が得られます。 
2. すべてのノード u について、ルート付きツリー内の隣接構造の観点から u を削除した効果を解釈します。 

u の各子 v は、v のサブツリーに等しい個別のコンポーネントになります。u より上のツリーの残りの部分は、1 つの追加コンポーネントになります。 
3. u の各子 v について、寄与率 size[v] × sum[v] を u の答えに加算します。 

サイズと合計の両方が前処理ですでにわかっているため、これはまさにそのコンポーネントに適用されるコスト定義です。 
4. u がルートではない場合、u のサブツリーの外側にある残りのコンポーネントの寄与を計算します。 

このコンポーネントのサイズは n − size[u]、合計 S − sum[u] です。ここで、S はすべてのノード値の合計です。 
5. u を削除するための総コストは、その子からのすべての寄与と、該当する場合は親側コンポーネントからの寄与の合計です。 
6. すべてのノード u の最大値を取得します。 

正確かどうかは、u を削除しても隣接するコンポーネントの内部構造が歪むことはなく、すでに明確に定義されたサブツリーまたはサブツリーの補体を分離するだけであるという事実にかかっています。 

前処理によって維持される不変条件は、任意のノードをルートとするすべてのサブツリーが、カットがそのサブツリーの上にある削除シナリオに現れる接続コンポーネントを 1 つだけ表すということです。 削除後のすべての可能なコンポーネントは子サブツリーまたはサブツリーの補完のいずれかであるため、必要な集約はすべてすでに使用可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    parent = [0] * n
    adj = [[] for _ in range(n)]
    
    p = list(map(int, input().split()))
    for i in range(1, n):
        parent[i] = p[i-1] - 1
        adj[parent[i]].append(i)
        adj[i].append(parent[i])

    sys.setrecursionlimit(10**7)

    sz = [0] * n
    sm = [0] * n

    def dfs(u, p):
        sz[u] = 1
        sm[u] = a[u]
        for v in adj[u]:
            if v == p:
                continue
            dfs(v, u)
            sz[u] += sz[v]
            sm[u] += sm[v]

    dfs(0, -1)

    total_sum = sum(a)
    ans = -10**30

    def dfs2(u, p):
        nonlocal ans

        cur = 0

        for v in adj[u]:
            if v == p:
                continue
            cur += sz[v] * sm[v]

        if p != -1:
            rest_sz = n - sz[u]
            rest_sm = total_sum - sm[u]
            cur += rest_sz * rest_sm

        ans = max(ans, cur)

        for v in adj[u]:
            if v == p:
                continue
            dfs2(v, u)

    dfs2(0, -1)

    print(ans)

if __name__ == "__main__":
    solve()
```最初の DFS は、古典的なサブツリー DP 配列を構築します。 2 番目の DFS は、各インシデント コンポーネントからの寄与を合計することによって、各ノードを削除された頂点として評価します。 唯一の微妙な点は、「親側」コンポーネントを正しく処理することです。そのため、コンポーネントを明示的に再構築しようとするのではなく、合計と合計サイズからサブツリー情報を差し引いた情報に依存しています。 

## 実用的な例

 ### 例 1

 入力:

 n = 4

 a = [1、2、3、4]

 エッジ: 1-2、1-3、1-4

 ルート 1 のサブツリー値を計算します。 

| ノードが削除されました | 子コンポーネントの貢献 | 親コンポーネントの貢献 | 合計 |
 | --- | --- | --- | --- |
 | 1 | 1・2 + 1・3 + 1・4 = 9 | なし | 9 |
 | 2 | 0 | 3・(1+3+4)=24 | 24 |
 | 3 | 0 | 3・(1+2+4)=21 | 21 |
 | 4 | 0 | 3・(1+2+3)=18 | 18 |

 最良の選択は、ノード 2 を削除することです。これにより、大規模な高額コンポーネントが分離されます。 

これは、最適な選択は、多くの場合、局所的な除去コストではなく、残留構造の積を最大化することから得られることを裏付けています。 

### 例 2

 入力:

 n = 5

 a = [1、-1、-1、-1、-1]

 チェーン: 1-2-3-4-5

 ここではサブツリーの合計が大きく交互に現れるため、異なる位置で分割すると符号の相互作用が変化します。 

| 削除されました | コンポーネント | 合計 |
 | --- | --- | --- |
 | 3 | 左 {1,2}、右 {4,5} | 2・0 + 2・(-2) + 2・(-2) = -8 |
 | 1 | {2,3,4,5} | 4・(-4) = -16 |

 中間の除去は、負の質量をより小さな成分にバランスさせ、負の積の大きさを減らすため、より優れています。

 ## 特殊なケース

 重要なエッジ ケースは、削除された頂点がルートである場合です。 この場合、親側コンポーネントは存在せず、子サブツリーのみが寄与します。 親インジケーターが -1 で補数の計算をスキップするため、アルゴリズムはこれをきれいに処理します。 

もう 1 つのケースは縮退チェーンです。 このようなツリーでは、削除ごとに最大 2 つのコンポーネントが作成され、正確さは補数のサイズと合計を適切に計算することに完全に依存します。 total_sum からサブツリーの合計を引いたものを使用すると、内部ノードを特殊なケースにする必要がなくなります。 

星型ツリーの場合、サブツリーのサイズはルートの配置に応じて 1 または n−1 になります。 サブツリー DP がすべての子の寄与を正しく捕捉し、リーフを削除するときに親側の項が支配的になるため、このアルゴリズムは引き続き機能します。 

すべての場合において、サブツリー コンポーネントと補完への分解により、隠れたコンポーネント構造が見逃されることはありません。
