 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられ、複数の独立したクエリに答えるように求められます。 各クエリはターゲット値を提供します$x$そして、要素が正確に乗算される連続した部分配列が存在するかどうかを判断する必要があります。$x$。 

言い換えれば、クエリごとに、その積が指定された数値と等しいセグメントが配列に含まれているかどうかをチェックしています。 セグメントは連続している必要があり、異なるクエリは互いに独立しています。 

制約は、すべてのテスト ケースにわたる配列の合計長が最大で次であることを示します。$2 \cdot 10^5$、クエリの合計数も最大です。$2 \cdot 10^5$。 これにより、クエリごとに部分配列の積を最初から再計算したり、クエリごとにすべての部分配列を個別に明示的に列挙したりするソリューションは直ちに除外されます。 テスト ケースごとに 2 次式のアプローチであれば、約$10^{10}$最悪の場合の作戦は実行可能をはるかに超えています。 

微妙な難しさは、サブ配列の数だけでなく、積のサイズにもあります。 適度に長いサブ配列であっても、一般的な整数の範囲をオーバーフローするため、早期に停止しない単純な乗算は遅いだけでなく、数値的に安全でもありません。 

いくつかの危険な状況については、覚えておく価値があります。 

たとえば、配列に多くのものが含まれている場合、$a = [1, 1, 1, 1]$、その場合、すべてのサブ配列は積 1 になります。積を「拡大」しようとする単純なアプローチでは、1 を乗算しても値が変わらないため、処理が進まずに過剰にループする可能性があります。 

クエリで、サブ配列積として表示されない値が要求された場合、次のようになります。$x = 12$のような配列で$[2, 3, 6, 1, 4]$の場合、多くの部分配列は部分的に次の要素と一致します。$x$ですが、完全に一致するものは存在しません。 完全な検証を行わずに、可分性または部分的な因子一致のみをチェックするアプローチでは、そのようなケースが誤って受け入れられる可能性があります。 

最後に、すべての数値は正であるため、稼働中の製品が次の値を超えると、$x$、それはさらに増加するだけであり、これは正しい解決策が利用しなければならない強力な剪定の機会を与えます。 

## アプローチ

 最も直接的なアイデアは、すべての部分配列を列挙し、その積を計算することです。 開始インデックスごとに$l$、延長します$r$右側で、一致するまで要素を乗算します。$x$または製品がそれを超えます。 正確にヒットしたなら$x$、そのクエリを早期に停止できます。 

このアプローチは、考えられるすべての候補セグメントを明示的にチェックするため、正しいです。 ただし、最悪の場合の動作はテスト ケースごとに 2 次です。 配列が大きく、1 のような小さな値が多数含まれている場合、積は長時間にわたって小さいままとなり、各開始位置がサフィックスのほぼ全体をスキャンする可能性があります。 これは約につながります$O(n^2)$テストごとの乗算は遅すぎます。$n$まで$2 \cdot 10^5$すべてのテストにわたって。 

重要な点は、すべてのクエリのすべてのサブ配列を個別に考慮する必要がないということです。 開始インデックスが固定されている場合、そのテスト ケースで積が最大クエリ値を超えると、拡張を安全に停止できます。 すべての数値が正であるため、セグメントを拡張すると積は単調になり、それ以上拡張しても有効な値に戻すことはできません。 

これにより、開始位置ごとに、到達可能なすべてのサブ配列積を妥当なカットオフまで事前に計算し、それらをハッシュ セットに格納することができます。 その後、各クエリは単純なメンバーシップ チェックになります。 

これは理論的には依然として最悪の二次構造を持っていますが、積が単調に増加するため、実際には、特に値が大きい場合、多くのセグメントが早期に終了することが保証されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列とすべてのクエリを読み取り、最大クエリ値を計算します。$X_{\max}$。 この値より大きいサブ配列積はクエリに答えることができないため、この値は積拡張のカットオフとして機能します。 
2. 有効な候補であるすべてのサブアレイ積を格納する空のハッシュ セットを初期化します。 
3. 各開始インデックスについて$l$、実行中の製品を 1 として初期化します。 
4. 右側のエンドポイントを延長します$r$から$l$に$n$、現在の積を乗算します。$a[r]$。 商品が数量を超え次第、$X_{\max}$、ここからの延長はやめます$l$、さらに拡張しても増加するだけであるためです。 
5. 製品を更新するたびに、それをセットに挿入します。 これにより、カットオフまでの到達可能なすべてのサブアレイ積が確実に記録されます。 
6. すべての開始点を前処理した後、クエリの値がセット内に存在するかどうかを確認して各クエリに答えます。 

正確さは、すべての有効な部分配列がペアとして 1 回だけ考慮されるかどうかにかかっています。$(l, r)$また、クエリに役に立たない値を超えた場合にのみ拡張を停止するため、有効な製品を見逃すことはありません。 

### なぜ効果があるのか

 固定開始インデックスの場合、すべての要素が正であるため、右に拡張する積の順序は厳密には減少しません。 これにより、製品が超過すると、$X_{\max}$、それ以上の拡張では、クエリに一致する値を生成できません。 したがって、枝刈りによって潜在的に有効な答えが排除されるわけではありません。 すべてのサブ配列は正確に 1 つの開始点から生成されるため、関連する範囲までのすべての可能な積がセットに含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        queries = [int(input()) for _ in range(q)]

        x_max = max(queries)

        seen = set()

        for l in range(n):
            prod = 1
            for r in range(l, n):
                prod *= a[r]
                if prod > x_max:
                    break
                seen.add(prod)

        out = []
        for x in queries:
            out.append("YES" if x in seen else "NO")
        print("\n".join(out))

if __name__ == "__main__":
    solve()
```コア構造は開始位置と終了位置にわたる二重ループですが、実行中の製品が最大クエリ値を超えるとハード カットオフになります。 このカットオフは不可欠です。 これがないと、ソリューションはすぐにタイムアウトになってしまいます。 

ハッシュ セットには、到達可能なすべての製品が格納され、各クエリは一定時間のメンバーシップ チェックに減ります。 このソリューションは、Python の多倍長整数を利用して、オーバーフローを心配することなく中間乗算を安全に処理します。

 ## 特殊なケース

 配列が完全に 1 で構成されている場合、拡張子ごとに積は変更されません。 アルゴリズムは依然としてすべての部分配列に値 1 を正しく挿入し、セット内で 1 より大きいクエリが見つかることはありません。 

単一要素配列の場合、長さ 1 の部分配列のみが存在するため、アルゴリズムは開始ごとに 1 つの積のみを生成し、これが正確性条件に直接一致します。 

すべての要素が等しく 1 より大きい場合、拡張するにつれて製品は指数関数的に増加します。 これにより枝刈りが効果的になり、内側のループが迅速に終了するようになり、実際には二次関数の爆発が防止されます。
