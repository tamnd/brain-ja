 ## 解決策
 ## 問題の理解

 固定の市松模様の色を持つ 1000 × 1000 のグリッドが与えられます。 セル (x, y) は、x + y が偶数の場合は白、それ以外の場合は黒になります。 各テスト ケースでは 2 つの整数 a と b が与えられ、セットにちょうど 1 個の白セルとちょうど b 個の黒セルが含まれるように接続されたセルのセットを選択できるかどうかを判断する必要があります。 可能であれば、そのような接続されたセットをその座標をリストすることによって出力する必要があります。 

接続は標準の 4 方向隣接であるため、選択した 2 つのセルは、選択したセット内の共有エッジを経由して相互に到達可能である必要があります。 重要な問題は、単に 2 色の任意の数を選択するだけではなく、選択したセルが 1 つの連結成分を形成するように強制していることです。 

制約の合計サイズは大きくなりますが、各テスト ケースは独立しており、すべての a + b の合計は最大 10^6 です。これは、各コンポーネントをそのサイズの線形時間で明示的に構築する必要があることを強く示唆しています。 テスト ケースごとに 1000 x 1000 グリッド全体にわたる検索を伴うものはすべて不要であり、繰り返すと非常に遅くなります。 

微妙な制約は、グリッドが 2 部構成であることです。 これは、接続された領域が、各ステップで色が反転する開始セルからのパス状の拡張のように動作することを直ちに意味します。 これにより、任意の (a, b) ペアのマッチングにおける柔軟性が制限されます。 

主なエッジケースは不均衡から生じます。 a または b が 0 の場合、1 色のみを使用することになりますが、チェッカーボード グリッド内の単色で誘導されたサブグラフは、同じ色のセルが直交することがないため、完全に切り離されます。 したがって、a > 0 かつ b = 0、またはその逆の場合は、カウントが正確に 1 でない限り不可能です。 

残りのターゲット カラー分布の接続性を確保せずに、貪欲にパスを拡張しようとすると、別の障害モードが発生します。 単純なアプローチでは、やみくもに色を交互に変更する可能性がありますが、実際には、1 つの色の余剰を制御できる構造が必要です。 

## アプローチ

 強引なアイデアは、すべての開始セルから BFS を介して接続コンポーネントを構築し、選択した白と黒のセルの数を追跡し、(a, b) が一致したときに停止することです。 BFS は接続されているすべてのシェイプを列挙するため、これは概念的には正しいですが、まったく実行不可能です。各 BFS は最大 10^6 ノードを探索し、多くの開始または多くのテスト ケースに対してこれを行うと、二次的な動作が発生します。 

重要な観察点は、グリッドが規則的で二部構成であるため、構築する接続された形状は成長するツリーとして扱うことができるということです。 グリッドを検索する代わりに、(1, 1) から始まる単一の長い蛇のようなパスを明示的に構築し、どこまで伸ばすか、どのように分岐するかを選択することでカラー バランスを制御します。 

重要なトリックは、最初に長い交互のパスを構築することです。これにより、開始色と長さのパリティに応じて、ほとんど同じ数の白と黒のセルが自然に得られますが、その違いは最大で 1 つです。 次に、パスの近くに長さ 2 の小さな迂回路を取り付けてアンバランスを調整します。 長さ 2 の迂回により色が 2 回反転され、接続を切断することなく 1 つの色数を増やすことができます。 

具体的には、白マスからスタートします。 パスでは色が決定的に交互になります。 単純なパスが提供するものを超えて黒よりも多くの白が必要な場合、またはその逆の場合は、既存のノードから小さな 2 段階の拡張である「バンプ」を挿入します。これにより、接続ポイントのパリティに応じて (白 1 つ、黒 1 つ) またはバイアスのいずれかをローカルに追加します。 

この構築はグリッド グラフ上で制御された成長プロセスとなり、すべての新しいセルがすでに選択されているセルに隣接し、接続が自動的に維持されます。

 ## アルゴリズムのチュートリアル

 コンポーネントをセルごとに構築する直接的な構築的戦略について説明します。 

まず、実現可能性を確認します。 a + b = 1 の場合、単一のセルは自明に接続されているため、答えは常に可能であり、(1, 1) を選択するだけです。 a または b のいずれかが 0 で、合計が 1 より大きい場合は、単色の接続領域がチェッカーボード グリッドに存在できないため、直ちに拒否されます。 

次に開始色を決めます。 常に白の (1, 1) から開始します。 これにより構造が固定され、パリティ推論が簡素化されます。 

次に、グリッド内に長い蛇行パスを構築します。 行の終わりまで右に移動し、次に 1 ステップ下がって方向を逆にし、このパターンを繰り返します。 これにより、ハミルトニアンのような長方形の横断が得られます。 この走査に沿って、少なくとも a + b 個のセルが選択可能になるまでセルを収集します。 グリッドが十分に大きいので、常に十分なスペースが確保されます。 

この時点で、この走査から最初の a + b セルを取得します。 これにより、接続されたパスのような形状が作成されます。 この接頭辞に含まれる白人と黒人の数を計算します。 

カウントがすでに一致している場合 (a、b)、完了です。 

それ以外の場合は、黒に対して白の数を増やす必要があるとします。 構築されたパスに沿ってスキャンし、少なくとも 1 つの未使用の隣接セルを持つ黒いセルを探します。 グリッド構造のため、すべての内部セルにはパスの外側に追加の隣接セルがあるため、そのような場所は常に存在します。 その黒色のセルから、まだ使用されていない白色の新しい隣接セルを接続します。 これにより、接続を維持しながら白いセルが 1 つ追加されます。 

代わりにさらに多くの黒セルが必要な場合は、白セルの隣に対称的に接続します。 

カウントが正確に一致するまで、この調整を繰り返します。 各調整では新しい未使用のセルが使用され、必要な合計サイズは a + b によって制限されるため、1000 x 1000 のグリッド内のスペースが不足することはありません。 

### なぜ効果があるのか

 すべての新しいセルが共有エッジによって既存の選択されたセルに接続されるため、この構築ではすべてのステップで単一の接続コンポーネントが維持されます。 初期パスは、基本構造の接続を保証します。 各修正ステップはリーフ ノードを追加するだけで変更されるため、再構築を必要とせずに接続が維持されます。 

カウントの正確さは、すべての操作でカラー カウントの 1 つだけが +1 変更され、もう 1 つは変更されないままになるという不変条件から導き出されます。 パス接頭語から派生した既知の (最初の白、黒) ペアから開始し、各ステップがターゲットに向かって進むため、間違った方向にオーバーシュートすることなく、最終的には (a, b) に到達する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def color(x, y):
    return (x + y) & 1  # 0 white, 1 black

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())

        if a + b == 1:
            print("YES")
            print(1, 1)
            continue

        if a == 0 or b == 0:
            print("NO")
            continue

        # build a simple snake path
        cells = []
        n = 1000

        x = 1
        y = 1
        dir_right = True

        while len(cells) < a + b:
            cells.append((x, y))
            if dir_right:
                if y < n:
                    y += 1
                else:
                    x += 1
                    dir_right = False
            else:
                if y > 1:
                    y -= 1
                else:
                    x += 1
                    dir_right = True

        # count colors
        w = b0 = 0
        for i in range(a + b):
            if color(*cells[i]) == 0:
                w += 1
            else:
                b0 += 1

        # we now adjust by local expansions if needed
        used = set(cells[:a + b])
        res = cells[:a + b]

        def add_extra(desired_white):
            nonlocal w, b0, res, used
            for i in range(len(res)):
                x, y = res[i]
                for dx, dy in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                    nx, ny = x + dx, y + dy
                    if 1 <= nx <= 1000 and 1 <= ny <= 1000 and (nx, ny) not in used:
                        used.add((nx, ny))
                        res.append((nx, ny))
                        if color(nx, ny) == 0:
                            w += 1
                        else:
                            b0 += 1
                        return

        # fix imbalance greedily
        while w != a or b0 != b:
            if w < a:
                add_extra(True)
            else:
                add_extra(False)

        print("YES")
        for x, y in res:
            print(x, y)

if __name__ == "__main__":
    solve()
```このコードは、些細な不可能性を処理することから始まります。単一セルのケースは常に有効ですが、1 つの色のみを使用し、複数のセルを使用するリクエストは直ちに拒否されます。 

スネーク構造は行方向のジグザグとして実装されているため、常に境界内に留まり、長く接続されたトラバースが生成されます。 最初の a + b セルが基本コンポーネントとして取得されます。 

次に、座標のパリティを使用して色分布を計算します。 その後、調整を追加するときに座標を再利用しないように、使用されたセルのセットを維持します。 

調整機能は現在の構造をスキャンし、隣接する未使用のセルを接続して接続を保証します。 ループは、カウントがターゲットと正確に一致するまで継続します。 

## 実用的な例

 a = 5 および b = 4 の場合を考えてみましょう。(1, 1) から開始してスネーク パスを構築します。 

| ステップ | 追加されたセル | 白カウント | 黒カウント |
 | --- | --- | --- | --- |
 | 1 | (1,1) | 1 | 0 |
 | 2 | (1,2) | 1 | 1 |
 | 3 | (1,3) | 2 | 1 |
 | 4 | (1,4) | 2 | 2 |
 | 5 | (1,5) | 3 | 2 |
 | 6 | (2,5) | 3 | 3 |
 | 7 | (2,4) | 4 | 3 |
 | 8 | (2,3) | 4 | 4 |
 | 9 | (2,2) | 5 | 4 |

 この時点ではすでに (5, 4) と一致しているため、調整は必要ありません。 工事はただちに中止される。 

ここで、a = 3、b = 1 という歪んだケースを考えてみましょう。単純な接頭辞では (2, 2) が得られる可能性があります。 余剰の黒を検出し、構造内の有効な白セルから余分な白の隣接セルを追加します。たとえば、未使用が許可されない場合は (1, 2) から (2, 2) に拡張するため、代わりに未使用の隣接境界セルを選択します。 このプロセスはカウントが (3, 1) になるまで続きますが、新しいセルはそれぞれ 1 つのエッジで接続されるため、接続はそのまま残ります。 

これらの例は、ベース パスがほぼバランスのとれた構造を提供し、小さなローカル アタッチメントが不一致を修正することを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、カウントの 1 つがゼロで、合計が 1 を超える場合です。 単色の選択は市松模様のグリッドに接続できないため、アルゴリズムはこれらを即座に拒否します。 たとえば、黒セルは決して互いに接触しないため、入力 (0, 3) は NO を出力する必要があります。 

もう 1 つのエッジ ケースは、単一セル入力 (1, 0) または (0, 1) です。 これは有効であり、任意の 1 つの座標で YES を出力する必要があり、アルゴリズムは構築の前に明示的にこれを処理します。 

最後のエッジ ケースは、最初のスネーク プレフィックスがすでに 1 つの色をわずかにオーバーシュートしている場合です。 この状況では、調整フェーズではセルの追加のみが行われ、セルの削除は行われないため、バランシングを開始する前に a + b に正確に等しいプレフィックス長を慎重に選択することでオーバーシュートが回避されます。
