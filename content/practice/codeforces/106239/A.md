 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、そのセグメント内の最大要素と最小要素の差ができるだけ大きくなるように、連続したセグメントを選択するように求められます。 この最大差の値に加えて、それを達成する 1 つのセグメントも出力する必要があります。 

入力は、長さが 100 までの単一の配列で、各値は 0 ～ 100 です。有効な答えは、インデックスの任意のペアです。$l, r$サブ配列が$A[l..r]$可能な最大値は次のとおりです$\max(A[l..r]) - \min(A[l..r])$。 

制約$n \le 100$すでに 3 次または 2 次の解が受け入れられることを示しています。 線形または線形演算による解決策も問題ありませんが、その必要はありません。 重要な観察は、問題が特別な単調特性や動的状態のような固有の構造を求めているのではなく、すべての部分配列にわたる大域最適のみを求めているということです。 

微妙な点は、最適なセグメントは必ずしも一意ではなく、複数のセグメントが同じ最大差を達成する可能性があることです。 有効なセグメントは 1 つだけ受け入れられます。つまり、正確性を超えたタイブレーク ルールは必要ありません。 

単純ですがよくある間違いは、最適なセグメントには配列全体のグローバル最小値またはグローバル最大値のいずれかが含まれている必要があると想定することです。 この問題ではこれは正しいですが、仮定ではなく列挙ロジックによる正当化が必要です。 

たとえば、次のことを考えてみましょう。```
A = [2, 3, 4, 1]
```最良のセグメントは、最大 4 と最小 1、差 3 を与える配列全体です。間違いは、差 2 を持つ [2, 3, 4] のようなセグメントを選択することであり、1 を含むように拡張すると結果が改善されるという事実を見逃してしまいます。 

もう 1 つのエッジ ケースは、すべての要素が等しい場合です。```
A = [5, 5, 5]
```すべてのセグメントには差分 0 があるため、単一要素セグメントは有効です。 単純なソリューションでは、不必要に長いセグメントが返される可能性がありますが、正確さには影響しません。 

## アプローチ

 最も直接的な解決策は、考えられるすべての部分配列を列挙することです。 インデックスの各ペアについて$l, r$、サブ配列をスキャンしてその最小値と最大値を計算し、この差が現在の最良値を改善する場合は最良の答えを更新します。 

これは、すべての候補セグメントの目的関数を明示的に評価するため機能します。 正確さは即座にわかります。欠落したサブ配列はありません。 

ただし、コストが高い。 がある$O(n^2)$サブ配列、および各テイクの最小値と最大値の計算$O(n)$、につながる$O(n^3)$トータルオペレーション。 その間$n = 100$これは境界線に達しますが、それでも許容できるものであり、不必要に遅いです。 

計算を再利用することでこれを改善できます。 左側の端点を修正すると$l$、右のエンドポイントを拡張できます$r$現在の最小値と最大値を一定時間維持しながら段階的に増加します。 各拡張では答えが更新されます$O(1)$、全体的な複雑さが軽減されます。$O(n^2)$。 

重要な考え方は、セグメントごとに最小値と最大値を最初から再計算するのは冗長であるということです。 同じ左端点を持つセグメントは成長シーケンスを形成するため、拡張しても状態を維持できます。 

これにより、問題は 2 層ループになり、外側のループが開始を固定し、内側のループが実行極値を維持しながら終了を延長します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 許容範囲内だが遅い |
 | 最小値/最大値を実行して展開 | O(n²) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. これまでに見つかった最良の答え (最良の差、最良の左インデックス、最良の右インデックス) を格納する変数を初期化します。 非常に小さな最良の差から開始して、実際のセグメントがそれを改善します。 
2. 左側のエンドポイントを修正します$l$1から$n$。 これは、候補サブ配列の開始を表します。 すべての有効な部分配列はどこかで始まる必要があるため、体系的にすべての可能性を試します。 
3. それぞれについて$l$、2つの変数を初期化します`cur_min`そして`cur_max`に$A[l]$。 これは、位置にある単一の要素のみで構成される部分配列の状態を表します。$l$。 
4. 右側のエンドポイントを延長します$r$から$l$に$n$、更新中`cur_min = min(cur_min, A[r])`そして`cur_max = max(cur_max, A[r])`。 これにより、再計算せずに現在の部分配列の正しい極値が維持されます。 
5. 電流の差を計算します。`cur_max - cur_min`。 これがこれまでの最良の差よりも大きい場合、保存されている回答を次のように更新します。$(l, r)$そして新たな違い。 
6. すべてが終わるまで拡張を続けます。$r$これに対する価値観$l$処理されてから次へ進む$l$。 
7. すべての反復の後、保存されている最良のセグメントとその差を出力します。 

### なぜ効果があるのか

 拡張の各段階で$r$、アルゴリズムは現在の部分配列の正確な最小値と最大値を維持します。$[l, r]$。 これは更新ルールによって保存される不変式です。要素を 1 つ追加する場合、それを前の極値と比較するだけで済みます。 すべての部分配列は何らかのペアによって一意に表現されるため、$(l, r)$、そのような各ペアは 1 回だけ評価され、アルゴリズムはすべての候補を重複や省略なしに考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    best_diff = -1
    best_l, best_r = 0, 0
    
    for l in range(n):
        cur_min = a[l]
        cur_max = a[l]
        
        for r in range(l, n):
            if r > l:
                cur_min = min(cur_min, a[r])
                cur_max = max(cur_max, a[r])
            
            diff = cur_max - cur_min
            if diff > best_diff:
                best_diff = diff
                best_l = l
                best_r = r
    
    print(best_l + 1, best_r + 1, best_diff)

if __name__ == "__main__":
    solve()
```このコードは、2 層列挙戦略を直接実装しています。 外側のループは左側の境界を固定し、内側のループは実行中の最小値と最大値を維持しながら右側の境界を拡張します。 Python 配列は 0 ベースであるのに対し、問題では 1 ベースのインデックスが使用されるため、出力で +1 シフトが必要です。 

一般的な実装の落とし穴は再初期化です。`cur_min`そして`cur_max`内部ループ内で誤って実行すると、増分最適化が破壊されます。 もう 1 つの微妙な問題は、差分を計算する前に極値を更新することです。これは、現在の要素が確実に含まれるように正しい順序で実行する必要があります。

 ## 特殊なケース

 次のような単一要素配列の場合`A = [7]`、アルゴリズムセット`cur_min = cur_max = 7`他のセグメントが存在しないため、正しく出力されます。`(1, 1, 0)`。 

次のようなすべてが等しい配列の場合`A = [3, 3, 3, 3]`、すべての反復は維持します`cur_min = cur_max = 3`展開関係なく。 差が 0 を超えることはないため、最初のセグメントは`(1, 1)`保存された回答はそのまま残ります。 

次のような厳密に増加する配列の場合`A = [1, 2, 3, 4]`、最初の外側のループでは、全範囲に拡張すると最大の差が生じることがすでにわかっています。 不変式により、将来の部分配列はすべてサブセットまたは等範囲バリアントであるため、両方の極値が含まれると、その後のセグメントはその値を超えることができなくなります。
