 ## 解決策
 ## 問題の理解

 平面には正方形の領域が含まれています。$0$に$N$両方の軸で。 この領域内には、それぞれに重みを持った多くの無限の直線が与えられます。 すべての線は傾きのいずれかです$+1$、と書かれています$y = x + b$、または傾斜$-1$、と書かれています$y = -x + c$。 各線は通過するすべての点に重みを与えます。どの点でも、総エネルギーはその点をカバーするすべての線の重みの合計になります。 

タスクは、正方形の内部または境界上の任意の点を選択し、その点の総エネルギーを最大化することです。 最適な点は整数座標である必要はなく、線の交点である必要もありません。 連続領域のどこにでも存在できます。 

制約が非常に厳しいため、候補点を反復処理することは不可能です。 まで$10^5$テストごとの行数とテスト全体の合計数$10^5$、すべての交差点をチェックしたり、飛行機を直接サンプリングしようとするソリューションは制限時間を超過します。 有効なアプローチでは、連続ジオメトリを管理可能な離散構造に縮小し、線間の二次相互作用を回避する必要があります。 

微妙な問題は、最良の点が線の交差が発生しない領域に存在する可能性があることです。 たとえば、すべての線が一方向に平行で、ストリップ内に集中している場合、最大値は連続セグメントに沿った任意の場所で発生する可能性があります。 

もう 1 つの問題は、最適な点が必ずしも整数座標にあるとは限らないことです。 線の交点のみを評価する単純なアプローチは、たとえ小さなケースであっても失敗します。 

次の例を考えてみましょう。 

入力:```
N = 2
1 line: y = x (weight 10)
1 line: y = -x + 2 (weight 10)
```両方の線が次の点で交差します$(1,1)$、その点が最適です。 しかし、正方形の中で交差しないように 1 本の線を少しずらすと、次のようになります。$y = x + 1$そして$y = -x + 1$の場合、最大値は、離散的な交差点ではなく、境界近くのセグメントに沿って達成されます。 交差のみに依存する方法では、これを見逃してしまいます。 

重要な難点は、面は連続しているが、線の構造は高度に揃っていることです。 

## アプローチ

 直接的な総当たりビューでは、正方形内のすべての可能な点を考慮し、そこを通過する線の数を計算しようとします。 空間は連続しているため、これは不可能です。 線の交点に限定しても、$O(Q^2)$そのような点は、限界をはるかに超えています。$Q = 10^5$。 

重要な構造は、すべての線が 2 つの方向のみに分類されるという事実から生まれます。 これは、ジオメトリを軸に沿った構造に変える座標変換を示唆しています。 

新しい変数を定義します。$$u = x + y, \quad v = x - y$$この変換により、各行は非常にシンプルになります。 一行$y = x + b$になる$x - y = -b$、定数に対応することを意味します$v$。 同様に、行$y = -x + c$になる$x + y = c$、定数に対応することを意味します$u$。 

これは、すべての線が単一の水平線または垂直線に沿って重み付けされることを意味します。$(u, v)$-空間。 問題はポイントの選択になります$(u, v)$最大化するには:$$U(u) + V(v)$$どこ$U(u)$すべての行の重みの合計です。$x+y = u$、 そして$V(v)$すべての行の重みの合計です。$x-y = v$。 

残りの複雑さは、すべてではないということです$(u, v)$ペアは有効です。 元の制約$0 \le x, y \le N$は次のようになります:$$0 \le \frac{u+v}{2} \le N, \quad 0 \le \frac{u-v}{2} \le N$$これは次のように単純化されます。$$-u \le v \le u, \quad 0 \le u \le 2N$$したがって、有効な領域は次のダイヤモンド型の制約になります。$(u,v)$-空間。 

さて、問題は純粋に「最大化」です。$U(u) + V(v)$単調制約によって制限された値の長方形グリッド上で$|v| \le u$。 両方$U$そして$V$は、指定された座標でのみ定義された区分定数関数です。 

イベント座標のすべてのペアに対するブルート フォース スキャンでは、依然として次のような結果が得られます。$O(Q^2)$。 重要な観察は、最適なソリューションでは次の臨界値のみを考慮する必要があるということです。$u$そして$v$、および境界条件$v = \pm u$、イベント座標間ではどちらの関数も変化しないためです。 

したがって、検索をソート済みのスイープに縮小します。$u$-最大値をクエリできる構造を維持しながら値を取得します。$V(v)$内部$[-u, u]$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 点または交差点に対するブルート フォース |$O(Q^2)$|$O(Q)$| 遅すぎる |
 | 座標変換 + スイープ + 範囲最大値 |$O(Q \log Q)$|$O(Q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、幾何学的な問題を制約の下で 2 つの独立した 1 次元の重み付き座標に変換します。 

1. 各行を座標イベントに変換します。 行ごとに$y = x + b$、計算する$v = -b$そしてその重量を位置に追加します$v$。 行ごとに$y = -x + c$、計算する$u = c$そしてその重量を位置に追加します$u$。 これにより、2 つのスパース マップが作成されます。$u$そして1つオーバー$v$。 
2. 異なるものをすべて収集する$u$-座標と$v$-座標を調整して並べ替えます。 これらは、目的関数が値を変更できる唯一の場所です。 彼らの間では、両方とも$U$そして$V$一定のままです。 
3. 構造を構築する$v$-間隔を超えて最大の高速クエリを可能にする値。 最大値だけが必要なので、$V(v)$範囲を超えて$[-u, u]$、セグメント ツリーまたは座標圧縮配列が機能します。 
4. 各候補者について$u$、計算する$U(u)$事前計算されたマップから直接。 次に、次の最大値をクエリします。$V(v)$範囲内で$[-u, u]$。 それらを組み合わせて答えの候補を取得します。 
5. 唯一の$u$- テストする必要がある値はイベントの位置です。$U(u)$変更、および制約の境界にある値$u = |v_i|$アクティブになります。 これにより、実現可能な移行を決して見逃すことがなくなります。$v$-範囲は、の新しいセグメントを含むように始まります。$V$構造。 
6. すべての候補の最大値を取得します。 

これが機能する理由は、両方とも$U(u)$そして$V(v)$はステップ関数です。 連続するイベント座標間ではどちらの関数も変化せず、実行可能な間隔の拡大または縮小は、ブレークポイントを横切る場合にのみ問題になります。$V$または、制約領域の境界に位置合わせします。 したがって、最適値は、正確に不連続点にあるとき、または次のいずれかのときに発生する必要があります。$U$、またはアクティブな$v$- 範囲の境界が不連続部分に触れています$V$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N, Q = map(int, input().split())

        U = {}
        V = {}

        u_vals = set()
        v_vals = set()

        for _ in range(Q):
            t, x, y, e = map(int, input().split())
            if t == 1:
                v = x - y  # = -b
                V[v] = V.get(v, 0) + e
                v_vals.add(v)
            else:
                u = x + y  # = c
                U[u] = U.get(u, 0) + e
                u_vals.add(u)

        v_list = sorted(v_vals)
        u_list = sorted(u_vals)

        if not v_list:
            # only u-lines
            print(max(U.values()))
            continue
        if not u_list:
            # only v-lines
            print(max(V.values()))
            continue

        v_index = {v:i for i, v in enumerate(v_list)}
        seg = [0] * (4 * len(v_list))

        def build(i, l, r):
            if l == r:
                seg[i] = V[v_list[l]]
                return
            m = (l + r) // 2
            build(i*2, l, m)
            build(i*2+1, m+1, r)
            seg[i] = max(seg[i*2], seg[i*2+1])

        def query(i, l, r, ql, qr):
            if ql <= l and r <= qr:
                return seg[i]
            if r < ql or l > qr:
                return 0
            m = (l + r) // 2
            return max(
                query(i*2, l, m, ql, qr),
                query(i*2+1, m+1, r, ql, qr)
            )

        build(1, 0, len(v_list)-1)

        ans = 0

        for u in u_list:
            base = U[u]

            L = -u
            R = u

            # find indices in v_list
            import bisect
            l = bisect.bisect_left(v_list, L)
            r = bisect.bisect_right(v_list, R) - 1

            if l <= r:
                best_v = query(1, 0, len(v_list)-1, l, r)
                ans = max(ans, base + best_v)
            else:
                ans = max(ans, base)

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、2 つのライン ファミリを、変換された座標によってインデックス付けされた 2 つの独立した重み配列に変換します。 セグメントツリーは全体にわたって構築されます$v$- 範囲に対する最大のクエリをサポートする座標。 それぞれについて$u$-座標、コードは実行可能な間隔を計算します。$v$としての値$[-u, u]$、次に、達成可能な最良のものをクエリします$V(v)$その間隔内でそれを組み合わせます$U(u)$。 

微妙な点は、イベント座標のみが使用されることです。$u$、彼らの間以来$U(u)$変わりません。 これにより、範囲クエリからの対数係数までスイープが線形に保たれます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての回線が 1 つのファミリーのみに属している場合、つまり、すべての回線が 1 つのファミリーにのみ属している場合に発生します。$u$-行またはすべては$v$-行。 その場合、不足している次元に影響を与えることなく、制約を満たす最適な点を常にどこにでも配置できるため、答えは単純な重みの最大値に減ります。 アルゴリズムはこれを明示的にチェックし、空の範囲のクエリを回避します。 

最良の場合には、別のエッジケースが現れます。$v$-range は指定された値に対して空です$u$。 これは次のような場合に起こります。$|u|$既存のものよりも小さい$v$-コーディネート。 その場合、コードは正しくフォールバックして、$U(u)$、ないので$v$-lineをアクティブにすることができます。 

最後の微妙なケースは、最適な点がちょうど境界上にある場合です。$v = \pm u$。 これらの点に対応するのは、$x=0$または$y=0$オリジナルのコーディネートで。 変換ではそれらが正確に保持され、包含二分処理を使用して範囲クエリに境界が含まれるため、これらのケースは完全にキャプチャされます。
