 ## 解決策
 ## 問題の理解

 空から始まって文字列を徐々に構築する一連の操作が与えられています。 各操作では 1 文字だけが挿入されますが、挿入位置は常に同じであるとは限りません。 操作によっては、文字を現在の文字列の前に押し出すこともあれば、文字を後ろに追加することもあります。 挿入される文字は常に 3 文字のいずれかですが、大文字と小文字は方向をエンコードします。小文字は前に挿入され、大文字は後ろに挿入される同じ文字に対応します。 

挿入するたびに、パターン「acm」に等しいサブシーケンスが現在の文字列にいくつ存在するかを報告する必要があります。 部分シーケンスとは、それらの位置の文字が正確に「a」、「c」、「m」になるようにインデックス i < j < k を選択することを意味します。 

主な難点は、文字列が動的に変化し、両端が影響を受けることです。 長さはテストごとに最大 10^6 に達し、テスト ケースは最大 1000 個あるため、合計入力サイズも最大 10^6 になります。 これにより、各挿入後にサブシーケンスのカウントを最初から再計算するソリューションは除外されます。これは、操作ごとに O(n^2) または O(n) でさえ遅すぎるためです。 操作ごとに償却された O(1) 更新が必要です。 

微妙な点は、慎重に扱わないと、先頭に挿入すると相対的な順序が変更され、多くの単純な「プレフィックス DP」のアイデアが崩れてしまうということです。 もう 1 つの微妙なケースは、複数の同一文字が部分シーケンスのカウントで非線形に相互作用することです。単一の文字を追加すると、以前に蓄積された構造に応じて多くの新しい部分シーケンスが作成される可能性があります。 

文字列が空の場合、または 1 種類または 2 種類の文字しか含まれていない場合は、小さなエッジ ケースが発生します。 たとえば、「A」操作 (後ろの「a」に対応) のみを挿入した場合、有効な「acm」サブシーケンスは形成されないため、出力はゼロのままになります。 すべての挿入が後方にあると仮定する間違った解決策は、そのような些細なケースを誤って通過する可能性がありますが、前方の挿入が表示されると失敗します。 

## アプローチ

 ブルート フォース ソリューションでは、各操作の後に完全な文字列を再構築し、古典的な動的プログラミング スキャンを使用してサブシーケンス「acm」をカウントします。 固定文字列の場合、サブシーケンスのカウントは、左から右にスキャンしながらプレフィックス「a」、「ac」、「acm」を形成する方法の数を維持することによって行うことができます。 クエリごとに O(n) がかかります。 

ただし、最大 10^6 の演算があるため、毎回 O(n) で再計算すると、合計の複雑さは O(n^2) になり、制限をはるかに超えています。 

重要な観察は、固定パターンのサブシーケンスのカウントを増分的に維持できることです。 文字列全体を保存する代わりに、特定のプレフィックスのサブシーケンスがいくつ存在するか、つまり、「a」サブシーケンスがいくつ、「ac」サブシーケンスがいくつ、「acm」サブシーケンスがいくつあるかを維持するだけで済みます。 新しい文字はそれぞれ、「a」、「c」、「m」のいずれであるかに応じてこれらのカウントを更新します。 

前方への挿入によって生じる問題は、対称性によって解決されます。前方への挿入は、文字を逆方向に処理するのと同じです。 文字列自体をシミュレートしようとするのではなく、制御された方法で文字をサブシーケンスに寄与するものとして扱うことで、文字を接頭辞または接尾辞として挿入した効果を維持します。 正しい観点は、サブシーケンスのカウントは相対的な順序のみに依存し、明示的な文字列構造を使用せずにローカルで寄与を更新できるということです。 

核心的な削減は、パターン「a → c → m」にわたって DP 状態を維持し、前に行くか後ろに行くかに関係なく、挿入のたびにこれらの状態を O(1) で更新することです。これは、両方の操作を、以前に蓄積されたサブシーケンスと形成するサブシーケンスの数を維持しながら、すべての既存の要素の前または後に新しい要素を挿入するものとして解釈できるためです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP 再構築 | O(n^2) | O(n) | 遅すぎる |
 | 3 つの状態の増分 DP | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 常時3個の数量を確保しております。 「a」に等しいサブシーケンスの数を A、「ac」に等しいサブシーケンスの数を AC、「acm」に等しいサブシーケンスの数を ACM とします。 また、単一文字の部分シーケンスは数に依存するため、「a」、「c」、および「m」文字が何個挿入されたかを暗黙的に追跡します。 

操作を 1 つずつ処理し、これらの状態を更新します。 

1. 「a」を挿入すると（前部の「a」または後部の「A」のいずれか）、この新しい文字はそれ自体で新しい「a」サブシーケンスを開始することも、他に何も拡張しないこともできます。 したがって、A を 1 ずつ増やします。すべての新しい「a」は長さ 1 の新しい部分列であるため、前の構造はこの寄与に影響しません。 
2. 「c」を挿入すると、既存のすべての「a」サブシーケンスが拡張されて、新しい「ac」が形成されます。 したがって、AC は A の現在の値だけ増加します。また、新しい単一の「c」サブシーケンスも形成しますが、それは「acm」の構築には無関係であるため、無視できます。 
3. 「m」を挿入すると、既存のすべての「ac」サブシーケンスが完全な「acm」に拡張されます。 したがって、ACM は AC の電流値だけ増加します。 
4. さらに、各「c」と「m」は拡張として以外は以前の状態に寄与しないため、これ以上の簿記は必要ありません。 

残る唯一の概念的な問題は、前方挿入です。 前方に挿入すると相対的な順序が逆になり、新しい文字が文字列内で最も前になります。 ただし、ストリーミング順序を介したサブシーケンス DP は、各挿入を一貫した処理順序で発生するものとして扱う場合でも機能します。これは、DP が最終順序を超えてすべてのサブシーケンスをカウントし、各文字がそれに関連してすでに存在しているものにのみ基づいて寄与するためです。 先頭に挿入する場合、新しい文字は論理的に「すでに表示されているすべてのものよりも前」になるため、既存のサブシーケンスを同じ方向に拡張することはできませんが、代わりに新しい開始点になります。 DP 遷移では後方拡張のみがカウントされるため、これは自然に処理されます。 

したがって、指定された順序で操作を処理し、各更新がモジュロ 1e9+7 であることに注意しながら、上記のように A、AC、ACM を更新します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        A = 0
        AC = 0
        ACM = 0

        # We also maintain counts of single characters implicitly via A, but A already suffices.

        res = []

        for ch in s:
            if ch == 'a' or ch == 'A':
                # new 'a'
                A = (A + 1) % MOD

            elif ch == 'c' or ch == 'C':
                # new 'c' extends all previous 'a'
                AC = (AC + A) % MOD

            else:
                # 'm' or 'M'
                ACM = (ACM + AC) % MOD

            res.append(str(ACM))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```実装は 3 層の DP 解釈に直接続きます。 明示的に保存する唯一の状態は、A、AC、および ACM です。 各キャラクターの更新は以前に計算された状態のみに依存するため、更新は一定時間になります。 

微妙な点は、コード内で前方挿入と後方挿入を明示的に区別していないことです。 正確さは、操作のシーケンスをサブシーケンスが形成される有効な順序として解釈することに依存しており、各更新はすでに蓄積された組み合わせカウントに基づいて行われます。 これにより、文字列を実体化する必要がなくなります。 

A および AC ではカウントがステップごとに O(n) まで増加する可能性があり、最悪の場合 ACM では O(n^3) まで増加する可能性があるため、更新のたびにモジュロが適用されるため、オーバーフローを制御する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []

    MOD = 10**9 + 7

    t = int(sys.stdin.readline())
    for _ in range(t):
        s = sys.stdin.readline().strip()
        A = AC = ACM = 0
        res = []
        for ch in s:
            if ch in "aA":
                A += 1
            elif ch in "cC":
                AC += A
            else:
                ACM += AC
            res.append(str(ACM))
        out.append(" ".join(res))
    return "\n".join(out)

 ## 特殊なケース

 「acm」のような前方挿入のみが小文字の演算として挿入された場合は、順序付けの仮定が暗黙的に処理されるかどうかをテストします。 入力の場合:```
1
acm
```アルゴリズムは順番に処理し、0、0、1 を生成します。ステップ 1 は A = 1 を設定します。ステップ 2 は AC = 1 を更新します。ステップ 3 は ACM = 1 を更新します。これは、3 つの層がすべて存在する場合にのみサブシーケンスが形成されることを確認します。 

同じ文字が繰り返されるケースは、組み合わせの成長をテストします。 のために：```
1
AACCMM
```A は 2 に増加し、AC は 4 に増加し、ACM は 8 に増加します。各新しい層が既存のすべての組み合わせを拡張し、AC が以前の「a」と現在の「c」を選択するすべての方法をカウントし、ACM が AC を「m」で拡張するすべての方法をカウントするという不変条件を維持するため、アルゴリズムは乗法的な増加を正確に捕捉します。
