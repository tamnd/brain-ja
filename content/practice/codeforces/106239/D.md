 ## 解決策
 ## 問題の理解

 マップは次の行で構成されます。`0`に`n+1`とコラム`1`に`m`。 行`0`そして`n+1`北極と南極を表します。 すべての供給ポイントは列の内側にあります`1...n`。 

細胞から`(x,y)`私たちは南に移動するかもしれません`(x+1,y)`、または同じ行内で左右に移動します。 列は循環するため、列`1`列に隣接しています`m`。 

旅はどこかから始まる`0`、行のどこかで終了します`n+1`、すべての補給ポイントを少なくとも 1 回訪問する必要があります。 北への移動は禁止されているため、行は昇順ではない順序で走査されます。 合計ステップ数を最小限に抑えたいと考えています。 

実際には上下の動きは固定されています。 列から移動するには`0`漕ぐ`n+1`正確に下降しなければなりません`n+1`どのルートを選択しても、 唯一の自由は、各列内でどれだけ水平方向の移動が実行されるかです。 

制約は非常に大きいです。 両方`n`そして`m`到達できる`10^9`, そのため、グリッド自体を保存することはできません。 すべてのテスト ケースにわたる供給ポイントの数は最大で`10^6`これは、点の数が線形に近いアルゴリズムが必要であることを意味します。 列または行に対する動的プログラミングを伴うアプローチは、直ちに不可能になります。 

微妙な点は、供給ポイントのない列は重要ではないということです。 それらを通過することは、強制的な下方向への移動に寄与するだけです。 もう 1 つの微妙な点は、列の周期的な性質です。 たとえば、`m=10`、列から移動`1`列へ`10`コストは 9 ステップではなく 1 ステップです。 

考慮する```
1
1 10 2
1 1
1 10
```答えは`3`。 

列から始めます`0`、列を選択します`1`、に行きます`(1,1)`、一度左に移動して、`(1,10)`、そして南極に降ります。 列を線形に解釈すると、誤ったコストが与えられる`11`。 

Another tricky case is```
1
3 10 3
1 2
1 8
3 5
```最初の行では列にアクセスする必要があります`2`そして`8`。 柱はサイクルを形成するため、最も安価な方法は、間隔の外側の短い円弧を横断することであり、必ずしも間隔から直接移動する必要はありません。`2`に`8`。 

## アプローチ

 強引なアイデアは、すべての列を状態とみなすことです。 1 行を処理した後、各列で終了するための最小コストを維持します。 複数の供給ポイントを含む行の場合、遷移はそれらすべての供給ポイントへの訪問をシミュレートします。 

これが機能するのは、行の順序が固定されており、終了列のみが今後の決定に影響を与えるためです。 残念ながら`m`多分`10^9`したがって、列ごとに 1 つの値を維持することは絶望的です。 

重要な観察は、供給ポイントを含む行のみが水平方向の移動に影響を与えるということです。 このような行内で、左端と右端の供給列が`L`そして`R`、有効なパスはすべて、それらの間のすべてのポイントをカバーする必要があります。 すべての点は 1 つの円上にあるため、すべての点を訪問することは、両極端を訪問することと同じです。 

ある列の行に入るとします。`p`。 すべてのポイントを訪問した後、最終的な位置は 2 つの極端な位置のいずれかになるだけで済みます。`L`または`R`。 他の場所で終了する解決策は、最も近い極限まで続けることで短縮できます。 したがって、各行は 2 つの状態のみを提供します。 

これにより、問題は電源を含む行に関する動的計画問題に帰着します。 あれば`s`このような行では、現在の行を左端または右端で終了するための最小コストが維持されます。 以来`s≤k`、複雑さは線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(km) | O(m) | 遅すぎる |
 | 最適 | O(k log k) | O(k) | 承認済み |

 対数係数は、供給ポイントを行ごとに並べ替えることから得られます。 

## アルゴリズムのチュートリアル

 ### 1. 供給ポイントを行ごとにグループ化する

 すべての供給ポイントを行ごとに並べ替えます。 少なくとも 1 つの点を含むすべての行について、最小の列のみを記録します。`L`最大列`R`。 

両端をカバーするパスはその行のすべての供給ポイントを自動的にカバーするため、中間点は無関係です。 

### 2. 処理された行ごとに 2 つの状態を定義します

 アクティブな行ごとに、`dpL`: この行を列で終了するときに、これまでに累積された最小水平コスト`L`。`dpR`: この行を列で終了するときに、これまでに累積された最小水平コスト`R`。 

上下移動は常時なので別途追加します`n+1`。 

### 3. 最初のアクティブ行を処理します。 

最初の行に入る前に、北極の任意の列から開始できます。 したがって、入力欄は自由に選択できます。 

インターバルをカバーするには`[L,R]`円上では、短い方の円弧を横切ります。 すべてを訪問して終了するのにかかる費用`L`等しい```
circle_distance(L,R)
```で終了する場合も同様に、`R`。 

点が 1 つだけある行の場合、両方のコストはゼロです。 

### 4. 連続するアクティブ行間の遷移

 前の行の極値が次のようになると仮定します。`(L1,R1)`現在の行の極値は`(L2,R2)`。 

終了コストを計算するには`L2`では、次の 4 つの可能性を考えます。 

から始まる`L1`または`R1`、その列から新しい行に入り、間隔内のすべての列を訪問し、最後にで停止します。`L2`。 

で終了する場合も同じことが行われます`R2`。 

円上の 2 つの列間の水平距離は次のとおりです。```
dist(a,b)=min(|a-b|,m-|a-b|)
```現在の行内で、列から開始すると`p`で終了したいと思います`L2`、まず到達する必要があります`R2`なぜなら、両極端を訪れる必要があるからです。 費用は```
dist(p,R2)+linear_length
```どこ```
linear_length=R2-L2
```同様に、次で終わります`R2`費用```
dist(p,L2)+linear_length
```その理由は、一方の極を最終位置として選択した後、もう一方の極をより早く訪問する必要があるためです。 

### 5. すべてのアクティブな行に対して繰り返します。 

2 つの状態値を行ごとに更新します。 

### 6. 垂直方向の動きを追加する

 行から降順`0`漕ぐ`n+1`常に正確に要求する`n+1`ステップ。 

最終的な答えは、```
n+1+min(dpL,dpR)
```### なぜ効果があるのか

 行を処理した後、将来の行に関連する唯一の情報は、現在どの極端な列に立っているのか、およびそこに到達するための最小コストです。 行のすべての供給ポイントは 2 つの端点の間にあるため、有効なトラバースは距離を増やさずに端点で終了するものに再配置できます。 これにより、行ごとに正確に 2 つの状態を持つ最適な部分構造が得られます。 すべての遷移では、以前の考えられるすべての極端な値が考慮されるため、動的プログラミングはあらゆる最適なルートを探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def dist(a, b, m):
    d = abs(a - b)
    return min(d, m - d)

t = int(input())
ans = []

for _ in range(t):
    n, m, k = map(int, input().split())

    rows = {}

    for _ in range(k):
        x, y = map(int, input().split())
        if x not in rows:
            rows[x] = [y, y]
        else:
            rows[x][0] = min(rows[x][0], y)
            rows[x][1] = max(rows[x][1], y)

    items = sorted(rows.items())

    first_L, first_R = items[0][1]
    width = first_R - first_L

    dpL = width
    dpR = width

    prevL, prevR = first_L, first_R

    for _, (curL, curR) in items[1:]:
        width = curR - curL

        ndpL = min(
            dpL + dist(prevL, curR, m) + width,
            dpR + dist(prevR, curR, m) + width
        )

        ndpR = min(
            dpL + dist(prevL, curL, m) + width,
            dpR + dist(prevR, curL, m) + width
        )

        dpL, dpR = ndpL, ndpR
        prevL, prevR = curL, curR

    ans.append(str(n + 1 + min(dpL, dpR)))

print("\n".join(ans))
```ディクショナリには、実際に供給ポイントを含む行のみが格納されます。 このような行ごとに、左端と右端の列のみを保持します。 

動的プログラミング変数は、これまでに蓄積された最小水平距離を表します。 垂直距離は一定で次と等しいため、遷移中は省略されます。`n+1`。 

新しい行に移動するときに、左端で終わるということは、最初に右端にアクセスする必要があることを意味します。 したがって、遷移では距離を使用して、`curR`間隔幅を加えます。 右端で終了する式は対称です。 

すべての値は 64 ビット整数内に簡単に収まりますが、Python 整数を使用すると、オーバーフローの問題が完全に回避されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    INF = 10**18

    def dist(a, b, m):
        d = abs(a - b)
        return min(d, m - d)

    t = int(input())
    out = []

    for _ in range(t):
        n, m, k = map(int, input().split())

        rows = {}

        for _ in range(k):
            x, y = map(int, input().split())
            if x not in rows:
                rows[x] = [y, y]
            else:
                rows[x][0] = min(rows[x][0], y)
                rows[x][1] = max(rows[x][1], y)

        items = sorted(rows.items())

        L, R = items[0][1]
        dpL = dpR = R - L
        prevL, prevR = L, R

        for _, (L, R) in items[1:]:
            width = R - L

            ndpL = min(
                dpL + dist(prevL, R, m) + width,
                dpR + dist(prevR, R, m) + width
            )

            ndpR = min(
                dpL + dist(prevL, L, m) + width,
                dpR + dist(prevR, L, m) + width
            )

            dpL, dpR = ndpL, ndpR
            prevL, prevR = L, R

        out.append(str(n + 1 + min(dpL, dpR)))

    return "\n".join(out)
