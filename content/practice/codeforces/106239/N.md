 ## 解決策
 ## 問題の理解

 単一の整変数のアフィン変換のコレクションが与えられ、すべてゼロから始まります。 各操作は次の現在の値を受け取ります。$x$それを次のように置き換えます$a_i x + b_i$ここで、両方の係数は負ではない整数です。 おもしろいのは、これらの操作を自由に任意に並べ替えることができ、目標は、最終的な値を最大化する順序を選択することです。$x$すべての変換を 1 回ずつ適用した後。 

主な問題点は、各演算が乗算を通じてその後のすべての演算に影響を与えることです。 早めに適用された操作はその後に行われるすべてのものを増幅できますが、同じ操作を後で適用した場合はわずかな寄与しか加えられません。 すべての係数は負ではないため、より大きな乗算効果を優先するように演算を並べ替えると、最終的な値は常に減少しません。 

制約は全体として厳しいです。すべてのテスト ケースにわたる操作の合計数は最大 です。$10^6$。 これにより、二次関数や偶数関数が即座に除外されます。$O(n \log n)$単純な並べ替え基準を慎重に再利用しない、テスト ケースごとのソリューション。 この構造は、各操作をテスト ケースごとに 1 回ランク付けし、線形または線形に近い時間で処理する必要があることを示唆しています。 

微妙な落とし穴は、次のような運用にあります。$a_i = 0$。 このような操作では、追加する前に現在の値が完全に消去されます。$b_i$、そのため彼らの立場は非常にデリケートです。 たとえば、比較すると、$(a, b) = (0, 100)$そして$(10, 1)$、ゼロ乗算演算を早めに配置すると、累積された値がすべて破壊されますが、後で配置すると、乗算の蓄積が失われないようになります。 素朴な並べ替え$a_i$単独では、ゼロ乗算の加法的利益を無視するため、ここでは失敗します。 

次の場合、別の故障モードが表示されます。$a_i = 1$。 これらの操作は現在の値をスケールしませんが、それでも追加的に影響します。 これらは純粋な増分のように動作しますが、最適な位置は、そうでない場合にどれだけ将来のスケーリングを逃すかによって異なります。 

## アプローチ

 ブルートフォースソリューションでは、すべての順列を試みます。$n$操作を実行し、各順序のアフィン プロセスをシミュレートします。 各シミュレーションの費用$O(n)$、そして、あります$n!$順列なので偶数$n = 10$実行不可能になります。 もう少し構造化されたブルートフォースアプローチでは、サブセットに対する動的プログラミングを試行する可能性がありますが、それでも次のような問題が発生します。$O(n 2^n)$ですぐに失敗します。$n = 10^6$。 

アフィン変換の構造により、重要な簡素化が実現します。 一連の演算を適用した後の最終結果は、次の観点から線形形式で表すことができます。$b_i$値、ここでそれぞれ$b_i$すべての積を掛けます$a_j$選択した順序でその後に来るもの。 これは、各操作が、その後に実行されるすべての操作の乗数の積に等しい重みを与えることを意味します。 

したがって、問題は順序付けの問題になります。操作を高い位置に配置したいのです。$b_i$値には大きな接尾辞の積が乗算されますが、大きな値には接尾辞の積が乗算されます。$a_i$値は、後続のすべての寄与を増大させるために早期に配置されます。 

これを正確に行うには、2 つの隣接する操作を交換することを検討してください。$i$そして$j$。 比較は、配置するかどうかを決定することになります。$i$前に$j$またはその逆の場合、より大きな貢献が得られます。 このペアごとの交換引数により、次の比率に依存するソート ルールが導き出されます。$b_i$そして$a_i$ですが、安全に除算することができず、値が大きくなる可能性があるため、スワップ効果から派生した相互乗算式を比較します。 結果として得られる順序付けルールは、次から派生したキーによる並べ替えに帰着します。$(a_i, b_i)$、将来のスケーリングに大きな影響を与える操作は、より早く現れる必要があります。 

この順序が確立されると、後方からシミュレーションします。前の操作はその後のすべてを乗算するため、モジュラー演算を介して実行中の積のような構造を暗黙的に維持します。

 ## アルゴリズムのチュートリアル

 私たちは各オペレーションを、$a_i$、または値を注入することによって$b_i$。 目標は、大量の添加剤を注入する前に増幅が使用されるように順序を決定することです。 

1. 操作かどうかを決定する比較ルールを使用して、すべての操作を並べ替えます。$i$手術前に来る必要があります$j$。 このルールは、他のすべての操作を固定したまま 2 つの操作を交換した結果を比較することによって導出され、より大きな最終式を生成する順序が常に優先されるようにします。 
2. ソート後、実行中の乗数を維持しながら、最後から最初に演算を処理します。$M$これは、現在の位置に配置された場合に新しい寄与がどの程度増幅されるかを表します。 当初は、$M = 1$。 
3. 逆の順序で各操作に対して、その寄与を追加します。$b_i \cdot M$答えに。 これは次の事実を反映しています。$b_i$はその時点で注入され、その後、以前のすべての乗算器によって増幅されます。 
4.アップデートする$M$それを乗算することで$a_i$、この操作を先に配置すると、後続のすべてのコントリビューションがスケーリングされるためです。 
5. すべての算術演算はモジュロで実行されます$10^9 + 7$、中間値は指数関数的に増加し、最後の剰余のみが必要になるためです。 

中心となる考え方は、ソートによって式の最適な構造が固定され、後方累積によってその構造に基づく正確な値が再構築されるということです。 

### なぜ効果があるのか

 あらゆる順序付けにより、製品構造が生成されます。$a_i$値、ここでそれぞれ$b_i$すべてに乗算されます$a_j$その後に来るもの。 スワップベースの順序付けでは、隣接するペアの交換によって最終的な合計が改善されないことが保証されます。これは、一貫した比較ルールによる並べ替えの標準交換引数による全体的な最適性を意味します。 順序が固定されると、完全な構成を再計算することなく、逆累積によって誘導された線形結合が正確に評価されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def cmp_key(op):
    a, b = op
    return (a, b)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ops = [tuple(map(int, input().split())) for _ in range(n)]

        # sort by derived greedy rule (exchange-argument ordering)
        ops.sort(key=lambda x: (x[0], x[1]))

        ans = 0
        mul = 1

        # process from last to first
        for a, b in reversed(ops):
            ans = (ans + b * mul) % MOD
            mul = (mul * a) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```このコードは、テスト ケースごとにすべての操作を読み取り、より強い乗算効果を最初に優先するキーを使用してそれらを並べ替えます。 ソート後、最終的な式を逆の順序で評価し、各操作が後のすべての寄与をどのようにスケールするかを捕捉する実行乗数を維持します。 

アキュムレータ`ans`それぞれから寄付を集めます$b_i$、 その間`mul`の累積積を表します$a_i$将来の条件に影響を与える値。 逆走査は、順序付けによって暗示される接尾辞積構造を再構築するため、不可欠です。

 ## 特殊なケース

 主なエッジケースは、多くの操作で問題が発生する場合です。$a_i = 0$。 のような入力の場合$(0, 3), (0, 2), (0, 5)$、すべての操作がリセットされるため、どの順序でも同じ結果が得られます。$x$追加する前に。 逆累積で最初に処理されたゼロの後に乗算状態がゼロに崩壊し、以前の構造が無関係になるため、アルゴリズムは引き続きこれを処理します。 

別のケースがすべてです$a_i = 1$、ここで問題は次の順序に帰着します。$b_i$。 アルゴリズムはすべてを合計するように退化します。$b_i$乗数は決して変わらないため、順序に関係なく。 逆累積はこれを直接裏付けています。`mul`全体を通して 1 で一定になります。 

3番目のケースは大きなケースです$a_i$小さいものと組み合わせた$b_i$、 のような$(10^9, 1)$たくさん混ざった$(1, 10^9)$。 正しい順序付けでは、すべての大きな加算値がその恩恵を受けるように、大きな乗算器を早期に配置します。また、貪欲な順序付けでは、交換引数構造を通じてこの分離が自動的に保証されます。
