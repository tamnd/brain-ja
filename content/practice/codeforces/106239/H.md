 ## 解決策
 ## 問題の理解

 私たちは 0 から n までラベル付けされた位置の線上に立っています。 位置 0 はスタートであり報酬はありませんが、1 から n までのすべての位置に着地すると、固定のエネルギー値が与えられます。 位置 0 から開始し、位置 n に到達したいと考えています。 

動きは 2 つの方法で制限されます。 各移動は、長さ 1 または 2 のステップのいずれかになります。 ただし、1歩手を2回連続で取ることはできません。 これにより、最後の移動と次に許可される移動の間に依存関係が作成されます。 位置 i に着地するたびに、すぐに Ai を回収します。 

課題は、「1 ステップが 2 つ連続しない」ルールを尊重し、収集されたエネルギーの合計を最大化する、0 から n までの有効なジャンプ シーケンスを選択することです。 

n ≤ 100000 という制約は、少なくとも線形または線形に近い時間が必要であることを意味します。 パスを列挙するソリューションは指数関数的です。各位置でグローバルな依存関係を持つ 2 つの移動タイプに分岐し、有効なシーケンスの数がフィボナッチ スタイルの漸化式のように増加しますが、状態が追加されるため、ブルート フォースは不可能です。 状態を圧縮せずにすべてのシーケンスを試行する単純な動的プログラミングでも、同じ部分問題が繰り返されます。 

微妙なエッジケースは、連続 1 ステップの制限から生じます。 ソリューションがこの依存関係を忘れると、問題を標準の「1 段または 2 段登る」DP として誤って処理し、無効な遷移を過剰にカウントすることになります。 もう 1 つのエッジ ケースは、n が小さい場合、特に n = 1 または n = 2 の場合です。この場合、「連続した 1 ステップなし」に関するルールが完全にはアクティブにならず、不注意な遷移により範囲外のインデックスが付けられたり、唯一の有効なパスを見逃したりする可能性があります。 

たとえば、n = 2 および E = [100, 1] の場合、許可されていれば最適なパスは 0 → 2 ですが、解釈によっては、0 → 1 → 2 は連続 1 ステップにより禁止されているため、有効な手のみを慎重にチェックする必要があるため、答えは E2 = 1 になります。 

## アプローチ

 ブルート フォース アプローチでは、0 から開始して可能なすべてのジャンプ シーケンスを試行し、現在の位置と最後の動きが 1 ステップか 2 ステップかを追跡します。 各状態で有効な動きに分岐し、エネルギーを蓄積します。 これは、すべての合法的なパスを探索し、着陸位置に応じて正確に報酬を合計するため、正しいです。 問題は、パスの数が n に応じて指数関数的に増加することです。 無効な連続 1 ステップ遷移を枝刈りしても、状態空間は依然として爆発します。これは、各位置に異なる履歴を持つ複数の方法で到達する可能性があり、再計算が繰り返されるためです。 

重要な観察は、重要な履歴情報は、前の手が 1 ステップであったか 2 ステップであったかだけであるということです。 問題全体は、2 つの状態を持つ位置をめぐる動的計画法に集約されます。 この状態をエンコードすると、遷移はローカルになり、完全な履歴から独立します。 これにより、問題は線形 DP に変換され、各位置が状態ごとに 1 回計算されます。 

dp[i][0] を最後の手が 1 ステップで i に到達したときの最大エネルギーとして定義し、dp[i][1] が最後の手が 2 ステップで i に到達したときの最大エネルギーとして定義します。 この制約は、別の 1 ステップによる dp[i][0] から i+1 への遷移を禁止しており、当然ルールが適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) 再帰の深さ | 遅すぎる |
 | 最適なDP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 位置と最後の手のタイプによってインデックス付けされた DP テーブルを維持します。

1. 開始状態を除くすべての状態を負の無限大として初期化します。 位置 0 では、概念的には「前の移動がない」状態から開始し、最初のアクションとして 1 ステップまたは 2 ステップのいずれかを許可します。 これにより、最初のジャンプが誤って制限されることが回避されます。 
2. 各位置から、どのようにしてそこに到達したかに応じて移行を検討します。 1 ステップで到達した場合、次の移動は 2 ステップでなければならないため、i+2 にのみ移行します。 2 ステップで到着した場合は、i+1 または i+2 に進む可能性があります。 これにより、ルールが直接エンコードされ、無効な連続 1 ステップ シーケンスが防止されます。 
3. i から j に遷移するとき、着地時にエネルギーを収集するため、DP 値に Ej を加算します。 これにより、すべての着陸寄与が正確に 1 回だけ考慮されることが保証されます。 
4. 位置は 0 から n まで昇順に処理されます。これは、すべての遷移が前進するため、以前の状態は使用される前に完全に確定されるためです。 
5. n に到達する可能性があるのは、最後の移動タイプのどちらでも発生する可能性があるため、答えは dp[n][0] と dp[n][1] の最大値です。 

なぜそれが機能するかは、状態圧縮の引数に関係しています。 i で終わる有効なパスは、その最高スコアと最後の移動タイプによって完全に特徴付けられます。 他の履歴の詳細は将来の合法性や報酬に影響を与えないため、これら 2 つの状態のみを保存することで最適な下部構造が保存されます。 すべての移行は実現可能性を維持し、すべての実現可能なパスは DP で表現できるため、候補となる解決策が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    E = [0] + list(map(int, input().split()))

    NEG = -10**18

    dp = [[NEG, NEG] for _ in range(n + 1)]

    dp[0][0] = dp[0][1] = 0

    for i in range(n + 1):
        for last in (0, 1):
            if dp[i][last] == NEG:
                continue

            if i + 1 <= n:
                if last == 1:
                    dp[i + 1][0] = max(dp[i + 1][0], dp[i][last] + E[i + 1])
            if i + 2 <= n:
                dp[i + 2][1] = max(dp[i + 2][1], dp[i][last] + E[i + 2])

    print(max(dp[n][0], dp[n][1]))

if __name__ == "__main__":
    solve()
```DP テーブルは、許可される 2 つの「最後の移動」状態を明示的に分離します。 遷移ロジックはルールを適用します。1 ステップ (最後 = 0) の後は 2 ステップのみが許可されるため、dp[i+2][1] のみを更新します。 2 ステップ (最後 = 1) の後、両方の遷移が有効になります。 エネルギーは到着の瞬間に追加され、各位置がパスごとに 1 回だけ寄与することが保証されます。 

初期化 dp[0][0] = dp[0][1] = 0 は、特殊なケースを使用せずに最初の移動を均一に動作させるためのモデリング トリックです。 位置 0 にはエネルギーがないため、合計は歪みません。 

## 実用的な例

 サンプル入力 n = 5、E = [1, 10, 10, 10, 1] を考えてみましょう。 

到達可能な状態のみを追跡します。 

| 私 | dp[i][last=1] (最後の 2 ステップ) | dp[i][last=0] (最後の 1 ステップ) |
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 2 | 10 | - |
 | 4 | 20 | - |
 | 5 | - | 21 |

 トランジションは 0 → 2 → 4 → 5 です。着地するたびに、エネルギーが追加されます: 10 + 10 + 1 = 21。この表は、ルールが連続する 1 ステップを厳しく制限しているため、2 ステップのトランジションのみが優勢であることを示しています。 

次に、より小さいケース n = 4、E = [5, 100, 5, 100] を考えてみましょう。 

| 私 | dp[i][last=1] | dp[i][last=0] |
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 2 | 100 | - |
 | 3 | - | 105 |
 | 4 | 200 | - |

 ここで、最適なパスは 0 → 2 → 4 で、100 + 100 = 200 を収集します。 1 ステップを早めに挿入しようとすると、別の 1 ステップがブロックされ、柔軟性が低下しますが、DP はこれを正しくキャプチャします。 

トレースは、状態分割が将来の移動オプションが最後のステップのみにどのように依存するかを正しく表していることを確認します。

 ## 特殊なケース

 n = 1 の場合、唯一の有効な移動は位置 1 への直接移動です。DP は dp[0][*] = 0 を初期化し、2 ステップを許可しますが、i+2 は無効であるため、最後の状態で許可されている場合は i+1 遷移のみが使用されます。 アルゴリズムは E1 を正しく生成します。 

n = 2、E = [100, 1] の場合、1 ステップの後に別の 1 ステップが禁止されるため、最適パスは 0 → 1 → 2 を回避します。 DP では 2 ステップによる 0 → 2 のみが許可され、値 1 が生成され、これは制約を意識した最適なソリューションと一致します。 

すべての値が同じ場合、将来の移動性が低下しないため、DP は当然、より多くの 2 ステップ ジャンプを好みます。 たとえば、n = 4、すべての E = 10 は 0 → 2 → 4 の合計 20 を生成しますが、状態制限により無効なチェーンが構築されることはなく、DP はオーバーカウントを正しく回避します。 

これらのケースは、状態エンコーディングが、より深い履歴を必要とせずに、移動制限を完全にキャプチャしていることを確認します。
