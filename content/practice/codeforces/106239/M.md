 ## 解決策
 ## 問題の理解

 私たちは国のコレクションを与えられています。各国はグラフ内のノードであり、すべての直接の敵関係はエッジです。 重要な構造上の保証は、これらの関係がツリーを形成するため、サイクルがなく、グラフが正確に n − 1 個のエッジで接続されていることです。 

「友情」という概念は直接的に縁関係として与えられるものではない。 代わりに、これはルールから導出されます。国 x に敵 y がいて、その敵 y に別の敵 z がいる場合、z は x の友人になります。 グラフ用語で言えば、これは、正確に 2 つのエッジをたどることによって x から到達可能なノードはすべて、x の友人に対応することを意味します。 このルールを超えてそれ以上の伝播は発生しないため、友情は厳密に長さ 2 のパスに関連付けられます。 

タスクは、すべてのノードについて、そのノードからちょうど 2 の距離にある個別のノードの数を計算し、この値を最大化するノードを最大数とともに出力することです。 

この制約は、テスト ケースごとに最大 10,000 個のテスト ケースで n を最大 200,000 にできることを意味しますが、すべての n の合計は 200,000 に制限されます。 これは、すべてのアルゴリズムが合計入力サイズに対して線形である必要があることを直ちに示唆しています。 テスト ケースごとに n で 2 次の解は遅すぎるため、テスト ケースごとに O(n log n) であっても、繰り返し適用すると危険になります。 

素朴な解釈では、ノードごとに深さ 2 までの BFS を実行し、距離 2 でノードをカウントすることを示唆します。これは正しいですが、これは多くの作業を繰り返すことになり、星型ツリーでは O(n²) 個の動作が発生する危険性があります。 

いくつかの微妙なケースについては注意する価値があります。 1 つの中心ノードが他のすべてのノードに接続する星型ツリーでは、すべてのリーフの BFS が中心と他のすべてのリーフを繰り返し通過するため、冗長な作業が発生します。 もう 1 つのエッジ ケースはパス グラフです。長いチェーンでは、各 BFS は依然として小さな部分を歩きますが、累積すると二次関数になります。 

重要な観察は、距離 2 のノードは、反復的な走査を実行せずに、純粋にローカル次数情報からカウントできることです。 

## アプローチ

 ブルート フォース ソリューションでは、各ノードを開始点と見なし、深さ 2 までの BFS または DFS を実行します。 ノード x から、すべての隣接ノード y を探索し、次に y のすべての隣接ノードを探索し、正確に 2 の距離にあるノードを収集します。 これは友情の定義に直接従うため、正しいです。 

ただし、各 BFS は密集した近傍で最大 O(n) ノードに接触する可能性があり、すべてのノードに対してこれを行うと、スターなどの最悪の場合のツリーでは合計で O(n²) の複雑さが生じます。 冗長性は、同じ隣接リストを繰り返しスキャンすることで得られます。 

重要な構造的洞察は、x からちょうど 2 の距離にあるノード z は、x の中間に隣接するノード y を介して接続されなければならないということです。 固定 y の場合、x を除く y のすべての近傍は、x から 2 の距離にある 1 つの有効なノードに寄与します。 これは、各近傍 y が x に deg(y) − 1 の候補を与えることを意味します。 x の近傍をすべて合計すると答えが得られます。 

これにより、計算がグラフの反復走査から隣接リストの単一パスに移行し、各エッジが一定量の情報を提供します。

 ## アルゴリズムのチュートリアル

1. ツリーの隣接リストを作成し、すべてのノードの次数を計算します。 この度数は、各国に直接の敵が何人いるかを表し、第 2 レベルの関係を推測するために使用されます。 
2. すべてのノード x について、カウンター ans[x] をゼロに初期化します。 これにより、正確に 2 の距離にあるノードの数が保存されます。 
3. ノード x のすべての隣接ノード y を反復します。 このような近隣ノードごとに、y に接続されているすべてのノードを考慮します。 
4. deg(y) − 1 を ans[x] に加算します。 減算により、y の近傍の数から x 自体が削除され、x から y までちょうど 2 ステップ離れたノードのみが残ります。 
5. すべてのノードを処理した後、ans をスキャンして最大値を持つノードを見つけます。 複数のノードが最大値を共有する場合、それらのいずれかを返すことができます。 

### なぜ効果があるのか

 任意の固定ノード x については、距離がちょうど 2 のすべてのノードが、x の近傍 y の近傍として現れる必要があります。 グラフはツリーであるため、任意の 2 つのノード間には単純なパスが 1 つだけ存在し、サイクル全体で二重にカウントされることはありません。 x のすべての近傍 y にわたって deg(y) − 1 を合計すると、距離 2 にある有効な各ノードは、x からの一意のパス上の一意の中間近傍 y に対応するため、1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n + 1)]
        deg = [0] * (n + 1)

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)
            deg[u] += 1
            deg[v] += 1

        ans = [0] * (n + 1)

        for x in range(1, n + 1):
            total = 0
            for y in g[x]:
                total += deg[y] - 1
            ans[x] = total

        best_node = 1
        best_val = ans[1]

        for i in range(2, n + 1):
            if ans[i] > best_val:
                best_val = ans[i]
                best_node = i

        print(best_node, best_val)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず隣接リストと次数カウントを線形時間で構築します。 次に、コアの計算は、近隣ノードからの寄与を合計することによって各ノードを独立して評価します。 近隣ノードごとに 1 つ減算することは、発信元ノード自体のカウントを防ぐ重要な修正です。 

最後のスキャンは、最大値を特定するための単純な直線パスです。

 ## 特殊なケース

 次のような 2 ノード ツリー`1 - 2`両方のノードにフレンドが作成されません。 各ノードには次数 1 の近傍ノードが 1 つだけ存在するため、アルゴリズムはこれを自然に処理します。そのため、1 を減算するとすべての寄与がゼロになります。 

星型の木は最も重要なストレスケースです。 他のすべてのノードに接続されている中心ノードの場合、各リーフは中心にゼロを寄与しますが、各リーフは中心を介して他のすべてのリーフを蓄積します。 この式は、横断することなく最大値を中心に正しく割り当てます。 

長いパスは、低次数ノード全体の累積をテストします。 内部ノードには 2 つの隣接ノードがあり、どちらも次数 2 で寄与がゼロですが、エンドポイントは距離 2 で正確に 1 つのノードを正確に蓄積します。
