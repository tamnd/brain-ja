 ## 解決策
 ## 問題の理解

 複数の独立したクエリが与えられます。 各クエリでは 2 つの素数が提供されますが、どちらも厳密には 10000 未満であり、必要に応じて先頭にゼロを埋め込んで 4 桁の数値として扱います。 許可される操作は、1 桁の位置を選択し、それを 0 ～ 9 の任意の桁に置き換えて、新しい 4 桁の文字列を形成することです。 変更後、結果の数値は通常どおりに解釈され (先頭のゼロは許可されます)、引き続き 2 ～ 9999 の範囲の素数を表す必要があります。 

課題は、常に素数を維持しながら、ある素数を別の素数に変換するために必要な、そのような 1 桁の変更の最小数を決定することです。 有効な変換のシーケンスが存在しない場合は、-1 を返します。 

ここでの構造は、数値操作の中に隠されたグラフ問題です。 10000 未満の有効な素数はそれぞれノードです。 2 つのノード間にエッジが存在するのは、それらの 10 進表記がちょうど 1 桁の位置で異なる場合です。 この問題は、この暗黙のグラフでは最短経路問題となり、最大 100 回繰り返されます。 

数値が 10000 未満であるという制約は、最大 10000 個の候補が素数であることを意味します。 クエリごとの直接最短パスは、繰り返しの検索を処理できるほど効率的である必要があります。 クエリごとに単純にグラフを構築するのは遅すぎますが、事前計算または再利用により実行可能になります。 

微妙なエッジケースは、先行ゼロから発生します。 たとえば、1031 は 0031 に変換できますが、これは有効で 31 として解釈されますが、素数の場合は範囲​​内にあります。 ただし、0031 のような中間状態は、近傍を生成するときに 4 桁の表現として扱う必要があります。 もう 1 つのエッジ ケースは、A が B に等しい場合で、答えはすぐにゼロになります。 

もう 1 つの重要なケースは、素数グラフで A と B が切断されている場合です。 両方が素数であっても、桁制限によりコンポーネントが分離される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、各クエリを独立して処理し、A から始まるすべての可能な数字シーケンスを検索し、一度に 1 桁ずつ変更して有効な次の素数をすべて生成することです。 これはグラフ走査問題であり、幅優先探索により自然に最短経路が見つかります。 

各テスト ケースに対して BFS を最初から実行すると、最大 9000 個の候補ノードが生成され、4 つの位置はそれぞれ任意の数字に置き換えることができるため、各ノードには最大 4 × 10 の可能な遷移があります。 これは、最悪の場合、BFS レイヤー探索ごとに約 360,000 の遷移が発生し、最大 100 のクエリが繰り返されます。これはまだ管理可能ですが、実装の品質によっては境界線に達します。 

重要な観察は、グラフがすべてのクエリにわたって固定されていることです。 10000 未満の素数はテスト ケース間で変化しません。 これにより、すべての素数を一度事前計算し、暗黙的に隣接関係を構築し、BFS の結果を効率的に再利用することができます。 最も重要な改善点は、ソースとして表示される素数のみから全ペアの最短パスを事前計算すること、またはより単純に、事前計算された素数セットと高速近傍生成を使用してクエリごとに BFS を実行することです。 

この問題を次のように簡略化します。数値から、1 桁を変更し、ふるいを使用して O(1) の素数をチェックすることで、有効な近傍をすべて生成します。 

これにより、クエリごとにクリーンな最短パスが得られます。

 ## アルゴリズムのチュートリアル

 まず、ふるいを使用して 9999 までのすべての素数を事前計算します。 これにより、移行中に一定時間の素数チェックが可能になります。これは、各 BFS ステップが多数の候補番号を生成する可能性があるため重要です。

次に、クエリごとに、A から始まる標準の幅優先検索を実行します。未訪問の状態を意味する -1 で初期化された距離配列または辞書を維持します。 

A を距離 0 のキューにプッシュします。 

次に、キューから数値を繰り返し抽出し、それを拡張しようとします。 近傍を生成するには、数値を先頭のゼロを保持した 4 文字の文字列に変換します。 4 つの位置のそれぞれについて、それを 0 から 9 までの数字に置き換えてみます。生成された候補ごとに、それを整数に変換し直し、2 つの条件をチェックします。それは、ふるいによると素数であること、およびまだ訪問されていないことです。 

両方の条件が成立する場合、その距離を割り当ててキューにプッシュします。 

Bに到達した場合は、早めに停止して距離を戻すことができます。 

B に到達せずに BFS が終了した場合、答えは -1 になります。 

### なぜ効果があるのか

 状態空間は正確に素数の 4 桁表現のセットであり、有効な各移動は 1 桁が異なる 2 つの状態間のエッジに対応します。 すべてのエッジが均一のコスト 1 を持つため、BFS はこのグラフの移動回数を増やして探索します。最初に B に到達するときは、最小数の変換を使用する必要があります。これは、代替パスには重み付けされていないグラフ内の少なくとも同じ数のエッジが必要になるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

MAXN = 10000

# Sieve for primes
is_prime = [True] * MAXN
is_prime[0] = is_prime[1] = False
for i in range(2, int(MAXN ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, MAXN, step):
            is_prime[j] = False

def bfs(start, target):
    if start == target:
        return 0

    dist = [-1] * MAXN
    q = deque([start])
    dist[start] = 0

    while q:
        x = q.popleft()
        s = list(f"{x:04d}")

        for i in range(4):
            original = s[i]
            for d in "0123456789":
                if d == original:
                    continue
                s[i] = d
                y = int("".join(s))

                if y >= 10000:
                    continue
                if y < 2:
                    continue
                if not is_prime[y]:
                    continue
                if dist[y] != -1:
                    continue

                dist[y] = dist[x] + 1
                if y == target:
                    return dist[y]
                q.append(y)

            s[i] = original

    return -1

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(bfs(a, b)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```sieve はグローバルに一度構築されるため、すべてのクエリが定数時間の素数チェックの恩恵を受けることができます。 BFS 内部では、数値は 4 桁の文字列としてフォーマットされるため、先頭のゼロも含めて桁の置換が簡単になります。 

主要な実装の詳細は、置換を試行した後に数字を復元し、一度に 1 つの位置のみを変更するようにすることです。 また、2 未満および 9999 を超える無効な数値もスキップしますが、その構造ではすでに上限が適用されています。 

目標に達したときに早期に終了すると、実際には実行時間が大幅に短縮されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    MAXN = 10000
    is_prime = [True] * MAXN
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(MAXN ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, MAXN, i):
                is_prime[j] = False

    def bfs(start, target):
        if start == target:
            return 0
        dist = [-1] * MAXN
        q = deque([start])
        dist[start] = 0
        while q:
            x = q.popleft()
            s = list(f"{x:04d}")
            for i in range(4):
                orig = s[i]
                for d in "0123456789":
                    if d == orig:
                        continue
                    s[i] = d
                    y = int("".join(s))
                    if y < 2 or y >= 10000:
                        continue
                    if not is_prime[y]:
                        continue
                    if dist[y] != -1:
                        continue
                    dist[y] = dist[x] + 1
                    if y == target:
                        return dist[y]
                    q.append(y)
                s[i] = orig
        return -1

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(bfs(a, b)))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、変換後の数値の内部位置にゼロが含まれる場合です。 たとえば、1031 から 0031 は有効な大きさを変更しますが、表現は BFS に対して有効なままです。 書式設定が常に 4 桁に固定されており、整数への変換が一貫しているため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、コンポーネントが切断されていることです。 A が 1009 のような素数で、B が 8179 の場合、有効なパスが存在しない可能性があります。 訪問した配列には B が含まれないため、BFS は到達可能な素数をすべて使い果たし、-1 を返します。 

3 番目のケースは自己変革です。 A が B と等しい場合、アルゴリズムは BFS に入らずにすぐに 0 を返し、不必要な計算を回避し、同じ状態の誤った再処理を防ぎます。
