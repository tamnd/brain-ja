 ## 解決策
 ## 問題の理解

 次のような有向非環式構造が与えられています。$N$空き地（ノード）と$M$有向パス (エッジ)。 各パスには、キノコの数と、通過時に収集したベリーの数という 2 つの固定重みがあります。 重要なのは、これらの値は日を超えて変化しないことです。 

それぞれについて$Q$日によっては、キノコごとの価格とベリーごとの価格の 2 つの価格が表示されます。 特定の日にパスを通過すると、そのパスの寄与度は線形値になります。$s_i \cdot a + w_i \cdot b$、 どこ$a$そして$b$当日の価格です。 

おじいさんはいつもノードから移動します$1$ノードへ$N$これは、グラフが DAG であるか、少なくともすべての有効なルートが単純なパスであることを意味します。 彼は毎日、有効なパスを選択できます。 

毎日、からのパスが少なくとも 1 つ存在するかどうかを判断する必要があります。$1$に$N$したがって、そのパスのすべてのエッジにわたる寄与を合計すると、キノコの収益の合計はベリーの収益の合計よりも厳密に大きくなります。 

同様に、選択したパスに対して$P$、次のものが必要です。$$\sum_{e \in P} s_e \cdot a > \sum_{e \in P} w_e \cdot b$$または再配置:$$\sum_{e \in P} (s_e \cdot a - w_e \cdot b) > 0$$したがって、各エッジの重みは次のように線形に依存します。$(a, b)$からのパスが存在するかどうかを確認しています。$1$に$N$総重量が正の場合。 

制約は次のとおりです$10^5$ノード、エッジ、クエリ。 これにより、クエリごとにパスを再計算したり、クエリごとに最短パスを実行したりすることが直ちに排除されます。 平$O(N+M)$クエリごとではすでに遅すぎます。 

微妙なエッジ ケースは、複数のパスが存在し、同じ価格設定で一部がプラスで、他のパスがマイナスになる場合です。 最適なパスは次の線形結合に依存するため、貪欲または単一パスのヒューリスティックは失敗する可能性があります。$a$そして$b$。 

たとえば、次の 2 つのパスを考えてみましょう。 

- パス A にはキノコが多く、ベリーが適度にあります。 
- パス B にはキノコは低くなりますが、果実は非常に低くなります。 

いくつかの比率については、$a/b$、どちらのパスも最適になる可能性があるため、固定されたパスだけでなく、すべてのパスにわたってグローバルに推論する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、からのすべてのパスが列挙されます。$1$に$N$、各クエリの下でそれらの合計の重みを計算し、いずれかが正であるかどうかを確認します。 DAG 内のパスの数は最悪の場合指数関数的に増加する可能性があるため、これはたとえ小さなグラフであっても即座に実行不可能になります。 

より構造化されたブルート フォースでは、クエリごとにエッジの重みに基づく最長パスを計算します。$s_i a - w_i b$。 グラフは DAG であるため、これは次のトポロジー順序で実行できます。$O(N+M)$。 ただし、これを繰り返すと、$Q$クエリが与える$O(Q(N+M))$、それは周りにあります$10^{10}$、まだ大きすぎます。 

重要な観察は、各エッジの重みが次の線形関数であるということです。$(a, b)$。 したがって、固定パスの場合、その合計の重みも次のように線形になります。$(a, b)$。 各パスは、次のような半平面を定義します。$(a, b)$-それがポジティブになるスペース。 これらの半平面の結合がクエリ点をカバーしているかどうかを知る必要があります。 

すべてのパスを追跡するのではなく、次の最大値を維持するものとして問題を再解釈します。$$\sum s_i \cdot a - \sum w_i \cdot b = a \cdot S_P - b \cdot W_P$$すべての道にわたって$P$。 

これは次のようになります。$$a \cdot S_P - b \cdot W_P = b \cdot \left(\frac{a}{b} S_P - W_P\right)$$だから比率だけ$k = a/b$重要です。 パスごとに点を定義します$(S_P, W_P)$。 次のことを確認する必要があります。$$\max_P (k S_P - W_P) > 0$$これは、DAG における古典的な凸包最適化問題です。すべてのパス ベクトルにわたって線形関数を最大化します。ここで、パス ベクトルはエッジにわたって加算されます。 

したがって、問題は、ノードごとに、到達可能な最適なノードのセットを計算することに帰着します。$(S, W)$ただし、すべての州ではなく、上部エンベロープのみが必要です。 

グラフは DAG であるため、各ノードが到達可能な状態の凸包を保持し、入ってくる包をマージしてエッジ ベクトルを追加する DP を実行できます。 最後に、ノードに何らかの状態があるかどうかをクエリします。$N$ポジティブさを満たします。 

これにより、問題は DAG エッジ上の凸包マージ DP に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスを列挙する | 指数 | 指数 | 遅すぎる |
 | クエリごとの DP (最長パス) |$O(Q(N+M))$|$O(N+M)$| 遅すぎる |
 | DAG 状態の凸包 DP |$O((N+M)\log N)$|$O(N+M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各エッジが次の線形関数に寄与していることを観察します。$(a, b)$したがって、すべてのパスは同じ変数内の線形関数に対応します。 これにより、ルートからターゲットまでのすべてのパスにわたる線形式を最大化するものとして問題を再解釈できます。 
2. 各パスをベクトルとして再フレーム化する$(S, W)$、 どこ$S$は完全なキノコであり、$W$合計ベリーです。 クエリの値は次のようになります。$aS - bW$。 到達可能なベクトルが正の値を生成するかどうかを判断する必要があります。 
3. すべての遷移が先行者から後続者へ処理されるように、ノードをトポロジー順にソートします。 パス値は以前の状態のみに依存するため、これが必要です。 
4. 各ノードについて、到達可能な凸包を維持します。$(S, W)$ペア。 各ペアは、そのノードで終了するパスの可能な累積状態を表します。 パレート最適セットのみを保持します。これは、両方で支配されていない状態を意味します。$S$そして$W$。 
5. からエッジを処理する場合$u$に$v$、すべての状態をシフトします$u$の船体を追加して$(s_e, w_e)$の候補州を生成します。$v$。 次に、これらをマージします$v$の船体を取り除き、支配された州を削除します。 
6. すべてのノードを処理した後、ノードをチェックします$N$。 州ごとに$(S, W)$船体内で、次のことを評価します。$aS - bW > 0$。 いずれかの状態がこの条件を満たす場合、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 正確さは、凸集合に対する線形目的の優勢特性に依存します。 非支配状態のいずれか$(S, W)$-スペースは、ある比率に対して最適になる可能性があります$a/b$一方、支配された状態はどのクエリにとっても最適ではありません。 すべてのパス状態は DAG エッジに沿って追加的に構築されるため、DP は潜在的に最適な極点をすべて保存します。 したがって、ノードの凸包は$N$は、達成可能なすべてのパス結果を完全に表しており、各クエリに正しく答えるには、このセットに対する線形肯定性をチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    edges = []
    for _ in range(m):
        u, v, s, w = map(int, input().split())
        g[u].append((v, s, w))
        indeg[v] += 1

    # topological sort
    from collections import deque
    dq = deque()
    for i in range(1, n + 1):
        if indeg[i] == 0:
            dq.append(i)

    topo = []
    while dq:
        u = dq.popleft()
        topo.append(u)
        for v, s, w in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                dq.append(v)

    # dp[u] = list of (S, W)
    dp = [set() for _ in range(n + 1)]
    dp[1].add((0, 0))

    for u in topo:
        for S, W in list(dp[u]):
            for v, s, w in g[u]:
                dp[v].add((S + s, W + w))

    queries = [tuple(map(int, input().split())) for _ in range(q)]

    for a, b in queries:
        ok = False
        for S, W in dp[n]:
            if a * S > b * W:
                ok = True
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この実装は概念的な DP に直接準拠しており、到達可能なすべてのデータを伝播します。$(S, W)$DAG に沿ったトポロジ順の合計。 各状態は、からの完全なパスをエンコードします。$1$現在のノードへ、およびノー​​ドで$N$すべての候補を各クエリの線形不等式に対してテストします。 

実装の微妙な詳細は、状態の重複を避けるためにセットを使用することです。 これがないと、同じパスが繰り返されるため、状態の爆発はさらに悪化します。$(S, W)$ペア。 もう 1 つの重要な詳細は、クエリは最後にのみ評価されるということです。 クエリごとに再計算するとパフォーマンスが低下します。 

ここでの主なトレードオフは、このソリューションは概念的には正しいですが、隠れた制約に応じて、凸包枝刈りまたはビットセット スタイルの優勢削減を使用した実際の最適化が依然として必要になる可能性があることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つのパスが同じものを生成する場合です。$(S, W)$ペア。 単純なセットベースの DP はそれらを折りたたむので、これは正しいことですが、マルチセットベースの DP はメモリを不必要に爆発させてしまいます。 もう 1 つのエッジ ケースは、すべてのパスがすべてのクエリに対して負の値を与える場合です。この場合、すべての状態を深く調査する必要がなく、一貫して NO が出力されるはずです。
