 ## 解決策
 ## 問題の理解

 複数の単語で構成されるテキストが与えられ、各単語は架空の言語の単純な音声規則に従うことになっています。 この言語定義では、単語が「名詞」または「動詞」のいずれかであれば有効です。 動詞は、母音のみで構成される空でないシーケンスです。 名詞とは、文字が母音と子音の間で厳密に交互に配置される空ではないシーケンスです。 

タスクは、意味論的な方法で単語を完全に再構成したり再分類したりすることではなく、すべての単語がこれらのルールの下で有効になるようにテキストを最小限に変更することです。 変更とは、文字を別の小文字のラテン文字に変更することを意味します。 変更された各文字は 1 つの間違いとしてカウントされ、すべての単語にわたる文字変更の合計数が最小になることが必要です。 

重要な構造的観察は、単語が独立しているということです。 ある単語を修正するコストは他の単語に影響を与えないため、全体的な答えは単語ごとの最適コストの合計にすぎません。 

入力サイズによってこれが重要になります。 最大 10^5 の単語を含めることができ、すべての単語の合計文字数は 10^6 に達することがあります。 単語ごとに二次関数さえも実行するソリューションは直ちに不可能です。 1 単語あたり O(n^2) であっても、限界をはるかに超えています。 意図したソリューションでは、各文字を O(1) 回の作業で処理し、合計線形 O(全長) を与える必要があります。 

素朴な誤解は、「すべての置換を試してみよう」としたり、「単語を名詞にするべきか動詞にするべきかを推測して、局所的に調整しようとしたりする」ことから生じます。 微妙なケースでは失敗する可能性があります。 

たとえば、次の言葉について考えてみましょう`"abc"`。 名詞の構造を選択する場合は、母音-子音-母音、または子音-母音-子音を交互に配置する必要があります。 動詞の構造を選択した場合は、すべてを母音に変換する必要があります。 不用意に貪欲なアプローチを行うと、両方のパターンをグローバルにチェックせずに一部の文字のみを変換し、編集数が最適以下になる可能性があります。 

もう 1 つの特殊なケースは、次のような 1 文字の単語です。`"b"`。 これは、名詞 (単一の文字が空に交互する) としても、動詞 (単一の母音のみ) としてもすでに有効です。 単純なアプローチでは、誤って変更を強制してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各単語を独立して扱い、それを同じ長さの可能なすべての有効な単語に変換しようとします。 長さ L の単語の場合、26^L 通りの可能性があり、母音パターンまたは子音パターンに限定しても、文字割り当ての指数関数的な組み合わせが依然として残ります。 構造パターンのみを修正して不一致を計算したとしても、考えられるすべての交互パターンと全母音パターンを試し、それぞれの編集距離を計算し、最小値を取るという乱暴な考えになります。 

最終的な有効な単語はこれらの構造テンプレートのいずれかに一致する必要があるため、これは原理的には正しいです。 ただし、単語ごとに文字を繰り返し再スキャンして複数のパターン チェックを行うため、遅すぎます。すべてのパターン バリエーションにわたって単純に実行すると、二次関数またはさらに悪い動作に劣化します。 

重要な洞察は、有効な単語の構造が非常に限られているということです。 パターンの種類は 2 つだけです。 

まず、動詞のパターンです。このパターンでは、すべての文字が母音でなければなりません。 

2 番目は名詞パターンです。各位置には、パリティのみに応じて固定の必要なタイプがあります。つまり、母音から始まる母音-子音-母音-子音、または子音から始まるかのいずれかです。 これにより、正確に 2 つの交互のテンプレートが得られます。 

単語ごとに、これら 3 つの候補 (全母音、母音で始まる交互、子音で始まる交互) に対するマッチングのコストを計算するだけで済みます。 各コストは 1 回のリニア スキャンで計算できます。 その中で一番良いのは、その言葉に対する答えです。 

これにより、問題は「文字列の検索」から「3 つの決定的なテンプレートの評価」に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての変換に対するブルートフォース | 指数 | お(1) | 遅すぎる |
 | 単語ごとに 3 つの構造テンプレートをチェック | O(全長) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各単語を個別に処理し、3 つのコストを計算します。 

1. 文字が母音であるかどうかをチェックするヘルパー述語を定義します。 母音セットは {a、e、i、o、u、y} です。 これにより、文字ごとに O(1) の分類が可能になります。 
2. 特定の単語について、その文字が母音ではない位置の数であるcost_vowelを計算します。 これは単語全体を動詞に変換するコストです。 その理由は、すべての非母音は母音に変更される必要があり、すべての母音はすでに有効であるということです。 
3. 母音で始まる単語を交互に作成するコストであるcost_alt0を計算します。 位置 i について、i が偶数の場合、ターゲットは母音でなければならず、それ以外の場合は子音です。 不一致ごとにコストが 1 増加します。 
4. 子音から始まる単語を交互に作成するコスト、cost_alt1 を計算します。 位置 i について、i が偶数の場合、ターゲットは子音、それ以外の場合は母音です。 再び不一致を数えます。 
5. 3 つのコストの最小値を取得し、それを全体的な答えに追加します。 
6. この結果をすべての単語にわたって合計し、出力します。 

重要な実装の詳細は、文字列を決して変更しないことです。 不一致のみをカウントするため、ソリューションが線形に保たれ、不必要な割り当てが回避されます。 

### なぜ効果があるのか

 有効な最終単語は、すべての母音、母音で始まる交互、または子音で始まる交互の 3 つの構造形式のいずれかに正確に準拠する必要があります。 固定ターゲット構造の場合、必要なタイプに一致するように各文字を個別に変更できるため、単語をその構造に変換するための最小編集回数は、正確に不一致の位置の数になります。 3 つの構造はすべての有効な定義を網羅しているため、それらの最小値を取ると全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def solve():
    n = int(input())
    words = input().split()
    
    ans = 0
    
    for w in words:
        cost_vowel = 0
        cost_alt0 = 0
        cost_alt1 = 0
        
        for i, ch in enumerate(w):
            is_vowel = ch in VOWELS
            
            # all vowels
            if not is_vowel:
                cost_vowel += 1
            
            # alternating starting with vowel
            if i % 2 == 0:
                if not is_vowel:
                    cost_alt0 += 1
                if is_vowel:
                    cost_alt1 += 1
            else:
                if is_vowel:
                    cost_alt0 += 1
                if not is_vowel:
                    cost_alt1 += 1
        
        ans += min(cost_vowel, cost_alt0, cost_alt1)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、すべての単語を一度に読み取り、文字に対する単一のループで処理します。 母音チェックはセットを使用した一定時間です。 

交互ロジックは純粋にインデックス パリティを通じて処理されます。 偶数のインデックスは最初のパターンの開始に対応し、奇数のインデックスがそれに応じて続きます。 これにより、文字列変換や補助配列が回避されます。 

微妙な点は、cost_alt0 とcost_alt1 が 1 つのパスで同時に計算されることです。 これにより、各単語を 3 回スキャンする必要がなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdin.readline() and solve_capture(inp)

def solve_capture(inp: str) -> str:
    from io import StringIO
    import sys

    backup = sys.stdin
    sys.stdin = StringIO(inp)

    VOWELS = set("aeiouy")

    n = int(sys.stdin.readline())
    words = sys.stdin.readline().split()

    ans = 0
    for w in words:
        cv = ca0 = ca1 = 0
        for i, ch in enumerate(w):
            v = ch in VOWELS
            if not v:
                cv += 1
            if i % 2 == 0:
                if not v:
                    ca0 += 1
                if v:
                    ca1 += 1
            else:
                if v:
                    ca0 += 1
                if not v:
                    ca1 += 1
        ans += min(cv, ca0, ca1)

    sys.stdin = backup
    return str(ans)

# minimum size
assert solve_capture("1\na\n") == "0"

# all consonants
assert solve_capture("1\nbcdf\n") == "2"

# all vowels
assert solve_capture("1\naeiouy\n") == "0"

# alternating already valid
assert solve_capture("1\naba\n") in {"0", "1"}

 ## 特殊なケース

 のような一文字の単語`"b"`3 つの構造すべてが重複する可能性があることを示しています。 このアルゴリズムは、cost_vowel = 1、cost_alt0 = 0 または 1 (パリティ ルールに応じて 1) を計算し、cost_alt1 も同様に計算するため、有効な構造が編集なしですでに一致している場合、最小値は正しく 0 になります。 

次のような完全子音文字列`"bcdfgh"`ソリューションが交互のパターンに依存するようになります。 母音のみの変換はコストが高く、最小限の編集で済むのはパリティベースの補正のみです。 スキャンでは、グローバルな再構築を必要とせずに、不一致が正しくカウントされます。 

のような完全母音文字列`"aeiouy"`は、動詞パターンが優勢な逆の状況を示しています。 どちらの交互パターンでも不要な不一致が生じますが、アルゴリズムは全母音オプションを正しく選択します。
