 ## 問題の理解

 プロジェクトの最終バージョン番号が正の整数で与えられます。$N$。 プロジェクトは、現在のバージョンが$k$1 か月後に次の数だけ増加します。$k$もの。 たとえば、5 桁のバージョンは次のように増加します。$11111$翌月には 3 桁のバージョンが増加します$111$、 等々。 

タスクは、順方向にシミュレーションすることではなく、指定された数値につながる可能性のある可能な限り最長の履歴を再構築することです。$N$。 その履歴の最初のバージョンは任意の正の整数にすることができ、各遷移は増分が現在の状態の桁長に依存するという規則に従う必要があります。 現在の月を含め、可能な最大の月数が必要です。 

重要な問題は、増分が固定定数ではなく、現在のバージョンの桁数に依存することです。 これは、このプロセスが単純な等差数列ではなく、それを元に戻すのが簡単ではないことを意味します。 

制約$N \le 10^{18}$すべての中間値が 64 ビット整数内に収まることを意味します。 考えられるすべての歴史を素朴に調査しようとするアプローチはどれも指数関数的に爆発的に増加します。なぜなら、各州には原則として複数の可能な前任者が存在する可能性があるからです。 

微妙なエッジケースは、桁長の遷移から発生します。 たとえば、999 と 1000 の間を移動すると桁数が変わり、次のステップでの増分サイズが変わります。 プロセスを元に戻すときに数字の制約を無視すると、前方のルールを満たさない無効な履歴が構築される可能性があります。 

## アプローチ

 直接的なアイデアは、から逆方向にシミュレーションすることです。$N$。 もし私たちが価値のあるところにいるなら$x$、前の値を推測しようとします$y$。 もし$y$持っていた$k$数字の場合、順方向遷移は次のようになります。$y + R_k = x$、 どこ$R_k = 111\ldots1$(k 桁)。 したがって、候補を計算できます$y = x - R_k$考えられるすべての桁の長さに対して$k$、次にこれがあるかどうかを確認してください$y$有効です。 

この総当りの逆ステップは局所的には正しいです。有効な以前のすべての状態がこれらの候補の中に出現する必要があります。 ただし、可能な限り分岐する$k \in [1, 18]$すべてのチェーンを再帰的に探索すると、最悪の場合、大きな検索ツリーが生成されます。 値が縮小するため深さは制限されますが、さまざまな選択肢が存在します。$k$異なる履歴が生じる可能性があり、最大長が必要であるため、貪欲な選択は明らかに安全ではありません。 

重要な観察は、出力遷移に関しては状態空間が小さいということです。 各数値には最大 18 個の有効な先行値があり、各先行値は次の条件によって一意に決定されます。$k$。 これにより、各ノードが数値であり、エッジが有効な以前の状態を指す有向グラフとしてプロセスを扱うことができます。 値はエッジに沿って厳密に減少するため、サイクルはなく、メモ化された DFS を使用して最長パスを計算できます。 

問題は、次で終わる最長のチェーンを見つけることになります。$N$DAG では、各ノードが桁長の制約によって定義される最大 18 個の先行ノードに分岐します。

 ## アルゴリズムのチュートリアル

 ### 1. レピュユニット値を定義します。 

考えられる各桁の長さについて$k$、事前計算$R_k = 111\ldots1$。 これは次のように効率的に計算されます。$(10^k - 1)/9$。 

これにより、数値が以前の状態から取得されたものであるかどうかをテストする直接的な方法が得られます。$k$数字。 

### 2. 逆遷移を定義する

 現在値の場合$x$、考えられるすべての桁の長さを試します$k$。 候補となる前任者を計算します。$$y = x - R_k$$これは、前の数値が正確に次の値を持っていた場合にのみ可能な前の値を表します。$k$数字。 

### 3. 候補者を検証する

 候補者$y$2 つの条件を満たす場合にのみ有効です。 

まず、それは正であり、次の範囲内にある必要があります。$k$-桁の数字:$$10^{k-1} \le y \le 10^k - 1$$次に、前方一貫性がなければなりません。$$y + R_k = x$$2 番目の条件は、次のように構築した場合、常に代数的に真です。$y$したがって、実際の制約は桁長の一貫性です。 

### 4. DFS + メモ化を使用して最適なチェーンを計算する

 関数を定義します$f(x)$で終わるステップの最大数として$x$。 それから：$$f(x) = 1 + \max f(y)$$すべての有効な先行者にわたって$y$。 

有効な先行者が存在しない場合は、$f(x) = 1$。 

メモ化により、各値が 1 回計算されることが保証されます。 

### 5. 答えを返す

 最終的な答えは、$f(N)$、指定されたバージョンで終わる可能な限り長い履歴を表します。 

### なぜ効果があるのか

 すべての有効な履歴は一連の有効な逆遷移に対応する必要があり、すべての逆遷移は桁長の選択によって完全に決定されます。 各遷移は数値の大きさを厳密に減少させるため、状態グラフは非周期的になります。 したがって、メモ化された繰り返しでは、考えられるすべての先行パスが最適に探索され再利用されるため、この DAG 内の最長パスが正確に計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

from functools import lru_cache

def repunit(k):
    return (10**k - 1) // 9

pow10 = [1]
for _ in range(20):
    pow10.append(pow10[-1] * 10)

@lru_cache(None)
def dfs(x):
    best = 1
    for k in range(1, 19):
        r = repunit(k)
        y = x - r
        if y <= 0:
            continue
        if pow10[k-1] <= y <= pow10[k] - 1:
            best = max(best, 1 + dfs(y))
    return best

def main():
    n = int(input().strip())
    print(dfs(n))

if __name__ == "__main__":
    main()
```実装は繰り返しを直接エンコードします。 の`repunit(k)`関数は増分パターンを効率的に構築します。 の`pow10`配列は、一定時間内に桁長の制約を強制するために使用されます。 

DFS は、考えられるすべての有効な先行データを探索し、結果をメモ化するため、各数値は 1 回だけ処理されます。 各ステップで大きさが大幅に減少するため、再帰の深さは小さいままです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(18 \cdot \text{states})$| 各状態は最大 18 桁の長さを試行し、各値はメモ化によって 1 回計算されます。 
| スペース |$O(\text{states})$| メモ化テーブルは、到達可能な各数値を 1 回ずつ保存します。 

到達可能な状態の数は、遷移ごとに大幅に減少するため少なくなります。そのため、再帰では、次の値までの値のまばらなサブセットのみが調査されます。$10^{18}$。

 ## 特殊なケース

 主なエッジケースは、減算により桁長が変化する場合です。 たとえば、4 桁の数値から開始すると、3 桁の先行数値が生成され、次のステップの増分ルールが変更される場合があります。 アルゴリズムは、各候補の桁制約を明示的にチェックすることでこれを処理します。$k$、有効な長さの先行部分のみが考慮されるようにします。 

別の特殊なケースは、10 の累乗付近で発生します。 たとえば、1000 や 10000 のような値は、条件に応じて 1 桁短いか、同じ長さの先行文字を持つことができます。$k$。 DFS は桁の長さの連続性を仮定せず、すべての可能性を独立して評価します。 

最後のケースは、先行者が存在しない非常に少数のケースです。 このような場合、DFS は正しく 1 を返し、現在のバージョンのみで構成される長さ 1 の履歴を表します。
