 ## 解決策
 ## 問題の理解

 一連の都市があり、各都市には既知の数のアトラクションが含まれています。 どの都市にも望遠鏡が設置されています。 各望遠鏡には、負ではない整数のパワーがあります。 街中の望遠鏡なら$i$力がある$p$そうすると、それを使用する観光客は、インデックスが距離内にあるすべての都市を観察できます$p$から$i$を中心とする連続セグメントを形成します。$i$、国境で切り取られます。 

固定都市の場合、望遠鏡を通して見ると、望遠鏡の可視セグメント内のすべての都市の観光スポットの合計に等しい、目に見える観光スポットの総数が生成されます。 要件は、この合計がグローバル制限を決して超えてはいけないことです。$R$。 各都市には独自の望遠鏡があり、中心都市でこの制約が満たされるように、各望遠鏡に可能な限り最大の出力を割り当てたいと考えています。 電力ゼロでもすでに制約を破っている都市がある場合は、構成が不可能です。 

重要な点は、各都市は個別にチェックされますが、制約はその都市の周囲の範囲の合計に依存するということです。 したがって、どのポジションでも$i$、事実上、最大半径を探しています。$p_i$周囲の対称セグメントの合計が$i$を超えない$R$。 

制約により強制的に$O(N \log N)$または$O(N)$解決。 と$N \le 10^5$、区間の二次展開は遅すぎます。 アトラクションの合計は最大に達する可能性があるため、$10^{14}$、プレフィックスの合計には 64 ビット演算も必要です。 

いくつかのエッジの状況が重要です。 

都市がすでに持っている場合$s_i > R$の場合、半径がゼロであっても失敗するため、その都市の答えはすぐに得られます。$-1$。 たとえば、次の場合$R = 3$そして$s = [1, 10, 1]$の場合、中央都市には有効な望遠鏡の電力を割り当てることができません。 

もう 1 つの微妙なケースは、半径を拡大すると配列の境界を急速に超える場合です。 正しい解釈は、間隔が端でクリップされるだけであり、これは範囲合計の計算で自然に処理される必要があるということです。 

最後に、各都市は独立しているため、都市間の半径を結合しようとするのは間違いです。 この制約は望遠鏡間で相互作用しません。 

## アプローチ

 簡単なアイデアは、各都市を独立して扱うことです。 固定中心の場合$i$、可能な限りあらゆる半径を試します$p$、のアトラクションの合計を計算します。$[i-p, i+p]$、それが範囲内にあるかどうかを確認します$R$。 これが機能するのは、条件がその区間に対して純粋にローカルであるためです。 

ただし、この強引なアプローチは遅すぎます。 最悪の場合、各都市は最大で半径を許可する可能性があります。$O(N)$、そして半径ごとに範囲の合計を単純に再計算すると、次のようになります。$O(N)$都市ごとに作業するか、$O(N^2)$トータルオペレーション。 と$10^5$都市の皆さん、これは制限時間をはるかに超えています。 

重要な点は、プレフィックス合計を使用して範囲合計を一定時間でクエリできることです。 プレフィックス合計が利用可能になると、固定半径のチェックが行われます。$O(1)$。 これにより、問題が単調探索に変換されます。半径が増加しても、間隔の合計は決して減少しないため、各都市の最大有効半径を二分探索できます。 

この単調性が解決策の鍵を握るのです。 すべての半径をスキャンする代わりに、間隔の合計が最初に超える境界を検索します。$R$。

 | 都市ごとのプレフィックス合計 + 二分検索 |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 アトラクション配列のプレフィックス合計を前処理して、セグメント合計を一定時間で計算できるようにします。 

都市ごとに$i$、次に最大半径を検索します。$p_i$区間内のアトラクションの合計が$[i-p_i, i+p_i]$を超えない$R$。 たとえさえあれば$p_i = 0$失敗した場合は出力します$-1$。 

1. アトラクションのプレフィックス合計配列を構築します。 これにより、任意の区間合計を一定時間で高速に計算できます。 
2. 都市ごとに$i$, まず、単一の都市がすでに制約に違反しているかどうかを確認します。 もし$s_i > R$、すぐに割り当てます$-1$。 これは、拡張ではローカル違反を修正できないため、必要です。 
3. それ以外の場合は、考えられる半径に対して二分探索を実行します。$0$に$N$。 上限$N$間隔が配列全体を超えることはできないため、安全です。 
4. 半径の候補について$m$、間隔を計算します$[L, R] = [i-m, i+m]$、有効なインデックスにクランプします。 プレフィックスの合計を使用して、このセグメント内のアトラクションの合計を計算します。 
5. 合計が以下の場合$R$、半径は実現可能であり、さらに拡大しようとします。 それ以外の場合は、半径を小さくします。 
6. 二分検索の結果により、都市の最大有効半径が得られます。$i$、これは答えとして保存されます。 

ステップ 4 の重要な考え方は、クランプによって境界都市が自然に処理されるため、インデックスの制限を超える特別なケースは必要ないということです。 

### なぜ効果があるのか

 固定中心ごとに$i$、関数を定義します$f(p)$の魅力の合計として$[i-p, i+p]$。 として$p$増加しても間隔は広がるだけなので、$f(p)$単調非減少です。 これにより、一度は$f(p)$を超える$R$、それより大きな半径はすべて無効です。 この単調な構造こそが二分探索を正確にし、中間候補を見逃さずに実行可能な最大半径を見つけることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def range_sum(l, rr):
        if l > rr:
            return 0
        return pref[rr + 1] - pref[l]

    def can(i, rad):
        l = max(0, i - rad)
        rr = min(n - 1, i + rad)
        return range_sum(l, rr) <= r

    res = []
    for i in range(n):
        if a[i] > r:
            res.append(-1)
            continue

        lo, hi = 0, n
        best = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(i, mid):
                best = mid
                lo = mid + 1
            else:
                hi = mid - 1

        res.append(best)

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```プレフィックス合計配列は 1 回構築されるため、各間隔クエリは 2 つの値の減算になります。 ヘルパー関数`can`境界クリッピングを強制します。これは配列の終端近くで不可欠です。 

二分探索は都市ごとに独立して実行されます。 の選択`n`半径が配列の全範囲を超えることはできないため、上限は安全です。 

ここでよくある間違いは、ケースの処理を忘れることです`a[i] > R`早い。 これがないと、中心自体が既に制約に違反しているにもかかわらず、二分探索で誤って正の半径が返される可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
3 4
1 2 1
```プレフィックスの合計を計算します。`[1, 3, 4]`。 

都市 1 (値 2) の場合、半径 0 は有効な 2 を与え、半径 1 は 1+2+1 = 4 を与え、これも有効です。半径 2 は境界を超えますが、それでも合計は 4 に等しくなります。したがって、結果は 2 になります。 

都市 2 (値 2) の場合、対称性により同じ結果 2 が得られます。 

都市 3 (値 1) の場合、半径 0 は 1、半径 1 は 2+1 = 3、半径 2 は 4 となるため、結果は 2 になります。 

出力:```
2
2
2
```このトレースは、セグメント全体の合計が制限に達した時点で拡張が正確に停止する様子を示しています。 

### 例 2

 入力:```
3 3
1 3 5
```プレフィックスの合計:`[1, 4, 9]`。 

都市 2 (値 3) の場合、半径 0 が有効です。 半径 1 では 1+3+5 = 9 が得られ、3 を超えるため、結果は 0 になります。 

都市 3 の値 5 はすでに 3 を超えているため、出力は -1 になります。 

| 都市 | 最適な半径 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 0 |
 | 3 | -1 |

 この例は、小さな拡張であってもすぐに制約を破る可能性があること、および無効な中心が検索前に検出されることを示しています。
