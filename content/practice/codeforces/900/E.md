 ## 解決策

 ## 問題の理解

 固定文字と未知の位置を含む長いテキスト文字列が与えられます。 それぞれの未知の位置は、後で次のいずれかで埋めることができます。`'a'`または`'b'`。 これに加えて、常に交互に現れるパターン文字列も与えられます。`'a'`その後`'b'`、 それから`'a'`、 等々。 

メイン文字列内の不明な文字を置き換える方法を選択できます。 文字列を修正した後、パターンのコピーをできるだけ多く配置したいと考えますが、これらのコピーは重なってはいけません。 このような互いに素なパターンの出現数を最大化する未知数を埋めるあらゆる方法の中で、置換の数も最小限に抑えたいと考えています。`'?'`私たちは作らなければなりませんでした。 

出力は、強制割り当ての最小数です。 

この制約により、両方の文字列の長さを最大 100,000 にすることができます。 これにより、すべての配置またはすべての割り当てを明示的に試行するアプローチは即座に除外されます。 すべての部分文字列の配置に対する 2 次スキャンでさえ、単純に実行すると最大 10^10 の潜在的なアライメントが存在するため、遅すぎます。 したがって、どのようなソリューションでも、効率的なローカル チェックを使用して問題を線形または線形に近いスキャンに減らす必要があります。 

重複するパターンと柔軟性の間の相互作用から、微妙な問題が発生します。`'?'`。 「可能な場合は常に一致を配置する」などの貪欲なローカル決定は、ローカルで有効な配置が後で複数のより適切な配置をブロックする可能性があるため失敗します。 もう 1 つの落とし穴は、1 つのウィンドウ内に文字を強制的に入れることが隣接するウィンドウにどのような影響を与えるかを考慮せずに、各一致を独立して処理することです。 

たとえば、文字列が次の場合、`"???"`パターンの長さが 2 の場合、複数の配置が重なり合います。 最初の一致候補を貪欲に選択すると、後で追加の置換が強制される可能性があります。ただし、それをスキップすると、総割り当て数が減り、2 つの素な一致が可能になる可能性があります。 

主要な困難は、パターン出現のグローバル パッキングを最大化し、同時に制約が重複する中でローカル割り当てコストを最小化することです。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法で置き換えを試みます。`'?'`と`'a'`そして`'b'`、次に、パターンの素の一致の最大数を計算します。 これだけでも、k が未知数の数である 2^k 個の可能性がすでに暗示されていますが、10^5 では実現不可能です。 

文字列の単一の補完を修正したとしても、素の出現の最大数を見つけることは O(n) で貪欲に実行できますが、すべての補完を試行すると爆発が発生します。 したがって、ブルートフォースは組み合わせ論によって根本的にブロックされます。 

割り当てを列挙することを完全に避ける必要があります。 重要な観察は、パターンが固定されており、非常に構造化されているということです。`'a'`そして`'b'`。 これは、候補部分文字列内のすべての位置に決定的な必須文字があることを意味します。 長さ m の各ウィンドウは、現在の部分文字列と互換性があるか互換性がありません。互換性がある場合は、完全に一致させるために必要な修正の最小数を計算できます。 

これにより、問題は、各間隔のコストが次の数に等しい、互いに素な間隔 (有効なパターン一致) を選択することに変わります。`'?'`それを実現するには修正する必要があります。 まず間隔の数を最大化し、次にその最大カーディナリティの下で総コストを最小化したいと考えています。 

これは、辞書編集的な目的を備えた古典的な加重間隔の選択です。つまり、カウントを最大化し、次にコストを最小化します。 間隔はすべて等しい長さ m であり、開始位置は線形であるため、左から右へ動的計画法を実行できます。 各位置で、スキップするか、そこで終了する有効な間隔をとり、i-m から i に移行します。 

すべてのウィンドウの一致コストを効率的に計算するために、プレフィックス合計を使用して不一致情報を事前計算します。 の場合、各ポジションは 1 を貢献します。`'?'`交互パターンとのパリティの位置合わせに応じて、文字が間違っている場合もあります。 これにより、O(1) ウィンドウ コスト クエリが可能になります。 

位置 i の DP 状態には、i までの最良の一致数と、その中での最小の置換のペアが格納されます。 遷移は辞書順に比較されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | O(2^k · n) | O(n) | 遅すぎる |
 | DP とウィンドウコスト | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字が必要なパターン文字と一致するか、または修正する必要があるかを位置ごとに示す配列を事前計算します。 

i で始まるウィンドウ内の位置 j に必要な文字は次のとおりです。`'a'`(j-i) が偶数であり、`'b'`さもないと。 不一致とは、間違った固定文字か、`'?'`。 
2. 任意のウィンドウ [i, i+m-1] を定数時間で評価できるように、不一致に対するプレフィックスの合計を構築します。 

これにより、重複するウィンドウに対して同じチェックを繰り返し再計算することが回避されます。 
3. 各状態がペア (一致数、置換数) を格納する動的プログラミング配列 dp を作成します。 

dp[i] は、位置 i で正確に終わるプレフィックスを使用して、達成可能な最良の結果を表します。 
4. 文字がない場合は一致も置換も行われないことを意味するため、dp[0] を (0, 0) として初期化します。 
5. 1 から n までの各位置 i について、まずデフォルトの遷移として dp[i-1] を繰り越します (i での一致終了をスキップします)。 

これにより、配置を強制しないベースライン ソリューションが常に確保されます。 
6. i で終わるウィンドウが存在する場合 (i ≥ m)、プレフィックス合計を使用してその不一致コストを計算します。 

次に、1 つの一致を追加し、不一致コストを追加して、dp[i-m] から移行することを検討します。 
7. スキップ オプションとテイク オプションを辞書順に比較します。一致が多いほど優れており、等しい場合は置換が少ないほど優れています。 

2 つのうち良い方を dp[i] に格納します。 
8. 答えは dp[n]、具体的にはその置換数です。dp[n] はすでにグローバルな一致の最大数に対応しているためです。 

### なぜ効果があるのか

 DP は、i-m から i へのすべての遷移が正確に m 位置をスキップするため、選択された間隔は特定の位置で終了する必要があり、以前に選択された間隔と決して重ならないように強制します。 すべての状態はプレフィックスに対する最適なソリューションを表し、遷移では 1 間隔だけ延長するかどうかのすべての有効な方法が考慮されるため、有効なパッキングは除外されません。 辞書編集的な比較により、区間数の最大化が優先されることが保証され、その場合にのみアルゴリズムが置換を最小限に抑え、問題の目的と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()
m = int(input().strip())

# mismatch prefix: mismatch[i] = 1 if s[i] differs from alternating pattern
pref = [0] * (n + 1)

def expected(pos):
    return 'a' if pos % 2 == 0 else 'b'

for i in range(n):
    ok = 1
    if s[i] != '?':
        if s[i] != expected(i):
            ok = 0
    pref[i + 1] = pref[i] + (1 - ok)

def cost(l, r):
    return pref[r + 1] - pref[l]

NEG = (-10**18, 10**18)
dp = [NEG] * (n + 1)
dp[0] = (0, 0)

for i in range(1, n + 1):
    best = dp[i - 1]
    if i >= m:
        prev_matches, prev_cost = dp[i - m]
        cur_cost = cost(i - m, i - 1)
        candidate = (prev_matches + 1, prev_cost + cur_cost)
        if candidate > best:
            best = candidate
    dp[i] = best

print(dp[n][1])
```この解決策は、文字を強制的に交互パターンに一致させるために必要な変更の数をエンコードすることから始まります。 これをウィンドウごとに再計算する代わりに、プレフィックス合計によって情報が圧縮されるため、各間隔コスト クエリは定数時間になります。 

次に、DP は左から右に進み、現在の位置でパターンの出現を終了することで辞書編集の目的が改善されるかどうかを常に考慮します。 ペアの比較では、個別のパスを必要とせずに、「一致を最大化し、置換を最小化する」ことが直接強制されます。 

DP ではインデックス付けは 1 ベースですが、文字列は 0 ベースなので、ウィンドウ [i-m, i-1] は i で終わる長さ m の出現に正確に対応します。

| 私 | 決定 | dp[i] |

    import sys

    s = input().strip()
    m = int(input().strip())

    def expected(pos):

        ok = 1
        if s[i] != '?':
            if s[i] != expected(i):
                ok = 0
        pref[i + 1] = pref[i] + (1 - ok)

    NEG = (-10**18, 10**18)

 ## 特殊なケース

 重要なエッジ ケースは、m = 1 の場合です。すべての位置が独立して有効な一致となるため、アルゴリズムは、すでに一致している固定文字の数をカウントすることになります。`'a'`。 すべてのインデックスが重複制約なしでテイクトランジションを許可するため、DP はこれを自然に処理します。 

もう 1 つのケースは、次のような完全に未知の文字列です。`"?????"`大きなmで。 すべてのウィンドウのコストはゼロですが、最大の分離ウィンドウの選択は純粋に間隔に依存します。 DP は、重複しないセグメントのみが選択されることを保証するため、floor(n/m) セグメントが正しく選択されます。 

文字列にウィンドウ内で競合する固定文字が含まれている場合。`"ababa"`パターン用`"aba"`、プレフィックスのコストによってそのようなウィンドウは高価になるため、DP は一致の最大数を維持するために必要な場合を除き、これらのウィンドウを回避します。
