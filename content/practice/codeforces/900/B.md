 ## 解決策
 ## 問題の理解

 2 つの整数を除算して形成される有理数が与えられ、その小数点以下の小数表現に興味があります。 タスクは、その無限 (または終了) 10 進展開で特定の数字が現れる最も早い位置を決定することです。 

入力は、分数を定義する分子と分母、および検索対象の 1 桁で構成されます。 概念的には、分子を分母で除算し、小数点以下に表示される数字を 1 つずつ観察することを想像します。 出力は、ターゲットの数字がこのシーケンスで最初に出現したときのインデックスです。小数点の後の最初の数字は位置 1 になります。その数字が一度も出現しない場合、答えは -1 になります。 

この制約により、小数部の両方の数値が最大 100000 になることが許可されます。これは十分に小さいため、桁ごとに長除算をシミュレートすることが可能です。 Long 除算の各ステップでは定数時間演算のみを使用するため、O(b) シミュレーションで十分です。 10 進数展開は最大でも長さ b のサイクルで繰り返すことができるため、意味のあるステップの数も b によって制限されます。 

素朴だが重要なエッジ ケースは、10 進数展開が早期に終了する場合です。 たとえば、剰余がゼロになると拡張は終了し、それ以上の桁は存在しません。 もう 1 つの微妙なケースは、必要な桁が 0 の場合です。多くの分数では、ゼロのない長い範囲が生成され、終端を誤って仮定したり、ゼロが数ステップの除算の後にのみ出現する可能性があることを見逃したりすることがよくあります。 

## アプローチ

 10 進展開を生成する簡単な方法は、手で行うのとまったく同じように長除算をシミュレートすることです。 a を b で割った余りから始めて、余りを 10 倍し、整数除算で次の桁を抽出し、余りを更新します。 生成された各桁がターゲットの桁と照合されます。 このプロセスは、数字が見つかるか、剰余がゼロになるまで続きます。これは、10 進数の展開が終了することを意味します。 

これが機能するのは、各ステップで 10 進数が 1 つずつ順番に生成されるためです。 ただし、最悪の場合、剰余は繰り返す前に多くの値を循環する可能性があり、プロセスは最大 b ステップ実行される可能性があります。 b は 100000 にできるため、これでも効率的ですが、保証したい値の上限に位置します。 

より構造化されたビューは、剰余を決定論的なプロセスの状態として扱うことです。 各剰余は、次の桁と次の剰余を一意に決定します。 可能な剰余は b 個だけであるため、剰余が繰り返されると、10 進展開が循環し始めます。 これにより、シーケンスを完全に特徴付けるために b ステップを超える必要がなくなりました。 必要に応じて、訪問した剰余を追跡できますが、単に b ステップまで繰り返すか、剰余 0 で停止するだけで十分です。

 ## アルゴリズムのチュートリアル

 標準的な長除法手順を使用して、10 進数展開を段階的にシミュレートします。

1. a mod b に等しい初期剰余から開始します。 これは、整数部分を抽出した後に残ったものを表しますが、小数点以下の数字のみが重要であるため無視します。 
2. 以下のプロセスを b ステップまで繰り返します。これは、繰り返す必要があるまでに可能な残りが最大 b 個あるためです。 
3. 現在の余りに 10 を掛けます。これにより、除算が次の小数位に移動します。 
4. この値を b で割った整数として次の桁を計算します。 これは、まさに 10 進展開の次の桁です。 
5. b によって剰余をこの値の係数に更新します。 この余りによって、将来のすべての桁が決まります。 
6. 生成された数字とターゲットの数字を比較します。 c. 一致する場合は、現在の位置 (1 から始まるインデックス) を返します。 
7. 剰余がゼロになると、10 進数展開は終了するため、早めに停止し、桁が見つからなかった場合は -1 を返します。 

重要な不変条件は、各ステップで、ペア (数字、剰余) が正確な長い除算プロセスの次の未使用部分を正しく表すことです。 長除算は決定論的であり、剰余によって完全に特徴付けられるため、桁がスキップされたり、計算が間違ったりすることはありません。 10 進展開のすべての位置は、順番に 1 回だけ訪問されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    rem = a % b
    for pos in range(1, b + 1):
        rem *= 10
        digit = rem // b
        rem %= b

        if digit == c:
            print(pos)
            return

        if rem == 0:
            break

    print(-1)

if __name__ == "__main__":
    solve()
```この実装は、長い除算プロセスを直接反映しています。 剰余はモジュロを使用して初期化され、整数部分が破棄されます。 各反復では 10 進数が 1 つだけ生成され、ループ インデックスは小数点以降の位置を表します。 剰余がゼロになったときに早期に終了することで、10 進展開が終了した後の不要な反復を防止します。 

微妙な詳細は、b 回の反復のループ境界です。 訪問した残りの状態を明示的に追跡しなくても、考えられる残りの状態は b 個しかないため、この境界によって終了が保証されます。 もう 1 つの重要な詳細は、整数演算のみを使用し、浮動小数点エラーを完全に回避することです。

 ## 特殊なケース

 一般的なエッジケースは、剰余がゼロになるために小数部が早期に終了する場合です。 たとえば、入力の場合`1 4 3`、小数展開は次のようになります。`0.25`。 2 桁目を生成すると、余りは 0 になります。 ループはすぐに停止し、数字 3 が表示されないため、出力は -1 になります。 このアルゴリズムは、存在しない数字への継続を正しく回避します。 

もう 1 つのケースは、対象の桁が 0 の場合です。 のために`1 8`、展開は`0.125`。 アルゴリズムは生成された各桁を明示的にチェックするため、2 番目の位置のゼロは特別なケースを使用せずに正しく検出されます。 

最後の微妙なケースは、数字が繰り返しサイクルの後半に現れる場合です。 のために`1 7`、展開は`0.142857...`。 アルゴリズムは剰余のサイクル全体を探索し、サイクル内に数字が存在する場合は最終的にその数字を検出します。 そうでない場合は、有界反復により無限ループを起こさずに確実に終了します。
