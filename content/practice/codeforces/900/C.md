 ## 解決策

 ## 問題の理解

 順列が与えられ、それを左から右に見て、その値がその前に見られたものよりも厳密に大きい場合は必ずその位置を「レコード」としてマークします。 同様に、レコードは、新しいプレフィックス最大値が現れる位置です。 

順列から 1 つの要素だけを削除することができます。 削除後、残りのシーケンスが圧縮され、この新しいシーケンスにレコード位置がいくつ存在するかが再度カウントされます。 タスクは、削除によってこの数値が最大になる要素を選択することです。複数の要素が同じ最良の結果を与える場合、それらの中で最小の値を出力する必要があります。 

入力サイズは最大 100000 に達するため、すべての削除選択肢に対する二次シミュレーションは遅すぎます。 すべての削除を試行し、線形時間でレコード数を再計算するソリューションでは、最悪の場合でも約 10^10 の操作が必要になりますが、これは 2 秒では実現できません。 これにより、プレフィックス情報を再利用し、すべてを最初から再計算することを回避するソリューションが即座に推進されます。 

配列が非常に小さい場合、微妙なエッジ ケースが発生します。 順列のサイズが 1 の場合、唯一の要素を削除すると空のシーケンスが残り、唯一の有効な答えはその要素自体です。 もう 1 つの重要な状況は、初期の大きな要素を削除すると、プレフィックスの最大値が下がり、新しいレコードが以前よりも早く表示されるようになるため、後の多くのレコードが変更される場合です。 レコード位置を削除するときに 1 つのレコードを減算するだけの単純なアプローチは、サフィックスのしきい値がどのように変化するかを無視するため、このような場合には失敗します。 

## アプローチ

 直接的なアプローチは簡単です。 インデックスごとに、その要素を削除し、配列を再構築し、プレフィックスの最大値を数えながら左から右にスキャンします。 これが機能するのは、定義がローカルであるためです。つまり、各要素は以前の最大値にのみ依存します。 ただし、n 個の候補のそれぞれに O(n) 個の作業コストがかかるため、削除するたびに再構築と再スキャンを行うと O(n^2) アルゴリズムが必要になります。 

重要な観察は、記録は完全に現在の最大値によって決まるということです。 要素の削除は、サフィックス内の比較にのみ影響し、各ステップでの現在の最大値の変更を通じてのみ影響します。 これは、削除のたびに配列全体を再構築する必要がないことを意味します。 1 つの要素をスキップした後に実行最大値がどのように変化するかを理解することだけが必要です。 

これを構造化する便利な方法は、位置を元の配列内のレコードである位置とそうでない位置に分割することです。 非レコード要素を削除すると、すべての元のプレフィックス最大値は同じ位置で有効なままとなり、すべてのしきい値が変更されないため、新しい要素は以前よりも前にレコードになることはできません。 したがって、このような削除では常に同じ数のレコードが保持されます。 

レコード位置を削除すると、実行最大シーケンスが変更されます。 しきい値が前のレコードの値まで低下するため、次のレコード セグメントが早く開始される可能性があります。 これにより、サフィックス内の複数の新しい要素がレコードになる可能性があります。 したがって、解答を改善できる候補となるのはレコード位置のみです。 

これにより、問題は、しきい値が以前のレコードの最大値まで下げられたときに、レコード位置ごとにサフィックスに表示される新しいレコードの数を評価することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 記録に基づく評価 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 順列を 1 回処理して、すべてのレコードの位置を特定し、それらの値を順番に保存します。 また、各位置までの最大値も追跡するので、インデックスごとに O(1) のレコードを認識できます。 

次に、考えられる削除をそれぞれ評価します。

1. 元の順列におけるレコード位置のリストを計算します。 

位置 i の値が以前のすべての値の最大値より大きい場合、その位置はレコードです。 これにより、配列に沿って厳密に増加するレコード値のシーケンスが得られます。 
2. レコード位置を r1、r2、...、rk とします。 また、prevMax[t] を厳密に rt 前の最大値として定義します。これは正確に r(t-1) の値であり、prevMax[1] は 0 として扱われます。 
3. 非レコード要素を削除することを検討してください。 

プレフィックス最大値シーケンスはまったく変化しないため、レコード数は k のままです。 これによりベースラインの答えが得られ、最適なソリューションは少なくともこの程度の優れたものでなければなりません。 
4. 位置 rt にあるレコードを削除することを検討します。 

これにより、保証されたレコードが 1 つ削除されるため、カウントは 1 つ減少しますが、セグメント (rt、rt+1) に新しいレコードが作成される可能性があります。 
5. 連続レコード間の各セグメントについて、開始最大値を prevMax[t] まで下げた場合にレコードになる要素の数をシミュレートします。 

セグメントをスキャンし、値が現在の実行最大値を超える要素をカウントします。この最大値は prevMax[t] から始まり、新しいレコードが見つかるたびに更新されます。 
6. すべての削除の中から最良の結果を取得し、同点の中から削除された要素の最小値を選択します。 

### なぜ効果があるのか

 このアルゴリズムは、レコード位置が実行最大値に関して配列を独立した単調セグメントに分割するという事実に基づいています。 各セグメント内では、要素がレコードになるかどうかは、セグメントに入る最大値のみに依存します。 非レコードを削除してもセグメント境界条件は変更されないため、今後の比較に影響を与えることはありません。 レコードを削除すると、1 つの境界条件、つまり後続のセグメントの開始最大値のみが変更されます。 これがレコードの作成に影響を与える唯一の値であるため、調整されたしきい値を使用して各レコードの位置を評価すると、レコード数の考えられるすべての変化が正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    if n == 1:
        print(p[0])
        return

    # find record positions
    records = []
    max_so_far = 0
    is_record = [False] * n

    for i in range(n):
        if p[i] > max_so_far:
            is_record[i] = True
            records.append(i)
            max_so_far = p[i]

    k = len(records)

    # baseline: remove any non-record keeps k records
    best_count = k
    best_value = min(p[i] for i in range(n) if not is_record[i]) if k < n else p[records[0]]

    # try removing each record
    for idx, r in enumerate(records):
        prev_max = 0 if idx == 0 else p[records[idx - 1]]

        count = k - 1
        cur_max = prev_max

        i = r + 1
        while i < n:
            if p[i] > cur_max:
                count += 1
                cur_max = p[i]
            i += 1

        if count > best_count or (count == best_count and p[r] < best_value):
            best_count = count
            best_value = p[r]

    print(best_value)

if __name__ == "__main__":
    solve()
```この実装では、最初に単一パスですべてのレコード位置を識別します。 次に、2 種類の削除を個別に評価します。 非レコード削除のベースラインは、どの要素がレコードとしてマークされていないかをチェックし、その中で最小のものを選択するだけで計算されます。 

レコードの削除の場合、コードは削除されたレコードの直後から始まるサフィックスを明示的にシミュレートしますが、実行最大値は前のレコードの値に初期化されます。 これは、そのレコードの削除によって引き起こされるしきい値の変化と直接一致します。 

よくある落とし穴は、レコードを削除した後、次の要素がより小さい最大値と比較されることを忘れることです。これにより、レコード数が大幅に増加する可能性があります。 内側のループでは、この効果が完全に取り込まれます。

 ## 特殊なケース

 単一要素の置換の場合、アルゴリズムは直ちにその要素を返します。 分析するレコード位置はなく、それを削除すると、唯一の有効な出力が自明に生成されます。 

厳密に増加する順列の場合、すべての要素がレコードになります。 最初の要素を削除すると、初期最大値が非常に小さい値から 2 番目の要素に下がりますが、追加のレコードは作成されないため、最小値を削除するのが最適です。 

厳密に減少する順列の場合、最初の要素のみがレコードになります。 これを削除すると、初期最大値がゼロに下がり、すべての要素が新しいベースラインを基準としたサフィックス スキャンのレコードになり、残りのセグメントに対するシミュレーションによって正しくキャプチャされます。 

高い値と低い値が交互に現れるなど、混合順列の場合、レコード位置を削除すると、サフィックス内の複数の新しいレコードのロックが解除されるようにしきい値が変更されます。 アルゴリズムは、調整された開始最大値を使用してサフィックスを明示的に再計算し、これらのカスケード効果が完全にカウントされるようにします。
