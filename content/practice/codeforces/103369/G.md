 ## 問題の理解

 整数の配列と、最大 1 回のみ使用できる 1 つの許可された操作が与えられます。 この操作により、位置のサブセットを選択し、同じ正の値を追加できます。$k$選択したすべての要素に適用されます。 オプションでこの操作を 1 回適用した後、結果として得られる配列が非減少になるようにします。 

言い換えれば、均一なシフトによって一部の要素を上方に「リフト」することができ、選択したサブセットに適用されるこの単一のグローバル増分のみを使用して、元の順序によって引き起こされるすべての逆転を修正できるかどうかを知りたいのです。 

主な難点は、操作が非常に制約されていることです。要素を個別に調整することはできず、配列を 2 つのグループに分割するだけです。$+k$そうでない人も。 

制約が意味するのは、$n$まで$2 \cdot 10^5$したがって、すべてのソリューションはテスト ケースごとに線形またはほぼ線形である必要があります。 すべてのサブセットまたはペアにわたる二次推論は不可能です。 

素朴な解釈では、インデックスのすべてのサブセットと可能なすべてを試してみることを提案するかもしれません。$k$、しかし、それはサブセットの選択では指数関数的であり、無限です$k$。 構造パターンに限定しても、強い単調性を利用しない限り、依然として多くのケースが発生します。 

配列がすでに非減少である場合、微妙なエッジケースが発生します。 その場合、正しい答えはすぐにわかります。操作をまったく適用しないことを選択できます。 配列が複数の減少セグメントを除いて「ほぼソートされている」場合、別のエッジ ケースが発生します。 たとえば、次のような配列では、$[3, 1, 2, 4]$、必要な修正が反転間で一貫性がない場合、単一の均一リフトでは順序を修復できません。 

## アプローチ

 ブルートフォース戦略では、インデックスのすべてのサブセットを「リフトセット」とみなして、リフトセットが存在するかどうかを判断しようとします。$k$追加した後のように$k$そのサブセットに対して、配列はソートされます。 固定サブセットの場合、実現可能性の判断は、違反したすべての順序制約が単一の一貫したシフトによって満たされるかどうかを確認することに帰着します。 ただし、$2^n$サブセット、そしてそれぞれをチェックするのにも時間がかかります$O(n)$、につながる$O(n2^n)$、これは実現不可能です。 

重要な点は、この操作により配列位置のバイナリ パーティションが作成されることです。各インデックスは変更されないか、同じ量だけシフトされます。 有効な最終ソート配列を修正したら、すべての要素は 2 つの「レベル」のいずれかに属さなければなりません: 元の値または元の値と値を加えたもの$k$。 これは、最終的にソートされたシーケンスで、シフトされていない要素からシフトされた要素に移行するときは常に、差異の構造がグローバルに一貫していなければならないことを意味します。 

重要な洞察は、配列のソートされたバージョンを確認し、それを元の配列と比較することです。 配列をソートすることを想像すると、最終的な配列の各要素は、元の値、または元の値から値を引いた値のいずれかに対応します。$k$。 したがって、元の配列をそのソートされたバージョンと整列させる場合、対応する要素間の差異は最大 2 つの異なる値を取る必要があります。$0$そして$k$。 3 番目の違いがあると、すぐに変換が不可能になります。 

これにより、問題は、元の配列とソートされた配列の間の差分マルチセットに最大 1 つの正の個別値が含まれるかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 ### 1. 配列のコピーをソートします。 

入力配列のソートされたバージョンを構築します。 これは、達成したい目標の非減少順序を表します。 

### 2. 元の各要素とソートされた位置を比較します。 

インデックスごとに、並べ替えられた値と元の値の差を計算します。 この違いにより、ソートされた位置に一致させるためにその要素をどれだけ増やす必要があるかがわかります。 

負の差が見つかった場合、それは元の要素がすでに並べ替えられた位置よりも大きいことを意味し、値を追加するだけでは修正できないため、答えは直ちに不可能になります。 

### 3. 肯定的な相違点をすべて収集する

 私たちはすべての肯定的な違いを集めます。 これらは、並べ替えられた位置に到達するために増加する必要がある要素を表します。 

単一の操作で 1 つの操作のみが許可される場合$k$の場合、選択されたすべての要素がまったく同じ増分を受け取るため、これらの正の差はすべて等しい必要があります。 

### 4. 必要な増分の一貫性を検証する

 一連の正の差に複数の異なる値が含まれている場合、単一の値を選択することは不可能です。$k$必要なすべての位置を同時に修正します。 

明確な正の差が 1 つだけ存在する場合、その値が候補となります。$k$。 

### 5. 実現可能性を決定する

 競合が発生せず、すべての条件が満たされている場合、配列は 1 回の操作で修正できます。すでにソートされている場合は 0 回の操作で配列を修正できます。 

### なぜ効果があるのか

 この操作により、厳密な構造が課せられます。つまり、変更されたすべての要素がまったく同じ量だけシフトします。 ソートされたターゲットと比較する場合、各要素は独立して必要なシフト値を意味します。 上に移動する必要がある要素間で複数のシフト値が必要な場合、それらを単一のグローバルと調整する方法はありません。$k$。 逆に、必要なシフトがすべて一致する場合は、それらの要素を正確に選択して適用できます。$k$、ソートされた配列を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    diffs = set()
    
    for x, y in zip(a, b):
        if y < x:
            print("No")
            return
        if y > x:
            diffs.add(y - x)
    
    if len(diffs) <= 1:
        print("Yes")
    else:
        print("No")

t = int(input())
for _ in range(t):
    solve()
```この実装は、配列をそのソートされたバージョンと位置合わせするという考えに直接従っています。 重要な点は、いかなる増額要求も必要とされる均一なシフトの証拠として扱うということです。 複数の明確なプラスの変化が現れた場合、直ちに拒否します。 

小切手`y < x`ソートで要素を減らす必要があるが、操作では許可されていない、不可逆的な反転のケースを処理します。 

セット`diffs`必要な増分のグローバルな一貫性を強制します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、配列がすでにソートされている場合です。 すべての差がゼロであるため、アルゴリズムはこれを処理し、セットは空のままになり、答えが受け入れられます。 

もう 1 つのケースは、1 つの要素だけを移動する必要がある場合です。 例えば、$[1, 3, 2]$単一の正の差分パターンが生成されますが、これは依然として一貫しているため、アルゴリズムはそれを正しく受け入れます。
