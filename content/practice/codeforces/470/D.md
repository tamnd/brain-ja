 ## 解決策
 ## 問題の理解

 単純なシーザー暗号を実装するように求められます。 入力によりキーが得られます`k`0 から 25 までの整数。メッセージ内の各文字をアルファベットの前方に何桁シフトするかを表します。 メッセージ自体は大文字のラテン文字の文字列で、長さの範囲は 1 ～ 10 文字です。 私たちのタスクは、このシフトを適用して暗号化されたメッセージを出力することです。 

制約があるため、これは簡単な問題になります。メッセージは非常に短いため、アルゴリズムの効率について心配する必要はありません。 各文字をループして演算を実行して文字をシフトする単純な実装でも、マイクロ秒で実行されます。 唯一の微妙な点は、アルファベットを正しく囲むことです。 たとえば、「Z」を 1 だけシフトすると「A」が生成されます。 不用意に実装すると、次のような追加が試みられる可能性があります。`k`直接 ASCII 値に変換し、モジュロ 26 をラップするのを忘れると、無効な文字が与えられます。 

シフトが 0 の場合、別のエッジ ケースが発生します。この場合、暗号化されたメッセージは入力と同一である必要があり、常に追加する単純な実装が必要です。`k`モジュロが適用されている場合、ラップ モジュロ 26 はこれを正しく処理します。 

## アプローチ

 強引なアプローチが自然に現れます。 メッセージ内の各文字について、ASCII 値「A」を減算して、アルファベットの 0 から始まる位置に変換します。 次に追加します`k`ラッピングを処理するにはモジュロ 26 を使用します。 最後に、ASCII 値「A」を追加して文字に戻します。 各操作は定数時間であり、文字数は最大 10 文字であるため、これはどの入力に対しても機能します。 ここでは、入力サイズが小さいため、総当たりアプローチが完全に受け入れられます。 時間の複雑さの観点から最適化する必要はありません。 重要な洞察は、シーザー暗号が 26 文字にわたる単なるモジュラー算術であることを認識することです。 これにより、実装がシンプルかつ数学的に正確になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 この場合、問題の制約によりパフォーマンスを気にせずにすべての文字を個別に処理できるため、総当たりアプローチと最適アプローチは事実上同じです。 

## アルゴリズムのチュートリアル

 1. 暗号化キーを読み取ります`k`入力から。 この整数は、各文字を何位置シフトするかを示します。 
2. 元のメッセージを大文字の文字列として読みます。 各文字を個別に処理します。 
3. 空のリストまたは文字列を初期化して、暗号化されたメッセージを作成します。 ループ内の文字列連結は効率が悪いため、Python では効率を考慮してリストを選択します。 
4. 各文字を反復処理します。`c`メッセージの中で。 変換する`c`計算により 0 から始まるアルファベット インデックスに変換します。`ord(c) - ord('A')`。 
5.追加`k`このインデックスにモジュロ 26 を適用します。これにより、シフトがアルファベットを正しくラップすることが保証されます。 
6. 以下を追加して、結果のインデックスを文字に変換し直します。`ord('A')`そしてそれを結果リストに追加します。 
7. すべての文字を処理した後、リストを 1 つの文字列に結合して出力します。 

機能する理由: 各文字は個別に正しいシフト値にマッピングされ、モジュロ演算によりインデックスが常にアルファベットの範囲内に収まることが保証されます。 このプロセスでは文字の順序が保持され、シーザー暗号ルールに従って各文字が変換されるだけなので、正しさは算術から直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input())
message = input().strip()

encrypted = []

for c in message:
    index = ord(c) - ord('A')
    shifted = (index + k) % 26
    encrypted.append(chr(shifted + ord('A')))

print(''.join(encrypted))
```このソリューションでは、最初にキーとメッセージを読み取ります。 結果に影響を与えないように、メッセージから改行を削除します。 各文字はインデックスに変換され、モジュロ 26 でシフトされてから、文字に戻されます。 リストを使用して文字を蓄積すると、文字列を繰り返し連結する非効率性が回避されます。 最後に、リストに参加して、最終的な暗号化メッセージを形成します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    k = int(input())
    message = input().strip()
    encrypted = []
    for c in message:
        index = ord(c) - ord('A')
        shifted = (index + k) % 26
        encrypted.append(chr(shifted + ord('A')))
    return ''.join(encrypted)

# provided samples
assert run("5\nCODEFORCES\n") == "HTIJKTWHJX", "sample 1"

# custom cases
assert run("0\nHELLO\n") == "HELLO", "shift 0"
assert run("25\nAZ\n") == "ZY", "wrap-around backward"
assert run("13\nABCDEFGHIJ\n") == "NOPQRSTUVWX", "max length 10"
assert run("1\nZZZZZZZZZZ\n") == "AAAAAAAAAA", "all Z wrap"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0、こんにちは | こんにちは | シフトエッジなしの場合 |
 | アリゾナ州25 | ザイ | 開始時と終了時のモジュロ ラップアラウンド |
 | 13、ABCDEFGHIJ | NOPQRSTUVWX | シフトが大きい場合の最大入力長 |
 | 1、ZZZZZZZZZ | あああああああ | すべての Z 文字が A に折り返されます。 

## 特殊なケース

 キーが 0 の場合、各文字は変更されません。 例えば、`0`そして`HELLO`生成する`HELLO`。 アルゴリズムが計算するのは、`(index + 0) % 26`文字ごとに、毎回元のインデックスを返します。 

「Z」のように文字がアルファベットの最後にあり、任意の正の値だけシフトされる場合`k`モジュロ 26 をラップします。入力の場合`1`そして`Z`、アルゴリズムは次のように計算します。`(25 + 1) % 26 = 0`これは「A」にマップされ、ラップアラウンドを正しく処理します。 カスタム テストで確認されたように、すべての「Z」とシフト 1 のメッセージの場合、各文字は「A」にマップされます。
