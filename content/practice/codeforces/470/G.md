 ## 解決策
 ## 問題の理解

 タスクは、同じ長さの 2 つの文字列間のハミング距離を計算することです。 実際には、2 つの文字シーケンスを比較し、異なる文字が含まれる位置の数を数えることになります。 それぞれの不一致は距離に 1 だけ寄与します。 たとえば、比較すると、`CODECHEF`そして`TOPCODER`、文字が異なる位置ごとに合計が 1 ずつ増加し、距離は 6 になります。 

入力制約は単純です。文字列の長さは 1 ～ 100 です。これは、問題のサイズが非常に小さいことを意味するため、各文字を 1 つずつ明示的に比較するソリューションであっても、制限時間内で快適に実行できます。 2 つの短い文字列とカウンターを格納するだけでよいため、メモリも問題になりません。 主なエッジ ケースには、長さ 1 の最も短い文字列、同一の文字列、またはすべての文字が異なる文字列が含まれます。 たとえば、文字列`A`そして`A`の距離が生じるはずです`0`、 一方`A`そして`B`生産する`1`。 実装を不注意にすると、最初または最後の文字を誤って無視したり、文字列が同一である場合にカウントを間違えたりする可能性があります。 

## アプローチ

 ここでは、入力サイズが小さいため、総当たりアプローチが最適なアプローチでもあります。 文字列を並行して反復処理し、同じインデックスにある文字を比較します。 文字が異なるたびに、カウンターがインクリメントされます。 ループの終わりに、カウンターには合計ハミング距離が含まれます。 この方法は、ハミング距離の定義 (異なる位置の数) を直接実装しているため、正しいです。 

すべての文字を少なくとも 1 回調べて、一致するか異なるかを判断する必要があるため、この問題に対してより高速な漸近アルゴリズムはありません。 n ≤ 100 であるため、前処理や巧妙なビット操作によってさらに最適化を試みても、実行時間が改善されることはなく、解決策が複雑になるだけです。唯一の潜在的な落とし穴は、インデックス作成時の off-by-one エラーと、長さ 1 の文字列を正しく処理することを忘れることです。

 ## アルゴリズムのチュートリアル

 1. 2 つの入力文字列を読み取ります。 文字列の長さが等しいことが保証されているため、追加のチェックは必要ありません。 
2. カウンタ変数をゼロに初期化します。 これによりハミング距離が保持されます。 
3. 0 から n-1 までの文字列のインデックスを反復処理します。 インデックスごとに、両方の文字列の文字を比較します。 
4. 文字が異なる場合は、カウンタを 1 つインクリメントします。 これは、ハミング距離の定義を直接捉えています。 
5. 反復が完了したら、カウンターを出力します。 これは、不一致の位置の合計数を表します。 

機能する理由: このアルゴリズムは、カウンタがこれまでに確認された不一致文字の数と常に等しいという不変条件を維持します。 すべての位置を反復処理し、文字を 1 回だけチェックすることで、不一致の見逃しや二重カウントがないことを保証します。 すべてのインデックスが考慮されるため、最終的なカウンターは正確にハミング距離になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s1 = input().strip()
s2 = input().strip()

distance = 0
for c1, c2 in zip(s1, s2):
    if c1 != c2:
        distance += 1

print(distance)
```このソリューションは、高速入力を使用して 2 つの文字列を読み取ります。 の`strip()`この呼び出しは、誤った不一致を引き起こす可能性のある末尾の改行文字を削除します。 ループは使用します`zip`両方の文字列を同時に反復処理します。これは、インデックス カウンターを使用するよりもクリーンです。 不一致があるたびに、距離カウンターが増加します。 最後に、結果を出力します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s1 = input().strip()
    s2 = input().strip()
    distance = sum(1 for c1, c2 in zip(s1, s2) if c1 != c2)
    return str(distance)

# provided sample
assert run("CODECHEF\nTOPCODER\n") == "6", "sample 1"

# minimum-size input, identical
assert run("A\nA\n") == "0", "single char equal"

# minimum-size input, different
assert run("A\nB\n") == "1", "single char different"

# all characters equal
assert run("XYZXYZ\nXYZXYZ\n") == "0", "all equal"

# all characters different
assert run("AAAA\nBBBB\n") == "4", "all different"

# mixed case
assert run("ABCD\nACBD\n") == "2", "mixed differences"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | A\nA | 0 | 同一の単一文字列 |
 | A\nB | 1 | | 異なる単一文字列
 | XYZXYZ\nXYZXYZ | 0 | すべての文字が等しい長い文字列 |
 | ああああ\nBBBB | 4 | すべての文字が異なる長い文字列 |
 | ABCD\nACBD | 2 | 正しいカウントをチェックするための部分一致の文字列 |

 ## 特殊なケース

 最小の文字列の場合、次のようになります。`A`そして`B`、アルゴリズムが初期化されます`distance = 0`、唯一の文字を比較し、異なるため 1 回インクリメントして出力します。`1`。 次のような同一の文字列の場合`XYZXYZ`そして`XYZXYZ`、カウンターは決してインクリメントされず、`0`。 すべての文字が異なる文字列。例:`AAAA`そして`BBBB`、インデックスごとにカウンタをインクリメントし、文字列の長さを距離として生成します。 すべての場合において、反復不変式によって正確さが保証され、ソリューションは可能な入力の全範囲を処理します。
