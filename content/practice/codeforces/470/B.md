 ## 解決策
 ## 問題の理解

 数字のみで構成される文字列が与えられ、その文字列内のどこかに数字「666」が連続したシーケンスとして出現するかどうかを判断することが課題となります。 存在する場合、出力は「YES」、そうでない場合は「NO」になります。 これは数値計算の問題ではなくパターン検出の問題であるため、数値の実際のサイズは無関係です。 入力を純粋に文字のシーケンスとして扱います。 

文字列は 1 桁まで短くても、100 桁まで長くても構いません。 100 は現代の計算限界としては非常に小さい数であるため、高度に洗練されたアルゴリズムは必要ありません。 長さ 3 の考えられるすべての部分文字列を検査するアプローチでも、そのような部分文字列の最大数はおよそ 98 であるため、効率的に実行されます。 

明らかではないエッジ ケースには、3 桁より短い文字列が含まれます。この場合、部分文字列として「666」を持つことは不可能です。 たとえば、「66」を入力すると「NO」を出力する必要があります。 もう 1 つのエッジ ケースは、「666123」や「123666」など、「666」が文字列の最初または最後に表示される場合です。 文字列の途中だけをスキャンする不注意な実装では、これらの出現を見逃す可能性があります。 「6666」のように、3 桁より長い繰り返し数字を含む文字列でも、「YES」が返されます。これは、繰り返しシーケンス内に長さ 3 の連続した部分文字列が存在するためです。 

## アプローチ

 単純な総当たりアプローチでは、文字列内の長さ 3 のすべての部分文字列を反復処理し、それが「666」と一致するかどうかをチェックする必要があります。 このアプローチは、すべての候補を明示的に検査するため正しいですが、文字列が制約で許容されるよりもはるかに長い場合は非効率的になります。 最悪の場合のチェック回数は約`n-2`比較、ここで`n`文字列の長さです。 最大長が 100 の場合、これはわずか 98 チェックであり、これは簡単です。 

最適なアプローチは、Python の組み込みの部分文字列検索に依存します。 の`in`演算子は、文字列長に対して線形時間で文字列内に「666」が含まれているかどうかを確認できます。 これにより、手動によるインデックス作成が回避され、定型コードが削減され、すべてのエッジ ケースが正しく処理されます。 重要な洞察は、この問題は単純なパターン メンバーシップ チェックに帰着し、Python はそのために高度に最適化されたメカニズムを提供するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 (部分文字列検索) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取り、末尾の改行文字または空白文字を削除します。 これにより、数字自体のみを扱うことが保証されます。 
2. を使用して、文字列「666」が入力文字列のどこかに含まれているかどうかを確認します。`in`オペレーター。 これにより、単一パスで文字列が効率的にスキャンされます。 
3. 「666」が見つかった場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

機能する理由: このアルゴリズムは、特定のパターン「666」の文字列をスキャンしたという不変条件を維持します。 リニアスキャンで文字列全体をチェックするため、有効な部分文字列が欠落する可能性はありません。 正確さは、Python の部分文字列メンバーシップが正確であり、連続性を尊重しているという事実から生じており、これは問題の要件と一致しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

p = input().strip()

if "666" in p:
    print("YES")
else:
    print("NO")
```最初の行はインポートします`sys`そしてリバインドします`input`に`sys.stdin.readline`高速入力読み取り用。 偽陰性を避けるために、末尾の空白をすぐに削除します。 の`in`演算子は、文字列に対して線形スキャンを実行して、連続シーケンス「666」をチェックします。 最後に、部分文字列が見つかったかどうかに基づいて正しい応答を出力します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | の`in`演算子は、長さ 3 の部分文字列について、文字列の各位置を最大 1 回チェックします。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    p = input().strip()
    if "666" in p:
        print("YES")
    else:
        print("NO")
    return output.getvalue().strip()

# Provided samples
assert run("123098\n") == "NO", "sample 1"

# Custom cases
assert run("666\n") == "YES", "exact match"
assert run("66\n") == "NO", "too short"
assert run("6666\n") == "YES", "longer repeated sixes"
assert run("123666789\n") == "YES", "in the middle"
assert run("0000000\n") == "NO", "no sixes at all"
assert run("6\n") == "NO", "single character"
assert run("123456789012345678901234567890666\n") == "YES", "end of long string"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 「666」 | はい | 部分文字列 | の完全一致
 | 「66」 | いいえ | 文字列が短すぎて 666 を含めることができません。 
| "6666" | はい | 重複するオカレンスは処理されます。 
| "123666789" | はい | 中央の部分文字列 |
 | "0000000" | いいえ | シックスはまったくありません |

 ## 特殊なケース

 3 文字未満の文字列には、「66」などの「666」を含めることはできません。 アルゴリズムは「NO」を返します。`in`演算子は、長さ 3 の連続する部分文字列をすべてチェックしますが、何も見つかりません。 「6666」のように、3 より長い 6 が繰り返される場合でも、部分文字列「666」が複数の位置で始まるため、アルゴリズムは依然として「YES」を返します。 「666123」や「123666」などの先頭または末尾の部分文字列は、検索では位置をスキップせずに文字列全体をスキャンするため、正しく検出されます。
