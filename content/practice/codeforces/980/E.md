 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノード。 各ノードは地区を表し、道路網は任意の 2 つの地区間に 1 つの単純な経路が存在することを保証します。 各地区$i$以下に等しい値を提供します$2^i$したがって、番号が大きい地区は、番号が小さい地区よりも指数関数的に価値が高くなります。 

正確に削除する必要があります$k$地区。 削除後も、残りの地区は元の道路の下に接続されたグラフを形成する必要があります。つまり、削除されたノードを通過せずに、残りの 2 つのノード間を移動することができます。 有効な削除方法の中でも、$k$ノードの合計を最大化したいと考えています。$2^i$これは、高インデックス ノードの削除による影響を最小限に抑えることと同じです。 

指数関数的な重みが重要なのは、$2^i$より小さいインデックスの組み合わせを支配します。 これは、目的が本質的に辞書編集的であることを意味します。つまり、より大きい番号のノードを保持することが、より小さい番号のノードのコレクションよりも常に重要です。 

制約により許可されるのは、$n$まで$10^6$したがって、どの解も線形または線形に近い必要があります。$O(n \log n)$。 接続性を繰り返し再計算したり、完全なグラフ チェックを使用して削除をシミュレートしたりするような 2 次戦略は、非常に遅すぎます。 

微妙な点は、ノードのすべてのサブセットが許可されるわけではないということです。 ノードの集合の合計の重みが高くても、残りのグラフを切断してしまうと無効になります。 たとえば、中央の関節ノードを早期に削除すると、残りのノードが複数のコンポーネントに分割される可能性がありますが、これは禁止されています。 

もう 1 つの特殊なケースは、ツリーがスターである場合です。 ノード 1 が中心であり、それを削除するのが早すぎると、残りのすべてのノードが孤立してしまいます。 たとえば、次の場合$n = 4$そしてエッジは$1$に接続されています$2,3,4$、ノード 1 を削除すると、最初に 3 つの孤立したノードが残り、接続に違反します。 したがって、削除では値の順序だけでなく、構造上の制約も考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべてのサブセットが試行されます$n-k$、誘導された部分グラフが接続されているかどうかを確認し、重みの合計を計算します。 接続性チェックを無視しても、サブセットの数は$\binom{n}{k}$、それはたとえ小さくても実行不可能です$n$。 候補者ごとに 1 回の接続チェックにはすでにコストがかかります$O(n)$、このアプローチは指数関数的で使用できなくなります。 

重要な観察は、ツリー内の削除の下で接続がどのように維持されるかを理解することから得られます。 ツリーでは、ノードを削除すると、そのノードが現在の残りのセットのアーティキュレーション ポイントである場合にのみ、残りのグラフが切断されます。 ただし、ツリーでは、現在残っているグラフの葉でない限り、すべてのノードが潜在的な関節点になります。 

これは構造の単純化につながります。削除中も残りのグラフを接続したままにしたい場合は、現在残っているツリーの葉であるノードのみを削除できます。 内部ノードを削除すると、残りの頂点が少なくとも 2 つのコンポーネントに分割されます。 

その制限を受け入れると、問題は貪欲なプロセスになります。 葉を繰り返し取り除きます。 残りの合計を最大化する必要があり、インデックスが高いほど価値があるため、各ステップで利用可能な最小のリーフを削除することを優先する必要があります。 まず小さいラベルを削除すると、接続を維持しながら、大きいラベルができるだけ長く保持されます。 

このプロセスは、現在のリーフの優先キューを使用して動的に維持できます。 リーフを削除するたびに、その隣のリーフが新しいリーフになる可能性があり、それに応じて更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | ヒープで貪欲な葉の剪定 | 写真$O(n \log n)$| O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 残りのツリーのノードの現在の次数と、常に最小番号の取り外し可能なリーフを与える構造を維持します。 

1. 隣接リストからすべてのノードの次数を計算します。 これは、各ノードが現在アクティブな接続の数を表します。 
2. 次数が正確に 1 であるすべてのノードを含む最小ヒープを初期化します。これらは現在のリーフであり、接続を切断せずに安全に削除できるのはこれらのノードだけです。 
3. 以下のプロセスを正確に繰り返します$k$回。 各繰り返しは 1 つのノードの削除に対応します。 
4. ヒープから最小のインデックス付きノードを抽出します。 これにより、現在安全なすべての選択肢の中から最も価値の低いノードが確実に削除され、指数関数的な重みの損失を最小限に抑えることができます。 
5. このノードを削除済みとしてマークします。 これは、最終的な接続コンポーネントには表示されないことを意味します。 
6. 削除されたノードへのエッジが消えるため、このノードの一意の隣接ノードの次数を 1 つ減らします。 この近隣の次数が 1 になり、まだ削除されていない場合は、新しいリーフとなってヒープに挿入されます。 
7. まで続けます$k$ノードが削除されました。 

これらの手順の後、残りのノードは接続されたサブツリーを形成し、削除されたノードはプロセス中に記録されたものとまったく同じになります。 

正確性は、残りのグラフが常に接続されているという不変条件に基づいており、葉のみを削除するため、すべての削除でこの特性が維持されます。 さらに、すべての有効なリーフ削除シーケンスの中で、常に最小のラベル リーフを選択することで、より高いラベルが構造的に可能な限り長く保持されることが保証されます。これは、指数関数的な重み付けにより最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

n, k = map(int, input().split())
adj = [[] for _ in range(n + 1)]
deg = [0] * (n + 1)

for _ in range(n - 1):
    a, b = map(int, input().split())
    adj[a].append(b)
    adj[b].append(a)
    deg[a] += 1
    deg[b] += 1

removed = [False] * (n + 1)
heap = []

for i in range(1, n + 1):
    if deg[i] == 1:
        heapq.heappush(heap, i)

ans = []

for _ in range(k):
    while heap:
        v = heapq.heappop(heap)
        if not removed[v]:
            break

    removed[v] = True
    ans.append(v)

    for to in adj[v]:
        if not removed[to]:
            deg[to] -= 1
            if deg[to] == 1:
                heapq.heappush(heap, to)

ans.sort()
print(*ans)
```隣接リストはツリーを効率的に保存し、次数配列はノードが削除されたときに各ノードにまだアクティブなエッジがいくつあるかを追跡します。 ヒープにより、常に最小の有効なリーフが選択されるようになります。$O(\log n)$時間。 

実装の微妙な詳細は、ヒープ内の遅延削除です。 ノードは有効なリーフでなくなった後もヒープ内に残る可能性があるため、ポップするときにすでに削除されたノードをスキップします。 これにより、コストのかかるヒープのメンテナンスが回避されます。 

削除は必ずしも昇順ではなくプロセス順に生成されるため、最終的な答えを並べ替える必要があります。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
6 3
2 1
2 6
4 2
5 6
2 3
```最初、リーフは次数 1 のノード (ノード 1、3、4、5) です。ヒープは常に最小のリーフを選択します。 

| ステップ | ヒープ (概念的) | 選ばれた | 削除されました | 学位変更 |
 | --- | --- | --- | --- | --- |
 | 1 | 1,3,4,5 | 1 | {1} | ノード 2 次が減少します |
 | 2 | 3、4、5 | 3 | {1,3} | ノード 2 次が減少します |
 | 3 | 4,5 | 4 | {1,3,4} | 次数 1 の条件が満たされた場合、ノード 2 はリーフになります。 

処理後、削除されたノードは次のようになります。$1, 3, 4$、期待される出力と一致します。 

このトレースは、アルゴリズムが常に安全な境界ノードを削除し、自然にリーフになるまで内部構造に触れないことを示しています。 

2 番目の例として、チェーンを考えてみましょう。```
5 2
1 2
2 3
3 4
4 5
```葉は 1 と 5 から始まります。アルゴリズムは最初に 1 を削除し、次に 5 を削除します。パスの端点を削除すると短いパスが保持されるため、残りのグラフは接続されたままになります。 

| ステップ | 葉 | 選ばれた | 削除されました |
 | --- | --- | --- | --- |
 | 1 | 1,5 | 1 | {1} |
 | 2 | 2,5 | 2 | {1,2} |

 これは、プルーニングを繰り返した後にのみ内部ノードが削除可能になる様子を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, k = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    deg = [0] * (n + 1)

    for _ in range(n - 1):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)
        deg[a] += 1
        deg[b] += 1

    removed = [False] * (n + 1)
    heap = []

    for i in range(1, n + 1):
        if deg[i] == 1:
            heapq.heappush(heap, i)

    ans = []

    for _ in range(k):
        while heap:
            v = heapq.heappop(heap)
            if not removed[v]:
                break
        removed[v] = True
        ans.append(v)

        for to in adj[v]:
            if not removed[to]:
                deg[to] -= 1
                if deg[to] == 1:
                    heapq.heappush(heap, to)

    ans.sort()
    return " ".join(map(str, ans))

 ## 特殊なケース

 星型ツリーでは、最初は葉だけを取り外すことができます。 このアルゴリズムは削除をリーフ ノードに正しく制限するため、中心が途中で削除されることはありません。 たとえば、エッジの場合$1$に接続されています$2,3,4$、初期ヒープには以下が含まれます$2,3,4$、ノード 1 はリーフになるまでヒープに入ることはありません。リーフになることは、他のすべてが削除されない限り決して起こりません。 

長いチェーンでは、エンドポイントが削除された後にのみ内部ノードが徐々にリーフになります。 次数の更新により、構造的に有効な場合にのみノードがヒープに入ることが保証されるため、アルゴリズムは当然この遷移を尊重します。 

複数のリーフが存在する場合、常に最小のインデックスを選択すると、値の低いノードが最初に決定的に削除されます。これは指数関数的な重み付けと一致し、インデックスの低いノードが最適に保持されないようにします。
