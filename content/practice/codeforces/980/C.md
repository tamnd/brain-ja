 ## 問題の理解

 それぞれ 0 ～ 255 の整数のピクセル強度のシーケンスが与えられます。タスクは、最初に値の範囲全体を分割することによって、このシーケンスを「単純化」することです。$[0, 255]$連続したセグメントに分割します。 各セグメントの長さは最大でも$k$、範囲内のすべての整数は、正確に 1 つのセグメントに属している必要があります。 各セグメントに対して、キーと呼ばれる代表値を選択します。 その後、すべてのピクセル値が、それが属するセグメントのキーに置き換えられます。 

最終出力は、変換されたピクセル配列です。 範囲を分割してキーを選択するすべての有効な方法の中で、辞書順に最小の結果の配列が必要です。 

重要な相互作用は、変換が配列内の位置ではなく、値のセグメント化のみに依存することです。 どの値がどのキーにマップされるかを決定すると、その値のすべての出現が一貫して置き換えられます。 

値の領域では制約は小さいですが (可能な色は 256 色のみ)、配列の長さでは制約が大きくなります。$n \le 10^5$。 これは、どのソリューションでも 256 個の値すべてのマッピングを事前計算し、それを配列に対して線形時間で適用する必要があることを直ちに示唆しています。 

素朴なアプローチでは、すべてのセグメンテーションを試します。$[0,255]$。 各セグメントの長さは最大でも$k$、これは指数関数的な選択肢を伴う組み合わせ分割問題になります。 256 は小さいですが、考えられるすべてのセグメント境界を越えて分岐すると、可能性が爆発的に広がります。 

2 番目の単純なアイデアは、グローバルな相互作用を考慮せずに、変換された配列を最小化するパーティションを貪欲に選択することです。 ここで微妙な失敗が発生します。セグメント境界に関する早期の決定は将来のキーに影響を与え、局所的に最適な選択により後で辞書編集上の値が増加する可能性があります。 

典型的な失敗シナリオは、ブロック内の最小値ではないセグメント キーを選択した場合に発生します。 たとえば、グループ化すると、$[2,3,4]$鍵付き$3$、ただしキーを選択することもできました$2$の場合、2 が出現するたびに辞書順に悪化します。 たとえ後のセグメントが他の位置を改善したとしても、辞書編集上の順序は最初の異なるインデックスで決定されます。 

したがって、重要な問題は、辞書編集順序をグローバルに最適化するために、セグメントの境界と選択されたキーを調整する必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効なパーティションが列挙されます。$[0,255]$最大でも一定の長さのセグメントに分割$k$。 各パーティションについて、各セグメント内のキーの可能なすべての選択を試し、256 個の値すべてに対する結果のマッピングを計算し、それを配列に適用して、結果を辞書編集的に比較します。 セグメンテーションだけを考慮したとしても、長さ 256 の配列を最大ブロック サイズで切り出す方法は数多くあります。$k$256 では指数関数的に増加するため、これは実行不可能になります。 

重要な点は、値のドメインが固定されており小さいため、配列内の位置ではなく、各値のマッピングについて考える必要があるということです。$v \in [0,255]$最終代表者に。 このマッピングが修正されると、出力の構築は簡単になります。 

ここで、最終的な配列の辞書編集的な順序がどのように動作するかを考えてみましょう。 配列内の異なる最初の位置は、異なるマッピング結果を取得する最小ピクセル値に完全に依存します。 これは、より小さい値をできるだけ早く、有利に処理する必要があることを示唆しています。 

どのセグメント内でも、より大きなキーを選択すると、同じセグメント内でより小さなキーを選択した場合と比較して、値が悪化するか同等になるだけです。 したがって、固定セグメントの場合、最適な選択は常に最小値になります。 

これにより、問題はセグメント境界のみを選択することになります。 各セグメント$[l, r]$（と$r - l + 1 \le k$) その中のすべての値を次のようにマッピングします$\min(l, r)$は正しくありません。 代わりに、次のようにマッピングされます。$\min$概念的にはそのセグメントに存在する値の数ですが、すべての整数が範囲内に存在するため、最良の代表値は単純に$l$。 したがって、各セグメントは、すべての値がその左端にマップされるブロックになります。 

次に、範囲をどこでカットするかを選択する必要があります。 貪欲な戦略は、辞書編集上の順序を最も早く改善する、常に 0 から始まる可能な最大のセグメントを取得することです。 しかし、重要な単純化はさらに強力です。各値のマッピングを昇順に決定し、常にセグメントを可能な限りサイズまで拡張することができます。$k$なぜなら、カットを遅らせることは、より大きな値がより小さな代表をより早く共有することを強制するだけであり、これは常に辞書編集的に最適であるためです。 

これは単純な貪欲につながります。0 から 255 までの値を調べ、各値を現在のセグメントに割り当て、セグメントがサイズに達するたびに割り当てます。$k$、新しいものを始めます。 各セグメントのキーはその最初の値です。 

これにより、256 個すべての値の固定マッピングが生成され、それを配列に適用します。

 ## アルゴリズムのチュートリアル

 それぞれの値からマッピングを構築します$0 \ldots 255$最終的な圧縮値に変換します。 

1. 空のマッピング配列を初期化します。`mp`サイズは 256 です。変数を設定します`start = 0`、現在のセグメントの始まりを示します。 
2. 値を反復処理する`v`0から255まで。 
3.割り当て`mp[v] = start`、現在のセグメント内のすべての値がセグメントの開始点にマップされることを意味します。 
4. 当社が割り当てた場合$k$最後のセグメントの開始以降の値を移動します`start = v + 1`、新しいセグメントが始まります。 

これにより、各セグメントのサイズが最大でも確実になります。$k$、常に可能な限り早い代表者を選択します。 
5. すべての値を処理した後、考えられるすべてのピクセル強度の完全なマッピングが得られます。 
6. 各値を置き換えて入力配列を変換します`p[i]`と`mp[p[i]]`。 

これが機能する理由は、値が で始まるセグメントに割り当てられるからです。`start`、それより大きな代表値を割り当てると、それが出現するすべての位置で最終配列の値が増加するだけです。 辞書編集上の順序は左から右に決定されるため、初期の値を大きくしても後で補正することはできません。 貪欲なセグメンテーションにより、以前にマップされた値が増加する可能性がある方法で境界を遅らせることがないことが保証されます。 

不変条件は、各セグメントが常に可能な限り最小の代表値を使用し、サイズを超えることがないため、処理されたすべての値のプレフィックスについて、マッピングがそれらの値のみを含むすべての配列に対してすでに最適であるということです。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    mp = [0] * 256
    
    start = 0
    cnt = 0
    
    for v in range(256):
        mp[v] = start
        cnt += 1
        if cnt == k:
            start = v + 1
            cnt = 0
    
    res = [str(mp[x]) for x in arr]
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```コードはまず、256 個の可能なピクセル値の固定領域にマッピングを構築します。 変数`start`現在のセグメントの左側の境界を追跡します。 割り当てるたびに`k`値をセグメントに設定したら、リセットします`start`新しいブロックを開始します。 

変換ステップは直接的です。各ピクセルは、一定時間内に事前計算されたマッピング値に置き換えられます。 

微妙な点は、セグメント範囲を明示的に保存する必要がないことです。 ペア`(start, cnt)`現在のセグメントを暗黙的に定義します。 また、部分セグメントは許可され、自動的に処理されるため、完全なセグメントが正確に 255 で終了することを心配する必要はありません。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = 1$。 アルゴリズムにより、すべての値が新しいセグメントを直ちに開始するよう強制されるため、`mp[v] = v`。 これにより ID マッピングが生成されます。これは、2 つの異なる値がグループを共有できないため、正しいものになります。 

もう一つのケースは、$k = 256$、範囲全体が 1 つのセグメントになります。 ここでは、セグメントは 0 から始まりリセットされないため、すべての値が 0 にマップされます。 このアルゴリズムは、完全に平坦化された配列を正しく生成します。 

より微妙なケースは、入力の値がまばらである場合、たとえば 200 ～ 210 のような大きな値のみである場合です。マッピングは依然として 0 ～ 255 の全範囲にわたってグローバルに決定されるため、これらの値は予想とは異なるセグメントに分類される可能性があります。 問題定義で必要とされる入力分布とは独立してセグメンテーションが固定されるため、アルゴリズムは引き続き機能します。
