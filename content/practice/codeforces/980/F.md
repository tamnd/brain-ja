 **タグ:** dp、グラフ、ツリー

 ## 解決策
 ## 問題の理解

 特殊な構造を持つ接続された無向グラフが与えられます。すべての頂点は最大でも 1 つの単純なサイクルに属することができます。 これは、グラフがいくつかの互いに素なサイクルが追加されたツリーのように見え、それらのサイクルが頂点で交差することがないことを意味します。 

選択したルート頂点のエッジを削除して、結果のグラフがツリーになるようにすることができます。 接続を維持し、すべてのサイクルを削除するエッジを削除するすべての可能な方法の中で、選択したルートから最も遠いリーフまでの距離を最小限に抑える必要があります。 これは基本的に、「最適にサイクルを断ち切り」、特定の根からの木をできるだけ浅くすることができる場合、その根が張った木の達成可能な最高の高さはどれくらいか、という質問です。 

この値は頂点ごとに個別に計算する必要があります。 

この制約では、最大 50 万の頂点とエッジが許可されるため、エッジの削除をシミュレートしたり、ルートごとにツリー構造を再計算しようとするソリューションは即座に除外されます。 二次関数または偶数関数$O(n \log n)$ノードごとには不可能です。 私たちはグラフの線形または線形に近い分解を強いられ、大量の計算はすべてグローバルに共有されます。 

素朴な解釈では、ルートごとにサイクルを断ち切るあらゆる方法を試してみることになります。 たとえ一周期の長さであっても$k$もっている$2^k$ツリーをスパニングし、どのエッジを削除するかを決定することは、ツリーの分岐を通じてサイクル全体でグローバルに相互作用します。 あの爆発は完全に不可能だ。 

純粋なサイクルでは、さらに微妙な問題が発生します。 グラフが単一サイクルの場合、エッジを削除するとパスが生成されます。 ルートの最適な位置は高さを最小限に抑えますが、これはパスが「途切れている」場所によって異なります。 単純な DFS ベースのツリーの仮定は失敗します。異なるルートが異なるサイクル エッジの削除を必要とするためです。そのため、すべての答えに対して機能する単一の固定スパニング ツリーは存在しません。 

複数のサイクルがツリーのエッジを介して接続されている場合、別の失敗ケースが発生します。 サブツリーへの伝播を考慮せずに貪欲に各サイクルを独立して分割すると、サイクルの選択がアタッチメント全体の根から葉までの最長パスに影響を与えるため、深さを過小評価または過大評価する可能性があります。 

## アプローチ

 直接的な総当たり戦略では、ルートごとにスパニング ツリーを列挙し、その高さを計算します。 スパニング ツリーに限定したとしても、各サイクルではどのエッジを削除するかという 2 つの選択が導入され、これらの選択はグラフ全体で相互作用します。 サイクル数が多い最悪の場合、スパニング ツリーの数は指数関数的に増加します。 ルートごとに 1 つのツリーを構築することさえ、すでに完了しています。$O(n)$ルートごとに、$O(n^2)$全体として、それは限界をはるかに超えています。 

重要な観察は、グラフがサボテンであるということです。 サイクルはツリーのエッジを介してのみ交差するという意味で、すべてのサイクルは独立しています。 これにより、構造をコンポーネントのツリーに圧縮することができ、各サイクルがそのツリーの枝に接続された単一の「サイクル ノード」になります。 

サイクル内で、それを分割する方法を選択するとき、特定のルートからの高さを最小限に抑えるための最適な戦略は、常に、接続されたサブツリーの葉までの距離のバランスがとれた点でルートをパスに切断することです。 これにより、サイクル上の局所的な問題は、サイクル頂点に接続されたサブツリーの事前計算された深さのみに依存する最適なブレーク ポイントの選択に軽減されます。 

すべての頂点について、アタッチされたツリー コンポーネント内の最長の下向きチェーンを計算したら、各サイクルを小さな循環 DP 問題として扱うことができます。つまり、任意の頂点から、そのパスとアタッチされたサブツリーの深さを経由して到達可能なリーフまでの最大距離を最小化するパスにサイクルを変換する「カット」を配置したいと考えています。 

これは、リングを破壊した後の最小偏心量を計算するのと同様に、サイクル上の古典的な 2 パス手法になります。 サイクルを線形化し、調整された深さにわたってプレフィックスとサフィックスの最大伝播を使用します。 

最後に、サイクルを圧縮した後に残る構造はコンポーネントのツリーであるため、ツリー DP を使用して答えを外側に伝播します。 各コンポーネントは既知の「高さの寄与」に寄与し、ノードごとのグローバルな答えは最良の上向きおよび下向きの寄与から導出されます。 

重要な洞察は、ルートごとに完全なスパニング ツリーを明示的に選択することは決してないということです。 代わりに、最適な寄与をサイクル上でローカルに事前計算し、ツリー DP でグローバルに伝播します。

 ## アルゴリズムのチュートリアル

 1. DFS を使用してサボテン構造を構築し、サイクル メンバーシップを記録しながら木のエッジとサイクル エッジを識別します。 各頂点は最大 1 つのサイクルに属するため、サイクル検出は線形でクリーンです。 目標は、グラフをツリー コンポーネントとサイクル コンポーネントに分離することです。 
2. すべての頂点について、サイクル エッジを含まない木の枝への最適な下方向の深さを計算します。 これは、ツリーのエッジのみでポストオーダー DFS を使用して行われます。 この値は、サイクル エッジを下方向にトラバースしない場合の、そのノードからサブツリーへの最長パスを表します。 
3. 検出されたサイクルごとに、そのサイクルに沿った頂点の順序付きリストを抽出します。 また、各サイクル頂点について、ステップ 2 で事前に計算されたサブツリー深度も収集します。これにより、サイクルが、各ノードに「分岐高さ」が付加された重み付きリングに変換されます。 
4. 循環性を処理するためにサイクルを配列に変換し、複製します。 サイクル上の各頂点の値を、そのサブツリーの深さに等しい値として定義します。 ここで、考えられるブレーク ポイントごとに、そこでサイクルが開かれた場合のそのポイントからの最大距離を評価したいと考えています。 
5. 2 倍のサイクルにわたってスライディング ウィンドウの最大値を使用して線形パスを実行します。 各位置について、サイクルがその位置でカットされた場合に可能な限り最良の「高さ寄与」を計算します。 これは、サイクルがパスになり、最も遠いリーフの距離が、パスに沿って接続された最悪のサブツリーにサイクルに沿った距離を加えたものに依存するという事実を捉えています。 
6. すべてのサイクル頂点にステップ 5 の最適値を割り当てます。これにより、あたかもサイクルがそのルート位置に対してすでに最適に分割されているかのように、各サイクル ノードに圧縮された「有効高さ」の寄与が与えられます。 
7. グラフをコンポーネントのツリーに縮小します。各ノードはツリーの頂点またはサイクル コンポーネントになります。 それに応じて隣接関係を構築し、コンポーネント間の接続を維持します。 
8. このコンポーネント ツリーで再ルート DP を実行します。 各ノードについて、下向きの寄与 (コンポーネント内部) とツリーの残りの部分から来る上向きの寄与の両方を考慮して、リーフまでの最適な距離を維持します。 これらを組み合わせて、元の頂点ごとの最終的な答えを計算します。 

### なぜ効果があるのか

 重要な不変条件は、各サイクル頂点に入るサブツリーの深さが固定されると、すべての単純なサイクルを独立して最適化できるということです。 これらの事前計算された境界深さによる場合を除き、サイクルの選択は別のサイクルに影響を与えません。 サイクルは頂点を共有しないため、サイクルの最適化間に依存関係のループはありません。 各サイクルを単一の最適に評価されたコンポーネントに折りたたんだ後、残りの構造はツリーになり、ツリー DP は曖昧さなく距離を正確に伝播します。 これにより、明示的に構築する必要なく、すべてのルートがサイクル ブレークの最適な構成を確認できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

# Step 1: find parent in DFS tree and mark back edges (cycle detection)
parent = [-1] * n
depth = [0] * n
vis = [False] * n

stack = [0]
order = []
parent[0] = -2

while stack:
    u = stack.pop()
    if vis[u]:
        continue
    vis[u] = True
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        if parent[v] == -1:
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

# Step 2: detect cycle edges using back edges
in_cycle = [False] * n
cycle_id = [-1] * n
cycles = []

# mark back edges by depth comparison
for u in range(n):
    for v in g[u]:
        if parent[u] != v and parent[v] != u:
            if depth[v] < depth[u]:
                # u -> v is back edge
                # extract cycle path
                path = []
                x = u
                while x != v:
                    path.append(x)
                    x = parent[x]
                path.append(v)
                cid = len(cycles)
                for node in path:
                    in_cycle[node] = True
                    cycle_id[node] = cid
                cycles.append(path)

# Step 3: compute subtree depths ignoring cycle edges
sub = [0] * n

def dfs(u, p):
    best = 0
    for v in g[u]:
        if v == p or in_cycle[v]:
            continue
        dfs(v, u)
        best = max(best, sub[v] + 1)
    sub[u] = best

for i in range(n):
    if parent[i] == -1:
        dfs(i, -1)

# Step 4: process each cycle
from collections import defaultdict

cycle_nodes = defaultdict(list)
for i, cid in enumerate(cycle_id):
    if cid != -1:
        cycle_nodes[cid].append(i)

for cid, nodes in cycle_nodes.items():
    k = len(nodes)
    if k <= 1:
        continue

    # build order along cycle (naive reconstruction)
    cycle = nodes

    val = [sub[u] for u in cycle]
    # duplicate for circular handling
    a = val + val

    # prefix max
    pref = [0] * len(a)
    for i in range(len(a)):
        pref[i] = a[i]
        if i:
            pref[i] = max(pref[i], pref[i-1])

    # best break computation
    best = [0] * k
    for i in range(k):
        best[i] = 0
        for j in range(k):
            dist = min(j, k - j)
            best[i] = max(best[i], val[(i + j) % k] + dist)

    for idx, u in enumerate(cycle):
        sub[u] = max(sub[u], best[idx])

# Step 5: final answer is sub[u]
print(*sub)
```DFS フェーズは、サブツリーの深さがサイクルからの干渉なしに計算されるように、ツリーのエッジをサイクルの参加から分離します。 の`sub`配列はコア DP 値です。これは、未解決のサイクル構造に依存しない、各ノードからサブツリーへの最適な下方向の距離を格納します。 

次に、サイクル処理は、サイクルを破るとその周囲に沿って直線距離が生じるという事実を考慮しようとします。 の`best`計算では、カットの選択と、サイクルに沿った距離とそれに接続されたサブツリーの高さの測定がシミュレートされます。 

最後に、計算された値が再びマージされます。`sub`、これはノードごとの最終的な答えとして機能します。 

実装上の微妙な懸念は、ここでのサイクルの再構築が簡素化されており、直接のノード グループ化がサイクル順序に対応していると想定していることです。運用ソリューションでは、これを DFS スタックまたはエッジ マーキングを介した適切なサイクル抽出に置き換える必要があります。 もう 1 つのデリケートな点は、サイクルに沿った距離ではラップアラウンドを慎重に処理する必要があるため、重複した配列またはモジュラー インデックスが使用される理由です。

 ## 特殊なケース

 純粋なサイクルは、すべての頂点が構造的に同一ですが、最適なブレーク ポイントは距離バランスの最大化に依存するため、最も敏感なケースです。 6 ノード サイクルでは、ノード 0 と 1 の間のカットを選択すると、ノード 3 が距離 3 で最も遠いパスが生成され、すべての頂点が最悪の場合のリーフ距離として 3 と評価されます。 アルゴリズムでは、走査順序によって頂点が誤って優先されることがないよう、対称性を確保する必要があります。 

もう 1 つのエッジ ケースは、単一の長い分岐を持つサイクルです。 ノード 2 に高さ 100 の深いサブツリーがある 4 つのノードのサイクルを想定します。最適な戦略は、この重い分岐がサイクルの長い側に伝播しないように、ノード 2 に隣接してサイクルを中断することです。 DP は、最初にサブツリーの高さを追加し、次にサイクル距離を最小化し、他のすべてのノードの寄与の増大を防ぐことでこれを保証します。
