 ## 解決策
 ## 問題の理解

 非常に小さなグリッドのような形をした都市が与えられています。正確に 4 つの行と奇数の列があります。 重要なのは 2 つの位置のペアです。最初のジャーニーは左上隅から開始して右下隅に到達したいのに対し、2 番目のジャーニーは左下隅から開始して右上隅に到達したいと考えています。 移動は 4 方向のみ、ブロックされていないセルを通過する場合のみ許可されます。 

正確に配置するように求められます$k$グリッド セル上にホテルを配置します。グリッドの外側の境界線にはホテルを配置できないという制限があります。 境界線は、最初と最後の行、および最初と最後の列で構成されます。 これらのブロックされたセルを配置した後、2 対のコーナー間の最短パスを検討します。 目標は、最初の行程の最短パスの数が 2 番目の行程の最短パスの数と等しくなるようにすることです。 

入力サイズは非常に小さいため、$n \le 99$なので、グリッド サイズが線形であればどのような構成でも十分です。 制約$k \le 2(n-2)$は任意ではありません。中央の 2 つの行の内部セルの数と正確に一致します。 

対称性を維持せずにセルを貪欲にブロックしようとすると、微妙な失敗例が発生します。 たとえば、単一のブロッキング セルを配置すると、すべての対称性が即座に破られます。 4 × 5 グリッド上:```
.....
..#..
.....
.....
```障害物は進行方向の 1 方向にのみ影響するため、1 番目と 2 番目の経路システムは等価ではなくなります。 このような非対称な配置は通常、一方のパス数を変更しますが、もう一方のパス数は変更しません。これは要件に違反します。 

もう 1 つのエッジケースは次のような場合です$k$大きいです。 配置が注意深く構成されていない場合、一方の方向のすべてのパスを誤ってブロックし、他方のパスは接続されたままにしてしまう可能性があります。 

## アプローチ

 強引なアイデアは、あらゆる配置方法を試すことです。$k$許可された内部セル内のホテルを検索し、動的プログラミングまたは BFS ベースのカウントを使用して両方のペアの最短パスの数を計算します。 内部セルの数は$2(n-2)$したがって、構成の数は次のようになります。$\binom{2(n-2)}{k}$。 たとえ$n = 99$、これは天文学的に大きくなり、各構成でパス数を再計算する必要があり、これでは非常に時間がかかります。 

重要な観察は、実際にはパス数を計算する必要がまったくないということです。 両方のパス数が等しいことを確認するだけで済みます。 グリッドの構造は自然な対称性を示唆しています。グリッドを垂直に反映すると (行を入れ替えると)$i$列あり$5-i$)、2 つの旅程の開始点と終了点も交換されます。 これは、一方向のすべての有効なパスがもう一方の方向のミラーリングされたパスに対応するため、この反射の下で対称的な構成では 2 つのパス数が強制的に同一になることを意味します。 

この対称性を維持するには、ブロックされたすべてのセルを、垂直方向にミラーリングされた対応するセルとペアにする必要があります。 4 行グリッドでは、行 2 は行 3 をミラーリングしますが、行 1 と行 4 は境界線であり、ブロックを含めることはできません。 したがって、すべての有効な配置は、列を選択し、ブロックを同時に配置することで構成されます。$(2, c)$そして$(3, c)$。 

これにより、問題はただちに選択の問題に軽減されます。$k/2$列のうち、$n-2$利用可能な内部柱。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\binom{2(n-2)}{k} \cdot n)$|$O(n^2)$| 遅すぎる |
 | 対称構造 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず次のことを確認します。$k$は均等です。 そうでない場合は、すべての有効な配置を中央の行にミラーリングする必要があるため、対称的な配置は不可能になります。つまり、セルはペアになることになります。 もし$k$が奇数の場合は、直ちに NO を出力します。 
2. ドットで埋められた最初は空のグリッドを作成します。 
3. 境界線が禁止されており、対称性によりすべてのアクションがそこに強制されるため、中央の 2 行、行 2 と行 3 にのみ焦点を当てます。 
4. 内部列を 2 から 2 まで繰り返します。$n-1$。 各列について、両方の列にホテルを配置します。$(2, c)$そして$(3, c)$まさにそれまで$k/2$柱が使われてきました。 これにより正確に保証されます$k$セルが全体的にブロックされます。 
5. YES に続いてグリッドを出力します。 

正確さは、行 2 と行 3 の間で厳密なミラー対称性を維持することで得られます。この対称性により、一方向のすべての最短パスが反対方向に一意のミラーリングされた対応物を持つことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

if k % 2 == 1:
    print("NO")
    sys.exit()

grid = [['.'] * n for _ in range(4)]

need = k // 2
for c in range(1, n - 1):
    if need == 0:
        break
    grid[1][c] = '#'
    grid[2][c] = '#'
    need -= 1

print("YES")
for row in grid:
    print("".join(row))
```実装は構築の直後に行われます。 グリッドには 0 からインデックスが付けられるため、ステートメントの行 2 と行 3 はコードのインデックス 1 と 2 に対応します。 1 から 1 までの列のみを使用します$n-2$、必要な境界制約を維持します。 選択された各列にはブロックされたセルが 2 つだけ含まれており、合計数が一致することが保証されます。$k$。 

よくある間違いは、グリッド全体にブロックを任意に配置しようとしたり、中央の行の 1 つだけを使用しようとしたりすることです。 それは対称性の議論を即座に破壊し、正しさを無効にします。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$k = 0$。 このアルゴリズムは空のグリッドを生成しますが、これは自明のことながら対称であるため、両方のパス数は変化せず、等しいままになります。 

もう一つのケースは次のような場合です。$k = 2(n-2)$。 ここでは、行 2 と行 3 のすべての内部セルが塗りつぶされます。 すべての列が対称的に埋められ、グリッドが完全に鏡像化されたままであるため、この構造は依然として機能します。 

3番目のケースは奇妙です$k$、 例えば：```
n = 7, k = 3
```アルゴリズムは即座に拒否します。 これは正しいです。対称的なセルのペアではブロックされたセルの総数が奇数になる可能性はなく、そのため、いかなる試みも必然的に必要なパス数の等価性を破ることになるからです。
