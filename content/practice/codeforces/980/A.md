 ## 問題の理解

 2 種類の文字で構成される円形の配置が与えられています。`o`およびで表されるリンク`-`。 構造がネックレスであるため、文字列は循環していると見なされます。これは、最後の文字が最初の文字に隣接していることを意味します。 

許可された操作では、文字のマルチセットは変更されません。 任意の文字を選択し、円上の他の場所に再挿入できます。 つまり、ネックレスを任意に並べ替えることはできますが、存在するパールやリンクの数は変更できません。 

目標は、円を一周するときに、連続する真珠の各ペア間のリンクの数がすべてのペアで同じになるようにネックレスを再配置できるかどうかを判断することです。 

あれば$k$真珠を配置し、最終的な配置で円を次のように分割します。$k$連続するパールの間にアークがあり、各アークには同じ数のパールが含まれている必要があります。`-`文字。 

制約は小さいですが、$|s| \le 100$したがって、構成を複数回スキャンまたはシミュレートするソリューションでも許容されます。 ただし、重要なのは、再配置をシミュレートするのではなく、問題を単純な算術実行可能条件に還元することです。 

いくつかの特殊なケースが重要です。 

真珠が存在しない場合、「隣接する真珠」がないため、この条件はまったく意味がありません。 少なくとも 1 つを仮定する推論`o`ここで失敗するだろう。 

真珠がちょうど 1 つ存在する場合、隣接する真珠のペアも存在しないため、どのような配置でも条件は自明に満たされます。 

複数のパールがあるがリンクがない場合、すべてのギャップにはリンクが含まれていない必要があるため、これは有効です。 

微妙なケースは、リンクは存在するが、パールのギャップ全体に均等に分散できない場合、特にパールの数がリンクに比べて少ない場合です。 

## アプローチ

 一見すると、この問題はサイクル上の並べ替えパズルのように見えます。 強引なアイデアは、パールとリンクの可能なすべての円順列をシミュレートすること、または同様に、パール間のギャップにリンクを分配するためのあらゆる方法を試みることです。 

これはすぐに実行不可能になります。 円上のパールの配置だけを考慮した場合でも、リンクの合計数に応じてギャップ サイズを選択する方法の数は組み合わせにより増加します。 のために$k$真珠と$m$リンク、基本的には配布しています$m$同一のオブジェクトを$k$ラベル付きのビン、これはすでに提供されています$\binom{m + k - 1}{k - 1}$可能性。 制約が小さい場合でも、この構造を強引に実行する必要はありません。 

重要な観察は、再配置が完全に自由になった後、重要な唯一の不変条件は、均一性を求める場合、連続するパール間にいくつのリンクが存在する必要があるかということです。 あれば$k$パール、サークルは分割されています$k$ギャップ。 すべてのリンクはこれらのギャップの 1 つに正確に属している必要があるため、配置が有効であれば、各ギャップに正確に含まれている必要があります。$m / k$リンク、ここで$m$の合計数です`-`。 

これにより、問題全体が可算性のチェックに帰着します。 もし$k = 0$、または$m$で割り切れない$k$、それが不可能であることはすぐにわかります。 それ以外の場合は、パールを円の周りに均等に配置し、リンクを各セグメントに均等に分配できるため、有効な構造が常に存在します。 

これにより、問題は構造的な再配置から単純な算術条件に変換されます。

 ## アルゴリズムのチュートリアル

 1. 真珠の数を数えます`k`とリンク`m`文字列の中で。 操作では任意の再配置が可能であるため、これにより、最終的な配置に関連するすべての情報が取得されます。 
2. もし`k == 0`、すぐに「YES」を返します。 真珠が存在しない場合、隣接する真珠のペアは存在しないため、条件は空虚に満たされます。 
3. もし`k == 1`、「YES」を返します。 パールは 1 つだけなので、制約を課す連続したパールのペアは存在しません。 
4. かどうかを確認します。`m % k == 0`。 そうでない場合は、すべてのパール ギャップにリンクを均等に分散することは不可能であるため、「いいえ」を返します。 
5. 割り切れる場合は、正確に代入できるため、「YES」を返します。`m / k`それぞれへのリンク`k`円の周りの隙間。 

### なぜ効果があるのか

 再配置の自由度は、最終構成における唯一の意味のある構造が、連続するパール間のセグメントへのリンクの分割であることを意味します。 各リンクは 1 つのセグメントにのみ属している必要があり、各セグメントには同じ数のリンクが含まれている必要があります。 これにより、すべての有効な構成が強制的に均等な分割に対応します。`m`の中へ`k`部品。 配置順序を制限する制約はこれ以上ないため、割り算は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

k = s.count('o')
m = s.count('-')

if k <= 1:
    print("YES")
else:
    if m % k == 0:
        print("YES")
    else:
        print("NO")
```実装では、文字列の 1 回のパスで両方の文字を直接カウントします。 再配置が許可されると、問題ではすべての位置制約が破棄されるため、これで十分です。 

唯一の微妙な部分は、次の小さな値の処理です。`k`。 いつ`k`が 0 または 1 の場合、「隣接するパール間」という概念が制約を課さないため、除算ロジックは完全にスキップされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    k = s.count('o')
    m = s.count('-')
    if k <= 1:
        return "YES"
    return "YES" if m % k == 0 else "NO"

# provided sample
assert run("-o-o--") == "YES"

# single pearl
assert run("o") == "YES"

# no pearls
assert run("---") == "YES"

# impossible split
assert run("o--o") == "NO"

# already balanced
assert run("o-o-o-") == "YES"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`o`| はい | シングルパールエッジケース |
 |`---`| はい | パールエッジケースなし |
 |`o--o`| いいえ | 分割できないリンク |
 |`o-o-o-`| はい | 一様分布の場合 |
