 ## 解決策
 ## 問題の理解

 各テストケースにはルート付きツリーが与えられます。 すべてのノードにはルートを除く親が 1 つだけあり、親ポインターが構造全体を定義します。 このツリーから、ノードの空ではないすべてのサブセットを考慮します。 各サブセットについて、その最も低い共通祖先、つまりサブセット内のすべてのノードの祖先である最も深いノードを計算します。 タスクは、すべてのサブセットにわたるこれらの LCA のインデックスをモジュロで合計することです。$10^9 + 7$。 

これを解釈する直接的な方法は、ツリー内のノードのグループを選択し、単一の共有祖先で出会うまでそれらを上方向に「圧縮」することを想像することです。 その集合場所が、そのラベルを最終的な合計額に反映させます。 課題は、サブセットの数が指数関数的であるため、それらを明示的に列挙することが不可能であることです。 

制約は以下を意味します$10^5$すべてのテスト ケースにわたるノードなので、おおよそより悪い解決策はありません$O(n \log n)$テストケースごとに生き残ることはできません。 アン$O(2^n)$あるいは$O(n^2)$テストケースごとのアプローチは直ちに実行不可能です。 

いくつかの特殊なケースは概念的に重要です。 すべてのノードがルートに接続されたリーフである場合、ほとんどのサブセットは LCA としてルートを持つことになるため、答えはルートに集中します。 ツリーがチェーンの場合、LCA はセグメントに沿って最小値のように動作し、より深いノードが多くのサブセットを支配します。 ツリーに同一の親構造が繰り返されている場合、複数のサブセットが非明白な方法で同じ LCA に崩壊します。これはまさに単純なカウントが失敗する場所です。 

## アプローチ

 ブルートフォース手法は原理的には簡単です。 すべてを繰り返します$2^n - 1$空ではないサブセットの場合、標準的なバイナリ リフティング LCA 構造を使用してその LCA を計算します。$O(\log n)$、結果を蓄積します。 これは定義に直接従っているため、正しいです。 問題は実行時です。$n = 20$、これはすでに約 100 万のサブセットであり、$n = 100000$それはまったく不可能です。 操作数は指数関数的に増加し、他のすべてを支配します。 

重要な点は、実際にはサブセットを処理する必要がないということです。 サブセットの観点から考える代わりに、ノードごとに視点を逆転させます。$v$、LCA が次と正確に等しいサブセットがいくつあるかを数えます。$v$。 この数を効率的に計算できれば、答えはノード全体の加重合計になります。 

サブセットの LCA は次のとおりです$v$選択されたすべてのノードがサブツリー内にある場合に限り、$v$、少なくとも 1 つの選択されたノードが、LCA をより高く押し上げる厳密な子孫サブツリーに含まれていません。 これを処理するきれいな方法は、ノードをリーフから上に向かって処理し、サブセットがどのようにして上位の祖先に「逃げ出す」かのカウントを維持することです。 これは自然に、各ノードがその子からの貢献を集約するツリー DP につながり、LCA の構造はサブツリーに対する包含-排他によって解決されます。 

これを言い換えると、この問題は標準的なツリー集約の問題になります。すべてのノードは、そのノードに最上位の共通祖先として「固定」されているサブセットの数に基づいて寄与します。 これは、DFS とサブツリー サイズの組み合わせカウントを使用して線形時間で計算できます。

 ## アルゴリズムのチュートリアル

 指定された親ポインターを使用してツリーをルート化し、一意の自己親ノードをルートとして扱います。 次に、サブツリーのサイズを計算し、DFS ベースの DP を使用して、各ノードと等しい LCA を持つサブセットの数を数えます。 

1. まず、親配列からツリーの隣接リストを作成します。 これにより、ノードをルートとする無向構造が得られます。$p_v = v$。 
2. DFS を実行して、すべてのサブツリーのサイズを計算します。 サブツリー サイズは、そのノードをルートとするコンポーネント内のノード (それ自体を含む) の数です。 この値は、サブツリーに完全に含まれるサブセットの数を決定するため、非常に重要です。 
3. 各ノードについて$v$、そのサブツリーに完全に含まれるサブセットの総数を考慮します。 これは$2^{\text{subtree}[v]} - 1$、そのサブツリーの空でないサブセットはすべて有効であるためです。 
4. 次に、LCA が正確に一致するサブセットを分離する必要があります。$v$、誰かの子孫ではありません。 それぞれの子どもたちにとって$c$の$v$、完全に含まれるサブセット$c$のサブツリーには、そのサブツリー内に LCA が含まれるため、に帰属する場合は除外する必要があります。$v$。 
5. これを形式化するために、サブツリー構造の最上位の祖先がまさにそのノードである有効なサブセットの数を表す DP 値をノードごとに計算します。 これはボトムアップで行われます。最初に子が寄与を計算し、次に親がさまざまな子ブランチからの可能性を掛け合わせてそれらを結合しますが、少なくとも 1 つのブランチが LCA を親に引き上げることを保証します。 
6. 最後に、各ノード$v$貢献する$v \times \text{count}(v)$答えを求めて、すべてのノードを合計します。 

重要な考え方は、LCA が以下のサブセットであるということです。$v$これは、まさに、次の時点で収束を「強制」する方法で、さまざまな子サブツリーからノードを選択するものです。$v$単一の子サブツリー内ではなく。 

### なぜ効果があるのか

 正確さは、すべてのサブセットが一意の LCA を持ち、その LCA が選択されたノードが異なるブランチに分岐する最高点によって決定されるという事実に基づいています。 各ノードのツリーを独立した子サブツリーに分解することにより、選択された要素が複数の枝にまたがるか、ノード自体を含む最上位ノードでサブセットが確実に一意に分類されます。 DP は、サブセットを 1 つの子サブツリー内に完全に含めることができない最初のポイントでのみ寄与がカウントされるようにすることで、この一意性を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    root = 0

    for i in range(n):
        if p[i] == i + 1:
            root = i
        else:
            g[p[i] - 1].append(i)

    sys.setrecursionlimit(10**7)

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    size = [0] * n
    dp = [0] * n

    def dfs(u):
        size[u] = 1
        child_prod = 1

        for v in g[u]:
            dfs(v)
            size[u] += size[v]
            child_prod = (child_prod * (pow2[size[v]] - 1)) % MOD

        dp[u] = child_prod
        return

    dfs(root)

    ans = 0
    for i in range(n):
        ans = (ans + (i + 1) * dp[i]) % MOD

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```コードは、親配列からルート付きツリーを構築することから始まります。 次に、サブツリー内のサブセットを高速にカウントするために 2 の累乗を事前計算します。 DFS はサブツリーのサイズを計算し、乗算構造を使用して子サブツリーからの寄与を結合します。 各子サブツリーが貢献します$2^{size} - 1$、ブランチ間で結合されない限り、そのサブツリー内で LCA の制約を維持するノードを選択するための空ではないすべての方法を表します。 

最後のループでは、すべてのノードからの寄与を集約し、問題の必要に応じてラベルによって各ノードに重み付けを行います。 

実装の微妙な詳細は、サブツリーの組み合わせ内でモジュラー演算を使用することです。 それがなければ、中間値は指数関数的に爆発します。 もう 1 つの重要な点は再帰の深さです。そうしないと、チェーン状のツリーが Python のデフォルトの再帰制限を超えてしまうからです。 

## 実用的な例

 ### 例 1

 3 つのノードの小さなチェーンを考えてみましょう。1 は 2 の親であり、2 は 3 の親です。 

| ノード | サブツリーのサイズ | dp値 |
 | --- | --- | --- |
 | 3 | 1 | 1 |
 | 2 | 2 | (2^1 - 1) = 1 |
 | 1 | 3 | (2^2 - 1) = 3 |

 したがって、貢献は次のとおりです。 

ノード 1 は 1×3 = 3 に寄与し、ノード 2 は 2×1 = 2 に寄与し、ノード 3 は 3×1 = 3 に寄与し、合計 8 になります。 

これは、多くのサブセットが連鎖的に上位の祖先に崩壊するという直観と一致します。 

### 例 2

 1 がルート、ノード 2、3、4 がその子であるスター ツリー。 

| ノード | サブツリーのサイズ | dp値 |
 | --- | --- | --- |
 | 2 | 1 | 1 |
 | 3 | 1 | 1 |
 | 4 | 1 | 1 |
 | 1 | 4 | (2^1 - 1)^3 = 1 |

 複数のリーフからノードを選択するサブセットは LCA を 1 に強制するため、ルートが優先されます。

 ## 特殊なケース

 単一ノード ツリーの場合、アルゴリズムはそのノードをルートとして扱い、そのサブツリー サイズは 1 であるため、dp は 1 になり、答えは単にノード インデックスになります。 これは、可能な唯一のサブセットと一致します。 

チェーンの場合、すべてのサブツリーがネストされるため、各ノードの dp 値は 1 に縮小され、すべての祖先を通じて寄与が蓄積されます。 DFS はサイズを正しく累積するため、サブセットが二重にカウントされることはありません。 

星型ツリーの場合、すべてのリーフの dp は 1 に等しく、ルートはすべての子からの寄与を乗算して、LCA がルートとなるグローバル サブセット構造を 1 つだけ生成します。 これにより、子に対する積構造がブランチ間の相互作用を正しく捕捉していることが確認されます。
