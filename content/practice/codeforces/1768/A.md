 ## 問題の理解

 この問題では、最大の整数を見つけるように求められます。`x`指定された整数より小さい`k`の合計が`x!`そして`(x-1)!`で割り切れます`k`。 分かりやすく言えば、すぐ下の数字が必要です`k`ここで、その階乗を前の数値の階乗に加算すると、次の倍数が得られます。`k`。 各テスト ケースは単一の整数です`k`、対応するものを出力する必要があります`x`または`-1`そのような番号が存在しない場合。 

制約を見てみると、`k`最大で 10 億に達する可能性があり、最大 10,000 のテスト ケースが存在する可能性があります。 これは、近似する数値の階乗を明示的に計算するソリューションを意味します。`k`全く実現不可能です。 階乗は非常に速く成長し、`100!`すでに超えています`10^157`、実際には標準的な整数演算をはるかに超えています。 したがって、大規模な階乗を直接計算しようとするアプローチは、`k`機能しません。 

の値が非常に小さい場合、微妙なエッジケースが発生します。`k`。 たとえば、次の場合`k = 3`、最大の`x`は`2`なぜなら`2! + 1! = 2 + 1 = 3`、3 で割り切れます。`x = k - 1`確認しなくても機能する可能性がありますが、なぜこのパターンが成り立つのかを理解する必要があります。 

## アプローチ

 ブルートフォースアプローチは繰り返されるでしょう`x`から`k-1`まで`1`、計算する`x! + (x-1)!`、そして次によって割り算をチェックします`k`。 これは数学的には正しいですが、計算的には失敗します。 階乗の計算`10^9`不可能です。 モジュラー演算を使用した場合でも、階乗シーケンスは実行可能な整数サイズをすぐに超えてしまうため、このアプローチは時間がかかりすぎ、メモリを大量に消費します。 

重要な観察は、合計が`x! + (x-1)!`次のように書き換えることができます`(x-1)! * (x + 1)`。 この式を次の式で割り切れるようにします。`k`。 もし`x >= k`、`(x-1)!`すでに含まれています`k`そのときの要因として`k > 2`、ただし、次のことに限定されます。`x < k`。 それで最大の`x`それは機能します`k-1`。 これは、`(k-1)! + (k-2)!`単純化すると`(k-2)! * k`、これは常に次で割り切れます。`k`のために`k > 2`。 のために`k = 2`、唯一の候補は`x = 1`。 

要約すると、次のようになります。`k >= 3`、答えは`k-1`。 のために`k = 2`、答えは`1`。 階乗を明示的に計算する必要がないため、問題は単純な算術に削減されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、`t`。 
2. 各テスト ケースについて、整数を読み取ります。`k`。 
3. もし`k`2 に等しい、出力 1。これは、最大値が`x`ではありません`k-1`。 
4. それ以外の場合は出力`k-1`。 これが機能する理由は、`(k-1)! + (k-2)! = (k-2)! * k`で割り切れます。`k`。 
5. すべてのテスト ケースに対して繰り返します。 

なぜ機能するのか: 重要な特性は階乗分解です。 任意の整数の場合`k > 2`、`(k-2)!`乗算`k`可分性を保証します。 常に摂取することで`x = k-1`を最大限に活用していることを保証します。`x`未満に保ちながら`k`。 特別な場合`k = 2`階乗パターンが依然として保持される最小境界を処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k = int(input())
    if k == 2:
        print(1)
    else:
        print(k - 1)
```コードは最初にテスト ケースの数を読み取ります。 テスト ケースごとに、特殊なケースをチェックします。`k = 2`なぜなら、一般式は`k-1`生み出すだろう`1`これは偶然一致しますが、明確にするために明示的に処理します。 その他すべてについて`k`、印刷されます`k-1`、数学的単純化を使用します。 高速入力`sys.stdin.readline`最大 10,000 のテスト ケースに対してソリューションが効率的に実行されることを保証します。
