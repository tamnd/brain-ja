 ## 解決策
 ## 問題の理解

 順列、つまり 1 から n までの数値の並べ替えが与えられています。 1 回の操作で、任意の k 個の要素を選択し、配列からそれらを削除し、選択した要素だけを並べ替えて、最後に追加し直します。 配列の残りの部分は相対的な順序を維持します。 

タスクは、順列をソートされた順序に変換するために必要なそのような移動の数を計算することです。 

重要な制約は、すべてのテスト ケースで n が最大 100000 になる可能性があるため、操作をシミュレートしたり、選択したサブセットの組み合わせを試したりするアプローチは、直ちに遅すぎるということです。 テスト ケースごとに線形または線形に近いものを超えるものは避けなければなりません。 

よくある失敗例は、操作ごとに k 個の間違って配置された要素を常に「修正」できると想定していることから発生します。 たとえば、k が n に等しい場合、すべてを一度に並べ替えるので、すでに並べ替えられていない限り、答えは常に 1 になります。 しかし、k が小さい場合、要素間の相互作用が大きく影響します。 

k が 1 に等しい場合、微妙なエッジ ケースが発生します。その場合、各操作は 1 つの要素を選択し、それを変更せずに末尾に追加します。これは、要素を効果的に回転させることを意味します。 単純な貪欲な人は、これがバブルソートのように動作し、操作を過小評価すると考えるかもしれません。 

もう 1 つの失敗モードは、要素を正しい位置に独立して配置できると仮定した場合です。 実際には、要素が後ろに移動されると、その相対的な順序の制約が維持されるため、進行状況はローカルな修正ではなくグローバルな構造によって制御されます。 

## アプローチ

 ブルートフォース解釈では、すべてのステップで k 個の要素の考えられるすべての選択をシミュレートし、最小限の移動でソート順に到達しようとします。 これは、操作の下で到達可能な置換の完全な状態空間を探索するため、原理的には正しいです。 ただし、ステップごとに選択可能な選択がchoose(n, k) あるため、分岐係数が膨大になり、n = 20の場合でも指数関数的になり使用できなくなります。 

重要な点は、この操作では要素をバッファーに「収集」し、最後にそれらを並べ替えられた順序で再挿入することしかできないということです。 これは、すでに正しい相対順序になっている要素は無視できることを意味し、難易度は、恒等順列構造にすでに整列している要素の数によって完全に決まります。 

正しい観点は、ソートされた順列のどの接頭辞がすでに安定しているか、およびそれに対して「場違い」な要素がいくつあるかを追跡することです。 各操作では、最大 k 個の間違って配置された要素を修正できますが、これは要素が適切に選択されている場合に限られます。 これにより、すでに正しい相対位置にある要素の数とソートされていない要素の数に基づいてカウント引数が得られます。 

より正確に特徴付けると、答えは、端からスキャンするときに正しいサフィックスにすでに含まれている要素の数に依存することがわかります。 移動ごとに正しく完全に配置できるのは k 個の要素だけであるため、各操作ではこのサフィックスを最大 k 個の要素まで拡張できます。 

これにより、問題はシミュレーションではなく貪欲な計数プロセスに縮小されます。

 ## アルゴリズムのチュートリアル

 単純に 1 から n までの並べ替え順序と比較することによって、並べ替えを処理します。 最後からスキャンして、既に正しく減少する接尾辞の位置にある要素の数を数えます。 

ポインタを維持します`need = n`、最後に正しく配置されると予想される最大値を表します。 配列を右から左にスキャンします。`need`、デクリメントします`need`。 これは、どの程度のサフィックスが既に正しく配置されているかを測定します。 

このスキャンの後、次の場合は、`need`が 0 になると、配列はすでにソートされており、操作は必要ありません。 

それ以外の場合、残りの満たされていないプレフィックスのサイズは次のとおりです。`need`。 各操作では、まだ正しく配置されていない最大 k 個の要素を「修正」できます。これは、常に k 個の間違って配置された要素を選択し、並べ替えられた順序で最後に移動し、時間の経過とともにそれらを正しいサフィックス位置に効果的にロックできるためです。 

したがって、必要な操作数の上限は次のとおりです。`need / k`。 

### なぜ効果があるのか

 サフィックス スキャンは、最終位置に関してすでに正しい最長のテールをキャプチャします。 このサフィックスの外側にあるものはすべて、積極的に位置を変更する必要があります。 各操作では、k 個の要素を正しい最終ブロックに最終化することしかできないため、問題をパッキング引数、つまり、間違って配置されたすべての要素をカバーするにはサイズ k のグループがいくつ必要かという問題に落とし込みます。 どの操作でも k 個を超える要素を修正することはできません。これは、操作ごとに k 個だけが移動され、それらを並べ替えても、それらの k を超える新しい正しい配置が作成されないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    p = list(map(int, input().split()))

    need = n
    for x in reversed(p):
        if x == need:
            need -= 1

    if need == 0:
        print(0)
    else:
        print((need + k - 1) // k)
```このソリューションは、各テスト ケースを個別に読み取り、すでに正しいサフィックス位置にある要素の数を計算します。 逆スキャンは、実際に有効な最終末尾を形成できる要素のみを順番に照合するため、重要です。 

最終的な式`(need + k - 1) // k`は、標準的な上限区分であり、残りの誤って配置された要素をすべてカバーするために必要な完全な操作の数を表します。 

## 実用的な例

 次のサンプルを考えてみましょう。`n = 4, k = 2`そして`p = [1, 3, 2, 4]`。 

最後からスキャンします。 

| ステップ | 要素 | 前に必要 | アクション | | 以降が必要です
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 4 に一致 | 3 |
 | 2 | 2 | 3 | スキップ | 3 |
 | 3 | 3 | 3 | 一致 3 | 2 |
 | 4 | 1 | 2 | matches 1 does not match 2 | 2 |

 それで`need = 2`これは、2 つの要素がまだ正しいサフィックス位置合わせになっていないことを意味します。 k = 2 の場合、1 回の操作で十分です。 

ここで考えてみましょう`p = [2, 3, 1, 4]`、`k = 2`。 

| ステップ | 要素 | 前に必要 | アクション | | 以降が必要です
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 一致 | 3 |
 | 2 | 1 | 3 | スキップ | 3 |
 | 3 | 3 | 3 | 一致 | 2 |
 | 4 | 2 | 2 | 一致 | 1 |

 ここ`need = 1`、単一の要素が依然として完全な位置合わせをブロックするため、1 つの操作が必要になります。 

これらのトレースは、アルゴリズムがスワップを追跡しているのではなく、すでに「固定」されているとみなせる最終サフィックスの構造を追跡していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | テストあたり O(n) | 順列の 1 回の逆スキャン |

すべてのテスト ケースの合計 n は 100000 で制限されるため、線形スキャンは Python の制約下でも十分に高速になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))

        need = n
        for x in reversed(p):
            if x == need:
                need -= 1

        if need == 0:
            out.append("0")
        else:
            out.append(str((need + k - 1) // k))

    return "\n".join(out)

# provided samples
assert run("""4
3 2
1 2 3
3 1
3 1 2
4 2
1 3 2 4
4 2
2 3 1 4
""") == """0
1
1
2"""

# all sorted
assert run("""1
5 3
1 2 3 4 5
""") == "0"

# reverse order
assert run("""1
5 2
5 4 3 2 1
""") == "2"

# k = n case
assert run("""1
4 4
3 2 1 4
""") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すでに並べ替えられています | 0 | サフィックス検出の正確性 |
 | 逆順列 | 2 | 複数のステップの要件 |
 | k = n の場合 | 1 | 1 回の操作で完全なコレクション |

 ## 特殊なケース

 When the permutation is already sorted, the reverse scan immediately consumes all values and`need`ゼロになります。 これにより、アルゴリズムは不必要な演算を実行せずに正しくゼロを出力するようになります。 

k が n と等しい場合、順列がまだソートされていないときは常に、式は 1 回の操作に減ります。これは、すべての要素を 1 回選択してソートできるという事実と一致します。 

k が 1 に等しい場合、各演算は効果的に 1 つの要素を最後に移動するため、答えは正しいサフィックスにまだ含まれていない要素の数となり、数式の 1 による除算の動作と一致します。
