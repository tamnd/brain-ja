 ## 解決策
 ## 問題の理解

 頂点が人々を表し、エッジが関係を表す無向グラフが与えられます。 あらゆるクエリに対して`(u, v)`からの単純なパスが存在するかどうかを判断する必要があります。`u`に`v`長さが奇数です。 

ここでのキーワードは「シンプル」です。 頂点を再訪することはできません。 グラフは必ずしもつながっているわけではなく、循環が含まれる場合もあります。 

すべてのクエリ頂点からの直接 BFS は機能しません。 到達できる頂点とエッジの数の両方`10^5`、までもあります。`10^5`クエリ。 クエリごとに直線的な時間を費やすソリューションでは、次の時間が必要になります。`10^10`最悪の場合、限界をはるかに超えて動作する可能性があります。 

本当の難しさは、頂点のペアの間に偶数と奇数の両方の単純なパスが存在する可能性があることです。 答えは最短パスのパリティだけでは決まりません。 

次のグラフを考えてみましょう。```
1 - 2
|   |
3 - 4
```間`1`そして`2`、奇妙な道があります`1-2`、ただし均等なパスでもあります`1-3-4-2`。 この問題は、少なくとも 1 つの奇妙な単純なパスが存在するかどうかのみを尋ねます。 

よくある間違いは、2 部構成のカラーリングですべてが解決すると考えることです。 2 部グラフでは、2 つの頂点間のすべてのパスが同じパリティを持つため、そこで色付けが機能します。 ただし、グラフに奇数サイクルが含まれると、両方のパリティが可能になる可能性があります。 

例えば：```
1 - 2
 \ /
  3
```三角形には奇数のサイクルが含まれています。 間`1`そして`2`、 我々は持っています：```
1-2        length 1
1-3-2      length 2
```両方のパリティが存在します。 ペアごとに 1 つのパリティのみを保存するアプローチは失敗します。 

もう 1 つの微妙なケースは、同じ頂点をクエリする場合です。 

入力：```
3 3
1 2
2 3
3 1
2
1 1
2 2
```出力：```
Yes
Yes
```三角形には奇数のサイクルが含まれているため、頂点`1`単純な奇数サイクルの長さを使用して自分自身に戻ることができます`3`。 不用意に実装すると、誤った答えが返される可能性があります`"No"`空のパスには長さがあるため`0`。 

コンポーネントが接続されていないこともミスの原因です。 

入力：```
4 1
1 2
2
1 3
3 4
```出力：```
No
No
```パスがまったく存在しないため、答えは次のようになります。`"No"`パリティに関係なく。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆるクエリに対して`(u, v)`、パリティを追跡する BFS または DFS を実行します。 各頂点を 2 つの状態に複製できます。```
(vertex, parity)
```エッジを通過すると、パリティが反転します。 

辿り着くことができたら`(v, 1)`の場合、奇妙なパスが存在します。 

このアプローチは散歩には適していますが、単純な道には必ずしも適していません。 頂点の繰り返しを防ぐと、検索が非常に困難になります。 一般的なグラフでは、クエリごとに単純パス パリティを直接追跡するとコストが高くなります。 

単純さの問題を無視してクエリごとに BFS を実行したとしても、複雑さは次のようになります。```
O(q(n + m))
```すべての値が近い場合`10^5`、これはおおよそです`10^10`操作。 

重要な観察は構造的です。 

接続された 2 部コンポーネントの内部では、2 つの頂点間のすべてのパスに固定パリティがあります。 2 つの頂点が同じカラー クラスにある場合、それらの間のパスはすべて均等になります。 それらが反対のクラスにある場合、すべてのパスは奇数になります。 

接続された非 2 部コンポーネントの内部では、状況は完全に変わります。 奇数サイクルが存在し、その奇数サイクルによりパス パリティを反転できます。 実際:

 接続されたコンポーネントが 2 部構成でない場合、頂点のすべてのペアには、それらの間に偶数と奇数の両方の単純なパスがあります。 

そのたった一つの事実が問題全体を崩壊させます。 

したがって、解決策は次のようになります。 

1. 接続されたコンポーネントを検索します。 
2. 各コンポーネントが 2 部構成であるかどうかを判断します。 
3. コンポーネントが 2 部構成の場合、頂点カラーを使用してパリティを決定します。 
4. コンポーネントが 2 部構成でない場合、コンポーネント内のすべてのペアが応答します`"Yes"`。 

これにより、1 回の DFS/BFS 前処理パス後のすべてのクエリが一定時間のチェックに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(q(n + m)) | O(n + m) | 遅すぎる |
 | 最適なグラフ前処理 | O(n + m + q) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 

グラフはまばらであるため、隣接リストが自然に表現されます。 
2. DFS または BFS を使用して、接続されているすべてのコンポーネントをスキャンします。 

トラバース中に、各頂点にバイナリ カラーを割り当てます。 
3. エッジをトラバースしているとき`(u, v)`、色の一貫性を確認します。 

もし`u`そして`v`すでに同じ色を持っている場合、コンポーネントは 2 部構成ではありません。 
4. 頂点ごとに保存します。 

- 接続されているコンポーネント ID
 - 二部構成の色
 - そのコンポーネントが二部構成であるかどうか
 5. 各クエリについて`(u, v)`:

 1. もし`u`そして`v`異なる接続コンポーネントに属する、印刷`"No"`。 

パスがまったく存在しません。 
2. それ以外の場合、コンポーネントが 2 部構成でない場合は、出力します。`"Yes"`。 

非二部連結成分には奇数サイクルが含まれており、これにより任意のペア間に奇数の単純なパスを構築できます。 
3. それ以外の場合、コンポーネントは 2 部構成になります。 

2 部グラフでは、2 つの頂点間のすべてのパスが同じパリティを持ちます。 

印刷する`"Yes"`色が異なる場合、そうでない場合`"No"`。 

### なぜ効果があるのか

 接続されたグラフは、奇数サイクルが含まれていない場合に限り、二部グラフになります。 

2 部グラフでは、すべてのエッジが反対の色のクラスを接続します。 どのパスでもステップごとに色が交互になるため、2 つの頂点間のパスのパリティは色によって一意に決まります。 

グラフが 2 部構成でない場合は、奇数のサイクルが存在します。 間の任意のパスから開始`u`そして`v`、パスを単純に保ちながら、奇数サイクルを経由してパリティを反転することができます。 コンポーネントが接続されているため、頂点のすべてのペアが奇数サイクルに到達し、それを使用してパリティを変更することができます。 

つまり:

 - 2 部コンポーネント → パリティ固定
 - 非 2 部コンポーネント → 両方のパリティが利用可能

 アルゴリズムはこれらの条件を正確にチェックするため、すべての答えは正しいものになります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    comp = [-1] * (n + 1)
    color = [-1] * (n + 1)
    bipartite = []

    cid = 0

    for start in range(1, n + 1):
        if comp[start] != -1:
            continue

        queue = deque([start])
        comp[start] = cid
        color[start] = 0

        ok = True

        while queue:
            u = queue.popleft()

            for v in graph[u]:
                if comp[v] == -1:
                    comp[v] = cid
                    color[v] = color[u] ^ 1
                    queue.append(v)
                else:
                    if color[v] == color[u]:
                        ok = False

        bipartite.append(ok)
        cid += 1

    q = int(input())

    out = []

    for _ in range(q):
        u, v = map(int, input().split())

        if comp[u] != comp[v]:
            out.append("No")
        elif not bipartite[comp[u]]:
            out.append("Yes")
        else:
            out.append("Yes" if color[u] != color[v] else "No")

    print("\n".join(out))

solve()
```前処理フェーズでは、接続されているすべてのコンポーネントに対して BFS を実行します。 トラバース中に、頂点は交互の色を受け取ります。 

の`comp`配列は、各頂点がどの接続コンポーネントに属するかを識別します。 これにより、接続に関する質問に即座に回答します。 

の`color`配列には 2 部構成のパーティションが格納されます。 隣接する頂点は常に反対の色を受け取る必要があります。 同じ色を接続するエッジに遭遇した場合、そのコンポーネントには奇数のサイクルが含まれており、非 2 部構成としてマークされます。 

の`bipartite`list にはコンポーネントごとに 1 つのブール値が格納されます。 これにより、各クエリを一定時間で実行できるようになります。 

微妙な実装の詳細は、色の競合を検出した後でもトラバースを継続することです。 早期に停止すると、コンポーネントの一部が未訪問のままになり、後のクエリが中断されてしまいます。 

もう 1 つの重要な詳細は、次のようなクエリの処理です。`(u, u)`。 2 部構成コンポーネントの場合、答えは次のとおりです。`"No"`すべてのサイクルが均等であるためです。 非 2 部コンポーネントの場合、答えは次のようになります。`"Yes"`奇数サイクルが存在するからです。
