 ## 解決策
 ## 問題の理解

 地下室を表すグリッドがあります。 一部のセルは壁であり、一部は歩行可能であり、正確に 1 つの歩行可能なセルが出口になります。 ロボットは未知の歩行可能なセルからスタートします。 次のような一連の固定された移動コマンドが与えられます。`L`、`R`、`U`、`D`。 

When the robot receives a command, it tries to move one cell in that direction. If the target cell is a wall, it stays where it is. The same command sequence is applied regardless of the robot’s starting position.

 コマンド シーケンスの最小のプレフィックスが必要です。そのプレフィックスを実行した後、考えられるすべての開始位置が出口セルで終了するようにします。 プレフィックスが機能しない場合は、印刷します`-1`。 

地下室にはせいぜい`150 × 150 = 22500`セル、コマンドシーケンスの長さは最大です`10^5`。 コマンドごとにすべてのセルを個別にシミュレートするアルゴリズムは、すぐに高価になります。 すべてのコマンドに対するすべてのセルにわたる単純なシミュレーションには、すでにおよそのコストがかかります`2.25 × 10^9`限界をはるかに超えた最悪の場合の動作。 

ここではグラフの構造が重要です。 通過可能なすべてのセルは出口に接続されており、外側の境界はすべて壁です。 これらの条件により、移動の処理が簡素化され、グリッドからの脱出を伴う特殊なケースが排除されます。 

難しいのは、コマンドがロボットの可能なすべての位置に同時に作用することです。 コマンドはロボットの移動先を選択するのではなく、可能な位置のセット全体を決定論的に変換します。 

いくつかの特殊なケースは、素朴な推論を打ち破ります。 

通行可能なセルが 1 つだけある地下室を考えてみましょう。```
###
#E#
###
```コマンド シーケンスは、何かを実行する前にすでに成功しています。 正しい答えは、`0`。 常に少なくとも 1 つのコマンドを処理するソリューションは失敗します。 

もう 1 つの微妙なケースは、ロボットが一時的に集合し、後で再び分離する可能性がある場合です。```
#####
#...#
#.E.#
#...#
#####
```コマンド:```
LR
```後`L`、動きをブロックする壁が異なるため、複数の位置が一緒に崩壊する可能性があります。 後`R`、彼らは再び分離することができます。 したがって、プロセス中にすべてのロボットが出会うかどうかを確認することは正しくありません。 接頭辞の後の最後の位置のみが重要です。 

もう 1 つの重要なケースは、シーケンス全体が依然として収束を強制しない場合です。```
#####
#E..#
#####
```コマンド:```
RRRR
```出口セルはブロックされるまで右に移動し、別のセルも同じ右端の位置で終了します。 ロボットがすべて同時に出口で終了することはありません。 正しい答えは、`-1`。 

中心的な課題は、グローバルな変換が繰り返される中で考えられるすべてのロボットの状態を効率的に追跡することです。 

## アプローチ

 強引な発想は当然だ。 通過可能な開始セルごとに、コマンド シーケンスを通じてロボットをシミュレートします。 各プレフィックスを処理した後、すべてのロボットが出口にあるかどうかを確認します。 

ロボットのダイナミクスは決定論的であるため、これは正しいです。 各プレフィックスの後のすべての開始位置がどこで終わるかがわかっていれば、条件を直接テストできます。 

問題は規模だ。 させて`P`通過可能なセルの数になります。 最悪の場合、`P ≈ 22500`。 それぞれについて、`10^5`コマンドを使用すると、すべてを更新します`P`位置を調べ、それらすべてを出口と比較する可能性があります。 それはおおよそ次のようになります。```
22500 × 100000 = 2.25 × 10^9
```操作。 

重要な観察は、コマンド シーケンスがセルの関数を定義していることです。 

コマンドプレフィックスの場合`t`、 定義する：```
f_t(x) = final position after applying first t commands starting from x
```最初のものが必要です`t`次のような:```
f_t(x) = exit for every x
```すべてのロボットを個別にシミュレートする代わりに、逆に考えることができます。 

コマンドの接尾辞を処理した後、どのセルが出口で終了する可能性があるかがわかったとします。 次に、もう 1 つのコマンドを前に追加して、このセットを逆方向に変換します。 

たとえば、次のコマンドが`L`、次にセル`u`適用する場合はコマンドの前に行うと良いでしょう`L`から`u`すでに良好なセット内に収まります。 

これは、セルのサブセットにわたる逆到達可能性プロセスになります。 

重要な最適化は、サブセットをビットセットとして表すことです。 通過可能な各セルにはインデックスが付けられます。 セルのサブセットがビットマスクになります。 遷移計算は、マシンワードを介した高速なビット単位の演算になります。 

すべての方向とすべてのセルについて、次のセルが決定的にわかります。 逆遷移を事前計算できます。```
rev[d][v] = set of cells that move to v under command d
```次に、コマンド シーケンスを逆方向に処理します。 以下から開始します:```
good = {exit}
```繰り返し拡張します。```
good = preimage under current command
```最終的には`good`通過可能なすべてのセルが含まれている場合、対応する接頭辞が機能します。 

これにより、すべてのロボットを個別にシミュレートすることから、ビットセットの伝播を繰り返すことへと複雑さが変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 定数が大きい O(P · k) は事実上大きすぎます。 O(P) | 遅すぎる |
 | 最適 | O(k・P / 64) | O(P² / 64) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 通過可能なすべてのセルを列挙し、それぞれに整数の ID を割り当てます。 

これにより、セルの任意のサブセットを ID でインデックス付けされたビットセットとして表すことができます。 
2. すべてのセルおよびすべての方向について、1 つのコマンドの後で宛先セルを計算します。 

移動が壁にぶつかった場合、目的地は同じセルになります。 
3. 逆遷移ビットセットを構築します。 

方向ごとに`d`そして各ターゲットセル`v`、すべてのセルを保存します`u`から移動するように`u`を使用して`d`で終わる`v`。 

これにより、プリイメージを効率的に計算できるようになります。 
4. ビットセットを初期化する`good`出口セルのみが含まれます。 

この段階では、`good`は、空のサフィックスを処理した後に出口で終了することが保証されているすべての位置を表します。 
5. コマンド シーケンスを逆方向に処理します。 

現在のコマンドが`c`。 塗った後に良くなるすべての細胞が欲しい`c`。 

あらゆる細胞に`v`すでに中に`good`、内のすべてのセル`rev[c][v]`コマンドの前にも良くなります。 
6. 現在のセルのすべての逆遷移セットの和集合を計算します。`good`。 

これにより、新しいものが生成されます`good`。 
7. 位置から始まるサフィックスの処理後`i`、どうかを確認してください`good`すでにすべての通過可能なセルが含まれています。 

「はい」の場合、その接尾辞の前で終わる接頭辞によって、すべての開始位置が強制的に出口に配置されます。 
8. プレフィックスの長さの最小値を返します。 

逆方向に処理するため、現在のサフィックスの開始によってプレフィックスの長さが直接決まります。 
9. すべてのセルをカバーするステージがない場合は、印刷します。`-1`。 

### なぜ効果があるのか

 あらゆる段階で、`good`残りのサフィックスによって出口での終了が保証されるセルが正確に含まれます。 

不変条件は逆遷移によって維持されます。 現在のコマンドを適用するとセルは古いセットに送信され、正確に新しいセットに属します。 ロボットの動きは決定論的であるため、この特徴付けは正確です。 

いつ`good`が通過可能なすべてのセルのセットになると、すべての開始位置は、対応する接尾辞の後の出口に到達することが保証されます。 同様に、補完的なプレフィックスでも十分です。 

すべてのコマンドを逆の順序で処理し、最も早い有効なポイントで停止するため、返されるプレフィックスの長さは最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()

    cells = []
    idx = [[-1] * m for _ in range(n)]

    exit_id = -1

    for i in range(n):
        for j in range(m):
            if grid[i][j] != '#':
                idx[i][j] = len(cells)
                cells.append((i, j))
                if grid[i][j] == 'E':
                    exit_id = idx[i][j]

    p = len(cells)

    if p == 1:
        print(0)
        return

    dirs = {
        'L': (0, -1),
        'R': (0, 1),
        'U': (-1, 0),
        'D': (1, 0),
    }

    trans = [[0] * p for _ in range(4)]

    dir_id = {'L': 0, 'R': 1, 'U': 2, 'D': 3}

    for u, (x, y) in enumerate(cells):
        for ch, (dx, dy) in dirs.items():
            nx = x + dx
            ny = y + dy

            if grid[nx][ny] == '#':
                v = u
            else:
                v = idx[nx][ny]

            trans[dir_id[ch]][u] = v

    rev = [[0] * p for _ in range(4)]

    for d in range(4):
        for u in range(p):
            v = trans[d][u]
            rev[d][v] |= (1 << u)

    all_mask = (1 << p) - 1

    good = 1 << exit_id

    if good == all_mask:
        print(k)
        return

    for pos in range(k - 1, -1, -1):
        d = dir_id[s[pos]]

        new_good = 0

        cur = good

        while cur:
            lsb = cur & -cur
            v = lsb.bit_length() - 1
            new_good |= rev[d][v]
            cur ^= lsb

        good = new_good

        if good == all_mask:
            print(pos)
            return

    print(-1)

solve()
```最初の部分では、通過可能なすべてのセルに整数 ID を割り当てます。 ビットセットは座標ペアではなくコンパクトな整数インデックスに対して機能するため、この変換は不可欠です。 

の`trans`配列には決定的な移動結果が格納されます。 各方向および各セルについて、1 つのコマンド後にロボットがどこで終了するかを事前に計算します。 ここでは、ブロックされた動きを正しく処理することが重要です。 隣接するセルが壁の場合、ロボットはその場に留まります。 

逆グラフはビットマスクとして保存されます。`rev[d][v]`に移動するすべてのセルが含まれます。`v`指示の下で`d`。 これを一度構築すると、後で非常に高速な逆伝播が可能になります。 

変数`good`は核となる不変式です。 これは、すでに処理されたサフィックスによって出口への到達が保証されているすべてのセルを表します。 

逆方向反復では、コマンドを最後から最初に向かって処理します。 現在正常なターゲット セルごとに`v`、私たちは、に移動するすべての前任者を結合します。`v`。 

ビット反復のトリック:```
lsb = cur & -cur
```一度に 1 セットのビットを効率的に抽出します。 

微妙な詳細は、返されるインデックスです。 位置から逆方向に処理中`pos`、サフィックスかどうかを判断しています。`s[pos:]`出口を保証します。 それはプレフィックス長を意味します`pos`前にコマンドがあるため、これで十分です。`pos`接尾辞が強制的に収束すると、無関係になります。 

もう 1 つの簡単な間違いは、更新する前に状態を確認することです。`good`。 不変式は現在処理されているサフィックスに対応するため、現在のコマンドを組み込んだ後にチェックを行う必要があります。
