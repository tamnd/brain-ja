 ## 問題の理解

 以下の整数の順列を構築する必要があります。`1`に`n`3 つの特別な要件があります。 

最初の位置には次の値を含める必要があります`x`。 最後の位置には次の値を含める必要があります`1`。 あらゆるポジションについて`i`から`1`に`n-1`、そこに配置される値は次の倍数である必要があります。`i`。 

すべての有効な順列の中で、辞書編集的に最小の順列が必要です。 有効な順列が存在しない場合は、次のように出力します。`-1`。 

制約が十分に大きいため、答えを直接構築する必要があります。 すべての合計`n`値は最大でも`2·10^5`、つまり、`O(n log n)`あるいは`O(n√n)`すべてのテスト ケースにわたる合計作業量が線形に近い限り、テスト ケースごとのソリューションは問題ありません。 順列に対するブルートフォース検索は不可能です。 たとえ`n = 15`、すでに 1 兆を超える順列が存在します。 

微妙なエッジケースが現れるのは、`x`分けない`n`。 

例えば：```
n = 5, x = 4
```最初の位置には以下が含まれます`4`。 結局その価値は`5`どこかに現れるはずです。 最後を除くすべての位置にはそのインデックスの倍数が含まれている必要があるため、すべての制約が適用されるように必要な値をルーティングする方法はありません。 正しい答えは次のとおりです。```
-1
```もう 1 つの簡単な間違いは、`x`位置にある`1`そして`1`位置にある`n`残りは自動的に決定されます。 

考慮する：```
n = 12, x = 3
```これら 2 つの変更を含む恒等順列は、位置から値が削除されているため無効です。`1`すべての割り算制約を維持しながら再配置する必要があります。 

3 番目の微妙な点は、辞書編集上の最小限性です。 私たちは単に有効な順列を探しているだけではありません。 有効な順列が複数存在する場合、すべての位置を左から右へできるだけ小さく保つ必要があります。 

## アプローチ

 ブルートフォース手法では、順列を生成し、すべての位置が可算条件を満たすかどうかをテストします。 サイズ 15 のすべての順列をチェックすることさえすでに絶望的であるため、制約の構造を利用する必要があります。 

重要な観察は、すべての数値がそれ自体の倍数であるため、恒等順列がすでに割り算の要件を満たしているということです。 

ポジション制限がなかったら`1`そして`n`、順列```
1 2 3 ... n
```有効でしょう。 

唯一の問題はそのポジションです`1`を含める必要があります`x`そして位置`n`を含める必要があります`1`。 

これは、恒等順列から開始して位置の小さなチェーンのみを変更することを示唆しています。 可分性条件は非常に限定的です。 位置の場合`i`含まれていない`i`の場合、さらに大きな倍数が含まれている必要があります。`i`。 

配置するとします`x`位置にある`1`。 次に、元々位置に属していた値`x`どこか別の場所に移動しなければなりません。 この引数を繰り返すと、次の各位置が前の位置の倍数になる一連の位置が作成されます。 

解決策が存在するためには、最終的には適切な位置に到達する必要があります`n`。 これはすぐに次のことを意味します`x`分けなければなりません`n`。 もし`x`分けない`n`、有効なチェーンが存在しません。 

辞書編集的に最小の答えを取得するには、常に最も早く変更された位置が可能な限り最小の有効な値を受け取るようにします。 これにより、現在の位置から、到達可能な最小の約数の倍数への貪欲な移行が行われます。`n`。 

結果として得られる構造は、次の除数チェーンに従います。`x`に`n`。

 ## アルゴリズムのチュートリアル

 1. もし`n`で割り切れない`x`、出力`-1`。 
2. 順列を恒等順列として初期化します。```
p[i] = i
```3. 以下を設定します。```
p[1] = x
p[n] = 1
```4. しましょう`cur = x`。 
5. ながら`cur != n`、最小の倍数を見つけます`next`の`cur`次のような:

 -`next`分割する`n`-`next > cur`このようなすべての候補の中から、最小のものを選択します。 
6. 以下を設定します。```
p[cur] = next
```そして移動します:```
cur = next
```7.到達後`n`、 セット：```
p[n] = 1
```8. 順列を出力します。 

貪欲な選択が解決策の核心です。 各ステップで、次の有効な次の約数の最小値を選択します。`n`それは現在の位置の倍数でもあります。 より大きな選択肢を選択すると、順列のより前の位置が増加するため、辞書編集的により大きな答えが生成されます。 

### なぜ効果があるのか

 変更されたすべての位置はチェーンに属します```
1 -> x -> ... -> n -> 1
```各遷移は数値からその倍数の 1 つに移行するため、割り算の要件は満たされたままになります。 

チェーンの外側のすべての位置は元の値を維持し、割り算の要件も満たします。 

チェーンは次の約数のみを使用します。`n`、すべてのステップが最終的に到達できるように、`n`。 もし`x`分けない`n`、すべての動きが維持されるため、そのような連鎖は存在しません。`n`。 

貪欲ルールは、選択肢が存在する最も早い位置で可能な限り最小の次の値を選択します。 辞書編集上の順序は最初の異なる位置によって決定されるため、これにより最小の有効な順列が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        if n % x != 0:
            print(-1)
            continue

        p = list(range(n + 1))

        p[1] = x
        p[n] = 1

        cur = x

        while cur != n:
            nxt = n

            d = cur * 2
            while d <= n:
                if n % d == 0 and d % cur == 0:
                    nxt = d
                    break
                d += cur

            p[cur] = nxt
            cur = nxt

        print(*p[1:])

solve()
```並べ替えは恒等順列として開始されます。これは、すべての割り算制約がすでに満たされているためです。 

変化する位置は、除数チェーン上の位置だけです。 現在のポジションについて`cur`の倍数を検索します。`cur`まだ分​​割できる最小のものを選択します`n`。 その選択により、最終的に到達する可能性が保たれます`n`並べ替えを辞書編集的に最小限にしながら。 

よくある実装上の間違いは、次のことを忘れることです。`p[n]`最終的には次のようになるはずです`1`。 もう1つは、チェーンの外側でポジションを交換することです。 タッチされていないすべての位置は、そのインデックスと同じままでなければなりません。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = []

    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        if n % x:
            out.append("-1")
            continue

        p = list(range(n + 1))
        p[1] = x
        p[n] = 1

        cur = x

        while cur != n:
            nxt = n

            d = cur * 2
            while d <= n:
                if n % d == 0 and d % cur == 0:
                    nxt = d
                    break
                d += cur

            p[cur] = nxt
            cur = nxt

        out.append(" ".join(map(str, p[1:])))

    return "\n".join(out)

# provided samples
assert run("3\n3 3\n4 2\n5 4\n") == (
    "3 2 1\n"
    "2 4 3 1\n"
    "-1"
)

# minimum valid case
assert run("1\n2 2\n") == "2 1"

# impossible because x does not divide n
assert run("1\n10 6\n") == "-1"

# direct chain
assert run("1\n6 3\n") == "3 2 6 4 5 1"

# larger divisor chain
assert run("1\n12 3\n") == "3 2 6 4 5 12 7 8 9 10 11 1"
