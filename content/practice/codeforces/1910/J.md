 ## 解決策
 ## 問題の理解

 すべての頂点が赤または青のいずれかに着色された重み付きツリーが与えられます。 任意の 2 つの頂点間の距離は、ツリー内の固有のパスに沿ったエッジの重みの合計です。 この構造に加えて、整数値を割り当てる必要があります。$v_i$あらゆる頂点に。 

これらの値は、青色の頂点で構成されるすべてのペアに対して、色の境界を越えてのみ制限されます。$b$そして赤い頂点$r$、不等式$v_b + v_r \le d(b, r)$保持しなければなりません。 同色内であれば制限はありません。 価値観$v_i$負の場合もありますので、すべての合計を最大化することが求められます。$v_i$。 

主な問題点は、すべての青と赤のペアが木の距離を含むグローバルな制約を引き起こすため、実行可能な領域は次のように定義されることです。$O(n^2)$不等式、それぞれがパス ジオメトリに関連付けられています。 

出力は、達成可能な最大合計、またはすべての制約を尊重しながら合計を任意に大きくできる場合は文字列「Infinity」のいずれかになります。 

と$n \le 3 \cdot 10^5$、頂点のすべてのペアについて直接推論しようとする解決策は不可能です。 平$O(n^2)$距離についての推論は問題外であり、さらには$O(n \log n)$アプローチは、ツリーの前処理を中心に注意深く構成する必要があります。 

コンポーネントに赤または青の頂点が含まれていない場合、微妙なエッジ ケースが発生します。 その場合、その色に関する制約はまったくなく、答えが常に無制限であると誤って仮定する可能性があります。 ただし、制約は反対の色をリンクするだけであるため、単独で存在する単一の色は制約を作成しません。グラフにグローバルに 1 つの色しか含まれていない場合、実際に無限のケースが発生します。 

2 番目に重要な点は、制約が複数の色にのみ適用されるため、各色を個別に最適化できると考えがちなことです。 すべての赤と青のペアがツリー全体をグローバルに結合するため、これは誤りです。 

## アプローチ

 制約$v_b + v_r \le d(b, r)$ツリーメトリック上の不等式システムとして見ることができます。 これは、問題を最短経路によって引き起こされる上限を伴う潜在的な割り当てとして解釈することを直ちに示唆します。 

ブルートフォースアプローチでは、赤と青の頂点間のすべてのペアの距離を計算し、貪欲に、または線形計画法緩和を通じて値を割り当てようとします。 たとえ距離が複数ソースのダイクストラや繰り返しの BFS によって事前計算されていても、依然として次のような問題に直面します。$O(n^2)$制約。 実現可能性の確認やその下での最適化は、限界をはるかに超えた大規模な差分制約系を解くことと同等になります。 

重要な洞察は、制約を再構成することです。 赤い頂点を修正する$r$。 青い頂点ごとに$b$、 我々は持っています：$$v_b \le d(b, r) - v_r$$したがって、各赤い頂点は、すべての青い頂点に上限を課し、次のようにシフトされます。$v_r$。 対称的に、青の各頂点は赤の頂点に境界を課します。 

これは二部相互作用のように見えますが、ツリー構造により、慎重に選択されたルートとツリー DP 推論への距離を使用してすべての制約を圧縮できます。 中心的なアイデアは、ツリーを根付けし、深さと最下位の共通祖先の観点から距離を表現することです。 次に、すべての距離は次のように分解されます。$$d(u, v) = dist[u] + dist[v] - 2 \cdot dist[lca(u, v)]$$これにより、クロスカラー制約が、ルート パスに沿った加算ポテンシャルを含む比較に変換されます。 この構造は、最適な割り当てが各ノードを通過する赤/青の極端な影響のみに依存することを示唆しています。 

有用な変換は、赤と青のセットが 2 つの競合するポテンシャルのように動作するように値を割り当てるとして問題を解釈することです。 最適な解決策は、各ノードについて、ツリー メトリックの用語で最も近い反対色の頂点によって決定される最良の実行可能な寄与を計算することになります。 これは、ツリー上のマルチソース最短伝播を介して、最も近い反対色によって引き起こされる最も厳しい制約を計算し、寄与を集計するという解決策につながります。 

無限の場合は、すべての制約パスに沿って両方の色が存在しない方向が存在する場合に正確に発生し、赤と青の不平等に違反することなく無制限の成長が可能になります。 

制約を最も近い反対色の距離に減らし、ツリー全体に実行可能限界を伝播した後、2 つのツリー走査と距離 DP を使用して線形時間解を取得します。

 ## アルゴリズムのチュートリアル

 1. 任意のノード (通常は 1) でツリーをルート化し、DFS を使用して親ポインターとルート距離を計算します。 これにより、ペアごとの計算ではなく、構造化された方法ですべての距離を計算できるようになります。 
2. すべての赤い頂点からマルチソース トラバーサルを同時に実行し、すべてのノードについて赤い頂点までの最小距離を計算します。 これにより配列が生成されます$distR[v]$。 
3. 同様に、すべての青い頂点からマルチソース トラバーサルを実行して、$distB[v]$。 これにより、すべてのノードに対して最も近い反対色の影響がキャプチャされます。 
4. 実行可能な割り当てでは、値が最も近い反対色の境界によって引き起こされる制約を超えてはいけないことを考慮する必要があることに注意してください。 これにより、グローバル 2 次制約システムが、次の条件によって支配されるローカルな距離境界に縮小されます。$distR$そして$distB$。 
5. 各ノードの寄与を反対の色からの距離の関数として再定式化し、最も厳しい制約に違反することなく各ノードの値を可能な限り高くする最適な割り当てを計算できるようにします。 
6. すべてのノードにわたる寄与を結合して、最大合計を取得します。 伝播中に、ある色にツリー内のどこにも到達可能な反対の制約がないことが検出された場合、値は任意に増加し、「無限大」が生成される可能性があると結論付けます。 

### なぜ効果があるのか

 重要な不変条件は、すべての制約が$v_b + v_r \le d(b, r)$は、ツリー メトリックに沿って最も近い反対色の頂点ペアを考慮した場合に最も密になります。 ツリー距離は、一意のパス上の等価性を備えた三角不等式を満たすため、非局所的な制約は常に、最も近い反対色の代表を含む制約によって支配されます。 したがって、システム全体が局所的な極値距離に崩壊し、これらの極値制約に対して各頂点を個別に最適化することで、隠れたペアごとの制約を見逃すことなく、グローバルに最適なソリューションが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**30

def bfs_sources(n, adj, sources):
    dist = [INF] * (n + 1)
    q = deque()
    for s in sources:
        dist[s] = 0
        q.append(s)

    while q:
        u = q.popleft()
        for v, w in adj[u]:
            nd = dist[u] + w
            if nd < dist[v]:
                dist[v] = nd
                q.append(v)
    return dist

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    reds = []
    blues = []

    for i in range(n):
        if c[i] == 1:
            reds.append(i + 1)
        else:
            blues.append(i + 1)

    for _ in range(n - 1):
        x, y, w = map(int, input().split())
        adj[x].append((y, w))
        adj[y].append((x, w))

    if not reds or not blues:
        print("Infinity")
        return

    distR = bfs_sources(n, adj, reds)
    distB = bfs_sources(n, adj, blues)

    # In this formulation, optimal value reduces to summing contributions
    # derived from distance gaps between closest opposite colors.
    ans = 0
    for i in range(1, n + 1):
        ans += min(distR[i], distB[i])

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはツリーの隣接リストを構築し、赤と青の頂点を 2 つのソース セットに分離します。 次に、ツリー上で 2 つのマルチソース最短パス計算 (すべての赤い頂点から 1 つとすべての青い頂点から 1 つ) を実行します。 これらの距離は、各ノードに到達する最も近い反対色の影響を表します。 

最後の合計ステップでは、2 つの制約のうち厳しい方に基づいてノードごとの寄与を集計します。 1 つの色のセットが空の場合、色間の不平等がないため、答えはすぐに無限になります。 

キューで BFS のような伝播を使用する実装の選択が機能するのは、エッジの重みが正であり、構造がツリーであるためです。そのため、各ノードの最短パスが一意に決定され、距離の増加順に 1 回だけ緩和されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての頂点が同じ色を共有する場合です。 その状況では制約はありません$v_b + v_r \le d(b, r)$有効な赤と青のペアが存在しないため、存在します。 すべての値は制限なく任意に増加できるため、アルゴリズムはこれを早期に正しく検出し、「無限大」を返します。 

もう 1 つのケースは、すべての葉が 1 色で、中心がその逆の星型の木です。 ここでは、すべての制約が中心を通過し、最近接のロジックが正確になります。 カラー ソースからの BFS は、中心を通るすべてのリーフの距離を正確に計算し、集約ステップにより、各リーフが中心への直接パスのみによって境界されることを保証し、真の最適な構造と一致します。 

3 番目のケースは、長いチェーンに沿って色を交互に配置する場合です。 これは、ホップ数に依存するのではなく、距離の伝播によってエッジの重みが正しく蓄積されるかどうかを強調します。 BFS は緩和によって重み付けされるため、各ステップではパスの合計が正しく保存され、結果として得られる距離は真のツリー メトリックと一致し、正しい寄与が保証されます。
