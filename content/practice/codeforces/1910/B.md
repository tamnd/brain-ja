 ## 解決策
 ## 問題の理解

 私たちは、建物内に何人の人がいるかを経時的に追跡するシステムのログを受け取りました。 文字列内の各文字はイベントを表します。プラスは誰かが入場することを意味し、マイナスは誰かが退席することを意味します。 このシステムは車内に人がいない状態で一日を開始します。 

有効なログとは、シーケンスのどのプレフィックスでも負の数の人々が観察されないログです。 言い換えれば、「+」を +1、「-」を -1 として解釈して、左から右にプロセスをシミュレートすると、実行残高がゼロを下回ることはありません。 

The string we are given may violate this rule. ただし、文字列内の任意の 2 文字を最大 1 回交換するだけで修正することも、何も行わなくても修正できます。 タスクは、そのような修正が可能かどうかを判断し、可能であれば、有効なスワップ (おそらく同じインデックスの no-op スワップ) を出力することです。 

制約は大きく、テスト ケース全体のすべての文字列の長さの合計は最大 300,000 です。 テスト ケースごとに O(n²) 個の可能性があるため、すべてのスワップを試行するソリューションは即座に除外されます。 スワップ候補ごとの線形スキャンですら、遅すぎます。 テスト ケースごとに O(n) の不均衡の構造を検査するものが必要です。 

重要な微妙な点は、2 つの文字を交換すると、局所的な方法でのみプレフィックスのバランスに影響する可能性があるということです。 プラスとマイナスの合計数は変更されず、順序のみが変更されます。 これは、スワップでシーケンスを修正できる唯一の方法は、プレフィックス合計の初期の不足を修正することであることを意味します。 

エッジ ケースは、シーケンスがすでに有効である場合、スワップでは修復できない単一のプレフィックス違反がある場合、およびローカル修正が存在するにもかかわらずグローバルな不均衡が深刻すぎる場合に発生します。 たとえば、「---+++」のような文字列は、何を置き換えても最初の文字がすでに有効性を失っているため、修正することは不可能です。 スワップでは、最初の位置が「-」になる可能性があるという事実を取り除くことはできません。 

もう 1 つの微妙なケースは、文字列が有効であるにもかかわらずダミー スワップ (i, i) を出力できる場合です。 多くのソリューションは、常に実際のスワップを実行する必要があると誤って想定しています。 

## アプローチ

 ブルートフォース手法では、インデックス i と j のすべてのペア (i = j を含む) を試し、それらを交換し、プレフィックスの合計を再計算することで結果のシーケンスが有効かどうかを確認します。 各妥当性チェックのコストは O(n) で、スワップは O(n²) 回あり、最悪の場合、テスト ケースごとに O(n³) になります。 有効性チェックを O(1) の増分更新に減らしても、依然として O(n²) が残り、これは合計 300,000 までの n にとって遅すぎます。 

重要な観察は、ほとんどのスワップを実際には気にしていないということです。 プレフィックスが無効になるのは、実行残高が初めてゼロを下回ったときだけです。 Let that first position be p. 位置 p には、その位置にあってはいけない「​​-」が配置されているはずです。 これを修正するには、後でどこかから '+' を取得し、それを p の前または前のセグメントに移動するか、問題のある '-' と同等に交換する必要があります。 

これにより、問題全体が、残高がマイナスになる最も早いプレフィックスを特定することに集約されます。 そのようなプレフィックスが存在しない場合、シーケンスはすでに有効です。 それ以外の場合は、最初の不良 '-' をその後のどこかの '+' に置き換えることによって修復を試みます。 正しさは、最初の違反のみが重要であり、その後の違反は同じ不均衡の結果であり、最初の違反が修正されれば解決されるという事実にかかっています。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 残高がマイナスになる最初の位置を追跡しながら、文字列にわたるプレフィックスの合計をシミュレートします。

1. Compute prefix balance while scanning from left to right, treating '+' as +1 and '-' as -1. If we never go below zero, the sequence is already valid and we output a trivial swap (1, 1). これは、修正が必要なく、問題により何も実行されないため機能します。 
2. If we find the first index p where the balance becomes negative, we stop immediately. This position is the earliest structural failure in the sequence, and any valid fix must address it directly.
 3. We identify the character at position p, which must be a '-'. The only way to fix this prefix is to swap this '-' with a '+' from some position q > p.
 4. We scan the suffix from p+1 onward to find any '+'. 何も存在しない場合は、赤字を修復するのに十分な早期にプラスの寄与を導入する方法がないため、-1 が出力されます。 
5. If we find such a position q, we output the swap (p+1, q+1) since indices are 1-based.

 最初の違反のみを考慮する理由は、プレフィックスの合計が局所的な修正に関して単調に動作するためです。 最初の負のプレフィックスが修正されると、その不足に依存していたその後のすべてのプレフィックスも修正されるか、非負になります。 

### なぜ効果があるのか

 各位置のプレフィックスの合計は、「+」と「-」の相対的な順序にのみ依存します。 The first time the prefix sum becomes negative identifies a structural imbalance where there are more '-' than '+' in a prefix. 有効なシーケンスでは、すべてのプレフィックスについて、「+」の数が少なくとも「-」の数であることを保証する必要があります。 

最初の無効な接頭辞 p には、許可されている数よりも 1 つ多い「-」が必ず必要になります。 単一のスワップを使用した唯一の可能な修正は、プレフィックス内の 1 つの「-」を「+」に置き換えることです。これにより、その時点以降のすべてのプレフィックスの合計が、逆方向のスワップと比較して厳密に 2 増加します。 位置 p を含まないスワップでは、プレフィックスが p ですでにゼロ未満になっているという事実を修正できません。 したがって、成功の必要条件は、p の後に「+」が存在し、それをプレフィックスに置き換えることで最初の違反が解決され、その後は以前の違反が存在しないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)

    bal = 0
    first_bad = -1

    for i, ch in enumerate(s):
        if ch == '+':
            bal += 1
        else:
            bal -= 1
        if bal < 0:
            first_bad = i
            break

    if first_bad == -1:
        print(1, 1)
        continue

    pos_plus = -1
    for j in range(first_bad + 1, n):
        if s[j] == '+':
            pos_plus = j
            break

    if pos_plus == -1:
        print(-1)
    else:
        print(first_bad + 1, pos_plus + 1)
```このソリューションでは、まず、実行残高を追跡することで、シーケンスがすでに有効であるかどうかを検出します。 マイナスになった瞬間に、そのインデックスを最も古い障害点として記録します。 

障害が存在しない場合は、ダミー スワップを返します。 文字をそれ自体と交換してもシーケンスは変更されないため、これは有効です。 

障害が発生した場合は、障害の後のサフィックスで「+」のみが検索されます。 その「+」を失敗した位置に置き換えると、失敗ポイントのプレフィックス合計が元に比べて 2 増加します。これは、最初の違反を除去するのに十分です。 

内部ロジックでは 0 から始まるインデックスが使用されるため、実装では出力での 1 から始まるインデックスについて注意が必要です。 

## 実用的な例

 ### 例 1

 入力:`-+`プレフィックスのバランスを追跡します。 

| 私 | 文字 | バランス | 最初の悪い |
 | --- | --- | --- | --- |
 | 0 | - | -1 | 0 |

 i = 0 では残高がマイナスになるため、first_bad = 0 となります。インデックス 0 以降を検索し、インデックス 1 で「+」を見つけます。位置 1 と 2 を交換すると、有効な「+-」が生成されます。 

これは、先頭にある 1 つの間違った「-」を、「+」を前に移動することでどのように修正できるかを示しています。 

### 例 2

 入力:`+--+`プレフィックススキャン:

 | 私 | 文字 | バランス | 最初の悪い |
 | --- | --- | --- | --- |
 | 0 | + | 1 | - |
 | 1 | - | 0 | - |
 | 2 | - | -1 | 2 |

 最初の違反はインデックス 2 で見つかります。次に、その後ろにある「+」を探し、インデックス 3 でそれを見つけます。それらを交換すると、次のようになります。`++- -`、これはプレフィックス シミュレーションでも有効です。 

これは、最初の失敗のみを考慮していることを示しています。 プレフィックスが修復されると、後の構造は自動的に修正されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 最初の違反を見つけるために 1 回スキャンし、'+' | をもう一度スキャンします。 
| スペース | お(1) | 少数の変数のみが保存されます。 

この解決策は合計入力サイズにおいて線形であり、合計 300,000 文字という制約を考慮するとこれが必要です。 どちらのパスも文字列を単純にスキャンするだけなので、十分に高速なソリューションが簡単に得られます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        n = len(s)

        bal = 0
        first_bad = -1

        for i, ch in enumerate(s):
            if ch == '+':
                bal += 1
            else:
                bal -= 1
            if bal < 0:
                first_bad = i
                break

        if first_bad == -1:
            out.append("1 1")
            continue

        pos_plus = -1
        for j in range(first_bad + 1, n):
            if s[j] == '+':
                pos_plus = j
                break

        if pos_plus == -1:
            out.append("-1")
        else:
            out.append(f"{first_bad+1} {pos_plus+1}")

    return "\n".join(out)

) == """1 1"""

 |`++ / -- / +-+-`|`1 1 / -1 / 1 3`| すでに有効、不可能、簡単な修正 |

 ## 特殊なケース

 文字列がすでに有効である場合、アルゴリズムは失敗分岐に入ることはありません。 出力`1 1`は no-op スワップを正しく表し、プレフィックスの有効性は変更されません。 

文字列が完全に「-」文字である場合、接頭辞の合計は最初のステップで負になり、後で置き換える「+」はありません。 スキャンでは有効なパートナーが見つからず、正しくは -1 が生成されました。 

最初の文字が '-' の場合、アルゴリズムはインデックス 0 の最初の違反を即座に識別します。その後、接尾辞の '+' のみを正しく検索し、後の冗長な障害ではなく、考えられる最も早い障害を直接修正のターゲットにします。
