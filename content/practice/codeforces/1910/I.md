 ## 問題の理解

 連続したブロックを繰り返し削除する文字列プロセスが与えられています。`k`文字列が短すぎて続行できなくなるまで、文字列を続けます。 削除は任意であるため、長さの最終的な結果はさまざまです。`r = n mod k`可能です。 考えられるすべての最終文字列の中で、辞書編集的に最小のものを選択し、それをプロセスの結果と呼びます。 

これでタスクが逆転しました。 削除をシミュレートする代わりに、次のことが与えられます。`n`、`k`、アルファベットのサイズ`c`、およびターゲット文字列`t`長さの`r`。 初期文字列の数を数えなければなりません`s`最初以上に`c`文字は、辞書編集的に達成可能な最小の最終文字列が正確に次のような状況を生成します。`t`。 

重要な問題は、削除が強制的または固定された方法で順次実行されるわけではないことです。 任意の長さの連続したセグメント`k`いつでも削除でき、さまざまな選択がグローバルな方法で相互作用します。 これは、最終結果が単一の貪欲な実行ではなく、文字列全体の構造特性に依存することを意味します。 

この制約により、文字列を列挙したり、削除シーケンスをシミュレートしたりするソリューションは不可能であることが明らかです。 と`n`最大 100 万の場合、文字列ごとの線形推論でも遅すぎるため、本質的に線形または線形に近いソリューションが必要です。`n`のみ多項式に依存する`c`または`k`完全に避けられてます。 

微妙なエッジケースは次のような場合です`k`に近いです`n`。 たとえば、次の場合`n = 7`そして`k = 6`の場合、削除できるのは 1 つだけです。 最後の文字列の長さは常に 1 ですが、どの 6 ブロックが削除されるかに応じて、残りの文字が変化する可能性があります。 素朴な解釈では、残りの文字は単に接尾辞または接頭辞の文字であると想定するかもしれませんが、実際には、選択した削除でカバーされない任意の位置である可能性があり、局所性推論が失敗していることがすでに示されています。 

もう 1 つの特殊なケースは、すべての文字が`t`は同一です。 それでも、いろいろと`s`辞書編集上の最小性は、等価性制約だけでなく、代替構造が任意の段階で厳密に小さい接頭辞を生成できるかどうかに依存するため、それを生成する場合と生成しない場合があります。

 ## アルゴリズムのチュートリアル

 私たちは定義します`r = n mod k`、これは最後の文字列の長さです。 

問題は文字列のカウントに帰着します`s`辞書編集上で達成可能な最小の長さになるように、`r`結果が等しい`t`。 重要な構造的事実は、辞書編集的に達成可能な最小の結果が貪欲な部分列構築のように動作するということです。システムは各位置で、有効な長さの完成を可能にしながら、効果的に可能な限り最小の次の文字を選択しようとします。`r`結果。 

この貪欲な制約を直接エンコードします。 

### ステップ

 1.文字列を処理します`s`概念的に辞書編集上で達成可能な最小の長さを構築しながら、左から右に -`r`続いて。 

各位置で、現在の文字がこのサブシーケンスの次の文字になることができるかどうかを決定します。 完了中に、代わりに小さな文字を使用できた場合`r`文字以降の場合、現在の選択は固定ターゲットの生成には無効​​になります。`t`。 
2. DP 状態を定義します`dp[i][j]`、最初の処理後の意味`i`文字、一致しました`j`の登場人物`t`達成可能な最小限の結果の強制プレフィックスとして。 

遷移は次の文字かどうかによって異なります。`x`で`s`こうなるだろう:

 - 一致`t[j]`、一致したプレフィックスを進めることができます、または
 - より大きいこと`t[j]`この場合、同じ状態が維持されるか、または
 - より小さいこと`t[j]`、これは、辞書編集的に達成可能な最小の結果が正確に次であるという要件に違反します。`t`。 
3. 各ポジションについて、DP を有効に保つ文字の選択肢の数を数えます。 これは、アルファベットの遷移に関する制限されたカウント問題になります。 
4. プレフィックス DP を使用して位置全体の寄与を乗算し、以前の偏差によって辞書順に小さいサブシーケンスが生成されないようにします。`t`。 
5. 最終的な答えは、長さの完全な文字列の数です。`n`DP の一貫性を維持し、強制的な構築マッチングで終了する`t`。 

### なぜ効果があるのか

 不変条件は、構築された文字列のすべてのプレフィックスで、DP 状態が、長さまで完成できる辞書編集上の最小のサブシーケンスを表すことです。`r`許可された削除構造の下で。 どこかの時点でプレフィックスが`t`が達成可能になると、その接頭辞が最終的な辞書編集上の最小結果を支配し、文字列が不適格になります。 したがって、有効な文字列とは、まさに貪欲な構造をロックし続ける文字列です。`t`あらゆる段階で。 

これにより、グローバルな組み合わせプロセス (任意の削除) がローカルなプレフィックス制約システムに変換され、動的プログラミングが適用できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k, c = map(int, input().split())
    t = input().strip()
    r = n % k

    # We model DP over positions and matched prefix length of t.
    # dp[j] = number of ways after current prefix with j matched characters.
    dp = [0] * (r + 1)
    dp[0] = 1

    # Precompute transitions: at each step we try all letters.
    # We enforce that we never create a prefix smaller than t.
    for _ in range(n):
        ndp = [0] * (r + 1)
        for j in range(r + 1):
            if dp[j] == 0:
                continue

            for ch in range(c):
                if j < r:
                    tc = ord(t[j]) - 97
                    if ch < tc:
                        continue
                    elif ch == tc:
                        ndp[j + 1] = (ndp[j + 1] + dp[j]) % MOD
                    else:
                        ndp[j] = (ndp[j] + dp[j]) % MOD
                else:
                    ndp[j] = (ndp[j] + dp[j]) % MOD

        dp = ndp

    print(dp[r] % MOD)

if __name__ == "__main__":
    solve()
```DP は、構築された文字列がターゲットとどのように一致するかを追跡します。`t`強制的に辞書編集的に達成可能な最小の部分列として。 各文字の選択は、一致を進めるか保存するか、許可されているよりも小さいプレフィックスが作成される場合は破棄されます。 

重要な実装の詳細は、現在必要な文字よりも小さい文字を厳密に拒否することです。`t`試合が終わる前に。 これは、辞書編集上の最小性をグローバルに強制するものです。

 ## 特殊なケース

 主なエッジケースは次のような場合です`r = 1`、最後の文字列は常に 1 文字であることを意味します。 この場合、問題は、以下に等しい辞書編集上で達成可能な最小の文字を持つ文字列がいくつあるかを数えるということになります。`t[0]`。 DP は正確に、削除されても生き残る可能性のある位置に小さな文字が決して出現しないことを保証し、全体的な最小制約を効果的に強制します。 

もう 1 つのエッジケースは次のような場合です`k = n - 1`、これにより、`r = 1`繰り返しになりますが、削除の柔軟性が最大限に高まります。 多くの文字列は同じ最小の結果に折りたたまれます。DP は、たとえ「安全な」位置に一度でも小さな文字を導入する文字列を過剰にカウントしてはなりません。 

最後に、すべての文字が`t`が等しい場合、DP はすべてのステップで等価遷移を許可しますが、より小さい文字を早期に導入する分岐は拒否します。 これにより、対称性が非常に高い場合でも、正確な辞書編集上の最小構造に寄与する有効な構造のみがカウントされることが保証されます。
