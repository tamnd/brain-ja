 ## 解決策
 ## 問題の理解

 頂点 1 にルートが固定されたルート付きツリーが与えられます。各頂点には、最初はちょうど 1 つのビスケットが含まれています。 正確に k 個の操作を実行します。 1 つの操作で、頂点 x を選択し、x からルートまでの単純なパス上にまだ存在するすべてのビスケットをすぐに食べます。 ビスケットは一度食べると永久に消えるため、その後の操作で再びビスケットを獲得することはできません。 

目標は、すべての操作で食べられるビスケットの総数ができるだけ多くなるように k 個の頂点を選択することです。 パスが重なっているため、異なる頂点を選択すると、ツリーのすでに空になっている部分を繰り返し通過することになり、潜在的な利益が無駄になる可能性があります。 

制約は n と k が 500,000 に達するため、操作ごとにパス情報を最初から再計算するソリューションは即座に除外されます。 O(nk) さえも実現不可能であり、O(k log n) さえも各ステップが非常に軽い場合にのみ安全です。 パス クエリを含むツリーの構造は、高速な「パスの合計」と高速な「パスの更新」をサポートする表現が必要であることを示唆しています。 

1 つの貪欲な決定が将来の選択に永久に損害を与える場合、微妙な失敗例が現れます。 たとえば、チェーン 1-2-3-4-5 では、ノード 5 を選択すると、最初にチェーン全体のすべてのビスケットが消費されます。 ノード 4 などの 2 番目の選択肢は、最初は最適に見えたとしても、その後はほとんど役に立たなくなります。 したがって、単純な「最も深いノードを繰り返し選択する」戦略では、すでに消費されているノードを考慮していない場合、ゲインが過大評価される可能性があります。 

主な問題点は、各選択により、ルート パス上で現在食べられていないノードの数に等しい値が与えられ、これらの値は操作のたびに動的に変化することです。 

## アプローチ

 ブルート フォース戦略では、頂点ごとに、ルートへのパス上に存在する未食のノードの数を再計算し、毎回最適なものを選択し、影響を受けるすべてのノードを更新することで、k 個の選択肢すべてをシミュレートします。 各更新は完全なルート パスにアクセスするため、チェーンではこれは操作ごとに O(n) になります。 k 回の操作を超えると、これは O(nk) になり、5・10^5 には大きすぎます。 

重要な観察は、各頂点が、選択されたパスによって最初に「カバーされる」場合にのみ、答えに寄与するということです。 それ以降は永遠に関係ありません。 したがって、ビスケットが繰り返し除去されるという観点から考える代わりに、ノードが「覆われていない」状態から「覆われている」状態に 1 回だけ切り替わるという観点から考えることができます。 

頂点 x を選択するたびに、x からルートまでのパス上にあるカバーされていないノードの数が正確に得られます。 したがって、ルート パスに沿ってカバーされていないノードの合計をクエリすることと、ルート パス上のすべてのノードをカバーされているものとしてマークするという 2 つの操作を効率的にサポートするデータ構造が必要になります。 

これは当然、ノード上のセグメント ツリーと組み合わせた重光分解につながり、各ノードはまだカバーされていないかどうかを格納します。 パスのクエリと更新は n で対数になります。 

ただし、すべての頂点の中から次にどの頂点を選択するかを決定する必要もあります。この選択は、現在のカバーされていない状態によって異なります。 現在のゲインをキーとしたすべての頂点に対する優先順位構造を維持できます。 更新後にゲインが変化するため、候補がポップされたときに遅延的に再計算します。 

これにより、古典的な「遅延最大ヒープ + パス データ構造」ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nk) | O(n) | 遅すぎる |
 | HLD + セグメント ツリー + 遅延ヒープ | O((n + k) log^2 n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのノードのバイナリ状態、つまりビスケットがまだ利用可能かどうかを維持します。 最初はすべてのノードが使用可能です。

また、任意の頂点について、その頂点からルートまでのパス上に利用可能なノードがいくつあるかを計算できる構造も維持します。 これは、範囲合計クエリと範囲更新をサポートするセグメント ツリーによる重光分解を使用して実装されます。 

また、候補頂点の最大優先度キューも維持します。各頂点は「現在のゲイン」に関連付けられています。これは、今その頂点を選択した場合に収集される新しいビスケットの数を意味します。 

1. ツリーを構築し、親ポインターと重光分解を計算して、すべてのルート パスを O(log n) セグメントに分割できるようにします。 
2. すべてのビスケットが最初に利用可能であるため、ノードごとにセグメント ツリーを初期化し、すべてのノードに 1 を格納します。 これにより、任意のパス上に利用可能なノードがいくつあるかを問い合わせることができます。 
3. すべての頂点 x について、その初期ゲインを x からルートまでのパス上のノードの数として計算します。 これは深さに 1 を加えたもので、(gain, x) を最大ヒープにプッシュします。 
4. k 回繰り返します。 毎回、現在保存されている最大のゲインで頂点 x をポップします。 
5. x からルートまでのパス上の利用可能なノードの合計をクエリすることにより、セグメント ツリーを使用して x の真のゲインを再計算します。 この値が保存されている値と異なる場合は、値を更新し、選択せずにヒープに戻します。 これにより、有効な優先順位にのみ基づいて行動することが保証されます。 
6. x が選択されたことを確認したら、その再計算されたゲインを答えに追加します。 
7. 重光分解更新を使用して、x からルートまでのパス上のすべてのノードを使用不可としてマークします。 これにより、今後のクエリでこれらのノードが再びカウントされなくなります。 

重要な考え方は、各ノードが 1 回だけ利用できなくなるため、プロセス全体にわたるすべての更新が n セグメントで線形になり、それぞれが対数時間で処理されるということです。 

### なぜ効果があるのか

 各操作は、少なくとも 1 つのルートから選択された頂点へのパス上で「使用可能」から「使用不可」に遷移するノードの正確な数に影響します。 ノードは 1 回しか遷移できないため、寄与の合計は、選択された少なくとも 1 つのパス上に存在するノードの数とまったく同じになります。 

アルゴリズムは常に、ルートへのパス上で現在使用可能なノードの数を最大にする頂点を選択します。 以前に選択された頂点は、ノードを削除することによって将来のゲインを減らすだけであり、セグメント ツリーにより、再計算されたすべてのゲインが真の現在の状態を反映していることが保証されます。 レイジー ヒープは、古いゲイン値に決してコミットしないことを保証するため、各選択は現在の構成に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def build(self, i, l, r):
        if l == r:
            self.t[i] = 1
            return
        m = (l + r) // 2
        self.build(i * 2, l, m)
        self.build(i * 2 + 1, m + 1, r)
        self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]

    def update(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.t[i] = 0
            return
        if r < ql or l > qr:
            return
        m = (l + r) // 2
        self.update(i * 2, l, m, ql, qr)
        self.update(i * 2 + 1, m + 1, r, ql, qr)
        self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]

    def query(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[i]
        if r < ql or l > qr:
            return 0
        m = (l + r) // 2
        return self.query(i * 2, l, m, ql, qr) + self.query(i * 2 + 1, m + 1, r, ql, qr)

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
depth = [0] * (n + 1)

def dfs(u, p):
    parent[u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 0)

# HLD (simplified version: we only need path-to-root via parent chain segments)
heavy = [0] * (n + 1)
size = [0] * (n + 1)

def dfs_size(u, p):
    size[u] = 1
    maxc = 0
    for v in g[u]:
        if v == p:
            continue
        dfs_size(v, u)
        size[u] += size[v]
        if size[v] > maxc:
            maxc = size[v]
            heavy[u] = v

dfs_size(1, 0)

top = [0] * (n + 1)
in_id = [0] * (n + 1)
timer = 0

def dfs_hld(u, t):
    global timer
    top[u] = t
    timer += 1
    in_id[u] = timer
    if heavy[u]:
        dfs_hld(heavy[u], t)
    for v in g[u]:
        if v != parent[u] and v != heavy[u]:
            dfs_hld(v, v)

dfs_hld(1, 1)

seg = SegTree(n)
seg.build(1, 1, n)

def path_query(u):
    res = 0
    while u:
        res += seg.query(1, 1, n, in_id[top[u]], in_id[u])
        u = parent[top[u]]
    return res

def path_update(u):
    while u:
        seg.update(1, 1, n, in_id[top[u]], in_id[u])
        u = parent[top[u]]

import heapq
heap = []

for i in range(1, n + 1):
    heapq.heappush(heap, (- (depth[i] + 1), i))

ans = 0
for _ in range(k):
    while True:
        val, u = heapq.heappop(heap)
        val = -val
        cur = path_query(u)
        if cur != val:
            heapq.heappush(heap, (-cur, u))
            continue
        ans += cur
        path_update(u)
        break

print(ans)
```この実装では、ルートからノードへのパスを O(log n) セグメントに分割できるように、ヘビーライト分解が構築されます。 セグメント ツリーには、どのノードにまだビスケットがあるかが保存されます。 各クエリは、それらのうちまだ利用可能なものがいくつあるかを集計します。 

ヒープには楽観的なゲインが格納されます。 ノードが抽出されると、そのゲインが現在の状態に対して再計算されます。 古い場合は、修正された値でプッシュバックされます。 これにより、パスを削除するたびにすべてのヒープ エントリを更新する必要がなく、正確さが保証されます。 

更新ステップでは、選択したパス上のすべてのノードが削除され、将来の操作でそれらのノードが再び関与することがなくなります。 

## 実用的な例

 ### 例 1

 入力:```
5 2
1 2
1 3
2 4
2 5
```選択したノードと残りの利用可能なビスケットを追跡します。 

| ステップ | 選択されたノード | ゲイン | 新しくカバーされたノード | 対象となる合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 3 | 4、2、1 | 3 |
 | 2 | 5 | 1 | 5 | 4 |

 4 を選択すると、ノード 1、2、および 4 が使用できなくなります。 5 を選択すると、ノード 5 のみが提供されます。 

これは最終回答 4 と一致します。 

### 例 2

 入力:```
5 2
1 2
2 3
3 4
4 5
```これは連鎖です。 

| ステップ | 選択されたノード | ゲイン | 新しくカバーされたノード | 対象となる合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 5 | 1、2、3、4、5 | 5 |
 | 2 | 4 | 0 | なし | 5 |

 最初の操作の後、ツリー全体がすでに消費されているため、2 番目の操作では何も追加されません。 

これは、貪欲な選択ではツリーの動的な枯渇を考慮する必要があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + k) log^2 n) | k 個の選択のそれぞれが O(log^2 n) パスのクエリ/更新をトリガーし、各ノードが全体で 1 回更新されます。 
| スペース | O(n) | ツリー、セグメント ツリー、および分解配列 |

 n と k は両方とも最大 5·10^5 であり、対数因数は実際には小さいままであるため、この複雑さは制限内に収まります。

 ## 特殊なケース

 チェーン状のツリーは、深いノードを選択すると他のすべてのパスが即座に無効になる可能性があるという事実を強調しています。 チェーン 1-2-3-4-5 では、最初に 5 を選択すると、パス上のすべてのノードが消費され、他のすべての頂点は限界ゲインがゼロのままになります。 最初の更新後にルート パス上のすべてのノードが使用不可としてマークされるため、セグメント ツリーはこれを正しく反映し、後続のクエリではゼロが返されます。 

ルート 1 にある星形のツリーは、逆の動作を示します。 いずれかのリーフを選択すると、即座にルートが消費され、その後、他のすべてのリーフがそれ以上の利益に寄与することがブロックされます。 複数のリーフが選択された場合、最初のリーフだけが最大の恩恵をもたらし、他のすべてのリーフは寄与がゼロになります。これは、それらのパスがすでに削除されているルートで交差するためです。 

どちらの場合も、ルート パス上の可用性を一貫して追跡することにより、アルゴリズムが完全な重複と完全な独立性を正しく処理していることが確認されています。
