 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、1 から 1 までのすべての整数を意味します。$n$は 1 回だけ表示されます。 インデックスのペアごとに$(l, r)$から配列のセグメントを調べます。$l$に$r$。 エンドポイントの値が次のようなセグメントのみをカウントしたいと考えています。$p_l$そして$p_r$、すでにセグメント全体を「制御」しています。セグメント内のすべての要素は、2 つのエンドポイントのうち小さい方と大きい方の間に位置する必要があります。 

言い換えると、2 つのエンドポイントの最小値と最大値を取得する場合、それらの間の部分配列全体がその数値間隔内に収まる必要があります。 セグメント内の要素は、エンドポイントによって定義された範囲の外に出ることはできません。 

単純な解釈では、すべてのセグメントを考慮し、エンドポイントの境界に違反する要素があるかどうかを検証します。 と$n$まで$5 \cdot 10^5$、約あります$2.5 \cdot 10^{11}$セグメントがあり、それぞれを線形時間でチェックすることさえ不可能です。 たとえ$O(n^2)$メソッドはすでに大きすぎます。 

微妙な点は、この条件は端点の値の極値のみに依存しますが、それでもすべての内部要素を制約することです。 これは、エンドポイントが「十分に極端」であるため、中間要素がその値の間隔から逃れられないセグメントを実際にカウントしていることを示唆しています。 

単純な罠は、隣接するセグメントまたは単調なセグメントのみが重要であると想定することです。 たとえば、次のような順列では、$1\ 3\ 2\ 4\ 5$、セグメント$(1,5)$は、すべての内部値が 1 から 5 の間にあるため、単調でなくても有効です。$(2,4)$一部の内部値がエンドポイントの範囲外にある場合、失敗する可能性があります。 

問題はグローバルです。すべてのセグメントはすべての中間値に依存するため、すべてのペアの最小値と最大値の再計算を回避する方法が必要です。 

## アプローチ

 ブルートフォースの解決策は簡単です。 各ペアごとに$(l, r)$、部分配列の最小値と最大値を計算します。$p[l:r]$またはセグメントをスキャンして、要素が外側にあるかどうかを確認します$[\min(p_l, p_r), \max(p_l, p_r)]$。 これは条件を直接検証するため機能しますが、次のいずれかが必要です。$O(n^3)$極値を単純に再計算する場合の時間、または$O(n^2)$開始インデックスごとの実行最小値と最大値を維持する場合。 と$n = 5 \cdot 10^5$、 平$O(n^2)$約につながる$2.5 \cdot 10^{11}$限界をはるかに超えた操作。 

重要な観察は、エンドポイントによって定義されたセグメントからバリアとして機能する要素に視点を移すことです。 たとえば、1 つのエンドポイントを修正する$l$。 拡大するにつれて$r$外側では、セグメントは、によって定義された範囲外の値に遭遇するまで有効です。$p_l$そして$p_r$。 問題は、範囲自体が変化することです。$r$, so this still feels circular.

 中間要素によって課される順序制約の観点から考えると、実際の構造がより明確になります。 セグメント$(l, r)$インデックスが存在する場合は無効です$i \in (l, r)$そのような$p_i < \min(p_l, p_r)$または$p_i > \max(p_l, p_r)$。 これは、すべての内部要素が間隔のエンドポイントで「カバー」される必要があることを意味します。 

これは、すべての内部位置について、エンドポイント値が値空間内でその位置をまたがる必要があると言うのと同じです。 各内部要素は、特定のエンドポイントのペアを効果的に禁止します。内部値が非常に小さいか非常に大きい場合、どのエンドポイントがその周囲に有効なペアを形成できるかが制限されます。 

これを再構成する生産的な方法は、ポジションを値の昇順に処理することです。 値を固定するとき$x$、インデックス空間内で「またがる」ペアを制限します。 具体的には、すべての値が以下であるか大きいかがわかっている場合、$x$嘘です、の両側に端点を持つペアが何組あるかを決定できます。$x$、次の場合を除き、有効性に違反します。$x$エンドポイント値の範囲内にあります。 

これは、古典的な反転スタイルのカウントのアイデアにつながります。各要素は、その両側にある小さい/大きい要素の数に応じて、無効なペアに寄与します。 セグメントをチェックする代わりに、トリプルの数を数えます。$(l, r, i)$違反を引き起こし、合計ペアから減算します。 

インデックスの合計ペアは$n(n+1)/2$。 エンドポイントの範囲外にある内部ポイントが存在する場合、ペアは無効です。これは、禁止された方法で交差するペアの「セパレーター」として機能する各要素を介してカウントできます。 フェンウィック ツリー (または BIT) 内の位置を追跡することで、各側で確認された値の数を維持し、寄与を効率的にカウントできます。 

最終的な解決策は、値を順番に処理し、その位置に関して作成された反転の数をカウントすることです。各要素は、その左右にあるすでに処理された要素の数に基づいて寄与します。

 ## アルゴリズムのチュートリアル

 値の昇順に順列を処理し、各値を「アクティブ」になった瞬間として扱います。 

1. 各値をその位置に配置し、どの位置がすでにアクティブ化されているかを追跡するデータ構造を維持します。 最初はアクティブなポジションはありません。 これにより、どの値が現在の値より小さく、すでに処理されているかをいつでも知ることができます。 
2. 値を加工する場合$x$位置にある$pos[x]$、インデックスを介してフェンウィック ツリーに挿入します。 この構造により、インデックスの左側または右側に既に挿入されている位置がいくつあるかを効率的に数えることができます。 
3. 現在の位置について$pos[x]$、以前に処理された位置が左側にいくつあるか、右側にいくつあるかを計算します。 これらをそのままにしておきます$L$そして$R$。 これらは、以下の値に対応します。$x$それらの地域にはすでに配置されています。 
4. によって導入された新しい無効なペアの数$x$は$L \cdot R$。 これは、左側と右側で 1 つの小さな要素を選択し、挟み込むエンドポイントを形成することから生まれます。$x$彼らの範囲外です。 
5. これらの寄与をすべての値にわたって累積します。 無効な構成の合計数は、そのような製品すべての合計です。 
6. インデックスの合計ペアを取得し、無効な寄与を差し引くことにより、最終的な答えに変換します。 

### なぜ効果があるのか

 各要素$x$エンドポイントがその位置の反対側にあるペアの一意の最小または最大バリアとして機能します。 エンドポイントがまたがる場合$x$インデックス順ですが、$x$が値の順序でそれらの間にない場合、条件はそのペアに対して 1 回だけ失敗します。 値は昇順に処理されるため、このような違反はすべて、エンドポイント間隔を壊すスパン内の最小要素に正確に起因すると考えられます。 これにより、ペアが二重にカウントされたり、無効なペアが見逃されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, v in enumerate(p, 1):
    pos[v] = i

fw = Fenwick(n)

ans = 0

for v in range(1, n + 1):
    i = pos[v]
    left = fw.sum(i - 1)
    right = fw.sum(n) - fw.sum(i)
    ans += left * right
    fw.add(i, 1)

total_pairs = n * (n + 1) // 2
print(total_pairs - ans)
```フェンウィック ツリーは、現在の値よりも小さい値がすでに配置されている数を維持します。 各ステップで、現在の値は、そのような小さい値がその左側と右側にいくつあるかに基づいて寄与します。これらの値は、この値が内部違反ポイントとして機能する条件を満たさないエンドポイント ペアを形成するためです。 

最後の減算ステップでは、計算された無効なカウントを有効なセグメントの必要な数に変換します。

 ## 特殊なケース

 単一要素の置換の場合、有効なセグメントは次のとおりです。$(1,1)$。 アルゴリズムは最初の値を挿入し、左右の寄与を見つけずに出力します。$1$無効なペアを合計から差し引いた後。 

完全に増加または減少する順列の場合、処理中に両側に小さい要素を持つ値は存在しないため、すべての寄与はゼロのままになります。 結果は満額になります$n(n+1)/2$これは、すべてのセグメントがモノトーン構造の下で有効であるという事実と一致します。
