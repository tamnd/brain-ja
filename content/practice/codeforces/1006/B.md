 ## 解決策
 ## 問題の理解

 一連の問題の難易度が固定された順序で与えられているため、この一連の課題を正確に分割する必要があります。`k`連続したセグメント。 各セグメントは 1 日の練習に対応し、すべての問題は 1 つのセグメントに属している必要があります。 制限は、1 日内で問題を並べ替えたり、スキップしたり、分割したりすることはできないため、毎日、配列の連続した部分を左から右に取得することです。 

その日のスコアは、選択したセグメント内の最大難易度として定義されます。 目標は、どこに配置するかを選択することです。`k - 1`セグメントの最大値の合計ができるだけ大きくなるようにカットします。 

これは、配列の固定順序に関する分割の問題であり、大きな値をグループ化するか、別々のセグメントに分離するかの間でトレードオフが行われます。 

制約は十分に小さいため、二次動的計画法やさらには三次動的計画法も実行可能です。 と`n ≤ 2000`、`O(n^2 k)`または`O(n^2)`解決策は受け入れられます。 およそ数億回の操作よりも悪いものはすべて危険ですが、プレフィックス計算を備えた古典的な DP は快適に適合します。 

貪欲に考えると、微妙な問題が発生します。最大の値を取得してすぐに分離することは、常に機能するとは限りません。大きな値がすでにセグメントを支配している可能性があり、分割が早すぎると、後で他の大きな値に対する柔軟性が低下する可能性があるためです。 

もう 1 つの一般的なエッジケースは次のような場合です。`k = 1`。 この場合、カットは許可されず、答えは単純に配列全体の最大値になります。 反対の極端な場合、`k = n`、すべての要素は独自のセグメントであり、答えはすべての要素の合計です。 正しい解決策は、再構成時に特別なケースエラーを発生させることなく、両方の極端な問題を自然に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な方法で配置を試みます。`k - 1`間のカット`n - 1`ギャップ。 各パーティションについて、セグメントの最大値を計算し、それらを合計します。 カットを選択する方法の数は指数関数的に増えています`n`、 だいたい`C(n-1, k-1)`, これは、中程度の値であっても天文学的に大きくなります。`n`。 たとえ単一のパーティションの評価に直線的な時間がかかるとしても、このアプローチは実行不可能です。 

重要な観察は、問題には最適な部分構造があるということです。最後のセグメントが 位置で終わると決定すると、`i`、プレフィックスに対する最良の回答`1..i`セグメントが少ない場合は、サフィックスをどのように分割するかには依存しません。 これはすぐに動的プログラミングを示唆します。 

処理した要素の数と形成したセグメントの数に基づいて状態を定義します。 新しいセグメント境界に移行するには、最後のセグメントの最大値を知る必要があります。これは、セグメントを後方に拡張することでオンザフライで計算できます。 これにより、パーティションごとに最大値を最初から再計算する必要がなくなります。 

完全なパーティションを列挙する代わりに、ソリューションを段階的に構築します。エンドポイントごとに、考えられるすべての以前のカット位置を試し、すでに計算された DP 値を再利用します。 これにより、パーティションにわたる指数関数的な検索の問題が、間隔にわたる二次 DP に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | インターバルDP | O(n² · k) | O(n · k) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは定義します`dp[i][j]`最初のパラメータを使用して得られる最大合計利益として`i`要素が正確に分割される`j`セグメント。 

1. DP テーブルを非常に負の値で初期化します。`dp[0][0] = 0`。 This represents having processed nothing with zero segments and zero profit.
 2. ポジションごとに`i`から`1`に`n`、および可能なすべてのセグメント数について`j`から`1`に`k`、最後のセグメントを次で終了することを検討します。`i`。 
3. To form the last segment, we try all possible previous cut positions`p`、最後のセグメントは次から始まります`p + 1`そしてで終わります`i`。 For each such choice, we compute the maximum value in`a[p+1..i]`。 
4. 移動中も最大値を維持します`p`から後ろ向きに`i`に`1`。 This allows us to compute segment maxima in amortized O(1) per extension instead of recomputing from scratch.
 5. それぞれについて`(p, i)`ペア、更新します`dp[i][j] = max(dp[i][j], dp[p][j-1] + max(a[p+1..i]))`。 
6. テーブルに記入したら、`dp[n][k]`最適な答えが含まれています。 
7. パーティション サイズを再構築するには、次のようにバックトラックします。`(n, k)`各セグメントが終了した場所から回復します。 カット位置を見つけるたびに`p`最適な値を達成した場合、セグメント長を記録します`i - p`そして続きから`(p, j-1)`。 

機能する理由: すべての有効なパーティションは最後のセグメントで終わる必要があります`[p+1..i]`。 DP は、そのような末尾の可能性をすべて列挙し、それぞれについて、プレフィックスの最適なパーティションを個別に付加します。 最後のカットが修正されると、以前の決定は最終セグメントの最大値に影響を与えず、以前のすべての寄与はすでに最適に解決されているため、独立性が維持されます。`dp[p][j-1]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    NEG = -10**18
    
    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    parent = [[-1] * (k + 1) for _ in range(n + 1)]
    
    dp[0][0] = 0
    
    for i in range(1, n + 1):
        for j in range(1, k + 1):
            mx = 0
            # try all possible starts of last segment
            for p in range(i - 1, -1, -1):
                if j - 1 <= p:
                    if p > 0 and dp[p][j - 1] == NEG:
                        continue
                    if p == 0 and j - 1 != 0:
                        continue
                    
                    mx = max(mx, a[p])
                    val = dp[p][j - 1] + mx
                    if val > dp[i][j]:
                        dp[i][j] = val
                        parent[i][j] = p
    
    # reconstruct
    res = []
    i, j = n, k
    
    while j > 0:
        p = parent[i][j]
        res.append(i - p)
        i = p
        j -= 1
    
    res.reverse()
    
    print(dp[n][k])
    print(*res)

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i][j]`プレフィックスの達成可能な最良の合計を最大で保存します`i`に分割する`j`セグメント。 ネストされたループオーバー`p`最大値を維持しながら最後のセグメントを後方に拡張します`mx`したがって、セグメント最大値を最初から再計算することはありません。 

の`parent`テーブルには、最後のセグメントが開始された場所が記録されます。 これが必要なのは、DP のみが構造ではなく値のみを保存するためです。 再建中、私たちは何度もそこから飛び降ります。`(i, j)`に`(p, j-1)`この表を使って。 

インデックス作成には注意が必要です。`a[p]`使用される理由は`p`開始インデックスを 0 から始まる形式で表します。`i`DP では 1 から始まります。 これらの規則を誤って混合すると、off-by-one エラーの一般的な原因になります。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
8 3
5 4 2 6 5 1 9 2
```構築のための重要な DP の決定をいくつか追跡します。`dp[8][3]`。 

### 8 で終わる最終セグメントの DP トランジション

 | p | セグメント [p+1..8] | 最大 | dp[p][2] | 合計 |
 | --- | --- | --- | --- | --- |
 | 5 | 6 1 9 2 | 9 | ベスト(dp[5][2]) | 候補者 |
 | 6 | 1 9 2 | 9 | dp[6][2] | 候補者 |
 | 7 | 9 2 | 9 | dp[7][2] | 候補者 |

 最適な分割は、`9`これは、それを含む接尾辞よりも優先されるためです。 

最終的には次のようなパーティションを再構築します。`[5,4,2] [6,5] [1,9,2]`。 

これは、最適なカットではセグメント内で希釈される大きなピークを分離する傾向があることを示しています。 

次に、より小規模な構築例を考えてみましょう。```

1 100 2 3 4
```最善の戦略は隔離することです`100`独自のセグメントに分割します。 

| p | セグメント [p+1..5] | 最大 | dp[p][1] | 合計 |

 | 1 | 100 2 3 4 | 100 | dp[1][1] | 100 + 1 |
 | 2 | 2 3 4 | 4 | dp[2][1] | もっと悪い |
 | 3 | 3 4 | 4 | dp[3][1] | もっと悪い |

 ## 特殊なケース

 いつ`k = 1`、DP は決して分割されず、配列全体が 1 つのセグメントとして扱われます。 アルゴリズムは当然、からの遷移のみを評価します。`p = 0`に`i = n`、全範囲にわたって最大の要素が生成され、これが正解と一致します。 

いつ`k = n`、すべての位置が独自のセグメントを形成する必要があります。 DP はユニット移行を強制されます。`p = i - 1`、個々の要素に等しいセグメント最大値が生成されます。 再構成により、すべてのセグメント サイズが次のように得られます。`1`、要件に正しく一致しています。 

すべての値が等しい場合、すべてのパーティションは同一のセグメント最大値を持つため、DP は任意のカット位置を選択できます。 すべての遷移が等しい値を生成し、アルゴリズムは正確さに影響を与えることなくそれらの 1 つを一貫して記録するため、親の再構成でも有効なセグメンテーションが生成されます。
