 ## 解決策
 ## 問題の理解

 一列に並んだ一連の数字が与えられているので、この行を 3 つの連続するセグメントに切り分けたいと考えています。 最初のセグメントは先頭から始まり、2 番目のセグメントは中央に位置し、3 番目のセグメントは最後の要素で終了します。 これらのセグメントの一部は空にすることができます。つまり、要素を取得せずに境界でカットが発生する可能性があります。 

重要なのは、最初のセグメント内の値の合計と 3 番目のセグメント内の値の合計です。 これら 2 つの合計が等しくなるようにしたいのですが、配列を切り取る有効な方法の中で、共通の合計の可能な最大値が必要です。 

入力サイズは 20 万要素に達する可能性があるため、3 つのセグメントすべてに対して考えられるすべてのカット位置を個別に試行するソリューションは即座に除外されます。 三重にネストされた列挙は、n の 3 乗のオーダーの可能性を意味しますが、これは実現可能性をはるかに超えています。 カットポイントをまたぐ二重ループであっても、各クエリが一定時間または対数時間で処理される場合にのみ許容されるため、線形または線形に近い解決策が期待されるはずです。 

微妙な点は、空のセグメントが許可されていることです。 これにより、一致する合計の一方または両方がゼロになる可能性がある特殊なケースが発生します。 たとえば、すべての数値が正の場合、外側のセグメントを両方とも空にするという単純な解決策は常に機能し、答えは 0 になりますが、より適切な分割が存在する可能性があります。 最適な構成で非常に小さなプレフィックスおよびサフィックス セグメントが使用される場合、別のエッジ ケースが発生します。そのため、中央付近のみを検索したり、バランスのとれた分割を想定したソリューションは失敗します。 

素朴なアプローチは、次のような場合に失敗することがよくあります。`[1,2,3,2,1]`。 最良の答えは 4 ですが、プレフィックスとサフィックスを段階的に一致させようとする貪欲なアプローチでは、プレフィックスの合計をより小さくすることに早期にコミットし、より大きな一致するサフィックスを見逃す可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、2 つのカットポイントが選択されます。`a`そして`b`、最初のセグメントを次のように定義します`[0..a]`、2番目として`[a+1..b]`、3番目は次のようになります`[b+1..n-1]`。 各ペアについて、最初と 3 番目のセグメントの合計を計算し、等しいかどうかを確認します。 これにはペアごとに O(n) の作業が必要で、O(n²) 個のペアがあるため、O(n³) 時間がかかります。 プレフィックス合計によってセグメント合計の計算が O(1) に削減されたとしても、二重ループでは依然として O(n²) が発生し、これは 200,000 個の要素にとって遅すぎます。 

重要な観察は、中間セグメントは連続性を確保すること以外は無関係であるということです。 接頭辞の合計を選択したら、それから切り離された同じ合計を持つ接尾辞が存在するかどうかだけを気にします。 これにより、問題は、プレフィックスの合計とサフィックスの合計の両方として重複せずに現れる最大値を見つけることに変換されます。 

すべてのプレフィックスの合計を事前に計算できます。 次に、サフィックスの合計を維持しながら右からスキャンします。 すべての位置で、現在のサフィックスの合計が、サフィックスが始まる前に厳密に終了するプレフィックスの合計として表示されているかどうかを確認します。 正確性を効率的に保証するために、2 ポインタ スタイルのトラバーサルを使用します。1 つのポインタは左側の累積プレフィックス合計候補から移動し、もう 1 つは右側の累積サフィックス合計候補から移動します。 次に、順序の制約を維持しながら、それらを貪欲に一致させようとします。 

これが機能するのは、プレフィックスの合計とサフィックスの合計の両方が累積で単調に変化し、任意の部分配列の合計ではなく累積値が等しいことを検索しているためです。

 ## アルゴリズムのチュートリアル

 2 つのポインター (1 つは左から始まり、もう 1 つは右から始まります) と、現在のプレフィックス合計とサフィックス合計を表す 2 つの現在の合計を維持します。 

1.初期化`i = 0`、`j = n - 1`、`left_sum = 0`、`right_sum = 0`、 そして`answer = 0`。 

ポインタは、プレフィックス セグメントとサフィックス セグメントの境界候補を表します。 
2. その間`i <= j`、和の小さい方を拡張します。 

もし`left_sum`それより小さいか等しい場合、追加します`d[i]`に`left_sum`そして移動します`i`フォワード。 それ以外の場合は追加します`d[j]`に`right_sum`そして移動します`j`後ろ向きに。 

このバランスにより、有効なアライメントをスキップすることなく、可能なイコライゼーション ポイントをすべて探索できるようになります。 
3. 拡張するたびに、次のことを確認します。`left_sum == right_sum`。 

等しい場合は更新します`answer`この値で。 これにより、プレフィックスとサフィックスが一致する有効な分割がキャプチャされます。 
4. ポインタが交差するまで続けます。 

その時点で、実行可能なすべての素なプレフィックスとサフィックスのペアが単調な方法で調査されました。 

重要な考え方は、合計を増やすだけで決して減らさないということです。これにより、等価イベントが発生した瞬間に完全に捕捉されます。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`left_sum`は常にプレフィックスセグメントと`right_sum`は常に接尾辞セグメントの合計であり、これらのセグメントが重複することはありません。 考えられるすべての有効な解決策は、ポインターが配列を 3 つの連続する部分に分割する瞬間に対応します。 常に小さい側を拡張するため、すべての実行可能なプレフィックスとサフィックスの合計ペアを累積の昇順でシミュレートします。 有効な等式はスキップできません。これは、等式が失われると片側を減らす必要があり、プロセスではそれが行われないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    i, j = 0, n - 1
    left_sum, right_sum = 0, 0
    ans = 0

    while i <= j:
        if left_sum <= right_sum:
            left_sum += a[i]
            i += 1
        else:
            right_sum += a[j]
            j -= 1

        if left_sum == right_sum:
            ans = left_sum

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは配列を読み取り、2 つのポインターを使用して、増大するプレフィックスおよびサフィックス セグメントをシミュレートします。 中間セグメントは、暗黙的に、次の中間セグメント間の残りの部分です。`i`そして`j`。 小切手`left_sum == right_sum`両端が同じ合計を蓄積するたびに、有効な分割をキャプチャします。 

常に小さい合計側を拡張するという決定により、潜在的な一致を見逃さないことが保証されます。 常に一方の側を任意に拡張した場合、もう一方の側で先に等価性が発生する構成をスキップできます。

 ## 特殊なケース

 のような入力の場合`1 2 3`の場合、アルゴリズムは両端の拡張を開始しますが、サフィックスとプレフィックスの合計がすぐに発散するため、ゼロ以外では等しくなりません。 ポインタの移動により、一致を誤って宣言することなく、両端が最終的に使い果たされることが保証されます。 

のために`2 2 2 2`、アルゴリズムは、両側が対称的に成長するにつれて、繰り返し等価に達します。 それぞれの等式によって答えが更新され、最終結果には達成可能な最大の分割が反映されます。 

のために`1`の場合、アルゴリズムは、left_sum が 1 になり、right_sum が 0 のままになる単一ステップを実行するため、等価性はなくなり、正しく 0 が返されます。
