 ## 解決策
 ## 問題の理解

 ルート役員 1 を除く各役員に固有の直属の上司を持つ役員のルート ツリーが与えられます。これにより、すべてのノードが役員を表し、エッジが上司から部下に向かう階層が作成されます。 各クエリでは、特定の将校から開始する非常に具体的な横断プロセスをシミュレートし、その横断中にコマンドを受信した k 番目の将校を報告するよう求められます。 

トラバーサル ルールは、入力順序で記述された標準の事前順序ではありません。 代わりに、各将校はコマンドを直属の部下に 1 人ずつ伝え、まだ処理されていないインデックスが最も小さい部下を常に選択します。 選択された各部下は、現在の役員が次の部下を続行する前に、独自のサブツリーを完全に完成させます。 これは事実上、インデックスの昇順で子を訪問する深さ優先検索です。 

各クエリの出力は、トラバーサルの特定のルートから始まるこの DFS 順序の k 番目のノード、または訪問したノードが k 未満の場合は -1 です。 

制約は大きく、最大 200,000 ノードと 200,000 クエリがあります。 クエリごとに DFS をシミュレートするソリューションは、1 回の走査に O(n) 時間がかかる可能性があり、クエリごとにそれを実行すると O(nq) になり、まったく実行不可能であるため、遅すぎます。 すべてのノードの完全なトラバーサル配列を個別に保存するだけでも、メモリが多すぎます。 

すべてのクエリが同じ決定論的な走査ルールを使用するため、問題の構造はツリーのグローバル DFS オーダーを前処理することを強く示唆しています。 主な課題は、特定のノードのサブツリーに注目を迅速に制限し、そのセグメント内の k 番目の位置クエリに答えなければならないことです。 

k がサブツリーのサイズを超えると、微妙なエッジ ケースが発生します。 たとえば、ノードの DFS 範囲内に子孫が 2 つだけあり、k = 5 の場合、正解は -1 です。 もう 1 つのケースは、ノードがリーフの場合です。この場合、そのトラバーサル リストはそれ自体であるため、k = 1 のみが有効です。 

## アプローチ

 直接シミュレーションでは、DFS を実行し、アクセスされたノードを追加することによって、クエリ ノードから開始してトラバーサル リストを構築します。 これは正しいです。トラバーサル ルールは決定的であり、並べ替えられた隣接リストを持つ DFS と一致するからです。 ただし、各クエリではサブツリー全体の走査が必要になる可能性があり、最悪の場合は O(n) になります。 最大 2e5 クエリの場合、これは O(nq) となり、実現可能な制限をはるかに超えます。 

重要な観察は、子を昇順に固定すると、ツリー全体の DFS トラバーサルにより、各サブツリーが連続セグメントに対応するグローバルな順序付けが生成されるということです。 これは、DFS 順序付けの古典的なオイラー ツアーのような特性です。 この順序を一度計算すると、すべてのサブツリーがこの配列のスライスになります。 

高速なクエリをサポートするために、DFS が最初にノードを訪問したときの開始時刻と、そのサブツリーを終了した後の終了時刻をノードごとに記録します。 この場合、ノード u のサブツリー全体が、DFS 配列内の tin[u] から tout[u] までの連続セグメントに対応します。 u からのトラバーサルで k 番目に訪問したノードは、tout[u] を超えない限り、単にこの配列の (tin[u] + k - 1) 番目の要素になります。 

したがって、前処理により単一の DFS 注文が作成され、エントリー位置が保存されます。 各クエリは O(1) 算術チェックになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | 事前計算された DFS 順序 + インデックス作成 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、サブツリー トラバーサルを、事前に計算された DFS 順序での範囲インデックス作成に変えることで解決します。

1. 隣接リストを使用してツリーを構築し、インデックスを増やして各ノードの子を並べ替えます。 これにより、走査順序が常に使用可能な最小の下位を最初に選択するというルールに一致することが保証されます。 
2. グローバル タイマーとアレイを維持しながら、ノード 1 から開始して単一の DFS を実行します。`order`。 ノードに入るたびに、その入った時刻を記録し、ノードに追加します。`order`。 これにより、トラバーサル中にノードが訪問された正確な瞬間がキャプチャされます。 
3. ノードのすべての子を訪問した後、その終了時間を記録します。 間隔`[tin[u], tout[u]]`は、u のサブツリーに属する DFS オーダーのセグメントを正確に表します。 
4. 各クエリについて`(u, k)`、インデックスを計算します`pos = tin[u] + k - 1`。 もし`pos`より大きい`tout[u]`の場合、サブツリーには k 個の要素が含まれていないため、-1 を返します。 
5.そうでない場合は戻る`order[pos]`、これは、u の DFS トラバーサルで k 番目に訪問したノードです。 

これが機能する理由は、ツリー上の DFS の構造特性によるものです。ノードに入ると、その親に戻る前にそのサブツリー内のすべてのノードが参照されます。また、子はソートされた順序で処理されるため、結果として得られるグローバル シーケンスは、必要な拡散ルールを正確に尊重します。 これにより、各サブツリーがグローバル トラバーサルの連続した間隔になるため、位置クエリが単純なインデックス作成に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
p = list(map(int, input().split()))

g = [[] for _ in range(n + 1)]
for i, par in enumerate(p, start=2):
    g[par].append(i)

for i in range(1, n + 1):
    g[i].sort()

order = []
tin = [0] * (n + 1)
tout = [0] * (n + 1)
timer = 0

def dfs(u):
    global timer
    tin[u] = timer
    order.append(u)
    timer += 1

    for v in g[u]:
        dfs(v)

    tout[u] = timer - 1

dfs(1)

for _ in range(q):
    u, k = map(int, input().split())
    pos = tin[u] + k - 1
    if pos > tout[u]:
        print(-1)
    else:
        print(order[pos])
```DFS は、トラバーサルの単一の線形表現を構築します。 配列`order`これは、士官がルートから始まる完全な走査でコマンドを受信するシーケンスとまったく同じです。 配列`tin`そして`tout`各サブツリーに対応するこのシーケンスのセグメントを定義します。 

隣接リストのソートは必須です。これがないと、走査順序が必要な最小インデックス優先ルールではなく入力順序に依存してしまうためです。 

各クエリは、このグローバル順序で k 番目の位置を直接インデックスに変換することによって回答されます。 境界チェックにより、サブツリー セグメントの外側にアクセスしないことが保証されます。 

## 実用的な例

 ### 例 1

 小さな階層を考えてみましょう。```
1 -> {2, 3}
2 -> {4}
3 -> {}
4 -> {}
```DFS の注文は`[1, 2, 4, 3]`。 

| ステップ | アクション | 注文 | tin/tout の最新情報 |
 | --- | --- | --- | --- |
 | 1 | 訪問 1 | [1] | tin[1]=0 |
 | 2 | 2へ | [1,2] | 錫[2]=1 |
 | 3 | 4へ | [1,2,4] | 錫[4]=2 |
 | 4 | 戻って 3 に進みます | [1,2,4,3] | 錫[3]=3 |

 今すぐクエリ`(2,2)`2 のサブツリーの 2 番目のノードを要求します。サブツリーの順序は次のとおりです。`[2,4]`したがって、答えは 4 です。計算には次のものが使用されます。`tin[2]=1`したがって、位置は 2 で、DFS 配列のインデックス 2 と一致します。 

### 例 2

 鎖状の木:```
1 -> 2 -> 3 -> 4
```DFS の注文は`[1,2,3,4]`。 

問い合わせ用`(3,1)`、私たちは得ます`tin[3]=2`したがって、位置は 2 で、答えは次のようになります。`order[2]=3`。 のために`(3,2)`の場合、位置は 3 になり、有効であり、4 を返します。`(3,3)`、位置が超えています`tout[3]=3`したがって、出力は -1 になります。 

これにより、サブツリー セグメントが連続した間隔として動作することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | DFS は各ノードを 1 回訪問し、各クエリは O(1) |
 | スペース | O(n) | 隣接リスト、DFS 順序、およびタイミング配列 |

 前処理はツリーのサイズにおいて線形であり、各クエリは定数演算で解決されます。これは、n、q の制限内に最大 200,000 まで快適に収まります。

 ## 特殊なケース

 リーフ ノード クエリは、アルゴリズムが単一ノードのサブツリーを正しく処理するかどうかをテストします。 以来`tin[u] == tout[u]`、 のみ`k = 1`有効な間隔内でマップされ、それより大きい k は範囲チェックに正しく失敗します。 

ディープチェーンは、DFS の順序がサブツリーのスライスと一貫性を保っているかどうかをテストします。 ノードがネストされている場合でも、連続間隔プロパティは引き続き保持され、正しいインデックス付けが保証されます。 

多くの子を持つノードではソートが必要になります。 隣接リストをソートしないと、走査順序が必要な最小インデックス優先ルールと一致せず、不正な DFS シーケンスと、兄弟順序に関係するすべてのクエリに対する誤った応答が発生します。
