 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられ、少数の交換操作のセットを使用してそれらを操作できます。 各位置は、最初の文字列から 1 つと 2 番目の文字列から 1 つずつ、垂直方向の文字のペアを形成します。 さらに、各文字列内の位置を個別にミラーリングできます。 

主な目的は、これらの交換操作を使用して 2 つの文字列を同一にできるかどうかを判断することです。できない場合は、後で交換するだけでそのような変換が可能になるように、最初の文字列の何文字を事前に変更する必要があるかを判断することです。 

この操作では、自由に文字数をグローバルに変更することはありません。 代わりに、特定の接続構造 (文字列全体の垂直ペアと各文字列内の対称位置) 内でのみ文字を再配置できます。 これは、問題は基本的に、すべての位置について、その連結コンポーネント内の利用可能な文字のマルチセットが 2 つの文字列間で一致できるかどうかであることを意味します。 

n は最大 100000 までであるため、スワップをシミュレートしたり状態を明示的に探索しようとするソリューションは不可能です。 代わりに、操作の構造は、インデックスを独立したコンポーネントにグループ化し、各コンポーネント内でローカルに推論することを提案しています。 

コンポーネント内の文字の不均衡が内部スワップだけでは修正できない場合に、微妙なエッジ ケースが発生します。 たとえば、コンポーネントに両方の文字列が矛盾する形で一致しない 2 つの位置が含まれている場合、単純な貪欲な配置はローカルで修正しようとしますが、コンポーネント内の文字を並べ替えるだけで、新しい文字は導入されないため、グローバルに失敗する可能性があります。 

## アプローチ

 直接的なブルートフォース解釈では、可能なすべてのスワップシーケンスをシミュレートし、許可された操作で到達可能なすべての順列を効果的に探索しようとします。 各操作は、文字列内で対称的にスワップするか、文字列全体で垂直にスワップし、インデックス上で接続されたスワップ グラフを生成します。 最悪の場合、このグラフは大きく、高度に接続されています。これは、到達可能な構成の数がコンポーネントのサイズに影響することを意味します。 状態空間が爆発するため、これは n = 20 の場合でも完全に実行不可能です。 

重要な洞察は、スワップのシーケンスという観点から考えるのをやめ、代わりにスワップが引き起こす構造を特徴付けることです。 この操作はインデックスをコンポーネントに接続し、すべての文字を同等の「スロット」間で自由に並べ替えることができます。 各コンポーネントは制約に影響を与えます。つまり、すべてのスロットにわたる文字のマルチセットは、前処理後に 2 つの文字列間で一致する必要があります。 

インデックスをコンポーネントに圧縮すると、各コンポーネントは独立して動作します。 コンポーネント内では、すでに一致している位置の数と、a と b の間に存在する不一致の数だけを考慮します。 インデックス i での前処理操作は、スロット内の文字を変更するものとして解釈でき、そのコンポーネントの不均衡を効果的に修正します。 

したがって、問題は、コンポーネントごとに、スワップによって内部的に解決できない不一致ペアの数を数えることに帰着します。 このような相容れない不一致には、a の前処理変更が 1 つだけ必要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | スワップに対するブルートフォース | 指数 | 指数 | 遅すぎる |
 | コンポーネントベースのカウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グラフ内のノードとしてインデックスをモデル化します。各インデックス i は各文字列内の n - i + 1 に接続され、同じインデックスで a と b の間も垂直に接続されます。 このグラフは、許可されるすべてのスワップを推移的な接続として表します。 このグラフの連結成分は、どの位置で文字を自由に交換できるかを定義します。 
2. これらのコンポーネントは、union-find 構造を使用して構築します。 各インデックス i について、a 文字列層については i と n - i + 1 を結合し、b 文字列層についても同じことを行い、さらに倍増表現の別個のノードとして a[i] と b[i] を結合します。 これにより、各ノードがいずれかの文字列内の位置を表す統一された構造が作成されます。 
3. すべてのインデックス i について、a[i] と b[i] を含むコンポーネントを考慮します。 コンポーネント内で、各文字が a に属する位置に何回出現するか、および各文字が b に属する位置に出現する回数を数えます。 許可されたスワップは、コンポーネント内で文字を任意に並べ替えることができることを意味するため、重要なのはこれらの合計だけです。 
4. 各成分について、度数分布を比較することによって不一致コストを計算します。つまり、a 側と b 側のカウント間の正の差の文字を合計します。 スワップだけでは不足文字を解決できないため、それぞれの不一致は必要な前処理変更を表します。 
5. すべてのコンポーネントのコストを合計します。 この合計は、スワップによって 2 つの文字列を完全に揃える前に変更する必要がある、 a 内の位置の最小数です。 

機能する理由: すべての操作で各接続コンポーネント内の文字のマルチセットが保存され、交換はそれらの再配布のみを行います。 したがって、実現可能性は、各コンポーネント内に a と b の同一のマルチセットがあることと同等です。 不均衡は、a の変更を前処理することによって修正する必要があり、各変更は、他のコンポーネントに影響を与えることなく、1 つのコンポーネントの不均衡単位を正確に修正します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    dsu = DSU(2 * n)

    def A(i): return i
    def B(i): return i + n

    for i in range(n):
        j = n - i - 1
        dsu.union(A(i), A(j))
        dsu.union(B(i), B(j))
        dsu.union(A(i), B(i))

    comp = {}
    for i in range(n):
        ca = dsu.find(A(i))
        cb = dsu.find(B(i))

        comp.setdefault(ca, [0, 0, [0] * 26, [0] * 26])

    # map both sides into same root key
    for i in range(n):
        r = dsu.find(A(i))
        if r not in comp:
            comp[r] = [0, 0, [0] * 26, [0] * 26]

        ca = comp[r]
        ca[0] += 1
        ca[2][ord(a[i]) - 97] += 1
        ca[3][ord(b[i]) - 97] += 1

    ans = 0
    for v in comp.values():
        ca, cb, cnta, cntb = v
        for c in range(26):
            if cnta[c] > cntb[c]:
                ans += cnta[c] - cntb[c]

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、スワップ操作によって引き起こされる連結コンポーネントを構築します。 Union-find 構造は、a と b の各位置を別個のノードとして扱い、対称インデックスと垂直ペアを接続します。 圧縮後、各ルートは完全に交換可能な位置のセットを表します。 

2 番目のフェーズでは、コンポーネントごとの周波数カウントが集計されます。 重要な実装の詳細は、a から b までの不均衡を測定するだけでよいということです。 a に同じコンポーネント内の他の場所に十分な供給がある場合、b の余剰分はコンポーネント内のスワップによって供給できます。 

よくある落とし穴は、両方の周波数配列を対称的に一致させることによって完全な実現可能性を追跡しようとすることです。 これにより作業は 2 倍になりますが、答えは変わりません。 正しい見解は、b に対する a の赤字のみを支払うということです。

 ## 特殊なケース

 エッジ ケースの 1 つは、最初は独立しているように見えるインデックスが対称性によって接続されている場合に発生します。 のような入力の場合`abba`対`baab`単純なインデックスごとの比較では複数の不一致が示唆されますが、対称性によりインデックスが 1 つのコンポーネントにマージされ、スワップによりほとんどの差異が内部的に解決されます。 このアルゴリズムは、ミラーリングされたインデックスを正しく結合し、周波数バランシングによってゼロまたは最小限の必要な編集が示される単一の共有コンポーネントを生成します。 

すべての不一致が 1 つの大きなコンポーネント内にある場合、別の特殊なケースが発生します。 たとえば、a が b の順列であるものの、対称性の下で大きくスクランブルされている文字列は、依然として 1 つの連結成分を形成します。 DSU はすべてのインデックスをマージし、コンポーネント内ですべての文字を自由に再配置できるため、頻度の比較によって前処理が必要ないことが保証されます。
