 ## 問題の理解

 階段構造のさまざまなセグメントに何段が存在するかを表す 5 つの整数が与えられます。 このピクチャ (明示的には必要ありません) は、可能なルートのセットを下から上にエンコードします。各ルートは、接続されたセグメントのシーケンスの選択に対応します。 各セグメントは独自のステップ数を提供します。タスクは、開始から終了までのすべての有効なルートの中から可能な限り最小の総ステップ数を見つけることです。 

重要な解釈は、5 つの値をすべて合計しているわけではないということです。 代わりに、各値は小さなグラフのような構造内の固定ノードに属し、有効なパスは接続されたノードのシーケンスを正確に選択します。 すべてのパスには正確に 3 つのセグメントがあるため、答えは常に 3 つの選択された値の合計になりますが、許可されるトリプルは図内の接続に応じて異なります。 

値が 5 つしかなく、固定された小さな構造があるため、計算は定数時間で行われます。 値ごとに最大 10^8 という制約は、Python では算術オーバーフローや特殊な処理は無関係であり、正しい組み合わせを選択することに純粋に集中すべきであることを示しています。 

ここでの単純な間違いは、任意の 3 つの値を選択できると仮定することです。 たとえば、入力の場合`1 3 2 4 5`、最も小さい 3 つの値を誤って取得する可能性があります。`1 + 2 + 3 = 6`ただし、その組み合わせが階段レイアウトで有効なパスであるとは限りません。 この構造では、どのトリプルが許可されるかを制限しているため、正確さはこれらの制約を尊重するかどうかに依存します。 

もう 1 つの微妙な問題は、対称性を仮定するか、最短パスを動的に計算しようとすることです。 グラフは固定されており小さいため、これはやりすぎです。 答えは、候補の合計の小さなセットによって決定されます。 

## アプローチ

 構造を無視して、考えられるすべてのルートを明示的に探索しようとすると、図の一番下のノードから一番上のノードまでのすべてのパスを列挙することになります。 各パスは、接続されたセグメントを通る一連の移動に対応し、パスごとに 3 つのセグメント値の合計を計算します。 ノードが 5 つある場合、この総当たり列挙はサイズが一定ですが、概念的にはグラフ走査のように動作します。 

このような定式化の非効率性は、それを一般化した場合にのみ現れます。パスの列挙は一般的なグラフでは指数関数的です。 グラフは固定されており、有効なルートが少数しかないため、ここでは不要です。 

重要な観察は、この図では少数の有効な組み合わせのみが定義されており、すべての有効なパスが 5 つの変数にわたる候補式の小さなセットに限定されるということです。 これらの候補合計を特定すると、問題は一定数の式にわたる単純な最小値になります。 

階段の構造は、まさに 3 つの意味のあるルート パターンを暗示しています。 各パターンは、各分岐点で 2 つの選択肢のうち 1 つを選択することに対応します。 パスを探索する代わりに、これらのパターンを直接評価します。

 ## アルゴリズムのチュートリアル

 階段は、途中で 3 つの決定を伴う小さな有向構造としてモデル化できます。 各決定は 2 つの隣接するセグメントから選択し、各決定ポイントからの 1 つの選択肢を組み合わせて完全なルートが形成されます。 

1. 図によってエンコードされた 3 つの有効なパス パターンを特定します。 各パターンは、階段内の隣接関係を考慮しながら、下から上へ移動するさまざまな方法に対応しています。 
2. 各パターンを 5 つの値のうち 3 つの合計として表現します。 重要なステップは、図内の各動きをそれに関連付けられた入力値にマッピングすることです。 
3. 算術演算を使用して、3 つの候補の合計をすべて直接計算します。 
4. これらの候補合計の最小値を最終的な答えとして返します。 

動的推論を試みるのではなく、これらの合計を明示的に列挙する理由は、グラフにはサイクルや大きな分岐構造がなく、すべての有効なパスが事前に決定されているためです。 

### なぜ効果があるのか

 下から上へのすべての有効なルートは、階段構造の 2 つの中間ジャンクションのそれぞれで、正確に 1 つの選択肢を通過する必要があります。 これにより、パス空間が正確に 3 つの組み合わせに分割されます。 各組み合わせは固定セグメントの選択によって完全に決定されるため、すべてを評価して最小値を選択すると、最短パスが保証されます。 構造内に追加の分岐点がないため、この列挙の外には他のルートは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c, d, e = map(int, input().split())

# three valid paths in the staircase graph
path1 = a + b + d
path2 = a + c + e
path3 = a + c + d

print(min(path1, path2, path3))
```この実装は、パスから固定式への削減に直接続きます。 各式は、階段を通る 1 つの構造的に有効なルートに対応します。 

実装でよくある落とし穴は、どのセグメントがどのルートに属しているかを誤って認識することです。 正しいマッピングは、値の並べ替えや貪欲な選択からではなく、ダイアグラムの隣接性を追跡することから得られます。 

もう 1 つの微妙な点は、すべての計算が独立しているため、中間ストレージや反復的な更新が必要ないことです。

 ## 特殊なケース

 すべての値が等しい場合、たとえば`1 1 1 1 1`、各候補の合計は 3 と評価されます。アルゴリズムは 3 つの式すべてを計算し、3 を返すため、特別な処理は必要ありません。 

ある値が他の値を支配する場合、次のようになります。`10 1 100 1 1`、正しいパスは、可能な限り大きな 100 を避けます。 候補の評価には、次のルートを使用する両方のルートが明示的に含まれます。`c`とそれを回避するルートがあるため、最小値は正しく 12 になります。 

次のようなエンドポイントに大きな値が表示される場合`100 1 1 100 100`、アルゴリズムは依然として各固定の組み合わせを独立して評価します。 複数の大きな値が存在する場合でも、1 つの組み合わせだけで重複が最小限に抑えられ、最小の操作によって正しく選択されます。 

各ケースは純粋に事前定義された構造の算術評​​価を通じて処理されるため、3 つの合計を計算して比較する以外に動的な推論や条件分岐は必要ありません。
