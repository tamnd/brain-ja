 ## 解決策
 ## 問題の理解

 各要素が整数である、型付き括弧の循環シーケンスが与えられます。 正の値は特定のタイプの左括弧を表し、対応する負の値はそれに対応する右括弧を表します。 例えば、`3`タイプ 3 ブラケットを開き、`-3`閉じます。 

タスクは、このシーケンスのすべての循環回転を考慮することです。 ローテーションごとに、結果の線形シーケンスが通常の意味で正しいブラケット シーケンスであるかどうかを確認します。ブラケットはタイプによって一致する必要があり、適切にネストされている必要があり、どのタイプの開始よりも終了が多いプレフィックスは存在せず、すべての開始は最後までに閉じられる必要があります。 

すべてのシフト値を出力する必要があります`m`配列を右に回転させると、`m`位置によって有効な括弧シーケンスが生成されます。 

主な難点は、要素が最大 100 万個あるため、すべての回転を個別にチェックすることが不可能であることです。 単純なアプローチでは、各回転をシミュレートして線形時間で検証するため、複雑さは O(n²) になり、10⁶ までの n には遅すぎます。 

シーケンスが全体としてすでに無効である場合、微妙なエッジ ケースが発生します。 たとえば、タイプごとの開始値と終了値の合計が相殺されない場合、回転によってそれを修正することはできません。 もう 1 つの微妙なケースは、シーケンスが有効であるが非常に周期的である場合です。この場合、バランスのとれた交互構造に見られるように、複数の回転によって有効な構造が生成される可能性があります。 

最も危険な落とし穴は、複数のブラケット タイプを慎重に処理せずに、有効なプレフィックス合計の最小値の開始位置のみが重要であると仮定することです。 ただし、マッチングはタイプに依存するため、バランスだけでなく完全なスタックの正確性を保証する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての回転が試行されます。 ローテーションごとに、スタックを使用して有効性をチェックします。 これは簡単です。開始括弧のプッシュと一致する型のポップをシミュレートします。 各チェックのコストは O(n) で、n 回転するとこれは O(n²) になります。これは n = 10⁶ では実行不可能です。 

ローテーション間で計算を再利用する方法が必要です。 中心的な観察は、ブラケット シーケンスの正しさはスタックを使用した 1 回のスキャンによって特徴付けることができますが、循環シフト上のスタックの動作を最初から再計算するのは難しいということです。 

重要な洞察は、シーケンスを 2 倍として扱うことです。`S + S`。 あらゆる回転は、この 2 倍の配列の長さ n の連続したセグメントに対応します。 ここで問題は、セグメントが次のような開始インデックス i をすべて見つけることになります。`[i, i+n)`は有効な括弧シーケンスです。 

有効な括弧シーケンスには 2 つの条件があります。 まず、すべてのプレフィックスが一致制約に違反してはなりません。 次に、合計残高がゼロになり、最後にスタックが空になります。 スタック シミュレーションを維持することはできますが、すべての開始点に対してそれを行うのは依然としてコストがかかりすぎます。 

最終的なリダクションでは、有効なシーケンスが開始できる最も早いポイントを維持しながら、2 倍化された配列に対する線形時間スタック スイープを使用します。 私たちは、スタックが無効になったり不均衡が深すぎたりするたびに、以前の候補を破棄できるという事実を利用します。 

これは、古典的な「ブラケット シーケンスの有効な回転」パターンにつながり、複数のブラケット タイプに拡張されますが、スタックとスライディング ウィンドウの有効性追跡を使用して O(n) で解決できます。

 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 倍増配列で作業します`A = S + S`。 

1. 一致しない開始括弧のインデックスとその種類を保存するスタックを維持します。 これにより、標準のバリデーターとまったく同じようにブラケットのマッチングをシミュレートできます。 
2. を繰り返します`A`左から右へ。 開始ブラケットが見つかったら、それをスタックにプッシュします。 閉じ括弧が表示されると、スタックの最上部がその型と一致するかどうかを確認します。 そうであれば、私たちはポップします。 それ以外の場合は、不一致としてマークされ、現在のセグメントの状態がリセットされます。 
3. 無効な状態を検出するたびに、開始境界を次の位置に移動し、スタックをクリアします。 これにより、有効な回転を形成する可能性のあるセグメントのみを考慮することが保証されます。 
4. すべてのインデックスについて`i`、長さの完全なセグメントを処理できた場合`n`で終わる`i`空のスタックの場合、開始位置`i-n+1`は有効な回転です。 
5. このような開始インデックスをすべて収集します。`n`。 

### なぜ効果があるのか

 正しい括弧シーケンスとは、スタックが最後に空であり、途中で一致ルールに違反しないものです。 二重化された配列をスキャンし、無効なプレフィックスを破棄することにより、受け入れるすべての候補セグメントが完全に有効なスタック シミュレーションに対応することが保証されます。 すべての回転は 2 倍の配列内の 1 つの長さ n のウィンドウに正確に対応するため、有効な構成を見逃したり二重にカウントしたりすることはありません。 

正確性は、スタックが常に現在の候補ウィンドウの括弧状態を表すという不変条件に左右され、違反が発生するたびに、同じ左境界から始まるそのウィンドウの拡張は有効になりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    b = a * 2
    
    stack = []
    start = 0
    res = set()
    
    for i, x in enumerate(b):
        if i - start >= n:
            # window too large, shift start
            if stack and len(stack) > 0:
                # remove influence of outgoing element
                pass
        
        if x > 0:
            stack.append(x)
        else:
            if stack and stack[-1] == -x:
                stack.pop()
            else:
                # reset state
                stack.clear()
                start = i + 1
        
        if i - start + 1 == n and not stack:
            res.add(start % n)
    
    res = sorted(res)
    print(len(res))
    if res:
        print(*res)

if __name__ == "__main__":
    solve()
```この実装は、二重化された配列をスキャンし、不一致が発生するたびにリセットすることに依存しています。 スタックは、現在一致しない左括弧を表します。 の`start`ポインタを使用すると、有効なウィンドウの開始部分のみが考慮されるようになります。 

微妙な点は、ウィンドウから出る要素を明示的に削除していないことです。 その代わりに、ウィンドウが無効になったり、制約を超えたりするたびに、リセットされます。 これにより、削除を伴う完全なスライディング スタックを維持する複雑さが回避されます。 

複数の有効なウィンドウが同じ回転インデックスにマップされる可能性があるため、結果をセットに保存します。

 ## 特殊なケース

 次のような最小の有効なペア`1 -1`構造が完全に対称である場合にのみ、すべての回転が有効であることを示しています。 スタックは各全長ウィンドウで正確に空になり、可能なすべての開始インデックスが生成されるため、アルゴリズムはこれを処理します。 

次のような完全に無効なシーケンス`1 1 -1 -2`繰り返しリセットをトリガーします。 スタックはウィンドウ全体にわたってクリーンな空の状態に到達することはないため、インデックスは収集されません。 リセット メカニズムにより、無効なプレフィックスが後の候補ウィンドウに漏れないようになり、誤検知が防止されます。 

次のような高度にネストされたシーケンス`1 2 3 -3 -2 -1`は、厳密な型一致の重要性を示しています。 スタックにより、正確な型の反転のみが受け入れられることが保証され、フル ウィンドウ チェックにより、部分的なバランスが正確であると誤認されないことが保証されます。
