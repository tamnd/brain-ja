 ## 解決策
 ## 問題の理解

 ボードは非常に高いですが、幅は 2 列しかないため、すべての行は左または右のセルにすぎません。 白いポーンは左下のセルから始まり、スタックするか最上行の高さに達するまで、行ごとに上に移動します。$10^{18}$。 

各行には、セルごとに最大 1 つの黒い部分を含めることができます。 ポーンは一度に 1 行ずつ上に移動しますが、列の選択とそれが横切ることができるかどうかは、移動先のセルに黒いピースが含まれているかどうかによって決まります。 同じ列内での通常の前方移動は、ターゲット セルが空の場合にのみ許可されます。 他の列への対角線のような移動は、ターゲット セルに黒いピースが含まれている場合にのみ許可され、その場合、ポーンはそこに移動してそのピースを削除します。 

したがって、各行は小さなローカル決定点のように動作します。つまり、行の指定された列からです。$r$、ポーンは列に入る方法を決定します$r+1$、その決定は、行にある 2 つのセルがそれぞれ正しいかどうかによってのみ決まります。$r+1$ブロックされています。 

重要な問題は、行が次まで続くことです。$10^{18}$、しかし、ただ$10^5$それらには黒い部分が含まれています。 他のすべての行は完全に空であり、空の行は決定論的に動作します。つまり、ある列に空の行を入力すると、ピースを含む次の行で変更が強制されるまで、連続するすべての空の行の間その列に留まることが強制されます。 

出力は単純に、行に到達する一連の正当な手が存在するかどうかです。$10^{18}$。 

制約$n \le 10^5$まで行ごとに反復するシミュレーションは直ちに除外されます。$10^{18}$。 イベントごとの処理であっても、線形である必要があります。$n \log n$。 すべての行遷移を明示的にシミュレートしようとするアプローチは不可能です。 

黒のピースがまばらだが戦略的に配置されている場合、微妙なエッジケースが現れます。 たとえば、すべての駒が 1 つの列にあるにもかかわらず、両方の「強制交差方向」をブロックしている場合、ほとんどの列が空であっても、ポーンは永続的に動けなくなる可能性があります。 もう 1 つのエッジ ケースは、ポーンが列間を複数回往復する必要がある場合です。 行ごとの貪欲な決定は、グローバルな状態伝播の問題として処理しないと失敗する可能性があります。 

## アプローチ

 直接シミュレーションでは、ポーンの位置を行ごとに維持しようとします。 各行で、次の行の 2 つのセルをチェックし、移動ルールを適用します。 ポーンの状態は単にその列であるため、これは概念的には機能しますが、問題は行数です。連続する黒駒の行の間には、最大で 2 までのギャップが存在する可能性があります。$10^{18}$。 単純なシミュレーションでは、これらのギャップを反復処理するのに時間がかかりますが、これは不可能です。 

重要な観察は、空の行が均一であるということです。 列の場合$r$黒の部分がない場合は列から入力します$c$同じ列から強制的に離れる$c$、この動作は、連続する空の行ごとに同じように繰り返されます。 そのため、長い空のストレッチは状態を変更しません。 単に「時間を遅らせる」だけです。 

これは、少なくとも 1 つの黒い部分を含む行について推論する必要があるだけであることを意味します。 問題を高さ順に並べ替えた一連の「興味深い行」に圧縮します。 2 つの連続する興味深い行の間では、ポーンの列は変更されないため、状態を前に進めるだけで済みます。 

これで、システムはソートされた行に対する 2 状態の動的プロセスになります。 対象となる各行では、どのセルがブロックされているかに応じて、一部の遷移で列の切り替えが強制される場合や、留まることが許可される場合があります。 到達可能な状態を前方に伝播します。 いずれかの時点で両方の状態が不可能になった場合、プロセスは終了します。 

これにより、ソートされた行をスキャンし、各イベント行で 2 つの列のどちらに到達できるかを維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 行インデックスで並べ替えられた、少なくとも 1 つの黒い部分を含む行のみが処理されます。 

1. すべての黒のピースを行インデックスに基づいてグループ化し、列 1 および/または列 2 がその行でブロックされているかどうかを保存します。 これにより、同じ行内の複数の部分が単純な 2 ビット マスクに縮小されます。 これは、部分の数ではなく、列ごとの占有のみが遷移に影響するため、重要です。 
2. 少なくとも 1 つの部分を含む行を並べ替えます。 これらの行全体にわたる動きのみを昇順にシミュレートします。 
3. 状態配列を維持する`dp`サイズ 2 の場合、`dp[c]`列に並ぶことが可能であることを意味します`c`現在の対象行を処理する直前。 
4.初期化`dp = [True, False]`これは、行 1 の列 1 から開始し、最初はその状態のみに到達できるためです。 
5. ソートされた行を昇順に繰り返します。 行ごとに`r`、次の状態を計算します`ndp`現在到達可能なすべての列に基づいて:

 - 行の前の列 1 にいる場合`r+1`、その後:

 - セルがブロックされていない場合は、列 1 まで直接移動できます。 
- 列 2 がその行でブロックされている場合、列 2 に斜めに移動できます (キャプチャと遷移が可能になるため)。 
- 行の前の列 2 にいる場合`r+1`、対称ロジックが適用されます。 

このステップは、到達可能な状態ごとに独立して適用され、結果を次のように結合します。`ndp`。 
6. 交換する`dp`と`ndp`。 両方の状態が false になる場合は、ポーンがスタックしているため、早期に終了します。 
7. 対象となるすべての行を処理した後、次の最終段階がまだ残っています。$10^{18}$。 完全に空であるため、それ以上の遷移は発生しません。 どちらの状態も有効な終了状態です。 最後に処理された行でいずれかの列に到達できる場合は、先頭まで無限に続行できます。 
8. 最後に少なくとも 1 つの列状態に到達できる場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 不変条件は、ある高さまでのすべての行を処理した後、$r$、`dp[c]`ポーンが列に入れることができるかどうかを正しく表します$c$列で$r$。 空の行は列を変更しないため、この不変条件が保持されます。 状態のすべての変化はピースを含む行でのみ発生し、それらの行は DP にエンコードされた遷移ルール​​によって完全にキャプチャされます。 遷移はすぐ次の行のみに依存し、より深い履歴には依存しないため、現在の列の状態を超える追加のメモリは必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
rows = {}

for _ in range(n):
    c, r = map(int, input().split())
    if r not in rows:
        rows[r] = [False, False]
    rows[r][c - 1] = True  # black piece exists

events = sorted(rows.items())

dp = [True, False]  # at row 1, column 1

prev_r = 1

for r, mask in events:
    ndp = [False, False]

    # we process jump from prev_r to r, but empty rows don't change state
    # so dp remains valid until r

    for c in (0, 1):
        if not dp[c]:
            continue

        # move to same column if empty
        if not mask[c]:
            ndp[c] = True

        # move to other column if there is a piece there
        oc = 1 - c
        if mask[oc]:
            ndp[oc] = True

    dp = ndp

    if not dp[0] and not dp[1]:
        print("NO")
        exit()

# after last event, infinite empty rows to the top
print("YES" if dp[0] or dp[1] else "NO")
```この実装では、行ごとにすべての部分がブール マスクに圧縮されます。 これにより、同じ行内の複数の部分の繰り返し処理が回避されます。 

DP 遷移は移動ルールに直接に従います。同じ列に留まるには目的のセルにピースが存在しないことが必要ですが、列を切り替えるにはキャプチャするピースが存在する必要があります。 その時点を超えて状態を変更することはできないため、最終的な答えは、関連する最後の行の後の到達可能性をチェックします。

 ポーンは、行 1 の列 1 から開始します。行 2 では、列 1 がブロックされているため、真っすぐに移動することはできません。 列 2 がブロックされ、キャプチャが列 2 に移動できるようになります。その後、イベントは存在しないため、最終状態に到達できます。 

これは、単一の障害物によってコラム スイッチがどのように強制されるかを示しています。

 ## 特殊なケース

 主なエッジケースは、開始点よりもはるかに上の列に黒い部分だけが表示される場合です。 たとえば、最初に占有されている行が$10^{18}$、ポーンは制約なしですべての下の行を通過します。 最初のイベント行まで DP は変更されず、空のプレフィックスが効果的に圧縮されるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、行内の両方のセルがブロックされている場合です。 その状況では、すべての受信状態はその行のデッド状態に遷移し、DP は空になります。 アルゴリズムは検出直後に正しく NO を返します。`dp`全て虚偽となる。 

3 番目のケースでは、多くの行にわたって強制スイッチを交互に実行します。 各行は 2 つの状態のみで独立して処理されるため、発振を繰り返す場合、現在の DP ベクトルを超えて履歴を保存する必要はありません。
