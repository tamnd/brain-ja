 ## 解決策
 ## 問題の理解

 いくつかの線形チェーンが与えられていますが、それぞれは単なる単純なパス グラフです。 これらのチェーンから、単一の白い根の頂点から始まる成長するツリーにチェーンの一部を接続することができます。 チェーンをアタッチするたびに、チェーンの頂点を選択し、それを現在のツリーの既存の白い頂点に接続します。 この新しい接続の終点とチェーン内の選択された頂点は両方とも黒になり、チェーン内のその他のものはすべて白のままです。 

目標は、少なくとも k 個の白い頂点を含むツリーを構築することです。 このようなすべての構築の中で、ルートから k 番目に近い白い頂点までの距離に注目し、この距離を最小限に抑えたいと考えています。 

最適化される主要なオブジェクトは、ツリー自体の形状ではなく、ルートからの距離による白い頂点の分布です。 チェーンは、接続方法に応じて、深度が増すにつれて潜在的な白い頂点の構造化されたセットに寄与します。 

制約は大きく、n は 2⋅10^5 まで、k は 10^9 までです。 これにより、ツリーを明示的にシミュレートしたり頂点を列挙しようとするソリューションは即座に除外されます。 有効なアプローチでは、各チェーンを少量の概要情報に削減し、集約された貢献に対して貪欲または二分探索推論を使用する必要があります。 

単純な間違いは、より長いチェーンを接続することが常に直接的に役立つ、またはチェーンのすべての頂点が均等に寄与すると仮定することです。 たとえば、k が小さいがチェーンが長い場合、単純な貪欲な人は、チェーン全体が白のままであると仮定して、浅い深さにある白い頂点を過剰にカウントする可能性があります。これは、チェーンごとに 1 つのアタッチメント ポイントだけがその一部を黒にするため、正しくありません。 

もう 1 つの微妙なエッジ ケースは、k が可能な白い頂点の総数よりも大きい場合です。 各チェーンはアタッチメントに応じて使用可能な白い頂点の数に制限があるため、すべてのチェーンを使用しても不十分な場合があり、答えは -1 でなければなりません。 

## アプローチ

 この強引なアイデアは、チェーンを選択し、各チェーン内の接続点を選択し、結果としてツリーを構築するすべての方法を検討してから、すべての白い頂点までの距離を計算することです。 各チェーンは使用することも使用しないこともでき、使用する場合は接続位置によってツリーに沿った白い頂点の分布が変化するため、これはチェーンの数において明らかに指数関数的です。 結合位置を無視しても、サブセット選択だけで O(2^n) が得られますが、これは 2⋅10^5 までの n では不可能です。 

重要な観察は、各チェーンが接続されたときに、到達可能な白い頂点に非常に構造化された単調な効果を与えるということです。 チェーンがアタッチされると、ちょうど 1 つの頂点が接続ポイントになり、チェーン内のそのポイントを超えるすべてのものはルートからの距離の点で「上」になりますが、それに近いものはすべて黒化により事実上無駄になります。 これは、各チェーンを使用可能な白い頂点のセグメントを生成するものとして扱うことができ、その寄与を費用対効果曲線、つまり特定の距離のしきい値で獲得する白い頂点の数によって要約できることを意味します。 

ツリーを構築する代わりに、視点を逆転させます。 距離制限 D を固定して、距離 ≤ D で少なくとも k 個の白い頂点を確保できるかどうかを尋ねるとします。 これに答えることができれば、最小の D を二分探索できます。固定 D の場合、各チェーンは、深さ D 内に配置できるすべての頂点に寄与するか、チェーンを接続する場所に応じて部分的に寄与します。 固定 D の最適な戦略は貪欲です。距離 D 内にある白い頂点の数を最大化する方法で常にチェーンを接続します。これにより、各チェーンが D とその長さの単純な関数に縮小されます。 

これにより、問題は、D に対する二分探索内の実行可能性チェックのための貢献をソートし、貪欲に蓄積することに変換されます。

 | サブセットと添付ファイルに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性 | O(n log n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、タスクを答え候補 D (k 番目の白い頂点までの最大許容距離) に関する決定問題として再定式化します。 

1. [1, max(l_i)] の範囲で D を二分探索します。 目標は、ルートから距離 D 以内に少なくとも k 個の白い頂点を取得できる最小の D を見つけることです。 これが機能するのは、構成が D で機能する場合、それより大きな D でも機能するためです。 
2. 固定 D の場合、距離 D 内にいくつの白い頂点を配置できるかを計算します。長さ L の各チェーンは、それがどのように接続されているかに基づいて寄与します。 頂点のセグメントが距離 D 内に位置するように接続する場合、できる限りの最善の方法は、距離制限内に収まる頂点の数を最大化する接続点を選択することです。 
3. 長さ L のチェーンの場合、チェーンに沿ってカット位置 t を選択することを考慮します。 カットの一方の側はルートに近づき、もう一方の側はさらに遠ざかりますが、接続に使用される端点は 1 つだけであるため、事実上、使用可能な白い頂点の連続セグメントのみを保存できます。 固定 D の最適な寄与は、チェーンを最適に位置合わせした場合に距離 D 内にチェーンの頂点をいくつ配置できるかに応じて決まります。 
4. 各チェーンについて、距離 D 内で寄与できる頂点の最大数を計算します。すべての正の寄与を収集して並べ替え、k に達するかすべてのチェーンを使い果たすまで、最も大きな寄与を貪欲に最初に取得します。 
5. 寄与の合計が少なくとも k に達する場合、D は実行可能です。 それ以外の場合はそうではありません。 
6. 実現可能な最小限の D を二分探索します。 

### なぜ効果があるのか

 重要な不変条件は、固定 D の場合、各チェーンが独立して動作することです。到達可能な白い頂点の数への寄与は、D とその長さにのみ依存し、他のチェーンの選択には依存しません。 この独立性は、ツリー構造が非周期的であり、接続点はローカルな距離にのみ影響するという事実から来ています。 したがって、距離 D 内の白い頂点の合計を最大化すると、各チェーンの寄与を独立して最大化し、それらを合計することになります。 寄与は相加的であり、チェーン間に相互作用ペナルティがないため、寄与が大きいチェーンを最初に貪欲に選択することが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(D, a, k):
    gains = []
    total = 0

    for L in a:
        if D <= 0:
            continue
        # maximum usable segment we can fit within distance D
        # optimal contribution behaves like taking best placement of chain
        # effectively we can "center" the chain around attachment
        gain = min(L - 1, D)
        gains.append(gain)

    gains.sort(reverse=True)

    for g in gains:
        total += g
        if total >= k - 1:
            return True
    return False

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # impossible even in best case
    if sum(L - 1 for L in a) + 1 < k:
        print(-1)
        return

    lo, hi = 1, max(a)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a, k):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```二分探索が応答距離を超えています。 実現可能性チェックは、各チェーンを単純な上限寄与率に変換します。 表現`L - 1`1 つの端点が黒になり、使用可能な白い頂点として寄与しないため、長さ L の各チェーンはルート接続構造を超えて L-1 個の追加頂点しか寄与できないことを反映しています。 

内部`can`では、各チェーンから距離 D 内に配置できる頂点の数を概算します。貪欲な累積により、制約の下でより多くの白い頂点を提供できるチェーンが常に優先されることが保証され、これはチェーンの独立性と一致します。 

早期の不可能性チェックにより、すべてのチェーンを使用しても k 個の白い頂点に到達できない場合には二分探索が行われないことが保証されます。 

## 実用的な例

 一定の長さのチェーンを持つ小さなインスタンスを考えてみましょう`[4, 3]`そして`k = 3`。 

候補 D = 2 をテストします。 

| チェーン | Ｌ | D | 内のゲイン 現在の合計 |
 | --- | --- | --- | --- |
 | 1 | 4 | 2 | 2 |
 | 2 | 3 | 2 | 4 |

 少なくとも k-1 = 2 個の追加の白い頂点に達するため、D = 2 が実現可能です。 

これは、各チェーンがどのように単純な制限された貢献に還元され、貪欲に結合されるかを示しています。 

ここで考えてみましょう`[3, 3, 3]`、`k = 5`、D = 1。 

| チェーン | Ｌ | D | 内のゲイン 現在の合計 |
 | --- | --- | --- | --- |
 | 1 | 3 | 1 | 1 |
 | 2 | 3 | 1 | 2 |
 | 3 | 3 | 1 | 3 |

 k-1 = 4 に到達できないため、D = 1 は実現不可能であり、より大きな距離を余儀なくされます。 

これらのトレースは、実現可能性が構造ではなく集合的な寄与のみに依存する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log max l_i) | 距離に対する二分探索、各チェックで n 個の寄与をソート |
 | スペース | O(n) | チェックごとにゲインを保存 |

 この制約では最大 2⋅10^5 のチェーンが許可されるため、実現可能性チェックごとの並べ替えが許容されます。 バイナリ検索の深さは約 18 回の反復であり、解を時間制限内に十分に収めることができます。

 ## 特殊なケース

 1 つのエッジ ケースは、すべてのチェーンを使用して k がかろうじて達成可能な場合に発生します。 その状況では、二分探索は最大チェーン長に近い値に収束します。 各チェーンが最大 L−1 に寄与し、合計条件が厳密な実現可能性を正確に捕捉するため、実現可能性チェックは依然として正しく動作します。 

もう 1 つの特殊なケースは、すべてのチェーンが短く、k が大きい場合です。 たとえば、k が 2⋅10^9 に近い長さ 3 のチェーンが多数存在します。 初期チェック`sum(L - 1) + 1 < k`即座にトリガーされるため、不必要な計算が防止されます。 

3 番目のケースは、1 つの非常に長いチェーンが他のすべてのチェーンを支配する場合です。 貪欲な選択により、このチェーンのゲインがどの D の下でも最大になるため、実行可能性チェックでこのチェーンが常に最初に選択され、より小さなチェーンの構造によって決定が歪められることがなくなります。
