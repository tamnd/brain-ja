[CF 1469A - 通常のブラケット シーケンス](https://codeforces.com/problemset/problem/1469/A)

 **評価:** 1000
 **タグ:** 建設的アルゴリズム、貪欲
 **解決時間:** 2 分 14 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 左括弧、閉じ括弧、疑問符の 3 種類の文字のみで構成される短い文字列が与えられます。 すべての疑問符は独立して開始括弧または終了括弧のいずれかになる可能性があるため、文字列が固定されていないのが特徴です。 2 つの特別な事実により、構造が大幅に簡素化されます。文字列には、固定開始括弧と固定終了括弧が 1 つだけ含まれており、その他はすべて柔軟です。 

タスクは、結果のシーケンスが正しい括弧シーケンスになるように、すべての疑問符を置き換える方法が存在するかどうかを判断することです。 正しいシーケンスとは、括弧として解釈した場合、すべての接頭語に少なくとも閉じ括弧と同じ数の開き括弧があり、合計数が正確に一致し、最終的な残高がゼロになることを意味します。 

テスト ケースごとの入力が小さいように見えても、テスト ケースの数は大きくなる可能性があります。 各文字列の長さは最大 100 であるため、テスト ケースごとに 2 次以下の解はすでに安全ですが、疑問符のすべての割り当てを直接調査しようとすると、指数関数的なものは非常に遅くなります。 

疑問符をすべてブルートフォースで置き換えるという単純な考えは、すぐに失敗します。 k 個の疑問符がある場合、2^k 通りの可能性が生じます。 k が約 100 になると、これは天文学的に大きくなります。 無効なプレフィックスを削除したとしても、分岐は依然として大きすぎて制限内で処理できません。 

もう 1 つの微妙な失敗例は、局所的なバランスのみに基づいて、すべての疑問符を開始または終了のいずれかに貪欲に割り当てることによって発生します。 たとえば、プレフィックスに閉じ括弧が「必要」であると早い段階で判断すると、後で残りのサフィックスのバランスが適切に取れなくなり、行き詰まりにつながる可能性があります。 これは、グローバル構造を考慮せずにローカルで貪欲な決定を行うのは安全ではないことを示しています。 

主要な構造に欠けているのは、固定アンカーが 2 つしかないことです。1 つは確実に開くもの、もう 1 つは閉じることが保証されるものです。 つまり、答えは主に、シーケンスを有効な接頭辞と接尾辞の構造に分割できる方法で、疑問符から隙間を埋めるのに十分な柔軟性を備えた方法でこれら 2 つのアンカーを配置できるかどうかに依存します。 

## アプローチ

 ブルート フォース手法では、すべての疑問符に「(」または「)」を割り当て、結果のシーケンスが有効かどうかをリニア スキャンを使用してチェックします。 これは問題の定義を直接シミュレートするため、これは正しいです。 ただし、k 個の疑問符がある場合、2^k 個の文字列が評価され、各妥当性チェックのコストは O(n) となり、合計の複雑さは O(n・2^n) になります。 これは中程度のnでも使えません。 

重要な点は、実際にはすべての文字を独立して決定する必要はないということです。 有効な括弧シーケンスは接頭辞のバランスを維持する必要があり、すべての不確実性は疑問符に集中しているため、唯一意味のある質問は、特定の点の前に十分な開始括弧と、その後に十分な閉じ括弧を配置できるかどうかです。 

固定された開始ブラケットと終了ブラケットは、文字列を効果的に構造に分割します。必要なのは、その周囲でシーケンスのバランスが取れていることを確認することだけです。 この条件は、2 つの固定アンカーを交換すると、プレフィックス間でバランスを維持する機能が損なわれるかどうかを確認することになります。 具体的には、固定の '(' が固定の ')' の前に来なければならないと仮定すると、文字列を有効にできるかどうかを検証できます。 それらの相対順序が間違っている場合、疑問符を割り当ててもプレフィックス制約に違反せずにその反転を修正できないため、不可能になります。 

したがって、問題全体は、文字列内の一意の「(」と「)」の相対位置をチェックすることに帰着します。

 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンし、一意の開始括弧と一意の終了括弧のインデックスを記録します。 

残りの文字は柔軟であり、構造を直接制約しないため、それらの位置が必要です。 
2. 開始括弧が終了括弧の前に表示されるかどうかを確認します。 

有効な括弧シーケンスには、閉じ括弧を過剰に消費し始める前に、開始容量が利用可能なプレフィックスが必要であるため、この条件は不可欠です。 
3. 終了括弧の後に開始括弧が発生した場合は、すぐに NO を返します。 

その場合、疑問符を最適に配置したとしても、固定構造を並べ替えることはできないため、無効は避けられません。 
4. それ以外の場合は、YES を返します。 

開始括弧が前にある場合は、常に疑問符を割り当てて、固定位置の前後の接頭語のバランスを取ることができます。 

### なぜ効果があるのか

 有効な括弧シーケンスには、すべての接頭辞において、開始括弧の数が少なくとも終了括弧の数であるという特性がなければなりません。 固定開始ブラケットは、早期にある程度のプラスのバランスを作成できることを保証しますが、固定終了ブラケットは後で少なくとも 1 つの減少を強制します。 右括弧が左括弧の前に出現する場合、疑問符をどのように割り当てたかに関係なく、必要なバランス条件がすでに違反されているプレフィックスが存在します。疑問符はこれら 2 つの固定制約の順序を変更できないためです。 開始括弧が前にある場合は、終了括弧に遭遇するまでプレフィックスの実現可能性を維持する疑問符の割り当てを常に選択し、その後バランスを完了することができます。 他のすべての位置は柔軟であるため、追加の構造上の制限が発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    
    open_pos = -1
    close_pos = -1
    
    for i, ch in enumerate(s):
        if ch == '(':
            open_pos = i
        elif ch == ')':
            close_pos = i
    
    if open_pos < close_pos:
        print("YES")
    else:
        print("NO")
```コードはまず、唯一の保証された開始括弧と終了括弧を識別します。 次に、それらの位置を直接比較します。 これが機能するのは、他のすべての文字が柔軟であり、これら 2 つのアンカーの相対的な順序よりも強い順序制約を強制できないためです。 

微妙な点は、疑問符をまったく付けようとしていないことです。 これは意図的なものです。それらの唯一の役割はスラックを提供することであり、固定ペアがすでに行っている以上に実現可能性を制限することはありません。 

## 実用的な例

 ### 例 1:`(? ) ? ()`固定ブラケットの位置を追跡します。 

| ステップ | インデックスを開く | インデックスを閉じる | 状態 |
 | --- | --- | --- | --- |
 | スキャン | 0 | 2 | 開く < 閉じる |

 開始括弧は終了括弧の前に表示されるため、答えは「YES」です。 

これは、疑問符を自由に配置でき、固定された構造がすでに有効な順序と一致している場合を示しています。 

### 例 2:`)?(?`| ステップ | インデックスを開く | インデックスを閉じる | 状態 |
 | --- | --- | --- | --- |
 | スキャン | 2 | 0 | 開く > 閉じる |

 ここでは、右括弧が最初に表示されます。 疑問符をどのように割り当てるかに関係なく、開き括弧がそれを補う前に閉じ括弧が発生する場所に接頭辞が存在することを避けることはできません。 答えは「ノー」です。 

これはキーの故障モードを示しています。反転した固定構造は修復できません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | テスト ケースごとに 1 回のスキャンで 2 つの固定ブラケットを特定します。 
| スペース | お(1) | 2 つのインデックスのみが保存されます。 

この制約により、長さ 100 の文字列を含むテスト ケースが最大 1000 個まで許可されるため、テスト ケースごとのリニア スキャンは十分に高速になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        open_pos = -1
        close_pos = -1
        for i, ch in enumerate(s):
            if ch == '(':
                open_pos = i
            elif ch == ')':
                close_pos = i
        out.append("YES" if open_pos < close_pos else "NO")
    return "\n".join(out) + "\n"

 ## 特殊なケース

 重大なエッジ ケースは、2 つの固定ブラケットが隣接しているものの、順序が間違っている場合です。 たとえば、入力`)(??`。 アルゴリズムは、open_pos > close_pos を即座に記録し、NO を返します。 これは正しいです。なぜなら、疑問符が存在するとしても、最初の文字がすでにプレフィックスの有効性に違反しているからです。 

もう 1 つのケースは、疑問符が文字列の大部分を占めている場合です。`??(??)?`。 ここでは、open_pos はまだ close_pos より前にあるため、アルゴリズムは YES を返します。 これが機能するのは、固定右括弧に到達するまでは接頭辞のバランスを維持するために疑問符を常に割り当てることができ、その後シーケンスを完了できるためです。 

最後のエッジケースは最小の有効な構成です`()`。 スキャンでは open_pos = 0 および close_pos = 1 が検出されるため、条件が成立し、ただちに YES が返され、通常の括弧シーケンスの定義と一致します。
