 ## 解決策
 ## 問題の理解

 正の整数が与えられます`n`バイナリ文字列として。 正の整数がいくつあるかを数える必要があります`x`のバイナリ表現が存在するように存在します。`x`以下のビットしかありません`n`、および 3 つの値`n + x`、`n | x`、 そして`n ^ x`はすべて同一です。 答えはモジュロで出力する必要があります`10^9 + 7`。 

この問題の重要な部分は、加算がビット単位の演算とまったく同じように動作する場合を理解することです。 二進加算では、次の唯一の違いは、`n + x`そして`n | x`キャリーから来ています。 両方にビットが設定されている場合`n`そして`x`、これら 2 つのビットを追加するとキャリーが作成されます。 両方の数字が入る位置がない場合は、`1`、加算は既存のビットを一緒に配置するだけであり、これはまさに OR が行うことです。 

2 番目の条件は、OR と XOR が一致する必要があることです。 両方の数字があるビットで`1`、OR は生成します`1`XOR が生成する間、`0`。 他のすべてのビット位置では、それらは等しい。 したがって、この条件には次のことも必要です`n`そして`x`セットビットを決して共有しないでください。 

どちらの要件も同じ単純な条件に帰着します。```
n & x = 0
```ここで、問題は正の整数を数えるようになります。`x`せいぜい`m`ビット、ここで`m`はバイナリ文字列の長さであり、次の位置のみを使用します。`n`ゼロがあります。 

長さの制限は、使用可能な最大のビット インデックスが次のとおりであることを意味します。`m - 1`。 の先頭ビット`n`いつもです`1`、その位置は決して使用できません`x`。 残りの位置のすべてのゼロは自由に選択できます。次のいずれかを入れることができます。`0`または`1`で`x`。 以来`x`正の値でなければなりません。すべてゼロを選択することはできません。 

入力サイズは以下に達します`10^6`ビット。 これにより、値自体が大きすぎるため、バイナリ文字列を通常の整数に変換したり、値に対して算術ループを使用したりすることが除外されます。 アルゴリズムは文字列を直接処理し、ビットごとに一定量の作業を実行して、`O(m)`解決。 

よくある間違いはそれを忘れることです`x`ゼロにすることはできません。 たとえば、次の場合`n = 111`、すべてのビットが占有されています。 設定ビットが重複していない唯一の数値は、`0`, しかしそれは許されないので、答えはこうなります。`0`。 

もう 1 つのエッジ ケースは、空きビットが 1 つだけある場合です。 入力の場合:```
m = 3
n = 101
```有効な値は、`x`だけです`{2}`なぜなら`010`の設定ビットを回避する唯一のポジティブマスクです。`n`。 正しい出力は次のとおりです。```
1
```空のマスクを減算せずにすべてのマスクをカウントするソリューションでは、誤った出力が発生します。`2`。 

## アプローチ

 強引なアイデアは、あらゆる可能性を試すことです`x`から`1`に`2^m - 1`、どうかを確認してください`n & x`はゼロであり、有効な選択肢を数えます。 上記で導出された条件は必要かつ十分であるため、これは正しいです。 問題はそれです`m`できる`10^6`, したがって、候補者の数は指数関数的に増加します。 たとえ数百ビットであっても列挙することは不可能です。 

有益な観察は、`x`独立しています。 すべてのビット位置について、`n`ゼロがある、`x`どちらかを選択してもよい`0`または`1`。 すべてのビット位置について、`n`1つあります、`x`選択を迫られる`0`。 

あれば`cnt`長さ内のゼロビット`n`、 がある`2^cnt`すべてゼロのマスクを含む可能なマスク。 以来`x`肯定的である必要があります。最終的な答えは次のとおりです`2^cnt - 1`。 

残る唯一の課題はコンピューティングです`cnt`。 バイナリ文字列をスキャンし、ゼロ文字をカウントします。 最初の文字は常に`1`、すべてのゼロ文字をカウントすると、空き位置の数が直接得られます。

 | ブルートフォース | O(2^m) | お(1) | 遅すぎる |
 | 最適 | O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列と文字列自体の長さを読み取ります。 長さは、利用可能なビット位置の数を知るためにのみ必要です。 
2. 文字列内の文字数を数えます。`0`。 このような各位置は、ビットを表します。`x`設定するかどうかは自由に選択できます。 
3. コンピューティング`2^cnt`モジュロ`10^9 + 7`、 どこ`cnt`はゼロビットの数です。 
4. 結果から 1 を減算して、無効な選択肢を削除します。`x`はゼロです。 
5. 結果のモジュロ値を出力します。`10^9 + 7`。 

機能する理由: すべての有効な`x`のゼロ位置のサブセットを選択することに対応します。`n`。 2 つの異なるサブセットは 2 つの異なる正の整数を作成し、そのようなサブセットはすべて次の条件を満たします。`n & x = 0`。 許可されない唯一のサブセットは空のサブセットです。`x = 0`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    m_line = input().strip()
    if not m_line:
        return
    m = int(m_line)
    s = input().strip()

    cnt = s.count('0')
    ans = pow(2, cnt, MOD) - 1
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装はカウント引数の直後に続きます。 文字列操作`count('0')`2 進数を整数に変換せずに、使用可能なビット位置の数を返します。 

ゼロビットの数は最大になる可能性があるため、べき乗モジュラーを使用して電力が計算されます。`10^6`。 パイソンの`pow`係数を使用すると、中間値が小さく保たれ、指数に関して対数時間で実行されます。 

1 による減算はべき乗モジュロを取得した後に行われます。`MOD`。 最後のモジュロ演算は、値が負になる場合を処理します。

## テストケース```python
import sys
import io

MOD = 10**9 + 7

def solve_io(data: str) -> str:
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    m_line = input().strip()
    if not m_line:
        return ""

    m = int(m_line)
    s = input().strip()

    cnt = s.count("0")
    return str((pow(2, cnt, MOD) - 1) % MOD)

# sample 1
assert solve_io("5\n11010\n") == "3", "sample 1"

# all bits are one
assert solve_io("4\n1111\n") == "0", "no valid x"

# only one zero bit
assert solve_io("3\n101\n") == "1", "single choice"

# minimum size
assert solve_io("1\n1\n") == "0", "one bit number"

# many zeros
assert solve_io("6\n100000\n") == "31", "all lower bits are free"

 ## 特殊なケース

 のために`n = 111`、すべての位置にはすでに`1`。 アルゴリズムはゼロの空きポジションをカウントし、計算します`2^0 - 1`、そして戻ります`0`。 これは、ポジティブな結果が存在しないという事実と一致します。`x`との重なりを避けることができる`n`。 

のために`n = 101`、唯一のゼロ位置は中央ビットです。 アルゴリズムは 1 つの空きポジションをカウントし、計算します`2^1 - 1 = 1`。 単一の有効な値は次のとおりです。`x = 010`、 そして`101 & 010 = 0`したがって、3 つの式はすべて等しいです。 

のような数値の場合`n = 100000`、すべての下位ビットは無料です。 ゼロの位置は 5 つあるため、それらの位置の空でないサブセットはすべて有効です。 答えは次のようになります`2^5 - 1 = 31`これは、アルゴリズムが最大数の選択肢を持つケースを正しく処理していることを示しています。
