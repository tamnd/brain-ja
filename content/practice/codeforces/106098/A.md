 ## 解決策
 ## 問題の理解

 この問題は、問題のリストに基づいてプレイされる 2 人用のゲームであり、各問題には個別の難易度の値があります。 難易度の値は順列を形成するため、1 から n までのすべての数字が 1 回だけ表示されます。 

観光客が最初に動き、プレイヤーは交互にターンします。 各ターンで、現在のプレイヤーは残りの問題を選択し、すぐにその難易度に等しいポイントを獲得します。 その後、その問題はプールから削除されます。 問題がなくなった時点でゲームは終了し、合計スコアがより大きいプレイヤーが勝者となります。 両方のスコアが等しい場合でも、Tourist は明示的に負けませんが、タスクでは最適なプレイでどちらが勝つかを決定するように求められます。 

重要な観察は、いつでもどの問題に挑戦できるかについての制限がないため、唯一の構造は得点ルールとターン順序によって決まるということです。 すべての値は正で明確であるため、両方のプレイヤーは可能な限り大きな残りの値を取得するよう常に動機付けられます。 

入力サイズは 100000 に達します。これにより、2 次時間で手ごとに選択肢を検索または再計算する戦略をシミュレートするソリューションは即座に除外されます。 残りのすべての要素を繰り返し検査するアプローチでは O(n^2) まで劣化し、遅すぎます。 答えは、動的シミュレーションではなく、順列の直接の組み合わせ特性に依存すると予想する必要があります。 

n が小さい場合、または順序付けが敵対的である場合、微妙なエッジ ケースが発生します。 

たとえば、n = 1 で配列が [1] の場合、Tourist が唯一の要素を取得して勝ちます。 

n = 2 で配列が [1, 2] の場合、Tourist が 2 を獲得し、Bald が 1 を獲得し、Tourist が 1 ポイント勝ちます。 ターン順序だけで勝者が決まるという素朴な考えがあるかもしれませんが、最適なプレイでは常に最大の残りの要素が選択されるため、これはすでに誤解を招きます。 

さらに深刻な問題は、配列は実際には位置ではなく、値の複数セットのみが重要であるため、配列内の「位置」を追跡しようとする戦略は無関係であるということです。 

## アプローチ

 ブルートフォース シミュレーションでは、ゲームの状態を明示的にモデル化しようとします。 各ターンで、プレイヤーは残りの要素をすべてスキャンし、何らかの戦略に従って 1 つを選択し、それを削除します。 両方のプレイヤーが常に貪欲に選択したとしても、n ターンをシミュレートし、各ターンで最大 O(n) 要素をスキャンする必要があるため、O(n^2) 時間がかかります。 これは、n = 100000 ではすでに失敗します。 

重要な単純化は、両方のプレイヤーの能力が対称的であり、完全に合理的であり、すべての手が単に残りの数字の選択であることを認識することです。 すべての値は個別であり、加算的なものであるため、唯一意味のある決定は、複数の値セットが消費される順序を決定することです。 

すべての値を降順に並べ替えると、最適なプレイでは、ターンで現在のプレイヤーに最大の残りの値が効果的に割り当てられます。 プレーヤーがより大きな値をスキップしてより小さな値を取るというシナリオはありません。これは最終的な合計を減らすだけであり、対戦相手に将来のより厳密に有利なポジションを与えるだけだからです。 

したがって、ゲームはソートされた値をツーリストとハゲの間で交互に分配することになります。 観光客が最初に選択され、次に Bald が選択されます。 

したがって、Tourist はソートされた配列の位置 0、2、4、... の値を受け取り、Bald は位置 1、3、5、... を受け取ります。 

勝者は、これら 2 つの部分列の合計を比較することによって決定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | ソート + 交互の合計 | O(n log n) | O(1) 追加 (入力以外) | 承認済み |

 ## アルゴリズムのチュートリアル

1. サイズ n の順列を読み取り、すべての値を保存します。 
2. 残りの最良の選択肢が常に最初に考慮されるように、値を降順に並べ替えます。 
3. 2 つのアキュムレータを初期化します。1 つは Tourist 用、もう 1 つは Bald 用です。 
4. ソートされた配列を反復処理します。 インデックス 0、2、4、... を Tourist に割り当て、1、3、5、... を Bald に割り当て、各値をそれぞれの合計に加算します。 
5. 2 つの合計を比較します。 厳密に観光客の合計が大きい場合、観光客が勝ちます。 そうでなければハゲが勝ちます。 

重要な推論ステップは、交互割り当てがなぜ有効なのかです。 ゲームのどの時点でも、両方のプレイヤーには同じ残りセットが表示されます。 すべての値は正で独立しているため、より大きな値が存在するときにより小さな値を採用しても、結果が改善されることはありません。 これにより、両方のプレイヤーに同じ貪欲な動作が強制され、ソートされた交互の割り当てが独自の最適な結果を表すようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    tourist = 0
    bald = 0
    
    for i, val in enumerate(a):
        if i % 2 == 0:
            tourist += val
        else:
            bald += val
    
    if tourist > bald:
        print("Tourist")
    else:
        print("Bald")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列を降順に並べ替えて、利用可能な最も強力な選択肢が常に最初に考慮されるようにします。 次に、ループは純粋にターン インデックスのパリティに基づいて値を割り当てます。これは誰が最初にプレイするかに対応し、厳密な交代を維持します。 

ここでよくある間違いは、優先キューを使用して実際のゲームの決定をシミュレートしようとしているにもかかわらず、毎ターン不必要に選択肢を再計算していることです。 これにより、結果は変わらないまま、ロジックが冗長になってしまいます。 正しい洞察は、ゲームがグローバルな降順割り当てから決して逸脱しないということです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは n = 1 です。`1 1`, 観光客はすぐに唯一の値を取得して勝ちます。 アルゴリズムはインデックス 0 を Tourist に割り当てるため、Tourist は全額を正しく取得します。 

もう 1 つのエッジ ケースは、最大値が他の値の合計よりもはるかに大きい場合です。たとえば、`100000 1 2 3 ...`。 ソート後、Tourist は常に最大の要素を最初に取得し、残りの分布に関係なく優位性を保証します。 最初の要素は常に Tourist に割り当てられるため、交互の割り当てはこれを正しく反映しています。 

最後の微妙なケースは、合計が非常に近い場合です。 例えば`3 2 1`。 ソート処理の結果、Tourist = 3 + 1、Bald = 2 が得られるため、Tourist が引き続き勝ちます。 これにより、素朴な直観がバランス調整の動きを示唆する場合でも、パリティ ベースの割り当てが最適な動作を正しくモデル化していることが確認されます。
