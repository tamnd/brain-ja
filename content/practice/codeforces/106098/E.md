 ## 解決策
 ## 問題の理解

 正三角形の集合が与えられています。 辺の長さは別個の偶数の整数であり、各三角形は元のインデックスを保持します。 

すべてのクエリに対して 3 つの数字$d_1,d_2,d_3$が与えられます。 これらは、ある内部点からの垂直距離の二乗です。$P$正三角形の三辺まで。 与えられた三角形の 1 つにそのような点が含まれるかどうかを判断する必要があります。 可能であれば、一致する三角形のインデックスを出力します。 それ以外の場合は出力します`-1`。 

入力サイズが大きいです。 三角形の数とクエリの数の両方が到達可能です$2 \cdot 10^5$。 すべてのクエリに対してすべての三角形をスキャンするソリューションでは、約$4 \cdot 10^{10}$最悪の場合の操作は完全に不可能です。 各クエリは、ほぼ一定時間または対数時間で回答される必要があります。 

厄介な点は、クエリでは距離そのものではなく二乗距離が提供されることです。 実際の距離を回復するには、平方根の合計が正三角形の高度と等しくなる場合を理解する必要があります。 

よくある間違いは、浮動小数点の平方根を計算して比較することです。 考慮する：```
n = 1
l = [14]

query:
48 3 12
```距離は$4\sqrt3$、$\sqrt3$、 そして$2\sqrt3$。 それらの合計は$7\sqrt3$、これはまさに辺の長さを伴う三角形の高度です。$14$。 浮動小数点演算では丸めエラーが発生し、クエリが誤って拒否される可能性があります。 

別の微妙なケースは次のとおりです。```
n = 1
l = [12]

query:
3 12 1
```距離は$\sqrt3$、$2\sqrt3$、 そして$1$。 それらの合計には両方が含まれます$\sqrt3$そして合理的な要素。 の整数倍はありません$\sqrt3$はその合計に等しいので、答えは次のようになります。`-1`。 おおよその数値的等価性のみをチェックするソリューションは、ここで失敗する可能性があります。 

最後のエッジケースは、距離が次の形式ではない場合です。$3a^2$:```
n = 1
l = [6]

query:
6 6 6
```それぞれの距離は$\sqrt6$。 合計は$3\sqrt6$, この問題では、これを三角形の高度にすることはできません。 正しい答えは、`-1`。 

## アプローチ

 最も直接的なアプローチは、各クエリを処理し、必要な三角形の辺の長さを計算してから、利用可能なすべての三角形をスキャンして一致するものを探すことです。 

ジオメトリ自体はシンプルです。 正三角形では、内部の点から 3 つの辺までの垂直距離の合計が高度に等しくなります。 これがヴィヴィアーニの定理です。 距離が次の場合$x_1,x_2,x_3$、 それから$$x_1+x_2+x_3 = h.$$辺の長さがあるので、$l$、$$h=\frac{\sqrt3}{2}l.$$ブルートフォースのアイデアは次のように計算します。$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}$$そしてそれが任意の三角形の高度と等しいかどうかを確認します。 たとえその計算が正確に行われたとしても、すべてをスキャンすると、$n$クエリあたりの三角形のコスト$O(nq)$、これは大きすぎます。 

重要な観察は、すべての三角形の辺の長さが均等であるという事実から得られます。 

させて$l=2k$。 すると高度はこうなります$$h=k\sqrt3.$$だから必要なのです$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}=k\sqrt3.$$毎に書く$d_i$として$$d_i=s_i^2 \cdot m_i,$$どこ$m_i$スクエアフリーです。 それから$$\sqrt{d_i}=s_i\sqrt{m_i}.$$異なる平方自由部分を持つ平方根項は、有理数に対して線形独立です。 すべての距離は正の値であるため、キャンセルはできません。 それらの合計が次の純粋な倍数に等しくなる唯一の方法$\sqrt3$すべての項にすでに正方形のない部分がある場合です$3$。 

つまり、すべての$d_i$まさにそうでなければなりません$$d_i=3a_i^2.$$それから$$\sqrt{d_i}=a_i\sqrt3,$$そして$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}
=
(a_1+a_2+a_3)\sqrt3.$$したがって$$k=a_1+a_2+a_3,
\qquad
l=2k.$$クエリ全体は次のようになります。 

1. それぞれの$d_i/3$は完全な正方形です。 
2. 平方根を合計します。 
3.辺の長さを調べる$2k$ハッシュテーブルで。 

これにより、一定時間のクエリ処理が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n+q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての三角形の辺の長さを読み取り、辺の長さから元のインデックスへのマッピングを保存します。 
2. クエリごとに、3 つの値を個別に処理します。 
3. 価値について$d$, まず、次の値で割り切れるかどうかを確認します。$3$。 そうでない場合、クエリは不可能です。 
4. コンピューティング$x=d/3$。 させて$r=\lfloor\sqrt{x}\rfloor$。 
5. 次のことを確認します。$r^2=x$。 そうでない場合は、$d$形ではありません$3a^2$, したがって、クエリは不可能です。 
6. 蓄積する$r$。 この値はまさに$a_i$。 
7. 3 つの数値を処理した後、$$k=a_1+a_2+a_3.$$必要な辺の長さは、$$l=2k.$$1. かどうかを確認します。$l$利用可能な三角形のハッシュ テーブルに存在します。 
2. 保存されたインデックスが存在する場合は出力、存在しない場合は出力`-1`。 

### なぜ効果があるのか

 正三角形の場合、内部の点から 3 つの辺までの垂直距離の合計が高度に等しくなります。 辺の長さが等しい三角形の高度$l=2k$は$k\sqrt3$。 

クエリは次の場合にのみ有効になります。$$\sqrt{d_1}+\sqrt{d_2}+\sqrt{d_3}$$はまさに次の倍数です$\sqrt3$。 すべての距離は正であるため、すべての平方根項自体が次の整数倍でなければなりません。$\sqrt3$。 したがって、それぞれ$d_i$でなければなりません$3a_i^2$。 

この条件が成立すると、高度は$$(a_1+a_2+a_3)\sqrt3,$$これは辺の長さに相当します$$2(a_1+a_2+a_3).$$アルゴリズムはこの辺の長さを正確に計算し、指定された三角形の中にそれが存在するかどうかをチェックします。 有効な三角形が欠落することはなく、報告されたすべての三角形は必要な距離の合計を満たしています。 

## Python ソリューション```python
import sys
from math import isqrt

input = sys.stdin.readline

n, q = map(int, input().split())
lengths = list(map(int, input().split()))

pos = {}
for i, l in enumerate(lengths, start=1):
    pos[l] = i

ans = []

for _ in range(q):
    d1, d2, d3 = map(int, input().split())

    total = 0
    ok = True

    for d in (d1, d2, d3):
        if d % 3 != 0:
            ok = False
            break

        x = d // 3
        r = isqrt(x)

        if r * r != x:
            ok = False
            break

        total += r

    if not ok:
        ans.append("-1")
        continue

    need = 2 * total
    ans.append(str(pos.get(need, -1)))

sys.stdout.write("\n".join(ans))
```最初の部分では、辺の長さからインデックスまでのハッシュ テーブルを構築します。 すべての辺の長さは異なるため、単純な辞書で十分です。 

クエリごとに、コードはすべての二乗距離が次の形式であるかどうかをチェックします。$3a^2$。 整数の平方根は次のように計算されます。`isqrt`これにより、すべての浮動小数点精度の問題が回避されます。 

変数`total`店舗$$a_1+a_2+a_3.$$必要な辺の長さは、`2 * total`。 辞書で調べてみると、$O(1)$答え。 

最も一般的な実装エラーは、浮動小数点平方根を使用することです。 値は次のように大きくできます。$10^{18}$となり、正確な等価比較は信頼できなくなります。`isqrt`計算全体を整数で実行します。 

もう 1 つの簡単な間違いは、辺の長さが次のとおりであることを忘れることです。$2k$、 ない$k$。 正三角形の高度は、$\frac{\sqrt3}{2}l$を解決し、$l$この 2 の係数を導入します。

 ## 特殊なケース

 次のことを考慮してください。```
1 1
6
3 3 1
```アルゴリズムは 3 番目の値を検査します。 以来`1 % 3 != 0`、すぐにクエリを拒否して出力します。`-1`。 合計には有理成分が含まれており、次の形式の高度と等しくなることはありません。$k\sqrt3$。 

考慮する：```
1 1
12
6 6 6
```それぞれの値は 3 で割り切れますが、$$6/3 = 2$$は完全な正方形ではありません。 整数の平方根チェックは失敗するため、答えは次のようになります。`-1`。 これにより、誤った治療を防ぐことができます$\sqrt6$の倍数として$\sqrt3$。 

考慮する：```
1 1
8
3 12 27
```値は以下に対応します$a_1=1$、$a_2=2$、$a_3=3$。 それらの合計は$6$、したがって、必要な辺の長さは次のようになります。$12$。 利用可能な唯一の三角形は辺の長さがあります$8$したがって、検索は失敗し、アルゴリズムは次のように出力します。`-1`。 

どの場合でも、浮動小数点演算を必要とせず、距離の正確な代数構造から直接決定が行われます。
