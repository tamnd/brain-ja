 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、以下の各値が含まれていることを意味します。$0$に$n-1$まさに一度。 この順列のすべての連続セグメントについて、そのセグメントに現れない最小の非負の整数である MEX を計算します。 タスクは、すべての可能な部分配列にわたってこれらの MEX 値を合計することです。 

直接解釈すると、すべてのサブ配列は、ゼロから始まる小さな整数のセットをどの程度すでに「カバー」しているかに応じて値を提供します。 部分配列に次のものが含まれる場合、$0,1,2,\dots,k-1$しかし行方不明です$k$の場合、その MEX は$k$。 

入力サイズが到達しました$2 \cdot 10^5$テストごとに合計なので、二次関数はすべて$n$テストケースごとに実行することは直ちに不可能です。 すべてのサブ配列を列挙するとすでにコストがかかります$O(n^2)$、それぞれの MEX を再計算すると、次の方向に進むことになります。$O(n^3)$素朴な実装では。 ウィンドウごとの周波数配列を維持しても、依然として問題が残ります$O(n^2)$が鈍くなるにもほどがあります。 

重要な構造の詳細は、順列を使用して作業していることです。 これにより重複が削除され、各番号が一意の位置に配置されるようになります。 この特性により、部分配列の状態を再計算するのではなく、値の寄与をグローバルに推論することが可能になります。 

いくつかの危険な状況は、素朴な思考が失敗する理由を明らかにします。 

順列がすでに増加している場合は、次のようになります。$[0,1,2,3]$、すべてのプレフィックスは次の欠損値に等しい MEX を持ちますが、多くのサブ配列は初期の要素をスキップするため、依然として 0 に等しい MEX を持ちます。 単純なプレフィックスのみのアプローチでは、これらの貢献が欠けています。 

順列が逆の場合、次のようになります。$[3,2,1,0]$、ほとんどのサブ配列は小さな値を見逃し、MEX は頻繁に 0 または 1 になります。サブ配列の範囲を追跡せずに値の出現だけをカウントすると、カウントが過剰になります。 

もし$0$などの最後の近くに表示されます。$[1,2,3,0]$、左側の多くの部分配列は 0 を認識しないため、他の小さな値が含まれている場合でも、MEX は 0 になります。 小さな値が存在するだけで MEX が正になると仮定するアプローチは、ここでは失敗します。 

重要な問題は、MEX が存在数だけではなく、範囲内の不在にも依存することです。 

## アプローチ

 ブルートフォース戦略は単純です。すべてのサブ配列を列挙し、周波数配列を維持し、欠損値が見つかるまで 0 から上方向にスキャンして MEX を計算します。 各サブアレイのコスト$O(n)$MEX を再計算するには、$O(n^2)$部分配列、与える$O(n^3)$最悪の場合。 増分更新を行っても、MEX スキャンにより、$O(n^2)$が遅すぎる$2 \cdot 10^5$。 

重要な観察は、視点を反転することです。 「各サブ配列の MEX は何か」を尋ねる代わりに、「各値について」を尋ねます。$k$、MEX が厳密に大きいサブ配列がいくつあるか$k$”。この変換は、部分配列の MEX が より大きいため機能します。$k$すべての値が含まれる場合に正確に$0$を通して$k$。 

これで、順列構造が強力になります。 固定の場合$k$、部分配列にすべての値が含まれるという条件$0..k$は、その左の端点がそれらの値の中で最も早く出現する前にあり、その右の終点がそれらの値の中で最も新しく出現した後であることに相当します。 

これにより、問題は間隔の範囲に限定されます。$k$、値の最小位置と最大位置を追跡します。$0..k$。 この間隔にわたるすべてのサブ配列は、最大のすべての MEX 値に 1 を与えます。$k$、これらの貢献は効率的に蓄積できます。 

増えるにつれて$k$の場合、間隔を 1 つの新しい位置だけ拡張するだけなので、現在の境界セグメントを増分的に維持できます。 

これにより、推論による問題が軽減されます$O(n^2)$サブ配列を値の線形スイープに変換$0..n-1$。

 ## アルゴリズムのチュートリアル

 各値が 1 回だけ出現するという事実を利用して、その位置を配列に格納します。`pos`。 

次に、これまでに確認された値の中で最小および最大のインデックスを維持します。 

1. アレイを構築する`pos[x]`価値のインデックスを与える`x`順列の中で。 これにより、各値が存在する場所への定時間アクセスが可能になります。 
2. 2 つの変数を初期化する`L`そして`R`価値観の位置として`0`。 この時点で、すべての値が含まれる間隔$0..0$はたったの1点です。 
3. 回答アキュムレーターを維持する`ans`そして変数`k`間隔に含まれる現在の最大値を表します。 
4. 次の各値について`k`1から$n-1$、更新して間隔を拡張します`L = min(L, pos[k])`そして`R = max(R, pos[k])`。 これにより、すべての発生をカバーする間隔が維持されます。$0..k$。 
5. 間隔を更新した後、完全に含まれるすべてのサブ配列が`[L, R]`すべての値が含まれています`0..k`したがって、少なくとも次の値までのすべての MEX 値に寄与します。`k`。 このような部分配列の数は`(L + 1) * (n - R)`。 
6. このカウントを回答の貢献度に加算して値を算出します`k`。 
7. 全体の貢献度を合計する`k`。 最終的な合計は、すべてのサブアレイの合計 MEX 合計と等しくなります。 

重要な考え方は、各拡張ステップで、少なくともいくつのサブアレイが新たに MEX を達成するかを正確にカウントするということです。`k`、これらのレイヤーはきれいに積み重ねられます。 

### なぜ効果があるのか

 このアルゴリズムは、値を処理した後の不変条件に依存します。`k`、セグメント`[L, R]`すべての数値を含む最小の間隔です`0..k`。 順列では各値が一意に配置されるため、この間隔を含むサブ配列にはこれらの値がすべて含まれている必要があります。 逆に、これらの値の少なくとも 1 つが欠けているサブ配列は完全にはカバーできません。`[L, R]`。 

これにより、必要な要素をすべて含むサブ配列と固定間隔をカバーするサブ配列の間に直接等価性が作成されます。 間隔の包含は組み合わせで計算するのが簡単であるため、MEX 寄与は、重複するサブ配列状態ではなく、独立した増分制約の合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    pos = [0] * n
    for i, v in enumerate(p):
        pos[v] = i

    L = R = pos[0]
    ans = 0

    for k in range(1, n):
        L = min(L, pos[k])
        R = max(R, pos[k])
        ans += (L + 1) * (n - R)

    print(ans)
```解決策は、順列によって一意性が保証されるため、各数値が出現する場所を記録することから始まります。 間隔`[L, R]`現在までのすべての値がすでに含まれている最小のセグメントを追跡します。`k`。 掛け算`(L + 1) * (n - R)`このセグメントを完全にカバーするサブ配列の数をカウントします。左の端点は次のいずれかから選択できます。`0`に`L`、およびどこからでも適切なエンドポイント`R`に`n-1`。 

よくある間違いは、これを MEX を持つサブ配列を正確に数えると解釈することです。`k`、しかし実際には少なくとも MEX を持つ人をカウントします。`k`。 全体の合計`k`標準的な層分解を通じて正確な MEX 合計を再構築するものです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * n
        for i, v in enumerate(p):
            pos[v] = i

        L = R = pos[0]
        ans = 0
        for k in range(1, n):
            L = min(L, pos[k])
            R = max(R, pos[k])
            ans += (L + 1) * (n - R)

        out.append(str(ans))
    return "\n".join(out)

# provided samples
assert run("2\n3\n1 2 0\n5\n0 3 2 4 1\n") == "5\n9"

# custom cases
assert run("1\n1\n0\n") == "0", "single element"
assert run("1\n2\n0 1\n") == "3", "simple increasing"
assert run("1\n2\n1 0\n") == "3", "reversed pair"
assert run("1\n4\n3 2 1 0\n") == "4", "fully reversed"

 ## 特殊なケース

 単一要素の置換の場合、唯一の部分配列の MEX が 1 に等しいですが、0 から始まる値のみを合計するため、アルゴリズムは処理後に正しく 0 を返します。 間隔が 1 点を超えて拡大することはないため、寄与は追加されません。 

次のようなソートされた順列の場合`[0,1,2,...]`、間隔はジャンプすることなく左から右に徐々に拡大し、すべてのステップが正確に寄与します`(0+1)*(n-R)`最後までどこで`R`になる`n-1`。 これは、初期のサブ配列ではすべての小さな値がすぐに蓄積されるという直観と一致します。 

逆順列の場合、最初の値は`0`一番右にあるので、`L`その間は小さいまま`R`大きいです。 これにより、`(L+1)`最小限であり、後の拡張によってのみわずかに増加します。 この構造は、ほとんどのサブ配列が早い段階で小さなプレフィックスを含まないことを正確に捉えており、ほとんどの範囲で MEX を低く保ちます。
