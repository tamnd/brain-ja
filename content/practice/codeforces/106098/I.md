 ## 解決策
 ## 問題の理解

 すべての数字について$a_i$、Meda が計算します$$f(a_i)=\prod_{p \mid a_i}\left(1-\frac1p\right)$$ここで、積は次の異なる素約数上で実行されます。$a_i$。 

最大の配列が与えられます$2 \cdot 10^5$整数、それぞれ最大$10^6$そして、計算されたすべての値の中で、異なる有理値がいくつ出現するかを決定する必要があります。$f(a_i)$。 

最初の観察は、指数は重要ではないということです。 値は、数値を何回分割するかではなく、どの素数が数値を分割するかによってのみ決まります。 例えば、$$f(12)=\left(1-\frac12\right)\left(1-\frac13\right)$$そして$$f(36)=\left(1-\frac12\right)\left(1-\frac13\right)$$両方の数値が同じ一連の異なる素因数を持っているためです。 

この制約により、試行除算によるすべての数値の因数分解が直ちに除外されます。$\sqrt{10^6}$。 最悪の場合、大まかに言うと$2 \cdot 10^5 \cdot 1000$Python ではすでに大きすぎる操作です。 すべての値が最大であるため、$10^6$、ふるいベースの前処理アプローチは自然な方向です。 

微妙な点は、2 つの異なる素約数のセットが同じ値を生成しないことです。$f$。 浮動小数点近似を保存するソリューションは、丸め後に個別の有理数が区別できなくなる可能性があるため、失敗する可能性があります。 

数字を考えてみましょう。```
6 10
```彼らの価値観は、$$f(6)=\frac12\cdot\frac23=\frac13$$そして$$f(10)=\frac12\cdot\frac45=\frac25$$これらは異なる論理です。 低精度の浮動小数点演算に基づくアプローチでは、区別すべき値がマージされる危険があります。 

もう 1 つの簡単な間違いは、数値を個別の素数集合ではなく完全な因数分解によって区別することです。 

例えば：```
2 4 8 16
```4 つの数値はすべて同じ素数セットを持っています$\{2\}$、つまり、すべての値は等しい$1/2$、答えは1です。 

## アプローチ

 ブルートフォースソリューションでは、各数値を因数分解し、次の有理数値を明示的に計算します。$$\prod_{p \mid n}\left(1-\frac1p\right),$$端数を減らしてセットに挿入します。 

式が値を直接定義しているため、これは正しいです。 ボトルネックは因数分解です。 トライアル部門まで$\sqrt{n}$番号ごとに約 1000 小切手の費用がかかります$n$近いです$10^6$。 と$2 \cdot 10^5$数字にすると、それは何億もの操作になります。 

重要な観察は次のとおりです$$f(n)=\prod_{p\mid n}\frac{p-1}{p}.$$値は、一連の個別の素約数にのみ依存します。 

ここで重要な数論的事実が登場します。 2 つの数値が素数集合を持つと仮定します。$S_1$そして$S_2$。 それから$$\prod_{p\in S_1}\frac{p-1}{p}
=
\prod_{p\in S_2}\frac{p-1}{p}.$$両辺に関係するすべての素数の積を掛けると、次のようになります。$$\prod_{p\in S_1}(p-1)\prod_{q\in S_2\setminus S_1}q
=
\prod_{p\in S_2}(p-1)\prod_{q\in S_1\setminus S_2}q.$$プライムを取る$r$それはちょうど 1 つのセットに属します。$r\in S_1\setminus S_2$。 右辺は次のように割り切れます$r$という要素が含まれているため、$r$。 左辺は次で割り切れません$r$、 以来$r\nmid (r-1)$そして$r\nmid (p-1)$そこに現れる他のすべての素因数について。 矛盾。 

したがって、値が等しいということは、素数集合が同一であることを意味します。 

問題ははるかに単純になりました。 配列内に出現する素数の異なるセットがいくつあるかを数えるだけで済みます。 

以来$a_i \le 10^6$、ふるいを使用して、すべての数値の最小の素因数を事前に計算できます。 次に、各数値を対数時間で因数分解し、その個別の素約数を抽出し、結果のタプルをセットに挿入できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n\sqrt A)$|$O(n)$| 遅すぎる |
 | 最適 |$O(A \log\log A + n\log A)$|$O(A)$| 承認済み |

 ここ$A = 10^6$。 

## アルゴリズムのチュートリアル

 1. 配列を読み取り、そこに現れる最大値を決定します。 
2. その最大値までの最小素因数ふるいを構築します。 
3. 各数値について、その最小の素因数で繰り返し除算します。 
4. 新しい素因数が見つかるたびに、それを個別の素数のリストに追加します。 
5. 因数分解を続行する前に、同じ素数の繰り返し出現をすべてスキップします。 これにより、個別の素約数セットのみが抽出されます。 
6. 個別の素数のリストをタプルに変換し、セットに挿入します。 
7. すべての数値を処理した後、セットのサイズを出力します。 

ステップ 6 が機能する理由は、タプルが素数セットを一意に識別し、上記の証明が次の値を示しているためです。$f(n)$はそのセットによって一意に決定されます。 

### なぜ効果があるのか

 すべての数字について$n$、値$f(n)$は、その個別の素約数にのみ依存します。 

2 つの異なる素約数セットが同じ値を生成できないことを証明しました。$f$。 したがって、次の値の間には 1 対 1 の対応関係があります。$f$および個別の素約数のセット。 

アルゴリズムはそれらのセットを正確に保存します。 同じセットが出現するたびに同じタプルが提供され、異なるセットが出現するたびに異なるタプルが提供されます。 個別のタプルの数は、次の個別の値の数と正確に一致します。$f$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

mx = max(a)

spf = list(range(mx + 1))
for i in range(2, int(mx ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, mx + 1, i):
            if spf[j] == j:
                spf[j] = i

seen = set()

for x in a:
    primes = []

    while x > 1:
        p = spf[x]
        primes.append(p)

        while x % p == 0:
            x //= p

    seen.add(tuple(primes))

print(len(seen))
```ふるいには、すべての数値の最小の素因数が保存されます。 これにより、各因数分解で一度に 1 つの素数を繰り返し剥がすことができます。 

内側のループは、同じ素数のすべてのコピーを削除します。 この関数は異なる素約数のみに依存するため、これは重要な詳細です。 繰り返しを削除しないと、2 や 4 などの数値は、同じ値を生成する場合でも、異なる署名を生成します。 

Python セット内でタプルを使用すると、素数セットのコンパクトな表現が提供されます。 SPF ふるいを使用する場合、因数分解では自然に素数が昇順で検出されるため、タプル表現は標準的であり、追加の並べ替えは必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    mx = max(a)

    spf = list(range(mx + 1))
    for i in range(2, int(mx ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, mx + 1, i):
                if spf[j] == j:
                    spf[j] = i

    seen = set()

    for x in a:
        cur = []
        while x > 1:
            p = spf[x]
            cur.append(p)
            while x % p == 0:
                x //= p
        seen.add(tuple(cur))

    return str(len(seen))

# provided samples
assert run("3\n2 3 4\n") == "2", "sample 1"
assert run("6\n3 9 93842 123 2 1024\n") == "4", "sample 2"

# custom cases
assert run("1\n2\n") == "1", "minimum size"
assert run("4\n2 4 8 16\n") == "1", "same prime set"
assert run("3\n6 10 15\n") == "3", "three different prime sets"
assert run("5\n30 60 90 210 2310\n") == "3", "mixed repeated sets"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 2`|`1`| 最小入力サイズ |
 |`2 4 8 16`|`1`| 同じ素数の力が崩壊します。 
|`6 10 15`|`3`| 異なる素数セットは区別されます。

 ## 特殊なケース

 次のことを考慮してください。```
4
2 4 8 16
```因数分解は同じ異なる素数タプルを生成します`(2,)`毎回。 セットは 1 つの要素で終わるため、答えは次のようになります。`1`。 指数を保持するソリューションでは、4 つの異なる署名が誤ってカウントされてしまいます。 

考慮する：```
2
6 10
```タプルは`(2,3)`そして`(2,5)`。 両方が別々に挿入され、答えが得られます`2`。 これにより、異なる素数セットが決してマージされないことが確認されます。 

考慮する：```
3
6 12 18
```すべての数値には個別の素約数があります`{2,3}`。 アルゴリズムが抽出する`(2,3)`3 つの数値すべてに対して、それを 1 回挿入して出力します。`1`。 これにより、次の定義の要求どおりに、繰り返される指数が完全に無視されることが検証されます。$f(n)$。
