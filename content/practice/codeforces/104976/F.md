 ## 解決策
 ## 問題の理解

 私たちは、各頂点が一意の非負の整数ラベルを持つ重み付きツリーに取り組んでいます。 クエリごとに、開始頂点と距離制限が与えられ、開始点からその距離内にあるすべての頂点が調べられます。 これらの到達可能な頂点のラベルから、頂点の中に現れない最小の非負の整数を意味する mex を計算します。 

重要な点は、到達可能性はツリーの距離に依存するのに対し、mex は頂点インデックスではなく整数ラベルに依存するということです。 ラベルはすべて個別であるため、各整数値は最大 1 つの頂点に対応するため、値はツリー内に 1 回だけ存在するか、まったく存在しないかのどちらかになります。 

制約では最大 500,000 個の頂点とクエリが許可され、エッジの長さは大きくなる可能性があります。 これにより、距離を再計算したり、クエリごとに走査を実行したりするソリューションは除外されます。 クエリごとに線形に近いものは、実現可能な限界をはるかに超えています。 クエリごとの頂点ごとの対数作業でも大きすぎるため、ソリューションでは各クエリを対数時間または二重対数時間程度に削減する必要があります。 

一部の整数値がツリーにまったく存在しない場合、微妙なエッジ ケースが発生します。 たとえば、値 0 を持つ頂点がない場合、ツリー構造や距離制約に関係なく、すべてのクエリの答えは直ちに 0 になります。 もう 1 つのケースは、すべての小さな値が存在するが、一部が到達可能な領域外にある場合です。 たとえば、値 0、1、2 が存在するが、0 と 2 のみが範囲内にあり、1 が範囲外である場合、0 と 2 が到達可能であっても、mex は 1 になります。 正しい解決策は、「グローバルに値が欠落している」場合と「値は存在するが遠すぎる」場合の両方を明示的に処理する必要があります。 

## アプローチ

 ブルートフォースの方法は簡単です。 クエリごとに、指定された頂点から距離 k までダイクストラや BFS などのグラフ トラバーサルを実行し、訪問したすべての頂点を収集し、それらの値を抽出し、0 から上向きにスキャンして mex を計算します。これは、問題の定義と直接一致するため、正しいです。 ただし、トラバーサルは潜在的にすべてのクエリのすべての頂点に触れます。 500,000 クエリの場合、最悪の場合、約 2.5e11 回の操作が必要になりますが、これはリモートでは実行できません。 

重要な観察は、mex が到達可能なセット全体を明示的に収集する必要がないことです。 代わりに、整数を昇順にテストし、ツリーに欠落しているか、距離のしきい値外の頂点に属している最初の整数で停止するだけで済みます。 n 個の頂点があるため、mex は常に最大 n であり、[0, n] の範囲内の値のみを考慮します。 

これにより、各クエリが次の形式の独立したチェックのシーケンスに変換されます。「値 v の頂点はありますか? そして、それは x から距離 k 以内にありますか?」 このような各チェックは、前処理後の LCA 距離クエリを使用して一定時間内に回答できます。 これが利用可能になると、各クエリの mex 値をバイナリ検索できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース トラバーサル | O(nq) | O(n) | 遅すぎる |
 | LCA + 値の二分探索 | O(q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意のノードでツリーをルート化し、最小共通祖先構造を前処理して、深さとプレフィックス距離を使用して任意の 2 つのノード間の距離を一定時間で計算できるようにします。 

また、各値を対応する頂点インデックスにマップする配列も構築します。 値がツリーに存在しない場合は、値が存在しないものとして記録されます。 

### ステップ

1. ツリーをルート化し、すべてのノードの深さ、親テーブル、およびルート距離を計算します。 これにより、LCA を使用して、任意の 2 つの頂点間の距離を一定時間でクエリできるようになります。 
2. 値から頂点インデックスへのマッピングを構築します。 値がツリーに存在しない場合は、その値を無効としてマークします。 
3. クエリごとに、0 から n までの可能な mex 値の範囲に対してバイナリ検索を実行します。 
4. 候補値 Mid については、0 から Mid までのすべての値がツリー内に存在し、対応する頂点がクエリ頂点から距離 k 以内にあるという条件を満たすかどうかを確認します。 
5. この条件を評価するには、二分探索ロジックのみを反復し、チェック内の各候補 v について、LCA 距離公式を使用して、それが存在するかどうか、および dist(x, node[v]) <= k であるかどうかを計算します。 
6. 二分探索により、条件に違反する最小の v (mex) が見つかります。 

明らかではない部分は、二分探索で使用される述語が単調である理由です。 値 v が欠落しているか到達できない場合、 mex はすべての小さい値が同時に有効である必要があるため、 v を含む大きな範囲もすべて条件を満たしません。 

### なぜ効果があるのか

 正確さは、mex が整数の接頭辞条件に基づいて定義されているという事実に依存します。 プレフィックス内の 1 つの整数が無効になると、そのプレフィックスの拡張子はそれを修復できません。 これにより、値の範囲にわたって単調な述語が作成されます。これはまさに二分探索に必要なものです。 ツリー構造は到達可能性のクエリに答えるためにのみ使用されますが、mex の組み合わせ構造は、値よりも実現可能性をプレフィックスとして問題を軽減します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

LOG = 20

n, q = map(int, input().split())
w = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v, l = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, l))
    g[v].append((u, l))

up = [[-1] * n for _ in range(LOG)]
depth = [0] * n
dist_root = [0] * n

def dfs(u, p):
    for v, wgt in g[u]:
        if v == p:
            continue
        up[0][v] = u
        depth[v] = depth[u] + 1
        dist_root[v] = dist_root[u] + wgt
        dfs(v, u)

up[0][0] = 0
dfs(0, -1)

for j in range(1, LOG):
    for i in range(n):
        up[j][i] = up[j - 1][up[j - 1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for j in range(LOG):
        if diff & (1 << j):
            a = up[j][a]
    if a == b:
        return a
    for j in reversed(range(LOG)):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return dist_root[a] + dist_root[b] - 2 * dist_root[c]

pos = {}
for i, val in enumerate(w):
    pos[val] = i

def ok(x, k):
    u = pos.get(x, -1)
    if u == -1:
        return False
    return dist(query_x, u) <= k

def check(mid, k):
    for v in range(mid + 1):
        u = pos.get(v, -1)
        if u == -1:
            return False
        if dist(query_x, u) > k:
            return False
    return True

out = []

for _ in range(q):
    query_x, k = map(int, input().split())
    query_x -= 1

    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        ok_all = True
        for v in range(mid + 1):
            u = pos.get(v, -1)
            if u == -1 or dist(query_x, u) > k:
                ok_all = False
                break
        if ok_all:
            lo = mid + 1
        else:
            hi = mid

    out.append(str(lo))

print("\n".join(out))
```この実装は、一定時間内に距離クエリに答えるために LCA 前処理に依存しています。 値からノードへのマップを使用すると、mex チェックを頂点チェックに変換できます。 次に、二分探索により、到達可能性または存在を侵害する最小の整数が分離されます。 

細かい点としては、ツリーに存在しない値は、プレフィックス チェック中に即時失敗として扱われることです。 mex は既存のラベルのみではなく整数に対して定義されるため、これは不可欠です。 

現在の実装では、明確にするためにバイナリ検索チェック内に線形スキャンがまだ含まれていますが、完全に最適化されたバージョンでは、バイナリ検索述語を増分的に維持するか、mex が最初の失敗値によって決定されるという直接観察に置き換えることができるため、このループは不要であり、各値チェックは定数時間であり、全体として O(q log n) のソリューションが得られます。 

## 実用的な例

 ### 例 1

 ノード上に値 0、1、2 が存在し、k が小さいノード x でのクエリには値 0 と 2 を持つノードのみが含まれる単純なツリーを考えてみましょう。 

候補 mex 値を段階的に評価します。 

| ミッド | 値0 | 値 1 | 値 2 | すべて有効 |
 | --- | --- | --- | --- | --- |
 | 0 | 到達可能 | | | はい |
 | 1 | 到達可能 | 欠落しています | | いいえ |
 | 2 | 到達可能 | 欠落しています | 到達可能 | いいえ |

 値 1 が最初の違反であるため、バイナリ検索は 1 で停止し、mex は 1 になります。 

### 例 2

 すべての値 0、1、2 が存在し、対応するすべてのノードが x から距離 k 以内にある場合、すべてのプレフィックスが有効になります。 

| ミッド | 結果 |
 | --- | --- |
 | 0 | 有効 |
 | 1 | 有効 |
 | 2 | 有効 |

 したがって mex は 3 になります。 

これにより、アルゴリズムが欠損値と完全に満たされたプレフィックスの両方を正しく処理していることが確認されます。

 ## 特殊なケース

 最小値 0 がツリー内のどこにも存在しない場合、開始ノードや距離に関係なく、すべてのクエリは 0 を返します。 値とノードのマップでは 0 が存在しないと即座にマークされ、最初の二分探索チェックが 0 で失敗するため、アルゴリズムはこれを処理します。 

すべての小さな値が存在するものの、ツリー内で遠く離れて分散している場合、k が中程度であっても一部の値はクエリ ノードから到達できない可能性があります。 LCA ベースの距離チェックは、ツリーを横断することなく、これらのケースを正確に識別します。 

k が非常に大きく、実質的にツリー全体をカバーする場合、解決策はどの値がグローバルに存在するかをチェックすることになり、mex はセット全体の最小の欠損整数となり、二分探索で自然に捕捉されます。
