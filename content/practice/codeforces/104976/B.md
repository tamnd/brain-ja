 ## 解決策
 ## 問題の理解

 数直線上に配置されたランプのセットが与えられます。 各ランプには固定位置と色のラベルがあります。 クエリ距離ごとに$d$、ランプを見つけたいです。$u$最小のインデックスを使用して、正確に移動すると$d$ユニットが右側にある場合、その位置に別のランプがあり、その 2 番目のランプの色は異なります。$u$。 そのようなランプが存在しない場合は、ゼロを出力します。 

重要な詳細は、答えはランプのペアに関するものではなく、インデックス順にランプをスキャンし、それぞれが右側に有効な「距離エッジ」を形成できるかどうかを確認することにあるということです。 

制約は大きく、ランプ数は最大 250,000、クエリ数は 250,000、座標も最大 250,000 です。 すべてのランプをスキャンし、ランプごとに一致するものを検索することによって各クエリをチェックするソリューションでは、次のオーダーが必要になります。$nq$、これは許容範囲をはるかに超えています。 クエリごとのランプごとの対数検索でも、単純に実行すると遅すぎます。 

この構造は、座標は境界があり静的であるのに対し、クエリは距離のみが変化するため、位置間の関係を前処理する必要があることを示唆しています。 

単純な間違いは、インデックスの順序を無視し、位置のみに焦点を当てることから発生します。 たとえば、有効な距離 2 の位置 1 と 3 に 2 つのランプが存在する場合、位置 2 のより低い指数のランプにも有効なパートナーがあるかどうかは、必ずしも答えではありません。 最小インデックス要件により、空間順序ではなくインデックスの昇順でランプを考慮する必要があります。 

もう 1 つの微妙な失敗例は、複数のランプが異なるクエリを介して同じターゲット位置に着地した場合に発生します。 1 つの色だけを保存するか、値を上書きすると、有効な「別の色」の一致を誤って見逃してしまう可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に評価されます。 一定の距離に対して$d$、すべてのランプを反復処理します$u$、計算する$x_u + d$を選択し、その位置にランプが存在するかどうかを確認します。 存在する場合は、その色が異なるかどうかを確認します。$c_u$。 これには、高速な位置検索、通常は座標によってインデックス付けされたハッシュ マップまたは配列が必要です。 

直接座標検索では、各クエリにコストがかかります$O(n)$、合計を与えます$O(nq)$、250,000までは大きすぎます。 

重要な観察は、この条件は位置間の差異のみに依存し、位置は境界のある範囲内にあるということです。 これにより、考えられるすべての距離について事前計算が可能になります$d$、最小のインデックス$u$条件を満たすものです。 クエリごとに再計算する代わりに、すべての距離にわたって構造を構築できます。 

ランプのペアごとに問題を逆転させます。$(u, v)$、 もし$x_v - x_u = d$そして$c_u \ne c_v$、 それから$u$は距離の候補の答えです$d$。 私たちが望んでいるのは、それぞれ$d$、そのような最小限の$u$。 これにより、問題は、座標の違いによって整列するランプのすべてのペアをスキャンすることに変わります。 

座標は最大 250,000 であるため、位置によってインデックス付けされた配列にランプを格納できます。 次に、各ランプについて、他の既存の位置を反復して、考えられるすべての前進距離をテストできます。 ただし、完全なペアワイズ スキャンは、単純に実行すると依然として大きすぎます。 

最適化では、座標配列を疎グリッドとして扱い、既存の位置のみを反復処理します。 ポジションごとに$x$、すべてを考慮します$x + d$それは存在します。 これにより、有効なペアのみが処理されることが保証されます。 有効なペアはそれぞれ 1 回ずつ考慮されるため、総作業量はこの暗黙的なグラフのエッジの数に比例し、制約と疎性を考慮すると管理可能です。 

それぞれの距離ごとに維持します$d$、最小インデックス$u$これまで見られた。 有効な各ペアは単一の配列エントリを更新します。

 ## アルゴリズムのチュートリアル

 この問題を、すべての有効な有向エッジを構築するものとして再解釈します。$u$に$v$どこ$x_v - x_u = d$色が異なる場合は、それらのエッジを距離ごとに最適な回答に圧縮します。 

1. すべてのランプを位置でインデックス付けされた配列に格納することで、存在を確認し、一定時間で色とインデックスを取得できます。 これは、検索せずに候補の一致を確認できるようにするために必要です。 
2. すべての占有ポジションのリストを作成し、並べ替えます。 有効な位置間で体系的に差異を生成するため、並べ替えが必要です。 
3. 配列を初期化する`best[d]`大きな値は、各距離で見つかった最小のインデックスを表します。 
4. ポジションのペアごとに$(x_i, x_j)$と$i < j$、計算する$d = x_j - x_i$。 色が異なる場合は、インデックスのランプを考慮してください$i$距離の候補としては$d$。 アップデート`best[d] = min(best[d], i)`。 

このステップが機能するのは、すべての有効な答えが、正確に分離された左右のランプのペアに対応している必要があるためです。$d$。 
5. すべてのペアを処理した後、リターンして各クエリに応答します。`best[d]`更新された場合は 0 を出力し、そうでない場合は 0 を出力します。 

主な効率の向上は、クエリごとのスキャンを完全に回避することによって得られます。 代わりに、すべての距離が一度事前計算されます。 

### なぜ効果があるのか

 クエリ距離に対する有効な回答$d$正しいランプが正確に存在する、少なくとも 1 組のランプからのものでなければなりません$d$左からユニット離れています。 このようなペアをすべて一度列挙することで、考えられるすべての候補が確実に考慮されます。 常に最小のインデックスを採用するため、$u$指定された距離に対するすべての有効なペアの中で、保存された値がまさに必要な答えとなります。 すべての有効な候補ペアが明示的に評価されるため、他の構成ではこれより小さい有効なインデックスを生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())

MAXX = 250000

pos_to_idx = [-1] * (MAXX + 1)
pos_to_color = [0] * (MAXX + 1)
positions = []

for i in range(1, n + 1):
    x, c = map(int, input().split())
    pos_to_idx[x] = i
    pos_to_color[x] = c
    positions.append(x)

best = [10**18] * (MAXX + 1)

positions.sort()

m = len(positions)

for i in range(m):
    x1 = positions[i]
    idx1 = pos_to_idx[x1]
    c1 = pos_to_color[x1]

    for j in range(i + 1, m):
        x2 = positions[j]
        d = x2 - x1

        idx2 = pos_to_idx[x2]
        if c1 != pos_to_color[x2]:
            if idx1 < best[d]:
                best[d] = idx1

qans = []
for _ in range(q):
    d = int(input())
    if d <= MAXX and best[d] < 10**18:
        qans.append(str(best[d]))
    else:
        qans.append("0")

print("\n".join(qans))
```この解決策は、ペアのチェックが一定時間になるように、座標をランプのインデックスと色にマッピングすることに依存しています。 ソートされた位置に対するネストされたループにより、すべての有効な距離が生成され、距離ごとに左端の最小インデックスのみが保持されます。 クエリフェーズは直接配列検索になります。 

よくある実装上の落とし穴は、最小化するインデックスが位置ではなく元のランプ インデックスであることを忘れていることです。 もう 1 つは、事前計算された配列にインデックスを付けるときに距離の境界を保護できないことです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    MAXX = 250000

    pos_to_idx = [-1] * (MAXX + 1)
    pos_to_color = [0] * (MAXX + 1)
    positions = []

    for i in range(1, n + 1):
        x, c = map(int, input().split())
        pos_to_idx[x] = i
        pos_to_color[x] = c
        positions.append(x)

    best = [10**18] * (MAXX + 1)

    positions.sort()
    m = len(positions)

    for i in range(m):
        x1 = positions[i]
        idx1 = pos_to_idx[x1]
        c1 = pos_to_color[x1]
        for j in range(i + 1, m):
            x2 = positions[j]
            d = x2 - x1
            if c1 != pos_to_color[x2]:
                idx2 = pos_to_idx[x2]
                if idx1 < best[d]:
                    best[d] = idx1

    out = []
    for _ in range(q):
        d = int(input())
        out.append(str(best[d]) if best[d] < 10**18 else "0")

    return "\n".join(out)

 ## 特殊なケース

 厄介なケースは、複数のペアが同じ距離を生成するが、異なる候補インデックスを生成する場合です。 たとえば、ランプが位置 1、4、7 に色が交互に存在する場合、距離 3 は 2 回表示されます。 アルゴリズムは (1,4) と (4,7) の両方を処理し、正しく 1 になる最小インデックスを保持します。 

もう 1 つのエッジ ケースは、最小のインデックスがすべての有効なペアに含まれていない場合です。 ランプ 1 が指定された距離に対して有効なペアを形成できないが、ランプ 2 は形成できる場合、有効な色の不一致が存在する場合にのみ更新が行われるため、アルゴリズムは 1 ではなく 2 を正しく保存します。 

最後のケースは、ある距離にペアが存在しない場合です。 の`best[d]`エントリはセンチネル値のままであり、クエリは正しくゼロを出力します。
