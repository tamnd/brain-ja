 ## 解決策
 ## 問題の理解

 文字列のシーケンスが与えられ、個々の文字列内の文字を自由に並べ替えることができます。 これらの再配置の後、すべての連続するペア間に構造的な互換性条件が必要になります。つまり、各文字列は前の文字列の周期的な拡張である必要があります。 具体的には、2つの文字列を固定すると、$a$そして$b$、 それから$a$の期間です$b$繰り返すとき$a$周期的に生成する$b$正確に、不一致なく。 

重要な自由度は、各文字列を任意に再配置できるため、各文字列内の複数の文字セットのみが問題となることです。 タスクは、この周期的な関係がチェーン全体を保持するように、すべての文字列内の文字を並べ替えることができるかどうかを決定し、可能であれば、有効な最終構成を構築することです。 

制約により、線形時間または線形に近い解決策が強制されます。 すべてのテスト ケースの合計文字数は最大で次のとおりです。$5 \cdot 10^6$したがって、各文字を一定の回数だけ処理するあらゆるアプローチが受け入れられます。 文字列間のペアごとのチェックや長さ全体の繰り返し一致を伴うものはすべて、すぐに失敗します。 

ローカルな実現可能性がグローバルな実現可能性と誤解される場合、微妙な失敗例が現れます。 たとえば、たとえ$s_{i-1}$個別に分割できる$s_i$文字数の観点から言えば、制約はチェーン全体で一貫している必要があります。 

次のことを考慮してください。 

入力:```
3
abc
aabbcc
ab
```単純な考えでは、隣接する各ペアを個別に照合しようとするかもしれません。 最初のペアは問題ありません。`abc`の期間を形成することができます`aabbcc`。 しかし、最後の文字列は`ab`～と互換性のある取り決めが必要です`aabbcc`中間構造によって異なる繰り返しパターンが強制されると、一貫性が損なわれる可能性があります。 

もう 1 つの特殊なケースは、長さがひどく相互作用する場合です。```
2
ab
aab
```どちらもローカルで互換性のある文字があるにもかかわらず、`ab`の期間にすることはできません`aab`なぜなら、3 は 2 で割り切れず、再配置してもこの構造的制約は修正されないからです。 

したがって、問題は周波数の一致だけではなく、すべての文字列に伝播する一貫した基本パターンを確保することにもあります。 

## アプローチ

 各文字列内で文字を任意に交換することは、各文字列が単なるマルチセットであることを意味します。 唯一意味のある疑問は、すべての文字列が前の文字列を繰り返すことによって構築されるような順列を各文字列に割り当てることができるかどうかです。 

定義から始めると、次のようにします。$s_{i-1}$の期間です$s_i$。 それから$s_i$ある長さのブロックを繰り返して形成する必要があります$|s_{i-1}|$、そのブロックはまさに$s_{i-1}$。 これは、強力な構造上の制約を意味します。チェーン内のすべての文字列は、単一の進化する「基本サイクル」と互換性がなければなりませんが、基本は長さの可分性と一致する方法でのみ変更できます。 

ブルートフォースのアイデアでは、各文字列のすべての順列を構築し、有効なチェーンが存在するかどうかを確認しようとします。 それは文字列ごとの階乗であり、すぐには不可能です。 

より良い観点は、周期条件を逆にすることです。 もし$s_{i-1}$の期間です$s_i$、その後、すべての文字がカウントされます$s_i$の対応するカウントの倍数でなければなりません$s_{i-1}$、スケールによって$|s_i| / |s_{i-1}|$。 つまり、候補の配置を決定したら、$s_1$、以降のすべての文字列は、それに関連する互換性のある周波数パターンに強制されます。 

ここで重要な点がわかります。自由に並べ替えることができるため、各文字列は本質的に周波数ベクトルです。 基本パターンが存在するかどうかを見つける必要があります$P$すべての文字列をコピーに分割できるようにする$P$、そしてこれらのコピーはチェーンに沿って一貫しています。 これにより、問題は、長さの割り算がスケーリングを決定する、単一の進化するマルチセット制約とすべての文字列が互換性を持つようにできるかどうかのチェックに集約されます。 

最初から構築するのではなく、最初の文字列以降の一貫性を貪欲に強化します。 各ステップで、前の文字列は必要な「ブロック構造」を定義し、次の文字列はそのサイズの等しいブロックに再配置できる必要があります。 

ブルートフォース | O(∑ |s_i|!) | お(1) | 遅すぎる

 最適 | O(∑ |s_i|) | O(Σアルファベット) | 承認されました

 ## アルゴリズムのチュートリアル

 現在の「基本期間」の候補構造を維持しながら、文字列を左から右に処理します。 

1. 最初の文字列の頻度カウントを計算し、それを最初のベース ブロックとして扱います。 このブロックは 1 つの完全な期間単位を表します。 
2. 次の各文字列について、その長さが現在の基本長で割り切れるかどうかを確認します。 そうでない場合、繰り返しには正確なタイリングが必要となるため、チェーンを周期的にすることはできません。 
3. 繰り返し係数を次のようにします。$k = |s_i| / |base|$。 の各文字の頻度が正しいかどうかを検証します。$s_i$等しい$k$ベースの周波数の倍になります。 これが失敗した場合、並べ替えによってカウントが保持されるため、再配置しても問題を解決できません。 
4. 有効な場合、ベースは変更しません。 ベースは、前方に伝播する最小の繰り返し単位のままです。これを拡大すると、後の一貫性が難しくなるだけです。 
5. すべての文字列を処理した後、それぞれを構築します$s_i$基本パターンを正確に繰り返すことによって$k_i$回、どこで$k_i = |s_i| / |base|$。 

重要な点は、最初の文字列が可能な最小の期間を決定し、答えが存在する場合、後続のすべての文字列は強制的にそれに従うことです。 

### なぜ効果があるのか

 不変条件は、処理後のものです。$i$文字列の場合、基本周波数ベクトルは、その繰り返しによって以前のすべての文字列を生成できる有効な期間を表します。 有効なソリューションでは、周波数構造がすべての処理された文字列を同時に分割する基底を使用する必要があります。 いずれかの時点で文字列を基本周波数ベクトルの整数倍として表現できない場合、文字数は不変であるため、再配置してもこの不一致を修復できません。 したがって、固定ベースを維持すると、必要なすべての制約が維持されると同時に、誤検知が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = [input().strip() for _ in range(n)]

        base = Counter(s[0])

        ok = True
        for i in range(1, n):
            cnt = Counter(s[i])
            if len(cnt) == 0:
                ok = False
                break

            # check divisibility of lengths
            if len(s[i]) % len(s[i-1]) != 0:
                ok = False
                break

            k = len(s[i]) // len(s[i-1])

            # derive expected base scaling
            for ch in cnt:
                if cnt[ch] % k != 0:
                    ok = False
                    break
            if not ok:
                break

        if not ok:
            print("NO")
            continue

        # construct answer using first string sorted as base pattern
        base_pattern = ''.join(sorted(s[0]))

        res = []
        for i in range(n):
            k = len(s[i]) // len(base_pattern)
            res.append(base_pattern * k)

        print("YES")
        print("\n".join(res))

if __name__ == "__main__":
    solve()
```コードは最初に、単に長さと文字数の割り算によって、各文字列を前の文字列と位置合わせできるかどうかをチェックします。 これは、任意の置換の下での周期的繰り返しによって課せられる必要条件です。 

構築フェーズでは、任意の順列が許可されるため、最初の文字列をソートすることで正規のベースを修正します。 このベースを選択すると、それを必要な回数繰り返すことですべての文字列が埋められます。 

実装の微妙な点は、初期化後にベースを動的に調整しようとしないことです。 そうすると、複数のステップにわたる繰り返しの一貫性によって実際には許可されない自由度が誤って導入されてしまいます。

 ## 特殊なケース

 次のような単一文字のチェーン`["a", "aa", "aaa"]`基本が自明の 1 文字であり、すべての長さが 1 の倍数であるため、合格します。 アルゴリズムは塩基を次のように扱います。`a`、すべての文字列が周波数スケーリング条件を満たします。 

みたいな失敗例`["ab", "aba"]`長さの可分性をチェックするときにすぐに拒否されます。 両方に有効な文字が含まれている場合でも、3 は 2 で割り切れないため、繰り返しブロックは存在しません。 アルゴリズムは、周波数推論の前にこのチェックで停止します。 

などの並び替えが混在するケース`["abc", "bca", "cab"]`すべての文字列が同一の周波数ベクトルと等しい長さを共有するため、常に受け入れられます。 最初の文字列を並べ替えた後も基数は固定されたままで、後続のすべての文字列は必要な繰り返し係数 1 に一致します。
