 ## 解決策
 ## 問題の理解

 すでに非常に特殊な形状を持つシーケンスが与えられています。最初は 1 つの最低点まで厳密に下降し、その点以降は厳密に上昇します。 言い換えれば、独特の「谷」インデックスがあり、その左側にあるものはすべて段階的に下に移動し、その右側にあるものはすべて段階的に上に移動します。 

このシーケンスから、連続したセグメントを選択することができますが、選択したセグメントが同じ「V 字型プロパティ」を持っていることを確認する必要があります。 このようなすべての有効なセグメントの中で、可能な限り最大の平均値を持つセグメントが必要です。これは、合計を長さで割った値を最大化することを意味します。 

重要な点は、妥当性とは部分配列を選択することだけではないということです。 選択したセグメント自体には、厳密な減少部分とそれに続く厳密な増加部分が 1 つ存在する必要があります。 この構造は、許可されるサブ配列を強く制限します。 

この制約により、すべてのテスト ケースの合計の長さが 3×10^5 に達することが許可されます。 これにより、配列またはすべての部分配列に対する二次関数のアプローチが即座に除外されます。 テスト ケースごとにすべてのセグメント、またはすべての左右の組み合わせを列挙するものは存続できません。 ソリューションは、テスト ケースごとに本質的に線形または線形演算的である必要があります。 

最良のセグメントがグローバルバレーを回避すると仮定すると、微妙な故障モードが現れます。 たとえば、これらの領域には大きな値が含まれる可能性があるため、減少するプレフィックスのみまたは増加するサフィックスのみを取得することは魅力的に思えますが、そのようなセグメントには、転換点を伴う減少フェーズと増加フェーズの両方を含めることはできないため、有効な V 字型ではありません。 したがって、有効な答えには元の谷インデックスが含まれている必要があります。 

もう 1 つの落とし穴は、最良のセグメントが常に谷の中心にしっかりと集中していると仮定することによって発生します。 たとえば、9 7 1 2 10 11 12 のようなシーケンスでは、さらに右に拡張すると、値に応じて平均が薄まるか、改善される可能性があります。 最適なセグメントは、非常に高い値を取得することと、長さを増やすコストを支払うこととの間のバランスです。 

## アプローチ

 直接的なアプローチは、谷のインデックスを含むすべての可能なサブ配列を試すことです。 有効な V 字型部分配列にはグローバル最小位置が含まれている必要があるため、問題は、l ≤ i ≤ r (i は谷のインデックス) となるように l と r を選択することになります。 

厳密に減少するシーケンスを制限しても厳密に減少したままであり、厳密に増加するシーケンスを制限しても厳密に増加したままであるため、このようなすべてのサブ配列は有効です。 これは、谷を修正すると構造上の制約が自明になり、妥当性が自動的に保証されることを意味します。 

したがって、タスクは純粋に数値的なものになります。i を含むすべてのセグメントの平均合計を最大化します。 

ブルート フォース手法では、すべてのペア (l、r) をチェックし、合計を計算し、長さで除算します。 テスト ケースごとにそのようなセグメントが O(n^2) あり、プレフィックスの合計は定数係数を減らすだけです。 合計要素が 3×10^5 の場合、最悪の場合の複雑さは 10^10 の演算程度になるため、これは非常に遅くなります。 

重要な洞察は、「合計/長さの最大化」という条件を決定問題に再定式化することです。 比率を直接最大化する代わりに、候補の平均を差し引いた後の調整スコアが負でない i を含むセグメントが存在するかどうかを尋ねます。 これにより、問題は目標平均を達成できるかどうかを確認することに変換されます。 

固定の候補値 x の場合、配列を各要素が a_j − x になる新しい配列に変換します。 変換された合計が少なくとも 0 である場合に限り、セグメントは少なくとも x の平均を持ちます。 唯一の追加の制約は、セグメントに谷インデックスを含める必要があることです。これにより、問題が i を中心とする左右の寄与に自然に分割されます。

有効なセグメントはすべて、i で終わる左拡張と i で始まる右拡張の結合であるため、固定 x の左側と右側から最適な寄与を独立して計算できます。 各辺は、修正されたスコアリング関数を使用した片面配列上の古典的な最大部分配列問題になります。 

これにより、O(n) での実現可能性チェックが可能になり、十分な精度で答えをバイナリ検索します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | valley | を含むすべてのセグメントを列挙します。 O(n^2) | お(1) | 遅すぎる |
 | 二分探索 + 線形実行可能性チェック | O(n 対数精度) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 谷のインデックスを i で表します。 

1. テストしたい候補平均値 x を修正します。 概念的には、すべての要素を a_j − x に変換します。 変換された値の合計が負でない場合、セグメントは正確に少なくとも x の平均を持ちます。 
2. i を含む有効なセグメントを 2 つの独立した部分に分割します。i で終わる左側の部分と、i で始まる右側の部分です。 変換された合計の合計は、両方の部分の合計に i での中心値の調整を加えたものです。 
3. 可能な限り最良の左寄与を計算します。 i で終わり、左方向に伸びるすべてのセグメントを調べます。 各開始位置 l ≤ i について、a_l から a_i までの変換された合計を評価します。 そのような最大値が必要です。 
4. 同様に、可能な限り最良の正しい寄与を計算します。 i から始まり r ≥ i までのすべてのセグメントを考慮し、a_i から a_r までの最大変換合計を計算します。 
5. 最適な左、最適な右、中央の調整を組み合わせます。 それらの合計がゼロ以上の場合、平均が少なくとも x である i を含む有効なセグメントが存在します。 
6. x に対して二分探索を使用します。 答えは、実現可能性チェックで true が返される最大値です。 

### なぜ効果があるのか

 谷を含むすべての有効なセグメントは、左の延長部分と右の延長部分に一意に分割されます。 x を減算することによる変換により、平均条件が線形になるため、目的はこれら 2 つの独立した側面にわたって加算的になります。 各辺で独立して最大化するため、有効なセグメントが非負の変換合計を達成した場合、各辺を最大化する分割でも少なくともその値が達成されることが保証されます。 これにより、実現可能性チェックの正確性が維持され、二分探索が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)

    # find valley (unique minimum)
    i = min(range(n), key=lambda k: a[k])

    def can(mid):
        # left side: best suffix ending at i
        best = 0
        cur = 0
        for j in range(i, -1, -1):
            cur += a[j] - mid
            best = max(best, cur)

        left_best = best

        # right side: best prefix starting at i
        best = 0
        cur = 0
        for j in range(i, n):
            cur += a[j] - mid
            best = max(best, cur)

        right_best = best

        # combine, but a[i] counted twice so adjust once
        return left_best + right_best - (a[i] - mid) >= 0

    lo, hi = 0.0, 1e9

    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid):
            lo = mid
        else:
            hi = mid

    return lo

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(f"{solve_case(a):.12f}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、まず全体的な最小値をスキャンして谷のインデックスを特定します。 有効な V 字型部分配列にはこの位置が含まれている必要があるため、これで十分です。 

実現可能性チェックでは、線形スキャンを使用して、左側と右側で個別に達成可能な最良の変換合計を構築します。 どちらのスキャンでも、シフトされた値 a_j −mid の下の谷で終わる、または谷で始まる最適なサブ配列が効果的に計算されます。 

谷要素は両方のスキャンに含まれているため、最終的な組み合わせでは、谷要素の重複した寄与が差し引かれます。 

二分探索は固定反復で実行され、必要な誤差許容範囲内の精度を確保します。 

## 実用的な例

 小さなシーケンスを考えてみましょう。```
a = [9, 6, 2, 3, 8]
```谷はインデックス 2 (値 2) にあります。 

候補の平均 x = 5 をテストします。 

| ステップ | 左スキャン (i で終わる) | 右スキャン (i から開始) | 最良の値 |
 | --- | --- | --- | --- |
 | 初期化 | カーソル = 0 | カーソル = 0 | ベストL = 0、ベストR = 0 |
 | 左を展開 | 2-5、6-5、9-5 を累積 | - | bestL はサフィックスに基づいて更新されます |
 | 右に展開 | - | 2-5、3-5、8-5 を累積 | bestR はプレフィックスに基づいて更新されます |

 結合結果が負の場合、平均 5 は大きすぎます。 

ここで、x = 4.5 について考えてみましょう。 

変換された合計が改善され、結合された値が負でなくなる可能性があり、実現可能性を示します。 

これは、決定手順が全体的な比率の最適化を谷付近の 2 つの局所的な線形最適化にどのように変換するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():
        t = int(input())
        res = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

            i = min(range(n), key=lambda k: a[k])

            def can(mid):
                best = cur = 0
                for j in range(i, -1, -1):
                    cur += a[j] - mid
                    best = max(best, cur)
                left = best

                best = cur = 0
                for j in range(i, n):
                    cur += a[j] - mid
                    best = max(best, cur)
                right = best

                return left + right - (a[i] - mid) >= 0

            lo, hi = 0.0, 1e9
            for _ in range(50):
                mid = (lo + hi) / 2
                if can(mid):
                    lo = mid
                else:
                    hi = mid

            res.append(str(lo))
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 重要なエッジ ケースは、最適なセグメントが非常に小さい場合であり、おそらく谷と両側の 1 つの隣接セグメントだけである場合があります。 このような場合でも、実行可能性チェックで最小限の拡張が正しく評価されるため、バイナリ検索は引き続き機能します。 

もう 1 つのエッジ ケースは、谷を除くすべての値が同一である場合に発生します。この場合、最良のセグメントは、平均を大きく変えることなく両方向に大きく伸びる可能性があります。 左と右の両方の寄与が同じ変換値の下で線形に増加するため、アルゴリズムはこれを処理します。 

3 番目のケースは、一方の方向に拡張すると平均が向上し、他方の方向に拡張すると平均が低下する場合です。 分割の最適化により、両側が独立して最大化されるため、非対称構成が見逃されることはありません。
