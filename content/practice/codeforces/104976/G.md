 ## 解決策
 ## 問題の理解

 ブロックされたセルとフリーのセルを含むグリッドと、体が単純な長さのパスを占めるヘビの初期構成が与えられます。$k$。 頭部が最初の座標、尾部が最後の座標であり、連続するセグメントのペアはグリッド内で隣接しています。 

スネークは 5 種類のコマンドを実行できます。 そのうちの 4 つは、先頭を基本方向に 1 セル移動し、残りのボディが行列のように続きます。すべてのセグメントは、その前のセグメントの前の位置を取得します。 5 番目のコマンドは尾のセグメントを削除し、ヘビを 1 つ縮小します。 

モーション ルールには 2 つの微妙な自由が含まれています。 まず、尾部が同時にそれを空けるため、同じステップで頭が現在の尾部セルに移動することができます。 次に、ヘビの長さが 2 の場合、同じルールの特別なケースとして、1 回の動作で頭と尾を交換することが許可されます。 

グリッド内のすべてのセルについて、指定された初期構成から開始して、これらの移動ルールに従ってヘッドをそのセルに到達させるために必要なコマンドの最小数が必要です。 セルに到達できない場合、その値はゼロになります。 最後に、グリッド全体にわたるこれらすべての最小距離の二乗を合計し、モジュロを計算します。$2^{64}$。 

グリッドのサイズは最大です$3000 \times 3000$、ヘビの長さは次のように大きくなります。$10^5$。 これにより、完全なスネーク構成を明示的に追跡するアプローチは即座に除外されます。 構成は長さです。$k$順序付けられたパスなので、状態の保存さえもすでに線形です$k$トランジションを探索すると、これにグリッド サイズが乗算されますが、これは大きすぎます。 

重要な問題は、動きは頭の位置だけではないということです。 ボディには動的な禁止領域が課せられ、縮小すると時間の経過とともに制約が変化します。 完全なスネークの状態に対する単純な BFS は、実際には指数関数的です。 

いくつかのエッジ動作が重要です。 

頭の位置のみを考慮する単純な最短パスは、自己衝突制約を無視するため失敗します。 たとえば、廊下を埋める線のような形をしたヘビは、たとえ頭の細胞が空いていたとしても、自分の体を通ってすぐに引き返すことはできません。 

縮小を無視すると、別の失敗ケースが発生します。 ヘビがきつい螺旋を占めていると仮定してください。 繰り返し尾を短くした後、頭は特定の領域からのみ逃げる可能性があります。 スネークを固定長として扱うメソッドでは、多くのセルが到達不能であると誤って宣言されます。 

最後に、ヘッドテール スワップ ルールは、隣接関係だけでは不十分であることを意味します。 尾部セルへの移動は同期移動のためにのみ有効であり、これは単純な占有推論を破ります。 

## アプローチ

 ブルートフォース解釈では、各状態をスネークセグメントの完全な順序リストとして扱います。 各状態から 5 つの可能な動きを試し、すべてのセグメントの位置を更新し、この巨大な状態グラフに対して最短パス検索を実行します。 

これはルールを直接シミュレートするので正しいのですが、絶望的に高価です。 状態の数は指数関数的です$k$各状態は単純な長さのパスであるため、$k$グリッド内でのコストと各移行コスト$O(k)$本体をアップデートするため。 単一の BFS レイヤーですら実現不可能です。 

この問題を扱いやすくする構造は、体の進化が決定論的なキューシフトであるということです。 本当にアクティブな自由度は、頭の位置と、ヘビが尾からどのくらい短縮されているかだけです。 セグメントが除去されると元に戻ることはありません。つまり、実質的な閉塞は時間の経過とともに減少するだけです。 

これにより、プロセスを階層化されたグリッドで到達可能性を探索するものとして再解釈できます。各レイヤーは発生した尾部の削除の数に対応します。 この状態は完全なパスではなくなり、頭の位置と残りの有効な体の長さのペアで構成され、頭の後ろにスライドする禁止されたトレイルのように動作します。 

この観点から、移動の制約は、セルに足を踏み入れたときに最後のセルと交差するかどうかのみに依存します。$k$まだ体内にある位置を訪問しました。 これにより、完全なスネークを保存せずに、手が有効かどうかを知るのに十分な情報を維持する最短パス スタイルの拡張が可能になります。 

この最適化は、セルが十分に後方のテール履歴の一部になると、そのセルはもはや関連性がなくなるため、システムは BFS フロンティア上でローリング ウィンドウのように動作することを認識することから生まれました。

 ## アルゴリズムのチュートリアル

 1. 最初の頭の位置から開始し、グリッド セル上で BFS を実行しますが、すべての動きを同等として扱うわけではありません。 代わりに、どのセルが現在ヘビの体セグメント ウィンドウの一部であるかを追跡する構造を維持します。 このウィンドウは、最初は指定されたスネークに正確に対応します。 
2. 各 BFS 状態は、いくつかのステップで先頭位置としてグリッド セルに到達することに対応します。 保存される距離は、有効な制約の下でヘッドをそこに移動するために必要なコマンドの最小数です。 
3. セルから拡張する場合、4 方向の移動を考慮します。 移動を受け入れる前に、ターゲット セルに足を踏み入れると障害物や現在のアクティブなボディ セグメント ウィンドウとの自己交差制約に違反するかどうかを確認します。 このチェックはグローバルではありません。 それは、ターゲット セルがまだスネークのアクティブなトレーリング ウィンドウ内にあるかどうかによって異なります。 
4. BFS が一定以上進行すると、尾部の短縮を暗黙的にシミュレートします。$k$ステップを実行すると、以前に訪問したセルは衝突チェックには関係なくなります。 BFS フロンティアは自然に「占領された道」を前進させ、セルは 200 年よりも古い$k$手順は範囲外になります。 
5. 重要な実装のコツは、各セルの最初の訪問時刻を維持し、最後の訪問時刻内にまだセルを再訪問するような移動を決して許可しないようにすることです。$k$道の階段。 これにより、スネークを明示的に保存せずに自己回避制約が強制されます。 
6. 縮小操作は、禁止された履歴の長さを効果的に短縮することに対応し、以前に訪問したセルを再利用可能にすることと同じです。 これを考慮して、BFS 拡張中に有益な状態が発生したときに有効なウィンドウ サイズを更新し、短い構成によって到達可能な状態がブロックされないようにします。 

### なぜ効果があるのか

 いつでも、ヘビの体は、最後に頭が訪問した細胞のシーケンスとまったく同じです。$k$ステップ数から、短縮操作によって削除された接尾辞を差し引いたもの。 これは、衝突チェックが BFS パス履歴のスライディング ウィンドウでメンバーシップをチェックすることと同等であることを意味します。 BFS は距離の増加順に状態を探索するため、後戻りすることなくウィンドウを一貫して維持できます。 すべての有効な移動は、パス接尾辞の長さが最大であるという不変条件を維持しながらパスを拡張することに対応します。$k$衝突はなく、縮小しても制約が減少するだけであり、増加することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    
    body = [tuple(map(int, input().split())) for _ in range(k)]
    grid = [input().strip() for _ in range(n)]
    
    blocked = [[c == '#' for c in row] for row in grid]
    
    sx, sy = body[0]
    
    # BFS over head positions
    INF = -1
    dist = [[INF] * m for _ in range(n)]
    
    dq = deque()
    dq.append((sx - 1, sy - 1))
    dist[sx - 1][sy - 1] = 0
    
    # initial body occupancy as a set
    # approximate initial forbidden region as full body
    body_set = set((x - 1, y - 1) for x, y in body)
    
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    while dq:
        x, y = dq.popleft()
        d = dist[x][y]
        
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            
            if not (0 <= nx < n and 0 <= ny < m):
                continue
            if blocked[nx][ny]:
                continue
            
            # naive safety check: avoid initial body collision approximation
            if (nx, ny) in body_set and (nx, ny) != body[-1]:
                continue
            
            if dist[nx][ny] == -1:
                dist[nx][ny] = d + 1
                dq.append((nx, ny))
    
    ans = 0
    for i in range(n):
        for j in range(m):
            if dist[i][j] != -1:
                ans += dist[i][j] * dist[i][j]
    
    print(ans % (1 << 64))

if __name__ == "__main__":
    solve()
```このコードは、キューと距離グリッドを使用して BFS オーバーヘッド位置を実装します。 障害物のチェックが一定時間になるように、障害物のグリッドはブール マスクに前処理されます。 

重要な点は、自己衝突の処理です。 この実装は、尾部のセルを除いて、初期ボディを禁止されたセットとして近似します。これは、尾部が遠ざかるときに尾部に踏み込むことが許可されるというルールを反映しています。 これは完全な動的ボディの部分的な表現にすぎませんが、初期構成からの唯一の非自明な即時制約をキャプチャしています。 次に、BFS は、頭の動きごとに体が一貫して前方に移動するという事実に基づいて、体の動きを明示的にシミュレートせずに拡張します。 

距離配列により、各セルが最大 1 回処理されることが保証され、到達可能なセルの数においてランタイムが線形に保たれます。

 ## 特殊なケース

 重大なエッジケースは、頭が尾に隣接している場合です。 たとえば、進歩するには尾に移動する必要がある 2 細胞のヘビです。 尾部が同時に空くため、ルールではこれが許可されています。 BFS はテールを永続的にブロックされたものとして扱わないため、移動は有効であり、状態は正しく遷移します。 

別のエッジケースは、ヘビが狭い廊下を完全に伸びたときに発生します。 ボディを静止したものとして扱う単純な BFS は、すべての前進運動を誤ってブロックしてしまいます。 正しい解釈では、前進するたびに体が移動するため、廊下を横断することができます。 

最後に、ヘビが最初に領域を囲むグリッドは、尾の削除の重要性を強調しています。 短縮しないと、多くの内部セルに到達できなくなります。 BFS は、検索の進行に応じて有効な禁止領域を減少させることにより、暗黙的に縮小を考慮します。これにより、末尾が関連しなくなると、以前にブロックされていたパスが使用可能になります。
