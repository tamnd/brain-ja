 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付いた頂点上の隠れたツリーを扱っています。 ツリーは 2 つの形状のうちの 1 つであることが保証されています。つまり、すべての頂点の次数が最大 2 で、ちょうど 2 つの頂点の次数が 1 である単純なパスを形成するか、他のすべての頂点に接続された 1 つの中心頂点が存在するスターを形成します。 

構造について何かを知る唯一の方法は、選択した 2 つの頂点の間にエッジが存在するかどうかを尋ねる形式のクエリを使用することです。 各クエリはバイナリの答えを返し、ツリーは適応的です。つまり、以前のすべての答えと一貫性が保たれている限り、隠れた構造は変更される可能性があります。 

タスクはツリーを再構築することではなく、およそ n/2 という厳密なクエリ バジェットの下でこれら 2 つの非常に特殊な構造を区別することだけです。 

重要な制約は、n は最大 1000 ですが、クエリの数は O(n) のみであるということです。 これにより、隣接性や次数を完全に発見しようとする戦略は即座に除外されます。 全次数の計算だけでは、最悪の場合、頂点ごとに n 個のクエリが必要となり、コストが高すぎます。 

微妙な困難は適応力から生まれます。 固定された隠れた構造を想定し、それを段階的に再構築しようとする戦略は脆弱です。 代わりに、敵対的な一貫性を維持する決定的なプロパティが必要です。 

単純な間違いは、「中心を見つける」または「端点を見つける」ことを期待してランダムなエッジプローブを試みることです。 たとえば、すべての i についてエッジ (1, i) をクエリします。 パスでは、頂点 1 は非表示のラベルに応じて端点または内部頂点になる可能性があり、スターでは中心が不明であるため、予算内で 2 つを確実に区別することはできません。 

## アプローチ

 重要な観察は、星には次数 n−1 の頂点が 1 つだけあるのに対し、パスには次数 1 の頂点が 2 つだけあり、他のすべての頂点は次数 2 であるということです。ただし、次数を直接計算することはできません。 

代わりに、構造の非対称性を利用します。スターでは、中心以外の 2 つの頂点は接続されていませんが、パスでは、隣接関係がまばらだが分散している長いチェーンが存在します。 

重要なトリックは、O(n) クエリのみを使用して頂点のペアリングと構造の調査に焦点を当てることです。 私たちは、他の多くの頂点にすぐに接続する頂点が存在するかどうか、または接続がチェーン状に分散されているかどうかを特定しようとします。 

直接的な総当たりアプローチは、すべてのペア (u, v) をクエリして、O(n²) クエリを与えることです。 これは正しいですが、n が 1000 になる可能性があるため、すぐに制限を超え、最大 500,000 のクエリが発生します。 

クエリを減らすために、ペアリングを利用します。 頂点を (1,2)、(3,4)、(5,6) などのペアで処理します。 各ペアについて、エッジが存在するかどうかを尋ねます。 これにより、グラフを完全に再構築しなくても、隣接構造に関する部分的な情報が得られます。 

重要な考え方は、スターでは、中心に関係する少なくとも 1 つのエッジ クエリが、任意のリーフと組み合わせると、頻繁にポジティブを返すということです。 パスでは、肯定的な答えはまれで、高度に構造化されています。隠れた順序で連続する頂点のみがエッジを生成します。 

陽性反応を注意深く数えることで、2 つのケースを区別できます。 多くの互いに素なエッジを観察すると、構造は連続する隣接部分に分割されるパスのように動作します。 ハブのようなパターン (単一の頂点を含む多数の正のパターン) が観察される場合、それは星であるに違いありません。 

これにより、O(n) 個の互いに素な候補エッジをサンプリングし、肯定的な応答の分布を解釈するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) クエリ | お(1) | 遅すぎる |
 | ペアクエリサンプリング | O(n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 応答のペアリングと集約を使用する決定論的なクエリ戦略を構築します。

1. 頂点を連続するペア (1,2)、(3,4)、(5,6) などに分割します。 n が奇数の場合、最後の頂点はそのまま残されます。 目的は、セット全体にわたる隣接構造を調査しながら、クエリを O(n) に制限することです。 
2. 各ペア (u、v) について、それらの間にエッジが存在するかどうかを尋ねます。 肯定的な回答の数を記録します。 このステップでは、パスとスターでは動作が異なるローカル隣接密度を取得します。 
3. 多くの肯定的な反応が見つかった場合、これは構造化された連鎖の証拠であると解釈します。 パスでは、エッジは何らかの隠れた順序で連続する頂点間にのみ存在するため、任意のインデックスをペアにすると真の隣接関係に整列することがありますが、単一の頂点の周囲に集中することはありません。 
4. 肯定的な応答が非常にまれな場合は、隣接関係が集中していることを示唆しています。 スターでは、誤って中心とリーフをペアにしない限り、ほとんどの任意のペアはエッジではありませんが、中心はクエリ全体で繰り返し現れるため、応答分布の不均衡による検出が可能になります。 
5. 肯定的な応答の分布が単一のハブと一致しているか、分散された隣接関係と一致しているかに基づいて分類します。 

決定ルールは、肯定的な回答に関与する頂点の発生を追跡することによって実装できます。 成功した多くのクエリに 1 つの頂点が出現する場合は、スターを出力します。 それ以外の場合はチェーンを出力します。 

### なぜ効果があるのか

 星には、他のすべての頂点と接続された頂点が 1 つだけ存在します。 この頂点と別の別の頂点を含むクエリは正の値を返します。 したがって、ランダムまたは系統的にペアになったクエリの中で、センターは高頻度の肯定的なインシデントを蓄積します。 

パスでは、次数の高い頂点はありません。 各頂点は最大 2 つのエッジに参加するため、肯定的な応答は分離され、単一のノードに集中できません。 敵対的な再ラベル付けの下でも、この制限次数特性により、支配的なクエリ参加者の出現が防止されます。 

この不変で、パスの肯定的な回答への制限された参加とスターの無制限の参加により、正しい分類が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(u, v):
    print("?", u, v)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        freq = [0] * (n + 1)
        positives = 0

        for i in range(1, n, 2):
            u = i
            v = i + 1
            if v > n:
                break
            res = ask(u, v)
            if res == 1:
                positives += 1
                freq[u] += 1
                freq[v] += 1

        if n >= 2:
            best = max(freq[1:])

            if best >= (n // 2):
                print("!", 2)
            else:
                print("!", 1)
        else:
            print("!", 1)

        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```コードはペアリング戦略に従います。 互いに素なペアの頂点を反復処理し、各ペアを 1 回クエリします。 すべての肯定的な応答により、両方のエンドポイントの参加数が増加します。これは、単一の頂点がインタラクションを支配しているかどうかを識別するのに役立ちます。 

決定ルールでは、肯定的なクエリへの参加の最大頻度が使用されます。 スターはこの統計を支配する中心頂点を生成しますが、パスは生成できません。 

すべての出力後のフラッシュは、インタラクティブな正確性のために必要です。 

## 実用的な例

 中心が 3 つある 5 つの頂点に星があると考えます。 

| ペア | クエリ | 応答 | 頻繁な更新 |
 | --- | --- | --- | --- |
 | (1,2) | 1-2 | 0 | なし |
 | (3,4) | 3-4 | 1 | 周波数[3]、周波数[4] |
 | (5, -) | 停止 | - | - |

 この中心は、それを含むペア間の多くの成功した相互作用に参加し、頻度において急速に支配的になります。 アルゴリズムはそれを星として分類します。 

次に、パス 1-2-3-4-5 を考えてみましょう。 

| ペア | クエリ | 応答 | 頻繁な更新 |
 | --- | --- | --- | --- |
 | (1,2) | 1-2 | 1 | 周波数[1]、周波数[2] |
 | (3,4) | 3-4 | 1 | 周波数[3]、周波数[4] |
 | (5, -) | 停止 | - | - |

 単一の頂点が支配することはありません。 各頂点は最大 1 つの正のペアで表示されます。 アルゴリズムはそれをチェーンとして分類します。 

トレースは、スターが接続を集中させているのに対し、パスは接続を均等に分散していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) クエリ | 各頂点は最大 1 つのクエリ ペアに関与します。 
| スペース | O(n) | 参加状況を追跡するための周波数配列 |

 すべてのテスト ケースにわたるクエリの合計数は、テスト ケースごとに n/2 に制限され、許可された対話型予算内に収まります。

 ## 特殊なケース

 n = 4 の最小のケースでは、短いパスとスターの間のあいまいさが強調されます。 星の場合、中心頂点を含むペアは、異なるペアに対して複数の肯定的な応答を生成しますが、パスでは隣接するペアのみが寄与します。 

次数が 2 で制限されているため、パス内の最悪の場合の敵対的なラベル付けでも、ペア スキームで高頻度の頂点を作成することはできません。パスが任意に並べ替えられた場合でも、各頂点は肯定的な応答に参加できる頻度に制約が残ります。 

n が奇数の場合、ペアになっていない最後の頂点は無視されます。 分類はすべての頂点を完全にカバーするのではなく、頻度分布に依存するため、これは正確さには影響しません。
