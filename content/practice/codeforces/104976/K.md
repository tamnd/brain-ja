 ## 解決策
 ## 問題の理解

 1 枚ずつ列に配置されたカードを表す一連の整数が与えられます。 シーケンスを左から右に処理すると、特別なキャンセル ルールを備えたスタックのように動作する別のシーケンスが維持されます。 

新しいカードが到着すると、そのカードは現在のシーケンスの最後に追加されます。 この値が現在のシーケンスでこれまでに出現したことがない場合は、それ以上何も起こりません。 以前に出現したことがある場合は、最後に最も近い前の出現を見つけて、その以前の出現から新しく追加されたカードまでのすべてを削除します。 これは、構造に同じ値の 2 つのアクティブな出現が決して含まれないことを意味します。値が繰り返されると、最近の 2 つの出現の間でセグメントの「崩壊」がトリガーされます。 

配列全体を処理した後は、最終シーケンスをグローバルに要求されません。 代わりに、複数の質問に答える必要があります。 各クエリは元の配列の範囲を与え、その部分配列のみを処理した場合の最終シーケンスの長さを計算する必要があります。 

この難しさは、クエリがオンラインであり、前の回答と XOR エンコードされているため、順序を尊重せずにすべてのクエリを個別に前処理することができないという事実に起因します。 この制約により、最大 300,000 個の要素と 300,000 個のクエリが許可され、クエリごとのシミュレーションやセグメントの二次スキャンが除外されます。 たとえ$O(n \sqrt{n})$各クエリ自体が広範囲に影響する可能性があり、動的構造の再計算にコストがかかるため、このソリューションは危険です。 

単純なアプローチでは、各クエリのプロセスを個別にシミュレートします。 単一の範囲については、リストを維持し、セグメントの挿入と削除を繰り返します。 削除するたびに多くの要素が削除される可能性があり、これはクエリ全体で次のようになります。$O(n)$最悪の場合、クエリごとに、$O(nq)$、それは限界をはるかに超えています。 

最後に発生したものだけをグローバルに保持し、すべてのクエリで再利用しようとすると、より微妙な障害モードが発生します。 これは、キャンセルの動作が制限されたサブ配列に厳密に依存するため、問題が発生します。クエリ範囲外の要素は存在すべきではないため、「一致するペア」への影響はなくなります。 

小さな例で落とし穴を明らかにします。 配列が次のようになっているとします。$[1, 2, 1, 2]$。 完全な配列では、すべてがキャンセルされて空のシーケンスになります。 でも範囲内では$[2, 3]$、シーケンスは次のとおりです$[2, 1]$、それ以上キャンセルされません。 グローバル キャンセル ペアを再利用するソリューションでは、サブ配列に実際に存在するキャンセルよりも強力なキャンセルが誤って想定されてしまいます。 

## アプローチ

 重要な観察は、プロセスがスタックのように動作し、各値が常に以前の不一致の出現とのみ相互作用し、その相互作用によってそれらの間のセグメントが完全に消去されることです。 これは、すべての要素が「現在開いている間隔」として存続するか、そのような間隔を閉じることによって削除されることを示唆しています。 

固定配列に対してプロセスを左から右にシミュレートすると、インデックスのスタックを維持できます。 各値は、現在のスタック内の最後の位置を格納します。 繰り返される値が見つかった場合は、前の値が削除されるまでポップし、実質的に連続するサフィックス セグメントを削除します。 

これは、あらゆるポジションについて、維持に相当する構造を即座に示唆します。$i$、前回の発生$a_i$アクティブな構造内で。 現在の有効なスタック内で最も近い前の出現がわかれば、スタックを効率的に維持できます。 

本当に難しいのは、範囲クエリに答えることです。 処理後の最終スタック サイズのみが必要です$a_\ell \ldots a_r$。 これは、答えが範囲内の等しい要素間の相互作用に依存する古典的な設定であり、それらの相互作用は位置間のエッジとして表すことができます。 

重要な再定式化は、各位置について、親ポインターの観点から考えることです。$i$、 させて$p_i$以前に発生したことである$a_i$(何もない場合は 0)。 プロセスは本質的につながります$i$に$p_i$ただし、次の場合に限ります。$p_i$現在のスタック内でまだ「生きている」。 各クエリは次のようになります: 範囲内$[\ell, r]$、ペアを繰り返し削除した後に生き残るポジションの数$(p_i, i)$ここで、両方のエンドポイントが範囲内にあり、有効なキャンセル チェーンを形成します。 

これは、セグメントにわたる機能構造内の一致しない要素をカウントするという問題になります。この問題は、スタックのようなロールバックのアイデアと組み合わせたセグメント ツリーによって、時間の経過とともに効率的に処理されます。 ただし、よりクリーンなビューは、インデックスのセグメント ツリーに対する永続的なスタック シミュレーションを使用してクエリを処理することです。セグメントごとに、空の入力からそのセグメントを処理した場合に得られるスタック状態を維持します。 

各セグメントには、入力スタックを出力スタックに変換する方法の圧縮表現が格納されます。 2 つの隣接するセグメントを結合するとき、右セグメントの出力を左セグメントへの入力として供給することをシミュレートします。 キャンセルは LIFO 順序で一致する値にのみ依存するため、セグメント状態内の最後の出現を追跡するスタック マージ手法を使用して相互作用を解決できます。 

古典的な最適化では、各セグメントを一致しない要素の「縮小シーケンス」で表し、左側の接尾辞と右側の接頭辞の間のキャンセルをシミュレートすることによって 2 つのセグメントをマージしますが、これらの圧縮表現のみが対象となります。 各要素はセグメント ツリーのレベルごとに最大 1 回だけ縮小形式に出入りできるため、合計の複雑さはクエリごとに対数のままになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション |$O(n^2)$最悪の場合 |$O(n)$| 遅すぎる |
 | スタックをマージしたセグメント ツリー |$O(n \log n)$|$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列上にセグメント ツリーを構築します。各ノードは、最初は空のスタック上でサブ配列を処理した結果を表します。 

各ノードは、そのセグメント内の一致しない値の縮小されたスタックのようなベクトルを格納します。 
2. リーフ ノードの場合、縮小表現は単に次の内容を含む単一要素スタックです。$a_i$1 つの要素内ではキャンセルできないためです。 
3. 内部ノードの場合、左の子の縮小表現を取得し、右の子の縮小表現をそれに「フィード」します。 

これは、スタック プロセスをシミュレートすることによって行われます。右ベクトルを反復処理し、同じキャンセル ルールを現在の左ベクトルに対して適用します。 
4. このマージ中に、値から現在の縮小スタック内の最後の出現位置までのマップを維持します。 

すでに存在する値が見つかった場合は、その前の値が削除されるまでスタックから要素を削除し、その後、新しい値を追加します。 
5. マージ後、結果として縮小されたスタックがノードの格納状態になります。 この状態は、そのセグメントのみを処理した後に残っているものを正確に表します。 
6. 質問に答えるには$[\ell, r]$、その範囲の結合された縮小スタックをセグメント ツリーにクエリします。 答えは単純に、縮小されたスタックのサイズです。 

これが機能する理由は、削減されたスタックがセグメントの処理後の状態を完全に特徴付けるためです。今後の処理は、すでに解決された内部キャンセルには依存せず、残っているもののみに依存します。 これにより、元の配列を再度参照することなくセグメント結果をマージできる構成構造が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    def __init__(self):
        self.st = []

def merge(a, b):
    if not a.st:
        return b
    if not b.st:
        return a

    res = a.st[:]
    last = {}

    for i, v in enumerate(res):
        last[v] = i

    for v in b.st:
        if v in last:
            idx = last[v]
            res = res[:idx]
            last = {x: i for i, x in enumerate(res)}
        else:
            last[v] = len(res)
            res.append(v)

    a.st = res
    return a

def build(a, v, l, r, seg):
    if l == r:
        seg[v].st = [a[l]]
        return
    m = (l + r) // 2
    build(a, v*2, l, m, seg)
    build(a, v*2+1, m+1, r, seg)
    seg[v] = merge(seg[v*2], seg[v*2+1])

def query(v, l, r, ql, qr, seg):
    if ql <= l and r <= qr:
        return seg[v]
    m = (l + r) // 2
    if qr <= m:
        return query(v*2, l, m, ql, qr, seg)
    if ql > m:
        return query(v*2+1, m+1, r, ql, qr, seg)
    left = query(v*2, l, m, ql, qr, seg)
    right = query(v*2+1, m+1, r, ql, qr, seg)
    return merge(left, right)

n, q = map(int, input().split())
a = list(map(int, input().split()))

seg = [Node() for _ in range(4*n)]
build(a, 1, 0, n-1, seg)

lastans = 0
for _ in range(q):
    x, y = map(int, input().split())
    l = x ^ lastans
    r = y ^ lastans
    l -= 1
    r -= 1
    res = query(1, 0, n-1, l, r, seg)
    lastans = len(res.st)
    print(lastans)
```セグメント ツリーは、各ノードがその間隔の圧縮されたスタック表現を格納するように構築されます。 マージ関数はコア ロジックです。元のプロセスで使用されたのと同じキャンセル ルールを適用して、1 つの縮小スタックを別のスタックにフィードすることをシミュレートします。 

クエリ関数は、セグメントを正しい順序で結合して、範囲にわたってマージされた表現を収集します。 最終的な答えは、結果として縮小されたスタックのサイズです。 

クエリはデコード後に 1 から始まりますが、内部構造は 0 から始まるため、インデックス付けには注意が必要です。 もう 1 つの微妙な点は、切り捨て後に以前のインデックスが無効になるため、マージ中に最後に出現したマップを再計算する必要があることです。 

## 実用的な例

 サンプルの順序を検討してください$[2, 3, 1, 1, 1]$。 セグメントがどのように動作するかを追跡します。

 | ステップ | 処理されたセグメント | スタック状態 |
 | --- | --- | --- |
 | 1 | [2] | [2] |
 | 2 | [2、3] | [2、3] |
 | 3 | [2、3、1] | [2、3、1] |

 これは、繰り返される要素によって接尾辞部分がどのように消去されるか、また、将来のマージでは削減された構造のみが重要となる理由を示しています。 

次に、クエリの例を考えてみましょう。$[1, 4]$対$[2, 5]$。 の上$[1, 4]$、最後のスタックは$[2, 3]$。 の上$[2, 5]$、最初の要素が消え、インタラクション パターン全体が変化するため、キャンセルは異なります。 

| クエリ範囲 | 結果のスタック | 答え |

 トレースでは、セグメントの動作がグローバル ペアリングではなく内部構造に厳密に依存していることが確認されています。

 ## 特殊なケース

 最小のエッジ ケースは、長さ 1 のセグメントです。 アルゴリズムはそれをリーフ ノードとして扱い、キャンセルが不可能であるという事実と一致して、サイズ 1 のスタックを直接返します。 

より微妙なケースは、キャンセルが完全にセグメント内で発生するが、境界を越えて発生しない場合です。 たとえば、$[1, 2, 1, 2]$、完全なセグメントは空になりますが、次のように分割されます。$[1, 2]$そして$[1, 2]$空ではない中間状態を生成します。 セグメント ツリーのマージは、削減された状態を順番に再結合し、境界を越えてキャンセルを再適用するため、正確性が保証されます。 

もう 1 つの重要なケースは、次のような長いギャップのある値の繰り返しです。$[1, 2, 3, 1, 2, 3]$。 ここでは、すべての値が削除のカスケードをトリガーします。 各マージでは一致しない値のみが保持され、縮小されたスタックの強制切り捨てが重複して行われ、介在するすべての要素がインタラクションごとに 1 回だけ削除されるため、アルゴリズムはこれを正しく処理します。
