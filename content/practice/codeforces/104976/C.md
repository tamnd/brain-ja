 ## 解決策
 ## 問題の理解

 大きな無向重み付きグラフと、多くの独立したクエリが与えられます。 各クエリは、指定された 2 つの頂点間を移動する最も安価な方法を要求しますが、ルートで使用できるエッジは最大 3 つであるという厳しい制限があります。 

したがって、一般的な最短パスを求める代わりに、直接エッジ、ちょうど 1 つの中間頂点を通る 2 つのエッジのパス、またはちょうど 2 つの中間頂点を通る 3 つのエッジのパスなど、非常に短いウォークのみを考慮することができます。 安くても長ければ意味がありません。 

グラフ自体は非常に大きくなり、最大 100 万頂点と 100 万エッジになるため、クエリごとにグラフ検索を行う余裕はありません。 クエリの数も最大 100 万件に達するため、すべての有用な情報を一度計算して一定時間内に応答する必要がある前処理アプローチが必要になります。 

重要な構造上の制約は、グラフが平面であることです。 実際には、これはスパース性を意味します。つまり、エッジの数は頂点の数に対して線形であり、平均次数は制限されたままになります。 これが、短い散歩を列挙することが可能な隠れた理由です。 

主なエッジ ケースは、最適な答えがさまざまなパス長から得られる可能性があり、場合によっては最適なパスが一意ではないという事実から生じます。 たとえば、直接エッジは高価ですが、両エッジ ルートは安価である可能性があります。 

すべての長さを比較する必要性を示す小さな例:

 入力:```
3 3
1 2 10
2 3 1
1 3 100
1
1 3
```正しい出力:```
11
```単純な最短パス アルゴリズムでは、重み 100 の直接エッジを見つけて停止し、安価な 2 エッジ ルートを見逃してしまう可能性があります。 さらに重要なことは、3 つのエッジよりも長いパスは許可されていないため、標準のダイクストラは不要であるため、グローバルな探索は無駄な作業となります。 

もう 1 つの微妙なケースは、同じエンドポイント間に複数の短いウォークが存在する場合です。 すべての有効な歩行のうち、最小重量のみを維持する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリを独立して処理します。 各ペアごとに`(s, t)`、最大 3 つのエッジのみを許可する境界付き BFS またはダイクストラ検索を実行できます。 これでも、近隣の近隣、および場合によってはそれらの近隣の近隣を探索します。 最悪の場合、アルゴリズムはターゲットがどこにあるかを知らず、深さ 3 に達する前に広範囲に拡張する可能性があるため、この限定検索でもクエリごとに最大 O(m) エッジを訪問する可能性があります。 クエリが 100 万件に達すると、これは完全に不可能になり、密度が高い場合は約 10¹² の操作が必要になります。 

重要な観察は、深さの制限が非常に小さく、固定されているということです。 すべての有効な答えは、単一エッジ、2 エッジ チェーン、または 3 エッジ チェーンの 3 つの構造形式のうちの 1 つのパスに対応します。 これは、動的に検索する必要がまったくないことを意味します。 代わりに、グラフ全体で最大 3 つの長さの考えられるパスをすべて 1 回列挙し、そのエンドポイントとコストを計算し、順序付けされたペアごとに最適な結果を保存できます。 

平面性により、グラフが十分にまばらになり、そのような短いパスをすべて列挙しても実際には線形のままになります。 各頂点には平均して一定数の近傍しかないため、長さ 2 および長さ 3 のウォークをすべて拡張しても組み合わせ爆発は起こりません。 

これにより、問題はローカル近傍に対する前処理タスクに変換され、クエリごとに O(1) ハッシュ ルックアップが続きます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの総当たり検索 | O(q・m) | O(n + m) | 遅すぎる |
 | ≤3 エッジのパスをすべて列挙する | O(m) が期待されます | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な前処理戦略

 1. 各頂点のすべての近傍をエッジの重みとともに格納する隣接リストを作成します。 これにより、ローカル構造への定時アクセスが可能になります。これは、すべての有効なパスの長さが最大 ​​3 であるため、不可欠です。 
2. ハッシュマップを初期化する`best[(u, v)]`これは、からの有効なパスの最小コストを保存します。`u`に`v`最大 3 つのエッジを使用します。 グラフが無向であってもパスには方向があるため、有向ペアを保存します。 
3. すべてのシングルエッジ パスを挿入します。 あらゆるエッジに`(u, v, w)`、 アップデート`best[(u, v)]`そして`best[(v, u)]`費用がかかる`w`。 これは、長さ 1 のすべてのソリューションを処理します。 
4. 各エッジを 1 回延長して、長さ 2 のパスをすべて列挙します。 頂点ごとに`u`、それぞれの隣人を考慮します`v`、次に各近隣者について`x`の`v`、パスを取得します`u → v → x`費用がかかる`w(u, v) + w(v, x)`。 アップデート`best[(u, x)]`。 このステップでは、すべての有効な 2 エッジ ルートをキャプチャします。 
5. もう一度拡張して、長さ 3 のパスをすべて生成します。 各長さ 2 の構造について`u → v → x`、隣接するものを反復処理します`y`の`x`そして更新します`best[(u, y)]`費用がかかる`w(u, v) + w(v, x) + w(x, y)`。 これで、有効な 3 エッジ ウォークがすべて完了します。 
6. 各質問に答えます`(s, t)`戻ることで`best[(s, t)]`存在する場合、それ以外の場合は出力`-1`。 

### なぜ効果があるのか

 すべての有効な答えは、長さ 1、2、または 3 のウォークに正確に対応します。アルゴリズムは、可能な隣接エッジのすべてのシーケンスを反復することによって、そのようなウォークをすべて明示的に構築します。 すべてのステップが実際のエッジを拡張するため、無効なパスは導入されません。 エンドポイント ペアごとの最小コストのみを保存するため、複数の重複する構造は最適な値に正しく折りたたまれます。 中間頂点の可能な選択肢はすべて隣接拡張によって列挙されるため、有効なパスが失われる可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
        edges.append((u, v, w))

    best = {}

    def upd(a, b, w):
        key = (a, b)
        if key not in best or w < best[key]:
            best[key] = w

    for u, v, w in edges:
        upd(u, v, w)
        upd(v, u, w)

    for u in range(1, n + 1):
        for v, w1 in adj[u]:
            for x, w2 in adj[v]:
                if x == u:
                    continue
                upd(u, x, w1 + w2)

    for u in range(1, n + 1):
        for v, w1 in adj[u]:
            for x, w2 in adj[v]:
                if x == u:
                    continue
                for y, w3 in adj[x]:
                    if y == v:
                        continue
                    upd(u, y, w1 + w2 + w3)

    q = int(input())
    out = []
    for _ in range(q):
        s, t = map(int, input().split())
        out.append(str(best.get((s, t), -1)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```隣接リストは、1 ステップで到達可能なすべての候補を定数時間で列挙できるため、ソリューションのバックボーンとなります。 の`best`Dictionary は、回答空間全体の圧縮表現です。パスを明示的に保存する代わりに、エンドポイント ペアごとの最適コストのみを保存します。 

三重にネストされた展開が重要な部分です。 最初のループはすべてのエッジをエンコードします。 2 番目のループはすべての 2 エッジ ウォークを構築し、3 番目のループはそれらを 3 エッジ ウォークに拡張します。 ような小さな小切手`x == u`または`y == v`正確性は冗長な状態に依存しませんが、冗長な状態を生成する可能性がある即座の些細なバックトラッキングを避けます。 

すべてのクエリの回答は単純な辞書検索であるため、ソリューションは 100 万クエリまで拡張できます。

 ## 特殊なケース

 マルチステップ パスよりも悪い直接エッジは、初期化ステップですべてのエッジが保存されるため、正しく処理されますが、その後の 2 エッジおよび 3 エッジの拡張による更新により、より小さい値で上書きされる可能性があります。 

たとえば、三角形の場合`1-2-3`重いエッジで`1-3`、アルゴリズムは最初に保存します`(1,3)=heavy`、その後発見`1→2→3`そしてそれをより小さい値に置き換えます。 これにより、最終的な辞書には、許可されたすべてのパス長の中で常に最適なものが反映されます。 

2 番目のエッジ ケースは、最適パスがちょうど 3 つのエッジを使用する場合です。 3 番目の拡張層は、そのようなパスがすべて明示的に生成されることを保証します。 2 エッジ プレフィックスが最適でない場合でも、それは依然として構成要素として使用されるため、有効な 3 エッジ ソリューションがスキップされることはありません。
