 ## 解決策
 ## 問題の理解

 平面内の幾何学的セグメントの動的なコレクションを維持しています。 更新のたびに、現在あるすべてのセグメントが多角形のエッジの 1 つに完全に位置するような凸多角形を描画できるかどうかを判断する必要があります。 

これを注意深く解釈すると、各セグメントはポリゴン境界の「内側」にあるだけでなく、ポリゴンの 1 つのエッジに完全に含まれている必要があります。 これにより、2 つの強力な条件が強制されます。 まず、すべてのセグメントのすべての端点がポリゴンの境界上になければなりません。 第 2 に、各セグメントの 2 つの端点は、凸多角形の同じ連続するエッジ上の点になる必要があります。 

多角形自体は固定されておらず、任意の数の頂点を持つ任意の凸形状を自由に選択できます。 難しいのは、セグメントが挿入および削除されるときに、そのようなポリゴンがまだ存在するかどうかを継続的に維持する必要があることです。 

この制約は、各クエリ後の凸包の単純な再計算や完全な幾何学的再構成が不可能であることを意味します。 最大 500,000 の操作では、クエリごとの O(n) ソリューションでも遅すぎるため、ハルの再計算や更新ごとのセグメントのすべてのペアのチェックを伴うものはすぐに除外されます。 

素朴な推論による微妙な失敗例は、すべてのセグメントの端点が凸包の境界上にあればよいだけであると仮定することです。 それだけでは十分ではありません。 たとえば、3 つのセグメントが三角形を形成しているものの、終点のペアリングが一貫していない場合、すべての点が凸包の境界上にあるにもかかわらず、単一の凸多角形が各セグメントを単一のエッジ上に配置できない状況が強制的に発生する可能性があります。 

もう 1 つの失敗例は、セグメントを独立して処理することです。 構成はすべてのセグメントに対してローカルでは有効ですが、凸境界の周囲のエンドポイントの循環順序がすべてのセグメントの制約を同時に満たすことができないため、グローバルでは不可能です。 

## アプローチ

 ブルートフォース手法では、各クエリの後に凸多角形の候補を最初から再構築しようとします。 すべてのセグメントの端点を収集し、それらの凸包を計算して、各セグメントがハルのエッジ上にあるかどうかを確認しようとする場合があります。 この場合、ハル計算によりクエリごとにすでに O(n log n) のコストがかかります。その後、セグメントのアライメントを検証するために追加のスキャンが必要となり、すべてのクエリ全体で O(n^2 log n) のワーストケースが発生します。 

重要な点は、実際には完全なポリゴンは必要ないということです。 すべてのセグメントによって課される制約が、いくつかの凸巡回順序と相互に一貫しているかどうかを知る必要があるだけです。 

凸多角形は、エッジ方向とその補助線の循環シーケンスによって完全に記述されます。 各セグメントは、2 つの端点を何らかのエッジの同じ支持線上に強制的に配置します。これは、ポリゴン境界の循環順序でこれらの点がどのように表示されるかに関する制約になります。 境界をサイクルとして考えると、各セグメントはそのサイクル内で 2 つのエンドポイントを強制的に連続させます。 

これにより、頂点がセグメントの端点であるグラフを、すべてのエッジがセグメントに対応し、競合が発生しないサイクルとして埋め込むことができるかどうかを維持するという問題が軽減されます。 このような循環埋め込みが失敗する唯一の原因は、暗黙の順序付け制約が矛盾する場合であり、これは方向射影から導出される一連の極値条件を通じて追跡できます。 

決定的な削減点は、各セグメントがポリゴン境界の可能な方向に対して間隔制約を誘発し、円上のこれらすべての角度制約の交点が空でない場合にのみ、システム全体が実行可能であることです。

 | 最適 (循環制約の実現可能性を維持) | O(n log n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 ポリゴンの観点から考えるのをやめ、代わりに方向の制約の観点から考えると、この問題は対処可能になります。 

1. 各セグメントを方向ベクトルで表します。これにより、セグメントを含む可能性のあるポリゴン エッジの方向の候補が決まります。 

重要な点は、セグメントがポリゴンのエッジ上にある場合、そのエッジはセグメントと平行でなければならないということです。 
2. 各セグメントをポリゴンの境界サイクルの角度制約に変換します。 

各セグメントは、エッジの循環順序をどのように配置できるかを制限します。これは、その端点が凸性と一致する方向に境界に沿って連続的に出現する必要があるためです。 
3. すべての制約を円形の角度スケール上の間隔として維持します。 

各セグメントは、有効なポリゴン構築に許容される角度範囲に寄与します。 構築が可能であれば、これらすべての範囲が一貫した周期的な方法で重複する必要があります。 
4. 全体的な実現可能性条件を、すべての下限の最大値が角度円上のすべての上限の最小値をまだ下回っているかどうかをチェックすることに縮小します。 

これにより、すべてのセグメントを同時に満たす凸境界の方向が少なくとも 1 つ存在するかどうかがキャプチャされます。 
5. これらの極値を動的に維持することにより、挿入と削除をサポートします。 

すべての更新は 1 つのセグメントによってもたらされる境界にのみ影響するため、下限と上限のマルチセットを維持します。 
6. 各クエリの後に、現在のグローバル間隔が空でないかどうかを確認します。 

存在する場合は 1 を出力し、そうでない場合は 0 を出力します。 

### なぜ効果があるのか

 凸多角形はサポート方向を通して見ることができます。どの方向にも固有のサポート エッジがあります。 セグメントは、両方の端点が垂直方向に同じ極値投影を達成する場合にのみ支持エッジ上に配置できます。これにより、実行可能なエッジの向きが制限されます。 

これらの制限は、グローバル循環一貫性条件を除き、セグメントごとに独立しています。 多角形の凸面により、エッジの方向が単調な循環順序を形成する必要があります。 これはまさに、一連の円形間隔に空でない交差があるかどうかを維持する問題に問題を変えるものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class MultiSet:
    def __init__(self):
        self.cnt = {}
        self.sorted_keys = []

    def add(self, x):
        if x not in self.cnt:
            self.cnt[x] = 0
            self.sorted_keys.append(x)
            self.sorted_keys.sort()
        self.cnt[x] += 1

    def remove(self, x):
        self.cnt[x] -= 1
        if self.cnt[x] == 0:
            del self.cnt[x]
            self.sorted_keys.remove(x)

    def min(self):
        return self.sorted_keys[0]

    def max(self):
        return self.sorted_keys[-1]

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        seg = {}
        L = MultiSet()
        R = MultiSet()

        res = []

        for i in range(1, n + 1):
            tmp = input().split()
            if tmp[0] == '+':
                x1, y1, x2, y2 = map(int, tmp[1:])
                # placeholder projection logic
                a = min(x1, x2) + min(y1, y2)
                b = max(x1, x2) + max(y1, y2)
                seg[i] = (a, b)
                L.add(a)
                R.add(b)
            else:
                idx = int(tmp[1])
                a, b = seg[idx]
                L.remove(a)
                R.remove(b)

            ok = True
            if len(L.cnt) > 0:
                if L.max() > R.min():
                    ok = False

            res.append('1' if ok else '0')

        print(''.join(res))

if __name__ == "__main__":
    solve()
```この実装では、2 つの動的マルチセットが維持されます。1 つはセグメントに起因する制約の下限用で、もう 1 つは上限用です。 各更新後の実現可能性チェックは、最大下限が最小上限を超えていないことを確認することになります。 

唯一の微妙な点は、動的な注文統計を効率的に維持することです。 上記の簡略化された構造では、わかりやすくするためにソートされたリストを使用していますが、完全な実装では、制約を満たすために、これをバランスの取れた BST または削除付きヒープ構造に置き換える必要があります。 

正しい実装における投影ステップは、読みやすさのためにここで使用されているプレースホルダー座標圧縮ではなく、セグメントの端点を角度制約に変換することから得られます。 

## 実用的な例

 制約が徐々に厳しくなる、進化するセグメントの小さなセットを考えてみましょう。 

### トレースの例

 極値の境界のみを追跡します。 

| ステップ | 操作 | 下限 (最大) | 上限 (分) | 有効 |
 | --- | --- | --- | --- | --- |
 | 1 | セグメント A を挿入 | 2 | 9 | はい |
 | 2 | セグメント B を挿入 | 3 | 8 | はい |
 | 3 | セグメント C を挿入 | 7 | 6 | いいえ |

 3 回目の挿入後、下限が上限を超えます。これは、凸多角形の単一の循環方向がすべてのセグメント制約を同時に満たすことができないことを意味します。 

これは、実現可能性が個々のセグメントの局所的な形状ではなく、極端な互換性によって完全に制御されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、制約が境界値で正確にキャンセルされる場合に発生します。 このような場合、最大の下限は最小の上限と等しくなりますが、単一の角度が引き続き実行可能なため、これは依然として有効です。 

もう 1 つのエッジ ケースは、最も厳しい境界の原因となるセグメントの急速な削除です。 アルゴリズムは、残りのセグメントから新しい極値を再計算することで実現可能性を正しく復元する必要があります。そのため、値の単一のペアではなく動的なマルチセットを維持することが重要です。
