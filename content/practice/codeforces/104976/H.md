 ## 解決策
 ## 問題の理解

 私たちは子供のコレクションを与えられ、それぞれが一定量の砂糖から始まります。 それらに加えて、子供ごとに 1 つのイベントを含む一連のイベントもあります。 各イベントは、イベントの所有者と別の固定「参照」子という 2 つの子を参照します。 

イベントが実行されると、これら 2 つの子の現在の砂糖量を比較します。 イベントの所有者が現在、参照されている子よりも厳密に砂糖が少ない場合、所有者は固定ボーナスを獲得します。 そうでなければ何も起こりません。 重要な問題は、すべてのイベントが一様にランダムな順序で実行されるため、以前のイベントによって将来の比較が重要な方法で変更される可能性があることです。 

タスクは、すべてのイベントが処理された後に、すべての子供について予想される最終的な砂糖の量を計算し、その結果を大きな素数を法として出力することです。 

制約が十分に大きいため、イベントの順序をシミュレートするアプローチは不可能です。 1 回のテストで最大 50 万人の子供を対象とし、イベント数が同じであれば、たとえ 1 回でも$O(n \log n)$テストごとの解決策は、不用意に繰り返されると境界線に達する可能性があり、順列を探索したり、イベントの順序を明示的に推論しようとするものはすぐに除外されます。 解決策は、順序付けのランダム性を閉じた形式の確率計算または非常に構造化された依存関係に減らす必要があります。 

イベントを入力順にシミュレートまたは貪欲に処理しようとすると、微妙な障害モードがすぐに現れます。 実際の実行順序はランダムであるため、決定論的な走査では完全に異なる中間状態が得られます。 たとえば、2 つのイベントが比較によって相互に依存している場合、順序を入れ替えるとどちらのボーナスがトリガーされるかが逆転する可能性があるため、固定順序で単純に評価すると、期待と一致しない偏った結果が生成されます。 

もう 1 つのよくある落とし穴は、イベント間の独立性を前提とすることです。 イベントの場合$i$子供の糖分によって異なります$b_i$、その子の糖分は他のイベントに依存し、イベントの結果に依存します。$i$は、それらの以前のイベントがその前に出現したかどうかと相関しています。 これらを独立した確率として扱うと、不正確な集計が行われます。 

## アプローチ

 ブルートフォース戦略では、すべてが列挙されます。$n!$イベントの順序を並べ替えて、それぞれをシミュレートし、結果を平均します。 たとえ楽観的にシミュレーションを次のように削減したとしても、$O(n)$注文ごとに、これは次のようになります$O(n \cdot n!)$、それはまったく実現不可能です。 要求される精度は正確な素数法であるため、サンプリングさえもパスしません。 

重要な構造的観察は、各イベントがちょうど 2 つの子 (イベント自身の子と固定参照の子) を含む比較にのみ依存しているということです。 さらに、イベントは糖分を増加させるだけで、減少させることはありません。 これは、唯一の不確実性は、ランダムな置換で特定のイベントが発生する前に、関与する 2 人の子のそれぞれが受け取るボーナス更新の数によってもたらされることを意味します。 

これにより、問題は完全な順列ではなく相対的な順序に関する推論に変換されます。 特にどんなイベントでも$i$、どちらかの子供に影響を与える可能性のあるイベントのみ$i$または子供$b_i$それとの比較が重要です。 この依存関係により、各ノードが正確に 1 つの他のノードを指す関数グラフが形成されるため、構造は有向サイクルにつながるツリーに分解されます。 

接続された各構造の内部では、ランダムな並べ替えによって対称的な順序付けが引き起こされ、これはペアごとの順序付け確率に折りたたむことができます。 この対称性により、更新の複雑なカスケードを明示的に追跡する必要がなくなります。重要なのは相対的な順序のみであり、それらは均一です。 

この削減が行われると、各イベントの期待される寄与は、初期値が等しいか厳密に順序付けされているかにのみ依存するローカルな式になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース |$O(n \cdot n!)$|$O(n)$| 遅すぎる |
 | 対称性 + ペアごとの確率削減 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ランダム性が比較にどのような影響を与えるかを理解すると、最終的な計算は各イベントを個別に評価することになります。 

1. それぞれの子どもに対して$i$、そのイベントを特定します$i$、子を比較します$i$子供と一緒に$b_i$。 現時点でのイベントにおいて比較条件が真である可能性がどの程度あるかを理解する必要があるだけです。$i$ランダムな順列で実行されます。 
2. すべてのイベントが一様にランダムな順序で配置されるため、イベント間の相対的な順序が変化することに注目してください。$i$そしてイベント$b_i$どちらの方向にも同じ確率で起こります。 これにより、次のベースライン確率が得られます。$1/2$一方が他方より先に現れるということです。 
3. 比較に対する唯一の決定的な影響は、砂糖の初期値です。$a_i$そして$a_{b_i}$なぜなら、以前のイベントはランダムな順序で両側に対称的に影響を与えるからです。 
4. もし$a_i < a_{b_i}$そうすると、ランダム性の影響が生じる前であっても、比較によりほとんどの順序でトリガーが優先されるため、イベントは確率でトリガーされます。$1$。 
5. もし$a_i > a_{b_i}$, 対称性は、順序バイアスが期待値における厳密な優位性を逆転させることができないことを意味するため、イベントは期待値に寄与することはありません。 
6. もし$a_i = a_{b_i}$、どちらの側にも構造上の利点がなく、ランダムな順序によりトリガー条件がちょうど半分の時間保持されます。 
7. 各イベントの重みを乗算します$w_i$トリガー確率で計算し、これを初期値に加算します。$a_i$期待される最終値を取得します。 

### なぜ効果があるのか

 ランダムな並べ替えにより、イベントのペアの相対的な順序が均一になります。 すべての更新は比較の 1 つのエンドポイントにのみ影響し、すべての更新は追加的であるため、対称性により、より深い依存関係チェーンは期待どおりにキャンセルされます。つまり、サイクルまたは依存関係チェーン内のノードは、体系的に他のノードよりも先に優位性を得ることができません。 これにより、システムは初期順序のみによって決定されるペアごとの比較に崩壊します。この比較は、置換平均化の下でも不変のままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV2 = (MOD + 1) // 2

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    w = list(map(int, input().split()))
    
    ans = a[:]
    
    for i in range(n):
        j = b[i] - 1
        
        if a[i] < a[j]:
            ans[i] = (ans[i] + w[i]) % MOD
        elif a[i] == a[j]:
            ans[i] = (ans[i] + w[i] * INV2) % MOD
        else:
            pass
    
    print(*ans)
```この実装では、各イベントの確率分類が直接適用されます。 唯一の微妙な点は、確率が次のような等しい場合の処理​​です。$1/2$、2 の逆モジュラーを使用して実装されます。 

各イベントは独立して処理されます。$O(1)$したがって、合計の複雑さは入力サイズに対して線形のままです。 

重要な設計上の選択は、イベント順序のシミュレーションを避けることです。 ランダム性全体は、初期値に基づく単純なケースの区別に吸収されます。

## テストケース```python
import sys, io

MOD = 10**9 + 7
INV2 = (MOD + 1) // 2

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        w = list(map(int, input().split()))
        ans = a[:]
        for i in range(n):
            j = b[i] - 1
            if a[i] < a[j]:
                ans[i] = (ans[i] + w[i]) % MOD
            elif a[i] == a[j]:
                ans[i] = (ans[i] + w[i] * INV2) % MOD
        out.append(" ".join(map(str, ans)))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# sample-style tests

""") == "11 10 5"

# all equal chain

 ## 特殊なケース

 最小限の単一子システムは、基本的な動作を公開します。 と$n = 1$、イベントは子をそれ自体と比較するため、平等が成り立ち、イベントは期待値のちょうど半分の重みを与えます。 アルゴリズムは等価ルールを正しく適用し、$a_1 + w_1 / 2$。 

2 ノードの対称スワップでは、両方の子が等しい初期値で相互に比較されます。 各イベントは確率でトリガーされます$1/2$、順序対称性とは独立しています。 両方の比較が等価分岐に分類されるため、アルゴリズムはこれをきれいに処理します。 

厳密に順序付けされたペアでは、$a_i < a_j$、参照ポインタが循環を形成している場合でも、分類は最初の比較にのみ依存します。 このアルゴリズムは確率 1 を割り当てます。これは、一連の対称ランダム更新によって、最初に導入された決定論的な順序付けバイアスを逆転させることはできないという事実と一致します。
