 ## 問題の理解

 サイズの配列からインデックスのサブセットを選択しています$n$、各インデックスには値があります$b_i$それが合計スコアに貢献します。 制約は、通常の意味での隣接性や順序ではなく、値間の可分性の関係にあります。$a_i$。 

それぞれの立場を考えてみる$i$重みを運ぶノードとして$b_i$。 ノードを含める場合$i$、特定の以前のノード、つまり以前のすべてのインデックスも含める必要があります。$j < i$誰の価値$a_j$分割する$a_i$。 これにより、有向依存関係が作成されます。$i$そんなすべての人に$j$、を含むことを意味します$i$すべての「分割可能な先行者」を含める必要があります。 

タスクは、選択されたノードの合計を最大化しながら、これらの依存関係ルールの下で閉じられているノードのサブセットを選択することです。$b_i$。 なぜなら、いくつかの$b_i$負の値になる可能性があるため、到達可能なすべてを取得することが常に最適であるとは限らないため、構造は有向グラフ上の重み付き閉包問題になります。 

制約$n \le 3000$おおよそ許可します$O(n^2)$しかし、大規模なノード拡張やすべてのサブセットにわたる単純なサブセット DP を備えた完全なフロー ネットワークを構築するものは、直ちに不可能になります。 重要な制限は、$a_i \le 100$、これは値空間を圧縮し、実際の構造上のボトルネックになります。 

微妙なエッジケースは、負の重みから発生します。 もしすべてなら$b_i$が負の場合、最適な答えは空のセットですが、単純な依存関係クロージャーのアプローチでは、他のノードを独立して考慮するときに依然として一部のノードを強制的に含めることになり、過剰カウントにつながる可能性があります。 

複数のインデックスが同じものを共有する場合、別の特殊なケースが発生します。$a_i$。 値が繰り返されても、依存関係は依然としてインデックスベースであり、以前の位置のみが考慮されます。 この順序は重要です。インデックス間で同じ値を交換すると、存在する依存関係が変わるため、ソリューションでは処理できなくなります。$a_i$値を独立したマルチセット ノードとして扱います。 

## アプローチ

 ブルートフォース手法では、インデックスのすべてのサブセットを試し、ルールに従って有効かどうかを確認します。 選択したサブセットごとに$S$、すべての場合にそれを検証します$i \in S$、 全て$j < i$と$a_j \mid a_i$も入っています$S$。 1 つのサブセットの有効性をチェックするにはすでに時間がかかります$O(n^2)$、そして、あります$2^n$サブセットは、たとえ$n = 40$。 

より構造化されたビューは、ルールをクロージャ条件として解釈することです。ノードを選択する場合は、そのノードに含まれる隣接依存関係をすべて含める必要があります。 これは、最大重み閉集合問題の古典的な形式であり、最小カットによって解決できます。 各ノードには重みがあります$b_i$、依存関係は、クロージャを強制する無限の容量を持つ有向エッジです。 

ただし、完全なフロー グラフは、$n \le 3000$潜在的に$O(n^2)$エッジは、特に Codeforces 制約と 32 MB 制限の下では、メモリが少ない場合に 4 秒で標準の maxflow を実行するには大きすぎます。 

重要な単純化は、依存関係が小さな数の割り算によって完全に支配されることを観察することによって得られます。$a_i \le 100$。 インデックスに基づいてグラフを作成する代わりに、動作を値ごとに集計し、問題を約数に対する動的プログラミングとして扱います。 

インデックスを昇順に処理し、各値を維持します$v$可分性制約と一致する状態で終了する有効なセットの達成可能な最良の寄与。 インデックスを考えると$i$、その決定は、以前のポジションの中に必要な約数をすべて含めるかどうかによってのみ決まります。 すべての依存関係は次のように決定されるため、$a_j \mid a_i$、 そして$a_i$が小さい場合、除数リストを事前計算し、値ごとにグループ化された DP 遷移を維持できます。 

これにより、問題は 100 個の可能な値を超える構成で達成可能な最良の合計を維持することに変わります。各値は、寄与する前にそのすべての約数がアクティブである必要があります。 DP は、インデックスに沿ってではなく除数格子に沿って「活性化」を効果的に伝播します。

 ## アルゴリズムのチュートリアル

 依存関係が数値のみに依存することを利用します。$a_i$、順序付けを超えたインデックス構造ではありません。 

1. すべての値について事前計算する$v \in [1, 100]$、その約数のリスト。 これにより、値をアクティブにする前にどの状態を満たさなければならないかをすばやく特定できます。 
2. 配列を維持する`dp[v]`最後にアクティブ化された値グループごとに構成を追跡しているという条件下で、処理されたインデックスから達成できる最良の合計寄与度を表します。 実際には、各インデックスがその値クラスに独立して寄与するため、これを値全体の単一の DP に圧縮します。 
3. インデックスを左から右に処理します。 インデックスごとに$i$を含めるかどうかを決定します。 それを排除しても何も変わりません。 これを含めると、以前のすべてのインデックスが$j$と$a_j \mid a_i$がすでに含まれている必要があるため、これらの除数の州からの寄与がすでに考慮されていることを確認します。 
4. これを強制するために、値ごとの累積最良合計を維持し、値を処理するときに次のことを保証します。$x$、追加することしかできません$b_i$すべての約数の状態が$x$すでに検討されています。 これは、値の昇順で DP を更新し、以前に計算された除数 DP 値を使用することによって実装されます。 
5. 各インデックスについて$i$、それを含めた場合に最も有効な寄与を計算します。それは次と等しくなります。$b_i$必要なすべての除数値の最良の寄与の合計を加えたもの。 次に、対応する状態を更新します$a_i$。 
6. 最後に、空のセットが許可されているため、すべての DP 状態の最大値を取得し、0 と比較します。 

### なぜ効果があるのか

 重要な不変条件は、値を処理する前に$v$、除算する値を持つインデックスからのすべての寄与$v$配列内で前に現れる および は、それらの除数値の DP 状態ですでに考慮されています。 これにより、インデックスを含めたときに、$i$、必要なすべての前任者はすでに州で「支払い」を受けています。 割り算は値にのみ依存し、後の構造には依存しないため、将来の決定によって、以前に満たされたクロージャ制約が無効になることはありません。 

したがって、すべての有効なストレンジ セットは DP 内の 1 つの一貫した累積パスに正確に対応し、すべての DP 状態は有効な閉セットに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    MAXV = 100

    divs = [[] for _ in range(MAXV + 1)]
    for v in range(1, MAXV + 1):
        for d in range(1, v + 1):
            if v % d == 0:
                divs[v].append(d)

    dp = [0] * (MAXV + 1)

    for i in range(n):
        v = a[i]
        gain = b[i]

        best_prev = 0
        for d in divs[v]:
            best_prev += max(0, dp[d])

        cand = best_prev + gain
        dp[v] = max(dp[v], cand)

    ans = max(0, max(dp))
    print(ans)

if __name__ == "__main__":
    solve()
```DP アレイ`dp[v]`価値を「活性化」する有効な構造を終わらせることに私たちが関連付けることができる最高の貢献を表します`v`。 インデックスを処理するとき、すべての除数状態からの寄与を合計します。これは、これらの状態がまさに現在の要素を選択する前に含める必要があるインデックスであるためです。 遷移では、現在の値クラスのみが更新され、以前の最良の値が維持されます。 

微妙な実装の詳細は、次を使用して除数状態からの寄与をクランプすることです。`max(0, dp[d])`。 これは、負の寄与を持つ除数グループを含めても最大の目的には決して役に立たないため、有害な連鎖を自由に無視できることを反映しています。 

依存関係に関係なく、何も選択しないことが常に有効であるため、最終的な答えにはゼロが含まれます。

 ## 特殊なケース

 いつすべて$b_i$が負の場合、すべての値が含まれるとスコアが減少するため、正解は 0 になります。 アルゴリズムはこれを処理します。`best_prev`ゼロから始まりマイナスの寄与は改善されない`dp[v]`, したがって、どの状態もポジティブになることはありません。 

価値観が次のような純粋な連鎖を形成するとき$1, 2, 4, 8$、後の各要素は以前のすべての要素に依存します。 DP は除数格子に沿って寄与を正しく蓄積し、最終ノードを含めることで暗黙的に完全なチェーンを収集します。 

複数のインデックスが同じ値を共有する場合、更新は同じインデックスに蓄積されます。`dp[v]`州。 常に最大値を採用するため、後のより優れた貢献によって以前の貢献が上書きされ、二重にカウントされることなく重複の中で最適なサブセットが確実に保持されます。 

これらの動作により、問題によって許可されるすべての構造パターンにわたって DP の一貫性が維持されます。
