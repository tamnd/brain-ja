 ## 解決策
 ## 問題の理解

 正の整数の 2 つのコレクションが与えられています。 1 つのコレクションは最初の数値として選択できる値を表し、2 番目のコレクションは 2 番目の数値として選択できる値を表します。 各コレクションから 1 つの値を選択した後、それらの合計を計算します。 制約は、この合計が元のコレクションのいずれにも存在してはならないということです。 

タスクは、最初の配列の 1 つの要素と 2 番目の配列の 1 つの有効なペアを、それらの合計が「新しい」、つまりどちらの配列にも存在しないように出力することです。 

問題の重要な構造は、値が小さいことです。 すべての数値は 1 ～ 200 の範囲にあり、両方の配列のサイズは最大 100 です。候補ペアの総数は最大 10,000 であり、各チェックは度数表を使用して一定時間で実行できるため、すべての可能な合計をチェックすることを含む解決策が実行可能であることがすぐにわかります。 

素朴だが重要な観察は、任意の要素を選択すると、配列の 1 つにすでに存在する合計を誤って生成してしまう可能性があるということです。 たとえば、両方の配列に 1 ～ 100 のような小さく密な範囲が含まれている場合、多くの合計がそれらの範囲内に収まるため、盲目的に小さい数値を選択することは安全ではありません。 

もう 1 つの微妙な失敗例は、対称性に起因します。 両方の配列が同一であるか、重なり合っている場合、両方の配列から同じ値を選択すると、セット内に合計が生成されることがよくあります。 たとえば、両方の配列に 1 と 2 が含まれている場合、(1, 2) を選択すると 3 が得られますが、これはどちらか一方にまだ存在している可能性があります。 したがって、正確さは、構造的な仮定ではなく、合計のメンバーシップを明示的にチェックすることに依存します。 

重要な唯一の特殊なケースは、単調性や素性を仮定しないようにすることです。 配列は任意にオーバーラップできます。 

## アプローチ

 ブルートフォース手法では、すべてのペア (a、b) を試し、その合計を計算し、この合計がいずれかの配列に存在するかどうかを確認します。 各配列には最大 100 個の要素があるため、最大で 10,000 個のペアが生成されます。 各ペアについて、線形検索を使用して配列内のメンバーシップをチェックすると、O(n + m) のコストがかかり、最悪の場合、約 10,000 × 200 回の操作が必要になります。これは許容範囲内ですが、不必要に遅く、冗長になります。 

主な改善点は、繰り返し行われるメンバーシップ チェックを直接検索構造に置き換えることです。 すべての値は 1 ～ 200 であるため、A と B の両方についてブール値の存在配列を構築できます。その後、合計が存在するかどうかを確認することは O(1) になります。 

これにより、問題は単純なスキャンに変換されます。つまり、どちらのプレゼンス テーブルにも合計がマークされていないペアが見つかるまで、ペアを試してみます。 

制約が小さく、解決策が存在することが保証されているため、さらに最適化する必要はありません。

 ## アルゴリズムのチュートリアル

 1. 配列 A と B の両方を読み取り、2 つのブール配列 presentA と presentB を構築します。ここで、x が A にある場合は presentA[x] が true になり、B についても同様です。これにより、定数時間のメンバーシップ クエリが可能になります。 
2. A のすべての要素 a を繰り返します。各 a について、B のすべての要素 b を繰り返します。これにより、組み合わせを見逃すことなく、可能なすべてのペアを系統的に検査できます。 
3. 各ペア (a、b) について、s = a + b を計算します。 
4. presentA[s] または presentB[s] が true であるかどうかを確認します。 どちらも当てはまらない場合は、有効なペアが見つかったので、それをすぐに出力できます。 
5. スキャン中にペアが見つからなかった場合、この問題が発生しないことが保証されるため、枯渇する前に終了が常に保証されます。 

### なぜ効果があるのか

アルゴリズムは考えられるすべてのペアをチェックするため、有効なペアが存在する場合は、反復中にそのペアが見つかる必要があります。 正確さの条件は選択の瞬間に直接適用されます。ペアの合計が両方の配列に存在しない場合にのみ、ペアを受け入れます。 メンバーシップ チェックは正確で近似的ではないため、無効なペアは通過できず、有効なペアもスキップできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    m = int(input())
    B = list(map(int, input().split()))
    
    presentA = [False] * 205
    presentB = [False] * 205
    
    for x in A:
        presentA[x] = True
    for x in B:
        presentB[x] = True
    
    for a in A:
        for b in B:
            s = a + b
            if not presentA[s] and not presentB[s]:
                print(a, b)
                return

solve()
```この解決策は、両方の配列のメンバーシップを、値によってインデックス付けされた固定サイズのブール テーブルにエンコードすることから始まります。 これにより、ペアの評価中にスキャンが繰り返されることが回避されます。 次に、ネストされたループは、考えられるすべてのペアを決定的な順序で列挙します。 条件を満たす最初のペアがすぐに出力されます。これは、有効な答えであればどれでも受け入れられるため有効です。 

微妙な点は、配列が十分小さいため、最大 400 までのすべての可能な合計をカバーするために、200 よりわずかに大きいサイズの配列を安全に割り当てることができるということです。ただし、制約によって正確さが保証されるため、条件ロジックで範囲外の合計を明示的に処理する必要はありません。サイズが正しく設定されていれば、Python リストのインデックス付けは安全なままであるためです。

 30 はどちらの配列にも存在しないため、すぐに (20, 10) を選択します。 アルゴリズムは最初の有効なペアで停止します。これは、解が見つかったら完全な検索が必要ないことを示しています。 

### 例 2

 | ステップ | | b | 合計 | で | Bで| 有効 |

 最初のペアはすでに条件を満たしており、順序が問題ではないことが確認されます。 有効なペアはどれでも受け入れられ、アルゴリズムは当然、最も古いペアを返します。 

これらのトレースは、ソリューションが入力順序の影響を受けず、メンバーシップ構造のみに依存していることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の配列が同一で小さい場合です (たとえば、A = [1, 2] と B = [1, 2])。 アルゴリズムは 4 つのペアすべてをチェックします。 (1,1) の場合、合計は 2 であるため、拒否されます。 (1,2) の場合、合計は 3 ですが、これはどちらの配列にも存在しないため、すぐに受け入れられます。 このアルゴリズムは一意性を前提とせず、メンバーシップを明示的に検証します。 

もう 1 つのケースは、A = [200] および B = [200] など、値が最大の場合です。 唯一のペアは合計 400 を生成しますが、これは両方の配列の範囲外です。 存在配列は最大 200 までしかマークしないため、400 は自動的に存在せず、ペアは正しく受け入れられます。 

3 番目のケースは密な重複であり、A と B の両方に 1 つを除く 1 から 200 までのほぼすべての数値が含まれています。 それでも、このアルゴリズムはギャップの大小に依存せず、不足しているものが見つかるまで合計を直接テストするため、依然として機能します。これは問題文で保証されています。
