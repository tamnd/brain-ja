 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 1 回の操作で、任意の要素を選択し、それを 1 増やすか 1 減らすことができます。そのような変更ごとに 1 コインのコストがかかります。 

目標は、可能な限り最小限のコインを消費しながら、すべての要素の積が正確に 1 になるように配列を変更することです。 

最終的な積は 1 でなければならないため、最終的な配列内のすべての要素は 1 または -1 でなければなりません。 絶対値が 1 より大きい値は、不必要なコストの原因となります。値を ±1 に近づけると、必要な操作の数が常に減少するためです。 ゼロを含む積はゼロであるため、ゼロはゼロのままであることもできません。 

制約$n \le 10^5$線形または線形に近い解決策が必要であることを即座に示唆しています。 多くの可能な最終構成を試したり、製品に対して動的プログラミングを実行したりするアプローチは、コストがかかりすぎます。 100,000 個の要素を使用すると、$O(n)$スキャンが理想的です。 

いくつかの特殊なケースは注目に値します。 

ゼロのみを含む配列を考えてみましょう。```
1
0
```答えは 1 です。1 回の操作で 0 を 1 に変えることができます。 負と正のみをカウントするソリューションでは、ゼロの処理を忘れる可能性があります。 

ゼロが利用できない奇数の負の数を考えてみましょう。```
3
-1 -1 -1
```積は-1です。 積を 1 にするには、1 つの要素を -1 から 1 に変更する必要があり、2 回の操作が必要になります。 正解は 2 です。不用意に貪欲なソリューションを使用すると、すべてを最も近い ±1 に変換した後に停止し、誤って 0 を返す可能性があります。 

ここで、少なくとも 1 つのゼロを持つ奇数の負数を考えてみましょう。```
2
-1 0
```最も安価な選択は、コスト 1 のゼロを -1 に変換し、製品 1 を与えることです。答えは 1 です。すべてのゼロを 1 に自動的に変換するソリューションでは、代わりに 3 回の操作が必要になります。 

## アプローチ

 ブルートフォースの観点では、すべての要素の最終値を考え、考えられる 1 と -1 の割り当てをすべて試してみます。 各要素には 2 つの可能な最終状態があるため、次のようになります。$2^n$可能なターゲット配列。 割り当てごとにコストを計算し、積が 1 に等しいかどうかを確認できます。 

すべての有効な最終配列は 1 と -1 のみで構成されるため、これは概念的に機能します。 問題は探索空間のサイズです。 と$n=10^5$、 平$2^{50}$可能性はすでに不可能です、ましてや$2^{100000}$。 

重要な観察は、1 または -1 に到達する最も安価な方法を計算するときに、各要素を独立して処理できることです。 

正の数の場合$x>0$、最も安い貢献はそれを 1 に変えることです。$x-1$。 

負の数の場合$x<0$、最も安価な貢献は、それを -1 に変えることです。$-1-x$。 

ゼロの場合、1 または -1 に達すると、コストはちょうど 1 になります。 

すべての要素を本来のターゲットにできるだけ近づけた後、残る唯一の問題は、負の値の数の均等性です。 -1 値の数が偶数である場合に限り、積は 1 と等しくなります。 

マイナスの数がすでに偶数であれば、完了です。 

奇数であれば、もう 1 回調整が必要です。 ゼロが存在する場合、通常の 1 コインを超える追加コストなしで、1 つのゼロを 1 の代わりに -1 に変換することができます。 ゼロがない場合、最後の -1 を 1 に変更する必要があり、さらに 2 つの操作が必要になります。 

これは、線形時間の貪欲なソリューションに直接つながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 合計コスト、負の要素の数、およびゼロの数の 3 つの変数を初期化します。 
2. アレイを 1 回スキャンします。 
3. 現在の値が正の場合、概念的に 1 に変換します。$x-1$コストに。 
4. 現在の値が負の場合は、概念的に -1 に変換します。 追加$-1-x$をコストに加算し、負のカウンターをインクリメントします。 
5. 現在の値がゼロの場合、コストに 1 を加えてゼロ カウンタをインクリメントします。 

ゼロは同じコストで 1 または -1 のいずれかになる可能性があるため、今のところはその存在のみを記録します。 
6. すべての要素を処理した後、負の数が偶数であるかどうかを確認します。 
7. マイナスの数が偶数であれば、現在のコストはすでに最適です。 
8. マイナスの数が奇数で、少なくとも 1 つのゼロが存在する場合、追加のコストは必要ありません。 

1 つのゼロを 1 の代わりに -1 に変えることができ、正確に 1 コインのコストを維持しながらパリティを修正します。 
9. 負の数が奇数でゼロがない場合は、答えに 2 を加えます。 

唯一のオプションは、最後の -1 を 1 に変更することですが、これには 2 つの操作が必要です。 
10. 総コストを出力します。 

### なぜ効果があるのか

 ゼロ以外のすべての要素について、到達可能な最も安価な値$\{-1,1\}$は独立して決定されます。 他の選択肢を選択すると、さらに費用がかかります。 たとえば、正の数を -1 に変更すると、常に 1 に変更するよりも正確に 2 コストがかかります。 

これらの局所的な最適な選択の後、唯一のグローバル条件は、-1 値の合計数が偶数でなければならないことです。 パリティがすでに正しい場合、局所的に最適な決定により、全体的に最適なソリューションが形成されます。 

パリティが間違っている場合、最も安価な修正は、追加コストなしで -1 になれる既存のゼロを使用するか、最後の -1 を 1 に反転するためにちょうど 2 回の追加操作を支払うことです。これより安価な調整は存在しないため、アルゴリズムは常に最小コストを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cost = 0
    negatives = 0
    zeros = 0

    for x in a:
        if x > 0:
            cost += x - 1
        elif x < 0:
            cost += -1 - x
            negatives += 1
        else:
            cost += 1
            zeros += 1

    if negatives % 2 == 1 and zeros == 0:
        cost += 2

    print(cost)

solve()
```最初のループは、すべての要素を最も近い有用な値にするための最小コストを計算します。 正の数は 1 に向かって移動し、負の数は -1 に向かって移動します。ゼロを残すには 1 回の操作が必要です。 

変数`negatives`自然に -1 になる要素の数を記録します。 変数`zeros`パリティを無料で修復する柔軟性があるかどうかを記録します。 

最終条件だけが微妙な部分です。 負の数が奇数の場合、積は -1 になることを意味します。 使用可能なゼロがない場合は、1 つの -1 が 1 になる必要があり、これにはちょうど 2 回の追加演算が必要になります。 少なくとも 1 つのゼロが存在する場合、そのゼロは 1 ではなく -1 になり、すでにカウントされているコストを増やすことなくパリティを修正できます。 

Python の整数は、考えられる最大コストがはるかに低いため、答えのサイズを簡単に処理できます。$10^{14}$。

 ## 特殊なケース

 ### 奇数の負の数とゼロなし

 入力:```
3
-1 -1 -1
```スキャンでは、コスト 0、マイナス 3、ゼロ 0 が生成されます。マイナスの数が奇数であるため、積は -1 になります。 使用可能なゼロがないため、アルゴリズムは 2 を加算して 2 を返します。 

1 つの -1 を 1 に変更するにはちょうど 2 つの操作が必要になるため、これは可能な限り安価な修正です。 

### ゼロを含む奇数の負数

 入力:```
2
-1 0
```スキャンにより、コスト 1、マイナス 1、ゼロ 1 が生成されます。マイナスのカウントは奇数ですが、ゼロが存在します。 ゼロを 1 に変換する代わりに、既にカウントされているのと同じ 1 つの操作を使用して、ゼロを -1 に変換します。 

最終的な配列は次のようになります`[-1, -1]`、その積は 1 です。答えは 1 のままです。 

### すべてゼロ

 入力:```
3
0 0 0
```各ゼロは 1 を与え、コスト 3 を与えます。マイナスは 0 のままであり、偶数です。 

アルゴリズムは 3 を返します。有効な最終配列の 1 つは次のとおりです。`[1, 1, 1]`。 

### 単一の負の要素

 入力:```
1
-1
```スキャンではコスト 0、マイナス 1、ゼロ 0 が得られます。パリティは奇数であるため、アルゴリズムは 2 を加算します。 

最終的な答えは 2 で、変更に対応します。`-1`の中へ`1`。 

このケースは、要素がすでに目標値の 1 つに達しているため見落とされがちですが、製品要件により追加の調整が必要になります。
