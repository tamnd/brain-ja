 ## 問題の理解

 座標平面上に配置された一連のゴルフホールがあります。 プレーヤーは、ミーシークが提案したポイントからボールを​​開始します。 許可される唯一の動きは 2 つのショットで構成されます。最初にボールは左にのみ移動でき、次にボールは下にのみ移動できます。 2 つのショットの長さは、負でない任意の値にすることができます。 

スタートポジションとしては`(a, b)`、これら 2 つのショットの後の最終位置は、座標が次の条件を満たす任意のホールにすることができます。`x <= a`そして`y <= b`。 最初のショットは x 座標のみを減少させ、2 番目のショットは y 座標を減少させるだけであるため、ショットの順序によってこの条件は変わりません。 

入力は最大になります`100000`穴と最大`100000`提案。 すべての提案に対して、少なくとも 1 つの穴が到達可能かどうかを回答する必要があります。 

境界により、すべてのホールに対するすべての提案のチェックが直ちに除外されます。 直接的な解決策には最大で次のことが必要です`10^10`これは、一般的な 2 秒の制限をはるかに超えています。 各クエリが対数時間で応答できるように、ホールを前処理する必要があります。 

主なエッジケースは移動方向から発生します。 大きい x 座標または y 座標を持つ穴には、他の座標が適切であっても到達できません。 例えば：```
Input
2
5 5
10 1
3
6 6
9 2
4 10
```最初のクエリは出力するはずです`YES`なぜなら`(5,5)`の下と左にあります`(6,6)`。 2 番目のクエリは出力する必要があります。`NO`なぜなら`(5,5)`X 座標は小さいですが、もう 1 つの穴があります`(10,1)`右すぎる。 1 つの座標だけをチェックする不注意な解決策は、それを誤って受け入れてしまいます。 

もう 1 つのよくある間違いは、出発点自体が有効な目的地となり得ることを忘れていることです。 例えば：```
Input
1
7 4
1
7 4
```答えは`YES`両方のショットの長さがゼロになる可能性があるためです。 この場合、厳密に小さい座標を必要とする解決策は失敗します。 

穴の重複も可能です。 例えば：```
Input
3
2 3
2 3
5 1
1
2 3
```答えは`YES`。 重複によってロジックは変更されませんが、前処理中にポイントを誤って削除する実装では、誤って有効な情報が失われる可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 あらゆる提案に対して`(a, b)`、すべての穴をスキャンし、穴が存在するかどうかを確認します。`(x, y)`と`x <= a`そして`y <= b`。 これは、到達可能性の条件を正確にテストするため、正しいです。 ただし、`n`穴と`q`クエリ、最悪の場合の実行`n * q`比較。 両方の値が等しい場合`100000`、これは次のようになります`10^10`動作が遅すぎます。 

条件の構造により、より迅速なアプローチが可能になります。 すべてのクエリは、で終わる左下の四角形内に点が存在するかどうかを尋ねます。`(a, b)`。 毎回この四角形を検索する代わりに、穴を前処理して、答えが単に比較される形式にすることができます。 

すべての穴を X 座標で並べ替えます。 左から右に移動しながら、これまでに確認されたすべての穴の中で最大の y 座標を維持します。 考えられるすべての x 境界について、この値は水平方向に到達できる最も高い穴を示します。 クエリ`(a, b)`穴の中にあるかどうかだけを知る必要があります。`x <= a`少なくとも最大の y を持つものが存在します`b`。 

これにより、問題はプレフィックス最大クエリに変換されます。 穴を並べ替えた後、x 座標の配列と対応する最大 y 値を保存します。 各クエリは二分探索を使用して最後のホールを見つけます。`x <= a`、次に、保存されている最大値 y を確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての穴を X 座標で並べ替えます。 2 つの穴が同じ x 座標を持つ場合、それらはすべて同じプレフィックスの一部になるため、相対的な順序は重要ではありません。 
2. プレフィックス最大配列を構築します。 ソートされた穴の各位置について、最初からその位置までのすべての穴の中で最大の y 座標を保存します。 この値は、x 座標が現在の x 座標以下であるすべてのホールの中で最も高い到達可能なホールを表します。 
3. Meeseeks のあらゆる提案に対して`(a, b)`、ソートされた x 座標で二分探索を使用して、次の穴を含む最後のインデックスを見つけます。`x <= a`。 X 座標が大きすぎるため、そのインデックス以降のすべてのホールに到達することはできません。 
4. そのようなインデックスが存在しない場合、開始点の左側に穴はないため、答えは次のようになります。`NO`。 それ以外の場合は、そのインデックスでのプレフィックスの最大 y 座標を次と比較します。`b`。 少なくともそれであれば`b`、到達可能な穴が存在し、その答えは`YES`。 

機能する理由: x で並べ替えると、すべてのプレフィックスに水平方向の要件を満たすホールが正確に含まれます。 そのプレフィックスに保存されている最大値 y は、それらの穴の中で考えられる最良の垂直位置を表します。 最大の y さえもクエリの y 座標よりも下にある場合、プレフィックスのすべてのホールが低すぎます。 最大値がクエリの y 座標に達すると、そのホールは両方の座標を満たし、到達可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    holes = []

    for _ in range(n):
        x, y = map(int, input().split())
        holes.append((x, y))

    holes.sort()

    xs = []
    pref_y = []

    best = 0
    for x, y in holes:
        xs.append(x)
        best = max(best, y)
        pref_y.append(best)

    q = int(input())
    ans = []

    import bisect

    for _ in range(q):
        a, b = map(int, input().split())

        idx = bisect.bisect_right(xs, a) - 1

        if idx >= 0 and pref_y[idx] >= b:
            ans.append("YES")
        else:
            ans.append("NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```ソートステップでは、プレフィックス処理用のポイントを準備します。 ソート後、インデックスで終わるすべてのプレフィックス`i`最大でも x 座標を持つ穴が正確に含まれます`xs[i]`。 

の`pref_y`配列には、各プレフィックスで利用可能な最も強力な垂直オプションが格納されます。 クエリでは、どのホールがそれを提供するかは気にせず、あるホールが十分な高さに達するかどうかのみを考慮するため、最大 y のみを保持するだけで十分です。 

クエリごとに、`bisect_right`最初の位置を見つけます。`a`X 配列をソートしたまま挿入できます。 1 を減算すると、最後の有効な穴が得られます。`x <= a`。 との比較`pref_y[idx]`垂直方向の要件を処理します。 

二分探索境界は最も間違いを犯しやすい場所です。 使用する`bisect_right`の代わりに`bisect_left`正確に開始 x 座標上のホールに到達できるため、これが必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 並べ替えのコストは O(n log n) で、各クエリは 1 つのバイナリ検索を使用します。 |
 | スペース | O(n) | ソートされた座標と接頭辞の最大値には、すべての穴の情報が格納されます。 |

 このソリューションはクエリごとに対数量の作業のみを実行するため、`100000`穴と`100000`クエリは制限内に簡単に収まります。

## 特殊なケース

 最初のエッジケースの場合:```
2
5 5
10 1
1
9 2
```アルゴリズムは穴を分類し、それのみを見つけます`(5,5)`の接頭辞に属します`x <= 9`。 そのプレフィックスの最大 y は次のとおりです。`5`、少なくとも`2`、したがって、答えは次のとおりです`YES`。 

クエリと同じデータの場合`(9,6)`、プレフィックスの最大値は依然として`5`、しかし今は必要な y 座標を下回っています。 アルゴリズムは戻ります`NO`、水平方向には到達可能だが垂直方向に高すぎる点を正しく拒否します。 

ゼロ距離移動の場合:```
1
7 4
1
7 4
```二分探索で穴が見つかるのは、`x <= a`値が等しい場合は true です。 プレフィックスの最大値 y も次と等しくなります。`b`、したがって、答えは次のとおりです`YES`。 

重複した穴の場合:```
3
2 3
2 3
5 1
1
2 3
```両方のコピー`(2,3)`並べ替えると先頭に表示されます。 プレフィックスの最大値は次のようになります。`3`となり、クエリは成功します。 このアルゴリズムは一意性に依存しないため、重複に対して特別な処理は必要ありません。
