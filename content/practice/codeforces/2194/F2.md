 ## 解決策
 ## 問題の理解

 木を特定のプロパティを持つ接続コンポーネントに切断する特定の方法を数えるように求められます。 木には、`n`それぞれの頂点に値が付いている`a_v`。 小さな数字のセットも与えられています`b_1, ..., b_k`。 エッジのセットは、それらのエッジを削除した後、接続されているすべてのコンポーネントがそのセットに属する頂点値のビットごとの XOR を持っている場合に美しいと呼ばれます。`b`。 タスクは、そのようなセットをすべて数えることです。`10^9 + 7`。 

潜在的なエッジのサブセットの数は指数関数的であるため、この問題は厄介です。`n`頂点には`n-1`エッジがあるので、`2^(n-1)`可能なサブセット。 明らかに、すべてのエッジの組み合わせを総当たりでチェックすることは不可能です。`n`まで`10^5`。 ただし、小さな制限`k ≤ 10`限られた数のターゲット XOR 値を活用して動的プログラミング ソリューションを設計できることを示唆しています。 

明白でないエッジ ケースには、すべての頂点値が 0 である場合や、次のような場合が含まれます。`b`ゼロが含まれています。 たとえば、すべての値が 0 と 0 である 3 つのノードからなるツリーの場合、`b = [0]`エッジをカットしないなど、複数の方法でエッジをカットできます。 単純なアプローチでは、ゼロ以外の XOR を生成し、有効な構成が欠落しているカットのみが考慮される可能性があります。 コンポーネントに単一のノードが含まれている場合、別のエッジ ケースが発生します。 その XOR はちょうど`a_v`したがって、アルゴリズムは単一ノードのコンポーネントを正しく処理する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、可能なすべてのエッジのサブセットを試し、結果として得られる各接続コンポーネントの XOR を計算し、すべてのコンポーネントの XOR がセットに属しているかどうかを確認します。`b`。 これは原理的には正しいですが、サブセットの数は`2^(n-1)`、大まかに言うと`10^30`いつ`n = 100`。 これは明らかに、実行可能な制限時間を超えています。 

重要な洞察は、ツリーの階層構造と、XOR が結合的で可逆的であることを認識することです。 サブツリーの XOR を考慮すると、その親までのエッジを切断するかどうかを決定できます。 具体的には、サブツリーの XOR が`b`、それを独立したコンポーネントとして扱うか (接続エッジを切断する)、上向きにマージを続けることができます。 これは、ツリー上での動的プログラミングのアプローチを示唆しています。 各ノードは、可能な XOR 値を、その XOR を生成するサブツリーを分割する方法の数にマッピングする DP テーブルを維持します。 

小さいもの`k`DP テーブルが大きくなりすぎないようにします。 すべてを追跡するのではなく、`2^30`XOR 値。最終的に要素に還元できる XOR を追跡するだけで済みます。`b`。 子サブツリーを結合する場合、XOR を使用してこれらの DP テーブルを結合し、状態を枝刈りすることができます。`b`計算を実行可能な状態に保つためです。 This converts an exponential problem into a linear-tree DP with manageable overhead.

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n-1) * n) | O(n) | 遅すぎる |
 | XOR 枝刈りを使用したツリー DP | O(n * 2^k) | O(n * 2^k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを任意に、たとえばノード 1 でルート化することから始めます。これにより、親を考慮する前にサブツリーを解決するボトムアップ DP アプローチが可能になります。 
2. ノードごとに辞書を維持します。`dp[x]`すべての頂点の XOR が等しくなるように、このノードをルートとするサブツリーを分割する方法の数を表します。`x`。 当初は、`dp[a_v] = 1`リーフノードの場合。 
3. DFS を使用してツリーを走査します。 ノードごとに、その子の DP テーブルを結合します。 子サブツリーを現在のノードにマージするとき、各 XOR を取得して形成されたすべての新しい XOR を計算します。`x`現在の DP と各 XOR から`y`子供のDPと録音から`x ^ y`。 
4. 子をマージした後、エッジの切断も考慮します。子の XOR が`b`、独立したコンポーネントを形成できます。 この場合、子の DP 値からウェイを乗算し、親とマージせずに個別に検討します。 
5. すべての子を処理した後、現在のノードの DP 値を確認します。 の各 XOR 値に対して、`b`、対応するカウントを保持します。 このプルーニングにより、DP は不要な XOR 値を追跡せず、次の値に制限されます。`2^k`。 
6. 最後に、ルートを処理した後、XOR 値のすべての DP カウントの合計が計算されます。`b`美しいエッジセットの総数を示します。 

正確さは、各ノードにおける不変式から得られます。`dp[x]`XOR を生成するサブツリーのすべての有効なパーティションを正しくカウントします。`x`。 XOR を介して子 DP テーブルをマージすると、すべての可能性が維持され、子 XOR が存在する場合はカットが考慮されます。`b`有効なパーティションが失われないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        edges = [[] for _ in range(n)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            edges[u-1].append(v-1)
            edges[v-1].append(u-1)
        a = list(map(int, input().split()))
        b_set = set(map(int, input().split()))
        
        def dfs(u, parent):
            dp = {a[u]: 1}  # xor -> ways
            for v in edges[u]:
                if v == parent:
                    continue
                child_dp = dfs(v, u)
                new_dp = {}
                # merge without cut
                for x1, cnt1 in dp.items():
                    for x2, cnt2 in child_dp.items():
                        new_x = x1 ^ x2
                        new_dp[new_x] = (new_dp.get(new_x, 0) + cnt1 * cnt2) % MOD
                # consider cut
                for x2, cnt2 in child_dp.items():
                    if x2 in b_set:
                        for x1, cnt1 in dp.items():
                            new_dp[x1] = (new_dp.get(x1, 0) + cnt1 * cnt2) % MOD
                dp = new_dp
            # prune to only relevant XORs
            dp = {x: cnt for x, cnt in dp.items() if x in b_set}
            return dp
        
        result = sum(dfs(0, -1).values()) % MOD
        print(result)

if __name__ == "__main__":
    solve()
```このコードは、DFS ツリー トラバーサルを設定し、ディクショナリ内の XOR を追跡し、子の DP テーブルをマージし、子の XOR が存在するたびにカットを考慮します。`b_set`。 プルーニングにより、関連する XOR のみが保存され、計算の実行可能性が維持されます。
