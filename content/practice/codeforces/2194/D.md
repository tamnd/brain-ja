 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$0 と 1 で埋められます。 左上隅から右下隅まで、右または下にのみ移動してカットする必要があります。 このカットにより、テーブルが 2 つの領域に分割されます。カットの「上または上」のセルと、カットの「下または上」のセルです。 各領域について、そこに含まれる 1 の数を数え、それらを次のように呼びます。$a$そして$b$。 私たちの目標は製品を最大限に活用することです$a \cdot b$また、この最大値を達成するカットのパスを 1 つ提供する必要があります。 

入力では、次のグリッドが許可されます。$n$そして$m$まで$3 \cdot 10^5$合計ですが、すべての合計$n \cdot m$テストケース全体の境界は次のとおりです$3 \cdot 10^5$。 これは、テスト ケースあたりのセル数が線形より遅いものは許容できないことを意味します。$O(n \cdot m)$。 二次関数またはより複雑な組み合わせアプローチでは、時間がかかりすぎます。 

テーブルが非常に小さい場合、トリッキーなエッジケースが発生します。たとえば、$2 \times 2$みんなと一緒に。 どのパス カットにも両方の領域に複数のセルが含まれるため、「次の 1 を選択するだけ」に基づく単純な貪欲なカットでは、最適な分割を見逃す可能性があります。 もう 1 つの微妙なシナリオは、コーナーにクラスターが集まっている場合です。厳密に 1 つのエッジに沿って移動するパスを選択すると、バランスのとれたカットと比較して製品が大幅に変わる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、左上隅から右下隅まで可能なすべてのパスを列挙し、$a$そして$b$パスごとに最大値を取得します。 パスの数$n \times m$グリッドは$\binom{n+m-2}{n-1}$、指数関数的に増加します。 控えめなグリッドの場合でも、これは大きすぎるため、このアプローチは非常に小さい場合にのみ機能します。$n$そして$m$。 

効率的なアプローチの重要な洞察は、カットが右または下に移動する単調なパスとして表現でき、「R」と「D」のシーケンスとしてエンコードできることです。 行と列に沿って 1 のプレフィックスの合計を計算し、次のステップを下に進むべきか右に進むべきかを貪欲に推論できます。 それぞれの決定は、次の行と次の列を含めた場合の積の潜在的な増加を比較することによって行うことができます。 前進するだけであり、積は累積積に関して凸であるため、各ステップでの局所的な最適な選択が全体的な最適化につながることを保証できます。 

したがって、問題を、指数関数的に多くのパスを列挙することから、両方のパーティションのパスの累計を追跡しながら貪欲に 1 つのパスを構築することに軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^{n+m}) | O(nm) | 遅すぎる |
 | 最適 (プレフィックス合計で貪欲) | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、テーブル全体の 1 の合計数を計算します。 これにより、減算によってカットの「他の部分」のカウントを計算できるようになります。 
2. 現在の位置、カットの上/上の領域内の 1 の数、およびパス文字列を追跡する変数を初期化します。 左上隅から始めます。 
3. 各ステップで、可能であれば右または下に移動することを検討してください。 各方向に移動した場合に最初の領域に追加される 1 の数を計算します。 結果の積を一時的に計算します$a \cdot b$両方の選択肢に対して。 
4. 結果として得られる製品を最大化する方向を選択します。 同点の場合は、どの選択も有効です。 現在の位置を更新し、セルに 1 が含まれている場合は最初の領域の 1 のカウントを増分し、選択した方向をパス文字列に追加します。 
5. 右下隅に到達するまで繰り返します。 その時点でパスは完成し、最終製品は可能な限り最大のものになります。 

これが機能する理由は、すべてのステップで、潜在的な製品を局所的に最大化する決定を下すためです。 積は各領域の累積積に線形に依存し、カットは単調であるため、貪欲な選択により最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        
        # Compute prefix sums
        pref = [[0]*(m+1) for _ in range(n+1)]
        for i in range(n):
            for j in range(m):
                pref[i+1][j+1] = grid[i][j] + pref[i][j+1] + pref[i+1][j] - pref[i][j]
        
        total_ones = pref[n][m]
        a_count = 0
        i = j = 0
        path = []
        
        while i < n-1 or j < m-1:
            if i == n-1:
                j += 1
                a_count += grid[i][j]
                path.append('R')
            elif j == m-1:
                i += 1
                a_count += grid[i][j]
                path.append('D')
            else:
                # Check moving right
                right_a = a_count + grid[i][j+1]
                right_b = total_ones - right_a
                right_prod = right_a * right_b
                # Check moving down
                down_a = a_count + grid[i+1][j]
                down_b = total_ones - down_a
                down_prod = down_a * down_b
                if right_prod >= down_prod:
                    j += 1
                    a_count += grid[i][j]
                    path.append('R')
                else:
                    i += 1
                    a_count += grid[i][j]
                    path.append('D')
        
        b_count = total_ones - a_count
        print(a_count * b_count)
        print(''.join(path))

solve()
```コードはプレフィックスの合計を計算して、必要に応じて長方形の合計にすばやくアクセスできるようにします。ただし、ここでは次のセルを段階的に追加するだけです。 各ステップでの決定では、製品を右に移動するか下に移動するかを比較します。 最終行または最終列に到達したときに移動を強制することで、境界条件を処理します。 Off-by-1 エラーは、アクセス時にゼロベースのインデックスを慎重に使用することで回避されます。`grid[i][j]`。
