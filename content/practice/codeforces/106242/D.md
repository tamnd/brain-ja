 ## 解決策
 ## 問題の理解

 このタスクは、gcd と lcm に基づく数論的なペアリング ルールを使用して、正の整数でインデックス付けされた 2 つのシーケンスを結合することです。 概念的には、出力内の各位置は入力配列内の位置のペアから集計された値を表しますが、等しいインデックスまたはシフトによってペアにするのではなく、ペアはインデックス間の算術構造によって決定されます。 

問題の一部では、最大公約数が指定された値に等しいすべてのペアの寄与を求めます。 別の部分では、最小公倍数が指定された値に等しいすべてのペアの寄与を対称的に求めます。 有効な各ペアは、2 つの配列の対応する値の積を、その gcd または lcm 条件によって決定される 1 つの出力バケットに入力します。 

したがって、インデックスの加算に関する古典的な畳み込みの代わりに、これは整数の除数格子に関する畳み込みです。 答えの構造は、値が約数とインデックスの倍数にどのように分布するかによって完全に決まります。 

最大インデックスが最大約 10^5 または同様の場合、すべてのインデックス ペアにわたる二次ペア列挙は実行できなくなります。 平$10^5$要素が意味するものは$10^{10}$ペアチェックは現実的な制限時間をはるかに超えています。 したがって、ソリューションでは、各ペアが明示的に反復されることがなく、代わりに寄与が約数または倍数にわたってグループ化された形式で集約されるように計算を再編成する必要があります。 

多重度を考慮せずに、gcd 条件または lcm 条件をインデックスに対する単純な算術制約として処理しようとすると、微妙な失敗例が発生します。 たとえば、各数値の約数に基づいて寄与のみを個別に累積すると、複数の約数の関係を共有するペアを二重にカウントする可能性があります。 

配列のインデックスが 1..6 であり、gcd 寄与を計算するという小さなシナリオを考えてみましょう。 ペア (2,4) には gcd 2 がありますが、共有除数 1 を通じて間接的にも寄与します。正確な gcd クラスを分離しない素朴な除数加算方法では、この寄与が 1 つではなく複数のバケットに誤って配置されます。 正しい定式化では、各ペアが、それが属する正確な gcd または lcm クラスにのみ寄与することを保証する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 インデックスのペアごとに$i, j$、どちらかを計算します$\gcd(i,j)$または$\mathrm{lcm}(i,j)$そして追加します$a[i] \cdot b[j]$対応する出力バケットに送信されます。 これは、畳み込みの定義に直接従うため、正しいです。 ただし、すべてのインデックスのペアを反復処理する必要があるため、次のようになります。$O(n^2)$操作。 いつ$n$到達する$10^5$、これは次のことにつながります$10^{10}$制限時間内に実行できない操作。 

重要な点は、gcd 条件と lcm 条件が、除数と複数の関係を使用してインデックスを再作成できる整数ペアのパーティションを定義していることです。 ペアの観点から考える代わりに、視点を切り替え、値を固定します。$d$、で割り切れるすべてのインデックスをグループ化します。$d$。 すべてのインデックスは次の倍数として書き込むことができます。$d$、および gcd または lcm 制約は、この縮小された空間で変換されたインデックスを通じて表現できます。 

ここで、除数変換が強力になります。 各約数の倍数にわたって値を累積することにより、ペアごとの条件を独立した合計に変換できます。 gcd ベースの集計の場合、まず公約数を共有するすべてのペアにわたる寄与を計算し、次にメビウス反転を使用して過剰にカウントされた寄与を減算します。 lcm ベースの集計では、視点を逆にします。倍数にわたって蓄積し、正しい最小公倍数クラスに寄与を慎重に分配します。 

全体の問題は、ペアを列挙するのではなく、少数の構造化除数和変換を実行することに帰着します。

 ## アルゴリズムのチュートリアル

 gcd 畳み込みの計算について説明します。 lcm バージョンでは、約数と倍数の間で役割が対称的に逆転します。 

1. 配列を初期化する`F[d]`インデックスが次の倍数であるすべてのペアの寄与を累積します。`d`。 それぞれの値について`d`で割り切れるすべてのインデックスを集めます。`d`なぜなら、gcd および lcm 制約はこれらの共有約数グループを通じて分解できるからです。 
2. For each divisor`d`、すべての倍数を反復処理します。`i = d, 2d, 3d, ...`の合計を蓄積します`a[i]`一時配列に入れる`Adiv[d]`。 に対しても同じことを行います`b[i]`の中へ`Bdiv[d]`。 このステップでは、元の配列を除数空間表現に圧縮します。 
3. それぞれについて`d`、予備的なペアの寄与を計算します`F[d] = Adiv[d] * Bdiv[d]`。 これは、両方のインデックスが少なくとも約数を共有するすべてのペアをカウントします。`d`、つまり、gcd は次の倍数になります。`d`、必ずしも等しいとは限りません`d`。 これは過剰にカウントされた数量ですが、有用な方法で構成されています。 
4. メビウス反転を約数に対して降順で適用します。 それぞれについて`d`、すべての倍数の寄与を差し引きます。`k*d`から`F[d]`。 これにより、gcd が正確に一致するペアが正確に分離されます。`d`、gcd が厳密に大きいペアから寄与を削除します。 
5. 結果として`F[d]`各値の正確な gcd 畳み込み結果を表すようになりました。`d`。 
6. lcm 畳み込みでは、視点を逆にします。 公約数でグループ化する代わりに、共有倍数でグループ化します。 約数からの寄与を上方に計算し、ふるいのような伝播を使用してそれらを倍数に分配し、各ペアがその最小公倍数に 1 回だけ寄与するようにします。 

正しさは、整数のすべてのペアが一意の gcd クラスと一意の lcm クラスに対応し、除数閉包によってこれらのクラスを複数のセットにわたる線形結合として表現できるという事実に依存します。 

不変条件とは、値を処理した後の条件です。`d`、すべてのオーバーカウントは厳密な倍数から計算されます。`d`は削除され、gcd が正確に一致するペアからの寄与のみが残ります。`d`。 除数格子は降順で処理されるため、より高い gcd 寄与は低いものから減算される前に完全に解決され、循環依存性が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 100000

def solve():
    n = int(input())
    a = [0] * (MAXN + 1)
    b = [0] * (MAXN + 1)

    arr = list(map(int, input().split()))
    for i in range(1, n + 1):
        a[i] = arr[i - 1]

    arr = list(map(int, input().split()))
    for i in range(1, n + 1):
        b[i] = arr[i - 1]

    Adiv = [0] * (MAXN + 1)
    Bdiv = [0] * (MAXN + 1)

    for d in range(1, n + 1):
        s = 0
        for i in range(d, n + 1, d):
            s += a[i]
        Adiv[d] = s

    for d in range(1, n + 1):
        s = 0
        for i in range(d, n + 1, d):
            s += b[i]
        Bdiv[d] = s

    F = [0] * (MAXN + 1)

    for d in range(n, 0, -1):
        F[d] = Adiv[d] * Bdiv[d]
        k = 2 * d
        while k <= n:
            F[d] -= F[k]
            k += d

    print(*F[1:n + 1])

if __name__ == "__main__":
    solve()
```コードはまず各配列を除数和形式に圧縮します。`d`で割り切れるインデックスのすべてのエントリの合計を格納します。`d`。 これにより、元のペア空間が除数格子表現に変換されます。 

乗算ステップでは、過剰にカウントされた構造が構築されます。`F[d]`少なくとも約数を共有するすべてのペアが含まれます`d`。 次に、減算ループは下方向に反復して、より厳密なすべての除数から寄与を除去し、より高い倍数が最初に解決されるようにします。 この順序は重要です。`F[k]`は、除数から減算される前に必要です。 

よくある落とし穴は反復です`d`反転時は上向きになります。 これにより、まだ完全に修正されていない値が減算され、不正確なカウントが格子内に伝播されます。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
a = [1, 2, 3, 4]
b = [4, 3, 2, 1]
```約数の合計を計算します。 

| d | Adiv[d] | Bdiv[d] | 減算前の F[d] |
 | --- | --- | --- | --- |
 | 4 | 4 | 1 | 4 |
 | 3 | 3 | 2 | 6 |
 | 2 | 6 | 4 | 24 |
 | 1 | 10 | 10 | 100 |

 次に、倍数を引きます。 

d = 2 の場合: F[4] を減算 → 24 - 4 = 20

 d = 1 の場合: F[2]、F[3]、F[4] を減算 → 100 - 20 - 6 - 4 = 70

 最終:

 | d | F[d] |
 | --- | --- |
 | 1 | 70 |
 | 2 | 20 |
 | 3 | 6 |
 | 4 | 4 |

 このトレースは、各 gcd クラスがすべての厳密な倍数を処理した後にのみ分離されるという不変条件と一致して、より低い除数を確定する前に、より高い除数の寄与がどのように除去されるかを示しています。 

### 例 2

 入力:```
n = 6
a = [1,1,1,1,1,1]

```すべての約数の合計は倍数になります。 

| d | Adiv[d] | Bdiv[d] | 初期 F[d] |

 ## 特殊なケース

 重要なエッジ ケースは、すべての値が小さい数の倍数のインデックスに配置される場合です。たとえば、すべての非ゼロ エントリが偶数の位置にのみ現れる場合です。 その状況では、奇数の値の約数の合計はゼロのままで、偶数の約数のみが寄与を蓄積します。 奇数の約数は決して質量を受け取らないため、アルゴリズムはこれを自然に処理します。`Adiv`または`Bdiv`したがって、偽の gcd 寄与は決して生成されません。 

もう 1 つの微妙なケースは、配列のインデックスに 0 以外のエントリが 1 つある場合です。`n`。 ゼロ以外の除数バケットのみが次の除数です。`n`、そして反転ステップは、その寄与を の除数チェーンに沿ってのみきれいに伝播します。`n`。 これにより、各インデックスはそれ自体の除数構造の倍数にのみ関与するため、無関係な除数チェーン間で相互汚染が発生しないことが確認されます。
