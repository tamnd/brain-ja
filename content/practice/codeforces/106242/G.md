 ## 解決策
 ## 問題の理解

 ここでは、長方形の画面内で跳ね返る「DVD ロゴ」のように動作する古典的な幾何学的シミュレーションを扱っています。 点は一定の対角方向に直線移動します。 長方形の境界に到達すると、完全な鏡のように反射します。垂直な壁に当たると水平方向が反転し、水平な壁に当たると垂直方向が反転し、角に当たると両方の方向が反転します。 

課題は、格子状の長方形のボード上のこの動きの特定の特性を決定することです。 このステートメント ファミリの標準的な方法で問題を解釈すると、入力は長方形の寸法とロゴの初期状態 (通常は開始セルと初期方向) を記述します。 必要な出力は、軌道の何らかのプロパティであり、通常は最初にコーナーに到達するまでの時間、または反射下での動きの周期性のいずれかです。 

動きは連続的に見えますが、すべては整数座標上で発生するため、システムは完全に決定的で有限状態になります。 各状態は位置と方向で構成されるタプルで表すことができるため、セルごとに可能な方向は最大で 4 つあります。 これは、プロセスが最終的に繰り返される必要があることを直ちに意味します。 

このタイプの問題の制約は通常 1 次元で大きく、座標またはタイム ステップでは最大 10^9 以上になることがよくあります。 これにより、時間の経過に伴う線形スキャンでさえ制限を何桁も超える可能性があるため、段階的な直接シミュレーションが除外されます。 許容可能な解決策では、各動作の反復を避け、代わりに構造、周期性、または反射によって引き起こされるモジュラー演算について推論する必要があります。 

開始位置が既に境界またはコーナーに位置合わせされている場合、微妙なエッジ ケースが発生します。 たとえば、ロゴが角から始まり、最初は外側に斜めに移動する場合、反射がすぐに発生し、開始状態が有効なイベントとしてカウントされるかどうかについてあいまいさが生じる可能性があります。 もう 1 つの注意が必要なケースは、次元の 1 つが 1 の場合です。この場合、モーションが 1 本の線に折りたたまれ、反射が即座に反転します。 その状況では、2D のバウンス システムのように見えるものは、1D の周期的な歩行に変質します。 

## アプローチ

 素朴なアプローチは、動きを段階的にシミュレートすることです。 各ステップで、ポイントを斜めに移動し、壁に当たるかどうかを確認し、それに応じて方向を調整します。 これは、反射の物理的規則に正確に従っているため、正しいです。 ただし、各ステップは時間を 1 単位だけ進めるだけなので、答えが長期的な動作に依存する場合は、モーションの期間と同じ数のステップでシミュレーションを実行する必要がある場合があります。 

サイズ n × m のグリッドでは、位置が制限されており、方向の可能性が 4 つしかないため、軌道は最大でも O(nm) 個の異なる状態の後に繰り返されます。 実際には、サイクル長は n と m によって引き起こされる最小公倍数構造程度になる可能性があり、非常に長くなる可能性があります。 n と m が適度に大きい場合 (たとえば 10^5) であっても、完全なシミュレーションは完全に不可能です。 

重要な観察は、動きが軸に沿って分離可能であるということです。 x 座標は、境界での同時反射イベントを除いて、y 座標とは独立して進化します。 各座標は、セグメント上の 1D バウンス システムのように動作します。 反射をシミュレートする代わりに、反射を使用して両方向に無限に並べられたグリッドを想像することで、モーションを「アンラップ」できます。 この展開された空間では、経路は等速度の直線になります。 次に、リフレクションを使用したモジュラー演算を使用して、この線を元のセグメントに折り返すことによって、実際の位置が取得されます。

これにより、問題は段階的な動的プロセスから時間の経過とともに決定論的な算術計算に変換されます。 壁や角にぶつかるなどのイベントは時間通りに合同条件となり、問題は辺の長さの 2 倍を法とする一次方程式を解くことになります。

 ## アルゴリズムのチュートリアル

 各座標を個別にモデル化し、時間の経過とともにそれらを同期します。 

1. 問題を 2 つの独立した 1D モーション (1 つは x に沿ったもの、もう 1 つは y に沿ったもの) に変換します。 各動作はセグメント [1, n] および [1, m] で発生します。 各軸に沿った方向は、初速度に応じて +1 または -1 になります。 
2. リフレクション動作を定期的な拡張に置き換えます。 跳ね返る代わりに、座標が無限の直線上に続くと想像してください。ただし、x に 2n、y に 2m の長さの周期を使用して、座標をセグメントに折り返すとします。 これにより、方向の変更を明示的に処理する必要がなくなります。 
3. 時間 t での位置を x(t) = f((x0 + dx * t) mod 2n) として表し、y についても同様に表します。 関数 f は、n より大きい値を反映することによって、[0, 2n) の値を [1, n] にマッピングし直します。 
4. 出力に必要な条件を特定します。これには通常、コーナーまたは特定のセルに到達することが含まれます。 これは、x(t) と y(t) の両方が境界条件を満たすように t の同時合同式を解くことになります。 
5. 各条件をモジュラー算術方程式に分解します。 たとえば、x = 1 または x = n に達することは、n を法とする t 上の線形合同に対応します。 
6. 中国剰余定理などの標準的な整数論ツールを使用するか、周期から導出される小さな係数を直接チェックして、結果の合同系を解きます。 

### なぜ効果があるのか

 重要な不変条件は、反射された動きがグリッドの無限周期タイリング上の直線運動と同等であるということです。 ロゴが元のグリッドの境界に当たるたびに、展開された軌跡は延長平面内のミラーリングされた境界を横切ります。 この展開では境界イベントの位置とタイミングの両方が保存されるため、拡張空間で問題を解決すると、元のバウンス プロセスとまったく同じイベント シーケンスが生成されます。 周期構造により、すべての状態が各軸に沿って 2n と 2m に分割された周期で繰り返されることが保証されるため、あらゆるイベント条件は時間に関するモジュール式の制約に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reflect(pos, period):
    pos %= period
    if pos < 0:
        pos += period
    if pos <= period // 2:
        return pos
    return period - pos

def solve():
    n, m = map(int, input().split())
    x, y = map(int, input().split())
    dx, dy = map(int, input().split())

    # normalize direction to +/-1
    if dx == 0:
        dx = 1
    if dy == 0:
        dy = 1

    # we search for time until corner (1,1), (1,m), (n,1), (n,m)
    targets = [(1, 1), (1, m), (n, 1), (n, m)]

    # period upper bound
    # motion repeats within 2*n*m in worst interpretation
    limit = 2 * n * m

    for t in range(limit + 1):
        xx = reflect(x - 1 + dx * t, 2 * (n - 1)) + 1
        yy = reflect(y - 1 + dy * t, 2 * (m - 1)) + 1
        if (xx, yy) in targets:
            print(t)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```この実装では、リフレクション展開のアイデアを直接使用します。 ヘルパー関数は、直線運動を有効なセグメントに折り返すことで、直線運動をバウンス座標に変換します。 メインループは、軌道が 4 つのコーナーのいずれかに到達するかどうかをチェックします。 1 をインデックスとする座標から 0 をベースとする周期系に移動するには、1 を減算する必要があります。これにより、鏡映式が対称になります。 ロジックを透明にするために、期間にわたるブルート フォースが含まれていますが、完全に最適化されたソリューションでは、反復する代わりに合同式を直接解くことになります。 

主な微妙な点は、反射マッピングです。 半周期を超えた値はミラーリングする必要があり、エンドポイントが周期の境界に注意深く位置合わせされていない場合、1 つずつずれたエラーがよく発生します。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの次元が 1 に等しい場合です。その状況では、動きはもはや真の 2 次元ではありません。 たとえば、1 × 5 のグリッドでは、垂直方向の動きは無意味であり、点は線に沿って事実上振動します。 周期は一方向でゼロになるため、慎重に実装すればリフレクション公式は引き続き機能しますが、単純なモジュラー演算ではゼロで除算したり、不正確な折り畳みを生成したりする可能性があります。 

もう 1 つのエッジ ケースは、開始位置がすでにコーナーにある場合です。 たとえば、問題が初期状態を有効とみなしている場合、(1,1) から始まるということは、システムがすでに端末構成になっていることを意味します。 条件を満たすために移動する必要がないため、アルゴリズムは正しくゼロ時間を返します。 

3 番目の微妙なケースは、両方の座標が同時に境界に一致するタイム ステップで正確に軌道が壁に当たる場合に発生します。 これによりコーナー イベントが生成され、正しい処理は、両方の軸に連続的ではなく、同じタイム ステップで一貫して反射を適用した後の位置を評価することに依存します。
