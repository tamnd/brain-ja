 ## 解決策
 ## 問題の理解

 離散的な動きで進化するプロセスをシミュレートしています。 空から始まるコンテナがあり、Alya は正確に実行します`n`アクション。 最初のアクションは修正されています。彼女は常にキャンディーを 1 つだけ追加します。 その後、各アクションは現在の状態と増加する「バッチ サイズ」に応じて異なります。 

2 回目のアクション以降、可能であればキャンディーを 1 つ削除するか、キャンディーのバッチを追加します。 バッチのサイズは一定ではありません。 キャンディーを追加することを選択するたびに、追加する量は最後にキャンディーを追加したときよりも 1 つ増えます。 したがって、追加は 1 から始まる厳密に増加するシーケンスを形成しますが、削除が挟み込まれます。 

最後に 2 つのパラメータが与えられます: アクションの総数`n`、最終的なキャンディーの数`k`すべてのアクションの後、ボックスに残ります。 課題は、彼女が除去手術を行った回数を特定することであり、これは彼女が食べたキャンディーの数に相当します。 

制約は非常に大きく、`n`1e9まで。 これにより、アクションの線形スキャンですら遅すぎるため、プロセスの段階的なシミュレーションが即座に除外されます。 代わりに、ソリューションは、追加と削除がどのように相互作用するかから構造を抽出することに依存する必要があります。 

除去が早い段階で優勢になると、微妙なエッジケースが現れます。これは、追加が大きくなる一方で、除去はカウントを 1 減らすだけであるためです。 加算のグローバル構造を追跡せずに「ボックスを非負に保つ」ことを試みる単純な貪欲なシミュレーションは失敗します。 たとえば、追加は頻繁に行われるが、削除が早期にまばらに行われる小規模なシナリオでは、単純なアプローチでは将来の大規模な追加の寄与が過小評価され、食べたキャンディーの最終的な再構成が不正確になる可能性があります。 

主な難しさは、プロセスをシミュレートすることを求められるのではなく、決定論的な進化から 1 つの欠落した統計を再構築することを求められることです。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの`n`直接的なアクション。 現在のキャンディーの数を維持し、次の追加サイズを追跡し、追加するか削除するかに応じてカウンターを増分します。 これは簡単でルールを正確に反映していますが、次の場合には不可能になります。`n`大きいです。 1e9 ステップでは、Python では単純なループでも遅すぎます。 

重要な観察は、プロセスの構造が「加算サイズ」において単調であるということです。 キャンディーを追加するたびに、削除とは関係なく、その量は厳密に増加します。 削除は次の追加サイズには影響しません。 これにより、進化が 2 つの独立したカウンター (追加が発生した回数と削除が発生した回数) に分離されます。 

させて`e`食べたキャンディー（除去）の数になります。 すると加算数は`n - 1 - e`, 最初の動きは常に追加なので。 追加されるキャンディーの総数は、最初のキャンディーの合計です。`(n - e)`自然数。 この合計から、`e`削除の場合、最終値を一致させる必要があります`k`。 

これにより、問題全体が、三角数と線形補正項を含む単一の方程式を解くことに帰着します。 関数は単調なので、`e`、二分探索を使用して解決できます。

 | 答えの二分探索 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 しましょう`e`食べたキャンディーの数になります。 

1.修正`e`そしてプロセスを正確に次のものとして解釈します`n - e`合計の加算演算。 最初の演算は常に加算であるため、`n - e`1から加算を増やしていきます。 
2. すべての追加によって追加されたキャンディーの合計を、最初のキャンディーの合計として計算します。`(n - e)`正の整数。 これは三角数であり、挿入操作からのすべての寄与を表します。 
3. 減算`e`除去するたびにボックスのキャンディーがちょうど 1 つ減るため、この合計から除去を計算します。 
4. 得られた最終的なキャンディー数を次と比較します。`k`。 これにより、次の単調関係が得られます。`e`、増えているので`e`追加を減らし、削除を増やします。 
5. 二分探索を使用する`e`範囲内で`[0, n]`一致する一意の値を見つけるには`k`。 

### なぜ効果があるのか

 重要な不変条件は、一定の除去数に対して`e`、最終的なキャンディーの数は完全に決定されます。 加算による寄与は、発生した加算ステップの数にのみ依存し、除去は独立した単位の減算です。 として`e`が増加すると、加算の数を減らし、減算の数を同時に増やすため、結果として得られる最終値は厳密に減少します。 この単調性により、一意の解が保証され、二分探索が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc(n, e):
    # number of additions = n - e
    a = n - e
    # sum of first a integers
    total_add = a * (a + 1) // 2
    # remove e candies
    return total_add - e

n, k = map(int, input().split())

lo, hi = 0, n
ans = 0

while lo <= hi:
    mid = (lo + hi) // 2
    val = calc(n, mid)
    if val == k:
        ans = mid
        break
    elif val > k:
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```機能`calc`食べたキャンディーの仮定の数に対して最終的なキャンディーの数を再構築します。`e`。 二分探索では、考えられるすべての値を調べます。`e`単調性を使用して、反復ごとに検索スペースの半分を破棄します。 

重要な詳細は、加算を自然数の前置和として解釈することです。 それが確立されると、残りの実装は直接単調反転です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def calc(n, e):
        a = n - e
        return a * (a + 1) // 2 - e

    n, k = map(int, input().split())

    lo, hi = 0, n
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        val = calc(n, mid)
        if val == k:
            ans = mid
            break
        elif val > k:
            lo = mid + 1
        else:
            hi = mid - 1

    return str(ans)

 ## 特殊なケース

 重要なエッジケースの 1 つは、除去がまったくない場合です。 たとえば、入力`n = 10, k = 55`これは、すべての追加を取得し、食べる操作をまったく使用しないことに相当します。 アルゴリズムはチェックすることでこれを処理します。`e = 0`、ここで、計算された三角和はすでに最終値と等しくなります。 

除去が最大になると、別の特殊なケースが発生します。 もし`e = n`の場合、強制された最初のステップ以外に加算は行われず、システムはすぐに減算によって支配されるようになります。 この公式は今でも適用されます。`n - e`中間推論ではゼロまたは負になりますが、二分探索では制限されます。`e`式が範囲内で有効なままになるようにします。 

最後に、次のようなケース`k`非常に小さいため、二分探索によって自然に処理されます。`e`最終値を減らし、等価条件が満たされるまで、検索はより高い除去カウントに向かって収束します。
