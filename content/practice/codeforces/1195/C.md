 ## 解決策
 ## 問題の理解

 学生の横 2 列が与えられ、各列には同じ数の人々が含まれます。 各生徒には身長があり、厳格な順序付けルールに基づいてこれら 2 つの行から生徒を選択してチームを構築したいと考えています。つまり、左から右へ選択を開始すると、インデックスを決して後戻りすることはできません。また、同じ行から 2 人の生徒を連続して選択することも禁止されています。 

これにより、2 つの並列配列にわたって制約付きシーケンスの問題が発生します。 各ステップで、次の生徒を一番上の行または一番下の行から選択しますが、その列のインデックスが最後に選択した生徒のインデックスよりも厳密に大きい場合に限り、行は前の選択と交互になります。 

目標は、選択した生徒の身長の合計を最大化することです。 

制約$n \le 10^5$位置のペアに対する指数関数または二次動的計画法は即座に除外されます。 すべてのインデックスのペア間のすべてのシーケンスまたはすべての遷移を明示的に考慮しようとするソリューションは、遅すぎます。 線形または線形に近いアプローチが必要です。 

微妙な問題は、隣接する列を選択する必要がないことです。 列を完全にスキップすることもできます。これは、基本的に各ステップで、反対側の行のすべての有効なポジションの中から将来の最適な候補を選択することを意味します。 次に利用可能な 2 人の生徒のうち背の高い方を常に選択するような素朴な貪欲な選択は失敗します。局所的に最適な選択により、後でより優れた交互のチェーンへのアクセスがブロックされる可能性があるためです。 

典型的な失敗シナリオは、わずかに小さい即時ピックにより、他の行のはるかに大きい将来のシーケンスにアクセスできる場合です。 たとえば、1 つの行の早い段階で大きな値を選択すると、後で小さな値のシーケンスが強制される可能性がありますが、少し待って行を早めに切り替えると、より高い合計が得られます。 

この構造は、各行での決定が将来のインデックスから始まる最良の継続に依存することを示唆しています。これは、ポジションに対する動的プログラミングの古典的なシグナルです。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての最初の選択肢から開始して、すべての有効な交互シーケンスをシミュレートしようとします。 各開始セルから、より高いインデックスを持つ反対側の行にある有効な次のセルすべてに分岐し、合計を累積します。 これは、各位置から反対側の行にある将来の多くの位置にジャンプでき、それぞれがさらなる分岐につながるため、指数関数的に大きな状態空間を探索します。 有効なシーケンスが依然として非常に多数存在する可能性があるため、枝刈りを行っても最悪の場合の爆発は防止できません。 

重要な観察は、修正すると現在列に到達しているということです。$i$1 つの行では、関連する将来の選択肢のみが、反対側の行の より大きいインデックスにあります。$i$。 これらすべての将来の選択の中で、私たちはそのインデックスから始まる可能な限り最良の継続のみを考慮します。 これは、最適なサフィックス値を事前に計算することを示唆しています。 

2 つの DP 配列を定義しましょう。$dp_1[i]$最後に選択した生徒が行 1、列にいる場合に取得できる最高の合計です。$i$。 同様に、$dp_2[i]$行 2 に定義されています。 

もし私たちがいるなら$dp_1[i]$、次の選択は、インデックスの行 2 から行われる必要があります。$j > i$。 からの最高の続き$j$すでにエンコードされています$dp_2[j]$。 したがって、次のことが必要です。$$dp_1[i] = h_{1,i} + \max_{j > i} dp_2[j]$$そして同様に:$$dp_2[i] = h_{2,i} + \max_{j > i} dp_1[j]$$この構造により、実行中のサフィックス最大値を維持しながら、右から左に DP を計算できます。

 | 接尾辞 maxima を含む最適な DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を作成します$dp_1$そして$dp_2$、最初はゼロで埋められます。 これらは、そのポジションがその行の最後のピックとして選択されたときに、各ポジションから開始して達成可能な最良の合計を表します。 
2. 2 つの実行変数も維持します`best1`そして`best2`の最大値を表します。$dp_1[j]$そして$dp_2[j]$すべてのインデックスに対して$j > i$。 これらは、遷移に必要な接尾辞の最大値をエンコードします。 
3. インデックスを右から左にトラバースします。$i = n-1$まで$0$。 この順序により、状態を計算するときに次のことが保証されます。$i$、右側の状態はすべて既知です。 
4. 各インデックスで$i$、次を計算します。$dp_1[i] = h_{1,i} + best2$そして$dp_2[i] = h_{2,i} + best1$。 これは、すでに計算された最良の継続を使用して遷移ルール​​を直接適用します。 
5. インデックスの両方の値を計算した後$i$、 アップデート`best1`そして`best2`を使用して$dp_1[i]$そして$dp_2[i]$。 これにより、将来の (左方向の) 州が正しいサフィックス情報を使用できるようになります。 
6. すべてのインデックスを処理した後、答えはすべてのインデックスの中で最大になります。$dp_1[i]$そして$dp_2[i]$、最初に選ばれた生徒はどこからでも始めることができるためです。 

### なぜ効果があるのか

 正確さは、すべての有効な交互シーケンスが明確に定義された最初に選択されたインデックスを持ち、その後、DP 依存性の観点から「残りのサフィックス選択肢」の厳密に減少するシーケンスを持っているという事実にかかっています。 どの位置でも$i$、行を切り替えた後の最適な継続は、厳密に右から始まる最適な継続にのみ依存します。 右から左に処理することで、すべてのサフィックスの選択がすでに最適に解決されていることを保証するため、すべての有効な継続を完全に把握した状態で各 DP 状態が計算されます。 これにより、今後の改善によって計算された状態が無効になることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    dp1 = [0] * n
    dp2 = [0] * n

    best1 = 0
    best2 = 0

    for i in range(n - 1, -1, -1):
        dp1[i] = a[i] + best2
        dp2[i] = b[i] + best1

        if dp1[i] > best1:
            best1 = dp1[i]
        if dp2[i] > best2:
            best2 = dp2[i]

    print(max(best1, best2))

if __name__ == "__main__":
    solve()
```このコードは、前述のサフィックス DP を直接実装します。 配列`dp1`そして`dp2`各インデックスから始まる最適な値を保存しますが、実際には接尾辞の最大値を更新するためにのみ必要です。 変数`best1`そして`best2`DP テーブルを行ごとに O(1) メモリに圧縮します。 

逆反復は、位置を計算するときに次のことが保証されるため、不可欠です。$i$、すべての州$j > i$はすでに接尾辞 maxima に組み込まれています。 最終的な答えは、両方の行にわたって最適な開始点を取得します。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [9, 3, 5, 7, 3]
b = [5, 8, 1, 4, 5]
```右から左に処理していきます。 

| 私 | dp1[i] | dp2[i] | ベスト1 | ベスト2 |
 | --- | --- | --- | --- | --- |
 | 4 | 3 + 0 = 3 | 5 + 0 = 5 | 3 | 5 |
 | 3 | 7 + 5 = 12 | 4 + 3 = 7 | 12 | 7 |
 | 2 | 5 + 7 = 12 | 1 + 12 = 13 | 12 | 13 |
 | 1 | 3 + 13 = 16 | 8 + 12 = 20 | 16 | 20 |
 | 0 | 9 + 20 = 29 | 5 + 16 = 21 | 29 | 21 |

 最終的な答えは29です。 

このトレースは、サフィックスの寄与がどのように蓄積されるかを示しています。各位置は、厳密にその右側の反対側の行にある最良の継続から恩恵を受けています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    dp1 = [0] * n
    dp2 = [0] * n
    best1 = best2 = 0

    for i in range(n - 1, -1, -1):
        dp1[i] = a[i] + best2
        dp2[i] = b[i] + best1
        best1 = max(best1, dp1[i])
        best2 = max(best2, dp2[i])

    return str(max(best1, best2))

# provided sample
assert run("5\n9 3 5 7 3\n5 8 1 4 5\n") == "29"

# minimum size
assert run("1\n10\n20\n") == "20"

# all equal
assert run("4\n5 5 5 5\n5 5 5 5\n") == "20"

# alternating dominance
assert run("3\n1 100 1\n1 1 100\n") == "201"

# increasing only top
assert run("3\n1 2 3\n3 2 1\n") == "6"

 ## 特殊なケース

 重要なエッジケースは、最適解が最初の行ではなく 2 行目から始まる場合です。 アルゴリズムは両方を計算するため、これを自然に処理します。$dp_1[i]$そして$dp_2[i]$対称であり、最後に全体的な最大値を取ります。 たとえば、行 2 の位置 0 に大きな値があり、行 1 が弱い場合でも、DP はそれをキャプチャします。$dp_2[0]$事前の選択を必要とせずに、回答に直接貢献できます。 

もう 1 つの微妙なケースは、高値の代替に到達するために多くのインデックスをスキップする必要がある場合です。 遷移は接尾辞 maxima にのみ依存するため、スキップは暗黙的に処理されます。`best1`そして`best2`将来のすべての位置にわたって達成可能な最良の継続を集約するため、DP は隣接関係を強制せず、まばらな最適シーケンスを正しく評価します。
