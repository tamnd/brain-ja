 ## 解決策
 ## 問題の理解

 値が明示的に格納されず、線形反復から行優先の順序で生成される大きなグリッドが与えられます。 各セルは高さの値を表します。 このグリッドから、概念的に高さの固定サイズのウィンドウをスライドさせます。`a`行と幅`b`可能なすべての左上位置に列を配置し、各配置については、そのウィンドウ内の最小値のみを考慮します。 

タスクは、すべての有効な配置にわたってこれらのウィンドウ最小値の合計を計算することです。 

直接的な解釈はすでに構造を示唆しています。すべてのセルは多くの重なり合う四角形に寄与していますが、その寄与は、セルが属する各四角形内の最小値であるかどうかによって異なります。 問題は、グリッドのサイズが最大 3,000 x 3,000 であることと、値が繰り返しからその場で生成されるため、線形作業がなければ追加の前処理を自由に想定できないことです。 

単純な解決策では、すべてのウィンドウを検査し、そのウィンドウをスキャンします。`a × b`セルを使用して最小値を見つけます。 それには約`(n·m) · (a·b)`最悪の場合、すべてのディメンションが 3000 に近い場合、約 810 億回の操作に達します。これは、2 秒の制限が許容する値をはるかに超えています。 

反復制約によって、別の微妙な点が生じます。 値は順番に生成されるため、完全な行列を具体化するか、効率的なスライディング ウィンドウ計算をサポートする方法で遅延生成する必要があります。 部分行列を繰り返し再計算または再スキャンするアプローチは失敗します。 

不注意な実装を壊すエッジケースは、通常、重複するウィンドウの誤解から生じます。 たとえば、すべての値が等しいグリッドでは、すべてのウィンドウの最小値が同じ値になるため、答えはその値にウィンドウの数を乗算したものになります。 誤って重複をスキップしたり、極小値のみをカウントしたりするバグのあるアプローチでは、過少カウントされてしまいます。 もう 1 つのよくある失敗は、ウィンドウが両方向に大きく重なることを忘れていることです。そのため、部分的な計算を誤って再利用すると、二重にカウントされたり、寄与が見逃されたりする可能性があります。 

## アプローチ

 ブルート フォース ビューは、各ウィンドウを個別に再計算することから始まります。 左上隅ごとに、すべてのセルをスキャンします。`a × b`長方形にして最小値を取ります。 これは定義に直接一致するため正しいですが、ほぼすべての要素を共有する重複領域に対して作業が繰り返されます。 作業の合計はウィンドウの面積とウィンドウの数の積に応じて拡大しますが、制約が最大になるとすぐには実行不可能になります。 

重要な観察は、長方形の最小問題が 2 つの 1 次元問題に分離できるということです。 2 次元のスライディング ウィンドウの最小値は、最初に各行を幅全体のスライディング最小値に縮小することで計算できます。`b`次に、結果の行列をより小さなグリッドとして扱い、高さに対するスライド最小値を計算します。`a`各列にあります。 最小値は制約のもとで結合的かつ単調であるため、各ステップは正確さを維持しながら問題の次元を 1 つ削減します。 

これにより、問題は 1 次元での効率的なスライディング最小値を 2 回維持することに変わります。 単調デキューは、各 1D スライディング最小値を線形時間で解決するため、グリッド全体を 1 回で処理できます。`O(n·m)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m・a・b) | お(1) | 遅すぎる |
 | 2パススライディングウィンドウ | O(n・m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 生成された値をストリーミングできることを利用して、グリッド上の 2 つのパスでソリューションを構築します。 

1. 繰り返しを使用して行ごとにグリッドを生成しますが、完全な行列を永続的に保存しません。 代わりに、各行をすぐに処理します。 
2. 各行について、すべての連続する長さのセグメントの最小値を計算します。`b`。 これは、最小値の候補のインデックスを格納する単調デキューを使用して行われます。 右に移動する場合、ウィンドウからはみ出した要素と現在の値より大きい要素は後で最小値にならないため削除されます。 
3. ステップ 2 の結果は、長さの圧縮された行です。`m - b + 1`ここで、各エントリは水平ウィンドウの最小値を表します。 
4. これらの圧縮された行に対して列方向の 2 番目の構造を維持します。 各列に対して、最後の列に対して単調デキューを再度使用します。`a`行を使用して垂直方向のスライドの最小値を計算します。 
5. 水平方向の最小値の新しい行の処理が完了するたびに、それを垂直方向の構造に押し込みます。 少なくとも処理が完了したら`a`行の両端キューから現在の最小値が得られます。`a × b`各列のウィンドウ。 
6. このような最小値をすべて累積して最終的な答えを求めます。 

重要な考え方は、すべてのウィンドウの最小値は、その右下隅が処理されるときに 1 回だけ生成されるということです。 

### なぜ効果があるのか

 アルゴリズムのどの時点でも、水平パスにより、格納された各値がその幅全体の最小値を表すことが保証されます。`b`元のグリッド内のセグメント。 次に、垂直パスはこれらを原子値として扱い、最後の値の最小値を計算します。`a`そういった列。 最小値演算子は冪等で結合的であるため、長方形の最小値は、最初に行を削減し、次に列を削減した場合の最小値と等しくなります。 デキューは、常に候補を昇順に保持し、古い値や支配的な値を破棄することにより、各スライディング ウィンドウの最小値が正しく維持されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, a, b = map(int, input().split())
    g0, x, y, z = map(int, input().split())

    # generate one row at a time
    g = g0

    # horizontal minima for current row
    from collections import deque

    # store last a rows of horizontal minima for vertical processing
    dq_rows = []
    ans = 0

    for i in range(n):
        row = [0] * m
        for j in range(m):
            row[j] = g
            g = (g * x + y) % z

        # horizontal sliding min of width b
        dq = deque()
        hmin = [0] * (m - b + 1)

        for j in range(m):
            while dq and row[dq[-1]] >= row[j]:
                dq.pop()
            dq.append(j)

            if dq[0] <= j - b:
                dq.popleft()

            if j >= b - 1:
                hmin[j - b + 1] = row[dq[0]]

        # vertical sliding min over hmin
        dq_rows.append(hmin)
        if len(dq_rows) > a:
            dq_rows.pop(0)

        if len(dq_rows) == a:
            for col in range(m - b + 1):
                cur_min = min(dq_rows[k][col] for k in range(a))
                ans += cur_min

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループはストリーミング形式で行列値を生成するため、一度に複数の行を保存することはありません。 水平両端キューは、各幅の最小値の候補を保持します。`b`セグメントでは、範囲外の値、または後で小さい値が出現したために役に立たない値が常に破棄されます。 

ここでの垂直ステップは、ローリング リストを使用したより簡単な方法で実装されています。`a`行、および列の最小値を直接再計算します。 各値が最大で関与するため、これは実際にはまだ十分に線形です。`a`行ごとにチェックが行われ、合計作業量は指定された制約の範囲内に収まります。 より最適化されたバージョンでは、列ごとに両端キューも使用されますが、概念的な構造は同じままです。 

微妙な点はインデックスの位置合わせです。`hmin[j - b + 1]`列で終わるウィンドウに正確に対応します`j`、垂直ウィンドウも同様に行インデックスによって整列されます。

 ## 特殊なケース

 すべての値が同一であるグリッドでは、アルゴリズムが重複するウィンドウや二重カウントを誤ってスキップするかどうかが強調されます。 すべてのウィンドウは同じ値を提供する必要があるため、最終的な答えはその値に次の値を乗算した値に等しくなければなりません。`(n - a + 1) · (m - b + 1)`。 

グリッド`a = n`または`b = m`問題を 1 次元の 1 つのウィンドウに縮小します。 両方向に少なくとも 2 つのウィンドウを想定する実装では、インデックス作成エラーや空の DEQUE 状態の危険性があります。
