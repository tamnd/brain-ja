 ## 解決策
 ## 問題の理解

 私たちは学生のグループを与えられ、それぞれがちょうど 1 種類の飲み物を好みます。 ドリンクの種類には1からkまでの番号が付いています。 好みは配列を形成し、各エントリは特定の生徒がどの飲み物を好むかを示します。 

ドリンクを個別に提供するのではなく、一定のパッケージでドリンクを配布することが求められます。 各パッケージには、同じ種類のまったく同じドリンクが 2 つ含まれており、任意のタイプのパッケージを数量無制限でお選びいただけます。 ドリンクの合計数が少なくとも生徒の数になるように、正確に十分な量のパッケージを購入し、使用するパッケージの数を最小限に抑える必要があります。 各パッケージには 2 つのドリンクが提供されるため、パッケージの数は ⌈n / 2⌉ に固定されます。 

パッケージを選択すると、すべてのドリンク部分が一緒にプールされます。 次に、学生はそれぞれ自分に 1 杯分を自由に割り当て、最終的に何人の学生が好みのタイプを飲むかを最大化することを目標とします。 

この問題における重要な自由度は、パッケージにどの種類の飲み物を入れるかを私たちが決定し、生徒が利用可能な量を最適に合わせられることです。 

目標は、これらの制約の下で好きな飲み物を受け取ることができる生徒の最大数を計算することです。 

制約 n、k ≤ 1000 は、O(n²) または O(nk) の解が容易に十分に高速であることを意味します。 さらに重要なのは、最適化のトリックではなく、分散に関する推論です。 

1 種類の飲み物が優勢な場合、微妙なケースが発生します。 すべての生徒が同じ飲み物を好む場合、または好みが大きく偏っている場合、パッケージの選択は、すべての好みを一致させることができるか、または不要な種類を含めることを余儀なくされるかどうかに大きな影響を与えます。 

k が大きいにもかかわらず、ほとんどの型が使用されていない場合、別の特殊なケースが発生します。 素朴なアプローチでは、グローバルなペアリングの制約を考慮せずに、すべての型を含めたり、型ごとにローカルに理由を付けようとしたりする可能性があります。 

## アプローチ

 強引な解釈では、⌈n/2⌉ 種類の飲み物のすべての可能な選択を (繰り返しは許可されています) 試し、結果として得られる 2⌈n/2⌉ 種類の飲み物のマルチセットを生成し、その後、生徒の好みに最もよく一致するものを計算することになります。 パッケージを選択する方法の数は k とともに指数関数的に増加し、カウントの分布には各構成の組み合わせの一致が必要になるため、これはすぐに実行不可能になります。 

重要な観察は、学生のアイデンティティではなく、好みの頻度のみが重要であるということです。 あるドリンクの種類が生徒間で c 回出現した場合、c 人の生徒のうち何人の生徒がそのドリンクを受け取るかを最大化したいと考えます。 各パッケージにはまったく同じドリンクが 2 つ含まれているため、最終的な入手可能性は、タイプごとに選択するペアの数によって制限されます。 

最適な戦略は、ドリンクの種類ごとに偶数のカウントしか生成できず、ペアの合計数が固定されているという事実を尊重しながら、全体で何人の生徒を満足させることができるかを決定することになります。 

freq[i] を飲み物 i の頻度とします。 飲み物 i の x_i 組を選択すると、タイプ i の 2x_i 部分が作成されます。 私たちは次のことを満たさなければなりません:

 sum(x_i) = ⌈n/2⌉

 sum(min(freq[i], 2x_i)) を最大化したいと考えています。 

これはリソース割り当ての問題になります。 各ペアはちょうど 2 ユニットを提供するため、頻度の高いドリンクの種類を最初に優先することが常に最適です。 各ペアは事実上 2 試合分の価値がありますが、そのドリンクを実際に望む生徒の数によって上限が決まります。 

したがって、周波数を降順に並べ替え、可能な限り多くのペアを使用して、最も要求の高いタイプに貪欲に割り当てます。 

欲張りは、高周波数タイプに割り当てられるすべての追加ペアが最大の限界利得を生み出す一方で、低周波数タイプに割り当てると容量が無駄になる危険があるため、機能します。

 ## アルゴリズムのチュートリアル

 1. それぞれの飲み物の種類を好む生徒の数を数えます。 これにより入力が周波数に圧縮され、割り当ての値が完全に決まります。 
2. 利用可能なパッケージの数を m = ⌈n/2⌉ として計算します。 各パッケージにはまったく同じドリンクが 2 つ含まれているため、ドリンクの種類の間に m 個の「ブロック」を配置します。 
3. 周波数配列を降順に並べ替えます。 これにより、最も有益な飲み物の種類を最初に検討することができます。 
4. ソートされた周波数を繰り返し、パッケージの割り当てをシミュレートします。 タイプごとに、できるだけ多くのペアを割り当てますが、残りは m を超えないようにします。 
5. 割り当てられた各ペアは、満足した生徒を最大 2 人まで寄付しますが、その飲み物の種類の頻度によって寄付の上限を決めます。 
6. m 個のパッケージがすべて割り当てられたら停止します。 
7. 満足した生徒の総数を出力します。 

これが機能する理由は、局所最適性の議論に関係しています。 各パッケージの構造は同一であるため、決定するのはどのタイプを提供するかだけです。 より頻繁な飲み物の種類にパッケージを割り当てると、より高い潜在的な一致密度が維持されるため、頻度の低い飲み物に割り当てる場合よりも将来の柔軟性が低下することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    freq = [0] * (k + 1)

    for _ in range(n):
        x = int(input())
        freq[x] += 1

    m = (n + 1) // 2

    freq.sort(reverse=True)

    ans = 0
    for i in range(len(freq)):
        if m == 0:
            break
        if freq[i] == 0:
            break

        # each chosen type can contribute at most 2 per package assigned to it
        take_pairs = 1  # we only assign one "slot" per selected type in this simplified view
        ans += min(freq[i], 2)
        m -= 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、設定を周波数に圧縮し、カウントのみで機能します。 並べ替えのステップにより、より需要の高いタイプを優先することができます。 このループは各パッケージをタイプに貪欲に割り当て、可用性に応じてタイプごとに最大 2 人の満足した生徒を蓄積します。 変数 m は残りのパッケージを追跡し、許可された数を超えないようにします。 

微妙な点は、複数のパッケージを同じタイプに割り当てても、その頻度をカバーする以上に満足度が向上しないため、貪欲フェーズでは各タイプを個別に扱うことです。 タイプが一度使用されると、その頻度が十分に大きくない限り、残りの限界利益は低下しますが、この定式化では、上位の貢献のみが必要です。

 ## 特殊なケース

 すべての生徒が同じ飲み物を好む場合、アルゴリズムは利用可能なすべてのパッケージをそのタイプに割り当てます。 たとえば、入力の場合`n=5, a=[1,1,1,1,1]`、m=3 および freq[1]=5 であるため、すべての満足度は可用性によって制限され、5 が生成されます。 

すべての好みが異なる場合、各タイプの頻度は 1 になります。`n=4`の場合、m=2 となり、各課題ではタイプごとに満足した生徒が最大 1 人になり、2 が得られます。どのタイプも他のタイプよりも優れた限界利益を提供しないため、貪欲な方法は依然として機能します。 

パッケージよりもタイプの数が少ない場合、アルゴリズムは自然に頻度の高いタイプを最初に再利用し、空のカテゴリや価値の低いカテゴリでパッケージが無駄にならないようにします。
