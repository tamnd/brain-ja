 ## 解決策

 ## 問題の理解

 固定された順序で配置された一連の整数が与えられます。 オプションで、このシーケンスから 1 つの要素を削除することも、変更しないままにすることもできます。 この操作の後、結果のシーケンスのすべての連続セグメントを調べ、値が厳密に左から右に増加するセグメントのみに焦点を当てます。 このようなすべてのセグメントの中で、可能な限り最大の長さが必要です。 

より簡単に言うと、私たちは単一の「ほぼ増加の実行」をできるだけ長くしようとしています。トレンドを壊す要素を 1 つ削除することで、局所的な混乱を 1 つだけ修正することができます。 

までの制約$2 \cdot 10^5$要素は、すべての位置で削除をシミュレートし、最長の増加セグメントを最初から再計算しようとするソリューションを直ちに除外します。 削除するたびにスキャンを再計算する二次アプローチでは、約$n^2$これは 2 秒の制限をはるかに超えています。 直線的または直線に近いアプローチが必要です。 

いくつかのエッジケースは、素朴な思考が失敗する理由を明らかにします。 

たとえば、配列がすでに厳密に増加している場合は、次のようになります。```
5
1 2 3 4 5
```何も削除してもメリットがないので、答えは 5 です。 常に 1 つの要素を削除する単純な戦略では、誤って答えが 4 に減ってしまいます。 

配列が厳密に減少している場合:```
5
5 4 3 2 1
```単一の欠失では、局所的な増加連鎖が形成できないため、最も長い増加セグメントはせいぜい長さ 2 のままになります。 複数の破損を「修正」しようとする単純な試みは、1 つの削除による利益を誤って過大評価する可能性があります。 

より微妙なケース:```
5
1 3 2 3 4
```中央の 2 を削除すると、増加する 2 つのランがより長いランにマージされます。 正しい解決策は、削除の利点が、すでに増加している 2 つのセグメントをブリッジすることによってのみ得られることを検出する必要があります。 

## アプローチ

 ブルートフォースの方法は簡単です。 インデックスごとに、その要素の削除をシミュレートし、配列全体をスキャンして、厳密に増加する最長の連続部分配列を計算します。 このスキャンは線形であるため、すべてのインデックスに対して実行すると、$O(n^2)$時間。 と$n = 2 \cdot 10^5$、これには約が必要になります$4 \cdot 10^{10}$実行不可能な操作。 

重要な観察は、増加するセグメントの構造がすでに欠失がなく非常に規則的であるということです。 位置ごとに、増加するランが左右にどれだけ伸びるかを事前に計算できます。 これが分かると、1 つの要素を削除する唯一の意味のある効果は、左の増加するランの末尾を接続する可能性があることになります。$i-1$から始まる右の増加実行$i+1$、境界条件が与えられた場合$a[i-1] < a[i+1]$が成立する。 

これにより、問題はローカル ランレングスの追跡と、インデックスごとに最大 1 つのマージ ポイントのチェックに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 単調構造を記述する 2 つの配列を計算します。 

1. 配列を計算する`left[i]`インデックスで終わる厳密に増加する連続したサブ配列の長さを格納します$i$。 

これは、左から右にスキャンして構築されます。 もし$a[i] > a[i-1]$、前回の実行を延長します。 それ以外の場合は 1 にリセットされます。 
2. 配列を計算する`right[i]`インデックスから開始して厳密に増加する連続する部分配列の長さを格納します$i$。 

これは、同じロジックを使用して右から左にスキャンすることによって構築されます。 
3. 答えを次の最大値として初期化します。`left[i]`。 

これは、要素を削除しない場合を表します。 
4. ポジションごとに$i$、削除を検討してください$a[i]$。 

削除により、で終わる増加セグメントが接続される可能性があります。$i-1$で始まるものと$i+1$。 
5. マージは次の場合にのみ有効です。$a[i-1] < a[i+1]$。 

これが当てはまる場合、マージされたセグメントの長さは次のようになります。`left[i-1] + right[i+1]`。 
6. すべての削除にわたる最大値で回答を更新します。 

### なぜ効果があるのか

 1 回の削除後の最終配列内の厳密に増加する連続セグメントは、2 つのカテゴリのいずれかに分類される必要があります。 削除された要素を通過しません。つまり、元の配列にすでに存在しており、次の方法でキャプチャされます。`left[i]`または、削除された位置と交差します。これは、削除されたインデックスで正確に分離された 2 つの元の増加ランを連結することによって形成されることを意味します。 厳密に増加するセグメントには内部減少を含めることはできないため、他の構造的可能性はありません。そのため、削除によって修復できる「ブレーク ポイント」は最大 1 つです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

left = [1] * n
right = [1] * n

for i in range(1, n):
    if a[i] > a[i - 1]:
        left[i] = left[i - 1] + 1
    else:
        left[i] = 1

for i in range(n - 2, -1, -1):
    if a[i] < a[i + 1]:
        right[i] = right[i + 1] + 1
    else:
        right[i] = 1

ans = max(left)

for i in range(n):
    if i == 0:
        ans = max(ans, right[1])
    elif i == n - 1:
        ans = max(ans, left[n - 2])
    else:
        if a[i - 1] < a[i + 1]:
            ans = max(ans, left[i - 1] + right[i + 1])
        else:
            ans = max(ans, left[i - 1], right[i + 1])

print(ans)
```の`left`配列は、各位置で終了する増加セグメントを変更せずにどこまで拡張できるかをキャプチャします。 の`right`配列は右側から対称的なジョブを実行します。 

ループオーバー`i`境界位置を慎重に処理します。 最初または最後の要素を削除すると、片側だけが残るため、達成可能な最良のセグメントは、対応する事前計算された実行そのものになります。 

内部ポジションの場合、両者が融合できるかどうかが重要なチェックポイントとなります。 条件`a[i - 1] < a[i + 1]`確実に削除します`a[i]`結合点での厳密な増加に違反しません。 失敗すると、2 つのセグメントを接続できなくなり、最適な独立した実行にフォールバックする必要があります。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    left = [1] * n
    right = [1] * n

    for i in range(1, n):
        if a[i] > a[i - 1]:
            left[i] = left[i - 1] + 1
        else:
            left[i] = 1

    for i in range(n - 2, -1, -1):
        if a[i] < a[i + 1]:
            right[i] = right[i + 1] + 1
        else:
            right[i] = 1

    ans = max(left)

    for i in range(n):
        if i == 0:
            ans = max(ans, right[1])
        elif i == n - 1:
            ans = max(ans, left[n - 2])
        else:
            if a[i - 1] < a[i + 1]:
                ans = max(ans, left[i - 1] + right[i + 1])
            else:
                ans = max(ans, left[i - 1], right[i + 1])

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided sample
assert run("5\n1 2 5 3 4\n") == "4"

# minimum size
assert run("2\n1 2\n") == "2"

# already increasing
assert run("5\n1 2 3 4 5\n") == "5"

# all equal
assert run("4\n7 7 7 7\n") == "1"

# valley fix
assert run("6\n1 2 3 2 3 4\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 1 2 | 2 | 最小限の場合、削除は必要ありません。 
| 1 2 3 4 5 | 5 | 削除しなくてもすでに最適です |
 | 7 7 7 7 | 1 | 厳格な増加要件 |
 | 1 2 3 2 3 4 | 5 | 単一の欠失により 2 つの実行がブリッジされます。 

## 特殊なケース

 重要なエッジケースは、エンドポイントを削除する場合です。 最初の要素が削除された場合、最良の結果は単にインデックス 1 から始まる最も長く増加するプレフィックスになります。アルゴリズムはこれを次のように直接処理します。`right[1]`。 例えば：```
5
5 1 2 3 4
```5 を削除すると答え 4 が得られ、`right[1]`これを正しく捉えています。 

もう 1 つのケースは、マージを行わないことが有益な場合です。 例えば：```
5
5 4 3 2 1
```毎`left[i]`そして`right[i]`は 1 であり、有効なマージ条件は成立しません。 要素を削除しても 1 を超える増加セグメントは残らないため、アルゴリズムは自然に 1 に戻り、これが正解と一致します。 

最後の微妙なケースは、潜在的なマージ ポイントが複数存在するにもかかわらず、削除が 1 つだけ許可される場合です。 のために：```
6
1 2 10 3 4 5
```10 を削除するだけで完全なマージが行われます。 このアルゴリズムは各インデックスを個別に正しく評価し、最適な単一の改善を選択するため、削除が二重にカウントされることはありません。
