 ## 解決策

 ## 問題の理解

 長さのある 1 次元のボードが与えられます$n$, ここで、各セルは$i$値が含まれています$a_i$。 位置から$i$、最大で 2 つの他の位置に決定論的にジャンプできます。$i - a_i$そして$i + a_i$それらの位置が配列の境界内にある限り。 各ジャンプにはちょうど 1 回の移動が必要です。 

すべての開始位置について$i$、任意の位置に到達するために必要なジャンプ回数を最小限にしたいと考えています。$j$の値が$j$～と比べて逆のパリティがある$a_i$。 もし$a_i$が奇数の場合は、偶数の値の位置に到達する必要があり、その逆も同様です。 そのような到達可能な位置が存在しない場合は、次のように出力します。$-1$。 

これは、次のような暗黙的なグラフ上の最短経路問題です。$n$各ノードには最大 2 つの有向エッジがあります。 ここでの注意点は、ターゲット条件がノードの固定セットではなく、開始ノードのパリティに依存することです。 

制約$n \le 2 \cdot 10^5$に近い解決策があることを意味します。$O(n^2)$通りません。 すべてのノードからの線形 BFS でも大きすぎます。 ノード間で作業を再利用するグローバル構造が必要です。 

素朴な考え方では、微妙な問題が発生します。つまり、すべてのノードから独立して BFS を実行しようとする可能性があります。 もう 1 つの誘惑は、有効なパリティに達するまで、各ノードからの考え方と BFS を逆にすることです。 どちらのアプローチも同じエッジを繰り返し通過するため、壊滅的な冗長性が生じます。 

もう 1 つの明白ではない落とし穴は、貪欲なジャンプやローカル パリティの変更が重要であると想定することです。 パリティ制約は宛先にのみ適用され、中間ノードには適用されないため、ローカル パリティ発振は無関係です。 この構造は、重み付けされていないグラフ上の純粋な最短パスです。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 各インデックスに対して$i$、反対のパリティを持つノードに到達するまで、グラフに対して BFS を実行します。 各ノードには最大 2 つの発信エッジがあるため、BFS は最悪の場合でもノード数が線形になります。 すべての開始ノードに対してこれを行うと、$O(n^2)$時間の複雑さは限界をはるかに超えています。$n = 2 \cdot 10^5$。 

重要な点は、実際にはすべてのノードからの最短パスを個別に計算する必要がないということです。 Instead, we reverse the perspective. 各ノードから反対パリティの最も近いノードまでの距離が必要です。 これは、ターゲット パリティのすべてのノードが同時にソースとして機能するグラフ内の最短距離を計算することに相当します。 

This suggests a multi-source BFS. パリティに基づいてノードを 2 つのグループに分割します。$a_i$。 奇数の値を持つノードの応答が必要だとします。そのターゲットは偶数ノードです。 すべての偶数ノードから同時に BFS を実行すると、1 回の走査ですべてのノードから最も近い偶数ノードまでの最短距離が計算されます。 同じプロセスが奇数ノードに対して対称的に繰り返されます。 

これを効率的に行うために、グラフ内のすべてのエッジを反転します。 そこから歩く代わりに、$i$に$i \pm a_i$、各ノードが存在する隣接リストを構築します。$v$すべてのノードを保存します$u$そのような$u \pm a_u = v$。 次に、1 つのパリティのすべてのノードからの BFS は、距離を逆方向に外側に広げ、任意のソースへの最も近い距離を効果的に計算します。 

これにより、問題はグラフ上で 2 つの BFS 実行に変換されます。$O(n)$エッジ。

 | --- | --- | --- | --- |
 | ノードごとのブルート フォース BFS |$O(n^2)$|$O(n)$| 遅すぎる |
 | 反転グラフ上のマルチソース BFS |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置について反転したグラフを作成します。$i$からエッジを追加します。$i + a_i$に$i$そしてから$i - a_i$に$i$、これらのインデックスが有効な場合はいつでも。 この逆転により、BFS は「誰に連絡できるか」の情報を効率的に伝達することが保証されます。 
2. パリティに基づいてノードを 2 つのセットに分割します。$a_i$なぜなら、各ノードの答えは反対側のパリティ セットに到達するかどうかに依存するからです。 
3. 2 つの距離配列を初期化します。1 つは最も近い偶数値のノードまでの距離用、もう 1 つは最も近い奇数値のノードまでの距離用です。 
4. 反転グラフ上のすべての偶数ノードから同時に開始して BFS を実行し、「偶数までの距離」配列を埋めます。 各ステップは逆エッジで外側に伝播するため、偶数ノードへの最短パスを計算します。 
5. すべての奇数値ノードから開始して 2 番目の BFS を実行し、同様に「奇数までの距離」配列を埋めます。 
6. 各インデックスについて$i$、 もし$a_i$奇数の場合、偶数ノードまでの出力距離。 もし$a_i$が偶数の場合、奇数ノードまでの出力距離。 対応する距離がまだ無限である場合、出力$-1$。 

### なぜ効果があるのか

 各 BFS は、一連のソースから重み付けされていないグラフ内の最短パスを計算します。 エッジを反転すると、反転したグラフの「i から最も近いターゲットまでの距離」が「ターゲットから i までの距離」に変換されます。 BFS は重み付けされていないグラフでの最短パス距離を保証するため、反転 BFS で最初にノードに到達するときは、反対のパリティのノードに到達するために必要な前方ジャンプの最小数に正確に対応します。 

ソースはすべて 1 つのパリティのノードであるため、冗長な再計算を回避し、すべてのノードが BFS ごとに最大 1 回処理されるようにします。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

rev = [[] for _ in range(n)]

for i in range(n):
    if i - a[i] >= 0:
        rev[i - a[i]].append(i)
    if i + a[i] < n:
        rev[i + a[i]].append(i)

even = [i for i in range(n) if a[i] % 2 == 0]
odd = [i for i in range(n) if a[i] % 2 == 1]

INF = 10**18

def bfs(starts):
    dist = [INF] * n
    q = deque()
    for s in starts:
        dist[s] = 0
        q.append(s)

    while q:
        v = q.popleft()
        for u in rev[v]:
            if dist[u] == INF:
                dist[u] = dist[v] + 1
                q.append(u)
    return dist

dist_even = bfs(even)
dist_odd = bfs(odd)

res = []
for i in range(n):
    if a[i] % 2 == 0:
        res.append(str(dist_odd[i] if dist_odd[i] < INF else -1))
    else:
        res.append(str(dist_even[i] if dist_even[i] < INF else -1))

print(" ".join(res))
```このコードは、BFS が目的のパリティのノードに到達するための最小ステップを自然に蓄積するように、反転グラフを構築します。 2 つの BFS 呼び出しはコア最適化であり、ノードごとの検索を置き換えます。 

実装の微妙な点は、個々のノードから BFS を実行しないことです。 代わりに、指定されたパリティのすべてのノードをキューに一度にシードします。 もう 1 つの重要な点は、反転グラフを慎重に作成する必要があるということです。 どちらの方向にも欠けている$i \pm a_i$到達可能性が損なわれる可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [2, 3, 1, 4, 2]
```逆エッジを構築します。 

| v | 受信ノードを反転 |
 | --- | --- |
 | 0 | 2から |
 | 1 | 4から |
 | 2 | 0、3から |
 | 3 | 1から |
 | 4 | 2から |

 偶数インデックス: 0、3

 奇数のインデックス: 1、2、4

 私たちは計算します`dist_even`0 と 3 から始まる BFS による、および`dist_odd`1、2、4から。 

ノード 1 (奇数) については、次のようになります。`dist_even[1]`これは、1 → 4 → 2 → 0 を経由するか、逆接続に応じて直接 1 になります。 

これにより、マルチソース BFS が複数のターゲットからのパスを正しくマージしていることが確認されます。 

### 例 2

 入力:```
n = 4
a = [1, 1, 1, 1]
```すべての動きは対称的です。 

| ノード | パリティ | 隣人 |
 | --- | --- | --- |
 | 0 | 奇数 | 1 |
 | 1 | 奇数 | 0、2 |
 | 2 | 奇数 | 1、3 |
 | 3 | 奇数 | 2 |

 ノードセットも空なので、`dist_even`すべてINFです。 すべての奇数ノードは -1 を出力します。 これは、到達可能な偶数ノードが存在しないという事実と一致します。 

この例では、到達不能なターゲットの処理を検証します。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))

    rev = [[] for _ in range(n)]
    for i in range(n):
        if i - a[i] >= 0:
            rev[i - a[i]].append(i)
        if i + a[i] < n:
            rev[i + a[i]].append(i)

    even = [i for i in range(n) if a[i] % 2 == 0]
    odd = [i for i in range(n) if a[i] % 2 == 1]

    INF = 10**18

    def bfs(starts):
        dist = [INF] * n
        q = deque()
        for s in starts:
            dist[s] = 0
            q.append(s)
        while q:
            v = q.popleft()
            for u in rev[v]:
                if dist[u] == INF:
                    dist[u] = dist[v] + 1
                    q.append(u)
        return dist

    dist_even = bfs(even)
    dist_odd = bfs(odd)

    res = []
    for i in range(n):
        if a[i] % 2 == 0:
            res.append(str(dist_odd[i] if dist_odd[i] < INF else -1))
        else:
            res.append(str(dist_even[i] if dist_even[i] < INF else -1))

    return " ".join(res)

 ## 特殊なケース

 主なエッジ ケースは、1 つのパリティ グループが空の場合です。 すべての値が偶数の場合、ターゲットがないため、どのノードも奇数の値のノードに到達することはできません。 BFS 開始セットは空になり、すべての距離は無限のままになります。 アルゴリズムは正しく出力します$-1$あらゆるポジションに。 

もう 1 つのケースは、ノードが反対側のパリティ ノードに直接ジャンプする場合です。 反転したグラフでは、そのノードはソース ノードから直接入ってくるエッジとして表示されるため、BFS はすぐに距離 1 を割り当てます。 これにより、逆伝播モデルが正しいことが確認されます。 

最後に、次のような境界ジャンプ$i + a_i = n$または$i - a_i = 0$グラフ構築時に明示的に処理されます。 省略すると、有効な最短パスが暗黙的に削除されるため、慎重なインデックス チェックが不可欠です。
