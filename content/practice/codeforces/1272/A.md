 ## 解決策

 ## 問題の理解

 3 人の友人が数直線上の位置に座ります$a$、$b$、 そして$c$。 1 回の移動で、各フレンドは最大 1 ユニット左、1 ユニット右に移動するか、その場に留まることができます。 ちょうど 1 回の同時移動の後、それらがどの程度広がっているかを確認し、その広がりを最終位置間のペアごとの距離の合計として測定します。 

課題は、このペアごとの距離の合計ができるだけ小さくなるように、3 人全員の手を選択することです。 

入力に関する重要な観察は、各テスト ケースが独立しており、3 つの整数のみで構成されているため、各ケースを定数時間で解決できることです。 最大 1000 のテスト ケースを使用して、それを超えるソリューションを実現$O(q)$または$O(q \log q)$不要ですが、それでも$O(q)$重い定数を使用しても問題ありません。 

重要な実際の制約はサイズではなく構造です。 ポイントが 3 つだけで、それぞれの移動単位が 1 つだけであるため、システムが到達可能な構成は非常に限られています。 これにより、原理的にはすべての動きの組み合わせに対する総当たり攻撃が可能になりますが、それでも目標の形状を認識する必要があります。 

すべての位置が等しい場合、微妙なエッジケースが発生します。たとえば、$a=b=c=5$。 その場合、それらを一緒に保つ移動はコストがゼロになり、個別の順序付けを前提としたり、エンドポイントのシフトのみを計算したりする単純なアプローチは、マージがすでに最適であることを忘れてしまうと失敗する可能性があります。 

もう 1 つのエッジ ケースは、2 つの点が一致し、3 番目の点が遠く離れている場合です。$1, 1000000000, 1000000000$。 素朴な「貪欲にお互いに近づく」アプローチでは、1 人あたり 1 つのユニットのみが許可されることを慎重に処理する必要があります。 大きなギャップを完全に潰すことはできません。 

## アプローチ

 直接的なアプローチは、各友人の動きについてあらゆる可能性を試すことです。 各友達には、左に移動する、留まる、または右に移動するという 3 つの選択肢があります。 それは与える$3^3 = 27$テストケースごとに可能な最終構成。 各構成について、ペアごとの距離の合計を計算し、最小値を取得します。 これでもすでに十分速いので、$27 \cdot 1000$無視できるほどです。 

これが機能するのは、状態空間が非常に小さいためです。 コスト関数も定数時間で簡単に評価できます。 

ただし、対物レンズの構造により、より鮮明な視界が可能になります。 3 点間のペアごとの距離の合計は、それらの並べ替え順序にのみ依存します。 最終的な位置を次のように並べ替えると、$x \le y \le z$の場合、式は次のようになります。$$|x-y| + |x-z| + |y-z| = (z-x) + (z-y) + (y-x) = 2(z-x)$$したがって、ペアごとの合計距離を最小化することは、最小最終位置と最大最終位置の間のスパンを最小化することと同じです。 

これにより、問題は、各ポイントが最大 1 移動した後に最小値と最大値をどの程度緊密にパックできるかを制御することになります。直観的には、最小のポイントを上に引き上げ、最大のポイントを下に引き上げたいと考えますが、中間のポイントは、その間に役立つように、または中間に留まるように調整できます。 

各移動の唯一の意味のある効果は、ポイントが中心に向かって移動するか、中心から遠ざかるかどうかです。 各ポイントは最大 1 だけ移動できるため、範囲を縮小することで最終的な最適な構成が達成されます。$[\min, \max]$できるだけ。 

したがって、最適な戦略は次と同等です。 

最小値を 1 ずつ上に移動し、最大値を 1 ずつ下に移動して、中央を柔軟なままにし、一貫したすべての選択肢に対して結果の範囲を再計算します。 これは、一定数のケースをチェックすること、またはより直接的には、答えが初期範囲を縮小できるかどうかのみに依存することを観察することになります。 

各エンドポイントは最大 1 だけ内側に移動できるため、考えられる最適な新しい範囲は次のとおりです。$$\max(0, (max - min) - 2)$$ペアごとの合計距離はこの範囲の 2 倍になります。 

これにより、直接$O(1)$テストケースごとの式。

 ## アルゴリズムのチュートリアル

 範囲圧縮に基づいた最適化された推論に焦点を当てます。 

1. 各テスト ケースについて、3 つの位置を読み取ります。$a, b, c$。 それらを線上の小さな点のセットとして扱います。 
2. 3 つの値の最小値と最大値を計算します。 中間値はソート後の極端な距離に影響を与えないため、システムの広がりはこれら 2 つの値によって完全に決定されます。 
3. 初期範囲を計算します$d = \max(a,b,c) - \min(a,b,c)$。 これは現在のスプレッドの合計を表します。 
4. 動きが極端な場合にどのような影響を与えるかを観察します。 最小のポイントは最大 1 増加でき、最大のポイントは最大 1 減少できるため、範囲は最大 2 だけ縮小できます。 
5. 交換する$d$と$\max(0, d - 2)$。 これにより、1 回の移動後に可能な限り最高の圧縮が得られます。 
6. 出力$2 \cdot \max(0, d - 2)$3 点間のペアごとの距離の合計は、ソート後の範囲の 2 倍に等しいためです。 

### なぜ効果があるのか

 任意の 3 つの点について、それらを並べ替えると、目的は常に最小点と最大点の間の距離の 2 倍に等しいことがわかります。 中間点は対称的に寄与し、合計では相殺されます。 

各エンドポイントは最大 1 ユニットだけ内側に移動できるため、スパンに対する可能な限りの改善は合計でちょうど 2 ユニットになります。 中点を再配置しても、極値を圧縮することですでに達成されているものを超えて改善することはできません。それは、すでに極値の外側にあるか、一致しない限り、極値になることはできないからです。 

これにより、問題は間隔のエンドポイントがどの程度縮小できるかによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        a, b, c = map(int, input().split())
        mn = min(a, b, c)
        mx = max(a, b, c)
        d = mx - mn
        ans = max(0, d - 2) * 2
        print(ans)

if __name__ == "__main__":
    solve()
```コードはテスト ケースごとの最小値と最大値のみを計算し、順列や中間値を考慮する必要を回避します。 2 による減算は、両方の極が一度内側に移動できるという事実を直接モデル化します。 

よくある実装上の落とし穴は、最後の 2 の乗算を忘れることです。 最小化される量は範囲そのものではなく、ペアごとの距離の合計であり、これは常に 3 つの並べ替えられた点の範囲の 2 倍になります。 

もう 1 つの微妙な問題は、狭い範囲を正しく処理することです。 いつ$d \le 2$、移動後にすべてのポイントを 1 つの場所にマージできるため、答えはゼロになる必要があります。 の`max(0, d - 2)`これを強制します。 

## 実用的な例

 場合を考えてみましょう$10, 20, 30$。 

| ステップ | 分 | 最大 | 範囲 d | 調整範囲 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 10 | 30 | 20 | - | - |
 | 圧縮後 | - | - | - | 18 | 36 |

 ここでは、両方の極端な値が最適に内側に移動し、広がりが 20 から 18 に減少します。最終的な答えは次のとおりです。$2 \cdot 18 = 36$、出力と一致します。 

ここで考えてみましょう$3, 3, 4$。 

| ステップ | 分 | 最大 | 範囲 d | 調整範囲 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 3 | 4 | 1 | - | - |
 | 圧縮後 | - | - | - | 0 | 0 |

 最大点が左に移動して他の点と一致する可能性があるため、最も近い 2 つの点は 1 回の移動後にすでに完全に折りたたむことができます。 

これらの例は、変換が内部の配置ではなく、最も外側の点にのみ依存することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        a, b, c = map(int, input().split())
        mn = min(a, b, c)
        mx = max(a, b, c)
        d = mx - mn
        out.append(str(max(0, d - 2) * 2))
    return "\n".join(out)

 ## 特殊なケース

 のために$a=b=c$、アルゴリズムは次のように計算します。$d=0$、次にゼロにクランプされ、正しいゼロ出力が生成されます。 すべての動きは距離を増やすことしかできないため、一緒にいることに勝る構成はありません。 

次のようなほぼ等しいトリプルの場合$1,2,3$、範囲は 2 です。2 を減算するとゼロになります。これは、エンドポイントを内側に移動することで完全な折りたたみが可能であることを意味します。 アルゴリズムは、クランプ ステップを通じてこれを直接取得します。 

極端な分離の場合は、$1, 1000000000, 999999999$、範囲は広いですが、それでも 2 だけ減少します。アルゴリズムは、エンドポイントごとに 1 単位の移動しか利用できないという事実を正しく考慮しているため、最終的な減少は厳密に制限されます。
