 ## 解決策
 ## 問題の理解

 私たちは、単語の内部の文字が並べ替えられた可能性のある文を与えられます。 すべての単語について、最初と最後の文字は固定されたままであり、その間の文字の並べ替えは許可されていました。 壊れた文と一緒に、元の文に現れた可能性のあるすべての単語を含む辞書も受け取ります。 

破損した文内の単語ごとに、その内部の文字のみを並べ替えることでその単語になる可能性のある辞書の単語を見つける必要があります。 辞書の単語は、最初の文字、最後の文字が同じで、各文字の出現回数が同じ場合に正確に互換性があります。 すべての文単語に対して少なくとも 1 つの互換性のある辞書単語が存在する場合、そのような再構成を出力できます。 一文でも辞書に対応する単語がない場合、答えは次のようになります。`No solution`。 

文の合計文字数は最大 (5\cdot10^5) であり、辞書の合計文字数も最大 (5\cdot10^5) です。 辞書エントリの数は (5\cdot10^5) に達します。 これらの境界により、文内のすべての単語に対して辞書のフル スキャンを実行することが除外されます。 文には数十万の単語が含まれる可能性があるため、(W) が文の単語数である (O(Wn)) 検索では、個々の境界 (W\le250000) および (n\le500000) の下でおよそ (1.25\cdot10^{11}) 個の候補チェックに到達できます。 代わりに、入力の総量に比例した処理が必要です。 

不注意な実装によって誤って処理される可能性のある境界ケースがいくつかあります。 1 文字の単語には内部文字がないため、まったく同じ 1 文字を持つ辞書の単語のみと一致します。 たとえば、入力の場合```
a.
1
a
```答えは`a.`。 1 文字の場合を処理せずに最初と最後の文字を 2 つの別個の位置として扱うと、空の中央に誤ってインデックスが付けられる可能性があります。 

異なる辞書の単語がまったく同じ署名を持つことがあります。 例えば、```
tihs.
2
this
hits
```だけを持っています`this`有効な答えとして、`hits`最初と最後の文字が異なります。 一方で、```
scret.
2
secret
serect
```観察された単語の長さと文字数が同じであれば、互換性のある単語のいずれかを許可します。 この問題では有効な答えを明示的に許可しているため、署名ごとに 1 つの単語のみを保存するだけで十分です。 

単語の長さが正しい場合でも、内部の 1 つの文字の多重度が間違っているために再構築できない場合もあります。 例えば、```
wlrd.
1
world
```解決策がありません。 観察された単語には 4 文字しか含まれていませんが、辞書の単語には 5 文字が含まれているため、最初と最後の文字だけを比較すると、誤ってその単語が受け入れられてしまいます。 

最後に、ピリオドは単語ではなく文の構文に属します。 のために```
hello wolrd.
2
hello
world
```2番目の単語は`wolrd`、 ない`wolrd.`。 単語の署名にピリオドを含むパーサーは検出に失敗します。`world`。 

## アプローチ

 直接的なアプローチは、破損した文からすべての単語を取り出し、それを辞書のすべての単語と比較することです。 候補のペアについては、最初と最後の文字を確認し、2 つの単語内の文字の頻度を比較できます。 これらの条件は、まさに内部文字を並べ替えることによって得られる定義であるため、この方法は正しいです。 

問題は辞書スキャンの繰り返しです。 文に (W) 個の単語があり、辞書に (n) 個の項目がある場合、(Wn) 個の候補チェックが行われる可能性があります。 入力境界から、(W) は約 (250000)、(n) は (500000) になる可能性があり、候補検査の上限は (125000000000) になります。 ほとんどの候補者にとって、継続的に拒否されることさえ、合理的な範囲をはるかに超えています。 

重要な点は、内部の文字の順序はまったく重要ではないということです。 すべての単語は、最初の文字、最後の文字、および 26 個の小文字のそれぞれの頻度で構成される標準署名によって表すことができます。 2 つの単語は、その署名が等しい場合にのみ互換性があります。 

この署名を辞書の単語ごとに 1 回計算し、ハッシュ テーブルに入れることができます。 次に、各文単語が同じ署名に変換され、直接検索されます。 コストのかかる繰り返しの検索がなくなり、辞書の 1 回のパスと文の 1 回のパスだけが残ります。 

ブルートフォース手法は、正確に正しい条件をテストするため機能しますが、同じ情報が繰り返し再発見されます。 互換性は小さな正規署名によって完全に決定されるという観察により、繰り返される比較をハッシュ テーブル検索に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Wn)) 候補チェック、追加の単語比較コスト | (O(n)) | 遅すぎる |
 | 最適 | (O(S+D+26n+26W))、実質的には (O(S+D)) | (O(D+26n)) | 承認済み |

 ここで、(S) は文章の単語の合計長、(D) は辞書の単語の合計長です。 どちらも最大 (5\cdot10^5) であるため、線形項が支配的になります。 

## アルゴリズムのチュートリアル

 1. 破損した文を読み、最後のピリオドを削除します。 入力では隣接する単語間に 1 つのスペースが保証されているため、残りの文字列をスペースで分割すると、破損した単語のシーケンスが正確に得られます。 
2. 辞書の単語ごとに、その最初の文字、最後の文字、および 26 要素の頻度ベクトルを含む署名を構築します。 頻度ベクトルは、端点を含む単語内のすべての文字をカウントします。 エンドポイントも固定されているため、カウントにエンドポイントを含めても安全です。 
3. ハッシュ テーブル内の署名ごとに 1 つの辞書単語を保存します。 いくつかの異なる辞書の単語が 1 つの署名を共有する場合がありますが、ステートメントは有効な再構成を受け入れるため、問題は発生しません。 
4. 破損した文の単語ごとに、その署名を計算し、テーブルで検索します。 署名が存在しない場合、どの辞書単語もこの観察された単語を生成できないため、文全体が有効な再構成を持ちません。 
5. 署名が存在する場合は、保存されている辞書の単語を再構成された文に追加します。 これを単語ごとに個別に繰り返します。 
6. 再構築された単語を単一のスペースで結合し、最後にピリオドを追加します。 結果の文字列には、入力文とまったく同じ単語境界と句読点が含まれます。 

### なぜ効果があるのか

不変条件は、保存されているすべての署名が辞書単語のセットを正確に表しており、その文字は最初または最後の文字を変更することなく、対応する観察された単語に再配置できるということです。 観察された単語が辞書の単語と同じシグネチャを持っている場合、2 つの単語はまったく同じ文字のマルチセットを含み、同一のエンドポイントを持っているため、内部の文字を並べ替えて一方を他方に変換できます。 それらの署名が異なる場合、少なくとも 1 つのエンドポイントまたは文字頻度が異なるため、そのような並べ替えは不可能になります。 したがって、選択されたすべての辞書単語は有効であり、署名が見つからない場合は、有効な再構成が存在しないことが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def signature(word):
    cnt = [0] * 26
    for ch in word:
        cnt[ord(ch) - 97] += 1
    return (word[0], word[-1], tuple(cnt))

def solve():
    text = input().rstrip('\n')
    n = int(input())

    dictionary = {}

    for _ in range(n):
        word = input().strip()
        key = signature(word)
        if key not in dictionary:
            dictionary[key] = word

    words = text[:-1].split(' ')
    answer = []

    for word in words:
        key = signature(word)
        original = dictionary.get(key)

        if original is None:
            print("No solution")
            return

        answer.append(original)

    print(' '.join(answer) + '.')

if __name__ == "__main__":
    solve()
```の`signature`関数は固定サイズの周波数ベクトルを構築します。 すべての文字が 1 回だけ処理されるため、実行時間は単語長に対して直線的です。 タプルによりベクトルが不変になるため、辞書キーの一部として安全に使用できます。 

辞書は文を処理する前に埋められます。 2 つの辞書単語が同じ署名を持つ場合、最初の単語が保持されます。 出力に必要な有効な元のテキストは 1 つだけであるため、これは意図的なものです。 

文は次のように解析されます`text[:-1]`、最後のピリオドを正確に削除します。 入力に関する保証は、他の句読点には特別な処理が必要ないことを意味します。 単一のスペースで分割すると、元の単語シーケンスが得られます。 

ルックアップで使用されるのは、`dictionary.get(key)`直接インデックスを作成するのではなく、 署名が欠けていると、`None`、プログラムがすぐにレポートできるようにします`No solution`。 有効な辞書の単語はすべて空ではない小文字の文字列であるため、`None`正規に保存されている値と混同することはできません。 

最後のピリオドは、すべての単語が再構築された後にのみ追加されます。 これにより、誤って単語署名の一部として扱われることがなくなります。 

ここでは Python の整数はオーバーフローしません。 最大の周波数は最大でも (5\cdot10^5) であり、実際の整数の制限をはるかに下回ります。 

## 実用的な例

 サンプル 1 の場合、辞書には以下が含まれます。`hello`そして`world`。 観察された言葉は、`hello`そして`wolrd`。 

| 単語 | 最初 | 最後 | 文字数 | 検索結果 |
 | --- | --- | --- | --- | --- |
 |`hello`|`h`|`o`|`e:1, h:1, l:2, o:1`|`hello`|
 |`wolrd`|`w`|`d`|`d:1, l:1, o:1, r:1, w:1`|`world`|

 最初の単語はすでに辞書形式になっているため、その署名は`hello`。 2 番目の単語には、同じ文字マルチセットとエンドポイントがあります。`world`、そのため、その署名は見つかります`world`。 再構築した結果は、`hello world.`。 

サンプル 2 の場合、2 番目の文の単語と一致する可能性がある唯一の辞書の単語は次のとおりです。`world`、しかし観察された単語は`wlrd`。 

| 単語 | 最初 | 最後 | 長さ | 検索結果 |
 | --- | --- | --- | --- | --- |
 |`hello`|`h`|`o`| 5 |`hello`|
 |`wlrd`|`w`|`d`| 4 | 不在 |

 2 番目の署名は、次の署名と同じにすることはできません。`world`、手紙だから`o`が欠落しており、合計文字数が異なります。 ルックアップが失敗したため、アルゴリズムはすぐに出力します。`No solution`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(S+D+26(W+n)))、実質的には (O(S+D)) | すべての入力文字は 1 回カウントされ、各署名にはちょうど 26 個のカウンターがあります。 
| スペース | (O(D+26(W+n)))、実質的には (O(D+W+n)) | ハッシュ テーブルには、辞書署名ごとに 1 つの代表単語と 1 つの固定サイズの署名が格納されます。 

文の合計の長さと辞書の合計の長さは両方とも (5\cdot10^5) によって制限されます。 アルファベットは 26 文字しかないため、各署名の固定の 26 要素部分は小さくなります。 その結果、アルゴリズムは線形量の文字処理とハッシュ テーブル操作を実行し、意図した制約に適合します。 

## テストケース```python
import sys
import io

def signature(word):
    cnt = [0] * 26
    for ch in word:
        cnt[ord(ch) - 97] += 1
    return (word[0], word[-1], tuple(cnt))

def solve():
    input = sys.stdin.readline

    text = input().rstrip('\n')
    n = int(input())

    dictionary = {}

    for _ in range(n):
        word = input().strip()
        key = signature(word)
        if key not in dictionary:
            dictionary[key] = word

    words = text[:-1].split(' ')
    answer = []

    for word in words:
        original = dictionary.get(signature(word))
        if original is None:
            print("No solution")
            return
        answer.append(original)

    print(' '.join(answer) + '.')

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("""hello wolrd.
2
hello
world
""") == "hello world.", "sample 1"

assert run("""hello wlrd.
2
hello
world
""") == "No solution", "sample 2"

assert run("""tihs is vrey sceret txet.
7
text
secret
serect
scret
is
very
this
""") == "this is very secret text.", "sample 3"

# Minimum-size input
assert run("""a.
1
a
""") == "a.", "single-letter word"

# One-letter observed word must not match another letter
assert run("""b.
1
a
""") == "No solution", "single-letter mismatch"

# Same endpoints and letter multiset, but dictionary has several valid choices
result = run("""scret.
2
secret
serect
""")
assert result in {"secret.", "serect."}, "multiple valid dictionary words"

# Boundary case where the last letter matters
assert run("""abcda.
1
abcdb
""") == "No solution", "different last letter"

# Large input close to the sentence-size limit
long_word = "a" * 499999
large_input = long_word + ".\n1\n" + long_word + "\n"
assert run(large_input) == long_word + ".", "large word"
