 ## 問題の理解

 頂点が反時計回りに指定され、整数の座標を持つ厳密に凸状の多角形があります。 多角形を正確に等しい面積の 2 つの領域に分割する 1 本の直線を描く必要があります。 ライン自体には 2 つの異なる整数座標点が含まれている必要があり、それらの座標は (-10^{18}) から (10^{18}) の範囲内に収まる必要があります。 

有益な幾何学的特性は、多角形をその頂点のいずれか 1 つから三角形分割できることです。 最初の頂点 (V_0) を選択し、それを他のすべての頂点に接続します。 すべての座標が整数であるため、これにより、2 倍の面積が整数となる (N-2) 個の三角形が生成されます。 全体の問題は、2 倍になった合計面積の半分がこの一連の三角形のどこに収まるかを見つけることになります。 元の問題では、(N\le 1000)、(10^5) で囲まれた座標、および 1 秒の制限が使用されています。 これは線形または二次アルゴリズムにとっては十分小さいですが、扇形三角形分割が認識されれば二次アルゴリズムを実行する理由はありません。 また、必要な等価性が正確であるため、浮動小数点演算よりも正確な整数演算の方が適しています。 

すべての整数と座標のペア (A、B) に対する直接の網羅的な検索は、座標が制限されているため有限ですが、まったく役に立ちません。 およそ ((4\cdot10^{36})^2/2\estimate8\cdot10^{72}) 個の順序のない格子点のペアがあり、すべてのポリゴン エッジに対して 1 つのラインをチェックすると、係数 (N) がさらに追加されます。 (N=1000) の場合、これは (10^{75}) 個の基本的な幾何学的操作に相当します。 有効な切断線が 2 つのポリゴン頂点を通過する必要がないため、ポリゴン頂点のペアを通るラインを試すなど、より合理的に見える強引なアプローチも十分ではありません。 

不注意な実装によって誤って処理される可能性のある境界ケースがいくつかあります。 三角形の場合```
3
0 0
4 0
0 2
```答えは、((0,0)) から反対側のエッジの中点までの中央値です。 中点自体は整数座標を持つ必要はないため、単にエッジ上の整数点を探すだけでは失敗する可能性があります。 私たちの構築では、有理点に分母を掛けて、同じ線上の整数点を取得します。

指定された制約の下では、解決策は常に存在します。`-1`出力は決して必要ありません。 以下の構造は、有効な入力ごとに 1 つを明示的に生成します。 

## アプローチ

 最も文字通りの総当り的な解決策は、整数点を検索し、候補行をテストすることです。 格子には約 (4\cdot10^{36}) 個の点が含まれているため、座標境界だけからはすでに不可能です。 検索をポリゴン頂点のペアを通るラインに制限しても (O(N^2)) 個の候補が残り、各候補をポリゴンに対してチェックするのに (O(N)) 時間がかかります。 最悪のケースは、(N=1000) に対して約 (N^3/2)、およそ (5\cdot10^8) 個のエッジ操作になります。 さらに重要なのは、必要なラインが厳密にエッジの内側にある 2 点でポリゴン境界と交わる可能性があるため、制限された検索が完了していないことです。 

重要な点は、方向を検索する必要がまったくないということです。 最初のポリゴン頂点 (V_0) を固定し、ポリゴンを次のように三角形化します。 

[
 (V_0,V_1,V_2),\quad
 (V_0,V_2,V_3),\quad
 \ドット、\クワッド
 (V_0、V_{N-2}、V_{N-1})。 
]

 各三角形の面積を 2 倍にした値は整数になります。 これらの三角形を通過すると、累積面積はゼロから始まり、多角形全体の 2 倍の面積で終わります。 したがって、これを含めると累積面積が全体の半分以上になる最初の三角形が存在します。 

ある完全な三角形の後で累積領域がちょうど半分である場合、(V_0) からその三角形の最後の頂点までの対角線はすでに目的の切断線になります。 

それ以外の場合、総面積の半分は厳密に 1 つの三角形 (V_0BC) の内側にあります。 その三角形の内部では、(V_0) を通るすべての線と (BC) 上の点 (P) が三角形 (V_0BP) を切り取っています。 (P) が (BC) に沿って移動するにつれてその面積は線形に変化するため、(BC) で必要な比率を正確に選択できます。 

残りの困難は、(P) が整数ではなく有理数である可能性があることです。 ここで、異常に大きい (10^{18}) 出力境界が役に立ちます。 もし

 [
 P=\frac{(2T-d)B+dC}{2T}、
 ]

 単純に使えます

 [
 Q=(2T-d)B+dC。 
]

 点 (Q) は整数の座標を持ち、(V_0) からの (P) と同じ光線上にあります。 したがって、ライン (V_0Q) はまさに必要な切断ラインです。 除算や浮動小数点演算はどこにもありません。

 ## アルゴリズムのチュートリアル

 1. 扇形三角形分割の共通頂点として最初のポリゴン頂点 (V_0) を選択します。 (V_0) を減算して頂点を 1 つおきに移動し、(V_0) が原点になります。 変換によって (V_0) までの領域や行は変更されません。 
2. 連続するペア (V_i,V_{i+1}) ごとに、(1\le i<N-1) を使用して計算します。 

[
 T_i=\left|\オペレーター名{cross}(V_i,V_{i+1})\right|。 
]

 これは三角形 (V_0V_iV_{i+1}) の面積の 2 倍です。 すべての座標は整数であるため、すべての (T_i) は整数です。 

1. すべての (T_i) を合計して、多角形全体の 2 倍の面積 (S) を取得します。 分数を導入せずに、ターゲットが正確に (S/2) になるように、意図的に 2 倍の領域を使用します。 
2. プレフィックスの 2 倍の領域を維持しながら、三角形を通過します。 新しい接頭辞が (2\cdot\text{prefix}\ge S) を満たす最初の三角形 (V_0BC) を見つけます。 凸面性により、すべての扇形三角形が多角形の内側にあり、正の面積を持つことが保証されるため、そのような三角形は常に存在します。 
3. (2\cdot\text{prefix}=S) の場合、(V_0) と現在の三角形の最後の頂点を出力します。 この対角線の前にある扇形の三角形の面積は、ちょうど全体の半分になります。 
4. それ以外の場合は、`before`を (V_0BC) の前のすべての扇形三角形の 2 倍の面積とし、(T) を (V_0BC) の 2 倍の面積とします。 定義する

 [
 d=S-2\cdot\text{前}。 
]

 現在の三角形の必要な部分の面積は 2 倍 (d/2) でなければなりません。 現在の三角形はハーフエリアの境界を横切る最初の三角形であるため、

 [
 0<d<2T。 
]

 1. (B=V_i) および (C=V_{i+1}) とします。 (BC) 上の点は次のように書くことができます。 

[
 P=\frac{(2T-d)B+dC}{2T}。 
]

 三角形 (V_0BP) の面積が 2 倍になります

 # \frac{d}{2T}\operatorname{cross}(B,C)

 \frac d2。 
]

 したがって、この三角形の前の領域に (V_0BP) の領域を加えた値は、正確に (S/2) になります。 

1. (P) は小数になる可能性があるため、出力しません。 代わりに計算します

 [
 Q=(2T-d)B+dC。 
]

 (Q) の座標はすべて整数です。 (Q=2T\cdot P) であるため、点 (V_0,P,Q) は同一直線上にあるため、(V_0) と (Q) を通る線が必要な切断線になります。 

番号付けされたステップの後、不変条件は、累積された扇形三角形が候補対角線の片側の領域を正確に表すということです。 選択した三角形の前では、この領域は厳密に半分より下でしたが、選択した三角形を追加した後は少なくとも半分になります。 三角形の境界で等号が発生した場合、対応する対角線で問題が解決されます。 それ以外の場合、必要な量は厳密にゼロと選択した三角形の全領域の間にあるため、上記の固有点 (P) は厳密にそのエッジの内側にあります。 スケーリングされた整数点 (Q) はまったく同じ線上にあり、出力ラインに整数点があり、多角形を正確に二等分していることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def solve():
    n = int(input())
    p = [tuple(map(int, input().split())) for _ in range(n)]

    ox, oy = p[0]

    # Translate the polygon so p[0] becomes (0, 0).
    q = [(x - ox, y - oy) for x, y in p]
    q[0] = (0, 0)

    # Doubled areas of the fan triangles.
    areas = []
    total = 0

    for i in range(1, n - 1):
        ax, ay = q[i]
        bx, by = q[i + 1]
        t = abs(cross(ax, ay, bx, by))
        areas.append(t)
        total += t

    prefix = 0

    for i, t in enumerate(areas, start=1):
        prefix += t

        # The current fan triangle ends at q[i + 1].
        if prefix * 2 == total:
            x, y = q[i + 1]
            print(ox, oy)
            print(ox + x, oy + y)
            return

        if prefix * 2 > total:
            before = prefix - t
            d = total - 2 * before

            # Current triangle is q[0], q[i], q[i + 1].
            bx, by = q[i]
            cx, cy = q[i + 1]

            # Q = (2T-d) * B + d * C.
            #
            # Q is a scaled version of the exact rational
            # point on BC, so OQ is the same cutting line.
            qx = (2 * t - d) * bx + d * cx
            qy = (2 * t - d) * by + d * cy

            print(ox, oy)
            print(ox + qx, oy + qy)
            return

if __name__ == "__main__":
    solve()
```実装の最初の部分では、最初の頂点によって多角形を平行移動します。 これにより、すべての扇形三角形が 1 つの頂点として原点を持つため、面積公式が特に単純になります。 

の`cross`function は必要な唯一の幾何プリミティブです。 2 つのベクトル (u) と (v) の場合、その絶対値は原点とそれらのベクトルによって形成される三角形の面積の 2 倍になります。 Python の整数には任意の精度があるため、構築された出力が入力座標よりはるかに大きくなる可能性がある場合でも、中間積は安全です。 

最初のループでは、ファンの三角形の面積とその合計を計算します。 2 番目のループでは、その合計の半分を超える最初のプレフィックスを検索します。 等式分岐は、その場合、目的の線がすでに多角形の対角線であるため、分離されています。 

厳密に交差する分岐では、`before`はすでに考慮されている 2 倍の領域です。 数量`d = total - 2 * before`は、現在の三角形から必要な残りの領域の 2 倍です。 係数`2 * t - d`そして`d`は両方とも正であるため、構築された点は、スケーリング前の現在の 2 つのポリゴン頂点間のセグメント上にあります。 

コードは決して除算しません`2 * t`。 これが実装の中心的なトリックです。 有理点に分母を掛けて、整数点を生成します。`Q`同じ線上にあります。 (10^5) で区切られた入力座標では、すべての変換された座標の大きさは最大でも (2\cdot10^5) ですが、個々の三角形については (2T\le8\cdot10^{10}) になります。 したがって、構築された座標は (10^{18}) よりも快適に下回ります。

        p = poly[i]
        q = poly[(i + 1) % len(poly)]
        fp = line_value(a, b, p)
        fq = line_value(a, b, q)
        inp = inside(fp)
        inq = inside(fq)

        if inp:
            result.append(p)

        if inp != inq:
            den = fq - fp
            t = Fraction(-fp, den)
            x = p[0] + t * (q[0] - p[0])
            y = p[1] + t * (q[1] - p[1])
            result.append((x, y))

    return result

def double_area_fraction(poly):
    if len(poly) < 3:
        return Fraction(0)

    s = Fraction(0)
    for i in range(len(poly)):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % len(poly)]
        s += x1 * y2 - y1 * x2
    return abs(s)

def valid_cut(inp, out):
    tokens = out.strip().split()
    if len(tokens) == 1 and tokens[0] == "-1":
        return False

    if len(tokens) != 4:
        return False

    a = (int(tokens[0]), int(tokens[1]))
    b = (int(tokens[2]), int(tokens[3]))

    if a == b:
        return False

    it = iter(inp.strip().split())
    n = int(next(it))
    poly = [(int(next(it)), int(next(it))) for _ in range(n)]

    total = Fraction(polygon_double_area(poly))

    left = clip_halfplane(poly, a, b, True)
    right = clip_halfplane(poly, a, b, False)

    return (
        double_area_fraction(left) * 2 == total
        and double_area_fraction(right) * 2 == total
        and abs(a[0]) <= 10**18
        and abs(a[1]) <= 10**18
        and abs(b[0]) <= 10**18
        and abs(b[1]) <= 10**18
    )

 ## 特殊なケース

 最小の三角形の場合```
3
0 0
4 0
0 2
```このアルゴリズムには、面積が 2 倍になった扇形三角形が 1 つだけあります (8)。 プレフィックスはすぐに合計と等しくなりますが、半分の領域の条件は、三角形全体の後ではなく、その三角形の内部で到達します。 ここ`before = 0`、(T=8)、および(d=8)。 構築された整数点は (Q=8(4,0)+8(0,2)=(32,16)) です。 ((0,0)) から ((32,16)) までの線は中央値なので、両方の部分の面積は (4) になります。 

正確なプレフィックスの場合```
4
0 0
2 0
2 2
0 2
```最初の扇形三角形の面積は 2 倍になり (4)、2 倍になった合計面積は (8) になります。 等価性テストは、厳密に交差する分岐の前に起動されます。 出力の対角線 ((0,0)) から ((2,2)) は、正方形を 2 つの等しい三角形に分割します。 このケースでは、現在の三角形を選択する際の off-by-one エラーと、半分の領域の点が常にエッジの内側にあると想定する実装の両方が捕捉されます。 

付属のサンプルについては```
4
0 3
3 0
3 6
0 7
```最初の三角形の面積は 2 倍になり (18)、多角形全体の面積は 2 倍になります (30)。 (18>15) なので、ターゲットはその三角形の内側にあります。 正確にスケーリングされた点は、最初の頂点を基準とした座標で ((108,72)) となり、出力点 ((108,75)) になります。 ((0,3)) と ((108,75)) を通る線は、((3,5)) で再び多角形と交差し、結果として得られる三角形の面積は (7.5)、多角形の面積 (15) のちょうど半分です。 

境界座標の場合```
3
100000 100000
-100000 100000
-100000 -100000
```入力では、許容される最大の座標の大きさが使用されます。 最初の頂点による平行移動後の他の点は ((-200000,0)) と ((-200000,-200000)) になります。 この構築では、反対側のエッジの中点を三角形の 2 倍の面積でスケールし、(10^{13}) 程度 (10^{18}) をはるかに下回る大きさの点を生成します。 浮動小数点演算は必要ないため、境界で精度が失われることはありません。 

最も微妙なエッジ ケースは、それ自体が整数点ではない合理的な切断点です。 アルゴリズムはその点を丸めることを決して試みません。 代わりに、点を 2 つの整数頂点の有理アフィン組み合わせとして表し、組み合わせ全体にその分母を乗算します。 固定整数頂点 (V_0) からベクトルをスケーリングすると、その長さは変わりますが、方向は変わりません。そのため、結果として得られる整数点は、まったく同じ切断線を決定します。 これが、この構築が、半分の領域のカットがたまたま既存の格子点を通過するポリゴンに対してだけではなく、すべての有効な整数座標の凸型ポリゴンに対して機能する理由です。
