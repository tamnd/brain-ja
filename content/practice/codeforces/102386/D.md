 ## 解決策
 ## 問題の理解

 ちょうど 3 つの戦車があり、1、2、3 と番号が付けられており、Artem は戦車からスタートします。`k`。 各コマンドは 2 つの異なる戦車に名前を付けます。 これら 2 台の戦車の乗組員は戦車を交換するため、アルテムは現在の戦車がコマンドに記載されている 2 台のうちの 1 台である場合にのみ移動します。 

入力には以下が含まれます`n`コマンドは指定された順序で実行されます。 最初の行はコマンドの数と Artem の初期戦車を示します。 次の各行には、1 つのスワップに関係する 2 つのタンク番号が含まれます。 必要な出力は、すべてのコマンドが処理された後の Artem を含むタンク番号です。 

制約`n <= 10^5`これは、ソリューションが各コマンドを一定の回数だけ処理する必要があることを意味します。 アン`O(n)`アルゴリズムは数十万の基本操作のみを実行します。これは、通常の競技プログラミングの制限時間に簡単に適しています。 アン`O(n^2)`シミュレーションには約`10^10`最大入力サイズでの操作が可能になりますが、これは実用的なサイズをはるかに超えています。 

最初のエッジ ケースは、Artem の現在の戦車が関与しないコマンドです。 例えば、```
1 1
2 3
```生成する`1`。 タンク 2 とタンク 3 の間で完全に交換が行われるため、アルテムはタンク 1 に残ります。タンクが関与しているかどうかを確認せずに、コマンドごとにアルテムの位置を変更する不注意な実装により、アルテムが誤って移動する可能性があります。 

2 番目のエッジ ケースは、アルテムが交換された戦車の 1 つにいて、コマンドによって彼が別の戦車に移動する場合です。 例えば、```
1 2
1 2
```生成する`1`。 Artem はタンク 2 から開始するため、タンク 1 と 2 を交換すると、タンク 1 に移動します。 コマンド内の 2 つの数値は、一方が他方を置き換える順序付けられた操作としてではなく、交換の 2 つのエンドポイントとして扱われる必要があります。 

3 番目の有用なケースは、スワップを繰り返すことです。 例えば、```
2 3
2 3
2 3
```生成する`3`。 最初の交換で Artem は 3 から 2 に移動し、2 回目の交換では Artem が 3 に戻ります。実装で繰り返されたコマンドを誤って無視したり、順序を維持せずにコマンドを簡略化しようとしたりすると、この問題が発生する可能性があります。 

## アプローチ

 直接的ではあるが不必要にコストがかかるアプローチは、コマンドごとに Artem の位置を最初から再計算することです。 コマンド処理後`i`、すべてをシミュレートします`i`コマンドの後に答えがあったとしても、アルテムがどこにいるかを特定するコマンド`i-1`はすでに知られています。 シミュレートされたコマンドの総数は次のようになります。`1 + 2 + 3 + ... + n = n(n + 1) / 2`。 

のために`n = 100000`、つまり`5,000,050,000`コマンドシミュレーション。 シミュレーション自体は元のプロセスとまったく同じスワップに従っているため正しいですが、ほぼすべての作業が何度も繰り返されます。 

重要な観察は、乗組員を完全に配置する必要はないということです。 私たちが気にしているのは Artem の現在の戦車だけです。 1つのコマンドに対して`(a, b)`、可能性は3つだけです。 アルテムがどちらにも属さない場合`a`または`b`、彼の立場は変わりません。 彼がいるなら`a`、彼はに移動します`b`。 彼がいるなら`b`、彼はに移動します`a`。 

すべてのコマンドが決定的であるため、ブルート フォース再計算は機能しますが、既に計算された情報を繰り返し再構築すると失敗します。 次の位置は Artem の現在位置と現在のコマンドのみに依存するという観察により、プロセス全体をコマンドごとに 1 つの定数時間更新に減らすことができます。 

結果として得られるアルゴリズムには、戦車の内容の配列や乗組員の表現は必要ありません。 Artem の現在の戦車を含む 1 つの整数で十分です。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そしてアルテムの初期戦車`k`。 店`k`コマンドが実行される前は、それがまさに Artem の位置であるためです。 
2. を処理します。`n`コマンドを入力順に並べます。 コマンドごとに、交換された 2 つのタンクを読み取ります`a`そして`b`。 
3. 現在位置が等しい場合`a`に変更します`b`。 アルチョムは交換中の 2 つの水槽のうちの 1 つに座っていたので、もう一方の水槽に移動します。 
4. それ以外の場合、現在位置が等しい場合`b`に変更します`a`。 同じスワップ ルールが逆方向にも適用されます。 
5. 現在位置がどちらでもない場合`a`または`b`、変更しないままにしておきます。 このコマンドは他の 2 台の戦車に影響を及ぼし、アルテムを動かすことはできません。 
6. すべてのコマンドが処理された後、現在位置を出力します。 すべてのアップデートは元の順序で適用されているため、この値が Artem の最後の戦車になります。 

### なぜ効果があるのか

 不変条件は、すべてのコマンドを処理する直前に、`k`Artem の実際の現在の戦車を保管します。 コマンドの場合`(a, b)`、 もし`k`は`a`、戦車の乗組員`a`タンクに移動します`b`、それでアルテムは次へ移動します`b`。 対称ケースが成立するのは、`k`は`b`、そしていつ`k`タンクでもなければ、アルテムも動きません。 したがって、不変条件はすべてのコマンドの後でも true のままです。 After the last command,`k`したがって、必要な最終タンクでなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    for _ in range(n):
        a, b = map(int, input().split())

        if k == a:
            k = b
        elif k == b:
            k = a

    print(k)

if __name__ == "__main__":
    solve()
```最初の行には、コマンドの数と Artem の初期戦車の両方が読み込まれます。 変数`k`is deliberately reused to represent the current tank, so there is no need for a separate state structure.

 Inside the loop, each command is processed exactly once. の`if`ブランチは Artem がコマンドの最初の戦車にいる場合を処理しますが、`elif`2番目のタンクを担当します。 どちらの条件も true でない場合は、何も割り当てられません`k`、それでアルテムはその場に残ります。 

後のコマンドは前のすべてのコマンドの後に Artem の位置を使用する必要があるため、これらの更新の順序は重要です。 タンクにはすでに 1 から 3 までの番号が付けられているため、ここではインデックス変換はありません。実際には、Python 整数ではこれらの値に対するオーバーフローの心配はありません。`k`1 ～ 3 の範囲外になることはありません。 

入力にはテスト ケースが 1 つだけ含まれているため、外部のテスト ケース ループはありません。 使用する`sys.stdin.readline`最大で効率的な入力処理を実現します。`10^5`コマンド。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n, k = map(int, input().split())

    for _ in range(n):
        a, b = map(int, input().split())

        if k == a:
            k = b
        elif k == b:
            k = a

    print(k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("""2 1
1 2
2 3
""") == "3\n", "sample 1"

# Minimum-size input
assert run("""1 1
2 3
""") == "1\n", "Artem is not involved in the only swap"

# Artem starts at the largest tank number
assert run("""1 3
1 3
""") == "1\n", "boundary tank 3 moves to tank 1"

# Repeated swaps return Artem to the original tank
assert run("""2 3
2 3
2 3
""") == "3\n", "two identical swaps cancel each other"

# Multiple commands, including commands that do not involve Artem
assert run("""5 3
1 2
2 3
1 3
1 2
2 3
""") == "1\n", "mixed swaps"

# Maximum-size input, repeated identical swaps
n = 100000
large_input = f"{n} 1\n" + "1 2\n" * n
expected = "1\n" if n % 2 == 0 else "2\n"
assert run(large_input) == expected, "maximum-size input"

 ## 特殊なケース

 アルテムがスワップに関与していない場合、彼のポジションは変更されない必要があります。 入力用```
1 1
2 3
```初期位置は`1`。 コマンドは戦車を交換するだけです`2`そして`3`、だからどちらでもない`k == a`または`k == b`それは本当です。 アルゴリズムは終了します`k`に等しい`1`そしてプリント`1`。 これにより、すべてのコマンドが Artem を動かすというよくある間違いを防ぐことができます。 

Artem がタンク 2 で開始され、タンク 1 と 2 が交換される場合、更新ではコマンドのもう一方のエンドポイントを使用する必要があります。 のために```
1 2
1 2
```アルゴリズムは次から始まります`k = 2`。 最初の条件は失敗します。`2 != 1`、一方、2 番目は成功します。`2 == 2`、 それで`k`になる`1`。 出力は`1`。 

繰り返されるスワップは個別に処理する必要があります。 のために```
2 3
2 3
2 3
```最初のコマンドが変更されます`k`から`3`に`2`。 2 番目のコマンドは更新された値を確認します。`2`そしてそれを元に戻します`3`。 最終的な出力は次のとおりです`3`。 これは、コマンドを並べ替えたり、単一の永続的なマッピングとして扱うことができない理由を示しています。 

最大サイズの場合には、特別なロジックは必要ありません。 と`100000`などのコマンド```

...
