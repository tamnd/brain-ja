 ## 解決策
 ## 問題の理解

 (n) 日間のシーケンスがあります。 日 (i) には、主題 (a_i) の宿題が表示されます。 ディマは、1 つの科目について現在蓄積されている宿題をすべてこなして 1 日を過ごすか、何もせずに過ごすかのどちらかです。 科目を実行すると、それまでに受けたその科目の課題がすべてクリアされます。 

目標は、すべての割り当てが 1 日の終わり (n) までに完了していることを確認しながら、可能な限り最小の稼働日数を選択することです。 出力は長さ (n) の配列です。 ゼロはディマがその日休むことを意味し、正の値 (c) は主題 (c) の蓄積された宿題をすべて完了することを意味します。 

重要な観察は、同じ主題の割り当てをまとめて延期できることです。 主題 (c) の最後の課題が日 (p) に到着した場合、Dima は単に日 (p) まで待って、そこで (c) のすべての課題を完了することができます。 主題が異なれば最終出現位置も異なるため、これらの操作が競合することはありません。 

制約があるため、これは特に便利です。 (n) と (k) が両方とも (10^5) と同じ大きさである場合、(O(nk)) ソリューションは最大 (10^{10}) 個の演算を実行できますが、これは一般的な競技プログラミングの制限時間をはるかに超えています。 (O(n)) または (O(n+k)) の解が適切なターゲットです。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 件名が 1 回だけ出現する場合は、その唯一の出現を処理日として使用する必要があります。 たとえば、入力の場合```
1 1
1
```答えはきっと```
1
```唯一の課題を完了する必要があるからです。 

同じ主題が何度も出現する場合、割り当てのたびにそれを処理する必要はありません。 のために```
4 2
1 1 1 1
```答え```
0 0 0 1
```4 つの課題すべてを最終日にまとめて完了できるため、これが最適です。 

決して現れない被験者は手術を受けるべきではありません。 例えば、```
3 5
2 2 2
```と答えることができます```
0 0 2
```そして主題 (1、3、4、5) はまったく作業を必要としません。 処理日が発生するかどうかを確認せずに、すべてのサブジェクトを何らかの処理日に初期化する実装では、無効なスケジュールが生成されます。 

最後に、最後に出現するのが最終日である主題は完全に有効です。 のために```
3 2
1 2 2
```出力できます```
0 1 2
```件名 (1) の操作は 2 日目に行われ、件名 (2) は最終割り当てが到着してから 3 日目に処理されます。 

## アプローチ

 直接的なアプローチは、各サブジェクトを個別に処理し、配列全体で最後に出現するものを検索することです。 主題 (1) については、(1) が見つかるまで端からスキャンし、その後、主題 (2) についても同じ検索を繰り返します。 結果として得られるポジションは、まさに私たちが働くべき日です。 

このアプローチは正しいです。なぜなら、最後の出現だけでその主題のすべての割り当てを完了できるからです。 同じ配列を繰り返しスキャンするため、速度が非常に遅くなります。 最悪の場合 (n=k=10^5) では、(n\cdot k=10^{10}) 個の配列検査が必要になります。 

問題の構造により、繰り返しの検索をすべて回避できます。 シーケンスを左から右に 1 回スキャンしているときに、主題 (a_i) を見つけるたびに、その最新の既知の発生が日 (i) であることを簡単に記録できます。 スキャン後、出現するすべての被写体の保存された位置は、まさにその最後の出現位置になります。 次に、その主題を回答のその位置に置き、1 日おきにゼロのままにします。 

セグメント ツリーやさらに複雑なデータ構造は必要ありません。 「延期」というアイデアは、最終課題が到着するまで各被験者の作業を延期することで簡単に実現されます。 

これが最小作業日数を規定する理由は、少なくとも 1 回出現するすべての主題を少なくとも 1 回処理する必要があるためです。 そうしないと、その割り当ては未完了のままになります。 私たちの構築では、出現するすべての主題に対してちょうど 1 営業日を使用するため、この避けられない下限に達します。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(nk)) | (O(k)) | 遅すぎる |
 | 最適 | (O(n+k)) | (O(n+k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n)、(k)、およびシーケンス (a) を読み取ります。 配列を作成する`last`件名ごとにインデックスが付けられ、最初はゼロで埋められます。 ゼロは、その主題がまだ現れていないことを意味します。 
2. (1) から (n) までの日をスキャンします。 日 (i) については、次のように設定します。`last[a[i]] = i`。 同じ被写体が後で再び現れると、その保存された位置は上書きされるため、スキャン後には最後の出現が含まれます。 
3. (n) 個のゼロの応答配列を作成します。 (1) から (k) までのすべての被験者 (c) について、検査します。`last[c]`。 ゼロ以外の場合は、答えのその位置に (c) を入れます。 

ここが重要な構造です。 (c) が最後に発生した時点で、(c) のすべての課題はすでに到着しているため、そこで蓄積されたすべての作業を行うと、その主題のすべての課題が一度に完了します。 
4. 回答配列を出力します。 ゼロ以外のすべての位置は、正確に 1 人の被験者の最後の出現を表し、その他の日はすべて空いています。 

不変条件は、最初の (i) 日間を処理した後、`last[c]`は、主語 (c) が出現する最大 (i) の最大の位置、または出現していない場合は 0 です。 最後に、出現するすべての主題は、最後に出現したときに 1 回だけ処理されます。 有効なソリューションでは、出現するすべての主題に少なくとも 1 日の処理が必要なため、作業日数は最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    last = [0] * (k + 1)

    for i, subject in enumerate(a, start=1):
        last[subject] = i

    answer = [0] * n

    for subject in range(1, k + 1):
        pos = last[subject]
        if pos != 0:
            answer[pos - 1] = subject

    print(*answer)

if __name__ == "__main__":
    solve()
```の`last`配列には、考えられるすべての主題に対して 1 つのエントリがあります。 そのインデックス付けは (1) から始まり、入力内の件名の番号付けと一致しますが、位置 0 は使用されません。 

この問題では 1 から始まる番号付けを使用して日数を記述するため、列挙は 1 から始まります。 最終的な答えは Python のゼロベースのインデックスを使用するため、`last[subject] - 1`に書き込むときに使用されます`answer`。 これはアルゴリズムにおける唯一のインデックス変換であり、他の場所で 2 つの規則が混在することを避けます。 

入力をスキャンするとき、割り当て`last[subject] = i`以前の位置を意図的に上書きします。 その主題の蓄積された宿題はすべて、最後の出現で完了できるため、以前の出現は必要ありません。 

2 番目のループでは、考えられるすべての主題をチェックします。 対象者`last[subject] == 0`決して出現しないため、それらに対する操作は生成されません。 これにより、未使用の件名が誤って回答に表示されるのを防ぎます。 

Python では整数オーバーフローの懸念はなく、保存される最大の日数は (10^5) のみです。

 ## 特殊なケース

 主語が 1 回だけ出現する場合、その最後に出現したものが最初の出現でもあります。 のために```
1 1
1
```スキャンセット`last[1] = 1`、そして答えは次のようになります`1`。 作業を 1 日目以降に延期する方法はないため、建設は強制的かつ最適化されます。 

ある主題が繰り返し現れる場合、以前に起こったことは意図的に忘れられます。 のために```
4 2
1 1 1 1
```件名 (1) に保存されている値は連続して (1,2,3,4) となります。`last[1] = 4`スキャン後。 したがって、答えには 1 つの操作のみが含まれます。`0 0 0 1`。 4 つの割り当てはすべて 4 日目までに保留され、一緒に完了します。 

一部の主題がまったく発生しない場合、その主題は`last`エントリはゼロのままです。 のために```
3 5
2 2 2
```で終わります`last[1] = 0`、`last[2] = 3`、 そして`last[3] = last[4] = last[5] = 0`。 位置 3 のみが値を受け取ります`2`、生産`0 0 2`。 アルゴリズムは、不在の主題のために仕事を発明することはありません。 

サブジェクトの最後の出現が最終日である場合でも、そのサブジェクトに対するすべての割り当てがその時点までに到着しているため、操作は依然として合法です。 のために```
3 2
1 2 2
```最終的な順位は`last[1] = 1`そして`last[2] = 3`したがって、出力は次のようになります`1 0 2`。 主題 (1) はその 1 回の出現で完了しますが、主題 (2) の両方の課題は 3 日目に一緒に完了します。 

繰り返される 2 つの主題間の境界も特別な処理を引き起こしません。 のために```
6 3
1 2 3 1 2 3
```最終的な位置は (4,5,6) です。`0 0 0 1 2 3`。 最初の 3 つの課題は、Dima が待機している間保留されたままになり、最後の課題の後に各主題が 1 回だけ完了します。 

中心的なプロパティは、これらすべてのケースで存続します。出現するすべてのサブジェクトは、その最後の出現時に 1 回処理され、出現しないすべてのサブジェクトは 0 回処理されます。 出現する各主題は必ず少なくとも 1 作業日を必要とするため、この構成よりも短い作業日を使用できる有効なスケジュールはありません。
