 ## 解決策
 ## 問題の理解

 すべてのエッジがインデックスと重みを持つ、接続された無向グラフが与えられます。 ノード 1 から開始し、2 つの目標を同時に達成する必要があります。グラフ内のすべてのエッジを少なくとも 1 回横断し、ノード 1 に戻る必要があります。 

移動方法は 2 つあります。 1 つ目は、エッジに沿った標準的なトラバースで、そのエッジの重みを負担します。 2 つ目は、特別な「テレポートのような」動きです。現在のノードから、任意の宛先ノードとそれらの間の任意のウォークを選択できますが、そのウォークに沿った重みの合計を支払う代わりに、選択したパス上の最大のインデックスを持つエッジの重みを支払います。 これにより、コストは距離ではなくエッジの順序に依存します。 

課題は、すべてのエッジを少なくとも 1 回はカバーし、開始したところから終了することを保証しながら、総コストを最小限に抑えることです。 

この制約は、すべてのテスト ケースにわたって最大約 100 万個の頂点とエッジを意味するため、どのソリューションもエッジの数が基本的に線形またはほぼ線形である必要があります。 すべてのノードのペアを試したり、すべてのパスを明示的に列挙したりするなど、二次的なことは不可能です。 

微妙な点は、グラフの接続は保証されていますが、自己ループや平行エッジが含まれる可能性があることです。 自己ループは依然として「訪問」する必要があるため、見落とされがちですが、接続には役立ちません。 平行エッジは、それぞれカバーする必要がある別個のエッジであるため、重要です。 

単純な間違いは、2 番目の操作のインデックス ベースのコスト ルールを無視して、問題を最短パスまたは MST バリアントとして扱うことです。 たとえば、2 番目の操作に最大エッジ インデックスではなくパスに沿った最大重みがかかると仮定すると、その構造は標準的なグラフ問題に崩壊し、エッジ インデックスと重みが発散する場合に誤った結果が得られます。 

もう 1 つの一般的な失敗ケースは、すべてのエッジを 1 回訪問することがオイラー ツアー条件と同等であると仮定することです。 エッジ トラバーサルのみを使用する場合はこれが当てはまりますが、テレポート操作ではインデックスに関連付けられたコストで「構造のスキップ」が可能になるため、最適な戦略により、グラフの高価な部分の再ウォークを回避できます。 

## アプローチ

 この強引なアイデアは、どのエッジが使用されたかを追跡しながら、歩行またはテレポートの可能なあらゆる方法をモデル化することです。 各状態は現在のノードと使用されているエッジのビットマスクで構成され、遷移はエッジの横断または任意のパスに沿ったテレポートのいずれかをシミュレートします。 これはすべての有効な行程を直接表すため、これは正しいですが、すぐに爆発的に増加します。つまり、エッジのサブセットが指数関数的に多くなり、可能なパスが指数関数的に多くなります。 中程度のグラフであっても、これは完全に不可能になります。 

重要な観察は、「テレポート」操作により、選択したパスの内部構造を実質的に無視し、そのパス上の最大のインデックス付きエッジのみを考慮できるようになるということです。 これにより、問題はパスから、エッジがグローバルにどのように順序付けされるかという方向に移ります。 エッジがインデックスによってソートされると、コスト構造は単調になります。つまり、より高いインデックスが付けられたエッジの使用が、それを含むすべてのパスを支配します。 

これは、インデックスの昇順でエッジを処理し、すでに「アクティブ化された」エッジ上の接続構造を維持することを示唆しています。 新たに追加されたエッジが、低インデックス接続の観点から以前は分離されていたコンポーネントを接続するため、新たなコストを支払わなければならない場合を理解することが目標となります。 

最適な構造は、コンポーネントがどのようにマージされるか、および必要な「高価な遷移」の数を追跡しながら、インデックス順にエッジを追加することでコンポーネントを構築することになります。 エッジが以前は別々だった 2 つのコンポーネントを接続するたびに、必要なコストが発生します。 これは当然、union-find 構造を使用して処理されます。

 ## アルゴリズムのチュートリアル

 素のセット和集合構造を使用して、既に考慮されているエッジによって形成された接続コンポーネントを追跡し、インデックスの昇順にエッジを処理します。 

1. すべての頂点に対して DSU を初期化します。各頂点は独自のコンポーネントとして開始されます。 これは、最初はエッジが使用されていないことを表します。 
2. エッジをインデックスでソートするか、インデックスがすでに 1 から m であるため、単純に入力順序に依存します。 
3. インデックスの昇順でエッジを繰り返します。 各エッジ (u、v) について:

 u と v を含む DSU コンポーネントが異なる場合は、それらをマージします。 

このステップが重要である理由は、一度エッジが考慮されると、将来のパスはそのコストがそのインデックスに依存する「ブリッジ」としてそれを使用できるため、新しい到達可能性構造が定義されるためです。 
4. 各マージ後に存在するコンポーネントの数を反映する実行構造を維持します。 各マージは構造上の必要性に対応します。マージがなければ、グラフは分割されたままになり、コストを最適化した方法ですべてのエッジを確実にカバーすることができません。 
5. 最終的な答えは、このインデックス主導の進化の下で構造を接続するために必要な DSU マージの数から導出されます。これは、より高いインデックス付きエッジによって導入される避けられないコストの寄与に対応します。 

### なぜ効果があるのか

 DSU の進化は、より高いインデックスのエッジが移動に影響を与えることができるようになり、接続性が徐々に強化される様子を反映しています。 すべてのエッジをカバーするジャーニーは、最終的には、より低いインデックスのエッジによって形成されるすべてのコンポーネント間を横断する必要があり、テレポート操作により、そのようなコンポーネント間の移動には、接続を可能にする最も高いインデックスのエッジが正確にかかることが保証されます。 これにより、各 DSU マージが強制コスト イベントを表します。 マージは、以前に分離されていた構造を接続する必要がある場合にのみ発生するため、代替ルートではその移行の費用を回避することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True

    cost = 0

    for i in range(m):
        u, v, w = map(int, input().split())
        if union(u, v):
            cost += w

    print(cost)

if __name__ == "__main__":
    solve()
```このコードでは、パス圧縮とサイズによる結合を備えた標準 DSU を使用して、ほぼ線形のパフォーマンスを保証します。 重要な決定点は、結合が実際に 2 つのコンポーネントをマージする場合にのみエッジの重みを追加することです。これは、インデックスの増加の解釈の下で構造的に必要な接続に対応します。 

実装の微妙な点は、テレポート操作を明示的にシミュレートしないことです。 その効果は、コンポーネント間の接続がエッジ経由で最初に可能になったときに、その接続を 1 回だけ考慮する必要があるという事実によって暗黙的に把握されます。

 ## 特殊なケース

 サイクルを含むグラフは、アルゴリズムがエッジを誤って二重カウントしているかどうかを明らかにするため、最も重要なケースです。 たとえば、三角形では、2 つのエッジが 3 つのノードすべてに接続すると、3 番目のエッジは新しい DSU マージを作成しないため、何も寄与しません。 これは、内部冗長性によって必要な構造コストが増加すべきではないという考えと一致します。 

自己ループもエッジケースです。 自己ループはコンポーネントをマージしないため、ユニオン ロジックでは無視され、接続には影響しません。 これは、頂点間の移動には役に立たず、到達可能性も変更しないため、正しいです。 

平行エッジも正しく動作します。2 つのコンポーネントを接続する最初のエッジのみがカウントされます。 後続の平行エッジは、すでに接続されている端点を検出し、何も寄与しません。
