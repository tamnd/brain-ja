 ## 解決策
 ## 問題の理解

 一連の数値と初期値が与えられます。$x$。 シーケンスを任意に並べ替えることができます。 順序を修正した後、要素を左から右に処理し、現在の値を繰り返し置き換えます。$x$次の配列要素で割ったときの余り。 

各操作では、現在の値を減らすか、変更しないままにすることしかできません。$x \bmod a_i$常に範囲内にあります$[0, a_i - 1]$。 目標は、最終的な値が以下になるような配列の順序を選択することです。$x$すべての操作の後、できるだけ大きくなります。 

重要なオブジェクトは、最終的なシーケンス自体ではなく、各モジュラス演算がその時点の値をどのように制約するかです。 早めに配置された大きな要素は情報を即座に破棄する可能性がありますが、早めに配置された小さな要素は、値をほとんど減らさずに大きな値を保持できます。 

制約が非常に厳しい$n$、 と$n \le 21$。 これは、サブセットまたは順列に対する指数関数的な戦略が許可されることを直ちに示唆しています。 ただし、値自体は次のように大きくなる可能性があります。$10^{18}$したがって、単純な遷移を超える数値状態の列挙に依存するアプローチは不可能です。 これにより、正確な算術探索ではなく、プロセスの構造情報のみを追跡する状態定義が求められます。 

素朴な解釈では、配列のすべての順列を試してプロセスをシミュレートする可能性があります。 これは論理的には機能しますが、計算上は失敗します。$n!$であっても天文学的な大きさです$n = 21$。 

2 番目の素朴なアイデアは、現在の値を正確に保存するサブセットに対する動的プログラミングです。 値の範囲が以下であるため、これも失敗します。$10^{18}$、同じサブセットは、順序に応じて多くの異なる中間値を生成する可能性があります。 

貪欲な直感を打ち破るエッジケースは、多数が非自明な順序で相互作用するときに現れます。 たとえば、次の場合$x = 100$そして配列は$[60, 50, 40]$、最初の利回りを 60 個配置します$100 \bmod 60 = 40$ただし、最初に 40 を配置すると、$100 \bmod 40 = 20$、後でさらに悪化します。 局所的に最適な選択は後のステップ全体で安定しないため、値による貪欲な並べ替えは信頼できません。 

## アプローチ

 ブルートフォースアプローチは、配列のすべての順列を試し、モジュロプロセスをシミュレートし、最大の結果を取得することです。 各シミュレーションの費用$O(n)$、そして、あります$n!$順列なので、総作業量は次のように増加します。$O(n! \cdot n)$。 でさえ$n = 15$、これは不可能になります。 

重要な観察は、順序は各ステップでどの要素が適用されるかによってのみ重要であり、状態空間は使用される要素のサブセットによって支配されるということです。 以来$n \le 21$、余裕があります$2^n$状態を定義できるため、サブセットに対する動的プログラミングを定義できます。 

重要な洞察は、プロセスが DP の意味で可逆的であるということです。シーケンスを前方に構築する代わりに、シーケンスの最後に適用する次の要素を選択することを考えることができます。 要素のサブセットを適用した後の結果がわかっている場合は、最後にもう 1 つの要素を追加して、結果の値を計算できます。 これにより、各状態が使用される要素のセットと、それらを何らかの順序で処理した後の結果の値に対応するサブセット DP が作成されます。 

マスクに対する DP を定義しますが、同じサブセットの順序が異なると異なる結果が生じる可能性があるため、一般にマスクごとに 1 つの値だけを保存するだけでは十分ではありません。 重要なのは、最終結果を最大化するため、すべての値が必要ではなく、各サブセットで達成可能な最良の値のみが必要であるということです。 

これにより、各状態が 1 つの未使用要素による拡張を試み、モジュロ遷移を適用する標準の「値遷移を伴うサブセット DP」が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | マスク上のサブセット DP |$O(n \cdot 2^n)$|$O(2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. どの要素がプロセスですでに使用されているかを表すビットマスクと、現在の値を定義します。$x$これらの要素を何らかの順序で適用した後。 各マスクはシーケンスではなくセットを表すため、DP はそのセットに対して達成可能な最良の結果のみを保持します。 
2. DP を空のセットで初期化します。値は元の値です。$x$。 これは、まだモジュロ演算を適用していないことに対応します。 
3. 要素のサブセットごとに、未使用の要素を 1 つシーケンスに追加しようとします。 現在の状態が次の場合$(mask, value)$そして要素を試してみます$a_i$、新しい値は次のようになります$value \bmod a_i$、新しいマスクには以下が含まれます$i$。 
4. 現在の値と新しく計算された値の間の最大値を取ることによって、新しいマスクの DP エントリを更新します。 これにより、複数の注文が同じサブセットにつながった場合でも、最良の結果のみが保持されることが保証されます。 
5. すべてのサブセットを処理した後、答えはすべての完全なマスクの最大値になります。これは、順序付けが最終的にすべての要素を使用するパスに対応するためです。 

### なぜ効果があるのか

 DP は、要素のサブセットごとに、次の最大値を格納するという不変条件を維持します。$x$これらの要素をある順序で正確に適用すると達成できます。 完全な順列は、各ステップで 1 つの要素が正確に追加されるサブセットを通るパスに対応します。 すべての遷移でモジュロ演算の正確さが維持され、各サブセットの可能な最後のステップがすべて考慮されるため、有効な順序付けが失われることはなく、サブセット全体の最大値が最適化される必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
x = int(input())

N = 1 << n
dp = [-1] * N
dp[0] = x

for mask in range(N):
    cur = dp[mask]
    if cur == -1:
        continue
    for i in range(n):
        if not (mask >> i) & 1:
            nxt = cur % a[i]
            nmask = mask | (1 << i)
            if nxt > dp[nmask]:
                dp[nmask] = nxt

ans = max(dp)
print(ans)
```DP 配列には、使用される要素のサブセットごとに達成可能な最良の値が格納されます。 遷移はすべての未使用の要素をループし、モジュロ演算を適用します。 すべての遷移はより小さいか等しいサブセットのみに依存し、常に保存された値を改善または維持するため、マスクの反復順序は重要ではありません。 

微妙な点は、正確なシーケンスを再構築するのではなく、最終値の最大化のみを考慮しているため、状態の上書きは安全であるということです。 また、未使用の状態を次のように初期化します。$-1$無効な遷移が伝播するのを防ぎます。 

## 実用的な例

 ### 例 1

 入力:```
3
5 6 7
15
```DP 状態をサブセットとして追跡します。 

| マスク | 使用される要素 | 値 |
 | --- | --- | --- |
 | 000 | なし | 15 |
 | 001 | 5 | 15 % 5 = 0 |
 | 010 | 6 | 15 % 6 = 3 |
 | 100 | 7 | 15 % 7 = 1 |
 | 110 | 6,7 | 以前の移行から最高 |
 | 111 | 5,6,7 | 最終最大値 = 3 |

 最適な順序付けでは、最初に 5 などの初期の破壊的モジュロを回避し、代わりに 6 または 7 を最初に適用してより大きな中間値を保持し、最終的に 3 を達成します。 

このトレースは、異なる部分順序がどのように異なる中間値につながるかを示しており、DP はサブセットごとに最良の値を保持します。

 入力:```

| マスク | 使用される要素 | 値 |

この例は、10 が最小の約数であっても、値を早期に崩壊させる可能性があるため、これを早めに配置することが必ずしも最適であるとは限らないことを示しています。

## 特殊なケース

 単一要素の配列が最も単純なシナリオです。 アルゴリズムは次のように DP を初期化します。$x$、唯一の要素を適用すると、すぐに次のようになります$x \bmod a_0$これは、その要素を含む最終マスクに正しく反映されます。 

値の 1 つが 1 である場合は、1 によるモジュロによって値がゼロに折りたたまれるため、極端です。 DP は、サブセットごとに常に最大値を維持するため、完全なカバレッジによって強制されない限り、1 を早すぎる適用することを自然に回避します。 

非常に大きな数値を伴うケース$10^{18}$Python ではオーバーフローの問題は発生しませんが、固定幅の整数を使用する言語では、乗算やその他の演算の前にモジュロが適用されるように注意する必要があります。 ここではモジュロのみが使用されるため、値は安全に制限されたままになります。 

小さな数字が大きな数字の横に表示されると、微妙な順序の罠が発生します。 DP は両方の順序を正しく探索し、可能であれば早期の崩壊を確実に回避し、サブセット探索を通じて最適なシーケンスを発見します。
