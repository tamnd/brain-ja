 ## 解決策
 ## 問題の理解

 いくつかの固定着点を持つ直線が与えられ、それぞれが数直線上の座標に位置します。 プレーヤーは位置 0 から開始し、これらのポイントの最も遠いところに到達したいと考えます。 

動きが制限されています: 現在の位置から前進するには 2 つの方法があります。1 つは通常のジャンプで、最大でもカバー範囲をカバーします。`x`ユニットを使用するか、最大でプレイヤーを前進させる特別なスキルを使用します。`y`単位。 特別なスキルが使用されるたびに、それは 1 回の操作としてカウントされますが、通常のジャンプは、最小限に抑えようとしている答えを増加させないという意味で無料です。 

課題は、最も遠い地点に到達できるかどうかを判断し、到達可能な場合は、ジャンプが任意に使用できると仮定して、そこに到達するために特別なスキルを使用する必要がある回数を最小限に抑えることです。 

重要な隠された構造は、いかなる瞬間においても到達可能な最大位置のみが重要であるということです。 中間の着地点は存在しますが、それが重要なのは、より大きな座標に向かって進むことができる場合に限られます。 

この制約は、足場の数が最大でも数千であるのに対し、座標は最大 100 万であることを意味します。 これは、並べ替えとスキャンだけで十分であり、ポイント間の移動のすべての組み合わせをシミュレートしようとするアプローチは、それがおおよそ 2 次以上である限り問題ないことをすぐに示唆しています。 立方体以上のものはボーダーラインになる可能性がありますが、小さいため合格する可能性があります。`n`。 

失敗することが多い素朴な考えは、各足場を独立して扱い、最初から 1 歩か 2 歩で到達できるかどうかを判断することです。 これは、遠くの地点に到達するには複数の中間足場を連鎖させる必要があり、特別なスキルを最大限に活用できるかどうかは以前の選択に依存するという事実を見逃しています。 

2 番目の微妙な落とし穴が現れるのは、`x`そして`y`は大きく異なります。 もし`x`以上です`y`、特技は実際には役に立たないが、もし`y`が大きい場合、有用な中間点をスキップする必要がある場合、これを使いすぎると有害になる可能性があります。 構造は位置的には単調ですが、コスト的には単調ではありません。 

## アプローチ

 ブルートフォースアプローチでは、足場間の移動の考えられるすべてのシーケンスをシミュレートします。 各位置から、いずれかの移動タイプを使用して到達可能な次のポイントにジャンプして、スキルの使用数を追跡することができます。 これは当然、エッジがいずれかのジャンプ タイプによる到達可能性を表す完全な有向グラフにわたる最短経路問題になります。 

正しいとはいえ、このアプローチはコストがかかりすぎます。`n`以降のすべてのポイントへの移行を検討できるポイントは、約`O(n^2)`完全な最短パスを実行すると、追加のオーバーヘッドが必要になります。 これはすでに境界線に達する危険性があり、これ以上明示的な州の拡大は不可能になります。 

重要な点は、実際には「どの足場から来たのか」を複雑な方法で追跡する必要がないということです。 重要なのは、貪欲に到達可能な最も遠い位置を常に維持しながら、一定のスキル使用回数で到達できるかどうかです。 これにより、問題は 1 次元の進行問題に変わり、ポイントを昇順に処理し、指定された数の特別な動きで達成可能な最高のリーチを維持します。 

すべての遷移を分岐する代わりに、動的な状態を維持します。各足場インデックスについて、そこに到達するために必要な特殊スキルの最小数を計算します。 トランジションについては、フリー ジャンプと高価なスキルの組み合わせを使用して 2 点間のギャップをカバーできるかどうかのみを考慮します。 これにより、各遷移が単純な算術チェックに減ります。

 ## アルゴリズムのチュートリアル

 まず、すべての足場の位置を昇順に並べ替えます。 目標は、左から右に移動することを常に考えることです。後向きに移動しても最も遠い点に到達するのに役立つわけではないからです。 

動的な値を定義します`dp[i]`に到達するために必要な特殊スキルの使用の最小数として`i`- 番目の足場。 

初期化する`dp[0] = 0`, スキルを使用せずに位置0から開始するためです。 

あらゆる足場に`i`、到達可能なすべての足場を更新しようとします`j > i`。 

各ペアごとに`(i, j)`、距離を計算します`d = a[j] - a[i]`。 

次に、最大何段階のサイズを決定します。`x`特別なスキルを使わずに撮影できます。 させて`base = x`。 もし`d <= base`、から行くことができます`i`に`j`特別なスキルを使用せずに、`dp[j] = min(dp[j], dp[i])`。 

それ以外の場合は、満杯の数を計算します。`x`- 使用できるジャンプと、それらを使い果たした後に残るもの。 残りのギャップは特殊スキルを使用して処理され、そのようなスキルを使用するたびに 1 ユニットがコストに貢献します。 更新します`dp[j] = min(dp[j], dp[i] + ceil((d - x) / y))`。 

最終的な答えは、`dp[n-1]`それが有限である場合、そうでない場合、目的地に到達できません。 

正しさは、2 つの足場の間の最適なパスをセグメントに分解でき、限界までフリー ジャンプを使用して前進できるという事実に依存します。`x`、その場合にのみ、残った距離を埋めるために特別な動きを使用します。 ポジションは直線的で厳密に増加するため、以前のポイントを再検討してもコスト削減には決して役立ちません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    INF = 10**18
    dp = [INF] * n
    dp[0] = 0

    for i in range(n):
        for j in range(i + 1, n):
            d = a[j] - a[i]
            if d <= x:
                dp[j] = min(dp[j], dp[i])
            else:
                rem = d - x
                need = (rem + y - 1) // y
                dp[j] = min(dp[j], dp[i] + need)

    ans = dp[n - 1]
    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```コードは最初に足場を並べ替えて、遷移が常に前に進むようにします。 DP 配列には、ポジションごとの最小限のスキル使用量が保存されます。 二重ループでは、可能なすべての前方ジャンプが考慮されます。 

微妙な部分は、1 回の通常のジャンプではギャップをカバーできない場合の処理​​です。 複数の交互ジャンプを明示的にシミュレートしようとする代わりに、効果を単純な算術計算に圧縮します。サイズが 1 つの最大の通常ジャンプの後です。`x`、残りの距離は特殊スキルを繰り返し使用することでカバーされ、それぞれが貢献します`y`進捗。 

最終チェックでは、到達不可能な状態が無限としてマークされたままであることを確認します。

 ## 特殊なケース

 エッジケースの 1 つは、すべての足場が互いに非常に近く、距離内にある場合です。`x`。 この場合、スキルの使用はまったく必要ありません。 すべての遷移が次の条件を満たすため、アルゴリズムがこれを処理します。`d ≤ x`、 それで`dp[n-1]`全体を通してゼロのままです。 

もう 1 つのエッジケースは次のような場合です`x = 0`。 そうなると通常の動作は不可能となり、すべての移行は特殊なスキルに完全に依存しなければなりません。 この式は、繰り返し除算にきれいに退化します。`y`、DP は依然として必要な使用量を正しく蓄積します。 

3 番目のケースは次の場合です。`y = 0`, つまり特技は全く動けません。 その状況ではギャップだけが`≤ x`横断可能です。 ギャップが大きくなると DP 値が無限になり、最終的な答えに到達できなくなり、アルゴリズムはその答えを次のように正しく出力します。`-1`。
