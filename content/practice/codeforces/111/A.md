 ## 解決策
 ## 問題の理解

 次の配列を構築する必要があります`n`正の整数。 配列は 2 つの条件を同時に満たさなければなりません。 

すべての要素の二乗和は少なくとも`x`、要素の通常の合計は以下を超えてはなりません`y`。 

タスクは何かを最適化することではありません。 有効な構造を 1 つ見つけるか、構造が存在しないと判断するだけで済みます。 

この制約により、コストのかかる検索は即座に排除されます。 の値`n`到達できる`10^5`したがって、二次関数や指数関数は不可能です。 の値`x`特に大きく、最大で`10^12`つまり、候補配列のブルートフォース攻撃は完全に非現実的です。 線形時間で計算できる直接的な数学的構造が必要です。 

重要な詳細は、平方条件が通常の合計よりもはるかに速く増加することです。 単一の大きな数値は二乗和に大きく寄与しますが、通常の和には線形にしか寄与しません。 この観察は、値の大部分を均等に分散させるのではなく、1 つの要素に集中させることを強く示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1 10 3
```二乗が少なくとも次の正の整数が 1 つ必要です。`10`、ただし、その値は最大でも`3`。 可能な唯一の要素は、次の両方を満たす必要があります。```
a^2 >= 10
a <= 3
```そのような整数は存在しません。`3^2 = 9`。 正しい出力は次のとおりです。```
-1
```不注意な実装では、正方形の条件をチェックして出力するだけになる可能性があります。`4`, 合計限度額に違反していることを忘れています。 

もう 1 つの微妙なケースは、最小可能額がすでに超えている場合です。`y`。```
5 100 4
```すべての数値は正である必要があるため、可能な最小の合計はすでに`5`。 以来`5 > 4`、関係なく答えは不可能です`x`。 正しい出力は次のとおりです。```
-1
```平方要件のみに焦点を当てた実装では、この即時不可能なシナリオを見逃す可能性があります。 

もう 1 つのトリッキーな例:```
3 11 5
```単純な考えは、値を均等に分配することです。たとえば、`[2,2,1]`。 合計は有効です:```
2 + 2 + 1 = 5
```しかし、平方和は次のとおりです。```
4 + 4 + 1 = 9
```それは小さすぎます。 有効な構造は次のとおりです。```
3 1 1
```なぜなら：```
9 + 1 + 1 = 11
3 + 1 + 1 = 5
```これは、価値を分散させるよりも 1 つの要素に集中させる方が強力である理由を示しています。 

## アプローチ

 ブルートフォースアプローチでは、配列を生成し、それらが 2 つの不等式を満たすかどうかを確認しようとします。 各要素を最大で に制限したとしても、`y`、配列の数は依然として天文学的になります。 たとえば、`n = 20`そして`y = 20`、すでにあります`20^20`可能な配列。 これはまったく実現不可能です。 

候補配列のチェックは簡単なので、総当たりのアイデアは概念的に機能します。 両方の合計を線形時間で計算できます。 問題は検索スペースです。 

画期的な進歩は、正方形がどのように動作するかを理解することから生まれます。 すでに合計額が決まっていると仮定します。 その合計を持つすべての配列の中で、1 つの要素にできるだけ多くの値を入れると、二乗和が最大になります。 

例えば：```
5^2 = 25
```その間：```
3^2 + 2^2 = 13
```数値をより小さな部分に分割すると、二乗寄与が減少します。 

つまり、最良の戦略は非常にシンプルです。 作る`n - 1`に等しい要素`1`すべての数値は正でなければならないためです。 他のすべてを 1 つの大きな要素に入れます。 

その大きな要素を`k`。 

それから：```
sum = k + (n - 1)
square_sum = k^2 + (n - 1)
```必要なものは次のとおりです。```
k^2 + (n - 1) >= x
k + (n - 1) <= y
```有効な最小値`k`平方条件の場合は次のようになります。```
k >= ceil(sqrt(x - (n - 1)))
```それなら`k`和制約も満たしているため、有効な構造が得られます。 そうでなければ、解決策は存在しません。 

これにより、問題全体が数回の算術演算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`x`、 そして`y`。 
2. 予約する`n - 1`要素として`1`。 

すべての数値は正でなければならないため、これはこれらのポジションからの可能な最小の寄与です。 
3. 残りの要素を次のようにします。`k`。 

平方和の合計は次のようになります。```
k^2 + (n - 1)
```4. 最小値を計算する`k`正方形の条件を満たしています。 

必要なものは次のとおりです。```
k^2 >= x - (n - 1)
```それで：```
k = ceil(sqrt(x - (n - 1)))
```もし`x - (n - 1)`すでに非陽性である場合、`k = 1`十分です。 
5. 通常の合計制約が満たされているかどうかを確認します。 

合計額は次のとおりです。```
k + (n - 1)
```これを超えると`y`、印刷`-1`。 
6. それ以外の場合は、印刷します`k`に続く`n - 1`もの。 

### なぜ効果があるのか

 この構造は、任意の与えられた二乗寄与の通常の合計を最小化します。 

大きな平方和が必要だとします。 値を複数の数値に分割することは、次の理由から非効率的です。```
(a + b)^2 > a^2 + b^2
```正の整数の場合`a`そして`b`。 

したがって、固定された通常の合計に対する最大二乗寄与は、できるだけ多くの値を 1 つの要素に集中させることによって達成されます。 他のすべての要素を次のように設定すると、`1`、単一の大きな数値に対して可能な限り最大の予算を残します。 

この可能な限り最善の配置でも両方の不等式を同時に満たすことができない場合、他の配置では満たすことはできません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

n, x, y = map(int, input().split())

need = x - (n - 1)

if need <= 1:
    k = 1
else:
    k = math.isqrt(need)
    if k * k < need:
        k += 1

if k + (n - 1) > y:
    print(-1)
else:
    print(k)
    for _ in range(n - 1):
        print(1)
```実装は構築に直接続きます。 

まずは予約します`n - 1`1人分のポジション。 彼らの平方貢献もまた、`n - 1`、したがって、残りの正方形の要件は次のようになります。```
x - (n - 1)
```次に最小の整数を計算します`k`その正方形は十分に大きいです。 使用する`math.isqrt`浮動小数点精度の問題を回避します。`isqrt(v)`平方根の下限を返すので、必要に応じて 1 ずつ増やします。 

条件:```
if need <= 1:
    k = 1
```既存のものがすでに平方条件をほぼ満たしている場合を処理します。 すべての値は正のままでなければならないため、`k`ゼロにすることはできません。 

最終チェック:```
if k + (n - 1) > y:
```重要な不可能性のテストです。 最も平方効率の高い構造でも合計の制限に違反するため、解決策は存在しません。 

出力順序は関係ありません。 任意の有効な配列が受け入れられます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    n, x, y = map(int, input().split())

    need = x - (n - 1)

    if need <= 1:
        k = 1
    else:
        k = math.isqrt(need)
        if k * k < need:
            k += 1

    if k + (n - 1) > y:
        print(-1)
    else:
        print(k)
        for _ in range(n - 1):
            print(1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("5 15 15\n") == "4\n1\n1\n1\n1\n"

# minimum size, impossible
assert run("1 10 3\n") == "-1\n"

# exact boundary
assert run("3 11 5\n") == "3\n1\n1\n"

# already satisfied by all ones
assert run("4 4 10\n") == "1\n1\n1\n1\n"

# impossible because minimum sum exceeds y
assert run("5 100 4\n") == "-1\n"

# large square requirement
out = run("2 1000000 2000\n")
vals = list(map(int, out.strip().split()))
assert len(vals) == 2
assert vals[0] + vals[1] <= 2000
assert vals[0] * vals[0] + vals[1] * vals[1] >= 1000000
