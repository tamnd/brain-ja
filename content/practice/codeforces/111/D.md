 ## 解決策
 ## 問題の理解

 私たちは、$n \times m$グリッドであり、すべてのセルを次のいずれかでペイントする必要があります。$k$色。 

制限は、列間の垂直方向のカットごとにあります。 ボードを左側の部分と右側の部分に分割し、どちらも空ではない場合、左側に表示される個別の色の数は、右側に表示される個別の色の数と等しくなければなりません。 

この条件を満たす色の数を法で数えなければなりません。$10^9+7$。 

基板の寸法は最大でも$1000$、これは 2 次または 3 次の前処理に十分小さいです。$n$そして$m$。 危険なパラメータは$k$、次のように大きくすることができます$10^6$。 すべての色を直接反復するアルゴリズムは、次のことを行う場合を除いて不可能です。$O(k)$一度働いてください。 単一の列にすでに$k^n$可能性。 

最も難しいのは、この状況が実際に世界的に何を強制しているのかを理解することです。 素朴な解釈では、すべての垂直分割を個別に検査する必要があることがわかりますが、その観点には強力な構造的制約が隠されています。 

間違いやすいのは、状態が左右のパーツ内での色分布に依存すると仮定することです。 異なる色の数だけが重要です。 

たとえば:

 入力:```
1 3 2
```有効な色は次のとおりです。```
aaa
bbb
aba
bab
```答えは次のとおりです。```
4
```不注意なアプローチでは、隣接する列のすべてのペアが同じカラー セットを使用する必要があると誤って認識し、拒否される可能性があります。`aba`そして`bab`。 

もう一つの微妙なケースは次のような場合です。$m=1$。 縦方向のカットが一切ないので、どのカラーリングも有効です。 

例：```
2 1 3
```ボードには 2 つのセルがあり、それぞれに 3 つの選択肢があるため、答えは次のようになります。```
9
```カットから派生した数式を盲目的に適用する実装では、誤って 0 を返したり、単色ボードの数だけを返したりする可能性があります。 

3 番目の落とし穴は、「同じ数の異なる色」と「同じ色のセット」を混同することから生じます。 

例：```
1 4 4
```着色：```
1 2 3 4
```最初のカットの後、左側には 1 つの異なる色があり、右側には 3 つの異なる色があるため、すぐに失敗します。 

しかし:```
1 2 1 2
```実際のセットがカット間で異なっていても機能します。 両面には常に 2 つの異なる色が含まれます。 

全体の問題は、正確なセットを一致させることではなく、異なる色を慎重に数えることにあります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのセルは次のいずれかを取得できます。$k$色があるので、$k^{nm}$合計ボード。 各ボードについて、すべての垂直分割をテストし、両面の異なる色をカウントできます。 

状態を直接確認するのが簡単なため、これは小さなケースに機能します。 しかし、探索空間はすぐに爆発します。 たとえ$n=m=5$そして$k=5$、すでに取得しています$5^{25}$ボード、それは完全に不可能です。 

ブルートフォース手法はすべてのセルを独立して処理するため失敗しますが、条件は列全体での色がどのように表示されるかのみに依存します。 

重要な点は、このプロパティが非常に制限的であるため、すべての色がすべての列に表示されるか、1 つの列にのみ表示される必要があるということです。 

その理由を確認するには、列に何らかの色が表示されていると仮定します。$l$を通して$r$、しかしどこでもというわけではありません。 列内の出現は区別性にとって重要ではないため、その色を含む列のセットのみが重要になります。 

色がカットの両側に現れる場合、それは両方の個別の色の数に寄与します。 片側にのみ表示される場合は、1 つのカウントのみに寄与します。 

次に、列の中間範囲に表示されるが、どこにも表示されるわけではない色を想像してください。 この色が片側にのみ存在するカットが存在し、バランスが 1 変化します。すべてのカットで等価性が成り立つ必要があるため、別の色がすべてのカットを完全に補わない限り、そのような動作は不可能です。 この議論に従うと、すべてのカットで非常に厳格な構造が強制されます。 

すべての色は次のいずれかです。 

1. すべての列に存在する、または
 2. 1 つの列にのみ存在します。 

これが理解されると、問題は幾何学的なものではなく、組み合わせ的なものになります。 

正確に仮定してください$t$すべての列に色が表示されます。 その後、残りのすべての使用色は一意の列に属します。 

単一の列について、色を付ける方法の数を数えなければなりません。$n$セルは以下を使用します:

 1.すべて$t$グローバルカラーが表示される場合と表示されない場合があります。 
2. この列にのみ割り当てられるいくつかのプライベート カラー、
 3. すべてのプライベート カラーが少なくとも 1 回は使用されています。 

これは当然、第 2 種スターリング数と包含排除スタイルのカウントにつながります。 

残りの作業は、これらの独立した列の貢献を効率的に組み立てることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k^{nm} \cdot m \cdot nm)$|$O(k)$| 遅すぎる |
 | 最適 |$O(n^2 + m + k)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。$1000$。 

次のような組み合わせが繰り返し必要になります$\binom{k}{t}$したがって、それらを前処理すると、すべてのクエリが定数時間になります。 
2. 第 2 種スターリング数を事前計算する$S(i,j)$みんなのために$0 \le i,j \le n$。$S(i,j)$のパーティションをカウントします$i$ラベル付きオブジェクトを$j$空ではないグループ。 

ここでは、列が正確に使用する場合に表示されます。$j$プライベート カラー。すべてのプライベート カラーは少なくとも 1 回は出現する必要があります。$n$細胞。 
3. 番号を修正する$t$グローバルカラーの。 

これらの色は複数の列に表示される場合があります。 構造上の議論は、それらがまさにすべての列に表示される色であることを示しています。 
4. それらを選択してください$t$からの色$k$利用可能な色。 

これは次のことに貢献します。$$\binom{k}{t}$$5. しましょう$r = k-t$残りの色になります。 

これらの色は、正確に 1 つの列に対してプライベートです。 
6. 1 つの列について、正確に使用する有効な方法の数を計算します。$x$プライベートカラー。 

まず、この列に属するプライベート カラーを選択します。$$\binom{r}{x}$$次に、$n$間の細胞$t+x$利用可能な色はすべて$x$プライベートカラーは少なくとも1回は出現します。 

包含/除外の使用:$$\sum_{i=0}^{x} (-1)^i \binom{x}{i}(t+x-i)^n$$7. プライベートカラーを付与すると列が独立するため、母関数の観点が有用となる。 

定義する：$$f_x = \frac{1}{x!} \sum_{i=0}^{x} (-1)^i \binom{x}{i}(t+x-i)^n$$すべての列の寄与度は次のようになります。$$(x! f_x)^m$$多項カウントによって結合されます。 
8. 列に対して DP を実行します。 

させて`dp[j]`正確に代入した後のウェイの数を表す`j`プライベートカラー。 

すべての列に追加してみてください`x`新しいプライベート カラーを追加し、それらを使用して有効な列カラーリングの数を掛けます。 
9. すべての列を処理した後、この問題の答えは修正されました。$t$は`dp[r]`。 
10. 可能なすべての合計$t$。 

なぜ効果があるのか:

 証明は構造的特徴付けに基づいています。 すべての列ではないが、複数の列に表示される色は、片側のみに寄与するカットを作成します。 等価条件はすべてのカットで成立する必要があるため、これは不可能です。 したがって、すべての色は 1 つの列に対してグローバルまたはプライベートになります。 

この縮小後、列は、プライベート カラーが列間でどのように分散されるかによってのみ相互作用します。 列内での唯一の要件は、割り当てられたすべてのプライベート カラーが実際に少なくとも 1 回表示されることです。 包含-除外は、それらの全射的割り当てを正確にカウントします。 すべての選択肢は独立してカウントされ、有効なカラーリングはすべてグローバル カラーとプライベート カラーへの 1 つの分解に正確にマッピングされるため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, m, k = map(int, input().split())

MAXN = 1005

# factorials
fact = [1] * (MAXN)
for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact = [1] * (MAXN)
invfact[-1] = pow(fact[-1], MOD - 2, MOD)

for i in range(MAXN - 1, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    if n < MAXN:
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    num = 1
    den = 1
    for i in range(r):
        num = num * (n - i) % MOD
        den = den * (i + 1) % MOD
    return num * pow(den, MOD - 2, MOD) % MOD

# Stirling numbers of the second kind
S = [[0] * (n + 1) for _ in range(n + 1)]
S[0][0] = 1

for i in range(1, n + 1):
    for j in range(1, i + 1):
        S[i][j] = (S[i - 1][j - 1] + j * S[i - 1][j]) % MOD

ans = 0

for t in range(k + 1):
    if t > n:
        break

    global_choose = C(k, t)

    vals = [0] * (n + 1)

    for x in range(n + 1):
        if t + x == 0:
            continue

        vals[x] = fact[x] * S[n][x] % MOD
        vals[x] = vals[x] * pow(t + x, 0, MOD) % MOD

        total = 0
        for y in range(x + 1):
            ways = C(x, y) * pow(t + y, n, MOD)
            ways %= MOD

            if (x - y) & 1:
                total -= ways
            else:
                total += ways

        vals[x] = total % MOD

    dp = [0] * (k - t + 1)
    dp[0] = 1

    for _ in range(m):
        ndp = [0] * (k - t + 1)

        for used in range(k - t + 1):
            if dp[used] == 0:
                continue

            rem = k - t - used

            for add in range(rem + 1):
                ways = C(rem, add) * vals[add]
                ways %= MOD

                ndp[used + add] += dp[used] * ways
                ndp[used + add] %= MOD

        dp = ndp

    ans += global_choose * dp[k - t]
    ans %= MOD

print(ans % MOD)
```この解決策は、階乗と逆階乗を前処理することから始まります。 ほとんどの組み合わせ式は組み合わせであるため、それらを定数時間に減らすことが重要です。 

スターリング テーブルは、古典的な再帰を使用して計算されます。$$S(n,k)=S(n-1,k-1)+kS(n-1,k)$$これは、プライベート カラーへのセルの全射割り当てをカウントします。 

外側のループはグローバル カラーの数を固定します。 その値が固定されると、残りの色はすべて 1 つの列に割り当てられたプライベート カラーになります。 

の`vals[x]`配列には、単一の列が正確に使用する有効な方法の数が格納されます。`x`プライベートカラー。 包含/除外により、選択されたすべてのプライベート カラーが少なくとも 1 回は表示されることが保証されます。 

DP はプライベート カラーを列全体に分散します。`used`以前の列にすでに割り当てられているプラ​​イベート カラーの数を追跡します。 現在の列として選択するのは`add`新しいプライベート カラーを追加し、有効な列カラーリングの数を掛けます。 

実装の微妙な詳細の 1 つは、包含/除外内のモジュラー減算です。 中間値は負になる可能性があるため、すべての結果は次のように正規化する必要があります。`% MOD`。 

もう 1 つの簡単な間違いは、反復することです`t`ずっと`k`。 もし`t > n`の場合、列には`n`細胞。 ループは一度停止します`t > n`。

11

21
22
