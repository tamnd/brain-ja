 ## 解決策
 ## 問題の理解

 期間のある一連のエピソードがあります`t1, t2, ..., tn`。 コリャはそれらを順番に見て、正確に費やします`m`1 日あたりの時間単位。ただし、到着する前にシリーズが終了する可能性がある最終日を除く。`m`。 

視聴セッションの長さが正確であれば、その日は成功したと呼ばれます`m`いくつかのエピソードの正確な終わりに終了します。 セッションがエピソードの途中で終了した場合、その日は成功しません。 最終日は特別です: より少ない場合`m`視聴単位が残っている場合、たとえシリーズがエピソードの最後にちょうど終了したとしても、その日はカウントされません。 

入力により、エピソードの長さと 1 日の視聴制限が決まります。 成功した日が何日あるかを数えなければなりません。 

重要な観察は、視聴の進行状況は総視聴時間のみに依存するということです。 丸一日経ってコーリャは観察した`m`丸 2 日後のユニット`2m`丸3日後`3m`、 等々。 これらの累積視聴時間のいずれかがエピソードの終了と一致したとき、その日は成功したことになります。 

という点では制約は小さい`n`、最大 1000 までですが、エピソードの長さと`m`到達できる`10^9`。 これにより、一度に 1 単位ずつ進むシミュレーションは即座に除外されます。 個々の時間単位ではなく、累積合計に基づいたアプローチが必要です。 

微妙な点は、最後の半日の扱いです。 すべてのエピソードの合計時間が次のようになると仮定します。`S`。 完全な視聴日は時間のみに対応します`m, 2m, 3m, ...`それは厳密に監視のプロセス内にあります。 エピソードが時間通りに終了した場合`S`そして`S`丸一日かかっても到達しない`m`、カウントしてはいけません。 

考慮する：```
1 5
3
```シリーズ全体でわずか 3 ユニットしか続きません。 コーリャさんはそれを半日かけて見ています。 正しい答えは、`0`、 ない`1`。 

もう 1 つの簡単な間違いは、正確に 1 日の境界ではなく、1 日に発生するエピソードの終了を数えることです。 

例：```
2 3
1 2
```初回は1単位で終わりますが、初日は3単位で終了です。 正しい答えは、`1`時間 3 の日の境界がエピソード 2 の終わりと一致するためです。すべてのエピソードの終わりを数えるのは間違っています。 

3 番目のエッジ ケースは、合計期間が次の倍数である場合に発生します。`m`。 

例：```
2 2
1 3
```合計期間は 4 です。丸 2 日あります。 1 日目はエピソード 2 の途中である時刻 2 に終了します。2 日目は時刻 4 に終了します。これはまさにシリーズの終わりであり、エピソードの終わりでもあります。 答えは`1`。 

コリャが正確に見ていたので、最後の丸一日はまだ価値があります`m`その日の単位。 

## アプローチ

 この問題を考える強引な方法は、コリャの視聴状況を毎日シミュレートすることです。 毎日、私たちは彼がどこで止まるかを決定し、場合によってはいくつかのエピソードを移動します。 以来`n`1000しかないので、繰り返しエピソードを進めても問題ありません。 現在のエピソードとその中の位置を維持し、シリーズが終了するまで毎日シミュレーションすることができます。 

ブルート フォース シミュレーションは、表示プロセスに正確に従っているため、正確です。 問題は、それが不必要に複雑であるということです。 プロセスの実際の状態は、総監視時間によって完全に決まります。 

重要な観察は、エピソードの終了はエピソード期間の累積和で発生するということです。 定義すると```
pref[i] = t1 + t2 + ... + ti
```それからエピソード`i`ちょうど時間通りに終わる`pref[i]`。 

1 日のフル視聴の終了がエピソードの終了と一致した場合、成功した 1 日と見なされます。 フル視聴日は終了する場合があります```
m, 2m, 3m, ...
```シリーズの合計期間まで。 

したがって、エピソードの終了時間を次の倍数で数えるだけで済みます。`m`。 

もう一つ条件があります。 最後の半日はカウントされません。 ある時点で終わるエピソード`pref[i]`丸 1 日の終わりに到達した場合にのみ寄付されます。 つまり、`pref[i]`で割り切れる必要があります`m`。 

他には何も関係ありません。 一時停止やエピソードの移行をシミュレートする必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n + 日数) | お(1) | 受け入れられるが、不必要に複雑 |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. 実行中の累積期間を初期化します。`prefix = 0`。 
3. 答えを初期化する`ans = 0`。 
4. エピソードを順番に処理します。 
5. 現在のエピソードの長さを`prefix`。 
6.次のことを確認します。`prefix % m == 0`。 

累積期間が次で割り切れる場合`m`、このエピソードの終了は、フル視聴日の終了と一致します。 
7. 条件が成立する場合、インクリメントします。`ans`。 
8. すべてのエピソードが処理された後、出力します。`ans`。 

これが最後の半日を自動的に処理するのはなぜですか? なぜなら、半日が次の倍数の時刻に終わることは決してないからです。`m`。 累積視聴時間に対応するのは、丸視聴日のみです。`k·m`。 したがって、エピソードの終了を次の倍数で数えることになります。`m`成功した日を正確にカウントし、未完了の最後の日は無視します。 

### なぜ効果があるのか

 しましょう`pref[i]`エピソードが起こる瞬間になる`i`終わります。 

後`k`フル視聴日、Kolya は正確に視聴しました`k·m`時間の単位。 一日が成功したのは、その終わりの瞬間がエピソードの終わりと一致したときです。 ということはエピソードが存在するはずだ`i`そのような```
pref[i] = k·m
```ある整数に対して`k`。 

この条件は次と同等です```
pref[i] % m = 0
```すべての成功した日は、次の数で割り切れる 1 つのエピソードの終了時間に正確に対応します。`m`、そのようなエピソードの終了時間はすべて、成功した日に対応します。 アルゴリズムはこれらの瞬間を正確にカウントするため、結果は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
t = list(map(int, input().split()))

prefix = 0
ans = 0

for x in t:
    prefix += x
    if prefix % m == 0:
        ans += 1

print(ans)
```このソリューションは、これまでに処理されたすべてのエピソードの累積継続時間を維持します。 

累積期間が次の値で割り切れるたびに、`m`、これは、現在のエピソードが完全な視聴日の終わりにちょうど終了することを意味します。 すぐに答えを増やします。 

追加のデータ構造は必要ありません。 累積合計は次のように大きくなる可能性があります`1000 × 10^9 = 10^12`、これは Python の整数に簡単に適合します。 

よくある実装上の間違いは、個々の日とエピソードの位置を推論しようとすることです。 分割条件はすでにプロセス全体を捉えています。 もう一つの間違いは、最終日の部分を心配していることです。 の倍数だけなので、`m`カウントされ、未完了の日数は自動的に除外されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, m = map(int, input().split())
    t = list(map(int, input().split()))

    prefix = 0
    ans = 0

    for x in t:
        prefix += x
        if prefix % m == 0:
            ans += 1

    return str(ans)

# provided samples
assert run("4 2\n1 1 1 1\n") == "2", "sample 1"
assert run("4 3\n1 1 2 1\n") == "0", "sample 2"

# minimum size

# partial final day
assert run("1 5\n3\n") == "0", "only partial day"

# all equal values
assert run("5 2\n2 2 2 2 2\n") == "5", "every episode end is successful"

# off-by-one style check
assert run("2 2\n1 3\n") == "1", "only final episode end matches"

# large values
assert run("3 1000000000\n1000000000 1000000000 1000000000\n") == "3", "large numbers"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 インプットを考慮する```
1 5
3
```累積エピソード終了時間は 3 です。`3 % 5 != 0`、アルゴリズムはそれをカウントせずに返します`0`。 これは、最後の半日は成功しないというルールに一致します。 

ここで考えてみましょう```
2 3
1 2
```累積和は 1 と 3 です。3 で割り切れるのは 3 だけなので、答えは次のようになります。`1`。 

トレース：```
prefix = 1 -> not counted
prefix = 3 -> counted
```このアルゴリズムは、単にエピソード終了の存在だけでなく、日の境界もカウントします。 

最後に考えてみましょう```
2 2
1 3
```累積和は 1 と 4 です。```
1 % 2 = 1
4 % 2 = 0
```第 2 話のみが貢献し、答えを生み出します`1`。 初日はエピソード 2 内で終了しますが、丸 2 日はシリーズが終了すると同時に終了します。 アルゴリズムは、累積エピソード終了時間の割り算を通じて、この区別を自動的に捕捉します。
