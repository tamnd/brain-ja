 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$。 このグリッドから、グリッド線に沿ったサブ四角形を選択します。これは、行と列の連続したブロックを選択することを意味します。 長方形の位置は重要ではないため、長方形はその寸法、高さ、幅によってのみ定義され、2 つの長方形は寸法が異なる場合にのみ同じとみなされます。 

選択したサイズの長方形ごとに$a \times b$、その内部のグリッド線を形成するすべての単位セグメントを、その境界を含めて概念的に描画します。 隣接するグリッド ポイント間の各単位セグメントの描画には 1 秒かかります。 私たちには制限時間が与えられている$t$そして、少なくとも必要な異なる長方形のサイズがいくつあるかを数える必要があります。$t$描画されるセグメント。 

重要な出力は、グリッド内の配置の数ではなく、有効な次元ペアの数です。$(a, b)$その長方形の描画コストが少なくとも$t$、制約付き$1 \le a \le n$、$1 \le b \le m$。 

セグメントの数$a \times b$長方形はグリッド ジオメトリから来ています。 がある$(a+1)b$垂直セグメントと$(b+1)a$水平セグメントなので、合計は次のようになります。$$(a+1)b + (b+1)a = 2ab + a + b$$ペアを数えなければなりません$(a, b)$満足のいく：$$2ab + a + b \ge t$$制約が重要:$n \le 10^3$、 しかし$m, t \le 10^9$。 これは、すべてを反復処理できないことをすぐに示唆しています$a, b$ペアで$O(nm)$、それは次第なので$10^{12}$操作。 平$O(n \log m)$許容されます。$n$は小さく、単調性を利用できます。$b$。 

エッジケースが発生するのは次の場合です$t$非常に小さいか非常に大きいです。 

もし$t = 1$、すべての四角形は有効です。$1 \times 1$長方形には$2\cdot1\cdot1 + 1 + 1 = 4$セグメント。 

もし$t$非常に大きい、たとえば$t = 10^9$、最大の長方形も$n \times m$条件を満たさない可能性があるため、答えはゼロになります。 

よくある間違いは、境界セグメントを無視して、境界セグメントのみを使用することです。$2ab$これはコストを過小評価し、特に小さな長方形の場合に不正確な比較につながります。 

## アプローチ

 素朴なアイデアは簡単です。すべての四角形のサイズを列挙します。$a \times b$、計算する$2ab + a + b$、少なくとも次であるかどうかを確認します$t$。 この式は単位セグメントの数を直接測定するため、これは正しいです。 ただし、これには確認が必要です$n \times m$ペア、最悪の場合は$10^3 \times 10^9$、完全に不可能です。 

不平等の構造はすべてを変えます。 固定する$a$、式$2ab + a + b$と直線的に成長します$b$。 つまり、固定高さの場合$a$のしきい値があります。$b$それ以降は、より大きな幅がすべて有効になります。 この単調な動作により、有効な最小値を求めることができます。$b$残りの選択肢がいくつあるか数えます$O(1)$。 

不等式を整理すると次のようになります。$$2ab + a + b \ge t$$

$$b(2a + 1) \ge t - a$$それぞれについて$a$、最小の整数を計算できます$b$それは以下を満たす：$$b \ge \left\lceil \frac{t - a}{2a + 1} \right\rceil$$それから全部$b$その値から最大まで$m$下限が範囲内にある限り、有効です。 

これにより、2 次元の計数問題が 1 次元のスイープに変換されます。$a$、ステップごとに定数時間の演算を行います。

 ## アルゴリズムのチュートリアル

 あらゆる可能な高さを加工します$a$独立して、それぞれについて幅を計算します$b$有効です。 

1. 値を固定する$a$1から$n$。 これにより 1 つの次元が分離されるので、次の単調性について推論できます。$b$。 
2. 不等式を書き直す$2ab + a + b \ge t$の中へ$b(2a+1) \ge t - a$。 これにより隔離されます$b$それは直接の閾値条件を解決できるからです。 
3. 最小の整数を計算する$b$それは不等式を満たします。 もし$t \le a$、その後は偶数$b = 1$これは、右側が非正になり、この高さのすべての四角形が有効になるため、機能します。 
4. それ以外の場合は、次のように計算します。$$b_{\min} = \left\lceil \frac{t - a}{2a + 1} \right\rceil$$このステップにより、最初の有効な幅が確実に見つかります。 
5. もし$b_{\min} \le m$、からのすべての幅$b_{\min}$に$m$有効である、貢献している$m - b_{\min} + 1$長方形。 もし$b_{\min} > m$、この高さは何も貢献しません。 
6. 全体の寄付額を合計する$a$。 

### なぜ効果があるのか

 固定用$a$、関数$f(b) = 2ab + a + b$厳密に増加しています$b$。 これにより、単一のしきい値動作が保証されます: 1 回$b$が不等式を満たすのに十分な大きさである場合、より大きな値もすべてこの不等式を満たします。 したがってカウントは有効です$b$つまり、不等式が成立する最初の点を見つけることになります。 それぞれなので$a$は独立して網羅的に処理されるため、有効な四角形はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, t = map(int, input().split())

ans = 0

for a in range(1, n + 1):
    # inequality: 2ab + a + b >= t
    # b(2a+1) >= t - a

    if t <= a:
        # even b = 1 works
        ans += m
        continue

    numerator = t - a
    denom = 2 * a + 1

    b_min = (numerator + denom - 1) // denom  # ceil division

    if b_min <= m:
        ans += m - b_min + 1

print(ans)
```コアの実装は代数変換の後に直接続きます。 重要なのは事件の処理です$t \le a$、分子が非正になり、単純な天井除算では誤ってゼロまたは負の値が生成されます。 個別に扱うことで、微妙なオフバイワンの問題を回避できます。 

上限除算は整数演算を使用して実装され、浮動小数点精度のリスクを伴うことなく正確性が保証されます。 

## 実用的な例

 ### 例 1:`2 3 15`高みを越えて繰り返します$a = 1, 2$。

のために$a = 2$:$$4b + 2 + b = 5b + 2 \ge 15 \Rightarrow b \ge 3$$のみ$b = 3$動作します。 

| | 状態 | b_分 | 有効な b カウント |

 最終的な答えは 1 です。 

これは、高さが大きくなると、しきい値が幅の効率においてどのように下方にシフトするかを示しています。 

### 例 2:`3 3 15`全てチェックします$a \in [1,3]$。 

| | 不等式 | b_分 | 貢献 |

この例では、複数の高さが有効な幅の重複に寄与する可能性があり、アルゴリズムがそれらを個別に累積することを強調しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, m, t = map(int, input().split())

    ans = 0
    for a in range(1, n + 1):
        if t <= a:
            ans += m
            continue

        denom = 2 * a + 1

    return str(ans)

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$t \le a$ここで、代数的並べ替えは非正の分子を示唆しています。 たとえば、$n = 5, m = 5, t = 2$、 のために$a = 3$私たちは得ます$t - a = -1$。 正しい動作は、すべての$b \in [1, m]$動作します。 コードはこの条件を明示的にチェックし、すべての寄与を割り当てます。$m$、誤った天井分割を防ぎます。 

もう 1 つのエッジ ケースは、計算された$b_{\min}$を超える$m$。 例えば、$n = 3, m = 3, t = 100$。 全員にとって$a$、しきい値が非常に大きいため、$b_{\min} > 3$、貢献度はゼロでなければなりません。 アルゴリズムはチェックすることでこれを保証します。$b_{\min} \le m$何かを追加する前に、負のカウントやラップアラウンド エラーを回避します。
