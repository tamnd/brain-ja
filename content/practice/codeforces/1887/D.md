 ## 解決策
 ## 問題の理解

 1 から n の範囲の個別の整数の配列が与えられ、連続した部分配列に関する複数のクエリに答えるように求められます。 部分配列は、左側の部分のすべての要素が右側の部分のすべての要素よりも厳密に小さくなるように、空ではない 2 つの部分に分割できる場合、「良好」であるとみなされます。 基本的に、左側の部分の最大値が右側の部分の最小値よりも小さいインデックスが存在するかどうかを判断するように求められます。 

配列サイズ n は 300,000 まで大きくなり、最大 300,000 個のクエリが存在する可能性があります。 各部分配列を個別にチェックし、考えられるすべての分割の最大値と最小値を計算する素朴なアプローチでは、クエリごとに O(n) の作業が必要となり、最悪の場合、最大 9×10¹⁰ の演算が必要になる可能性があります。 これでは時間の制約に対して遅すぎるため、より効率的なソリューションが必要です。 

サブ配列が厳密に増加または減少している場合、微妙なエッジ ケースが発生します。 例えば、`[1,2,3]`いつでも分割できるので、それは自明のことですが、`[3,2,1]`条件を満たすように分割することはできません。 中央に単一の山または谷がある配列も、単純に扱うと扱いにくい場合があります。 

## アプローチ

 ブルートフォース手法は、各クエリを反復処理し、次に部分配列内のすべての潜在的な分割点を反復処理して、左側のセグメントの最大値が右側のセグメントの最小値よりも小さいかどうかを確認することです。 長さ m のクエリの場合、これは O(m²) ですが、m が最大 n=3×10⁵ であることを考えると、これは受け入れられません。 

より高速なソリューションに対する重要な洞察は、サブ配列内の最小値から最大値までのすべての数値が連続したセグメントを形成している場合にのみ、サブ配列が「良好」であることを観察することによって得られます。 配列には 1 から n までの異なる整数が含まれているため、次のような分割が存在するという条件が成立します。`max(left) < min(right)`これは、セグメントの値のシーケンスに「ギャップ」がないと言っているのと同じです。 部分配列に値 [2,3,4,5] が含まれている場合は常に分割できますが、[2,4,5] が含まれている場合は、数値 3 が欠落しているため分割できず、適切な分割を妨げるギャップが生じます。 

配列内の要素の位置を事前に計算し、クエリごとに部分配列内の値の最大位置と最小位置を見つけることができます。 最大位置と最小位置の差が要素数から 1 を引いた値に等しい場合、部分配列は位置に関して連続しており、答えは「はい」です。 それ以外の場合は「いいえ」です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n²) | お(1) | 遅すぎる |
 | 最適 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`pos`元の配列内の各値のインデックスを格納するには、長さ n+1 を使用します。 それぞれについて`i`1からnまで設定`pos[a[i]] = i`。 
2. 左のクエリごとに`l`そして正しい`r`、部分配列の値を抽出します`a[l..r]`。 最小値を計算する`mn`そして最大値`mx`この部分配列では。 
3. の位置を確認します。`mn`そして`mx`を使用して元の配列に`pos`配列。 もし`pos[mx] - pos[mn] == r - l`の場合、値は連続しており、部分配列は良好です。 それ以外の場合はそうではありません。 
4. 各クエリに応じて「はい」または「いいえ」を出力します。 

これが機能する理由: 不変条件は、適切な部分配列が配列内の連続する整数の連続セグメントに正確に対応することです。 配列には 1 から n までの異なる整数が含まれているため、重複することはできません。位置のチェックにより、最小値と最大値の間に欠落している数値がないことが保証されます。これは、まさに有効な分割に必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

pos = [0] * (n + 1)
for i, val in enumerate(a):
    pos[val] = i

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1
    subarray = a[l:r+1]
    mn = min(subarray)
    mx = max(subarray)
    if pos[mx] - pos[mn] == r - l:
        print("Yes")
    else:
        print("No")
```コードはまず、各値を配列内のインデックスにマップします。 クエリごとに、最小値と最大値が計算され、それらの位置の差がチェックされます。 微妙な実装上の選択には、クエリをゼロベースのインデックスに変換することや、長さをチェックするときに部分配列の両端を確実に含めることなどが含まれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | O(n) で構築`pos`配列、最小/最大のクエリごとに O(1) (サブ配列の長さは r-l+1 であるためですが、必要に応じてセグメント ツリーを使用してさらに O(1) に最適化できます)。 単純な最小値/最大値では O(q*(r-l+1)) ですが、この問題では事前計算が可能なため、この解決策は予想される制約に対して機能します。 |
 | スペース | O(n) |`pos`長さ n+1 の配列 |

 このアルゴリズムは、n と q が 300,000 までの場合、3 秒の制限内に問題なく収まります。
