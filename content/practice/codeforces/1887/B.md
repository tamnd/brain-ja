 ## 解決策
 ## 問題の理解

 私たちには、固定された一連の都市と一連の歴史的スナップショットが与えられます。 各スナップショットは、その時点で都市間にどの道路が存在するかを示します。 これらの道路網は、スナップショットごとに完全に変化します。 

タイムマシンは、固定された一連のスナップショットを強制的に実行します。 このシーケンスの最初のスナップショットでは都市 1 から開始します。 次のスナップショットへの各強制ジャンプの後、次のジャンプが発生するまでに、そのスナップショットに存在する道路を最大 1 つ通過することができます。 このプロセスは、都市 n に到達するか、すべてのタイム ジャンプを使い果たすまで続きます。 

目標は、最初のスナップショット訪問を 1 回の移動として数えて、都市 n に到達するのに十分な、指定された時間シーケンスの最小のプレフィックスを決定することです。 

この制約は、すべてのスナップショットにわたる都市の数と道路の合計が最大 2・10^5 になる可能性があることを示しています。 これにより、接続を再計算したり、スナップショットごとに最短パスを個別に実行したりするアプローチは除外されます。 BFS を使用してすべてのスナップショットを最初からリニア スキャンしても遅すぎます。 

より微妙な制約は、スナップショットごとに単一エッジのルールです。 これにより、問題は、各層が最大 1 つのエッジ トラバーサルに寄与する、階層化された時間拡張到達可能性問題に変わります。 素朴な直感では、各スナップショット内で BFS を実行することを提案するかもしれませんが、1 つのスナップショット内で任意に探索することは許可されていないため、これは失敗します。 

いくつかの重要なエッジケースがその構造を浮き彫りにしています。 

すべてのスナップショットが空の場合、移動は不可能であるため、答えは -1 になります。 

都市 1 が都市 n と等しい場合、最初のスナップショットですでに目的地に到着しているため、答えはすぐに 1 になります。 

単一のスナップショットに 1 から n までの直接エッジが含まれているが、それがシーケンスの後半に表示される場合、以前のスナップショットによって誤った中間状態が強制されると、依然としてそのエッジに到達できない可能性があります。 

## アプローチ

 ブルートフォース解釈では、指定された一連のスナップショットに沿ってプロセスを段階的にシミュレートします。 各スナップショットで、現在到達可能な都市のセットがわかり、それらの各都市から、オプションでそのスナップショット内の 1 つの発信エッジに沿って移動できます。 これは、到達可能なセットを維持し、繰り返し更新することを示唆しています。 

ただし、これを慎重に行うのは困難です。 スナップショットごとに完全な BFS フロンティアを維持しようとすると、各スナップショットの更新でそのスナップショットのすべてのエッジがスキャンされる可能性があります。 最大合計 2·10^5 のエッジを持つ k 個以上のスナップショットでは、これはすでに境界線に見えます。 本当の問題は、単純なシミュレーションでは、時間拡張グラフ上で階層化された最短パスを効果的に実行していることが捉えられないことです。各スナップショットは 1 つのレイヤーに対応し、各移動は 1 つのレイヤー遷移を消費することに対応します。 

重要な観察は、州は単なる都市ではなく、現在の都市と使用したタイム ジャンプの回数の組み合わせであるということです。 各状態から次のスナップショットに移行し、必要に応じてそのスナップショット内の 1 つのエッジを横断します。 これにより、レイヤー上に DAG のような構造が作成されます。 各スナップショットで到達可能性を個別に再計算するのではなく、シーケンスを通じてフロンティアを前方に一度伝播します。 

スナップショットの各プレフィックスを処理した後、到達可能な都市のセットを維持します。 各スナップショットについて、以前に到達可能なセットから開始し、そのスナップショット内で 1 つのエッジ緩和を許可します。都市 u にいて、現在のスナップショットにエッジ u-v がある場合、同じタイム ステップで v に到達できます。 これは本質的に、各スナップショットが 1 つの緩和ステップに寄与する BFS レイヤーの拡張です。 

重要な効率化の秘訣は、各スナップショットを独立して扱いますが、到達可能かどうかのバイナリ状態のみを伝播し、そのスナップショットの隣接リストを使用して一度だけ更新することです。 各エッジはすべてのスナップショットにわたって 1 回処理されるため、合計作業量は線形のままです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | スナップショットごとのブルート フォース BFS | O(k · (n + m)) | O(n + m) | 遅すぎる |
 | スナップショット上の階層化された伝播 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、一連の時間層を通じて到達可能なセットを繰り返し伝播するものであると解釈します。 

1. 都市 1 のみが到達可能としてマークされて、サイズ n の到達可能なブール配列を初期化します。 これは、移動前の最初のスナップショットで都市 1 にいたことを表します。 
2. 指定された順序でスナップショットを処理します。 スナップショット i については、到達可能およびスナップショット i に存在するすべてのエッジに基づいて新しいセット next_reachable を計算します。 
3. next_reachable を、reachable のコピーとして開始します。 これは、このスナップショットの間、道路を横断せずに同じ都市に滞在することを選択する可能性があるという事実をエンコードしています。 
4. スナップショット i のすべての道路 (u, v) について、u が到達可能であれば、v を next_reachable で到達可能としてマークし、v が到達可能であれば、対称的に u をマークします。 これは、このスナップショット中に許可される単一のエッジ トラバーサルをモデル化します。 
5. スナップショット i のすべてのエッジを処理した後、reachable = next_reachable を更新します。 
6. スナップショットを更新するたびに、都市 n に到達可能かどうかを確認します。 これが発生する最初のスナップショット インデックスは、必要な最小タイム トラベル数に対応します。 
7. 都市 n に到達することなくすべてのスナップショットを終了した場合は、-1 を返します。 

微妙な点は、スナップショットごとに 1 つのエッジ トラバーサルのみを許可することですが、これは、スナップショットごとに 1 回のみ到達可能性を伝播することで当然強制されます。 新しく到達したノードから次回のレイヤーまで再拡張しないため、同じスナップショット内で複数のエッジをチェーンすることはありません。 

### なぜ効果があるのか

 i 個のスナップショットを処理した後の任意の時点で、到達可能は、各スナップショットが最大 1 つのエッジ トラバーサルに寄与するという制約を考慮して、i 個のタイムトラベル後に占有できる都市のセットを正確に表します。 これは、reachable から next_reachable への各遷移が、所定の位置に留まるか、スナップショット i から 1 つのエッジを正確に適用することに対応するため当てはまります。 同じスナップショット内で新しく追加されたノードを再処理することは決してないので、単一のタイムレイヤー内でのマルチエッジチェーンを防止し、問題の制限を維持します。 

すべての有効な移動シーケンスは、これらの層を通る 1 つの伝播パスに正確に対応し、そのようなすべての遷移が考慮されるため、最初に都市 n が到達可能に表示されるのが、必要な最小タイムトラベル数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    
    snapshots = []
    for _ in range(t):
        m = int(input())
        edges = []
        for _ in range(m):
            u, v = map(int, input().split())
            edges.append((u - 1, v - 1))
        snapshots.append(edges)

    k = int(input())
    a = list(map(int, input().split()))

    # reachable cities (0-indexed)
    reachable = [False] * n
    reachable[0] = True

    for i in range(k):
        edges = snapshots[a[i] - 1]

        nxt = reachable[:]  # we can always stay

        for u, v in edges:
            if reachable[u]:
                nxt[v] = True
            if reachable[v]:
                nxt[u] = True

        reachable = nxt

        if reachable[n - 1]:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、レイヤーごとの伝播を直接実装します。 重要な実装の詳細は、nxt へのスナップショットのコピーです。 これにより、同じスナップショット内で更新がカスケードされなくなります。 到達可能をその場で更新すると、新しく到達した都市が同じスナップショット内の別のエッジを誤って伝播し、「瞬間ごとに最大 1 本の道路」ルールに違反する可能性があります。 

また、都市 1 と都市 n をマークする際の off-by-one エラーを回避するために、都市を 0 ベースのインデックスに変換します。

 ## 特殊なケース

 都市 1 がすでに都市 n である場合、アルゴリズムはスナップショット処理の前にすぐに到達可能な [n - 1] を true とみなして 1 を返します。最初の到達可能な配列には開始都市のみが含まれるため、このケースは反復せずにきれいに処理されます。 

スナップショットにエッジが含まれているが、現在到達可能なノードに接続されていない場合、nxt は到達可能なままになります。 これにより、アルゴリズムは、偶発的な状態の増加を発生させることなく、無駄なタイムトラベルステップを正しくモデル化することが保証されます。 

すべてのスナップショットが空の場合、すべての nxt はすべてのステップで到達可能になります。 拡張は決して起こらないため、都市 n に到達することはなく、最終的な答えは正しく -1 になります。
