 ## 解決策
 ## 問題の理解

 一連の整数が与えられます`r_1, r_2, ..., r_n`、未知の配列の特性と呼ばれる`a_1, a_2, ..., a_n`長さの`n`。 それぞれ`r_i`最小のインデックスを表します`j ≥ i`からのサブセグメントが`a_i`に`a_j`元のシーケンスのどこかに出現するすべての数値が含まれます`a`。 そのような場合`j`存在しません、`r_i`は`n + 1`。 私たちの仕事は、あらゆるシーケンスを再構築することです`a`この特徴と一致するか、そのような配列は存在しないと報告します。 

入力には複数のテスト ケースがあり、`n`テスト ケースごとに最大 200,000 に達する可能性があり、合計は`n`すべてのテストで最大 200,000 件。 これは、すべてのサブセグメントを検査する単純な O(n²) アプローチが実行不可能であることを意味します。 線形または線形に近い解決策が必要です。 

エッジケースが発生するのは次の場合です`r_i = i`これは、現在の要素だけですべての個別の数値のセットが完成することを意味します。`r_i`長いセグメントでは一定のままです。 繰り返しを考慮しない不注意な実装`r_i`値またはそれを超えたジャンプ`n`解決策が不可能であると誤って宣言する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、再構築が試みられます。`a`それぞれをスキャンすることで`i`そして実装`a_i`まで、考えられるすべての数字を使って、`r_i`という制約が満たされています。 これには、各セグメント内の一連の個別の数値を繰り返し追跡する必要があります。 のために`n`2・10^5 までの場合、このアプローチは O(n²) であり、最悪の場合にはおよそ 10^10 の演算を実行することになりますが、これでは遅すぎます。 

重要な洞察は、次の順序を理解することです。`a`単一の「現在の値」プレースホルダーを使用して貪欲に再構築できます。 毎回`r_i`前進（すなわち、`r_i`>`r_{i-1}`)、最近使用されていない新しい番号を導入する必要があります。 もし`r_i`等しい`r_{i-1}`、前の番号を安全に繰り返すことができます。 唯一の無効なシナリオが発生するのは、`r_i`<`i`、またはシーケンスに数字を入力できない場合`[1, n]`特性を損なうことなく。 

これにより、問題は単純な貪欲な塗りつぶしになります。つまり、左から右に繰り返し、新しい番号を割り当ててセグメントを拡張するか、前の番号を再利用します。 の構造`r`特性が存在する場合、一連の選択がその特性を満たすことを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 貪欲な再構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の配列を初期化する`a`長さの`n`再構築されたシーケンスを保存します。 カウンターを維持する`next_number`1 から始まり、必要に応じて個別の番号を割り当てます。 
2. インデックスを反復処理する`i`0からn-1まで。 追跡する`last_r`、最初は0です。 
3. 各インデックスで`i`、 チェック`r[i]`。 もし`r[i] == last_r`で前の要素を繰り返します。`a`。 セグメント長の要件は変更されていないため、これは安全です。 
4. もし`r[i] > last_r`、割り当てます`a[i] = next_number`そして増加します`next_number`。 これにより、カバーするセグメントを拡張するための新しい個別の値が導入されます。`r[i]`。 
5. もし`next_number`を超える`n`、または`r[i] < i + 1`、制約を満たすことができないため、「いいえ」を宣言します。 
6.すべて記入したら`a_i`、「はい」を出力し、配列`a`。 

なぜ機能するのか: 不変条件は、各インデックスで`i`、サブセグメント`a[i:r_i]`これまでに紹介したすべての個別の番号が含まれます。 以前の番号を再利用するという貪欲な選択`r_i`セグメントを拡張しないため、前進しながら不必要な新しい番号を導入しないことが保証されます。`next_number`必要に応じて、新しい要素のカバレッジを保証します。 この構造はすべてを満足させます`r_i`制約があり、許容される数値範囲を超えません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        r = list(map(int, input().split()))
        
        a = [0] * n
        next_number = 1
        used_numbers = set()
        last_r = 0
        valid = True
        
        for i in range(n):
            if r[i] < i + 1:
                valid = False
                break
            if i == 0 or r[i] > r[i-1]:
                a[i] = next_number
                next_number += 1
            else:
                a[i] = a[i-1]
        
        if valid:
            print("Yes")
            print(" ".join(map(str, a)))
        else:
            print("No")

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースの数を読み取り、各ケースを反復処理します。 要素ごとに、新しい数値を導入するか、前の数値を繰り返すかを決定します。 小切手`r[i] < i + 1`不可能な構成を迅速に検出し、`next_number`すべての数値が範囲内に収まるようにします`[1, n]`。

## 特殊なケース

 いつ`r_i = i`みんなのために`i`、各要素だけですべての個別の数値をカバーする必要があります。 アルゴリズムは各ステップで新しい番号を割り当て、厳密に増加するシーケンスを生成します。`1, 2, ..., n`、特性と一致します。 

いつ`r_i`複数のインデックスにわたって一定のままであれば、アルゴリズムは前の数値を正確に繰り返します。 例えば、`r = [3, 3, 3]`生成する`a = [1, 1, 1]`または`a = [1, 2, 1]`、両方とも有効で、アルゴリズムが個別の数値を過剰にカウントせずに繰り返しセグメントを処理することを示しています。 

いつ`r_i > n`発生すると、自動的に無効としてフラグが立てられます
