 ## 解決策
 ## 問題の理解

 サイズの順列を数えるように求められます`n`ここで、特定の数字`x`固定インデックスに配置されます`pos`、問題で説明されているように、標準の二分探索手順では、次のものが正常に見つかります。`x`その位置で。 ここでの順列とは、数値の任意の順序のことです`1`を通して`n`。 入力では 3 つの整数を指定します。`n`順列のサイズについては、`x`検索している番号について、そして`pos`インデックスの場合、`x`終わらなければならない。 出力は有効な順列の数を法で表したものです。`10^9+7`。 

明らかではない点は、二分探索が一連の比較をシミュレートすることです。 検索するとき`x`の場合、検索では左右の境界が維持され、中央の要素が繰り返しチェックされます。 各比較により、残りの配列が効果的に、以下の数値またはより大きい数値に分割されます。`x`検索パスに基づいて。 したがって、置換が成功するには、左側の要素が必要です。`pos`として訪れたのは`mid`そして比較して`x`すべて以下でなければなりません`x`、右側の要素の方が大きくなければなりません。 

制約は中程度です。`n`最大 1000 に達する可能性があり、すべてに対してブルートフォース アプローチが行われます。`n!`順列は実行不可能ですが、3 次または 2 次の複雑さのアルゴリズムも可能です。 

重要なエッジケースが発生するのは次の場合です。`x`極端なインデックス (0 または n-1) にあります。 二分探索は特定の位置のみを訪問し、他の位置はスキップされる場合があります。 すべての順列をカウントする素朴なアプローチ`x`にあります`pos`バイナリ検索パスをシミュレートしないと、不正確な結果が得られます。 たとえば、`n=3`、`x=2`、 そして`pos=0`、他の数値の特定の配置のみで二分探索が成功します。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 サイズのすべての順列を生成します`n`、 場所`x`で`pos`、各順列で二分探索をシミュレートし、成功をカウントします。 このアプローチは正しいですが、計算上実行不可能です。`n!`急速に増加し、10^256 に達します`n=1000`。 

最適なアプローチは、バイナリ検索の動作を分析することから得られます。 インデックスでの二分検索の反復ごと`mid`かどうかを決定します`mid`以下である、以上である、または等しい`pos`。 もし`mid < pos`の要素`mid`より小さい必要があります`x`。 もし`mid > pos`、要素は以下より大きくなければなりません`x`。 したがって、以下の要素の数を数えることができます。`x`それは左側にある位置に入らなければなりません`pos`より大きな要素についても同様です。 残りのポジションは自由に入力できます。 これにより、問題は階乗と組み合わせを使用した組み合わせ計数問題に変わります。 

この洞察により、問題は、すべての順列の生成から、二分探索パスを尊重しながら小さい数と大きい数を分配する方法を数えることにまで軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 組み合わせ計数 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 10^9+7 を法とする階乗と逆階乗を事前計算して、順列と組み合わせを効率的に計算できるようにします。 
2.初期化`left = 0`そして`right = n`。 これは二分探索限界を表します。 2 つのカウンターを追跡します。`less_needed`より小さい数値の場合`x`それは現れるはずです、そして`greater_needed`より大きい数値の場合`x`それは必ず現れるはずです。 
3. 二分探索をシミュレートします。`left < right`、計算する`mid = (left + right) // 2`。 もし`mid <= pos`、 動く`left = mid + 1`そして増加します`less_needed`もし`mid != pos`そのインデックスには以下の数値が含まれている必要があるため、`x`。 もし`mid > pos`、 動く`right = mid`そして増加します`greater_needed`そのインデックスには より大きい数値が含まれている必要があるため、`x`。 
4. ループの後、以下より小さい数値が正確にいくつあるかがわかります。`x`特定の位置を占める必要があるか、それより大きい数字がいくつあるか`x`他のポジションを占める必要がある。 
5. 階乗を使用してこれらの数値を割り当てる方法の数を計算します。 選ぶ`less_needed`からの数字`x-1`数字を小さくして並べます。 選ぶ`greater_needed`からの数字`n-x`より大きな数を指定して配置します。 残りの数字は残りの位置を自由に埋めることができます。 
6. これらの数値を掛け合わせ、10^9+7 を法として求めて最終的な答えを求めます。 

機能する理由: バイナリ検索パスは、以下の要素より小さい要素と大きい要素に厳密な順序制約を課します。`x`。 小さい要素と大きい要素がどれくらいの数の左右の位置を占める必要があるかを正確に数えることによって、`pos`、残りの要素を任意に配置して、有効な順列をすべて重複や欠落なく列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(a, m):
    return pow(a, m-2, m)

def precompute_factorials(n):
    fact = [1]*(n+1)
    inv_fact = [1]*(n+1)
    for i in range(1, n+1):
        fact[i] = fact[i-1]*i % MOD
    inv_fact[n] = modinv(fact[n], MOD)
    for i in range(n-1, 0, -1):
        inv_fact[i] = inv_fact[i+1]*(i+1) % MOD
    return fact, inv_fact

def solve():
    n, x, pos = map(int, input().split())
    fact, inv_fact = precompute_factorials(n)
    
    left = 0
    right = n
    less_needed = 0
    greater_needed = 0

    while left < right:
        mid = (left + right) // 2
        if mid <= pos:
            if mid != pos:
                less_needed += 1
            left = mid + 1
        else:
            greater_needed += 1
            right = mid

    if less_needed > x - 1 or greater_needed > n - x:
        print(0)
        return

    remaining = n - 1 - less_needed - greater_needed

    def comb(a, b):
        return fact[a]*inv_fact[b]%MOD*inv_fact[a-b]%MOD

    ans = comb(x-1, less_needed) * fact[less_needed] % MOD
    ans = ans * comb(n-x, greater_needed) % MOD
    ans = ans * fact[greater_needed] % MOD
    ans = ans * fact[remaining] % MOD
    print(ans % MOD)

solve()
```コードは階乗とモジュラー逆関数を事前計算することから始まります。 次に、二分探索をシミュレートして、以下の数値より小さいまたは大きい数値がいくつあるかを数えます。`x`特定の位置を占めなければなりません。 組み合わせ公式は、これらの数値を割り当てる方法の数を計算し、残りの位置は残った数値で埋められます。 モジュロ演算により、値が範囲内に収まることが保証されます。 

## 実用的な例

 **サンプル 1:**`n=4, x=1, pos=2`| ステップ | 左 | 右 | ミッド | 必要性が低い | 必要以上 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 4 | 2 | 0 | 0 |
 | 2 | 3 | 4 | 3 | 0 | 1 |
 | 3 | 3 | 3 | - | 0 | 1 |

 残り = 2 (位置 0 と 1)。`x-1=0`より小さい数字、`n-x=3`より大きな数字。 より大きな数値を 1 つ選択して、greater_needed を埋め、残りの 2 つの数値で残りを埋めます。 合計ウェイ = 3_1_2 = 6。 

**サンプル 2:**`n=3, x=2, pos=0`| ステップ | 左 | 右 | ミッド | 必要性が低い | 必要以上 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 1 | 0 | 1 |
 | 2 | 0 | 1 | 0 | 0 | 1 |

 残り = 1。小さい数 = 1、大きい数 = 1。ウェイ = 1_1_1*1=1。 

これらのトレースは、二分探索シミュレーションが、強制位置を占有する必要がある小さい数値と大きい数値の個数を正確に特定していることを示しています。
