 ## 解決策
 ## 問題の理解

 この問題では、整数の配列が提示され、特定の加重合計が指定された目標値と一致するように整数の配列を並べ替えることができるかどうかが尋ねられます。 合計はすべての開始位置の合計として定義されます$i$その位置から各要素の末尾までの合計を 1 から始まるインデックスで割った値。 概念的には、各要素は全体の合計の複数の項に寄与し、前の要素は後の要素よりも多くの項に影響を与えます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列の長さ、ターゲットの合計、および配列自体が示されます。 正確な合計を生成する配列の順列が存在する場合、出力は「YES」、それ以外の場合は「NO」になります。 

制約がある中で$1 \le n \le 100$そして$0 \le a_i, m \le 10^6$で計算を安全に実行できます。$O(n \log n)$または$O(n^2)$テストケースごとに、$100^2$操作は許容されます。 すべてを試みる素朴な解決策$n!$順列は不可能です。 監視すべきエッジケースには、ゼロの配列、単一要素を含む配列、または最小要素よりも小さいターゲットが含まれます。 たとえば、配列の場合$[0, 0, 0]$そしてターゲット$1$、正しい出力は「NO」です。 配列が$[5]$そしてターゲットは$5$、答えは「YES」です。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$n!$順列を作成し、それぞれの合計を計算します。 正しいですが、これは非現実的です。$n = 10$、順列の数は 300 万を超えます。 

重要な観察は、合計が配列要素内で線形であることです。 式を書き直すと次のようになります。$$\sum_{i=1}^{n}\sum_{j=i}^{n} \frac{a_j}{j} = \sum_{j=1}^{n} a_j \sum_{i=1}^{j} \frac{1}{j} = \sum_{j=1}^{n} a_j$$以来$\sum_{i=1}^{j} \frac{1}{j} = 1$。 したがって、加重合計は配列要素の単純な合計になります。 この顕著な単純化は、並べ替えても合計が不変であることを意味します。 次に、問題は、すべての要素の合計がターゲットと等しいかどうかを確認することになります。 この洞察により、一見複雑な組み合わせ問題が単純な算術チェックに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | O(n! * n) | O(n) | 遅すぎる |
 | サムチェック（最適） | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして$m$、次に長さの配列を読み取ります$n$。 
3. すべての配列要素の合計を計算します。 
4. この合計を次と比較します。$m$。 それらが等しい場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

これが機能する理由: 問題で指定された数式は、配列要素の順序に関係なく、配列要素の合計に折りたたまれます。 したがって、合計がターゲットと一致する場合、どの順列も条件を自明に満たします。 そうでない場合、どの順列も条件を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        if sum(a) == m:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、入力を効率的に読み取ります。`sys.stdin.readline`、線形時間で合計を計算し、それをターゲットと直接比較します。 テスト ケース間での再利用を避けるために、変数のスコープはループ内に設定されます。 すべての数値が整数であるため、サム チェックは正確であり、浮動小数点の問題が回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * t) | 各テスト ケースの要素の合計は最大 100 個です。 |
 | スペース | O(n) | テスト ケースごとの配列ストレージ。 |

 と$t \le 100$そして$n \le 100$、最悪の場合の操作は 10,000 であり、十分に制限内です。

 ## 特殊なケース

 最小のエッジ ケースは、長さ 1 の配列です。 単一の要素がターゲットと一致する必要があるため、サム チェックはこれを簡単に処理します。 すべてゼロの配列はターゲットがゼロである限り機能し、順序を無視してすべての要素の合計が正確に重要であるため、ゼロが混在する配列は正しく動作します。 すべての演算は整数の合計であるため、浮動小数点演算は必要ありません。
