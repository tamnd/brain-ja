 ## 解決策
 ## 問題の理解

 配列が与えられると、2 つの厳密なグローバル操作だけを使用して配列を変更できます。 1 回の操作で配列が 1 位置右に回転し、最後の要素が前に移動します。 もう 1 つの操作は配列全体を反転します。 目標は、できるだけ少ない操作を使用して配列を非減少シーケンスに変換するか、これらの操作シーケンスでは並べ替えられた配列を実現できないと判断することです。 

重要な点は、どちらの操作も要素のマルチセットを変更しないため、並べ替えは位置を並べ替えるだけであるということです。 ただし、許可された移動では、任意の順列が生成されません。 元の配列またはその逆の回転である配列のみを生成します。 これはすでに強い構造的制限を示唆しています。到達可能な状態は最大 2n 個の異なる構成を形成します。 

制約は大きく、テスト ケースの合計 n は最大 200,000 です。一連の操作をシミュレートしたり、状態全体にわたって BFS を試行したりするソリューションは、直ちに不可能になります。 最悪の場合、テスト ケースあたり O(n^2) でも遅すぎます。 

配列がすでにソートされているか、反転後にソートされる場合、微妙なエッジ ケースが発生します。 もう 1 つの注意が必要な状況は、すべての要素が等しい場合です。 この場合、どちらの操作でも配列の状態は変更されますが、配列は常にソートされており、答えは 0 でなければなりません。 

より危険な失敗例は、すべての配列を回転だけでソートできると仮定することです。 たとえば、[3, 1, 2] には並べ替えを行う回転がありません。また、[2, 1, 3] になるため反転も役に立ちません。これも非降順に循環的に並べ替えることができません。 

## アプローチ

 ブルートフォースのアイデアは、シフト操作とリバース操作を繰り返し適用することで、到達可能なすべての状態を探索することです。 各状態はさらに 2 つ生成できるため、最大 2n 個のノードを持つグラフになりますが、状態間の遷移で複雑さが軽減されることは保証されません。 実際、一連の操作を明示的に扱うと、検索スペースは操作の長さに応じて指数関数的に増加します。 

重要な構造的洞察は、シフトによって周期的な回転が生成され、トラバース方向が反転するということです。 したがって、到達可能な配列はすべて、元の配列の回転か、反転された配列の回転のいずれかになります。 どちらの操作も周期的な回転と反転まで隣接構造を保持するため、他の順列は不可能です。 

したがって、問題は線形配列のすべての回転とその反転バージョンをチェックすることに帰着します。 候補の配置ごとに、ソートされているかどうかを確認します。 そうであれば、それに到達するまでに何回のシフトが必要かを計算し、オプションで 1 つの逆演算を使用することもできます。 

答えは次の中で最小のものです。 

- 元の配列の回転
 - 反転された配列の回転に 1 つの反転コストを加えたもの

 回転を行わずにソートされた配列が得られる場合、答えは -1 です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース状態検索 | O(2^n) | O(2^n) | 遅すぎる |
 | 回転チェック | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を 2 つの配列 (元の配列と反転した配列) の巡回シフトのチェックに変換します。

1. 配列をそれ自体と連結します。 これにより、すべての回転を長さ n の連続した部分配列として表すことができます。 これにより、明示的な回転シミュレーションが回避されます。 
2. この 2 倍の配列内のサイズ n のウィンドウが非降順でソートされているかどうかを事前計算します。 これは、ウィンドウ内の隣接する反転の数を追跡することによって行われます。 
3. 元の配列の場合、サイズ n のウィンドウを 2 倍の配列全体にスライドさせ、有効なソートされた回転を検出します。 それぞれの有効なウィンドウは回転に対応します。 必要なシフト数は、そのウィンドウの開始インデックスによって決まります。 
4. 反転したアレイに対して同じプロセスを繰り返します。 これは、回転前に 1 回だけ反転操作を必要とするソリューションを考慮しています。 
5. 答えは、すべての有効な構成の中での最小操作数です。 配列がすでにソートされている場合、答えはゼロです。 

### なぜ効果があるのか

 許可された操作は、配列インデックスの二面体グループを正確に生成します。回転は循環グループを形成し、反転は反射を導入します。 到達可能な構成は、元のシーケンスの回転、またはその逆バージョンの回転のいずれかです。 したがって、これら 2 つのファミリーを列挙することですべての可能性がカバーされ、それらの間の並べ替えをチェックすることで最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    
    def best(arr):
        b = arr + arr
        
        bad = 0
        for i in range(n - 1):
            if b[i] > b[i + 1]:
                bad += 1
        
        res = float('inf')
        
        for i in range(n):
            if i > 0:
                if b[i - 1] > b[i]:
                    bad -= 1
                if b[i + n - 2] > b[i + n - 1]:
                    bad += 1
            
            if bad == 0:
                res = min(res, i)
        
        return res
    
    ans = best(a)
    ans_rev = best(a[::-1])
    
    if ans == float('inf') and ans_rev == float('inf'):
        return -1
    
    res = float('inf')
    if ans != float('inf'):
        res = min(res, ans)
    if ans_rev != float('inf'):
        res = min(res, ans_rev + 1)
    
    return res

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```機能`best`固定方向からソートされた配列を取得するために必要なシフトの最小数を計算します。 2 倍化のトリックにより、すべての回転が長さ n のウィンドウに対応することが保証されます。 

毎回セグメント全体を再チェックするのではなく、ウィンドウ内の「不正な隣接ペア」を追跡します。 ウィンドウが 1 位置スライドすると、2 つの隣接関係のみが変化するため、O(1) でカウントを更新します。 

最終的な答えは、元の配列を直接回転する場合と、最初に反転してから回転する場合の 2 つのシナリオを比較します。 反転は1回の作戦コストとしてカウントされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []

        def best(a):
            n = len(a)
            b = a + a
            bad = 0
            for i in range(n - 1):
                if b[i] > b[i + 1]:
                    bad += 1
            res = float('inf')
            for i in range(n):
                if i > 0:
                    if b[i - 1] > b[i]:
                        bad -= 1
                    if b[i + n - 2] > b[i + n - 1]:
                        bad += 1
                if bad == 0:
                    res = min(res, i)
            return res

        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            x = best(a)
            y = best(a[::-1])
            if x == float('inf') and y == float('inf'):
                out.append("-1")
            else:
                ans = min(x if x != float('inf') else 10**9,
                          (y + 1) if y != float('inf') else 10**9)
                out.append(str(ans))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 A subtle case is when the array is already non-decreasing but not strictly increasing. The algorithm must still treat it as valid without performing any operations. Since the sliding window detects a fully sorted window at index zero, it correctly returns zero.

 Another edge case occurs when multiple equal values create many valid rotations. スライディング ウィンドウのアプローチは、等価性が「悪い」反転に寄与しないため、引き続き機能し、すべての等しいセグメントは常にソートされていると見なされます。
