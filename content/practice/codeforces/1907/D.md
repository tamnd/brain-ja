 ## 解決策
 ## 問題の理解

 数直線上に一連の間隔が与えられ、それらを横切る制約された移動プロセスをシミュレートします。 プレイヤーは位置 0 から開始します。順番にインターバルごとに、プレイヤーは 1 つの移動を行い、その移動の後、対応するインターバル内に着地する必要があります。 移動ルールでは、各ステップで最大距離のジャンプが許可されます。`k`、そのような最小のものを選択するように求められます`k`これにより、すべての間隔制約を順番に満たすことが可能になります。 

したがって、個々のポイントについて考えるのではなく、各ステップの後にプレーヤーがどこにいる可能性があるかを考える方が良いでしょう。 最初の間隔を処理した後、到達可能な位置のセットが存在し、後続の各間隔の後、このセットは 2 つの制約に基づいて展開されます: 以前の到達可能な範囲は最大で 1 倍拡大されます。`k`、その後、現在の間隔にクリップされます。 

出力は最小の整数です`k`このプロセスでは空のセットが生成されることはありません。つまり、各セグメントの後には常に少なくとも 1 つの有効な位置が存在します。 

制約は大きく、合計すると`n`最大 2e5 のテスト ケースにわたって。 これにより、複数の候補値を試行するシミュレーションが除外されます。`k`到達可能性を最初から再計算します。 二分探索`k`線形チェックに対数係数を乗算しますが、これは境界線ではありますが不要です。 この問題の構造により、テスト ケースごとに線形時間での直接的な貪欲な計算が可能になります。 

単純な間違いは、固定のプロセスをシミュレートすることです。`k`ただし、範囲ではなく単一の位置のみを追跡します。 たとえば、間隔が次の場合、`[1,5]`それから`[10,12]`単一位置アプローチでは、貪欲に 1 から 10 までジャンプしようとし、内部に複数の選択肢があることを認識できない可能性があります。`[1,5]`案件。 もう 1 つのよくある失敗は、各ステップの後、1 つのエンドポイントだけではなく、到達可能な間隔全体が重要であることを忘れていることです。 

## アプローチ

 強引なアイデアは候補者を固定することです`k`and simulate all possible positions. 各セグメントの後、到達可能なすべての位置から、距離内の任意の点にジャンプできます。`k`、次の区間と交差します。 これは、連続的に到達可能なセグメントを維持することに相当しますが、状態のセットまたはリストとして単純に実行すると、各ステップが無限に多くの点に分岐するため、指数関数的に爆発的に増加します。 

重要な観察は、到達可能なセットが常に連続した間隔であるということです。 ステップの場合`i`私たちはどこにでも立つことができます`[L, R]`、制限付きで 1 回移動した後`k`、正確に到達できます`[L-k, R+k]`。 次のセグメントとの交差`[l_i, r_i]`再度間隔をあけます。 したがって、ステップごとに 1 つの間隔だけを追跡します。 

これにより、特定の間隔の伝播を維持するという問題が軽減されます。`k`。 The remaining task is to find the smallest`k`これにより、どのステップでもこの間隔が空になることがなくなります。 

二分探索の代わりに`k`、直接導出できます。 各ステップで、以前の到達可能な間隔を現在のセグメントに接続するためにどの程度の拡張が必要かを確認します。 現在のセグメントが拡張された前の間隔と重なる場合、追加のコストは必要ありません。 それ以外の場合は、ギャップによって必要な最小限のジャンプが決まります。

 ## アルゴリズムのチュートリアル

 現在の実行可能な間隔を維持します`[L, R]`、各セグメントの処理後にプレーヤーが取り得るすべてのポジションを表します。 

1. 間隔を次のように初期化します。`[0, 0]`。 This represents the starting point before any movement.
 2. 最初のセグメントの場合`[l1, r1]`、0 から到達する必要があります。必要な最小限のジャンプは、0 がこのセグメントからどのくらい離れているかによって決まります。 0 がその中にある場合、移動は必要ありません。 それ以外の場合は、最も近い境界にジャンプする必要があります。 
3. 次のセグメントごとに`[li, ri]`、現在の間隔かどうかを考慮します。`[L, R]`すでに重なっています。 そうなった場合は、交差点内の適切な点を選択することでオーバーラップ内にとどまることができるため、新たな距離は必要ありません。 
4. 重なりがなければ隙間ができます。 もし`R < li`、最も近い到達可能なポイントは`R`そして私たちはそこにジャンプしなければなりません`li`、少なくとも必要です`li - R`。 もし`ri < L`、下にジャンプする必要があります。`L - ri`。 
5. すべてのステップにわたって必要なジャンプの最大値を累積します。`k`最悪の移行をサポートする必要があります。 
6. 移動の制約を考慮した後、拡張されたリーチを現在のセグメントと交差させることによって、到達可能な間隔を更新します。 
7. 最終的な答えは、このプロセス中に発生する最大ギャップです。 

重要な考え方は、各ステップが規模の制約に寄与するということです。`k`連続する実行可能な間隔の間の距離を埋める必要があります。 

### なぜ効果があるのか

 すべてのステップで、到達可能なセットは連続間隔によって完全に記述されます。 進歩を妨げる唯一の障害は、連続する 2 つのインターバルがギャップによって区切られている場合です。 前の間隔内の中間点は、現在のセグメント境界までの距離という点で等しいため、そのギャップのサイズは、まさに 1 回の移動でそれらを接続するために必要な最小ジャンプとなります。 後のステップは実現可能性をさらに制限するだけで、すでに満たされている遷移の要件を減らすことはないため、すべての遷移にわたる最大ギャップは有効な最小値になります。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        l0, r0 = map(int, input().split())
        L, R = l0, r0
        
        # distance needed from start 0
        if 0 < L:
            ans = L
        elif 0 > R:
            ans = -R
        else:
            ans = 0
        
        for _ in range(1, n):
            l, r = map(int, input().split())
            
            if R < l:
                ans = max(ans, l - R)
            elif r < L:
                ans = max(ans, L - r)
            
            L = max(L, l)
            R = min(R, r)
            
            if L > R:
                L, R = l, r
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは、現在の実行可能な間隔を追跡します。`[L, R]`。 各セグメントを読み取った後、まず現在の間隔と次のセグメントの間のギャップを計算します。 それらが重複しない場合、そのギャップにより、下限候補として答えが更新されます。`k`。 

アップデート`L = max(L, l)`そして`R = min(R, r)`は、実現可能性を到達可能な位置と現在のセグメントの交点に制限することを表します。 この交差点が空になると、コードは現在のセグメントにリセットされます。これは、プレーヤーが十分なサイズの有効なジャンプの後、常にセグメント内のどこにでも着地できることを反映しています。 

微妙な点は、開始位置が 0 に固定されているため、最初のセグメントを残りのセグメントとは別に処理することです。

 ## 特殊なケース

 重要なエッジ ケースは、最初の間隔にすでに 0 が含まれている場合です。この場合、最初のセグメント内に到達するためにジャンプする必要がないため、初期要件は 0 です。 

もう 1 つのケースは、間隔が厳密に増加し、ばらばらになっている場合です。 例えば`[0,1] → [100,101] → [0,1]`。 アルゴリズムは、からの移行時に発生する最大のギャップを正確に記録します。`[0,1]`に`[100,101]`、生産`99`。 

微妙なシナリオとしては、間隔が部分的に重なっているにもかかわらず、片側に隙間が生じる場合があります。 例えば`[0,10] → [20,30] → [15,25]`。 到達可能な間隔は縮小して移動し、ギャップは境界を使用して計算されます。`R`に対して`20`、正しい必要なジャンプを生成します。`10`。
