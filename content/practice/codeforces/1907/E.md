 ## 解決策
 ## 問題の理解

 非負整数の順序付きトリプルを数える必要があります$(a,b,c)$正確にその合計は$n$。 珍しい部分は、桁の合計条件です。$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)=\text{digsum}(n).$$トリプルは、両方の条件が満たされる場合にのみカウントされます。 順番が大事なので、$(1,2,3)$そして$(3,2,1)$異なるトリプルです。 

の値$n$と同じ大きさにすることができます$10^7$、そしてそれがあるかもしれません$10^4$テストケース。 可能な値を反復するアルゴリズム$a$、$b$、 そして$c$すぐには無理です。 すべてのペアを反復しても$(a,b)$前後が必要になります$10^{14}$最悪の場合の運用。 

キーの制約はサイズではありません$n$、しかし、という事実$n$10 進数は最大 8 桁です。 これは、答えが数値そのものではなく、10 進表現の桁ごとに依存することを強く示唆しています。 

単純な解決策を簡単に誤解させる可能性のある特殊なケースがいくつかあります。 

のために$n=0$、唯一の有効なトリプルは、$(0,0,0)$。 答えは$1$。 すべての桁が複数の可能性を考慮した数式は、誤ってより大きな値を返します。 

のために$n=10$、有効なトリプルはすべての解ではありません。$a+b+c=10$。 例えば、$(5,5,0)$桁の合計がある$5+5+0=10$、 その間$\text{digsum}(10)=1$, したがって無効です。 キャリー操作が重要です。 

のために$n=10000000$、ほとんどの桁はゼロです。 不注意な数字 DP により、誤ってポジション間のキャリーが許可され、多くの余分な構成がカウントされる可能性があります。 正解はただ、$3$、値全体を 3 つの数値のうちの 1 つに正確に配置することに対応します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルを列挙します。$(a,b,c)$と$a+b+c=n$, 次に、桁の合計の条件を確認します。 以来$c$によって決定されます$a$そして$b$、これにはおおよその必要があります$$\sum_{a=0}^{n}(n-a+1)=O(n^2)$$州。 

のために$n=10^7$、それはその辺です$10^{14}$繰り返し、完全に不可能です。 

重要な観察は、10 進加算の標準的な性質から得られます。 キャリーが発生するたびに、桁の合計の合計は の倍数で減少します。$9$。 

負でない整数の場合、$$\text{digsum}(x)+\text{digsum}(y)-\text{digsum}(x+y)$$等しい$9$加算中に生成されるキャリーの数の倍。 

これを繰り返し応用すると、$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)-\text{digsum}(n)$$は$9$3 つの数値を加算するときに発生するキャリーの合計数を掛けます。 

私たちの条件では、この差が正確にゼロであることが必要です。 キャリーは左側を大きくすることしかできないため、唯一の可能性は **どこにもキャリーが発生しない** ということです。 

それは問題を完全に変えます。 私たちは数字について考える代わりに、数字について考えます。 

次の数字があるとします$n$は$d$。 桁上げは許可されていないため、対応する数字は$x,y,z$の$a,b,c$満たさなければなりません$$x+y+z=d.$$異なる桁位置は独立します。 有効なトリプルの数は、単純に、各桁の桁トリプルの数の積です。$n$。 

固定桁の場合$d$の非負の解の数が必要です。$$x+y+z=d.$$以来$d\le 9$、桁の境界$x,y,z\le 9$自動的に満たされます。 

星と棒によって、$$\#(x+y+z=d)=\binom{d+2}{2}.$$各桁は独立して寄与するため、最終的な答えは次のようになります。$$\prod_{\text{digits } d \text{ of } n} \binom{d+2}{2}.$$| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. 値を事前計算する$$f[d]=\binom{d+2}{2}$$数字の場合$d=0$を通して$9$。 
2. テスト ケースごとに、次のように変換します。$n$10 進表現に変換します。 
3. 答えを次のように初期化します。$1$。 
4. すべての桁を処理する$d$の$n$。 
5. 答えを乗算します$f[d]$。 

これはすべての桁のトリプルをカウントします$(x,y,z)$その合計が等しい$d$その位置で。 
6. すべての桁が処理された後、積を出力します。 

### なぜ効果があるのか

 桁和条件は、加算中に桁上げが発生しないことと同じです。$a+b+c=n$。 キャリーが1つでも出れば数量は$$\text{digsum}(a)+\text{digsum}(b)+\text{digsum}(c)$$厳密にはより大きくなります$\text{digsum}(n)$の倍数で$9$。 

キャリーがない場合、各小数点位置は独立しています。 桁位置で、$n$数字が含まれています$d$、のために選択された数字$a$、$b$、 そして$c$満足するだけでいい$x+y+z=d$。 このようなトリプルの数は$\binom{d+2}{2}$。 異なる位置での選択は相互作用しないため、乗算の原理によりすべての桁にわたる積が得られます。 したがって、すべての有効なトリプルは 1 回だけカウントされ、カウントされたすべての構成が有効なトリプルを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# f[d] = C(d + 2, 2)
ways = [(d + 2) * (d + 1) // 2 for d in range(10)]

t = int(input())

for _ in range(t):
    n = input().strip()

    ans = 1
    for ch in n:
        ans *= ways[ord(ch) - ord('0')]

    print(ans)
```配列`ways`の非負の解の数を格納します。$x+y+z=d$すべての桁ごとに$d$。 以来$d\le 9$、星と棒の公式が直接適用されます。 

各テスト ケースでは、数値を文字列として読み取ります。 これにより、除算で繰り返し数字を抽出することがなくなり、最大の値を自然に処理できます。$10^7$。 

答えは次から始まります$1$。 各桁は独立した乗算係数に寄与するため、次のように乗算します。`ways[d]`すべての桁ごとに。 

Python の整数は自動的に任意のサイズに拡張されます。これは、次のような答えが得られるため便利です。$9999999$32 ビットおよび 64 ビットの制限を超えています。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    ways = [(d + 2) * (d + 1) // 2 for d in range(10)]

    t = int(input())
    out = []

    for _ in range(t):
        n = input().strip()
        ans = 1
        for ch in n:
            ans *= ways[int(ch)]
        out.append(str(ans))

    return "\n".join(out)

次の入力を考えてみましょう。```
1

```数字は$1$そして$0$。 彼らの貢献は、$3$そして$1$。$$3 \times 1 = 3.$$有効なトリプルは正確に次のとおりです$(10,0,0)$、$(0,10,0)$、 そして$(0,0,10)$。 次のようなトリプル$(5,5,0)$単位の桁にキャリーが発生し、桁の合計条件に違反します。 アルゴリズムはキャリーなしの数字の割り当てのみをカウントするため、これを自動的に除外します。

```桁の貢献度は次のとおりです。$$3 \times 1 \times 1 \times 1 \times 1 \times 1 \times 1 \times 1 = 3.$$先頭を含めることができる数字は 1 つだけです$1$、他の 2 つはゼロでなければなりません。 アルゴリズムは正しく返します$3$。
