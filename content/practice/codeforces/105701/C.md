 ## 解決策
 ## 問題の理解

 直線に沿って配置された一連の木が与えられています。 各ツリーには固定の位置と高さがあります。 木は一点として立っていることもあれば、切り取られて完全に左または右に倒れ、高さによって長さが決まる部分になることもあります。 

重要な制限は、倒木が既に占有されている位置と重なってはいけないということです。 最初は、元のツリー位置のみが占有されます。 木が倒れると、その木がカバーするセグメント全体が占有されることになり、今後の決定は以前に占有されていたすべての点を尊重する必要があります。 

目標は、これらの制約の下でどれだけの木を伐採できるかを最大化することです。 

入力サイズは最大 100,000 ツリーで、座標と高さは 10^9 までの大きさになります。 これにより、線形時間で以前のすべてのツリーに対する間隔オーバーラップ チェックを使用して各カットを素朴にシミュレートしようとするソリューションは即座に除外されます。これは、最悪の場合 O(n²) に低下し、明らかに時間制限を超えるためです。 線形か、最悪 O(n log n) を目指す必要がありますが、位置によってソートされる入力の構造は、貪欲なスイープで十分である可能性が高いことを示唆しています。 

微妙な点は、木の伐採はその近隣だけでなく、左右の広い範囲の空間に影響を与える可能性があるということです。 すべての占有セグメントを保存し、交差をチェックする単純な間隔ブックキーピングのアプローチは、重複するカットの長いチェーンでは失敗します。 

いくつかの特殊なケースは、素朴な考え方の危険性を示しています。 

高さが 10 のような大きな位置 1、2、3、4 など、すべての木が非常に近い場合、最適な交互戦略が存在する場合でも、あまりにも積極的に早期に切断すると、その後のすべての切断がブロックされる可能性があります。 方向性を考慮せず、常に可能な限りカットする貪欲な人は、ここで失敗する可能性があります。 

高さが 1 の位置 1、2、3、4 など、高さが非常に小さい場合は、すべてがカットされる可能性があり、どのアルゴリズムも、有効なカットを誤ってブロックすることなく、狭い間隔を正しく処理する必要があります。 

大きなギャップ (位置 1、2、1000、1001 など) がある場合、ギャップの周囲のツリーはほぼ独立して動作し、正しいソリューションではギャップ全体のローカル制約をリセットする必要があります。 

主な困難は、幾何学的精度ではなく、木が左に倒れるべきか、右に倒れるべきか、それとも留まるべきかを左から右に局所的に決定することです。 

## アプローチ

 この大胆なアイデアは、すべての木を検討し、3 つの可能性すべてを試してみることです。つまり、木を立てたままにしておく、左に切る、または右に切るということです。 各選択の後、占有点または間隔のグローバル セットを維持し、再帰的に続行します。 これは、すべての有効な構成を調査するので正しいですが、各ツリーが最大 3 つの状態に分岐し、O(3^n) 個の可能性があるため、指数関数的になります。 

無効なオーバーラップを早期に削除したとしても、結局は区間交差を繰り返しチェックすることになり、各チェックに O(n) のコストがかかる可能性があるため、分岐を考慮する前でさえ実質的な最悪のケースは O(n²) 以上になります。 

重要な観察は、ツリーがすでに位置によってソートされており、制約は 1 次元で純粋に幾何学的であるということです。 これは、ツリーを左から右に処理したら、左側にある以前に占有されていた最も近い境界だけを気にする必要があることを意味します。 同様に、右側の木を切るかどうかを決定するときは、次の木の元の位置を妨げないことを確認するだけで済みます。 

これは、(おそらく左側の木を切った後) 左側にあった最後の位置を維持し、次の木の位置を先読みして、現在の木を安全に右側に切ることができるかどうかを判断するという貪欲な戦略につながります。 それぞれの決定はローカルになり、隣接する隣接地と現在占有されている境界にのみ依存します。

各ステップで、現在のツリーを可能な限り積極的に切断しようとします。以前に占有されていた位置と衝突しない場合は左に切断することを優先し、次のツリーに到達しない場合は右に切断することを試み、そうでない場合はそのままにしておきます。 右に切ると隣の木が邪魔になる可能性があるため、この順序は非常に重要であり、十分なスペースを確保する必要があります。

 ## アルゴリズムのチュートリアル

 1. ソートは入力順序によってすでに保証されているため、ツリーを並べ替えずに左から右に処理します。 
2. 変数を維持する`pos`現在地上で占有されている右端の点を表します。 まだ何もカットされていないため、最初は負の無限大です。 
3. それぞれの木について`i`、優先順位の高い順に 3 つの可能性を検討します。 まずは左にカットしてみます。 これは、セグメントが`[x_i - h_i, x_i]`厳密にその後に始まります`pos`。 その場合は、左にカットして更新します`pos`に`x_i`。 

これが機能するのは、左切断は木の位置の左側のスペースにのみ影響するため、将来の木には干渉しないからです。 
4. 左に切ることができない場合は、木を立てたままにしてください。 これは単一点のみを占有するため、常に安全です。`x_i`と競合しないことを確認できます。`pos`もし`x_i > pos`。 

立っていることさえ不可能な場合、木は実質的にブロックされ、答えには何も貢献しません。 
5. それ以外の場合は、右側にカットしてみてください。 これは、セグメントが`[x_i, x_i + h_i]`次の木の位置に到達しない`x_{i+1}`。 有効な場合は、適切に切り取って更新します`pos`に`x_i + h_i`。 

この条件が十分である理由は、将来のツリーは離散的な位置でのみ開始するため、次の開始点をカバーしない限り、将来の競合は発生しないためです。 
6. 左または右に関係なく、成功したすべてのカット操作を 1 つの処理されたツリーとしてカウントします。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`pos`always represents the furthest right point that is already occupied by some previously processed tree. Every decision ensures that newly created segments do not intersect this boundary or the next critical anchor point in the sorted order.

 ツリーは位置の昇順に処理されるため、重複は直前の占有領域または直前の未処理のツリー位置でのみ発生します。 There is no need to track earlier trees individually, since their influence is already absorbed into`pos`。 これにより、グローバルな幾何学的制約がローカルな間隔の実行可能性チェックに縮小され、受け入れられたすべてのカットがグローバルな非オーバーラップを維持することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
trees = [tuple(map(int, input().split())) for _ in range(n)]

ans = 0

# last occupied coordinate
pos = -10**30

for i in range(n):
    x, h = trees[i]

    # try cut left
    if x - h > pos:
        ans += 1
        pos = x
    # try stand
    elif x > pos:
        pos = x
    # try cut right
    elif i == n - 1 or x + h < trees[i + 1][0]:
        ans += 1
        pos = x + h
    else:
        pos = x

print(ans)
```コアの実装は、単一の境界変数を維持するかどうかにかかっています。`pos`。 各ツリーは順番に 1 回処理され、将来のツリーをブロックすることがないため、ロジックは最初に左カットの実現可能性をチェックします。一方、右カットは、次のツリーに対して必要かつ安全な場合にのみ使用されます。 

実装の微妙な詳細は、最後のツリーの処理です。`i == n - 1`次にブロックするツリーがないため、これが必要です。 これを忘れると、有効な最終カットが誤って拒否されることにつながります。 

もう 1 つの微妙な点は、左側のカット条件が厳密に不平等であることです。`x - h > pos`。 使用する`>=`位置は占有点と見なされるため、「重複なし」ルールに依然として違反しているセグメントの接触が誤って許可されてしまいます。

 ## 特殊なケース

 すべてのツリーが非常に近く、高さが高い場合、次のツリー位置が展開を即座にブロックするため、アルゴリズムは無効な右カットを正しく回避します。 各反復は左のカットまたはスタンディングのいずれかに戻り、セグメントの重複が発生しないようにします。 

最後のツリーでは、次のアンカーが存在しないということは、右のカットが常に独立して評価されることを意味し、条件は`i == n - 1`最後のツリーが存在しない近傍によって誤って制限されないことを保証します。 

木と木の間に大きな隙間がある場合、`pos`切り口や林分が境界を局所的にのみ前方に移動させるため、境界は自然にリセットされ、前のセグメントからの干渉なしに後の木を独立して処理できるようになります。
