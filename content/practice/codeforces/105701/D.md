 ## 解決策
 ## 問題の理解

 すべてのエッジが非負の重みを持つ無向接続グラフが与えられます。 「ジャーニー」とは、ノード 1 から始まりノード k で終わる任意のウォークであり、同じエッジを 2 回再利用することは許可されていませんが、頂点を再訪することは問題ありません。 

このようなウォークでは、そこで使用されているすべてのエッジの重みを調べます。 ウォークは 2 つの特別な値、つまりエッジ間の最小の重みとエッジ間の最大の重みに寄与します。 歩行のコストは、これら 2 つの極端な値の合計です。 

すべての頂点 k について、1 から k までのすべての有効なウォークにわたって可能な最小コストが必要です。 

グラフは、n または m での 2 次または 3 次さえも直ちに不可能になるほど大きくなる可能性があります。 最大 300,000 個の頂点とエッジを使用すると、およそ O(m log m) または O(m α(n)) 時間で作業できると予想されます。 ウォークの数は指数関数的であるため、すべての可能なパスまたはエッジのすべてのサブセットを探索しようとするソリューションは失敗します。 

微妙な問題は、ウォークが頂点の点で単純なパスである必要がないため、構造が直ちに木の問題になるわけではないことです。 ただし、エッジが繰り返されないという制限により、私たちはすでに、任意のウォークではなく、複数の構造にまたがる観点から考えるようになりました。 

よくある落とし穴は、最短経路スタイルのリラクゼーションが機能すると思い込んでしまうことです。 コストは追加的な寄与ではなく、パスに沿った大域的な極値に依存するため、そうではありません。 もう 1 つの落とし穴は、エッジの重みの最小値と最大値を個別に最適化できると想定していることです。 これらは、両方が同じウォークに出現する必要があるという要件によって結合されます。 

## アプローチ

 直接的なアプローチでは、1 から k までのすべての可能なウォークを列挙し、確認された最小および最大のエッジの重みを追跡し、最良の結果を取得します。 繰り返されるエッジを削除したとしても、密なグラフでは明確なエッジ単純ウォークの数は依然として指数関数的であるため、これはすぐに実行不可能になります。 

2 番目の単純なアイデアは、最小エッジ重み x と最大エッジ重み y を固定し、1 と k を結ぶ区間 [x, y] 内の重みを持つエッジのみを使用するパスが存在するかどうかを確認することです。 そのようなパスが存在する場合は、x + y を最小化することを試みることができます。 これは原理的には正しいですが、すべての O(m²) 間隔の接続をチェックするのは遅すぎます。 

重要な構造的観察は、接続性の問題に対して、サイクルは代替ルートを提供する以外には役に立たないということです。 どのウォークも、発生する重みの範囲を増やすことなく、使用されるエッジのスパニング ツリーに圧縮できます。 これは、グラフの本質的な動作がスパニング ツリー構造によって捕捉されていることを示唆しています。 

すべてのスパニング ツリーの中で、ここで最も役立つのは最大スパニング ツリーです。 その理由は、高重量の接続を可能な限り維持し、パス上のボトルネック エッジを可能な限り大きくするためです。 このツリーに限定すると、2 つの頂点間のパスはすべて一意になり、そのパス上の最小エッジと最大エッジが固定されます。 

これにより、問題は、グラフ内の任意のウォークの検索から、クエリ ノードごとにツリー内の単一のパスの評価へと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 散歩を列挙する | 指数 | O(m) | 遅すぎる |
 | インターバル接続チェック | O(m3 log m) | O(m) | 遅すぎる |
 | スパニング ツリー + パス クエリの最大数 | O(m log m + n log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのエッジを重みの降順にソートし、DSU 構造を使用して最大スパニング ツリーを構築します。 2 つのコンポーネントを接続するたびに、利用可能な最も高いエッジを取得し、可能な限り最も強力な接続を最初に維持します。 
2. スパニング ツリーが構築されたら、任意の 2 つのノード u および v について、元のグラフ内のすべての有効なウォークが、それらの間のツリー パス上に存在するものを超えて重みの範囲を改善しないエッジの観点から表現できることを観察します。 
3. ツリーをノード 1 でルートし、最低共通祖先クエリ用に前処理します。 LCA とともに、各ノードのバイナリ リフティング テーブルを維持し、2 の累乗距離ごとにその祖先へのパス上の最小および最大のエッジ重みを保存します。 
4. 各ノード k について、LCA を使用して 1 から k までのパスを計算します。 パス上の最小エッジ重みは、1 および k から LCA までの両方の上向きセグメントにわたる最小値です。 最大エッジ重みも同様に計算されます。 
5. これら 2 つの値の合計をノード k の答えとして出力します。 

重要な計算ステップは、ツリー内のパス クエリが 2 つの上向きパスに分解されることです。各パスは、事前に計算されたジャンプ テーブルを使用して対数時間で応答できます。 

### なぜ効果があるのか

 最大スパニング ツリーでは、より小さな代替を導入する前に、任意の 2 つの頂点ができるだけ大きなエッジを使用して接続されるようにします。 より小さいエッジを使用して接続性を向上させようとする元のグラフ内のウォークは、パス上の可能な最小の最大エッジを減らすだけであり、極値の合計を改善することはありません。 これは、1 と k の間の最適なウォークが常に最大スパニング ツリーの一意のパスに対応し、最小エッジ値と最大エッジ値が接続性の制約の下でグローバルに最適であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

n, m = map(int, input().split())
edges = []
for i in range(m):
    u, v, w = map(int, input().split())
    edges.append((w, u-1, v-1))

edges.sort(reverse=True)

dsu = DSU(n)
g = [[] for _ in range(n)]

for w, u, v in edges:
    if dsu.union(u, v):
        g[u].append((v, w))
        g[v].append((u, w))

LOG = 20
up = [[-1]*n for _ in range(LOG)]
mx = [[0]*n for _ in range(LOG)]
mn = [[10**18]*n for _ in range(LOG)]
depth = [0]*n

def dfs(v, p):
    for to, w in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        up[0][to] = v
        mx[0][to] = w
        mn[0][to] = w
        dfs(to, v)

up[0][0] = 0
mx[0][0] = 0
mn[0][0] = 10**18
dfs(0, -1)

for j in range(1, LOG):
    for i in range(n):
        up[j][i] = up[j-1][up[j-1][i]]
        mx[j][i] = max(mx[j-1][i], mx[j-1][up[j-1][i]])
        mn[j][i] = min(mn[j-1][i], mn[j-1][up[j-1][i]])

def query(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    maxv = 0
    minv = 10**18

    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            maxv = max(maxv, mx[i][a])
            minv = min(minv, mn[i][a])
            a = up[i][a]

    if a == b:
        return minv + maxv

    for i in range(LOG-1, -1, -1):
        if up[i][a] != up[i][b]:
            maxv = max(maxv, mx[i][a], mx[i][b])
            minv = min(minv, mn[i][a], mn[i][b])
            a = up[i][a]
            b = up[i][b]

    maxv = max(maxv, mx[0][a], mx[0][b])
    minv = min(minv, mn[0][a], mn[0][b])

    return minv + maxv

res = []
for k in range(1, n):
    res.append(str(query(0, k)))

print("\n".join(res))
```DSU ステージは最大スパニング ツリーを構築し、最も関連性の高いエッジのみが残るようにします。 DFS は親とエッジの情報を初期化します。 バイナリ リフティング テーブルを使用すると、ルートからノードへのパス上の最小および最大のエッジ重みを効率的に抽出できます。 各クエリは、極値を追跡しながら両方のエンドポイントを LCA まで引き上げることにより、対数時間でノード k の結果を計算します。 

重要な一般的な実装の詳細は、最小テーブルを大きなセンチネル値で初期化し、上向きジャンプ中に最小値と最大値の両方を注意深く更新することです。1 つのセグメントが欠けていると正確性が損なわれるためです。 

## 実用的な例

 ノード 1 が重み 2 で 2 に接続し、ノード 1 が重み 1 で 3 に接続し、ノード 2 が重み 1 で 3 に接続する小さなグラフを考えてみましょう。 

最大スパニング ツリーを構築した後、エッジ 2-1 と 2-3 は接続を維持する最も強力な接続であるため、維持します。 

k = 3 の場合、ツリー内のパスは 3 → 2 → 1 になります。 

| ステップ | 現在のノード | マックスエッジ | 最小エッジ |
 | --- | --- | --- | --- |
 | 3 から 2 へリフト | 2 | 1 | 1 |
 | 2 から 1 へリフト | 1 | 2 | 1 |

 結果は 1 + 2 = 3 となります。 

ここで、1 から 4 のパスに沿って重みが 5、3、4 である、少し大きなチェーンを考えてみましょう。 

最大スパニング ツリーでは、最初にエッジ 5 と 4 が保持され、次に 3 が保持されます。 

k = 4の場合:

 | ステップ | リフト操作 | マックスエッジ | 最小エッジ |
 | --- | --- | --- | --- |
 | 4 から開始 | - | 0 | INF |
 | LCA に移動 | 蓄積する | 5 | 3 |

 答えは 3 + 5 = 8 です。 

これらのトレースは、ツリーが修正されると、計算がパス上の純粋な間隔集計に減少することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、複数のエッジが同じ重みを持つ場合です。 この状況でも、DSU は一貫してエッジを選択する必要がありますが、すべてのエッジがパスの極値に等しく寄与するため、有効なスパニング ツリーであればどれでも受け入れられます。 

元のグラフの最適なウォークが最小値または最大値を改善するためにサイクルを使用しようとする場合、別のエッジ ケースが発生します。 スパニング ツリーの定式化では、このようなサイクルはなくなりますが、ツリー パス上の極値はすでに達成可能な最良の間隔を捉えているため、結果は変わりません。 

最後のエッジ ケースは、ノード 1 が単一の高重みのバックボーンと多数の低重みのショートカットを介して残りのノードに接続されている偏ったグラフです。 最大スパニング ツリーはバックボーン エッジを優先し、低重みのエッジが誤って最大値を縮小したり、最小値を最適値を超えて人為的に下げたりすることを防ぎます。
