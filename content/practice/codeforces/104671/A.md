 ## 解決策
 ## 問題の理解

 成分の品質を表す数値のコレクションが与えられます。 これらの数値を正確に分割する必要があります`k`空ではないグループ。各数値は 1 つのグループにのみ属します。 各グループは料理を表します。 

料理のスコアは少し変わった方法で定義されます。 料理に値が含まれている場合、そのスコアは、その料理内のすべての値の合計に、その料理内の最大値を再度加えたものになります。 したがって、グループに要素がある場合、最大の要素は 2 回貢献し、他のすべての要素は 1 回貢献します。 

目標は、配列を分割する方法を選択することです。`k`すべての料理スコアの合計ができるだけ大きくなるようにグループ化します。 

主な問題は、グループ化の決定が、値がそのグループ内の最大値になるか、単なる通常の寄与値になるかに影響を与えることです。 すべてのグループがその最大値を再度加算するため、グループの構造は単なる値の合計よりも重要です。 

制約により、最大で`2 * 10^5`したがって、どのような解も線形または線形演算に近いものでなければなりません。 O(n^2) または O(nk) スタイルのグループ化戦略では、多くの可能なパーティションを反復したり、グループ数と割り当ての間の遷移を追跡したりする必要があるため、すぐに遅すぎます。 

すべての値が同一の場合、微妙なエッジケースが発生します。 たとえば、すべてが`a_i = 1`そして`k = n`、すべての要素は単独である必要があり、答えは次のようになります。`2n`。 素朴な直観では、このような均一なケースではグループ化はあまり重要ではないと思われるかもしれませんが、それでも「グループごとの追加最大値」により、各シングルトン グループに追加の値を提供することが強制されます。 

もう 1 つの重要なエッジケースは次のような場合です。`k = 1`。 この場合、すべての要素は 1 つのグループに属し、答えは単純です。`sum(a) + max(a)`。 分割が常に有益であると仮定するアルゴリズムは、ここでは失敗します。 

## アプローチ

 ブルートフォースソリューションでは、配列の可能なすべてのパーティションを試します。`k`グループ。 各パーティションについて、各グループの合計とその最大値を計算し、次にグループ全体の合計を計算します。 パーティションの数は組み合わせ的に増加し、基本的に第 2 種スターリング数によって支配されます。 この問題ではグループが連続している必要はないため、連続したパーティションに制限しても役に立ちません。 

いくつの要素がいくつのグループに割り当てられているかを追跡する動的プログラミング アプローチでさえ、プレフィックスとグループ数ごとに最大値を最適に分配する方法を知る必要があるため、すぐに実行不可能になります。 状態空間が大きすぎるため、`n`まで`2e5`。 

重要な洞察は、グループ内で価値を生み出すものを再解釈することです。 すべての要素は、すべてのグループの合計を通じて合計に 1 回だけ寄与します。 唯一の追加貢献は、各グループが最大 1 回追加するという事実から生じます。 

したがって、全体の最適化は、選択されたグループの最大値の合計を最大化することになります。 まさに`k`グループを選択する必要があります`k`それぞれのグループの最大値となる「グループリーダー」として機能する要素。 他のすべての要素は、グローバル合計を通じて 1 回だけ寄与します。 

これは、次の合計を最大化する必要があることを意味します。`k`最大値として機能するように選択された要素。 当然のことながら、私たちが望んでいるのは、`k`配列内の最大の要素は、可能な限り最大の追加寄与を与えるためです。 残り`n-k`要素は、一度だけ貢献する通常のメンバーになります。 

したがって、最終的な答えは、すべての要素の合計に要素の合計を加えたものになります。`k`最大の要素。

 | --- | --- | --- | --- |
 | ブルートフォース | 超指数関数的 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(1) から O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての要素の合計を計算します。 これは、グループ化構造に関係なく、すべての要素が正確に 1 回カウントされる基本寄与を表します。 
2. 配列を降順に並べ替えます。 これにより、グループ最大値の候補となる要素を簡単に特定できます。 
3. 最初のものを取る`k`このソート順からの要素。 これらは、グループ最大値として追加時間に寄与する要素の可能な最良の選択を表します。 
4. これらの合計を加算します`k`要素を基本合計に加算します。 これは、各グループの最大要素の追加の寄与を説明します。 
5. 結果の値を、最大達成可能な合計スコアとして出力します。 

特に最大のものを採用する理由`k`要素は、各グループが正確に 1 つの最大値に寄与し、選択された要素をグループの最大値として割り当てることを妨げる制限がないことです。 グループは任意であるため、選択した最大値を常に独自のグループに配置し、残りの要素を自由に配布できます。 

### なぜ効果があるのか

 各要素は少なくとも 1 回は寄与するため、ベースラインの合計は固定されます。 唯一の自由は、どの要素が最大値になるかを選択することです。 各グループは、その最大値に等しい追加の寄与を 1 つだけ追加するため、効果的に選択しています。`k`要素はその値に等しいボーナスを受け取ります。 このボーナスを個別に最大化することは、最大のボーナスを選択することに直接つながります。`k`グループ間に結合制約がないため、値が制限されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    total = sum(a)
    a.sort(reverse=True)
    
    bonus = sum(a[:k])
    print(total + bonus)

if __name__ == "__main__":
    solve()
```このソリューションはまず、すべての成分の合計を計算します。これは、避けられない基本寄与分です。 次に、配列を降順に並べ替えて、最大の要素に線形順序でアクセスできるようにします。 

重要なステップはトップを選択することです`k`追加の貢献源としての要素。 各グループは正確に 1 つの最大値を提供するため、これをグループごとに 1 つの「ボーナス スロット」を割り当て、それらのスロットを利用可能な最大値で埋めると考えることができ、結果が最大化されます。 

残りの要素はボーナス期間に影響を与えず、基本合計を通じてのみ寄与するため、並べ替え後は無視できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    total = sum(a)
    a.sort(reverse=True)
    bonus = sum(a[:k])
    return str(total + bonus)

assert run("6 2\n1 100 1 1 100 1\n") == str(sum([1,100,1,1,100,1]) + 200), "two large maxima"
assert run("3 3\n2 2 2\n") == "12", "all equal split"

 ## 特殊なケース

 いつ`k = n`、すべての要素は独自のグループを形成する必要があります。 アルゴリズムはすべての要素を最上位として選択します`k`, したがって、ボーナスは全額となり、`2 * sum(a)`これは、すべてのシングルトン グループがその要素を 2 回提供するという事実と一致します。 

いつ`k = 1`、アルゴリズムは最大の要素のみをボーナスとして選択します。`sum(a) + max(a)`。 これは、すべてを 1 つのグループに配置することに対応し、最大値が 1 つだけ追加されます。 

すべての値が等しい場合、次のようにします。`[x, x, x]`と`k = 2`、アルゴリズムは依然として任意の 2 つの要素をボーナス寄与者として選択し、`3x + 2x = 5x`。 すべてのグループの最大値が同一であるため、どのパーティションでも同じ構造が得られ、同点の状況で任意の最上位要素を選択することが正しいことが確認されます。
