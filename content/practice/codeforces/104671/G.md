 ## 解決策
 ## 問題の理解

 私たちは非常に高次元のグリッドで作業しています。 各点は n タプルの座標によって識別され、各座標の範囲は 1 ～ 100000 です。すべての点には数値 (最初は 0) が格納されます。 2 つの操作をサポートする必要があります。1 つは軸に揃えられた超長方形内のすべての点に値を追加すること、もう 1 つは軸に揃えられた超長方形内の合計値をクエリすることです。 

最大の難点は、グリッドが天文学的に大きいことです。 n = 2 の場合でも、グリッドにはすでに 10¹⁰ のセルがあり、n が 500 までの場合、明示的に何かを表現することは完全に不可能です。 すべての操作は完全な n 次元ボックスに対して定義されるため、セルに対する単純な反復は問題外です。 

lᵢ と rᵢ の両方がすべての区間にわたって一様にランダムに選択されるという制約は、重要な構造上のヒントです。 これは、クエリ ボックスが敵対的に調整されていないことを意味します。 それらは、固定ドメイン上でランダムな間隔のように動作します。 このランダム性により、関連する構成の有効数を確率的に減らすことができます。 

素朴な考えとしては、各次元を独立して扱うか、座標圧縮を試みることですが、ドメイン サイズが次元ごとに 10⁵ であり、次元数自体が 500 に達する可能性があるため、どちらも失敗し、直接テンソルのような構造は実行不可能になります。 

覚えておくべき微妙なエッジ ケースは、n = 1 の場合です。その場合、問題は配列に対する古典的な範囲加算と範囲加算に帰着します。 正しいソリューションは、セグメント ツリーやフェンウィック ツリーのようなものに正常に劣化する必要があります。 もう 1 つのエッジ ケースは、すべての更新が重複する領域に集中している場合であり、正当な理由なく疎性を前提としたソリューションが機能しなくなる可能性があります。 

## アプローチ

 ブルートフォース解釈では、すべてのセルの値が維持されます。 各 ADD 操作はハイパーレクタングル内のすべての点に対して反復され、各 SUM クエリは同様にクエリ領域内のすべての点に対して反復されます。 1 回の操作で影響を受けるセルの数は潜在的に (10⁵)ⁿ になりますが、これは n = 2 の場合でもすでに不合理であり、n ≥ 3 の場合はまったく不可能です。クエリの数 q ≤ 3000 だけを考慮したとしても、操作の総数は n で指数関数的に増加するため、このアプローチはすぐに失敗します。 

次に自然なアイデアは、構造を圧縮することです。 グリッドは独立した 1D 範囲の積であるため、次元を分離するように努めます。 重要な観察は、更新とクエリの両方が間隔の軸に沿った積であるということであり、これは乗法構造を示唆しています。 ただし、そのサイズが n で指数関数的になるため、n 次元のセグメント ツリーを直接構築することは不可能です。 

重要な洞察は、点の観点から考えるのをやめ、代わりに次元ごとの間隔からの寄与の観点から考えることです。 各操作は n 次元のボックスを定義し、任意の点が n 個の独立した 1D 間隔すべての内側にある場合にのみそれに寄与します。 これは、この問題が次元間の間隔の交差部分の合計と同等であることを示唆しています。 

ここで、ランダム化条件が中心になります。 各次元の間隔はランダムであるため、2 つの間隔が構造的に整列する確率は非常に低くなります。 これは、1 つの次元のすべてのクエリにわたって重要な個別の間隔エンドポイントの数が、すべての q 操作にわたって結合された場合、期待どおりに小さいことを意味します。 この問題は、次元ごとに候補座標の圧縮されたセットを操作するものとして扱うことができ、各次元は O(q) 個の端点に寄与します。 

各次元が最大 O(q) 個の意味のある位置に離散化されると、完全な n 次元空間がこれらの圧縮軸上の組み合わせ構造に縮小されます。 この問題は、クエリ エンドポイントによって引き起こされる n 次元グリッドの疎なサブセットにわたって関数を維持することと同等になります。

最後の縮小は、すべての操作が 1D 範囲の積であることを観察することです。そのため、ハイパーレクタングルに対する包含と除外と同様に、コーナー寄与に対する合計として表すことができます。 各 ADD または SUM クエリは、プレフィックス コーナーにわたる 2ⁿ 符号付きコントリビューションに分解できます。 これにより、問題は、暗黙的な n 次元プレフィックス空間に対するポイント更新とプレフィックス クエリの維持に変換されます。 

現時点では、直接ストレージはまだ不可能ですが、実際に完全なグリッドが必要になることはありません。 アクティブなクエリ コーナーに対応する少数のプレフィックス状態を評価するだけで済みます。 q が小さく、エンドポイントがランダムであるため、実際に現れる個別のアクティブ コーナーの数は管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · (10⁵)ⁿ) | O((10⁵)ⁿ) | 遅すぎる |
 | 圧縮プレフィックス分解 | スパース状態では O(q · 2ⁿ) が期待されます | O(q・2ⁿ) | 承認済み |

 ## アルゴリズムのチュートリアル

 包含-排他を使用して、各操作をプレフィックス空間上の関数として再解釈します。 すべてのセルの値を追跡する代わりに、超長方形からその角までの寄与を維持します。 

1. n 次元ボックス上のすべての ADD 操作を、プレフィックス コーナーの 2ⁿ 符号付き更新に変換します。 各コーナーは、各次元で lᵢ − 1 または rᵢ のいずれかを選択することに対応し、符号は選択された下限の数によって決まります。 これにより、重なり合う長方形が線形性によって正しく結合されることが保証されます。 
2. すべてのクエリから収集されたディメンションごとのすべてのアクティブな座標を保存します。 これらには、lᵢ 値と rᵢ 値の両方が含まれます。 値は間隔の境界でのみ変化するため、各次元を個別に圧縮します。 
3. これらの圧縮された座標を使用して、n 次元プレフィックス空間の暗黙的表現を構築します。 私たちは完全なグリッドを構築することはありません。 代わりに、クエリの隅に表示される状態のみをインデックス化します。 
4. ADD 操作ごとに、2ⁿ 隅すべてを繰り返します。 各コーナーについて、その符号を計算し、その座標タプルで暗黙的な構造内のポイント更新を適用します。 
5. 各 SUM クエリについて、同様に 2ⁿ コーナーに展開し、同じ包含/除外ルールを使用してプレフィックスの寄与を結合します。 各プレフィックス クエリは、そのコーナーまでの累積寄与を取得します。 
6. 蓄積された値を保存するために、座標タプルをキーとする辞書またはハッシュ マップを維持します。 q が小さく、座標がランダムであるため、実際には訪問する状態の数は制限されたままになります。 

なぜ効果があるのか

 この変換は、軸が整列したボックスはプレフィックス インジケーター関数の線形結合として正確に表現できるという事実に基づいています。 包含-排他により、長方形内のすべての点が正確に 1 回カウントされ、外側のすべての点が相殺されることが保証されます。 加算は線形であるため、正確さを変えることなく、すべての更新とクエリを通じてこの分解をプッシュできます。 ランダム性の仮定により、これまでに触れられた個別のプレフィックス状態の数が時間制限内に収まる程度に十分に小さいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def sign(bits):
    # bits: number of lower bounds chosen
    return -1 if bits % 2 else 1

def process():
    n, q = map(int, input().split())

    ops = []
    coords = [[] for _ in range(n)]

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "ADD":
            arr = list(map(int, tmp[1:]))
            l = arr[:2*n:2]
            r = arr[1:2*n:2]
            x = arr[-1]
            ops.append(("ADD", l, r, x))
            for i in range(n):
                coords[i].append(l[i])
                coords[i].append(r[i])
        else:
            arr = list(map(int, tmp[1:]))
            l = arr[:2*n:2]
            r = arr[1:2*n:2]
            ops.append(("SUM", l, r))
            for i in range(n):
                coords[i].append(l[i])
                coords[i].append(r[i])

    comp = []
    for i in range(n):
        comp.append({v: idx for idx, v in enumerate(sorted(set(coords[i])))})

    def encode(point):
        return tuple(comp[i][point[i]] for i in range(n))

    from collections import defaultdict
    fenw = defaultdict(int)

    def update(pt, val):
        fenw[pt] = (fenw[pt] + val) % MOD

    def query(pt):
        return fenw.get(pt, 0)

    def corners(l, r):
        # generate all 2^n corners
        res = []
        for mask in range(1 << n):
            pt = []
            sgn = 1
            for i in range(n):
                if mask & (1 << i):
                    pt.append(r[i])
                else:
                    pt.append(l[i] - 1)
                    sgn *= -1
            res.append((tuple(pt), sgn))
        return res

    for op in ops:
        if op[0] == "ADD":
            _, l, r, x = op
            for mask in range(1 << n):
                pt = []
                sgn = 1
                for i in range(n):
                    if mask & (1 << i):
                        pt.append(r[i])
                    else:
                        pt.append(l[i] - 1)
                        sgn *= -1
                pt = tuple(pt)
                fenw[pt] = (fenw[pt] + sgn * x) % MOD

        else:
            _, l, r = op
            res = 0
            for mask in range(1 << n):
                pt = []
                sgn = 1
                for i in range(n):
                    if mask & (1 << i):
                        pt.append(r[i])
                    else:
                        pt.append(l[i] - 1)
                        sgn *= -1
                pt = tuple(pt)
                res = (res + sgn * fenw.get(pt, 0)) % MOD
            print(res % MOD)

if __name__ == "__main__":
    process()
```コードは包含/除外分解を直接実装します。 各四角形はその角の表現に拡張され、更新の効果は座標タプルをキーとしたスパース マップに保存されます。 クエリは同じ分解を再利用して、プレフィックスの寄与から合計を再構築します。 

実装の微妙な詳細は lᵢ − 1 の処理です。これは暗黙的に 1 ベースのプレフィックス ユニバースを想定しており、閉区間をプレフィックス合計の差に変換するものです。 もう 1 つの重要な点は、以前に構築された厳密な意味での座標圧縮を実際には決して使用しないことです。 これは理論的な削減を反映するためだけに含まれていますが、実際の評価は生の座標で行われます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは更新ごとに 2 つのプレフィックス寄与を維持することになります。1 つは r に、もう 1 つは l − 1 にあります。クエリは単にこれら 2 つのプレフィックス値の差です。 これは、古典的な接頭辞の合計の解釈と正確に一致し、最も低い次元での正しさを確認します。 

区間が 1 で始まる場合、項 l − 1 は 0 になり、中立境界として機能します。 座標 0 へのアクセスは単に何も貢献しません。キャンセル条件を除いて、更新によってそこに質量が割り当てられることはないからです。 

多くの更新が重なり合う場合でも、各四角形は独立して分解されるため、包含/除外によって各領域が正しく分離されます。 2 つの長方形が完全に重なっている場合でも、それらの寄与はコーナー状態の同じセットで線形に加算され、二重にカウントされることなく正確さが維持されます。
