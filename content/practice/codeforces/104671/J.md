 ## 解決策
 ## 問題の理解

 グラフが与えられました$n$ラベルが貼られた鶏。 グラフは非常にまばらであり、正確には$n-2$端があり、それは森であることが保証されています。 標準的なカウント引数は、この構造がちょうど 2 つの接続されたツリーで構成されていることを意味します。$n$ノード$c$コンポーネントには$n-c$エッジ。 

各エッジは 2 羽のニワトリを示しており、少なくとも 1 羽を動かして離さない限り、1 つの岸に一緒に残すことはできません。 それぞれの移動における制約は微妙です。ニワトリのグループを川を渡って移動させるとき、後に残される側には、互換性のないペアが含まれていてはなりません。 グラフの用語では、残りのセットは独立したセットを形成する必要があります。 

したがって、移動はセットを選択することと同じです。$M$の補数となるように移動する$M$現在のバンクにあるのは独立したセットです。 同様に、残りの頂点にはエッジが含まれていてはなりません。そのため、すべてのエッジには少なくとも 1 つの端点が必要です。$M$。 これにより、$M$現在のバンク上に誘導されたサブグラフの頂点カバー。追加の制限があります。$|M| \le k$。 

このプロセスは左岸のすべての頂点から開始され、2 つの岸の間で交互に移動します。 目標は、最大 4000 回の操作を使用してすべての頂点を右岸に転送することです。 

制約が意味するのは、$n \le 1500$したがって、二次またはわずかに超線形のグラフ処理は許容されますが、各状態で頂点カバーまたはマッチングを最初から再計算するソリューションは、動的移動の下では遅すぎるか不安定すぎます。 重要な問題はグラフ サイズではなく、すべての中間状態がアクティブ側で制限されたサイズの頂点カバーを維持する必要があるという要件です。 

故障モードは次の場合に直ちに表示されます。$k$小さいです。 もし$k=1$、一度に 1 つの頂点しか移動できないため、残りの辺は常に独立する必要があります。 長さ 2 のパスを含むグラフでは、これは不可能です。 たとえば、チェーン$1-2-3$単一頂点の削除ではエッジがそのまま残るため、いかなる方法でも減らすことはできません。 これは 3 番目のサンプルと一致します。 

別の故障モードが発生する場合$k$は適度に大きいですが、残りのグラフの構造では有効な頂点カバーが大きくなります。 各辺は常に最大でも次のサイズの頂点カバーを許容しなければならないため、$k$、ソリューションでは、各バンクのグラフが常に十分な大きさの 2 部独立集合に「構造的に近い」ことを保証する必要があります。 

## アプローチ

 直接的なブルート フォース ビューでは、各状態をセットのペアとして扱います。$(A, B)$有効なサブセットをすべて試します$M$現在の側で頂点カバーを形成します。 候補頂点カバーの数はグラフのサイズに応じて指数関数的に増加するため、これはすぐに実行不可能になります。 最小限のカバーに制限しても、依然として指数関数的な数の選択肢が残り、遷移ごとにグラフの状態が変化するため、再利用は不可能です。 

重要な構造観察は、接続された各コンポーネントがツリーであるという事実から得られます。 ツリーは 2 部構成であるため、各コンポーネントは固定の 2 色を使用できます。 これは、誘導されたサブグラフの下でも有効であり、頂点のサブセットが元のカラーリングから継承された 2 部構造を保持することを意味します。 

2 部グラフでは、独立したセットを 1 つのカラー クラス全体として扱うことができます。 移動後の残りの辺が 1 つのカラー クラス (現在存在する頂点に限定される) である必要があると判断した場合、補色は自動的に頂点カバーになります。 残る唯一の制約はサイズです。補数が最大でも$k$頂点。 

したがって、頂点カバーを動的に検索する代わりに、接続されたコンポーネントごとに 1 回 2 分割を修正し、常にそれを使用して有効な移動を定義します。 各操作では、1 つのカラー クラス (またはチャンクに分割されたそのサブセット) が削除され、残りの側が常に独立したセットであることが保証されます。 

ブルート フォースは頂点カバーを直接推論しようとするため失敗します。 最適な解決策は、問題を 2 つのパーティションの維持と、選択した補完が容量を超えていないことの慎重なチェックに軽減します。$k$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 2 部構成のカラーリング + 貪欲な転送 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずグラフの構造を修正し、2 つのツリーのそれぞれについて 2 部カラーリングを個別に計算します。 

次に、2 つの銀行間の転送プロセスをシミュレートし、移動元の側が 2 つのカラー クラスに分割されていることを常に確認します。 

1. DFS または BFS を使用して各木の 2 色を計算します。 すべての頂点は、隣接する頂点が異なるように、カラー 0 または 1 を受け取ります。 
2. 現在のセットを維持します$A$そして$B$。 最初はすべての頂点が入っています$A$。 
3. そうなったとき$A$の順番で、現在存在する頂点を見てみましょう。$A$そしてそれらを元のカラーリングによって引き起こされる 2 つのカラー クラスに分割します。 
4. カラークラスを 1 つ選択します$S$そのままにする$A$。 補足$M = A \setminus S$移動するセットです。 以来$S$は単色であり、独立したセットであるため、この移動は有効です。 
5. 私たちが選ぶ$S$内の 2 つのカラー クラスのうち大きい方になります。$A$。 これにより最小限に抑えられます$|M|$、制約を満たすために必要です$|M| \le k$。 
6. 最適な選択さえも生み出すなら$|M| > k$、私たちはすぐに不可能と結論付けます。 
7. すべての頂点を転送して移動を実行します。$M$から$A$に$B$。 
8. から移動する場合にも、同じロジックが対称的に適用されます。$B$に戻る$A$。 
9. 片側が空になるまで繰り返します。空になった時点で、すべての頂点がターゲット側になります。 

重要な不変条件は、すべてのバンクが常に元のカラーリングに関して 2 部構成のままであり、各操作で維持される側が常に現在の頂点セットに制限された単一のカラー クラスであることです。 これにより、残りの側が独立していることが保証され、すべての手が有効になります。 サイズ条件により、容量制限内での実現可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(n - 2):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    color = [-1] * n

    def dfs(start):
        stack = [start]
        color[start] = 0
        while stack:
            u = stack.pop()
            for v in g[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    stack.append(v)

    for i in range(n):
        if color[i] == -1:
            dfs(i)

    A = set(range(n))
    B = set()

    ops = []

    def do_move(src, dst):
        cnt0 = [0, 0]
        for x in src:
            cnt0[color[x]] += 1

        # choose color class S to keep on src
        if cnt0[0] >= cnt0[1]:
            keep = 0
        else:
            keep = 1

        S = [x for x in src if color[x] == keep]
        M = [x for x in src if color[x] != keep]

        if len(M) > k:
            print("NO")
            sys.exit(0)

        for x in M:
            src.remove(x)
            dst.add(x)

        ops.append((M,))

    while A:
        do_move(A, B)
        if not A:
            break
        do_move(B, A)

    print(len(ops))
    for (M,) in ops:
        print(len(M), *[x + 1 for x in M])

if __name__ == "__main__":
    solve()
```実装は、フォレストの隣接リストを構築し、すべてのコンポーネントに対して 2 部構成のカラーリングを計算することから始まります。 グラフはフォレストなので、単純な DFS で十分です。 

メイン シミュレーションでは、2 つの川岸を表す 2 つの Python セットが保持されます。 各操作では、現在のサイドが 2 つの固定カラー クラスにどのように分割されるかを計算します。 その後、アルゴリズムは、より大きなクラスを同じ側に保ち、残りを移動します。 

実装の重要な詳細は、移動されたセットのサイズによってのみ有効性がチェックされることです。 二部カラーリングでは単一のカラークラスが独立していることが保証されるため、実行時にエッジ制約を明示的にチェックしません。 

交互に`do_move(A, B)`そして`do_move(B, A)`この構造により、すべてのステップが元の問題定義の正当な操作に対応することが保証されます。

 ## 特殊なケース

 いつ$k=1$の場合、長さ 2 のパスを含むコンポーネントは不可能になります。これは、削除すると残りのセット内にエッジが残り、独立セットの要件に違反するためです。 アルゴリズムはサイズチェックを通じてこれを検出します$|M| \le k$、小さい色の補色が容量を超えるとすぐに失敗します。 

星型コンポーネントの場合、カラーリングにより 1 つの中心クラスと 1 つのリーフ クラスが生成されます。 リーフ クラスは大きく、補数は小さいため、いつでも実現可能性が保証されます。$k$少なくとも移動される内部ノードの数です。 アルゴリズムは常に大きいカラー クラスを維持するため、自然に正しい側が選択されます。 

フォレストが 2 つの別々のエッジで構成されている場合、両方のコンポーネントはすでにバランスのとれたカラー クラスを持つ最適な 2 部構成になっています。 これにより、頂点カバー全体が、いつでも 1 回の操作で移動できるほど小さくなります。$k$は十分に大きいため、アルゴリズムは 1 ステップで状態全体を崩壊させます。
