 ## 解決策
 ## 問題の理解

 私たちには、表向きまたは裏向きのカードの列が与えられます。 移動は、カードが現在表になっている位置を選択し、選択したカード自体を含むすべてのカードをその位置から行の最後まで裏返すことで構成されます。 反転すると、各カードの状態が切り替わります。 

少なくとも 1 つの有効な手が存在する限り、プロセスは続行されます。 移動は、選択した位置に現在表向きのカードが含まれている場合にのみ有効です。 目標は、特定の戦略を選択することではなく、構成が表向きのカードがない状態に達するまでに実行できる最大可能な移動数を決定することです。 

この制約により、文字列の長さは最大 200,000 まで許可され、操作ごとに線形時間でセグメントのスキャンと反転を繰り返すシミュレーションは直ちに除外されます。 各フリップを直接シミュレートしようとする素朴なアプローチでは、操作ごとに最大 O(n) の作業が必要となり、最悪の場合、O(n) 操作が発生して O(n^2) となり、遅すぎる可能性があります。 

左から右への反転を貪欲にシミュレートすることについて推論すると、微妙な問題が発生します。 反転の影響はサフィックスに対してグローバルであるため、以前の決定は将来のすべての状態に影響します。 このため、プロセスを圧縮するグローバルな不変式を見つけない限り、ローカルでの貪欲な選択は信頼できなくなります。 

エッジケースの小さな例は、次のような文字列です。`OXO`。 常に左端を選択しようとすると、`O`、国家は、非局所的に機会を生み出したり破壊したりする方法で進化します。 どのようなシミュレーション手法でも、サフィックスに影響を与えるフリップのパリティを注意深く考慮する必要があります。そうしないと、操作のカウントが誤ってしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 現在の文字列を維持し、左から右に繰り返しスキャンして表向きのカードを見つけます。 インデックス i を見つけたら、`O`では、すべての文字を i から n に反転します。 各フリップは O(n)、スキャンも O(n) であるため、各操作のコストは O(n) です。 最悪の場合、処理が完了する前に O(n) 操作が実行される可能性があります。`O`が残るため、時間計算量は O(n^2) となり、2e5 には遅すぎます。 

重要な洞察は、動きが実際に何を行うかを再構成することから得られます。 各操作は、現在の有効な状態が存在する位置 i を選択することと同じです。`O`、サフィックスを切り替えます。 すべての操作後に完全な文字列を追跡するのではなく、各位置がサフィックス反転によって何回影響を受けたかが重要であることがわかります。 

サフィックスに適用されるフリップの実行パリティを維持しながら左から右に処理すると、現在の文字が効果的に有効かどうかを判断できます。`O`または`X`いつでも。 効果的なものに出会うたびに、`O`、最大の操作シーケンスで、その位置から開始して反転を実行することを強制されます。`O`永久に残り、後で別の有効な操作が可能になります。 これにより、問題はサフィックス反転を開始することを強制される回数を数えるということになります。 

したがって、文字列をシミュレートする代わりに、現在のプレフィックスが偶数回または奇数回反転されたかどうかを表す単一のパリティ変数を追跡し、反転がいつ発生する必要があるかを貪欲に決定します。

 ## アルゴリズムのチュートリアル

 変数を維持しながら文字列を左から右にスキャンします。`flip`これは、現在の位置が以前の操作によって奇数回反転されたかどうかを表します。 

1.初期化`flip = 0`そして`ans = 0`。 変数`flip`現在の文字が元の値に対して反転されているかどうかを追跡します。 
2. 0 から n - 1 までのインデックス i ごとに、カードの実効値を計算します。 オリジナルキャラクターなら`O`、その場合は表向きになります。`flip = 0`そして裏向きのとき`flip = 1`。 そうであれば`X`と解釈が逆転します。 
3. 位置 i での実効値が表を向いている場合、i から始まる有効な操作が可能です。 最大限の操作シーケンスでは、これを直ちに実行する必要があります。これを遅らせても何のメリットも生まれず、強制的なサフィックス反転が延期されるだけだからです。 
4. i で操作を実行すると、答えがインクリメントされ、トグルが切り替わります。`flip`。 これは、将来のすべての位置が以前の解釈に対して反転されることを表します。 
5. 最後までスキャンを続けます。 フリップをトリガーした合計回数が答えです。 

重要なアイデアは、各強制操作が現在利用可能な最も古い表向きのカードを消費し、その効果をサフィックスに伝播し、その効果は単一のパリティ状態を切り替えることによって正確にキャプチャされるということです。 

### なぜ効果があるのか

 どの時点でも、重要な唯一の決定は、現在のポジションが事実上フェイスアップであるかどうかです。 そうである場合、反転しないままにすることは、すぐに実行できる操作を保持するため、最大長シーケンスの一部にすることはできません。 これをすぐに実行すると、サフィックスの状態が均一に変換され、将来の強制操作の数は減りません。 それはそれらをシフトするだけです。 これにより、最大操作と新たに有効な操作に遭遇した回数との間に 1 対 1 の対応関係が作成されます。`O`パリティ反転時の左から右へのスイープ中。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    flip = 0
    ans = 0

    for ch in s:
        if ch == 'O':
            cur = flip ^ 0
        else:
            cur = flip ^ 1

        if cur == 1:  # effective face-up
            ans += 1
            flip ^= 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、元の文字列をバイナリ解釈にエンコードすることに依存しています。`O`0であり、`X`が 1 の場合、意味が反転するかどうかを追跡します。 XOR 演算は、文字列を変更せずにサフィックスのトグル効果を取得します。 

最もデリケートな部分は、`cur`。 正規化後は表向きを1として扱います。 位置が表向きであると検出されると、すぐに論理反転を適用して、そのインデックスでの操作の実行を表します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout

    s = input().strip()

    flip = 0
    ans = 0

    for ch in s:
        cur = flip ^ (0 if ch == 'O' else 1)
        if cur == 1:
            ans += 1
            flip ^= 1

    return str(ans)

 ## 特殊なケース

 シングル`O`は、有効な移動が常に唯一の利用可能な操作を消費し、プロセスを即座に終了することを示しています。 アルゴリズムはインデックス 0 を処理し、有効なフェイスアップを確認し、答えをインクリメントし、パリティを反転するので、それ以上の位置は問題になりません。 

のような文字列`XXXXXX`は、すべてのカードが最初は裏向きであっても、パリティ解釈の下では最初の位置が実質的に表向きになり、操作が 1 つだけ生成されることを示しています。 この後、後続のすべてのポジションは事実上裏向きになり、それ以上の移動は不可能になり、サフィックス反転によって暗示されるシミュレーション動作と一致します。
