 ## 問題の理解

 私たちは 2 フェーズのインタラクティブな問題を扱っています。 最初のフェーズでは、プレーヤー A は完全な$n \times n$バイナリ グリッド。各セルは 0 または 1 であり、各テスト ケースでは、グリッドが 1 を介して完全に接続されているかどうかも指定されます。 プレーヤー A はプレーヤー B に接続性を直接伝えることはできませんが、陪審員に 2 つの整数を送信できます。$r$そして$c$、選択された行と列を表します。 第 2 フェーズでは、プレイヤー B は$r$- 番目の行と$c$インデックス自体が分からないため、グリッドが 1 を介して接続されているかどうかを判断する必要があります。 

重要な制約は次のとおりです。$n$最大 1000 まで可能で、すべてのテスト ケースにわたるセルの合計数は最大でも$2 \cdot 10^6$これらの制約は、最初の実行でグリッド全体を送信する余裕がないことを示唆しています。 プレーヤー B が 1 行 1 列だけから接続性を推測できるように、最小限の情報を選択する必要があります。 入力には最大まで含めることができるため、$10^4$テストケースでは、テストごとの処理がほぼ線形である必要があります。$n$。 

明らかではないエッジ ケースには、各行と列に 1 つの 1 があり、切断されたクラスターを形成するグリッドが含まれます。 プレイヤー B がこれらの選択から接続性を推測できない場合、最初の行と列を 1 で選択する単純なアプローチは失敗する可能性があります。 たとえば、グリッドが```
10
01
```接続性は 0 ですが、両方とも 1 を含む最初の行と列を選択すると、プレイヤー B はグリッドが接続されていると誤解してしまいます。 

## アプローチ

 ブルート フォース方式では、接続を一意に識別する行と列の情報全体を送信する必要があります。 行と列を慎重に選択して、グリッド全体を行と列にエンコードすることを想像することもできますが、これは不必要に複雑であり、メモリまたは帯域幅の制限を超える可能性があります。 原理的には、グリッドを整数のペアにマッピングする関数であればプレーヤー B に接続性を推定させることができるため、総当り攻撃は正しいのですが、大規模な場合は非現実的になります。$n$。 

重要な洞察は、行と列が 1 のすべての接続コンポーネントと交差する場合、1 を介した接続が維持されるということです。 プレーヤー A は、少なくとも 1 つの 1 を含む行と、少なくとも 1 つの 1 を含む任意の列を見つけることができます。すべての接続コンポーネントは少なくとも 1 つの行と 1 つの列と交差する必要があるため、プレーヤー B は、行と列に重複する 1 が含まれているかどうかを確認することで、どの 1 が接続されているかを再構築できます。 具体的には、行と列を合わせて 1 つのコンポーネントにすべて 1 が含まれている場合、プレーヤー B は、いずれかの 1 が孤立または切断されているかどうかを確認できます。 これにより、プレーヤー B が必要とする情報がグリッド全体から選択された行と列のみに減ります。 

この戦略は、どのグリッドでも、1 を含む最初の行と最初の列を選択することで、各連結成分から少なくとも 1 つの 1 が確実に公開されるようにすることで機能します。 プレイヤー B は、行の 1 の位置が列の 1 と交差するかどうかを確認することで接続性を判断できます。 行と列に 1 が 1 つだけあり、それらが一致する場合、グリッドは接続されます。 それ以外の場合は切断されます。

 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の実行 (プレイヤー A) では、各行を反復処理して、少なくとも 1 つの 1 を含む最初の行を見つけます。そのインデックスを次のように保存します。$r$。 次に、各列を反復して、少なくとも 1 つの 1 を含む最初の列を見つけます。そのインデックスを次のように格納します。$c$。 ペアを返却する$(r, c)$。 
2. 2 回目の実行 (プレーヤー B) では、指定された行と列を読み取ります。 それらを、その行と列の内容を表すバイナリ配列として扱います。 
3. 行と列の交差部分を介してすべての 1 に到達できるかどうかを確認して、接続を確認します。 具体的には、小型の場合$n$, 行と列の任意の位置に重複する 1 がある場合、グリッドが接続されていることを宣言します。 それ以外の場合は、切断されたと宣言します。 

機能する理由: 1 を含む任意の行と任意の列を選択すると、プレイヤー B にはすべての接続されたコンポーネントの代表が表示されることが保証されます。 複数の連結成分がある場合は、他の成分と交差しない行または列に少なくとも 1 つの 1 が表示され、検出可能になります。 不変条件は、1 のすべての連結コンポーネントが少なくとも 1 つの行と 1 つの列と交差することです。そのため、選択によってコンポーネントの構造が公開されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def player_a():
    t = int(input())
    res = []
    for _ in range(t):
        n, c = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        row_idx, col_idx = -1, -1
        for i in range(n):
            if '1' in grid[i]:
                row_idx = i + 1
                break
        for j in range(n):
            if any(grid[i][j] == '1' for i in range(n)):
                col_idx = j + 1
                break
        res.append(f"{row_idx} {col_idx}")
    print('\n'.join(res))

def player_b():
    t = int(input())
    for _ in range(t):
        n = int(input())
        row = input().strip()
        col = input().strip()
        connected = 0
        for i in range(n):
            if row[i] == '1' and col[i] == '1':
                connected = 1
                break
        print(connected)

def main():
    mode = input().strip()
    if mode == 'first':
        player_a()
    else:
        player_b()

if __name__ == "__main__":
    main()
```最初の実行では、1 を含む任意の行と列を選択します。2 回目の実行では、行と列を使用して重複を検出します。 重要な微妙な点は、プレーヤー B はインデックスを知ることができず、内容だけを知ることができるということです。 同じ相対位置で一致する 1 をチェックすることで、接続されたグリッドの検出が保証されます。
