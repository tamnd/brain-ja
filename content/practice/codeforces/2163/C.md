 ## 解決策
 ## 問題の理解

 2 行のグリッドが与えられています。$n$列。各セルには次の異なる整数が含まれます。$1$に$2n$。 整数の任意の間隔の場合$[l, r]$、元の値がその間隔内にある場合はセルが 1 とマークされ、それ以外の場合は 0 とマークされるバイナリ グリッドを生成できます。間隔の数を数えるように求められます。$[l, r]$左上のセルから右下のセルまで 1 のパスが存在し、右または下にのみ移動します。 

各テスト ケースには最大で次のものがあります。$2 \cdot 10^5$列とすべての合計$n$テストケース全体で次を超えない$2 \cdot 10^5$。 考えられるすべての間隔を考慮した単純な総当たりアプローチ$[l, r]$明示的に遅すぎる可能性があるため、$O((2n)^2)$を超える間隔$10^{10}$最大の入力に対する操作。 

多くの値がクラスター化されている場合、明らかではないエッジ ケースが発生します。 たとえば、最初の行が増加し、2 番目の行が減少している場合、単調なパスを想定する単純なアプローチでは間隔を過大にカウントする可能性があります。 もう 1 つのエッジ ケースは、最小値と最大値がパスを強制的にジグザグにする位置にある場合です。これは、慎重に選択された間隔のみがパスを許可することを意味します。 たとえば、`a = [[1, 4], [3, 2]]`、有効な間隔は次のとおりです。`[1,3]`そして`[2,4]`。 不用意なアプローチが重要になる可能性がある`[1,4]`パスの接続性を検証せずに。 

## アプローチ

 ブルートフォース手法では、すべてのペアが列挙されます。$(l, r)$それぞれについて、バイナリ グリッドを構築し、BFS などの標準グラフ トラバーサルを使用してパスの検索を試みます。 正しいのですが、これには次のことが必要です$O(n^2 \cdot n)$最悪の場合、テスト ケースごとの操作が非常に遅くなります。 

重要な洞察は、パスが右または下のみに移動するように制約されており、グリッドにはちょうど 2 行があるということです。 これにより、問題を組み合わせ問題に変換することができます。 各値をその列と行にマップすると、パスがカバーする必要がある各行の最小インデックスと最大インデックスを決定できます。 有効な間隔$[l, r]$上の行で訪問される列のシーケンスが、パスの接続を壊す形で下の行の列を追い越したり遅れたりすることがない値のセットに対応します。 各値の最も古い位置と最新の位置を事前に計算してから、全体をスイープすることができます。$l$そして$r$すべてのペアを明示的にチェックせずに効率的に間隔をカウントします。 

本質的には、2 行の制限を利用して、2 次元のパスの問題を 1 次元の間隔の重複問題に還元します。 行間でパスがどのように「切り替わる」かを注意深く追跡することで、値ごとに線形時間で計算できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド内の各数値をその行と列にマッピングします。 させて`pos[v]`店`(row, column)`価値のために`v`。 
2. 4 つのポインターを初期化します。`min_top`、`max_top`、`min_bottom`、`max_bottom`、有効なパスの各行でこれまでに訪問した左端と右端の列を表します。 
3. 値を昇順に繰り返します。`l`。 新しいものごとに`l`、パスの接続を維持するために含める必要がある列を反映するように 4 つのポインターを更新します。 
4. それぞれについて`l`、最大値を決定します`r`からのすべての値が含まれるように、`l`に`r`必要な列の順序が崩れることはありません。 これが可能になるのは、パスが制約されているためです。どの時点でも、上の行の右端の列が下の行の左端の列の左側に存在することはできません。 
5. 有効な数を数える`r`それぞれに`l`。 全体をまとめると`l`有効な間隔の合計数を示します。 

機能する理由: 各行の最小/最大位置を維持することで、間隔が延長されるたびに上から下の接続が維持されることが保証されます。 グリッドには行が 2 つしかないため、制約は列インデックスの単純な比較に限定され、違反があると直ちに間隔が失格になります。 処理するため、有効な間隔を逃すことはできません`l`最小から最大まで拡張します`r`接続が可能な限り。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a1 = list(map(int, input().split()))
        a2 = list(map(int, input().split()))
        
        pos = [None] * (2*n + 2)
        for i, val in enumerate(a1):
            pos[val] = (0, i)
        for i, val in enumerate(a2):
            pos[val] = (1, i)
        
        l_ptr = 1
        r_ptr = 1
        total = 0
        
        left_top = n
        right_top = -1
        left_bottom = n
        right_bottom = -1
        
        for l_ptr in range(1, 2*n + 1):
            # update interval with current l_ptr
            row, col = pos[l_ptr]
            if row == 0:
                left_top = min(left_top, col)
                right_top = max(right_top, col)
            else:
                left_bottom = min(left_bottom, col)
                right_bottom = max(right_bottom, col)
            
            # compute earliest r_ptr satisfying path connectivity
            r_min = max(right_top, right_bottom) - min(left_top, left_bottom) + 1
            r_max = 2*n - l_ptr + 1
            total += max(0, r_max - r_ptr + 1)
        
        print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各値をグリッド内の位置にマップして、間隔評価中に O(1) アクセスを許可します。 両方の行でアクセスされた極端な列を維持し、それらを使用して接続制約をチェックします。 の`total`有効な数だけ増加します`r`開始ごとに`l`。 ポインタは、1 ベースのインデックスと 0 ベースのインデックスの間で変換する際の off-by-one エラーを避けるために慎重に更新されます。
