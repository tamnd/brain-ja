 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$、およびバイナリ文字列$x$同じ長さの。 最初に、別のバイナリ文字列があります。$s$ゼロの。 私たちのタスクは、値を「埋める」操作を最大 5 つ実行することです。$s$すべての位置が$x$1 があり、また 1 が入っています$s$。 

各操作は 2 つのインデックスによって定義されます$l$そして$r$。 選択した後$l$そして$r$、任意の位置$i$厳密に間$l$そして$r$その値は厳密に次の範囲内にあります$p_l$そして$p_r$に 1 に設定されます$s$。 基本的に、操作は順列の間隔を描画し、2 つのエンドポイントによって定義された四角形の内側にある要素を「マーク」します。 

制約が教えてくれるのは$n$と同じ大きさにすることができます$2 \cdot 10^5$まであります$10^4$テストケース。 これにより私たちは回避せざるを得なくなります$O(n^2)$考えられるすべてのペアに対するブルート フォース チェック$l, r$1 つのテスト ケースでも生成される可能性があるため、$O(n^2) = 4 \cdot 10^{10}$という操作が行われますが、これは非現実的です。 

明らかではないエッジケースは、必要なものが$x$複数の切り離された増加または減少の「波」として現れます。$p$。 たとえば、次の場合$p = [6, 2, 3, 4, 5, 1]$そして$x = 110110$、連続していない位置に必要なクラスターが存在します。$p$注文。 最初のセグメントから最後のセグメントまでの 1 つのセグメントのみを考慮する不注意なアプローチでは、これらの島を見逃す可能性があり、間違った解決策が得られる可能性があります。 

## アプローチ

 素朴な総当たりアプローチでは、考えられるすべてのペアを検討することになります。$(l, r)$操作をシミュレーションして、どの位置がどの位置にあるかを確認します。$s$準備を整えてください。 次に、最大 5 つの操作のすべてのサブセットを試行して、$x$カバーされています。 これは原理的には正しいですが、絶望的に遅いためです。$O(n^2)$チェック サブセットで乗算されたペアは指数関数的に増加します。 

重要な洞察は幾何学的なものです。 各操作は、連続したセグメントを「埋める」$p$間の値$p_l$そして$p_r$。 したがって、すべての演算をカバーするために必要な最小限の演算数は、$x$必要なすべてのセグメントを含む順列内の連続する増加または減少セグメントの最小数に対応します。 最大 5 つの演算を使用でき、順列には 1 つの最大値と最小値があるため、簡単な戦略は、1 を必要とする左端と右端の位置を取得し、それらの間の完全なセグメントをカバーする演算を実行することです。 いくつかのものが、最小位置と最大位置によって定義される連続した間隔の外側にある場合、$p$、2回目の手術が必要になる場合があります。 実際には、操作が 2 つの別々の「波」に現れる場合は、最大でも 2 つの操作で十分です。 

この戦略では、問題を最小インデックスと最大インデックスを特定することに縮小します。$p$どこ$x_i = 1$、これらの境界にまたがる 1 つまたは 2 つの操作を出力します。 それ以降にそれらがカバーされない場合、または 5 つ以上の別々のセグメントに分散されている場合は、不可能であると宣言します。

 ## アルゴリズムのチュートリアル

 1. 与えられた順列に対して$p$とターゲット文字列$x$を反復処理します$x$すべての位置を特定するには$x_i = 1$。 最小限のインデックスを追跡する`lmin`そして最大インデックス`rmax`これらのポジションのうち。 
2. 誰もいない場合$x$、答えは簡単です: 操作はゼロです。 
3. すべてが入っている場合$x$連続した間隔を形成する$p$から単一の操作を実行できます。`lmin`に`rmax`。 この操作は、値が厳密に次の範囲内にあるすべての要素をカバーします。`p[lmin]`そして`p[rmax]`。 
4. それらが 2 つの別々の連続した間隔を形成する場合、$p$、2 つの操作でカバーできます。 最初の操作は最初のセグメントにまたがり、2 番目の操作は 2 番目のセグメントにまたがります。 
5. 3 つ以上の個別の間隔がある場合、出力`-1`なぜなら、この問題では最大 5 つの操作に制限されており、2 つの間隔を超えて散在する操作は、この単純な貪欲な方法では効率的にカバーできないからです。 
6. 操作の数とペアを出力する`(l, r)`それぞれの操作を表します。 操作境界は、元の配列内の包括的なインデックスです。 

このアルゴリズムが機能するのは、各操作がインデックスと値の両方のエンドポイント間に厳密に存在するすべての要素をカバーできるためです。 1 の左端と右端の位置を選択することで、必要なすべてのものが確実に含まれるようになります。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        x = input().strip()
        ones = [i for i, c in enumerate(x) if c == '1']
        
        if not ones:
            print(0)
            continue
        
        l = ones[0]
        r = ones[-1]
        
        if l == r:
            print(0)
            continue
        
        # check if the interval is already sorted increasing or decreasing in p
        segment = p[l:r+1]
        if segment != sorted(segment) and segment != sorted(segment, reverse=True):
            print(2)
            print(l+1, r+1)
        else:
            print(1)
            print(l+1, r+1)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に 1 の位置を抽出します。これにより、最小のカバー間隔を特定できるようになります。 私たちが使用するのは`enumerate`インデックスと値の両方を追跡します。 セグメントがソート順に連続している場合は、1 回の操作で十分です。 そうでない場合は、2 つ必要になる可能性があります。 出力ではインデックスは 1 から始まります。 印刷時に慎重にインクリメントすることで、1 ずつずれたエラーが回避されます。
