 ## 解決策
 ## 問題の理解

 整数の 1 次元配列が与えられており、それをブロックと呼ばれる連続したサブ配列に分割したいと考えています。 各ブロックはその要素の合計が同じである必要があり、2 つのブロックが重複することはできません。 これを満たすブロックのすべての選択肢の中で、最大数のブロックが必要です。 出力には、ブロックの数と各ブロックのインデックスがリストされます。 

配列サイズの制限は 1500 で、各要素は ±10^5 以内です。 n ≤ 1500 の場合、O(n^3) アルゴリズムは約 3.3×10^9 の演算を実行しますが、これは 3 秒の制限には多すぎるため、O(n^2) 以上を目指す必要があります。 メモリは十分にあるため、O(n^2) 構造の使用が許容されます。 

明らかではないエッジ ケースには、負の数とゼロを含む配列が含まれます。 例えば、`[0, 0, 0]`合計がゼロの有効なブロック パーティションが複数あります。 最初に最大のブロックを常に選択する単純な貪欲なアプローチは、後でさらに多くのブロックがブロックされるのを妨げる場合に失敗する可能性があります。 もう 1 つのエッジ ケースは、次のような厳密に増加する配列です。`[1, 2, 3, 4, 5]`ここで、最大の数値は、より小さい合計をグループ化するのではなく、独自のブロックとして扱われる可能性があります。 アルゴリズムは、部分配列に現れるすべての可能な合計を正しく調査する必要があります。 

## アプローチ

 強引な解決策は、連続する部分配列によって形成されるすべての可能な合計を考慮し、その合計に対して互いに素なブロックの最大セットを選択することです。 1 つの方法は、すべての O(n^2) 部分配列とその合計を生成し、個別の合計ごとに、互いに素なブロックの最大のセットを選択することです。 各チェックは左から右に貪欲に実行できます。 このアプローチの問題は、すべてのペアの組み合わせを考慮しようとすると、すべての部分配列の合計を明示的に格納するには O(n^3) の演算が必要になる可能性があり、時間がかかりすぎることです。 

重要な洞察は、合計ごとにすべてのブロックを個別に列挙する必要がないということです。 代わりに、接頭辞の合計を使用して、O(1) の部分配列の合計を計算できます。 次に、潜在的なターゲット合計ごとに、左から右にスキャンして、重複せずにできるだけ早く終了するブロックを貪欲に選択できます。 これが機能するのは、素ブロックの最大数が必要な場合、左側の小さいブロックの合計が同じであれば、後でより多くのブロックをブロックできないからです。 したがって、出現するすべての部分配列の合計を考慮し、最も重複しないブロックを生成する合計を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての部分配列をブルート フォースする | O(n^3) | O(n^2) | 遅すぎる |
 | プレフィックスの合計 + 合計による貪欲 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を計算します。`pref`どこ`pref[i] = a[0] + a[1] + ... + a[i-1]`。 これにより、任意のブロックの合計を計算できるようになります。`[l, r]`O(1) として`pref[r+1] - pref[l]`。 
2. 辞書を作成する`sum_to_blocks`各合計について、その合計を達成するブロックのリストを保存します。 すべてのペアをループする`(l, r)`0 ≤ l ≤ r < n の場合、合計を計算します`s = pref[r+1] - pref[l]`、追加します`(l, r)`に`sum_to_blocks[s]`。 
3. 変数を初期化して、重複しないブロックの最大数を追跡します。`max_blocks = 0`そして`best_blocks = []`。 
4. 各合計を反復処理します。`s`で`sum_to_blocks`。 に対応するブロックのリストについては、`s`、終了インデックスで並べ替えます`r`。 これにより、左から右への貪欲な選択によって最大数のブロックが生成されることが保証されます。 
5. 貪欲な選択を実行します: 初期化`last_end = -1`、次にブロックごとに`(l, r)`ソートされた順序で、`l > last_end`、ブロックを追加します`current_blocks`そして更新します`last_end = r`。 
6. この合計に対して選択されたブロックの数が超過した場合`max_blocks`、 アップデート`max_blocks`そして`best_blocks`。 
7. 出力`max_blocks`およびブロックの 1 から始まるインデックス`best_blocks`。 

機能する理由: ブロックを右のエンドポイントで並べ替え、左から貪欲に選択することで、重複しないブロックの最大数が保証されます。 これは古典的な間隔スケジュールの原則です。 配列内に現れるすべての可能な合計を考慮することで、最大の分割を可能にする合計を欠落していないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

from collections import defaultdict

sum_to_blocks = defaultdict(list)
for l in range(n):
    for r in range(l, n):
        s = pref[r + 1] - pref[l]
        sum_to_blocks[s].append((l, r))

max_blocks = 0
best_blocks = []

for s, blocks in sum_to_blocks.items():
    blocks.sort(key=lambda x: x[1])
    current_blocks = []
    last_end = -1
    for l, r in blocks:
        if l > last_end:
            current_blocks.append((l + 1, r + 1))  # 1-based
            last_end = r
    if len(current_blocks) > max_blocks:
        max_blocks = len(current_blocks)
        best_blocks = current_blocks

print(max_blocks)
for l, r in best_blocks:
    print(l, r)
```プレフィックス合計配列を使用すると、部分配列の合計を効率的に計算できます。 の`defaultdict`ブロックを合計で収集します。 終了インデックスでソートすると、貪欲な選択が可能になります。 変換`l + 1, r + 1`問題に必要な 1 から始まるインデックスに調整します。 Off-by-one エラーは次の方法で回避できます。`pref[r+1]`そしてそれを繰り返す`r`から`l`に`n-1`。 

## 実用的な例

 **サンプル 1**

 入力:`[4, 1, 2, 2, 1, 5, 3]`| l | r | 合計 | 合計ブロック数[合計] |
 | --- | --- | --- | --- |
 | 0 | 0 | 4 | [(0,0)] |
 | 0 | 1 | 5 | [(0,1)] |
 | 1 | 2 | 3 | [(1,2)] |
 | 2 | 3 | 4 | [(2,3)] |
 | 4 | 5 | 6 | [(4,5)] |
 | 6 | 6 | 3 | [(6,6)] |

 sum=3 を選択し、r でソートするとブロックが得られます。`(1,2)`、`(6,6)`last_end 追跡を使用すると、重複がないことが保証されます。 合計 3 の最大ブロック数は 3 です。`(2,3)`、`(4,5)`、`(7,7)`。 

**カスタム例**

 入力:`[0, 0, 0]`すべての合計は 0 です。合計 0 によるブロック:`(0,0)`、`(0,1)`、`(0,2)`、`(1,1)`、`(1,2)`、`(2,2)`。 r による貪欲な選択の結果`(0,0)`、`(1,1)`、`(2,2)`、最大 3 つのブロックを与えます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | O(n^2) 個の部分配列があります。 それぞれの合計は O(1) で計算されます。 合計あたりの貪欲な選択は O(n)、合計 O(n^2) です。 |
 | スペース | O(n^2) | 個別の合計ごとにブロックのリストを保存します。 最悪の場合、すべての部分配列が異なる合計を持ちます。 |

 n ≤ 1500 の場合、n^2 ≈ 2.25×10^6 となり、これは 3 秒の制限時間として許容されます。 メモリは 256 MB に余裕で収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    pref = [0]*(n+1)
    for i in range(n):
        pref[i+1] = pref[i]+a[i]
    from collections import defaultdict
    sum_to_blocks = defaultdict(list)
    for l in range(n):
        for r in range(l,n):
            sum_to_blocks[pref[r+1]-pref[l]].append((l,r))
    max_blocks = 0
    best_blocks = []
    for s, blocks in sum_to_blocks.items():
        blocks.sort(key=lambda x:x[1])
        current_blocks = []
        last_end = -1
        for l,r in blocks:
            if l>last_end:
                current_blocks.append((l+1,r+1))
                last_end = r
        if len(current_blocks) > max_blocks:
            max_blocks = len(current_blocks)
            best_blocks = current_blocks
    out = [str(max_blocks)]
    for l,r in best_blocks:
        out.append(f"{l} {r}")
    return '\n'.join(out)

assert run("7\n4 1 2 2 1 5 3\n") == "3\n2 3\n4 5\n7 7", "sample 1"

# custom cases
assert run("3\n0 0 0\n")
```
