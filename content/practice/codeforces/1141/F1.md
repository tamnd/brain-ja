 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、ブロックと呼ばれるいくつかの連続したサブ配列を選択できます。 選択されたすべてのブロックの合計はまったく同じである必要があり、選択された 2 つのブロックが重複してはなりません。 

すべての可能な合計の中で、最大数のペアごとに互いに素なブロックを許容するものが必要です。 最適な合計を見つけた後、その合計を持つブロックの最大サイズのコレクションを 1 つ出力する必要があります。 

重要な点は、金額が事前に提示されないことです。 選択したすべてのブロックがその値を共有している限り、任意の値を自由に選択できます。 

簡単バージョンには、$n \le 50$。 そうすれば問題の性質はすぐに変わります。 部分配列の総数は$$\frac{n(n+1)}{2} \le 1275.$$これは、すべての部分配列とその合計を明示的に生成できることを意味します。 普通では不可能なアプローチ$n=10^5$ここでは完全に合理的になります。 

よくある間違いは、同じ合計を持つ多数の部分配列を見つけることだけに集中することです。 ブロックも互いに素である必要があります。 例えば：```
3
1 1 1
```合計$2$ブロックで出現する$(1,2)$そして$(2,3)$, しかし、これらは重複しているため、どちらか 1 つしか取得できません。 

もう 1 つの陥りやすい落とし穴は、ブロックが長いほうが何らかの形で優れていると思い込むことです。 考慮する：```
4
1 1 1 1
```合計について$2$、選択できます$(1,2)$そして$(3,4)$、2つのブロックを与えます。 合計について$4$、私たちが得るのは$(1,4)$、1つのブロックを与えます。 ブロック数を最大化することが目的であり、カバーされる長さを最大化することではありません。 

負の数も重要です。 例えば：```
4
1 -1 1 -1
```いくつかの異なる部分配列には合計があります$0$。 ツーポインターなど、積極性に依存する解決策は失敗します。 

## アプローチ

 最も直接的なアイデアは、すべての部分配列を生成し、その合計を計算し、その合計によって部分配列をグループ化することです。 特定の金額を確定したら$S$、問題は次のようになります。 

> すべての間隔のうち、合計が$S$、重複しない間隔の最大数を選択します。 

これは古典的な間隔スケジューリングの問題です。 

各合計の総当たり検索では、間隔のすべてのサブセットを試して、それらが重複しているかどうかを確認できます。 それは明らかに正しいですが、合計ごとの間隔が数十しかない場合でも、サブセットの数は指数関数的に増加します。 

すべてを変える観察は、間隔スケジュールには貪欲な解決策があるということです。 すべての間隔の合計がすでに同じである場合、重要なのは重複しない間隔の数を最大化することだけです。 標準的な戦略は、終了位置によって間隔を並べ替え、最後に選択した間隔の後に始まる最初の間隔を繰り返し取得することです。 

なぜここでそれが機能するのでしょうか? 最も早い終了間隔を選択すると、将来の間隔にできるだけ多くの余地が残ります。 これは、古典的な最大非重複間隔問題で使用される引数とまったく同じです。 

以来$n \le 50$、すべてを生成できます$O(n^2)$サブ配列を合計ごとにグループ化して保存し、個別の合計ごとに間隔スケジュールを個別に実行します。 すべての合計の中で最良の結果が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 合計ごとのブルート フォース サブセット | 指数 | 指数 | 遅すぎる |
 | すべてのサブ配列 + 貪欲な間隔スケジューリングを生成 | O(n² log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのサブ配列を列挙する$(l,r)$。 

プレフィックス合計または直接累積を使用して、各部分配列の合計を計算します。 その合計に関連付けられたコンテナ内に間隔を保存します。 
2. それぞれの合計について$S$、要素の合計が以下になるすべての間隔を収集します。$S$。 

ここで、この特定の合計の問題は、他のすべての合計とは独立しています。 
3. これらの間隔を右のエンドポイントで並べ替えます。 

これは、間隔スケジュールで使用される標準的な順序です。 
4. ソートされた間隔を左から右にスキャンします。 

最後に選択した間隔の終了位置を追跡します。 
5. 最後に選択した間隔が終了した後に間隔が開始される場合は、その間隔を選択します。 

この間隔は、以前に選択した間隔と重複することはできません。 
6. この合計のすべての間隔が処理されるまで続行します。 

結果として得られるセットは、合計を含む素の間隔の最大サイズのコレクションです。$S$。 
7. そのサイズを、これまでに見つかった最良の回答と比較します。 

それが大きい場合は、現在の最良の回答を置き換えます。 
8. すべての合計を確認した後、保存されている最良のコレクションを出力します。 

### なぜ効果があるのか

 合計を修正する$S$。 あらゆる有効な解決策は、$S$合計が等しい間隔のみで構成されます$S$。 これらの間隔のうち、ペアごとに素な間隔の最大数が必要です。 

これはまさにインターバルスケジューリングの問題です。 よく知られている貪欲ルールは、常に最も早い終了位置で利用可能な間隔を取得し、重複しない間隔の最適な最大カーディナリティのセットを生成します。 

考えられるすべての合計に対して最適なコレクションを個別に計算し、その中で最大のものを選択するため、最終的な答えもすべての合計に対して最適になります。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sums = defaultdict(list)

    for l in range(n):
        cur = 0
        for r in range(l, n):
            cur += a[r]
            sums[cur].append((l + 1, r + 1))

    best = []

    for intervals in sums.values():
        intervals.sort(key=lambda x: x[1])

        chosen = []
        last_end = 0

        for l, r in intervals:
            if l > last_end:
                chosen.append((l, r))
                last_end = r

        if len(chosen) > len(best):
            best = chosen

    print(len(best))
    for l, r in best:
        print(l, r)

if __name__ == "__main__":
    solve()
```最初のネストされたループは、すべての部分配列を生成します。 以来$n$50 のみです。すべてを保存しています$O(n^2)$間隔は完全に安全です。 合計を最初から再計算する代わりに、変数`cur`現在の部分配列を一度に 1 位置ずつ拡張します。 

辞書`sums`部分配列の合計によって間隔をグループ化します。 すべてのキーは候補の共通合計を表します。 

各グループについて、間隔は右端点によって並べ替えられます。 貪欲スキャンでは次のように使用されます。`last_end`最後に選択した間隔の終わりを記憶します。 条件`l > last_end`厳密な非重複を保証します。 

間隔エンドポイントは、生成されるとすぐに 1 から始まるインデックスとして保存されます。 これにより、後で印刷する際の変換ミスを回避できます。 

Python では整数オーバーフローは問題になりませんが、固定幅の整数を使用する言語では、ブロック合計の大きさが数百万に達する可能性があるため、合計を 64 ビット型で格納する必要があります。

4
1 1 1 1
```和2を考えてみましょう。 

間隔:

 | 間隔 | 合計 |

 ## 特殊なケース

 次のことを考慮してください。```
3
1 1 1
```和が 2 の区間は次のとおりです。$(1,2)$そして$(2,3)$。 これらは位置 2 で重なっています。右のエンドポイントでソートした後、貪欲アルゴリズムは$(1,2)$。 届いたら$(2,3)$、条件`l > last_end`失敗する理由`2 > 2`は誤りです。 最適な間隔は 1 つだけ選択されます。 

次に、次のことを考えてみましょう。```
4
1 1 1 1
```合計 2 には、3 つの候補区間があります。 貪欲スキャンが選択するのは、$(1,2)$、スキップします$(2,3)$、そして選択します$(3,4)$。 答えのサイズは2つになります。 同じ合計の間隔を単にカウントするだけの不注意な実装では、誤って 3 が返されます。 

最後に、次のことを考慮してください。```
4
1 -1 1 -1
```間隔$(1,2)$そして$(3,4)$どちらも合計が 0 であり、重なりません。 負の数が存在する場合でも、アルゴリズムによってそれらがグループ化され、間隔スケジュールによって両方が選択されます。 単調和や正の値に関する仮定は使用されないため、この方法は正しいままです。
