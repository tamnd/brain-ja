 ## 問題の理解

 私たちに与えられた木は、$n$頂点と$n-1$エッジ。 すべてのエッジに会社番号を割り当てる必要があります。 都市に付随するすべての道路が異なる会社に属している場合、その都市は「良好」であるとみなされます。 少なくとも 2 つの事故道路が同じ会社を受けると、その都市は「悪い」になります。 

私たちが許されるのはせいぜい$k$悪い都市。 すべての有効な割り当ての中で、企業の数を最小限に抑える必要があります$r$。 可能な限り最小のものを見つけた後、$r$、会社番号を使用してエッジの有効なカラーリングを 1 つ出力する必要もあります。$1$に$r$。 

グラフはツリーです。これは、頂点の各ペアの間に単純なパスが 1 つだけ存在することを意味します。 入力ではすべての道路の終点が指定され、出力ではすべての道路に会社番号を割り当てる必要があります。 

制約こそが本当の課題なのです。 ツリーには最大で次のものを含めることができます$200\,000$したがって、すべての頂点を繰り返しスキャンしたり、多くの候補のカラーリングを試したりするアルゴリズムは、コストが高すぎます。 わずか 2 秒しか使用できないため、意図したソリューションは線形または$O(n \log n)$。 

重要な問題は、企業の数を最小限に抑えることが、ツリー全体に直接影響するわけではないということです。 個別の色の条件に違反することは、最大で許可されます。$k$頂点。 どの頂点を犠牲にするべきかを理解することが主な洞察です。 

頂点 1 を中心とする星について考えます。```
1-2
1-3
1-4
1-5
```と$k=1$。 

中心の次数は 4 です。頂点 1 が不良であることを許可すると、すべてのエッジが同じ色を使用する可能性があります。$r=1$。 すべての頂点を適切なものにしようと盲目的に試みるソリューションでは、4 つの異なる色が必要であるという誤った結論を下すことになります。 

もう 1 つの微妙なケースはパスです。```
1-2-3-4-5
```と$k=0$。 

すべての頂点の次数は最大 2 です。木のエッジを適切に色付けするには、次数だけが必要なので、答えは 2 ではありません。$\Delta$色、どこ$\Delta$は最大次数です。 ここ$\Delta=2$、パスに沿って色を交互に配置すると機能します。 すべてのエッジが一意の色を取得する必要があると想定する実装では、答えが過大評価されてしまいます。 

3 番目のトラップは、多くの頂点が同じ次数を共有する場合に発生します。 度数が次のとおりであるとします。```
5, 5, 5, 1, 1, ...
```そして$k=2$。 

次数 5 の頂点のうち任意の 2 つを選択して不良にすることができます。 答えは、どの特定の頂点が選択されるかではなく、3 番目に大きい次数によって決まります。 等しい次数を誤って処理する実装では、必要以上に大きな値が生成される可能性があります。$r$。 

## アプローチ

 強引な視点は企業数を推測すること$r$、次に、木を最大で色付けできるかどうかを判断してください。$r$せいぜい作成中に色を付ける$k$頂点が悪い。 

これはすぐに実行不可能になります。 単一の値をチェックするだけでも、$r$可能なエッジのカラーリングを探索することにより、膨大な検索スペースが得られます。 ある木$200\,000$頂点にはすでに含まれています$199\,999$エッジがあるため、組み合わせ検索は絶望的です。 

転換点は、何が多数の色を強制するのかを問うことから生じます。 

頂点を良好な状態に保つ必要がある場合、すべての入射エッジに個別の色が必要です。 次数の頂点$d$少なくともすぐに必要になります$d$利用可能な色。 

ここで、いくつかの頂点が不良である可能性があると判断したとします。 そうすれば、入射エッジがそこで色を繰り返すかどうかは気にしなくなります。 

この観察により、問題は完全に変わります。 大量の色数を強制する唯一の頂点は、良好な状態を維持するために選択した頂点です。 

度が降順に並べ替えられていると仮定します。$$d_1 \ge d_2 \ge \cdots \ge d_n.$$私たちが犠牲にできるのはせいぜい$k$頂点。 当然のことながら、最大次数の頂点は最も強い色の要件を課すため、それらの頂点を犠牲にする必要があります。 

それらを削除した後、$k$最悪の制約がある場合、必要最小限の色数は次のようになります。$$r = d_{k+1}.$$もし$k=0$、これは単に最大次数です。 もし$k=n-1$1 つを除くすべての頂点が不良である可能性があるため、$r=1$。 

残りのタスクは建設的です。正確に使用してエッジのカラーリングを生成します。$r$色。 

標準の木のエッジカラーリング DFS は、ここでは完璧に機能します。 トラバースしながら木の根を張ってエッジに色を付けます。 次数を超える頂点で$r$、意図的に繰り返しを許可します。 1 つおきの頂点で、すべての入射エッジに異なる色を割り当てます。 

なぜなら$r$に等しい$(k+1)$- 番目に大きい次数、最大でも$k$次数を超える頂点$r$。 それらは悪い頂点になります。

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、すべての頂点の次数を計算します。 
2. すべての度を降順に並べ替えます。 
3. しましょう$r$になる$(k+1)$- 番目に大きい次数。 ゼロベースのインデックス付けでは、これは次のようになります。`sorted_deg[k]`。 

この値は可能な最小の色数です。少なくとも次の理由からです。$n-k$頂点は良好なままでなければならず、次数のすべての良好な頂点は維持されなければなりません$d$必要$d$独特の色。 
4. 任意の頂点、たとえば頂点 1 でツリーをルートします。 
5. DFS を実行します。 
6. 現在の頂点をその親に接続するエッジに色があると仮定します。`parent_color`。 
7. 現在の頂点の子に対して、1 から 2 までの色を順番に割り当てます。$r$、スキップ`parent_color`。 

これにより、次数が次を超えない限り、この頂点のすべての入射エッジが明確な色を受け取ることが保証されます。$r$。 
8. カラーカウンターが超過した場合$r$、1に戻します。 

このようなラッピングでは、次数が次を超える頂点でのみ繰り返しカラーを作成できます。$r$。 これらはまさに私たちが悪者にしたい頂点です。 
9. すべてのエッジに割り当てられたカラーを、元の入力インデックスによって保存します。 
10. 出力$r$そしてすべてのエッジカラー。 

### なぜ効果があるのか

 重要な特性は、すべての頂点の次数が最大でも$r$すべての入射エッジでペアごとに異なる色を受け取ります。 

このような頂点では、1 つの色がその親へのエッジによってすでに占有されています。 DFS は、親の色をスキップしながら、すべての子エッジに個別の色を割り当てます。 入射エッジの総数が超えないため、$r$、利用可能な色が十分にあり、繰り返しは発生しません。 

繰り返しは、頂点の次数が次より大きい場合にのみ発生します。$r$。 このような頂点の数は最大で$k$、 なぜなら$r$として選ばれました$(k+1)$- 番目に大きい次数。 したがって、せいぜい$k$頂点が悪くなる。 

カラーリングは色のみを使用します$1 \ldots r$、不正な頂点の制限を満たしており、$r$最小限です。 したがって、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())

    g = [[] for _ in range(n)]
    deg = [0] * n
    edges = []

    for idx in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        edges.append((u, v))

        g[u].append((v, idx))
        g[v].append((u, idx))

        deg[u] += 1
        deg[v] += 1

    sorted_deg = sorted(deg, reverse=True)
    r = sorted_deg[k]

    ans = [0] * (n - 1)

    stack = [(0, -1, 0)]

    while stack:
        v, parent, parent_color = stack.pop()

        color = 1

        for to, eid in g[v]:
            if to == parent:
                continue

            if color == parent_color:
                color += 1

            if color > r:
                color = 1

            ans[eid] = color

            stack.append((to, v, color))

            color += 1
            if color > r:
                color = 1

    print(r)
    print(*ans)

if __name__ == "__main__":
    main()
```最初の部分では、隣接リストを構築し、頂点次数を計算します。 

ソートされた度数配列は 1 回だけ使用されます。 位置の値`k`まさに$(k+1)$- 番目に大きい次数。これが最適な色の数です。 

DFS は再帰的ではなく反復的です。 再帰的ソリューションは、ツリー上の Python の再帰制限をオーバーフローさせる可能性があります。$200\,000$頂点。 

変数`parent_color`現在の頂点につながるエッジの色を記録します。 子エッジに色を割り当てる場合、その色は可能な限りスキップされます。 これにより、低次数頂点での明確な入射色が保証されます。 

ラップアラウンド動作は意図的なものです。 頂点に以上のものがあると、`r`出来事の端では、繰り返しが避けられなくなります。 それらの頂点こそが、私たちが犠牲にできる頂点なのです。
