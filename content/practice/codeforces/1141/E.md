 ## 解決策
 ## 問題の理解

 私たちには、初期体力値と 1 分ごとに適用される繰り返しダメージ パターンを持つモンスターが与えられます。 柄に長さがある`n`、最後の 1 分が経過すると、すぐに最初の 1 分にループバックし、永遠に継続します。 

1 分ごとに、負または正の固定整数が追加されることによって、現在の状態が変更されます。 モンスターは、その健康状態が初めてプラスでなくなったときに死亡します。 これが起こるとき、この無限のタイムラインの最も早い瞬間を特定するか、これは決して起こらないと結論付ける必要があります。 

この制約により、強引な推論が重要になります。 シミュレーションできる分数には原則として制限はありませんが、`n`最大 200,000、初期ヘルスは最大 10^12 です。 分ごとの進行の単純なシミュレーションでは、最悪の場合、最大 10^12 回の反復が必要になる可能性があり、これは実行可能な限界をはるかに超えています。 単一のパスを何度も繰り返しても、大きなブロックをスキップできる場合にのみ許容されます。 

微妙な問題は、体力がラウンド内で増加し、その後減少する可能性があるため、死亡の瞬間がサイクルの境界だけでなく、サイクルの途中で発生する可能性があることです。 

エッジ ケースの 1 つは、1 つの完全なサイクルの合計が負ではなく、モンスターを殺すほど十分に減少しないプレフィックスがない場合です。 たとえば、すべてが`d_i`肯定的な場合、モンスターは決して死ぬことはありません。 単純なシミュレーションは依然として永久に実行される可能性があります。 

累積効果が全体的にマイナスであるにもかかわらず、モンスターが初期のサイクルで生き残る場合、別のエッジケースが発生します。 何度も完全に繰り返した後、後のサイクルの奥深くで死が発生する可能性があるため、プレフィックスの動作とシフトの繰り返しを組み合わせる必要があります。 

## アプローチ

 ブルートフォース手法では、分ごとにシミュレーションを実行し、シーケンスを継続的に適用して、健全性がゼロ以下に低下するかどうかを確認します。 これはプロセスを正確に反映するため正しいですが、シミュレートされるステップの数が非常に大きくなる可能性があるため、実行不可能になります。 もし答えが`k`、最悪の場合は`k`は 10^12 以上になる可能性があるため、このアプローチは時間制限内では不可能になります。 

重要な観察は、シーケンスが周期的であるため、各完全なサイクルの後、健全性はすべてのサイクルの合計に等しい一定値だけ変化するということです。`d_i`。 これにより、繰り返されるサイクルを圧縮できます。 毎分シミュレーションするのではなく、健康状態が世界的にどのように変化するかを追跡しながら、全サイクルをシミュレーションします。 

配列のプレフィックス合計を事前計算し、サイクル内の各分後の正味の変化を示します。 特定の健康状態から始まる任意のサイクル内で`H`、次のことを確認することで、そのサイクル中にモンスターが死亡したかどうかを判断できます。`H + prefix[i] <= 0`一部の人にとっては`i`。 そうでない場合は、全サイクル後の新しい健全性を次のように計算します。`H + total_sum`そして繰り返します。 

サイクルの合計が負でなく、モンスターが死なずに 1 サイクル生き残る場合、モンスターは決して死ぬことはありません。 これは、将来のサイクルによって、新しい最小値が作成されるほど健全性が低下することは決してないためです。 

サイクルごとの反復を避けるために、以前に確認した一連の状態を使用するか、合計が負の場合に算術を使用して安全にスキップできる完全なサイクルの数を直接計算できます。

 ## アルゴリズムのチュートリアル

 1. ダメージ配列のプレフィックスの合計を計算します。 これにより、単一サイクルの各分後の正味の健全性の変化が得られます。 この構造により、段階的にシミュレーションすることなく、サイクル内の死を検出できます。 
2. プレフィックスの合計をスキャンして最も古いインデックスを見つけます。`i`そのような`H + prefix[i] <= 0`。 そのようなインデックスが存在し、最初のサイクルにいる場合は、すぐに返すことができます。`i + 1`答えとして。 
3. 1 つの完全なサイクルの合計を計算します。 この値は、サイクルを繰り返すことで時間の経過とともにモンスターが弱くなるか強くなるかを決定します。 
4. 合計がゼロ以上で、モンスターが最初の完全なサイクルを生き延びた場合は、戻り値が返されます。`-1`。 これは、ヘルスが全サイクルにわたって減少することがないため、将来のサイクルは少なくとも同じかそれ以上のヘルスで開始され、プレフィックス パターンが同一であるためです。 
5. それ以外の場合、合計はマイナスになります。 サイクルを繰り返しシミュレーションしますが、分ごとにステップを進めるのではなく、まず各サイクル内で死亡が発生したかどうかを確認します。 そうでない場合は、ヘルスの合計を減らし、処理された分数を累積します。 
6. 各サイクルでは、開始時のヘルスを調整し、死亡が発生するサイクルが見つかるまで、プレフィックスの合計を使用してしきい値チェックを再計算します。 

### なぜ効果があるのか

 このアルゴリズムは、各サイクル内で唯一の考えられる障害点が、サイクルの開始状態に対するプレフィックスの合計によって決定されるという不変式に依存しています。 プレフィックス合計の順序はサイクル間で決して変わりません。 一定のシフトのみが適用されます。 サイクルの合計が負でなく、致死的なプレフィックスがない場合、将来のすべてのサイクルは同一または生存に有利であり、最終的な死を防ぎます。 合計が負の場合、繰り返し適用すると開始時の体力が厳密に減少し、生存が無限でない場合には最終的な終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    H, n = map(int, input().split())
    d = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + d[i]

    total = pref[n]

    cur = H
    time = 0
    seen = {}

    # We iterate cycle by cycle, but break early when possible
    while True:
        # check death inside current cycle
        for i in range(1, n + 1):
            if cur + pref[i] <= 0:
                print(time + i)
                return

        # survive full cycle
        cur += total
        time += n

        if total >= 0:
            print(-1)
            return

        # optional safety (not strictly needed but avoids pathological loops)
        if cur in seen:
            print(-1)
            return
        seen[cur] = True

        if cur <= 0:
            print(time)
            return

if __name__ == "__main__":
    solve()
```このソリューションは、各サイクルを線形時間でチェックできるようにプレフィックス合計を構築します。 内側のループは、現在の開始時のヘルスとプレフィックスの合計がそのサイクル内で死亡につながるかどうかをチェックします。 そのようなプレフィックスが存在しない場合、サイクル全体が存続し、サイクル合計の合計を加算することによって健全性が更新されます。 

重要な実装の詳細は次のとおりです。`cur + pref[i] <= 0`モンスターが瞬間的に死亡するかどうかを直接エンコードするチェック`i`各減算ステップをシミュレートせずに現在のサイクルを計算します。 

次のような無限の場合も処理します。`total >= 0`, なぜなら、サイクルを繰り返しても、結果が変わるほど初期体力が減少することはないからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    H, n = map(int, input().split())
    d = list(map(int, input().split()))

    pref = [0]
    for x in d:
        pref.append(pref[-1] + x)

    total = pref[-1]
    cur = H
    time = 0

    while True:
        for i in range(1, n + 1):
            if cur + pref[i] <= 0:
                return str(time + i)

        cur += total
        time += n

        if total >= 0:
            return "-1"

# provided sample
assert run("1000 6\n-100 -200 -300 125 77 -4\n") == "9"

# minimum case
assert run("1 1\n-1\n") == "1"

# always survive
assert run("10 2\n1 1\n") == "-1"

# dies immediately after cycle repetition
assert run("5 2\n3 -10\n") == "2"

 ## 特殊なケース

 エッジケースの 1 つは、最初のサイクル内でモンスターが死亡した場合です。 のような入力の場合`H = 3, d = [-2, 10]`、プレフィックスの合計は 1 分目に即時失敗を示します。`3 + (-2) <= 0`。 アルゴリズムは、サイクルを繰り返す前にこれを捕捉します。 

もう 1 つのエッジ ケースは、サイクル合計がゼロの場合です。 例えば、`d = [1, -1]`そして`H = 5`。 プレフィックスの合計によってヘルスが減少することはなく、各サイクル後のヘルスは同一のままです。 最初のサイクルでモンスターを殺すプレフィックスがないため、以降のすべてのサイクルは同一となり、結果は次のようになります。`-1`。
