 ## 問題の理解

 まずは数字から始めて、より大きな目標数字に到達したいと考えています。 唯一許可される演算は、現在の値に次の値を乗算することです。`2`またはによって`3`。 タスクは、必要な操作の数を判断するか、変換を実行できないことを報告することです。 

プロセスについて考えるのに役立つ方法は、開始値と目標値の間で何が変化するかを観察することです。 すべての動きは、追加の要素を導入するだけです`2`または`3`。 それ以外に何も現れることはありません。 ターゲットに他の素因数が含まれている場合`2`そして`3`、開始番号と比較すると、変換は不可能です。 

数字は最大でも`5 × 10^8`、これは十分に小さいため、除算を繰り返すことができます。`2`そして`3`非常に安いです。 最悪の場合でもそれ以下の数値`5 × 10^8`含まれる要素は 30 未満です`2`および 20 未満の要素`3`したがって、単純なループで十分です。 

いくつかの特殊なケースは注目に値します。 

開始値と目標値がすでに等しいと仮定します。 

入力：```
10 10
```出力：```
0
```操作は必要ありません。 常に少なくとも 1 つの乗算を実行するソリューションは、ここでは失敗します。 

ターゲットが開始値の倍数ではないとします。 

入力：```
48 72
```出力：```
-1
```すべての演算は現在の値を乗算するだけなので、係数を減らしたり削除したりすることはできません。 もし`m`で割り切れない`n`、そこに到達することは不可能です。 

比率に次の素因数が含まれていると仮定します。`2`または`3`。 

入力：```
4 20
```出力：```
-1
```比率は`20 / 4 = 5`。 乗算`2`そして`3`～の因子を決して作り出すことはできない`5`。 

## アプローチ

 ブルートフォースの観点では、各数値を状態として扱い、繰り返し乗算を試みます。`2`そして`3`目標に到達するまで。 すべてのエッジが 1 つの動きを表すため、幅優先検索では最終的に答えが見つかります。 

問題は数値の範囲が広いことです。 ターゲットはたったそれだけなのに、`5 × 10^8`、到達可能なすべての状態を探索するのは不必要な作業です。 状態グラフは移動の数とともに指数関数的に増加するため、一般的な検索は必要以上に複雑になります。 

重要な観察は、すべての有効な演算シーケンスが開始数値に次の累乗の組み合わせを乗算することです。`2`そして`3`。 

もし$$m = n \cdot 2^a \cdot 3^b,$$それから正確に`a + b`移動が必要です。 各乗算`2`～の一要素に寄与する`2`、および各乗算`3`～の一要素に寄与する`3`。 

これにより、問題は直ちに比率の分析に集約されます。$$r = \frac{m}{n}.$$もし`m`で割り切れない`n`、解決策はありません。 

それ以外の場合は分割を繰り返します`r`による`2`可能な限り、それが何回起こるかを数えてください。 次に、同じことを行います`3`。 それ以外に何か残っていたら`1`、比率には他の素因数が含まれており、変換は不可能でした。 残りの値が`1`、答えは単に実行された分割の合計数です。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. かどうかを確認します。`m`で割り切れます`n`。 

そうでない場合は出力`-1`なぜなら、乗算ではターゲット比率にすでに存在する要素を決して取り除くことができないからです。 
3. コンピューティング`r = m // n`。 

この比率は、次の乗算によって加算する必要があるすべてを表します。`2`そして`3`。 
4.初期化`moves = 0`。 
5. ながら`r`で割り切れます`2`で割ります`2`そして増加します`moves`。 

各除算は 1 回の乗算に対応します。`2`前進プロセス中。 
6.ながら`r`で割り切れます`3`で割ります`3`そして増加します`moves`。 

各除算は 1 回の乗算に対応します。`3`。 
7. 残量を確認する`r`。 

もし`r != 1`、以外のいくつかの素因数`2`または`3`残っているので出力`-1`。 
8. それ以外の場合は出力`moves`。 

### なぜ効果があるのか

 比率`m / n`ターゲットに到達するために必要な乗算変化を正確に捕捉します。 許可されたすべての操作は、次のいずれかの要素に寄与します。`2`または`3`したがって、到達可能な比率は次の形式でなければなりません。`2^a 3^b`。 

アルゴリズムはすべての要素を除去します。`2`そして`3`比率から。 何も残らない場合、比率は正確に`2^a 3^b`、 そして`a + b`操作は必要かつ十分です。 何らかの要素が残っている場合、許可された操作を使用して要素を作成することはできず、変換は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if m % n != 0:
        print(-1)
        return

    r = m // n
    moves = 0

    while r % 2 == 0:
        r //= 2
        moves += 1

    while r % 3 == 0:
        r //= 3
        moves += 1

    if r != 1:
        print(-1)
    else:
        print(moves)

solve()
```最初のチェックでは、ターゲットが開始値の倍数であることを確認します。 この条件がなければ、整数の除算は不可能なケースを隠してしまいます。 

変数`r`許可された操作によってまだ説明する必要がある比率を格納します。 で割るたびに`2`または`3`、対応する動きを 1 つカウントします。 

最終チェックが重要です。 あらゆる要素を取り除いた後、`2`そして`3`、残りの値は正確に次の値でなければなりません`1`。 そうでない場合は、禁止された素因数が残ります。 このチェックを怠ると、次のようなケースが誤って受け入れられます。`4 → 20`, ここで、比率は`5`。 

すべての算術演算は Python 整数内に快適に収まり、ループは対数的にのみ実行されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        n, m = map(int, input().split())

        if m % n != 0:
            print(-1)
            return

        r = m // n
        moves = 0

        while r % 2 == 0:
            r //= 2
            moves += 1

        while r % 3 == 0:
            r //= 3
            moves += 1

        print(moves if r == 1 else -1)

    solve()
    return sys.stdout.getvalue() if hasattr(sys.stdout, "getvalue") else ""

# provided sample
assert run("120 51840\n").strip() == "7", "sample 1"

# custom cases
assert run("1 1\n").strip() == "0", "equal values"
assert run("48 72\n").strip() == "-1", "ratio contains forbidden factor"
assert run("4 20\n").strip() == "-1", "factor 5 remains"
assert run("1 268435456\n").strip() == "28", "large power of 2"
assert run("9 162\n").strip() == "2", "one factor 2 and one factor 3"
