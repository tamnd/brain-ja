 ## 解決策
 ## 問題の理解

 1 日を表すバイナリ シーケンスが与えられます。各位置は 1 時間に対応します。 の値`1`ポリカルプがその時間中休んでいることを意味します。`0`彼は働いているという意味です。 同じシーケンスが永遠に繰り返されるため、1 日の最後の 1 時間が経過すると、次の 1 時間が再び同じスケジュールの最初の 1 時間になります。 

課題は、1 日の終わりと次の日の始まりの間の境界を越えて移動できる場合に、中断されない最長の休憩時間を決定することです。 

重要な点は、シーケンスが循環しているということです。 配列の終わり近くで始まるセグメントは、あたかも配列がループ内で端から端まで接続されているかのように、先頭から継続できます。 

入力サイズは 200,000 時間に達する場合があります。 これにより、可能な開始位置をすべてチェックして外側に拡張しようとする解決策は除外されます。これは、最悪の場合、二次関数の動作につながる可能性があるためです。 リニア スキャンが唯一の現実的なターゲットです。 

配列を線形として扱い、ラップアラウンドを無視すると、単純な間違いが発生します。 たとえば、`1 1 0 1 1 1`、正解は 4 です。`1 1`最後に接続します`1 1 1`初めに。 リニア スキャンでは誤って 3 が報告されます。 

もう 1 つの一般的なエッジ ケースは、配列が 1 つを除いて完全に 0 である場合です。 休憩時間はなく、単純な循環マージ戦略ではギャップを誤って休憩として扱う可能性があるため、正解は 0 です。 

## アプローチ

 ブルートフォース ソリューションでは、開始時間ごとに試行し、次のような問題に遭遇しながら前進します。`1`s、モジュロ演算を使用してラップアラウンドします。 開始位置ごとに、次の地点まで歩きます。`n`ステップ。 これにより、`O(n^2)`各開始点が配列のほぼ全体を横断する可能性があるため、最悪の場合にはアルゴリズムが実行されません。 と`n = 2 * 10^5`、これでは遅すぎます。 

問題の構造は円形配列を示唆しており、目標は、最も長く連続するブロックを見つけることです。`1`円の上にあります。 循環シーケンスの標準的な手法は、配列を複製して、ラップアラウンド セグメントを通常の連続セグメントに変換することです。 

建てたら`a + a`、元の配列で境界を越えるセグメントは、2 倍になった配列では通常のセグメントになります。 唯一の注意点は、有効なセグメントが長さを超えてはいけないことです。`n`というのは、まだ 1 日の 1 回転を表しているからです。 

したがって、問題は連続する最大数を見つけることになります。`1`s を 2 倍にした配列内で、次の値を超えてカウントしないようにします。`n`要素。

 ## アルゴリズムのチュートリアル

 1.長さの配列を読み取ります`n`。 これを循環、つまりインデックスとして扱います。`n - 1`インデックスに接続し直す`0`。 
2. 新しいアレイを作成する`b`それは`a`それ自体と連結されます。 これにより、循環隣接関係が通常の隣接関係に変換されるため、ラップアラウンド シーケンスは直線セグメントになります。 
3. 2 つの変数を初期化します。`best = 0`1 の最大連続値を保存し、`current = 0`スキャン中に現在の縞の長さを追跡します。 
4. の各要素を反復処理します。`b`左から右へ。 

現在の要素が`1`、増分`current`連勝が続いているので1つずつ。 そうであれば`0`、リセット`current`ストリークが切れたためゼロになります。 
5.アップデート後`current`、 アップデート`best`として`max(best, current)`。 
6. もし`current`を超える`n`、クランプで戻します`n`。 これにより、元の 1 日の 1 サイクルを超えるセグメントをカウントすることができなくなります。 
7.最後まで続ける`b`。 最終的な答えは、`best`。 

### なぜ効果があるのか

 元の配列内の連続する円形セグメントのすべての有効な円形セグメントは、二重化された配列内の連続するセグメントに正確に対応します。 倍増した配列をスキャンすることにより、考えられるすべてのラップアラウンド セグメントを暗黙的に列挙します。 唯一の制限は、以下を超えるものは使用できないことです。`n`なぜなら、それは 1 日の複数のサイクルを横断することを意味するからです。 単純な実行カウントを維持することで、すべての最大ブロックが確実にキャプチャされ、ゼロにリセットすることでセグメンテーションの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

b = a + a

best = 0
current = 0

for i in range(len(b)):
    if b[i] == 1:
        current += 1
        if current > n:
            current = n
    else:
        current = 0
    best = max(best, current)

print(best)
```この実装は、円形配列を線形配列に変換するという考えに直接従っています。 倍加ステップにより、ラップアラウンドセグメントが自然に処理されるようになります。 

唯一の微妙な点は、キャップです。`n`これにより、2 倍の配列により人為的に長いストリークが許可される場合に、実行が誇張されるのを防ぎます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input().strip())
    a = list(map(int, input().split()))
    b = a + a

    best = 0
    cur = 0

    for x in b:
        if x == 1:
            cur += 1
            if cur > n:
                cur = n
        else:
            cur = 0
        best = max(best, cur)

    print(best)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from io import StringIO
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_stdout
    sys.stdin = old_stdin
    return out.getvalue().strip()

 ## 特殊なケース

 インプットを考慮する`6 1 1 0 1 1 1`。 最適なセグメントは、末尾から先頭に回り込み、5 つの 1 が連続します。 

二重化された配列では、次のようになります。`1 1 0 1 1 1 1 1 0 1 1 1`。 スキャンはインデックス 0 で長さ 2 に達するストリークを開始し、2 で中断し、3 で再開し、境界を通って増加してインデックス 7 で 5 に達します。その時点で、`best`は 5 になり、変化しません。 

これにより、ラップアラウンド ケースが明示的なモジュラー演算なしで自然にキャプチャされることが確認されます。
