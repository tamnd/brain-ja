 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列 (s) と (t) があります。 文字列 (s) はボックスの上から下への現在の順序を表し、(t) は以前の順序を表します。 2 つの方法で変換できます。 まず、最初 (k) 文字を取り出して最後に移動することで、循環的に回転させることができます。 第 2 に、すべての文字は同じシーザー シフト (d) によって後方にシフトでき、アルファベットは後ろに回り込みます。`a`に`z`。 (k) と (d) の選択によって (s) が正確に (t) になるかどうかを判断する必要があります。 

必要な出力は次のいずれかです`Impossible`、 または`Success`その後に 1 つの有効なペア (k,d) が続きます。 回転は (0 \le k < n) を満たす必要がありますが、シフトは (-25) と (25) の間の整数だけで済みます。 26 ずつずらしても何も変わらないので、(0) から (25) までの代表値を使用すれば十分です。 

長さは (200,000) に達する可能性があるため、すべての回転を試してすべての (n) 文字を比較するには、(O(n^2)) 個の操作が必要になり、最悪の場合はおよそ (4\cdot10^{10}) 個の文字比較が必要になります。 これは、競技プログラミングの時間制限が対応できる範囲をはるかに超えています。 本質的に線形な解決策が必要です。 

直接実装が失敗する可能性のあるいくつかの特殊なケースがあります。 (n=1) の場合、隣接する文字のペアは存在しないため、適切なシーザー シフトによって単一文字列を等しくすることができます。 例えば、```
1
z
a
```答えがあります`Success`シフトが 26 を法として表される場合は、(k=0,d=-25) で、または等価的に (k=0,d=1) となります。通常の隣接差分配列を構築し、それに少なくとも 1 つの要素が含まれると想定する実装では、このケースを誤って処理する可能性があります。 

2 番目の問題は、周期境界です。 考慮する```
3
abc
bca
```ここで (s=\texttt{abc}) を 1 位置左に回転すると、`bca`, したがって、(k=1,d=0) が機能します。 最後の文字と最初の文字の間のペアは、循環構造の一部です。 位置 (0) と (1)、および (1) と (2) の間の差だけを比較すると、その境界に関する情報が失われ、実際には一致しない回転が誤って受け入れられる可能性があります。 

3 番目の問題は、シーザー シフトがアルファベットを包み込むことです。 例えば、```
1
a
z
```間の通常の数値差であっても、解くことができます。`a`そして`z`は、通常の整数の意味での有用な符号付きシフトではありません。 アルファベットの算術演算は 26 を法として実行する必要があります。 

## アプローチ

 直接的な解決策は、可能なすべての回転 (k) を試すことです。 回転ごとに、結果の文字列を構築または検査し、すべての文字を (t) の対応する文字に変換する 1 つのシーザー シフトがあるかどうかを確認します。 チェック自体は線形です。最初の文字が必要なシフトを決定すると、残りのすべての文字はまったく同じモジュール差を持たなければなりません。 (n) 回の回転があるため、これには (O(n^2)) 時間がかかります。 (n=200,000) の場合、最悪の場合約 (400) 億文字の比較となるため、方法は正しいですが、使用できません。 

重要な観察は、シーザー シフトによってすべての文字がまったく同じ量だけ変更されるということです。 したがって、隣接する 2 つの文字間の差が 26 を法として測定される場合、それらの差は変わりません。 

文字列 (x) の場合、その巡回差分シーケンスを次のように定義します。 

[
 \演算子名{diff}(x)_i=(x_{i+1}-x_i)\bmod 26,
 】

 ここで、(n-1) の後のインデックスは (0) に戻ります。 (x) のすべての文字を同じ量だけシーザー シフトすると、すべての違いの両方の文字が同じ加算を受け、その違いは相殺されます。 

したがって、2 つの文字列は、巡回差分シーケンスが等しい場合に正確にシーザー シフトによってのみ異なります。 回転操作は、この差分シーケンスを同じ量だけ回転するだけです。 したがって、元の問題はパターン マッチング問題になります。つまり、(s) の差分シーケンスの 2 つの連続したコピー内で (t) の差分シーケンスを見つけます。 

これはまさに KMP が役立つ状況です。 (t) の差分シーケンスをパターンとして構築し、それを検索します。`diff_s + diff_s`。 位置 (k) で始まる一致は、(s) を (k) だけ左に回転すると、巡回差が (t) の巡回差と同一である文字列が得られることを意味します。 (k) が分かると、シーザー シフトは最初の文字によって決定されます。 

差分表現が十分である理由は、単に必要条件であるというよりも強力です。 2 つの循環文字列が隣接するすべての位置で同じ違いを持つ場合は、対応する文字ペアを 1 つ選択します。 次のすべての文字は差によって強制されるため、すべての文字は 26 を法とする 1 つの共通の加法定数まで決定されます。その定数はまさにシーザー シフトです。

 ## アルゴリズムのチュートリアル

 1. すべての小文字を (0) から (25) までの数字に変換します。 これにより、Caesar は通常の算術シフトを 26 を法として実行します。 
2. 巡回差分配列を構築する`ds`(s) の場合。 すべての位置 (i) について、(s[i]) から次の文字までの差を保存し、最後の文字から最初の文字に折り返します。 対応する配列を構築する`dt`(t) の場合。 

これらの配列は、アルファベットの絶対位置とは関係なく、文字列の形状を記述します。 シーザー シフトは絶対位置を変更しますが、すべての違いは変更されません。 
3. (n=1) の場合、比較する差分情報はありません。 唯一可能な回転は (k=0) であり、必要なシーザー シフトは単に (s[0]) と (t[0]) の間のモジュラー差分です。 
4. (n>1) の場合、次のようにみなします。`dt`パターンとして検索してください`ds + ds`。 の循環回転`ds`は、通常の循環文字列ローテーションが 2 つのコピーの部分文字列になるのとまったく同じように、この 2 倍の配列の連続セグメントによって表されます。 
5. KMP プレフィックス関数を使用して、線形時間で一致を見つけます。 開始位置 (0) ～ (n-1) のみが個別の回転に対応するため、そのような位置で一致が見つかると、その位置が必要な回転 (k) になります。 
6.最初のキャラクターからシーザーシフトを回復します。 (s) を (k) だけ左に回転すると、その最初の文字は次のようになります。`s[k]`。 シーザー変換が (d) だけ後方にシフトすると、

 [
 t[0]\equiv s[k]-d\pmod{26},
 】

 それで

 [
 d\equiv s[k]-t[0]\pmod{26}。 
】

 この値は、ステートメントで許可されている (0) ～ (25) の範囲で出力されます。 
7. KMP が有効な開始位置を見つけられない場合、(t) と同じ巡回差分シーケンスを持つ回転はありません。 一般的なシーザー シフトには等しい巡回差分が必要であるため、答えは次のようになります。`Impossible`。 

### なぜ効果があるのか

 不変量は巡回差分シーケンスです。 シーザー シフトはすべての文字に同じ値を追加するため、隣接するモジュラーの差はすべて変更されません。 回転は循環シーケンスが開始する位置のみを変更するため、回転された (複数の) の差分シーケンスは正確に次の循環回転になります。`ds`。 

KMP は、次のことを正確に検出します。`dt`それらの周期的な回転の 1 つとして発生します。 位置 (k) にある場合、(s) を (k) だけ回転させた後、2 つの文字列は同一の差を持ちます。 最初の文字から始めて、後続のすべての文字は同じ定数モジュロ 26 によって強制的に異なります。シーザー シフトとしてその定数を選択すると、正確に (t) が生成されます。 逆に、有効な変換はすべての循環差分を保存する必要があるため、その回転は KMP 一致として表示される必要があります。 したがって、アルゴリズムは有効な答えが存在するときはいつでもそれを見つけることができ、無効な答えを受け入れることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def differences(s):
    n = len(s)
    return [
        (ord(s[(i + 1) % n]) - ord(s[i])) % 26
        for i in range(n)
    ]

def prefix_function(pattern):
    m = len(pattern)
    pi = [0] * m

    for i in range(1, m):
        j = pi[i - 1]

        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]

        if pattern[i] == pattern[j]:
            j += 1

        pi[i] = j

    return pi

def solve():
    n = int(input())
    t = input().strip()
    s = input().strip()

    if n == 1:
        d = (ord(s[0]) - ord(t[0])) % 26
        print("Success")
        print(0, d)
        return

    ds = differences(s)
    dt = differences(t)

    pi = prefix_function(dt)

    # We only need 2*n - 1 elements. A match starting at n
    # would be the same cyclic rotation as starting at 0.
    text_length = 2 * n - 1
    j = 0

    for i in range(text_length):
        value = ds[i % n]

        while j > 0 and value != dt[j]:
            j = pi[j - 1]

        if value == dt[j]:
            j += 1

        if j == n:
            k = i - n + 1

            if k < n:
                d = (ord(s[k]) - ord(t[0])) % 26
                print("Success")
                print(k, d)
                return

            j = pi[j - 1]

    print("Impossible")

if __name__ == "__main__":
    solve()
```の`differences`関数は、アルゴリズムで記述された巡回表現を構築します。 表現`(i + 1) % n`最後の文字から最初の文字までのエッジを処理します。回転は線形ではなく周期的であるため、これは不可欠です。 

プレフィックス関数は、標準の KMP 前処理です。`pi[i]`位置で終わるサフィックスでもあるパターンの最も長い適切なプレフィックスの長さを格納します`i`。 これにより、不一致が発生した場合に、検索を最初からやり直すのではなく、情報を再利用できるようになります。 

検索は物理的に構築されません`ds + ds`。 その代わり、`ds[i % n]`概念的な double 配列の対応する文字にアクセスします。 これにより、一時的な配列が 1 つ節約され、周期的な性質が明確になります。 を繰り返します`2*n - 1`すべての回転は、(0) から (n-1) までのインデックスで始まる長さ (n) のセグメントで表すことができるためです。 (n) から開始すると、(0) から開始する回転が複製されます。 

の表現`d`注目に値する。 変換は後方シフトなので、`t[0]`等しい必要があります`s[k] - d`モジュロ 26. 並べ替えると、`d = s[k] - t[0]`モジュロ 26. Python の`% 26`は非負の結果を生成するため、戻り値は (0,\ldots,25) にあり、そのすべてが許容範囲を満たします。 

格納されている差分はすべて (0) と (25) の間であり、プレフィックス配列には (0) と (n) の間の値が含まれるため、整数オーバーフローの心配はありません。 Python の整数にも任意の精度があります。

import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    try:
        n = int(input())
        t = input().strip()
        s = input().strip()

        if n == 1:
            d = (ord(s[0]) - ord(t[0])) % 26
            return f"Success\n0 {d}\n"

        def differences(x):
            return [
                (ord(x[(i + 1) % n]) - ord(x[i])) % 26
                for i in range(n)
            ]

        ds = differences(s)
        dt = differences(t)

        pi = [0] * n

        for i in range(1, n):
            j = pi[i - 1]
            while j > 0 and dt[i] != dt[j]:
                j = pi[j - 1]
            if dt[i] == dt[j]:
                j += 1
            pi[i] = j

        j = 0

        for i in range(2 * n - 1):
            value = ds[i % n]

            while j > 0 and value != dt[j]:
                j = pi[j - 1]

            if value == dt[j]:
                j += 1

            if j == n:
                k = i - n + 1

                if k < n:
                    d = (ord(s[k]) - ord(t[0])) % 26
                    return f"Success\n{k} {d}\n"

                j = pi[j - 1]

        return "Impossible\n"

    finally:
        sys.stdin = old_stdin

def run(inp: str) -> str:
    return solve_data(inp)

def validate(inp: str, output: str) -> bool:
    lines = output.strip().splitlines()

    first = lines[0]
    n, t, s = inp.strip().splitlines()
    n = int(n)

    if first == "Impossible":
        return True

    assert first == "Success"
    k, d = map(int, lines[1].split())

    assert 0 <= k < n
    assert -26 < d < 26

    rotated = s[k:] + s[:k]

    result = ''.join(
        chr((ord(c) - ord('a') - d) % 26 + ord('a'))
        for c in rotated
    )

    return result == t

 |`5 / aaaaa / zzzzz`| 任意の有効な`Success`| すべての周期的な差はゼロに等しい |
 |`4 / abcd / dabc`| 任意の有効な`Success`(k=3) | 境界回転 (k=n-1) |
 |`5 / abcde / efabc`| 任意の有効な`Success`| シーザーシフトと組み合わせた回転 |
 | (n=200000)、すべて`a`対すべて`z`| 任意の有効な`Success`| 最大入力サイズと線形パフォーマンス |

 ## 特殊なケース

 巡回差分配列には 1 つの差分、つまり文字からそれ自体に戻る差分のみが含まれており、常に 0 であるため、単一文字の場合は別個の処理が必要です。 より直接的には、可能な回転は 1 つ (k=0) だけです。```
1
z
a
```必要な後方シフトは (a=z-d\pmod{26}) を満たし、(d=25) を与えます。これはサンプルの (d=-25) モジュロ 26 に相当します。実装は有効な代表を返します。`25`。 

巡回境界は差分を構築するときに処理されます。 のために```
3
abc
bca
```の差分列`abc`は`(1,1,24)`、 その間`bca`もっている`(1,24,1)`。 2 番目のシーケンスは、1 位置だけ左に回転された最初のシーケンスであるため、KMP は (k=1) を見つけます。 最後と最初の違いを無視すると、これらの循環配置を区別するために必要な情報が正確に失われます。 

アルファベットのラッピングは`% 26`。 たとえば、シフトする`z`25 だけ後ろ向きにすると`a`、 それでも`ord('z') - ord('a')`通常の整数演算では 25 です。 モジュール式はアルファベットをサイクルに変換します。これがシーザー暗号の実際の構造です。 

すべて等しい文字列は、もう 1 つの有用なストレス ケースです。 のために```
5
aaaaa
zzzzz
```両方の文字列のすべての巡回差はゼロです。 したがって、すべての回転は構造的に有効であり、シーザー シフトのみが問題となります。 アルゴリズムは (k=0) を返す可能性がありますが、回転も正しいはずです。 

最後に、(k=n-1) での一致により、上部回転境界が適用されます。 のために```
4
abcd
dabc
```必要な回転はちょうど 3 つの位置です。 最初の (n-1) 位置のみを検索すると、この有効な答えが得られませんが、開始位置をチェックせずに完全な 2 倍のシーケンスを検索すると、位置 (n) で重複した回転がカウントされる可能性があります。 実装の検索`2*n-1`位置を指定し、一致するもののみを受け入れます`k < n`、すべての個別の回転を 1 回だけカバーします。
