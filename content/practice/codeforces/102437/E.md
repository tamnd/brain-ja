 ## 解決策
 ## 問題の理解

 2 つの注文があり、それぞれ長さ (n) の文字列で表されます。 (i) 番目の文字は、スタック内の (i) 番目のボックスの商品番号を表します。 現在の順序 (s) を前の順序 (t) に変換できるかどうかを判断する必要があります。 

許可される変換には 2 つの独立した部分があります。 まず、すべての文字が同じシーザー シフト (d) によって、循環的に 26 を法としてシフトされます。第 2 に、スタックを回転できます。これは、(s) の接頭辞が上から下に移動することを意味します。 回転量が (k) の場合、結果の次数は次のようになります。 

[
 s[k:] + s[]。 
]

 両方の操作の後、結果の文字列は (t) に等しくなる必要があります。 有効なペア ((k,d)) を出力するか、レポートする必要があります。`Impossible`。 

長さは最大 (200,000) まで可能です。 すべての回転を検査し、すべての (n) 文字を比較するアルゴリズムでは、最悪の場合、最大 (n^2 = 40,000,000,000) 文字の比較が実行されますが、これは実用的なレベルをはるかに超えています。 本質的に文字列の長さが線形である解決策が必要です。 

単純な実装を壊す可能性のあるエッジケースがいくつかあります。 1 つ目は (n=1) です。 検索する意味のある回転はありませんが、それでもシーザー シフトが必要な場合があります。 例えば、```
1
z
a
```シフトするため、(k=0) で解くことができます。`z`25 だけ後ろ向きにすると`a`。 検査する隣接する文字があることを前提とした実装は、この場合には失敗します。 

もう 1 つのエッジケースは、アルファベットのラップアラウンドです。 例えば、```
1
a
z
```も解決可能です。 必要なシフトは (d=1) として表すことができます。`z`1 だけ後ろに戻すと`y`、シフトしながら`a`1 だけ後ろに戻すと`z`。 算術演算は、通常の整数の差を使用するのではなく、26 を法として実行する必要があります。 

3 番目の問題は、文字列の端での回転です。 考慮する```
5
abcde
bcdea
```回転中`bcdea`(4) 位置によって生成される`abcde`, したがって、正解は (k=4) と (d=0) で存在します。 通常の部分文字列のみをチェックする検索`s`そして、循環境界がこの解決策を見逃すことを忘れています。 

最後に、文字を繰り返すことで複数の回転を有効にすることができます。 例えば、```
4
aaaa
aaaa
```はすべての回転を有効な回転として持ち、(d=0) はそれらすべてに対して機能します。 アルゴリズムは、一意性に依存するのではなく、最初の有効な候補を受け入れる必要があります。 

## アプローチ

 直接的な解決策は、可能なすべての回転 (k) を試すことです。 回転ごとに、回転された (s) のすべての文字を (t) の対応する文字と比較します。 最初の位置のペアによってシーザー シフトが決定され、残りのすべての位置が 26 を法とするまったく同じシフトを持つ必要があります。この方法は、考えられるすべての変換を明示的にチェックするため、正しいです。 

問題は繰り返し作業の量です。 (n) 回転があり、1 回転のチェックには (O(n)) 時間がかかります。 (n=200,000) では、最悪のケースで (200,000^2=40,000,000,000) 文字チェックに達します。 ブルート フォースは概念的には単純ですが、二次関数の動作により排除されます。 

有益な観察は、シーザー シフトによって隣接する文字間の差異が変化しないことです。 もし`x`に変更されます`x-d`そして`y`に変更されます`y-d`、その後、それらの違いは残ります

 [
 (y-d)-(x-d)=y-x \pmod {26}。 
]

 したがって、元の文字を比較する代わりに、連続する文字間の差異の循環シーケンスを比較できます。 

文字列 (x) については、次のように定義します。 

(x[(i+1)\bmod n]-x[i])\bmod 26.
 ]

 このシーケンスには、最後の文字から最初の文字までの違いも含まれているため、正確に (n) 個の要素があります。 

シーザー シフトの前に、位置 (s) を (k) ずつ回転すると正しい配置が得られると仮定します。 その巡回差分シーケンスは、単に (k) の位置から始まる (s) の巡回差分シーケンスです。 その後、シーザーシフトによって差異はまったく変わりません。 したがって、有効な回転は、(t) の巡回差分シーケンスが (s) の巡回差分シーケンスの巡回回転として発生するときに正確に存在します。 

循環シーケンスの中に別の循環シーケンスを見つけることは、標準的な文字列マッチング問題です。 (s) の差分シーケンスをそれ自体と連結し、Knuth-Morris-Pratt アルゴリズムを使用して、(O(n)) 時間で (t) の差分シーケンスを見つけることができます。 一致する開始位置 (k) が見つかると、最初の文字によってシーザー シフトが決定されます。 

[
 d=(s[k]-t[0])\bmod 26.
 ]

 差分表現は回転の問題を解決し、KMP は検索を線形にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (s) と (t) のすべての文字を 0 から 25 までの数値に変換します。これにより、すべてのシーザー シフト演算を通常のモジュラー演算で実行できるようになります。 
2. 巡回差分配列を構築する`ds`(s) の場合。 すべての位置 (i) について、(s[i]) から (s[(i+1)\bmod n]) までの差を 26 を法として保存します。`dt`(t) についてもまったく同じ方法で計算します。 
3. KMP プレフィックス関数を構築します。`dt`。 プレフィックス関数は、不一致が発生した後もパターンのどのくらいがまだ使用可能であるかを示すため、検索を最初からやり直す必要はありません。 
4. 検索`dt`内部`ds + ds`。 巡回配列の回転は、その 2 倍になったバージョンの連続セグメントに対応します。 それらは正確に (n) 個の可能な回転であるため、(n) より小さいインデックスで始まる一致のみを受け入れます。 
5. 一致するものがない場合は、印刷します。`Impossible`。 有効な変換には循環差の一致が必要であるため、シーザー シフトでは欠落した回転を修復できません。 
6. 試合が (k) から始まる場合、次のように計算します。 

[
 d=(s[k]-t[0])\bmod 26.
 ]

 回転された文字列は次で始まります`s[k]`。 その文字を (d) だけ後方にシフトすると、次のようになります。`t[0]`したがって、この方程式は必要なシーザー シフトを正確に与えます。 

1. 印刷`Success`、次に (k) と (d) が続きます。 モジュロ 26 によって生成される値は 0 ～ 25 の範囲にあり、必要な範囲 (-26<d<26) を満たします。 

### なぜ効果があるのか

 中心となる不変条件は、2 つの文字列の対応する巡回差が等しい場合にのみ、一様なシーザー シフトによってのみ異なるということです。 シーザー シフトは、隣接する 2 つの文字が減算されるとキャンセルされるため、差分配列に影響を与えることはできません。 

(k) による回転は、巡回差分配列の開始点を変更するだけです。 検索中`dt`内部`ds + ds`したがって、相対文字構造が (t) の文字構造と一致する回転を正確に検索します。 このような回転が見つかると、隣接するすべての差が一致するため、回転された (s) と (t) の差はサイクル全体にわたって一定になります。 その定数は、まさに最初の文字から計算されたシーザー シフトです。 したがって、報告されたすべてのペア ((k,d)) は (t) を生成し、有効なペアが存在する場合は、その回転が KMP 検索に表示される必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_diff(s):
    n = len(s)
    if n == 1:
        return []
    return [
        (ord(s[(i + 1) % n]) - ord(s[i])) % 26
        for i in range(n)
    ]

def prefix_function(pattern):
    m = len(pattern)
    pi = [0] * m

    for i in range(1, m):
        j = pi[i - 1]

        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j - 1]

        if pattern[i] == pattern[j]:
            j += 1

        pi[i] = j

    return pi

def solve():
    n = int(input())
    t = input().strip()
    s = input().strip()

    if n == 1:
        d = (ord(s[0]) - ord(t[0])) % 26
        print("Success")
        print(0, d)
        return

    ds = build_diff(s)
    dt = build_diff(t)

    pi = prefix_function(dt)

    j = 0
    doubled = ds + ds

    for i, value in enumerate(doubled):
        while j > 0 and value != dt[j]:
            j = pi[j - 1]

        if value == dt[j]:
            j += 1

        if j == n:
            start = i - n + 1

            if start < n:
                d = (ord(s[start]) - ord(t[0])) % 26
                print("Success")
                print(start, d)
                return

            j = pi[j - 1]

    print("Impossible")

if __name__ == "__main__":
    solve()
```の`build_diff`関数は文字列を巡回差分シーケンスに変換します。 表現`(i + 1) % n`最後から最初へのエッジを処理します。これは、回転が通常の部分文字列操作ではなく循環的なため必要です。 

(n=1) の場合は、その差分シーケンスが空になるため、個別に処理されます。 可能な回転は 1 つ (k=0) のみであり、シーザー シフトは 2 つの文字から直接取得できます。 

プレフィックス関数は次の場合にのみ計算されます。`dt`。 KMP 検索中に、`ds + ds`のすべての周期的回転を表します`ds`通常の連続セグメントとして。 最初 (n) の可能な開始位置は (k=0,\ldots,n-1) に正確に対応します。 

KMPが到達すると`j == n`、ターゲットの差分シーケンス全体が一致しました。 表現`i - n + 1`その試合の始まりを告げます。 (n) 以降の開始は、配列を 2 倍にすることによって作成された重複一致であるため、拒否します。 

ついに、`d = (ord(s[start]) - ord(t[0])) % 26`シーザー作戦の指示に直接従う。 回転させた文字が`c`、(d) だけ後方にシフトすると、次のようになります。`c-d`、だから必要です`c-d = t[0] (mod 26)`。 並べ替えると、コードで使用される式が得られます。 

Python の整数には任意の精度があるため、オーバーフローの問題はありません。 すべてのインデックスは (2n) 以内に収まり、すべての文字変換は定数時間で行われます。

```すべての周期的な差はゼロであるため、すべての回転が一致します。 KMP は最初の文字 (k=0) を受け入れ、最初の文字は (d=0) を与えます。 問題ではそれらのいずれか 1 つを受け入れるため、複数の有効な回答を区別する必要はありません。 

最も微妙な正確性のケースは、差分シーケンスは一致するが、文字列の最初の文字が最初は同じではない場合です。 例えば、```
3
abc
def
```両方の文字列の巡回差分シーケンスは次のようになります。`[1, 1, 24]`したがって、(k=0) は有効な構造一致です。 最初の文字の違いにより、

 [
 d=(d-a)\bmod26=3。 
]

 シフトする`def`3 だけ逆方向に生成します`abc`。 これは、差異のマッチングだけが最終ステップではない理由を示していますが、残りの作業が 1 つのグローバル シーザー シフトの決定に減ります。
