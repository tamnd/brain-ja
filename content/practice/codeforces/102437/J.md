 ## 解決策
 ## 問題の理解

 ロボットは整数平面内で移動し、2 つの固定回転中心、点 ((0,0)) と ((1,0)) を持ちます。 各コマンドは、これら 2 つの中心のいずれかを中心に、現在位置を時計回りまたは反時計回りに正確に (90^\circ) だけ回転します。 したがって、4 つのコマンドは、現在の座標の 4 つのアフィン変換にすぎません。 

現在の点が ((x,y)) の場合、変換は次のようになります。 

[
 1:(x,y)\mapsto(y,-x),
 ]

 [
 2:(x,y)\mapsto(-y,x),
 ]

 [
 3:(x,y)\mapsto(y+1,1-x),
 ]

 [
 4:(x,y)\mapsto(1-y,x-1)。 
]

 出発点と別の目的地が与えられます。 このタスクは、最初の点を 2 番目の点に変換する最大 (10^6) 個のコマンドのシーケンスを出力するか、そのようなシーケンスが存在しない場合は (-1) を出力することです。 

座標は絶対値で (100000) で区切られているため、2 点間の変位はどちらの座標でも最大で (200000) になります。 巨大な状態グラフを明示的に調査するアプローチは不必要であり、必要な応答自体に数十万のコマンドが含まれる可能性があるため、潜在的に危険です。 ここでは、実行時間が基本的に出力の長さに比例する構造が必要です。これは簡単に十分に高速です。 

不注意な構築によって誤って処理される可能性がある 2 つのエッジケースがあります。 まず、等しいパリティが必要です。 例えば、```
0 1
1 1
```生産しなければならない`-1`。 すべてのコマンドは (x+y) のパリティを保持するため、2 つの点を接続することはできません。 座標が「近い」ように見えるかどうかだけをチェックする検索では、この不変条件が見逃される可能性があります。 

第 2 に、目的地は開始点とは異なることが保証されていますが、中間の翻訳では係数がゼロになる可能性があります。 例えば、```
0 0
1 1
```((1,1)) 方向への単位変換は 1 つだけ必要です。 1 つの方向のみが必要な場合に誤って空の答えを出力するのではなく、1 つの係数がゼロになるように構築する必要があります。 

提供されたステートメントのサンプルの 2 番目の入力に書式破損がありますが、元の問題では 2 番目のサンプルが次のようになります。```
0 1
1 1
```出力あり`-1`。 

## アプローチ

 直接的な総当たりアプローチは、すべての整数点をグラフの頂点とみなして、到達可能なすべての点から 4 つのコマンドすべてを試行することです。 それぞれの動きは決定的であるため、幅優先探索では、ターゲットに到達できるときはいつでも、最終的に最短のシーケンスが見つかります。 すべての正当なコマンドはエッジで表されるため、これは正しいです。 

問題は、平面が境界がなく、入力に関連する座標範囲内であっても、およそ (400000^2) 個の可能な整数位置があることです。 これは (1.6\cdot10^{11}) 状態付近であり、2 秒の実装で探索できるものをはるかに超えています。 検索範囲がはるかに小さい場合でも受け入れられません。 

有益な観察は、2 つの異なる中心の周りの回転を組み合わせると平行移動が生成されるということです。 コマンド (1) を実行し、続いてコマンド (4) を実行します。 コマンド(1)は原点を中心に時計回りに回転し、コマンド(4)は((1,0))を中心に反時計回りに回転します。 代数的には、

 [
 (x,y)\xrightarrow{1}(y,-x)
 \xrightarrow{4}(x+1,y-1)。 
]

 したがって、2 つのコマンド シーケンスは`14`現在の座標に関係なく、すべての点を正確に ((1,-1)) だけ移動します。 

その逆は`32`、すべての点を ((-1,1)) だけ移動します。 

次に、この平行移動を (90^\circ) だけ回転させます。 シーケンス`1142`の共役です`14`すべての点を ((1,1)) だけ移動します。 その逆は`1322`、すべての点を ((-1,-1)) だけ移動します。 

これにより、幾何学的な問題が通常の整数演算に単純化されます。 必要な変位が

 [
 (dx,dy)=(x_2-x_1,y_2-y_1)、
 ]

 次のように書くことができます

 a(1,1)+b(1,-1)、
 ]

 どこで

 [
 a=\frac{dx+dy}{2}、
 \qquad
 b=\frac{dx-dy}{2}。 
]

 (dx) と (dy) が同じパリティを持つ場合、つまり (x_1+y_1) と (x_2+y_2) が同じパリティを持つ場合、これらの係数は整数になります。 

そのパリティ条件も必要です。 コマンド(1)では、

 [
 x+y\マップを y-x、
 ]

 これは (x+y) と同じパリティを持ちます。 同じ計算が 4 つのコマンドすべてに当てはまります。 したがって、(x+y) のパリティはプロセス全体の不変量です。 

したがって、条件は必要かつ十分です。 それが成立する場合は、2 つの利用可能な翻訳を必要な回数だけ繰り返すだけです。 

(a) または (b) のいずれかで取り得る最大の絶対値は (200000) です。 対角変換ではユニットごとに 4 つのコマンドが使用され、((1,-1)) 変換ではユニットごとに 2 つのコマンドが使用されます。 最悪の場合はコマンド数が最大 (800000) であるため、必要な (10^6) 制限は問題なく尊重されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(V+E))、潜在的に (10^{11}) 状態 | (O(V)) | 遅すぎる |
 | 翻訳構築 | (O( | a | + | b | )) | (O( | a | + | b | )) の答え | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始点 ((x_1,y_1)) と目的地 ((x_2,y_2)) を読み取り、計算します。 

[
 dx=x_2-x_1、\qquad dy=y_2-y_1。 
]

 生成された変換はどこでも同じように動作するため、構造全体はこの変位のみに依存します。 

1. (dx) と (dy) が同じパリティを持っているかどうかを確認します。 同様に、次のことを確認します。 

[
 (dx+dy)\bmod 2=0。 
]

 これが false の場合は、印刷します`-1`。 すべての正当なコマンドは (x+y) のパリティを保持するため、シーケンスが宛先に到達することはできません。 

1. コンピューティング

 [
 a=\frac{dx+dy}{2}、\qquad b=\frac{dx-dy}{2}。 
]

 それから

 # (a+b,a-b)

 (dx、dy)。 
]

 変位は、生成方法がわかっている 2 つの平行移動に分解されました。 

1. (a>0) の場合、追加します。`1142`ちょうど (a) 回です。 このシーケンスは、現在の点を ((1,1)) だけ変換します。 (a<0) の場合は追加します`1322`正確に (-a) 回、((-1,-1)) で変換します。 

の 4 つのコマンド`1142`恣意的なトリックではありません。 これらは基本的な翻訳の共役です`14`(90^\circ) 回転するので、その変位は回転ベクトル ((1,-1))、つまり ((1,1)) になります。 

1. (b>0) の場合、追加します。`14`ちょうど (b) 回です。 (b<0) の場合は追加します`32`ちょうど (-b) 回です。 これらの変換は (b(1,-1)) に寄与します。 
2. 結果のコマンド文字列には正確なディスプレイスメントが含まれます

 [
 a(1,1)+b(1,-1)=(dx,dy)、
 ]

 したがって、ロボットは ((x_2,y_2)) で終了します。 その長さと文字列を出力します。 

### なぜ効果があるのか

 中心不変量は (x+y) のパリティです。 個々のコマンドはすべてそれを保持し、異なるパリティ クラスが決して通信できないことを証明しています。 パリティが一致する場合、(dx)と(dy)は同じパリティを持つため、(a)と(b)は整数になります。 コマンドシーケンス`14`、`32`、`1142`、 そして`1322`それぞれ ((1,-1))、((-1,1))、((1,1))、((-1,-1)) による変換を実現します。 それらの組み合わせにより、2 つの座標が同じパリティを持つすべての変位が生成されます。 したがって、アルゴリズムは到達可能な点のペアに対して正確に成功します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    # Every operation preserves the parity of x + y.
    if (dx + dy) & 1:
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    if a > 0:
        ans.append("1142" * a)
    elif a < 0:
        ans.append("1322" * (-a))

    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("32" * (-b))

    s = "".join(ans)

    print(len(s))
    print(s)

if __name__ == "__main__":
    solve()
```最初のパリティ チェックは、到達可能性の不変式に直接対応します。 使用する`(dx + dy) & 1`は、浮動小数点演算に依存せずに整数のパリティをチェックするため、負の Python 整数に対しても安全です。 

係数は、パリティ テストで両方の分子が偶数であることが確認された後にのみ、整数の除算で計算されます。 丸めは行われません。 

正の (a) の場合、`1142`((1,1)) によって変換されるため、繰り返されます。 負の (a) の場合、`1322`はその逆です。 同じく、`14`そして`32`は、((1,-1)) 方向に沿った逆変換です。 

答えは、ネストされた Python 操作内に個々の文字を追加するのではなく、文字列として組み立てられます。 最大の答えは (10^6) 文字未満であるため、これは通常のメモリ制限内に十分収まります。 

翻訳は相互に変換されるため、2 つの翻訳グループの順序は重要ではありません。 最初にすべての対角移動を適用し、次にすべての反対角移動を適用すると、他の順序とまったく同じ最終変位が得られます。 

## 実用的な例

 ### サンプル 1

 最初のサンプルは ((0,1)) から始まり、((1,-2)) に到達する必要があります。 

変位とその分解は次のとおりです。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (1) |
 | (ダイ) | (-3) |
 | (dx+dy) | (-2) |
 | (a=(dx+dy)/2) | (-1) |
 | (b=(dx-dy)/2) | (2) |

 (a=-1) なので、アルゴリズムは次のように出力します。`1322`、((-1,-1)) だけ移動します。 (b=2) なので、放射します。`1414`、((2,-2)) だけ移動します。 

総変位は

 [
 (-1,-1)+(2,-2)=(1,-3)、
 ]

 それで

 [
 (0,1)+(1,-3)=(1,-2)。 
]

 したがって、アルゴリズムは 8 つのコマンドの有効なシーケンスを出力します。 公式サンプルではたまたまもっと短いシーケンスが使用されています`24`ただし、長さを最小限に抑える必要はありません。 この問題は、最大 (10^6) 個のコマンドの有効なシーケンスを受け入れます。 

### サンプル 2

 オリジナルの 2 番目のサンプルは、```
0 1
1 1
```変位は ((1,0)) です。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (1) |
 | (ダイ) | (0) |
 | (dx+dy) | (1) |
 | パリティチェック | 失敗する |
 | 結果 |`-1`|

 2 つの変位座標は異なるパリティを持っているため、次を満たす整数ペア (a,b) は存在しません。 

[
 (dx,dy)=a(1,1)+b(1,-1)。 
]

 より基本的には、開始点は (x+y=1) であり、目的地は (x+y=2) です。 すべてのコマンドがそのパリティを保持するため、ターゲットには到達できません。

## テストケース

 有効な答えは一意ではないため、テストでは正確なコマンド文字列を比較するのではなく、生成されたコマンド シーケンスを検証する必要があります。 以下のヘルパーは、4 つの変換すべてを個別にシミュレートし、最終的な位置が正しいことを確認します。 また、(10^6) コマンド制限もチェックします。```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        x1, y1 = map(int, input().split())
        x2, y2 = map(int, input().split())

        dx = x2 - x1
        dy = y2 - y1

        if (dx + dy) & 1:
            return "-1\n"

        a = (dx + dy) // 2
        b = (dx - dy) // 2

        ans = []

        if a > 0:
            ans.append("1142" * a)
        elif a < 0:
            ans.append("1322" * (-a))

        if b > 0:
            ans.append("14" * b)
        elif b < 0:
            ans.append("32" * (-b))

        s = "".join(ans)
        return f"{len(s)}\n{s}\n"
    finally:
        sys.stdin = old_stdin

def run(inp: str) -> str:
    return solve_data(inp)

def verify(inp: str):
    x1, y1 = map(int, inp.splitlines()[0].split())
    x2, y2 = map(int, inp.splitlines()[1].split())

    out = run(inp).strip().splitlines()

    if out[0] == "-1":
        return False, "reported impossible"

    k = int(out[0])
    s = out[1]

    assert k == len(s)
    assert 0 < k <= 10**6
    assert all(c in "1234" for c in s)

    x, y = x1, y1

    for c in s:
        if c == "1":
            x, y = y, -x
        elif c == "2":
            x, y = -y, x
        elif c == "3":
            x, y = y + 1, 1 - x
        else:
            x, y = 1 - y, x - 1

    return (x, y) == (x2, y2), (x, y)

# Provided sample 1. Any valid sequence is accepted.
ok, _ = verify("0 1\n1 -2\n")
assert ok, "sample 1"

# Provided sample 2 from the original statement.
assert run("0 1\n1 1\n").strip() == "-1", "sample 2"

# Minimum-size displacement that is reachable.
ok, _ = verify("0 0\n1 1\n")
assert ok, "unit diagonal translation"

# Negative diagonal displacement.
ok, _ = verify("0 0\n-1 -1\n")
assert ok, "negative diagonal translation"

# Boundary-sized reachable displacement.
ok, _ = verify("-100000 -100000\n100000 100000\n")
assert ok, "maximum diagonal displacement"

# Boundary-sized unreachable displacement.
assert run("-100000 -100000\n100000 99999\n").strip() == "-1", \
    "boundary parity case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 1 / 1 -2`| 任意の有効なシーケンス | 公式に到達可能なサンプルと自明ではない混合ディスプレイスメント |
 |`0 1 / 1 1`|`-1`| パリティ不変 |
 |`0 0 / 1 1`| 任意の有効なシーケンス | 1 つの正の対角変換 |

 |`-100000 -100000 / 100000 100000`| 任意の有効なシーケンス | 最大座標差とコマンド限界 |

 ## 特殊なケース

 最初の自明ではないケースは、パリティによって引き起こされる到達不能点です。 のために```
0 1
1 1
```(dx=1) と (dy=0) があるため、(dx+dy=1) は奇数になります。 アルゴリズムはすぐに停止し、出力します。`-1`。 これは、シーケンスを構築しようとして、長い検索の後に初めて失敗を発見するよりも望ましい方法です。 

2 番目のケースは、生成された 1 つの方向に完全に沿った変位です。 のために```
0 0
1 1
```(a=1) と (b=0) が得られます。 アルゴリズムは正確に放射します`1142`。 4 つのコマンドを適用すると、

 [
 (0,0)\xrightarrow{1}(0,0)
 \xrightarrow{1}(0,0)
 \xrightarrow{4}(1,-1)
 \xrightarrow{2}(1,1)。 
]

 ロボットが最初のタワーから開始するため、最初の 2 つの回転はキャンセルされますが、完全なシーケンスでは依然として必要な変換が実現されます。 

負の係数は逆シーケンスを使用して処理されます。 のために```
0 0
-1 -1
```(a=-1) が得られるので、アルゴリズムは次のように出力します。`1322`。 その正味変位は ((-1,-1)) で、原点から目的地まで直接移動します。 

到達可能な最大変位も安全です。 のために```
-100000 -100000
100000 100000
```(dx=dy=200000) があるため、(a=200000) と (b=0) になります。 出力には、(10^6) 制限を下回る (4\cdot200000=800000) コマンドが含まれています。 これは、建設の出力サイズにとって最悪のケースです。 

最後に、係数がゼロの場合、アルゴリズムは空のコマンド文字列を出力してはなりません。 たとえば、(b) のみがゼロでない場合、対角変換ブロックは単純にスキップされ、`14`または`32`ブロックはディスプレイスメント全体を提供します。 元の点が異なることが保証されているため、(a) と (b) の少なくとも 1 つはゼロではないため、ターゲットに到達可能な場合、最終的な答えは常に正の長さのコマンド文字列になります。
