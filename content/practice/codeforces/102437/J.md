 ## 問題の理解

 ロボットは整数点 (x 1 ,y 1 ) から開始し、別の整数点 (x 2 ,y 2 ) に到達する必要があります。 (0,0) と (1,0) に 2 つの固定電波塔があります。 各コマンドは、これらの塔の 1 つを中心に、現在のポイントを時計回りまたは反時計回りに正確に 90 °回転させます。 したがって、4 つのコマンドは、平面の 4 つのアフィン変換になります。 タスクは、必要な変換を実行する最大 10 6 コマンドを出力することです。`-1`目的地に到達できないとき。 

公式の制約では、すべての座標は -100000 ～ 100000 の間にありますが、コマンド制限は 10 6 で、時間制限は 2 秒、メモリは 512 MB です。 プレーンの大部分を明示的に検索するソリューションは魅力的ではありません。 有用な構築では、探索された座標領域のサイズへの依存を回避し、座標差においてほぼ直線的な時間でシーケンスを生成する必要があります。 

最初の隠されたプロパティはパリティです。 すべての操作では、x+y のパリティが維持されます。 たとえば、コマンド 1 は、(x,y) を (y,-x) に変換します。その座標の合計は y-x であり、x+y と同じパリティを持ちます。 (1,0) を中心とした回転も同様に動作します。 したがって、(0,1) などの点は (1,1) に到達できません。これは、それらの合計のパリティが異なるためです。 これはまさに2番目の公式サンプルです。 

誤って処理しやすいもう 1 つのケースは、1 つの対角線のみに沿った変位です。 (0,0) から (1,1) まで、変位は (1,1) であるため、構築にはコマンドのみが必要です`23`。 両方の対角成分が正または負であると仮定する一般的な実装は、2 つのカウントのうちの 1 つがゼロであるため、ここでは失敗します。 

3 番目の境界ケースは、大きな変位です。 (-100000,-100000) から (100000,100000) までの変位は (200000,200000) です。 構築には20万部の斜め平行移動が使用されます。`23`、400,000 コマンドの場合、快適に 10 6 未満です。マンハッタンの距離の単位ごとに 1 つのコマンドを実行するソリューションはここでも機能しますが、コマンド シーケンスによるブルート フォース検索は完全に不可能です。 

最後に、このステートメントは、開始点と目的地が異なることを保証します。 したがって、(5,5) から (5,5) へのような入力は、たとえ数学的には空のシーケンスで解決されるとしても、有効な入力領域の外にあります。 プログラムは空のコマンド シーケンスを生成する必要はありません。 

## アプローチ

 直接的なアプローチは、すべての整数点をグラフの頂点として扱い、各点を 4 つのコマンドによって取得された 4 つの位置に接続することです。 すべてのコマンドには単位コストがあるため、幅優先検索は正しく、BFS が初めてターゲットに到達したときに有効なシーケンスが見つかったことになります。 問題はグラフの大きさです。 入力によって許可される座標正方形の内部には、約 200001 2、つまりおよそ 4⋅10 10 個の可能な点があります。 このような各ポイントから 4 つの出力遷移を調べるだけでも、1.6⋅10 11 のオーダーの遷移チェックが必要になります。 コマンド文字列を直接検索することはさらに悪いことです。長さ L 以下のすべての文字列には、(4 L+1 −1)/3 の可能性が含まれます。 

ブルートフォース手法は、すべてのコマンドを正確にシミュレートできるため機能しますが、4 つの変換で共有される代数構造を無視するため失敗します。 重要な観察は、2 つのコマンドが回転をキャンセルして純粋な平行移動を残すことができるということです。 

コマンド 1 を (0,0) を中心とした時計回りの回転とし、コマンド 4 を (1,0) を中心とした反時計回りの回転とします。 コマンド 1 に続けてコマンド 4 を適用すると、次のようになります。 

(x,y) 1 (y,−x) 4 (1+x,y−1)。 

それでペアは`14`すべての点を (1, −1) で変換します。 

同様に、コマンド 2 に続けてコマンド 3 を実行すると、次のようになります。 

(x,y) 2 (−y,x) 3 (1+x,1+y)、

 それで`23`すべての点を (1,1) で変換します。 

これら 2 つの変換は、到達可能なパリティ クラスの正確な基礎を形成します。 必要な変位が

 (dx,dy)=(x 2 −x 1 ,y 2 −y 1 )、

 次のように書くことができます

 (dx,dy)=a(1,1)+b(1,−1)、

 どこで

 a= 2dx+dy 、b= 2dx−dy 。 

これらの値は、dx と dy が同じパリティを持つ場合に正確に整数になります。これは、同じパリティを持つ x 1 ＋y 1 と x 2 ＋y 2 と同等です。 

ネガティブ翻訳は、対応する 2 つのコマンド シーケンスを逆にすることで得られます。 の逆`23`は`41`、(−1,−1) を生成し、その逆`14`は`32`、(−1,+1)を生成します。 

コマンドの数が特に便利です。 2(∣a∣+∣b∣) 個のコマンドが必要です。 

∣a∣+∣b∣=max(∣dx∣,∣dy∣)。 

各座標の差は最大 200,000 であるため、最終シーケンスには最大 400,000 個のコマンドが含まれますが、これは許容される 10 6 を大幅に下回ります。

 ## アルゴリズムのチュートリアル

 1. 変位 dx=x 2 −x 1 および dy=y 2 −y 1 を計算します。 私たちが使用するコマンド ペアは、どの開始点からでも同様に機能する変換であるため、構造全体はこの変位を再現するだけで済みます。 
2. x 1 +y 1 と x 2 +y 2 が同じパリティを持つかどうかを確認します。 異なる場合は印刷してください`-1`。 すべての正当なコマンドは x+y のパリティを保持するため、シーケンスが 2 つのパリティ クラス間で交差することはできません。 
3. コンピューティング

 a=(dx+dy)/2、b=(dx−dy)/2。 

値 a は変換 (1,1) を適用する回数を示し、値 b は (1,−1) を適用する回数を示します。 パリティ チェックにより、両方の除算が正確であることが保証されます。 
4. a>0 の各単位に、`23`。 各ペアは、現在の位置に正確に (1,1) を加算します。 a<0 の場合は追加します`41`代わりに、そのペアは (−1,−1) を追加するためです。 
5. b>0 の各単位に、`14`。 各ペアは (1, −1) を加算します。 b<0 の場合は追加します`32`、これは (−1,1) を加算します。 
6. 結果のシーケンスを印刷します。 2(∣a∣+∣b∣)=2max(∣dx∣,∣dy∣)≤400000 なので、コマンド制限は自動的に満たされます。 

### なぜ効果があるのか

 不変式は x+y のパリティであるため、パリティ テストでは到達不可能なターゲットがすべて除外されます。 到達可能なターゲットの場合、変位は両方の座標で同じパリティを持ち、a と b は整数になります。 コマンドペア`23`そして`14`は (1,1) と (1,−1) による変換です。`41`そして`32`はそれぞれの逆数です。 したがって、生成されたシーケンスは開始点を正確に a(1,1)+b(1,−1)=(dx,dy) だけ変更し、ロボットを (x 2 ,y 2 ) に配置します。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    x1, y1 = map(int, input().split())    x2, y2 = map(int, input().split())
    # x + y parity is invariant under every command.    if (x1 + y1) % 2 != (x2 + y2) % 2:        print(-1)        return
    dx = x2 - x1    dy = y2 - y1
    # dx = a + b    # dy = a - b    a = (dx + dy) // 2    b = (dx - dy) // 2
    ans = []
    if a > 0:        ans.append("23" * a)    elif a < 0:        ans.append("41" * (-a))
    if b > 0:        ans.append("14" * b)    elif b < 0:        ans.append("32" * (-b))
    s = "".join(ans)
    print(len(s))
```最初のチェックではパリティのみが使用されるため、浮動小数点演算は含まれません。 これは、以下の 2 つの除算が、使用後にたまたま整数を生成するかどうかを確認するよりも望ましいです。`/`。 

変数`a`そして`b`2 つの方程式 a+b=dx と a−b=dy を解くことで直接得られます。 パリティ条件によって 2 で割り切れる可能性がすでに確立されているため、Python の整数の除算はここでは安全です。 

シーケンスは、個々のコマンドを個別の Python オブジェクトとして保存するのではなく、文字列として蓄積されます。 有効な最大の回答は 400,000 文字であるため、結果として生じるメモリ使用量は少なくなります。 

2 つの翻訳グループはどちらも通常の翻訳であるため、順序は重要ではありません。 全て適用中`23`または`41`まず最初にペア`14`または`32`その後、ペアの変位ベクトルの正確な合計が生成されます。 

Python の整数はオーバーフローせず、この構造における最大の中間座標は、指定された座標範囲に生成された変位を加えた程度にすぎません。

## 特殊なケース

 ### パリティの不一致

 検討してください```
0 11 1
```初期合計は 1 ですが、目標合計は 2 です。すべてのコマンドは x+y のパリティを保持するため、アルゴリズムはすぐに次を出力します。`-1`。 座標が幾何学的に近いかどうかだけをチェックする構造では、誤ってコマンドを生成しようとする可能性があります。

 のために```
0 01 1
```dx=1、dy=1 となるため、a=1、b=0 となります。 アルゴリズムが出力する`23`。 コマンド 2 は (0,0) をそれ自体にマップし、コマンド 3 はそれを (1,1) にマップします。 不必要な繰り返しを避けること以外に、ゼロ係数に対する特別な処理は必要ありません。
