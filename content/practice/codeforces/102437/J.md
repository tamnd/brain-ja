 ## 解決策
 ## 問題の理解

 ロボットは飛行機内を移動し、その 4 つのコマンドは 2 つの固定電波塔のうちの 1 つの周りを 4 分の 1 回転します。 コマンド 1 および 2 は、現在の点を原点を中心に時計回りまたは反時計回りに 90 度回転させます。 コマンド 3 と 4 は、点 ((1,0)) の周囲で同じことを行います。 

ロボットの開始整数点 ((x_1,y_1)) と別の整数の目的地 ((x_2,y_2)) が与えられます。 タスクは、ロボットを目的地まで正確に移動させる、またはそのようなシーケンスが存在しないことを報告する、最大 (10^6) 個のコマンドを出力することです。 公式声明では、制限時間は 2 秒、メモリは 512 MB とされています。 

座標境界は (10^5) のみであるため、座標の差に比例する構築は簡単に十分に高速です。 出力自体には最大 (10^6) 文字を含めることができるため、(O(10^6)) 構造は許容されますが、距離が指数関数的なものはまったく実用的ではありません。 実際、以下の構築には最大 (400,000) 個のコマンドが必要ですが、これは制限を余裕で下回っています。 

中心的な問題は、回転をどのようにシミュレートするかではなく、どの点に到達できるかということです。 すべてのコマンドは (x+y) のパリティを保持します。 たとえば、原点の周りの回転は ((x,y)) を ((y,-x)) または ((-y,x)) にマッピングし、両方の新しい座標合計は (x+y) と同じパリティを持ちます。 ((1,0)) を中心とした回転は、中心からの追加の寄与が (2) であるため、同じ特性を持ちます。 したがって、(x+y) のパリティが異なる点には決して到達できません。 

たとえば、入力```
0 1
1 1
```開始パリティ (0+1=1) と宛先パリティ (1+1=0) があるため、正しい出力は次のようになります。`-1`。 制限された数の状態だけを調べる不注意な検索では、不可能であることと検索の深さが不十分であることを区別できない可能性があります。 

もう 1 つのエッジ ケースは、1 つの座標におけるゼロの変位です。 例えば、```
0 0
5 5
```変位が ((5,5)) であるため、到達可能です。 個別のコマンドが水平または垂直の単位移動ではないため、水平方向と垂直方向の独立した移動に基づいた構造は誤解を招きます。 有用な翻訳は対角線です。 

開始点と目的地は異なることが保証されているため、空のシーケンスが有効な答えになることはありません。 それにも関わらず、((5,5)) のような変位には 1 種類の変換しか必要ないため、実装では中間変換カウントのゼロ値を正しく処理する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、4 つのコマンドが、頂点が整数点である暗黙的なグラフのエッジと見なされます。 ((x_1,y_1)) から始めて、すべてのコマンドを試し、それ以降のすべてのコマンドを試すことができます。 これは正しいです。すべての正当なコマンド シーケンスがこのグラフ内のパスに対応しているからです。 

問題は配列の数です。 すべてのシーケンスを深さ (L) で検索して調べます

 [
 1+4+4^2+\dots+4^L=\frac{4^{L+1}-1}{3}
 】

 最悪の場合はノード。 深さ (20) に達したとしても、すでに (10^{12}) 個を超えるコマンド文字列が考えられることになります。 私たちの有効な構築には最大 (400,000) のコマンドが必要となる可能性があるため、リモートからの総当たり攻撃は実行できません。 

重要な観察は、異なる中心を中心とした 2 つの回転により、回転部分がキャンセルされ、純粋な平行移動が残る可能性があるということです。 コマンド 2 の後にコマンド 3 が続くとします。コマンド 2 は原点を中心とした反時計回りの回転であり、コマンド 3 は ((1,0)) を中心とした時計回りの回転です。 それらの複合効果はまさに

 [
 (x,y)\rightarrow(x+1,y+1)。 
】

 したがって、2 つのコマンド シーケンスは`23`ロボットは、現在の位置に関係なく、((1,1)) だけ移動します。 

同様に、コマンド 1 に続いてコマンド 4 を実行すると、翻訳が生成されます。 

[
 (x,y)\rightarrow(x+1,y-1),
 】

 それで`14`((1,-1)) だけ移動します。 

これら 2 つの対角線の移動により、2 つの座標が同じパリティを持つすべての変位が生成されます。 必要な変位が ((dx,dy)) の場合、次のように記述します。 

[
 a=\frac{dx+dy}{2}、\qquad b=\frac{dx-dy}{2}。 
】

 それから

 [
 (dx,dy)=a(1,1)+b(1,-1)。 
】

 (dx) と (dy) が同じパリティを持つ場合、値 (a) と (b) は整数になります。これは、(x+y) が両方のエンドポイントで同じパリティを持つという不変条件と等価です。 

負の係数は逆変換を使用して処理されます。 以来`23`((1,1)) によって変換され、その逆は次のようになります。`32`、これは ((-1,-1)) によって変換されます。 同じく、`41`((-1,1))、の逆変換`14`。 

ブルート フォースは、考えられるすべてのコマンド シーケンスを探索するため機能しますが、分岐係数が 4 であるため失敗します。 コマンドのペアが変換を生成するという観察により、問題全体は 1 つのパリティ条件をチェックし、制限された数の反復 2 文字ブロックを出力することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(4^L)) 深さ (L) の場合 | (O(4^L)) | 遅すぎる |
 | 翻訳構築 | (O( | dx | + | dy | )) | (O( | dx | + | dy | )) 出力 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始点から目的地までの変位を計算します。 

[
 dx=x_2-x_1、\qquad dy=y_2-y_1。 
】

 以下の便利なコマンド ペアは変換として機能し、現在の位置に依存しないため、ロボットはこの変位を認識するだけで済みます。 

1. (dx) と (dy) が同じパリティを持っているかどうかを確認します。 同様に、次のことを確認します。 

[
 (x_1+y_1)\bmod 2=(x_2+y_2)\bmod 2.
 】

 パリティが異なる場合は出力`-1`。 (x+y) のパリティは、許可されたすべての回転の下で不変であるため、コマンド シーケンスが 2 つのパリティ クラス間で交差することはできません。 

1. コンピューティング

 [
 a=\frac{dx+dy}{2}、\qquad b=\frac{dx-dy}{2}。 
】

 パリティ チェックが成功したため、両方の値は整数になります。 

1. (a>0) の場合、追加します。`23`ちょうど (a) 回です。 各コピーはロボットを ((1,1)) だけ移動します。 (a<0) の場合は追加します`32`ちょうど (-a) 回、逆の変換になります。 
2. (b>0) の場合、追加します。`14`ちょうど (b) 回です。 各コピーはロボットを ((1,-1)) だけ移動します。 (b<0) の場合は追加します`41`ちょうど (-b) 回です。 
3. 生成されたすべてのコマンドを連結し、その数とそれに続くコマンド文字列を出力します。 コマンドペアの数は

 [
 |a|+|b|=\max(|dx|,|dy|),
 】

 したがって、個々のコマンドの合計数は次のようになります。 

[
 2\max(|dx|,|dy|)\le 400,000。 
】

 これは許容値 (10^6) を安全に下回っています。 

### なぜ効果があるのか

 不変式は (x+y) のパリティであるため、パリティ チェックにより、拒否されたすべてのインスタンスが本当に到達不可能であることが証明されます。 受け入れられたインスタンスの場合、変位は次の条件を満たします。 

[
 (dx,dy)=a(1,1)+b(1,-1)。 
】

 シーケンス`23`最初の基底ベクトルを正確に実現し、`14`まさに2番目を実現します。 それらの逆シーケンスは、対応する負のベクトルを実現します。 その結果、生成されたシーケンスは開始位置に正確に ((dx,dy)) を追加し、((x_2,y_2)) で終了します。 この構築では最大 (400,000) 個のコマンドが使用されるため、受け入れられるすべてのインスタンスは長さの制限も満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    # x + y parity is invariant under every operation.
    if (dx - dy) % 2 != 0:
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    if a > 0:
        ans.append("23" * a)
    elif a < 0:
        ans.append("32" * (-a))

    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("41" * (-b))

    s = "".join(ans)

    print(len(s))
    print(s)

if __name__ == "__main__":
    solve()
```最初の 2 つの入力行は、4 つの座標に直接読み込まれます。 この問題には複数のテスト ケースはありません。 

パリティテストでは以下を使用します。`(dx - dy) % 2`これは、(dx) と (dy) のパリティが等しいことを確認することと同じです。 Python の整数演算には任意の精度があるため、実際の座標が小さくてもオーバーフローの問題は発生しません。 

価値観`a`そして`b`は 2 つの対角平行移動ベクトルの係数です。 正の係数の場合、前方ペアが使用されます。 負の係数の場合、合成を反転すると逆変換が行われるため、ペアは反転されます。 

この構築では、一度に 1 文字ずつ追加する Python ループではなく、文字列の乗算を使用します。 これにより実装がシンプルになり、Python は繰り返される各ブロックを効率的に構築できるようになります。 最後の文字列には最大 (400,000) 文字が含まれます。 

翻訳は交換されるため、2 つの翻訳ブロックの順序は重要ではありません。 この実装は、最初に ((1,1)) 変換を出力し、次に ((1,-1)) 変換を出力します。これにより、次の式と対応します。`a`そして`b`明示的な。

## テストケース

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin

    x2, y2 = map(int, lines[1].split())

    out = run(inp).strip().splitlines()

    if out[0] == "-1":
        assert (x1 + y1) % 2 != (x2 + y2) % 2
        return

    k = int(out[0])
    s = out[1]

    assert k == len(s)
    assert 0 < k <= 10**6
    assert all(c in "1234" for c in s)

    x, y = x1, y1

    for c in s:
        if c == "1":
            x, y = y, -x
        elif c == "2":
            x, y = -y, x
        elif c == "3":

        else:

 ## 特殊なケース

 パリティの不一致は、基本的に不可能なケースです。 のために```
0 1
1 1
```(x+y) の開始値は (1) ですが、宛先値は (2) であるため、それらのパリティは異なります。 アルゴリズムは即座に拒否します。 個々の回転では (x+y) のパリティが保持されるため、どのシーケンスもこれを修正できません。 

実装で両方の係数がゼロ以外でなければならないと想定している場合、対角成分が 1 つだけある変位も誤って処理されやすくなります。 のために```
0 0
5 5
```(a=5) と (b=0) が得られます。 アルゴリズムが出力する`23`5 回実行し、(b) では何も発行せず、10 個のコマンドを生成します。 それぞれ`23`((1,1)) を追加するため、最終位置は ((5,5)) になります。 

負の係数を使用するには、逆コマンドのペアを正しい順序で使用する必要があります。 のために```
5 5
0 0
```((-5,-5)) が必要なので、(a=-5) と (b=0) になります。 アルゴリズムが出力する`32`5回。 以来`23`は ((1,1)) による翻訳です。`32`はその逆であり、((-1,-1)) によって変換され、原点に正確に到達します。 

1 つの座標変位がゼロである場合には、別のよくある間違いが発生します。 のために```
0 0
4 0
```(a=2) と (b=2) があるため、

 [
 4(1,0)=2(1,1)+2(1,-1)。
