 ## 解決策
 ## 問題の理解

 ロボットは整数平面内で移動し、((0,0)) と ((1,0)) に 2 つの固定回転中心があります。 各コマンドは、これら 2 つの中心のいずれかを中心に、現在位置を時計回りまたは反時計回りに正確に (90^\circ) だけ回転します。 したがって、すべてのコマンドは剛体回転であり、タスクは、ロボットを ((x_1,y_1)) から ((x_2,y_2)) に移動させる、最大 (10^6) 個の回転のシーケンスを見つけるか、そのようなシーケンスが存在しないことを証明することです。 

4 つのコマンドは座標変換として直接記述できます。 

[
 1:(x,y)\mapsto(y,-x),
 ]

 [
 2:(x,y)\mapsto(-y,x),
 ]

 [
 3:(x,y)\mapsto(y+1,1-x),
 ]

 [
 4:(x,y)\mapsto(1-y,x-1)。 
]

 公式問題には2秒の制限時間と512MBのメモリ制限があります。 座標は (100000) で区切られているため、座標範囲に比例するアルゴリズムは簡単に実現できますが、座標正方形のサイズが 2 次のものは大きすぎます。 数十万のコマンドのみを使用する構築も、(10^6) の制限内に余裕で収まります。 

最初の明らかではない問題は、すべてのポイントに到達できるわけではないということです。 考慮する```
0 1
1 1
```(x+y) の初期値は (1) ですが、ターゲットは (x+y=2) です。 正しい出力は次のとおりです`-1`。 幾何学的距離のみをチェックするか、2 つの回転中心が整数平面全体を生成すると仮定する不注意な検索では、その点が到達可能であると誤って主張する可能性があります。 

2 番目の問題は、構築自体は単純であるにもかかわらず、答えを得るには多くのコマンドが必要になる可能性があることです。 例えば、```
-100000 -100000
100000 100000
```は到達可能ですが、変位は両方の座標で (200000) です。 一度に 1 つのユニットを移動する構築では、数十万回の操作が必要となる場合があるため、実装ではコストのかかる検索を繰り返し実行するのではなく、効率的に答えを構築する必要があります。 

変位が正確に対角となる小さな境界ケースもあります。```
0 0
1 1
```正しい順序は`23`。 これら 2 つのコマンドの順序が欠けていると、異なる変換が行われるため、コマンドを順序のない操作として扱うのは正しくありません。 

## アプローチ

 直接的な総当たりアプローチは、すべての整数点をグラフの頂点と見なし、各点を 1 つのコマンドで取得された 4 つの点に接続することです。 すべてのコマンドには単位コストがあるため、幅優先検索は正しく、BFS が初めてターゲットに到達したときに有効なシーケンスが見つかったことになります。 問題はグラフの大きさです。 許可されたすべての入力座標を含む (200001\times200001) 個の正方形に注意を限定したとしても、考えられる点は (40,000,400,001) 個あり、点ごとに 4 つの遷移を調べることは、最大 (160,001,600,004) 個の隣接遷移を意味します。 真に制限のない BFS には、依存する有限の座標ボックスがまったくありません。 代わりにコマンド文字列を列挙すると、深さ (k) には (4^k) 個のシーケンスが含まれるため、さらに悪いことになります。 

すべてのコマンドは簡単にシミュレートできるため、ブルート フォースは機能しますが、変換の代数構造は完全に無視されます。 重要な観察は、2 つのコマンドが純粋な平行移動を残したまま回転をキャンセルできることです。 

コマンド 2 を適用し、次にコマンド 3 を適用します。((x,y)) から開始して、

 [
 (x,y)\xrightarrow{2}(-y,x)\xrightarrow{3}(x+1,y+1)。 
]

それで`23`すべての点を ((1,1)) で変換します。 

同様に、

 [
 (x,y)\xrightarrow{1}(y,-x)\xrightarrow{4}(x+1,y-1),
 ]

 それで`14`すべての点を ((1,-1)) で変換します。 

それらの逆数は次のとおりです。`41`、 ((-1,-1)) によって変換され、`32`、これは ((-1,1)) によって変換されます。 

これにより、問題全体が、2 つの対角ベクトル ((1,1)) と ((1,-1)) の組み合わせとして目的の変位を表現することになります。 しましょう

 [
 dx=x_2-x_1、\qquad dy=y_2-y_1。 
]

 を満たす整数 (a,b) が必要です。 

[
 a(1,1)+b(1,-1)=(dx,dy)。 
]

 2 つの方程式を解くと、

 [
 a=\frac{dx+dy}{2}、\qquad b=\frac{dx-dy}{2}。 
]

 このような整数は、(dx) と (dy) が同じパリティを持つ場合に正確に存在します。 同様に、(x_1+y_1) と (x_2+y_2) は同じパリティを持つ必要があります。 

構築には (2|a|+2|b|) コマンドが必要です。 使用する

 [
 |dx+dy|+|dx-dy|=2\max(|dx|,|dy|),
 ]

 すべての座標差の絶対値は最大 (200,000) であるため、コマンドの数は最大 (400,000) です。 これは安全に必要な値 (10^6) を下回っています。

 ## アルゴリズムのチュートリアル

 1. 変位を計算します

 [
 dx=x_2-x_1、\qquad dy=y_2-y_1。 
]

 2 つのコマンド シーケンスは、全体の構造でこの変位を再現するだけで済みます。`23`そして`14`あらゆる点から機能する翻訳です。 

1. (dx) と (dy) が同じパリティを持っているかどうかを確認します。 そうでない場合は、印刷してください`-1`。 

すべてのコマンドは (x+y) のパリティを保持します。 原点の周りを回転すると、((x,y)) は ((-y,x)) または ((y,-x)) に変化し、その座標の合計は (x+y) と同じパリティになります。 ((1,0)) を中心とした回転にも同じ性質があります。 したがって、(x+y) の異なるパリティを接続することはできません。 

1. コンピューティング

 [
 a=\frac{dx+dy}{2}、\qquad b=\frac{dx-dy}{2}。 
]

 最初の係数は変換 ((1,1)) を何回使用するかを示し、2 番目の係数は ((1,-1)) を何回使用するかを示します。 

1. (a>0) の場合、追加します。`23`ちょうど (a) 回です。 (a<0) の場合は追加します`41`ちょうど (-a) 回です。`23`((1,1)) を加算しますが、`41`その逆数 ((-1,-1)) を加算します。 

1. (b>0) の場合、追加します。`14`ちょうど (b) 回です。 (b<0) の場合は追加します`32`ちょうど (-b) 回です。`14`((1,-1)) を加算しますが、`32`((-1,1)) を加算します。 

翻訳は交換されるため、これらの翻訳ブロックの順序は重要ではありません。 同等の翻訳をグループ化すると、構築が簡単に実装できるようになります。 

1. 生成された文字列と文字列自体の長さを出力します。 

ソースとターゲットは異なることが保証されているため、ターゲットに到達できる場合は常に、(a,b) の少なくとも 1 つはゼロ以外であり、結果のコマンド カウントは正になります。 

### なぜ効果があるのか

 この構造では、現在の位置が初期位置にこれまでに生成されたすべての変換の合計を加えたものに等しいという不変条件が維持されます。 それぞれ`23`それぞれが ((1,1)) に貢献します`41`それぞれ ((-1,-1)) に寄与します`14`((1,-1)) に寄与し、それぞれ`32`((-1,1)) に寄与します。 したがって、最終的な変位は次のようになります。 

[
 a(1,1)+b(1,-1)
 =(a+b,a-b)
 =(dx,dy),
 ]

 したがって、最終的な位置は正確に ((x_2,y_2)) になります。 

パリティ テストが失敗した場合、すべての正当なコマンドは (x+y\bmod 2) を保持するため、解決策は存在しません。 合格した場合、(a) と (b) は整数であり、構築により明示的にターゲットが生成されるため、パリティ条件も十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    # The parity of x + y is invariant.
    if (dx - dy) % 2 != 0:
        print(-1)
        return

    a = (dx + dy) // 2
    b = (dx - dy) // 2

    ans = []

    # 23 = translation by (1, 1)
    # 41 = translation by (-1, -1)
    if a > 0:
        ans.append("23" * a)
    elif a < 0:
        ans.append("41" * (-a))

    # 14 = translation by (1, -1)
    # 32 = translation by (-1, 1)
    if b > 0:
        ans.append("14" * b)
    elif b < 0:
        ans.append("32" * (-b))

    result = ''.join(ans)

    print(len(result))
    print(result)

if __name__ == "__main__":
    solve()
```最初の部分では、コマンドごとにロボットの位置を操作するのではなく、ターゲットの変位を計算します。 パリティチェックでは、`(dx - dy) % 2`これは、(dx) と (dy) のパリティが等しいことを確認することと同じです。 Python のモジュロ演算は負の値に対して安全であるため、これは許可されたすべての座標に対して機能します。 

2 つの係数は、パリティ テストが成功した後にのみ整数の除算になります。 これにより、半整数係数が暗黙的に切り捨てられ、無効なシーケンスが生成されることが回避されます。 

コマンド ブロックは、一度に 1 文字ずつではなく、文字列として追加されます。 これにより、実装が単純になり、各コマンドを個別の Python オブジェクトとして保存することがなくなります。 最大の答えには (400,000) 文字が含まれているため、結果の文字列はメモリ制限に対して十分に小さいです。 

各ペア内のコマンドの順序が重要です。`23`コマンド 2 とそれに続くコマンド 3 を意味する必要があり、また`14`コマンド 1 の後にコマンド 4 が続くことを意味する必要があります。どちらかのペアを逆にすると、結果の変換が変わります。 

Python の整数には任意の精度があるため、実際の座標境界が小さくてもオーバーフローの問題は発生しません。

1 1
