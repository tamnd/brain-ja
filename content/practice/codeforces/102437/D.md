 ## 解決策
 ## 問題の理解

 フィボナッチ数列の最初の (n+1) 要素の二乗和を計算する必要があります。 シーケンスは 2 つの 1 で始まるため、最初の値は次のようになります。 

[
 1、1、2、3、5、8、\ldots
 】

 その後の値はすべて、前の 2 つの値の合計になります。 必要な答えは、

 [
 f_0^2+f_1^2+\cdots+f_n^2
 】

 (998,244,353) を法として計算されます。 

難易度は限界です (n\le 10^{18})。 (O(n)) アルゴリズムでも、最大 (10^{18}) 回の反復が必要となり、実際の時間制限をはるかに超えます。 実行時間が (n) のビット数に依存するメソッドが必要ですが、(10^{18}) の場合はわずか約 60 です。 これにより、(O(\log n)) アルゴリズムが自然なターゲットになります。 

インデックス作成の間違いが簡単に隠れてしまう小規模なケースがいくつかあります。 (n=0) の場合、合計には (f_0^2=1) のみが含まれるため、答えは (1) になります。 シフトを調整せずに通常のフィボナッチ指数を使用する数式は、誤って (0) を返す可能性があります。 (n=1) の場合、答えは (1^2+1^2=2) となり、最初のものが両方とも含まれていることを確認します。 (n=2) の場合、合計は (1+1+4=6) であるため、新しいフィボナッチ値を生成した後にのみ累積を開始する再帰実装は 1 だけずれます。 

ビネーの式に基づく式には別の問題があります。 Binet の式は数学的には正しいですが、直接実装する場合は浮動小数点数を使用し、(10^{18}) 付近の値には標準の浮動小数点型が提供できるよりもはるかに高い精度が必要です。 整数の高速 2 倍化を使用したモジュラー演算により、この問題は完全に回避されます。 

## アプローチ

 直接的な解決策は簡単です。 (f_0=f_1=1) から開始して、次のフィボナッチ値を繰り返し生成し、それを 2 乗し、その 2 乗をモジュロ (998,244,353) の答えに加算します。 これは正しいです。なぜなら、すべての項が 1 回だけ生成され、生成されたすべての平方が必要な合計に 1 回だけ寄与するからです。 

問題は(n)の大きさです。 (n=10^{18}) の場合、このメソッドは (10^{18}+1) 個のシーケンス項を生成します。 各漸化ステップごとに 1 回の加算、各 2 乗ごとに 1 回の乗算、および各累積ごとに 1 回の加算をカウントすると、その作業は (3n) 程度になります。これは、およそ (3\cdot10^{18}) 個の基本的な算術演算に相当します。 正確なカウントは、初期値とアキュムレータがどのように処理されるかによって異なりますが、漸近的な問題は決定的です。つまり、線形時間は不可能です。 

有益な観察は、問題内の数列が標準のフィボナッチ数列を 1 位置だけシフトしたものであるということです。 (F_0=0,F_1=1) とします。 それから

 [
 f_i=F_{i+1}。 
】

 クラシックなアイデンティティもある

 [
 \sum_{k=1}^{m}F_k^2=F_mF_{m+1}。 
】

 (m=n+1) と設定すると、

 # \sum_{i=0}^{n}F_{i+1}^2

 F_{n+1}F_{n+2}。 
】

 したがって、合計全体は 2 つのフィボナッチ数の積に崩れます。 

インデックスが (10^{18}+2) まで大きくなる可能性があるフィボナッチ数を計算する必要があります。 高速倍増では、まさにそれが (O(\log n)) 時間で行われます。 この手法では、(F_k) と (F_{k+1}) から直接 (F_{2k}) と (F_{2k+1}) を導出する恒等式を使用します。 

[
 F_{2k}=F_k(2F_{k+1}-F_k)
 】

 そして

 [
 F_{2k+1}=F_k^2+F_{k+1}^2。 
】

 したがって、(k=\lfloor n/2\rfloor) の問題を再帰的に解いた後、一定数のモジュラー乗算と加算のみを使用して (n) の答えを構築できます。 

総当たり法が機能するのは、反復によって必要な用語をすべて列挙できるためです。 それらは (10^{18}+1) 個存在する可能性があるため、失敗します。 フィボナッチ二乗の和が閉じた形式であるという観察により、問題は 1 つのフィボナッチ ペアの計算に軽減され、高速 2 倍化によりその計算が線形時間から対数時間に短縮されます。

 | ブルートフォース | (O(n)) | (O(1)) | 遅すぎる |
 | 最適 | (O(\log n)) | (O(\log n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 標準のフィボナッチ数列 (F_0=0,F_1=1) を導入します。 問題の数列は (f_i=F_{i+1}) を満たすため、必要な合計は次のようになります。 

[
 \sum_{i=0}^{n}F_{i+1}^2。 
】

 このインデックスの変更は、off-by-one エラーが発生する主な場所です。 

1. ID を適用する

 [
 \sum_{k=1}^{m}F_k^2=F_mF_{m+1}。 
】

 (m=n+1) の場合、必要な答えは次のとおりです。 

[
 F_{n+1}F_{n+2}。 
】

 したがって、必要なのは連続するペア ((F_{n+1},F_{n+2})) だけです。 

1. ペア ((F_k,F_{k+1})) を返す関数を定義します。 (k=0) の場合、ペアは ((0,1)) になります。 
2. (k=\lfloor n/2\rfloor) のペアを再帰的に計算します。 ((a,b)=(F_k,F_{k+1})) を返すとします。 
3. 高速倍増 ID を使用して、

 [
 c=F_{2k}=a(2b-a)
 】

 そして

 [
 d=F_{2k+1}=a^2+b^2。 
】

 すべての演算はモジュロ (998,244,353) で実行されます。 

1. (n) が偶数の場合、(n=2k) であるため、((c,d)) を返します。 

(n) が奇数の場合、(n=2k+1) および (F_{2k+2}=F_{2k}+F_{2k+1}) であるため、((d,c+d)) を返します。 

1. (n+1) で関数を呼び出します。 ((x,y)) を返す場合は、(x=F_{n+1}) および (y=F_{n+2}) になります。 出力 (xy\bmod 998,244,353)。 

### なぜ効果があるのか

 再帰関数の不変式は次のとおりです。`fib_pair(k)`常に正確に ((F_k,F_{k+1})) を返します。 基本ケースは、((F_0,F_1)=(0,1)) を直接返します。 大きい (k) の場合、再帰呼び出しにより (\lfloor k/2\rfloor) の正しいペアが得られ、二重恒等式によりインデックス (2\lfloor k/2\rfloor) および (2\lfloor k/2\rfloor+1) の正確な値が生成されます。 次に、パリティ チェックによって (k) に適切なペアが選択されます。 その結果、最後の呼び出しは ((F_{n+1},F_{n+2})) を返し、その積はフィボナッチ二乗和恒等式による元の合計と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def fib_pair(n):
    if n == 0:
        return 0, 1

    a, b = fib_pair(n // 2)

    c = a * ((2 * b - a) % MOD) % MOD
    d = (a * a + b * b) % MOD

    if n % 2 == 0:
        return c, d

    return d, (c + d) % MOD

def solve():
    n = int(input())

    fn1, fn2 = fib_pair(n + 1)
    answer = fn1 * fn2 % MOD

    print(answer)

if __name__ == "__main__":
    solve()
```定数`MOD`必要な係数を格納します。 すべての中間フィボナッチ値の換算モジュロを維持する`MOD`後の演算はすべて加算と乗算であり、どちらもモジュラー等価性を考慮しているため、これで十分です。 

再帰関数は、1 つだけではなく、2 つの連続するフィボナッチ数を返します。 (F_{2k}) の 2 倍の公式では (F_k) と (F_{k+1}) の両方が使用されるため、これが必要になります。 ペアを返すということは、奇数の場合でも最後の加算を 1 回行うだけで (F_{2k+2}) を取得できることも意味します。 

表現`2 * b - a`モジュロ演算の前に負の値になる可能性があるため、コードは明示的に計算します。`(2 * b - a) % MOD`。 Python のモジュロ演算は負の中間値を正しく処理し、必要な範囲の値を生成します。 

呼び出しでは、`n + 1`、 ない`n`。 元のシーケンスは標準のフィボナッチ数列に対してシフトされており、二乗和恒等式には (F_{n+1}F_{n+2}) が必要です。 以来`fib_pair(n + 1)`(F_{n+1}) から始まる連続した値を返す場合、乗算はまさに望ましい答えになります。 

Python の整数には任意の精度があるため、整数のオーバーフローは発生しません。 さらに重要なのは、アルゴリズムが実際の膨大なフィボナッチ数を決して構築しないことです。 すべての値はすぐに剰余 (998,244,353) に減算されます。 

## 実用的な例

 サンプル 1 の場合、(n=0)。 アルゴリズムはインデックス (n+1=1) のペアを要求します。 

| ステップ | (n) | 返されたペア | 意味 |
 | --- | --- | --- | --- |
 | ベース | 0 | ((0,1)) | (F_0,F_1) |
 | 奇妙なケース | 1 | ((1,1)) | (F_1、F_2) |
 | 最終回 | 0 | (1\cdot1) | (1) |

 返されるペアは ((F_1,F_2)=(1,1)) であるため、答えは (1) です。 これにより、可能な最小の入力が確認され、(f_0) が含まれることが検証されます。 

サンプル 2 の場合、(n=2)。 インデックス (3) のペアが必要です。 

| ステップ | 現在のインデックス | 半分のインデックス | 半分のペア | 現在のペア |
 | --- | --- | --- | --- | --- |
 | ベース | 0 | 0 | ((0,1)) | ((0,1)) |
 | 倍増 | 1 | 0 | ((0,1)) | ((1,1)) |
 | 倍増 | 3 | 1 | ((1,1)) | ((2,3)) |
 | 最終製品 | 2 | 3 | ((2,3)) | (2\cdot3=6) |

 ここで返されるペアは ((F_3,F_4)=(2,3)) です。 彼らの製品は (6) で、一致します。 

[
 1^2+1^2+2^2=6。 
】

 トレースは、関数が 2 つの連続した値を返す理由も示しています。 ペア ((2,3)) は、最終的な閉じた形式に必要な両方のフィボナッチ数を与えます。

    d = (a * a + b * b) % MOD

## 特殊なケース

 (n=0) の場合、入力は次のようになります。`0`。 アルゴリズムが呼び出すのは、`fib_pair(1)`、((1,1)) を返します。 最終的な乗算は (1\cdot1=1) で、唯一の項 (f_0^2=1) と一致します。 (f_i) から (F_{i+1}) へのシフトを忘れた数式は、ここですぐに失敗する可能性があります。 

(n=1) の場合、入力は次のようになります。`1`。 必要な合計は (1^2+1^2=2) です。 アルゴリズムは計算します`fib_pair(2)`、((F_2,F_3)=(1,2))を求め、それらを乗算して(2)を求めます。 これにより、最初の 2 つのうちの 1 つだけで誤って合計を開始する実装が捕捉されます。 

(n=2) の場合、入力は次のようになります。`2`。 関係する標準のフィボナッチ値は (F_1,F_2,F_3=1,1,2) であるため、答えは (1+1+4=6) となります。 アルゴリズムが取得するのは、`fib_pair(3)=(2,3)`そして (2\cdot3=6) を計算します。 これは、初期条件を超えて二乗和の同一性をチェックする最も単純なケースです。 

(n=10^{18}) の場合、入力は許可される最大のインデックスになります。 アルゴリズムがシーケンスを反復することはありません。 再帰呼び出しごとに現在のインデックスがその半分の整数で置き換えられるため、チェーンには約 60 レベルしか含まれません。 すべてのフィボナッチ値は法 (998,244,353) で削減されるため、実際のフィボナッチ数の桁数が膨大であっても、計算は小規模のままです。 結果として得られる積は、必要な係数を再度法として減算され、必要な答えが正確に得られます。
