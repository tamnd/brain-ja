## アプローチ

 基本的な解決策は、バイナリ表現を直接処理することです。 から始まる`2^59`, その金額を引き出すことができるかどうかを尋ねます。 可能であれば、残高から差し引いてください。 次に、次のように続けます`2^58`、`2^57`など、以下に至るまで`1`。 各ステップで、対応するバイナリ ビットが設定されている場合、そのビットは削除されます。 60 個の累乗をすべて考慮すると、残高はゼロになります。 

これが機能するのは、次のすべての数値が`10^18`よりも小さいです`2^60`、そのため、そのバイナリ表現には次の累乗のみが含まれます。`2^59`を通して`2^0`。 問題はインタラクションの数です。 などの小さなバランスの場合、`n = 1`、このメソッドではまだ 60 回の試行が行われますが、ターミナルでは 10 回しか試行できません。公式コンテストのチュートリアルでは、まさにこれをベースラインとして説明し、その後、二分探索でクエリの数を減らします。 

重要な観察は、現在引き出すことができる 2 の正確な最大累乗を実際に知る必要がないということです。 残りの残高を制限するのに十分な大きさのパワーのみが必要です。そのような制限を取得したら、すべての小さなパワーを処理するだけで十分であるためです。 

60 個の可能な累乗を二分探索することで、有用な開始指数を見つけることができます。 お問い合わせの場合`2^m`、`accepted`答えは、現在の残高が少なくとも`2^m`、 それで`m`は有効な指数なので、左の境界を次のように移動します。`m`。 あ`rejected`答えは現在の残高が以下であることを証明します`2^m`、 それで`m`は使用できないため、右の境界を次の場所に移動します。`m`。 

問題は、受け入れられたクエリによって金額が減算されるため、この二分探索中に残高が変化することです。 幸いなことに、これによってメソッドが壊れることはありません。 これまでに受け入れられたと記録されたすべての指数は、その瞬間に天秤に実際に存在していた力に対応します。 残高は減ることしかできないので、その力も元の残高以下である。 したがって、最終的な`l`元の二進対数を超えることはできません`n`。 

二分探索が終了すると、`r = l + 1`、最後に拒否された境界は、現在の残高が以下よりも小さいことを示しています。`2^r = 2^(l+1)`。 簡単に試してみることができるようになりました`2^l`、`2^(l-1)`、...、`1`。 これらはすべて、 より小さい数の 2 進数表現で発生する可能性がある累乗です。`2^(l+1)`、したがって、アカウントを完全に空にするのに十分です。 

可能な指数は 60 個しかないため、バイナリ検索クエリは最大 6 つです。`2^6 = 64 > 60`。 クリーンアップで使用されるのは最大でも`l + 1`クエリ、および`l <= q`、 どこ`q`元のバランスの対数です。 したがって、合計は最大でも`q + 7`、許容範囲を快適に下回ります`q + 10`。

 ## アルゴリズムのチュートリアル

 1.セット`l = 0`そして`r = 60`。 間隔は、以下のすべての可能な 2 進指数を表します。`0`を通して`59`、 そして`2^60`は、考えられるすべての初期バランスを超えることがすでに知られています。 
2. その間`r - l > 1`、 選ぶ`m = (l + r) // 2`そして撤回を求める`2^m`。 これが二分探索ステップです。 受け入れられた応答はその指数を証明します`m`達成可能なので設定します`l = m`。 拒否された応答は次のことを証明します`2^m`現在の残高に対して大きすぎるため、設定します`r = m`。 
3. インタラクターが応答した場合`fail`、すぐに終了します。 続いて`fail`有効な判決を下すことはできません。 
4. 二分探索の後、次の指数を処理します。`l`まで`0`。 指数ごとに`i`、撤回を依頼する`2^i`。 もし答えが`accepted`、その電力は残りの残高から削除されます。 そうであれば`rejected`、その電力に対応するビットがないため、何も変更する必要はありません。 
5. 印刷`finish`すべての力を通した後`2^0`検討されてきました。 この時点で残高はゼロでなければなりません。 

### なぜ効果があるのか

 二分探索の最後には、`r = l + 1`、右の境界は、ある時点で拒否されたパワーに対応します。 残高は拒否された後にのみ減少する可能性があるため、現在の残高は確実に`2^r = 2^(l+1)`。 より小さいすべての非負の整数`2^(l+1)`累乗のみを使用して表すことができます`2^l, 2^(l-1), ..., 1`。 クリーンアップ フェーズでは、これらのパワーを正確にテストし、存在するすべてのパワーを撤回するため、残りの残高はゼロになります。 

クエリ制限は 2 番目の不変条件から決まります。 二分探索が設定されるたびに`l = m`、の撤退`2^m`受け入れられました。これは、元の残高が少なくとも`2^m`。 したがって、`m <= q`。 その結果`l <= q`。 二分検索には最大 6 つのクエリが必要で、クリーンアップには最大でも 6 つのクエリが必要です。`l + 1 <= q + 1`クエリ、最大で合計`q + 7`、以下にあります`q + 10`。 

## Python ソリューション

 この問題はインタラクティブであるため、このプログラムは従来のテスト ケースを読み取るのではなく、公式インタラクターと通信することを目的としています。```python
import sys
input = sys.stdin.readline

def ask(x):
    print(f"withdraw {x}", flush=True)
    response = input().strip()

    if response == "accepted":
        return True
    if response == "rejected":
        return False

    # The only other possible response is "fail".
    sys.exit(0)

def main():
    l = 0
    r = 60

    # Find an exponent l such that the remaining balance is below 2^(l+1).
    while r - l > 1:
        m = (l + r) // 2

        if ask(1 << m):
            l = m
        else:
            r = m

    # The remaining balance is smaller than 2^(l+1).
    # Its binary representation therefore uses only these powers.
    for i in range(l, -1, -1):
        ask(1 << i)

    print("finish", flush=True)

if __name__ == "__main__":
    main()
```の`ask`関数は対話型の出金を 1 回だけ実行します。 使用する`flush=True`インタラクターはコマンドを受信するまで応答できないため、これは必須です。 この関数は 2 つの通常の応答に対してブール値を返し、次の応答に対してはすぐに終了します。`fail`。 

二分探索間隔では、金額ではなく指数が使用されます。`r = 60`考えられるすべての初期残高が厳密に以下よりも小さいため、安全です。`2^60`。 ループ条件`r - l > 1`連続した境界を残すため、ループの後`r = l + 1`。 

表現`1 << m`計算する`2^m`直接。 Python の整数には任意の精度があるため、オーバーフローの問題はありません。 生み出される最大の価値は、`2^59`、これも安全に許可された引き出し金額の範囲内です。`10^18`。 

クリーンアップ ループは意図的に下向きになります。 より小さいべき乗を最初に処理した場合、後で受け入れられるより大きなべき乗でも、より小さいビットを含むバランスが残る可能性があり、推論が直接的ではなくなります。 降べきべき乗は通常のバイナリ分解を反映し、残りのすべてのビットが正確に 1 回処理されることが保証されます。 

拒否されたクリーンアップ クエリをスキップすることはできません。 拒否されたクエリもインタラクションとしてカウントされますが、そのバイナリ ビットが存在するかどうかを判断する必要があるため、これが必要になります。 このようなクエリの数はすでにカバーされています。`q + 7`縛られた。

## テストケース

 これは対話型の問題であるため、通常は`run(input_string)`テストでは、stdin を介して非表示のバランスを提供することはできません。 代わりに、便利なオフライン テスト ハーネスがインタラクターをシミュレートします。 次のコードは、偽の端末に対して同じアルゴリズムを使用し、最終残高がゼロであることを確認し、クエリ制限を検証します。```python
import io
import sys

def run_simulation(initial_balance):
    balance = initial_balance
    attempts = 0
    commands = []

    def ask(x):
        nonlocal balance, attempts
        attempts += 1
        commands.append(f"withdraw {x}")

        if balance >= x:
            balance -= x
            return True
        return False

    l = 0
    r = 60

    while r - l > 1:
        m = (l + r) // 2

        if ask(1 << m):
            l = m
        else:
            r = m

    for i in range(l, -1, -1):
        ask(1 << i)

    commands.append("finish")

    q = 0
    while (1 << q) < initial_balance:
        q += 1

    assert balance == 0
    assert attempts <= q + 10

    return "\n".join(commands)

# Provided sample 1 corresponds to an initial balance of 1.
sample1 = run_simulation(1)
assert sample1.endswith("finish"), "sample 1"

# Provided sample 2 corresponds to an initial balance of 0.
sample2 = run_simulation(0)
assert sample2.endswith("finish"), "sample 2"

# Minimum-size balance.
assert run_simulation(0).endswith("finish"), "zero balance"

# Small boundary values around powers of two.
for n in [1, 2, 3, 4, 7, 8, 9, 15, 16, 17]:
    run_simulation(n)

# A large value close to 2^60.
assert run_simulation(10**18).endswith("finish"), "maximum allowed balance"

# Exact powers of two exercise the boundary between q values.
for n in [2**10, 2**20, 2**30, 2**40, 2**50, 2**59]:
    run_simulation(n)

# Values immediately below and above powers of two catch off-by-one errors.
for n in [2**10 - 1, 2**10, 2**10 + 1]:
    run_simulation(n)
