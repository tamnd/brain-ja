 ## 問題の理解

 これは対話型の問題です。 口座残高を含む通常の入力はありません。 インタラクターは、(0 \le n \le 10^{18}) で初期残高 (n) を秘密裏に選択します。プログラムは、残高全体を転送するために、それに関する十分な情報を検出する必要があります。 唯一のクエリは、`withdraw x`。 現在の残高が少なくとも (x) の場合、インタラクターは応答します。`accepted`そして (x) を削除します。 それ以外の場合は応答します`rejected`そして残高は変更されないままになります。 印刷して終了する場合もあります`finish`, ただし、これは、隠された残高が実際にゼロである場合にのみ受け入れられます。 公式声明は、この対話型プロトコルと (q+10) 個のクエリの制限を確認しています。ここで、(q) は (n\le2^q) を満たす最小の整数です。 

課題は、単に (n) を見つけることではなく、破壊的な比較をほとんど行わずにそれを行うことです。 (n) は (10^{18}) まで大きくなるため、1 ドルあたり 1 回の出金を実行する戦略には (10^{18}) 個のクエリが必要になる可能性があります。 区間全体 ([0,10^{18}]) にわたる通常の二分検索でも約 60 個のクエリが使用されますが、(n) が小さい場合にはすでに多すぎます。 たとえば、(n=1) の場合、(q=0) となるため、最大 10 回の試行が許可されます。 

特別な注意が必要な 2 つの特殊なケースがあります。 (n=0) の場合、正しい対話は次のようになります。`withdraw 1`、受信`rejected`、 に続く`finish`。 2 の大きなべき乗を盲目的にテストし始める戦略では、多くのクエリが無駄になり、(q=0) の制限を超えてしまいます。 (n=1) の場合、最初の`withdraw 1`は受け入れられますが、それだけではアカウントが空であることを証明するものではありません。 2番目`withdraw 1`(n=1) と (n\ge2) を区別するために必要です。 たとえば、サンプル インタラクション```
withdraw 42
withdraw 1
withdraw 1
finish
```返信あり```

```最初の拒否は (n<42) を示し、最初に受け入れられた出金は (n\ge1) を示し、2 番目の拒否は 1 ドルを取り出した後に何も残っていないことを証明します。 公式サンプルには、まさにこのやり取りが含まれています。 

## アプローチ

 直接的なアプローチは、繰り返し試すことです`withdraw 1`。 クエリが成功するたびにちょうど 1 ドルが削除されるため、これは明らかに正しく、最終的にアカウントは空になります。 問題は操作回数です。 (n=10^{18}) の場合、正確に (10^{18}) 回の試行が必要ですが、インタラクターは (q=60) で (q+10) のみを許可します。 このアプローチは遠隔地では実現不可能です。 

より有望なアイデアは、2 のべき乗を使用することです。 バランスが (2^k) と (2^{k+1}-1) の間にあることが何らかの形でわかっている場合、(2^{k-1},2^{k-2},\ldots,1) を撤回すると、最大 (k) 個のクエリで残りのバイナリ表現が抽出されます。 欠けている部分は、2 のべき乗をテストするだけでさらに (k) クエリを費やすことなく (k) を発見する方法です。 

重要な観察は、成功した引き出しは元の残高との比較として扱うことができるということです。 ちょうど (s) ドルをすでに引き出しているので、当座預金口座には (n-s) が含まれていると仮定します。 元の残高が少なくとも何らかの目標 (T) であったかどうかを尋ねるには、次のように要求できます。`withdraw T-s`。 それが受け入れられる場合は、(n-s\ge T-s) となり、(n\ge T) と同等になります。 クエリが成功すると、引き出される合計金額はちょうど (T) になります。 拒否された場合、引き出し総額は (s) 残り、これで (n<T) ことがわかりました。 

これにより、(n) を超えない最大の 2 のべき乗の指数で二分探索を実行できるようになり、比較が成功するたびに、既に引き出した金額がテストされたべき乗に移動するだけになります。 可能な指数は 60 個しかないため、その指数を見つけるのに必要なクエリは約 6 回だけです。 その後、残りの残高は既知の最大の 2 のべき乗より小さいため、そのバイナリ表現を直接抽出できます。 

ブルートフォース手法では 1 ドルあたり 1 つのクエリが使用されますが、最適な手法では一定数のクエリを使用して大きさを特定し、その後 2 進数ごとに 1 つのクエリが使用されます。 クエリ制限自体が (n) で対数であるため、この区別は重要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n)) クエリ | (O(1)) | 遅すぎる |
 | 最適 | (O(\log n)) クエリ | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 ドル要求します。 インタラクターが拒否した場合、非表示残高はゼロになるため、次のように出力します。`finish`。 これは、単一のクエリ内で (n=0) のケースを処理します。 
2. 最初の 1 ドルが受け入れられた場合は、もう 1 ドル要求します。 拒否された場合、元の残高はちょうど 1 であるため、次のように出力します。`finish`。 2 回の 1 ドルの出金が受け入れられた後、(n\ge2) とちょうど 2 ドルがすでに削除されたことがわかります。 
3. メンテナンス`paid`、すでに引き出された合計金額。 最初は`paid = 2`。 ここで、(2^f\le n) のような最大の指数 (f) を見つけます。 (n\le10^{18}<2^{60}) なので、1 から 59 までの指数を検索すれば十分です。 
4. 指数を二分探索します。 候補指数 (m) については、次のようにします。`target = 2^m`。 もし`target <= paid`の場合、(n\gepaid\ge target) はすでにわかっているため、クエリは必要ありません。 それ以外の場合はリクエストしてください`withdraw target - paid`。 受け入れられた応答は (n\ge target) であることを証明し、更新します`paid`に`target`。 拒否された応答は (n<target) を証明するため、候補指数が大きすぎます。 
5. 指数検索後、`paid = 2^f`そして (2^f\le n<2^{f+1})。 したがって、残りの残高は (2^f) より小さくなります。 べき乗 (2^{f-1},2^{f-2},\ldots,1) を降順にテストします。 クエリが受け入れられるたびに、その 2 進数が存在し、アカウントから削除されます。 拒否は、数字が存在しないことを意味します。 
6. これらすべてのべき乗がテストされると、(2^f) より下のすべての可能な 2 進数が削除されます。 アカウントは空なので印刷してください`finish`。 

### なぜ効果があるのか

 中心的な不変条件は次のとおりです`paid`は常に元のアカウントから削除された合計金額とまったく同じになります。 したがって、現在の残高は (n-\text{paid}) となります。 (n\ge T) と (T>\text{paid}) かどうかをテストしたいときはいつでも、クエリ`withdraw T-paid`は (n-\text{paid}\ge T-\text{paid}) のときに正確に受け入れられます。これは正確に (n\ge T) です。 成功したクエリも変化します`paid`(T) に変換し、不変式を維持します。 

その結果、指数検索により、(n) を超えない最大の 2 のべき乗が見つかります。 その電力が取り出されると、残りの量は厳密にそれより小さくなります。 すべての小さい累乗を降順でテストすることは、まさにバイナリ表現の貪欲な構築であるため、最終的には残りのすべてのドルが転送されます。 1 の最終べき乗がテストされた後は、クエリがゼロ以外の残高を残すことはできません。 

試行回数も特別なインタラクティブ境界内にあります。 初期クエリは最大 2 個、指数検索クエリは最大 6 個、2 進数クエリは最大 59 個あります。 したがって、最大 67 回の試行が行われます。 可能な最大の残高 (q=60) の場合、制限は 70 です。残高が小さい場合でも、指数検索のコストは一定のクエリ数のみですが、最終的なバイナリ抽出のコストは最大でも (q) クエリであり、必要なスラックは 10 クエリになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x):
    print(f"withdraw {x}", flush=True)
    response = input().strip()

    if response == "fail":
        sys.exit(0)

    return response == "accepted"

def finish():
    print("finish", flush=True)

# First distinguish n = 0 and n = 1.
if not ask(1):
    finish()
    sys.exit(0)

if not ask(1):
    finish()
    sys.exit(0)

# Two dollars have already been withdrawn.
paid = 2

# Find the largest f such that 2^f <= n.
lo = 1
hi = 59

while lo < hi:
    mid = (lo + hi + 1) // 2
    target = 1 << mid

    if target <= paid:
        lo = mid
    else:
        if ask(target - paid):
            paid = target
            lo = mid
        else:
            hi = mid - 1

f = lo

# Extract the remaining balance bit by bit.
power = 1 << (f - 1)

while power >= 1:
    if ask(power):
        pass
    power >>= 1

finish()
```の`ask`function は、インタラクターと通信する唯一の場所です。 コマンドを出力し、すぐにフラッシュして、応答を読み取ります。 あ`fail`続行するとプロトコルに違反するため、応答はプログラムを直ちに終了する必要があります。 

最初の 2 つの呼び出しは、`ask(1)`特別です。 1 つ目は、ゼロとプラスの残高を区別することです。 2 番目は 1 つと少なくとも 2 つを区別します。 両方の呼び出しが成功すると、`paid`は正確に 2 であり、元の残高からすでに削除されている既知の金額が得られます。 

指数検索中に、式は`target - paid`クエリは次の場合にのみ実行されるため、常に正になります。`target > paid`。 また、最大でも (2^{59}) であり、許可される最大クエリ量 (10^{18}) を下回ります。 Python の整数には任意の精度があるため、オーバーフローの問題はありません。 

最後のループでは、当座預金残高用の別の変数を維持する必要はありません。 電力の回収が成功するたびに、その 2 進数が削除されるだけです。 電力は最大から最小の順にテストされるため、どの点でも、テストされた電力は残りの可能なバランス範囲を超えることはありません。 

これは対話型タスクであるため、プログラムには解析するための通常の入力がありません。 必要な`input = sys.stdin.readline`宣言は、Python 実装規約で要求されているように、インタラクターの応答を読み取るために引き続き使用されます。

import io

def offline_commands(n):
    balance = n
    commands = []

    def ask(x):
        nonlocal balance

        assert 1 <= x <= 10**18
        commands.append(("withdraw", x))

        if balance >= x:
            balance -= x
            return True
        return False

    if not ask(1):
        commands.append(("finish",))
        return commands, balance

    if not ask(1):
        commands.append(("finish",))
        return commands, balance

    paid = 2

    lo = 1
    hi = 59

    while lo < hi:
        mid = (lo + hi + 1) // 2
        target = 1 << mid

        if target <= paid:
            lo = mid
        else:
            if ask(target - paid):
                paid = target
                lo = mid
            else:
                hi = mid - 1

    f = lo
    power = 1 << (f - 1)

    while power >= 1:
        ask(power)
        power >>= 1

    commands.append(("finish",))
    return commands, balance

    q = 0 if n == 0 else (n - 1).bit_length()
    attempts = sum(1 for command in commands if command[0] == "withdraw")

    assert balance == 0
    assert commands[-1] == ("finish",)
    assert attempts <= q + 10

    return commands

 ## 特殊なケース

 (n=0) の場合、正確な入力状態は隠れた残高ゼロであるため、最初のコマンドは次のようになります。`withdraw 1`。 インタラクターは (0<1) という理由でそれを拒否し、プログラムはすぐに出力します。`finish`。 試行は 1 回だけ行われましたが、(q=0) では 10 回の試行が許可されます。 

(n=1) の場合、対話は次のように始まります。`withdraw 1`、これは受け入れられ、ゼロのままになります。 すべての (n\ge1) に対して同じ応答が発生するため、この時点でプログラムを単純に終了することはできません。 送信します`withdraw 1`再び、受け取ります`rejected`、元の残高が 2 未満であったことがわかります。 最初に受け入れられた引き出しと組み合わせると、これは (n=1) であることがわかります。 その後、プログラムは 2 回の試行後に終了します (q+10=10)。 

(n=2) の場合、最初の 1 ドルのクエリは両方とも受け入れられるため、`paid=2`そして実際のアカウントは空です。 指数検索では、指数 1 がすでに有効であることがわかります。`paid`それ自体は (2^1) に等しい。 ゼロ値のクエリは発行されません。 残りの電力テストは資金がなくなり、すべて拒否されます。`finish`は正しいです。 これにより、実装が誤って試みる一般的な境界バグが回避されます。`withdraw 0`。 

(n=3) の場合、最初の 2 つの引き出しにより再び確立されます。`paid=2`。 (2\le3<4) であるため、指数検索では (f=1) が見つかります。 残りは1なので、最終的には`withdraw 1`成功して削除されます。 バイナリ抽出では、要求どおりに元の値が (2+1) として表現されています。 

(n=2^{59}) の場合、指数検索は最大許容電力 (2^{59}) に達します。 比較が成功した後、`paid`全体の残高と等しくなります。 最終テストでは、(2^{58}) から 1 までのべき乗が使用されますが、すべて拒否されます。 このケースでは、(2^{60}) をクエリすることなく指数の上限を行使しますが、これは許可された引き出し額 (10^{18}) を超えることになります。 

(n=10^{18}) の場合、可能な最大の初期残高は (q=60) になります。 このアルゴリズムは、最初に 2 ドルを引き出し、最大 6 つの追加クエリを使用して最も関連性の高い検出力を特定し、次に最大 59 の 2 進数クエリを使用します。 最悪のインタラクションでも、これは最大でも 67 回の引き出し試行であり、許容される回数 (q+10=70) を下回ります。 また、実装は、個々の引き出しごとに許可された最大値 (10^{18}) 内に収まります。
