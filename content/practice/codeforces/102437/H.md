 ## 問題の理解

 正の値の配列があります`a[1..n]`。 2 人のプレイヤーが左から右に処理します。 各ターンで、現在のプレイヤーは前からまだ使用されていない要素を任意の数捨てて、次の要素を取得することができます。 したがって、プレーヤーがポジションを取った後、`j`までのすべてのポジション`j`が消えて次のプレイヤーが開始します`j + 1`。 

プレイヤーは要素を取得する前に一部のプレフィックスを破棄できるため、要素をスキップできます。 目的は、個々の要素の合計を最大化することではなく、プレイヤー自身の合計と相手の合計との差を最大化することです。 Sam が最初に移動するため、次の最適値が必要です。`Sam's sum - Catcher's sum`。 

配列には最大で次のものを含めることができます`200000`要素はすべて、すべての値は次のように大きくできます。`10^9`。 公式声明では、時間制限は 2 秒、メモリ制限は 512 MB とされています。 アン`O(n^2)`アルゴリズムは約を実行します`n(n+1)/2`、またはおおよそ`20,000,100,000`、候補者は最大サイズで遷移しますが、これは制限時間内に収まるサイズをはるかに超えています。 必要なのは`O(n)`またはそれに近い`O(n log n)`解決。 答え自体は次のように大きくなる可能性があります`10^9`、Python 整数は、特別なオーバーフロー処理を行わずに安全に処理します。 

よくある間違いを明らかにする小さなケースがいくつかあります。 のために`n = 1`そして`a = [7]`、答えは`7`なぜなら、サムは単純に唯一の要素を取るからです。 のために`n = 2`そして`a = [1, 100]`、答えは`100`: サムは破棄できます`1`そしてすぐに取ってください`100`、2番目のプレーヤーには何も残りません。 すべての要素が取得される必要があると想定するソリューションでは、誤って取得されます。`-99`。 逆に、`n = 2`そして`a = [5, 1]`、サムは取るべきです`5`、その後相手は`1`、与える`4`。 ここでは常に最大の残りの値にジャンプする貪欲なルールが機能しますが、それが解決策が正しい理由ではありません。 

同等の価値観にも注意が必要です。 のために`[1, 1, 1, 1]`、答えは`1`、 ない`0`または`2`。 サムはそれを受け取ることができます`1`、対戦相手は別のものを取ることができますが、プレイヤーは要素をスキップすることもできます。 正しく反復するには、プレーヤーが単に隣接する要素を交互に移動することを前提とするのではなく、考えられるすべての次の位置を考慮する必要があります。 

## アプローチ

 直接的な動的プログラミングの定式化は、ゲームを正確に記述するのにすでに十分です。 させて`dp[i]`残りの配列がその位置で開始されるときのターンのプレイヤーにとっての最適なスコア差になります。`i`。 プレーヤーがポジションを選択したとします`j`、 どこ`j >= i`。 彼らは受け取ります`a[j]`、残りのゲーム全体は から始まります`j + 1`相手と一緒に移動します。 現在のプレイヤーの観点からすると、将来のゲームには価値がある`dp[j + 1]`相手に貢献するから`-dp[j + 1]`現在のプレイヤーのスコアに。 選択する`j`したがって、与えられます`a[j] - dp[j + 1]`。 

可能な限り最善の選択をすると、`dp[i] = max(a[j] - dp[j + 1])`みんなのために`j >= i`、

と`dp[n + 1] = 0`。 

すべての正当な手は現在のプレーヤーが選択するポジションによって完全に特徴付けられるため、この繰り返しは正しいです。 その位置が固定されると、残りのゲームはちょうど 1 つ、つまりその位置の後のサフィックスになります。 

ブルートフォース実装では、すべての最大値を個別に評価します。`i`。 のために`i = 1`それはチェックします`n`選択肢、のための`i = 2`それはチェックします`n - 1`、 等々。 チェックの合計数は、`n + (n - 1) + ... + 1 = n(n+1)/2`。 で`n = 200000`、つまり`20,000,100,000`チェックが行われるため、二次バージョンは合格できません。 

重要な観察は、最大化される式が特別な形式を持つということです。 計算するとき`dp[i]`、どの候補者も`a[j] - dp[j + 1]`。 位置に属する値`j`に依存しない`i`。 右から左に移動するにつれて、現在の位置に対応する新しい候補者を 1 つだけ追加します。 サフィックス全体を再度スキャンする代わりに、これまでに確認された最大の候補を維持できます。 これにより、二次漸化式が単一の後向きパスに変わります。 同じ最適化については公式論説でも説明されています。候補値は次のように固定されたままです。`i`減少するため、実行最大値で十分です。 

セグメント ツリーやその他の複雑なデータ構造は必要ありません。 クエリされる範囲は常に接尾辞であり、これらの接尾辞は逆方向の走査中にちょうど 1 要素ずつ増加します。

 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のサフィックスの値を次のように設定します。`dp[n + 1] = 0`。 コンストラクターが残っていない場合、獲得できるスコア差はありません。 
2. からの位置を処理します`n`まで`1`。 位置で`i`、まさにこのポジションを取る候補者は`a[i] - dp[i + 1]`。 引き算が表示されるのは、摂取した後だからです。`a[i]`の場合、対戦相手は最適スコア差が 1 であるプレイヤーになります。`dp[i + 1]`。 
3. 変数を維持する`best`の最大値を含む`a[j] - dp[j + 1]`すべてのポジションの中で`j`すでに処理されています。 加工時`i`、計算する`a[i] - dp[i + 1]`そして更新します`best`この候補者と一緒に。 
4.セット`dp[i] = best`。 これが機能するのは、州による法的選択があるためです。`i`まさに位置です`i, i + 1, ..., n`、 そして`best`はまさにそのサフィックスの最大の候補です。 
5. 加工後の位置`1`、出力`dp[1]`、その状態が元のゲームであり、サムが最初の動きをするプレイヤーであるためです。 

不変条件は、処理後の位置です。`i`、`best`の最大値に等しい`a[j] - dp[j + 1]`すべてにわたって`j >= i`。 その結果`dp[i]`まさに、から始まるゲームの最適な結果です。`i`。 すべての合法的な最初の動きは 1 つの候補によって表され、再発はその手の後の最適な継続を説明します。 再発は右から左に評価されるため、必要なすべての`dp[j + 1]`候補が検討された時点ですでにわかっています。 したがって、ランニングマキシマムでは、合法的な手を省略したり、違法な手を導入したりすることはできません。 

実装にはさらに簡素化が加えられています。 実際には全体を保存する必要はありません`dp`配列。 処理中`i`、 のみ`dp[i + 1]`が必要であり、実行最大値はすでに`dp[i]`。 以前の DP 値用に 1 つの変数を保持し、現在の最大値用に 1 つの変数を保持できます。 これにより、補助メモリが減少します。`O(1)`入力配列を超えています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(n, a):
    dp_next = 0
    best = -10**30

    for i in range(n - 1, -1, -1):
        candidate = a[i] - dp_next
        if candidate > best:
            best = candidate
        dp_next = best

    return dp_next

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve(n, a))

if __name__ == "__main__":
    main()
```配列は 1 回読み取られ、その後ループが最後の要素から開始されます。`dp_next`を表します`dp[i + 1]`したがって、最終位置を処理する前にゼロに初期化されます。 候補者`a[i] - dp_next`位置を選択することによって得られる値とまったく同じです`i`。 

候補を計算した後、`best`に割り当てる前に更新されます`dp_next`。 この順序が重要です。 新しい`dp[i]`現在の要素を取得する可能性が含まれるため、現在の候補は次の要素の一部である必要があります。`best`前に`dp_next`は次の反復の値になります。 

初期化`-10**30`考えられるすべての候補より安全です。 実際、すべてが`a[i]`が正であり、スコアの差が配列の合計によって制限される場合、通常の Python 整数ですでに十分です。 ループは正確に実行されます`n`反復が行われ、各反復では定数時間の演算と比較が使用されます。 

ソリューションでは、`O(n)`入力配列のみのメモリ`O(1)`動的プログラミング状態用の追加メモリ。 

## 実用的な例

 ### サンプル 1

 のために`a = [1, 2, 3]`、配列を右から左に処理します。 

| 位置`i`|`a[i]`|`dp_next`| 候補者`a[i] - dp_next`|`best`|`dp[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 3 | 3 | 3 |
 | 2 | 2 | 3 | -1 | 3 | 3 |
 | 1 | 1 | 3 | -2 | 3 | 3 |

 最初のプレイヤーは最終的に次の差を得ることができます。`3`。 最適な最初の動きは破棄することです`1`そして`2`そして取ってください`3`、すぐにゲームを終了します。 実行最大値は、以前のポジションが処理されるときにこのオプションを正しく保持します。 

### サンプル 2

 のために`a = [3, 2, 1]`と同様に逆方向に計算すると次のようになります。 

| 位置`i`|`a[i]`|`dp_next`| 候補者`a[i] - dp_next`|`best`|`dp[i]`|
 | --- | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 1 | 1 | 1 |
 | 2 | 2 | 1 | 1 | 1 | 1 |
 | 1 | 3 | 1 | 2 | 2 | 2 |

 最初の位置で、`3`葉`[2, 1]`、相手にとっての最適値は`1`、それでサムは得ます`3 - 1 = 2`。 スキップする代わりの方法`2`または`1`それはもっと良くありません。 結果は`2`、サンプルと一致します。

 単一のコンストラクターの場合、入力```

```から始まる`dp[2] = 0`。 唯一の候補は、`7 - 0 = 7`、 それで`best`そして`dp[1]`どちらもなる`7`。 アルゴリズムの出力`7`、特別なケースを必要とせずに接尾辞の境界を正しく処理します。

2

```最終的な位置は次のようになります`dp[2] = 100`。 位置で`1`をとり、`1`生み出すだろう`1 - 100 = -99`、しかしポジション候補`2`はすでに保存されています`best`として`100`。 したがって`dp[1] = 100`。 これは、サムが最初のコンストラクターを破壊して 2 番目のコンストラクターを取得することができ、その後は配列が空になり、対戦相手は動けなくなるという重要なルールを捉えています。
