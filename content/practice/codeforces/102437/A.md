 ## 解決策
 ## 問題の理解

 (n) 個の都市が円の周りに配置され、その中心に首都が 1 つあります。 可能な唯一の道路は、連続する外側の都市間の (n 個の) 環状道路と、首都から外側の都市への (n 個の) スポークです。 一部の道路が存在しない場合があります。 既存のすべての道路は、白または黒のいずれかによって管理されます。 

このグラフのスパニング ツリーを、含まれる白管理の道路の数に応じてカウントする必要があります。 木に正確に (k) 個の白い道路がある場合、それは係数 (a_k) に寄与します。 (n+1) 頂点上のスパニング ツリーには常に正確に (n) 個のエッジがあるため、(k) の範囲は (0) から (n) です。 

入力を 2 つの循環配列として考えると便利です。 文字列 (s) は円形のエッジを表します。(s_i) は都市 (i) から都市 (i+1) までのエッジで、(n+1) は都市 (1) として解釈されます。 文字列 (t) はスポークを表し、(t_i) は首都から都市 (i) までのエッジです。 キャラクター`W`エッジの重み (x)、文字を与える`B`それに重みを与えます (1)、そして`-`重み (0) を与えます。 

この場合、必要な答えは単にスパニングツリー生成多項式の係数列です。 

[
 F(x)=\sum_T x^{#W(T)}。 
】

 制約 (n\le 50000) は、(n) 内の二次関数を除外します。 (O(n^2)) 動的プログラムであっても、上限では約 (2.5\cdot 10^9) 個の基本演算が必要になります。 答え自体には (n+1) 個の係数があるため、(O(n\log^2 n)) または同様の多項式時間アプローチが適切です。 係数 (998244353) は、効率的な NTT 多項式乗算をサポートしているため、特に便利です。 

表面的に正しい数え方の議論が失敗する境界例がいくつかあります。 たとえば、すべてのスポークが欠落している場合、```
3
WWW
---
```円形の都市は循環を形成していますが、首都は孤立しているため、スパニングツリーは存在せず、答えは次のとおりです。`0 0 0 0`。 首都への接続を明示的に強制せずに外側のサイクルで森林をカウントする方法では、森林が誤ってカウントされます。 

If all roads are Black,```
3
BBB
BBB
```グラフは (K_4) であるため、(16) のスパニング ツリーがあり、すべてにゼロの白い道路が含まれています。 答えは、`16 0 0 0`。 定数係数はすべての多項式操作に耐える必要があるため、これは便利なチェックです。 

すべての道が白なら、```
3
WWW
WWW
```同じグラフには 16 本のスパニング ツリーがありますが、どのツリーにもちょうど 3 つの白いエッジが含まれています。 答えは、`0 0 0 16`。 これにより、多項式の次数が黒エッジの数として解釈される間違いが見つかります。 

周期的な境界も重要です。 のために```
4
---W
BBBB
```唯一の環状道路は都市 (4) から都市 (1) に戻る端です。 4 つの黒いスポークすべてで構成される 1 つのツリーと、白の円形エッジを使用し、都市へのスポーク (1) または都市へのスポーク (4) のいずれかを省略したさらに 2 つのツリーがあります。 したがって、答えは次のとおりです`1 2 0 0 0`。 円形配列をパスとして扱うと、これら 2 つのツリーが失われます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、既存の道路のすべてのサブセットを列挙し、正確に (n) 個のエッジが含まれているかどうかを確認し、それらのエッジがスパニング ツリーを形成しているかどうかをテストできます。 可能な道路は最大で (2n) 個あるため、すべてのサブセットを列挙すると、すでに (2^{2n}=4^n) 個の可能性が得られます。 すべてのサブセットの接続性をチェックするにはさらに (O(n)) のコストがかかり、最も単純な実装では (O(n4^n)) 時間がかかります。 木に正確に (n) 個のエッジがあるという事実を使用しても、これは大まかに変わるだけです

 [
 O\left(n\binom{2n}{n}\right),
 】

 それは依然として指数関数的です。 すべてのスパニング ツリーは正確に 1 つの列挙されたエッジ サブセットであるため、ブルート フォースは正しいですが、ずっと前 (n=50000) で役に立たなくなります。 

このグラフの構造により、スパニング ツリーをより詳細に説明できます。 選択した円形エッジのみを見てください。 これらはパスの集合、または円全体を形成します。 少なくとも 1 つの円形エッジが欠落している場合、選択した円形エッジによって外側の頂点がいくつかのパス コンポーネントに分割されます。 このようなすべてのコンポーネントには、首都への選択されたスポークが 1 つだけ含まれている必要があります。 スポークが含まれていない場合、そのコンポーネントは首都から切り離されたままになります。 2 つ以上のスポークが含まれている場合、2 つのスポークとそのエンドポイント間のパスがサイクルを作成します。 

この観察により、グラフ問題がローカルシーケンス問題に変換されます。 円の周りを歩き回っている間、現在の外側のコンポーネントにその固有のスポークがすでに取り付けられているかどうかを思い出すだけで済みます。 それが二状態オートマトンです。 

グラフの周期的な性質は、このオートマトンを任意に選択した開始状態から実行する代わりに、その (2\times2) 遷移行列を乗算してそのトレースを取得することを意味します。 トレースは、最後のエッジの後の状態を最初のエッジの前の状態と強制的に等しくします。これは、まさにシーケンスがラップアラウンドするときに必要とされるものです。 

各行列エントリは (x) の多項式です。 したがって、要素が次数が増加する多項式である小さな行列を乗算 (n) する必要があります。 通常の多項式乗算は再び 2 次になるため、最後の要素は NTT 畳み込みです。 分割統治積ツリーは (O(\log n)) レベルで行列を乗算しますが、各レベルは (O(n\log n)) によって制限される多項式乗算の合計量を実行します。 完全な複雑さは (O(n\log^2 n)) です。 

行列の積自体は、通常の 8 つの代わりに Strassen (2\times2) 公式を使用して 7 つの多項式乗算で実行できます。 これは単なる実装の最適化ですが、多項式の畳み込みが実行時間の大半を占めるため、Python の実装にとっては重要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n4^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log^2 n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 既存のすべての道路を多項式の重みとして扱います。 白い道路には重み (x)、黒い道路には重み (1)、存在しない道路には重み (0) が与えられます。 選択したエッジ セットの重みの積は正確に (x^k) になります。ここで (k) はその白エッジの数です。 
2. すべての外側の都市 (i) について、(q_i) をそのスポークの重みとし、(r_i) を (i) から (i+1) までの円形エッジの重みとします。 

都市 (i) を処理している間、状態 (0) または (1) を維持します。 状態 (0) は、現在の円形コンポーネントがまだスポークを選択していないことを意味し、状態 (1) は、すでに一意のスポークを持っていることを意味します。 
3. まず、円形エッジ (i) が存在しない場合を考えます。 現在のコンポーネントは都市 (i) で終わるため、スポークは 1 つだけ含まれている必要があります。 状態 (0) から、寄与するスポーク (q_i) を選択し、次のコンポーネントの状態 (0) に移動する必要があります。 状態 (1) から、(1) に寄与する別のスポークを選択して、再び状態 (0) に移動してはなりません。 

その遷移行列は次のとおりです。

[
 A_i=
 \begin{p行列}
 q_i&0\
 1&0
 \end{p行列}。 
】
 4. 次に、円形エッジ (i) が選択された場合を考えます。 貢献します(r_i)。 現在のコンポーネントの状態 (0) がある場合、スポークを省略して状態 (0) に留まるか、スポークを選択して状態 (1) に移動します。 コンポーネントがすでに状態 (1) を持っている場合は、別のスポークを選択できないため、状態 (1) のままになります。 

エッジの重みを乗算する前の遷移行列は次のとおりです。 

[
 B_i=
 \begin{p行列}
 1&q_i\
 0&1
 \end{p行列}。 
】

 円形エッジの重みを含めると (r_iB_i) が得られます。 
5. 円形エッジのどちらかの状態を選択できるため、完全な遷移行列は次のようになります。 

\begin{p行列}
 q_i+r_i&q_ir_i\
 1&r_i
 \end{p行列}。 
】

 有効なローカル選択はすべて、この行列内で 1 回だけ表されます。 
6. すべての行列を循環順序で乗算します。 

[
 P=M_1M_2\cdots M_n。 
】

 (\operatorname{tr}(P)) を取得すると、オートマトンは開始時と同じ状態で強制的に終了します。 少なくとも 1 つの円形エッジが存在しない場合、すべての円形コンポーネントに 1 つのスポークが含まれるという条件が正確に与えられます。 
7. トレースではカウントされますが、スパニング ツリーではない例外的な設定が 1 つあります。 すべての円形エッジを選択すると、外側の頂点が 1 つの完全なサイクルを形成します。 オートマトンには 2 つの可能な循環状態 (どこでも状態 (0) とどこでも状態 (1)) があり、どちらも次と等しい寄与を生成します。 

[
 \prod_i r_i.
 】

 どちらの構成でもスポークが選択されていないため、首都は切断されています。 したがって、減算する必要があります

 [
 2\prod_i r_i.
 】

 円形エッジが存在しない場合、この積はゼロとなり、減算するものは何もありません。 
8. すべてのスパニング ツリーには正確に (n) 個のエッジがあるため、結果として得られる多項式の次数は最大 (n) です。 多項式の乗算中に、次数 (n) を超える係数は最終的な答えに影響を与えることがないため、破棄できます。 
9. (n) 個の多項式行列を順次乗算すると、(O(n^2)) 個の作業が生成されます。 代わりに、バランスのとれた分割統治型の製品ツリーを構築します。 行列のセグメントはその積で表され、再帰呼び出しが返されると、隣接する 2 つのセグメントの積が乗算されます。 
10. 多項式乗算は NTT によって (998244353) に基づいて実行されます。 非常に小さな多項式の場合、通常の (O(ab)) 乗算は NTT アレイを構築するよりも高速であるため、実装では小さな単純乗算しきい値が使用されます。 
11. 最後に、完全な行列のトレースを取得し、例外的な全円エッジの寄与を差し引いて、係数 (0) から (n) を出力します。 

この構築の背後にある不変条件は、円形エッジが処理されるたびに、現在開いている円形コンポーネントに許可された 1 つのスポークが既に含まれているかどうかをマトリックス状態が正確に記録するということです。 存在しない円形エッジを通過する遷移は、コンポーネントにスポークが 1 つだけある場合にのみ許可されますが、選択された円形エッジは 2 番目のスポークを許可せずにコンポーネントを延長するだけです。 したがって、トレースによってカウントされるすべての循環状態シーケンスは、コンポーネントごとに正確に 1 つのスポークを持つ循環パスの集合に対応します。 このようなコレクションは正確に (n) 個のエッジを持ち、接続されているため、スパニング ツリーになります。 この対応関係の外にある唯一のトレース構成は、すべての円形エッジが選択された場合の 2 つのゼロ スポーク状態であり、これらは明示的に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
ROOT = 3
NAIVE_LIMIT = 32

LIMIT = 0
root_cache = {}
inv_root_cache = {}

def cut(p):
    if len(p) > LIMIT + 1:
        p = p[:LIMIT + 1]
    while len(p) > 1 and p[-1] == 0:
        p.pop()
    return p

def padd(a, b):
    n = max(len(a), len(b))
    c = [0] * n
    la = len(a)
    lb = len(b)
    for i in range(n):
        x = a[i] if i < la else 0
        y = b[i] if i < lb else 0
        z = x + y
        if z >= MOD:
            z -= MOD
        c[i] = z
    return cut(c)

def psub(a, b):
    n = max(len(a), len(b))
    c = [0] * n
    la = len(a)
    lb = len(b)
    for i in range(n):
        x = a[i] if i < la else 0
        y = b[i] if i < lb else 0
        z = x - y
        if z < 0:
            z += MOD
        c[i] = z
    return cut(c)

def lincomb(items):
    n = 1
    for p, _ in items:
        if len(p) > n:
            n = len(p)

    c = [0] * n
    for p, sign in items:
        if sign == 1:
            for i, x in enumerate(p):
                c[i] += x
        else:
            for i, x in enumerate(p):
                c[i] -= x

    for i in range(n):
        c[i] %= MOD

    return cut(c)

def ntt(a, invert):
    n = len(a)

    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        if invert:
            wlen = inv_root_cache.get(length)
            if wlen is None:
                wlen = pow(ROOT, (MOD - 1) // length, MOD)
                wlen = pow(wlen, MOD - 2, MOD)
                inv_root_cache[length] = wlen
        else:
            wlen = root_cache.get(length)
            if wlen is None:
                wlen = pow(ROOT, (MOD - 1) // length, MOD)
                root_cache[length] = wlen

        half = length >> 1

        for start in range(0, n, length):
            w = 1
            end = start + half
            j = start
            while j < end:
                u = a[j]
                v = a[j + half] * w % MOD

                x = u + v
                if x >= MOD:
                    x -= MOD

                y = u - v
                if y < 0:
                    y += MOD

                a[j] = x
                a[j + half] = y
                w = w * wlen % MOD
                j += 1

        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    if not a or not b:
        return [0]

    if a == [0] or b == [0]:
        return [0]

    la = len(a)
    lb = len(b)

    if min(la, lb) <= NAIVE_LIMIT or la * lb <= 4096:
        res = [0] * (min(la + lb - 1, LIMIT + 1))

        for i, x in enumerate(a):
            if x == 0:
                continue
            max_j = min(lb, LIMIT + 1 - i)
            for j in range(max_j):
                res[i + j] = (res[i + j] + x * b[j]) % MOD

        return cut(res)

    need = min(la + lb - 1, LIMIT + 1)

    size = 1
    while size < la + lb - 1:
        size <<= 1

    fa = a + [0] * (size - la)
    fb = b + [0] * (size - lb)

    ntt(fa, False)
    ntt(fb, False)

    for i in range(size):
        fa[i] = fa[i] * fb[i] % MOD

    ntt(fa, True)

    return cut(fa[:need])

def matrix_add(a, b):
    return (
        padd(a[0], b[0]),
        padd(a[1], b[1]),
        padd(a[2], b[2]),
        padd(a[3], b[3]),
    )

def matrix_product(a, b):
    """
    a = [[a0, a1],
         [a2, a3]]

    b = [[b0, b1],
         [b2, b3]]

    Polynomial Strassen multiplication.
    """

    a0, a1, a2, a3 = a
    b0, b1, b2, b3 = b

    p1 = convolution(padd(a0, a3), padd(b0, b3))
    p2 = convolution(padd(a2, a3), b0)
    p3 = convolution(a0, psub(b1, b3))
    p4 = convolution(a3, psub(b2, b0))
    p5 = convolution(padd(a0, a1), b3)
    p6 = convolution(psub(a2, a0), padd(b0, b1))
    p7 = convolution(psub(a1, a3), padd(b2, b3))

    c0 = lincomb([
        (p1, 1),
        (p4, 1),
        (p5, -1),
        (p7, 1),
    ])

    c1 = lincomb([
        (p3, 1),
        (p5, 1),
    ])

    c2 = lincomb([
        (p2, 1),
        (p4, 1),
    ])

    c3 = lincomb([
        (p1, 1),
        (p3, 1),
        (p2, -1),
        (p6, 1),
    ])

    return c0, c1, c2, c3

def make_poly(v):
    if v == 0:
        return [0]
    if v == 1:
        return [1]
    return [0, 1]

def build_product(s, t, left, right):
    if right - left == 1:
        q = make_poly(1 if t[left] == 'B' else 0 if t[left] == '-' else 2)
        r = make_poly(1 if s[left] == 'B' else 0 if s[left] == '-' else 2)

        # The encoding above used 2 for W temporarily.
        # Replace it by the polynomial x.
        if t[left] == 'W':
            q = [0, 1]
        if s[left] == 'W':
            r = [0, 1]

        qr = convolution(q, r)
        qr = cut(qr)

        return (
            padd(q, r),
            qr,
            [1],
            r,
        )

    mid = (left + right) >> 1

    a = build_product(s, t, left, mid)
    b = build_product(s, t, mid, right)

    return matrix_product(a, b)

def solve_case(n, s, t):
    global LIMIT
    LIMIT = n

    # M_i =
    #
    # [ q_i + r_i, q_i r_i ]
    # [     1,       r_i   ]

    product = build_product(s, t, 0, n)

    answer = product[0][:]
    if len(product[3]) > len(answer):
        answer += [0] * (len(product[3]) - len(answer))

    for i, x in enumerate(product[3]):
        answer[i] = (answer[i] + x) % MOD

    # The trace is product[0] + product[3].
    # If every circular edge is present, it contains two
    # invalid zero-spoke cyclic states.
    if '-' not in s:
        white_rim = s.count('W')
        if white_rim >= len(answer):
            answer += [0] * (white_rim + 1 - len(answer))
        answer[white_rim] = (answer[white_rim] - 2) % MOD

    if len(answer) < n + 1:
        answer += [0] * (n + 1 - len(answer))

    answer = answer[:n + 1]

    return ' '.join(map(str, answer))

def main():
    n = int(input())
    s = input().strip()
    t = input().strip()
    print(solve_case(n, s, t))

if __name__ == "__main__":
    main()
```この実装では、(2\times2) 多項式行列を行優先の 4 つの多項式のタプルで表します。 葉っぱのところに、`q`はスポークの重量であり、`r`は円形エッジの重みなので、行列は正確に次のようになります。 

[
 \begin{p行列}
 q+r&qr\
 1(&R)
 \end{p行列}。 
】

 での小さな変換`build_product`意図的に、存在しないエッジをゼロ多項式として、黒エッジを定数多項式 (1) として、白エッジを (x) として保持します。 

再帰関数`build_product`元の循環順序が維持されます。 まず左半分と右半分の積を計算し、次にこれら 2 つの行列を乗算します。 行列の交換は実行されません。行列の乗算自体は可換ではないため、これは必要です。 

多項式演算は常に次数 (n) で切り捨てられます。 これは安全です。なぜなら、必要なすべてのスパニング ツリー項には正確に (n) 個のエッジがあり、より高い次数の係数が要求された答えに影響を与えることはありません。 

行列の乗算では、7 積のストラッセン恒等式が使用されます。 多項式の場合、その恒等式の各スカラー乗算は畳み込みに置き換えられます。 これにより、行列マージごとに 8 つの NTT 畳み込みが 7 つに減ります。 

の`convolution`関数は、入力が小さい場合は通常の乗算​​に切り替えます。 NTT は比較的大きな定数係数を持っていますが、数十の係数からなる多項式は直接乗算する方が安価であるため、これは重要です。 

(2\prod r_i) の減算は、別の多項式乗算を行わずに実装されます。 各 (r_i) は (0)、(1)、または (x) のいずれかであるため、円形エッジが存在しない場合、それらの積はゼロになります。 それ以外の場合は、単純に (x^c) になります。ここで、(c) は白い円形エッジの数です。 

Python の整数はオーバーフローしないため、別個のオーバーフローの懸念はありません。 多項式に入力されるすべての算術結果は、剰余法 (998244353) で縮小されます。 必要な最大の変換はサポートされている 2 のべき乗を十分に下回っているため、NTT の長さがモジュラス制限に近づくことはありません。

 ## 特殊なケース

 首都にインシデントエッジがない場合、アルゴリズムは自動的にゼロを与えます。 すべての遷移には (q_i=0) があるため、円形コンポーネントは選択されたスポークで閉じることはできません。 円形グラフがまだ存在する場合、トレースは円形構成を表す可能性がありますが、コンポーネントごとに 1 つのスポークという必須の条件により円形構成は排除されます。 のために`3 / WWW / ---`、すべての係数はゼロです。 

すべての道路が黒の場合、すべての道路の重みは (1) になります。 (n=3) の場合、グラフは (K_4) となり、遷移積により完全なスパニング ツリー カウントが生成されます。 補正により 2 つの無効な全円エッジ状態が減算され、(16) が 0 度のままになります。 したがって、答えは次のとおりです`16 0 0 0`。 

すべての道路が白の場合、選択されたすべてのエッジが (x) の 1 つの係数に寄与します。 すべてのスパニング ツリーには厳密に (n) 個のエッジがあるため、すべての有効な用語には次数 (n) が必要です。 (n=3) の場合、多項式は (16x^3) となり、次のようになります。`0 0 0 16`。 これは、(n) を超える次数を切り捨てても有効な答えを削除できないことを確認するのにも役立ちます。 

円形エッジが 1 つ欠落している場合、(\prod_i r_i=0) のため、例外的な補正は消えます。 たとえば、```
4
---W
BBBB
```唯一の円形エッジはラップアラウンド エッジ (4\leftrightarrow1) です。 オールスポーク ツリーは、次数 0 の 1 つの項に寄与します。 白い円形エッジを選択すると、都市 (4) と (1) の間にパスが作成されるため、2 つのスポークのうち 1 つを正確に削除する必要があります。 そのような木が 2 つあり、両方とも 1 つの白いエッジがあります。 結果は`1 2 0 0 0`。 

すべての円形エッジが存在する場合は、微妙な周期境界の場合です。 オートマトンはコンポーネントを閉じることなく永久に状態 (0) または永久に状態 (1) に留まることができるため、トレースには 2 つの人為的な構成があります。 どちらも、すべての円形エッジを選択し、スポークを選択しないことに対応します。 首都が分離されているため、これらはスパニング ツリーではないため、正確に (2\prod_i r_i) を減算する必要があります。 減算では、積が (x) の適切なべき乗を伝達するため、黒と白の混合円形エッジも正しく処理されます。 

最後に、存在しないエッジは単純にスキップするのではなく、ゼロ多項式で表す必要があります。 それらの存在により、選択したエッジの重みだけでなく、接続構造も変化します。 遷移行列は、存在しない道路を選択するすべての遷移の寄与をゼロにすることでこれを組み込んでおり、同時に、その道路が省略された場合にオートマトンが現在のコンポーネントを閉じることを可能にします。
