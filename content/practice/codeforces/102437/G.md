 ## 問題の理解

 頂点が都市、エッジが道路である無向グラフがあります。 サムは都会からスタート`s`時に`0`そして街に行きたいと思っています`t`できるだけ早く。 すべての道路には、独自の繰り返しの天気スケジュールがあります。 道路にパラメータがある場合`a`、`b`、 そして`d`、その期間は`P = a + b`。 どの時間帯でも路面は常に乾いています`Pk`を通して`Pk + a`、そしてからの雨`Pk + a`を通して`P(k + 1)`。 サムは都市では自由に待つことができますが、道路を横断している間は`d`時間単位では、横断全体が 1 つの乾燥間隔内に収まる必要があります。 

タスクは、次の場所への最も早い到着時間を計算することです。`t`、 または`-1`使用可能なルートが存在しない場合。 道路には方向性がないため、サムが道路を使用する方向に関係なく、同じタイムスケジュールが適用されます。 

グラフには最大で`100000`都市と`200000`道路。 このサイズでは、単純なパスの数がすでに指数関数的に増加している可能性があるため、すべての可能なパスを検査するアルゴリズムは絶望的です。 たとえ`O(nm)`この規模ではグラフ アルゴリズムは高価すぎるため、線形に近い、または`O(m log n)`アプローチ。 の値`a`、`b`、 そして`d`到達できる`10^9`、待機は多くの道路にわたって蓄積される可能性があるため、実装では 32 ビット整数よりもはるかに大きな時間も処理する必要があります。 Python 整数はこれに自動的に適しています。 

不用意に実装すると失敗する可能性がある境界がいくつかあります。 まず、道路は次の場合にのみ使用できます。`d <= a`。 例えば、```
2 1 1 2
1 2 1 1 2
```長さの乾燥間隔があります`1`、しかし、その道はかかります`2`交差する単位があるため、答えは次のようになります。`-1`。 道路を平均的な移動時間があるものとして扱ったり、単に出発時点で道路が乾いているかどうかを確認するだけでは、誤って許可されてしまいます。 

2 番目の境界は、Sam がドライ インターバルの開始時刻に正確に開始し、ドライ インターバルの終了時刻に正確に終了する可能性があることです。 例えば、```

## アプローチ

 直接的なブルート フォース ソリューションでは、考えられるすべてのルートを列挙できます。`s`に`t`、そのルート内のすべての道路の天気予報をシミュレートし、最も早い到着時間を維持します。 これは正しいです。すべての実行可能な行程が何らかのグラフ パスに対応しており、固定パスをシミュレートすると、可能な限り最も早い通過時間がわかるからです。 問題はパスの数です。 スパースなグラフであっても、階層化されたグラフには次の要素を含めることができます。`2^(n/2)`独特のシンプルな`s`に`t`パス。 あらゆる道が通るなら`Theta(n)`シミュレーションする作業、最悪のケースは`Theta(n * 2^(n/2))`処理できる範囲をはるかに超えた操作`n = 100000`。 

有益な観察は、サムが都市に到着したときに、その履歴全体を思い出す必要がないということです。 彼がある都市に到着したとします。`x`。 どのような往路でも、その道路を横断し始めることができる最も早い時刻が独自に決定されます。 市内で長く待っても、この可能な限り早い出発より早く他の終点に到着することはできません。 

1つの道路については、`P = a + b`そしてさせてください`r = x mod P`。 もし`d > a`、すべての乾きの間隔はわずかであるため、道路を横断することはできません。`a`単位が長い。 それ以外の場合、サムは次の場合にすぐに立ち去ることができます`r + d <= a`。 この条件が満たされない場合は、次の乾燥間隔が始まるまで待たなければなりません。`x - r + P`、そして支出`d`道路上のユニット。 

これにより、一定の時間がかかる時間依存のエッジ緩和が得られます。 さらに重要なことは、結果として得られる最早到着関数は FIFO であるということです。都市に遅く到着しても、同じ道を通って他の終点に早く到着することは決してできません。 即時横断可能な部分内では開始時間とともに到着時間が増加します。 トラバースが適合しなくなると、これらの開始時間はすべて次の同じ乾燥間隔を待って平坦なセクションが生成され、その後関数が再び上昇します。 したがって、通常のディクストラの貪欲な選択は依然として有効です。 

ブルート フォース アプローチは、すべてのパスを正確に評価できるため機能しますが、パスが多すぎるため失敗します。 FIFO プロパティを使用すると、同じ都市に到達するすべてのパスを単一の状態 (最も早い到着時刻) にまとめることができます。 次に、ダイクストラのアルゴリズムを使用して、固定エッジの重みを、その道路を通る最も早い合法的な到着を計算する定数時間関数に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 両方向のすべての道路を含む隣接リストを作成します。 道路ごとに、そのパラメータを保存します`a`、`b`、 そして`d`なぜなら、天気予報はどちらのエンドポイントからでも同じだからです。 
2.初期化`dist[s] = 0`そして、無限までのあらゆる距離。 置く`(0, s)`最小ヒープに入れます。 ヒープからは、現在わかっている最も早い到着時間が最も短い都市が常に表示されます。 
3.都市のとき`u`時間の経過とともにヒープから削除されます`cur`、次の場合はエントリを無視します。`cur`よりも大きいです`dist[u]`。 このようなエントリは、後の緩和によってすでに到達するためのより良い方法が見つかっているため、古くなります。`u`。 
4. からのすべての道路について`u`に`v`、最初にその周期を計算します`P = a + b`。 もし`d > a`、横断を含めるのに十分な長さの乾燥区間がないため、この道路はスキップします。 
5. それ以外の場合は計算します`r = cur % P`。 もし`r + d <= a`, サムはすぐに道路に入ることができるので、到着候補時間は`cur + d`。 
6. もし`r + d > a`、現在の乾燥間隔は短すぎます。 サムは次の生理が始まるまで待ちます`cur - r + P`、道路を横切り、候補者が到着します`cur - r + P + d`。 
7. この候補が以下より小さい場合`dist[v]`、 アップデート`dist[v]`そして押します`(candidate, v)`山の中へ。 緩和は通常のダイクストラとまったく同じ役割ですが、エッジの有効移動時間が現在時刻に依存する点が異なります。 
8. ヒープが空になったら、出力します。`dist[t]`有限の場合は出力、それ以外の場合は出力`-1`。 すぐに中止することも可能です`t`ヒープは、将来の状態がこれより短い到着時間を持つことはできないことを保証するため、現在の距離でポップされます。 

### なぜ効果があるのか

 不変条件は、都市が常に`u`ヒープから永続的に抽出されます。`dist[u]`サムが到着できる最も早い時間です`u`。 すべての下り道路について、到着時刻を考慮して緩和により、他の終点への可能な限り最も早い到着が計算されます。`u`。 道路の到着関数は FIFO であるため、到達`u`後でその道路を通って早く到着することはできません。 したがって、通常のダイクストラの議論が適用されます。つまり、最小の暫定到着時間を抽出した後、未発見のルートはその都市に早く到着することはできません。 これをすべてのリラクゼーションにわたって繰り返すと、到達可能なすべての都市の真の最も早い到着時間が得られます。`t`。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m, s, t = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v, a, b, d = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, a, b, d))
        graph[v].append((u, a, b, d))

    dist = [INF] * n
    dist[s - 1] = 0

    pq = [(0, s - 1)]

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        if u == t - 1:
            print(cur)
            return

        for v, a, b, d in graph[u]:
            if d > a:
                continue

            period = a + b
            r = cur % period

            if r + d <= a:
                arrive = cur + d
            else:
                arrive = cur - r + period + d

            if arrive < dist[v]:
                dist[v] = arrive
                heapq.heappush(pq, (arrive, v))

    print(-1)

if __name__ == "__main__":
    solve()
```隣接リストには方向のない各道路が 2 回保存されるため、横断方向に関係なくすべての緩和が同一になります。 保存された各タプルには、次の正当な走査を計算するために必要なパラメータが正確に含まれています。 

小切手`d > a`不可能な道路を直ちに削除します。 ドライ間隔は正確に長さがあります`a`、したがって、これより長く走査することはできません`a`その中に収まることができます。 

表現`cur % period`現在の天気サイクル内でのサムの位置を示します。 いつ`r + d <= a`、雨が降り始める前にトラバース全体が収まります。 乾燥間隔のエンドポイントは有効であるため、等価性が許可されます。 

トラバースが合わないときは、`cur - r`現在の期間の始まりなので、`cur - r + period`次の期間の始まりです。 追加`d`待った後、最も早い到着を与えます。 この公式は浮動小数点演算を回避し、任意のサイズの時間を処理します。 

優先キューは遅延削除を使用します。 都市は、徐々により良いルートが見つかった後に数回挿入される可能性があるため、抽出されたペアの時刻が現在の時刻と異なる場合は常に無視されます。`dist[u]`。 

考えられる最大の答えは、`10^9`なぜなら、多くの道路はそれぞれ、移動時間と待ち時間に多大な影響を与える可能性があるからです。 Python の任意精度の整数は、特別な処理を行わなくてもオーバーフローを回避します。
