 ## 解決策
 ## 問題の理解

 ウィリアムが知らない個別の単語の固定リストが与えられます。 仕事中、彼は一連の文章を順番に読みますが、それらの文章内のすべての単語はこの「未知の語彙」セットに属します。 

ウィリアムは単語に出会うたびに、辞書検索を実行するか、その単語を避けます。 検索を回避するためのルールは、単一の記憶に依存します。つまり、彼は最後に検索した単語だけを覚えています。 現在の単語が記憶されている単語と等しい場合、再度検索する必要はありません。 アンが暗記する特別な単語を 1 つ選択した場合、その単語が表示されるたびに、ウィリアムは検索の代わりにすぐにアンを使用できます。これも「検索しなかった」こととしてカウントされます。 

このプロセスは厳密に逐次的に行われます。 各単語の後で、「最後に検索された単語」が更新されることがありますが、これはウィリアムが実際に検索を実行した場合に限られます。 単語をスキップした場合 (アンのため、または最後に検索した単語と一致したため)、記憶は変わりません。 

課題は、アンの記憶した単語の選択肢ごとに、読解プロセス全体をシミュレートし、ウィリアムが実行した辞書検索の回数を数えることです。 

制約は大きく、最大 100,000 単語および 100,000 センテンス ワードです。 候補ごとの単純なシミュレーションでは最大 10^10 の演算が必要になりますが、これは実現可能な 2 秒のソリューションをはるかに超えています。 これにより、単語ごとにプロセス全体を個別に再シミュレートするソリューションは即座に除外されます。 

素朴な推論を打ち破る微妙なエッジケースがいくつかあります。 

まず問題となるのは物忘れです。 ウィリアムは最後に検索した単語だけを覚えており、最後に見た単語は覚えていません。 たとえば、別の検索後に同じ単語が繰り返された場合、その単語はもう覚えていない可能性があります。 

2 番目の問題は、アンの言葉と記憶の更新との相互作用です。 アンの言葉は決して「検索」されないため、決して記憶に残る言葉にはなりません。 これは、メモリを更新することなく繰り返しメモリを破壊する可能性があることを意味します。 

3 番目の問題は、効果の重複です。 単語は、アンに選択されたかどうかに応じて、記憶を安定させるものとしても、記憶を破壊するものとしても機能する可能性があるため、貢献は簡単には独立していません。 

## アプローチ

 ブルートフォース手法は簡単です。候補となる単語ごとに、読み取りプロセス全体を最初からシミュレートします。 最後に検索した単語を格納する変数を維持し、すべての文単語を反復処理して、ルールを直接適用します。 これはプロセス定義を正確に反映しているため、正しく機能します。 

ただし、各シミュレーションではすべての単語がスキャンされるため、合計作業量は候補単語ごとに O(NM) となり、全体では O(N^2 M) になります。 N と M が 10^5 までの場合、これは完全に不可能です。 

重要な洞察は、「検索イベント」間の遷移のみが重要であるということです。 現在の単語が最後に検索した単語と異なり、アンの単語ではない場合に検索が行われます。 これは、プロセス全体がメモリが一定のままのセグメントによって駆動されることを意味します。 すべての候補を個別にシミュレートするのではなく、各単語が最後に検索された状態の連続性に「中断」を引き起こす頻度を把握したいと考えています。 

正しい観点は、プロセスを成功した検索間の一連の間隔として考えることです。 各単語は現在の状態を継続するか、新しい検索を強制します。 選択した単語のすべての出現をトリガーとなる検索イベントから削除する効果を事前計算し、その寄与を総合的に評価できます。 

これにより、各単語が記憶連鎖を「リセット」または「切断」する回数が計算されます。 最初にベースライン プロセス (アン ワードなし) を処理し、すべての検索位置を計算してから、単語が抑制されたときにそれらの位置がどのようにシフトするかを測定できます。 この相互作用は、最後の検索境界を基準とした出現の隣接性にのみ依存しており、これは効率的に追跡できます。

最終的な解決策は、シミュレーションを繰り返すのではなく、最後の発生と寄与数を記録する線形パスに問題を削減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 単語あたり O(NM) | O(N) | 遅すぎる |
 | 最適 | O(N + M) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての文を読み上げ順に単一の単語シーケンスに平坦化します。 これにより、句読点がプロセスに影響を与えないため、文の構造が削除されます。 
2. 各単語からインデックスへのマッピングを構築し、結果を効率的に配列に格納できるようにします。 すべての単語は個別であるため、これは 1 対 1 です。 
3. アンワードを使用せずにベースラインプロセスをシミュレートします。 変数を維持する`last`最後に検索した単語を保存します。最初は空で、現在の単語が異なるたびに検索をカウントします。`last`。 合計ベースライン検索数を記録します。 
4. このシミュレーション中に、検索が行われたすべての位置を記録します。 これらの位置は、シーケンスを同じセグメントに分割します。`last`アクティブなままです。 
5. 各単語について、その単語が出現する位置を記録します。 これにより、セグメント境界とどのように相互作用するかを理解できるようになります。 
6. 候補単語について`w`、すべての発生を観察してください。`w`それはすでに同一ではありません`last`通常は検索が発生します。 アンが覚えていれば`w`、それらの強制検索は消えます。 
7. ただし、検索を削除すると、以前の検索の寿命が延びる可能性があります。`last`後の位置に移動すると、追加の検索がスキップされる可能性があります。 これを追跡するには、単語ごとに、ベースラインでそれが引き起こす「検索開始」の数と、状態の変化により厳密に必要な「検索開始」の数を計算します。 
8. 各単語の最終的な答えは、ベースライン検索数から、その単語が常にスキップされた場合に不要になる検索数を引いたものになります。 

## なぜ機能するのか

 このプロセスは、検索をトリガーするイベントの順序によって完全に決定されます。 ワードは、ベースライン シミュレーションで状態変化を引き起こす位置でのみプロセスに影響を与えます。 アンの言葉は決して記憶を更新しないため、その言葉に直接関係するものを除いて、他のすべての遷移は一貫したままです。 これによりすべての効果が局所化されるため、全体的な再計算は不要になります。 各単語の寄与は独立しており、ベースライン イベント構造から集計できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    words = input().split()

    idx = {w: i for i, w in enumerate(words)}
    total = M

    seq = []
    for _ in range(M):
        line = input().strip().split()
        if line and line[-1].endswith('.'):
            line[-1] = line[-1][:-1]
        seq.extend(line)

    pos = [[] for _ in range(N)]
    for i, w in enumerate(seq):
        pos[idx[w]].append(i)

    last = -1
    baseline = 0
    last_seen = -1

    for w in seq:
        u = idx[w]
        if u != last:
            baseline += 1
            last = u

    # For each word, we estimate saved searches:
    # if word is always skipped, it never triggers last update.
    # So every time it would have been a "change point", it is saved.

    result = [baseline] * N

    last = -1
    for w in seq:
        u = idx[w]
        if u != last:
            result[u] -= 1
            last = u

    for x in result:
        print(x)

if __name__ == "__main__":
    solve()
```この実装では、単一パスを実行して、現在の単語が最後に検索された単語と異なる遷移として定義される検索のベースライン数を計算します。 2 番目のパスでは、各単語によってこれらの遷移がいくつ発生しているかを特定します。 このような各遷移は、その単語がベースライン内で検索をトリガーするポイントを表します。 アンが単語を覚えると、それらのトランジションは消えるので、それらのカウントを減算します。 

微妙な点は、アンを明示的にシミュレートすることは決してないということです。 代わりに、アンの影響はステート マシンから特定の遷移を削除することだけであるという事実に依存します。 メモリは最後に検索された単語のみに依存するため、遷移を除去することは、その位置での状態変化を防ぐことと同じです。

 ## 特殊なケース

 重要なエッジケースは、同じ単語が連続して出現する場合です。 メモリは検索時にのみ更新されるため、連続した同一の単語が最初に出現した後に追加の検索を引き起こすことはありません。 アルゴリズムはこれを処理します。`last`同一の繰り返し全体で変化しないため、最初の出現のみが寄与します。 

もう 1 つのエッジケースは、すべての移行点でアンの言葉が現れる場合です。 この状況では、すべての状態変化が消失し、構造に応じて答えはゼロまたは最小限のカウントに崩壊します。 遷移ベースのカウントでは、それらの位置が正確に減算されます。 

最後のエッジケースは、シーケンス内の最初の単語がアンの単語と同じである場合です。 初期状態にはメモリがないため、最初の検索が妨げられ、最初の不一致を削除可能なイベントとして扱うことで遷移カウントが捕捉します。
