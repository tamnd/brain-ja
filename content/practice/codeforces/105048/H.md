 ## 解決策
 ## 問題の理解

 ある長さの「テキスト」を表す長い文字列が与えられます。$N$。 それに加えて、次のセットも提供されます。$M$独特の言葉。 すべての単語を組み合わせた合計の長さには制限があるため、単語の数は多くても、その組み合わせ構造はコンパクトです。 

それから私たちは尋ねられます$Q$質問。 各質問には間隔が与えられます$[l, r]$メイン文字列内で、その区間に完全に含まれる部分文字列が、指定された単語のいずれかに一致する数を数えなければなりません。 すべての出現は独立してカウントされるため、単語が異なる位置で複数回出現する場合、または異なる単語が重複する場合、すべての有効な一致が答えに寄与します。 

主な問題は、文字列とクエリの数の両方が大きいため、各クエリ間隔内の一致を最初から再計算すると時間がかかりすぎることです。 隠された構造は、ある位置で始まる部分文字列が辞書の単語の 1 つに一致するかどうか、そしてそれらの開始位置が各クエリ範囲内にいくつあるかだけを気にすることだけです。 

この制約は、ソリューションがテキストと辞書の合計長のサイズが線形または線形に近い必要があり、おそらくクエリごとに対数的なオーバーヘッドが発生することを意味します。 二次関数以上のもの$N$またはそれ以上$Q$すぐには無理です。 

単純な試みでは、すべてのクエリ間隔をスキャンし、すべての部分文字列の一致を試みます。 辞書の単語に限定しても、すべての位置をすべての単語に対してチェックすると、最悪のケースが発生します。$O(N \cdot M)$、それは限界をはるかに超えています。 

より微妙な失敗のケースは、重複した一致によって発生します。 たとえば、文字列が次の場合、`"AAAAA"`そして言葉には以下が含まれます`"A"`、`"AA"`、 そして`"AAA"`、その後、すべての位置で複数の一致が開始され、単純な部分文字列の列挙が誤って二重にカウントされるか、クエリごとにすべての可能性を拡張するのに時間がかかりすぎます。 

もう 1 つのエッジ ケースは、多くのクエリが重度に重複する場合です。 クエリごとに一致を個別に再計算すると、基になる一致が同一であっても、繰り返しの作業が爆発的に増加します。 

## アプローチ

 重要な観察は、すべての有効な答えが辞書一致の開始位置によって決定されるということです。 わかっていれば、すべてのインデックスについて$i$で始まる単語は何語ありますか$i$の場合、各クエリはその配列に対する単純な範囲の合計になります。 

したがって、問題はテキストの頻度配列を計算することになります。各位置について、そこから開始して一致する辞書の単語の数を数えます。 

強引な方法は、すべての単語をすべての位置で試してみることです。 これは次のことにつながります$O(N \cdot \text{word length})$単語ごとの比較の合計数が大きすぎます。 

共有プレフィックスを持つ多くのパターンの構造は、トライの構築を示唆しています。 すべての位置で各単語を個別にチェックするのではなく、トライを進めながらテキストを 1 回スキャンすることで、繰り返された接頭辞が自然にマージされます。 これにより、繰り返される文字比較が共有トランジションに変換されます。 

すべての単語のトライを構築し、そこで終わる単語の数で終端ノードをマークします。 次に、各位置からテキストをスキャンし、一致できなくなるまでトライ内を前進します。 終端ノードに到達すると、単語がそこで終了することが記録されます。これは、有効な部分文字列が最初の位置から始まることを意味します。 

合計の単語の長さは次のように制限されているため、$10^5$、すべてのワードにわたるトライ遷移の合計数も制限されており、不一致が発生するとすぐに、ある位置からの各スキャンが停止します。 これにより、合計作業量は、一致するトランジションの合計に比例するようになります。$N \cdot M$。 

配列を取得したら`cnt[i]`= 位置から始まる単語の数$i$、プレフィックスの合計を構築します。 各クエリ$[l, r]$単一の引き算になります。

 ## アルゴリズムのチュートリアル

 1. すべての単語からトライを作成します。 各ノードには、A から Z までの文字の遷移と、そのノードで終わる単語の数を示すカウンターが格納されます。 これにより、接頭辞を共有する複数の単語が作業を複製する代わりに構造を再利用できるようになります。 
2. 配列を初期化する`cnt`サイズの$N$ゼロ付き。 この配列には、メイン文字列の各位置で始まる辞書の単語の数が格納されます。 
3. 開始位置ごとに$i$メイン文字列で、次から始まるトライを 1 文字ずつ走査します。$s[i]$。 キャラクターが存在する場合、各ステップはトライを下に移動します。 そうしないと、一致が不可能になるため、すぐに停止します。 
4. 1 つ以上の単語の終わりをマークする trie ノードに到達するたびに、そのノードの終了カウントを`cnt[i]`。 これは、position で始まるすべての単語をキャプチャします。$i$これまでに確認されたプレフィックスと一致します。 
5. すべての開始位置に対してこのプロセスを繰り返します。 各ステップは有効な辞書プレフィックスに沿って進むか停止するため、トライ遷移の総数はすべての単語の合計長によって制限されます。 
6. プレフィックス合計配列を構築します`cnt`。 これにより、あらゆるクエリに回答できるようになります$[l, r]$計算により一定時間内に$\sum_{i=l}^{r} cnt[i]$。 
7. クエリごとに、プレフィックスの合計の差を出力します。 

### なぜ効果があるのか

 辞書の単語の有効な出現はすべて、開始位置という 1 つのペアに正確に対応します。$i$そしてそこから始まる一致する単語。 からのトライトラバース$i$各単語が一意の終端ノード パスに対応するため、これらの単語が重複することなく正確に列挙されます。 プレフィックス合計ステップはカウントを変更せず、間隔にわたる寄与を集計するだけです。 各一致は 1 回だけカウントされるため、`cnt[i]`、各クエリは内部の位置を正確に合計します。$[l, r]$、結果は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "end")
    def __init__(self):
        self.next = {}
        self.end = 0

def solve():
    N, M, Q = map(int, input().split())
    s = input().strip()

    root = Node()

    # build trie
    for _ in range(M):
        w = input().strip()
        cur = root
        for ch in w:
            if ch not in cur.next:
                cur.next[ch] = Node()
            cur = cur.next[ch]
        cur.end += 1

    cnt = [0] * N

    # scan from every position
    for i in range(N):
        cur = root
        j = i
        while j < N:
            ch = s[j]
            if ch not in cur.next:
                break
            cur = cur.next[ch]
            if cur.end:
                cnt[i] += cur.end
            j += 1

    # prefix sums
    pref = [0] * (N + 1)
    for i in range(N):
        pref[i + 1] = pref[i] + cnt[i]

    out = []
    for _ in range(Q):
        l, r = map(int, input().split())
        out.append(str(pref[r] - pref[l - 1]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```トライ構造により、共有プレフィックスが繰り返し再計算されなくなります。 各ノードの`end`value は、その時点で終了する単語の数を集計するため、辞書内に重複が存在する場合は自然に処理されます。 スキャン ループは不一致が発生するとすぐに停止し、不必要なトラバースを防ぎます。 

プレフィックス合計配列はインデックスを 1 だけシフトするため、範囲クエリはオフバイ 1 の複雑さのないクリーンな減算になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての単語が 1 文字である場合です。 その状況では、文字列内のすべての位置が複数の単語と一致する可能性があり、トライは単一レベルの分岐構造に縮退します。 各位置が独立して寄与するため、アルゴリズムは依然として正しく動作します。`cnt[i]`、およびプレフィックス合計は、相互作用なしにこれらの寄与を蓄積します。 

もう 1 つのケースは、単語が長い接頭辞を共有しているものの、後で分岐する場合です。`"ABCDE", "ABCDF", "ABCDG"`。 トライにより共有プレフィックスが保証されます`"ABCD"`開始位置ごとに 1 回横断され、分岐は最終ステップでのみ発生します。 複数の単語が同じ深さで一致する場合でも、`end`ターミナル ノードのカウンターにより、個別のスキャンを行わなくても、すべてが正しくカウントされることが保証されます。
