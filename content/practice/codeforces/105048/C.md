 ## 解決策
 ## 問題の理解

 私たちはスタックのグリッドを維持しています。 内の各セル$N \times N$board は文字の垂直スタックを格納します。更新ごとに、文字をスタックにプッシュするか、最上位の文字をポップするか、現在のスタックに「支配的な」文字があるかどうかを尋ねます。 

クエリされた文字がそのスタック内の要素の半分以上に厳密に出現する場合、そのスタックはクエリの下で美しいとみなされます。 

したがって、各操作は単一のセルにローカライズされますが、重要な問題はシーケンスが動的であることです。プッシュとポップは時間の経過とともにスタックの高さを変更し、クエリはそのスタック内の現在の文字のマルチセットを反映する必要があります。 

制約は実際の信号です。 グリッドが小さい（$N \le 100$)、したがって、独立したスタックは最大 10,000 個になります。 ただし、操作の数は次のとおりです。$2 \cdot 10^5$。 単一のスタックは操作に応じて直線的に増加する可能性があるため、これによりスタックのクエリごとのスキャンが除外されます。 最悪の場合、1 つのセルに繰り返しプッシュすると、サイズのスタックが作成されます。$2 \cdot 10^5$、クエリごとにスキャンすると、すぐに時間制限を超えてしまいます。 

すべてのクエリのスタック内の頻度をカウントする単純なアプローチではコストがかかります$O(k)$クエリごとに、ここで$k$はスタックの高さであり、$O(Q^2)$最悪の場合。 

微妙なエッジ ケースは、空のスタックの削除から発生します。 タッチされていないセルに対する削除操作は何も行いませんが、スタックが存在することを前提とした不注意な実装では、エラーが発生したり、誤ってカウントが 0 未満に減算される可能性があります。 

もう 1 つの注意が必要なシナリオは、同じセル上で操作をインターリーブすることです。 

入力:```
0 a 0 0
0 b 0 0
2 a 0 0
1 0 0
2 a 0 0
```正しい動作には、プッシュ後、正確な順序を追跡する必要があります。`a`、 それから`b`、スタックは`[a, b]`, したがって、どちらの文字も多数派ではありません。 ポップ後のスタックは`[a]`、 それで`a`支配的になります。 

## アプローチ

 ブルート フォースの解決策は簡単です。セルごとに、そのスタックを表すリストを維持します。 プッシュは追加し、ポップは最後の要素が存在する場合は削除し、クエリはスタック全体でターゲット文字の出現をカウントし、それがスタック サイズの半分を超えているかどうかを確認します。 

これは、定義を直接シミュレートするため、正しいです。 問題はパフォーマンスです。 各クエリはスタック サイズまでスキャンする必要があり、敵対的なケースではスタック サイズが最大で大きくなります。$O(Q)$。 まで$2 \cdot 10^5$操作すると、これは次のようになります$O(Q^2)$が遅すぎます。 

重要な観察は、すべての文字についての完全な頻度情報は必要ではなく、その時点でクエリされた候補文字についてのみ必要であるということです。 ただし、スタックから任意の文字を削除すると時間の経過とともにバランスが変化するため、削除時に多数派を動的に検証したい場合は、カウントを維持するだけでは不十分です。 

現在のスタック内の文字の頻度マップをセルごとに維持すると、構造はより単純になります。 次に、プッシュごとにカウントが 1 つ増加し、ポップごとに削除された先頭文字のカウントが減少し、現在のスタック サイズも維持されます。 これにより、各操作が$O(1)$平均すると、各クエリも$O(1)$: かどうかだけをチェックします。`freq[l] > size/2`。 

唯一欠けている部分は、ポップ中にどの文字をデクリメントするかを知ることです。これには、カウントだけでなく実際のスタックの内容を保存する必要があります。 

これにより、最適な設計が得られます。各セルには、スタック (順序用) と周波数辞書 (カウント用) の両方が格納されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとのスキャン スタック) |$O(Q^2)$|$O(Q)$| 遅すぎる |
 | セルごとのスタック + 周波数マップ |$O(Q)$|$O(N^2 + Q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズのグリッドを初期化します。$N \times N$ここで、各セルには空のスタックと空の周波数マップが含まれています。 

これにより、座標ごとに操作を分離できるため、グローバルな再計算が不要になります。 
2. でのペイント操作の場合$(x, y)$、そのセルのスタックに文字をプッシュし、その頻度カウンターをインクリメントします。 

スタックにより、後でこれを正しく元に戻すことができ、カウンタは集計情報を一定時間で保持します。 
3. での削除操作の場合$(x, y)$、スタックが空でないかどうかを確認します。 空の場合は何もしません。 

空でない場合は、最上位の要素をポップし、その頻度を減らします。 これにより、順序とカウントの一貫性が保証されます。 
4. お問い合わせについては、$(x, y)$手紙付き$l$、現在のスタック サイズを計算します。 ゼロの場合は「no」を出力します。 

それ以外の場合は、`frequency[l] * 2 > size`。 これは、浮動小数点演算を行わずに厳密多数決を直接エンコードします。 

### なぜ効果があるのか

 あらゆる瞬間において、各セルのスタックは格納されたリストによって正確に表現され、周波数マップはそのスタック内の文字のマルチセットと正確に一致します。 プッシュおよびポップ操作では、挿入または削除のたびに両方の構造が一貫して更新されるため、この不変状態が維持されます。 したがって、クエリに答えるとき、頻度マップは現在のスタック内のクエリされた文字の正確な数を提供し、それをスタック サイズの半分と比較することで、それが厳密な多数を形成するかどうかを正確に判断します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    
    grid = [[[] for _ in range(N)] for _ in range(N)]
    freq = [[dict() for _ in range(N)] for _ in range(N)]
    size = [[0 for _ in range(N)] for _ in range(N)]
    
    out = []
    
    for _ in range(Q):
        parts = input().split()
        s = int(parts[0])
        
        if s == 0:
            l = parts[1]
            x = int(parts[2])
            y = int(parts[3])
            
            grid[x][y].append(l)
            size[x][y] += 1
            freq[x][y][l] = freq[x][y].get(l, 0) + 1
        
        elif s == 1:
            x = int(parts[1])
            y = int(parts[2])
            
            if size[x][y] == 0:
                continue
            
            ch = grid[x][y].pop()
            size[x][y] -= 1
            freq[x][y][ch] -= 1
            if freq[x][y][ch] == 0:
                del freq[x][y][ch]
        
        else:
            l = parts[1]
            x = int(parts[2])
            y = int(parts[3])
            
            if size[x][y] == 0:
                out.append("no")
            else:
                if freq[x][y].get(l, 0) * 2 > size[x][y]:
                    out.append("yes")
                else:
                    out.append("no")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、セルごとのスタックを維持して順序を維持し、正しいポップ動作をサポートします。 頻度ディクショナリはスタックの変更と同期して更新され、クエリ中に一定時間の多数決チェックが保証されます。 別個の`size`array は長さを繰り返し再計算することを避けます。 

実装の微妙な詳細の 1 つは、辞書エントリの数が 0 になったときに辞書エントリを削除することです。 これは正確さを保つために必須ではありませんが、メモリの制限を維持し、操作中に誤解を招くキーを回避します。`.get()`小切手。

 ## 特殊なケース

 重要なエッジ ケースは、空のスタックをクエリすることです。 実装では、周波数マップにアクセスする前にサイズを明示的にチェックします。 このガードがないと、単純な除算や検索が欠落しているキーを誤ってゼロとして扱い、処理を続行する可能性があります。これは、サイズが慎重に扱われた場合にのみ正しいことになります。 

別のケースとしては、空のスタック上でポップ操作が繰り返される場合があります。 操作は no-op でなければならないため、実装ではチェックすることでアンダーフローを回避します。`size[x][y] == 0`弾ける前に。 これにより、スタックと周波数マップが発散することがなくなります。 

最後の微妙なケースは、文字がスタックから完全に消える場合です。 カウントが 0 に達したときに辞書エントリを削除すると、キーの存在が肯定的なことを意味すると仮定する将来のロジックで、古いキーが誤解を招くことを防ぎます。
