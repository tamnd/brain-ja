 ## 解決策
 ## 問題の理解

 数直線上の一連の点が与えられ、各点は時間ゼロにおけるジュリエットの可能な初期位置を表します。 ロミオは後にそのことを知ります`d`、ジュリエットは既知の間隔内のどこかに横たわっている必要があります`[A, B]`。 時間の間`0`そして時間`d`、ジュリエットはラインに沿って自由に移動できますが、速度には制限があります。1 分あたり最大 1 単位の距離しか移動できないため、`d`数分以内に彼女はどこにでも行き着くことができる`d`彼女が始めたところから。 

課題は、与えられた候補者のどの出発点が内部の何らかのポジションに発展する可能性があるかを判断することです。`[A, B]`まさにその後`d`そのような動きの数分間。 出力は、それらの有効な開始点のインデックスのリストです。 

制約により、最大で次のことが許可されます。`10^5`候補点と座標まで`10^9`、 と`d`までも`10^9`。 これにより、動きをシミュレートしたり、到達可能性を分ごとにチェックしたりするアプローチは即座に除外されます。 どのようなソリューションでも、各ポイントを一定時間のチェックに減らす必要があります。`O(N)`または`O(N log N)`解は快適に通過すると予想されますが、二次関数は遅すぎるでしょう。 

境界推論から微妙な問題が生じます。 よくある間違いは、到達可能性を間隔ではなく単一の点として扱うことです。 もう 1 つは、移動の一方向のみをチェックすることです。たとえば、`P_i`到達できる`A`または`B`到達可能な範囲の重複をチェックするのではなく、個別に確認します。 これらの間違いは、ジュリエットが区間の正しい部分に向かって単純に移動する有効な開始点を拒否することにつながります。 

たとえば、次のように仮定します。`d = 2`、`P_i = 5`、 そして`[A, B] = [6, 7]`。 ジュリエットはから移動できます`5`に`7`2 つのステップで行われるため、この開始点は有効です。 「彼女は到達できるか」のような素朴なチェック`A`正確に」と誤って拒否してしまいます。 

## アプローチ

 ブルートフォース解釈は、各開始位置からの動きをシミュレートします。 ある点から`x`、 後`d`分 ジュリエットは間隔のどこにいても構いません`[x - d, x + d]`。 妥当性をチェックするには、から到達可能なすべての位置を列挙することができます。`x`何かが存在するかどうかを確認します`[A, B]`。 各間隔には次の要素が含まれるため、これはすぐに実行不可能になります。`O(d)`整数の位置、および`d`と同じ大きさにすることができます`10^9`、シミュレーションが不可能になります。 

重要な観察は、移動によって各開始点が連続した区間に変換され、2 つの区間が交差するかどうかだけを知る必要があるということです。 すべての可能な位置を追跡する代わりに、到達可能な間隔を計算します。`[x - d, x + d]`と重なっているかどうかを確認します`[A, B]`。 Interval overlap reduces to a pair of linear inequalities, which simplifies further into a direct constraint on`x`。 

間隔が交差するのは、両方の中に位置が存在する場合に限ります。 これはまさに次のようなときに起こります。`x + d >= A`そして`x - d <= B`。 並べ替えると`x >= A - d`そして`x <= B + d`。 したがって、各候補点は一定時間内に独立してチェックできます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N・d) | お(1) | 遅すぎる |
 | 間隔の短縮 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 到達可能性の問題を元の点の単純な範囲フィルターに変換します。 

1. まだ到達できる最小の開始位置を計算します。`[A, B]`後`d`分、つまり`A - d`。 これは、右方向への最大の動きを逆転させることによって得られます。 
2. まだ到達できる最大の開始位置を計算します。`[A, B]`、つまり`B + d`、最大の左方向への動きを反転することから来ます。 
3. すべての点を反復処理します。`P[i]`。 
4. 各点について、その点が区間内にあるかどうかを確認します。`[A - d, B + d]`。 存在する場合は、回答にそのインデックスを含めてください。 
5. 収集されたすべてのインデックスを昇順に出力します。 

動きを順方向にシミュレートするのではなく間隔を逆にする理由は、すべての開始位置が対称の到達可能なセグメントにマップされるためです。 逆方向に作業すると、動的な到達可能性の問題が静的なフィルタリング条件に変換されます。 

### なぜ効果があるのか

 時間ゼロ、開始位置`x`全区間に拡張されます`[x - d, x + d]`時に`d`。 ジュリエットは、この間隔が交差する場合にのみ有効です`[A, B]`。 区間の交差は、どちらの区間ももう一方の区間の完全に左または完全に右にない条件と同等です。 これらの重複しない条件を変換すると、境界が生成されます。`x >= A - d`そして`x <= B + d`。 したがって、すべての有効な開始点はこのフィルターによって 1 回だけキャプチャされ、無効な点はフィルターを満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B, d = map(int, input().split())
    P = list(map(int, input().split()))

    left = A - d
    right = B + d

    res = []
    for i, x in enumerate(P):
        if left <= x <= right:
            res.append(str(i))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```実装では、導出された間隔条件を直接エンコードします。 唯一の微妙な点は、インデックスが入力順序から保持されるため、次のように列挙します。`i`ゼロから始まり、それらのインデックスを文字列として出力します。 

拡張された方法でポイントごとの到達可能性を再計算しないように注意する必要があります。 ソリューション全体は、各ポイントを事前計算された間隔との単一の比較に減らすことに依存しています。

| 私 | P[i] | チェック (-5 ≤ x ≤ 5) | 結果 |

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`d = 0`。 この状況では、ジュリエットはまったく動くことができないため、有効な開始点はすでに内部にあるものだけです。`[A, B]`。 間隔は次のようになるため、アルゴリズムはこれを自然に処理します。`[A, B]`、したがって、条件は直接のメンバーシップテストに減ります。 

もう一つのケースは次のような場合です。`A - d`マイナスになる。 入力では座標をゼロにすることはできますが、負にすることはできないため、これは単に有効な領域を可能な点の領域を超えて左に拡張します。 負の境界があっても比較は有効なままであり、特別なクランプは必要ないため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは次のような場合です。`[A, B]`は非常に大きく、ほぼすべての可能な位置と重複します。 その場合、`A - d`そして`B + d`どちらの方向でも入力限界を超える可能性がありますが、区間チェックは絶対的な範囲制限ではなく不等式関係にのみ依存するため、やはり正しいままです。
