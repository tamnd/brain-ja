 ## 解決策
 ## 問題の理解

 多くの決定にわたって乗算的および加算的に相互作用する 2 つの独立したシーケンスが与えられます。 各ベーカリーにはポジション値があります$x_i$。 各メールボックスには位置があります$y_j$および関連コスト$k_j$。 シラノはパン屋ごとに、訪問するメールボックスを 1 つだけ選択します。 ベーカリーのペアリングにかかる​​費用$i$メールボックス付き$j$旅費の 2 つの部分の合計です。$x_i \cdot y_j$、固定メールボックス料金$k_j$。 目標は、すべてのベーカリーの総コストを最小限に抑えることです。 

構造は、すべての$x_i$は、正確に 1 つのメールボックスに一致する必要があり、選択のコストは、選択したメールボックスと現在のベーカリー値にのみ依存します。 

制約$N, M \le 10^5$および最大値$10^9$すぐに除外します$O(NM)$ペアリング戦略。 すべてのペアにわたる単一の 2 次パスでも大きすぎます。 許容可能な解決策では、すべてのペアを明示的にチェックすることを避け、代わりに代数構造を利用する必要があります。 

複数のメールボックスに同一のパラメーターまたは優勢なパラメーターがある場合、微妙なエッジ ケースが発生します。 たとえば、1 つのメールボックスに、より大きな両方のメールボックスがある場合、$y$そしてさらに大きい$k$他のものよりも最適であることはありませんが、単純なアルゴリズムではそれでも考慮される可能性があります。 もう 1 つの例外的なケースは次のような場合です。$x_i = 0$、乗算コストを完全に削除し、$k_j$そのパン屋に関連しています。 同様に、$y_j = 0$～への依存関係を削除します$x_i$、そのようなメールボックスは、パン屋のパン屋に関係なく、潜在的に世界的に最適になります。$x_i$。 

## アプローチ

 直接的なアプローチは、ベーカリーごとに計算することです。$x_i$、すべてのメールボックスの最小値:$$\min_j (x_i \cdot y_j + k_j)$$これらの値を合計します。 これは正しいですがコストがかかります$O(NM)$、それぞれの$N$パン屋はすべてをスキャンします$M$メールボックス。 と$10^5$両方の次元で、これには次のことが必要になります$10^{10}$実現可能な限界をはるかに超えた評価です。 

重要な観察は、式が次の点で線形であることです。$x_i$。 固定郵便ポストの場合$j$、の関数としてのコスト$x$は直線です:$$f_j(x) = y_j \cdot x + k_j$$したがって、問題は次のようになります。$x_i$の中で最小値を評価します。$M$点の線$x_i$。 

これは古典的な凸包トリック シナリオですが、ここで重要な単純化は、$x_i$値は独立したクエリであり、並べ替え後に処理できます。 両方を並べ替えます$x_i$そして傾きによるライン$y_j$、その後、ラインの下部ハルを維持します。 クエリは単調であるため、ハルに対するポインタまたは二分探索を使用してクエリを効率的に評価できます。 

幾何学的解釈では、各メールボックスがラインを定義し、各ベーカリーが特定の x 座標での最低ラインを要求します。 ソートにより、関連する候補行を維持し、決して最適ではない候補行を破棄するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NM)$|$O(1)$| 遅すぎる |
 | 凸包トリック (ソートされたクエリ) |$O((N+M)\log M)$または$O(N+M)$|$O(M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、一連の線形関数を効率的に評価することに変換します。 

## アルゴリズムのチュートリアル

 1.各メールボックスを解釈する$j$線として$f_j(x) = y_j x + k_j$。 目標は、それぞれを見つけることです$x_i$、その時点でのすべての行の最小値。 この再構成により、問題は最小行クエリの繰り返しに変わります。 
2. パン屋を並べ替える$x_i$。 ソートにより行を昇順にクエリできるため、ソートは不可欠です。$x$これにより、候補構造の増分メンテナンスが可能になります。 
3. メールボックスを傾斜順に並べ替える$y_j$。 これにより、傾斜の増加順に下部凸包を構築するためのセットが準備されます。 順序付けにより、新しいラインを追加するときに、交差部分を以前に保存したラインと比較することで、それが有用かどうかを判断できるようになります。 
4. 線の凸包を構築します。 新しい行はそれぞれ、構造内の最後の 2 行と比較されます。 新しい行によって前の行が今後のすべてのクエリにとって無関係になる場合は、その行を削除します。 これにより、特定の範囲に最適な行のみを保持することが保証されます。$x$。 
5. クエリを処理している間、ハルの上にポインタを維持します。$x_i$。 各ベーカリー値について、次の行の値が小さい限りポインタを前方に移動します。 これが機能するのは、最適なライン インデックスが単調であるためです。$x$。 
6. それぞれについて$x_i$、現在のポインターで最良の行を評価し、その結果を答えのモジュロに追加します。$10^9+7$。 

### なぜ効果があるのか

 各メールボックスは線形関数を定義し、線形関数以上の最小値は、下から見ると区分的線形凹構造を形成します。 傾きによって並べ替えると、ライン間の交点が一貫して順序付けされます。 クエリ点の単調性により、ラインが最適でなくなったら、より大きなラインに対して再び最適になることは決してないことが保証されます。$x$。 これにより後戻りが防止され、船体の直線的な横断が可能になります。 このアルゴリズムは、将来のクエリに最適な行を決して破棄しないため、すべてのクエリで真のグローバル最小値が確認されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def bad(l1, l2, l3):
    # check if l2 is unnecessary between l1 and l3
    # using cross multiplication to avoid floating point
    (m1, b1) = l1
    (m2, b2) = l2
    (m3, b3) = l3
    return (b3 - b1) * (m1 - m2) <= (b2 - b1) * (m1 - m3)

def solve():
    N, M = map(int, input().split())
    xs = [int(input()) for _ in range(N)]
    lines = []
    for _ in range(M):
        y, k = map(int, input().split())
        lines.append((y, k))

    xs.sort()
    lines.sort()

    hull = []
    for m, b in lines:
        hull.append((m, b))
        while len(hull) >= 3 and bad(hull[-3], hull[-2], hull[-1]):
            hull.pop(-2)

    def eval_line(line, x):
        return line[0] * x + line[1]

    ans = 0
    j = 0

    for x in xs:
        if j >= len(hull):
            j = len(hull) - 1
        while j + 1 < len(hull) and eval_line(hull[j + 1], x) <= eval_line(hull[j], x):
            j += 1
        ans = (ans + eval_line(hull[j], x)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各メールボックスを傾きで定義された線形関数に圧縮します。$y_j$そしてインターセプト$k_j$。 これらの行を並べ替えて、凸包を段階的に構築できるようにします。 の`bad`関数は、交差乗算を使用して交点を比較することにより、決して最適ではない中間ラインを削除します。 

クエリ処理中に、ハル上のポインターが前方のみに移動するようにベーカリーが並べ替えられます。 それぞれ$x_i$償却定数時間で最適なラインを選択します。 個々の評価はモジュラス範囲を超える可能性があるため、モジュロ演算は累積時にのみ適用されます。 

よくある微妙な点は、ハル チェックにおける不等号の方向です。 使用する`<=`同一直線上または支配的なラインが一貫して削除され、重複した候補による誤ったポインターの移動が防止されます。

 ## 特殊なケース

 いつ$x_i = 0$、どこのパン屋も坂を無視して見るだけです。$k_j$。 船体は効果的に最小インターセプトラインを選択するように縮小します。 アルゴリズムはこれを自然に処理します。$m \cdot 0 + b$常に戻ってきます$b$したがって、ポインタは最小の切片に収束します。 

メールボックスに$y_j = 0$、平らな線になります。 最小限のものもあれば$k_j$、それはすべての他の行を支配します。$x$。 船体の建設中に、より高い切片のフラット ラインは交差チェックによって削除され、最適な一定のラインのみが残り、正しいグローバル ドミナンスが保証されます。 

複数の郵便ポストが同じ傾斜を共有している場合、切片が最小の郵便ポストだけが船体の建設に耐えられます。 の`bad`関数は冗長な線を削除し、ポインタが振動したり、等しい傾きの候補間で誤って切り替わったりしないようにします。
