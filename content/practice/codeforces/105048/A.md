 ## 解決策
 ## 問題の理解

 スペースを含む大文字と小文字の英字が含まれる 1 行のテキストが与えられます。 タスクは、大文字を無視した場合に、連続する文字「be」がこのテキストのどこかに現れるかどうかを判断することです。 

重要な変換は、大文字と小文字が区別されないことです。そのため、検索する前に、すべての文字を小文字であるかのように扱う必要があります。 スペースは入力内の単なる通常の文字ですが、特に「be」を形成する 2 つの連続する文字を探しているため、ターゲットの部分文字列の一部にすることはできません。 

入力サイズは最大 1000 文字ですが、これは競技プログラミングの標準からすると非常に小さいです。 これにより、リニア スキャン以外の効率に関する懸念が即座に排除されます。 考えられるすべての部分文字列をチェックする単純なアプローチでも、制限内であればすでに十分です。 

主な微妙な点は、大文字と小文字の正規化を処理し、連続する文字のみを考慮するようにすることです。 よくある間違いは、大文字と小文字を変換せずに元の文字列で「be」を検索することです。「BE」や「Be」などの入力では失敗します。 もう 1 つの間違いは、隣接ロジックを壊す方法でスペースを誤ってスキップすることです。 たとえば、元の文字列では文字が連続していないため、「b e」は一致しません。 

エッジ ケースには、「b e」など、文字が互いに近くにあるにもかかわらずパターンを形成する文字がない文字列や、「bE」または「BE」など、一致が異なるケースにまたがる文字列が含まれます。 「b」や「e」などの 1 文字の文字列も、「no」を正しく返す必要があります。 

## アプローチ

 簡単なアプローチは、文字列を均一な大文字と小文字に正規化し、それを左から右にスキャンして、隣接する文字のペアをすべてチェックすることです。 いずれかのペアが「be」に等しい場合、答えは肯定的であるとすぐに結論付けます。 

ブルート フォースの亜種では、長さ 2 のすべての部分文字列を明示的にテストし、小文字に変換した後に「be」と比較します。 長さ n の文字列の場合、これは n - 1 個の部分文字列をそれぞれ一定時間でチェックし、線形の複雑さを与えます。 すべての部分文字列を生成するようなさらに単純なメソッドは不要ですが、制約が与えられていれば合格します。 

重要な観察は、問題が固定長 2 の単純なパターン検索に帰着するということです。パターンのサイズが一定であるため、KMP のような高度な文字列アルゴリズムは必要ありません。 これにより、タスクが文字列上の 1 つのパスに折りたたまれます。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を 1 行として読み取ります。 この文字列にはスペースが含まれる場合がありますが、スペースは削除されません。文字比較を通じて間接的に照合する場合にのみ無視されます。 
2. 文字列全体を小文字に変換します。 これにより、比較が均一になり、後で大文字と小文字に基づいた分岐が排除されます。 
3. 文字列をインデックス 0 から n - 2 まで繰り返します。常に連続する文字のペアをチェックしているため、n - 2 で停止します。 
4. 各位置 i について、s[i] が 'b' であり、s[i + 1] が 'e' であるかどうかを確認します。 これは、i で始まる部分文字列がターゲット パターンと一致するかどうかを直接テストします。 
5. そのようなペアが見つかった場合は、すぐに「yes」を出力してプログラムを終了します。 
6. 一致するものが見つからずにループが終了した場合は、「no」を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、元の文字列内に出現する部分文字列「be」はすべて、インデックス ペア (i, i + 1) 内の 2 つの連続する文字として出現する必要があるという不変式に依存しています。 小文字にすることで文字間の等価関係が維持されるため、元の文字列内の有効な一致は、変換された文字列内の一致と正確に一致します。 すべての隣接するペアをチェックするため、有効な出現を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().rstrip("\n")
s = s.lower()

found = False
for i in range(len(s) - 1):
    if s[i] == 'b' and s[i + 1] == 'e':
        found = True
        break

print("YES" if found else "NO")
```このソリューションは入力を効率的に読み取り、次を使用して直ちに正規化します。`.lower()`。 アクセス時に範囲外のインデックスが作成されないように、ループは慎重に制限されています。`i + 1`。 早期終了により、パターンが見つかったらすぐに停止しますが、早期終了がなくても複雑さは線形のままです。 

実装でよくある落とし穴は、文字列内にスペースが残っていることを忘れることです。 このコードは、スペースが「b」または「e」のいずれとも一致しないため、これを正しく処理します。そのため、特別な処理を必要とせずに、自然に比較に失敗します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = sys.stdin.readline().rstrip("\n").lower()
    for i in range(len(s) - 1):
        if s[i] == 'b' and s[i + 1] == 'e':
            return "YES"
    return "NO"

assert run("b e\n") == "NO"

 ## 特殊なケース

 重要なエッジ ケースは、部分文字列が大文字と小文字が混在している場合です。 「bE」のような入力の場合、アルゴリズムはまずそれを「be」に変換し、次に隣接するチェックがインデックス 0 でそれを検出し、すぐに YES を返します。 これにより、正規化によってすべてのケースのバリエーションが正しく統一されることが確認されます。 

もう 1 つの特殊なケースは、パターンを形成する文字間にスペースが存在することです。 たとえば、「be e」は正規化すると「be e」になります。 このループは隣接するインデックスのみをチェックするため、スペースをまたいで文字が結合されることはなく、正しく NO を返します。 

最後のエッジケースは、「b」や「e」などの非常に短い文字列です。 小文字化後は、長さから 1 を引いた値が 0 または負であるため、ループ範囲は空になり、反復は発生せず、関数は正しく NO を返します。
