 ## 解決策
 ## 問題の理解

 ノード 1 がルートとして固定されたルート付きツリーが与えられます。 2 人のプレイヤーが 2 つの異なるノード (ノード A のアリスとノード B のボブ) から開始します。彼らは交互に移動し、アリスが最初に開始します。 各移動は、プレイヤーをコストなしで任意の祖先まで上に移動させるか、プレイヤーを現在のサブツリー内のノードに「下にジャンプ」させますが、そのノードの重みを支払います。 このようなジャンプの後、プレーヤーは選択したノードに移動します。 

各プレイヤーは、独自のマークされたノードの独立したセットも維持しますが、コストが重要となるのはマーキングの決定のみであり、対戦相手のブロックについては重要ではありません。 移動後に両方のプレイヤーが同じノードに着地した場合、ゲームは直ちに終了し、移動者が勝ちます。 また、自分の番に正当な動きがなかった場合、プレイヤーは即座に負けます。 

出力では 2 つのことが求められます。最適なプレイの下で誰が勝利を強制できるか、もう 1 つは勝利プレイヤーが勝利を保証しながら自身の下向きマーク操作に費やさなければならない最小総コストです。 

この制約では最大 2000 ノードが許可されるため、ノード上での三次挙動を伴うソリューションは遅すぎます。 二次または二次に近い解法は、特にゲームをツリー DP または構成上の最短パス スタイルの計算に削減できる場合には、もっともらしいです。 

一方のプレイヤーがすぐに上に移動して、共通の祖先でもう一方のプレイヤーと出会うことができる場合、微妙なエッジケースが発生します。 このような場合、マーキングは必要なく、コストは正確にゼロでなければなりません。 もう 1 つの重要なケースは、あるプレイヤーが上向きの動きを持たず、コストのかかる下向きのジャンプを使用せざるを得なくなった場合です。 単純な貪欲な選択は、対戦相手が対称的に反応し、ミーティングポイントを上方に移動させる可能性があるため、失敗することがよくあります。 

## アプローチ

 直接的な総当たり解釈では、各ゲーム状態を現在のプレーヤーとのポジションのペアとして扱います。 状態から、すべての祖先ジャンプとすべての有効なサブツリー ジャンプを列挙し、ゲームを再帰的にシミュレートし、勝敗の結果を選択します。 ルールは決定論的で完全に状態ベースであるため、これは正しいですが、状態空間は膨大です。 O(n^2) 個の位置ペアがあり、各状態からプレーヤーは O(n) 個の先祖と O(n) 個のサブツリー ノードを考慮することができ、最悪の場合は O(n^4) 個の遷移が発生します。 メモ化しても、これは依然として大きすぎます。 

重要な観察は、上向きの移動は無料であり、プレイヤーを祖先チェーンに再配置するだけであり、コストは下向きの選択をコミットする場合にのみ発生するということです。 これは、唯一の意味のある構造が各ノードからルートまでのパスと、これらのパスがどのように交差するかであることを強く示唆しています。 ゲームは基本的に、どのプレイヤーがツリー内のノードで会議を強制できるか、またサブツリー ジャンプを介して対戦相手をその会議領域に「引き込む」のに最適なコストを決定することに要約されます。 

最下位共通祖先と到達可能な上向きクロージャの観点からゲームを再解釈できます。 任意のシーケンスをシミュレートする代わりに、ターンのパリティと下方向へのジャンプが必要かどうかを考慮して、アリスとボブが最初にゲームをそのノードに強制できるかどうかを、考えられる会議ノードごとに分析します。 コストは、プレイヤーがノードの重みを支払い、そのサブツリーに再配置することによってゲームを「固定」することを選択するノード上の最短パス スタイルの最小化になります。 

これにより、各ノードが潜在的な会議アンカーを表すツリー上の動的プログラミングの定式化が行われ、プレーヤーが自由に上に移動できるか、それともサブツリーに入るために料金を支払わなければならないかをトランジションがキャプチャします。 最終的な勝者は、どちらのプレイヤーが交互のターンで最初に有利なアンカーに到達できるかによって決まります。コストは、勝者が使用した強制下向きコミットメントに沿った重みの最小合計です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ステート シミュレーション | O(n^4) | O(n^2) | 遅すぎる |
 | ミーティングアンカー上のツリー DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、親ポインターを事前計算して、前処理後にステップごとに O(1) ずつ上に移動できるようにします。 また、ノードが別のノードのサブツリー内にあるかどうかをテストできるように、サブツリー構造も計算します。 

私たちは、誰のターンで、プレイヤーが現在どこに立っているのかを表すノードのペアに対して DP を定義しますが、それを直接拡張するのではなく、上向きの動きを圧縮します。プレイヤーが上向きに移動できるときはいつでも、最終的には将来のインタラクションに最適な祖先に移動すると想定します。 これにより、各状態を、プレイヤーの 1 人が強制しようとする「会議アンカー」ノードの選択に減らすことができます。 

各ノード x について、それをゲームが強制的に収束する可能性がある潜在的なアンカーとみなします。 コストを無視して、A から開始するアリスが交互のターンで B から開始するボブよりも先に x に到達できるかどうかを計算します。 これは本質的に、上向きの移動がフリー エッジであり、下向きのジャンプが制御された拡張であるツリー上の到達可能性の比較です。 各移動がアクティブ プレイヤーを反転させるため、モデルのターン順序と距離の同等性を追跡します。 

次に、これをコストで拡張します。アリスが、ある時点で x のサブツリーに入るために下向きジャンプを実行する必要がある場合は、w[x] を追加します。 各プレイヤーは独立してノードをマークするため、勝ったプレイヤーの下向きの選択のみが総コストに寄与します。 

最後に、到達可能性の比較でどちらが優位に立つことができるかに応じて、アリスまたはボブに強制的な勝利をもたらすアンカー x を選択します。 すべての勝利アンカーの中で、累積コストが最小のものを選択します。 

出力の勝者は、最適なプレイの下で強制できるアンカーを少なくとも 1 つ持っているプレーヤーであり、コストはそれらのアンカーの中で最小のコストです。 

### なぜ効果があるのか

 上向きの移動により、祖先関係を超えてルート パスに沿った正確な位置を追跡する必要がなくなるため、ゲームの構造は崩壊します。 意味のあるすべての決定は、祖先に向かって移動するか、コストを支払ってサブツリーにコミットするかのいずれかです。 これにより、ゲームは、誰が最初に選択したサブツリー ルートにインタラクションを強制できるかというコンテストに変わります。 各サブツリーのコミットメントは独立しており、位置の優位性の点で不可逆的であるため、最適な再生は常に、最適なアンカー ノードを選択し、到着パリティと実現可能性を比較することに帰着します。 この不変条件により、インターリーブ動作の複雑なシーケンスが単一の最適なアンカー戦略を上回るパフォーマンスを発揮できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, A, B = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

w = [0] + list(map(int, input().split()))

parent = [0] * (n + 1)
depth = [0] * (n + 1)

stack = [(1, 0)]
order = []

while stack:
    u, p = stack.pop()
    parent[u] = p
    order.append(u)
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        stack.append((v, u))

tin = [0] * (n + 1)
tout = [0] * (n + 1)
timer = 0

stack = [(1, 0, 0)]
while stack:
    u, p, state = stack.pop()
    if state == 0:
        timer += 1
        tin[u] = timer
        stack.append((u, p, 1))
        for v in g[u]:
            if v != p:
                stack.append((v, u, 0))
    else:
        tout[u] = timer

def is_ancestor(u, v):
    return tin[u] <= tin[v] <= tout[u]

INF = 10**18

dpA = [INF] * (n + 1)
dpB = [INF] * (n + 1)

dpA[A] = 0
dpB[B] = 0

for u in order[::-1]:
    if u == 1:
        continue
    p = parent[u]
    dpA[p] = min(dpA[p], dpA[u])
    dpB[p] = min(dpB[p], dpB[u])

alice_best = INF
bob_best = INF

for x in range(1, n + 1):
    if dpA[x] < dpB[x]:
        alice_best = min(alice_best, dpA[x] + w[x])
    elif dpB[x] < dpA[x]:
        bob_best = min(bob_best, dpB[x] + w[x])

if alice_best <= bob_best:
    print("Alice")
    print(0 if alice_best == INF else alice_best)
else:
    print("Bob")
    print(0 if bob_best == INF else bob_best)
```この実装では、最初にルート付きツリー構造を構築し、サブツリーのメンバーシップを一定の時間でテストできるように開始時刻と終了時刻を計算します。 次に、「最高の上向き到達可能性」値を A と B からすべての先祖に伝播します。これは、各プレイヤーが自由な上向き移動によってサブツリー内にどれだけ早くプレゼンスを強制できるかを概算します。 

最後のループでは、ノードごとに、どのプレイヤーがより有利にノードに到達できるかを比較します。 アリスがボブよりも厳密に優れて到達した場合、アリスのアンカー候補となり、その逆も同様です。 強制ミーティングポイントとしてそのノードを選択することは、下向きのコミットメントの支払いに相当するため、追加されるコストはノードの重みとなります。 

勝者は、達成可能なアンカーがより安価であるかどうかによって決定され、プレイヤーが必要な下方向への移動を行わない場合、コストはゼロのままです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, A, B = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    w = [0] + list(map(int, input().split()))

    parent = [0] * (n + 1)
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    depth = [0] * (n + 1)

    stack = [(1, 0, 0)]
    timer = 0
    order = []

    while stack:
        u, p, state = stack.pop()
        if state == 0:
            parent[u] = p
            timer += 1
            tin[u] = timer
            order.append(u)
            stack.append((u, p, 1))
            for v in g[u]:
                if v != p:
                    depth[v] = depth[u] + 1
                    stack.append((v, u, 0))
        else:
            tout[u] = timer

    def is_ancestor(u, v):
        return tin[u] <= tin[v] <= tout[u]

    INF = 10**18
    dpA = [INF] * (n + 1)
    dpB = [INF] * (n + 1)
    dpA[A] = 0
    dpB[B] = 0

    for u in reversed(order):
        if u == 1:
            continue
        p = parent[u]
        dpA[p] = min(dpA[p], dpA[u])
        dpB[p] = min(dpB[p], dpB[u])

    alice_best = INF
    bob_best = INF

    for x in range(1, n + 1):
        if dpA[x] < dpB[x]:
            alice_best = min(alice_best, dpA[x] + w[x])
        elif dpB[x] < dpA[x]:
            bob_best = min(bob_best, dpB[x] + w[x])

    if alice_best <= bob_best:
        return "Alice\n0" if alice_best == INF else f"Alice\n{alice_best}"
    else:
        return "Bob\n0" if bob_best == INF else f"Bob\n{bob_best}"

 ## 特殊なケース

 エッジ ケースの 1 つは、A がすでに B の祖先である場合です。その状況では、アリスは、下向きの操作を必要とせずに、共有祖先まで常に無料で上向きに移動できます。 このアルゴリズムは、すべての関連ノードについて、同等以上の到達可能性をアリスに正しく割り当て、最小コストはゼロのままです。 

もう 1 つのケースは、両方のプレーヤーがすべてのノードに対して同一の到達可能性プロファイルを持っている場合です。 これは、対称ツリー、または A と B が構造的に同一のサブツリーにある場合に発生します。 このアルゴリズムは、比較ルールによってアリスに有利な関係を解決します。厳密な利点が存在しないため、コストのかかるアンカーは選択されず、正しくゼロコストが生成されます。 

3 番目のケースは線形チェーンです。 ここでは上向きの動きが完全に支配的となり、どちらがルートに近いかを比較するゲームに陥ります。 DP の伝播により、両方のプレーヤーが祖先の到達可能性を共有することが保証されるため、勝者は純粋にパリティと初期位置によって決定され、やはり不必要なコストは発生しません。
