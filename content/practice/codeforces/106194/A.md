 ## 解決策
 ## 問題の理解

 2 つの非常に大きな整数が与えられ、それぞれが別の記録カードに書かれた数値を表します。 タスクは、全体の合計を計算することではなく、合計の最後の桁を決定することだけです。 この値は、機械式本棚ロックの 1 桁のアクセス コードとして使用されます。 

より具体的には、入力は 2 つの整数で構成されます。$A$そして$B$、それぞれが非常に大きくなる可能性があり、$10^{100}$。 出力は 1 桁で、次のようになります。$(A + B) \bmod 10$。 

サイズの制約がここで重要なシグナルです。 までの数値$10^{100}$標準の 64 ビット整数型に格納することはできません。また、最後の桁だけを気にするのであれば、任意の長さの整数の加算であっても、不必要な過剰作業となります。 ネイティブの整数演算を使用して完全な整数を解析し、それらの合計を直接計算しようとするソリューションは失敗するか、不必要に重くなります。 

入力の書式設定を考えるときに、微妙な特殊なケースが発生します。 数値は非常に大きくなる可能性があるため、標準の数値タイプの容量をはるかに超える先行桁が含まれる場合があります。 たとえば:

 入力:```
99999999999999999999999999999999999999999999999999 1
```正しい出力:```
0
```整数型への変換を試みる単純な実装は、ここで失敗します。 大きな整数を使用する場合でも、最後の桁だけが重要な場合は、合計を計算するのは不要な作業です。 

もう 1 つのエッジ ケースは、一方または両方の数値が 1 桁の値である場合であり、この場合でもロジックは均一に動作するはずです。 

入力:```
7 8
```出力：```
5
```出力の単純さにより、同じロジックがすべての大きさにわたって均一に動作する必要があるという事実が隠されます。 

## アプローチ

 ブルート フォース アプローチでは、両方の数値を完全な整数として解釈し、大きな整数型に変換し、合計を計算して、最後の桁を抽出します。 この問題はモジュラー演算に帰着するため、これは概念的には正しいです。 ただし、任意精度をサポートしていない言語では、オーバーフローが発生してすぐに失敗します。 大きな整数をサポートする言語であっても、最後の桁だけが重要であるにもかかわらず、すべての桁が処理されるため、このアプローチは無駄です。 

重要な観察は、合計の最後の桁は加数の最後の桁にのみ依存するということです。 これはモジュラー演算から得られます。$$(A + B) \bmod 10 = ((A \bmod 10) + (B \bmod 10)) \bmod 10$$したがって、数値全体を解析する代わりに、数値の最後の文字を読み取り、整数に変換し、10 を法とする合計を計算するだけで済みます。 

これにより、問題は任意長の演算から定数時間の計算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (完全な整数の加算) | O(n) | O(n) | 受け入れられるが不要 |
 | 最適 (最後の桁のみを使用) | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の数値を整数ではなく文字列として読み取ります。 これにより、オーバーフローのリスクが回避され、すべての桁が指定どおりに正確に保存されます。 問題の構造により、文字検査以外の数値解析は必要ないことが保証されています。 
2. 最初の文字列の最後の文字を抽出し、それを整数に変換します。 これは、$A \bmod 10$10 進数の最後の桁が 10 を法とした余りを完全に決定するためです。 
3. 2 番目の文字列の最後の文字を抽出し、それを整数に変換します。 これは、$B \bmod 10$同じ理由で。 
4. これら 2 つの数字の合計を計算します。 
5. 出力も 1 桁である必要があるため、結果のモジュロ 10 を取得して、1 桁を超えるキャリーを処理します。 
6. 結果の数字を出力します。 

機能する理由: 10 進表現は 10 に関するモジュラー構造を保持します。つまり、最後の桁を除くすべての桁が 10 の倍数に寄与するため、モジュロ 10 で消滅します。このアルゴリズムは、基数 10 で書かれた整数について、最後の桁より前で終わるすべての接頭辞は 10 で割り切れるという不変式に依存しているため、最終的な余りには影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b = input().split()

da = ord(a[-1]) - ord('0')
db = ord(b[-1]) - ord('0')

print((da + db) % 10)
```このソリューションでは、2 つの値を文字列として読み取り、単一文字を超える数値変換を回避します。 表現`a[-1]`そして`b[-1]`長さに関係なく最後の桁に安全にアクセスします。 使用する`ord(...)-ord('0')`これは、遅い解析ルーチンを呼び出すことなく、文字数字を整数に変換する高速かつ明示的な方法です。 

最後のモジュロ演算により、2 桁の合計が 9 を超える場合でも正確さが保証されます。そうでない場合は 2 桁の中間結果が生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a, b = sys.stdin.readline().split()
    return str((int(a[-1]) + int(b[-1])) % 10)

assert run("1 1") == "2"
assert run("114514 1919810") == "4"
assert run("0 0") == "0"
assert run("99999999999999999999 1") == "0"
assert run("123456789 987654321") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | 2 | 基本的な正しさ |
 | 114514 1919810 | 4 | サンプルスタイルの大量入力 |
 | 0 0 | 0 | 最小境界の場合 |
 | 999...9 1 | 0 | 多くの桁にわたってキャリー |
 | 123456789 987654321 | 0 | 対称大桁キャンセル |
