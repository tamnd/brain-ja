 ## 解決策
 ## 問題の理解

 円上に配置された点が与えられます。各点は角度 θ と、「アクティブ化」される独立した確率 p を持ちます。 アクティブ化後、アクティブ化されたポイントのすべてのトリプルが三角形を形成し、そのような三角形はすべて一緒になって防御領域として機能します。 中心的な問題は、原点がこれらの三角形の少なくとも 1 つで覆われているかどうかです。 カバーされていない場合、攻撃は成功します。 

したがって、タスクは、円の中心がアクティブ化された点によって形成される三角形に含まれない確率を計算することに帰着します。 

幾何学的には、これは、アクティブ化された点のセットが原点を「囲む」ことができないときを尋ねることと同じです。 平面幾何学におけるよく知られた事実は、円上の一連の点が半円に含まれていない場合に限り、その凸包に原点が含まれるということです。 点から形成された三角形は完全な凸包を生成するため、アクティブ化されたセットがどの半円にも含まれていない場合に限り、原点がカバーされます。 

したがって、問題は次のようになります。すべてのアクティブ化された点が半円の内側にある確率を計算します。 

2^n は実行可能な計算をはるかに超えているため、入力サイズ n が 10^5 までの場合、サブセットの指数列挙は除外されます。 O(n^2) のアプローチでも遅すぎます。 ソート後の解は O(n log n) または O(n) が必要です。 

微妙な問題は、角度が連続浮動小数点数であることです。 2 つの点の角度がほぼ同じである場合、または 2π でラップアラウンドが発生した場合、循環順序を慎重に正規化しない限り、単純なウィンドウ ロジックが壊れる可能性があります。 

エッジケースは次の場合に発生します。 

まず、すべての点は決定論的に半円内にありますが、確率は異なります。 たとえば、すべての p = 1 で、点が 180 度以内にある場合、答えは 1 でなければなりません。 

第 2 に、近くにある 2 つの点がなく、すべてが均等に広がっている場合、少なくとも 3 つの点が広い範囲にわたってアクティブになる場合にのみ、それらが半円に含まれる確率は 0 になります。 この条件は多くの変数を結合するため、単純な独立性の仮定は失敗します。 

第三に、重複または重複に近い角度は、一貫して処理されないと、厳密な「< π」と「≤ π」の境界を破る可能性があります。 

## アプローチ

 ブルートフォース手法では、アクティブ化されたノードのすべてのサブセットを列挙します。 各サブセットについて、そのすべての点が半円の内側に収まるかどうかを確認し、正確にそのサブセットが発生する確率を合計します。 アクティブ化は独立しているため、これは正しいですが、2^n 個のサブセットすべてを反復処理する必要があり、サブセットごとの半円の包含をチェックするだけでも O(n) コストがかかり、O(n 2^n) になります。これは、10^5 までの n では不可能です。 

重要な観察は、視点を反転することです。 サブセットについて推論する代わりに、角度によって点の順序を修正し、「良好な」サブセットを求めます。これは、選択されたすべての点が円周上の長さ π の範囲内にあることを意味します。 その区間の左端の点を固定すると、有効なサブセットはまさにその点から始まる角度幅 π のスライディング ウィンドウに含まれるサブセットとなり、その点が代表的なアンカーとして選択されます。 

これにより、配列を並べ替えて複製した後、グローバル循環制約が線形ウィンドウ制約に変換されます。 次に、「選択されなかった」イベントのプレフィックス積を使用して確率を累積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、角度ごとにポイントを並べ替えます。 循環ラップアラウンドを処理するには、各角度と最後に 2π を追加して、並べ替えられたリストを複製します。 

元の配列の各点 i について、角度差 θ[j] − θ[i] が厳密に π 未満となるような最も遠い点 j を見つけます。 これは、i から始まる最大の半円を定義します。

次に、i をその半円の左端のアクティブ化された点として解釈します。 すべてのアクティブ化された点が半円内にある有効な構成はすべて、i がその構成内の最小角度のアクティブ化された点である固有の表現を持ちます。 

次のように各 i からの寄与を計算します。 

1. i を角度順で最初にアクティブ化された点として固定します。 i はアクティブでなければならないため、これは係数 p[i] に寄与します。 
2. i 以降から j までのすべての点について、各点 k は非アクティブまたはアクティブでなければなりませんが、アクティブな場合はウィンドウ内に留まらなければなりません。 ただし、すべてのアクティブなポイントがウィンドウ内にあることのみが必要なため、ウィンドウ外でのアクティブ化は禁止されます。 したがって、ウィンドウの外側のすべてのポイントは非アクティブでなければなりません。 
3. i 以降のウィンドウ内の点については、i が最初のアクティブな点であることを確認して二重カウントを避ける必要がある場合を除き、自由にアクティブまたは非アクティブにすることができます。 これは、循環順序で i より前のすべての点が非アクティブであることを要求することによって処理されます。これは、スライディング ウィンドウを使用してソートされた順序でスキャンすることによって自然に保証されます。 
4. したがって、貢献度は次のようになります。 

p[i] に (1 − p[k]) の (i, j] の k の積を乗算します。これは、ウィンドウ内の以前の点が「最初の点」構造を壊さないことを表します。

 (1 − p[i]) のプレフィックス積を事前計算して、これらの積を O(1) で評価します。 

すべての i を合計し、モジュロ 998244353 が機能するように注意します。 

### なぜ効果があるのか

 ある半円に含まれるすべての有効なアクティブ化されたサブセットは、その最小角度点を i として選択することによって一意の表現を持ちます。 そのサブセットは合計に 1 回だけ寄与します。 スライディング ウィンドウにより、角度スパンが π 未満のサブセットのみを考慮することが保証され、乗算の構築は活性化イベントの独立性と一致します。 これにより、有効なサブセットと貢献の間の全単射が確立され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n = int(input())
    pts = []
    angles = []

    for _ in range(n):
        theta, x, y = input().split()
        theta = float(theta)
        x = int(x)
        y = int(y)
        p = x * modinv(y) % MOD
        pts.append((theta, p))
        angles.append(theta)

    pts.sort(key=lambda x: x[0])

    # duplicate for circular handling
    arr = pts + [(theta + 6.283185307179586, p) for theta, p in pts]

    m = len(pts)
    p = [arr[i][1] for i in range(len(arr))]
    ang = [arr[i][0] for i in range(len(arr))]

    j = 0
    res = 0

    pref = [1] * (len(arr) + 1)
    for i in range(len(arr)):
        pref[i + 1] = pref[i] * (1 - p[i]) % MOD

    def range_prod(l, r):
        return pref[r] * modinv(pref[l]) % MOD

    for i in range(m):
        while j < i + m and ang[j] - ang[i] < 3.141592653589793:
            j += 1
        # contribution: p[i] * product of (1-p[k]) for k in (i+1..j-1)
        res = (res + p[i] * range_prod(i + 1, j)) % MOD

    print(res % MOD)

if __name__ == "__main__":
    main()
```この解決策は、逆モジュロ演算を使用してすべてのアクティベーション確率をモジュラー形式に変換することから始まります。 角度によって並べ替えると、円上で直線的な順序が確立され、重複によってラップアラウンドの問題が解決されます。 

ポインタ j は、i から始まる最大の半円を拡張します。 プレフィックス積配列を使用すると、効率に不可欠な任意の間隔で積を定時間で計算できます。 

微妙な点の 1 つは、浮動小数点比較と π しきい値の間の一貫性を維持することです。 θ はミリメートル精度で最大 1,000 分の 1 で与えられるため、このコンテキストでは二重比較を使用するのが安全です。 

## 実用的な例

 ### 例 1

 円上に等間隔に配置され、それぞれの確率が 1/2 である 3 つの点を考えます。 

寄与度を計算します。 

| 私 | ウィンドウ [i, j) | 貢献 |
 | --- | --- | --- |
 | 0 | 0..2 | p0 · (1-p1)(1-p2) |
 | 1 | 1..0 (ラップ処理) | p1 · (1-p2)(1-p0) |
 | 2 | 2..1 | p2 · (1-p0)(1-p1) |

 各項は、半円に含まれるサブセットの一意の開始点を選択することに対応します。 これらを合計すると、最終的な確率が得られます。 

これは、有効なサブセットがそれぞれ 1 回だけカウントされることを示しています。 

### 例 2

 すべての点が決定論的に半円内にあり、すべての確率が 1 の場合、j は常に任意の i のすべての点をカバーします。 

| 私 | ウィンドウサイズ | 貢献 |
 | --- | --- | --- |
 | 0 | すべてのポイント | 1 |
 | 1 | すべてのポイント | 除外ロジック後は 0 |
 | 2 | すべてのポイント | 0 |

 合計は 1 になり、中心が常にカバー範囲外にあるという事実と一致します。 

これは、極端な決定論的なケースでの正しさを裏付けます。

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n = int(input())
        pts = []
        for _ in range(n):
            t, x, y = input().split()
            t = float(t)
            x = int(x); y = int(y)
            p = x * pow(y, MOD-2, MOD) % MOD
            pts.append((t, p))

        pts.sort()
        arr = pts + [(t + 6.283185307179586, p) for t, p in pts]
        m = len(pts)

        ang = [a for a,_ in arr]
        prob = [p for _,p in arr]

        pref = [1]*(len(arr)+1)
        for i in range(len(arr)):
            pref[i+1] = pref[i]*(1-prob[i])%MOD

        def get(l,r):
            return pref[r]*pow(pref[l],MOD-2,MOD)%MOD

        j = 0
        ans = 0
        for i in range(m):
            while j < i+m and ang[j]-ang[i] < 3.141592653589793:
                j += 1
            ans = (ans + prob[i]*get(i+1,j))%MOD
        return str(ans)

    return solve()

 ## 特殊なケース

 半円内に密集した点の場合、アルゴリズムは常にクラスター全体をカバーする j を生成し、そのクラスター内のすべての i は、有効なすべてのサブセットと一致する項に寄与します。 スライディング ウィンドウにより、π を超えるサブセットがカウントされることがなくなります。 

完全な円の周囲に等間隔に配置された点の場合、各 i の j は小さいままであり、無効なワイド サブセットが含まれるのを防ぎます。 複製により、角度 0 を横切る構成を見逃すことなく、ラップアラウンド サブセットが正しく処理されるようになります。 

重複した角度の場合、角度差の厳密な不平等により、競合するウィンドウに同一の境界点が二重に含まれることが防止され、アンカー表現の一意性が維持されます。
