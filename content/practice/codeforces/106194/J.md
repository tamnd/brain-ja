 ## 解決策
 ## 問題の理解

 2 つの都市の間では二部構成のシステムが与えられています。 片側には$n$エンティティともう一方は$m$。 双方の間のいくつかのペアはすでに「リンク」によって接続されています。 これらの最初のリンクから、特別なルールにより新しいリンクが表示されます: 1 つの左側のノードがすでにわかっている場合$i$2 つの正しいノードに接続します$k$そして$l$、および別の左側のノード$j$に接続します$k$、その後、間の新しい接続を推測して作成することができます。$j$そして$l$。 対称的に、このルールは基本的に、2 つの行が 1 つの列を共有し、そのうちの 1 つに別の列がある場合は常に、その構造が伝播することを示しています。 

2 人のプレイヤーが交互に動きます。 各移動は、この推論ルールを繰り返し適用することによって現在許可されている新しい接続を追加することで構成されます。 最初の都市 (アーカム) が最初に動き、どちらかのプレイヤーが有効な動きがなくなるまで交互に動きます。 タスクは、考えられるすべてのプレイをシミュレートすることではなく、双方の最適なプレイを考慮して、どちらの側が最終的に最後に手数を使い果たすことが保証されているかを判断することです。 

重要な隠された側面は、ルールが恣意的な成長ではなく、接続性が暗黙のエッジの組み合わせ爆発を生み出す 2 部グラフ上の閉包プロセスであるということです。 

制約により、最大で$10^5$両側にノードがあり、最大で$10^5$したがって、すべての推論されたエッジを明示的に生成しようとしたり、各動きを個別にシミュレートしようとしたソリューションは、すぐに失敗します。 隣接行列を維持することさえ、メモリのせいで不可能です。 

素朴な解釈では、各移動を、有効な推論を見つけるためにノードのトリプルをすべてスキャンするものとして扱います。 それはもうそうなるだろう$O(n^2 m)$最悪の場合。 さらに微妙なのは、推論されたエッジがさらに推論されたエッジを作成する可能性があるため、ステップバイステップのシミュレーションではカスケード拡張の危険性があることです。 

グラフが推論ルールに従ってすでに「構造が完成している」場合、微妙なエッジ ケースが発生します。 たとえば、1 つのパーティション内のすべてのノードが共通の隣接ノードを共有する場合、クロージャはすぐに完全な 2 部構成のクリークを生成します。これは、最初の伝播ステップの後に意味のある変更が存在しないことを意味します。 単純な交互シミュレーションでは、依然として移動ごとに処理を進めようとするため、TLE が発生したり、飽和点が誤って処理されたりする可能性があります。 

## アプローチ

 この問題を単純化するための鍵は、推論ルールがまさに共有隣接関係の下での二部隣接関係の推移閉包であることを認識することです。 このルールは、2 つの左側のノードが右側の隣接ノードを共有する場合、どちらかに接続されているすべての右側の隣接ノードへの到達可能性の点で実質的に同等になることを示しています。 

これは、一方の側に結合検索構造があることをすぐに示唆しています。 2 つの左側のノードが少なくとも 1 つの右側の隣接ノードを共有する場合、それらは同じ「コンポーネント」に属している必要があります。これは、共有隣接ノードを介して接続されると、そのコンポーネント内で到達可能なすべての隣接ノードに相互に接続を伝播できるためです。 同じ理由が右側にも対称的に当てはまります。 

ただし、重要な洞察は、実際にはすべての暗黙のエッジを構築する必要はないということです。 重要なのは、最初のエッジによって引き起こされる 2 部グラフ内の連結成分の構造です。 接続された各コンポーネントは、クロージャの下で完全な 2 部構成のブロックになります。コンポーネント内のすべての左ノードは、最終的には同じコンポーネント内のすべての右ノードに接続されます。 

これが観察されると、ゲームはもはやエッジの作成ではなく、各コンポーネント内で各側がどれだけの「拡張の機会」を持っているかが重要になります。 すべてのコンポーネントは、2 部構成の完了で欠落しているエッジの数に等しい固定数の強制移動に寄与します。 プレーヤーはアーカムから始めてグローバルに交代するため、勝者は純粋にすべてのコンポーネントにわたる強制追加の合計数の同等性によって決まります。 

したがって、問題は次のようになります。2 部グラフの連結成分を計算し、完全な 2 部グラフになるために各成分に欠けているエッジの数を計算し、これらの値を合計し、どのプレイヤーが最後の手を打つかを決定します。 

ブルート フォース シミュレーションでは、動的隣接行列を明示的に維持し、新しいエッジが現れなくなるまで推論ルールを繰り返し適用します。 これはすべてのトリプルにわたってスキャンを繰り返すことになり、次の時点では実行不可能になります。$10^5$規模。 

最適化されたアプローチでは、プロセスが 2 部グラフ上の DSU または BFS に圧縮され、その後コンポーネントごとの組み合わせカウントが続きます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2 m)$|$O(nm)$| 遅すぎる |
 | DSU / コンポーネントのカウント |$O(n + m + k)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 二部グラフを、左ノードと右ノードが別個のセットである標準的な無向グラフとして扱います。 

1. 左の各ノードが入力で指定されたすべての右のノードに接続するグラフを構築します。 これは、推論を行わずに隣接リストを保存するだけです。 
2. 2 部構成で DFS または DSU を実行し、接続されているコンポーネントを特定します。 トラバース中に、エッジを介して左右のパーティション間を確実に伝播します。 
3. 各接続コンポーネントについて、残っているノードの数を数えます。$L$そして右側のノード$R$含まれています。 
4. コンポーネントの場合$L$左側のノードと$R$右側のノードでは、完全に飽和した二部構造には以下が含まれます。$L \cdot R$エッジ。 このコンポーネント内の最初のエッジを減算して、最終的に形成する必要がある新しいエッジの数を計算します。 
5. すべてのコンポーネントにわたるこれらの欠落エッジを合計して、強制移動の総数を取得します。 
6. Arkham から順番に手番を開始するため、合計手数が奇数の場合は Arkham が最後の手を行い、そうでない場合は Yightek が行います。 

これが機能する理由は、推論ルールがコンポーネント間に新しい接続を導入しないためです。 2 つのノードが最初のグラフの異なる接続コンポーネント内にあると、すべての推論に共有隣接パスが必要となるため、ルール アプリケーションはそれらをブリッジできません。 コンポーネント内では、このルールにより完全な 2 部グラフが最終的に完成することが保証されます。つまり、欠落しているエッジはすべて最終的に 1 回だけ作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())

adjL = [[] for _ in range(n + 1)]
adjR = [[] for _ in range(m + 1)]

edges = []

for _ in range(k):
    x, y = map(int, input().split())
    adjL[x].append(y)
    adjR[y].append(x)
    edges.append((x, y))

visitedL = [False] * (n + 1)
visitedR = [False] * (m + 1)

def dfs_l(x, compL, compR):
    visitedL[x] = True
    compL.append(x)
    for y in adjL[x]:
        if not visitedR[y]:
            dfs_r(y, compL, compR)

def dfs_r(y, compL, compR):
    visitedR[y] = True
    compR.append(y)
    for x in adjR[y]:
        if not visitedL[x]:
            dfs_l(x, compL, compR)

total_moves = 0

for i in range(1, n + 1):
    if not visitedL[i]:
        compL, compR = [], []
        dfs_l(i, compL, compR)

        comp_edges = 0
        comp_setR = set(compR)

        for x in compL:
            for y in adjL[x]:
                if y in comp_setR:
                    comp_edges += 1

        total_moves += len(compL) * len(compR) - comp_edges

# nodes in R not visited but isolated (no edges)
for j in range(1, m + 1):
    if not visitedR[j]:
        total_moves += 0
        visitedR[j] = True

if total_moves % 2 == 1:
    print("Arkham")
else:
    print("Yightek")
```DFS は、左右のパーティションを交互に切り替えて、ノードを再度訪問することなく、接続されている各コンポーネントを完全に探索できるようにします。 このコンポーネントは、到達可能な左右のノードをすべて収集します。 

カウントするステップでは、コンポーネント内にすでに存在するエッジの数を明示的に計算します。 表現$L \cdot R - \text{existing edges}$は、完全な 2 部クロージャに到達するためにまだ作成する必要があるエッジの数を正確に表します。これは、そのコンポーネントによって寄与された有効な移動の数に対応します。 

最後に、プレイヤーは有効なエッジがなくなるまで交互に強制加算を行うため、パリティによって勝者が決まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + m + k)$| 各ノードとエッジは DFS 中に 1 回アクセスされ、カウントされます。 
| スペース |$O(n + m)$| 隣接リストと訪問配列 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    adjL = [[] for _ in range(n + 1)]
    adjR = [[] for _ in range(m + 1)]

    edges = []
    for _ in range(k):
        x, y = map(int, input().split())
        adjL[x].append(y)
        adjR[y].append(x)
        edges.append((x, y))

    visitedL = [False] * (n + 1)
    visitedR = [False] * (m + 1)

    sys.setrecursionlimit(10**7)

    def dfs_l(x):
        visitedL[x] = True
        for y in adjL[x]:
            if not visitedR[y]:
                dfs_r(y)

    def dfs_r(y):
        visitedR[y] = True
        for x in adjR[y]:
            if not visitedL[x]:
                dfs_l(x)

    total_moves = 0

    for i in range(1, n + 1):
        if not visitedL[i]:
            compL, compR = [], []
            stack = [(i, 0)]
            visitedL[i] = True

            while stack:
                node, t = stack.pop()
                if t == 0:
                    compL.append(node)
                    for y in adjL[node]:
                        if not visitedR[y]:
                            visitedR[y] = True
                            stack.append((y, 1))
                else:
                    compR.append(node)
                    for x in adjR[node]:
                        if not visitedL[x]:
                            visitedL[x] = True
                            stack.append((x, 0))

            comp_setR = set(compR)
            comp_edges = 0
            for x in compL:
                for y in adjL[x]:
                    if y in comp_setR:
                        comp_edges += 1

            total_moves += len(compL) * len(compR) - comp_edges

    if total_moves % 2 == 0:
        return "Yightek"
    else:
        return "Arkham"

 ## 特殊なケース

 完全に空のグラフの場合、エッジは存在しないため、強制的に完了するコンポーネントはありません。 合計の手数がゼロであり、2 番目のプレーヤーには勝ち手がないため、アルゴリズムは Yightek を正しく出力します。 

すべてのノードが単一のエッジを介して接続されているグラフの場合、次のようになります。$n = m = 1$の場合、DFS は 1 つの既存エッジを持ち、欠落エッジがない 1 つのコンポーネントを生成するため、移動はできず、Yightek が返されます。 

次のような切断されたペアの場合$(1,1)$そして$(2,2)$の場合、アルゴリズムはそれらを別のコンポーネントとして扱います。 それぞれが強制完了に寄与しないため、ゲームはすぐに終了し、再び Yightek が得られます。
