 ## 解決策
 ## 問題の理解

 グリッドは、各セルが自由な地面、障害物となる建物、道路タイル、または 2 つの特別な位置 (開始点と目標点) のいずれかである都市地図を記述します。 最短経路を使用して S から T に移動したいと考えていますが、道路には特別な「ブロックされた道路タイルを 1 つ飛び越える」メカニズムが導入されているため、移動は標準的な 4 方向のグリッドウォークではありません。 

どのセルからでも、空いているセルまたはターゲットであれば、隣接するセルに移動できます。これには 1 ステップかかります。 さらに、ある方向の次のセルが街路セル M である場合、着地セルが存在し、フリーまたはターゲットである場合には、それを完全にスキップして、同じ方向の次のセルに着地することができます。 このジャンプにも 1 ステップかかります。 重要な制限は、M の上に立つことは決してできないことですが、ジャンプするときに正確に M の上を横切ることはできるということです。 

グリッド サイズは 3000 × 3000 まで増加するため、頂点の数は最大 900 万になります。 すべてのセルにわたってスキャンを繰り返したり、マルチソース緩和を複数回行ったりして距離を再計算しようとするアルゴリズムは失敗します。 唯一の実行可能なアプローチは、エッジの数が線形に近いもの、またはグリッド サイズに対して最大でも小さな定数係数であることです。これは、すべての移動のコストが等しいため、BFS または 0-1 BFS のような最短パス アルゴリズムを提案します。 

微妙なエッジケースは、M 細胞の連鎖から生じます。 直接隣接するものだけをチェックする単純な実装では、ジャンプが複数ではなく 1 つの M をスキップすることに依存していることを見逃してしまう可能性があります。 誤って M を通行可能な地形として扱うと、別の障害モードが発生します。ルールでは、その地形への着陸が明示的に禁止されているため、M への踏み込みを許可する BFS は無効な状態を誤って拡大します。 

不注意な取り扱いによって破損する小さな例:

 入力:```
1 3
S M T
```M を飛び越えることができるため、正しい出力は 1 です。特別なロジックを使用せずにジャンプを禁止するか、M をブロックとして扱う単純な BFS は、-1 を出力します。 

もう 1 つのエッジ ケースは、S と T が直接隣接するのではなく、有効なダブル ジャンプ ルートのみを持つ壁によって分離されている場合です。 ジャンプメカニズムを完全に欠落すると、再び不正確で到達不能な結果が発生します。 

## アプローチ

 この強引なアイデアは、各セルをグラフ内のノードとして扱い、明示的にエッジを構築することです。 すべてのセルからその 4 つの方向をスキャンします。 各方向について、壁でない場合は隣接するセルに接続するか、可能性のある M の後の次のセルをチェックし、有効な場合はジャンプ エッジを追加します。 グラフが構築されたら、S から BFS を実行して T までの最短距離を計算します。 

すべての正当な手はコスト 1 のエッジとして表されるため、正確さは簡単です。問題は効率です。すべてのセルを 4 方向すべてにスキャンしてエッジを構築するのはすでに O(HW) ですが、隠れたコストは慎重な境界チェックと隣接評価の繰り返しです。 漸近的には線形に見えますが、単純な実装は、最大 900 万のノードにわたって繰り返されるスキャン ロジックと貧弱な定数係数により劣化することがよくあります。 さらに重要なのは、明示的な隣接ストレージにはエッジに比例したメモリが必要になるため、Python では十分な大きさになる可能性があり、リスクが伴う可能性があります。 

重要な点は、グラフを明示的に構築する必要がないということです。 BFS をグリッド上で直接実行でき、セルを拡張するときにその場で発信移動を生成します。 すべての移動のコストが 1 であるため、標準の BFS で十分です。 各セルは 1 回処理され、セルごとに最大 4 つの方向遷移のみを計算するため、全体の作業は H·W で線形になります。 

ジャンプ ルールはローカルで処理されます。ある方向を見るときは、まず隣接するセルをチェックします。 それが無料または T の場合は、キューに入れます。 M の場合、同じ方向の次のセルをチェックし、有効であればそれをキューに入れます。 これにより、前処理が不要になります。

 ## アルゴリズムのチュートリアル

 グリッドを暗黙的なグラフとして扱い、S から BFS を実行します。 

1. グリッドを読み取りながら、S と T の座標を見つけます。 高速アクセスのためにグリッドも保存します。 BFS には開始ノードと終了条件が必要なため、これが必要です。 
2. すべてのセルに対して距離配列を -1 で初期化し、S の距離を 0 に設定します。また、S をキューにプッシュします。 これにより BFS 階層化が確立され、初めてセルに到達する際の距離が最短になることが保証されます。 
3. キューが空でない間に、セル (x, y) をポップします。 T の場合、BFS がこれが最短パスであることを保証するため、早期に停止できます。 
4. 4 つの方向のそれぞれについて、隣接するセル (nx、ny) を計算します。 それが境界内にあり、壁ではなく、フリーまたは T のいずれかである場合、まだアクセスされていない場合は、それを押すことによって通常の移動を試みます。 これは標準の BFS エッジに対応します。 
5. 隣接するセルが M の場合、特別なジャンプを試みます。 その先のセル (nx2、ny2) を計算します。 そのセルがグリッド内にあり、空いているか T である場合、それをキューに入れます。 これは、その方向に正確に 1 つの M セルをスキップすることをモデル化します。 
6. BFS が完了するか、T に達するまで続行します。 

正確さは、BFS が距離の増加順に状態を探索するという事実に基づいています。 通常であれジャンプであれ、すべての有効な動きのコストは正確に 1 であるため、BFS の階層化は最短のパス長に正確に対応します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    H, W = map(int, input().split())
    grid = []
    sx = sy = tx = ty = -1

    for i in range(H):
        row = list(input().strip())
        for j, c in enumerate(row):
            if c == 'S':
                sx, sy = i, j
            elif c == 'T':
                tx, ty = i, j
        grid.append(row)

    dist = [[-1] * W for _ in range(H)]
    q = deque()

    dist[sx][sy] = 0
    q.append((sx, sy))

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        x, y = q.popleft()

        if x == tx and y == ty:
            print(dist[x][y])
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy

            if 0 <= nx < H and 0 <= ny < W:
                cell = grid[nx][ny]

                if cell != '#':
                    if cell != 'M':
                        if dist[nx][ny] == -1:
                            dist[nx][ny] = dist[x][y] + 1
                            q.append((nx, ny))
                    else:
                        nx2, ny2 = nx + dx, ny + dy
                        if 0 <= nx2 < H and 0 <= ny2 < W:
                            cell2 = grid[nx2][ny2]
                            if cell2 != '#' and cell2 != 'M':
                                if dist[nx2][ny2] == -1:
                                    dist[nx2][ny2] = dist[x][y] + 1
                                    q.append((nx2, ny2))

    print(-1)

if __name__ == "__main__":
    solve()
```BFS はデキューを使用して FIFO 処理を保証します。 距離配列により、各セルが 1 回処理されることが保証され、繰り返しの緩和が防止されます。 ジャンプ ロジックは隣接拡張に直接組み込まれており、前処理のオーバーヘッドを回避します。 

微妙な実装の詳細は、ジャンプ後であっても M での着地を決して許可しないことです。 条件`cell2 != 'M'`これを厳格に強制します。 もう 1 つの重要な点は、訪問したノードがキューに入れられるまでマークしないことです。これにより、BFS の正確性が維持され、重複したキュー エントリが回避されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、S と T が隣接しているが、単一の M によって分離されている場合です。アルゴリズムは、M に遭遇するたびにジャンプ ルールをチェックし、有効であれば着陸セルをキューに入れるため、これを正しく処理します。 入力用`S M T`, S からの BFS は M を正しい方向に見て、その先のセルを T として計算し、距離 1 でキューに入れます。 

もう一つのケースは、複数の M セルが連続して出現する場合です。 このアルゴリズムでは、移動ごとに正確に 1 つの M のスキップのみが考慮されるため、複数の M セルを介したジャンプの連鎖は許可されません。 のようなセグメントの場合`S M M T`、最初の M は、その後の着地セルが有効な場合にのみジャンプを許可します。 2 番目の M は、正常に到達しない限り意味がありません。 

最後のエッジ ケースは、T が S にすぐ隣接しているが、別の方向の壁によってブロックされている場合です。 壁がキューに入れられることはなく、有効な隣接要素のみが拡張に寄与するため、BFS は引き続き無効なパスを正しく回避します。
