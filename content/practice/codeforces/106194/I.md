 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$m$まで$10^{12}$。 この数値からすべての正の約数を考慮し、昇順に並べ替えます。 ソートが完了したら、連続する約数を調べ、正確に 1 単位だけ異なる隣接するペアがいくつあるかを数えます。これは、約数セット内でそれらの間に整数が存在しないことを意味します。 

同様に、約数リストをスキャンして、約数に連続する整数が何回含まれているかを尋ねます。 

The output is just this count.

 制約$m \le 10^{12}$までのすべての整数を反復しようとするアプローチは直ちに除外されます。$m$。 数直線を完全にスキャンすることは不可能です。 すべての数値を繰り返しても、$10^{12}$あるいは、単純な割り算チェックを行うと、時間制限を何桁も超えてしまいます。 

正しい解決策は、サブリニア時間での約数の列挙に依存する必要があります。$O(\sqrt{m})$、約数はペアで現れるためです。 

微妙なコーナーケースが現れるのは、$m = 1$。 除数セットは次のとおりです$\{1\}$したがって、隣接するペアはまったく存在せず、答えは 0 になります。もう 1 つのエッジ状況は次のような場合です。$m$は素数、約数は$\{1, m\}$、やはり連続したペアは得られません。 

約数をリストしてから隣接性をチェックする単純なアプローチは問題ありませんが、平方根の重複排除を忘れたり、誤って並べ替えたり、ペア内の連続した構造を仮定したりする単純な約数の列挙は失敗します。 

## アプローチ

 問題を解決する強引な方法は、1 から 2 までのすべての整数をテストすることです。$m$、分割されるかどうかを確認します$m$、そのような数値をすべて保存し、並べ替えてから、1 つ異なる隣接するペアを数えます。 

これは約数の定義に直接従うため、これは正しいです。 ただし、コストの大半はチェックによって決まります。$m$候補はそれぞれモジュロ演算を必要とします。 つまり$O(m)$、これは完全に不可能になります$10^{12}$。 

約数の構造により、より強力な観察が可能になります。 すべての約数$d$とペアにする$m/d$したがって、すべての約数は最大までの反復だけで生成できます。$\sqrt{m}$。 これにより、列挙コストが大幅に削減されます。 すべての約数を最大約約のサイズのリストに集めたら、$2\sqrt{m}$、それらを並べ替えて、連続する差異が 1 に等しいかどうかを数えます。 

重要な考え方は、隣接性は純粋にソートされた約数リストのプロパティであり、約数の生成方法ではないということです。 そこで、問題を 2 つのフェーズに分けます。効率的な除数の生成と、ソートされたリストの線形スキャンです。

 | 最適 |$O(\sqrt{m} \log \sqrt{m})$|$O(\sqrt{m})$| 承認済み |

 ## アルゴリズムのチュートリアル

 除数リストを効率的に構築し、その隣接構造を分析します。 

1. 反復する$i$1から$\lfloor \sqrt{m} \rfloor$。 それぞれについて$i$、どうかを確認してください$i \mid m$。 上記の約数はすべて存在するため、これが必要な唯一の範囲です。$\sqrt{m}$その下にマッチングパートナーがいます。 
2.いつでも$i \mid m$、 追加$i$除数リストに追加します。 これは、除数のペアの小さい側をキャプチャします。 
3. さらに追加$m / i$異なる場合はリストに追加$i$。 これにより、重複を避けながら、ペアになったより大きな除数が取得されます。$i^2 = m$。 
4. 収集した約数を並べ替えます。 ペアワイズ生成では順序が保証されず、隣接関係はソートされた順序で定義されるため、ソートが必要です。 
5. ソートされたリストを調べて、インデックスの数を数えます。$j$満足する$d[j] + 1 = d[j+1]$。 

最終的なカウントが答えになります。 

### なぜ効果があるのか

 のすべての約数$m$各約数のペアはより小さいエンドポイントで検出されるため、構築されたリストに 1 回だけ出現します。$i \le \sqrt{m}$。 並べ替えると、約数の自然な数値順序が復元されます。 Since adjacency is defined strictly in that order, checking consecutive elements after sorting exactly captures all pairs of consecutive integers within the divisor set. 除数セット内の連続する整数はソート順に並べて表示される必要があるため、ペアを見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

m = int(input().strip())

divs = []

i = 1
while i * i <= m:
    if m % i == 0:
        divs.append(i)
        if i * i != m:
            divs.append(m // i)
    i += 1

divs.sort()

ans = 0
for i in range(len(divs) - 1):
    if divs[i] + 1 == divs[i + 1]:
        ans += 1

print(ans)
```コードは、整数を読み取り、約数の空のリストを構築することから始まります。 までのループ$\sqrt{m}$についてのみ実行することを保証します$10^6$最悪の場合でも反復可能ですが、これは安全です$10^{12}$。 条件`i * i != m`完全正方形の二重カウントを回避します。そうしないと、重複したエントリが作成され、ソート後に隣接カウントが破損します。 

約数は最初に小さな因子があり、すぐに大きな因子が追加されるという混合順序で生成されるため、並べ替えは不可欠です。 ソートがなければ、隣接性チェックは意味がありません。 

最後のループは、連続する整数をチェックする単一の線形スキャンです。

    import sys
    input = sys.stdin.readline

 ## 特殊なケース

 のために$m = 1$、除数リストに含まれるのは$[1]$。 アルゴリズムが生成するのは、$i = 1$、1 を 1 回追加し、重複の追加を避けます。 並べ替えは簡単ではないため、スキャン ループは実行されず、0 が生成されます。 

のような完全な正方形の場合$m = 36$、 いつ$i = 6$、条件$i \cdot i = m$追加を妨げます$m/i$また。 これにより、並べ替え時に誤って誤った隣接関係が作成される、6 の 2 つのコピーなどの重複エントリが回避されます。 

素数の場合のみ、$i = 1$貢献する、生み出す$[1, m]$。 スキャンでは 1 より大きい単一のギャップがチェックされるため、結果は 0 になります。
