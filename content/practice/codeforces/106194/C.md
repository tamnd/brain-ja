 ## 解決策
 ## 問題の理解

 システムに保存された測定値を表す一連の値が与えられます。 これらの値は一連の操作によって破損しています。 各操作では、配列の連続セグメントが選択され、そのセグメント内のすべての値の符号が反転されます。 

操作は次々に適用され、与えられた配列は、すべての反転がすでに発生した後の最終的な破損状態を反映しています。 タスクは、これらの符号反転が発生する前の配列の元の合計が何であったかを再構築することです。 

配列内の各位置は、いくつかの範囲反転の影響を受けます。 位置が偶数回反転された場合、その位置は元の位置と比較して変更されません。 奇数回反転すると、最終的な配列では符号が反転されます。 このパリティ効果が問題の全体的な構造です。 

制約は最大 50 万の要素と 50 万の演算に達します。 すべての操作ですべての要素にアクセスするソリューションでは、10^11 のオーダーで更新が試行されますが、これは 1 秒の制限をはるかに超えています。 これにより、直接のシミュレーションが直ちに除外されます。 

素朴だが重要な間違いは、各フリップを配列上で直接シミュレートすることです。 たとえば、セグメントを繰り返し反転すると、操作ごとに線形の時間を費やすことになります。 配列サイズと演算数が両方とも大きいため、これは中程度の入力でも失敗します。 

もう 1 つの微妙な間違いは、逆の順序で操作を反転し、反転を再適用することによって、元の配列を再構築しようとすることです。 これは論理的には正しいですが、計算的にはシミュレーションと同じであり、複雑さは改善されません。 

欠けている重要な洞察は、配列の中間状態をまったく知る必要がないことです。 各インデックスが何回反転されるかというパリティのみが重要です。 

## アプローチ

 直接シミュレーションのアプローチでは、間隔内のすべてのインデックスを反復処理し、負の 1 を乗算することで各範囲反転を適用します。 これは操作の定義を正確に反映しているため、これは正しいです。 ただし、各操作は最大 n 個の要素に影響を与える可能性があるため、最悪の場合、合計作業量は m 倍になります。 どちらも最大 50 万なので、これでは数桁遅すぎます。 

この改善は、各操作がインデックスごとのカウントにのみ寄与することを観察することで得られます。 符号の変更を繰り返し適用する必要はありません。 カバーの総数が偶数か奇数かを知る必要があるだけです。 これにより、問題は増分範囲の維持とインデックスごとの最終パリティの計算に変換されます。 

これは、差分配列が機能する典型的な状況です。 各操作では、セグメントのカバレッジ カウンタに 1 が加算されます。 すべての操作を処理した後、各インデックスが何回カバーされたかを再構築します。 パリティのみが重要なので、その数を 2 を法として計算します。 次に、それに応じて各要素の符号を調整します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nm) | O(1) おまけ | 遅すぎる |
 | 差分配列 (パリティ追跡) | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての範囲操作は、クエリごとにすべての位置を明示的に更新せずに、各インデックスが反転される回数を計算できる方法で処理されます。

1. ゼロに初期化された差分配列を作成します。 この構造体は、各位置で開始および終了する反転操作の数をエンコードします。 範囲の増分は、左端点で 1 を加算し、右端点の直後で 1 を減算することによって表されます。 
2. 各演算間隔 [l, r] について、l で差分配列をインクリメントし、r + 1 でデクリメントします。これにより、後でプレフィックスの合計を計算するときに、間隔内のすべてのインデックスが正確に 1 つの追加カウントを受け取ることが保証されます。 
3. 差分配列に対してプレフィックスの合計を計算します。 これにより、位置ごとに、そのインデックスが含まれる操作の数が再構築されます。 結果は、各要素に適用される符号反転の数になります。 
4. 各位置 i について、フリップ数が偶数か奇数かをチェックします。 偶数の場合、値は最終配列で指定されたままになります。 奇数の場合、元の値は指定された値の否定であるはずなので、その符号を反転します。 
5. すべての修正値を累積して、元の合計を計算します。 

これが機能する主な理由は、各操作が各インデックスに独立して寄与し、符号反転がパリティのみが重要なグループを形成するためです。 複数のフリップはペアでキャンセルされるため、合計カウントが奇数であるかどうかのみが値を変更します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())

    diff = [0] * (n + 2)

    for _ in range(m):
        l, r = map(int, input().split())
        diff[l - 1] += 1
        diff[r] -= 1

    cur = 0
    ans = 0

    for i in range(n):
        cur += diff[i]
        if cur % 2 == 0:
            ans += a[i]
        else:
            ans -= a[i]

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ゼロベースのインデックスにシフトされた差分配列が使用されます。 各操作は左側の境界で加算し、右側の境界の直後で減算するため、プレフィックスの累積によってカバレッジ カウントが正しく再構成されます。 実行変数 cur は、現在のインデックスに影響を与えるアクティブなフリップの数を追跡します。 

決定ステップは純粋にパリティに基づいています。 cur が奇数の場合、要素は指定された最終状態に対して反転する必要があります。

 再構成された合計は -12 になります。 これは、奇数回反転されたインデックスは、提供された状態に対して反転する必要があるという考えと一致します。 

2 番目のサンプルでは、​​複数のオーバーラップと繰り返しの反転がいくつかの位置で相殺され、混合パリティ パターンが残ります。 プレフィックス カバレッジを計算すると、次の結果が得られます。

 ## 特殊なケース

 フルレンジ フリップを 1 回適用すると、コア パリティ ロジックが実証されます。 入力用`n=4, a=[2,2,2,2], m=1, [1,4]`、すべてのインデックスのフリップ カウントは 1 です。アルゴリズムはすべての位置に対して cur=1 を計算するため、すべての値が否定され、最終的な合計は -8 になります。 これは、単一のグローバル反転によってすべての寄与が逆転するという期待と一致します。 

操作が行われないケースでは、アルゴリズムが意図しない変更を導入していないことが確認されます。 と`m=0`、差分配列はどこでもゼロのままで、プレフィックス数はすべて偶数で、出力は配列の元の合計と等しくなります。 

単一要素のエッジ ケースにより、インデックス付けの正確さが保証されます。 と`n=1`の場合、差分の更新は単一の増分と減分となり、依然として正しいプレフィックス パリティが生成されます。 アルゴリズムは、単一の範囲にその値が含まれるかどうかに応じて、唯一の値を正しく反転または保持します。
