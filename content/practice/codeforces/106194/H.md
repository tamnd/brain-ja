 ## 解決策
 ## 問題の理解

 一列に配置された町の友好度の値を表す一連の整数が与えられます。 旅行者はこのシーケンスの連続するセグメントを選択する必要がありますが、セグメントの長さには制限があります。少なくとも L 個の町、最大で R 個の町が含まれている必要があります。 すべての有効なセグメントの中で、平均値ができるだけ大きいセグメントが必要です。 出力は正確な最大平均ではなく、その下限です。 

したがって、キー オブジェクトは制約付き部分配列です。すべての候補は、L ≤ (r − l + 1) ≤ R となるウィンドウ [l, r] です。このようなウィンドウごとに、平均合計を長さで割った値を計算し、その比率を最大化したいと考えます。 

制約は n = 2 × 10^5 まであり、すべての部分配列の O(n²) 列挙は即座に除外されます。 O(nR)でもRが大きいと危険になります。 これにより、各位置が償却定数時間または対数時間で処理されるという解決策が導き出されます。 

単純な間違いは、右のエンドポイントを修正して、貪欲に平均を最大化することで最良の左のエンドポイントを選択できると考えることです。 セグメントを短くすると平均は増加しますが、単調ではないため、これは失敗します。 

たとえば、最後に値の高い要素を追加すると合計は増加しますが、平均は減少します。プレフィックスは短いほど優れていますが、他の部分のセグメントがわずかに長い方がさらに優れているセグメントについて考えてみましょう。 最適なウィンドウはどちらの方向でも単調ではありません。 

もう 1 つの微妙なエッジ ケースは、L = R の場合です。その場合、問題は固定長ウィンドウ、つまり単純なスライディング ウィンドウの最大平均を選択することになります。 一般的なソリューションでは、劣化することなくこれを正しく処理する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。すべての有効なペア (l, r) を列挙し、その長さが [L, R] 以内であるかどうかを確認し、その合計を計算し、平均を計算し、最大値を追跡します。 合計の計算はプレフィックス合計を使用して高速化できるため、各クエリは O(1) になりますが、サブ配列の数は最悪の場合でも O(n²) になります。 n = 2 × 10^5 では、これは完全に不可能です。 

改善するには、目標を書き換えます。 固定された候補回答 x の場合、各要素を b[i] = a[i] − x として変換することを検討してください。 次に、その変換された合計が負でない場合に限り、セグメントの平均値は少なくとも x になります。 これは、問題を [L, R] 内に合計が 0 以上となる長さの部分配列が存在するかどうかをチェックすることに変換します。これは、推測された答えに対する標準的な実行可能性チェックです。 

これにより、答えに対する二分探索が即座に提案されます。 残る唯一の課題は、特定の x の実現可能性を効率的にチェックすることです。 

固定 x の場合、b[i] の接頭辞の合計を維持します。 長さが L と R の間である i で終わる部分配列を見つける必要があります。つまり、次のことが必要です。 

S[i] − S[j] ≥ 0 (i − R ≤ j ≤ i − L)。 

したがって、各 i について、スライディング ウィンドウ範囲内の最小プレフィックス合計 S[j] が必要です。 これは、プレフィックス合計に対する単調デキューを使用して維持でき、償却された O(1) 内の各 i に対して最適な候補 j が常に存在することが保証されます。 これにより、各実現可能性チェックが O(n) になり、二分探索により log(最大値) 係数が追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) または O(n) | 遅すぎる |
 | 二分探索 + スライディング ウィンドウ | O(n log A) | O(n) | 承認済み |

 ここで、A はフレンドリーさの値の範囲で、最大 10^9 です。 

## アルゴリズムのチュートリアル

 問題を再定式化して、候補の平均値 x が達成可能かどうかを判断し、そのような x の最大値を二分探索します。

1. 候補値 x を固定し、配列を b[i] = a[i] − x に変換します。 目標は、合計 ≥ 0 の有効な部分配列を見つけることになります。 
2. S[0] = 0 および S[i] = b[1] + … + b[i] であるプレフィックス合計 S を計算します。 これにより、任意の部分配列の合計を S[i] − S[j] として記述することができます。 
3. 各エンドポイント i に対して、i − R ≤ j ≤ i − L となる開始インデックス j を選択する必要があります。部分配列は、その長さが [L, R] にある場合にのみ有効です。 これにより、有効な j 値のスライディング ウィンドウが作成されます。 
4. 有効な j 値の間の最小プレフィックス合計を追跡するデータ構造を維持します。 デキューは、プレフィックスの合計が昇順に保持される場合に使用されます。 これにより、フロントには常に最小の S[j] が格納され、S[i] − S[j] が最大化されます。 
5. i を L から n に移動するとき、まずインデックス i − L を両端キューに挿入し (新しく有効になるため)、i − R より小さいインデックスを削除します (許可されなくなったため)。 
6. デキューを更新した後、S[i] − minimum_prefix_in_window ≥ 0 かどうかを確認します。YES の場合、候補 x は実行可能です。 
7. 十分に広い範囲 (通常は 0 から max(a[i]) まで)、または必要に応じて浮動境界を使用して x を二分探索します。 答えの下限が必要なので、整数 x を二分探索できます。 

### なぜ効果があるのか

 重要な不変条件は、すべての位置 i で、両端キューにはすべての j の接頭辞の合計 S[j] が正確に含まれており、i で終了し開始 j を持つ部分配列の長さが [L, R] になり、その中で先頭が最小の接頭辞の合計になるということです。 これにより、i で終わる有効な部分配列が sum ≥ 0 を達成できる場合、最小の S[j] を使用する部分配列がそれを検出することが保証されます。 したがって、実現可能性チェックは正確であり、二分探索は達成可能な最大の平均値に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def can(avg, a, n, L, R):
    # transformed prefix sums
    S = [0] * (n + 1)
    for i in range(1, n + 1):
        S[i] = S[i - 1] + (a[i - 1] - avg)

    dq = deque()
    dq.append(0)

    # we maintain candidates j for each i
    for i in range(L, n + 1):
        # add new valid index i-L
        j_add = i - L
        while dq and S[dq[-1]] >= S[j_add]:
            dq.pop()
        dq.append(j_add)

        # remove out-of-range indices (i - R - 1 becomes invalid)
        if i - R - 1 >= 0:
            j_remove = i - R - 1
            if dq and dq[0] == j_remove:
                dq.popleft()

        # check feasibility
        if S[i] - S[dq[0]] >= 0:
            return True

    return False

def solve():
    n, L, R = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 0, max(a)

    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid, a, n, L, R):
            lo = mid
        else:
            hi = mid - 1

    print(lo)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性のチェックを最適化から分離します。 の`can`関数は、固定された候補平均に対して変換されたプレフィックス合計を構築し、両端キューを使用して開始インデックスの有効ウィンドウ内の最小プレフィックス合計を維持します。 

平均は最大要素を超えることができないため、二分探索では max(a) の上限が使用されます。 収束時の無限ループを避けるために、中点は上向きにバイアスされています。 

デキュー ロジックは重要な部分です。有効性 (インデックス範囲の制約) と最適性 (最小プレフィックス合計) の両方を同時に適用します。 挿入と削除の順序により、各インデックスが正確に 1 回処理されることが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
5 2 3
1 12 7 9 2
```x = 9 の実現可能性をテストします。 

| 私 | S[i] | 有効な j 範囲 | デキュー (インデックス) | 最高のS[j] | チェック |
 | --- | --- | --- | --- | --- | --- |
 | 2 | ... | [0..0] | [0] | S[0] | S[2]-S[0] < 0 |
 | 3 | ... | [1..1] | [1] | S[1] | 有効 ≥ 0 |

 i = 3 では、セグメント [2,3] (値 12,7) の平均値は 9.5 であるため、実現可能性は成功します。 二分探索は 9 に収束します。 

これは、構造がどのようにして、長く希薄化されたセグメントではなく、最適な短くて高価値のセグメントを自然に選択するかを示しています。

```x ≤ 5 の場合、すべての変換された値はどのセグメントに対しても負ではないため、実現可能性は常に真です。 二分検索では 5 が返されます。 

これにより、均一な配列が L と R に関係なく正しく折りたたまれることが確認されます。

 ## 特殊なケース

 最小限の長さのケースのような`n = 1, L = R = 1`すべてを単一の値に削減し、アルゴリズムは両端キューをインデックス 0 で初期化し、ただちに唯一の有効なセグメントを正しく評価します。 

次のような均一な配列`[3, 3, 3, 3]`すべてのプレフィックス合計の差の一貫性が維持され、両端キューが比較の結果を変更することはありません。そのため、すべての実現可能性チェックは x ≤ 3 については成功し、それを超えると失敗します。 

最適なセグメントが正確に長さ L にある場合は、挿入する理由を示しています。`i - L`それ以前ではなく、各ステップで正確に。 たとえば、`[1, 2, 100, 2, 1]`L = R = 3 の場合、セグメントは`[2,3,4]`は、i = 4 および j = 1 がアクティブになった場合にのみ評価されます。これは、インデックスの遅延アクティブ化が正確さのために不可欠であることを示しています。
