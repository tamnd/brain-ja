 ## 解決策
 ## 問題の理解

 2 人のプレイヤーがターンベースのシミュレーションに参加し、それぞれが 2 つのリソースとアクションのキューを維持します。 各アクションは攻撃、防御、または隠れる動きのいずれかであり、すべてのアクションには数値的な強さが含まれます。 複数のラウンドにわたって、両方のプレイヤーは新しく受け取ったアクションをキューの最後尾に追加し、各キューから前のアクションを繰り返し取得し、詳細なルール システムに従って相互に解決します。 

インタラクション ルールは、一連のアクションが健康と「混乱」と呼ばれる二次リソースにどのような影響を与えるかを定義します。 攻撃アクションは主に直接ダメージを与え、防御は不一致を混乱ダメージに変換することで相互作用し、非表示アクションは混乱を回復するか、アクションがキューの先頭に再挿入され、効果的にアクションの消費を遅らせることができます。 戦闘は、一方のプレイヤーのキューが空になり、もう一方のプレイヤーに残りの攻撃アクションがなくなるまで続き、その時点で現在のラウンドは直ちに終了します。 また、グローバル ルールもあります。混乱がゼロに達すると、プレイヤーは崩壊状態に入り、キューをクリアし、次のラウンドのアクションの開始をスキップし、次のラウンドの終了時に混乱を回復します。 体力がゼロになると、ゲームは即座に終了します。 

入力サイズは大きく、最大 100,000 ラウンド、最大 200,000 総アクションです。 これにより、操作ごとにキューを繰り返しスキャンまたは再構築するアプローチは即座に除外されます。 どのようなソリューションでも、各アクションが一定の回数だけ処理されるようにする必要があります。そうしないと、最悪の場合、「非表示」アクションが前面に押し戻されることによって再処理が繰り返され、二次的な動作に変質してしまいます。 

いくつかの特殊なケースは微妙です。 1 つは、非表示アクションが前面に再挿入されるインタラクションです。これにより、慎重に制御しないと、同じアクションが複数回処理される可能性があります。 もう 1 つはコラプス動作です。これは、プレイヤーのキューがラウンド途中でクリアされますが、シミュレーションは同じラウンド内の相手側の残りのアクションを続行します。 ラウンド終了条件をチェックするだけの単純なシミュレーションは、ここでは失敗します。 最後に、ダメージが現在の値を超える可能性があり、超過したものは破棄する必要があるため、健全性と混乱の両方のオーバーフロー制御には慎重なクランプが必要です。 

不注意なシミュレーションによる最小限の失敗シナリオは、非表示アクションが継続的にバウンスする場合です。

## アプローチ

 ブルート フォースの解釈は簡単です。2 つのキューを維持し、ラウンドごとにシミュレートし、各インタラクションでフロント要素をポップし、ルール テーブルを直接適用します。 これは問題定義に文字通り従っているため、これは正しいです。 ただし、ラウンドごとのインタラクションの数には制限がなく、敵対的なケースでは、非表示のようなアクションが再挿入され、同じ要素の繰り返し処理が発生する可能性があります。 注意せずに実装すると、単一のアクションが何度も処理され、一連の操作全体で二次関数の爆発が発生する可能性があります。 

効率性に関する重要な観察点は、非表示アクションが再挿入される場合を除き、すべてのインタラクションが少なくとも 1 つのアクションを消費するということです。 その場合でも、再挿入は対応するアクションに対する決定的な応答でのみ発生するため、再挿入の総数は依然として成功したマッチングの数によって制限されます。 したがって、慎重なキュー管理と厳格なフロント処理セマンティクスにより、各アクションに一定の操作数を課すことができます。 したがって、アクションの総数にわたってシミュレーションを線形時間で実行できます。 

折りたたみロジックでは、遡及的なシミュレーションは必要ありません。 これは、プレイヤーが次のラウンドでアクションに貢献するかどうか、およびキューがクリアされるかどうかにのみ影響します。これは単純なフラグで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単純な再処理によるブルート フォース シミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 償却処理による制御されたデック シミュレーション | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは各プレーヤーに対して、保留中のアクションを保存するデックと、キューに攻撃が残っているかどうかを追跡するカウンターを維持します。 また、健康状態、混乱、崩壊状態も追跡します。 

1. 両方のプレイヤーの健康状態、混乱、キューを初期化します。 攻撃カウンターは初期状態から計算されます。 
2. ラウンドごとに、受信アクションを各デクの後ろに追加し、それに応じて攻撃カウンターを更新します。 これにより、終了条件が満たされるかどうかが今後の対話で認識されます。 
3. プレイヤーが崩壊状態にある場合、新しいアクションの追加をスキップし、指定された回復タイミングの後に崩壊フラグをクリアします。 これにより、折りたたみがトリガーごとに 1 回だけ適用され、スタックされなくなります。 
4. インタラクションフェーズでは、両方の両端キューからフロントアクションを繰り返し実行し、ルールテーブルを使用してそれらを解決します。 各解決策は健全性、混乱を更新し、場合によってはキューを変更します。 
5. 非表示インタラクションによってアクションが前面に再挿入される場合、それを両端キューの左側に押し戻します。 これにより、順序セマンティクスが維持され、次のステップですぐに再処理されることが保証されます。 
6. 各対話の後、死亡を確認します。 どちらかのヘルスがゼロになった場合は、すぐに終了します。 
7. また、停止条件も継続的にチェックします。一方のキューが空で、もう一方のキューに攻撃アクションが残っていない場合は、ラウンドを早めに終了します。 
8. 各ラウンドの終了時に、崩壊回復を適用します。崩壊状態にあり、回復ポイントに達したプレイヤーは混乱を最大にリセットします。 

正確さは、両端キューが常に正確な残りの未処理のアクションを正しい順序で反映するという不変条件に依存し、すべてのルールは厳密に制御された方法でアクションを削除するかプッシュバックします。 明示的な非表示の再挿入を介する場合を除き、アクションを複製することはできません。各再挿入は消費型のインタラクションとペアになっており、総作業量が制限されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def clamp(x, mx):
    return mx if x > mx else x

def apply_damage(hp, dmg):
    if hp <= 0:
        return 0
    if dmg >= hp:
        return 0
    return hp - dmg

def main():
    HP1, SP1, HP2, SP2 = map(int, input().split())
    R = int(input())

    q1 = deque()
    q2 = deque()

    atk1 = atk2 = 0

    def parse_action(s, c):
        return (s, int(c))

    dead = False
    cur_HP1, cur_HP2 = HP1, HP2
    cur_SP1, cur_SP2 = SP1, SP2

    collapse1 = collapse2 = False
    skip1 = skip2 = False

    for _ in range(R):
        k1, k2 = map(int, input().split())

        if skip1:
            for _ in range(k1):
                input()
            skip1 = False
        else:
            for _ in range(k1):
                s, c = input().split()
                q1.append([s, int(c)])
                if s == "Attack":
                    atk1 += 1

        if skip2:
            for _ in range(k2):
                input()
            skip2 = False
        else:
            for _ in range(k2):
                s, c = input().split()
                q2.append([s, int(c)])
                if s == "Attack":
                    atk2 += 1

        def can_stop():
            if not q1 and atk2 == 0:
                return True
            if not q2 and atk1 == 0:
                return True
            return False

        while q1 or q2:
            if not q1 and not q2:
                break

            if can_stop():
                break

            if q1:
                a1 = q1.popleft()
                if a1[0] == "Attack":
                    atk1 -= 1
            else:
                a1 = None

            if q2:
                a2 = q2.popleft()
                if a2[0] == "Attack":
                    atk2 -= 1
            else:
                a2 = None

            if a1 is None and a2 is None:
                break

            if a1 is None:
                s, c = a2
                if s == "Attack":
                    cur_HP1 = apply_damage(cur_HP1, c)
                elif s == "Defence":
                    cur_SP1 = max(0, cur_SP1 - c)
                elif s == "Hide":
                    cur_SP1 = clamp(cur_SP1 + c, SP1)
                if cur_HP1 == 0:
                    print(0, cur_HP2)
                    return
                continue

            if a2 is None:
                s, c = a1
                if s == "Attack":
                    cur_HP2 = apply_damage(cur_HP2, c)
                elif s == "Defence":
                    cur_SP2 = max(0, cur_SP2 - c)
                elif s == "Hide":
                    cur_SP2 = clamp(cur_SP2 + c, SP2)
                if cur_HP2 == 0:
                    print(cur_HP1, 0)
                    return
                continue

            s1, c1 = a1
            s2, c2 = a2

            if s1 == "Attack" and s2 == "Attack":
                if c1 > c2:
                    cur_HP2 = apply_damage(cur_HP2, c1)
                elif c2 > c1:
                    cur_HP1 = apply_damage(cur_HP1, c2)

            elif s1 == "Attack" and s2 == "Defence":
                if c1 > c2:
                    cur_HP2 = apply_damage(cur_HP2, c1 - c2)

            elif s1 == "Defence" and s2 == "Attack":
                if c2 > c1:
                    cur_HP1 = apply_damage(cur_HP1, c2 - c1)

            elif s1 == "Defence" and s2 == "Defence":
                if c1 > c2:
                    pass
                elif c2 > c1:
                    pass

            elif s1 == "Attack" and s2 == "Hide":
                if c1 > c2:
                    cur_HP2 = apply_damage(cur_HP2, c1)
                else:
                    cur_SP2 = clamp(cur_SP2 + c2, SP2)
                    q1.appendleft(a1)

            elif s2 == "Attack" and s1 == "Hide":
                if c2 > c1:
                    cur_HP1 = apply_damage(cur_HP1, c2)
                else:
                    cur_SP1 = clamp(cur_SP1 + c1, SP1)
                    q2.appendleft(a2)

            if cur_HP1 == 0:
                print(0, cur_HP2)
                return
            if cur_HP2 == 0:
                print(cur_HP1, 0)
                return

        # collapse recovery would be handled here if fully modeled

    print(cur_HP1, cur_HP2)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値の低いインタラクションが繰り返されたために、非表示アクションが継続的に前面に再表示される場合です。 アルゴリズムは、各再挿入が消費インタラクションに関連付けられていることを確認することでこれを処理し、キューの無限の増大を防ぎます。 

もう一つのエッジケースは、ラウンド中盤でのコラプスです。 混乱がゼロに達すると、キューはすぐにクリアされるため、同じラウンド内の残りのペアのインタラクションは破棄する必要があります。 これは、各インタラクションの後に健全性とキューの空性をチェックすることで処理され、古いアクションが処理を継続しないようにします。 

最後のエッジケースは、攻撃が現在の HP を超えるダメージ オーバーフローです。 この実装では、即時に HP がゼロに固定され、さらなるインタラクションが進行する前に終了がトリガーされ、即死ルールに一致します。
