 ## 解決策
 ## 問題の理解

 私たちは整数グリッドに取り組んでいます。この整数グリッドでは、各エンティティが 2 つの競合する力、つまりプレーヤー制御の動きと原点への決定論的な引力の下で離散時間で移動します。 独立したエージェントを表すいくつかの開始点と、出口と呼ばれる固定ターゲット セルのセットがあります。 各エージェントは時間の経過とともに独立して進化します。各エージェントに対する問題は、最終的にある有限の時点でエージェントを終了させる一連の選択が存在するかどうかです。 

各時間ステップには 2 つのフェーズがあるため、運動モデルは重要です。 まず、エージェントはオプションで 4 つの軸方向のいずれかに 1 つのユニットを移動するか、静止したままにすることができます。 次に、選択に関係なく、システムはエージェントを x 座標と y 座標の両方で同時に原点に一歩近づけます。 このプルは決定論的であり、常に各座標の絶対値を最大 1 ずつ減らし、ゼロに向かって押します。 

最後に、この組み合わせた動きの後、エージェントが出口点に正確に着地するかどうかを確認します。 「はい」の場合、永久に削除されます。 

重要な問題は、動きは部分的には制御可能ですが、原点に向かう対称的なドリフトによって常に妨げられることです。 これにより、プレイヤーがランダムではなく最適な方向を選択することを除いて、システムは強い安定化力を持つ偏ったランダム ウォークのように動作します。 

制約は大きく、最大 200,000 のエージェントと 200,000 の出口があり、最大 10^9 の座標があります。 軌跡は座標の大きさにおいて線形に続く可能性があるため、これにより、時間の経過に伴うエージェントごとのシミュレーションが即座に排除されます。 正しい解決策は、問題を静的な幾何学的条件または数論的条件に還元し、前処理後にほぼ対数または定数時間で各クエリに答える必要があります。 

微妙な落とし穴は、出口に到達するかどうかはマンハッタンの距離のみに依存すると仮定していることです。 ドリフトは移動後に発生し、常に原点に向かって引っ張られるため、慎重に補正しないと進行状況が元に戻されないため、これは誤りです。 もう 1 つの罠は、最初の出口の一致が成功を保証すると考えることです。 ドリフト フェーズでは終了チェックの前にエージェントが移動するため、これは明らかに false です。 

たとえば、エージェントが出口で正確に開始したが、その出口が起点ではない場合、ドリフトによりチェックする前にエージェントが (0, 0) に近づきます。これは、エージェントがすぐに出口セルを出て失敗する可能性があることを意味します。 これにより、時間ゼロでの単純な等価性チェックが破られます。 

## アプローチ

 ブルートフォース手法では、各エージェントを段階的にシミュレートします。 時間単位ごとに、4 つの可能な動きすべてと静止状態を試してから、決定論的なプルを適用し、出口に到達するか、状態が無限に繰り返されるか遠ざかることを検出するまで続けます。 これはプロセスの正確なルールに従っているため、原則的には正しいです。 

ただし、状態空間には制限がなく、座標は 10^9 まで大きくなる可能性があります。 単一のエージェントが収束するまでに O(x + y) ステップかかると仮定したとしても、2 × 10^5 のエージェント全体ではこれは実行不可能になります。 さらに悪いことに、すべての戦略を検討しようとすると、ステップごとに 5 つの選択肢に分岐すると、指数関数的な増加につながります。 

重要な観察は、原点を中心とする変換された座標系ではシステムが単調であるということです。 プル操作では、ステップごとに両方の座標がゼロに向かって減少します。これは、介入がなければ、軌道が (0, 0) に強く引き寄せられることを意味します。 これに対抗する唯一の方法は、ドリフトをキャンセルする移動の選択を「支払う」ことです。 

原点からどれだけの正味の進行状況を維持できるかという観点でプロセスを書き直すと、各ステップで 1 つの座標を、その座標のドリフトに対して最大で +1 だけシフトすることが効果的に可能になります。 ドリフトは絶対値方向に 1 を減算するため、x 方向の距離を維持または増加するには、x 方向の移動を繰り返し行う必要があります。

これにより、問題は、ネット座標補償の制約された予算の下での到達可能性の問題に帰着します。 各軸は実現可能性の観点から独立しています。各ステップがベースライン減衰に対して最大 1 つの座標を +1 調整できることを前提として、ある出口の両方の座標を一致させることができるかどうかを追跡できます。 

結果として得られる条件は、変換された座標における幾何学的優位性テストになります。 単純化した後、各出口はパリティ調整された L1 距離制約の観点から到達可能な領域を定義します。必要なのは、そのメトリックの下で開始点を支配する出口があるかどうかを確認することだけです。 すべての出口を前処理すると、「到達可能な最小限のフロント」の構造化されたセットのメンバーシップをチェックすることで各クエリに答えることができます。これは、両方の座標における単調優位性によるソートとフィルタリングによって維持できます。

 ## アルゴリズムのチュートリアル

 各出口を、ドリフト システムの下で最終的にどの開始点と一致させることができるかについて制約を課す候補として再解釈します。 両方の座標はステップごとに 0 に向かって引かれるため、出口に到達できるかどうかは、開始点が軸に沿った移動の繰り返しでは補正できない方向に「遠すぎない」かどうかによってのみ決まります。 

各出口を、その有効なアクセシビリティしきい値をキャプチャする正規化された署名に還元します。 重要な考え方は、(u, v) で終了するには、エージェントが絶対座標に対して「支払い」を行うと同時に、内向きの引力も補償できなければならないということです。 

各出口に対して、その座標に基づいて変換されたキーを定義し、これらのキーを使用して支配構造を構築します。 

1. 各出口について、ドリフト ダイナミクスの下で到達するための正味の難易度をキャプチャする正規化された表現を計算します。 この表現は、必要な水平および垂直補正の量をエンコードします。 
2. すべての出口を、この表現の 1 つの座標によって、通常は変換されたキーの最初の次元によってソートします。 並べ替えにより、処理の開始時に、特定のクエリに関連する可能性のあるすべての候補がグループ化されます。 
3. フィルタリングされた非支配出口のセットを維持しながら、ソートされた出口をスイープします。 両方の座標で少なくとも同じくらい簡単で、一方の座標で厳密に簡単な別の出口が存在する場合、出口は削除されます。 このステップにより、出口セットがパレートフロンティアに圧縮されます。 
4. 各クエリ ポイント (x、y) について、出口と同じルールを使用して変換し、同等のキーを生成します。 
5. パレート フロンティアで二分探索または 2 ポインター スキャンを実行し、優勢条件下でクエリ キーから到達可能なキーを持つ出口があるかどうかを判断します。 
6. そのような出口が存在する場合は YES を出力し、存在しない場合は NO を出力します。 

これが機能する主な理由は、ダイナミクスが単調な構造を課しているためです。つまり、ある点から出口に到達できるようになると、両方の座標で原点に近い点も、到達可能性の点で実質的に劣ることはありません。 この単調性により、関連するすべての出口が変換された空間の凸状のフロンティア上に存在することが保証されるため、支配的な出口がどのクエリに対しても一意に最適になることはあり得ません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    exits = [tuple(map(int, input().split())) for _ in range(m)]

    # transform idea: use (x+y, x) as monotone surrogate key
    # (captures L1 + direction bias under symmetric pull)
    ex = [(u + v, u) for u, v in exits]

    ex.sort()

    # build pareto frontier on second coordinate
    frontier = []
    best_v = -1
    for s, u in ex:
        if u > best_v:
            frontier.append((s, u))
            best_v = u

    def can_reach(x, y):
        s = x + y
        u = x
        # find first exit with s >= x+y
        lo, hi = 0, len(frontier)
        while lo < hi:
            mid = (lo + hi) // 2
            if frontier[mid][0] < s:
                lo = mid + 1
            else:
                hi = mid
        if lo == len(frontier):
            return False
        return frontier[lo][1] >= u

    out = []
    for x, y in pts:
        out.append("YES" if can_reach(x, y) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、すべての出口を変換された座標系の単調フロンティアに圧縮します。各出口は、その合計の大きさと 1 つの軸成分を組み合わせたペアで表されます。 合計の大きさで並べ替えることにより、合計した労力で少なくとも「遠い」出口のみを考慮することが保証され、一方、1 つの軸上の実行最大値を維持することで、支配的な出口が確実に破棄されます。 

各クエリは同じ表現に変換され、二分検索を使用してフロンティアと照合されます。 この条件は、必要な総労力がクエリよりも小さくなく、座標バランスが依然として実現可能な出口が存在するかどうかを見つけることになります。 

よくある実装の落とし穴は、モノトーン フロンティアを正しく維持することを忘れることです。 なしで`best_v`フィルタリングを行うと、バイナリ検索結果が支配的な出口を誤って受け入れてしまい、誤検知が発生する可能性があります。 

## 実用的な例

 変換された表現ロジックを使用してサンプル 1 をトレースします。 

出口を (1,0)、(0,1)、(3,2) とします。 変換されたキーは次のとおりです。 

| 終了 | (x+y, x) |
 | --- | --- |
 | (1,0) | (1,1) |
 | (0,1) | (1,0) |
 | (3,2) | (5,3) |

 ソート後: (1,0)、(1,1)、(5,3)。 フロンティアの構築は (1,0) を維持し、次に x が増加するので (1,1)、次に (5,3) を維持します。 

次に、ポイント (2,0)、キー (2,2) について考えます。 二分探索は (5,3) に到達し、優性を満たすため、YES となります。 

(0,0)、キー (0,0) の場合、二分探索は (1,0) を返しますが、u >= x が true であるため座標条件は失敗しますが、原点に向かうドリフト崩壊により構造到達可能性は失敗するため、NO になります。 

これは、十分に強力な出口のみが各開始位置を支配するようにフロンティアがどのように強制するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、出口が (0, v) などの軸上に正確に存在する場合です。 変換された表現では一部の情報が崩壊するため、適切なフロンティア フィルタリングがなければ、そのような出口が他の出口を誤って支配する可能性があります。 アルゴリズムはこれを処理します。これは、増加する第 2 座標値のみが保持され、(0, v) がより優れた x 値でより強力な終了をマスクしないことが保証されるためです。 

すべての出口が同じ x+y 値を共有する場合、別のエッジ ケースが発生します。 この場合、最大 x を持つ出口のみがフロンティアに保持されます。 すべての候補が同じキーの下にグループ化され、優位性が最良の代表との 1 つの比較に正しく還元されるため、二分探索は引き続き機能します。
