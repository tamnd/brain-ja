 ## 解決策
 ## 問題の理解

 括弧文字列があります。 ウォークは位置 1 から始まり、最終的に位置 1 で終了する必要があります。`n`。 あらゆる瞬間に、現在の位置に書かれた括弧を記録します。 任意に何度も左右に移動する可能性があるため、生成されるシーケンスは元の文字列よりもはるかに長くなる可能性があります。 

記録されたブラケット シーケンスが通常のブラケット シーケンス (RBS) であるウォークが存在する場合、文字列は _walkable_ と呼ばれます。 

各クエリの後、元の文字列の 1 文字が反転されます。 更新は永続的であり、更新のたびに、現在の文字列がウォーク可能かどうかを回答する必要があります。 

最初の課題は、どのような種類の文字列が歩きやすいのかを理解することです。 可能な経路が無限にあるため、歩行プロセスは複雑に見えます。 重要な観察は、ウォーク構造がエンドポイントと隣接する等号括弧の出現場所に驚くほど強力な制約を課していることです。 

制約は大きいです。 両方`n`そして`q`到達できる`2 · 10^5`。 更新のたびに線形のものを再計算するには、大まかに必要になります`4 · 10^10`最悪の場合の操作は完全に不可能です。 クエリごとにほぼ対数の作業が必要です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する`n = 1`。```
(
```または```
)
```同じ文字で開始および終了するため、ウォークでは空でない通常のブラケット シーケンスが生成されません。 答えはいつも`NO`。 

考慮する：```
()
```ここは歩くのが簡単です。 直接右に歩くと、`"()"`。 

ここで次のことを考えてみましょう。```

```左括弧と右括弧の数はバランスが取れていますが、最初に記録される文字は`')'`。 生成されたすべてのシーケンスは次から始まります`')'`, そのため、通常の括弧シーケンスは使用できません。 

より微妙な例は次のとおりです。```
(()(
```最初の文字は`'('`そして最後は`'('`。 通常の括弧シーケンスは次で終わる必要があります。`')'`、したがって、内部構造に関係なく、これは決して歩くことはできません。 

最も重要な隠れたケースは次のとおりです。```

```隣接する等号括弧があります。`"(( "`そして`"))"`。 単純なアプローチでは、カウントとエンドポイントのみをチェックする可能性がありますが、それだけでは十分ではありません。 等隣接ペアの位置によって、有効なウォークが存在するかどうかが決まります。 

## アプローチ

 ブルート フォース ビューでは、位置がグラフの頂点として扱われます。 ポジション 1 からポジションまでのすべての可能なウォークを特徴付けることを試みることができます。`n`、生成された括弧文字列を生成し、それらのいずれかが通常の括弧シーケンスであるかどうかを確認します。 

これでは絶望的だ。 小さな文字列であっても、左右に何度も任意に移動する可能性があるため、歩行の数は指数関数的に増加します。 制約を無視して直接状態空間を探索することはできません。 

画期的な進歩は、歩きやすい文字列の構造を理解することから生まれます。 

隣接する位置を見てみましょう。 隣接する 2 つの文字が異なる場合、その端を越えて移動すると 1 つの値が得られます。`'('`そして1つ`')'`ある順序で。 このようなエッジは無害です。 

問題となるのは隣接する等号括弧です。 

もし持っていれば```
((
```次に、どこかで「追加の」左括弧を取得します。 もし持っていれば```
))
```次に、どこかで「追加の」閉じ括弧を取得します。 

公式の解決策は、次の特性評価に依存しています。 

偶数の場合`n`、文字列は次の場合にのみウォーク可能です。 

1.`s[0] = '('`。 
2.`s[n-1] = ')'`。 
3. 最初の発生`"))"`が最後に出現した後に厳密に表示されます`"(("`。 

同様に、すべての`"(("`すべての左側になければなりません`"))"`。 

奇数の場合`n`、答えはいつも`NO`なぜなら、すべての通常の括弧シーケンスの長さは偶数である一方、すべてのウォーク長は次と同じパリティを持っているからです。`n`。 

この特徴付けにより、歩行の側面が完全に削除されます。 以下を維持するだけで済みます。 

1. 最初の文字が`'('`。 
2. 最後の文字が`')'`。 
3. 最大位置に含まれるかどうか`"(("`を含む最小位置より小さい`"))"`。 

フリップ後は、その位置に触れているペアのみが変更できます。 このような隣接するペアは最大でも 2 つあります。 これは、すべての場所の位置を維持することを示唆しています。`"(("`そしてすべて`"))"`順序付けされたセットで。 

次に、各クエリはいくつかの挿入/削除と一定数の極値設定クエリになります。

 ## アルゴリズムのチュートリアル

 1. もし`n`奇妙です、すべての答えはすぐにわかります`NO`。 

通常の括弧シーケンスはすべて偶数の長さを持ちます。 考えられるすべてのウォーク出力のパリティは固定されており、奇数長の文字列は決してウォーク可能ではありません。 
2. 現在の括弧文字列を可変配列に保持します。 
3. セットを維持する`open2`すべてのインデックスを含む`i`そのような`s[i]s[i+1] = "(("`。 

保存されるインデックスは、ペアの左側の位置です。 
4. セットを維持する`close2`すべてのインデックスを含む`i`そのような`s[i]s[i+1] = "))"`。 
5. クエリを処理する前に、すべての隣接するペアを 1 回スキャンし、両方のセットにデータを入力します。 
6. 位置決め時`p`反転され、ペアのみ`(p-1,p)`そして`(p,p+1)`変えることができる。 

まず、古いコントリビューションをセットから削除します。 
7. キャラクターを反転します。 
8. それらの同じ隣接ペアを再計算し、それらの新しい寄与を挿入します。 
9. クエリに答えるには、まずエンドポイントを確認します。 

必要です`s[0] = '('`そして`s[n-1] = ')'`。 
10. いずれかのエンドポイント条件が失敗した場合は、応答します`NO`。 
11. それ以外の場合、両方のセットが空でない場合は、次のように計算します。`max(open2)`そして`min(close2)`。 

文字列は次の場合にのみ有効です。`max(open2) < min(close2)`。 

1. セットの 1 つが空の場合、条件は自動的に成立します。 

競合するペアの順序はありません。 

### なぜ効果があるのか

 核となる定理は、偶数であるということです。`n`、ウォーカビリティは、順序付け条件を伴うエンドポイント条件と同等です。```
all "((" occur before all "))"
```あ`"(("`ペアは余剰の左括弧のソースのように動作しますが、`"))"`ペアは余剰の閉じ括弧のソースのように動作します。 有効なウォークは、すべての余剰オープニングがすべての余剰クロージングの前に出現するときに正確に構築できます。 

セットには、これらの余剰ペアが発生する場所が正確に保存されます。 最大の`"(("`位置と最小`"))"`順序付けプロパティがグローバルに保持されるかどうかをテストするには、position だけで十分です。 最大の場合`"(("`最小のものはまだ残っています`"))"`、その後は毎回`"(("`すべての前に嘘をつく`"))"`。 そうしないと、プロパティが侵害されます。 

反転は、反転された位置に接触する隣接するペアにのみ影響するため、これらのセットを動的に維持することは正確かつ効率的です。 

## Python ソリューション```python
import sys
from bisect import bisect_left, insort

input = sys.stdin.readline

class OrderedSet:
    def __init__(self):
        self.a = []

    def add(self, x):
        i = bisect_left(self.a, x)
        if i == len(self.a) or self.a[i] != x:
            self.a.insert(i, x)

    def discard(self, x):
        i = bisect_left(self.a, x)
        if i < len(self.a) and self.a[i] == x:
            self.a.pop(i)

    def __len__(self):
        return len(self.a)

    def min(self):
        return self.a[0]

    def max(self):
        return self.a[-1]

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    open2 = OrderedSet()
    close2 = OrderedSet()

    for i in range(n - 1):
        pair = s[i] + s[i + 1]
        if pair == "((":
            open2.add(i)
        elif pair == "))":
            close2.add(i)

    ans = []

    for _ in range(q):
        p = int(input()) - 1

        if n % 2 == 1:
            s[p] = ')' if s[p] == '(' else '('
            ans.append("NO")
            continue

        for i in (p - 1, p):
            if 0 <= i < n - 1:
                pair = s[i] + s[i + 1]
                if pair == "((":
                    open2.discard(i)
                elif pair == "))":
                    close2.discard(i)

        s[p] = ')' if s[p] == '(' else '('

        for i in (p - 1, p):
            if 0 <= i < n - 1:
                pair = s[i] + s[i + 1]
                if pair == "((":
                    open2.add(i)
                elif pair == "))":
                    close2.add(i)

        if s[0] != '(' or s[-1] != ')':
            ans.append("NO")
            continue

        if len(open2) and len(close2):
            ans.append("YES" if open2.max() < close2.min() else "NO")
        else:
            ans.append("YES")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```編集ロジックは実装に直接反映されます。`open2`すべての位置を保存します。`"(("`が発生し、`close2`すべての位置を保存します。`"))"`が発生します。 答えは、最初のセットの最大の要素と 2 番目のセットの最小の要素にのみ依存します。 

実装の重要な詳細は、反転された位置に接触するペアのみを更新することです。 他の隣接するペアは変更されないままであるため、他のものを変更するのは無駄な作業になります。 

もう 1 つの微妙な点は、奇数の処理です`n`。 答えはいつも`NO`ただし、文字列自体はクエリのたびに変更されます。 今後の更新は現在の状態に依存するため、答えがあらかじめ決まっている場合でもフリップを実行する必要があります。 

エンドポイント チェックは、セットを調べる前に実行する必要があります。 で始まる文字列`')'`またはで終わる`'('`ペアの順序に関係なく、歩くことはできません。

 ## 特殊なケース

 次のことを考慮してください。```
n = 3
s = ()(
```すべてのクエリが返されます`NO`。 

アルゴリズムは最初にパリティをチェックします。 以来`n`が奇数である場合、ペアの順序付け条件を評価しようとしません。 これは、すべての通常の括弧シーケンスの長さが均等であるという定理と一致します。 

考慮する：```
n = 4
s = )()(
```最初の文字は`')'`そして最後は`'('`。 

たとえ矛盾がなかったとしても`"(("`そして`"))"`有効な通常の括弧シーケンスは次で始まる必要があるため、アルゴリズムは直ちにその文字列を拒否します。`'('`そして次で終わります`')'`。 

考慮する：```
(())
```ここに次のものがあります:```
open2 = {1}
close2 = {2}
```そして```
max(open2) = 1
min(close2) = 2
```順序付け条件が成り立つので、答えは次のようになります。`YES`。 

ここでパターンを逆にします。```
))((
```それから：```
open2 = {2}
close2 = {0}
```そして```
max(open2) = 2
min(close2) = 0
```順序付け条件が満たされないため、答えは次のようになります。`NO`。 

これはまさに、セットベースのテストが検出するように設計された状況です。 エンドポイントが固定されると、余剰開始ペアと余剰終了ペアの相対的な順序によって、歩行可能性が完全に決まります。
