 ## 解決策
 ## 問題の理解

 クリスタルはイエローとブルーの2種類をご用意しております。 

各種類のボールの生産には、固定レシピのクリスタルが消費されます。 黄色のボールには黄色のクリスタルが 2 個必要です。 緑色のボールには黄色のクリスタルと青色のクリスタルが 1 つずつ必要です。 青いボールには青いクリスタルが 3 つ必要です。 

入力により、黄色のクリスタルの現在の在庫がわかります。`A`そして青い結晶`B`、続いて必要な数の黄色、緑、青のボールを入力します。`x`、`y`、 そして`z`。 

私たちの仕事は、要求されたすべてのボールを生産できるように、追加でクリスタルをいくつ購入する必要があるかを決定することです。 黄色と青色の両方のクリスタルを自由に購入できますが、追加のクリスタルの合計数は最小限に抑えたいと考えています。 

制約は次のとおりです$10^9$。 このような値は、ボールを 1 つずつ作成したり、クリスタルを繰り返し減算したりするシミュレーションを即座に除外します。 ボールの数に関する線形アルゴリズムであっても、遅すぎるでしょう。 入力は 5 つの整数のみで構成されているため、定数時間の算術解が期待できます。 

よくある間違いは、最初にクリスタルの合計必要量を計算するのではなく、ボールの種類ごとに不足分を個別に処理することです。 

考慮する：```
A = 2, B = 1
x = 1, y = 1, z = 0
```必要な黄色の結晶は、$2 \cdot 1 + 1 = 3$。 必要なブルークリスタルは、$1$。 

ちょうど 1 つの黄色のクリスタルが足りないので、答えは次のとおりです。`1`。 

各ボールのレシピを個別にチェックする不用意なアプローチは、不足を二重にカウントする可能性があります。 

もう 1 つの簡単な間違いは、合計必要量から利用可能なクリスタルを差し引き、マイナスの赤字が答えを減らすことを許可することです。 

例：```
A = 100, B = 0
x = 1, y = 0, z = 0
```必要な黄色のクリスタルは2つだけです。 余った 98 個の黄色のクリスタルは、他の状況で不足している青色のクリスタルを補うことはできません。 各色は個別に処理する必要があります。 ここでの正しい追加金額は、`0`、負の数ではありません。 

最後のエッジケースは、1 つの色が余剰で、もう 1 つの色が不足する場合に発生します。```
A = 10, B = 1
x = 0, y = 0, z = 1
```青いクリスタルが 3 つ必要ですが、持っているのは 1 つだけです。答えは次のとおりです。`2`黄色の結晶が豊富にあるにもかかわらず。 クリスタルの色は交換できません。 

## アプローチ

 最も直接的な考え方は、要求されたすべてのボールを 1 つずつ生産することを考えることです。 黄色のボールごとに黄色のクリスタルを 2 つ消費し、緑のボールごとに黄色のクリスタルと青のクリスタルを 1 つずつ、青いボールごとに青のクリスタルを 3 つ消費します。 クリスタルがなくなったら、さらに何個購入する必要があるかを数えます。 

このアプローチはレシピに正確に従っているため、正しいです。 問題は到達できるボールの数です。$10^9$。 各ボールをシミュレートするには数十億回の操作が必要ですが、制限時間内では不可能です。 

重要な観察は、生成の順序は重要ではないということです。 すべての黄色のボールは常に 2 つの黄色のクリスタルを消費します。 すべての緑のボールは常に黄色と青のクリスタルを 1 つずつ消費します。 すべての青いボールは常に 3 つの青いクリスタルを消費します。 

生産をシミュレートする代わりに、結晶の総要件を直接計算できます。 

必要な黄色のクリスタルの合計は次のとおりです。$$2x + y$$必要な青いクリスタルの合計は次のとおりです。$$y + 3z$$これらの合計が判明したら、それらを入手可能な供給量と比較します。 

必要な黄色の結晶が超過した場合`A`、その差額を買わなければなりません。 そうでなければ何も買わない。 同じ論理が青い結晶にも当てはまります。 

答えは単純に 2 つの不足分の合計です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(x + y + z) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 利用可能な黄色と青色のクリスタルを読み取ります。`A`そして`B`。 
2. 必要な数の黄、緑、青のボールを読み取り、`x`、`y`、 そして`z`。 
3. 必要な黄色の結晶の合計を次のように計算します。`2 * x + y`。 

すべての黄色のボールは 2 つの黄色のクリスタルを提供し、すべての緑色のボールは 1 つの黄色のクリスタルを提供します。 
4. 必要な青い結晶の合計を次のように計算します。`y + 3 * z`。 

すべての緑のボールは 1 つの青のクリスタルを提供し、すべての青のボールは 3 つの青のクリスタルを提供します。 
5. 黄色の不足分を次のように計算します。`max(0, needed_yellow - A)`。 

すでに十分な黄色のクリスタルがある場合、不足分はマイナスではなくゼロになるはずです。 
6. 青の不足分を次のように計算します。`max(0, needed_blue - B)`。 
7. 2 つの不足分の合計を出力します。 

### なぜ効果があるのか

 レシピは、要求されたボールごとに消費される黄色と青色のクリスタルの数を正確に決定します。 これらの寄与を追加すると、各結晶の色の固有の合計要件が得られます。 

黄色の結晶は黄色の要件のみを満たすことができ、青色の結晶は青色の要件のみを満たすことができます。 2 つの色は独立しているため、追加のクリスタルの最小数は、欠落している黄色のクリスタルと欠落している青のクリスタルの単純な合計になります。 一方の色が余っても、もう一方の色の不足を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())
    x, y, z = map(int, input().split())

    needed_yellow = 2 * x + y
    needed_blue = y + 3 * z

    answer = max(0, needed_yellow - A) + max(0, needed_blue - B)
    print(answer)

solve()
```The first two lines read the available crystal counts and the requested ball counts.

 変数`needed_yellow`そして`needed_blue`レシピから直接導出された合計クリスタル要件を保存します。 これにより、シミュレーションが回避されます。 

への呼び出し`max(0, ...)`重要です。 すでに十分な色の結晶がある場合、その色は答えに寄与しません。 ここで負の値を許可すると、誤って 1 色の余剰が合計を減らすことになります。 

Python の整数は 32 ビットの制限を超える値を自動的に処理しますが、固定サイズの整数を使用する言語であっても、最大の式はわずか数十億であり、64 ビット型に快適に適合します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    A, B = map(int, input().split())
    x, y, z = map(int, input().split())

    needed_yellow = 2 * x + y
    needed_blue = y + 3 * z

    return str(
        max(0, needed_yellow - A) +
        max(0, needed_blue - B)
    ) + "\n"

# provided sample
assert run("4 3\n2 1 1\n") == "2\n", "sample 1"

# minimum values
assert run("0 0\n0 0 0\n") == "0\n", "all zeros"

# only yellow shortage
assert run("1 100\n1 0 0\n") == "1\n", "need one more yellow crystal"

# only blue shortage
assert run("100 1\n0 0 1\n") == "2\n", "need two more blue crystals"

# large boundary values
assert run("1000000000 1000000000\n1000000000 1000000000 1000000000\n") == "4000000000\n", "large numbers"

# exactly enough crystals
assert run("5 4\n2 1 1\n") == "0\n", "perfect match"
