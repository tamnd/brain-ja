 ## 解決策
 ## 問題の理解

 非常に具体的な整数のセットを列挙し、その順序付きリストから特定の要素を選択するように求められます。 許可される数値は、その素因数がすべて指定された素数の固定された小さなセットから得られる数値です。 言い換えれば、有効な数値はすべて、指定された素数のみのべき乗の積として記述でき、因数分解に他の素数を使用することはできません。 

1 には素数がなく、この定義では常に有効であるため、シーケンスは 1 から始まる昇順に考慮されます。 タスクは、この無限増加シーケンスの k 番目の要素を見つけることです。 

制約は、解空間を強力に形成します。 許可される素数の数は最大 16 です。これにより、すべての値にわたって単純指数関数的に素数のすべてのサブセットを明示的に結合しようとするアプローチが除外されます。 ただし、素数自体の値は小さく、答えは最大でも 10^18 であることが保証されているため、すべての可能性を組み合わせて生成するのではなく、数値検索の観点から推論することができます。 隠れた構造は、シーケンスの長さが無限であるにもかかわらず、値がまばらで単調であるということです。 

微妙なエッジケースがシーケンスの開始直後に現れます。 数字の 1 を最初の要素として含める必要があります。 素数から直接生成を開始し、1 を無視する実装は、1 ずつずれます。 重複生成によって別の問題が発生します。 注意しないと、12 = 2^2 * 3 のような数値が複数の乗算パスによって生成される可能性があるため、順序を強制しない限り、素数を自由に並べ替える単純な DFS はオーバーカウントしてしまいます。 

## アプローチ

 直接的なアプローチは、最小ヒープを使用して昇順に数値を生成し、発見された数値に各素数を繰り返し乗算し、結果を押し戻すことです。 これは「醜い数字」を生成することに似ています。 これは k が小さい場合にうまく機能しますが、ここでは k のサイズに制限がなく、実際の答えの値が 10^18 以内に収まるにもかかわらず、k が非常に大きくなる可能性があります。 ヒープベースの方法では k 回の挿入と log k の操作が必要になりますが、k が大きい場合は実行不可能になります。 

重要な点は、実際にはインデックス k までのシーケンスを構築する必要がないということです。 どの値が k 番目に小さいかを判断するだけでよく、答えの値には厳密な制限が与えられます。 これは視点を逆転することを示唆しています。インデックスによってシーケンスを生成する代わりに、候補値をテストし、≤ x である有効な数値がいくつあるかを尋ねます。 これにより、問題が単調なカウント関数に変換され、答えに対する二分探索が可能になります。 

残りの困難は、有効な数値 ≤ x の数を効率的に計算することです。 n ≤ 16 であるため、素数に対して深さ優先の列挙を実行し、重複を避けるために非減少素数インデックスを強制しながら積を構築できます。 各状態は、現在の値に選択した素数を乗算し、積が制限内に留まる限り継続します。 これにより、有効な数値がそれぞれ 1 回だけ生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ヒープ生成 | O(k log k) | O(k) | 遅すぎる |
 | 二分探索 + DFS カウンティング | O(log V・S) | O(深さ) | 承認済み |

 ここで、V は最大 10^18、S は枝刈りの下で生成される状態の数です。 

## アルゴリズムのチュートリアル

 答えの値を二分探索し、カウント手順を使用して実現可能性をテストすることで問題を解決します。 

1. 関数を定義する`count(x)`これは、≤ x である有効な数値がいくつあるかを返します。 

この関数には、1 と、値が x を超えない指定された素数のすべての積が含まれます。 
2.実装する`count(x)`素数に対する深さ優先検索を使用します。 

値 1 から開始し、各ステップで現在のインデックス以上のインデックスを持つ素数を乗算します。 

この順序付けにより、素因数の異なる順列によって同じ数値が生成されることが防止されます。 
3. DFS では、現在の値が ≤ x である場合は常に、有効な数値としてカウントされます。 

次に、適格な素数を乗算して拡張を続け、積が x を超えると停止します。 
4. 1 ～ 10^18 の回答空間で二分検索を実行します。 

各中間点midについて、計算します`count(mid)`。 

カウントが少なくとも k であれば、答えは Mid 以下にあることがわかり、そうでない場合は Mid より上にあります。 
5. 二分探索が収束したら、その最小値を出力します。`count(value) ≥ k`。 

正確さはカウント関数の単調性にかかっています。x が増加すると、有効な数値 ≤ x のセットは増加するだけです。 

### なぜ効果があるのか

 すべての有効な数値は、指定された素数と非負の指数の積として一意の表現を持ちます。 現在のインデックス以降の素数のみを使用して乗算することを強制することで、各組み合わせが 1 回だけ構築されるようになります。 DFS は、制限内の有効な数値の空間を正確に探索し、二分探索では、しきい値と到達可能な数値のカウントの間の単調な関係を利用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

primes = []

def count_leq(x):
    n = len(primes)
    res = 0

    def dfs(i, val):
        nonlocal res
        res += 1
        for j in range(i, n):
            p = primes[j]
            if val > x // p:
                break
            dfs(j, val * p)

    dfs(0, 1)
    return res

def solve():
    global primes
    n = int(input())
    primes = list(map(int, input().split()))
    k = int(input())

    lo, hi = 1, 10**18

    while lo < hi:
        mid = (lo + hi) // 2
        if count_leq(mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```DFS は、各再帰呼び出しが有効な因数分解をもう 1 つの素因数で拡張することを表すように注意深く構造化されています。 分割チェック`val > x // p`オーバーフローを回避し、値が制限を超えて増加した場合でも積極的な枝刈りを続けます。 二分探索では、このカウント関数をラップして、k 番目の数値が出現する正確なしきい値を見つけます。 

よくある間違いは、DFS がすべてのレベルでインデックス 0 から再開できるようにすることです。これにより、同じ因数分解の順列が発生します。 制約`for j in range(i, n)`正規の順序付けを強制するものです。 

## 実用的な例

 素数を含むサンプルを考えてみましょう`[2, 3, 5]`そしてk = 7。 

DFS は構造の深さが増すにつれて数値を列挙しますが、概念的には有効な順序は次のとおりです。 

| ステップ | 現在の x | 新しい拡張 |
 | --- | --- | --- |
 | 1 | 1 | 2、3、5 |
 | 2 | 2 | 4、6、10 |
 | 3 | 3 | 6、9、15 |
 | 4 | 4 | 8、12、20 |

 構築ルールによる重複排除後のソート順序は次のようになります。 

1、2、3、4、5、6、8、...

 7 番目の要素は 8 で、出力と一致します。 

次に、素数を使用した小さなカスタム例を考えてみましょう。`[2, 3]`k = 5。 

| ステップ | 抽出された順序 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |
 | 4 | 4 |
 | 5 | 6 |

 結果は6です。 

このトレースは、DFS のインデックス増加制約により、製品がどのように分岐しても順序付けされ、一意性が保たれる様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log(10^18) · S) | 値の範囲にわたるバイナリ検索。各ステップでは、制限内ですべての有効な製品に対して DFS を実行します。 
| スペース | O(n) | 再帰の深さは素数の数と生成物連鎖の成長によって制限されます。 

到達可能な状態の数は、素数 ≥ 2 による各乗算がすぐに限界を超えるため、積の急速な増加によって制御され、DFS を管理可能に保ちます。 固定の 64 ビット範囲でのバイナリ検索と組み合わせることで、このソリューションは制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    primes = []

    def count_leq(x):
        n = len(primes)
        res = 0

        def dfs(i, val):
            nonlocal res
            res += 1
            for j in range(i, n):
                p = primes[j]
                if val > x // p:
                    break
                dfs(j, val * p)

        dfs(0, 1)
        return res

    def solve():
        nonlocal primes
        n = int(input())
        primes = list(map(int, input().split()))
        k = int(input())

        lo, hi = 1, 10**18
        while lo < hi:
            mid = (lo + hi) // 2
            if count_leq(mid) >= k:
                hi = mid
            else:
                lo = mid + 1
        return str(lo)

    return solve()

# power-heavy
assert run("2\n2 3\n10\n") == "12"

 ## 特殊なケース

 n = 1 の場合、シーケンスは単一の素数に 1 を加えた累乗になります。1 ではなく素数自体から列挙を開始する解はすべてのインデックスをシフトし、間違った結果を返します。 

k = 1 の場合、素数に関係なく、答えは常に 1 になります。 最初に生成される値が素数の 1 回の乗算から得られると実装が想定している場合、これは見逃されることがよくあります。 

k が大きくても値が急速に増大する場合、たとえ答えの大きさが小さくても、インデックスによる単純な生成はタイムアウトになります。 これはまさに、シーケンス構築の代わりに値空間に対する二分探索が必要になる状況です。
