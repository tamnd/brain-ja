 ## 解決策
 ## 問題の理解

 私たちは、_n_ 個のキャンディーの袋から最大 _k_ 個のキャンディーを選択して、グリシャが幸福を最大化するのを手伝ってください。それぞれに 1 から _n_ までの独自の美味しさがあります。 幸福度は通常の美味しさの合計ではなく、選択されたすべての美味しさにビットごとの XOR 演算子を適用した結果である XOR 合計です。 入力は 2 つの整数 _n_ と _k_ で構成され、_n_ は潜在的に以下と同じ大きさになります。$10^{18}$つまり、すべてのキャンディーまたはサブセットを明示的に列挙することはできません。 

出力は単一の整数、つまり _k_ 個以下のキャンディーを使用して取得できる最大の xor-sum です。 キャンディーのすべてのサブセットを試す単純な解決策は、サブセットの数が膨大であるため、明らかに不可能です。$2^n$これは、控えめな_n_でも天文学的な金額になります。 _n_ の大きな境界は、列挙ではなくビット単位のプロパティに依存する必要があることを示唆しています。 

明らかではないエッジ ケースには、_k_ が _n_ より小さいシナリオが含まれます。 たとえば、$n = 4$そして$k = 3$、すべてのキャンディーの xor 合計 (1、2、3、4) は 4 ですが、1、2、および 4 を選択すると 7 になります。常に最大の数値を取得する不用意なアプローチでは、誤って 2、3、4 が選択され、5 が生成されます。もう 1 つのエッジ ケースは、_k_ が 2 のべき乗または 2 のべき乗より 1 小さい場合です。 ソリューションでは、特定の位置までのすべてのビットを埋める数値と xor がどのように相互作用するかを考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチは、最大 _k_ のサイズのすべてのサブセットを生成し、それらの XOR 和を計算して、最大値を返すことです。 XOR は結合的で可換であるため、どのサブセットでも有効な合計が生成されるため、このアプローチは正確性を保つために機能します。 ただし、反復処理が必要です$O(2^n)$サブセット、ましてや小さな _n_ であっても実現不可能です$10^{18}$。 操作数は実際の制限時間を桁違いに超えてしまいます。 

重要な洞察は、数値の 2 進表現を調べることで得られます。 可能な限り各ビットが 1 に設定されると、一連の数値の XOR 合計が最大化されます。 1 から _n_ までの数値について、最大の XOR 合計は _n_ の最大ビット数によって決まります。具体的には、$2^{\lfloor \log_2 n \rfloor + 1} - 1$。 _k_ が、このパターンを達成するために必要なすべての数値を含めるのに十分な大きさであれば、答えは単純にこの最大パターンになります。 それ以外の場合、_k_ が制限されている場合は、最上位ビットを効率的にカバーするサブシーケンスを形成する数値を選択する必要がある場合があります。 シーケンス 1 から _n_ の構造により、特定のパターンで数値を選択することにより、最大の XOR を達成できます。つまり、2 のべき乗と、すべてのビット セットに到達するためにギャップを埋める数値です。 これは古典的なビットごとの構成的アプローチであり、どの数値がどのビットに寄与するかを分析することで解決策を導き出すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | お(1) | 遅すぎる |
 | 建設的なビットごと | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. _n_ 以下の最大の 2 の累乗 _p_ を計算します。 これは、選択したサブセットに設定できる最上位ビットを定義します。 最大 xor-sum を超えることはできません$2^{\text{bit length of n}} - 1$。 
2. _k_ が十分に大きい場合 (具体的には、_k_ が _p_ 以上の場合)、その最上位ビットまでのすべてのビットを埋めるパターンで数値を選択できます。 この場合、最大の xor-sum は次のようになります。$2^{\lceil \log_2(n+1) \rceil} - 1$。 
3. それ以外の場合、_k_ の制約により、貪欲に数値を選択して最上位ビットを最初に設定する必要があります。 最上位のビット位置から始めて、そのビットが設定されている数値を含めてみてください。 各包含は xor-sum のビットを反転し、_k_ 個の数値が選択されるまで続行します。 
4. 結果の xor-sum を返します。 

機能する理由: xor 演算は GF(2) に対して線形であり、シーケンス 1 から _n_ には、_n_ のビット長内で xor パターンを構築するために必要なすべての数値が含まれています。 常に残りの最大ビットを最初に設定しようとすることで、他の _k_ 数値を選択してもより高い xor 和が得られないことが保証されます。 貪欲なアプローチでは、_i_ 数値を選択した後、現在の xor-sum がサイズ _i_ のすべてのサブセットの中で可能な最大値を持つという不変条件が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_xor(n, k):
    # If k >= n, we can take all numbers
    if k >= n:
        # maximum xor of numbers 1..n is either n (if n is power of 2) or 2^(bit_length)-1
        l = n.bit_length()
        return (1 << l) - 1
    
    # Otherwise, we need to construct the xor maximally with <= k numbers
    ans = 0
    remaining = k
    for bit in reversed(range(n.bit_length())):
        mask = 1 << bit
        # How many numbers from 1..n have this bit set?
        full_cycles = n // (mask << 1)
        rem = n % (mask << 1)
        count = full_cycles * mask + max(0, rem - mask + 1)
        if count > 0 and remaining > 0:
            ans |= mask
            remaining -= 1
    return ans

def main():
    n, k = map(int, input().split())
    print(max_xor(n, k))

if __name__ == "__main__":
    main()
```このソリューションでは、まず _k_ がすべてのキャンディーを受け入れるのに十分な大きさかどうかを確認します。 そうである場合、_n_ までの完全なセットの xor を計算します。これは、_n_ の最上位ビットによって決まります。 それ以外の場合は、最上位ビットから最下位ビットまで反復処理されます。 ビットごとに、1.._n_ 内のこのビットが設定されている数値がいくつあるかを計算します。 少なくとも 1 つ存在し、まだピックが残っている場合は、応答にこのビットを設定し、残りのカウントをデクリメントします。 これにより、選択された各数値が xor-sum の新しいビットの設定に寄与することが保証されます。
