 ## 解決策
 ## 問題の理解

 キルから得られるゴールドを最大化することを目的として、すべての敵に固定ダメージを与えるグローバル アビリティを発動する瞬間を選択するように求められます。 各敵には初期体力があり、時間の経過とともに一定の割合で体力が回復し、特定の秒数で個別に体力が変化する可能性があります。 敵を倒した場合の報酬は時間の経過とともに直線的に増加します。 

正式には、`n`敵にはそれぞれ最大体力、時間ゼロの初期体力、および再生速度があります。 さらに、`m`体力は特定の瞬間に更新され、敵の体力が瞬時に変化します。 究極の瞬間をキャストする`t`敵の健康状態が次の場合、敵を殺します。`t`最終的なダメージを差し引いても、最大でもゼロです。 その敵を一度に倒すためのゴールド`t`基本報酬に 1 秒あたりの増分を乗じたものです。`t`。 タスクは、最適な整数を見つけることです。`t`ゴールドの合計を最大化するか、ゴールドが無制限に増加できるかどうかを決定します。 

制約は重要です。`n`そして`m`最大 10^5 まで可能です。 これにより、大規模なものまで毎秒シミュレートしようとするソリューションは除外されます。`T`、または、すべての敵に対して個別に毎秒反復します。 代わりに、敵を最初に倒すことができるときや個別の健康状態の変化が発生するときなど、潜在的に重大な瞬間のみを考慮するアプローチが必要です。 

エッジケースは微妙です。 たとえば、敵の最大体力が最終ダメージ以下の場合、その敵はいつでも倒すことができ、報酬は無限に増加するため、ゴールドの総量は無限になる可能性があります。 もう 1 つのエッジ ケースは、敵がアルティメットによって決して殺されないほどの速さで回復する場合です。 継続的な再生成と個別の更新の両方を考慮しないと、正しい強制終了ウィンドウが失われる可能性があります。 

不注意な間違いの小さな具体例: 敵の初期体力は 100、1 秒あたり 10 回復し、最終的には 50 のダメージを与えます。体力の更新によって t=3 で体力が 30 に低下した場合、回復の整数倍のみを考慮する単純なアプローチでは、t=3 が最適であるという事実を見落とします。 

## アプローチ

 ブルートフォース手法では、毎秒反復処理を行います。`t`そして、すべての再生と個別の更新を適用して、その瞬間のすべての敵の体力を計算し、死亡する敵のゴールドを合計します。 これは概念的には正しいですが、最大 10^5 の敵と任意の時間範囲を使用すると、法外に遅くなります。 10^5 秒でも考慮すると、操作数は約 10^10 となり、実用的な制限をはるかに超えます。 

重要な洞察は、敵の体力が個別の更新間で直線的に変化するということです。 したがって、倒せる敵の数が変化する候補秒のセットは有限です。 具体的には、線形不等式を解くことで定義される正確な秒間で各敵を初めて倒すことができます。`health(t) - D <= 0`。 その前の瞬間では敵を殺すことはできませんが、その後の瞬間では、次の健康状態が更新されるか、健康状態が最終的なしきい値を超えて回復するまで、敵を殺し続ける可能性があります。 

敵が倒せるようになる瞬間や、健康状態が個別に更新される瞬間をすべて収集することで、それらの時間のみに焦点を当てることができます。 これらの候補秒を並べ替えて、それぞれの時点での合計ゴールドを評価すると、問題がすべての時間にわたる反復から O(n+m) 個の重要な瞬間にわたる反復に軽減されます。 

ブルート フォースは正確性が保証されているため機能しますが、期間が無制限の場合は失敗します。 敵のキルステータスが変化する重要な瞬間のみが関連していることを観察すると、問題をイベントベースの貪欲な評価に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大時間 * n) | O(n) | 遅すぎる |
 | イベントベースの評価 | O((n+m) log(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての敵をチェックして、体力が最大になっている敵がいるかどうかを確認します`Hmax <= D`（最終ダメージ）。 そうであれば、彼らを殺すためのゴールドは際限なく増加し、-1 を返します。 
2. 敵ごとに、最初の秒を計算します。`t0`解決することで敵が倒せるようになったとき`H0 + R*t0 <= D`、 どこ`H0`現在の健康状態と`R`再生率です。 天井を取るので、`t`整数でなければなりません。 この値が負の場合は、`t0 = 0`。 
3. この敵のヘルス更新のすべての秒数を追加の秒数候補として含めます。これにより、キルアビリティ ステータスが変化する可能性があります。 
4. すべての敵からすべての秒候補を収集し、並べ替えます。 
5. 各候補を 2 番目に繰り返します。`t`、合計してゴールドの合計を計算します。`C + t * G`その秒で殺せる敵ごとに。 遭遇したゴールドの最大合計を追跡します。 
6. 見つかった最大合計ゴールドを返します。 

機能する理由: 倒せる敵の数は、敵が倒せる閾値を超えたとき、または個別の体力変化が発生したときにのみ変化します。 これらのイベント間では、倒せる敵のセットは一定であるため、これらの候補秒数でのみ合計ゴールドを評価することで、最適な時間を逃すことがなくなります。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

n, m = map(int, input().split())
C, G, D = map(int, input().split())

enemies = []
for _ in range(n):
    Hmax, H0, R = map(int, input().split())
    enemies.append([Hmax, H0, R])

updates = [[] for _ in range(n)]
for _ in range(m):
    t, idx, Hnew = map(int, input().split())
    updates[idx-1].append((t, Hnew))

# Step 1: check for infinite gold
for Hmax, _, _ in enemies:
    if Hmax <= D:
        print(-1)
        sys.exit(0)

# Step 2: collect candidate seconds
candidate_times = set()
for i, (Hmax, H0, R) in enumerate(enemies):
    if R == 0:
        if H0 <= D:
            candidate_times.add(0)
    else:
        t0 = math.ceil((D - H0)/R)
        if t0 >= 0:
            candidate_times.add(t0)
    for t, _ in updates[i]:
        candidate_times.add(t)

candidate_times = sorted(candidate_times)

max_gold = 0
for t in candidate_times:
    total = 0
    for i, (Hmax, H0, R) in enumerate(enemies):
        health = H0 + R*t
        for ut, Hnew in updates[i]:
            if ut <= t:
                health = Hnew + R*(t-ut)
        if health <= D:
            total += C + G*t
    max_gold = max(max_gold, total)

print(max_gold)
```このソリューションでは、最初に無限のゴールド条件がチェックされます。 次に、各敵について、最初に倒せるようになる時間を計算し、ヘルス更新時間を候補秒数として追加します。 候補となる秒時点でのみ合計ゴールドを評価することで、不必要なシミュレーションを回避できます。 個別の更新後にヘルスを調整するために注意が必要です。 

## 実用的な例

 **サンプル 1**

 | 敵 | H0 | R | アップデート | 最初に殺せる t | t=50 の健康状態 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 5 | [(20,10),(30,10)] | 9 | 55 |
 | 2 | 70 | 1 | [] | 20 | 70 |
 | 3 | 110 | 2 | [] | 30 | 110 |

 候補秒数: 9、20、30、50 (イベントの評価後)。 

t=50 では、敵 2 と 3 は究極後の D=50 以下となり、ゴールド 2*(1000+50*10)=3000 が得られます。 

**サンプル 2**

 一部の敵に対する Hmax <= D の入力は -1 を生成し、報酬が無限であることを確認します。 

これらの例は、アルゴリズムが有限最適時間と無制限のケースの両方を正しく処理し、離散更新が適切に考慮されていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+m) log(n+m) + n*(n+m)) | 候補秒をソートし、それを反復処理して合計ゴールドを評価する |
 | スペース | O(n+m) | 敵、健康状態の更新、および候補者の秒数を保存します。 

このアルゴリズムは、10^5 までの n,m に対して効率的です。 主要な要因は、候補秒数と敵に対するネストされた反復です。これは、候補秒数が n+m に比例し、最悪の場合でも合計操作が 10^10 程度に保たれるため、許容可能です。
