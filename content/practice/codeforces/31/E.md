 ## 解決策
 ## 問題の理解

 次の文字列が与えられます`2n`数字。 数字は厳密に左から右に処理されます。 各ステップで、Homer または Marge のいずれかが現在の左端の数字を取得し、それを自分の番号に追加します。 最後までに、両プレイヤーは正確にテイクをとったに違いありません`n`数字。 

最終的なスコアは、構築された 2 つの数値の合計です。 次を使用して、有効な一連の動きを 1 つ出力する必要があります。`H`そして`M`, この合計を最大化します。 

重要な点は、各プレーヤーの番号内の順序が固定されていることです。 ホーマーがポジションで数字を取る場合`i1 < i2 < ...`、その場合、彼の番号はまさにその順序の数字です。 マージも同様です。 

制約は動的プログラミングを可能にするのに十分小さいですが、すべての割り当てに対するブルート フォースが不可能なほど十分に大きいです。 以来`n ≤ 18`、合計桁数は最大です`36`。 プレーヤーへの数字の割り当てすべてを単純に検索すると、次のようになります。`2^(2n)`可能性。 最悪の場合こうなります`2^36`、約680億の州、2秒では完全に実行不可能です。 

同時に、`36 × 36 × 10^18`スタイルの算術演算はまったく問題ありません。 最後の数値自体は最大 18 桁であるため、64 ビット整数が必要です。 Python の整数はこれを自動的に処理します。 

いくつかの特殊なケースは、推論が正確でないと誤って処理されやすくなります。 

考慮する：```
1
09
```ホーマーが取るなら`0`そしてマージは`9`、合計は`0 + 9 = 9`。 

ホーマーが取るなら`9`そしてマージは`0`、合計は`9 + 0 = 9`。 

先頭のゼロは正当であるため、構築された文字列を無効な数値として扱うことはできません。 

別の微妙なケースは次のとおりです。```
2
9090
```より小さい現在値を持つプレイヤーに現在の桁を常に与えるという貪欲な戦略は失敗する可能性があります。これは、前の桁の方が重要であるためです。 先に数字を割り当てると、後の数字を割り当てるよりも上位の小数点以下の桁が変更されます。 

もう 1 つの重要なシナリオは次のとおりです。```
2
1234
```Homer が最初の 2 桁を取り、Marge が最後の 2 桁を取ると、次のようになります。`12 + 34 = 46`。 

しかし、交互に行うと次のようになります。`13 + 24 = 37`各プレーヤーの番号内の位置は、絶対的な数字そのものよりも重要です。 数字が早く配置されると、10 の累乗が大きくなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 それぞれについて、`2n`ポジションを決定し、両方が正確に受信できるようにしながら、数字がホーマーに行くかマージに行くかを決定します。`n`数字。 

割り当てが修正されたら、両方の数値を作成し、それらの合計を計算できます。 有効な割り当ての数は次のとおりです。$$\binom{2n}{n}$$のために`n = 18`、これは次のとおりです。$$\binom{36}{18} \approx 9 \times 10^9$$それらの状態のほんの一部をチェックすることさえ不可能です。 

ブルート フォースが概念的に機能する理由は、すべての有効なシーケンスが最終的な数値を一意に決定するためです。 問題は純粋に組み合わせの爆発です。 

重要な観察は、数字の寄与は次の 2 つのことだけに依存するということです。 

まず、どのプレイヤーがそれを受け取るかです。 

次に、プレイヤーがその後も受け取る桁数。 

ホーマーがすでに取っていると仮定してください`h`位置の前の桁`i`。 その後、現在の桁は次のようになります。`(h+1)`ホーマー数の - 桁目。 ホーマーは正確に終わるので`n`数字の場合、この数字は以下に寄与します。$$digit \times 10^{n-h-1}$$今後の決定によってこのポジションの重みが変わることはありません。 

つまり、左から右に数字を処理し、ホーマーがすでに取得した数字の数について動的プログラミングを使用できることを意味します。 

位置で`i`、マージが自動的に取得しました`i-h`数字。 

したがって、状態全体は単一のパラメータによって決定されます。$$dp[i][h]$$最初の処理後に取得できる最大合計値を意味します。`i`ホーマーが正確に取得した数字`h`彼らのうち。 

この状態から、次のことを試します。 

1. 次の数字をホーマーに渡します。 
2. 次の数字をマージに渡します。 

各遷移により、既知の寄与が即座に追加されます。 

州の総数はわずか約`36 × 18`、瞬時に計算できるほど小さい。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(2n)) | O(2^(2n)) | 遅すぎる |
 | 最適なDP | O(n²) | O(n²) | 承認済み |

### なぜ効果があるのか

 どのプレーヤーがそれを受け取るか、そしてそのプレーヤーの番号内のどの位置を占めるかがわかれば、すべての数字は独立して貢献します。 

数字を左から右に処理する場合、Homer の番号内の位置は、Homer が既に取得した桁数によって完全に決定されます。 マージも同様です。 

したがって、国家からの将来の結果はすべて、次のものにのみ依存します。 

1. 処理された桁数。 
2. ホーマーはそのうちの何匹を奪ったか。 

DP は、すべての有効な割り当てを 1 回だけ調査し、各状態で達成可能な最良の合計を計算します。 遷移では現在の桁の正確な 10 進数の寄与が加算されるため、最終値は構築された 2 つの数値の真の合計に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -(10**30)

def solve():
    n = int(input())
    s = input().strip()

    total = 2 * n

    pow10 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow10[i] = pow10[i - 1] * 10

    dp = [[INF] * (n + 1) for _ in range(total + 1)]
    parent = [[None] * (n + 1) for _ in range(total + 1)]

    dp[0][0] = 0

    for i in range(total):
        digit = int(s[i])

        for h in range(n + 1):
            if dp[i][h] == INF:
                continue

            m = i - h

            # Give digit to Homer
            if h < n:
                add = digit * pow10[n - h - 1]
                val = dp[i][h] + add

                if val > dp[i + 1][h + 1]:
                    dp[i + 1][h + 1] = val
                    parent[i + 1][h + 1] = (i, h, 'H')

            # Give digit to Marge
            if m < n:
                add = digit * pow10[n - m - 1]
                val = dp[i][h] + add

                if val > dp[i + 1][h]:
                    dp[i + 1][h] = val
                    parent[i + 1][h] = (i, h, 'M')

    ans = []

    i = total
    h = n

    while i > 0:
        pi, ph, ch = parent[i][h]
        ans.append(ch)
        i, h = pi, ph

    ans.reverse()

    print("".join(ans))

solve()
```DP テーブルには、Homer に割り当てられたすべてのプレフィックス長とすべての可能な桁数について、達成可能な最良の合計が格納されます。 

移行ロジックはソリューションの中核です。 数字が割り当てられると、その正確な位置の重みがすぐにわかります。 たとえば、ホーマーがすでに取得している場合`h`桁を増やすと、現在の桁がその番号の次の桁になり、次のようになります。```
digit × 10^(n-h-1)
```その後の決定によってこの貢献を変更することはできません。 

この問題では最大スコアだけでなく、一連の動きも要求されるため、親テーブルが必要です。 各親エントリは以下を記録します。 

1. 以前の状態。 
2. どのプレイヤーが数字を受け取ったか。 

微妙な詳細の 1 つは、マージの桁数の計算です。```
m = i - h
```これは機能します。`i`数字は処理されており、`h`彼らのうちはホメロスのもとへ行きました。 

もう 1 つの簡単な間違いは、先頭のゼロが有効であることを忘れることです。 数字は純粋に位置寄与として扱われるため、DP はそれらを自然に処理します。 

値の範囲は 32 ビット整数を超えることができます。 Python の整数はオーバーフローを自動的に回避します。
