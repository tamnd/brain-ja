 ## 解決策
 ## 問題の理解

 区切り文字なしで連結された複数の電子メール アドレスを表す 1 つの文字列が与えられます。 各メールアドレスにはフォームがあります`A@B`、 どこ`A`そして`B`小文字のラテン文字で構成される空ではない文字列です。 私たちのタスクは、文字列を一連の有効な電子メール アドレスに分割することです。 これを行う方法がない場合は、出力する必要があります`No solution`。 有効な分割が複数存在する場合は、どれでも受け入れられます。 

重要な問題は、元の文字列には繰り返しのアドレスまたは任意の長さのアドレスが含まれている可能性があり、元の境界について他に手がかりがないことです。 最初の段階でやみくもに分割することはできません`@`なぜならその後の`@`文字は次のメールに含まれる可能性があります。 文字列の長さは最大 200 文字と小さいため、およそ 2 次の複雑さのソリューションが可能になります。 これにより、指数関数的な数の分割をチェックする必要があるアプローチが除外されます。 

入力に ​​1 つだけが含まれる場合、微妙なエッジ ケースが発生します。`@`、または複数の`@`記号が連続して現れます。 例えば、`a@a@a`次のように分割できます`a@a,a@a`またはとして`a@aa@a`。 素朴な貪欲なアプローチでは、ローカル部分に誤って少なすぎる文字を割り当てる可能性があります`A`またはドメイン部分に多すぎます`B`、無効なアドレスが生成されるか、有効な分割が欠落します。 同様に、文字列が次で始まるか終わる場合、`@`、それは両方ともすぐに不可能です`A`そして`B`空であってはなりません。 

## アプローチ

 ブルートフォースアプローチは、すべてのアドレスに 1 つがあるというルールを維持する位置で文字列を分割するあらゆる可能な方法を試みることです。`@`空でないものを区切る`A`そして`B`。 ある長さの文字列の場合`n`、 がある`2^(n-1)`文字のペアごとに分割することを考慮した場合の分割の可能性。 これはすぐに実行不可能になります`n=20`組み合わせの数が指数関数的に増加するためです。 

問題を単純化する主な観察点は、各電子メール アドレスには ** 正確に 1 つが含まれている必要があるということです。`@`** であり、アドレスの先頭または末尾に指定することはできません。 この構造により、左から右へ貪欲な構築が可能になります。 最初のものを特定したら`@`現在の文字列の先頭以降は、それまでのすべてを処理できます。`@`ローカル部分として。 ドメイン部分には **少なくとも 1 文字** を使用する必要があります。追加の文字がある場合は、`@`記号以降の場合、次のアドレスは現在のドメインの最初の文字の次の文字から始まります。 これにより、文字列を効率的に消費しながら常に有効なアドレスを生成できるようになります。 

事実上、このアルゴリズムは常に最初の分割の直後に分割することで機能します。`@`未処理のサフィックスで検出され、ドメインに少なくとも 1 文字が残されています。 このアプローチは、次の数において線形です。`@`記号を使用でき、入力サイズが小さいため安全です。

 | --- | --- | --- | --- |

 | 貪欲な分割`@`| O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の先頭から開始して、最初の文字列を探します。`@`シンボル。 無い場合は返却`No solution`すぐに。 文字列には少なくとも 1 つが含まれている必要があります`@`有効な電子メールを作成します。 
2. これより前のすべての文字を処理します`@`ローカル部分として`A`。 この部分が空の場合、解決は不可能です。 
3. 1 文字前に移動します`@`ドメイン部分を開始するには`B`。 ドメインも空であってはなりません。 次だったら`@`現在残っている文字列の最後の文字の前に発生し、それまでのすべての文字を割り当てます`@`現在のドメインとして。 それ以外の場合は、残りのすべての文字を最後のアドレスのドメインとして割り当てます。 
4. 抽出したアドレスを追加します`A@B`回答リストに追加します。 
5. 現在のドメインの末尾の次の文字から文字列の末尾までこのプロセスを繰り返します。 
6. いずれかの時点でドメインまたはローカル部分が空の場合は、停止して出力します。`No solution`。 それ以外の場合は、収集したアドレスをカンマで結合して結果を出力します。 

機能する理由: 各分割では、ローカル部分が空ではないこと、およびドメイン部分が少なくとも 1 文字を消費することが保証されます。 最初に可能なものを貪欲に割り当てることで、`@`残りは後続のアドレスに残しておくため、重複したアドレスや無効なアドレスが生成されることはなく、最終的には文字列全体が消費されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

if s.count('@') == 0:
    print("No solution")
    sys.exit()

res = []
i = 0
while i < n:
    # find the next '@'
    at_pos = s.find('@', i)
    if at_pos == -1 or at_pos == i or at_pos == n - 1:
        print("No solution")
        sys.exit()
    
    # local part is from i to at_pos - 1
    local = s[i:at_pos]
    
    # domain must take at least one character
    j = at_pos + 1
    # the next '@' determines the end of the current domain
    next_at = s.find('@', j)
    if next_at == -1:
        # last address takes all remaining characters
        domain = s[j:]
        i = n
    else:
        # leave at least one char for the next local part
        domain = s[j:next_at]
        if not domain:
            print("No solution")
            sys.exit()
        i = next_at - 1
    res.append(f"{local}@{domain}")

print(",".join(res))
```コードは文字列を読み取り、インデックスを初期化します。`i`。 それは次を見つけます`@`そして、ローカル部分とドメイン部分を慎重に切り出します。 ドメインが空の場合、または無効なドメインが発生した場合`@`配置したら、次で終了します`No solution`。 それ以外の場合は、アドレスをカンマで結合します。 最も注意が必要な部分は、ドメインを分割するときに次のアドレスに少なくとも 1 文字を残すことです。

 ## 特殊なケース

 文字列が次で始まるエッジケース`@`扱われるため、`at_pos == i`トリガー`No solution`。 のために`abc@`、ドメインは空であるため、アルゴリズムは正しく終了します。 複数の文字列の場合`@`のような`a@b@c@d`、貪欲なアプローチでは、各ドメインに少なくとも 1 つの文字が正しく割り当てられ、ポインタが前方に移動し、次のような有効な分割が生成されます。`a@b,c@d`。 

これは、アルゴリズムが空ではないローカル部分およびドメイン部分の不変条件を体系的に尊重し、未処理の文字を決して残さないことを確認します。
