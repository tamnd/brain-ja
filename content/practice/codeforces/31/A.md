 ## 解決策
 ## 問題の理解

 ワームの長さの配列が与えられます。 各位置は異なる線虫の形態を表しており、1 つのインデックスの長さが他の 2 つのインデックスの長さの合計と等しくなるように、3 つの異なるインデックスを見つける必要があります。 

より具体的には、インデックスが必要です`i`、`j`、 そして`k`どこ：```
a[i] = a[j] + a[k]
```インデックスはすべて異なる必要がありますが、値自体は繰り返すことができます。 たとえば、配列に値を持つ 2 つの異なる位置が含まれている場合、`2`、両方とも方程式に参加できます。 

入力サイズは非常に小さいです。 ワームの形態の数は最大で`100`、それぞれの長さは最大です`1000`。 と`n = 100`、たとえ`O(n^3)`このアルゴリズムは約 100 万回のチェックのみを実行しますが、これは Python の 2 秒の制限内であれば完全に安全です。 これにより、問題に対する私たちの考え方が変わります。 高度なデータ構造や最適化は必要ありません。 直接実装はすでに十分に高速です。 

難しいのはパフォーマンスではなく、個別のインデックスに関する正確さです。 

次の例を考えてみましょう。```
3
2 1 1
```正しい答えは次のとおりです。```
1 2 3
```値のみを使用した不注意な実装は、誤って同じものを再利用する可能性があります。`1`同じ位置から２回。 この問題では、等しい値は許容されますが、等しいインデックスは許容されません。 3 つの位置がすべて異なることを明示的に確認する必要があります。 

もう 1 つの簡単な間違いは、重複した値が存在する場合に発生します。```
4
4 2 2 1
```有効な答えは次のとおりです。```
1 2 3
```ここ`4 = 2 + 2`、そして二人`2`はさまざまなインデックスから来ています。 ハッシュ マップ内の値ごとに 1 つのインデックスのみを格納する実装では、解決策が存在しないと誤って結論付ける可能性があります。 

有効なトリプルが存在しない場合もあります。```
5
1 2 4 8 16
```他の 2 つの要素の合計に等しい要素はないため、出力は次のようになります。`-1`。 プログラムがあまりにも早く停止したり、何らかの解決策が常に存在すると仮定したりすると、ここで失敗します。 

## アプローチ

 最も直接的なアイデアはブルートフォースです。 個別のインデックスの順序付けられたトリプルをすべて試すことができます`(i, j, k)`そして、次のことを確認してください。```
a[i] == a[j] + a[k]
```制約が小さいため、これは機能します。 と`n = 100`、トリプルの最大数は次のとおりです。```
100 × 100 × 100 = 1,000,000
```Python では、100 万回の単純な整数の加算と比較は簡単です。 

強引な方法も推論が簡単です。 考えられるすべての有効なインデックスの組み合わせを明示的にチェックするため、解決策を見逃すことはありません。 有効なトリプルが存在する場合、反復の 1 つでそのトリプルに遭遇します。 

それを改善する方法についてはまだ考えることができます。 繰り返される作業は、3 つのインデックスすべてを個別にチェックすることから始まります。 2 つのインデックスを修正したら`j`そして`k`、目標値`a[j] + a[k]`すぐに知られるようになる。 可能な限りすべてをスキャンするのではなく、`i`を使用すると、値からインデックスまでのマップに値を格納し、合計が存在するかどうかを調べることができます。 

それは、`O(n^2)`解決。 すべてのペアについて`(j, k)`、次のように計算します。```
target = a[j] + a[k]
```次に、次のことを確認します。`target`配列内の別の場所の別のインデックスに存在します。 

これが機能するのは、この問題では和の関係が求められており、配列全体を繰り返しスキャンするよりも値による検索の方がはるかに安価であるためです。 

それでも`O(n^3)`すでに快適に過ぎていますが、`O(n^2)`バージョンはよりクリーンで、問題の根本的な構造を示しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 承認済み |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ワームの長さの配列を読み取ります。 
2. 各値を、それが出現するすべてのインデックスにマップするディクショナリを構築します。 

重複した値が重要であるため、1 つだけではなくすべてのインデックスを保存します。 例えば、`4 = 2 + 2`以下を含む 2 つの異なる位置が必要です`2`。 
3. すべてのインデックスのペアを反復処理します。`(j, k)`。 

これらは、長さを加算している 2 つのワームを表しています。 
4. ペアをスキップする場合`j == k`。 

The problem requires three distinct forms, so the same index cannot be reused.
 5. 以下を計算します。```
target = a[j] + a[k]
```6.次のことを確認します。`target`辞書に存在します。 

存在しない場合は無効です`i`このペアの方程式を満たすことができます。 
7. ストアドインデックスごとに`i`に対応する`target`、それを確認してください`i`、`j`、 そして`k`はすべて異なります。 

これにより、同じ配列位置が複数回参加する無効なケースが回避されます。 
8. 有効なトリプルが見つかるとすぐに、1 から始まる形式でインデックスを出力して終了します。 
9. 解決策が見つからずにすべてのペアが使い果たされた場合は、次のように出力します。`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての加数のペアを体系的に検査します。`(j, k)`。 各ペアについて、必要な正確な値を計算します。`a[i]`。 辞書は、そのような値が配列内のどこかに存在する場合、一致するすべての位置をすぐに見つけることができることを保証します。 

すべての有効なペアがチェックされ、すべての一致するインデックスの区別性が検証されるため、アルゴリズムは正しい答えを見逃すことはなく、無効な答えを出力することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    positions = {}

    for i, value in enumerate(a):
        if value not in positions:
            positions[value] = []
        positions[value].append(i)

    for j in range(n):
        for k in range(n):
            if j == k:
                continue

            target = a[j] + a[k]

            if target not in positions:
                continue

            for i in positions[target]:
                if i != j and i != k:
                    print(i + 1, j + 1, k + 1)
                    return

    print(-1)

solve()
```コードの最初の部分では、という辞書を構築します。`positions`。 各キーはワームの長さであり、値はその長さが表示されるすべてのインデックスのリストです。 

リストの使用は実装の重要な詳細です。 値ごとにインデックスを 1 つだけ保存した場合、次のようなケースが考えられます。`4 = 2 + 2`両方とも失敗する可能性があります`2`は異なる立場から来なければなりません。 

ネストされたループは、順序付けされたすべてのペアを列挙します。`(j, k)`。 この問題では任意の有効な答えが許容されるため、順序付きペアは許容されます。 ケースはスキップします`j == k`同じワームフォームを二度使用することはできないため、すぐに使用できます。 

各ペアについて、必要なターゲット値を計算し、それが辞書に存在するかどうかを確認します。 存在する場合は、すべての候補インデックスを反復処理します。`i`その値が含まれているもの。 

最終条件:```
if i != j and i != k:
```3 つのインデックスがすべて異なることを保証します。 

出力は次を使用します`+1`Codeforces の配列にはインデックスが付けられているため、`1`、一方、Python は`0`-ベースのインデックスを内部的に作成します。 

## 実用的な例

 ### 例 1

 入力:```
5
1 2 3 5 7
```トレース:

 | j | k | a[j] | a[k] | ターゲット | マッチングインデックス | 有効なトリプル |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 2 | 3 | [2] | はい |

 アルゴリズムは次のものを即座に見つけます。```
a[2] = 3
a[0] + a[1] = 1 + 2 = 3
```したがって、次のように出力されます。```
3 1 2
```方程式を満たすあらゆる置換が受け入れられます。 

このトレースは、中心となる検索のアイデアを示しています。 ペアになったら`(1, 2)`が固定されている場合、必要な値は確定的になります。 

### 例 2

 入力:```
4
4 2 2 1
```トレース:

 | j | k | a[j] | a[k] | ターゲット | マッチングインデックス | 有効なトリプル |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 2 | 4 | [0] | はい |

 アルゴリズムは次のことを検出します。```
4 = 2 + 2
```インデックスを使用する`1`、`2`、 そして`0`。 

出力：```
1 2 3
```この例は、すべてのインデックスを保存することが重要である理由を示しています。 二人`2`は、値が同じであっても、異なる位置から来ています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | すべての順序付きインデックスのペアを調べます。 
| スペース | O(n) | 辞書にはすべての配列インデックスが格納されます。 

と`n ≤ 100`、三次解でも十分高速です。 二次解はほぼ瞬時に実行され、メモリの使用量はごくわずかです。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    positions = {}

    for i, value in enumerate(a):
        if value not in positions:
            positions[value] = []
        positions[value].append(i)

    for j in range(n):
        for k in range(n):
            if j == k:
                continue

            target = a[j] + a[k]

            if target not in positions:
                continue

            for i in positions[target]:
                if i != j and i != k:
                    print(i + 1, j + 1, k + 1)
                    return

    print(-1)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("5\n1 2 3 5 7\n") in {
    "3 1 2",
    "3 2 1"
}, "sample 1"

# minimum size with solution
assert run("3\n2 1 1\n") in {
    "1 2 3",
    "1 3 2"
}, "minimum size"

# no valid triple
assert run("5\n1 2 4 8 16\n") == "-1", "no solution"

# duplicate values
assert run("4\n4 2 2 1\n") in {
    "1 2 3",
    "1 3 2"
}, "duplicate values"

# all equal values
assert run("5\n5 5 5 5 5\n") == "-1", "all equal without valid sum"

# boundary style case
large_case = "100\n" + " ".join(map(str, range(1, 101))) + "\n"
assert run(large_case) != "", "maximum n"

 | --- | --- | --- |

 |`4 / 4 2 2 1`| 有効なトリプル | 異なるインデックスを持つ重複した値 |

## 特殊なケース

 次の入力を考えてみましょう。```
3
2 1 1
```アルゴリズムは以下を保存します。```
2 -> [0]
1 -> [1, 2]
```指数を調べるとき`(1, 2)`、ターゲットは`2`。 辞書検索はインデックスを返します`0`、これは両方の加数インデックスとは異なります。 アルゴリズムは次を出力します。```
1 2 3
```このケースでは、インデックスが異なる限り、等しい値が許可されることが確認されています。 

ここで次のことを考えてみましょう。```
4
4 2 2 1
```辞書は次のようになります。```
4 -> [0]
2 -> [1, 2]
1 -> [3]
```のために`(1, 2)`、ターゲットは`4`。 アルゴリズムはインデックスを取得します`0`すべてのインデックスが異なることを検証します。 

各値の出現を 1 つだけ保存するバグのある実装では、特に合計に重複が必要な場合に、この構造が誤って処理される可能性があります。 

最後に、解決策がないケースを考えてみましょう。```
5
1 2 4 8 16
```すべてのペアの合計がチェックされます。```
1 + 2 = 3
1 + 4 = 5
2 + 4 = 6
...
```これらの値はいずれも配列内に存在しません。 ループは戻らずに終了するため、アルゴリズムは次のように正しく出力します。```
-1
```これは、アルゴリズムが解決策の存在を想定しておらず、すべての可能性を徹底的に検証していることを確認します。
