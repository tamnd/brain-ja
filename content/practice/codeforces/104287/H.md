 ## 解決策
 ## 問題の理解

 私たちは高さの完全な二分木を扱っています。$d$。 ツリーには標準のヒープ スタイルの方法でラベルが付けられます: ノード$1$はルートであり、すべてのノードです$u$子供がいる$2u$そして$2u+1$それらが存在する限り。 ツリーがいっぱいなので、すべてのレベルが$0$に$d-1$完全に埋められているため、ノードの総数は次のようになります。$n = 2^d - 1$。 

タスクは、順序付けされたノードのすべてのペア間の距離の合計を計算することです。 すべてのペアについて$(i, j)$、それらの間の一意のパス上のエッジの数を測定し、これを全体で合計します。$n^2$注文したペア。 

制約は非常に大きいです。$d$まで可能です$10^5$これは、ノードの数が天文学的に多く、明示的に構築できないことを意味します。 ノードの反復やレベルの明示的な保存に依存する解決策は不可能です。 平$O(n)$ここでは無意味なので、$n = 2^{100000} - 1$。 

重要な意味は、答えは純粋に次の関数として表現可能でなければならないということです。$d$、明示的なトラバーサルではなく、完全なバイナリ ツリーの構造特性を使用します。 

単純なアプローチでは、すべてのノードからの BFS によって、またはすべてのペアごとの LCA クエリを前処理することによって距離を計算しようとします。 アイデンティティを利用しても$$dist(u, v) = depth(u) + depth(v) - 2 \cdot depth(lca(u, v)),$$すべてのペアの寄与をカウントする必要がありますが、これもまた指数関数的な作業になります。 

微妙なエッジケースが非常に浅い深さで現れます。 のために$d = 1$、ノードは 1 つだけあり、答えは次のとおりです。$0$。 のために$d = 2$、ノードが 3 つあり、順序付きペアは順序なしペアと比較して寄与が 2 倍になるため、完全なペアごとの合計はすでに自明ではなくなります。 導出では、ペアが順序付けされているかどうかに注意する必要があります。 ここではそれらは順序付けされているため、すべての無指向の貢献は事実上 2 回カウントされます。 

## アプローチ

 ブルートフォースの観点は、定義を拡張することから始まります。 ノードの各ペアは、それらの間のエッジの数に等しい距離に寄与します。 各ノードから BFS を実行し、距離を合計することを想像できます。 それには費用がかかります$O(n(n + m))$、これは中程度の人でもすでに不可能です$d$、 以来$n$指数関数的に成長します。 

より構造化されたブルートフォースの改善は、LCA を使用することです。 すべてのノードがあれば、次のように計算できます。$$\sum_{i,j} (depth(i) + depth(j) - 2 \cdot depth(lca(i,j))).$$最初の 2 つの項は集計するのが簡単ですが、LCA 項は、特定のノードを持つペアの数を LCA としてカウントする必要があるため、依然としてコストがかかります。 これはサブツリーのサイズに関する再帰につながりますが、これは正しい方向です。 

重要な観察は、ツリーが完全に対称であることです。 ノードのすべてのサブツリーは、それ自体が完全な二分木です。 これにより、個々のノードではなく、レベルごとの貢献について推論できるようになります。 

ノードのペアの観点から考える代わりに、エッジの観点から考えるように切り替えます。 各エッジは、まさにその反対側にあるノードのペア間の距離に寄与します。 端を切ると、木は 2 つのコンポーネントに分かれます。 注文したすべてのペア$(u, v)$と$u$1 つのコンポーネントで、$v$もう 1 つは、そのパスでそのエッジを使用します。 

したがって、問題は次のようになります。各エッジについて、そのエッジによって区切られている順序ペアの数を数え、1 を掛けて、すべてのエッジの合計を計算します。 

ここで必要なのはサブツリーのサイズだけです。 親と子の間のエッジについては、子のサブツリーが次のサイズであると仮定します。$s$、ツリー全体にはサイズがあります$n$。 そして、そのエッジは次のように貢献します。$$s \cdot (n - s) \cdot 2,$$順序ペアにはカットを横切る両方向が含まれるためです。 

完全なバイナリ ツリーでは、サブツリーのサイズは 2 の累乗 - 1 であり、純粋に深さによって決まります。 残っている唯一のタスクは、レベルごとにグループ化されたすべてのエッジにわたるこの寄与を合計することです。 

レベルで$k$、各ノードには次のサイズのサブツリーがあります。$2^{d-k} - 1$、そして、あります$2^k$ノード。 各ノードは 2 つのエッジをその子 (リーフを除く) に提供するため、レベルごとにエッジを数えることによって、慎重に貢献を集計します。 

これにより、問題全体がレベル間の幾何学的構造の合計に還元されます。これは次のように実行できます。$O(d)$を処理し、べき乗モジュラーを使用してさらに最適化します。$d$まで$10^5$。

 ## アルゴリズムのチュートリアル

 ツリー内のレベルごとに寄与度を計算します。 

1. すべてのエッジが、そのエッジによって引き起こされる切断の異なる部分に端点が存在するすべての順序ペアに寄与するという観察から開始します。 これにより、最短パスの合計がエッジ上の計数問題に変換されます。 
2. レベルのルートからツリー レベルにインデックスを付けます$0$レベルまで下げる$d-1$。 レベルのノード$k$サブツリーの高さがある$d-1-k$、したがって、各サブツリーのサイズは$2^{d-k} - 1$。 これにより、エッジの下にノードがいくつあるかを計算する直接的な方法が得られます。 
3. レベルのノードの場合$k$、レベルの子供へのエッジ$k+1$ツリーをあるサイズのサブツリーに分割します$2^{d-k-1} - 1$サイズの残りの部分$n - (2^{d-k-1} - 1)$。 これら 2 つの量を使用して、このエッジを横切る順序ペアの数を計算します。 
4. まさに、$2^k$レベルのノード$k$、各内部ノードは 2 つのエッジ (左と右の子) に寄与するため、$2^{k+1}$レベルから始まるエッジ$k$。 エッジごとの寄与にこのカウントを乗算します。 
5. これをすべての有効なレベルで合計します。$k = 0$に$d-2$、最後のレベルには子がないためです。 
6. すべての演算はモジュロで実行されます$10^9+7$、および 2 のすべてのべき乗は、大規模なデータを処理するために高速なべき乗を使用して計算されます。$d$。 

### なぜ効果があるのか

 ツリー内のすべての単純なパスは、それが交差する一連のエッジによって一意に識別されます。 各エッジは、そのエッジの反対側にエンドポイントを持つ順序付けされたペアごとに 1 回だけ寄与します。 ツリーは無向で非巡回であるため、どのペアもエッジ寄与のカウントを回避したり重複したりすることはできません。 したがって、すべてのエッジを合計すると、すべてのペアごとの距離の合計が正確に再構築されます。 

完全な二分木の対称性により、サブツリーのサイズは深さのみに依存するため、エッジの寄与はレベルのみに依存します。 これにより、問題は指数構造から決定論的な幾何学和に分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve(d):
    n = (pow(2, d, MOD) - 1) % MOD  # not actually used directly for large d logic
    
    # We will compute using subtree reasoning:
    # contribution per edge at level k depends on subtree size.
    
    ans = 0
    
    pow2 = 1  # 2^k
    for k in range(d - 1):
        # number of nodes at level k
        nodes = pow2
        
        # subtree size of child at level k+1:
        # height remaining = d - (k+1)
        subtree = (pow(2, d - k - 1, MOD) - 1) % MOD
        
        # complement side size
        comp = (pow(2, d, MOD) - 1 - subtree) % MOD
        
        # edges from level k to k+1: each node has 2 children
        edges = (nodes * 2) % MOD
        
        ans = (ans + edges * subtree % MOD * comp) % MOD
        
        pow2 = (pow2 * 2) % MOD
    
    return ans % MOD

def main():
    t = int(input())
    for _ in range(t):
        d = int(input())
        print(solve(d))

if __name__ == "__main__":
    main()
```コードはエッジカット解釈に従います。 レベルを反復処理し、2 のべき乗を使用してサブツリーのサイズを計算します。 このループは、べき乗を繰り返し再計算するのではなく、実行パワーを使用してレベルごとのノード数を構築します。 

微妙な点は、すべての算術演算がモジュロで実行されることです。$10^9+7$ただし、サブツリーのサイズは概念的には正確な整数から得られます。 この実装は、2 の累乗の差に対するモジュラー算術恒等式に依存します。 減算は常にモジュロで正規化されることに注意する必要があります。

import sys, io

MOD = 10**9 + 7

def solve(d):
    n = (pow(2, d, MOD) - 1) % MOD
    ans = 0
    pow2 = 1
    for k in range(d - 1):
        nodes = pow2
        subtree = (pow(2, d - k - 1, MOD) - 1) % MOD
        comp = (pow(2, d, MOD) - 1 - subtree) % MOD
        edges = (nodes * 2) % MOD
        ans = (ans + edges * subtree % MOD * comp) % MOD
        pow2 = (pow2 * 2) % MOD
    return ans

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    it = iter(sys.stdin.read().strip().split())
    t = int(next(it))
    out = []
    for _ in range(t):
        d = int(next(it))
        out.append(str(solve(d)))
    return "\n".join(out)

 ## 特殊なケース

 のために$d = 1$の場合、エッジがないため、アルゴリズムは反復を 0 回実行します。 合計は残ります$0$これは、異なるノードのペアが存在しないという事実と一致します。 

のために$d = 2$、ループは 1 回実行されます。 サブツリーのサイズは次のように評価されます。$1$、補数サイズ$2$、エッジカウントは$2$。 貢献度は、$2 \cdot 1 \cdot 2 = 4$無向形式で、順序付けられた解釈はこれを 2 倍にします。$8$、これは期待される結果と一致します。 

大型の場合$d$、最も深いレベルでは、次のサブツリー サイズが生成されます。$1$、つまり、葉に近い各エッジの寄与は最小限になります。 蓄積はサブツリー サイズが大きい上位レベルによって支配され、レベルベースの集計はノードを列挙することなくこれを正確に捕捉します。
