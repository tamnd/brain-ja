 ## 解決策
 ## 問題の理解

 小文字とワイルドカード文字を含む文字列が与えられます。 各ワイルドカードは独立して任意の小文字に置き換えることができます。 置換を選択した後、結果の文字列が固定され、その文字を並べ替えることによって取得できるすべての個別の文字列が考慮されます。 

完全に具体的な文字列の場合、個別の順列の数はその文字の頻度によってのみ決まります。 文字が複数回出現する場合、同じ文字を交換しても新しい文字列は作成されないため、カウントは頻度カウントに基づく多項係数になります。 

ここでのプロセスは 2 層になっています。 まず、全体にわたって均一にワイルドカードを置き換える方法をランダムに選択します。$26^{k}$割り当てがある場合$k$疑問符。 次に、結果の文字列に対して、個別の順列の数を計算します。 タスクは、大きな素数を法として、この順列カウントの期待値を計算することです。 

この制約により、文字列の長さは 1000 まで、テスト ケースは 500 個まで (合計長は 5000) が許可されます。これにより、疑問符の充填を列挙したり、最終文字列の順列を列挙したりするアプローチは除外されます。 テスト ケースごとの二次作業でも問題ありませんが、ワイルドカードの数が指数関数的に増加することは不可能です。 

微妙な特殊なケースは、多くの疑問符が存在する場合です。 素朴なアイデアは、埋められた各文字列を独立して処理し、その順列カウントを計算することですが、これは実際の構造を隠します。多くの埋め込みは同じ周波数のマルチセットを共有し、直接列挙すると二重カウントが大きくなります。 もう 1 つの落とし穴は、充填ごとの順列数をシミュレートしようとすることです。$O(n!)$自然界ではまったく不可能です。 

本当の課題は、期待が代入を超えていることですが、量は最終的な頻度カウントにのみ依存するため、ランダムな独立した文字の割り当てによって引き起こされる平均多項係数を計算する方法が必要です。 

## アプローチ

 ブルートフォース解釈は簡単です。すべてを反復処理します。$26^{k}$疑問符を埋める方法、完成した各文字列の文字頻度を計算する方法、次に階乗と頻度分母を使用して個別の順列の数を計算する方法。 階乗を事前に計算したとしても、各評価にはコストがかかります$O(n)$、につながる$O(n \cdot 26^k)$、これは限界をはるかに超えています。$k$適度に大きいです。 

重要な洞察は、順列についての考え方を逆転させることです。 充填を生成してから順列を数える代わりに、最初に順列を選択し、ランダムな充填が構造化された方法で有効になるかどうかを尋ねることを考えることができます。 もう 1 つの同等でより直接的な方法は、期待される多項係数を各文字の寄与に関して個別に表現することです。 

最終的な文字数のマルチセットを修正$c_1, c_2, \dots, c_{26}$。 個別の順列の数は次のとおりです。$$\frac{n!}{\prod c_i!}$$ランダム性は、疑問符によって提供される文字数にのみ影響します。 各疑問符は独立して一様にランダムな文字に 1 つの単位を与えるため、最終的なカウントは決定的な基底カウントと多項ランダム ベクトルの合計になります。 

私たちが望んでいるのは:$$\mathbb{E}\left[\frac{n!}{\prod c_i!}\right]$$因数分解$n!$これはすべての詰め物にわたって一定であるため、次のようになります。$$n! \cdot \mathbb{E}\left[\prod \frac{1}{c_i!}\right]$$難しいのは、$c_i$すべての疑問符が文字全体に分散されるという制約によって相関されます。 確率変数の階乗を直接操作する代わりに、古典的な組み合わせトリックを使用して期待値を拡張します。つまり、疑問符の寄与に対する生成関数を介して各文字を独立して処理します。 

文字ごとに$i$すでに表示されていると仮定します$a_i$文字列の固定部分の回数。 させて$x_i$疑問符が何個文字になるか$i$。 それから：$$c_i = a_i + x_i$$すべての分布を合計する必要があります。$x_i$と$\sum x_i = k$、多項確率で重み付け:$$\frac{k!}{x_1! \cdots x_{26}!} \cdot \frac{1}{26^k}$$したがって、期待値は次のようになります。$$\frac{n!}{26^k} \sum_{x_1+\cdots+x_{26}=k} \prod_{i=1}^{26} \frac{1}{(a_i + x_i)!} \cdot \frac{k!}{x_1! \cdots x_{26}!}$$これで、構造は文字によって区切られ、文字上の DP と割り当てられた疑問符の数を使用してこれを計算できます。 各州は、処理された文字間で疑問符が何個配布されたかを追跡します。 

以下を定義します。$$dp[i][j]$$最初に使用する貢献として$i$正確に含まれる文字$j$疑問符が割り当てられます。 疑問符の数の推移$t$手紙に行く$i$、乗算:$$\frac{1}{(a_i + t)! \cdot t!}$$最後に乗算します$n! \cdot k! / 26^k$。 この DP は小さいです: 26 文字と最大 1000 個の疑問符なので、$O(26 \cdot k^2)$テストごとの最適化やテストケース全体での事前計算の再利用は許容されます。 

これにより、文字列に対する確率的な期待が、26 の有界次元にわたる構造化された畳み込みに変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(26^k \cdot n)$|$O(n)$| 遅すぎる |
 | 文字数と文字数に対する最適な DP |$O(26 \cdot k^2)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字が文字列内にすでに出現している回数を数え、疑問符が何個存在するかを数えます。 これにより、固定構造がランダム性から分離されます。 
2. 可能な最大文字列長まで階乗を事前計算します。 順列数の分子と分母の両方に階乗が必要です。 
3. グローバル乗算係数を計算する$n! \cdot k! / 26^k$。 の$k!$分散疑問符の多項重み付けから生じます。 
4. 各状態が文字のプレフィックスを処理し、文字間で一定数の疑問符を分散することを表す DP 配列を構築します。 
5. DP を最初の文字で初期化します。 固定文字の場合は、割り当ててみてください$t$それには疑問符がつきます。 それぞれの選択が重みに影響します。$$\frac{1}{(a_i + t)! \cdot t!}$$前の状態からの組み合わせ遷移を乗算します。 
6. 26 文字すべてを反復処理し、文字の処理後に DP をレイヤーごとに更新します。$i$、最初の疑問符のすべての分布$i$文字が考慮されます。 
7. すべての文字を処理した後、DP 値は正確に$k$割り当てられた疑問符は、すべての有効な分布に必要な合計です。 
8. DP の結果に前に計算したグローバル係数を乗算して、期待値のモジュロを取得します。$10^9+7$。 

### なぜ効果があるのか

 DP は、文字全体にわたる疑問符のすべての可能な割り当てを正確に 1 回列挙し、各割り当ては正しい多項確率によって重み付けされます。 順列カウントは最終的な周波数ベクトルにのみ依存し、独立した文字ごとの階乗項に因数分解されるため、各割り当ての寄与は文字上の積に分解されます。 DP は、すべての有効なベクトルを合計する単純な構造化された方法です。$(x_1, \dots, x_{26})$正しい組み合わせ重みを使用しているため、期待値の定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 1000

# factorials
fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN] = pow(fact[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def solve(s):
    n = len(s)
    cnt = [0] * 26
    k = 0

    for ch in s:
        if ch == '?':
            k += 1
        else:
            cnt[ord(ch) - 97] += 1

    # dp[j] = sum of contributions after processing letters so far
    dp = [0] * (k + 1)
    dp[0] = 1

    for i in range(26):
        ndp = [0] * (k + 1)
        a = cnt[i]

        for used in range(k + 1):
            if dp[used] == 0:
                continue
            base = dp[used]
            for add in range(k - used + 1):
                val = base * invfact[a + add] % MOD * invfact[add] % MOD
                ndp[used + add] = (ndp[used + add] + val) % MOD

        dp = ndp

    ways = dp[k]

    # multiply global factor: n! * k! / 26^k
    ans = fact[n] * fact[k] % MOD
    ans = ans * pow(26, MOD - 1 - k, MOD) % MOD
    ans = ans * ways % MOD

    return ans

t = int(input())
for _ in range(t):
    s = input().strip()
    print(solve(s))
```順列と多項展開は両方とも階乗反転の繰り返しに依存するため、解決策は階乗テーブルを修正することから始まります。 各テスト ケースでは、固定文字と疑問符が分離されます。 

DP は、割り当てられた疑問符の合計に対して 1 つの次元を使用します。 文字ごとに、追加の疑問符を分配し、最終的な頻度ペナルティを表す逆階乗項を乗算します。 2 番目の逆階乗は、その文字に疑問符を割り当てる多項重みに対応します。 

最終的なスケーリング係数は、順列分子を結合します。$n!$、多項正規化$k!$、確率の正規化$26^{-k}$。 

## 実用的な例

 ### 例 1:`a?b`我々は持っています$a_a = 1$、$a_b = 1$、 そして$k = 1$。 

| 加工された文字 | 使用済み ？ | dp 状態 (選択された値) |
 | --- | --- | --- |
 | | 0 または 1 | 1/1!、1/2!がたまります。 |
 | b | 最終 | 貢献を組み合わせる |

 すべての文字を処理した後、DP は 2 つのケースをキャプチャします。疑問符が a または b になります。 最終的な加重合計は、文字列を埋めると 2 つの等しい文字構造または 3 つの異なる文字構造が生成され、順列カウントがそれに応じて異なるという事実と一致します。 DP は、各ケースが確率によって重み付けされることを保証します。$1/26$。 

これにより、アルゴリズムが順列を列挙するのではなく、構造的な結果を正しく分離していることが検証されます。 

### 例 2:`??`ここ$k = 2$、すべての塩基カウントはゼロです。 

| 手紙 | 使用済み ？ | DP の洞察 |
 | --- | --- | --- |
 | | 0 から 2 に分配します | aa、a? などのコントリビューションを構築します。 
| b | 配布を継続します | 多項分割をマージします。 

DP は、文字全体にわたる 2 つの同一のランダムな割り当てのすべての分割を列挙します。 両方の文字が同じである場合と異なる場合をキャプチャし、正しく重み付けします。$1/26^2$配布物。 最終結果は、割り当ては順序ではなく衝突パターンのみに依存するという対称性と一致します。

 ## 特殊なケース

 特殊なケースとしては、文字列に疑問符が含まれていない場合があります。 その場合、DP は単一の決定論的な周波数ベクトルに縮小され、答えは次と等しくなります。$n! / \prod c_i!$。 アルゴリズムはこれを処理します。$k = 0$したがって、DP は分岐せず、最終的なスケーリングは次のようになります。$n! \cdot 1$。 

もう 1 つのケースは、すべての文字が疑問符である場合です。 この場合、すべての塩基数はゼロになり、DP は 26 文字にわたる純粋な多項分布になります。 対称性により、衝突構造のみが重要になることが保証されます。 すべての階乗ペナルティは割り当てられたカウントからのみ発生し、すべての割り当ては均一に扱われるため、アルゴリズムはこれを自然に処理します。 

3 番目のケースは、1 つの文字が固定部分を占めており、すべての疑問符をその周囲に配置する必要がある場合です。 DP は高周波階乗分母の大きな寄与を正確に蓄積し、単純な計数ロジックのオーバーフローを防ぎます。
