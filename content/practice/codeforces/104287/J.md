 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、正の整数の配列があります。 ニノから始めて 2 人のプレイヤーが交互にターンします。 ターンでは、プレイヤーは任意の 1 つの要素を選択し、それを ⌊x/2⌋ または ⌊x/3⌋ のいずれかに置き換えます。ただし、結果が依然としてプラスである場合に限ります。 プレイヤーが自分の番に有効な手を持っていなかった場合、プレイヤーは負けます。 問題は、両方のプレイヤーが最適にプレーしたと仮定してどちらが勝つかです。 

重要な点は、ゲームの状態は配列の値だけではなく、各値からどれだけのリダクション ステップが可能であるかであるということです。 1 つの手ごとに 1 つの要素のみが変更されるため、各番号はターン順序を除いて独立して進化します。 

制約は大きく、テスト ケースは最大 100,000、配列の合計サイズは最大 100,000 です。これにより、ゲーム ツリーの手ごとのシミュレーションが除外されます。 単純に調査すると 10^9 までの単一の値に多くの削減パスが存在する可能性があるため、数値ごとに完全なゲーム グラフを計算するだけでも遅すぎます。 

当然の危険は、動きを直接シミュレートしようとすることです。 たとえば、10^9 のような単一の値の場合、2 または 3 で繰り返し除算すると、状態の大きな分岐ツリーが生成され、そのような値を複数組み合わせると、状態空間が指数関数的になります。 それぞれの動きを明示的に扱うアプローチは失敗します。 

2 番目の微妙な問題は、値のパリティのみが重要であると仮定していることです。 これは誤りです。3 で割ると 2 で割る場合とは異なる削減軌道が作成され、ゲーム用語ではこれらは同等ではありません。 

## アプローチ

 一見すると、これは通常の公平な組み合わせゲームです。 各配列要素は山のように動作し、個別のステップでサイズを縮小できます。 これは、要素ごとにグランディ数を計算し、XOR 演算することを示唆しています。 

単一の値 x に対して総当たり攻撃を行う場合、結果が正のまま x → ⌊x/2⌋ または x → ⌊x/3⌋ を繰り返し適用することで、到達可能なすべての状態を定義できます。 これにより、状態の有向非巡回グラフが構築されます。 そのグラフからグランディ数を計算します。 これは正しいです。移動するたびに値が厳密に減少するため、サイクルは存在しません。 

ただし、各 x のすべての状態をブルートフォースで生成するとコストがかかります。 最悪の場合、各数値は O(log x) の深さを生成する可能性があり、2 つの操作による分岐により、さまざまなテスト ケース間で多くの繰り返し状態が発生します。 値が 10^5 を超えると、速度が非常に遅くなります。 

重要な観察は、数値の状態グラフが非常に構造化されているということです。 すべての値は最終的に少数の終端状態のセットにマッピングされ、ほとんどのパスはすぐに収束します。 さらに重要なことは、Grundy 値は、さまざまなシーケンスで 2 と 3 で何回除算できるかのみに依存することです。これは、完全なパスを探索するのではなく、到達可能な小さなセット内の状態をカウントすることになります。 

より効率的な方法は、分割チェーンを介して到達可能な最大値までのすべての数値のグランディ値を計算することです。ただし、各ステップで値が少なくとも 2 または 3 の係数で減少するため、すべてのノードにわたる個別の到達可能な値の合計は、重複することなくテスト ケースごとに動的に事前計算できるほど十分に小さいです。 これは、⌊x/2⌋ および ⌊x/3⌋ への直接遷移を伴う状態のメモ化につながります。 

各要素の Grundy 値を計算すると、ゲーム全体は独立した公平なゲームの合計となるため、XOR によって勝者が決まります。ゼロ以外の XOR は、最初のプレーヤーの勝利を意味します。

 | テスト ケースごとのブルート フォース状態探索 | 最悪の場合は指数関数的 | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 各値をゲーム状態として扱い、そのグランディ数は 2 つの可能な動きに依存します。

1. 各テスト ケースでは、すべての要素を個別に処理しますが、グローバルメモ化マップを再利用するため、繰り返される値は再計算されません。 ゲームのルールは位置ではなく値のみに依存するため、これは有効です。 
2. 値 x のグランディ数を返す関数 grundy(x) を定義します。 x が 1 の場合、移動は不可能であるため、グランディ数は 0 になります。 
3. x が 1 より大きい場合は、到達可能なすべての状態 (x を 2 で割ったものと x を 3 で割ったもの) を考慮します。ただし、結果が正の場合のみです。 これらは唯一の合法的な措置であるため、移行構造を完全に定義します。 
4. grundy(x // 2) と grundy(x // 3) を再帰的に計算します。 結果をセットに収集します。 
5. x のグランディ値は、そのセットの mex (最小除外値) です。 この問題では集合サイズは最大 2 なので、0、1、2 を順番にチェックして mex を計算します。 
6. 配列に対するすべての grundy(a_i) の XOR。 結果がゼロ以外の場合は、ニノが勝ちます。 そうでなければミクの勝ちです。 

### なぜ効果があるのか

 それぞれの動きは選択された要素の値を厳密に減少させるため、ゲーム グラフは非周期的であり、標準的なスプレイグ グランディ理論に適合します。 移動は 1 つのポジションにのみ影響するため、各要素は独立したサブゲームです。 したがって、完全なゲームは独立した Grundy 値の XOR です。 

メモ化により、各整数値が 1 回解決されることが保証され、遷移ごとに大きさが少なくとも 2 または 3 の係数で減少するため、再帰の深さは値のサイズが対数になります。 これにより、DP が迅速に収束し、再計算によって複雑さが増大しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

memo = {}

def grundy(x):
    if x == 1:
        return 0
    if x in memo:
        return memo[x]

    moves = set()

    nx = x // 2
    if nx > 0:
        moves.add(grundy(nx))

    ny = x // 3
    if ny > 0:
        moves.add(grundy(ny))

    g = 0
    while g in moves:
        g += 1

    memo[x] = g
    return g

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))

    xor_sum = 0
    for v in arr:
        xor_sum ^= grundy(v)

    print("Nino" if xor_sum != 0 else "Miku")
```このソリューションは、メモ化された再帰的グランディ計算を中心に構築されています。 メモ ディクショナリにより、各値がグローバルに 1 回評価されることが保証されます。 再帰は、許可された 2 つの遷移を直接処理します。 

各状態には最大 2 つの出力エッジがあるため、mex の計算は簡素化されます。そのため、小さい整数のみを順次テストします。 

XOR 集約は、互いに素なパイルに対する Sprague-Grundy の定理を実装します。 

微妙な実装の詳細はグローバル メモです。これがないと、テスト ケース全体で値が繰り返されるとチェーン全体が再計算され、時間が膨大になってしまいます。 もう 1 つの微妙な点は再帰の深さです。 値は急速に縮小しますが、Python の再帰制限は依然として敵対的チェーンに達する可能性があるため、再帰制限は増加します。 

## 実用的な例

 2 つのサンプル テスト ケースをトレースします。 

### サンプル:`[1, 2, 5]`グランディ値を計算します。 

| 値 | x//2 | x//3 | ムーブグランディセット | グランディ |
 | --- | --- | --- | --- | --- |
 | 1 | - | - | ∅ | 0 |
 | 2 | 1 | 0 無効 | {0} | 1 |
 | 5 | 2 | 1 | {1, 0} | 2 |

 ここで XOR: 0 ⊕ 1 ⊕ 2 = 3 ≠ 0 となるため、Nino が勝ちます。 

これは、5 からの小さな分岐でも 2 つの異なる到達可能な Grundy 状態を生成し、自明ではない mex を与えることを示しています。 

### サンプル:`[1, 2, 3, 4]`次のように計算します。 

| 値 | x//2 | x//3 | ムーブグランディセット | グランディ |
 | --- | --- | --- | --- | --- |
 | 1 | - | - | ∅ | 0 |
 | 2 | 1 | 0 無効 | {0} | 1 |
 | 3 | 1 | 1 | {0} | 1 |
 | 4 | 2 | 1 | {1, 0} | 2 |

 XOR: 0 ⊕ 1 ⊕ 1 ⊕ 2 = 2 ≠ 0 なので、ニノが勝ちます。 

このトレースは、複数の同一の Grundy 値が出現し、依然としてゼロ以外の結果が残っている場合の XOR でのキャンセル効果を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑ log a_i) 償却 | 各整数状態は 1 回計算され、各計算は x/2 および x/3 までのみ再帰されます。 
| スペース | O(#個別の到達可能な値) | メモ化は、検出された値ごとに 1 つのエントリを保存します。 

状態の総数は、すべての入力から 2 と 3 で繰り返し除算することで到達できる一意の値の数によって制限されます。 各ステップで大きさが急速に減少するため、これは合計入力サイズ 10^5 の制限内に留まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    sys.setrecursionlimit(10**7)
    memo = {}

    def grundy(x):
        if x == 1:
            return 0
        if x in memo:
            return memo[x]

        moves = set()

        nx = x // 2
        if nx > 0:
            moves.add(grundy(nx))

        ny = x // 3
        if ny > 0:
            moves.add(grundy(ny))

        g = 0
        while g in moves:
            g += 1

        memo[x] = g
        return g

    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        xor_sum = 0
        for v in arr:
            xor_sum ^= grundy(v)
        res.append("Nino" if xor_sum else "Miku")

    return "\n".join(res) + "\n"

 ## 特殊なケース

 のために`a = [1]`、唯一の要素にはすでに有効な動きがないため、開始プレイヤーはすぐに負けます。 アルゴリズムは Grundy(1) = 0、XOR = 0 を返すため、ミクが勝ちます。 

次のような大きな値の場合`10^9`再帰では、1 に達するまで 2 と 3 による除算が繰り返し適用されます。メモ化により、10^9 → 5×10^8 → 2.5×10^8 などの重複する部分問題が 1 回計算され、テスト スイート全体で再利用されます。 これにより、指数関数的な爆発が防止されます。 

同一の要素が繰り返される場合、次のようになります。`[2, 2, 2, 2]`、それぞれが Grundy(2) = 1 に寄与し、XOR はペアごとにキャンセルされます。 アルゴリズムは正しく 0 を生成します。これは 2 番目のプレーヤーが勝つことを意味し、同一の独立した山の対称性に一致します。
