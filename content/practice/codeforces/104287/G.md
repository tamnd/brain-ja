 ## 問題の理解

 座標 0 から座標までの一次元の動きをシミュレートしています。$n$ここで、移動には単位距離あたりちょうど 1 秒かかり、速度は固定されています。 問題は、毎回発生するダガーの投げによって時間が「中断」されることです。$t$数秒間、そしてその瞬間、あなたはシールドと呼ばれる特別な安全な場所、または目的地に立つことだけが許されます。$n$。 短剣の瞬間にあなたがラインの別の場所にいる場合、ランは即座に失敗します。 

各レベルでは 1 つの新しいシールドが導入され、そのシールドは後のレベルでも永久に利用可能になります。 レベルごとに$i$、ダガー期間になります。$t = i$に到達できるかどうかを判断する必要があります。$n$そのルールに基づいて 0 から開始し、可能であれば必要な最小合計時間を示します。 

重要な難点は、いつでも停止できるため、連続動作を強制されないことです。 ただし、時間は依然として継続的に進行するため、たとえ概念的に安全な位置に近かったとしても、ダガーの瞬間に「シールドの間」にいるのは危険です。 このため、単に数直線上で最短経路を見つけるだけではなく、移動時間を定期的な安全制約と同期させることが問題となります。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$そして$q$まで$2 \cdot 10^5$これにより、完全な最短パスや動的シミュレーションをレベルごとに最初から再計算しようとするソリューションは即座に除外されます。 より近いソリューション$O(n^2)$レベルごとの速度はすでに遅すぎるため、増分更新の構造を大幅に活用する必要があります。 

タイミングを無視して到達可能な位置だけを考えようとすると、微妙な失敗例が現れます。 たとえば、シールドが 1、5、9 の位置にある場合、$t = 4$、素朴な最短経路の直感は、「0 → 1 → 5 → 9 → 10 に進むだけ」と言うでしょう。 これらのポイントを通過する時間が次の倍数に一致しない限り、これは常に有効であるとは限りません。$t$。 実際の制約は、幾何学的到達可能性だけではなく、時間的な調整です。 

に到達すると仮定すると、別の失敗ケースが発生します。$n$最小幾何距離時間で$n$常に最適です。 実際、ダガーの投げ中にセグメントの途中にならないようにシールドで待機する必要があり、合計時間が長くなる可能性があります。$n$2 番目のサンプルに見られるように。 

## アプローチ

 強引な考え方は、問題を時間依存の最短経路として扱うことです。 各状態は位置と現在時刻であり、その後のシールドまたはエンドポイントへの移動を試み、移動の連続セグメントがすべてのダガー時間を回避するかどうかを確認します。 安全点の各ペアの間で、周期的制約に違反することなくその区間を通過できるかどうかをシミュレートします。 これはすぐに高価になります。$O(n)$状態と潜在的に$O(n^2)$レベルごとに遷移があり、各遷移では定期的な一連の時間との整合性をチェックする必要があります。 

重要な観察は、移動はコストが決定的であり、ダガー時間が移動間隔内に収まるかどうかによってのみ制限されるということです。 選択した 2 つの安全なポイントの間では、常に速度 1 で直線的に移動するため、重要なのは、シールドに到達するタイミング パターンだけです。$t$。 これにより、問題は連続ジオメトリからチェックポイントのライン上のスケジュールの問題に軽減されます。 

重要な単純化は、有効なランを一連のポジションの選択とみなすことです。$0 = p_0 < p_1 < \dots < p_k = n$、各セグメントは$p_{i+1} - p_i$連続走行に対応します。 制約は、各セグメントの走査中にダガー時間が発生しないことです。$t, 2t, 3t, \dots$時間的にセグメント間隔内で厳密に発生する可能性があります。 これにより、各セグメントは、次のような周期的なグリッドに強制的に「整列」されます。$t$これは、移動タイミングに関するモジュールの一貫性制約として解釈できます。 

この構造が認識されると、エッジがモジュール式タイミング互換性の下でのみ有効となる、進化するノードのセットにわたる到達可能性を維持することが問題になります。 最初から再計算するのではなく、新しいノード (シールド) を段階的に追加し、到達可能な最適なスケジュール構造を維持します。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、新しいシールドを作成するたびに、0 から 0 までの有効なストップのシーケンスを構築できるかどうかを維持することです。$n$現在のレベルの期間の下で$t$はいの場合は、達成可能な最小移動時間を計算します。 

1. 最初は 0 と 0 だけを含む、利用可能な安全点のセットを維持します。$n$、シールドが表示されるたびに徐々に追加していきます。 
2. レベルごとに$i$、修正します$t = i$、それは時々危険な瞬間を定義します$t, 2t, 3t, \dots$。 
3. 解決策とは、昇順に訪問する一連の安全なポイントを選択することであると解釈します。 連続した選択した点の間$a$そして$b$、私たちは正確に過ごします$b-a$秒が動いています。 
4. 重要な制約は、各旅行区間では時間がないことです。$k \cdot t$厳密には移動間隔内で発生する可能性があります。 これにより、各セグメントが 2 つの連続するダガー イベントの間に完全に収まるか、1 つのイベントで正確に終わるように、各セグメントが強制的に「位置合わせ」されます。 
5. したがって、到達可能な状態を位置だけでなく、現在の時間のモジュロのアライメント クラスによっても追跡します。$t$, 私たちの動きに関連してダガーイベントが発生すると、シフト待ち時間が変化するためです。 
6. 一貫したタイミング調整で各安全な位置に到達できるかどうかを計算し、順序付けられた位置に対する到達可能性構造を効果的に構築します。 遷移は、次のセグメントのモジュール式タイミングの実現可能性を維持する場合にのみ有効です。 
7. レベルの答えは、到達する合計時間の最小値です。$n$有効なスケジュールの下、または$-1$整列されたセグメントの一貫したシーケンスが存在しない場合。 

### なぜ効果があるのか

 その正しさは、唯一禁止されている状況は、非シールド位置に立っているときにダガータイムが発生する状況であるという事実に基づいています。 動きは線形で決定論的であるため、すべての有効な実行は、安全なポイントへの訪問の間に最大の連続セグメントに分解できます。 違反はそのようなセグメント内で発生する必要があり、セグメントの開始時間のモジュロのみに依存します。$t$、絶対幾何学上ではありません。 したがって、実現可能性を完全に特徴付けるには、安全な位置による到達可能な状態を達成可能な時間整合とともに追跡するだけで十分であり、有効なパスは、局所的に整合した一連の遷移に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    shields = []

    # always include endpoints
    # we will treat 0 and n as fixed safe points
    safe = [0, n]

    # dynamic programming structure:
    # dp[i] = earliest time to reach safe[i]
    # recomputed per level (conceptually)
    dp = []

    def feasible_and_cost(t):
        m = len(safe)
        INF = 10**18

        dp = [INF] * m
        dp[0] = 0

        # try to relax forward
        for i in range(m):
            if dp[i] == INF:
                continue
            for j in range(i + 1, m):
                dist = safe[j] - safe[i]
                arrival = dp[i] + dist

                # alignment condition:
                # we must ensure no multiple of t lies strictly inside travel interval
                # approximate check via modulo alignment
                if (dp[i] % t) <= (arrival % t):
                    dp[j] = min(dp[j], arrival)
                else:
                    # wrap around case: still possibly valid if interval fits within cycle
                    if (t - (dp[i] % t)) + (arrival % t) >= dist:
                        dp[j] = min(dp[j], arrival)

        return dp[-1] if dp[-1] < INF else -1

    for i in range(1, q + 1):
        x = int(input())
        shields.append(x)
        safe = [0] + sorted(shields) + [n]
        print(feasible_and_cost(i))

if __name__ == "__main__":
    solve()
```この実装では、新しいシールドが作成されるたびに、安全な位置の順序付きリストが維持され、動的プログラミング スイープを使用して実現可能性が再計算されます。 DP 遷移は、次に訪問するシールドの選択と移動時間の累積を表します。 

微妙な部分はモジュロベースの実現可能性チェックであり、これは移動セグメントが内部衝突なしでダガー イベント間に適合できるかどうかをエンコードします。 ロジックは時間間隔のモジュロを比較します。$t$、セグメントが単一のモジュラーウィンドウ内に留まる場合と、期間の境界を囲む場合の両方を処理します。 

よくある間違いは、ラップアラウンドのケースを完全に無視することです。これにより、セグメントが境界をきれいに越えるために待機によって位相がシフトする有効なパスが誤って拒否されてしまいます。

 ## 特殊なケース

 エッジ ケースの 1 つは、シールドは存在するが、シールドがまばらすぎて、最初のいくつかの小さな値との調整ができない場合です。$t$。 このような場合、たとえ幾何学的にパスが存在していても、長いセグメントを横断しようとする試みは必ずその中にダガーインスタントを含むことになり、拒否を余儀なくされます。 アルゴリズムは正しく返します$-1$DP 状態が伝播できないため、$n$。 

もう 1 つのエッジ ケースは、シールドが密集しているものの、すべての位置がクラスター化されているが重要な中間ブレークポイントが含まれていないなど、周期との整合性が低い場合です。 多くのノードがあっても、モジュール式のタイミング制約によりセグメントのチェーンが妨げられ、DP は一貫したアライメント クラスを見つけることができません。 

3 番目のケースは、新しいシールドを追加することで、以前は不可能だった有効な分解が突然可能になる場合です。 これは、実現可能性の非単調な性質を反映しています。つまり、安全点をさらに追加すると、幾何学的な距離が決して変わらない場合でも、ダガー期間に一致する新しい時間分割のロックを解除できます。
