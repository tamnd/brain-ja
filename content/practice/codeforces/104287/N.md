 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられています。$N$によって接続されたノード$N-1$エッジにはサイクルがなく、各エッジには負ではない重みがあります。 このツリーから、ノードを共有しない 2 つのパスを選択する必要があります。 選択したパスごとに、それに沿ったエッジの重みの合計を計算します。 最終スコアは 2 つのパスの合計の最小値であり、タスクは、2 つのノードに共通のパスのすべての有効な選択肢にわたってこのスコアを最大化することです。 

つまり、構造は次のとおりです。ツリー内の 2 つの単純なパスを選択し、それらの頂点が互いに切り離されていることを確認し、弱い方ができるだけ強くなるようにそれらのバランスをとることだけを考慮します。 

制約は次のとおりです$5 \cdot 10^5$これにより、すべてのパス、さらにはすべてのパスのペアを列挙しようとするソリューションは即座に除外されます。 平$O(N^2)$テスト ケースごとのアプローチは不可能であり、ノードまたはエッジのすべてのペアを直接処理するものは範囲外です。 テスト ケースごとに線形または線形に近いトラバースを強いられます。 

微妙な点は、「2 つのノードが切り離されたパス」は、それらが何らかのルートの異なるサブツリーに存在する必要があることを意味するものではないということです。 頂点が重ならない限り、ツリー内のどこにでも配置できます。 このため、ブルートフォースによるパスのペアリングは特に危険になります。 

素朴な考えを打ち破る傾向があるエッジ ケースには、中間のどこかに重い分岐がある長いチェーンなど、最適パスが非常にアンバランスであるツリーや、両方の最適パスが重みの高い中央領域を共有し、素性制約が優勢になるツリーなどがあります。 

たとえば、次のような単純なチェーンを考えてみましょう。```
1 -2- 2 -2- 3 -2- 4
```パス (1 ～ 4) を選択すると、他のパスを選択できないため、スコアは 0 になります。しかし、最適な解決策は、(1-2) と (3-4) のような 2 つの互いに素なパスに分割し、それぞれの合計が 2 になり、スコアが 2 になることです。貪欲な最長パスのみのアプローチは、分割を無視するため、ここでは失敗します。 

もう 1 つの失敗ケースは、ノード 1 を中心とするスターであり、すべてのエッジがリーフに接続されています。 単純なアプローチでは、2 つの最も重いエッジを 2 つのシングルエッジ パスとして選択する可能性があります。これはここでは正しいですが、長いチェーンを構築しようとするアプローチは、長いチェーンが存在しないため失敗します。 

## アプローチ

 ブルートフォースのアイデアは、直接的な解釈から始まります。つまり、ツリー内のすべての単純なパスを列挙し、次にノードに共通でないパスのすべてのペアを試し、それらの合計の最小値を計算し、最大の結果を追跡します。 

木の中には、$O(N^2)$単純な道。 それらをペアリングすると、すでに得られます$O(N^4)$最悪の組み合わせ。 枝刈りを行っても、有効なパスのペアの数は依然として多すぎるままです。 ボトルネックは正確さではなく、候補となるパスのペアの数が膨大であることです。 

重要な構造的洞察は、何らかの分離構造を除去すると、ツリー内の 2 つのノードに切り離されたパスが異なる接続コンポーネントに存在するはずであるということです。さらに重要なことに、最適な解決策は、ツリーが独立した部分に分割される「中央」領域の周囲の分解を通じて常に解釈できるということです。 任意のパスのペアについて考えるのではなく、視点を変えます。つまり、2 つの「可能な限り最良の」パスが互いに切り離された部分に存在し、弱い方のパスを最大化するようにツリーを切断する方法を見つけたいと考えています。 

有用な再定式化は、ルート分解から生じるパス候補の観点から考えることです。すべての最適なペアは、交差しない 2 つのパスを選択することに対応します。これは、ツリー内の分割点を選択することによって、最も重なり合うパスを回避する必要があることを意味します。 これは当然、DP またはリルートベースの最適な下方向および最適なグローバル パス寄与の計算につながります。 

この解決策は最終的には、ノードごとに、そのノード以上で分離されたツリーのさまざまな部分で形成できる、結合されていない最良の 2 つの「高価値パス コントリビューション」を計算することになります。 これは、選択した 2 つのパス間でノードを再利用しないようにしながら、最長の下向きパスを計算し、それらを慎重に組み合わせることで行われます。 

中心的な考え方は、すべての有効な解は、ある分解ポイントの異なる分岐にある 2 つのエッジが分離された (したがって頂点が分離された) パスとして表現でき、そのようなすべての分割ポイントを考慮し、別個のサブツリーからの最良の候補を組み合わせることで答えが得られる、ということです。

 ## アルゴリズムのチュートリアル

 任意のノードでツリーをルート化します。 目標は、ノードごとに、そのサブツリー内に完全に存在する最適パスの寄与に関する情報を計算し、異なる子サブツリーからの寄与を結合することになります。 

すべてのノードについて、そのノードからそのサブツリーまでの最適な下向きパスの合計を維持します。 これは標準のツリー DP です。子ごとに、最適な下向きのパスを選択し、接続エッジを追加します。 

ただし、最終的な答えには 2 つの互いに素なパスが含まれており、両方とも異なるサブツリー内にあるか、両方ともルートからリーフへのパスではなく内部構造である可能性があるため、単一の下向きパスでは十分ではありません。 

したがって、各ノードで、異なる子サブツリーから取得できる重複しない最適な 2 つのパス候補も知りたいと考えます。 これが重要な点です。子サブツリーの共有はノードの共有を意味するため、ノードで交わる 2 つのノードに切り離されたパスは、異なる子に由来する必要があります。 

以下のように進めていきます。 

1. ノード 1 でツリーをルートし、隣接リストを計算します。 
2. 各ノードに対して、そのノードから始まる最適な下向きパスを計算する DFS を実行します。 この値は、このノードから始まり 1 つの子サブツリーに至るパスの最大合計を表します。 1 つの分岐に制限する理由は、ノードに入って下に向かう単純なパスは、正確に 1 つの子方向を選択する必要があるためです。 
3. DFS 中に、各ノードについて、エッジの重みを追加した後、その子からすべての候補の下方寄与を収集します。 これらは、現在のノードから始まり、別個のサブツリーに広がる独立したパス セグメントを表します。 
4. 各ノードで、上位数個の子コントリビューションをソートまたは維持します。 複数が必要な理由は、最終的な答えには 2 つの互いに素なパスを選択する必要があるためです (最良の場合、これらのパスは 2 つの異なる子から得られます)。 
5. 各ノードで 2 種類の候補を計算します。1 つ目は、そのサブツリーに完全に含まれる最良の単一パス (下向き DP によってすでにキャプチャされている)、2 つ目は、異なるサブツリーに属する 2 つの最良の子寄与を取得することによって形成される最良のペアです。 ノードを共有しないため、それらの合計は独立しています。 
6. 選択した 2 つのパスの合計の最小値を使用して、グローバルな答えを更新します。 これは、2 つの互いに素なパスを選択すると、スコアは弱い方のパスによって決定されるという事実を反映しているため、両方のパスが可能な限り強力であることを確認する必要があります。 
7. DFS トラバーサルを続行して、各ノードがその子からの情報を集約し、ツリー内の考えられるすべての分割点が確実に考慮されるようにします。 

### なぜ効果があるのか

 重要な不変条件は、ノードに共通のパスのすべての有効なペアが (ルート ツリー内に) 一意の最上位共通の祖先を持ち、その祖先では 2 つのパスが異なる子サブツリーに存在する必要があるということです。 私たちの DP は、各ノードで、異なるサブツリーから 2 つの互いに素な寄与を選択するすべての方法を列挙します。 すべての有効なペアは、まさにこの方法でノードで分離する必要があるため、実行可能なすべての解はその分割点で表されます。 下向き DP により、各サブツリーがそのような組み合わせに対して可能な限り最適なパスを提供するため、より適切なローカル構成が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        g[v].append((u, w))

    ans = 0

    def dfs(u, p):
        nonlocal ans
        best_down = 0
        gains = []

        for v, w in g[u]:
            if v == p:
                continue
            child_down = dfs(v, u) + w
            gains.append(child_down)
            best_down = max(best_down, child_down)

        gains.sort(reverse=True)

        if len(gains) >= 2:
            ans = max(ans, gains[0] + gains[1])

        ans = max(ans, best_down)

        return best_down

    dfs(0, -1)
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、テスト ケースごとに 1 つの DFS を使用します。 重要な構造は、`dfs`ノードから始まる最適な下向きパスを返す関数。 この値は、すべての子の下向き寄与とエッジの重みの最大値を取ることによって計算されます。 

の`gains`list はすべての子コントリビューションを収集するため、最適な 2 つの独立したブランチを特定できます。 わかりやすくするために並べ替えを使用していますが、実際には上位 2 つの選択を実行するだけで十分かつ高速です。 

グローバルな答えは 2 つの方法で更新されます。1 つは単一の最適な下向きパスを使用し、2 つ目はノードでの最良の 2 つの子の寄与の合計を使用します。これは、そのノードのすぐ下で分岐する 2 つの互いに素なパスを選択することに相当します。 

微妙な実装の詳細は、同じサブツリーからのパスを混合してはいけないということです。これは当然強制されます。`child_down`別の子エッジから生じています。 もう 1 つの重要な点は、答えはグローバルに 2 つのパスに依存するにもかかわらず、DFS の戻り値は 1 つのパスのみであるということです。

 ## 特殊なケース

 キーエッジケースは直線状のチェーンです。 このような構造では、すべてのノードが子コントリビューションを最大 1 つ持つため、どのノードも 2 つの互いに素な分岐パスの有効なペアを形成することはありません。 アルゴリズムは単一パス値のみを正しく更新し続け、答えは 2 つの別々のセグメントに可能な限り最適に分割されることによって決定され続けます。これは、チェーン内で中央の 1 つのエッジを切断することになります。 

もう 1 つのエッジケースはスターです。 ここで、すべての有効なパスは単一のエッジであり、正解は単に 2 つの最大のエッジの重みの合計です。 DFS はすべての子コントリビューションをルートで収集し、そのノードでのペアごとの組み合わせによって最適なソリューションを直接取得します。 

最後に、ゼロ重みツリーにより、より長い構造パスが誤って優先されることがなくなります。 すべての寄与はゼロであるため、すべての組み合わせは同等に評価され、アルゴリズムは構造に関係なく正しくゼロを返します。
