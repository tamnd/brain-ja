 ## 解決策
 ## 問題の理解

 直線的な山道に沿って一連の標高が与えられます。 各インデックスは位置を表し、各値は高度を表します。 あらゆるクエリに対して、私たちは特定の位置に立っています`p`そして、高さに霧の層がある間に、特定のルールの下でそこから見える他の位置がいくつあるか数えてみます。`f`高度の関係によっては、一部の視界が遮られます。 

ポジション`q`から見えるとみなされます`p`3つの条件が同時に成立する場合のみ。 まず、高度は、`q`の高度より厳密に低くなければなりません`p`したがって、クエリ ポイントに対して「下り坂」のみを調べることになります。 次に、からスキャンする場合、`p`に`q`ラインに沿って、高度が少なくとも同じ高さの中間地点に遭遇してはなりません。`a_p`、最初の高さの「壁」によって視界が遮られることを意味します。`a_p`以上。 第三に、フォグはどの低いポイントが実際にカウントされるかを変更します。フォグがより高い場合は、`a_p`、そのような目に見える低い点はすべてカウントされますが、霧が 1 以下の場合は、`a_p`、標高が少なくとも以下のポイントのみ`f`カウントされます。 

各クエリの出力は、指定された開始点からのこれらの可視性ルールを満たすインデックスの数にすぎません。 

この制約により、総当たり攻撃は実行不可能になります。 最大 100 万の位置と 10 万のクエリを使用すると、クエリごとに配列をスキャンするソリューションでは遅すぎます。 たとえ`O(NQ)`このアプローチは約 10¹¹ の操作に達しますが、これは 2 秒で実行できるほどではありません。 これにより、各クエリが対数時間以上で応答できる前処理戦略にすぐに移行できます。 

甘い解釈で現れる失敗例もいくつかあります。 よくある間違いの 1 つは、ブロック ルールを適切に無視することです。 たとえば、次のような配列では、`[1, 5, 2, 1]`、インデックスから始まる`1`（価値`5`）、 位置`4`見えないのに`1 < 5`、インデックスなので`2`価値がある`5`、それ以降のすべてをブロックします。 もう 1 つの微妙な問題は、霧の処理の誤りです。 もし`a_p = 10`そして`f = 3`、価値のあるポイント`2`は、高さの制約を満たしていても、フォグによって除外されるためカウントされません。`f ≤ a_p`。 これらの相互作用は、可視性が値に対する単純な範囲カウントではなく、動的に決定されたセグメントに制限された範囲カウントであることを意味します。 

## アプローチ

 直接的な解決策では、位置から左右にスキャンして各クエリを処理します。`p`、値以上になると停止します。`a_p`が発生し、フォグ ルールを適用しながらすべての有効な位置をカウントします。 これは、可視性の定義を正確にシミュレートするため、概念的には正しいです。 ただし、配列が厳密に増加または減少している最悪の場合、各スキャンはほぼすべての領域に影響を与えます。`N`要素。 と`Q`クエリの場合、これは次のようになります`O(NQ)`、これは許容範囲をはるかに超えています。 

重要な観察は、可視性がクエリとは独立したローカルのブロッキング構造によって制御されるということです: 各位置について`p`、そこから見えるインデックスのセグメントは固定されています。 まさに最大間隔です`p`少なくとも値を持つ要素が含まれていない`a_p`。 これは古典的な「最も近い以上の要素」構造です。 両側で最も近いブロック境界を事前に計算すると、各クエリは、固定セグメント内の値がフォグによって決定された値の範囲に入る値の数をカウントすることになります。 

これにより、問題は 2 次元の範囲カウント問題、つまり固定インデックス間隔に変換されます。`[L, R]`と値の間隔`[low, a_p - 1]`。 このための標準構造はマージ ソート ツリー (ソートされた配列のセグメント ツリー) です。これにより、値の範囲内の部分配列内の要素をカウントできます。`O(log^2 N)`時間。

 | クエリごとのブルート フォース スキャン | O(NQ) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ### 1. 可視性の境界を計算する

 あらゆるインデックスに対して`i`、値が少なくとも次の値である左右に最も近いインデックスを計算します。`a[i]`。 これは単調スタックを使用して行われます。 左から右に処理する間、最初のブロック要素をすぐに見つけられるように、減少するスタックを維持します。 

これらの境界の外側にある要素は決してブロックされないため、このステップは重要です。`a[i]`したがって、可視性とは自動的に無関係になります。 

### 2. 各位置の表示セグメントを定義します。 

インデックスごとに`i`では、次のように定義します。 

-`L[i]`前の以上の要素の右側の最初のインデックスとして
 -`R[i]`次の以上の要素の前の最後のインデックスとして

 表示されているすべての候補者`i`内にあるに違いない`[L[i], R[i]]`。 

これにより、幾何学的可視性の問題が静的な部分配列の問題に縮小されます。 

### 3. 値に対するマージソートツリーを構築する

 各ノードがセグメント内のすべての値のソートされたリストを格納するセグメント ツリーを構築します。 これにより、二分探索を使用して、指定された範囲に含まれる値の数を数えることができます。 

この構造の目的は、次の形式のクエリに答えることです。`[L, R]`、値はいくつありますか`[x, y]`”。

 ### 4. 各クエリを処理する

 お問い合わせの場合`(p, f)`、まず可視セグメントを決定します`[L[p], R[p]]`。 

次に、有効な値の範囲を決定します。 

- もし`f > a[p]`、霧は観測者の上にあるため、すべての値`< a[p]`は許可されます。つまり、下限は事実上、`1`- それ以外の場合は、次の値のみ`[f, a[p] - 1]`許可されています

 答えは次のように計算されます。 

カウントイン`[L, R]`価値観の`< a[p]`マイナス

 カウントイン`[L, R]`価値観の`< low`### なぜ効果があるのか

 正確さは、2 つの独立した制約を分離することで得られます。 最初の制約は構造的なものです。可視性はブロック要素を越えることができないため、すべての有効な位置は純粋に以下との比較によって定義された最大セグメント内に存在する必要があります。`a[p]`。 2 番目の制約は値ベースであり、フォグとエンドポイントのみに依存します。`p`、中間構造ではありません。 

どちらの制約も、素のディメンション、インデックス、値に対する単調フィルターであるため、最初にインデックス範囲を制限し、次に値範囲カウントを適用することで、それらを安全に交差させることができます。 単調スタックでは、インデックス セグメントにブロックされていない領域のみが正確に含まれることが保証されるため、値のフィルタリング ステップの前に有効なポイントが除外されたり、誤って含まれたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_merge_sort_tree(arr):
    n = len(arr)
    size = 1
    while size < n:
        size <<= 1

    tree = [[] for _ in range(2 * size)]

    for i in range(n):
        tree[size + i] = [arr[i]]

    for i in range(size - 1, 0, -1):
        tree[i] = sorted(tree[2 * i] + tree[2 * i + 1])

    return tree, size

def query(tree, size, l, r, x):
    # count of elements <= x in [l, r]
    l += size
    r += size
    res = 0

    while l <= r:
        if l % 2 == 1:
            from bisect import bisect_right
            res += bisect_right(tree[l], x)
            l += 1
        if r % 2 == 0:
            from bisect import bisect_right
            res += bisect_right(tree[r], x)
            r -= 1
        l //= 2
        r //= 2

    return res

def build_bounds(a):
    n = len(a)
    left = [-1] * n
    right = [n] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack.clear()
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    return left, right

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    left, right = build_bounds(a)

    tree, size = build_merge_sort_tree(a)

    for _ in range(q):
        p, f = map(int, input().split())
        p -= 1

        L = left[p] + 1
        R = right[p] - 1

        ap = a[p]

        hi = ap - 1
        if hi < 0 or L > R:
            print(0)
            continue

        if f > ap:
            low = 1
        else:
            low = f

        if low > hi:
            print(0)
            continue

        def count_le(x):
            return query(tree, size, L, R, x)

        ans = count_le(hi) - count_le(low - 1)
        print(ans)

if __name__ == "__main__":
    main()
```コードはまず単調スタックを構築して、最も近いブロック境界を決定します。 次に、高度配列に対してマージ ソート ツリーを構築し、各セグメント ツリー ノードが効率的にカウントできるようにソートされた値を格納します。 

各クエリは、可視性ルールを固定インデックス間隔と値間隔に変換します。 最終的な答えは、その間隔で 2 つのプレフィックス数を減算することによって得られ、これにより、必要な範囲内の値が正確に分離されます。 

微妙な点は、境界の処理です。`left[i]`そして`right[i]`ブロック要素のインデックスを格納するため、実際の有効範囲にはブロック要素が除外されます。そのため、コードでは`+1`そして`-1`形成時にズレる`[L, R]`。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリ位置がプラトーの一部であるか、最大値が繰り返される場合です。 のような配列の場合`[3, 3, 3, 1]`、インデックスから始まる`2`の場合、最も近い以上の境界がすぐにそれを囲み、可視領域がそのプラトー セグメントのみに縮小されます。 単調スタックは等価性をブロッキングとして扱い、プラトーを超える等高さの漏れがないことを保証するため、アルゴリズムはこれを正しく処理します。 

フォグが到達可能なすべての値を下回る場合には、別のケースが発生します。 配列内で`[8, 2, 7, 1]`と`f = 1`の値のみ`[1, a_p - 1]`が考慮されます。 プレフィックス数を減算すると、次の値が保証されます。`f`これは、観測者が霧の上にいるときに霧が低すぎる点の可視性をブロックするという条件と一致します。 

最後の微妙なケースは、表示されているセグメントが空の場合です。 これは、両方の隣接ノードの値が ≥ である場合に発生します。`a_p`に隣接しています`p`。 計算された間隔`[L, R]`が無効になり、コードが明示的にチェックします`L > R`ゼロを返すため、反転された境界を越える不正な範囲クエリが防止されます。
