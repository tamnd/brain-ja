 ## 解決策
 ## 問題の理解

 各テストでは 3 つの整数が得られます。 最初の 2 つの数値は、整数が「有効」であるルールを定義するものと考えてください。数値は、両方で割り切れる場合にのみ有効です。 3 番目の数値は、剰余を通じてのみ考慮される係数の上限のように機能します。 

すべての有効な数値の中から、非常に大きな数値も含めて、任意の数値を選択することができます。 選択した数値ごとに、3 番目の数値で割ったときの余りを計算します。 タスクは、これまでに得られる最大の剰余を決定することです。 

重要な問題は、有効な数値が任意ではないことです。 両方の入力で割り切れる数値は、それらの最小公倍数の倍数でなければなりません。 したがって、検索空間は最小公倍数から始まる無限の等差数列になります。 

制約の値は大きくなりますが、テスト ケースの数は中程度です。 クエリは最大で数千件あり、各値は最大 10^9 になります。 これは、テスト ケースごとに対数時間または定数時間であるソリューションを強く示唆しています。 有効な数値には制限がなく、モジュラスの上限も大きくなる可能性があるため、倍数を列挙したり、有効な数値の増加をシミュレートしたりするアプローチは、すぐに失敗します。 

単純な間違いは、c までの最小公倍数のいくつかの倍数をチェックするだけでよいと仮定することです。 最良の剰余は多くの場合、係数サイクルの開始付近ではなく、終了付近に発生するため、これは安全ではありません。 

たとえば、最小公倍数が 6 で、c が 10 であるとします。有効なシーケンスは 6、12、18、24 などです。 10 を法とした余りは 6、2、8、4、0 の繰り返しです。 最大値は 8 ですが、これは予測可能な小さなウィンドウの 1 番目または 2 番目の倍数からは得られません。 制限されたスキャンでは、カットオフに応じて見逃される可能性があります。 

もう 1 つの微妙な問題は、答えが単純に c を法とする最小公倍数であると仮定していることです。 これは、倍数が大きくなるとラップアラウンドして基本値よりも大きな剰余が生成される可能性があるため、失敗します。 

## アプローチ

 問題内のすべての有効な数値は、単一の基本値の倍数、つまり 2 つの入力の最小公倍数の形式になります。 この値を L とすると、すべての候補は L、2L、3L などとなります。 

ブルート フォース アプローチでは、これらの値を生成し、その剰余を c を法として計算し、ある範囲の後で停止します。 これは概念的には正しいですが、どこまで到達する必要があるかについて自然な上限がないため、すぐに破綻します。 c が 10^9 になる可能性がある場合、最初の c 倍数に制限するだけでもすでに大きすぎます。 

重要な観察は、元の整数に対して最適化しようとしているのではなく、c を法とする剰余に対して最適化しようとしているということです。 すべての有効な数値を c を法として削減すると、構造は周期的になります。 シーケンス (k・L) mod c は、モジュラー演算における単純な巡回サブグループを形成します。 ステップ サイズは固定されているため、到達可能な残基はモジュラー円の周りに等間隔に配置されます。 

この構造は、到達可能な残基のセットが正確に gcd(L, c) の倍数のセットであることを意味します。 これから、到達可能な最大残基は、c よりも小さい gcd の最大倍数 (c から gcd を引いたもの) になります。 

したがって、問題は完全に L を計算してから 1 回の gcd 操作に帰着します。

 | --- | --- | --- | --- |
 | ブルートフォース | テストごとに O(c / LCM ステップ)、最悪の場合は無制限 | お(1) | 遅すぎる |
 | 最適 | O(log a + log b + log c) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 L を a と b の最小公倍数とし、g を L と c の最大公約数とします。

1. g1 = gcd(a, b) を計算します。 これにより、a と b の間の素因数の重複が特定され、LCM を構築する際のオーバーフローが防止されます。 最小公倍数は a * b / g1 です。 
2. 乗算の前に除算を使用して L を慎重に計算します: L = (a // g1) * b。 これにより、Python は技術的には大きな整数を安全に処理できますが、32 ビット境界を超える中間オーバーフローが回避されます。 
3. g = gcd(L, c) を計算します。 これは、c を法とする到達可能な残基の間隔を取得します。 モジュラー算術では、有効な数値はすべて g の倍数になります。 
4. c ～ g を答えとして返します。 これは、c を法とする L によって生成される剰余クラスにある c より厳密に小さい最大値です。 

ステップ 3 が正しい理由は、c を法とする L を乗算すると、c を法とする加法群の循環サブグループが生成されるためです。 サブグループのサイズは完全に gcd(L, c) によって決定され、到達可能なすべての残基は正確にその gcd の倍数になります。 

## なぜ機能するのか

 すべての有効な数値は L の倍数です。モジュロ c を削減すると、これが固定ステップ サイズ L mod c の繰り返し加算に変わります。 したがって、到達可能な残基のセットは、c を法とする環内で L によって生成される加法部分群になります。 このサブグループには、gcd(L, c) のすべての倍数が正確に含まれます。 そのセット内の最大の要素は、c を超えてラップする前の最後の倍数、つまり c から gcd(L, c) を引いたものです。 L の増分はこの固定格子内でのみ移動するため、これより大きな残差には到達できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        
        g1 = gcd(a, b)
        l = (a // g1) * b
        g = gcd(l, c)
        
        out.append(str(c - g))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は代数に直接に従います。 唯一のデリケートな部分は、中間ステップでオーバーフローを発生させずに LCM を構築することですが、これは乗算する前に除算することで処理されます。 

最後の引き算`c - g`これは、モジュラーサイクルで到達可能な最高の残基を選択することに対応します。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
a = 2, b = 3, c = 10
```ここで L = 6 です。倍数の表は次のとおりです。 

| k | d = kL | d モッド c |
 | --- | --- | --- |

 | 3 | 18 | 8 |

 | 5 | 30 | 0 |

 最大値は 8 です。gcd(6, 10) = 2 であるため、式は 10 - 2 = 8 となり、表と一致します。 

次に、次のことを考えてみましょう。```
a = 4, b = 2, c = 2023
```ここで L = 4 です。2023 は 2 または 4 で割り切れないため、c の gcd は 1 になります。 

| k | d = 4k | dmod2023 |
 | --- | --- | --- |
 | 1 | 4 | 4 |
 | 2 | 8 | 8 |
 | 3 | 12 | 12 |

 到達可能な剰余は、最終的に 2023 を法とする 1 の倍数をすべてカバーするため、最大値は 2022 になります。この式では、2023 - 1 = 2022 が得られます。

 ## 特殊なケース

 a と b が同一の場合、最小公倍数は同じ値に集約され、到達可能なセットはその数値の倍数になります。 入力 6 6 10 の場合、L は 6、gcd(6, 10) は 2 であるため、答えは 8 mod 10 となり、10 − 2 = 8 と一致します。 

a と b が互いに素の場合、L はそれらの積になりますが、gcd(L, c) はその積が c とどのように相互作用するかのみに依存するため、構造は単純化されます。 共有因子が存在しない場合、gcd は 1 で、答えは c − 1 になります。これは、0 を除くすべての剰余が到達可能であることを意味します。 

c がすべての素因数を L と共有する場合、gcd は c に等しく、答えは 0 になります。これは、すべての有効な数値が常に c で割り切れるため、正の剰余が出現しない場合に対応します。
