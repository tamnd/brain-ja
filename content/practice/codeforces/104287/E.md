 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、最初の配列を 2 番目の配列と同一になるまで変更できます。 コストモデルには 2 つの部分があります。 まず、任意の位置で各ユニットをインクリメントまたはデクリメントするには 1 回の操作が必要となるため、次の値を変更すると`x`に`y`費用`|x - y|`。 2 番目に、オプションの構造操作が 1 つあります。固定長の連続したセグメントを 1 つ選択できます。`k`そして左に一回転させます。 この回転の後、セグメント内の要素は循環的に並べ替えられますが、外側の要素はすべて所定の位置に留まります。 

タスクは、最初の配列を 2 番目の配列に変換するために必要な操作の最小総コストを見つけることです。この場合、回転はまったく使用しないか、有効な長さのセグメントに対して 1 回だけ使用するかのどちらかです。`k`。 

この制約により、ソリューションはテスト ケースごとに線形に近くなければならないことが明確になります。 すべてのテストの合計サイズは最大でも`2 · 10^5`なので、二次関数は何でも`n`テストごとに実行することは直ちに不可能です。 たとえ`O(n log n)`テストごとは慎重に実装された場合にのみ許容されますが、ここでは構造が次のことを強く示唆しています。`O(n)`または`O(n log n)`配列を単純に渡すだけで解決できます。 

単純なアプローチでは、考えられるすべての回転セグメントを試し、完全な変換コストを最初から再計算します。 これは小さな例ではすでに失敗しています。 

たとえば、次のように仮定します`n = 5`そして`k = 3`。 ブルートフォース手法ではセグメントを試行します`[1,3]`、`[2,4]`、`[3,5]`、毎回回転を適用し、合計コストを再計算します。 それぞれの再計算は`O(n)`、与える`O(n^2)`全体。 これでは遅すぎる`n`到達する`2 · 10^5`。 

より微妙な失敗ケースは、値が大きいが構造化されている場合に発生します。たとえば、次のような場合です。`a`そして`b`回転すると値が完全に揃う小さなウィンドウを除いて、同じです。 単純な方法では、ローテーションによる改善がグローバルな再計算ではなく、ローカルな変更のみに依存することを見落とす可能性があります。 

## アプローチ

 回転を無視すると、問題は完全に単純になります。 各位置は独立しており、コストは対応する要素間の絶対差の単純な合計になります。 これにより基本的な答えが得られます。 

問題は、許可される循環シフトが 1 つだけであることにあります。 重要な点は、この操作では 1 つのサイズのウィンドウ内の値のみを並べ替えることです。`k`。 ウィンドウの外側のすべては変更されないため、そのウィンドウ内のコスト寄与のみが影響を受けます。 

強引なアイデアは、可能な長さのすべてのセグメントを試してみることです`k`、回転をシミュレートし、総コストを最初から再計算します。 これは概念的に機能します。`n - k + 1`選択肢はありますが、それぞれのシミュレーションに費用がかかります`O(n)`、につながる`O(n^2)`テストケースごとに。 

この改善は、配列の影響を受けない部分を影響を受けるウィンドウから分離することで実現します。 選択したセグメントの外側では、コストへの寄与は回転の前後で同じです。 セグメント内では回転のみが変化します。`a`要素がどの要素とペアになっているか`b`位置。 これにより、事前に計算された少数の合計に関して新しいコストを表現できるようになります。 

すべてを再計算するのではなく、ベースラインの不一致コストを事前に計算し、そこに回転を適用した場合にコストがどのように変化するかをウィンドウごとに計算します。 これにより、線形前処理後の各候補の評価が一定時間に短縮されます。

 ## アルゴリズムのチュートリアル

 まず、配列を変更しない場合のコストを計算します。 これは単純に、次の間の絶対差の合計です。`a[i]`そして`b[i]`。 

次に、セグメントに回転を適用すると何が起こるかを分析します。`[l, r]`どこ`r = l + k - 1`。 

1. ベースライン不一致配列を事前計算する`base[i] = |a[i] - b[i]|`。 これは、回転が使用されない場合の総コストに対する各位置の寄与を表します。 
2. ヘルパー不一致配列を定義する`shift_cost[i] = |a[i+1] - b[i]|`要素が左にシフトされるウィンドウ内の位置。 これは、回転後のセグメントの最後の位置を除くすべての位置で起こることに対応します。`i`値を受け取ります`a[i+1]`。 
3.固定窓の場合`[l, r]`、回転後のウィンドウ内のコストを計算します。 ポジションについて`l`に`r-1`、費用は`|a[i+1] - b[i]|`、そして位置について`r`、費用は`|a[l] - b[r]|`。 
4. プレフィックス合計を使用してこれを効率的に表現します。 合計が終わりました`shift_cost[l .. r-1]`は O(1) でクエリでき、最後の項は直接計算されます。 
5. 同じウィンドウの元のベースライン コストを差し引きます。これは、次の合計です。`base[l .. r]`、プレフィックスサム経由でも利用できます。 
6. この差により、回転を適用することによる純利益または損失が得られます。`[l, r]`。 
7. 有効なすべての値についてこの値を計算します。`l`すべてのウィンドウで最小値を取得します。 最終的な答えは、何もしない場合と最適な回転を適用する場合との間の最小値です。 

### なぜ効果があるのか

 重要な不変条件は、選択したセグメント内のインデックスのみが、次の要素との組み合わせを変更できるということです。`b`。 セグメント外のすべてのインデックスは、回転の前後でまったく同じコストに寄与します。 セグメント内では、各位置は正確に 1 つの新しい値を受け取り、そのマッピングは完全に決定的です。単一の左循環シフトは長さの固定順列に対応します。`k`。 コスト関数はインデックス間で分離可能であるため、総コスト差は独立した位置ごとの差の合計に分解され、プレフィックス合計を使用して集計できます。 これにより、各セグメントを個別に評価するだけで十分であり、グローバルな相互作用が見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = [abs(a[i] - b[i]) for i in range(n)]
        pref_base = [0] * (n + 1)
        for i in range(n):
            pref_base[i + 1] = pref_base[i] + base[i]

        # shift contribution: a[i+1] matches b[i]
        shift = [0] * (n - 1)
        for i in range(n - 1):
            shift[i] = abs(a[i + 1] - b[i])

        pref_shift = [0] * (n)
        for i in range(n - 1):
            pref_shift[i + 1] = pref_shift[i] + shift[i]
        pref_shift[n - 1] = pref_shift[n - 2] if n > 1 else 0

        best_delta = 0

        if k == 1:
            # rotation does nothing
            print(pref_base[n])
            continue

        for l in range(0, n - k + 1):
            r = l + k - 1

            # cost of shifted positions l..r-1
            shifted_sum = pref_shift[r] - pref_shift[l]

            # last position uses a[l]
            last_cost = abs(a[l] - b[r])

            new_cost = shifted_sum + last_cost
            old_cost = pref_base[r + 1] - pref_base[l]

            delta = new_cost - old_cost
            best_delta = min(best_delta, delta)

        print(pref_base[n] + best_delta)

if __name__ == "__main__":
    solve()
```実装は、ベースライン コストを計算し、プレフィックスの合計を保存することから始まり、任意の範囲コストを一定時間内にクエリできるようになります。 2 番目のプレフィックス配列は、シフトされた配置に対して構築され、配列内の次の要素を受け取った場合の各位置のコストを表します。 

回転ウィンドウのすべての有効な開始位置にわたるループは、そのウィンドウの新しいコストを定数時間で計算します。 シフトされた部分は事前計算されたプレフィックスから取得されますが、ウィンドウの最後の要素はセグメントの最初の要素に折り返されるため、個別に処理されます。 

答えは、回転をまったく適用しない可能性も含め、すべてのセグメントにわたる最良の改善を追跡します。

これは、アルゴリズムが有益でない場合には回転を強制しないことを示しています。 

### サンプル トレース 2

 回転が役立つ場合については、値が周期的にずれているウィンドウを考えてみましょう。

 ここでは、シフトされた位置合わせにより、選択したウィンドウ内の不一致が大幅に減少します。 アルゴリズムはこれを最小デルタとして識別し、それを 1 回適用して、ベースラインよりも低い総コストを生成します。 

これにより、ウィンドウ分解が無関係な位置に影響を与えることなく、ローカル順列の利点を正しく捉えていることが確認されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`k = 1`。 この状況では、許可される回転は何も行われないため、答えは絶対差の合計に換算される必要があります。 このアルゴリズムは、ベースライン コストをすぐに返すことでこれを明示的に処理し、シフトされた配列でオフバイ 1 エラーが発生する不必要なプレフィックス計算を回避します。 

別のエッジケースが発生するのは次の場合です。`k = n`。 ここで、回転は配列全体に適用され、アルゴリズムはすべてのインデックスをカバーする単一のウィンドウを正しく評価します。 配列の最初の要素が回転後の最終位置として使用されるため、ラップアラウンド項は依然として正しく処理されます。 

3 番目のケースは、最適解が回転をまったく使用しない場合です。 これは、最適なデルタをゼロに初期化し、厳密に優れた構成が見つかった場合にのみそれを更新することで処理され、ローテーションごとにコストが増加してもベースライン ソリューションが有効なままであることが保証されます。
