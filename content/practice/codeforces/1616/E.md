 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられており、最初の文字列を変更できるのは、隣接する文字を交換することだけです。 各スワップには 1 回の操作が必要です。 目標は、最小のスワップ数を使用して、最初の文字列の結果のバージョンを辞書編集的に 2 番目の文字列よりも小さくするか、それがまったく不可能であると判断することです。 

重要な問題は、文字列を完全に並べ替えたり、特定のターゲットに変換したりしようとしていないことです。 代わりに、変換された文字列が固定文字列よりも厳密に小さくなる瞬間のみを考慮します。`t`辞書編集的な比較の下で、できるだけ安価にその状態に到達したいと考えています。 

最大 2 × 10^5 の長さの合計の制約は、テスト ケースごとに、すべての解が線形または線形演算に近い必要があることを意味します。 スワップを明示的にシミュレートしたり、最初の不一致に対してすべてのポジションを試したりするアプローチは、コストを素朴に再計算すると遅すぎます。 操作は隣接するスワップであるため、各移動コストは実質的に反転距離となり、スワップをシミュレートするのではなく、キャラクターが移動する距離を追跡する構造を示唆しています。 

微妙なエッジケースが現れるのは、`s`はすでに辞書編集的により小さくなっています`t`。 この場合、答えはゼロになりますが、それは次の場合に限られます。`s < t`再配置後に小さくなった場合はそうではありません。 もう 1 つの注意が必要なケースは次のような場合です。`s`たとえば、両方の文字列に同一のマルチセットが含まれている場合や、`s`はすでに辞書編集上最大の配置となっています`t`。 最初の不一致を貪欲に修正する素朴な貪欲なアプローチは、後の交換によって以前の改善が無効になる可能性があるため、失敗する可能性があります。 

強欲が失敗する例:```
s = "bca"
t = "bac"
```最初のキャラクターを貪欲に修正すると、不必要な交換につながる可能性がありますが、最適な戦略は、小さいキャラクターをどれだけ前進させるかによって決まります。 

中心的な観察は、辞書編集上の比較は文字列が異なる最初の位置のみに依存するため、一致する最も古い位置を作成するように努めるべきであるということです。`s[i] < t[i]`、以前のすべての位置が等しいことを確認しながら。 

## アプローチ

 強引なアイデアは、隣接するスワップの可能なすべてのシーケンスをある限界までシミュレートし、実行できるかどうかを確認することです。`s`より小さい`t`。 スワップごとに新しい状態が生成されるため、これは本質的に順列の最短パスになります。 分岐係数が大きく、状態空間が`n!`, そのため、すぐに剪定することさえ不可能になります。 州を越える BFS であっても、それを超えることは不可能です`n ≤ 10`。 

次の単純な改善は、最初の位置を固定することです`i`私たちが望む場所`s[i] < t[i]`、次に、より小さい文字を持ってくるようにしてください。`t[i]`所定の位置に`i`隣接スワップを使用します。 各候補文字について、そのコストを、それを前に出すために必要な反転の数として計算します。 ただし、すべてのポジションについてこれらのコストをゼロから再計算すると、次のようになります。`O(n^2)`テストケースごとに、遅すぎます。 

重要な洞察は、位置を左から右に処理し、各キャラクターの現在の位置を維持することです。 距離を再計算する代わりに、最も近い文字の出現を検索し、それを「使用」するときに削除することをサポートする動的構造を維持します。 フェンウィック ツリーまたはポジション上の BIT を使用すると、2 つのインデックスの間にアクティブなキャラクターが何人いるかを計算でき、これによりスワップ コストが直接得られます。 

戦略は次のようになります。 各ポジションについて`i`、キャラクターを配置できるかどうかを尋ねます`c < t[i]`位置にある`i`以前のすべてのポジションを変更せずに、最小限のコストで。 残りのポジションの注文統計を使用してコストを計算します。 すべての有効な選択肢から最小値を取得し、文字を元の位置から「削除」するときに構造を更新します。 

これにより、問題は対数コスト クエリによるポジションの貪欲なスイープに変わります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず次のことを確認します。`s`はすでに辞書編集的により小さくなっています`t`。 「はい」の場合、戻ります`0`。 どの操作もコストをゼロ以上に削減できず、すぐに停止できるため、これは安全です。 
2. どのポジションにあるかを把握する体制を維持します。`s`まだ「未使用」です。 最初はすべてのポジションがアクティブです。 また、出現箇所を効率的に取得できるように、文字ごとにその位置のキューを維持します。 
3. インデックスを反復処理します`i`左から右に、厳密な不平等が生じる可能性がある最初の位置として扱います。 
4. 位置で`i`より厳密に小さい文字を配置できるかどうかを検討します。`t[i]`。 キャラクターごとに`c`から`'a'`に`t[i]-1`、未使用のオカレンスがあるかどうかを確認します。`c`。 
5. 位置にそのような事象が存在する場合`j`、位置に移動するコストを計算します。`i`。 コストは、次の間で現在アクティブなキャラクターの数です。`j`そして`i`、これは、バブルを残すために必要なスワップの数を表します。 これはフェンウィック ツリーを使用して計算されます。 
6. 当社は、有効なすべての費用のうち最小の費用を負担します。`c`そして全体的な回答候補を更新します。 
7. それとは別に、私たちは以前の地位についても平等を維持しなければなりません。 もし`s[i]`まだ利用可能な場合は、位置で「一致」させます`i`アクティブ セットから削除して続行します。 
8. 答えは、少なくとも 1 つの有効なポジションが達成可能である場合に、すべてのポジションで見つかった最小コストです。 作成できるポジションがない場合`s < t`、戻ります`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、インデックスを処理する前の不変式に依存します。`i`、すべてのポジション`< i`一致するようにすでに修正されています`t`最小限のコストで可能な限り近づけます。 有効なソリューションはすべて次のものと異なっていなければなりません`t`不等式が導入される最初の位置で、各インデックスで候補を列挙することで、すべての最適なブレークポイントがカバーされます。 フェンウィック ツリーは、各候補を実現するコストが、以前に固定された位置を乱すことなくキャラクターを前に出すために必要なスワップの数として正確に計算されることを保証します。 各文字は 1 回だけ削除されるため、二重カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        if i < 0:
            return 0
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = list(input().strip())
        t = list(input().strip())

        if s < t:
            print(0)
            continue

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i)

        used = [False] * n
        bit = BIT(n)

        for i in range(n):
            bit.add(i, 1)

        ans = float('inf')

        for i in range(n):
            ci = ord(t[i]) - 97

            for c in range(ci):
                if pos[c]:
                    j = pos[c][-1]
                    if not used[j]:
                        cost = bit.range_sum(j, i) - 1
                        ans = min(ans, cost)

            if pos[ord(s[i]) - 97]:
                j = pos[ord(s[i]) - 97].pop()
                used[j] = True
                bit.add(j, -1)

        print(ans if ans != float('inf') else -1)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、任意のプレフィックス内でまだアクティブな文字の数を追跡します。 文字の削除は、使用されている文字をマークし、BIT を更新することに相当します。 表現`bit.range_sum(j, i) - 1`キャラクターを所定の位置に移動するために必要なスワップの回数を正確にカウントします`j`所定の位置に`i`。 

微妙な点は、リストから最後に出現した文字を常に取得することです。 これが機能するのは、オカレンスを逆方向に効果的に消費しているためです。これは、以前の位置での干渉を最小限に抑えることと一致しています。 

早めのチェック`if s < t`すでに有効なケースでの不必要な計算を回避します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次の文字より小さい文字がない場合です。`t[i]`～のどこにでも存在する`s`ある位置で`i`。 その場合、そのインデックスでは有効な辞書編集上の改善を作成できないため、アルゴリズムは答えを更新せずに正しく続行されます。 

もう 1 つのエッジケースは次のような場合です`s`すでに よりも小さいです`t`。 このアルゴリズムは、構造が構築される前に直ちにゼロを返し、不必要な計算を回避し、些細な入力の正確性を保証します。 

最後のケースは、最適な動きが右端のキャラクターに関係する場合です。 BIT により、すべての中間文字が正しくカウントされることが保証されるため、長距離スワップでも正確に請求されます。
