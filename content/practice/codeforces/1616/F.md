 ## 解決策
 ## 問題の理解

 与えられた小さな無向グラフでは、すべてのエッジが最終的に 3 色のいずれかで塗られることになっています。 一部のエッジはすでに色で固定されていますが、他のエッジは最初は色付けされていないため、値を割り当てる必要があります。`{1, 2, 3}`。 

制約は単一のエッジまたは頂点に対してローカルではありません。 ペアごとに接続された 3 つの頂点によって形成されるすべての三角形は、非常に厳密な規則を満たす必要があります。つまり、その三角形の 3 つの辺を見ると、3 つの色すべてが同一であるか、3 つの色すべてが異なるかのいずれかです。 2 つが同じで 1 つが異なるなどの混合パターンは禁止されます。 

タスクは、部分的なカラーリングを完全に有効なカラーリングに完了できるかどうかを判断し、完了した場合はそのような完了を出力することです。 

グラフの頂点は最大 64 個と小さく、エッジは最大 256 個とまばらです。これは、単純な方法ですべての頂点のトリプルにわたる重い組み合わせ論に依存するのではなく、むしろ構造的一貫性の制約を利用することが期待されることをすでに示唆しています。 

重要な点は、条件がグラフ内に存在する三角形にのみ適用されることです。 いくつかのエッジが欠落している場合、多くの頂点のトリプルは無関係です。 これは、制約がまばらであるが相互依存性が高いことを意味します。 

よくある失敗モードは、各三角形を個別に扱うことです。 たとえば、エッジが複数の三角形に関与している場合、局所的に各三角形を貪欲に満たすと、一貫性が損なわれる可能性があります。 もう 1 つの微妙な問題は、接続コンポーネントごとまたは頂点隣接リストごとに独立して色を割り当てるだけで十分であると想定していることです。これは、グローバルな一貫性を無視しています。 

最小限の失敗構成は、重なっている三角形に表示されます。 エッジを仮定します`(1,2)`、`(2,3)`、`(1,3)`三角形を形成し、`(1,3)`別のトライアングルにも参加`(1,3,4)`。 最初の三角形を固定するローカル割り当ては、後で 2 番目の三角形と矛盾する可能性があります。 

この相互依存が問題の核心です。 

## アプローチ

 強引なアイデアは、色の付いていない各エッジに 3 色のいずれかを割り当て、すべての三角形をチェックすることです。 エッジは最大 256 個あるため、検索スペースは次のようになります。`3^k`どこ`k`色付けされていないエッジの数です。 制約を早期にチェックしてプルーニングしたとしても、これは依然として指数関数的であり、実行不可能です。 

制約の構造は、より強力なものを示唆しています。三角形は任意の制約ではなく、代数的一貫性を定義します。 「すべて等しいか、すべて異なる」というルールは、まさに、3 つのクラスへの分割と一致する 3 エッジ カラーリングとして知られる構造のシグネチャ、または同等の、隠れた頂点ポテンシャルの下でサイズ 3 のグループの加算のように動作するラベル付けです。 

重要な洞察は、エッジの色を頂点ラベル間の違いとして解釈することです。`{0,1,2}`モジュロ 3. 各頂点に値を割り当てるとします。`x[v] ∈ {0,1,2}`の場合、エッジの色を次のように定義できます。`(x[u] - x[v]) mod 3`にマッピングされる`{1,2,3}`。 この構造では、すべての三角形が自動的に条件を満たします。 

すべての頂点ラベルが等しい場合、すべてのエッジの差は 0 であるため、すべてのエッジは同じ色になります。 すべての頂点ラベルが個別である場合、すべてのペアごとの差異が 3 つの残基すべてをカバーし、3 つの個別の色が生成されます。 

その逆は、十分な制約がある接続コンポーネントにも当てはまります。三角形のルールと一致する有効なカラーリングは、そのような頂点の可能性をグローバル シフトまで誘発します。 これにより、エッジのカラーリングから頂点割り当ての一貫性までの問題が軽減されます。 

したがって、タスクは次のようになります。`{0,1,2}`事前に色付けされたすべてのエッジが差分制約を強制するように、各頂点に適用されます。 次に、これらの制約を伝播し、矛盾を検出します。 

これで、頂点に対して BFS/DFS を使用して、エッジをフォームの制約として扱い、これを解決できるようになりました。`x[v] = x[u] + d (mod 3)`どこ`d`エッジの色によって異なります。 

エッジに色が付けられていない場合、制約は課されませんが、頂点が割り当てられると、その色が決定されます。 

エッジ上のブルート フォースは、頂点上の線形伝播問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^m · n²) | O(n + m) | 遅すぎる |
 | 最適 (頂点上の制約の伝播) | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、エッジ制約を頂点ラベルのモジュラー方程式に変換します。 

1. すべての頂点に初期値「未割り当て」を割り当てます。 後で値を割り当てます`{0,1,2}`。 
2. 色付きのエッジごとに`(u, v, c)`、色をエンドポイント間のモジュラー差分制約として解釈します。 次のようなマッピングを修正します。`1 → 0`、`2 → 1`、`3 → 2`、色は剰余 mod 3 を表すことを意味します。 

両方向を強制します。`x[v] = (x[u] + d) mod 3`そして`x[u] = (x[v] - d) mod 3`。 

このステップでは、エッジ制約を小さな循環グループにわたる線形方程式に変換します。 
3. すべての頂点に対して BFS または DFS を実行します。 ラベル付きの頂点をラベルのない頂点に接続するエッジに遭遇するたびに、制約を使用して近傍を割り当てます。 ネイバーがすでに割り当てられている場合は、整合性が検証されます。 

矛盾がある場合は、方程式系が矛盾していることを意味するため、有効な色付けが存在しません。 
4. 制約グラフの各接続コンポーネント内で頂点値が完全に決定された後、エッジに色を割り当てます。 

各エッジについて`(u, v)`:

 - 計算する`diff = (x[u] - x[v]) mod 3`- に変換し直す`{1,2,3}`5. もともと色が付けられていなかったエッジの場合、この計算された値が最終的な色になります。 
6. すべてのエッジカラーを入力順に出力します。 

重要な考え方は、頂点ラベルが一致すると三角形の制約が自動的に満たされるため、三角形を明示的にチェックすることは決してないということです。 

### なぜ効果があるのか

 不変条件は、BFS 中に、割り当てられたすべての頂点値が以前に処理されたすべての制約と一致することです。これは、すべてのカラー エッジが固定モジュラー差分方程式を満たすことを意味します。 各三角形は 3 つのエッジで構成されているため、任意の三角形の周囲の差の合計は 0 mod 3 である必要があり、これにより三角形が単色か完全な虹のいずれかであることが保証されます。 三角形構造の違反は頂点の割り当てに矛盾があることを意味し、BFS はすでに割り当てられている頂点を再訪するときにそれを検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        adj = [[] for _ in range(n)]
        
        def to_diff(c):
            return c - 1  # map 1,2,3 -> 0,1,2
        
        for i in range(m):
            a, b, c = map(int, input().split())
            a -= 1
            b -= 1
            edges.append((a, b, c))
            if c != -1:
                d = to_diff(c)
                adj[a].append((b, d))
                adj[b].append((a, (-d) % 3))
            else:
                adj[a].append((b, None))
                adj[b].append((a, None))
        
        from collections import deque
        
        color = [-1] * n
        ok = True
        
        for i in range(n):
            if color[i] != -1:
                continue
            color[i] = 0
            q = deque([i])
            
            while q and ok:
                u = q.popleft()
                for v, d in adj[u]:
                    if d is None:
                        continue
                    if color[v] == -1:
                        color[v] = (color[u] + d) % 3
                        q.append(v)
                    else:
                        if color[v] != (color[u] + d) % 3:
                            ok = False
                            break
        
        if not ok:
            print(-1)
            continue
        
        res = []
        for a, b, c in edges:
            if c != -1:
                res.append(c)
            else:
                diff = (color[a] - color[b]) % 3
                res.append(diff + 1)
        
        print(*res)

if __name__ == "__main__":
    solve()
```この実装では、まず、各色のエッジがその端点間のモジュラー方程式となる制約グラフを構築します。 BFS は頂点ラベルを割り当て、即座に整合性をチェックします。 ラベルが固定されると、計算された差分を使用して、色の付いていないすべてのエッジが直接解決されます。 

よくある実装の落とし穴は、逆制約を作成するときに、負の差に対するモジュロ正規化の処理を忘れることです。 もう 1 つの微妙な点は、BFS の伝播中に色の付いていないエッジが無視されることです。 これらは制約を課すものではなく、整合性チェックに影響を与えてはなりません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、矛盾を強制する制約のサイクルです。 たとえば、エッジが意味する場合、`x1 = x2`、`x2 = x3`、`x3 = x1 + 1 mod 3`の場合、BFS は最初の 2 つのエッジに一貫した値を割り当てますが、最後のエッジを処理するときに、すでに割り当てられている頂点を再検討し、不一致を検出します。 アルゴリズムは正しく出力します`-1`一貫した頂点ラベルが存在しないためです。 

もう 1 つのケースは、各コンポーネントが独立した制約を持つ、切り離されたグラフです。 BFS は未訪問の各頂点から再開し、新しい頂点を割り当てます。`0`ベースライン。 これが機能するのは、世界的な変化の下でも解が不変であるためです。`{0,1,2}`、そのため、コンポーネント間の一貫性に影響を与えることなく、各コンポーネントを独立して固定できます。 

3 番目のケースは、すべてのエッジが色付けされていない場合です。 BFS はすべての頂点を割り当てます`0`、すべてのエッジが色になります`1`。 すべての三角形が単色であるため、これは三角形の条件を自明に満たしており、アルゴリズムが制約の不在を自然に処理していることを示しています。
