 ## 解決策
 ## 問題の理解

 整数の配列とターゲット値が与えられます。`x`。 タスクは、連続して選択された要素に対する制約付きで、この配列からできるだけ多くの要素を選択することです。完全に選択された少なくとも 2 つの長さの連続した部分配列は、少なくとも平均を持たなければなりません。`x`。 同様に、完全に選択された長さのサブセグメントの合計`k`少なくとも`k * x`。 長さ 1 の部分配列は除外されるため、単一要素はいつでも選択できます。 

入力は複数のテスト ケースを提供します。 各ケースは配列サイズで構成されます`n`、配列要素、および整数`x`。 配列の長さは 50,000 要素に達する可能性があります。これは、サブセグメントの数が二次関数的に増加するため、すべてのサブセグメントを直接反復するソリューションは遅すぎることを意味します。 

すべての数値が負の場合、または次の場合に、いくつかの非明白なエッジ ケースが発生します。`x`が負であるか、配列要素に大きな正と大きな負が混在している場合。 たとえば、配列が次の場合、`[10, -1, 10]`そして`x = 5`、3 つすべてを選択すると部分配列に違反します`[10, -1]`なぜなら`10 + (-1) = 9 < 2 * 5 = 10`。 連続する合計を考慮せずに、単純に最大の数値を貪欲に選択すると、このシナリオでは失敗します。 

最適な選択が連続していない場合、別の微妙な問題が発生します。 値の降順で要素を選択するのは自然なことのように思えるかもしれませんが、後でより小さい数を選択すると、部分配列の平均制約が破られる可能性があります。 これは、価値の高い要素を個別ではなく組み合わせて優先する必要がある構造を示唆しています。 

## アプローチ

 ブルートフォース手法では、配列の考えられるすべてのサブセットを考慮し、完全に選択された少なくとも 2 つの長さのサブセグメントをすべてチェックし、実行可能な最大の選択をカウントします。 長さの配列の場合`n`、 がある`2^n`サブセット。 たとえ`n = 20`、これは容認できないほど遅いでしょう、ましてや`n = 50,000`。 ブルート フォースはすべての可能性を試すため、原理的には機能しますが、サブセットの数が指数関数的に増加するため実行不可能です。 

重要な洞察は、要素が大きくなると、サブ配列の合計制約が弱くなるということです。 これは、配列を降順に並べ替えて、最初に最大の要素を選択しようとすることを示唆しています。 要素を最大から最小の順に処理すると、各ステップで選択した要素の合計と選択した要素の数を維持できます。 最初の平均`k`要素は単純に合計を で割ったものです。`k`。 ある時点で平均値が下回った場合`x`、小さな要素を追加しても改善されないため、やめます。 この観察により、問題は並べ替え後の貪欲な戦略に帰着します。つまり、累積平均が下回るまで降順で要素を選択するというものです。`x`。 

この戦略は、サブ配列の条件が完全に選択された連続セグメントにのみ関係するため機能します。 並べ替えにより、選択したプレフィックスが可能な限り「最も重い」ものとなり、このプレフィックスのサブセグメントの平均が少なくともプレフィックス平均以上であることが保証されます。 プレフィックス平均が満たされる場合`x`、そのすべての連続する部分配列も満たされます`x`。 したがって、この貪欲なプレフィックスのアプローチは正しく、効率的です。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`、配列`a`、および整数`x`。 
2. 並べ替え`a`降順で。 これにより、プレフィックスの選択により合計が最大化され、これが平均制約を維持するための鍵となります。 
3. 2 つの変数を初期化します。`total_sum = 0`選択した要素の合計を追跡し、`selected_count = 0`選択できる要素の数を追跡します。 
4. ソートされた配列を反復処理します。 要素ごとに`a[i]`に追加します`total_sum`そして増加します`selected_count`。 現在の平均を次のように計算します。`total_sum / selected_count`。 
5. 平均値を下回った場合`x`、最後に追加された要素を含めることはできません。 繰り返しをやめてください。 選択可能な要素の最大数は次のとおりです。`selected_count - 1`。 それ以外の場合は続行します。 
6. 反復が終了したら、テスト ケースに対して選択された要素の数を出力します。 

これが機能する理由は、ソートされたプレフィックスの連続する部分配列の合計が少なくともその長さに比例するためです。これは、末尾から要素を削除しても残りの要素の平均が増加するだけであるためです。 したがって、合計プレフィックス平均が少なくとも`x`、長さが 2 以上の連続するすべての部分配列は、元の制約を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        x = int(input())
        
        a.sort(reverse=True)
        total_sum = 0
        selected_count = 0
        
        for i in range(n):
            total_sum += a[i]
            if total_sum >= x * (i + 1):
                selected_count = i + 1
            else:
                break
        
        print(selected_count)

if __name__ == "__main__":
    solve()
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 配列を降順に並べ替えると、貪欲なプレフィックス チェックが可能になります。`total_sum >= x * (i + 1)`プレフィックスの平均制約を保証します。 すべてのサブ配列をチェックする必要はありません。プレフィックスの平均値が一致する場合、プレフィックス プロパティにより、すべての連続するサブ配列が平均要件を満たすことが保証されるためです。
