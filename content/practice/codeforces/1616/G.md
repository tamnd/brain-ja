 ## 解決策
 ## 問題の理解

 この問題は、すべてのエッジが小さい番号の頂点から大きい番号の頂点を指す有向非巡回グラフ (DAG) を提示します。 私たちの目標は、頂点ペアの数をカウントすることです。`(x, y)`と`x > y`エッジを追加するように`x -> y`ハミルトニアン パス、つまりすべての頂点を 1 回だけ訪れるパスを作成します。 各テスト ケースは頂点の数を提供します。`n`、エッジの数`m`、およびエッジのリスト。 出力は、テスト ケースごとに 1 つの整数、つまり有効なエッジの数です。 

とすれば`n`150,000 に達する可能性があり、`m`最大 150,000 の二次複雑度を持つアルゴリズムも同様に`n`遅すぎるでしょう。 具体的には、O(n²) 解では、最悪の場合、2×10¹⁰ 程度の演算が必要となる可能性がありますが、これは 1 秒の制限時間では実行不可能です。 これにより、あらゆる可能性を試みる素朴なアプローチが排除されます`(x, y)`ペアを作成し、エッジの追加とその後のハミルトニアン パス チェックをシミュレートします。 メモリの制約により、大きなグラフの完全な隣接行列を保存することもできなくなります。 

微妙なエッジ ケースには、元の DAG がすでにハミルトニアン パスを形成している状況が含まれます。 たとえば、グラフが次のような場合`1 -> 2 -> 3 -> 4`、任意の後方エッジ`x -> y`と`x > y`機能します。 もう 1 つの注意が必要なシナリオは、DAG がいくつかのエッジを除いて切断されている場合です。 単純なアプローチでは、「最長のパス セグメント」を正しく考慮できなかったり、すべてのペアが有効であると誤って仮定したりする可能性があります。 たとえば、次のように考えてみましょう`n=4`そしてエッジ`1->2, 3->4`。 セグメントを接続するエッジのみを追加する`2->3`または`4->1`すべての後向きエッジではなく、ハミルトニアン パスが生成される場合があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。`(x, y)`と`x > y`、エッジを追加します`x -> y`、DFS または動的プログラミングを使用してハミルトニアン パスを確認しようとします。 各ハミルトニアン パス チェックは O(n + m) であり、O(n²) ペアの場合、O(n²*(n+m)) の演算が行われますが、これは n の上限では明らかに実行不可能です。 

重要な洞察は、DAG の構造から得られます。 既存のエッジはすべて下位の頂点から上位の頂点に向かうため、DAG 内のハミルトニアン パスはトポロジー順序に従います。 トポロジカルソートにおいて最大連続シーケンスの最初と最後の頂点を考慮するだけで済みます。 頂点ごとに、到達可能な最も早い頂点を計算できます (`l[i]`) および後方に到達可能な最新の頂点 (`r[i]`) トポロジカル順序付け。 これらの境界を使用して、どの後方エッジを決定することができます`(x -> y)`グラフを単一のハミルトニアン パスに接続します。 問題は、その数を数えるということになります。`x > y`どこでペア`y >= l[x]`そして`x <= r[y]`。 

この観察により、問題は O(n²) から線形スキャンと単純なプレフィックス/サフィックス境界に変換され、n が 150,000 までであれば実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²*(n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、頂点の数を読み取ります。`n`そしてエッジ`m`。 DAG の隣接リストを初期化します。 
2. 頂点のトポロジー的順序を構築します。これは、エッジが常に小さい方から大きい方へ進むため、当然のことながら頂点インデックスになります。 
3. コンピューティング`l[i]`、頂点から開始して最も早く到達可能な頂点`i`。 エッジごとに左から右に反復します。`i -> j`、 セット`l[j] = min(l[j], l[i])`。 
4. コンピューティング`r[i]`、頂点に到達できる最新の頂点`i`。 各エッジに対して右から左に反復します。`i -> j`、 セット`r[i] = max(r[i], r[j])`。 
5. 最大の連続プレフィックスを特定する`L`どこ`l[i] == 0`および最小の連続接尾辞`R`どこ`r[i] == n-1`。 これらは、単一の後向きエッジを追加するときにハミルトニアン パスの安全な終点となり得る頂点を区切ります。 
6. すべてのペアを数えます`(x, y)`と`x > y`、`y < R`、 そして`x > L`。 これは、累積合計による単一の線形スキャンを使用して行われ、二重ループを回避します。 
7. テスト ケースの合計数を出力します。 

なぜ効果があるのか​​:`l[i]`そして`r[i]`は、各頂点がハミルトニアン パスの一部となり得る範囲を表します。 ハミルトニアン パスを形成できるのは、グラフの重複しないセグメントを位相順序で接続するペアのみです。 グラフをスキャンし、プレフィックスとサフィックスの到達可能性を組み合わせることで、カウントされたすべてのペアがハミルトニアン パスを正しく生成し、無効なペアがカウントされないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            a, b = map(int, input().split())
            adj[a-1].append(b-1)

        l = [i for i in range(n)]
        r = [i for i in range(n)]
        
        for i in range(n):
            for j in adj[i]:
                l[j] = min(l[j], l[i])
        
        for i in reversed(range(n)):
            for j in adj[i]:
                r[i] = max(r[i], r[j])

        left = 0
        while left + 1 < n and l[left+1] == 0:
            left += 1
        right = n - 1
        while right - 1 >= 0 and r[right-1] == n - 1:
            right -= 1

        total = 0
        # vertices in (left+1 .. right-1) are flexible
        total = (right - left - 1) * (right - left) // 2
        # add edges from right..n to left..right-1
        total += left + 1
        total += n - right
        print(total)

if __name__ == "__main__":
    solve()
```コードは入力を効率的に読み取り、隣接リストを構築し、各頂点の到達可能な左端と右端の頂点を計算し、有効な頂点の数を計算します。`(x, y)`の特性を使用したペア`l`そして`r`。 特にインデックスの境界処理は、off-by-one エラーを防ぐために慎重に管理されます。 式`(right - left - 1)*(right - left)//2`フレキシブルな中間セグメント内の有効なペアをカウントします。
