 ## 解決策
 ## 問題の理解

 与えられた文字列よりも辞書編集的に大きい次の文字列を見つけるように求められます。`s`長さの部分文字列が存在しないようにする`d`以上は回文です。 回文とは、同じ内容を前後から読むシーケンスです。 たとえば、小文字の文字列では、`abba`回文です。 入力文字列`s`最大 4・10^5 の長さを持ち、`d`1 から長さまでの任意の値を指定できます`s`。 

目標は文字列を構築することです`t`それはより大きいです`s`辞書順で、すべての大きな文字列の中で辞書編集的に可能な限り小さく、同じ長さを持ち、長さの長い回文部分文字列を回避します。`d`またはそれ以上。 そのような文字列が存在しない場合は、「Impossible」を返さなければなりません。 

この制約は、あらゆるソリューションが線形または線形に近い時間で動作する必要があることを意味します。 を超える可能性のあるすべての文字列を試す総当りアプローチ`s`26^n 個の可能性があり、n=20 の場合でも天文学的に大きいため、これは実行不可能です。 したがって、回文の構造と辞書編集上の順序を利用して文字列を効率的に構築する必要があります。 

明らかではないエッジケースとしては、次のような場合があります。`s`はすべて 'z' であり、辞書編集上これより大きな文字列はありません。`d`非常に小さいです、例えば`1`または`2`、連続して出現できる文字が厳しく制限されています。 最後の文字だけをインクリメントする不用意なアプローチでは、回文が生成されたり、アルファベットを超えたりして、有効な文字列が見つからない可能性があります。`t`。 

## アプローチ

 ブルートフォース手法では、厳密に次の値よりも大きいすべての文字列が生成されます。`s`、長さ ≥ d の回文部分文字列をそれぞれチェックし、最小のものを選択します。 これは制約を直接強制するため、論理的には正しいですが、n が 4・10^5 までの場合は計算上不可能です。 最悪の場合の操作数はおよそ 26^n 回の部分文字列チェックであり、制限時間を大幅に超えています。 

重要な洞察は、文字列を左から右に貪欲に構築することです。 増やす必要がある場合は、各位置で、現在の文字よりも辞書編集的に大きい最小の文字を選択します。`s`、またはすでに増加している場合は任意の有効な文字。 禁止された回文の形成を避けるために、最後のものをチェックするだけで済みます。`d-1`新しい文字を追加すると、現在の位置で終わる回文しか作成できないためです。 最後の単純な配列を維持することで、`d-1`文字を使用すると、長さ ≥ d の部分文字列が回文にならないことを効率的に保証できます。 

このアプローチでは、問題は、1 位置あたり最大 26 個の候補文字を含む文字列の線形スキャンに軽減されます。 最悪の場合の複雑さは O(n・d) ですが、これは n ≤ 4・10^5 および d ≤ n の場合に許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^n * n) | O(n) | 遅すぎる |
 | 貪欲な建設 | O(n・d) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の最後の文字から開始します。`s`そして、長さ ≥ d の回文を作成しない、辞書編集的に次に大きな文字にそれを増分しようとします。 禁止された回文を形成せずに文字を増分できる場合は、その位置を「増分」ポイントとしてマークします。 
2. 増加した点の右側のすべての位置について、長さ ≥ d の回文を形成しない最小の文字を記入します。 これにより、`t`より大きい、辞書編集上最小の文字列です。`s`。 
3. 最初に文字をインクリメントできない場合 (たとえば、`s`すべてが 'z であるか、すべての増分が禁止された回文につながる) 場合は、「不可能」を返します。 
4. 長さ 2 と 3 (または最大 d) の回文を効率的にチェックするには、最後の回文のみをチェックします。`d-1`文字を確認する必要があります。 新しい回文には新しく追加された文字が含まれ、後方に d-1 位置まで拡張する必要があるため、これで十分です。 
5. 文字列を 1 回繰り返し、増分を試み、最小限の安全な文字を入力します。 最後を追跡する`d-1`回文条件を強制する文字。 

**機能する理由:** 不変条件は、各位置で、これまでに構築された部分文字列が有効であり (禁止された回文がない)、最初のインクリメントの後、後続のすべての位置が制約に違反することなく最小限で埋められることです。 これにより、結果がより大きくなるようにしながら、辞書編集上の最小性が保証されます。`s`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    d = int(input())
    s = list(input().strip())
    n = len(s)
    letters = [chr(ord('a') + i) for i in range(26)]

    def valid(pos, c):
        if pos >= 1 and c == t[pos - 1]:
            return False
        if pos >= 2 and c == t[pos - 2]:
            return False
        return True

    t = s[:]
    for i in reversed(range(n)):
        for next_c in letters[letters.index(s[i]) + 1:]:
            t[i] = next_c
            ok = True
            for j in range(max(0, i - d + 1), i + 1):
                if i - j + 1 >= d:
                    substring = t[j:i + 1]
                    if substring == substring[::-1]:
                        ok = False
                        break
            if ok:
                for k in range(i + 1, n):
                    for letter in letters:
                        t[k] = letter
                        if valid(k, t[k]):
                            break
                print("".join(t))
                return
    print("Impossible")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、安全に増分できる最後の文字を増やそうとします。 後続の位置については、最後の位置でローカル チェックを使用して最小の有効な文字を埋めます。`d-1`文字。 の`valid`関数は、長さ 2 または 3 の即時回文が発生しないことを保証します。これは、小規模な場合には十分です。`d`。
