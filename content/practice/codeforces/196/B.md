 ## 解決策
 ## 問題の理解

 私たちには有限のサイズの迷路が与えられています`n × m`。 一部のセルは壁で、一部は開いており、1 つのセルには開始位置が含まれます`S`。 

迷路は一度だけ使用されるわけではありません。 代わりに、同じ長方形のコピーで平面をタイリングするように、グリッド全体があらゆる方向に無限に繰り返されます。 1 つのコピーの外側に移動すると、すぐに対応する位置に別のコピーが入ります。 

問題は、プレイヤーが壁以外のセルのみを踏んで開始位置から任意に遠くに移動できるかどうかです。 

無限迷路について考えるのに役立つ方法は次のとおりです。 

無限平面内のすべての位置は以下に対応します。 

1. 元のグリッド内のセル。 
2. 現在いるグリッドのコピー。 

2 つの異なる無限の位置が同じにマッピングされる場合があります`(row, col)`タイルの異なるコピーに属している場合は、元の迷路内にあります。 

制約が非常に大きいため、無限迷路を直接探索することは不可能です。 元のグリッドには最大で次のものを含めることができます。`1500 × 1500 = 2.25 million`細胞。 セルを何度も再訪問したり、無限に多くの位置の情報を保存したりするアルゴリズムは、すぐに失敗します。 

元のグリッド上でのグラフの走査は、元の各セルが一度だけ現れるため、引き続き実行可能です。 アン`O(nm)`または`O(nm log(nm))`アルゴリズムは制限内に快適に収まります。 セル数の二次関数はそうではありません。 

厄介な点は、同じ元のセルを再訪することが必ずしも冗長であるとは限らないということです。 同じに到達する`(r, c)`無限のタイリングのさまざまなコピーから作成することが、まさに無限の動きを生み出すものなのです。 

次の例を考えてみましょう。```
2 2
S.
..
```正しい答えは、`"Yes"`。 

有限グリッドのみ上の単純な BFS は、各セルを 1 回訪問して停止し、動きが有限であると誤って結論付けてしまいます。 実際には壁がないので、迷路のさまざまなコピーを永遠に歩き続けることができます。 

もう 1 つの微妙なケースは、サイクルが境界領域内にのみ存在する場合です。```
3 3
###
#S#
#.#
```正しい答えは、`"No"`。 

プレイヤーはいくつかのセル間を永久に行き来できますが、迷路の別のコピーに逃げることはできません。 グラフにサイクルが含まれていても、無限の歩行距離は不可能です。 

もう 1 つの危険な間違いは、負の座標のモジュロを誤って処理することです。 Pythonでは、`%`この問題に対してはすでに正しく動作していますが、多くの言語で`(-1) % m`マイナスになる。 例えば：```
1 2
S.
```列から左に移動`0`列に折り返す必要があります`1`隣接するコピーの。 モジュロ処理が正しくないと、この移行は完全に中断されます。 

## アプローチ

 最も直接的なアイデアは、無限迷路を文字通りに扱い、到達可能なすべての座標に対して BFS または DFS を実行することです。`(x, y)`飛行機の中。 

通常のグラフの走査を通じて、到達可能なすべての位置を探索できるため、これは概念的に機能します。 トラバースが決して終わらない場合、答えは次のとおりです。`"Yes"`。 

問題は、グラフが無限であることです。 たとえ小さな廊下しか存在しなかったとしても、探索は永遠に続くかもしれない。 探索される州の数に上限はありません。 

重要な観察は、迷路パターンが周期的に繰り返されるということです。 

無限座標に立っていると仮定します`(x, y)`。 実際のセルの種類は以下にのみ依存します。```
(x mod n, y mod m)
```非常に多くの無限の位置が、元のグリッド内の同じセルに対応します。 

ここからが重要な洞察です。 

横断中に元の同じセルに到達した場合`(r, c)`2 つの異なる無限座標から、タイル状の平面を通る非自明なサイクルを発見しました。 その時点からは、永久にコピー間を移動し続けることができるため、答えは次のようになります。`"Yes"`。 

なぜこれが機能するのでしょうか?

 2 つの無限座標の差が迷路のコピー間の並進ベクトルを表すためです。 対応する動作シーケンスを繰り返すことで、無限に遠くまで漂流できます。 

これは、正しい状態表現を示唆しています。 

元のグリッド セルごとに、そのセルに到達した最初の無限座標を保存します。 

DFS または BFS の間:

 - セルに一度もアクセスしたことがない場合は、その無限座標を記録します。 
- 以前に別の無限座標でセルを訪問した場合、無限の動きが見つかりました。 

これにより、無限に多くの状態を探索することが完全に回避されます。 通常の場合、元の各セルは 1 回だけ処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 無限平面上のブルートフォース | 無制限 | 無制限 | 不可能 |
 | 座標マッピングを使用した DFS/BFS | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、開始セルを見つけます。`S`。 
2. に対応する無限座標から開始して DFS または BFS を実行します。`S`。 
3. 探索された無限の位置ごとに`(x, y)`、対応する元のグリッド セルを計算します。```
rx = x % n
ry = y % m
```これにより、私たちがどのタイル セル上に立っているのかがわかります。 

1. マップされたセルが壁の場合、移動を無視します。 
2. すべての元のグリッド セルについて`(rx, ry)`、最初に到達した無限座標を保存します。 

例えば：```
vis[rx][ry] = (x, y)
```1.到達時`(rx, ry)`もう一度:

 - 保存されている無限座標が同一の場合`(x, y)`、これは同じ無限の位置への単なる別の横断パスです。 無視してください。 
- 保存されている座標が異なる場合`(x, y)`、その後、迷路の 2 つの異なるコピーから同じ元のセルに到達しました。 印刷する`"Yes"`すぐに。 
2. 4 方向への移動を続けます。 
3. このような競合が検出されずに走査が終了した場合は、次のように出力します。`"No"`。 

### なぜ効果があるのか

 不変条件は次のとおりです。 

オリジナルのグリッド セルごとに、そこに到達できる無限の座標を 1 つだけ記憶します。 

後で別の無限座標を使用して同じ元のセルに到達すると、正味変位がゼロ以外のパスが存在します。 その移動を繰り返すことで、無限に多くの迷路のコピーを移動できます。 

逆に、そのような異なる座標を持つ重複が存在しない場合、到達可能なすべての状態は、元のセルごとに 1 つの無限座標に正確に対応します。 しかないので、`nm`元のセルでは、到達可能な領域は有限です。 

これにより、両方の正しさの方向が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

grid = []
sx = sy = -1

for i in range(n):
    row = input().strip()
    grid.append(row)

    for j, ch in enumerate(row):
        if ch == 'S':
            sx, sy = i, j

visited = [[None] * m for _ in range(n)]

dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

def dfs(x, y):
    rx = x % n
    ry = y % m

    if grid[rx][ry] == '#':
        return False

    if visited[rx][ry] is not None:
        px, py = visited[rx][ry]

        if px != x or py != y:
            return True

        return False

    visited[rx][ry] = (x, y)

    for dx, dy in dirs:
        nx = x + dx
        ny = y + dy

        if dfs(nx, ny):
            return True

    return False

print("Yes" if dfs(sx, sy) else "No")
```トラバースは無限の座標で動作します`(x, y)`元のグリッド内の位置だけでなく。 これは、私たちが訪れている迷路のコピーに関する情報を保存するための中心となるアイデアです。 

モジュロ演算は、すべての無限座標を元のタイルにマップし直します。```
rx = x % n
ry = y % m
```Python のモジュロはすでに負の数を正しく処理しています。これは、移動が上または左の境界を越える場合に不可欠です。 

の`visited`配列にはブール値は格納されません。 これは、各オリジナル グリッド セルに最初に到達した正確な無限座標を保存します。 この区別が全体的な解決策になります。 

仮定する`(2, 3)`無限座標からタイル内に最初に到達しました`(2, 3)`。 後で同じタイル セルに到達すると、`(2 + n, 3)`、その後、迷路の別のコピーに横断したことがわかります。 

このような競合が発生すると、DFS はただちに停止します。 

間違いやすい実装の詳細の 1 つは、まったく同じ無限座標を再検討することです。 それは無害であり、引き起こすべきではありません`"Yes"`。 

この条件は重要なチェックです。```
if px != x or py != y:
    return True
```到達可能なコンポーネントには長いチェーンに数百万のセルが含まれる可能性があるため、再帰制限が増加します。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n, m = map(int, input().split())

    grid = []
    sx = sy = -1

    for i in range(n):
        row = input().strip()
        grid.append(row)

        for j, ch in enumerate(row):
            if ch == 'S':
                sx, sy = i, j

    visited = [[None] * m for _ in range(n)]

    dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    def dfs(x, y):
        rx = x % n
        ry = y % m

        if grid[rx][ry] == '#':
            return False

        if visited[rx][ry] is not None:
            px, py = visited[rx][ry]

            if px != x or py != y:
                return True

            return False

        visited[rx][ry] = (x, y)

        for dx, dy in dirs:
            if dfs(x + dx, y + dy):
                return True

        return False

    return "Yes\n" if dfs(sx, sy) else "No\n"

assert run(

##S#

#.##
#..#
"""

"""

# open strip

"""

 ## 特殊なケース

 可能な最小のグリッドを考えてみましょう。```
1 1
S
```単一のセルは全方向に無限に繰り返します。 から始まる`(0,0)`、上に移動すると到達します`(-1,0)`にマッピングされます。`(0,0)`。 

アルゴリズムは最初に以下を保存します。```
visited[0][0] = (0,0)
```その後、次のようになります。```
(-1,0)
```これは同じタイル セルにマップされますが、異なる無限座標を持ちます。 アルゴリズムは正しく印刷します`"Yes"`。 

ここで、トラップされた構成を考えてみましょう。```
3 3
###
#S#
###
```DFS は探索のみを行います。`(1,1)`。 モジュロ マッピングの後は、隣接するすべてのセルが壁になります。 2 番目の無限座標が同じタイル セルに到達することはないため、トラバースは終了し、答えは次のようになります。`"No"`。 

最後に、負の座標をラップすることを検討してください。```
1 2
S.
```から左に移動`(0,0)`与える`(0,-1)`。 Python は以下を計算します。```
-1 % 2 == 1
```したがって、マップされた位置は次のようになります`(0,1)`、まさに左側のコピー内の隣接するタイル セルです。 

モジュロ処理が正しくないと、クラッシュするか無効な列にマップされ、間違った答えが生成されます。
