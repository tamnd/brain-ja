 ## 解決策
 ## 問題の理解

 線形シーケンスのサービス ウィンドウが与えられており、各ウィンドウでドキュメント間で可能な変換が 1 つだけあります。現在特定のドキュメントを保持している場合は、それを別のドキュメントに変換する手順を実行することを選択できます。 手順を実行しても元のドキュメントは削除されないため、ドキュメントのコレクションは時間の経過とともに増加するだけです。 

ドキュメント 0 から開始し、最終的にドキュメント m-1 を取得することが目標です。 主な制限は、ウィンドウが厳密に順序付けされていることです。ウィンドウを通過すると、決して戻ることはできません。そのため、各ウィンドウによって提供される変換は、現在そのウィンドウにいるか、そのウィンドウの前にいるときにのみ使用できます。 

タスクは、文書 m-1 を取得するために必要な実行手順の最小数を決定するか、それが不可能であると報告することです。 

この制約は 2 つの異なる体制を示唆しています。 ウィンドウとドキュメントの数は、最も困難な場合には両方とも 100 万にも達する可能性があるため、到達可能なすべてのドキュメント セットを明示的にシミュレートしたり、ウィンドウごとに到達可能性を繰り返し再計算したりするソリューションは遅すぎます。 O(nm) 推論でさえ完全に実行不可能であり、複雑な更新が必要な場合は、ドキュメントごとの構造が重い O(n log n) でも危険です。 

重要な構造上の制約は、各ウィンドウがドキュメント間の有向エッジを 1 つだけ提供し、エッジは順番に処理する必要があるということです。 これは、各エッジが 1 回考慮される単一の線形パス ソリューションを示唆しています。 

「文書のグラフの最短経路」だけを考えると、微妙な失敗例が現れます。 たとえば、順序を無視すると、次のようになります。 

入力:```
3 4
0 2
2 1
1 3
```素朴な最短経路の解釈では、コスト 3 の 0 → 2 → 1 → 3 がすぐに得られますが、これはここでは正しいです。 ただし、エッジを並べ替えると次のようになります。```
3 4
2 1
0 2
1 3
```単純なグラフ ビューでは依然として同じエッジが表示されますが、実行順序が重要です。エッジ 2 → 1 は 2 を取得する前に表示されるため、使用できません。 ウィンドウ順序を無視するアプローチは到達可能性を過大評価し、不可能であると誤って主張したり、ステップを過小評価したりする可能性があります。 

最大の問題は、到達可能性がドキュメントの状態と処理されるウィンドウのプレフィックスの両方に依存することです。 

## アプローチ

 ブルートフォース戦略では、現在保持しているドキュメントの完全なセットを維持しながら、ウィンドウごとにプロセスをシミュレートします。 各ウィンドウ i で、ドキュメント a_i がある場合、変換を適用してセットに b_i を追加することを選択できます。 これはルールに直接一致しており、順序と制約を明示的に尊重しているため、正しいです。 

ただし、この単純なシミュレーションは、ドキュメント セットのサイズが O(m) に達する可能性があり、各ウィンドウがこの増大するセット全体でチェックをトリガーする可能性があるため、コストが高くなります。 最悪の場合、O(nm) 回のメンバーシップ チェックまたは更新が実行されますが、n と m の両方が 100 万に達すると、これは許容限界をはるかに超えます。 

重要な観察は、実際にはドキュメントの完全なセットを気にしていないということです。 私たちは、各文書に到達するために必要な最小限の手順のみを考慮します。 ドキュメントが k ステップで到達可能になると、ドキュメントは決して失われることがなく、その後の操作はタイミングではなく存在のみに依存するため、永久に到達可能な状態が続きます。 

これにより、進化する状態全体を単一の配列 dist に圧縮できます。ここで、dist[x] は、ドキュメント x を取得するために必要なプロシージャの最小数を表します。 a_i → b_i の遷移を持つウィンドウ i にいるとき、a_i が dist[a_i] ですでに到達可能であれば、dist[b_i] を dist[a_i] + 1 に改善できます。ウィンドウ i を使用するパスは、dist[a_i] の計算時にすでに処理されている以前のウィンドウにのみ依存できるため、順序付け制約は当然尊重されます。 

したがって、問題は、エッジが位相順序で与えられる DAG の最短パスとまったく同じように、エッジ上の単一の左から右への緩和に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ドキュメントセットのブルートシミュレーション | O(nm) | O(m) | 遅すぎる |
 | 秩序あるDP緩和 | O(n) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ドキュメントを取得するために必要な既知の手順の数を維持しながら、指定された順序でウィンドウを処理します。 

1. すでに利用可能なドキュメント 0 から開始するため、dist[0] = 0 を除くすべての値を無限大に設定してサイズ m の配列 dist を初期化します。 
2. ウィンドウを 1 から n まで順番に繰り返します。 ウィンドウ i で、ペア (a_i, b_i) を読み取ります。これは、a_i を b_i に変換するのに 1 つの手順を費やす可能性があることを意味します。 
3. dist[a_i] が依然として無限大である場合、これはドキュメント a_i が以前のウィンドウのシーケンスを使用して達成できなかったことを意味するため、このウィンドウは有意義に使用できず、スキップします。 
4. それ以外の場合は、dist[b_i] = min(dist[b_i], dist[a_i] + 1) を設定することによって、b_i の状態を緩和しようとします。 これは、b_i に到達する有効な手順シーケンスの最後のステップとしてこのウィンドウを使用することに対応します。 
5. すべてのウィンドウを処理した後の答えは dist[m−1] になります。 それでも無限大の場合は無理と出力します。 

重要な考え方は、すべての有効なプロシージャ シーケンスは、インデックスの昇順でウィンドウのサブシーケンスを選択することに対応しており、この DP により、ドキュメントあたりの最良のコストのみを常に保存しながら、そのようなすべてのサブシーケンスを確実に考慮できるということです。 

### なぜ効果があるのか

 不変条件は、最初の i ウィンドウを処理した後、dist[x] が i までのウィンドウのみを使用してドキュメント x を取得するために必要な最小数のプロシージャを格納することです。 x を生成し、最初の i ウィンドウ内で終了する有効なシーケンスは、x を生成するウィンドウ j ≤ i で終了する必要があり、DP 緩和により、ウィンドウ j が処理されるときに遷移が正確に適用されることが保証されます。 前のウィンドウは後のウィンドウが考慮される前に完全に確定するため、将来の情報が順序に違反して以前の遷移を遡及的に改善することはできません。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18
    
    for _ in range(t):
        n, m = map(int, input().split())
        dist = [INF] * m
        dist[0] = 0
        
        for _ in range(n):
            a, b = map(int, input().split())
            if dist[a] != INF:
                nd = dist[a] + 1
                if nd < dist[b]:
                    dist[b] = nd
        
        if dist[m - 1] == INF:
            print("Imposible")
        else:
            print(dist[m - 1])

if __name__ == "__main__":
    solve()
```この実装はリラクゼーションのアイデアに直接従っています。 配列 dist は、到達可能なすべての状態を圧縮し、ドキュメント セットの明示的な追跡を回避します。 check dist[a] != INF は、前提条件ドキュメントが以前のウィンドウを使用してすでに達成されている場合にのみウィンドウを使用することを保証するため、必須です。 

更新ステップ dist[b] = min(dist[b], dist[a] + 1) は、同じドキュメントに到達する複数の可能な方法にわたって最適化を強制します。 

## 実用的な例

 最初のサンプルを考えてみましょう。 

入力:```
2 3
0 1
1 2
```dist を時間の経過とともに追跡します。 

| ウィンドウ | a → b | 距離[0] | 距離[1] | 距離[2] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | 0 | ∞ | ∞ | 開始 |
 | 1 | 0→1 | 0 | 1 | ∞ | リラックス 1 |
 | 2 | 1→2 | 0 | 1 | 2 | リラックス2 |

 最後に dist[2] = 2 となり、2 つの手順が必要となることを意味します。 

次に、順序によって使用がブロックされる場合を考えてみましょう。 

入力:```
2 3
1 2
0 1
```| ウィンドウ | a → b | 距離[0] | 距離[1] | 距離[2] | アクション |

 ここでは、エッジに関してはパス 0 → 1 → 2 がありますが、順序付けにより 1 → 2 は早すぎるため使用できません。 DP はこれを正しく反映し、2 を到達不能のままにします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ウィンドウは定数時間緩和で 1 回処理されます。 
| スペース | O(m) | 距離配列には各ドキュメントの最適コストが格納されます。 

n と m の両方が最大 100 万に達するため、この解は制約内に問題なく収まりますが、線形パスと単純な配列演算のみが実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    INF = 10**18

    for _ in range(T):
        n, m = map(int, input().split())
        dist = [INF] * m
        dist[0] = 0

        for _ in range(n):
            a, b = map(int, input().split())
            if dist[a] != INF:
                dist[b] = min(dist[b], dist[a] + 1)

        out.append("Imposible" if dist[m-1] == INF else str(dist[m-1]))

    return "\n".join(out)

 ## 特殊なケース

 一般的なエッジ ケースは、唯一の利用可能なパスで、その前提条件ドキュメントが到達可能になる前に表示されるウィンドウを使用する必要がある場合です。 たとえば:

 入力:```
3 3
1 2
0 1
```処理の結果、ウィンドウ 1 → 2 は、表示された時点では dist[1] が無限大であるため、最初は使用できないことがわかります。 その後、0 → 1 が処理されるときに dist[1] を更新しますが、以前のウィンドウには戻りません。 これは正しいです。有効なシーケンスはウィンドウの順序を尊重する必要があるため、0 → 1 の前に 1 → 2 を使用することは本質的に不可能です。 アルゴリズムは当然ながら、前方処理のみを許可することでこの制約を強制し、正しい結果を生成します。
