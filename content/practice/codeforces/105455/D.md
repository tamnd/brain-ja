 ## 問題の理解

 私たちには、プレイヤーのセットとペアごとの「憎悪関係」のリストが与えられ、それぞれに数値的な強さが示されています。 すべてのプレイヤーを 2 つのチームに分ける必要があります。 同じチームに配置された 2 人のプレーヤーは、互いの憎しみが「大きすぎない」場合にのみ許容されます。 ただし、しきい値を選択することはできます。$k$、そして私たちはそのような最小のものを望んでいます$k$これにより、有効な 2 チームの割り当てが存在します。 

より構造的に言い換えると、すべてのペア$(u, v)$重さで$h$と判断した場合にのみアクティブになる制約のように動作します。$k < h$。 この場合、2 人のプレイヤーが同じチームに所属することは禁止されます。 代わりに$k \ge h$、そのエッジはまったく制限を課さないため、無視できます。 

したがって、固定の場合$k$、厳密に よりも大きい重みを持つエッジのみを取得します。$k$。 これらのエッジでは、エンドポイントは異なるチームに属している必要があります。 これはまさに二部制約です。「十分に強い憎しみのエッジ」によって形成されるグラフを 2 色にできるかどうかを尋ねています。 

タスクは最小のものを見つけることです$k$グラフが重みを超えるエッジで構成されるようにする$k$二部構成です。 

制約により、最大で$2 \cdot 10^5$ノードとエッジ、最大重み付き$10^9$。 あらゆる可能性を試みるアプローチ$k$候補ごとに二部性を最初から評価したり再計算したりすると、時間がかかりすぎます。 単一の二者チェックであっても、$O(n + m)$したがって、重みに対する二分探索にはコストがかかります$O((n+m)\log m)$、これは許容されますが、不要です。 

エッジはソートされた順序で処理できるため、より直接的なアプローチが存在します。 

微妙なエッジ ケースは、奇数サイクルを形成する異なる重みを持つ複数のエッジが存在する場合に発生します。 答えは「サイクルの最大エッジ」ではなく、矛盾が避けられなくなる重みの減少順序の最初の点です。 

## アプローチ

 ブルートフォース戦略により値が固定される$k$、より大きい重みを持つすべてのエッジをフィルタリングします。$k$そして、DFS または BFS カラーリングを使用して、そのグラフが 2 部構成であるかどうかを確認します。 これは、2 色の制約が満たされるかどうかを直接検証するため、正しいです。 ただし、これを可能な限り実行すると、$k$重みが大きくて個別であり、各チェックにはグラフ サイズの直線的な時間がかかるため、値を計算することは不可能です。 最悪の場合、これを多数の候補しきい値にわたって繰り返すと、3 次スタイルの動作が発生します。 

重要な観察は、グラフを繰り返し再構築する代わりに、重みの降順にエッジを処理し、最初に徐々に強い制約を導入できることです。 重みが大きいほど、小さくても存続するため、より重要になります。$k$, そのため、早めに検討する必要があります。 

エッジを最大の重みから最小の重みまで処理するときに、現在「アクティブ」な制約が二部構成のままであるかどうかを追跡する構造を維持します。 ある時点で、以前の制約と矛盾する制約を強制しようとした場合、それは、二部性が崩れる最初の重みレベルを発見したことを意味します。 あの重さはまさにミニマム$k$これにより、有効なパーティションが引き続き許可されます。 

エッジ挿入下で二部性を効率的に維持するために、パリティを備えた Disjoint Set Union を使用します。ここで、各ノードは、親と同じ側にあるか反対側にあるかを格納します。 これにより、「u と v は別のチームに属している必要がある」という形式の制約をほぼ一定時間で強制することができます。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを重みの降順に並べ替えます。 これにより、将来の有効性に関して最も制限の厳しいものから最も制限の少ないものへと制約が処理されます。 
2. 各ノードが、union-find ツリー内の親に対して同じパーティションにあるか反対側のパーティションにあるかを示すパリティ値も格納する DSU 構造を初期化します。 
3. ソートされた順序でエッジを 1 つずつ処理します。 各エッジについて$(u, v, w)$、それを強制しようとします$u$そして$v$さまざまなチームに所属しています。 
4. これを強制するために、現在の DSU 代表者と同等関係を確認します。 それらがすでに一貫した「異なるセット」関係にある場合は、それに応じてそれらをマージします。 
5. 矛盾を発見した場合、$u$そして$v$同じチームと異なるチームの両方に同時に所属することを強制される場合、すぐに出力します$w$応答として応答し、処理を停止します。 

この停止点が意味を持つ理由は、以前に処理されたすべてのエッジの重みが厳密に高いためです。 これらのエッジは、次の場合にも保持される必要がある制約に対応します。$k$すぐ下にあります$w$、一方、現在のエッジはまさにそのしきい値でアクティブになります。 

### なぜ効果があるのか

 エッジを降順で処理する場合、DSU は常に、現在のエッジより厳密に大きい重みを持つすべてのエッジの有効な 2 分割を表します。 現在のエッジを追加すると矛盾が生じる場合は、この値以上の重みを持つエッジのうち、制約グラフ内に奇数のサイクルが存在することを意味します。 この奇数サイクルは、厳密に より小さいしきい値では解決できません。$w$なぜなら、それらのより重みの高いエッジはすべてアクティブのままだからです。 したがって、$w$は、矛盾する制約を含めることを強制的に中止する最小のしきい値であり、それが答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.parity = [0] * n  # parity to parent: 0 same, 1 different

    def find(self, x):
        if self.parent[x] == x:
            return x, 0
        root, p = self.find(self.parent[x])
        self.parity[x] ^= p
        self.parent[x] = root
        return self.parent[x], self.parity[x]

    def union(self, a, b):
        ra, pa = self.find(a)
        rb, pb = self.find(b)

        if ra == rb:
            # must be in different sets
            return (pa ^ pb) == 1

        # union by size
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
            pa, pb = pb, pa

        self.parent[rb] = ra
        self.parity[rb] = pa ^ pb ^ 1
        self.size[ra] += self.size[rb]
        return True

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((w, u - 1, v - 1))

        edges.sort(reverse=True)

        dsu = DSU(n)
        ans = 0

        for w, u, v in edges:
            if not dsu.union(u, v):
                ans = w
                break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU は、ノード間の接続性と相対パリティの両方を維持します。これにより、コンポーネントを明示的に色付けせずに 2 部制約を強制することができます。 ユニオン操作は、反対のパリティ要件を持つ 2 つのコンポーネントをマージするか、すでに接続されているコンポーネント内で要件に違反している場合に矛盾を検出します。 

重要な詳細は、エッジを重みの降順で処理することです。 これにより、最初の矛盾が、アクティブな制約グラフの二部性が壊れる最小のしきい値に正確に対応することが保証されます。

 ## 特殊なケース

 重要なケースは、エッジがまったくない場合です。 制約グラフは、次の条件に関係なく常に 2 部構成です。$k$, したがって、答えはゼロです。 DSU ループが競合を引き起こすことはなく、デフォルトの応答は変更されません。 

もう 1 つの微妙なケースは、すべてのエッジがサイクルを形成しているが、最後のエッジが処理されるまで矛盾が現れない場合に発生します。 たとえば、スクエア サイクルでは、中間結合は一貫しており、最後のエッジのみがパリティ矛盾を強制します。 アルゴリズムは、最後のエッジの重みを正確に返します。これは、まさに「アクティブな」エッジの制約グラフが 2 部でなくなる点であるためです。 

3 番目のケースには、サイクルを形成する同じ重みを持つ複数のエッジが含まれます。 これらは降順で一緒に処理されるため、最初に競合するエッジが応答をトリガーします。これは、これらすべてのエッジが同時にアクティブになるしきい値の解釈と一致します。$k$その体重を下回ります。
