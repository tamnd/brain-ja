 ## 解決策
 ## 問題の理解

 複数の独立したシナリオが与えられます。 各シナリオでは、骨折後に残った 3 つの骨片の長さを表す 3 つの正の整数が提供されます。 各トリプルについて、これら 3 つの長さが非縮退三角形の辺の長さとして機能するかどうかを決定する必要があります。 

有効な三角形では、2 つの辺の合計が 3 番目の辺よりも厳密に大きいことが必要です。 この条件は、指定された長さの 3 つのペアごとの組み合わせすべてに当てはまります。 

出力は、三角不等式が成り立つかどうかに応じて、テスト ケースごとに単に「はい」または「いいえ」の決定を行います。 

この制約により、各長さは 10^8 まで大きくなり、標準の整数演算を超える特殊な数値処理の必要性が即座に排除されます。 テスト ケースの数は明示的に制限されていませんが、一般的な Codeforces の書式設定では潜在的に大きな入力ストリームが含まれるため、各ケースを一定時間で処理する必要があります。 

ジオメトリを構築またはシミュレートしようとする単純なアプローチは必要ありません。 唯一意味のある操作は、数値のペアの合計を比較することです。 

エッジケースは主に平等性と順序に関するものです。 よくある間違いは、三角形は非縮退でなければならないため、等式は無効であることを忘れることです。 たとえば、1 2 3 のような入力は、1 + 2 が 3 に等しく、有効な三角形を形成しないため失敗します。 もう 1 つの微妙なケースは、5 5 5 など、すべての辺が等しい場合です。これは、5 + 5 が厳密に 5 より大きいため、常に有効です。 

## アプローチ

 この問題を考える強引な方法は、三角形の定義を直接適用することです。テスト ケースごとに 3 つの不等式をすべてチェックします。 数値が 3 つしかないため、これはケースごとにすでに一定の作業であるため、冗長な計算や繰り返しの計算を行う以外に意味のある「遅い」バージョンはありません。 

辺を並べ替えたり、三角形の構築をシミュレートしようとする誤ったアプローチを想像することもできますが、それは不必要なオーバーヘッドになります。 問題の構造は純粋に関係的なものであり、比較のみが重要です。 

重要な単純化は、3 つの不等式のうち、並べ替え後に注意深くチェックする必要があるのは 1 つだけであることに気づいたことから来ています。 a ≤ b ≤ c になるように辺を並べ替える場合、自明でない可能性のある唯一の条件は、a + b > c かどうかです。 c が最大値であるため、他の 2 つの不等式は自動的に成り立ちます。 

これにより、問題はテスト ケースごとに 1 つの比較に減ります。

 ## アルゴリズムのチュートリアル

 ### 最適な方法

 1. 入力が終了するまで、3 つの整数を読み取ります。 各トリプルは 3 つの辺の長さの候補を表します。 
2. トリプルごとに、値が非降順になるように値を並べ替えます。 このステップでは、三角形条件に違反する可能性がある唯一の値である最大値を分離します。 
3. 2 つの小さい値の合計を最大値と比較します。 合計が厳密に大きい場合は、3 つのセグメントが三角形を形成する可能性があります。 
4. 条件が成立する場合は「si」を出力し、成立しない場合は「no」を出力します。 

ソートのステップは効率ではなく、チェックする必要がある条件の数を減らすことを目的としています。 順序付けしない場合は、3 つの不等式すべてを明示的にチェックする必要がありますが、順序付けすると、そのうち 2 つが冗長であることが保証されます。 

### なぜ効果があるのか

三角不等式では、すべてのペアの合計が残りの辺を超える必要があります。 a ≤ b ≤ c になるように値を並べると、c が最大で b と c が両方とも正であるため、不等式 a + c > b および b + c > a が自動的に真になります。 失敗する可能性がある残りの唯一の制約は、2 つの最小値を合わせた値が最大値を超えるのに十分な大きさであるかどうかです。 それが失敗した場合、他の組み合わせは c と比較される合計を減らすだけであるため、同じ値の順列は三角形条件を満たすことができません。 

この縮小は、順序付けされた値の単調構造に依存します。つまり、最大の要素が、それに関係するすべての比較を支配します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    out = []
    for line in sys.stdin:
        if not line.strip():
            continue
        a, b, c = map(int, line.split())
        if a > b:
            a, b = b, a
        if b > c:
            b, c = c, b
        if a > b:
            a, b = b, a

        if a + b > c:
            out.append("si")
        else:
            out.append("no")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では入力を 1 行ずつ処理しますが、問題の形式を考えるとこれで十分です。 関係する要素が 3 つだけであるため、各トリプルは完全な並べ替えではなく、最小限のスワップ シーケンスを使用して並べ替えられます。 

決定の核となるのは単一の不等式です`a + b > c`。 平等は縮退三角形に相当し、明示的に禁止されているため、厳密な不等式が不可欠です。 

繰り返しの I/O オーバーヘッドを避けるために、出力はリストに蓄積され、一度印刷されます。 

## 実用的な例

 ### 例 1

 入力:```
3 4 5
```注文後、値は (3、4、5) のままになります。 

| ステップ | | b | c | チェック |
 | --- | --- | --- | --- | --- |
 | 入力 | 3 | 4 | 5 | 生 |
 | 注文済み | 3 | 4 | 5 | a ≤ b ≤ c |
 | 比較 | 3 | 4 | 5 | 3 + 4 > 5 |

 結果は true なので、出力は「si」になります。 

これは、すべての不等式が厳密に満たされる標準的な有効な三角形を示しています。 

### 例 2

 入力:```
9 2 4
```注文後の値は(2,4,9)となります。 

| ステップ | | b | c | チェック |
 | --- | --- | --- | --- | --- |
 | 入力 | 9 | 2 | 4 | 生 |
 | 注文済み | 2 | 4 | 9 | a ≤ b ≤ c |
 | 比較 | 2 | 4 | 9 | 2 + 4 > 9 |

 6 は 9 より大きくないため、三角形条件は失敗します。 

この事例は、順序が重要である理由を浮き彫りにしています。つまり、最大の側が実現可能性のチェックを支配します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T) | 各テスト ケースでは、一定数の比較と交換が必要です。 
| スペース | お(1) | 入力サイズに関係なく、少数の整変数のみが使用されます。 

この解は入力行数において線形であり、すべてのケースを少なくとも 1 回読み取る必要があるため、これが最適です。 メモリ使用量は一定のままであり、制限内に十分収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio

    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("3 4 5\n9 2 4\n") == "si\nno"

# all equal sides
assert run("5 5 5\n") == "si"

# degenerate case
assert run("1 2 3\n") == "no"

# large valid triangle
assert run("100000000 99999999 99999998\n") == "si"

# two small, one large
assert run("1 1 100\n") == "no"

 ## 特殊なケース

 微妙なエッジケースは、三角形がほぼ縮退している場合です。 例えば、`1 2 3`ソート後は`(1, 2, 3)`。 アルゴリズムは計算します`1 + 2 = 3`、厳密な不等式が必要なため、正しく「no」が出力されます。 を使用する弱い実装`>=`の代わりに`>`このケースを誤って受け入れることになります。 

もう 1 つのケースは、入力がすでに逆順にソートされている場合です。`9 2 4`。 スワップベースの順序付けにより、正しい正規化が保証されます。`(2, 4, 9)`、その後は同じ単一の比較が適用されます。 順序付けを行わない場合、単純なチェックでは不一致のペアを誤って比較し、それでも正しい結果に到達する可能性がありますが、この問題をより複雑に拡張すると、そのアプローチは失敗し、順序付けステップが安定した一般的なパターンになります。
