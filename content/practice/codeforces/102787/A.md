 ## 解決策
 ## 問題の理解

 この問題は、次のシーケンスを説明します。`n`タイルは最初に次のように配置されました`1, 2, 3, ..., n`。 私たちは与えられています`n`シャッフル操作。 各オペレーションは 2 つのポジションを受け取ります`a`そして`b`。 もし`b`後ではない`a`、何も起こりません。 それ以外の場合、操作によりタイルが次のように交換されます。`a`タイルを使って`b`、次にタイル`a + 1`タイルを使って`b + 1`など、2 つの範囲のいずれかが配列の最後に達すると停止します。 すべての操作を適用した後、タイルの最終的な順序を印刷する必要があります。 

入力サイズが重要な難易度です。 まであります`500000`操作、配列の最大サイズは同じです。 1 つの操作の直接シミュレーションは多くの位置に影響を与える可能性があり、最悪の場合は 1 つの操作で移動する可能性があります。`O(n)`要素。 それを繰り返すと、`n`操作が与える`O(n^2)`これは、50 万個の要素で可能なことをはるかに超えています。 各シャッフルはほぼ対数時間で処理される必要があります。 

いくつかの特殊なケースは見落とされがちです。 もし`b <= a`の場合、操作は完全に無視する必要があります。 例えば：```
Input:
1
1 1
```アレイは残ります`[1]`したがって、出力は次のようになります。```
1
```空ではないスワップ範囲を常に作成する不注意な実装では、無効な位置にアクセスする可能性があります。 

もう 1 つの重要なケースは、2 番目にスワップされたセグメントが配列の最後に到達したときです。 例えば：```
Input:
5
4 1
5 4
3 5
4 5
5 2
```最初の操作では何も行われません。`1 <= 4`。 スワップの右側が配列の境界によって短くカットされる可能性があるため、後の操作では有効な長さが異なります。 すべての操作を常に 2 つの等しい完全なブロックを交換するかのように扱うと、間違った順列が生成されます。 

## アプローチ

 簡単な解決策は、配列を明示的に保存し、定義内のすべての交換を実行することです。 手術の場合`(a, b)`とやり取りを繰り返します`array[a]`と`array[b]`両方のインデックスを前進させながら。 これはシャッフル手順に正確に従っているため、正しい実装です。 

問題は走行時間です。 配列のほぼ全体を繰り返しスワップする操作を考えてみましょう。 1 回の操作でほぼ次のものが必要になる場合があります`n/2`交換します。 と`n`操作に応じて、基本的な交換の数はほぼ増加します`250000000000`、それは実現不可能です。 

有益な観察は、各シャッフルでは配列に格納されている値を考慮しないことです。 位置を並べ替えるだけです。 この操作は、連続するシーケンスの並べ替え、具体的には 2 つの隣接するブロックの交換です。 配列は、断片の切断と結合が効率的である順序付けられたシーケンスとして表すことができます。 

暗黙的 treap は、位置による分割とマージをサポートしながらシーケンスを保存するため、適しています。 シーケンスを前の部分にカットしてシャッフルすることができます。`a`、最初のブロック、2 番目のブロック、および残りのサフィックス。 次に、中央の 2 つのブロックを逆の順序で結合します。 ピースの数は一定なので、すべての操作に時間がかかります`O(log n)`予想される時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 暗黙的トレプ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを含む暗黙的トレップを構築します。`1, 2, ..., n`。 ノードのトリープ位置は現在の配列内のインデックスを表すため、配列を通常のリストに格納する必要はありません。 
2. シャッフルごとに`(a, b)`、次の場合は無視してください`b <= a`。 この場合、操作では何も交換できません。 
3. 交換される最初のブロックの長さを計算します。 2 つのブロックは次から始まります`a`そして`b`、したがって、それらの距離は`b - a`。 2 番目のブロックは配列の終わりまでしか拡張できず、長さは次のようになります。```
min(b - a, n - b + 1)
```1. トレップを4つに分割します。 最初の部分には以前の位置が含まれています`a`。 次の 2 つの部分は交換する必要があるブロックです。 最後の部分には、交換された領域以降のすべてが含まれます。 
2. プレフィックス、2 番目のブロック、最初のブロック、サフィックスの順序でピースをマージします。 これにより、元の手順で実行されたスワップが正確に再現されます。 
3. すべての操作が完了したら、トレプを順番に走査し、保存されている値を出力します。 

これが機能する理由は、隣接ブロックの交換がその 2 つのブロックによって完全に記述されるためです。 treap は実際の配列と同じシーケンス順序を維持するため、2 つのブロックを分割してその位置を切り替えると、個々のスワップを実行する場合とまったく同じ順列が適用されます。 

なぜ効果があるのか:

 不変条件は、任意の数の操作を処理した後、トレプの順序トラバーサルがそれらの操作後の実際の配列と同一であることです。 トレプには ID 順列が含まれているため、最初はこれが当てはまります。 シャッフル中、分割操作では、元のループがアクセスするのとまったく同じ 4 つの連続する範囲が抽出されます。 2 つの中間範囲の順序を変更すると、それらの位置のみが変更されます。これはまさにすべての個別の交換と同じです。 各操作では不変条件が維持されるため、最後の走査が必要な答えとなります。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prio", "size", "left", "right")

    def __init__(self, val):
        self.val = val
        self.prio = random.randint(1, 1 << 30)
        self.size = 1
        self.left = None
        self.right = None

def size(t):
    return t.size if t else 0

def update(t):
    if t:
        t.size = 1 + size(t.left) + size(t.right)

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    if a.prio > b.prio:
        a.right = merge(a.right, b)
        update(a)
        return a
    else:
        b.left = merge(a, b.left)
        update(b)
        return b

def split(t, k):
    if not t:
        return None, None
    if size(t.left) >= k:
        a, b = split(t.left, k)
        t.left = b
        update(t)
        return a, t
    else:
        a, b = split(t.right, k - size(t.left) - 1)
        t.right = a
        update(t)
        return t, b

def build(n):
    root = None
    for i in range(1, n + 1):
        root = merge(root, Node(i))
    return root

def collect(t, ans):
    if not t:
        return
    collect(t.left, ans)
    ans.append(str(t.val))
    collect(t.right, ans)

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    root = build(n)

    for _ in range(n):
        a, b = map(int, input().split())
        if b <= a:
            continue

        length = min(b - a, n - b + 1)

        left, rest = split(root, a - 1)
        first, rest = split(rest, length)
        second, right = split(rest, length)

        root = merge(left, merge(second, merge(first, right)))

    ans = []
    collect(root, ans)
    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```treap ノードは値とサブツリー サイズのみを保存します。 優先フィールドはツリーのバランスをランダムに保ち、対数で期待される高さを与えます。 

の`split`関数はコア操作です。 最初のものを分離します`k`シーケンスの残りの要素からの要素。 インデックスはサブツリー サイズによって内部的に 0 から始まりますが、問題では 1 から始まる位置が使用されるため、すべての入力位置は次のように調整されます。`a - 1`。 

シャッフル長の計算では、多くの間違った解決策が失敗します。 2 番目のブロックは次から始まります`b`、つまり、最大でも次の内容が含まれます。`n - b + 1`要素。 また、次の間隔よりも長くすることはできません。`a`そして`b`、そのため、これら 2 つの量の最小値が必要です。 

暗黙的トレプは左のサブツリー、ノード、右のサブツリーの順序でシーケンスを表すため、最後のトラバーサルでは inorder 順序が使用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | それぞれの`n`shuffles は、一定数の treap 分割とマージを実行します。 |
 | スペース | O(n) | トレプはタイルごとに 1 つのノードを保存します。 |

 と`n = 500000`、二次シミュレーションは不可能です。 treap ソリューションは、シャッフルごとに約数十の対数演算を実行しますが、これは意図した制約に適合します。 

## テストケース```python
import sys
import io
import random

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    n = int(data())
    
    class Node:
        __slots__ = ("v", "p", "s", "l", "r")
        def __init__(self, v):
            self.v = v
            self.p = random.randint(1, 10**9)
            self.s = 1
            self.l = None
            self.r = None

    def sz(t):
        return t.s if t else 0

    def up(t):
        if t:
            t.s = sz(t.l) + sz(t.r) + 1

    def merge(a, b):
        if not a or not b:
            return a or b
        if a.p > b.p:
            a.r = merge(a.r, b)
            up(a)
            return a
        b.l = merge(a, b.l)
        up(b)
        return b

    def split(t, k):
        if not t:
            return None, None
        if sz(t.l) >= k:
            a, b = split(t.l, k)
            t.l = b
            up(t)
            return a, t
        a, b = split(t.r, k - sz(t.l) - 1)
        t.r = a
        up(t)
        return t, b

    root = None
    for i in range(1, n + 1):
        root = merge(root, Node(i))

    for _ in range(n):
        a, b = map(int, data().split())
        if b > a:
            length = min(b - a, n - b + 1)
            x, root = split(root, a - 1)
            y, root = split(root, length)
            z, w = split(root, length)
            root = merge(x, merge(z, merge(y, w)))

    ans = []
    def dfs(t):
        if t:
            dfs(t.l)
            ans.append(str(t.v))
            dfs(t.r)
    dfs(root)
    return " ".join(ans)

 ## 特殊なケース

 いつ`a`そして`b`が等しい場合、アルゴリズムは分割の前に終了します。 入力の場合:```
1
1 1
```トレプは変更されず、出力は次のようになります。`1`。 

スワップの右側が配列の終わりに接触すると、計算されたブロック サイズにより、シーケンスを超える位置にアクセスできなくなります。 のために：```
5
3 5
```距離は`2`、ただし、位置で始まるサフィックス`5`長さがある`1`, したがって、1 つのペアだけが交換されます。 シーケンスは次のように変わります。```
1 2 3 4 5
```に：```
1 2 5 4 3
```分割サイズは想定される完全な間隔ではなく、実際に使用可能なブロック長に基づいているため、treap はこれを処理します。 

すべてのシャッフルが現在の処理順序に適用されるため、同じ範囲での繰り返し操作も安全です。 この構造は初期化後の元の位置に依存しないため、進化する順列を自然に追跡します。
