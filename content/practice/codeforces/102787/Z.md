 ## 解決策
 # 問題の理解

 この問題は、順序付けられた treap ノードのグループのコレクションを維持します。 ノードは値を使用して作成され、その識別子はノードを作成したクエリ番号です。 グループはシーケンスのように動作します。2 つのグループが結合されると、1 つのノードを含むグループ全体が、他のノードを含むグループ全体の前に配置されます。 グループは、指定された数のノードの後で切り取られ、そのプレフィックスとそのサフィックスを分離することもできます。 クエリでは、特定のノードを含むグループ内のすべての値の合計が求められます。 

入力は最大のストリームです$5 \cdot 10^5$操作。 すべての操作はオンラインで処理する必要があるため、グループの再構築やその内容のスキャンは不可能です。 各マージ、分割、またはクエリ中にすべてのノードにアクセスするソリューションは、$O(q^2)$、これは 8 秒の制限が処理できる範囲をはるかに超えています。 各操作は対数時間で機能する必要があります。 

厄介なケースは、ノード識別子が位置を記述していないという事実から生じます。 ノードは、マージおよび分割後にグループ内のどこにでも移動できます。 

たとえば、次のような場合:```
5
1 10
1 20
2 1 2
4 1
4 2
```出力は次のとおりです。```
30
30
```各ノードの元のグループのみを記憶する不注意な解決策は失敗します。ノード 1 と 2 が同じ順序付けられたシーケンスの一部になるためです。 

もう 1 つのエッジ ケースは、クエリされたノードを含むグループを分割するが、そのノードをカットのどちらかの側に残す場合です。 

例えば：```
4
1 5
1 7
2 1 2
3 2 1
4 2
```出力は次のとおりです。```
7
```分割前のシーケンスは次のとおりです。`[1, 2]`。 最初のノードの作成後に分割する`[1]`そして`[2]`。 ノード 2 は最初のグループに属していないため、古いルートのみを保存すると間違った結果が得られます。 

最後の境界ケースは、グループの終わり近くで分割されています。```
3
1 8
3 1 1
4 1
```出力は次のとおりです。```
8
```グループにはノードが 1 つしかないため、分割は何も行いません。 両方の結果部分が存在することを前提とした実装では、親ポインターが破損する可能性があります。 

## アプローチ

 直接的なアプローチは、すべてのグループをリストとして保存することです。 ノードの作成は簡単で、グループのクエリはそのリストを合計することを意味します。 この問題は、操作によりグループ全体を移動したり分割したりするときに発生します。 2 つの大きなグループを結合するには、多くの要素をコピーまたはリンクする必要があり、分割するには、カット位置まで歩く必要があります。 最悪の場合、$5 \cdot 10^5$操作はそれぞれタッチできます$5 \cdot 10^5$ノード、説明$2.5 \cdot 10^{11}$操作。 

操作の構造から重要な観察結果が得られます。 グループは任意のセットではなく、順序付けられたシーケンスです。 必要な操作は、暗黙的 treap でサポートされている操作とまったく同じです。つまり、2 つのシーケンスの連結、シーケンスの位置による分割、値の合計などの集計情報の維持です。 

残りの課題は、どのシーケンスに特定のノードが含まれているかを答えることです。 各 treap ノードには親ポインタが格納されます。 親ポインターをたどると、そのグループの現在のルートに到達します。 トレプ高さは平均して対数であるため、グループの検索も対数になります。 

ブルート フォースはグループを直接モデル化するため機能しますが、グループが動的シーケンスであることを無視するため失敗します。 すべての操作がシーケンス操作であるという観察により、すべてのグループを暗黙的な treap で表現し、すべての操作を高速に保つことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q^2)$|$O(q)$| 遅すぎる |
 | 最適 |$O(q \log q)$予想される |$O(q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 作成クエリが表示されたら、暗黙的 treap ノードを 1 つ作成します。 その値は指定された値であり、そのサイズは 1 であり、その合計はその値です。 今後のクエリがこのノードに直接アクセスできるように、そのインデックスを保存します。 
2. マージ クエリの場合は、2 つの参照ノードのルートを見つけます。 すでに同じトレプ内にある場合は、何も変わりません。 それ以外の場合は、2 つのトレプをマージし、最初のルートを 2 番目のルートの前に配置します。 暗黙的な treap マージ操作では、ツリーのバランスを保ちながらシーケンスの順序が維持されます。 
3. 分割クエリの場合は、参照されるノードのルートを見つけます。 最初のトリープの後でそのトリープを分割する$z$ノード。 結果として得られる 2 つの treap は、プレフィックス グループとサフィックス グループを表します。 ノード自体はどちらの部分にもなる可能性があるため、保存されたグループ識別子ではなく親ポインターに依存する必要があります。 
4. 合計クエリの場合は、参照ノードから親ポインタを経由してグループ ルートに到達するまで登ります。 ルートにはトレプ全体の合計が保存されるため、その値が答えとなります。 

なぜ効果があるのか:

 不変条件は、すべてのトリープが正確に 1 つの現在のグループを表し、トリープの順序どおりの走査がそのグループ内のノードの順序であるということです。 マージでは、2 つのグループを連結したものと同じ順序のシーケンスが維持されます。 Split は、要求された位置で順序どおりのシーケンスを分割するため、結果として得られる両方のグループに正確に正しいノードが含まれます。 保存されたサブツリーの合計は、構造が変更されるたびに更新され、ルートの合計がグループ全体の合計と等しくなります。 親ポインタは常にすべてのノードをそのトレプの現在のルートに接続するため、ノード クエリは常に正しいグループに到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import random
sys.setrecursionlimit(1 << 25)

left = [0]
right = [0]
parent = [0]
size = [0]
total = [0]
value = [0]
priority = [0]

def pull(x):
    if x:
        size[x] = size[left[x]] + size[right[x]] + 1
        total[x] = total[left[x]] + total[right[x]] + value[x]

def merge(a, b):
    if not a:
        if b:
            parent[b] = 0
        return b
    if not b:
        parent[a] = 0
        return a
    if priority[a] > priority[b]:
        right[a] = merge(right[a], b)
        if right[a]:
            parent[right[a]] = a
        pull(a)
        parent[a] = 0
        return a
    else:
        left[b] = merge(a, left[b])
        if left[b]:
            parent[left[b]] = b
        pull(b)
        parent[b] = 0
        return b

def split(t, k):
    if not t:
        return 0, 0
    if size[left[t]] >= k:
        a, b = split(left[t], k)
        left[t] = b
        if b:
            parent[b] = t
        pull(t)
        parent[t] = 0
        if a:
            parent[a] = 0
        return a, t
    else:
        a, b = split(right[t], k - size[left[t]] - 1)
        right[t] = a
        if a:
            parent[a] = t
        pull(t)
        parent[t] = 0
        if b:
            parent[b] = 0
        return t, b

def root_of(x):
    while parent[x]:
        x = parent[x]
    return x

def new_node(v):
    idx = len(value)
    left.append(0)
    right.append(0)
    parent.append(0)
    size.append(1)
    total.append(v)
    value.append(v)
    priority.append(random.randrange(1 << 60))
    return idx

def solve():
    q = int(input())
    ans = []
    nodes = [0] * (q + 1)

    for i in range(1, q + 1):
        query = list(map(int, input().split()))
        t = query[0]

        if t == 1:
            nodes[i] = new_node(query[1])

        elif t == 2:
            y, z = query[1], query[2]
            a = root_of(nodes[y])
            b = root_of(nodes[z])
            if a != b:
                merge(a, b)

        elif t == 3:
            y, z = query[1], query[2]
            r = root_of(nodes[y])
            if size[r] > z:
                split(r, z)

        else:
            y = query[1]
            ans.append(str(total[root_of(nodes[y])]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列は treap ノードのフィールドを表します。 Python オブジェクトの代わりに配列を使用すると、ノードの最大数が制限されるため、メモリのオーバーヘッドが削減されます。$5 \cdot 10^5$。`merge`そして`split`これらは標準の暗黙的な treap 操作です。 ポインタを変更するたびに、`pull`サブツリーのサイズと合計を再計算します。 親ポインタは、後でノードの現在のグループを見つけるときに必要になるため、これらの操作中に更新されます。 

の`root_of`この関数はパス圧縮を必要としません。 優先順位がランダムであるため、トレプの高さは対数のままであると予想されるため、上向きに歩くのは十分に速いです。 

分割条件は次を使用します`size[left[t]]`暗黙的な treap は左側のサブツリーのサイズから位置を決定するためです。 これにより、最初の要素を分離するときに 1 つずつずれてしまうミスを回避できます。$z$ノード。

 ## 特殊なケース

 マージ ID の問題の場合:```
5
1 10
1 20
2 1 2
4 1
4 2
```このアルゴリズムでは、作成時にノードを個別に保存し、その後、マージ操作によって両方のノードを含む 1 つのツリーを作成します。 両方の親チェーンが同じルートに到達するようになったため、両方のクエリは結合された合計を返します。 

クエリされたノードを中心に分割する場合:```
4
1 5
1 7
2 1 2
3 2 1
4 2
```トレプシーケンス`[5,7]`に分かれています`[5]`そして`[7]`。 ノード 2 は 2 番目のトレプのルートになるため、ルートの合計は 7 になります。親トラバーサルでは、古い情報を使用する代わりに、新しいルートが検索されます。 

何も分離できない分割の場合:```
3
1 8
3 1 1
4 1
```アルゴリズムは、分割する前にグループ サイズをチェックします。 サイズが要求されたプレフィックス長より大きくないため、操作ではトレプは変更されず、クエリでは依然として合計 8 が表示されます。
