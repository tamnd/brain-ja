 ## 解決策
 ## 問題の理解

 変更可能な文字列を維持します。 文字列は次で始まります`n`小文字、そして`q`操作により変更するか、それについて質問してください。 削除では、連続した間隔全体が削除されます。 挿入では、指定された位置に 1 つの新しい文字が配置され、後続の文字が右にシフトされます。 クエリは、現在の部分文字列がその逆の部分文字列と等しいかどうかを尋ねます。 

難しさは、ポジションが固定されていないという事実から来ています。 現在位置 100 にある文字は、削除と挿入により、後で位置 20 になる可能性があります。 同時に、回文を直接チェックするには、クエリされた間隔内のすべての文字を調べる必要があります。 

制限が大きい: 初期の長さと操作の数の両方が制限に達する可能性があります。`3 * 10^5`。 長さの部分文字列をスキャンするソリューション`n`すべてのクエリが実行できるのは`n * q`、それは約です`9 * 10^10`最悪の場合は性格検査。 操作ごとの単純な線形解であっても、コンテストの制限時間の許容範囲をはるかに超えています。 各操作が対数時間で機能する必要があります。 

見落としやすいケースがいくつかあります。 1 文字の部分文字列は常に回文です。 たとえば、入力```
1 1
z
3 1 1
```出力しなければなりません```
yes
```2 つの半分を比較し、このケースを忘れたソリューションでは、誤って拒否される可能性があります。 

もう 1 つのケースは、挿入が先頭または末尾で発生する場合です。 例えば、```
3 2
abc
2 a 1
3 1 2
```文字列を生成します`aabc`、クエリされた部分文字列は`aa`、したがって、答えは次のとおりです`yes`。 位置をゼロベースとして誤って扱うコードは、多くの場合、ここで間違った場所に挿入されます。 

削除すると、文字列の大部分が空になる場合もあります。 例えば、```
5 2
abcba
1 2 4
3 1 2
```葉`aa`、これは回文です。 削除後に古いインデックスを保持する構造は、代わりに古い文字列の結果を返す場合があります。 

## アプローチ

 直接的な方法は、文字列を配列またはリストに格納することです。 挿入と削除には文字を移動する必要があり、回文クエリでは両端の文字を比較できます。 クエリ自体にコストがかかる`O(length of substring)`、挿入と削除にはコストがかかる場合がありますが、`O(n)`多くのキャラクターが動く可能性があるため。 と`3 * 10^5`運用上、最悪の場合はおよそに達する`O(nq)`が鈍くなるにもほどがあります。 

重要な点は、操作がすべてシーケンス内の位置に基づいているということです。 すべての要素にランダムにアクセスする必要はありません。シーケンスを任意の位置で分割し、部分を結合して、セグメントに関する情報をすばやく取得する必要があります。 

暗黙的トレプはまさにこのために設計されています。 これは、シーケンスをランダム化されたバランスのとれたバイナリ ツリーとして保存します。この場合、順序内トラバーサルが現在の文字列順序となります。 各ノードはそのサブツリーのサイズを保存するため、ある位置で分割して部分をマージできます。`O(log n)`予想される時間。 

回文クエリに答えるために、すべての treap ノードは 2 つのローリング ハッシュを維持します。1 つは通常の順序の文字列用、もう 1 つは逆順の文字列用です。 部分文字列が同じ前方ハッシュと後方ハッシュを持つ場合、それは回文とみなされます。 トリープを分割すると、要求された部分文字列が分離され、文字をスキャンせずに、保存されたハッシュがクエリに応答できるようになります。 

ブルートフォース手法は、回文の定義を直接チェックするため機能しますが、情報は繰り返し再計算されます。 部分文字列が維持されたハッシュで表現できるという観察により、反復スキャンを対数分割後の定数時間チェックに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n)`クエリごとに、`O(n)`修正ごと |`O(n)`| 遅すぎる |
 | 最適 |`O(log n)`操作ごとに期待される |`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期文字列から暗黙的トリープを構築します。 各ノードには、その文字、サブツリーのサイズ、優先順位、左右の子、および 2 つのハッシュが格納されます。 順方向ハッシュは、左から右に表示される部分文字列を表し、逆方向ハッシュは、同じ部分文字列を右から左に表します。 
2. ポジションの削除について`l`を通して`r`、トレプを 3 つの部分に分割します。`l`、削除されるセグメント、およびその後の接尾辞`r`。 中央の部分は破棄され、残りの 2 つの部分がマージされます。 
3. 位置挿入用`p`、トレプを最初の部分に分割します`p-1`文字と残りのサフィックス。 挿入したキャラクタの新しいノードを作成し、3 つの部分を結合して戻します。 
4. 位置に関する回文クエリの場合`l`を通して`r`、要求されたセグメントを分割します。 順方向ハッシュと逆方向ハッシュを比較します。 ハッシュが等しいということは、セグメントが両方向で同じように読み取られることを意味します。 後で部分をマージして元の文字列を復元します。 
5. マージまたは分割するたびに、保存されたサイズとハッシュを再計算します。 これにより、すべてのノードの概要がそのサブツリーの正確な情報と等しくなります。 

アルゴリズムの背後にある不変条件は、すべての treap ノードが常にそのサブツリーに含まれるシーケンスを正確に記述するということです。 分割では文字の順序が保持され、マージではすでに正しいシーケンスのみが連結されます。 格納されたハッシュは構造が変更されるたびに更新されるため、クエリで使用される分離セグメントは常に正しい順方向および逆方向の表現を持ちます。 等しい表現は、維持されているハッシュに従ってセグメントが回文であることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD1 = 10**9 + 7
MOD2 = 10**9 + 9
BASE = 911382323

MAXN = 700000

pow1 = [1] * (MAXN + 5)
pow2 = [1] * (MAXN + 5)
for i in range(1, MAXN + 5):
    pow1[i] = pow1[i - 1] * BASE % MOD1
    pow2[i] = pow2[i - 1] * BASE % MOD2

import random
random.seed(1)

class Node:
    __slots__ = ("c", "p", "l", "r", "sz", "h1", "h2", "rh1", "rh2")
    def __init__(self, c):
        self.c = ord(c) - 96
        self.p = random.randint(1, 1 << 60)
        self.l = None
        self.r = None
        self.sz = 1
        self.h1 = self.h2 = self.c
        self.rh1 = self.rh2 = self.c

def size(t):
    return t.sz if t else 0

def hashes(t):
    if t:
        return t.h1, t.h2, t.rh1, t.rh2
    return 0, 0, 0, 0

def pull(t):
    if not t:
        return
    ls = size(t.l)
    rs = size(t.r)
    lh1, lh2, lrh1, lrh2 = hashes(t.l)
    rh1, rh2, rrh1, rrh2 = hashes(t.r)

    t.sz = ls + 1 + rs

    t.h1 = (lh1 * pow1[1 + rs] + t.c * pow1[rs] + rh1) % MOD1
    t.h2 = (lh2 * pow2[1 + rs] + t.c * pow2[rs] + rh2) % MOD2

    t.rh1 = (rrh1 * pow1[1 + ls] + t.c * pow1[ls] + lrh1) % MOD1
    t.rh2 = (rrh2 * pow2[1 + ls] + t.c * pow2[ls] + lrh2) % MOD2

def split(t, k):
    if not t:
        return None, None
    if size(t.l) >= k:
        a, b = split(t.l, k)
        t.l = b
        pull(t)
        return a, t
    else:
        a, b = split(t.r, k - size(t.l) - 1)
        t.r = a
        pull(t)
        return t, b

def merge(a, b):
    if not a or not b:
        return a or b
    if a.p > b.p:
        a.r = merge(a.r, b)
        pull(a)
        return a
    else:
        b.l = merge(a, b.l)
        pull(b)
        return b

def build(s):
    root = None
    for ch in s:
        root = merge(root, Node(ch))
    return root

def solve():
    n, q = map(int, input().split())
    root = build(input().strip())
    ans = []

    for _ in range(q):
        query = input().split()
        typ = int(query[0])

        if typ == 1:
            l, r = int(query[1]), int(query[2])
            a, b = split(root, l - 1)
            _, c = split(b, r - l + 1)
            root = merge(a, c)

        elif typ == 2:
            c = query[1]
            p = int(query[2])
            a, b = split(root, p - 1)
            root = merge(merge(a, Node(c)), b)

        else:
            l, r = int(query[1]), int(query[2])
            a, b = split(root, l - 1)
            mid, c = split(b, r - l + 1)
            if mid.h1 == mid.rh1 and mid.h2 == mid.rh2:
                ans.append("yes")
            else:
                ans.append("no")
            root = merge(a, merge(mid, c))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ノード クラスには、トレプに必要な情報が正確に含まれています。 サブツリーのサイズにより、`split`明示的なインデックスを保存せずに位置を検索します。 4 つのハッシュは、2 つの異なる係数の下での順方向ローリング ハッシュと逆方向ローリング ハッシュであり、衝突の可能性を減らします。 

の`pull`機能は中核となるメンテナンス操作です。 子が変更されると、サブツリー全体のサマリーが再計算されます。 数式では、フォワード ハッシュの左側の子が現在の文字の前に配置され、次に右側の子の前に配置されます。 逆ハッシュは、同じアイデアを逆方向に適用します。 

の`split`関数はサブツリー サイズを使用して最初の部分を分離します`k`残りのキャラクター。 重要な境界条件は、`k`は文字数を表すため、位置に挿入します`p`で分割することを意味します`p - 1`。 

クエリ操作により、要求された間隔が一時的に削除されます。 これは文字をコピーするのではなく、ツリーのリンクを変更するだけなので、対数のままです。 ハッシュを確認した後、同じ部分をマージすることで元の treap が再構築されます。

 ## 特殊なケース

 1 文字のクエリは、他のすべてのクエリと同じハッシュ比較によって処理されます。 のために```
1 1
z
3 1 1
```分離されたトリープには、`z`。 その順方向ハッシュと逆方向ハッシュは両方とも`26`、したがって、答えは次のとおりです`yes`。 

最初の位置への挿入は、off-by-one エラーの一般的な原因です。 のために```
3 2
abc
2 a 1
3 1 2
```分割点はゼロ文字です。 新しい木はこうなります`aabc`、最初の 2 文字は`aa`したがって、両方のハッシュが一致し、答えは次のようになります。`yes`。 

削除された間隔は treap セグメント全体として表されるため、大規模な削除は機能します。 のために```
5 2
abcba
1 2 4
3 1 2
```分割は削除します`bcb`、出発`aa`。 クエリはこれら 2 つの文字を分離し、等しいハッシュを比較して、`yes`。 トレプ構造はすでに新しいシーケンスを表しているため、文字位置を手動で調整する必要はありません。
