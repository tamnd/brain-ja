 ## 解決策
 ## 問題の理解

 この問題は一連のスニーッチを追跡しており、各スニーッチには 0 または 1 つの星が付いています。 クエリは連続した間隔を選択し、その値を切り替えるマシンを介してこれらのスニーッチを送信します。つまり、0 は 1 になり、1 は 0 になります。 トグル操作のたびに、すべてのスニーッチが同じ値を持つ最長の連続セグメントの長さを報告する必要があります。 この問題の最初のバージョンには、これらの切り替えクエリのみが含まれています。 

入力により、スニーッチを説明する最初のバイナリ文字列が与えられ、その後、切り替える間隔のシーケンスが与えられます。 すべての間隔で、出力は 1 または 0 の数ではなく、現在の文字列内の任意の場所にある同一の隣接する値の最長ブロックです。 

制約は大きく、スニーッチの数と操作の数は両方とも上限に達します。$3 \cdot 10^5$。 すべての操作の後に配列全体をスキャンするソリューションでは、次のような処理が実行されます。$9 \cdot 10^{10}$最悪の場合、通常のコンテストの制限時間内に収まる時間をはるかに超えた操作が行われます。 各更新とクエリの結果は対数時間で処理される必要があります。 

主なエッジ ケースは、境界に接する間隔、または配列全体を含む間隔から発生します。 間隔内のみを更新し、答えが境界を越えてマージされる可能性があることを忘れたソリューションは失敗します。 たとえば、入力が次の場合:```
5 1
00111
1 2 4
```配列は次のようになります`01011`、したがって、答えは次のとおりです`2`最後の 2 つは最長の等しいセグメントを形成するためです。 反転したセグメントだけをチェックするいい加減な実装`101`誤って報告する可能性がある`1`。 

もう 1 つの注意が必要なケースは、すでに均一になっている間隔を反転することです。 例えば：```
4 1
0000
1 2 3
```結果は`0110`、そして答えは`2`。 更新により、中央の部分がすべて 0 からすべて 1 に変更されますが、外側の 0 は接続されたままになります。 変更された間隔内で作成された最大セグメントのみを保存するアプローチでは、外部の寄与が見逃される可能性があります。 

最後の境界ケースは、単一要素の更新です。```
3 1
010
1 2 2
```配列は次のようになります`000`、したがって、答えは次のとおりです`3`。 反転された区間には常にマージする 2 つの側面があると想定している実装では、この状況を誤って処理する可能性があります。 

## アプローチ

 直接的な解決策は、バイナリ配列を保存し、から実行して各操作を処理することです。`l`に`r`、すべての要素を切り替えます。 更新後、別のスキャンで同じ値の最長の連続を見つけることができます。 これは問題で説明されているプロセスを正確にシミュレートしているため、これは正しいです。 ただし、1 回の操作ですべてにアクセスできます。$n$要素があり、答えを見つけるにもコストがかかります$O(n)$。 と$q$操作を行うと、最悪のケースが発生します。$O(nq)$、それは約です$9 \cdot 10^{10}$最大制約のための要素の訪問数。 

重要な観察は、操作が範囲反転であり、要求された応答が隣接するセグメントから結合できるプロパティであるということです。 セグメント ツリーは、2 つの半分をマージするのに十分な情報を格納することで、すべての間隔を表すことができます。 毎回の操作後にセグメント全体の正確な値は必要ありません。 必要なのは、セグメント長とともに、最長のプレフィックス、最長のサフィックス、および 0 と 1 の最長の内部連続だけです。 

セグメントが反転されると、0 と 1 は単に役割を交換します。 最長のゼロのプレフィックスは、前の最長のプレフィックス 1 になり、同じことがサフィックスと最良のセグメントにも当てはまります。 これにより、遅延伝播が自然になります。すべての要素を訪問する代わりに、セグメント全体を反転済みとしてマークし、子が実際に必要になるまでその変更のプッシュを遅らせます。 

すべての要素が明示的に変更されるため、ブルート フォースが機能します。 要素が多すぎると頻繁に変更される可能性があるため、失敗します。 セグメント ツリーが機能するのは、大規模な範囲の更新を 1 つの遅延フラグで表すことができ、各操作を$O(\log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | 最適 |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期バイナリ文字列からセグメント ツリーを構築します。 すべてのノードについて、セグメント長、ゼロのみで構成される最長のプレフィックスとサフィックス、1 の同じ値、最良のオール ゼロ セグメント、最良のオール 1 セグメント、および遅延反転フラグを保存します。 

これらの値は、まさに 2 つの隣接するセグメントを結合するために必要な情報です。 2 つの子の境界に関係する回答には、左の子の接尾辞と右の子の接頭辞を使用する必要があります。 
2. クエリ間隔の場合$[l,r]$、セグメント ツリーに再帰的にアクセスします。 ノードが完全に間隔内にある場合は、さらに深く進むのではなく、そのノードに反転を適用します。 

フリップを適用すると、すべての 0 関連フィールドが、対応する 1 関連フィールドと交換され、遅延フラグが切り替わるだけです。 セグメントの長さは変わりません。 
3. 部分的にカバーされているノードにアクセスしたら、続行する前にその保留中のフリップをその子にプッシュします。 

これにより、子と親の現在の状態の一貫性が保たれます。 親にはすでに正しく結合された情報が含まれているため、更新を遅らせても安全です。 
4. 間隔を更新した後、ルート ノードの応答を、最長のオール 0 セグメントと最長のオール 1 セグメントの最大値として読み取ります。 

ルートは完全な配列を表すため、ルートに保存されている最良のセグメントがまさに必要な答えとなります。 

なぜ効果があるのか:

 すべてのセグメント ツリー ノードは常に、その間隔の現在の状態を記述します。 マージ操作では、すべての最長の等しい値セグメントが完全に左側の子内にあるか、完全に右側の子内にあるか、中央の境界を越えているため、このプロパティが保持されます。 保存されたプレフィックスとサフィックスの値は、交差する場合を処理します。 フリップは 0 と 1 の役割を交換するだけなので、保存されている 0 と 1 の情報を交換することでノードが正しく保たれます。 すべての更新では影響を受けるすべてのノードの不変式が保持されるため、ルートには常に正しい最長均一セグメントが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = (
        "length",
        "pref0", "suff0", "best0",
        "pref1", "suff1", "best1",
        "lazy"
    )

    def __init__(self):
        self.length = 0
        self.pref0 = self.suff0 = self.best0 = 0
        self.pref1 = self.suff1 = self.best1 = 0
        self.lazy = False

def merge(a, b):
    c = Node()
    c.length = a.length + b.length

    c.pref0 = a.pref0
    if a.pref0 == a.length:
        c.pref0 += b.pref0

    c.pref1 = a.pref1
    if a.pref1 == a.length:
        c.pref1 += b.pref1

    c.suff0 = b.suff0
    if b.suff0 == b.length:
        c.suff0 += a.suff0

    c.suff1 = b.suff1
    if b.suff1 == b.length:
        c.suff1 += a.suff1

    c.best0 = max(a.best0, b.best0, a.suff0 + b.pref0)
    c.best1 = max(a.best1, b.best1, a.suff1 + b.pref1)

    return c

def apply_flip(node):
    node.pref0, node.pref1 = node.pref1, node.pref0
    node.suff0, node.suff1 = node.suff1, node.suff0
    node.best0, node.best1 = node.best1, node.best0
    node.lazy = not node.lazy

def build(idx, l, r):
    tree[idx] = Node()
    if l == r:
        tree[idx].length = 1
        if s[l] == '0':
            tree[idx].pref0 = tree[idx].suff0 = tree[idx].best0 = 1
        else:
            tree[idx].pref1 = tree[idx].suff1 = tree[idx].best1 = 1
        return

    m = (l + r) // 2
    build(idx * 2, l, m)
    build(idx * 2 + 1, m + 1, r)
    tree[idx] = merge(tree[idx * 2], tree[idx * 2 + 1])

def push(idx):
    if tree[idx].lazy:
        apply_flip(tree[idx * 2])
        apply_flip(tree[idx * 2 + 1])
        tree[idx].lazy = False

def update(idx, l, r, ql, qr):
    if qr < l or r < ql:
        return
    if ql <= l and r <= qr:
        apply_flip(tree[idx])
        return

    push(idx)
    m = (l + r) // 2
    update(idx * 2, l, m, ql, qr)
    update(idx * 2 + 1, m + 1, r, ql, qr)
    tree[idx] = merge(tree[idx * 2], tree[idx * 2 + 1])

def solve():
    global s, tree

    n, q = map(int, input().split())
    s = input().strip()
    s = " " + s

    tree = [None] * (4 * n + 5)
    build(1, 1, n)

    ans = []
    for _ in range(q):
        _, l, r = map(int, input().split())
        update(1, 1, n, l, r)
        ans.append(str(max(tree[1].best0, tree[1].best1)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`Node`オブジェクトにはマージに必要な情報のみが格納されます。 ゼロランと 1 ランの値を別々に保持すると、セグメントの実際の内容を知る必要がなくなります。 

の`merge`関数は、最適なセグメントの 3 つの可能な位置 (完全に左側の子内、完全に右側の子内、または境界を越える) を処理します。 交差するケースがあるため、サフィックスとプレフィックスの長さの両方が保存されます。 

の`apply_flip`関数は問題の中心的な観察です。 反転によってセグメントの長さは変更されることはなく、0 と 1 の意味が交換されるだけです。 遅延フラグは、子がこの交換を適用する必要があることを記録します。 

再帰的更新では遅延伝播が使用されます。 完全に覆われたセグメントはすぐに反転され、部分的なセグメントは最初に下に押し込まれます。 この順序により、古い子情報が将来のマージに影響を与えるのを防ぎます。 

Python の整数はここではオーバーフローしません。これは、保存されている最大値は$n$、最大でも$3 \cdot 10^5$。 インデックス付けでは、クエリ インデックスがステートメントと直接一致するように、位置 0 にダミー文字が使用されます。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old_stdin

    it = iter(data)
    n = int(next(it))
    q = int(next(it))
    s = next(it)

    arr = list(map(int, s))
    out = []

    for _ in range(q):
        next(it)
        l = int(next(it)) - 1
        r = int(next(it)) - 1
        for i in range(l, r + 1):
            arr[i] ^= 1

        best = 1
        cur = 1
        for i in range(1, n):
            if arr[i] == arr[i - 1]:
                cur += 1
            else:
                cur = 1
            best = max(best, cur)
        out.append(str(best))

    return "\n".join(out)
