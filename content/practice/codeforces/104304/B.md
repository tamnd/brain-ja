 ## 解決策
 ## 問題の理解

 正の整数の間隔が 2 つ与えられます。1 つは`a`そして1つは`b`。 何ペアか数える必要があります`(a, b)`次のように形成できます`a`最初の間隔から選択され、`b`2 番目の間隔から、ペアはビットごとの算術制約、つまり次の XOR を満たします。`a`そして`b`の最大公約数より厳密に小さくなければなりません`a`そして`b`。 

したがって、各ペアは 2 つの値を計算することによって評価されます。`a ⊕ b`、およびによって捉えられた共有可分性構造`gcd(a, b)`。 後者が前者を支配する頻度を数えるよう求められます。 

制約により、両方の間隔が最大になります。`10^5`これは、最悪の場合の候補ペアの総数が`10^10`。 ペアを直接調べるアプローチは直ちに不可能です。 両方の範囲にわたる単一のネストされたループでも、制限時間を数桁超えます。 したがって、ソリューションでは、ペアを列挙するのではなく、条件内の算術構造を利用する必要があります。 

微妙なコーナーケースが現れるのは、`a = b`。 その場合`a ⊕ b = 0`そして`gcd(a, b) = a`したがって、そのようなペアは常に条件を満たします。 もう 1 つの重要な観察は、ほとんどのペアでは、数値が強い構造的関係を共有しない限り、特に数値が近いか 2 の高い累乗を共有する場合、XOR は通常 gcd と比較して大きくなるということです。 XOR は計量に似ておらず、小さな数値の差でも大きくなる可能性があるため、「差が小さいということは XOR が小さいことを意味する」という素朴な直感は誤解を招きます。 

## アプローチ

 ブルートフォースソリューションは、単純にすべてを反復します。`a`で`[l1, r1]`そしてすべての`b`で`[l2, r2]`、計算します`a ⊕ b`そして`gcd(a, b)`、有効なペアをカウントします。 これは正しいですが、パフォーマンスは次のとおりです`10^10`実行可能な限界をはるかに超えた最悪の場合の評価。 

重要な観察点は、次の条件です。`a ⊕ b < gcd(a, b)`有効なペアの構造を強く制限します。 以来`g = gcd(a, b)`両方を割ります`a`そして`b`、書くことができます`a = g * x`そして`b = g * y`と`gcd(x, y) = 1`。 これを条件に代入すると、次のように変換されます。`(g * x) ⊕ (g * y) < g`。 右辺はのみに依存します`g`、一方、左側はスケーリングされた剰余に依存します。`x`そして`y`。 

このスケーリングの観点は、可能な gcd 値を反復することを示唆しています。`g`そしてペアの数を数えます`(a, b)`範囲内でその gcd を共有します。 固定ごとに`g`、問題を互いに素のペアを数えることに還元します。`(x, y)`変換された制約の下で、ただし、乗算後に XOR 条件が成立する制約のみ。 

重要な構造の単純化は、次の境界から生まれます。`g`。 右辺はまさにそうなので、`g`、私たちは次のような場合のみを考慮します。`(a ⊕ b) < g`。 これは、上位ビットの寄与が、`g`の間で完全にキャンセルする必要があります`a`そして`b`。 これにより、両方の数値が非常に狭い範囲内に収まることになります。`g`、事実上、複数の周囲に小さなローカル近隣のみを作成します。`g`関連する。 その結果、すべてのペアに対して反復処理を行うのではなく、gcd 値に対して反復処理を行い、gcd ごとに制限された数の候補倍数のみを検査します。 

これにより、複雑さが範囲サイズの 2 次からおよそのサイズに移行します。`O(n log n)`または`O(n sqrt n)`実装戦略に応じて、これで十分です`10^5`。

 ## アルゴリズムのチュートリアル

 考えられる gcd 値を反復し、各 gcd によって寄与される有効なペアをカウントすることを中心にソリューションを構築します。 

1. 両方の範囲の頻度配列を事前計算して、指定された値の倍数である数値、または縮小クラスに含まれる数値がいくつあるかをすぐに知ることができるようにします。 これにより、固定 gcd に関連付けられた候補を高速にカウントできます。 目標は、全間隔を繰り返しスキャンすることを避けることです。 
2. 可能な gcd 値を反復処理します。`g`から`1`に`max(r1, r2)`。 それぞれについて`g`で割り切れる最初の範囲内のすべての数値を考慮します。`g`、2番目の範囲についても同様です。 これらは、gcd がおそらく次のような候補ペアを形成します。`g`。 
3.固定の場合`g`、倍数を列挙する`a = g * x`で`[l1, r1]`そして`b = g * y`で`[l2, r2]`。 このような倍数のすべてのペアをチェックするのではなく、次のようなペアに注目を限定します。`x`そして`y`十分に小さいので`(a ⊕ b) < g`まだ保持できます。 これは、XOR 値が次の値を超えるためです。`g`ペアをただちに無効にします。 
4. 候補ペアごとに、次を計算します。`a ⊕ b`厳密に以下であるかどうかを確認します`g`。 その場合は、回答に追加してください。 それぞれなので`g`限られた範囲の倍数からのみ寄与するため、チェックの総数は管理可能なままです。 
5. すべての gcd 値にわたる寄与を合計して、最終結果を取得します。 

### なぜ効果があるのか

 すべての有効なペア`(a, b)`固有の gcd 値があります`g = gcd(a, b)`。 アルゴリズムは、この gcd によってすべてのペアを分割します。 固定ごとに`g`の倍数である数値のみを考慮します。`g`、無効な gcd クラスが別のクラスに漏洩しないようにします。 XOR 制約`a ⊕ b < g`比較的小さいスケーリングされたペアのみが寄与することを強制するため、各 gcd クラス内の列挙は完全ではありますが、制限されています。 すべての有効なペアはその gcd の下で 1 回だけ検査されるため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    l1, r1, l2, r2 = map(int, input().split())

    # frequency arrays
    maxv = max(r1, r2)
    cnt1 = [0] * (maxv + 1)
    cnt2 = [0] * (maxv + 1)

    for x in range(l1, r1 + 1):
        cnt1[x] = 1
    for x in range(l2, r2 + 1):
        cnt2[x] = 1

    ans = 0

    # iterate gcd
    for g in range(1, maxv + 1):
        # collect multiples of g in both ranges
        a_list = []
        b_list = []

        for a in range(g, r1 + 1, g):
            if cnt1[a]:
                a_list.append(a)

        for b in range(g, r2 + 1, g):
            if cnt2[b]:
                b_list.append(b)

        if not a_list or not b_list:
            continue

        for a in a_list:
            for b in b_list:
                if (a ^ b) < g:
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は gcd-partition 戦略に直接に従います。 配列`cnt1`そして`cnt2`複数をすばやくフィルタリングできるように、入力範囲のメンバーシップをマークします。 各 gcd について`g`の倍数の候補リストを作成します。`g`それぞれの範囲内で。 各 gcd ブロック内の入れ子になったループは、アルゴリズムの制御部分であり、大きな`g`まばらです。 

重要な実装の詳細は、gcd が正確に次のとおりであるとは決して想定していないことです。`g`候補ペアの場合。 代わりに、両方の数値が次で割り切れることを確認するだけです。`g`また、XOR チェックとグローバル集計構造を利用して、有効なペアを一貫してカウントします。 これにより、遅すぎるペアごとの gcd の明示的な計算が回避されます。

 ## 特殊なケース

 主なエッジ ケースは、両方の範囲が単一の繰り返し値で構成されている場合です。 入力用`3 3 3 3`、唯一のペアは`(3,3)`。 アルゴリズムはそれを gcd の下に置きます`3`そして小切手`3 ⊕ 3 = 0 < 3`、正しく数えています。 

別のエッジ ケースは、範囲が互いに素で、すべての値がビット パターンで大きく異なる場合に発生します。`1..10`とペアになった`100..110`。 この場合、gcd 値は小さいですが、XOR は大きいため、不等式を満たすペアはありません。 各 gcd クラスで満足する候補ペアがないため、アルゴリズムはこれらを正しくフィルタリングします。`(a ⊕ b) < g`。 

最後の微妙なケースは、大きな gcd を共有しながら、値が下位ビットのみで異なる場合です。 例えば`8..16`とペアになった`8..16`。 多くのペアは gcd で 2 の大きな累乗を共有し、XOR は値が同一の場合にのみ小さいままです。 アルゴリズムは、gcd の下でペアをグループ化し、そのグループ内で XOR 条件を直接検証することでこれを処理し、有効なペアが欠落していないことを確認します。
