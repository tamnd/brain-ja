 ## 解決策
 ## 問題の理解

 円上に配置されたバイナリ シーケンスが与えられます。 各位置には 0 または 1 が含まれており、位置 n−1 が位置 0 に隣接するようにインデックスがラップアラウンドします。許可された操作では、任意の開始インデックス b を選択し、この円上の正確に k 個の連続する位置を反転します。これは、選択された各ビットが 0 から 1、または 1 から 0 に反転されることを意味します。 

目標は、このような長さ k の循環反転を可能な限り最小数使用して、円全体をすべて 1 に変換することです。また、可能であれば、1 つの最適な操作シーケンスも出力します。 まったくできない場合は、不可能であることを報告しなければなりません。 

重要な制約は、すべてのテスト ケースにわたる n の合計が最大 2×10^6 であることです。 T が大きい場合、テストごとに O(n log n) でも遅すぎるため、これにより、テスト ケースごとにすべての解が線形になることが強制されます。 メモリ使用量も線形であり、慎重に管理する必要があります。 

微妙な難しさは、円形の構造に起因します。 多くの素朴なソリューションは配列を線形として扱い、ラップアラウンド効果を無視します。 終わり近くの操作が最初に影響を与えるため、これは正確性を損ないます。 もう 1 つのよくある落とし穴は、パリティを適切に追跡せずに貪欲な反転を行うことであり、これにより実現可能性について誤った結論が導き出されます。 

小さな失敗例としては、n=5、k=2、a=[1,0,0,0,1] があります。 線形化された配列に対する単純な左から右への貪欲は、初期のゼロを修正する可能性がありますが、最後の反転が再びインデックス 0 に影響することを忘れ、有効な循環戦略が存在する場合でも、一貫性のない最終状態が生成されます。 

## アプローチ

 ブルートフォースの見方は簡単です。操作を選択するプロセスをシミュレートし、その数を最小限に抑えようとします。 各ステップで、開始点として任意のインデックスを選択し、反転を適用して、再帰的に続行できます。 これは、サイズ 2^n の状態グラフ上で最短経路問題を形成しますが、各状態には n 個の遷移があり、状態空間は指数関数的に爆発するため、n=20 の場合でも完全に実行不可能です。 

重要な構造は、k 個の連続する位置の反転がスライディング ウィンドウ パリティ効果の切り替えとしてモデル化できることです。 完全な構成を動的に追跡するのではなく、以前の操作を考慮した上で、各位置が現在正しいか間違っているかを追跡します。 順番にスイープする場合、現在の位置を固定する必要があると判断すると、各操作の選択が強制されます。 

主な障害は循環性です。 これを取り除くために、最初の k−1 位置を慎重に考慮し、ラップアラウンド時の一貫性を確保することで、円上の有効な解を表現できることがわかります。 標準的なトリックは、シーケンスを線形に扱いますが、n ラップを超えて拡張する反転を強制し、プレフィックスの位置に影響を与えることです。これは、差分配列を維持しながらモジュラーインデックスによって処理できます。 

各位置のモジュロ 2 に影響を与えるアクティブな反転の数を追跡する差分配列を維持します。0 から n−1 までスイープすると、ランニング パリティを維持することで現在のビットが反転されているかどうかがわかります。 以前の操作を適用した後、現在のビットが 0 の場合は、この位置で反転を開始することを強制されます。これは、今後の操作では以前の固定位置に影響を与えずにビットを遡って変更することができないためです。 

位置 i で、i から始まる演算を適用するかどうかを決定します。 その場合、差分構造を使用して範囲 [i, i+k) modulo n のパリティを切り替えます。 唯一の複雑な点は、制限 n 操作を超えないようにすることと、操作がラップアラウンドするときに一貫性を維持することです。 

すべての位置は最終的に 1 でなければならず、位置 i の 0 を修正する唯一の方法は、i またはそれより前から開始してそれをカバーする反転を適用することであるため、欲張りが機能します。 i を渡すと、それ以降の操作では以前の決定に違反せずに i をカバーできないため、選択は局所的に強制されます。

 | --- | --- | --- | --- |
 | ブルートフォース検索 | O(2^n · n) | O(2^n) | 遅すぎる |
 | 差分配列を使用した貪欲なスイープ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず問題を、反転が各位置にどのように影響するかを追跡することに変換します。 各操作は円上の長さ k の連続セグメントを切り替えるため、範囲 XOR 更新をサポートする差分配列を使用して効果をシミュレートします。 

現在の位置が奇数回反転されたかどうかを示す実行変数 current_flip_parity を維持します。 

また、範囲切り替えを効率的に適用するために、サイズ n+1 (論理的に循環化) の配列 diff も維持します。 

1. diff 配列をゼロおよび current_flip_parity = 0 で初期化します。選択した操作に対する回答リストも準備します。 
2. i を 0 から n−1 まで順番にスイープします。 各位置で、diff[i] modulo 2 を追加して current_flip_parity を更新します。これにより、a[i] が現在反転しているかどうかがわかります。 
3. 実効値を計算します。current_flip_parity が 1 の場合、ビットは反転され、それ以外の場合は元のビットです。 有効値が 1 の場合、この位置はすでに目標を満たしているため、次に進みます。 
4. 実効値が 0 の場合、i から始まる演算を適用する必要があります。 i を操作開始として記録します。 
5. i から開始して長さ k の反転を適用します。 これは、循環的な意味で diff[i] と diff[i+k] (mod n) を更新することによって行われます。 セグメントが循環する場合、更新を 2 つの間隔に分割します。 
6. current_flip_parity を適宜更新し、続行します。 
7. すべてのインデックスを処理した後、累積されたフリップの下ですべてのポジションが 1 で終了することを確認します。 そうでない場合は、-1 を出力します。 

それが機能する理由は、強制選択の不変条件から来ています。 位置 i に到着すると、以前のインデックスには触れずに i に影響を与える可能性のあるすべての操作がすでに決定されています。 i の後に開始される操作は i に影響を与えることができないため、i が現在 0 の場合、唯一可能な修正は i で反転を開始することです。 これにより、貪欲な決定が必要かつ十分となり、差分配列によりセグメントを再計算することなく一貫してエフェクトを適用できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    diff = [0] * (n + 1)
    cur = 0
    ops = []

    for i in range(n):
        cur ^= diff[i]

        if (a[i] ^ cur) == 0:
            ops.append(i)
            cur ^= 1

            end = i + k
            if end < n:
                diff[end] ^= 1
                if i + 1 <= n:
                    diff[i + 1] ^= 1
            else:
                end %= n
                diff[0] ^= 1
                if i + 1 <= n:
                    diff[i + 1] ^= 1

    check = 0
    diff2 = [0] * (n + 1)

    for i in range(n):
        check ^= diff2[i]
        if (a[i] ^ check) == 0:
            return "-1"

        if i in ops:
            check ^= 1
            end = i + k
            if end < n:
                diff2[end] ^= 1
                if i + 1 <= n:
                    diff2[i + 1] ^= 1
            else:
                end %= n
                diff2[0] ^= 1
                if i + 1 <= n:
                    diff2[i + 1] ^= 1

    out = [str(len(ops))]
    if ops:
        out.append(" ".join(map(str, ops)))
    else:
        out.append("")
    return "\n".join(out)

def main():
    t = int(input())
    for _ in range(t):
        print(solve())

if __name__ == "__main__":
    main()
```この実装では、差分配列を使用して範囲 XOR 更新をシミュレートしながら、円上のスイープ ラインを維持します。 変数 cur は、現在のインデックスに影響を与えるアクティブなフリップのパリティを表します。 位置が 0 と評価されると、すぐにそこで反転を開始することにコミットします。 

サークルではラップアラウンドが導入されているため、更新は必要に応じて分割されます。 2 番目のパスでは正確さを検証し、循環伝播によって隠れた不整合が残っていないことを確認します。 

微妙な点は、操作位置をリストに記録し、検証パスで再生することです。 これにより、ラップアラウンド ロジックの下では脆弱になる可能性がある中間状態のみを信頼することが回避されます。

 ## 特殊なケース

 クリティカルなエッジケースは、k が n に近い場合です。 その場合、すべてのフリップはほぼ円全体をカバーするため、初期の貪欲な決定は後の位置を強く制限します。 位置が 0 の場合でもスイープによって決定が強制され、ラップアラウンド更新によって境界間の一貫性が保証されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、配列がすでにすべて 1 である場合です。 すべての有効な値が各ステップですでに満たされているため、アルゴリズムは演算を実行しません。そのため、ops は空のままで、出力は 0 個の演算を正しく返します。 

よりデリケートなケースは、i+k が n を超えるために操作が複数回ラップアラウンドする場合です。 分割更新により、プレフィックスとサフィックスの両方が正しく切り替わることが保証されるため、循環境界を越えて隠れたパリティ ドリフトが蓄積することはありません。
