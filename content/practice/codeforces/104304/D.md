 ## 問題の理解

 私たちには次のシーケンスが与えられています$n$独立した「描画」。 で$i$- 3 回目の抽選では、整数のスコアを選択します$x_i$範囲から均一に$[0, a_i]$、 どこ$a_i < k$。 各描画の後、選択されたすべての値の現在のプレフィックス合計を維持します。 このプレフィックスの合計が次の数で割り切れるときは常に、$k$, 「レアカード」を1枚と数えます。 このプロセスは全員に対して継続されます$n$ドローし、最後にいくつかのレアカードを入手します。 

タスクはランダム性をシミュレートすることではなく、値の割り当てが完了した回数をカウントすることです。$x_1, \dots, x_n$正確に導く$m$珍しいカード。 2 つの割り当てが選択された場合、それらは異なるものとみなされます$x_i$異なるため、確率ではなく有効なシーケンスをカウントします。 

重要な問題は、イベント「プレフィックスの合計が次の値で割り切れる」ということです。$k$” はプレフィックス和モジュロのみに依存します$k$、そしてすべての位置は、可能な遷移の可変範囲に寄与します。 以来$n, k \le 300$、私たちは次のような体制にいます。$O(n^2 k)$または$O(n k^2)$スタイルの動的プログラミングは許容されますが、指数関数的なものは何でも可能です。$n$またはすべての完全な列挙を伴う$\prod (a_i+1)$シーケンスは不可能です。 

素朴なアプローチでは、すべての選択肢を列挙することになります。$x_i$、プレフィックスの合計を計算し、プレフィックスの合計が次の倍数に達する回数を数えます。$k$。 それぞれだとしても$a_i \le 299$、シーケンスの数は次のとおりです。$300^{300}$、それは完全に不可能です。 

「レアカードイベント」が独立していると仮定すると、素朴な推論による微妙な失敗例が現れます。 例えば、小さなことでも、$n$、ステップのイベント$i$以前の合計モジュロ全体に依存します$k$そのため、ポジションごとの貢献度を個別にカウントすると、不正確な結果が得られます。 もう 1 つの間違いは、各位置を剰余 0 に到達する固定確率に寄与するものとして扱おうとすることです。剰余分布はカウント中に決定論的に進化するため、これは破綻します。 

## アプローチ

 重要な観察は、最初の状態を処理した後の唯一の状態が重要であるということです。$i$draws は現在のプレフィックス合計のモジュロです$k$これに気づくと、問題は位置、剰余状態、およびヒット数に関する階層化された DP になります。 

ポジションごとに$i$、選択する$x_i \in [0, a_i]$残差をから移行します$r$に$(r + x_i) \bmod k$。 固定の場合$r$、それぞれ可能です$x_i$次の残基が 1 つだけ生成されるため、遷移は完全に決定されますが、範囲は制限されます。 

主な困難は、すべての選択肢を効率的に集約することです。$x_i$すべての状態ですべての値を明示的に反復する必要はありません。 以来$a_i < k$、残差ごとに事前計算できます。$r$、選択肢はいくつありますか$x_i \in [0, a_i]$送信$r$可能な次の残基ごとに。 これは、区間モジュロにわたる単純なカウントです。$k$で実行できます。$O(k)$ポジションごとに。 

これらの遷移カウントを取得したら、DP を実行します。$dp[i][r][c]$その後何通りか数えます$i$残りのステップ$r$そして正確に見た$c$レアカードイベント。 ステップに移行中$i+1$、次の剰余が 0 になるたびに、レア カードの数が増加します。 

これにより、$O(n \cdot k \cdot m \cdot k)$単純な DP ですが、遷移を注意深く集計すると、次のように減少します。$O(n \cdot k \cdot m)$、それで十分です。

 ## アルゴリズムのチュートリアル

 このプロセスを、現在のモジュロで定義された状態にわたる分布を進化させるものとして扱います。$k$値と、これまでに残基ゼロに到達した回数。 

1. DP テーブルを初期化します。$dp[r][c]$剰余に到達する方法の数を表します$r$要素のプレフィックスを処理した後、正確に収集した後$c$珍しいカード。 当初は、$dp[0][0] = 1$、描画する前は合計がゼロであり、まだイベントをカウントしていないためです。 
2. ポジションごとに$i$、各残基がどのように変化するかを説明する遷移表を構築します。$r$可能なすべての次の残基に移動します$r'$。 あらゆる可能な値に対して$x \in [0, a_i]$、計算します$r' = (r + x) \bmod k$。 すべてを繰り返すのではなく$x$州ごとにいくつあるかを集計します$x$値により各剰余シフトが生成されます。 これにより、遷移の計算が次のように削減されます。$O(k)$ポジションごとに。 
3. 新しい DP アレイを作成する$ndp$ゼロに初期化されます。 現在の残余ごとに$r$そして数えます$c$、配布しています$dp[r][c]$考えられるすべての次の残基にわたって$r'$事前に計算された遷移カウントを使用します。 
4. トランジションが残留物に到達するたびに$0$、レアカードの数を 1 つ増やします。 これはアップデートすることで行われます$ndp[0][c+1]$の代わりに$ndp[0][c]$。 他のすべての残基については、カウントは変更されません。 
5. すべての位置を処理した後、すべての剰余を合計します。$r$値$dp[r][m]$, 最終的な残りは重要ではないため、レアカードの数のみが重要になります。 

正確さは、誘発された状態ごとにグループ化されたすべてのシーケンスの完全なカウントを維持することで得られます。 すべてのステップで、DP 状態は、すべての可能なプレフィックス和のモジュロのマルチセットを正確にエンコードします。$k$剰余ゼロに到達した回数。 それぞれのステップから移行するので、$i$に$i+1$すべての有効な値を考慮します$x_i$正確に 1 回、シーケンスが省略されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_transitions(a, k):
    cnt = [0] * k
    for x in range(a + 1):
        cnt[x % k] += 1
    return cnt

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    dp = [[0] * (m + 1) for _ in range(k)]
    dp[0][0] = 1

    for i in range(n):
        trans = build_transitions(a[i], k)
        ndp = [[0] * (m + 1) for _ in range(k)]

        for r in range(k):
            row = dp[r]
            if not any(row):
                continue
            for c in range(m + 1):
                val = row[c]
                if val == 0:
                    continue
                for add in range(k):
                    ways = trans[add]
                    if ways == 0:
                        continue
                    nr = (r + add) % k
                    nc = c + (1 if nr == 0 else 0)
                    if nc <= m:
                        ndp[nr][nc] = (ndp[nr][nc] + val * ways) % MOD

        dp = ndp

    ans = sum(dp[r][m] for r in range(k)) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、稀なイベントの残基とカウントに関する 2 次元の DP を維持します。 ヘルパー関数により選択範囲が圧縮されます$[0, a_i]$これは、DP 遷移内で各値を個別に反復処理することを回避する重要な最適化です。 

微妙な点はカウントの更新条件です。 レアカードは現在のドローを適用した後にトリガーされるため、増分は現在の残基ではなく次の残基に依存します。 この順序は正確さを保つために非常に重要です。 

この問題はまれなイベントの数のみを制限し、最終的な和のモジュロではないため、最終的な答えは、考えられるすべての終了残基を集計します。$k$。 

## 実用的な例

 小さな例を考えてみましょう。$n = 2, k = 3$、 そして$a = [1, 2]$、 と$m = 1$。 

最初に:

 | --- | --- | --- |

| 残差 r | c=0 | c=1 |

 これは、ステップ数を適用した後、トランジションのみが残基 0 に正確に着地するため、レア カードがまだ発生していないことを示しています。 

今すぐ処理してください$a_2 = 2$、各剰余からの遷移は 3 つの値に分布します。$0,1,2$。 残基 1 から残基 0 に 2 が追加され、レア カードが作成されます。 これによりカウント次元が増加し、次のような状態が生成されます。$c=1$。 

このトレースは、遷移が剰余 0 に到達するとカウント次元が正確に増加し、他のすべての遷移ではカウントが保持されることを確認します。 

2 番目の例は、$n=1, k=2, a=[1]$境界動作を示します。 残基 0 から開始、両方の選択肢$x=0$そして$x=1$有効ですが、$x=0$レアカードを生み出します。 DP は次のようにして 1 つのパスに正しく分割されます。$c=1$そして一つは$c=0$、直接列挙に一致します。

## 特殊なケース

 いつ$k = 1$、すべてのプレフィックスの合計は次で割り切れます。$k$, したがって、すべてのポジションがレアカードに貢献します。 DP は、次のようにしてカウントを強制的に増加させる必要があります。$n$、すべての選択肢は同一のモジュロ 1 であるため、すべてのシーケンスは 1 つの有効な方法にまとめられます。 

いつすべて$a_i = 0$、すべてのドローは固定されています。 プレフィックスの合計は常にゼロであるため、すべてのプレフィックスがレア カードをトリガーします。 アルゴリズムは、DP を介して 1 つのパスを正確に伝播し、分岐することなくすべてのステップでカウントを増加させる必要があります。 

いつ$m = 0$、DP は、そのような遷移が発生しない場合を除き、剰余 0 にヒットした遷移が直ちにカウント対象として無効な状態に移行することを保証する必要があります。 これにより、カウントの増分が厳密に適用され、遅れたり誤って集計されたりしていないことがチェックされます。
