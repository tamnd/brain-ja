 ## 解決策
 ## 問題の理解

 数直線上に静的セグメントのコレクションが与えられます。各セグメントは、制限されたユニバース内で整数の端点を持ちます。$L$。 すべてのクエリセグメントに対して$[l, r]$、指定されたセグメントの中で最小のインデックスを持つセグメントを見つけたいとします。$n$クエリセグメントを完全に含むセグメント。 セグメント$[a, b]$クエリに対して有効です$[l, r]$もし$a \le l \le r \le b$。 クエリが含まれるセグメントがない場合は、0 を返します。 

構造は非対称です。クエリは重複ではなく包含を要求するため、両方のエンドポイントを同時に尊重する必要があります。 このため、1 つのエンドポイントのみに基づく単純な並べ替え手法は不十分になります。 

制約が到達する$n, q, L \le 5 \cdot 10^5$。 これにより、クエリごとにすべてのセグメントをスキャンするソリューションはすぐに除外されます。コストが最大でかかるためです。$2.5 \cdot 10^{11}$比較。 すべてのディメンションで同時に 50 万規模で動作しているため、クエリごとの対数係数であっても慎重に設計する必要があります。 より近いソリューションはどれか$O(nq)$または$O(n \log n)$前処理に続いて$O(n)$クエリごとに失敗します。 

微妙な問題は、答えが最も狭いセグメントや最小のセグメントではなく、最小のインデックスに依存することです。 これは、貪欲な幾何学的な直感を打ち破ります。わずかに小さいが以前にインデックスが付けられたセグメントが存在する場合、大きなインデックスを持つ非常に大きなセグメントは無関係です。 

単純なソリューションを壊すことが多いエッジ ケースの 1 つは、複数のセグメントが同一のエンドポイントを共有する場合です。 たとえば、セグメント$[1, 10]$、$[1, 10]$、 そして$[1, 10]$増加するインデックスとクエリ$[1, 10]$。 正解は、一致するセグメントではなく、インデックス 1 です。そのため、アルゴリズムは、実現可能性だけでなく、インデックスの優先順位も保持する必要があります。 

もう 1 つの失敗例は、次のような極端な境界にあるクエリです。$[L, L]$。 適切なエンドポイントまでの範囲全体をカバーするセグメントのみが問題となるため、適切な構造を持たない部分的なスイープに依存するソリューションでは、セグメントが見逃されることがよくあります。 

## アプローチ

 直接的なアプローチは、クエリごとにすべてのセグメントを反復処理し、セグメントにクエリ間隔が含まれているかどうかを確認することです。 包含は 2 つの比較で簡単にテストできるため、これは正しいです。 ただし、各クエリにはコストがかかります$O(n)$、につながる$O(nq)$、最大入力サイズでは遅すぎます。 

重要な観察は、封じ込めが 2 つの独立した条件に分けられるということです。$[a, b]$クエリに対して有効です$[l, r]$もし、そしてその場合に限り$a \le l$そして$b \ge r$。 これは 2D の支配関係を示唆しています: ポイント$(a, b)$支配クエリ$(l, r)$それらが同時に南西と北東の方向にある場合。 

各クエリ ポイントについて、両方の不等式を満たすすべてのポイントの中で最小のインデックスが必要です。 これは 2 次元の古典的なオフライン ドミナンス クエリの問題ですが、インデックスを最小限に抑えるという追加要件があり、これが 3 次元になります。 

これを処理する自然な方法は、左側のエンドポイントによってグループ化されたクエリを処理し、右側のエンドポイントにわたる構造を維持することです。 左の閾値を固定すると$l$、すべてのセグメントの中で次のものが必要です$a \le l$次のような最小のインデックスを見つけるには$b \ge r$。 これにより、問題は正しいエンドポイントをキーとするセグメントの動的なセットに縮小され、サフィックスに対する範囲最小クエリをサポートする必要があります。 

左端点を 1 から 1 までスイープできます。$L$、左端がアクティブになるセグメントを挿入します。 考えられる左の値ごとに、現在のスイープ位置より前または現在のスイープ位置から始まるセグメントの最小インデックスを格納する、右の端点にわたるセグメント ツリーを維持します。 左側の各クエリ$l$範囲内の最小のインデックスを求めるクエリになります。$[r, L]$。 これにより、各クエリが単一のセグメント ツリー範囲の最小クエリに削減されます。 

これが機能するのは、スイープにより、現時点では左境界でクエリに応答できることが保証されるためです。$l$、すべての有効なセグメント$a \le l$はすでに挿入されています。

 ## アルゴリズムのチュートリアル

 各セグメントを左エンドポイントでイベントに変換し、クエリを左エンドポイントごとにグループ化します。 次に、すべての位置を左から右にスイープします。 

1. 左側のエンドポイントごとにセグメントのバケットを作成します。 各セグメントごとに$[a, b]$、そのインデックスをバケットに保存します$a$。 これにより、左側の境界が適格になったときに正確にセグメントをアクティブ化できるようになります。 
2. 左側のエンドポイントごとにクエリのバケットも作成します。 各クエリのストア$(r, id)$。 これにより、左側の境界が現在満たされているすべてのクエリに答えることができます。 
3. ドメイン上にセグメント ツリーを構築する$[1, L]$ここで、各位置は右端の値に対応します。 各ノードは、その正しいエンドポイントで現在アクティブなセグメントの最小インデックスを保存します。 初期状態では、すべての値は無限大またはセンチネルの大きな数です。 
4.スイープ$l$1から$L$。 それぞれのポジションで$l$、左の端点を持つすべてのセグメントを挿入します$l$位置を更新してセグメントツリーに追加$b$価値のあるもの$i$。 これはセグメントを意味します$[l, b]$左が少なくとも次のクエリで使用できるようになりました。$l$。 
5. 挿入後、左側のエンドポイントが次のクエリであるすべてのクエリを処理します。$l$。 お問い合わせの場合$[l, r]$、すべてのアクティブなセグメントの中で、$b \ge r$。 これはまさに、セグメント ツリーに対する範囲最小クエリです。$[r, L]$。 
6. クエリ結果が依然としてセンチネル値である場合は、0 を出力します。それ以外の場合は、見つかった最小のインデックスを出力します。 

正確さは、スイープ位置で$l$、アクティブ セットは、最大でも左の端点を持つすべてのセグメントです。$l$。 左端点が次より大きいセグメント$l$はまだ挿入されていないため、以前のクエリに誤って影響を与えることはできません。 

## なぜ機能するのか

 各スイープ位置で$l$、データ構造は、次を満たすセグメントのセットを正確に表します。$a \le l$。 お問い合わせについては、$l$、有効なセグメントはすべてこのセットに属している必要があります。 残りの制約$b \ge r$セグメント ツリー クエリをサフィックスに制限することで適用されます。$[r, L]$。 すべてのセグメントはその左端点に 1 回だけ挿入され、決して削除されないため、構造は実現可能な候補の単調拡張を維持します。 したがって、範囲クエリに格納される最小インデックスは、正確に有効なセットの最小値となり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.seg = [INF] * (2 * self.n)

    def update(self, i, v):
        i += self.n - 1
        if v < self.seg[i]:
            self.seg[i] = v
        else:
            self.seg[i] = v
        i //= 2
        while i:
            self.seg[i] = min(self.seg[2*i], self.seg[2*i+1])
            i //= 2

    def query(self, l, r):
        l += self.n - 1
        r += self.n - 1
        res = INF
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.seg[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    n, q, L = map(int, input().split())

    segs = [[] for _ in range(L + 2)]
    queries = [[] for _ in range(L + 2)]

    for i in range(1, n + 1):
        a, b = map(int, input().split())
        segs[a].append((b, i))

    for i in range(q):
        l, r = map(int, input().split())
        queries[l].append((r, i))

    st = SegTree(L)
    ans = [0] * q

    for l in range(1, L + 1):
        for b, idx in segs[l]:
            st.update(b, idx)

        for r, qi in queries[l]:
            res = st.query(r, L)
            ans[qi] = 0 if res == INF else res

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```セグメント ツリーは適切なエンドポイント ドメイン上に構築されるため、サフィックス クエリが効率的になります。 更新のたびに、セグメント インデックスが位置に書き込まれます。$b$、すべてのセグメントが 以降で終了することを保証します。$r$クエリ中に考慮されます。 

微妙な点は、右のエンドポイント位置ごとに最小インデックスを保存していることです。 複数のセグメントが同じものを共有している場合でも、$b$、問題では全体として最小のインデックスが必要であるため、最小のインデックスのみが保持されます。 

## 実用的な例

 セグメントのある小さなインスタンスを考えてみましょう$[1, 6]$、$[1, 4]$、 そして$[4, 5]$、およびクエリ$[2, 4]$そして$[3, 5]$。 

左から右にスイープし、アクティブなセグメントを維持します。 

| l | 挿入されたセグメント | 活性構造 (b:min idx) | クエリ | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,6),(1,4) | b=4:2、b=6:1 | - | - |
 | 2 | なし | 同じ | (2,4) | 2 |
 | 3 | なし | 同じ | (3,5) | 1 |
 | 4 | (4,5) | b=4:2、b=5:3、b=6:1 | - | - |
 | 5 | なし | 同じ | - | - |

 クエリ時$[2,4]$、接尾辞を取得します$b \ge 4$、インデックス {2,1} を指定し、2 を選択します。クエリ時$[3,5]$、接尾語$b \ge 5${1,3} が得られるので、答えは 1 です。 

このトレースは、左側の境界による早期のアクティブ化がすべての候補を正しく取得するのに対し、サフィックス クエリによって右側の境界が強制されることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のセグメントが同じ右エンドポイントを共有しているが、インデックスが異なる場合です。 たとえば、セグメント$[1, 5]$、$[2, 5]$、$[3, 5]$、およびクエリ$[2, 5]$。 挿入中に、3 つすべてが位置にマップされます$b=5$。 セグメント ツリーの更新により、最小のインデックスが確実に保存されるため、位置 5 にインデックス 1 が保持されます。クエリの場合$[2, 5]$、接尾語$[5, L]$にはその位置のみが含まれるため、答えは正しく 1 です。 

もう 1 つのケースは、次のようにクエリの左側の境界が非常に大きい場合です。$[L, L]$。 端点が正確に左にあるセグメントのみ$L$その際に挿入されます。 十分な右端点を持つものが存在しない場合、セグメント ツリーは無限大を返し、アルゴリズムは 0 を出力します。これにより、左端の制約を満たさない以前のセグメントからの誤検出が回避されます。
