 ## 解決策
 ## 問題の理解

 一緒に送信された 2 つのバイナリ文字列が与えられていますが、一部の位置がワイルドカード記号に破損している可能性があります。`*`。 1 つの文字列は大きな 2 進数を表し、もう 1 つの文字列ははるかに小さな 2 進数を表します。 元の送信には、最初の文字列によってエンコードされた値が 2 番目の文字列によってエンコードされた値で割り切れるという特性がありました。 

私たちのタスクは、受信した部分情報と一致する、最初の数値の有効な元のバイナリ文字列を再構築し、割り算条件を true にする 2 番目の文字列の完成が少なくとも 1 つ存在するようにすることです。 一部のポジションは次のように固定されています`0`または`1`、不明なものもあります。 最初の文字列自体は最大 500 ビットになる場合がありますが、両方の文字列にわたる未知のビットの合計数は少なく、最大 16 です。 

この構造は強い非対称性を意味します。 多数の場合は不明な位置が多数含まれる可能性がありますが、合計で存在する位置はごくわずかです。 2 番目の数値は短く、最大でも 16 ビットであるため、その数値は常に十分に小さく、それに対するモジュラー算術が実行可能です。 割り切れる条件は、完全な整数ではなく剰余について推論する必要があることを示唆しています。 

主な問題は、両方の文字列を単純に再構築すると、最大 16 個の未知のビットにわたる指数関数的な分岐が発生することです。 それはせいぜい$2^{16} = 65536$可能性はぎりぎりですが、各候補を効率的にチェックすればまだ実現可能です。 

2 番目の数値が非常に小さい場合、特に 1 または 2 に評価される場合、微妙なエッジ ケースが発生します。そのような場合、割り算の制約が自明になるか縮退し、可逆性や非ゼロモジュラスの動作を前提とした不用意な実装は失敗する可能性があります。 もう 1 つのエッジ ケースは、ワイルドカードの分布が大きな文字列に大きく偏っており、ほとんどの分岐が係数内で直接発生するのではなく、位置の寄与で発生することを強制される場合です。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法ですべての文字列を置き換えようとします。`*`両方の文字列で`0`または`1`、結果の整数を計算し、割り切れるかどうかを確認します。 未知のビットは合計で最大 16 個あるため、最大で 16 ビットが生成されます。$2^{16}$候補者たち。 各候補は潜在的に 500 ビットの整数を構築する必要がありますが、それは増分バイナリ評価またはモジュラー演算によって処理できます。 これは正しいですが、大きな整数に繰り返し直接実装すると、特に完全な値を毎回再計算する場合は脆弱になります。 

重要な観察は、大きな数の完全な値は決して必要ではなく、構築された小さな数を法とした剰余のみが必要であるということです。 2 番目の数値の候補が決定したら、その値を計算できます$N$、そして、大きな文字列を 2 進数のモジュロとして解釈します。$N$ワンパスで。 これにより、各チェックが大きな文字列の長さにおける線形時間に短縮されます。 

したがって、問題の構造は 2 レベルの検索になります。 まず、小さな文字列の有効な補完をすべて列挙します。これは、この文字列には最大 16 個の未知のビットが含まれており、とにかく短いためです。 次に、そのような候補モジュラスごとに、剰余ゼロを生成する、それと一致する大きな文字列の完成が存在するかどうかを計算します。 未知のビットはグローバルに制限されているため、すべての未知の位置をバイナリ決定の単一のプールとして扱い、一貫性を確保する方法でそれらを位置間で分散できます。 

未知の空間が小さいためブルート フォースは機能しますが、完全な整数を繰り返し再計算したり、大きな文字列を完全な列挙が必要なものとして扱ったりすると、ブルート フォースは失敗します。 モジュラー演算により大きな文字列評価が圧縮されるという観察により、各候補割り当てを線形時間で検証できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 完全な再計算によるすべての割り当てに対するブルート フォース |$O(2^{16} \cdot n)$大きな定数の場合 |$O(1)$| 遅すぎる/壊れやすい |
 | 小さな文字列代入 + モジュラー チェックを列挙する |$O(2^{k} \cdot n)$、$k \le 16$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 未知の構造を 2 つのフェーズ (管理番号の選択とメッセージの検証) に分けて進めます。 

1. 考えられるすべての置換を列挙します。`*`2番目の文字列で。 未知の各ビットは 0 または 1 であるため、約数の候補となるすべての 2 進数を生成します。 これが可能なのは、未知のビットの総数が最大 16 個であるため、たとえすべてがこの文字列内にあったとしても、合計の組み合わせは制限されたままであるためです。 
2. 候補となる 2 番目の文字列ごとに、その整数値を計算します。$N$。 もし$N = 0$、割り算は定義されておらず、問題は少なくとも 1 つを保証するため、スキップしてください。`1`が存在するため、有効な候補が常に存在します。 
3.固定の場合$N$、最初の文字列の有効な補完を構築しようとします。 最初の文字列を 2 進数として扱い、それを剰余として評価します。$N$。 完全な整数を構築する代わりに、剰余を維持しながら左から右にスキャンします。 各位置で、ビットが固定されている場合はそれを使用します。 もしそうなら`*`両方の可能性を試しますが、分岐全体がグローバルに制限されていることを念頭に置いて、制御された方法でこれを実行します。 
4. 大きな文字列全体にわたる指数関数的な爆発を避けるために、両方の文字列にわたる未知のビットがグローバルに制限されているという事実を利用します。 これらの未知の位置に単一の状態空間として決定を割り当てます。 それぞれの完全な割り当てにより、両方の文字列が同時に修正されます。 
5. 完全な割り当てごとに、両方の文字列の整数値を線形時間で計算し、$M \bmod N = 0$。 それが成立する場合、構築されたものを出力します。$M$すぐに。 
6. 特定の選択に対して割り当てが機能しない場合は、$N$、有効なペアが見つかるまで次の候補に進みます。 

正確性は、受信した文字列のすべての可能な完了が、最大 16 個のワイルドカード ビットの 1 つの割り当てに正確に対応するという事実に左右されるため、すべての割り当てを列挙することで、すべての有効な元の送信がカバーされることが保証されます。 

### なぜ効果があるのか

 不確実性の状態空間は完全にワイルドカード位置に含まれます。 このような各位置は、正確に 1 つの二者決定に寄与します。 アルゴリズムはそのような決定をすべて列挙し、それぞれについて、誘導されたペアが可分性制約を満たすかどうかを評価します。 すべての有効なオリジナルの送信はこれらの割り当ての 1 つに対応するため、検索で解決策を見逃すことはありません。 同時に、算術演算は候補ごとに正確に計算されるため、無効な補完はモジュラス チェックに合格できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_candidates(s):
    pos = [i for i, c in enumerate(s) if c == '*']
    k = len(pos)
    res = []

    for mask in range(1 << k):
        arr = list(s)
        for i in range(k):
            arr[pos[i]] = '1' if (mask >> i) & 1 else '0'
        res.append(''.join(arr))
    return res

def to_int(bin_str):
    val = 0
    for c in bin_str:
        val = (val << 1) + (c == '1')
    return val

def check(M, N):
    if N == 0:
        return False
    val = 0
    for c in M:
        val = (val << 1) + (c == '1')
        val %= N
    return val == 0

def main():
    M_raw = input().strip()
    N_raw = input().strip()

    N_candidates = build_candidates(N_raw)
    M_candidates = build_candidates(M_raw)

    for N_str in N_candidates:
        N_val = to_int(N_str)
        if N_val == 0:
            continue

        for M_str in M_candidates:
            if check(M_str, N_val):
                print(M_str)
                return

if __name__ == "__main__":
    main()
```このソリューションでは、まず両方の文字列のすべてのワイルドカード補完を展開します。 ワイルドカードの合計数は最大 16 であり、結合された検索スペースは制限されたままであるため、これは安全です。 各候補約数は整数に変換され、各候補メッセージはその約数を法とする剰余を計算することによってテストされます。 

重要な実装の詳細は、大きなバイナリ文字列のモジュール評価です。 このコードでは、大きな整数を構築する代わりに、ビット シフトを使用してローリング剰余を維持するため、一定のメモリ使用量とチェックごとの線形時間が保証されます。 

よくある間違いは、ペアごとに整数値を繰り返し再計算することです。これは不要ですが、制約の下では許容されます。 ただし、モジュラー累積を使用すると、ソリューションの安定性と高速性が維持されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、2 番目の数値が非常に小さい場合に発生します。`1`または`10`。 そうであれば`1`、すべての数値は割り切れるため、最初の文字列の補完はすべて有効です。 このアルゴリズムはすべての割り当てをテストし、最初の有効な割り当てがすぐに返されるため、引き続き機能します。 

もう 1 つのエッジ ケースは、すべてのワイルドカードが 2 番目の文字列にある場合です。 その状況では、外側のループは最初にすべての約数を列挙します。 各約数について、最初の文字列がそのままテストされます。 これにより、2 つの文字列間の依存関係が回避され、候補間で除数が大幅に変化する場合でも正確さが保証されます。 

最後のエッジケースは、再構築された文字列に先頭のゼロが現れる場合です。 バイナリ解釈では有効性を変更せずに先行ゼロを許可するため、アルゴリズムはそれらを拒否しません。 このような補完は割り算チェックと一貫性を保っているため、有効な文字列を返すだけで十分です。
