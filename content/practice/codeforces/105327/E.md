 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$正方形の宝石箱を表す整数のグリッド。 各セルには個別の数のパールが含まれており、意図された正しい構成では、値はすべての行に沿って左から右に厳密に増加し、またすべての列に沿って上から下に厳密に増加します。 

実際に受け取ったグリッドは、元の向きではない場合があります。 代わりに、時計回りに 0、90、180、または 270 度回転された可能性があり、その結果の構成が表示されます。 私たちのタスクは、元の構成が行方向と列方向の増加特性を満たしていると仮定して、グリッドを元の方向に戻すために反時計回りに何回回転する必要があるかを決定することです。 

重要な制約は、$N \le 50$これにより、グリッドが十分に小さく保たれるため、二次演算や行列の複数の完全な変換さえも可能になります。 グリッド全体を一定回数繰り返しスキャンまたは変換するソリューションは、容易に制限内に収まります。 これにより、これよりも複雑なものは除外されます。$O(N^2)$ただし、4 つの回転すべてを明示的にチェックする余地はまだ残っています。 

微妙な点は、元のグリッドが直接与えられていないことです。 回転したバージョンのみが表示されます。 元の方向は、4 つの回転のうち単調性制約を満たすものとして暗黙的に定義されます。 したがって、出力は外部参照と照合することによって計算されるのではなく、どの回転が有効な増加グリッドを生成するかを識別することによって計算されます。 

エッジケースは主に対称性と小さいサイズに関するものです。 たとえば、非常に小さな回転により、すべての回転が誤って単調性条件を満たした場合、$N$、それでも最小の回転数を選択する必要があります。 

単純なことを考えてみましょう$2 \times 2$場合:

 入力:```
2
1 2
3 4
```これはすでに両方向に増加しているため、正しい答えは 0 です。入力が常に有効な形式から離れる方向に回転されると仮定する不用意なアプローチでは、誤って 0 以外の値が返される可能性があります。 

もう 1 つのケースは、行列が有効な行列を正確に回転したバージョンである場合です。 

入力:```
2
2 4
1 3
```この構成は、ソートされた行列を時計回りに 270 度 (または反時計回りに 90 度) 回転させたものであるため、答えは 3 です。列をチェックせずに行の順序だけを比較するなど、部分的な構造のみを比較するバグがあると、そのようなケースを誤分類する可能性があります。 

## アプローチ

 問題を解決する直接的な方法は、グリッドの 4 つの可能な方向をすべてシミュレートすることです。 方向ごとに、グリッドがすべての行が厳密に左から右に増加し、すべての列が厳密に上から下に増加するという条件を満たすかどうかを確認します。 1 つの方向だけが有効な場合は、その回転カウントを返します。 

ブルートフォースアプローチは簡単です。行列を明示的に回転するか、同等に回転した座標をオンザフライで計算し、各バージョンを検証します。 各検証ではすべてをスキャンする必要があります$N^2$セルをチェックし、行と列の隣接関係をチェックします。 4回転してみるので、合計の仕事量は$4 \cdot O(N^2)$、最悪の場合は約$4 \cdot 2500 = 10000$操作。 時間制限を考えるとこれは些細なことです。 

問題空間は 4 つの状態のみであるため、より深い組み合わせ構造は必要ありません。 重要な観察は、回転は閉じた有限の変換セットであるため、軌道を徹底的にチェックするだけで十分かつ最適であるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(4N^2)$|$O(N^2)$| 承認済み |
 | 最適 |$O(4N^2)$|$O(N^2)$| 承認済み |

 いわゆる最適解は、構造的には総当たりと同じです。制約によってすでに状態空間が 4 つの可能性に制限されているからです。 

## アルゴリズムのチュートリアル

 入力グリッドを現在の方向として扱い、有効な単調構成に到達するために反時計回りに何回回転する必要があるかをテストします。 

1. マトリックスをメモリに読み取ります。 すべての回転の基本状態として再利用できるように、変更しないままにします。 これにより、繰り返しの変換による回転エラーの蓄積が回避されます。 
2. 各候補のローテーション数$k = 0, 1, 2, 3$、その後の行列がどのようになるかを解釈します。$k$反時計回りの回転。 行列を物理的に回転する代わりに、回転した座標から元の行列に戻すマッピングを使用して、オンデマンドでインデックスを計算します。 
3. それぞれについて$k$、暗黙の回転グリッドが有効かどうかを検証します。 すべての行をチェックして、各要素が次の要素よりも厳密に小さいことを確認し、すべての列をチェックして、各要素がその下の要素よりも厳密に小さいことを確認します。 違反が発生した場合、構成は無効となり、次のステップに進みます。$k$。 
4. 最初の$k$行と列の両方のチェックに合格したものが答えとして返されます。 

最初の有効ですぐに止められる理由$k$この問題は、元の構成が 4 つの回転のうちの 1 つであることを保証するため、正確に 1 つであることを意味します。$k$単調性条件を満たします。 

### なぜ効果があるのか

 4 つの回転により、指定された正方形のすべての可能な方向の完全な分割が形成されます。 元のグリッドは、両方の軸で厳密な単調性を満たすことが知られています。 このようなグリッドを回転すると、相対的な順序構造は維持されますが、座標軸との位置合わせが変更されます。 したがって、正確に 1 回転するだけで、行方向と列方向の両方の単調性が復元されるように、固有の順序付けが軸の方向に合わせられます。 4 つの状態すべてを徹底的にテストし、有効なモノトーン構成のみを受け入れるため、固有の正しい方向を見つける必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get(n, a, r, c, k):
    if k == 0:
        return a[r][c]
    if k == 1:  # 90 CCW
        return a[c][n - 1 - r]
    if k == 2:
        return a[n - 1 - r][n - 1 - c]
    # k == 3
    return a[n - 1 - c][r]

def valid(n, a, k):
    for i in range(n):
        for j in range(n - 1):
            if get(n, a, i, j, k) >= get(n, a, i, j + 1, k):
                return False
    for j in range(n):
        for i in range(n - 1):
            if get(n, a, i, j, k) >= get(n, a, i + 1, j, k):
                return False
    return True

def main():
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]
    
    for k in range(4):
        if valid(n, a, k):
            print(k)
            return

if __name__ == "__main__":
    main()
```実装における中心的なアイデアは、マトリックスの物理的な回転を避けることです。 代わりに、各回転は定数時間のインデックス変換として表現されます。 これにより、不必要なメモリのコピーが防止され、ソリューションがクリーンな状態に保たれます。 

有効性チェックは行スキャンと列スキャンに分割されます。 各比較では、`get`回転ロジックを抽象化する関数。 実装における最も一般的な間違いは、回転、特に 90 度および 270 度のインデックス マッピングが正しくないことです。 ここで使用されるマッピングは、座標の標準的な幾何学的変換に従います。

        if k == 1:
            return a[c][n - 1 - r]

            for i in range(n - 1):
                if get(n, a, i, j, k) >= get(n, a, i + 1, j, k):

 ## 特殊なケース

 最小限の$2 \times 2$グリッドは、不正な回転マッピングの影響を最も受けやすくなります。 次のことを考慮してください。 

入力:```
2
1 3
2 4
```このグリッドは標準方向ですでに有効であるため、正しい答えは 0 です。90 度または 270 度の回転インデックス マッピングが 1 つの座標交換によってずれている場合、このケースは別の回転では誤って有効であるように見え、間違った答えが生成されます。 アルゴリズムはすべての回転を独立してチェックするため、1 つのマッピングが間違っていても、他のマッピングは干渉せず、正確さは完全に正確な座標変換に依存します。 

もう 1 つのエッジ ケースは、完全に反転したグリッドです。 

入力:```
2
4 3
2 1
```のために$k=0$、最初の行が 4 > 3 であるため、行順序はすぐに失敗します。 のために$k=1$、マッピングにより非単調な構成が生成されます。 のために$k=2$、行列は両方向に増加するため、アルゴリズムはそこで停止します。 のために$k=3$、やはり単調性に違反します。 段階的なチェックにより、正しい回転のみが検証に残ることが保証され、無効な状態の早期拒否によって正しい解決策がスキップされないことが確認されます。
