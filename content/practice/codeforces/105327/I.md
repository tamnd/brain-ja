 ## 解決策
 ## 問題の理解

 各食品には番号が付けられており、その番号は複数の素因数のセットとして考える必要があります。 食品の値が 12 である場合、実際には、その食品が成分 2、2、および 3 に寄与していることを意味します。したがって、すべての食品は、場合によっては繰り返しを伴う一連のプライム「食材」に対応しますが、制限はプライムが出現するかどうかに関するものだけであるため、アレルギー ルールにとって繰り返しは問題ではありません。 

顧客もアレルギーを表す数値を持っており、これも素因数分解によって解釈します。 素数が顧客の数を割った場合、その素数を要素として含む食品を含む料理をその顧客は摂取することはできません。 料理とは、空のサブセットを含む、利用可能な食品の任意のサブセットです。 

課題は、顧客ごとに、顧客の数を割る素数が選択された食品に現れないように、N 個の食品のサブセットがいくつ選択できるかを数えることです。 

制約を直接解釈すると、非常に大きな検索スペースが強制されます。 食品は最大 100,000 個あるため、サブセットの数は 2^N となり、天文学的に大きくなります。 各クエリを個別に処理しようとした場合でも、クエリごとにすべての食品を因数分解してチェックすると、10^10 スケールの動作が発生しますが、これは 1 秒では不可能です。 

隠された構造は、制限が乗算的であるが素数ごとに独立しており、値の世界が 10^6 で制限されていることです。これは、約数または素数に対する事前計算を強く示唆しています。 

微妙なエッジ ケースは、食品の値 1 の存在です。1 には素因数がないため、禁止されることはなく、常にすべての人にとって安全です。 ソリューションが誤って 1 を無視するか無効として扱うと、すべてのクエリで過小評価されます。 

もう 1 つの特殊なケースは、同じ食品値が繰り返されることです。 複数の食品が同じ主因数を共有している場合でも、それらはサブセット内の個別の選択肢であるため、カウントを折りたたむのではなく倍増させます。 

## アプローチ

 直接的な総当りのソリューションでは、クエリごとに食品のすべてのサブセットを反復処理し、選択した食品がクエリのアレルギー番号と素因数を共有するかどうかを確認します。 N 個の食品、つまり 2^N 個のサブセットの場合、単一のクエリですら実行不可能になります。 

もう少し単純ではない改良として、各食品と各クエリ番号の素因数を事前に計算し、クエリごとに禁止されているすべての素数をマークし、すべての食品をスキャンして有効なものをカウントします。 これにより、サブセットごとのチェックは既に削減されていますが、最悪の場合 (約 10^10 の演算) では依然として O(NQ) 動作が残ります。 

重要な観察は、視点を逆転させることです。 どの食品がその人に許可されているかを尋ねる代わりに、私たちは食品をその食品に含まれる一連の素数によって分類します。 クエリの禁止された素数セットと少なくとも 1 つの素数を共有する場合、その食品は禁止されます。 したがって、クエリにとって重要なのは、禁止されたプライムを含むすべての食品の結合だけです。 

これは、食品を「悪い素数」でグループ化し、素数を含めて食品の価値を分割することを示唆しています。 値は最大 10^6 であるため、各値を因数分解してその素数と関連付けることができます。 次に、各素数 p について、p で割り切れる食品の数を維持します。 クエリ内で素数のサブセットに対して包含-排他を使用すると、禁止されている食品の数が得られ、したがって許可されている食品の数がわかります。 許可される食品の数がわかれば、許可される食品のすべてのサブセットが独立して有効な料理を形成するため、有効な料理の数は単純に 2^(allowed_count) になります。 

これにより、問題は効率的な因数分解と高速なべき乗に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(Q · 2^N) | お(1) | 遅すぎる |
 | クエリごとにスキャン | O(NQ) + 因数分解 | お(1) | 遅すぎる |
 | 素数 + 包含数のカウント | O((N + Q) √V + Q · 2^k) | O(V) | 承認済み |

ここで、k はクエリ内の個別の素因数の数です。数値が ≤ 10^6 であるため、この値は小さくなります。 

## アルゴリズムのチュートリアル

 1. ふるいを使用して、10^6 までのすべての整数の最小素因数を事前計算します。 これにより、すべての食品とクエリ値を対数時間で高速に因数分解できます。 
2. 各食品値 Vi について、それを個別の素約数に因数分解します。 素数が存在する場合、その食品はアレルギーのあるユーザーにとって禁止されるため、指数ではなく、素数が出現するかどうかのみを考慮します。 
3. 素数 p で割り切れる食品の数を格納する頻度配列 cnt[p] を維持します。 各食品は、その因数分解において個別の素数ごとに 1 回寄与します。 これは、禁止されたプライムについて、無効になる食品の数を示します。 
4. 食品のサブセットの総数を 2^N モジュロ MOD として事前計算します。 除外される食品がないため、人にアレルギーがない場合の答えです。 
5. 各クエリ値 Xi について、それを個別の素約数に因数分解します。 これらの素数は禁止されている成分を表します。 
6. これらの素数に対して包含-除外を使用して、「悪い」食品、つまり少なくとも 1 つの禁止された素数が含まれている食品の数を計算します。 素数のサブセットごとに、サブセット内のすべての素数で割り切れる食品の数を計算し、重複を数えすぎないように符号を交互に置きます。 
7. N から悪い食品の数を引くと、安全な食品の数が得られます。 
8. 安全な食品の各サブセットは有効な料理であり、選択肢は独立しているため、クエリの答えは 2^(安全な食品) モジュロ MOD です。 

包含排除が必要となる主な理由は、食品には複数の禁止素数が含まれる可能性があるため、cnt[p] ダブルカウントの単純合計が重複するためです。 

### なぜ効果があるのか

 すべての料理は、どの食品が含まれるかによってのみ定義されます。 料理は、選択されたすべての食品が禁止されているプラ​​イムをすべて回避している場合にのみ有効です。 安全な食品のセットを特定すると、食品間にはそれ以上の制約がないため、それらのサブセットは有効になります。 したがって、問題はフィルタリングされたセットのサブセットをカウントすることに帰着し、包含-除外により、フィルタリング ステップで禁止された素数セットと正確に 1 回交差するすべての食品が正しく除去されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXV = 10**6

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_distinct(x):
    primes = []
    while x > 1:
        p = spf[x]
        primes.append(p)
        while x % p == 0:
            x //= p
    return primes

N = int(input())
V = list(map(int, input().split()))

cnt = {}
for v in V:
    if v == 1:
        continue
    ps = factor_distinct(v)
    for p in ps:
        cnt[p] = cnt.get(p, 0) + 1

# total subsets
pow2 = [1] * (N + 1)
for i in range(1, N + 1):
    pow2[i] = pow2[i - 1] * 2 % MOD

Q = int(input())

for _ in range(Q):
    x = int(input())
    if x == 1:
        print(pow2[N])
        continue

    ps = factor_distinct(x)
    ps = list(set(ps))

    m = len(ps)
    bad = 0

    # inclusion-exclusion over primes of x
    for mask in range(1, 1 << m):
        mult = 1
        bits = 0
        for i in range(m):
            if mask & (1 << i):
                mult *= ps[i]
                bits += 1
        c = cnt.get(mult, 0)
        if bits % 2 == 1:
            bad += c
        else:
            bad -= c

    bad %= MOD
    if bad < 0:
        bad += MOD

    safe = N - bad
    print(pow2[safe])
```sieve は最小の素因数テーブルを構築するため、食品とクエリの両方の因数分解が高速かつ均一になります。 cnt ディクショナリには、各素数で割り切れる食品の数が格納されます。包含-除外再構築ではクエリ内の素数間の重複が重複するため、これで十分です。 

クエリごとに、個別の素数を抽出し、それらのすべてのサブセットを反復処理します。 10^6 までの数値には最大でも約 7 つの異なる素因数があるため、サブセット ループは小さくなります。 各サブセットについて、これらの素数の積で割り切れる食品の数を計算します。これは、これらの素数をすべて同時に含む食品に正確に対応します。 

最後に、安全な食品の数を計算し、その値に 2 を乗算します。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
N = 6
V = [1, 2, 3, 4, 5, 6]
Q = 4
queries = [1, 2, 4, 6]
```まず cnt を計算します。 

2 は {2,4,6} に出現するため、cnt[2] = 3

 3 は {3,6} に出現するため、cnt[3] = 2

 5 は {5} に出現するため、cnt[5] = 1

 次に、クエリをトレースします。 

### クエリ 1: x = 1

 | ステップ | 値 |
 | --- | --- |
 | 素数 | [] |
 | 安全な食品 | 6 |
 | 答え | 2^6 = 64 |

 プライムは禁止されていないため、すべての食品は安全です。 

### クエリ 2: x = 2

 | ステップ | 値 |
 | --- | --- |
 | 素数 | [2] |
 | サブセット {2} | cnt[2] = 3 |
 | 悪い食べ物 | 3 |
 | 安全な食品 | 3 |
 | 答え | 2^3 = 8 |

 2、4、6 の 2 を含む食品は除外されます。 

### クエリ 3: x = 4

 4 = 2^2 ですが、素数集合は [2] のままです。 

| ステップ | 値 |
 | --- | --- |
 | 素数 | [2] |
 | 悪い食べ物 | 3 |
 | 安全な食品 | 3 |
 | 答え | 8 |

 これにより、指数多重度が重要ではないことが確認されます。 

### クエリ 4: x = 6

 | ステップ | 値 |
 | --- | --- |
 | 素数 | [2、3] |
 | サブセット {2} | 3 |
 | サブセット {3} | 2 |
 | サブセット {2,3} | 1 |
 | 悪い食べ物 | 3 + 2 − 1 = 4 |
 | 安全な食品 | 2 |
 | 答え | 2^2 = 4 |

 除外される食品は 2 または 3 で割り切れる食品であり、包含除外によって重複が修正されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V log log V + N log V + Q · 2^k) | sieve は SPF を構築し、因数分解は高速で、各クエリは小さなサブセット列挙を使用します。 
| スペース | O(V + N) | SPF 配列と素数上の周波数マップ |

 ふるいは前処理の大半を占めますが、10^6 の場合は 1 秒に簡単に収まります。 k は 10^6 までの異なる素因数の数によって制限されるため、各クエリは小さくなります。

 ## 特殊なケース

 重要なエッジケースは、食べ物の値が 1 の場合です。入力の場合:```
N = 3
V = [1, 2, 3]
X = 2
```食品 1 は常に安全です。 このアルゴリズムは素数集合に 1 を挿入しないため、cnt はそれを無視します。 クエリ 2 では、安全な食品を 2 (食品 1 と食品 3) として計算するため、答えは 2^2 = 4 となり、サブセット {}、{1}、{3}、{1,3} に対応します。 これにより、中性要素の正しい取り扱いが確認されます。 

もう 1 つのエッジ ケースは、X = 8 = 2^3 などのクエリ番号で素数が繰り返されることです。 因数分解ステップは [2] のみを返すため、包含/除外は正しいままであり、二重にカウントされません。 したがって、アルゴリズムはすべての累乗を一貫して扱い、禁止された素数を過剰にカウントすることを回避します。
