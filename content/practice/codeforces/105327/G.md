 ## 解決策
 ## 問題の理解

 私たちには、すべての源が最終的に海に注ぐ最後の 1 つの川に合流する、単一の河川系の根付いた構造が与えられています。 各水源は、固定の初期水量と独自の識別子を名前とする独立した川として始まります。 次に、決定的な順序で、1 つの川だけが残るまで、既存の川のペアがマージされます。 

合流するたびに、2 つの独立した川が新しい川に結合され、その水量は 2 つの川の合計になります。 結果として生じる川の名前は任意ではなく、合流する 2 つの川の合計量を比較することによって選択されます。 水量の多い川はその名を残しています。 両方のボリュームが等しい場合、小さい方のインデックスを選択することで同点が解消されます。 

全体の構造が構築された後、いくつかの元の水源の水量を繰り返し増加させます。 これらの増加は永続的であり、将来のすべてのマージに影響します。 更新のたびに、マージ構造全体のルートにある最終的な川の名前を報告する必要があります。 

重要な観察は、マージ構造が最大 2N-1 ノードにわたる固定バイナリ ツリーであるということです。 時間の経過とともに変化するのはリーフの値だけですが、内部ノードはその合計と勝者名を暗黙的に再計算します。 

この制約により、最大 100,000 のソースと 100,000 の更新が許可されます。 更新のたびにすべてのサブツリーの合計を直接再計算するには、クエリごとに O(N) が必要となり、O(NQ) が大きすぎて、最大 10^10 の演算が必要になります。 これにより、クエリごとにツリーを最初から再計算するアプローチは即座に除外されます。 

複数のマージによって等しいサブツリーの合計が生成される場合、微妙なエッジ ケースが発生します。 その場合、最小のインデックスを伝播する必要があります。 単純な実装では、タイブレークが初期構造ではなく現在の値に依存することを忘れてしまう可能性があります。 もう 1 つの微妙な問題は、更新はリーフ ノードにのみ影響しますが、その影響はすべての祖先に伝播するということです。つまり、正確性は動的なサブツリー集合体の維持に依存します。 

## アプローチ

 この構造は固定バイナリ ツリーであり、各内部ノードがそのサブツリー内の葉の合計と、その 2 つの子を比較することによって定義された「勝者」ラベルを格納します。 ブルートフォースのアイデアは単純です。更新のたびに、葉から上に向かってすべてのサブツリーの合計を再計算し、すべての内部ノードの勝者を再計算します。 これが機能するのは、ツリーが静的で評価が決定的であるためです。そのため、完全な再計算によって常に正しいルートが得られます。 各更新が N 個のノードすべてに影響し、Q 個の更新があり、二次的な動作が発生するため、障害点は純粋にパフォーマンスです。 

重要な洞察は、ルートの決定は集約されたサブツリーの合計のみに依存し、これらの合計は変更されたリーフからルートまでのパスに沿ってのみ変化するということです。 これは、バランスの取れた構造であれば、各更新が O(log N) のような伝播に影響を与える静的ツリーのセグメントとして構造を扱うことを示唆していますが、ここではツリーは任意です。 高さを利用しようとする代わりに、依存関係を逆転させます。各ノードは、その 2 つの子のどちらが現在優勢であるかを知る必要があるだけです。 すべてのノードについて、現在の勝者と現在のサブツリーの合計を維持する場合、リーフでの更新では、ルートへのパスに沿ってそれらの値を再計算するだけで済みます。 ツリーは静的であるため、各ノードは影響を受けるパスごとに 1 回更新でき、各内部ノードの再計算は O(1) です。 

重要な構造特性は、各内部ノードの値がその 2 つの子の純粋な関数であるため、正確性を維持するということは、固定ツリーに対するボトムアップの動的プログラムを維持することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにツリー全体を再計算する | O(NQ) | O(N) | 遅すぎる |
 | ツリー上のボトムアップ伝播 | O((N + Q) log N) ワーストケース、O((N + Q)) は親ポインタを使用すると現実的 | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、構築プロセスを 2N−1 個のノードを持つ明示的なバイナリ ツリーとして再解釈します。ここで、各内部ノードには正確に 2 つの子があり、各葉は元のソースに対応します。 

1. 与えられたとおりにツリーを構築し、各ノードの 2 つの子と各ノードの親ポインタを保存します。 これにより、更新後に上方への伝播が可能になります。 
2. 配列を初期化する`value[i]`各ノードの現在の水量を保存します。 葉の場合はこれが与えられ、内部ノードの場合は計算されます。 
3. ポストオーダートラバーサルまたは反復ボトムアップパスを実行して、すべてのノードの初期サブツリー値と勝者ラベルを計算します。 各内部ノードについて、その合計をその子の合計の合計として計算します。 
4. ノードを「再計算」する関数を定義します。 子 A と B を持つノードの場合、その合計は次のようになります。`sum[A] + sum[B]`。 その勝者は、サブツリーの合計が厳密に大きい子、または等しい場合はインデックスが小さい子になります。 このステップでは、河川の命名規則をエンコードします。 
5. リーフの値を増やして、リーフでの更新を処理します。 リーフを変更した後、親ポインターを使用してそのリーフからルートまで上向きに移動し、上記のルールを使用してこのパス上の各ノードを再計算します。 
6. 各更新の伝播が終了した後、ルート ノードに保存されている勝者を出力します。 

上向きの伝播で十分な理由は、更新されたリーフの祖先のみがサブツリーの合計を変更できるためです。 そのパスの外側にあるノードはすべて同一のサブツリー構成を持ち、したがって合計と勝者も同一になります。 

### なぜ効果があるのか

 各ノードは、そのサブツリーの正確な要約、つまりその総水量と、結合ルールに基づいてそこから出現する川の識別情報を維持します。 リーフの更新では、サブツリーのリーフ値が 1 つだけ変更されるため、要約が無効になるノードは、まさにこのリーフをサブツリーに含むノードだけです。 ツリーは静的であるため、これらのノードはルートへの単一のパスを形成し、このパスに沿って再計算すると、リーフから上に向かって帰納的に正確さが復元されます。 再計算のたびに、子はすでに正しいため、各親は有効な入力から再計算され、ルートに至るまで正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    # nodes are 1..2n-1
    N = 2 * n
    left = [0] * N
    right = [0] * N
    parent = [0] * N

    for i in range(n + 1, 2 * n):
        u, v = map(int, input().split())
        left[i] = u
        right[i] = v
        parent[u] = i
        parent[v] = i

    # sum and winner
    sm = [0] * N
    winner = [0] * N

    for i in range(1, n + 1):
        sm[i] = a[i]
        winner[i] = i

    def recompute(x):
        l = left[x]
        r = right[x]
        sm[x] = sm[l] + sm[r]

        wl = winner[l]
        wr = winner[r]

        if sm[l] > sm[r]:
            winner[x] = wl
        elif sm[r] > sm[l]:
            winner[x] = wr
        else:
            winner[x] = min(wl, wr)

    for i in range(n + 1, 2 * n):
        recompute(i)

    root = 2 * n - 1

    def update(i, delta):
        nonlocal a
        x = i
        sm[x] += delta
        while x:
            if x != i:
                recompute(x)
            x = parent[x]

    q = int(input())
    out = []
    for _ in range(q):
        i, d = map(int, input().split())
        update(i, d)
        out.append(str(winner[root]))

    print(winner[root])
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、完全なバイナリ マージ ツリーが明示的に構築されます。 各内部ノードは 2 つの子へのポインタを格納し、各ノードはその親を認識しているため、更新後の上方への伝播が可能になります。 配列`sm`そして`winner`現在のサブツリー合計と勝利インデックスをそれぞれ維持します。 

の`recompute`関数はコアトランジションです。 合計集計と名前付けルールの両方を一定時間内に適用します。 タイブレーク条件は、次を使用して明示的に処理されます。`min`これにより、サブツリーの合計が等しい場合に正確さが保証されます。 

更新はリーフにのみ適用されます。 リーフ値を増やした後、親ポインターを使用して上方向に進み、影響を受けるすべてのノードを再計算します。 その後、ルート値が直接読み取られます。 

実装の微妙な詳細は、リーフ自体を 1 回だけ再計算し、その後上向きに伝播する必要があることです。 また、ルートは常にノードです`2n-1`、各マージにより新しいノードが順番に作成されるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + Q・h) | 各更新では、ルートへのパスに沿ってノードが再計算されます。 
| スペース | O(N) | ツリーおよび DP アレイのストレージ |

 ここで、 h は構築されたマージ ツリーの高さです。 ツリーは順次構築されるため、通常は最悪の場合にのみ歪められますが、それでも N によって制限されます。N、Q が最大 10^5 であるため、この伝播は実際には効率的です。これは、各ノードの再計算が O(1) であり、各更新が 1 つのリーフの先祖のみに影響するためです。 

すべての配列のノード数が線形であるため、メモリ使用量は制限内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つのサブツリーの合計ボリュームが正確に等しい場合です。 その場合、勝者は小さいインデックスである必要があり、必ずしもより高いリーフ値を持つインデックスである必要はありません。 たとえば、サブツリー A の葉の合計が 5 であり、サブツリー B の合計も 5 である場合、決定は純粋に現在の勝者のインデックスに依存します。 再計算関数は明示的に等価性をチェックして適用します。`min(wl, wr)`内部構造に関係なく正確性が保たれます。 

もう 1 つのケースは、同じリーフ上で更新が繰り返される場合です。 更新は加算的であるため、リーフ値は任意に大きくなる可能性がありますが、Python ではすべての計算が整数の範囲内に留まります。 伝播は依然として祖先ノードにのみ影響するため、更新を繰り返しても正確性は低下せず、更新ごとのツリーの高さに比例するパフォーマンスのみが低下します。 

最後の構造ケースは、入力された構築順序によりツリーのバランスが著しく崩れている場合です。 この場合でも、すべての内部ノードが明示的な親リンクを格納しているため、親ポインターの伝播では影響を受けるすべての祖先が正しく再計算されます。 このアルゴリズムはバランスを前提としていないため、根が非常に深い場合でも正確さは影響を受けません。
