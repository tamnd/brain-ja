 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、同じ位置にある 2 つの数値の間で個々のビットを交換する操作を繰り返し適用できます。 2 つのインデックスとビット位置を選択すると、2 つの数値の間でそのビットが 0 であるか 1 であるかを交換できます。 

重要な結果は、ビットが元の数値に関連付けられなくなることです。 位置のすべてのビット$k$アレイ全体にわたって任意に再分配できます。$N$各ビット位置の 1 の合計数が同じである限り。 

タスクは、結果として得られる配列が辞書編集上最大になるように、任意の数のスワップを使用してこれらのビットを再配置することです。 つまり、まず最大化します$a_1$、そのようなすべての構成の中で最大化します$a_2$、 等々。 

制約$N \le 10^5$そして$a_i \le 10^9$各数値が最大 30 ビット以内に収まることを意味します。 スワップをシミュレートしたり、数値ごとに構成を考慮したりするソリューションは失敗します。これは、潜在的な構成の総数が指数関数的に増加するためです。 ビット位置ごと、要素ごとに線形または線形に近い時間で機能するアプローチが必要です。 

微妙な落とし穴は、可能な限りビットを 1 に設定することで、各数値を個別に貪欲に最大化できると想定していることです。 ビットは共有グローバル リソースであるため、これは失敗します。 

たとえば、値があるとします。`[8, 4, 2, 1]`、すべてのビットは個別です。 大きなビットをすべて取得して最初の要素を最大化しようと貪欲に試みると、同じビットを複数の数値で再利用できないことを見落とす可能性があります。 正しい出力は次のようになります`[15, 0, 0, 0]`、すべてのビットが最初の数値に集中します。 

上位ビットが不足している場合には、別の特殊なケースが発生します。 のために`[12, 15, 1, 20]`、辞書編集構造を尊重せずにビットを貪欲に分散すると、大きなビットを後の位置に与えるなど、最適でない順序付けが発生する可能性があります。 正しい解決策は`[31, 13, 4, 0]`、最上位ビットが最初に以前のインデックスに割り当てられます。 

中心的な課題は、問題は数値の交換に関するものではなく、固定された複数セットのビットを位置間で再分配することにあることを認識することです。 

## アプローチ

 ブルートフォースアプローチでは、操作を直接シミュレートしようとします。 各操作は 2 つの数値の間でビットを交換するため、辞書編集順で改善が不可能になるまで、有益な交換を繰り返し選択することが想像できます。 これはすぐに手に負えなくなります。 スワップごとに構成が変更されます。$O(N \cdot \log A)$ビットが増加し、天文学的な数の状態が発生します。 貪欲なローカル スワップであっても、後の要素を改善すると以前の要素が悪化する可能性があるため、グローバルな最適値への収束は保証されません。 

重要な洞察は、ビット位置ごとに問題を分離することです。 スワップは同じ位置のビットのみを交換するため、各ビット位置は他のビット位置から独立しています。 ビットごとに$k$、配列全体にいくつ存在するかが正確にわかり、この数は決して変わりません。 

したがって、ビット位置ごとに、固定数の 1 を割り当てることが事実上求められます。$N$辞書順を最大化する方法で、ビットごとに配列位置ごとに 1 つのスロット。 辞書順とは、配列内のインデックスの上位の要素が下位の要素よりも指数関数的に重要であることを意味するため、常に、上位の値のビットを前の位置に設定することを優先する必要があります。 

これは、値の寄与によってすべてのビットの寄与をソートすることになりますが、ビットごとに行われます。最高位から最低位までの各ビットについて、そのビットを、依然としてグローバルな順序に利益をもたらす最も早い利用可能な位置に分配します。 具体的には、各ビットの値を、それらを収容できる最小のインデックスに貪欲に割り当て、段階的に番号を構築します。 

ブルート フォースは、ビットを構造なしでローカルに移動可能なものとして扱うため、失敗します。 各ビット位置が独立しているという観察により、問題は位置間での 1 の貪欲な割り当てに変換されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(N) | 遅すぎる |
 | ビットごとの貪欲な分散 | O(N log A) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 最上位ビットから最下位ビットまで、各ビット位置を個別に処理します。 

1. すべての数値の各ビット位置に 1 がいくつ存在するかを数えます。 これにより、ビットごとの固定予算が得られます。 これが機能する理由は、スワップがビット数をグローバルに保存するため、これらのビット数は不変であるためです。 
2. 最上位から最下位までの各ビット位置について、そのビットのどの配列位置が 1 を受け取るかを決定します。 辞書編集順では初期のインデックスの方が重要であるため、利用可能なインデックスを常に、メリットが得られる最も早い位置に割り当てるよう努めます。 
3. それぞれの現在の値を維持します。$a_i$、最初はゼロで、少しずつ構築します。 ビットごとにインデックスを順番に繰り返し、そのビットにまだインデックスが残っている場合は 1 を割り当てます。 割り当てられた場合、残りのカウントをデクリメントします。 
4. ビットを処理した後、次の下位ビットに移動します。 これにより、下位ビットが順序を調整する前に、上位ビットが辞書編集構造を支配するようになります。 
5. 割り当てられたビットを組み合わせて最終値を構築します。 

なぜこれが機能するのかは、貪欲な優位性の議論と結びついています。 上位ビットは、下位ビットの組み合わせよりも辞書編集上の順序に厳密に大きな影響を与えます。 上位ビットを最初に割り当て、常に以前のインデックスに配置することで、後の再割り当てによってビットの保存に違反することなく、以前のプレフィックスを改善できるようになります。 各ビット位置は、事実上、接頭辞重み付けされた辞書編集値を最大化するために割り当てられた個別のリソースです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    MAXB = 30
    cnt = [0] * MAXB

    for x in a:
        for b in range(MAXB):
            if x >> b & 1:
                cnt[b] += 1

    res = [0] * n

    for b in range(MAXB - 1, -1, -1):
        if cnt[b] == 0:
            continue
        for i in range(n):
            if cnt[b] == 0:
                break
            res[i] |= (1 << b)
            cnt[b] -= 1

    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、最初にグローバル ビット数が抽出されます。これは、スワップによってビットごとの合計が保持されるため安全です。 次に、最上位ビットから下に向かって貪欲に結果を構築します。 

実装の重要な詳細は、ビットごとにインデックスを左から右に反復することです。 これにより、辞書編集上の優先順位が正しく強制されます。つまり、上位ビットには以前のインデックスが最初に埋められ、配列全体の順序が決まります。 

もう 1 つの微妙な点は、30 ビットの固定境界です。$10^9$。 それを超えて繰り返すことは不必要であり、時間を無駄にするだけです。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての数値がゼロである場合です。 このアルゴリズムはどこでもビット 0 をカウントするため、割り当ては行われず、出力はすべて 0 のままになります。 入力用`3 / 0 0 0`、すべてのビット カウンタは 0 であるため、構築ループは何も割り当てません。 

もう 1 つの特殊なケースは、単一要素の配列です。 すべてのビットが 1 つの数値に属しているため、再分配しても何も変わりません。 入力用`1 / 7`、ビット数は保存され、唯一のインデックスに割り当てられ、`7`。 

最後のエッジ ケースは、次のようなビットの最大分散です。`[1, 2, 4, 8, 16]`。 アルゴリズムは、すべてのビットをビットの重要度の降順で最初の位置に集めます。 すべてのビットが上位から割り当てられるため、次のようになります。`[31, 0, 0, 0, 0]`。 これは、辞書編集上の最大化により、独立したビット ソースが初期のインデックスに自然に折りたたまれることを示しています。
