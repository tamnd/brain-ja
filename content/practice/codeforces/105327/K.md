 ## 解決策
 ## 問題の理解

 複数のバッグ サイズのセットが与えられており、各バッグには一定数の同一のアイテムが含まれています。 バッグは選択した順序で 1 つずつ処理する必要があります。 バッグを処理するとき、その中身全体が 2 人のうちアイテムの総数が少ない方に与えられます。 両方が現在同じ金額を持っている場合、アリスはバッグを受け取ります。 

目標は、すべての転送後にアリスとボブのアイテムの合計数がまったく同じになるようにバッグを再注文できるかどうかを決定することです。そうであれば、有効な注文を 1 つ出力します。 

順序が固定されると、プロセス自体は決定的になります。 唯一の自由は、この貪欲な割り当てルールをシミュレートする前に入力配列を並べ替えることです。 

制約は小さく、値が 100 までのバッグは最大 100 個です。これにより、制限された形式でのすべての候補順列に対する完全なシミュレーションや繰り返しスキャンによる貪欲な構築など、N で少なくとも 2 次または 3 次のあらゆる解が即座に可能になります。 ただし、順列の階乗列挙は不要であり、N = 10 であっても無駄になります。 

微妙な点は、割り当てルールが合計だけではなく、_prefix Balance_ に依存することです。 すべての要素の合計が均等であることだけを確認してから、それらを均等に分割しようとするのが単純な考えかもしれませんが、これは、初期の大きなバッグが貪欲なプロセスを永続的に歪める可能性があることを無視しています。 

素朴な推論による具体的な失敗例は、合計が均等であるにもかかわらず、1 つの大きな初期バッグが常に優勢である場合です。 

入力:```
3
1 1 100
```合計は 102 なので、バランスの取れた順序が存在すると単純に予想されるかもしれません。 しかし、100 を早く置く順序はアリスに大きなリードを与え、貪欲なルールの下では残りの 2 つの 1 は埋め合わせることができません。 実際、順序付けには、大きな値を小さな値に対して慎重に配置する必要があるという制約があります。 

もう 1 つの微妙なエッジ ケースは、結合動作による対称性の破れです。 同点は常にアリスに帰するため、部分和が等しいときは常にアリスが構造的に有利になります。 これは、全体の完全な対称性が分布の対称性を保証しないことを意味します。 順序付けはタイバイアスを補正する必要があります。 

## アプローチ

 強引なアプローチは、バッグのすべての順列を試し、各注文の貪欲な分布をシミュレートし、アリスとボブの合計が等しいかどうかを確認することです。 単一の順列のシミュレーションには O(N) が必要ですが、N 個あります。 順列は O(N! · N) につながりますが、これは中程度の N であっても実行不可能です。 

重要な観察は、アリスとボブの間の最終的な違いが、制御された方法で進化するということです。 各ステップで、現在の差によって次のバッグを誰が受け取るかが決まります。 アリスがそれ以下の場合はバッグを受け取り、差は a_i だけ増加します。 そうでない場合は、ボブがそれを取得し、差は a_i だけ減少します。 

したがって、各要素は、その瞬間の符号に応じて、走行差を上方または下方に押し上げます。 このプロセスは基本的に貪欲なサインウォークであり、ゼロで終わるようにバランスを保とうとしています。 

これは、署名された貢献のプレフィックスの合計を制御するという観点から考える必要があることを示唆しています。 問題は、代入の交互の「プル」が正確に打ち消されるように数値を配置することになります。 

重要な洞察は、同点がアリスに与えられるため、差がゼロの場合は常にアリスがわずかに有利であるため、多くの初期の同点がアリス側に余分な質量を蓄積する構造を避けなければならないということです。 このバイアスを中和する安定した方法は、可能な限り、ボブに十分に大きな値を早い段階で供給して、必要なときに負のドリフトを強制し、システムがすでに負になっているときにアリスに小さなバランス値を与えることです。 

これは、現在の差を維持し、制御された方法で状態をゼロに近づける残りのバッグを各ステップで選択する、絶対的な不均衡の拡大を減らす選択を優先する、建設的な貪欲戦略につながります。

 ## アルゴリズムのチュートリアル

 順序を構築するときに、アリスとボブの間の現在の差異を維持します。 また、未使用のバッグ サイズのマルチセットまたはリストも管理します。 

1. アリスとボブがアイテムを持たず、差がゼロに設定された状態から開始します。 目標は、この差を管理可能に保ち、最後にはゼロに戻せるような注文を構築することです。 
2. 順番に配置する次のバッグを繰り返し選択します。 各候補バッグについて、現在の状態に対するその影響をシミュレートします。差が正でない場合、アリスはそれを受け取り、差はそのサイズだけ増加します。 それ以外の場合は、ボブがそれを受け取り、差はそのサイズだけ減少します。 
3. 残りのすべての候補の中から、配置後に生じる差の絶対値を最小にする候補を選択します。 これは、時間の経過とともにプロセスの対称性を維持することを直接ターゲットとするローカル バランシング ヒューリスティックです。 
4. 選択したバッグを回答シーケンスに追加し、それに応じて現在の差分を更新します。 
5. 選択したバッグをプールから取り出し、すべてのバッグが配置されるまで繰り返します。 
6. シーケンスを構築した後、最終的な差が正確にゼロであるかどうかを確認します。 存在する場合は、シーケンスを出力します。 それ以外の場合は、-1 を出力します。

貪欲な選択が機能するのは、各ステップで差がいずれかの方向に大きく変動することを明示的に防止するためであり、すべての値が小さいため、システムをゼロ近くに保つことで、どちらかのプレイヤーによる不可逆的な支配が回避されるからです。 

### なぜ効果があるのか

 プロセスの状態は、アリスとボブの間の単一の整数の差によって完全に記述されます。 すべてのバッグは、現在の差の符号に応じて値を加算または減算する遷移を引き起こします。 アルゴリズムは常に、結果の状態の大きさを最小化する遷移を選択します。これにより、構築全体を通じて差異がゼロ付近の境界コリドー内に留まることが保証されます。 

有効な順序が存在する場合、状態のバランスを保ち、ゼロに戻す一連の遷移が存在します。 貪欲ルールは、局所的に対称性を最もよく維持する遷移を常に優先することでこの構造を反映し、初期の不可逆的なバイアスを防ぎます。 すべての遷移の大きさは単調であり、状態空間が小さいため (総和 ≤ 10000 で制限される)、実行可能なバランスの選択肢が存在する場合、不均衡を強いるいかなる偏差も回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(order):
    alice = 0
    bob = 0
    for x in order:
        if alice <= bob:
            alice += x
        else:
            bob += x
    return alice, bob

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    unused = arr[:]
    order = []
    diff = 0  # alice - bob

    for _ in range(n):
        best_idx = -1
        best_diff = None

        for i, x in enumerate(unused):
            if diff <= 0:
                new_diff = diff + x
            else:
                new_diff = diff - x

            if best_diff is None or abs(new_diff) < abs(best_diff):
                best_diff = new_diff
                best_idx = i

        x = unused.pop(best_idx)
        order.append(x)

        if diff <= 0:
            diff += x
        else:
            diff -= x

    a, b = simulate(order)
    if a == b:
        print(*order)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```実装によりランニングの差が維持される`diff`これは、アリスとボブの間の現在の不均衡をエンコードしています。 各ステップで、残りのすべての候補を試し、その候補が次に配置された場合に新しい差がどのようになるかを計算します。 選択された要素は、絶対的な不均衡を最小に保つ要素です。 

ローカル バランシングでは、構築されたすべての貪欲なプロセスにおけるグローバルな最適性が数学的に保証されないため、最終的なシミュレーションが必要です。 これは、複数のローカルな選択によって異なる最終結果が生じる場合の正確性フィルターとして機能します。 

実装の微妙な詳細は、割り当てルールが次のものに依存することです。`alice <= bob`、厳密にはそうではありません`<`。 この結合条件は、初期の蓄積がアリスに偏り、進化に直接影響を与えるため、重要です。`diff`。 シミュレーションと構築の両方で、このルールを一貫して尊重する必要があります。

 ## 特殊なケース

 シングルバッグケースのような`1 5 10`これは構築ループによって即座に処理され、単一の要素の順序付けが生成されます。 次に、シミュレーションはそれをアリスに割り当て、ボブをゼロのままにするため、最終チェックは失敗して -1 を返し、1 回の移動でバランスを取るのが不可能であることを正確に照合します。 

のような場合`1 1`、貪欲なプロセスは、最初に同一の要素の 1 つを選択します。 diff は 0 から始まるため、アリスが最初の 1 を取り、次にボブが 2 番目の 1 を取り、等価になります。 重みが等しい場合には不均衡な増幅は不可能であるため、アルゴリズムは自然に収束します。 

のために`1 1 100`、差が小さい場合、どの順序でも最終的にはアリスまたはボブに 100 が与えられ、同点ルールにより不可逆的なドリフトが強制されます。 貪欲な選択でもある程度の順序は生成されますが、最終的な検証では不均衡が検出され、それが正しく拒否されます。
