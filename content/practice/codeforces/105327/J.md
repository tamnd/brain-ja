 ## 解決策
 ## 問題の理解

 各エッジが 2 つの都市を接続し、カラー ラベルを持つ無向マルチグラフが与えられます。 このタスクは、すべてのエッジを 1 回だけ使用する閉じたウォークを構築することです。そのため、構造的にはオイラー ツアーの要件ですが、順序に追加の制限があります。ツアー内の連続するエッジが同じ色を共有することは許可されず、最初と最後のエッジも色が異なっていなければなりません。 

出力は単に「はい」または「いいえ」だけではありません。 有効なツアーが存在する場合は、開始都市を出力し、次に横断順序を記述するすべてのエッジ インデックスの順列を出力する必要があります。 そのような走査が存在しない場合は、-1 を出力します。 

制約は十分小さいため、線形または線形に近いグラフの走査が可能です。 最大 1000 のエッジでは、テストあたりおよそ O(M) または O(M log M) のアルゴリズムは許容されますが、M の二次関数は合格しますが、不要です。 最大 1000 色の存在は、色ベースの状態追跡が行われる可能性があることを示唆していますが、エッジ数により、隣接構造を明示的に操作することが可能になります。 

通常、単純なオイラー回路構成 (Hierholzer のアルゴリズム) で問題は解決されますが、色は完全に無視されます。 課題は、オイラー回路が存在する場合でも、色の制限により有効性が損なわれる可能性があるため、制御された方法でエッジを選択する必要があることです。 

いくつかの特殊なケースが非常に重要です。 

1 つは、通常の意味でオイラーグラフですが、ノードに属するすべてのエッジが同じ色を持つグラフです。 たとえば、ノード 1 を中心とする星で、すべてのエッジの色が 1 であるとします。オイラー ツアーは次数が偶数の場合にのみ存在しますが、その場合でも、トラバースでは中心を通るエッジが交互になり、必然的に同じ色が連続して繰り返されるため、制約に違反します。 正しい出力は -1 です。 

もう 1 つのケースは、基礎となるグラフに複数の有効なオイラー ツアーが存在するが、その一部のみが色の変更を満たす場合です。 隣接リストの単純な DFS 順序付けでは、有効なオイラー構造を簡単に選択できますが、ローカルで色の制約に失敗します。 

3 番目の微妙なケースは、グラフに複数の連結成分がある場合です。 標準のオイラー ツアーは接続性 (孤立した頂点を無視する) を必要とするため、単純なアプローチではコンポーネントごとのツアーを構築して連結しようとしますが、ツアーはすべてのエッジにわたる単一サイクルである必要があるため失敗します。 

## アプローチ

 この強引なアイデアは、考えられるすべてのオイラー ツアーを検索するものとして問題を扱うことです。 バックトラッキングを伴う DFS を使用して、エッジの有効な順列の構築を試みることができます。各ステップで、前のエッジとの色の制約に違反しない未使用のエッジを選択します。 これは、制約と一致するすべての可能なエッジ順序を探索し、最終的に有効なオイラー回路が存在する場合はそれを見つけるため、正しいです。 

ただし分岐要素は大きい。 次数 d のノードでは、d 個の可能な次のエッジがあり、M 個のエッジにわたって、可能性の数はおおよそ階乗動作のように増加します。 枝刈りを行ったとしても、密度が高い場合、検索は指数関数的な時間にまで低下します。 M が 1000 までの場合、これは不可能です。 

重要な観察は、まだ基本的にオイラー回路を構築している途中であるため、Hierholzer のアルゴリズム構造が必要であるということです。 唯一の自由は、隣接エッジを消費する順序です。 グローバルにバックトラッキングする代わりに、エッジ選択中にローカルに色の制約を適用します。 

洞察としては、障害状態が発生するのは、ノードで行き詰まっているにもかかわらず、別の場所に異なる色構造の未使用のエッジがまだある場合だけです。 これは、オイラー ツアーを貪欲に構築する必要があることを示唆していますが、最後のエッジの色が最初のエッジの色と等しい状況に陥らないように常に注意してください。

標準的なトリックは、Hierholzer のアルゴリズムを実行することですが、同じ色が連続して繰り返されないように次のエッジを慎重に選択します。 グラフのサイズが小さいため、ノードごとに隣接リストを維持し、最後の色と一致しないエッジを動的に選択し、必要な場合にのみフォールバックできます。 有効なエッジが存在しない点に到達すると、構築は失敗します。

 ## アルゴリズムのチュートリアル

 Hierholzer のアルゴリズムと同様に、スタックを使用して修正オイラー ツアーを構築しますが、最後に使用されたエッジの色を追跡します。 

1. 各都市の隣接リストを構築し、(近隣、エッジ ID、色) のペアを保存します。 エッジの使用済み配列も維持します。 

その理由は、オイラー トラバーサルではエッジを 1 回だけ消費する必要があり、隣接構造が唯一のアクセス メカニズムであるためです。 
2. 少なくとも 1 つのエッジがある開始都市を選択します。 ここがツアーのスタート地点となります。 

開始点はオイラー回路の正確さに影響しません。 任意の有効なサイクルを回転させることができます。 
3. 開始都市と、すべての実際の色とは異なるセンチネルの前のカラー値を使用してスタックを初期化します。 
4. スタックが空でない間に、一番上の現在の都市を調べます。 
5. この都市から、その隣接リストを反復処理して、前のエッジの色と異なる色を持つ未使用のエッジを探します。 

これにより、構造内に同じ色の 2 つの連続するエッジが配置されることがなくなります。 
6. そのようなエッジが見つかった場合は、それを使用済みとしてマークし、隣接する都市をスタックにプッシュし、ツアーにエッジ ID を記録し、最後の色を更新します。 

これはオイラートラバースの前進運動です。 
7. 現在のノードに有効なエッジが存在しない場合は、スタックからノードをポップします。 

これは、すべての出力エッジが使い果たされた場合の Hierholzer のアルゴリズムにおけるバックトラッキングに対応します。 
8. トラバース後、すべてのエッジが使用されたかどうかを確認します。 そうでない場合は、-1 を出力します。 
9. 最後に、構築されたシーケンスの最初と最後のエッジが異なる色であることを確認します。 そうでない場合は、-1 を出力します。 

正確さは、局所的な色の競合を決して許可しないという事実にかかっており、オイラー構造によって各エッジが正確に 1 回使用されることを保証します。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの結合された不変条件を維持します。 まず、スタック構造により、常に有効な部分オイラー トレイルが構築されることが保証されます。つまり、未使用のエッジのみをトラバースし、それらを再訪することはありません。 第 2 に、色の制約は拡張ステップごとに適用されるため、無効な隣接関係が導入されることはありません。 

すべてのエッジは最終的に使用されるか、色の制約の下では到達不可能であることが証明されるため、失敗は有効な順序が存在しないことを意味します。 Hierholzer のアルゴリズムに固有のバックトラッキング動作により、有効な順序付けが存在する場合、すべての代替案をブロックする行き止まりに早まってコミットすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    edges = [None] * (m + 1)
    for i in range(1, m + 1):
        u, v, c = map(int, input().split())
        adj[u].append((v, i, c))
        adj[v].append((u, i, c))
        edges[i] = (u, v, c)

    used = [False] * (m + 1)

    start = 1
    for i in range(1, n + 1):
        if adj[i]:
            start = i
            break

    stack = [(start, -1)]
    tour_nodes = []
    tour_edges = []
    last_color = -1

    while stack:
        u, _ = stack[-1]
        found = False

        while adj[u]:
            v, eid, col = adj[u].pop()
            if used[eid]:
                continue
            if last_color == col:
                continue
            used[eid] = True
            stack.append((v, col))
            tour_edges.append(eid)
            last_color = col
            found = True
            break

        if not found:
            stack.pop()

    if len(tour_edges) != m:
        print(-1)
        return

    # check first/last color condition
    first_color = edges[tour_edges[0]][2]
    last_color = edges[tour_edges[-1]][2]
    if first_color == last_color:
        print(-1)
        return

    print(start)
    print(*tour_edges)

if __name__ == "__main__":
    solve()
```隣接リストにはフルエッジのメタデータが保存されるため、走査中に色の制約を検証できます。 使用される配列により、各エッジが正確に 1 回消費されることが保証されます。 

スタックはオイラー走査をシミュレートします。 先に進むたびに、色の制約が直ちに適用されますが、これが標準 Hierholzer からの唯一の逸脱です。 

ローカル制約が満たされていても、サイクル ラップアラウンド条件が失敗する可能性があるため、最後の検証ステップが必要です。

 都市 1 から開始します。隣接構造により、複数の有効な選択肢が可能になります。

 トラバーサルではすべてのエッジが 1 回だけ使用され、各ステップでの色の変更が尊重されます。 

これは、ローカル カラー フィルタリングを使用した貪欲な選択でも完全なオイラー回路を完成できることを示しています。 

### サンプル 2

 すべてのエッジは 2 つのノードの間にありますが、色が異なります。 

| ステップ | 現在のノード | 最後の色 | 選ばれたエッジ | 次のノード | 残りのエッジ |

 ここでの重要な動作は、平行なエッジにより慎重な交互配置が強制されることですが、色のバランスがとれているため、トラバースは成功します。

 ## 特殊なケース

 すべてのエッジが単一の色を共有する構成は、オイラー回路が存在する場合でも、すぐに構造を壊します。 すべてのエッジの色が 1 の三角形では、すべての走査で同じ色を連続して配置するか、ラップアラウンドで配置する必要があるため、アルゴリズムは最初と最後の色が同じであることを検出すると、最終検証ステップで正常に失敗します。 

交互の色の 4 つのエッジで接続された 2 つの都市などのマルチエッジの状況でも、貪欲な選択が各ステップで常に異なる色のエッジを見つけ、スタックによって途中で終了しないことが保証されるため、引き続き成功します。 

グラフが切断されていると、すべてのエッジが消費される前にスタックが早期に使い果たされます。 条件`len(tour_edges) != m`はこれを正確に捉え、部分的なツアーを誤って出力しないようにします。
