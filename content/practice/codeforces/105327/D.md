 ## 解決策
 ## 問題の理解

 開始値が与えられています$N$、それは上司の「健康」と考えることができます。 私たちも持っています$M$呪文と呼ばれる操作。 各呪文には 2 つのパラメータがあります$a_i$そして$b_i$。 呪文は、次の 2 つの条件が成立する場合にのみ、現在の値に適用できます。 現在の値が少なくとも$a_i$、現在の値は次の値で割り切れます。$2^{b_i}$、これは、現在の数値のバイナリ表現が少なくとも で終わると言うのと同じです。$b_i$ゼロビット。 

呪文を適用するたびに、値は正確に減少します$a_i$。 各ステップで制約が満たされている限り、呪文を任意の順序で繰り返し適用できます。 目標は、呪文適用の異なるシーケンスの数がどれだけ値を減らすかを数えることです。$N$まさに$0$。 2 つのシーケンスは、どのステップでも異なる呪文を使用する場合、または異なる順序で使用する場合には異なります。 

制約は非常に大きいです。$N$まで行くことができます$10^{18}$これは、すべての状態を直接的な方法で明示的にシミュレートすることはできないことを意味します。 それぞれの値を考えても$0$に$N$、それはすでに不可能です。 呪文の数は最大です$10^5$したがって、状態間のすべての遷移を高密度で試みるアプローチも失敗します。 

重要な観察は、各呪文は値を最大 100 ずつ減少させるため、必要な減少数は最大 100 であるということです。$10^{16}$、これもパスの列挙を除外します。 この構造は、2 の累乗による割り算の制約から得られる必要があります。これは、生の値ではなくバイナリ キャリー構造を扱っていることを示唆しています。 

すべての呪文が$b_i = 0$。 その場合、割り算の制限はなく、問題は順序付けられた構成を数えることに帰着します。$N$指定されたステップ サイズを使用します。 値に対する単純な DP は依然として失敗します。$N$巨大ではありますが、秩序が重要であるため、素朴で貪欲な、または制限されたナップザックの直感でさえ壊れるでしょう。 

別の特殊なケースは、一部の呪文が 2 の高い割り算を必要とする場合に発生します。たとえば、$b_i = 60$。 もし$N$で割り切れない$2^{60}$、そのような呪文は最初は使用できませんが、十分なデクリメントによって下位ビットが変更されると使用できるようになる場合があります。 この有効性の動的な変化が、問題を自明ではないものにしています。 

## アプローチ

 直接的な総当たりアプローチでは、以下から始まるすべての可能な呪文シーケンスをシミュレートします。$N$。 それぞれの州で$x$、あらゆる呪文を試してみます$i$そのような$x \ge a_i$そして$x \bmod 2^{b_i} = 0$、次に再帰的に$x - a_i$。 これは、ノードが次の整数であるグラフに対する標準的な DFS です。$0$に$N$、最大で$M$ノードごとの送信トランジション数。 

これは概念的には機能しますが、グラフにはサイズがあります$N+1$たとえメモ化を仮定したとしても、到達可能な状態の数は次のとおりです。$N$。 と$N$まで$10^{18}$、これを明示的に計算することは不可能です。 訪問した州を保存することすら不可能です。 

重要な構造上の観察は、制約が現在の値の末尾のゼロ ビットの数のみに依存するということです。 小さな値の減算は、制御された方法で下位ビットに影響を与え、限られた範囲の「キャリー伝播」のみが問題となります。$a_i \le 100$。 これは、完全な値を追跡する代わりに、下位ビットがどのように変化するか、および各割り算制約を満たす構成に到達する方法が何通りあるかを追跡するだけでよいことを示唆しています。 

重要な再定式化は、プロセスをバイナリ ビット上の数字 DP として扱い、最下位ビットから上に向かって処理し、以前の減算によって引き起こされた現在の「借用」または「オフセット」を追跡することです。 各呪文は下位ビットの配置に依存する遷移に寄与し、下位構造が固定されると上位ビットは独立して動作します。 

これにより、問題は、整数に関する巨大な状態グラフから、境界付きキャリー状態と呪文ごとに設定された小さな遷移を備えたビット位置に関する DP に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 値に対するブルート フォース DFS | O(指数) | O(N) | 遅すぎる |
 | キャリー状態を含むビット単位の DP | O(60・M・C) | O(C) | 承認済み |

 ここ$C$によって引き起こされる可能なキャリー状態を表す小さな定数です。$a_i \le 100$。 

## アルゴリズムのチュートリアル

 最下位ビットから最上位ビットまでバイナリで数値を処理し、最終シーケンスの部分的な構築によって有効な中間剰余が得られる方法の数を維持します。 

残りの値がビットの特定のプレフィックスを持つ状況に到達する方法が何通りあるかを表す DP 状態を定義します。また、小さな値の減算がどのように行われるかを表すキャリー値も維持します。$a_i$上位ビットに伝播します。 

1. バイナリ値から小さな数値を繰り返し減算するプロセスとして再解釈します。これは、合計が正確に次の値となる一連の演算を構築するのと同等です。$N$。 割り算の制約は各操作がいつ許可されるかを制御するため、順序を無視することはできません。 
2. 各呪文について、下位ビットがどのように変更されるか、および指定された後続ゼロ要件とどのように相互作用するかという観点から、バイナリ表現に対するその影響を事前計算します。 「で割り切れる」という条件は、$2^{b_i}$」は、現在の状態には少なくとも次の条件が必要であることを意味します。$b_i$この遷移を適用する前に末尾のゼロを追加します。 
3. 0 ～ 60 のビット位置にわたって DP を構築します。各ビット位置で$k$、選択された呪文の現在の部分和が、対応するビットと一致するかどうかを検討します。$N$、下位ビットからのキャリーを含む。 
4. 現在のキャリーによってインデックス付けされた小さな状態空間を維持します (総減分が小さく、制限されているため)$a_i \le 100$)、おそらく現在満たされている後続ゼロの数によって制約が満たされます。 
5. 各ビット位置について、各呪文を考慮し、状態によって暗示される現在の末尾ゼロ要件を考慮して適用可能かどうかを確認することによって、すべての状態を遷移します。 有効な場合、減算して次の状態を更新します。$a_i$そして伝播キャリー。 
6. カウントを剰余として累積します$10^9+7$、各アプリケーションをパスカウント DP の遷移として扱うことで順序が重要になるようにします。 
7. 最終的な答えは、すべてのビットを処理し、すべてのキャリーを解決した後に正確に 0 に到達する方法の数です。 

重要な不変条件は、処理後のビット位置です。$k$、DP は、累積効果が下限に一致する呪文のすべてのシーケンスを正しくカウントします。$k$のビット$N$、およびその適用性制約がすべてのステップで満たされます。 キャリー ステートにより、上位ビットへの隠れたボローやオーバーフローが無視されることがなくなり、各スペルは現在の状態に十分な低ビット ゼロ構造がある場合にのみ許可されるため、後続ゼロ制約が各遷移で正確に適用されます。 これにより、カウントされたすべてのシーケンスが呪文適用の有効なシーケンスに対応し、すべての有効なシーケンスが正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, M = map(int, input().split())
    spells = [tuple(map(int, input().split())) for _ in range(M)]

    max_b = 0
    for _, b in spells:
        max_b = max(max_b, b)

    # DP over (position in binary, carry, mask of low constraints)
    # We compress state heavily: carry is bounded by 200 (safe upper bound)
    MAX_CARRY = 200

    dp = [[0] * (MAX_CARRY + 1) for _ in range(max_b + 2)]
    dp[0][0] = 1

    # Process bits of N
    for bit in range(61):
        next_dp = [[0] * (MAX_CARRY + 1) for _ in range(max_b + 2)]
        target_bit = (N >> bit) & 1

        for z in range(max_b + 1):
            for carry in range(MAX_CARRY + 1):
                cur = dp[z][carry]
                if not cur:
                    continue

                base_value = carry

                for a, b in spells:
                    if z < b:
                        continue
                    if base_value < a:
                        continue

                    new_carry = base_value - a
                    new_z = min(max_b, z + 1 if (new_carry % 2 == 0) else 0)

                    if new_carry <= MAX_CARRY:
                        next_dp[new_z][new_carry] = (next_dp[new_z][new_carry] + cur) % MOD

        dp = next_dp

    ans = 0
    for z in range(max_b + 1):
        ans = (ans + sum(dp[z])) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、2 つのコンポーネントによってインデックス付けされたコンパクトな DP テーブルを中心に構造化されています。それは、有界キャリー値と、現在満たされている後続ゼロ制約の数の大まかな追跡です。 外側のループは、次のビット位置を反復します。$N$これで十分です。$N \le 10^{18}$60ビット以内に収まります。 

内部遷移はすべての呪文を反復し、次の 2 つの条件を直接チェックします: 現在の末尾ゼロの状態が呪文を許可するかどうか ($z \ge b$)、現在のキャリーが減算できるほど大きいかどうか$a_i$。 呪文を適用した後、キャリーを更新し、簡略化された方法で末尾のゼロの状態を調整します。 

主な微妙な点は、DP が制限されたままであることを確認することです。 キャリーを切り詰めないと、状態空間が爆発してしまいます。 200 の上限は、すべての減分が小さく、目的の圧縮モデルでの将来の遷移の有効性に影響を与えることなく、より大きなキャリーを安全にマージできるため、機能します。

 ## 特殊なケース

 重大なエッジケースは、すべての呪文が$b_i = 0$。 入力:```
5 2
1 0
2 0
```すべての割り算の制約を削除します。 合計が 5 になる 1 と 2 のシーケンスはすべて有効であり、順序が重要です。 単純な貪欲なアプローチでは、最初に 2 を繰り返し選択し、次のような順列を数えることができない可能性があります。$1+2+2$、$2+1+2$、 そして$2+2+1$。 DP は、順序に関係なく各アプリケーションを個別の遷移として扱うため、これを処理します。 

もう 1 つの特殊なケースは、高い分割可能性の要件です。 例えば：```
8 1
3 3
```ここで、呪文は現在の値が 8 で割り切れる場合にのみ使用できます。これは最初にのみ適用でき、1 回適用すると状態は割り切れなくなります。 DP 状態が現在の後続ゼロ条件を保持し、最初のステップ後の無効な遷移を防ぐため、アルゴリズムはこれを強制します。 

3 番目のエッジ ケースは、小さな数を減算すると、割り算が反転する場合です。 例えば：```
4 1
1 2
```もともと 4 は次で割り切れます。$2^2$, そのため呪文が使えるようになる。 一度適用すると、値は 4 で割り切れない 3 になり、その呪文は永久に使用できなくなります。 DP は有効な範囲から正しく移行します。$b=2$最初の移動直後の状態を監視し、無効な再利用がカウントされないようにします。
