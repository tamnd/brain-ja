 ## 解決策
 ## 問題の理解

 映画のコレクションが与えられ、各映画には一連の俳優が含まれています。 2 人の俳優が少なくとも 1 つの映画に一緒に出演している場合、直接関係があるとみなされます。 これは当然、無向グラフを定義します。アクターはノードであり、両方を含む映画がある場合、2 人のアクターの間にエッジが存在します。 

ただし、タスクは接続性を判断することだけではありません。 クエリごとに、アクターから始まる明示的な交互シーケンスを構築するように求められます。$x$そして俳優で終わります$y$、連続する俳優がムービーを共有する必要があり、連続するムービーには隣接する俳優が含まれている必要があります。 言い換えれば、俳優と映画からなる二部構成のパスを交互に出力する必要があり、俳優は共通の映画を通じてのみ別の俳優に移動できるという制約があります。 

重要な難点は、$M$アクターの数は最大で$10^6$したがって、完全なアクター グラフを明示的に構築したり走査したりすることはできません。 映画の数は多くても 100 件と少ないですが、各映画には多くの俳優が出演することがあり、すべての俳優の出演の合計は最大 100 件です。$10^6$。 これは、構造が映画に関しては疎であるが、各映画内では潜在的に密であることを強く示唆しています。 

単純な解釈では、俳優に関する完全なグラフを構築し、各映画内のすべてのペア間にエッジを追加することになります。 それはすぐに不可能になります。$k$俳優たちが貢献するだろう$O(k^2)$エッジ、これは限界をはるかに超えています。$k$大きいです。 

2 番目の単純なアプローチは、クエリごとにアクターに対して BFS を実行し、共有ムービーを動的に探索することです。 概念的には正しいですが、隣接するすべてのムービーを繰り返しスキャンすると、$O(Q \cdot N \cdot M)$最悪の場合、 - スタイルの動作が発生しますが、これも遅すぎます。 

俳優たちが映画の長いチェーンを通じてのみ接続されている場合、微妙な特殊なケースが発生します。 たとえば、映画 1 に俳優が含まれている場合、$[1,2]$、ムービー 2 には次の内容が含まれています$[2,3]$、ムービー 3 には以下が含まれます$[3,4]$、次にクエリ$(1,4)$明示的な代替パスを作成する必要があります。 直接の共存をチェックするだけの単純なソリューションでは、中間アクターを介した接続が存在する場合でも、誤って到達不能を返します。 

もう 1 つのエッジ ケースは、俳優が重なり合う複数の映画に出演する場合です。 不注意で、グローバルな訪問状態を追跡せずに各ムービーを個別に扱うと、俳優を誤って繰り返したり、最短の接続や有効な接続さえも見つけられなかったりする可能性があります。 

## アプローチ

 問題の構造は、映画が複数の俳優を接続するハイパーエッジのように動作することを示唆しています。 各映画をクリークに拡張する代わりに、グラフを俳優と映画間の二部横断問題として扱うことができます。 

ブルートフォースのアイデアは単純です。 クエリごとに、ステートがアクターである BFS を実行し、トランジションがムービーを通過します。アクターから、そのアクターが属するすべてのムービーを探索し、そのような各ムービーから、その中の他のすべてのアクターに到達できます。 これは、すべての有効な遷移を明示的に調査するため、正しいです。 問題は、各クエリが大きな映画リストを繰り返しスキャンする可能性があることです。 映画に含まれている場合$k$俳優、そしてそれを探索することで貢献する$O(k)$これは多くのクエリにわたって乗算的に行われます。 最悪の場合、これは同じ大きなムービーを繰り返し処理することになり、おおよその結果が得られます。$O(Q \cdot \sum n_i)$が遅すぎるときは、$Q = 10^4$そして$\sum n_i = 10^6$。 

重要な観察は、映画の数が少ないということです。 BFS 中にムービーを繰り返し展開する代わりに、圧縮コネクタとしてムービーを再利用できます。 私たちは俳優に対して BFS を実行しますが、各ムービーが検索ごとに最大 1 回「拡張」されることを保証します。 任意のアクターを介して最初にムービーに到達すると、そのすべてのアクターを 1 つのバッチで処理し、その BFS に使用されるものとしてマークします。 これにより、同じ大きなリストを繰り返しスキャンすることが防止されます。 

実際の交互シーケンスを再構築するために、俳優だけでなく、俳優に到達するために使用されるムービーの親ポインターも保存します。 これにより、俳優 → ムービー → 俳優 → ムービー チェーンとしてパスを再構築できます。 

各ムービーはクエリ BFS ごとに最大 1 回処理されるため、クエリごとの合計作業量は、入力制約によって制限される、関与する俳優と検索中に遭遇するムービーの数に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ムービー拡張を繰り返すクエリごとのブルート フォース BFS |$O(Q \cdot \sum n_i)$|$O(\sum n_i)$| 遅すぎる |
 | クエリごとのムービー訪問 + 親の再構築による最適化された BFS |$O(\sum n_i + Q \cdot N)$現実的な最悪のケース |$O(\sum n_i)$| 承認済み |

 ## アルゴリズムのチュートリアル

 アクターに対する BFS としてプロセスをモデル化しますが、ムービーが拡張ハブとして機能します。 

1. 映画から俳優へ、および俳優から映画への隣接リストを構築します。 これは、2 種類のノード間をすばやく移動できるように保存されます。 
2. クエリごとに$(x, y)$、アクターを使用して BFS キューを初期化します$x$。 配列も保守します`prev_actor`そして`prev_movie`パスを再構築します。 また、俳優の訪問済み配列と、映画の別の訪問済み配列を維持し、クエリごとにリセットします。 
3. キューが空でない間にアクターをポップします$a$。 あらゆる映画について$m$含む$a$、 もし$m$この BFS ではまだ処理されていないため、処理済みとしてマークし、すべてのアクターを反復処理します。$b$あの映画の中で。 そんな俳優ひとりひとりに$b$まだ訪れていないので、設定しました`prev_actor[b] = a`そして`prev_movie[b] = m`を押してから、$b$列に並びます。 

ムービーを処理済みとしてマークする理由は、同じムービーを異なる俳優を通じて複数回再スキャンすることを避けるためです。そうしないと、作業が大幅に重複してしまいます。 
4. たどり着いたら$y$必要なのは有効なパスが 1 つだけであるため、BFS を早めに停止します。 
5. パスを再構築するには、前から後ろ向きに歩きます。$y$を使用して`prev_actor`そして`prev_movie`。 これにより、俳優と映画の逆の交互シーケンスが生成されます。 
6. 再構成されたシーケンスを逆にして、順方向の最終出力を生成します。 

正確さは、アクターが BFS で最初に発見されたときに、そのアクターへの有効な代替パスが見つかったという不変条件に依存します。 BFS は俳優と映画を交互に展開するレイヤーを探索するため、最初にノードに到達すると有効な接続が保証され、親ポインターを保存することでその構造が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    movies = []
    actor_movies = [[] for _ in range(m + 1)]
    
    for i in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        people = arr[1:]
        movies.append(people)
        for p in people:
            actor_movies[p].append(i)
    
    q = int(input())
    
    for _ in range(q):
        s, t = map(int, input().split())
        
        if s == t:
            print(1)
            print(s)
            continue
        
        visited_actor = [False] * (m + 1)
        used_movie = [False] * n
        prev_actor = [-1] * (m + 1)
        prev_movie = [-1] * (m + 1)
        
        dq = deque([s])
        visited_actor[s] = True
        
        found = False
        
        while dq and not found:
            a = dq.popleft()
            
            for mv in actor_movies[a]:
                if used_movie[mv]:
                    continue
                used_movie[mv] = True
                
                for b in movies[mv]:
                    if not visited_actor[b]:
                        visited_actor[b] = True
                        prev_actor[b] = a
                        prev_movie[b] = mv
                        if b == t:
                            found = True
                            break
                        dq.append(b)
                if found:
                    break
        
        if not visited_actor[t]:
            print(-1)
            continue
        
        path = []
        cur = t
        
        while cur != -1:
            path.append(cur)
            cur = prev_actor[cur]
        
        path.reverse()
        
        print(len(path))
        print(*path)

if __name__ == "__main__":
    solve()
```この実装では、映画の構造を俳優のエッジに平坦化するのではなく、そのままの状態に保ちます。 の`actor_movies`リストにより、俳優は出演しているすべての映画に簡単にアクセスできます。`used_movie`配列は、各ムービーが BFS ごとに最大 1 回展開されることを保証し、大規模な俳優リストの繰り返しスキャンを防ぐため、非常に重要です。 

再構築フェーズは、次のもののみに依存します。`prev_actor`、出力には俳優のみが必要であり、露骨な映画は必要ないためです。 ムービーは、BFS 中のトランジションを正当化するためにのみ使用されます。 

微妙な点は、ターゲットを見つけたときに早めに停止することです。 これがないと、BFS は不要なムービーを拡張し続け、密度の高いケースでは実行時間が大幅に増加する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        n, m = map(int, input().split())
        movies = []
        actor_movies = [[] for _ in range(m + 1)]
        for i in range(n):
            arr = list(map(int, input().split()))
            k = arr[0]
            people = arr[1:]
            movies.append(people)
            for p in people:
                actor_movies[p].append(i)

        q = int(input())
        out = []
        for _ in range(q):
            s, t = map(int, input().split())
            if s == t:
                out.append("1\n{}".format(s))
                continue

            visited_actor = [False] * (m + 1)
            used_movie = [False] * n
            prev_actor = [-1] * (m + 1)

            dq = deque([s])
            visited_actor[s] = True
            found = False

            while dq and not found:
                a = dq.popleft()
                for mv in actor_movies[a]:
                    if used_movie[mv]:
                        continue
                    used_movie[mv] = True
                    for b in movies[mv]:
                        if not visited_actor[b]:
                            visited_actor[b] = True
                            prev_actor[b] = a
                            if b == t:
                                found = True
                                break
                            dq.append(b)
                    if found:
                        break

            if not visited_actor[t]:
                out.append("-1")
                continue

            path = []
            cur = t
            while cur != -1:
                path.append(cur)
                cur = prev_actor[cur]
            path.reverse()

            out.append(str(len(path)))
            out.append(" ".join(map(str, path)))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 2 人の俳優が含まれる 1 つのムービーの最小限のケースで、直接の隣接性をテストします。 BFS は 1 人の俳優から開始し、そのムービーを 1 回拡張して、すぐに他の俳優を見つけます。 親ポインターは直接設定され、再構築により中間ステップなしの 2 アクター パスが生成されます。 

各俳優が個別の映画に出演する完全に切り離されたケースでは、BFS はターゲットをマークすることなく、開始俳優から到達可能なすべての映画を確実に使い果たします。 訪問した配列により無限ループが防止され、正しい出力は -1 になります。 

多くの俳優が出演する密度の高い 1 本の映画で、`used_movie`最適化が不可欠です。 映画を処理済みとしてマークしないと、各俳優が同じリストを再スキャンすることになり、作業が倍増します。 最適化により、ムービーが 1 回拡張され、すべてのアクターが 1 回キューに入れられ、BFS が正常に処理されます。
