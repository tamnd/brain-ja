 ## 解決策
 ## 問題の理解

 「1 で割ったものに類似のものを加えたもの」という形式の繰り返しネストされたパターンから構築された、再帰的に定義された分数のファミリーが与えられます。 構築は簡単な基本値から開始され、同じ構造の新しいレイヤー内に前の結果を繰り返しラップします。 

より具体的には、各レベルは単一の有理数を生成します。 最初の非自明レベルは、1 を取り、分子に 1、分母に 1 とその前の値を加えた分数を形成することによって取得されます。 次の各レベルはまったく同じ変換を繰り返し、常に前の部分の周囲に同じ「ラップ」を適用します。 

タスクは分数自体を出力するのではなく、レベル N で完全に縮小された分数の分子のみを出力することです。式が深くネストされた連分数に成長しても、最終結果は縮小分数 a/b に単純化され、a のみを出力するように求められます。 

N ≤ 40 という制約は、深さが非常に小さいことを意味するため、レベルごとに一定または線形の作業を実行するソリューションであれば十分です。 大きな整数や分数を明示的に操作するアルゴリズムであっても、値はフィボナッチ数のように増加し、競技プログラミング標準では小さいままであるため、安全です。 

微妙な点は、式が左から右に評価されず、文字列として単純に展開されないことです。 分数構造を慎重に保持しないと、単純なシンボリック展開によって実装が簡単に誤解される可能性があります。 もう 1 つの一般的な落とし穴は、各ステップで分数の約定に失敗することです。ただし、この特定の繰り返しでは、正しく構築されていれば、分数は自動的に最低項のままになります。 

エッジケースは最小限です。 N = 1 では、式は単純に 1/(1+1) = 1/2 であるため、分子は 1 になります。値が大きくなると、構造は急速にフィボナッチの成長に似てきます。実装が間違っていると、分子と分母の更新が入れ替わることが多く、シフトされたシーケンスが生成されます。 

## アプローチ

 値を計算する直接的な方法は、連分数をレベルごとに明示的に構築することです。 各ステップで、現在の分数 p = a/b を保存し、変換を適用します。 

p → 1 / (1 + p)。 

p = a/b を代入すると、

 1 + p = (b + a) / b、したがって

 1 / (1 + p) = b / (a + b)。 

これは、各ステップで (a, b) が (b, a + b) に変換されることを示しており、これはまさにフィボナッチ回帰構造です。 分子と分母は、連続するフィボナッチ数のように、逆の順序で進化します。 

p₁ = 1/2 から始めると、(a, b) = (1, 2) が得られます。 更新を繰り返し適用すると、ペア (1,2)、(2,3)、(3,5)、(5,8) などが生成されます。 したがって、レベル N の分子は、このインデックス付け規則では N 番目のフィボナッチ数になります。 

ブルートフォースの代替案では、有理算術またはシンボリック ツリーを使用して、各レベルでネストされた分数を明示的に構築します。 これは正しいですが、概念的には非効率的です。なぜなら、各レベルが以前の構造全体を複製してネストするため、展開すると式のサイズが指数関数的に大きくなるからです。 Python の分数でも N ≤ 40 を処理できますが、線形漸化と比較すると不必要に間接的になります。 

重要な洞察は、連分数が各ラッピング ステップで分数を分子と分母の単純な線形変換に変換するように設計されていることです。 これにより、深くネストされた式がフィボナッチのような数列に折りたたまれます。

 ## アルゴリズムのチュートリアル

 ネストされた式を展開することなく、各レベルの後で分数の分子と分母を追跡したいと考えています。

1. 基底分数 p₁ = 1/2 から開始します。したがって、分子 a = 1、分母 b = 2 となります。これは、構築開始後の最初の明示的に指定されたレベルです。 
2. 2 から N までの次のレベルごとに、現在の分数 p = a/b を 1 / (1 + p) に置き換えます。 構造が破壊されてしまうため、10 進数式またはネストされた式として直接計算することはありません。 
3. 1 + p を (a + b) / b に書き換えます。 このステップは、ネストされた分数を、きれいに反転できる単純な有理式に変換するため、非常に重要です。 
4. 逆数を計算すると、新しい分数 b / (a + b) が得られます。 これにより、ペア (a, b) が (b, a + b) に直接更新されます。 この変換は純粋に分数の代数操作から得られるため、正確さが保たれます。 
5. 初期状態はすでにレベル 1 に対応しているため、この更新を N − 1 回繰り返します。 
6. すべての遷移が終了したら、最後の分数の分子である a を出力します。 

### なぜ効果があるのか

 すべてのステップで、(a, b) が現在のレベルでの換算された分数を表すという不変式を維持します。 (a, b) から (b, a + b) への変換は、まさに p → 1 / (1 + p) を適用する代数的単純化です。 分子と分母の両方が正確な算術を使用して更新され、変換では共素性が維持されるため、分数はプロセス全体を通じて最低項のままになります。 これにより、N − 1 回の適用後、a が正確に p_N の分子になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input().strip())

    a, b = 1, 2  # p1 = 1/2

    for _ in range(N - 1):
        a, b = b, a + b

    print(a)

if __name__ == "__main__":
    solve()
```実装では分子と分母のみが保存され、それらが適切に更新されます。 初期状態は最初に定義された分数に正確に対応し、各ループ反復では導出された反復 (a, b) → (b, a + b) が適用されます。 レベル 1 はすでに初期化されているため、反復回数は N − 1 です。 

重要な実装の詳細は、同時のスワップと追加の更新です。 これがタプルをアンパックせずに 2 つの別個の代入として記述される場合は、値を途中で上書きしないように注意する必要があります。

 ## 特殊なケース

 N = 1 では、アルゴリズムは (a, b) = (1, 2) を初期化し、反復を 0 回実行します。 出力はすぐに a = 1 となり、基数の 1/2 と一致します。 

N = 2 の場合、1 回の更新を実行します。 (1,2) から開始すると、変換により (2,3) が得られます。 明示的に計算された第 2 レベルの分数と一致する分子 2 が出力されます。 

N = 40 など、N が大きい場合は、同じ不変式を保持する変換を繰り返し適用することで正確さが保証されます。 各ステップでは、連続するフィボナッチ数が互いに素であるため、分数は減少したままになります。そのため、漸化式自体を超える隠れた単純化は必要ありません。
