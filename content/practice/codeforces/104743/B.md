 ## 問題の理解

 長さの配列を構築できるかどうかを判断するように求められます。`n`2 つのグローバルなビットごとの制約が同時に満たされるように、別個の整数を使用します。 1 つの制約により、すべての要素のビット単位の OR が強制的に等しくなります。`x`、に表示されるすべてのビットを意味します。`x`少なくとも 1 つの配列要素に出現する必要があり、どの要素も外部にビットを導入することは許可されません`x`。 もう 1 つの制約は、すべての要素に対するビット単位の AND を強制的に等しくします。`y`、つまり、すべての要素には次のすべてのビットが含まれている必要があります。`y`、および含まれていないビット`y`少なくとも 1 つの要素に欠落している必要があります。 

これら 2 つの制約間の相互作用により、強力な構造的制限が作成されます。 すべての配列値は、次の「マスク空間」内に存在する必要があります。`x`のすべてのビットを含めることも強制されますが、`y`。 したがって、それぞれの要素は本質的には`y`さらに、によって許可される追加ビットのいくつかの選択`x`。 

制約が大きいのは、`n`したがって、候補配列を明示的に構築または検索しようとするソリューションは、それが線形である場合にのみ実行可能です。`n`。 次の場合、ビットマスクを超える指数関数的なことは不可能です。`n`まで到達できます`10^5`。 

いくつかの特殊なケースは、単純な推論を即座に打ち破ります。 

もし`n = 1`、配列要素は 1 つだけです。 その場合、OR と AND は両方ともその 1 つの値と等しいため、次のようにする必要があります。`x = y`。 例えば、`n = 1, x = 2, y = 0`同時に 2 と 0 でない限り、単一の数値が OR 2 と AND 0 を同時に持つことはできないため、これは不可能です。 

もし`y`に存在しないビットが含まれています`x`の場合、すべての配列要素には、OR で禁止されているビットが強制的に含まれます。 例えば、`x = 2 (10b)`そして`y = 3 (11b)`すべての要素には最下位ビットが含まれている必要がありますが、OR には最下位ビットが含まれてはならないため、このメソッドはすぐに失敗します。 

もっと微妙な失敗が起こるのは、`n > 1`しかし、すべてのビットをカバーしながら、すべての要素が明確に保たれることを保証せずに、「ビットを独立して拡散」しようとします。`x`。 

## アプローチ

 ブルートフォースアプローチでは、考えられるサイズの配列をすべて列挙しようとします。`n`各要素が間にある場所`0`そして`x`、すべての要素に次のものが含まれることを強制します。`y`, 次に、OR 条件と AND 条件を確認します。 値をビットのサブセットに制限したとしても、`x`、候補の数は、空きビットの数において指数関数的になります。 最大 30 ビットの場合、これは次のようになります。`2^30`要素ごとに可能性があり、配列を構築することは明らかに実行不可能です。 

重要な観察は、AND 条件が構造を大きく制約しているということです。 すべての要素には次のすべてのビットが含まれている必要があるため、`y`、因数分解できます`y`あらゆる要素から。 各要素は次のように記述できます。`a_i = y | s_i`どこ`s_i`によって許可されているビットのみを使用します`x`しかしまだ修正されていない`y`。 

させて`free = x XOR y`(または同等のビット`x`入っていない`y`）。 すべての有効な配列要素は、これらの空きビットのサブセットの選択に対応します。 

ここで、OR 条件は、選択されたすべてのサブセットにわたって、すべてのビットが一致するという要件になります。`free`少なくとも 1 回は出現する必要があります。 AND 条件はすでに構築によって処理されています。`y`すべての要素で固定されています。 

また、すべての要素が区別できる必要があるため、個別のサブセットを選択することになります。`s_i`。 

空きビットの可能な個別のサブセットの総数は次のとおりです。`2^k`、 どこ`k`は設定されたビット数です`free`。 したがって、必要な条件は、`n <= 2^k`。 

特殊なケースにも対応する必要がある`n = 1`、ここで、単一の値は OR と AND の両方を同時に満たす必要があり、強制的に`x = y`。 

建設的なアイデアは、空きビットのサブセットをバイナリ マスクとして扱い、任意のビットを選択することです。`n`個別のマスクを作成しながら、そのうちの 1 つが完全なマスク (すべての空きビットがセットされている) であることを確認します。これにより、OR が正確に一致することが保証されます。`x`。

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。`y`外側のビットを含む`x`。 もし`(y & ~x) != 0`、解決策は存在しません。 これは、すべての要素に次の要素が含まれている必要があるためです。`y`、これにより、禁止されたビットが OR に強制的に挿入されます。 
2. もし`n == 1`、次の場合にのみ YES を返します。`x == y`。 1 つの要素では、OR と AND は同一であるため、自由は存在しません。 
3. コンピューティング`free = x ^ y`、要素間で異なる可能性のあるビットを表します。 
4. しましょう`k`に設定されているビット数になります`free`。 構築できる個別の有効な要素の数は次のとおりです。`2^k`。 もし`n > 2^k`、十分な個別の配列を生成できないため、NO を返します。 
5. のサブセットを使用して配列を構築します。`free`。 それぞれの要素は`y | mask`、 どこ`mask`の異なるサブセットです`free`。 
6. 選択した少なくとも 1 つのマスクが完全なマスクであることを確認します。`(2^k - 1)`すべての要素にわたる OR が次の値に達するようにします。`x`。 その後、残りを埋めます`n - 1`他の個別のマスクを持つ要素。 

### なぜ効果があるのか

 構築されたすべての要素には以下が含まれます`y`したがって、すべての要素の AND は常に要素のすべてのビットを保持します。`y`。 すべての要素は内のビットに制限されます`x`、したがって、OR は次を超えることはできません`x`。 完全な空きビット マスクを含めると、すべてのビットが`x`少なくとも 1 つの要素に出現し、OR が正確に成立します`x`。 すべてのマスクが個別であるため、個別性が保証され、実現可能性は使用可能なサブセットの数によって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())

        if (y & ~x) != 0:
            print("NO")
            continue

        if n == 1:
            print("YES" if x == y else "NO")
            continue

        free = x ^ y
        k = free.bit_count()

        if n > (1 << k):
            print("NO")
            continue

        print("YES")

if __name__ == "__main__":
    solve()
```この実装では、まず、次の間のビット包含制約が適用されます。`y`そして`x`。 次に、単一要素のエッジ ケースを直接処理します。 より大きな配列の場合、空きビット位置の利用可能なサブセットをカウントするだけで問題が軽減されます。 の使用`bit_count()`30 ビット整数およびシフトについては定数時間で実行されるため安全です`1 << k`以来有効です`k <= 30`。 

この問題では実現可能性のみが求められるため、構築自体はここでは明示的に示されていません。 この推論では、条件が満たされれば有効な配列を常に形成できることがすでに保証されています。

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムは直接比較します`x`そして`y`。 これは、OR と AND が単一値制約に集約される唯一の状況です。 たとえば、入力`1 5 5`YESを返しますが、`1 5 4`両方のターゲットに等しくない限り、単一の数値は両方を同時に満たすことはできないため、NO を返します。 

いつ`y`外部にビットが含まれています`x`、 のような`n = 4, x = 2, y = 3`、条件`(y & ~x) != 0`すぐにトリガーされます。 すべての要素にはビットが含まれている必要があります`0`, しかし、ORではそれが禁止されており、関係なく建設が不可能になっています。`n`。 

空きビット領域が大きい場合でも、`n`を超える`2^k`、 のような`x = 1023, y = 0`と`n = 2000`の場合、アルゴリズムはケースを正しく拒否します。`1024`個別のサブセットが利用できるため、OR/AND 制約が柔軟であっても、個別性だけでは不可能になります。
