 ## 問題の理解

 この問題は、すべてが同じ瞬間に鳴り始める 3 つの目覚まし時計について説明しています。`0`。 毎に最初の時計が鳴ります`a`分、秒ごと`b`分、3 分ごと`c`分。 からの瞬間を数える必要があります`0`を通して`T`少なくとも 2 つの時計が同時に鳴ったとき。 

ある瞬間が興味深いのは、それが 2 つ以上の時計の鳴動スケジュールに属している場合だけです。 1 つの期間のみで割り切れる時間は寄与しません。 その瞬間`0`は、3 つの時計すべてがすぐに鳴るという点で特別なので、常にカウントする必要があります。 

期間は最大でも`1000`、 しかし`T`と同じ大きさにすることができます`10^12`。 毎分を直接シミュレーションするには最大 1 兆回の反復が必要ですが、これはプログラムが制限時間内に実行できる量をはるかに超えています。 期間が小さいことは、スケジュールが頻繁に繰り返されることを示唆していますが、値が大きいことは、`T`毎回個別にチェックするのではなく、何度も繰り返す必要があることを示唆しています。 

主なエッジケースは、スケジュール間の重複から発生します。 ペアごとのオーバーラップのみをチェックするソリューションでは、同じ瞬間を 2 回カウントできます。 たとえば、次のようになります。```
2
3
6
6
```正しい答えは`3`、興味深い瞬間は次のとおりです。`0`、`3`、 そして`6`。 ～の倍数を数える`(2,3)`、`(2,6)`、 そして`(3,6)`別々にカウントされます`6`複数回。 

もう一つの簡単な間違いは時間を忘れることです`0`。 例えば：```
5
7
11
0
```答えは`1`、すべての時計が開始の瞬間に鳴るからです。 のみを使用した式`T // period`戻るだろう`0`そしてこの事件を見逃してください。

4
6
9

```答えは`4`、その瞬間があるので、`0`、`6`、`9`、 そして`12`。 を含める代わりに厳密な不等式を使用する`T`最後の瞬間を誤って削除してしまいます。 

## アプローチ

 最も簡単なアプローチは、毎回次から繰り返すことです。`0`に`T`そしてそれを 3 つの期間のうちの何つに分割するかをテストします。 考えられるすべての瞬間が直接チェックされるため、これは正しいです。 問題はそのサイズです`T`。 いつ`T`到達する`10^12`、これには約 1 兆回のチェックが必要ですが、これは不可能です。 

有益な観察は、各アラーム スケジュールは単にその周期の倍数のセットであるということです。 これらの倍数を 1 つずつ生成する必要はありません。 区間内にある数値の倍数を数えるだけで済みます。`[0, T]`。 

一定期間`x`、倍数は`floor(T / x) + 1`。 余分な`1`時間を表します`0`。 

残りのタスクは、3 つのセットの和集合を数えることです。`A`の倍数が含まれます`a`、`B`の倍数が含まれます`b`、 そして`C`の倍数が含まれます`c`。 

包含-排他原理により、これらのセットの少なくとも 1 つに現れる要素の数がわかります。 アラームが 1 つだけ鳴った時間はカウントされるべきではないため、同じ考え方がここでも使用できます。 少なくとも 1 つのアラームが鳴るすべての時間をカウントし、包含除外式を通じて間接的に 1 つのアラームのみが鳴る時間を差し引くことができます。 

2 つのスケジュールの交差部分は、それらの最小公倍数のすべての倍数になります。 3 つのスケジュールすべての交差部分は、3 つの期間すべての最小公倍数のすべての倍数になります。 

すべての有効な時間が検査されるため、総当たり攻撃が機能します。 すべてのスケジュールが周期的であるという観察により、シミュレーションを一定数の算術演算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 指定された期間の倍数を返すヘルパー関数を定義します。`x`の間に存在する`0`そして`T`。 答えは`T // x + 1`、倍数であるため、`x, 2x, 3x, ...`プラス最初の瞬間`0`。 
2. 包含除外を使用して、少なくとも 1 つのアラームが鳴った瞬間の数を数えます。 のカウントを追加します`a`、`b`、 そして`c`。 
3. ペアごとの交差を減算します。 2 つのアラームが鳴る瞬間が 2 回追加されたため、ピリオドを使用して 1 つのコピーを削除します。`lcm(a, b)`、`lcm(a, c)`、 そして`lcm(b, c)`。 
4. 3 つのアラームすべての交差部分を追加します。 3つのリングが3回追加され、3回削除されて消えた瞬間。 を追加し直すと、`lcm(a, b, c)`count はそれを 1 回復元します。 
5. 結果のカウントを出力します。 

機能する理由: すべての時間値は、8 つの可能なカテゴリのいずれかに属します。どのスケジュールにも属さない、1 つのスケジュールのみ、2 つのスケジュールのみ、または 3 つのスケジュールすべてに属すことができます。 包含/除外では、少なくとも 1 つのスケジュールに属するすべての値に 1 という合計寄与度が割り当てられ、他のすべての値には 0 が割り当てられます。 必要な答えは少なくとも 2 つのスケジュールに属する一連の時刻であるため、追加の調整が 1 つ必要です。つまり、アラームが 1 つだけ鳴る瞬間を差し引く必要があります。 これらを個別に処理する代わりに、より単純な同等の観測値、つまり結合数から単一スケジュールを引いた値を使用できます。 これを展開すると、以下の式が得られます。`pairwise intersections - triple intersection`少なくとも 2 つのアラームが鳴った回数をカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    a = int(input())
    b = int(input())
    c = int(input())
    T = int(input())

    def count(x):
        return T // x + 1

    ab = lcm(a, b)
    ac = lcm(a, c)
    bc = lcm(b, c)
    abc = lcm(ab, c)

    ans = count(ab) + count(ac) + count(bc) - count(abc)
    print(ans)

if __name__ == "__main__":
    solve()
```の`gcd`関数は最小公倍数を安全に計算するために使用されます。 表現`a // gcd(a, b) * b`これは、LCM を計算する標準的な方法である乗算の前に不必要な増大を回避します。 

の`count`ヘルパーには時間が含まれます`0`整数除算の後に 1 を加算します。 この調整を忘れると、開始時点が常に有効な同時呼び出し時間となるため、状況が常に変化します。 

最後の式では、ペアごとの重複が最初にカウントされます。 ちょうど 2 つのアラームによって共有される瞬間が、回答に 1 回表示されます。 3 つのアラームすべてが共有する瞬間は 3 回表示されるため、3 つの重複を 2 回減算しすぎると誤りになります。 トリプル LCM の最後の減算により、これらの瞬間は 1 回だけカウントされたままになります。

import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    a = int(input())
    b = int(input())
    c = int(input())
    T = int(input())

    def gcd(x, y):
        while y:
            x, y = y, x % y
        return x

    def lcm(x, y):
        return x // gcd(x, y) * y

    def count(x):
        return T // x + 1

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

 ## 特殊なケース

 3 つのアラームすべてが同じ期間を共有する場合:```

20

5
7
11
0
