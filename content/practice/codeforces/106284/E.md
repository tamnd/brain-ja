 ## 問題の理解

 ゲームにはニンジンモンスターのラインが含まれています。 クロシュはまだ生きている最初のモンスターのみを直接攻撃できます。 後のモンスターに到達するには、その前のモンスターをすべて倒す必要があります。 

現在のモンスターを狙ったショットは、連続したブロックに与えるダメージが増加します。 狙ったモンスターは1ダメージを受け、次のモンスターは2ダメージを受け、その次のモンスターは3ダメージを受け、以下同様に最大でダメージが与えられる。`k`モンスター。 健康を持ったモンスター`h`ダメージを受けるのは`d`健康状態が次のように変わります`|h - d|`。 モンスターの体力がゼロになると、永久に敗北したままになります。 

課題は、すべてのモンスターを倒すために必要な最小ショット数を見つけることです。 

制限は問題の重要な部分です。 まであります`2 * 10^5`モンスター、一方で`k`せいぜい`200`。 ヘルス値が大きくなる可能性があるため、ショット数に比例した作業を実行するシミュレーションは不可能です。 モンスターが死ぬまで繰り返しダメージを与えるアプローチであっても、数十億回の操作が必要となる場合があります。 

の小さな値`k`構造物がどこにあるかを教えてくれます。 モンスターは前のモンスターの影響しか受けられない`k - 1`モンスター、ショットはせいぜい届くので`k`ポジション。 ゲームの毎秒反復処理を避け、代わりに多数の同一操作の効果を一度に処理する必要があります。 

いくつかの特殊なケースは見落とされがちです。 

モンスターが以前のモンスターからのダメージによってすでに殺されている場合、再度攻撃してはなりません。 例えば：```
1 2
5 1
```最初のモンスターは5発撃たれると死ぬ。 これらのショットの間、2 番目のモンスターはダメージ 2 を 5 回受けます。`1 -> 1 -> 1 -> 1 -> 1`実は体力更新は絶対差なので状態は1のままです。答えは最初のモンスター以降の直接攻撃5回+1回の連打ではなく、合計6発です。 直接攻撃のみをカウントし、側面ダメージを無視する解決策は、これを誤ります。 

モンスターは前線に到達する前にゼロになる可能性があります。 例えば：```
2 1
1 2
```The first monster needs one shot. そのショットは 2 番目のモンスターに 2 ダメージを与え、2 から 0 に変化します。答えは 1 です。常に各モンスターと個別に戦う単純な左から右へのシミュレーションでは、出力は 2 になります。 

多数の攻撃は数学的に処理する必要があります。 For example, if a future monster receives damage`3`100 万回の更新をシミュレートする必要はありません。 繰り返される絶対差分演算のサイクルは短く、これがソリューションで使用される主な観測値です。 

## アプローチ

 強引なアイデアは、現在のモンスターを死ぬまで繰り返し撃つことです。 モンスターが現在体力を持っている場合`h`、これは正確にかかります`h`毎回ダメージ1を受けるので撃つ。 すべてのショットの後、次のすべてのモンスターを更新します。`k - 1`ポジション。 

このアプローチはゲームに正確に従っているので正しいですが、健康値が大きい場合は失敗します。 体力のあるモンスター1体`10^18`すでに不可能な回数の反復が必要になります。 

この問題を解決できる観察は、将来のモンスターが受けるダメージが 1 回の戦闘中に常に同じ値であるということです。 モンスターなら`i`攻撃されています、モンスター`i + j`受け取る`j + 1`それらのショットのすべてにダメージを与えます。 関数を適用するだけです`x -> |x - d|`小さな固定で何度も`d`。 

この関数には単純なパターンがあります。 書く`x = q * d + r`、 どこ`0 <= r < d`。 後`q`アプリケーションの場合、値は次のようになります`r`。 もし`r = 0`、モンスターは死んだ。 それ以外の場合は、次のように切り替わります。`r`そして`d - r`。 これにより、一定時間内に繰り返される更新を任意の数だけスキップできます。 

アルゴリズム全体が各モンスターを 1 回処理し、次のモンスターのみを更新します。`k - 1`モンスター。 以来`k`量が少ないと、作業の総量は制限されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(総ショット数 * k) | O(n) | 遅すぎる |
 | 最適 | O(nk) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのモンスターの現在の健康状態を保存します。 ゲームの順序は最初に生きているモンスターのみが攻撃できるというルールによって強制されているため、モンスターを左から右に処理します。 
2. 現在のモンスターの体力がすでにゼロの場合は、スキップします。 以前の攻撃ですでに敗北しました。 
3. それ以外の場合は、現在の状態をそのままにしておきます。`h`。 モンスターがまさに必要としているのは、`h`すべての直接攻撃がダメージを与えるため、ショットを追加します。`h`答えを選択し、モンスターを敗北としてマークします。 
4. この間`h`次の各ショットを更新します`k - 1`モンスター。 遠くにいる怪物`j`ダメージを受ける`j + 1`すべてのショットにダメージが発生するため、その固定ダメージ値で絶対差分演算を繰り返し適用します。 
5. 応募するには`x -> |x - d|`その通り`t`倍、割る`x`による`d`。 もし`t`が商より小さい場合、答えは次のようになります。`x - t*d`。 それ以外の場合、残りの部分は 0 または 2 値のサイクルになります。 

なぜ効果があるのか:

 最初に生きているモンスターは常にダメージ 1 のみを受けるため、その寿命は正確にその現在の健康状態になります。 他のすべてのモンスターは前のモンスターの影響のみを受け、戦闘ごとに 1 つの固定された変換が繰り返し適用されるため、それらの効果は圧縮できます。 このアルゴリズムは、まだ処理されていないすべてのモンスターの正確な状態を維持するため、モンスターが最前線に到達したときに保存される値は、実際のゲームが生成するであろう状態とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_damage(x, d, t):
    if x == 0:
        return 0

    q, r = divmod(x, d)

    if t < q:
        return x - t * d

    if r == 0:
        return 0

    if (t - q) % 2 == 0:
        return r
    return d - r

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    ans = 0

    for i in range(n):
        if h[i] == 0:
            continue

        shots = h[i]
        ans += shots
        h[i] = 0

        for j in range(1, k):
            if i + j >= n:
                break
            if h[i + j] != 0:
                h[i + j] = apply_damage(h[i + j], j + 1, shots)

    print(ans)

if __name__ == "__main__":
    solve()
```機能`apply_damage`は数学的なショートカットです。 商`q`サイズの完全なチャンクの数を表します`d`残りに達する前に削除できます。 アプリケーションの数がその点に達しない場合、値は単純に減少します。`d`毎回。 

残りに達した後は、可能な状態は 2 つだけになります。 残りがゼロの場合は、モンスターが死んでいることを意味します。 ゼロ以外の剰余は以下を交互に返します。`r`そして`d - r`したがって、残りの操作数の同等性のみが問題となります。 

メイン ループはゲームの強制的な順序に従います。 現在のモンスターはその体力を答えに貢献し、ゼロになり、次のモンスターにのみ影響します。`k - 1`ポジション。 更新するたびにヘルスがゼロかどうかをチェックすることで、すでに倒されたモンスターが再び変化するのを防ぎます。 

Python の整数はオーバーフローしません。これは、答えが 32 ビットの制限を超える可能性があるため、必要です。

 ## 特殊なケース

 以前の攻撃によってすでに殺されているモンスターの場合、アルゴリズムは処理する前にゼロをチェックします。 入力で```
2 1
1 2
```最初のモンスターには一撃が必要です。 ２体目のモンスターは２ダメージを受けて０になる。 保存されたヘルスは現在`[0, 0]`、したがって、答えは次のとおりです`1`。 

多数の変換を繰り返す場合、アルゴリズムはショットごとに 1 回の更新を実行しません。 体力のあるモンスターを考えてみましょう`1000000000`ダメージを受ける`2`のために`500000000`ショット。 変換は除算によって圧縮されます。`1000000000 = 500000000 * 2 + 0`したがって、これらの操作の直後にモンスターはゼロになります。 この関数は一定時間内にゼロを返します。 

のために`k = 1`、すべてのショットは現在のモンスターにのみ影響します。 内部更新ループは 0 回実行され、各モンスターは単純に初期体力を提供します。 スプラッシュダメージがないのでゲームにマッチします。 

受けるダメージよりもヘルス値が小さいモンスターの場合、絶対差の動作が直接処理されます。 モンスターに体力がある場合`3`そしてダメージを受ける`5`、になります。`2`、ゼロではありません。 サイクル式は、通常の減算ではなく正確な変換に基づいているため、この動作が維持されます。
