 ## 問題の理解

 符号なし整数型がいくつかあります。 が付いているタイプ`a`ビットは次の値を保存できます。`0`に`2^a - 1`。 何らかの整数が存在するかどうかを判断する必要があります`x`これは小さい活字には適合しますが、その正方形は大きい活字には適合しません。 

つまり、指定されたビット サイズの中に、サイズが 2 種類あるかどうかを知る必要があります。`a < b`によって表現できる値が`a`ビットには、以上のものを必要とする正方形があります`b`ビット。 

入力により、使用可能なタイプの数とそのビット容量が得られます。 出力は`YES`そのような型のペアが存在する場合、および`NO`さもないと。 

型の数は最大になる可能性があるため、制限は重要です。`100000`、各ビット サイズは次のように大きくできます。`10^9`。 型のすべてのペアを比較するソリューションは、約`10^10`最悪の場合にチェックが行われますが、これは通常のコンテストの制限時間の許容範囲をはるかに超えています。 に近い解決策が必要です`O(n log n)`またはそれ以上です。 

値が大きいということは、考えられる数値を反復処理できないことも意味します`x`または巨大な力を計算します。 答えはビット長自体の関係から得られるはずです。 

難しいのは、ビット サイズが等しいと有効なペアが作成されないことです。これは、厳密に小さい型が必要であるためです。`x`厳密に大きいタイプ`x^2`。 たとえば、次の入力を使用します。```
2
5 5
```答えは次のとおりです。```
NO
```2 つの値が異なるかどうかだけをチェックする不用意なソリューションでは、誤って受け入れられる可能性があります。 

最小の型が最大の型よりもはるかに小さい場合、別の特殊なケースが発生します。 例えば：```
3

```答えは次のとおりです。```
YES

## アプローチ

 直接的なアプローチは、すべての小さなタイプとすべての大きなタイプを試してみることです。 ビットサイズのペアの場合`a`そして`b`、小さい方の型に適合する最大値は次のとおりです。`2^a - 1`。 かどうかを確認する必要があります。`(2^a - 1)^2 >= 2^b`。 true の場合、小さい型には 2 乗が大きい型をオーバーフローする値が含まれています。 

最大値を確認するだけで十分なので、このアプローチは正しいです。 数値が大きくなるにつれて二乗も大きくなるため、可能な最大値がオーバーフローしない場合、それより小さい値もオーバーフローすることはできません。 

ただし、すべてのペアをチェックするのは遅すぎます。 と`n = 100000`、ペアの数はおおよそ次のとおりです。`n^2 / 2`、約 50 億件の比較になります。 

重要な観察は、ビット長のみを考慮しているということです。 の値の場合`a`ビットの場合、可能な最大値の 2 乗は、`2^(2a)`。 つまり、`b`ビットは、からのすべての正方形を保持できます。`a`-bit型の場合のみ`b`少なくとも`2a`。 より小さいタイプがある場合`2a`ビット、答えはすぐにわかります`YES`。 

したがって、問題はビットサイズが存在するかどうかを見つけることになります`a`ここで、別の既存のビット サイズは`a`ただし未満`2a`。 サイズを並べ替えて、これまでに確認された最大値を維持できます。 サイズを加工する場合`a`、少なくとも次の以前のサイズがあるかどうかを知る必要があります。`a`? より簡単な方法は、降順に並べ替えて、すでに処理された最大サイズを小さくすることです。 

条件はソートされた配列で確認できます。 どのサイズでも、危険な大きいサイズはその 2 倍を下回るサイズだけです。 すべてのサイズがソートされているため、二分検索を使用してそのような値が存在するかどうかを見つけることができます。

 ## アルゴリズムのチュートリアル

 1. すべてのビット サイズを昇順に並べ替えます。 並べ替えると、特定の型について考えられるすべてのより大きな型がその右側のどこかに表示されます。 
2. ポジションごとに`i`、現在のサイズを扱います`a[i]`収納するタイプとしては`x`。 これよりも小さい新しいサイズがあるかどうかを見つける必要があります。`2 * a[i]`。 このようなサイズは、より大きなタイプになるには十分な大きさですが、可能なすべての正方形を格納するには小さすぎます。 
3. 二分検索を使用して、次の最初のインデックスを見つけます。`i`その値は少なくとも`2 * a[i]`。 そのインデックスが配列のすぐ次の境界ではない場合、次の値の間に値が存在します。`a[i]`そして`2 * a[i]`、したがって、答えは次のとおりです`YES`。 
4. すべてのタイプがこのチェックに合格した場合、印刷します。`NO`。 

なぜ効果があるのか​​: あるタイプの場合`a`ビット、格納される最大値は`2^a - 1`。 それを二乗すると、より小さい数が得られます`2^(2a)`そしてその限界に非常に近づいています。 より少ないタイプ`2a`ビットはそのような正方形をすべて表すことはできません。 1 つのオーバーフロー値の存在を証明するだけでよいため、以下のより大きな型を見つけます。`2a`まさに必須条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    for i in range(n):
        target = 2 * a[i]
        lo, hi = i + 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] >= target:
                hi = mid
            else:
                lo = mid + 1
        if lo < n and lo > i + 1:
            print("YES")
            return

    print("NO")

solve()
```配列は最初に並べ替えられ、より大きな型がすべてグループ化されます。 各タイプについて、二分探索により、以下のサイズ以上の最初のサイズが検索されます。`2 * a[i]`。 その位置が次の要素ではない場合は、その前に少なくとも 1 つの大きな型があり、その型は小さすぎてすべての正方形を安全に含めることができません。 

入力値が次の値に適合するため、2 による乗算は安全です。`10^9`, そのため、中間値は Python 整数内に簡単に収まります。 二分探索は次から始まります`i + 1`型はそれ自体とペアにできないためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    a.sort()
    for i in range(n):
        target = 2 * a[i]
        lo, hi = i + 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] >= target:
                hi = mid
            else:
                lo = mid + 1
        if lo < n and lo > i + 1:
            return "YES\n"
    return "NO\n"

assert run("3\n64 16 32\n") == "NO\n"
assert run("4\n4 2 1 3\n") == "YES\n"

assert run("2\n5 5\n") == "NO\n", "equal sizes"
assert run("3\n1 2 3\n") == "YES\n", "non adjacent pair"
assert run("5\n1 1 1 1 1\n") == "NO\n", "all equal values"
assert run("2\n1000000000 1999999999\n") == "YES\n", "large boundary"
