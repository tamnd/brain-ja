 ## 解決策
 ## 問題の理解

 私たちには円形の賞金ホイールが与えられます。`l`からの番号付きセクション`0`に`l-1`。 ホイール ポインタはセクションから始まります`a`。 スピンするたびにポインタが正確に前方に移動します`b`位置のモジュロ`l`。 目的は、ゼロスピンを含むホイールを任意の回数回転させることで到達できる最大セクション数を決定することです。 

制約は中程度です。`l`そして`b`それぞれ最大 5000 まで、テスト ケースは最大 500 まで可能です。 これは、あらゆるスピンアップをシミュレートするアプローチはすべて、`l`5000 ステップ× 500 テスト ケースは約 250 万操作となり、1 秒の制限時間内で許容できるため、テスト ケースごとのステップ数は実現可能です。 位置が繰り返されるまでスピンを繰り返す強引な方法も機能しますが、不必要な反復を避けるためのより単純な公式が存在するかどうかを調査する価値があります。 

明らかではないエッジケースが発生する場合`b`よりも大きいです`l`、 いつ`b`そして`l`が互いに素でない、またはそのとき`b`分割する`l`その通り。 たとえば、`l=2`、`a=0`、 そして`b=6`、ポインタがセクションから離れることはありません`0`なぜなら`(0 + k*6) mod 2`いつもです`0`。 を前提とした不注意なアプローチ`b`常に新しい位置を生成すると、誤ってより高い最大値が提案される可能性があります。 もう一つのエッジケースは、`b=1`、最終的にはすべてのポジションが訪問されるため、最大値は常に`l-1`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 から始まる`a`、追加し続けます`b`モジュロ`l`到達した最大値を追跡します。 これは正しいです。加算モジュロが繰り返されるためです。`l`の最大公約数によって決定されるセクションのサブセットを循環します。`b`そして`l`。 最悪の場合、ポインタがすべてに当たる可能性があります。`l`位置なので、反復の最大数は次のようになります。`l`。 500 のテスト ケースにわたる結果は次のとおりです。`500 * 5000 = 2.5 * 10^6`許容範囲内です。 

最適なソリューションを実現するための重要な洞察は、ポインターが到達できる位置が等差数列モジュロを形成することを認識することです。`l`。 具体的には、到達可能なセクションの順序は次のとおりです。`a, (a+b) mod l, (a+2b) mod l, ...`。 サイクルは次の後に終了します`l / gcd(b, l)`たくさんスピンした後、`(a + k*b) mod l`に戻ります`a`。 最大到達可能セクションは、次の式を使用して反復せずに直接計算できます。`l - gcd(l, b) + ((a - 1) % gcd(l, b))`または、より単純なロジック: サイクルが繰り返される前の等差数列の最後のセクション。 

この観察により、問題は次の最大公約数 (GCD) の計算に帰着します。`l`そして`b`次に、到達可能なサブセットの最大値を決定します。 これにより、正確性を保証しながら、すべてのスピンのシミュレーションを回避できます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`l`、`a`、 そして`b`。 
2. コンピューティング`g = gcd(l, b)`。 これは、連続する到達可能な位置の間のステップのサイズを法で示します。`l`。 
3. サイクル内で最後に到達可能な位置を決定します。 最大の位置は、`l - g + a % g`。 位置に間隔があるため、これは機能します`g`それとは別に、から始めて`a % g`、以下の最大値`l`この等差数列では`l - g + (a % g)`。 
4. 各テスト ケースのこの最大値を出力します。 

これが機能する理由は、ポインタが一致するセクションのみに到達できるためです。`a modulo g`。 以下の合同クラスの最大のセクション`l`は`l - g + (a % g)`。 到達可能なすべての位置は等差数列に含まれるため、最大値の候補を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

t = int(input())
for _ in range(t):
    l, a, b = map(int, input().split())
    g = gcd(l, b)
    max_prize = l - g + a % g
    print(max_prize)
```解決策は、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに、次の GCD を計算します。`l`そして`b`、位置のステップ サイズをモジュロで定義します。`l`。 次に、次の式を使用してサイクル内で到達可能な最大セクションを計算します。`l - g + (a % g)`。 この式は、開始位置を考慮して残りを慎重に処理します。`a`値が厳密に以下であることを保証します。`l`。 結果はすぐに印刷されます。

 ## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    t = int(input())
    for _ in range(t):
        l, a, b = map(int, input().split())
        g = gcd(l, b)
        output.write(str(l - g + a % g) + "\n")
    return output.getvalue().strip()

 ## 特殊なケース

 のために`l=2, a=0, b=6`、ポインタは 0 のままです。数式は次のように計算します。`gcd(2,6)=2`、 そして`max_prize = 2 - 2 + 0%2 = 0`、これは観察された動作と一致します。 のために`l=5, a=3, b=2`、ポインタはすべての位置を循環します。 GCD は 1 なので、`max_prize = 5-1 + 3%1 = 4`、最も高いセクションを正確にキャプチャします。 この式は、静止位置と完全なサイクルの両方を正しく処理します。
