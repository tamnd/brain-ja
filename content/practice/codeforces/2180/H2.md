 ## 問題の理解

 各ゲームは等差数列を形成する 3 つの数字から始まるため、状態は常に次のように表すことができます。$(a, a+d, a+2d)$と$d > 0$。 プレイヤーは繰り返し 1 つの座標を選択し、それを増加させますが、トリプルはすべての移動の後でも等差数列のままでなければなりません。 順序を入れ替えることはできますが、「等間隔の 3 つの点」という構造は有効なままでなければならず、共通の差は同じままか増加することしかできません。 

単一の「シリーズ」は 1 つのゲームに対応するのではなく、多くのゲームに対応します。固定トリプルの場合$(a_i, b_i, c_i)$のすべての値を考慮します。$x$で$[l_i, r_i]$、それぞれについて$x$同じ開始トリプルで独立してプレイしますが、上限は異なります$x$。 ゲーム全体は、これらの独立した公平なゲームの素の合計であり、プレイヤーは未終了のゲーム間で交互に手を動かします。 動けない方が負けです。 

重要な構造上のポイントは、個々のゲームの Sprague-Grundy 値、または少なくとも勝敗状態を理解すると、それぞれのゲームが有限かつ決定的になるということです。 グローバル勝者は、すべてのゲーム貢献度の XOR によって決定されます。 

制約があるため、私たちは動きのシミュレーションから遠ざけられます。 まであります$2 \cdot 10^5$セグメント、およびエンドポイントは以下に到達します$10^{18}$したがって、答えは、次の各区間の寄与の閉じた形式の特徴付けから得られる必要があります。$O(n)$または$O(n \log n)$合計。 

素朴なアプローチでは、それぞれを分析しようとします。$x$個別にゲームの状態をシミュレートまたは再計算します。 すべてのインターバルにわたるゲームの総数は次のように大きくなる可能性があるため、これは直ちに不可能です。$10^{23}$最悪の場合。 

2 番目の単純なアイデアは、各ゲームを独立して扱い、開始位置が勝っているかどうかを計算することです。 その場合でも、到達可能なすべての状態を理解する必要があり、構造がなければ依然として遅すぎます。 

最も微妙な失敗ケースは、ゲームが周期的なパターンで負け状態から勝ち状態に切り替わる時点で、間隔の境界が正確に切れる場合です。 たとえば、固定の場合$(a,b,c)$、パリティまたはしきい値に応じて結果が変わります。$x$の場合、この交互の構造を知らずに各間隔を独立して処理すると、誤った集計が発生します。

実際には、状態空間は、限界に達する前に進行をどこまで「伸ばす」ことができるかによって決まる少数の構成に崩壊します。$x$。 重要な観察は、ゲームの結果は、初期状態から少なくとも 1 つの有効な手が存在するかどうか、および存在する場合、最終構成に到達するまでに強制的な手が何層存在するかによってのみ左右されるということです。

 ## アルゴリズムのチュートリアル

 最初のトリプルを次のように書き換えます$a, a+d, a+2d$。 重要な問題は、制限内で何らかの動きが可能かどうかです。$x$。 

1. 初期状態がすでに終端状態であるかどうかを確認します。 移動は、要素を 1 つ増やしても等差数列を維持できる場合にのみ存在します。 これを実現できる唯一の意味のある方法は、スペースを維持しながら進行を上にシフトできる場合です。そのためには下に十分な「スペース」が必要です。$x$。 
2. 最小値を決定する$x$少なくとも 1 つの手が存在します。 どのような動きも効果的に 1 つのエンドポイントをプッシュし、進行のバランスを強制的に再調整するため、制限要因は次のとおりです。$x$よりも厳密に大きな進行を許可します$(a, a+d, a+2d)$。 もし$x = c$、移動は不可能です。 もし$x > c$、少なくとも 1 つの拡張が可能になります。 
3. まさに次の時点でポジションが負けていると結論付けます。$x = c$そして全員の勝利$x > c$。 これにより、一定の間隔にわたる単純なステップ関数が作成されます。$[l_i, r_i]$。 
4. 各セグメントについて、次の値がいくつあるかを計算します。$x$で$[l_i, r_i]$満足する$x = c_i$。 これは単一のポイントであるため、セグメントごとに最大 1 つだけ寄与します。 
5. セグメント間のすべての寄与を XOR します。 最終的な XOR が 0 の場合、Feature が勝ちます。 それ以外の場合はバグが勝ちます。 

このアルゴリズムは、各間隔に単一の重要な値が含まれているかどうかをカウントすることに帰着します。$c_i$、それに応じてパリティを切り替えます。 

### なぜ効果があるのか

 不変条件は、移動を妨げる唯一の障害は、厳密な上限の下で有効な等差数列を維持できないことです。 進行は厳格であるため、許可された移動は直ちに境界に違反するか、最大要素を厳密に増加させる均一なシフトを強制します。 これにより、複数ステップの分岐が排除されます。ターミナル動作から非ターミナル動作への意味のある遷移は最大でも 1 つだけです。 したがって、各ゲームはシングルビット ゲームと同等であり、その値は次のいずれかによってのみ決まります。$x$で閾値を超えます$c_i$。 グローバル プレイは、独立したユニットの貢献度の XOR になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        xor = 0
        for _ in range(n):
            a, b, c, l, r = map(int, input().split())
            if l <= c <= r:
                xor ^= 1
        out.append("Bug" if xor else "Feature")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、臨界値が以下であるかどうかのみをチェックします。$c_i$それぞれの間隔の中にあります。 これは、その特定のサブゲームが XOR 全体への勝利トグルに寄与しているかどうかを検出することに対応します。 

唯一の微妙な実装の詳細は、すべての算術演算は比較以外には無関係であるため、すべてが Python の整数に安全に収まることです。 テスト ケース間のゲームは独立しているため、XOR の累積はテスト ケースごとに行われます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$c_i$はちょうど区間の境界上にあります。 条件は両端を含む必要があります。 たとえば、次の場合$l = c$、ゲームはまだ切り替えに貢献しています。 アルゴリズムはこれを正しく処理します。`l <= c <= r`厳密な不平等ではなく。 

もう 1 つのエッジケースは次のような場合です$n = 1$。 ゲーム全体は 1 つのブール値チェックに集約され、勝者は即座に決定されます。 XOR は 0 から始まるため、実装ではこれを自然に処理します。 

最後に、最大の大きな値は、$10^{18}$比較のみが使用されるため、特別な処理は必要ありません。また、Python 整数はオーバーフローせずにこれを処理します。
