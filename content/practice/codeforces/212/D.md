 ## 解決策
 ## 問題の理解

 私たちには、高さが固定された垂直の板の長いストリップが与えられます。 固定長の板の連続セグメントの場合$k$, Vasya は、そのセグメント内の最も短い板によって高さが決定される長方形をペイントします。 したがって、開始位置を選択するたびに、その部分配列の最小の高さという 1 つの値が生成されます。 

要求されたセグメント長ごとに$k_i$、概念的には、次のサイズのウィンドウをスライドさせます。$k_i$配列全体で左から右へ。 各位置は最小値を生成し、すべての位置の可能性は同等です。 タスクは、これらの最小値の平均を計算することです。 

入力サイズが大きいため、プランクの数とクエリの数の両方が上限に達する可能性があります。$10^6$。 これにより、すべてのウィンドウの最小値を個別に再計算することが直ちに排除されます。 クエリごとの単純なスキャンはすでに行われています。$O(nk)$最悪の場合、両方のパラメータが大きい場合、これは完全に不可能です。 

さらに微妙な問題は、単一の答えではなく、すべてのウィンドウにわたる期待を求められることです。 このため、事前計算が不可欠になります。すべてのスライディング ウィンドウ最小値の構造をクエリ間で再利用する必要があります。 

エッジケースは、高さが平坦または完全に単調な場合に発生します。 たとえば、すべての高さが等しい場合、すべてのウィンドウの最小値は同じであるため、すべての答えはその高さに等しくなければなりません。 部分最小値やエンドポイントなど、他のものを誤って平均してしまう単純な実装は、ここで失敗します。 もう一つの落とし穴は、$k = 1$ここで、各ウィンドウには 1 つの要素が含まれているため、答えは単純に配列の平均になります。 

## アプローチ

 強引なアイデアは直接的です。 各クエリウィンドウのサイズについて$k$、すべての開始位置を反復し、各ウィンドウの最小値を計算し、結果を平均します。 各ウィンドウコストの最小値を単純に計算する$O(k)$したがって、各クエリにはコストがかかります$O(nk)$。 まで$10^6$クエリと$n$まで$10^6$、これは天文学的に大きくなり、簡単に超えます$10^{12}$操作。 

スパース テーブルや両端キューのようなデータ構造を使用して最小限のクエリを最適化したとしても、依然として深刻な問題に直面しています。それは、クエリごとに独立して答えを再計算するということです。$k$ほぼ同じ作業を繰り返します。 重要な観察は、答えは、個々のウィンドウ自体には依存せず、各要素がいくつかのウィンドウの最小値となる場所の分布のみに依存するということです。 

これは古典的な視点の逆転につながります。ウィンドウを反復して最小値を取得する代わりに、要素を修正し、それが最小値として機能するウィンドウの数を尋ねます。 数えられるなら、ポジションごとに$i$、長さのウィンドウの数$k$持っている$a[i]$を最小値とすると、期待値はすべての要素の加重合計をウィンドウの数で割ったものになります。 

このカウントをすべての人にとって効率的に行うには$k$、要素ごとに、それが最小として支配できるウィンドウ サイズの範囲を知る必要があります。 これは、単調スタックを使用して見つけることができる、両側の最も近い小さい要素によって決定されます。 これらの境界が判明すると、各要素がウィンドウ サイズの予測可能な範囲に寄与し、すべての要素の寄与を集計できるようになります。$k$一回のスイープで。

 ## アルゴリズムのチュートリアル

 1. ポジションごと$i$、左右に最も近い厳密に小さい要素を計算します。 

これにより、最大セグメントが決定されます。$a[i]$最小限にすることができます。 単調増加スタックにより、これらの境界が線形時間で与えられます。 
2. これらの境界をスパンに変換します$[L_i, R_i]$、 どこ$i$は、その範囲に完全に含まれるサブ配列の最小値です。 

このスパンの長さは$len_i = R_i - L_i + 1$。 
3. 固定要素の場合$a[i]$、長さの部分配列の数を決定します$k$持っている$i$それらの最低限のものとして。 

これは、サイズのウィンドウの数を数えるのと同じです。$k$内側に完全に収まる$[L_i, R_i]$そして含まれます$i$。 
4. この寄与を関数として表現します。$k$。 

それぞれを再計算するのではなく、$k$、次のように観察してください$k$増加すると、有効なウィンドウの数は区分的に線形に減少します。 各要素は、可能な範囲にわたって三角形のプロファイルに寄与します。$k$。 
5. 差分配列を使用する$k$効率的に貢献度を貯めることができます。 

すべての要素からのすべての寄与がマージされるように、等差数列の範囲を追加します。$O(n)$。 
6. すべての要素を処理した後、プレフィックスの合計を計算します。$k$すべてのウィンドウ サイズの最小値の合計を取得します。 
7. 各クエリについて$k_i$、事前に計算された合計をウィンドウの数で割ります。$n - k_i + 1$期待値を得るために。 

### なぜ効果があるのか

 各要素は最小となる連続領域を担当し、この領域はすべてのウィンドウ サイズにわたる動作を完全に決定します。 単調スタックは、これらの領域が最大であり、構造的な意味で重複していないことを保証します。 すべての要素の寄与がウィンドウ サイズの関数として表現されると、線形集計により二重カウントがなくなり、すべての要素の正確さが維持されます。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    ks = list(map(int, input().split()))

    # nearest smaller to left and right
    left = [-1] * n
    right = [n] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    # contribution array for sum of minima over all k
    # we compute via sweep over each element
    max_k = n
    diff = [0.0] * (n + 3)

    for i in range(n):
        l = i - left[i]
        r = right[i] - i

        total = l * r

        # contributions for window sizes 1..n form a piecewise shape
        # add linear segments via difference trick
        diff[1] += a[i]
        diff[min(l, r) + 1] -= a[i]

        diff[min(l, r) + 1] += a[i] * min(l, r)
        diff[max(l, r) + 1] -= a[i] * min(l, r)

    # prefix accumulation to get sum for each k
    for i in range(1, n + 1):
        diff[i] += diff[i - 1]

    ans_sum = diff

    # answer queries
    out = []
    for k in ks:
        windows = n - k + 1
        out.append(f"{ans_sum[k] / windows:.12f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の最初の部分では、単調スタックを使用して最も近い小さな境界を計算します。 左側のスキャンでは厳密な減少が強制されますが、右側のスキャンでは非厳密な比較を使用して等しい値の二重カウントを回避し、各セグメントが一意の制御最小値を持つようにします。 

2 番目の部分では、各要素がウィンドウ サイズに対する寄与プロファイルに変換されます。 重要な実装の詳細は、差分配列を使用して、すべてを明示的に反復することなく、寄与度の区分的線形変化をエンコードすることです。$k$。 

最後に、各クエリは、事前に計算された合計を使用して一定時間内に回答されます。 による除算$n - k + 1$すべてのウィンドウの合計を期待値に変換します。

 ## 特殊なケース

 単一要素の配列の場合、単調スタックはすぐに空の境界を生成し、すべてのクエリはその要素自体に帰着します。 すべてのウィンドウにはその要素のみが含まれている必要があるため、コントリビューション メカニズムはすべてのウィンドウ サイズにわたって値を正しく割り当てます。 

定数配列の場合、左右の境界は両方とも最大限に広がります。これは、すべての要素が同じように寄与することを意味します。 累積により全体にわたって一定の関数が生成されます。$k$、ウィンドウの数で割ると、その定数値が保持されます。 

厳密に増加する配列の場合、各要素の右側の境界が優先されるため、各要素は主にウィンドウの右側の端点である場合に最小になります。 アルゴリズムは非対称を通じてこれを捕捉します$l$そして$r$結果として得られる集約関数は、より大きなインデックスに向かって重みを正しくシフトします。 

厳密に減少する配列の場合は、逆のことが起こります。左側の境界が優勢となり、各要素が左側に拡張するウィンドウを制御します。 スタックベースの境界計算により、この対称性が特別なケースなしで処理されることが保証されます。
