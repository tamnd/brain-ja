 ## 解決策
 ## 問題の理解

 1 つの長い小文字文字列が与えられます`s`。 すべてのクエリに対して、一連の文字も与えられます。`C`。 

すべての部分文字列の中で、`s`、異なる文字のセットが正確に一致するものだけを考慮します。`C`。 これらの部分文字列から、包含によって最大となる部分文字列の数を数えなければなりません。 

同じ文字セットを維持しながら、より大きな部分文字列に拡張できない場合、部分文字列は最大になります。 拡張は左側、右側、または両方に発生する可能性があります。 

たとえば、次のように仮定します。`s = "ababa"`そして`C = {a, b}`。 部分文字列`"aba"`内側にあるため最大ではありません`"ababa"`、まだ使用しているのは`{a, b}`。 全体`"ababa"`拡張すると文字列が残るため、これが最大になります。 

文字列の長さが次の値に達しました`10^6`、クエリの数は最大です。`10^4`。 すべての部分文字列を検査するソリューションは完全に不可能です。 すべての部分文字列を保存する場合でも、既に二次メモリが必要になります。 

アルファベットには英小文字のみが含まれており、問題の性質が完全に変わります。 文字は 26 個しかないため、すべての文字セットは 26 ビット マスクとして表現できます。 個別のマスクの総数は次のとおりです。`2^26`理論的には大きいですが、処理中に実際に表示されるマスクの数は管理できる程度です。 

難しいのは、「包含による最大化」が実際に何を意味するのかを理解することです。 文字セットを含む部分文字列`C`左または右に 1 文字拡張すると外側に新しい文字が導入される場合に、正確に最大値になります。`C`。 

不用意に実装すると、ここで間違いが発生することがよくあります。 

考慮する：```
s = "aaaaa"
C = {a}
```すべての部分文字列は次のもののみで構成されます`'a'`, but only the whole string is maximal. 答えは`1`、 ない`15`。 

もう一つの簡単な罠:```
s = "abac"
C = {a, b}
```部分文字列`"ab"`は最大値ではありません。`"aba"`新しいキャラクターを導入することなく。 正しい最大部分文字列は次のとおりです。`"aba"`。 

もう 1 つの微妙なケース:```
s = "abcabc"
C = {a, b, c}
```文字列全体が 1 つの最大部分文字列になります。 のような小さな部分文字列`"abc"`より大きな有効な部分文字列内に含まれるため、カウントしてはなりません。 

問題は、指定されたセットの部分文字列をカウントしないことです。 文字がセット内に留まり、使用されている文字のセットがセットと正確に等しい、最大の接続領域をカウントします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての部分文字列を列挙し、その一連の個別の文字を計算し、それが最大であるかどうかをテストします。 

がある`O(n^2)`部分文字列。 文字マスクを段階的に維持したとしても、依然として二次作業が必要です。 と`n = 10^6`、これくらいになります`10^12`部分文字列ですが、これは完全に不可能です。 

重要な観察は、最大部分文字列が非常に剛直な構造を持っているということです。 

いくつかの文字セットを修正`C`。 文字列をスキャンして、次の文字列に属する文字だけを調べることを想像してください。`C`。 以下の文字のみを含む最大の連続ブロック。`C`が 1 つの候補領域を形成します。 その領域内で、すべての文字が`C`少なくとも 1 回出現すると、ブロック全体がトレースのある最大の部分文字列になります`C`。 

例えば：```
s = "abacxaba"
C = {a, b}
```有効なブロックは次のとおりです。```
"abac" -> stops before c, invalid
"aba"  -> valid
```実際には、のみを使用した最大の連続領域`{a,b}`は`"aba"`そして`"aba"`。 それぞれに両方の文字が含まれているため、両方が貢献します。 

これにより問題は完全に変わります。 

部分文字列を列挙する代わりに、すべての文字が何らかのマスクに属する最大間隔を列挙します。 このような間隔はすべて、その中に現れる文字によって形成されるマスクに対する 1 つの答えに寄与します。 

ここで、アルファベットのサイズが重要になります。 文字は 26 個しかないため、すべての部分文字列マスクは整数内に収まります。 

位置から始めるとします`i`そして右方向に伸びます。 26 文字すべてを確認するか、文字列の終わりに到達するとすぐに停止します。 すべての拡張子について、使用される文字のセットを維持します。 

重要なプロパティは次のとおりです。 

固定右境界拡張の場合、マスクの最大間隔は一意に決定されます。 

禁止文字が出現する位置の間を拡張することで、すべての最大間隔を計算できます。 

受け入れられた解決策は、マスクと間隔の境界上でローリング探索を使用します。 アルファベットが小さいため、個別のマスク トランジションの総数は管理可能なままです。

 ## アルゴリズムのチュートリアル

 1. すべての文字を次のビット位置に変換します。`0`に`25`。 
2. あらゆる可能な開始位置に対して`l`、右側の境界を延長します`r`使用されている文字の現在のマスクを追跡しながら。 
3. 各間隔について、現在のマスクの文字のみを含むその周囲の最大セグメントを決定します。 
4. すべての部分文字列をカウントする代わりに、そのマスクに対応する一意の最大間隔のみをカウントします。 
5. マスクの最大間隔`M`は連続セグメントであり、次のとおりです。`every character belongs to M`、 そして`the segment contains every character of M at least once`。 
6. 文字列をスキャンしている間、次の文字のみで構成される連続ブロックを最大限に維持します。`M`。 
7. そのようなブロックに正確なトレースがある場合`M`の答えをインクリメントします。`M`。 
8. ビットマスクでインデックス付けされたハッシュ マップに回答を保存します。 
9. 各クエリ文字列について、それをマスクに変換し、保存されている回答を出力します。 

明らかではない部分は、重複したカウントを避けることです。 多くのより小さな部分文字列が同じ最大ブロックに属する可能性がありますが、包含によって最大となるのはブロック全体だけです。 最大の連続領域を直接操作することにより、すべての有効な回答が 1 回だけカウントされます。 

### なぜ効果があるのか

 トレースのある最大部分文字列を考慮します`M`。 

その中のすべての文字が属しています`M`。 また、左または右に 1 ステップ拡張すると、文字列が離れるか、文字列の外側に文字が導入されます。`M`。 つまり、この部分文字列は、正確に次の文字のみで構成される最大の連続ブロックです。`M`。 

逆に、最大の連続ブロックはすべて、次の文字のみで構成されます。`M`のすべての文字が含まれています`M`含めることで最大になります。 これを拡張すると、必然的に禁止文字が導入されることになります。 

これにより、有効な回答と最大ブロックの間に 1 対 1 の対応関係が作成されます。これはまさにアルゴリズムがカウントするものです。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    arr = [ord(c) - 97 for c in s]

    ans = defaultdict(int)

    for mask in range(1, 1 << 26):
        pass

    # enumerate maximal segments efficiently
    for left in range(n):
        cur_mask = 0

        freq = [0] * 26

        for right in range(left, min(n, left + 26)):
            c = arr[right]

            freq[c] += 1
            cur_mask |= 1 << c

            # check maximality
            ok_left = (
                left == 0 or
                ((1 << arr[left - 1]) & cur_mask) == 0
            )

            ok_right = (
                right == n - 1 or
                ((1 << arr[right + 1]) & cur_mask) == 0
            )

            if ok_left and ok_right:
                ans[cur_mask] += 1

    m = int(input())

    out = []

    for _ in range(m):
        q = input().strip()

        mask = 0

        for ch in q:
            mask |= 1 << (ord(ch) - 97)

        out.append(str(ans[mask]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装における重要な点は、アルファベットのサイズが固定されているため、最大の部分文字列には 26 個を超える異なる文字を含めることはできないということです。 

すべての開始位置について、文字を繰り返すか、可能なすべての個別の文字を使い果たす前に、最大 26 ステップを拡張するだけで済みます。 これは二次関数に見えるものを大まかに変換します`26n`。 

2 つの最大性チェックが重要な部分です。```
ok_left = (
    left == 0 or
    ((1 << arr[left - 1]) & cur_mask) == 0
)
```これにより、左に 1 ステップ拡張すると、現在のマスクの外側に文字が導入されることが検証されます。 

同様に:```
ok_right = (
    right == n - 1 or
    ((1 << arr[right + 1]) & cur_mask) == 0
)
```正しい拡張子をチェックします。 

両方の条件が当てはまる場合にのみ、部分文字列がカウントされます。 

よくある間違いは、隣接する文字が部分文字列自体の中に既に出現しているかどうかを確認することです。 実際の条件は、隣接する文字が間隔内の他の場所で発生するかどうかではなく、隣接する文字がマスクに属しているかどうかによって決まります。
