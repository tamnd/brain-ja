 ## 解決策
 ## 問題の理解

 個別の商品価格のリストが与えられます。 各項目は増やすか変更しない必要があり、最終的なシステムが正確に k 個の個別の値を使用するように新しい価格を選択します。 すべてのアイテムには 1 つの最終価格が割り当てられ、その価格は少なくとも元の価格でなければなりません。 目標は、すべての品目の合計増加額を最小限に抑えることです。 

これについて考えるのに役立つ方法は、元の価格を k レベルに「圧縮」しているということです。 各項目はこれらのレベルのいずれかに切り上げられ、合計の上方調整コストが支払われます。 

この制約により、すべてのテスト ケースにわたって合計で最大約 2000 個の項目が許可されるため、三次解は即座に除外されます。 テスト ケースごとに O(n^2) に近いものは境界線にありますが、慎重に実装され、n の合計が小さい場合にのみ許容されます。 すべてのサブセットまたはパーティションを明示的に試行すると失敗します。 

k が n と等しい場合、微妙なエッジ ケースが 1 つ現れます。 その状況では、すべての値を個別に保つことができるため、すべての i に対して単に e_i = s_i を選択できるため、最適な答えはゼロになります。 反対に、k が 1 に等しい場合、すべての項目は 1 つの値にまとめられる必要があり、最適な選択は、すべてを最大要素まで引き上げて、コストの合計 (max − s_i) を作成することです。 両極端を同じように扱う単純なアプローチでは、グループ化について明確に理由を付けていない場合、これらの動作を見逃してしまいます。 

もう 1 つの注意が必要な状況は、大きな値が配列の初期に出現する場合です。 値の増加のみが許可されているため、グループ化戦略が不十分であると、小さな値が大きなターゲットに割り当てられている場合に、過剰な値の増加が強制される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、アレイを k 個のグループに分割し、各構成のコストを計算するために考えられるすべての方法を試みることです。 固定グループの場合、その最大値が M の場合、そのグループ内のすべての要素は少なくとも M に引き上げられる必要があるため、コストはグループ全体の (M − s_i) の合計になります。 すべてのグループを合計すると、合計コストが得られます。 

これは正しいですが、すぐに実行不可能になります。 n 個の要素を k 個の連続するグループに分割する方法の数は、n で指数関数的になります。並べ替え後に連続するセグメントに制限したとしても、単純な動的計画法による解決策ではやはり O(n^2 k) となり、最悪の場合には遅すぎます。 

重要な観察は、最終的な構造は順序付けのみに依存するということです。 すべての操作は単調増加であるため、ソートされた配列を操作することが常に最適です。 並べ替えると、重要な構造上の事実が明らかになります。最適解では、各グループは連続したセグメントに対応し、各セグメント内で、最終的に割り当てられた値はまさにそのセグメントの最大要素になります。 

これにより、ソートされた配列を分割する k 個のセグメントを選択するという問題が軽減され、セグメント全体の合計 (segment_size ×segment_max −segment_sum) が最小化されます。 パーティションを直接最適化する代わりに、プロセスを再解釈することができます。つまり、最終的な個別の値として機能する k 個の「代表」要素を効果的に選択し、すべての要素がそれ自体より小さくない最小の代表に上向きにマップされます。 

重要な単純化は、k 個の最大の要素を代表として選択することが最適であるということです。 これらが修正されると、他のすべての要素が次に選択された代表者にプッシュアップされます。 この貪欲な構造により、パーティションにわたる動的プログラミングの必要がなくなります。

 ## アルゴリズムのチュートリアル

1. 元の価格の配列を降順でない順に並べ替えます。 これにより、最終値の有効な割り当てが上方丸めに関して一貫して解釈されることが保証されます。 
2. k 個の最大の要素を「代表値」として選択します。 これらは k 個の個別の最終価格になります。 直感的には、値が大きいほど柔軟性が高くなります。これは、値を必要以上に増やすことなく、多くの小さな要素のターゲットとして機能できるためです。 
3. これらの k 個の代表を昇順に並べ替えます。 これらは、許可される最終レベルのチェーンを定義します。 
4. 元の要素ごとに、それと少なくとも同じ大きさの最小の代表を決定します。 これは、要素が引き上げられるレベルを表します。 
5. 選択した代表値と元の値の差を答えに追加します。 

割り当てステップは、両方のリストがソートされているため、代表値内を移動するポインタによって自然に実装されます。 

### なぜ効果があるのか

 不変条件は、選択された代表のセットが実行可能性の点で常に最適なソリューションを支配し、不必要にコストを増加させないということです。 最適な解には k 個の異なる最終値が必要であり、クラスター内の最大以外の代表値をより大きな値に置き換えても、実現可能性は向上せずにコストが増加するだけです。 したがって、最適な構造は常に崩壊し、k 個の最も効果的なターゲットを選択し、すべてを貪欲に上向きに割り当てます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        # choose k largest as representatives
        reps = a[n - k:]
        reps.sort()

        ans = 0
        j = 0

        for x in a:
            while j < k and reps[j] < x:
                j += 1
            ans += reps[j] - x

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、グループ化動作が単調になるように、まず配列を並べ替えます。 代表値は k 個の最大要素として取得され、正確に k 個の異なる最終値が保証されます。 ポインタ j により、各要素が最小の有効な代表値に割り当てられるようになり、不必要な増加が回避されます。 

実装の微妙な詳細は、 j が要素ごとにリセットされないことです。 両方の配列がソートされているため、前方にのみ進みます。 これにより、ソート後の線形スキャンが保証され、O(nk) 内部ループが防止されます。

入力:

| 要素 | 担当者ポインタ j | 選ばれた担当者 | 費用 |

 | 1 | 0 | 1 | 0 |

 増加する必要はなく、境界で正しいことが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        reps = a[n - k:]
        reps.sort()

        ans = 0
        j = 0
        for x in a:
            while j < k and reps[j] < x:
                j += 1
            ans += reps[j] - x
        out.append(str(ans))

    return "\n".join(out)

# k = 1 case
assert run("1\n3 1\n1 2 3\n") == "3"

# identical structure test
assert run("1\n5 2\n1 1 1 1 10\n") == "0"

 ## 特殊なケース

 k が n と等しい場合、すべての要素は独自のグループになります。 アルゴリズムは、すべての要素を代表として選択することでこれを処理するため、各値はそれ自体にマッピングされ、コストはゼロのままになります。 

k が 1 の場合、代表セットには最大の要素のみが含まれます。 他のすべての要素がこの単一の値に割り当てられ、必要な変換に一致する最大の差の合計に等しいコストが生成されます。 

多数の小さな値と少数の大きな値がある場合、貪欲な割り当てにより、小さな値が実行可能な最小の代表値に確実に吸収され、不必要に大きなターゲットに上げすぎないようにします。
