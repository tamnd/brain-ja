 ## 解決策
 ## 問題の理解

 整数の配列があります。 演算により、任意の 2 つの位置とビット インデックスを選択し、2 つの数値間でそのビットの値を交換できます。 

重要な点は、スワップ中にビット位置が固定されるということです。 移動できます`1`ある数値から別の数値へのビット変換ですが、同じビット位置内でのみ可能です。 たとえば、位置 3 のビットが位置 2 のビットになることはありません。 

目標は、このような操作を任意の回数実行した後、配列内の最大要素と最小要素の差を最大化することです。 

配列のサイズは最大 512 で、すべての値は 1024 未満です。1024 は$2^{10}$、各数値には関連するビット位置が 10 個だけ含まれています。 ビット幅が小さいということは、ビットごとに推論する方が演算をシミュレートするよりも有用であることを強く示唆しています。 

よくある間違いは、スワップによって各数値の値が保持されると考えることです。 そうではありません。 例えば：```
2
4 3
```バイナリ形式は`100`そして`011`。 ビット 2 を交換すると、次のようになります。```
000 = 0
111 = 7
```数字は劇的に変わります。 

もう 1 つの簡単な間違いは、異なるビット位置を相互作用しているものとして扱うことです。 彼らは完全に独立しています。 例えば：```
3
1 2 4
```各ビット位置には 1 つだけあります`1`。 どの操作をしても移動できません`1`ある位置から別の位置へ。 私たちにできる最善のことは、既存のものをすべて収集することです`1`ビットを 1 つの数値に変換し、`7`、別の番号をそのままにしておきます`0`。 答えは`7`。 

3 番目のエッジケースは、すべての数値が同一である場合です。```
4
5 5 5 5
```すべてのビット位置には、すべて 0 またはすべて 1 が含まれます。 ビットを交換しても何も変わらないので、答えは残ります`0`。 

## アプローチ

 ブルートフォースの考え方は、どの状態に到達できるかを尋ねることから始まります。 ビット交換を繰り返し実行して、新しい配列を生成し、可能な最大値を検索することができます。`max(a) - min(a)`。 

あらゆる合法的な運用が検討されるため、これは原則として正しいです。 問題は、状態空間がすぐに爆発してしまうことです。 単一の操作でも、$O(n^2 \cdot 10)$選択肢。 一連の操作により、到達可能な配列が膨大な数に作成されるため、明示的な検索が完全に不可能になります。 

重要な点は、ビット位置が独立しているということです。 

1 つの固定ビット位置を考慮します$b$。 正確に仮定してください$k$現在、数字には`1`その位置で。 ビットを交換すると、それらのビットが再配置されるだけです$k$配列位置のうちの 1 つ。 そのビット位置にある 1 の合計数は決して変わりません。 

これは、各ビット位置について、ビット位置が現在どこにあるかではなく、存在するビット位置の数のみを考慮することを意味します。 

次に、次のことを最大化することを考えてみましょう。```
max(a) - min(a)
```この差をできるだけ大きくするには、1 つの数値をできるだけ大きくし、別の数値をできるだけ小さくする必要があります。 

すべてのビット位置について:

 少なくとも 1 つあれば`1`その位置に存在する場合は、そのうちの 1 つを将来の最大要素に移動できます。 

すべての数字に`1`その位置では、一部の要素に`0`そこに、将来の最小限の要素を作成するのに役立ちます。 

以来$n \ge 3$、ビット位置に少なくとも 1 つが含まれる場合は常に`1`、いつでも配置できます`1`最大要素と`0`同時に最小要素に取り込みます。 

結果として、すべてのビット位置が最終的な差に独立して寄与します。 

ビット位置が少なくとも 1 つの数値に出現する場合、そのビット位置はその完全な値に寄与します。$2^b$答えに。 

これはまさに、配列全体にわたるビットごとの OR の定義です。 

したがって、答えは簡単です。```
a1 OR a2 OR ... OR an
```同じ結果を確認する別の方法もあります。 させて：```
M = OR of all elements
```利用可能なものはすべて集めることができます`1`1 つの要素をビット化し、価値を生み出す`M`。 

最小要素については、すべての数値に存在しないすべてのビットを作成できます。`0`。 以来$n \ge 3$、それらのビットを保持するために別の要素を選択できます。 最小限で駆動できるのは、`0`。 

したがって、次のようになります。```
max(a) - min(a) = M - 0 = M

 ## アルゴリズムのチュートリアル

 1. アキュムレータを初期化する`ans = 0`。 
2. 配列内のすべての数値を反復処理します。 
3.アップデート`ans |= value`要素ごとに。 

これにより、配列内に少なくとも 1 回出現するすべてのビット位置が収集されます。 
4. 配列全体を処理した後、出力します。`ans`。 

これが機能する理由は、各ビット位置を独立して再配置できるためです。 配列内のどこかに存在するビットは、将来の最大要素に割り当てることができます。 最小要素は同時にそのビットの受信を回避できるため、そのビットの完全な値が最終的な差に寄与します。 

### なぜ効果があるのか

 ビット位置ごとに$b$、その値を次のようにします$2^b$。 

どの要素にもそのビットが含まれていない場合、そのビットはどこにも出現できないため、その寄与はゼロになります。 

少なくとも 1 つの要素にそのビットが含まれている場合、その位置にある 1 の数は正になります。 配列要素間でビットを交換することにより、それらのビットの 1 つを最大値として選択された要素に配置できます。 同時に、なぜなら、$n \ge 3$、その位置にゼロを持つ別の要素を保持し、それを最小候補として使用できます。 

したがって、少なくとも 1 回出現するすべてのビットが正確に寄与します。$2^b$達成可能な違いに。 すべてのビット位置にわたるこれらの寄与を合計すると、配列のビットごとの OR が得られ、これがまさに答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    for x in a:
        ans |= x

    print(ans)
```数学的観測によりすべてのシミュレーションが不要になるため、実装は非常に小さくなります。 

変数`ans`配列の実行中のビットごとの OR を格納します。 数値を処理するたびに、その数値に含まれるすべてのビットが`ans`。 

アレイ全体をスキャンした後、`ans`配列内の任意の場所に少なくとも 1 回出現するビット位置のセットが正確に含まれます。 上記の証明は、この値が達成可能な最大の差に等しいことを示しています。 

難しい境界条件はありません。 数値は小さいため、Python の整数は簡単に処理でき、答えは通常の整数の範囲内に収まります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        for x in a:
            ans |= x

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

## 特殊なケース

 ### すべての値が等しい

 入力:```

```アルゴリズムは以下を計算します。```

```出力：```

```すべてのビット位置は、すべての数値に存在するか、すべての数値に存在しません。 スワップしても何も変わりません。 達成可能な最大の差はちょうど 5 で、OR と一致します。
