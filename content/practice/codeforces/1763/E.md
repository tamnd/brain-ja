 ## 解決策
 ## 問題の理解

 未知の数の頂点上の有向グラフが与えられます。 グラフは構造条件を満たす必要があります。すべての順序付けされた頂点のペアの中に、正確に\(p\)\((u,v)\) とのペア\(u < v\)両方の頂点が互いに到達できるようにします。 言い換えれば、これらのペアは強く接続された構造内にあり、他のすべてのペアは一方向に動作します。 

タスクは 2 層構造になっています。 まず、次の要件を正確に満たす有向グラフを構築できる最小の頂点数を決定する必要があります。\(p\)相互に到達可能な順序ペア。 次に、このような最小サイズのグラフすべての中で、次の順序ペア \((u,v)\) の数を最大化したいと考えています。\(u \ne v\)は一方向です。つまり、からのパスがあることを意味します。\(u\)に\(v\)しかし戻る道はありません。 

与えられる唯一のパラメータは\(p\)、次のように大きくすることができます\(2 \cdot 10^5\)。 このスケールでは、二次関数やグラフ列挙ベースのものは除外されます。 どのようなソリューションも、明示的な構築ではなく、グラフをコンポーネントに構造的に分解することに依存する必要があります。 

重要な点は、相互の到達可能性が等価関係であるということです。 これにより、グラフが強く接続されたコンポーネントに強制され、すべての制約は実際にどのように分割するかに関するものになります。\(n\)ノードを SCC に追加し、それらをどのように順序付けするか。 

よくある失敗例は、ペアを独立して扱うことです。 たとえば、ローカルにサイクルを追加して「正確に p 個の相互に到達可能なペアを作成」しようとすると、オーバーカウントにつながります。これは、単一の SCC のサイズが大きいためです。\(t\)貢献する\(\binom{t}{2}\)そのようなペアを同時に。 

## アプローチ

 正しい観点は、グラフを強く接続されたコンポーネントに圧縮することです。 各サイズの SCC 内\(s\)、異なるノードの順序付きペアはすべて相互に到達可能であるため、このコンポーネントは\(\binom{s}{2}\)有効なペア。 

凝縮後の SCC グラフは DAG になります。 コンポーネント間の到達可能性は一方向です。 この分離は非常に重要です。内部構造は、\(p\)、DAG 構造は一方向ペアを決定します。 

ブルートフォースのアイデアは、すべてのパーティションを試してみることです。\(p\)二項係数に変換する\(\binom{s_i}{2}\)、次にノードの合計数を計算し、最適な構成を選択します。 これは正しいですが、パーティションの数は指数関数的に増加するため、現実的ではありません。\(p\)。 

重要な点は、ノードを最小限に抑えるには、SCC サイズをできるだけ大きくする必要があるということです。 目標とする貢献度を考慮すると、\(p\)、可能な限り最大の三角数を使用してパックしたいと考えています。\(\binom{s}{2}\)。 これは貪欲な分解になります。最大のものを繰り返し選択します。\(s\)そのような\(\binom{s}{2} \le p\)、それを減算して続行します。 

SCC サイズが固定されると、最小化するノード数が決定されます。 これらの最小限の構成のうち、一方向ペアを最大化すると、コンポーネント間の到達可能性が欠如していると追加の一方向ペアが作成されるため、チェーン内の SCC を順序付けることになります。 

これにより、決定論的な構造が得られます。つまり、サイズが次から貪欲に決定された SCC の直鎖です。\(p\)。

 ## アルゴリズムのチュートリアル

 しましょう\(p\)相互に到達可能な順序ペアの必要な数になります。 

1. 可能な最大のブロックから始めて SCC サイズを繰り返し構築します。 各ステップで最大の整数を選択します\(s\)そのような\(\binom{s}{2} \le p\)。 これにより、確実に削減できます\(p\)コンポーネントの数を最小限に抑えながら、できるだけ早く実行できます。 

2. 引き算します\(\binom{s}{2}\)から\(p\)そして記録する\(s\)1 つの SCC サイズとして。 残りの問題は同じですが、値が小さくなります。\(p\)。 

3. まで続けます\(p = 0\)。 これにより、SCC サイズのリストが生成されます。 

4. 最終的なグラフのノード数は、これらの SCC サイズの合計です。 

5. 一方向ペアを最大化するために、SCC を単一の有向チェーンに配置します。 以前のコンポーネントの頂点のすべてのペアは、後のコンポーネントのすべての頂点に到達できるため、到達可能性はコンポーネント全体で合計されます。 

6. 内部 SCC ペアはすべて双方向であるため、単方向ペアの数はコンポーネント間の順序によって完全に決定されます。 

### なぜ効果があるのか

 各 SCC は、相互に到達可能なペアの数に独立して寄与します。 二項構造により、次のような分解が保証されます。\(p\)SCC サイズのパーティションに対応します。 最大の SCC を選択すると、合計頂点数が最小限に抑えられます。\(\binom{s}{2}\)で二次的に成長します\(s\)したがって、貪欲にパッキングするとコンポーネントの数が減ります。 SCC 構造が固定されると、チェーン内でそれらを順序付けると、到達可能性の非対称性が最大化され、一方向ペアが最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    p = int(input())
    sizes = []

    # build SCC decomposition greedily
    while p > 0:
        # largest s such that s*(s-1)//2 <= p
        s = 1
        lo, hi = 1, 2 * int((2 * p) ** 0.5) + 5
        while lo <= hi:
            mid = (lo + hi) // 2
            if mid * (mid - 1) // 2 <= p:
                s = mid
                lo = mid + 1
            else:
                hi = mid - 1

        sizes.append(s)
        p -= s * (s - 1) // 2

    n = sum(sizes)

    # compute unidirectional pairs in chain of SCCs
    # prefix sizes give reachability structure
    unidirectional = 0
    prefix = 0
    total = n

    for s in sizes:
        total -= s
        # all pairs from previous components to future components
        unidirectional += s * total

    print(n, unidirectional)

if __name__ == "__main__":
    main()
```コードが最初に分解される\(p\)実現可能な最大の SCC サイズを求める二分探索を使用して、三角形コンポーネントに分割します。 これにより、線形スキャンが回避され、ステップごとの対数オーバーヘッドが確保されます。 SCC サイズを構築した後、頂点の数を直接計算します。 

2 番目のパスでは、SCC を DAG チェーン内のノードとして扱うことにより、一方向ペアを計算します。 各 SCC は、後続のすべての SCC に直接到達可能性を提供するため、コンポーネント間のペアの数は、プレフィックスとサフィックスのカウントを使用して累積されます。 

微妙な点は、グラフを明示的に構築しないことです。 すべての推論はコンポーネントのサイズのレベルで行われます。 

## 実用的な例

 検討してください\(p = 3\)。 満足できる最大のSCC\(\binom{s}{2} \le 3\)は\(s = 3\)、 以来\(\binom{3}{2} = 3\)。 これはすべてを消費します\(p\)、サイズ 3 の SCC が 1 つ残ります。ノードの合計数は 3 で、SCC が 1 つしかないため、単方向ペアは存在しません。 

| ステップ | p | 選ばれた | 残りの p | SCC サイズ |
 |-----|---|----------|---------------|----------|
 | 1 | 3 | 3 | 0 | [3] |

 ここで考えてみましょう\(p = 4\)。 最大の SCC は、\(s = 3\)、3ペア消費します。 残り\(p = 1\)ということで、次のSCCは\(s = 2\)。 最終的な分解は\([3,2]\)、5つのノードが与えられます。 チェーンの順序付けにより、次のような一方向ペアが生成されます。\(3 \cdot 2 = 6\)、最初の SCC のすべてのノードが 2 番目の SCC のすべてのノードに到達するためです。 

| ステップ | p | 選ばれた | 残りの p | SCC サイズ |
 |-----|---|----------|---------------|----------|
 | 1 | 4 | 3 | 1 | [3] |
 | 2 | 1 | 2 | 0 | [3,2] |

 これは、残った構造がどのように追加のコンポーネントを強制し、コンポーネント間の到達可能性を高めるかを示しています。

 ## 特殊なケース

 のために\(p = 0\)の場合、三角形の寄与は必要ないため、アルゴリズムはサイズ 1 の SCC のみを生成します。 これにより、チェーン状に配置された孤立したノードのグラフが生成され、純粋に順序付けから最大の一方向ペアが生成されます。 

小型用\(p\)のような\(p = 1\)の場合、分解によりサイズ 2 の単一の SCC が作成されます。\(\binom{2}{2} = 1\)。 結果として得られるグラフにはコンポーネント間構造がないため、一方向ペアはゼロのままです。 

大型用\(p\)に近い値など\(2 \cdot 10^5\)、貪欲なステップにより、SCC サイズが急速に増大し、コンポーネントの数が少なくなり、計算における二次関数の爆発が防止されます。
