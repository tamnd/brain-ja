 ## 解決策
 ## 問題の理解

 私たちはモンスターのセットと戦っています。 すべてのモンスターには体力値とパワー値があります。 

ジェノスは攻撃を繰り返す。 現在の攻撃力が`k`、まだ生きているすべてのモンスターが負けます。`k`同時に健康も。 その攻撃の後、私たちは生き残ったモンスターを観察します。 その中で最小の電力値を求めます。 その最小電力はから減算されます`k`、今後のすべての攻撃の強度を低下させます。 

このプロセスはすべてのモンスターが死ぬまで続きます。つまり、答えは次のとおりです。`"YES"`、または、モンスターがまだ生きている間に攻撃力が非正になる場合、つまり答えは`"NO"`。 

入力により複数のテスト ケースが提供されます。 各テストケースについて、初期の攻撃強度がわかっています。`k`、すべてのモンスターの健康状態、およびすべてのモンスターのパワー。 最終的にすべてのモンスターを排除できるかどうかを判断する必要があります。 

制約は、解決策を導く最初のものです。 1 つの健康またはパワーは次のように大きくなります。`10^9`、 そして`k`もできます`10^9`。 すべてのモンスターが死ぬまでに数十億回の攻撃が行われる可能性があるため、攻撃を 1 つずつシミュレートすることは不可能です。 すべてのテスト ケースにわたるモンスターの総数は次のとおりです。`2·10^5`これは、ソリューションに大まかに費やす必要があることを強く示唆しています。`O(n log n)`または`O(n)`テストケースごとに作業します。 

複数のモンスターが同じ攻撃で死亡すると、微妙なエッジケースが発生します。 攻撃後の生きている最弱のモンスターは、攻撃前の最弱のモンスターとはまったく異なる場合があります。 

考慮する：```
n = 2, k = 5
h = [5, 100]
p = [1, 100]
```最初の攻撃の後、最初のモンスターはすぐに死にます。 次の削減には電力を使用する必要があります`100`、力ではありません`1`、生き残った最弱のモンスターが力を持っているからです。`100`。 

もう 1 つの簡単な間違いは、健康値を直接シミュレートすることです。 健康値は次のように大きくなります。`10^9`したがって、すべてのモンスターからダメージを繰り返し減算するのは遅すぎます。 

3 番目のトラップは、モンスターが体力によって処理されるべきであると仮定することです。 パワーの値は、今後の攻撃がどれだけ早く弱まるかを決定するため、体力のみで並べ替えると重要な情報が失われます。 

例えば：```
h = [10, 20]
p = [100, 1]
```パワーの低いモンスターは戦略的に重要です。倒すのが遅いため、高い攻撃力が長時間維持されます。 

## アプローチ

 ブルートフォース シミュレーションでは、攻撃が繰り返し実行されます。 各攻撃中に、生きているすべてのモンスターから現在のダメージを差し引き、どのモンスターが生き残っているかを判断し、それらの中で最小のパワーを見つけて、ダメージを減らします。`k`、続けます。 

これはルールに直接従うため、正しいです。 残念ながら、攻撃の数には制限がありません。`n`。 攻撃力と体力値が到達可能`10^9`、そのため、プロセスには膨大な数の反復が必要になる可能性があります。 たとえそれぞれの攻撃がたっただけだったとしても`O(n)`、合計の作業は完全に実行不可能になります。 

重要な観察は、モンスターが死ぬ瞬間だけが実際に重要であるということです。 

させて`damage`これまでに各モンスターに与えたダメージの合計を表します。 モンスターは一度死ぬ`damage ≥ h_i`。 

現在の蓄積ダメージがわかっているとします。`damage`。 その後、すべてのモンスターが`h_i ≤ damage`すでに死んでいます。 残ったモンスターのうち、最も小さい威力が次の攻撃後の攻撃力の減少量を決定します。 

これはモンスターを健康状態で分類することを示唆しています。 一度分類すると、累積ダメージの合計が増加するにつれて、どのモンスターがすでに死亡したかを効率的に判断できます。 

2 番目の観察は、体力が現在の累積ダメージよりもまだ大きいモンスターの最小パワーのみを知る必要があるということです。 これは、サフィックス最小配列で維持できます。 

健康状態で並べ替えると、次のようになります。```
(h1,p1), (h2,p2), ...
```定義する```
suf[i] = min power among monsters i..n-1
```すべてのモンスターのインデックスが以下の場合`ptr`死んでいれば、生きている中で最も弱いモンスターが力を持つ`suf[ptr]`。 

これでプロセスは非常にコンパクトになりました。 

累計ダメージを維持します`damage`。 

反復ごとに現在の攻撃力が追加されます`k`に`damage`。 

体力が最大になっているすべてのモンスターを過ぎてポインターを進めます。`damage`。 

すべてのモンスターが死んだ場合、答えてください`"YES"`。 

そうでなければ、生き残る力が最も弱いのは、`suf[ptr]`, したがって、減少します`k`その金額で。 

反復回数は最大で`n`、すべての反復で少なくとも 1 つの新しいモンスターを殺すか、`k`非陽性。

 ## アルゴリズムのチュートリアル

 1. 各モンスターの体力とパワーをペアリングします。`(h_i, p_i)`。 
2. モンスターを体力順に並べ替えます。 
3. 接尾辞最小累乗配列を構築します。 あらゆるポジションについて`i`、`suf[i]`モンスターの中で最低限の力を蓄える`i`最後まで。 
4. 初期化します。 

-`damage = 0`-`ptr = 0`5. ながら`k > 0`:

 1. 現在の攻撃力を合計ダメージに加算します。`damage += k`。 
2.移動`ptr`前進しながら`health[ptr] ≤ damage`。 

これらのモンスターはすでに死んでいます。 
3. もし`ptr == n`、すべてのモンスターが死亡しました。 出力`"YES"`。 
4. それ以外の場合、生き残った最も弱いモンスターが力を持つ`suf[ptr]`。 攻撃力を下げる：`k -= suf[ptr]`。 
6. ループが終了した場合`k ≤ 0`一部のモンスターはまだ生きています、出力`"NO"`。 

### なぜ効果があるのか

 数回の攻撃後の累積ダメージは、すべてのモンスターの健康状態から差し引かれた合計値となります。 モンスターは、その健康状態がこの蓄積されたダメージを超えたときにこそ生きています。 

いかなる瞬間においても、将来の攻撃力の減少は、生きているモンスターの最小の力にのみ依存します。 体力で並べ替えた後、体力が小さいモンスターは遅くとも体力が大きいモンスターよりも早く死ぬため、生きているモンスターは常に配列の接尾辞を形成します。 

接尾辞の最小配列は、一定時間内のすべての生きているモンスターの中で最小のパワーを与えます。 すべての反復では、元のプロセスと同じ状態遷移が正確に再現されますが、個々のヘルス値は追跡されません。 シミュレーションは数学的に同一のままであるため、アルゴリズムは元のゲームと同じ結果を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, k = map(int, input().split())
        h = list(map(int, input().split()))
        p = list(map(int, input().split()))

        monsters = sorted(zip(h, p))

        suf = [0] * n
        suf[-1] = monsters[-1][1]

        for i in range(n - 2, -1, -1):
            suf[i] = min(suf[i + 1], monsters[i][1])

        damage = 0
        ptr = 0
        cur_k = k

        while cur_k > 0:
            damage += cur_k

            while ptr < n and monsters[ptr][0] <= damage:
                ptr += 1

            if ptr == n:
                answers.append("YES")
                break

            cur_k -= suf[ptr]
        else:
            answers.append("NO")

    sys.stdout.write("\n".join(answers))

solve()
```ソートステップは、モンスターが消える順序を作成します。 蓄積されたダメージの合計がモンスターの体力に達すると、そのモンスターは永久に死んだことになるため、生きているモンスターは常にソートされた配列のサフィックスを占めます。 

サフィックスの最小配列は重要な最適化です。 これがなければ、反復ごとに、生き残っているすべてのモンスターをスキャンして、最も弱いパワーを見つける必要があります。 それがあれば、最も弱い生存力がすぐに利用可能になります。 

ポインタ`ptr`前に進むだけです。 各モンスターは 1 回スキップされ、合計は`O(n)`テスト ケース全体にわたるポインターの移動。 

使用する`damage`すべてのヘルスを個別に更新するのではなく、次のような大きな値の処理を回避します。`10^9`繰り返し実行し、シミュレーションの効率を維持します。
