 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、および重みの配列。 
2. すべての重量の最小値と最大値を計算します。$w_i$。 これは、選択されたすべてのアイテムが同じ重量を持つ、極端な可能な構成を定義します。 
3. 必要な実現可能条件を確認します:$n$アイテムは間にある必要があります$n \cdot \min(w)$そして$n \cdot \max(w)$。 もし$m$がこの間隔の外にある場合、最も軽いまたは最も重い均一な選択でさえその範囲に到達できないため、答えは直ちに不可能になります。 
4. たとえば、1 つの基準重量を修正します。$w_0 = \min(w)$、すべての差を計算します$d_i = w_i - w_0$。 
5. 最大公約数を計算する$g$ゼロ以外のすべての差の合計。 この値は、選択したアイテムの数を固定したまま合計を変更できる最小ステップをキャプチャします。 
6.次のことを確認します。$m - n \cdot w_0$で割り切れます$g$。 そうでない場合、目標合計は、置換のどの組み合わせによっても到達できない剰余クラス内にあります。 
7. 範囲条件と割り切り条件が両方とも成立する場合は「Yes」を出力し、成立しない場合は「No」を出力します。 

### なぜ効果があるのか

 すべての有効な選択は、すべてが一致するベースラインから開始すると見なすことができます。$n$アイテムには重さがある$w_0$、合計を与える$n w_0$。 他の選択は、これらのベースライン項目の一部を他のタイプに置き換えることによって形成されます。 それぞれの置換は、追加の変化に寄与します。$w_i - w_0$したがって、ベースラインからの合計偏差は、これらの差の整数の組み合わせになります。 

いつも正確にパフォーマンスするから$n$選択すると、合計は、最小または最大の重みのみを選択することによって引き起こされる範囲内に制限されたままになります。 この範囲内で、残る唯一の制限は算術です。達成可能なすべての偏差は、差によって生成される加法サブグループ内にあり、これはちょうど gcd の倍数になります。 これにより、2 つの条件が必要かつ十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        w = list(map(int, input().split()))
        
        mn = min(w)
        mx = max(w)
        
        low = n * mn
        high = n * mx
        
        if m < low or m > high:
            print("No")
            continue
        
        g = 0
        for x in w:
            g = math.gcd(g, x - mn)
        
        if g == 0:
            print("Yes")
        else:
            print("Yes" if (m - low) % g == 0 else "No")

if __name__ == "__main__":
    solve()
```実装は理論構造に直接に従います。 最初のチェックでは、グローバル最小重みと最大重みにピック数を乗算して、不可能なケースを排除します。 2 番目のフェーズでは、最小重みに対するすべての差の gcd を計算します。これにより、特定の参照の選択への依存が回避されます。 

微妙な点は、すべての重みが同一である場合の処理​​です。 この場合、すべての差はゼロになり、gcd はゼロのままになります。つまり、すべての選択の合計が同じになります。$n \cdot w_0$、したがって、と完全に等しいだけです$m$有効です。 

## 実用的な例

 場合を考えてみましょう$n = 5$、重み$[4, 4, 4, 5, 5]$、そしてターゲット$m = 11$。 

私たちは計算します$mn = 5 \cdot 4 = 20$そして$mx = 5 \cdot 5 = 25$、したがって、実行可能な間隔は次のようになります。$[20, 25]$。 以来$11$がこの間隔の外にある場合、アルゴリズムは gcd 構造を計算せずに直ちにそれを拒否します。

 これは、より深い推論が必要になる前に、範囲条件によって不可能なターゲットがどのように排除されるかを示しています。 

ここで考えてみましょう$n = 5$、重み$[0, 1, 2, 3, 4]$、そしてターゲット$m = 10$。 

範囲は$[0, 20]$, それでは次に進みます。 取る$mn = 0$、違いは次のとおりです$[0,1,2,3,4]$そしてgcdは$1$。 間隔内ではすべての整数に到達できるため、10 を含む 0 から 20 までのすべての合計が達成可能です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        w = list(map(int, input().split()))
        mn, mx = min(w), max(w)
        low, high = n * mn, n * mx
        if m < low or m > high:
            out.append("No")
            continue
        g = 0
        for x in w:
            g = gcd(g, x - mn)
        out.append("Yes" if g == 0 or (m - low) % g == 0 else "No")
    return "\n".join(out) + "\n"

# provided sample-like cases

 ## 特殊なケース

 すべての重みが等しい場合、アルゴリズムは最小値と最大値の両方を同じ値として計算します。 範囲チェックは単一点に集約されるため、合計は 1 つだけ可能です。 たとえば、入力の場合$n = 4$、重み$[3,3,3,3]$、 そして$m = 12$、アルゴリズムは間隔を計算します$[12,12]$、この値のみを受け入れ、他のターゲットは正しく拒否します。 

差の gcd がゼロ以外の場合、アルゴリズムは、その gcd 構造に一致する合計のみが受け入れられることを保証します。 たとえば、重みを使用すると、$[1,3,5]$、すべての差は均等であるため、均等な偏差のみが得られます。$n \cdot 1$到達可能です。 このアルゴリズムは、実現可能な範囲内にある場合でも奇数のオフセットを拒否し、達成可能な合計の真の構造と一致します。
