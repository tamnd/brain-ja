 ## 解決策
 ## 問題の理解

 長い括弧文字列が与えられています`s`これは、8 つの括弧記号、4 つの開始タイプ、および対応する終了タイプを使用します。 この文字列から抽出します`m`部分文字列。 各部分文字列は独立したシーケンスとして扱われ、これらの部分文字列の一部をペアにすることができます。 各部分文字列は最大 1 回使用できます。目標は、形成する素のペアの数を最大化することです。 

選択した 2 つの部分文字列を順番に連結し、その結果の文字列が 8 つの括弧タイプすべてに拡張された通常のネスト規則の下で正しい括弧シーケンスになる場合、ペアは有効です。 

したがって、実際の作業は、文字を直接配置することではなく、並べて配置したときにどの部分文字列が相互に「補完」できるかを理解し、互換性のある文字列をできるだけ多くペアにすることです。 

この制約により、テスト ケースごとに線形または線形に近い時間で考えることが求められます。 テスト ケース全体のすべての文字列とクエリの合計長は最大 50 万です。 これにより、すべてのクエリで各部分文字列に 1 文字ずつ触れるものはすべて除外されます。 部分文字列ごとに構造を最初から再計算するソリューションは、部分文字列が大きくて多数の最悪の場合、すぐに制限を超えてしまいます。 

部分文字列が個別に有効であるにもかかわらずペアにできない場合、微妙なエッジ ケースが発生します。 ペアリングは有効性のみではなく、正確な構造の補完に依存するため、単一の有効な部分文字列がパートナーを持つことを保証するものではありません。 たとえば、部分文字列`"()[]{}"`は有効ですが、他の部分文字列が正確に相補的な構造を持たない場合、答えには何も寄与しません。 

別の失敗例は、部分文字列に同じ括弧の複数セットがあるが、ネスト順序が異なる場合に発生します。 例えば、`"([)]"`そして`"(())"`カウントは同じですが、構造的動作は完全に異なります。 カウントを比較するだけの単純なアプローチでは、このようなケースは誤って一致します。 

中心となる問題は、有効性が頻度だけではなく順序に依存するため、キャンセル動作を保持する表現が必要であることです。 

## アプローチ

 最初の試みは、各部分文字列を独立して処理し、部分文字列のすべてのペアについて、それらの連結が有効なシーケンスを形成しているかどうかを確認することです。 各部分文字列について、スタックをシミュレートして処理時にどのように動作するかを確認し、すべてのペアを試してみることができます。 

これは、正しさが直接チェックされるため概念的には機能しますが、非常に遅すぎます。 最大 500,000 個の部分文字列がある場合、表現を保存することさえ問題ありませんが、すべてのペアをチェックするのは二次関数的です。 最悪の場合、チェックの数は 10^11 のオーダーになりますが、これは現実的ではありません。 

重要な点は、実際には部分文字列をペアごとに比較する必要がないということです。 各部分文字列は、一致する括弧のすべての内部キャンセルが実行された後、標準的な「残留構造」に還元できます。 2 つの部分文字列は、括弧の反転の下で一方が他方の正確な補数である場合にのみ、連結されたときに有効なシーケンスを形成できます。 

これにより、問題は、標準的な縮小形式による部分文字列のグループ化と相補的なペアのカウントに変換されます。 各部分文字列が署名にマッピングされると、タスクは一致する頻度をカウントするようになります。 

残りの課題は、この署名を完全にスキャンせずに、すべての部分文字列に対して効率的に計算することです。 

元の文字列に対するセグメント ツリーを使用してこれを解決します。各ノードにはセグメントの縮小されたスタック表現が格納されます。 2 つのセグメントを結合すると、連結がシミュレートされ、左側のセグメントのサフィックスと右側のセグメントのプレフィックスの間でキャンセルが実行されます。 これにより、各クエリ部分文字列を組み合わせた構造として対数時間で取得できるようになり、そこから標準形式を導き出すことができます。

 | 正規署名付きのセグメント ツリー | O((n + m) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列に対するセグメント ツリーを維持します。`s`。 各ノードはセグメントを表し、縮小括弧構造を生のテキストとしてではなく、内部キャンセル後の一致しないシンボルのスタックとして保存します。 

2 つのノードの結合もサポートしています。 左右のセグメントを結合する場合、左側のスタックの読み取りに続いて右側のスタックの読み取りをシミュレートし、左側の構造の上部が右側の構造の前面と一致する場合は常に、一致するブラケットのペアをキャンセルします。 キャンセルは境界を越えてのみ発生するため、内部構造を再処理する必要はありません。 

各クエリ部分文字列について`[l, r]`、セグメントツリーをクエリし、その縮小された形式を再構築します。 

縮小形式を取得したら、それを正規の署名に変換します。 このシグネチャは、連結時に互いに打ち消し合う可能性がある部分文字列の等価クラスを識別するために使用されます。 

また、シーケンスの反転と括弧の方向の反転に対応する「逆署名」も計算します。 この逆は、完全に有効なブラケット シーケンスを形成するための唯一の有効なパートナー タイプを表します。 

すべての部分文字列を処理した後、各署名が出現する回数を数えます。 各署名について、その逆署名と貪欲に組み合わせます。 署名が自己反転の場合、それ自体内でのみペアリングできます。 

### なぜ効果があるのか

 セグメント ツリーは、各部分文字列が最初から処理されたかのように正確に削減されることを保証します。これは、スタックを介して追跡すると、括弧のキャンセルが連結よりも連想的なためです。 重要な不変条件は、保存されたすべての構造がそのセグメントの比類のないフロンティアを正確に表すということです。 2 つのセグメントを連結し、境界相互作用のみを解決すると、フルスタック シミュレーションの正確さが維持されます。 したがって、各クエリから得られた署名はグローバル ブラケット リダクション ルールと一致しており、逆署名によるペアリングは、連結が有効なシーケンスを形成するタイミングを正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

PAIRS = {
    '(': ')',
    ')': '(',
    '[': ']',
    ']': '[',
    '{': '}',
    '}': '{',
    '<': '>',
    '>': '<'
}

OPEN = set("([{<")

def merge(a, b):
    # a and b are stacks representing reduced forms
    # we simulate cancellation between a suffix and b prefix
    res = a[:]
    for ch in b:
        if res and PAIRS[ch] == res[-1]:
            res.pop()
        else:
            res.append(ch)
    return res

def reduce_segment(seg):
    st = []
    for ch in seg:
        if st and PAIRS[ch] == st[-1]:
            st.pop()
        else:
            st.append(ch)
    return tuple(st)

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.s = s
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [tuple() for _ in range(2 * self.size)]
        self.build()

    def build(self):
        for i in range(self.n):
            self.tree[self.size + i] = (self.s[i],)
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = merge(self.tree[2*i], self.tree[2*i+1])

    def query(self, l, r):
        l += self.size
        r += self.size + 1
        left_res = []
        right_res = []
        while l < r:
            if l & 1:
                left_res = merge(left_res, self.tree[l])
                l += 1
            if r & 1:
                r -= 1
                right_res = merge(self.tree[r], right_res)
            l //= 2
            r //= 2
        return tuple(merge(left_res, right_res))

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()

        st = SegTree(s)

        freq = {}

        def invert(seq):
            return tuple(PAIRS[c] for c in reversed(seq))

        for _ in range(m):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            seq = st.query(l, r)
            freq[seq] = freq.get(seq, 0) + 1

        used = set()
        ans = 0

        for k in list(freq.keys()):
            if k in used:
                continue
            inv = invert(k)
            if k == inv:
                ans += freq[k] // 2
            else:
                ans += min(freq.get(k, 0), freq.get(inv, 0))
            used.add(k)
            used.add(inv)

        print(ans)

if __name__ == "__main__":
    solve()
```セグメント ツリーは、すべてのセグメントの圧縮表現を構築します。 各ノードは、その間隔内でキャンセル後に削減されたスタックを保存します。 クエリは、これらのスタックをマージすることにより、関連するセグメントを対数時間で結合します。 

すべてのクエリ結果を収集した後、各縮小シーケンスを頻度マップに変換します。 反転関数は、すべての括弧を逆の順序で閉じるために必要な相補的な構造を構築します。 

最後に、各署名とその逆署名を貪欲に照合し、完全なペアがいくつ形成できるかを数えます。

 ## 特殊なケース

 最初のエッジ ケースは、すべての部分文字列がすでに有効であるものの、孤立している場合です。 それぞれが個別に有効条件を満たしたとしても、相補的な構造がないため、ペアリングはできません。 有効なシーケンスは空の署名または自己反転署名に変換され、重複が存在しない限り空の署名はペアにできないため、アルゴリズムはこれを処理します。 

別のエッジ ケースは、部分文字列が同一の縮小形式を持っているが、奇数の数で出現する場合に発生します。 その状況では、フロアを 2 で割ったものだけが答えに寄与し、周波数ベースのペアリングでは当然 1 つは未使用のままになります。 

最後のエッジ ケースは、括弧の反転の下で部分文字列が自己反転される場合です。 これらは内部でのみペアにすることができ、アルゴリズムは署名とその反転の間の等価性チェックを使用して、それらを正しく別々に処理します。
