 ## 解決策
 ## 問題の理解

 2 つの正の整数が与えられます。1 つは小さい値 (最大 5000)、もう 1 つは潜在的に非常に大きい値 (最大 10^18) です。 1 回の操作で、数値の 1 つを選択し、そこから現在のペアの最大公約数を引きます。 gcd は常に現在の値に基づいて計算されるため、数値の変化に応じて変化します。 

このプロセスは両方の数値がゼロになるまで続き、タスクは移動数を最小限に抑えることです。 

重要な問題は、gcd が 2 つの値を結び付けることです。 1 つの数値が非常に大きくなる場合でも、gcd は常に小さい数値によって制限されるため、実際のダイナミクスは小さい値によって制御されます。 これは、b の大きな境界がボトルネックではないことをすぐに示唆しています。 ボトルネックは、5000 以下の数を伴う状態の進化です。 

1 つの数値がゼロになると、微妙なケースが発生します。 b がまだ正のときに a がゼロになると、gcd は b になり、b をゼロに減らすことで 1 回の操作でプロセスを即座に終了できます。 このような場合、この最後の遷移を無視する解は 1 つずれます。 たとえば、(1, 10) から開始すると、両側で減算を繰り返す必要があると誤って考えるかもしれませんが、1 つの座標がゼロに達すると、残りの座標は 1 ステップで崩壊します。 

もう 1 つの重要なエッジは、gcd が a の現在の値と等しくなるときです。 これは 2 番目の数値が a の倍数である場合に発生します。その状況では、操作はその座標を即時にリセットするかのように動作し、状態グラフの構造を大幅に変更します。 

## アプローチ

 直接シミュレーションでは、プロセスを段階的に模倣します。 状態 (a, b) から g = gcd(a, b) を計算し、a から g を引くか、b から g を引くかの 2 つの可能性に分岐します。 これは正しいですが、値はさまざまな方法で変化し、b が巨大であるため、非常に遅くなります。 

重要な観察は、gcd(a, b) = gcd(a, b mod a) であるため、gcd は a と b の法 a にのみ依存するということです。 これは、b が巨大であるにもかかわらず、プロセスに関連するすべての情報が a を法とする剰余に含まれていることを意味します。 a が 5000 を超えることはないため、状態空間は、r = b mod a のペア (a, r) に崩壊します。 

ここで、このプロセスはグラフ問題になります。 状態 (a, r) から、g = gcd(a, r) とします。 遷移は 2 つあります。 r を変更せずに a を a − g に縮小することもできます。または b を縮小することもできます。これは、r を a を法として r − g に縮小することに相当します。これは、g が r を除算するため、単なる r − g になります。 

これにより、最大約 5000 × 5000 の状態にわたる有向グラフが生成されます。 重要なのは、一方のタイプの動きでは a が厳密に減少し、もう一方のタイプでは r が減少するため、すべての遷移は構造化された方法でより小さい値に向かって移動することです。 最短パスは、これらの状態にわたる BFS またはダイクストラのような走査を使用して計算できます。 

ブルートフォースのアイデアは、到達可能なすべての状態を探索しますが、各状態は繰り返し分岐する可能性があり、b には制限がないため、爆発します。 縮小された状態表現は、最短経路技術が直接適用される有限グラフに変わります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. r = b mod a を計算します。これにより、a と b の間のすべての gcd 相互作用が完全に決定されます。 
2. 各状態をペア (a, r) として扱います。ここで、r は常に現在の a を法として維持されます。 この不変式は、すべての演算が現在の gcd で割り切れる値を減算するため、それ自体が a を除算するため成り立ちます。 
3. 初期状態 (a、r) から開始し、複数の状態にわたって最短経路探索を実行します。 各状態は、移動前の構成を表します。 
4. 状態 (a, r) から g = gcd(a, r) を計算します。 これは、この状態で可能な唯一の gcd 値です。 
5. a を減らすことを選択した場合は、(a − g, r) に進みます。 これは、b の残りの構造を変更せずに a の一部を消費することを反映しています。 
6. b を減らすことを選択した場合は、(a, r − g) に進みます。 これは、a を固定したまま、a を法とした b の余​​りが減少することを反映しています。 
7. a = 0 および r = 0 の状態に到達すると、常に停止します。 これは、両方の元の数値が同時にゼロになることに対応します。 
8. 特別な終了遷移がグラフに暗黙的に含まれています。r = 0 の場合、g = a となるため、a を減らすと 1 回の操作で (0, 0) に直接つながります。 

正確さは、すべての有効な操作シーケンスがこの状態グラフ内のパスに正確に対応し、グラフ内のすべてのエッジが有効な操作に対応するという事実から得られます。 すべての移動のコストは等しいため、BFS は最小限の移動数を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque
from math import gcd

def solve():
    T = int(input())
    for _ in range(T):
        a, b = map(int, input().split())
        r0 = b % a

        start = (a, r0)
        dist = {(a, r0): 0}
        dq = deque([start])

        while dq:
            a_cur, r = dq.popleft()
            d = dist[(a_cur, r)]

            if a_cur == 0 and r == 0:
                print(d)
                break

            if a_cur == 0:
                continue

            g = gcd(a_cur, r)

            na = a_cur - g
            state1 = (na, r)
            if state1 not in dist:
                dist[state1] = d + 1
                dq.append(state1)

            nr = r - g
            state2 = (a_cur, nr)
            if state2 not in dist:
                dist[state2] = d + 1
                dq.append(state2)

        else:
            print(0)

if __name__ == "__main__":
    solve()
```この実装は状態グラフを直接ミラーリングします。 辞書`dist`各状態に到達するための最小操作数を保存します。 BFS キューは、ステップの昇順で、到達可能なすべての構成を探索します。 

微妙な点は、r が常に a を法とした正確な剰余として維持されることです。 r から g を減算する場合、g は常に r を除算するため、明示的なモジュロは必要ありません。したがって、結果は範囲内に収まります。 これにより、不必要な正規化のオーバーヘッドが防止されます。 

終了条件には (0, 0) が含まれます。これは、両方の元の値が完全に削減されることに対応します。 BFS は自然に、この吸収状態への最短経路を見つけます。 

## 実用的な例

 入力 (4, 20) を考えてみましょう。 最初は r = 20 mod 4 = 0 です。 

| ステップ | 状態 (a, r) | gcd(a, r) | 次の州 |
 | --- | --- | --- | --- |
 | 0 | (4,0) | 4 | (0, 0) |
 | 1 | (0, 0) | - | 停止 |

 これは、2 番目の数値が最初の数値の倍数である場合に即座に崩壊することを示しています。 アルゴリズムはこれを 1 回の動作で取得します。 

次に (3, 4) を考えてみましょう。 ここで、最初は r = 1 です。 

| ステップ | 状態 (a, r) | gcd(a, r) | アクション |
 | --- | --- | --- | --- |
 | 0 | (3,1) | 1 | (2, 1) または (3, 0) に移動します |
 | 1 | (3,0) | 3 | (0, 0) へ |

 このトレースは、r がゼロになったときに大きな gcd のロックが解除されるため、最初に r を減らす方が効率的であることを示しています。 

2 番目の例は、a でより大きなジャンプを可能にするために、剰余を制御することがどのように重要であるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑ a²) | 各状態 (a、r) は最大 1 回訪問され、r の範囲は最大 a | です。 
| スペース | O(∑ a²) | 距離マップには訪問したすべての州が保存されます。 

すべてのテスト ケースの合計は最大 10^4 であるため、状態の総数は最悪の場合でも約 5 × 10^7 に制限されますが、実際には、状態の急速な収束と gcd 遷移の構造により、状態の総数ははるかに小さくなります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque
    from math import gcd

    def solve():
        T = int(sys.stdin.readline())
        out = []
        for _ in range(T):
            a, b = map(int, sys.stdin.readline().split())
            r0 = b % a

            start = (a, r0)
            dist = {start: 0}
            dq = deque([start])

            while dq:
                a_cur, r = dq.popleft()
                d = dist[(a_cur, r)]

                if a_cur == 0 and r == 0:
                    out.append(str(d))
                    break

                if a_cur == 0:
                    continue

                s1 = (na, r)
                if s1 not in dist:
                    dist[s1] = d + 1
                    dq.append(s1)

                nr = r - g
                s2 = (a_cur, nr)
                if s2 not in dist:
                    dist[s2] = d + 1
                    dq.append(s2)
            else:
                out.append("0")

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 b が a の倍数の場合、最初の剰余は 0 であり、アルゴリズムは 1 回の演算で両方の数値を 0 に減らす状態にすぐに到達します。 gcd(a, 0) は a と等しいため、(a, 0) から (0, 0) への遷移は明示的にキャプチャされます。 

a がすでに 1 の場合、すべての gcd は 1 になるため、プロセスは線形ウォークに退化します。 すべての遷移で a または r のいずれかが 1 だけ減少し、特殊な場合を使用せずに確実に収束するため、状態グラフはこれを引き続き正しく処理します。 

いくつかのステップを経て r が 0 になると、アルゴリズムは gcd が最大になるという事実を利用し、a の残りの値を 1 回の動作で縮小します。 これにより、不必要な長いチェーンが防止され、このステップを遅らせるパスが短いパスによって正しく支配されることが保証されます。
