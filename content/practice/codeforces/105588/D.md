 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには、人形のサイズを表す整数が並べて並べられています。 各位置には最初は正確に 1 つの人形が含まれており、すべてのサイズが異なります。 

許可される操作は、2 つの隣接する位置を取得し、それらを 1 つの位置にマージすることです。 マージ後の位置には、両方の元の位置のすべての人形が含まれるため、その値の範囲は、マージされた 2 つのセグメントの最小値と最大値になります。 マージは、2 つの隣接するセグメントの値が完全に分離されている場合にのみ許可されます。つまり、左側のセグメントのすべての値が右側のセグメントのすべての値より厳密に小さいか、右側のセグメントのすべての値より厳密に大きいかのいずれかです。 

このプロセスが繰り返され、結合するたびに配列が 1 セグメントずつ縮小します。 マージの数を最大化したいと考えています。これは、移動が不可能になるまで、有効な隣接マージの可能な限り長いシーケンスを見つけることと同じです。 

この制約は、一般的な競技プログラミングの意味で厳しく、すべてのテスト ケースにわたる要素の総数は最大 100,000 です。これにより、考えられるすべてのマージ順序を試行したり、すべてのセグメンテーションにわたって動的プログラミング状態を維持したりするシミュレーションは直ちに除外されます。 テスト ケースごとの 3 次または 2 次のプロセスはタイムアウトになるため、ソリューションは全体として線形または線形演算に近くなければなりません。 

マージによって隣接関係が変更され、セグメント範囲も変更されるという事実から、微妙な困難が生じます。 早期のマージが将来の有効なマージをブロックする可能性があるため、可能な限りマージするという単純な貪欲な選択は失敗する可能性があります。 

たとえば、次のような小さな配置を考えてみましょう。`[2, 1, 4, 3]`。 貪欲に融合すれば`(2,1)`まずセグメントを作成します`[1,2]`。 これにより、次のものとのマージが可能になります`[4]`、そして、`[3]`、フルチェーンを達成します。 しかし、少し異なる配置では、早期のマージによって将来の境界を越える条件が破壊され、マージの合計が減少する可能性があります。 これは、マージを独立して扱うことができないことを示しています。 グローバルな構造が必要です。 

もう 1 つの失敗ケースは、マージの機会が複数存在するものの、最適なチェーンにつながるのは一部のみである場合です。 たとえば、`[3,1,4,2]`、結合`(1,4)`1 つ目は、範囲だけを考慮した場合、局所的には魅力的に見えるかもしれませんが、不可能です。 合法性は、隣接性とグローバル セグメントの極値に厳密に依存します。 

したがって、中心的な課題は、完全なマージ プロセスをシミュレートせずに、各ステップでセグメントが「値で分離」されたままになる隣接マージの最大数をカウントする必要があるということです。 

## アプローチ

 ブルートフォース解釈では、考えられるすべてのマージ シーケンスをシミュレートします。 各ステップで、隣接するセグメントのペアをすべてチェックし、それらの値の範囲が互いに素であるかどうかを検証し、マージの決定とマージしない決定の両方を再帰的に試行します。 各状態は配列のパーティションであり、そのようなパーティションは指数関数的に多く存在します。 各操作の後にすべての可能なマージを再計算する貪欲なシミュレーションでも、マージごとにサイズが 1 ずつ削減されますが、各ステップでスキャン隣接関係の制約が必要になるため、最悪の場合、テスト ケースごとに O(n²) のコストがかかります。 

重要な点は、このプロセスは任意のマージ順序を選択することではなく、最適な順序でマージできる隣接ペアの数を数えることであるということです。 条件`ri < li+1 or ri+1 < li`これは、2 つのセグメントの値の間隔が重ならない場合に正確にマージできることを意味します。 すべての値は異なるため、これは、あるセグメントの最大値が他のセグメントの最小値よりも小さいと言うのと同じです。 

これは、単調な構造を直ちに示唆します。セグメントをマージするたびに、内部順序はもはや重要ではなく、最小値と最大値のみが重要となる、より大きな間隔を効果的に構築することになります。 重要な特性は、2 つの隣接するセグメントをマージできる場合、一方のすべての値が順列順序において他方の一方の側に完全に位置することです。 

これにより、問題は、重複しない値の間隔への分割を維持しながら、隣接する「境界」の数を数えることに変換されます。 マージごとにセグメントの数が 1 つずつ減ります。そのため、答えは削除可能な境界の最大数になります。 

重要な洞察は、アクティブなセグメントの構造を維持しながら順列を処理でき、最後の 2 つのセグメントが値の順序によって「分離可能」になるたびに貪欲にマージできることです。 すべての値は個別であるため、スタックのような構造を使用して現在のセグメントの境界を追跡できます。各新しい要素は、新しいセグメントを開始するか、前のセグメントの範囲と現在の要素の間で厳密な順序付け条件が維持されている場合は後方にマージします。 

これは、セグメント範囲のスタックを維持するリニア スキャン ソリューションにつながります。 新しい要素を追加するたびに、分離条件が維持される限り、その要素を後方へマージしようとします。 成功したすべてのマージは、最終的な答えの 1 つの操作に対応します。 

この左から右への貪欲なマージは、2 つの隣接するセグメントがマージ可能になると機能します。マージを遅らせても将来の可能性が高まることはありません。マージは範囲を拡張するだけであり、単調な順序付けの制約が局所的に保持されるためです。

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、各要素が現在のマージされたセグメントを表すスタックを維持し、その最小値と最大値として保存します。 

1. 空のスタックから開始します。 新しい各要素は最初にセグメントを形成します。`min = max = value`。 これは、マージが考慮される前の状態を表します。 
2. 配列を左から右に繰り返します。 新しい値ごとに、新しいセグメントを作成し、スタックにプッシュします。 
3. 新しいセグメントをプッシュした後、スタック上の前のセグメントとのマージを試みます。 間隔が互いに素である場合、つまり一方の最大値が他方の最小値よりも厳密に小さい場合、マージは有効です。 
4. If the top two segments can be merged, remove them and replace them with a single merged segment whose minimum is the smaller min and whose maximum is the larger max. このようなマージごとに、答えは 1 つずつ増えます。 
5. マージにより以前のセグメントとの新しい有効な隣接関係が作成される可能性があるため、スタックの新しい最上位とのマージを続行します。 
6. 現在の位置でマージができなくなるまで繰り返し、アレイのスキャンを続けます。 
7. すべての要素を処理した後、マージの累積数が答えとなります。 

この貪欲なプロセスが安全である理由は、すべてのマージがローカルであり、構造的に元に戻せないためです。 2 つのセグメントがマージされると、それらの内部順序は 1 つの間隔に固定され、その後の操作ではそれらを再度分割することはできません。 したがって、マージを遅らせる必要があるかどうかではなく、マージがすぐに可能になる時期だけを決定する必要があります。 

### なぜ効果があるのか

 このアルゴリズムは、配列の現在のセグメント化を表す、素の値間隔のスタックを維持します。 各間隔は元の順序で連続したブロックに対応し、これらの間隔は値空間内で常に互いに素です。 

どの時点でも、スタックの最上位は右端のセグメントを表します。 A merge is possible exactly when this segment and the previous one have non-overlapping value ranges, which is both necessary and sufficient for validity. Because merging only enlarges intervals without creating overlaps that were not already implied by adjacency, any merge that can happen at a given point can be performed without reducing the total number of merges achievable later. これにより、各マージがローカルで有効になったときに 1 回だけカウントされる、貪欲に最適な構造が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        stack = []  # each element is (min_val, max_val)
        ans = 0

        for x in a:
            stack.append((x, x))

            while len(stack) >= 2:
                mn2, mx2 = stack[-1]
                mn1, mx1 = stack[-2]

                # check if two segments are separable
                if mx1 < mn2 or mx2 < mn1:
                    # merge them
                    stack.pop()
                    stack.pop()
                    new_mn = min(mn1, mn2)
                    new_mx = max(mx1, mx2)
                    stack.append((new_mn, new_mx))
                    ans += 1
                else:
                    break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを読み取り、セグメント間隔のスタックを維持します。 各要素は独自のセグメントとして始まります。 挿入後、上部 2 つのセグメントを繰り返しチェックします。 値の範囲が互いに素である場合はマージできるため、それらを結合区間に置き換えて、答えをインクリメントします。 

微妙な点は、上位 2 つのセグメントのみを比較していることです。 This is sufficient because any merge affects only adjacent segments, and any new merge opportunity must involve the most recently modified boundary.

 ## 特殊なケース

 重要なエッジ ケースは、配列がすでに単調増加または単調減少している場合です。 このような場合、隣接する 2 つのセグメントが厳密な分離条件を満たすことはなく、スタックがマージをトリガーすることはありません。 このアルゴリズムは、各要素を最後まで独自のセグメントとして適切に残し、マージを生成しません。 

もう 1 つのケースは、いくつかの中間要素が追加された後でのみマージが可能になる場合です。 たとえば、`[1, 3, 5, 2, 4]`、初期のセグメントはマージできませんが、挿入`2`複数のマージが可能になるように、右側の間隔を再形成します。 このアルゴリズムは、現在のスタックの最上位に基づいてマージのみを決定し、すべての再構築が将来の比較に即座に反映されるため、これを処理し、遅れた機会を逃さないようにします。
