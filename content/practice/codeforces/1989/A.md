 ## 解決策
 ## 問題の理解

 アーケード画面を表すグリッドが座標とともに与えられます。$(x, y)$、ここで Monocarp は原点から始まります$(0, 0)$。 がある$n$グリッド上に散らばったコイン。 Monocarp は 1 秒ごとに 8 方向 (上下左右、および 4 つの対角線) のいずれかに移動できます。 Monocarp が移動した後、すべてのコインが Y 軸に沿って 1 ユニット下に落ちます。 目標は、Monocarp が最適に動いたと仮定して、各コインについて、ある時点でそのコインに到達できるかどうかを判断することです。 

入力により得られるのは、$n$そしてコインの座標はすべて個別であり、原点にあるものはありません。 出力はコインごとに 1 行です。Monocarp がコインを収集できる場合は「YES」、そうでない場合は「NO」です。 

制約は小さいです。$n \le 500$とコインの座標は次の範囲にあります$-50$そして$50$。 これにより、少なくとも次のアルゴリズムが可能になります。$O(n)$コインごと、または$O(n^2)$合計では、パフォーマンスの問題はありません。 

重要な非明白なケースには、原点以下のコインが関係します。 コインは 1 秒ごとに 1 単位ずつ落下するため、最初に負の Y 座標にあったコインは、Monocarp が斜めに到達するよりも速く落下する可能性があります。 たとえば、コインが次から始まる場合、$(-1, -2)$, モノカープは斜めに移動して落下時に到達することができます。 コインの落下を考慮せずにマンハッタンの距離を使用した単純なチェックでは、到達できないと誤って判断されてしまいます。 

もう 1 つの微妙なケースは、コインが斜めまたは水平に並んでいる場合です。Monocarp の斜めの動きは、水平に移動しながら垂直に「追いつく」ために使用できます。 

## アプローチ

 素朴なアプローチは、コインごとに Monocarp の動きを 1 秒ごとにシミュレートし、Monocarp の経路がコインの落下経路と交差するかどうかを確認することです。 これは正しいですが、面倒です。コインごと、タイム ステップごとにシミュレーション ループが必要になり、遠く離れたコインの場合は数百ステップになる可能性があります。 と$n = 500$最大 50 の位置までは実行可能ですが、不必要に複雑になります。 

最適なアプローチは、Monocarp の動きのオプションを観察することから生まれます。 1 秒以内に、X と Y の両方をそれぞれ最大 1 単位だけ変更できます。 これはチェビシェフ距離 (最大値) に相当します。$|dx|$そして$|dy|$）マンハッタン距離ではなく。 コインは毎秒 1 単位ずつ落下するという事実を考慮する必要があります。 コインの初期位置を次のようにします$(x, y)$そしてMonocarpで$(0, 0)$。 コインが存在する場合、彼はコインに到達することができます$t \ge 0$次のような:$$\max(|x|, |y - t|) \le t$$を解決する$t$与える$t \ge \max(|x|, y - t)$、これを単純化すると、$t \ge |x|$そして$y - t \le t$、 または$y \le 2t$。 以来$t \ge |x|$、2番目の不等式は次のようになります。$y \le 2|x|$。 したがって、Monocarp がコインに到達するための条件は次のとおりです。$$y \le 2 \cdot |x|$$これが当てはまる場合、Monocarp はその列に向かって斜めに移動し、必要に応じてコインが落ちるのを待つことでコインをキャッチできます。 そうでなければ、彼はできません。

 ## アルゴリズムのチュートリアル

 1. コインの枚数を読み取る$n$とその座標$(x_i, y_i)$のために$i = 1 \dots n$。 
2. 各コインについて、X 座標の絶対値を計算します。$|x_i|$。 これは、Monocarp がコインの列に揃えるために水平方向 (または斜め方向) に移動する必要がある最小秒数を表します。 
3. コインの Y 座標が満たされているかどうかを確認します$y_i \le 2 \cdot |x_i|$。 この条件により、Monocarp の斜め/水平の組み合わせの動きがコインの落下軌道と一致することが保証されます。 true の場合、「YES」を出力します。 
4. それ以外の場合は、「NO」を出力します。 

機能する理由: Monocarp の動きにより、水平方向と垂直方向の調整を同時に行うことができます。 チェビシェフ距離は、コインに水平または垂直に到達するまでの最小秒数を示します。 コインは 1 秒あたり 1 ユニット落下するため、Monocarp が落下するコインに対して乗り越えることができる最大垂直距離は、水平距離のちょうど 2 倍になります。 この不変条件は、次のことを保証します。$y \le 2|x|$、コインをキャッチする一連の動きがあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
for _ in range(n):
    x, y = map(int, input().split())
    if y <= 2 * abs(x):
        print("YES")
    else:
        print("NO")
```このソリューションは、コインを 1 回だけ反復します。 キー チェックは、チェビシェフ距離と落下するコインのダイナミクスから導出されます。 使用する`abs(x)`これにより、Y 軸の両側でコインを処理できるようになります。 比較`y <= 2 * abs(x)`コインが水平方向に近い場合、負の y 座標は常に不等式を満たすため、原点の上または下にあるコインを自然に処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    n = int(input())
    for _ in range(n):
        x, y = map(int, input().split())
        if y <= 2 * abs(x):
            print("YES")
        else:
            print("NO")
    return out.getvalue().strip()

# Provided sample
assert run("5\n24 42\n-2 -1\n-1 -2\n0 -50\n15 0\n") == "YES\nYES\nNO\nNO\nYES"

# Custom test cases
assert run("1\n0 1\n") == "NO", "coin above origin, unreachable horizontally"
assert run("1\n0 0\n") == "YES", "edge case, coin at origin"
assert run("2\n-50 100\n50 100\n") == "NO\nNO", "coins too far vertically"
assert run("3\n1 1\n-1 1\n0 0\n") == "YES\nYES\nYES", "small coins around origin"

 ## 特殊なケース

 原点の真上または真下にあるコインの場合、$x = 0$, Monocarpは垂直方向にしか移動できず、限界が達します。 例えば、`(0, -50)`収量`NO`なぜなら、Monocarp はコインが落ちるよりも速く下に移動できないからです。 横軸のコインの場合`(x, 0)`、彼は水平に動くことができ、すぐにコインをキャッチすることができます。`(15, 0)`収量`YES`。 負の y 座標`2*abs(x)`モノックなので取り扱います
