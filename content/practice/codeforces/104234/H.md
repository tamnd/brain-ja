 ## 解決策
 ## 問題の理解

 無向の単純なグラフが与えられています。$n$頂点。 このグラフから、考えられるあらゆる方法で頂点を再ラベルすることによって取得できるすべてのグラフを概念的に生成します。 異なるエッジ セットを生成する 2 つの再ラベル付けは、異なるグラフとしてカウントされます。 

問題はそれらを列挙することではなく、指定されたグラフと同型である別個のラベル付きグラフの数が最大でも 1 つであるかどうかを判断することです。$n$。 言い換えれば、頂点ラベルのすべての順列を取得し、それらをグラフに適用し、結果として得られる同一のエッジ セットの重複を除去し、表示される一意のグラフの数をカウントします。 このカウントが次の制限を受けるかどうかを判断する必要があります。$n$。 

制約は大きく、すべてのテスト ケースにわたる頂点とエッジの総数は最大$10^5$。 これにより、明示的な置換推論やグラフの正規ラベル付けを含むものは即座に除外されます。 階乗成長、ブルートフォース自己同型検査、または順列ごとのグラフ同型検査に依存するアプローチは、時間制限内では不可能です。 

重要な問題は、求められる量がグラフの自己同型群に依存することです。 2 つの順列は、自己同型によって異なる場合に、まったく同じラベル付きグラフを生成します。 したがって、次と同型の個別のグラフの数は、$G$等しい$n! / |\mathrm{Aut}(G)|$。 したがって、このタスクは、この値が最大かどうかを確認することと同じです。$n$しかし、自己同型群のサイズを直接計算することは、実現可能性をはるかに超えています。 

微妙な問題が小さなグラフに現れます。 のために$n=1$そして$n=2$、ほとんどすべての構造は、ごく少数の個別のラベル付きグラフに簡単に崩壊するため、「多数の順列」についての素朴な直感は誤解を招く可能性があります。 たとえば、次のようなとき$n=2$、空のグラフとシングルエッジ グラフの両方は、たとえ$2!$順列。 

## アプローチ

 直接的なアプローチでは、頂点のすべての順列を理解し、それらが生成するグラフによってグループ化しようとします。 概念的には、順列ごとにグラフのラベルを付け直し、結果​​のエッジ セットをハッシュ セットに挿入します。 これは正しいですが、まったく実行不可能です。 がある$n!$順列、および再ラベル付けされたグラフを 1 つ生成する場合でもコストがかかります$O(n + m)$。 これはたとえであってもすぐに爆発します$n = 20$。 

重要な観察は、同型クラス内の個別のラベル付きグラフの数が対称性によって完全に決定されるということです。 対称性の高いグラフでは、多くの順列がエッジ構造を変更しないため、明確な再ラベル付けが少なくなります。 

この数値は最大でも次の値にしたいと考えています$n$に比べて非常に小さいです。$n!$。 そのため、自己同型群は非常に大きくなります。 実は減らす唯一の方法は$n! / |\mathrm{Aut}(G)|$まで$O(n)$のためのものです$|\mathrm{Aut}(G)|$の順序になる$(n-1)!$それ以上の場合、ほぼすべての順列が自己同型であることを意味します。 

このレベルの対称性は、すべての頂点が可能な限り最も強い意味で構造的に同一であるグラフでのみ可能です。 単純な無向グラフでは、これは空のグラフと完全なグラフの 2 つの場合にのみ発生します。 どちらの場合も、頂点のすべての置換によって隣接性が維持されるため、$|\mathrm{Aut}(G)| = n!$したがって、個別のラベル付きグラフの数は正確に$1$、これは条件を自明に満たします。 

他のグラフは対称性を破ります。 異なる次数または異なる隣接パターンを持つ頂点のペアが存在する瞬間、それらを分離する順列は自己同型ではなくなり、自己同型群は劇的に縮小します。 これにより、軌道サイズがはるかに大きくなります$n$, したがって、答えはNOになります。 

したがって、問題は単純な構造チェック、つまりグラフが空か完全かを判断することになります。

 | 順列に対するブルートフォース |$O(n! \cdot (n+m))$|$O(n+m)$| 遅すぎる |
 | 構造チェック (空または完全) |$O(n+m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、グラフにゼロのエッジがあるか、またはすべての可能なエッジがあるかをチェックすることに集約します。 

1. 頂点数を読み取る$n$そしてエッジ$m$、すべてのエッジを読み取ります。 
2. 単純な無向グラフ内の可能なエッジの総数を計算します。$n(n-1)/2$。 
3. もし$m = 0$、グラフは空です。つまり、すべての順列がグラフを保存するため、条件を満たします。 
4. もし$m = n(n-1)/2$、グラフは完全です。つまり、すべての順列がグラフを保存するため、条件も満たします。 
5. それ以外の場合、グラフは完全に対称でも最大接続でもないため、NO を出力します。 

これが機能する理由は、空の完全なグラフのみが完全な頂点対称性を持つためです。 これらの構造から逸脱すると、次数が他の頂点と異なるか、隣接パターンが異なる頂点が少なくとも 1 つ導入され、完全な対称性が崩れます。 これにより、自己同型グループのサイズが直ちに減少し、別個の再ラベル付けされたグラフの数が許容しきい値を超えて増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        for _ in range(m):
            input()
        max_edges = n * (n - 1) // 2
        if m == 0 or m == max_edges:
            out.append("YES")
        else:
            out.append("NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、エッジをカウントする以上に実際のエッジ構造を無視することに依存しています。 カウントのみが重要であるため、各テスト ケースはエッジ リストを保存せずに消費します。 

の計算$n(n-1)/2$整数演算を使用する必要があり、すべてを読み取るように注意してください。$m$エッジを使用して入力解析を整列させます。

 ## 特殊なケース

 空のグラフの場合は、完全な対称性の最も直接的な例です。 頂点の各置換はエッジの不在を維持するため、すべての頂点が置換されます。$n!$再ラベル付けは単一の別個のグラフに折りたたまれます。 アルゴリズムはチェックすることでこれを処理します。$m = 0$、すぐに YES がトリガーされます。 

完全なグラフの場合は、対称性の観点からは同じように動作します。 すべての頂点のペアは接続されているため、再ラベル付けによって隣接関係を変更することはできません。 アルゴリズムはこれを次のように検出します。$m = n(n-1)/2$。 

中間のグラフの場合、エッジが 1 つでも欠けているか余分なエッジがあると、頂点の完全な互換性が失われます。 たとえば、ある頂点の次数が別の頂点と異なる場合、頂点を交換するとグラフ構造が変化するため、多くの順列は自己同型群に属さなくなります。 これにより、個別のラベル付きグラフの数がはるかに多くなることが保証されます。$n$これが、極端でないすべてのケースでアルゴリズムが安全に NO を出力する理由です。
