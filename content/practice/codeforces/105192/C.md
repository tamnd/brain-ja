 ## 解決策
 ## 問題の理解

 このプロセスでは、ダメージ値がターンごとに独立していないターンベースのダメージ システムについて説明します。 各ターンは現在のダメージ数値から始まります`y`の場合、ボスの味方は常に固定の XOR 変換を適用します。`a`、オプションで別の XOR 変換を適用することもできます`b`。 これらの変換の後、結果の数値がそのターンに与えられるダメージとして使用され、次のターンの開始値になります。 

目標は、累積ダメージがどれくらい早く目標に達するか、目標を超えるかを判断することです。`x`。 唯一制御できるのは、XOR を適用するかどうかです。`b`各ターン、友達が既に XOR を適用した後`a`。 

重要な難点は、XOR がターンをまたがって繰り返し適用されるため、現在のダメージは現在のターンだけでなく選択履歴全体に依存することです。 

制約により、最大で`2 · 10^5`テスト ケース、最大値`10^9`。 これにより、テスト ケースごとに定数または対数以上の作業を行うシミュレーションが除外されます。 すべてのテストにわたる合計操作数が数百万であっても許容されますが、直線的なものはすべて許容されます。`x`あるいは長いターンの連続では不可能です。 

素朴な解釈では、合計が次の値に達するまでターンごとにシミュレーションすることになります。`x`。 損傷が長期間にわたって小さいままであれば、最悪の場合、プロセスに非常に多くのステップが必要になる可能性があるため、このことはすでに懸念を引き起こしています。 もう 1 つの単純なアイデアは、XOR 履歴が将来の状態にどのような影響を与えるかを考えずに、各ターンを独立して扱い、現在のダメージを貪欲に最大化することです。 それは選択した場合に壊れます`b`内部状態を永続的に変更することで、将来のダメージを軽減するようになりました。 

XOR 演算によってダメージ シーケンスに小さなサイクルが作成されると、微妙なエッジ ケースが発生します。 たとえば、次の場合`y = 1, a = 1, b = 1`、選択に応じて、ダメージは値の間で変動する可能性があり、初期の異なる選択が後で一貫してより高い値につながる場合でも、貪欲な決定により弱いサイクルに閉じ込められる可能性があります。 状態の進化を注意深く理解していないと、まさにここで「局所的に最適な」決定が失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのターンをシミュレートし、各ステップで両方の可能性を試すことです。`b`か否か。 これにより、時間の経過とともにバイナリ決定木が形成されます。 各ノードは現在のダメージ値によって定義された状態を表し、各エッジは 2 つの可能な遷移のうちの 1 つを表します。 

これは、すべての有効な一連の決定を探索するため、概念的に機能し、ターゲットに到達する最小ターン数を常に見つけます。 ただし、分岐係数はステップごとに 2 であるため、`n`ターンがあります`2^n`州。 控えめでも`n`、これはすぐに実行不可能になります。 

重要な観察は、状態の進化は XOR 演算の完全な履歴には依存せず、2 つのパリティ情報のみに依存するということです。 との繰り返しXOR`a`経過したターン数にのみ依存し、`b`それを適用することを選択した回数にのみ依存します。 どちらもパリティ駆動のエフェクトです。 これにより、システムは無制限の履歴ではなく、一定数の状態に崩壊します。 

システムが小さなステート マシンに縮小されると、プロセスは固定された選択ルールに基づいて決定的になります。 最適な戦略は、各状態で、当面のダメージ値を最大化する遷移を選択することになります。これは、将来の動作はすべて、結果として生じる状態のみに依存し、より深い履歴には依存しないためです。 

これにより、問題が指数関数的な探索から一定サイズの状態空間にわたる線形シミュレーションに変わります。

 | 状態削減 + 貪欲なシミュレーション | テストごとの O(T) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ターン後のダメージは、ターン数が奇数か偶数か、また、`b`偶数回または奇数回の操作。 これにより、完全な履歴が 2 つのバイナリ状態に縮小されます。 
2. システム状態を次のように表します。`(i_parity, b_parity)`、 どこ`i_parity`現在のターン番号が偶数か奇数かを追跡し、`b_parity`かどうかを追跡します`b`これまでに偶数回または奇数回適用されています。 
3. 式を使用して状態から現在のダメージ値を計算します。`y XOR (i_parity ? a : 0) XOR (b_parity ? b : 0)`。 これは、XOR を繰り返すとペアでキャンセルされるため、パリティのみが重要となるため有効です。 
4. 現在の状態から、考えられる 2 つのアクションを評価します。適用しない`b`、または申請してください`b`。 最初の保持`b_parity`変更されない場合、2 番目はそれを反転します。 
5. 現在のターンでより大きな即時ダメージ値を生み出すアクションを選択し、そのダメージを現在の合計に追加します。 
6. 反転して次の状態に遷移します`i_parity`毎ターン更新`b_parity`2 番目のアクションが選択された場合。 
7. 蓄積ダメージが一定以上になるまで繰り返します。`x`を入力し、使用したターン数を出力します。 

この方法の背後にある重要な特性は、システムが 4 つの状態しか持たない有限決定論的オートマトンであるということです。 どの状態からでも、決定は次の状態と当面の報酬にのみ影響し、将来の遷移はその結果の状態にのみ依存します。 パリティを超えた隠れた長期記憶はないため、各ステップでの即時ダメージを最大化することは、全体的に最適な蓄積と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y, a, b = map(int, input().split())

        # state: (i_parity, b_parity)
        i_parity = 0  # 0 means even turn index, but we start at turn 1 so handle carefully
        b_parity = 0

        total = 0
        turns = 0

        # we treat turn number starting from 1
        while total < x:
            i_parity ^= 1  # move to next turn parity (1 for odd turn)

            base = y
            if i_parity:
                base ^= a
            if b_parity:
                base ^= b

            # option 1: do not apply b
            v0 = base
            # option 2: apply b
            v1 = base ^ b

            if v1 > v0:
                total += v1
                b_parity ^= 1
            else:
                total += v0

            turns += 1

        print(turns)

if __name__ == "__main__":
    solve()
```実装では、ターン インデックスのパリティのみが維持されます。`b`奇数回適用されました。 各反復では、両方の選択肢に対する現在のダメージが再計算され、より良い即時結果が選択されます。 XOR 構造により、再計算が一定時間になります。 

微妙な点は、ターン パリティを正しく処理することです。 ダメージの計算式は、現在のステップが 1 番目か 2 番目などによって異なるため、ダメージを計算する前に各ループ反復の開始時にパリティが反転されます。

 ## 特殊なケース

 両方の場合にコーナーケースが発生します。`a`そして`b`はゼロです。 状態は決して変化せず、毎ターン一定のダメージを与えます。`y`。 アルゴリズムは正しく蓄積します`y`到達するまでの各反復`x`どちらのブランチも値を変更しないためです。 

別の特殊なケースが発生するのは、`a == b`。 その状況で申請すると、`b`後`a`フレンドの操作効果を打ち消す。 2 つの候補値は次のとおりであるため、アルゴリズムはこれを自然に処理します。`v0`そして`v1`同一の値または交換された値に崩壊するため、選択は中立になり、将来の状態には影響しません。 

3 番目のケースは、XOR 変換によって 2 つの値のサイクルが生成される場合です。 ダメージが高い値と低い値を交互に繰り返す場合でも、貪欲なステップは常により高い即時寄与を選択します。また、状態遷移は決定的で可逆的であるため、シーケンスは一貫性を保ち、非進行ループに陥ることなく累積がターゲットに向かって進みます。
