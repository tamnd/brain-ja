 ## 問題の理解

 固定オフセットによって結び付けられる 2 つの等差数列が与えられます。 インデックスごとに$i$から$0$に$d$、数値のペアを見てみましょう。$$x = a + i,\quad y = a + p^x + i$$そして関数を評価する必要があります$f(x, y)$各ペアについて、すべての結果を合計します。 

機能$f(x, y)$現在のペアの gcd を両方の値から繰り返し削除します。 各反復では、両方の数値を同じ量だけ、具体的にはその時点の gcd だけ減少させ、少なくとも 1 つの値がゼロになるまでそのような減少が何回可能かをカウントします。 それで$f(x, y)$は、いずれかの数値を使い切るために必要な「共通の gcd 減算ステップ」の数です。 

課題は、$p^x$の式内に表示されます$y$、 そして$x$それ自体も一緒に成長する$i$。 これにより、非常に非線形な依存関係が作成されます。$f$大きい、最大$10^{18}$、と変化します$i$。 

制約$a + p^x + d \le 10^{18}$値が 64 ビット整数に収まることを保証しますが、それはまた、$p^x$は一般にすでに非常に大きいため、その規模で何かを拡張したりシミュレーションしたりすることはできません。 

素朴な解釈では、計算しようとします。$f(x, y)$すべての人に直接$i$ただし、各呼び出しには、繰り返しの gcd 計算と減算ループが含まれます。 最悪の場合、$f(x, y)$数値の大きさに比例して時間がかかることがありますが、これは最大で不可能です。$d$反復のとき$d$それ自体は大きいかもしれません。 

次の場合、微妙なエッジケースが発生します。$x$そして$y$等しいか、ほぼ等しい。 たとえば、次の場合$y = x$、 それから$f(x, y) = 1$、最初の gcd が等しいため、$x$そして両方ともすぐにゼロになります。 複数の削減が常に必要であると想定するアプローチでは、ここで過大評価されます。

## アプローチ

重要な観察は、この操作がユークリッド アルゴリズムを繰り返し適用するのと同等ですが、モジュロの代わりに対称的な方法で gcd の倍数を減算していることです。 gcd がどのように進化するかを追跡すると、そのプロセスは Euclid のアルゴリズムに似た構造化降下を反映していますが、形式は「歩数カウント」です。 

させて$g = \gcd(x, y)$。 それを因数分解することができます。$$x = g \cdot x', \quad y = g \cdot y', \quad \gcd(x', y') = 1$$1 回の反復の後、両方とも次のようになります。$$x - g = g(x' - 1), \quad y - g = g(y' - 1)$$したがって、構造は、削減された係数の 1 つがゼロに達するまで、同じ gcd 係数を保持します。 これは、ステップ数が、gcd 構造を維持しながら両方の座標を同時にデクリメントできる回数と密接に関係していることを意味します。これは、gcd 構造間の比率構造の関数に帰着します。$x$そして$y$、その大きさではありません。 

重要な構造の簡素化は、次のように書き直すことで実現します。$$f(x, y) = \frac{x + y}{\gcd(x, y)} - 1$$この同一性は、各ステップで両方の数値から gcd サイズの質量の「層」が 1 つだけ削除され、層の総数が正規化された合計から 1 を引いた値に等しいことを観察することで検証できます。 これにより、反復プロセスが定数時間の gcd ベースの式に折りたたまれます。 

さて、問題は合計に帰着します。$$\sum_{i=0}^{d} \left( \frac{(a+i) + (a + p^x + i)}{\gcd(a+i, a + p^x + i)} - 1 \right)$$分子を単純化します。$$(a+i) + (a + p^x + i) = 2a + p^x + 2i$$gcd 構造は次のようになります。$$\gcd(a+i, a + p^x + i) = \gcd(a+i, p^x)$$以来$p$プライムです、$p^x$素数の純粋な力です。 したがって、gcd は次のいずれかになります。$p^k$一部の人にとっては$k$、回数に応じて$a+i$で割り切れます$p$。 したがって、問題は追跡に帰着します。$p$-連続する整数の進数評価。 

それぞれについて$i$、次のものが必要です。$$v_p(a+i)$$その後：$$\gcd(a+i, p^x) = p^{\min(x, v_p(a+i))}$$これにより、各項を計算できるようになります。$O(1)$バリュエーションを効率的に評価できれば、$i$範囲内で実行される場合、必要に応じて線形またはブロックで処理します。

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def vp(x, p):
    c = 0
    while x % p == 0:
        x //= p
        c += 1
    return c

def modpow(a, e, mod):
    return pow(a, e, mod)

a, p, x, d = map(int, input().split())

# precompute p^x modulo MOD
px = pow(p, x, MOD)

ans = 0

for i in range(d + 1):
    u = a + i
    v = vp(u, p)
    k = v if v < x else x
    g = pow(p, k, MOD)

    # numerator: (u + (a + px + i)) = 2a + px + 2i
    num = (2 * a + px + 2 * i) % MOD

    term = (num * pow(g, MOD - 2, MOD) - 1) % MOD
    ans = (ans + term) % MOD

print(ans)

評価関数`vp`は入力数値の構造に依存する唯一の部分であり、正確性を支配します。これにより、各数値が次の割り算によって正しく分類されることが保証されます。$p$。

 ## 特殊なケース

 重要なエッジケースは次のような場合に発生します。$a+i$は正確に次の累乗で割り切れます$p$。 たとえば、次の場合$p=2$、$a+i=8$、 それから$v_p = 3$となり、gcd が大きくなります。 この場合、次の除算により項は大幅に縮小します。$p^k$分子のスケーリングを支配します。 アルゴリズムは明示的に計算するため、これを正しく処理します。$k = \min(x, v_p(a+i))$共有構造を決して過大評価しないようにします。 

もう 1 つのエッジケースは次のような場合です$v_p(a+i) = 0$、で割り切れないことを意味します$p$。 それから$k=0$、$g=1$となり、式は単純な線形項に帰着します。 実装はこれを自然に処理します。$pow(p, 0) = 1$、分割の問題を回避し、正確さを維持します。
