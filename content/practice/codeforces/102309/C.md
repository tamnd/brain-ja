 ## 解決策
 ## 問題の理解

 (P=(x_0,y_0)) から投げられるバスケットボールの初速を、ある時点 (t) で (Q=(x_1,y_1)) に達するように、初速が (v_{\max}) を超えないように選択する必要があります。 

公式問題は物理方程式を使用します

 [
 B(t)=P+v_0t+\frac12gt^2、
 ]

 ここで、(g=(0,-9.80665))。 プロンプト内のコピーされたステートメントでは係数 (1/2) が省略されていますが、公式の Codeforces ステートメントにはこれが含まれており、サンプル出力はそのバージョンと一致しています。 

1 つのテスト ケースでは、4 つの座標は開始点と目標点をメートル単位で表し、(v_{\max}) は初速度の最大許容値 (メートル/秒単位) です。 (v_x)、(v_y)、および打撃時間 (t) を出力する必要があります。 有効な答えは任意に多く存在する可能性があるため、構築する必要があるのは 1 つだけです。 

座標は絶対値で (200) で区切られているため、どちらの方向の変位も最大で (400) になります。 入力には大きな配列やグラフが隠されておらず、一定数の算術演算を使用して各テスト ケースを解決できます。 本当の課題は、漸近的に大規模な計算を最適化することではなく、代数的構造を見つけることです。 複数のテスト ケースは EOF まで継続するため、ソリューションでは行ごとに一定の作業を使用する必要があります。 

明確な治療に値する特殊なケースが 2 つあります。 たとえば、開始点と目標点が一致する場合、```
0 0 0 0 0
```その場合、(v_0=(0,0)) および (t=0) が有効な答えになります。 点間の距離で割る式は、ゼロで割ることになります。 この問題が解を保証しているという事実は、この場合には (t=0) を受け入れなければならないことも意味します。(v_{\max}=0) では、同じ点に戻る正の時間の解は存在しないからです。 

2 番目の特殊なケースは、純粋に垂直の下向きの投げです。たとえば、```
0 10 0 0 0
```有効な答えは、```
0 0 1.428...
```重力だけでボールが 10 メートル下に移動するからです。 不用意に実装すると、正の垂直初速度を要求したり、水平変位で除算したりする可能性がありますが、どちらも必要ありません。 

## アプローチ

 直接的な数値的アプローチでは、飛行時間 (t) が未知数として扱われます。 すべての候補 (t) について、必要な速度は一意に決定されます。 

[
 v_x=\frac{dx}{t},
 \qquad
 v_y=\frac{dy}{t}+\frac{g_0t}{2},
 ]

 ここで、(dx=x_1-x_0)、(dy=y_1-y_0)、および (g_0=9.80665)。 (t) の可能な値をスキャンし、対応する速度を計算し、(v_{\max}) を超えない値を探すことができます。 この方法は概念的には正しいです。正の時間ごとに、ターゲットに到達する 1 つの速度が正確に決定されるからです。 

問題は精度です。 (10^{-8}) のステップで (0) から (100) までの間隔をスキャンすると、1 つのテスト ケースに対してすでに (10^{10}) 回の評価が必要になります。 ステップを非常に粗くすると、狭い有効時間間隔を逃したり、位置誤差が (10^{-6}) を超える軌道が生成されたりする可能性があります。 数値スキャンは、代数によって正確に解決できる問題を解決します。 

重要な観察は、速度を (t) で表現すると、その二乗の大きさが非常に単純な形になるということです。 しましょう

 [
 r=\sqrt{dx^2+dy^2}
 ]

 を 2 点間の距離とし、

 [
 k=\frac{9.80665}{2}=4.903325。 
]

 それから

 [
 v_x=\frac{dx}{t},
 \qquad
 v_y=\frac{dy}{t}+kt。 
]

 2乗して加算すると、

 \frac{r^2}{t^2}+2kdy+k^2t^2。 
]

 唯一の可変部分は、

 [
 \frac{r^2}{t^2}+k^2t^2。 
]

 この式は次の場合に最小化されます。 

[
 t^2=\frac{r}{k}=\frac{2r}{9.80665}。 
]

 そのため、実現可能な時間を探すのではなく、初速が最も小さくなる時間を意図的に選択します。 この問題では、実行可能な軌道が存在することが保証されているため、可能な最小速度も最大 (v_{\max}) になります。 これにより、有効な軌道がすぐに得られます。 

最低速度は次のように書くこともできます。 

# 2kr+2kdy

 9.80665(r+dy)。 
]

 (r\ge |dy|) なので、式が負になることはありません。 水平変位は、縮退の場合 (r=0) を除いて、別個の処理を必要としません。 

これが最適化全体です。飛行時間全体にわたって必要な初速度を最小限に抑え、その最小化時間を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(1/\varepsilon)) テスト ケースごと | (O(1)) | 必要な精度に対して遅すぎる |
 | 最適 | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変位を計算します

 [
 dx=x_1-x_0,\qquad dy=y_1-y_0
 ]

 とそのユークリッド長

 [
 r=\sqrt{dx^2+dy^2}。 
]

 ターゲットから開始点を差し引いた後に必要となる幾何学的情報は変位だけです。 

1. (r=0) の場合、(v_x=v_y=t=0) を出力します。 

ボールはすでにターゲットから始まっているため、移動する必要はありません。 一般式は (t) で割られるため、このケースは分離する必要があります。 

1. 軌道方程式で重力加速度を 2 で割った値に対応する (k=9.80665/2) を設定します。 

選択した正の時間 (t) に対して、必要な初速度は次のようになります。 

[
 v_x=\frac{dx}{t},
 \qquad
 v_y=\frac{dy}{t}+kt。 
]

 1. 選択します

 [
 t=\sqrt{\frac{r}{k}}。 
]

 これにより、二乗速度が最小限に抑えられます。 その理由を確認するには、速度の 2 乗の可変部分は次のようになります。 

[
 \frac{r^2}{t^2}+k^2t^2。 
]

 (t) が増加するにつれて最初の項は減少しますが、2 番目の項は増加します。 それらのバランスは次のときに発生します。 

[
 \frac{r^2}{t^2}=k^2t^2,
 ]

 これは (t^2=r/k) を与えます。 

1. コンピューティング

 [
 v_x=\frac{dx}{t}
 ]

 そして

 [
 v_y=\frac{dy}{t}+kt。 
]

 これらの値はターゲット方程式から直接構築されるため、それらを軌道に代入すると、選択した時刻に正確に (Q) に到達します。 

1. 3 つの値を十分な桁数で出力します。 

声明では出力を小数点以下 3 桁として説明していますが、サンプル自体ではさらに多くの桁が出力されており、裁判官はテキストの正確な同一性ではなく数値の妥当性をチェックします。 小数点以下 10 桁または 12 桁を印刷すると、数値誤差が必要な許容誤差を十分に下回ります。

これが機能する理由: 正の値 (t) ごとに、2 つの速度公式は時間 (t) に (Q) に達する固有の初速度になります。 このようなすべての速度の中で、選択された (t=\sqrt{r/k}) が速度を最小にします。 このステートメントでは、少なくとも 1 つの軌道の速度が最大 (v_{\max}) であることが保証されているため、この最小速度の軌道も速度制限を満たします。 縮退 (P=Q) の場合は、ゼロ時間の軌道で直接処理されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

G = 9.80665
K = G / 2.0

def solve():
    out = []

    for line in sys.stdin:
        if not line.strip():
            continue

        x0, y0, x1, y1, vmax = map(float, line.split())

        dx = x1 - x0
        dy = y1 - y0

        r = math.hypot(dx, dy)

        if r == 0.0:
            out.append("0.0000000000 0.0000000000 0.0000000000")
            continue

        t = math.sqrt(r / K)

        vx = dx / t
        vy = dy / t + K * t

        out.append(f"{vx:.12f} {vy:.12f} {t:.12f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```定数セクションには (9.80665/2) が次のように格納されます。`K`、公式の軌道方程式の (\frac12gt^2) 項と一致します。 

変位は、時間に関係する処理の前に計算されます。 これにより、導出は絶対座標から独立したものに保たれ、どちらの方向でも (200) ほど大きくなる可能性があります。`math.hypot(dx, dy)`平方根式を手動で記述せずに距離を計算します。 指定された境界ではオーバーフローの懸念はありませんが、`hypot`は、ユークリッド距離のクリーンな数値実装でもあります。 

の`r == 0.0`入力座標は整数であるため、ここではチェックは安全です。 したがって、(r=0) は、小さな浮動小数点近似によるものではなく、両方の点の座標が同一である場合に正確に発生します。 

ゼロ以外の変位ごとに、`t = sqrt(r / K)`は上記で導出された最小化時間です。 一度`t`が既知である場合、速度成分は 2 つの座標方程式から直接得られます。 長さが座標値に依存するループはなく、数値誤差が蓄積する可能性のある二分探索や反復もありません。 

コードは小数点以下 12 桁を出力します。 これは公称フォーマット要件よりも正確であり、チェッカーに、はるかに低い誤差 (10^{-6}) で軌道を評価するのに十分な情報を提供します。 

## 実用的な例

 付属のサンプルは、```
0 0 10 0 15
```ここでの変位は水平方向であるため、(dx=10)、(dy=0)、(r=10) となります。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (10) |
 | (ダイ) | (0) |
 | (r) | (10) |
 | (k) | (4.903325) |
 | (t=\sqrt{r/k}) | およそ (1.428) |
 | (v_x=dx/t) | およそ (7.002) |
 | (v_y=dy/t+kt) | およそ (7.002) |

 結果の初速度は約 (9.903) となり、許容値 (15) を下回ります。 公式サンプルでは、​​時間 (1.577) でおよそ ((6.342,7.732)) の別の有効な軌道が出力されます。これは、問題では制約を満たす任意の軌道が受け入れられるためです。 

2 番目の例として、次のことを考えてみましょう。```
0 10 0 0 0
```ターゲットはスタート地点の真下にあります。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (0) |
 | (ダイ) | (-10) |
 | (r) | (10) |
 | (k) | (4.903325) |
 | (t=\sqrt{r/k}) | およそ (1.428) |
 | (v_x) | (0) |
 | (v_y) | 約(0) |

 重力だけでボールは下に移動します

 [
 \frac12gt^2=4.903325\cdot\frac{10}{4.903325}=10。 
]

 したがって、ボールは初速度 0 でターゲットに到達し、(v_{\max}=0) 制約に正確に一致します。 この例は、この方法が垂直方向の動きに特別な式を必要としない理由も示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとの (O(1)) | 固定数の算術演算と 1 平方根が使用されます。 
| スペース | (O(1)) 出力ストレージを除く | 一定数の浮動​​小数点変数のみが必要です。 

座標境界によりすべての算術量が小さくなり、各テスト ケースにかかる時間は一定になります。 非常に多くのテスト ケースであっても、1 行あたりわずか数回の浮動小数点演算で処理されるため、このメソッドは 1 秒と 256 MB の制限に簡単に適合します。 

## テストケース

 問題は特別に判断されるため、テスト ハーネスは出力テキストを 1 つの正確な文字列と比較すべきではありません。 代わりに、数学的条件を直接検証する必要があります。 これは、サンプル出力が多数の有効な回答のうちの 1 つにすぎないという事実も正しく処理します。```python
import sys
import io
import math

G = 9.80665
K = G / 2.0

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    try:
        out = []

        for line in sys.stdin:
            if not line.strip():
                continue

            x0, y0, x1, y1, vmax = map(float, line.split())

            dx = x1 - x0
            dy = y1 - y0
            r = math.hypot(dx, dy)

            if r == 0.0:
                out.append("0.0000000000 0.0000000000 0.0000000000")
                continue

            t = math.sqrt(r / K)
            vx = dx / t
            vy = dy / t + K * t

            out.append(f"{vx:.12f} {vy:.12f} {t:.12f}")

        print("\n".join(out))

        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def check_case(inp: str):
    lines = inp.strip().splitlines()
    result = solve_data(inp).strip().splitlines()

    assert len(result) == len(lines)

    for original, produced in zip(lines, result):
        x0, y0, x1, y1, vmax = map(float, original.split())
        vx, vy, t = map(float, produced.split())

        assert t >= 0.0

        speed_sq = vx * vx + vy * vy
        assert vmax * vmax - speed_sq > -1e-6

        bx = x0 + vx * t
        by = y0 + vy * t - K * t * t

        assert abs(bx - x1) <= 1e-6
        assert abs(by - y1) <= 1e-6

# Provided sample.
check_case("0 0 10 0 15")

# Same starting and target point, including vmax = 0.
check_case("0 0 0 0 0")

# Pure vertical drop with zero initial velocity.
check_case("0 10 0 0 0")

# Pure vertical upward displacement.
check_case("0 0 0 10 20")

# Large coordinate differences and a generous speed limit.
check_case("-200 -200 200 200 200")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 0 0 0 0`|`0 0 0`有効です | 一致点とゼロ許容速度 |
 |`0 10 0 0 0`| 約`0 0 1.428`| 重力のみによる下向きの動き |
 |`0 0 0 10 20`| 約`0 14.005 1.428`| 純粋な上向き変位 |
 |`-200 -200 200 200 200`| 有効な非ゼロの軌道 | 最大座標の大きさと対角変位 |

 ## 特殊なケース

 一致点の場合、正確な入力```
0 0 0 0 0
```(r=0) が得られます。 一般的な構造では、(t=\sqrt{r/k}=0) を使用してから (t) で除算しようとするため、実装はこれらの除算を実行する前にゼロ ベクトルとゼロ時間を返します。 これらの値を軌道に代入すると (B(0)=P=Q) となり、速度は正確にゼロになります。 

重力のみによる落下の場合は、次のことを考慮してください。```
0 10 0 0 0
```ここ (r=10) なので、

 [
 t=\sqrt{\frac{10}{4.903325}}\約1.428。 
]

 垂直速度は次のようになります。 

[
 v_y=\frac{-10}{t}+4.903325t\約0。 
]

 したがって、ボールは初速度なしで 10 メートル下の点に到達します。 (v_y) が正でなければならないと仮定するメソッドは、この有効な軌道を誤って拒否します。 

上向きの目標に向けて、```
0 0 0 10 20
```同じ時間は約 (1.428) ですが、現在は

 [
 v_y=\frac{10}{t}+4.903325t\約14.005。 
]

 初速は(14.005)程度で、(20)を余裕で下回ります。 (dy) の符号は垂直成分の符号と大きさを自然に決定するため、別個の上向きの動きの公式は必要ありません。 

最後に、付属のサンプル```
0 0 10 0 15
```水平変位は (10) メートルです。 このソリューションによって生成される最小化軌道は、約 (v_x=v_y=7.002) および (t=1.428) を使用し、速度は約 (9.903<15) です。 サンプルの公開された回答では、別の有効な軌道が使用されているため、テスト ハーネスでは、出力された 3 つの数値を 1 文字ずつ比較するのではなく、物理を検証する必要があります。
