 ## 解決策
 ## 問題の理解

 このプログラムは、ハノイの塔問題に対する標準的な再帰的解法を生成します。 の塔の場合`n`ディスクの場合、最初に上部が移動します`n-1`ディスクをソース ペグから補助ペグに移動し、ディスクを移動します`n`ソースから宛先へ、そして最後に`n-1`補助ペグから宛先までのディスク。 

テストケースごとに、`n`はディスクの数であり、`k`は、生成された出力内の 1 から始まる位置です。 どの手がその位置に現れるかを正確に判断する必要があります`k`、前の動きを生成せずに。 初期ロールはソースとして固定されています`A`、 行き先`B`、および補助`C`。 完全なハノイ ソリューションに含まれる内容が以下の場合`k`動きます、答えは`Orz`。 

塔と`n`ディスクは正確に生成します`2^n - 1`動きます。 両方なので`n`そして`k`と同じ大きさにすることができます`10^18`、再帰を直接シミュレートすることは不可能です。 平`n = 60`すでに生産している`2^60 - 1 = 1,152,921,504,606,846,975`可能な最大値を超えて移動します`k`。 アルゴリズムはすべての手を反復することなく動作する必要があり、それに比例するループを実行する余裕さえありません。`n`いつ`n`それ自体は`10^18`。 

一見正しい実装が失敗する可能性がある境界ケースがいくつかあります。 入力あり`1 1`、唯一の動きは`move 1 from A to B`。 ゼロベースのインデックスを使用する実装では、この最初の動作が誤って拒否される可能性があります。 入力あり`1 2`、正しい結果は次のとおりです`Orz`1 ディスク タワーには出力回線が 1 つしかないためです。 をチェックする不注意な実装`k >= 2^n - 1`の代わりに`k > 2^n - 1`最後の有効な移動を誤って拒否してしまいます。 のために`n = 59`、合計移動数は`2^59 - 1`、 それで`59 576460752303423487`は有効であり、最終的な動きを要求しますが、`59 576460752303423488`生産しなければならない`Orz`。 最後に、非常に大きな場合には、`n`、 のような`1000000000000000000 1`、答えは`move 1 from A to C`なぜなら、均等なサイズのハノイのソリューションは、最小のディスクを補助ペグに向かって移動させることから始まるからです。 単純にデクリメントするループ`n`この場合、一度に 1 レベルずつでは決して終わることはありません。 

## アプローチ

 直接的なアプローチは、指定された再帰プロシージャを実行し、行に到達するまでに生成された行数をカウントすることです。`k`。 プログラム自体が正確な出力順序を定義しているため、これは正しいことです。 移動回数に対する反復は次のようになります。`M(n) = 2M(n-1) + 1`と`M(0) = 0`、与える`M(n) = 2^n - 1`。 したがって、最悪の場合に必要となるのは、`2^n - 1`生成された移動と、同程度の再帰呼び出しの数。 のために`n = 60`、それはすでに約です`1.15 * 10^18`移動するので、強引な攻撃は完全に不可能です。 

有益な観察は、再帰によって出力が 3 つの連続する部分に分割されるということです。 電話の場合`H(n, from, to, another)`、 最初`2^(n-1)-1`行が属する`H(n-1, from, another, to)`。 次の行はディスクの単一の移動です`n`、残りは`2^(n-1)-1`行が属する`H(n-1, another, to, from)`。 

これは、移動を生成する必要がないことを意味します。 これら 3 つの領域のどれに位置が含まれるかを決定するだけで済みます。`k`。 もし`k`が最初の領域にある場合、最初の再帰部分問題に入ります。 それがその領域の直後の境界線に等しい場合、答えは見つかりました。 それ以外の場合は、最初の領域全体と中間の移動を次から差し引きます。`k`、次に 2 番目の副問題に入ります。 

残る難点は、`n`それ自体は可能です`10^18`。 幸いなことに、`k`せいぜい`10^18`。 一度`n`より大きい`60`、最初の再帰ブロックには以下が含まれます`2^(n-1)-1`、これは確かにあらゆる可能なものよりも大きいです`k`。 これらの最初の再帰レベルをすべて一度にスキップできます。 このようなレベルごとに役割が変わります`to`そして`another`, それでスキップした後`t`レベルでは、これら 2 つの役割を正確に交換します。`t`奇数です。 その後、通常どおり続行できます`n = 60`。

 ## アルゴリズムのチュートリアル

 1. まず、要求された行が存在できるかどうかを判断します。 いつ`n < 60`、合計移動数は`2^n - 1`、だから、もし`k`この値より大きい場合、出力`Orz`。 いつ`n >= 60`、許可されたすべての`k <= 10^18`は有効です。`2^60 - 1 > 10^18`。 
2. もし`n > 60`、最初を飛ばしてください`n - 60`再帰的なレベル。 スキップされたすべてのレベルで、目的の位置は必ず最初の再帰呼び出し内にあり、その引数は次から変更されます。`(from, to, another)`に`(from, another, to)`。 したがって、スキップされたレベルの数の同等性のみが問題となります。 もし`n - 60`奇数です、交換してください`to`そして`another`、次に設定します`n = 60`。 
3. 現在の状態について、次を計算します。`half = 2^(n-1)`。 最初の再帰ブロックには以下が含まれます`half - 1`移動するため、中間の移動は正確な位置で行われます`half`。 
4. もし`k == half`、要求された行は、現在のハノイ副問題の中間手です。 そのディスク番号は`n`から移動します。`from`に`to`、だから戻ってください`move n from from to to`。 
5. もし`k < half`、答えは最初の再帰ブロックにあります。 ペグの役割を次のように置き換えます。`(from, another, to)`そして減少します`n`1つずつ。 の値`k`ターゲット位置はそのサブ問題の最初から測定されているため、変化しません。 
6. もし`k > half`、答えは 2 番目の再帰ブロックにあります。 最初のものを削除します`half - 1`設定により移動と中央が移動`k = k - half`。 2 番目のブロックには引数があります`(another, to, from)`したがって、それに応じて 3 つのペグの役割を更新し、減少させます。`n`1つずつ。 
7. 中央の位置に到達するまで続けます。 大規模な終了後に残るレベルは最大で 60 です。`n`ショートカットなので、すべてのテスト ケースはごく少数の反復後に終了します。 

### なぜ効果があるのか

 不変条件は、反復ごとに現在の状態が変化することです。`(n, k, from, to, another)`は、出力に元の要求された行が含まれる再帰的ハノイ呼び出しを正確に説明しています。 その呼び出しの出力は常に次の最初のブロックで構成されます。`2^(n-1)-1`移動、その位置で中間の 1 回の移動`2^(n-1)`、同じサイズの 2 番目のブロック。 アルゴリズムは、次の内容を含むブロックを正確に選択します。`k`、対応する再帰呼び出しに一致するようにペグの役割を変更します。 いつ`k`中間位置に到達すると、再帰プログラムはディスクを出力します。`n`から`from`に`to`したがって、構築された行はまさに必要な出力行です。 大きな-`n`スキップされたすべてのレベルは最初の再帰ブロックに入る必要があり、これを繰り返し行うことによる唯一の効果は、`to`そして`another`役割をペグします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def kth_move(n, k):
    # For n < 60 we can check the exact number of moves.
    if n < 60 and k > (1 << n) - 1:
        return "Orz"

    # For n > 60, k <= 10^18 is always inside the first
    # recursive block for every skipped level.
    if n > 60:
        skipped = n - 60
        if skipped & 1:
            # Every first-recursion step swaps 'to' and 'another'.
            pass
        n = 60
    else:
        skipped = 0

    from_peg, to_peg, aux_peg = 'A', 'B', 'C'

    if skipped & 1:
        to_peg, aux_peg = aux_peg, to_peg

    while n > 0:
        half = 1 << (n - 1)

        if k == half:
            return f"move {n} from {from_peg} to {to_peg}"

        if k < half:
            # H(n-1, from, aux, to)
            to_peg, aux_peg = aux_peg, to_peg
        else:
            # Skip the first block and the middle move.
            k -= half

            # H(n-1, aux, to, from)
            from_peg, to_peg, aux_peg = aux_peg, to_peg, from_peg

        n -= 1

    return "Orz"

def solve():
    out = []

    for line in sys.stdin:
        if not line.strip():
            continue

        n, k = map(int, line.split())
        out.append(kth_move(n, k))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の有効性チェックでは、`k > (1 << n) - 1`、 ない`>=`、最後の動きは正確に`2^n - 1`有効です。 チェックは以下に対してのみ実行されます。`n < 60`、以来`n >= 60`合計移動数がすでに許可されているすべての値を超えています`k`。 

のために`n > 60`、コードは最初にスキップできるレベルの数を計算します。 それぞれのレベルで、`k`must lie in the first recursive call. その電話は続く`from`交換中は変化なし`to`そして`another`。 Repeating this transformation an even number of times restores the original ordering, while an odd number of times swaps the two pegs. The code captures exactly that with`skipped & 1`。 

縮小後、ループはハノイ再帰の 3 つの領域を直接実装します。`half`最初の再帰呼び出しが寄与するため、現在のディスクの移動位置です。`2^(n-1)-1`線。 平等は答えを特定します。 小さめの`k`変更せずに最初の再帰呼び出しに入る`k`、より大きい一方で`k`最初の再帰呼び出しを削除した後、2 番目の再帰呼び出しを開始します。`half`線。 

Python の整数には任意の精度があるため、2 の累乗を計算するときにオーバーフローの問題は発生しません。 実装ではパワーアップのみを計算します。`2^59`メインループ内で、すべてのペグ更新はデクリメント前に行われます。`n`、再帰呼び出しと正確に一致します。

        if n < 60 and k > (1 << n) - 1:
            return "Orz"

        skipped = 0
        if n > 60:
            skipped = n - 60
            n = 60

        from_peg, to_peg, aux_peg = 'A', 'B', 'C'

        if skipped & 1:
            to_peg, aux_peg = aux_peg, to_peg

        while n > 0:
            half = 1 << (n - 1)

            if k == half:
                return f"move {n} from {from_peg} to {to_peg}"

                to_peg, aux_peg = aux_peg, to_peg
            else:
                k -= half
                from_peg, to_peg, aux_peg = aux_peg, to_peg, from_peg

        return "Orz"

    out = []
    for line in inp.splitlines():
        if line.strip():
            n, k = map(int, line.split())
            out.append(kth_move(n, k))

    return "\n".join(out)
