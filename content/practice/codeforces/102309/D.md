 ## 問題の理解

 2 つの機能グループがあります。 最初のグループには (n) 個のフィーチャが含まれ、2 番目のグループには (m) 個のフィーチャが含まれます。 すべての機能には正の重みがあり、一部のペアは互換性がないと宣言されています。 入力では、互換性のないすべてのペアに最初のグループの 1 つの特徴と 2 番目のグループの 1 つの特徴が含まれることが保証されるため、競合グラフは 2 部構成になります。 

両方のエンドポイントが選択されて競合が発生しないように、合計の重みが最大になる一連の特徴を選択する必要があります。 グラフ用語では、これは 2 部グラフの最大重み独立集合です。 

各テスト ケースの最初の行は (n) と (m) を示します。 次の行は、(n+m) 個の特徴の重みを示します。 次に、(k) 個の競合ペアが続きます。 ペア ((p,q)) は、特徴量 (p) と特徴量 (q) を同時に選択できないことを意味します。 (p\le n<q) であるため、すべてのエッジは 2 部グラフの左側の部分から右側の部分に進みます。 

必要な出力は、競合のない一連の特徴の重みの可能な最大の合計です。 複数のテスト ケースが存在する可能性があり、ファイルの終わりまで続行されます。 

ここでは (n,m\le100) なので、グラフには最大 200 個の頂点があります。 競合の数は 10,000 に達する可能性があり、これは 100 頂点の 2 つのグループ間のエッジの最大数に近い値です。 すべてのサブセットに対するブルート フォース検索には最大 (2^{200}) 個の可能性があり、これは 1 秒のソリューションで処理できる範囲をはるかに超えています。 頂点の数が少ないことから、最初はサブセットの列挙が考えられるかもしれませんが、実際の障害は指数関数です。 高密度のエッジ境界は、アルゴリズムが約 10,000 個のエッジを快適に処理できる必要があることも意味します。 

重みは (10^7) まで大きくすることができます。 最大 200 個の特徴があるため、答えは (2\cdot10^9) に達します。 Python の整数には任意の精度がありますが、C++ 実装では、符号付き 32 ビット整数内にこの特定の境界が収まりますが、フロー実装では 64 ビット容量を使用するのが標準的な安全な選択です。 

一見単純な実装でも失敗するケースがいくつかあります。 まず、対立は、あるグループ全体が選択または拒否されなければならないことを意味するものではありません。 例えば、```
1 1
5 7
1
1 2
```答えがあります`7`2 番目の機能を選択し、最初の機能は選択しないままにしておくことができるためです。 ここでは、より重い機能を貪欲に選択する方法が機能しますが、複数の競合が相互作用すると、そのアイデアは失敗します。 

例えば、```
2 2
6 5 7 7
3

```答えがあります`12`、特徴 2 と 4 を選択することで得られます。特徴 1 について貪欲な決定を行うと、右側の特徴の両方がブロックされ、より小さな答えが生成される可能性があります。 

もう 1 つの境界ケースは、競合のないフィーチャです。 のために```
1 1
4 9
1
1 2
```両方の特徴を利用することはできませんが、重み 9 の特徴を利用することはできるので、答えは次のようになります。`9`。 フロー構築では、インシデント競合エッジがない場合でも、すべての頂点が独自の重み容量を受け取る必要があります。 

最後の実装トラップは、競合エッジに使用される容量です。 これは、すべての特徴の重みの合計より大きくなければなりません。 選択した容量が小さすぎる場合、最小カットでは頂点の料金を支払うよりも競合エッジのカットが優先される可能性があり、これはフィーチャの削除に相当しません。 選択する`sum(weights) + 1`その問題を完全に回避します。 

## アプローチ

 直接的なアプローチは、(n+m) 個の特徴のすべてのサブセットを列挙することです。 各サブセットについて、競合エッジの両方のエンドポイントが含まれているかどうかを確認します。 有効な場合、その重みを計算し、最大値を維持します。 考えられるすべての選択がサブセット内で 1 回だけ出現するため、これは正しいです。 

ただし、特徴量が最大 200 個の場合、(2^{200}) 個のサブセットが存在する可能性があります。 1 つのサブセットのチェックに一定の時間しかかからなかったとしても、これは約 (1.6\cdot10^{60}) 状態になります。 すべてのサブセットについて最大 10,000 件の競合をチェックすると、理論上の作業はさらに膨大になります。 強引な解決策は問題を理解するのには役立ちますが、制限時間内に解決する可能性はありません。 

紛争の構造により、より強力なルートが得られます。 グラフは 2 部構成であり、最大重みの独立したセットを探しています。 すべての独立セットはまさに頂点カバーの補完です。独立セットの外側にあるすべての頂点を削除する場合、すべての競合エッジで少なくとも 1 つのエンドポイントが削除されている必要があります。 すべての重みは正であるため、保持される重みを最大化することは、削除される総重みを最小化することと同じです。 

したがって、問題は 2 部グラフにおける最小重みの頂点カバーになります。 ケーニッヒの定理の重み付きバージョンは、最小の (s)-(t) カットで解くことができます。 

ソース (複数可)、すべての最初のグループの頂点、すべての 2 番目のグループの頂点、およびシンク (t) を含むフロー ネットワークを構築します。 すべての最初のグループの頂点に、その重みに等しい容量を持つエッジを与えます。 すべての 2 番目のグループの頂点に、その重みに等しい容量を持つエッジを (t) に与えます。 左の頂点から右の頂点へのすべての競合に対して、すべての頂点の合計重みよりも大きい容量を持つ有向エッジを追加します。 

(s)-(t) カットを考えてみましょう。 左の頂点がソース側に残っている場合、そのソース エッジはカットされません。 シンク側に移動すると、ソースエッジが切断され、その重量がかかります。 同様に、ソース側の右側の頂点によってシンクへのエッジが切断され、その重みがかかります。 

非常に大きな競合エッジにより、最小カットによって反対側の競合する左頂点と右頂点が間違った方向に配置されることが防止されます。 コストのカットは常にすべての頂点の合計重量を超えないため、その合計を超える容量を持つ競合エッジが最小カットに含まれることはありません。 したがって、すべての最小カットは頂点カバーに対応し、その容量はまさにそのカバーの重量になります。 

最小頂点カバーに重み (C) がある場合、最大独立セットにも重みがあります

 [
 \sum_i w_i-C.
 ]

 したがって、1 回の最大流量計算で答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^{n+m}k)) | (O(n+m+k)) | 遅すぎる |
 | 最適 | (O(V^2E)) ディニックと | (O(V+E)) | 承認済み |

 ここで、(V=n+m+2) および (E=k+n+m) です。 指定された (O(V^2E)) 限界は、一般的な整数容量ネットワークにおける Dinic のアルゴリズムの標準的な最悪の場合の限界です。 最大でも約 202 個の頂点と 10,200 個の前方エッジがあるため、これは簡単に管理できます。 

## アルゴリズムのチュートリアル

1. 1 つのテスト ケースを読み取り、すべての (n+m) 個の特徴の重みを保存します。 合計重量を計算します。 最終的には、破棄する必要がある頂点の最小重みを減算します。 
2. ソース、(n) 個の左側フィーチャ頂点、(m) 個の右側フィーチャ頂点、およびシンクを含むフロー ネットワークを作成します。 各入力フィーチャ番号を 1 ベースのインデックスから変換しながら、0 ベースの内部頂点インデックスを使用します。 
3. ソースからすべての左側のフィーチャに、そのフィーチャの重みに等しい容量でエッジを追加します。 このエッジをカットするということは、選択したセットからそのフィーチャを削除することを意味するため、そうするコストはまさにその重量になります。 
4. 右側のすべてのフィーチャから、重量に等しい容量を持つエッジをシンクに追加します。 このようなエッジを切断すると、右側のフィーチャについても同じ解釈が得られます。 
5. すべての競合 ((p,q)) について、対応する左の頂点から対応する右の頂点に、容量のあるエッジを追加します。`total_weight + 1`。 この容量は、すべての機能を削除するコストよりも意図的に大きくなっています。 最小カットではそのようなエッジをカットすることは決して選択されないため、すべての競合は、少なくとも 1 つの端点頂点をカットの適切な側に移動することでカバーする必要があります。 
6. 結果のネットワーク上で最大フロー アルゴリズムを実行します。 最大流量最小カット定理により、結果として得られる流量値は最小カット容量と等しくなります。 構造上、その最小カットはまさに頂点カバーの最小重量となります。 
7. フィーチャの合計重みから最小頂点カバー重みを減算します。 残りの特徴は最大重みの独立したセットを形成するため、この差が必要な答えになります。 

これが機能する理由: 最小カットを考慮し、ソース側の頂点を確認します。 シンク側の左の頂点はカットにソース エッジを与え、ソース側の右の頂点はシンク エッジを与えます。 すべての競合エッジにはすべての頂点の合計ウェイトよりも大きな容量があるため、最小カットでは競合エッジは使用されません。 したがって、すべての競合には、ソース側の独立セットの外側に少なくとも 1 つのエンドポイントがあります。 そのセットから削除された頂点は頂点カバーを形成し、カット キャパシティはその総重量に正確に等しくなります。 逆に、削除された左側の頂点をシンク側に配置し、削除された右側の頂点をソース側に配置することにより、任意の頂点カバーで同じウェイトのカットを定義できます。 したがって、最小カットは正確に最小重みの頂点カバーです。 その補数を取得すると、最大重みの独立セットが得られます。これはまさに必要な特徴の選択です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap):
        forward = [v, cap, None]
        backward = [u, 0, forward]
        forward[2] = backward
        self.g[u].append(forward)
        self.g[v].append(backward)

    def bfs(self, s, t):
        level = [-1] * self.n
        level[s] = 0
        queue = [s]
        head = 0

        while head < len(queue):
            u = queue[head]
            head += 1

            for v, cap, rev in self.g[u]:
                if cap > 0 and level[v] == -1:
                    level[v] = level[u] + 1
                    queue.append(v)

        return level[t] != -1, level

    def dfs(self, u, t, pushed, level, it):
        if u == t:
            return pushed

        while it[u] < len(self.g[u]):
            edge = self.g[u][it[u]]
            v, cap, rev = edge

            if cap > 0 and level[v] == level[u] + 1:
                flow = self.dfs(v, t, min(pushed, cap), level, it)

                if flow:
                    edge[1] -= flow
                    rev[1] += flow
                    return flow

            it[u] += 1

        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**30

        while True:
            found, level = self.bfs(s, t)
            if not found:
                break

            it = [0] * self.n

            while True:
                pushed = self.dfs(s, t, INF, level, it)
                if pushed == 0:
                    break
                flow += pushed

        return flow

def solve(data):
    pos = 0
    out = []

    while pos < len(data):
        n = data[pos]
        m = data[pos + 1]
        pos += 2

        weights = data[pos:pos + n + m]
        pos += n + m

        k = data[pos]
        pos += 1

        conflicts = []
        for _ in range(k):
            p = data[pos] - 1
            q = data[pos + 1] - 1
            pos += 2
            conflicts.append((p, q))

        total = sum(weights)

        source = n + m
        sink = source + 1
        dinic = Dinic(n + m + 2)

        for i in range(n):
            dinic.add_edge(source, i, weights[i])

        for j in range(n, n + m):
            dinic.add_edge(j, sink, weights[j])

        inf = total + 1

        for p, q in conflicts:
            dinic.add_edge(p, q, inf)

        cover_weight = dinic.max_flow(source, sink)
        out.append(str(total - cover_weight))

    return "\n".join(out)

def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```の`Dinic`クラスは、各残差エッジをその逆エッジへの参照とともに保存します。 流れが前方に押し出されるとき、前進容量は減少し、逆方向容量は増加します。 この逆の容量により、後でパスを拡張することで以前の決定を取り消すことができます。 

BFS は、Dinic によって使用されるレベル グラフを構築します。 正の残余容量を持つエッジのみを横断するため、現在それ以上のフローを受け取ることができない頂点は無視されます。 

DFS は、一度に 1 レベルずつ進むエッジを介してブロッキング フローを送信します。 の`it`配列は、各頂点に対してどの出力エッジが最後に考慮されたかを記憶します。 これがないと、同じ飽和エッジまたは使用不能なエッジが繰り返しスキャンされる可能性があり、実装が大幅に遅くなります。 

の`solve`関数はまず入力全体を整数として読み取ります。 テスト ケースは EOF まで継続し、入力には明示的なテスト ケース カウントがないため、これは便利です。 位置`pos`は、平坦化された整数配列内を移動し、各テスト ケースに属する値の数を正確に消費します。 

ソースには次のようにインデックスが付けられます`n + m`、シンクとして`n + m + 1`。 入力内の番号 (p) が付けられたフィーチャが頂点になります`p - 1`これは、入力では 1 から始まるインデックスが使用されるのに対し、Python 配列では 0 から始まるインデックスが使用されるため、これが必要です。 

紛争能力は`total + 1`(10^9) のような任意の定数ではありません。 すべての機能を削除するカットには正確なコストがかかるため、これで十分です`total`したがって、最小カットでは、以下のコストがかかるコンフリクトエッジを優先することはできません。`total`。 

Python では整数オーバーフローの懸念はありません。 有効な最大容量は、すべての重みの合計 (2\cdot10^9) をわずかに上回るだけですが、Python の任意精度の整数により、その境界が変化しても実装が堅牢になります。 

最終的な答えは、`total - cover_weight`、独立したセットと頂点カバーの間の補完関係を直接実装します。

    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap):
        f = [v, cap, None]
        r = [u, 0, f]
        f[2] = r
        self.g[u].append(f)
        self.g[v].append(r)

    def bfs(self, s, t):
        level = [-1] * self.n
        level[s] = 0
        q = [s]
        head = 0

        while head < len(q):
            u = q[head]
            head += 1

            for v, cap, rev in self.g[u]:
                if cap > 0 and level[v] == -1:
                    level[v] = level[u] + 1
                    q.append(v)

        return level[t] != -1, level

    def dfs(self, u, t, pushed, level, it):
        if u == t:
            return pushed

        while it[u] < len(self.g[u]):
            edge = self.g[u][it[u]]
            v, cap, rev = edge

            if cap > 0 and level[v] == level[u] + 1:
                f = self.dfs(v, t, min(pushed, cap), level, it)
                if f:
                    edge[1] -= f
                    rev[1] += f
                    return f

            it[u] += 1

        return 0

    def max_flow(self, s, t):
        ans = 0
        INF = 10**30

        while True:
            ok, level = self.bfs(s, t)
            if not ok:
                break

            it = [0] * self.n

            while True:
                f = self.dfs(s, t, INF, level, it)
                if f == 0:
                    break
                ans += f

        return ans

def solve(data):
    pos = 0
    ans = []

    while pos < len(data):
        n, m = data[pos], data[pos + 1]
        pos += 2

        w = data[pos:pos + n + m]
        pos += n + m

        k = data[pos]
        pos += 1

        edges = []
        for _ in range(k):
            p, q = data[pos] - 1, data[pos + 1] - 1
            pos += 2
            edges.append((p, q))

        total = sum(w)
        s = n + m
        t = s + 1

        flow = Dinic(t + 1)

        for i in range(n):
            flow.add_edge(s, i, w[i])

        for i in range(n, n + m):
            flow.add_edge(i, t, w[i])

        inf = total + 1

        for p, q in edges:
            flow.add_edge(p, q, inf)

        ans.append(str(total - flow.max_flow(s, t)))

    return "\n".join(ans)

def run(inp: str) -> str:
    data = list(map(int, inp.split()))
    return solve(data)

 最大サイズのテストでは、考えられるすべての左から右への競合を使用して、完全な (K_{100,100}) を生成します。 2 つのグループのすべてのペアが競合するため、競合のない選択には片側の頂点のみを含めることができ、200 個の頂点すべてに単位ウェイトがあるためウェイト 100 が与えられます。 このテストは、一部のエッジを誤って省略したり、誤った特徴インデックス境界を使用したりする実装を検出するのに特に役立ちます。 

## 特殊なケース

 最初のエッジ ケースは、重みが等しくない単一の競合です。```
1 1
5 7
1
1 2
```合計の重みは 12 です。ネットワークには、ソースから左頂点までの容量 5、右頂点からシンクまでの容量 7 が含まれており、容量 13 の競合エッジがあります。最小カットでは、削除する安価な頂点、つまり重み 5 の左頂点が選択されます。最大の独立セットの重みは (12-5=7) です。 常に正しいエンドポイントを削除する不注意な実装では、誤って 5 が返されます。 

2 番目のエッジ ケースは、競合をグローバルに考慮する必要がある理由を示しています。```
2 2
6 5 7 7
3
1 3
1 4
2 3
```合計の重みは 25 です。特徴 3 と 4 を選択すると 14 になり、競合はありません。 対応する最小頂点カバーの重みは 11 で、特徴 1 と 2 で構成されます。したがって、フロー値は 11 で、答えは 14 になります。最初の競合を処理し、ローカルでより安価なエンドポイントをすぐに削除する貪欲な方法では、後の競合と悪影響を与える選択を行う可能性があります。 

3 番目のエッジ ケースは、完全に接続された 2 部グラフです。```
2 2
5 5 5 5
4
1 3
1 4
2 3
2 4
```左側のすべてのフィーチャが右側のすべてのフィーチャと競合します。 したがって、有効な選択では片側の頂点のみを使用できます。 どちらかの側が 10 を寄与するため、答えは 10 になります。フロー ネットワークの最小頂点カバーの重みは 10 で、補数の重みも 10 です。これにより、構築がすべての頂点に発生する複数の競合エッジを処理していることがチェックされます。 

4 番目のエッジ ケースでは、最大の有効容量スケールをチェックします。```
1 1
10000000 10000000
1
1 2
```総重量は 20,000,000 なので、競合容量は 20,000,001 になります。 最小カットでは、コスト 10,000,000 でどちらかのフィーチャが削除され、もう一方が選択されたままになります。 答えは10,000,000です。 使用する`total + 1`無限の容量で十分であり、ハードコーディングされたマジックナンバーに依存する必要がないからです。 

最後の境界ケースは、各辺に 100 個の頂点があり、10,000 個の競合がすべて存在する密なグラフです。 このアルゴリズムはすべての競合エッジを追加しますが、その容量が頂点の合計の重みを超えるため、最小カットではそれらのエッジをカットできません。 代わりに、より安価な頂点カバーの代替として側面全体を選択する必要があります。 すべての頂点に単位重みを付けると、最小カバーのコストは 100 になり、最大の独立セットの重みも 100 になります。これにより、小さなインスタンスで使用される同じ数学的不変式を維持しながら、頂点とエッジの両方の最大値が実行されます。
