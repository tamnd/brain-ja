 ## 問題の理解

 私たちは持っています`n`部屋は左から右に配置されています。 各部屋には石の山とグループ化された入力レコードが含まれています`(p, q, c)`その部屋を意味します`q`含まれています`c`サイズが次のような個別の山`p`。 クエリは間隔を与えます`[l, r]`。 この間隔内のすべての部屋から、qkoqhh はパイルを選択しないか、そのルーム内のパイルの 1 つだけを選択することができます。 

サイズの追加の山も1つあります`x`, ゲーム開始前に作成されます。 すべての選択が行われた後、選択された山とこの追加の山が Nim ポジションを形成します。 最初のプレイヤーは、すべてのパイル サイズの xor がゼロ以外のときに正確に勝ちます。したがって、qkoqhh は、選択したルーム パイルの xor がゼロでないときに正確に勝ちます。`x`。 クエリに対する答えは、これらの選択を行うためのさまざまな方法の数を法で数えたものです。`10007`。 

多重度が重要です。 部屋にサイズの異なる 3 つの山がある場合`5`、サイズの 1 つの山を選択します。`5`3 つの異なる選択肢が表示されます。 を含む部屋`c`サイズゼロの杭が貢献します`c`何も選択しないという選択に加えて、xor を変更しないようにするさまざまな方法があります。 

制約により、構造が非常に特殊になります。 あるのは`n <= 500`部屋、あらゆるパイルサイズ、`x`せいぜい`500`したがって、すべてのパイル サイズは 9 ビットの XOR 状態内に収まります。 したがって、あるのは`2^9 = 512`可能な XOR 値。 一方で、`m`できる`10000`、単一のレコードで説明できます`10000`物理的なパイルなので、すべてのパイルを明示的に展開すると、最大で`10^8`オブジェクト。 アルゴリズムは、個々の杭を反復するのではなく、等しい杭サイズを集約する必要があります。 

いくつでもありえます`n(n+1)/2 = 125250`クエリ。 費やす方法`O(n)`クエリあたりの作業量はすでに数千万回程度になっているため、小さい固定 XOR ディメンションは`512`悪用しなければならない。 有用なターゲットはおおよそ次のとおりです`O((n+Q) * 512)`前処理後。

いくつかのエッジケースでは、より単純な実装が静かに破壊される可能性があります。 まず、サイズがゼロのパイルは xor 値を変更しませんが、異なるサイズのゼロのパイルを選択すると、依然として異なる選択肢が得られます。 たとえば、`n=1`、`x=0`、部屋にゼロサイズの山が 1 つあります`1`、クエリ`[1,1]`答えがあります`2`: 何も選択しないか、ゼロの山を選択します。 サイズがゼロのパイルを無視する実装では、次のエラーが返されます。`1`。

 ブルートフォースソリューションでは、合法的に選択された杭をすべて列挙し、選択された杭の XOR を計算し、それを次の式で XOR します。`x`、最後の xor が 0 である選択をカウントします。 これは正しいです。なぜなら、Nim はパイル xor がゼロのときにまさに負けているからです。 問題は選択数です。 部屋ごとに 1 つの山というはるかに小さいケースでも、すでに`2^500`実際の入力には最大で 6 つの選択肢を含めることができます。`10^8`多重度による物理的な積み重ね。 

自然な動的プログラミングの改善は、`dp[s]`、xor を取得する方法の数`s`いくつかの部屋を処理した後。 パイルにサイズがあるお部屋に`p`多重度あり`c[p]`、移行は`new[s] = dp[s] + sum(c[p] * dp[s xor p])`。 

これは正しく、物理的な杭の数への依存はすでに解消されています。 ただし、この移行を直接行うにはコストがかかります`O(512 * number_of_distinct_sizes)`部屋ごとに。 さらに重要なのは、すべての間隔に個別に応答するには、その間隔内のすべての部屋を処理する必要があることです。 

重要な観察は、遷移が XOR 畳み込みであるということです。 部屋ベクトルを定義する`f`設定により`f[0]`に`1`何も選択せず、すべてのパイル サイズの多重度を対応する位置に追加します。 区間 DP は、区間内のすべての部屋ベクトルの XOR 畳み込みです。 

Walsh-Hadamard 変換は、XOR 畳み込みを対角化します。 ベクトルを変換すると、XOR 畳み込みは通常の点ごとの乗算になります。 これは、高速ウォルシュ アダマール変換が XOR 畳み込みに一般的に使用されるのと同じ理由です。 

変換された座標の場合`k`、 させて`a_q[k]`変換された部屋の値になります`q`。 変換された間隔の値`[l,r]`単純に`a_l[k] * a_{l+1}[k] * ... * a_r[k]`。 

現在、間隔の問題は範囲積の問題になりました。`512`独立したスカラー シーケンス。 

通常、プレフィックス積を使用すると、除算によって範囲積を取得できます。 複雑な点が 1 つあります。それは、係数がゼロモジュロになる可能性があることです。`10007`。 変換された座標ごとに 2 つの情報を維持することでこの問題を解決します。 1 つ目は、これまでに確認されたすべての非ゼロ因子の積です。 2 つ目は、最新のゼロ要素の位置です。 最新のゼロが中にある場合`[l,r]`、区間積はゼロです。 それ以外の場合、間隔積は 2 つの非ゼロのプレフィックス積の商になります。 

最後に、逆ウォルシュ アダマール変換により、各 xor 値の選択数が得られます。 に対応する係数だけが必要です`x`したがって、区間全体を逆変換する代わりに、逆変換式を使用してその係数を直接計算できます。

 ## アルゴリズムのチュートリアル

 1. すべての部屋に`q`、配列を構築します`f_q`長さの`512`。 位置`0`価値から始まる`1`、何も選択しないという選択を表します。 すべての入力レコードに対して`(p,q,c)`、 追加`c`に`f_q[p]`。 もし`p=0`、 これはつまり`f_q[0]`になる`1+c`ゼロパイルのいずれかを選択すると、xor は変更されませんが、明確な選択肢が得られるためです。 
2. Walsh-Hadamard 変換をすべての部屋ベクトルに適用します。 変換されたベクトル`A_q`もっている`512`コーディネート。 座標で`k`それは表します`A_q[k] = sum_v f_q[v] * (-1)^{popcount(k & v)}`。 

この変換を選択する理由は、部屋選択分布間の XOR 畳み込みが通常の座標ごとの乗算になるためです。 
3. 変換された座標ごとに`k`、部屋を左から右にスキャンし、ゼロ以外の因子のみを含むプレフィックス積を構築します。 させて`pref[k][i]`の産物である`A_1[k] ... A_i[k]`ゼロに等しいすべての因子をスキップした後。 ストアも`last_zero[k][i]`、最大でも最大の部屋指数`i`どこ`A_q[k]`ゼロだった。 
4. お問い合わせの場合`[l,r]`そして固定座標`k`、最初のチェック`last_zero[k][r]`。 少なくともそれであれば`l`の場合、区間内の 1 つの因子がゼロになるため、変換された区間積はゼロになります。 それ以外の場合、区間内のすべての因子はゼロ以外であり、その積は次のようになります。`pref[k][r] / pref[k][l-1]`。 

係数以来`10007`が素数の場合、すべての非ゼロ剰余は逆剰余を持ちます。 この実装では、すべての非ゼロ剰余の逆関数が 1 回事前計算されるため、各範囲の積は定数時間で取得されます。 
5. 逆ウォルシュ アダマール変換には、特に便利な公式があります。 もし`P[k]`は変換された区間積であり、xor が次のような選択の数になります。`x`は`answer = inv(512) * sum_k P[k] * (-1)^{popcount(k & x)}`。 

この符号をすべての場合に事前計算します`k`、すべてのクエリの数式を評価します。 
6. 同じ変換されたプレフィックス データを使用してすべてのクエリを処理します。 間隔ごとに xor DP を再構成する必要はありません。 各クエリが実行するのは、`512`独立したスカラー範囲積ルックアップと 1 つの最後のモジュラー削減。 

なぜ効果があるのか

 どのお部屋にも、`f_q[v]`は、部屋が xor に貢献する方法の正確な数です。`v`。 2 つの部屋を結合するということは、それぞれから 1 つの寄与を選択することを意味するため、結果の分布はベクトルの XOR 畳み込みになります。 Walsh-Hadamard 変換はこの畳み込みを座標的な乗算に変換するため、変換された区間のベクトルは正確にそのルーム変換の積になります。 

プレフィックス構造は、すべての座標に対してその積を正しく返します。 間隔内でゼロ要素が発生した場合、保存されている最後のゼロ位置がそれを検出し、ゼロを返します。 ゼロが発生しない場合、両方のプレフィックス積はゼロではないため、それらの商は正確に目的の区間積モジュロになります。`10007`。 

次に、逆ウォルシュ アダマール公式により xor の係数が抽出されます。`x`。 この係数は、選択されたパイルの xor が次の値になる選択を正確にカウントします。`x`、これは最初のパイルとその xor を意味します。`x`はゼロです。 このような Nim ポジションは最初のプレイヤーにとって負けとなるため、カウントされたすべての選択はまさに qkoqhh にとって勝利の選択肢となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10007
S = 512
INV_S = pow(S, MOD - 2, MOD)

# Modular inverses of every nonzero residue modulo MOD.
INV = [0] * MOD
INV[1] = 1
for i in range(2, MOD):
    INV[i] = MOD - (MOD // i) * INV[MOD % i] % MOD

def fwht(a):
    """Walsh-Hadamard transform for XOR convolution."""
    h = 1
    while h < S:
        step = h << 1
        for base in range(0, S, step):
            end = base + h
            j = base
            while j < end:
                u = a[j]
                v = a[j + h]

                x = u + v
                if x >= MOD:
                    x -= MOD

                y = u - v
                if y < 0:
                    y += MOD

                a[j] = x
                a[j + h] = y
                j += 1
        h <<= 1

def solve():
    out = []

    while True:
        line = input()
        if not line:
            break
        if not line.strip():
            continue

        n, x = map(int, line.split())

        m = int(input())

        rooms = [[0] * S for _ in range(n)]

        for _ in range(m):
            p, q, c = map(int, input().split())
            rooms[q - 1][p] = (rooms[q - 1][p] + c) % MOD

        # Choosing nothing is always one possibility.
        for q in range(n):
            rooms[q][0] = (rooms[q][0] + 1) % MOD

        # Transform every room.
        for q in range(n):
            fwht(rooms[q])

        # pref[k][i] = product of all nonzero transformed factors
        # among rooms 1..i at coordinate k.
        pref = [[1] * (n + 1) for _ in range(S)]

        # last_zero[k][i] = latest room <= i whose transformed
        # value at coordinate k is zero.
        last_zero = [[0] * (n + 1) for _ in range(S)]

        for k in range(S):
            p = 1
            z = 0

            prow = pref[k]
            zrow = last_zero[k]

            for i in range(1, n + 1):
                value = rooms[i - 1][k]

                if value == 0:
                    z = i
                else:
                    p = (p * value) % MOD

                prow[i] = p
                zrow[i] = z

        qn = int(input())
        queries = []

        for _ in range(qn):
            l, r = map(int, input().split())
            queries.append((l, r))

        # The inverse transform coefficient for xor x uses
        # the character (-1)^(popcount(k & x)).
        signs = [1] * S
        for k in range(S):
            if (k & x).bit_count() & 1:
                signs[k] = -1

        answers = [0] * qn

        # Process one transformed coordinate at a time.
        # This keeps the prefix rows local and avoids repeated
        # two-dimensional indexing in the hottest loop.
        for k in range(S):
            prow = pref[k]
            zrow = last_zero[k]
            sign = signs[k]

            for qi, (l, r) in enumerate(queries):
                if zrow[r] >= l:
                    continue

                # Both prefix values are nonzero, so division is valid.
                value = prow[r] * INV[prow[l - 1]]

                if sign == 1:
                    answers[qi] += value
                else:
                    answers[qi] -= value

        for value in answers:
            value %= MOD
            value = value * INV_S % MOD
            out.append(str(value))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

Walsh-Hadamard 変換は標準のバタフライ演算を使用します`u+v`そして`u-v`。 値は剰余として減算されます`10007`各バタフライの後で、保存されているすべての係数が小さく保たれます。 変換の長さは正確に`512`すべてのパイルサイズが以下であるため`512`。 

プレフィックスの構築では、ゼロ変換係数をプレフィックスに乗算するのではなく、意図的に無視します。 これにより、後で分割が可能になります。`last_zero`ゼロ係数を含む区間と、ゼロ以外の積がたまたま同じプレフィックス値を持つ区間を区別するために必要な欠落情報が含まれています。 

逆表`INV`すべてのクエリと頻度に対してべき乗剰余演算を呼び出すことを回避します。 接頭積は決してゼロにはならないので、`INV[prow[l - 1]]`は常に有効です。 表現`prow[r] * INV[prow[l - 1]]`最終的なクエリの削減までは、通常の Python 整数として残されます。 これにより、最もホットなループからコストのかかるモジュロ演算が削除されます。 

クエリ ループは、クエリごとに配列を再構築するのではなく、変換された座標に対して実行されます。 符号は、共有されるビットのパリティによって決まります。`k`そして`x`、xor 値の逆ウォルシュ アダマール文字と正確に一致します。`x`。 

Python では整数オーバーフローの懸念はありません。 固定幅言語では、両方のオペランドが以下であるため、中間積も小さくなります。`10007`ただし、Python は自然に、これまでに蓄積されたより大きな一時的な合計を処理します。`512`コーディネート。

 | 時間 |`O(n * 512 * log 512 + (n + Q) * 512 + m)`| 各部屋は 1 回変換され、512 個の座標すべてに対してプレフィックスが構築され、すべてのクエリで 512 個の座標がチェックされます。 
| スペース |`O(n * 512 + Q)`| ルーム変換、プレフィックス積、ゼロ位置、ストアド クエリ |

 と`n <= 500`そして`Q <= 125250`、クエリフェーズは最大で約約実行されます。`64`百万の単純な座標操作。 xor 次元は次のように固定されます。`512`、部屋の変換に必要なのは`9`蝶のレイヤー。 このアルゴリズムは、物理的なパイルの保存も回避します。これは、多重度がはるかに多くのオブジェクトを表すことができるため、必要です。`m`と示唆する。 

公式の問題ページにも同じことが記載されています`n <= 500`、`m <= 10000`、 そして`Q <= n(n+1)/2`限界。

 ## 特殊なケース

 サイズがゼロの杭を含む部屋は、そのベクトルが初期化されるときに処理されます。 入力が```
1 0
1
0 1 1
1
1 1
```部屋 1 には最初は空の選択肢があり、XOR ゼロへの 1 つの方法に貢献します。 単一のゼロ サイズの山は、ゼロの xor を行う別の方法を追加します。`f[0]=2`。 変換されたすべての座標は結果的に次のように乗算されます。`2`。 最終的な xor-zero 係数は次のとおりです。`2`, これはまさに選択肢の数です。 から始まる不用意な実装`f[0]=1`ただし、レコードは破棄されます`p=0`誤って生成してしまう`1`。 

重複した杭は同じものに追加することで処理されます。`f[p]`エントリ。 のために```
1 1
1
1 1 2
1
1 1
```部屋のベクトルは`f[0]=1`そして`f[1]=2`。 法的な部屋の選択肢は 3 つあります。何も選択しない、最初のサイズ 1 パイルを選択する、または 2 番目のサイズ 1 パイルを選択するです。 最後の 2 つだけが xor を与えます`1`、したがって、答えは次のとおりです`2`。 アルゴリズムは、変換されたベクトル内の 2 つの山を区別する必要はありません。これは、それらの多重度がすでに係数によって表されているためです。`2`。 

区間境界の場合は次のようになります。```
3 3
3
1 1 1
2 2 1
4 3 1
3
1 2
2 3
1 3
```のために`[1,2]`、使用可能なゼロ以外の値は次のとおりです。`1`そして`2`、そしてそれらの可能な xor は次のとおりです。`0,1,2,3`、だからxor`3`両方の山を選択すると 1 回発生します。 答えは`1`。 のために`[2,3]`、考えられる xor は次のとおりです。`0,2,4,6`、だからxor`3`決して起こらない、そして答えは`0`。 のために`[1,3]`、サイズ 1 およびサイズ 2 の山を選択すると、xor が得られます。`3`、一方、サイズ 4 のパイルは別の組み合わせの一部にすることはできません。`3`、したがって、答えは再びです`1`。 プレフィックスインデックス作成では、`pref[l-1]`これはまさに、左側のエンドポイントが誤って 2 回除外されたり含まれたりするのを防ぐものです。 

ゼロ変換係数のケースは、パイル サイズとは独立して処理されます。 ある程度の周波数に関しては`k`、ある区間にわたって変換された部屋の値が次のようになると仮定します。`5,0,7`。 正しい変換された積はゼロです。 プレフィックス構造は、非ゼロ因数の積を次のように格納します。`35`そしてゼロの位置を記録します。 ゼロをカバーするクエリでは、`last_zero[k][r] >= l`そしてすぐに貢献度はゼロになります。 そのゼロの後に始まるクエリは、その間隔内にゼロが存在しないことを認識し、ゼロ以外のプレフィックスの積を安全に分割します。 これが、実装が単に通常のプレフィックス分割を使用しない理由です。 

最後に、余分な初期の山は別の部屋として扱われません。 その唯一の役割は、ターゲットの xor を変更することです。`0`に`x`。 ルームパイルの選択されたセットは、その xor が等しい場合に qkoqhh に勝ちます。`x`なぜなら、最初の山を含む合計の xor は次のようになります。`x xor x = 0`。 これが、最終的な逆変換抽出で座標を使用する理由です。`x`コーディネートというよりも`0`。
