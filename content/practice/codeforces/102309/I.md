 ## 解決策
 ## 問題の理解

 各テスト ケースでは、完全な 128 ビット IPv6 アドレスを表す 1 つの非負の整数が与えられます。 IPv6 アドレスには 16 ビット セクションがちょうど 8 つあるため、最初の作業は、整数を正確に 32 桁の 16 進数として書き込み、それらの桁を 4 つずつ 8 つのグループに分割することです。 各グループは先頭のゼロなしで書き込まれます。 

その正規化の後、ゼロ値グループの連続実行は次のように置き換えられる場合があります。`::`ただし、実行に少なくとも 2 つのグループが含まれている場合に限ります。 圧縮は最大 1 回のみ使用できます。 すべての法的表現の中で、最初に明示的なセクションが最も少ない表現が必要であり、次に辞書編集的に最小の表現が必要です。 公式問題では、最大 128 ビットの入力、EOF までの複数のテスト ケース、および 1 秒、256 MB の制限が指定されています。 

IPv6 アドレスは常にちょうど 8 つのグループになるため、128 ビット バウンドはここでは特に便利です。 入力に依存するサイズ (n) の配列はなく、複雑なデータ構造も必要ありません。 考えられるすべてのゼロ間隔を調べる方法でも、考慮すべき間隔は (8 \cdot 9 / 2 = 36) 個だけです。 Python の任意精度の整数は、標準の整数型が 128 ビットより小さい言語で発生するオーバーフローの問題も解決します。 

最初の微妙なケースは、単一のゼロ グループです。 たとえば、整数`340282366920938463463374607431768145920`を表します`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 正しい出力は次のとおりです`ffff:ffff:ffff:ffff:ffff:ffff:ffff:0`。 不用意に実装すると、最後のゼロが次のように圧縮される可能性があります。`::`、生産`ffff:ffff:ffff:ffff:ffff:ffff:ffff::`ただし、単一のセクションを省略することは明示的に禁止されています。 

2 番目の微妙なケースは、ゼロ以外のグループがまったく含まれていないアドレスです。 入力用`0`、8 つの正規化されたグループはすべて`0`、正しい出力は次のとおりです。`::`。 すべてゼロのアドレスを通常のプレフィックスやサフィックスと同様に扱うと、誤って空の文字列や無効な単一コロンが生成される可能性があります。 

3 番目の微妙なケースは、複数のゼロ ランが同じ最大長を持つ場合です。 8つのグループを考えてみましょう`1:0:0:2:0:0:3:4`。 両方`1::2:0:0:3:4`そして`1:0:0:2::3:4`2 つのゼロ グループを圧縮し、残りのセクションの数に関しても同様に良好です。 正しい答えは、`1:0:0:2::3:4`辞書編集的に小さいためです。 最初の最も長い実行を単純に選択するソリューションは、このケースでは失敗します。 

最後に、先頭または末尾のゼロランには特別な文字列構築が必要です。 のために`1`、正規化されたグループは次のとおりです。`0:0:0:0:0:0:0:1`、したがって、答えは次のとおりです`::1`。 のために`0`、圧縮された実行の両側は空であるため、答えは正確に次のようになります。`::`、 ない`:`。 

## アプローチ

 グループが 8 つしかないため、直接的な総当たりの解決策が可能です。 それらを正規化した後、すべての間隔を考慮することができます`[l, r]`そのグループはすべてゼロです。 間隔は最大 36 個あり、長さ 1 の間隔は破棄されます。 残りの間隔ごとに、その間隔を次のように置き換えることによって得られるアドレスを構築します。`::`、次に、必要な順序に従って候補を比較します。 有効な間隔がない場合は、非圧縮の正規化されたアドレスが答えとなります。 

このブルート フォースは、実際の問題に対してすでに十分に高速です。 最悪のケースでは、可能な間隔は 36 個あり、1 つの候補を構築すると最大 8 つのグループに接触するため、短い文字列操作を除いて、テスト ケースごとに最大 (36 \times 8 = 288) 個のグループ レベルの操作が存在します。 与えられた固定の 8 グループ表現の下では、このアプローチが遅すぎる意味のある入力サイズはありません。 アドレス形式自体は、可変長問題で見られる通常の (O(n^2)) 爆発を防ぎます。 

最初の最適化基準が何を意味するかを観察することで、検索をさらに簡素化できます。 長さ (k) のゼロランを圧縮すると、正確に (k) 個の明示的なグループが削除され、それらが 1 つのグループに置き換えられます。`::`。 したがって、残りのセクションの数は、最長のゼロランを選択することによって正確に最小化されます。 長さ 1 のランは決して適格ではないため、少なくとも 2 の長さのランのみが問題となります。 

最大ラン長が判明すると、すべての候補は同じ数の残りのグループを使用し、同じ数の文字も削除します。 残る唯一の基準は辞書編集順です。 等しい長さのゼロランの場合、後のランを選択すると、辞書順に常に小さくなります。 2 つの候補が異なる最初の位置では、前の実行を圧縮する候補には次のものが含まれます。`:`、一方、そのゼログループを明示的に残す候補には、次のものが含まれます。`0`。 以来`0`辞書編集的には以下より小さい`:`、後の実行が勝ちます。 この事実を直接使用することも、より確実に、すべての最大長の実行の候補を構築して Python の`min`。 

最適な実装では、8 つのグループを 1 回スキャンして最長のゼロ ランを見つけ、その最大長のランのみの候補を構築し、辞書編集的に最小のものを採用します。 漸近的な複雑さは依然として (O(8)) であり、これは単純に (O(1)) ですが、推論は無関係な区間を列挙するのではなく、最適化基準を直接反映しています。

 ## アルゴリズムのチュートリアル

 1. 入力整数を正確に 32 桁の 16 進数に変換します。 先頭のゼロビットは依然として 128 ビット アドレスの一部であるため、パディングが必要です。 結果を 4 桁の 16 進数からなる 8 つのグループに分割し、各グループから先頭のゼロを削除します。`"0"`グループが完全にゼロのとき。 
2. 8 つの正規化されたグループを左から右にスキャンします。 ゼロ グループが見つかった場合は常に、ゼロ ランが終了するまで続行し、その開始位置と長さを記録します。 RFC スタイルの圧縮では 1 つの省略されたセクションを表現できないため、2 つのグループより短いランは無視して、見つかった最大長を維持します。 
3. 少なくとも 2 の長さのランが存在しない場合は、8 つの正規化されたグループをコロンで結合し、そのアドレスを返します。 法的には使用できません`::`この状況では。 
4. 長さが最大長に等しいゼロランごとに、その完全なランを次のものに置き換えることによって候補アドレスを構築します。`::`。 実行前後のグループは変更されません。 短いランごとにより明示的なセクションが残るため、最大長のランのみを考慮するだけで十分です。 
5. 候補を辞書順に比較し、最小のものを返します。 これにより、別個のタイブレーク ロジックを必要とせずに、開始、中間、終了での実行が処理されます。 
6. 選択した実行が 8 つのグループすべてをカバーする場合、構築により次の結果が得られます。`::`。 最初のグループから開始する場合、結果は次の形式になります。`::suffix`; 最後のグループで終わる場合は、次の形式になります。`prefix::`。 これらのケースは、両側を結合するときに明示的に処理されます。 

これが機能する理由: 正規化後、すべての法的略語は、連続するゼロランが次の値に置き換えられる点のみが異なります。`::`。 長さ (k) のランは (8-k) 個の明示的なセクションを残すため、すべての最適な略語は最長の正当なゼロランを使用する必要があります。 最大長が等しいランの中で、すべての候補を構築し、辞書編集的に最小のものを選択すると、最終的なタイブレーク ルールが正確に実装されます。 構築されたすべての候補は、元の同じ 8 つのグループを表します。`::`は省略されたゼロ グループを正確に表します。 したがって、選択された候補は、法的な圧縮、残りのセクションの可能な最小数、およびそれらの選択肢の中での最小の辞書編集表現という 3 つの要件をすべて満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def make_candidate(groups, l, r):
    left = groups[:l]
    right = groups[r + 1:]

    # Two empty fields joined by ':' produce '::'.
    return ":".join(left + ["", ""] + right)

def abbreviate(x):
    # Exactly 32 hexadecimal digits correspond to eight 16-bit groups.
    h = f"{x:032x}"
    groups = []

    for i in range(0, 32, 4):
        part = h[i:i + 4]
        value = part.lstrip("0")
        groups.append(value if value else "0")

    best_len = 0
    runs = []

    i = 0
    while i < 8:
        if groups[i] != "0":
            i += 1
            continue

        j = i
        while j < 8 and groups[j] == "0":
            j += 1

        length = j - i

        if length >= 2:
            if length > best_len:
                best_len = length
                runs = [(i, j - 1)]
            elif length == best_len:
                runs.append((i, j - 1))

        i = j

    if best_len == 0:
        return ":".join(groups)

    answer = None

    for l, r in runs:
        candidate = make_candidate(groups, l, r)
        if answer is None or candidate < answer:
            answer = candidate

    return answer

def solve():
    out = []

    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue

        x = int(line)
        out.append(abbreviate(x))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```変換`f"{x:032x}"`はキー表現のステップです。 幅 32 は表面的なものではなく、次のような整数です。`1`にならなければなりません`00000000000000000000000000000001`そうしないと、8 つの 16 ビット境界が失われます。 

4 文字の各チャンクは、次のように正規化された 16 進形式に変換されます。`lstrip("0")`。 へのフォールバック`"0"`すべてのゼロを削除するため、これが必要です。`"0000"`空の文字列を生成します。 

ゼロランスキャンでは、`i`最初の未処理グループとして進みます`j`現在の実行が終了するまで。 設定`i = j`は実行全体をスキップするため、8 つの各グループは一定の回数だけ検査されます。 Runs of length one are deliberately ignored.

 候補ビルダーは、特殊な場合のプレフィックスとサフィックスを連結しようとするのではなく、2 つの空の文字列を使用します。 例えば、`["1", "", "", "2"]`と結合した`:`になる`1::2`、 その間`["", "", "1"]`になる`::1`そして`["1", "", ""]`になる`1::`。 すべてのグループが圧縮されている場合、`["", ""]`になる`::`。 

Python の整数には任意の精度があるため、次のようにして 10 進数の入力を読み取ります。`int`ゼロから (2^{128}-1) までの範囲全体を直接処理します。 手動による 10 進数から 2 進数への変換やオーバーフロー処理は必要ありません。 

候補の比較は、Python の通常の文字列順序に意図的に委任されています。 この時点で考慮されるすべての候補は同じ最適なゼロラン長を持っているため、最初の最適化基準で短いため、どの候補も勝つことはできません。 文字列比較では、最終的な辞書編集上のタイのみが解決されます。

 ### サンプル 1

 最初のサンプル整数は次のとおりです。`42540578239448488099419523072699400193`。 その正規化された 16 進数グループは次のとおりです。`2001:470:f003:0:0:0:0:1`。

この例では、主要な最適化を直接示します。 4 つのゼロ グループを実行すると、明示的なグループが 4 つだけ残りますが、より短い実行を圧縮すると、より多くのセクションが残ります。 

### サンプル 2

 入力用`1`、固定幅の 16 進表現は次のようになります。`00000000000000000000000000000001`。 

| 私 | グループ | 現在のゼロラン | ベストの長さ | ベストラン |

このトレースは、圧縮間隔の検索中に先頭のゼロ グループがアドレスの一部に残る必要があることを確認します。 これらは、整数全体の数値の先行ゼロとして破棄されません。 

### サンプル 3

 入力用`0`、8 つの正規化されたグループはすべてゼロです。 

| 私 | グループ | 現在のゼロラン | ベストの長さ | ベストラン |

この場合は、プレフィックスとサフィックスの両方が空である境界を検証します。 これは、完全な IPv6 アドレスが両側に何もない圧縮マーカーによって表される 1 つのケースです。

## テストケース```python
import sys
import io

def make_candidate(groups, l, r):
    return ":".join(groups[:l] + ["", ""] + groups[r + 1:])

def abbreviate(x):
    h = f"{x:032x}"
    groups = []

    for i in range(0, 32, 4):
        part = h[i:i + 4]
        part = part.lstrip("0")
        groups.append(part if part else "0")

    best_len = 0
    runs = []

    i = 0
    while i < 8:
        if groups[i] != "0":
            i += 1
            continue

        j = i
        while j < 8 and groups[j] == "0":
            j += 1

        length = j - i

        if length >= 2:
            if length > best_len:
                best_len = length
                runs = [(i, j - 1)]
            elif length == best_len:
                runs.append((i, j - 1))

        i = j

    if best_len == 0:
        return ":".join(groups)

    return min(make_candidate(groups, l, r) for l, r in runs)

def solve():
    out = []
    for line in sys.stdin:
        line = line.strip()
        if line:
            out.append(abbreviate(int(line)))
    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("42540578239448488099419523072699400193\n") == \
       "2001:470:f003::1\n", "sample 1"

assert run("1\n") == "::1\n", "sample 2"

assert run("0\n") == "::\n", "sample 3"

# Maximum 128-bit value, containing no zero groups.
assert run("340282366920938463463374607431768211455\n") == \
       "ffff:ffff:ffff:ffff:ffff:ffff:ffff:ffff\n", \
       "maximum value"

# A single zero group must not be compressed.
assert run("340282366920938463463374607431768145920\n") == \
       "ffff:ffff:ffff:ffff:ffff:ffff:ffff:0\n", \
       "single zero group"

# Two equally long zero runs. The later one is lexicographically smaller.
tie_value = (
    (1 << 112) +
    (2 << 64) +
    (3 << 16) +
    4
)
assert run(str(tie_value) + "\n") == \
       "1:0:0:2::3:4\n", \
       "lexicographic tie"

# No compressible zero run.
no_run_value = (
    (1 << 112) +
    (2 << 96) +
    (3 << 80) +
    (4 << 64) +
    (5 << 48) +
    (6 << 32) +
    (7 << 16) +
    8
)
assert run(str(no_run_value) + "\n") == \
       "1:2:3:4:5:6:7:8\n", \
       "no zero run"
