 ## 解決策
 ## 問題の理解

 (n\times) の整数行列 (A) と正の整数 (b_1,\ldots,b_n) が与えられます。 ベクトル (x) に対して、(y=Ax) を定義します。 積分では、軸に揃えられたボックス内に画像 (y) が存在するすべてのベクトル (x) の (n) 次元ボリュームが求められます。 

[
 0\le y_i\le b_i.
 】

 必要な答えはその体積の 2 乗です。 

したがって、重要な幾何学的問題は実際には積分に関するものではありません。 有効な (y) のセットは単なる長方形のボックスですが、(x) は線形変換 (A) を通じて (y) から取得されます。 (A) が反転可能な場合、箱は平行面に変換され、その体積は (A) の行列式によって決まります。 (A) が特異な場合、(x) 空間のある方向は (Ax) には完全に見えないため、実現可能な集合はその方向に無限に広がります。 

(A) が可逆のとき、

 # \frac{\operatorname{Vol}(y)}{|\det A|}

 \frac{\prod_i b_i}{|\det A|}。 
】

 したがって、要求された値は次のようになります。 

[
 \箱入り{
 \frac{\left(\prod_i b_i\right)^2}{(\det A)^2}
 }。 
】

 制約には (n\le300) があるため、(O(n^3)) アルゴリズムが適切です。 3次アルゴリズムは約(3億^3=27)百万の基本的な行列演算を実行しますが、指数演算や階乗演算は完全に実行不可能です。 行列のエントリと (b_i) の値は (10^9) と同じくらい大きいため、行列式を通常のマシン整数として計算することも安全ではありません。 Python の任意精度の整数はオーバーフローを回避しますが、要求された結果自体が素数の法​​であるため、モジュラー ガウス消去法の方がよりクリーンです。 

不注意な実装では、2 つの異なる失敗ケースを区別する必要があります。 まず、特異行列は積分を無限大にします。 例えば、```
2
1 1
1 1
2 2
```行列式はゼロであり、正しい出力は次のとおりです。`Orz`。 実現可能な (x) セットには無制限の方向が含まれているため、行列式を単なる分母として扱うと、ゼロによる除算を誤って示唆することになります。 

第 2 に、ゼロ以外の整数行列式自体は (M=10^9+7) で割り切れます。 例えば、```
2
1 2
-500000003 1
1 1
```決定要因がある

 [
 1+2\cdot500000003=1000000007=M.
 】

 積分は有限ですが、すべての (b_i\le10^9<M) であるため、その換算分母には (M) が含まれており、(\prod b_i) には素因数 (M) を含めることはできません。 必要な逆モジュラーが存在しないため、正解は再び次のとおりです。`Orz`。 行列式が整数に対してゼロ以外であるかどうかだけをチェックし、その後盲目的に逆モジュラーを呼び出すソリューションでは、無効な結果が生成されます。 

サンプル付き```
2
1 1
1 -1
4 5
```行列式 (-2) があります。 変換されたボックスの体積は (4\cdot5=20) であるため、実行可能な (x) 領域の体積は (20/2=10) となり、要求された正方形は (100) になります。 

## アプローチ

 行列式について直接的に力ずくで考える方法は、ライプニッツの公式です。 

[
 \det A=\sum_{\pi} \オペレータ名{sgn}(\pi)
 \prod_i A_{i,\pi(i)}。 
】

 (n) 列の順列ごとに 1 つの項を調べます。 これは、(n!) 個の積、および積が独立して形成された場合はおおよそ (n\cdot n!) 個のスカラー演算を意味します。 (n=300) では、(300!) でも 4 秒で処理できるものよりも天文学的に大きくなります。 積分領域は元の座標における任意の高次元多面体であるため、直接的な数値積分はさらに役に立ちません。 

幾何学的観察により積分は完全に除去されます。 制約はすでに (y=Ax) 座標のボックスになっています。 可逆線形マップの場合、ボリュームは正確に係数 (|\det A|) だけ変化します。 したがって、積分全体は 1 つの行列式と (b_i) の積を使用して表現できます。 

残りの課題は、その行列式をモジュラー除算と互換性のある形式で効率的に計算することです。 ガウス消去法は、(O(n^3)) の行列式を計算します。 モジュラス (M=1000000007) は素数であるため、すべての非ゼロ行列エントリのモジュロ (M) は逆モジュラーを持ちます。 したがって、完全にモジュロ (M) で消去を実行できます。 

ゼロ行列式モジュロ (M) の意味については、微妙な点が 1 つあります。 整数に対する行列式が 0 であるということは、行列が特異であることを意味しますが、逆のモジュロ (M) は少し異なります。整数行列式は、(M) で割り切れる間は非ゼロになる可能性があります。 その事件はまだ生み出さなければならない`Orz`, 合理的な答えには (M) を含む分母があるからです。 すべて (b_i<M) であるため、分子 ((\prod b_i)^2) は (M) で割り切れないため、分数換算中に因数 (M) が消えることはありません。

 ## アルゴリズムのチュートリアル

 1. (A) と (b) を読み取り、すべての行列エントリのモジュロを削減します (M=1000000007)。 負のエントリは、同等の非負の残基に変換されます。 
2. ガウス消去法を使用して (\det A\bmod M) を計算します。 列 (i) で、行 (i,\ldots,n-1) でゼロ以外のピボットを検索します。 存在しない場合、行列式はゼロモジュロ (M) であるため、出力`Orz`。 

行列式がゼロ法 (M) の場合、(A) が真に特異であるか、その非ゼロ整数行列式が (M) で割り切れます。 どちらの場合も次のような結果につながります`Orz`、さまざまな数学的理由から。 
3. 現在の行の下にピボットが見つかったら、2 つの行を交換します。 行を交換すると行列式の符号が変わるため、累積された行列式に (-1) を掛けます。 
4. 行列式アキュムレータにピボット値を掛けます。 次に、そのピボットの下のエントリを削除します。 ピボットが (p) で、削除されるエントリが (v) の場合、次を使用します。 

[
 f=v p^{-1}\pmod M
 】

 そして行を次のように置き換えます

 [
 R_j\左矢印 R_j-fR_i。 
】

 現在の列がゼロになるため、ピボットの右側の列のみを更新する必要があります。 

1. すべての列が処理された後、行列式アキュムレータは (\det A\bmod M) になります。 ゼロの場合は出力`Orz`。 それ以外の場合は計算します

 [
 B=\prod_i b_i\pmod M.
 】

 1. 必要な値は次のとおりです。 

[
 \frac{B^2}{(\det A)^2}。 
】

 行列式は非ゼロモジュロ (M) であるため、その逆モジュラが存在します。 コンピューティング

 [
 B^2\cdot(\det A)^{-2}\pmod M.
 】

 パイソンの`pow(x, M-2, M)`(M) が素数であるため、逆モジュラーが得られます。 

### なぜ効果があるのか

 (S={x:0\le (Ax)_i\le b_i\text{ for each }i}) とします。 (A) が反転可能な場合、マップ (x\mapsto Ax) は (S) をボックス (B=[0,b_1]\times\cdots\times[0,b_n]) に全単射的にマップします。 変数の線形変化は (|\det A|) によってボリュームをスケールします。 

# \frac{\operatorname{Vol}(B)}{|\det A|}

 \frac{\prod_i b_i}{|\det A|}。 
】

 二乗により行列式の符号が削除され、アルゴリズムで使用される式が得られます。 

(A) が特異な場合、(Av=0) の非ゼロベクトル (v) が存在します。 任意の実行可能な点から開始して (v) に沿って移動しても (Ax) は変化しないため、実行可能な領域には境界のない線が含まれ、体積は無限になります。 したがって、特異行列は次の結果を生成する必要があります。`Orz`。 

最後に、(\det A\ne0) は整数ですが、(\det A\equiv0\pmod M) であるとします。 (M) は素数であり、すべて (b_i<M) であるため、分子 ((\prod b_i)^2) は (M) で割り切れません。 したがって、縮小された分母にはまだ (M) が含まれているため、その逆モジュールは存在しません。 同じ`Orz`決断は正しい。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def determinant_mod(a):
    n = len(a)
    det = 1

    for col in range(n):
        pivot = col
        while pivot < n and a[pivot][col] == 0:
            pivot += 1

        if pivot == n:
            return 0

        if pivot != col:
            a[col], a[pivot] = a[pivot], a[col]
            det = (-det) % MOD

        p = a[col][col]
        det = det * p % MOD

        inv_p = pow(p, MOD - 2, MOD)

        pivot_row = a[col]

        for row in range(col + 1, n):
            value = a[row][col]
            if value == 0:
                continue

            factor = value * inv_p % MOD
            current = a[row]

            for j in range(col + 1, n):
                current[j] = (current[j] - factor * pivot_row[j]) % MOD

            current[col] = 0

    return det

def solve():
    out = []

    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue

        n = int(line)

        a = []
        for _ in range(n):
            row = list(map(int, input().split()))
            a.append([x % MOD for x in row])

        b = list(map(int, input().split()))

        det = determinant_mod(a)

        if det == 0:
            out.append("Orz")
            continue

        product_b = 1
        for x in b:
            product_b = product_b * (x % MOD) % MOD

        inv_det = pow(det, MOD - 2, MOD)
        ans = product_b * product_b % MOD
        ans = ans * inv_det % MOD
        ans = ans * inv_det % MOD

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```行列式ルーチンはその場で行列を変更するため、別の (n\times) 行列の割り当てが回避されます。 すべてのエントリはモジュロ (M) で保持されるため、すべての算術演算はモジュロ演算の前にほぼ (M^2) によって制限されたままになります。 

ガウス消去法ではゼロ ピボットで除算できないため、ピボット検索が必要です。 行を交換すると、決定要素の符号が変わります。これが理由です。`det`別のピボット行が選択されると無効になります。 

消去係数は次のように計算されます。`value * inv_p % MOD`。 その後、現在のピボット列が明示的にゼロに設定されます。 内側のループは次から始まります`col + 1`ではなく、`col`これは、現在の列の値がゼロになることがすでにわかっているためです。 これにより作業が節約され、後の行で使用される前にピボット列を誤って変更してしまうことがなくなります。 

行列式は、消去前に各ピボットで乗算されます。 ガウス消去法では、ある行の倍数を別の行から減算しても行列式は変わらないため、行の交換まで行列式が保持されます。 したがって、ピボットの積と行の交換による符号は、まさに行列式モジュロ (M) になります。 

Python には固定幅の整数オーバーフローがありませんが、数学的出力はモジュロ (M) であり、モジュラー ガウス消去法により巨大な行列値が回避されるため、実装では依然としてすべての演算がモジュロ (M) で実行されます。 

二人の呼びかけは、`inv_det`最終的な式の は、分母の二乗行列式に対応します。 正方形では符号が無関係になるため、絶対的な行列式を計算する必要はありません。
