 ## 解決策
 ## 問題の理解

 (n) 個のボックスが左から右に配置されています。 タイプ 1 の演算では、間隔 ([l,r])、桁 (x)、およびオフセット (c) を選択します。 その間隔内のすべての位置 (p) (p=l+k-1) に対して、正確に 1 つの新しい紙ストリップがボックス (p) に配置されます。 その値は、数字 (x) の (c+k) 個のコピーで構成される数値です。 

タイプ 2 の操作では、現在ボックス ([l,r]) に格納されているすべての紙ストリップを調べ、一様にランダムに 1 つを選択し、選択したストリップの期待値を返すように求められます。 したがって、答えは、区間内のすべてのストリップ値の合計を、そこにあるストリップの総数で割ったものになります。 除算はモジュロ (10^9+7) で実行されます。 

この制約により、直接シミュレーションが不可能になります。 (10^5) 個の操作と (10^4) 個のボックスが存在する可能性があるため、更新ごとに影響を受けるすべてのボックスを処理するには、(10^9) 個のボックス更新が必要になる場合があります。 値パラメータ (c) も (10^9) に達する可能性があるため、実際の 10 進数文字列を構築することは完全に問題外です。 すべてのストリップ値を代数的に表し、間隔全体を一度に更新する必要があります。 

単純な実装では誤って処理される可能性のあるエッジケースがいくつかあります。 まず、クエリはストリップをまったく含まないボックスをカバーできます。 例えば、```
1 1
2 1 1
```利用可能なストリップがないので、答えは次のようになります。`0`。 カウントの逆数を盲目的に計算するソリューションでは、ゼロで除算することになります。 

第二に、(l>1) の間、(c) はゼロになる可能性があります。 例えば、```
3 2
1 3 3 1 0
2 3 3
```1 桁のストリップを配置します`1`ボックス 3 に入力すると、答えは次のようになります。`1`。 代数表現には当然 (10^{c-l+1}=10^{-2}) が含まれるため、この指数を通常の非負の指数として扱うと誤った結果が得られます。 これは、10 の逆べき乗を事前に計算することで処理します。 

第三に、クエリ間隔は更新間隔と一致する必要はありません。 例えば、```
4 2
1 2 4 3 1
2 3 4
```作成します`33`、`333`、 そして`3333`ボックス 2、3、および 4。クエリでは次の内容のみが表示されます。`333`そして`3333`, したがって、答えは(3666/2=1833)となります。 位置の境界を考慮せずに、各更新の合計貢献度のみを保存するソリューションには、次のものが含まれます。`33`間違っています。 

最後に、多くの更新が重複する可能性があります。 ストリップは後の操作では置き換えられず、蓄積されます。 例えば、```
1 3
1 1 1 9 0
1 1 1 9 0
2 1 1
```2 つのストリップが残り、両方とも次と等しい`9`、したがって、期待はまだあります`9`。 データ構造は、追加的な更新の下で合計とカウントを維持する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのボックスについて、現在そのボックス内にあるストリップのリストを維持します。 タイプ 1 の演算の場合、(p=l,\ldots,r) を反復処理し、対応する反復桁数を計算し、それをボックス (p) に追加します。 タイプ 2 の操作の場合、要求されたボックスを反復処理し、ストリップの数とそれらのストリップの値の両方を合計します。 これは正しいです。均一に選択された項目の期待値は、合計値を項目数で割った値となります。 

問題は仕事量です。 1 つのタイプ 1 操作で (10^4) 個のボックスにタッチでき、(10^5) 個の操作があり、(10^9) 個もの個別のボックスが更新されます。 クエリでは、それぞれ (10^4) 個のボックスをスキャンする必要がある場合もあります。 データ自体には、操作の有効期間全体にわたって最大 (10^9) 個のストリップが含まれる可能性があるため、すべてのストリップを明示的に保存することも現実的ではありません。 

有益な観察は、位置 (p) に追加されるストリップの値が非常に単純な形式であるということです。 長さ(L)の繰り返し桁数は、

 [
 x\frac{10^L-1}{9}。 
]

 (l) で始まる更新の場合、位置 (p) は (k=p-l+1) に対応するため、そのストリップの長さは (c+p-l+1) になります。 その値は

 [
 x\frac{10^{c+p-l+1}-1}{9}。 
]

 並べ替えると

 [
 \frac{x10^{c-l+1}}9 10^p-\frac{x}{9}。 
]

 修正されたアップデートの場合、これは単純に

 [
 A\cdot 10^p+B、
 ]

 ここで、(A) と (B) は更新間隔全体にわたる定数です。 

これはまさに、遅延セグメント ツリーが活用できる構造です。 すべてのセグメントについて、(10^p) の合計、現在のすべてのストリップ値の合計、およびストリップの数を保存します。 係数 (A,B) による更新を適用すると、セグメント ([L,R]) の値の合計が次のように変更されます。 

[
 A\sum_{p=L}^{R}10^p+B(R-L+1)。 
]

 同時に、すべての位置に 1 つの新しいストリップが追加されるため、ストリップ数は (R-L+1) だけ増加します。 

したがって、セグメント ツリーは (O(\log n)) でタイプ 1 の操作全体を遅延実行し、タイプ 2 の操作は (O(\log n)) で合計値と合計数の両方を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(mn)) | (O(mn)) 最悪の場合 | 遅すぎる |
 | 最適 | (O(m\log n+\sum \log c_i)) | (O(n)) | 承認済み |

 (\log c_i) 項は、(10^{c_i}) を計算するときのべき乗剰余演算に由来します。 (c_i\le 10^9) なので、これは更新ごとに約 30 回のモジュラー乗算にすぎません。 

## アルゴリズムのチュートリアル

 1. (0\le p\le n) ごとに (10^p\bmod M) と (10^{-p}\bmod M) を事前計算します。 (c<l-1) の場合、係数 (10^{c-l+1}) は負の指数を持つ可能性があるため、逆べき乗が必要になります。 (10^c10^{1-l}) と安全に書くことができます。 
2. 位置 (1,\ldots,n) にセグメント ツリーを構築します。 各ノードが保存する`pow_sum`、そのセグメントにわたる (10^p) の合計、および 2 つの動的量:`value_sum`、現在セグメント内にあるすべての紙片の値の合計、および`count_sum`、現在セグメント内にあるストリップの数。 
3. タイプ 1 演算 ((l,r,x,c)) の場合、位置 (p) に追加された値を次のように書き換えます。 

[
 \frac{x10^{c-l+1}}9 10^p-\frac{x}{9}。 
]

 定義する

 [
 A=x10^c10^{1-l}9^{-1}\pmod M
 ]

 そして

 [
 B=-x9^{-1}\pmod M.
 ]

 すべての位置 (p\in[l,r]) の更新は正確に (A10^p+B) になります。 
4. この更新をセグメント ツリーに遅延適用します。 ([L,R]) を表す完全にカバーされたノードの場合、次を追加します。 

[
 A\cdot\text{pow_sum}+B(R-L+1)
 ]

 値の合計に (R-L+1) を加え、そのカウントに (R-L+1) を加えます。 (A,B) を格納すると、子孫が後で同じ更新を受信できるように、ノードの遅延フィールドにカウントが増加します。 
5. タイプ 2 クエリ ([l,r]) の場合、セグメント ツリーのペア ((S,C)) をクエリします。ここで、(S) はそれらのボックス内のすべてのストリップの合計値、(C) はそれらの合計数です。 (C=0)の場合、出力`0`。 それ以外の場合は出力

 [
 S C^{-1}\pmod M.
 ]
 6. EOF までテスト ケースを処理します。 ツリーは新しいペア ((n,m)) ごとに再構築されるため、異なるテスト ケースからのストリップが相互作用することはありません。 

### なぜ効果があるのか

 不変条件は、すべてのセグメント ツリー ノードについて、`value_sum`は、そのノードの間隔内の位置に現在属しているすべてのストリップの値の合計に等しくなります。`count_sum`それらのストリップの数に等しい。 静電気`pow_sum`同じ位置の (10^p) の合計に等しい。 

タイプ 1 の操作は、(A10^p+B) を影響を受ける各位置の 1 つの新しいストリップに追加します。 完全なセグメントの場合、この式を合計すると、(A\cdot\text{pow_sum}+B\cdot\text{length})、つまりツリーによって適用される更新が正確に得られ、新しいストリップの数は正確にセグメントの長さになります。 遅延伝播では、すべての子孫に対してこれらの同じ量が保存されます。 

したがって、タイプ 2 のクエリは、その間隔内の選択可能なストリップの正確な合計値と正確な合計数を取得します。 前者を後者で割ることは、まさに要求された期待値の定義であるため、返されるモジュラー値は正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007
INV9 = pow(9, MOD - 2, MOD)
INV10 = pow(10, MOD - 2, MOD)

def solve():
    out = []

    while True:
        first = input()
        if not first:
            break

        n, m = map(int, first.split())

        pow10 = [1] * (n + 1)
        invpow10 = [1] * (n + 1)

        for i in range(1, n + 1):
            pow10[i] = pow10[i - 1] * 10 % MOD
            invpow10[i] = invpow10[i - 1] * INV10 % MOD

        size = 4 * n + 5

        pow_sum = [0] * size
        value_sum = [0] * size
        count_sum = [0] * size

        lazy_a = [0] * size
        lazy_b = [0] * size
        lazy_c = [0] * size

        def build(node, left, right):
            if left == right:
                pow_sum[node] = pow10[left]
                return

            mid = (left + right) >> 1
            lc = node << 1
            rc = lc | 1

            build(lc, left, mid)
            build(rc, mid + 1, right)

            pow_sum[node] = (pow_sum[lc] + pow_sum[rc]) % MOD

        def apply(node, left, right, a, b, c):
            length = right - left + 1

            value_sum[node] = (
                value_sum[node]
                + a * pow_sum[node]
                + b * length
            ) % MOD

            count_sum[node] += c * length

            lazy_a[node] = (lazy_a[node] + a) % MOD
            lazy_b[node] = (lazy_b[node] + b) % MOD
            lazy_c[node] += c

        def push(node, left, right):
            a = lazy_a[node]
            b = lazy_b[node]
            c = lazy_c[node]

            if a == 0 and b == 0 and c == 0:
                return

            if left != right:
                mid = (left + right) >> 1
                lc = node << 1
                rc = lc | 1

                apply(lc, left, mid, a, b, c)
                apply(rc, mid + 1, right, a, b, c)

            lazy_a[node] = 0
            lazy_b[node] = 0
            lazy_c[node] = 0

        def update(node, left, right, ql, qr, a, b):
            if ql <= left and right <= qr:
                apply(node, left, right, a, b, 1)
                return

            push(node, left, right)

            mid = (left + right) >> 1
            lc = node << 1
            rc = lc | 1

            if ql <= mid:
                update(lc, left, mid, ql, qr, a, b)

            if qr > mid:
                update(rc, mid + 1, right, ql, qr, a, b)

            value_sum[node] = (value_sum[lc] + value_sum[rc]) % MOD
            count_sum[node] = count_sum[lc] + count_sum[rc]

        def query(node, left, right, ql, qr):
            if ql <= left and right <= qr:
                return value_sum[node], count_sum[node]

            push(node, left, right)

            mid = (left + right) >> 1
            lc = node << 1
            rc = lc | 1

            total_value = 0
            total_count = 0

            if ql <= mid:
                v, c = query(lc, left, mid, ql, qr)
                total_value += v
                total_count += c

            if qr > mid:
                v, c = query(rc, mid + 1, right, ql, qr)
                total_value += v
                total_count += c

            return total_value % MOD, total_count

        build(1, 1, n)

        for _ in range(m):
            operation = list(map(int, input().split()))

            if operation[0] == 1:
                _, l, r, x, c = operation

                # x * 10^(c-l+1) / 9
                # = x * 10^c * 10^(1-l) / 9
                a = x * pow(10, c, MOD) % MOD
                a = a * invpow10[l - 1] % MOD
                a = a * 10 % MOD
                a = a * INV9 % MOD

                b = (-x * INV9) % MOD

                update(1, 1, n, l, r, a, b)

            else:
                _, l, r = operation

                total_value, total_count = query(
                    1, 1, n, l, r
                )

                if total_count == 0:
                    out.append("0")
                else:
                    answer = total_value * pow(
                        total_count, MOD - 2, MOD
                    ) % MOD
                    out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`pow10`配列には、各ボックスの静的重み (10^p) が含まれます。 の`invpow10`array は、(c-l+1) が負の場合を処理します。 使用する

 [
 10^{c-l+1}=10^c10^{-(l-1)}10
 ]

 渡されたすべての指数を保持します`pow`非負。 

セグメントツリーの`pow_sum`ボックスの位置は決して変わらないため、決して変わりません。 他の 3 つのノード量は動的です。`value_sum`ストリップ値のモジュール和を保存します。`count_sum`は通常の整数カウントを格納し、3 つの遅延配列は子に伝播する必要がある更新を記述します。 

中の注文は`apply`概念的に重要です。 まず、現在のノードが完全な更新を受け取ります。 その後のみ、遅延伝播は同じ更新をその子に延期します。 クエリが部分的にノードと交差する場合、`push`は降順の前に呼び出されるため、子は以前に祖先にのみ保存されていたすべての更新を参照します。 

カウントは意図的にモジュロ (M) で減算されません。 最大 (10^5) 個の操作はそれぞれ最大 (10^4) 個のストリップをクエリに寄与できるため、合計数は最大 (10^9) となり、(M=10^9+7) より小さくなります。 したがって、ゼロ以外のカウントは常に可逆モジュロ (M) であり、それを通常の整数として維持すると、ゼロ テストも直接的になります。 

Python の整数はオーバーフローしないため、中間積は`a * pow_sum[node]`安全です。 値の合計と遅延係数は、サイズが制御されたままになるように、算術演算後にモジュロ (M) で削減されます。

import io
import solution

def run(inp: str) -> str:

    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solution.input = sys.stdin.readline
        solution.solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run(

2 2 3
"""
) == "3907", "sample 1"

1 1 1 9 0

"""

# Boundary case with c = 0 and l > 1, which needs inverse powers of 10

 ## 特殊なケース

 空のクエリはモジュラー反転の前に処理されます。 のために```
1 1
2 1 1
```ルートは唯一のボックスを表し、`count_sum = 0`。 クエリは戻ります`(0, 0)`したがって、コードはすぐに追加されます`0`。 逆は試みられません。 

負の指数の場合は、逆べき乗配列によって処理されます。 のために```
3 2
1 3 3 1 0
2 3 3
```ストリップには長さ (c+1=1) があるため、その値は正確に`1`。 代数的には、

 [
 1\frac{10^{0+1}-1}{9}=1。 
]

 係数表現には次のものを使用します。 

[
 10^{c-l+1}=10^{-2}、
 ]

 これは次のように表されます`10^0 * 10^-2`。 セグメント ツリーは、この係数に (10^3)​​ を乗算し、定数 (1/9) を減算して回復します。`1`モジュロ (M)。 

境界の位置合わせは、包含間隔を通じて実装されたセグメント ツリーのハーフオープン ロジックによって処理されます。 のために```
4 2
1 2 4 3 1
2 3 4
```更新は位置 2、3、および 4 に正確に影響します。クエリは位置 3 と 4 にのみアクセスし、値を返します。`333`そして`3333`、合計付き`3666`そして数えます`2`。 結果は`1833`。 

すべてのタイプ 1 操作は置換ではなく新しいストリップを表すため、重複する更新は追加的です。 2 つの同一の更新が同じボックスに影響を与える場合、ノードの`value_sum`そして`count_sum`それぞれが 2 つの独立した貢献を受け取ります。 3 つのアップデートの追加`9`唯一のボックスに保存されたペアは、`(27,3)`、クエリは (27/3=9) を返します。 

Large (c) は 10 進文字列の構築に使用されることはありません。 (c=10^9) の場合、コードはべき乗剰余で (10^{c}\bmod M) を計算し、それを開始位置の事前計算された逆べき乗と組み合わせます。 結果の値は、数学的には桁が繰り返される巨大な整数と同一ですが、すべての算術演算はモジュロ (10^9+7) のままです。 

1 つのクエリ内のストリップの最大合計数は (10^9) に達する可能性がありますが、これはまだ (M) 未満です。 したがって、指定された制約の下では、分母はゼロ モジュロ (M) に一致することはできません。 カウントを通常の Python 整数として保存すると、モジュラー リダクションによって誤って情報が失われることも避けられます。
