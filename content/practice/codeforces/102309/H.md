 ## 解決策
 ## 問題の理解

 頂点が Orz Panda であり、エッジがデータ リンクである可能性がある無向グラフがあります。 すべてのエッジには 2 つの正の値があります。`a`そして`b`。 選択したエッジのセットに対して`S`、通信要件には、選択されたエッジが接続されたスパニング サブグラフを形成する必要があることが記載されています。 このようなセットのスコアは、

 [
 f(S)=\frac{\sum_{e\in S} b_e}{\sum_{e\in S} a_e}。 
】

 課題は、この比率を最大化することです。 

分母は常に正です。`a_e`は正であり、次のように接続されたグラフです。`n > 1`少なくとも 1 つのエッジが必要です。 グラフには少なくとも 1 つの接続されたスパニング サブグラフが含まれることが保証されているため、最適化問題には常に実行可能な解決策が存在します。 

制約が十分に大きいため、エッジ サブセットを列挙することは完全に不可能です。 最大 (10^5) 個のエッジでは、(O(m^2)) さえもすでに (10^{10}) 回の演算に近づきますが、必要なグラフ アルゴリズムは最適化ステップごとに (O(m\log m)) に近くなる必要があります。 頂点の数は最大 (10^4) であるため、素の集合結合構造は、接続されたコンポーネントを繰り返し維持するのに自然に適合します。 の値`a`そして`b`は (10^7) に達する可能性があるため、合計はおおよそ (10^{12}) に達する可能性があります。 Python の整数はこれを安全に処理しますが、浮動小数点は比率パラメータにのみ必要です。 

一見合理的な単純化が失敗するケースがいくつかあります。 

まず、答えはスパニング ツリーで表す必要はありません。 考慮する```
3 3
1 2 1 10
2 3 1 1
1 3 10 10
```エッジの選択`1-2`そして`2-3`3 つすべてを選択すると (21/12=1.75) が得られます (11/2=5.5)。 ここでは最適なソリューションがたまたまツリーになっていますが、この例は、個々の比率が大きいすべてのエッジを単に選択するだけでは十分ではないことを示しています。 接続性と累積された分子と分母を一緒に考慮する必要があります。 

第 2 に、変換されたエッジは負の値を持つ可能性がありますが、依然として必要です。 例えば、```
3 2
1 2 1 10
2 3 100 1
```唯一の接続されたソリューションには両方のエッジが含まれるため、答えは次のようになります。 

[
 \frac{10+1}{1+100}=\frac{11}{101}。 
】

 単純に正に変換された重みを持つエッジを保持する方法では、2 番目のエッジが破棄され、グラフが切り離されたままになります。 

第三に、いくつかのエッジはまったく同じ比率を持つことができます。 のために```
3 3
1 2 7 7
2 3 7 7
1 3 14 14
```実行可能なすべての選択肢にはスコア (1) が付けられます。 アルゴリズムは、ゼロ変換された重みを、途中で終了する理由として扱わずに処理する必要があります。 

## アプローチ

 ブルートフォースソリューションは概念的には単純です。 のすべてのサブセットを列挙します。`m`考えられるリンク。選択したエッジがすべて接続しているかどうかをテストします。`n`頂点を計算し、接続されているサブセットごとに、その合計の比率を計算します。`b`合計に対する値`a`価値。 (2^m) 個のサブセットがあり、DFS または DSU を使用して接続コスト (O(n+m)) をチェックしています。 したがって、最悪の場合の演算数は (O(2^m(n+m))) となり、(10^5) はおろか、数十のエッジでもすでに絶望的になります。 

さらに魅力的なアイデアは、最適な比率のスパニング ツリーを検索することです。 元の問題では余分なエッジが許可されているため、これでは十分ではありません。 追加のエッジは、独自の場合に比率を向上させることができます。`b/a`サイクルが発生する場合でも、比率は現在の比率を上回ります。 最適化はツリーだけでなく、接続されたサブグラフに対しても行われます。 

重要な観察は、比率目標を線形目標に一時的に置き換えることです。 答えが何らかの値 (\lambda) であると推測するとします。 接続されたエッジ セットの場合`S`、定義します

 [
 W_\lambda(S)=\sum_{e\in S}(b_e-\lambda a_e)。 
】

 真の最適値が (R) である場合、

 [
 R=\max_S\frac{B(S)}{A(S)}
 】

 と言うのと同じです

 [
 \max_S \left(B(S)-R A(S)\right)=0。 
】

 候補 (\lambda) の場合、エッジは重みを変換しました

 [
 w_e=b_e-\lambda a_e。 
】

 ここで、接続されているすべてのスパニング サブグラフ間で変換された最大合計重みを見つける必要があります。 

この補助問題は単純な貪欲構造を持っています。 正の変換された重みを持つすべてのエッジを含める必要があります。これを追加しても接続性が損なわれることはなく、厳密に変換された目的が増加するためです。 変換された対物レンズではコストがかからず、接続に役立つ可能性があるため、すべてのゼロ重みエッジを含めることもできます。 すべての非負のエッジが含まれた後、それらの端点はいくつかの接続されたコンポーネントを形成します。 残っている唯一の作業は、これらのコンポーネントを接続することです。 まだ考慮されているすべてのエッジには負の変換された重みがあるため、コンポーネントを接続する最も有害なエッジが必要です。 これはまさに、残りのコンポーネントに関する最大スパニング ツリーの問題であり、クラスカルのアルゴリズムは、変換された重みを最大から最小に処理することによって解決します。 

これにより、固定 (\lambda) に対する正確なオラクルが得られます。 

次に、ディンケルバッハの分数計画法を使用します。 実行可能な接続エッジ セットから開始し、その比率を (\lambda) とします。 (B-\lambda A) を最大化する接続された部分グラフを見つけます。 変換された値がゼロの場合、(\lambda) が最適です。 それ以外の場合は、新しく選択されたサブグラフの比率が厳密に優れているため、(\lambda) をその比率で置き換えて繰り返します。 

ブルート フォースは、実行可能なすべてのサブグラフを直接評価するため機能しますが、サブグラフの数が指数関数的なため失敗します。 比率を線形式に変換できるという観察により、最大重み接続サブグラフ オラクルが得られ、ディンケルバッハの方法は、そのオラクルへの繰り返し呼び出しを目的の最適値に変換します。 

比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^m(n+m))) | (O(n+m)) | 遅すぎる |
 | 二分探索 + 変換された接続部分グラフ オラクル | (O(Km\log m)) | (O(n+m)) | 正しいですが、多くの Oracle 呼び出しがあります。 
| ディンケルバッハ + 変換された接続部分グラフ オラクル | (O(Im\log m)) | (O(n+m)) | 承認済み |

 ここ`K`は二分探索の反復回数であり、`I`ディンケルバッハ反復数です。 この有限の組み合わせ問題では、ディンケルバッハは、選択された解を有限回変更した後に最適な比率に到達し、実際には反復回数は少なくなります。 承認されたコンテストのアプローチでは、数十回の固定精度の二分探索ラウンドに料金を支払うのではなく、この特性を使用します。 

## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、エッジ セット全体の比率 (\lambda=B_{\text{all}}/A_{\text{all}}) を計算します。 入力グラフ自体が接続されているため、完全なエッジ セットが実行可能なソリューションとなり、これにより有効な開始比率が得られます。 
2. (\lambda) の現在の値について、すべてのエッジに変換された重みを割り当てます。 

[
 w_e=b_e-\lambda a_e。 
】

 このパラメータで元の比率を最大化することは、これらの変換された重みの合計を最大化することと同じです。 
3. 変換された重みを減らすことによってすべてのエッジを並べ替えます。 DSU 構造を使用して、すでに受け入れられたエッジによって形成された接続コンポーネントを維持します。 
4. エッジに非負の変換された重みがある場合は常に、それを選択したサブグラフに含めます。 そのエンドポイントも DSU に統合されます。 ポジティブ エッジは変換された目標を増加させますが、ゼロ エッジは接続性のみを支援します。 
5. ネガティブに変換されたエッジの場合は、そのエンドポイントが現在別の DSU コンポーネントに属している場合にのみ含めます。 このようなエッジはこれらのコンポーネントを接続するために必要であり、クラスカルの順序付けにより、コンポーネントを接続するすべての方法の中で、選択された負のエッジが変換された合計を最大化することが保証されます。 
6. エッジの選択中に、元の分子と分母の両方を累積します。`sum_b`そして`sum_a`。 変換された目的も次と等しくなります。`sum_b - lambda * sum_a`。 
7. すべてのエッジが処理された後、次の計算を行います。 

[
 \lambda_{\text{new}}=\frac{\text{sum_b}}{\text{sum_a}}。 
】

 新しい値が現在の値から変化していない場合、変換された最適値はゼロとなり、現在の比率は最適になります。 それ以外の場合は、設定します`lambda = lambda_new`そして繰り返します。 
8. 最終的な比率を十分な小数桁で出力します。 小数点以下 12 桁あれば、必要な (10^{-9}) 絶対誤差または相対誤差には十分です。 

変換された部分問題が機能する理由は、その不変式によって捉えられます。つまり、変換された重みを減少させてエッジのプレフィックスを処理した後、DSU は、すでに考慮されたエッジを使用して取得できる接続性を正確に表しますが、選択されたセットは、その部分処理の対象となる最大の可能な変換値を持ちます。 すべての非負のエッジは、変換された問題の最適化において必須であり、依然として必要な負のエッジは、結果として得られるコンポーネント間に最大範囲フォレストを形成します。 

ディンケルバッハの部分では、(F(\lambda)) を、接続されたスパニング サブグラフにわたる (B(S)-\lambda A(S)) の最大値とします。 (\lambda<R) の場合、実行可能な解の比率は (\lambda) より大きいため、(F(\lambda)>0) になります。 (\lambda>R) の場合、すべての実行可能な解は最大​​でも (\lambda) の比を持つため、(F(\lambda)<0) となります。 最適(R)では、(F(R)=0)。 オラクルが正に変換された値を持つ解を返す場合、その比率は現在 (\lambda) よりも厳密に大きいため、シーケンスは最適値に向かって単調に移動します。 オラクルがゼロを返した場合、現在の値はまさに最適な比率です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    __slots__ = ("parent", "size")

    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        parent = self.parent
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(self, a, b):
        parent = self.parent
        size = self.size

        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]
        return True

def solve_case(n, edges):
    total_a = 0
    total_b = 0

    for u, v, a, b in edges:
        total_a += a
        total_b += b

    # The complete graph is connected, so this is a feasible starting point.
    lam = total_b / total_a

    # Dinkelbach iterations.
    while True:
        # Reordering the edge list is intentional. Timsort can reuse existing
        # order between iterations in many instances.
        edges.sort(key=lambda e: e[3] - lam * e[2], reverse=True)

        dsu = DSU(n)

        sum_a = 0
        sum_b = 0

        for u, v, a, b in edges:
            w = b - lam * a

            if w >= 0.0:
                # Every nonnegative transformed edge belongs to an optimum.
                sum_a += a
                sum_b += b
                dsu.union(u, v)
            else:
                # Negative edges are used only when they are necessary for
                # connecting two currently different components.
                if dsu.union(u, v):
                    sum_a += a
                    sum_b += b

        new_lam = sum_b / sum_a

        # At the exact optimum, the maximizing transformed solution has
        # ratio equal to the current parameter.
        if new_lam == lam:
            return lam

        lam = new_lam

def main():
    out = []

    while True:
        line = input()
        if not line:
            break

        n, m = map(int, line.split())
        edges = []

        for _ in range(m):
            x, y, a, b = map(int, input().split())
            edges.append((x - 1, y - 1, a, b))

        ans = solve_case(n, edges)
        out.append(f"{ans:.12f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```DSU は、サイズによる結合とパス圧縮を併用するため、各結合または検索操作は、関係する問題のサイズに対して事実上一定時間になります。 グラフの頂点は、1 から始まる入力インデックスから 0 から始まるインデックスに即座に変換されるため、すべての内部配列アクセスの一貫性が保たれます。 

最初のパスでは、すべてのエッジの比率が計算されます。 フルエッジセットは入力保証によって接続されているため、これは有効な実現可能な比率です。 ディンケルバッハの更新ごとに最適な比率に向けてのみ改善できるため、実行可能な比率から開始することは有益です。 

各反復内で、変換された重みは次のように評価されます。`b - lam * a`。 最大重みの問題を解決しているため、ソート順は降順になっています。 コードの扱い`w >= 0`無条件の包含として。 これには、変換された対物レンズを変更せずにコンポーネントを接続できるゼロウェイト エッジが含まれます。 

負のエッジの場合、DSU チェックはクラスカル条件です。 エンドポイントがすでに接続されている場合、エッジを追加しても、変換された目的が減少するだけです。 それらが異なるコンポーネントにある場合、接続されたグラフに向かって進むにはエッジが必要であるため、受け入れられます。 

オリジナル`a`そして`b`合計は浮動小数点変換された合計ではなく累積されます。 これにより、次の比率を計算するときに不要な数値エラーが回避されます。 すべての入力合計は Python 整数に快適に適合し、唯一の浮動小数点演算は変換された比較と比率の更新です。 

終了テストでは、任意のイプシロンではなく、浮動小数点比の等価性が使用されます。 すべての更新自体は 2 つの整数の合計の商であり、同じ最適な組み合わせ解が再度選択されると、計算された商は同じ Python 浮動小数点値で表されます。 これにより、単に選択したイプシロンが残りのギャップよりも大きいという理由だけで早期に停止することが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(Im\log m)) | 各ディンケルバッハ反復のソート`m`エッジの重みを変換し、(O(m\alpha(n))) DSU 作業を実行します。 
| スペース | (O(n+m)) | エッジ リスト、DSU 配列、メタデータの並べ替えには線形メモリが必要です。 

ここ`I`はディンケルバッハ反復回数を示します。 各反復はエッジのソートによって支配されますが、DSU 操作は実質的に線形です。 (m\le 10^5) を使用すると、グラフ自体はメモリ制限内で簡単に表現できます。 ディンケルバッハ反復の実際の回数は、非終端反復ごとに現在の比率を厳密により適切に変換された解の比率に置き換えるため、少なくなります。 

ここでは、固定の 60 ステップまたは 100 ステップの二分探索ではなくディンケルバッハを使用することが特に便利です。これは、すべての Oracle 呼び出しで最大 (10^5) エッジのソートが必要となるためです。 このような呼び出しの数を減らすことが、パフォーマンスに関する主な考慮事項です。

            return False

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]
        return True

def solve_case(n, edges):
    total_a = sum(e[2] for e in edges)
    total_b = sum(e[3] for e in edges)

    lam = total_b / total_a

    while True:
        edges.sort(key=lambda e: e[3] - lam * e[2], reverse=True)

        dsu = DSU(n)
        sa = 0
        sb = 0

        for u, v, a, b in edges:
            w = b - lam * a

            if w >= 0.0:
                sa += a
                sb += b
                dsu.union(u, v)
            elif dsu.union(u, v):
                sa += a
                sb += b

        new_lam = sb / sa

        if new_lam == lam:
            return lam

        lam = new_lam

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    out = []

    while True:
        line = sys.stdin.readline()
        if not line:
            break

        n, m = map(int, line.split())
        edges = []

        for _ in range(m):
            x, y, a, b = map(int, sys.stdin.readline().split())
            edges.append((x - 1, y - 1, a, b))

        out.append(f"{solve_case(n, edges):.12f}")

    sys.stdin = old_stdin
    return "\n".join(out)

 ## 特殊なケース

 頂点が 2 つだけのグラフには、最小の有効なインスタンス内に必要な接続が 1 つだけあります。 のために```
2 1
1 2 2 8
```唯一の実行可能なセットには単一のエッジが含まれるため、答えは (8/2=4) になります。 初期比率はすでに 4 で、変換された重みは 0 であるため、アルゴリズムはすぐに固定点に到達します。 

必須の低比率ブリッジは、変換されたオラクルの Kruskal 部分によって処理されます。 で```
3 2
1 2 1 10
2 3 100 1
```最初のエッジは高い変換値を持ち、2 番目のエッジは負です。 最初のエッジを受け入れた後、頂点 1 と 2 が 1 つのコンポーネントを形成し、頂点 3 が分離されます。 負のエッジはこれらのコンポーネントに結合するため、DSU はその負の寄与にもかかわらずそれを受け入れます。 最終的な比率は (11/101)、およそ`0.108910891089`。 

等しい比率は、もう 1 つの有用な境界ケースです。 で```
3 3
1 2 7 7
2 3 7 7
1 3 14 14
```すべてのエッジの比率は 1 です。(\lambda=1) では、変換されたすべての重みは正確に 0 になります。 オラクルにはエッジを含めることができ、結果の比率は 1 のままです。`w >= 0.0`ゼロウェイト エッジが接続を提供できるようになります。 

最大サイズのテストには、(10^4) 個の頂点と (10^5) 個のエッジが含まれており、すべてのエッジが次の条件を満たします。`a=b=10000000`。 合計は大きくなりますが、Python の整数はそれらを正確に表します。 すべてのエッジの比率が 1 であるため、変換された重みは (\lambda=1) で消え、答えは正確に 1 のままになります。このケースでは、指定された最大の入力次元で DSU とソート コードも実行されます。
