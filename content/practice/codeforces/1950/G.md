 ## 解決策
 ## 問題の理解

 各曲には、ジャンルと作家という 2 つの属性があります。 いくつかの曲を削除した後、残りの曲を任意に並べ替えることができます。 目標は、隣接する曲のすべてのペアが少なくとも 1 つの属性 (同じジャンル、同じ作者、またはその両方) を共有するように配置することです。 

できるだけ少ない曲を削除したいと考えています。 同様に、できるだけ多くの曲を保持し、それらの曲を有効なシーケンスに並べることができるかどうかを確認したいと考えています。 

問題をグラフとして表示するのは便利な方法です。 曲ごとに 1 つの頂点を作成します。 同じジャンルまたは同じ作者の 2 つの曲を接続します。 したがって、エキサイティングなプレイリストとは、まさに、連続するすべてのペアがエッジで接続された曲の順序です。 

つまり、選択したすべての頂点を 1 回だけ訪れるパスとして配置できる頂点の最大のサブセットを探しています。 グラフの用語では、グラフに含まれる最大のハミルトニアン パスのサイズが必要です。 答えは次のとおりです。$$n - (\text{maximum number of songs that can appear in such a path})$$制約によって、意図されたアプローチが明らかになります。 曲数は多くても16曲と非常に少ないです。 指数関数的なソリューション$n$可能です。 このステートメントは、次のような強力なヒントさえ与えています。$2^n$すべてのテストケースで次を超えない$2^{16}$。 これは、サブセット動的プログラミングの古典的なセットアップです。 

文字列の長さが長くても、アルゴリズム的には問題になりません。 ジャンルと作家が平等であるかどうかのみを比較します。 文字列が読み取られると、各ペアの曲を個別にチェックできます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

単一の曲について考えてみましょう。```
1
pop taylor
```正解は 0 です。1 つの頂点からなるパスはすでに有効です。 パス内に少なくとも 1 つのエッジを必要とする実装では、誤って 1 が返されます。 

まったく関係のない 3 つの曲を考えてみましょう。```
3
a x
b y
c z
```2 つの曲を隣接させることはできません。 最大の有効なプレイリストにはちょうど 1 つの曲が含まれるため、答えは 2 です。不注意な実装では、接続されているすべてのコンポーネントがそのすべての頂点に寄与すると想定する可能性があります。 

最適なソリューションが接続コンポーネントのすべての頂点を使用しないグラフを考えてみましょう。```
4
a x
a y
b y
c z
```曲 1、2、および 3 はチェーンを形成し、曲 4 は分離されています。 最適なプレイリストでは、曲 1、2、および 3 が保持されます。答えは 1 です。接続だけでは十分ではありません。 選択したサブセット上の実際のハミルトニアン パスが必要です。 

## アプローチ

 最も直接的な強引なアイデアは、曲のすべてのサブセットとそのサブセット内のすべての順序を試すことです。 サイズのサブセットの場合$k$、 がある$k!$可能な注文。 最悪の場合こうなります$$\sum_{k=0}^{n} \binom{n}{k} k!$$それはすでに巨大なものです$n=16$。 16 曲のすべての順列をチェックするだけでも、おおよその時間がかかります$2 \times 10^{13}$命令、完全に実行不可能です。 

ブルート フォースが概念的に機能する理由は、注目するプロパティが順序内の連続する曲のみに依存するためです。 課題は、考えられるすべての順序の列挙を回避することです。 

重要な観察は、グラフには 16 個の頂点しかないことです。 頂点のサブセットをパスに配置できるかどうかを問う問題が発生するたびに、ハミルトニアン パス スタイルのビットマスク DP が自然になります。 

させて`dp[mask][last]`意味:

 "の頂点を正確に使用すると、`mask`、最終頂点が次である有効なパスはありますか?`last`？」

 そのようなパスが存在する場合は、別の頂点を追加できます`nxt`間にエッジがあるときはいつでも`last`そして`nxt`。 

これにより、順列列挙がサブセットに対する動的プログラミングに変換されます。 各状態は、一度に多数の可能な順序を表します。 

ある状態が到達可能なサブセットの最大サイズによって、保持できる曲の最大数が決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適なビットマスク DP |$O(2^n \cdot n^2)$|$O(2^n \cdot n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての曲を読みます。 
2. 曲の無向グラフを構築します。 

曲をつなぐ`i`そして`j`ジャンルが同じだったり、作家が同じだったりする場合。 
3. DP テーブルの作成`dp[mask][last]`。`dp[mask][last] = True`の頂点を正確に使用する有効なパスが存在することを意味します。`mask`そして終わる`last`。 
4. すべてのシングルトン サブセットを初期化します。 

どの曲にも`i`:`dp[1<<i][i] = True`単一の曲が常に有効なパスです。 
5. すべてのマスクを繰り返し処理します。 

到達可能なすべての状態について`(mask, last)`、パスを延長してみてください。 
6. 頂点ごとに`nxt`まだ入っていない`mask`、間にエッジがあるかどうかを確認します。`last`そして`nxt`。 

ある場合は、次のマークを付けます。`dp[mask | (1<<nxt)][nxt] = True`これは追加に対応します`nxt`既存のパスの終点まで。 
7. 状態に到達可能になるたびに、設定されたビット数を使用して最大パス長を更新します。`mask`。 
8. すべての状態を処理した後、`best`到達可能な最大のサブセット サイズになります。 
9. 出力`n - best`。 

### なぜ効果があるのか

 DP 状態には、パスを拡張するために必要な情報 (どの頂点がすでに使用されているか、どの頂点が現在終点にあるか) が正確に保存されます。 

初期化は、長さ 1 のすべてのパスをカバーします。 

すべての遷移で現在のエンドポイントに接続された新しい頂点が追加されるため、生成されたパスはすべて有効になります。 

逆に、有効なパスは、最後の頂点を繰り返し削除することで再構築できます。 最初の頂点から開始して、DP はこれらの拡張子を介してすべての有効なパスを再現します。 

すべての有効なパスは何らかの到達可能な DP 状態に対応し、すべての到達可能な DP 状態は有効なパスに対応するため、DP は可能なすべての有効なプレイリストを正確に列挙します。 到達可能なサブセットの最大サイズは、まさに保持できる曲の最大数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        genre = []
        writer = []

        for _ in range(n):
            g, w = input().split()
            genre.append(g)
            writer.append(w)

        adj = [[False] * n for _ in range(n)]

        for i in range(n):
            for j in range(i + 1, n):
                if genre[i] == genre[j] or writer[i] == writer[j]:
                    adj[i][j] = adj[j][i] = True

        m = 1 << n
        dp = [[False] * n for _ in range(m)]

        best = 1

        for i in range(n):
            dp[1 << i][i] = True

        for mask in range(m):
            length = mask.bit_count()

            for last in range(n):
                if not dp[mask][last]:
                    continue

                if length > best:
                    best = length

                for nxt in range(n):
                    if mask & (1 << nxt):
                        continue

                    if adj[last][nxt]:
                        dp[mask | (1 << nxt)][nxt] = True

        print(n - best)

solve()
```グラフの構築は、ステートメント内の隣接ルールに直接従います。 2 つの曲は、隣り合って表示される場合でも正確に接続されます。 

DP テーブルには、パスの長さではなく到達可能性が格納されます。 すべての状態がビットマスクを通じて使用される頂点の数を一意に決定しているため、到達可能性は十分です。 

シングルトンの初期化は必須です。 これがなければ、1 つの曲で構成されるパスは存在せず、孤立した頂点に対する不正解の原因となります。 

トランジションでは常に、新しい未使用の頂点が追加されます。 ビットマスクは使用されたすべての頂点を記録するため、同じパス内に頂点が 2 回出現することはできません。 

変数`best`DP 内の任意の場所で検出された、到達可能な最大のサブセットを追跡します。 パスが特定の頂点で終わる必要はないため、到達可能なすべてのエンドポイントが考慮されます。

    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    out = []

    t = int(input())

    for _ in range(t):
        n = int(input())

        genre = []
        writer = []

        for _ in range(n):
            g, w = input().split()
            genre.append(g)
            writer.append(w)

        adj = [[False] * n for _ in range(n)]

        for i in range(n):
            for j in range(i + 1, n):
                if genre[i] == genre[j] or writer[i] == writer[j]:
                    adj[i][j] = adj[j][i] = True

        m = 1 << n
        dp = [[False] * n for _ in range(m)]

        best = 1

        for i in range(n):
            dp[1 << i][i] = True

        for mask in range(m):
            for last in range(n):
                if not dp[mask][last]:

                        dp[mask | (1 << nxt)][nxt] = True

        out.append(str(n - best))

    return "\n".join(out)

## 特殊なケース

 単一の曲について考えてみましょう。```
1
pop taylor
```DP が初期化されます`dp[1][0] = True`。 遷移は存在しませんが、到達可能なサブセット サイズはすでに 1 です。`best = 1`そして答えは`1 - 1 = 0`。 

完全に切り離された曲を考えてみましょう。```
3
a x
b y
c z
```すべてのシングルトン マスクに到達可能です。 グラフのエッジがないため、これより大きなマスクには到達できません。 到達可能な最大サブセット サイズは 1 のままで、答えが得られます。`3 - 1 = 2`。 

完全には使用できない接続コンポーネントを考えてみましょう。```
4
a x
a y
b y
c z
```グラフにはエッジが含まれています`(1,2)`そして`(2,3)`。 頂点 4 が分離されます。 DP はパスに対応するマスクに到達します`1 -> 2 -> 3`、サイズ 3 を達成します。サイズ 4 の状態には到達できなくなります。 アルゴリズムは正しくレポートします`4 - 3 = 1`。 

これはまさに、ハミルトニアン パス DP は正しいままで、接続性だけをチェックすると失敗するような状況です。
