 ## 解決策
 ## 問題の理解

 3 桁の数字が与えられていますが、`a`、`b`、 そして`c`、そして彼らの関係を分類する必要があります。 

A sequence is called a **stair** when the values strictly increase from left to right, meaning`a < b < c`。 

中央の値が両方の隣接値よりも厳密に大きい場合、シーケンスは **ピーク** と呼ばれます。`a < b`そして`b > c`。 

どちらの条件も満たされない場合は、印刷します。`"NONE"`。 

各テスト ケースには 3 つの数値のみが含まれており、テスト ケースは最大 1000 個あります。 すべての分類で必要な比較はわずか数回だけであるため、テスト ケースごとの作業量は一定です。 単純な実装であっても、実行される操作はほんのわずかであるため、効率が問題になることはありません。 

主な課題は、厳密な不平等を正しく処理することです。 Equal values do not satisfy either definition.

 次の入力を考えてみましょう。```
1
1 1 2
```正しい答えは次のとおりです。```
NONE
```シーケンスが非減少であるかどうかのみをチェックする不注意な実装では、シーケンスを誤って階段として分類する可能性があります。 

もう 1 つの簡単な間違いは、左側の上昇を確認せずに極大値をピークとして扱うことです。```
1
3 2 1
```正しい答えは次のとおりです。```
NONE
```それでも`2 > 1`、条件`3 < 2`は false であるため、これはピークではありません。 

3 番目のエッジ ケースは、すべての値が等しい場合に発生します。```
1
0 0 0
```正しい出力は次のとおりです。```
NONE
```厳密な増加も厳密なピーク条件も当てはまりません。 

## アプローチ

 最も直接的なアプローチは、3 つの数値をすべて調べて、それらが定義を満たしているかどうかをテストすることです。 問題自体が不等式を使用して階段と頂点を定義しているため、これらの不等式を単純に評価できます。 

ブルート フォース ソリューションでは、考えられるすべてのパターンをチェックし、それに応じて値を比較します。 各テスト ケースには正確に 3 桁の数字が含まれているため、これはすでに定数時間で実行されます。 1000 のテスト ケースがあっても、合計の作業量はわずかです。 

重要な観察は、発見すべき隠れた構造がないということです。 この問題は純粋に実装の練習です。 定義はコードに直接変換できます。 

まず、次のことを確認します。`a < b < c`。 本当であれば、答えは次のとおりです`"STAIR"`。 

それ以外の場合は、`a < b > c`。 本当であれば、答えは次のとおりです`"PEAK"`。 

どちらの条件も一致しない場合、答えは次のようになります。`"NONE"`。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`a`、`b`、 そして`c`。 
3. かどうかを確認します。`a < b < c`。 

これは階段の定義と正確に一致します。 
4. 前の条件が false の場合は、次のことを確認します。`a < b > c`。 

これはピークの定義と正確に一致します。 
5. どちらの条件も真でない場合、出力`"NONE"`。 

### なぜ効果があるのか

 この問題では、両方の有効な分類の完全な定義が提供されます。 

シーケンスは次の場合にのみ階段になります。`a < b < c`。 シーケンスは次の場合にのみピークになります。`a < b > c`。 値が同時に満たすことはできないため、これらの条件は相互に排他的です。`b < c`そして`b > c`。 

アルゴリズムは階段の定義を直接テストし、次にピークの定義を直接テストします。 残りのシーケンスはどちらの定義も満たさないため、次のように分類する必要があります。`"NONE"`。 考えられる入力はすべてこれらのケースのいずれかに該当するため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b, c = map(int, input().split())

    if a < b < c:
        print("STAIR")
    elif a < b > c:
        print("PEAK")
    else:
        print("NONE")
```最初の部分はテスト ケースの数を読み取ります。 

テスト ケースごとに 3 桁が読み取られ、次の場所に保存されます。`a`、`b`、 そして`c`。 

条件`a < b < c`Python の連鎖比較構文を使用します。 両方をチェックするのと同じです`a < b`そして`b < c`。 

その条件が失敗した場合、コードはテストを実行します。`a < b > c`、これは両方をチェックするのと同じです`a < b`そして`b > c`。 

順序は、単一の答えを出力したいという理由だけで重要になります。 実際には、2 つの条件が同時に真になることはありません。 

値が等しい場合は、自動的に次のようになります。`"NONE"`どちらの定義も厳密な不等式を必要とするためです。

import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    ans = []

        a, b, c = map(int, input().split())

        if a < b < c:
            ans.append("STAIR")
        elif a < b > c:

        else:
            ans.append("NONE")

    return "\n".join(ans) + "\n"

 ## 特殊なケース

 次のことを考慮してください。```
1
1 1 2
```アルゴリズムチェック`1 < 1 < 2`、これは誤りです。`1 < 1`は誤りです。 次にチェックします`1 < 1 > 2`、これも誤りです。 出力は`"NONE"`。 これは等価性を正しく処理します。 

考慮する：```
1
3 2 1
```階段条件は次の理由で失敗します。`3 < 2`は誤りです。 The peak condition also fails because`3 < 2`は誤りです。 出力は次のようになります`"NONE"`。 これにより、減少シーケンスを誤ってピークとしてラベル付けすることが防止されます。 

考慮する：```

0 0 0
```どちらでもない`0 < 0 < 0`または`0 < 0 > 0`それは本当です。 アルゴリズムは出力します`"NONE"`、これは厳密な不等式を必要とする定義と一致します。 

考慮する：```
1
2 5 5
```階段条件は次の理由で失敗します。`5 < 5`は誤りです。 ピーク条件が失敗する理由は、`5 > 5`は誤りです。 結果は`"NONE"`。 これにより、隣接する等しい値が誤って有効なものとして扱われるというよくある間違いが見つかります。
