 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`長さの`n`。 可能な限り短い長さを見つけたい`L`パターン文字列が存在するような`k`長さの`L`、正確に繰り返されました`n / L`回、文字列を生成する`c`長さの`n`、 そして`c`とは異なります`s`多くても 1 つの位置で。 

つまり、最大 1 文字を変更した後、`s`、結果の文字列はピリオドの長さで完全に周期的になる必要があります。`L`。 すべての有効期間の中で、最も短いものが必要です。 

このステートメントから得られる重要な観察点は、繰り返される文字列が文字列全体の長さをカバーする必要があるため、候補となるピリオドの長さは分割する必要があるということです。`n`。 

すべてのテスト ケースの合計の長さは最大でも`2 · 10^5`。 これは十分に大きいため、考えられるすべてのパターンと考えられるすべての部分文字列を単純に比較すると、コストが高くなる可能性があります。 周りのアルゴリズム`O(n · d(n))`、 どこ`d(n)`は約数です。以下の最大の数であっても完全に安全です。`2 · 10^5`約数が比較的少ない。 アン`O(n²)`最悪の場合、アプローチが遅すぎます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
n = 4
s = abaa
```答えは`1`、 なぜなら`"aaaa"`ちょうど 1 つの位置が異なります。 元の文字列がすでに周期的であるかどうかのみをチェックするソリューションでは、ピリオドが誤って拒否されます。`1`。 

考慮する：```
n = 4
s = abba
```答えは`4`。 どちらの時代でもない`1`期間もありません`2`単一の文字変更で修正できます。 各剰余クラスで最も頻繁に使用される文字を貪欲に選択するソリューションでは、その期間が誤って結論付けられる可能性があります。`2`動作します。 

考慮する：```
n = 6
s = aaabaa
```答えは`1`。 文字列は異なります`"aaaaaa"`ちょうど 1 つの位置にあります。 このケースは、単一の不良文字がどこにでも現れる可能性があり、必ずしも最初のピリオド ブロック内に現れるとは限らないことを示しています。 

別の微妙なケースは次のとおりです。```
n = 8
s = ababcbab
```期間`2`機能しません。 この不一致は、同じ間違った文字を含む複数の比較で発生します。 実際の文字の変更をカウントする代わりに、ペアごとの不一致をカウントすると、必要な変更が過大評価される可能性があります。 

## アプローチ

 自然な総当たりアプローチは、すべての約数を試すことです`L`の`n`、可能なすべての長さのピリオド文字列を生成します`L`、それを繰り返して一致するかどうかを確認します`s`最大でも 1 つの不一致があります。 

問題は、使用可能なピリオド文字列が指数関数的に多く存在することです。 中に現れるピリオド文字列に限定しても`s`すぐには役に立ちません。 探索空間は膨大になります。 

1 文字だけが間違っている可能性があるという事実を利用する必要があります。 

候補期間の長さを固定するとします`L`。 あらゆるポジション`i`残基クラスに属します`i mod L`。 完全に周期的な文字列では、同じ剰余クラス内のすべての文字が等しくなければなりません。 

たとえば、`L = 3`:```
positions: 0 1 2 3 4 5 6 7 8
residues : 0 1 2 0 1 2 0 1 2
```各残基クラスには、単一の反復文字が含まれている必要があります。 

文字列全体を最大 1 つの変更で修復できる場合、残基クラスごとに位置をグループ化した後、おそらく 1 つを除くすべての位置が最終的な周期パターンとすでに一致しています。 

重要な点は、最大 1 文字が間違っている場合、正しいピリオド文字列は既存の長さのブロックの 1 つと等しくなければならないということです。`L`。 

なぜ？ 

最後の周期文字列にピリオドが使用されていると仮定します。`k`。 文字列全体の 1 つの位置だけが間違っているため、おそらく 1 つを除くすべてのブロックは次と同一です。`k`。 したがって、元の文字列の一部のブロックはすでに等しい必要があります`k`。 

これにより、検索スペースが直ちに減少します。 固定除数の場合`L`、既存の長さのブロックから取得した周期候補をテストするだけで済みます。`L`。 

がある`n / L`ブロック。 すべてを単純にテストするのはコストがかかりすぎますが、誤った文字が含まれるブロックは 1 つだけであるため、最初の 2 つのブロックをチェックするだけで十分です。 

有効な期間が存在する場合、すべての正しいブロックは真の期間と等しくなります。 最大で 1 つのブロックが異なります。 最初の 2 つのブロックのうち、少なくとも 1 つは正しい必要があります。 

したがって、各約数について`L`、テストします:```
candidate = first block
candidate = second block (if it exists)
```候補ごとに、繰り返されたパターンを文字列全体と比較し、不一致をカウントします。 不一致数が最大 1 の場合、`L`有効です。 

これにより、問題はすべての約数について少数の候補をチェックすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 期間の長さの指数 | O(L) | 遅すぎる |
 | 最適 | O(n · d(n)) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての約数を列挙します`L`の`n`昇順で。 
2. 各約数について、文字列を長さのブロックに分割します。`L`。 
3. 最初のブロックを使用して候補期間を構築します。 
4. 繰り返された候補を文字列全体と比較し、不一致をカウントします。 
5. 不一致数が 1 つ以下の場合は、リターンします。`L`除数は昇順に処理されるため、すぐに処理されます。 
6. それ以外の場合、複数のブロックがある場合は、2 番目のブロックを使用して 2 番目の候補を構築します。 
7. この 2 番目の候補を文字列全体と比較します。 
8. 不一致数が 1 つ以下の場合は、リターンします。`L`。 
9. 次の約数に進みます。 
10. より小さな除数が機能しない場合は、`L = n`文字列自体をピリオドとして使用できるため、常に機能します。 

### なぜ効果があるのか

 何らかの約数を仮定します`L`有効です。 させて`k`修理された弦の真の期間になります。 

文字列全体で間違っている可能性があるのは 1 文字だけであるため、最大でも 1 ブロックの長さになります。`L`とは異なります`k`。 1 つおきのブロックは次とまったく同じです`k`。 

最初の 2 つのブロックのうち、少なくとも 1 つは破損したブロックであってはなりません。 したがって、それらの少なくとも 1 つは真の周期と等しくなります。`k`。 

アルゴリズムがそのブロックを候補としてテストすると、繰り返される候補はまさに修復された文字列になります。 元の文字列に対する不一致数は最大 1 であるため、アルゴリズムは受け入れます。`L`。 

逆に、アルゴリズムが候補を受け入れる場合、その候補を繰り返すと、次とは異なる文字列が生成されます。`s`多くても 1 つの位置で。 これはまさに問題が要求する条件です。 

約数は昇順に処理されるため、最初に受け入れられた約数が可能な最小の答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def works(s, n, d, pat):
    mism = 0
    for i in range(n):
        if s[i] != pat[i % d]:
            mism += 1
            if mism > 1:
                return False
    return True

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        divisors = []
        i = 1
        while i * i <= n:
            if n % i == 0:
                divisors.append(i)
                if i * i != n:
                    divisors.append(n // i)
            i += 1

        divisors.sort()

        answer = n

        for d in divisors:
            block_cnt = n // d

            cand1 = s[:d]
            if works(s, n, d, cand1):
                answer = d
                break

            if block_cnt > 1:
                cand2 = s[d:2 * d]
                if works(s, n, d, cand2):
                    answer = d
                    break

        print(answer)

solve()
```ヘルパー関数`works`候補ピリオドが異なる文字列を生成できるかどうかをチェックします。`s`多くても 1 つの位置で。 繰り返される文字列を明示的に構築する代わりに、文字を比較します。`s[i]`と`pat[i % d]`。 これにより、余分なメモリが回避され、チェックが線形に保たれます。 

除数の生成では、標準の平方根列挙が使用されます。 各約数のペアが加算され、リストが並べ替えられて、期間が最小のものから最大のものまでテストされます。 

各約数について、アルゴリズムは最初の 2 つのブロックのみを検査します。 これが重要な最適化です。 正当性の引数は、有効な期間が存在する場合、これら 2 つのブロックの 1 つが真の期間と等しくなる必要があることを示しています。 

内部の早めの出口`works`重要です。 複数の不一致が現れると、その候補は決して有効にはならないため、文字列のスキャンを続ける理由はありません。

def solve():
    input = sys.stdin.readline

    def works(s, n, d, pat):
        mism = 0
        for i in range(n):
            if s[i] != pat[i % d]:
                mism += 1
                if mism > 1:
                    return False
        return True

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        divs = []
        i = 1

    sys.stdout = old
    return out.getvalue()
