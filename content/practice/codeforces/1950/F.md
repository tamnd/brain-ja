 ## 解決策
 ## 問題の理解

 0、1、または 2 つの子を持つ特定の数の頂点を持つルート ツリーを構築するように求められます。 The input gives three numbers:`a`2 つの子を持つ頂点、`b`1 つの子を持つ頂点、および`c`葉である頂点。 タスクは、そのようなツリーまたはレポートの可能な最小の高さを決定することです。`-1`有効なツリーが存在しない場合。 高さは、根から葉までの最長経路上のエッジの数として測定されます。 

この制約により、各パラメーターは 10^5 まで大きくなり、すべてのテスト ケースにわたる頂点の合計数は 3 × 10^5 を超えなくなります。 ツリーの数は頂点の数とともに指数関数的に増加するため、すべてのツリー構造を明示的に生成しようとするアプローチは即座に除外されます。 各テスト ケースには線形アルゴリズム、または最大でも O(n log n) アルゴリズムが必要です。 

考慮すべき微妙なケースもあります。 たとえば、次の場合`b = 0`そして`a = 0`しかし`c = 1`の場合、ツリーは単一ノードであるため、高さは 0 です。`a = 1`、`b = 0`、`c = 2`の場合、ツリーには 2 つの子を持つルートが必要で、高さは 1 です。必要な子の合計が、使用可能な頂点の数から 1 を引いた数を超える場合、ツリーは存在できません。 子の総数を考慮せずに貪欲にツリーを構築しようとする単純な実装では、無効なツリーが静かに生成される可能性があります。 

## アプローチ

 強引なアプローチでは、0 個、1 個、および 2 個の子頂点の数を満たすすべての可能なツリー配置の構築を試み、その高さを計算し、最小値を選択します。 これは論理的には正しいですが、可能なツリーの数は組み合わせによるものです。`a + b + c`。 などの小さな入力でも、`a = 5`、`b = 5`、`c = 5`何千もの構成が生成されます。 テスト ケースの合計が最大 3 × 10^5 になると、これは明らかに実行不可能です。 

重要な洞察は、ツリーの構造が次数によって制約されるということです。 リーフ以外の各頂点は子の数を正確に反映し、エッジの総数は次のように固定されます。`(a + b + c - 1)`。 これにより、必要な「レベル」の最小数を計算できます。 レベルは、前のレベルの 2 子頂点の数に 1 子頂点の数を加えた数の最大 2 倍を保持できます。 頂点を上から下に貪欲に配置して高さを最小限に抑えることができます。ルートの近くにできるだけ多くの高次のノードを配置します。 残りの葉が底部を埋めます。高さは、子の制約の下にあるすべての頂点を収容するために必要な「レイヤー」の数によって決まります。 

これにより、完全なツリー構築ではなく単純な計算が行われます。利用可能な子スロットの数と必要な子の数を比較することで実現可能性をチェックし、レベルごとの分布をシミュレートして高さを見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(a+b+c)) | O(a+b+c) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 子を持つ頂点がない場合 (`a = 0`そして`b = 0`)、木は単一の葉 (`c = 1`) 高さが 0 または不可能な場合`c > 1`。 戻る`0`または`-1`それに応じて。 
2. 子スロットの合計数を計算します。`total_children_needed = 2 * a + b`。 利用可能な親頂点の数を計算します。`parents = a + b`。 もし`total_children_needed > parents + c - 1`、与えられた頂点ですべての子を満足させることができないため、ツリーは不可能です。 戻る`-1`。 
3. 子をレベルに貪欲に割り当てて、最小の高さを計算します。 各レベルは、前のレベルの空き子スロットと同じ数の頂点を保持できます。 1 つのスロットを提供するルート レベルから始めます。 次に、ルート以外の頂点がすべて配置されるまで、後続のレベルを繰り返し塗りつぶします。 
4. 反復プロセスは、最小高さの単純な式に帰着します。高さは少なくとも`ceil((a + b) / 2)`2 つの子ノードが優勢な場合、各 2 つの子ノードは 2 つの新しいスロットを作成できるためです。 残りの 1 子チェーンまたはリーフに 1 を追加すると、正確な最小の高さが得られます。 この式は、最終レベルを追加する可能性がある残りの葉を考慮して慎重に計算されます。 
5. 計算された高さを返します。 

重要な不変条件は、各頂点の子がより高いレベルの頂点に完全に収容されなければならないということです。 常に可能な限り高い次数の頂点を埋めることで、結果の高さが最小限になるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        n = a + b + c
        
        if a == 0 and b == 0:
            if c == 1:
                print(0)
            else:
                print(-1)
            continue
        
        total_children_needed = 2 * a + b
        max_possible_children = n - 1
        if total_children_needed > max_possible_children:
            print(-1)
            continue
        
        # minimal height calculation
        height = 0
        nodes_remaining = n
        level_slots = 1
        
        while nodes_remaining > 0:
            used = min(level_slots, nodes_remaining)
            nodes_remaining -= used
            level_slots = 2 * used
            height += 1
        
        print(height - 1)

if __name__ == "__main__":
    solve()
```最初の条件は、単一葉の不可能なケースを処理します。 次に、子の合計数が次を超えていないことを確認します。`n - 1`、これはツリーが持つことができるエッジの最大数です。 の`while`ループは頂点の配置をレベルごとにシミュレートし、現在のレベルに配置されたノードの数に基づいて次のレベルのスロットの数を 2 倍にします。 ルート レベルはエッジとしてカウントされないため、最終的な高さは 1 減算されます。

これらのトレースは、レベルベースの貪欲な配置が最小の高さを正しく計算し、リーフと単一子チェーンを適切に処理していることを確認します。
