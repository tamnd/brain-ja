 ## 解決策
 ## 問題の理解

 整数の配列とセグメントのコレクションが与えられ、それぞれが開始インデックスと終了インデックスによって定義されます。 各セグメントを最大 1 回適用して、そのセグメント内のすべての値を 1 つ減らすことができます。 私たちの目標は、セグメントの一部のサブセットを選択して、それらを適用した後に、結果の配列内の最大要素と最小要素の差が最大になるようにすることです。 出力では、この最大差、使用されたセグメントの数、およびそれらのセグメントのインデックスが報告されます。 

ここでの重要な制約は配列のサイズであり、最大 100,000 要素にすることができます。 セグメントの数ははるかに少なく、最大 300 です。セグメントの任意のサブセットを選択できるため、セグメントのすべての組み合わせを考慮する総当りアプローチでは、最大 300 個のセグメントが必要になります。$2^{300}$まったく実行不可能な操作です。 これは、どのソリューションでも、すべてのサブセットを盲目的に試すのではなく、少数のセグメントを活用する必要があることを示しています。 配列サイズは、セグメントごとの操作が効率的であり、理想的には線形またはほぼ線形である必要があることを示唆しています。$n$、 なぜなら$n$大きくなる可能性があります。 

最適な選択に配列の最大値を含むセグメントをスキップすることが含まれる可能性がある場合、微妙なエッジ ケースが発生します。 たとえば、配列が`[5, 1, 2]`1 つのセグメントは 5 のみをカバーし、そのセグメントを適用すると最大値が減少し、差が増加するのではなく減少します。 もう 1 つの注意が必要な状況は、複数のセグメントが重なっている場合です。 最小要素をカバーするすべてのセグメントを無差別に適用すると、特定の位置が過度に減少する可能性があるため、最大要素を避けるセグメントを選択的に適用する必要があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのセグメントのサブセットに対して反復処理が行われます。 サブセットごとに、セグメントを配列に適用し、新しい最大値と最小値を計算し、確認された最大の差を追跡します。 複雑さは$O(2^m \cdot n)$、次の場合にのみ受け入れられます。$m$とても小さいです。 と$m$300 までは、このアプローチは不可能です。 

重要な洞察は、$m$が小さい場合、この要素が最終配列の最大値のままであると仮定して、各配列位置を潜在的な「アンカー」として試すことができます。 このような最大候補を修正したら、**この最大値をカバーしない**すべてのセグメントを安全に適用して、他の要素を減らし、差を増やすことができます。 これにより、問題が反復処理に軽減されます。$n$可能な最大位置と確認$m$それぞれのセグメント、つまり$O(n \cdot m)$。 これは実現可能なので、$n \cdot m \le 10^5 \cdot 300 = 3 \cdot 10^7$、制限時間 2 秒以内であれば許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(n) | 遅すぎる |
 | 最適 | O(n * m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 全体の最大差と対応するセグメント インデックスを追跡するために変数を初期化します。 
2. すべてのインデックスをループします。`i`配列内で。 考慮する`a[i]`いくつかのセグメントを適用した後に結果として得られる配列の最大値として残る要素として。 
3. この候補の最大値について`a[i]`、**インデックスをカバーしていないセグメントのリストを作成します`i`**。 これらのセグメントを適用すると、他の要素が減少するだけであり、選択した最大値は減少しません。 
4. 一時配列を作成する`b`のコピーとして初期化される`a`。 
5. 選択した各セグメントを、そのセグメント内のすべての値を減分して適用します。 これらのセグメントは候補の最大値に影響を与えないため、これは安全です。 
6. 結果の配列の最大値と最小値を計算します。`b`。 
7. 差を計算します`diff = max(b) - min(b)`。 もし`diff`がこれまでに見つかった最良の差よりも大きい場合、最良の差を更新し、適用されたセグメントのリストを保存します。 
8. すべての候補最大値をテストした後、最大差、適用されたセグメントの数、およびこれらのセグメントのインデックスを出力します。 

**なぜ効果があるのか**

 最適な構成では、すべてが減少した後も最大値に残る要素が存在するため、アルゴリズムは最適な解決策を見つけることが保証されています。 すべての要素を最大値の候補として試し、それを回避するすべてのセグメントを適用することで、最大値を維持するすべての構成を使い果たします。 候補の最大値に触れないセグメントのみを考慮するため、候補の最大値を誤って削減することはなく、計算された差がその最大値を考慮して最大となることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
segments = [tuple(map(int, input().split())) for _ in range(m)]

best_diff = -1
best_segments = []

for i in range(n):
    apply = []
    for j, (l, r) in enumerate(segments):
        if not (l-1 <= i <= r-1):
            apply.append(j)
    b = a[:]
    for j in apply:
        l, r = segments[j]
        for k in range(l-1, r):
            b[k] -= 1
    current_diff = max(b) - min(b)
    if current_diff > best_diff:
        best_diff = current_diff
        best_segments = apply

print(best_diff)
print(len(best_segments))
print(' '.join(str(x+1) for x in best_segments))
```コードはまず配列とセグメントを読み取ります。 各候補の最大値をループします`i`、回避するすべてのセグメントを収集します`i`、配列のコピーに適用します。 次に、この一時配列の最大値と最小値の差を計算します。 差が以前の最良の差よりも大きい場合は、結果を更新します。 セグメントは内部的には 0 ベースとして保存されますが、出力は 1 ベースとして行われます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m * n) 最悪の場合 | 各候補最大値 (n) について、m 個のセグメントをスキャンし、それらをサイズ n までのサブアレイに適用します。 |
 | スペース | O(n + m) | 配列のコピーとセグメントのリスト |

 実際には、`m`は小さい (≤ 300) ため、トリプル ループは許容されます。 もし`n`巨大だったし、`m`中程度の場合は、プレフィックス合計を使用して、操作ごとに O(n) ではなく O(1) のセグメントを適用する最適化が可能です。 これでも 2 秒の制限内に収まります。
