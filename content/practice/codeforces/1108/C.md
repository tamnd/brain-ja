 ## 解決策
 ## 問題の理解

 ランプのラインが与えられ、それぞれが R、G、B の 3 色のいずれかで塗られています。どのランプでも他の色に塗り直すことができます。 目標は、「特定の幾何学的意味で周期的」になるようにシーケンスを変更することです。同じ最終色の 2 つのランプは、インデックスが 3 の倍数異なる位置に配置されなければなりません。 

この状態は非常に厳しい構造的な結果をもたらします。 3 を法とする位置、つまりインデックス 0、1、2 の繰り返しを見ると、同じ色のすべての位置がこれらの剰余クラスのいずれかに正確に分類される必要があります。 言い換えれば、各剰余クラス mod 3 には 1 つの色が割り当てられなければならず、その割り当ては文字列全体にわたって一貫していなければなりません。 

したがって、タスクは 3 つの剰余クラス {0,1,2} から 3 つの色 {R,G,B} へのマッピングを選択し、すべての色が正確に 1 回使用されることを確認してから、その剰余クラスに割り当てられた色と一致するように各位置を再描画することになります。 元の文字列と異なる位置の数を最小限に抑えたいと考えています。 

入力サイズは最大 200,000 まで可能です。 これにより、位置の数に関する 2 次または 3 次は直ちに除外されます。 構造体を使用せずに位置ごとにすべてのローカルな再描画の組み合わせを独立して試行するソリューションは、制約がモジュロ クラスを介してグローバルに位置を結合するため、遅すぎるか不正確になります。 

素朴な考え方による微妙な失敗例は、「各位置を隣接する色の過半数と一致するようにペイントする」などの貪欲な局所修正や同様のヒューリスティックを試みることです。 たとえば、入力の場合`RGBRGB`、貪欲なアプローチは、最適な解決策がすでに有効である場合でも、位置を誤って早期に変更し、グローバルな一貫性を損なう可能性があります。 

もう 1 つの微妙なケースは、「RGBRGB…」のような固定パターンが常に最適に機能すると仮定することです。 のために`BRB`、そのような固定パターンは、残基に割り当てられた色の別の並べ替えよりも多くの変更を必要とする可能性があります。 

核心的な難しさは、問題が個々の位置に関するものではなく、3 つの剰余クラスにわたる 3 色の割り当ての最適な順列を選択することに関するものであるということです。 

## アプローチ

 強引に見ると構造が明らかになります。 すべての有効な最終ガーランドは、{R、G、B} の順列を剰余クラス 0、1、2 に割り当てることによって決定されるため、3 つすべてを試すことができます。 = 6 つの割り当て。 割り当てごとに、すでに一致しているポジションの数を計算し、最適なポジションを選択します。 

固定割り当ての場合、文字列を 1 回スキャンし、不一致をカウントします。 これには O(n) のコストがかかります。 6 つの順列がある場合、合計は O(6n) ですが、これは線形であり、実際には非常に小さくなります。 

重要な洞察は、「距離が 3 で割り切れる」という条件が、インデックスをモジュロ 3 でグループ化することとまったく同じであることを認識することです。これが理解されると、問題は任意の構造の色変更に関するものではなくなり、剰余クラスに対する定数サイズの代入問題になります。 

文字列に対する動的プログラミングや貪欲なシミュレーションは必要ありません。 最適化空間全体は 6 つの可能性に分類されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルート フォース (6 順列) | O(n) | お(1) | 承認済み |
 | 最適 (同じアイデア、構造化) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. i mod 3 に基づいて文字列のインデックスを 3 つのグループに分割します。 

これが問題の唯一の構造的制約であるため、すぐに分離します。 
2. 各剰余クラスに出現する R、G、B の数を事前計算します。 

これにより、順列ごとに文字比較を繰り返し再計算する必要がなくなります。 
3. 3 つの色のすべての順列を列挙します。 

各順列は、剰余クラスへの色の完全に有効な割り当てを表します。 
4. 特定の順列について、すでに一致する文字の数を計算します。 

各残基クラス r に対して、r に割り当てられたターゲット色のカウントを加算します。 
5. 一致の最大数で順列を追跡します。 

一致を最大化することは、再カラーを最小化することと同じです。 
6. i mod 3 に基づいて各位置 i に選択した色を書き込むことで、最適な割り当てを使用して回答文字列を再構築します。 

### なぜ効果があるのか

 すべての有効な「ナイス」文字列は、各剰余クラスに 3 を法とする 1 つの色を正確に割り当てる必要があります。これは、2 つの位置が色を共有する場合、それらのインデックスが 3 の倍数異なる必要があり、同じ剰余クラスに強制されるためです。 ちょうど 3 つの色と 3 つの剰余クラスがあるため、この割り当ては全単射です。 このアルゴリズムはすべての全単射を列挙し、元の文字列と最もよく一致するものを選択し、最適性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    colors = ['R', 'G', 'B']

    # cnt[pos_mod][color_index]
    cnt = [[0] * 3 for _ in range(3)]

    idx = {'R': 0, 'G': 1, 'B': 2}

    for i, ch in enumerate(s):
        cnt[i % 3][idx[ch]] += 1

    best_perm = None
    best_keep = -1

    # try all permutations
    from itertools import permutations

    for perm in permutations(range(3)):
        keep = 0
        for r in range(3):
            keep += cnt[r][perm[r]]
        if keep > best_keep:
            best_keep = keep
            best_perm = perm

    res = list(s)
    for i in range(n):
        res[i] = colors[best_perm[i % 3]]

    print(n - best_keep)
    print("".join(res))

if __name__ == "__main__":
    solve()
```この実装では、問題を残差クラスごとの一致のカウントに圧縮します。 の`cnt`テーブルには、各モジュロ バケットに各色が出現する頻度が格納されます。 各順列は、剰余クラスからカラー インデックスへのマッピングを表します。 順列のスコアは、単にそのマッピングにすでに一致する位置の数です。 

よくある落とし穴は、各順列の評価中に候補文字列を再構築することです。 それは不必要です。 スコアを計算するだけです。 再構築は、最適な順列を使用して 1 回実行されます。 

もう 1 つの微妙な点は、置換ループ内の位置ではなく、インデックス モジュロ 3 によってマッピングが適用されるようにすることです。 これら 2 つの解釈を混同すると、誤った答えが生じることがよくあります。

 ## 特殊なケース

 重要なエッジケースは、文字列がすでに完全に周期的である場合です。 入力用`RGBRGB`、各剰余クラスはすでに個別の色と一致しています。 アルゴリズムは 1 つの順列に対する完全一致をカウントし、結果として変更はゼロになります。 順列を比較するだけなので、当然ながら元の構造が保存されます。 

もう 1 つのエッジケースは、次のような均一入力です。`RRRRRR`。 ここで、各剰余クラスは同一の分布を持っているため、複数の順列は同じスコアを生成します。 アルゴリズムは一貫して任意の順列を選択し、次のような有効な交互パターンを生成します。`RGRGBB`または、実装順序に応じて別の同等の最適な配置が可能です。 正しさは、どのネクタイが選択されたかによって決まりません。 

3 番目のケースは、1 つの残基クラスが特定の色を大きく支配しますが、排他的ではない場合です。 順列スコアリングでは、ローカルな決定を下すのではなく、すべての割り当てにわたってグローバルな最大値を取得するため、アルゴリズムは依然としてその色を対応するモジュロ クラスに正しく割り当てます。
