 ## 解決策
 ## 問題の理解

 整数配列とそのインデックス上の間隔のコレクションが与えられます。 各間隔は操作を表します。これを選択すると、その範囲内のすべての位置が 1 つずつ減ります。 選択した各間隔は独立して適用されるため、あるポジションが複数の選択した間隔でカバーされる場合、その値は、そのポジションをカバーする選択した間隔の数だけ減ります。 

間隔のサブセットを適用した後、新しい配列を取得します。 目標は、結果の配列の最大要素と最小要素の差を最大化するサブセットを選択することです。 

重要な構造は、要素を恣意的に直接変更していないことです。 すべての操作で連続セグメントから 1 が減算されるため、インデックス i の最終値は次のようになります。 

元の値から i をカバーする選択されたセグメントの数を引いた値。 

制約は小さく、n と m は最大 300 です。これは、インデックスまたはセグメントに対する 2 次推論が実行可能であることをすぐに示唆しています。 状態探索ごとに 3 次以上のものはまだ許容されますが、セグメントにわたる指数関数的なものは枝刈りまたは構造が必要です。 

局所的に推論すると、微妙な障害モードが現れます。 単純な考えでは、常に最大要素を個別に押し下げるか、最小要素をさらに押し下げようとする必要があると考えますが、セグメントは個々のインデックスではなく範囲に影響を与えるため、両方の効果が結合されます。 たとえば、現在の最大値と最小値の両方を含む領域を減らすと、重複パターンに応じて範囲が縮小または拡大される可能性があります。 

もう 1 つのよくある間違いは、現在の最大値または最小値のみに影響を与えるセグメントを貪欲に選択すれば十分であると想定することです。 これが失敗する理由を簡単な例で示します。2 つのセグメントが部分的に重なっている場合、両方を選択するよりも 1 つだけを選択した方が全体的な広がりが小さくなる可能性があります。 

正しいソリューションでは、各インデックスが選択したセグメントによってカバーされる回数を評価する必要がありますが、選択はグローバルであり、間隔構造によって制限されます。 

## アプローチ

 ブルートフォース解釈では、セグメントのすべてのサブセットを試します。 各サブセットについて、すべてのインデックスでカバレッジ数を計算し、結果の配列範囲を評価します。 これは正しいですが、2^m 通りの可能性があり、m = 300 ではまったく実現不可能です。 

サブセットの選択を構造化されたものに変える方法が必要です。 重要な観察は、目標は各インデックスをカバーするセグメントの数のみに依存しますが、これらのカバー数は間隔全体を選択することによって得られるということです。 これは、差分配列の観点を示唆しています。セグメントの選択は、カバレッジ配列の範囲に +1 寄与します。 したがって、最後の操作は、セグメント上でバイナリ ベクトルを選択し、それらの間隔の寄与を合計することと同じです。 

重要な洞察は視点を逆転させることです。 「どのセグメントを選択すべきか」を考えるのではなく、「アレイにどのようなカバレッジ パターンが必要か」を考えます。 セグメントのサブセットはカバレッジ配列 c[i] を生成し、結果の値は a[i] - c[i] になります。 max(a[i] - c[i]) - min(a[i] - c[i]) を最大化したいと考えています。 

これは次のように書き換えることができます。 

max_i a[i] - c[i] から min_j a[j] - c[j] を引いたもの。 

したがって、2 つの位置 i と j の間の差を最大にするサブセットを選択したいと考えます。 i と j を固定すると、セグメントの選択に関して線形の目標が得られます。 各セグメントについて、i をカバーするか、j をカバーするか、または両方をカバーするかに応じて、+1、-1、または 0 のいずれかになります。 これにより、問題は各ペア (i, j) のサブセットにわたる重みを最大化することに変わり、これはセグメント分類を使用して貪欲に解決できます。 

各セグメントは、(i, j) に関して 4 つのカテゴリに分類されます。

どちらもカバーしないか、i のみ、j のみ、または両方をカバーします。 「i のみ」だけでは差が大きくなり、「j のみ」では差が大きくなり、「両方」では相殺されます。 したがって、fixed (i, j) の場合、i を含むが j を含まないすべてのセグメントを取得し、j を含むが i を含まないセグメントを除外します。 両方をカバーするセグメント、またはどちらもカバーしないセグメントは中立です。 

したがって、各ペア (i, j) について、達成可能な最良の値は次のようになります。 

(a[i] - a[j]) + (i のみをカバーするセグメント数) - (j のみをカバーするセグメント数)

 これは、すべてのセグメントをスキャンすることで計算できます。 

最後に、すべてのペア (i, j) の最良のものを採用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^m・n) | O(n) | 遅すぎる |
 | (i, j) に対するペアごとの最適化 | O(n^2m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスの順序付きペア (i, j) をすべて反復します。 i を最大位置候補、j を最小位置候補と解釈します。 これは、調整後に a[i] - a[j] を最大化するという目標をエンコードします。 
2. 各ペアについて、a[i] - a[j] に等しい実行スコアを初期化します。 これは、セグメントを選択しない場合のベースライン寄与度です。 
3. すべてのセグメント [l, r] について、i および j とどのように相互作用するかを決定します。 i がセグメント内にあり、j がセグメント内にない場合、それを選択すると、a[j] に比べて a[i] が減少するため、スコアが増加します。 j が内側にあり、i が内側にない場合、それを選択するとスコアが減ります。 両方をカバーするセグメントまたはどちらもカバーしないセグメントは、差異に影響を与えません。 
4. i をカバーするが j をカバーしない各セグメントに対して +1 を加算し、j をカバーするが i をカバーしない各セグメントに対して 1 を減算します。 これは、有益なセグメントをすべて選択し、有害なセグメントを回避すると仮定して、達成可能な最高の寄与を計算します。 
5. 最大スコアを生成する最良のペア (i, j) を追跡し、そのペアに対してどのセグメントがプラスにカウントされたかを保存します。 これらが私たちが選択するセグメントです。 
6. 最高のスコアと、対応する選択されたセグメント インデックスを出力します。 

正確さは、固定 (i, j) の場合、各セグメントが目的に対して独立した影響を与えるという事実に依存します。 加算的な寄与を超えるセグメント間の相互作用はないため、最適なサブセットはセグメントごとの局所的な符号決定によって決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    seg = []
    for _ in range(m):
        l, r = map(int, input().split())
        seg.append((l - 1, r - 1))

    best_val = float("-inf")
    best_choice = []

    for i in range(n):
        for j in range(n):
            cur = a[i] - a[j]
            chosen = []

            for idx, (l, r) in enumerate(seg):
                in_i = l <= i <= r
                in_j = l <= j <= r

                if in_i and not in_j:
                    cur += 1
                    chosen.append(idx + 1)
                elif in_j and not in_i:
                    cur -= 1

            if cur > best_val:
                best_val = cur
                best_choice = chosen

    print(best_val)
    print(len(best_choice))
    print(*best_choice)

if __name__ == "__main__":
    solve()
```この実装は、ペアごとの最適化のアイデアに直接準拠しています。 i と j にわたる二重ループにより、候補の極値位置が選択されます。 各セグメントについては、メンバーシップ チェックによってその貢献度が決定されます。 選択したペアの差を改善するセグメントのみが保存されます。 

微妙な点は、「自分にとって良い」とカウントされたセグメントのみを保存することです。これは、それらのセグメントがそのペアの最適なサブセット内で積極的に選択されるためです。 ペアにとって有害なセグメントは単に無視されます。 中立的なセグメントはどちらの場合でも問題ありません。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [2, -2, 3]
segments = [ [1,3], [2,3] ]
```ペア (i, j) を評価します。 (i = 2、j = 0) について考えてみましょう。 

| ステップ | 式 | 値 |
 | --- | --- | --- |
 | ベース | a[2] - a[0] | 3 - 2 = 1 |
 | セグメント1 | 両方をカバー → 変化なし | 1 |
 | セグメント2 | i のみをカバー → +1 | 2 |

 このペアに最適なのは 2 です。 

ここで (i = 2、j = 1) を考えます。同様の評価では異なるスコアが得られます。 アルゴリズムはすべてのペアをチェックし、最適なものを選択します。 

このトレースは、セグメントの寄与がグローバル構造ではなく、選択したエンドポイントに対する包含にのみ依存する様子を示しています。 

### 例 2

 入力:```
n = 4
a = [1, 3, -1, 2]
segments = [[1,2],[2,4],[1,4]]
```ペア (i = 1、j = 2) の場合:

 | セグメント | カバー i | カバーj | 効果 |
 | --- | --- | --- | --- |
 | [1,2] | はい | はい | 0 |
 | [2,4] | いいえ | はい | -1 |
 | [1,4] | はい | はい | 0 |

 スコアは(1 - 3) - 1 = -3となります。 

他のペアではより良い値が得られる可能性があり、アルゴリズムはすべてを体系的に探索します。 

これは、重複するセグメントが予測可能な方法で相殺され、非対称のカバレッジのみが重要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2m) | 各ペア (i, j) について、すべてのセグメントを 1 回スキャンします。 
| スペース | O(m) | セグメントリストと選択したインデックスを保存 |

 境界 n、m ≤ 300 では、最大 2,700 万回のセグメント チェックが行われますが、これは Python の単純な整数演算の制限内に十分収まります。

 ## 特殊なケース

 重要なエッジ ケースは、i と j が同一のセグメント カバレッジ パターンにある場合です。 考慮する：```
a = [5, 1, 5]
segments = [[1,3]]
```i = 0 と j = 2 の場合、両方とも唯一のセグメントによってカバーされるため、セグメントは何も寄与しません。 アルゴリズムはスコア 0 の変更を正しく生成し、結果は a[i] - a[j] = 0 のままになります。 

これにより、両方のエンドポイントをカバーするセグメントが中立であり、決定を決して歪めないことが確認されます。 このアルゴリズムは、セグメントを 4 つの素なケースに分類するだけであり、「両方」のケースは明示的に無視されるため、これを自然に処理します。
