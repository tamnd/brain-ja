 ## 解決策
 ## 問題の理解

 ホワイトボードに配置された一連の数字から始めます。 次に、一連の置換値が与えられます。 置換操作ごとに、任意の 1 つのホワイトボードを選択し、その現在の値を操作の新しい値で上書きできます。 

すべての操作を使用する必要がありますが、毎回どのホワイトボードを更新するかを自由に選択でき、同じホワイトボードを複数回更新することもできます。 目標は、すべての置換が適用された後にボードに書き込まれる値の最終合計を最大化することです。 

重要な観察は、各ボードの最終値のみが重要であり、演算が適用される順序は重要ではないということです。 すべての操作は、最終的にどこかに割り当てられる 1 つの値を提供します。 

以来$n, m \le 100$、制約により、単純な貪欲な推論が可能になります。 までのあらゆるソリューション$O(nm)$または$O(m \log m)$簡単に十分です。 

微妙なエッジケースは次のような場合です$m > n$つまり、一部のボードは複数回上書きされます。 もう一つは、いつ$m < n$つまり、一部の元の値は決して変更されません。 単純な間違いは、各操作が個別のボードに送信される必要があると想定することです。これは誤りであり、柔軟性を過小評価することにつながります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれに割り当てるすべての方法をシミュレートします。$m$に値する$n$ボード。 操作ごとに、次のいずれかを選択します。$n$ボード、につながる$n^m$可能性。 たとえ$n = m = 100$、これは大きすぎます。 

重要な簡素化は、最終的な構成が 2 つの数値セット (初期ボード値と操作リストから適用することを決定した値) のみに依存することを認識することで得られます。 各操作は 1 つの値だけを提供し、それをどこに渡すかを選択できます。 これは、どの最終値がどの初期値を置き換えるかを効果的に決定していることを意味します。 

合計を最大化するには、さらに大きな操作値に置き換えることができない限り、大きな初期値を保存する必要があります。 すべての演算値は最大 1 回のみ使用できるため、最適な戦略は、利用可能なすべての候補の中から可能な限り最大の値を選択し、それらを最も利益が得られるボードに配置することになります。 

これを明確に確認する方法は、サイズの最終的なマルチセットを構築していることです。$n$、ここから始めます$a_i$まで置き換えることができます$m$使用する要素$b_j$。 各置換は、合計が増加する場合にのみ使用する必要があり、すべての選択肢の中で常により大きな値を優先します。 

これにより、両方の配列がソートされ、最大のものと貪欲に一致します。$b_j$最小の値$a_i$価値観。

 ## アルゴリズムのチュートリアル

 1. 初期配列をソートする$a$昇順で並べるので、改善が最も簡単な最小値を簡単に特定できます。 その理由は、小さな値を置き換えることで最大の限界利益が得られるためです。 
2. 置換値を並べ替える$b$降順で並べているので、利用可能な最も強力な改善を最初に使用できます。 これにより、メリットがほとんどないポジションに大きな価値を無駄にすることがなくなります。 
3. 両方の配列を同時に繰り返し、残りの最小値を比較します。$a[i]$残っている最大のもので$b[j]$。 もし$b[j] > a[i]$、 交換する$a[i]$と$b[j]$。 それ以外の場合は、残りすべてが残っているため、それ以上の代替品の使用を中止してください。$a[i]$はさらに大きいです。 
4. 力が尽きるまでこのプロセスを続けます。$b$または、置き換えても合計が改善されない点に達します。 結果として得られる配列は、演算の最適な割り当てを表します。 
5. 変更された配列の最終合計を計算します。 

### なぜ効果があるのか

 正しさは交換引数に依存します。 より小さい置換値をより小さい置換値に割り当てる最適解があるとします。$a[i]$、一方、より大きな置換値は使用されないか、別の場所に割り当てられます。 これらの割り当てを交換しても合計が減少することはなく、増加する可能性があります。 この推論を繰り返すと、最大の$b$値は最小のものと一致します$a$有益な場合は常に値を設定します。これはまさに貪欲な手順が構築するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort(reverse=True)
    
    i = 0
    j = 0
    
    while i < n and j < m:
        if b[j] > a[i]:
            a[i] = b[j]
            i += 1
            j += 1
        else:
            break
    
    print(sum(a))
```実装は貪欲戦略に直接従います。 仕分け$a$これにより、常に最も弱いポジションを最初に改善することを試みることができます。 仕分け$b$降順に並べることで、最も強力なアップグレードを早期に消費できるようになります。 

改善が不可能になるとすぐにループが停止するため、すべてが残った場合に不必要な比較が回避されます。$a[i]$すでに残りよりも大きくなっています$b[j]$。 最終的な合計は、更新された配列から直接計算されます。 

## 実用的な例

 インプットを考慮する$a = [1,2,3]$そして$b = [4,5]$。 並べ替えた後、比較してみます$1$と$5$、交換して比較してください$2$と$4$、交換して停止します。 結果の配列は次のとおりです$[5,4,3]$。 

| ステップ | (状態) | b ポインタ | アクション |
 | --- | --- | --- | --- |
 | 1 | [1,2,3] | 5 | 1 を 5 に置き換えます |
 | 2 | [5,2,3] | 4 | 2 を 4 に置き換えます |
 | 3 | [5,4,3] | 停止 | 改善なし |

 最終的な合計額は、$12$、最適な構成に一致します。 

のために$a = [10,10]$そして$b = [1,2]$、ソートすると、$a$変わらずそして$b = [2,1]$。 最大のものでも$b$最小値より大きくない$a$、置換は行われず、合計は残ります。$20$。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        i = 0
        j = 0
        
        while i < n and j < m:
            if b[j] > a[i]:
                a[i] = b[j]
                i += 1
                j += 1
            else:
                break
        
        out.append(str(sum(a)))
    
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()
