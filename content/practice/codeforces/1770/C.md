 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられ、単一の正のシフト値を選択できます。$x$。 すべての要素を同じ量だけシフトした後、結果の数値のすべてのペアが互いに素になるようにします。 

同様に、配列を次のように変換します。$b_i = a_i + x$。 要件は、2 つの異なるインデックスについて、シフトされた 2 つの値が 1 より大きい公約数を共有しないことです。タスクは、そのようなシフトが少なくとも 1 つ存在するかどうかを判断することです。 

重要な点は、構築するように求められていないということです。$x$、存在を決定するだけです。 これは多くの場合、条件を大きな整数の検索ではなく、入力の構造特性に帰着できることを示します。 

制約は次のことを示しています$n \le 100$テストごとに値は次のようになります$10^{18}$。 これにより、可能な限り反復するアプローチは即座に除外されます。$x$、 以来$x$サイズに制限はありません。 また、推論は元の数値の絶対的な大きさではなく、数値間の関係に依存する必要があることも示唆しています。 

素朴な推論による微妙な失敗例は、大きな値を選択すると仮定することです。$x$数値は常に互いに素になります。 これは、シフトによって差が保存されるため、誤りです。シフト後に 2 つの数値が同時に何らかの素数で割り切れる場合、その素数によって禁止された gcd が作成されます。 もう 1 つの罠は、ペアごとの差異のみに焦点を当てることです$a_i - a_j$直接的には、シフト後の gcd 構造は差だけでは不変ではないためです。 

## アプローチ

 重要な観察は、gcd 条件をより構造的な方法で書き直すことから得られます。 シフトされた 2 つの数値が素数を共有する場合$p$、その後両方$a_i + x$そして$a_j + x$で割り切れます$p$。 つまり:$$a_i \equiv a_j \equiv -x \pmod p$$したがって、シフト後に素約数を共有するすべての数値は、同じ剰余クラスのモジュロに分類される必要があります。$p$。 

これにより、どの素数がシフトされた値を同時に除算できるかを制御することが問題になります。 考える代わりに$x$、すべての数値を潜在的な素数を法とする特定の合同クラスに強制する方法について考えます。 

便利な方法は、1 つの要素を参照として固定し、それを基準にしてすべてを表現することです。 選んでみましょう$a_1$。 もし望むなら$\gcd(a_1 + x, a_i + x) = 1$の場合、両方を割り算する素数は存在しません。 素数を仮定します$p$シフトされた両方の値を除算します。 次に、それらの差を分割します。$$(a_i + x) - (a_1 + x) = a_i - a_1$$したがって、悪い素数は何らかの差を除算する必要があります$a_i - a_1$。 これが重要な還元です。差分に現れる素数だけが重要です。 

これで構造が単純化されました。 プライムなら$p$差異を分割する場合、私たちは選択を避けなければなりません$x$すべての値が同じ剰余クラスのモジュロに収まるように$p$。 成功を保証する唯一の方法は、アレイ全体でそのような避けられない位置合わせが起こらないようにすることです。 

意図したソリューションで使用されている決定的な単純化はより強力です。配列に重複が含まれている場合、答えは即座に不可能になります。 もし$a_i = a_j$、その後、任意の$x$、私たちは得ます$a_i + x = a_j + x$したがって、それらの gcd は数値自体であり、常に 1 より大きくなります。これはすでに有効性をブロックしています。 

すべての値が異なる場合、いつでも次の値を構築できます。$x$これにより、差を分割する素数によって引き起こされる有限個の禁止された合同式がすべて回避されます。 以来$n$が小さい場合、この構築引数は明示的に見つけなくても存在を保証します。 

したがって、条件は、重複が存在するかどうかという単純なチェックに集約されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの配列を読み取り、値が複数回出現するかどうかを確認します。 このステップでは、障害に関係なく失敗を保証する唯一の障害物を直接テストします。$x$。 
2. 重複が存在する場合は、シフト後も同一の値が同一のままであるため、有効なシフトは存在できないと直ちに結論付け、非単位の gcd が強制されます。 
3. すべての要素が異なる場合、適切な要素であると結論付けます。$x$存在します。 その理由は、重複によって引き起こされる強制的な gcd がなければ、すべての共有素数制約を回避するシフトをいつでも選択できるということです。 

## なぜ機能するのか

 シフト後に 1 より大きい gcd が避けられない唯一の現象は、シフトされた 2 つの値が同一である場合に発生します。これは、まさに元の値が同一である場合に発生します。 他の gcd 条件は差分における素数による割り切りに依存し、これらは適切な選択によって回避できます。$x$禁止された剰余のセットは有限であり、すべての整数をカバーするわけではないためです。 したがって、重複が唯一の障害となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if len(set(a)) < n:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```実装は特性評価の直後に続きます。 唯一重要な手順は、セットを使用して重複を効率的に検出することです。 この理論は問題を完全に一意性に帰着させるため、算術操作は必要ありません。

これらのトレースは、アルゴリズムが等価性チェックを超えて大きさや構造に依存していないことを示しており、これは導出された条件と一致しています。

 ## 特殊なケース

 次のような完全に等しい配列`[7, 7, 7]`最も強力な失敗例です。 何らかのシフトの後$x$、すべての値が同一になるため、すべてのペアの gcd はシフトされた値と等しくなります。 このアルゴリズムは重複を即座に検出し、値の計算を行わずに NO を出力します。 

次のようなほぼ重複した配列`[1, 2, 1]`同じように動作します。 1 つの値だけが繰り返される場合でも、シフトされた 2 つの同一の値は常に gcd として完全な値を共有するため、矛盾を強制するだけで十分です。 

次のような完全に異なる配列`[1, 2, 3]`均一に処理されます: 設定されたサイズは次のとおりです$n$したがって、実際の gcd 計算について推論する必要がなく、アルゴリズムは YES を出力します。
