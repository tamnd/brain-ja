 ## 解決策
 ## 問題の理解

 2D 整数平面上にいくつかの独立したシナリオが与えられます。 各シナリオでは、ロボットはある座標から開始します。$I = (x_1, y_1)$そして目標座標に到達する必要があります$F = (x_2, y_2)$。 ロボットは整数のグリッド点上を移動しますが、平面はそれ以外の場合は境界がありません。つまり、初期の座標範囲に制限されません。 

一部のグリッド点は禁止されています。 座標が障害物としてリストされている場合、ロボットはその上に立つことができません。 他のすべての整数座標を自由に移動できます。 

移動は隣接するグリッド点の間で発生します。 コストは移動の種類によって異なります。8 コストの移動もあれば、16 の移動もある。禁止点を踏まずに最初から最後まで有効なパスが存在しない場合、答えは次のようになります。$-1$。 それ以外の場合は、可能な最小の総コストを計算する必要があります。 

重要な解釈は、ブロックされた頂点を除くすべての頂点が整数座標であり、エッジが 2 つの可能な重みで幾何学的近傍を接続する暗黙的な無限グラフ上の最短経路問題を解いているということです。 

座標に関する制約は小さく、$-50$そして$50$、テスト ケースごとに最大 100 個の障害があります。 ただし、ロボットはこのボックスから出ることができるため、グラフは明示的に境界付けされません。 これにより、到達可能な領域には原則として境界がないため、グリッド全体を構築したり、大きな長方形にわたって高密度 DP を実行しようとするアプローチは即座に排除されます。 

最も危険なエッジケースは、障害物が厳しい障壁を形成し、最初の境界ボックスの外への迂回を余儀なくされる場合です。 たとえば、開始が次の場合、$(0,0)$、で終了$(2,0)$、およびすべてのポイント$(1,y)$のために$y \in [-50,50]$がブロックされている場合、境界四角形に制限された単純な BFS は、誤って到達不能と判断したり、バリアを迂回する本当の迂回路を見逃したりする可能性があります。$y=51$。 

もう 1 つの微妙なケースは、開始点または終了点が多くの障害物に隣接している場合です。 「一歩近づける」ことを試みる貪欲なアプローチまたはヒューリスティックベースのアプローチは、極小値に陥る可能性があります。これは、最も安価な即時の移動が、ブロックされたノードに囲まれたデッド領域につながる可能性があるためです。 

## アプローチ

 強引なアイデアは、すべての整数座標をノードとして扱い、無限グリッド上で BFS またはダイクストラを実行することです。 各ノードから、障害物をスキップしながら、8 つの可能な移動すべてを試みます。 これはグラフを直接モデル化しているので正しいのですが、ノードの数が無限であるため、記載どおりに実行することは不可能です。 

重要な観察は、グリッドは無限であるにもかかわらず、関連する唯一の「穴」は障害点であり、その数は非常に少ないということです。 ユニット構造を持つグリッド内の最短経路は、距離に応じて移動コストが増大し、空の空間を探索しても報酬がないため、任意に遠くをさまよっても利益が得られません。 最適なパスは、開始点、終了点、およびすべての障害物を含む境界ボックス内にあると想定できます。場合によっては、境界に隣接する障害物を迂回できるようにわずかなマージンだけ拡張されます。 

これにより、問題は有限最短経路問題に帰着します。 すべてのポイントをカバーするグリッドに限定します。$\min(x)$に$\max(x)$、同様に$y$、各方向に 1 ずつ拡張されます。 エッジには 2 つの異なる重みがあるため、この有限のノード セットでダイクストラを実行します。

 ## アルゴリズムのチュートリアル

 グリッドを、慎重に選択した外接する四角形内の整数座標をノードとする加重グラフとして扱います。 

1. 開始、終了、障害物の座標を読み取り、すべての x 値と y 値を収集します。 これらから、最小値と最大値の x と y を計算します。 この範囲を全方向に1単位ずつ拡大します。 この拡張により、有用な領域の境界に正確に存在する障害物を回避してルートを設定できるようになります。 
2. O(1) メンバーシップ チェック用にブロックされた座標のセットを構築します。 障害物の検索は緩和ステップごとに行われるため、これは不可欠です。 
3. 初期座標からダイクストラのアルゴリズムを実行します。 状態の優先キューを維持します$(cost, x, y)$。 
4. それぞれのポップ状態から、8 方向すべてに移動してみます。 各移動は隣接する座標につながります。 その座標が境界ボックスの外側にある場合、またはブロックされている場合は、その座標を破棄します。 
5. 有効な各移動には、方向の種類に応じて固定コストがかかります。 直線移動のコストは 8、斜め移動のコストは 16 です。より安価なパスを見つけた場合は、隣人をリラックスさせます。 
6. ダイクストラはこれがその時点で可能な最小コストであることを保証するため、目標座標に到達したら早期に停止します。 
7. 目標に到達しない場合は、次のように出力します。$-1$。 

これが機能する理由は、任意の最適なパスを有限の境界ボックスに埋め込むことができるためです。 この領域の外では、移動コストは均一であり、絶対位置ではなくステップ タイプのみに依存するため、コストを増加させることなく迂回を投影することができます。 したがって、グラフを制限しても最適な解は削除されません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**18

# 8 directions: (dx, dy, cost)
dirs = [
    (1, 0, 8), (-1, 0, 8), (0, 1, 8), (0, -1, 8),
    (1, 1, 16), (1, -1, 16), (-1, 1, 16), (-1, -1, 16)
]

P = int(input())
for _ in range(P):
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    n = int(input())
    blocked = set()

    xs = [x1, x2]
    ys = [y1, y2]

    for _ in range(n):
        x, y = map(int, input().split())
        blocked.add((x, y))
        xs.append(x)
        ys.append(y)

    minx, maxx = min(xs) - 1, max(xs) + 1
    miny, maxy = min(ys) - 1, max(ys) + 1

    def inside(x, y):
        return minx <= x <= maxx and miny <= y <= maxy

    dist = {}
    pq = []

    start = (x1, y1)
    if start in blocked:
        print(-1)
        continue

    dist[start] = 0
    heapq.heappush(pq, (0, x1, y1))

    ans = -1

    while pq:
        d, x, y = heapq.heappop(pq)

        if d != dist.get((x, y), INF):
            continue

        if (x, y) == (x2, y2):
            ans = d
            break

        for dx, dy, w in dirs:
            nx, ny = x + dx, y + dy
            if not inside(nx, ny):
                continue
            if (nx, ny) in blocked:
                continue

            nd = d + w
            if nd < dist.get((nx, ny), INF):
                dist[(nx, ny)] = nd
                heapq.heappush(pq, (nd, nx, ny))

    print(ans)
```エッジの重みが均一ではないため、実装はダイクストラに依存します。 プライオリティ キューにより、ノードを完成させるたびに、その最適なコストがすでに得られることが保証されます。 

境界ボックスの制限により、無限グリッドが管理可能になります。 それがなければ、アルゴリズムは決して終了しません。

 これは、アルゴリズムがどのようにブロックされたセルを自然に回避し、代替パスを通じてコストを蓄積するかを示しています。

 ## 特殊なケース

 主なエッジ ケースは、最短パスを開始するために、開始点、終了点、および障害物によって定義される直接の長方形の外側に移動する必要がある場合です。 境界ボックスが 1 単位だけ拡張され、狭い障害物の周囲に最小限の迂回路ができるようになるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、開始点または終了点の大部分が囲まれている場合です。 たとえば、次の場合$(x_1, y_1)$1 つの対角エスケープを除いてすべての隣接ノードがブロックされていますが、ダイクストラは 8 方向すべてを均一に考慮し、貪欲な進行に依存しないため、残りの有効なエッジを引き続き探索します。 

最後のエッジケースは、開始と終了が等しい場合です。 最初に抽出されたノードがすでにターゲットと一致しているため、アルゴリズムは距離を正しくゼロに初期化し、展開ループに入らずにすぐに戻ります。
