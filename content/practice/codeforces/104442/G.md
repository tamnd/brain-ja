 ## 解決策
 ## 問題の理解

 固定長のバイナリ セル オートマトンが与えられます。 各構成は C 個のセルの行であり、各セルは 0 または 1 です。ルール R (0 から 255) は次の行がどのように生成されるかを定義します。各位置は現在の行の 3 つの連続するセルのブロックを調べ、そのトリプルを 3 ビットの数値として受け取り、R を使用して次の行の結果のビットを決定します。 

タスクは、順方向にシミュレーションすることではありません。 代わりに、ターゲット構成 A が与えられ、指定されたルールの下で A に進化する可能性のある以前の構成 B が存在するかどうかを判断する必要があります。 そのような B が存在しない場合、A はエデンの園構成と呼ばれ、SI を出力します。存在しない場合は、NO を出力します。 

グリッドの幅は狭く、C は最大 30 ですが、テスト ケースの数は多く、最大 5000 です。この組み合わせは、各テストをおよそ O(C) または O(C log C) 時間で解決する必要があることを強く示唆しています。これは、テストごとに二次関数を実行するとすでに遅すぎるためです。 

微妙な点は、配列の外側の境界セルは 0 に固定され、決して変更されないことです。 これは、最初と最後の遷移が仮想ゼロ近傍によって制約され、有効な先行処理はそれを尊重する必要があることを意味します。 

素朴な誤解は、前任者を左から右に貪欲に再構築できると考えることです。 これは失敗します。各セルが連続する前の 3 ビットに依存するため、選択が重複してグローバル制約が作成されるからです。 

2 番目のよくある間違いは、すべての可能な先行者にブルート フォースを実行しようとすることです。 C が 30 までの場合、候補は 2^30 あり、これはテストごとにすでに約 10 億の可能性があり、5000 のテスト ケースを考慮する前でさえ完全に実行不可能です。 

## アプローチ

 ブルート フォース アプローチでは、長さ C の以前の構成 B をすべて試し、オートマトンの 1 ステップをシミュレートして、それが A と一致するかどうかを確認します。各シミュレーションのコストは O(C) であるため、テストごとの総コストは O(C · 2^C) です。 これは、状態空間が約 10^9 構成である C = 30 ですぐに爆発します。 

重要な構造は、有効性がローカルであるということです。つまり、各位置 i は (B[i-1]、B[i]、B[i+1]) にのみ依存します。 これは、完全な文字列を個別に探索する必要がないことを意味します。 代わりに、ローカル制約を強制するのに十分なコンテキストを維持しながら、先行モデルを少しずつ構築できます。 

解決策を明らかにする観察は、左から右にスキャンする場合、部分割り当てを拡張できるかどうかを決定するために必要な唯一の情報は、選択された最後の 2 ビットであるということです。 B[i−1] と B[i] を固定すると、次のビット B[i+1] は、ルールに従って必要な出力 A[i] を生成するかどうかによってのみ制約されます。 

これにより、この問題は、隣接するビットのペアによって定義される状態に関するパスの存在の問題に変わります。これは、位置に関する動的プログラミングで解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C・2^C) | O(C) | 遅すぎる |
 | ペアDP | O(C・4) | お(4) | 承認済み |

 ## アルゴリズムのチュートリアル

 未知の先行データを、2 つの固定仮想境界ビット B[0] = 0 および B[C+1] = 0 を持つ、長さ C のバイナリ文字列 B として扱います。 

次に、すべての位置 i がその近傍と結合されたときに必要な A[i] を生成するようにしながら、左から右に B を構築しようとします。

1. 位置 1 の仮想左隣を 0 に設定して、境界条件を修正します。これにより、最初の遷移が明確に定義され、問題ステートメントと一致することが保証されます。 
2. 位置 i の動的状態をペア (B[i-1], B[i]) として定義します。 位置 i の制約には正確にこれら 2 ビットと次のビット B[i+1] が含まれるため、これで十分です。 
3. 位置 1 を処理する前に、唯一可能な開始ペア (0, 0) で DP を初期化します。これは、B[0] が 0 に固定されており、B[1] がまだ選択されていないことをエンコードします。 
4. 1 から C までの各位置 i について、考えられるすべての現在の状態 (x_{i−1}, x_i) を試します。 各状態について、{0, 1} の x_{i+1} を選択して拡張を試みます。 この拡張は、ルールを (x_{i−1}, x_i, x_{i+1}) に適用して A[i] が生成される場合にのみ有効です。 これにより、ローカルの整合性が延期されるのではなく、ただちに適用されます。 
5. 有効な拡張機能が存在する場合は常に、次の状態 (x_i, x_{i+1}) に遷移します。 これにより、将来の制約に必要なすべての情報を保持しながら、ウィンドウが 1 ステップ右に移動します。 
6. 位置 C を処理した後、最後に計算された遷移が B[C+1] = 0 と一致することを要求することで、最終境界条件を強制します。つまり、x_C と 0 を持つ状態のみが位置 C のルールを満たす必要があります。 
7. 有効な DP 状態が最後に存在する場合は、少なくとも 1 つの先行動作が存在するため、NO を出力します。 それ以外の場合は SI を出力します。 

正確さは、位置 i に関係するすべての制約が x_{i+1} の導入時に正確にチェックされるため、違反点を超えて無効な部分代入が残らないという事実に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rule_output(R, a, b, c):
    idx = (a << 2) | (b << 1) | c
    return (R >> idx) & 1

def solve_case(R, C, A):
    # dp over states (prev, cur)
    dp = [[False, False], [False, False]]
    dp[0][0] = True  # B[0]=0, B[1]=0 initially

    for i in range(1, C + 1):
        ndp = [[False, False], [False, False]]
        ai = (A >> (C - i)) & 1

        for p in range(2):
            for q in range(2):
                if not dp[p][q]:
                    continue
                for nxt in range(2):
                    if rule_output(R, p, q, nxt) == ai:
                        ndp[q][nxt] = True

        dp = ndp

    # enforce boundary: B[C+1] = 0
    return any(dp[p][0] for p in range(2))

def main():
    N = int(input())
    out = []
    for _ in range(N):
        R, C, A = map(int, input().split())
        out.append("NO" if solve_case(R, C, A) else "SI")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP テーブルには、位置 i までの部分先行処理が指定されたビットのペアで終了できるかどうかが格納されます。 各遷移は、正しい 3 ビット近傍を抽出し、それを位置 i のターゲット構成ビットと比較することによってオートマトン ルールをチェックします。 A からのビット抽出は、位置のインデックス作成が左から右のトラバースと一致するように、最上位から最下位の順に行われます。 

最終チェックでは、最後に構築されたビットの後に一貫して 0 が続く状態のみを受け入れることにより、右境界がゼロになるように強制します。 

## 実用的な例

 ### 例 1

 入力:

 R = 108、C = 8、A = 181 (バイナリ 10110101)

 DP の状態 (prev、cur) を追跡します。 到達可能な状態のみが表示されます。 

| 私 | アクティブな状態 (前、現在) |
 | --- | --- |
 | 0 | (0,0) |
 | 1 | (0,1) |
 | 2 | (1,0)、(1,1) |
 | 3 | (0,1)、(1,0) |
 | 8 | next = 0 で終わる状態はありません |

 DP は最終的に境界条件と矛盾するため、先行処理は存在せず、出力は SI になります。 

これは、ローカルで一貫した構築が、境界制約によってグローバルに失敗する可能性があることを示しています。 

### 例 2

 入力:

 R = 90、C = 10、A = 111

 | 私 | アクティブな状態 |
 | --- | --- |
 | 0 | (0,0) |
 | 1 | (0,1) |
 | 2 | (1,1) |
 | 3 | (1,0)、(1,1) |
 | 10 | 少なくとも 1 つの状態が有効です。 

ここでは、DP が空になることはなく、少なくとも 1 つの完全な先行データが存在するため、出力は NO になります。 

これは、複数の部分構造が共存する可能性があり、有効なパスが 1 つだけあれば十分であることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、ルールでは複数の継続が許可されているが、境界条件によってそのすべてが削除される場合です。 たとえば、R = 255 のような許容ルールでは、すべてのトリプルが 1 を生成するため、システムは内部的にすべて 1 を強制する傾向がありますが、C が極端に小さい場合を除き、最後の要件 B[C+1] = 0 は一貫性を壊します。 

もう 1 つのエッジ ケースは、R = 0 のような制限ルールの A = 0 です。この場合、すべてのトリプルが 0 を生成します。この場合、先行するものはどれも有効であり、たとえ構造があいまいさを示唆しているとしても、解が存在するため、DP は正しく NO を報告するはずです。 

すべての制約が各ステップでローカルに適用され、最終的な境界チェックが、有効な構造を排除できる唯一のグローバルな制限であるため、DP は両方のケースを均一に処理します。
