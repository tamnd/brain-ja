 ## 解決策
 ## 問題の理解

 重みの配列が与えられているので、これらの値を正確に分割する必要があります。$k$空ではないグループ。各重みは 1 つのグループにのみ属します。 どのグループでも、そのコストはそのグループ内の最大値と最小値の差として定義されます。 パーティションの総コストは、これらのグループ コストの合計です。 あらゆる人にとって$k$から$1$に$n$、可能な最小の総コストを計算する必要があります。 

したがって、実際の決定は、要素の順序付けではなく、グループ内の範囲を最小限に抑えるために、連続するサブセットまたは不連続なサブセットをどのように選択するかによって決まります。 グループの要素の価値が近い場合、グループは安くなります。 問題は、グループの数を増やさざるを得なくなったときに、達成可能な最良のコストがどのように変化するかを問うことです。 

入力サイズが大きい: 最大$10^5$テストごとの要素とテスト全体の合計も最大$10^5$。 これにより、テストごとの二次関数やすべてのパーティションを試行するものは直ちに除外されます。 すべての分割またはサブセット上の DP を評価しようとしても、ソリューションは遅すぎます。 ソートと線形または線形演算処理に近いものが必要です。 

微妙な問題は、グループ化が元の順序で連続している必要がないことです。 つまり、最初に並べ替えない限り、「配列をセグメントに分割する」という素朴な直感は誤解を招きます。コストの定義では値による相対的な順序のみが重要になるからです。 

よくある失敗例は、並べ替えを行わずに貪欲にグループ化することに起因します。 たとえば、値の場合$[1, 100, 2, 99]$、連続した要素をグループ化すると意味のない範囲が与えられますが、最適なグループ化はソートされた構造に依存します。$[1,2,99,100]$。 

## アプローチ

 ブルートフォースソリューションでは、あらゆる方法で配列を分割しようとします。$k$グループを作成し、各パーティションのコストを計算します。 固定用でも$k$、パーティションの数は指数関数的であり、本質的には第 2 種スターリング数です。 それぞれの評価にかかる費用$O(n)$したがって、このアプローチは非常に小さな値を超えるとすぐに爆発します。$n$。 

重要な観察は、ソート後、最適なグループの構造がソートされた順序と一致することです。 グループ内では最小値と最大値のみが重要であるため、グループ内で要素をインターリーブしても役に立ちません。 配列をソートすると、すべてのグループがいくつかの要素を選択すると考えることができますが、コストは極端な場合にのみ依存します。 重要な洞察は、2 つの隣接するグループをソート順にマージすると、境界要素間のギャップとまったく同じコスト増加が生じるということです。 

より具体的には、配列をソートする場合は、独自のグループ内の各要素から始めることを検討してください。 コストはゼロです。 ここで、もともと別々のシングルトンであった 2 つの隣接するグループをマージすると、それら 2 つの値の差分だけコストが増加します。 これにより、問題は、グループ間のカットとしてどの隣接するギャップを「アクティブ化」するかを選択することに変わります。 

したがって、問題を選択に還元します$k-1$間のカット$n-1$ソートされた配列内のギャップ。 各カットにより、潜在的なマージコストが削減されます。 同等に、最大のものを保持します$k-1$ギャップを区切り文字として使用するか、二重の観点から、最小のマージを最初に選択します。 

これは古典的な構造につながります。ソートされた配列内のすべての隣接する差分を計算し、それらをソートし、プレフィックスの合計を使用してすべての答えを構築します。$k$。

 ## アルゴリズムのチュートリアル

 この問題を、並べ替えられた値とその隣接するギャップに対する操作に変換します。 

1. 配列を降順でない順に並べ替えます。 これにより、グループ内で離れた値を混合しても範囲が不必要に増加するだけなので、このソートされたシーケンス内の連続セグメントに関して最適なグループを推論できることが保証されます。 
2. 連続する要素間の差を計算します。 これらは、隣接する値を同じグループに「接続するコスト」を表します。 それぞれの違いは、グループの数を減らすときの最終コストへの寄与候補となります。 
3. すべての要素が独自のグループとして開始される場合、総コストはゼロであることに注目してください。 2 つの隣接するグループをソート順にマージするたびに、それらの間のギャップに等しいコストが発生します。 これにより、問題はマージの選択に変換されます。 
4. 正確に形を整える$k$グループ、まさに必要です$n-k$合併します。 各マージは、隣接するギャップ コストを 1 つ取得することに対応します。 
5. 総コストを最小限に抑えたいため、最初に利用可能な最小のマージ コストを選択します。 したがって、ギャップ配列をソートします。 
6. ソートされたギャップに対してプレフィックスの合計を構築します。 の答えは、$k$グループは最小のものの合計です$n-k$ギャップ。 

これが機能する理由は構造的不変条件に由来します。ソートされた順序では、どのパーティションも隣接する要素間の一連のカットとして表すことができます。 各カットは、2 つの要素が同じグループに属するかどうかに独立して寄与し、2 つのセグメントを接続することによって寄与されるコストは境界ギャップのみに依存します。 これらの寄与は独立しており、相加的であるため、最適性はマージのための最小のギャップを選択することに帰着し、これによりすべてのステップで累積コストが最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 1:
            out.append("0")
            continue
        
        a.sort()
        
        gaps = []
        for i in range(n - 1):
            gaps.append(a[i + 1] - a[i])
        
        gaps.sort()
        
        prefix = [0] * (n)
        for i in range(n - 1):
            prefix[i + 1] = prefix[i] + gaps[i]
        
        res = []
        for k in range(1, n + 1):
            merges = n - k
            res.append(str(prefix[merges]))
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは最初に配列を並べ替えて、関連するすべての構造が線形になるようにします。 次に、隣接する要素間で考えられるすべてのコスト増分をエンコードするギャップ配列を構築します。 

ギャップを並べ替えることは重要な貪欲なステップです。これにより、グループの数を減らすときに常に最も安価なマージが最初に選択されるようになります。 プレフィックス配列を使用すると、最小値の合計に対する定数時間クエリが可能になります。$x$ギャップは、$n-x$マージするため、$k$グループ。 

間のマッピング$k$マージの数が主なインデックス作成の詳細です。$k$グループとは$n-k$要素間の接続。 

## 実用的な例

 次の入力を考えてみましょう。```
n = 4
a = [5, 2, 3, 7]
```並べ替え後:$[2, 3, 5, 7]$ギャップ:$$[1, 2, 2]$$ソートされたギャップが残ります。$[1, 2, 2]$プレフィックスの合計:$$[0, 1, 3, 5]$$ここで答えを計算します。 

| k | マージ = n-k | コスト (プレフィックス[マージ]) |
 | --- | --- | --- |
 | 1 | 3 | 5 |
 | 2 | 2 | 3 |
 | 3 | 1 | 1 |
 | 4 | 0 | 0 |

 これは、グループの数を増やすと、最初に大きなギャップを支払う必要がなくなり、より小さな内部マージのみが残ることを示しています。 

次に、次のことを考えてみましょう。```

a = [1, 100, 2, 3, 200]
```並べ替え:$[1,2,3,100,200]$ギャップ:$[1,1,97,100]$並べ替えられたギャップ:$[1,1,97,100]$プレフィックス:$[0,1,2,99,199]$| k | マージ | 費用 |
 | --- | --- | --- |
 | 1 | 4 | 199 |

 | 3 | 2 | 2 |
 | 4 | 1 | 1 |

 この例では、より多くのグループが許可される場合に、大きなギャップがどのように最初に回避されるかを示します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

 ## 特殊なケース

 すべての値が同一の入力の場合、次のようになります。```
1
5
10 10 10 10 10
```ソートではギャップが生成されないため、ギャップ配列はすべて 0 になります。 すべてのプレフィックスの合計はゼロであるため、すべての答えはゼロになります。 すべてのマージ コストがゼロであるため、どのパーティションも最適であるため、アルゴリズムはこれを自然に処理します。 

次のような厳密に増加するシーケンスの場合:```

4
1 2 3 4
```ギャップは$[1,1,1]$。 プレフィックス合計では、グループが減少するにつれてコストが増加します。 このアルゴリズムは、各ギャップを独立したマージ コストとして正しく解釈し、必要なマージの昇順で累積します。 

1 つの支配的な大きなギャップがあるケースの場合:```
1

```ギャップは$[1,1,97,1]$、に並べ替えられます$[1,1,1,97]$。 大きなギャップは、初期のマージでは常にスキップされるため、残っているグループがほとんどない場合にのみ使用されます。 これは、常に利用可能な最小の接続コストを最初に採用するという貪欲な原則を示しています。
