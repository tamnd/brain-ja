 ## 解決策
 ## 問題の理解

 グリッドは、ほとんどのセルが背景で残りのセルが飛行機に属する白黒画像を表します。 飛行機の各セルには 0 から 9 までの数字が付けられており、同じ数字を共有するすべてのセルが 1 つの「ゾーン タイプ」を形成します。 課題は、どのゾーン タイプを強化するかを決定することです。 

画像とは別に、衝撃点のリストが提供されます。 各衝撃は有効な飛行機セルに着地します。つまり、常に数字のラベルが付いているピクセルの 1 つに着弾します。 数字ごとに、その数字のピクセルに衝撃が当たった回数を数えます。 また、その数字を保持するグリッド セルの数によって測定される、各数字の領域の大きさもわかります。 

決定ルールは階層的です。 まず、ヒット数が最小の桁を選択します。 複数の数字が同点の場合、画像内で占める領域のピクセル数が少ない数字が優先されます。 それでも同点の場合は、最小の数値識別子の桁を選択します。 

制約は小さく、グリッドは最大 100 x 100 で、影響の数は最大 2000 です。 これは、すべての操作がグリッド サイズと衝撃の数で線形であるため、画像全体を直接スキャンし、衝撃ごとの単純な集計を行うのが簡単に十分に高速であることを意味します。 

よくある間違いは、数字が常に連続した構成要素または単一の連結要素に現れると想定することですが、それはここでは無関係です。 もう 1 つの微妙な罠は、一部の数字がグリッドにまったく表示されない可能性があることを忘れていることです。 これらはゾーンを表さないため、考慮から除外する必要があります。 

## アプローチ

 直接的な解決策は、0 から 9 までの各数字について 2 つの情報、つまりグリッド内のその数字を含むセルの数と、そこに衝突する衝撃の数を計算します。 どちらも、グリッド上の 1 回のパスとインパクト リスト上の 1 回のパスで蓄積できます。 

それぞれの影響に答える強引な方法は、グリッド全体をスキャンして、どこに到達するかを確認することですが、その場合、各クエリが O(MN) になり、合計作業量が O(DMN) になります。これは、グリッドに直接インデックスを付けて影響箇所の数字を見つけることができるため、不要です。 

重要な観察は、グリッドが分類に必要なものすべてをすでにエンコードしているということです。 それぞれの影響は、事前に計算されたラベル付けを参照するだけであるため、イベントごとに一定時間でカウントを蓄積できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (衝撃ごとのスキャン グリッド) | O(D・M・N) | O(M・N) | 遅すぎる |
 | 最適 (事前計算 + カウント) | O(M・N+D) | O(M・N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドの寸法を読み取り、グリッドを文字列のリストとして保存します。 各セルには「.」が含まれています。 または数字文字。 有効なゾーンを定義する数字セルのみを考慮します。 
2. サイズ 10 の配列を初期化して、各桁に属するセルの数を数えます。 また、サイズ 10 の別の配列を初期化して、各桁に当たる衝撃の数をカウントします。 
3. グリッド内のすべてのセルをスキャンします。 数字文字が表示されるたびに、それを整数に変換し、そのサイズ カウンターをインクリメントします。 これにより、各ゾーン タイプの合計面積が線形時間で構築されます。 
4. 衝撃の数を読み取り、各衝撃の座標を処理します。 各座標について、グリッド セルに直接アクセスし、数値に変換します。 対応するヒットカウンターをインクリメントします。 これが機能するのは、すべての衝撃が数字のセルに到達することが保証されているためです。 
5. すべての入力を処理した後、0 から 9 までの数字を繰り返し、比較ルールを使用して最適な候補を選択します。最初に最小のヒット数、次に最小のゾーン サイズ、次に最小の桁値です。 
6. 選択した桁を出力します。 

### なぜ効果があるのか

各影響は独立して正確に 1 桁のカテゴリに寄与するため、カウントは単に固定ラベル上のイベントの分割にすぎません。 グリッド スキャンでは各ラベルの正確な重みが得られ、インパクト スキャンでは正確な頻度が得られます。 両方の数量が桁ごとに完全に集計されるため、桁の比較は、事前に計算された統計よりも単純な辞書編集上の最小値に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    M, N = map(int, input().split())
    grid = [input().strip() for _ in range(N)]

    size = [0] * 10
    hits = [0] * 10

    for y in range(N):
        row = grid[y]
        for x in range(M):
            c = row[x]
            if c != '.':
                size[int(c)] += 1

    D = int(input())
    for _ in range(D):
        y, x = map(int, input().split())
        d = grid[y][x]
        hits[int(d)] += 1

    best = None
    for d in range(10):
        if size[d] == 0:
            continue
        cand = (hits[d], size[d], d)
        if best is None or cand < best:
            best = cand

    print(best[2])

if __name__ == "__main__":
    solve()
```このソリューションでは、まず領域サイズと影響数の両方の頻度表を作成します。 グリッドのトラバーサルはすべてのセルにわたる直接ネストされたループであり、各桁の合計面積が 1 回だけ正確に分かるようになります。 第 2 フェーズでは、グリッドに直接インデックスを作成することで、各影響を一定時間で処理します。 

最後の選択ステップは Python のタプル比較に依存します。これにより、必要な優先順位 (ヒット数の最小化、サイズの最小化、桁の最小化) が自然に実装されます。

入力:```
3 3

```ここで、グリッドには数字 0、1、2 が含まれています。 

まずサイズを計算します。 

| 数字 | サイズ |
 | --- | --- |
 | 0 | 2 |
 | 1 | 4 |
 | 2 | 1 |

 現在のプロセスは次のような影響を及ぼします。 

| 影響 | セル | 数字 | ヒット曲 |
 | --- | --- | --- | --- |
 | (0,0) | 0 | 0 | 1 |
 | (2,0) | 1 | 1 | 1 |
 | (2,2) | 1 | 1 | 2 |

 したがって、最終ヒット数は次のようになります。 

| 数字 | ヒット曲 |
 | --- | --- |
 | 0 | 1 |
 | 1 | 2 |
 | 2 | 0 |

 桁 2 はヒット数が最も少ないため、小さいですが選択されます。 これは、ヒット数が意思決定階層のサイズを支配していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(MN + D) | グリッドの 1 回のフル スキャンとすべての衝撃に対する 1 回のパス |
 | スペース | O(ミネソタ州) | グリッドと固定サイズのカウンターのストレージ |

 この制約により、最大 1,000 万個のグリッド セルと 2,000 個の衝撃が処理されることが保証され、これは時間制限内に簡単に収まります。

 ## 特殊なケース

 重要なケースの 1 つは、数字がグリッドに表示されているにもかかわらず、ヒットがゼロである場合です。 この状況では、ゼロが可能な最小ヒット数であるため、有力な候補になります。 すべての数字がゼロヒットで初期化され、グリッドに表示される数字のみが考慮されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、複数の数字のヒットがゼロである場合です。 たとえば、数字 2 と 8 が両方とも存在しても影響を受けない場合、決定は最小の領域サイズになります。 選択ループはヒット数の後にサイズを明示的に比較するため、より小さい正しいゾーンが選択されます。 

最後の微妙なケースは、0 から 9 までの一部の数字がグリッドに表示されない場合です。 これらは除外する必要があります。 そうしないと、サイズがゼロのゾーンとして誤って表示されてしまいます。 小切手`if size[d] == 0: continue`有効なゾーンのみが考慮されるようにします。
