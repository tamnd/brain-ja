 ## 解決策
 ## 問題の理解

 すべての演算が 32 ビット符号なし整数を使用して実行されるマシン モデルで作業しています。 つまり、すべての結果が剰余化されます。$2^{32}$表現可能な範囲を超えた場合。 言い換えれば、乗算は無制限の整数を生成するのではなく、剰余をラップアラウンドします。$2^{32}$。 

テストケースごとに値が与えられます$N$。 概念的には、考えられるすべての 32 ビット符号なし値を考慮します。$P$。 そういったそれぞれに対して$P$、積を計算します$N \cdot P$32 ビット オーバーフロー演算を使用し、結果が次と等しいかどうかを確認します。$P$もう一度同じ算術規則に基づいて計算します。 タスクは、次の値がいくつあるかを数えることです。$P$この固定小数点条件を満たします。 

したがって、核心的な質問は次のようになります。整数のモジュロの環内で$2^{32}$、要素はいくつありますか$P$満足する$$N \cdot P \equiv P \pmod{2^{32}}.$$制約$t \le 10^5$これは、各クエリに一定時間または対数時間で応答する必要があることを意味します。 すべてを反復するアプローチ$2^{32}$可能な値$P$テスト ケースごとに約 40 億チェックが必要になるため、これは完全に不可能です。 

微妙なエッジケースが現れるのは、$N = 1$。 その場合は毎回$P$1 を乗算しても何も起こらないため、式は満たされます。したがって、答えは次のようになります。$2^{32}$。 もう一つの重要な事例は、$N = 0$、式は次のようになります$0 \equiv P \pmod{2^{32}}$、だからそれだけ$P = 0$は機能し、解決策が 1 つだけ提供されます。 

単純な実装における主なリスクは、各オブジェクトに対してオーバーフロー演算をシミュレートしようとすることです。$P$。 C++ や Python で最適化したとしても、ドメイン全体を反復処理することは不可能です。 

## アプローチ

 ブルートフォース解釈により、あらゆる可能性が直接テストされます$P$、コンピューティング$N \cdot P \bmod 2^{32}$そして等価性をチェックする$P$。 これは定義上は正しいですが、次のことが必要です$2^{32}$テスト ケースごとの操作は、時間制限をはるかに超えています。 

重要な単純化は、これをマシンの整数に対する算術として考えるのをやめ、代わりにモジュラー方程式として扱うことです。$$N \cdot P \equiv P \pmod{2^{32}}.$$並べ替えると次のようになります。$$(N - 1)\cdot P \equiv 0 \pmod{2^{32}}.$$ここで、問題は古典的な線形合同式になります。残基の数を数えています。$P$積を次で割り切れるようにする$2^{32}$。 させて$M = 2^{32}$そして$a = N - 1$。 次のようなソリューションの数が必要です。$$aP \equiv 0 \pmod{M}.$$標準的な数理論の結果から、解の数を法とすることがわかります。$M$に$aP \equiv 0$まさに$\gcd(a, M)$。 直感的には、次の倍数のみです。$M / \gcd(a, M)$生き残る、そしてまさに存在する$\gcd(a, M)$このような残基は全範囲に含まれます。 

以来$M = 2^{32}$、答えは特に簡単です。それは 2 を割る最大の累乗です。$N - 1$ただし、次の場合を除きます。$N = 1$、私たちは治療します$N - 1 = 0$そしてすべてを手に入れる$2^{32}$ソリューション。

 ## アルゴリズムのチュートリアル

 問題を各テスト ケースの最大公約数の計算に落とし込みます。 

1.読む$N$テストケースの場合、算術モジュロを解釈します$M = 2^{32}$。 これにより、すべてのオーバーフロー動作が要求どおりに正確にモデル化されることが保証されます。 
2. コンピューティング$a = N - 1$整数演算で。 この値を概念的にモジュロとして扱います$M$ただし、Python 整数を使用すると、オーバーフローの問題が回避されます。 
3. コンピューティング$g = \gcd(a, M)$。 この値は、乗数間の構造的な重複を表します。$a$そしてモジュラス。 
4. 出力$g$。 これは残基の数を直接カウントします。$P$満足する$aP \equiv 0 \pmod{M}$。 

正しさは、合同を可分性条件として解釈するかどうかにかかっています。 私たちは次の解決策を検討しています$M \mid aP$、そして gcd は正確にどれだけの量を特徴づけますか$M$の主な権力構造はと共有されています$a$、自由度を決定します$P$変化する可能性があります。 

### なぜ効果があるのか

 条件$aP \equiv 0 \pmod{M}$と同等です$M \mid aP$。 書き込み$g = \gcd(a, M)$、分解します$a = g a'$そして$M = g M'$どこ$\gcd(a', M') = 1$。 割り切れる条件は、$M' \mid a'P$。 以来$a'$可逆モジュロです$M'$、これは強制的に$M' \mid P$。 したがって$P$の倍数でなければなりません$M'$、そしてまさにあります$g$このような値のモジュロ$M$。 これにより、カウントが正確かつ網羅的になることが保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

M = 1 << 32

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        N = int(input().strip())
        a = N - 1
        g = math.gcd(a, M)
        out.append(str(g))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は Python の任意精度の整数に依存しているため、から 1 を減算します。$N$オーバーフローの問題が発生する危険はありません。 弾性率$2^{32}$は正確に 2 のべき乗として表されます。 gcd の計算は、1 つのオペランドが 2 の固定累乗であるため効率的です。そのため、実際には、$N-1$を使用していますが、`math.gcd`溶液を清潔で安全に保ちます。 

よくある実装上の間違いは、ループ内で 32 ビット オーバーフロー乗算を明示的にシミュレートしようとすることです。 代数変換では乗算が完全に削除されるため、これは不要です。 

## 実用的な例

 代表的な 2 つのケースを考えてみましょう。 

初め、$N = 1$。 それから$a = 0$そして$g = \gcd(0, 2^{32}) = 2^{32}$。 毎$P$という方程式を満たします。 

| ステップ | 値 |
 | --- | --- |
 | N | 1 |
 | a = N - 1 | 0 |
 | gcd(a, 2^32) | 2^32 |
 | 答え | 2^32 |

 これにより、恒等乗算によりすべての可能な固定点が得られることが確認されます。 

2番、$N = 5$。 それから$a = 4$、そしてそれ以来$2^{32}$は 2 のべき乗であり、gcd は 4 を割る最大の 2 のべき乗、つまり 4 です。 

| ステップ | 値 |
 | --- | --- |
 | N | 5 |
 | a = N - 1 | 4 |
 | gcd(a, 2^32) | 4 |
 | 答え | 4 |

 これは次のことだけを示しています$P$で割り切れる$2^{30}$モジュロ構造内で適切にスケーリングされたものが生き残り、正確に 4 つの有効な残基が得られます。 

これらの例は、ソリューションがバイナリ構造のみにどのように依存するかを強調しています。$N - 1$、その大きさではありません。

## テストケース```python
import sys, io
import math

M = 1 << 32

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    res = []
    for _ in range(t):
        N = int(input().strip())
        res.append(str(math.gcd(N - 1, M)))
    return "\n".join(res)

# sample-style checks
assert solve("1\n1\n") == str(1 << 32)

# N = 2 => N-1 = 1 => gcd = 1
assert solve("1\n2\n") == "1"

# N = 5 => N-1 = 4 => gcd = 4
assert solve("1\n5\n") == "4"

# N = 0 => N-1 = -1 => gcd = 1
assert solve("1\n0\n") == "1"

# multiple cases
assert solve("3\n1\n2\n5\n") == f"{1<<32}\n1\n4"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 いつ$N = 1$、式は次のようになります$1 \cdot P = P$みんなのために$P$、アルゴリズムは次のように計算します。$a = 0$そして正しく戻ります$\gcd(0, 2^{32}) = 2^{32}$。 これにより、コード内の特別な分岐が回避されます。 

いつ$N = 0$、効率的に計算します$a = -1$。 剰余算術モジュロの場合$2^{32}$、これは次のように動作します$2^{32} - 1$と互いに素である$2^{32}$なので、gcd は 1 になります。アルゴリズムは、符号なし変換を必要とせずにこれを自然に処理します。 

いつ$N$は 2 の大きなべき乗であり、$N - 1$は一連の設定ビットとなり、gcd は最も低い設定ビットを抽出し、答えが常にモジュラス構造と一致する 2 のべき乗になるようにします。
