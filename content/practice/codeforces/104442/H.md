 ## 解決策
 ## 問題の理解

 平面内にいくつかの独立した点のシーケンスが与えられます。各シーケンスは、順番に従わなければならない固定ルートを記述します。 各ルートは座標のリストです$(x_1, y_1), (x_2, y_2), \dots, (x_n, y_n)$、連続したポイント間の動きのみを考慮します。 

連続するポイントのペアごとに、絶対水平変位の 3 倍と符号付き垂直変位の 2 倍という一次式で定義される「ファン コスト」を計算します。 水平部分は方向を無視しますが、垂直部分は方向を維持するため、上方向への移動と下方向への移動は別の方法で処理されます。 

各テスト ケースの目標は、ルート内のすべての連続するペアの中でこのコストの最大値を見つけることだけです。 

入力サイズの制約により、それぞれ最大 1000 ポイントを持つ最大 200 のシーケンスが許可されるため、合計で最大約 200,000 のエッジになります。 これはすぐに次のことを示唆しています。$O(n)$すべてのポイントにわたる完全な線形パスでも問題なく制限内に収まるため、テスト ケースごとのスキャンで十分です。 

ここでよくある微妙な間違いは、絶対値構造の読み間違いに起因します。 x の差だけが絶対的です。 y の違いはそうではありません。 たとえば、$(0, 0)$そして$(0, -10)$、貢献度は$3 \cdot 0 + 2 \cdot (-10) = -20$、これはマイナスです。 両方の座標に絶対値を適用する誤った実装により、これが誤って次のようになります。$20$、最大値を完全に変更します。 

もう 1 つの問題は、結果が負でないと仮定することです。 符号付き垂直項のため、すべての動きが式を減少させる場合、すべてのエッジにわたる最大値は依然として負になる可能性があります。 

## アプローチ

 問題の構造は非常に局所的なものです。 各エッジは独立して最終的な答えに寄与し、パスの異なるセグメント間に相互作用はありません。 これにより、プレフィックス構造、動的プログラミング、または幾何学的最適化の必要性が直ちに排除されます。 

ブルートフォースアプローチはすでに最適です。隣接するすべてのペアの値を計算し、最大値を追跡します。 正確性を保証するにはすべてのエッジを少なくとも 1 回検査する必要があるため、必要な比較の数を減らす代替の定式化はありません。 

大域的な幾何学的解釈を探ろうとする人もいるかもしれませんが、その式は距離計量ではなく、対称性や三角形の特性を有効な形で満たしていません。 依存関係は厳密にペアごとであるため、問題は計算された値の配列をスキャンすることになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. ポイント数を読み取る$n$そして座標リスト。 座標は平坦化された形式で与えられるため、連続したペアとして解釈されます。 
2. 変数を初期化する`best`すべての計算値が負になる可能性があるため、非常に小さな数に設定します。 
3. からの点の連続する各ペアを反復します。$i = 1$に$n - 1$。 ペアごとに抽出します$(x_i, y_i)$そして$(x_{i+1}, y_{i+1})$。 
4. 水平方向の差を次のように計算します。$|x_{i+1} - x_i|$。 これにより、水平方向の移動に方向は関係なくなります。 
5. 垂直方向の差を次のように計算します。$y_{i+1} - y_i$変更なしで。 
6. コストを評価する$3 \cdot |x_{i+1} - x_i| + 2 \cdot (y_{i+1} - y_i)$。 
7.アップデート`best`この値が現在保存されている最大値より大きい場合。 
8. すべてのエッジを処理した後、出力します`best`。 

### なぜ効果があるのか

 各エッジは独立したスカラー スコアに寄与し、問題はこれらの独立した値の最大値を求めます。 エッジ間に結合がないため、グローバル最適値はローカル評価の最大値と一致する必要があります。 このアルゴリズムは、考えられる寄与者をすべて 1 回だけ列挙するため、候補が見逃されることはなく、値が二重にカウントされたり、以降のステップで変更されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        best = -10**18
        
        for i in range(n - 1):
            x1, y1 = arr[2*i], arr[2*i + 1]
            x2, y2 = arr[2*i + 2], arr[2*i + 3]
            
            val = 3 * abs(x2 - x1) + 2 * (y2 - y1)
            if val > best:
                best = val
        
        out.append(str(best))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は数学的定義を直接反映しています。 重要な詳細は、垂直方向の用語を署名したままにすることです。 もう 1 つの微妙な点は初期化です`best`すべての計算値が負になる可能性があるため、ゼロではなく非常に小さな値を使用します。 

## 実用的な例

 3 つの点がある 1 つのルートを考えてみましょう。$(0,0)$、$(2,1)$、$(3,-2)$。 

最初のセグメントの場合:

 | セグメント | Δx | Δy | 値 |
 | --- | --- | --- | --- |
 | (0,0) → (2,1) | 2 | 1 | 3・2 + 2・1 = 8 |

 2 番目のセグメントの場合:

 | セグメント | Δx | Δy | 値 |
 | --- | --- | --- | --- |
 | (2,1) → (3,-2) | 1 | -3 | 3・1 + 2・(-3) = -3 |

 最大値は 8 です。 

このトレースは、負の垂直方向の動きがスコアを大幅に低下させる可能性があることを示しています。そのため、最適なエッジは必ずしも最大の絶対変位を持つエッジであるとは限りません。 

ここで、次のようなすべての値が負の場合を考えてみましょう。$(0,0)$、$(0,-1)$、$(0,-2)$。 

| セグメント | Δx | Δy | 値 |
 | --- | --- | --- | --- |
 | (0,0) → (0,-1) | 0 | -1 | -2 |
 | (0,-1) → (0,-2) | 0 | -1 | -2 |

 答えは -2 で、最大値が陽性を意味するものではないことがわかります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        best = -10**18
        for i in range(n - 1):
            x1, y1 = arr[2*i], arr[2*i + 1]
            x2, y2 = arr[2*i + 2], arr[2*i + 3]
            val = 3 * abs(x2 - x1) + 2 * (y2 - y1)
            best = max(best, val)
        out.append(str(best))
    
    return "\n".join(out)

# minimum size
assert run("1\n2\n0 0 1 1\n") == "5"

# all negative vertical movement
assert run("1\n3\n0 0 0 -1 0 -2\n") == "-2"

# horizontal only
assert run("1\n3\n0 0 5 0 10 0\n") == "15"

# mixed values
assert run("1\n4\n0 0 1 2 3 -1 4 0\n") == "9"

 ## 特殊なケース

 重要なエッジケースは、すべての垂直方向の動きが負であり、すべてのセグメント値が負になる可能性がある場合です。 このアルゴリズムは非負性を想定していないため、引き続き機能します。 最大値を非常に小さな値で初期化し、純粋に比較によって更新します。 

もう 1 つのエッジ ケースは、平坦な水平パスです。 この状況では、結果は水平方向のギャップのみに依存します。 絶対値により、方向の変更が結果に影響を与えないことが保証されるため、左右に進むパスでも正の寄与が正しく蓄積されます。
