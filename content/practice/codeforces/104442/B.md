 ## 解決策
 ## 問題の理解

 無限の整数グリッド上を移動するロボットが与えられています。 指定された座標から開始され、踏むことができない一連のブロックされたグリッド ポイントを回避しながらターゲット座標に到達する必要があります。 ロボットは領域を占有せず、単一点として扱われるため、衝突は正確な座標でのみチェックされます。 

移動ルールは通常の最短経路ルールではありません。 ロボットには方向があり、常に 4 つの軸方向のいずれかに一致します。 グリッド ポイントから、現在の方向に 1 単位だけ前進することも、左または右に 90 度回転することもできます。 先に進むには 1 単位の時間がかかります。 回転には 4 単位の時間がかかります。 回転した後、ロボットが前進する場合、その移動にはさらに 1 単位の時間がかかります。 

微妙だが重要なルールは、ロボットは開始位置で、コストをかけずに最初の方向を自由に選択できるということです。 目標は、最終的な向きに関係なく、目的地に到達するために必要な最小の合計時間を計算することです。 

モーションはグリッドベースですが、コスト構造により、これは標準の BFS 最短パスとは異なります。 回転は移動よりも大幅にコストがかかるため、最適なパスは必ずしもステップ数が最も少ないパスであるとは限りません。 

制約の観点から見ると、グリッドは潜在的に大きいか無制限ですが、ブロックされたセルの数は有限であり、通常はハッシュ セットに格納できるほど十分に小さいです。 これは、明示的なグリッドを構築しようとすべきではないことを強く示唆しています。 代わりに、移動ルールに従って最初から実際に到達可能な状態のみを生成します。 各状態には位置と方向があるため、自然状態空間は 4 倍になります。 

これにより、ポジションのみの加重されていない BFS が即座に除外されます。 また、分岐要素が急速に増大し、アクションごとにコストが異なるため、単純な再帰やすべてのパスの強引な列挙を行う余裕はありません。 重みを伴う最短パス アルゴリズムが必要です。 

よくある失敗例は、状態の一部としての方向性を無視したことに起因します。 たとえば、北を向いてセルに到達することは、東を向いてセルに到達することと同等ではありません。これは、回転ペナルティが大きいため、将来のコストが向きに大きく依存するためです。 

## アプローチ

 ブルートフォースアプローチでは、開始点からターゲットまでの可能なパスをすべて列挙し、一連の移動と回転をすべて調査しようとします。 すべての有効なパスが考慮されるため、これは理論的には正しいですが、可能なアクション シーケンスの数はパスの長さに応じて指数関数的に増加します。 各セルでロボットは回転または移動でき、位置を変えずに回転を繰り返すことができるため、わずかな数のステップでも、数え切れないほどの組み合わせが生成されます。 

重要な観察は、これが暗黙的な重み付きグラフ上の最短経路問題であるということです。 各状態は位置だけでなく向きによっても定義されます。 各状態からは最大 3 つの遷移があります。コスト 1 で前進、コスト 4 で左回転、コスト 4 で右回転です。これにより、問題が非負の重みを持つグラフに変換されます。これはまさにダイクストラのアルゴリズムが適用される設定です。 

重要な構造の単純化は、より高いコストをかけて同じ状態を再訪するパスを考慮する必要がないことです。 一度治療したら`(x, y, direction)`ノードとして、優先キューを安全に使用して、コストの昇順に状態を拡張できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスの総当たり列挙 | 指数 | 指数 | 遅すぎる |
 | (x、y、方向) の状態に関するダイクストラ | O(E log V) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 ロボットの各構成を、その位置と現在の向いている方向から構成される状態としてモデル化します。 次に、これらの状態に対して最短パス アルゴリズムを実行します。 

1. 考えられる 4 方向すべての開始位置で優先キューを初期化し、各方向のコストをゼロにします。 これは、初期方向をペナルティなしで自由に選択できるというルールをモデル化します。 すべての方向を有効な開始状態として扱うことで、最初の向きの変更を必要とする解を見逃すことがなくなります。 
2. をキーとする距離辞書を維持します。`(x, y, direction)`各状態に到達するための最もよく知られているコストを保存します。 より高いコストをかけて再訪された状態は無視されます。 
3. 各ステップで、優先キューから累積コストが最小の状態を抽出します。 これにより、状態を処理するときに、その最適なコストがすでに得られることが保証されます。 
4. 現状から左右への回転を考えます。 回転するたびに位置は変わりませんが、方向が変わり、コストが 4 追加されます。より安価にアクセスできる方法が見つかった場合は、それらの隣接州を緩和します。 
5. 現在の方向性をさらに進めることも検討します。 これにより、同じ方向の新しい位置状態が生成され、コスト 1 が追加されます。ただし、この遷移は、次のセルがブロックされていない場合にのみ許可されます。 
6. 優先キューが空になるか、ターゲットの位置に到達するまで、状態を拡張し続けます。 答えは、ターゲット座標における全方向の最小コストです。 

正確さの背後にある重要な考え方は、すべての正当なアクション シーケンスがこの状態グラフ内のパスに対応し、すべてのパス コストがエッジの重みの合計によって正確に表現されるということです。 ダイクストラは常にコストの昇順に探索するため、最初に状態を最終的に決定した時点で、その状態に到達するための最適な方法がすでに見つかっています。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

# direction encoding: 0=N, 1=E, 2=S, 3=W
dx = [-1, 0, 1, 0]
dy = [0, 1, 0, -1]

def solve():
    sx, sy = map(int, input().split())
    tx, ty = map(int, input().split())
    n = int(input().strip())

    blocked = set()
    for _ in range(n):
        x, y = map(int, input().split())
        blocked.add((x, y))

    INF = 10**18
    dist = {}

    pq = []

    # free initial orientation
    for d in range(4):
        dist[(sx, sy, d)] = 0
        heapq.heappush(pq, (0, sx, sy, d))

    while pq:
        cost, x, y, d = heapq.heappop(pq)

        if dist.get((x, y, d), INF) != cost:
            continue

        if x == tx and y == ty:
            print(cost)
            return

        # rotate left
        nd = (d + 3) % 4
        nc = cost + 4
        if dist.get((x, y, nd), INF) > nc:
            dist[(x, y, nd)] = nc
            heapq.heappush(pq, (nc, x, y, nd))

        # rotate right
        nd = (d + 1) % 4
        nc = cost + 4
        if dist.get((x, y, nd), INF) > nc:
            dist[(x, y, nd)] = nc
            heapq.heappush(pq, (nc, x, y, nd))

        # move forward
        nx = x + dx[d]
        ny = y + dy[d]
        if (nx, ny) not in blocked:
            nc = cost + 1
            if dist.get((nx, ny, d), INF) > nc:
                dist[(nx, ny, d)] = nc
                heapq.heappush(pq, (nc, nx, ny, d))

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、グリッドを事前計算するのではなく、オンデマンドで暗黙的な状態グラフを構築します。 プライオリティ キューにより、状態がコストの昇順で処理されることが保証されます。これは、回転エッジの重みが移動エッジよりも高いために必要です。 

実装の微妙な詳細は、開始時の 4 つの方向すべての初期化です。 これがないと、アルゴリズムは固定された初期方向を誤って仮定し、別の方向から開始する必要がある最適な解決策を逃す可能性があります。 

もう 1 つの重要な詳細は、距離ごとに保存することです。`(x, y, direction)`座標ごとではなく。 方向性が崩壊すると、将来のコストが根本的に異なる状態が統合され、最適性が損なわれます。 

## 実用的な例

 ロボットが次の場所から開始する簡単なシナリオを考えてみましょう。`(0, 0)`どの方向を向いても手を伸ばしたい`(2, 0)`障害物がない状態で。 

最小限のトレースは次のようになります。 

| ステップ | 状態 | コスト | アクション |
 | --- | --- | --- | --- |
 | 1 | (0,0,N) | 0 | 開始 |
 | 2 | (0,0,E) | 0 | 初期の自由回転 |
 | 3 | (0,0,E) | 4 | 回転は今のところ無視されます |
 | 4 | (1,0,E) | 1 | 前進 |
 | 5 | (2,0,E) | 2 | 前進 |

 これにより、アルゴリズムが不必要な回転よりも移動を正しく優先していることが確認されます。 

次に、回転が必要な場合を考えてみましょう。 

スタート`(0,0)`に`(1,1)`。 

| ステップ | 状態 | コスト | アクション |
 | --- | --- | --- | --- |
 | 1 | (0,0,E) | 0 | 開始 |
 | 2 | (0,0,N) | 4 | 左に回転 |
 | 3 | (0,0,N) | 4 | 回転が適用されました |
 | 4 | (0,1,N) | 5 | 前進 |
 | 5 | (1,1,N) | 6 | 前進 |

 このトレースは、回転コストが経路選択を支配していることを示しており、アルゴリズムは両方の可能性を調査することにより、早く回転するか遅く回転するかどちらが安くなるかを正しく評価します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((V + E) log V) | 州をめぐるダイクストラ`(x,y,dir)`ポジションごとに最大 4 方向 |
 | スペース | O(V) | 訪問した州ごとに最適な距離を保存する |

 訪問される状態の数は、座標範囲全体ではなく、到達可能なグリッド セルに依存するため、実際のアルゴリズムの効率が維持されます。 各状態は最大 3 つの遷移を生成するため、定数係数は小さいままです。 これは、障害物によるグリッド最短経路問題の一般的な制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    dx = [-1, 0, 1, 0]
    dy = [0, 1, 0, -1]

    sx, sy, tx, ty, *rest = map(int, inp.split())
    n = rest[0]
    blocked = set()
    idx = 1
    for _ in range(n):
        blocked.add((rest[idx], rest[idx+1]))
        idx += 2

    INF = 10**18
    dist = {}
    pq = []

    for d in range(4):
        dist[(sx, sy, d)] = 0
        heapq.heappush(pq, (0, sx, sy, d))

    while pq:
        cost, x, y, d = heapq.heappop(pq)
        if dist.get((x, y, d), INF) != cost:
            continue
        if x == tx and y == ty:
            return str(cost)

        for nd in [(d+3)%4, (d+1)%4]:
            nc = cost + 4
            if dist.get((x, y, nd), INF) > nc:
                dist[(x, y, nd)] = nc
                heapq.heappush(pq, (nc, x, y, nd))

        nx, ny = x + dx[d], y + dy[d]
        if (nx, ny) not in blocked:
            nc = cost + 1
            if dist.get((nx, ny, d), INF) > nc:
                dist[(nx, ny, d)] = nc
                heapq.heappush(pq, (nc, nx, ny, d))

    return "-1"

assert run("0 0\n1 1\n0\n") == "6"
assert run("0 0\n2 0\n1\n1 0\n") == "-1"
assert run("0 0\n0 0\n0\n") == "0"

 ## 特殊なケース

 一般的なエッジケースは、ターゲットが開始位置と同じである場合です。 4 つの初期状態はすべてターゲット座標ですでに開始されているため、アルゴリズムはこれを正しく処理します。そのため、最初のポップされた状態はすぐにコスト 0 で終了をトリガーします。 

もう 1 つの微妙なケースは、障害物によってロボットが特定の方向からセルに接近せざるを得なくなる場合です。 方向は状態にエンコードされているため、アルゴリズムは有用な方向を向いた座標に到達するか、使用できない方向に到達するかを区別し、強制的な迂回が正しく評価されるようにします。 

さらに特殊なケースとして、同じセルで複数回回転する方が、後で移動して方向を修正するよりもコストがかからない場合があります。 ダイクストラ フレームワークは、回転エッジが明示的にモデル化されており、総コストが削減される場合には繰り返し適用できるため、当然両方の可能性を検討します。
