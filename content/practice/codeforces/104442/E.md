 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは、一方通行の道路に沿った一連の建物の高さを記述します。 市は、左から右に移動しても高さが決して下がらないように、この順序を変更したいと考えています。 

唯一許可される操作は、連続するセグメントを選択し、そのセグメント内のすべての建物の高さを強制的に同じにすることです。 このような操作のコストは、セグメント内のすべての建物に適用される絶対的な変更の合計となります。 

目標は、操作の数を最小限に抑えることではなく、元の配列をこれらのセグメント書き換え操作を通じて到達可能な非減少シーケンスに変換するのに必要な総コストを最小限に抑えることです。 

重要な観察は、非減少でなければならないことを除いて、実行する操作の数や最終的な形状に制限がないことです。 これは、最終的な配列の構造が単調性を尊重する限り完全に柔軟であり、コストは元の値をどのように「再形成」するかによってのみ決まることを意味します。 

制約は十分に小さいので、テスト ケースごとに O(n^2) または O(n^3) の動的プログラミング アプローチが実現可能ですが、すべてのテスト ケースの n の合計は 5000 にすぎないため、注意が必要です。これは、テスト ケースごとの 2 次解は許容できるが、3 次のものはすべて最適化する必要があることを強く示唆しています。 

素朴な解釈では、セグメント操作をシミュレートしようとしたり、違反をローカルで貪欲に修正しようとしたりすることを提案するかもしれませんが、1 つのセグメントを変更すると、非ローカルな方法で将来の選択と相互作用する可能性があるため、これは失敗します。 

さらに微妙な問題は、最適な変換によって、ローカルの貪欲な観点からは明らかではない方法で重複するセグメントが繰り返し上書きされる可能性があることです。 たとえば、局所的に平坦化することですべての降下を貪欲に修正すると、すでに調整された値を再利用する機会が失われるため、後でコストが増加する可能性があります。 

## アプローチ

 強引なアイデアは、演算の観点から直接考えることです。非減少配列を生成するセグメント割り当てのシーケンスを選択します。 ただし、各ステップでセグメントとターゲットの高さが選択され、そのような操作のシーケンスが重なり合うため、すべてのセグメンテーションを列挙することは指数関数的になります。 

代わりに、問題を再解釈します。最終的な配列は非減少シーケンスであり、各セグメント操作は、ブロックを選択された定数値に強制するためのコストを支払う単なる方法です。 最終的な配列を修正すると、コストは位置間で独立したものになります。各インデックスは、元の値と最終的に割り当てられた値の間の絶対差をすべてのインデックスで合計したものになります。 

したがって、問題は減少しないターゲット配列を選択することになります。`b`最小化:

 合計 |p[i] - b[i]|

 ここでの問題は純粋に制約付きの最適化です。L1 距離が元のシーケンスに最も近い非減少シーケンスが必要です。 

これは古典的な動的プログラミング構造です。 させて`dp[i][v]`最初の最小コストになる`i`i 番目の最終値が正確に一致する場合の要素`v`。 移行には次のことが必要です`b[i] >= b[i-1]`、これにより、プレフィックスの最小制約が導入されます。`v`。 

値は最大 5000 であるため、候補値に対するプレフィックス最小値を使用して遷移を最適化できます。 

重要な洞察は、固定 i の場合、b[i] = v を選択すると |p[i] - v| に寄与し、最後の値 ≤ v を持つ前の最良の状態のみを考慮するということです。これにより、各遷移が dp[i-1] に対するプレフィックス最小クエリに変わります。 

したがって、可能な高さをスキャンし、プレフィックスの最小値を維持しながら行ごとに dp を構築します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

## ステップ 1: 非減少ターゲット配列の選択として問題を解釈する

 演算の概念をより単純な同等の概念に置き換えます。つまり、各位置は選択された高さで終了し、最終的なシーケンスは非減少でなければなりません。 コストは、元の値と選択した値の間の絶対差の合計です。 

これは、最終的なモノトーン シーケンスはセグメント操作によって構築でき、操作のシーケンスによって最終的にそのようなターゲット配列が定義されるため、有効です。 

## ステップ 2: 動的プログラミング状態を定義する

 私たちは定義します`dp[v]`配列の現在のプレフィックスを処理するための最小コストとして、最終値で正確に終了します`v`。 

初期化時に、最初の要素について、 dp[v] = |p[0] - v| を直接計算します。 

## ステップ 3: 新しいポジションごとに移行

 新しい要素 p[i] ごとに、新しい配列を計算します。`new_dp`。 

位置 i の候補最終値 v については、以前の値が ≤ v であることを確認する必要があります。したがって、次のことが必要です。 

new_dp[v] = |p[i] - v| すべての u ≤ v に対する + min(dp[u])

 内側の最小値は、dp に対するプレフィックスの最小値です。 

v を 1 から MAXA まで反復する間、実行中のプレフィックスの最小値を維持します。 

## ステップ 4: dp を更新する

 new_dp を計算した後、dp をそれに置き換えて、次のインデックスに進みます。 

## ステップ 5: 回答の抽出

 すべての要素を処理した後の答えは、すべての v にわたる min(dp[v]) になります。 

### なぜ効果があるのか

 DP は、最終的な高さのすべての単調割り当てを正確にエンコードします。 プレフィックスの最小値により、以前の有効な高さが許可されると同時に、非降順順序が強制されます。 各状態は、その高さで終了するすべてのシーケンスの中で最良のコストを表すため、実行可能な構成が失われることはなく、無効な減少遷移は許可されません。 

各遷移では、プレフィックス最小値を通じてすべての有効な以前の値が考慮されるため、反復ではシーケンスを明示的に列挙することなく、解空間全体が探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MAXV = 5000

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        dp = [0] * (MAXV + 1)

        for v in range(1, MAXV + 1):
            dp[v] = abs(p[0] - v)

        for i in range(1, n):
            new_dp = [0] * (MAXV + 1)

            best = float('inf')
            for v in range(1, MAXV + 1):
                if dp[v] < best:
                    best = dp[v]
                new_dp[v] = best + abs(p[i] - v)

            dp = new_dp

        print(min(dp[1:]))

if __name__ == "__main__":
    solve()
```初期化ステップでは、最初の要素を可能なそれぞれの高さに強制するコストをエンコードします。 遷移ループはプレフィックスの最小値を慎重に維持します`best`これは、v までの最も安価な有効な以前の高さを表します。これはまさに単調性制約です。 

最後の値は実現可能性を超えて制約されないため、最終的な答えは、考えられるすべての終了高さの最小値をとります。

 ## 特殊なケース

 重要なエッジケースは、次のような完全に減少する配列です。`[5,4,3,2,1]`。 貪欲な修正では、隣接するペアを繰り返し平らにしてオーバーペイすることになりますが、DP は代わりに、次のような滑らかな単調なターゲットを選択します。`[3,3,3,3,3]`最適なバランスに応じて、または同様のもの。 プレフィックスの最小値により、局所的な修正を強制することなく、すべての位置が初期の最適な高さを継承できるようになります。 

単一要素テストの場合、値の選択に関係なく答えが単純にゼロになるため、DP は正しく初期化され、すべての最終高さの最小値は操作が必要ないことを正確に反映します。 

次のような交互シーケンスの場合`[1,100,1,100]`、素朴な直感は交互の修正を示唆するかもしれませんが、DP はグローバルに一貫した単調ターゲットを正しく蓄積し、順序付けの制約に違反する振動的な決定を回避します。
