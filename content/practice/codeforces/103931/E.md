 ## 問題の理解

 ソース文字列が与えられます$S$そしてターゲット文字列$F$。 タスクは、連続したセグメントを切り取ることです。$S$、次のような部分文字列を意味します$F$は、そのセグメント内でサブシーケンスとして引き続き見つけることができます。 このようなすべての有効なセグメントの中で、可能な限り長さが短いセグメントが必要です。 

重要な制約は、$F$すでに次の部分列であることが保証されています$S$したがって、少なくとも 1 つの有効な部分文字列、つまり文字列全体が常に存在します。$S$。 

文字列は長いです:$S$到達できる$10^5$テスト ケースあたりの文字数は最大です。$10^4$結合された最大長のテスト ケース$5 \cdot 10^5$。 これにより、二次関数は即座に除外されます。$|S|$。 すべての部分文字列を明示的に試行したり、候補ウィンドウごとに最初からスキャンを繰り返したりするアプローチは失敗します。 

微妙なエッジ ケースは、サブシーケンス マッチングがインデックス選択において柔軟であるという事実から生じます。 同じキャラクターが$F$のさまざまな位置で一致させることができます$S$、マッチングが異なるとウィンドウの長さが異なる場合があります。 左からの単純な貪欲な前方一致は、不適切な終了位置に固定され、最小ではない部分文字列を生成する可能性があります。 

たとえば、次のように考えてみましょう$S =$ `abac`、$F =$ `ac`。 フォワード・グリーディ・マッチは選択する可能性があります`a(1) -> c(4)`、窓を与える`[1,4] = abac`、最適なウィンドウは`[3,4] = ac`。 不一致は、早期に発生することにコミットすることで発生します。`a`。 

別の失敗例は、1 つの文字が複数存在する場合に発生します。 各文字に対して最初に一致する可能性のあるものを選択する$F$終了インデックスは最大化されますが、ウィンドウの最小化は保証されません。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての部分文字列が試行されます。$S$、それぞれについて次のことを確認します。$F$はサブシーケンスです。 単一の部分文字列の長さをチェックする$m$長さのパターンに対して$|F|$費用$O(m)$。 がある$O(n^2)$部分文字列なので、全体の複雑さは次のようになります。$O(n^3)$、これは限界をはるかに超えています。$n = 10^5$。 

サブシーケンスチェックを最適化したとしても、$O(|F|)$、まだ得られます$O(n^2 \cdot |F|)$、それは依然として不可能です。 

重要な点は、実際にはすべての部分文字列を試す必要はないということです。 代わりに、部分シーケンスの一致が内部で終了する場所を修正できます。$S$、そして、そこで終了する有効なサブシーケンスを可能にする可能な限り最良の開始位置を求めます。 

これは 2 相マッチングのアイデアにつながります。 まず、すべての位置について計算します。$F$、での最も古いインデックス$S$ここで、その文字までの接頭辞を照合できます。 次に、すべての位置について右から計算します。$F$、可能な最新の開始インデックス$S$その位置以降のサフィックスと一致することができます。 これらを組み合わせると、各位置合わせ位置の候補ウィンドウが得られます。$F$, そして最低限のものを取ります。 

基本的に、サブシーケンスマッチングの前方到達可能性と後方到達可能性を事前計算します。 以来$|F| \le 100$、する余裕があります。$O(|S| \cdot |F|)$前処理中。

 ## アルゴリズムのチュートリアル

 マッチングを追跡位置として扱います。$S$の各プレフィックスとサフィックスに対応する$F$。 

### フォワードパス

 1. 配列を初期化する`L`サイズの$|F|$、 どこ`L[i]`最も古いインデックスを保存します$S$マッチングを終了できる場所$F[0..i]$。 

スキャンを開始します$S$ポインタを上に置いたまま左から右へ$F$。 
2. の各文字について$S$、現在の文字と一致する場合$F$、その位置を次の一致として割り当て、ポインタを に移動します。$F$フォワード。 
3. キャラクターを完成させたら$F[i]$、現在のインデックスを保存します`L[i]`。 

これにより、次のことが保証されます`L[i]`長さの接頭辞の可能な左端の終了位置です$i+1$、私たちは常に消費しているので、$S$貪欲に左から右へ。 

### バックパス

 1. 同様に配列を構築します`R`どこ`R[i]`の最新の開始インデックスです$S$そこからマッチングできます$F[i..]$。 
2.スキャンします$S$右から左へ、ポインタを末尾から維持します。$F$後ろ向きに。 
3. 文字が一致するたびに、現在の位置がそのサフィックスの有効な開始位置として記録されます。 

これにより、`R[i]`接尾辞の開始可能な右端です$F[i..]$。 

### 結果の結合

 1. 各スプリットポイントについて$i$で$F$で始まるウィンドウを考えてみましょう。`R[i]`そしてで終わります`L[i]`。 
2. 最良の答えは、有効なすべての答えのうちの最小値です。$i$の`L[i] - R[i] + 1`。 
3. からその部分文字列を抽出します。$S$。 

### なぜ効果があるのか

 以下を含む有効な部分文字列に対して、$F$サブシーケンスとして、次のマッピングが存在します。$F$の中へ$S$。 位置をどこにしますか$F[i]$マップされている場合は、split: プレフィックスを定義します$F[0..i]$ある位置で終わる一致とサフィックス$F[i..]$ある位置から一致します。 前方パスと後方パスは、これらのエンドポイントに対して可能な最良の極値の選択を個別に計算します。 有効な埋め込みはプレフィックス エンドポイントとサフィックス スタートの両方を尊重する必要があるため、これらの分割ポイントの間に最適なウィンドウが表示される必要があります。 これにより、部分文字列にわたるグローバル最適化問題が、部分文字列にわたる線形スキャンに縮小されます。$F$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S, F = input().split()
    n, m = len(S), len(F)

    # L[i] = earliest end position in S for F[0..i]
    L = [-1] * m
    j = 0
    for i in range(n):
        if j < m and S[i] == F[j]:
            L[j] = i
            j += 1
            if j == m:
                break

    # R[i] = latest start position in S for F[i..]
    R = [-1] * m
    j = m - 1
    for i in range(n - 1, -1, -1):
        if j >= 0 and S[i] == F[j]:
            R[j] = i
            j -= 1
            if j < 0:
                break

    best_len = n + 1
    best_l = best_r = 0

    for i in range(m):
        if L[i] != -1 and R[i] != -1 and R[i] <= L[i]:
            cur_len = L[i] - R[i] + 1
            if cur_len < best_len:
                best_len = cur_len
                best_l, best_r = R[i], L[i]

    print(S[best_l:best_r + 1])

if __name__ == "__main__":
    T = int(input())
    for _ in range(T):
        solve()
```順方向スキャンは、文字を貪欲に消費することによって、前方一致の最も早い完了ポイントを構築します。 逆方向スキャンでは、サフィックス一致の可能な最新の開始点を対称的に構築します。 

ここでよくある間違いは、前方の貪欲な一致のみが答えを決定すると仮定することです。 これでは 1 つのエンドポイントのみが修正され、サブシーケンスの開始を移動するとウィンドウが縮小する可能性があることは無視されます。 逆方向配列を使用すると、明示的に列挙することなく代替の配置を探索できるようになります。 

最後のループでは、すべての分割位置をチェックします。$F$安全です。$|F| \le 100$、したがって、$O(|F|)$テストケースごとのスキャンは簡単です。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$F$繰り返しの文字で構成されており、複数の有効な一致が存在します。$S$。 このアルゴリズムは、単一の貪欲なパスではなく、極端な位置のみを保存することでこれを処理します。 のために`S = aaaaa`、`F = a`、どちらのスキャンでも、唯一の文字が最も古いものと最も新しいものとしてマークされ、単一文字の正しい答えが生成されます。 

もう 1 つのケースは、より厳しい境界を達成するために、最適なウィンドウで初期の発生をスキップする必要がある場合です。 で`S = abac`、`F = ac`、順方向スキャンのみが一致します`a`インデックス 0 および`c`インデックス 3 ですが、逆方向スキャンによりペアリングが可能になります`a`インデックス 2 で`c`インデックス 3 で、最適な値を生成します。`ac`。 分割ベースの組み合わせにより、両方の可能性が確実に評価されます。 

最後の微妙なケースは、特定の分割に対して前方エンドポイントと後方エンドポイントが矛盾している場合です。 条件`R[i] <= L[i]`プレフィックスが終了した後にサフィックスが始まる無効なウィンドウを防ぎます。 これにより、実行可能なサブシーケンスの埋め込みのみが答えに寄与することが保証されます。
