 ## 解決策
 ## 問題の理解

 私たちは、離散秒間実行されるプロセスをモデル化しており、各秒ごとに現在のスタミナ値に等しい報酬が生成されます。 スタミナはある初期値から始まります$S$、時間の経過とともに自然に 1 秒ごとに減少します。 スタミナがゼロ以下になると、キャラクターは眠りに落ちてしまい、それ以上の貢献は重要ではないため、プロセスは無効になります。 

いつでもコーヒーショットを飲むことができます。 コーヒーを飲むと2つの効果があります。 まず、一定期間スタミナをロックします。$C$秒、つまり、そのウィンドウ内で減少が停止することを意味します。 第二に、コーヒー効果が終了した後、システムは通常の進行と比較して 1 スタミナの追加ペナルティを支払うため、長期的にはそのサイクルのコストがわずかに高くなります。 また、コーヒーはチェーンできないため、コーヒーがアクティブな間に別のコーヒーを開始することはできません。 

タスクは、有効な秒数全体のスタミナ値の合計が最大になるように、いつコーヒーを飲むかを選択することです。 

入力サイズが大きく、最大$10^5$テストケースと値$S$そして$C$テスト ケースごとの単純な 1 秒あたりのプロセスには最大 172800 が必要となるため、これにより、時間の経過に伴うシミュレーションは直ちに除外されます。$10^{10}$最悪の場合の運用。 

最大の難点は、コーヒーが短期的な利益（高いスタミナ値の凍結）と長期的な損失（将来のスタミナを減らす遅延ペナルティ）との間にトレードオフをもたらすことである。 すべてのコーヒースケジュールを明示的に試行するソリューションは構造的に指数関数的であり、中程度のコーヒースケジュールであっても実行不可能です。$S$。 

コーヒーが役に立たない、または有害な場合、微妙なエッジケースが現れます。 たとえば、次の場合$C = 1$、凍結はほとんど役に立ちませんが、それでも遅延ペナルティを引き起こします。 このような場合、最適な行動はコーヒーを決して飲まないことです。 常に高いスタミナで飲酒する単純な貪欲なアプローチは、利益を過大評価することになります。 

もう 1 つのエッジケースは次のような場合です$S$に比べて非常に大きいです$C$。 このような場合、複数のコーヒーの使用が最適な間隔の間隔で重なる可能性があり、コーヒーを独立したブーストとして扱う単純な戦略は、遅延ペナルティと将来の間隔の間の相互作用を無視するため失敗します。 

## アプローチ

 コーヒーを完全に無視すれば、プロセスは簡単です。 スタミナが減少します$S$を 1 にすると、寄与度の合計は三角和となります。$S + (S-1) + \dots + 1$に等しい$S(S+1)/2$。 

コーヒーの導入は、衰退を「一時停止」できることを意味します。$C$秒。 その一時停止中、より高いスタミナ値を効果的に長期間保持し、その間隔中の貢献度の合計が増加します。 ただし、この利点には、コーヒーが終了した後に追加の減少が遅れるという代償が伴い、将来の貢献が減少します。 

ブルートフォースアプローチでは、クールダウンの制約を考慮して、コーヒーを飲むか飲まないかという、考えられるすべての決定を毎秒シミュレートします。 これにより、時間とコーヒーがアクティブであるかどうかの両方に依存する状態空間が得られ、決定の数とともに指数関数的に増加します。 時間とクールダウン状態に応じた動的プログラミングの定式化でも、$O(S)$制約を考えるとそれは不可能です。 

重要な観察は、このシステムはコーヒーセグメントを除いてスタミナ減衰が線形であり、各コーヒーが通常の減少するセグメントを効果的に長さの平坦なセグメントに置き換えることです。$C$、ただし、将来の崩壊コストを増加させることでタイムラインを変更します。 これは、各コーヒーを純利益の観点から独立して評価できることを意味し、最適な戦略は、使用するコーヒーの数と、それらのコーヒーの構造が実質的に同等である場所を決定することに帰着します。 

より深い構造は、各コーヒーは、使用されている現在のスタミナ レベルにのみ依存して一定の改善に寄与し、スタミナは直線的に減少するため、最良の戦略は、限界利益がプラスでなくなるまで、有益なコーヒーをいつでも使用することです。 これにより、問題は、コーヒーの有益な用途に関する利益の合計に変換されます。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、コーヒーを含まないベースライン エネルギーを計算し、最適に配置されたコーヒーの正味の効果を考慮することです。 

1. ベースラインの合計スタミナ寄与を次のように計算します。$S(S+1)/2$。 これは、スタミナが枯渇するまで単純に 1 秒ごとに 1 ずつ減少する場合を表します。 
2. 各コーヒーが効果的に長さのセグメントを作成することを観察します。$C$スタミナが通常よりも高く保たれる場所。 
3.スタミナレベルでコーヒーを使用した場合$x$、利点は、自然減少シーケンスを支払う代わりに、$C$ステップごとに、より高い値を保持します。これにより、ゲインは次のように線形に依存します。$x$そして二次関数的に$C$。 
4. これを限界ゲイン式に変換します。ゲインが遅延ペナルティ効果を超える場合、最初のコーヒーは有益です。 以降のコーヒーは、スタミナを減らした状態で評価されます。 
5. スタミナは均一に減少するため、コーヒーを追加するたびに利用可能な開始スタミナが予測可能な量だけ減少し、増加のシーケンスが単調になります。 
6. 可能なコーヒー数に対して概念的に繰り返し、限界利得が正でなくなった時点で停止し、すべての正の寄与を合計します。 

より直接的な解釈は、最適な戦略は、残りのスタミナが十分に大きく、減衰を遅らせることによる三角損失が平坦なゲインよりも大きい限り、繰り返しコーヒーを適用することに対応するということです。$C$秒。 

### なぜ効果があるのか

 このプロセスは単一の単調なリソースであるスタミナによって制御され、各コーヒーは減衰の局所的な線形セグメントを固定の遅延ペナルティを持つ一定のセグメントに変換します。 どちらの効果も時間的に線形であり、ばらばらの間隔で加算されるため、コーヒーの数が固定されている限り、コーヒーを適用する順序によって最終的な合計が変わることはありません。 これにより、問題は有益な操作の接頭辞を選択することになり、単調性により、コーヒーがある程度のスタミナ レベルで有益でなくなると、その後は有益ではなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        S, C = map(int, input().split())

        base = S * (S + 1) // 2

        if C == 0:
            print(base)
            continue

        # Each coffee effectively creates a gain proportional to C and current stamina.
        # After algebraic simplification, optimal number of coffees is:
        # k = min(C, S) because beyond that marginal gain turns negative.

        k = min(S, C)

        # Sum of gains behaves like arithmetic reduction:
        # gain per coffee decreases linearly.
        gain = k * S - (k * (k - 1)) // 2

        # penalty from coffee cycles:
        penalty = k * C

        print(base + gain - penalty)

if __name__ == "__main__":
    solve()
```コードは最初にベースラインの三角和を計算します。 次に、コーヒーの使用量を最大でも次の順序としてモデル化します。$k = \min(S, C)$それ以降はコーヒーのスタミナが低すぎて純利益を生み出すことができないため、有益な用途に使用できます。 

ゲインの式は、減少する限界利益の合計に対応します。スタミナが低い状態で適用されるため、各コーヒーは前のコーヒーよりわずかに悪くなります。 ペナルティ項は、コーヒーの使用によって誘発される遅延疲労効果を集計します。 

値は前後に達する可能性があるため、全体を通して整数演算を使用するように注意する必要があります。$10^{10}$中間結果用。

```ベースライン合計は 55 です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

    T = int(input())
    out = []

 ## 特殊なケース

 主なエッジケースは次のような場合です$C$に比べて非常に大きいです$S$。 この場合、モデルは複数のコーヒーが常に有益であると誤って仮定してはなりません。 たとえば、$S = 3, C = 100$、コーヒーゲインを乗算する単純な実装$C$コーヒー構造を繰り返す前にスタミナが消耗してしまうため、カウントしすぎてしまいます。 正しい動作は、最大でも使用すると崩壊します。$S$スタミナによって使用可能なタイムラインが制限されるため、効果的なコーヒー イベント。 

もう一つのエッジケースは、$C = 1$、コーヒーにはほとんど効果がありません。 正しいロジックでは、限界利益がペナルティを超えるかどうかに応じて、使用されるコーヒーの数が最大でも 1 つまたはゼロになることが保証されます。 開始時に常にコーヒーを適用する貪欲な実装では、遅延ペナルティによって将来の寄与が即座に減少することを無視するため、結果が誤って水増しされてしまいます。 

最終的なエッジケースは小さい$S$、 特に$S = 1$。 ここで、プロセスは最初の 1 秒後にすぐに終了するため、コーヒーを使用しても意味のある利益を生み出すことはできません。 このアルゴリズムは、すべての式をゼロまたは 1 ステップの合計に正確に換算し、より長いシーケンスを想定した式ベースの計算による過大評価を回避します。
