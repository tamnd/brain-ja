 ## 解決策
 ## 問題の理解

 私たちは 2D 平面で作業していますが、通常、移動は連続的であり、ユークリッド距離に比例して時間がかかります。 平面には、境界線は許可されていますが、立ち入ることができない長方形の禁止ゾーンが含まれています。 通常の歩行に加えて、ブラストコーンと呼ばれる特別なテレポートのようなオブジェクトがあります。 ブラスト コーンの上に立つと、それを破壊し、半径円内の任意の点に即座に「ジャンプ」できます。$R$ただし、その目的点が長方形の内側にない場合に限ります。 このジャンプは瞬時に行われ、時間を消費しません。 

このタスクは、広場での自由歩行とブラスト コーンからの瞬間的なジャンプを組み合わせて、開始点から目標点まで移動するのに必要な最小時間を計算することです。 主な難点は、飛行機が連続していることですが、移動ショートカットには、接続性が視界、障害物、ジャンプの到達可能性に依存するグラフのような構造が導入されていることです。 

個別の特殊オブジェクトに関しては制約は小さく、最大でも 40 個の長方形と 40 個のブラスト コーンです。 ただし、座標は次のような大きさにすることができます。$10^6$したがって、ジオメトリは浮動小数点または正確な距離計算で処理する必要があります。 状態空間は無限であるため、連続的な最短経路を直接シミュレートしようとする素朴なアプローチは不可能です。 

重要な微妙なエッジケースは、長方形とジャンプの間の相互作用から生じます。 たとえ2点が距離内にあったとしても$R$、ジャンプは、目的地が厳密にすべての長方形の外側にある場合にのみ有効です。 たとえば、ブラスト コーンが長方形で囲まれた通路内にあり、その半径内のほとんどの点が無効なジャンプ ターゲットになる可能性があります。 もう 1 つのエッジ ケースは、長方形の境界に沿って歩くことが許可されることです。これは、最短のパスが障害物の境界を迂回するのではなく、障害物の境界に接触する可能性があることを意味します。 

## アプローチ

 ブラスト コーンを無視すると、問題は長方形の障害物がある平面内の最短経路に帰着します。これはすでに古典的な可視性グラフの問題です。 強引なアイデアは、すべての関心点をノードとして扱い、それらの間の直線セグメントが長方形の内部を通過しない場合にノードのペアを接続することです。 この可視性グラフに対してダイクストラを実行すると、正しい答えが得られます。 

ただし、ブラスト コーンが導入されると、このアプローチはさらに複雑になります。 各ブラスト コーンでは、円内の無限の多くのポイントへのテレポートが可能です。つまり、到達可能なすべての目的地へのエッジを直接列挙することはできません。 ジャンプ ターゲットを単純に離散化すると、グラフ サイズが爆発的に大きくなります。 

重要な観察は、平面内の任意の点を考慮する必要がまったくないということです。 最適なパスは、開始点、ターゲット、ブラスト コーンの位置、長方形の角などの有限の重要点でのみ回転します。 歩行の場合、多角形の障害物環境における最短経路は、障害物の頂点でのみ曲がることが知られています。 ジャンプの場合、目的地は連続的ですが、領域内に到達する最短パスはコストを増加させることなく境界に到達するまで継続的にシフトできるため、意味のある候補はやはり同じ幾何学的な「コーナー」構造だけです。 

したがって、スタート、ターゲット、ブラスト コーン、および四角形のコーナーをノードとするグラフを構築します。 次に 2 種類のエッジを追加します。 最初のタイプはウォーキング エッジです。セグメントがどの四角形の内部とも交差しない場合、任意のノードのペアの間に直接ユークリッド エッジを作成します。 2 番目のタイプはジャンプ エッジです。各ブラスト コーンから、距離内の任意のノードに接続できます。$R$これも (すべての長方形の外側で) 有効であり、コストはゼロです。 

このグラフが構築されると、問題はダイクストラのアルゴリズムを使用して開始点からターゲットまでの最短経路の計算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース連続モデリング | 不可能 | 無限 | 実現不可能 |
 | 可視性グラフ + ジャンプ エッジ |$O(N^2 \cdot K)$|$O(N^2)$| 承認済み |

 ここ$N \le 80 + 160 = 240$おおよそのノード数、および$K \le 40$セグメントチェック用の長方形。 

## アルゴリズムのチュートリアル

 まず、すべての候補ノードを抽出します。 これらには、開始点、目標点、すべてのブラスト コーン、およびすべての長方形の角が含まれます。 これらの点は、最適なパスが方向を変える可能性がある、またはジャンプが意味のある着地をする可能性がある唯一のセットを形成します。 

次に、点が厳密に長方形の内側にあるかどうかを判断する関数を事前計算します。 ポイントがすべての長方形の外側にある場合にのみ、移動とテレポートの両方が許可されるため、これは重要です。 境界点が許可されるため、厳密な不等式が使用されます。 

次に、歩行のためにすべてのノードのペアの間にエッジを構築します。 各ペアについて、直線セグメントが長方形の内部と交差するかどうかを確認します。 そうでない場合は、2 点間のユークリッド距離に等しいエッジの重みを割り当てます。 これにより、障害物の角の可視性グラフが生成されます。 

その後、Blast Cone トランジションを処理します。 各 Blast Cone ノードについて、他のすべてのノードを調べます。 ノードがすべての長方形の外側にあり、ユークリッド距離以内にある場合$R$では、Blast Cone からそのノードに重み 0 の有向エッジを追加します。 これは瞬間的なテレポートをモデル化します。 

次に、開始ノードから開始してダイクストラのアルゴリズムを実行します。エッジの重みはユークリッド距離またはゼロコスト ジャンプのいずれかです。 最終的な答えは、ターゲット ノードまでの最短距離です。 

### なぜ効果があるのか

 多角形の障害物環境内の最適なパスは、すべてのターンが障害物の頂点または端点で発生するように変換できます。 これは、自由空間でパスが曲がる場合、障害物の境界にぶつからない限り、コストを増加させることなく直線化できるためです。この場合、曲がりは頂点で発生する必要があります。 ジャンプの場合、制約に違反したりコスト構造を増加させたりすることなく、連続した自由領域内の任意の目的地を境界点に到達するまでスライドさせることができるため、テレポートのエンドポイントを同じ有限セットに制限することで最適性が維持されます。 したがって、構築されたグラフには、最適なパスに必要なすべての候補遷移が含まれます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def inside_rect(px, py, rect):
    x1, y1, x2, y2 = rect
    return x1 < px < x2 and y1 < py < y2

def segment_intersects_rect(p1, p2, rect):
    # Liang-Barsky style clipping test simplified:
    # If both points are on same side outside, quick reject
    x1, y1 = p1
    x2, y2 = p2
    rx1, ry1, rx2, ry2 = rect

    # If both points are outside on one side, no intersection
    if (x1 <= rx1 and x2 <= rx1) or (x1 >= rx2 and x2 >= rx2) or \
       (y1 <= ry1 and y2 <= ry1) or (y1 >= ry2 and y2 >= ry2):
        return False

    # Check if segment passes through interior by sampling intersection logic
    # We check midpoint + endpoints is insufficient; do proper param test
    dx = x2 - x1
    dy = y2 - y1

    t0, t1 = 0.0, 1.0

    for p, q in [(-dx, x1 - rx1),
                 ( dx, rx2 - x1),
                 (-dy, y1 - ry1),
                 ( dy, ry2 - y1)]:
        if p == 0:
            if q < 0:
                return False
            continue
        r = q / p
        if p < 0:
            t0 = max(t0, r)
        else:
            t1 = min(t1, r)
        if t0 > t1:
            return False

    # If there is overlap, segment intersects rectangle region
    # but touching borders is allowed; interior intersection counts
    return True

def valid_point(x, y, rects):
    for r in rects:
        if inside_rect(x, y, r):
            return False
    return True

def dist(a, b):
    return ((a[0]-b[0])**2 + (a[1]-b[1])**2) ** 0.5

n, m, R = map(int, input().split())

rects = []
nodes = []

for _ in range(n):
    x1, y1, x2, y2 = map(int, input().split())
    rects.append((x1, y1, x2, y2))
    nodes.append((x1, y1))
    nodes.append((x1, y2))
    nodes.append((x2, y1))
    nodes.append((x2, y2))

cones = []
for _ in range(m):
    x, y = map(int, input().split())
    cones.append((x, y))
    nodes.append((x, y))

xs, ys, xt, yt = map(int, input().split())
start = (xs, ys)
target = (xt, yt)

nodes.append(start)
nodes.append(target)

N = len(nodes)

adj = [[] for _ in range(N)]

def ok_segment(i, j):
    a, b = nodes[i], nodes[j]
    for r in rects:
        if segment_intersects_rect(a, b, r):
            return False
    return True

for i in range(N):
    for j in range(i+1, N):
        if ok_segment(i, j):
            d = dist(nodes[i], nodes[j])
            adj[i].append((j, d))
            adj[j].append((i, d))

R2 = R * R

for i in range(N):
    if nodes[i] in cones:
        for j in range(N):
            if valid_point(nodes[j][0], nodes[j][1], rects):
                dx = nodes[i][0] - nodes[j][0]
                dy = nodes[i][1] - nodes[j][1]
                if dx*dx + dy*dy <= R2:
                    adj[i].append((j, 0.0))

def dijkstra(s, t):
    dista = [INF] * N
    dista[s] = 0.0
    pq = [(0.0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dista[u]:
            continue
        if u == t:
            return d
        for v, w in adj[u]:
            nd = d + w
            if nd < dista[v]:
                dista[v] = nd
                heapq.heappush(pq, (nd, v))
    return dista[t]

start_idx = nodes.index(start)
target_idx = nodes.index(target)

print(dijkstra(start_idx, target_idx))
```この実装では、すべての幾何学的イベント ポイントにわたる完全な可視性グラフが構築されます。 多角形の障害物環境における最短経路はそのような頂点でのみ曲がるため、長方形の角が含まれています。 

セグメントの有効性は、パラメトリック交差テストを使用して各四角形に対してチェックされます。 これにより、自由空間内に残るか、境界に接触するウォーキング エッジのみが許可されるようになります。 

Blast Cone エッジは、グラフの構築後に追加されます。 各コーンは半径内のすべてのノードに接続します$R$、宛先が四角形の内側にない場合に限ります。 瞬間移​​動を反映してコストはゼロです。 

ダイクストラのアルゴリズムが使用されるのは、グラフにユークリッド距離とゼロコストのエッジが混在した非負の重みがあるためです。

 ## 特殊なケース

 エッジ ケースの 1 つは、Blast Cone が長方形の境界上に正確に位置する場合です。 境界線が許可されているため、ノードは引き続き有効であり、テレポート エッジも引き続き使用できます。 このアルゴリズムは境界点を外側の四角形として扱うため、厳密な内側チェックによって除外されません。 

もう 1 つのエッジ ケースは、最短パスが長方形の角にかろうじて触れる場合です。 その場合、可視性グラフにはノードとしてコーナーが含まれるため、パスはそこで合法的に曲がることができます。 セグメント チェックでは、境界に接するエッジが許可され、正確さが保証されます。 

3 番目のケースは、最適なパスがテレポートを使用しているが、別のブラスト コーンに正確に着地する場合です。 コーンもノードであるため、これは自然に処理され、ダイクストラは制限なくゼロコストのエッジを連鎖させ、正しいマルチホップ テレポート シーケンスを生成します。
