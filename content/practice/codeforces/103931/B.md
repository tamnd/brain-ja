 ## 解決策
 ## 問題の理解

 長さの隠し文字列が与えられます$n$, ここで、すべての文字は左括弧または右括弧のいずれかです。 文字列を直接見ることはできませんが、一連の間隔制約が与えられています。 各制約は部分文字列を指定します$[l, r]$そして、「その部分文字列に '(' が ') よりもいくつ多く現れるか」の値を教えてくれます。 

同様に、値を割り当てると、$+1$「(」と$-1$')' にすると、各クエリはこの未知の配列のセグメントの合計を返します。 タスクは、これらすべての合計と一致する有効なブラケット シーケンスを再構築すると同時に、最終シーケンスが正しいバランスの取れたブラケット シーケンスであることを確認することです。 制約が互いに矛盾する場合、または有効な括弧シーケンスに対応できない場合は、失敗を出力する必要があります。 

非表示の文字列は有効であるように制約されます。つまり、プレフィックスの残高がマイナスになることはなく、合計はゼロになります。 それは恣意を超えた構造を追加します$\pm 1$割り当て: 私たちは単に線形システムを解決しているのではなく、プレフィックスの実現可能性を備えた制約付きシステムを解決しています。 

制約は次のとおりです$n = 3000$、だからどれでも$O(n^3)$推論はまだギリギリ許容範囲かもしれませんが、それ以上のものは遅すぎます。 さらに重要なことは、問題の構造は、多くの区間合計の一貫性を維持する必要があることを示唆しており、これは自然に、総当り文字列ではなくプレフィックス合計と差分制約に変換されます。 

微妙な失敗のケースは、クエリがローカルでは一致するが、有効なブラケット シーケンスとグローバルでは矛盾する場合に発生します。 たとえば、早い段階でプレフィックスを正にしすぎると、後でバランスを負でないままに括弧を閉じることができなくなる可能性があります。 もう 1 つの失敗例は、次のような重複する間隔の合計が矛盾していることです。 

入力:```
2 2
1 1 1
1 2 0
```最初のクエリは強制的に$s_1 = +1$、位置 1 の「(」を意味します。2 番目の力$s_1 + s_2 = 0$、 それで$s_2 = -1$、ローカルで一貫しています。 しかし、代わりに次のようなことがあったとしたら:```
2 2
1 1 1
1 2 2
```有効な括弧文字列では長さ 2 の部分文字列が合計 2 を持つことができないため、これは不可能です。 このような矛盾を検出する必要があります。 

主要な問題は、プレフィックスの合計に対する線形制約を満たさなければならず、また、プレフィックスの合計が有効なブラケット パスのように動作することを強制する必要があることです。 

## アプローチ

 妥当性制約を無視すると、問題は値の割り当てに帰着します。$a[i] \in \{+1, -1\}$各クエリに対して$[l, r]$、プレフィックスの合計は次の条件を満たします。$$p[r] - p[l-1] = c$$どこ$p[i]$プレフィックスの合計は次のとおりです$a$。 

これは整数に関する一次方程式系です。 強引なアイデアは、すべてを試すことです$2^n$シーケンスを括弧で囲んですべてのクエリをチェックしますが、これは小規模なクエリであっても完全に実行不可能です$n$。 

より構造化されたブルート フォースでは、これをバックトラッキング問題として扱います。つまり、各位置に括弧を割り当て、すべてのクエリの合計を増分的に維持します。 各割り当ては最大に影響します$O(n)$クエリがあり、$2^n$課題があり、これが再び爆発します。 

重要な観察は、すべての制約がプレフィックス合計において線形であるということです。 個々の文字について推論する代わりに、接頭辞の値について推論します。$p[i]$。 すべてのクエリは差分制約になります。$$p[r] - p[l-1] = c$$これは、差分またはグラフ制約システムを使用した古典的な和集合検索です。 各プレフィックス インデックスをノードとして解釈し、各クエリを固定差分を強制するエッジとして解釈できます。 これにより、すべてのプレフィックスに一貫した値を割り当てたり、矛盾を検出したりすることができます。 

プレフィックスの合計がグローバル シフトまで決定された後は、シーケンスが有効なブラケット シーケンスに対応していることを確認する必要があります。 以来$a[i] = p[i] - p[i-1]$、各値は強制されるため、実現可能性はすべての値をチェックすることになります。$a[i]$いる$\{\pm 1\}$そして、接頭辞の合計が負になることはなく、ゼロで終わることはありません。 コンポーネントが切断されているために複数の有効な割り当てが存在する場合は、有効性を強制するルート正規化を選択できます。 

完全な解決策は次のようになります。プレフィックス合計に関する制約のグラフを構築し、ポテンシャルまたは BFS を使用して DSU を使用して一貫して値を割り当て、矛盾を検出し、文字を導き出し、最後に括弧の有効性を検証します。

 ## アルゴリズムのチュートリアル

 プレフィックスの合計を未知の変数として扱います$p[0], p[1], \dots, p[n]$、 と$p[0] = 0$。 

### ステップ 1: プレフィックス ノード間の制約を構築する

 あらゆるクエリに対して$(l, r, c)$、次のようにエンコードします。$$p[r] = p[l-1] + c$$これはノード間の重み付きエッジになります$l-1$そして$r$。 

これにより、部分文字列制約がグラフの一貫性の問題に変換されます。 

### ステップ 2: プレフィックス インデックスに対して重み付けされた DSU を維持する

 各ノードがその親とその親との重みの差を格納する Union-find 構造を使用します。 重みが表すのは、$p[x] - p[parent[x]]$。 2 つのノードをマージする場合、それらのルート間に必要な差異が強制されます。 

制約を処理するときに、2 つのノードがすでに接続されている場合は、暗黙的な差分が指定されたものと一致するかどうかを確認します。$c$。 そうでない場合は、システムに一貫性がありません。 

この手順により、すべてのプレフィックス合計が接続コンポーネントに至るまで一意に定義されるようになります。 

### ステップ 3: 実際のプレフィックス値を割り当てる

 すべての制約を処理した後、各連結成分は相対値を持ちますが、任意の絶対シフトを持ちます。 コンポーネントごとに 1 つの代表を固定し、それに値 0 を割り当て、DSU 関係を通じて値を伝播します。 

これにより、完全なプレフィックス合計配列が得られます。$p[i]$。 

### ステップ 4: 括弧文字を回復する

 ポジションごとに$i$、次を計算します。$$a[i] = p[i] - p[i-1]$$すべてのことを検証します$a[i]$+1 または -1 のいずれかです。 他の値が表示された場合、システムは無効です。 

+1 を '(' に、-1 を ')' にマッピングします。 

### ステップ 5: 括弧の順序を検証する

 構築されたシーケンスのプレフィックスバランスをシミュレートします。 私たちは次のことを保証します:$$p[i] \ge 0 \quad \forall i \in [1, n], \quad p[n] = 0$$違反した場合は失敗を出力します。 

### なぜ効果があるのか

 差分のある DSU は、すべての制約がプレフィックスの差に関する線形方程式であるため、すべての間隔合計制約の正確な一貫性を強制します。 有効なブラケット シーケンスはすべてのエッジを満たす一意のプレフィックス合計割り当てを誘導するため、DSU は実行可能なソリューションを除外しません。 逆に、DSU で検出された矛盾は、不可能な一次方程式系を意味するため、割り当ては存在しません。 

再構成後、差異を文字に変換し直すことが強制されるため、妥当性は、結果として得られるウォークが Dyck パスであるかどうかを確認することになります。 そうでない場合、一貫した割り当てはクエリと括弧の有効性の両方を同時に満たすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.diff = [0] * n  # value[x] - value[parent[x]]

    def find(self, x):
        if self.parent[x] == x:
            return x
        px = self.parent[x]
        root = self.find(px)
        self.diff[x] += self.diff[px]
        self.parent[x] = root
        return root

    def get(self, x):
        self.find(x)
        return self.diff[x]

    def union(self, x, y, w):
        rx = self.find(x)
        ry = self.find(y)
        if rx == ry:
            return self.get(x) - self.get(y) == w

        # attach rx under ry
        vx = self.get(x)
        vy = self.get(y)
        self.parent[rx] = ry
        self.diff[rx] = vy + w - vx
        return True

def solve():
    n, q = map(int, input().split())
    dsu = DSU(n + 1)

    for _ in range(q):
        l, r, c = map(int, input().split())
        if not dsu.union(l - 1, r, c):
            print("?")
            return

    val = [0] * (n + 1)

    for i in range(n + 1):
        dsu.find(i)

    for i in range(n + 1):
        val[i] = dsu.diff[i]

    # validate and build brackets
    res = []
    for i in range(1, n + 1):
        d = val[i] - val[i - 1]
        if d == 1:
            res.append('(')
        elif d == -1:
            res.append(')')
        else:
            print("?")
            return

    bal = 0
    for ch in res:
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        if bal < 0:
            print("?")
            return

    if bal != 0:
        print("?")
        return

    print("! " + "".join(res))

if __name__ == "__main__":
    solve()
```DSU 構造は、プレフィックス合計の差を圧縮形式で保持します。 結合演算は正確な方程式を満たすことを強制し、検索演算はプレフィックスの差を蓄積しながらパス圧縮を実行します。 

制約が解決された後、DSU デルタから絶対プレフィックス値を抽出します。 重要な点は、DSU からの相対的な一貫性のみを使用することです。 すべてのノードはそのルートを基準にして表現されるため、絶対値は一貫して再構築されます。 

最後の変換ステップは決定的です。プレフィックスの合計が固定されると、各文字が強制されます。 ～からの逸脱$\pm 1$すぐに矛盾が証明されます。 

最終スキャンでは、プレフィックスがゼロを下回らないことが保証されます。これが、括弧シーケンスの有効性のために必要な唯一の構造条件です。

 ## 特殊なケース

 エッジ ケースの 1 つは、制約がすべてのプレフィックス ノードを完全に接続していない場合です。 例えば：```
4 1
1 2 0
```ノード 0 ～ 4 はコンポーネントに分割されます。 DSU は相対値を割り当て、欠落しているコンポーネントは任意にシフトされます。 キャラクターを形成する際には差異のみが重要となるため、このアルゴリズムは依然として機能します。 

もう 1 つの特殊なケースは、単一の共用体演算内の直接の矛盾です。```
3 2
1 1 1
1 1 2
```最初の設定では p1 = 1 が設定され、2 番目の設定では p1 = 2 が必要です。結合中に、DSU は同じルート上の矛盾した差異を検出し、失敗を返します。 

最後のエッジ ケースは、再構成後にブラケットが有効でないシーケンスを生成する有効な線形制約です。 たとえば、代数的に一貫性がある場合でも、制約によってプレフィックス ディップが負になる場合があります。 最後のプレフィックス スキャンでこれが検出されます。```
p = [0, 1, 0, -1]
```これはバランスがマイナスになるため 3 番目の位置で失敗し、出力は正しく拒否されます。
