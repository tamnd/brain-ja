 ## 解決策
 ## 問題の理解

 値から開始する決定性シーケンスジェネレーターが与えられています。$a$そして二次変換を繰り返し適用します$x \mapsto x^2 + b$。 各クエリは、そのような無限シーケンスを 1 つ定義します。 値は整数として非常に速く増加しますが、私たちが気にする条件は値の大きさに直接依存するのではなく、固定係数と比較したときにシーケンスの 2 つの要素が非常に具体的な最大公約数を生成できるかどうかに依存します。$P$。 

より正確には、シーケンスの場合$x_0, x_1, x_2, \dots$、インデックスが 2 つ存在するかどうかを尋ねられます。$u > v$その違いは$x_u - x_v$と交差したとき$P$gcd 経由で正確に生成されます$Q$。 以来$Q$分割する$P$、書き換えることができます$P = Q \cdot M$となり、条件は構造的に制限的になります。差異には要素が正確に含まれている必要があります。$Q$に関して$P$、それ以上でもそれ以下でもありません。 

主な問題点は、シーケンスが無限であり、値が非常に急速に増加するため、実際の整数を総当たり攻撃することが不可能であることです。 完全な整数値についての推論も不要です。 関連するものはすべて、算術モジュロ除数によってフィルタリングされます。$P$。 

制約があるため、これはさらにデリケートになります。 最大 200 のシーケンスがあり、各シーケンスの価値はわずか数ステップで爆発的に増加する可能性があります。 以来$P \le 2^{32}-1$、意味のある計算は、次から導出されたものを法として値を減算する必要があります。$P$そうしないと、時間とメモリの両方がすぐに爆発してしまいます。 構造のない完全な整数や多くのステップを保存する単純なシミュレーションは失敗します。 

微妙なエッジケースは、等価モジュロであるという事実から生じます。$P$それは私たちが望んでいることではありません。 2 つの値が一致するモジュロ$P$それらの差が次で割り切れることを保証するだけです$P$、強すぎます。 gcd を正確に取得するには差分が必要です$Q$と$P$、つまり、次のように割り切れる必要があります。$Q$、ただし、から追加の素因数は取得しません。$M = P/Q$。 この「で割り切れる」間の不一致は、$P$” と “gcd は等しい”$Q$」 ほとんどの素朴なアプローチが間違っているのはここです。 

## アプローチ

 直接的な試みは、各シーケンスをシミュレートし、すべてのペアをチェックすることです。$(u, v)$。 これは直ちに実行不可能です。たとえ以下のモジュラー演算に限定したとしても、$P$、シーケンスはまだ進化しています$x_{i+1} = x_i^2 + b \bmod P$、決定論的な有限状態マシンのように動作します。 と$P$まで$2^{32}$、状態空間は膨大であり、繰り返しを検出したり、すべてのペアをチェックするには、最大で$O(P)$最悪の場合、シーケンスごとの遷移の数は制限をはるかに超えています。 

重要な観察は、シーケンスがモジュロの下で完全に決定的であるということです。$P$、したがって最終的にサイクルに入ります。 サイクルに入ると、すべての値が同じサイクル構造内で無限に繰り返されます。 これは任意のペアを意味します$(u, v)$一時的なプレフィックス内にあるのか、サイクル自体内にあるのかを考慮しており、最初に繰り返された状態を超える必要はありません。 

ただし、等価モジュロ$P$は私たちの条件には厳しすぎるため、代わりに gcd 条件が実際に要求するものに焦点を当てます。 書き込み$P = Q \cdot M$、条件$\gcd(x_u - x_v, P) = Q$は、次の 2 つの同時要件に相当します。$x_u \equiv x_v \pmod Q$因数分解後$Q$、残りの商は互いに素でなければなりません$M$。 これは、モジュロ値の構造を意味します。$Q$とモジュロ$M$どちらも重要です。 

重要な単純化は、両方の係数にわたる残基の完全なペアを常に追跡する必要がないことです。 システムは単一の反復であるため、すべての状態がすでに両方の残基を同時にエンコードしています。 シーケンスがサイクルモジュロに達すると$P$、重要な違いはすべて、このサイクル内の違いです。 有効なペアは最終的にサイクル内で繰り返される必要があるため、サイクル内をチェックするだけで十分です。 

したがって、問題はシーケンスのモジュロのサイクルを検出することに帰着します。$P$次に、サイクル内に gcd 条件が正確に評価されるペアが少なくとも 1 つ存在するかどうかを確認します。$Q$。

 ## アルゴリズムのチュートリアル

 ### 最適なアイデア

 シーケンスモジュロをシミュレートします$P$、すべての gcd 条件は、の約数を法とする値にのみ依存するためです。$P$、そしてそれを超える価値観$P$は無関係です。 

値からインデックスへのハッシュ マップを使用して繰り返しを検出します。 繰り返される値を確認したら、サイクルを特定します。その値の最初の出現から現在の位置までのすべてがサイクルを形成します。 

そのサイクル内では、サイクル内のインデックスのペア (オプションでプレフィックスとサイクルの間もチェックする必要がありますが、サイクルにはすでにすべての繰り返し動作が含まれています) をチェックするだけで済みます。 各ペアについて、次のことをテストします。$\gcd(x_u - x_v, P) = Q$。 

### ステップ

 1. 問題を作業モジュロに還元する$P$。 シミュレーションします$x_{i+1} = x_i^2 + b \bmod P$。 これにより、値の境界が維持され、すべての gcd 関連の構造が保持されます。 
2. 繰り返される値が見つかるまでシーケンスを生成します。 各値が出現する最初の位置を保存します。 値を再検討した瞬間に、その最初の出現から始まるサイクルが特定されます。 
3. サイクルセグメントを抽出します。 これは、すべての無限の将来の値を生成する繰り返し構造です。 
4. サイクルセグメント内のすべてのインデックスのペアを確認します。 各ペアごとに$(u, v)$、計算する$d = x_u - x_v$そして評価する$\gcd(d, P)$。 
5. いずれかのペアが正確に一致する場合$Q$、出力$1$。 それ以外の場合は出力$0$。 

注意をサイクルに限定する理由は、すべての無限シーケンスが最終的に周期的になるため、どの目撃ペアも差を変更せずに周期部分にシフトできるためです。 

### なぜ効果があるのか

 シーケンスが値を繰り返すと、将来全体が同じサイクルの繰り返しになります。 無限に頻繁に現れる可能性のある差異は、このサイクル内ですでに現れている必要があります。 gcd 条件は差分のみに依存し、両方のインデックスをフル サイクル前方にシフトしても差分は変わらないため、有効なペアはサイクル自体内で表現できます。 これにより、サイクルは gcd 条件に関連するすべての可能な動作を完全に表すものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve_one(P, Q, a, b):
    seen = {}
    seq = []

    x = a % P
    i = 0

    while x not in seen:
        seen[x] = i
        seq.append(x)
        x = (x * x + b) % P
        i += 1

        # safety bound: since P <= 2^32, cycle must appear quickly in practice
        if i > 2 * (len(seen) + 5):
            break

    # extract cycle
    start = seen[x]
    cycle = seq[start:]

    # check all pairs in cycle
    n = len(cycle)
    for i in range(n):
        for j in range(i):
            if gcd(cycle[i] - cycle[j], P) == Q:
                return "1"
    return "0"

def main():
    P, Q, k = map(int, input().split())
    res = []
    for _ in range(k):
        a, b = map(int, input().split())
        res.append(solve_one(P, Q, a, b))
    print("".join(res))

if __name__ == "__main__":
    main()
```シミュレーションはモジュロで実行されます$P$、値が制限されたままであることを保証します。 辞書は最初の出現を追跡して最初の繰り返しを検出し、これがサイクルを定義します。 サイクルが抽出されたら、その中のペアをブルート チェックします。これは、無限のインデックスの選択では循環動作のみが重要であるためです。 gcd は次のものに対して直接計算されます。$P$、必要な条件に正確に一致します。 

微妙な実装の詳細は、完全な整数の増加に決して依存しないことです。$x_i$。 すべての演算は剰余化されます$P$これは必須です。そうしないと二乗計算がすぐに 64 ビットの制限を超えてしまうためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シーケンスがすぐに固定小数点モジュロに入る場合です。$P$。 この状況では、サイクル長は 1 であり、可能な唯一のペアは自明です。 サイクル抽出では単一要素リストが生成され、gcd 条件を満たすペアが存在しないため、アルゴリズムはこれを自然に処理し、条件が縮退した方法で満たされない限り 0 を正しく返します。 

もう 1 つのエッジケースは次のような場合です$Q = P$。 次に、次のことを要求します$\gcd(x_u - x_v, P) = P$、強制的に$x_u \equiv x_v \pmod P$。 アルゴリズムがこれを正しく検出できるのは、サイクルに同一の値が繰り返されている場合のみです。その場合にのみ差が次の式で割り切れるためです。$P$。 

3 番目のエッジケースは次の場合に発生します。$P$プライムです。 その場合、gcd 条件は、差が次の条件で割り切れるかどうかを確認することになります。$P$、約数は 1 と 2 だけなので、$P$。 アルゴリズムは正しく縮退します。モジュロを除いて同一の値のみです。$P$条件を満たすことができるため、繰り返された状態のみが問題となり、これがまさにサイクル検出で捕捉されるものです。
