 ## 解決策
 ## 問題の理解

 それぞれ先行ゼロのない単純な 10 進数形式で書かれた 2 つの正の整数が与えられ、物語からインスピレーションを得た意図的に奇妙なルールを使用してそれらを比較する必要があります。 ユーモラスな「Koji 比較」にもかかわらず、実際のタスクは、最初の数値が 2 番目の数値より小さいか、等しいか、または大きいかを判断し、対応する関係を正確な形式で出力することになります。`a>b`、`a<b`、 または`a=b`。 

重要な詳細は、整数が非常に大きくなる可能性があるということです。$2 \cdot 10^{10}$そのため、一部の言語では標準の固定幅整数型に安全に適合しない可能性があります。 Python では、これはそれほど問題ではありませんが、制約の意図は、厳密な言語での単純な整数解析の仮定に依存するのではなく、それらを文字列として扱うか、任意精度のロジックを使用する必要があることは明らかです。 

単純ですがよくある間違いは、両方の入力を整数に変換して直接比較することです。 これは Python では正しいですが、他の環境ではオーバーフローの危険があります。 もう 1 つの微妙な落とし穴は、長さの違いを適切に処理せずに文字列として辞書編集的に比較しようとすることです。 例えば、`"9"`そして`"10"`: 辞書順に`"9" > "10"`は誤りです。なぜなら`'9' < '1'`間違って比較した場合にのみ false になります。 しかし、実際には文字列の比較は辞書順で行われるため、`"9" > "10"`次のように誤って評価されます`True`いくつかの単純な実装では、`'9' > '1'`。 正しい順序付けでは、最初に数値の長さを考慮する必要があります。 

ここで重要となるエッジ ケースには、1 桁の数値と複数桁の数値、等しい文字列、最初の桁がすぐに異なる数値とプレフィックスを共有するケースが含まれます。 

## アプローチ

 ブルート フォースのアプローチは簡単です。両方の入力を整数として解析し、直接比較します。 Python では、これは解析後の比較にかかる時間は事実上一定ですが、解析自体は桁数が線形です。 この問題では各数値は最大約 11 桁であるため、これは簡単で安全です。 より厳密な言語コンテキストでは、境界が小さいため、このアプローチはまだ許容される可能性がありますが、概念的な問題は、組み込みの大きな整数のサポートに依存していることです。 

どの言語でも機能する、より普遍的なアプローチは、数値を文字列として扱い、それらを数値文字列として比較することです。 重要な観察は、整数の比較が 2 つのルールに削減できるということです。 まず、長さが異なる場合、10 進数の桁数が多いため、長い数値の方が大きくなります。 次に、長さが等しい場合は、両方の文字列が整列された数字シーケンスを表すため、標準の辞書編集的比較が機能します。 

実際の整数値を暗黙的にシミュレートするため、ブルートフォースメンタルモデルが機能します。 ASCII での桁の順序付けは、さまざまな長さにわたる数値の大きさに合わせて調整されていないため、長さの正規化を行わずに生の辞書編集的な比較に依存する場合、概念的には失敗します。 桁の長さが大きさを決定するという観察により、完全な数値解析の必要性がなくなり、直接の比較規則が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (整数解析) | O(d) | O(d) | 承認済み |
 | 文字列の長さ + 辞書編集上の比較 | O(d) | O(1) おまけ | 承認済み |

 ここ$d$大きい方の数値の桁数です。 

## アルゴリズムのチュートリアル

 1. 2 つの入力文字列を読み取ります。`a`そして`b`。 それらの数値構造はその大きさを直接エンコードするため、それらを文字列として保持します。 
2. 長さを比較します。`a`そして`b`。 もし`len(a) > len(b)`、すぐに結論を出します`a > b`。 これが機能するのは、桁数が多い数値は必ず 10 進数で大きくなるからです。 
3. もし`len(a) < len(b)`、すぐに結論を出します`a < b`同じ理由で。 
4. 長さが等しい場合は比較します。`a`そして`b`左から右に一文字ずつ。 それらが異なる最初の位置によって順序が決まります。その位置にある大きい桁の文字列が、大きい数値に対応します。 
5. 異なる位置が存在しない場合、数値は同一であり、等しいことを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、10 進表現が位置指定であるという事実に基づいています。 最小の k 桁の数値は$10^{k-1}$、これは最大のものよりも厳密に大きくなります。$(k-1)$-桁の数字$10^{k-1}-1$。 桁数が一致する場合、両方の数値が同じ位置の重みを共有するため、各接頭辞の比較では数値の順序が維持されます。 最初の異なる桁によって、最も高い異なる位の値でどの数値がより大きな寄与を持つかが決まり、それ以降のすべての桁はその差を補うことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b = input().split()

if len(a) > len(b):
    print(f"{a}>{b}")
elif len(a) < len(b):
    print(f"{a}<{b}")
else:
    if a > b:
        print(f"{a}>{b}")
    elif a < b:
        print(f"{a}<{b}")
    else:
        print(f"{a}={b}")
```このソリューションでは、比較が 2 つの論理的に異なる段階に分割されます。最初に長さの比較が行われ、次に必要な場合にのみ辞書編集的な比較が行われます。 フォーマット要件は f 文字列を介して直接処理され、正確な出力構造が維持されます。 

実装の微妙な点は、文字列を整数に変換しないことです。 これにより、どの言語でもソリューションが安全に保たれ、不必要なオーバーヘッドが回避されます。 辞書編集的な比較は、等しい長さがすでに保証されているためにのみ有効です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a, b = input().split()

    if len(a) > len(b):
        return f"{a}>{b}"
    elif len(a) < len(b):
        return f"{a}<{b}"
    else:
        if a > b:
            return f"{a}>{b}"
        elif a < b:
            return f"{a}<{b}"
        else:
            return f"{a}={b}"

# provided samples
assert run("9 10") == "9<10"
assert run("114514 1919") == "114514>1919"
assert run("9 999") == "9<999"
assert run("99 99") == "99=99"

# custom cases
assert run("1 2") == "1<2", "single digit increasing"
assert run("10 2") == "10>2", "different digit lengths reversal"
assert run("123 123") == "123=123", "exact equality"
assert run("1000 999") == "1000>999", "power of ten boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 | 1<2 | 最小一桁の比較 |
 | 10 2 | 10>2 | 辞書編集上の直観よりも長さの優位性 |
 | 123 123 | 123=123 | 等価性の処理 |
 | 1000 999 | 1000>999 | 桁の長さの境界 |

 ## 特殊なケース

 主なエッジケースは、次のように、数値が桁数だけが異なる場合です。`10`対`9`。 このアルゴリズムは、長さの比較によってこれを即座に処理し、誤った辞書編集上の推論を回避します。 

別のケースは、次のような同一の数字です。`999`そして`999`、長さの比較でも辞書編集上の比較でも違いは見つかりません。 アルゴリズムは正しく等価に達します。 

最後に、次のようにプレフィックスは一致するが長さが異なる場合`100`そして`99`、桁検査の前に長さの比較が優先されるため、正しく解決されます。
