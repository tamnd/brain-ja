 ## 解決策
 ## 問題の理解

 グラフを構築するランダムなプロセスをシミュレートしています。$n$ラベル付きの頂点。 グラフは空から始まります。 各反復で、2 つの頂点を個別に選択します。$u$そして$v$から一律に$1$に$n$、許可します$u=v$。 エッジを追加する場合$(u,v)$構造を有効に保つため、それを挿入します。 それ以外の場合は、その試みは破棄されます。 有効なエッジを追加できなくなると、プロセスはすぐに停止します。 

有効性は、現在のエッジ セットの構造的制約によって純粋に定義されます。 重複するエッジのない単純なグラフを構築しており、各頂点の次数は最大 2 まで許可されています。したがって、進化する構造は常にパスとサイクルの素結合になります。 

出力は、プロセスが停止するまでの予想される反復回数です。反復とは、ペアの 1 つのランダムなサンプリングです。$(u,v)$、それが受け入れられるかどうかに関係なく。 

制約$n \le 200$状態空間は、ラベル付きグラフの完全な列挙を必要とするような指数関数的ではないことを示唆しています。 その代わりに重要なのは、有効なグラフの構造が高度に制限されていることです。コンポーネントはパスとサイクルだけであり、各頂点の次数は 0、1、または 2 です。これは、小さな状態または組み合わせマルコフ プロセスに対する DP を強く示唆しています。 

微妙なエッジケースは、$n=1$。 エッジは 2 つの異なる頂点を接続する必要があるため、有効なエッジは存在しません。そのため、プロセスは期待値 0 ですぐに終了します。もう 1 つは、$n=2$、1 つのエッジのみが可能ですが、次のような無効な描画が可能です。$(1,1)$、$(2,2)$、または重複したサンプリングにより、予想時間が大幅に延長されます。 

プロセスを直接シミュレートする単純なアプローチは、予想される反復回数が急速に増加するため失敗します。$n$、ランダム性があるため、収束するには多くのサンプルが必要です。 さらに悪いことに、1 秒の制限では、モンテカルロによって正確な期待値を計算することさえ不可能です。 

## アプローチ

 この強引なアイデアは、確率過程を段階的にシミュレートすることです。 各州でランダムに選択します$(u,v)$、有効性をチェックし、グラフを更新し、終了するまで続行します。 これは確率論的な意味では正しいですが、近似値しか得られません。 正確な期待値を取得するには、考えられるすべてのラベル付きグラフ構成をマルコフ連鎖内の状態として扱い、各状態が到達可能なすべての状態に依存する一連の線形方程式を解く必要があります。 

難しいのは状態の数です。 次数を最大 2 に制限しても、ラベル付きグラフの数は依然として膨大です。 遷移はグローバル構造に依存し、状態空間は超指数関数的に増大するため、グラフ上の直接 DP は実行不可能です。$n$。 

重要な観察は、このプロセスではコンポーネントの正確な形状が度を越えて気にされていないことです。 各頂点は、現在の次数 (0、1、または 2) によってのみ分類されます。構造は常にパスとサイクルの集合であり、内部頂点にこれ以上入射エッジを追加できないという意味で、サイクルはすでに「閉じられ」ています。 グローバルに重要なのは、各次数クラスに頂点がいくつあるか、および開いた端 (次数 1 頂点) がいくつ残っているかだけです。 

これにより、システムは集約された状態の小さなセットに縮小されます。 各トランジションはペアの選択に対応します$(u,v)$いくつかのカテゴリのいずれかに該当します: 2 つの次数 0 の頂点の接続、次数 0 と次数 1 の頂点の接続、2 つの次数 1 頂点の接続 (パスを閉じてサイクルにする)、または無効な試行。 期待時間は、これらの集約された状態に関する線形方程式を介して解くことができます。 

これにより、問題は多項式の状態数にわたるマルコフ期待値 DP に変わります。ここで、各状態は次数 0、次数 1、および次数 2 の頂点の数によって定義されます。

 ## アルゴリズムのチュートリアル

 状態を 3 つの整数で定義します。$a$、$b$、 そして$c$、それぞれ次数 0、1、2 の頂点の数を表します。$a + b + c = n$。 当初は、$(a,b,c) = (n,0,0)$。 有効なエッジが存在しない場合、プロセスは停止します。これは次の場合に発生します。$a + b \le 1$そして$b = 0$これは、別個の頂点のペアが有効な新しいエッジを形成できないことを意味します。 

私たちは計算します$E(a,b,c)$、特定の状態から終了するまでの予想される反復回数。 

1. 特定の状態について、可能な順序ペアの総数を計算します。$(u,v)$、つまり$n^2$。 各反復では均一に 1 つが選択されます。 
2. すべてのペアを次数に基づいてカテゴリに分割します。$u$そして$v$。 両方のエンドポイントの次数が 2 未満であり、区別できるペアのみがグラフを増加させる可能性があります。 他のすべては自己ループまたは無効な移動であり、状態は変更されませんが、1 回の反復を消費します。 
3. 有効な遷移タイプごとに、それを生成するペアの数を数えることにより、その確率を計算します。 たとえば、次数 0 の頂点を 2 つ選択すると、次数 1 の頂点の数が 2 つ増加します。 
4. 期待値の繰り返しを書きます。$$E(s) = 1 + \sum_{s'} P(s \to s') E(s')$$ここで、「+1」は現在の反復を表します。 
5. 線形システムに再配置します。$$E(s) - \sum_{s'} P(s \to s') E(s') = 1$$6. 再帰を伴うメモ化を使用してこのシステムを解きます。これは、遷移は常に、次数 0 の頂点が少ないか、より制約された構造を持つ状態に向かって移動し、状態遷移の非循環性が保証されるためです。 
7. 戻る$E(n,0,0)$。 

重要な不変条件は、すべての遷移が期待される「利用可能な新しいエッジ」の数を厳密に減らすということです。 次数 2 の頂点は吸収性があり、一度形成されるとそれ以上の成長に寄与することはありません。 したがって、状態空間は、使用可能なエンドポイントの数による調整の下で DAG を形成し、DP の終了を可能にします。 

## なぜ機能するのか

 このアルゴリズムは、遷移の正確性を失うことなく、グラフ全体を次数カウント統計に圧縮します。 これは、許可されるすべての操作が、現在エンドポイントの次数が 2 未満であるかどうか、およびエッジがすでに存在するかどうかにのみ依存するため、有効です。 エッジは決して再利用されず、次数は将来の接続の実現可能性を完全に把握するため、同一の 2 つの状態が存在します。$(a,b,c)$プロセスでは同じように動作します。 この対称性により、マルコフ特性が集約状態に保持されることが保証され、期待方程式が明確に定義され、解決可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

from functools import lru_cache

def solve():
    n = int(input())
    
    @lru_cache(None)
    def E(a, b, c):
        if a + b <= 1:
            return 0.0
        
        total = n * n
        res = 1.0
        
        # helper counts
        # pairs (u,v)
        
        # 0-0
        if a >= 2:
            ways = a * (a - 1)
            prob = ways / total
            res += prob * E(a - 2, b + 2, c)
        
        # 0-1
        if a >= 1 and b >= 1:
            ways = 2 * a * b
            prob = ways / total
            res += prob * E(a - 1, b - 1, c + 1)
        
        # 1-1
        if b >= 2:
            ways = b * (b - 1)
            prob = ways / total
            res += prob * E(a, b - 2, c + 2)
        
        # invalid or unchanged cases implicitly handled by staying in same state
        used = 0
        if a >= 2:
            used += a * (a - 1)
        if a >= 1 and b >= 1:
            used += 2 * a * b
        if b >= 2:
            used += b * (b - 1)
        
        prob_stay = 1.0 - used / total
        res += prob_stay * E(a, b, c)
        
        # solve for E(a,b,c)
        return res / (1.0 - prob_stay)
    
    print(f"{E(n,0,0):.9f}")

if __name__ == "__main__":
    solve()
```コードはメモ化を使用して繰り返しを直接実装します。 重要な構造は、すべての状態が次数クラス間の順序ペアを数えることによって遷移確率を計算するということです。 状態は最終的に最終構成に到達するため、再帰は安定しています。 

最終的な除算$1 - prob\_stay$自己参照の期待項を分離し、無効な動きが状態を変更しないままに保ちながらも時間に影響を与えるという事実を解決します。 

プロセスでは順序付けられたペアがサンプリングされるため、すべてのペアのカウントが順序付けされるように注意する必要があります。
