 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付いた頂点上の完全な無向グラフが与えられます。 個別の頂点 i と j のすべてのペアが接続され、そのエッジの重みは gcd(i, j) として定義されます。 この密なグラフから、スパニング ツリーを形成する n − 1 個のエッジを正確に選択する必要があり、選択したエッジの重みの合計が正確に k になる必要があります。 そのようなツリーが存在しない場合は、不可能であることを報告する必要があります。 

スパニング ツリーは常に完全なグラフ内に存在するため、主な問題は接続ではありません。 実際の制約は、ツリー構造を維持しながら gcd の重みの合計を制御することです。 すべてのエッジの重みは頂点ラベルから決定論的であるため、非常に特殊な算術重み関数を使用して、固定重み付けされた完全なグラフよりも効果的に構造を選択することになります。 

制約は大きく、n は最大 10^6 で、最大 5 × 10^5 のテスト ケースがあり、テスト全体の合計 n は 10^6 で制限されます。 これにより、テストごとに n の二次関数が即座に除外されます。 テストごとに O(n log n) であっても慎重に処理する必要があり、すべてのテストにわたって本質的に線形である必要があります。 

n が小さい場合、微妙なエッジケースが現れます。 n = 2 の場合、エッジは 1 つだけであるため、答えは固定されます。 k が gcd(1, 2) = 1 と異なる場合、それは不可能です。 もう 1 つの注意が必要なケースは、k が 10^12 までの非常に大きい場合に発生しますが、gcd 値の構造により、可能なツリーの最大重みがはるかに小さくなり、初期の棄却条件が強制されます。 

隠れた問題の中心は、すべてのペア間にエッジが存在するにもかかわらず、最適な構成で最も有用なエッジの重みが 1 になり、慎重に選択されたエッジのみがより高い重みに寄与することです。 

## アプローチ

 ブルート フォース アプローチでは、すべてのスパニング ツリーを試し、それらの合計 gcd 合計を計算します。 ツリー数の組み合わせ爆発を無視しても、完全なグラフのスパニング ツリーを生成するだけでも指数関数的になります。 Cayley の公式によれば、スパニング ツリーは n^(n−2) 個あり、それぞれを評価することは不可能です。 

より構造化された総当り攻撃は、ツリーを貪欲に構築し、常にエッジを試行し、合計 k と一致するようにバックトラックすることを検討することです。 各ステップがグローバル構造に依存しており、分岐要素が依然として膨大であるため、これでも失敗します。 

重要な構造的洞察は、任意のスパニング ツリーについて考えるのをやめ、代わりに固定バックボーンを持つ根付きツリーを構築し、合計を増加させる少数のエッジのみを慎重に制御することです。 すべてのエッジで gcd(i, j) が少なくとも 1 であるため、すべてのエッジが重み 1 で選択されている場合、ベースライン スパニング ツリーは自然に重み n − 1 に寄与します。n − 1 を超える追加の寄与は、gcd(i, j) ≥ 2 のエッジから得られる必要があります。 

これは、すべてのエッジの重みが 1 であるツリーから開始して、いくつかのエッジをより高い gcd エッジに選択的に置き換えて、制御された増分で合計を増やす必要があることを示唆しています。 より大きな gcd 値に寄与できる頂点は、約数を共有する頂点のみであるため、頂点を 2 のべき乗またはその他の構造化された倍数でグループ化することが不可欠になります。 標準的な構造では、すべての x に対して gcd(1, x) = 1 であるため、1 をルートとするスター状のバックボーンが使用され、きれいなベースラインが得られます。 

そこから、必要に応じて、より高い gcd 寄与を生成する方法で、いくつかの i の倍数である頂点を接続することができ、親リンクを再ルーティングすることによって重みの増加を効果的に制御できます。

 ## アルゴリズムのチュートリアル

 基本スパニング ツリーを構築し、必要な合計重み k に達するようにそれを調整します。 

### ステップ 1: ベースライン ツリーを構築する

 まず、すべての頂点 i (i ≥ 2 の場合) を頂点 1 に接続します。これにより、有効なスパニング ツリーが直ちに形成されます。

すべてのエッジ (1, i) の重みが gcd(1, i) = 1 であるため、このツリーの合計重みは n − 1 です。これにより、保証された最小の達成可能な合計が得られます。 

### ステップ 2: 実現可能性を確認する

 k < n − 1 の場合、すべてのスパニング ツリーには少なくとも n − 1 個のエッジがあり、各エッジの重みは少なくとも 1 である必要があるため、すぐに失敗します。したがって、最小可能な合計は n − 1 になります。 

### ステップ 3: 体重を増やす方法を理解する

 合計の重みを n − 1 より大きくするには、一部のエッジ (1, i) を、gcd(i, j) > 1 のエッジ (i, j) に置き換える必要があります。このような置換によるゲインは、gcd(i, j) − 1 です。 

k − (n − 1) に等しい合計ゲインを蓄積したいと考えています。 

### ステップ 4: 割り算構造を使用する

 n から 2 までの降順で頂点を処理します。各頂点 i について、それを 1 ではなく、ツリー内に既に存在する i の倍数 j に接続しようとします。 i を j に接続すると (j は i の倍数)、gcd(i, j) = i となり、ベースラインと比較して i − 1 のゲインが生成されます。 

これにより、総重量の大幅な増加を制御できます。 

### ステップ 5: ゲインの貪欲な割り当て

 残りの必要なゲイン R = k − (n − 1) を維持します。 大きいものから小さいものまでの各 i について、i をゲイン ソースとして使用できる場合 (つまり、利用可能な i の倍数である頂点がまだある)、i をそのような倍数の 1 つに付加し、R を i − 1 だけ削減します。 

以前に含まれていたノードに常に接続することで、接続が切断されないようにします。 

### ステップ 6: 残りのノードを完成させる

 ゲイン調整に使用されないノードは 1 に接続され、重み 1 のエッジが維持されます。 

### なぜ効果があるのか

 この構築は、現在のグラフが常にルート 1 の有効なツリーであるという不変条件に依存しており、すべての変更は接続性を維持しながら 1 つのエッジを正確に置き換えます。 「アップグレード」が成功するたびに、重み 1 のエッジが重み i のエッジに置き換えられ、合計の重みが正確に i − 1 だけ増加します。すべてのゲイン ステップは独立しており、互いに素なエッジを使用するため、合計は以前の選択を妨げることなく正確に制御されます。 

割り切れる保証により、i を i の倍数に接続すると、gcd は正確に i になることが保証され、これにより増分が正確かつ予測可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        if k < n - 1:
            print(-1)
            continue
        
        # initial tree: star at 1
        parent = [0] * (n + 1)
        used = [False] * (n + 1)
        parent[1] = 0
        
        # baseline connections
        for i in range(2, n + 1):
            parent[i] = 1
        
        remaining = k - (n - 1)
        
        # try to upgrade edges
        for i in range(n, 1, -1):
            if remaining <= 0:
                break
            
            # try to attach i to a multiple of i
            # we search for any j = 2*i, 3*i, ...
            if not used[i]:
                for j in range(2 * i, n + 1, i):
                    if parent[j] == 1 and remaining >= i - 1:
                        parent[j] = i
                        used[i] = True
                        remaining -= (i - 1)
                        break
        
        if remaining != 0:
            print(-1)
        else:
            for i in range(2, n + 1):
                print(i, parent[i])

if __name__ == "__main__":
    solve()
```実装は、ルート 1 の最小スター ツリーを構築することから始まります。これにより、有効なスパニング ツリーが保証され、予測可能なベースライン コスト n − 1 が得られます。`remaining`どれだけの追加重量が必要かを追跡します。 

貪欲ループは、i の倍数を 1 ではなく i に直接接続することにより、各 i を「重みソース」として使用しようとします。parent[j] を 1 から i に置き換えるとエッジの重みが 1 から i に増加するため、これが合計の重みを増加させる唯一の操作です。 

の`used`配列により、同じ i が複数回再利用されなくなり、構造の一貫性が保たれます。 内側のループは i の倍数をスキャンし、残りのバジェットを負にしない最初の実行可能なアップグレードを実行します。 

最後に、残りの必要なゲインが正確にゼロでない場合は、部分的な完了が正確なターゲット合計制約に違反するため、-1 を出力します。 

## 実用的な例

 ### 例 1

 入力:

 n = 5、k = 5

 ベースライン ツリーは 4 つのエッジを使用し、すべての重みが 1、合計 = 4 です。ゲイン 1 が必要です。 

まず i = 2 を考えます。 2の倍数は4です。 

| ステップ | アクション | 親の変更 | 残りのゲイン |
 | --- | --- | --- | --- |
 | 開始 | 1 をルートとするスター | すべての私→ 1 | 1 |
 | i = 2 | 4を2に付ける | 親[4]=2 | 0 |

 出力ツリーエッジ:

 (1,2)、(1,3)、(2,4)、(1,5)

 総重量は1+1+2+1=5となります。 

これは、単一の gcd アップグレードが必要な増分とどのように正確に一致するかを示しています。 

### 例 2

 入力:

 n = 2、k = 2

 可能なエッジは、重み gcd(1,2)=1 の (1,2) だけです。 

| ステップ | アクション | 残り |
 | --- | --- | --- |
 | 開始 | 強制エッジ | 0 |

 重み 2 に到達できないため、出力は -1 になります。 

これは、下限 n − 1 が厳しく、上方に到達できない場合があることを裏付けています。

 ## 特殊なケース

 n = 2 の場合、グラフにはエッジが 1 つだけ含まれます。 このアルゴリズムは、k を n − 1 と比較することにより、実行可能性を直ちにチェックします。n − 1 = 1 であるため、k = 1 のみが有効です。 この構造では単一のエッジ (1, 2) が出力され、それ以上の処理は行われないため、無効な調整の試行は行われません。 

k < n − 1 の場合、アルゴリズムは構造を構築する前に早期に拒否します。 たとえば、n = 10、k = 5 の場合は、スパニング ツリーの合計重みが少なくとも 9 である必要があるため、即時に障害が発生します。 

k が非常に大きい場合、貪欲なアップグレード プロセスにより、最終的には考えられるすべての gcd ゲインが使い果たされます。 最後に残りが 0 でない場合、アルゴリズムは -1 を出力し、すべての大きなターゲットが gcd ベースの増分で表現できるわけではないことを正確に捕捉します。
