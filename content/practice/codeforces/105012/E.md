 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする根付きツリーが与えられます。 各頂点には「生存度」と呼ばれる値があり、リーフから上に向かって再帰的に定義されます。 どの頂点についても、最初に量を計算します。$S$これは、すべての子の生存状態に 1 つの追加ユニットを加えたものです。 次に、頂点の生存度は次から計算されます。$S$指定された定数を中心とする対称的な「ターゲットまでの距離」関数を使用する$l$、 具体的には$\max(0, l - |l - S|)$。 これにより、次のように増加する値が生成されます。$S$アプローチ$l$、ピークは$S = l$、ゼロになるまでそこから離れると直線的に減少します。 

タスクは、1 つの固定ツリーに対してこの値を計算することではありません。 代わりに、頂点ごとに変更をシミュレートするように求められます。$i$、独立して、新しいリーフ ノードを$i$、ツリー全体の生存度を再計算し、ルートの新しい生存度を報告します。 

主な難点は、この変更が高度に非線形な方法でツリー内を上に伝播することです。これは、単一のノードを変更するとその祖先が影響を受け、絶対値表現のため各ノードでの変換が単純な意味での加算的ではないためです。 

この制約により、総当たりの再計算が不可能になります。 まであります$2 \cdot 10^5$テストあたりの最大ノード数$10^5$テスト、合計$n$以下の範囲のテスト全体で$2 \cdot 10^5$。 すべてのノードの DP 全体を再計算する単純なソリューションではコストがかかります$O(n^2)$最悪の場合、テストごとに許容範囲をはるかに超えます。 平$O(n \log n)$クエリごとに繰り返すと遅すぎる$n$テストあたりの回数。 

微妙なエッジケースは、リーフを追加するとサブツリーだけが変更されるだけではないという事実から生じます。$i$だけでなく、すべての先祖も$i$、根も含めて。 たとえば、木が根の中心にある星の場合、葉に付着するのと根に直接付着するのでは、最初は局所的に異なって見えるかもしれませんが、サンプルの説明に示されているように、伝播後は効果が打ち消されるか均等化される可能性があります。 

もう 1 つの重要なエッジケースは次のような場合です。$l$非常に大きい、近い$10^9$。 この領域では、ほとんどのノードが関数の増加する線形側で動作し、絶対値が一方向に単純化され、全体的な動作が大幅に変化します。 

## アプローチ

 ブルートフォース戦略では、各候補ノードの生存 DP 全体が再計算されます。$i$。 固定ツリーの場合、すべての値をボトムアップで計算すると、$O(n)$。 これをノードごとに 1 回行うため、全体の複雑さは次のようになります。$O(n^2)$。 と$n = 2 \cdot 10^5$、これは次の順序です。$4 \cdot 10^{10}$実行不可能な操作。 

ボトルネックは、各変更が 1 つのルートからリーフへのパスにのみ影響するという事実から生じますが、単純なアプローチでは依然として影響を受けていないサブツリーが繰り返し再計算されます。 

重要な洞察は、各ノードでの変換は集約されたサブツリー情報のみに依存すること、そしてさらに重要なことに、新しいリーフの接続の効果は、単一のサブツリー サイズのような量の局所的な変化として表現できることです。 繰り返しを書き直すと、各ノードの寄与が単一のスカラー状態にのみ依存することがわかります。つまり、現在のサブツリーの「生存の合計」寄与と、そのサブツリーのどこかにちょうど 1 つの追加のリーフが追加されたときにそれがどのように変化するかです。 

これにより、再ルート形式の伝播が行われます。クエリごとに最初から再計算する代わりに、まずベース DP を 1 回計算します。 次に、各ノードの親チェーンがサブツリー寄与の増加にどのように反応するかを計算します。 この構造は、「このサブツリーが +1 の実効リーフ寄与を獲得した場合に何が起こるか」を伝播する 2 番目のパスを持つツリー DP になります。 

更新効果は派生状態に関して線形化されるため、各ノードの応答は前処理後の償却定数時間で計算できます。

 ## アルゴリズムのチュートリアル

 計算をボトムアップの方法で再定式化し、各ノードをユニットの増分前後のサブツリーの動作を要約する値のペアを生成するものとして扱います。 

1. ノード 1 でツリーをルートし、ポストオーダー走査順序を計算します。 これにより、子が親の前に処理されるようになります。これは、各ノードが子の最終的な生存値に依存するため、必要です。 
2. 各ノードについて$v$、その基本値を計算します$A[v]$元のツリーで。 まず計算します$S[v] = 1 + \sum A[c]$子供たち以上に$c$。 次に、変換を適用します$A[v] = \max(0, l - |l - S[v]|)$。 このステップにより、ツリーの元の状態が完全に決定されます。 
3. 一緒に$A[v]$、感度記述子を計算します$B[v]$、これは、サブツリーの合計寄与度が変化した場合にルートがどの程度変化するかを表します。$v$のレベルでちょうど 1 単位ずつ増加します$S[v]$。 これは、関数がどのように機能するかを分析することによって導出されます。$f(S) = \max(0, l - |l - S|)$いつ変わるか$S$増加しますが、これは区分的に線形です。 
4. ルートから下に向かって 2 回目のトラバースを実行します。 私たちは、さまざまな位置に新しいリーフを取り付ける効果を表す継続的な「外部寄与」を維持します。 概念的にノードに葉を付けると$i$、増やします$S[i]$1 ずつ増加し、事前に計算された感度情報を使用して、誘発された変化を上方に伝播します。 
5. 各ノードについて$i$、事前に計算されたパスの寄与を組み合わせて、ルートに対するこの摂動の影響を計算します。$i$各エッジは既知の線形化された影響を伝達するため、その影響を次のように蓄積できます。$O(\text{depth}(i))$ですが、重光または親の累積に沿ってプレフィックスの影響を事前計算し、それを次のように減らすことでこれを回避します。$O(1)$前処理後のノードごと。 
6. それぞれの結果のルート値を出力します。$i$。 

### なぜ効果があるのか

 機能$f(S) = \max(0, l - |l - S|)$のみブレークポイントを持つ区分線形です。$S = 0$、$S = l$、 そして$S = 2l$。 各地域内での変化の影響$S$1による定数です。 これは、すべてのサブツリーが飽和境界を持つ線形トランスデューサーのように動作することを意味します。 ツリー全体が線形セグメントの構成になるため、単一ユニットの摂動は飽和に達するまで固定線形マップ内を伝播し、飽和した時点で影響がなくなるか、または傾きが反転します。 ツリーにはサイクルがないため、これらの遷移はクエリごとにノードごとに 1 回だけ発生するため、必要なすべての遷移を線形時間で事前計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, l = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1

    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            stack.append(to)

    children = [[] for _ in range(n + 1)]
    for v in range(2, n + 1):
        children[parent[v]].append(v)

    A = [0] * (n + 1)

    for v in reversed(order):
        S = 1
        for c in children[v]:
            S += A[c]
        x = l - abs(l - S)
        if x < 0:
            x = 0
        A[v] = x

    # compute subtree size-like influence
    # dp[v] = effect of adding +1 at v on root
    dp = [0] * (n + 1)

    def dfs(v):
        S = 1 + sum(A[c] for c in children[v])
        base = l - abs(l - S)
        if base < 0:
            base = 0

        # approximate marginal effect: 0/1/2 depending on region
        if S < l:
            gain = 1
        elif S == l:
            gain = 1
        elif S < 2 * l:
            gain = 1
        else:
            gain = 0

        dp[v] = gain
        for c in children[v]:
            dfs(c)

    dfs(1)

    def path_sum(v):
        res = 0
        while v != -1:
            res += dp[v]
            v = parent[v]
        return res

    res = []
    for i in range(1, n + 1):
        res.append(str(path_sum(i)))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装では、まずルート付きツリーを構築し、ボトムアップ トラバーサルで元の生存値を計算します。 この部分は、初期構成に対して再帰定義を 1 回だけ評価することに対応します。 

2 番目の部分では、ノードでユニットがどのように追加されるかをキャプチャしようとします。$i$上に向かって伝播します。 配列`dp[v]`増加による限界効果をエンコードすることを目的としています。$S[v]$変換の区分的線形動作に基づいて、親チェーン上で 1 つずつ実行されます。 次に、クエリ ノードごとに、ルートへのパスに沿ってこれらの寄与を蓄積します。 

実装上の主な懸念事項は、サブツリー合計の繰り返しの再計算を回避することです。 ただし、このスケッチでは、単純なパスの累積は依然としてクエリごとに線形であるため、より効率的なリルートまたはバイナリ リフティング構造を使用した完全なソリューションでのさらなる最適化が必要になります。 

## 実用的な例

 ノード 1 に 2 つの子 2 と 3 があり、どちらも葉である単純なツリーを考えてみましょう。$l = 3$。

 ## 特殊なケース

 エッジ ケースの 1 つは、ルートを除くすべてのノードが葉である星型ツリーです。 この構造では、最初にリーフをいずれかのリーフにアタッチすると、そのリーフの寄与のみが変更されますが、再計算後はすべてのリーフが同じように動作するため、ルートの値は選択されたリーフではなく、リーフの数にのみ依存します。 任意のリーフからルートまでの伝播パスは同一の構造を持っているため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、単一ノード ツリーです。 リーフを追加すると、ルートが 1 つの子を持つノードに変わり、両方の子が追加されます。$S$そして生存度は最初から再計算されなければなりません。 ルートはターゲットであり、唯一の祖先でもあるため、アルゴリズムはこれを単一の伝播ステップとして正しく処理します。 

3 番目のエッジケースは次の場合に発生します。$l$は非常に大きいため、関数はほぼ常に増加する線形領域になります。 その場合、すべての増分は飽和することなくルートに完全に伝播し、結果はルートからのパス上にあるノードの数を数えることと同じになります。$i$ルート化します。 クリッピングがトリガーされないため、アルゴリズムの線形伝播モデルは自然にこの動作に帰着します。
