 ## 解決策
 ## 問題の理解

 バイナリ配列と、ターゲット セグメント サイズを記述する 2 番目の配列が与えられます。 バイナリ配列を取得し、それを等しい値の最大ランに圧縮すると、一連のブロック長が得られます。 たとえば、次のようなシーケンス`1 1 0 0 0 1`一定の長さのブロックになる`[2, 3, 1]`。 これらのブロックの順序は、配列の開始位置と実行の交互方法によって異なります。 

個々のビットを反転することができます。 各フリップはこれらのランの構造を変更し、2 つのブロックをマージしたり、1 つのブロックを分割したり、ブロック間の境界を変更したりする可能性があります。 目標は、最初のバイナリ配列を変換して、そのランレングス エンコーディングがマルチセットとして表示され、配列内の値のマルチセットと正確に一致するようにすることです。`b`。 

出力は、ブロック長が正確に一致する配置を実現するために必要なビット フリップの最小数です。`b`任意の順序で。 

制約は小さいです:両方とも`n`そして`m`これは、3 次動的計画法、または慎重に設計された 2 次動的計画法によるソリューションが実現可能であることを直ちに示唆しています。 ただし、本当の困難は計算規模ではなく、反転が実行境界にどのような影響を与えるかを推論することです。 

最初の配列にブロック長の正しいマルチセットがすでに含まれているものの、配置が異なる場合、微妙なエッジ ケースが発生します。 たとえば、ブロックが`[1, 2, 3]`しかしターゲットは`[3, 1, 2]`、セグメンテーションが正しく配置されていることを確認する以外に、構造を再配置する必要はありません。 ブロックを左から右に貪欲に一致させようとする素朴なアプローチは失敗します。`b`、固定された順序ではありません。 

マージと分割が相互作用するときに、別の注意が必要なケースが発生します。 長いラン内のビットを反転すると、単にローカルでコストが増加するだけではなく、2 つの新しいランが作成され、複数の隣接するブロックの長さが同時に変更される可能性があります。 位置ごとにローカルで貪欲な調整を行うと、この結合が過小評価されてしまいます。 

## アプローチ

 ブルート フォースの観点は、最終的なバイナリ文字列が、長さが順列を形成するランへの配列の一部の分割に対応するという観察から始まります。`b`。 すべてのバイナリ文字列を反復処理し、それらのランレングスが一致するかどうかをチェックすることを想像することもできます。`b`。 これは明らかに指数関数的です`n`、あるので`2^n`バイナリ文字列、および構造ごとにプルーニングしても、依然として多すぎる構成が残ります。 

より構造化されたブルート フォースでは、あらゆる方法で各セグメントの長さを割り当てようとします。`b`を最終実行分解の位置に設定し、割り当てごとにそのセグメンテーションを強制するために必要な最小限の反転を計算します。 これでもすでにセグメント数の組み合わせになり、本質的には階乗になります。`m`。 

重要な点は、実際には最終的な文字列を明示的に構築する必要がないということです。 重要なのはランの構造です。 ターゲットのセグメンテーションを修正する場合、つまりランの境界がどこにあり、各ランに対応する長さを正確に決定する場合、コストの計算が簡単になります。各セグメントは強制的にすべて 0 またはすべて 1 に交互に設定され、元の配列との不一致に対してのみ支払いが行われます。 

したがって、構造を恣意的に変更する反転について考える代わりに、視点を逆転させます。 実行構造を配列に「強制」し、一致しないビットの数を計算します。 境界が固定されると、押し付けられた各セグメントは独立します。 問題は、セグメントの長さの配置を選択することに帰着します。`b`長さの直線的なレイアウトに`n`、開始ビット パリティを決定しながら、不一致コストを最小限に抑えます。 

これは、セグメントにわたる古典的な間隔 DP になります。 現在のセグメントが 0 であるべきか 1 であるべきかを追跡しながら、セグメントごとに最終的な文字列の構築をシミュレートします。 各ステップで、次にどの残りのセグメント長を配置するかを選択し、その間隔を強制的に定数ビットにするコストを計算します。 

順列の側面`b`は、セグメントを順序付けされていない選択肢として扱うことによって処理されます。 これにより、使用されるセグメントのサブセットに対して組み合わせ状態が導入されますが、`m ≤ 100`、直接サブセット DP が大きすぎます。 代わりに、意図された構造はソートすることです。`b`また、未使用のセグメント長間の遷移を許可しながら、同一の長さを圧縮するか、周波数ベースの DP を使用しながら、セグメント インデックス上で DP を使用します。 

重要な単純化は、セグメントの長さの複数セットのみが重要であり、順序は無関係であるということです。 したがって、並べ替えることができます`b`、DP 状態を、現在の位置とともに「すでに配置したセグメントの数」として扱います。`a`セグメントカラーのパリティ。 これにより、最適なソリューションでは常にセグメント境界がいくつかのパーティション ポイントに位置合わせされるため、セグメント境界の貪欲なマッチングによる線形スキャン DP が得られます。`a`反転コストが変わるところ。 

最終的に、問題は、連続したサイズのチャンクを割り当てるための不一致コストの計算に帰着します。`b[i]`最適な順序を選択すると、大きなセグメントと低コストの領域をペアにすることになります。これは、両方の構造をソートすることで実現されます。 

したがって、最適な解決策は、セグメントの長さと元の文字列によって引き起こされる連続領域の間のマッチング問題となり、領域ごとのフリップ コストを最小限に抑えます。

 ## アルゴリズムのチュートリアル

 1. まず、バイナリ配列をランレングス エンコーディングに圧縮します。 これにより、それぞれ固定長の 0 と 1 の交互のセグメントが得られます。 このステップにより、反転は実行の一貫性に影響を与える場合にのみ重要となるため、問題は個々のビットではなく構造ブロックの操作に軽減されます。 
2. 開始極性を選択する考えられるそれぞれの方法について、選択したセグメント長にわたってきれいな交互パターンを強制した場合に最終的なセグメンテーションがどのように見えるかを検討します。 開始極性は、最初のセグメントが 0 であるか 1 であるかを決定するため、重要です。 
3. 任意の間隔を強制するコストを事前計算する`[l, r)`元の配列をすべて 0 またはすべて 1 にします。 このコストは、単にその間隔内の不一致ビットの数です。 これにより、プレフィックス合計を前処理した後、O(1) 内の仮想セグメントの配置を評価できるようになります。 
4. 配列をソートする`b`。 最終的なランレングス エンコーディングは次の順列であるため、これは有効です。`b`したがって、セグメントの長さを任意の順序で自由に割り当てることができます。 ソートにより、順列を調べることなく最適な構造を推論することができます。 
5. DP を構築します。セグメントを長さの昇順に 1 つずつ配置し、消費された量を追跡するポインターを元の配列に保持します。 各セグメントについて、正確にその長さだけパーティションを拡張し、パリティに応じてセグメントがすべて 0 またはすべて 1 であると仮定して、不一致コストを計算します。 
6. DP 移行により、現在のセグメントに加えて以前の最良の構成を強制するコストが追加されます。 ポジションが固定されるとセグメントは独立するため、コストは線形に蓄積されます。 
7. 可能な両方の開始極性の最小値を取得します。 

### なぜ効果があるのか

 配列のセグメント化を、長さが正確に要素である間隔に固定したら、`b`、問題はセグメントごとに独立します。 各セグメントは一定であることが強制され、それを強制するコストは純粋にローカルです。 唯一のグローバル構造はセグメントの長さの順序ですが、目的はマルチセットのメンバーシップのみに依存し、不等長間の隣接性制約には依存しないため、コストを増加させることなく、最適な配置をソートされた順序に並べ替えることができます。 この交換引数により、ソートされたセグメントに対する DP が最適なソリューションのスーパーセットを探索することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # prefix sums for cost queries
    pref0 = [0] * (n + 1)
    pref1 = [0] * (n + 1)
    
    for i in range(n):
        pref0[i+1] = pref0[i] + (a[i] == 1)
        pref1[i+1] = pref1[i] + (a[i] == 0)
    
    def cost(l, r, bit):
        if bit == 0:
            return pref0[r] - pref0[l]
        else:
            return pref1[r] - pref1[l]
    
    b.sort()
    
    INF = 10**18
    
    # dp[i][j][p]: first i segments, current position j, parity p
    # but we compress position by greedy placement: j is implicit cumulative length
    dp0 = 0
    dp1 = 0
    pos = 0
    
    # try both starting parities
    ans = INF
    for start in [0, 1]:
        pos = 0
        cur0 = 0
        cur1 = 0
        
        for i in range(m):
            length = b[i]
            nxt = pos + length
            
            c0 = cost(pos, nxt, 0)
            c1 = cost(pos, nxt, 1)
            
            if i % 2 == start:
                new0 = min(cur0, cur1) + c0
                new1 = min(cur0, cur1) + c1
            else:
                new0 = min(cur0, cur1) + c1
                new1 = min(cur0, cur1) + c0
            
            cur0, cur1 = new0, new1
            pos = nxt
        
        ans = min(ans, min(cur0, cur1))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、プレフィックスの合計に依存して、一定時間内のセグメント強制コストを評価します。 DP はステップごとに 2 つの値、つまり現在のセグメントがゼロまたは 1 に強制された場合のコストを追跡します。 パリティ条件は、開始ビットの選択によって制御され、セグメント間の代替を強制します。 

微妙な点は、複数の順序の位置にセグメント長を明示的に割り当てていないことです。 仕分け`b`そしてそれを順番に消費することは、実現可能性を変えることなく最適な順列を並べ替えることができるという交換引数を前提としています。 これは、順列の側面を線形スキャンに折りたたむものです。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`b`以下に等しい単一の大きな値が含まれます`n`。 このアルゴリズムは、配列全体を強制的に定数ビットにします。 DP は、プレフィックス合計を使用してオール 0 コストとオール 1 コストの両方を正しく評価し、最小値を選択します。 

別の特殊なケースは、次のすべての要素が存在する場合に発生します。`a`すでに交互のビットを形成しています。 その状況では、セグメンテーションによってすべての境界で不一致が生じます。 各セグメントのコストが個別に計算され、DP が避けられない反転を自然に蓄積するため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、同一の長さのセグメントが複数存在する場合です。 以来`b`ソートされると、同じ値が隣接し、互換的に処理されます。 これにより、同等の順列の冗長な探索が防止され、DP はそれらを対称的に処理して正確さを維持します。
