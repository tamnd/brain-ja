 ## 問題の理解

 それぞれが正の重みを持つシェルの線形シーケンスが与えられます。 貝殻は浜辺に沿って順番に並べられており、連続したブロックのみ採取が許可されています。 ただし、容量の制限があります。バッグには最大でも収納できます。`K`砲弾の総重量に関係なく。 

タスクは、長さが次を超えない連続セグメントを選択することです。`K`、そのセグメント内の重みの合計が最大化されるようにします。 

出力は単一の数値であり、すべての有効な連続セグメントの可能な最大の合計です。 

制約が十分に大きいため、$O(N^2)$すべてのサブアレイをスキャンすることは不可能です。 と$N \le 2 \cdot 10^5$、二次アプローチは次数を意味します。$4 \cdot 10^{10}$これは通常の限界をはるかに超えています。 これは、線形または線形に近い方法が必要であることを直ちに示唆しています。 

微妙なエッジケースが現れるのは、`K >= N`。 この状況では、すべての要素を取得できるため、答えは単純に配列全体の合計になります。 常に固定ウィンドウ サイズを維持しようとする単純なスライディング ウィンドウの実装`K`配列が有効範囲よりも短い場合は、有効範囲を下回らないように注意する必要があります。`K`。 

もう 1 つの潜在的な落とし穴は、最適なセグメントが常に正確な長さであると仮定していることです。`K`。 これは必ずしも当てはまりません。負の構造を回避すれば短いセグメントの方が合計が大きくなる可能性があるからです。ただし、この問題ではすべての重みが正であるため、最適なセグメントは常に正確に使用されます。`K`境界によって制限されない限り、要素。 その特性により、引き違い窓のアプローチがきれいになります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての開始位置を試し、それを次の位置まで拡張します。`K`進みながら合計を積み上げていきます。 インデックスごとに`i`、から始まるすべてのサブ配列をチェックします。`i`そして最大でも長さ`K`、グローバル最大値を更新します。 

これは、すべての有効なセグメントを明示的に列挙するため、正しいです。 問題は手術回数です。 それぞれについて、`N`開始点、最大`K`要素が処理される可能性があり、$O(NK)$時間。 以来`K`と同じ大きさにすることができます$10^7$、これはまったく不可能です。 

問題の構造は、より良いアプローチを示唆しています。 固定の最大長制約を使用して、すべての連続セグメントの合計を最大化しています。 すべての重みが正であるため、ウィンドウを拡張すると常に合計が増加します。そのため、固定された右端点の場合、そこで終了する最適な有効なセグメントは、長さまでの可能な限り長いものになります。`K`。 これは、最大でも次のサイズのスライディング ウィンドウのみを維持する必要があることを意味します。`K`左から右にスキャンしながら、現在の合計を効率的に追跡します。 

現在のウィンドウの累計を維持します。 右の境界を前方に移動すると、新しい要素が追加されます。 ウィンドウがサイズを超える場合`K`、一番左の要素を削除します。 すべてのステップで、現在の合計はその位置で終了する最良のセグメントを表すため、答えを更新します。

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化する`l = 0`そして累計`current = 0`、および変数`best = 0`。 

ポインタは、検討しているシェルの現在のウィンドウを定義します。 
2. 反復する`r`から`0`に`N - 1`、各位置をウィンドウの右端として扱います。 

各ステップでは、さらに 1 つのシェルを含めることによって候補セグメントを拡張します。 
3.追加`W[r]`に`current`。 

これにより、新しいシェルが実行ウィンドウの合計に組み込まれます。 
4. ウィンドウサイズを超える場合`K`、左から減算して縮小します。`W[l]`そして増加する`l`。 

これにより、最大でも次の制約が尊重されます。`K`貝殻が取れる。 ここで要素を削除しないと、ウィンドウが任意に大きくなり、問題の条件に違反する可能性があります。 
5.ウィンドウを調整した後、更新します`best = max(best, current)`。 

この時点で、ウィンドウは次で終了する最も有効なセグメントを表します。`r`なぜなら、プレフィックスが短くても、重みが正であるために合計が減るだけだからです。 
6. すべての位置を処理した後、出力します`best`。 

### なぜ効果があるのか

 あらゆるポジションで`r`、アルゴリズムはウィンドウを維持します`[l, r]`それは有効です (最大長さ`K`)、その合計が正確に計算されます。 すべての重みが正であるため、次で終わる有効なセグメントはすべて`r`現在のウィンドウよりも長さが短い場合、合計は小さいか同じになります。 したがって、制約の下でウィンドウの長さが最大化されると、そのエンドポイントの合計も最大化されます。 すべてスキャン中`r`考えられるすべての右側の境界が確実に考慮されるため、すべての有効なセグメントにわたるグローバル最大値が取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    k = int(input())

    l = 0
    current = 0
    best = 0

    for r in range(n):
        current += w[r]

        if r - l + 1 > k:
            current -= w[l]
            l += 1

        if current > best:
            best = current

    print(best)

if __name__ == "__main__":
    solve()
```このコードは、配列全体にわたって単一のスライディング ウィンドウを維持します。 左のポインタ`l`は前方にのみ移動するため、各要素の追加と削除は最大 1 回で、直線的な複雑さが保証されます。 条件`r - l + 1 > k`最大ウィンドウ サイズの制約を強制します。 変数`current`現在の有効なセグメントの合計を常に保存し、`best`これまでに確認された最大値を追跡します。 

よくある実装上の間違いは、追加する前にウィンドウ サイズを確認することです。`w[r]`これにより、off-by-one エラーが発生する可能性があります。 正しい順序は、最初に要素を含めてから、必要に応じてウィンドウを修正することです。

 ## 特殊なケース

 いつ`K >= N`、サイズ制約に違反しないため、ウィンドウが縮小することはありません。 このアルゴリズムはすべての要素を一度に蓄積するだけで、`best`の合計となります。 

次のような単一要素配列の場合`N = 1`、ループが 1 回実行され、要素が追加されますが、縮小は発生しません。 結果はまさにその要素であり、唯一の有効なセグメントと一致します。 

大きな値が間隔をあけて配置されている配列では、次のようになります。`[2, 100, 3, 4, 5, 6, 1]`と`K = 3`を選択すると、スライディング ウィンドウが正しく移動して、適合する最大の連続グループが含まれるようになります。 各ステップで、ウィンドウは有効なままであり、高値クラスターが完全にウィンドウ内に入った時点で最大値が更新されます。
