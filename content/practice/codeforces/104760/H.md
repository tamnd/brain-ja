 ## 解決策
 ## 問題の理解

 最初に 2 つの異なる宇宙に分かれた 2 つの旅行者のグループが与えられ、一方には A 人、もう一方には B 人がいます。 2 つのユニバースの間には N 個のポータルがあり、各ポータルは使用できる回数が制限されています。 誰かがポータルを通過するたびに、彼らは陣営を切り替え、ポータルが正確に使用された後、$f_i$何度も壊れて使えなくなります。 

このプロセスは、ユーザーとポータルを繰り返し選択し、そのユーザーをポータル内で移動させ、その使用量をポータルの制限にカウントすることで構成されます。 目標は、すべてのポータルが完全に破壊され、すべての旅行者が同じ宇宙に行き着くという 2 つの条件が最後に成立するように、このような一連の動きを実行できるかどうかを決定することです。 

入力サイズは最大で$10^5$最大容量のポータル$10^9$、これにより、個々の交差点のシミュレーションが即座に除外されます。 ステップバイステップで操作を行う解決策は、交差の総数が次の数に達する可能性があるため、非常に遅すぎます。$10^{14}$。 

微妙な点は、各ポータルに方向性がなく、使用するたびに 1 人の人物の面だけが反転することです。 どのポータルを誰が使用するかについての制限はありません。つまり、グローバルな制約は、個人のアイデンティティやポータルの構造ではなく、移動回数とサイドチェンジの同等性によってのみ決まることを意味します。 

素朴だが間違ったアプローチは、人々をポータルに貪欲に割り当てたり、異動をシミュレートしたりしようとすることです。 たとえば、A = 2、B = 2、ポータル [1, 1, 1] の場合、局所的にサイドのバランスをとろうとする貪欲な戦略は、各ステップでどの個人が移動するかを選択する柔軟性を考慮していないため、バランスをとることは不可能であるという誤った結論を下す可能性があります。 実際の制約はグローバルであり、構造ではなく合計にのみ依存します。 

もう 1 つの落とし穴は、各ポータルを正確に使用する必要があると想定していることです。$f_i$時として、これらの使用の時間的分布が重要になります。 そうではありません。 サイドフリップの合計数だけが重要です。 

## アプローチ

 ブルート フォースの観点は、プロセス全体をシミュレートすることです。利用可能なポータル キャパシティのマルチセットと各側の人のリストを維持し、その後、人物とポータルを繰り返し選択し、移動を適用し、残りのキャパシティを減らします。 それぞれの操作は、$O(1)$、しかし、あります$\sum f_i$合計の操作。 以来$\sum f_i$と同じ大きさにすることができます$10^{14}$、このアプローチは完全に実行不可能です。 

重要な簡素化は、ポータルのアイデンティティを無視し、各操作がグローバルに行うことだけに焦点を当てることです。 横断するたびに、ちょうど 1 人の人物が一方の側からもう一方の側に反転します。 すべてのポータルが使い果たされた後、正確に$T = \sum f_i$このような反転が発生しました。 重要なのは、A から B へのフリップと B から A へのフリップの数だけです。 

しましょう$p$A から B への移動回数、および$q$BからAへ。そして$p + q = T$。 最終的なA面の人数は、$A + q - p$。 すべての人を一方の側に配置したいので、これらの有効な分割が存在するかどうかを確認するだけで済みます。$T$どちらかを生み出す動き$A + B$片側または$0$あちら側で。 

これにより、問題全体がパリティと実現可能性の条件に還元されます。$T$、唯一の自由は各方向に何回移動するかを選択することであるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(\sum f_i)$|$O(1)$| 遅すぎる |
 | 総数 + パリティ推論 |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ポータルの合計使用数を計算します$T = \sum f_i$。 その後、問題全体は、A 側の全員で終了できるか、B 側の全員で終了できるかを確認することになります。 

1. コンピューティング$T = \sum f_i$。 これは、発生する必要がある横向きの動きの合計数を表します。 
2. すべての旅行者が A 面で終了する可能性を考慮します。 この場合、最終的な A 面の人口は次のようになります。$A + B$。 それぞれの動きは正確に 1 人を反転させます。$T$移動すると、A サイドの人口の変化は、各方向に移動した回数によって決まります。 これにより、次のような状態が生じます。$T \ge B$、少なくともすべてのB側の旅行者を移動させる必要があるためです。 
3. A で終わるためのパリティの一貫性を確保します。 違い$T - B$逆方向の移動の各ペアが 1 つの正味シフトを打ち消すため、 は偶数である必要があります。 これにより、残りの純移動量がすべての B 旅行者の必要な移動量と正確に一致することが保証されます。 
4. B 面でも同じ理由を繰り返して終了します。 その場合に必要なのは、$T \ge A$そしてそれ$T - A$は均等です。 
5. 2 つのターゲット構成のいずれかが実行可能な場合は、YES を出力します。 それ以外の場合は、NO を出力します。 

### なぜ効果があるのか

 各操作により、A 側の人数が正確に変更されます。$+1$または$-1$、方向によって異なります。 すべての操作の後、重要なのはそのような増分の合計数のみであり、その順序やどのポータルが増分を生成したかは重要ではありません。 これにより、システムは次のシーケンスを選択するのと同等になります。$T$正味合計が固定目標と一致する必要がある署名付きステップ。 唯一の障害は、パリティとマグニチュードの制約が必要な最終構成と一致しているかどうかです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())
    n = int(input())
    f = list(map(int, input().split()))
    
    T = sum(f)
    
    if (T >= B and (T - B) % 2 == 0) or (T >= A and (T - A) % 2 == 0):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```実装では、最初にすべてのポータル容量が 1 つの合計に集約されます。 その時点以降、ポータルごとの推論は必要ありません。 2 つの条件チェックは、最終的な統合ユニバースとして A または B を選択するための実現可能性条件を直接エンコードします。 モジュロ チェックにより、必要な転送を考慮した後に残った不均衡が、反対の動きのペアを使用して解決できることが保証されます。

 ## 特殊なケース

 いつ$T$が A と B の両方より小さい場合、反対側のすべての旅行者を再配置することさえ不可能であるため、アルゴリズムは両方の最終構成を即座に拒否します。 たとえば、$A = 10$、$B = 10$、 そして$f = [1, 1]$、私たちは得ます$T = 2$、どちらの側からもすべての旅行者を移動させるには不十分であり、NOが生成されます。 

いつ$T$大きさは正しいがパリティが間違っている場合、十分な手があるにもかかわらず実現可能性は失敗します。 例えば、$A = 4$、$B = 4$、$T = 5$これにより、一方向への十分な転送が可能になりますが、再分配が成功するたびに反対方向への移動をペアにする必要があるため、合計が奇数になるとバランスが取れなくなります。
