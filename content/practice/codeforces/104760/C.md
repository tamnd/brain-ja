 ## 解決策
 ## 問題の理解

 数直線に沿って配置された間隔のコレクションが与えられます。 各間隔は、道路の開始座標から終了座標までのセグメントを照らすランプを表します。 複数のランプが重なり合ったり、道路の一部がいくつかの間隔で覆われたり、まったく覆われなかったりする場合があります。 

タスクは、少なくとも 1 つのランプで照らされている道路の全長を決定することです。 言い換えれば、指定されたすべての間隔の和集合の長さを計算する必要があります。 

この制約では、最大 10,000 の間隔が許可され、座標の範囲は負から正の 10 億です。 このサイズでは、道路を点ごとに検査しようとするアプローチは即座に排除されます。 座標範囲を単純に離散化するには、最大 20 億の位置を反復する必要がありますが、これは実行可能な限界をはるかに超えています。 考えられるすべての座標を明示的に保存することさえ、時間的にもメモリ的にも不可能です。 

オーバーラップの処理では、さらに微妙な問題が発生します。 たとえば、間隔がネストされているか、重なり合っている場合、それらの長さを単純に合計すると、共有領域の数が超過してしまいます。 間隔を考慮する`[0, 10]`そして`[5, 15]`。 長さを合計すると 10 + 10 = 20 になりますが、正しい和集合は次のとおりです。`[0, 15]`正しい解決策では、重複するセグメントの二重カウントを明示的に回避する必要があります。 

一般に単純な実装を破壊するエッジ ケースには、完全に切り離された間隔、完全にネストされた間隔、エンドポイントでのみ接触する間隔などがあります。 例えば、`[0, 5]`そして`[5, 10]`エンドポイントが連続カバレッジとみなされる場合、合計の長さは 10 になります。これがこの問題の標準的な解釈です。 単純な「重複が厳密な場合にのみマージ」の実装では、接触間隔が誤って別個のものとして扱われる可能性があります。 

## アプローチ

 強引な解釈では、きめの細かい数直線上でカバレッジをシミュレートすることになります。 任意の間隔に含まれるすべての整数点をマークし、マークされた数をカウントすることを想像できます。 概念的には単純ですが、座標は -10^9 から 10^9 までにわたるため、これはすぐに失敗します。 座標を圧縮したとしても、各間隔が非常に大きい可能性があるため、ポイントごとのマーキングまたはスキャンを実行すると、依然として時間がかかりすぎます。 

もう 1 つの大胆なアイデアは、間隔のすべてのペアを比較し、安定するまで繰り返しオーバーラップをマージすることです。 各マージ ステップでは多くの間隔でのスキャンと更新が必要になる可能性があり、パスの繰り返しが必要になる場合があるため、これにより最悪の場合は O(N^2) プロセスが必要になります。 

重要な観察は、実際にはポイントレベルのカバレッジを知る必要がないということです。 カバレッジが「カバーされていない」から「カバーされている」に、またはその逆にどこで変化するかを知る必要があるだけです。 開始座標によって間隔がソートされると、重複が構造化されます。間隔を順番に処理する場合、これまでに確認された最も右の端点を維持するだけで済みます。 新しい間隔は、現在カバーされている領域を拡張するか、新しい分離領域を開始します。 

これにより、問題はソートされた間隔にわたる古典的なスイープに縮小され、現在のアクティブなセグメントが維持され、ギャップが現れるたびにその寄与が蓄積されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースマーキング | O(R) ここで、R は座標範囲 | O(R) | 不可能 |
 | ペアごとのマージ | O(N^2) | O(N) | 遅すぎる |
 | ソート + スイープ | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を読み取り、開始座標で並べ替えます。 並べ替えることにより、左から右に移動するときに、以前に発見されたギャップを誤って再訪問することがなくなります。 
2. 最初の間隔を使用して実行セグメントを初期化します。 このセグメントは、構築中の重複する間隔の現在の結合を表します。 
3. 残りの間隔を並べ替えられた順序で 1 つずつ繰り返します。 
4. 各間隔について、その開始位置と現在のセグメントの終了位置を比較します。 開始点が現在の終了点以下である場合、間隔は重なるか接触するため、現在のセグメントの終了点を両端の最大値まで延長します。 これにより、二重にカウントされることなく補償範囲の継続性が維持されます。 
5. 開始が現在の終了より大きい場合、現在カバーされているセグメントと新しい間隔の間にギャップがあります。 この場合、現在のセグメントの長さを答えに追加し、現在の間隔から新しいセグメントを開始します。 
6. すべての間隔を処理した後、最後のアクティブなセグメントを回答に追加します。 

重要な考え方は、将来の間隔が延長できないことが確実な場合にのみセグメントを終了するということです。これはまさにギャップを検出したときに発生します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは不変条件を維持します。つまり、現在のセグメントは、これまでに処理された、互いに交差するか、オーバーラップによって接続されたチェーンを形成するすべての間隔の結合を正確に表します。 間隔は開始の昇順に処理されるため、将来の間隔はこのセグメントを拡張するか、厳密にその後に開始することしかできません。 したがって、現在の終了後に始まる新しい間隔に遭遇した場合、現在のセグメントは完全に決定され、将来のデータの影響を受けることがないため、その長さを最終結果に安全に追加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []
    for _ in range(n):
        a, b = map(int, input().split())
        intervals.append((a, b))

    intervals.sort()

    cur_l, cur_r = intervals[0]
    total = 0

    for l, r in intervals[1:]:
        if l <= cur_r:
            if r > cur_r:
                cur_r = r
        else:
            total += cur_r - cur_l
            cur_l, cur_r = l, r

    total += cur_r - cur_l
    print(total)

if __name__ == "__main__":
    solve()
```コードは、すべての間隔を読み取って並べ替えることから始まります。これは、重複部分が連続して表示されるようにするために不可欠です。 変数`cur_l`そして`cur_r`現在アクティブなマージされたセグメントを追跡します。 新しい間隔が重なると、右側の境界だけが拡張される可能性があるため、最大値を採用します。 ギャップが見つかると、現在のセグメントの長さが確定され、`total`、セグメントを再開します。 

微妙な点は、オーバーラップ処理中に部分的な寄与を決して追加しないことです。 これにより、各セグメントが閉じられたときに 1 回だけ計算されるため、二重カウントが完全に回避されます。

 ## 特殊なケース

 次のような素な間隔の場合`[0,1]`そして`[3,4]`、アルゴリズムは最初の間隔を処理してから、`3 > 1`そして、新しいセグメントを開始する前に最初のセグメントを終了します。 これにより、ギャップ間で人為的なマージが発生することがなくなります。 

次のようなネストされた間隔の場合`[0,10]`、`[2,5]`、`[3,7]`、実行終了は 10 までしか増加せず、すべての開始が現在の範囲内にあるため、早期終了は発生しません。 不変条件`cur_r`すべての重複する間隔の最大の右端点であり、正確性が保証されます。 

タッチ間隔などに`[0,5]`そして`[5,10]`、条件`l <= cur_r`それらは接続されているものとして扱われるため、次のようにマージされます。`[0,10]`。 これにより、連続カバレッジ問題における境界分離規則による過小カウントが回避されます。
