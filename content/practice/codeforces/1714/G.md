 ## 解決策
 ## 問題の理解

 各エッジに値を持つルート付きツリーを処理するように求められます。 各エッジには 2 つの整数があり、$a_j$そして$b_j$。 ルート以外のノードごとに$i$、ルートからへのパスを考慮します。$i$。 させて$A_i$すべての合計になる$a_j$この道に沿って。 私たちは見つけるように求められています$r_i$、このパスの最長のプレフィックスの長さ。$b_j$プレフィックスに沿って次を超えない$A_i$。 プレフィックスの長さはエッジで測定されるため、$r_i = 0$は、プレフィックスにエッジを含めることができないことを意味します。 

入力には複数のテスト ケースが与えられ、それぞれがツリーを次のように記述します。$n$ノードと$n-1$エッジ。各エッジは親によって定義されます。$p_j$そして2つのコスト$a_j$そして$b_j$。 出力は次の配列です。$n-1$整数。非ルート ノードごとに 1 つ。 

制約は厳しいです:$n$まで可能です$2 \cdot 10^5$、との合計$n$すべてのテスト ケースでは、次の制限もあります。$2 \cdot 10^5$。 各ノードのすべてのプレフィックスを明示的に合計する素朴なアプローチは次のようになります。$O(n^2)$が遅すぎます。 テスト ケースごとのノード数が線形または線形に近いソリューションが必要です。 エッジケースはすべての場合に発生します$b_j$よりも大きい$A_i$ノードの場合、正しいプレフィックス長はゼロです。$A_i$一部のプレフィックス合計と完全に一致するため、off-by-one エラーを避けるために慎重に処理する必要があります。 

## アプローチ

 ブルートフォース手法では、ルートから各ノードまでのパスを再構築します。$i$次に、すべてのプレフィックスを反復処理して、次の合計を計算します。$b_j$、合計を超えると停止します$A_i$。 これは正しいですが、次のことが必要です$O(n^2)$最大の制約に失敗する最悪の場合の操作。 

最適化のための重要な観察は、次のプレフィックスの合計のみが必要であるということです。$b_j$根元から道沿いに。 の累積合計を格納する配列を維持すると、$b_j$現在のノードへのパスに沿った値がある場合、これらの合計をバイナリ検索して、合計が以下の最長のプレフィックスを見つけることができます。$A_i$。 ツリーはルート化されているため、深さ優先検索を使用してこれらのプレフィックス合計を構築し、累積合計を親から子に伝播できます。 各二分探索演算には時間がかかります$O(\log n)$、各ノードにアクセスするには時間がかかります$O(1)$、全体的な結果につながります$O(n \log n)$解決。 リストを使用して累積合計を DFS に保存すると、先祖に効率的にアクセスできるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | プレフィックス合計に関する DFS + 二分検索 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`prefix_b`の累積合計を保存する$b_j$根元から道沿いに。 ルート ノードの累積合計はゼロです。 配列を維持する`A`の累積合計を追跡する$a_j$根元から。 
2. ツリーを隣接リストとして構築し、子ごとにエッジ値を保存します$a_j$そして$b_j$。 これにより、ルートからの DFS トラバースが容易になります。 
3. DFS をルートから起動します。 各ノードについて$u$訪問、計算`A[u] = A[parent] + a_edge`の合計です。$a_j$根元からそこまでの道に沿って$u$。 
4. を維持します。`prefix_b`の累積和を表す配列$b_j$道沿いにあります。 お子様を訪問する場合は追加してください`prefix_b[-1] + b_edge`再帰的な DFS 呼び出しの前に配列にコピーします。 
5. 計算するには$r_i$現在のノードに対して二分探索を実行します。`prefix_b`右端のインデックスを見つけるには`idx`そのような`prefix_b[idx] <= A[i]`。 このインデックスは、最長のプレフィックスの長さと正確に一致します。 
6. 子の DFS が完了したら、次の要素から最後の要素をポップします。`prefix_b`次の兄弟の状態を元に戻して復元します。 

機能する理由: 各ノードでは、`prefix_b`配列には累積和が格納されます$b_j$根元から道沿いに。 ツリーはルート化されているため、パスは一意であり、配列は厳密に増加しています。 この配列をバイナリ検索すると、合計制約を満たす最長のプレフィックスが確実に見つかります。 DFS トラバーサルにより、各ノードが 1 回だけ訪問され、プレフィックスの合計が正しいパスを反映することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tree = [[] for _ in range(n + 1)]
        for j in range(2, n + 1):
            p, a, b = map(int, input().split())
            tree[p].append((j, a, b))

        A = [0] * (n + 1)
        res = [0] * (n + 1)
        prefix_b = [0]

        def dfs(u):
            for v, a_edge, b_edge in tree[u]:
                A[v] = A[u] + a_edge
                prefix_b.append(prefix_b[-1] + b_edge)
                # Binary search to find the longest prefix
                idx = bisect.bisect_right(prefix_b, A[v]) - 1
                res[v] = idx
                dfs(v)
                prefix_b.pop()

        dfs(1)
        print(" ".join(str(res[i]) for i in range(2, n + 1)))

if __name__ == "__main__":
    solve()
```DFS は、`prefix_b`の累積和としての配列$b_j$現在のノードへのパスに沿って。 二分探索は各ノードの最大プレフィックス長を効率的に見つけるために使用され、子を訪問した後にポップすることで兄弟トラバーサルの正しい状態が復元されます。 使用する`bisect_right`プレフィックスの合計が等しい場合を確実に処理します。`A_i`正しく。
