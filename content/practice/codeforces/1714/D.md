 ## 解決策
 ## 問題の理解

 ターゲット文字列が与えられています`t`最大 10 個のパターン文字列。 移動は、パターンを 1 つ選択し、その中にあるパターンの 1 つを選択することで構成されます。`t`、次に、その出現箇所のすべての文字を色付きとしてマークします。 キャラクターに一度色を付けると、その色は永久に維持され、重なっても元に戻されることはありません。 

目標は、文字列全体を完全にカバーすることです`t`選択したオカレンスをできるだけ少なくします。 各移動は 1 つのパターンの 1 つの出現を正確に選択するため、問題は、許可されたパターンの固定セットから最小数の部分文字列を選択することになります。`t`少なくとも 1 つの選択された部分文字列でカバーされます。 

制約は小さく、`t`は最大 100、パターンは最大 10、各パターンの長さは最大 10 です。これは、位置について 2 次または 3 次の推論が可能であることをすぐに示唆しています。`t`、すべての部分文字列をチェックするか、位置を越えて動的プログラムを実行することを伴う解決策は実行可能です。 

構造上の主な問題は、パターンが重なり合い、相互作用することです。 「常に最長の一致を取得する」または「常に左端のカバーされていない位置から開始する」という貪欲な選択が最適であるとは限りません。一致が長いと、後で総移動数が減少する構成がスキップされる可能性があるためです。 

貪欲さの微妙な失敗例は、短いパターンによってより適切な連鎖が可能になる場合に現れます。 

たとえば、次の場合`t = ababa`そしてパターンは`aba`そして`ba`、ピッキング`aba`最初に位置 1 から 3 をカバーし、そのまま残ります`ba`2 回ありますが、別の順序で重複を減らすことができます。 最適な戦略は、間隔がローカルではなくグローバルにどのように重なるかによって決まります。 

もう 1 つの重要なエッジ ケースは、不可能であることです。`t`パターンの発生によってカバーされない場合があります。 たとえば、次の場合`t = abc`そしてパターンは`{ab, bc}`、 位置`c`インデックス 3 は以下でのみカバーされます`bc`2から始まるので問題ありませんが、パターンが`{ab, cd}`、 それから`c`完全に解明され、その答えは`-1`。 

したがって、中心となるタスクは、すべての有効な出現を間隔として扱い、カバーする間隔の最小数を選択することになります。`[1, |t|]`。 

## アプローチ

 ブルート フォース ビューでは、各パターンの各出現を選択可能な間隔として扱い、間隔のすべてのサブセットを試して、文字列全体をカバーしているかどうかを確認します。 開始位置は最大で 100 個、パターンは 10 個あるため、最悪の場合でも最大で約 1000 個の間隔が存在します。 これらの間隔にわたるサブセット検索は不可能です。`2^1000`。 

より構造化されたブルート フォースは、各インデックスでの位置に対する動的プログラミングです。`i`で始まるすべての出現を試してください。`i`、接尾辞を再帰的に解決します。 これでも、遷移を注意深くメモ化しないと、指数関数的な分岐が発生します。 

重要な観察は、この問題が直線上の古典的な最小間隔をカバーする問題であるということです。 それぞれの出現は間隔として機能します`[l, r]`をカバーしたいと思います。`[1, n]`最小限の間隔で。 ただし、すべての間隔が指定されている標準バージョンとは異なり、ここではパターンから間隔が生成されますが、その生成は安価です。 

これに気づいたら、ポジションを超えて貪欲または DP を実行できます。 左から右への直接的な貪欲は、現在位置またはその前から始まり、最も右に広がる間隔を常に選択する場合に機能します。ただし、ここでは、選択された出現の実際のセットを再構築し、複数の選択肢が存在する場合の正確性を保証する必要もあります。 なぜなら`n ≤ 100`、右から左へのクリーンな DP の方が安全で正当化が簡単です。 

ポジションごとに計算します`i`で始まるサフィックスをカバーするためにできる最善のこと`i`。 各局面について、そこから始まるすべてのパターンの一致を考慮し、残りに必要な手の数を最小限にするものを選択します。

 ## アルゴリズムのチュートリアル

 まず、内部のすべてのパターンの有効な出現をすべて事前計算します。`t`。 試合ごとにペアを記録します`(l, r, pattern_id)`そのパターンをその開始位置で使用するとセグメントがカバーされることを意味します`[l, r]`。 

次に、文字列内の位置にわたる最短パスとして問題を解決します。 

1. リストを作成する`occ[l]`位置から始まるすべての間隔を保存します`l`。 現在のカバーされていない位置から始まる動きのみを考慮するため、これによりトランジションが効率的に整理されます。 
2. DP 配列を定義する`dp[i]`位置から始まるサフィックスを完全にカバーするために必要な最小移動数として`i`。 また、`parent[i]`ソリューションを再構築するためのポインター。 
3.セット`dp[n+1] = 0`空のサフィックスをカバーするには移動が必要ないためです。 
4. からの位置を処理します`n`まで`1`。 ポジションごとに`i`、初期化します`dp[i]`無限のように。 
5. インターバルごとに`(i, r, id)`で`occ[i]`、候補コストを計算します`1 + dp[r+1]`。 これが改善されれば`dp[i]`、それを保存し、その位置に記録します`i`パターンを選択します`id`そしてに移動します`r+1`。 
6. すべてのポジションを処理した後、次の場合は`dp[1]`は無限大なので、カバレッジは不可能であり、出力します。`-1`。 
7. それ以外の場合は、位置から開始して答えを再構築します`1`。 各ステップで、保存された選択に従います`(pattern_id, end_position)`、移動を出力し、次のカバーされていない位置にジャンプします。 

各遷移はカバレッジを拡張する実際の部分文字列の出現に対応するため、再構成では当然、有効な一連の操作が生成されます。 

### なぜ効果があるのか

 それぞれのポジションで`i`、DP は、次のカバーされていない位置が正確であると仮定して、最適解を計算します。`i`。 有効な解決策は、最初のカバーされていない位置またはその前で始まる何らかの出現を選択する必要があります。最適性を失うことなく、常にそのカバーされていない境界から開始するように位置をシフトできます。 これにより、きれいな分解が作成されます。 から始まる間隔を選択すると、`i`、残りの問題は独立しており、次から始まります。`r+1`。 最適な下部構造は、カバレッジを介する場合を除いて間隔が相互作用しないという事実から直接導き出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = len(t)
    m = int(input())
    s = [input().strip() for _ in range(m)]

    occ = [[] for _ in range(n + 2)]

    for idx, pat in enumerate(s):
        L = len(pat)
        for i in range(n - L + 1):
            if t[i:i+L] == pat:
                occ[i + 1].append((i + 1, i + L, idx + 1))

    INF = 10**9
    dp = [INF] * (n + 3)
    nxt = [None] * (n + 3)
    dp[n + 1] = 0

    for i in range(n, 0, -1):
        for l, r, pid in occ[i]:
            if dp[r + 1] + 1 < dp[i]:
                dp[i] = dp[r + 1] + 1
                nxt[i] = (r + 1, pid, i)

    if dp[1] >= INF:
        print(-1)
        return

    print(dp[1])
    i = 1
    ans = []
    while i <= n:
        r, pid, l = nxt[i]
        ans.append((pid, l))
        i = r

    for w, p in ans:
        print(w, p)

q = int(input())
for _ in range(q):
    solve()
```このソリューションでは、すべての出現箇所が直接部分文字列一致によって構築されるため、安全です。`|t| ≤ 100`。 各一致は、開始インデックスが 1 ベースのインデックスにシフトされた状態で保存されます。 DP は右から左に進み、セグメントを評価するときに次のようになります。`i`、すべてのサフィックス結果はすでに計算されています。 

実装でよくある落とし穴は、複数のパターンが同じ位置から始まる可能性があり、それらすべてを考慮する必要があることを忘れていることです。 もう 1 つの微妙な点は、インデックス付けです。トランジションは次から開始する必要があります。`r+1`、 ない`r`、カバレッジにはエンドポイントが含まれるためです。 

## 実用的な例

 最初のサンプルを考えてみましょう`t = bababa`模様付き`ba`そして`aba`。 

出来事を列挙します。 

| 私 | 間隔 | パターン |
 | --- | --- | --- |
 | 1 | [1,2] | ば |
 | 2 | [2,4] | アバ |
 | 4 | [4,5] | ば |
 | 2 | [2,3] | ば |

 DP は右から進みます。 

で`i = 4`、私たちは取ることができます`[4,5]`、 それで`dp[4] = 1 + dp[6] = 1`。 

で`i = 2`、一番いいのは`[2,4]`与える`1 + dp[5] = 2`。 

で`i = 1`、取る`[1,2]`につながる`1 + dp[3] = 2`、しかし、再構築を介して、サフィックス構造により、3 つの動きの最適なシーケンスに到達します。 

このトレースは、重複する間隔により複数の決定が強制される可能性があり、DP が将来の補償範囲のコストを正しく伝播することを示しています。

 ## 特殊なケース

 文字に一致するパターンがない場合は、その位置から始まる間隔が存在しないため、すぐに処理され、そのまま残ります。`dp[i]`無限で伝播不可能。 

複数の間隔が重なり合う場合でも、DP はすべての遷移を評価するため、たとえ長い間隔が魅力的であるように見えても、サフィックス コストが最適な場合にのみ選択されます。 

繰り返される単一文字列などの密に重なり合うパターンの場合、すべての位置に複数の冗長間隔があるため、DP は最小限のセグメントを正しく選択しますが、サフィックス コストにより、最大限の貪欲な拡張ではなく最小限の選択が強制されます。
