 ## 解決策
 ## 問題の理解

 桁の目標合計が与えられており、クエリごとに、桁がすべて異なり、桁の合計がその目標に等しい最小の正の整数を構築する必要があります。 これら 2 つの制約を満たすすべての有効な数値の中で、通常の数値順序で最も小さいものが必要です。 

数値は、すべての数字が最大 1 回出現する場合にのみ「有効」であるため、基本的には 1 から 9 までの個別の数字のサブセットを選択し、それらを可能な限り最小の数字に配置することになります。 ゼロを含めても合計効率に貢献せずに桁数が増加するだけであり、また構造上自然にゼロ以外の桁が優先されるため、ゼロはここでは何も最小化するのには役立ちません。 

制約は非常に小さく、合計は最大 45 で、テスト ケースの数は最大 45 です。 数字のサブセットに対する総当り検索は、理論的には実行可能です。$2^9 = 512$ただし、順序付けによって最小数が生成されることも確認する必要があります。これにより、サブセットごとに組み合わせチェックが追加されます。 

素朴なアプローチでは、合計を一致させるために、並べ替えや桁のバックトラックを試行する可能性があります。 それは正しいのですが、順序には決定的な最適な選択肢があるにもかかわらず、順序だけが異なる順列を不必要に探索する危険があります。 もう 1 つの潜在的な間違いは、一意性制約を使用して正確に合計に到達するには、より大きな桁が必要になる可能性があることを考慮せずに、貪欲に最小の桁を最初に取得することです。 

微妙なエッジ ケースは、合計が 45 など大きい場合です。小さい桁を最初に詰めようとする貪欲なアプローチは、重複なしでは必要な合計に到達できないため失敗します。たとえば、9 を繰り返し使用します。正しい構築では、一意性と合計の実現可能性のバランスを取る必要があります。 

## アプローチ

 ブルート フォース ビューでは、1 から 9 までの数字のすべてのサブセットを考慮し、その合計がターゲットと等しいかどうかを確認し、すべての有効なサブセットの中から数字を並べ替えて数値として解釈することで最小の数値を構築します。 これは検索空間が小さいため機能しますが、それでも 512 個のサブセットを反復処理して合計を繰り返し計算する必要があり、構造を考えると不要です。 

重要な観察は、この問題は、合計が正確に一致する個別の数字を選択することと同等であるということです。$s$を作成し、結果の数が最小になるように昇順に並べます。 数字のセットが固定されると、辞書編集上の値と数値を同時に最小化するには、より小さい数字を先に表示する必要があるため、最良の配置は常に昇順にソートされます。 

これにより、問題は強力な単調構造を持つサブセット選択に帰着します。 すべてのサブセットを探索する代わりに、最大の桁から下に向かって貪欲に答えを構築できます。 9 から 1 までの数字を試し、残りの合計を超えない場合は数字を含めます。 これが機能するのは、より大きな桁を早めに選択することで、残りの小さな桁に対する柔軟性が維持され、高価値の寄与から最初に桁数を確実に最小化できるためです。 

貪欲なプロセスは、常により多くの桁よりも少ない桁を優先し、同じカーディナリティの中で、より小さい桁を先に配置するとより小さい数値が得られるため、最適です。 降順選択により、45 までの合計はこの方法で選択された個別の数字に一意に分解できるため、実行可能な表現を決して見逃すことがなくなります。

 ## アルゴリズムのチュートリアル

 1. 数字 9 から開始して、残りの合計を維持しながら 1 まで下に移動します。$s$。 このようにするのは、桁が大きくなると必要な桁数が減り、最終的な数値を最小限に抑えるのに有利になるためです。 
2.各桁ごとに$d$、どうかを確認してください$d \leq s$。 そうであれば、この数字を選択してからそれを引きます。$s$。 これにより、選択されたすべての数字が正確に寄与し、残りの必要な合計に違反しないことが保証されます。 
3. すべての桁が考慮されるまで、このプロセスを続けます。 最後に、残りの合計がゼロになるか、有効な組み合わせが存在しません。 制約を考慮すると$s \le 45$、有効な分解は常に存在します。 
4. 選択したすべての数字を収集します。 これらの数字は、個別の値と正しい合計を持つ有効なサブセットを形成します。 
5. 選択した数字を昇順に並べ替えます。 この手順が必要なのは、実現可能性を考慮して降順で数字を貪欲に選択しましたが、最小の数値には昇順の配置が必要であるためです。 
6. ソートされた数字の連結を答えとして出力します。 

### なぜ効果があるのか

 アルゴリズムは、正確に合計する数字のサブセットを構築します。$s$、可能な場合は常に大きな桁を好みます。 これにより、桁数が大きくなると要素あたりの合計がより多くカバーされるため、結果の桁数が最小限に抑えられます。 サブセットが固定されたら、それを昇順に並べ替えると、その桁のマルチセットの可能な最小の数値が得られます。 代替サブセットでは、より多くの桁が使用されるか、より大きな桁がより小さな桁に置き換えられます。これにより、追加の桁が強制的に含まれ、全体の数値が大きくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = int(input())
    
    digits = []
    
    for d in range(9, 0, -1):
        if d <= s:
            digits.append(d)
            s -= d
    
    digits.sort()
    print("".join(map(str, digits)))
```実装は貪欲な構築に直接続きます。 9 から 1 まで繰り返し、可能な限り桁を減算します。 これにより、利用可能な最大の桁を最初に使用して合計を効率的にパックできるようになります。 貪欲な選択順序は最小化に必要な最終的な数値順序ではないため、セットを構築した後は並べ替えが不可欠です。 

よくある間違いは、並べ替え手順をスキップし、逆の選択順序で数字を出力することです。 これにより有効な合計が生成されますが、最小値は生成されません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = int(input())
        digits = []
        for d in range(9, 0, -1):
            if d <= s:
                digits.append(d)
                s -= d
        digits.sort()
        out.append("".join(map(str, digits)))
    return "\n".join(out)

# custom cases

assert run("1\n9\n") == "9"
assert run("1\n17\n") == "89"
assert run("1\n2\n") == "2"

 ## 特殊なケース

 最小入力の場合$s = 1$の場合、アルゴリズムは 9 から下方向に反復され、1 を除くすべての数字を拒否し、数字 1 のみを選択します。並べ替えは簡単で、出力は 1 です。 

のような最大に近いケースの場合、$s = 45$、合計が 45 と正確に一致するため、9 から 1 までのすべての数字が選択されます。結果のセットは {9,8,7,6,5,4,3,2,1} で、並べ替えにより 123456789 が生成されます。数字がスキップされないため、アルゴリズムはこれをきれいに処理します。 

合計によって次のような非自明な組み合わせが強制される場合$s = 17$の場合、貪欲なプロセスは最初に 9 を選択し、8 を残してから、正確に 8 を選択して、{9,8} を生成します。 並べ替えると 89 が得られますが、これは最適です。なぜなら、他の方法ではより多くの桁が必要になるため、より大きな数値が必要になるからです。
