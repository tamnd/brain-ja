 ## 解決策
 ## 問題の理解

 固定数の頂点と、頂点 1、2、3 間の 3 つの特定の距離制約を持つルートなしツリーを構築するように求められます。各テスト ケースでは、次の 4 つの整数が提供されます。$n$そしてペアごとの距離$d_{12}$、$d_{23}$、 そして$d_{31}$。 タスクは、これらの距離を満たす木が存在するかどうかを判断し、存在する場合はそのような木のエッジを出力することです。 

ある木$n$頂点は正確に持っています$n-1$エッジがあり、サイクルがありません。 距離$d_{12}, d_{23}, d_{31}$頂点 1、2、および 3 を接続するパスに制約を定義します。ツリーには任意の 2 つの頂点間に一意のパスがあるため、これらの距離によってこれら 3 つの頂点の相対的なレイアウトが一意に決まります。 

境界は次のことを示します$n$最大 200,000、最大 10,000 のテスト ケースがあり、すべての合計$n$テスト ケース全体の数は 200,000 に制限されています。 これにより、線形よりも悪いアルゴリズムは排除されます。$n$テストケースごとに。 すべてのツリー トポロジを明示的に試す余裕はありません。 指定された距離に基づいて直接構築する必要があります。 

エッジケースは、距離が三角不等式を満たさない場合に発生します。 たとえば、次の場合$d_{12} + d_{23} < d_{31}$の場合、1 から 3 までのパスは少なくとも 2 を通るパスの合計と同じ長さでなければならないため、これらの距離を満たす木はありません。小さな木も制約を作成します。 と$n=3$、3 つの距離すべての合計が、単一のパスを形成する正確に 2 つのエッジになる必要があります。 

たとえば、$n=4$そして距離$d_{12}=3, d_{23}=1, d_{31}=1$の場合、ツリー構造に違反せずに距離を調整できないため、パスに沿って頂点を配置しようとする単純な試みは失敗します。 

## アプローチ

 ブルートフォース手法では、すべてのツリー形状を試し、1、2、3 の間の距離が要件を満たしているかどうかを確認します。 これは、木の数が多いため、組み合わせ的に爆発的です。$n$頂点は超指数関数的に増加します。 すべてのツリーを生成する場合でも、$n=20$実現不可能でしょう。 

重要な洞察は、どのツリーでも 3 つの頂点 1、2、3 が「パス」または「スター状」構造のいずれかを形成する必要があるということです。 パスのシナリオでは、1 つの頂点が中央にあり、他の 2 つの頂点を接続しており、距離は次の条件を満たす必要があります。$d_{12} + d_{23} = d_{31}$または循環順列の 1 つ。 任意の 2 つの距離の合計が 3 番目の距離と等しい場合、頂点を 1 つの線上に配置し、残りの距離を追加できます。$n-3$パスに沿った任意の場所に取り付けられた葉としてのノード。 2 つの距離の合計が 3 番目の距離と等しくない場合、考えられる唯一の形状は、3 つすべてを接続する中央の頂点であり、Y 字型のツリーを形成します。 この場合、距離は次の条件を満たす必要があります。$(d_{12} + d_{23} + d_{31}) \mod 2 = 0$そして、Y の腕に沿った距離を分割するための派生式。 

この洞察により、すべてのツリーをチェックすることから、単に実現可能な配置をチェックし、パスまたは Y 字型を直接構築することに問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. まず、距離が三角不等式を満たすかどうかを確認します。各距離は、他の 2 つの距離の合計以下である必要があります。 そうでない場合は、直ちに NO を出力します。 
2. 単純なパス レイアウトの形成を試みます。 距離の 1 つが他の 2 つの距離の合計と等しいかどうかを確認します。 たとえば、次の場合$d_{12} + d_{23} = d_{31}$、頂点 2 は直線パスに沿って 1 と 3 の間にあります。 同様に、他の順列も確認します。 このような関係が存在する場合、パスを構築し、残りの頂点をリーフとしてアタッチできます。 
3. パスのレイアウトが機能しない場合は、Y 字型のツリーを形成してみてください。 中心頂点から「腕の長さ」を計算します。$c$以下を使用して 1、2、および 3 に変換します。$$x = \frac{d_{12} + d_{31} - d_{23}}{2}, \quad y = \frac{d_{12} + d_{23} - d_{31}}{2}, \quad z = \frac{d_{23} + d_{31} - d_{12}}{2}$$いずれかの場合$x, y, z$が負または非整数の場合、Y 字型は不可能です。 
4. アームの端に頂点 1、2、3 を配置します。 中央の頂点を通ってアームを接続します。 残りを取り付ける$n-3$1、2、3 の間のパスの一意性を侵害することなく、頂点をツリー上の任意の頂点へのリーフとして送信します。 
5. YES を出力し、エッジを印刷します。 

機能する理由: どの木も 1、2、3 を接続するパスであるか、それらを接続する中心頂点を持っています。 導出された公式は、正確な距離を維持する整数のアーム長を保証します。 残りの頂点はいつでもリーフとして追加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, d12, d23, d31 = map(int, input().split())

        # Attempt path-based layout
        path_found = False
        for a, b, c in [(d12, d23, d31), (d23, d31, d12), (d31, d12, d23)]:
            if a + b == c:
                path_found = True
                edges = []
                nxt = 4
                # build path a-b-c
                v = [1, 2, 3]
                if (a, b, c) != (d12, d23, d31):
                    # permute so that 1,2,3 correspond to a-b-c
                    if (a, b, c) == (d23, d31, d12):
                        v = [2,3,1]
                    else:
                        v = [3,1,2]
                # build path from v[0] to v[1] length a
                last = v[0]
                for _ in range(a-1):
                    edges.append((last, nxt))
                    last = nxt
                    nxt += 1
                edges.append((last, v[1]))
                last = v[1]
                # build path from v[1] to v[2] length b
                for _ in range(b-1):
                    edges.append((last, nxt))
                    last = nxt
                    nxt += 1
                edges.append((last, v[2]))
                # attach remaining vertices
                for i in range(n - (len(edges)+1)):
                    edges.append((1, nxt))
                    nxt += 1
                print("YES")
                for u, w in edges:
                    print(u, w)
                break
        if path_found:
            continue

        # attempt Y-shaped tree
        x = (d12 + d31 - d23) // 2
        y = (d12 + d23 - d31) // 2
        z = (d23 + d31 - d12) // 2
        if (d12 + d31 - d23) % 2 or (d12 + d23 - d31) % 2 or (d23 + d31 - d12) % 2 or min(x, y, z) < 0:
            print("NO")
            continue
        edges = []
        nxt = 4
        center = 4
        # connect central vertex
        edges.append((center,1))
        last = center
        # arm to 2
        prev = last
        for _ in range(x):
            edges.append((prev,nxt))
            prev = nxt
            nxt += 1
        edges.append((prev,2))
        # arm to 3
        prev = last
        for _ in range(z):
            edges.append((prev,nxt))
            prev = nxt
            nxt += 1
        edges.append((prev,3))
        # attach remaining vertices
        used = nxt-1
        for i in range(used, n):
            edges.append((1, nxt))
            nxt += 1
        print("YES")
        for u, w in edges:
            print(u, w)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、距離がパス レイアウトを許可するかどうかを確認します。 1、2、3 がパスの正しい終点に対応するように、頂点を注意深く並べ替えます。 パスの構築では中間エッジに一時的な頂点を使用し、カウンタをインクリメントして新しい頂点番号を割り当てます。 パスが不可能な場合、コードは Y 字型レイアウトのアームの長さを計算し、導出されたすべての長さが負でない整数であることを確認します。 残りのノードは、ツリーのプロパティを維持するために葉として接続されます。
