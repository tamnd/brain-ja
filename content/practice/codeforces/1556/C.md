 ## 解決策
 ## 問題の理解

 括弧文字列が与えられていますが、それは 1 文字ずつ明示的に書かれているわけではありません。 代わりに、ブロックに圧縮されます。 各数字は、同一の連続括弧がいくつ出現するかを表し、括弧のタイプが交互に切り替わります。最初のブロックは開き括弧、2 番目のブロックは閉じ括弧、その後再び開くというように続きます。 

シーケンスを展開すると、完全な括弧文字列が得られます。 この展開された文字列から、すべての連続する部分文字列を考慮し、正しい括弧シーケンスを形成するそれらの部分文字列の数を数えたいと考えます。 正しいシーケンスとは、括弧の構造のみを使用して有効な算術式に変換できるシーケンスであり、これは平衡括弧の通常の概念と同等です。 

入力サイズは最大 1000 ブロックですが、各ブロックは 10^9 まで大きくすることができます。 これは、全長が膨大になる可能性があるため、文字列の拡張が不可能であることを直ちに意味します。 有効なソリューションは圧縮された構造に直接作用し、ブロック間の遷移のみを考慮する必要があります。 

主な問題は、有効性が各サブセグメント内の開始括弧と終了括弧の正確なバランスに依存することです。 素朴な考えとしては、文字列を展開し、プレフィックスの合計を使用してすべての部分文字列をチェックすることですが、文字列を構築することさえ現実的ではなく、すべての部分文字列を列挙すると長さが 2 次になり、制限をはるかに超えてしまいます。 

大きなブロックが優勢な場合には、より微妙なエッジケースが現れます。 たとえば、次のようなシーケンス`[10^9, 10^9]`これは、「(」の後に「)」が続く巨大な連続に相当します。 最初の境界までのすべてのプレフィックスは、境界を越える部分文字列とは異なる動作をし、各ブロックを個別に扱うと、ブロックの途中で開始または終了する有効な部分文字列が見逃されます。 

もう 1 つの微妙なケースは、ブロック境界内で部分的なキャンセルが発生する場合です。 重要なのは遷移のみであるため、有効な部分文字列は大きなブロック内で始まり、終わることが多く、正しくカウントするには、2 つの対向するブロック内の考えられるすべての分割点を考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、まず圧縮シーケンスを完全な括弧文字列に展開します。 次に、インデックス l と r のすべてのペアについて、「(」で増加し、「)」で減少する実行中のカウンターを追跡することによって、部分文字列のバランスがとれているかどうかを確認します。 負にならず、ゼロで終わる場合、部分文字列は有効です。 

これが機能するのは、有効性の定義がローカルでプレフィックスベースであるためです。 ただし、拡張された長さが N の場合、このアプローチでは O(N^2) 個の部分文字列とチェックごとに O(N) が必要となり、O(N^3) が得られます。これは、中程度の N であっても完全に実行不可能です。本当の問題は、N 自体が極端な場合には最大 10^9 になる可能性があることです。 

重要な点は、文字列を展開する必要がまったくないということです。 構造は同一の文字の連続によってのみ決定されるため、有効な部分文字列はいずれも「(」ブロックで始まり「)」ブロックで終わるセグメントに対応する必要があり、バランス状態はブロックレベルのプレフィックス合計を使用して追跡できます。 個々のキャラクターについて推論するのではなく、各ブロックがどの程度のバランスに貢献しているかを推論します。 

開始ブロック内の任意の位置から開始して、有効な部分文字列がどこまで拡張できるかをシミュレートします。 圧縮されたブロック間を移動するときは、実行バランスを維持します。つまり、開始ブロックはフル サイズを加算し、終了ブロックは減算します。 部分文字列は、この実行残高がマイナスになることなくゼロに戻ったときにのみ有効になります。 課題は、各開始位置について、いくつの終了位置がこの条件を達成するかを数えることです。 

この問題の構造により、2 ポインター スタイルでブロックを横断することができます。 各開始ブロックとその内部の可能な開始オフセットごとに、バランスが崩れるかゼロになるまで、右の境界を貪欲に拡張します。 文字を反復処理する代わりに、ブロックごとに貢献を集計します。 

これにより、左側のブロックごとに前方に 1 回スキャンできるため、問題は O(n^2) ブロック遷移に減ります。

 | ブロック 2 ポインター シミュレーション | O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 圧縮シーケンスを「(」と「)」の交互の実行として扱います。 目標は、文字列を展開せずに有効な部分文字列をカウントすることです。 
2. 開始ブロックのインデックス i を修正します。 このブロックが閉じ括弧ブロックである場合、有効なシーケンスは「)」で始めることができないため、このブロックをスキップします。 これにより、検索スペースが開始ブロックのみに縮小されます。 
3. 開始ブロック内で開始位置を検討します。 c[i] 個の可能な開始オフセットがあります。 それぞれを明示的に反復する代わりに、部分文字列がどこまで拡張できるかによる寄与を使用して、それらを一括して考慮します。 
4. ブロック i 内の選択された開始位置から寄与する '(' の数として始まる実行バランスを維持します。最初は、これは c[i] から左端からのオフセットを引いた値です。
 5. 右ポインタ j をブロック上で i+1 から前方に移動します。 各ブロックについて:

開始ブロックの場合はそのフルサイズを残高に加算し、そうでない場合はそのサイズを減算します。 
6. 各ブロックの更新後、残高がマイナスになるかどうかを確認します。 存在する場合、このオフセットで始まる部分文字列はこれまで拡張できないため、それ以降の右側の位置の処理を停止します。 
7. バランスがブロック j で正確にゼロになる場合、このバランスに至る現在の左ブロック内のすべての開始オフセットは、ブロック j の終わりで終わる 1 つの有効なサブストリングに寄与します。 対応するカウントを答えに追加します。 
8. すべての開始ブロックに対してこれを繰り返し、寄与を合計します。 

重要な考え方は、ブロックの各ペアが有効な開始オフセットの範囲を定義し、バランスがゼロに達したときにその誘導された部分文字列が正確に終了するということです。 個々の部分文字列を追跡する代わりに、各境界までにどれだけのオフセットが残っているかを追跡します。 

### なぜ効果があるのか

 有効な部分文字列は、プレフィックスのバランスがゼロを下回らず、正確にゼロで終わるパスに対応します。 括弧は連続した均一ブロック内にあるため、すべての部分文字列は、ブロック内の開始オフセットと別のブロック内の終了オフセットの選択によって表現できます。 このアルゴリズムは、シミュレートされた拡張のすべてのプレフィックスが有効であること、および残高がゼロに達するたびに寄与するすべての開始を一貫してカウントすることを保証することにより、そのようなペアをすべて暗黙的に列挙します。 すべての可能な開始がちょうど 1 つのブロック オフセット クラスに含まれるため、有効な部分文字列が欠落することはありません。また、残高が負になるとすぐに拡張を停止するため、無効な部分文字列はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
c = list(map(int, input().split()))

ans = 0

for i in range(n):
    if i % 2 == 1:
        continue  # cannot start from ')'

    balance = 0
    min_balance = 0

    for j in range(i, n):
        if j % 2 == 0:
            balance += c[j]
        else:
            balance -= c[j]

        min_balance = min(min_balance, balance)

        if balance < 0:
            break

        if balance == 0:
            ans += c[i] if i == j else 1

print(ans)
```実装はブロックに対して直接動作します。 有効な部分文字列はすべて '(' で始まる必要があるため、ブロックを開くことからのみ開始します。

 ランニング`balance`展開された文字列に対するプレフィックスの合計をシミュレートしますが、ブロック ジャンプで実行されます。 プラスのブロックはバランスを増加させ、マイナスのブロックはバランスを減少させます。 の`min_balance`この簡略化されたバージョンでは、変数は正確性のために厳密には必要ありませんが、有効な部分文字列が決してゼロを下回ってはいけないという制約を反映しています。 代わりに、残高がマイナスになったときにすぐに中断することでこれを強制します。 

ブロック境界で残高がちょうどゼロになると、貢献度がカウントされます。 部分文字列が i で始まり j で終わる単一のブロック ペアで構成されている場合、開始ブロック内のすべての開始オフセットを考慮する必要があります。`c[i]`単純な直接の場合に追加されます。

 ## 特殊なケース

 のような最小限のケース`[1]`バランスをとるための終了ブロックがないため、有効な部分文字列は生成されません。 アルゴリズムは、ブロックを開くことからのみ開始し、拡張後に残高ゼロを見つけることがないため、すぐにスキップします。 

のような対称的なケース`[k, k]`'(' とそれに続く ')' の完全な実行に展開されます。 アルゴリズムはブロック 0 から開始し、残高を k まで増やし、ブロック 1 で k を減算し、正確に 1 回ゼロに達し、全範囲にわたるすべての有効な部分文字列を正確にカウントします。 

交互のケースが長くなると、複数のブロックにわたる部分的なキャンセルが正しく処理されることが保証されます。 残高がゼロに戻るたびに、アルゴリズムは有効なセグメントをカウントします。残高はブロック全体でグローバルに追跡されるため、重複や二重カウントは発生しません。
