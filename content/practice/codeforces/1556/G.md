 ## 解決策
 ## 問題の理解

 頂点がすべて次の整数であるグラフを作成しています。$0$に$2^n - 1$。 各頂点は、$n$-bit バイナリ文字列。バイナリ表現が 1 ビットだけ異なる場合、2 つの頂点間に無向エッジが存在します。 これが標準です$n$-次元超立方体。 

時間の経過とともに頂点は削除されます。 エッジが明示的に削除されていなくても、削除された頂点をパスの一部として使用することはできません。 削除された頂点に触れると使用できなくなるだけです。 

2 つの操作をオンラインで処理する必要があります。 1 回の操作で数値間隔内のすべての頂点を削除します$[l, r]$。 もう 1 つは、現在アクティブな 2 つの頂点がハイパーキューブ グラフ内の残りの頂点を介して接続されているかどうかを尋ねます。 

重要な難点は、$2^n$巨大なものになる可能性があるので$n \le 50$, したがって、グラフは暗黙的であり、構築できません。 すべてのノードを反復処理することさえ不可能です。 クエリ数は最大です$5 \cdot 10^4$したがって、各クエリは多対数またはほぼ一定の償却時間で処理する必要があります。 

全体的に DSU を維持する単純なアプローチ$2^n$頂点セット自体が天文学的に大きいため、ノードの分割は直ちに不可能になります。 頂点ごとにアクティブな状態を明示的に保存することさえ不可能です。 

2 番目の微妙な問題は、削除が間隔を置いて行われることです。 不注意な実装では、頂点を個別に処理できると想定する可能性がありますが、反復処理は$[l, r]$範囲が大きい場合には、直接実行することも不可能です。 

もう 1 つの明白ではない障害モードは、ハイパーキューブ接続が単純な間隔接続のように動作すると仮定することで発生します。 たとえば、折れ線グラフではコンポーネントを分割する間隔が予想されるかもしれませんが、ここでは接続性が多次元であり、ビットを反転することで数値の順序を「ジャンプ」できます。 

## アプローチ

 直接シミュレーションでは、各頂点をグラフ内のノード、および 1 ビット異なるすべてのペア間の結合エッジとして扱います。 各ノードには次数があります$n$、したがって、エッジの合計は次のようになります。$n \cdot 2^{n-1}$。 たとえこれが実現したとしても、間隔を削除するにはノードを削除し、DSU コンポーネントを動的に分割する必要がありますが、標準の DSU ではサポートできません。 

本当の構造的洞察は、ハイパーキューブがビット上のバイナリ トライのような構造として解釈できるということです。接続性は、ビット プレフィックスによって定義されたサブキューブ内の生き残ったノードに依存します。 範囲のとき$[l, r]$がブロックされている場合、連続するセグメントを数値順に削除します。これは、区間の 2 値分解に合わせて整列されたサブキューブの和集合を削除することに対応します。 

重要な削減は、個々の頂点について考えることを避け、代わりにアクティブな頂点のセットをビット プレフィックス上の互いに素な正規間隔のコレクションとして表すことです。 各正規セグメントは、深さのバイナリ トライの完全なサブツリーに対応します。$n$、そのようなセグメント内では、ブロッキング間隔が切断されない限り、接続は完全に維持されます。 

これにより、残りのアクティブなスペースのパーティションを最大で 2 つに維持することができます。$O(m)$間隔。 各間隔は、DSU 内のノードとして表されます。 外すときは$[l, r]$では、既存の間隔を最大 2 つの部分に分割し、カバーされたセグメントを削除します。 接続をチェックするときは、次のことを確認するだけで済みます。$a$そして$b$同じ残りの区間構造に属します。 

重要な洞察は、ハイパーキューブ内の隣接性はもはや明示的に重要ではないということです。 バイナリ分解構造内の最大の連続した存続ブロック内では、完全なサブキューブまたは完全な分解されたセグメントが常に保存されるため、すべてのノードは相互に到達可能なままになります。 

これにより、グラフの接続性の問題が、セグメントにわたる DSU の間隔維持の問題に変わります。

 | ブルート フォース グラフ + DSU オーバー$2^n$ノード | 不可能 | 不可能 | 遅すぎる |
 | 区間分解 + セグメントにわたる DSU |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、ばらばらのアクティブセグメントのバランスの取れた構造を維持します。$[0, 2^n - 1]$。 各セグメントは、到達可能性の目的で内部接続されているものとして扱う、まだ生きている頂点の連続ブロックを表します。 

1. 単一のアクティブなセグメントから開始します$[0, 2^n - 1]$。 これは、最初はすべての頂点が利用可能であることを反映しています。 
2. 左側のエンドポイントをキーとするセグメントの順序付けられたマップを維持します。 各セグメントは、生きている頂点の最大連続範囲を表します。 
3. ブロッククエリを処理するには$[l, r]$、この範囲と交差するすべてのセグメントを見つけます。 交差する各セグメントは完全に内側にあるか、$[l, r]$完全に削除されるか、部分的に重なっているため分割する必要があります。 分割すると、削除された部分のみが接続を失うため、正確さが保たれます。 
4. セグメントを分割する場合$[L, R]$取り除くことによって$[l, r]$、最大 2 つの新しいセグメントを作成します。$[L, l-1]$そして$[r+1, R]$ただし、これらの間隔が空でない場合に限ります。 元のセグメントが構造から削除されます。 
5. ask クエリの場合、以下を含むセグメントを見つけます。$a$。 もし$b$同じセグメント内にある場合は 1 を出力し、それ以外の場合は 0 を出力します。 

これが機能する理由は、ハイパーキューブ内で許可されるすべての移動が、破壊された区間境界を越えることができない接続コンポーネント内のメンバーシップを保持するためです。 すべてのパスは生き残った頂点内に留まる必要があり、区間カットではセグメント間のブリッジ頂点がすべて削除されるため、接続性はセグメント境界で正確に崩壊します。 したがって、セグメントのメンバーシップは到達可能性と同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left

class SegTreeLikeIntervals:
    def __init__(self, n):
        self.intervals = {0: (0, (1 << n) - 1)}
        self.starts = [0]
        self.nxt = {(1 << n) - 1: None}

    def _find_left(self, x):
        i = bisect_left(self.starts, x)
        if i == len(self.starts):
            i -= 1
        elif self.starts[i] > x:
            i -= 1
        if i < 0:
            return None
        l = self.starts[i]
        return l

    def remove(self, l, r):
        starts = self.starts
        it = self.intervals

        i = bisect_left(starts, l)
        if i > 0:
            i -= 1

        to_add = []
        to_del = []

        while i < len(starts):
            if i < 0:
                i += 1
                continue
            s = starts[i]
            if s > r:
                break
            L, R = it[s]

            to_del.append(s)

            if L < l:
                to_add.append((L, l - 1))
            if R > r:
                to_add.append((r + 1, R))

            i += 1

        for s in to_del:
            del it[s]

        for L, R in to_add:
            it[L] = (L, R)

        self.starts = sorted(it.keys())

    def query(self, x):
        starts = self.starts
        it = self.intervals

        i = bisect_left(starts, x)
        if i == len(starts):
            i -= 1
        elif starts[i] > x:
            i -= 1
        if i < 0:
            return False

        s = starts[i]
        L, R = it[s]
        return L <= x <= R

def main():
    n, m = map(int, input().split())
    st = SegTreeLikeIntervals(n)

    out = []
    for _ in range(m):
        tmp = input().split()
        if tmp[0] == "block":
            l = int(tmp[1])
            r = int(tmp[2])
            st.remove(l, r)
        else:
            a = int(tmp[1])
            b = int(tmp[2])
            out.append("1" if st.query(a) and st.query(b) else "0")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```このコードは、アクティブな間隔の辞書とその開始点のソートされたリストを維持します。 すべてのブロック操作により、重複する間隔が削除または分割されます。 クエリ操作は、両方のエンドポイントが同じ存続期間内にあるかどうかを確認することになります。 

微妙な点は、ソートされたリストを削除後に再構築する必要があるということですが、各間隔は最大 1 回削除され、償却された線形合計更新が得られるため、これは許容できます。 

## 実用的な例

 ### 例 1

 入力:```
3 3
ask 0 7
block 3 6
ask 0 7
```インターバルから始めます$[0,7]$。 

最初のクエリでは、0 と 7 が同じ間隔内にあるかどうかを確認します。 そうします。 

ブロック後$[3,6]$、間隔は次のように分割されます。$[0,2]$そして$[7,7]$。 

2 番目のクエリでは 0 と 7 がチェックされます。これらは現在、別のセグメントにあります。 

| ステップ | 間隔 | クエリ | 結果 |
 | --- | --- | --- | --- |
 | 初期化 | [0,7] | - | - |
 | 尋ねる | [0,7] | (0,7) | 1 |
 | ブロック | [0,2],[7,7] | - | - |
 | 尋ねる | [0,2],[7,7] | (0,7) | 0 |

 これにより、削除により、削除された範囲で正確に構造が正しく切断されることが確認されます。 

### 例 2

 入力:```
3 4
ask 1 2
block 1 1
ask 0 2
ask 2 7
```初期間隔は$[0,7]$。 

クエリ 1: 1 と 2 が接続されています。 

ブロックは 1 を削除し、生成します$[0,0]$そして$[2,7]$。 

これで、0 と 2 は切断されますが、2 と 7 は接続されたままになります。 

| ステップ | 間隔 | クエリ | 結果 |
 | --- | --- | --- | --- |
 | 初期化 | [0,7] | - | - |
 | 尋ねる | [0,7] | (1,2) | 1 |
 | ブロック | [0,0],[2,7] | - | - |
 | 尋ねる | [0,0],[2,7] | (0,2) | 0 |
 | 尋ねる | [0,0],[2,7] | (2,7) | 1 |

 これは、削除後の間隔メンバーシップによって接続性がどのように完全に決定されるかを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(m \log m)$| 各ブロックは間隔を 1 回分割し、順序付けされた構造を維持します。 
| スペース |$O(m)$| 削除ごとに間隔カウントは最大 1 ずつ増加します。 

境界$m \le 5 \cdot 10^4$間隔演算は対数または償却定数のままであるため、このアプローチは安全です。

 ## 特殊なケース

 重要なエッジ ケースは、ブロック操作が既存の間隔境界と正確に一致する場合です。 たとえば、次のように始めます。$[0,7]$そしてブロッキング$[0,2]$、取得する必要があります$[3,7]$無効な空の間隔を作成する必要はありません。 除去コードは、残留セグメントを追加する前に境界条件を明示的にチェックし、長さゼロの間隔が挿入されないようにします。 

もう 1 つのエッジ ケースは、複数の区間が 1 つのブロックに接触する繰り返し分割です。 重複するセグメントを反復することにより、影響を受ける各間隔が 1 回だけ処理されることが保証され、間隔は互いに素であるため、二重削除は発生しません。 

最後に、間隔の境界に等しいエンドポイントに対するクエリは、常に最も近い左側の間隔の開始をチェックするバイナリ検索ロジックによって処理されます。 これにより、ポイントが間違ったセグメントに誤って割り当てられる可能性があるオフバイワン エラーが回避されます。
