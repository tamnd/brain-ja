 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、隣接する要素を交換することができます。 目標は、隣接する 2 つの要素が同じパリティを共有しないように配列を再配置することです。つまり、偶数と奇数の交互のパターンが必要になります。 

各スワップでは、隣り合う 2 つの要素のみが交換されるため、要素を移動するコストは、要素が移動する距離によって異なります。 タスクは、有効な交互パリティ配置に到達するために必要なそのような隣接スワップの最小数を見つけるか、そのような配置を形成できないと判断することです。 

ソリューションを形成する主な制約はサイズです。すべてのテスト ケースにわたる要素の合計数は最大 100,000 です。 これにより、スワップを明示的にシミュレートしたり、配置の並べ替えを試みたりするアプローチは除外されます。 バブルのようなロジックで要素をシフトすると二次関数の動作が低下する可能性があるため、テスト ケースごとに O(n²) であっても遅すぎます。 

偶数と奇数のカウントが大きく異なる場合、微妙な問題が発生します。 交互配列が存在するには、カウントの違いが最大 1 でなければなりません。 これに違反すると、スワップに関係なく、いかなる取り決めも機能しません。 たとえば、`[2, 4, 6, 8, 1]`、偶数が 4 つ、奇数が 1 つあり、どのような配置でも少なくとも 2 つの偶数が隣接することになります。 

もう 1 つのエッジ ケースは、配列がすでに有効である場合です。 その場合、答えはゼロとなり、要素をやみくもに移動する貪欲なスワッピング手法では、不必要なスワップが誤って導入される可能性があります。 

## アプローチ

 強引なアイデアは、スワップをシミュレートすることです。配列を繰り返しスキャンし、パリティ交互に違反するたびに隣接する要素を交換し、違反がなくなるまで継続します。 これは基本的に、配列を有効なパリティ パターンにバブルソートすることです。 これは正しいですが、各要素が配列全体を移動する必要がある可能性があるため、最悪の場合は O(n²) スワップがかかる可能性があります。 

重要な観察は、問題は値に関するものではなく、パリティ クラスの位置に関するものであるということです。 偶数で始まるか奇数で始まるターゲットの交互パターンを修正したら、各パリティ要素が割り当てられた位置に到達するまでにどれだけ移動する必要があるかを測定するだけで済みます。 

開始パリティを固定する場合、たとえばインデックス 0 であっても、すべての偶数要素がインデックス 0、2、4 などを占有する必要があります。 一連の項目を行内のターゲット位置に移動するために必要な隣接スワップの最小数は、現在の位置とターゲット位置をソートした場合のそれらの間の絶対的な差の合計です。 これにより、問題は 2 つの候補パターンと単純なコスト計算に減ります。 

両方の有効な開始構成 (可能な場合) のコストを計算し、最小値を採用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 隣接スワップシミュレーション | O(n²) | お(1) | 遅すぎる |
 | 貪欲な位置マッチング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を偶数値要素と奇数値要素のインデックスに分割します。 

1. 偶数と奇数を数えます。 もし`abs(evens - odds) > 1`、交互配置が存在しないため、-1 を返します。 これは、スワップ電力とは独立した構造的な制約です。 
2. 元の配列内の偶数の位置と奇数の位置という 2 つのリストを作成します。 
3. 偶数がインデックス 0 から始まる場合を考えてみましょう。 

実現可能性をチェックします。これには次のことが必要です`evens >= odds`。 そうでない場合、この構成は不可能です。 
4. 以下を照合して、この構成のコストを計算します。 

偶数位置 → 対象スロット`[0, 2, 4, ...]`各偶数要素は対応するスロットに順番に割り当てられ、絶対的な差を合計します。 
5. 奇数がインデックス 0 から始まる、つまり、奇数が偶数のインデックスを占めると仮定して、同じ計算を繰り返します。 
6. 有効な構成の中での最小コストを返します。 

### なぜ効果があるのか

 パリティの割り当てが固定されると、同じパリティの要素は交換可能になります。 重要なのは、最終的に占有されたインデックスだけです。 隣接するスワップを最小限に抑えるための最適な戦略は、ソートされたペアリングの下で​​インデックス空間の総変位を最小限に抑えることと同じです。 これにより、問題は回線上の最適な割り当てのインスタンスに還元されます。交差した割り当てでは総距離が増加するだけであるため、ソートされたグリーディー ペアリングが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost(positions, start_index):
    res = 0
    for i, pos in enumerate(positions):
        res += abs(pos - (start_index + 2 * i))
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even_pos = []
    odd_pos = []

    for i, v in enumerate(a):
        if v % 2 == 0:
            even_pos.append(i)
        else:
            odd_pos.append(i)

    ev = len(even_pos)
    od = len(odd_pos)

    if abs(ev - od) > 1:
        print(-1)
        continue

    ans = float('inf')

    # try even starts at 0
    if ev >= od:
        ans = min(ans, cost(even_pos, 0))

    # try odd starts at 0
    if od >= ev:
        ans = min(ans, cost(odd_pos, 0))

    print(ans)
```このソリューションでは、パリティの位置を分離し、ヘルパー関数を使用して、パリティ グループをターゲット インデックスに合わせるために必要なスワップの数を計算します。 の`cost`関数は、現在の位置と理想的な交互スロットの間の貪欲なマッチングをエンコードします。 

よくある実装上の間違いは、どのパリティ リストがどの開始パターンに対応するかを混同することです。 もう 1 つの微妙な問題は、カウントが等しい場合に両方の構成をチェックする必要があることを忘れていることです。 

## 実用的な例

 ### 例 1

 入力:```
3
6 6 1
```偶数の位置:`[0, 1]`奇数の位置:`[2]`両方の構成をテストします。 

| 構成 | 割り当て | コスト |
 | --- | --- | --- |
 | 偶数は 0 から始まります | 偶数 → [0,2]、オッズ → [1] あり得ない不一致は無視される | 偶数コスト = 1 のみを計算します。 
| 奇数は 0 から始まります | 不一致のため無効です | インフ |

 結果は`1`。 

これは、カウントが 1 つ異なる場合でも、有効な構成は 1 つだけであることを示しています。 

### 例 2

 入力:```
6 1 1 2 2 2
```偶数の位置:`[3, 4, 5]`奇数の位置:`[1, 2]`オッズが少ないため、インデックス 0 から奇数を試します。 

| 奇数のスタート | 奇数のターゲット スロット | 偶数ターゲットスロット | コスト |
 | --- | --- | --- | --- |
 | 0 | [0,2] | [1,3,5] | 計算された変位の合計 = 3 |

 このトレースは、貪欲な一致ペアが交差することなく順番に配置される様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素はパリティを分類するために 1 回処理され、コスト計算は線形です。 
| スペース | O(n) | 偶数とオッズの位置を保存します。 

この制約では合計 100,000 個の要素が許可されるため、テスト ケースごとにリニア スキャンで十分です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_pos = []
        odd_pos = []

        for i, v in enumerate(a):
            if v % 2 == 0:
                even_pos.append(i)
            else:
                odd_pos.append(i)

        ev = len(even_pos)
        od = len(odd_pos)

        if abs(ev - od) > 1:
            out.append("-1")
            continue

        def cost(pos):
            res = 0
            for i, p in enumerate(pos):
                res += abs(p - (2 * i))
            return res

        ans = float('inf')
        if ev >= od:
            ans = min(ans, cost(even_pos))
        if od >= ev:
            ans = min(ans, cost(odd_pos))

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 のために`n = 1`、隣接するペアがないため、配列は常に有効です。 パリティ構成の 1 つが自明に実現可能であるため、アルゴリズムは正しくゼロを返します。 

パリティ数が正確にバランスされたアレイの場合、両方の開始パターンがチェックされます。 これにより、両方が可能な場合に最適な配置を逃すことがなくなります。`[1, 2, 3, 4]`ここで、偶数開始構成と奇数開始構成の両方で、コストが異なる有効な交互配列を生成できます。 

次のような不可能な分布の場合`[2, 2, 2, 1]`、条件`abs(evens - odds) > 1`コスト計算の前にケースを即座に拒否し、交互レイアウトを強制する誤った試みを回避します。
