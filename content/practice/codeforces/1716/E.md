 ## 解決策
 ## 問題の理解

 配列には正確に次のものが含まれます$2^n$要素。 すべてのクエリはレベルを選択します$k$、各位置を異なる位置と交換します。$2^k$。 スワップは素のペアで同時に行われるため、サイズのブロックごとに$2^{k+1}$左半分と右半分が入れ替わっています。 

スワップを適用した後、すべての連続するサブ配列間の最大合計が必要になります。ここで、空のサブ配列は許可され、ゼロに寄与します。 

配列自体は永続的に変更されるため、クエリが蓄積されます。 元の配列に同じ操作を繰り返し適用しているのではなく、現在の配置を変更しています。 

配列のサイズは最大でも$2^{18}=262144$、中程度です。 カダネパスは 1 枚だけ安いですが、$2\cdot10^5$クエリ。 すべてのクエリの後で配列を再構築し、答えを再計算するには、大まかに必要となります。$$2\cdot10^5 \times 2^{18}\approx 5\cdot10^{10}$$限界をはるかに超えた操作。 

スワップ操作自体は欺瞞的です。 クエリ$k=0$隣接する要素を交換します。 2回繰り返すと元の順序に戻ります。 より一般的には、各レベルは独立して動作し、すべてのインデックスで 1 ビットを反転しているとみなすことができます。 クエリのシーケンスは、どのレベルが奇数回反転されたかを決定するだけです。 

いくつかの状況が間違いにつながりやすいです。 

仮定する```
n = 1
a = [-5, -7]
```可能な唯一のクエリの後、配列は次のようになります。```
[-7, -5]
```空の部分配列が許可されるため、正解は 0 です。 少なくとも 1 つの要素を選択することを要求する Kadane の不注意な実装では、-5 が出力されます。 

もう 1 つの落とし穴は、操作が蓄積されることを忘れることです。 のために```
n = 2
a = [1,2,3,4]
queries: 0,0
```最初のクエリは次のようになります。```
[2,1,4,3]
```2 番目のクエリは復元します```
[1,2,3,4]
```答えは 10 と 10 です。各クエリを元の配列に再適用すると、誤って同じ最初の状態が 2 回生成されてしまいます。 

最も微妙な問題は、より大きなブロック内でレベル スワップが何を行うかを理解することです。 のために```
[1,2,3,4,5,6,7,8]
```と$k=1$、長さ 4 のブロックごとに変化します```
[1,2,3,4] → [3,4,1,2]
[5,6,7,8] → [7,8,5,6]
```この操作では配列がグローバルにシフトされません。 サイズのブロック内の半分のみを交換します$2^{k+1}$。 

## アプローチ

 簡単な方法は、現在の配列を明示的に維持することです。 クエリごとに、必要なすべてのスワップを実行してから、Kadane のアルゴリズムを実行して最大の部分配列の合計を取得します。 Kadane は必要な数量を正確に計算するため、これは正しいです。 

残念ながら、クエリはすべてに影響を与える可能性があります$2^n$Kadane は配列全体もスキャンします。 と$2\cdot10^5$クエリと$2^{18}$要素の合計作業量は約$10^{11}$、それは絶望的です。 

重要な観察は、すべてのスワップが、あるセグメントの 2 つの半分を交換するということです。 これはセグメント ツリーとまったく同じ構造です。 ノードがセグメントを表す場合、その答えは 4 つの数値のみに依存します。 

合計金額。 

最大プレフィックス合計。 

サフィックスの合計の最大値。 

部分配列の合計の最大値。 

これらは、最大サブ配列クエリに使用される通常の値です。 

通常、左の子は常に右の子より前に来ます。 ここで、レベル反転により、その高さのすべてのノード内で順序が逆転する可能性があります。 各ノードには 2 つの可能な方向しかないため、両方のバージョンを事前計算できます。 

ノードごとに 2 つの状態を保存します。 

状態 0 は、子が通常の順序で連結されていることを意味します。 

状態 1 は、子が逆の順序で連結されていることを意味します。 

子を結合する場合、順序を逆にすると、単純に役割が入れ替わります。 各ノードには 2 つの可能性しかないため、前処理は線形のままです。 

クエリは 1 つのレベルを切り替えます。 その高さのすべてのノードの向きが同時に変わります。 それらを個別に扱う代わりに、どのレベルが反転されるかを記述するビットマスクを維持します。 そのマスクを使用すると、ルートでどの状態を使用する必要があるかがわかります。 ルートの部分配列の最大値が答えです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q2^n)$|$O(2^n)$| 遅すぎる |
 | 最適 |$O(2^n+q)$|$O(2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイ上に完全なバイナリ ツリーを構築します。 

すべてのノードは、長さが 2 の累乗であるセグメントに対応します。 
2. 葉の場合、どちらの方向も同じです。 

合計は要素自体に等しくなります。 プレフィックス、サフィックス、および最大サブ配列は、正の場合はすべて要素値になります。それ以外の場合は、空のサブ配列が許可されるため、ゼロになります。 
3. 内部ノードの場合、2 つのバージョンを計算します。 

バージョン 0 では、左の子に続いて右の子が連結されます。 

バージョン 1 では、右の子に続いて左の子が連結されます。 
4. 2 つのセグメントを結合するには$A$そして$B$、標準の公式を使用します。 

合計額は$A.sum+B.sum$。 

最大プレフィックスのほうが優れています$A.pref$そして$A.sum+B.pref$。 

最大サフィックスのほうが優れています$B.suff$そして$B.sum+A.suff$。 

最大サブ配列は、内部の最適なセグメントの最大値です。$A$、内部の最高のセグメント$B$、および境界を越えるセグメント。その値は$A.suff+B.pref$。 
5. どのレベルが奇数回反転されたかを記述するマスクを維持します。 

値を含むクエリ$k$ビットを切り替えます$k$。 
6. 前処理中に、下からレベルの番号を付けます。 

高さにあるノードの場合$h$、その方向はビットのみに依存します$h-1$現在のマスクの様子。 
7. ルートには 2 つの事前計算された状態があります。 

マスクを更新した後、最上位のビット パターンに対応するルート状態を選択し、その最大サブ配列値を出力します。 

### なぜ効果があるのか

 各クエリは、サイズが次のとおりであるすべてのセグメントの 2 つの半分を独立して交換します。$2^{k+1}$。 その高さのノードでは局所反転が 1 回だけ発生しますが、より深いノードやより高いノードは影響を受けません。 したがって、すべてのノードの順序は、それ自体のレベルのフリップのパリティのみに依存します。 

ノードには 2 つの可能な順序しかないため、両方の可能性を保存することで、将来のすべての配置が完全に記述されます。 マージ式は、セグメント ツリーで部分配列合計の最大値を求めるために使用される式とまったく同じであるため、各方向に対して計算される値は正確です。 ルートは配列全体を表すため、その部分配列の最大値が答えに等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sm", "pref", "suff", "best")

    def __init__(self, sm=0, pref=0, suff=0, best=0):
        self.sm = sm
        self.pref = pref
        self.suff = suff
        self.best = best

def merge(a, b):
    res = Node()
    res.sm = a.sm + b.sm
    res.pref = max(a.pref, a.sm + b.pref)
    res.suff = max(b.suff, b.sm + a.suff)
    res.best = max(a.best, b.best, a.suff + b.pref)
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = 1 << n

    dp = [[None, None] for _ in range(2 * m)]

    for i, x in enumerate(a):
        val = max(0, x)
        node = Node(x, val, val, val)
        dp[m + i][0] = node
        dp[m + i][1] = node

    for v in range(m - 1, 0, -1):
        left = v << 1
        right = left | 1

        dp[v][0] = merge(dp[left][0], dp[right][0])
        dp[v][1] = merge(dp[right][1], dp[left][1])

    orient = [0] * (n + 1)

    q = int(input())
    out = []

    for _ in range(q):
        k = int(input())
        level = k + 1
        orient[level] ^= 1

        cur = 1
        for h in range(n, 0, -1):
            bit = orient[h]
            cur = (cur << 1) | bit

        out.append(str(dp[cur][0].best))

    sys.stdout.write("\n".join(out))

solve()
```空のサブ配列が許可されるため、負のプレフィックス、サフィックス、および最大値にはゼロを保存します。 

マージ ルーチンは、標準の最大サブ配列マージです。 必要な数字は 4 つだけです。 

各内部ノードは 2 つの方向を保存します。 1 つの方向では、左側の子が右側の子よりも前に配置され、もう 1 つの方向では、それらの順序が逆になります。 

方向配列は、すべてのレベルでフリップのパリティを維持します。 同じクエリを 2 回適用すると自動的にキャンセルされるため、重要なのはパリティだけです。 

実装では、セグメント ツリーの高さとクエリ値を慎重に区別します。 クエリ$k$長さのセグメントに影響します$2^{k+1}$、レベルに対応します$k+1$葉から上に数えた場合。
