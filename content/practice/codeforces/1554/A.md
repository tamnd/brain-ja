 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 少なくとも 2 つの要素を含むすべてのサブ配列について、その最大の要素と最小の要素の積を計算します。 タスクは、可能なすべての部分配列の中からそのような積の最大値を見つけることです。 

定義を直接読むと、エンドポイントのすべてのペアを考慮し、その範囲内の最小値と最大値を計算することが示唆されます。 課題は、テスト ケースに最大で次のものを含めることができることです。$10^5$すべてのテスト ケースにわたる要素の合計数は次のとおりです。$3 \cdot 10^5$。 すべてを検査するアルゴリズム$O(n^2)$サブ配列はすぐに遅すぎます。$10^{10}$最悪の場合の運用。 

値自体は次のように大きくなります。$10^6$。 答えは 2 つの配列値の積であるため、次の値に達する可能性があります。$10^{12}$したがって、64 ビット整数演算が必要です。 Python はこれを自動的に処理します。 

微妙な点は、最適なサブ配列が必ずしも長いとは限らないということです。 考慮する：```
3
2 4 3
```サブアレイ$[4,3]$与える$4 \cdot 3 = 12$、一方、より大きな部分配列$[2,4,3]$だけを与える$4 \cdot 2 = 8$。 範囲を拡大すると最小値が減少し、製品が悪化する可能性があります。 

もう 1 つの簡単な間違いは、答えには大域的な最大要素が含まれている必要があると仮定することです。 例えば：```
4
100 1 50 50
```サブアレイ$[50,50]$与える$2500$、100 を含むすべての部分配列には 1 も含まれ、最大でも生成されます。$100$。 最大値だけに注目すると正解を見逃してしまいます。 

3 番目の落とし穴は、32 ビット整数が使用される場合の C++ などの言語での整数オーバーフローです。```
2
1000000 1000000
```正しい答えは、$10^{12}$、これは 32 ビット符号付き整数に収まりません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 エンドポイントのペアごとに$(l,r)$、その部分配列内の最小値と最大値を計算し、答えを更新します。 これは、すべての候補範囲を明示的に評価するため、正しいです。 

問題は走行時間です。 がある$O(n^2)$サブ配列を作成し、それぞれの最小値と最大値を再計算するには次のようになります。$O(n)$。 それは次のことにつながります$O(n^3)$時間。 最小値と最大値を段階的に維持し、複雑さを最小限に抑えたとしても、$O(n^2)$が鈍くなるにもほどがあります。$n=10^5$。 

重要な観察は、部分配列に 3 つ以上の要素が含まれている場合に何が起こるかを理解することから得られます。 

部分配列に最小値があるとします。$m$そして最大値$M$。 これらの値は両方とも、サブ配列内のどこかに現れます。 の位置間のセグメントを考慮します。$m$そして$M$。 そのセグメントも部分配列であり、その最小値は依然として$m$最大値がまだ残っている間に$M$。 商品は残ります$m \cdot M$。 

ここで 2 つの位置を見てください。$m$そして$M$起こる。 ある位置から別の位置に移動するには、隣接する要素のペアが少なくとも 1 つ存在する必要があります。 それらの隣接するペアのうち、1 つのペアは少なくとも積を持ちます。$m \cdot M$。 なぜ？ そのパス上のすべての値は、$m$そして$M$したがって、隣接するペアはその間隔内の値で構成されます。 達成可能な最大の答えは、常に、何らかの隣接するペアによって実現されます。 

それを確認するさらに簡単な方法は、最小値が次の部分配列の場合です。$m$そして最大値は$M$、その部分配列によって提供される答えは正確に$mM$。 ペア$(m,M)$配列内のどこかに、それらの間の値のみを区切って指定する必要があります。 隣接するペアを調べるだけで十分であり、これがこの問題の意図された観察です。 

したがって、すべての部分配列をチェックする代わりに、すべての隣接するペアをチェックして計算するだけで済みます。$$a_i \cdot a_{i+1}$$これらの製品の最大値が答えです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. テスト ケースごとに、配列を読み取ります。 
3. 答えを 0 として初期化します。 
4. すべての隣接するペアを反復処理します。$(a_i, a_{i+1})$。 
5. 積を計算し、この積の方が大きい場合は答えを更新します。 
6. すべての隣接するペアを処理した後、答えを出力します。 

これが機能する理由は、より長い部分配列から得られるすべての候補の答えも、その範囲内の最小値と最大値を考慮することによって達成でき、最終的に可能な最大の積が隣接する要素間で現れるからです。 隣接するすべてのペアがチェックされるため、最適な値を見逃すことはありません。 

### なぜ効果があるのか

 最適な部分配列に最小値を持たせる$m$そして最大値$M$。 その部分配列によって提供される値は次のとおりです。$mM$。 

位置に焦点を当てます。$m$そして$M$起こる。 これらの位置間のすべての要素は、$m$そして$M$包括的な。 このパスに沿って隣接するペアがあり、その積は少なくとも$mM$。 最適な部分配列はすでに生成されているため、$mM$、全体的な最適値は、隣接するペアの最大積と等しくなければなりません。 

このアルゴリズムはすべての隣接するペアを 1 回だけチェックするため、必然的に最大の積が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    for i in range(n - 1):
        ans = max(ans, a[i] * a[i + 1])

    print(ans)
```解決策は観察に直接従うものです。 

ループはインデックス 0 からインデックスまで実行されます。$n-2$これにより、隣接するすべてのペアが 1 回だけ処理されることが保証されます。 各ペアについて、その積が計算され、現在の最良の答えと比較されます。 

すべての配列値が正であるため、応答変数は 0 から始まり、有効な積もすべて正になります。 

Python の整数は、次の値よりも大きい値を自動的にサポートします。$2^{31}-1$、したがって、製品まで$10^{12}$特別な注意を払うことなく安全に取り扱われます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        for i in range(n - 1):
            ans = max(ans, a[i] * a[i + 1])

        out.append(str(ans))

    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result
