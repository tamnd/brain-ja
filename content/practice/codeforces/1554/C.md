 ## 解決策
 ## 問題の理解

 We are given a fixed integer`n`および整数の範囲`0, 1, 2, ..., m`。 この範囲内の各数値は次のものと XOR 演算されます。`n`、一連の値を生成します。 この結果のセットから、表示されない最小の非負の整数が必要になります。 

これについて考えるのに便利な方法は、インデックスの間隔を取ることです。`[0, m]`、ビットごとの変換を適用する`i → n ⊕ i`、そして、変換されたセットから欠落している最初の整数を求めます。 

重要な構造上の事実は、固定数による XOR はすべての整数の全単射であるため、グローバルに衝突が発生しないことです。 一部の数値が欠落している唯一の理由は、元のドメインが切り詰められていることです。`[0, m]`。 

制約は大きく、最大 30,000 のテスト ケースと最大値があります。`10^9`。 これにより、全範囲にわたるシミュレーションや値ごとのチェックが除外されます。 どのソリューションも、テスト ケースごとに一定時間または対数時間で実行する必要があり、基本的にはバイナリ表現のレベルで動作します。 

単純な試みは、すべての値を生成することです`n ⊕ i`のために`i`で`[0, m]`、それらを並べ替えて、mex を計算します。 これはすでに失敗しています。`m`大きくなる可能性があり、範囲は最大で`10^9`最悪の場合の要素。これは実現不可能です。 

より微妙な失敗例は、セットを構築しようとしてメンバーシップを段階的にチェックすることから発生します。`0, 1, 2, ...`。 各メンバーシップ チェックは O(1) ですが、mex 自体は次のように大きくなる可能性があります。`10^9`したがって、ループは依然として応答サイズの線形時間に縮退する可能性があります。 

重要な点は、セット全体が必要ないということです。 述語がどのように機能するかを理解することだけが必要です`x is present ⇔ (n ⊕ x) ≤ m`ビット構造上で動作します。 

## アプローチ

 ブルートフォースアプローチでは、あらゆるものを列挙します。`i`で`[0, m]`、計算します`n ⊕ i`、結果をセットに格納してから増分します。`mex`欠損値が見つかるまで。 これは、変換されたセット全体を直接構築するため、正しいです。 ただし、そのコストは次のとおりです。`m`まで可能です。`10^9`, なので使えません。 

構造の単純化は、メンバーシップの書き換えによって実現されます。 数字`x`が存在する場合に限り、最終セットに含まれます。`i ∈ [0, m]`そのような`x = n ⊕ i`。 XOR は可逆であるため、これは次のことと同じです。`i = n ⊕ x`にある`[0, m]`。 したがって、メンバーシップは単一の不等式条件になります。`x is present ⇔ (n ⊕ x) ≤ m`。 

これにより、問題は最小値を見つけることに変わります`x`そのような`(n ⊕ x) > m`。 

ここでのタスクは古典的なビット単位の構築問題です。最小の整数を構築しています。`x`導出された値が`n ⊕ x`限界を超えます。 難しいのは、XOR は単調性を破壊するため、単純に値を数値的に比較することができないことです。 私たちは構築しなければなりません`x`まだ維持できるかどうかを追跡しながら少しずつ`(n ⊕ x)`範囲内で。 

これは、最上位ビットから最下位ビットまでの貪欲な数字 DP を使用して解決します。 各ビットで、ビットを設定するかどうかを決定します。`x`残りのビットの完了を許可できるため、`(n ⊕ x) ≤ m`。 可能であれば、ビットを小さくしておきます。 それ以外の場合は、強制的に設定する必要があります。

 ## アルゴリズムのチュートリアル

 に現れる可能性のある最上位ビットから始めて、少しずつ答えを構築します。`n`または`m`。 

1.初期化`x = 0`。 最上位ビットから下に向かって答えを構築していきます。 この構造により、`x`を満たす最小の数です`(n ⊕ x) > m`。 
2. 各ビット位置について`b`高から低まで、このビットを設定してみます`x`に`0`初め。 これは、辞書編集 (バイナリ) 順序で答えをできるだけ小さく保つことに対応します。 
3. プレフィックスを仮固定した後、`x`、残りの下位ビットを選択できるかどうかを尋ねます。`(n ⊕ x) ≤ m`が成立する。 これはサフィックス ビットに関する実現可能性の問題です。 
4. 実現可能性を確認するために、不等式を満たすための最良のシナリオをシミュレーションします。 固定プレフィックスの場合、下位ビット`x`自由に選択できます。つまり、`(n ⊕ x)`も自由に変えることができます。 したがって、重要な唯一の制約は、すでに固定されている上位ビットが強制的に適用されるかどうかです。`(n ⊕ x)`超える`m`または、まだそれ以下のままにします。 
5. 実現可能性があれば、現在のビットを次のように維持します。`0`そして続けます。 実現可能性が失敗した場合、それは選択することを意味します`0`維持できなくなるだろう`(n ⊕ x) ≤ m`したがって、このビットを次のように設定する必要があります。`1`。 
6. すべてのビットが処理されるまで続行します。 結果として得られる`x`は次のような最小の整数です`(n ⊕ x) > m`。 

### なぜ効果があるのか

 このアルゴリズムは、バイナリ プレフィックスに対する貪欲な構築であり、制約はバイナリ プレフィックス間のプレフィックス比較です。`(n ⊕ x)`そして`m`。 各ステップで、現在のプレフィックスの何らかの補完が存在するという不変条件を保持します。`(n ⊕ x)`意図的に制限を超えるように強制しない限り、許可された制限内に収まります。 なぜなら、常に最小の実現可能なビットを選択するからです。`x`、初めて実現可能性を破らざるを得なくなるのは、まさにそのときです。`(n ⊕ x)`を超えなければなりません`m`。 これにより、構築された`x`すべての有効な候補の中で最小です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m):
    x = 0

    for b in range(30, -1, -1):
        candidate = x | (1 << b)

        # check if this prefix of x can still allow (n xor x) <= m
        # we simulate feasibility by greedily completing lower bits optimally
        ok = True
        cur_x = candidate
        cur_val = 0

        # we test bit by bit whether (n xor cur_x) can stay <= m
        # using a tight-style simulation
        tight = True

        for i in range(30, -1, -1):
            nb = (n >> i) & 1
            xb = (cur_x >> i) & 1
            vb = nb ^ xb

            mb = (m >> i) & 1

            if tight:
                if vb < mb:
                    tight = False
                elif vb > mb:
                    ok = False
                    break

        if not ok:
            x |= (1 << b)

    return x

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        print(solve_case(n, m))

if __name__ == "__main__":
    main()
```コードは、最上位ビットから貪欲に答えを構築します。 候補ビットごとに、そのビットを選択しても許可されるかどうかを確認します。`(n ⊕ x)`せいぜい残る`m`。 実現可能性チェックは、次のプレフィックスを比較することによって実装されます。`(n ⊕ x)`と`m`デジット DP スタイルのスキャンで。 

微妙な点は、下位ビットのすべての完了を明示的に列挙していないことです。 代わりに、一度接頭辞が`(n ⊕ x)`の対応するプレフィックスより厳密に小さくなります`m`、残りの完了はすべて安全です。 それがさらに大きくなった場合、その選択は無効になります。

def solve(inp: str) -> str:

    input = sys.stdin.readline

            candidate = x | (1 << b)

            tight = True

 ## 特殊なケース

 いつ`m = 0`、シーケンスには次のみが含まれます`n ⊕ 0 = n`、つまりメキシコは`0`ない限り`n = 0`、この場合、mex は次のようになります。`1`。 最初にチェックされる値は常に次の値であるため、アルゴリズムはこれを正しく処理します。`x = 0`、そして実現可能性がまさにそのとき失敗します`n`すでに`0`。 

いつ`n = 0`、シーケンスは単純です`[0, 1, ..., m]`、つまりメキシコは`m + 1`。 ビットごとの構造はこれを再現します。`(0 ⊕ x) = x`したがって、条件は、次より大きい最初の整数を見つけることになります。`m`。 

いつ`n`そして`m`が大きく、上位ビットを共有すると、早期の決定は上位で決定され、下位ビットは無関係になります。 貪欲な構造は、最も高い異なるビットで答えを正しく解決します。`(n ⊕ x) ≤ m`まず壊れます。
