 ## 解決策
 ## 問題の理解

 1 からインデックス付けされた値の配列が与えられており、この配列内の 2 つの異なる位置を選択したいとします。 選択したインデックスのペアについて、競合する 2 つの部分で構成されるスコアを計算します。1 つはインデックスの積に応じて増加する正の項、もう 1 つは定数係数 k でスケールされた、対応する配列値のビットごとの OR に依存するペナルティ項です。 目標は、このスコアを最大化するインデックスのペアを見つけることです。 

重要な構造は、インデックスの寄与が位置のみに依存するのに対し、ペナルティはビットごとの OR による値のみに依存するということです。 大きなインデックスが望ましいが、大きな OR 値はコストがかかるため、この分離が問題を興味深いものにしています。 

典型的な競技プログラミングの意味では、制約は厳しいです。 すべてのテスト ケースにわたる要素の合計数は最大 3 × 10^5 に達し、最大 10^4 のテスト ケースが存在します。 この組み合わせにより、テスト ケースごとに平均してすべてのソリューションが線形またはほぼ線形に近くなります。 テスト ケースごとのすべてのペアに対する単純な 2 次スキャンでは、最悪の場合、およそ 10^10 の演算が試行されるため、すぐに制限を超えてしまいます。 

貪欲な直感が失敗する微妙なケースもあります。 非常に大きなインデックスを持つペアは、OR で導入されるビットが多すぎる場合、常に最適であるとは限りません。 たとえば、1 つの値に多くの設定ビットがある場合、それを別の大きなインデックスと組み合わせると、インデックスの積から得られるものよりも、OR ペナルティによる損失の方が大きくなる可能性があります。 同様に、OR がほぼゼロの 2 つの小さいインデックスは、大きいインデックスよりもパフォーマンスが優れている可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペア i と j を反復処理し、i × j − k × (a[i] | a[j]) を計算し、最大値を追跡します。 これは、近似を行わずに完全な検索スペースを評価するため、正しいです。 ただし、n が 10^5 までの場合、テスト ケースごとに約 10^10 の OR 演算が必要となり、これは実行不可能です。 

主な観察は、式の 2 つのコンポーネントを分離することで得られます。 項 i × j はインデックスのみに依存するため、大きなインデックスを含むペアの方が当然有望です。 OR 項は値のみに依存し、k は小さく、最大でも 100 です。この小さな k が、検索スペースを削減できる鍵となります。 

すべてのペアを試す代わりに、1 つのインデックス j をより大きなエンドポイントとして固定し、j に近い限られた数の候補 i のみを考慮します。 直感的には、固定 j の場合、i × j は i とともに線形に増加するため、OR ペナルティによって結果が劇的に変化しない限り、j の最適なパートナーは最大数のインデックスの中にあるはずです。 k が小さいため、OR ペナルティはステップが多すぎる場合の i の大幅な低下を補償できないため、以前のインデックスの小さなウィンドウのみが問題になります。 これにより、各 j の最後の約 100 個の候補のみが維持されることになります。 

最近のインデックスのスライディング ウィンドウを維持しながら、左から右にスキャンして答えを計算します。 各位置 j について、保存されているすべての候補に対してテストし、答えを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最後の k 個の候補に対するスライディング ウィンドウ | O(n・k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n、k、および配列 a を読み取ります。 

以前のインデックスの小さなサブセットのみを確実に保存しながら、候補ペアを評価する準備をします。 
2. 最初は空の候補インデックスのリストを維持します。 

このリストは、将来のインデックスと組み合わせたいと考えている唯一のポジションを表しています。 目標は、リストを小さく保ちながら、最適なペアを見逃さないようにすることです。 
3. j を 1 から n まで繰り返します。 

各ステップで、j を潜在的なペアの右端点として扱います。 
4. 候補リスト内の各 i について、i × j − k × (a[i] | a[j]) を計算し、グローバル最大値を更新します。

このステップでは、j で終わるすべての意味のあるペアを評価します。 候補への制限は、k の制限された影響によって正当化されます。 
5. j を処理した後、j を候補リストに挿入します。 

これにより、将来のポジションが j とペアになることが保証されます。 また、リストのサイズが k に関連付けられた小さな定数境界を超えないことも保証します。 
6. 候補リストが大きくなりすぎる場合は、最も古い要素を削除します。 

非常に古いインデックスは、OR ペナルティを補うには i × j 項にあまり寄与しないため、これにより最も関連性の高いインデックスのみが保持されます。 

### なぜ効果があるのか

 値 i × j は両方のインデックスで線形に増加しますが、OR ペナルティはビット サイズによって制限され、k ≤ 100 によってスケールされます。これにより、インデックスが競争力を維持できる範囲が制限されます。 i が j に対して小さくなりすぎると、可能な限り最良の OR 値でも積の損失を補償できなくなります。 したがって、最適なペアに参加できる最近のインデックスの制限された数だけがあり、スライディング ウィンドウに注意を限定しても最適なソリューションが削除されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        best = -10**18
        candidates = []

        for j in range(n):
            for i in candidates:
                val = (i + 1) * (j + 1) - k * (a[i] | a[j])
                if val > best:
                    best = val

            candidates.append(j)

            if len(candidates) > k + 5:
                candidates.pop(0)

        print(best)

if __name__ == "__main__":
    solve()
```この実装ではインデックスが 0 ベースの形式で保存されますが、i × j の問題定義と一致するように評価中に 1 ベースの形式に変換されます。 

候補者リストはスライディング ウィンドウとして機能します。 境界 k + 5 は、OR ペナルティの強度が限られているため、少数の最近のインデックスのみが関連するという制約を反映する実用的なエンベロープです。 

OR 計算はビットごとの演算子を使用して直接実行され、すべての更新はチェックされたペアごとに O(1) で実行されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        best = -10**18
        cand = []
        for j in range(n):
            for i in cand:
                best = max(best, (i+1)*(j+1) - k*(a[i] | a[j]))
            cand.append(j)
            if len(cand) > k + 5:
                cand.pop(0)
        out.append(str(best))
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての配列値が同一である場合です。 その状況では、OR 項はすべてのペアで一定であるため、問題は i × j を最大化することになります。 アルゴリズムは常に最新のインデックスを保持しており、最良のペアは常にこれまでに確認された 2 つの最大のインデックスとなるため、このアルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、値が 2 の累乗で増加する場合です。 ここでは、さまざまな要素の OR が急速に密になり、大きなインデックスであってもペナルティが優勢になる可能性があります。 スライディング ウィンドウは、積項が最も強い付近のすべての高インデックス ペアを評価するため、依然として機能します。これはまさに、最適な妥協点が存在する場所です。 

最後のケースは、k が 100 近くの最大値の場合です。これにより、OR ペナルティの重みが増加しますが、有用な候補の制限された性質は変わりません。 アルゴリズムは引き続き小さなウィンドウに制限され、潜在的に最適なトレードオフ ペアはすべてそのウィンドウ内でテストされます。
