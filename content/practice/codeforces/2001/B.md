 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列を構築するように求められます。$n$つまり、Misuki が 2 つのタイプライターのどちらを使用しても、置換を完了するために必要なキャリッジ リターンの数は同じになります。 1 つのタイプライターは位置 1 から開始して左から右に移動し、もう 1 つは位置 1 から開始して右から左に移動します。$n$。 書き込みは空の位置にのみ許可されます。 各ステップは、欠落している次に小さい値を書き込むか、ポインタを移動するか、キャリッジ リターンを実行してポインタをリセットするかのいずれかです。 

入力はテスト ケースの数と長さを示します$n$各テストケースの順列。 出力は、両方のタイプライターが配列を埋めるために同じ最小数の復帰を必要とするような順列 (不可能な場合は -1) でなければなりません。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$すべてのテスト ケースにわたって、タイプライターごとに位置ごとに数字を書くことをシミュレートするソリューションは除外されます。 線形時間で順列を生成する建設的な解決策が必要です。 

明らかではないエッジケースが発生するのは次の場合です。$n = 2$。 一方のタイプライターは常に 1 回の実行で配列を完了し、もう一方のタイプライターは少なくとも 1 つのキャリッジ リターンを必要とするため、キャリッジ リターンの数のバランスをとる長さ 2 の順列はありません。 小さな例としては、$n = 1$些細な作業、そして$n = 3$利益のバランスをとる解決策を認めます。$[3,1,2]$。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべての置換が試行されます。$n$各タイプライターのプロセスをシミュレートして、最小限の復帰をカウントします。 これは階乗になります$n$、明らかに実行不可能です$n$まで$2 \cdot 10^5$。 

重要な洞察は、タイプライターの対称性の問題が、順列を左右から減少する連続ブロックに分割することに帰着できることを理解することです。 もし$n = 1$、順列は自明です$[1]$。 もし$n = 2$1 つのタイプライターがキャリッジ リターンを必要とせずに、単一の位置を同時に最初と最後の両方にすることはできないため、バランスのとれた順列は存在しません。 のために$n \ge 3$、最大の数値を最初に配置し、その後残りを順番に埋めることで、有効な構築が常に可能になります。 これにより、両方のタイプライターで常に少なくとも 1 つのキャリッジ リターンが必要となり、キャリッジ リターンの数が同じになります。 

パターンは次のように表現できます。$n$、それを先頭に配置し、1 から 1 までの数字を追加します。$n-1$。 これにより、バランスの取れた最小限の復帰シーケンスが作成されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、順列の長さ。 
3. もし$n = 1$、印刷`[1]`キャリッジリターンが必要ないためです。 
4. もし$n = 2$、印刷`-1`往復送料のバランスをとることが不可能だからです。 
5. のために$n \ge 3$を配置して順列を構築します。$n$最初に 1 から 1 までの数字が続きます$n-1$。 これにより対称性が保証されます。どちらのタイプライターでも、置換を完了するにはちょうど 1 つのキャリッジ リターンが必要です。 
6. 構築された順列を出力します。 

機能する理由: 最大の数値を先頭に置くことで、各タイプライターはリターンが必要な境界に遭遇し、残りを順次埋めていくことで、ポインターの移動と書き込みの各ステップが他のタイプライターを反映するようになります。 これにより、両方のタイプライターが同一の最小キャリッジリターンを持つことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    if n == 1:
        print(1)
    elif n == 2:
        print(-1)
    else:
        perm = [n] + list(range(1, n))
        print(" ".join(map(str, perm)))
```コードはテスト ケースの数を読み取り、それぞれの長さを処理します。$n$。 のために$n = 1$それは印刷します`1`。 のために$n = 2$、`-1`有効な順列が存在しないため、「」と表示されます。 大型の場合$n$、次のように順列を構築します。`[n, 1, 2, ..., n-1]`リスト内包表記を使用し、スペースで区切って出力します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 1:
            output.append("1")
        elif n == 2:
            output.append("-1")
        else:
            perm = [n] + list(range(1, n))
            output.append(" ".join(map(str, perm)))
    return "\n".join(output)

# Provided samples
assert run("3\n1\n2\n3\n") == "1\n-1\n3 1 2"

# Custom cases
assert run("1\n4\n") == "4 1 2 3", "n=4, standard permutation"
assert run("1\n5\n") == "5 1 2 3 4", "n=5, standard permutation"
assert run("1\n1\n") == "1", "n=1, trivial"
assert run("1\n2\n") == "-1", "n=2, impossible case"
assert run("2\n6\n7\n") == "6 1 2 3 4 5\n7 1 2 3 4 5 6", "larger n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | n=1 の自明な解 |
 | 2 | -1 | n=2 が不可能な場合 |
 | 4 | 4 1 2 3 | 標準構造、n>=3 |
 | 7 | 7 1 2 3 4 5 6 | n が大きいほど、順列の正確性 |

 ## 特殊なケース

 のために`n=1`、アルゴリズムの出力`[1]`。 実行トレースは、位置 1 でのポインターの書き込みを示し、ゼロの復帰ですぐに完了します。 

のために`n=2`、アルゴリズムの出力`-1`。 どちらのタイプライターも異なる数のキャリッジ リターンを必要とし、これは不可能条件に一致します。 

のために`n>=3`、順列`[n,1,...,n-1]`対称性を確保します。 のために`n=3`、どちらのタイプライターも最初に最大の数値に遭遇し、その後、残りの位置を順番に埋めていきます。 最初のタイプライターは左から右に移動して書きます`1`それから`2`、改行が 1 回必要です。 2 番目のタイプライターは右から左に移動し、シーケンスを反映しますが、キャリッジ リターンも 1 回必要です。 不変式はどんな場合にも成り立ちます`n>=3`。
