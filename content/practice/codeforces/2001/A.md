 ## 解決策
 ## 問題の理解

 循環的に配置された整数の配列が与えられます。これは、最初と最後の要素が隣接していると見なされることを意味します。 許可される操作は、最初の要素が 2 番目の要素以下である連続する要素のペアを選択し、2 つの要素のうちの 1 つだけを削除することで構成されます。 タスクは、残りの要素をすべて等しくするために必要なそのような操作の最小数を決定することです。 

配列のサイズ$n$せいぜい$100$テストケースの数は最大で$500$。 以来$n$小さいですが、アルゴリズムは最大で複雑です$O(n^2)$テストケースごとに実行可能です。 配列内の値は次のように制限されます。$1 \le a_i \le n$効率的に周波数をカウントできるようになります。 明らかでないエッジ ケースには、すべての要素がすでに等しい配列、厳密に減少している配列、最大周波数要素が配列の終端と始端にまたがって分割される周期的繰り返しが含まれます。 たとえば、配列$[1, 2, 1]$以下に等しい 2 つの要素があります$1$、ただし、それらは次のように区切られています。$2$したがって、連続する等しい要素のみをカウントする単純な貪欲なアプローチは失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、許可されているすべての削除をシミュレートし、すべての要素が等しくなるまで各操作後の配列の状態を追跡します。 これは非常に小さな配列では機能しますが、最大数の配列が存在する可能性があるため非効率的になります。$2^{n-1}$考えられる削除シーケンス。 このアプローチは正しいですが、次のような場合には明らかに非現実的です。$n=100$。 

重要な洞察は、配列を単一の繰り返し値に減らす削除シーケンスでは、最も頻繁に発生する要素が優先されるということです。 させて$x$最も高い頻度を持つ要素になります。 削除の数を最小限に抑えるために、すべての発生を保持したいと考えています。$x$そして他の要素を削除します。 次に、問題は、そうでないすべての要素を削除するために必要な最小の削除数を見つけることに帰着できます。$x$隣接ルールに従いながら。 非連続ブロックのそれぞれは、$x$要素は削除する必要があり、削除操作ごとにブロック サイズが少なくとも 1 ずつ減少します。 ただし、1 回の操作でブロックから削除できる要素は 1 つまでであるため、操作の最小数は、非ブロックの最大ブロックのサイズと等しくなります。$x$要素。 配列は循環しているため、配列の末尾をラップするブロックも考慮する必要があります。 

この観察により、問題は、連続する非結合のサイズを数えるという問題に変換されます。$x$セグメントを分割し、場合によってはラップアラウンドし、各ブロック サイズの 2 を底とする対数の上限を取得して、必要な操作の数を決定します。 対数にする理由は、各操作の後にブロックを分割することができ、問題を効果的に指数関数的に軽減できるためです。 この貪欲なカウント手法は、以下の場合に効率的に機能します。$O(n)$テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^n) | O(n) | 遅すぎる |
 | 貪欲なブロックカウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースを反復処理し、配列の長さを読み取ります。$n$と要素$a$。 
2. 配列内のすべての個別の値を特定し、その頻度を決定します。 させて$x$最大頻度の値になります。 
3. 配列を、要素が次の値に等しいバイナリ インジケーター配列に変換します。$x$としてマークされています$1$そして他のすべては$0$。 
4. バイナリ配列を走査して、連続するセグメントを特定します。$0$、連続する非$x$要素。 セグメントのサイズを追跡します。 最初と最後の要素が両方とも$0$、これらのセグメントをマージして、周期的な隣接関係を考慮します。 
5. 長さの各セグメントについて$k$、次の式を使用して、それを排除するための最小操作数を計算します。$\lceil \log_2(k+1) \rceil$。 必要に応じてすべてのセグメントを合計しますが、セグメントは独立しているため、最大のセグメントによって演算数が決まります。 
6. 現在のテスト ケースに対して計算された操作数を出力します。 

このアルゴリズムが機能するのは、隣接ルールにより各操作で 1 つの要素を削除できるためです。これにより、非ターゲット要素の連続ブロックが操作ごとに少なくとも 1 つ効果的に削減されます。 対数計算は、隣接性を考慮してブロックが効率的に縮小されるような方法で要素を削除する戦略から生じます。 最も頻繁に使用される要素に焦点を当てることで、操作の数を最小限に抑えます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def min_operations_to_equal(a):
    n = len(a)
    if n == 1:
        return 0
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1
    max_val = max(freq, key=lambda k: freq[k])
    b = [1 if v == max_val else 0 for v in a]
    segments = []
    i = 0
    while i < n:
        if b[i] == 1:
            i += 1
            continue
        j = i
        while j < n and b[j] == 0:
            j += 1
        segments.append(j - i)
        i = j
    if len(segments) >= 2 and b[0] == 0 and b[-1] == 0:
        segments[0] += segments[-1]
        segments.pop()
    ans = 0
    for seg in segments:
        ops = 0
        length = seg
        while length > 0:
            length = length // 2
            ops += 1
        ans = max(ans, ops)
    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_operations_to_equal(a))
```機能`min_operations_to_equal`まず、最も頻繁に使用される要素を特定します。 次に、配列をバイナリ インジケータに変換して、削除が必要な要素のブロックを簡単に見つけます。 循環セグメントをマージし、半減を繰り返すことで各ブロックの演算数を計算することで、隣接制約が尊重され、最小限の演算数が効率的に計算されるようになります。 循環マージを処理するループにより、ラップアラウンドするセグメントの二重カウントが回避されます。
