 ## 解決策
 ## 問題の理解

 それぞれの長さが m である n 枚のまばらな「カード」のセットが与えられます。 各カードには一部の位置にのみ文字が書かれており、他の位置はすべて空白です。 長さ m のターゲット文字列 s もあります。 

すべてのカードを上から下に順番に積み重ねることができます。 各位置 i について、列 i に文字がある一番上のカードを調べ、その文字が結果の文字列で表示される文字になります。 カードの位置 i に文字が入っていない場合、その位置を埋めることはできず、順序は無効になります。 

タスクは、正確に s を生成するカードの順序が存在するかどうかを判断し、存在する場合は有効な順列を出力することです。 

この制約により、n と m は最大 100,000、書き込まれるセルの総数は最大 200,000 まで許可されます。これにより、カードのすべてのペアを直接比較したり、順列ごとにスタッキングをシミュレートしたりするものは即座に除外されます。 どのソリューションも、書き込まれたエントリの数に対してほぼ直線的またはほぼ直線的な時間で機能する必要があります。 

微妙な点は、各位置は可視性の点では独立していますが、順序によってそれらが結合されることです。ある位置を満たすカードを選択すると、その下にある他のカードがブロックされたり、上書きされたりする可能性があります。 もう 1 つの重要な詳細は、複数のカードに同じ位置が含まれる可能性があり、最上位のカードのみが重要であるということです。 

単純な間違いは、各ポジションを貪欲にいくつかのカードに個別に割り当てようとすることです。 たとえば、位置 i で s[i] に一致するカードを選択すると、複数の位置を一貫して満たすために同じカードが必要になる可能性があるため、後で簡単に矛盾が生じる可能性があります。 もう 1 つの失敗モードは、制約が位置ごとであり、多くのカード間で共有されることを考慮せずに、カード間の依存関係のグラフを構築しようとすることです。 

## アプローチ

 直接的な強引なアイデアは、カードのすべての順列を試し、それぞれの順序でターゲットの文字列が生成されるかどうかをシミュレートすることです。 これは定義に正確に従っているので正しいですが、n の階乗であり、n = 100 の場合でも不可能です。 

重要な観察は、最終文字列の各位置 i が、i に文字を含む (順序付けの) 最初のカードによって決定されるということです。 したがって、すべてのポジション i に対して、「責任のある」カードが 1 枚だけ存在します。つまり、そのポジションを含むカードの中で最も上位のカードです。 そのカードの位置 i には s[i] が含まれている必要があります。 

これにより、問題はカードの相対的な順序に関する制約システムに変わります。 各位置 i について、i に文字を含むすべてのカードを調べます。 その中で、最終的な順序の一番上のカードは、i の文字が s[i] に等しいカードでなければなりません。 i に異なる文字を持つカードは、その選択したカードの下に厳密に配置する必要があります。そうしないと、表示されている文字が上書きされ、s が中断されます。 

したがって、ポジションごとに、s[i] に一致する「証人カード」を 1 枚選択し、そのポジションの競合するカードはすべて順番の後ろに来る必要があります。 これにより、カード間に有向制約が生じます。 最後の問題は、これらの順序付け制約をすべて満たす順列を見つけられるか、見つかった場合はトポロジカルな順序付けを出力できるかということです。 

エッジ a → b はカード a がカード b の上に現れる必要があることを意味する有向グラフを構築します。 次に、トポロジカルソートを実行します。 サイクルがある場合、順序は存在しません。 

重要な効率化の秘訣は、O(n^2) の方法ですべての競合に対して明示的にペアごとのエッジを追加しないことです。 代わりに、位置ごとに処理します。各位置 i について、i に含まれる文字によってカードをグループ化します。 i に一致しない文字を持つすべてのカードは、i に一致する文字を持つすべてのカードの下になければならないため、一致するグループからのエッジをその位置にある他のすべてのカードに追加します。 合計出現数は 200000 で制限されているため、これは依然として効率的です。

 | 制約グラフ + トポソート | O(n + 合計セル数) | O(n + 合計セル数) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、各列から個別に導出される順序付け制約に変換します。 

1. すべてのカードについて、その文字を文字にマッピングする構造の位置に保存します。 これにより、特定の列でカードがどのような貢献をしているかを簡単に検索できます。 制約は位置固有の比較に依存するため、これが必要になります。 
2. 1 から m までの各位置 i について、i に文字があるすべてのカードを集めます。 その中で、カードを s[i] に一致するカードと一致しないカードに分割します。 
3. i の文字が s[i] に等しいカードが少なくとも 1 枚ある場合、それらを位置 i の潜在的な「トッププロバイダー」として扱います。 一致しないセット内のカードは、一致するすべてのカードの下になければなりません。そうしないと、i に表示されている文字がオーバーライドされ、ターゲット文字列が壊れてしまいます。 
4. 位置 i にあるすべての一致するカードから、位置 i にあるすべての非一致カードに有向エッジを追加します。 これにより、有効な順序付けでは、その位置ですべての正しい貢献者がすべての不正確な貢献者よりも上位に配置される必要があります。 
5. すべての位置を処理した後、グラフに対してトポロジカル ソートを実行します。 すべてのノードを順序付けできる場合、その順序は有効なスタック順序になります。 そうでない場合、制約は互いに矛盾し、解決策は存在しません。 

なぜそれが機能するのかは、可視性がどのように定義されるかによって決まります。 各位置で、目に見える文字は、そこに文字がある最も高いカードによってのみ決定されます。 間違った文字が正しい文字の上に表示されると、その列が永久に上書きされるため、そのような構成は順序付けによって禁止する必要があります。 私たちの制約はこれらの禁止された反転を正確にエンコードしており、それらを満たす順序はすべての位置で独立して正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

n, m = map(int, input().split())
s = input().strip()

# store: for each position, list of (card_id, char)
pos_cards = [[] for _ in range(m)]

cards = []
for idx in range(n):
    parts = input().split()
    k = int(parts[0])
    card = {}
    j = 1
    for _ in range(k):
        a = int(parts[j]) - 1
        c = parts[j + 1]
        j += 2
        card[a] = c
        pos_cards[a].append((idx, c))
    cards.append(card)

graph = [[] for _ in range(n)]
indeg = [0] * n

# build constraints
for i in range(m):
    if not pos_cards[i]:
        continue

    good = []
    bad = []

    for idx, c in pos_cards[i]:
        if c == s[i]:
            good.append(idx)
        else:
            bad.append(idx)

    if not good:
        print(-1)
        sys.exit()

    # every good card must be above every bad card
    for u in good:
        for v in bad:
            graph[u].append(v)
            indeg[v] += 1

# topological sort
q = deque(i for i in range(n) if indeg[i] == 0)
order = []

while q:
    u = q.popleft()
    order.append(u)
    for v in graph[u]:
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)

if len(order) != n:
    print(-1)
else:
    print(*[x + 1 for x in order])
```このソリューションでは、位置ごとに制約を構築します。 各カードはそのスパース表現を保存しますが、キーの構造は次のとおりです。`pos_cards`これにより、列に影響を与えるすべてのカードをすばやく見つけることができます。 

列ごとに、カードを一致するグループと一致しないグループに分けます。 一致するカードがない場合、最上位の選択では s[i] を生成できないため、答えは不可能です。 それ以外の場合は、一致するすべてのカードが一致しないすべてのカードの上に表示されるように強制します。 

最悪の場合、単一列のグラフは密になる可能性がありますが、各 (カード、位置) ペアが 1 回ずつ寄与するため、エッジの合計は入力の出現回数の合計によって制限されます。 

最後に、トポロジー的順序付けを計算します。 それが失敗すると、サイクルが存在し、ポジション間で矛盾した制約が発生することになります。 

## 実用的な例

 ### 例 1

 入力:```
3 4
glhf
3 1 r 3 h 4 i
3 1 r 2 l 3 o
2 1 g 4 f
```位置ごとの制約を追跡します。 

| ポジション | s[i] | 良いカード | 悪いカード | エッジが追加されました |
 | --- | --- | --- | --- | --- |
 | 1 | g | {2} | {0,1} | 2→0、2→1 |
 | 2 | l | {1} | {} | なし |
 | 3 | h | {0} | {1} | 0→1 |
 | 4 | f | {2} | {0} | 2→0 |

 これらの制約をトポロジカルに並べ替えると、次のような有効な順序が得られます。 

2、1、0。 

これは、単一のカードが複数の位置を一意に満たすため、どのようにしてそのカードが最上位に押し出されるかを示しています。 

### 例 2

 入力:```
2 2
aa
2 1 a 2 b
2 1 b 2 a
```位置 1 では、カード 0 には a があり、カード 1 には b があります。 s[0] = a なので、カード 0 は良好で、カード 1 は不良であるため、エッジ 0→1 を追加します。 

位置 2 では、s[1] = a であるため、カード 1 は良好で、カード 0 は不良であるため、エッジ 1→0 を追加します。 

0→1と1→0というサイクルが得られます。 トポロジカルソートは失敗し、-1 が出力されます。 

これは矛盾を捉えたものです。各カードは、他のカードが別の列で一番上になることをブロックします。

 ## 特殊なケース

 特殊なケースの 1 つは、ポジションに文字を含むカードがない場合です。 たとえば、s[i] が 'a' であるが、どのカードも位置 i に何も書き込まない場合、順序付けによってターゲット文字列を生成することはできません。 「良好な」セットは空であるため、アルゴリズムはこれを即座に検出し、-1 を返します。 

もう 1 つの特殊なケースは、複数のカードがある位置で s[i] と一致する場合です。 その場合、それらのいずれかが最上位のプロバイダーになる可能性があり、アルゴリズムは単一の選択を強制しません。 代わりに、一致しないすべてのカードが一致するすべてのカードよりも下になければならないことのみを強制するため、柔軟性が維持され、ソリューションの過度の制約が回避されます。 

最後のエッジ ケースは、2 サイクルの場合のように、異なる位置にわたる矛盾した制約です。 それぞれの位置は独立して方向を強制しますが、位置を組み合わせるとサイクルが作成される場合があります。 トポロジカルソートはこれをグローバルに検出し、ローカルな制約が一貫しているように見える場合でも正確さを保証します。
