 ## 解決策
 # 問題の理解

 ゼロ以外の整数の配列が与えられます。 サブシーケンスを選択する必要があります。これは、一部の要素を元の順序で保持し、残りを破棄することを意味します。 選択した要素には交互の符号が必要であるため、すべての正の数値の後には負の数値が続き、すべての負の数値の後には正の数値が続く必要があります。 このようなすべてのサブシーケンスの中で、選択した値の可能な最大合計が必要です。 空のサブシーケンスは許可されるため、答えがゼロになる可能性があります。 

配列の長さは次のとおりです$10^5$、値は次のように大きくできます。$10^9$絶対値で言うと。 二次アプローチでは次のことが必要になります$10^{10}$最悪の場合、通常のコンテストの制限時間をはるかに超えた場合の操作。 線形時間に近い解が必要です。$10^5$要素は簡単に管理できます。 

難しい部分は、交互の条件自体ではなく、等号のグループの処理と、数値を取得する方がスキップするよりも悪い可能性があることです。 たとえば、次のようなすべての負の数値の場合:```
3
-5 -2 -7
```答えは次のとおりです。```
0
```常に少なくとも 1 つの要素を選択する不注意な解決策では、誤った出力が発生します。`-2`。 

もう 1 つの特殊なケースは、同じ符号の数値が 1 つだけ取られるグループです。 のために：```
5
3 8 1 -10 5
```最良の答えは`8 - 10 + 5 = 3`。 負の数値の前にすべての正の数値を選択すると、`3 + 8 + 1 - 10 + 5 = 7`、ただし、サブシーケンス内で正の値が隣接しているため、符号は交互になりません。 アルゴリズムは、連続する各符号ブロックから 1 つの値のみが寄与できることを理解する必要があります。 

最後の境界ケースは単一の要素です。```
1
100
```答えは`100`1 要素のサブシーケンスがすでに交互ルールを満たしているためです。 

# アプローチ

 簡単なアイデアは、すべてのサブシーケンスを試して、最も有効なサブシーケンスを保持することです。 長さの配列の部分列の数$n$は$2^n$, そのため、これは適度に小さい配列でも不可能になります。 正または負の数字で終わる最良の回答を記憶する動的プログラミングを使用して、これを改善できます。 これは機能しますが、問題が必要とする以上の状態です。 

重要な点は、同じ符号を持つ連続する数値ブロック内では、部分列には最大 1 つの要素を含めることができるということです。 連続して 2 つの正の数を取ることは交互に違反し、大きな正の数の代わりに小さな正の数を取ることは決して役に立ちません。 同じ理由がネガティブ ブロックにも当てはまります。合計を最大化したいので、最も害の少ない、つまり最大の値を採用する必要があります。 

これにより、問題は配列をスキャンし、配列を等号の最大のブロックに分割し、各ブロックから最大の要素を取り出し、それらの選択された値を加算するという問題に軽減されます。 空のサブシーケンスは自然に処理されます。選択されたブロックの最大値は結果を改善するだけであり、利用可能な選択肢がすべて負の場合、最終的な答えはゼロと比較される必要があります。 

ブルート フォースは、考えられるすべての有効な選択肢を探索するため機能しますが、検索スペースが膨大であるため失敗します。 標識ブロックに関する観察により、不要な選択肢がすべて削除され、各ブロックを最もよく表すものだけが残ります。

 # アルゴリズムのチュートリアル

 1. 最初の要素から始めます。 最初の符号ブロックが作成され、このブロック内の現在の最良の値がその要素になります。 
2. 配列内を左から右に移動します。 現在の要素が現在のブロックと同じ符号を持つ場合、このブロックに保存されている最大値を更新します。 その理由は、サブシーケンスがこのブロックから取得できる値は 1 つだけであるため、可能な限り最良の値を保持するためです。 
3. 符号が変わると前のブロックが終了します。 その最大値を答えに追加し、現在の要素で新しいブロックを開始します。 
4. ループ終了後、更新をトリガーする後続の符号変化がないため、最後のブロックから最大値を加算します。 
5. 結果の合計が負の場合、要素の選択は許可されないため、ゼロが出力されます。 

これが機能する理由: すべての有効なサブシーケンスには、各最大同符号セグメントからの要素を最大 1 つ含めることができます。 貪欲な選択では、すべてのセグメントから可能な限り最大の要素が取得されるため、各セグメントに対して独立して最高の寄与が得られます。 1 つのセグメントから選択しても、別のセグメントからどの値を選択できるかには影響しないため、これらのローカルで最適な選択肢を組み合わせると、グローバルに最適なサブシーケンスが生成されます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    cur = a[0]
    sign = 1 if a[0] > 0 else -1

    for x in a[1:]:
        current_sign = 1 if x > 0 else -1

        if current_sign == sign:
            cur = max(cur, x)
        else:
            ans += cur
            cur = x
            sign = current_sign

    ans += cur

    print(max(ans, 0))

solve()
```変数`cur`現在の符号ブロック内に最適な値を保存します。 すべてのブロックには少なくとも 1 つの値が含まれている必要があるため、最初の配列要素から始まります。 

スキャン中は等号のみが更新されます`cur`有効な交互サブシーケンスでは同じブロックから別の要素を選択することは不可能であるためです。 符号が変わると、前のブロックは成長できなくなるため、その最良の値が追加されます。`ans`。 

ループ後の最後の追加では、最後のブロックが処理されます。 最後のブロックでは符号の変化が発生しないため、この手順を忘れるとよく​​ある off-by-one エラーが発生します。 の`max(ans, 0)`可能なすべての部分列の合計が負である配列を処理します。

# テストケース```python
import sys, io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    cur = a[0]
    sign = 1 if a[0] > 0 else -1

    for x in a[1:]:
        s = 1 if x > 0 else -1
        if s == sign:
            cur = max(cur, x)
        else:
            ans += cur
            cur = x
            sign = s

    ans += cur
    return str(max(ans, 0))

 # エッジケース

 全陰性の場合:```
3
-1 -1 -1
```配列全体が 1 つの負のブロックです。 アルゴリズムは最大値を保持します。これは、`-1`, しかし、それを追加すると合計は減ります。 最後のゼロとの比較では、空のサブシーケンスが正しく選択されます。 

変化が続く兆候の繰り返しの場合:```
5

```最初のブロックはポジティブで貢献します`8`、2 番目のブロックは負であり、寄与します。`-10`、最後のブロックが貢献します`5`。 結果は`3`、有効なサブシーケンスに対応します`[8, -10, 5]`。 

単一の値の場合:```
1
100
```ブロックは 1 つあり、その最大値は`100`。 最後の追加では、特別なコードを必要とせずに正しい答えが得られます。
