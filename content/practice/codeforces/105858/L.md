 ## 解決策
 ## 問題の理解

 私たちは持っています`n`お土産。 各お土産は、2 人の友人のうちの 1 人に割り当てる必要があります。 お土産なら`i`最初の友達に行き、貢献します`a_i`最初の友人には幸せでも、二番目の友人には何もありません。 2 人目の友人に渡した場合、価値については逆のことが起こります`b_i`。 

目標は、最適な分布を 1 つだけ見つけることではありません。 最初のものが必要です`2^min(n,20)`2 人の友人の合計幸福度の絶対差によって並べ替えた場合の分布。 

違いはもっと簡単に書くことができます。 すべてのお土産について、次のように定義します。`d_i = a_i - b_i`最初の友達を選択すると追加されます`d_i`最終差まで。 2人目の友達を選択すると追加されます`-d_i`。 最終的な絶対差は、すべての符号付き合計の絶対値です。`d_i`。 

入力サイズは十分に小さいので、`n`40 に達しますが、可能な配布数は最大です`2^40`、これは約1兆です。 すべてのディストリビューションを列挙するソリューションは不可能です。数十億の操作でさえ、すでに一般的なコンテストの制限時間をはるかに超えているからです。 

出力サイズは意図的に大きくなっています。 いつ`n`40です、印刷しなければなりません`2^20`値、約 100 万件の回答。 これは、アルゴリズムが`O(2^20 log 2^20)`現実的ですが、それに近いものは`O(2^n)`そうではありません。 

最小の差分のみを検出する実装が失敗するケースがいくつかあります。 例えば：```
Input
2
-1 10
-1 10

Output
9 9 11 11
```不注意な解決法では最小値が見つかる可能性があります`9`そしてやめてください。 このタスクには、反復値を含む 4 つの最適な分布が必要です。 

もう 1 つのよくある間違いは、兆候がネガティブな可能性があることを忘れていることです。 考慮する：```
Input
1
-5
10

Output
15 15
```2 つの選択肢が違いを生む`|-5 - 10| = 15`そして`|10 - (-5)| = 15`。 値を常に正として扱うと、答えが変わります。 

最後の厄介な状況は、同じ答えが多数ある場合です。 で：```
Input
4
1 2 3 4
4 3 2 1
```多くの異なる割り当てでは、最小の差は同じになります。 出力には、一意の値だけでなく、これらすべてのコピーが必要です。 

## アプローチ

 直接的なアプローチは、考えられるすべてのお土産の割り当てを生成することです。 割り当てごとに、次の符号付き合計を計算します。`d_i`値を取得し、その絶対値を取得し、すべての結果を収集して並べ替えます。 

これは正しいです。考えられるすべての分布が、まさに 1 つの記号の選択に対応するからです。 ただし、お土産は40個あります。`2^40`可能性。 これらの値を保存することさえ不可能であり、それらを並べ替えるには約 1 兆個の要素が必要になります。 

有益な観察は、答えは最初の部分のみを要求するということです。`2^20`価値観。 お土産を2つに分けることができます。 それぞれの半分には最大 20 個の項目があるため、半分内ですべての符号付き合計を生成できます。 これにより、最大で 2 つの配列が作成されます。`2^20`価値観。 

現在、すべての完全なディストリビューションは次のように表されます。`left_sum + right_sum`問題は、2 つの配列からすべてのペアの中で最小の絶対値を見つけることになります。 

重要なのは、両方の配列をソートできることです。 1 つの値について`x`最初の配列では、2 番目の配列の最良のパートナーが近くにあります。`-x`。 2 番目の配列はソートされているため、1 つの配列のすべての候補が`x`の位置から外側に拡張することで絶対値を大きくすることができます。`-x`が挿入されることになります。 

これらのソートされた候補ストリームを優先キューとマージします。 最初は、すべての左半分の合計が、可能な限り最良のパートナーに貢献します。 現在の最小の答えを削除するたびに、そのストリームのみを次の候補に進めます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 中央 + ヒープで会う | O(2^(n/2) log 2^(n/2)) | O(2^(n/2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`d_i = a_i - b_i`あらゆるお土産に。 最終的な幸福度の差は、これらの値の選択された符号付きバージョンの合計の絶対値です。 
2. 相違点の配列を 2 つの部分に分割します。 各部分には最大 20 個の要素があるため、1 つの部分内のすべての可能な符号付き合計を生成できます。 
3. 後半の合計のリストを並べ替えます。 この順序を使用して、ターゲットに最も近い値をすばやく見つけます。 
4. 合計ごとに`x`前半から挿入位置を見つけます`-x`ソートされた後半の合計。 この位置は、負の合計と正の合計を生成する値を区切ります。 
5. それぞれについて次の候補を 2 つ作成します。`x`：挿入位置の直前の値と挿入位置の値。 これらは最も近い可能性であるため、答えに属することができる最初の値です。 
6. これらすべての候補を絶対差の順に並べた優先キューに入れます。 
7. 最小の候補を繰り返し削除します。 その値を回答リストに追加します。 次に、同じストリームを、削除された候補を生成した側にさらに 1 ステップ移動します。 

ストリーム移動が機能する理由は、前半の値が固定されている場合、右に移動すると挿入ポイントの左側の後半の値が近づき、右に移動すると右側の値が遠ざかるからです。 両側はすでに絶対値でソートされています。 

なぜ効果があるのか:

 すべての固定左和について、絶対最終差分によるすべての可能な右和の順序付けされたシーケンスが得られます。 ヒープには、そのようなすべてのシーケンスからの最小の未使用要素が含まれます。 優先キューのマージでは、常にすべてのシーケンスの中で残っている最小の要素が抽出されるため、生成されるすべての答えは次に小さな可能な分布になります。 すべての分布はちょうど 1 つの半和のペアに属するため、候補が見逃されることはありません。 

## Python ソリューション```python
import sys
import bisect
import heapq

input = sys.stdin.readline

def generate(vals):
    res = [0]
    for v in vals:
        res += [x + v for x in res]
        res += [x - v for x in res[:len(res)//2]]
    return res

def generate(vals):
    res = [0]
    for v in vals:
        cur = []
        for x in res:
            cur.append(x + v)
            cur.append(x - v)
        res = cur
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    diff = [a[i] - b[i] for i in range(n)]

    mid = n // 2
    left = generate(diff[:mid])
    right = generate(diff[mid:])

    right.sort()

    heap = []
    for i, x in enumerate(left):
        pos = bisect.bisect_left(right, -x)
        if pos < len(right):
            heap.append((abs(x + right[pos]), x + right[pos], i, pos, 1))
        if pos > 0:
            heap.append((abs(x + right[pos - 1]), x + right[pos - 1], i, pos - 1, -1))

    heapq.heapify(heap)

    need = 1 << min(n, 20)
    ans = []

    while len(ans) < need:
        _, value, i, j, direction = heapq.heappop(heap)
        ans.append(value if value >= 0 else -value)

        nj = j + direction
        if 0 <= nj < len(right):
            heapq.heappush(
                heap,
                (abs(left[i] + right[nj]), left[i] + right[nj], i, nj, direction)
            )

    print(*sorted(ans))

if __name__ == "__main__":
    solve()
```の`generate`関数は、半分のすべての符号付き合計を計算します。 前回の合計に対して、次のお土産では、お土産の値を加算するか減算するという 2 つの可能性が生じます。 

後半は、二分探索と順序付き展開がその性質に依存するため、ソートされます。 残りの合計ごとに、`bisect_left`以下の最初の後半の値を見つけます。`-x`。 

ヒープには、左半分の和ごとに、現在最も未使用の候補が保存されます。 タプルには、順序付けに使用される絶対値、実際の符号付き差、および抽出後に同じストリームを進めるのに十分な情報が含まれています。 

Python の整数は任意の精度であるため、入力からの大きな値には特別な処理は必要ありません。 唯一の微妙な境界条件は、挿入ポイントの両側をチェックすることです。`-x`ソートされた配列の範囲外である可能性があります。

## 特殊なケース

 幸福度が負の場合は、すべてのお土産を署名付きの寄付に変換することで処理されます。 のために：```
1
-5
10
```差の値は`-15`。 考えられる 2 つの符号付き合計は次のとおりです。`-15`そして`15`したがって、両方の答えは次のようになります。`15`。 

ヒープには考えられるすべての分布が個別に格納されるため、等しい答えが多数あるケースは機能します。 10 個の異なる割り当てで同じ差が生じた場合、その値は結果に 10 回挿入されます。 

境界の場合`-x`右半分のすべての値よりも小さい場合、挿入ポイントが存在する場合、その右側のみを使用して処理されます。 同様に、`-x`がどの値よりも大きい場合は、左側のみが有効です。 これにより、最も近い候補を考慮しながら、無効な位置へのアクセスが回避されます。
