 ## 解決策
 ## 問題の理解

 この問題は、平面を等しい正方形のブロックに繰り返し再分割し、すべてのスケールで中央の特定の領域を削除することによって構築される、無限グリッド上の 2 次元のフラクタル パターンを定義します。 この構築を無限に多くのレベルで行った後、一部のセルは「満たされた」ままになり、他のセルは「穴」になります。 

タスクは、個々のグリッド座標に関するクエリに答えることです。 各クエリはセルの位置を示し、そのセルが再帰的な削除プロセスを経ても生き残るか、構築のあるレベルで削除されるかを判断する必要があります。 通常、出力はクエリごとの 2 値の回答であり、セルがカーペットの一部であるか、削除された領域に属しているかを示します。 

グリッドは概念的には無限ですが、入力内の座標は大きくても有限であり、多くの場合最大約 10^18 です。 これにより、グリッドをシミュレートしたり、中程度のプレフィックスを明示的に構築しようとするアプローチは即座に除外されます。 1 レベルの拡張ですでにグリッド サイズが倍増し、数レベル後には構造が大きすぎて保存したり走査したりできなくなります。 セルの反復処理や 2D 配列の維持に依存するソリューションは、時間とメモリの両方の制限を超えることになります。 

よくある微妙な失敗のケースは、クエリごとにレベルごとに構築をシミュレートしようとしたときに発生します。 たとえば、ルールが中央のセルが削除される 3×3 のサブディビジョンである場合、グリッドをレベル 10 まで構築して点をチェックすると、既に 3^20 スケールの構造を処理することになりますが、これは実行不可能です。 

別の種類の誤った解決策は、トップレベルのサブディビジョンのみをチェックすることから生じます。 たとえば、レベル 1 の中央の削除されたブロック内にはないが、レベル 2 以上の中央のブロック内にある点を考えてみましょう。 チェックが浅い場合、誤って塗りつぶしとしてマークされてしまいます。 

具体的な例として、ルールが各 3×3 ブロックの中央のセルを削除すると仮定します。 点 (1, 1) はすぐに削除されます。 点 (4, 4) は、第 1 レベルの非中心ブロック内にありますが、そのサブブロックにスケールインした後は (1, 1) になるため、これも削除する必要があります。 最初の分解ステップのみをチェックするソリューションでは、(4, 4) に対して誤って「filled」が出力されます。 

主な問題点は、除去が単一のグローバル条件ではなく、すべてのスケールで繰り返し適用されるローカル条件であることです。 

## アプローチ

 ブルートフォースアプローチでは、フラクタル構造を明示的にシミュレートしようとします。 各クエリ ポイントについて、グリッドを維持し、それを繰り返し 3×3 ブロックに再分割し、反復ごとに中央のブロックを削除済みとしてマークします。 理論的には、十分な反復の後、ポイントが存続するかどうかを判断できます。 

このアプローチは、構造の正確な定義に従っているため、正しいです。 ただし、各レベルではブロックの数が 9 倍になるため、構造を明示的にシミュレートする場合は、単一のポイントを含むブロックの追跡に限定してもあまり役に立ちません。 座標が 10^18 まで増加すると、レベル数は log₃(10^18) ≈ 38 程度になり、レベルごとに構造を再構築したりブロックをスキャンしたりする単純なシミュレーションは、多くのクエリを増やすとすぐにコストが高くなります。 

重要な観察は、構造が自己相似であるということです。 すべてのレベルで、すべてのサブスクエア内に同じルールが適用されます。 これは、グリッドを構築する代わりに、クエリ ポイントが連続するスケールされたブロック内のどこに到達するかを追跡するだけでよいことを意味します。 各ステップで問題のサイズが 3 分の 1 に減少します。重要な情報は、ポイントが禁止された中心位置に到達するかどうかだけです。 

したがって、問題は基数 3 の桁分解問題になります。座標を 3 を法として繰り返し削減して、各レベルの 3×3 グリッド内での位置を決定します。 いずれかのレベルで両方の座標が中央のインデックス (1, 1) にある場合、そのポイントは削除されます。

これにより、指数関数的な幾何学構造が対数体系チェックに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(9^d) | O(9^d) | 遅すぎる |
 | Base-3 桁のチェック | クエリあたり O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各クエリ点 (x、y) を読み取ります。 目標は、この点が任意の再帰レベルで削除された中心領域に該当するかどうかを判断することです。 
2. x > 0 または y > 0 の間、3×3 ブロック内の点の現在のローカル位置を繰り返し検査します。 これは、x % 3 と y % 3 を使用して行われます。このステップでは、フラクタルの現在のスケール内のどこに点があるかを特定します。 
3. いずれかのステップで x % 3 == 1 および y % 3 == 1 の場合、ただちに点が削除されたと判断し、このクエリの処理を停止します。 この条件は、再帰レベルごとに削除される 3×3 ブロックの中央セルに正確に対応します。 
4. それ以外の場合は、x //= 3 および y //= 3 を更新して、次の上位レベルに移動します。これにより、フラクタル階層内の親ブロックに効果的にズームアウトされます。 
5. 禁止された中心位置に遭遇することなくループが終了した場合、そのポイントはすべてのレベルに残り、カーペットの一部になります。 

正確さは、各除算ステップが同じ構造を保持するという事実にかかっています。つまり、すべての 3x3 ブロックはパターン全体のスケールされたコピーであるため、基数 3 で桁ごとにチェックすることで再帰的定義が完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_filled(x, y):
    while x > 0 or y > 0:
        if x % 3 == 1 and y % 3 == 1:
            return False
        x //= 3
        y //= 3
    return True

def main():
    q = int(input())
    for _ in range(q):
        x, y = map(int, input().split())
        print("YES" if is_filled(x, y) else "NO")

if __name__ == "__main__":
    main()
```機能`is_filled`基数 3 の点の桁ごとの検査を実装します。各反復では、モジュロ演算を使用して現在のレベルのローカル座標が分離されます。 ポイントが削除された中心に到達した場合は、早期に終了します。 それ以外の場合、整数除算は視点をフラクタルの次のレベルに移します。 

実装の微妙な詳細は、両方の座標をすべてのレベルで同時にチェックする必要があることです。 1 つの座標だけをチェックすると、対角線上または中心から外れた禁止領域にある点が誤って分類されます。 

## 実用的な例

 2 つの点 (1, 1) と (4, 4) を持つクエリ シーケンスを考えてみましょう。 

(1, 1) については、その進行を追跡します。 

| ステップ | × | y | x % 3 | y%3 | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 1 | 削除されました |

 ポイントは中央セルのすぐ中にあるため、カーペットの一部ではありません。 

(4, 4) については、次のように追跡します。 

| ステップ | × | y | x % 3 | y%3 | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 1 | 1 | 削除されました |

 (4, 4) は、最初のスケールでは視覚的に中心ではありませんが、基数 3 で表現するとサブブロックの中心セルにマッピングされるため、これも削除されます。 

これらの例は、最上位レベルだけでなく、すべてのスケールで条件が再帰的に適用されることを示しています。

import sys, io

 ## 特殊なケース

 重要なエッジ ケースは原点 (0, 0) です。 この定式化では、両方の座標がすべてのレベルを通じてゼロのままであるため、削除された中心に該当することはなく、常に塗りつぶしとして分類されます。 ループは禁止条件をトリガーせずにただちに終了するため、アルゴリズムはこれを正しく処理します。 

もう 1 つの微妙なケースは、1 つの座標のみが 3 を法として中心位置に一致する場合です。たとえば、(1, 0) または (0, 1) は削除されません。 削除には両方の座標が同時に 1 を法とする 3 に等しくなる必要があるため、アルゴリズムはそれらを正しく保持します。 

より深いケースは、(3^k + 1, 3^k + 1) など、大きいが削除された小さなセルと構造的に同等のポイントです。 これらは k 回目の反復で (1, 1) に折りたたまれ、ループは最初のレベルではなくそのレベルでの削除を正しく検出します。これは、再帰的チェックが 1 回限りの条件ではなく不可欠であることを示しています。
