 ## 問題の理解

 まず、厳密に増加する一連のタワーの高さから始めます。 その後、ゲームは個別のステップで進化します。 ステップ番号で`j`、隣接するすべての塔のペアを調べます。 タワー間の違いはいつでも`i`そして塔`i-1`まさに`j`、操作を実行します。位置からすべてのタワーを増やします。`i`までに最後まで`1`。 

このプロセスでは時間の経過とともに高さが変化するため、ステップが進むにつれて高さの差と合計の両方が変化します。 重要なのは、モンスター クエリごとに、プロセスが最初の配列から再開され、最初のステップでどのようなステップで実行するかという 1 つの質問をされることです。`j`すべての塔の高さの合計は、そのモンスターを倒すのに十分な大きさになるでしょうか。 

モンスターの答えは、最終ステップが見つかった後の個々のタワーの状態ではなく、時間の経過に伴う合計の変化のみに依存します。 

制約は大きく、最大 100 万のタワーと 100 万のクエリです。 ステップを 1 つずつシミュレートするソリューションはすぐに遅すぎます。`j`それ自体が大きくなる可能性があり、プロセスを単純に繰り返すことはできません。 

微妙な問題がダイナミクスに現れます。操作により配列が変更され、それによって将来の差異が変更されます。 各ペアが一度だけ貢献するという単純な解釈は、プロセスの誤ったモデルにつながり、成長を過小評価することになります。 正しいモデルでは、その差が進化するにつれて、複数のステップにわたって同じ位置が繰り返しトリガーされることを考慮する必要があります。 

素朴な推論を打ち破るエッジケースには、答えがゼロである状況、つまり最初の合計がすでにモンスターを殺してしまっている状況や、非常に大きな金額が発生しているケースが含まれます。`h_i`、その答えは、初期の急上昇ではなく、長期的な直線的な成長によって決まります。 

## アプローチ

 直接シミュレーションでは、配列を維持し、各ステップですべての隣接する差分を再計算します。 それぞれのステップで`j`、すべてスキャンします`n`位置を確認し、更新を適用し、合計を再計算します。 これにはすでに費用がかかります`O(n)`ステップごとに、最悪の場合には`j`それ自体は、配列内の最大値のオーダーまで増加する可能性があります。`1e9`。 たとえプロセスが早期に安定したとしても、スキャンが繰り返されるとこれは不可能になります。 

重要な点は、どのステップでも実際には完全な配列が必要ないということです。 ステップ後のすべての高さの合計のみが必要です`j`。 ステップまでの増分に何回寄与するかを理解していれば、各位置の効果を個別に追跡できます。`j`。 

単一の隣接するペアに注目してみましょう。 定義する`d_i = a_i - a_{i-1}`。 ステップで`d_i`、条件がトリガーされ、次から始まるサフィックスを増やします。`i`。 この操作の後、`a_i`その間増加します`a_{i-1}`そうでないため、差が大きくなります`d_i`による`1`。 これは、ステップで`d_i + 1`、条件は再び true になります。 同じロジックが無限に繰り返されます。つまり、ポジションが発射を開始すると、後続のすべてのステップで発射が継続されます。 

これにより、インデックスごとにプロセスが累積的な効果に変わります。`i`、すべてのステップでサフィックスの合計に寄与します。`j`そのような`j >= d_i`、その寄与は時間とともに直線的に増加します。 

これから、ステップ後の合計を表すことができます`j`純粋に初期データに関して。 各インデックスは等差数列に寄与します。`j`、最初の差とその重み (サフィックス内の要素の数) のみに依存します。

 ## アルゴリズムのチュートリアル

 ### 1. 違いの構造を構築する

 コンピューティング`d_i = a_i - a_{i-1}`あらゆる人にとって`i >= 2`。 それぞれ`d_i`いつ位置を決定するか`i`合計額に影響を及ぼし始めます。 

重みも定義します`w_i = n - i + 1`、これは正確に、配置時に増加するタワーの数です。`i`トリガー。 

### 2. アクティベーション時間で貢献を並べ替えます

 すべてのペアを並べ替えます`(d_i, w_i)`による`d_i`。 これにより、特定のステップでアクティブなポジションの数を効率的に推論できるようになります。`j`。 

### 3. プレフィックス集約を構築する

 ソートされた位置にわたってプレフィックスの合計を維持します。`W(k) = sum of w_i for d_i <= k`

`WD(k) = sum of w_i * d_i for d_i <= k`これらを使用すると、すべてのインデックスを反復処理することなく、任意のステップまでの合計寄与度を計算できます。 

### 4. 指定されたステップでの合計を評価する

 固定の場合`j`、各インデックスは次の場合にのみ寄与します。`d_i <= j`、その貢献度はアクティブなステップ数に比例します。 

合計は次のようになります。`S(j) = base + sum w_i * (j - d_i + 1) for all d_i <= j`プレフィックス値を使用してこれを展開すると、次のようになります。`S(j) = base + j * W(j) - (WD(j) - W(j))`この式により計算が可能になります`S(j)`ソート済みの二分探索を使用した対数時間で`d_i`。 

### 5. 二分検索を使用して各クエリに回答します

 モンスターの体力ごとに`h`、最小のものを二分探索します`j`そのような`S(j) >= h`。 

含まれます`j = 0`何も操作を行っていない初期状態です。 

### なぜ効果があるのか

 各ポジション`i`アクティブ化時間後は独立して合計額に寄与します`d_i`。 アクティブになると、その寄与はステップ数に応じて直線的に増加します。 アクティブ化時間は初期の差にのみ依存し、減少することはないため、アクティブなインデックスのセットは単調になります。`j`。 これにより、次のことが保証されます`S(j)`単調増加なので二分探索が有効になります。 各寄与は次の一次関数に分解されるため、プレフィックス式は二重にカウントすることなくすべてのアクティブな寄与を正確に取得します。`j`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    h = list(map(int, input().split()))

    base = sum(a)

    events = []
    for i in range(1, n):
        d = a[i] - a[i - 1]
        w = n - i
        events.append((d, w))

    events.sort()

    ds = [0]
    ws = [0]
    wds = [0]

    for d, w in events:
        ds.append(d)
        ws.append(ws[-1] + w)
        wds.append(wds[-1] + w * d)

    def S(j):
        # find last d_i <= j
        lo, hi = 0, len(events)
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if ds[mid] <= j:
                lo = mid
            else:
                hi = mid - 1
        k = lo

        W = ws[k]
        WD = wds[k]

        return base + j * W - (WD - W)

    def can(j, target):
        return S(j) >= target

    max_d = max([d for d, _ in events], default=0)
    ans = []

    for target in h:
        lo, hi = 0, max(max_d, target) + 1

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, target):
                hi = mid
            else:
                lo = mid + 1

        ans.append(str(lo))

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```コードはまず、初期の差分を使用してすべての遷移ポイントを圧縮します。 次に、プレフィックス合計を構築して、任意のステップですべてのアクティブなインデックスの合計寄与度を評価します。 機能`S(j)`ステップ後の合計ダメージを計算します`j`アクティブ化しきい値に対する二分探索を使用した対数時間での。 

外側の二分探索は、計算されたダメージが各モンスターに必要なしきい値に達する最も早いステップを見つけます。 

微妙な点は、`j = 0`、これは更新前の初期配列に対応します。 これは、返すことによって計算に自然に含まれます。`base`アクティブなイベントがないとき。
