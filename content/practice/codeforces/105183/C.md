 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$。 連続したセグメントについては、そのセグメント内にそれぞれの個別の値が何回出現するかを調べます。 これにより、周波数のマルチセットが生成されます。 これらの周波数自体が順列を形成する場合、セグメントは「特別」と呼ばれます。つまり、ゼロ以外の周波数をすべてリストすると、それらの周波数には以下の各整数が含まれます。$1$個別の値の数まで 1 回だけ。 

あらゆる可能な値に対して$i$、正確にいくつのセグメントがあるかを数えなければなりません$i$異なる値を持ち、この周波数の順列条件を満たします。 

出力はシーケンスです。$i$- 番目の数字は、セグメントが正確にいくつあるかを示します。$i$個別の要素とその周波数マルチセットが次の順列である$\{1, 2, \dots, i\}$。 

制約$n \le 2 \cdot 10^5$すべてを列挙するソリューションは除外されます。$O(n^2)$セグメント化して周波数を最初から計算します。 平$O(n^2 \log n)$不可能です。 各セグメントが個別に処理されるのではなく、貢献度が間接的に集計またはカウントされる方法が必要です。 

微妙な問題は、値の範囲が次のとおりであることです。$10^9$したがって、周波数配列またはマップを効率的に維持するには座標圧縮が必要です。 

よくある落とし穴の 1 つは、条件を誤解することです。周波数は任意ではなく、正確に次の順列でなければなりません。$1 \dots k$。 たとえば、次のような周波数$[1, 1, 2]$重複と欠損値があるため失敗します$3$。 もう 1 つの失敗例は、「すべての周波数が異なる」だけで十分であると想定していることですが、これは当てはまりません。$[1, 3, 5]$サイズ 3 ではまだ失敗します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのセグメントを列挙します。$[l, r]$、その中のすべての値の頻度を計算し、ゼロ以外の頻度のリストを抽出し、それが順列であるかどうかを確認します。 これは定義に直接従うため、正しいです。 ただし、各セグメントの頻度マップを維持するにはコストがかかります$O(n)$、につながる$O(n^3)$最悪の場合は合計、または$O(n^2)$増分更新ではまだ大きすぎます。$2 \cdot 10^5$。 

重要な観察は、「周波数が順列を形成する」という制約が非常に厳格であるということです。 セグメントに$k$個別の値の場合、頻度はセグメント長に合計され、正確に並べ替えられたものでなければなりません。$1, 2, \dots, k$。 これは、セグメントの長さが一度固定されることを意味します。$k$選ばれています: そうでなければなりません$$1 + 2 + \dots + k = \frac{k(k+1)}{2}.$$したがって、次の有効なセグメントは$k$個別の値は正確な長さを持たなければなりません$T_k = k(k+1)/2$。 これはすぐに限界を迎えます$k$による$O(\sqrt{n})$、大きいので$k$作る$T_k > n$。 

これにより、問題は任意の長さのスライディング ウィンドウから、ターゲット ウィンドウの長さの制限されたファミリーに変換されます。 それぞれの可能性について$k$、長さのセグメントをカウントするだけで済みます。$T_k$その周波数マルチセットは順列条件を満たします。 

ここでのタスクは次のようになります。固定ウィンドウ サイズに対して、非常に構造化された周波数制約を満たすウィンドウの数を数えます。 これは、頻度テーブルを維持し、各頻度を持つ値の数を追跡しながら、スライディング ウィンドウを使用してチェックできます。 置換条件は、再計算するのではなく、段階的に維持できます。 

これにより問題は次のように縮小されます$O(\sqrt{n} \cdot n)$、それは実現可能です。

 ## アルゴリズムのチュートリアル

 周波数をコンパクトな値でインデックス付けされた配列に格納できるように、座標圧縮を使用して配列を前処理します。 

それぞれについて$k \ge 1$、ターゲットウィンドウサイズを計算します$T_k = k(k+1)/2$。 もし$T_k > n$、やめます。 

次に、長さのウィンドウをスライドさせます$T_k$配列全体にわたって周波数情報を維持し、現在のウィンドウが置換条件を満たしているかどうかを確認します。 

### ステップ

 1. 配列値を範囲に圧縮します。$[0, m-1]$。 これにより、ハッシュ マップを使用せずに周波数配列に直接インデックスを作成できるようになり、更新が維持されます。$O(1)$。 
2. それぞれについて$k \ge 1$、計算する$T_k = k(k+1)/2$。 もし$T_k > n$このタイプの有効なセグメントは存在できないため、ブレークします。 
3. 周波数配列を初期化する`cnt[val] = 0`と補助構造`freqCount[f]`現在頻度を持っている値の数を追跡します$f$。 この構造により、周波数が正確に形成されているかどうかを知ることができます。$1..k$すべての値をスキャンせずに。 
4. 適切なサイズの最初のウィンドウを構築します$T_k$。 要素ごとに、その周波数を更新します。古い周波数クラスをデクリメントします。`freqCount`、新しい周波数クラスをインクリメントし、更新します`distinct`周波数が0から1になるときにカウントします。 
5. 以下を確認して、現在のウィンドウが有効かどうかを確認します。 

個別の要素の数は正確に$k$、

 そしてあらゆる人にとって$j \in [1, k]$、頻度を持つ値は 1 つだけです$j$。 

2 番目の条件は次を使用して検証されます。`freqCount[j] == 1`。 
6. 左側の要素を削除し、次の右側の要素を追加してウィンドウをスライドさせます。 アップデートごとに調整`cnt`そして`freqCount`一定時間内に。 
7. ウィンドウ位置ごとに、条件を満たす場合、次の答えをインクリメントします。$k$。 

### なぜ効果があるのか

 重要な不変条件は、すべてのステップで、`cnt`現在のウィンドウ内の周波数を正しく表現し、`freqCount[f]`現在頻度を持っている個別の値の数を正確に追跡します$f$。 更新は要素の挿入および削除ごとにアトミックに行われるため、古いカウントは残りません。 

ウィンドウは、その頻度分布が次の順列と一致する場合に正確にカウントされます。$1..k$。 を通じて強制される条件`freqCount`完全性 (すべての周波数 1..k が表示される) と一意性 (それぞれが 1 回だけ表示される) の両方が保証され、これらが合わせて必要な構造を定義します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # coordinate compression
    vals = {v: i for i, v in enumerate(sorted(set(a)))}
    a = [vals[v] for v in a]
    m = len(vals)

    ans = [0] * (n + 1)

    for k in range(1, n + 1):
        need_len = k * (k + 1) // 2
        if need_len > n:
            break

        cnt = [0] * m
        freq_cnt = [0] * (need_len + 2)

        distinct = 0

        def add(x):
            nonlocal distinct
            old = cnt[x]
            if old > 0:
                freq_cnt[old] -= 1
            cnt[x] += 1
            new = cnt[x]
            freq_cnt[new] += 1
            if old == 0:
                distinct += 1

        def remove(x):
            nonlocal distinct
            old = cnt[x]
            freq_cnt[old] -= 1
            cnt[x] -= 1
            new = cnt[x]
            if new > 0:
                freq_cnt[new] += 1
            if new == 0:
                distinct -= 1

        for i in range(need_len):
            add(a[i])

        def ok():
            if distinct != k:
                return False
            for f in range(1, k + 1):
                if freq_cnt[f] != 1:
                    return False
            return True

        if ok():
            ans[k] += 1

        for i in range(need_len, n):
            add(a[i])
            remove(a[i - need_len])
            if ok():
                ans[k] += 1

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```実装は固定ごとのスライディング ウィンドウに従います。$k$。 周波数配列`cnt`それぞれにローカルな$k$これにより、異なるウィンドウ サイズ間の相互汚染が回避されます。 の`freq_cnt`array は、現在各周波数を持つ値の数を追跡します。これは、分布の再計算を回避する中心的な最適化です。 

機能`ok()`意図的に単純ですが呼び出されます$O(n)$回あたり$k$、これは許容されます。$k$までしか上がりません$O(\sqrt{n})$。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 入力用`[5,5,5,5]`、 のみ$k=1$大きいものでも機能するので、$k$には複数の個別の値が必要ですが、これを満たすことができません。 アルゴリズムはこれを正しく処理します。`distinct != k`すべてがすぐに失敗します$k > 1$。 

もう 1 つのエッジ ケースは、値が完全に交互になる場合です。`[1,2,1,2,1,2]`。 ここでは、サイズ 3 の複数のウィンドウが満たされます。$k=2$、周波数追跡により、重複するウィンドウがすべて独立してカウントされ、二重にカウントされたり、遷移が欠落したりすることがなくなります。 

最後のエッジケースは次のような場合です$T_k$に近いです$n$、ウィンドウが 1 つだけ、または存在しない場合。 初期化によって最初の完全なセグメントが構築され、ループは単に実行されないか、特別なケースを必要とせずに 1 回だけ実行されるため、スライディング ウィンドウは引き続き正しく動作します。
