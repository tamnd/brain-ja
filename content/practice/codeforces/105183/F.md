 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた配列が与えられます。ここで、各位置はストリートを表し、各ストリートはその「強さ」または「サイズ」を表す正の値 a[i] を持ちます。 

インデックス i1 < i2 < ... < ik の部分列を選択する必要があります。 選択されたインデックスは、すべての連続するペア間の間隔ルールを尊重する必要があります。つまり、選択された 2 つの位置間の距離は、少なくとも対応する 2 つの値のうち小さい方でなければなりません。 言い換えれば、選択した 1 つのストリートから次のストリートへの移動は、インデックスの差が 2 つのストリートのうち弱い方を「受け入れる」のに十分な大きさである場合にのみ許可されます。 

課題は、このルールを尊重しながら選択できるインデックスの数を最大化することです。 

n ≤ 10^6 という制約は、インデックスのペアに対する二次アプローチが直ちに不可能であることを意味します。 O(n log n) の解であっても、ペア間のすべてのエッジを明示的に保存または処理することはできないため、慎重に構造化する必要があります。 どのようなソリューションでも、以前の多くの状態を再検討することなく、各位置を含めるかスキップするかを、線形または線形に近い時間でローカルに効果的に決定する必要があります。 

制約が a[i] と a[j] の両方の値に依存するという事実から、微妙な困難が生じます。 これにより、制約が 1 つのエンドポイントのみに依存する標準的な「純粋な」間隔スケジュールの定式化が除外されます。 

単純なアプローチでは、以前に選択されたすべての要素に対して動的プログラミングを試みる可能性がありますが、これには以前の多くの状態との互換性をチェックする必要があり、拡張できません。 

素朴で貪欲な直感を打ち破ることが多いエッジ ケースの 1 つは、大きな値がクラスター化される場合です。 たとえば、セグメントの値が [5, 6, 7, 8] である場合、隣接するインデックスの違いは 1 だけであり、min(5,6)、min(6,7) などより小さいため、連続した選択は不可能になります。「常に高い値を取得するのが良い」と想定する誤った貪欲なアプローチは失敗します。1 つの大きな要素を取得すると、将来の多くの選択がブロックされる可能性があるためです。 

もう 1 つの注意が必要な状況は、小さい値と大きい値を交互に使用することです。 たとえば、[1, 100, 1, 100, 1] では、ほぼすべてのインデックスを選択できますが、小さな値を早期にスキップする単純な戦略は、将来の柔軟性を不必要に低下させる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての有効なサブシーケンスが試行されます。 現在のサブシーケンスごとに、j - i ≥ min(a[i], a[j]) を満たすすべての可能な次のインデックス j > i で拡張を試みます。 各要素が潜在的に多くの有効な継続に分岐し、遷移のチェックさえ O(n^2) で済むため、これはすぐに指数関数的になります。 

自然な改良は、dp[i] が i で終わるサブシーケンスの最大長である動的プログラミングです。 dp[i] を計算するには、すべての j < i をスキャンし、j が i に接続できるかどうかを確認します。 これは正しいですが、コストが O(n^2) となり、n が 10^6 までの場合は遅すぎます。 

重要な構造的観察は、移行の実現可能性は最後に選択されたインデックスのみに依存するということです。 最後に選択した位置 j を決定すると、すべての候補 i が j に対して独立して評価されます。 サブシーケンスを拡張するための条件は最後の要素に対して純粋にローカルであるため、j より前のことを覚えておく必要はありません。 

これは、実際には以前のすべての状態にわたる一般的な DP を解いているのではなく、エッジがローカル互換性条件をエンコードする有向非巡回グラフ内の単一の最長チェーンを構築していることを示唆しています。 このような設定では、選択を遅らせても将来の実現可能性が向上することはないため、常に可能な限り早い有効な拡張を採用することで、最適なチェーンを貪欲に見つけることができます。 

これにより、問題は、最後に選択された要素に対する単一のポインターを維持し、前方に 1 回スキャンして、各位置が現在のチェーンを拡張できるかどうかを判断するという問題に軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ペア上の DP | O(n^2) | O(n) | 遅すぎる |
 | 貪欲なチェーン構築 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 最後に選択したインデックスを常に維持しながら、左から右に貪欲にサブシーケンスを構築します。 

1. 要素を選択せず​​に開始し、回答の長さをゼロに初期化します。 
2. 1 から n までのインデックスを昇順に繰り返します。 
3. インデックスがまだ選択されていない場合は、最初のインデックスをサブシーケンスの開始として選択します。 事前制約がないので安全です。 
4. 次のインデックス i ごとに、最後に選択したインデックス j に従うことができるかどうかをテストします。 条件は、i - j が少なくとも min(a[j], a[i]) でなければならないということです。 これが当てはまる場合、i をサブシーケンスに追加し、j を i に更新します。 
5. 条件が失敗した場合は、i をスキップして続行します。 i を取ると最後に選択した要素の間隔ルールに違反するため、スキップが必要です。 
6. 配列の最後まで続行し、チェーンの延長に成功した回数を数えます。 

重要な考え方は、アルゴリズムが以前の決定を決して再考しないということです。 インデックスは、一度スキップされると再検討されることはなく、一度インデックスが取得されると、それが将来のすべての決定の唯一の参照点になります。 

### なぜ効果があるのか

 サブシーケンス制約は、隣接する選択された要素にのみ依存するため、構造全体がチェーンを形成し、各リンクが前のリンクに対して独立して検証されます。 最後に選択した固定位置 j にいる場合、有効な拡張子 i は、以前の履歴ではなく、j と i にのみ依存します。 すべての実現可能な拡張の中で、可能な限り早いものを選択しても、将来のオプションの数を減らすことはできません。将来の実現可能性は最後に選択されたインデックスにのみ依存し、より小さいインデックスを選択すると、潜在的により大きな a[i] を持つ後のインデックスに選択を延期する場合と比較して、後続のステップのギャップ要件が常に小さくなるか等しいためです。 これにより、有効な拡張機能をスキップして後の拡張機能を優先するという利点がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    last = -1
    ans = 0

    for i in range(n):
        if last == -1:
            last = i
            ans += 1
        else:
            if i - last >= min(a[i], a[last]):
                last = i
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは単一のポインターを維持します`last`、サブシーケンス内で最後に選択されたインデックスを追跡します。 新しいインデックスごとに、問題ステートメントとまったく同じ条件を使用してチェーンの拡張の妥当性をチェックします。 有効な場合は、すぐにコミットします。これは、貪欲に最大チェーンを構築することに相当します。 

よくある実装上の落とし穴は、Python では 0 から始まるインデックスが使用されているのに、問題ステートメントではインデックスが 1 から始まることを忘れていることです。 条件は差分のみに依存するため、両側が一貫している限り、インデックスを変更しても正確さに影響しません。 

もう 1 つの微妙な点は、サブシーケンス自体を保存する必要はなく、最後に選択した位置と長さのみを保存する必要があることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が等しく、大きい場合です。 例えば、`n = 4, a = [10, 10, 10, 10]`。 連続する各ペアには少なくとも 10 の距離が必要ですが、インデックスの間隔は 1 だけであるため、アルゴリズムは最初の要素のみを選択します。 貪欲なプロシージャは、条件が満たされていないため、後続のすべてのインデックスを正しく拒否します。`i - last >= 10`あらゆる段階で失敗します。 

もう 1 つのケースは、非常に小さい値と非常に大きい値が混在している場合です。 のために`a = [1, 100, 1, 100, 1]`の場合、値が小さい隣接ペアごとに最小距離 1 が強制され、常に満たされるため、アルゴリズムは選択を交互に行います。 これは、値が大きくても、隣接するか密に詰め込まれていない限り、本質的にチェーンの長さは短くならないことを示しています。 

最後のエッジケースは、小さな値が長く続いた後、大きな値が遅れて現れる場合です。 最後に選択されたインデックスでギャップ条件が成立する場合、アルゴリズムはそれを受け入れます。これは、決定が常に純粋にローカルであり、以前にスキップされた機会に依存しないことを示しています。
