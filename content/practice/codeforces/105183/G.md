 ## 問題の理解

 私たちは 8 × 8 のボード上でチェスのような一連の動きを与えられます。 初期設定は固定されています。白いピースは行 1 と 2 のすべてのマス目を占め、黒いピースは行 7 と 8 を占めます。すべてのピースは永続的に一方の側に属します。 プロモーションや新しい作品の作成はありません。 

各移動は、指定された開始マスから既存のピースを 1 つ取り出し、それをターゲットマスに配置することを表します。 重要な簡素化は、ジオメトリに関係なく、ピースを任意の正方形に移動できることです。 唯一の制限は、同じ色のピースが現在占有しているマス目にピースを配置できないことです。 移動先のマスに相手の駒がある場合、その相手の駒は取り除かれます。 

一連の動きは時系列順に記載されていますが、記録には誤りが含まれる可能性があります。 移動が行われるはずの時点で、移動される駒が開始マスに存在しない場合、または開始マスに以前に削除されていない正しい色の駒が含まれていない場合、移動は無効とみなされます。 一度無効になった移動は、その後のすべてが無効になります。 最初の i の動きで既に矛盾が生じるような最小のインデックス i を見つけなければなりません。 矛盾が現れない場合は、-1 を出力します。 

制約は小さく、最大手数は 100 で、ボードには 64 マスしかありません。 これは、プロセスを直接シミュレートできることをすぐに示唆しています。 ボードの状態を明示的に追跡し、移動ごとに更新するソリューションは、簡単に十分に高速です。 

主な微妙な点は、ピースがキャプチャされると消えるため、最初に不可能だったという理由ではなく、ピースが以前にすでに削除されていたために、手が無効になる可能性があることです。 単純な間違いは、その作品がその時点でまだ存在しているかどうかではなく、かつて存在したかどうかだけを確認することです。 

2 番目の微妙なケースは、同じ色の複数の部分が概念的に入力内の同じ正方形から始まる場合に発生します。 これは有効な状態では不可能であるため、これが発生した場合はすでに不整合を示しています。 

## アプローチ

 最も直接的なアプローチは、8 × 8 のボードを維持し、動きを 1 つずつシミュレートすることです。 各セルには、ピースがないか、白いピース、または黒いピースが含まれています。 移動するたびに、開始マスに現在正しい色のピースが含まれているかどうかを確認します。 そうでない場合は、このステップでレコードに一貫性がないことがすぐにわかります。 

開始マスが有効な場合は、そこからピースを削除し、目的のマスに置きます。 移動先のマスに相手の駒がある場合は、単純に上書きします。 同じ色の駒が含まれている場合、味方の駒の上に置くことはルールで禁止されているため、その手は無効となります。 

n は最大 100 であるため、各演算は O(1) であり、このアプローチはすでに最適です。 

状態空間は小さく、更新は一定時間であるため、より高度なデータ構造は必要ありません。 さらに最適化を試みても、正確性が複雑になるだけで、パフォーマンスは向上しません。

 ## アルゴリズムのチュートリアル

 ボードを 2D 配列として表します。 各セルには、空の場合は 0、白の場合は 1、黒の場合は 2 が格納されます。 

行 1 と 2 を白いピースで埋め、行 7 と 8 を黒いピースで埋めてボードを初期化します。 

順番に動きを処理していきます。

1. 各移動 i について、(x1, y1, x2, y2) を読み取ります。 座標をボードのインデックスとして直接解釈します。 このステップでは、現時点で推論している正確な正方形を設定します。 
2. 開始セル (x1、y1) を確認します。 空の場合、移動する駒が存在しないため、i 番目の移動は直ちに無効になります。 前の動きでは矛盾が生じなかったので、停止して i を返すことができます。 
3. (x1, y1) の駒の色が予想されるプレイヤーと一致することを確認します。 移動順序が交互になります。奇数のインデックスでは白が移動し、偶数のインデックスでは黒が移動します。 色が一致しない場合、プレイヤーは相手の駒を動かすことができないため、構造的な矛盾が生じます。 
4. 宛先セル（x2、y2）を確認します。 移動者と同じ色の駒が含まれている場合、その移動は味方の駒の上に駒を置くことができないというルールに違反します。 これはボードを更新する前に検出する必要があります。 
5.移動先に相手の駒があった場合は捕獲したものとして上書きします。 
6. 最後に、ピースを移動します。(x1, y1) をクリアし、(x2, y2) を移動する色に設定します。 

すべての手が矛盾なく処理された場合は、-1 を返します。 

### なぜ効果があるのか

 ボード配列は常に、有効な手のプレフィックスを処理した後の正確な状態を表します。 すべての無効な動きは、ルール内の存在または占有の制約の違反に正確に対応します。 手は順番に適用され、各手は現在のボードの状態にのみ依存するため、矛盾は状態が不可能になる最も早い時点で現れるはずです。 したがって、最初に検出された無効な手が、矛盾が生じる最小のインデックスであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    board = [[0] * 9 for _ in range(9)]
    
    for i in range(1, 3):
        for j in range(1, 9):
            board[i][j] = 1
    
    for i in range(7, 9):
        for j in range(1, 9):
            board[i][j] = 2
    
    for i in range(1, n + 1):
        x1, y1, x2, y2 = map(int, input().split())
        
        piece = board[x1][y1]
        
        if piece == 0:
            print(i)
            return
        
        expected = 1 if i % 2 == 1 else 2
        if piece != expected:
            print(i)
            return
        
        if board[x2][y2] == expected:
            print(i)
            return
        
        board[x1][y1] = 0
        board[x2][y2] = expected
    
    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、説明どおりに最初のボードを構築することから始まり、白いピースが行 1 と 2 を占め、黒いピースが行 7 と 8 を占めます。その後、シミュレーションは 1 行ずつ進み、状態の変更を適用する前に妥当性をチェックします。 

重要な順序は、ボードを変更する前に手を検証することです。 これにより、正当性チェックに必要な情報を誤って上書きすることがなくなります。 空の開始マスのチェックは、すでにキャプチャされたピースの使用を防ぐ主な手段であり、色の交互チェックは、移動シーケンスがターン順序を尊重することを保証します。 

## 実用的な例

 ### トレースの例

 初期のキャプチャが後の移動を無効にする、3 つの移動の単純化されたシーケンスを考えてみましょう。 

| ステップ | 移動 | 開始セル | 終了セル | 理事会結果 | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | W 移動 | ピースは存在します | 空 | 移動が適用されました | はい |
 | 2 | B 移動 | Wピースをキャプチャ | 上書きします | ボードが更新されました | はい |
 | 3 | W 移動 | 同じスタートを再利用 | 空 | 無効 | いいえ |

 ステップ 3 で、白のプレーヤーはステップ 2 ですでにキャプチャされた駒を移動しようとします。そのため、シミュレーションは正しく停止します。 

これは、正確さが初期配置だけでなく追跡除去に依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ピースがキャプチャされ、後で開始ピースとして参照される場合です。 そのような状況では、ボード セルは空になり、そこから移動しようとする試みは即座に失敗する必要があります。 シミュレーションでは他の処理を行う前に占有を明示的にチェックするため、このケースは自然に処理されます。 

もう 1 つのケースは、同じ色が占めるマス目に駒を配置しようとする場合です。 現在の状態を常にボード配列に保存するため、これは上書きする前に一定時間でチェックされます。 誤って最初に更新してから確認すると、違反を検出するために必要な情報が失われます。 

最後の微妙なケースは、無効な動きが繰り返されることです。 最初の無効な手が見つかったら、答えはそのインデックスでなければならず、スキャンを続行してはなりません。 アルゴリズムは即座に戻り、最小のインデックスを見つける要件を維持します。
