 ## 解決策
 ## 問題の理解

 私たちには固定のトレーニング日数と目標総トレーニング時間数が与えられています。 毎日、通常のトレーニング時間または増加したトレーニング時間のいずれかに貢献します。 通常の日では常に 24 時間のトレーニングが提供されますが、特別な「スーパーデイ」では代わりに 72 時間のトレーニングが提供されます。 タスクは、スーパーデイの数をできる限り少なく保ちながら、すべての日の合計累積トレーニング時間が必要な目標以上になるように、利用可能な日数のうち何日をスーパーデイに変えるかを選択することです。 

入力は、利用可能な日数と必要な合計トレーニング時間の 2 つの数値で構成されます。 出力は、目標合計を超えるためにスーパーデイにアップグレードする必要がある最小日数を表す単一の整数です。 

必要な時間が日数の 72 倍を超えないという制約により、実現可能性が保証されます。 たとえ毎日がスーパーデーであっても、目標は必ず達成できます。 

複雑さの観点から見ると、どちらの値も 100,000 に達する可能性があります。 これにより、再帰または徹底的な検索を使用して、1 日あたりのスーパーデイのすべての可能な選択肢をシミュレートしようとするアプローチは除外されます。これは、日数が増えるにつれて指数関数的に増加するためです。 数日にわたる二次ループでさえ、単独では安全ですが、その必要はありません。 問題の構造は、単一の整数パラメーターを最適化していることを示唆しているため、閉じた形式または貪欲な推論が期待されます。 

素朴な推論を打ち破る可能性のある微妙なケースは、スーパーデイなしで目標がすでに達成可能である場合に現れます。 たとえば、5 日があり、目標が 100 時間である場合、通常のスケジュールではすでに 120 時間が与えられています。 この場合、正しい答えはゼロであり、盲目的に正の要件を計算する式は間違っています。 

ターゲットが通常の合計と正確に等しい場合、別のエッジ ケースが発生します。 たとえば、3 日間で目標が 72 の場合、スーパーデイは必要ありません。 解には必然的にマイナスになる可能性のある減算が含まれるため、これらの境界条件は重要です。 

## アプローチ

 強引なアイデアは、0 から d までのスーパーデイのすべての可能な数を試し、各選択肢の合計トレーニング時間を計算し、最小の有効な値を選択することです。 各候補 x について、合計時間は 24(d − x) + 72x として計算されます。 すべての可能性をチェックするには O(d) 回の評価が必要で、各評価は O(1) であるため、全体の複雑さは O(d) になります。 d が 100,000 までであれば、これでも許容できますが、不必要であり、概念的に必要以上に重くなります。 

重要な観察は、通常の日をスーパーデーに置き換えてもスケジュールの構造は変更されず、固定量の追加トレーニングが追加されるだけであるということです。 通常の日は 24 時間寄与するのに対し、スーパーデイは 72 時間寄与するため、1 日アップグレードすると、通常のままにした場合と比べて、純利益は 48 時間増加します。 これにより、問題は単純な増分ゲイン シナリオに変換されます。つまり、すべて通常の日から開始し、ベースラインの合計を計算し、目標に到達するまでに 48 時間の増分が何回必要かを尋ねます。 

これにより、問題は 24d + 48x ≥ h となる最小の整数 x を見つけることになります。 この不等式を直接解くと、天井分割を使用した閉じた形式の式が得られ、数日にわたるシミュレーションの必要がなくなります。

 ## アルゴリズムのチュートリアル

1. すべての日が正常な場合の合計トレーニング時間 (24 × d) を計算します。 これは、アップグレードを行わない場合のベースライン容量を表します。 
2. このベースラインがすでにターゲット h を満たしているか超えている場合は、スーパーデイは必要ないため、0 を返します。 
3. それ以外の場合は、h − 24 × d として定義される残りの不足分を計算します。 これは、数日のアップグレードによって提供される必要がある追加の時間数です。 
4. 各スーパーデイは、通常の日と比較して 48 時間追加されるため、不足分をカバーするために必要な追加時間の数を決定します。 これは、48 × x ≥ 不足となる最小の整数 x として計算されます。 
5. 答えとして x を返します。 

この正しさは、すべての有効なスケジュールを、すべての非スーパーデイが通常日であり、すべてのスーパーデイが同一のアップグレードであるスケジュールに変換できるという事実から得られます。 すべてのアップグレードには同一の限界利益があり、日間の相互作用がないため、問題は単一の変数に対する単純な線形カバレッジ問題になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    d, h = map(int, input().split())
    
    base = 24 * d
    if base >= h:
        print(0)
        return
    
    deficit = h - base
    # each superday adds 48 extra hours compared to normal day
    x = (deficit + 48 - 1) // 48
    print(x)

if __name__ == "__main__":
    solve()
```この実装は、派生した式を直接反映します。 最初のステップでは、ベースライン合計を計算します。 早期復帰は、アップグレードが必要ない重要な境界ケースを処理します。 残りの計算では、浮動小数点の不正確さを避けるために整数演算を使用して実装された上限除算が実行されます。 表現`(deficit + 47) // 48`赤字が 48 で割り切れない場合に、正しく切り上げられるようにします。

 ## 特殊なケース

 重要な境界の 1 つは、アップグレードせずに要件がすでに満たされている場合です。 入力用`d = 2, h = 40`, the baseline is 48 hours. 不足分は計算されないため、アルゴリズムは比較ステップの後にすぐにゼロを返します。 これにより、負の算術演算が上限式に伝播するリスクが回避されます。 

もう1つのケースは、赤字が1回のスーパーデイ拠出金よりも小さい場合です。 例えば`d = 1, h = 50`、ベースラインは 24、不足分は 26 です。スーパーデーが 1 つ増えると 48 時間が追加されるため、天井分割は 1 を生成し、単一のアップグレードが正しく選択されます。 

最後の構造的なケースは、毎日をアップグレードする必要がある場合に発生します。 のために`d = 3, h = 216`、ベースラインは 72、不足分は 144 です。各スーパーデイは 48 を寄与するため、ちょうど 3 つのスーパーデイが必要です。 式は自然に飽和します。`d`ターゲットが可能なトレーニング合計の最大値に近づいたとき。
