## 問題の理解

 ある正多角形の 3 つの頂点の座標が与えられています。 多角形自体は不明です。多角形の辺がいくつあるか、中心がどこにあるのか、3 つの点がどの頂点に対応するのかがわかりません。 これら 3 つの点を頂点として含むすべての正多角形の中で、面積が最小のものを見つけなければなりません。 

重要な幾何学的事実は、すべての正多角形には外接円があるということです。 すべての頂点は同じ円上にあり、角度によって等間隔に配置されます。 同一線上にない 3 つの点によって一意に円が決定されるため、3 本の柱によってすでに外接円が完全に固定されています。 残る唯一の問題は、与えられた 3 つの点すべてが頂点位置に着くように、その円上に等間隔に配置された頂点がいくつ存在するかということです。 

制約は入力サイズの点で非常に小さく、ポイントは 3 つだけです。 この課題は完全に数学的なものです。 最大 100 辺のすべての多角形に対する総当り検索は完全に実現可能ですが、3 つの点が同じ正多角形に属する可能性があるときの信頼できる幾何学的特徴付けがまだ必要です。 

浮動小数点の精度は、この問題の危険な部分です。 正しい多角形は π/7 や π/13 などの角度に依存する可能性があり、直接の等価性チェックは丸め誤差により失敗します。 もう 1 つの微妙な問題は、3 つの点が隣接する頂点であることが保証されていないことです。 連続した頂点を仮定する単純な解決策では、すぐに間違った答えが生成されます。 

次の例を考えてみましょう。```
0 0
1 0
0 1
```これら 3 点は直角三角形を形成します。 不用意にアプローチすると、3 つの頂点がわかっているため、多角形が三角形であると想定される可能性があります。 しかし、これらの点は実際には正方形の頂点であり、その面積は同じ点を通る外接正三角形よりも小さくなります。 

多角形に多くの辺があり、中心角が非常に小さくなる場合、別の注意が必要な状況が発生します。 たとえば、真の多角形に 97 の辺がある場合、イプシロンを慎重に使用しない限り、繰り返しの角度計算で蓄積された浮動小数点誤差により、gcd スタイルの角度削減が簡単に不安定になる可能性があります。 

3 番目のよくある間違いは、ほぼ縮退した三角形の外心を誤って計算することです。 入力によって有効な答えが保証されている場合でも、不安定な数式は不注意に実装されると大幅な精度の低下を引き起こす可能性があります。 

## アプローチ

 この強引なアイデアは、ポリゴンの辺の数が最大でも 100 であるという観察から始まります。考えられるすべてのことを試すことができます。`n`3から100まで。 

固定の場合`n`、定期的な`n`-gon は円を角度の円弧に分割します`2π/n`。 指定された 3 つの点がその多角形の頂点である場合、点の各ペア間の中心角は次の整数倍でなければなりません。`2π/n`。 

したがって、総当たりアルゴリズムは次のようになります。 

1. 3 点の外心と外半径を計算します。 
2. 中心の周りの各点の極角を計算します。 
3. あらゆる人にとって`n`3から100まで:

 - すべてのペアごとの角度の差が次の倍数であるかどうかを確認します。`2π/n`。 
- 「はい」の場合、ポリゴン領域を計算します。 
4. 最小面積を出力します。 

これはすでに制限内で機能しています。 98 ポリゴン サイズのみをテストし、各テストでは定数時間ジオメトリを使用します。 総作業量はごくわずかです。 

本当の課題はスピードではなく正確さです。 浮動小数点の角度を正確な倍数と比較することは脆弱です。 確認すると:```
diff % step == 0
```精度ノイズのせいで、ソリューションはすぐに失敗します。 

重要な洞察は、多角形の構造が中心角の最大公約数によって記述できるということです。 

3 つの点が次のように区切られた頂点に対応すると仮定します。`a`、`b`、 そして`c`ポリゴンを踏みます。 それらの中心角は次のとおりです。```
a * 2π/n
b * 2π/n
c * 2π/n
```つまり、すべての角度差は同じ基本単位角度を共有する必要があります。 最小の有効な多角形は、まさにその単位角度がすべての中心角の差の gcd である多角形です。 

整数演算では、gcd に Euclid のアルゴリズムを使用します。 浮動小数点の角度については、同じ考え方を数値的にシミュレートします。 以来`n ≤ 100`、さらに単純な戦略で十分です。すべてを試してください。`n`すべての角度が次の整数倍であるかどうかを確認します。`2π/n`イプシロン内で。 

正しくなったら`n`が知られている場合、多角形の領域は標準的な二等辺三角形への分解に従います。 定期的な`n`-外周半径のあるゴン`R`面積があります:$A = \frac{nR^2\sin\left(\frac{2\pi}{n}\right)}{2}$辺の制限が 100 のみであるため、総当りアプローチと最適アプローチは漸近的に実質的に同じです。最適性は、多角形の検証を外接円上の角度の可分性に限定する幾何学的な洞察から得られます。

 ## アルゴリズムのチュートリアル

 1. 3 つのポイントをお読みください。 

3 つの点は同一直線上にないことが保証されているため、これら 3 点は外接円を一意に決定します。 
2. 点によって形成される三角形の辺の長さを計算します。 

三角形の面積公式を使用して外周半径を計算するには、これらの長さが必要です。 
3. 外積を使用して三角形の面積を計算します。 

三角形の頂点が`A`、`B`、 そして`C`、 それから：$\text{Area} = \frac{|(B-A) \times (C-A)|}{2}$4. 外周半径を計算する`R`。 

標準の関係を使用すると、次のようになります。$R = \frac{abc}{4\Delta}$どこ`a`、`b`、 そして`c`は辺の長さであり、`Δ`三角地帯です。 
5. 3 つの中心角を計算します。 

三角形の各辺は、外心で一定の角度を成します。 拡張正弦の法則により、次のようになります。$\theta = 2\arcsin\left(\frac{a}{2R}\right)$これを 3 つの三角形の辺すべてについて計算します。 
6. あらゆるポリゴン サイズを試す`n`3から100まで。 

レギュラーの基本的な角度ステップ`n`-gon は次のとおりです。$\frac{2\pi}{n}$7. 各中心角について、それがステップ角の整数倍であるかどうかを確認します。 

次のように計算します。```
ratio = angle / step
```そしてそれを確認してください`ratio`は整数に十分に近いです。 
8. 最初の有効な`n`最小の面積が得られます。 

より大きな`n`は、同じ外接円上のより多くの辺を意味し、常に円の領域に向かって多角形の領域が増加します。 
9. 外周半径公式を使用して正多角形の面積を計算します。 
10. 十分な精度で答えを出力します。 

### なぜ効果があるのか

 3 つの点は独自の外接円上にあります。 それらを含む正多角形は、この正確な円を外接円として使用する必要があります。 

定期的な`n`-gon は、円を等しい角度ステップに分割します。`2π/n`。 したがって、2 つのポリゴン頂点間のすべての円弧は、そのステップの整数倍でなければなりません。 指定された 3 つの点によって 3 つの中心角が決定され、これらの角はすべて同じ基本ステップ角で割り切れる必要があります。 

毎回チェックすることで、`n`最小から最大まで、最初の有効なポリゴンの面積が最小であることが保証されます。 外周半径が固定されている場合、辺の数を増やすと正多角形の面積が厳密に増加します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

EPS = 1e-6

def dist(x1, y1, x2, y2):
    return math.hypot(x1 - x2, y1 - y2)

def is_multiple(angle, step):
    k = round(angle / step)
    return abs(angle - k * step) < EPS

def solve():
    points = [tuple(map(float, input().split())) for _ in range(3)]

    (x1, y1), (x2, y2), (x3, y3) = points

    a = dist(x2, y2, x3, y3)
    b = dist(x1, y1, x3, y3)
    c = dist(x1, y1, x2, y2)

    cross = abs((x2 - x1) * (y3 - y1) - (y2 - y1) * (x3 - x1))
    triangle_area = cross / 2.0

    R = (a * b * c) / (4.0 * triangle_area)

    angles = []
    for side in [a, b, c]:
        value = side / (2.0 * R)
        value = max(-1.0, min(1.0, value))
        angles.append(2.0 * math.asin(value))

    answer = 0.0

    for n in range(3, 101):
        step = 2.0 * math.pi / n

        ok = True

        for angle in angles:
            if not is_multiple(angle, step):
                ok = False
                break

        if ok:
            answer = 0.5 * n * R * R * math.sin(2.0 * math.pi / n)
            break

    print(f"{answer:.10f}")

solve()
```最初のセクションでは、三角形の辺の長さと面積を計算します。 外積公式は数値的に安定しており、細い三角形の精度が失われる可能性があるヘロンの公式を回避します。 

外周半径の計算では、辺の長さと三角形の面積の間の古典的な関係が使用されます。 すべての座標が小さいため、浮動小数点のオーバーフローは問題になりません。 

中心角は弦の長さから導出されます。 一定の長さのコードの場合`a`半径の円の中で`R`、対応する中心角は次の条件を満たします。```
a = 2R sin(theta / 2)
```この関係を次のように逆転させます。`asin`。 クランプは`[-1, 1]`浮動小数点エラーは次のような値を生成する可能性があるため、これは重要です。`1.0000000002`、クラッシュするでしょう`asin`。 

検証ステップでは、各角度がポリゴン ステップ角度の倍数であるかどうかをチェックします。 比率を最も近い整数に四捨五入し、再構成誤差をイプシロンと比較します。 浮動小数点数に対する直接的な剰余演算の信頼性ははるかに低くなります。 

ループは次から始まります`n = 3`したがって、最初の有効なポリゴンの面積は自動的に最小になります。

 ## 特殊なケース

 よくある失敗例は、3 つの点が連続した頂点であると仮定することです。 

入力：```
0 0
1 1
0 1
```これらの点によって形成される三角形は規則的ではありません。 単純なアルゴリズムは次の点で停止する可能性があります。`n = 3`そして外接三角形の面積を計算します。 代わりに、私たちのアルゴリズムは中心角の可分性をチェックします。 角度が次の倍数ではないため、三角形は失敗します。`2π/3`。 すべての角度が次の倍数であるため、正方形は成功します。`π/2`。 

もう 1 つの微妙なケースは、浮動小数点の丸めによって値が有効な三角関数の範囲をわずかに外れる場合です。 

入力：```
1 0
-1 0
0 1
```数学的には、1 つの弦の長さは正確に等しい`2R`なので、中の式は`asin`まさにそうあるべきです`1`。 浮動小数点演算により生成される可能性がある`1.0000000001`。 クランプなしで、`asin`ドメインエラーがスローされます。 実装では値を明示的に制限します。`[-1, 1]`。 

3 番目の危険なシナリオは、角度のステップが小さくなる、多くの辺を持つポリゴンです。 

入力：```
1 0
0.9980267284 0.0627905195
0.9921147013 0.1253332336
```これらは、正 100 角形の連続した頂点です。 計算された角度には蓄積された数値ノイズが含まれるため、浮動小数点角度の直接的な等価性チェックは失敗します。 イプシロンベースの整数倍数チェックにより、ポリゴン構造が正しく認識されます。
