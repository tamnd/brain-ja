## 問題の理解

 このタスクでは、2 つの形式のいずれかで記述されたスプレッドシートのセル座標が提供されます。すべての座標について、それを他の形式に変換する必要があります。 

最初の形式は、通常の Excel スタイルの表記法です。 列は文字を使用して記述され、その直後に行番号が続きます。 例えば、`BC23`列を意味します`BC`そして漕ぐ`23`。 厄介な点は、列がゼロ桁のない基数 26 の番号付けシステムのように動作することです。`A = 1`、`B = 2`、...、`Z = 26`、`AA = 27`、 等々。 

2 番目の形式では、次と同じ情報が書き込まれます。`R<row>C<column>`。 例えば、`R23C55`行を意味します`23`、 カラム`55`。 

すべての入力文字列について、まず使用する表記法を決定し、それから他の表記法に変換します。 

制約が大きいため、効率が重要になります。 まであります`10^5`座標、および各座標は最大の値を表すことができます。`10^6`。 巨大な範囲に対してスプレッドシートの番号付けを 1 文字ずつ繰り返しシミュレートするソリューションでは、時間がかかりすぎます。 入力文字列の長さは線形に近いものが必要です。 各座標は短いため、`O(length)`クエリごとの変換は十分に高速です。 

主な困難は、形式を正しく認識することです。 「で始まる」のような素朴なチェック`R`」は、有効な Excel スタイルの座標が次で始まる可能性があるため失敗します。`R`。 例えば：```
R23C55
```いる`RXCY`形式ですが、```
RC23
```は実際には Excel スタイルの表記法です。`RC`は列名であり、`23`という行です。 

不注意なパーサーにより誤って分類される可能性があります`RC23`として`RXCY`から始まるから`R`そして含まれています`C`。 正しいルールはより厳密です: 先頭の`R`、少なくとも 1 つの数字が必要です。`C`、次に少なくとも 1 桁を再度入力します。 

もう 1 つの一般的なバグの原因は、スプレッドシートの列変換そのものです。 スプレッドシートの列にはゼロ桁がないため、標準の基数 26 ではありません。 例えば：```
26 -> Z
27 -> AA
52 -> AZ
53 -> BA
```直接使用する場合`% 26`この欠けているゼロ桁を調整せずに、`26`間違ってなる`BA`の代わりに`Z`。 

## アプローチ

 この強引なアイデアは、スプレッドシートの列名を次の順序で明示的に生成することです。```
A, B, C, ..., Z, AA, AB, ...
```要求された列番号に到達したら停止します。 文字から数値に戻す変換は位置演算を使用すると簡単ですが、前の列をすべて生成して数値を文字に変換するのはすぐに非現実的になります。 

列が必要だとします`10^6`。 生成された各ラベルに一定の時間がかかるとしても、1 つのクエリに対して約 100 万回の反復を実行することになります。 と`10^5`クエリ、これは爆発的に広がります`10^11`許容範囲をはるかに超えた操作。 

重要な観察は、スプレッドシートの列が位置数値体系を形成しているということです。 唯一の珍しい部分は、数字の範囲が次のとおりであることです。`1`に`26`の代わりに`0`に`25`。 

つまり、2 つの表現間で数学的に直接変換できるということです。 

文字を数値に変換するには、基数変換とまったく同じように文字列を処理します。```
ABC = 1 * 26^2 + 2 * 26^1 + 3
```数値を文字に変換するには、モジュロ演算を使用して最後の桁を繰り返し抽出します。 ゼロの桁がないので、1 を引いてから計算します。`% 26`。 

形式を検出するために、文字列をスキャンして一致するかどうかを確認します。```
R + digits + C + digits
```そうであれば、から変換します`RXCY`エクセル風に。 それ以外の場合は、逆方向に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとの O(列値) | お(1) | 遅すぎる |
 | 最適 | クエリごとの O(文字列の長さ) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 座標文字列を読み取ります。 
2. 形式を決定します。 

文字列が入っています`RXCY`次の場合にフォーマットします:

 - それはから始まります`'R'`- 後`'R'`少なくとも 1 桁あります
 - これらの数字の後には`'C'`- 後`'C'`少なくとも 1 桁あります

 これにより、次のような文字列の誤分類が回避されます。`RC23`。 
3. 文字列が Excel スタイルの場合:

 2 つの部分に分割します。 

- 列を表す先頭の文字
 - 行を表す後続の数字
 4. 列の文字を数値に変換します。 

各文字を左から右に処理します。```
value = value * 26 + letter_value
```どこ`A = 1`、`B = 2`、...、`Z = 26`。 
5. 結果を次のように出力します。```
R<row>C<column_number>
```6. 文字列がすでに入っている場合`RXCY`形式:

 行番号と列番号を抽出します。 
7. 列番号をスプレッドシートの文字に変換します。 

繰り返し:

 - 数値から 1 を引きます
 - 取る`% 26`現在の手紙を取得するには
 - 次のステップのために 26 で割ります

 スプレッドシート列のインデックスは 0 ではなく 1 であるため、減算が必要です。 
8. 変換では最下位桁から最上位桁まで文字列が構築されるため、収集した文字を逆にします。 
9. 出力:```
<column_letters><row>
```### なぜ効果があるのか

 このアルゴリズムは、スプレッドシートの列が基数 26 と数字を使用した位置記数法とまったく同じように動作するという事実に基づいています。`1..26`。 

文字を数値に変換する場合、各ステップで現在の値が 26 進数で 1 桁シフトされ、次の数字が追加されます。 これは通常の 10 進数の解析と同じです。 

数値を文字に変換する場合、1 を引くと範囲が変換されます。`1..26`標準に入る`0..25`モジュロ演算に必要な範囲。 各反復では、base-26 の数字が 1 つだけ抽出されるため、生成された文字は元の列番号を一意に表します。 

2 つの形式は構造的に異なるため、形式検出ルールはすべての入力が正しく分類されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_rxcy(s):
    if not s or s[0] != 'R':
        return False

    i = 1

    if i >= len(s) or not s[i].isdigit():
        return False

    while i < len(s) and s[i].isdigit():
        i += 1

    if i >= len(s) or s[i] != 'C':
        return False

    i += 1

    if i >= len(s):
        return False

    while i < len(s):
        if not s[i].isdigit():
            return False
        i += 1

    return True

def letters_to_number(col):
    value = 0

    for ch in col:
        value = value * 26 + (ord(ch) - ord('A') + 1)

    return value

def number_to_letters(num):
    result = []

    while num > 0:
        num -= 1
        result.append(chr(num % 26 + ord('A')))
        num //= 26

    return ''.join(reversed(result))

def solve():
    n = int(input())
    ans = []

    for _ in range(n):
        s = input().strip()

        if is_rxcy(s):
            c_pos = s.index('C')

            row = s[1:c_pos]
            col_num = int(s[c_pos + 1:])

            col_letters = number_to_letters(col_num)

            ans.append(col_letters + row)

        else:
            i = 0

            while s[i].isalpha():
                i += 1

            col_letters = s[:i]
            row = s[i:]

            col_num = letters_to_number(col_letters)

            ans.append(f"R{row}C{col_num}")

    print('\n'.join(ans))

solve()
```この解決策は、問題を 3 つの独立した部分 (形式の検出、文字から数字への変換、数字から文字への変換) に分割します。 

の`is_rxcy`関数は、単純なパターン チェックよりも厳密です。 必要な構造を明示的に検証します。```
R + digits + C + digits
```これにより、次のような誤った一致が防止されます。`RC23`。 

の`letters_to_number`関数は通常の位置解析を実行します。 新しい文字ごとに、現在の値が 26 進数で 1 桁シフトされ、次の桁の値が追加されます。 

逆変換はさらに微妙です。 スプレッドシートの列にはゼロインデックスが付けられていないため、`% 26`現在の数値から 1 を引きます。 この調整を行わない場合:```
26 % 26 = 0
```間違ってマッピングされてしまう`26`に`'A'`の代わりに`'Z'`。 

変換では自然に文字が右から左に構築されるため、最後に結果を逆にします。 

この実装では、出力リストとは別に一定の追加メモリのみが使用され、すべての文字が一定の回数処理されます。
