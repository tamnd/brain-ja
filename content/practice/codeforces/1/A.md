## 問題の理解

 長さ _n_ メートル、幅 _m_ メートルの長方形の広場、劇場広場が与えられています。 市はエリア全体を _a_ 面の正方形の敷石で舗装したいと考えています。 この質問では、広場を完全に覆うために必要な敷石の最小数を尋ねます。 各敷石は正方形の辺に沿って配置する必要があります。 切り取ることはできませんが、敷石が広場の端を越えて伸びることは許容されます。 

入力数値は最大 10^9 まで非常に大きくすることができます。 これは、正方形の 1 メートルごと、または考えられるタイルの配置ごとに反復するアプローチは実行不可能であることを示しています。 定数時間の算術ベースのソリューションが必要です。 

明らかではないエッジ ケースには、正方形の寸法がタイル サイズで割り切れない状況が含まれます。 たとえば、正方形が 6 × 6 メートルで、敷石が 4 × 4 メートルの場合、単純な整数除算では、次元ごとに 1 つの敷石 (6 // 4 = 1) が表示され、合計は 1 になる可能性があります。1 つの 4 × 4 の敷石では 6 メートルをカバーできないため、これは明らかに間違っています。 正しいアプローチでは、剰余を考慮して除算を切り上げる必要があります。 

もう 1 つの微妙なケースは、_n_ または _m_ が _a_ で正確に割り切れる場合ですが、これは余分な敷石を追加すべきではありません。 たとえば、4×4 タイルを含む 12×8 の正方形では、正確に 6 つのタイル (長さに沿って 3 つ、幅に沿って 2 つ) を使用する必要があります。それ以上は使用できません。 

## アプローチ

 ブルートフォースアプローチでは、各タイルの配置をシミュレートし、長さと幅に沿って適合する数を数え、残ったスペースに追加のタイルを追加しようとします。 概念的には、入れ子になったループが各タイルの左上隅を反復することを想像できます。 それは正しいのですが、最悪の場合の演算数は最大入力 (n = m = 10^9、a = 1) に対して 10^18 に達する可能性があり、これはまったく実行不可能です。 

重要な洞察は、何もシミュレーションする必要がないということです。 各次元は独立して処理できます。 1 つの次元に沿って、必要なタイルの数は、正方形の長さをタイル サイズで割った上限になります。 数学的には、これは`ceil(n / a)`。 両方の次元に対してこれを実行し、結果を乗算すると、タイルの合計数が得られます。 切り上げにより、残りがわずかに存在する場合でも、それをカバーするために追加のタイルが割り当てられるようになります。 

上限演算は、整数の除算を使用して、浮動小数点演算を行わずに計算できます。`(n + a - 1) // a`。 これは機能します。`n`で割り切れない`a`、追加`a-1`商が切り上げられるようにします。 もし`n`で割り切れます`a`、加算しても商は変わりません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m / a^2) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取る`n`、`m`、 そして`a`。 これらは長さ、幅、タイルのサイズを表します。 
2. 整数演算を使用して、長さに沿ったタイルの数を計算します。`tiles_along_length = (n + a - 1) // a`。 追加`a - 1`次の場合に切り上げが保証されます`n`で割り切れない`a`。 
3. 同じ方法で幅に沿ったタイルの数を計算します。`tiles_along_width = (m + a - 1) // a`。 
4. 2 つの結果を乗算して、タイルの合計数を取得します。`total_tiles = tiles_along_length * tiles_along_width`。 
5. 結果を印刷します。 

機能する理由: 全長をカバーする最小数のタイルを使用して、各次元が個別にカバーされます。 乗算により、長方形領域の 2 次元の範囲が保証されます。 切り上げステップにより、たとえ次のような場合でもスペースがカバーされないことが保証されます。`n`または`m`の倍数ではありません`a`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, a = map(int, input().split())

tiles_along_length = (n + a - 1) // a
tiles_along_width = (m + a - 1) // a

total_tiles = tiles_along_length * tiles_along_width
print(total_tiles)
```コードはアルゴリズムに直接続きます。 入力を読み取る`sys.stdin.readline`大きな入力に対する I/O オーバーヘッドを回避します。 の`(n + a - 1) // a`このトリックは浮動小数点除算を回避し、精度の問題やオーバーフローを防ぎます。 2 つのカウントを乗算すると、正しい敷石の合計数が得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, a = map(int, sys.stdin.readline().split())
    return str(((n + a - 1) // a) * ((m + a - 1) // a))

# Provided sample
assert run("6 6 4\n") == "4", "sample 1"

# Custom cases
assert run("12 8 4\n") == "6", "exact division"
assert run("1 1 1\n") == "1", "minimum-size input"
assert run("1000000000 1000000000 1\n") == "1000000000000000000", "maximum-size input"
assert run("5 5 3\n") == "4", "odd dimensions with remainder"
assert run("10 10 10\n") == "1", "tile exactly fits"
```| Test input | Expected output | What it validates |

 ## Edge Cases

For the case`n = 5, m = 5, a = 3`、計算は`(5 + 3 - 1) // 3 = 7 // 3 = 2`次元ごとのタイル。 乗算すると 4 つのタイルが得られます。 残り 2 メートルにもかかわらず、各寸法は完全にカバーされています。 切り上げを行わない単純な整数除算では 1×1 = 1 タイルが返されますが、これでは明らかに不十分です。 これにより、丸めロジックが割り切れない次元を正しく処理していることが確認されます。 

最大値の場合`n = m = 10^9, a = 1`、計算`(10^9 + 1 - 1) // 1 = 10^9`次元ごとに与える`10^9 × 10^9 = 10^18`タイル。 Python はこの大きな整数をオーバーフローせずに処理し、極端な入力に対するアプローチを検証します。
