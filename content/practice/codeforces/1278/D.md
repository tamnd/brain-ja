 ## 解決策

 ## 問題の理解

 数直線上の線分の集合が与えられます。 各セグメントは 2 つの異なる整数エンドポイントによって定義され、入力内のどこにも 2 つのエンドポイントが一致することはありません。 これらのセグメントから、各セグメントが頂点となるグラフを構築します。 

2 つの頂点のセグメントが非常に特殊な方法で交差する場合、2 つの頂点は接続されます。それらは重なり合う必要がありますが、どちらのセグメントももう一方のセグメントを完全に含むことはできません。 したがって、有効な隣接関係は、エンドポイントがインターリーブして「交差」パターンを形成する場合にのみ発生します。 

順序的には 2 つのセグメント$[l_1, r_1]$そして$[l_2, r_2]$次のいずれかが当てはまる場合、正確に接続されます。$l_1 < l_2 < r_1 < r_2$または$l_2 < l_1 < r_2 < r_1$。 

タスクは、結果のグラフがツリーであるかどうかを判断することです。 つまり、接続されており、正確に含まれている必要があります。$n-1$エッジ、サイクルなし。 

制約$n \le 5 \cdot 10^5$すべてのセグメントのペアをチェックするソリューションは除外されます。 二次関数のアプローチでは、次のオーダーが必要になります。$10^{11}$これは 2 秒の制限をはるかに超えています。 平$O(n \log n)$クエリだけでなくエッジ生成も考慮する必要があるため、慎重な設計が必要です。 

いくつかの微妙なケースが素朴な推論を打ち破ります。 1 つは、セグメントが重なり合っているものの、ネストされている場合です。 例えば$[1,10], [2,9], [3,8]$すべてのペアが包含されているため、エッジがまったく生成されず、強い重なりにもかかわらずグラフが切断されます。 もう 1 つのケースは、インターリーブの三角形に配置された 3 つのセグメントなど、交差がサイクルを形成する場合です。 各ペアがローカルに有効であるように見えても、グローバル構造はツリー条件を満たさない可能性があります。 

主な困難は、エッジが間隔の幾何学的条件によって定義されることですが、グローバルなグラフ プロパティについて推論する必要があることです。 

## アプローチ

 ブルート フォース ソリューションは、セグメントのすべてのペアをチェックし、それらが必要な方法で交差するかどうかをテストします。 これは簡単です: 各ペアについて$(i, j)$、エンドポイントを比較し、エンドポイントがインターリーブしている場合はエッジを追加します。 グラフを構築した後、DFS または DSU を実行して、接続とサイクルの存在を確認します。 

これは正しく動作しますが、調べます$\frac{n(n-1)}{2}$ペア、つまり約$10^{11}$最悪の場合のチェック。 各チェックは定数時間ですが、この定数はこのスケールでは問題にならないほど小さすぎます。 

重要な点は、すべてのエッジを事前に明示的に構築する必要がないということです。 各セグメントは、エンドポイントがそのセグメントに対して非常に特定の範囲内にあるセグメントを持つエッジにのみ参加します。 左側の端点の昇順にセグメントを処理する場合、セグメントを考慮すると、以前に開始されたすべての潜在的な隣接セグメントがすでに「アクティブ」になっています。 これらのアクティブなセグメントのうち、右端が特定の間隔内にあるセグメントのみが必要です。 これにより、問題は、アクティブなセグメントの動的なセットの維持と、適切なエンドポイントによるクエリに変わります。 

すべてのアクティブなセグメントをフラット セットに保存する代わりに、正しいエンドポイント上のセグメント ツリーを使用します。 各セグメントはアクティブになったときに 1 回挿入され、エッジの一部として検出されたときに 1 回だけ削除されます。 これにより、すべてのクエリにわたって各セグメントが一定の回数処理されることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | セグメントツリー + DSU スイープ |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 左側のエンドポイントの増加順にセグメントを処理し、右側のエンドポイントによってインデックス付けされたセグメント ツリーを維持します。 

1. セグメントを左の端点で並べ替えます。 これにより、セグメントを処理するときに、先に開始する可能性のあるすべての隣接セグメントがすでに構造内に存在することが保証されます。 
2. エンドポイントの座標範囲にわたってセグメント ツリーを維持します。 各アクティブ セグメントは、その右のエンドポイントに対応するリーフに格納されます。 
3. 並べ替えられた順序でセグメントを反復処理します。$l$。 現在のセグメントの場合$[l, r]$、間隔でセグメント ツリーをクエリします。$(l, r)$。 この範囲内で見つかったアクティブなセグメントは、現在のセグメント内に正しい端点を持ちます。これは、セグメントが重複していることを意味します。 
4. セグメントごとに$j$そのクエリ内で見つかった場合は、セグメント ツリーからそれを削除し、DSU 構造内の現在のセグメントと結合します。 削除すると、各セグメントが「検出された隣接セグメント」として 1 回だけ処理されるようになります。 
5. 現在のセグメントのすべてのオーバーラップを処理した後、セグメント ツリーの次の位置に挿入します。$r$。 
6. 結合の処理中に、同じ DSU コンポーネント内に既に存在する 2 つの頂点を結合しようとすると、サイクルが検出され、グラフがツリーではないと即座に結論付けることができます。 
7. すべてのセグメントが処理された後、2 つの条件を検証します。形成されたエッジの数が正確に一致している必要があります。$n-1$、すべてのセグメントは単一の DSU コンポーネントに属している必要があります。 

セグメント ツリーは、右のエンドポイントによるアクティブなセグメントの高速な取得のみを担当します。 DSU はグローバル構造制約を強制します。 

### なぜ効果があるのか

 交差エッジは、右側の端点が別のセグメント内にあり、左側の端点が順序付けされているセグメントによって完全に決定されます。 この構造により、後のセグメントが処理されるときに、すべての有効なエッジが 1 回だけ検出されることが保証されます。 すべてのインターリーブ ペアにはその時点で先に開始されたセグメントがアクティブであるため、エッジが失われることはありません。また、セグメントが一致すると構造から削除されるため、エッジが重複することはありません。 

これにより、アルゴリズムは問題で定義されたグラフのエッジ セットを正確に探索すると同時に、総作業量がセグメント数と検出されたエッジの数に比例するように維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [[] for _ in range(4 * n)]

    def add(self, idx, l, r, pos, val):
        if l == r:
            self.t[idx].append(val)
            return
        m = (l + r) // 2
        if pos <= m:
            self.add(idx * 2, l, m, pos, val)
        else:
            self.add(idx * 2 + 1, m + 1, r, pos, val)
        self.t[idx].append(val)

    def query(self, idx, l, r, ql, qr, out):
        if ql <= l and r <= qr:
            out.extend(self.t[idx])
            self.t[idx].clear()
            return
        if r < ql or l > qr:
            return
        m = (l + r) // 2
        self.query(idx * 2, l, m, ql, qr, out)
        self.query(idx * 2 + 1, m + 1, r, ql, qr, out)

def main():
    n = int(input())
    segs = []
    coords = set()

    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i))
        coords.add(l)
        coords.add(r)

    segs.sort()
    coords = sorted(coords)

    # coordinate compression for r only
    comp = {v: i + 1 for i, v in enumerate(coords)}
    maxv = len(coords)

    segs2 = [(l, comp[r], i) for l, r, i in segs]

    st = SegTree(maxv)
    dsu = DSU(n)

    edges = 0
    ok = True

    for l, r, i in segs2:
        found = []
        if l + 1 <= r - 1:
            st.query(1, 1, maxv, comp[l] + 1, r - 1, found)

        for j in found:
            if not dsu.union(i, j):
                ok = False
            edges += 1

        st.add(1, 1, maxv, r, i)

    if ok and edges == n - 1:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    main()
```この解決策は、アクティブなセグメントが常に以前に開始されたセグメントに対応するように、セグメントを左端で並べ替えることから始まります。 右のエンドポイントによってインデックス付けされたセグメント ツリーには、現在アクティブなセグメントが格納されます。 

処理中に、各セグメントは、右端点がそれ自身の左端点と右端点の間に厳密に含まれるすべてのアクティブなセグメントをツリーに照会します。 これらはまさに、それと有効な交差エッジを形成するセグメントです。 取得されたすべてのセグメントは、重複処理を避けるために構造から直ちに削除され、DSU で結合されます。 

DSU は接続を追跡し、エッジ作成中にサイクルを検出します。 ツリーの最終条件は、それを正確にチェックすることによって適用されます。$n-1$エッジが形成され、サイクルは検出されませんでした。 

セグメント ツリーはノードにリストを保存して、クエリ中のバッチ削除をサポートし、償却効率を確保します。

 ## 特殊なケース

 次のような完全にネストされた構造$[1,10], [2,9], [3,8]$有効な交差を生成するクエリは生成されないため、DSU はコンポーネントを接続せず、グラフは切断されたままになります。 次のような交差する三角形$[1,4], [2,6], [3,5]$各セグメントが他の 2 つのセグメントと交互に交差するため、サイクルが生成されます。DSU は 3 番目のエッジが試行されるときに繰り返し接続を検出し、誤ったツリー分類を防ぎます。
