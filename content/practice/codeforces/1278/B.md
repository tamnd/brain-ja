 ## 解決策
 ## 問題の理解

 2 つの整数が与えられ、k 番目の演算のコストが正確に k になる演算を繰り返し実行できます。 各操作では、2 つの数値のうち 1 つを選択し、現在の操作インデックスをそれに追加します。 選択したすべての増分後に両方の数が等しくなるために必要な、このような操作の最小数を知りたいと考えています。 

これを考えるのに役立つ方法は、演算の観点からではなく、2 つの数値の差の観点から考えることです。 初期の差を次のようにします$d = |a - b|$。 すべての操作が値に貢献します$1, 2, 3, \dots, n$、これらの値のそれぞれが左または右の番号に割り当てられます。 したがって、セットを効果的に分割しています$\{1, 2, \dots, n\}$を 2 つのグループに分け、それらの合計の差が正確に一致するようにします。$d$。 

制約により、最大で次のことが許可されます。$t = 100$テスト ケース。各値は次のように大きくできます。$10^9$。 これは、操作をシミュレートしたり、サブセットを明示的に試行したりできないことがすぐにわかります。 平$O(\sqrt{d})$テスト ケースごとの値は許容できるかもしれませんが、差や操作数の直線的なものはすべて実際のターゲットです。 

微妙な点はパリティです。 最初の合計$n$整数は$\frac{n(n+1)}{2}$。 この合計を差分のある 2 つの部分に分割したい場合$d$、 それから$\frac{n(n+1)}{2} - d$偶数である必要があります。そうでない場合、パーティションは存在しません。 差を一致させることだけを貪欲に考えると、このパリティ制約は見落とされやすくなります。 

エッジケースが発生するのは次の場合です$a = b$、答えは明らかにゼロです。 もう 1 つは、最小限の場合です。$n$必要な合計に達するのは小さすぎますが、パリティを増やす必要があります$n$さらに遠く。 たとえば、差が 1 の場合、$n = 1$合計が 1 であるため、この関数は機能します。ただし、差分 2 の場合は、$n = 2$和は 3 になりますが、パリティが一致しないため差 2 を生成できません。 私たちは行く必要があります$n = 3$, ここで、和は 6 で、差は 2 になります。 

## アプローチ

 ブルートフォース手法では、値を 1 つずつ増やすことをシミュレートし、それぞれを次のいずれかに割り当てようとします。$a$または$b$、すべてを探索する$2^n$可能な演算数ごとの割り当て$n$。 これは、考えられるすべての増分の分布を直接モデル化しているため、正しいのですが、遅すぎます。 たとえ$n = 30$、これは不可能になります。 

私たちは視点を変えます。割り当てを追跡するのではなく、割り当て後に生み出される差異のみを追跡します。$n$操作。 後$n$ステップごとに、加算された合計は次のように固定されます。$S = \frac{n(n+1)}{2}$。 有効な割り当てはすべて、この合計を 2 つの部分集合に分割することに対応します。$S_1$そして$S_2$、 どこ$S_1 - S_2 = d$そして$S_1 + S_2 = S$。 これらを解決すると、$S_1 = \frac{S + d}{2}$。 したがって、問題は次のようになります: 最小のものを見つける$n$そのような$S \ge d$そして$S \equiv d \pmod{2}$。 

これにより、問題は単調な検索に変換されます。$n$, 三角和はどんどん大きくなるので。 最小値を計算できます$n$単純なループまたは二分探索を使用します。

 ## アルゴリズムのチュートリアル

 問題を絶対差に還元します$d = |a - b|$。 

1. コンピューティング$d = |a - b|$。 もし$d = 0$、操作は必要ないため、すぐに 0 を返します。 これにより、些細なケースが早期に削除され、不必要な計算が回避されます。 
2. から始める$n = 0$と累計$S = 0$。 概念的には最小のものを見つけようとしています$n$最初の$n$自然数は差を達成する分割を形成できる$d$。 
3.増加$n$ステップバイステップ、更新$S = S + n$。 各増分後、次のことを確認します。$S \ge d$。 これにより、必要な差を表すのに十分な総質量が確保されます。 
4. 1回$S \ge d$、どうかを確認してください$(S - d)$は均等です。 この条件により、次のことが保証されます。$S_1 = (S + d)/2$そして$S_2 = (S - d)/2$両方とも整数であり、有効なパーティションが存在することを意味します。 
5. 最初の$n$両方の条件を満たすことが答えです。 以来$S$二次関数的に成長するため、このループは十分に高速です。 

### なぜ効果があるのか

 あらゆる段階で$n$、セットへの記号の可能なすべての割り当てを暗黙的に考慮しています。$\{1, 2, \dots, n\}$。 到達可能な差分は、正確にパリティに一致するものです。$S$そしてそれを超えないでください。 増えるから$n$以前の合計を無効にすることなく、到達可能な合計のセットを拡大するだけです。最初の有効な合計は$n$最小限であることが保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        d = abs(a - b)

        if d == 0:
            print(0)
            continue

        n = 0
        s = 0

        while True:
            n += 1
            s += n
            if s >= d and (s - d) % 2 == 0:
                print(n)
                break

if __name__ == "__main__":
    solve()
```この解決策は、三角数が必要な差を表現できるようになるまで三角数を累積することに重点を置いています。 合計は次のように増加するため、ループは安全です。$O(n^2)$、したがって、いずれかに到達します$d \le 10^9$およそで起こる$O(\sqrt{d})$繰り返し。 

重要な実装の詳細は、両方の条件を一緒にチェックすることです。少なくとも、$d$、満足のいく同等性。 どちらかが欠けていると、特に合計がすでに十分に大きいにもかかわらずパリティの不一致が続くような小さな差の場合、不正確な答えにつながります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        d = abs(a - b)
        if d == 0:
            out.append("0")
            continue
        n = 0
        s = 0
        while True:
            n += 1
            s += n
            if s >= d and (s - d) % 2 == 0:
                out.append(str(n))
                break
    return "\n".join(out)

# provided samples
assert run("3\n1 3\n11 11\n30 20") == "3\n0\n4"

# custom cases
assert run("1\n1 1") == "0", "minimum equal"
assert run("1\n1 2") == "3", "small odd difference"
assert run("1\n100 1000000000") is not None, "large difference feasibility"
assert run("1\n5 5") == "0", "already equal"

 ## 特殊なケース

 いつ$a = b$の場合、アルゴリズムはループに入る前にすぐに 0 を返します。 入力用`5 5`の場合、差はゼロであるため、累積は実行されず、反復なしで出力は正確になります。 

差が非常に小さいが、早い段階でパリティの不一致が発生した場合、ループは最初の十分に見える合計を超えて継続されます。 のために`1 2`、$d = 1$。 最初のステップでは、$S = 1$、すでに両方の条件を満たしているため、答えは 1 です。ただし、2 などの他の小さな違いについては、パリティが一致しない中間合計を意図的にスキップして、正確性を確保します。 

次のような大きな値の場合、`1 1000000000`、三角和が差に達するかそれを超えるまで、ループは成長します。 各ステップは O(1) のままで、ステップ数は約 44700 にとどまりますが、これは制約内で安全です。
