 ## 問題の理解

 パスワードを表す基本文字列と、そのパスワードの「ハッシュ」であると主張される別の文字列が与えられます。 ハッシュは、通常の意味での暗号化ハッシュではありません。 代わりに、パスワードのすべての文字を取得し、それらを任意の順序で並べ替え、その前後に任意の余分な小文字を含む大きな文字列内のどこかにその並べ替えを埋め込むことによって構築されます。 

問題は、2 番目の文字列がこの方法で生成されたかどうかです。 言い換えれば、複数の文字セットがパスワードの複数の文字セットと正確に一致するハッシュの部分文字列が見つかるかどうかをチェックしています。 この選択された部分文字列の外側のハッシュの残りの部分は何でも構いません。 

各テスト ケースは独立しているため、複数の文字列ペアに対してこのチェックを繰り返します。 

制約は小さく、両方の文字列の長さは最大 100 で、テスト ケースの数は最大 100 です。 これにより、合計数百万の単純な操作よりも複雑なものは即座に排除されます。 O(n³) アプローチでもまだ安全ですが、指数関数的または順列を伴うものは不要です。 

よくある間違ったアプローチは、パスワードのすべての順列を生成し、ハッシュ内でそれらを検索しようとすることです。 10 文字のパスワードでも 10 文字あるため、これはすぐに失敗します。 順列はすでに大きすぎます。 

もう 1 つの微妙な間違いは、パスワードがハッシュの部分列として現れるかどうかだけをチェックすることです。 再配置後、パスワード文字は分散してではなく連続して表示される必要があるため、これは不正解です。 シャッフルは選択したブロック内の順序にのみ影響し、文字列全体の位置には影響しません。 

素朴なロジックを打ち破る小さな例:

 入力:```
p = "ab"
h = "axb"
```ここ、`"ab"`は部分列として表示されますが、長さ 2 の連続した部分文字列はありません。`h`それは両方を持っています`'a'`そして`'b'`一緒に。 したがって、答えは実際には「NO」です。 

正しい条件は、スライディング ウィンドウ内の一致する文字数によって決まります。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての部分文字列を考慮することです。`h`に等しい長さを抽出します。`len(p)`、部分文字列が次と同じ文字頻度を持つかどうかを確認します。`p`。 部分文字列ごとにカウントを最初から再計算します。これには、チェックごとに O(26) または O(n) のコストがかかります。 O(n) 個の部分文字列があるため、O(n²) 個のチェックが行われ、毎回 O(n) が機能し、最悪の場合は O(n³) になります。 

これは n ≤ 100 の場合は簡単に機能しますが、それでも必要以上に機能します。 

重要な観察は、次の部分文字列が存在するかどうかだけを気にするということです。`h`とまったく同じ複数の文字セットを持っています`p`。 これは、古典的な固定長アナグラム マッチング問題です。 すべての部分文字列の頻度を再計算する代わりに、サイズ |p| のスライディング ウィンドウを維持します。 以上`h`、ステップごとに O(1) の文字数を更新します。 

ウィンドウの周波数配列を次の周波数配列と比較します。`p`。 アルファベットのサイズは一定 (小文字 26 文字) であるため、比較は O(26) であり、事実上一定です。 

これにより、問題は線形スキャンに帰着します。`h`。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. パスワード文字列の頻度配列を計算します。`p`。 この配列には各文字が何回格納されるか`'a'`に`'z'`が表示されます。 これは、次の部分文字列で正確に一致する必要があるパターンです。`h`。 
2. もし`h`よりも短いです`p`の部分文字列がないため、すぐに「NO」を返します。`h`のすべての文字を含めることができます`p`。 
3. 最初のウィンドウの周波数配列を構築します。`h`に等しい長さの`p`。 このウィンドウは候補部分文字列を表します。 
4. ウィンドウの頻度とパスワードの頻度を比較します。 一致する場合は、すぐに「YES」を返します。 
5. ウィンドウを一度に 1 文字ずつスライドさせます`h`。 各ステップで:

 - 発信キャラクターの貢献を削除します (ウィンドウの左側)。 
- 受信文字を追加します (ウィンドウの右側)。 

これにより、ウィンドウ周波数が O(1) で更新され続けます。 
6. 更新するたびに、更新されたウィンドウの頻度とパスワードの頻度を比較します。 いずれかの時点でそれらが一致する場合は、「YES」を返します。 
7. 一致するものが見つからずにすべてのウィンドウのスキャンが終了した場合は、「NO」を返します。 

この手順が正しい理由は、考えられるすべての連続セグメントが`h`長さの`|p|`は候補として 1 回だけ検査され、すべての候補は次の順列であるかどうかチェックされます。`p`。 

### なぜ効果があるのか

 重要な不変条件は、スライディング ウィンドウの各ステップで、ウィンドウの周波数配列が現在の部分文字列の文字マルチセットを正確に反映することです。`h`長さの`|p|`。 長さ -|p| のあらゆる可能な配置があるため、 substring は一度訪問されると、有効な候補を見逃すことはありません。 逆に、一致する部分文字列はこれらのウィンドウの 1 つとして表示される必要があるため、一致するものがない場合は、有効な構造が存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(p, h):
    n, m = len(p), len(h)
    if m < n:
        return "NO"
    
    def freq(s):
        f = [0] * 26
        for c in s:
            f[ord(c) - 97] += 1
        return f
    
    fp = freq(p)
    window = freq(h[:n])
    
    if window == fp:
        return "YES"
    
    for i in range(n, m):
        window[ord(h[i]) - 97] += 1
        window[ord(h[i - n]) - 97] -= 1
        if window == fp:
            return "YES"
    
    return "NO"

def main():
    t = int(input())
    out = []
    for _ in range(t):
        p = input().strip()
        h = input().strip()
        out.append(solve_one(p, h))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、単一のテスト ケースをチェックするヘルパーを中心に構成されています。 頻度配列は長さ 26 の単純な固定サイズのリストであり、辞書によるオーバーヘッドを回避します。 スライディング更新はインプレースで実行されるため、ウィンドウ間の移行が一定時間で行われます。 

よくある実装上の間違いは、初期ウィンドウを個別に処理するのを忘れることです。 もう 1 つは、周波数配列の誤った更新、特に送信インデックスと受信インデックスの混同です。 どちらの操作も対称的なデクリメントとインクリメントであるため、これらを静かに交換すると正確性が損なわれます。

 ## 特殊なケース

 主なエッジケースは、パスワードに繰り返しの文字が含まれている場合です。 このような場合、順列は一意ではないため、順序に基づく単純な部分文字列チェックは失敗します。 たとえば:

 入力:```
p = "aab"
h = "ababa"
```正しい答えは YES です。`"aba"`または`"baa"`どちらも必要な周波数に一致します。 

スライディング ウィンドウは、順序ではなくカウントのみを追跡するため、これを正しく処理します。 各ウィンドウは純粋にマルチセットの同等性に基づいて比較されるため、重複は自然にサポートされます。 

もう 1 つのエッジケースは次のような場合です`h`よりも短いです`p`。 例えば：```

```有効なウィンドウが存在しないため、アルゴリズムは処理の前にこれを即座に拒否します。 これにより、不必要な計算が回避され、範囲外のスライディング ロジックが防止されます。 

最後の微妙なケースは、有効な部分文字列が文字列の最後に現れる場合です。`h`。 初期化と完全なスライディング ループにより、最後のウィンドウが明示的にチェックされるため、境界ケースが見逃されることはありません。
