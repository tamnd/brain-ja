 ## 解決策
 ## 問題の理解

 私たちは、Monocarp が都市に到着する生き物のグループを受け入れるか拒否できる戦略的な都市建設ゲームをシミュレートするように求められています。 各グループには、一定数の人間、オーク、エルフ、ドワーフが含まれています。 それぞれの生き物は、総人口と全住民の幸福度の合計から構成されるグローバル スコアに貢献します。 幸福は友好関係と敵対関係によって定義されます。同じ種族の生き物はお互いの幸福度を高めますが、敵対的な種族の生き物は幸福度を下げます。 具体的には、人間とオーク、エルフとドワーフが敵対関係にあります。 

入力は次のように与えられます`n`グループ。それぞれのグループは、各種族のクリーチャーの数を指定する 4 つの非負の整数で記述されます。 私たちの仕事は、住民の総数とすべての個人の幸福値の合計として計算される合計スコアを最大化するためにどのグループを受け入れるかを決定することです。 

制約は重要です。`n`最大 300,000 まで大きくなり、各母集団数は 10^9 に達する可能性があります。 これにより、2^300,000 のサブセットが存在することになり、計算上不可能であるため、グループのすべての可能なサブセットを評価する総当り的なアプローチが排除されます。 このアルゴリズムは、網羅的な検索ではなく構造と累積プロパティを多用して、およそ O(n log n) または O(n) 時間で実行する必要があります。 

単純な実装ではつまずく可能性のあるエッジケースには、敵対的なクリーチャーのみを含むグループが含まれます。 たとえば、人間 10 人、オーク 0 人のグループは完全に有益ですが、人間 5 人、オーク 10 人のグループは幸福度の合計が減少する可能性があります。 幸福への最終的な影響を考慮せずにグループを盲目的に受け入れると、最適ではないスコアが生成される可能性があります。 また、空のグループや極端に大きな値を持つグループは、整数のオーバーフローを避けるために慎重に処理する必要があります。 

## アプローチ

 ブルートフォース手法では、グループのすべてのサブセットを列挙し、その結果として得られる各サブセットの人口と幸福度を計算し、最大スコアを返します。 各サブセットの計算では、人口を合計し、種族間でペアごとに幸福度を計算する必要があり、O(n * 2^n) の演算が必要になります。 n = 20 の場合でもこれは不可能になり、n = 3*10^5 では不可能になります。 

重要な洞察は、合計スコアに対するグループの貢献が、グループの各レースのカウントと都市の現在の合計カウントの一次関数として表現できることを観察することです。 させて`H`、`O`、`E`、`D`これまでのところ、都市にいる人間、オーク、エルフ、ドワーフの合計を示しています。 カウントを持つ新しいグループの幸福への貢献`a, b, c, d`は：```
(a*(H) - a*(B)) + (b*(O) - b*(A)) + (c*(E) - c*(D)) + (d*(D) - d*(C))
```どこ`A, B, C, D`人間、オーク、エルフ、ドワーフの現在の合計です。 並べ替えると、幸福度の寄与は、味方の数と敵対的な数の合計の差に線形になります。 次のように定義すると、```
x = humans - orcs
y = elves - dwarves
```次に、問題は、次の線形関数の合計を最大化するグループのサブセットを選択することに帰着します。`x`そして`y`。 各グループの貢献度が単調であるため、`x`そして`y`、ジオメトリからの戦略を活用できます。グループを「傾き」で並べ替えます。`(x, y)`プレーンを選択し、貪欲な選択を適用します。 具体的には、グループは次のパリティによって分類できます。`(humans + orcs) - (elves + dwarves)`、そして問題は、これらの線形投影の合計を最大化することに帰着します。 最終的なソリューションでは、sort-and-greed アプローチとプレフィックス合計を組み合わせて合計スコアを効率的に計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.すべて読む`n`グループ化してカウントを保存する`(a, b, c, d)`リストで。 これらは、各グループの人間、オーク、エルフ、ドワーフを表しています。 これにより、最適化ステップの入力が設定されます。 
2. 各グループについて、2 つの導出値を計算します。`x = humans - orcs`そして`y = elves - dwarves`。 これらの違いは、敵対的な相互作用による幸福への最終的な影響をコード化しています。 新しいグループはそれぞれ、次の点でスコアに直線的に貢献します。`x`そして`y`。 
3. 合計スコアは、総人口と幸福度の寄与の合計の合計であることを認識します。 グループを追加することによる幸福度の寄与は次のように表すことができます。`a*(H-B) + b*(O-A) + c*(E-D) + d*(D-C)`、これは次のように単純化します。`x`そして`y`現在の合計では単調です。 
4. 合計スコアを最大化するには、次の符号によってグループを分類します。`x`そして`y`。 ポジティブなグループ`x`そして`y`現在の合計が増加し、幸福度が増加するので、受け入れるべきです。 マイナスの寄与を持つグループは慎重な評価が必要です。 この変換された空間ではスコア関数が凸であるため、最適な選択は、合計によってグループを並べ替えるという貪欲な戦略に帰着します。`x + y`またはその絶対値を選択し、合計スコアが増加した場合にそれらを受け入れます。 
5. ソートされたグループを反復処理して、人間、オーク、エルフ、ドワーフの累積合計を維持します。 各グループについて、追加した場合の合計スコアに対する限界寄与度を計算します。 限界寄与率が負でない場合は、グループを受け入れて合計を更新します。 それ以外の場合はスキップしてください。 これにより、追加するたびに厳密にスコアが向上します。 
6. すべてのグループを処理した後、母集団の合計と反復中に追跡された幸福度の合計の合計として最終的な合計スコアを計算します。 

機能する理由: 各ステップで、合計スコアが増加するグループのみを受け入れます。 幸福度寄与度の線形性`(x, y)`拒否されたグループは現在の累積合計を減少させるだけであるため、以前に拒否されたグループの組み合わせではスコアが改善されなかったことが保証されます。 貢献関数は友好的種族と敵対的種族の純差においてスーパーモジュール化されており、ローカルで最適な選択をグローバルに最適にするため、貪欲な選択は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
groups = [tuple(map(int, input().split())) for _ in range(n)]

# Compute derived values
vals = []
for a, b, c, d in groups:
    x = a - b
    y = c - d
    vals.append((x, y, a + b + c + d))

# Sort by slope in the (x, y) plane to maximize contribution
vals.sort(key=lambda t: -(t[0] + t[1]))

total_score = 0
H = O = E = D = 0

for x, y, total in vals:
    delta = x*(H - O) + y*(E - D) + total
    if delta >= 0:
        H += x + (x < 0)*(-x)  # recover actual humans
        O += (H-O) - x
        E += y + (y < 0)*(-y)
        D += (E-D) - y
        total_score += delta

print(total_score)
```このソリューションでは、まず各グループを敵味方軸に沿った純貢献度に換算し、次に予測スコアで並べ替えます。 難しい部分は、累積幸福度寄与を正しく計算し、グループの合計が正確に更新されるようにすることです。 貪欲なステップは、次のスコア関数の凸性によって正当化されます。`(x, y)`空間。
