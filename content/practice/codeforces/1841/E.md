 ## 解決策
 ## 問題の理解

 マトリックスの各列には、黒の接頭辞と白の接尾辞が含まれます。 列内`i`、行`1..a_i`行はブロックされていますが、`a_i+1..n`利用可能です。 

整数を配置する必要があります`1,2,...,m`明確な白血球に変化します。 美しさは連続したペアの数を数えます`(j, j+1)`同じ行の水平方向に隣接するセルになります。`j+1`のすぐ右側`j`。 

数値の実際の値は、その順序によってのみ重要になります。 白いセルの水平セグメント内に連続する数字を配置するたびに、セグメントには次の内容が含まれます。`k`数字は正確に寄与する`k-1`美しさは、その実行内のすべての隣接するペアが 1 回ずつ寄与するためです。 

マトリックスのサイズは最大でも`2·10^5`すべてのテストケースにわたって。 すべてに明示的に触れるアルゴリズム`n²`細胞は無理です。 行列全体を保存するだけでもコストがかかりすぎます。 白セルの構造はアレイから直接利用する必要があります。`a`。 

微妙な点としては、`m`非常に大きくなる可能性があります。 このステートメントは、32 ビット整数に収まらない可能性があることを明示的に警告しています。 配置された値の数を含むすべての計算では、64 ビット演算を使用する必要があります。 

もう 1 つの簡単な間違いは、各行を独立して処理できると考えることです。 考慮する：```
n = 3
a = [0,0,0]
m = 9
```すべてのセルは白色です。 長さの行セグメントが 3 つあります`3`。 それぞれをしっかり満たして美しさを与える`2 + 2 + 2 = 6`、これが最適です。 ここでは行を独立して処理しても問題ありません。 

ここで次のことを考えてみましょう。```
n = 4
a = [2,0,3,1]
m = 5
```行セグメントの長さは異なります。 新しいセグメントごとに 1 ペナルティが発生するため、短いセグメントに数値を費やすと最終的な美しさが損なわれる可能性があります。 最適な戦略は、行自体ではなく、セグメントの長さによって決まります。 

3 番目のトラップは、残りの整数が次のセグメントを完全に埋めることができない場合に表示されます。 ある長さのセグメントの場合`L`、置くだけ`x < L`数字が貢献する`x-1`、 ない`x`。 この詳細が欠けていると、最後の貪欲なステップで off-by-one エラーが発生します。 

## アプローチ

 まず最初に役立つのは総当たりビューです。 

最大の水平方向の白いセグメントをすべて抽出することを想像してください。 セグメントに長さがある場合`L`、次に充填`k`その部分の細胞が連続して美しさを生み出します`k-1`いつでも`k > 0`。 

すべてのセグメントを知っていたとします。 そうすれば、可能な限りのディストリビューションを試すことができます。`m`その中の数字。 これは明らかに正しいです。美しさは各セグメントが受け取る数値の数によってのみ決まるからです。 残念ながら、分布の数は膨大であり、単純にすべてのセグメントを生成するだけでも、マトリックス全体を調べる必要があります。`4·10^10`細胞。 

重要な観察は、塗りつぶされたセグメントが`k`数字が貢献する```
k - 1
```これは次のように書き換えることができます```
k - (number of used segments)
```すべてのセグメントの合計。 

配置された数字の合計数は固定されているため、`m`、美しさを最大化することは、少なくとも 1 つの数値を受け取るセグメントの数を最小化することと同じです。 

それはすぐに貪欲な戦略を示唆します。 利用可能なセグメントが複数ある場合は、最も長いセグメントを最初に入力する必要があります。 長いセグメントは、短いセグメントと同じ「1 セグメント」ペナルティを支払う一方で、多くの番号を吸収できます。 

問題は次のようになります。 

1. 考えられるすべての長さに対して、最大の水平方向の白色セグメントがいくつ存在するかを見つけます。 
2.`m`セグメント上の最大長から最小長までの番号。 

残りの課題は、マトリックスを構築せずに、最大の水平方向の白色セグメントをすべて抽出することです。 

一列に`r`、 カラム`i`白いなら`a_i < r`。 最大の水平セグメントは、すべての高さが行レベルを下回る列の間隔に対応します。 

これはヒストグラムの問題に現れる構造とまったく同じです。 単調スタックを使用すると、長さごとに最大セグメントがいくつ存在するかを数えることができます。 スタックは、次のように形成されたスカイラインを処理します。`a_i`、そしてすべてのポップは、その範囲を生成する行レベルの数とともに範囲の長さを決定します。 

取得後`cnt[len]`、長さの最大セグメントの数`len`、貪欲な充填は簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n²) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 以下の実装は、長さにわたる反復とは別に、実際には線形時間で実行されます。 

## アルゴリズムのチュートリアル

 1. 通訳する`a_i`ブロックされたセルの列の高さとして。 
2.高さのセンチネル列を 2 つ追加します`n`両端にあります。 これらにより、すべてのセグメントが最終的に閉じられ、カウントされることが保証されます。 
3. 単調減少スタックで配列を処理します。 
4. 現在の高さが少なくとも前の列の高さになったら、スタック要素のポップを開始します。 
5. ポップ中に、ポップされた各高さは、特定の長さの最大の水平方向の白いセグメントを作成する行レベルの範囲を表します。 これらの貢献を蓄積して、`cnt[length]`。 
6. 許可されたすべてのポップの後、スタックがまだ空でない場合は、最後にポップされた高さと現在の高さとの間に生成された残りの寄与を追加します。 
7. すべての列を処理した後、`cnt[len]`長さを持つ最大の白セグメントの数を格納します`len`。 
8. トラバースの長さは最大から最小までです。 
9. 長さについて`L`カウント付き`C`：

- もし`m >= L·C`、そのようなセグメントをすべて完全に埋めます。 
- 完全に埋められた各セグメントが貢献します`L-1`。 
- Subtract`L·C`から`m`。 
10. 数字が足りない場合`C`セグメント:

 - 完全に記入してください`m // L`セグメント。 
- 残りを使用する`m % L`追加の 1 つのセグメント内にあります。 
- 部分的に塗りつぶされたセグメント`r`数字が貢献する`r-1`いつ`r > 0`。 
- このステップの後、すべての数値が使用され、アルゴリズムが停止します。 

### なぜ効果があるのか

 占有されているすべてのセグメントは、その中に配置されている整数の数と比較して、正確に 1 単位の美しさの損失を支払います。 

セグメント受信の場合`k`数字:```
beauty = k - 1
```使用されているすべてのセグメントを合計すると、次のようになります。```
beauty = m - used_segments
```配置される整数の総数は固定されているため、`m`。 

美しさを最大限に高めるには、番号を受け取るセグメントの数を最小限に抑える必要があります。 そのための最適な方法は、常に、利用可能な最も長いセグメントから容量を最初に消費することです。 より長い未使用セグメントが存在するときに短いセグメントを使用する解決策は、占有セグメントの数を決して増やさずに、番号を短いセグメントから長いセグメントに移動することで改善できます。 

単調スタックは、各ポップが特定の高さが制限境界となる間隔を正確に識別するため、最大の白いセグメントを正確にカウントします。 隣接する高さの差によって、その間隔の長さを生成する行レベルの数が決まります。 これは標準のヒストグラム分解引数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        m = int(input())

        a = [n] + arr + [n]
        N = n + 1

        stack = [0]
        cnt = {}

        for i in range(1, N + 1):
            if a[i] >= a[i - 1]:
                prev = a[stack[-1]]
                stack.pop()

                while stack and a[stack[-1]] <= a[i]:
                    length = i - stack[-1] - 1
                    cnt[length] = cnt.get(length, 0) + (a[stack[-1]] - prev)
                    prev = a[stack[-1]]
                    stack.pop()

                if stack:
                    length = i - stack[-1] - 1
                    cnt[length] = cnt.get(length, 0) + (a[i] - prev)

            stack.append(i)

        ans = 0

        for length in sorted(cnt.keys(), reverse=True):
            if length == 1:
                continue

            c = cnt[length]
            total_cells = length * c

            if total_cells <= m:
                ans += c * (length - 1)
                m -= total_cells
            else:
                full = m // length
                ans += full * (length - 1)
                m -= full * length

                if m > 0:
                    ans += m - 1

                m = 0
                break

            if m == 0:
                break

        print(ans)

solve()
```コードの最初の部分は、列の高さによって形成されたヒストグラムの単調スタック分解を実行します。 辞書`cnt`各長さに対して最大の水平セグメントがいくつ存在するかを格納します。 

変数`prev`重要な詳細です。 連続したポップされた高さは、行レベルの異なるバンドを表します。 高さの違いを使用すると、同じ行レベルを複数回カウントすることを回避できます。 

すべてのセグメント数がわかった後、貪欲フェーズは最大の長さから下に向かって反復されます。 完全に満たされた長さのセグメント`L`貢献する`L-1`そのため、更新内容は次のとおりです。```
ans += count * (L - 1)
```部分塗りつぶしの場合は、最も間違いが起こりやすい箇所です。 残りが`r`、貢献度は`r-1`、 ない`r`。 いつ`r = 0`、余分なセグメントは存在しないため、何も追加されません。 

Python の整数は、次の大きな値を自動的に処理します。`m`。

 ## 特殊なケース

 次のことを考慮してください。```
1
1
0
1
```白マスはちょうど 1 つあります。 唯一可能な配置は、1 つの数字を含む 1 つのセグメントを使用することです。 美しさは`1 - 1 = 0`。 貪欲フェーズでは長さ 1 のセグメントから何も得られないため、アルゴリズムは正しく出力します。`0`。 

考慮する：```
1
2
0 0
3
```長さの行セグメントが 2 つあります`2`。 アルゴリズムはまず 1 つのセグメントを完全に埋めて、`1`美しさと2つの数字の使い方。 1 つの番号が残り、別のセグメントが開始され、寄与します`0`。 トータルな美しさは、`2 - 1 = 1`最初のセグメントからプラス`0`2番目から、与える`2`全体。 部分塗りつぶしルール`r - 1`これを正確に処理します。 

考慮する：```
1
3
3 3 3
0
```どのセルも黒いです。 スタック分解では、有用なセグメント長は生成されません。 貪欲フェーズは何もせずに戻ります`0`、これが唯一可能な答えです。 

最後に、残りの数値が長いセグメントの途中で停止する場合を考えてみましょう。```
1
3
0 0 0
4
```最善の戦略は、4 つの数字すべてを長さ 3 のセグメント内に配置し、必要な場合にのみ別のセグメントに続けることです。 アルゴリズムは 1 つの長さ 3 のセグメントを完全に埋めて、`2`、残りの単一の数値が寄与します`0`。 答えは`2`、最適な構造に一致します。
