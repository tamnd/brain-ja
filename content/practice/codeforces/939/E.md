 ## 解決策
 ## 問題の理解

 私たちは正の整数の増加するコレクションを維持しています。 コレクションは空から始まり、新しい数値を挿入するか、現在のコレクションについて質問するという 2 種類の操作を処理します。 

挿入ルールは特別です。すべての新しい数値は、以前に挿入されたすべての数値と少なくとも同じ大きさであることが保証されます。 これは、マルチセットが到着の降順でない順序で効果的に維持されることを意味します。 

このクエリでは、現在の数値の空でないサブセットを選択するように求められます。 そのサブセットについて、その最大要素とその平均値の差として定義される値を計算します。 すべてのサブセット選択に対して、この式の可能な最大値を返さなければなりません。 

主な問題点は、クエリごとにサブセットを個別に最適化していないことです。 挿入するたびに構造が永続的に変更され、クエリはストリーム内のどこにでも現れる可能性があります。 最大 500,000 の操作があるため、クエリごとに最初から再計算することは不可能です。 

この制約は、挿入された要素の数が二次関数的に動作する解は失敗することを意味します。 平$O(n)$クエリごとにつながる$O(n^2)$最悪の場合、総作業量は限界をはるかに超えます。 私たちは、挿入のたびに、$O(1)$または$O(\log n)$、各クエリも$O(1)$または$O(\log n)$。 

サブセットの最適化では、微妙な問題が発生します。単純な直感では、サフィックスのみ、または最大要素を含むサブセットのみを試行することを提案するかもしれませんが、慎重に推論しないと、正しい削減を見逃しがちです。 もう 1 つの落とし穴は、クエリごとにすべての要素を明示的に追跡する必要があると想定していることです。これにより、繰り返しスキャンとタイムアウトが発生します。 

## アプローチ

 ブルートフォース手法では、クエリごとに現在のセットのすべてのサブセットを列挙し、それらの最大値と平均値を計算し、最適な値を追跡します。 大域的最大値を含むサブセットに限定したとしても、依然として指数関数的な数の選択肢に直面します。 これは直ちに実行不可能です。 

より合理的な素朴なアプローチは、最大要素が固定されている場合、より小さい要素を追加すると平均が減少することを観察することです。 そこで、最大の要素を修正し、最大と平均の間のギャップを増やすために最小の要素を追加することを検討してみてください。 ただし、残りの要素のすべての組み合わせを試しても、依然として指数関数的な動作が発生します。 

重要な構造観察は、目的を書き直すことから得られます。 サブセットの場合$s$、その最大値を$M$、そのサイズは$k$、その合計は$S$。 値は$$M - \frac{S}{k}.$$直したら$M$、要素のみ$\le M$が適格であり、平均を最小化し、値の小さい要素を選択することによる比率効果を同等に最大化したいと考えています。 

要素は減少しない順序で到着するため、新しい最大値が現れると、以前のすべての要素はすでに固定されており、既知であることがわかります。 これにより、それぞれの新しい値を潜在的な「アンカー最大値」として扱い、以前のすべての値の集計統計を維持することができます。 

固定最大値の場合$a_i$、この要素と以前の要素のプレフィックスから構成されるサブセットを選択するとします。 これまでの要素はすべて小さいか等しいため、目的を向上させるかどうかに応じて、すべてを含めるか、まったく含めないかが最善の戦略です。 これにより、プレフィックスの合計を維持し、クエリごとに線形式をテストするという問題が軽減されます。 

この式は、考えられる分割点ごとに、次の形式の値を評価することを単純化します。$$a_i - \frac{S_j + a_i}{j+1}.$$再配置すると、凸包のような構造または単調な構造を使用して候補値を維持できる形式が得られます。 ただし、非減少挿入制約により、最適なサブセットは常にシーケンスの一部のプレフィックスに現在の最大値を加えたものに対応するという、より単純な観察が成り立ちます。 

したがって、挿入された要素のプレフィックスの合計を維持し、最適な分割を効率的に評価するだけで済みます。 各クエリは、単調なシーケンスに対して事前に計算された式をチェックすることになり、段階的に維持できます。

 ## アルゴリズムのチュートリアル

 1. 実行中のプレフィックス合計配列とともに、挿入された値のリストを順番に維持します。 これにより、任意のプレフィックスの合計を定数時間で計算できます。 
2. 挿入ごとに、新しい値を追加し、プレフィックスの合計を更新します。 値は減少しないため、要素を並べ替えたり結合したりする必要はありません。 
3. クエリの場合、明示的なループではなく維持された構造を使用して、可能なプレフィックス長を暗黙的に反復します。 各プレフィックスから導出された式の最適な値を追跡します。 
4. 次の形式の候補値を格納する補助構造を維持します。$$f(k) = k \cdot a_k - S_k$$または、現在の最大値で終わる最適なサブセットを迅速に評価できる同等の変換された式。 
5. 各クエリで、現在の最大要素と保存されている最良の候補を使用して最良の値を計算し、結果を出力します。 

中心的な考え方は、挿入はドメインを拡張するだけであり、要素は到着順にソートされるため、以前の構造上の決定を再検討する必要がないということです。 

### なぜ効果があるのか

 正確さは、最適なサブセットにはその最大要素が含まれている必要があり、その最大値が固定されると、残りのすべての候補が挿入オーダーの連続するプレフィックスから得られるという事実から得られます。 非減少挿入ルールにより、プレフィックス合計が目的に関連するすべてのサブセット合計を完全に特徴付けることが保証され、選択されたより大きな要素を除外されたより小さな要素で置き換えることで常に目的が改善または維持されるため、インターリーブ サブセットがプレフィックス ベースの構築よりも優れたパフォーマンスを発揮することはありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    out = []

    for line in inp.strip().splitlines()[1:]:
        t = list(map(int, line.split()))
        if t[0] == 1:

 ## 特殊なケース

 重要なエッジケースは、クエリ時に要素が 1 つだけ存在する場合です。 サブセットにはその要素が含まれている必要があるため、値は常にゼロになります。 このアルゴリズムは、配列の長さが 1 の場合に明示的にゼロを返すことでこれを処理します。 

すべての要素が等しい場合、別の特殊なケースが発生します。 どのサブセットでも最大値は平均値に等しいため、サブセットのサイズに関係なく、答えは常に 0 になります。 接頭辞の評価では、当然のことながら、すべての候補に対してゼロが生成されます。 

最後の微妙なケースは、多数の小さな要素の後に非常に大きな要素が到着する場合です。 最適なサブセットには常に大きな要素と、慎重に選択された小さな要素のサブセットのみが含まれます。 プレフィックス スキャンでは、すべてのプレフィックスが最終的な最大値に対してテストされるため、この対話が正しくキャプチャされることが保証されます。
