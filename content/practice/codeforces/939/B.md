 ## 解決策
 ## 問題の理解

 Dima には、輸送の準備が整う固定数のハムスターと、それぞれ容量の異なるボックス タイプのコレクションが用意されています。 使用するすべてのボックスは完全に満たされている必要があり、混合タイプを購入すると割引が適用されないため、選択したすべてのボックスは単一のタイプである必要があります。 

したがって、決定は次のとおりです。リストから容量値を 1 つ選択し、それが保持されているとします。`a`箱ごとにハムスターを梱包し、利用可能な梱包材を使用して、そのサイズの完全な箱をできるだけ多く梱包します。`N`ハムスター。 完全な箱に収まらない残りのハムスターは取り残され、結果には寄与しません。 

選択した容量に対して`a`、使用可能なボックスの数は`N // a`、輸送されたハムスターの数は、`a * (N // a)`。 目標は、この転送された合計を最大化するインデックスを選択することです。 

制約は非常に大きいです。`N`は最大 10^18、各容量も最大 10^18 で、タイプの数は 100,000 に達することがあります。 これにより、梱包をシミュレートしたり、ハムスターや箱を個別に反復しようとしたりするアプローチは即座に除外されます。 容量を超える二次推論さえ不可能です。 唯一実現可能な方向は、各型を一定時間で独立して評価することです。 

いくつかの特殊なケースは注目に値します。 いつ`N = 0`、ハムスターは存在しないため、どの容量でも輸送されるハムスターはゼロになり、どのタイプも有効ですが、ボックスの数もゼロでなければなりません。 ボックス容量がそれより大きい場合`N`、このタイプでは、完全なボックスを形成できないため、輸送されるハムスターもゼロになります。 これらのケースでは、少なくとも 1 つの完全なボックスが常に存在することを前提とする誤った貪欲なロジックが静かに壊れる可能性があります。 

## アプローチ

 強引な解釈では、各タイプを選択した後に何匹のハムスターが残り、何個の完全な箱が形成できるかを推論しようとします。 容量ごとに`a_i`、完全なボックスがいくつ収まるかを計算し、それを乗算して輸送された合計を取得します。 各タイプは相互作用せずに独立して評価できるため、これはすでに最適に近い状態になっています。 

単純な間違いは、タイプごとにいくつのボックスを取得するかを列挙しようとすることです。`1`まで`N / a_i`、タイプごとに最適な選択を計算します。 その場合、総複雑さは考えられるすべてのボックス数の合計に比例し、最悪の場合は 10^18 に達し、完全に実行不可能になります。 

重要な観察は、問題の構造がすべての組み合わせ相互作用を排除していることです。 容量が決まると、できるだけ多くの完全なボックスを取得するという最善の戦略が強制されます。 未使用のハムスターは後で何も改善できないため、箱の数を減らしてもメリットはありません。 これにより、問題はタイプごとに 1 つの式を評価し、最大値を選択することになります。

 | 各タイプを 1 回評価する | O(K) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ボックス タイプを個別に処理し、そのタイプが選択された場合に達成可能な最良の結果を計算します。 

1.読む`N`そして容量のリスト。 これらは、利用可能なハムスターの合計と可能なすべてのボックス サイズを定義します。 
2. 変数を初期化して、これまでに見つかった最良の答え (最良のインデックスや最良の転送値など) を格納します。 
3. 種類ごとに`i`、いくつの完全なボックスを形成できるかを計算します。`N // a[i]`。 これにより、ボックスを完全に埋める必要があるという要件が直接強制されます。 
4. 輸送されたハムスターを次のように計算します。`a[i] * (N // a[i])`。 これは、その選択で使用可能な合計出力を測定します。 
5. この値がこれまでに確認された最良の値よりも大きい場合は、最良のインデックスを更新し、インデックスとボックスの数の両方を保存します。 
6. すべてのタイプをスキャンした後、保存されている最良のインデックスと対応するボックス数を出力します。 

中心的な考え方は、各候補タイプが決定論的な結果を引き起こすため、問題は独立したオプションに対する線形スキャンになるということです。 

### なぜ効果があるのか

 固定容量の場合、部分的なボックスは禁止され、未使用のハムスターをタイプ間で再分配できないため、最適な戦略は完全に決定されます。 したがって、各タイプは 1 つの可能な結果を​​定義します。 選択肢間に結合はないため、これらの結果を個別に比較するだけで、グローバル最大値が見つかることを保証できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    best_idx = 1
    best_val = -1
    best_boxes = 0

    for i, x in enumerate(a, start=1):
        boxes = n // x
        total = boxes * x

        if total > best_val:
            best_val = total
            best_idx = i
            best_boxes = boxes

    print(best_idx, best_boxes)

if __name__ == "__main__":
    solve()
```実装は、各タイプの派生式に直接に従います。 Python の整数はオーバーフローしないため、整数の除算はすべての大きな値を安全に処理します。 比較では、転送された合計を主要なメトリックとして使用しますが、ボックスの数は、最適なタイプが特定された後の出力用にのみ保存されます。 インデックスは、入力仕様と一致するように 1 から始まる形式で追跡されます。 

微妙な点は初期化：設定です。`best_val`に`-1`場合でも確実に`N = 0`、最初のタイプはまだ選択されており、ボックスがゼロの有効な回答が生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    best_idx = 1
    best_val = -1
    best_boxes = 0

    for i, x in enumerate(a, start=1):
        boxes = n // x
        total = boxes * x
        if total > best_val:
            best_val = total
            best_idx = i
            best_boxes = boxes

    return f"{best_idx} {best_boxes}"

assert run("19 3\n5 4 10\n") == "2 4"

# minimum N = 0
assert run("0 3\n5 4 10\n") in ["1 0", "2 0", "3 0"]

# all capacities larger than N
assert run("3 3\n10 11 12\n") in ["1 0", "2 0", "3 0"]

# all equal capacities
assert run("20 3\n5 5 5\n") in ["1 4", "2 4", "3 4"]

# mixed case
assert run("17 4\n3 4 5 6\n") == "2 4"

 ## 特殊なケース

 いつ`N = 0`、計算`N // a[i]`は常にゼロであるため、どのタイプでも輸送されるハムスターはゼロになります。 比較では次から始まる厳密な大なりチェックが使用されるため、アルゴリズムは引き続き最初のタイプを選択します。`-1`、すべての候補者がゼロで引き分けられます。 出力ではボックスがゼロであることが正しく報告されます。 

すべての容量を超えた場合`N`の場合、各候補はボックスを生成しません。 このアルゴリズムは、これらの型を途中で破棄しようとしません。これにより、フィルタリング ロジックによる誤った動作が回避されます。 最初のタイプは有効な応答として返されます。 

複数のタイプが同じ最大転送値に達すると、アルゴリズムは最初に見つかった最大値を保持します。 この問題では任意の正解が許容されるため、このタイブレークは有効であり、一貫性があります。
