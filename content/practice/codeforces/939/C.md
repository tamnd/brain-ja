 ## 問題の理解

 私たちには円形のタイムラインが与えられています。$n$個別の時間。時間ラベルはラップアラウンドして、その後$n$また1が来ます。 それぞれの$n$タイムゾーンは、近隣のタイムゾーンと比較して現地時間を正確に 1 時間ずらすため、タイムゾーン 1 のグローバル開始時刻は、他のすべてのタイムゾーンで固定のローカル開始時刻を誘導します。 

タイムゾーンごとに$i$、 がある$a_i$参加者。 タイムゾーンからの参加者$i$そのタイムゾーンのローカル時計でコンテストが正時以降に開始される場合にのみコンテストに参加します$s$、厳密に正時間前に終了します$f$。 コンテストはちょうど 1 時間続き、常に整数時間に始まります。 

タスクは、タイムゾーン 1 の開始時間を選択して、その開始時間を各タイムゾーンの現地時間に変換した後、制約を満たす参加者の数が最大になるようにすることです。 複数の開始時間で同じ最大参加者数が得られる場合は、タイムゾーン 1 の最小の開始時間を返す必要があります。 

入力サイズ$n \le 10^5$直接シミュレーションのコスト計算を使用して、考えられるすべての開始時間をチェックすることを即座に除外します。$O(n^2)$。 どのソリューションも、ほぼ線形または線形時間で動作する必要があります。 これは、各開始時刻を最初から再計算するのではなく、段階的に更新するか、プレフィックス構造を介して計算する必要があることを示唆しています。 

微妙な点は、時間の循環性です。 のような間隔$[s, f)$ローカル時間では、ラップアラウンドするため、単一の配列内の時間の線形表現と必ずしも一致するとは限りません。$n$それらを 2 つのセグメントに分割します。 ラップアラウンドを無視する素朴なアプローチは、次のような場合には失敗します。$s > f$問題は保証されていますが、$s < f$、タイムゾーン オフセットによってシフトした後もラップは表示されます。 

2 番目のエッジ ケースはタイブレークから発生します。複数の開始時間が同じ最大値を生成する場合、最小のインデックスを返さなければなりません。 したがって、スライディング ウィンドウ スタイルのソリューションでは、誤って後のインデックスが優先されることがないように、更新順序を慎重に定義する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、タイムゾーン 1 で考えられるすべての開始時間を試行します。$t$、各タイムゾーンのローカル開始時間を計算します。$i$、実質的には$t + (i-1)$モジュロ$n$、区間内にあるかどうかを確認します$[s, f)$。 そうであれば、追加します$a_i$その開始時間の合計寄与度に加算されます。 

このアプローチは、すべての参加者の条件を直接シミュレートするため、正しいです。 ただし、それぞれについて、$n$開始時間、すべてを繰り返します$n$タイムゾーン、それにつながる$O(n^2)$操作。 と$n = 10^5$、これは$10^{10}$制限時間をはるかに超えたチェック。 

重要な観察は、各開始時刻が同じ値のセットを周期的にシフトすることです。 寄与を最初から再計算する代わりに、円形配列上でスライディング ウィンドウを維持することとして問題を捉えることができます。 開始時間が固定されている場合、参加する参加者は、シフトされたインデックスが円軸上の連続した間隔に該当するタイムゾーンに正確に対応します。 

これにより、固定長の移動ウィンドウ内で重みの合計を維持するという問題が軽減されます。$f - s$。 開始時間が 1 ずつ増加すると、このウィンドウは 1 位置ずつシフトし、2 つの境界位置のみがメンバーシップを変更します。 プレフィックスサムまたは 2 ポインター構造を使用すると、次のように答えを更新できます。$O(1)$シフトごとに。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. タイムゾーン 1 の各開始時刻を、すべてのタイムゾーンのシフトを引き起こすものとして解釈します。これは、コントリビューションの配列を円上で回転させるのと同じです。 この再定式化により、問題は円形配列上の固定長のウィンドウの選択に変換されます。 
2. サイズの補助配列を構築する$2n$オリジナルを複製することで$a_i$。 これにより、モジュラー演算を行わずに円形ウィンドウを線形セグメントとして表現できるようになります。 
3. 拡張配列全体でプレフィックスの合計を計算し、セグメントの合計を一定時間で計算できるようにします。 
4. ウィンドウの長さを決定する$L = f - s$。 可能な開始位置ごとに$t$から$1$に$n$、セグメントを考えてみましょう$[t + s, t + f)$ローカル座標で、拡張配列内の固定長の間隔にマップされます。 
5. それぞれについて$t$、プレフィックス合計を使用して、参加者の合計を範囲合計として計算します。 最大値と、それを達成する最小のインデックスを追跡します。 

この定式化が機能する理由は、グローバル開始時刻を変更することが、許容可能なローカル間隔内に収まるタイムゾーンを変更することに正確に対応するためです。 すべてのタイムゾーンは均一にシフトするため、「良好な」インデックスの相対的な構造は、循環シーケンスにわたるスライディング ウィンドウとして保存されます。 プレフィックスサムの削減により、各候補ウィンドウが一定時間で評価されることが保証されるため、すべての開始点にわたる完全なスイープは線形のままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
s, f = map(int, input().split())

# build circular array
arr = a + a

# prefix sums
pref = [0] * (2 * n + 1)
for i in range(2 * n):
    pref[i + 1] = pref[i] + arr[i]

length = f - s  # window size in local time

best_value = -1
best_idx = 1

for start in range(n):
    left = start + s - 1
    right = start + f - 1
    total = pref[right] - pref[left]

    if total > best_value:
        best_value = total
        best_idx = start + 1

print(best_idx)
```コードはまず配列を 2 倍にして、円形の間隔を直線セグメントとして表現できるようにします。 プレフィックス合計では、O(1) セグメント合計クエリが可能です。 タイムゾーン 1 の可能な開始時間ごとに、拡張配列内のどのインデックスが現地時間が該当する参加者に対応するかを計算します。$[s, f)$。 引き算`pref[right] - pref[left]`はまさにそのセグメントの合計です。 

注意が必要なのはインデックス作成です。 1 ベースの時間記述から 0 ベースの Python インデックスへの変換により、一貫したシフトが導入されます。`start + s - 1`そして`start + f - 1`セグメントがプレフィックス境界と正確に一致していることを確認します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s, f = map(int, input().split())

    arr = a + a
    pref = [0] * (2 * n + 1)

            best_idx = start + 1

 ## 特殊なケース

 エッジ ケースの 1 つは、最適な間隔が円形配列の境界を囲む場合です。 たとえば、高い値が配列の最後と先頭にある構成では、最適なウィンドウ スパンのインデックスは次のようになります。$[n-1, 1]$。 二重配列構造により、これが連続セグメントとして扱われることが保証されるため、プレフィックス合計クエリは引き続き正しくキャプチャされます。 

もう 1 つのエッジ ケースは、複数の開始位置で合計が同じになる場合です。 厳密に大きい場合にのみ最良のものを更新するため、最初に出現したものが保持され、最小のインデックスが返されることが保証されます。
