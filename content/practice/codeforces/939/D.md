 ## 解決策

 ## 問題の理解

 同じ長さの 2 つの文字列が与えられ、1 つはヴァリヤのプルオーバーに、もう 1 つはトーリヤの T シャツに書かれています。 目標は、許可された変換ルールのセットを使用して 2 つの文字列を同一にすることです。 

各呪文は小文字のペアに対応します。 手紙の呪文を買ったら`c1`そして`c2`、変換することが許可されています`c1`の中へ`c2`そしてまた`c2`の中へ`c1`この変換は、両方の文字列の任意の位置に何度でも適用できます。 

重要な点は、固定された順序で文字に対する操作を直接実行しないことです。 代わりに、文字間に一連の「双方向エッジ」を選択します。これらのエッジは、変換の連鎖を通じて最終的にどの文字がどの文字に変換されるかを定義します。 私たちのタスクは、すべての位置で次のようなエッジの可能な限り最小のセットを選択することです。`i`、これらの変換を使用して、その位置にある 2 つの文字を等しくすることができます。 

したがって、問題は次のようになります: 26 文字で無向グラフを構築する。 エッジの追加には 1 のコストがかかり、エッジを使用すると、接続されたコンポーネントに沿って自由に移動できます。 どのペアも欲しい`(s[i], t[i])`同じ接続コンポーネント内に存在します。 目的は、エッジの数を最小限に抑え、最適なエッジ セットを出力することです。 

制約`n ≤ 100000`これは、位置ごとに変換をシミュレートしたり、操作のサブセットを試行したりできないことを意味します。 文字の二次関数や文字列に対する演算ごとの線形関数は遅すぎます。 アルファベットのサイズは 26 に固定されているため、文字のペアを推論したり、文字に対して DSU を使用したりするソリューションが実行可能です。 

いくつかの特殊なケースが重要です。 

両方の文字列がすでに同一である場合、答えはゼロとなり、何も出力しなければなりません。 単純なアプローチでは、不要な操作を追加しようとする可能性があります。 

たとえば、すべてのポジションがまったく異なる場合、`"abc"`そして`"xyz"`、不注意で貪欲なアプローチは、すべての不一致を独立して接続しようとし、構造を再利用する代わりに多くの冗長なエッジを生成する可能性があります。 

主な落とし穴は、それぞれの不一致が個別に処理できると想定していることです。 実際には、1 つのエッジがコンポーネントを接続するため、一度に多くの位置を支援できます。 

## アプローチ

 ブルートフォースの方法は、これを 26 個のノード間のエッジのセットを選択し、誘導されたグラフ内ですべてのペアを接続できるかどうかをテストするものとして扱います。 文字間のエッジのすべてのサブセットを列挙し、DSU または BFS を使用して接続をシミュレートし、実現可能性を確認できます。 可能なエッジの数は 325 なので、これは不可能です。 不一致に現れるエッジのみに制限しても、最大 26×26 の可能性が得られ、依然として指数関数的です。 

重要な観察は、各位置が次の要件を強制することです: 文字`a = s[i]`そして`b = t[i]`同じ接続コンポーネントに到達する必要があります。 それらがすでに同じ文字である場合は、無視できます。 それ以外の場合は、2 つのノード間の接続を確保する必要があります。 これを最小限のエッジで実現するには、コンポーネントをできるだけ安価にマージしたいと考えます。 

これは古典的な DSU 構築の問題になります。 26 個のシングルトン コンポーネントから始めます。 それぞれの不一致ペアについて`(a, b)`、すでに接続されている場合は何もしません。 それ以外の場合は、それらの間にエッジを追加して、それらのコンポーネントをマージする必要があります。 エッジを追加するたびに、接続されているコンポーネントの数が最大 1 つずつ減ります。そのため、必要な場合にのみエッジを追加します。 

2 つのコンポーネント間に必要な同等性があれば、それらの間に少なくとも 1 つの接続が強制されるため、これは最適です。 有効なソリューションでは、必要なすべてのペアを接続する必要があるため、DSU マージは必要な最小限の接続をキャプチャします。

 ## アルゴリズムのチュートリアル

 1. 26 個の小文字を使用して DSU を初期化します。各文字は独自のコンポーネントに含まれます。 
2. 文字列のすべてのインデックスを反復処理します。 
3. ポジションごとに`i`、 比較する`s[i]`そして`t[i]`。 
4. 同じ文字の場合は、変換する必要がないのでスキップします。 
5. 異なる場合は、それらのコンポーネントがすでに DSU に接続されているかどうかを確認します。 
6. 接続されていない場合は、結合してペアを記録します。`(s[i], t[i])`選んだ呪文として。 
7. すべての位置が処理されるまで続行します。 
8. 記録された呪文の数とペアのリストを出力します。 

2 つの文字が異なるコンポーネントにある場合にのみ呪文を追加する理由は、一度接続すると、このペアまたは間接的に関連するペアの今後の出現が推移的な接続性によってすでに満たされるためです。 

### なぜ効果があるのか

 各結合操作は、以前は別々だった 2 つのコンポーネントを接続し、2 つの文字間に必要な等価性がある場合は、それらのコンポーネントが接続されることが要求されます。 コンポーネントをマージするときにのみエッジを追加するため、エッジを選択した時点ですべての操作が必要になります。 少なくとも 1 つの位置の接続を切断せずにエッジを削除することはできません。また、DSU によって必要なすべてのペアが推移的に接続されることが保証されるため、追加のエッジは必要ありません。 

したがって、このアルゴリズムは、文字列の不一致によってエッジが引き起こされるグラフ上に最小全域フォレストを構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.r[ra] < self.r[rb]:
            ra, rb = rb, ra
        self.p[rb] = ra
        if self.r[ra] == self.r[rb]:
            self.r[ra] += 1
        return True

n = int(input())
s = input().strip()
t = input().strip()

dsu = DSU(26)
res = []

for i in range(n):
    a = ord(s[i]) - 97
    b = ord(t[i]) - 97
    if a == b:
        continue
    if dsu.union(a, b):
        res.append((s[i], t[i]))

print(len(res))
for a, b in res:
    print(a, b)
```DSU 構造は、文字の接続されたコンポーネントを維持します。 不一致が見つかるたびに、コンポーネントをマージしようとします。 の`union`この関数により、実際にマージが発生した場合にのみコストを支払うことが保証され、コンポーネントの数を減らさない冗長な呪文が回避されます。 

微妙な点は、変換を明示的に保存またはシミュレートしようとしていないことです。 一連の呪文はグラフ内の到達可能性に正確に対応するため、接続性だけで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
            self.r = [0] * n

        def find(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x

        def union(self, a, b):
            ra, rb = self.find(a), self.find(b)
            if ra == rb:
                return False
            if self.r[ra] < self.r[rb]:
                ra, rb = rb, ra
            self.p[rb] = ra
            if self.r[ra] == self.r[rb]:
                self.r[ra] += 1
            return True

    n = int(input())
    s = input().strip()
    t = input().strip()

    dsu = DSU(26)
    res = []

    for i in range(n):
        a = ord(s[i]) - 97
        b = ord(t[i]) - 97
        if a != b and dsu.union(a, b):
            res.append((s[i], t[i]))

    out = [str(len(res))]
    out += [f"{a} {b}" for a, b in res]
    return "\n".join(out)

 ## 特殊なケース

 エッジケースの 1 つは、すべての位置がすでに等しい場合です。 DSU は結合を実行しないので、結果リストは空のままで、正しくゼロが出力されます。 

もう 1 つのケースは、すでに接続されている文字に関係する不一致が繰り返される場合です。 たとえば、合併後`a`そして`b`、その後の出会い`(b, a)`新しいエッジは生成されません。 DSU チェックはエッジの重複を防止し、過剰にカウントしないようにします。 

最後の微妙なケースは、次のような長いチェーンです。`a-b-c-d`さまざまな立場によって引き起こされます。 このアルゴリズムは、コンポーネントが形成されると、そのコンポーネント内の将来のすべてのペアが自動的に満たされるため、以前の決定を再考することなくスパニング構造を正しく構築します。
