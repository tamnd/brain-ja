 ## 解決策
 ## 問題の理解

 私たちには指示された構造が与えられています$n$各ノードには出力エッジが 1 つだけあります。 具体的には飛行機$i$平面を指す$f_i$、つまり、別の 1 つのプレーンが「好き」であることを意味します。 自己ループは明示的に禁止されているため、ノード自体がポイントされることはありません。 

タスクは、長さがちょうど 3 の有向サイクルが存在するかどうかを判断することです。 言い換えれば、3 つの異なる平面を探しています。$A, B, C$そのような$A \to B$、$B \to C$、 そして$C \to A$。 

すべてのノードが出次数 1 を持つため、この構造は関数グラフです。これは、すべての接続コンポーネントが、それにフィードする有向ツリーを含むサイクルで構成されていることを直ちに意味します。 ただし、ここでは長さ 3 のサイクルのみが問題になります。 

制約$n \le 5000$十分に小さいので、$O(n^2)$または単純な$O(n)$ノードごとに定期的にチェックを行うスキャンで十分です。 立方体的なものやノードごとの反復的なトラバースを伴うものはすべて通過しますが、不要です。 

微妙なエッジケースは、トラバース方向の誤解から発生します。 各ノードは正確に 1 つのノードを指しますが、複数のノードが同じターゲットを指す可能性があるため、無向の観点で考えたり、対称性を仮定したりすると、正確さが損なわれます。 

もう 1 つのエッジ ケースは、どのサイクルでも条件を満たすと仮定することです。 たとえば、次のような長さ 2 のサイクル$1 \to 2 \to 1$は無効です。 長さ 3 サイクルのみがカウントされます。 

トラップの具体例:

 入力:```
3
2 1 2
```これにより形成される$1 \to 2 \to 1$、 そして$3 \to 2$。 サイクルがありますが、長さは 2 であるため、正しい出力は次のようになります。```
NO
```「サイクルが存在する」で停止する単純なサイクル検出アプローチでは、誤って「YES」と答えてしまいます。 

## アプローチ

 強引なアイデアは、注文されたすべてのトリプルを試すことです$(i, j, k)$かどうかを確認してください$i \to j$、$j \to k$、 そして$k \to i$。 これは、配列を直接検索することで簡単に実装できます。$f$。 ただし、これには次のことが必要です$O(n^3)$チェックがあるので、$n^3$可能なトリプルであり、各チェックは定数時間です。 と$n = 5000$、これは次の順序です。$1.25 \times 10^{11}$制限時間をはるかに超えているチェック。 

グラフの構造を観察することで、無駄な検索を省くことができます。 各ノードには出力エッジが 1 つだけあるため、任意のノードから開始されます。$i$、従うべきチェーンは 1 つだけです。$i \to f_i \to f_{f_i} \to \dots$。 3 サイクルが存在する場合、それはこの決定論的なチェーン構造に現れる必要があります。 

これは、ノードごとに直接チェックすることを示唆しています。 各ノードについて$i$、次のように定義できます。 

-$a = f_i$-$b = f_a$-$c = f_b$次に、次のことを確認するだけで済みます。$c = i$。 もしそうであれば、以下を含む 3 サイクルが見つかりました。$i$、$a$、 そして$b$。 すべてのノードには出力エッジが 1 つだけあるため、潜在的な 3 サイクルはすべて、そのノードの 1 つから開始することで検出されます。 

これにより問題は次のように縮小されます$O(n)$小切手。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのトリプル) |$O(n^3)$|$O(1)$| 遅すぎる |
 | ノードごとの直接 3 ステップ チェック |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る$f$、必要に応じて 0 から始まるインデックスを調整します。 これにより、一定時間内に後継者にアクセスできるようになります。 
2. 各ノードについて$i$、最初、2 番目、および 3 番目のジャンプを計算します。$a = f[i]$、$b = f[a]$、 そして$c = f[b]$。 This simulates following directed edges exactly three times.
 3. かどうかを確認します。$c == i$。 これが当てはまる場合、 で始まり で終わる長さ 3 の有向サイクルが閉じたことになります。$i$。 
4. 該当する場合$i$条件を満たした場合は直ちにYESを出力します。 有効な三角形が 1 つ存在するだけで十分であるため、この早期終了は有効です。 
5. どのノードも有効な 3 ステップリターンを生成しない場合は、NO を出力します。 

### なぜ効果があるのか

 各ノードには出力エッジが 1 つだけあるため、長さ 3 の各サイクルはその開始ノードによって一意に表現される必要があります。 サイクルなら$A \to B \to C \to A$存在し、から開始します$A$決定的に生成します$f_A = B$、$f_B = C$、 そして$f_C = A$、チェックが成功します。 すべての遷移は決定的であるため、サイクルが見逃されることはなく、条件が 3 ステップ後に明示的にクロージャを強制するため、誤検知が発生することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
f = list(map(int, input().split()))

# convert to 0-based indexing
for i in range(n):
    f[i] -= 1

for i in range(n):
    a = f[i]
    b = f[a]
    c = f[b]
    if c == i:
        print("YES")
        sys.exit()

print("NO")
```重要な実装の詳細は、0 ベースのインデックスへの即時変換です。 これにより、トラバーサル中に -1 調整が繰り返されることがなくなり、配列へのアクセスがクリーンに保たれます。 

もう一つ重要な点は早めの退場です。 有効な三角形が見つかると、問題は列挙ではなく存在のみを要求するため、すぐに終了します。 

トリプル ジャンプ ロジックは数学的条件を直接反映します。$f(f(f(i))) = i$、これは関数グラフにおける 3 サイクルの定義特性です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    f = list(map(int, input().split()))
    for i in range(n):
        f[i] -= 1

    for i in range(n):
        a = f[i]
        b = f[a]
        c = f[b]
        if c == i:
            return "YES"
    return "NO"

# provided sample
assert run("5\n2 4 5 1 3\n") == "YES"

# no cycle of length 3
assert run("3\n2 1 2\n") == "NO"

# minimal n
assert run("2\n2 1\n") == "NO"

# simple 3-cycle
assert run("3\n2 3 1\n") == "YES"

# larger with embedded triangle
assert run("4\n2 3 1 2\n") == "YES"
```| テスト入力 | 期待される出力 | 検証内容 |

| 2 2 1 | いいえ | 最小サイズ、三角形は不可 |

 ## 特殊なケース

 重要なエッジ ケースは、グラフにサイクルが含まれているものの、長さ 3 のサイクルが含まれていない場合です。たとえば、次のような純粋な 2 サイクルです。```
3
2 1 2
```各ノードから開始して、アルゴリズムは正確に 3 つの遷移を計算します。 ノード 1 の場合:$1 \to 2 \to 1 \to 2$、これは 1 に戻らないため、正しく拒否されます。 すべてのノードで同じことが起こるため、出力は NO になります。 

もう 1 つのエッジ ケースは、複数のノードが有効な 3 サイクルにフィードする場合です。 このアルゴリズムは、到達可能性や接続性に依存せず、直接的な機能構成のみに依存するため、引き続き機能します。 サイクル内のどのノードでも、トリプル ジャンプはサイクル内にとどまって正しく戻り、サイクルが分離されていない場合でも確実に検出されます。
