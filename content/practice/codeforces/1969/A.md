 ## 解決策
 ## 問題の理解

 各友人には、「親友」としてちょうど 1 人の友人が割り当てられ、この割り当てはサイズの順列を形成します。$n$。 重要なルールは、友人とその割り当てられた親友の両方が招待された場合にのみ、友人がパーティーに参加するということです。 

これにより、すべての頂点に 1 つの出力エッジがあり、すべてのノードにも 1 つの入力エッジがある依存関係グラフが作成されます。 したがって、この構造は有向サイクルの素結合です。 各サイクルは相互依存関係の閉じたグループを表します。 

友人のサブセットに招待状を送信することができます。 招待された人の中で実際に現れるのは一部の友人だけです$i$両方の場合にのみ最終出席に表示されます。$i$そして$p_i$招待セットに入っています。 目標は、送信される招待状の数を最小限に抑えながら、少なくとも 2 人の友人が参加することを保証することです。 

制約は小さく、$n \le 50$したがって、テスト ケースごとに 3 次または指数推論でも許容されます。 ただし、テスト ケースの数は最大 5000 と大きくなる可能性があるため、テスト ケースごとの解は線形またはほぼ線形である必要があります。 

素朴だが重要な失敗例は、友人 2 人を招待すれば常に十分だと思い込んでいることから生じます。 次のような 4 サイクルを考えてみましょう$1 \to 2 \to 3 \to 4 \to 1$。 相互の親友ではない 2 つのノード (たとえば 1 と 2) だけを招待すると、1 には 2 が必要で、2 には 3 が必要であるため、誰も参加しません。したがって、実際の出席者は空になります。 これは、「2 人を招待する」ことが「2 人の出席者を獲得する」ことと同等ではないことを示しています。 

もう 1 つの微妙なケースは、2 サイクルがある場合です。 例えば$1 \leftrightarrow 2$。 1 と 2 だけを招待するだけで十分で、両方とも参加します。 これは、小さなサイクルは長いサイクルとは異なる動作をし、サイクル構造が問題の核心であることを示唆しています。 

## アプローチ

 この強引なアイデアは、招待された友人のすべてのサブセットを試し、誰が参加するかをシミュレートし、少なくとも 2 人の出席者が得られる最小のサブセットを選択することです。 サブセットごとに、すべての友人をチェックして、その友人とその親友の両方が存在するかどうかを確認します。 これは$O(2^n \cdot n)$、これはすでに実行不可能です$n = 50$、 以来$2^{50}$天文学的に大きいです。 

重要な観察は、出席率が順列のサイクルによって完全に決定されるということです。 各ノードは正確に 1 つの他のノードを指しており、すべてのノードは個別であるため、グラフはサイクルに分解されます。 サイクル内では、出席はそのサイクルに沿った隣接関係によって制限されます。 

長さ 2 のサイクルの場合、両方のノードを招待すると、すぐに 2 人の参加者が得られます。 2 を超える長さのサイクルでは、単一の招待されたノードは出席を伝播しません。これは、その近隣ノードも招待する必要があり、その近隣ノードが別のノードに依存するため、サイクル全体が考慮されない限り閉じることができないチェーンが作成されるためです。 

重要な単純化は、答えが最小のサイクル サイズにのみ依存することですが、特別な区別があります。2 サイクルでは答え 2 が得られますが、少なくとも 3 の長さのサイクルでは、サイクル内の任意の 3 つの連続するノードを招待することで 2 人の参加者を得ることができます。 これにより、2 つの隣接する依存関係が同時に満たされるチェーンが保証されます。 

したがって、問題は、すべてのサイクル長を見つけて、少なくとも 2 人の出席者を生成するための最小限の方法を採用することになります。参加者は 2 (2 サイクルが存在する場合) か、そうでない場合は 3 になります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、順列サイクルを抽出します。 

1. サイズの訪問済み配列を構築する$n$、最初はすべて false です。 これにより、すでにサイクルに割り当てられているノードを再訪する必要がなくなります。 
2. すべてのノードを反復処理する$i$。 まだ訪れていない場合は、チェーンをたどってください。$i \to p_i \to p_{p_i} \to \dots$訪問したノードに戻るまで。 遭遇するすべてのノードは 1 つのサイクルを形成します。 訪問者をマークします。 
3. 各サイクルの長さを記録します。 順列構造により分岐がないことが保証され、すべてのノードが正確に 1 つのサイクルに属するため、これで十分です。 
4. サイクルの長さが正確に 2 の場合は、すぐに 2 を返します。これは、2 サイクルでは、ノードごとに 1 つずつ、正確に 2 つの招待で相互依存関係を満たすことができるためです。 
5. 2 サイクルが存在しない場合は、3 を返します。これより長いサイクルでは常に、少なくとも 2 人の出席者を生成する 3 つの招待を含む有効な構成を構築できます。 

正しさは、親友関係が長さ 2 のサイクル内でのみ対称であるという事実にかかっています。サイクルが長くなると、依存関係のチェーンを切断する必要があり、出席を生成する最小の安定した構成には、連続する 3 つのノードが必要です。 

### なぜ効果があるのか

 順列は独立したサイクルに分解され、出席制約はエッジに対してローカルになります。 2 サイクルは、3 番目のノードを介さずに 2 つのノードが相互に満足できる唯一の構造です。 長さが 3 以上の各サイクルでは、少なくとも 1 つの中間依存関係が強制されるため、サイクル自体のサイズが正確に 2 でない限り、2 人の参加者を保証するには 2 つの招待状では不十分です。すべての 2 サイクルが除外されると、2 つの隣接する依存関係をアクティブにする最小限の構築には 3 つのノードが必要になりますが、これは長いサイクル内で常に達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = [0] + list(map(int, input().split()))
        
        vis = [False] * (n + 1)
        has_two_cycle = False

        for i in range(1, n + 1):
            if not vis[i]:
                cur = i
                cycle = []
                while not vis[cur]:
                    vis[cur] = True
                    cycle.append(cur)
                    cur = p[cur]

                if len(cycle) == 2:
                    has_two_cycle = True

        if has_two_cycle:
            print(2)
        else:
            print(3)

if __name__ == "__main__":
    solve()
```コードは順列のサイクル分解を直接実装します。 配列は問題の定義に一致するように 1 からインデックス付けされており、次の場合に 1 つ違いの間違いを避けることができます。$p_i$。 各サイクルは、以前に訪問したノードに遭遇するまで歩くことによって収集され、その長さは 2 サイクルが存在するかどうかを検出するためにのみ使用されます。 答えは、長さ 2 のサイクルが現れるかどうかによってのみ異なります。 

微妙な点は、招待や出席を明示的にシミュレートする必要がないことです。 サイクル構造によって実現可能性が完全に決まるため、サイクル長のみを追跡するだけで十分です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())
        p = [0] + list(map(int, input().split()))
        
        vis = [False] * (n + 1)
        has_two_cycle = False

        for i in range(1, n + 1):
            if not vis[i]:
                cur = i
                cycle = []
                while not vis[cur]:
                    vis[cur] = True
                    cycle.append(cur)
                    cur = p[cur]
                if len(cycle) == 2:
                    has_two_cycle = True

        print(2 if has_two_cycle else 3)

    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

 ## 特殊なケース

 重要なエッジ ケースは、順列全体が 2 より長いサイクルで構成されている場合です。たとえば、$1 \to 2 \to 3 \to 4 \to 1$。 このアルゴリズムは、長さ 4 の単一サイクルを正しく識別し、2 サイクル フラグを設定せず、出力 3 を生成します。相互依存関係を満たすペアがないため、招待を 2 つに減らそうとする試みは失敗します。 

もう 1 つのケースは、複数のサイクルが存在し、そのうちの 1 つだけが 2 サイクルである場合です。$1 \leftrightarrow 2$そして$3 \to 4 \to 5 \to 3$。 アルゴリズムは最初のコンポーネントで 2 サイクルを検出し、すぐに答えが 2 であると結論付けます。サイクルは独立しており、少なくとも 2 人の出席者の要件を満たすには 1 つの有効なペアで十分であるため、これは正しいです。 

最後の微妙なケースは次のような場合です。$n = 2$。 可能な順列は 2 サイクルのみであるため、答えは常に 2 になります。サイクル検出ロジックは長さ 2 のサイクルを直接マークするため、アルゴリズムは特別なケースなしでこれを自然に処理します。
