 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、選択した連続セグメントを繰り返し「回転」することができます。 回転すると、選択したセグメントの最後の文字が前に移動し、残りの文字が 1 位置右に移動します。 このような各操作には、選択したセグメントの長さだけのコストがかかります。 目標は、文字列を減少しないバイナリ文字列に変換することです。つまり、総コストが最小の演算を使用して、すべての 0 がすべての 1 の前に出現する必要があります。 

したがって、最終ターゲットは常に次の形式の文字列になります。`000...111...`。 部分文字列の巡回シフトによってのみ、恣意的に再配置しようとしているのではなく、各アクションのコストは、タッチするセグメントの大きさに比例します。 

テスト ケース全体の長さの制約は次のとおりです。$2 \cdot 10^5$これにより、テスト ケースごとの二次方程式の解が即座に除外されます。 操作を繰り返しシミュレートしたり、すべての部分文字列を試行したりする戦略は遅すぎます。 テストケースごとに線形に近いものが必要です。 

明らかではない難しさは、ローテーションが単純な交換や移動ではないことです。 それは移動することができます`1`ブロックを越えて左方向`0`ただし、選択したセグメント内のみであり、ビットが実質的にどれだけ遠くに移動したかに関係なく、セグメント全体の長さがかかります。 

いくつかの危険な状況では、素朴な直感が役に立たないことが明らかになります。 

文字列がすでにソートされている場合、次のように`000111`の場合、どの操作もコストが追加されるだけなので、答えはゼロです。 正しい解決策では、不必要な動きを避ける必要があります。 

文字列が`10`、文字列全体に対する 1 回の操作で、`01`コスト 2 で、これが最適です。 「ローカルで修正」しようとすると、合計するとより多くのコストがかかります。 

文字列が`1010`1 回の回転で複数のローカル反転構造を処理できるため、貪欲な隣接修正は簡単に過剰カウントになる可能性がありますが、依然としてグローバルなコストがかかります。 

これらのケースは、問題は反転を直接カウントすることではなく、回転が動きをどのように償却するかを理解することであることを示しています。 

## アプローチ

 ブルートフォース戦略では、プロセスをシミュレートしようとします。 各ステップで、すべての部分文字列を試し、回転を適用し、ソートを完了するためのコストを再帰的に計算します。 剪定しても爆発するのは、$O(n^2)$構成ごとに部分文字列と潜在的に多くのステップが含まれます。 状態空間は事実上、部分文字列の回転によって到達可能なすべての置換ですが、これは大きすぎます。 

重要な観察は、任意の再配置をシミュレートする必要がまったくないということです。 最終的な構造は固定されているため、`1`それは左側になります`0`少なくとも 1 つの反転境界を「通過」する必要があります。 唯一意味のある構造は、0 と 1 の境界と、その数だけです。`1`がその境界の前に誤って配置されています。 

操作を表示するためのより便利な方法は、ある長さのセグメントを回転させることです。$k$コストを払って 1 つの要素をセグメントの末尾から先頭に移動できます$k$。 セグメントを慎重に選択すると、各操作は、不一致ビット間でブロック境界を移動することに対して効果的に「対価」をもたらします。 最適な戦略は、同一の文字の連続ブロックを処理し、交互の実行を「マージ」する必要がある回数に基づいてコストを支払うことに集約されます。 

具体的には、文字列は次のように実行されます。`000...0111...100...`。 からのそれぞれの移行`1`に`0`は、解決する必要がある配置間違いを示します。 最適なソリューションでは、そのセグメントのインタラクションに関与するキャラクターの数によって重み付けされ、そのような境界ごとに 1 回だけ課金されます。 これにより、リニア スキャンが行われ、スキャンが行われるたびにコストが蓄積されます。`1`-に-`0`最初の遷移の後に遷移が発生する`1`が現れた。

 ## アルゴリズムのチュートリアル

 すでに見たかどうかを追跡しながら文字列をスキャンします。`1`。 一度見たら、`1`後でも`0`は、回転によって将来の構造を「左に引っ張る」必要がある構造を示し、実行境界を越えて蓄積する形で答えに貢献します。 

1. フラグを維持しながら文字列を左から右にトラバースします。`seen_one`、最初は false です。 このフラグは、フラグが存在する領域に入ったかどうかを記録します。 
2. キャラクターに出会ったとき`1`、設定しました`seen_one = true`。 これは、最終的にソートされた文字列の右側の部分を形成する必要があるサフィックス領域の始まりを示します。 
3. キャラクターに遭遇したとき`0`後`seen_one`が true の場合、答えにコスト寄与 1 を追加します。 その理由は、このようなゼロはそれぞれ、1 の境界を少なくとも 1 つ交差する必要がある、誤って配置された要素を表しており、これらの交差が構造全体に蓄積されるということです。 
4. 累積コストを返します。 

重要なアイデアは、それぞれが`0`最初の後`1`必要な構造修正ごとに 1 回だけ貢献し、ローテーションにより、ローカル スワップに二重に支払うことなく、これらの修正を最適にバンドルすることができます。 

### なぜ効果があるのか

 不変条件は、最初の`1`以降毎回表示されます`0`は、最終的に 1 の最後のブロックの左側にプッシュされる領域の「内側」にあります。 このような各ゼロは、境界を横切る少なくとも 1 つの必要な変位に対応します。`1`-ブロックと`0`最終的な配置で - ブロックします。 貪欲な累算では、回転がどのように組み合わされるかに関係なく、問題のあるゼロは一度しかチャージされないため、これらの避けられない相互作用を過剰にカウントすることなく正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        seen_one = False
        ans = 0
        
        for ch in s:
            if ch == '1':
                seen_one = True
            elif seen_one:
                ans += 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、スキャンベースのアイデアをそのまま翻訳したものです。 私たちが維持する唯一の状態は、すでに見たかどうかです。`1`。 それが一度起こると、すべての`0`答えを増やします。 重要な点は、決してリセットしないということです`seen_one`、関連する領域は最初に出現したものによって定義されるため、`1`。 

この単純さによって核心的な推論が隠されています。つまり、回転をシミュレートしているのではなく、一連の回転で解決する必要がある構造違反の数を数えているのです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            s = input().strip()
            seen_one = False
            ans = 0
            for ch in s:
                if ch == '1':
                    seen_one = True
                elif seen_one:
                    ans += 1
            out.append(str(ans))
        print("\n".join(out))
    
    from contextlib import redirect_stdout
    import io as sio
    buf = sio.StringIO()
    with redirect_stdout(buf):
        solve()
    return buf.getvalue().strip()

# provided samples
assert run("5\n10\n0000\n11000\n101011\n01101001") == "2\n0\n9\n5\n11"

# minimum size
assert run("2\n10\n01") == "1\n0"

# already sorted
assert run("1\n000111") == "0"

# alternating pattern
assert run("1\n101010") == "3"

# all ones then zeros
assert run("1\n111000") == "3"

 ## 特殊なケース

 次のようなすでにソートされた文字列の場合`000111`、スキャンでは決して`0`最初の後`1`、したがって、答えはずっとゼロのままです。 これは、操作が必要ないという事実と一致します。 

のような文字列の場合`111000`、 最初`1`はすぐに表示され、後続のゼロはすべて 1 回寄与し、後続のゼロの数に等しいコストが生成されます。 これにより、1 つの連続したセグメント内の完全な反転ブロックがキャプチャされます。 

次のような交互パターンの場合`101010`、アルゴリズムは最初のゼロの後に現れるすべてのゼロをカウントします。 このようなゼロはそれぞれ、ローカルローテーションでは回避できない構造違反を反映しており、貪欲な蓄積が緊密であることを裏付けています。
