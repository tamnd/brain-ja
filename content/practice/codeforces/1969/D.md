 ## 解決策
 ## 問題の理解

 アイテムのコレクションが与えられ、各アイテムには 2 つの値があります。 最初の値は、アリスがアイテムを取得するためにいくら支払わなければならないかを表し、2 番目の値は、そのアイテムが無料で手に入らなかった場合にボブがアリスに支払う金額を表します。 

アリスはまず、購入したいアイテムのサブセットを選択します。 彼女は、選択したアイテムの最初の価値の合計を支払います。 その後、ボブは彼女の選択に反応します。 彼女が選んだアイテムが k 未満の場合、ボブは単にすべてを無料で受け取ります。つまり、アリスは何も返されません。 彼女が少なくとも k 個のアイテムを選択した場合、ボブはそれらのアイテムのうち正確に k 個を選択し、それらを無料で受け取ることができます。 残りの選択されたアイテムについて、ボブはアリスに 2 番目の価値を支払います。 

アリスの最終的な利益は、ボブから受け取ったお金から店に支払った金額を差し引いたものです。 ボブの目標はこの利益を最小限に抑えることであり、アリスはそれを最大化しようとします。 最適なプレーの下での均衡結果を計算する必要があります。 

制約は大きく、テスト ケース全体の合計 n は最大 2×10^5 です。 これにより、サブセットに対する二次または三次の列挙が除外されます。 テスト ケースごとに O(n^2) であっても、遅すぎます。 解は、テスト ケースごとに線形または n log n に近い必要があります。 

素朴な間違いは、ボブの戦略的選択を無視することから生じます。 たとえば、アリスの選択とは無関係に、ボブが常に最も安い k 個のアイテムを選択する、または常に最も高価な k 個のアイテムを選択すると仮定すると、誤った推論につながります。 ボブの選択はアリスがコミットするサブセットに依存するため、選択したサブセットの構造が重要になります。 

k が大きい場合には、別の微妙な失敗ケースが発生します。 アリスが正確に k 個のアイテムを選択した場合、ボブはそれらすべてを無料で受け取ることができ、アイテムが個々にどれほど優れているかに関係なく、利益はゼロになります。 このしきい値の動作を無視する貪欲なソリューションは、そのような入力ですぐに機能しません。 

## アプローチ

 強引な戦略は、アリスが選択できる項目のすべてのサブセットを試し、各サブセットに対するボブの最適な応答をシミュレートすることです。 固定サブセットの場合、ボブは無料で削除するメリットが最も大きい k 個の項目を選択し、アリスの利益を直接計算できます。 これは概念的には機能しますが、2^n 個のサブセットを調べる必要があり、1 つのサブセットを評価するだけでも並べ替えや選択が必要となるため、小さな n を超えると完全に実行不可能になります。 

重要な観察は、ボブの効果は選択されたセットにのみ依存し、その外側のアイテムのアイデンティティには依存しないということです。 アリスが集合 S を選択した場合、ボブは利益貢献の観点からアリスに最も損害を与える S 内の k 項目を削除します。 各項目について、ボブが行動する前のその貢献度は (b_i - a_i) ですが、ボブの除去は k 個の貢献度を選択的に排除することができ、事実上アリスに弱い項目や危険な項目を選択することに対して「支払い」を強制することができます。 

これにより、問題は、アリスが選択したセット内でのみ、(b_i - a_i) 効果の点で最悪の k 項目をボブが削除すると仮定できるサブセットの選択に変わります。 サブセットについて推論する代わりに、決定を次のように再解釈できます。アリスは、k 個の最悪のペナルティを削除した後、残りの調整された合計が最大になるように項目を選択したいと考えています。 

標準的な変換が現れます。つまり、各項目の値を定義します。しかし、難しいのは、Bob の削除により、選択したセット内の項目が結合されることです。 解決策は、変換されたキーでアイテムを並べ替え、可能な限り最適なサブセット サイズを維持し、「自由な破棄予算」として扱うことで k 個の強制削除を考慮する貪欲な選択を使用することです。 

正しい構造は、項目を (b_i - a_i) でソートし、その項目がボブの削除後に生き残った場合にアリスが効果的にその値を取得すると考えることになります。 私たちは、Bob の削除が常に最も利益の少ない選択された項目をターゲットにする方法で候補を維持します。これは、ヒープを使用するか、項目をソート順に処理して最良の利益のプレフィックスを維持することによってシミュレートできます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各項目について、最終的に支払われた場合の純利益 (b_i - a_i) を計算します。 これにより、ボブが削除しなかった場合のアリスの利益が得られます。 
2. 保持することが最も収益性の高いアイテムを優先するため、アイテムをこの値で降順に並べ替えます。 
3. 項目を反復処理し、アリスが現在選択しているセットと、ボブがこの時点で停止した場合に削除される最悪の k 個の要素を表す構造を維持します。 
4. 選択したアイテムのゲインの実行中のマルチセット (またはヒープ) と、選択したすべてのゲインの実行中の合計を維持します。 
5. 新しい項目を追加するたびにセットを更新し、Bob が最大 k 個の最悪の要素を削除したことを考慮した後、最良の寄与のみが残るようにします。 実際には、これは合計を追跡し、現在のプレフィックスの k 個の最小ゲインを減算することを意味します。 
6. 答えは、すべてのプレフィックスにわたる (選択されたゲインの合計から k 個の最小ゲインの合計を引いたもの) の最大値です。 

これが機能する理由は、サブセット サイズが固定されている場合、Bob の最適な戦略は常に、そのサブセット内の最小 (b_i - a_i) を持つ k 項目を削除することであるためです。 したがって、アリスの問題は、k 個の最小要素を削除した後に合計ゲインを最大化するサブセットを選択することになり、最適なサブセットは常にゲインによってソートされた順序のプレフィックスに対応します。 

なぜそれが機能するかは、交換の引数に関係しています。選択したサブセットに、より高いゲインの項目を除外しながら、より低いゲインの項目が含まれている場合、それらを交換しても、アリスにとってボブの削除が悪化することはなく、合計の利益が改善または維持されるだけです。 これにより、最適なソリューションが並べ替えられた項目のプレフィックスとして表現できるようになり、そのプレフィックス内でボブのアクションが完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        items = [(b[i] - a[i], a[i], b[i]) for i in range(n)]
        items.sort(reverse=True)

        import heapq

        total_gain = 0
        heap = []  # store chosen gains (as min-heap of selected items)
        sum_heap = 0

        best = 0

        for gain, ai, bi in items:
            total_gain += gain
            heapq.heappush(heap, gain)
            sum_heap += gain

            if len(heap) > k:
                sum_heap -= heapq.heappop(heap)

            # current value: total gain minus k smallest (in heap structure)
            # heap currently holds at most k smallest of selected prefix
            if len(heap) == k:
                best = max(best, sum_heap)

        print(best)

if __name__ == "__main__":
    solve()
```コードはまず各アイテムをその有効な寄与 (b_i - a_i) に変換します。 並べ替えることにより、収益性の高い項目から最も低い項目まで確実に考慮されます。 ヒープは、現在考慮されているプレフィックスの中で、ボブの最適なフリーピックに対応する k 個の最小要素を維持するために使用されます。 

微妙な点は、アリスが k 個以上のアイテムを選択した場合にのみボブが削除を開始できるため、少なくとも k 個のアイテムが考慮されている状態のみを評価することです。 ヒープ合計は、Bob がそのプレフィックス内の最悪の項目を正確に k 個削除した後の純利益を直接表します。 

## 実用的な例

 メカニズムを説明するために、単純化した例をトレースします。 

次の項目を検討してください。 

( a, b ) = (1,3)、(2,2)、(1,4)、k = 1

 ゲインを計算します。 

(2)、(0)、(3)

 ゲイン順に並べ替えます:

 (3)、(2)、(0)

 | ステップ | アイテム | 合計ゲイン | ヒープ | ヒープの合計 | ベスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | [3] | 3 | - |
 | 2 | 2 | 5 | [2,3] | 5 | 5 |
 | 3 | 0 | 5 | [0,2,3] → ポップ 0 | 5 | 5 |

 各ステップの後、ボブは k=1 が適用されると最小の利益を削除し、調整後に達成可能な最大利益 5 を残します。 

ここで、k = 2 で同じ項目がある場合を考えてみましょう。 

| ステップ | アイテム | k=2 を強制した後のヒープ | 合計ヒープ | ベスト |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | [3] | 3 | - |
 | 2 | 2 | [2,3] | 5 | 5 |
 | 3 | 0 | [0,2,3] → 0 を削除 | 5 | 5 |

 これは、ボブが常に最も弱い寄与を削除し、アリスの最善の戦略は、最悪 k 個だけが破棄されるため、すべての項目を含めることであることを示しています。 

これらのトレースは、ローリング プレフィックスを維持し、k 個の最小要素をトリミングすることで、ボブの最適な応答を正しくシミュレートしていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n log n) | ソートが優先され、ヒープ操作は項目ごとに対数的になります。 
| スペース | O(n) | アイテムとヒープの保存 |

 ## 特殊なケース

 k = 0 の場合、ボブは無料アイテムを決して取得しないため、アリスは単純に正の (b_i - a_i) を持つすべてのアイテムを選択する必要があります。 ヒープでは何も削除されず、すべてのゲインが蓄積されるため、アルゴリズムはこれを自然に処理します。 

k = n の場合、アリスが少なくとも n 個の商品を購入すると、ボブはいつでもすべてを無料で受け取ることができるため、最適解はゼロになります。 ヒープは最終的にすべてをトリミングし、利益を保持しません。 

すべての (b_i - a_i) 値が負の場合、最適な戦略は何も選択しないことです。 ソートされたプロセスでは、正のプレフィックス合計が形成されないことが保証されるため、損失が累積するのではなく、答えはゼロのままになります。
