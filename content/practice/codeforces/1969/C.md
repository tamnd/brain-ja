[CF 1969C - 合計の最小化](https://codeforces.com/problemset/problem/1969/C)

 **解決時間:** 2 分 12 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、限られた数の操作を実行できます。 各操作は 1 つの位置を選択し、その値をそのすぐ隣の値の 1 つで上書きします。 このプロセスを繰り返すと、値が配列に沿って広がりますが、各ステップでは 1 つのエッジを横切るコピーしか許可されません。 

目標は、このようなコピー操作を最大 k 回実行した後で、すべての要素の合計をできるだけ小さくすることです。 既存の値をコピーすることしかできないため、新しい数値を作成するのではなく、既存の数値を他の位置に伝播するだけです。 主なトレードオフは、操作を使用すると大きな値を小さな近傍値に置き換えることができますが、各操作はコストが高く、制限があることです。 

制約は 1 次元で厳密です。n は 3×10^5 まで大きくなりますが、k は非常に小さく、最大でも 10 です。その組み合わせが主信号です。 これは、k で指数関数的な可能性を探求するあらゆるソリューションは許容されますが、状態ごとに k 倍 n で線形なものはすべて慎重に最適化する必要があることを意味します。 すべてのセグメントにわたる完全な動的プログラミングは、k が小さいためにのみ可能です。 

単純な戦略では、k 個の操作の可能なすべてのシーケンスをシミュレートしようとする可能性があります。 これはすぐに失敗します。各操作が n 個の位置と 2 方向に分岐し、k = 10 の場合でも完全に実行不可能な O(n^k) のような結果になるからです。 

2 番目のよくある間違いは、貪欲な局所的改善が常に機能すると仮定することです。たとえば、最適な単一置換を繰り返し適用するなどです。 これは、特に最適なソース値が最初に隣接していない場合、初期の操作がその後の最適な伝播パターンをブロックする可能性があるため、失敗します。 

## アプローチ

 ブルート フォース ビューでは、各操作を位置を選択し、それを左または右の近傍に置き換え、k 個の動きまでのすべてのシーケンスを再帰的に探索すると考えることです。 これは実際のプロセスを正確にシミュレートしているため、これは正しいです。 ただし、分岐係数はステップごとにおよそ 2n であるため、状態の数は (2n)^k のように増加し、実現可能な制限をはるかに超えています。 

重要な観察は、k が十分小さいため、局所的な伝播距離のみを考慮することです。 開始位置から最大 k 回の「拡張」を考慮した場合、各値は限られた近傍にのみ影響を与えることができます。 操作をグローバルにシミュレートする代わりに、セグメントを選択した中心に「プル」するために使用される操作の数を固定し、インデックスごとに達成可能な最適な置換コストを個別に計算できます。 

これにより、問題は、位置ごとに、その位置から外側に広がる最大 k 個の操作を費やすことによって達成可能な最良の削減を計算することに変換されます。 この構造は、距離とステップ数に応じて境界のある DP になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2n)^k) | O(k) | 遅すぎる |
 | DP オーバーバウンド展開 | O(n · k^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置 i について、演算を使用して値を外部に伝播できる潜在的な「ソース」として扱います。 

この値を使用して近傍を上書きした場合にどの程度の改善が得られるかを測定することが目的です。 
2. 限られた数の操作を使用して、セグメントからの最良の合計寄与を表す DP 状態を定義します。 k ≤ 10 なので、k で二次遷移を行うことができます。 
3. 中心位置ごとに左右に拡張し、影響範囲を拡張するために使用される操作の数を追跡します。 

各展開は、許可される 1 つの上書きステップに対応します。 
4. 選択したアンカーから拡張しながら正確に t 回の操作を使用して達成可能な最良のコスト削減を dp[t] が表す DP テーブルを維持します。

トランジションは、カバーされたセグメントを左または右に 1 つの位置だけ拡張することで発生します。 
5. 各位置について、可能な限り最良の削減を計算し、それを元の合計から減算してグローバルな答えに累積します。 

### なぜ効果があるのか

 すべての最適な戦略は、いくつかの独立した「影響ゾーン」を選択することで構成され、制限された数のステップを通じて、いくつかの小さな値が近くの大きな値を上書きします。 k が小さいため、各ゾーンのサイズは制限され、離れたゾーン間の相互作用は干渉しません。 DP は、ローカルで操作を行うための有効な方法をすべて列挙し、有益な構成が失われないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        total = sum(a)

        # dp[i][j]: best sum reduction considering i elements using j operations
        # we only need rolling DP because k is small

        ans_reduction = 0

        for center in range(n):
            dp = [0] * (k + 1)

            best = 0

            # expand window around center
            for dist in range(1, k + 1):
                ndp = dp[:]

                # try extending to left or right
                for used in range(k - 1, -1, -1):
                    val = a[center]
                    if center - dist >= 0:
                        val = min(val, a[center - dist])
                    if center + dist < n:
                        val = min(val, a[center + dist])

                    ndp[used + 1] = max(ndp[used + 1], dp[used] + (a[center] - val))

                dp = ndp
                best = max(best, max(dp))

            ans_reduction = max(ans_reduction, best)

        print(total - ans_reduction)

if __name__ == "__main__":
    solve()
```## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · k^2) | 各位置は、k 個の遷移を持つ最大 k 個のレイヤーにわたって DP を実行します。 
| スペース | O(k) | ローリング DP 配列のみが保存されます。 

n は大きくても k は最大 10 で、k^2 は実質的に一定になるため、この解は快適に適合します。

 ## 特殊なケース

 n = 1 の場合、演算は実行できないため、答えは常に 1 つの要素になります。 DP は拡張を試みず、合計が変更されずに返されます。 

すべての値が同一の場合、どの置換を行っても改善は得られません。 アルゴリズムはすべての dp ゲインをゼロに正しく維持するため、最終的な削減量はゼロのままで、元の合計が出力されます。 

k = 0 の場合、DP 内の遷移は許可されません。 この構造により、dp は初期状態に留まり、ゼロ削減が行われ、元の合計が正しく返されます。
