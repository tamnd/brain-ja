 ## 解決策
 ## 問題の理解

 都市と道路の有向グラフがあります。 市`1`首都です。 どの道路もすでに使用可能か、壊れているかのどちらかです。 壊れた道路は修復される可能性があり、その後は通常の有向エッジのように動作します。 

政府はすべての都市が首都からアクセスできるようにしたいと考えています。 壊れた道路の一部を修復することは許可されており、修復の回数を最小限に抑える必要があります。 

グラフに方向性があるため、問題は完全に変わります。 からの道`u`に`v`その方向にのみ役立ちます。 たとえ戻る道があったとしても、それは首都が都市に到達するのに役立ちません。 

入力はフラグとともにすべてのエッジを与えます。 

-`0`道路がすでに機能していることを意味します。 
-`1`道路が壊れており、修復しないと使用できないことを意味します。 

出力は次のいずれかです。 

-`-1`壊れた道路をすべて修復したにもかかわらず、どこかの都市に到達できない場合、または
 - 修復された道路の最小数と 1 つの有効なエッジ インデックスのセット。 

制約は大きく、両方とも`n`そして`m`までです`10^5`。 グラフの走査を繰り返し実行したり、到達可能性を最初から再計算したりするアルゴリズムは失敗します。 たとえば、壊れた道路のすべてのサブセットを試すことは不可能であり、頂点ごとに BFS を 1 回実行するだけでもすでに遅すぎます。 

線形または線形に近いグラフ アルゴリズムが必要です。 周りに何か`O(n + m)`が理想的です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次のグラフを考えてみましょう。```
1 -> 2 (broken)
2 -> 3 (good)
```入力：```
3 2
1 2 1
2 3 0
```最初のエッジだけを修復すれば十分です。 都市ごとに個別に修復を最小限に抑える不注意なソリューションでは、同じ修復されたエッジを誤って複数回カウントする可能性があります。 

もう 1 つの危険なケースは、コンポーネントに到達できない場合です。```
4 2
1 2 0
3 4 1
```都市`3`そして`4`すべての道路が修復されたとしても、首都から切り離されています。 正しい答えは次のとおりです。```
-1
```一部の実装では、現在良好な道路のみを使用して検索し、どこかの 1 つのエッジを修復すると効果があると誤って結論付けます。 

サイクルも重要です。```
3 3
1 2 1
2 3 0
3 2 0
```エッジの修復`1 -> 2`両方のロックを解除します`2`そして`3`。 最適な答えは、2 つのエッジではなく 1 つのエッジを修復します。 

問題の構造はグローバルです。 私たちは独立して都市を接続しているわけではありません。 私たちは首都から直接到達可能な 1 つの地域を構築しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての壊れたエッジをオプションとして扱い、壊れたエッジのすべてのサブセットを試し、すべての頂点が首都から到達可能になるかどうかを確認します。 

あれば`k`壊れたエッジ、これには必要です`2^k`サブセット。 到達可能性チェックのコスト`O(n + m)`毎回。 だけでも`40`エッジが壊れると、これは天文学的に大きくなります。 

もう少し賢いブルートフォースは、すべての都市に対して個別に最短経路を試みます。 コストの割り当て`0`優れたエッジとコストを実現`1`壊れたエッジに。 次に、すべての頂点に到達するために必要な最小修復数を計算します。 

これは個々の都市では機能しますが、実際の最適化目標を解決することはできません。 異なる都市は修復されたエッジを共有できます。 独立した最短経路のコストを合計すると、修理額が超過します。 

重要な点は、各パスを個別に最小化することではなく、すべての頂点が到達可能になるかどうかだけを考慮しているということです。 

重みを割り当てるとします。 

-`0`良いエッジまで、
 -`1`壊れたエッジに。 

ここで、首都をルートとする最短パス ツリーを構築することを想像してください。ここで、ノードの距離は、ノードに到達するために必要な修復されたエッジの最小数を意味します。 

この重み付けされたグラフですべてのノードが到達可能である場合、最短パス ツリーで使用される親エッジを選択すると、修復された道路の全体的に最適なセットが得られます。 

なぜこれが機能するのでしょうか?

 最終的なソリューション内のすべての修復されたエッジは、首都からの経路上のどこかに表示される必要があります。 最短パス ツリーは、修復されたエッジの最小数で各ノードに到達することを保証します。 さらに重要なのは、すべての親エッジの結合によって有向樹枝が形成されることです。 そのツリー内の修復されたエッジは、少なくとも 1 つの新しい頂点に到達するのに貢献します。 無駄な修理はありません。 

エッジの重みは`0`そして`1`、線形時間で 0 ～ 1 BFS を使用して最短パスを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 修復されたサブセットに対するブルート フォース |$O(2^k \cdot (n+m))$|$O(n+m)$| 遅すぎる |
 | 都市ごとの独立した最短パス |$O(n(n+m))$|$O(n+m)$| 間違った考え |
 | 0-1 BFS + 最短パス ツリー |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフを構築します。 

すべてのエッジについて、以下を保存します。 

- 宛先頂点、
 - 修理費用 (`0`または`1`）、
 - オリジナルのエッジインデックス。 
2. 都市から 0-1 BFS を実行する`1`。 

良好なエッジを通過するにはコストがかかります`0`。 

壊れたエッジを通過するにはコストがかかります`1`。 

すべての重みは次のいずれかであるため、`0`または`1`、両端キューを使用できます。 

- コストを前面に押し出す`0`、
 - コストを理由に反対`1`。 

これにより、すべての都市に到達するために必要な修復されたエッジの最小数が計算されます。 
3. エッジを緩和しながら、最適な距離を生成した親エッジを保存します。 

頂点ごとに`v`、 保つ：

-`parent[v]`= 到達するために使用されるエッジ インデックス`v`、
 -`parent_cost[v]`= そのエッジが壊れているかどうか。 
4. 一部の都市が依然として接続できない場合は、印刷します。`-1`。 

これは、壊れたエッジをすべて修復した後でも、有向パスが存在しないことを意味します。 
5. 選択した修復セットを再構築します。 

首都を除くすべての頂点には、最短パス ツリー内に親エッジが 1 つだけあります。 

すべての頂点を横断します。 

- 親エッジが壊れている場合は、そのインデックスを答えに追加します。 
6. 収集されたエッジ インデックスを出力します。 

このようなエッジの数は最小限です。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`dist[v]`到達するために必要な修復エッジの最小数に等しい`v`首都から。 

親ポインタは最短パス ツリーを定義します。 すべての頂点は、この最小修復数を達成するパスを介して首都に接続されています。 

別のソリューションにより、全体的に修復される道路の数が少なくなったとします。 その場合、ツリー内の少なくとも 1 つの頂点には、最短パス距離よりも少ない修復エッジを使用して到達する必要がありますが、これは不可能です。 

選択した修復されたエッジは、まさに最短パス ツリーに表示される破損したエッジです。 それらのいずれかを削除すると、少なくとも 1 つのサブツリーが首都から切断されます。 選択されたすべての修復はツリー構造に必要です。 

ツリーはすべての頂点に到達し、ルートから頂点までのすべてのパスに沿って最小限の数の修復されたエッジを使用するため、修復される道路の総数は全体的に最小限になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for idx in range(1, m + 1):
        a, b, c = map(int, input().split())
        graph[a].append((b, c, idx))

    INF = 10**18

    dist = [INF] * (n + 1)
    parent = [-1] * (n + 1)
    parent_cost = [0] * (n + 1)

    dist[1] = 0

    dq = deque([1])

    while dq:
        u = dq.popleft()

        for v, w, idx in graph[u]:
            nd = dist[u] + w

            if nd < dist[v]:
                dist[v] = nd
                parent[v] = idx
                parent_cost[v] = w

                if w == 0:
                    dq.appendleft(v)
                else:
                    dq.append(v)

    for v in range(1, n + 1):
        if dist[v] == INF:
            print(-1)
            return

    ans = []

    for v in range(2, n + 1):
        if parent_cost[v] == 1:
            ans.append(parent[v])

    if not ans:
        print(0)
    else:
        print(len(ans))
        print(*ans)

solve()
```制約が隣接行列には大きすぎるため、グラフは隣接リストとして保存されます。 

実装の中心部分は 0-1 BFS です。 通常の BFS は重み付けされていないグラフに対してのみ機能しますが、ダイクストラは機能しますが、ここでは不必要にコストがかかります。 すべてのエッジの重みは次のいずれかであるため、`0`または`1`、deque はダイクストラを線形時間でシミュレートします。 

リラックス効果が高まると`dist[v]`、コードも更新されます。 

- 入力に使用されるエッジ`v`、
 - そのエッジの修理が必要かどうか。 

最短パス ツリーは、これらの親ポインタを介して暗黙的に格納されます。 

微妙な点の 1 つは、次の場合にのみ更新するということです。`nd < dist[v]`、 ない`<=`。 頂点がすでに最適な距離を持っている場合、それを別の等距離の親に置き換える必要はありません。 

もう 1 つの重要な詳細は、到​​達不能の検出です。 ノードにまだ距離がある場合`INF`BFS の後は、壊れたエッジをすべて修復しても、方向のあるパスがまったく存在しないため、それを首都に接続することはできません。 

最後に、親エッジをスキャンすることで答えが再構築されます。 壊れた親エッジはすべて修復する必要があります。
