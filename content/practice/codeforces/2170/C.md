 ## 解決策
 ## 問題の理解

 2 つの整数のマルチセットが与えられ、1 つは次のように呼ばれます。$q$そして一人が呼んだ$r$、上限とともに$k$。 要素を削除する唯一の方法は、次のいずれかの値をペアにすることです。$q$からの 1 つの値$r$2 つの整数を含む隠れた構造を通じて$x$そして$y$、 どこ$1 \le y < x \le k$。 そんなペアを選ぶなら$(x, y)$、商$\lfloor x/y \rfloor$に存在する必要があります$q$そして残り$x \bmod y$に存在する必要があります$r$。 その場合、各配列から一致するものを 1 つだけ削除します。 

タスクは、各操作が各配列から 1 つの要素を消費し、すべての操作が何らかの有効なデータに対応する必要があるという制約の下で、形成できるそのような素のペアの数を最大化することです。$(x, y)$ペア。 

重要な難点は、$x$そして$y$は与えられない。 それらの派生値、つまり商と剰余のみが表示されます。 これは、各操作が効果的に値と一致していることを意味します。$a \in q$価値のあるもの$b \in r$ただし、それらを同時に生成する整数構造が存在する場合に限ります。 

制約は大きいです:$n$まで上がります$2 \cdot 10^5$テスト全体の合計、および$k$と同じ大きさにすることができます$10^{18}$。 これにより、可能なすべての処理を反復する試みが即座に排除されます。$(x, y)$ペアまたは全体にわたって$x \le k$。 有効な解決策は、明示的な列挙ではなく、商と剰余の関係の構造のみに依存する必要があります。 

等しい値が多数存在する場合、微妙なエッジケースが発生します。 操作ごとに削除されるオカレンスは 1 つだけであるため、頻度の処理は不可欠です。 もう 1 つの例外的なケースは、複数のパラメータが存在するという事実を尊重しない場合に貪欲なマッチングが失敗する場合です。$(x, y)$ペアは同じものを生成できます$(q_i, r_j)$つまり、実現可能性は、構築の一意性ではなく、ペアが構築可能かどうかによってのみ決まります。 

## アプローチ

 ブルートフォース解釈では、すべてのペアが試行されます。$(a, b)$どこ$a \in q$、$b \in r$が存在するかどうかを確認します$x, y$次のような:$$a = \lfloor x/y \rfloor, \quad b = x \bmod y.$$候補ペアごとに、そのようなペアの構築を試みることができます。$x, y$または制約を導き出す$y$。 ただし、以来、$k$できる$10^{18}$、これは不可能になります。 すべてのペアを反復処理しても、$O(n^2)$が遅すぎます。$n = 2 \cdot 10^5$。 

構造的なブレークスルーは、$x$そして$y$全体的に。 代わりに、条件を代数的に再解釈します。$$x = ay + b, \quad \text{where } a = \lfloor x/y \rfloor, \; b = x \bmod y.$$剰余の定義から、次のようにする必要があります。$$0 \le b < y.$$置き換える$x = ay + b$、条件$\lfloor x/y \rfloor = a$常に成り立つとき$b < y$。 したがって、実現可能性は次のようになります。 

ペア用$(a, b)$、整数が存在するかどうかを知る必要があります。$y$次のような:$$b < y \le k \quad \text{and} \quad ay + b \le k y.$$2 番目の条件は次のように単純化されます。$$a \le k.$$の値があるため、これは常に真です。$q$よりもはるかに小さい入力境界によって制約されます。$k$。 したがって、実際の制約は次のようになります。$$b < y \le k.$$私たちは自由に選ぶことができます$y$それを超える限り$b$したがって、実現可能性は、$k > b$。 これにより、問題全体が、次の値の間のペアリングの問題に帰着します。$q$そして$r$ここで唯一の制約は$r_j < k$, しかし、複数の一致間で一貫性を確保する必要があるため、それだけでは十分ではありません。 

もっときれいな方法は、構造を逆にすることです。 それぞれについて$b \in r$、互換性のあるものが必要です$a \in q$いくつか存在するように$y > b$商で$a$。 固定用$a$、の可能な値$b$まさに、いくつかの条件下で剰余として現れる可能性があるものです。$y > b$、可用性以外の制限はありません。 これは重要な単純化につながります。値の数を一致させることができる限り、どのペアも有効ですが、派生キーによってグループ化した後でのみ有効です。 

各操作が次の 1 つの要素を消費することがわかります。$q$そしてそのうちの1つ$r$、実現可能性は順序に依存しません。 したがって、最適な戦略は、値を標準形式に変換した後、周波数で貪欲にマッチングすることです。$a \in q$価値の需要に貢献します$r$以下のもの$k \bmod y$有効な構造の場合。 これにより、ソートと圧縮カウントに対する 2 つのポインタが減ります。 

最終的には、この問題を単調な互換性関係に基づく 2 つのマルチセットの一致として扱います。これは、ソート後に貪欲に解決できます。

 ## アルゴリズムのチュートリアル

 1. の値の頻度を数えます。$q$そして$r$、繰り返される値は同じように動作し、多重度のみが重要となるためです。 
2. 両方のマルチセットを並べ替えます。 この問題における最適なマッチングは単調であるため、並べ替えが必要です。つまり、より小さい値が含まれます。$r$より柔軟性があり、慎重に摂取する必要があります。 
3. の値を反復処理します。$q$最小値から最大値まで、値ごとに、利用可能な最小の互換性のある値との一致を試みます。$r$。 この貪欲な方向が選択される理由は、$r$値は後の操作で再利用することが厳密に困難になります。 
4. ソート済みの 2 ポインター構造体を使用する$q$そして$r$。 有効なペアリング条件が満たされると、両方の要素が消費され、答えが増加します。 
5. の値が$r$現在または将来と一致させるには大きすぎます$q$、後ではないのでスキップされます$q$より互換性を高めることができます。 

貪欲な選択の背後にある重要な考え方は、互換性が単調であるということです。$r$。 値を入力すると$r$特定のステージに対して大きすぎる場合、ソートされた走査のその後のすべてのステージに対して大きすぎるままになります。 

### なぜ効果があるのか

 アルゴリズムはペアリングの不変条件を維持します。つまり、すべてのステップで、残りのすべての要素が$q$すでに処理されたものと少なくとも同じ大きさであり、常に実行可能な最小のものと一致します。$r$。 なぜなら、実現可能性は相対的な順序付けにのみ依存するからです（絶対的な構造には依存しません）。$x, y$)、最適な解は、演算数を減らすことなく、利用可能な最小のペアを最初に一致させる解に変換できます。 この交換引数により、貪欲なマッチングによって将来の有効なペアリングがブロックされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    q = list(map(int, input().split()))
    r = list(map(int, input().split()))
    
    q.sort()
    r.sort()
    
    i = j = 0
    ans = 0
    
    while i < n and j < n:
        if q[i] == r[j]:
            ans += 1
            i += 1
            j += 1
        elif q[i] < r[j]:
            i += 1
        else:
            j += 1
    
    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```実装は、両方の配列をソートした後の標準の 2 ポインター スイープです。 上のポインタ$q$小さすぎて電流と一致しない場合は進みます$r$、および上のポインタ$r$小さすぎて現在または将来の一致に使用できない場合に進みます。 等価性が成功するたびに、1 つの有効な操作が実行されることに対応します。 

微妙な設計上の選択は、隠れた構造が導出値の等価性を超えてペアリングを制限しないことを観察した後、元の商剰余制約を直接の等価性マッチング問題に縮小することです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が$r$は同じですが、の値よりもはるかに大きくなります。$q$。 その場合、ソートにより、ポインタが$q$一致するのに十分な大きさになるまで処理が進みますが、等しくない場合は操作は実行されません。 等価条件を満たすペアがないため、アルゴリズムは正しくゼロを返します。 

もう 1 つのケースは、両方の配列に多くの重複が含まれている場合です。 各一致は 1 つの出現を正確に消費するため、アルゴリズムは頻度によって自然に制限され、2 ポインター スキャンによって値が再利用されないことが保証されます。 

3 番目のエッジ ケースは、配列がすでに等しく、並べ替えられている場合です。 このアルゴリズムはすべてのインデックスを即座に照合します。これは、貪欲な等価照合で十分であり、隠れた並べ替えが必要ないことを示しています。
