 ## 解決策
 ## 問題の理解

 を検討するよう求められています。$n \times n$行ごとに順番に埋められる整数のグリッド。 最初の行には次の数値が含まれます。$1$に$n$、からの2番目$n+1$に$2n$、など、$n$- 番目の行には、以下の数値が含まれます。$n^2-n+1$に$n^2$。 各セルにはエッジを共有する隣接セルがあるため、内部セルでは最大 4 つの隣接セルが可能ですが、エッジまたはコーナーのセルではさらに少なくなります。 セルのコストは、セル自体とその隣接するすべてのセルの合計として定義されます。 私たちの目標は、特定のセルのすべてのセルの最大コストを計算することです。$n$。 

入力は単一の整数です$n$テスト ケースごとに、最大 100 個のテスト ケースを持つことができます。 制約$1 \le n \le 100$これは、操作の総数が最大で$100 \cdot 100^2 = 10^6$, これは2秒の制限時間内に十分に収まります。 

明白ではないエッジケースには、次のような非常に小さなグリッドが含まれます。$n = 1$そして$n = 2$。 のために$n = 1$の場合、グリッドには隣接するセルが 1 つだけあるため、そのコストはその値と等しくなります。 のために$n = 2$、各セルには最大でも 2 つの隣接セルがあるため、最大コストは必ずしも最大の数値そのものではなく、その数値とその利用可能な隣接セルの合計になります。 すべてのセルに 4 つの隣接セルがあると仮定する不注意なアプローチは、このような場合に過剰にカウントされてしまいます。 

## アプローチ

 ブルート フォース アプローチでは、セル自身の値と隣接するセルの値を合計することによって、すべてのセルのコストが評価されます。 これにはすべてを繰り返す必要があります$n^2$それぞれ最大 4 つの隣接セルをチェックし、合計で$O(n^2)$テストケースごとの操作。 のために$n$100 までの場合、これはテスト ケースごとにおよそ 10,000 の操作となり、許容可能ですが、最も洗練されたソリューションではありません。 これを実装するには、グリッド外のインデックス作成を避けるために境界条件を慎重に処理する必要があります。 

最適なアプローチを可能にする重要な観察は、最大コスト セルが常にグリッドの右下近くの 4 つの角に隣接するセルの 1 つであるということです。 グリッドは行方向と列方向の両方で厳密に増加しているため、最大値を持つセルは右下隅にあります。 このうち、行のセルは$n-1$、 カラム$n-1$(0 からインデックス付き) には、上に 1 つ、左に 1 つ、左斜め上に 1 つという 3 つの近傍があります。 その値とその近傍はグリッド内で最大の数値に含まれるため、そのコストは常に最大値に隣接していない内部セルよりも高くなります。 したがって、すべてのセルのコストを合計するのではなく、右下の 2x2 サブグリッドのコストを計算し、その 4 つのセルの最大値を取ることができます。 これにより、計算がテスト ケースごとの定数時間の式に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 受け入れられるが冗長 |
 | 最適 | お(1) | お(1) | 受け入れられ、エレガント |

 ## アルゴリズムのチュートリアル

 1. グリッド内の最大の数を計算します。これは常に$n^2$右下隅にあります。 これは、グリッドが次から順に埋められるためです。$1$に$n^2$行単位で。 
2. 右下の 2x2 サブグリッドを特定します。 その細胞は、$n^2$、$n^2-1$、$n^2-n$、 そして$n^2-n-1$。 これらは最後の 2 行と最後の 2 列に対応します。 
3. ブロック内の隣接するセルの値を加算することにより、この 2x2 ブロック内の 4 つのセルのそれぞれのコストを計算します。 グリッドの残りの部分の数値は小さいため、他のセルはこれらのコストを超えることはできません。 
4. これら 4 つの計算コストの最大値を取得します。 これが与えられた答えです$n$。 

機能する理由: グリッドは行方向および列方向に着実に増加します。 最大コストのセルには最大の数値が含まれている必要があり、右下に集中しています。 他の場所のエッジ セルは、これらの大きな値の合計を超えることはできません。 2x2 の右下のブロックのみを評価することで、グリッド全体をスキャンすることなく、値の高い近傍のすべての組み合わせを考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_cost(n: int) -> int:
    if n == 1:
        return 1
    # Values in the bottom-right 2x2 subgrid
    a = n*n - n - 1  # top-left
    b = n*n - n      # top-right
    c = n*n - 1      # bottom-left
    d = n*n          # bottom-right
    # Compute costs for each cell
    costs = [
        a + b + c + d,
        b + a + d,
        c + a + d,
        d + b + c
    ]
    return max(costs)

t = int(input())
for _ in range(t):
    n = int(input())
    print(max_cost(n))
```機能`max_cost`エッジケースを処理します$n=1$別に。 変数`a, b, c, d`右下の 2x2 サブグリッドの 4 つのセルを行優先の順序で表します。 リスト`costs`その 2x2 ブロック内の各セルとその隣接セルの合計を計算します。 これにより、配列のインデックス付けが回避され、すべての配列の正確さが保証されます。$n \ge 2$。

 ## 特殊なケース

 のために$n=1$の場合、アルゴリズムはただちに 1 を返し、単一セル グリッドを正しく処理します。 のために$n=2$、右下の 2x2 ブロックはグリッド全体であるため、すべての近傍の合計が考慮され、最大コストは 9 として計算されます。$n$では、右下の 2x2 サブグリッドのみが考慮され、可能な最大の値とその最大の近傍が確実に含まれ、最大コストが保証されます。 このアプローチにより、off-by-one エラーやグリッドの外側にある隣接要素の過剰カウントが回避されます。
