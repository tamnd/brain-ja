 ## アルゴリズムのチュートリアル

 まず配列をソートします$b$常に最大の要件が最初に処理されるように、昇順ではありません。 

1. 並べ替え$b$降順で。 これにより、コアのオーバーラップ構造を決定する弱いカバレッジ要件よりも先に、最も制約されたカバレッジ要件を処理できるようになります。 
2. 変数を維持する$cur$、現在「アクティブ」な間隔の数を表し、次の位置まで拡張する必要があります。 
3. 並べ替えられた値を調べます。 それぞれのステップで$i$、少なくともどれくらいの間隔をカバーする必要があるかを概念的に決定します$i$- 番目の層。 

更新します$cur$そのため、まだカバーが必要な残りの需要の高い要素の数を下回ることはありません。 
4. 実現可能な最大セグメント長は、次の最大値によって決まります。$k$これにより、必要なカバレッジ レイヤーをすべて満たす前にアクティブな間隔が不足することがなくなります。 
5. 答えは、このアクティブなインターバルプロセスの最大持続深度として抽出されます。 

重要なアイデアは、各ユニットが$b_i$位置を通過する一定の間隔によってカバーされる必要がある 1 つの「レイヤー」に対応します$i$。 最も難しいのは、これらのレイヤーを継続的にサポートするために十分な間隔を維持することです。 

### なぜ効果があるのか

 左から右へ層状に間隔を構築することを考えてください。 の各ユニット$b$は、その位置をカバーする 1 つの間隔の要求です。 インターバルは連続しているため、インターバルが開始されると終了するまで継続する必要があるため、ポジションを超えて継続的に寄与します。 ソートされた順序により、常にインターバルの連続性が最も高い要求に最初に割り当てられるようになり、同時にアクティブにする必要があるインターバルの最小数が定義されます。 最大セグメント長は、カバレッジ要件に違反することなくこのアクティブ セットを維持できる最大範囲となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        
        b.sort(reverse=True)
        
        cur = 0
        ans = 0
        
        for i, val in enumerate(b):
            cur = min(cur + 1, val)
            ans = max(ans, cur)
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に処理します。 並べ替えにより、常に最も強い制約が最初に考慮されるようになります。 変数`cur`現在の「層の深さ」でどれくらいの間隔を維持できるかを追跡します。`ans`可能な最大セグメント長に対応する最大持続深度を記録します。 

移行`cur = min(cur + 1, val)`新しい要素ごとにアクティブな必要なレイヤーの数を最大 1 つ増やすことができますが、その位置での需要を超えることはできないという考えを捉えています。 これは、成長するセグメントに同時に強制できる間隔の数を効果的にモデル化します。
