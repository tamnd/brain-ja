 ## 解決策
 ## 問題の理解

 単一の整数が与えられます`n`、 どこ`n ≥ 12`。 タスクは、合計が正確に一致する 2 つの合成数を見つけることです。`n`。 

合成数は、1 とそれ自体以外の約数を少なくとも 1 つ持つ、1 より大きい整数です。 たとえば、4、6、8、および 9 は合成ですが、2、3、5、および 7 は素数です。 

入力には値が 1 つだけ含まれるため、複数のテスト ケースを処理する必要はありません。 上限は`10^6`これは十分に小さいため、数百万の操作を伴うアルゴリズムであっても、1 秒の制限時間内で簡単に十分に高速になります。 

この問題の興味深い部分は、効率ではなく、保証された構造を見つけることです。 このステートメントは、少なくとも 12 のすべての整数が 2 つの合成数の合計として表現できることを保証しているため、必要なのは常に 1 つの有効なペアを生成するメソッドだけです。 

よくある間違いは、素数性テストに焦点を当て、有効な分解を徹底的に検索することです。 これは機能しますが、不要です。 

1 つのエッジ ケースが許容最小値です。 

入力の場合:```
12
```有効な答えは次のとおりです。```
4 8
```どちらの数値も合成です。 どのソリューションでも、この下限を正しく処理する必要があります。 

もう 1 つの微妙なケースは、次のような奇数の値です。```
15
```のような分解`4 + 11`11 は素数なので無効です。 正しい出力は次のようになります。```
6 9
```どちらの数値も合成です。 

常に印刷するなどの雑な施工`4`そして`n - 4`奇数の場合は失敗します。 たとえば、`n = 15`、それは生成します`4 + 11`、これは許可されていません。 

## アプローチ

 最も直接的なアプローチはブルートフォースです。 考えられるすべての最初の数字を試すことができます`x`4から`n - 4`、 させて`y = n - x`、両方の数値が合成であるかどうかを確認します。 までの数値`10^6`大まかに複合性をテストできます`O(√n)`時間。 

このアプローチは、考えられるすべての分解を明示的に検索し、最初の有効な分解を返すため、正しいです。 問題は、最悪の場合、100 万近くの候補を検査する可能性があり、各候補に平方根素数チェックが必要になる可能性があることです。 それにより複雑さがさらに高まります`O(n√n)`、これは必要以上に手間がかかります。 

重要な観察はパリティから得られます。 

もし`n`が偶数の場合、次のようになります。```
4 + (n - 4)
```常に機能します。 

数字の 4 は合成です。 以来`n`均等です、`n - 4`も均等です。 なぜなら`n ≥ 12`、 我々は持っています`n - 4 ≥ 8`。 2 より大きいすべての偶数は合成ですか、それとも少なくとも素数ではありませんか? より具体的には、少なくとも 4 のすべての偶数が合成されます。 したがって、両方の数値は合成されます。 

もし`n`が奇数の場合:```
9 + (n - 9)
```常に機能します。 

9 という数字は合成です。 以来`n`奇妙です、`n - 9`は均等です。 なぜなら`n ≥ 13`奇数の有効な入力については、次のようになります。`n - 9 ≥ 4`。 少なくとも 4 のすべての偶数は合成であるため、2 番目の数も同様に合成です。 

この観察により、すべての検索が不要になります。 すぐに答えを組み立てることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n√n) | お(1) | 遅すぎて不必要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. かどうかを確認します。`n`は均等です。 
3. もし`n`偶数、出力`4`そして`n - 4`。 

最初の数値は合成です。 2 番目の数値は少なくとも 8 の偶数の整数であり、これも合成です。 
4. それ以外の場合は、`n`奇数です。 出力`9`そして`n - 9`。 

最初の数値は合成です。 2 番目の数値は少なくとも 4 の偶数の整数であり、合成されます。 

### なぜ効果があるのか

 このアルゴリズムは完全にパリティに依存しています。 

偶数の場合`n`、分解`4 + (n - 4)`4 は複合値であるため、これは有効です。`n - 4`は少なくとも 8 の偶数です。2 より大きい偶数の整数は約数 2 を持つため、合成されます。 

奇数の場合`n`、分解`9 + (n - 9)`9 は複合値であるため、これは有効です。`n - 9`は少なくとも 4 の偶数です。ここでも、2 より大きいすべての偶数の整数は合成されます。 

これら 2 つのケースのいずれかが常に適用されるため、アルゴリズムは常に合計が正確に一致する 2 つの合成数を出力します。`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

if n % 2 == 0:
    print(4, n - 4)
else:
    print(9, n - 9)
```プログラムは、単一の入力値を読み取ることから始まります。 

のパリティ`n`どの構造を使用するかを決定します。 偶数の場合、ペア`(4, n - 4)`が生産されます。 奇数の場合、ペア`(9, n - 9)`が生産されます。 

唯一の境界条件は、2 番目の数値が合成されたままであることを保証することです。 制約によってこれが自動的に保証されます。 最小の偶数入力の場合、`n = 12`、2 番目の値は`8`。 最小の奇数入力の場合、`n = 13`、2 番目の値は`4`。 どちらも複合です。 

ループ、素数テスト、追加のデータ構造は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())

    if n % 2 == 0:
        print(4, n - 4)
    else:
        print(9, n - 9)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("12\n") == "4 8", "sample"

# custom cases
assert run("13\n") == "9 4", "smallest odd valid input"
assert run("14\n") == "4 10", "small even input"
assert run("15\n") == "9 6", "odd input"
assert run("1000000\n") == "4 999996", "maximum constraint"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 13 | 9 4 | 奇数の有効な最小値 |
 | 14 | 4 10 | 小さい偶数値 |
 | 15 | 9 6 | 奇数構築 |
