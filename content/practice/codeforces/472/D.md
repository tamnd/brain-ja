 **タグ:** dfs および類似のもの、dsu、最短パス、ツリー
 **解決時間:** 1 分 6 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$マトリックスでは、各エントリは$d[i][j]$ノード間の距離を表します$i$そして$j$。 質問は、次の重み付きツリーが存在するかどうかを尋ねます。$n$任意の 2 つのノード間のツリーに沿った距離が、行列内の対応するエントリと正確に一致するようにノードを配置します。 すべてのエッジの重みは正の整数である必要があります。 

すぐに確認すべき最初の条件は、ノードからノード自体までの距離がゼロであるため、対角要素がすべてゼロである必要があることです。 同様に、行列は対称でなければなりません。$i$に$j$からの距離に等しい$j$に$i$。 不用意に実装すると、これらのチェックがスキップされ、無効な入力からツリーを構築しようとし、誤った結論が得られる可能性があります。 

この問題により、$n$最大 2000 までです。これは重要です。なぜなら、すべてのトリプルを単純にチェックしたり、すべての可能なツリー構造を試行したりするアルゴリズムは、この上限を簡単に超えてしまうからです。$O(n^3)$しきい値。 以来$n^3$オペレーションは 80 億件に達する可能性があるため、ソリューションを 2 秒以内に完了するには、強引な方法よりも賢いアプローチが必要です。 

明らかでないエッジ ケースには、三角不等式に違反する行列が含まれます。 たとえば、3×3 行列を考えてみましょう。```
0 1 3
1 0 1
3 1 0
```ここで、ノード 1 と 3 の間の距離は 3 ですが、距離 1→2 と 2→3 の合計はわずか 2 です。貪欲な方法を使用してエッジを構築するだけの単純なアプローチでは、この矛盾を検出できませんが、ツリーのコンテキストで三角不等式を適切にチェックすると、矛盾を検出できます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのツリーを生成しようとします。$n$ノードを作成し、それぞれの距離行列を計算し、入力と一致するものがあるかどうかを確認します。 ラベル付きツリーの数は指数関数的に増加するため、これは実行不可能です。$n$、具体的には$n^{n-2}$ケイリーの公式によると。 たとえ$n=10$、検索スペースは 1 億を超えます。 

重要な洞察は、ツリー内では任意の 2 つのノード間に一意のパスが存在するということです。 これは、任意の 3 つのノードに対して、三角不等式が正確に成立する必要があることを意味します。$i, j, k$、距離$d[i][j]$以下である必要があります$d[i][k] + d[k][j]$、そしていくつかのノードで等価性が発生する必要があります$k$道沿いにあります。 さらに、距離行列は、重み付きグラフ上の最短パスを表すものと考えることができます。 いずれかのエントリが三角不等式に違反する場合、または対角線がゼロでない場合、または対称性が崩れる場合、ツリーは存在できません。 これらの条件が満たされると、エッジが重みの順に考慮される最小スパニング ツリー アプローチを使用してツリーの再構築を試みることができ、各新しいエッジがツリーの距離プロパティを保持することが保証されます。 これにより、指数関数的な検索の問題が軽減されます。$O(n^3)$制約を考慮すると、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのツリー) | O(n^(n)) | O(n^2) | 遅すぎる |
 | 三角不等式 + MST 構築 | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、距離行列の基本プロパティを検証します。 すべてのノードのペアを反復処理し、対角要素がゼロであり、行列が対称であることを確認します。 どちらかのチェックが失敗した場合は、直ちに「NO」を出力します。 これらは、ツリーを表す距離行列の基本的な要件です。 
2. 次に、異なるノードのトリプルごとに三角不等式を検証します。$i, j, k$。 具体的に確認してみると、$d[i][j] \le d[i][k] + d[k][j]$。 トリプルがこの条件に違反する場合は、「NO」を出力します。 このステップにより、ツリー内の一意のパス プロパティと矛盾する不可能な距離が存在しないことが保証されます。 
3. 両方のチェックに合格した場合は、ツリーの構築を試みることができます。 1 つのアプローチは、すべてのエッジを考慮することです$(i, j)$重さで$d[i][j]$そして、距離行列を再現する方法でノードを接続しようとします。 より体系的な方法は、行列を距離によって重み付けされた完全なグラフとして解釈し、最小の重みでエッジを優先する最小スパニング ツリー アルゴリズムを使用することです。 その際、エッジの追加によってサイクルが作成されないこと、および接続されたノード間の距離が元の行列と一致していることを確認してください。 行列は三角不等式と対称性を満たしているため、この手順でツリーが正常に再構築されます。 
4. 最後に、ツリーの再構築後、必要に応じて、構築されたツリー上で計算された距離が元の行列と正確に一致することを検証します。 存在する場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

正確さを保証する不変条件は、ツリーの有効な距離行列の場合、任意の距離です。$d[i][j]$を接続する一意のパスに沿ったエッジの重みの合計に等しい$i$そして$j$。 三角形不等式により、代替のより短いパスが存在しないことが保証され、対称性により双方向の一貫性が保証され、ゼロ対角によりノードから自己への距離プロパティが強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    d = [list(map(int, input().split())) for _ in range(n)]
    
    # Step 1: check diagonal and symmetry
    for i in range(n):
        if d[i][i] != 0:
            print("NO")
            return
        for j in range(i + 1, n):
            if d[i][j] != d[j][i] or d[i][j] == 0:
                print("NO")
                return
    
    # Step 2: check triangle inequality
    for i in range(n):
        for j in range(n):
            for k in range(n):
                if i != j and j != k and i != k:
                    if d[i][j] > d[i][k] + d[k][j]:
                        print("NO")
                        return
    
    # If all checks pass
    print("YES")

if __name__ == "__main__":
    solve()
```コードは最初に距離行列を読み取り、基本的なツリーのプロパティを検証します。 次に、三角不等式の 3 次チェックを実行します。 早期のリターンに注目してください。違反が見つかるとすぐにアルゴリズムが停止し、不必要な計算が回避されます。 小切手`d[i][j] == 0`非対角要素の場合、すべてのエッジが正の重みを持つ必要があるため、重みがゼロのエッジが存在しないことが保証されます。
