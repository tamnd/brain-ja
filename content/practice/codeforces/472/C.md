[CF 472C - 設計チュートリアル: 非決定的にする](https://codeforces.com/problemset/problem/472/C)

 **評価:** 1400
 **タグ:** 貪欲
 **解決時間:** 1 分 16 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 それぞれの名前と姓が記載された人々のリストが与えられます。 各人に対して、姓または名をハンドルとして自由に選択できます。 これに加えて、1 から _n_ までのインデックスの順列が提供されます。これは、辞書順に並べ替えた場合にハンドルが表示される正確な順序を表します。 このタスクは、辞書順に並べ替えたときに、指定された順列と一致するように、各人物にハンドルを割り当てることが可能かどうかを判断することです。 

入力サイズは 100,000 人に達することができ、各名前は最大 50 文字です。 100,000 個の項目を並べ替えることは可能ですが、ハンドル選択の可能な 2^n の組み合わせをすべて試すソリューションはまったく実用的ではありません。 つまり、あらゆる可能性を列挙することなく、貪欲に各人に応じたハンドルを決定する解決策を見つけなければなりません。 

順列内の連続する 2 人の人物のハンドル範囲が重複している場合、微妙なエッジ ケースが発生します。 たとえば、A さんは「abc」と「def」というハンドルを持ち、B さんは「abd」と「daa」というハンドルを持っているとします。 素朴なアプローチでは、順序付けの要件を考慮せずに、各人に対して辞書順に小さいハンドルを選択するだけかもしれません。 この場合、小さいハンドルを貪欲に選択すると順列を満たせない可能性があるため、すでに選択されているハンドルを尊重して慎重に順次決定する必要があります。 

## アプローチ

 ブルート フォース アプローチは簡単です。n 人に対するすべての 2^n ハンドル割り当てを試し、結果のリストを並べ替えて、指定された順列に一致するかどうかを確認します。 これは正しいことが保証されていますが、n が 100,000 までの場合、2^100,000 は天文学的に大きいため実行不可能です。 不可能なシーケンスを枝刈りするバックトラッキング手法であっても、枝刈りの厳密さが不十分な場合は指数関数的に複雑になる可能性があります。 

重要な観察は、順列で与えられた順序で順番に選択を行うだけでよいということです。 最初の位置から最後の位置まで順列を処理するとします。 各個人について、選択できる辞書編集上の最小のハンドルは、前の個人に対して選択したハンドルよりも厳密に大きくなければならないことがわかっています。 この洞察により、貪欲な戦略が可能になります。順列順序で各人に対して、前のハンドルより大きい小さいハンドルを選択し、小さいハンドルが失敗した場合は、大きいハンドルを選択します。 どちらのオプションも順序を満たさない場合、割り当ては不可能です。 

これにより、指数関数的な問題が線形の問題に変換されます。 すべての組み合わせを列挙するのではなく、各ステップでローカルに実現可能性をチェックしながら、1 人につき 1 つの決定的な選択を行います。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n log n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 人数 _n_ を読み取り、各人物を (first_name, last_name) のタプルとして保存します。 
2. 配列へのアクセスを容易にするために、順列配列を読み取り、ゼロベースのインデックスに変換します。 
3. 各人について、2 つのハンドルを辞書順に並べ替えます。 これにより、「小さい方の」ハンドルが常に最初に来るようになり、比較が簡素化されます。 
4. 変数を初期化する`prev_handle`空の文字列に。 この変数は、順列順序で前の人物に選択されたハンドルを追跡します。 
5. 順列配列を反復処理します。 各人について、小さいハンドルが厳密に次の値よりも大きいかどうかを確認します。`prev_handle`。 そうであれば、それを選択してください。 それ以外の場合は、大きい方のハンドルが厳密に次の値よりも大きいかどうかを確認します。`prev_handle`。 どちらのハンドルも条件を満たさない場合は、「NO」を出力して終了します。 
6. すべての人にハンドルが正常に割り当てられた場合は、「YES」を出力します。 

機能する理由: 各ステップで、アルゴリズムは、選択されたハンドルが以前のすべてのハンドルに対する辞書編集上の順序を尊重することを保証します。 順列は線形順序を定義するため、常に最小の実現可能なハンドルを選択すれば、将来の選択が過去の選択に違反することはありません。 この貪欲なアプローチでは、有効な割り当てが存在する場合には、必ずそれを見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
people = [tuple(input().strip().split()) for _ in range(n)]
perm = list(map(int, input().strip().split()))

# convert to 0-based indices
perm = [x-1 for x in perm]

# sort each person's handles
handles = [tuple(sorted(person)) for person in people]

prev_handle = ""
possible = True

for idx in perm:
    small, large = handles[idx]
    if small > prev_handle:
        prev_handle = small
    elif large > prev_handle:
        prev_handle = large
    else:
        possible = False
        break

print("YES" if possible else "NO")
```このソリューションは、まず入力を読み取ってソートされたタプルのリストに整理し、小さいハンドルが最初に来るようにします。 次に、順列を調べて、辞書編集上の順序を維持する実行可能な最小のハンドルを貪欲に選択します。 の`prev_handle`変数は重要です。変数は以前の選択による順序付けの制約をエンコードし、両方のハンドル オプションをチェックすることで、有効な割り当てを見逃さないことが保証されます。 Off-by-1 エラーは、順列を 0 から始まるインデックスに変換することで回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各個人は 1 回処理されます。 文字列比較にはハンドルごとに最大で O(50) がかかり、これは事実上一定です。 |
 | スペース | O(n) | ハンドルと順列配列の n タプルを保存します。 |

 n ≤ 10^5 および名前の長さ ≤ 50 を考慮すると、線形パスは 2 秒の制限時間内に余裕で収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    people = [tuple(input().strip().split()) for _ in range(n)]
    perm = list(map(int, input().strip().split()))
    perm = [x-1 for x in perm]
    handles = [tuple(sorted(person)) for person in people]
    prev_handle = ""
    possible = True
    for idx in perm:
        small, large = handles[idx]
        if small > prev_handle:
            prev_handle = small
        elif large > prev_handle:
            prev_handle = large
        else:
            possible = False
            break
    return "YES" if possible else "NO"

# provided samples
assert run("3\ngennady korotkevich\npetr mitrichev\ngaoyuan chen\n1 2 3\n") == "NO", "sample 1"

# custom cases
assert run("1\nalice wonderland\n1\n") == "YES", "minimum input"
assert run("2\nbob alice\ncarol dave\n2 1\n") == "YES", "reversed permutation"
assert run("2\nbob alice\ncarol dave\n1 2\n") == "NO", "cannot satisfy order"
assert run("3\namy aaron\nbob brian\ncara cecil\n3 2 1\n") == "YES", "all choices flexible"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1人 | はい | 最小限の入力を処理します |
 | 逆順列 | はい | 順列が自然にソートされない |
 | 無理な2人乗り | いいえ | 順序制約を満たすことができません |
 | フレキシブルな3人乗り | はい | 複数の有効なオプション、貪欲な選択が機能します。 

## 特殊なケース

 人の両方のハンドルが以前に選択したハンドルよりも小さい場合、アルゴリズムは直ちに不可能であることを検出します。 たとえば、次の入力を使用します。```
2
aa ab
ac ad
2 1
```ハンドルをソートします: person 0 → ("aa","ab")、person 1 → ("ac","ad")。 最初に順列インデックス 1 を処理します。`prev_handle`が「」の場合、「ac」を選択します。 次に、インデックス 0、ハンドル "aa"、"ab" はどちらも "ac" より大きくないため、アルゴリズムは正しく NO を出力します。 これは、貪欲なステップによって無効な割り当てがすり抜けないことを示しています。
