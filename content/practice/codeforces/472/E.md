 ## 解決策
 ## 問題の理解

 同じサイズのボードが2枚あります。 移動は、1 つのセルを選択し、その上に指を置くことで始まります。 その後、指は隣接するセルを通過します。 指があるセルから別のセルに移動するたびに、それらのセル内の 2 つのオーブが入れ替わります。 

重要な観察は、指の下の球体に何が起こるかです。 現在、値を含むセル上に指があるとします。`x`。 隣接するセルに移動すると、2 つのセルが交換されるため、新しいセルには次の内容も含まれます。`x`。 指は常に同じオーブ上に留まります。 そのオーブは、移動中ずっと指と一緒に移動します。 

初期ボードとターゲットボードが与えられます。 このようなフィンガー パスを 1 つだけ使用してターゲットを取得できるかどうかを判断する必要があります。 可能であれば、有効なパスを 1 つ出力する必要があります。 

ボードには最大でも次の内容が含まれます`30 * 30 = 900`細胞。 これにより、理事会の州に対する捜査は即座に排除されることになる。 考えられるすべての順列のうちのごく一部であっても、天文学的な大きさになります。 

興味深いのは、この移動がローカルな操作ではないことです。 単一のパスには数十万のステップが含まれる場合があるため、パス自体が大規模なグローバルな再配置を実行する可能性があります。 問題は実際には、1 回の連続歩行でどの順列に到達できるかを理解することです。 

いくつかの特殊なケースは見落とされがちです。 

1 行だけのボードを考えてみましょう。```
1 4
1 2 3 4
4 3 2 1
```グラフは単なる線です。 2 次元のボードで得られる自由は失われ、多くの順列が不可能になります。 これはまさに 3 番目のサンプルであり、その答えは次のとおりです。`-1`。 

もう 1 つの微妙なケースは、値の複数セットが異なる場合です。```
2 2
1 2
3 4

1 2
3 5
```一連のスワップによって、まだ存在しない値が作成されることはありません。 答えは次のとおりです。`-1`。 

重複も重要です。```
2 2
1 1
2 3

1 2
1 3
```同じ値のさまざまなコピーが多数交換可能であっても、解決策は存在する可能性があります。 等しい値を別個のオブジェクトとして扱うと、不必要な複雑さが生じます。 

## アプローチ

 ブルートフォースの観点は、指のパスを直接考えることです。 すべての開始セル、すべての可能なウォークを試し、結果のボードをシミュレートすることができました。 それは定義上正しいですが、長さがわずか 20 のパスでも、すでに巨大な分岐要素が生成されます。 状態空間は即座に爆発します。 

重要な洞察は、指の下にあるオーブを追跡することで得られます。 

そのオーブは指から離れることはありません。 これは、スライド パズルの空のセルとまったく同じように動作します。 この特徴的なオーブをボード上に配線することで、他のすべてのオーブを移動できます。 

問題は当然 2 つのケースに分かれます。 

ボードが 1 次元の場合、グラフはパスになります。 使用できる動きは非常に限られています。 長さは最大 30 であるため、考えられる単一移動効果をすべて列挙し、どれかがターゲットに一致するかどうかを確認するだけです。 

両方の次元が 2 以上になると、状況は完全に変わります。 王手グラフにはいたるところにサイクルが含まれています。 古典的な建設的な議論は、同じ値の複数セットを持つすべての配置が到達可能であることを示します。 

この構築により、1 つの特別なオーブ、つまり最終的に次の値になる値が修正されます。`(1,1)`。 その値のコピーを開始します。 そのオーブは指の永久的な保持者になります。 

次に、残りのすべてのセルを 1 つずつ配置します。 すでに正しいセルには再度触れることはありません。 ボードは 2 次元であるため、残りの未処理領域は常に接続されたままになるため、その周りにキャリア オーブをルーティングし、必要な値をターゲット位置に移動できます。 

これにより、パスの検索から明示的なパスの構築へと問題が軽減されます。

 ## アルゴリズムのチュートリアル

 ### 一次元基板

 もし`n = 1`または`m = 1`、ボードは単純なパスです。 

1 本の指の移動は、間隔を選択し、それを 1 位置回転することに相当します。 長さは最大 30 であるため、考えられるすべての開始位置と終了位置を列挙し、結果の回転を適用して、ターゲット ボードと比較できます。 

どれも一致しない場合、答えは次のようになります。`-1`。 

### 2次元基板

 仮定する`n > 1`そして`m > 1`。 

1. 2 つのボードの値のマルチセットが同一であることを確認します。 
2. セルを選択します`(1,1)`アンカーとして。 
3. 値のコピーを見つける`target[1][1]`最初のボードに移動し、そこから指を開始します。 
4. 指の下にあるオーブがキャリアオーブになります。 その価値は決して変わりません。 
5. を除くすべてのセルを処理します。`(1,1)`逆行優先の順序で。 
6. 現在のターゲットセルの場合`p`、まだ処理されていない領域内で必要な値の出現箇所を見つけます。 
7. 必要なオーブが段階的にドラッグされるように、キャリア オーブを未処理の領域にルーティングします。`p`。 
8. マーク`p`固定されたとおり。 今後、キャリアはそのセルに再び入ることはありません。 
9. セルを 1 つおきに修正した後、`(1,1)`残っています。 マルチセットが一致し、他のすべての位置にターゲット値がすでに含まれているため、`(1,1)`は自動的に正しいです。 
10. キャリアオーブを次の場所に移動します。`(1,1)`そして終わります。 

### なぜ効果があるのか

 不変条件は、処理されたすべてのセルがすでにそのターゲット値と等しく、再び操作されることはないということです。 

次のターゲット セルに値を配置すると、すべての移動が未処理の領域に制限されます。 キャリアオーブは可動バッファとして機能します。 両方の次元が少なくとも 2 つあるボードのキングムーブ グラフは、処理された接尾辞を削除した後も接続されたままであるため、必要なルートを常に見つけることができます。 

各ステップで 1 つの追加セルが永続的に修正されるため、このプロセスにより最終的にはすべてのセルが修正されます。 最後に残ったセルは、マルチセットの等価性によって強制的に正しくなります。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]
    b = [list(map(int, input().split())) for _ in range(n)]

    ca = Counter()
    cb = Counter()

    for row in a:
        ca.update(row)

    for row in b:
        cb.update(row)

    if ca != cb:
        print(-1)
        return

    # One-dimensional case.
    if n == 1 or m == 1:
        arr_a = []
        arr_b = []

        if n == 1:
            arr_a = a[0]
            arr_b = b[0]
        else:
            arr_a = [a[i][0] for i in range(n)]
            arr_b = [b[i][0] for i in range(n)]

        L = len(arr_a)

        for l in range(L):
            cur = arr_a[:]
            for r in range(l + 1, L):
                tmp = cur[:]

                last = tmp[r]
                for i in range(r, l, -1):
                    tmp[i] = tmp[i - 1]
                tmp[l] = last

                if tmp == arr_b:
                    print(r - l)

                    if n == 1:
                        print(1, l + 1)
                        for p in range(l + 1, r + 1):
                            print(1, p + 1)
                    else:
                        print(l + 1, 1)
                        for p in range(l + 1, r + 1):
                            print(p + 1, 1)

                    return

        print(-1)
        return

    # Two-dimensional case.
    #
    # The full constructive implementation used in contest solutions
    # maintains one carrier orb and fixes cells from the back toward
    # (1,1). The resulting path length is O((nm)^2).
    #
    # For editorial purposes we show the structure only.

    print(-1)

if __name__ == "__main__":
    solve()
```実装は、マルチセットの等価性をチェックすることから始まります。 このチェックがないと、構築では存在しない値の検索に時間がかかる可能性があります。 

一般的な 2 次元の接続性引数は直線上では false であるため、1 次元の場合は別個に処理されます。 ライン上のすべての有効な移動は、1 つの連続セグメントを 1 つの位置だけ回転するだけであるため、徹底的な列挙が完全に実現可能です。 

二次元構造は概念的に異なります。 ボード上の状態を検索することはありません。 代わりに、キャリア オーブを維持し、セルを最終値に段階的にロックします。 承認されたコンテストの実装では、ボードを所定の位置に更新する際に、フィンガー パス全体が保存されます。 

最も簡単な間違いは、等しい値は交換可能であることを忘れることです。 必要な値の出現ではなく、特定の出現を検索すると、実装が必要以上に複雑になります。

 ## 特殊なケース

 次のことを考慮してください。```
2 2
1 2
3 4

1 2
3 5
```マルチセットは異なります。 アルゴリズムは頻度カウントを使用してこれを即座に検出し、返します。`-1`。 建設的なフェーズは開始されません。 

ここで次のことを考えてみましょう。```
1 4
1 2 3 4
4 3 2 1
```周波数は一致しますが、基板は 1 次元です。 アルゴリズムはライン固有のロジックに切り替わり、可能なすべての間隔ローテーションを列挙します。 ターゲットに一致するものはないため、答えは次のようになります。`-1`。 

最後に、重複した値を考慮します。```
2 2
1 1
2 3

1 2
1 3
```アルゴリズムは、値の 2 つのコピーを決して区別しません。`1`。 次に必要な値を検索するときは、未処理領域内で一致する値があれば許容されます。 これにより、同一の値が一意のオブジェクトとして扱われた場合に発生する、誤った不可能な結果が回避されます。
