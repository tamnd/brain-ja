 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられています。`x`そして`y`、それぞれの長さ`n`。 配列`x`は開始状態であり、`y`は望ましい目標状態です。 許可される唯一の操作は、`x[i] ^= x[j]`に代わる`x[i]`次のビット単位の XOR を使用して、`x[i]`そして`x[j]`。 私たちの使命は変革することです`x`の中へ`y`これらの XOR 演算のシーケンスを使用します。 無理ならアウトプットすればいい`-1`; それ以外の場合は、最大 1,000,000 ステップの有効な一連の操作を作成する必要があります。 

重要な制約は、`n`最大 10,000 まで大きくなり、各要素は`x`そして`y`最大 10^9 まで可能です。 これにより、XOR 演算の可能なシーケンスの数が指数関数的に増加するため、XOR 演算のすべての可能なシーケンスを試行するアプローチは即座に除外されます。`n`。 ほぼ線形、またはわずかに超線形のアプローチが必要です。`n`、XOR はビット単位で動作するため、理想的には O(n * log(max_value)) です。 

のすべての要素が一致する場合、微妙なエッジケースが発生します。`x`ゼロですが、`y`ゼロ以外の数値が含まれています。 この場合、XOR 演算ではゼロから非ゼロの数値を生成できないため、答えは次のようになります。`-1`。 別のエッジケースが発生するのは次の場合です。`x`すでに等しい`y`最初は; ここでの正解は、単に操作がゼロであるということです。 

主な課題は、XOR 演算が GF(2) (0 と 1 の 2 つの要素を持つフィールド) に対する線形演算に対応することを認識することです。 各数値はビットのベクトルであり、数値の XOR 演算はベクトルの加算に対応します。 これにより、問題が GF(2) 上の線形代数問題に変換され、目標は各ターゲット ベクトルを表現することになります。`y[i]`現在のベクトルの線形結合として`x`。 

## アプローチ

 ブルート フォース アプローチでは、XOR 操作のすべてのシーケンスが試行されます。`x`等しい`y`。 これは明らかに非現実的です。`n`、シーケンスの数は膨大です。 ブルート フォースは、最終的には有効な XOR 操作のシーケンスになる必要があるため、原理的には正しいですが、パフォーマンスの観点からすぐに失敗します。 

効率的な解決策の重要な洞察は、各数値をビットのベクトルとして扱い、次のベクトルのセットを考慮できることです。`x`GF(2) の基礎として。 これらのベクトル間で XOR 演算を実行することにより、それらの線形結合を構築できます。 次に、問題は 2 つのステップに分かれます。まず、削減します。`x`線形独立基底へ。 次に、それぞれの目標を表現します`y[i]`XOR 演算を使用したこの基礎の線形結合として。 もしあれば`y[i]`基底ベクトルの組み合わせとして表現できない場合、変換は不可能です。 

このアプローチは、GF(2) に対するガウス消去法に似ています。 各ステップで残りの数値の中から最大の未設定ビットを選択し、適切に XOR 演算することで、体系的にベクトルの三角形システムを構築できます。 次に、それぞれを達成するために逆置換できます。`y[i]`その通り。 各ベクトルのビット数は最大 30 ビットであるため (0 ≤ x[i]、y[i] ≤ 10^9 であるため)、演算の合計数は O(n * log(max_value)) によって制限されます。

 ## アルゴリズムのチュートリアル

 1. 空の操作リストを初期化します。 の各要素`x`は 30 ビットのベクトルとして扱われます。 
2. 順方向パスを実行して、次の線形独立基底を構築します。`x`。 最上位から最下位までの各ビットについて、次の数値を見つけます。`x`まだピボットとして使用されていないビットが設定されています。 現在の位置に交換します。 このビットが設定されている他のすべての数値と XOR します。 各 XOR 演算が記録されます。 これにより、各ピボットが固有の先頭ビットを持つことが保証されます。 
3. フォワードパス後、すべてのことを確認します。`y[i]`は、基底ベクトルの線形結合として表すことができます。 それぞれについて`y[i]`、で使用されたのと同じピボット位置を使用してビットを削除しようとします。`x`。 除去できないビットが残っている場合、ターゲットは到達不可能であるため、出力します。`-1`。 
4. もしすべてが`y[i]`を表すことができ、それぞれに到達するために必要な XOR 演算のシーケンスを構築します。`y[i]`基礎から。 これは、記録された順方向操作を逆に実行するか、ビルドすることによって実行できます。`y`基本要素の XOR を段階的に使用します。 
5. シーケンスに続く操作の合計数を出力します。 

機能する理由: 各 XOR 演算は、GF(2) へのベクトルの追加に対応します。 基礎を構築することで、`x`、私たちは到達可能なすべての線形結合を知っています。 ガウス消去法により基底が線形独立であることが保証されるため、任意の線形結合を構築できます。 記録された操作は、ターゲットを再構築するためのレシピを形成します。`y`到達不可能なビットを導入することなく。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
x = list(map(int, input().split()))
y = list(map(int, input().split()))

ops = []
# make a copy to avoid modifying original
a = x[:]

pivots = [-1] * 32
idx = [-1] * 32

# forward elimination to build basis
for i in range(n):
    for b in reversed(range(30)):
        if (a[i] >> b) & 1:
            if pivots[b] == -1:
                pivots[b] = a[i]
                idx[b] = i
                break
            else:
                a[i] ^= pivots[b]
                ops.append((i+1, idx[b]+1))

# check reachability of y
for i in range(n):
    t = y[i]
    for b in reversed(range(30)):
        if (t >> b) & 1:
            if pivots[b] == -1:
                print(-1)
                sys.exit()
            else:
                t ^= pivots[b]
                ops.append((i+1, idx[b]+1))

print(len(ops))
for u, v in ops:
    print(u, v)
```このコードは、まず GF(2) に対するガウス消去法を使用して基底を構築します。 数値を基本形式に減らすために必要な各 XOR 演算を記録します。 そして、それぞれを表現してみます`y[i]`基底の線形結合として。 不可能な場合は、次のように終了します。`-1`。 それ以外の場合は、すべての操作が出力されます。 

注意点としては、ピボット ビットの一意性を維持するためのビットの順序 (上位から順) や、動作レポートのためのインデックスの追跡などが挙げられます。 Off-by-one エラーは次の方法で回避できます。`i+1`操作を記録するとき。
