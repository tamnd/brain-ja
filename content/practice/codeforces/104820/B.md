 ## 解決策
 ## 問題の理解

 山の表面を表す長方形のグリッドが与えられます。 各セルには、正または負の整数値が含まれます。 パスは、このグリッド上の歩行を表します。最初の行の任意のセルから開始し、4 つの基本方向を使用して隣接するセル間を移動しますが、上方向に移動することはできません。 また、同じセルに複数回アクセスすることはできません。 パスは、一番下の行からグリッドの外に出たときに終了します。パスの値は、訪問したすべてのセルの合計です。 

タスクは、これらの移動ルールに基づいて可能な最大パス合計を計算することです。 

グリッド サイズは最大 1500 x 1500 で、これは約 225 万個のセルを意味します。 このようなグリッド上の小さな分岐要素でさえ指数関数的な動作につながるため、すべてのパスを明示的に探索しようとする解決策は不可能です。 このため、各セルを小さい一定回数 (理想的には O(nm)) で処理する動的プログラミング ソリューションを使用する必要があります。 

微妙な難しさは、水平方向の移動と「再訪問禁止」の制約の組み合わせです。 上向きの動きは禁止されていますが、水平方向の動きは基礎となるグラフに潜在的なサイクルを生み出します。 標準のグラフ アルゴリズムでは非周期性が想定されているか、制御された方法での再訪が許可されているため、単純な最短パスまたは最長パスの緩和は機能しません。 ここで、正確性は、各行内で単純なパスのみを考慮しながらも、達成可能な最良の合計を効率的に伝播することを保証するかどうかに依存します。 

単純なアプローチを破ることが多いエッジ ケースの 1 つは、最適なパスが下降する前に列内で長い水平方向の迂回を必要とする場合です。 たとえば、次のような行について考えてみましょう。`[1, -100, 1]`続いて行`[100, 100, 100]`。 最善の戦略は、ドロップする前に慎重に上の行を移動することですが、単純な「常にすぐに下に移動する」という貪欲なアプローチでは、最適な構造を完全に見逃してしまいます。 

各セルが左右から独立して処理できると仮定すると、別の問題が発生します。 水平方向の移動では行全体に依存関係が生じるため、左から右への 1 つのパスでは不十分です。 

## アプローチ

 ブルートフォース解釈では、各セルをグラフ内のノードとして扱い、上向きのエッジを除いてその 4 つの隣接するエッジを持ちます。 次に、ノードを再度訪問することなく、最上行のノードから最下位の出口ノードまでの最大パス合計を計算しようとします。 これは本質的に、一般的なグラフにおける単純な最長経路の問題であり、計算的には扱いにくいものです。 再訪しなくても、行内の分岐構造により指数関数的な数のパスが可能になり、それらを直接探索するには、最悪の場合でも O(4^(nm)) 程度の時間が必要になります。 

重要な構造的観察は、水平方向の動きによって基礎となるグラフにサイクルが導入されるものの、「上方への動きなし」という制約により行による強力な層構造が誘導されるということです。 すべての動きは、行内で行われるか、厳密に下向きに行われます。 これは、グリッドを行ごとに処理することを示唆しており、セルの状態は上の行と同じ行内の水平方向の伝播のみに依存します。 

これにより、上から入力される最適な値がわかれば、各行を独立して解決できる動的プログラミング システムに問題が変わります。 残りの課題は、セルを再度訪問することなく、行内で任意の水平方向の歩行を考慮する必要があることです。 これは、行内のパス値の最適な伝播をシミュレートする 2 つの方向のスイープによって処理できます。

 ## アルゴリズムのチュートリアル

 グリッドを行ごとに処理し、各セルの達成可能な最良の合計を上からのエントリ値または以前の水平方向の移動からのエントリ値として維持します。 

### ステップ

 1. 最初の行の DP 配列を初期化します。各エントリは単にそのセルの値です。 これは、どのトップセルからでも開始できることを反映しています。 
2. 後続の各行について、最初にそのグリッド値を真上のセルの最適値に加算することにより、各セルの一時的な DP 値を計算します。 これにより、垂直に到着するすべてのパスがキャプチャされます。 
3. 行全体で左から右へのスイープを実行します。 各セルについて、同じ行内の左隣から移動し、現在のセル値を追加することを考慮して、その最適な値を更新します。 これは、パスを右に水平に延長することをシミュレートします。 
4. 同じロジックで右から左へのスイープを実行し、右側からの伝播を可能にします。 これにより、列内で方向転換する必要があるパスが正しく捕捉されます。 
5. 両方のスイープの後、行の DP 値は、すべての有効な行内移動後の各セルで終了する最良の合計を表します。 
6. すべての行に対してこのプロセスを繰り返し、常に DP 配列を上書きします。 
7. 最終的な答えは、最後の行の DP 配列の最大値です。これは、追加コストなしでどの下部セルからでもグリッドを終了できるためです。 

### なぜ効果があるのか

 重要な不変条件は、行 r を処理した後、各セルの DP 値がそのセルで終了する有効なパスの最大合計を表し、行 1 から r までのすべての移動ルールを尊重することです。 水平方向のスイープは、行内のすべての単純なパスを正確に解決します。これは、最適な水平方向の動きが、左から右および右から左への緩和によって捕捉される一連の単調な拡張に分解できるためです。 行間の移動は厳密に下向きであるため、将来の行が過去の行の状態を改善する方法はなく、最適な下部構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    dp = grid[0][:]

    for r in range(1, n):
        new_dp = [0] * m
        
        for c in range(m):
            new_dp[c] = dp[c] + grid[r][c]

        for c in range(1, m):
            new_dp[c] = max(new_dp[c], new_dp[c-1] + grid[r][c])

        for c in range(m-2, -1, -1):
            new_dp[c] = max(new_dp[c], new_dp[c+1] + grid[r][c])

        dp = new_dp

    print(max(dp))

if __name__ == "__main__":
    solve()
```この実装では、一度に 1 つの DP 行のみが保持されます。これは、処理後に以前の行を再度参照する必要がないためです。 

最初の初期化ステップは、先頭行のどこからでも開始できる自由を直接エンコードします。 上からセルに入ることが許可される唯一の下方向の行間移動であるため、垂直方向の遷移は現在のセル値を単純に加算します。 

2本の横パスが重要な部分だ。 左から右へのパスは、前のセルで終了する最適なパスを現在のセルまで延長できることを前提としています。 右から左へのパスはこれを反映しており、右に移動した後に左に移動する必要があるパスもカバーされるように対称性を確保しています。 両方のパスがないと、行内のいくつかの最適なジグザグ パスが失われます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各セルは 2 つの線形スイープで行ごとに 1 回処理されます。 
| スペース | O(m) | 常に 1 つの DP 行のみが保存されます。 

グリッド サイズは最大 225 万セルに達し、各セルは一定の回数タッチされます。これは、最適化された Python または C++ での 1 ～ 2 秒の時間予算の一般的な制限内に快適に収まります。

 ## 特殊なケース

 サイズ 1 x 1 の最小グリッドは、初期化によって DP がセル値に直接設定され、遷移が発生しないため、正しく処理されます。 

単一行の場合、アルゴリズムは垂直方向の遷移を伴わずに、無制限の水平方向の動きを正確にシミュレートします。 2 つのスイープにより、行全体に最適なセグメントの合計が完全に伝播されます。 

単一の列により、問題は上から下への単純なパスに帰着します。 DP の反復は累積和になり、水平方向の近傍がないため水平方向のスイープは効果がなく、アルゴリズムが偽の遷移を導入しないことが確認されます。
