 ## 解決策
 ## 問題の理解

 いくつかの音楽ジャンルが与えられており、各ジャンルには固定の曲数があります。 ここでの課題は、隣接する 2 つの曲が同じジャンルに属さないように、すべての曲を 1 つのプレイリストに配置できるかどうかを判断することです。 

これについての別の考え方は、同一のアイテムの複数のグループをインターリーブしようとしているということです。 各ジャンルは同一のトークンのブロックのように動作するため、隣接する同一のトークンを避けながら、行内のすべてのトークンを並べ替える必要があります。 

入力サイズは最大 100,000 ジャンルが可能で、各ジャンルは最大 10,000 曲を提供できます。 これは、曲の総数が非常に大きくなり、最大 10^9 になる可能性があることを意味します。 順列を明示的に構築またはシミュレートしようとする解決策は不可能です。 個々の曲の並べ替えや貪欲なシミュレーションでも、完全に展開されたシーケンスを反復処理すると、速度が遅すぎます。 

時間制限は、曲の総数ではなく、ジャンルの数に対して O(n) または O(n log n) で作業する必要があることを意味します。 

重要なエッジケースは、1 つのジャンルが残りのジャンルを支配する場合に発生します。 たとえば、1000、1、1、1 のようなカウントがある場合、主要なジャンルのすべての出現を分離するのに十分な量の他の曲をインターリーブすることは明らかに不可能です。 総和またはパリティのみをチェックする単純なアプローチは、ここでは失敗します。これは、集合体だけでなく最大の山の構造が重要であるためです。 

もう 1 つの微妙なケースは、2 つの大きなジャンルが一緒になって残りを支配する場合です。 たとえば、50、49、1、1、1 などのカウントは引き続き機能しますが、正確な不等号推論を行わずに最大値と他の値の合計を比較するだけの小さな誤った判断は、正しく実装されていない場合、誤解を招く可能性があります。 

## アプローチ

 ブルートフォース戦略では、プレイリストを明示的に構築しようとします。 利用可能なジャンルの中から貪欲に選択して、最後に配置された曲とは異なるジャンルを繰り返し選択することもできます。 これは、優先順位構造を備えたシミュレーションに似ています。 それぞれの配置には有効な次のジャンルを選択する必要があり、最悪の場合、数十億曲にも及ぶ可能性のある曲ごとに線形または対数的な選択が実行されます。 総曲数はすべての a_i の合計であるため、これは O(総曲 log n) 以上になり、実行不可能です。 

重要な点は、正確な配置は必要なく、その存在だけが必要であるということです。 問題は古典的な実現可能性条件に帰着します。つまり、他のすべての曲を区切り文字として使用して、最も頻繁に出現するジャンルを分離できるかということです。 

1 つのジャンルに曲が多すぎると、必然的にそのジャンルとの隣接性が強制されます。 他のすべての曲を区切り文字として最初に配置することを想像してください。 各セパレータは、主要なジャンルの 2 つの出現の間の隣接関係を最大 1 つまで分割できます。 最大カウントが他の曲の合計数に 1 を加えたものより大きい場合、隣接を避ける方法はありません。 

max を最大の a_i とし、sum を曲の総数とします。 最大以外の曲の数は合計 - 最大です。 最大のジャンルの出現の間に他の曲を配置するには、少なくとも max - 1 のギャップが必要です。 したがって、条件は次のようになります。 

最大値 - 1 ≤ 合計 - 最大値

 これは次のように単純化されます。 

最大 ≤ 合計 - 最大 + 1

 この不等式が成り立たない場合、取り決めは存在しません。 それ以外の場合は、貪欲なインターリーブ引数を使用して常に有効な順序を構築できるため、条件は必要であると同時に十分でもあります。

 ## アルゴリズムのチュートリアル

1. すべてのジャンルのカウントを読み取り、その合計と最大値を計算します。 これは、分布がどの程度集中しているかの世界的な構造を捉えています。 
2. 最も頻繁に発生するジャンルのみが避けられない隣接問題を引き起こす可能性があるため、最大数を特定します。 他のすべてのジャンルは、十分な量が存在する場合、いつでも区切り文字として使用できます。 
3. 合計から最大値を引いて、主要なジャンルに含まれない曲が何曲あるかを計算します。 使用できる区切り文字はこれらのみです。 
4. 使用可能な区切り文字の数が少なくとも max - 1 であるかどうかを確認します。これは、有効なシーケンス内で主要なジャンルが出現する間のギャップの数です。 
5. 条件が成立する場合は「Yes」を出力し、成立しない場合は「No」を出力します。 

### なぜ効果があるのか

 正しさは、ギャップを埋める議論にかかっています。 最も頻繁に使用されるジャンルを配置すると、その出現の間に正確に最大 - 1 個の強制的なギャップが作成されます。 隣接を避けたい場合、他の曲は最大でも 1 つのギャップを占めることができます。 非ドミナントな曲の数がギャップよりも少ない場合は、少なくとも 1 つのギャップが空のままである必要があり、2 つの同一のジャンルが強制的に接触します。 逆に、十分なセパレータが存在する場合は、常にセパレータをギャップ全体に分散し、実行可能性を損なうことなく残りの主要な要素を挿入して、有効な配置が存在することを保証できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    if mx <= total - mx + 1:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```実装は派生条件に直接に従います。 すべてのカウントの合計が 1 回計算され、配列の 1 回のパスで最大値が抽出されます。 最後の不等式は実現可能条件全体をエンコードするため、それ以上のシミュレーションは必要ありません。 

微妙な点としては、`+1`状態で。 これは、最大のジャンルがシーケンスの両端を占めることができるため、必要な区切り文字の数がその数よりも 1 つ少ないという事実に対応します。

 ## 特殊なケース

 主なエッジケースは、ジャンルが 1 つしかない場合です。 入力の場合:```
1
5
```total = 5 および mx = 5 を計算します。条件は 5 ≤ 1 となり、偽となるため、出力は No になります。これは、同一の曲のシーケンスが常に隣接ルールに違反することを正しく反映しています。 

もう 1 つのエッジケースは、最大のジャンルがぎりぎり大きすぎる場合です。 のために：```
4
1 1 1 4
```total = 7 および mx = 4 です。条件は 4 ≤ 4 で true なので、答えは Yes です。 有効な配置は、最大のジャンルの出現の間にシングルトンを配置することによって存在します。 

最後に、密集した失敗のケースを考えてみましょう。```
3
1 1 3
```ここでは total = 5 および mx = 3 です。条件は 3 ≤ 3 であるため、有効です。 3 1 3 1 3 のようなシーケンスを構築できます。これは、等価性がまさに可能な構成と不可能な構成の境界であることを示しています。
