 ## 解決策
 ## 問題の理解

 行と列のサイズが均一ではないグリッドが与えられています。 各行の高さは配列で指定された正の値になります。`A`、各列は配列で与えられる正の幅を持ちます。`B`。 連続した行のブロックと連続した列のブロックを取ると、それらは単位セルで構成される長方形の領域を形成します。`(i, j)`は、選択した行と列に応じて面積の寄与が異なる、より大きな幾何学的な長方形の中に存在します。 

から行を選択すると、`l`に`r`とコラム`x`に`y`、選択された形状は完全な部分行列です。 選択されたセクターの数は、単にそのサブマトリックス内のセルの数であり、次の値となります。`(r - l + 1) * (y - x + 1)`。 

ただし、幾何学的制約があります。 各行は高さに寄与するため、選択した行セグメントの合計高さは次の合計になります。`A[i]`各列が幅に寄与するため、合計幅は次の合計になります。`B[j]`柱セグメント上にあります。 結果として得られる長方形の物理面積は、これら 2 つの合計の積であり、この積は次の値を超えてはなりません。`S`。 

タスクは、幾何学的面積制約を満たしながら、結果として得られる四角形内のセルの数を最大化するために、1 つの連続した行セグメントと 1 つの連続した列セグメントを選択することです。 

制約`N, M ≤ 1000`おおよそ以上の解決策があることを意味します`O(N^2 M)`または`O(N M^2)`遅すぎるでしょう。 解決策`O(N^2 log M + M^2 log N)`ディメンションあたり約 100 万の間隔は実現可能ですが、クエリごとのネストされたフル スキャンは実現できないため、それ以上の値が許容されます。 

行セグメントと列セグメントのすべてのペアを個別に試す単純な試みでは、大まかにチェックされます。`O(N^2 M^2)`組み合わせ、つまり約`10^12`、限界をはるかに超えています。 

単純な枝刈りが微妙に失敗するケースは、一方の次元が大きいものの、もう一方の許容範囲がわずかに減少する場合に発生します。 たとえば、わずかに大きな行セグメントを選択すると、許容される列幅が 1 列だけ減少する可能性がありますが、その 1 列の損失により領域数が大幅に減少する可能性があります。 すべての間隔を考慮せずに 1 次元で貪欲に拡張すると、そのようなトレードオフが失われます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、可能なすべての行間隔とすべての列間隔が列挙されます。 各ペアについて、次の合計を計算します。`A`そして`B`それらの間隔で、製品が最大で`S`、セルの数を計算します。 これは、すべての有効な四角形を徹底的にチェックするため、正しいです。 問題はコストです。`O(N^2)`行間隔と`O(M^2)`列間隔、および各ペアのチェックには、プレフィックス合計が使用されている場合は一定時間または対数時間がかかり、おおよその時間が得られます。`10^12`最悪の場合の評価も。 

重要な構造上の観察は、行と列の選択が、単一のスカラー制約 (それらの合計の積) を介さない限り独立しているということです。 これは、問題を 2 つの段階に分けることを示唆しています。 行間隔を固定すると、その合計は定数になります`H`。 この場合、有効な列間隔は次の条件を満たす必要があります。`sum(B[l..r]) ≤ S / H`。 その固定しきい値には、最大長の列間隔が必要です。 

これにより、問題がパターンに変わります。すべての列間隔を 1 回事前計算し、それらの合計で保存し、多くの「合計 ≤ T の間隔間の最大長」クエリに答えます。 同じことを行に対して対称的に行うこともできますが、一度行うだけで十分です。 

2D 選択の問題を、1 つの次元のすべての 1D 間隔を生成し、それらを効率的にクエリすることに還元します。

 ## アルゴリズムのチュートリアル

 すべての列間隔を事前計算し、それらの情報を合計制約による高速なクエリを可能にする構造に圧縮します。 

1. 配列のプレフィックスの合計を計算する`B`, したがって、任意の区間合計は O(1) で取得できます。 これにより、すべての列セグメントを効率的に評価できるようになります。 
2. すべての列間隔を列挙します。`(l, r)`そして、それぞれについて 2 つの値を計算します。`sumB = B[l] + ... + B[r]`そして`lenB = r - l + 1`。 これにより、約`M² / 2`間隔。 
3. これらの間隔を次の基準で並べ替えます。`sumB`。 ソート後、各位置に最大値を格納する配列を構築します。`lenB`これまで見られた。 これにより、あらゆるしきい値に対して構造が単調なクエリ ツールに変換されます。`T`、合計 ≤ の場合、すべての間隔の中で最適な列の長さを見つけることができます。`T`バイナリ検索とそれに続くプレフィックス最大ルックアップを使用します。 
4. 同じプレフィックス合計の準備を繰り返します。`A`。 
5. すべての行間隔を列挙します。`(i, j)`、計算する`sumA = A[i] + ... + A[j]`そして`lenA = j - i + 1`。 
6. 行間隔ごとに、最大許容列合計を計算します。`T = S // sumA`。 
7. 前処理された列構造をクエリして、合計が超えない最適な列長を取得します。`T`。 
8.次のように回答を更新します。`lenA * bestLenB`。 

これが機能する理由は、行間隔が固定されると、列の選択が事前計算されたセットに対する独立した制約付きの最適化問題になり、またその逆になるためです。 

### なぜ効果があるのか

 有効な四角形ごとに、それを表す行間隔と列間隔が 1 つだけ存在します。 このアルゴリズムは、すべての行間隔を明示的に考慮し、そのような間隔ごとに、その行の選択によって引き起こされる正確な制約の下で、最適な互換性のある列間隔を計算します。 列間隔が完全に列挙され、可能な合計しきい値ごとに最適化されるため、実行可能な構成がスキップされることはありません。 制約は単一のスカラー積を通じてのみ次元を結合するため、分解では最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_intervals(arr):
    n = len(arr)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + arr[i]

    intervals = []
    for i in range(n):
        for j in range(i, n):
            s = pref[j + 1] - pref[i]
            length = j - i + 1
            intervals.append((s, length))
    return intervals

def build_query_structure(intervals):
    intervals.sort()
    best = []
    max_len = 0

    for s, l in intervals:
        if l > max_len:
            max_len = l
        best.append((s, max_len))
    return best

def query(best, T):
    import bisect
    idx = bisect.bisect_right(best, (T, 10**18)) - 1
    if idx < 0:
        return 0
    return best[idx][1]

def solve():
    N, M, S = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    col_intervals = build_intervals(B)
    col_best = build_query_structure(col_intervals)

    row_intervals = build_intervals(A)

    ans = 0

    for sumA, lenA in row_intervals:
        if sumA > 0:
            T = S // sumA
            lenB = query(col_best, T)
            ans = max(ans, lenA * lenB)

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、プレフィックスの合計を使用して、各配列を可能なすべての連続セグメントに変換します。 各セグメントは、その合計と長さによって表されます。 列の場合、これらのセグメントは合計によってソートされ、圧縮されるため、任意の合計しきい値に対して達成可能な最大幅を効率的に取得できます。 

クエリ関数は、圧縮された構造に対して二分検索を使用します。 構造は合計が単調であるため、任意のしきい値の最適な長さは常に、合計が制限内にある最後の間隔またはそれより前に見つかります。 

行ループは、考えられる高さの選択肢をそれぞれ評価し、それを最大許容列合計に変換します。 最も一致する列と行の長さの積により、回答の候補が得られます。

A = [2, 4, 1, 3]

```まず、いくつかの列間隔をリストします。

 圧縮後、次のような小さなしきい値の場合`T = 1`、合計 ≤ 1 の間隔のみが使用可能であり、最適な長さは 1 になります。 

行間隔には、次のような単一要素の行が含まれます。`[3]`sumA = 1 および lenA = 1 です。これにより、次のようになります。`T = 2`したがって、合計 ≤ 2 の任意の列間隔を使用でき、最適な列長は 1 になります。積は 1 です。 

より大きな行合計を試行すると、すぐに減少します`T`0 に設定すると、有効な列が得られません。 ベストアンサーは 1 のままです。 

このトレースは、厳しい制約により、解が最小の有効な長方形に近づくことを示しています。 

### サンプル 2

 入力:```
A = [2, 4, 1, 3]
B = [4, 2, 1, 2]
S = 20
```制約が十分に緩くなり、より大きな長方形を使用できるようになりました。 

行間隔の場合`[4, 1, 3]`、 sumA = 8 および lenA = 3 なので、`T = 20 // 8 = 2`。 次のように、合計 ≤ 2 で最適な列間隔を選択できます。`[2]`または`[3]`または`[4]`、 lenB = 1 となります。積は 3 です。 

行間隔の場合`[1, 3]`、 sumA = 4 および lenA = 2 なので、`T = 5`。 現在の列間隔`[2,3]`は合計が 3、長さが 2 の場合に有効で、積は 4 になります。 

最良の組み合わせは、積の制約を尊重しながら両方の寸法が適度に大きい場合に達成されます。 

このトレースは、許容領域の増加により、実行可能な列の選択肢がどのように非線形的に拡大するかを示しています。

 ## 特殊なケース

 すべての行の合計が次の値を超える場合、まれなケースが発生します。`S`。 そのような状況では、あらゆる`T`がゼロになり、列間隔は無効になります。 二分探索では次の結果が返されるため、アルゴリズムがこれを処理します。`0`となり、製品のアップデートはトリガーされません。 

単一行間隔のみが有効な場合には、別のケースが発生します。 たとえば、次の場合`A = [100, 1, 100]`そして`S = 10`、中央の行のみが有効な構成に寄与します。 ループは当然ながら各行間隔を個別に評価し、次の行間隔のみを評価します。`sumA = 1`ゼロ以外の列結果が生成されます。 

3 番目のケースは、1 つの非常に小さな行セグメントが不釣り合いに大きな列セグメントのロックを解除する不均等な分布を伴います。 すべての行間隔は貪欲に拡張されるのではなく明示的に列挙されるため、アルゴリズムはこれらの非対称の最適な構造を見逃すことはありません。
