 ## 解決策
 ## 問題の理解

 バイナリの数を数えるように求められます$n \times n$グリッドはローカル制限の下に存在します。各セルは 0 または 1 のいずれかであり、辺を共有する隣接するセルに 2 つの 1 を配置することは禁止されています。 斜めの隣接性は関係ありません。上下左右の隣接性のみが重要です。 

したがって、このタスクは純粋に組み合わせによるものです。$2^{n^2}$バイナリ行列では、2 つの 1 が水平方向または垂直方向に接していないものをカウントする必要があります。 

入力は単一の整数です$n \le 10$。 出力は有効なグリッドの数を法的に表したものです。$10^9+7$。 

小さな制約が主信号です。 グリッドには最大 100 個のセルがありますが、状態を行ごとに圧縮すれば、指数関数的なスペースも管理可能です。 すべてのグリッドを直接列挙しようとすると、枝刈りを行ったとしても、最悪の場合、速度が遅すぎる可能性があります。 

いくつかのコーナー状況については、覚えておく価値があります。 

いつ$n = 1$、すべての単一細胞が分離されているため、両方`0`そして`1`は有効で、答え 2 が得られます。隣接関係を誤って斜め方向にも解釈したり、グローバルに最大 1 つの 1 を想定したりすると、これを誤って 1 に減らすことになります。 

いつ$n = 2$、合計 16 個のグリッドがあります。 この制約は、隣接する 2 つの 1 がエッジを共有する構成のみを削除しますが、複数の孤立した 1 は引き続き許可されます。 正解は 7 です。これは、構造が自明ではなく、独立したセルのカウントだけではないことをすでに示しています。 

重要な点は、制約がローカルであるにもかかわらず、グリッド全体にわたって相互作用することです。 これが、単純なセルごとの独立性を無効にする理由です。 

## アプローチ

 直接的なアプローチは、可能な限りすべてのことを試すことです$n \times n$バイナリ行列を作成し、隣接するすべてのペアをスキャンして検証します。 各グリッドチェックのコスト$O(n^2)$、そして、あります$2^{n^2}$グリッド。 と$n = 10$、これは次のようになります$2^{100}$、それは完全に不可能です。 

構造を活用する必要があります。 この制限は近隣にのみ関係します。つまり、対話はローカルであり、段階的に処理できます。 グリッドを処理する自然な方法は行ごとです。 行が固定されると、その内部有効性は行内の隣接するセルのみに依存し、前の行との互換性は垂直方向の隣接性のみに依存します。 

これは、各行を長さのビットマスクとして扱うという古典的なプロファイル動的プログラミングのアイデアにつながります。$n$。 マスクは、水平方向に連続する 1 がない場合に有効です。 この場合、連続する 2 つの行は、同じ列に 1 を配置しない限り互換性があります。これは、垂直方向の隣接関係の競合が発生するためです。 

したがって、個々のセルについて推論するのではなく、有効な行の状態とそれらの間の遷移について推論します。 グリッドは次のシーケンスになります。$n$行マスクを使用すると、問題は互換性制約の下で有効なシーケンスをカウントすることに帰着します。 

以来$n \le 10$、有効な行マスクの数は最大でもフィボナッチ サイズです。$n$、およそ 1000 ですが、これは簡単に管理できます。 マスク間の遷移は事前に計算でき、行にわたる単純な DP で問題を解決します。

 ## アルゴリズムのチュートリアル

 各行をビットマスクに圧縮し、隣接する 1 を含まないマスクのみを許可します。 次に、積み重ねる方法を数えます$n$そういった列。 

1. 0 から 0 までのすべてのマスクを列挙します。$2^n - 1$。 隣接する 2 つのビットが 1 でないビットのみを保持します。これにより、各行が個別に水平制約を満たすことが保証されます。 
2. 有効なマスクのすべてのペア間の互換性を事前計算します。 2 つのマスクは、どの列にも 1 を共有しない場合、互換性があります。 これにより、連続する行間に 1 が垂直に隣接しないことが保証されます。 
3. 以下の場合に動的プログラミングを使用します。`dp[i][mask]`最初のものを構築する方法の数を表します`i`構成で終わる行`mask`。 
4.初期化`dp[1][mask] = 1`最初の行には競合する前の行がないため、すべての有効なマスクが対象となります。 
5. 後続の各行について`i`、以前のすべてのマスクからの移行`prev`すべての有効な現在のマスクに`cur`互換性がある場合。 カウントを蓄積する`dp[i][cur]`。 
6. すべての値を合計します。`dp[n][mask]`最終的な答えを得るためにすべての有効なマスクを調べます。 

### なぜ効果があるのか

 DP 状態は、過去に関する必要な情報を正確に取得します。行をリンクする唯一の制約は、前の行のみに依存する垂直方向の隣接性です。 以前の行は直前の行を介する場合を除いて現在の行と対話できないため、より深い履歴は無関係です。 これにより、行マスクに対してクリーンなマルコフ プロパティが得られ、一意のマスク シーケンスを通じてすべての有効なグリッドが正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())

    valid = []
    for mask in range(1 << n):
        if mask & (mask << 1):
            continue
        valid.append(mask)

    m = len(valid)

    compat = [[False] * m for _ in range(m)]
    for i in range(m):
        for j in range(m):
            if valid[i] & valid[j] == 0:
                compat[i][j] = True

    dp = [1] * m  # row 1

    for _ in range(1, n):
        ndp = [0] * m
        for i in range(m):
            if dp[i] == 0:
                continue
            for j in range(m):
                if compat[i][j]:
                    ndp[j] = (ndp[j] + dp[i]) % MOD
        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```コードは、水平隣接ルールを満たすすべての行構成を生成することから始まります。 条件`mask & (mask << 1)`シフトおよび交差することにより、行内の隣接する 1 を検出します。 

互換性テーブルは垂直方向の安全性をエンコードしています。2 つのマスクは、どの列でも重なり合わない場合、正確に互換性があります。 これは、別の 1 の上に積み重ねられたセルは 1 になることができないという制約を直接強制します。 

各行は前の行のみに依存するため、DP は 1 次元に圧縮されます。 更新ステップでは、以前のすべての有効な行構成からすべての現在の有効な構成への遷移が蓄積されます。 

最終的な合計は、すべての行を処理した後のすべての可能な終了を集計します。

 ## 特殊なケース

 のために$n = 1$の場合、DP は 2 つの有効なマスクを持つ 1 つの行に縮小されます。 遷移フェーズは完全にスキップされ、初期状態の合計は 2 となり、考えられる両方の単一セル グリッドと一致します。 

のために$n = 2$、すべての行マスクは、列の重複を通じてのみ他のすべての行マスクと相互作用します。 DP は、行 1 列 0 および行 2 列 1 に 1 を配置するような構成 (有効なまま) と、互換性によって除外される垂直方向に整列した 1 を積み重ねた構成とを正しく区別します。
