 ## 解決策
 ## 問題の理解

 2 つの評価システムが与えられています。1 つは 1 から n までのスコアを使用し、もう 1 つは 1 から m までのスコアを使用します。 最初のシステムの一部のスコアは 2 番目のシステムの一部のスコアと同等であると考えられますが、この問題では任意のペアは得られません。 代わりに、サンプルによって暗示される構造は、等価性が 2 つのシステム間の均一なスケーリングのように動作するということです。つまり、同じ相対的な「品質レベル」に対応する値は、最大値の同じ部分を表す場合には常に整列します。 

この観点から、両方が同じ正規化された位置を表す場合、m スケールのスコア x は、n スケールのあるスコア y に対応します (x / m = y / n を意味します)。 2 つのスケール間の共有分数グリッドは最大公約数によって決定されるため、このようなペアは、x が m / gcd(n, m) の倍数である場合に正確に存在します。 

このタスクは、[1, m] の範囲内の整数 x がこの共有グリッドに実際にいくつ現れるかをカウントすることに帰着します。 

制約は n と m の両方で 10^18 に達するため、値を反復したり配列を構築したりする解決策は不可能です。 O(min(n, m)) ですら大きすぎます。 解決策は、問題を大きな整数に対する一定数の算術演算に削減する必要があります。 

n と m が互いに素である場合、微妙なエッジケースが発生します。 この場合、唯一の共有正規化点は分数形式の端点 0 と 1 であり、これは m スケールの値 m 自体にのみ対応します。 たとえば、n = 3 および m = 4 の場合、一致する値は 1 つだけです。 

もう 1 つのエッジ ケースは、n = m の場合です。 この場合、すべてのスコアはそれ自体と一致するため、答えは m になります。 「適切にマップされた内部ポイント」のみをカウントする単純な解釈では、誤ってエンドポイントを見逃してしまいます。 

## アプローチ

 同値を直接シミュレートしようとすると、[1, m] 内のすべての x について、x / m = y / n となるような y が [1, n] に存在するかどうかをチェックする必要があります。 この条件をチェックするには、合理的に削減するか、すべての候補をスキャンする必要があります。 10^18 までの m を 1 回通過することさえ不可能です。 

重要な観察は、分数 x / m と y / n が等しいということは、相互乗算 (x * n = y * m) を意味するということです。 有効なペアは、両方のグリッド上の共有有理点に対応します。 このようなすべての点のセットは、まさに n と m の最小公倍数構造によって生成された格子です。 

連続して一致する x 値間の間隔は m / gcd(n, m) です。 これは、等式を x = k * (m / gcd(n, m)) として書き直すことで得られます。ここで、k の範囲は、対応する y が [1, n] 内に収まるようにすべての整数に及びます。 k の範囲は 1 から gcd(n, m) までであるため、x の有効な値は正確に gcd(n, m) になります。 

したがって、問題は、m スケール内にいくつの等価点が存在するかを直接カウントする gcd(n, m) の計算に帰着します。

 | --- | --- | --- | --- |
 | [1, m] の x の総当たり列挙 | O(m) | お(1) | 遅すぎる |
 | gcd 構造を使用した最適な | O(log min(n, m)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの整数 n と m を読み取ります。 これらは、比例調整を通じて比較する 2 つの離散スケールを定義します。 
2. g = gcd(n, m) を計算します。 これにより、2 つのスケール間の比例的等価性が維持される最大ステップ サイズが取得されます。 
3. m スケールの有効なマッチング スコアはそれぞれ、k * (m / g) の形式でなければならないことを認識します。ここで、k は 1 から g までの整数です。 
4. 有効なスコアの数はちょうど g であると結論付けます。 

この列挙が機能する理由は、n と m の両方を gcd で割ると、分数 n/m が最小項に減らされるためです。 2 つのシーケンス間のアラインメント ポイントは、この短縮されたステップの倍数で正確に発生します。 

### なぜ効果があるのか

有効な対応関係はすべて x / m = y / n を満たします。 並べ替えると x * n = y * m が得られます。 g = gcd(n, m) とし、n = g * n' および m = g * m' と書きます。ここで、n' と m' は互いに素です。 方程式は x * n' = y * m' になります。 n' と m' には共通の因数がないため、x は m' で割り切れる必要があり、y は n' で割り切れる必要があります。 これにより、ある整数 k に対して x = k * m' および y = k * n' が強制されます。 制約 1 ≤ x ≤ m および 1 ≤ y ≤ n は、k の範囲が正確に 1 から g であり、g 個の有効な値を生成することを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

n, m = map(int, input().split())
print(gcd(n, m))
```ソリューション全体は、最大公約数を計算することに基づいています。 数学モジュールの実装では、最大 10^18 の値に適した効率的なユークリッド アルゴリズムが使用されます。 

唯一の微妙な点は、追加の正規化や境界処理が必要ないことです。 gcd カウントでは、n に対応する最大スコア m を含む完全なアライメント ポイントがすでに考慮されているため、両方のエンドポイントが暗黙的に含まれます。 

## 実用的な例

 ### 例 1: n = 5、m = 10

 g = gcd(5, 10) = 5 を計算します。 

| ステップ | 値 |
 | --- | --- |
 | n | 5 |
 | メートル | 10 |
 | gcd(n,m) | 5 |
 | 答え | 5 |

 5 つの一致点は分数 1/5、2/5、3/5、4/5、および 5/5 に対応し、10 スケールの 2、4、6、8、および 10 にマッピングされます。 これにより、すべての等間隔の比例レベルがカウントされることが確認されます。 

### 例 2: n = 3、m = 4

 g = gcd(3, 4) = 1 を計算します。 

| ステップ | 値 |
 | --- | --- |
 | n | 3 |
 | メートル | 4 |
 | gcd(n,m) | 1 |
 | 答え | 1 |

 エンドポイント 4 のみが有効な共有分数 (1) に対応するため、m スケールにはスコアが 1 つだけ存在します。

## テストケース```python
import sys, io
from math import gcd

def solve():
    n, m = map(int, sys.stdin.readline().split())
    print(gcd(n, m))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_stdout
    sys.stdin = old_stdin
    return out.getvalue().strip()

assert run("5 10") == "5"
assert run("1 1") == "1"
assert run("3 4") == "1"
assert run("6 9") == "3"
assert run("10 1000000000000000000") == "10"
assert run("7 13") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 10 | 5 | 基本的な比例配置 |
 | 1 1 | 1 | 最小限のケース |
 | 3 4 | 1 | コプライムケース |
 | 6 9 | 3 | 自明ではない gcd |
 | 10 10^18 | 10 | 大きな不均衡ストレス |

 ## 特殊なケース

 n = m の場合、gcd は n に等しいため、答えは n になります。 たとえば、入力 7 7 は gcd(7, 7) = 7 を生成します。これは、m スケールの 7 つのスコアすべてが n スケールの同一の位置に直接対応することを意味します。 

n と m が互いに素である場合 (7 と 13 など)、gcd は 1 です。アルゴリズムは 1 を返し、端点のみが正規化空間内で整列していることを反映します。 ユークリッド アルゴリズムでは自然にペアがこのケースに帰着するため、計算には特別な処理は必要ありません。 

10 や 10^18 など、一方の値が非常に大きく、もう一方の値が小さい場合でも、gcd は完全な構造をキャプチャします。 ユークリッド アルゴリズムは、10 を法とする 10^18 をすぐに縮小し、gcd 10 を残します。
