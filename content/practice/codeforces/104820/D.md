 ## 解決策
 ## 問題の理解

 シーケンスは 1 桁の文字列から始まり、前の文字列を取得し、現在のインデックスの 10 進表現を追加し、前の文字列を再度追加することを繰り返して増加します。 したがって、各ステップでは、中央に数字が挿入されて前のコンテンツが 2 倍になります。 

これらの文字列を構築するように求められるわけではありません。 タスクは、位置 n の最終文字列に含まれる文字数を決定することだけです。 

重要な点は、数値ではなく、数値の長さのみが重要であるということです。 i を挿入すると、i の桁数が正確に挿入されます。 したがって、構造は純粋に組み合わせです。各ステージは以前の長さと桁数にのみ依存します。 

入力 n は 10^9 まで大きくすることができます。 これにより、1 から n までのすべてのインデックスを反復するアプローチは即座に除外されます。 O(n) でさえ実現可能な限界をはるかに超えており、対数係数が極端に小さく定数が自明でない限り、O(n log n) でさえ思考が遅すぎます。 実行可能なソリューションでは、各ステップをシミュレートせずに答えを計算する必要があります。 

単純な再帰的展開では文字列が 2 倍になることを繰り返し、時間とメモリが指数関数的に増大し、n が 30 程度であってもすぐにメモリがオーバーフローします。 

長さのみを n まで繰り返し計算しようとすると、より微妙な故障モードが表示されます。 それさえも不可能です。n 自体が大きすぎるため、2 から n までの i に対するインデックスごとのループは時間内に終了しません。 

## アプローチ

 最初の単純化は、文字列を完全に忘れて、その長さのみを追跡することです。 F_i の長さを L_i とします。 構造から、各 F_i は F_{i-1}、次に i の 10 進表現、そして再び F_{i-1} で構成されます。 これは直接的に再発をもたらします。 

ブルートフォース再帰は簡単です。 L_1 = 1 から始めて、L_i = 2 * L_{i-1} + d(i) を計算します。ここで、d(i) は i の桁数です。 これは正しく、導出も簡単です。 ただし、これを n まで計算するには、すべての i を反復する必要がありますが、n が 10^9 までの場合は不可能です。 

重要な構造的問題は、L_i が繰り返しの 2 倍化を通じて以前のすべての値に依存することです。 漸化式を拡張すると、先に進むにつれて、前の桁の寄与が繰り返し 2 倍になります。 これは、繰り返しを繰り返すのではなく、繰り返しを展開することを示唆しています。 

漸化式を展開すると、各 d(i) が n からの距離に応じて 2 のべき乗で乗算されることがわかります。 これにより、問題は 2 から n までのすべての i にわたる重み付けされた合計に変換されます。ここで、重みは 2^{n-i} です。 これにより、問題はインデックスに関する動的計画法から、指数関数的な重みを伴う算術範囲にわたる合計に変換されます。 

問題は、すべての値を反復せずに i にわたる寄与を合計することに移ります。 d(i) は [1..9]、[10..99]、[100..999] のような区間にわたって一定であるため、範囲 [1..n] を桁長のブロックに分割できます。 各ブロック内で、2^{n-i} に定数を乗算した形式の項を合計する必要があります。 

これは 2^n を因数分解した後の等比数列になります。 残りの合計には 2^{-i} が含まれ、比率 1/2 で減少する等比数列を形成します。 したがって、各ブロックは累乗剰余を使用して O(1) で評価できます。

 ## アルゴリズムのチュートリアル

 まず、1 から n まで反復せずに評価できるように繰り返しを書き直します。

1. L_n を最終文字列の長さとして定義します。 L_1 = 1 から開始します。シーケンスはそこから完全に決定されるため、これが唯一の基本値です。 
2. 繰り返しを 1 回展開します。各ステップで前の文字列が 2 倍になり、d(i) が追加されます。 展開を繰り返すと、繰り越された回数に応じて、以前のすべての寄与が 2 のべき乗で乗算されることがわかります。 
3. この展開から、結果を次のように表現します。 

L_n = 2^{n-1} + sum_{i=2..n} d(i) * 2^{n-i}。 

最初の項は、すべてのレベルで複製される最初の元の 1 文字に対応します。 
4. 合計部分から 2^n を因数分解し、合計を次のように書き換えます。 

L_n = 2^{n-1} + 2^n * sum_{i=2..n} d(i) * 2^{-i}。 

これにより、i に対するすべての依存関係が 1/2 乗に分離されます。 
5. inv2 = 2^{-1} mod M を定義します。すると、2^{-i} は inv2^i になります。 問題は、inv2 乗の加重和を計算することに帰着します。 

d(i) * inv2^i の合計。 
6. 区間 [2..n] を、d(i) が定数であるブロックに分割します。 各ブロックは、[10^{k-1}, 10^k - 1] など、n で切り捨てられた同じ桁長 k の数値に対応します。 
7. 固定ブロック [l..r] について、等比級数を使用して sum_{i=l..r} inv2^i を計算します。 最初の項は inv2^1 で、比率は inv2 です。 この合計は、有限等比数列の標準的な閉じた形式を使用して評価できます。 
8. ブロック合計に k (桁長) を乗算し、それを合計加重合計に累積します。 
9. すべてを結合します。加重合計に 2^n を乗算し、2^{n-1} を加算し、結果のモジュロ 1e9+7 を返します。 

### なぜ効果があるのか

 正確さは、挿入された各数字が再帰的 2 倍構造を通じてどのように伝播するかを追跡することで得られます。 シーケンス F_i の各要素は、作成後に以降のすべての文字列に 1 ステップにつき 2 回出現します。これにより、n までの距離に応じて 2 のべき乗の乗算係数が生じます。 再帰展開は、この伝播を正確に捉えます。 これを i の重み付き合計に変換すると、シーケンスを明示的にシミュレートすることなく、この寄与構造が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def digits(x):
    return len(str(x))

n = int(input())

inv2 = (MOD + 1) // 2

pow2_n = modpow(2, n)
inv2_pow = lambda e: modpow(inv2, e)

total = 0
start = 2

max_pow = 1
while max_pow <= n:
    max_pow *= 10

cur = 1
while cur <= n:
    l = cur
    r = min(n, cur * 10 - 1)
    k = len(str(cur))

    len_seg = r - l + 1

    first = modpow(inv2, l)
    ratio = modpow(inv2, len_seg)

    denom = (1 - inv2) % MOD
    inv_denom = modpow(denom, MOD - 2)

    seg_sum = first * (1 - ratio) % MOD
    seg_sum = seg_sum * inv_denom % MOD

    total = (total + k * seg_sum) % MOD

    cur *= 10

ans = (modpow(2, n - 1) + pow2_n * total) % MOD
print(ans)
```実装は閉じた形式の導出に直接従います。 指数は n まで大きくなるため、べき乗ヘルパーはすべてのべき乗モジュラーに使用されます。 数字ブロックのループでは、同じ桁長の数値が連続した範囲を形成するという事実を利用しているため、各ブロックは単一の等比級数項に寄与します。 

微妙な点は等比級数の分母です。 inv2 = 1/2 であるため、係数 (1 - inv2) はモジュール的に可逆であり、その逆数を使用して合計を正規化します。 

最後の式は、初期寄与 2^{n-1} と、2^n でスケールされた累積された重み付き桁寄与を組み合わせます。 

## 実用的な例

 n = 3 について考えてみましょう。 

私たちは以下のものを持っています:

 L_1 = 1

 L_2 = 2 * 1 + 1 = 3

 L_3 = 2 * 3 + 1 = 7

 アルゴリズムは以下を介して同じことを計算します。 

L_3 = 2^{2} + 2^3 * (d(2)*2^{-2} + d(3)*2^{-3})

 | 私 | d(i) | 2^{-i} | 貢献 |
 | --- | --- | --- | --- |
 | 2 | 1 | 1/4 | 1/4 |
 | 3 | 1 | 1/8 | 1/8 |

 合計は 3/8 なので、次のようになります。 

L_3 = 4 + 8 * 3/8 = 7。 

このトレースは、2 の逆べき乗による重み付けが、各桁が将来の 2 倍化を通じてどのように伝播するかを正しく捉えていることを確認します。 

ここで、n = 4 について考えてみましょう。 

直接計算:

 L_1 = 1

 L_2 = 3

 L_3 = 7

 L_4 = 2 * 7 + 1 = 15

 加重フォーム:

 L_4 = 8 + 16 * (d(2)/4 + d(3)/8 + d(4)/16)

 | 私 | d(i) | 2^{-i} | 貢献 |
 | --- | --- | --- | --- |
 | 2 | 1 | 1/4 | 1/4 |
 | 3 | 1 | 1/8 | 1/8 |
 | 4 | 1 | 1/16 | 1/16 |

 合計は 7/16 となり、次のようになります。 

L_4 = 8 + 16 * 7/16 = 15。 

これにより、複数のステップにわたって導出された式の一貫性が確認されます。

 ## 特殊なケース

 n = 1 の場合、再帰は決して拡張されないため、答えは 1 のままでなければなりません。i に関する合計は 2 から始まり、空の寄与が生成されるため、アルゴリズムはこれを処理します。 基本項 2^{n-1} のみが残り、n = 1 の場合、これは 1 に等しくなります。 

n = 10 の場合、桁長の境界はちょうど 10 で交差します。これは、ブロック構造が 1 桁の数値から 2 桁の数値に変化することを意味します。 等比級数の処理により、各ブロックが独立しており、n で正しく切り捨てられるため、この境界での分割に特別なケースが必要なくなります。 

10^9 などの大きな n の場合、個々の i 値に対する反復は発生しません。 このアルゴリズムは一定数の等比級数項のみを評価し、すべてのべき乗は対数時間で処理されるため、最大入力サイズでもパフォーマンスは安定しています。
