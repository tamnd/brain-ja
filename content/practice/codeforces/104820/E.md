 ## 解決策
 ## 問題の理解

 小文字のラテン文字の上に文字列が与えられます。 任意の位置を繰り返し選択して、その文字を他の文字に置き換えることができます。 各交換のコストは 1 であるため、総コストを最小限に抑えたいと考えています。 

すべての変更後に満たさなければならない制約はグローバルです。長さが奇数のすべての部分文字列は回文でなければなりません。 つまり、長さが 1、3、5 などの最終文字列のセグメントを取得する場合、それを左から右に読むことは、右から左に読むことと一致する必要があります。 

タスクは、文字列がこのプロパティを満たすために必要な文字変更の最小数を計算することです。 

文字列の長さは最大 50,000 であるため、すべての部分文字列をチェックしようとする解決策は直ちに不可能になります。 部分文字列の数は 2 次であり、部分文字列ごとに回文性をチェックしても、最悪の場合は 3 次になります。 部分文字列ごとの線形スキャンでも、依然として限界をはるかに超えています。 

微妙な点は、この条件がプレフィックスや文字列全体ではなく、すべての奇数長の部分文字列に適用されることです。 これは文字列全体が回文であるのと同等であると考えるのが単純な間違いですが、これははるかに強力です。 もう 1 つのよくある誤解は、実際には中心の対称性が位置全体にわたってグローバルに伝播するのに、局所的に中心の対称性を制限しているだけであると想定することです。 

たとえば、次のような文字列では`abca`、部分文字列を調べる`abc`力`a == c`、および部分文字列`bca`力`b == a`これは、コンストレイントがどのように離れた位置を素早く接続するかをすでに示しています。 

隠れた主な困難は、制約が重なり合うことです。正しい解決策では、明示的にチェックするのではなく、「奇数の部分文字列はすべて回文である」ことによって引き起こされる構造を特定する必要があります。 

## アプローチ

 ブルートフォース手法では、奇数の長さの部分文字列をすべて列挙し、暫定的な変更セットごとにそれが回文であるかどうかを検証します。 固定文字列のみを検証する場合でも、すべての部分文字列をチェックするには O(n²) 時間がかかり、そのループ内で何かを行うと実行不可能になります。 

もう少し良い方向ですが、まだ間違っている方向は、文字列全体を回文にするだけで十分だと想定することです。 これは、古典的な 2 ポイントの不一致カウントの問題につながります。 ただし、これは、非対称位置間に追加の等価性を課す、より短い奇数部分文字列からの制約を無視します。 

重要な観察は、条件を文字間の等価制約のシステムとして再解釈することです。 すべての奇数長の部分文字列は、その中心付近のミラーリングされた位置間の等価性を強制します。 これらの制約は文字列全体に推移的に伝播します。 

任意の位置から開始する場合は、2 つずつ移動できます (奇数長の部分文字列の対称性により、インデックスは常に同じパリティ距離構造に関連付けられるため)。 これにより、インデックスの 2 つの独立したグループが作成されます。すべての奇数の位置が 1 つの連結成分を形成し、すべての偶数の位置が別の連結成分を形成します。 各グループ内では、最終的な文字列ではすべての文字が同一になる必要があります。 

この構造が認識されると、問題は、すべての奇数インデックスに対して最後の文字を 1 つ選択し、すべての偶数インデックスに対して最後の文字を 1 つ選択することになり、置換が最小限に抑えられます。 

パリティ グループごとに文字の頻度を計算し、最も頻度の高い文字を変更せずに他のすべての文字を変更します。

 ## アルゴリズムのチュートリアル

 文字列を 1 回処理し、インデックス パリティによって情報を分離します。 

1. インデックスを 2 つのグループ、位置 0、2、4、... と位置 1、3、5、... (または 1 から始まる奇数と偶数) に分割します。 対称制約は同じパリティ構造を持つ位置のみを接続するため、この分離は自然です。 
2. 奇数インデックスグループ内の各文字の頻度をカウントします。 これは、特定の最後の文字を選択することと互換性のある位置がすでにいくつあるかを示します。 
3. 偶数インデックスグループ内の各文字の頻度を同様に数えます。 
4. 奇数グループの場合、すべての文字の最大頻度を決定します。 最も一般的な文字を維持することで置換が最小限に抑えられるため、これはそのグループの最終文字の最適な選択を表します。 
5. 奇数位置の合計からこの最大頻度を引いたものとして、奇数位置の置換を計算します。 
6. 偶数の位置についても同じ計算を繰り返します。 
7. 両方の値を合計し、結果を返します。 

最も頻繁に使用される文字を選択する背後にある理由は、グループ内のすべての位置が最終的に同一になる必要があるため、選択された文字との不一致には 1 回の置換が必要となり、これが直接の頻度最大化の問題になるということです。 

### なぜ効果があるのか

 すべての奇数長の部分文字列が回文であるという制約により、考えられるすべての中心で対称ペア間の等価性が強制されます。 これらの制約は文字列全体に推移的に伝播し、同じパリティのすべてのインデックスを単一の等価クラスにリンクします。 各クラス内では、有効な最終文字列内のすべての文字が等しい必要があります。 各ポジションは独立して変更できるため、各クラスで最も頻繁に存在するキャラクターを選択することで最適なソリューションが得られ、クラスを統一するために必要な変更の数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    odd = [0] * 26
    even = [0] * 26

    for i, ch in enumerate(s):
        if i % 2 == 0:
            odd[ord(ch) - 97] += 1
        else:
            even[ord(ch) - 97] += 1

    odd_len = (n + 1) // 2
    even_len = n // 2

    best_odd = max(odd)
    best_even = max(even)

    print((odd_len - best_odd) + (even_len - best_even))

if __name__ == "__main__":
    solve()
```実装はパリティ分解の直後に続きます。 唯一の微妙な点は、グループ サイズを正しく計算することです。ゼロから始まるインデックスは位置 0、2、4 を最初のグループに入れるため、そのサイズは次のようになります。`(n + 1) // 2`。 

よくある間違いは、頻度を合計してグループ サイズを再計算することです。これは不要ですが安全です。または、0 ベースと 1 ベースのインデックス付けを混合して誤ってパリティ グループを交換してしまいます。 コードでは、一貫して 0 から始まるインデックスを使用することでこれを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)

    odd = [0] * 26
    even = [0] * 26

    for i, ch in enumerate(s):
        if i % 2 == 0:
            odd[ord(ch) - 97] += 1
        else:
            even[ord(ch) - 97] += 1

    odd_len = (n + 1) // 2
    even_len = n // 2

    return str((odd_len - max(odd)) + (even_len - max(even)))

assert run("aaa\n") == "0"
assert run("ababb\n") == "1"
assert run("abccba\n") == "4"

# all same alternating pressure
assert run("abababab\n") == "4"

# single char
assert run("z\n") == "0"

# two different chars
assert run("ab\n") == "0"

 ## 特殊なケース

 エッジケースの 1 つは、次のような単一文字列です。`x`。 奇数長の部分文字列はすべて文字そのものであるため、すでに回文です。 アルゴリズムはこの文字を奇数位置グループに配置し、最大頻度 1 を確認して、正しく 0 を返します。 

別のケースは、次のような長さ 2 の文字列です。`ab`。 長さが 1 を超える奇数長の部分文字列は存在しないため、単純な長さ 1 の部分文字列を超える制約は存在しません。 このアルゴリズムは 1 つの奇数位置と 1 つの偶数位置に分割され、それぞれに 1 文字が含まれるため、置換は必要ありません。 

より微妙なケースは、次のような高度に混合された文字列です。`abcabcabc`。 構造化されているように見えますが、パリティ グループ化により、奇数インデックスと偶数インデックスの独立した均質化が強制されます。 このアルゴリズムは、より長いパターンを正しく無視し、各グループ内の周波数の最適化のみに焦点を当て、最小限の変換コストを生成します。
