 ## 問題の理解

 私たちは与えられています$n$ボールの色。 各色ごとに$i$、 がある$a_i$箱の中にはその色の見分けのつかないボールが入っています。 要件配列もあります$b$、 どこ$b_i$カラーボールの数を教えてください$i$私たちは保証したいと思っています。 

私たちは絵を描きます$x$見ずにボックスからボールを​​取り出します。 引き分けは、どちらであっても確実に行わなければならないという意味で敵対的です。$x$ボールが取られると、その中に少なくとも少なくとも持っている可能性が常にあります$b_i$あらゆる色のボール$i$。 私たちはそのような最小のものを望んでいます$x$。 

同様に、すべての可能な選択が一致するように、マルチセット描画の最小プレフィックス サイズを検索しています。$x$ボールには必ず少なくとも次のものが含まれます$b_i$各色のボール。 別の見方としては、「悪い」選択、つまり、$x$少なくとも 1 つの要件に違反するボール$b_i$。 

重要な問題は、故障モードが 1 つの色に局所的ではないことです。 選択を誤ると、少数の色に集中して要件を満たせなくなる可能性があります。 

制約により許可されるのは、$n$まで$10^5$したがって、どのような解も線形または線形に近いものでなければなりません。 アン$O(n^2)$または$O(n \log n)$重い定数を使用することは、二次関数の動作を隠す場合にのみ危険です。 すべての価値観があるので、$a_i, b_i$まで可能です$10^9$、算術演算は 64 ビット整数で実行する必要があります。 

増加の素朴なシミュレーション$x$実現可能性をチェックするには、それぞれの最悪ケースの分布を再計算する必要があります。$x$が遅すぎます。 

微妙なエッジケースが現れるのは、$b_i > a_i$。 この場合、すべてのボールを取得したとしても要件は不可能であるため、答えは自明のことながらボールの総数になります。 たとえば、次の場合$a = [2,2]$そして$b = [3,1]$、色 1 を満たす選択は存在しないため、意味のある唯一の答えは次のとおりです。$x = 4$、すべてを取得しても論理的に失敗する必要があるため、「実行可能性を保証する最小 x」定義を満たすと、フルセットサイズに縮退します。 

もう 1 つの特殊なケースは、すべてが$b_i = 1$。 次に、各色のボールが少なくとも 1 つだけ必要なので、答えはボールの合計数になります。$\sum a_i$なぜなら、選択範囲が小さいと、一部の色が完全に欠けてしまう可能性があるからです。 

## アプローチ

 強引な解釈で各候補者について推論しようとする$x$。 固定の場合$x$のすべての選択かどうかを尋ねます。$x$ボールはすべての制約を満たさなければなりません。 これは、次の選択肢が存在するかどうかを尋ねることと同じです。$x$少なくとも 1 つの制約に違反するボール。 そのような選択が存在する場合、$x$では不十分です。 

最悪の場合の選択を構築するために、予算を「消費」しようとします。$x$要件を満たさずに選択しやすい色を選択します。 候補者ごとに$x$、敵が複数の色にピックを分配することをシミュレートし、実現可能性を繰り返しテストします。 これはすぐに組み合わせになります。$x$、すべてのサイズ分布にわたる最適化を効果的に解決しています。$x$、すでに費用がかかります$O(n)$あるいはさらに悪いことに、$O(n^2)$全体。 

重要な観察は、実現可能性は、必要な最小値を超えてどれだけの「空き領域」が存在するかによってのみ決まるということです。 少なくとも保証したいのであれば$b_i$色の$i$の場合、「悪い」構成とは、少なくとも 1 つの色の要件を満たさない構成です。 選んだカラーに対して$i$、最悪の敵の戦略は、他の色のボールをすべて取り、ボールだけを取り出すことです。$b_i - 1$色から$i$。 要件を満たしながらも最大数のボールが生成されます$i$。 

ということで、各色ごとに$i$、要件に違反しながらも取得できるボールの最大数。$i$は：$$(a_i - (b_i - 1)) + \sum_{j \ne i} a_j$$これは次のように単純化されます。$$\sum a_j - (b_i - 1)$$これにより、「悪い」選択に対する一連の上限が決まります。 どれでも$x$これらの境界をすべて超えると、すべての選択がすべての要件を満たすように強制されます。 したがって、答えは次のようになります。$$\min x \text{ such that } x > \sum a_j - (b_i - 1) \ \forall i$$これは次のように単純化されます。$$x = \max_i \left(\sum a_j - (b_i - 1)\right) + 1$$

$$x = \sum a_j - \min_i (b_i - 1) + 1$$よりきれいに書き直す:$$x = \sum a_j - \min_i b_i + 2$$ただし、off-by-one ロジックを慎重に調整する必要があります。 より明確な導出は、色ごとに最大の「不正な描画サイズ」を計算することです。$$S_i = \sum a_j - (b_i - 1)$$それから一番小さいのは$x$成功を保証するものは次のとおりです。$$x = \min \{ x : x > \max_i S_i \} = \max_i S_i + 1$$したがって、合計と最小値のみが必要です$b_i$。

 ## アルゴリズムのチュートリアル

 1. ボールの総数を計算します。$S = \sum a_i$。 これは、可能な最大描画サイズを表します。 
2. の最小値を追跡します。$b_i$、呼んでください$m = \min b_i$。 これは、すべての色の中で最も弱い要件です。 
3. 候補の答えを次のように計算します。$x = S - m + 2$。 これは、最小限の要件を可能な限り違反しようとする最悪の場合の構築から来ています。 
4. 結果を最大でクランプします。$S$ボックス内に存在する以上のボールを引き出すことはできないためです。 
5. 最終値を出力します。 

### なぜ効果があるのか

 選択に失敗した場合は、必ず何らかの色が失敗する必要があります$i$、最大でも含まれることを意味します$b_i - 1$その色のボール。 失敗しながら合計サイズを最大化するために、他のすべての色を完全に取り込み、その 1 色のみを制限します。 敵にとって最善の選択は、最小の色を選択することです。$b_i$、失敗しながらも最も多くのボールを取ることができるからです。 最大失敗構成を超えると、すべての選択がすべての要件を満たさなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    total = sum(a)
    min_b = min(b)
    
    ans = total - min_b + 2
    
    if ans > total:
        ans = total
    
    print(ans)

if __name__ == "__main__":
    solve()
```すべての推論は最終的にマルチセット全体のサイズに依存するため、コードは最初にボールの総数を集計します。 次に、最小の要件を見つけます。$b$なぜなら、これは敵対者が失敗するサブセットを構築する最も簡単な方法に相当するからです。 

式`total - min_b + 2`最も望ましい障害シナリオでさえそれを超えると不可能になるしきい値をエンコードします。 最後のクランプにより、利用可能なすべてのボールを超えるボールが出力されないことが保証されます。これは、小さなボールが原因でフォーミュラがオーバーシュートする場合に必要です。$b_i$。
