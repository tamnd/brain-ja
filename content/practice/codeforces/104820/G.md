 ## 解決策
 ## 問題の理解

 3 つの異なる種類のキャンディーを 3 人の友人に配布します。各友人は特定の種類の 1 つだけを受け取ります。 最初の友人はスニッカーズのみ、2 番目の友人はマーズのみ、3 番目の友人はバウンティのみを連れて行きます。 各タイプの利用可能な数量が与えられています: A スニッカーズ、B マーズ、C バウンティ。 

各友達は、好みの種類のキャンディーを少なくとも 1 つ受け取る必要があります。 さらに、受け取るキャンディーの数は、最初の友達から 2 人目へ、そして 2 人目から 3 人目へと厳密に増加する必要があります。 つまり、割り当てられた量を x、y、z と表す場合、x、y、z は x < y < z を満たさなければならず、x ≥ 1、y ≥ 1、z ≥ 1、さらに x ≤ A、y ≤ B、z ≤ C を満たさなければなりません。 

タスクは、これらすべての制約を満たすトリプル (x、y、z) の数を数えることです。 

制約は最大 10^6 であり、考えられるすべてのトリプルの反復が即座に除外されます。 単純な 3 次列挙、さらには 2 次列挙では、最悪の場合、最大 10^18 の反復が生成されますが、これは許容範囲をはるかに超えています。 解決策は、問題を線形スキャンまたは直接組み合わせ計数式のいずれかに減らす必要があります。 

A、B、または C のいずれかが 1 の場合、微妙なエッジ ケースが発生します。たとえば、A = B = C = 1 の場合、可能なトリプルは (1, 1, 1) のみになります。これは厳密な不等式に違反するため、答えは 0 になります。厳密な順序付けを忘れた単純なアプローチでは、これが誤って有効であるとカウントされる可能性があります。 

別のエッジ ケースは、A = 1、B = 2、C = 3 など、容量が小さいが等しくない場合に発生します。有効なトリプル (1、2、3) は 1 つだけであり、「少なくとも 1 つ」と「正確な割り当ての選択」を誤解すると、過大なカウントにつながる可能性があります。 

## アプローチ

 ブルートフォース手法では、x の考えられるすべての値を 1 から A まで、y を 1 から B まで、z を 1 から C まで試して、x < y < z かどうかを確認します。 これはすべての制約を直接強制するため正しいですが、その複雑さは O(ABC) です。 各変数が最大 10^6 の場合、最悪の場合は 10^18 の演算が行われることになりますが、これは実行不可能です。 

重要な観察は、制約が順序にのみ依存し、種類の制限を超えたキャンディーの ID には依存しないということです。 各要素が独立した上限によって制限される場合、厳密に増加するトリプルを事実上カウントしています。 これは、独立したキャップを使用して、1 ≤ x < y < z となるように x、y、z を選択するように再構成できます。 

すべてのトリプルを反復する代わりに、中央の値 y を固定できます。 y が固定されると、x は [1, y−1] 内の任意の整数になりますが、A を超えてはいけないため、x は min(A, y−1) によって制限されます。 同様に、z は [y+1, C] 内になければなりませんが、C を超えてはならず、厳密に y より大きく少なくとも 1 でなければなりません。また、y は z ではなく火星限界から割り当てられるため、B を考慮する必要があります。 実際には z は C にのみ依存します。 

したがって、各 y について、有効な x の選択肢の数は min(A, y−1) で、有効な z の選択肢の数は max(0, C − y) です。 y あたりの寄与は min(A, y−1) × max(0, C − y) になりますが、これは y ≤ B の場合に限られます。 

これにより、問題は y の 1 から B までの単一ループに縮小され、時間は O(B) になります。 B は最大 10^6 であるため、これは許容されます。

 ## アルゴリズムのチュートリアル

1. 1 から B までの y のすべての値を繰り返します。これは 2 番目の友人に与えられるキャンディーの数を表し、火星のキャンディーの制限を確実に尊重します。 
2. 各 y について、x に対して有効な選択肢がいくつ存在するかを計算します。 x は 1 ≤ x < y および x ≤ A を満たす必要があるため、有効範囲は 1 ～ min(A, y−1) です。 y = 1 の場合、この範囲は空であり、正しくは選択肢がゼロになります。 
3. 同じ y に対して、z に対して有効な選択肢がいくつ存在するかを計算します。 z は z > y および z ≤ C を満たす必要があるため、有効な範囲は y+1 から C で、サイズは max(0, C − y) になります。 
4. 有効な x の選択肢の数と有効な z の選択肢の数を掛けます。 これが機能するのは、y が固定されると x と z が独立し、すべての有効なペアが一意のトリプルを形成するためです。 
5. 1 から B までのすべての y にわたるこの寄与を合計します。 

これが機能する理由: すべての有効なトリプル (x、y、z) は、その中間要素 y によって一意に識別されます。 このような y ごとに、アルゴリズムは制約の下で、左側のすべての有効な x の選択肢と右側のすべての有効な z の選択肢を正確にカウントします。 各トリプルにはちょうど 1 つの中間要素があるため、トリプルは 2 回カウントされません。また、両側で境界と順序が厳密に強制されるため、無効なトリプルはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C = map(int, input().split())
    
    ans = 0
    for y in range(1, B + 1):
        x_cnt = min(A, y - 1)
        if x_cnt <= 0:
            continue
        z_cnt = C - y
        if z_cnt <= 0:
            continue
        ans += x_cnt * z_cnt
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、中間要素の列挙戦略に直接従います。 y に対するループにより、有効な 2 番目のフレンドの割り当てのみが考慮されるようになります。 表現`min(A, y - 1)`最初の友人に対して可用性と厳密な順序の両方を強制します。 用語`C - y`C より大きい値は無効となるため、厳密な不等式と報奨金カウントの上限の両方を暗黙的に処理します。 

境界条件に関しては注意が必要です。 y = 1 のとき、`y - 1`がゼロになり、無効な貢献が正しく排除されます。 y = C の場合、`C - y`がゼロになり、無効な z の選択肢がカウントされなくなります。

## 特殊なケース

 When all values are equal to 1, the loop only evaluates y = 1. In this case, x has no valid choices and z also has none, so the contribution is zero, matching the requirement that strict ordering is impossible.

 When A is very small compared to B and C, such as A = 1, B = 10, C = 10, most contributions vanish because x is always zero except when y = 1, but that case also fails because z requires y < z. アルゴリズムは、最小制約と差制約によってこれらのケースを自然にフィルター処理します。 

When C is small relative to B, such as C = 2 and B large, only y = 1 contributes meaningfully, but even then z choices become limited quickly, and the summation correctly collapses to zero or a very small number depending on A.
