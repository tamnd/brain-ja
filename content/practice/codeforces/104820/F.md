 ## 問題の理解

 正確に数値を構築するように求められます`n`数字。各数字はどこからのものでなければなりません`1`に`9`。 数字がありません`0`どこでも許可されるため、完全に正の数字列の範囲で作業します。 

固定長のウィンドウをスライドさせることで「美しさ」を定義する制約を課す`k`数字全体にわたって。 連続するブロックごとに、`k`桁の場合、そのブロック内の桁の合計を計算します。 これらの合計はシーケンスを形成し、そのシーケンスは厳密に左から右に増加する必要があります。 

課題は、そのような数字を数えたり、実現可能性を判断したりすることではありません。 これらの制約の下で、辞書編集的に最大の有効な数値を構築する必要があります。 

重要な緊張関係は、重複するウィンドウに対するローカルな制約と、桁を最大化するというグローバルな目標との間にあります。 

制約`n, k ≤ 100000`これは、どのソリューションも線形時間で実行する必要があることを意味します。 二次関数、特にすべての位置のウィンドウ合計を独立して再計算するものは、すぐに失敗します。 各桁は最大まで影響するので、`k`ウィンドウでは、単純な再計算は直接次のことにつながります。`O(nk)`限界をはるかに超えた行動。 

微妙なエッジケースが現れるのは、`k = 1`。 この場合、各ウィンドウは 1 桁となり、厳密に左から右に桁が増加する条件になります。 そのような最大可能数は単純に次のようになります。`123...9`長さを切り詰めた`n`、重なり合う構造から独立しています。 

もう一つのコーナーケースは、`k = n`。 ウィンドウが 1 つしかないため、比較はまったくできません。 からのすべての桁`1`に`9`は有効なので、最大値は自明です`9`s.

 ## アプローチ

 直接的な総当たりアプローチでは、考えられる長さのすべての数字列を構築しようとします。`n`数字を使う`1`に`9`、スライディング ウィンドウの合計を確認し、最も有効な候補を追跡します。 これは概念的には簡単です。辞書順に生成、検証、比較します。 ただし、そのような文字列の数は`9^n`制約は重なり合うウィンドウに依存するため、早期に枝刈りしても役に立ちません。そのため、部分的な割り当てでは検索空間の大部分が確実に除去されません。 Even checking a single candidate requires`O(nk)`または`O(n)`事前計算に依存して機能するため、全体的なアプローチが完全に実行不可能になります。 

重要な構造的観察は、ウィンドウの合計が連続する位置間で 2 桁だけ異なることです。ウィンドウから移動する場合`[i, i+k-1]`に`[i+1, i+k]`を取り除くと合計が変わります。`a[i]`そして追加`a[i+k]`。 これは制約を意味します```
sum[i] < sum[i+1]
```に翻訳します```
sum[i] - a[i] + a[i+k] > sum[i]
```これを単純化すると```
a[i+k] > a[i]
```これが重要な削減点です。長さの合計を比較するのではなく、`k`、数値のみを比較します`k`別に。 この条件は、固定ステップ サイズにわたる単純な単調性制約になります。 

したがって、問題は、すべての`i`、 我々は持っています`a[i+k] > a[i]`。 これは、次のように区切られた位置間の有向依存関係になります。`k`、剰余クラスのモジュロに基づいて独立したチェーンを形成します。`k`。 

各チェーンを個別に処理して、辞書編集的に最大化しながら、チェーンに沿って厳密に値を増加させることができます。

 ## アルゴリズムのチュートリアル

 私たちはポジションが次のように分かれているという事実を利用します。`k`独立シーケンス:インデックス`i, i+k, i+2k, ...`。 

1. インデックスを分割します。`k`インデックスモジュロに基づくチェーン`k`。 各チェーンは、左から右に厳密に増加する値を満たさなければなりません。 これは、変換された制約から直接得られます。`a[i] < a[i+k]`。 
2. チェーンごとに、チェーンに含まれる要素の数を決定します。 これにより、厳密に増加する桁数を割り当てる必要があることが決まります。 
3. チェーンの長さの場合`len`を割り当てる必要があります`len`～から選択された数字`1`に`9`、厳密に増加します。 辞書編集的に最大化するには、元の文字列の後の位置をできるだけ大きくする必要があるため、各チェーンの後のインデックスに大きな桁を割り当てることを好みます。 
4. 各チェーンをチェーンの順序で左から右に貪欲に構築し、常に完了できる最小の桁を選択します。 これは、割り当てを厳密に増やすために十分なスペースを予約することと同じです。 位置で`t`長い鎖の中で`len`、数字は少なくとも`len - t`9 未満のステップでは、制限された実行可能な間隔が与えられます。 
5. すべてのチェーン値を計算した後、各チェーン値を元のインデックスに戻して完全な数値を再構築します。 

微妙な点は、各チェーンが独立していることです。 異なる残基クラスを結び付ける制約がないため、各チェーンを個別に最適化すると全体的な最適値が得られます。 

### なぜ効果があるのか

 この変換により、重なり合うウィンドウ合計に関する元の条件が、固定距離位置間のローカル制約に減らされます。 これにより、異なる剰余クラス間のすべての結合がモジュロで排除されます。`k`。 各チェーン内では、厳密な不等式により単調増加シーケンスが強制され、実行可能性を尊重しながら、より大きな桁をできるだけ右に押し出すことで辞書編集上の最大値が達成されます。 1 つのチェーン内の選択が他のチェーンに影響を与えることは決してないため、最適なチェーン ソリューションを組み合わせることで全体的な最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    # split indices into k chains
    chains = [[] for _ in range(k)]
    for i in range(n):
        chains[i % k].append(i)
    
    ans = [0] * n
    
    # process each chain independently
    for chain in chains:
        m = len(chain)
        if m == 0:
            continue
        
        # we assign increasing digits; best is to push small digits early
        # and ensure we can still reach up to 9
        start = 1
        for t, idx in enumerate(chain):
            # we need enough room to place strictly increasing digits up to 9
            # remaining positions = m - t
            # so max feasible start is 10 - (m - t)
            val = max(start, 10 - (m - t))
            ans[idx] = val
            start = val + 1
    
    print("".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```実装のビルド`k`同じ剰余モジュロを持つインデックスをグループ化することによる独立したチェーン`k`。 その後、各チェーンが貪欲に埋められます。 変数`start`厳密な増加によって許可される最小値を追跡します。 表現`10 - (m - t)`厳密に増加するシーケンスを完了するのに十分な桁数が最大でも残るように強制します。`9`。 この制約がないと、構築がオーバーシュートして有効な継続がなくなる可能性があります。 

最後に、数字が元の位置に書き込まれ、出力文字列に連結されます。

 ## 特殊なケース

 いつ`k = 1`、すべての位置が独自のチェーンを形成し、配列全体にわたって厳密に増加する必要があります。 アルゴリズムは、次のような方法で実現可能性を強制します。`10 - (m - t)`制約は、桁内に収まる最小の増加シーケンスを生成し、`123...`。 

いつ`k = n`、各チェーンの長さは 1 です。 この式では代入が可能です`9`将来の制約が存在しないため、すべての桁がすぐに`9`。 

いつ`n < k`、ほとんどのチェーンは空または単一要素であり、複数の増加ステップを必要とするチェーンはないため、特別な処理を行わなくても同じロジックは正しく縮退します。
