 ## 解決策
 ## 問題の理解

 「良い」キーまたは「悪い」キーを使用して、それぞれに一定数のコインが入っている一連のチェストを開けるように求められます。 良い鍵の使用には固定量のコインがかかりますが、悪い鍵の使用には無料ですが、開いたチェストを含むすべての未開封のチェストのコインが半分になります（切り捨て）。 すべてのチェストを順番に開けた後、持っているコインの合計を最大化したいと考えています。 

入力により、チェストの数、正常な鍵のコスト、各チェスト内のコインの数がわかります。 出力は、達成可能な最大コインです。 概念的には、チェストごとに、最大の価値を得るために今コインを使うか、将来の利益を減らす無料のアクションを取るかを決定しています。 

制約は重要です。テスト ケースあたり最大 100,000 個のチェスト、最大 10,000 個のテスト ケースです。 の合計額`n`すべてのテスト ケースの数は 100,000 に制限されています。これは、テスト ケースごとの複雑度が O(n) の任意のソリューションが実行可能であることを意味します。 良い/悪いキー選択のすべてのシーケンスを総当りで探索することは指数関数的であり、実行不可能です。なぜなら、20 個のチェストでも 100 万を超えるシーケンスをチェックする必要があるからです。 コインの値とキーのコストは 10^9 に達する可能性があるため、32 ビット整数を使用する言語では整数オーバーフローが懸念されます。 

明らかではないエッジ ケースには、コインがゼロのチェスト、正常なキーのコストがゼロのケース、およびすべてのコインが等しい状況が含まれます。 たとえば、次の場合`n = 2`、`k = 1`、 そして`a = [0, 10]`, 最初の宝箱に良い鍵を使うとコインが無いので無駄です。 最初のチェストに悪いキーを使用すると、2 番目のチェストが半分になるため、選択をスキップするか慎重に調整するのが最適です。 

## アプローチ

 最も簡単なアプローチは総当たり法です。チェストごとに両方のキーの選択を考慮し、結果として得られるコインを再帰的に計算し、最大値を選択します。 これは、考えられるすべてのシーケンスを正しくモデル化しているため機能しますが、各チェストの状態数が 2 倍になるため失敗します。 と`n`10^5 までは O(2^n) 回の演算が必要となり、明らかに非現実的です。 

重要な洞察は、悪いキーは残りのチェストをすべて半分にするため、連続した悪いキーの効果は幾何学的減衰に従うということです。 これにより、問題を逆転させることができます。各組み合わせをシミュレートする代わりに、最後に使用される悪いキーの数を修正し、より大きなチェストに良いキーを貪欲に適用することができます。 最適な戦略は、最後の宝箱のうち何個を悪い鍵で開けるかを決めることです。 不正なキーの数を繰り返すことができます`b`0から`n`そして、結果として得られるコインを計算します: 最後のチェストの前のすべてのチェスト`b`良い鍵を手に入れて、最後に`b`連続した半減期の影響を受けます。 

これが機能するのは、早期に適切なキーを使用することは、将来の半減によって失われたコインを補う場合にのみ価値があるからです。 合計の反復回数は、`n`テスト ケースごとに実行でき、2 の累乗を事前計算する場合、各計算は O(n) または O(b) で実行できます。これは、制約が与えられた場合に十分高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n^2) ナイーブ、O(n) 接頭辞の合計/累乗 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最後のコインの合計をすぐに知るために、コインのプレフィックス合計を最後から計算します。`b`胸。 これにより、半分の値を効率的に計算できます。 
2. 整数除算を使用して 1/2 の累乗を事前計算します (`// 2`) 最大 60 回の反復。それを超えると半分になると、10^9 までの値を持つすべてのチェストがゼロになるためです。 
3. 反復する`b`0から`n`、最後に使用された不正なキーの数を表します。 それぞれについて`b`、適用して集めたコインを計算します`b`最後に連続して悪いキー`b`胸。 式は次の合計です。`floor(a[i] / 2^j)`適切な権限を得るために`j`。 
4. 残りの部分`n - b`チェストには良い鍵が使われています。 合計コストを差し引く`(n - b) * k`これらのチェストから集めたコインの合計から。 
5. すべての値の最大値を追跡します。`b`。 最大値がテスト ケースの答えになります。 

なぜ機能するのか: アルゴリズムは、それぞれに対して次の不変条件を維持します。`b`、すべてのシーケンスは正確に`b`最後に不良キーが考慮されるため、不良キーの最適な配置がすべて探索されることが保証されます。 悪いキーは残りのチェストにのみ影響するため、悪いキーが以前に適用されたシーケンスは、`b`この繰り返しでは。 適切なキーは、影響を受けていない最大のチェストに貪欲に適用されるため、これ以上の合計が達成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        res = 0
        total_good = 0
        # Start with all coins as if all bad keys were used
        suffix = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suffix[i] = suffix[i + 1] + a[i]
        max_coins = 0
        pow2 = 1
        for b in range(n + 1):
            coins_from_bad = 0
            for i in range(n - b, n):
                coins_from_bad += a[i] // pow2
            coins_from_good = suffix[0] - suffix[n - b] - (n - b) * k
            max_coins = max(max_coins, coins_from_good + coins_from_bad)
            pow2 *= 2
        print(max_coins)

solve()
```コードは最初にサフィックスの合計を計算して、グッドキー セクションの合計コインを迅速に評価します。 最後に使用された不良キーの数を反復処理し、整数の除算を繰り返してその影響を計算し、連続する半分をモデル化します。 乗算する`pow2`各ステップで 2 ずつ増やすことで、各半分が正しく計算されるようになります。 

微妙な点としては、整数の除算を慎重に処理して、切り捨てが自動的に行われ、浮動小数点エラーが回避されることが挙げられます。 使用する`suffix`不正なキーの前にチェストの合計への O(1) アクセスを許可し、ループ内で合計を繰り返す必要がなくなります。
