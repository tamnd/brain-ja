 ## 解決策
 ## 問題の理解

 コンテスト システムは、一連の問題解決を時間順に処理します。 入力文字列内の各文字は A から Z までの問題ラベルを表し、各文字が出現するたびに、その時点で何らかのチームがその問題を解決したことを意味します。 解決が行われるたびに、解決チームは風船を 1 つ受け取ります。 さらに、シーケンス全体でその特定の問題が初めて解決された場合、チームは追加の風船を 1 つ獲得します。 

したがって、タスクは文字列の累計を計算することです。すべての文字は少なくとも 1 つのバルーンに寄与し、その文字が最初に出現するときにさらに 1 つのバルーンに寄与します。 

制約は十分に小さいため、文字列に対する直接シミュレーションさえも簡単です。 テスト ケースが最大 100 個、文字列長が最大 50 の場合、操作の総数は最大でも数千回になります。 キャラクターごとに状態を追跡するソリューションは、簡単に十分に高速です。 

主な微妙な点は、「最初の解決」がチームごとやポジションごとではなく、シーケンス全体にわたってグローバルであることを理解していることです。 問題の文字が一度出現すると、それ以降の出現ではバルーンが 1 つだけ表示されるはずです。 

よくある間違いは、毎回プレフィックスをスキャンして解決が「最初」であるかどうかを再計算しようとすることです。 たとえば、入力の場合`BAAAA`誤って各文字を最初から再計算すると、誤って数え間違えたり、ロジックが不必要に複雑になったりする可能性があります。 もう一つの間違いは、文字を繰り返すと毎回 1 つの風船が与えられることを忘れていることです。 

## アプローチ

 ブルートフォース解釈では、文字列内の各位置を処理し、文字ごとに以前のすべての位置をスキャンして、その文字が前に出現したかどうかを確認します。 出現したことがない場合は答えに 2 を追加し、そうでない場合は 1 を追加します。 

これが機能するのは、「最初の出現」の定義が純粋に接頭辞ベースであるためです。 ただし、すべての文字のプレフィックス全体をチェックすると、各ステップが O(n) になり、テスト ケースごとに O(n²) になります。 n が 50 までであればこれでも問題ありませんが、このような小さな制約問題では不必要に複雑になります。 

すべてを単純化する観察は、各問題文字を以前に見たことがあるかどうかだけを覚えていればよいということです。 長さ 26 の固定サイズのブール配列で十分です。 文字が表示されると、その文字にマークが付けられ、その後のすべての文字が最初ではないことが自動的に認識されます。 

これにより、問題全体がテスト ケースごとに 1 回のリニア スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 受け入れられるがやりすぎ |
 | 最適 (セット/配列) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、どの問題文字がすでに出現したかを記録する構造を維持します。 

1. サイズ 26 のブール配列を false に設定して初期化し、問題がまだ解決されていないことを表します。 また、合計バルーンのカウンターをゼロに初期化します。 
2. 文字列内の各文字を順番に繰り返します。 各文字は特定の問題に対応します。 
3. 各文字について、ブール配列を使用する前にその文字が表示されているかどうかを確認します。 表示されていない場合は、これがその問題の最初の解決策であるため、答えに 2 を追加して、表示済みとしてマークします。 
4. すでに表示されている場合は、最初の解決策ではないため、回答に 1 だけを追加します。 
5. すべての文字を処理した後、累計を出力します。 

重要なアイデアは、ブール配列が必要なすべての履歴情報を一定空間にエンコードするため、各決定を一定時間内に行うことができるということです。 

### なぜ効果があるのか

 スキャンのどの時点でも、ブール配列は、現在のインデックスで終わるプレフィックスに少なくとも 1 回出現した一連の問題を正確に表します。 これにより、文字を処理するときに「初めて見た」チェックが定義上正しく行われることが保証されます。つまり、まだマークされていない場合に限り、最初にチェックされます。 マーキングは最初の検出の直後に行われ、決してリセットされないため、スキャン全体を通じて不変式が保持され、すべての決定が問題のルールと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        seen = [False] * 26
        total = 0

        for ch in s:
            idx = ord(ch) - ord('A')
            if not seen[idx]:
                total += 2
                seen[idx] = True
            else:
                total += 1

        print(total)

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースをループし、固定サイズの配列を維持します。`seen`アルファベットの場合。 マッピング`ord(ch) - ord('A')`文字を 0 から 25 のインデックスに変換します。条件分岐はスコアリング ルールを直接エンコードします。未表示の文字は 2 つ、表示されている文字は 1 つになります。 マーキングの順序は概念的に重要ですが、最初の出現を認識した後にのみマーキングするため、正しく処理されます。

## テストケース```python
import sys, io

def solve_io(data: str) -> str:
    sys.stdin = io.StringIO(data)
    import sys as _sys
    from io import StringIO

    input = sys.stdin.readline

    t = int(input())

        n = int(input())

 ## 特殊なケース

 重要なエッジ ケースは、文字列が単一の繰り返し文字で構成されている場合です。 入力用`AAAAA`、アルゴリズムはマークします`A`最初のステップでは表示されていないものとして扱われ、その後のすべての出現はすでに表示されているものとして扱われます。 トレースは、最初のステップが 2 を寄与し、残りの 4 つのステップがそれぞれ 1 を寄与し、6 を生成していることを示しています。 

別のケースは、次のようにすべての文字が異なる場合です。`ABCD`。 各文字は最初に出現した時点では見えないため、すべてのステップで 2 が加算されます。アルゴリズムは各文字を即座にマークし、後の混乱を防ぎ、最終的な結果は 8 になります。 

次のような混合交互パターン`ABACBC`これにより、文字が長い空白の後に再び表示された場合でも、一貫性が保証されます。
