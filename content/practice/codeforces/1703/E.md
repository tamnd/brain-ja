 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$セルにのみ含まれるグリッド`0`または`1`。 任意のセルを反転して変更することができます`0`に`1`または`1`に`0`、各フリップには 1 回の操作が必要です。 

目標は、グリッドを回転させた後、同じように見えるようにすることです。$90^\circ$、$180^\circ$、 または$270^\circ$。 言い換えれば、回転するたびに、元のグリッドとまったく同じグリッドが生成される必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースについて、正方形のグリッドのサイズを受け取り、次にグリッド自体を受け取ります。 回転対称を達成するために必要なセル反転の最小数を出力する必要があります。 

制約は十分に小さいため、すべてのセルを数回検査することは完全に実行可能です。 最大のグリッドには、$100 \times 100 = 10{,}000$セルがあり、テスト ケースは最大 100 個です。 アン$O(n^2)$テスト ケースごとのソリューションは簡単に制限内に収まりますが、フリップの組み合わせに対する指数関数的な検索を伴うものは不可能です。 

難しいのは、どのセルが回転対称によって結合されているかを理解することです。 不用意に実装すると、グリッドを回転させると複数の位置に常に同じ値が含まれるようになったとしても、セルが個別に処理される可能性があります。 

次のグリッドについて考えてみましょう。```
2
10
00
```回転に関係する 4 つの位置は次のとおりです。```
(0,0) -> (0,1) -> (1,1) -> (1,0)
```それらの値は次のとおりです。```
1 0 0 0
```4 つすべてを等しくするには、1 回反転するだけで十分です。 孤独をひっくり返す`1`ゼロが 4 つ与えられます。 ポジションを独立して扱うと、この関係が失われます。 

もう 1 つの微妙なケースは、奇数サイズのグリッドの中央セルです。```
3
000
010
000
```中央のセルは、回転するたびにそれ自体にマップされます。 そのために操作は必要ありません。 すべてのグループを強制的にサイズ 4 にしようとするソリューションでは、誤って余分なフリップをカウントする可能性があります。 

3 番目のよくある間違いは、ローテーション グループを二重にカウントすることです。 例えば：```
3
010
110
010
```隅のセルは 1 つの回転グループを形成し、端の中央のセルは別の回転グループを形成します。 すべてのセルを繰り返し処理し、すべてのグループを繰り返し処理すると、答えは 4 倍大きくなります。 

## アプローチ

 ブルートフォースの観点は、回転によって接続されたすべてのセルのセットを考慮することです。 各セットについて、考えられるすべての最終課題を試して、最も安価なものを選択することができます。 

によるローテーション$90^\circ$位置を送信します$(i,j)$に：$$(j,\ n-1-i)$$これを繰り返し適用すると、最大 4 つの異なる位置が生成されます。$$(i,j) \rightarrow (j,n-1-i) \rightarrow (n-1-i,n-1-j) \rightarrow (n-1-j,i)$$最終的なグリッドが回転後に変更されないようにするには、この軌道内のすべてのセルに同じ値が含まれている必要があります。 

各軌道が独立しているため、強引なアイデアが機能します。 1 つの軌道に属するセルがわかったら、それらがすべて次の軌道に属するかどうかを判断するだけで済みます。`0`あるいは全部になる`1`。 軌道に含まれる場合$k$1 つ、その後:```
cost to make all 0 = k
cost to make all 1 = size - k
```小さい方の値を採用します。 

残る唯一の課題は、同じ軌道の繰り返し処理を避けることです。 すべてのセルから開始すると、サイズ 4 のすべての軌道が 4 回表示されます。 代わりに、各軌道を 1 回だけ処理します。 

重要な観察は、すべての軌道が左上の象限とちょうど 1 回交差するということです。 のみを反復すると、次のようになります。```
0 <= i < n/2
0 <= j < (n+1)/2
```その場合、各ローテーション グループは 1 回だけ訪問されます。 4 つのセルを集めて、その数を数えます。`1`、必要な最小数のフリップを追加します。 

これは問題を単純なものに変換します$O(n^2)$スキャン。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | オービット処理を繰り返すブルートフォース |$O(n^2)$しかし、二重カウントの傾向があります。$O(1)$| 不正解 |
 | 最適な軌道ベースの処理 |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. 左上の代表領域のセルを繰り返し処理します。$$0 \le i < \frac{n}{2}$$

$$0 \le j < \frac{n+1}{2}$$すべての回転軌道はこの領域に 1 回だけ現れます。 
3. 選択した位置ごとに$(i,j)$、回転的に等価な 4 つのセルを計算します。$$(i,j)$$

$$(j,n-1-i)$$

$$(n-1-i,n-1-j)$$

$$(n-1-j,i)$$4. これら 4 つのセルのうち、次のものがいくつあるか数えます。`1`。 
5. カウントが`ones`の場合、ゼロの数は次のようになります。`4 - ones`。 
6. 4 つのセルをすべて等しくするには、すべての 1 を 0 に反転するか、すべての 0 を 1 に反転します。 追加：$$\min(\text{ones},\ 4-\text{ones})$$答えに。 
7. すべての代表セルを処理した後、累積された答えを出力します。 

### なぜ効果があるのか

 回転対称では、すべてのセルが、繰り返し適用して得られるすべてのセルの値と一致する必要があります。$90^\circ$回転。 これらの位置が軌道を形成します。 異なる軌道は決して相互作用しないため、最適解は軌道ごとに独立して計算され、合計されます。 

1 つの軌道内では、最終値はすべて 0 かすべて 1 でなければなりません。 最も安価な選択は、フリップの回数が少ない方です。$\min(\text{ones}, \text{zeros})$。 すべての軌道が 1 回だけ処理されるため、必要な変更はすべて 1 回だけカウントされ、操作の合計数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        g = [input().strip() for _ in range(n)]

        ans = 0

        for i in range(n // 2):
            for j in range((n + 1) // 2):
                cells = [
                    g[i][j],
                    g[j][n - 1 - i],
                    g[n - 1 - i][n - 1 - j],
                    g[n - 1 - j][i]
                ]

                ones = sum(c == '1' for c in cells)
                ans += min(ones, 4 - ones)

        print(ans)

solve()
```外側のループは、すべての回転軌道からの代表を 1 つだけ列挙します。 境界は実装の中で最もデリケートな部分です。 使用する`n // 2`行と`(n + 1) // 2`列はすべてのグループを 1 回だけカバーし、自然に中央のセルをスキップします。`n`奇数です。 

代表的な位置ごとに、コードは連続する位置から得られる 4 つの位置を計算します。$90^\circ$回転。 これらの座標は回転公式から直接導出されます。 

1 の数によって、その軌道の最適なコストが決まります。 軌道に 3 つの 1 と 1 つのゼロが含まれる場合、1 つのゼロを変更するには 1 回の操作が必要ですが、3 つの 1 を変更するには 3 回の操作が必要です。 最小値を取ると、最適なローカル貢献が得られます。 

軌道は独立しているため、これらのコストを合計すると全体的な最適値が得られます。
