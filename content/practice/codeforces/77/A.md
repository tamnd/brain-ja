 ## 解決策
 ## 問題の理解

 ちょうど 7 人のヒーローと 3 人のボスがいます。 各ボスはある程度の経験値を与え、そのボスに割り当てられたすべてのヒーローは切り捨てられた均等なシェアを受け取ります。 

上司が与えた場合`x`経験とそのチームが持つ`k`ヒーローの場合、そのチームのすべてのヒーローが受け取ります`x // k`。 

課題は、7 人の英雄を 3 つの空でないグループに分割することです。 各グループは 1 つのボスと戦い、すべてのボスは 1 つのグループに割り当てられる必要があります。 

最適化には 2 つの層があります。 

まず、ヒーローが受け取る最大経験と最小経験の差を最小限に抑えます。 

次に、最小の差を達成するすべてのパーティションの中で、グループ内に留まる「いいね！」の総数を最大化します。 

入力は、方向性のある好みの関係を記述します。 主人公なら`A`ヒーローが好き`B`両方とも同じチームに所属しているため、貢献できます`1`スコアに。 いいねは誘導されるので、相互いいねは2回カウントされます。 

重要な点は、ヒーローの数が 7 人に固定されていることです。 それは問題の性質全体を変えます。 

任意のセットに対する単純なパーティション検索は通常、組み合わせ的に爆発的に増加しますが、ここでは割り当ての総数はごくわずかです。 各ヒーローは 3 つのグループから 1 つを選択できるため、最大で 3 つのグループが選択されます。`3^7 = 2187`課題。 グループの有効性をチェックして「いいね！」を数えた後でも、2 秒の制限内ではこれは簡単です。 

いいね関係の数は最大で`42`、まさにその通りです`7 * 6`、自己ループのない有向エッジの最大数。 つまり、すべてのパーティションのすべてのリレーションを自由に反復できるということです。 

難しいのはパフォーマンスではなく、正確さです。 

簡単な間違いの 1 つは、上司が別個であることを忘れていることです。 同じヒーローのセットを持つ 2 つのグループは、どのボスと戦うかに応じて、異なる経験値分布を生成できます。 

例えば：```
0
100 1 1
```一人の英雄が戦えば、`100`ボスだけ、そのヒーローは得する`100`。 7 人の英雄が一緒に戦えば、それぞれが得られるもの`14`。 

もう 1 つの微妙な問題は、整数の除算です。 

考慮する：```
0
10 10 9
```チームの規模が次の場合`(2,2,3)`、経験はになります`(5,5,3)`なぜなら`9 // 3 = 3`、 ない`3.0`後で丸めます。 浮動小数点除算を使用すると、間違った答えが生成されます。 

3 番目の簡単なバグは、「いいね！」を無方向のものとして扱うことです。 

例：```
2
Anka likes Troll
Troll likes Anka
10 10 10
```アンカとトロルが一緒の場合、貢献度は`2`、 ない`1`。 

最後に、チームには 1 人のヒーローを含めることができますが、チームが空であることはできません。 

この入力は有効です:```
0
100 100 100
```のようなパーティション`(1,1,5)`完全に合法です。 

「バランスの取れた」チームを強制する不注意な実装は、最適な答えを逃すことになります。 

## アプローチ

 最も直接的な強引なアイデアは、チームへのヒーローの割り当てを可能な限りすべて試してみることです。 

7 人の英雄はそれぞれ独立して 3 つのグループから 1 つを選択し、`3^7 = 2187`課題。 すべての割り当てについて、3 つのグループがすべて空でないことを確認し、各ヒーローが受け取る経験値を計算し、最大および最小の経験値を計算し、グループ内に残っているすべての好感度関係をカウントします。 

この強引なアプローチはすでに十分に高速です。 

すべての課題について、「いいね！」を数えるのにかかる時間は長くても`42`操作。 コンピューティング エクスペリエンスには一定の時間がかかります。 総作業量はおおよそ次のとおりです。```
2187 * 42 ≈ 90000
```それは小さいです。 

この問題の興味深い部分は、制約が意図的に十分に小さいため、徹底的な検索が可能であることがわかります。 

たとえ 20 人のヒーローでもこの問題をより一般的に表現することは、このアプローチでは不可能になります。`3^20`割り当てはすでに 30 億を超えています。 

重要な観察は、7 人の英雄が事実上一定であるということです。 それを認識すると、問題は複雑な最適化問題ではなく実装演習になります。 

ブルートフォースを慎重に構築する必要があります。 

最もクリーンな表現は、すべてのヒーローに次の整数を割り当てることです。`0`に`2`、選ばれたボスを表します。 それから：```
team_size[t] = number of heroes assigned to team t
```チームの経験`t`は次のようになります:```
boss_exp[t] // team_size[t]
```その後、各ヒーローの経験は、割り当てられたチームにすぐに知られます。 

最後に、2 つの最適化基準を辞書編集的に評価します。 

1. 経験の差は小さい方が常に良いです。 
2. 同点の場合、いいね数が大きいほど良い。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパーティションに対するブルート フォース | O(3^7 × n) | お(1) | 承認済み |
 | 最適化された徹底的な検索 | O(3^7 × n) | お(1) | 承認済み |

 入力サイズが意図的に小さいため、「最適な」解決策は依然として総当たり的なものになります。 

## アルゴリズムのチュートリアル

 1. 7 人のヒーロー名を保存し、各名前をインデックスにマッピングします。`0`に`6`。 
2. すべての有向好感度関係を読み取り、それらをヒーロー インデックスのペアに変換します。 
3.からのすべての割り当てを繰り返します。`0`に`3^7 - 1`。 
4. 現在の数値を基数にデコードします`3`。 

の`i`- 番目の数字はどのチームのヒーローかを示します`i`に属しています。 
5. 各チームのヒーローの数を数えます。 

チーム サイズが 0 の場合は、すべてのボスと戦う必要があるため、この割り当てをスキップしてください。 
6. 各チームが受け取った経験を計算します。 

チームなら`t`サイズがあります`sz[t]`、その後、そのチームのすべてのヒーローが次のものを受け取ります。```
boss[t] // sz[t]
```7. 7 人のヒーローすべての最大および最小のヒーロー経験値を計算します。 

それらの違いが主な最適化ターゲットです。 
8. チーム内に残る好意関係の数を数えます。 

あらゆる有向エッジに対して`(u, v)`、 追加`1`英雄なら`u`そして`v`同じチームに所属しています。 
9. このパーティションを現在の最良の回答と比較します。 

経験の差が小さい場合は、回答を置き換えます。 

差が同じでもいいね数の方が大きい場合は、答えを置き換えます。 
10. すべての割り当てが処理された後、最良の差異と最良の類似度の数を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、7 人のヒーローの有効なパーティションをすべてチェックして、空ではない 3 つのグループに分けます。 空のチームを持つ無効なパーティションを除いてパーティションはスキップされないため、列挙中に最適なパーティションが表示される必要があります。 

すべてのパーティションについて、アルゴリズムはステートメントで定義された量を正確に計算します。 

1. フロア分割を使用したヒーローごとの経験値。 
2. 最大経験値から最小経験値を差し引いた値。 
3. チーム内での直接の「いいね！」の数。 

すべての有効なパーティションは、問題ステートメントと同じ辞書編集順序を使用して評価および比較されるため、選択された回答が最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    heroes = [
        "Anka",
        "Chapay",
        "Cleo",
        "Troll",
        "Dracul",
        "Snowy",
        "Hexadecimal"
    ]

    idx = {name: i for i, name in enumerate(heroes)}

    n = int(input())

    likes = []

    for _ in range(n):
        p, _, q = input().split()
        likes.append((idx[p], idx[q]))

    boss = list(map(int, input().split()))

    best_diff = float('inf')
    best_like = -1

    for mask in range(3 ** 7):
        x = mask

        team = [0] * 7
        sz = [0] * 3

        for i in range(7):
            team[i] = x % 3
            sz[team[i]] += 1
            x //= 3

        if 0 in sz:
            continue

        exp = [0] * 3

        for t in range(3):
            exp[t] = boss[t] // sz[t]

        vals = [exp[team[i]] for i in range(7)]

        diff = max(vals) - min(vals)

        like_count = 0

        for u, v in likes:
            if team[u] == team[v]:
                like_count += 1

        if diff < best_diff:
            best_diff = diff
            best_like = like_count
        elif diff == best_diff and like_count > best_like:
            best_like = like_count

    print(best_diff, best_like)

solve()
```実装はブルートフォース列挙に直接続きます。 

最も重要な実装の詳細は、base を使用して割り当てをデコードすることです。`3`。 からのすべての整数`0`に`3^7 - 1`チームへのヒーローの 1 つの割り当てを一意に表します。 

例えば：```
mask = 17
```デコードすると次のようになります。```
[2, 1, 0, 0, 0, 0, 0]
```英雄という意味`0`チームに加わります`2`、 ヒーロー`1`チームに加わります`1`、 等々。 

もう一つの微妙な点は、いいねが向けられることです。 コードは、すべての関係を与えられたとおりに正確に保存し、それぞれを独立してカウントします。 

経験値の計算には整数の除算を使用する必要があります。```
boss[t] // sz[t]
```通常の除算を使用すると浮動小数点値が生成され、意図したルールに違反します。 

辞書編集的な最適化は慎重に処理されます。 

まず最小化します`diff`。 2 つのパーティションが等しい場合のみ`diff`比較しますか`like_count`。
