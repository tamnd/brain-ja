 ## 解決策
 ## 問題の理解

 この問題は、ノードがレイヤーごとに順番に番号付けされる、無限の完全なバイナリ ツリーを記述します。 ルートの番号は 1、その左側の子は 2、右側の子は 3 であり、各ノードが次に利用可能な番号を持つ 2 つの子を取得するというパターンが続きます。 頂点番号が与えられると`n`、ルートからルートまでのパスに沿ったすべてのノード番号の合計を計算するように求められます。`n`。 

入力は複数のテスト ケースで構成され、それぞれが頂点番号を指定します。`n`これは次のように大きくすることができます$10^{16}$。 これにより、ブルート フォース トラバーサルには最大で$10^{16}$これは、1 秒の実行時間の実現可能な制限をはるかに超えています。 

明白ではないエッジケースには、可能な限り最小のノードが含まれます。`n = 1`。 この場合、パスにはルートのみが含まれており、合計は 1 になるはずです。`n`は 2 の累乗、または 2 の累乗の直後です。 レイヤーごとのノードの番号付けはバイナリ表現と自然に一致しており、これが効率的なソリューションの鍵となります。 子の割り当てを順番にシミュレートしようとする不注意なアプローチは、大規模な場合には失敗します。`n`。 

## アプローチ

 ブルートフォース手法では、ノードまでのツリーが生成されます。`n`、または各ノードの親ポインタを維持します。 その後、親ポインタをたどることができます。`n`パスを合計するには 1 にします。 これは小規模な場合に機能します`n`しかし、それは不可能になります`n`に近い$10^{16}$膨大な数の挿入またはメモリ割り当てが必要になるためです。 

重要な洞察は、ツリーの構造を観察することで得られます。 この無限バイナリ ツリー内のすべてのノードは、ルートからのパスをエンコードするバイナリ表現に関連付けることができます。 具体的には、ルートに 1、その左と右の子に 2 と 3 の番号を付け、層ごとに続行すると、下への各ステップは左または右の子を選択することに対応し、これは のビットに相当します。`n`のバイナリ形式。 より具体的に言うと、`n`ルートへの移動、親への各移動は整数の 2 による除算で計算でき、これらの値を合計すると望ましい結果が得られます。 これにより、問題が繰り返し半分になるという問題が軽減されます。`n`そして合計が 1 になるまで累積します。 

このアプローチが機能するのは、ツリーの番号付けが、完全なバイナリ ツリーの幅優先探索によって生成された一連の番号に正確に対応しているためです。 ノードからその親への移動は、`n // 2`、これをルートに到達するまで繰り返すことができます。 これにより、ビット数に比例する対数ステップ数が保証されます。`n`。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、`t`。 各テスト ケースについて、頂点番号を読み取ります。`n`。 
2. 変数を初期化する`ans`これは、パスに沿ったノードの合計を保持します。 
3. その間`n`0より大きい場合は追加します`n`に`ans`そして更新します`n`に`n // 2`。 2 で割るたびに、ツリーが 1 ステップ上に移動します。 
4. 1回`n`が 0 に達すると、パスは完全に通過されます。 出力`ans`。 

それが機能する理由: 不変条件は、反復ごとに、`n`ルートへのパス上の現在のノードを表します。 追加`n`に`ans`合計を累積し、2 で割るとその親に移動します。 これにより、パス内のすべてのノードが 1 回だけ含まれ、ルートで終了することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    ans = 0
    while n > 0:
        ans += n
        n //= 2
    print(ans)
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`までに必要です。$10^4$テストケース。 while ループにより、からのパスが確実にトレースされます。`n`対数時間でルートまで。 整数の除算を使用すると、正しい親の計算が保証され、Python の任意精度の整数は非常に大きな値を処理します。`n`。
