 ## 解決策
 ## 問題の理解

 オムスク地下鉄を表す成長する木が与えられ、各駅の重みは次のいずれかになります。`1`または`-1`。 ツリーには最初は番号が付けられた単一のステーションがあります。`1`重さで`1`。 次に、一連のイベントを実行します。新しいステーションを既存のステーションの子として追加するか、ステーションからのパスに沿って連続したセグメントが存在するかどうかをクエリします。`1`別の駅へ`v`その重みの合計が正確に整数になる`k`。 

駅に木が根付いているので`1`そして、から始まるパスのみをクエリします`1`の場合、各クエリのパスは、ルートからターゲット ノードまでの一意のルートに沿ったノードのシーケンスにすぎません。 各クエリは、合計が正確に一致するこのシーケンスの連続したサブセグメントが存在するかどうかを尋ねます。`k`。 

この問題では、最大で`2 * 10^5`すべてのテスト ケースにわたるイベントの合計。 クエリごとにすべてのサブセグメントを検査する総当りアプローチでは、クエリごとに O(n²) 時間がかかり、これでは遅すぎます。 理想的にはプレフィックス合計のプロパティを活用して、クエリごとに O(n) 個以上のソリューションが必要です。 主要なエッジ ケースには空のサブセグメントが含まれます (合計すると`0`) と完全に構成されるパス`1`または`-1`s、達成可能な合計を制限します。 

## アプローチ

 素朴なアプローチは、クエリごとにノードからのパスを再構築することです。`1`ターゲット ノードに接続し、このパスの可能な連続サブセグメントをすべてチェックして、それらの合計が等しいかどうかを確認します。`k`。 これには、O(n) 個のノードと O(n) 個のサブセグメントの反復処理が含まれるため、クエリごとに O(n²) になります。 まで`2 * 10^5`イベントの場合、これには O((2 * 10^5)²) の操作が必要になりますが、これは現実的ではありません。 

重要な観察は、パスに沿った達成可能な最大値と最小値の合計のみが必要であるということです。 各ノードは次のいずれかに貢献します`+1`または`-1`、したがって、パスの合計は区間内にあります`[min_sum, max_sum]`、 どこ`min_sum`すべての場合の合計です`-1`はパスの先頭で連続して取得され、`max_sum`すべての場合の合計です`1`は連続して取得されます。 なぜなら、すべての重みは`1`または`-1`、間の任意の整数`min_sum`そして`max_sum`は、いくつかの連続したサブセグメントの合計として達成可能です。 これにより、各クエリが単純なチェックに減ります。`k`間`min_sum`そして`max_sum`? パスを構築し、プレフィックス合計を維持すると、事前に計算された累積合計を使用して、クエリごとにこれらの境界を O(1) で計算できます。

 | --- | --- | --- | --- |

 | プレフィックス合計間隔チェック | O(n) ツリー構築後のクエリごとに O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. リストを初期化する`weights`各ステーションの重量を保存します。 リストを初期化する`cumulative`ルートから各ノードまでの累積合計を保存します。 から始める`weights[1] = 1`そして`cumulative[1] = 1`。 
2. を維持します。`parent`各ノードの親を知るための配列。 これは、必要に応じて任意のノードからルートまでのパスを追跡するために必要です。 
3. 「+」イベントの場合、新しいノードを子として追加します。`v_i`重さで`x_i`。 セット`cumulative[new_node] = cumulative[v_i] + x_i`。 新しいノードの親を保存します。 
4.「？」について とのイベント`u = 1`、パスは単にルートからノードまでのノードのシーケンスです。`v_i`。 パス全体の合計は、`cumulative[v_i]`。 
5. パスの連続するサブセグメントに沿って可能な最大合計を計算します。 重みだけなので、`-1`または`1`、最大合計は、すべての場合のパス合計そのものです。`1`が含まれており、最小値は次の数の負の値です。`-1`は。 これは次のように計算できます。`min_sum = -count(-1)`そして`max_sum = count(1)`。 
6. もし`k`間にあります`min_sum`そして`max_sum`、「はい」を出力します。 それ以外の場合は「いいえ」を出力します。 特殊なケースを含めます。`k = 0`これは、空のサブセグメントを選択することで常に実現できます。 

機能する理由: プレフィックス合計のトリックにより、パスに沿った最小合計と最大合計の間の任意の整数が達成可能であることが保証されます。 すべての重みは ±1 であるため、連続するサブセグメントに沿った達成可能な合計のセットはこの区間では連続的です。 累積合計により、クエリごとに O(1) でこのチェックが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0, 0]  # parent[1] = 0
        weights = [0, 1]  # weights[1] = 1
        count_plus = [0, 1]  # cumulative sum of +1 weights
        count_minus = [0, 0]  # cumulative sum of -1 weights
        node_id = 1
        
        for _ in range(n):
            parts = input().split()
            if parts[0] == '+':
                v, x = int(parts[1]), int(parts[2])
                node_id += 1
                parent.append(v)
                weights.append(x)
                count_plus.append(count_plus[v] + (x == 1))
                count_minus.append(count_minus[v] + (x == -1))
            else:
                u, v, k = int(parts[1]), int(parts[2]), int(parts[3])
                # Path from 1 to v
                max_sum = count_plus[v] - count_plus[u - 1]  # all 1s
                min_sum = -count_minus[v] + count_minus[u - 1]  # all -1s
                if min_sum <= k <= max_sum:
                    print("Yes")
                elif k == 0:
                    print("Yes")
                else:
                    print("No")

if __name__ == "__main__":
    solve()
```このソリューションでは、`count_plus`そして`count_minus`の数を追跡する`1`と`-1`ルートから各ノードまでのパスに沿って。 各クエリについて、`k`中にある`[min_sum, max_sum]`正確性を保証します。 空のパスの場合は次のように処理されます。`k == 0`。 の`parent`配列はツリー構造を維持するために使用されますが、この単純なバージョンでは、`u = 1`なので、パスを追跡するのは簡単です。
