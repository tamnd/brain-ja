 ## 解決策
 ## 問題の理解

 この問題は、オムスク地下鉄システムを表す成長するツリー構造をモデル化します。 ツリー内の各ノードはステーションであり、重み +1 のステーション 1 から始まります。 新しいステーションは 1 つずつ追加され、それぞれが既存のステーションに接続され、それぞれの重みは +1 または -1 になります。 ステーションの追加に加えて、重みの合計が指定された整数と正確に一致する 2 つのステーション間のパスに沿ってノードの連続セグメントが存在するかどうかを尋ねるクエリが到着します。$k$。 セグメントは空にすることもでき、その場合、合計は 0 になります。 

入力はステーションの追加とクエリを交互に行います。 出力は各クエリに「はい」または「いいえ」で答える必要があります。 

制約は厳しいです。 イベント数$n$到達できる$2 \cdot 10^5$テスト ケースごとに、すべてのテスト ケースの合計が次を超えない$2 \cdot 10^5$。 これは、クエリごとにパス全体を反復する単純なアプローチでは遅すぎることを意味します。最悪の場合$O(n^2)$アルゴリズムが実行する$10^{10}$2秒の制限時間を大幅に超えた操作。 もっと近いものが必要です$O(n \log n)$テストケースごとに。 

明らかではないエッジ ケースには、完全に +1 または -1 のパス、必要なパスが含まれます。$k$パス上のすべてのノードの重みの合計を超えているため、次のクエリを実行します。$u = v$。 たとえば、パスが 1 → 2 → 3 で重み [+1、-1、+1] の場合、次のクエリが実行されます。$k = 2$should return "Yes" because the subpath 1 → 3 sums to +1, so only the sum of a subpath 1 → 1 or 3 → 3 can be +1, showing the algorithm must carefully handle all contiguous subpaths.

 ## アプローチ

 ブルート フォース ソリューションでは、クエリされたノード間のパスを特定し、すべての連続するサブセグメントをチェックして、その合計が等しいかどうかを確認します。$k$。 パスを構築するには、両方のノードから最下位の共通祖先 (LCA) まで遡ることができます。 各パスには最大で次のものを含めることができます$O(n)$ノード、およびすべてのサブセグメントをチェックすることは、$O(n^2)$クエリごとに。 と$10^5$クエリ、これは計算上実行不可能です。 

重要な洞察は、すべてのノードの重みが +1 または -1 のいずれかであるということです。 この制限は、すべてのパスの合計が整数の範囲にあることを意味します。$[-L, L]$、 どこ$L$パスの長さです。 この問題は、「±1 要素の連続シーケンスのサブセット合計」の変形に帰着します。これは、プレフィックス合計を使用して効率的に解決できます。 パスに沿ったプレフィックスの合計により、次のことを確認できます。$k$任意の連続したサブセグメントによって取得できます: インデックスからのサブパスの合計$i$に$j$は$prefix[j] - prefix[i-1]$。 したがって、プレフィックスの合計をセットに格納すると、クエリは次のことをチェックすることになります。$prefix[j] - k$セットの中に存在します。 

ツリー構造には、任意のパスに沿ってプレフィックスの合計を計算する高速な方法が必要です。 オイラー ツアーまたは重光分解 (HLD) を使用すると、パスを配列に線形化できます。 ただし、±1 の重みを考慮すると、パスに沿った可能な最小値と最大値の和を知るだけで十分です。 させて$len$パスの長さ、$pos$+1 ノードの数、および$neg$-1 ノードの数。 すると、最大合計額は、$pos - neg$そして最小値は$-neg + pos$。 この範囲内で正しいパリティ (ノード数と同じパリティ) を持つ整数は、連続したサブパスの合計として取得できます。 これにより、クエリの処理が大幅に簡素化されます。

 ## アルゴリズムのチュートリアル

 1. ノード 1 の重み +1 を使用してツリーを初期化します。 ルートからの親、深さ、プレフィックスの合計を追跡します。 
2. 「+」イベントごとに、新しいノードを追加します。 その親、重みを保存し、そのプレフィックスの合計を次のように計算します。`prefix[node] = prefix[parent] + weight`。 
3. それぞれの「？」 クエリ:

 ａ． 間のパスを計算します。`u`そして`v`LCAを使って。 

b. させて`sum_path`からの合計になります`u`に`v`道沿いにあります。 

c. させて`len_path`このパス上のノードの数になります。 

d. 達成可能なサブパスの合計の最小値と最大値を計算します。`min_sum = -count_negative`そして`max_sum = count_positive`。 

e. もし`k`にある`[min_sum, max_sum]`そして`(k - min_sum) % 2`パス パリティに一致する場合は「Yes」を出力し、それ以外の場合は「No」を出力します。 
4. バイナリ リフティング配列または深さ配列を使用して、クエリごとに O(log n) で LCA を効率的に計算します。 

±1 和のすべてのサブセグメントが連続しており、達成可能な和の範囲内の任意の整数を連続したサブパスとして形成できるため、正確性が保証されます。 パリティ チェックにより、±1 ステップのみで特定の整数の合計が可能であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0, 0]  # 1-indexed; parent[1] = 0
        weight = [0, 1]  # weight[1] = 1
        depth = [0, 0]   # depth of root is 0

        # For prefix sums from root
        prefix = [0, 1]

        # For LCA
        LOG = 20
        up = [[0]*LOG for _ in range(n+2)]  # up[node][i] = 2^i-th ancestor
        up[1][0] = 0

        nodes = 1
        events = []
        for _ in range(n):
            parts = input().split()
            events.append(parts)

        for parts in events:
            if parts[0] == '+':
                v, x = int(parts[1]), int(parts[2])
                nodes += 1
                parent.append(v)
                weight.append(x)
                depth.append(depth[v] + 1)
                prefix.append(prefix[v] + x)
                up.append([0]*LOG)
                up[nodes][0] = v
                for i in range(1, LOG):
                    up[nodes][i] = up[up[nodes][i-1]][i-1] if up[nodes][i-1] else 0
            else:
                u, v, k = int(parts[1]), int(parts[2]), int(parts[3])
                # find lca
                def lca(a, b):
                    if depth[a] < depth[b]:
                        a, b = b, a
                    for i in range(LOG-1, -1, -1):
                        if depth[a] - (1 << i) >= depth[b]:
                            a = up[a][i]
                    if a == b:
                        return a
                    for i in range(LOG-1, -1, -1):
                        if up[a][i] != up[b][i]:
                            a = up[a][i]
                            b = up[b][i]
                    return parent[a]

                anc = lca(u, v)
                len_path = depth[u] + depth[v] - 2*depth[anc] + 1
                sum_path = prefix[u] + prefix[v] - 2*prefix[anc] + weight[anc]

                # Max and min achievable subpath sums along ±1 path
                max_sum = (len_path + sum_path)//2
                min_sum = (len_path - sum_path)//2 * -1

                if min_sum <= k <= max_sum:
                    print("Yes")
                else:
                    print("No")

if __name__ == "__main__":
    main()
```コードは最初に、親、重み、深さ、プレフィックス合計の配列を設定します。 バイナリリフティングによる`up`効率的な LCA 計算が可能になります。 各クエリについて、パスの長さと合計を使用して、達成可能な最大および最小のサブパス合計が計算されます。 チェック中`k`この範囲に対する答えが決まります。
