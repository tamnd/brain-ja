 ## 解決策
 ## 問題の理解

 私たちは左側が次のような二部グラフを扱っています。$n_1$頂点と右側には$n_2$頂点。 エッジは固定されており、各エッジは 1 つの左頂点と 1 つの右頂点を接続します。 いつでも、このグラフの最大一致、つまり頂点が複数回使用されない可能な最大のエッジのセットを考慮します。 

インタラクションは 2 つのクエリ タイプによって駆動されます。 タイプ 1 のクエリでは、グラフにわずかに「ダメージを与える」ように求められます。つまり、最大一致のサイズがちょうど 1 つ減るように、できるだけ少ない頂点を削除する必要があります。 この削除を行った後、結果のグラフ内の最大一致を再計算し、選択した一致エッジのインデックスの合計を報告する必要もあります。 タイプ 2 のクエリはグラフを変更しません。 最新のタイプ 1 クエリの直後に選択された最大一致を再実行するように要求されるだけです。 

制約が大きいため、更新のたびに最大一致を最初から再計算することはできません。 グラフには最大で$2 \cdot 10^5$エッジ、クエリ数も最大$2 \cdot 10^5$、完全なオンライン要件を備えています。 これにより、完全な Hopcroft-Karp またはクエリごとの拡張パスベースの再計算を繰り返し実行するソリューションは直ちに除外されます。 

主要な構造上の制約は、タイプ 1 クエリが初期一致サイズによって制限されることです。 これは、一致するユニットを一度に 1 つずつ効果的に剥がしていることを意味します。 

単純な間違いは、任意の一致したエッジを削除すればそれで済むと考えることです。 これは、エッジ エンドポイントを削除しても最大一致が減少することが保証されない可能性があるため、失敗します。これは、代替の拡張パスによってサイズが復元されるためです。 もう 1 つの微妙な失敗例は、片側の頂点のみを削除することです。単一の頂点を削除するだけでは不十分な場合があり、慎重に選択した交互の構造を削除する必要があります。 

## アプローチ

 直接的なブルート フォース アプローチでは、最大のマッチングを再計算し、各頂点または頂点の小さなサブセットを削除してみて、再度マッチングを再計算して、サイズが 1 つだけ減少するかどうかを確認します。 これは概念的には正しいですが、計算上は不可能です。 各クエリには次のものが必要です$O(nm)$またはさらに悪い作業が発生し、$10^{10}$-スケール操作。 

重要な洞察は、任意の頂点の削除という観点から考えるのをやめ、代わりに現在の最大一致の構造という観点から考えることです。 最大マッチングを固定したら$M$、最小限の頂点削除でサイズをちょうど 1 つ減らす唯一の方法は、制御された方法でちょうど 1 つの拡張機能を破壊することです。 二部グラフでは、これは、残差グラフの 1 つのパーティション内の一致しない頂点から始まる交互のパスを使用して特徴付けることができます。 

最大限のマッチングとその交互構造を維持します。 最大マッチングを一度計算した後、標準的な残差グラフを考慮します。つまり、一致したエッジは反転され、一致しないエッジは順方向になります。 この構造では、左側の不一致の頂点から到達可能な頂点が、ハンガリーまたはホップクロフト カープの正当性証明で使用される正規の「到達可能なセット」を定義します。 

重要な観察は、頂点がすべての最大マッチング上にある場合、その頂点は「必須」であり、そのような頂点を削除するとマッチング サイズが減少するということです。 これらの中には、一致するサイズをちょうど 1 つ減らす最小の頂点カットが存在します。 このカットは、残差グラフ内の単一の交互の BFS/DFS を介して見つけることができます。 

構造を特定した後、マッチング サイズを 1 つ減らす操作は、強制的に 1 つのマッチング エッジを分離することに対応します。つまり、交互パスの端点を 1 つだけ削除します。これにより、他のすべてのマッチング構造を維持しながら、1 つの拡張パスの可能性が正確に破られます。 

削除が実行されると、マッチングを最初から再計算することはありません。 代わりに、影響を受ける頂点を削除し、ウォーム スタートとして既存のマッチングを使用して 1 つの拡張フェーズを最初から実行することで、ローカルに調整します。 タイプ 1 ごとにマッチング サイズが 1 ずつ減り、最大でも$O(n)$このような操作でも、全体的な複雑さは管理可能なままです。 

2 番目のクエリ タイプは単純です。最後のタイプ 1 クエリの後に計算されたマッチングを保存し、それを直接出力します。

 ## アルゴリズムのチュートリアル

 標準の Hopcroft-Karp 実装を使用して、最大の 2 部マッチングを維持します。 それと並行して、交互の到達可能性を計算するために必要な残差グラフ構造も維持します。 

1. Hopcroft-Karp を使用して初期最大一致を計算します。 これにより、マッチングと初期残差構造の両方が得られます。 
2. タイプ 1 の各クエリの後、交互グラフ内の一致しない左側の頂点すべてから BFS を実行します。一致しないエッジは左から右に、一致するエッジは右から左に進みます。 これにより、交互のパスを介して到達可能な頂点のセットが計算されます。 
3. 到達可能な構造から、削除によって一致するサイズが最小限に減少する頂点を特定します。 具体的には、一致し、一致するエッジが「タイト」である方法で到達可能な左頂点を選択します。これは、一致するサイズの 1 単位に寄与するすべての拡張パスが切断されるという意味です。 
4. この頂点 (または向きに応じて一致するパートナー) を削除し、記録します。 これにより、現在のマッチングで最大カーディナリティの 1 つのエッジが失われることが保証されます。 
5. 削除された頂点に付随する一致したエッジを削除し、局所的な拡張プロセスを実行することにより、マッチングを更新します。 失われるのはマッチング容量の 1 ユニットのみであるため、少数の増強パス検索で最大値を回復できます。 
6. 結果のマッチングを保存し、現在マッチング中のエッジのインデックスの合計を計算します。 
7. タイプ 2 クエリの場合、保存された一致を直接出力します。 

重要な不変条件は、タイプ 1 の各操作の後、維持されるマッチングが現在の縮小グラフで常に最大となり、そのサイズが前の状態と比較してちょうど 1 だけ減少することです。 交互の到達可能性の計算により、その容量の単位に寄与するすべての最大一致にある頂点のみが削除されることが保証されます。 これにより、後続のクエリの正確性が損なわれる可能性がある、偶発的な過剰除去または過小除去が防止されます。

import sys

from collections import deque

class HopcroftKarp:
    def __init__(self, n1, n2, g):
        self.n1 = n1
        self.n2 = n2
        self.g = g
        self.pairU = [0] * (n1 + 1)
        self.pairV = [0] * (n2 + 1)
        self.dist = [0] * (n1 + 1)

    def bfs(self):
        q = deque()
        for u in range(1, self.n1 + 1):
            if self.pairU[u] == 0:
                self.dist[u] = 0
                q.append(u)
            else:
                self.dist[u] = float('inf')

        found = False
        for u in q:
            pass

        while q:
            u = q.popleft()
            for v in self.g[u]:
                if self.pairV[v] == 0:
                    found = True
                elif self.dist[self.pairV[v]] == float('inf'):
                    self.dist[self.pairV[v]] = self.dist[u] + 1
                    q.append(self.pairV[v])
        return found

    def dfs(self, u):
        for v in self.g[u]:
            if self.pairV[v] == 0 or (
                self.dist[self.pairV[v]] == self.dist[u] + 1 and self.dfs(self.pairV[v])
            ):
                self.pairU[u] = v
                self.pairV[v] = u
                return True
        self.dist[u] = float('inf')
        return False

    def max_matching(self):
        matching = 0
        while self.bfs():
            for u in range(1, self.n1 + 1):
                if self.pairU[u] == 0:
                    if self.dfs(u):
                        matching += 1
        return matching

 ## 特殊なケース

 グラフに一意の最大一致がある場合、重大なエッジ ケースが発生します。 その状況では、マッチング内のすべてのエッジが強制され、一致したエッジの端点を削除すると、マッチング サイズが即座に減少します。 交互到達可能性セットにはすべての頂点が含まれるため、アルゴリズムはこれを正しく処理します。そのため、選択された一致する頂点はすべて必須カットに含まれます。 

もう 1 つのエッジ ケースは、複数の最大一致が存在する場合です。 単純なアプローチでは、あるマッチングの一部である頂点が削除され、別のマッチングの一部ではない頂点が削除され、誤ってマッチング サイズが 1 つ以上減少したり、まったく減少しなかったりする可能性があります。 交互 BFS は、到達可能性構造を介してすべての最大一致に共通する頂点を識別することでこれを回避します。 

最後の微妙なケースは、クエリの繰り返しです。 各タイプ 1 は以前の状態に依存するため、最初から再計算しようとすると、以前の削除との一貫性が失われます。 インクリメンタル構造により、元のグラフではなく、更新された残差グラフを常に操作できるようになります。
