 ## 解決策
 ## 問題の理解

 2 つの非減少配列 (元の配列と最終配列) が与えられます。 元の配列は、各位置に負でない値を追加して要素ごとに「シフト」し、中間配列を生成できます。 その後、この中間配列がソートされ、その結果ソートされた配列が観察されます。 

課題は、このプロセスを部分的に逆転させることです。 元の配列の各位置について、その位置での追加値がどのくらい小さいか、どのくらい大きいかを判断しながら、変換と並べ替え後に最終的に指定されたソートされた最終的な配列を得ることができるようにしたいと考えています。 

重要な問題は、並べ替えによって位置間の直接の対応関係が破壊されてしまうことです。 追加された値の選択方法によっては、元の配列内の各要素が最終的な配列内の異なる位置と一致する可能性があります。 

制約は、テスト ケースごとに線形に近い、または線形に近い解決策を意味します。 すべてのテスト ケースにわたる n の合計は 2·10^5 であるため、テスト ケースごとに O(n log n) より悪いアプローチは失敗します。 これにより、位置間のすべての置換やブルートフォースマッチングを試みる構築は即座に排除されます。 

配列内の値が等しいかほぼ等しい場合、微妙なエッジ ケースが発生します。 このような場合、元の位置と最終的な位置の間の複数の一致が有効になり、固定ペアをあまりにも早く仮定すると、貪欲な決定が正確さを簡単に破ってしまう可能性があります。 たとえば、a = [1, 2, 3] および b = [1, 2, 3] の場合、すべての d はゼロでなければなりませんが、インデックスが一致しない単純な貪欲割り当てでは、誤って正の値が割り当てられる可能性があります。 

もう 1 つの注意が必要な状況は、中間推論で a の大きな値が b の小さな値と一致するときに発生します。 d は非負でなければならないため、順序付け制約に違反する不一致の仮定は、慎重に処理しない限り、暗黙のうちに無効な状態を生成します。 

## アプローチ

 ブルートフォースアプローチでは、各 a[i] をいくつかの b[j] に割り当て、d[i] = b[j] - a[i] を計算し、結果の値のマルチセットが並べ替え後に b と一致するような有効なグローバル割り当てが存在するかどうかを確認します。 これはすぐに制約とのマッチング問題になり、すべての順列を探索すると階乗の複雑さが生じます。 すべてのポジションには多数の一致候補があるため、バックトラッキングを使用して制限した場合でも、指数関数的な動作につながります。 

重要な観察は、両方の配列がソートされていることです。これにより、置換ではなく貪欲なマッチングを使用して、実行可能な割り当てを推論できるようになります。 恣意的な並べ替えという観点から考えるのではなく、問題を順序制約の下での要素のペアとして再解釈します。 

固定インデックス i の場合、a[i] が対応できる値 b[j] は、引数のカウントから導出される実行可能条件を満たさなければなりません。つまり、i より前の要素が b[j] 以下の値と一致できる要素の数と、i の後の要素が残りのスロットに収まる要素の数です。 これにより、問題は、プレフィックス マッチング ロジックを使用して特定の割り当ての実現可能性をテストできる構造に変わります。 

可能な最小値と最大値の d[i] を計算するには、各 i を独立して扱い、配列の残りの部分を貪欲な制約の下で一致可能に保ちながら、a[i] に割り当てることができる最小または最大の b[j] は何かと尋ねます。 これは 2 ポインタのシミュレーション問題になり、候補のペアを線形順序でテストします。 

中心的な考え方は、両方の配列がソートされているため、有効な割り当てをインデックス間の単調なマッチングに変換できるということです。 これにより、任意の順列を考慮する必要がなくなり、順序制約の下での位置合わせの実現可能性を確認する問題が軽減されます。

 | 最適な貪欲なマッチング | テストあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 各インデックス i を独立して処理し、可能な最小値と最大値の両方の d[i] を計算します。 

### 最小値 d[i]

 1. a[i] は、有効なグローバル マッチングの一部である可能性のある最も早い b[j] とマッチングされるべきであると仮定します。 
2. b を左から右にスキャンし、b[j] を a[i] に代入することで残りのすべての要素に対して十分な余地が残るかどうかをシミュレートします。 
3. 各候補 b[j] について、すべての要素の貪欲一致をシミュレートすることで実現可能性をチェックし、以前の a 値が以前の b 値と引き続き一致できることを確認します。 
4. この実現可能性チェックに合格した最初の b[j] は、可能な最小の b[j]、つまり最小の d[i] = b[j] - a[i] を与えます。 

左からスキャンする理由は、より小さい b 値はより小さい d[i] に対応するため、可能な限り最も早い一致が必要だからです。 

### 最大 d[i]

 1. 目的を逆にして、a[i] を可能な限り最新の b[j] と一致させようとします。 
2. b を右から左にスキャンし、a[i] を b[j] に固定する実現可能性を再度テストします。 
3. 残りの要素の完全に有効なマッチングを可能にする最大の b[j] を選択します。 
4. 差により最大 d[i] が得られます。 

b[j] が増加すると d[i] が増加するため、これは対称的に機能しますが、残りのマッチングの実行可能性が損なわれる点までに限られます。 

### なぜ効果があるのか

 正確さは、両方の配列がソートされているという事実から得られます。これは、a と b の間の有効な一致はインデックス間の単調な割り当てとして表現できることを意味します。 単一のインデックスの候補ペアを修正したら、残りの問題は、非負性制約に違反することなく残りの要素を順番に照合できるかどうかを確認することになります。 この単調な構造により、欲張りスキャン下でも実現可能性が維持されるため、最初 (または最後の) の有効な候補がそれぞれ最小値と最大値に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(a, b, forced_i, forced_j):
    n = len(a)
    used_b = [False] * n
    used_b[forced_j] = True

    j = 0
    # match all i except forced_i greedily
    for i in range(n):
        if i == forced_i:
            continue
        while j < n and (used_b[j] or b[j] < a[i]):
            j += 1
        if j == n:
            return False
        used_b[j] = True
        j += 1
    return True

def solve_case(a, b):
    n = len(a)
    min_d = [0] * n
    max_d = [0] * n

    for i in range(n):
        # min
        for j in range(n):
            if b[j] < a[i]:
                continue
            if feasible(a, b, i, j):
                min_d[i] = b[j] - a[i]
                break

        # max
        for j in range(n - 1, -1, -1):
            if b[j] < a[i]:
                continue
            if feasible(a, b, i, j):
                max_d[i] = b[j] - a[i]
                break

    return min_d, max_d

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        mn, mx = solve_case(a, b)
        print(*mn)
        print(*mx)

if __name__ == "__main__":
    main()
```このソリューションは、実現可能性のチェックを候補の選択から分離します。 の`feasible`関数は、強制ペアリングを完全に有効な割り当てに拡張できるかどうかをシミュレートします。 貪欲に残りを一致させます`a[i]`利用可能な有効な最小値への値`b[j]`価値観。 

最小配列と最大配列は、各位置のすべての可能な候補をスキャンすることによって構築されます。 正確かどうかは、単一のペアを修正した後に実行可能性を常にテストするかどうかに依存します。 

実装の微妙な詳細は、貪欲なマッチング中に強制インデックスをスキップすることです。 除外しないと、シミュレーションで強制値が誤って再利用され、有効性チェックが中断される可能性があります。

 ## 特殊なケース

 a と b のすべての値が同一の場合、すべての要素はそれ自体にマップされる必要があります。 要素を上にシフトしようとすると、別の要素がより小さいスロットを占有することになるため、実現可能性が損なわれますが、ソートされた制約の下ではこれは不可能です。 自己マッチングのみが実現可能性を通過するため、アルゴリズムは自然に差分ゼロに収束します。 

a に繰り返し値が含まれる場合、等しい b 値間に複数の代入が存在します。 貪欲な実現可能性チェックにより、同一の b[j] を選択しても残りの容量が破壊されないことが保証されるため、最小値と最大値の両方が適切に折りたたまれ、あいまいさが正確さに影響を与えないことが実証されます。
