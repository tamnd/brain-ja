 ## 解決策
 ## 問題の理解

 2 × 2 のグリッドに配置された 4 つのピクセルで構成される小さな画像が与えられます。 各ピクセルには、現在の色を表す小文字のラベルが付いています。 目標は、一連のペイント操作を使用して、4 つのピクセルすべてが最終的に同じ色になるようにすることです。 

各操作で最大 2 つのピクセルを選択できますが、それはそれらのピクセルが現在同じ色を共有している場合に限られます。 それらを選択した後、選択した両方のピクセルを、選択した単一の新しい色に再ペイントします。 1 つのピクセルだけを選択した場合は、単一のピクセルを単独で再描画することもできます。 

タスクは、各テスト ケースで 2 × 2 グリッド全体の色を均一にするために必要なこのような操作の最小数を計算することです。 

グリッド サイズは固定で非常に小さいため、アルゴリズムのスケーリングの問題はありません。 この制約により、一定の作業で各テストを独立して処理できるようになります。 4 つのセルを検査し、その色の分布を判断するソリューションは、制限内で快適に実行されます。 

主な微妙な点は、ペア操作の仕組みを過小評価していると、「すべてを最も頻繁に使用される色に変更するだけ」のような単純で貪欲なアイデアが失敗する可能性があることです。 たとえば、4 つの色がすべて異なる場合、4 つの手が必要であるように見えるかもしれませんが、重複が存在する場合にのみ賢くペアリングすることで、より良い結果を得ることができます。 

エッジケースは基本的にすべて頻度分布によって決まります。 すべてのピクセルが同一の場合、操作は必要ありません。 3 つが同一で 1 つが異なる場合、または 2 つのペアが存在する場合、またはすべてが異なる場合、答えは非自明ではあるが構造化された方法で変化します。 

## アプローチ

 ブルートフォース戦略では、すべてのピクセルが一致するまで、有効な操作の可能なすべてのシーケンスが試行されます。 どのような構成からでも、サイズ 1 または 2 のカラー クラスを選択し、それを他の色に再ペイントして続行できます。 状態空間は小さいですが、再描画するたびにカラー構成が複数の方法で変更され、異なるシーケンスによって同じ状態が繰り返し発生する可能性があるため、分岐はすぐに爆発します。 位置が 4 つしかないにもかかわらず、色の割り当てに対する単純な BFS は依然として多くの冗長な遷移を探索します。 

重要な観察は、中間色はまったく気にせず、最終的なターゲットの色に既に一致しているピクセルの数だけを気にするということです。 ターゲットの色を固定すると、その色をすでに持っているすべてのピクセルは無視できますが、残りのピクセルは変換する必要があります。 コストは、そのターゲットに既に一致するピクセルが何個あるかによって完全に異なります。 

固定ターゲットカラーの場合、次のように表示されるとします。`k`回。 残りを変換する必要があります`4 - k`ピクセル。 各操作では一度に最大 2 ピクセルを変換できますが、これは同じ現在のカラーを 2 つ選択できる場合に限られます。 自由に再描画できるため、可能な場合にはペアリングが個々の動きよりも悪くならないように、いつでも変換を調整できます。 これにより、各カラー クラスに既に存在するピクセルの数を確認し、最適なターゲットを選択するという答えが減ります。 

したがって、グリッドに表示されるすべての色を潜在的な最終色として試し、それぞれのコストを計算するだけです。 これらの候補の最小値が最適です。

 ## アルゴリズムのチュートリアル

 1. 2 x 2 のグリッドに各色が何回出現するかを数えます。 これにより、最大 4 文字にわたる頻度マップが得られます。 

その理由は、最終的な答えは、選択した最終色に既に一致するピクセルの数のみに依存するためです。 
2. グリッド内の個別の色ごとに、それを最終色の候補として扱います。 

他のすべてのピクセルをこの色に変換すると仮定します。 
3. 選択したターゲットカラーと頻度について`k`、変更する必要があるピクセル数を計算します。これは、`4 - k`。 
4. 各移動で最大 2 ピクセルまで再描画できるため、修正に必要な移動の最小数は`4 - k`ピクセルは次のとおりです。$$\lceil (4 - k) / 2 \rceil$$この式は、再ペイント可能なピクセルの可能な限り最良の組み合わせをキャプチャします。 
5. すべてのターゲット色の候補の最小値を取得し、出力します。 

### なぜ効果があるのか

 重要な特性は、最適なソリューションは最初に最終的な色を選択し、次に他のすべてをその色に変換すると見なすことができるということです。 最終的な均一性のみを考慮しているため、中間色はペア操作を有効にすること以外には重要ではありません。 すべての操作で不一致ピクセルの数が最大 2 つ減少します。変換可能なピクセルが 2 つ存在する場合にペアリングの機会を無駄にしないように、常に操作をスケジュールできます。 したがって、固定ターゲットのコストは、まだその色ではないピクセルが何個あるかによって完全に決定され、すべてのターゲットを試すことで最適な選択を逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        grid = [input().strip() for _ in range(2)]
        
        freq = {}
        for row in grid:
            for ch in row:
                freq[ch] = freq.get(ch, 0) + 1
        
        ans = 4
        for k in freq.values():
            need = 4 - k
            moves = (need + 1) // 2
            ans = min(ans, moves)
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず 2 x 2 グリッドを周波数辞書に圧縮します。 各エントリは、潜在的な最終色を表します。 このような色ごとに、既に正しいピクセルがいくつあるかを計算し、変更が必要なピクセルがいくつあるかを導き出します。 表現`(need + 1) // 2`は、各操作で最大 2 つの不一致ピクセルを修正できるため、必要な上限分割を実装します。 

答えはすべての候補色の最小値であり、これにより最も有利な最終的な色構成が確実に選択されます。

## 特殊なケース

 重要なエッジ ケースは、4 つのピクセルすべてがすでに同じ色を共有している場合です。 この状況では、周波数マップには値 4 を持つ単一のエントリが含まれています。計算により次のようになります。`4 - 4 = 0`、再描画が必要ないため、移動がゼロになります。これは要件に一致します。 

もう 1 つのケースは、色が 2 つのペアに均等に分割される場合です。`a a / b b`。 周波数マップは`a:2, b:2`。 どちらのターゲットでも、不一致の数は 2 で、天井分割により 1 手が与えられます。 このアルゴリズムは、同じ色の 2 つのピクセルを選択することにより、一致しない両方のピクセルを 1 回の操作で再描画できることを正確に捉えています。 

3 番目のケースは、すべての色が異なる場合です。 周波数マップには 1 のエントリが 4 つあります。どのターゲットでも 3 つの不一致が残ります。`(3 + 1) // 2 = 2`。 これは、1 回のペアリングの後、1 つのピクセルが残り、単独で処理する必要があり、2 回目の操作が必要であることを反映しています。
