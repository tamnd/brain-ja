 ## 解決策
 ## 問題の理解

 以下から数値の順列を構築する必要があります。`1`に`n`2つの条件付きで。 

最初の条件は、`p[p[i]] = i`あらゆるポジションに対して`i`。 順列を 2 回適用すると、元のインデックスに戻る必要があります。 これは、すべての要素がそのパートナーを指すことを意味します。 

2つ目の条件は、`p[i] != i`あらゆる人にとって`i`。 どの要素も独自の位置に留まることはできません。 

これらの条件を組み合わせると、置換が完全にインデックスのペア間のスワップで構成されるようになります。 もし`i`にマップします`j`、 それから`j`にマッピングし直す必要があります`i`、どちらも自分自身にマッピングできません。 

入力には単一の整数が含まれています`n`、順列のサイズ。 出力は 1 つの有効な完全順列、または`-1`そのような順列が存在しない場合。 

制約が非常に小さいので、`n ≤ 100`なので、パフォーマンスは心配ありません。 強引な攻撃でも技術的には適合します。 本当の課題は、条件の中に隠された数学的構造を認識することです。 

厄介なケースは、次のような奇数の値から発生します。`n`。 

たとえば:

 入力:```
1
```出力：```
-1
```可能な順列は 1 つだけです、`[1]`、しかし違反します`p[i] != i`。 

もう一つの重要なケース:

 入力:```
3
```不用意なアプローチをすると、次のようなことが起こる可能性があります。```
2 1 3
```最初の 2 つのポジションは有効なスワップを形成しますが、ポジション`3`それ自体にマップされますが、これは禁止されています。 

有効な最小のケースは次のとおりです。 

入力:```
2
```出力：```
2 1
```ここ：`p[1] = 2`

`p[2] = 1`順列を 2 回適用すると、元のインデックスに戻り、位置は固定されません。 

## アプローチ

 ブルートフォースソリューションでは、サイズのあらゆる順列が生成されます。`n`両方の条件を満たしているかどうかを確認します。 チェック自体は簡単です。 インデックスごとに`i`、それを確認してください`p[p[i]] == i`そして`p[i] != i`。 

これは制約が小さいため機能しますが、階乗増加はすぐに不合理になります。 平`10!`すでに 300 万以上の順列を意味します。 条件が何を意味するのかを理解すれば、完全な総当たり検索は必要ありません。 

重要な観察は、順列全体が互いに素なペアで構成されている必要があるということです。 

仮定する`p[i] = j`。 以来`p[p[i]] = i`、すぐに次の結果が得られます。```
p[j] = i
```したがって、すべての要素は 2 サイクルに属している必要があります。```
i <-> j
```単一要素サイクルは禁止されています。`p[i] != i`。 

つまり、配列をペアに分割する必要があります。 これは次の場合にのみ可能です`n`は均等です。 

それが見えてしまえば、構築は簡単になります。 隣接する数字を交換するだけです。```
1 <-> 2
3 <-> 4
5 <-> 6
...
```たとえば、次のようなとき`n = 6`:```
2 1 4 3 6 5
```順列を 2 回適用すると、すべてのインデックスがそれ自体に返されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × n) | O(n) | 概念的には遅すぎる |
 | 最適 | O(n) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. かどうかを確認します。`n`奇数です。 

もし`n`奇数です、印刷してください`-1`そしてやめてください。 完全な順列は完全にペアで構成されているため、奇数の要素は常に 1 つのペアになっていない要素を残します。 
3. それ以外の場合は、以下の数値を反復処理します。`1`に`n`の段階で`2`。 
4. ペアごとに`(i, i + 1)`、出力:```
i + 1, i
```これにより、2 サイクルが作成されます。```
i -> i + 1
i + 1 -> i
```5. 構築された順列を出力します。 

### なぜ効果があるのか

 すべてのペア`(i, i + 1)`スワップを形成します。 ペア内の要素については、順列を一度適用すると相手に移動し、再度適用すると元の位置に戻ります。 

例えば：```
p[i] = i + 1
p[i + 1] = i
```それから：```
p[p[i]] = p[i + 1] = i
```すべての要素が別の要素と交換されるため、要素自体にマップされる要素はありません。 

順列全体は独立した 2 サイクルで構成されるため、条件はすべてのインデックスに当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n % 2 == 1:
        print(-1)
        return

    ans = []

    for i in range(1, n + 1, 2):
        ans.append(str(i + 1))
        ans.append(str(i))

    print(" ".join(ans))

solve()
```コードで処理される最初の条件は、`n`奇数です。 奇数サイズのセットはペアに完全に分割できないため、完全な順列は存在しません。 

ループは次のように進みます`2`インデックスをペアで処理するため、毎回。 すべてのペアについて`(i, i + 1)`、数字は逆の順序で追加されます。 これにより、必要な 2 サイクル構造が直接作成されます。 

この実装では、出力の構築中に整数から文字列への変換が繰り返されることを避けるために、リスト内の文字列を使用します。 

境界は小さいですが、ソリューションは線形時間で実行され、競技プログラミングの規約に準拠した高速入力スタイルを使用します。
