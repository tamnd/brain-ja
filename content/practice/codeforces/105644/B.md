 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を扱い、作成される「不良」部分配列の数によって各順列を分類します。 サブ配列の最大要素がそのサブ配列の両端の一方にある場合、そのサブ配列は不良とみなされます。 つまり、連続するセグメントを見たときに、最大値がセグメントの左端または右端の要素であれば、そのセグメントがコストに寄与します。 

サイズ n のすべての順列の中で、そのような不良サブ配列の可能な最小数が存在します。 この最小値を達成する場合、置換はバランスが取れていると呼ばれます。 タスクは、そのような順列を 1 つ構築するだけではなく、それらを辞書順に列挙することです。l 番目に小さい平衡順列と、k 番目に大きい平衡順列が必要です。 いずれかのインデックスが平衡順列の数を超えた場合、その側に -1 を返します。 

入力サイズは最大 100000 に達し、l と k は 10^18 までの大きさになる可能性があります。これにより、場合によっては平衡順列の数が膨大になるか、明示的に生成せずにそれらを数えて組み合わせて構築できる必要があることがすぐにわかります。 置換を列挙しようとしたり、さらには DP を試みたりする解決策は不可能です。 O(n^2) でさえすでにタイトであるため、意図した構造では、問題を組み合わせ計数または非常に厳格な置換群を使用した決定論的な構造に還元する必要があります。 

微妙な特殊なケースとして、一部の n については答えがまったく存在しない可能性があります。 これは、特定のサイズでは、どの順列も不安定な部分配列の理論上の最小数に達しないことを意味します。 このような場合、片側のみに障害が発生した場合でも、両方の出力は -1 になります。 

もう 1 つの重要なコーナーは、10^18 の制限を持つ辞書編集的なインデックス作成です。 有効な順列の数が l または k より小さい場合は、完全な構築を試行せずに早期に検出する必要があります。 

## アプローチ

 ブルートフォースの観点は単純ですが、完全に実行不可能です。 すべての n を生成できます。 順列を作成し、すべての O(n^2) 部分配列をスキャンしてそれぞれの不安定な部分配列の数を計算し、最適なものを選択します。 たとえ最小値が事前に何らかの形でわかっていたとしても、それらの順列を数えて順序付けするには、階乗スケールの列挙が必要になります。 これはすでに 10^5 を超えています。 限界をはるかに超えた操作。 

重要な構造的観察は、不安定性の定義は最大値が部分配列内のどこに位置するかのみに依存するということです。 順列を修正すると、すべての部分配列の最大値が決定されるため、より小さい値と比較して、より大きな値がどこに表示されるかを実際に制御することになります。 

重要な単純化は、最適な置換では、大きな要素が境界最大値になることが多すぎる構成を回避する必要があるということです。 これにより、非常に厳格な配置ルールが強制されます。順列が増加し始めると、大きな要素を配置するのが早すぎたり遅すぎたりすると、境界最大値となる部分配列が多数作成されます。 このようなイベントを最小限に抑える唯一の方法は、順列の方向が変わる単一の制御された遷移点を持つ単調な構造を強制することです。 その移行点は、両側で小さい要素の数と大きい要素の数のバランスをとることによって強制されます。これにより、構造上の自由度が減り、基本的に、構造化された順序で残りの要素に切り替える前にプレフィックスをどこまで拡張するかを選択することになります。 

この構造が理解されると、バランスのとれた順列のセットは、分割点を選択し、固定ルールに従って一方の側を昇順に、もう一方の側を降順に埋めることによって生成される小さなファミリーに分解されます。 これが辞書編集インデックス作成を可能にするものです。私たちはもはや任意の順列を列挙するのではなく、各プレフィックスの決定によって残りが決定論的に決定される、制約された組み合わせファミリーの中から選択します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | 順列と部分配列に対するブルート フォース | O(n! · n^2) | O(n) | 遅すぎる |
 | 組み合わせインデックスによる構造化された構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定された n に対してバランスの取れた順列が存在するかどうかを判断します。 これは有効な構造の構造を通じて暗黙的に行われ、特定の n のみが実現可能な分割構成を許可します。 バランス条件を満たす構成がない場合は、すぐに -1 が出力されます。 

2. すべてのバランスのとれた順列の構造形式を特定します。 順列は、要素 1 から x が厳密に昇順でプレフィックスを占有し、要素 x+1 から n が厳密に降順でサフィックスを占めるように分割点 x を選択することによって完全に決定されます。 バランス条件により、x の許容範囲が固定されます。 

3. 有効な分割点と、その分割によって引き起こされる置換のファミリーのサイズを事前計算します。 x が固定されると構造は厳密になるため、有効な x はそれぞれ 1 つの順列にのみ寄与します。 

4. l 番目の辞書編集上最小の順列を構築するには、可能な分割点を昇順に繰り返します。 各候補について、その寄与の大きさを l と比較します。 正しいブロックが見つかったら、x を修正し、置換を直接構築します。 

5. 構築は、選択した分割に従って、プレフィックスに残りの最小の数字を昇順で埋め、サフィックスに残りの最大の数字を降順で埋めることによって行われます。 

6. 辞書編集上最大の順列の場合は、l の代わりに k を使用して、同じロジックを繰り返しますが、分割点を逆の順序でたどります。 

7. いずれかの点で l または k が有効な順列の総数を超えた場合、その側に対して -1 を返します。 

### なぜ効果があるのか

 重要な不変条件は、分割点が固定されると、順序にずれがあると、セグメント境界に余分な極大値が導入されるため、すぐに追加の不安定な部分配列が作成されるということです。 これは、すべてのバランスの取れた置換が有効な分割構成に一意に対応し、2 つの異なる内部並べ替えが最適性を維持できないことを意味します。 その結果、検索空間は分割された選択肢の離散的に順序付けられたセットになり、辞書編集的な順序付けはこれらの選択肢の増減に合わせて行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(n, split):
    res = list(range(1, split + 1))
    res += list(range(n, split, -1))
    return res

def solve_one(n, idx, reverse=False):
    # compute possible splits
    splits = []
    for s in range(1, n):
        splits.append(s)

    if reverse:
        splits = splits[::-1]

    for s in splits:
        # each split gives exactly 1 permutation
        if idx == 1:
            return build(n, s)
        idx -= 1

    return None

def solve():
    n, l, k = map(int, input().split())

    ans1 = solve_one(n, l, reverse=False)
    ans2 = solve_one(n, k, reverse=True)

    if ans1 is None:
        print(-1)
    else:
        print(*ans1)

    if ans2 is None:
        print(-1)
    else:
        print(*ans2)

if __name__ == "__main__":
    solve()
```この実装は、有効な各分割点が単一の正規順列を生成するという事実に依存しています。 ヘルパー関数`build`増加するプレフィックスと減少するサフィックスを連結することにより、O(n) 時間で直接置換を構築します。 

わかりやすくするために、辞書編集的な選択ロジックは分離されています。1 つのパスでは l 番目に小さいものを順方向にカウントし、もう 1 つのパスでは k 番目に大きいものを逆方向にカウントします。 ここでの主な落とし穴は、各分割が 1 つの順列に寄与することを忘れていることです。これにより、インデックス付けが階乗ではなく線形になります。 

## 実用的な例

 n = 4、l = 2 について考えてみましょう。 

有効な分割ポイントを列挙します。 

| ステップ | 分割 | 残り l | アクション |
 |---|---|---|---|
 | 1 | 1 | 2→1 | スキップ |
 | 2 | 2 | 1 | 選択 |

 分割 = 2 で、次のように構築します。`[1, 2] + [4, 3]`、与える`[1, 2, 4, 3]`。 

これは、辞書編集的な順序付けが分割点のスキャンにどのように直接対応するかを示しています。 

ここで、n = 3、l = 1 について考えてみましょう。 

| ステップ | 分割 | 残り l | アクション |
 |---|---|---|---|
 | 1 | 1 | 1 | 選択 |

 結果は`[1] + [3, 2]`=`[1, 3, 2]`。 

これは、最小の分割がすでに辞書編集上最初にバランスのとれた順列を生成していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | 建設あたり O(n) | 各順列は 2 つの線形シーケンスを埋めることによって構築されます。 
| スペース | O(n) | 順列配列 | を格納します。 

n ≤ 10^5 という制約により、答えごとに線形構築を快適に行うことができます。 多くても 2 つの順列しか構築しないため、解は十分に制限内に収まります。

 ## 特殊なケース

 n = 1 の場合、有効な分割点がないため、アルゴリズムは直接 -1 を出力し、内部最大値制約を使用して部分配列を形成できないという事実と一致します。 

3 などの小さい n の場合、唯一の有効な構築が強制され、分割メカニズムは単一の順列にきれいに縮退します。 分割列挙では候補が 1 つだけ生成されるため、アルゴリズムはこれを自然に処理します。 

l または k が有効な分割数を超える場合、走査はすべての候補を使い果たし、-1 を返します。 これにより、誤ったラップアラウンドや部分的な構築が防止されます。 

n が大きい場合でも、部分配列のシミュレーションやコストの再計算は行わず、決定論的なプレフィックスとサフィックスはクエリごとに 1 回だけ生成されるため、構築は依然として線形のままです。
