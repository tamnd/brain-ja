 ## 解決策
 ## 問題の理解

 この問題では、宇宙船が原点から出発し、クエリごとに選択された固定直線方向に移動する連続 2D 平面に配置されます。 同時に、飛行機内には複数の感染源が点在しています。 各感染は単位速度で全方向に均一に拡大するため、\(t\)、各ソースは半径の円をカバーします\(t\)初期位置の中心に配置されます。 

宇宙船はまた、各クエリで指定された方向ベクトルによって決定される光線に沿って単位速度で移動します。 各クエリにはしきい値も与えられます\(k\)。 宇宙船は、以下の数が少ない限り安全とみなされます。\(k\)感染地域にはそれが含まれています。 現在の位置を覆う感染サークルの数が少なくとも1つになった瞬間\(k\)、船は破壊されます。 これが決して起こらない場合、答えは無限に生き残ることです。 

各クエリは独立しています。感染ポイントは同じですが、移動方向としきい値が異なります。 

重要な問題は、「感染サークル内にいること」が時間の経過に伴う船の位置と感染​​の拡大速度の両方に依存するため、各感染がラインの軌跡に沿った時間依存の制約を効果的に定義することです。 

制約は以下を示します\(10^5\)感染ポイントと\(10^5\)これにより、クエリごとに単純に距離を再計算することが排除されます。 クエリごとにすべての感染を評価するソリューションは、直接 \(O(nq)\) につながりますが、これは遅すぎます。\(10^{10}\)操作。 

微妙なエッジ ケースは、方向の縮退から発生します。クエリの方向が感染ベクトルの方向に非常に近い場合、船舶が円の境界に出入りする時刻が非常に近くなるか、または一致する可能性があり、浮動小数点比較は慎重に処理する必要があります。 もう 1 つの重要なケースは次のような場合です。\(k = 1\)なぜなら、答えは単に単一の感染サークルが初めて船を覆ったときであり、集合的な状態ではないからです。 

## アプローチ

 ブルート フォース シミュレーションでは、クエリごとに船の動きをシミュレートし、現在のポイントが含まれる感染サークルの数を継続的に追跡します。 感染点が固定されている場合、光線に沿って時間的に二次方程式を解くことによって、船が拡大円に入る時期を計算できます。 それぞれの感染は、船が拡大する円の中に入る時間間隔に影響を与えます。 破壊時刻とは、少なくとも次の時点の最も早い瞬間です。\(k\)このような間隔が重なっています。 

単一のクエリの場合、これらすべての間隔を構築するには \(O(n)\) のコストがかかり、その後、エンドポイントの並べ替えによる重複の処理には \(O(n \log n)\) のコストがかかります。 すべてのクエリでこれは \(O(nq \log n)\) となり、非常に遅すぎます。 

重要な構造的観察は、各感染点が光線に沿った 1D 制約を引き起こすということです。つまり、クエリごとの任意のジオメトリを扱っているのではなく、線への投影を扱っているのです。 船の軌道は単位方向ベクトルによって完全に決定されるため、各感染点は時間のスカラー関数に還元できます。船と感染中心間の距離の二乗は、次の二次関数になります。\(t\)。 感染サークル内に入る条件は二次不等式に単純化され、最大でも 1 つの連続した時間間隔が得られます。 

したがって、各感染は、固定クエリの時間軸上の単一の間隔に寄与します。 問題は、最小時間を見つけることです。\(t\)少なくともそうなるように\(k\)間隔が重なる\(t\)。 これは、直線上の間隔に関する古典的な「k 番目のオーバーラップ イベント」問題です。 

次の改善点は、クエリごとにすべての間隔を完全に再計算することを避けることです。 感染とクエリのペアごとに高速な評価を可能にする方法でジオメトリを事前計算できますが、それでも、各クエリは間隔を生成するためにすべての感染を効果的にスキャンする必要があるため、主な最適化は定数を減らし、効率的な二次解法を使用することです。 意図されたソリューションは、高度なデータ構造ではなく、慎重な分析の簡素化に依存しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | タイム ステップごとのブルート フォース シミュレーション | O(Tnq) | お(1) | 不可能 |
 | クエリ間隔ごとの構築 + スイープ | クエリごとに O(n log n) | O(n) | 遅すぎる |
 | クエリごとの感染ごとの二次削減 | O(nq) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 クエリ方向ベクトル \(d = (dx, dy)\) を修正します。 時間における船の位置が正規化されるようにします。\(t\)は単に \(p(t) = t \cdot d\) です。ここで、\(|d| = 1\)。 

各感染点 \(i = (x_i, y_i)\) について、二乗距離を考慮します。\[
|p(t) - i|^2 = |t d - i|^2 = t^2 - 2t(d \cdot i) + |i|^2.
\]せいぜいこの状態になると感染が船を覆う\(t^2\)、感染半径が\(t\)したがって、次のことが必要です。\[
t^2 - 2t(d \cdot i) + |i|^2 \le t^2.
\]の\(t^2\)条件はキャンセルされ、終了します:\[
-2t(d \cdot i) + |i|^2 \le 0,
\]これは次のように単純化されます。\[
t \ge \frac{|i|^2}{2(d \cdot i)}.
\]これはすでにジオメトリが大幅に崩壊していることを示しています。ただし、各感染は単一のしきい値時間 (感染が船を覆い始めるとき) に寄与します。\(d \cdot i > 0\)。 もし\(d \cdot i \le 0\)、船は遠ざかるか直角に移動するため、感染が追いつくことはありません。 

現在、問題は、以前または一度にどれだけの感染が「活性化」したかを、時間の経過とともに追跡することになります。\(t\)。 これらのアクティベーション時間を並べ替えます。 

特定のクエリしきい値の場合\(k\)、答えは、\(k\)- 番目に小さい有効なアクティブ化時間。 未満の場合\(k\)感染症が活性化しても、船は永遠に存続します。 

## なぜ機能するのか

 のキャンセル\(t^2\)これは重要な構造特性です。船の移動と感染の拡大は同じ速度で起こります。 この対称性により、二次項が削除され、あらゆる感​​染の影響が時間の経過とともに単一の線形しきい値にまで減少します。 このため、各感染は最大でも 1 つの「イベント時間」に寄与し、破壊条件はこれらのイベント時間にわたる純粋な順序統計になります。 すでにアクティブ化されている感染数をカウントすることを除いて、感染間の相互作用はタイミングに影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    q = int(input())

    for _ in range(q):
        x, y, k = map(int, input().split())

        dx, dy = x, y
        # normalize direction
        norm = (dx * dx + dy * dy) ** 0.5
        dx /= norm
        dy /= norm

        times = []

        for xi, yi in pts:
            dot = xi * dx + yi * dy
            if dot <= 0:
                continue
            t = (xi * xi + yi * yi) / (2 * dot)
            times.append(t)

        times.sort()

        if len(times) < k:
            print(-1)
        else:
            print(times[k - 1])

if __name__ == "__main__":
    solve()
```このソリューションは、各クエリを個別に処理します。 すべての感染ポイントについて、船が進行方向に感染の「先」に到達するかどうかを内積を介して計算します。 そうでない場合、その感染は無視されます。 それ以外の場合、単一のしきい値時間は、封じ込め条件の直接代数的単純化から計算されます。 

結果の時間をソートすると、k 番目の破壊イベントを直接答えることができます。 

よくある落とし穴は、方向の正規化はドット スケーリングの一貫性の正確さのみに関係するということを忘れていることです。 もう 1 つは、特にドット積が非常に小さい場合に、除算ステップで浮動小数点精度を誤って処理することです。 との比較\(k\)順序のみに依存するため、安定した並べ替え動作が不可欠です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | \(O(n \log n)\) クエリごと | 各クエリは n 個のドット積を計算し、結果の時間を並べ替えます。 
| スペース | \(O(n)\) | 単一のクエリのアクティブ化時間を保存します。 

与えられた\(n, q \le 10^5\)、これは実現可能性の限界にあり、厳密な実装と一定係数の効率に依存しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():

        for _ in range(q):
            x, y, k = map(int, input().split())

            norm = math.sqrt(dx * dx + dy * dy)

                times.append(t)

            times.sort()
            if len(times) < k:
                print(-1)
            else:
                print(times[k - 1])

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 すべての感染点が方向ベクトルの背後にある場合、すべての内積は非正になります。 その場合、アクティベーション リストは空であり、次のクエリは実行されません。\(k \ge 1\)-1 を返します。 アルゴリズムは正確に候補時間を生成せず、生存を即座に報告します。 

方向ベクトルの大きさが非常に小さい場合、正規化により内積の数値的不安定が防止されます。 正規化を行わないと、しきい値時間のスケーリングが正しく行われず、順序が歪み、誤った k 番目の選択が生成されます。 

複数の感染によって同一のアクティベーション時間が発生した場合でも、ソートによってそれらが正しく処理され、重複が正しくオーバーラップ数に寄与し、k 番目のイベント解釈の正確さが維持されます。
