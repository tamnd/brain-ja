 ## 解決策
 ## 問題の理解

 文字で構成される 1 つの文字列が与えられ、そこからいくつの異なる部分列を形成できるかを判断することが課題となります。 部分シーケンスは、残りの文字の順序を変更せずに一部の文字を削除することによって取得されます。 2 つのサブシーケンスは、長さが同じであっても、少なくとも 1 つの位置または文字が異なる場合、異なるものとみなされます。 

これについて考えると便利な方法は、文字列内のすべての文字が、それをサブシーケンスに取り込むかスキップするかの二者決定を提供するということです。 ただし、繰り返される文字は異なる選択パターンを通じて同一のサブシーケンスを作成するため、この素朴な見方は非常に重要です。 目標は、結果として得られる一意の文字列のみをカウントすることです。 

入力はこの 1 つの文字列だけなので、全体の難しさは、繰り返しを処理し、重複が複数回カウントされないようにすることにあります。 出力は、個別のサブシーケンスの数を表す単一の整数であり、通常は規則に応じて空のサブシーケンスが含まれます。 

制約の影響は直接的です。 文字列の長さが約 10^5 までの場合、部分列の単純空間は 2^n であるため、部分列を列挙することは不可能です。 それらを保存するだけでも、制限時間のずっと前にメモリ制限を超えてしまいます。 これにより、各文字が一定時間の更新で 1 回または数回処理される、線形または線形に近い DP アプローチが強制されます。 

文字が繰り返される場合、微妙な失敗例が表示されます。 

たとえば、文字列「aa」について考えてみましょう。 単純な 2^n 推論では、「」、「a」、「a」、「aa」の 4 つの部分列が生成されます。 重複した「a」が 2 回出現しますが、カウントされるのは 1 つの異なるサブシーケンスのみです。 単純なビットマスクまたは再帰アプローチでは、両方とも誤ってカウントされます。 

もう 1 つのエッジ ケースは、「abab」のような文字列です。 多くのサブシーケンスは異なるインデックス選択にわたって繰り返されるため、過剰なカウントを修正するメカニズムがなければ、単純なカウントはすぐに正確性から乖離します。 

## アプローチ

 ブルートフォースのアイデアは、すべてのサブシーケンスを再帰的に、またはビットマスクによって生成することです。 位置ごとに、文字を含めるか除外し、2^n 個のサブシーケンスを生成します。 生成された各文字列をセットに挿入して重複を排除します。 

すべてのサブシーケンスが明示的に構築され、セットの一意性が保証されるため、これは正しいです。 この問題は、n が大きくなるとすぐに現れます。 n = 20 では、すでに約 100 万個のサブシーケンスがあり、これはほとんど管理できません。 n = 100000 では、サブシーケンスの数が天文学的に多くなるため、このアプローチは時間的にもメモリ的にも完全に実行不可能になります。 

重要な観察は、各文字が寄与する新しいサブシーケンスの数を追跡しながら、段階的に答えを構築できるということです。 新しい文字を処理する場合、既存のすべてのサブシーケンスはその文字を無視するか、含めることができ、カウントが 2 倍になります。 ただし、そのキャラクターが以前に出現したことがある場合は、以前の出現によりすでにカウントされているサブシーケンスの寄与を減算する必要があります。 

これは古典的な再発につながります。 dp[i] を、位置 i までのプレフィックスを使用した個別のサブシーケンスの数とする。 新しい文字 c を位置 i に追加すると、dp[i−1] のすべてのサブシーケンスが 2 つのバリアントを生成するため、2 * dp[i−1] から開始します。 しかし、c が位置 j に以前に出現した場合、j より前に形成された部分列はその前の c を含むことをすでに考慮しているため、dp[j−1] を減算します。 これにより、文字の繰り返しにより同一になるサブシーケンスを二重にカウントすることが回避されます。 

これを効率的に実装するために、すべての文字の最終出現インデックスを維持します。 これにより、ステップごとに一定時間の補正が可能になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのサブシーケンスを生成) | O(2^n) | O(2^n) | 遅すぎる |
 | 最後の出現を追跡する DP | O(n) | O(σ) | 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミング配列と各文字が最後に出現した場所の記録を維持しながら、文字列を左から右に処理します。 

1. 空のサブシーケンスを表すために dp[0] = 1 を初期化します。 これは、文字が選択されていない基本状態として機能します。 
2. 各文字が最後に出現した位置を保存する辞書を最後に保持します。 
3. 1 から n までの各位置 i について、文字 c を読み取ります。 
4. dp[i] = 2 * dp[i−1] を計算します。 これは、以前のすべてのサブシーケンスにわたって新しい文字を含めるか除外するかを考慮します。 
5. c が位置 j に以前に出現した場合は、dp[i] から dp[j−1] を減算します。 これにより、c が以前に処理されたときにすでにカウントされていた重複したサブシーケンスが削除されます。 
6. i を c の最後の出現として保存します。 
7. 文字列の終わりまで続けます。 
8. 最終的な答えは dp[n] です。 

減算ステップは重要な修正です。 これがないと、同じ文字の異なる出現を使用して同じ論理サブシーケンスが形成される可能性があるため、繰り返しの文字によって生成された同一のサブシーケンスが複数回カウントされることになります。 

### なぜ効果があるのか

 重要な不変条件は、dp[i] が常に i で終わる接頭辞を使用して形成された個別のサブシーケンスの数を表すことです。 2 倍化ステップでは、前のサブシーケンスを拡張するすべての方法が考慮されますが、減算では、最後の文字が繰り返し出現するサブシーケンスが複数回カウントされないことが保証されます。 それぞれの個別のサブシーケンスは、その最後の文字が選択される最も古い位置に関連付けられ、一意の構築パスが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    MOD = 10**9 + 7

    dp = [0] * (n + 1)
    dp[0] = 1

    last = {}

    for i in range(1, n + 1):
        c = s[i - 1]
        dp[i] = (2 * dp[i - 1]) % MOD

        if c in last:
            j = last[c]
            dp[i] = (dp[i] - dp[j - 1]) % MOD

        last[c] = i

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```実装は繰り返しの後に直接続きます。 dp 配列は各プレフィックスのカウントを保存し、最後に文字ごとに一定時間内にオーバーカウントを修正できることを保証します。 モジュロ演算は各ステップで適用され、オーバーフローを防止し、値を範囲内に保ちます。 

実装の微妙な詳細はインデックス作成です。 dp 配列は文字列に対して 1 のインデックスが付いているため、dp[i] は s[:i] に対応します。 これにより、減算 dp[j−1] がプレフィックス境界と一致します。 

## 実用的な例

 文字列「aba」について考えてみましょう。 

dpと最後を段階的に追跡します。 

| 私 | 文字 | dp[i-1] | 修正前の dp[i] | 最後に発生した | 訂正 | dp[i] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | | 1 | 2 | 新しい | なし | 2 |
 | 2 | b | 2 | 4 | 新しい | なし | 4 |
 | 3 | | 4 | 8 | 1 | dp[0]=1 を減算する | 7 |

 最終的に、結果は 7 つの異なるサブシーケンスになります。 

これは、位置 3 で「a」を繰り返すと、最初の「a」がすでに含まれているサブシーケンスがどのように複製されるかを示しています。 

ここで「aa」について考えてみましょう。 

| 私 | 文字 | dp[i-1] | 修正前の dp[i] | 最後に発生した | 訂正 | dp[i] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | | 1 | 2 | 新しい | なし | 2 |
 | 2 | | 2 | 4 | 1 | dp[0]=1 を減算する | 3 |

 最後のセットは「」、「a」、「aa」で、正しいことが確認されます。 重複した 1 文字の部分シーケンスは、減算によって暗黙的に削除されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は O(1) 辞書演算で 1 回処理されます。 
| スペース | O(σ) | それぞれの個別の文字が最後に出現したときの記憶域 |

 このアルゴリズムは、入力文字列に対して線形時間で実行されます。これは、二次関数または指数関数法が大規模な入力の制限を超えることを考慮すると必要です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import defaultdict

    def solve():
        s = sys.stdin.readline().strip()
        n = len(s)
        MOD = 10**9 + 7

        dp = [0] * (n + 1)
        dp[0] = 1

        last = {}

        for i in range(1, n + 1):
            c = s[i - 1]
            dp[i] = (2 * dp[i - 1]) % MOD
            if c in last:
                j = last[c]
                dp[i] = (dp[i] - dp[j - 1]) % MOD
            last[c] = i

        return str(dp[n] % MOD)

    return solve()

# minimum size
assert run("a\n") == "2"

# all equal characters
assert run("aaa\n") == "4"

# alternating pattern
assert run("abab\n") == "15"

# no repetition
assert run("abc\n") == "8"

# single character
assert run("z\n") == "2"

 ## 特殊なケース

 「aaaa」のような文字列の場合、アルゴリズムは以前の寄与を繰り返し減算します。 各ステップで、最後の出現が前方に移動し、各サブシーケンスの最も古い構成のみが確実に保持されます。 

簡単に追跡すると、dp は 2、3、4、5 → と進化し、dp[0]、dp[1]、dp[2] を使用して毎回補正が適用され、最終結果は 5 になります。これは、「」、「a」、「aa」、「aaa」、「aaaa」に対応します。 

「abcd」などの繰り返し文字を含まない文字列の場合、減算はトリガーされないため、dp は各ステップで単純に 2 倍になります。 これにより、重複が問題にならない場合、反復が完全な 2^n 構造に正しく縮退することが確認されます。
