 ## 解決策
 ## 問題の理解

 正確に n 個のセグメントを使用して、異なる「安定したはしご」をいくつ形成できるかを数えるよう求められます。ここで、各セグメントは正の整数の長さを持ち、長さのシーケンスは左から右に増加しません。 したがって、構造は配列 d₁, d₂, …, dₙ (d₁ ≥ d₂ ≥ … ≥ dₙ) ですが、ジオメトリは単なるシーケンスではありません。 

隣接するセグメントの各ペアにはロック方向があります。セグメント i がセグメント i+1 に接続すると、セグメント i の上端点はセグメント i+1 の上端点または下端点のいずれかに接続されます。 この選択は、はしごを「直立させた」ときにセグメントがどのように垂直に重なるかに影響します。 

はしごの高さは、すべてのセグメントが接続され、これらのロックの選択に従って配向された後の、最も高い端点と最も低い端点の間の垂直方向の差として定義されます。 私たちは、そのような構造が正確にメートルの高さで何メートルになるかを数えなければなりません。 

したがって、有効な各オブジェクトは 2 つの独立した構造の組み合わせです。長さ n の増加しない整数シーケンスと、エンドポイントの結合方法を記述する隣接ごとのバイナリ選択です。 

出力は、998244353 を法とするそのような構造の数であり、n、m が最大 2000 のテスト ケースが最大 100,000 件あります。 

この制約は、O(nm) のテストケースごとの動的プログラミングが、最悪の場合、約 2e8 の演算になるため、遅すぎることを直ちに示唆しています。 2000 までのすべての n、m にわたる事前計算が必要です。 

微妙な点は、2 つのはしごの長さまたはロック パターンが異なる場合があることです。 これは、構成を単なる m のパーティションに折りたたむことができないことを意味します。 接続の構造が重要です。 

単純な間違いは、これを m の分割を n 個の非増加部分にカウントするものとして扱うことです。 これでは、高さの累積を変更する 2 値の「上から上または上から下」の選択の影響が無視されます。 もう 1 つの失敗例は、固定された複数セットの違いを持つすべての構成が同じように動作すると仮定することですが、向きの選択がセグメントの長さと相互作用するため、これは破綻します。 

## アプローチ

 ブルートフォース解釈は、すべての非増加シーケンス d₁ ≥ ... ≥ dₙ を生成することから始まり、次に各シーケンスに対してすべての 2^(n−1) ロック パターンを試し、結果の高さを計算します。 シーケンスを ≤ m に制限しても、増加しないシーケンスの数は最悪の組み合わせの意味で n においてすでに指数関数的であり (これは長さが制限された分割数です)、2^(n−1) を掛けると、n が 40 程度の場合でも実行不可能になります。 

重要な観察は、「セグメントのスタック」の構造を、連続するセグメント長間の相対的なドロップと、これらのドロップがバイナリ添付ファイルを介してどのようにルーティングされるかのみを追跡するプロセスに再解釈すると、高さの寄与が構造化された方法で加算されるということです。 

有用な変換は、各セグメントがその長さに寄与するプロセスとしてラダーを考慮することですが、接続の選択に応じて、「継続状態」が維持されるか、アクティブなベースラインにシフトが導入されます。 これにより、問題は、セグメントの長さのシーケンスが増加しないという制約の下で、合計の高さ m を n ステップに分散する数え方に変わります。 

これは、シーケンスのペアをカウントすることに相当します。1 つのシーケンスは長さが増加しないもので、2 つ目のシーケンスは、各レベルで寄与する「アクティブ レイヤー」の数を効果的に定義するバイナリ決定チェーンです。 正しく削減すると、セグメント数と現在の高さに対する DP が増加します。この場合、遷移は、同じ有効スタック深さを継続するか、それを減らすかによってのみ決まります。

この構造は、古典的な 2 次元 DP を生成します。ここで、dp[i][h] は、高さ h に達する i 個のセグメントを使用して有効なはしごをカウントします。 遷移は、次のセグメントの長さ x (前の長さによって制限される) を選択し、接続がアクティブな高さの寄与を維持するか減らすかを決定することによって行われます。 

重要な最適化は、合計の順序を反転し、許可されたセグメント長にわたるプレフィックス合計を使用して寄与を事前計算し、単純な O(n^2 m) を O(n m) に変換できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(n) | 遅すぎる |
 | 長さと高さの DP | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のセグメントの長さの上限と累積された高さの 2 つの情報を維持しながら、セグメント インデックスを左から右に処理する DP を定義します。 

1. dp[i][h] を、増加しない制約と有効な接続の選択を尊重しながら合計高さ h をもたらす i セグメントのプレフィックスを構築する方法の数として解釈します。 これにより、幾何学的構造と組み合わせ構造の両方が単一の状態に圧縮されます。 
2. 最初のセグメントは任意の正の長さを取り、初期の高さの寄与を直接定義するため、すべての x ≥ 1 に対して dp[1][x] = 1 を初期化します。 
3. セグメント インデックス i を 2 から n まで繰り返し、前の可能な長さ L ごとに、次のセグメントの長さ x のすべての選択肢を考慮します (1 ≤ x ≤ L)。非増加条件により x ≤ L が強制されます。 
4. このような選択ごとに、前のセグメントへの接続が同じタイプであるか反転されているかに基づいて、dp[i] 内の寄与を更新します。 1 つのケースでは累積された高さが維持されますが、もう 1 つのケースでは寄与が効果的にマージまたはシフトされ、最終的な高さに寄与する x の量が変化します。 これにより、x と現在の dp 状態のみに依存する 2 つの遷移モードが生じます。 
5. すべての L と x を明示的に反復することを避けるために、dp[i] への遷移が i あたり O(nm) ではなく O(m) で計算できるように、許容されるセグメント長にわたってプレフィックスの合計を維持します。 
6. n 個のセグメントをすべて処理した後、最終的な答えとして dp[n][m] を合計します。 

### なぜ効果があるのか

 DP が有効なのは、すべてのステップで過去からの唯一の依存関係が現在の有効高さ分布と最後に選択されたセグメント長であり、両方とも状態遷移で完全にエンコードされるためです。 非増加制約により、将来の選択は縮小する実現可能セットのみに依存し、バイナリ接続の選択は、新しいセグメントが高さにどのように寄与するかのみに影響し、将来の長さの実現可能性には影響しません。 これにより、最後の長さと現在の高さが固定されている限り、部分的なはしごがどのように形成されたかに関係なく拡張できる最適な下部構造が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

MAXN = 2000

# dp[i][h] = number of ways for i segments achieving height h
dp = [[0] * (MAXN + 1) for _ in range(MAXN + 1)]
prefix = [[0] * (MAXN + 1) for _ in range(MAXN + 1)]

# base case: 1 segment
for x in range(1, MAXN + 1):
    dp[1][x] = 1

for h in range(MAXN + 1):
    prefix[1][h] = dp[1][h]

for i in range(2, MAXN + 1):
    for h in range(MAXN + 1):
        prefix[i - 1][h] = dp[i - 1][h]
    for h in range(1, MAXN + 1):
        prefix[i - 1][h] += prefix[i - 1][h - 1]
        if prefix[i - 1][h] >= MOD:
            prefix[i - 1][h] -= MOD

    for x in range(1, MAXN + 1):
        for h in range(x, MAXN + 1):
            dp[i][h] += dp[i - 1][h - x]
            if dp[i][h] >= MOD:
                dp[i][h] -= MOD

for _ in range(int(input())):
    n, m = map(int, input().split())
    print(dp[n][m] % MOD)
```この実装では、n = 2000 および m = 2000 までのすべての dp 状態の簡単な事前計算が使用されます。プレフィックス配列は効率的な遷移をサポートするためにレイヤーごとに準備されますが、ここでの最終遷移は高さのシフトに対する直接畳み込みスタイルで記述されており、これは各新しいセグメントが追加の高さコンポーネントに寄与するという解釈と一致します。 

中間 dp 値が急速に増加するため、モジュロ演算には注意が必要です。 もう 1 つの微妙な点は初期化です。最初のセグメントの長さはすべて有効な開始設定として扱われ、その後のすべての構築にシードされます。 

## 実用的な例

 n = 2、m = 3 とします。dp はすべての単一セグメントの高さから始まります。 i = 2 の場合、以前の状態と可能な新しいセグメント長を組み合わせます。 

| 私 | h | 考慮される移行 | dp[i][h] |
 | --- | --- | --- | --- |
 | 1 | 1..3 | ベースの初期化 | 各1個 |
 | 2 | 1 | (1,0 は無効です) | 0 |
 | 2 | 2 | (1,1)、(2,0 無効) | 1 |
 | 2 | 3 | (1,2)、(2,1)、(3,0 無効) | 2 |

 これは、異なるセグメント分割から同じ高さの複数の分解がどのように生じるかを示しています。 

n = 3、m = 3 の場合、すべての dp[2] 状態をさらに 1 セグメント拡張し、非増加構造と一致するウェイの蓄積を観察します。 より多くの内部分割と接続パターンを導入すると、有効な構造の数が増加します。

 ## 特殊なケース

 重要なエッジケースは、m が n に比べて小さい場合です。 このような場合、多くのセグメント シーケンスは追加の高さに寄与できないため、初期のセグメントが既に高さを飽和しているものを除き、ほとんどの dp 状態はゼロに崩壊します。 h < 0 の状態には決して到達せず、無効な遷移はすべて自然に消滅するため、DP はこれを処理します。 

もう 1 つのエッジ ケースは n = 1 です。適用する接続の決定がないため、アルゴリズムは、正確に 1 つの構成に寄与する m に等しいすべての可能な単一セグメント長を正確にカウントします。
