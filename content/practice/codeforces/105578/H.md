 ## 解決策
 ## 問題の理解

 完全なグラフが与えられています$n$都市、ただしそれだけ$n-2$その端の一部は風光明媚な場所としてマークされています。 これらの景色のエッジは、ほぼ接続された構造を形成します。つまり、エッジをもう 1 つ追加することができれば、景色のグラフは完全に接続されることになります。 

この構造条件により、景観エッジが 2 つの接続されたコンポーネント (それぞれが木) を形成するようになります。 3 つ以上のコンポーネントがある場合、1 つのエッジを追加してもすべてを接続することはできません。 すでに 1 つのコンポーネントである場合は、少なくとも$n-1$エッジ。 したがって、景観ネットワークはまさに​​ 2 本の木であり、その頂点セットがすべての都市を分割します。 

この基礎となる景観構造に加えて、道路の選択されたサブセット (完全なグラフの端) である任意の「ガイド マップ」を検討します。 小さな Q は、都市 1 から開始する決定論的な横断を実行します。彼は常に、現在の都市から、ガイド マップに表示される最小番号の未訪問の近隣都市に行こうとします。 何も存在しない場合は、有効な移動が見つかるか、都市 1 に戻って停止するまで、以前に使用したガイド マップの端に沿って後戻りします。 

この動作はまさに、ラベルの増加によって近傍をソートした深さ優先検索であり、ガイドマップ グラフ上で実行されます。 

要件は、この横断中に景色の良い端をすべて訪問する必要があり、その際に通過できるのは景色の良くない別の道路を 1 つだけとすることです。 私たちが「カバー」する義務があるのは景観の端だけであるため、ガイド マップは両方の景観の構成要素に到達できるようにする必要がありますが、それらの外側にある複数の追加の接続に依存してはなりません。 

タスクは、この制約を満たすさまざまなガイド マップがいくつあるかを数えることです。 

制約は次のとおりです$2 \cdot 10^5$したがって、どの解も線形または線形に近いものでなければなりません。$n$。 線形構造を超えたグラフやエッジを列挙することを伴うものは、直ちに不可能になります。 

トラバーサル ルールを解釈すると、微妙な問題が発生します。 単純に解釈すると、多数の候補グラフに対して DFS をシミュレートする必要があることが示唆されるかもしれませんが、シーニック グラフの構造により、はるかに単純な基礎となる組み合わせ条件が強制されます。 

潜在的な混乱の 1 つは、横断中に複数の非景観エッジを使用できるかどうかです。 ただし、トラバースは単一のグラフに従うため、ガイド マップに含まれる景観以外のエッジは使用できます。 「風景のない別の道路は最大 1 つまで」という制限は、旅全体を通じて、そのような端は 1 つだけが横断経路の一部になり得ることを意味します。 これにより、ガイド マップが風光明媚な森の上に建てられた木のように動作することが強く制限されます。 

## アプローチ

 走査プロセスから直接推論しようとすると、考えられるすべてのグラフを考慮する必要があります。$n$ノードを作成し、辞書編集的な順序を尊重する DFS をシミュレートしながら、これまでに使用された非景観エッジの数も追跡します。 これは絶望的です。木に限定しただけでも、すでに次の結果が得られます。$n^{n-2}$追加のエッジを追加すると、スペースがさらに広くなります。 

重要な単純化は、景観構造が何を強制するのかを理解することから生まれます。 景色の端はすでに 2 本のばらばらの木を形成している、と言う$A$そして$B$。 Little Q は都市 1 から始まるため、1 が 1 つのコンポーネントにある場合、景色の良い端を通って他のコンポーネントに至る経路はありません。 

したがって、有効なガイド マップには、これら 2 つのコンポーネントを接続する少なくとも 1 つの非景観エッジが含まれている必要があります。そうでない場合、DFS は 2 番目のコンポーネントにまったく到達することができず、ましてやその景観エッジを訪れることもできません。 

次に、景観を目的としない旅行の制限について考えてみましょう。 ガイド マップに複数の非景観エッジが含まれている場合、非景観エッジが果たす唯一の役割は 2 つの景観ツリー間の橋渡しであるため、DFS はグラフの一部を接続または探索するために少なくとも 2 つの異なるそのようなエッジを横断する必要があります。 これは制約に違反するため、ガイド マップでは 2 つのコンポーネント間の接続エッジを 1 つだけ導入できます。 

それが受け入れられると、有効なガイド マップの構造は非常に厳格になります。 これは、すべての景観エッジと、端点がさまざまな景観コンポーネントにある 1 つの追加エッジで構成されます。 このようなエッジは接続されたグラフを生成し、元の景色のエッジがすでにすべての頂点をカバーしているため、このグラフはツリーになります。 

DFS ルールは、グラフが接続されると、トラバーサルが完全に決定され、常に有効になるため、どの接続エッジが選択されるかをさらに制限しません。 このような選択ごとに異なるガイド マップが生成され、エッジが異なれば明らかに異なるグラフが生成されます。 

したがって、問題は、最初の景観コンポーネントで 1 つのエンドポイントを選択し、2 番目の景観コンポーネントで 1 つのエンドポイントを選択できる方法が何通りあるかを数えることになります。 コンポーネントのサイズが$s$そして$n-s$、答えは$s \cdot (n-s)$。

 ## アルゴリズムのチュートリアル

 1. 景観のエッジからグラフを作成し、その関連コンポーネントを見つけます。 まさにあるので、$n-2$エッジがあり、1 つのエッジを追加した後に構造が接続されることが保証されている場合、正確に 2 つのコンポーネントが見つかります。 
2. DFS または BFS を使用して各コンポーネントのサイズを計算します。 これらのサイズを$s$そして$n-s$。 景色のグラフはすでに森なので、トラバースは簡単です。 
3. 有効なガイド マップはこれら 2 つのコンポーネントを正確に 1 つの追加エッジで接続する必要があり、そのエッジは最初のコンポーネントの任意の頂点と 2 番目のコンポーネントの任意の頂点の間で任意に選択できることを認識してください。 
4. 2 つのコンポーネントのサイズを乗算して、有効なガイド マップの数を取得します。 

### なぜ効果があるのか

 シーニック エッジは、グラフを正確に 2 つのツリーに分割します。 有効な横断はそれらの間を移動できる必要がありますが、これはガイド マップに含まれる景観のない端を通ってのみ可能です。 制約ではそのようなエッジの使用が最大 1 つまで許可されているため、そのエッジが 2 つのコンポーネント間の唯一のコネクタである必要があります。 そのエッジが修正されると、ガイド マップは両方のコンポーネントを含むツリーになり、パーティション全体にわたるエンドポイントのすべての選択により、個別の有効な構造が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 2):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    visited = [False] * (n + 1)
    comp_sizes = []

    def dfs(start):
        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            u = stack.pop()
            size += 1
            for v in g[u]:
                if not visited[v]:
                    visited[v] = True
                    stack.append(v)

        return size

    for i in range(1, n + 1):
        if not visited[i]:
            comp_sizes.append(dfs(i))

    if len(comp_sizes) != 2:
        print(0)
        return

    ans = comp_sizes[0] * comp_sizes[1]
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず風光明媚な森林を再構築し、その連結コンポーネントを計算します。 入力により、エッジが 1 つ追加された後に構造が接続されることが保証されるため、正確に 2 つのコンポーネントが期待されますが、コードは依然として不一致を防ぎます。 

各 DFS の実行では、1 つの景観コンポーネントのサイズが測定されます。 最終的な答えは、必要な単一の接続エッジの端点を選択する方法の数に対応して、2 つのサイズを乗算します。 

この実装では、再帰の深さの問題を回避するために反復 DFS を使用します。$n$大きくなる可能性があります。 

## 実用的な例

 次のようなシナリオを考えてみましょう。$n=4$そして風光明媚な端は$(1,4)$そして$(2,3)$。 景観グラフは 2 つのコンポーネントに分かれています。$\{1,4\}$そして$\{2,3\}$。 

| ステップ | スタック/ノード | 訪問したコンポーネント | これまでのコンポーネントのサイズ |
 | --- | --- | --- | --- |
 | DFS を 1 から開始 | [1] | {1,4} | 2 |
 | 2 時に DFS を開始 | [2] | {2,3} | 2 |

 アルゴリズムはサイズ 2 と 2 の 2 つのコンポーネントを検出し、$2 \cdot 2 = 4$。 

これにより、2 つのコンポーネント間のすべての組み合わせによって有効なガイド マップが生成されることが確認されます。 

次に、次のような小さなケースを考えてみましょう。$n=3$、風光明媚な端が 1 つだけある場所、とします。$(1,2)$。 コンポーネントは次のとおりです。$\{1,2\}$そして$\{3\}$。 答えは次のようになります$2 \cdot 1 = 2$、いずれかを選択することに対応します$(1,3)$または$(2,3)$単一の接続エッジとして。

 ## 特殊なケース

 最低限のケース$n=2$景観のエッジが存在しない唯一の状況です。 アルゴリズムは、慎重に解釈した後にのみ、これを 2 つの単一頂点コンポーネントとして扱います。エッジがゼロであるため、両方の頂点は孤立したコンポーネントであり、サイズ 1 と 1 が与えられ、答え 1 が生成されます。DFS は 2 つのコンポーネントを正しく見つけて乗算します。 

鎖のようなケースでは$1-2-3$1 つのエッジのみが美しい場合、グラフはコンポーネントに分割されます$\{1,2\}$そして$\{3\}$。 The DFS starting at 1 visits two nodes, and a second DFS visits the last node, producing sizes 2 and 1. The multiplication correctly counts both possible connecting edges,$(1,3)$そして$(2,3)$これは、コンポーネント間の接続によって有効なガイド マップが生成されるという要件に一致します。
