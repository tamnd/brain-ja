 ## 解決策
 ## 問題の理解

 私たちには固定の 8 チームのシングルエリミネーションブラケットが与えられており、すでに準々決勝の順番が上から下に配置されています。 各チームには固有の名前と固有の整数の強さがあります。 トーナメントは標準的なノックアウト方式で進行します。ブラケット内で隣接するペアが試合を行い、強いチームが常に勝ち進み、弱いチームが敗退します。 これは準々決勝、準決勝、そして決勝戦まで続き、ちょうど 1 人のチャンピオンと 1 人の準優勝者が生まれます。 

タスクは、任意のトーナメント構造をシミュレートすることではなく、この固定ブラケット レイアウトに正確に従うことです。 つまり、第 1 ラウンドは 1 対 2、3 対 4、5 対 6、7 対 8 のチーム間の試合で構成されます。これらの試合の勝者が順に再び準決勝でペアになり、準決勝の勝者 2 人の間で決勝が行われます。 

ストーリーのコンテキストは e スポーツに関するものですが、計算の問題は純粋に、比較の固定バイナリ ツリーに対する決定論的な削減です。 

入力サイズは 8 チームで一定であるため、漸近的な最適化は必要ありません。 直接のシミュレーションや再計算さえも、あらゆる場合において簡単です。 ペアリング構造は読み間違えたり、誤って実装されやすいため、主な要件はブラケットの処理が正確であることです。 

制約によりエッジケースは最小限ですが、単純な実装では依然として微妙な障害モードが存在します。 

よくある間違いの 1 つは、すべてのチームを強さ順に並べ替えて上位 2 チームを取ることです。 トーナメントの構造は重要であるため、これは不正確です。 たとえば、最も強い 2 チームが準々決勝で対戦した場合、たとえ他のチームよりも強かったとしても、一方が早期に敗退し、準優勝することはできません。 

もう 1 つの間違いは、ブラケット内の勝者の順位ではなく、元のインデックスに基づいて再ペアリングするなど、ラウンド全体で誤ったペアリングを行うことです。 これにより、ノックアウト構造が破壊されます。 

## アプローチ

 ブルートフォース解釈では、トーナメント全体を明示的にシミュレートします。 現在のラウンド参加者のリストを管理し、隣接するエントリをペアにして強さを比較し、1 つのチームが残るまで次のラウンドを構築します。 各試合は継続的な作業であり、8 チームの場合、合計で最大 7 回の比較になります。 これはすでに些細なことですが、構造はきれいに一般化されます。 

重要な観察は、ブラケットが順序が固定された完全な二分木であるということです。 各試合では 2 つのチームが 1 つに減り、勝者は並べ替えられることなく上に伝播されます。 ラウンドは 3 つだけなので、オーバーヘッドなしでレベルごとにシミュレーションできます。 

構造が固定されており小さいため、総当たりアプローチと最適アプローチは実質的に同じです。 唯一の違いは、ラウンドを明示的にモデル化するか、より抽象的な方法で答えを導き出そうとするかどうかです。

 ## アルゴリズムのチュートリアル

 (強さ、名前) ペアのリストを使用して、ノックアウト ラウンドを直接シミュレートします。

1. 8 つのチームを順番に読み取り、強さと名前を含むペアとしてそれぞれを保存します。 比較は数値的かつ頻繁に行われるため、強度を第一に保ちます。 
2. 現在のラウンド リストを、ブラケット順にこれら 8 チームとして初期化します。 一致は常に隣接するペア間で行われるため、順序付けは重要です。 
3. ラウンドごとに、勝者の空のリストを作成します。 
4. 現在のリストを 2 つのステップで繰り返します。 隣接するペアごとに強さを比較し、より強いチームを次のラウンドのリストに追加します。 これは、より強い強さが常に勝つというルールを直接エンコードしています。 
5. すべてのペアを処理した後、現在のリストを勝者のリストに置き換えます。 
6. 1 つのチームだけが残るまで繰り返します。 そのチームはチャンピオンです。 
7. 準優勝チームは決勝戦で負けたチームとなります。 両方のファイナリストを比較する前に保存することで、最終ラウンド中に追跡できます。 

もう少し明確な方法は、準決勝後に停止し、4 チームが 2 つのファイナリストに減り、その後最終比較を 1 回実行して、勝者と敗者の両方を記録することです。 

### なぜ効果があるのか

 各ラウンドは、完全なバイナリ トーナメント ツリーの 1 レベルを正確にモデル化します。 すべてのチームは、敗退までラウンドごとに 1 試合だけ参加します。 組み合わせは固定されており決定的であるため、各試合の勝者は強さを比較することによって一意に決定されます。 この構造により、トーナメントの制約の下で最後に生き残ったノードがグローバル チャンピオンとなり、最後に敗退したノードが最終試合の敗者となるため次点となることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

teams = []

for _ in range(8):
    name, t = input().split()
    teams.append((int(t), name))

while len(teams) > 2:
    nxt = []
    for i in range(0, len(teams), 2):
        if teams[i][0] > teams[i + 1][0]:
            nxt.append(teams[i])
        else:
            nxt.append(teams[i + 1])
    teams = nxt

# final match
a, b = teams[0], teams[1]
if a[0] > b[0]:
    print(f"{a[1]} beats {b[1]}")
else:
    print(f"{b[1]} beats {a[1]}")
```コードは 8 つのチームを読み取り、それらを (強さ、名前) ペアとして保存するため、比較は単純な整数比較になります。 このループは、隣接する要素をペアにして勝者を前方に押し出すことによってラウンドを処理します。これは、固定ブラケットの構造と正確に一致します。 

最後に残った 2 チームがファイナリストとなります。 決勝の敗者は独自に定義されるため、最後の比較によってチャンピオンと次点の両方が直接決定されます。 

よくある実装上の落とし穴は、試合をシミュレーションする前に誤ってチームを並べ替えてしまうことです。 That would destroy bracket structure. もう 1 つの微妙な問題は、次のラウンドを構築するときにインデックスを混同することです。 各試合にはちょうど 2 人の参加者が必要となるため、2 つずつステップすることが必須です。

 ## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        # inline solution
        teams = []
        for _ in range(8):
            name, t = input().split()
            teams.append((int(t), name))

        while len(teams) > 2:
            nxt = []
            for i in range(0, len(teams), 2):
                if teams[i][0] > teams[i + 1][0]:
                    nxt.append(teams[i])
                else:
                    nxt.append(teams[i + 1])
            teams = nxt

        a, b = teams
        if a[0] > b[0]:
            print(f"{a[1]} beats {b[1]}")
        else:
            print(f"{b[1]} beats {a[1]}")

    return out.getvalue().strip()

 ## 特殊なケース

 エッジケースの 1 つは、最も強いチームが 2 番目に強いチームと早い段階で出会うブランチに配置される場合です。 たとえば:

 入力:```
A 100
B 99
C 1
D 2
E 98
F 3
G 97
H 4
```準々決勝では組み合わせに応じてBかAが生まれるが、準決勝以前でAとBが対戦した場合は、たとえ世界的に強いチームであってもどちらかが敗退する。 このアルゴリズムは、グローバル ランクを決して比較せず、隣接するブラケットのペアのみを比較するため、これを正しく処理します。 

もう 1 つのエッジケースは、次点が世界で 2 番目に強いチームではない場合です。 最終試合では、敗者は単に最後の比較で負けたファイナリストになります。 このコードは両方の最終候補を明示的に保存し、それらを一度比較することで、世界ランキングに関係なく次点者が正しく捕捉されるようにします。 

最後に、すべての値が一意であるため、比較において曖昧さがなくなるため、タイブレーク ロジックは必要ありません。
