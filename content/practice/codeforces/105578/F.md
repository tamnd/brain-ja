 ## 解決策
 ## 問題の理解

 私たちは、それぞれの 2^n 頂点がバイナリ ライト状態を保持する n 次元超立方体を扱っています。 移動は、2^n の操作タイプの 1 つを選択することで構成されます。 各操作タイプには固定コストがありますが、ハイパーキューブのさまざまな幾何学的サブ構造に適用できます。操作インデックスのバイナリ マスクに応じて、k 次元の面 (サブキューブ) を選択し、その面内のすべての頂点を切り替えます。 

主要な行動制約は本質的に敵対的なものです。 すべてのライトの初期構成は不明であり、2^{2^n} 個の可能な割り当てのいずれかである可能性があります。 一連の操作を実行することが許可されており、各操作の後にシステムはすべてのライトが点灯しているかどうかをチェックします。 開始時の設定が何であったとしても、シーケンスのあるプレフィックスで状態がすべて 1 になるような、操作の固定シーケンスが必要です。 

したがって、タスクは、既知の開始から特定の構成に到達することではありません。 代わりに、考えられるすべての初期状態が少なくとも 1 つのプレフィックスによって「消去」されること、つまり all-one ベクトルにマッピングされることを保証する一連の XOR 演算を設計する必要があります。 

n ≤ 20 という制約は、2^n ≤ 約 100 万を意味するため、頂点の状態空間は大きくなりますが、構造化されています。 演算の数も 2^n であるため、どのソリューションも頂点を個別に処理するのではなく、次元の累乗セットに対して機能する可能性があります。 

単純な解釈では、状態をシミュレートするか、頂点構成のサブセットを考慮しようとします。 単一の状態を保存するだけでもすでに 2^n ビットであり、すべての状態のセットは二重指数関数であるため、これはすぐに失敗します。 

これを独立した頂点反転として解釈しようとすると、微妙な落とし穴が現れます。操作は頂点に対して独立して動作するのではなく、構造化されたサブキューブに対して動作します。 もう 1 つのよくある間違いは、要件がすべての初期状態に対して同時に普遍的であるのに、「最悪の場合の初期状態を 1 つ修正する」だけでよいと想定していることです。 

## アプローチ

 強引な視点では、完全な状態空間の観点から考えようとします。 各ノードが未知の初期状態に適用される現在の XOR 変換に対応する演算の決定木を構築することを想像できます。また、考えられるすべての初期ベクトルが、最終的にはあるプレフィックスの all-one ベクトルにマップされるようにしたいと考えています。 これはすぐに指数関数的な状態群をカバーする問題となり、各演算は F2^{2^n} に対する線形変換であるため、遷移を明示的に表すことさえ不可能になります。 状態の数は 2^{2^n} であるため、明示的な走査は完全に不可能です。 

重要な構造的洞察は、個々の頂点について考えるのをやめ、代わりに次元のサブセットに対する基本ビューに切り替えることです。 すべての操作は、サブキューブ内のすべての頂点の切り替えに対応します。これは、F2^{2^n} のアフィン部分空間操作です。 これは、すべての操作が、一部の座標を固定し、他の座標を変更することによって引き起こされる基本的な「ビット反転パターン」の線形結合であることを意味します。 

n ビット マスクによって頂点にインデックスを付ける場合、一部の座標で固定ゼロ ビットによって定義される k 面を切り替えることは、部分空間の特性関数を追加することに対応します。 重要な観察は、そのようなすべての演算のセットが、次元のサブセットによってインデックス付けされた F2 上のベクトル空間を形成するということです。重要なのは、直接のジオメトリではなく、これらの演算がどのように組み合わされて、考えられるすべての初期状態の範囲に影響を与えるかということです。 

問題を再構成すると、一連のベクトル (演算) を効果的に選択しており、すべての初期ベクトル x に対して、x XOR S がすべて 1 のベクトルになるような接頭辞の合計 S が存在するようにしたいと考えています。 同様に、S は可能なすべての補数構成にヒットする必要があります。

これは、グループ F2^{2^n} のカバー条件になります。接頭辞の合計がすべて 1 のベクトルのすべての剰余集合と交差するようにします。 最適な解決策は、唯一の関連する構造が包含によって順序付けされたサブキューブの格子であること、およびその最適性は、最小のプレフィックス コストでこの格子にわたる一連の演算を選択することに帰着し、それが次元のサブセットにわたる最小コスト基準のような選択になることを理解したときに現れます。 

最終的な削減は、各演算が次元のサブセットに対応し、プレフィックスの合計がすべての 2^n パリティ制約を生成する最小コストのシーケンスが必要になるということです。 これは、すべてのサブセットの最小コスト順序を選択することと同じであり、新しいサブセットのそれぞれがブール格子に対するメビウス反転の意味で新しい独立制約に寄与します。 結果として得られる構造は、ビットマスク上のサブセット DP を介して処理されます。ゼータ変換スタイルでコストを集計し、誘発された必要性の昇順で寄与を貪欲に選択します。

 ## アルゴリズムのチュートリアル

 各オペレーション マスクをディメンションのサブセットとして再解釈します。 コスト配列には、これらのサブセットによってインデックスが付けられます。 

1. すべてのマスクに対して配列 dp を構築します。最初は dp[mask] = a[mask] です。 これは、その操作タイプを直接使用するコストを表します。 
2. dp[mask] がすべてのサブマスクからの寄与を累積するように、サブセット畳み込み (ゼータ変換) を使用して dp を変換します。 このステップは、高次元の顔操作には、追加の座標を固定することによって引き起こされるすべての低次元のトグル パターンが暗黙的に含まれるという事実をコード化します。 これは、幾何学的重なりが代数的包含に変換される重要な場所です。 
3. この変換後、dp[mask] は、次元相互作用の線形基礎におけるサブセット マスクに正確に対応するトグル パターンを達成するための有効コストを表します。 
4. ここで、問題は、この基底ですべての非ゼロマスクを確実にカバーするシーケンスを選択する必要があると解釈します。 最適な戦略は、これらのマスクを独立した要件として扱い、最小限の生成セットを維持しながら、コストの昇順でその寄与を選択することです。 
5. サブセット サイズに対するバケット化または増分選択を使用して、マスクをコスト別に暗黙的に並べ替えまたは処理します。 n ≤ 20 であるため、すべてのマスクを反復処理することが可能です。 
6. 必要最小限の寄与を合計します。これは、包含-除外正規化後のすべての dp[mask] 値の選択に対応します。 

なぜ効果があるのか:

 すべての演算は、次元サブセットのブール格子上の特性ベクトルに対応します。 ゼータ変換は、重なり合う面の操作を独立した基底係数に変換します。 この基底に入ると、すべての要件が独立し、有効なシーケンスにはすべての可能な初期状態のカバーに寄与する各基底ベクトルの代表を少なくとも 1 つ含める必要があります。 この変換により、二重カウントがなくなり、選択された基底寄与の最小合計が、プレフィックス クロージャーがオール 1 構成のすべての剰余類にヒットするシーケンスが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def zeta_transform(a, n):
    # subset sum over supersets
    # transforms a[mask] to sum over submasks or supersets depending on direction
    # here we use standard superset accumulation
    for i in range(n):
        for mask in range(1 << n):
            if mask & (1 << i):
                a[mask] += a[mask ^ (1 << i)]
    return a

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        m = 1 << n
        a = list(map(int, input().split()))

        dp = a[:]

        dp = zeta_transform(dp, n)

        # final answer is sum over all transformed contributions except empty redundancy handling
        ans = 0
        for mask in range(1, m):
            ans = (ans + dp[mask]) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```実装は、サブセット マスクによってインデックス付けされたすべての操作のコストを読み取ることから始まります。 ゼータ変換は、サブセット包含チェーンに沿って寄与を集約します。これは、各操作が複数の部分構造に暗黙的に影響を与えるため必要です。 ループ構造により、各次元がすべてのスーパーセットに正しく寄与することが保証されます。 

最終的な合計では、空のマスクは除外されます。これは、空のマスクは、次元の切り替え制約を導入しない単純な操作に対応するためです。 

微妙な点は、インプレース ゼータ変換次数です。 最も外側の次元を反復処理することで、各ビットが独立して処理されるようになり、無関係なサブセット間での二重カウントが防止されます。 

## 実用的な例

 n = 2 という小規模なケースを考えてみます。つまり、00、01、10、11 のインデックスが付けられた 4 つの操作があります。 

コストが a = [3, 1, 4, 2] であると仮定します。 

ゼータ変換後:

 | マスク | オリジナル | ビット 0 の処理後 | ビット 1 の処理後 |
 | --- | --- | --- | --- |
 | 00 | 3 | 3 | 3 |
 | 01 | 1 | 1 | 4 |
 | 10 | 4 | 7 | 7 |
 | 11 | 2 | 3 | 10 |

 最終的な dp は、各操作タイプに埋め込まれたすべての部分構造の累積寄与を反映します。 ゼロ以外のマスクをすべて合計すると、総コスト寄与が得られます。 

このトレースは、ビット次元に沿った包含がサブセット格子内でどのようにコストを上方に蓄積するかを示しています。 

次に、歪んだケース n = 2、a = [1, 100, 100, 100] を考えてみましょう。 

変換後、小さなマスクがそのスーパーセットを支配し、アルゴリズムにより、依然として完全なカバレッジに寄与する安価な低次元操作を見逃さないことが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、フルマスク操作のみが低コストである場合に発生します。 その状況でも、すべてのサブマスクがそれに寄与するため、アルゴリズムはゼータ変換を通じて正しく集計し、最終的な合計に最適なグローバル トグルが含まれることを保証します。 

すべてのコストが等しい場合、別のエッジケースが発生します。 サブセット格子は対称になり、変換後にすべてのマスクが均等に寄与するため、合計はゼロ以外のすべてのサブセットにわたる均一な累積に減少します。これは、初期状態に関係なく、すべての構成が何らかのプレフィックスによってカバーされなければならないという要件と一致します。
