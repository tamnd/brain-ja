 ## 解決策
 ## 問題の理解

 私たちに与えられたのは一次元の戦場であり、$n$細胞。 一部のセルには最初から文字が含まれています。 以上$m$ラウンドでは、各セルが隕石を受け取り、これらの隕石は消えるのではなく時間の経過とともに蓄積されます。 隕石のあるセルは、そこに入るには現在その上にある隕石の数に等しいコストを支払う必要があるという意味で危険になります。また、隕石がラウンドに落ちたときにキャラクターがそこに立っていると、そのキャラクターはすぐに死んでしまいます。 

各ラウンドで隕石の落下が終了した後、生き残ったキャラクターは左右に任意の数だけ移動できます。 移動は、すでに透明になっているか、隕石が払い戻された細胞を通してのみ可能です。 支払うと、そのセル上の隕石が削除され、横断が可能になります。 

目標は、隕石の除去に費やされる合計金額を最小限に抑えながら、最初に存在するすべてのキャラクターが全ラウンドを通して生き残り、事実上殺されることなく自由に移動できる状態を維持できるようにすることです。 これが保証できない場合は、次のように出力します。$-1$。 

重要な構造上の制約はサイズです。つまり、$n \times m$すべてのテスト ケースで最大でも$10^6$。 これは、単純な方法で各ラウンドの各セルを処理するソリューションは、すでに実現可能性の限界に達していることを意味します。 両方の次元にわたる二重ループは、各操作が次の場合にのみ受け入れられます。$O(1)$ただし、ラウンドごとのセルごとにこれ以上複雑なことは避けなければなりません。 

いくつかのラウンドで完全にブロックされる領域によってキャラクターが分離されている場合、微妙な失敗のケースが発生します。 ある時点で、必要な経路上のすべてのセルが隕石で占められており、それらを取り除く意志または除去する能力がなければ、移動は不可能になります。 たとえば、最初の 2 つの文字の間のセグメント全体が常に安全でなく、それをクリアする余裕がない場合、それらの文字は決して出会うことができず、不可能になります。 

## アプローチ

 直接シミュレーションでは、どのセルが安全で、どのセルがブロックされ、各キャラクターがどこに移動できるかをラウンドごとに追跡します。 各ラウンドの後、ライン上のすべてのキャラクターの到達可能性を再計算し、キャラクターがブロックされたセルに入ろうとするたびに、それをクリアするために料金を支払います。 各ラウンドでグリッド全体のスキャンと接続の更新が必要になる場合があるため、これはすぐにコストが高くなります。 と$n \times m$まで$10^6$、ラウンドごとの線形再計算でも、$10^{12}$最悪の場合は運用が不可能になります。 

重要な観察は、動きはプロセス全体の集合体としてのみ重要であるということです。 キャラクターは互いに到達するとマージでき、その後は単一のグループとして動作します。 戦場は線であるため、重要なのは、すべてのラウンドが計算された後に、すべての初期位置が通過可能なセルの連続したパスを介して接続できるかどうかだけです。 

各細胞は時間の経過とともに隕石を蓄積します。 セルがトラバース パスの一部として使用された場合、その累積コストを支払わなければなりません。 ただし、ルートを自由に選択できるため、最初の文字の間にあるセルのみを気にする必要があります。文字は線に沿って接続されるだけであるためです。 

これにより、すべての初期位置を接続するために線のどのセグメントを横断する必要があるかを特定する問題が軽減されます。 そのセグメントが判明したら、最初に占有されていない内部のすべてのセルを少なくとも 1 回クリアする必要があり、そのような各セルのコストは、すべてのラウンドで蓄積される隕石の合計数となります。 

したがって、この構造は、セルごとの累積重みを計算し、必要な領域にわたってそれらを合計することに分解されます。 必要な領域がルールに従って完全に使用できないために必要な接続を実現できない場合、答えは次のようになります。$-1$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ラウンドとポジションにわたる完全なシミュレーション |$O(nm)$に$O(nm \cdot \text{movement})$|$O(n)$| 遅すぎる |
 | プレフィックスの蓄積と間隔の推論 |$O(nm)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての隕石イベントをセルごとの単一の累積値に圧縮します。 隕石は加算されるだけなので、すべてのラウンド後の各セル上の最終的な隕石の数は、単純にすべての隕石の合計になります。$a_{i,j}$。 

これらの合計を取得したら、戦場をセルに入る加重線として扱います。$j$費用$A_j$、そして最初に占有されたセル内に留まるには費用はかかりません。 

1. すべてのラウンドを合計して、各セルの合計隕石負荷を計算します。 これは、そのセルの最終的な障害コストを表します。 
2. 最初に文字が含まれる左端と右端の位置を特定します。 キャラクターは結合できるため、最終的にはすべてのキャラクターが単一の到達可能な領域に接続される必要があるため、これらの両端の間のセグメントのみが重要になります。 
3. これらの両端の間に、パスを接続するために使用できる空のセルがない場合 (実際には、問題の制約の下でセグメントが完全に使用できない場合)、戻り値が返されます。$-1$。 
4. それ以外の場合は、セグメント内のすべての空のセルの累積隕石値を合計します。 これらは、すべての最初の文字間を通過できるようにするために、少なくとも 1 回クリアする必要がある唯一のセルです。 
5. この合計を最小コストとして出力します。 

正確さは、キャラクターが個々の位置ではなく接続性を維持するだけでよいという不変条件に依存します。 各ラウンド後の移動は制限されないため、すべての初期位置の間にパスが存在すると、すべてのキャラクターを 1 つの接続されたグループにマージし、その後は安全な状態を保つことができます。 コストはどのセルを通行可能にする必要があるかによって完全に決定され、そのような各セルはクリアされる前にすべての隕石を蓄積するため、総コストは固定されており、移動順序とは無関係です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        c = list(map(int, input().split()))
        
        has = False
        L, R = n, -1
        
        for i, x in enumerate(c):
            if x == 1:
                has = True
                L = min(L, i)
                R = max(R, i)
        
        if not has:
            print(-1)
            for __ in range(m):
                input()
            continue
        
        total = [0] * n
        
        for _ in range(m):
            row = list(map(int, input().split()))
            for j in range(n):
                total[j] += row[j]
        
        cost = 0
        for j in range(L, R + 1):
            if c[j] == 0:
                cost += total[j]
        
        print(cost)

if __name__ == "__main__":
    solve()
```この実装では、まず、左端の先頭文字から右端の先頭文字まで、対象のスパンを見つけます。 次に、すべてのラウンドにわたるセルごとのすべての隕石の寄与を集計します。 最後に、最初のグループを接続するためにアクティブにクリアする必要がある唯一のセルが文字によって占有されていないセグメント内の累積値のみを合計することによってコストを計算します。 

微妙な点は、入力行をスキップすると後続のテスト ケースの同期が解除されるため、早期終了ケースでも入力行を完全に消費する必要があることです。 

## 実用的な例

 文字が端にあり、中央の 1 つのセルに隕石が蓄積されている小さな行を考えてみましょう。 

入力：```
1
5 2
1 0 0 0 1
1 0 2 0 3
0 0 1 0 0
```蓄積後、セルあたりの隕石の総数は次のようになります。$[1, 0, 3, 0, 3]$。 必要なセグメントはインデックス 0 から 4 までです。エンドポイントにはすでに文字が含まれているため、セル 1、2、および 3 のみが走査に関係します。 

| セル | イニシャル | 隕石の総数 | 費用に含まれるもの |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | いいえ |
 | 1 | 0 | 0 | はい (0) |
 | 2 | 0 | 3 | はい (3) |
 | 3 | 0 | 0 | はい (0) |
 | 4 | 1 | 3 | いいえ |

 コストは$3$。 

これは、空の中間セルのみが寄与し、文字セルはすでにアンカーとして機能しているため無関係であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(nm)$テストケースごと（全体的に）$10^6$) | 各隕石値は蓄積中に 1 回処理されます。 
| スペース |$O(n)$| セルごとの累積のみが保存されます。 

この制約により、すべてのテスト ケースにわたるセル更新の合計数が最大で次であることが保証されます。$10^6$したがって、ソリューションは制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        c = list(map(int, input().split()))
        L, R = n, -1
        for i, x in enumerate(c):
            if x:
                L = min(L, i)
                R = max(R, i)

        total = [0] * n
        for _ in range(m):
            row = list(map(int, input().split()))
            for i in range(n):
                total[i] += row[i]

        if L > R:
            out.append("-1")
            continue

        ans = 0
        for i in range(L, R + 1):
            if c[i] == 0:
                ans += total[i]
        out.append(str(ans))

    return "\n".join(out)

# custom cases

# single character, no cost
assert run("1\n3 2\n0 1 0\n1 2 3\n0 0 0\n") == "0"

# two characters with blocked middle
assert run("1\n3 1\n1 0 1\n5 5 5\n") == "5"

# no empty cells needed
assert run("1\n4 2\n1 0 0 1\n1 0 2 0\n0 0 0 0\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一の文字 | 0 | トラバースは必要ありません |
 | ブロックされた中央セル | 5 | コストは正しく累積されます |
 | 複数ラウンドの累積 | 2 | ラウンド間の適切な合計 |

 ## 特殊なケース

 グリッド上に文字が 1 つだけある場合、アルゴリズムはすぐに文字を見つけます。$L = R$, したがって、セグメントには中間セルが含まれません。 横断する必要がなく、キャラクターは隕石の影響を受けた領域を通過する必要がないため、コストはゼロです。 

セグメント内のすべてのセルに隕石が現れても、実際に接続に必要なセルは 1 つだけである場合でも、アルゴリズムは必要な間隔のみを合計し、無関係な領域の過剰カウントを回避します。 これにより、アクティブ パスの外側にある高密度の隕石の分布が答えに影響を与えないことが保証されます。 

複数のラウンドが同じセルに寄与する場合、累積は繰り返しの加算を正しく処理します。 隕石を複数回受け取ったセルは、そのセルが廊下として使用された場合にそのセルを除去するのに必要な総コストを反映して全額を負担します。
