 ## 解決策
 ## 問題の理解

 固定の 2 x 2 バイナリ グリッドを使用しているため、すべての構成は 4 ビット状態になります。 各操作では、特定のパターン (1 つのセル、行全体、列全体、または 4 つのセルすべてを一度に) でビットを反転します。 各操作タイプには固定コストがあり、操作は連続して何度でも適用できます。 

問題は、最初のグリッドは不明ですが、最大 16 個の可能性のある特定のセットの 1 つであることが保証されていることです。 実際にどの初期グリッドから開始するかを知らなくても、一連の操作を事前にコミットすることができます。 各操作の後、グリッドがオール 1 になるとシグナルがトリガーされます。要件は、指定されたセット内のすべての可能な初期グリッドに対して、その特定の初期グリッドをオール 1 に変える、選択された操作シーケンスの何らかのプレフィックスが存在する必要があることです。 

出力は、そのような固定シーケンスの可能な最小総コストです。 

これは基本的に、サイズ 16 の有限状態空間上のウォークの構築に関する問題であり、各操作は状態間の移動であり、複数の可能な開始点から特定のターゲット状態に到達することを保証する単一のウォークが必要ですが、そのウォークは接頭辞変換として逆の視点で適用されます。 

重要な構造上の制約は、4 つのセルのそれぞれがバイナリであるため、可能なグリッドが合計 16 個しかないことです。 これは、グリッドサイズ内の指数関数的なアプローチを即座に排除し、すべての状態と遷移を明示的にモデル化できることを示唆しています。 

素朴な誤解は、各初期グリッドを個別にシミュレートし、それらを貪欲に同期させようとしていると考えることです。 これは、操作が共有されるため失敗します。同じシーケンスがすべての初期状態に対して同時に機能する必要があり、重要な問題は、累積的な効果が必要なすべての変換を「カバー」できる操作を選択することです。 

同じ操作シーケンスが状態を再訪する可能性があることを考慮すると、2 番目の微妙な落とし穴が現れます。 たとえば、「リセット」して、別の初期グリッドで再試行しようとするかもしれませんが、それは無料ではありません。すべての操作にはコストがあり、新しいプレフィックス XOR 状態が生成されない限り、繰り返しでは根本的に新しい到達可能性が追加されずにコストが増加するだけであるためです。 

## アプローチ

 重要な視点は、グリッドの観点から直接考えるのをやめ、代わりにすべてのグリッドを 4 ビット ベクトルとして扱うことです。 各演算は、2 を法とする固定 4 ビット ベクトルの加算に対応します。一連の演算は、ゼロ ベクトルから始まるプレフィックス XOR 合計のシーケンスを定義し、各プレフィックスは未知の初期状態に適用される累積変換を表します。 

初期状態が x で、プレフィックスの合計が p の場合、そのプレフィックスを適用した後の結果の状態は x XOR p になります。 これをすべて 1 のベクトルにする必要があるため、p は x XOR 1111 に等しくなければなりません。これは、すべての初期グリッドが、特定のターゲット プレフィックス状態がシーケンス内のどこかに出現する必要があるという要件を課すことを意味します。 

したがって、問題は 16 ノードのグラフで 0 から始まるウォークを構築することになります。ここで、ノードは 4 ビットの状態で、エッジは 4 つの演算に対応し、それぞれにコストがかかります。 訪問したプレフィックス ノードのセットに必要なすべてのターゲット ノードが含まれるウォークが必要です。 

ブルートフォースアプローチでは、これを一連のノードを訪問する最短のウォークとして扱います。 必要なノードのサブセットと 16 状態グラフ内の現在の位置に対して動的プログラミング状態を定義できます。 これは正しいグラフです。グラフは小さく完全に明示的ですが、コストがかかります。最大 2^16 のサブセットと 16 の位置があり、各遷移で 4 つの操作が試行されるため、テスト ケースごとにおよそ 2^16 · 16 · 4 つの遷移が発生します。

重要な観察は、状態空間が 16 ノードに固定されており、遷移がテスト ケース全体で均一であることです。 これにより、この 16 ノード グラフで単一ソースの最短パス アルゴリズムを使用して、状態のすべてのペア間の最短距離を事前計算できます。 その後、問題は必要なノードのサブセットのみに対するメトリック TSP スタイルの DP になります。これは、それらのノードだけがカバレッジに関係するためです。 

問題を、0 から開始し、エッジの重みが元の状態グラフの最短経路距離である完全なグラフ内の必要なすべてのノードを訪問する最小コストのウォークを見つけることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グラフとサブセットに対する完全な状態 DP を同時に | O(T · 2^16 · 16 · 4) | O(2^16 · 16) | 遅すぎる |
 | 必要なノードの距離 + サブセット DP を事前計算する | O(T · (16^2 log 16 + m^2 2^m)) | O(16^2 + m 2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各グリッドを 4 ビット整数として表します。 各セルは 1 ビットに対応するため、16 個の可能なグリッドはすべて 0 から 15 までの整数にマップされます。これにより、すべての操作で定数時間の XOR 遷移が可能になります。 
2. 各操作の効果を 4 ビット マスクとして事前計算します。 単一セルのトグルは 1 ビットを反転し、行と列のトグルは 2 ビットを反転し、グローバル トグルは 4 ビットすべてを反転します。 これら 4 つのマスクは、16 ノード上の固定有向重み付きグラフを定義します。 
3. ダイクストラ (すべてのコストが等しい場合は BFS バリアントですが、ここではコストが異なります) を使用して、すべてのノードからすべてのノードへの最短パスを実行します。 ノードごとに 16 個のノードと 4 つのエッジしかないため、これはテスト ケースごとに事実上一定時間になります。 
4. 与えられた m 個の初期グリッドのそれぞれをノードにマッピングし、必要なターゲット ノードを計算します。 各初期グリッド x に対して、必要なプレフィックス状態は x XOR 1111 です。 
5. 固有の必要なターゲット ノードのリストを作成します。 シーケンスは常に空のプレフィックス状態から始まるため、開始ノード 0 を追加ノードとして追加します。 
6. 事前に計算された最短経路距離を使用して、これらのノードにわたる完全な重み付きグラフを構築します。 
7. この縮小されたグラフに対してビットマスク DP を実行します。 dp[mask][i] がノード 0 から開始し、マスク内のノードのセットを正確に訪問し、ノード i で終了する最小コストを表すものとします。 事前に計算された距離を使用して、i からマスク内にない任意の j に移動することによって遷移します。 
8. 特定の状態で終了する必要はないので、答えはすべての終了位置 i にわたる最小 dp[full_mask][i] です。 

この正しさは、有効な操作シーケンスが 0 から始まる 16 ノードの状態グラフのウォークに正確に対応し、すべてのプレフィックスが訪問ノードに対応するという事実から得られます。 各初期グリッドがある時点ですべて 1 になるという要件は、まさにその対応するターゲット ノードがプレフィックス状態の中に現れるという要件と同じです。 DP は、操作グラフによって引き起こされるメトリック内の最適な移動コストを使用して、これらのノードを訪問する可能性のあるすべての順序を列挙するため、可能な限り最良のシーケンスを取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**30

# precompute operation masks on 2x2 grid:
# bit layout:
# 0 1
# 2 3
def build_ops():
    ops = []
    # single cells
    ops.append([1 << 0, 1 << 1, 1 << 2, 1 << 3])
    # row 0, row 1
    ops.append([(1 << 0) | (1 << 1), (1 << 2) | (1 << 3)])
    # column 0, column 1
    ops.append([(1 << 0) | (1 << 2), (1 << 1) | (1 << 3)])
    # all cells
    ops.append([(1 << 0) | (1 << 1) | (1 << 2) | (1 << 3)])
    return ops

OPS = build_ops()

def all_transitions():
    # returns list of (v -> nv, cost index)
    trans = [[] for _ in range(16)]
    # mapping: op types costs are global a0,a1,a2,a3
    # but masks:
    # a0: 4 single toggles
    # a1: 2 row toggles
    # a2: 2 col toggles
    # a3: 1 all toggle
    for v in range(16):
        # single
        for b in range(4):
            trans[v].append((v ^ (1 << b), 0))
        # rows
        trans[v].append((v ^ ((1<<0)|(1<<1)), 1))
        trans[v].append((v ^ ((1<<2)|(1<<3)), 1))
        # cols
        trans[v].append((v ^ ((1<<0)|(1<<2)), 2))
        trans[v].append((v ^ ((1<<1)|(1<<3)), 2))
        # all
        trans[v].append((v ^ 15, 3))
    return trans

TRANS = all_transitions()

def dijkstra(a0, a1, a2, a3):
    cost_op = [a0, a1, a2, a3]
    dist = [[INF]*16 for _ in range(16)]

    for s in range(16):
        d = [INF]*16
        d[s] = 0
        pq = [(0, s)]
        while pq:
            cd, v = heapq.heappop(pq)
            if cd != d[v]:
                continue
            for nv, t in TRANS[v]:
                nd = cd + cost_op[t]
                if nd < d[nv]:
                    d[nv] = nd
                    heapq.heappush(pq, (nd, nv))
        dist[s] = d
    return dist

def solve():
    T = int(input())
    for _ in range(T):
        a0, a1, a2, a3 = map(int, input().split())
        dist = dijkstra(a0, a1, a2, a3)

        m = int(input())
        targets = set()
        for _ in range(m):
            line = input().strip()
            if not line:
                line = input().strip()
            g = []
            g.append(line)
            g.append(input().strip())
            x = 0
            for i in range(2):
                for j in range(2):
                    if g[i][j] == '1':
                        x |= 1 << (i*2 + j)
            targets.add(x ^ 15)

        nodes = [0] + list(targets)
        k = len(nodes)

        idx = {v:i for i, v in enumerate(nodes)}

        dp = [[INF]*k for _ in range(1<<k)]
        dp[1][0] = 0

        for mask in range(1<<k):
            for i in range(k):
                if dp[mask][i] == INF:
                    continue
                for j in range(k):
                    if mask >> j & 1:
                        continue
                    nm = mask | (1<<j)
                    dp[nm][j] = min(dp[nm][j], dp[mask][i] + dist[nodes[i]][nodes[j]])

        full = (1<<k) - 1
        ans = min(dp[full][i] for i in range(k))
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、遷移が XOR 演算になるように、最初にすべてのグリッドを整数としてエンコードします。 次に、16 状態グラフの明示的な遷移リストを構築し、各状態からダイクストラを実行して、指定された操作コストの下ですべてのペアの最短経路を取得します。 これらの距離は、最終的な DP で使用されるメトリックを定義します。 

DP は、関連するターゲット状態と開始状態 0 のみに問題を圧縮します。ビットマスクは、どの必須ターゲットがプレフィックス状態として訪問されたかを追跡します。 DP のすべての遷移では、事前に計算された最短パス コストが使用されます。これは、これら 2 つの構成間の最適な操作シーケンスに対応します。 

微妙な点は、DP は元のシーケンスの構造を明示的に再検討することを強制しないことですが、それはすでにメトリック クロージャにエンコードされています。2 つの状態間の最短パスは実際の操作シーケンスに対応し、これらのパスを連結すると有効なグローバル操作シーケンスが生成されます。 

## 実用的な例

 グリッドが 1 つだけ存在し、そのグリッドがすでにすべて 0 である単純化されたケースを考えてみましょう。 その場合、そのターゲットは 1111 なので、状態 0 から状態 15 に到達するだけで済みます。DP は最短経路問題に縮退し、答えは単に 0000 を 1111 に変える最も安価な一連の操作になります。 

| ステップ | 現在の状態 | アクション | コスト | 訪問したターゲット |
 | --- | --- | --- | --- | --- |
 | 0 | 0000 | 開始 | 0 | ∅ |
 | 1 | 1111 | すべて切り替え | a3 | {1111} |

 これにより、ターゲットが 1 つだけ存在する場合、解が 1 つの最短パスに正しく還元されることが確認されます。 

次に、0000 と 1111 という 2 つのターゲットを考えます。次に、0 から始まるプレフィックス シーケンスで状態 15 と状態 0 の両方を訪問する必要があります。すでに 0 から開始しているため、15 だけが残ります。 

| ステップ | 状態 | マスク | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 0 | 0000 | {0} | 開始 | 0 |
 | 1 | 1111 | {0,15} | 最適なパス 0→15 | 距離[0][15] |

 これは、DP が不必要な再訪問を自然に回避し、必要なプレフィックス状態のカバレッジのみを強制することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T · (16^2 log 16 + 2^m · m^2)) | ダイクストラはテストごとに固定の 16 ノード グラフで実行され、DP は最大 16 ノードの最大 2^m のサブセットで実行されます。 
| スペース | O(16^2 + 2^m · m) | 距離行列とサブセット DP テーブル |

 グリッドの状態空間が 16 に固定されており、各テスト ケースが非常に小さなグラフ上で動作するため、定数係数は小さくなります。 複数のテスト ケースがある場合でも、状態の範囲が小さく固定されているため、テストごとの計算は依然として管理可能です。

 ## 特殊なケース

 エッジ ケースの 1 つは、提供されたグリッドがすべて同一である場合です。 その状況では、必要なターゲット ノードのセットには単一の要素が含まれており、DP は 0 からそのノードまでの単一の最短パスに折りたたまれます。 このアルゴリズムでも完全な DP テーブルが構築されますが、意味のあるマスク状態は 1 つだけであるため、追加のコストは発生しません。 

もう 1 つのエッジ ケースは、グリッドの 1 つがすでにすべて 1 である場合に発生します。 そのターゲットは 0000 になり、これがまさに開始ノードになります。 DP には常にアクセスするノード 0 が含まれているため、この要件は操作を強制することなく自動的に満たされます。 

最後の微妙なケースは、最適な戦略が一時的に目標状態から離れて、より安価なパスを通って戻る必要がある場合です。 DP で使用されるすべてのペアごとの遷移は、元の操作グラフの状態間のグローバルに最適な変換であるため、最短パスによるメトリック クロージャにより、そのような迂回がすでに考慮されていることを保証します。
