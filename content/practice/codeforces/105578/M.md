 ## 解決策
 ## 問題の理解

 すべての整数でインデックス付けされた部屋の無限の行が与えられます。 これらの部屋は次のように仕切られています$n$値のモジュロに従ってグループ化する$n$。 2 つの部屋は、次の値で割った余りが同じであれば、同じグループに属します。$n$したがって、各グループは、無限に多くの部屋を含む「フロア」のように動作します。 

がある$m$引っ越しのルール。 各ルールは代表的な部屋に固定されています$a$、剰余クラスを暗黙的に決定します$a \bmod n$。 ルールがあるとき$(a, b)$が適用されると、インデックスが同じ残りを持つ部屋に現在座っているすべての居住者が、$a$加算することでシフトされます$b$彼らの部屋番号に。 したがって、ルールは残留クラス全体に同時に作用し、適用後、部屋番号が変更されるため、影響を受けるすべてのゲストは新しい残留クラスに移動します。 

ゲストが部屋で始まります$x$、各ステップでゲストの現在の残基クラスに適用できるルールを選択する限り、ルールのシーケンスを任意の順序で、何度でも適用できます。 このプロセスは、ゲストを整数位置間で移動させることによって進化しますが、暗黙的に剰余クラス間でも移動します。 

クエリごとに、ゲストが到達できるすべての部屋のセットが無限であるかどうかが尋ねられます。 

制約により、最大で$5 \cdot 10^5$ルールとクエリなので、どのようなソリューションも線形または線形演算に近いものでなければなりません。 シーケンスの数は深さとともに指数関数的に増加するため、すべての可能な操作シーケンスを明示的に調査することは直ちに不可能になります。 状態空間の値は無限であり、剰余により構造が大きいため、クエリごとに到達可能なすべての状態を格納することすら不可能です。 

サイクルについて推論するときに、微妙な問題が発生します。 たとえば、ゲストが異なる一連のルールを介して同じ残基クラスに複数回戻る可能性があります。 これらのサイクルの 1 つで実際の部屋番号がゼロ以外の量だけ変更される場合、そのサイクルを繰り返すと任意に大きい値または小さい値が生成され、到達可能なセットが無限になります。 蓄積されたシフトを追跡せずに残差クラスの到達可能性をチェックするだけの単純なアプローチは、このような場合には失敗します。 

## アプローチ

 重要な単純化は、問題を 2 つの層 (剰余クラス間の移動と整数シフトの累積) に分離することです。 

各状態は剰余クラスで記述できます$r = x \bmod n$そして現在の部屋の価値。 あらゆるルール$(a, b)$剰余からの有向遷移として書き換えることができる$r = a \bmod n$残留物に$r' = (r + b) \bmod n$、重量を追加しながら$b$現在の値に。 これにより、システムが有向グラフに変わります。$n$ノードでは、各エッジが追加の重みを持ちます。 

さて、疑問は次のとおりです。剰余ノードから始めて、エッジに沿って歩くことによって、無限に多くの個別の累積和を生成できるでしょうか?

 このグラフ内に合計の重みがゼロでないサイクルが存在する場合、そのサイクルを繰り返したどって、部屋番号を毎回ゼロ以外の倍数で変更して、無限に多くの個別の値を生成できます。 そのようなサイクルが存在しない場合、すべてのサイクルの合計の重みは 0 になります。これは、任意の 2 つのノード間の合計の重みが明確に定義され、選択されたパスから独立していることを意味します。 その場合、各剰余クラスは開始点ごとに最大 1 つの到達可能な整数値を提供するため、到達可能なセットは有限になります。 

これにより、問題は、到達可能なコンポーネントに合計重みがゼロ以外のサイクルが含まれているかどうかを検出することに集約されます。 

ブルート フォース シミュレーションでは、累積された合計を追跡しながら、グラフ内のすべてのウォークを調査しようとします。 各ステップが複数のルールに分岐し、サイクルによって無限の再訪が可能になるため、これはすぐに指数関数的になります。 

この改善は、無限性の唯一の原因がサイクル重みの不一致であることを認識することによってもたらされます。 これにより、各強結合成分 (SCC) を圧縮できます。 SCC 内では、エッジの重みがポテンシャル関数と一致しているかどうかをチェックします。 そうでない場合、SCC には「悪い」サイクルが含まれており、すぐに値の無限生成が可能になります。 

すべての SCC を特定した後、それらを有向非巡回グラフに折りたたみます。 次に、各 SCC から、不良 SCC に到達できるかどうかを確認します。 それが可能であれば、そのコンポーネントから開始すると、最終的には無限のジェネレーター サイクルにアクセスできるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(状態) | 遅すぎる |
 | SCC + 一貫性 + 到達可能性 DP | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 各剰余クラスのモジュロをモデル化する$n$グラフ内のノードとして。 あらゆる指示に対して$(a, b)$、ノードから有向エッジを作成します$a \bmod n$に$(a \bmod n + b) \bmod n$重さで$b$。 これは、ルールを適用すると剰余と数値の両方がどのように変化するかを正確にキャプチャします。 
2. グラフを強く接続されたコンポーネントに分解します。 1 つの SCC 内では、すべてのノードが相互に到達可能であるため、累積値に影響を与える可能性のあるサイクルは完全に 1 つのコンポーネント内に存在する必要があります。 
3. 各 SCC について、エッジを横断することによって各ノードに潜在的な値を割り当ててみます。 値 0 を持つ SCC 内の任意のノードから開始し、次の関係を使用してエッジに沿って制約を伝播します。$pot[v] = pot[u] + w$。 
4. 伝播中に、以前に割り当てられた値が新しい値と一致しないノードに到達した場合、SCC に矛盾したサイクルが含まれているとしてマークを付けます。 この不一致は、合計の重みがゼロ以外のサイクルに直接対応します。 
5. SCC の凝縮グラフを構築します。これは、有向非巡回グラフであることが保証されます。 各ノードは、強く接続されたコンポーネント全体を表します。 
6. 一貫性のないすべての SCC を「不良」としてマークします。 
7. この情報を逆トポロジー順序で凝縮 DAG を介して伝播します。 SCC は、それ自体が不良であるか、不良状態に達する可能性のある別の SCC への発信エッジがある場合、不良状態に達する可能性があるとマークされます。 
8. クエリごとに、開始残基クラスの SCC を見つけます。$x \bmod n$。 この SCC が不良 SCC に到達できる場合は、「Yes」を出力します。 それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 SCC 内では、すべてのサイクルはエッジ トラバーサルの組み合わせです。 すべてのエッジ制約が一貫している場合、すべてのウォークにはエンドポイント間に明確に定義された潜在的な差があるため、すべてのサイクルの合計がゼロになる必要があります。 これは、走査を繰り返してもノードごとの固定オフセットを超えて累積値を変更できないため、到達できる値は有限個のみであることを意味します。 潜在的な代入中に矛盾が発生した場合、それは重みがゼロでないサイクルに正確に対応し、これを無限に繰り返して無制限の値を生成することができます。 SCC を折りたたむことで、サイクルについてローカルでのみ推論できるようになり、到達可能性 DP によって、そのようなサイクルが開始位置からアクティブ化できるかどうかを検出できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m, q = map(int, input().split())
    
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b = map(int, input().split())
        u = a % n
        v = (u + b) % n
        g[u].append((v, b))
    
    # Tarjan SCC
    idx = 0
    stack = []
    onstack = [False] * n
    ids = [-1] * n
    low = [0] * n
    comp = [-1] * n
    comp_id = 0

    def dfs(u):
        nonlocal idx, comp_id
        ids[u] = low[u] = idx
        idx += 1
        stack.append(u)
        onstack[u] = True

        for v, _ in g[u]:
            if ids[v] == -1:
                dfs(v)
                low[u] = min(low[u], low[v])
            elif onstack[v]:
                low[u] = min(low[u], ids[v])

        if low[u] == ids[u]:
            while True:
                x = stack.pop()
                onstack[x] = False
                comp[x] = comp_id
                if x == u:
                    break
            comp_id += 1

    for i in range(n):
        if ids[i] == -1:
            dfs(i)

    cg = [[] for _ in range(comp_id)]

    # build condensed graph edges
    for u in range(n):
        for v, w in g[u]:
            if comp[u] != comp[v]:
                cg[comp[u]].append((comp[v], u, v, w))

    # check bad SCCs via potential assignment
    bad = [False] * comp_id
    visited = [False] * n
    pot = [0] * n

    for i in range(n):
        if not visited[i]:
            cid = comp[i]
            stack = [i]
            visited[i] = True
            pot[i] = 0

            nodes = [i]
            ok = True

            while stack and ok:
                u = stack.pop()
                for v, w in g[u]:
                    if comp[v] != cid:
                        continue
                    if not visited[v]:
                        visited[v] = True
                        pot[v] = pot[u] + w
                        stack.append(v)
                        nodes.append(v)
                    else:
                        if pot[v] != pot[u] + w:
                            ok = False
                            break
                if not ok:
                    break

            if not ok:
                bad[cid] = True

    # build SCC graph (clean)
    dag = [[] for _ in range(comp_id)]
    for u in range(n):
        for v, w in g[u]:
            if comp[u] != comp[v]:
                dag[comp[u]].append(comp[v])

    # reach bad via reverse DP
    from collections import deque

    outdeg = [0] * comp_id
    rev = [[] for _ in range(comp_id)]
    for u in range(comp_id):
        for v in dag[u]:
            rev[v].append(u)
            outdeg[u] += 1

    can = bad[:]
    dq = deque([i for i in range(comp_id) if bad[i]])

    while dq:
        v = dq.popleft()
        for u in rev[v]:
            if not can[u]:
                can[u] = True
                dq.append(u)

    for _ in range(q):
        x = int(input())
        r = x % n
        cid = comp[r]
        print("Yes" if can[cid] else "No")

if __name__ == "__main__":
    solve()
```コードの最初の部分は、各ノードが剰余クラスであり、各命令が有向重み付きエッジとなる剰余グラフを構築します。 Tarjan のアルゴリズムは、このグラフを強く接続されたコンポーネントに圧縮し、すべてのサイクルがコンポーネント内に閉じ込められるようにします。 

次のフェーズでは、各ノードに潜在的な値を割り当てようとすることで、各 SCC の一貫性をチェックします。 矛盾が現れた場合、そのコンポーネントには合計重みがゼロ以外のサイクルが含まれているため、不良としてマークされます。 

最後に、逆到達可能性伝播により、最終的に不良 SCC に到達する可能性のあるすべてのコンポーネントがマークされます。 クエリは、開始残基の SCC をチェックし、そのようなコンポーネントに到達できるかどうかを確認することになります。 

累積された重みが大きくなる可能性があるため、整数値には注意が必要ですが、Python は任意の精度を安全に処理します。 主な論理的な微妙な点は、不整合検出が SCC ごとに確実に行われるようにすることです。 グローバルにチェックすると、無関係なコンポーネントが誤って混合されてしまいます。

 ## 特殊なケース

 一般的なエッジ ケースは、剰余が非ゼロ シフトでそれ自体にマップされる自己ループ命令です。 この場合、SCC は単一ノードで構成されており、整合性チェックによりそれが即座に検出されます。$pot[u] = pot[u] + b$でなければ不可能です$b = 0$、正しく不良としてマークされ、無限の答えが生成されます。 

別のケースには、複数の互いに素な SCC が含まれ、1 つのみに非ゼロ サイクルが含まれます。 伝播ステップにより、この不良 SCC に到達できるコンポーネントのみがマークされるようになり、無関係な残基が誤って分類されるのを防ぎます。 

最後の微妙なケースは、サイクルが存在するが、すべての合計の重みがゼロである場合に発生します。 潜在的な割り当ては各 SCC 内でグローバルに成功し、多くの異なるパスが存在しますが、それらはすべてノードごとに同じ累積値に集約されるため、到達可能なセットは有限のままです。
