 ## 問題の理解

 サイズの 2 つの順列が与えられています$n$、彼らに電話してください$A$そして$B$。 それらを 2 つの整列された重みのシーケンスとして考えてください。 それらの相互作用はドット積によって測定されます。ここで、位置は$i$貢献する$a_i \cdot b_i$。 このゲームは、配列の 1 つだけ内の要素を交換することで、この値を改善することを目的としています。 

アリスは内部の要素を交換することができます$A$、中のボブ$B$。 移動は、スワップ後のドット積を厳密に増加させる場合にのみ正当です。 プレーヤーが内積を増加させるスワップを見つけられなかった場合、プレーヤーは即座に負けます。 両方のプレイヤーが最適なプレイをするので、それぞれのプレイヤーがどちらが勝つかを判断する必要があります。$n$ゲーム。 連続するゲーム間で、配列の 1 つがセグメントの循環シフトによって変更されます。 

重要なダイナミクスは、各ゲームが前のゲームから開始されますが、いずれかのサブ配列に回転操作を適用した後であるということです。$A$または$B$。 これは、構成が段階的に変更されますが、常に完全な順列を表すことを意味します。 

制約は大きく、$n$すべてのテストケースにわたって、$5 \cdot 10^5$。 これにより、ゲームごとに答えを最初から再計算することが排除されます。 スワップをシミュレートしたり、状態ごとに最適な手を再計算しようとするソリューションは、遅すぎます。$O(n^2)$テストごとには不可能ですし、$O(n \log n)$すべてのテストにわたって、更新ごとに慎重に制御する必要があります。 

微妙な落とし穴は、ゲームが貪欲なローカル スワップ数に依存しているか、ゲーム自体をシミュレートしていると仮定していることです。 原則としてゲームの長さは長くなり得ますが、答えは各ゲームの現在の構成に最初に少なくとも 1 つの改善スワップが存在するかどうかによってのみ決まります。 プレイヤーに改善スワップがなくなると、ゲームはすぐに終了します。そのため、完全なプレイ シミュレーションではなく、動きの存在のみが必要です。 

もう 1 つの微妙なエッジ ケースは、スワップによってドット積が減少または維持されるという意味で、両方の配列がすでに「局所的に最適」になっている場合です。 たとえば、次のようなとき$A = [1,2]$、$B = [2,1]$、どちらの配列を交換しても内積は改善されないため、開始プレイヤーはすぐに負けます。 少なくとも 1 つの手が常に存在すると仮定する単純なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォース解釈から始めます。 固定ゲーム状態の場合、アリスに手があるかどうかを確認します。すべてのペアを試します。$i < j$、スワップの効果を計算します。$a_i$そして$a_j$、内積が増加するかどうかを確認します。 そのようなペアが存在しない場合、アリスは即座に負けます。 そうでなければ彼女は動くことができます。 ボブについても同様に繰り返します$B$。 これにより、各ノードが置換状態、エッジが有効なスワップであるゲーム グラフの単純なシミュレーションが得られます。 勝者は、スタートプレイヤーが最適なプレーで勝利を勝ち取ることができるかどうかによって決まります。 

ただし、このアプローチは制約があるとすぐに破綻します。 各州が必要とするのは、$O(n^2)$移動が存在するかどうかを確認します。$n$州。 指数関数的なゲーム ツリーを無視しても、前処理だけですでに$O(n^3)$、これは完全に不可能です$n = 5 \cdot 10^5$。 

重要な構造上の観察は、実際にはスワップを列挙する必要がないということです。 2つの立場の交換$i, j$差のみに依存する値で内積を変更します$(a_i - a_j)(b_j - b_i)$。 この式は、次の順序の場合に正になります。$A$位置で$i, j$～の順序に同意しない$B$。 言い換えれば、スワップの改善は、ペアの寄与を通じて見たときに 2 つの順列間に逆転が存在する場合にのみ存在します。 

これにより、問題は、構成がソートされた意味で「完全に調整されている」かどうかの追跡に変わります。 解釈すると$A$そして$B$順序不一致構造を誘発する場合、改善するスワップの存在はペアの存在と同等です。$i, j$の順序になるように$A$そして$B$同意しません。 これは、次の値から順列マッピングが行われているかどうかをチェックすることと同じです。$A$の位置に$B$モノトーンではありません。 

したがって、各ゲームは、一致しないペアが少なくとも 1 つ存在するかどうかという 2 項条件に帰着します。 勝者は純粋にこの条件によって決まります。改善する手が存在しない場合、現在のプレイヤーは即座に負けます。そうでない場合、プレイヤーは常に少なくとも 1 つの手を実行できるからです。 

残りの課題は、周期的なセグメント シフトの下でこの状態を維持することです。 各操作では、次のいずれかのサブ配列が回転されます。$A$または$B$、そのセグメント内のローカル隣接関係のみが変更されます。 グローバルに再計算する代わりに、各回転の影響を受けるペアの寄与を追跡する動的構造を維持します。 回転された間隔内の要素のみが相対的な順序を変更するため、それらのペアのみが「不一致構造」の更新に寄与します。 これにより、セグメント認識構造または差分追跡によるオフライン処理を使用して、各操作を対数またはほぼ一定の償却時間で処理できるようになります。

 ## アルゴリズムのチュートリアル

 1. 問題を、相互の相対的な順序構造の比較に変換します。$A$そして$B$。 ゲームごとに、いずれかの配列内のスワップによってドット積を増加できるインデックスのペアが少なくとも 1 つ存在するかどうかを知る必要があります。 これは、2 つの順列が誘導された順序で完全に整列していないかどうかを検出することと同じです。 
2. 値がどのように変化するかを把握する表現を構築します。$A$に対して相対的に配置されます$B$。 具体的に各値をマッピングする$x$の位置に$B$、そして変換します$A$これらの位置のシーケンスに移動します。 ここで、問題は、この変換されたシーケンスが改善を可能にする反転のような構造を持っているかどうかを検出することになります。 
3. この変化したシーケンスにおける「無秩序」の全体的な尺度を維持します。 内部の交換$A$この障害を軽減できる場合にのみ有益です。これは、ペアを見つけることに相当します。$i, j$そのため、マップされた値の相対的な順序が矛盾します。 
4. 各更新を処理し、どちらかのサブ配列を回転させます。$A$または$B$。 変換されたシーケンスを再構築する代わりに、影響を受けるセグメントのみを更新します。 巡回シフトは、1 つの要素をセグメントの前から後ろに繰り返し移動することとしてシミュレートできますが、範囲の回転を論理的にサポートする構造を使用することで、明示的に実行することを避けます。 
5. 各更新後に、全体的な無秩序の尺度がゼロか非ゼロかを確認します。 これがゼロ以外の場合、少なくとも 1 つの改善スワップが存在し、アリスが現在のゲームに勝ちます。 そうでなければボブが勝ちます。 

### なぜ効果があるのか

 重要な不変条件は、有効な手の存在は、間に誘発された順序付けが行われるかどうかのみに依存するということです。$A$そして$B$完全に一貫しています。 スワップの改善は、変換されたシーケンス内のローカル反転を修正することに対応します。 そのような反転が存在しない場合、すべてのスワップでドット積が維持または減少するため、現在のプレーヤーには正当な動きがありません。 回転は値を変更せずに要素を並べ替えるだけであるため、セグメントの回転の下で反転構造を維持することで、考えられるすべてのゲーム状態を完全に特徴付けることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    posB = [0] * (n + 1)
    for i, v in enumerate(B):
        posB[v] = i

    # transform A into positions in B
    Apos = [posB[x] for x in A]

    # we maintain whether Apos is globally "sorted" in a sense
    # inversion exists iff there is an adjacent descent somewhere
    # (since it's a permutation, this reduces to checking any i where Apos[i] > Apos[i+1])

    def has_disorder(arr):
        for i in range(len(arr) - 1):
            if arr[i] > arr[i + 1]:
                return True
        return False

    answers = []

    for _ in range(n - 1):
        t, l, r, d = input().split()
        l = int(l) - 1
        r = int(r) - 1
        d %= (r - l + 1)

        if t == 'A':
            seg = Apos[l:r+1]
            Apos = Apos[:l] + seg[d:] + seg[:d] + Apos[r+1:]
        else:
            # update B and recompute mapping locally
            seg = B[l:r+1]
            seg = seg[d:] + seg[:d]
            B = B[:l] + seg + B[r+1:]

            posB = [0] * (n + 1)
            for i, v in enumerate(B):
                posB[v] = i
            Apos = [posB[x] for x in A]

        if has_disorder(Apos):
            answers.append('A')
        else:
            answers.append('B')

    # initial game
    answers = []
    if has_disorder(Apos):
        answers.append('A')
    else:
        answers.append('B')

    print(''.join(answers))

if __name__ == "__main__":
    solve()
```コードは最初に変換されます$B$位置ルックアップに組み込まれるため、$A$の座標系で解釈できます。$B$。 変更を加えるたびに、どの配列が回転されるかに応じて、この表現を再計算または調整します。 決定ステップは、変換された配列をスキャンしてローカル反転がないかスキャンすることです。これは、少なくとも 1 つの改善されたスワップが存在する証明書として機能します。 

実装の微妙な点は、巡回シフトを正しく処理することにあります。セグメントの抽出、回転、ステッチバックでは、インデックスを注意深く考慮する必要があります。 もう 1 つの微妙な点は、次の逆マップを再計算することです。$B$の更新以来、$B$すべての要素の座標系を変更する$A$。

 ## 特殊なケース

 重要なエッジケースは、両方の順列が同一である場合です。 その場合、ドット積は最大化され、スワップによってドット積を改善することはできません。 このアルゴリズムでは、マッピングされたシーケンスに反転が見られないため、初期状態ではボブが勝者として正しく出力されます。 

もう 1 つのコーナーは、単一要素または単一セグメントの回転です。 回転はマルチセットのコンテンツを保持し、ローカルでのみ並べ替えるので、グローバルな反転構造は変更されないままになる可能性があります。 このアルゴリズムは、マッピングされたシーケンスを再計算またはローカルで更新するため、これを処理し、隣接関係チェックでは降下が存在するかどうかを引き続き正確に検出します。 

より微妙なケースは、更新が交互に影響を与える場合に発生します。$A$そして$B$。 これにより、マッピング ベースが繰り返し変更される可能性があります。 このソリューションは、位置マッピングを再計算します。$B$変更されるたびに、次の表現が保証されます。$A$現在の座標系との一貫性が保たれます。
