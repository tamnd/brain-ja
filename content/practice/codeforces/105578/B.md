 ## 問題の理解

 グリッドが与えられています$n$行と$m$列。 グリッドを埋める前に、各行に 1 つの番号を割り当て、各列に 1 つの番号を割り当てます。 行の値を呼び出します$a_1 \dots a_n$と列の値$b_1 \dots b_m$。 あらゆる細胞$(i, j)$次に、ルールを使用して入力されます$$c_{i,j} = (a_i \cdot b_j) \bmod (nm).$$目標は配列を選択することです$a$そして$b$、範囲内のすべての値$[0, nm-1]$、それですべてが$nm$グリッドのセルはペアごとに区別されます。 まさにあるので、$nm$セルと各値は同じ範囲内にある必要があります。この条件により、グリッドは次のすべての整数の順列になります。$0$に$nm-1$。 

本当の制約は値を構築するだけではなく、双一次形式が確実に成り立つようにすることです。$a_i b_j \bmod nm$すべてのペアにわたって単射的です$(i, j)$。 衝突は、2 つの異なるペアが同じ積モジュロを生成することを意味します。$nm$、これはすぐに要件を破ります。 

制限により許可されるのは、$n, m \le 10^6$合計で$nm$テストケース全体で最大$10^6$。 これは、二次関数やさらには何も実行できないことを意味します。$O(n \log n)$素朴な方法でテストケースごとに。 構築する出力のサイズはすべて線形である必要があります。 

等差数列や単純なスケーリングなどの任意の構築を試行すると、微妙な失敗モードが発生します。 たとえば、$a_i = i$そして$b_j = j$の場合、乗算のモジュロのため、すぐに多くの衝突が発生します。$nm$非注入性が高く、残基を強く絡めます。 

もう 1 つの重要なエッジケースは次のような場合です。$n = m = 2$。 このような配列を構築することは不可能です。 係数が小さすぎて乗法構造が崩壊するため、どのような試みもすぐに強制衝突に遭遇します。 これは、実現可能性が以下の算術条件に依存することを示唆しています。$n$そして$m$、サイズだけではありません。 

## アプローチ

 ブルートフォースアプローチでは、値を割り当てようとします。$a$そして$b$そして、すべてかどうかを確認します$nm$製品は独特です。 賢明に候補を体系的に生成しようとしても、各チェックでは完全なデータを構築する必要があります。$n \times m$テーブル、原価計算$O(nm)$試行ごとの時間。 建設スペースが膨大であるため、このアプローチは完全に実行不可能です。 

重要な観察は、数値目標を最適化しようとしているのではなく、ペア間の全単射を構築しようとしているということです。$(i, j)$剰余剰余$nm$。 これは乗算モジュロの場合にのみ可能です$nm$デカルト積の完全なエンコードのように動作させることができます。 

これは、係数の算術構造と密接に関係していることがわかります。$nm$。 もし$n$そして$m$1 より大きい共通因数を共有する場合、異なる因数分解が係数の下で崩壊するため、衝突は避けられません。 逆に言うと、$\gcd(n, m) = 1$、中国剰余定理により、構造を 2 つの独立したコンポーネントに分離することができ、行インデックスと列インデックスをきれいにエンコードできます。 

これは建設的な戦略につながります。$n$そして$m$が互いに素である場合、各ペアが次のように値を割り当てることができます。$(i, j)$固有の剰余にマッピングし、剰余系の因数分解を 2 つの独立した次元に効果的に構築します。 

いつ$\gcd(n, m) > 1$、そのようなきれいな分離は存在せず、どのような構築でも必然的に異なるペアをマージします。

 ## アルゴリズムのチュートリアル

 させていただきます$N = nm$。 

1. かどうかを確認します。$\gcd(n, m) = 1$。 そうでない場合は「いいえ」を出力します。 この条件が必要なのは、そうしないとモジュラス構造が異なる行と列の因子の組み合わせ間で重なり合うためです。 
2. いつ$\gcd(n, m) = 1$、内部のグリッドの 2 つの次元を「分離」するモジュラー演算を使用して 2 つのヘルパー配列を構築します。$\mathbb{Z}_N$。 
3. 各行が個別の剰余クラス mod に対応するように行の値を割り当てます。$m$、ただし全範囲に広がります$[0, N-1]$。 便利な方法の 1 つは、次の倍数を使用することです。$m$ゼロでの縮退を避けるために小さなシフトを加えます。 
4. 各列が個別の残基クラス mod に対応するように列値を割り当てます。$n$、再び持ち上げられました$[0, N-1]$行構造と互換性のある方法で。 
5. 配列を出力します。 結果の乗算$a_i b_j \bmod N$ペアの一意のエンコーディングを生成します$(i, j)$。 

### なぜ効果があるのか

 いつ$n$そして$m$互いに素である剰余系の剰余系$nm$2 つの独立したシステムのモジュロの積のように動作します$n$とモジュロ$m$。 これにより、設計が可能になります$a_i$そして$b_j$つまり、一方は残基の 1 つの成分を制御し、もう一方は 2 番目の成分を制御します。 乗算は構造化されたペアリング関数として機能し、明確なペアが確実に得られるようにします。$(i, j)$同じ残基に崩壊することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        N = n * m

        import math
        if math.gcd(n, m) != 1:
            print("No")
            continue

        print("Yes")

        # row construction
        # simple safe lift into [0, N)
        a = [(i * m + 1) % N for i in range(n)]
        b = [(j * n + 1) % N for j in range(m)]

        print(*a)
        print(*b)

if __name__ == "__main__":
    solve()
```この解決策は、まず、全単射を妨げる構造的障壁である gcd 条件を使用して、不可能なケースをフィルタリングします。 有効な場合、次の間隔で行値が構築されます。$m$と列の値の間隔$n$、次に小さなシフトを適用して、製品をすぐに崩壊させる些細なゼロ相互作用を回避します。 

重要な実装の詳細は、すべての値を厳密に範囲内に保つことです。$[0, N-1]$。 モジュール式の縮小により、構造的な間隔に影響を与えることなくこれが保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    T = int(input())
    out = []
    for _ in range(T):
        n, m = map(int, input().split())
        if math.gcd(n, m) != 1:
            out.append("No")
        else:
            out.append("Yes")
            N = n * m
            a = [(i * m + 1) % N for i in range(n)]
            b = [(j * n + 1) % N for j in range(m)]
            out.append(" ".join(map(str, a)))
            out.append(" ".join(map(str, b)))
    return "\n".join(out)

assert run("2\n2 3\n2 2\n") != "", "basic sanity"

assert run("1\n1 5\n") != "", "degenerate row case"
assert run("1\n3 4\n") != "", "coprime larger case"

 ## 特殊なケース

 のために$n = 1$を選択すると、グリッドが 1 行に減ります。 衝突しない有効な割り当て$b_j$行間に相互作用がないため、機能します。 各列が一意の複数構造にマップされ、行間の衝突が存在しないため、この構造でも個別の値が生成されます。 

のために$m = 1$、状況は対称的です。行の値のみが重要であり、構造は衝突のない単純なシーケンスに退化します。 

のために$\gcd(n, m) > 1$、 のような$2 \times 2$または$4 \times 6$の場合、アルゴリズムはすぐに拒否します。 共有因子により残基相互作用の繰り返しが強制され、配置に関係なく単射性が不可能になるため、構築を試みても失敗します。 

共素だが大きな値の場合$10^6 \times 1$1 つの次元のみが意味のある変動に寄与し、もう 1 つの次元は自明なスケーリング係数として機能するため、構築は線形で安全なままです。
