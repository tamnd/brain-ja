 ## 解決策
 ## 問題の理解

 数直線上にそれぞれ異なる正の整数座標にある一連の点が与えられており、すべての点のペアの間に形成されるセグメントによるカバレッジを理解したいと考えています。 2点ごとに$x_i < x_j$、閉じたセグメントを定義します$[x_i, x_j]$以下のすべての整数を含む$x_i$に$x_j$。 タスクはクエリのリストに答えることです$k_1, k_2, \dots, k_q$、正確にいくつの整数点が含まれているか$k_i$セグメント。 

最初の微妙な点は、セグメントの数が次のように二次関数的に増加することです。$n$： のために$n$ポイントがあります$n(n-1)/2$セグメント。 と$n$まで$10^5$明らかに、すべてのセグメントとすべての整数点を明示的に列挙することはできません。 各クエリは非常に大きなデータを要求する可能性があります$k_i$（まで$10^{18}$)、これはよりもはるかに大きいです$n(n-1)/2$、非常に多くのクエリは当然のことながらゼロを返します。 

単純なアプローチでは、すべてのセグメントを反復処理し、そのセグメント内の整数ごとにカウンターをインクリメントしてから、出現回数をカウントする可能性があります。 これには大まかに必要になります$O(n^2 \cdot D)$操作、どこで$D$は端点間の距離です。 それは実現不可能です。最大のセグメントはほぼ全域に及ぶ可能性があります。$10^9$整数。 エッジケースには、遠く離れたセグメント、不可能なクエリが含まれます$k_i$、および端の点は、中間点よりも少ないセグメントに含まれます。 

慎重な解決策には、セグメントの算術構造を利用して、すべてのポイントを反復せずにカバレッジを計算する方法が必要です。 

## アプローチ

 問題が明確に定義されているため、強引なアプローチが機能します。つまり、すべてのセグメントが連続する整数をカバーしています。 原理的には、すべてを反復することができます$i < j$次に、すべての整数に対して$x$で$[x_i, x_j]$count 配列をインクリメントします。 すべてのセグメントを処理した後、クエリ$k_i$は、単にそのカウントを正確に含むポイント数を返します。 操作数は、すべてのセグメントの長さのおおよその合計であり、O(n \cdot \text{max_ distance}) に達する可能性があり、明らかに長すぎます。$n=10^5$までの距離$10^9$。 

重要な洞察は、カバレッジ パターンが区分的に線形であるということです。 連続するポイント間のギャップに注目すると、ギャップ内の整数をカバーするセグメントの数は、純粋に左右のポイントの数によって決まります。 Specifically, for a gap$[x_i, x_{i+1}]$、内部の各整数は正確にカバーされます$(i) \cdot (n-i)$左側の任意の点と右側の任意の点を選択して、ギャップをカバーするセグメントを形成できるためです。 エンドポイント自体は特別です。最初のポイントは次のようにカバーされます。$n-1$セグメントが右で終わる場合、2 番目の点は、左または右の端点として関与するセグメントによってカバーされます。などです。ギャップと端点を個別に処理することで、すべての整数を反復処理することなくカバレッジ数を計算できます。 

次に、正確にカバーされる整数のカウントを累積します。$k$辞書またはハッシュマップを使用してセグメントを作成し、クエリに応答します。$O(1)$クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * 最大距離) | O(最大距離) | 遅すぎる |
 | 最適 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポイントを整理する$x_1, \dots, x_n$ソートが保証されていない場合。 これにより、ギャップが昇順になることが保証されます。 
2. 空の辞書を初期化する`count_map`正確にカバーされる整数の数を保存するには$k$セグメント。 
3. それぞれのギャップを処理する$[x_i, x_{i+1}]$のために$i = 1$に$n-1$。 させて`length = x_{i+1} - x_i - 1`、厳密に点間の整数の数。 このギャップ内の任意の整数をカバーするセグメントの数は正確に`i * (n - i)`あるから`i`左を指して、`n-i`は、ギャップを含む右側の形成セグメントを指します。 追加`length`に`count_map[i * (n - i)]`。 
4. エンドポイント自体を処理します。 ポイントについて`x_i`、それをカバーするセグメントの数は`(i-1) * (n-i) + (i-1) + (n-i) = i*(n-i)`で開始または終了するセグメントを扱う場合`x_i`。 実際には、ギャップ ロジックをわずかに調整することで、エンドポイントをギャップ カウントに含めることができます。 
5. ギャップとエンドポイントを処理した後、`count_map`正確にカバーされる整数のすべての数が含まれます`k`セグメント。 クエリごとに`k_i`、 戻る`count_map.get(k_i, 0)`。 
6. すべてのテスト ケースに対して繰り返します。 

これが機能する理由: 整数をカバーするセグメントの数は、指定された点の位置でのみ変化します。 点間では、すべての整数が同じセグメントのセットを認識します。 ポイントとエンドポイントの間の間隔ごとにカバレッジをカウントすることで、個別に繰り返すことなく、すべての整数を取得します。 すべてのセグメントは点のペアによって決定され、ギャップに含まれない整数は点自体にあり、それが処理されるため、これは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        x = list(map(int, input().split()))
        ks = list(map(int, input().split()))
        
        count_map = {}
        
        # process gaps
        for i in range(n-1):
            length = x[i+1] - x[i] - 1
            if length > 0:
                key = (i+1) * (n-(i+1))
                count_map[key] = count_map.get(key, 0) + length
        
        # process points themselves
        for i in range(n):
            key = (i) * (n-1-i) + (n-1)  # number of segments covering x[i]
            count_map[key] = count_map.get(key, 0) + 1
        
        res = [str(count_map.get(k, 0)) for k in ks]
        print(' '.join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、組み合わせ公式を使用して、各ギャップ内の整数の数とそれをカバーするセグメントの数を計算します。`i*(n-i)`。 エンドポイントは、それらを直接含むセグメントをカウントすることによって個別に処理されます。 辞書を使用すると、`O(1)`それぞれのクエリルックアップ`k_i`。

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) per test case | Each gap and endpoint is processed once, then each query is a dictionary lookup. |
 | スペース | O(n) |`count_map`ストア数は最大で n^2 の異なるセグメント カバレッジをカウントしますが、通常はさらに少なくなります。 |

 問題の制約が sum(n) ≤ 10^5 および sum(q) ≤ 10^5 である場合、この解決策は 2 秒未満で快適に実行されます。
