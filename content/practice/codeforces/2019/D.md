 ## 解決策
 ## 問題の理解

 並んでいます$n$都市ごとに期限がある$a_i$。 時間 1 で征服を開始する都市を 1 つ選択し、その後の時間ステップごとに、隣接する未征服都市に拡張します。 目標はすべての都市を征服することです$i$時間またはその前に$a_i$。 問題は、征服に成功できる開始都市がいくつあるかです。 

入力は複数のテスト ケースを提供し、それぞれが指定します$n$そして配列$a$。 出力は、勝利を保証する各テスト ケースの開始位置の数です。 

制約は強力です。$n$到達できる$2 \cdot 10^5$すべてのテストケースの合計も$2 \cdot 10^5$。 すべての開始都市をチェックし、段階的に拡張をシミュレーションする単純なソリューションでは、大まかに次のことが必要になります。$O(n^2)$テストケースごとに、これは遅すぎます。 必要です$O(n)$テストケースごとに。 

重要な微妙な点は、期限によって一部の都市を即座に征服する必要があり、期限を 1 つでも遵守しないと開始都市が無効になることです。 エッジ ケースには、境界で 1 に等しいデッドラインや、厳密に増加または減少する配列が含まれます。 たとえば、$n = 3$そして$a = [1, 2, 3]$, 都市1からスタートするのは問題ありませんが、都市3からスタートすると都市1に間に合わず失敗します。 

## アプローチ

 ブルートフォース手法は簡単です。開始都市の候補ごとに、左右の拡大をシミュレートし、各ステップで時間を増加させ、時間が超過するかどうかを確認します。$a_i$。 正しいですが、最悪の場合の複雑さは次のとおりです。$O(n^2)$までの可能性があります$4 \cdot 10^{10}$複数のテストケースにわたる操作 - 受け入れられません。 

線形解を導き出す洞察は、展開が常に連続したセグメントを形成することを観察することで得られます。 最も早く遠くの都市を征服できる$d$始まりの街からは時間だ$1 + d$。 したがって、成功の条件は、開始都市から左右に伸びるセグメントについて、期限が$a_i$少なくともスタートからの距離プラス 1 です。 つまり、次のように定義すると、$b_i = a_i - i$そして$c_i = a_i - (n-i+1)$の場合、プレフィックスとサフィックスの条件が満たされる場合、都市は開始点として有効です。 

これにより、問題は 2 つのパスによる単一の線形スキャンに縮小されます。1 つはサフィックスの実現可能性をチェックするための左から右へのパス、もう 1 つはプレフィックスの実現可能性を確認するための右から左へのパスです。 あらゆる可能な展開を明示的にシミュレートする必要はもうありません。

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化します。`left_ok`そして`right_ok`、長さの$n$、各サイドから拡張した場合に成功する可能性のある最も早いポジションと最新のポジションを追跡します。 
2. 左から右にトラバースします。 実行時間を守る`t`1 から始まります。都市ごとに`i`、どうかを確認してください`t <= a[i]`。 その場合は設定してください`right_ok[i] = True`そして増加します`t`。 そうしないと、左から右への拡張では、この位置から開始して後続のすべての都市に到達できなくなります。 
3. 同様に右から左へトラバースし、設定します。`left_ok[i]`かどうかに応じて`t <= a[i]`逆に。 
4. 両方の条件が満たされている都市は、有効な開始都市となります。`left_ok[i]`そして`right_ok[i]`は本当です。 これらの都市を数えてください。 
5. カウントを出力します。 

それが機能する理由: どの開始都市でも、左右に拡張することは期限によって制限されます。 配列`left_ok`そして`right_ok`各方向の期限を尊重する最大の連続セグメントをエンコードします。 それらの交差により、最初からの拡張がすべての期限を満たす正確な都市が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    left_ok = [0] * n
    right_ok = [0] * n
    
    # left to right
    time = 1
    for i in range(n):
        if time <= a[i]:
            right_ok[i] = 1
            time += 1
        else:
            break
    
    # right to left
    time = 1
    for i in range(n-1, -1, -1):
        if time <= a[i]:
            left_ok[i] = 1
            time += 1
        else:
            break
    
    # count valid starting cities
    ans = 0
    for i in range(n):
        if left_ok[i] and right_ok[i]:
            ans += 1
    print(ans)
```最初のパスでは、都市 1 から開始して右に移動する際に期限が遵守されることが保証されます。 2 番目のパスでは右からも同じことが保証されます。 双方向が可能な都市のみが有効な開始位置となります。 使用する`break`早期に行うことで、期限を過ぎた場合の不必要なチェックを回避できます。

 ## 特殊なケース

 1. **単一都市**:`n = 1, a = [1]`。 どちらのパスも自明に成功するため、アルゴリズムは 1 を返します。 
2. **距離の制約と等しい期限**:`n = 5, a = [1,2,3,4,5]`。 一番左の都市のみが満たされます`right_ok`、右端のみが満たされます`left_ok`、したがって、交差点は中心都市 (インデックス 2) がある場合はそれになります。 アルゴリズムは実行可能な開始を正確に識別します。 
3. **すべて平等な締め切り**:`n = 5, a = [5,5,5,5,5]`。 どちらのパスでもすべてのフラグが設定され、すべての都市が有効になります。 

これらのエッジ ケースは、アルゴリズムが境界と最小値/最大値を正しく処理することを示しています。 リニア スキャンでは、追加のロジックを必要とせずに、「開始からの距離 ≤ 期限」の不変条件が自然に強制されます。
