 ## 解決策
 ## 問題の理解

 整数座標のソートされたリストが 1 行に与えられます。 これらの点のすべてのペアから、閉じたセグメントを描画します。これは、端点間のすべての整数点がそのセグメントに含まれることを意味します。 このようなセグメントをすべて構築した後、ライン上の各整数位置はいくつかのセグメントでカバーされます。 タスクは、正確に指定された数のセグメントによってカバーされる整数の位置の数を尋ねる複数のクエリに答えることです。 

構造を解釈する直接的な方法は、線上の各点が、それを囲む選択された端点のペアの数に応じて「カバレッジ カウント」を累積するということです。 

この制約は、ポイントとクエリの両方の数が、テスト全体での合計がテスト ケースごとに最大 10 万までと大きくなる可能性があることを意味します。 これは、点のすべてのペアを反復する解法を即座に除外します。これは、二次関数であり、時間制限をはるかに超えるためです。 O(n²) 個のセグメントがあるため、すべてのセグメントの寄与を明示的に構築することさえ不可能です。 

主な問題点は、カバレッジが個々のセグメントに限定されず、ソートされた順序でのインデックス間の組み合わせ関係に依存することです。 

微妙なエッジ ケースは、座標が非常にまばらな場合、たとえば、連続する x 値の差が大きい場合に発生します。 このような場合、エンドポイント間の整数位置を反復する単純な解決策は失敗します。座標範囲が最大 10⁹ まで拡張される可能性があり、整数ごとの反復が不可能になるためです。 もう 1 つのエッジ ケースは、すべての x 値が連続している場合です。 ここでは構造が密になり、正しい解では O(n²) セグメントの相互作用を列挙せずに処理する必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのペア (i, j) を生成し、x_i と x_j の間のすべての整数点のカバレッジをマークします。 これは定義に直接従うため、原理的には正しいですが、各セグメントは最大 O(max x) の位置をカバーでき、O(n²) 個のセグメントがあるため、これはすぐに爆発します。 たとえ小さな最適化を行ったとしても、構造は基本的に大きすぎてシミュレーションできません。 

重要な観察は、視点を逆転させることです。 点をカバーするセグメントについて考える代わりに、与えられた整数位置 p をカバーするセグメントの数を尋ねます。 セグメント [x_i, x_j] は、x_i ≤ p ≤ x_j の場合に p を正確にカバーします。これは、p の反対側にある 2 つの端点を選択することと同じです。 cnt_left(p) をポイント数 ≤ p として定義し、cnt_right(p) をポイント数 ≥ p として定義すると、p をカバーするセグメントの数は、cnt_left(p) に cnt_right(p) を掛けて、順序付け制約のオーバーカウント補正を引いたものになります。 ただし、エンドポイントは厳密に指定されたセットからのものであるため、正確な構造は、p の左側に x_i がいくつあるかにのみ依存して関数に単純化されます。 

連続する x_i と x_{i+1} の間では、その区間内にセグメント エンドポイントが存在しないため、カバレッジ カウントは一定です。 これにより、問題は、個々の整数の位置ではなく、ソートされた座標によって引き起こされる間隔の分析に軽減されます。 

連続するポイント間のギャップごとに、そのギャップを完全にカバーするセグメントの数を計算します。 その値は、その領域の左右に何個のポイントがあるかによってのみ決まります。 各ペア (i, j) は正確に (x_j - x_i) 個の整数ポイントに寄与し、そのような各ポイントは同じカバレッジ構造を共有します。 これにより、座標範囲ではなくインデックス ペアの組み合わせカウントを使用して、寄与を O(n) で集計することができます。 

最後に、カバレッジ値の頻度マップを構築し、クエリに直接回答します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · 範囲) | O(範囲) | 遅すぎる |
 | 最適 | 実装に応じて O(n²) または O(n log n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 インデックスのペアからの寄与という観点から問題を再定式化し、各カバレッジ値を受け取る整数位置の数を集計します。 

1. 与えられた点を並べ替えて修正します。 これらはすでにソートされているため、並べ替えることなく位置を直接操作できます。 
2. 指定された点に隣接する整数座標でのみカバレッジが変化することを観察します。 x_i と x_{i+1} の間では、どのセグメントがそれをカバーするかに関して、すべての整数点は同じように動作します。 これにより、各間隔をブロックとして扱うことができます。 
3. インデックスのペア (i, j) ごとに、区間 [x_i, x_j] 内に厳密に整数点がいくつあるかを計算します。 このようなすべての点は、端点がそれを囲むセグメントからの寄与を正確に受け取るため、各ペアはその区間全体で均一に寄与します。 
4. 間隔内のすべてのポイントを反復する代わりに、差分を使用してカウントを累積します。 各セグメントは範囲更新に寄与するものとして扱います: [x_i, x_j] にわたる +1 カバレッジ。 整数座標にわたる差分配列は座標が大きいため不可能であるため、更新を連続する x 値間の間隔の寄与に圧縮します。 
5. これを、各基本区間 [x_k, x_{k+1}) をカバーするセグメントの数をカウントすることに変換します。 固定間隔の場合、カバーするセグメントの数は、エンドポイント i ≤ k および j ≥ k+1 を選択することによって決定され、k · (n − k) 個の選択肢が与えられます。 
6. このような各区間の長さは (x_{k+1} − x_k) であるため、同じカバレッジ値 k · (n − k) を持つ多くの整数点に寄与します。 
7. 1 から n-1 までのすべての k を集計し、間隔の長さを乗算した各カバレッジ値の頻度を保存します。 
8. 最後に、事前に計算された周波数マップを検索して、各クエリに答えます。 

### なぜ効果があるのか

 重要な不変条件は、連続する座標間のギャップ内のすべての整数点は、セグメント カバレッジに関して区別できないことです。そのような点を 1 つカバーするセグメントはすべてをカバーし、1 つが欠けているセグメントはすべてを見逃します。 これにより、問題は座標に関する推論からインデックス境界に関する推論に軽減されます。 ギャップをカバーするセグメントの数は、その左右にある端点の数にのみ依存します。これはギャップごとに固定されており、正確な整数の位置とは関係ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        x = list(map(int, input().split()))
        queries = list(map(int, input().split()))

        freq = defaultdict(int)

        for i in range(n - 1):
            left = i + 1
            right = n - (i + 1)
            cov = left * right
            length = x[i + 1] - x[i]
            freq[cov] += length

        res = []
        for k in queries:
            res.append(str(freq.get(k, 0)))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装は、各セグメントの寄与を隣接点間隔に圧縮することに依存しています。 i を介したループは、連続する座標間の各基本間隔を処理します。 区間 i の場合、その区間をカバーするセグメントは i 以降に開始し、i 後に終了する必要があり、積構造 (i+1) · (n−i−1) が得られます。 間隔の長さを乗算すると、セグメント数が整数ポイントの数に変換されます。 

よくある落とし穴は、ギャップを考慮せずに座標をインデックスとして直接処理しようとすることです。 各間隔は複数の整数の位置を表すため、x[i+1] − x[i] の乗算は不可欠です。 

## 実用的な例

 点 [1、3、6] を持つ小さなケースを考えてみましょう。 セグメントは [1,3]、[1,6]、[3,6] です。 区間 [1,3) は長さ 2 で、1 で始まり 3 または 6 で終わるセグメントによってカバーされるため、カバレッジはインデックス 0 付近のエンドポイントによって決まります。区間 [3,6) は長さ 3 で、インデックス 1 を含むセグメントによってカバーされます。 

| 間隔 | 長さ | カバレッジ計算式 | 結果 |
 | --- | --- | --- | --- |
 | [1,3) | 2 | 1×2 | 2 |
 | [3,6) | 3 | 2×1 | 2 |

 これは、異なる間隔サイズにわたって同じカバレッジ値がどのように表示されるかを示しています。 

次に [1,2,4,7] を考えてみましょう。 隣接する各ギャップは独立して寄与し、カバレッジは実際の距離ではなくインデックス分割にのみ依存します。 これは、間隔が固定されるとジオメトリは無関係であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 各間隔は 1 回処理され、各クエリは O(1) ルックアップで応答されます。 
| スペース | O(n) | 周波数マップは間隔ごとに最大 1 つのエントリを保存します。 

テスト ケース全体の n と q の合計は 2 × 10⁵ で制限されるため、合計の複雑さは制約と一致します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    from collections import defaultdict

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        x = list(map(int, input().split()))
        queries = list(map(int, input().split()))

        freq = defaultdict(int)

        for i in range(n - 1):
            cov = (i + 1) * (n - i - 1)
            freq[cov] += x[i + 1] - x[i]

        out.append(" ".join(str(freq.get(k, 0)) for k in queries))

    return "\n".join(out)

 ## 特殊なケース

 すべての座標が連続している場合、すべての区間の長さは 1 になり、解はインデックス ペアに関する純粋な組み合わせになります。 間隔の長さによる乗算が中立になるため、アルゴリズムは引き続き機能します。 

ギャップが非常に大きい場合、アルゴリズムは座標を直接反復することがないため、安定した状態を保ちます。 差分 x[i+1] − x[i] のみが使用され、複雑さに影響を与えることなく大きな値に安全にスケーリングされます。 

クエリが非常に大きな k を要求する場合、そのようなカバレッジを生成する間隔がないため、頻度マップは単純にゼロを返します。
