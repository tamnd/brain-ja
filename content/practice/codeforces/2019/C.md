 ## 解決策
 ## 問題の理解

 カードのコレクションが与えられ、各カードには整数が書かれています。 1 から 1 までの数字ごとに、$n$, 私たちは最初にそのタイプのカードを何枚持っているかを正確に知っています。 さらに、$k$コインがあり、各コインで選択した任意の種類のカードを購入できます。 購入後、すべてのカードが同じ枚数のカードを含み、どのデッキにも同じ番号のカードが 2 枚含まれないように、すべてのカードをデッキに分割したいと考えています。 

目標は、最適なカード購入で達成可能なデッキの最大サイズを決定することです。 

制約については慎重に検討する必要があります。 最大で$2 \cdot 10^5$すべてのテスト ケースにわたるカード タイプ。各カード タイプの数は最大で$10^{10}$、 そして$k$と同じ大きさにすることができます$10^{16}$。 これらの境界により、各カードを個別に列挙するソリューションが不要になります。 各カード タイプのカウントのみを使用し、大きな数に対して対数時間で機能するアプローチが必要です。 

注意すべきエッジケースには、一部のカード タイプがカード 0 から始まるシナリオが含まれます。$k$に比べて非常に大きい$n$、またはすべてのカードが同じタイプである場合。 たとえば、入力が次の場合:```
2 100
0 100
```タイプ 1 のカードは 0 枚、タイプ 2 のカードは 100 枚ありますが、コインは 100 枚あります。 単純なアプローチでは、単純にカードを配布しようとし、デッキ サイズのバランスをとるためにタイプ 1 のカードを購入できることに気づかない可能性があります。 

## アプローチ

 ブルートフォース手法では、1 からカードの総数に加えて、すべての可能なデッキ サイズが試行されます。$k$, それぞれについて、番号が重複せずに同じサイズのデッキを形成できるかどうかを確認します。 各候補デッキサイズについて$x$, 各カードの種類から何組のデッキを組むことができるかを計算し、合計の不足分がカードを購入することで補えるかどうかを確認します。 これは正しいですが、各デッキのサイズを最大までチェックするため、遅すぎます。$10^{16}$不可能です。 

重要な観察は、「すべてのデッキが同じサイズで重複してはいけない」という条件が単純な不等式に変換されるということです。$d$、現在各タイプでデッキをいくつ埋めることができるかを計算できます。$i$として$\text{floor}(a_i / d)$。 この合計を$s$。 そうすると、必要なデッキの総数は次のようになります。$\text{ceil}(\text{total cards after purchase} / d)$。 同様に、サイズを達成するために購入する必要がある追加カードの総数$d$各デッキについては$\text{desired decks} \cdot d - \sum_i a_i$である必要があります$\le k$。 

この観察により、**デッキサイズでの二分探索**を使用できるようになります。 問題は、候補サイズについて、有効なパーティションに到達するのに十分なカードを購入できるかどうかを確認することになります。 二分探索は必要なものだけなので高速です$O(\log (\text{max deck size}))$テストケースごとのチェック。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(max(a_i + k) * n) | O(n) | 遅すぎる |
 | 二分探索 / 貪欲 | O(n log(max(a_i + k))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初に持っているカードの総数を次のように計算します。$\text{total} = \sum_i a_i$。 最大デッキサイズを超えることはできません$\text{total} + k$。 
2. 次のコマンドで二分探索を初期化します。`low = 1`そして`high = total + k`。 有効な最大デッキサイズを検索します。 
3. 各候補デッキサイズについて`mid = (low + high) // 2`、すべてのサイズのデッキを作成するために必要な追加カードの数を計算します。`mid`。 これは、タイプごとに、次の差を合計することによって行われます。`mid`そして`a_i`以下のデッキの場合`mid`カード、最大でも`mid`デッキ。 より簡単な方法は、現在のカウントで可能なデッキの総数を次のように計算することです。`sum(a_i // mid)`そして計算します`needed = mid * number_of_decks - total_cards`。 
4. もし`needed <= k`、 それから`mid`は達成可能であるため、二分探索の下限を上に移動します。`low = mid + 1`。 さもないと、`mid`は大きすぎるため、上限を減らします。`high = mid - 1`。 
5. まで検索を続けます。`low > high`。 達成可能なデッキの最大サイズは次のとおりです。`high`。 

機能する理由: チェック関数はデッキ サイズで単調です - サイズが`d`より小さなサイズも実現可能です。 逆に、このサイズの場合、`d`これ以上のサイズは達成できません。 これにより、二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_deck_size(n, k, a):
    total = sum(a)
    low, high = 1, total + k
    while low <= high:
        mid = (low + high) // 2
        decks = sum(ai // mid for ai in a)
        needed = mid * decks - total
        if needed <= k:
            low = mid + 1
        else:
            high = mid - 1
    return high

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(max_deck_size(n, k, a))
```このコードは、バイナリ検索ロジックを関数に分割します。 合計します`a_i // mid`現在のカードで可能な完全に満たされたデッキの数を取得し、追加で必要なカードの数を計算します。 その数がコインの予算内であれば、このサイズのデッキを形成できることがわかります。 二分探索により、可能な最大サイズが効率的に見つかることが保証されます。 整数演算を使用すると、オーバーフローの問題が回避されます。

 出力：`2`説明したように、カードを 1 枚購入すると、サイズ 2 のデッキに分割できることが確認されました。 

**例 2:**

 入力:`5 4\n2 6 1 2 4`二分探索により、最大デッキ サイズが 3 であることがわかります。購入した追加カードにより、デッキに分配することができます`[1,2,3]`、`[1,2,4]`、`[1,2,5]`、など。 

これらのトレースは、不変条件がどのように変化するかを示しています。`needed <= k`二分探索をガイドします。
