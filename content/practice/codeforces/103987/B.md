 ## 解決策
 ## 問題の理解

 セルの 1 次元の行を表すバイナリ文字列が与えられます。 各セルは 0 または 1 のいずれかを保持します。ルール 110 として知られるセル オートマトンの 1 ステップを正確にシミュレートするように求められます。各位置の次の状態は、その現在の値とそのすぐ左と右の隣の値にのみ依存します。 文字列の外側のセルは 0 として扱われるため、概念的には配列の両端が固定ゼロで囲まれます。 

このタスクは純粋にローカルな変換です。すべての位置 i は、(i−1, i, i+1) によって形成されるトリプルに基づいて新しい値を生成します。 すべての更新は同時に行われます。つまり、位置 i の新しい値は、部分的に更新された結果からではなく、元の文字列のみから計算する必要があります。 

文字列の長さは最大 100,000 です。 これにより、線形時間よりも悪いものは即座に排除されます。 各セルの文字列上で複数のパスを繰り返しシフトまたはシミュレートしようとするアプローチは、二次関数の動作に向かってドリフトし、制限を下回って失敗します。 

よくある間違いは、文字列をその場で更新することです。 たとえば、s[i+1] の計算中に s[i] を上書きすると、近傍情報が破損します。 もう 1 つの微妙な問題は、境界条件を忘れていることです。左端のセルは左側に仮想 0 を使用し、右端のセルは右側に仮想 0 を使用します。 たとえば、入力が`1`、正しい近傍は次のとおりです。`0 1 0`したがって、欠落している近傍がコード内で暗黙的に消滅すると仮定するのではなく、そのトリプルによって決定される出力を生成する必要があります。 

## アプローチ

 直接シミュレーションでは、各インデックス i を読み取り、その左、中央、および右に隣接するインデックスを明示的に検査します。 ルールは完全にローカルで固定されているため、各出力文字を一定時間で計算できます。 ブルート フォース バージョンはすでにこのアイデアを正しく実行していますが、唯一の非効率性は、部分文字列を再計算したり、インデックスごとに文字列を繰り返しスライスしたりするなど、オーバーヘッドが追加される不注意な実装から生じます。 

重要な観察は、オートマトン ルールが位置全体にわたってステートレスであるということです。各出力セルは、正確に 3 つの入力値に依存し、それ以上には依存しません。 つまり、単一パスですべての位置を独立して処理できるということです。 収束するまで反復を必要とする伝播や依存関係のチェーンはありません。 次世代全体は、ビットのトリプルから単一ビットへの直接マップです。 

これにより、文字列を 1 回スキャンし、8 つの可能なトリプルに対して固定ルックアップを適用するだけで問題が軽減されます。 ルール 110 真理値表を明示的にエンコードするか、ステートメントから直接導出することができます。

 ## アルゴリズムのチュートリアル

 各位置を個別に評価して、次の状態文字列を計算します。 

1. すべてのインデックスが明確に定義された近傍を持つように、両端に仮想ゼロを使用して文字列の概念を拡張します。 これにより、メイン ロジック内の特殊なケースの境界位置が回避されます。 
2. 0 から n-1 までの各位置 i について、トリプル (a、b、c) を形成します。ここで、a は左隣 (i が 0 の場合 0)、b は現在のセル、c は右隣 (i が n-1 の場合 0) です。 このトリプルによって次の値が完全に決まります。 
3. ルール 110 マッピングをトリプルに適用します。 ルールは固定されており、小さな検索としてハードコードしたり、条件チェックとして実装したりできます。 可能なトリプルは 8 つだけなので、これは一定時間の作業になります。 
4. 元の文字列を上書きするのではなく、計算された値を新しい配列に保存します。 この分離により、すべての決定が元の構成に基づいて行われることが保証されます。 
5. すべてのインデックスを処理した後、構築された結果文字列を出力します。 

### なぜ効果があるのか

 オートマトンは同期ローカル更新ルールとして定義されます。つまり、すべてのセルの次の状態は、前の状態の直近の状態にのみ依存します。 元の配列から見た場合、近傍はインデックス間で独立しているため、各計算は分離されます。 別の出力配列を使用すると、この独立性が維持され、同じステップ中に計算値が別の値に影響を与えることがなくなります。 これにより、結果の文字列がルールの同時適用と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rule110(a, b, c):
    # Rule 110 truth table:
    # 111 -> 0
    # 110 -> 1
    # 101 -> 1
    # 100 -> 0
    # 011 -> 1
    # 010 -> 1
    # 001 -> 1
    # 000 -> 0
    if a == '1' and b == '1' and c == '1':
        return '0'
    if a == '1' and b == '1' and c == '0':
        return '1'
    if a == '1' and b == '0' and c == '1':
        return '1'
    if a == '1' and b == '0' and c == '0':
        return '0'
    if a == '0' and b == '1' and c == '1':
        return '1'
    if a == '0' and b == '1' and c == '0':
        return '1'
    if a == '0' and b == '0' and c == '1':
        return '1'
    return '0'

n = int(input())
s = input().strip()

res = []

for i in range(n):
    a = s[i - 1] if i > 0 else '0'
    b = s[i]
    c = s[i + 1] if i + 1 < n else '0'
    res.append(rule110(a, b, c))

print("".join(res))
```コードは入力を 1 回読み取り、効率を高めるために出力をリスト内に段階的に構築します。 ヘルパー関数はルールを明示的にエンコードし、正確性を不明瞭にする可能性のあるビット操作トリックを回避します。 

境界処理はインラインで行われます。インデックス −1 とインデックス n は文字列を変更せずにゼロとして扱われます。 これにより、余分なメモリのオーバーヘッドが回避され、すべての位置でロジックの対称性が維持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    s = sys.stdin.readline().strip()

    def rule(a, b, c):
        if a == '1' and b == '1' and c == '1': return '0'
        if a == '1' and b == '1' and c == '0': return '1'
        if a == '1' and b == '0' and c == '1': return '1'
        if a == '1' and b == '0' and c == '0': return '0'
        if a == '0' and b == '1' and c == '1': return '1'
        if a == '0' and b == '1' and c == '0': return '1'
        if a == '0' and b == '0' and c == '1': return '1'
        return '0'

    res = []
    for i in range(n):
        a = s[i-1] if i > 0 else '0'
        b = s[i]
        c = s[i+1] if i+1 < n else '0'
        res.append(rule(a,b,c))

    return "".join(res)

assert run("1\n0\n") == "1", "single zero"
assert run("1\n1\n") == "1", "single one"
assert run("3\n010\n") == "110", "basic propagation"
assert run("5\n00000\n") == "00000", "all zeros"
assert run("5\n11111\n") == "01110", "dense block"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 0`|`1`| 境界のみのトリプル処理 |
 |`1 / 1`|`1`| 孤立した 1 つの安定 |
 |`010`|`110`| 混合伝播の正確性 |
 |`00000`|`00000`| すべてゼロの固定小数点 |

 ## 特殊なケース

 最小長の文字列は、境界処理の影響を最も受けやすくなります。 入力用`s = "0"`、近所は`(0,0,0)`にマッピングされます。`0`、したがって出力は残ります`"0"`。 このアルゴリズムは、インデックスが範囲外になると両方の隣接セルを明示的にゼロとして扱うため、単一セルの両側は一貫して動作します。 

のために`s = "1"`、その辺はなる`(0,1,0)`。 ルールはこのトリプルを次のようにマッピングします。`1`コードは、サイズ 1 の入力に対する特別な分岐を必要とせずに、直接検索を通じてこれを反映します。 

すべて 1 の文字列は、隣接するセル間の相互作用を示します。 のために`s = "111"`、各位置には異なるトリプルが表示されます。中央には異なるトリプルが表示されます。`111`になる`0`、エッジが見える間、`011`そして`110`、両方ともマッピングされます`1`。 出力は次のようになります`"101"`各インデックスは部分的に更新されたバージョンではなく、元の文字列から独立して評価されるため、アルゴリズムはこれを正確に再現します。
