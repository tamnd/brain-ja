 ## 解決策
 ## 問題の理解

 左側に次のような 2 部グラフが与えられています。$n$ノードがあり、右側には$m$ノード。 各ノードは値を持ち、エッジは左のノードを右のノードに接続するだけです。 このタスクはエッジを直接選択することではなく、有効なマッチングのエンドポイントとして発生する可能性のあるノードのサブセットを選択することです。 

選択されたすべてのノードが正確に 1 つのエッジに一致し、複数のエッジでノードが使用されないような一致が存在する場合、ノードのサブセットは有効であるとみなされます。 言い換えれば、選択されたサブセットは、2 部グラフ内の一部の一致のエンドポイントのセットと正確でなければなりません。 一致しないノードをサブセットに含めることはできず、選択したすべてのノードをペアにする必要があります。 

各クエリ値について$x$、すべてのノード値の XOR が次と等しい有効なサブセットがいくつあるかを数える必要があります。$x$ここで、XOR はグラフの両側から選択されたすべてのノードに対して行われます。 答えは大きくなる可能性があるため、剰余を計算します。$10^9 + 7$。 

制約は非常に特殊な点で厳しいです。 両方$n$そして$m$は最大 20 であるため、ノードの合計数は最大 40 になります。これは、片側または両側での指数関数的な列挙を伴うソリューションは潜在的に許容できるが、40 個のノードすべてで同時に指数関数的なものは許容できないことをすぐに示唆しています。 クエリの数は次のように大きくなります。$10^5$したがって、クエリごとの処理は不可能です。 すべての答えは事前に計算する必要があります。 

微妙な点は、カウントされる構造が任意のサブセットではなく、一致する頂点セットを形成するサブセットであることです。 これにより、グローバル制約が導入されます。ノードは独立して選択できず、エッジ全体で一貫してペアにする必要があります。 

簡単な間違いは、問題が単純に「XOR x でサブセットを数える」ことだと考えることです。そうすると、マッチング制約が完全に無視され、$2^{40}$可能性。 もう 1 つの間違いは、左側と右側を独立して扱うことです。 マッチング制約により、それらが強く結合されます。 

失敗例を簡単に図解すると、これが明確になります。 一致制約を無視し、すべてのサブセットをカウントするとします。 この場合、エッジのないグラフでもすべてのサブセットが許可されますが、これは正しくありません。エッジでカバーできるノードがないため、空のセットのみが有効になるはずです。 グローバルなペアリングの一貫性を確保せずに次数制約をローカルでのみ適用すると、別の失敗が発生します。これにより、異なる部分構造でノードが「2 回使用される」構成が過大にカウントされます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブセットが列挙されます。$n+m$ノードを分割し、互いに素なエッジに分割できるかどうかを確認します。 各サブセットについて、それらのノードを正確にカバーする完全な一致が認められるかどうかを検証しようとします。 サブセットごとの 2 部一致チェックには少なくともコストがかかります$O(E \sqrt V)$または同様のもの、および$2^{40}$サブセットではこれは完全に不可能です。 有効なサブセットに限定したとしても、密な 2 部グラフ内の一致の数は依然として指数関数的です。 

重要な観察は、有効なサブセットが任意ではないということです。 それらはまさに一致する頂点セットです。 サブセットの観点から考える代わりに、直接のマッチングの観点から考えるように切り替えます。 すべての有効なサブセットは一致に一意に対応し、すべての一致は正確に 1 つのサブセット (そのエンドポイント) を誘導します。 これにより曖昧さがなくなり、構造的に一貫性のないサブセットをカウントすることが回避されます。 

したがって、問題は次のようになります。2 部グラフ内のすべての一致を列挙し、各一致のすべてのエンドポイントの XOR を計算し、XOR 値の頻度をカウントします。 課題は、一致を明示的に列挙せずにこれを効率的に行うことです。 

なぜなら$n,m \le 20$、二部構造の非対称性を利用します。 一致を左ノードからの割り当てとして扱います。各左ノードは一致しないか、隣接する 1 つの右ノードと一致するかのいずれかです。 これは自然に左側のビットマスク DP につながり、そこでどの右側のノードがすでに使用されているかを追跡します。 

これは、$2^m$右側で使用するための状態空間ですが、管理しやすいままです。$m \le 20$、 それで$2^m \approx 10^6$。 状態の一部として XOR 蓄積も行いますが、巨大な 3D テーブルを保存する代わりに、スパース表現と増分更新を使用して遷移を圧縮します。 

主なアイデアは、左側のノードを順番に動的プログラミングすることです。 各ステップで、ノードを一致しないままにするか、まだ使用されていない隣接ノードの 1 つとペアにします。 これにより、左の各ノードが一意の構造決定を行うため、すべての有効な一致が正確に 1 回カウントされることが保証されます。 

したがって、DP 状態は、どの右側のノードが占有されているか、およびこれまでにどのような XOR が蓄積されているかによって決まります。 状態空間は大きいですが、遷移は隣接リストによって制御され、各状態は有効なエッジを介してのみ拡張されます。 

これが機能する理由は、一般性を失うことなく、二部マッチングを片側から貪欲に構築できるためです。すべてのマッチングは、左のノードごとに昇順に行われた選択として一意の表現を持ちます。

 ## アルゴリズムのチュートリアル

 ### 1. 隣接関係リストの前処理

 二部グラフを左の各ノードから右のノードへの隣接リストに変換します。 これにより、DP 遷移中に可能な一致パートナーに対して一定時間の反復が可能になります。 

### 2. DP 状態を定義する

 右側のノードのサブセットに対して DP テーブルを定義します。 各右マスクについて、その構成につながる一致の数を表す XOR 値の頻度マップを保存します。 これにより、どの正しいノードがすでに一致しているかを正確にキャプチャします。 

### 3. 基本状態を初期化する

 空のマッチングから始めます。正しいノードは使用されず、XOR はゼロであるため、初期状態は一方向に寄与します。 

### 4. 左側のノードを順番に処理します

 左側のノードごとに、2 つの可能性を考慮して DP を更新します。ノードがマッチングに使用されていないか、マスクで現在使用されていない利用可能な右側の隣接ノードの 1 つとマッチングされているかのいずれかです。 各遷移はマスクと XOR の両方を更新します。 

このステップは、すべての正しいノードが最大 1 回使用されることを強制するため、中核となる正確性メカニズムです。 

### 5. 結果を集計する

 左側のすべてのノードを処理した後、すべての DP 状態は完全一致に対応します。 各状態について、その XOR カウントを XOR 値でインデックス付けされたグローバル頻度配列に累積します。 

### 6. 質問に答える

 前処理が完了すると、指定された XOR に対して事前計算された頻度を読み取ることによって、各クエリが一定時間内に応答されます。 

### なぜ効果があるのか

 すべての有効なマッチングは、左側のノードごとに順番に行われる決定に一意に分解できます。 各右側のノードは 1 回だけ使用されるとマークされるため、無効な重複は発生しません。 DP は、一貫した部分一致をすべて 1 回だけ調査し、すべての完全な状態が有効な一致に対応します。 したがって、XOR 値の度数表は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m, e = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    adj = [[] for _ in range(n)]
    for _ in range(e):
        u, v = map(int, input().split())
        adj[u - 1].append(v - 1)
    
    # dp[maskB][xor] is number of ways
    # maskB up to 2^m, xor up to 2^18
    max_mask = 1 << m
    MAXX = 1 << 18
    
    dp = [dict() for _ in range(max_mask)]
    dp[0][0] = 1
    
    for i in range(n):
        ndp = [dict() for _ in range(max_mask)]
        
        for mask in range(max_mask):
            if not dp[mask]:
                continue
            for xr, cnt in dp[mask].items():
                
                # option 1: skip i
                ndp[mask].setdefault(xr, 0)
                ndp[mask][xr] = (ndp[mask][xr] + cnt) % MOD
                
                # option 2: match i with a neighbor
                for j in adj[i]:
                    if not (mask & (1 << j)):
                        nmask = mask | (1 << j)
                        nxr = xr ^ a[i] ^ b[j]
                        ndp[nmask].setdefault(nxr, 0)
                        ndp[nmask][nxr] = (ndp[nmask][nxr] + cnt) % MOD
        
        dp = ndp
    
    ans = [0] * (1 << 18)
    
    for mask in range(max_mask):
        for xr, cnt in dp[mask].items():
            ans[xr] = (ans[xr] + cnt) % MOD
    
    q = int(input())
    out = []
    for _ in range(q):
        x = int(input())
        out.append(str(ans[x]))
    
    print("\n".join(out))

if __name__ == "__main__":
    main()
```DP は、左側の各ノードが未使用のままになるか、1 回だけペアになるように編成されます。 正しいノードに対するビットマスクにより、正しいノードが複数回使用されないことが保証されます。 XOR は、エッジが選択されるとすぐに更新され、両方のエンドポイントの値が結合されます。 

実装の微妙な詳細は、辞書を使用して DP 状態をまばらに保存することです。 これにより、完全な割り当てを回避できます。$2^{18}$マスクごとの XOR 配列。これは大きすぎます。 代わりに、到達可能な XOR 状態のみを保持します。

 ### 例 1

 左側に 1 つのノードと右側に 2 つのノードがあり、エッジが 1 つだけ存在し、ノード値が単純な小さなグラフを考えてみましょう。 

次のように DP を追跡します。 

| ステップ | マスクB | XOR 状態 | カウント |

 これは、単一の一致によって 1 つの有効なサブセットがどのように生成されるかを示しています。 

トレースにより、各 DP 遷移が一致するエッジの選択またはスキップに直接対応していることが確認されます。 

### 例 2

 2 つの左側のノードがそれぞれ異なる右側のノードに接続されているため、DP はノードごとに独立して進化します。 

| ステップ | マスクB | XOR 状態 | カウント |
 | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 1 |

 | A1以降 | 0、1、2、3 | XOR 和の組み合わせ | 拡張された |

 これは、独立した選択が干渉することなく DP を通じて自然に組み合わされることを示しています。

 ## 特殊なケース

 重要なエッジケースは、グラフにエッジがない場合です。 この状況では、ゼロより大きいサイズの一致は存在しないため、空のサブセットのみが寄与します。 遷移は不可能であるため、DP は初期状態のみを正しく保存します。 

もう 1 つのエッジ ケースは、ノードに複数の隣接ノードがある場合です。 DP は、マスク内の使用法をエンコードすることで、正しい各ノードが最大 1 回使用されるようにするため、複数の選択肢が存在する場合でも、それらは誤ってマージされるのではなく、異なる状態できれいに分離されます。 

最後に、XOR 値が異なるマッチング間で衝突する場合、集計ステップは寄与を同じバケットに正しく合計し、クエリがすべての構造的可能性を確実に反映するようにします。
