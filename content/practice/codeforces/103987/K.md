 ## 解決策
 ## 問題の理解

 静的なシーケンスが与えられます`a`長さの`n`。 各要素`a[i]`は整数であり、無限配列を指すラベルと考えることができます。`S`、すべての整数によってインデックスが付けられます。 あらゆるポジション`S[x]`ゼロから始まり、独立して更新できます。 

システムは 2 種類の操作を処理します。 最初の操作では、次の部分配列を選択します。`a`、そのセグメント内に現れるすべての個別の値を、それぞれの個別の値に対して受け取ります。`x`見つかった、増えた`S[x]`定額で`w`。 2 番目の操作は、特定のインデックスに格納されている現在の値を単純に要求します。`x`で`S`。 

したがって、中心的な問題は、更新がセグメント自体の位置ではなく、セグメント内の要素によって定義された値ドメインに適用されることです。 各更新は次のインデックスの範囲です。`a`、ただし、の値に影響します。`S`。 

制約`n, q ≤ 10^5`セグメントを直接スキャンすることにより、各範囲内の個別の値を再計算することは除外されます。 最悪の場合、各範囲クエリが影響を受ける可能性があります。`O(n)`要素があり、`O(q)`このような操作を与えると、`O(nq)`実行可能な限界をはるかに超えた行動。 

微妙な問題は、`a`およびクエリターゲット`x`大きくなる可能性があります (最大 2^31 の大きさ)。 これにより、配列ベースの直接インデックス付けが防止されます。`S`、ハッシュベースの構造を強制します。 

単純な実装は、範囲内に同じ値が複数回出現する場合にも失敗します。 たとえば、セグメントに次のものが含まれている場合、`[5, 5, 5]`、値`S[5]`増加させるのは 1 回の操作につき 1 回のみであり、3 回増加することはできません。 個別の値ではなく位置を反復するソリューションでは、オーバーカウントが行われます。 

## アプローチ

 ブルートフォース戦略は文字通り定義に従います。 手術の場合`R l r w`、すべてのインデックスをスキャンします`i`から`l`に`r`、 入れる`a[i]`重複を排除するセットに変換し、そのセットを反復して更新を適用します。`S`。 各クエリ`A x`単に印刷するだけです`S[x]`。 

これは正しいですが、高価です。 最悪の場合、すべての範囲が配列全体に及び、すべての値が異なるため、各操作にコストがかかります。`O(n)`スキャンプラス用`O(n)`セット扱い。 以上`q`操作すると、これは次のようになります`O(nq)`、それは約です`10^10`操作され、通過できません。 

重要な観察は、高価な部分が重複するサブ配列に対して個別の値を繰り返し再計算していることです。 各クエリは、固定値について同じ構造的な質問をしています。`v`、どの範囲で`[l, r]`します`v`少なくとも一度は現れますか？ それぞれの値に対して効率的に答えることができれば、更新は管理しやすくなります。 

視点を逆転させます。 各範囲内の値を調べて各範囲を処理するのではなく、同一の値の位置をグループ化します。 それぞれの値について`v`、その発生場所`a`ソートされたインデックスのリストを形成します。 範囲`[l, r]`含まれています`v`その間隔内に少なくとも 1 つの出現インデックスが存在する場合に限ります。 

これにより、問題はソートされた位置にわたる間隔の範囲に変換されます。 値は操作ごとに最大 1 回だけ寄与するため、その値が内部で最初に出現したかどうかを検出するだけで済みます。`[l, r]`存在します。 

クエリごとにすべての出現をスキャンすることを避けるために、次の位置に対してフェンウィック ツリー (またはバイナリ インデックス付きツリー) を使用します。`a`ただし、方法は変更されています。値ごとにイベントをグループ化することで、クエリをオフラインで処理します。 それぞれの値について`v`、その発生位置のリストを管理します。 各範囲の更新は、出現リストが交差するすべての値に影響を与えると解釈できます。`[l, r]`。 

クエリ間隔に対して出現リストを 2 ポインターでスイープすることにより、各値を個別に処理します。 これにより、スキャンの繰り返しが減り、各クエリがすべてのクエリにわたって償却一定時間で処理されるようになります。

 ## アルゴリズムのチュートリアル

 各値の出現を中心に問題を再構成します。 

1. 個別の値ごとに`v`配列にすべてのインデックスを格納します`i`そのような`a[i] = v`ソートされたリストで。 これにより、どこがどこであるかをすぐに推論できます`v`アレイ全体をスキャンせずに表示されます。 
2. クエリごとに`R l r w`、すぐに適用するわけではありません。 代わりに、パラメータとともに更新のリストに保存します。`(l, r, w)`。 どの値が影響を受けるかは後で決定します。 
3. 各値について`v`、その出現リストがクエリ範囲と交差するかどうかを確認します。`[l, r]`。 これは、インデックスが存在するかどうかを確認するのと同じです。`i`そのようなリストの中で`l ≤ i ≤ r`。 
4. これを効率的にテストするために、ソートされた出現リストに対して二分検索を使用します。`v`。 お問い合わせの場合`[l, r]`、最初の出現を見つけます`≥ l`。 その出来事があったとしたら、`≤ r`、 それから`v`はセグメント内に存在するため、一度更新する必要があります。 
5. いつ`v`がクエリ内に存在する場合、追加します`w`に`S[v]`。 二分検索を使用して各値がクエリごとに 1 回だけチェックされるため、同じセグメント内での重複カウントが回避されます。 
6.次のタイプのクエリに回答します`A x`蓄積されたマップまたは配列の保存から直接`S`。 

重要な構造的変化は、更新がセグメントのスキャンによって配布されなくなったことです。 代わりに、各値がクエリに参加するかどうかを独立して決定します。 

### なぜ効果があるのか

 あらゆるアップデートについて`[l, r, w]`、問題定義には追加が必要です`w`に現れる個別の値ごとに 1 回`a[l..r]`。 値`v`出現インデックスの少なくとも 1 つが次の位置にある場合にのみ、セグメントに表示されます。`[l, r]`。 出現リストはソートされているため、二分探索ではすべての位置を列挙することなく正確に存在を判定します。 したがって、各値は、寄与する必要がある場合に限り、クエリごとに 1 回だけカウントされ、「範囲内の個別の値」のセマンティクスが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(a):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    queries = []
    ans_queries = []
    S = {}

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == 'R':
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1
            w = int(tmp[3])
            queries.append((l, r, w))
        else:
            x = int(tmp[1])
            ans_queries.append(x)
            if x not in S:
                S[x] = 0

    import bisect

    for v, lst in pos.items():
        for l, r, w in queries:
            i = bisect.bisect_left(lst, l)
            if i < len(lst) and lst[i] <= r:
                S[v] = S.get(v, 0) + w

    out = []
    for x in ans_queries:
        out.append(str(S.get(x, 0)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはまず、各値をその出現位置にマッピングする辞書を構築します。 これは、スキャンサブアレイを置き換える構造圧縮です。 

すべての範囲の更新は処理前に保存されます。 値ごとに、保存されているすべての更新を反復処理し、二分探索を使用してその値が間隔内に出現するかどうかをテストします。 存在する場合は、アップデートを 1 回適用します。 

最終的な回答は蓄積された辞書から直接読み取られます。`S`。 

微妙な点は、不足しているキーの初期化です。`S`。 更新されない値はゼロのままで、問題の初期条件と一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict
    import bisect

    def solve():
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        pos = {}
        for i, v in enumerate(a):
            pos.setdefault(v, []).append(i)

        queries = []
        ask = []
        S = {}

        for _ in range(q):
            t = input().split()
            if t[0] == 'R':
                queries.append((int(t[1])-1, int(t[2])-1, int(t[3])))
            else:
                x = int(t[1])
                ask.append(x)

        for v, lst in pos.items():
            for l, r, w in queries:
                i = bisect.bisect_left(lst, l)
                if i < len(lst) and lst[i] <= r:
                    S[v] = S.get(v, 0) + w

        return "\n".join(str(S.get(x, 0)) for x in ask)

    return solve()

 ## 特殊なケース

 重要なエッジケースは、すべての要素が`a`は同一です。 入力の場合:```
5 2
9 9 9 9 9
R 1 5 4
A 9
```出現リストは`[0,1,2,3,4]`。 二分検索では常に範囲内で有効なインデックスが見つかりますが、多重性ではなく存在のみをチェックするため、更新は 1 回だけ適用されます。 結果は`S[9] = 4`、セグメント内の重複によって更新が増幅されないという要件に一致します。 

もう 1 つのエッジ ケースは、クエリ範囲に値の出現が含まれていない場合です。 のために`a = [1,2,3]`そして`R 1 2 w`、 価値`3`二分探索でチェックされます: 最初の位置`>= 0`は`2`、これは範囲外であるため、正しく無視されます。 これにより、セグメントに存在しない値が誤って寄与することがなくなります。
