 ## 問題の理解

 各タスクには開始インデックスが与えられます$i$、そして必要な計算は常に同じです: を中心とする 3 つの連続する整数を合計します。$i$、 具体的には$(i-1) + i + (i+1)$。 代数的にこれを単純化すると、$3i$したがって、すべてのタスクは事実上、3 の倍数を計算することを求めています。 

ただし、この制限は算術の正確さに関するものではなく、10 進加算の動作に関するものです。 Sinoey は、コンピューティングが必要なタスクの実行を拒否します。$3i$基数 10 で加算する場合、任意の桁位置でキャリーが必要になります。桁上げは、列方向の加算中に、一部の桁の合計が 10 以上に達し、次の上位桁への桁上げが強制されるときに発生します。 

したがって、問題は純粋に数字に関するものになります。つまり、整数がいくつあるかということになります。$i$範囲内で$1$に$n$3 を掛けると、標準的な 3 の掛け算で桁上げを行わずに形成できる数値が生成されます。 

制約$n \le 10^{18}$直接の反復を除外します。 それぞれの数字を個別に確認することさえ不可能です。 解決策は、桁構造と 10 進数表現に関するカウント引数のみに依存する必要があります。 

微妙な問題は、「桁上げなし」が桁間の相互作用に依存することです。$i$と 3 を掛けます。$3i$グローバルでは小さいですが、4 以上のような数字が原因でローカルでキャリーが発生する可能性があります。$i$、 以来$3 \cdot 4 = 12$。 

重要な隠されたエッジのケースは、キャリーが伝播することです。 たとえば、ある数字が次の位置へのキャリーを生成する場合、その直積が小さい場合でも、その次の位置もオーバーフローする可能性があります。 キャリー伝播を追跡しない単純な桁ごとのチェックは失敗します。

 ## アルゴリズムのチュートリアル

 に数字が何個あるか数えます$[0, n]$3倍してもキャリーは発生しません。 

1.変換$n$10 進数の配列に変換すると、最上位桁から最下位桁まで処理できるようになります。 これにより、上限制約を桁ごとに適用できるようになります。 
2. 動的プログラミング関数を定義する$dp(pos, tight, carry)$、 どこ$pos$現在の数字のインデックス、$tight$プレフィックスがまだ等しいかどうかを示します$n$、 そして$carry$前の桁の乗算によってこの位置へのキャリーが生成されたかどうかを示します。 
3. 各位置で、可能なすべての数字を試します$d$0 から 9 までですが、次の値に制限します。$d \le n[pos]$私たちが逼迫した状態にある場合。 これにより、決して超過しないことが保証されます$n$。 
4. 選択した各桁について$d$、この桁で 3 による乗算をシミュレートします。$val = 3d + carry$。 もし$val \ge 10$の場合、この遷移はキャリーを生成し、制約に違反するため無効です。 それ以外の場合、キャリーの伝播は必要ないため、次のキャリーは 0 になります。 
5. 更新された状態で次の桁に戻ります。 すべての有効な遷移を合計します。 
6. 数値 0 を含めた場合、最後に 1 を引きますが、問題は 1 から数えるだけです。 

重要なのは、キャリーの存在を決して許可しないことです。 したがって、DP は事実上、すべての数字がセット内にある数字シーケンスのみを受け入れます。$\{0,1,2,3\}$、 なぜなら$3 \cdot d \le 9$保持しなければなりません。 

### なぜ効果があるのか

 このアルゴリズムは、状態の伝播を通じてグローバルな正確性を維持しながら、各桁でローカルに乗算制約を適用します。 無効な数値は最初の桁で失敗する必要があります。$3d + carry \ge 10$、DP は厳しい制約の下ですべてのプレフィックスを探索するため、有効な数値はすべて 1 回だけカウントされます。 キャリーがないことで桁間の独立性が保証されるため、DP 状態は必要なすべての履歴を完全にキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = input().strip()
    digits = list(map(int, n))

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, carry):
        if pos == len(digits):
            return 1 if carry == 0 else 0

        limit = digits[pos] if tight else 9
        res = 0

        for d in range(limit + 1):
            if 3 * d + carry >= 10:
                continue
            nd = 0
            ntight = tight and (d == limit)
            res += dp(pos + 1, ntight, nd)

        return res

    ans = dp(0, 1, 0)
    print(ans - 1)

if __name__ == "__main__":
    solve()
```このコードは、次の 10 進数表現に対して標準的な数字 DP を実行します。$n$。 状態は、位置、プレフィックス制限、およびキャリー ステータスをエンコードします。 この遷移では、3 を乗算したときに桁上げが発生するすべての桁が明示的に拒否されます。最後の減算では、カウントから空の数値が削除されます。 

微妙な点は、次の状態ではキャリーがゼロになることだけを許可するということです。 これは正しいです。キャリーを生成する遷移は無効であり、すぐにプルーニングされるからです。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n$3 より大きい数字が含まれています。たとえば、$n = 49$。 このアルゴリズムは、4 ～ 9 の数字を含む数値を正しく拒否します。$3 \cdot d \ge 12$すぐにその桁でキャリーが発生します。 

もう 1 つのエッジケースは次のような場合です$n$それ自体は構造的には有効ですが、厳しい制約によって除外されます。 例えば、$n = 30$。 数値 30 は桁数 (3 と 0) としては有効ですが、31 ～ 39 などの多くの中間数値は桁制限により自動的に無効になり、DP によってそれらはカウントされないことが保証されます。 

最後のエッジケースは、$n = 0$ここで、DP は空の数を数えます。 最後の減算により、この人為的なケースが除外され、有効な正の整数のみがカウントされることが保証されます。
