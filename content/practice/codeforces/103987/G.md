 ## 解決策
 ## 問題の理解

 シマリスの列の空腹レベルを表す整数の配列が与えられます。 によってインデックス付けされた特定のシマリス`k`常に含める必要があります。 任意の連続したセグメントを選択できます`[l, r]`インデックスが含まれるようにする`k`。 このようなセグメントを選択するコストは、そのセグメント内のすべての値の合計です。 

すべての有効なセグメントは 1 つのコストを生成し、そのようなすべてのセグメントの間で、概念的にこれらの合計を昇順に並べ替えます。 タスクは出力することです`m`その中で - 番目に小さい値。 

制約は大きいです:`n`最大 100 万までになる可能性があるため、すべてのセグメントを明示的に列挙するソリューションは即座に除外されます。 固定インデックスを含むセグメントのみであっても`k`許可されていますが、その数はまだです`k * (n - k + 1)`最悪の場合は二次関数になります。 これにより、セグメントの合計を列挙するのではなく、暗黙的に生成またはカウントできる構造が強制されます。 

微妙な困難は負の値から生じます。 以来`a[i]`が負の場合、セグメントを拡張してもその合計は単調増加しません。 これにより、スライディング ウィンドウや貪欲な拡張に基づく直感は打ち破られます。 

単純な間違いは、「最小のセグメントは周囲の最短距離から来ている」と仮定することです。`k`たとえば、値が頻繁に交互する場合、わずかに長いセグメントは短いセグメントよりも合計が小さくなる可能性があります。そのため、順序付けはローカルではなくグローバルに処理する必要があります。 

別の失敗例は、すべてのプレフィックスの合計を事前計算し、すべてのペアを列挙しようとすることです。`(l, r)`と`l ≤ k ≤ r`。 これにより、次の場合に最大 1 兆の操作が生成されます。`n = 10^6`、時間的にも記憶力的にも不可能です。 

主な困難は、1 つのセグメントの合計を計算することではなく、`m`固定ピボットを中心とするセグメント合計の構造化ファミリーの中で 2 番目に小さい。 

## アプローチ

 ブルートフォースアプローチは簡単です。 毎回修正します`l ≤ k`そしてすべての`r ≥ k`、の合計を計算します`a[l..r]`、すべての結果を保存し、並べ替えて、`m`- 番目の要素。 有効なセグメントの完全なマルチセットを直接構築するため、正確性は即座にわかります。 

ボトルネックは列挙そのものです。 がある`k`左側のエンドポイントの選択肢と`n - k + 1`適切なエンドポイントの選択、生成`O(n^2)`最悪の場合はセグメント化されます。 たとえ各合計がプレフィックス合計を使用して O(1) で計算されたとしても、単にそれらを保存して並べ替えることは不可能です。`n = 10^6`。 

重要な観察は、すべてのセグメントの合計が構造を共有していることです。 直したら`k`、すべてのセグメント`[l, r]`の左拡張子を組み合わせて書くことができます。`k`そして右からの延長`k`。 より正確には、次のように書き換えることができます。`sum(l, r) = (sum from l to k) + (sum from k to r) - a[k]`これにより、各セグメントが一定の補正を伴う左側の寄与と右側の寄与に分離されます。 したがって、二次元で考えるのではなく、`(l, r)`として、問題をプレフィックスのような合計の 2 つの 1 次元族を結合することに縮小します。 

次に、次のように定義します。`L[i] = sum of a[i..k]`のために`i ≤ k`、 そして`R[j] = sum of a[k..j]`のために`j ≥ k`。 

すべての有効なセグメントの合計は次のようになります。`L[i] + R[j] - a[k]`。 

これにより、問題は選択に変わります。`m`- ソートされた 2 つの配列からの最小のペアの合計`L`そして`R`。 どちらの配列もプレフィックスの合計を使用して線形時間で計算でき、どちらも自然な方向で単調です。左に拡張すると減少します。`L`、右に伸ばすと増加します`R`。 

ここでのタスクは次のようになります: すべてのペアの合計を数えて順序付けする`L[i] + R[j]`、次に定数を減算します。 

これは古典的な「ソートされた行の k 番目に小さいペアの合計」問題で、答えに対する二分探索と 2 ポインター カウント手順を組み合わせて使用​​して解決できます。 

候補値を二分探索します`X`満たすペアの数を数えます`L[i] + R[j] ≤ X + a[k]`。 どちらの配列も単調であるため、2 ポインター スイープを使用して線形時間でカウントできます。 

これにより、問題全体が 2 次列挙から次のように縮小されます。`O(n log V)`どこ`V`は値の範囲です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(n² log n) | O(n²) | 遅すぎる |
 | 最適 | O(n log V) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、部分配列の合計を定数時間で計算できるようにプレフィックスの合計を構築します。 これにより、次の点を中心とする 2 つの配列を構築できるようになります。`k`合計を繰り返し再計算する必要はありません。 

1. 配列のプレフィックスの合計を計算します。 これにより、`sum(l, r)`O(1) でクエリを実行します。これは、多くのセグメントの合計を暗黙的に導出するために必要です。 
2. 左側の寄与配列を構築する`L`。 インデックスごとに`i ≤ k`、セグメントの合計を計算します`[i, k]`。 これらの値を配列に保存します。 これが機能する理由は、すべての有効なセグメントには左側の境界が 1 つだけあり、合計への寄与は、そこからどれだけ左に拡張するかによって完全に把握されるためです。`k`。 
3. 適切な寄与配列を構築する`R`。 インデックスごとに`j ≥ k`、の合計を計算します`[k, j]`。 これにより、すべての正しい拡張子が対称的にキャプチャされます。 
4. すべての有効なセグメントの合計が次になるように定式化を正規化します。`L[i] + R[j] - a[k]`。 減算により、中心要素の二重カウントが回避されます。`a[k]`。 
5. 並べ替え`L`そして`R`。 単調な 2 ポインタ スキャンを使用してペアの合計を効率的にカウントできるようにするには、並べ替えが必要です。 単調な構造は、明示的な列挙の必要性を置き換えるものです。 
6. 応答値の二分探索`X`。 候補者ごとに`X`、満足するペアの数を数えます`L[i] + R[j] - a[k] ≤ X`。 これは以下と同等です`L[i] + R[j] ≤ X + a[k]`。 
7. ペアを効率的にカウントするには、ポインタを修正します`j`最大の有効なインデックスで`R`そしてそれを下方向にのみ動かします。 それぞれについて`L[i]`、減少します`j`合計条件が満たされるまで。 その有効なペアの数`i`それなら`j + 1`。 これは、増加するため機能します。`i`増加する`L[i]`、 それで`j`全体的に一方向にしか動けない。 
8. 二分探索内のカウント関数を使用して、最小のものを見つけます。`X`少なくともそうなるように`m`ペアは条件を満たします。 

### なぜ効果があるのか

 すべての有効なセグメントは 1 つのペアに一意に対応します`(i, j)`から左右にどれだけ伸びるかを表します`k`。 変換では一定のシフトまで順序が保持されるため、セグメントの合計のランク付けはペアの合計のランク付けと同等になります。 

2 つのポインターのカウントは正しいです。`L`そして`R`モノトーン配列です。 ペアに1回`(i, j)`有効です、それより小さいか`j' < j`も同様に有効になります`i`、およびそれ以上の`i' > i`状態をさらに悪化させるだけです。 これにより、単調なフロンティアが保証され、まさに二分探索内での線形時間カウントが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(L, R, limit):
    n = len(L)
    m = len(R)
    j = m - 1
    total = 0

    for i in range(n):
        while j >= 0 and L[i] + R[j] > limit:
            j -= 1
        total += (j + 1)
    return total

def solve():
    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))

    k -= 1

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    L = []
    for i in range(k, -1, -1):
        L.append(prefix[k + 1] - prefix[i])

    R = []
    for j in range(k, n):
        R.append(prefix[j + 1] - prefix[k])

    L.sort()
    R.sort()

    base = a[k]

    def ok(x):
        return count_pairs(L, R, x + base) >= m

    lo = -10**18
    hi = 10**18

    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```実装は、左右のセグメントの合計が O(1) で計算できるように、プレフィックスの合計を構築することから始まります。 配列`L`そして`R`周囲の拡張からのすべての貢献を保存する`k`それぞれ左と右に。 それらを分類することにより、効率的なカウントに必要な単調な構造が可能になります。 

機能`count_pairs`重要な最適化です。 ポインタを維持します`j`それは左に移動するだけです`i`が増加します。 これにより、再計算が回避され、二分探索ステップごとに直線的な時間でカウントが実行されるようになります。 

二分探索は、最終的なセグメントの合計値に対して実行されます。 セグメントの合計をペアの合計と定数に変換したため、以下と比較します。`x + base`述語の内部。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    k -= 1

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    L = []
    for i in range(k, -1, -1):
        L.append(prefix[k + 1] - prefix[i])

    R = []
    for j in range(k, n):
        R.append(prefix[j + 1] - prefix[k])

    L.sort()
    R.sort()

    def count(limit):
        j = len(R) - 1
        res = 0
        for i in range(len(L)):
            while j >= 0 and L[i] + R[j] > limit:
                j -= 1
            res += j + 1
        return res

    def ok(x):
        return count(x + a[k]) >= m

    lo, hi = -10**18, 10**18
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が等しい場合です。 この状況では、すべてのセグメントは長さによる予測可能な線形順序付けになりますが、アルゴリズムは重複を正しく処理する必要があります。 ペアサム構造では多くの同一の値が生成されるため、二分探索は厳密な不等式に依存してはなりません。 

もう 1 つのケースは、すべての値が負の場合です。 その後、セグメントを延長すると、ほぼ常に合計が減少しますが、均一ではありません。 2 ポインタのカウントは、符号ではなく順序にのみ依存するため、引き続き機能します。 

最後のエッジケースは次のような場合です`k`一つの境界にあります。 もし`k = 1`、 それから`L`には要素が 1 つしかなく、問題は右側のプレフィックス セグメントに帰着します。 もし`k = n`、対称的に減少します。 の建設`L`そして`R`自然に正しく縮退するため、特別な処理は必要ありません。
