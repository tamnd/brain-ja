 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは石の山のコレクションを記述し、2 人のプレーヤーがアリスから開始して交互にゲームをプレイします。 

アリスの番では、彼女は 1 つの山を選択し、そこから正の数の石を取り除きます。 その手でアリスが取り除いた量が、ゲーム全体でアリスが取り除いた石の累計となります。 

ボブのターンでも、彼は単一の山を選択しますが、彼の動きには制限があります。ボブが取り除く石の数は、最後の動きだけでなく、アリスがゲームでこれまでに取り除いた石の合計数以上でなければなりません。 これにより、ゲームが進むにつれてボブの合法的な動きがますます制限されていきます。 

プレイヤーが自分のターンに有効な動きを行えず、そのプレイヤーが負けた場合、ゲームは終了します。 アリスが最初に動くので、ボブが最終的に有効な動きを持たない位置に強制的に移動しようとします。 

入力サイズは、すべてのテスト ケースにわたって最大 2·10^5 のパイルを示唆しているため、どのような解もテスト ケースごとにほぼ線形または線形である必要があります。 動きをシミュレートしたり、ターンごとにパイルを繰り返し更新したりするものは、直ちに実行不可能です。なぜなら、ゲームは、最悪の場合の推論で最大 O (石の合計) 個の動きまで続く可能性があり、これは制限をはるかに超えているためです。 

ボブの制約がどのように進化するかに、微妙なエッジケースがすぐに現れます。 アリスが最初に大量の除去を行った場合、ボブはまったく応答できない可能性があります。 たとえば、最大の山が、アリスが 1 回の動きで完全にそれを取得できる方法で組み合わせた他のすべてよりも厳密に大きい場合、ボブは最小要件を満たすのに十分な大きさの山を持たない可能性があります。 

2 番目の明白ではないエッジ ケースは、複数の大きな杭が存在する場合です。 そうすれば、ボブはいつでもアリスの最初の攻撃的な動きに反応できるようになり、ゲームがすぐに終了することはなくなり、両方のプレイヤーが繰り返し大きな山を消費する長い相互作用につながります。 

難しいのは、ゲームの残りの部分に対するボブの最小しきい値がアリスの最初の動きによって決定されるため、ゲーム構造全体がアリスの最初の動きによって支配されていることです。 

## アプローチ

 ブルートフォース手法では、ゲームを直接シミュレートします。 私たちはターンを繰り返し、アリスが取り除いた石の合計を追跡し、ボブの動きごとにすべての山をスキャンして、少なくともそのしきい値以上のサイズの有効な動きを見つけます。 これはルールに正確に従っているため、概念的には正しいです。 ただし、各移動には最大 O(n) 個の山をスキャンする必要があり、移動数は除去された石の合計に比例する可能性があります。 これにより、最悪の場合の複雑さが許容範囲をはるかに超えてしまいます。 

重要な観察は、ボブの制約が単一の値、つまりアリスがこれまでに削除した石の総数のみに依存しているということです。 この値は単調であり、アリスの最初の動きによって完全に制御されます。これは、アリスがそれ以上動いても値が増加するだけで、ボブが弱くなるだけであるためです。 

これは、最初の手がゲーム全体の構造を決定することを意味します。 アリスは常にボブへのプレッシャーを最大化するために最初の手を選択します。その最適な選択とは、山を選択し、そこからどれだけ取るかを決定することになります。 アリスの合計を増やすことはボブをさらに制限するだけであるため、部分的な除去は選択された山全体を単純に取ることによって支配されます。 

アリスがパイルを選択して完全に削除すると、ボブにはそのパイル サイズに等しい固定しきい値が残ります。 その瞬間から、ボブは少なくともその大きさの山でのみプレイすることができ、彼の各動きはそのような山を少なくともそのしきい値だけ減らします。 

これにより、ゲームは最大の山と残りの構造の間の比較に崩壊します。 最大の山が独自に優勢である場合、アリスは合法的な動きを行わずにボブを即座にその位置に強制することができます。 それ以外の場合、ボブはいつでも少なくとも最初の動きに答えることができ、ゲームは制御された方法で続行され、ボブが十分長く生き残って最終的にアリスのアドバンテージを使い果たすことになります。

 ## アルゴリズムのチュートリアル

 解決策は、最大と 2 番目に大きい杭のみを検査することになります。 

1. 配列内の最大パイル値を見つけます。 これは、アリスの最適な最初の動きを表します。これより小さな選択は彼女の立場を弱めるだけであるためです。 
2. この最大値に達する杭の数を数えます。 ボブの応答能力は、別の山がアリスのしきい値と一致するかどうかに依存するため、これは重要です。 
3. 最大値が 1 回だけ出現した場合、アリスは最初の動きで最大の山全体を取得できます。 この移動の後、他のパイルはボブの要件を満たすことができないため、ボブはすぐに負けます。 
4. 最大値が複数回出現する場合、ボブはいつでも別の最大値の山を選択することでアリスの最初の動きに応答できます。 これにより、オープニング以降もゲームが継続され、アリスが即座に勝利を強要することがなくなります。 
5. この場合、インタラクションは残りの大きな山で対称的な方法で継続し、ボブは常にアリスのプレッシャーを十分に長くミラーリングして、すぐに罠にかかるのを避けることができ、最適なプレイの下でボブの勝利につながります。 

### なぜ効果があるのか

 重要な不変条件は、ボブの制約がアリスの最初の動きによって完全に決定され、ボブの行動には決して依存しないということです。 これにより、ゲームは事実上、アリスの最初の選択からしきい値を選択するゲームになります。 しきい値が固定されると、ボブの移動能力は、各ラウンドの削減後に少なくとも 1 つのパイル ミーティングが存在するか、そのしきい値を超えるかどうかによってのみ決まります。 

最大値が一意である場合、アリスは自分の移動後には達成不可能なしきい値を選択し、ボブの正当な移動セットを即座に崩壊させることができます。 それが一意でない場合、しきい値はボブのターンの開始時に常に少なくとも 1 つの他の山によってサポートされ、すぐに崩壊するのを防ぎ、ボブが最適なプレイを通じて生存能力を維持できるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = max(a)
        cnt = 0
        for x in a:
            if x == mx:
                cnt += 1
        
        if cnt == 1:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    solve()
```実装は最大値を直接計算し、その発生回数をカウントします。 この推論は完全に初手の構造に基づいているため、シミュレーションは必要ありません。 唯一の微妙な点は、最大カウントがテスト ケースごとに O(n) 時間で正しく計算されるようにすることです。

 ## 特殊なケース

 重要なエッジケースは、すべての杭が同一である場合です。 この状況では、アリスに最初の優位性を与えるパイルは 1 つもありません。 アリスが 1 つの完全な山を取得した後、ボブは常に同じサイズの別の山を用意して応答するため、すぐに崩壊するのを防ぎます。 最大値は一意ではないため、アルゴリズムはこれをボブの勝利として正しく分類します。 

もう 1 つの特殊なケースは、山が 1 つしかない場合です。 アリスはそれを完全に削除し、ボブには法的な手段はありません。 最大値が 1 回だけ出現するため、アルゴリズムはアリスを正しく出力します。 

最後の微妙なケースは、配列が大きく歪んでいるが、上部が一意ではない場合です。 1 つの山が非常に大きく、他の山がはるかに小さい場合でも、その最大値が一意である限り、アリスは即座に勝ちます。 正しさは最大値の一意性のみに依存し、他の山の合計との関係には依存しません。
