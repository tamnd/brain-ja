 ## 解決策
 ## 問題の理解

 最終的な配列が与えられます`b`それは一連の結果から生じます`q`初期配列に対する操作`a`。 各操作で 2 つの位置が選択されます`x`そして`y`、現在の値の最小値を取得し、それを 3 番目の位置に割り当てます。`z`。 タスクは、有効な初期配列を再構築することです。`a`すべての操作を順番に適用すると、次のようになります。`b`。 そうでない場合`a`存在する場合は出力する必要があります`-1`。 

問題は微妙なので、`b`最終結果のみを提供します。 要素の場合`b_i`依存するものよりも小さいため、有効な値にバックトラックすることは不可能です`a`。 たとえば、次のように考えてみましょう`n=2`、`q=1`、操作`(2,1,2)`、 そして`b=[1,2]`。 操作後の 2 番目の要素は次のようになります。`min(a1, a2)`最大でもどれくらいでなければなりません`a1`。 以来`b2 > b1`、 いいえ`a`これを満たします。 

制約は大きい: まで`3*10^5`テスト ケースごとの要素と操作、最大`10^4`テストケース。 考えられるすべての初期配列を試したり、候補ごとにバックトラッキングをシミュレートしたりする単純なアプローチでは、あまりにも時間がかかりすぎます。 ほぼ線形のアルゴリズムが必要です`n + q`テストケースごとに。 

エッジケースには以下が含まれます:`x`、`y`、 または`z`一致する;`b`変更を必要とせずに、すでにすべての操作を満たしています。 最小の依存関係が観察された依存関係と矛盾するシーケンス`b`。 

## アプローチ

 ブルートフォースアプローチでは、すべての配列を生成しようとします。`a`すべての操作を適用すると、次の結果が得られるかどうかを確認します。`b`。 これは実行不可能です。`n=10`、可能な配列の数は天文学的です。 複数の選択肢があると矛盾が生じる可能性があるため、すべての操作を逆方向にシミュレートすることも危険です。 

重要な洞察は、各操作によって課される制約を観察することによって、プロセスを逆転させることです。 改造のため`c[z] = min(c[x], c[y])`譲る`b[z]`すべての操作の後、`b[z]`最大でもそうでなければなりません`b[x]`そして`b[y]`最終的な配列で。 これにより、_最小制約_を課すことができます`a[z]`に対して`b[z]`これらの制約を逆方向に伝播します。 以来、`min`操作では値を減少させることしかできず、可能な限り最大の値を減少させることしかできません。`a[i]`それは生み出すことができる`b[i]`まさに`b[i]`。 これを使用して、各要素を設定できます`a`すべての操作と互換性のある最大値に設定します。 何らかの操作が必要な場合`a[z]`より大きくなる`b[x]`または`b[y]`、それは不可能です、そして私たちは戻ります`-1`。 

これにより、問題は操作を単純にパススルーするだけで済みます。競合をチェックしてそれぞれを設定するだけです。`a[i]`許容される最大値まで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((最大値)^n * q) | O(n) | 遅すぎる |
 | 最適 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`q`、最終的な配列`b`、そしてすべて`q`オペレーション`(x, y, z)`。 
2.初期化`a`のコピーとして`b`。 これは、可能な最大値を表します。`a`と一致する`b`。 
3. 各操作ごとに`(x, y, z)`、どうかを確認してください`b[z]`どちらよりも大きい`b[x]`または`b[y]`。 もしそうであれば、操作では生成されなかったはずです`b[z]`どれからでも`a`ので、出力します`-1`。 
4. すべての操作に一貫性がある場合は、戻り値を返します。`a`有効な初期配列として。 の各要素`a`単純に`b[i]`なぜなら、各操作で最小値を取得しても、それを減らすか、変更しないままにすることしかできないからです。 

なぜ機能するのか: 重要な不変条件は、`min`この操作によって値が増加することはありません。 設定により`a[i] = b[i]`、ただし、いかなる操作も違反されないことを保証します。`b[z] <= b[x]`そして`b[z] <= b[y]`すべての変更に対して。 If any modification violates this, no initial array could satisfy it. This ensures correctness while avoiding unnecessary simulation of every possible`a`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        b = list(map(int, input().split()))
        ops = [tuple(map(lambda x: int(x)-1, input().split())) for _ in range(q)]

        possible = True
        for x, y, z in ops:
            if b[z] > b[x] or b[z] > b[y]:
                possible = False
                break
        
        if possible:
            print(" ".join(map(str, b)))
        else:
            print(-1)

solve()
```このコードでは、`ops`簡単にするために、ゼロインデックスの操作を保存します。 必要な条件のみをチェックします`b[z] <= b[x]`そして`b[z] <= b[y]`価値がないから`a`を超える可能性があります`b`最小操作に違反することなく。 使用する`b`として直接`a`初期配列を最大化し、有効な操作シーケンスが機能することを保証します。
