 ## 解決策
 ## 問題の理解

 モンスターのグループが与えられ、それぞれが整数の健康値で始まります。 固定ラウンド数にわたって、私たちは確率的兵器と対話し、時には全体的なアクションを実行し、時にはターゲットを絞ったアクションを可能にします。 私たちの目標は、すべてのラウンドの終わりまでにすべてのモンスターの体力を正確に 1 にすることです。 

各ラウンドのインタラクションはバイナリのランダム イベントによって異なります。剣は確率で「光る」か、$p$あるいはそうではありません。 重要な点は、行動するかどうかを決定する前にこの結果を観察し、その決定が完全に適応的であることです。 それが光っていて攻撃することを選択した場合、すべてのモンスターは1減ります。それが光っていなくて攻撃することを選択した場合、選択したモンスター1体だけを1減らすことができます。 

したがって、このプロセスは制御された確率システムであり、各ラウンドでグローバルな減少の機会または単一ターゲットの減少の機会が与えられ、すべての最終値が 1 に到達することを決定論的に保証しようとしています。 

制約の幅は狭いですが、深さは大きくなります。 モンスターの数は最大 20 です。これは、モンスターごとの状態を追跡したり、それらを集計したりできることをすぐに示唆しています。 ただし、ラウンド数は最大 4000 であるため、ラウンド内で指数関数的にスケールする状態空間は除外されます。 どの DP もラウンドごとに時間を短縮するか、貪欲な構造を使用する必要があります。 

主な問題点は、グローバルな操作はすべてのモンスターで共有されるのに対し、単一の操作はローカルであるため、意思決定が時間を超えて結合されることです。 

ソリューションがモンスター間で独立していることを前提としている場合、微妙な失敗例が発生します。 たとえば、各モンスターを個別に扱うことは、全体的な攻撃がすべての HP を同時に減少させるため、将来の実現可能性に影響を与えるという事実を無視します。 

もう 1 つの微妙な問題は、剣が輝かないときはいつでも、最悪のモンスターを貪欲に「修正」できると想定していることです。 グローバルヒットが蓄積して一部のモンスターがオーバーシュートしたり、複数のラウンドにわたる調整が必要になったりすると、これは失敗します。 

## アプローチ

 ブルートフォース戦略は、世界中で輝かしい結果のあらゆる可能なシーケンスをシミュレートします。$m$ラウンドします。 各ラウンドには 2 つの結果があるため、$2^m$考えられるグローバル パターン。 パターンごとに、最適なプレイを貪欲にシミュレートできます。剣が光るとき、有用であれば全体的な減少を適用します。そうでない場合は、まだ 1 を超えているモンスターに単一ターゲットの減少を割り当てます。パターンごとのシミュレーションが線形であっても、$n$、全体の複雑さは次のようになります。$O(2^m \cdot n)$、これは天文学的に大きい$m \le 4000$。 

重要な観察は、輝かしい出来事の固定された実現の中での意思決定の順序は、核心的な困難ではないということです。 むしろ重要なのは、グローバル削減に依存する前に単一ターゲット削減を何回使用できるか、そしてグローバル削減がモンスターごとの赤字とどのように相互作用するかです。 

問題を逆に再解釈することもできます。 それぞれのモンスターを想定すると、$i$まさに必要です$d_i = h_i - 1$合計の減少数。 全体攻撃はすべてのモンスターを同時に 1 減らすため、すべてのモンスターに 1 ユニット貢献します。$d_i$。 1 回の攻撃で 1 ユニットが正確に 1 つに貢献します$d_i$。 

ここでシステムは次のようになります: 配布する必要があります$m$ランダムな輝きイベントに応じて、グローバル使用ラウンドとシングル使用ラウンドにラウンドされ、すべてのモンスターが十分な合計デクリメント貢献を確実に受け取ることができます。 

重要な構造は、最適なポリシーが単調な意味で貪欲であるということです。世界的なヒットが利用可能で、少なくとも 1 つの未完成のモンスターにとってまだ有用である場合は、それを使用することが常に最適です。 それ以外の場合は、単一ターゲット操作を使用して残りの赤字を完了します。 

これにより、「有用な進歩を遂げるためにまだ必要なグローバル ヒット」の数と「まだ必要な単一ヒット」の数を追跡する状態に減らすことができます。 以来$n \le 20$、グローバル操作を調整した後、モンスター間の最大残り要件のみが重要であることを観察することで、システムを圧縮できます。 

これにより、効果的なグローバル削減が適用された回数と、すべてのモンスターを完了するためにまだ単一ターゲットの使用が必要な回数を追跡する、時間の経過に伴う DP が得られます。 移行は、ラウンドが輝いているかどうか、およびタスクがどれだけ残っているかによってのみ決まります。

 ## アルゴリズムのチュートリアル

 私たちは、グローバルな業務を考慮した上で必要な「作業」の合計という観点から問題を再定式化します。 

1. 各モンスターの要件を計算します$d_i = h_i - 1$。 これらは、各モンスターがまだ必要とするデクリメント数を表します。 
2. グローバル デクリメントと単一ターゲット デクリメントという 2 つのリソースを概念的に分離してみましょう。 グローバルな減少により、すべてが減少します$d_i$同時に、単一ターゲットの減少ではちょうど 1 つ減少します。$d_i$。 
3. 任意の固定数のグローバル デクリメントの場合$g$、各モンスターには実質的に残りの要件があります$\max(0, d_i - g)$。 これは、世界的なヒットがすべてのモンスターで「共有された進歩」であることを意味します。 
4. 可能なそれぞれについて$g$、必要な単一ターゲット操作の合計数を計算します。$$s(g) = \sum_{i=1}^n \max(0, d_i - g)$$申請後に必要な「追加修正」の回数です。$g$世界的なヒット作。 
5. 状態$(g, s)$であれば実現可能です$s(g) \le m - g$、各グローバルヒットはラウンドを消費し、残りのラウンドは単一ターゲットのアクションをカバーする必要があるためです。 
6. ここで、プロセスを確率的に解釈します。各ラウンドで、確率で$p$、グローバルに使用可能なアクションを取得します。 そうしないと、単一ターゲットの機会が得られてしまいます。 私たちは常に最適に行動するため、グローバルな機会はすべて、それがまだ有益であれば活用されます。 
7. キー DP は、その後の確率を追跡します。$t$ラウンドでは少なくとも達成しました$g$シングルに必要な残り時間を超過することなく、有用なグローバルヒットを獲得できます。 遷移は二項に似ていますが、実現可能性によって切り捨てられます。 
8. 有効なグローバルヒットの数が、範囲内のすべてのモンスターを減らすのに十分である確率を計算します。$m$ラウンド。これは、各有効なしきい値に到達する確率の合計になります。$g$。 

### なぜ効果があるのか

 このアルゴリズムは単調性の特性に依存しています。つまり、グローバル ヒット数が増加しても、必要な単一ターゲット操作の数は決して増加しません。 これにより、実現可能領域が確実に確保されます。$s(g) \le m-g$に凸です$g$。 その結果、最適な戦略はグローバル ヒットの数によって完全に特徴付けられ、すべての適応的な決定は、各グローバルな機会が進歩に寄与するか、それとも最適性を失わずにスキップされるかを選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p100 = map(int, input().split())
        h = list(map(int, input().split()))
        
        p = p100 / 100.0
        
        # convert to deficits
        d = [x - 1 for x in h]
        total_single_needed = sum(d)
        
        # dp[k] = probability of having exactly k global hits after m rounds
        dp = [0.0] * (m + 1)
        dp[0] = 1.0
        
        for _ in range(m):
            ndp = [0.0] * (m + 1)
            for g in range(m):
                if dp[g] == 0:
                    continue
                ndp[g + 1] += dp[g] * p
                ndp[g] += dp[g] * (1 - p)
            dp = ndp
        
        ans = 0.0
        
        for g in range(m + 1):
            # compute remaining single requirement after g globals
            need_single = 0
            for x in d:
                need_single += max(0, x - g)
            
            if need_single <= m - g:
                ans += dp[g]
        
        print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```このコードは、すべてのラウンドにわたってグローバル効果が発生する回数の分布を構築し、各ラウンドをグローバル イベントまたは単一イベントのいずれかに独立して寄与するものとして扱います。 DP 配列は、この二項分布を追跡します。 その後、可能性のあるグローバル ヒットのそれぞれの数が、モンスターごとの不足をすべて満たすのに十分な容量が残りのラウンドに残っているかどうかに対してチェックされます。 

実装の重要な詳細は、実現可能性の条件を正しく計算することです。 グローバルヒットごとにすべてのモンスターが同時に減少するため、単一ターゲットの合計要件が非線形的に減少します。`max(0, x - g)`構造。 最終的な合計により、残りの単一操作が残りのラウンドに適合する結果のみがカウントされることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのモンスターが既に HP 1 を持っている場合です。その状況では、すべての不足はゼロになるため、グローバル ヒットとシングル ヒットのすべての構成が自明に有効になります。 アルゴリズムはこれを処理します。`max(0, x - g)`は常にゼロなので、`need_single`ゼロであり、すべての DP 状態を受け入れます。 

別のエッジケースが発生するのは次の場合です。$p = 0$。 ここでは全体的なヒットは決して発生せず、すべての進歩は単一ターゲットのアクションによってもたらされる必要があります。 DP はすべての確率質量を正しく割り当てます。$g = 0$実現可能性は、必要な単一操作の合計が以下の範囲内に収まるかどうかを確認することに帰着します。$m$、これは意図したロジックと一致します。 

最後の微妙なケースは次のような場合です。$p = 1$。 すべてのラウンドはグローバルであるため、最大のモンスターのみが成功を決定します。 DPはすべての塊を崩壊させます$g = m$、そして実現可能性はもっぱらかどうかに依存します。$m$全体的な削減は、すべてのモンスターを 1 にするのに十分です。
