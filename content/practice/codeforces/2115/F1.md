 ## 問題の理解

 の配列を維持するように求められます`n`のシーケンスの下に設定されます`q`オンライン操作。各操作では、セットの一部のプレフィックスを変更するか、すべてのセットから特定の要素を削除し、特定のセット内の最小の要素を要求します。 各操作はエンコードされた形式で与えられるため、実際のインデックスと要素は前のクエリの答えに依存し、これがオンラインの問題になります。 操作は、プレフィックスへの要素の挿入、セットのプレフィックスの反転、またはすべてのセットからの特定の要素の削除です。 クエリは、指定されたセット内の最小要素を要求し、それが空の場合は 0 を返します。 

両方を考慮すると、`n`そして`q`まで可能です`10^5`、各セットを標準の Python セットとして保存し、操作を直接実行するという単純なアプローチでは遅すぎます。 たとえば、次のように挿入します。`r`セットを個別に実行すると、操作ごとに O(r) のコストがかかる可能性があり、最悪の場合は O(n*q) に達する可能性があり、実行可能な計算をはるかに超えます。 大きなプレフィックスに対する反転も、操作ごとに O(n) 時間がかかるのを避けるために慎重に処理する必要があります。 同様に、すべてのセットから特定の要素を単純に削除するには、すべてのセットのスキャンが必要になる可能性があり、これは法外な作業になります。 

微妙なエッジケースには次のようなものがあります。 まだ挿入されていない要素を削除の対象とする場合、操作は単にエラーなしで何も行わないはずです。 反転はセットの順序に影響しますが、各セット内の要素には影響しません。 挿入では操作インデックスが使用されます`i`セットのインデックスではなく、値として。 最後に、クエリ インデックスは前の答えに依存するため、モジュロ演算でオフバイ 1 エラーが発生しやすくなります。 

## アプローチ

 ブルートフォースの解決策は、文字通り問題をシミュレートすることです。`n`パイソン`set`オブジェクトの場合、最初のオブジェクトを反復して挿入を実装します。`r`セットを作成して要素を追加すること、セットの配列をスライスして反転することによって反転すること、および要素を削除するためにすべてのセットを反復することによって削除することです。 クエリは単に対応するセットの最小値を返すか、空の場合は 0 を返します。 この解決策は正しいですが、各演算が最大の時間に達する可能性があるため、最悪の場合の時間計算量は O(n*q) になります。`n`セット。 n と q が 10^5 までの場合、10^10 回の演算が行われますが、これは制限時間に対して大きすぎます。 

最適化における重要な洞察は、セット内の個々の要素を完全に明示的な方法で維持する必要がないということです。 すべての要素は、それが挿入された操作のインデックスです。 削除は特定の要素を対象とし、クエリはセット内の最小要素のみを要求するため、O(log k) の挿入、削除、および最小限の取得を可能にするセットごとのマルチセット構造を維持できます。 プレフィックスの反転の場合、すべてのセットを移動する代わりに、セグメント ツリーまたは遅延伝播手法を使用して論理ビューを維持できますが、この簡単なバージョンでは、慎重に実装すれば n*q が十分に小さいため、より単純な配列の反転が可能です。 

もう 1 つの最適化は、要素をそれらを含むセットにマップすることです。これにより、特定の要素の削除が必要なすべてのセットへの O(1) アクセスが可能になります。 すべての要素は一意であるため (各操作ではそのインデックスが要素として挿入されます)、この逆マッピングを使用して削除を効率的に行うことができます。

 ## アルゴリズムのチュートリアル

 1. の配列を初期化します。`n`セット。それぞれ最初は空です。 また、各要素を現在その要素が含まれているセットにマッピングする辞書も初期化します。 
2.セット`ans_0 = 0`最初のオペレーションのデコードを処理します。 
3. 各操作ごとに`i`1から`q`、前の回答を使用して操作パラメータをデコードします`ans_{i-1}`:

 - 操作が挿入の場合、計算します`r`そして値を挿入します`i`最初のそれぞれに`r`セット。 また、この要素が次のことをマッピングに記録します。`i`これらのセットに属します。 
- 操作が反転の場合、計算します`r`そして最初のものを逆にします`r`セット。 セット自体は変更されないため、マッピングを変更する必要はありません。 
- 操作が削除の場合、計算します`x`そしてマッピングを参照してください。 含まれる各セットについて`x`、 取り除く`x`そのセットから。 取り除く`x`繰り返しのスキャンを防ぐために、削除後にマッピングから除外します。 
4. クエリインデックスを計算する`p`そして、から最小の要素を取得します`p`- 番目のセット。 セットが空の場合は、0 を返します。答えを次のように保存します。`ans_i`次の操作をデコードするため。 
5. 印刷`ans_i`各クエリの直後に、オンライン要件を満たします。 

機能する理由: 要素からセットへのマッピングにより、削除では関連するセットのみが削除され、すべてのセットのスキャンが回避されます。 プレフィックスの反転は、配列スライスを物理的に反転することによって行われ、クエリの正しい順序が維持されます。 操作インデックスを挿入すると要素の一意性が維持され、削除ロジックが簡素化されます。 アップデートすることで`ans_i`各クエリの後、オンライン デコード式は正しいままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
sets = [set() for _ in range(n)]
element_to_sets = {}

ans_prev = 0

for i in range(1, q+1):
    a, b, c = map(int, input().split())

    if a == 1:
        r = (b + ans_prev - 1) % n + 1
        for idx in range(r):
            sets[idx].add(i)
            if i not in element_to_sets:
                element_to_sets[i] = []
            element_to_sets[i].append(idx)
    elif a == 2:
        r = (b + ans_prev - 1) % n + 1
        sets[:r] = sets[:r][::-1]
    elif a == 3:
        x = (b + ans_prev - 1) % q + 1
        if x in element_to_sets:
            for idx in element_to_sets[x]:
                sets[idx].discard(x)
            del element_to_sets[x]

    p = (c + ans_prev - 1) % n
    ans_prev = min(sets[p]) if sets[p] else 0
    print(ans_prev)
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`そしてセットの配列を明示的に維持します。 マッピング`element_to_sets`は挿入時にのみ更新され、削除時にのみ参照されるため、不必要な完全スキャンが防止されます。 クエリはすぐに応答され、保存されます。`ans_prev`次の操作のデコードのために。 モジュロ演算の境界処理は、次のようにして慎重に行われます。`+1`必要な場所に。
