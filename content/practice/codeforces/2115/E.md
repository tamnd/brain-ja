 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた頂点を持つ有向非巡回グラフ (DAG) をナビゲートするように求められます。 各頂点には、指定されたコストで指定されたパワーを持つカードを販売するトレーダーが含まれています。 ある程度のコインを持って頂点 1 から開始し、エッジに沿ってボスの位置を表すターゲット頂点まで移動したいとします。 訪れる各頂点で、お金に余裕がある限り、好きなだけカードを購入できます。 目標は、ボスに到達したときにカードの合計パワーを最大化することです。 

入力は、グラフ構造 (常に小さい頂点から大きい頂点に向かうエッジ)、トレーダー情報 (カードのコストとパワー)、および複数のクエリで構成されます。 各クエリはボスの頂点と開始時のコインの数を指定し、出力はその開始条件で達成可能なカード パワーの最大合計です。 

グラフは最大 200 個の頂点と 2000 個のエッジを持つ DAG であるため、O(n²) または O(n·m) のようなスケールの任意のアルゴリズムが受け入れられます。 各クエリには最大 10^9 のコインを含めることができるため、お金を対象とした単純な動的プログラミングなど、コインを直接反復するソリューションは除外されます。 

明らかではないエッジケースには次のようなものがあります。 

- 最も安価なカードに比べて非常に少ないコインから開始します。 たとえば、コイン = 1 で、すべてのカードのコストが ≥2 の場合、カードを購入することはできません。 答えは 0 でなければなりません。 
- 最大 10^9 の大きなコイン値により、単純な DP は実行不可能になります。 
- 非常に高いカードパワーを持つ頂点ですが、コストが高くなります。 不注意な解決策は、後でより高価でより強力なカードを購入するのを待つ代わりに、初期の頂点で最適ではない小さなカードを誤って購入する可能性があります。 
- 同じターゲット頂点を持つ複数のクエリ。 各クエリの再計算は遅すぎるため、前処理が必要です。 

エッジケースを示す小さな例:```
n = 3, m = 2
c = [2, 3, 5], w = [5, 10, 20]
edges = [(1,2),(2,3)]
query: p=3, r=4
```ここでは、最初に頂点 2 または 3 にカードを置く余裕はありません。 正しい答えは、頂点 1 で 2 枚のカードを購入し、合計パワーが 10 になることです。各頂点で常に 1 枚のカードを購入できると仮定した場合、単純なアプローチは失敗する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、頂点 1 からターゲット頂点までのすべてのパスをシミュレートし、各パスに沿って、残りのコインで購入できるカードのすべての組み合わせを検討します。 各カードの最大倍数の購入を考慮してわずかに最適化したとしても、クエリ値が大きい (最大 10^9) ため、可能なコインの配布数は膨大になります。 したがって、このアプローチは実行不可能です。 

重要な洞察は、グラフが DAG であり、各頂点でのコインとパワーの取引が線形で無制限であることを観察することで得られます。 頂点では、必要な量のコインを使って同じカードを繰り返し購入することができ、事実上、各頂点を 1 つのアイテムが入った無制限のナップザックに変えることができます。 最適な戦略は、各ステージでコインあたりのパワーの比率を最大化することですが、コインの量が多いため、コインに対する正確な DP は非現実的です。 

代わりに、凸包またはスロープ トリックと呼ばれる手法を使用して、各頂点で達成可能なパワーを消費したコインの関数として表すことができます。 私たちの設定では、各頂点で 1 つのカード タイプを無制限に購入できるため、頂点の DP 関数は区分的に線形になります。前の頂点ごとに`u`機能付き`f_u`、頂点の関数`v`の最大値です`f_u + k*w_v`コイン用`k*c_v ≤ total coins`。 対象となるコインバジェットの合計までの離散表現を使用することで (ただし、巧みに圧縮されています)、すべてのクエリに効率的に答えることができます。 

最後の観察は、クエリはターゲット頂点での特定のコイン量のみを要求するため、各頂点に対してコインバジェットの可能な最大パワーを妥当なカットオフ (たとえば、任意のパスに沿った最も安価なカードの合計) まで前処理し、その後、その頂点でのコインあたりのパワーを使用して、大きなコインを含むクエリを線形に外挿できるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(パス × コイン) | O(コイン) | r が大きいため遅すぎます |
 | 頂点ごとに無制限のナップザックを使用した DAG 上の DP | O(n² + m + q) 前処理あり | O(n × 最大有効コイン数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各頂点のグラフ、コスト、および累乗を読み取ります。 DAG の隣接リストを作成します。 
2. 頂点を位相的に並べ替えます。 これにより、すべての先行処理の後にのみ各頂点が処理されることが保証されます。 
3. 各頂点の DP 配列を初期化し、さまざまなコイン バジェットに対して達成可能な最大パワーを保存します。 頂点 1 から開始します: の最大パワー`r`コインは`(r // c_1) * w_1`。 
4. トポロジ順に頂点を反復処理します。 頂点ごとに`v`、すべての前任者を考慮してください`u`。 到達可能な電力状態ごとに、`u`の DP、新しい最大電力を計算します`v`の倍数を加算することで`v`のカードに残りのコインが与えられます。 アップデート`v`結果の電力がより高い場合は、 の DP エントリ。 
5. すべての頂点を処理した後、各頂点はコイン バジェットをその頂点で達成可能な最大パワーにマッピングする DP 関数を持ちます。 明示的に格納されていない大きなコイン値の場合は、頂点のコインあたりのパワー (c_v と w_v の積による残りのコインの床除算) に基づいて関数を線形に拡張します。 
6. 各クエリについて`(p, r)`、頂点で DP 関数を読み取ります`p`。 達成可能な最大電力を計算します。`r`保存された離散状態と大規模な場合の線形外挿を使用するコイン`r`。 

機能する理由: トポロジー順序により、すべての頂点がその依存関係の後に処理されることが保証されるため、DP は常に先行するものから正しい最大パワーを取得します。 無制限のナップザック プロパティを使用すると、任意のコイン金額に対して、その頂点でのカードの最適な購入が計算されることが保証されます。 DP 関数は、すべてのパスに沿って最適な達成可能な電力を正しく伝播します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

n, m = map(int, input().split())
c = [0] * n
w = [0] * n
for i in range(n):
    c[i], w[i] = map(int, input().split())

graph = [[] for _ in range(n)]
in_deg = [0] * n
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    graph[u].append(v)
    in_deg[v] += 1

# topological sort
order = []
queue = deque([i for i in range(n) if in_deg[i] == 0])
while queue:
    u = queue.popleft()
    order.append(u)
    for v in graph[u]:
        in_deg[v] -= 1
        if in_deg[v] == 0:
            queue.append(v)

# DP: max power achievable at vertex with coins up to "effective limit"
# Use only coins up to 200*n (heuristic safe bound)
LIMIT = 200 * n
dp = [defaultdict(int) for _ in range(n)]
dp[0][0] = 0
for u in order:
    # add unlimited purchases at u
    new_dp = defaultdict(int)
    for spent, power in dp[u].items():
        # buy multiples of card u within LIMIT
        max_buy = (LIMIT - spent) // c[u]
        for k in range(max_buy + 1):
            total_spent = spent + k * c[u]
            total_power = power + k * w[u]
            if new_dp[total_spent] < total_power:
                new_dp[total_spent] = total_power
    dp[u] = new_dp
    # propagate to children
    for v in graph[u]:
        for spent, power in dp[u].items():
            if dp[v][spent] < power:
                dp[v][spent] = power

q = int(input())
queries = [tuple(map(int, input().split())) for _ in range(q)]

# answer queries
for p, r in queries:
    p -= 1
    max_power = 0
    for spent, power in dp[p].items():
        if spent <= r:
            # remaining coins can buy multiples of p's card
            total_power = power + ((r - spent) // c[p]) * w[p]
            if total_power > max_power:
                max_power = total_power
    print(max_power)
```このソリューションでは、まずトポロジー順序を計算して、DP の伝播が DAG 構造に従うようにします。 各頂点について、コインバジェットの達成可能なすべてのパワーをヒューリスティック制限まで計算し、これらの状態を子に伝播します。 クエリ中に、現在の頂点のカードをできるだけ多く購入することで、残りのコインを計算します。 大型のようなエッジケース`r`整数の除算によって処理され、各コインの反復を回避します。
