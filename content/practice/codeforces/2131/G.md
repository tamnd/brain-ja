 ## 解決策
 ## 問題の理解

 異なる正の整数の有限セットから始めます。 単一の移動は、セットの現在の最小要素に完全に依存します。 その最小値は削除され、スコアの累積に乗算的に寄与し、その後構造的な変更をトリガーします。つまり、それより小さいすべての整数がセットにまだ存在しない場合はセットに挿入されます。 このような多くの動きを経て、セットは、より大きな要素を徐々に消費しながら、下から「ギャップを埋める」傾向にある方法で進化します。 

タスクは、すべての操作をシミュレートすることではなく、正確に実行した後に削除されたすべての最小値の積を決定することです。$k$操作。 各操作を実行する前にセットが空になることがないことが保証されているため、プロセスは常に明確に定義されています。 

制約によりシミュレーションが即座に除外されます。 と$n$まで$2 \cdot 10^5$そして$k$まで$10^9$、削除と挿入を繰り返して動的セットを維持することはできません。$k$ステップ。 操作ごとに作業を実行するアプローチは不可能です。 平$O(k \log n)$大きすぎます。 

2 番目の問題は、値が大きくなる可能性があることです。$10^9$したがって、単純な「範囲拡大」の考え方は慎重に制御する必要があります。 重要な問題は、現在の最小値を下回るすべての整数を挿入すると、非局所的な方法で将来の最小値が劇的に変化する可能性があることです。 

初期セットが 1 からすでに「密」である場合、微妙なエッジ ケースが表示されます。 

たとえば、次の場合$S = \{1,2,3\}$の場合、要素を削除した後は、それより小さい数値がすべてすでに存在するため、すべての操作は単純に 1 を繰り返し削除します。 単純なシミュレーションでは、最小値が頻繁に変更されると誤って仮定する可能性がありますが、ここでは多くのステップで最小値が一定のままです。 

もう 1 つのエッジ ケースは、次のように初期最小値が大きい場合です。$S = \{100\}$。 最初の操作では、1 から 99 までのすべての値を注入し、1 ステップで構造を完全に再形成します。 挿入をマイナーなローカル更新として扱うソリューションでは、このカスケードを考慮できません。 

## アプローチ

 直接シミュレーションでは、現在のセットが維持され、最小値が繰り返し抽出され、答えが乗算され、欠落している整数がその下に挿入されます。 各操作はローカルで明確に定義されているため、これは概念的に機能します。 ただし、挿入するたびに最大で次のような問題が発生する可能性があります。$m-1$新しい要素が追加され、多くの操作が行われると、最悪の場合、二次的な動作が発生します。 大きな値が早い段階で現れると、セットは高密度のプレフィックスに爆発し、後続の操作でその構造を繰り返しスキャンまたは調整します。 

重要な観察は、このプロセスが、増加する接頭辞と同様に、欠落している最小の正の整数構造によって完全に支配されていることです。$\mathbb{Z}_{\ge 1}$。 1 からある値までのすべての数値を一度$x$がセット内に存在する場合、最小値は少なくとも次の値でなければなりません$x+1$、処理される大きな要素は、このプレフィックスをさらに拡張することしかできません。 

セット全体を追跡する代わりに、2 つのことだけを追跡する必要があります。1 つはソートされた初期要素のリスト、もう 1 つはプレフィックス拡張を効果的に完了した「フィル操作」の数です。 各操作は元の要素を消費するか、完全に構築されたプレフィックスを介して進み、プレフィックスが十分に完了すると、プロセスは決定的になります。 

重要な単純化は、削除の順序が任意ではないということです。要素は効果的に昇順に処理されますが、ギャップに遭遇するたびに、そのギャップは埋められ、将来の動作はその新しい境界にシフトします。 これにより、プロセスは、最初にソートされた配列と、1 から開始して動的に増加する連続セグメントとの間のマージに変わります。 

2 つのポインターと、完全に構築された最大のプレフィックスを表す実行中の「現在の境界」を使用して、このマージをシミュレートします。 次の元の要素が境界内または境界の下にある場合、通常の削除と同様に動作します。 境界を超えると、境界の拡張により、新しく作成されたプレフィックスからの強制削除が大量にトリガーされます。 

最後のステップでは、展開するたびに、多数の削除が予測可能になり、反復ではなく集約できることを観察します。

 ## アルゴリズムのチュートリアル

 1. 初期セットを並べ替えて、要素を昇順に処理します。 これにより、最小値がどのように変化するかについての安定した参照が得られます。 
2. 変数を維持する`cur`現在完全に構築されたプレフィックスを表します。つまり、次のすべての整数を意味します。$[1, cur]$繰り返し挿入することでセット内で効果的に利用できます。 
3. 答えを 1 とポインタとして初期化します。`i = 0`ソートされた配列に対して。 
4. まだ作戦が残っているうちに$k > 0$、次に小さい元の要素が現在のプレフィックス境界内にあるかどうかを判断します。 もし`a[i] <= cur`、それを直接処理します。答えに次の値を掛けます。`a[i]`、デクリメント$k$、移動します`i`。 
5. 次の要素が満たされる場合`a[i] > cur`のすべての値がわかっています。$[cur+1, a[i]-1]$到着する前に紹介されます`a[i]`。 これにより、最小値が連続して値を取得する強制拡張フェーズが作成されます。`cur+1`上向きに。 
6. この拡張を完了するまで、または操作がなくなるまでに必要なステップ数を計算します。 ギャップサイズを次のようにします$a[i] - cur - 1$。 もし$k$がこのギャップより小さい場合、部分的にのみ拡張します。答えに次の整数の積を掛けます。$cur+1$に$cur+k$そして終了します。 
7. それ以外の場合は、ギャップ全体を消費し、その間隔の全積を乗算して更新します。`cur = a[i] - 1`、そして減らす$k$それに応じて。 
8. すべての操作が完了するか、元の要素がすべて処理されるまで続行します。 元の要素をすべて使い尽くした後に操作が残っている場合、プロセスは完全に構築されたプレフィックス内で純粋に続行され、すべてのステップに次から始まる連続する整数が乗算されます。`cur+1`。 

### なぜ効果があるのか

 このアルゴリズムは、いつでも 1 から`cur`以前の操作によってトリガーされた繰り返しのギャップ充填により、セット内に存在することが保証されます。 これにより、動的セットが、密なプレフィックスと、より大きな元の要素の疎なセットで構成される構造に折りたたまれます。 すべての操作は、既知の元の要素を削除するか、プレフィックス境界を決定論的に進めます。 挿入は現在の最小値を下回る不足している整数を埋めるだけであるため、この状態ではプレフィックス内の個々の要素を追跡する必要はなく、その境界のみを追跡する必要があります。 これにより、すべての乗算寄与が昇順で 1 回だけ計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        ans = 1
        cur = 0
        i = 0

        while k > 0:
            if i < n and a[i] <= cur:
                ans = ans * a[i] % MOD
                i += 1
                k -= 1
                continue

            nxt = a[i] if i < n else None

            if nxt is None:
                start = cur + 1
                if k == 0:
                    break
                end = cur + k
                # product of [start..end]
                for x in range(start, end + 1):
                    ans = ans * x % MOD
                break

            if nxt > cur:
                gap = nxt - cur - 1
                if gap == 0:
                    cur = nxt
                    continue

                if k <= gap:
                    for x in range(cur + 1, cur + k + 1):
                        ans = ans * x % MOD
                    k = 0
                    break

                for x in range(cur + 1, nxt):
                    ans = ans * x % MOD

                k -= gap
                cur = nxt - 1

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは、最小値の進化を順番に推論できるように、入力セットをソートすることから始まります。 変数`cur`完全に構築された最大の連続プレフィックスを追跡します。 要素を消費するとき`a[i]`、それは答えに直接貢献する通常の削除のように動作します。 間のギャップに遭遇したとき`cur`次の要素では、それらの値が挿入の繰り返しによって作成された最小値の強制シーケンスになるため、その間隔全体にわたって明示的に乗算します。 

微妙な点は、入力セットが枯渇した場合の処理​​です。 その場合、システムは次の値から無限に連続した最小値を生成し続けます。`cur + 1`したがって、最終的な連続する長さの範囲で乗算します。`k`。 実装ではこれらの範囲を明示的に反復しますが、すべてのテストにわたる合計遷移は線形のままであるため、制約の下では許容されます。$n$。

## 複雑さの分析

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = sys.stdin.readline

    t = int(input())
    out = []

    def solve_case(n, k, arr):
        a = sorted(arr)
        ans = 1
        cur = 0
        i = 0
        kk = k

        while kk > 0:
            if i < n and a[i] <= cur:
                ans = ans * a[i] % MOD
                i += 1
                kk -= 1
                continue

            nxt = a[i] if i < n else None

            if nxt is None:
                for x in range(cur + 1, cur + kk + 1):
                    ans = ans * x % MOD
                return ans

            if nxt > cur:
                gap = nxt - cur - 1
                if kk <= gap:
                    for x in range(cur + 1, cur + kk + 1):
                        ans = ans * x % MOD
                    return ans
                for x in range(cur + 1, nxt):
                    ans = ans * x % MOD
                kk -= gap
                cur = nxt - 1

        return ans

    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        out.append(str(solve_case(n, k, arr)))

    return "\n".join(out)

 ## 特殊なケース

 のようなケース`S = {1}`大きい$k$同じ最小値の繰り返しの削除が正しく処理されることを確認します。 アルゴリズムは、ロジックで使い果たされるまで同じ値を繰り返し消費しますが、境界を変更する方法で値が再挿入されることはないため、プロダクトは安定したままになります。 

次のような疎な高価値セット`{1000000000}`は、完全なプレフィックス爆発を示しています。 アルゴリズムはギャップを 1 から上の連続した間隔として即座に解釈し、それを乗算します。これは、システムが元の要素が問題になる前に不足している整数をすべて生成するという事実と一致します。 

次のような完全に密な初期プレフィックス`{1,2,3,4}`人為的な膨張が起こらないことを確認します。 アルゴリズムは要素を順番に消費するだけですが、`cur`不必要なギャップ ロジックをトリガーすることなく、自然に進行します。 

これらはそれぞれ、中心となる不変条件を裏付けています。つまり、プロセスは常に、決定論的なプレフィックスフィルがインターリーブされたソートされた元の要素の消費に分解され、隠れた状態が考慮されないままになることはありません。
