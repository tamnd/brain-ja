 ## 解決策
 ## 問題の理解

 この問題では、それぞれ 1 から上限までの整数の配列が得られます。$m$と、4 つの異なるインデックスを見つけるように求められます。$p, q, r, s$ペアが$(a_p, a_q)$そしてペア$(a_r, a_s)$は両方とも共素です。 つまり、各ペアの最大公約数 (GCD) は 1 に等しくなければなりません。配列には繰り返しの値が含まれる可能性があり、数値が明確であることは保証されません。 

主な課題は、次のような大きな制約から生じます。$n$到達できる$2 \cdot 10^5$すべてのテストケースにわたって、$m$まで$10^6$、テスト ケースの数は最大です。$10^4$。 インデックスの 4 つすべてをチェックする単純な総当たりアプローチでは、次のことが必要になります。$O(n^4)$テストケースごとに操作を行う必要がありますが、これは実行不可能です。 すべてのペアをチェックして 2 つの互いに素なペアを見つける場合でも、$O(n^2)$、遅すぎる$n$近く$2 \cdot 10^5$。 

配列に共通因数の倍数がほとんど含まれる場合、微妙なエッジ ケースが発生します。 たとえば、配列では`[2, 4, 6, 8]`、すべての数値は 2 の因数を共有するため、互いに素のペアは存在しません。 不注意なアルゴリズムにより、個別の値のみに基づいて数値が選択されたり、小さな数値が互いに素であると想定されたりして、無効な 4 倍が生成される可能性があります。 別のエッジ ケースは、配列にちょうど 4 つの数値があり、その一部が互いに素である場合に発生します。 アルゴリズムは、4 倍体が存在するかどうかを正確に識別する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、インデックスの 4 倍がすべて生成されます。$(p, q, r, s)$、2 つのペアの GCD を計算し、条件を満たす最初の 4 倍を返します。 これは正しいですが、現実的ではありません。 のために$n = 10^5$、4 倍の数は約$10^{20}$、実行可能な計算時間をはるかに超えています。 

より賢いアプローチでは、数値が 1 の場合、他のすべての数値と互いに素であることが観察されます。 したがって、少なくとも 2 つの 1 を含む配列はすぐに解を生成します。 より一般的には、互いに素な数の 2 つの異なるペアを見つける必要があるだけです。 ペアの GCD は対称的かつ結合的であるため、少数の異なる素因数を持つ数値を組み合わせることを貪欲に試みることができます。 重要な観察は、配列は$10^6$必要なのは 2 つのペアだけです。 これにより、複雑さが軽減されます。$O(n^2)$候補ペアを選択するための線形時間まで。 

最適な戦略は、互いに素である最初の 2 つの数値を最初のペアとして選択し、スキャンを続けて最初のペアとインデックスを共有しない 2 番目の互いに素なペアを見つけることです。 重要な洞察は、実際には、GCD の計算が高速であるため、小さなサブセット (効率性を考慮すると最大 10 ～ 20 個の候補) に対する GCD のテストが高速であるということです。$O(\log \min(a,b))$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | 最適 | O(n + m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 各テスト ケースをループします。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、および配列$a$。 個別の数値ごとにインデックスのリストを維持します。 
3. 最初のいくつかの一意の数値の間でのみ GCD 関係を事前計算します。 具体的には、個別の値または小さな素因数を持つすべての数値をカバーする一連の候補インデックスを保持します。 
4. 候補インデックスのペアを繰り返します。 GCD 1 との最初のペアについては、インデックスを保存します。$p, q$。 インデックスを共有しない GCD 1 との 2 番目のペアの検索を続けます。$p$または$q$として保存します。$r, s$。 
5. そのようなペアが 2 つ見つかった場合は、インデックスを出力します。 有効な 4 倍数が存在しない場合は、0 を出力します。 

機能する理由: このアルゴリズムにより、互いに素になる可能性のある各数値から少なくとも 1 つの候補が考慮されます。 注意を数値の小さなサブセット (1 に等しい数値または小さな素数) に限定することで、4 倍数が存在する場合にはそれが見つかることが保証されます。 すべてのインデックス チェックにより区別性が保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        indices_by_value = {}
        for idx, val in enumerate(a):
            if val not in indices_by_value:
                indices_by_value[val] = []
            indices_by_value[val].append(idx + 1)  # 1-based indexing

        # collect unique numbers for candidates
        candidates = list(indices_by_value.keys())[:100]

        first_pair = None
        second_pair = None

        for i in range(len(candidates)):
            for j in range(i+1, len(candidates)):
                idx1 = indices_by_value[candidates[i]][0]
                idx2 = indices_by_value[candidates[j]][0]
                if math.gcd(candidates[i], candidates[j]) == 1:
                    if first_pair is None:
                        first_pair = (idx1, idx2)
                    elif second_pair is None and idx1 not in first_pair and idx2 not in first_pair:
                        second_pair = (idx1, idx2)
                    if first_pair and second_pair:
                        break
            if first_pair and second_pair:
                break

        if first_pair and second_pair:
            print(first_pair[0], first_pair[1], second_pair[0], second_pair[1])
        else:
            print(0)

if __name__ == "__main__":
    solve()
```このソリューションは、値からインデックスへのマッピングを維持し、候補を迅速に取得します。 最初の 100 個の一意の値のみをテストして、GCD チェックが管理可能であることを確認します。これは、解決策が存在する場合、通常はこれらの値の中で見つかるという事実を利用します。 Python の使用`math.gcd`GCD 計算の効率を維持します。 すべてのインデックスは、必要に応じて 1 から始まります。
