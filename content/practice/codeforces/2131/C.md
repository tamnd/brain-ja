 ## 問題の理解

 マルチセットから始めます$S$サイズの$n$それを別のマルチセットに変換したいと考えています$T$同じサイズの。 唯一許可される移動は 1 つの要素を取る$x$から$S$を削除し、次のいずれかに置き換えます。$x+k$または$|x-k|$。 各操作ではマルチセットのサイズが維持されますが、個々の値は変更できます。 

核心的な問題は、こうした動きを繰り返し適用することで形を変えることができるかどうかである。$S$まさに$T$、多重性を尊重します。 

この制約は、各テスト ケースがほぼ直線的な時間で処理される必要があることを示唆しています。$n$、合計から$n$すべてのテストにわたって、$2 \cdot 10^5$。 値ごとの変換を調べたり、操作を段階的にシミュレートしたりするアプローチは、到達可能な状態が爆発的に増加するため、すぐに失敗します。 

微妙な点は、次の条件を除いて値が厳密に制限されていないことです。$10^9$したがって、値を直接グラフで走査することは不可能です。 

2 つのエッジ パターンは、素朴な考えを打ち破る傾向があります。 

まず、各要素が同じ剰余モジュレーションを持つ任意のターゲットに独立して到達できると仮定します。$k$は間違っています。$|x-k|$この操作では、値がゼロを超えるまで非線形に値を減らすことができ、その後動作が変わります。 たとえば、$k=5$、 から$x=6$に行くことができます$1$、その後に$4$、その後に$9$、純粋にモジュール式ではないサイクルが生成されます。 

第 2 に、変換にはどちらのマルチセットにも存在しない中間値が必要になる可能性があるため、最も近い値の貪欲なマッチングは失敗すると仮定します。 

誤解を招きやすい小さなケースは次のとおりです。```
S = [1, 6], T = [4, 3], k = 5
```貪欲な試みは 1→6 および 6→1 に一致する可能性がありますが、中間の遷移は、構造が単純な方法では対称ではないことを示しています。 

## アプローチ

 ブルートフォース解釈では、各値がエッジのあるグラフ内のノードとしてモデル化されます。$x \to x+k$そして$x \to |x-k|$、マルチセットかどうかを確認しようとします$T$から到達可能です$S$再配布経由で。 これは、状態カウントに関するマルチソースの到達可能性の問題に変わります。これは、値が無制限に増加するため、実際には指数関数的になります。$+k$方向。 

失敗点は、操作ごとに各数値が 2 つの可能性に分岐し、シーケンスが任意に長くなる可能性があることです。 ヒューリスティックな限界で値を制限したとしても、遷移は単調ではないため、枝刈りは安全ではありません。 

重要な観察は、演算構造が非常に強力な不変式を保持していることです。つまり、すべての数値は最終的にその剰余クラスのモジュロ内で独立して動作します。$k$ただし、繰り返し適用することで値を減らすことができます。$|x-k|$正規の範囲に入るまで。 

具体的には、「引き算」を繰り返し適用することで、$k$「絶対的な意味で」操作は常に区間内の一意の代表に向かって数値をプッシュします。$[0, k)$、その後、さらなる構造が予測可能になります。 すべての値は、剰余モジュロによって決定される小さな境界領域内で最終的に循環するチェーンにマッピングできます。$k$。 唯一の意味のある自由は、次を使用して「上向きにラップ」する回数です。$+k$、値をシフトしますが、その剰余クラスは変更しません。 

これにより、問題は、各残差クラスからの要素の数を追跡することになります。$S$そして必要な$T$、各クラス内でマルチセットが許可されたシフトの下で整列できることを確認します。 

最終チェックは残差クラスごとのバランスの問題となり、要素は段階的に上に押し上げられます。$k$、ただし残基全体で恣意的に再配置されるわけではありません。

 ## アルゴリズムのチュートリアル

 すべての値をその残基クラス内の標準形式に還元し、増加するチェーン全体に質量がどのように分布するかを比較します。 

1. グループ要素$S$そして$T$値のモジュロによって$k$。 これは、許可された操作の両方が剰余モジュレーションを保持するために必要です。$k$正規化後に消える符号効果まで。 
2. グループごとに、要素を並べ替えます。 変換により効果的に要素を 1 ずつ上にシフトできるため、ソートが必要になります。$k$したがって、整列はチェーン内の順序を尊重する必要があります。 
3. 剰余グループ内で値を昇順に処理し、余剰要素がどのように生成されるかをシミュレートします。$S$不足分を補うために上方に押し上げることができる$T$。 の値が$S$同じレベルで必要とされるものを超えている$T$、超過分は効果的に次の高いレベルに運ばれます。$x+k$。 
4. ソートされた値を反復処理しながら、実行中の余剰カウンターを維持します。 各ステップで、必要な分を差し引きます。$T$。 赤字がある場合は、より低い価値から繰り出される剰余を使って埋め合わせようとします。 
5. どこかの時点で不足を補うことができない場合、その剰余クラスでは変換は不可能です。 
6. すべての残基クラスに対して個別に繰り返します。 すべてのクラスが満足できる場合、答えは「YES」、そうでない場合は「NO」になります。 

重要なアイデアは、動きはステップの等差数列に沿って上向きにのみ流れるということです。$k$、したがって、各剰余クラスは一方向の流れシステムのように動作します。 

### なぜ効果があるのか

 各要素の唯一の不可逆方向は、追加により上向きになります。$k$、一方、$|x-k|$操作は値を減らすことのみができますが、クラス間の相互作用を可能にする方法でその残基クラスを変更することはできません。 これにより、残基ごとに独立した鎖が作成されます。 各チェーン内で要素を任意に上にシフトできますが、チェーンをまたいで交差したり並べ替えたりすることはできません。 貪欲な余剰の伝播はこの流れを正確にモデル化しており、すべての赤字が以前の黒字と一致する必要があり、不一致がある場合は不可能を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = list(map(int, input().split()))
        tarr = list(map(int, input().split()))
        
        groups_s = defaultdict(list)
        groups_t = defaultdict(list)
        
        for x in s:
            groups_s[x % k].append(x)
        for x in tarr:
            groups_t[x % k].append(x)
        
        ok = True
        
        for r in set(list(groups_s.keys()) + list(groups_t.keys())):
            a = sorted(groups_s[r])
            b = sorted(groups_t[r])
            
            i = j = 0
            surplus = 0
            
            while i < len(a) or j < len(b):
                av = a[i] if i < len(a) else float('inf')
                bv = b[j] if j < len(b) else float('inf')
                
                if av == bv:
                    i += 1
                    j += 1
                    continue
                
                if av < bv:
                    surplus += 1
                    i += 1
                else:
                    if surplus == 0:
                        ok = False
                        break
                    surplus -= 1
                    j += 1
            
            if not ok:
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```実装では、まず剰余剰余によって値を分割します。$k$、独立した変換チェーンを分離します。 各グループ内で、ソートにより、可能性のある上方シフトを処理するための一貫した方向が強制されます。 

2 ポインター ループは、次の可用性を比較します。$S$対需要$T$。 いつ$S$値が小さい場合、それを上方に押し上げることができる潜在的な余剰として扱います。 いつ$T$現在利用できない価値を要求する場合、以前に蓄積された余剰を消費します。 余剰が存在しない場合は、すぐに失敗します。 

番兵$+\infty$この処理により、1 つのリストが使い果たされたときに確実に正常に終了します。

 ## 特殊なケース

 重要なエッジ ケースは、両方のマルチセットが同一であるものの、変換が不要になるように配置されている場合です。 例えば、$S = T = [x_1, x_2, \dots]$。 このアルゴリズムは各残基グループを処理し、完全なペアごとの一致を確認し、余剰を使用することはありません。 出力は変換ロジックに依存せずに YES のままです。 

もう 1 つのエッジ ケースは、1 つの剰余クラスに、上方に複数回プッシュする必要がある非常に小さい要素がある場合です。 例えば：```
S = [0, 0, 0], T = [6, 6, 6], k = 3
```すべての要素は剰余 0 に属します。アルゴリズムは、より低い値で余剰を蓄積し、上に進むにつれてそれを消費し、すべての要求を首尾よく満たします。 これは、繰り返される +k 遷移が余剰伝播によって正しくモデル化されていることを確認します。 

失敗するケースは、必要なターゲットが同じチェーン内の十分な事前供給なしに出現する場合です。 で：```
S = [1], T = [100], k = 7
```中間ステップを介して上方に伝播する初期要素がないため、余剰生成シーケンスがギャップを埋めることはできません。 アルゴリズムは、需要時点で余剰がゼロのままである場合、これは不可能であると正確に識別します。
