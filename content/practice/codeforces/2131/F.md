 ## 解決策
 ## 問題の理解

 2 つのバイナリ文字列が与えられています。`a`そして`b`、それぞれの長さ`n`。 彼らは仮想を定義します`n × n`各セルが配置されるグリッド`(i, j)`値が含まれています`a[i] XOR b[j]`。 ユーリは左上のセルから開始します`(1,1)`右か下にしか移動できません。 あらゆる細胞への旅`(x, y)`パスに沿ったすべてのセルに以下が含まれている場合に有効です。`0`。 移動する前に、Yuri は任意の要素を反転できます。`a`または`b`グリッド値を変更するには、それに到達するために必要なフリップの最小数を計算する必要があります。`(x, y)`すべてのセルに対して値を計算し、グリッドのこれらの値を合計します。 

この問題には効率的な解決策が必要です。`n`まで可能です`2×10^5`と合計`n`すべてのテストケースにわたって、`2×10^5`。 BFS または DP を使用してセルごとに最小フリップを個別に計算する単純なソリューションは次のようになります。`O(n^3)`最悪の場合、2 秒の制限ではまったく実行不可能です。 線形または二次に近いアルゴリズムが必要です。`n`。 

エッジケースには、次のサイズのグリッドが含まれます`1×1`、唯一のセルがすでにゼロであるか、反転が必要である可能性があり、グリッドでは、`a`または`b`はすべて 0 または 1 です。 不用意に処理すると、行と列の両方の調整が必要なパスのフリップをカウントする際に、1 つずつずれたエラーが発生する可能性があります。 たとえば、次の場合`a = "1"`そして`b = "1"`、到達するには 2 回ではなく、1 回のフリップが必要です。`(1,1)`。 

## アプローチ

 ブルートフォースアプローチでは次のように計算されます。`f(x,y)`すべての細胞に対して独立して`(x,y)`。 各セルについて、反転のすべての組み合わせを試します。`a_i`または`b_j`パス上のすべてのセルがゼロになるようにします。 これは、各宛先への有効なパスが保証されるため、原則的には正しいです。 問題は、セルごとに可能なすべての反転を繰り返す必要があることです。`O(n^3)`単一のテスト ケースの複雑さ:`O(n^2)`セルと最大`O(n)`セルごとに反転します。 このアプローチは次の場合に失敗します。`n`到達する`2×10^5`。 

重要な洞察は、セルの最小フリップ数です。`(x,y)`プレフィックス内の 0 と 1 の数のみに依存します`a[1..x]`そして`b[1..y]`。 定義すると`prefix_a[i]`最初の 1 の数として`i`の要素`a`、同様に`b`、次に最小値を反転してパスを作成します`(x,y)`ゼロは、これらのプレフィックスの合計の関数として表現できます。 具体的には、パスに沿ったすべてのセルが次の条件を満たす必要があります。`a[i] XOR b[j] = 0`、これは以下と同等です`a[i] = b[j]`。 したがって、どのような場合でも、`(x,y)`、必要なフリップの数は、プレフィックスの和集合内の 1 の数です。`a[1..x]`そして`b[1..y]`、両方が 1 である位置の数の 2 倍を引いたものです (二重カウントを避けるため)。 この観察を使用すると、複雑さを次のように軽減できます。`O(n^2)`単純なプレフィックス合計計算を使用したテスト ケースごと。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 最適 (プレフィックスカウント) | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`、 弦`a`、文字列`b`。 
2.文字列を変換する`a`そして`b`簡単に操作できるように整数リストに変換します。 
3. プレフィックスの 1 の合計を事前計算します。`a`そして`b`。 させて`prefix_a[i]`内の 1 の数を示します`a[0..i-1]`そして同様に`prefix_b[i]`。 
4. 変数を初期化する`total`すべての最小フリップの合計を累積する`(x,y)`。 
5. 考えられるすべての宛先を反復処理します。`(x, y)`。 それぞれ:

 - コンピューティング`ones_a = prefix_a[x]`そして`ones_b = prefix_b[y]`。 
- コンピューティング`zeros_a = x - ones_a`そして`zeros_b = y - ones_b`。 
- 到達する最小フリップ数`(x,y)`は`min(ones_a + ones_b, zeros_a + zeros_b)`なぜなら、パスのプレフィックスですべての 1 を 0 に反転することも、0 を 1 に反転することもできるからです。 
6. 計算された最小フリップを`total`。 
7. すべての処理が完了したら`(x,y)`、印刷`total`。 

機能する理由: 重要な特性は、すべてのパスが`(1,1)`に`(x,y)`行と列に沿って単調です。 したがって、最小フリップは完全に行および列のプレフィックス内の 1 と 0 の数によって決まります。 これにより、パス制約に違反しないことが保証され、すべての 1 を 0 に変換するか、すべての 0 を 1 に変換する間の最小値を取ることで二重カウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().strip()))
    b = list(map(int, input().strip()))
    
    prefix_a = [0] * (n + 1)
    prefix_b = [0] * (n + 1)
    
    for i in range(n):
        prefix_a[i + 1] = prefix_a[i] + a[i]
        prefix_b[i + 1] = prefix_b[i] + b[i]
    
    total = 0
    for x in range(1, n + 1):
        ones_a = prefix_a[x]
        zeros_a = x - ones_a
        for y in range(1, n + 1):
            ones_b = prefix_b[y]
            zeros_b = y - ones_b
            total += min(ones_a + ones_b, zeros_a + zeros_b)
    print(total)
```このソリューションは入力を効率的に読み取り、プレフィックスの合計を計算して、プレフィックスの合計を繰り返し再計算することを回避します。 プレフィックス配列の 1 から n までを慎重に繰り返して、1 から始まる問題の説明と一致させます。 使用する`min(ones_a + ones_b, zeros_a + zeros_b)`最も安価な調整方法を確実に検討します`a`そして`b`パスに沿ってゼロにします。
