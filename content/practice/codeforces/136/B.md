 ## 解決策
 ## 問題の理解

 2 つの 10 進整数が与えられます。`a`そして`c`。 この問題のコンピュータはバイナリ XOR を使用しません。 代わりに、と呼ばれる三項演算を使用します。`tor`。 

申請するには`tor`、両方の数値は基数 3 で書かれます。一方の数値の桁数が少ない場合は、両方の長さが一致するように先頭にゼロが埋め込まれます。 次に、位置ごとに独立して、対応する数字をモジュロ 3 で加算します。 桁間の桁上げはありません。 

たとえば、基数 3 では次のようになります。 

-`14 = 112`-`50 = 1212`パディング後:

 -`0112`-`1212`桁ごとのモジュロ 3 加算は次のようになります。 

-`(0+1)%3 = 1`-`(1+2)%3 = 0`-`(1+1)%3 = 2`-`(2+2)%3 = 1`したがって、結果は次のとおりです`1021₃ = 34`。 

タスクが逆になります。 私たちは知っています`a`そして`c`そして、最小の 10 進整数を構築する必要があります。`b`次のような:```
a tor b = c
```制約は数値的に非常に小さく、両方の値は最大でも`10^9`。 の進数 3 表現`10^9`は約 20 桁しかありません。理由は次のとおりです。```
3^20 ≈ 3.4 × 10^9
```つまり、3 進形式で数値を 1 桁ずつ安全に処理できるということです。 3 進数の桁数に関して線形時間で動作するアルゴリズムは、これらの制約に対して事実上一定時間になります。 

この問題の危険な部分は、減算モジュロ 3 を正しく処理することです。 不用意に実装すると、次のことが計算される可能性があります。```
b_digit = c_digit - a_digit
```結果が範囲内に収まらなければならないことを忘れてください`[0, 2]`。 

考慮する：```
a = 2
c = 0
```三項では:```
2 tor 1 = 0
```なぜなら：```
(2 + 1) % 3 = 0
```正しい答えは、`1`、 ない`-2`。 適切な式は次のとおりです。```
b_digit = (c_digit - a_digit + 3) % 3
```もう 1 つの簡単な間違いは、1 つの数値がゼロになった後の残りの桁の処理を忘れることです。 

例：```
a = 0
c = 5
```以来`5`三項では`12`、次のものが必要です。```
0 tor b = b
```したがって、答えは次のようになります`5`。 

すぐにやめたら`a == 0`の上位 3 進数を誤って無視してしまいます。`c`。 

先頭のゼロも概念的に重要です。 仮定する：```
a = 14
c = 34
```3 項形式にはさまざまな長さがあります。```
14 = 112
34 = 1021
```それらを次のように解釈する必要があります。```
0112
1021
```そうしないと、桁の位置合わせが崩れ、間違った答えが生成されます。 

## アプローチ

 最も直接的な総当たりの解決策は、可能なすべての値を試してみることです。`b`、計算する`a tor b`と等しいかどうかを確認します`c`。 

計算するには`tor`、両方の数値を基数 3 に変換し、桁単位のモジュロ 3 加算をシミュレートします。 この演算自体は 20 桁程度の安価な演算です。 問題は検索スペースです。 以来`b`おおよそ同じくらいの大きさになる可能性があります`10^9`、ブルートフォースアプローチでは何十億ものチェックが必要になる可能性があります。 1 秒あたり数百万回の操作があっても、これはまったく実現不可能です。 

ブルートフォースが論理的に機能する理由は、操作が決定的であるためです。 すべての候補者に対して`b`、 どちらか：```
a tor b = c
```あるいはそうではありません。 

重要な観察は次のとおりです`tor`各 3 進数字で独立して動作します。 ポジション間のキャリー伝播はありません。 これにより、問題はグローバルな検索からローカルな再構築の問題に変わります。 

1 つの 3 進数字の位置を調べているとします。```
(a_digit + b_digit) % 3 = c_digit
```私たちは知っています`a_digit`そして`c_digit`なので、直接解くことができます。`b_digit`:```
b_digit = (c_digit - a_digit + 3) % 3
```すべての 3 進位置は独立して再構築できます。 すべての桁が回復されたら、3 進数の結果を 10 進数に変換します。 

これが機能するのは、モジュロ算術が次の式で一意の答えを与えるためです。`{0,1,2}`すべてのペアに`(a_digit, c_digit)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^9 × log₃10^9) | O(log₃10^9) | 遅すぎる |
 | 最適 | O(log₃10^9) | O(log₃10^9) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`そして`c`。 
2. 初期化します。 

-`power = 1`-`b = 0`変数`power`現在の 3 進位の値を表します。`1, 3, 9, 27, ...`。 
3. いずれかの場合`a`または`c`まだ 3 進数が残っています:

 - 現在の 3 進数を抽出します。```
da = a % 3
dc = c % 3
```- 必要な桁を計算します`b`:```
db = (dc - da + 3) % 3
```- この数字を答えに追加してください:```
b += db * power
```これにより、次を満たす一意の 3 進数が再構築されます。```
(da + db) % 3 = dc
```4. 処理された 3 進数字を削除します。```
a //= 3
c //= 3
```5. 次の 3 進位置に移動します。```
power *= 3
```6. すべての数字が処理されたら、印刷します。`b`。 

### なぜ効果があるのか

 操作`tor`位置間のキャリーがないため、すべての 3 進数字を独立して処理します。 それぞれの位置について次のように解決します。```
(a_digit + b_digit) % 3 = c_digit
```モジュロ算術では、有効な桁が 1 つだけ保証されます`b_digit`で`{0,1,2}`:```
b_digit = (c_digit - a_digit) mod 3
```すべての位置が正しく再構築され、位置が相互作用しないため、完全な数値が得られます。`b`は正しいです。 

解決策も自動的に最小限になります。 各 3 進数字は一意に決定されるため、可能な値は 1 つだけです`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, c = map(int, input().split())

b = 0
power = 1

while a > 0 or c > 0:
    da = a % 3
    dc = c % 3

    db = (dc - da + 3) % 3

    b += db * power

    a //= 3
    c //= 3
    power *= 3

print(b)
```このソリューションは、文字列や数字の配列を明示的に構築せずに、数値を 3 進数で直接処理します。 

表現:```
da = a % 3
```3 進数の最下位桁を抽出します。 整数を 3 で除算すると、後でその桁が削除されます。 

微妙な部分は次のとおりです。```
db = (dc - da + 3) % 3
```余分な`+3`負の中間値を防ぎます。 これがないと、次のようなケースが発生します。```
dc = 0
da = 2
```誤って生成してしまう`-2`の代わりに`1`。 

変数`power`現在の 3 進位の値を追跡します。 数字を計算するとき`db`、次を使用して、最終的な 10 進数の答えの正しい位置に配置します。```
b += db * power
```いずれかの数値に 3 進数がまだ残っている間、ループは継続します。 これにより、次のようなケースが正しく処理されます。`a`そして`c`異なる三進数の長さを持っています。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a, c = map(int, input().split())

    b = 0
    power = 1

    while a > 0 or c > 0:
        da = a % 3
        dc = c % 3

        db = (dc - da + 3) % 3

        b += db * power

        a //= 3
        c //= 3
        power *= 3

    print(b)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("14 34\n") == "50\n", "sample 1"

# minimum values
assert run("0 0\n") == "0\n", "both zero"

# modulo wraparound
assert run("2 0\n") == "1\n", "requires modulo subtraction"

# different ternary lengths
assert run("0 5\n") == "5\n", "remaining digits must be processed"

# large values
assert run("1000000000 1000000000\n") == "0\n", "a tor 0 = a"

# carry-like situation should not exist
assert run("8 0\n") == "4\n", "independent ternary digits"
