 ## 解決策
 ## 問題の理解

 一定数の溝が下から上に配置された斜面が与えられます。 各ボールはある溝に投げ込まれ、その後、決定的な規則に従います。ボールは開始溝を占有しようとしますが、その溝がすでに埋まっている場合は、最初の空の溝が見つかるまで下に滑り続けます。 一番下の溝よりも下に到達すると、斜面から完全に外れてしまいます。 

m 個のボールはそれぞれ独立して投げられ、ボールごとに 1 から n までの開始溝を選択します。 したがって、完全な「戦略」は m 個の開始位置のシーケンスです。 後のボールはすでに占有されている溝を認識するため、シーケンスが異なると、特にスペースを見つけられずに落ちるボールの数が異なる最終結果につながる可能性があります。 

課題は、長さ m の一連の投球によって正確に k 個のボールが斜面から落ちる回数を数えることです。 

制約は非常に厳しいので、入力が非常に小さい場合でも、すべての n^m シーケンスをブルート フォースすることは不可能です。 n = 500 および m = 1000 であっても、占有構成の状態空間だけでも膨大であることを意味します。 どのようなソリューションでもシーケンスの明示的なシミュレーションを避け、代わりに最終的な占有率がどのように変化するかについての組み合わせの解釈に依存する必要があります。 

微妙な問題は、このプロセスがボールのアイデンティティではなく、各溝内のフィルの相対的な順序のみに依存していることです。 ただし、シーケンスは順序付けされているため、同じ占有進化を生成するスローの異なる順列は依然として別々にカウントされるため、多重性を忘れると単純な組み合わせ論が簡単に過少カウントまたは過大カウントされます。 

素朴な推論を打ち破ることが多いエッジ ケースの 1 つは、すべてのボールが溝 1 に投げ込まれる場合です。この場合、最初の min(n, m) の充填位置のみが占有され、残りは落ちます。 この極端な点はすべての失敗を集中させており、「それぞれのグルーブが独立して動作する」が誤りであることを示しています。 

## アプローチ

 直接シミュレーションのアプローチでは、m 個のボールすべてを反復処理し、「次の空の溝に落ちる」プロセスを動的にモデル化しようとします。 各ボールについて、空のスロットを見つけるか、ボールが落ちると判断するまで、選択した溝から下方向にスキャンします。 占有配列を維持したとしても、各挿入のコストは O(n) となり、シーケンスごとに O(mn) が得られます。 n^m 個のシーケンスがあるため、これはまったく実行不可能です。 

シーケンスの列挙を放棄し、代わりに 1 つのプロセスのみをシミュレートしようとしても、指定された数の落下につながる可能性のあるすべてのシーケンスをカウントする必要があります。 重要な問題は、進化がグルーブの選択順序ではなく、各グルーブがターゲットにされる回数のみに依存することですが、これをクリーンなカウント モデルに変換することは明らかではありません。 

重要な観察は、視点を逆転させることです。 ボールが下に落ちると考えるのではなく、それぞれの溝をボールを積み重ねて受け入れる容器と考えることができます。 溝には複数のボールを入れることができますが、それはオーバーフローによって余分なボールが下の溝に押し込まれるまでに限られます。 最終的に、すべてのボールは n 個の溝の 1 つを占めるか、システムの外側で終わるオーバーフロー チェーンの一部になります。 

この構造は、「キャリーオーバー」メカニズムを使用して m 個のボールを n 個の順序付けされたバケットに分配するのと同等であり、所定の数の占有スロットを生成する挿入のシーケンスをカウントすることに密接に関連しています。 最終的な構成は、n 個の溝 (m - k) をどれだけのボールがうまく占有するかによってのみ決まります。 したがって、問題は、n 個の溝の中で正確に n-k 個の配置が成功し、残りはオーバーフローで占められるシーケンスをカウントすることに帰着します。 

このタイプのプロセスは、「効果的な配置」に関する動的プログラミングでは古典的であり、底部を越えてオー​​バーフローを引き起こした回数を維持しながら、埋められた溝の数とすでに処理されたボールの数を追跡します。

私たちは、処理されたボールの数と占有された溝の数に対する DP を定義し、新しいボールが場所を見つけるか、最終的に成功または失敗につながる下向きのカスケードをトリガーするかを反映する移行を行います。 挿入ごとに占有率が増加するか、完全なシフトが発生するため、占有されたグルーブの数のみが重要であり、グルーブの ID は問題ではないという事実を利用してトランジションを圧縮できます。 

これにより、多項式時間 DP 解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^m) | O(n) | 遅すぎる |
 | DP オーバーステート (ボール × 充填溝) | O(nm) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ボールのプレフィックスを処理した後、現在占有されている溝の数の観点からプロセスを解釈します。 

新しいボールはそれぞれ、その下向きの経路のどこかに空のスロットが見つかった場合に占有溝の数を 1 つ増やすか、最終的にボールの落下に対応するオーバーフロー イベントに寄与します。 

dp[i][j] が i 個のボールを処理した後の、j 個のボールがうまく溝を占めるようになった方法の数、つまり i - j 個のボールがこれまでに脱落したことを意味する DP テーブルを維持します。 

また、ボールが投げられるとき、開始溝の n 個の選択肢があるが、それらの選択肢のうち (n - current_occupied) 個だけが最終的に新しい空の溝に着地し、残りの選択肢はカスケードを引き起こし、構造がすでに十分に満たされている場合には最終的に失敗につながるという事実も利用します。 

1. dp[0][0] = 1 を初期化します。ボールがゼロの場合、占有溝も落下もゼロになるためです。 
2. ボールを 0 から m - 1 まで繰り返し、これまでに成功した配置の可能な数ごとに DP 状態を更新します。 
3. 状態 dp[i][j] について、すでに落ちたボールの数として k = i - j を計算します。 
4. 次のボールを処理するときは、2 つのケースを考慮します。 ボールが新しい溝にうまく収まって j が 1 増えるか、ボールが落ちて k が 1 増えるかのどちらかです。 
5. ボールが溝をうまく占有する方法の数は、まだ空いている溝の数 (n - j) によって決まります。 可能な開始位置は n 個あるため、成功につながる選択肢の数は n - j に比例し、失敗した選択肢は最終的に下にオーバーフローする残りの j + k 個の位置に対応します。 
6. これらの重みを組み合わせ遷移乗数として使用します。dp[i+1][j+1] は成功した配置からの寄与を受け取り、dp[i+1][j] は失敗からの寄与を受け取ります。 
7. すべての m 個のボールを処理した後、正確に k 個のボールが落ちているはずなので、答えは dp[m][m - k] になります。 

なぜ効果があるのか:

 不変条件は、i 個のボールを処理した後、dp[i][j] が、順序に関係なく、誘導されたプロセスで正確に j 回の配置が成功した長さ i のすべてのシーケンスを正しくカウントすることです。これは、すべてのシーケンスが占有溝の展開によって一意に分類されるためです。 各トランジションは、次のボールの考えられるすべての選択肢を、新しい占有溝を作成するものとそうでないものという、素のセットに分割します。 すべての開始グルーブは決定的に 1 つの結果 (成功またはオーバーフロー) につながるため、DP はすべてのシーケンスを重複や省略なしに正確に 1 回説明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())

        # dp[j]: ways after processing current i balls with j successful placements
        dp = [0] * (n + 1)
        dp[0] = 1

        for _ in range(m):
            ndp = [0] * (n + 1)
            for j in range(n + 1):
                if dp[j] == 0:
                    continue

                occupied = j
                # success: place into a new groove
                if occupied < n:
                    ndp[j + 1] = (ndp[j + 1] + dp[j] * (n - occupied)) % MOD

                # failure: fall out
                ndp[j] = (ndp[j] + dp[j] * (occupied + (_ - j))) % MOD

            dp = ndp

        print(dp[n - k] % MOD)

if __name__ == "__main__":
    solve()
```このコードは、正常に充填された溝の数に対してローリング DP を実装します。 状態 dp[j] は、現在のボール数を処理した後に正確に j 個の溝が占有される方法が何通りあるかを表します。 新しいボールごとに、トランジションを分割して占有率を増やすか、オーバーフローのために占有率を変更しないようにします。 

(n - 占有) という用語は、最終的に新しい空のスロットが埋まるまでに、開始グルーブの選択肢がいくつあるかを表します。 補数はオーバーフロー動作に寄与します。 ローリング配列により、メモリは確実に O(n) に留まります。 

実装上の微妙な問題は、遷移が前の層からのみ計算されるようにすることです。 別の ndp を使用すると、同じ反復内の状態間の汚染が回避されます。 

## 実用的な例

 n = 3、m = 2、k = 0 という小さなケースを考えてみましょう。ボールが落ちないすべてのシーケンスが必要です。つまり、両方のボールが最終的に溝を占めることになります。 

各ボールの後に dp[j] を追跡します。 

| ステップ | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | 0 |
 | アフターボール 1 | 0 | 3 | 0 |
 | アフターボール2 | 0 | 0 | 6 |

 最終的な答えは dp[2] = 6 です。これは、両方のボールが別々の溝を占め、オーバーフローが発生しないすべてのシーケンスに対応します。 

ここで、n = 2、m = 2、k = 1 を考えます。ちょうど 1 つのボールが落ちます。 

| ステップ | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | 0 |
 | アフターボール 1 | 0 | 2 | 0 |
 | アフターボール2 | 2 | 0 | 0 |

 dp[1] = 2 を最終的な答えとして読み取ります。 

これらのトレースは、ID ではなく純粋にカウントを通じて占有率がどのように変化するかを示しており、DP がすべての有効なシーケンスを正しく圧縮していることを確認しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは k = m の場合で、これはすべてのボールが落ちることを意味します。 この場合、溝が埋められることはありません。これは、すべての最初の選択が、完全な占有の伝播により最終的に最後の溝の下に達する場合にのみ発生します。 DP は、占有された溝がゼロを超えない状態のみをカウントするため、これを自然に処理します。 

もう 1 つのエッジ ケースは、k = 0 および m = n の場合です。 ここでは、すべてのボールが新しい溝を埋める必要があり、開始位置の繰り返しが成功した配置に解決される必要があります。 DP は詰め物の順列を数えることに帰着しますが、これは n! と一致します。 遷移ウェイトから現れる構造。 

3 番目のエッジ ケースは、n = 1 の場合です。すべてのボールは唯一の溝を満たすか、溝が満たされた直後に落下します。 DP は単純なシーケンスに崩壊し、正確に 1 つの配置が成功する可能性があり、残りのすべてのボールが k に寄与します。 最初の塗りつぶしの後、成功した選択の数がゼロになるため、反復ではこれを正しく捉えています。
