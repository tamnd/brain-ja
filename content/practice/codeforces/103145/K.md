 ## 解決策
 ## 問題の理解

 各エッジが 2 つの都市間の道路を表し、各道路が強度値を持つ重み付き無向グラフが与えられます。 グローバル攻撃パラメータ$x$強度が厳密に以下の道路をすべて削除します。$x$。 この除去後、少なくとも強度のあるエッジのみが除去されます$x$残りのグラフで接続性を考慮します。 

各クエリは、そのような攻撃の後でも接続されている都市のペアの数を尋ねます。 ペア$(u, v)$強度が少なくともクエリ値であるエッジのみを使用するパスがそれらの間に存在する場合にカウントされます。これは、パスが破壊プロセスを経ても存続することを意味します。 

したがって、出力は単純な接続チェックではなく、動的にフィルター処理されたグラフ内の到達可能なペアのグローバル数です。 

この制約により、クエリごとの接続の再計算が直ちに除外されます。 と$n$まで$10^5$、$m$そして$Q$まで$2 \cdot 10^5$、および最大 10 個のテスト ケースの場合、グラフを再構築したり、クエリごとに BFS または DFS を実行したりするアプローチでは、おおよその結果が得られます。$O(Q \cdot (n + m))$、これは実現可能な限界をはるかに超えています。 

すべてのエッジの強度が小さいにもかかわらず、クエリが大きい場合、微妙なエッジ ケースが発生します。 その場合、グラフは完全に切り離され、答えはすべてのペアでゼロになる必要があります。 逆に、すべてのエッジが大きくクエリが小さい場合、グラフ全体は接続されたままになり、答えは次のようになります。$\frac{n(n-1)}{2}$。 クエリごとにコンポーネントを再計算する単純なソリューションは、小規模なテストには合格する可能性がありますが、時間の複雑さのために失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純明快です: 各クエリに対して$p_i$、少なくとも強度を持つエッジのみからなる部分グラフを構築します$p_i$、DFS または Union-find を実行して連結成分を計算し、次の式を使用して各成分内のペアをカウントします。$s \cdot (s-1) / 2$、 どこ$s$コンポーネントのサイズです。 これは正しいです。無向グラフの接続によりノードが互いに素なコンポーネントに分割され、コンポーネント内のすべてのペアに到達できるからです。 

ただし、クエリごとにグラフを再構築したり接続を最初から再実行すると、ほぼ全体の計算が繰り返されます。$Q$回。 最悪の場合こうなります$O(Q \cdot (n + m))$のオーダーです。$10^{10}$実際の限界をはるかに超えた操作。 

重要な観察は、しきい値を緩和すると接続性が増加するだけであるということです。 強度の高い順にエッジを処理すると、徐々にグラフを構築でき、接続性は単調に進化します。 クエリごとに最初から再計算するのではなく、コンポーネントの増分マージをサポートする動的なユニオン検索構造を維持します。 

エッジを強度の降順で並べ替え、クエリも降順で処理します。 しきい値を大きい値から小さい値に下げるにつれて、アクティブになるエッジが追加され続けます。 各クエリについて、少なくともそのクエリ以上の強度を持つすべてのエッジが追加されると、union-find 構造は必要なグラフを正確に表します。 接続されたペアの合計数を段階的に維持できます。サイズの 2 つのコンポーネントの場合$a$そして$b$マージすると、新しく接続されたペアの数が増加します。$a \cdot b$。 

これにより、繰り返されるグラフの再構築が、償却されたほぼ一定の和集合演算を伴う単一のスイープに変換されます。

 ## アルゴリズムのチュートリアル

 エッジとクエリの両方を、強度としきい値の統一された降順で処理します。 

1. すべてのエッジを強度の降順に並べ替えます。 これにより、エッジを処理するときに、より強力なエッジがすべてすでに考慮されていることが保証されるため、現在の構造は、現在の強度レベルを超えるエッジによって引き起こされるグラフを正確に表します。 
2. 元のインデックスを追跡しながら、クエリをしきい値の降順に並べ替えます。 これにより、後で出力順序を復元しながら、単一パスでクエリに答えることができます。 
3. 各都市がサイズ 1 の独自のコンポーネントとして開始する Disjoint Set Union 構造を初期化します。また、到達可能なペアの数を追跡する変数を初期化します。エッジが存在しないため、最初はゼロです。 
4. 最高のしきい値から最低のしきい値までクエリを繰り返します。 各クエリ値について$p$、それに答える前に、少なくとも次の強度を持つすべてのエッジを挿入します。$p$そしてまだ処理されていません。 
5. サイズの異なる 2 つのコンポーネントの間にエッジを挿入する場合$a$そして$b$、すでに接続されているかどうかを確認します。 そうでない場合は、それらをマージすると、到達可能なペアの数が増加します。$a \cdot b$。 これが機能するのは、マージ後、一方のコンポーネントのすべてのノードが、もう一方のコンポーネントのすべてのノードからアクセス可能になるためです。 
6. 該当するすべてのエッジが追加された後、現在の DSU 状態は、より弱いエッジをすべて削除した後のグラフを正確に表します。$p$。 現在の到達可能なペアの数をこのクエリの答えとして保存します。 
7. すべてのクエリが処理されるまで繰り返し、その後、回答を元の順序で復元します。 

正確さは、各エッジが 1 回だけ考慮され、各結合操作でコンポーネントが永続的にマージされるという事実に依存します。そのため、後のクエリでは、以前のマージを無効にすることなく、しきい値を下方に調整するだけです。 

### なぜ効果があるのか

 スイープ中のどの瞬間でも、DSU は、少なくとも現在の処理しきい値以上の強度を持つすべてのエッジによって形成されたグラフを表します。 これは、エッジを降順に処理することによって維持される不変式です。 無向グラフの接続性は接続されたコンポーネントによって完全にキャプチャされるため、到達可能なすべてのペアは DSU コンポーネント内に存在する必要があります。 

2 つのコンポーネントが結合すると、それらにまたがるすべてのペアが新たに接続され、エッジが追加されるにつれて接続性が高まるため、以前にカウントされたペアが失われることはありません。 したがって、コンポーネント間のペアの累計は、現在のしきい値で到達可能なペアの数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a] * self.size[b] - self.size[b] * (self.size[a] - self.size[b])

def solve():
    T = int(input())
    for _ in range(T):
        n, m, q = map(int, input().split())
        edges = []
        for _ in range(m):
            x, y, k = map(int, input().split())
            edges.append((k, x - 1, y - 1))

        queries = []
        for i in range(q):
            p = int(input())
            queries.append((p, i))

        edges.sort(reverse=True)
        queries.sort(reverse=True)

        dsu = DSU(n)
        ans = [0] * q
        total = 0

        j = 0
        for p, idx in queries:
            while j < m and edges[j][0] >= p:
                k, u, v = edges[j]
                u_root = dsu.find(u)
                v_root = dsu.find(v)
                if u_root != v_root:
                    total += dsu.size[u_root] * dsu.size[v_root]
                    dsu.parent[v_root] = u_root
                    dsu.size[u_root] += dsu.size[v_root]
                j += 1
            ans[idx] = total

        print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```DSU は、エッジがアクティブ化されるときに接続されたコンポーネントを維持するために使用されます。 実装の重要な詳細は、接続を最初から再計算しないことです。 代わりに、コンポーネントをマージし、コンポーネント間のペアの現在までの合計を維持するだけです。 ポインタ$j$各エッジが 1 回処理されることを保証し、ソート後のスイープを線形にします。 

微妙な点は、すべてのエッジを少なくとも強度で処理した後に答えを更新する必要があることです。$p$クエリは包括的なしきい値であるため、以前はそうではありませんでした。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、エッジがまったく存在しない場合です。 DSU はユニオンを実行しないため、すべてのクエリは到達可能なペアを正しく返しません。 たとえば、$n = 5$、$m = 0$、任意の数のクエリはすべてゼロを出力する必要があります。 スイープ ループがエッジをアクティブにすることはなく、合計は変化しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、すべてのクエリがどのエッジの重みよりも大きい場合です。 エッジを降順で処理し、少なくともクエリの強度を持つエッジのみをアクティブ化するため、エッジは含まれません。 DSU は初期状態のままであるため、すべての答えはゼロになります。 

最後のケースは、すべてのエッジがすべてのクエリしきい値を超えている場合です。 その後、最初のクエリが回答される前にすべてのエッジがマージされ、単一の連結コンポーネントが生成されます。 DSU はすべてのペアの寄与を 1 回だけ蓄積し、すべてのクエリが正しく返されます。$n(n-1)/2$、同一またはそれより小さいしきい値で繰り返されたクエリ全体での安定性を示しています。
