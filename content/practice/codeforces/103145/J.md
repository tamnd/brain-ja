 ## 解決策
 ## 問題の理解

 原点と点によって定義される、3 次元空間内の固定線が与えられます。$(A, B, C)$。 この線は回転軸として機能します。 各テストケースについてもポイントを受け取ります$(x, y, z)$そして角度$r$。 概念的に点を回転させます$(x, y, z)$軸の周りに$+r$度、また$-r$度、空間内に 2 つの候補点が生成されます。 

これら 2 つの回転位置のうち、z 座標を比較し、z 座標が大きい点を出力します。 この声明は、同点が発生しないことを保証します。 

中心的な難しさは比較ステップではなく、最大 50,000 のテスト ケースに対して、任意の 3D 軸の周りの回転を効率的かつ正確に計算することです。 各回転は三角関数演算と軸ベクトルの正規化を含む完全な 3D 変換であるため、テスト ケースごとの単純な幾何学シミュレーションでは不十分です。 

制約は、$O(1)$テストケースごとのソリューション。 反復回転、ステップごとの基底ベクトルへの分解、または大量の再計算を伴う行列構築の繰り返しを試みるソリューションは、クエリごとに一定時間を維持する必要があります。そうでない場合、50,000 ケースの上限は高価になりますが、各ケースが非常に安価な場合にのみ管理可能です。 実際には、テスト ケースごとに数十の浮動小数点演算を超えるものは問題ありませんが、ケースごとのループや反復収束を伴うものは安全ではありません。 

軸ベクトルが次の場合に、微妙なエッジ ケースが発生します。$(A,B,C)$は正規化されておらず、テストごとに大きさが異なります。 単位軸を想定したり正規化をスキップしたりする不用意な実装は、不正確な回転を生成します。 もう 1 つの落とし穴は、回転の正規直交基底を構築する場合、または慎重に正規化せずにロドリゲスの公式を使用する場合に、数値が不安定になることです。 

## アプローチ

 ブルートフォース解釈では、3D 回転行列を構築するか、点を軸に平行および垂直な成分に繰り返し分解することで、任意の軸を中心とした回転をシミュレートします。 幾何学的な直観を使用して回転位置を導出することができます。つまり、点を軸上に投影し、その投影を減算し、軸に直交する平面内の垂直成分を回転させてから、点を再構成します。 

このアプローチは原理的には正しいですが、テスト ケースごとに投影を繰り返し計算し、ベクトルを正規化し、直交基底を再構築する必要があるため、単純に実装するとコストが高くなります。 各ステップは定数時間であっても、定数係数が重要になり、さらに重要なことに、正規化と基底構築が繰り返されるため、エラーが発生しやすくなります。 

重要な洞察は、これが任意の軸を中心とした標準的な回転であり、ロドリゲスの回転公式を使用してきれいに表現できるということです。 軸方向を正規化すると、回転は、回転角度の内積、外積、サインとコサインを含む直接の閉じた形式の式になります。 これにより、テスト ケースごとに座標フレームを構築する必要がなくなり、計算が固定のベクトル演算シーケンスに減ります。 

間の比較$+r$そして$-r$見た目よりもシンプルです。 両方の完全な回転を計算する代わりに、両方を計算して直接比較したり、正弦項で対称性を観察したりできますが、式はすでに定数時間であるため、両方の計算は簡単で安全です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ケースごとの単純な幾何学的分解 | 大きな定数係数を持つ O(T) | お(1) | 遅すぎる/壊れやすい |
 | ロドリゲスの回転公式 | O(T) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ロドリゲスの回転公式を使用して、任意の軸を中心にベクトルを回転します。 

1. 軸点を読み取る$(A,B,C)$そしてそれを原点からの方向ベクトルとして解釈します。 治療します$\mathbf{k} = (A,B,C)$回転軸方向として。 原点とこの点が軸線を定義します。 
2. 軸ベクトルを正規化して単位ベクトルを取得します。$\hat{k} = \frac{k}{|k|}$。 ロドリゲスの公式は単位軸を前提としているため、これが必要になります。 正規化しないと、回転の大きさが歪んでしまいます。 
3. 各テスト ケースのポイントを読む$p = (x,y,z)$と角度$r$。 変換する$r$三角関数はラジアンで動作するため、ラジアンに変換されます。 
4. 角度の回転を計算します。$+r$ロドリゲスの公式を使用すると、次のようになります。$$p_{+} = p \cos r + (\hat{k} \times p)\sin r + \hat{k}(\hat{k}\cdot p)(1-\cos r)$$各用語には幾何学的な意味があり、軸に沿った投影は固定され、垂直成分は回転します。 
5. 角度の回転を計算します。$-r$同様に。 すべてを再導出する代わりに、トリガー ID を再利用します。$\cos(-r)=\cos r$、$\sin(-r)=-\sin r$。 これは、外積項のみが符号を変えることを意味します。 
6. の Z 座標を比較します。$p_{+}$そして$p_{-}$。 大きい方の Z 座標を持つ点を出力します。 
7. 条件を満たすのに十分な浮動小数点精度で結果を出力します。$10^{-6}$許容範囲。 

### なぜ効果があるのか

 このアルゴリズムは、単位軸を中心とした 3D の回転が 3 つの直交成分 (軸に平行、回転面内の垂直、直交外積方向) に分解されるという事実に基づいています。 ロドリゲスの公式はこの分解から導出され、距離と角度の両方が保存されます。 両方にまったく同じ変換を適用するため、$+r$そして$-r$、唯一の非対称性は正弦項の符号にあり、軸の周りに 2 つの正確な鏡像位置が得られます。 したがって、それらの Z 座標を比較することは、2 つの有効な剛体回転の中から正しい方向を選択することと同等であり、正確性が保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def cross(ax, ay, az, bx, by, bz):
    return (
        ay * bz - az * by,
        az * bx - ax * bz,
        ax * by - ay * bx
    )

def dot(ax, ay, az, bx, by, bz):
    return ax * bx + ay * by + az * bz

def rotate(px, py, pz, kx, ky, kz, cos_t, sin_t):
    # Rodrigues' rotation formula
    # p*cos + (k x p)*sin + k*(k·p)*(1-cos)
    cx, cy, cz = cross(kx, ky, kz, px, py, pz)
    kd = dot(kx, ky, kz, px, py, pz)

    rx = px * cos_t + cx * sin_t + kx * kd * (1 - cos_t)
    ry = py * cos_t + cy * sin_t + ky * kd * (1 - cos_t)
    rz = pz * cos_t + cz * sin_t + kz * kd * (1 - cos_t)
    return rx, ry, rz

T = int(input())
out = []

# axis direction
Ax, Ay, Az = map(float, input().split())
norm = math.sqrt(Ax * Ax + Ay * Ay + Az * Az)
kx, ky, kz = Ax / norm, Ay / norm, Az / norm

for _ in range(T):
    x, y, z, r = map(float, input().split())
    rad = math.radians(r)
    c = math.cos(rad)
    s = math.sin(rad)

    p1 = rotate(x, y, z, kx, ky, kz, c, s)
    p2 = rotate(x, y, z, kx, ky, kz, c, -s)

    if p1[2] > p2[2]:
        out.append(f"{p1[0]:.10f} {p1[1]:.10f} {p1[2]:.10f}")
    else:
        out.append(f"{p2[0]:.10f} {p2[1]:.10f} {p2[2]:.10f}")

print("\n".join(out))
```この実装は、ロドリゲスの公式を直接翻訳したものです。 軸はすべてのテスト ケースで共有されるため、軸の正規化はグローバルに 1 回計算されます。 外積ヘルパーとドット積ヘルパーは幾何学的演算を分離するので、回転式は読みやすく、エラーが発生しにくくなります。 

実装の微妙な詳細は、両方の回転でコサインを再利用することです。 サイン項のみが符号を変更するため、三角関数の再計算が回避され、2 つの候補間での数値動作の一貫性が保たれます。

 ## 特殊なケース

 主なエッジ ケースは、軸ベクトルがすでに 1 つの座標軸と位置合わせされている場合です。 たとえば、次の場合$(A,B,C) = (1,0,0)$、回転は yz 平面内の単純な平面回転に還元されます。 正規化により生成されるため、アルゴリズムはこれを自然に処理します。$(1,0,0)$、外積は縮退することなく正しく単純化されます。 

もう 1 つのケースは、入力ポイントが軸線上に正確に位置する場合です。 この状況では、垂直成分がゼロであるため、両方の回転で同じ点が生成されます。 比較ステップは無関係になりますが、一意性が保証されているため、Z 座標は引き続き一貫して解決されます。 この式はどちらの場合も同じ結果をもたらします$+r$そして$-r$したがって、どちらの分岐も安全ですが、問題により、このケースでは曖昧さが生じないことが保証されています。 

最後の数値的なエッジケースは、次の場合に発生します。$r$180度に近いです。 ここで、サインはゼロに近く、コサインは -1 に近いため、次のような減算を多用する式は使用できません。$1 - \cos r$安定しますが、依然として浮動小数点のケアが必要です。 ロドリゲスの公式は、座標系の繰り返しの再計算を回避し、有界三角関数を直接使用するため、数値的に安定しています。
