 ## 解決策
 ## 問題の理解

 複数の行が与えられており、各行はスペースで区切られたピンイン音節で書かれた文です。 各音節は中国語の音声を表しており、2 回のキーストロークの双ピン表現に変換する必要があります。 

タイピング システムは、各音節を 2 つの部分に分割することによって機能します。 最初のキーは最初の子音 (または一部のイニシャルの特別なマッピング) を表し、2 番目のキーは音節の最後の部分を表します。 すべての音節は、指定されたマッピング ルールに基づいて正確に 2 つのキーストロークを使用して表現できることが保証されます。 

入力サイズが十分に大きいため、ソリューションは合計で最大 5000 音節を処理する必要があります。これは、O (合計音節) のソリューションが必要であることを意味します。 文字ごとに繰り返し検索または入力をシミュレートしようとするアプローチはまだ成功しますが、前処理を行わずに長いテーブルを音節ごとに繰り返しスキャンするアプローチは、Python では遅すぎる危険性があります。 

主な微妙な点は、音節が固定ルールによって均一に分割されていないことです。 一部の頭文字は「sh」、「ch」、「zh」などの複数文字であり、語尾は「uang」や「iong」などの複数文字の文字列になることもあります。 固定長のプレフィックスまたはサフィックスを前提とする単純なアプローチは、このような場合には機能しません。 もう 1 つのよくある落とし穴は、「shuang」のような音節を誤って分割することです。最初と最後の両方が複数の文字であり、慎重に一致させる必要があります。 

曖昧さの最小限の例は、「shuang」のような音節に現れます。正しい分割は最初の「sh」と最後の「uang」です。 誤って最初の文字のみをイニシャルとして取得すると、最終的な検索が無効になり、マッピングが失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各音節について、接頭辞と接尾辞の間で考えられるすべての分割に分解し、接頭辞が有効な初期マッピングであり、接尾辞が有効な最終マッピングであるかどうかを確認してから、対応する 2 つのキーを出力します。 各音節の長さは最大約 6 であるため、このアプローチは依然として音節ごとに一定の作業ですが、前処理なしで実装すると、検索ごとにマッピング リストを繰り返しスキャンするため、煩雑でエラーが発生しやすくなります。 最悪の場合、各一致に対してリスト検索を使用すると、マッピング テーブルに対して線形スキャンが繰り返されることになり、不必要に遅くなり、推論が困難になります。 

重要な観察は、問題は完全に静的な翻訳タスクであるということです。 各音節は、正確に 1 組のキーに決定的にマッピングされます。 これは、2 つのハッシュ マップ (最終値用とイニシャル用) を事前計算できることを意味します。 これらの辞書が存在すると、各音節は 1 つの分割操作になり、その後 2 つの辞書検索が行われます。 

唯一の本当の難しさは、分割ポイントを正確に決定することです。 複数文字のイニシャルは「sh」、「ch」、「zh」だけであるため、最初にこれらの接頭辞を確認することで、最初の部分を貪欲に解決できます。 それ以外はすべて 1 文字のイニシャルで始まります。 最初が抽出されると、残りは常に最終となり、直接検索できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォーススキャンによる音節ごとのマッピング | O(総音節数 × K) | O(K) | 遅すぎて不必要 |
 | ハッシュマップ + 貪欲な分割 | O(総音節数) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 提供されたテーブルに基づいて、すべての最終文字列を対応する Shuangpin キーにマップする辞書を構築します。 これにより、最終的なものが識別されると、O(1) ルックアップが可能になります。 
2. 頭子音の辞書を作成します。 特殊なケースの「sh」、「ch」、「zh」はそれぞれの一意のキーにマップされますが、他のすべてのイニシャルはシステム定義に従って直接マップされます。 
3. 入力内の各音節について、「zh」、「ch」、または「sh」で始まるかどうかを確認して、その頭文字を決定します。 どれも一致しない場合は、最初の文字をイニシャルとして使用します。 これらのプレフィックスと競合する有効な初期値が他にないため、この貪欲な決定は機能します。 
4. 音節から最初の部分を削除して、最後の部分を抽出します。 
5. 2 つの辞書を使用して頭文字と末尾を個別に変換し、結果の 2 つのキーを連結します。 
6. 変換されたすべての音節を 1 行に出力し、スペースを維持します。 

### なぜ効果があるのか

 正確さは、マッピング システムが制御された方法でプレフィックスの要素を持たないという事実に依存します。 使用可能なイニシャルのセットは、単一の文字、または 3 つの特別な 2 文字のクラスターで構成されます。 これらの特殊なクラスターは有効な 1 文字のイニシャルのプレフィックスではないため、貪欲な検出は安全です。 最初が固定されると、残りの部分文字列はマッピング テーブル内の最後の存在に一意に対応する必要があり、辞書検索が常に成功し、一意の出力が生成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# final mapping table
final_map = {
    "iu": "q", "ei": "w", "": "e", "uan": "r", "ue": "t", "un": "y",
    "sh": "u", "ch": "i", "uo": "o", "ie": "p", "": "a",
    "ong": "s", "iong": "s", "ai": "d",

    "en": "f", "eng": "g", "ang": "h", "an": "j",
    "uai": "k", "ing": "k", "uang": "l", "iang": "l",
    "ou": "z", "ia": "x", "ua": "x",
    "ao": "c", "zh": "v", "ui": "v",
    "in": "b", "iao": "n", "ian": "m"
}

# initial mapping (only special initials differ)
initial_map = {
    "sh": "u",
    "ch": "i",
    "zh": "v"
}

def convert(syllable: str) -> str:
    # determine initial
    if syllable.startswith("zh"):
        ini = "zh"
        rest = syllable[2:]
    elif syllable.startswith("ch"):
        ini = "ch"
        rest = syllable[2:]
    elif syllable.startswith("sh"):
        ini = "sh"
        rest = syllable[2:]
    else:
        ini = syllable[0]
        rest = syllable[1:]

    # initial key
    if ini in initial_map:
        first = initial_map[ini]
    else:
        first = ini

    # final key
    second = final_map[rest]

    return first + second

def solve():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        parts = line.split()
        out = [convert(p) for p in parts]
        print(" ".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは基本的に決定論的なトランスレーターです。 重要な実装の詳細は、単一文字のイニシャルにフォールバックする前に特殊なイニシャルを処理することだけです。 他のすべては辞書検索に帰着し、これによりあらゆる制約の下で実装の高速性と安全性が維持されます。

 ## 特殊なケース

 重要なエッジ ケースは、「sh」、「ch」、または「zh」で始まる音節です。 たとえば、「shuang」を「s」+「huang」として分割しないでください。分割すると「h」が語尾の一部として誤って扱われるためです。 アルゴリズムは最初にこれらのプレフィックスを明示的にチェックするため、「shuang」が最初の「sh」、最後の「uang」になり、有効な検索が生成されます。 

もう 1 つのエッジ ケースは、「iang」や「ian」など、語尾が最初の接頭辞と重複する音節です。 最初の抽出は最終的な検索の前に実行され、分割のあいまいさがなくなるため、これらは安全に処理されます。 

最後に、「a」や「e」などの母音のみの音節は、空の頭文字が正しく処理されるかどうかに依存します。 このような場合、シラブル全体が最後のものとして扱われ、初期マッピングはデフォルトでそれ自体になり、必要な 2 キーストロークの出力形式が維持されます。
