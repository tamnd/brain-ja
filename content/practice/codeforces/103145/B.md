 ## 解決策
 ## 問題の理解

 簡略化されたエニグマ形式の暗号機をシミュレートしています。 マシンは一連の文字を変換しますが、その変換は、キーを押すたびに進化する内部状態の変化に大きく依存します。 

マシンには 3 つの層があります。 最初の層はパッチ ケーブルのような文字交換の固定セットで、何かが起こる前に入力文字をペアで再マップします。 2 番目の層は、一連の回転する置換ディスクです。 各ディスクはアルファベットの固定順列のように動作しますが、その解釈はディスクが回転するにつれて変化します。 信号はディスクのある位置に入り、現在のシフトされた配線を通じてマッピングされ、新しい位置を生成します。 すべてのディスクを通過した後、信号はペアの文字をマッピングする反射板に当たり、逆マッピングを使用して同じディスクを介して逆方向に信号を送り返します。 最後に、パッチ ケーブルを再度適用して出力文字を生成します。 

重要な難点は、キーを押すたびにディスクが回転し、その回転が走行距離計のように伝播することです。最初のディスクが毎回回転し、完全に回転すると次のディスクが回転し、チェーンが上に進みます。 これは、各文字に適用される変換が、すでに処理された文字の数に依存することを意味します。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは、パッチ ケーブルの交換、ディスクの並べ替え、各ディスクの初期回転、およびリフレクターの並べ替えを記述します。 次に、マシンの状態がすべての文字にわたって継続されるように、いくつかのメッセージを順番に処理する必要があります。 

制約は小さく、ディスクは最大 50 枚、メッセージは最大 10 個、各メッセージは 50 未満です。これにより、キャラクター評価の総数は最大でも数千であるため、キャラクターごとのかなり直接的なシミュレーションでも許容できることがすぐにわかります。 ただし、完全な順列を再計算したり、ステップごとに非効率的にキャラクターの動きをシミュレートしたりする単純な実装はまだ合格しますが、回転を正しく処理する際に複雑さのバグが発生する危険性があります。 

最も危険なエッジケースは、回転が前方パスと後方パスの両方に対称的に影響を与えることを忘れることです。 もう 1 つの微妙な問題は、実際には両方の行が一緒にシフトするのに、ディスクの回転がマッピングの片側のみに影響を与えるものとして誤って処理されていることです。これは、順列自体が循環的にインデックス付けされることを意味します。 

ディスク配線が静的であると仮定すると、具体的な障害例が発生します。 

1 枚のディスクで入力:```
A swaps with B
1 disc: ABC...Z but second row reversed
di = 1
```キーを 1 回押すとディスクが回転し、マッピングが変わります。 静的置換の実装では、同じマッピングが繰り返し適用され、周期 1 の繰り返しサイクルが生成されますが、これは正しくありません。 

もう 1 つの失敗例は、キャリー伝播を無視した場合に発生します。 ディスク 1 が 26 回回転すると、ディスク 2 は 1 回回転する必要があります。 これを無視すると、長いメッセージが正しい出力から完全に外れてしまいます。 

## アプローチ

 ブルート フォース シミュレーションでは、各キーの押下が個別に処理され、各ディスクを介した信号の伝播が段階的に明示的にシミュレートされます。 キャラクターごとに、プラグボード スワップを適用し、現在の回転構成を使用してすべてのディスクを前方に歩き、リフレクターを適用してから、逆マッピングを後方に歩き、最後にプラグボードを再度適用します。 キャラクターを処理した後、キャリーの伝播を処理しながら、ディスクの回転状態を 1 つずつ更新します。 

このアプローチは、マシン定義を正確に反映するため、正しいです。 ただし、非効率的に実装すると、回転順列の再構築が繰り返されることがボトルネックになります。 シフトされた行を再計算したり、オンザフライでマッピングを再構築した場合、各ディスク トランジションのコストは O(26) となり、O(Q * L * n * 26) になります。これは問題ありませんが、不必要なオーバーヘッドになります。 

重要な観察は、各ディスクの動作が 26 を法とする回転にのみ依存するということです。完全な文字列をシミュレートしたり、配列を物理的に回転したりする必要はまったくありません。 代わりに、各ディスクは、循環オフセットと組み合わせた固定順列としてモデル化できます。 これにより、すべてのディスクが、入力位置とシフト状態によってインデックス付けされた定数時間ルックアップ テーブルに変わります。 前方マッピングと後方マッピングは、26 シフトすべてに対して事前に計算できます。 

これが完了すると、マシン全体が決定論的ステート マシンになり、各文字のコストは O(n) になり、キャリー伝播によりキー押下ごとの状態更新のコストは O(n) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再計算による直接シミュレーション | O(合計 * n * 26) | O(n * 26) | 受け入れられたが重い |
 | 事前計算されたシフト テーブル | O(合計 * n) | O(n * 26) | 承認済み |

 ここで、total はすべてのクエリの合計文字数です。 

## アルゴリズムのチュートリアル

 各ディスクを前処理して、考えられるすべての回転状態が順方向と逆方向の両方の 26 文字の順列として明示的に表現されるようにします。 これにより、実行時に文字列の回転をシミュレートする必要がなくなります。 

## アルゴリズムのチュートリアル

1. A から Z までのすべての文字をインデックス 0 から 25 に変換します。これにより、すべての変換を文字列操作ではなく配列インデックスとして表現できるようになります。これは速度と明瞭さに不可欠です。 
2. プラグボード スワップを読み取り、サイズ 26 の直接マッピング配列を構築します。この配列では、各文字がそのパートナー、または未変更の場合はそれ自体にマッピングされます。 これにより、一定時間の入力および終了変換が保証されます。 
3. 各ディスクについて、指定された文字列を順列の最初の 2 行目として解釈します。 最初の行は暗黙的に ID の順序付けになります。 これから、シフト 0 の入力位置から出力位置へマッピングする基本順列を構築します。 
4. 各ディスクおよび 0 ～ 25 の可能な回転状態ごとに、順方向マッピングと逆方向マッピングを事前計算します。 順方向マッピングは、信号が左側から入ったときにどこに行くかを記述し、逆マッピングは、反射後の逆方向の通過を記述します。 回転するとラベルの再設定だけでなく、両方の行の配置が変更されるため、この手順は非常に重要です。 
5. ディスク i が 26 を法として回転した回数を表す配列shift[i] を維持します。最初に、これは入力 di 値によって与えられます。 
6. 各メッセージの各文字に、完全な暗号化パスを適用します。 まずプラグボード マッピングを適用します。 次に、現在のシフト状態と事前計算された順方向テーブルを使用して、ディスクを介して順方向に伝播します。 次に、リフレクター マッピングを適用します。 次に、逆順序で逆テーブルを使用してディスクを逆方向に伝播します。 最後にプラグボードを再度適用して出力文字を取得します。 
7. 文字を処理した後、回転状態を更新します。 シフト[0]をインクリメントします。 26 になったら 0 にリセットし、shift[1] までキャリーを続け、キャリーがなくなるまで続けます。 これは、回転ディスクの走行距離計の動作をモデル化します。 

重要な不変条件は、各ステップで、shift[i] がディスク i の総回転数を 26 を法として正しく表し、事前計算されたテーブルがその回転状態によって引き起こされる正確な順列を正しくエンコードしていることです。 すべての変換は (ディスク インデックス、シフト状態、方向) のみに依存するため、シミュレーションで情報が失われたり、実際のマシンの状態からずれたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_tables(wiring):
    fwd = [[0]*26 for _ in range(26)]
    inv = [[0]*26 for _ in range(26)]

    base = list(wiring)

    for s in range(26):
        for i in range(26):
            # forward: input position i maps via shifted wiring
            j = (i + s) % 26
            c = base[j]
            out = (ord(c) - 65 - s) % 26
            fwd[s][i] = out

        for i in range(26):
            inv[s][fwd[s][i]] = i

    return fwd, inv

def apply_plug(x, plug):
    return plug[x]

def main():
    T = int(input())
    for _ in range(T):
        p = int(input())
        plug = list(range(26))

        for _ in range(p):
            a, b = input().strip()
            a = ord(a) - 65
            b = ord(b) - 65
            plug[a] = b
            plug[b] = a

        D = int(input())
        discs = []
        for _ in range(D):
            wiring = input().strip()
            discs.append(wiring)

        shift = list(map(int, input().split()))

        reflector = input().strip()
        ref = [ord(c) - 65 for c in reflector]

        fwd = []
        inv = []

        for d in discs:
            f, i = build_tables(d)
            fwd.append(f)
            inv.append(i)

        Q = int(input())

        for _ in range(Q):
            msg = input().strip()
            out = []

            for ch in msg:
                x = ord(ch) - 65

                x = plug[x]

                # forward
                for i in range(D):
                    x = fwd[i][shift[i]][x]

                # reflector
                x = ref[x]

                # backward
                for i in range(D-1, -1, -1):
                    x = inv[i][shift[i]][x]

                x = plug[x]
                out.append(chr(x + 65))

                # rotate
                carry = 1
                for i in range(D):
                    if carry == 0:
                        break
                    shift[i] += carry
                    if shift[i] == 26:
                        shift[i] = 0
                        carry = 1
                    else:
                        carry = 0

            print("".join(out))

if __name__ == "__main__":
    main()
```コードは、すべての変換を 0 ～ 25 の整数演算に変換することから始まります。プラグボードは、文字ごとに 2 回適用される直接配列マッピングです。 各ディスクは、回転状態によってインデックスが付けられた完全なルックアップ テーブルに拡張されるため、ランタイム シミュレーションではシフトされた文字列を再構築する必要がありません。 

前方パスと後方パスは単純なテーブル検索です。 リフレクターは固定のインボリューションであり、プロセスの途中でキャラクターごとに 1 回適用されます。 最後の回転ロジックはキャリー伝播を慎重に実装し、下位のディスクが 26 の完全なサイクルを完了した場合にのみ上位のディスクが回転するようにします。 

実装の微妙な詳細は、ディスクの回転が順方向マッピングと逆方向マッピングの両方に等しく影響することです。そのため、fwd テーブルと inv テーブルの両方が同じシフト インデックスに依存します。 もう 1 つの重要な点は、シフトの更新は各文字の処理前ではなく処理後に行われることです。これは、キーを押すとすぐに最初のディスクが回転するというステートメントと一致します。

| キャラクター | 前にシフト | disc0 の後にシフト | disc1 にキャリー |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ディスクがちょうど 26 回転に達したときです。 その瞬間、ゼロにリセットされ、キャリーがトリガーされます。 実装では、インクリメント直後に 26 との等価性をチェックすることでこれを処理し、中間の無効な状態が遷移で使用されないようにします。 

もう 1 つのエッジ ケースは、複数のクエリにわたってメッセージが順次処理されることです。 マシンの状態はクエリ間でリセットされないため、シフトは蓄積され続けます。 このアルゴリズムは、すべてのメッセージにわたって単一のグローバル シフト配列を維持することでこれを維持します。 

最後の微妙なケースは、対称プラグボード スワップです。 スワップはインボリューションであるため、プラグボードを 2 回適用すると、元の文字空間の一貫性が復元されます。 実装では、マシンに入る前と出た後の両方にそれが適用され、暗号設計に必要な可逆性が維持されます。
