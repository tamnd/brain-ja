 ## 解決策
 ## 問題の理解

 テスト ケースごとにツリーが与えられ、削除する頂点の任意のサブセットを選択します。 ツリーからノードを削除しているだけなので、これらの頂点を削除した後も、残りの頂点は依然としてフォレストを形成します。 

残りのグラフにおいて、残りのすべての頂点が残りの頂点の中に少なくとも 1 つの隣接頂点をまだ持っている場合、削除は有効であると呼ばれます。 言い換えれば、削除後、誘導されたサブグラフには孤立した頂点は残りません。 

したがって、残りのセットがその残りのセット内ですべての頂点が少なくとも 1 つの次数を持つ部分グラフを誘導するように、頂点のサブセットを数えています。 

入力は複数のテスト ケースで構成され、それぞれが最大 100,000 個のノードを持つツリーを提供し、すべてのテスト ケースのノードの総数は 1000,000 に達する可能性があります。各テスト ケースの出力は、有効な削除セットの数を 998244353 で割ったものになります。 

この制約により、頂点のサブセットに対する指数列挙は直ちに除外されます。 100,000 個の頂点を持つツリーはすでに 2^n 個の可能な削除セットを暗示しているため、テスト ケースごとにすべての解が線形またはほぼ線形である必要があり、通常は O(n) または O(n log n) です。 O(n sqrt n) であっても、スケール的には遅すぎます。 

残りのセットが非常に少なくなった場合、微妙なエッジケースが現れます。 たとえば、頂点を 1 つだけ残すと、その頂点の次数は 0 になるため、そのような構成は無効になります。 一方、頂点をゼロのままにすることは、条件が空に満たされるため、常に有効です。 

もう 1 つのコーナーケースは、星型のツリーです。 リーフのみを保持しようとすると、各リーフが分離されるため、ローカルに独立しているように見えても、そのような構成は除外する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、頂点のすべてのサブセットを試し、誘導サブグラフを構築し、残りの頂点の次数が 0 かどうかを確認します。 これには、各サブセットのすべてのエッジをスキャンする必要があり、最悪の場合、実行可能な制限をはるかに超えるおよそ O(n · 2^n) の操作が必要になります。 

重要な構造上の観察は、有効性が完全にローカルであるということです。残りのセット内の頂点は、その近傍の頂点の少なくとも 1 つが残りのセットにも含まれているかどうかのみを気にします。 これはエッジに沿った依存関係を示唆しており、これはまさにツリー動的プログラミングがうまく捉えているものです。 

問題は、制約が単純なサブツリー プロパティではないことです。 ノードが有効かどうかは、選択された隣接ノードが少なくとも 1 つあるかどうかによって決まります。これは、ルート化されたツリー内のその親または子の 1 つである可能性があります。 これにより、親状態を通じて兄弟サブツリー間の結合が作成されます。 

これを処理する標準的な方法は、ツリーをルート化し、各ノードが残りのセットで選択されているかどうか、およびその妥当性がどのように満たされるかを追跡する DP を実行することです。 ノードを選択するときは、その親が選択されているか、少なくとも 1 つの子が選択されている必要があります。 これにより、「少なくとも 1 つの子」制約が導入され、DP 遷移内の合計マイナス不良補数トリックを使用して処理できます。 

その結果、各ノードが 2 種類のサブツリー寄与を集約する線形 DP が得られます。つまり、ノードが選択されない構成と、選択されて隣接要件を満たす構成です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(n · 2^n) | O(n) | 遅すぎる |
 | 選択制約のあるツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 便宜上、ツリーを任意のノード (ノード 1) にルートします。ノードごとに、最終的に残ったセットでその親が選択されているかどうかに応じて DP 値を計算します。 

DP 状態は、ノードが残りのセットに含まれるかどうか、およびサブツリーと親コンテキストを考慮して「内部的に有効」であるかどうかを区別する方法で定義します。 

### ステップ

1. ノード 1 でツリーをルートし、親子の方向を修正します。 
2. 各ノード u と親状態 p に対して、u が残りのセットに含まれないウェイの数として dp[u][p][0] を定義します。 削除されたノードはそれ自体に制約を課さないため、これは常に有効です。 
3. 各ノード u と親状態 p について、dp[u][p][1] を、u が残りのセットに含まれ、残りのセットに少なくとも 1 つの近傍が含まれるという条件を満たすウェイの数として定義します。 
4. dp[u][p][0] を計算するとき、u が選択されていないため、各子 v が親状態 p を使用して独立して処理されることに注意してください。 有効な構成の合計数は、各子の有効な構成の合計を子に掛けた積です。 
5. dp[u][p][1] を計算するとき、u が選択されている状態の子を考慮するため、すべての子 v について親状態は 1 になります。 
6. 各子供について次のようにします。 

T_v は、親が選択されている場合のサブツリー v 内の有効な構成の総数であり、S_v は、v が選択されていない場合の構成の数です。 
7. p = 1 の場合、その親が選択されているため、u はすでに満たされています。 したがって、dp[u][1][1] は単にすべての子の T_v の積です。 
8. p = 0 の場合、u は少なくとも 1 つの子が選択されることで満たされる必要があります。 まず、子に対する制約のない積の合計を計算し、次に、すべての子が選択されていない無効なケースを減算します。 これにより、 dp[u][0][1] = product(T_v) − product(S_v) が得られます。 
9. すべてのノードの DP を計算すると、ルートには親がないため、答えは dp[1][0][0] + dp[1][0][1] になります。 

### なぜ効果があるのか

 不変条件は、p = 1 の場合にのみ u の親が選択され、すべての制約がローカルの親子相互作用を使用してのみ適用されるという仮定の下で、 dp[u][p] が u をルートとするサブツリーのすべての有効な構成を正しくカウントすることです。 選択されたすべての頂点が選択された隣接ノードを持たなければならないという唯一のグローバル制約は、選択された各ノードがその親または少なくとも 1 つの子のいずれかによってサポートされることを保証することによって完全に適用されます。 この親子関係ではすべてのエッジが 1 回だけ考慮されるため、無効な構成がすり抜けたり、二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    if n == 1:
        print(1)
        return

    parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp0 = [[1, 0] for _ in range(n + 1)]
    dp1 = [[1, 0] for _ in range(n + 1)]

    for u in reversed(order):
        children = [v for v in g[u] if v != parent[u]]

        # p = 0
        prod_total = 1
        prod_empty = 1
        for v in children:
            prod_total = prod_total * (dp0[v][0] + dp0[v][1]) % MOD
            prod_empty = prod_empty * dp0[v][0] % MOD
        dp0[u][0] = prod_total
        dp0[u][1] = (prod_total - prod_empty) % MOD

        # p = 1
        prod_total = 1
        prod_empty = 1
        for v in children:
            prod_total = prod_total * (dp1[v][0] + dp1[v][1]) % MOD
            prod_empty = prod_empty * dp1[v][0] % MOD
        dp1[u][0] = prod_total
        dp1[u][1] = (prod_total - prod_empty) % MOD

    ans = (dp0[1][0] + dp0[1][1]) % MOD
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装は、テスト全体で入力サイズが 100 万ノードに達する可能性があるため、再帰オーバーヘッドを回避するためにツリーをルート化し、親配列を構築することから始まります。 

2 つの DP テーブルを保存します。 dp0[u]はuの親が選択されていない場合に対応し、dp1[u]はuの親が選択されている場合に対応します。 各エントリには 2 つの値があります。選択されていない u の場合はインデックス 0、有効性が強制されて選択された u の場合はインデックス 1 です。 

重要な移行は、子に対する積です。 親の状態が固定されるとサブツリーは互いに素になるため、ノードごとに子の寄与を個別に集計します。 減算ステップでは、親が選択されていない場合に「少なくとも 1 つの子が選択されている」という条件が適用されます。 

値を 998244353 未満に制限するために、乗算のたびにモジュロ演算が適用されます。 

## 実用的な例

 ### 例 1

 単純なパス 1 - 2 - 3 を考えてみましょう。 

ルートは 1 です。 

ノード 3 (葉) の場合、dp 値は単純です。親が選択されている場合は、自由に選択することも選択しないこともできますが、潜在的な親サポートがあるため、選択は常に有効です。 親が選択されていない場合、3 を選択すると子が必要になりますが、子は存在しないため、このケースは無効です。 

ノード 2 の場合、ノード 3 からの結果が集約され、2 が選択されているかどうか、および親または子からのサポートがあるかどうかに応じてそれらが結合されます。 

| ノード | p (親が選択されています) | dp[u][p][0] | dp[u][p][1] |
 | --- | --- | --- | --- |
 | 3 | 0 | 1 | 0 |
 | 3 | 1 | 1 | 1 |

 ノード 2 の場合、この組み合わせにより、競合する方法でノードが選択されていないか、少なくとも 1 つの隣接関係が存在する有効な構成が得られます。 

これにより、ノード 1 のみを選択する、またはノード 3 のみを選択するなどの分離された選択が除外されることが確認されます。 

### 例 2

 中心 1 が 2、3、4 に接続されている星を考えてみましょう。 

葉 2、3、4 だけを選択しようとすると、それぞれの葉が孤立してしまうため、これを除外する必要があります。 中心を選択せず​​にリーフを選択すると、減算される「悪い」サブセットに寄与するため、DP はこれを強制します。 

| 構成 | 有効性 |
 | --- | --- |
 | {2,3,4} | 無効 |
 | {1,2} | 有効 |
 | {1,2,3,4} | 有効 |
 | {} | 有効 |

 DP は、選択されたすべての頂点に少なくとも 1 つの選択された隣接点がある構成を正しく保持します。

 ## 特殊なケース

 単一ノード ツリーは、ロジックにとって最もクリーンなストレス ポイントです。 唯一の有効な構成は、条件を空のまま満たす空のグラフを残してノードを削除することです。 空の積が 1 を提供し、「選択されたルート」ケースが無効になるため、DP は正しく 1 を返します。 

星型ツリーでは、中心を持たずに葉を選択する構成は隣接ルールに違反します。 DP は、親のサポートなしでセンターが選択された場合に「すべての子が選択されていない」ケースを明示的に減算し、これらの無効な構成が 1 回だけ削除されるようにします。 

2 ノード ツリーでは、空の残りのセットと完全な残りのセットの両方が有効であり、DP 定式化は正確に 2 を生成する必要があります。遷移では、相互依存関係を過剰にカウントしたり欠落したりすることなく、両方のケースが正しく許可されます。
