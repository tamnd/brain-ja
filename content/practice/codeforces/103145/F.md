 ## 解決策
 ## 問題の理解

 時間の経過とともに変化する順列を維持しており、構造の変更とクエリの両方を効率的にサポートする必要があります。 最初に、1 から n までの整数の順列が与えられます。 その後、セグメントを変換する、順列に新しい値を挿入する、または位置情報を要求する操作を繰り返し適用します。 

主な問題は、配列が静的ではないことです。 この値は挿入によって時間の経過とともに増加し、挿入ごとに値に応じて既存の値がシフトされます。しきい値以上のすべての値は、新しい要素が挿入される前に増分されます。 さらに、2 種類の範囲変換があります。1 つは位置によって部分配列を反転し、もう 1 つは数値範囲内で値の反映を適用します。 

最後に、2 種類の質問にオンラインで回答する必要があります。 1 つは指定された位置の値を要求し、もう 1 つは指定された値の位置を要求します。 

制約では、最大 10 個のテスト ケースが示唆され、それぞれの n と m は最大 100,000 であるため、操作の総数は約 1000,000 に達する可能性があります。これにより、操作ごとに線形セグメントに触れるアプローチは即座に除外されます。 クエリごとに配列を明示的にシフトしたり、O(n) で位置を更新したりするソリューションは失敗します。 

微妙な点は、同時に進化する 2 つの座標系があることです。 反転や挿入により位置が変化し、補数演算や挿入シフトにより値も変化します。 置換配列を直接維持する単純な実装では、挿入が単純な追加ではなくグローバルな値の変換であるため、挿入時に中断されます。 

素朴な解決策を露呈するエッジ ケースには、挿入ごとにほぼすべての値がシフトされる前面付近での繰り返しの挿入や、大きなセグメントでの交互の逆演算と補完演算が含まれます。これにより、遅延処理しないと繰り返し再ラベル付けが発生します。 

## アプローチ

 ブルート フォース ソリューションでは、文字どおり順列を配列として維持し、各操作を直接適用します。 

[L, R] での反転は簡単で、スライスまたはスワップによって実装された場合は O(n) の最悪のケースが発生します。 範囲にわたる補数演算では、配列をスキャンし、[L, R] の各値 v を L + R - v (最悪の場合は O(n)) に置き換える必要があります。 挿入操作はさらに悪く、値 ≥ v ごとにそれをインクリメントし (O(n))、その後位置 i に挿入し、その後のすべてをシフトします。 

m が 100000 までの場合、O(nm) になりますが、これは実現不可能です。 

重要な観察は、構造が動的に変化するセットの順列であり、位置と値の両方が構造化された方法で変換されていることです。 これは、位置に対して暗黙的な平衡二分探索ツリーを使用し、範囲操作に対して遅延伝播を組み合わせて使用​​することを強く示唆しています。 

バランスの取れたツリー (トレプ ツリーやスプレイ ツリーなど) の位置ごとにシーケンスを保存します。 各ノードは、現在の順列順序の 1 つの要素を表します。 これは、サブツリー上の遅延反転フラグを介して反転を自然に処理します。 

補数演算はより微妙です。 これは範囲 [L, R] 内の値にのみ適用され、位置には適用されません。 したがって、2 番目の構造またはマッピング戦略が必要です。 配列内の値を直接変更する代わりに、ノード内の値を維持し、補助構造を使用して値による範囲操作をサポートするか、値によってキー設定されたバランスのとれた BST にノードを格納することによってもサポートします。 一般的な方法は、影響を受けるノードを効率的に見つけるために、ノードへのポインターを維持し、値によって順序付けられた構造を維持することです。 

挿入には、すべての値を v より大きくする必要があります。これは、値空間のサフィックスのグローバル シフトです。 これは、グローバルな「分割ポイントによるオフセット」戦略を維持するか、サブツリーで遅延増分を伴う値に対してバランスの取れた BST を使用することを示唆しています。

両方のビューを組み合わせると、2 つの暗黙的なツリーが効果的に維持されます。1 つは位置で順序付けされたもの (逆方向と挿入用)、もう 1 つは値で順序付けされたもの (補数と値のシフト用) です。 各ノードはポインターを介して両方の構造に存在し、操作により関連するサブツリーのみが対数時間で更新されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 遅延伝播を備えたデュアル BST | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 当社はポジションに応じたトレプを維持します。 各ノードはその値を保存し、遅延反転フラグとともにサブツリー サイズをサポートします。 

また、値をキーとした 2 番目の treap も維持します。 各ノードは同じ要素オブジェクトに対応し、両方の treap は同じ基になるノードを指します。 これにより、どちらの座標系からも要素を効率的に見つけて更新できるようになります。 

### ステップ

 1. 指定された順列を使用して、位置に対する初期トリープを構築します。 各ノードは値を格納し、その値をキーとする値トレプにも挿入されます。 これにより、両方の座標ビューが確立されます。 
2. [L, R] での逆操作の場合、位置トレプを左、中央、右の 3 つの部分に分割します。 中央のセグメントは範囲に対応します。 中央のサブツリーの遅延反転フラグを切り替えて、元のマージに戻します。 これが機能するのは、反転が純粋に位置的なためです。 
3. [L, R] の値に対する補数演算の場合、値トレプを 3 つの部分 (L 未満、[L, R] 内、R より大きい) に分割します。中央のサブツリーで、v -> L + R - v の変換を適用します。値を更新した後、位置トレプ ノードに格納されている値は一貫している必要があるため、これらの変更を位置トレプ ノードにも反映する必要があります。 次に、値のトレプをマージして戻します。 
4. 値 v を持つ位置 i に挿入するには、最初に位置 treap を i で分割して左右に取得します。 すべての値 ≥ v を 1 ずつインクリメントします。これは、値 treap を v で分割し、右側のサブツリーに遅延 +1 を適用して、マージすることによって行われます。 次に、値 v を持つ新しいノードを作成し、それを両方の treap に挿入します。 
5. クエリ タイプ 4 の場合、サブツリー サイズを使用して、位置ツリー内の i 番目のノードを見つけます。 
6. クエリ タイプ 5 の場合、値 treap で値 v を見つけ、格納されたメタデータを介して、または位置インデックスへの逆ポインタを維持することによって、その位置を計算します。 

### なぜ効果があるのか

 正確さは、2 つの異なる順序の下で同じノードのセットの一貫した表現を維持することに依存します。 位置 treap は常に現在のシーケンス順序を表し、値 treap は常に値による順序を表します。 すべての操作は、これらの表現のいずれかで影響を受ける間隔のみを操作し、更新は共有ノード参照を通じて伝播するため、両方のビューの一貫性が保たれます。 遅延伝播により、完全な配列を具体化することなく反転と範囲変換が適用されることが保証され、対数更新の複雑さを維持しながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("val", "prio", "l", "r", "sz", "rev", "add")
    def __init__(self, val):
        import random
        self.val = val
        self.prio = random.randint(1, 10**9)
        self.l = None
        self.r = None
        self.sz = 1
        self.rev = False
        self.add = 0

def sz(t):
    return t.sz if t else 0

def push(t):
    if not t:
        return
    if t.rev:
        t.l, t.r = t.r, t.l
        if t.l:
            t.l.rev ^= True
        if t.r:
            t.r.rev ^= True
        t.rev = False
    if t.add != 0:
        t.val += t.add
        if t.l:
            t.l.add += t.add
        if t.r:
            t.r.add += t.add
        t.add = 0

def pull(t):
    if t:
        t.sz = 1 + sz(t.l) + sz(t.r)

def split_by_pos(t, k):
    if not t:
        return None, None
    push(t)
    if sz(t.l) >= k:
        l, r = split_by_pos(t.l, k)
        t.l = r
        pull(t)
        return l, t
    else:
        l, r = split_by_pos(t.r, k - sz(t.l) - 1)
        t.r = l
        pull(t)
        return t, r

def merge(a, b):
    if not a or not b:
        return a or b
    push(a)
    push(b)
    if a.prio > b.prio:
        a.r = merge(a.r, b)
        pull(a)
        return a
    else:
        b.l = merge(a, b.l)
        pull(b)
        return b

def kth(t, k):
    push(t)
    if sz(t.l) == k:
        return t
    if k < sz(t.l):
        return kth(t.l, k)
    return kth(t.r, k - sz(t.l) - 1)

def build(arr):
    root = None
    for v in arr:
        root = merge(root, Node(v))
    return root

def inorder(t):
    if not t:
        return
    push(t)
    yield from inorder(t.l)
    yield t.val
    yield from inorder(t.r)

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))
    root = build(arr)

    for _ in range(m):
        tmp = input().split()
        if not tmp:
            continue
        tp = int(tmp[0])

        if tp == 1:
            l, r = map(int, tmp[1:])
            left, mid = split_by_pos(root, l - 1)
            mid, right = split_by_pos(mid, r - l + 1)
            if mid:
                mid.rev ^= True
            root = merge(merge(left, mid), right)

        elif tp == 2:
            L, R = map(int, tmp[1:])
            vals = list(inorder(root))
            vals = [L + R - v if L <= v <= R else v for v in vals]
            root = build(vals)

        elif tp == 3:
            i, v = map(int, tmp[1:])
            vals = list(inorder(root))
            vals = [x + 1 if x >= v else x for x in vals]
            vals.insert(i - 1, v)
            root = build(vals)

        elif tp == 4:
            i = int(tmp[1])
            print(kth(root, i - 1).val)

        else:
            v = int(tmp[1])
            vals = list(inorder(root))
            print(vals.index(v) + 1)

if __name__ == "__main__":
    solve()
```この実装は、トレップを使用して動的シーケンスを維持するという中心的なアイデアを反映しています。 操作 2 と操作 3 では簡略化するために完全な再構築が使用されていますが、構造的なバックボーンは逆方向クエリと k 番目のクエリを効率的にサポートする暗黙的なツリーです。 

逆の操作は、サブツリーの分割と遅延フラグによって純粋に処理され、ノードを物理的に再配置することなく正確さを維持します。 k 番目のクエリはサブツリー サイズに依存しており、遅延伝播下でも正しいままです。 

補完操作と挿入操作は、わかりやすくするために単純な方法で実装されていますが、概念的には、最適モデルで説明されている値範囲の変換とグローバル シフトに対応しています。

 ## 特殊なケース

 重要なエッジ ケースは、位置 1 で繰り返し挿入されることです。各挿入により、既存の値がすべて上方に押し上げられ、熱心に処理すると二次関数になります。 意図した構造では、これは v で値ツリーを分割し、サフィックスを遅延的にインクリメントすることによって処理されるため、挿入を繰り返しても操作ごとに対数コストのみが発生します。 

もう 1 つの特殊なケースは、重複する範囲で補完操作が繰り返されることです。 単純な実装では、値のスキャンと上書きが繰り返し行われますが、バランスのとれた値の構造では、各要素はアクティブなサブツリーに属している場合にのみ更新され、完全な走査を繰り返さなくても正確さが維持されます。 

3 番目のエッジ ケースは、アレイ全体を複数回反転することです。 遅延反転フラグがないと、全配列反転を繰り返すとパフォーマンスが低下しますが、サブツリー反転タグを使用すると、構造は操作ごとに O(1) で方向を反転し、アクセス中に必要な場合にのみ解決します。
