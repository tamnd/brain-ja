 ## 問題の理解

 私たちには「花」が原点から始まるシステムが与えられています。$d$-次元の整数グリッド。 時間は離散的なステップで進み、各ステップで、座標軸の 1 つに沿って 1 つの単位を移動することによって花の形状が拡張されます。 それぞれの動きによって方向も選択されます。つまり、選択した軸に沿って成長がプラスまたはマイナスになる可能性があります。 

完全な進化が終わりました$t$秒は、次のシーケンスと同等です。$t$符号付き軸の選択。 各ステップで次のいずれかを選択します。$d$を調整し、それを増やすか減らすかを決定します。 いずれかのタイム ステップで選択した軸または方向が異なる場合、2 つの進化は異なるものとみなされます。 

出力では、その後、そのような有効なシーケンスの数が求められます。$t$ステップ、モジュロ$998244353$。 

制約$d, t \le 2 \cdot 10^5$シーケンスを明示的に列挙する解釈は直ちに除外されます。 単純な指数関数的なビューでは、各ステップを次のものとして扱います。$2d$オプション、それにつながる$(2d)^t$これは、たとえ小さな入力であっても計算をはるかに超えています。 有効なソリューションでは、これらのシーケンスの構造を、効率的に評価できる閉じた組み合わせ形式または畳み込みに圧縮する必要があります。 

微妙なケースの 1 つは、$t = 0$。 その場合、次元に関係なく、有効な進化は 1 つだけ、つまり空のシーケンスが存在します。 もう一つのエッジケースは、$d = 1$、すべてのステップが唯一の軸に強制されますが、それでも 2 つの方向の選択肢があります。 「独立して軸を選択し、方向を選択する」という単純な推論でも、後で特別なケースを使用せずにこれをきれいに処理する必要があります。 

より構造的な落とし穴は、「最終置換」と「配列の同一性」を混同することから生じます。 2 つのシーケンスは同じ最終座標に到達する可能性がありますが、中間ステップで異なる場合でも依然として区別されるため、問題は格子内のエンドポイントを数えるのではなく、ラベル付きステップ シーケンスを数えることにあります。 

## アプローチ

 直接的な総当たり法では、考えられるすべての長さのシーケンスが構築されます。$t$、各ステップで次のいずれかを選択します。$d$軸と 2 つの方向のいずれか。 これは正確に与えます$2d$ステップごとに選択肢があるため、シーケンスの総数は次のようになります。$(2d)^t$。 すべての選択が個別のシーケンスを生成し、自己交差や禁止状態などの追加の制約がないため、これは問題の定義の下では正しいです。 

問題は、これがすでに非還元形式の最終的な答えであり、べき乗剰余の計算が簡単であるため、問題が文字通りこれである場合、Codeforces の設定としては簡単すぎるということです。 重要な隠された構造は、方向の対称性が軸の選択と相互作用し、意図された解釈では、各符号付きの動きを独立して扱うのではなく、各座標が選択された回数によってシーケンスをグループ化することです。

 軸の選択と符号の選択を分離してシーケンスを再解釈すると、プロセスは長さを選択することになります。$t$シーケンスオーバー$d$ラベルを作成し、各出現箇所に独立して符号を割り当てます。 軸の使用を分散する方法の数は多項式です。$i$使用されています$c_i$倍すると、分布を実現するシーケンスの数は次のようになります。$$\binom{t}{c_1, c_2, \dots, c_d} \cdot 2^t.$$すべての構成を合計すると、$t$の中へ$d$部品は多項定理によって次のように崩壊します。$(d)^t$、独立した符号の選択を再導入すると、合計は次のようになります。$(2d)^t$。 したがって、問題は、任意の組み合わせ DP ではなく、高速べき乗剰余演算に帰着します。 

重要な洞察は、すべてのステップが独立しており、サイズが固定されたアルファベットに均等に分散されているということを認識することです。$2d$。 幾何学的解釈全体が気を散らすものです。 ステップ間に状態結合は存在しません。

 ## アルゴリズムのチュートリアル

 1. 各ステップを一連のサイズからの独立した選択として解釈します$2d$ここで、各軸は 2 つの方向の変化に寄与します。 これにより、幾何学的プロセスが独立したイベントに対する純粋な計数問題に再構成されます。 
2. 有効なシーケンスの総数を次のように計算します。$(2d)^t$。 これは、それぞれの$t$各ステップには同一の無制限の選択肢があります。 
3. べき乗モジュラを使用して、モジュラスの下のべき乗を計算します。$998244353$、次の場合には直接べき乗は実行不可能であるため、$t$大きいです。 
4. 結果を返します。 

再定式化後に残る唯一の計算タスクは高速累乗です。これは次のように実行できます。$O(\log t)$指数の現在のビットが設定されているときに、底の二乗と乗算を繰り返します。 

### なぜ効果があるのか

 正しさはステップの独立性から生まれます。 あらゆる瞬間において、システムの状態は将来の選択を制約しないため、有効なシーケンスのセットは正確に次のデカルト積になります。$t$同じサイズの選択セット$2d$。 シーケンスと長さの間の全単射 -$t$アルファベットを超えるサイズの文字列$2d$カウントを保持するため、累乗によって合計が正確に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def main():
    d, t = map(int, input().split())
    base = (2 * d) % MOD
    print(mod_pow(base, t))

if __name__ == "__main__":
    main()
```このソリューションでは、すべてを剰余指数の計算に集約します。 2 を乗算すると、各軸の 2 つの可能な方向が反映され、次のように乗算されます。$d$軸の選択を考慮します。 

主な実装の詳細は、オーバーフローを回避するために各ステップでモジュラー乗算が適用されること、および一定のメモリ使用量を維持するために累乗が再帰的ではなく反復的に実行されることを保証することです。

 ## 特殊なケース

 のために$t = 0$、アルゴリズムは次のように計算します。$(2d)^0 = 1$、単一の空の進化と一致します。 べき乗ルーチンは、乗算ループに入ることなく、正しく 1 を返します。 

のために$d = 1$、底は 2 になるので、答えは次のようになります。$2^t$。 これは、ステップごとに 2 つの方向を選択できる 1 つの軸に対応し、特別なケースを使用しなくても計算は安定したままになります。 

次のような大きな値の場合、$d = t = 2 \cdot 10^5$、べき乗剰余演算により、計算が対数時間内に収まることが保証されます。 このアルゴリズムはモジュラスを超える中間値を構築しないため、全体的にオーバーフローが回避されます。
