 ## 問題の理解

 私たちは、各セルに花が含まれる場合と含まれない場合がある、セルのグリッド上で進化するシステムを与えられています。 時間の経過とともに、2 種類のアクションが適用されます。セルをフラワー セルに変えることができ、2 つのセル間に接続を追加できます。 これらの接続は、グリッド自体の暗黙的な隣接関係に加えて、セル間の追加のエッジのように動作します。 

いつでも、私たちは花の細胞とそれらの間のつながりだけを考慮します。 2 つのフラワー セルは、グリッド隣接または地下接続を介して相互にアクセスできる場合、同じグループに属します。 このような各グループは、そのサイズと内部接続の密度に基づいて「エネルギーコスト」に寄与します。 

グループの場合、次の内容が含まれている場合$f$花の細胞と$c$そのグループ内の花細胞間の有効な接続、その寄与は次のように定義されます。$\max(f - \sqrt{c}, 0)$。 合計エネルギーは、各更新後のすべてのグループのこの値の合計です。 

入力は一連の操作です。 一部の操作は細胞を活性化し、花の細胞に変えます。 他のものは、各接続の少なくとも 1 つのエンドポイントが追加された時点ですでにフラワーであることを保証して、2 つのセル間の接続を追加します。 各操作の後に、現在の総エネルギーを出力する必要があります。 

この制約は、最大でも 100 × 100 のサイズのグリッド上で、最大約 1,000 回の少数の更新を意味します。 このことは、大量のオフライン処理や高度な動的接続などは必要ないことをすでに示唆しています。 ほぼ定数時間の共用体を備えた構造で十分です。 

単純なアプローチでは、グリッドおよびすべての接続上の完全な BFS または DFS を使用して、各クエリの後に接続されているすべてのコンポーネントを再計算します。 それはすでにコストがかかります$O(n^2)$クエリごとにグリッドを走査するだけで、各コンポーネントでもエッジをカウントする必要があるため、合計の作業量はおよそになります。$O(d \cdot n^2)$で許容されます。$n \le 100$ただし、慎重に実装された場合に限ります。 ただし、エッジを正しく再計算し、ノードと接続のすべてのペアを繰り返しスキャンすることは、不必要に繰り返しになります。 

さらに微妙な問題は、エッジのカウント方法に現れます。 よくある間違いは、グリッドの隣接性または地下のエッジを一貫性なくカウントすることです。 もう 1 つは、エッジを 2 倍にカウントするか、非アクティブなセルに接触するエッジを含めることです。 たとえば、アクティブ セルと非アクティブ セルの間に接続が追加された場合、非アクティブ セルがアクティブになるまで現在のコンポーネント構造に影響を与えるべきではありません。 

通常、素朴なソリューションを破壊するエッジケースには、次のようなものがあります。 

すべてのセルが非アクティブで開始され、接続のみが追加された場合、後でセルをアクティブ化すると、すでに追加されているすべての接続を遡って組み込む必要があります。 

同じセルのペア間に複数の接続が存在する場合、それらは独立してカウントされる必要があります。$c$、ステートメントでは重複が許可されているためです。 

コンポーネントに$f = 1$エッジがない場合、式は次のようになります。$1 - 0 = 1$ただし、エッジが追加されると、$c$が大きくなると、平方根の項が支配的になって寄与がゼロになる可能性があるため、正しい浮動小数点処理が重要になります。 

## アプローチ

 この強引なアイデアは、操作のたびに構造全体を再計算することです。 各更新後に、すべてのアクティブ セルに対してグラフ トラバーサルを実行し、グリッド隣接とアンダーグラウンド接続の両方を使用してセルをコンポーネントにグループ化します。 コンポーネントごとにノードの数を数え、すべてのエッジをスキャンして、コンポーネント内に両方のエンドポイントを持つノードの数を計算します。 

毎回正確なグラフが再構築されるため、これは概念的には正しいです。 問題は、すべてのノードとエッジを繰り返しスキャンすることです。 まで$d = 1000$操作と最大$10^4$セル、接続の再構築、エッジ数の再計算を繰り返し行うと、次のような結果が得られます。$10^7$に$10^8$ぎりぎりの運用だが、無駄も多い。 

重要な観察は、接続性は時間の経過とともに増加するということです。 セルは削除されず、エッジが追加されるだけです。 この単調な構造により、素の集合結合構造を使用して、接続されたコンポーネントを段階的に維持できるようになります。 コンポーネントを再計算する代わりに、新しい接続が出現したとき、またはセルのアクティブ化によってアクティブな隣接セルがリンクされたときにのみコンポーネントをマージします。 

各コンポーネントは 2 つの値を維持する必要があります: アクティブなセルの数$f$、および内部エッジの数$c$。 2 つのコンポーネントを結合すると、それらの値を直接結合でき、答えへの寄与をローカルに更新できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにコンポーネントを再計算する |$O(d \cdot n^2)$|$O(n^2)$| 許容できるが不要 |
 | 増分更新を備えた DSU |$O((n^2 + d)\alpha(n))$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セルを素集合和集合構造のノードとして表現します。 各ノードは、現在アクティブであるかどうか (フラワーがあるかどうか) を格納します。 また、コンポーネントごとの値も維持します。$f$そして$c$、およびゼロに初期化されたグローバル回答。 
2. セルがアクティブになったら、そのサイズを設定します$f = 1$とエッジ数$c = 0$。 次に、それを 4 つのグリッド方向のすべてのすでにアクティブな近傍とマージしようとします。 マージが成功するたびに 2 つのコンポーネントが結合され、グローバルな答えが更新されます。 
3. 1 つのエンドポイントが非アクティブであっても、アンダーグラウンド接続ごとに隣接リストに保存します。 操作時に両方のエンドポイントがアクティブな場合は、ただちにそれらのコンポーネントを結合します。 
4. 2 つのコンポーネントをマージする場合は、まずグローバル アンサーから古いコントリビューションを削除します。 次に、結合された値を計算します$f = f_1 + f_2$そして$c = c_1 + c_2 + 1$これは、新しいエッジがマージされたコンポーネントの内部になるためです。 最後に、新しいコントリビューションを追加し直します$\max(f - \sqrt{c}, 0)$。 
5. 各操作の後に、現在のグローバル応答を出力します。 

正確性は、各コンポーネントの寄与を個別に追跡し、コンポーネントが結合するか新しい内部エッジが出現した場合にのみ更新することにかかっています。 

### なぜ効果があるのか

 常に、各フラワー セルは 1 つの DSU コンポーネントに属しており、フラワー セル間の有効な接続はすべて、コンポーネント内か、まだマージされていないコンポーネント間のいずれかにあります。 2 つのコンポーネントをマージするたびに、それらのノード間のすべてのアクティブな接続が内部になるという不変条件が維持されるため、エッジ数とノード数は正確に結合されます。 各コンポーネントのエネルギーはその内部構造のみに依存し、外部エッジには依存しないため、全体的に正確さを維持するには、マージされたコンポーネントのみを更新するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

n, d = map(int, input().split())
grid = [input().strip() for _ in range(n)]

parent = list(range(n * n))
size = [1] * (n * n)
active = [False] * (n * n)

comp_f = [0] * (n * n)
comp_e = [0] * (n * n)

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

answer = 0.0

def add_component(root):
    global answer
    val = comp_f[root] - math.sqrt(comp_e[root])
    if val > 0:
        answer += val

def remove_component(root):
    global answer
    val = comp_f[root] - math.sqrt(comp_e[root])
    if val > 0:
        answer -= val

def union(a, b):
    global answer
    ra, rb = find(a), find(b)
    if ra == rb:
        comp_e[ra] += 1
        return

    remove_component(ra)
    remove_component(rb)

    if size[ra] < size[rb]:
        ra, rb = rb, ra

    parent[rb] = ra
    size[ra] += size[rb]
    comp_f[ra] += comp_f[rb]
    comp_e[ra] += comp_e[rb] + 1

    add_component(ra)

dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

def idx(x, y):
    return x * n + y

for i in range(n):
    for j in range(n):
        if grid[i][j] == '1':
            v = idx(i, j)
            active[v] = True
            comp_f[v] = 1

for i in range(n):
    for j in range(n):
        if active[idx(i, j)]:
            v = idx(i, j)
            for dx, dy in dirs:
                ni, nj = i + dx, j + dy
                if 0 <= ni < n and 0 <= nj < n and active[idx(ni, nj)]:
                    union(v, idx(ni, nj))

edges = [[] for _ in range(n * n)]

for _ in range(d):
    tmp = input().split()
    if tmp[0] == '1':
        x, y = map(int, tmp[1:])
        v = idx(x, y)
        if not active[v]:
            active[v] = True
            comp_f[v] = 1
            for dx, dy in dirs:
                ni, nj = x + dx, y + dy
                if 0 <= ni < n and 0 <= nj < n and active[idx(ni, nj)]:
                    union(v, idx(ni, nj))

            for u in edges[v]:
                if active[u]:
                    union(v, u)

    else:
        x1, y1, x2, y2 = map(int, tmp[1:])
        u, v = idx(x1, y1), idx(x2, y2)
        edges[u].append(v)
        edges[v].append(u)
        if active[u] and active[v]:
            union(u, v)

    print(f"{answer:.10f}")
```DSU は、接続とコンポーネントの統計の両方を維持します。 主要な実装の詳細は、コンポーネントが変更されるたびに、その以前の貢献が更新前に削除され、マージ後に再追加されることです。 これにより、コンポーネントのサイズや構造が変更された場合の二重カウントが防止されます。 

グリッドの隣接関係はアクティブ化中に暗黙的に処理されますが、アンダーグラウンド接続は両方のエンドポイントがアクティブな場合にのみ保存および適用されます。 

## 実用的な例

 小さなケースを考えてみましょう。$2 \times 2$グリッドは 1 つのアクティブなセルから始まり、徐々に接続を増やします。 

1 つのアクティベーションと 1 つの接続を追跡します。 

| ステップ | アクティブセル | コンポーネント | f | c | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | (0,0) | {(0,0)} | 1 | 0 | 1 |
 | 接続 (0,0)-(0,1 非アクティブ) を追加 | 変更なし | {(0,0)} | 1 | 0 | 1 |
 | (0,1) | をアクティブにする {(0,0),(0,1)} | 統合されました | 2 | 1 |$2 - 1 = 1$|

 これは、遅延エッジのアクティブ化がどのように正しく機能するかを示しています。エッジは、両方のエンドポイントがアクティブになった場合にのみ寄与します。 

ここで、複数のエッジが蓄積する、もう少し密度の高い構成を考えてみましょう。 

| ステップ | アクション | f | c | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | A | をアクティブにする 1 | 0 | 1 |
 | 2 | 隣接する B をアクティブにする | 2 | 1 | 1 |
 | 3 | 追加の接続 A-B を追加 | 2 | 2 |$2 - \sqrt{2}$|

 2番目のエッジはすぐに増加します$c$、平方根項はコンポーネントのエネルギーを滑らかに減少させ、エッジ追跡が多重度を正しくカウントする必要がある理由を示しています。

 ## 特殊なケース

 注意が必要なシナリオは、2 番目のエンドポイントがアクティブになる前にエッジが追加される場合です。 たとえば、アクティブなセルと非アクティブなセルの間にエッジが追加されます。 アルゴリズムはこのエッジを保存しますが、すぐには何も行いません。 後で非アクティブなノードがアクティブになると、保存されているすべてのエッジが処理され、その時点で結合が実行されます。 これにより、エッジがコンポーネント内で完全に有効になったときに、エッジが 1 回だけ寄与することが保証されます。 

もう 1 つの特殊なケースは、同じセルのペア間でエッジが繰り返されることです。 各エッジが増加するため、$c$、同じコンポーネント内で繰り返される結合では、構造マージが発生しない場合でもエッジ数をインクリメントする必要があります。 これは、DSU の特別なケースによって処理されます。`find(a) == find(b)`コンポーネントのエッジカウンターを直接インクリメントします。 

最後のエッジケースは次の場合に発生します。$f - \sqrt{c}$マイナスになる。 その場合、コンポーネントの寄与はゼロにクランプされます。 このアルゴリズムは、再計算の前に以前の寄与を削除し、ゼロをまたぐ遷移によって浮動小数点誤差や古い値が蓄積されないようにします。
