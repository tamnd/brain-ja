 ## 解決策
 ## 問題の理解

 都市地図を表す有向グラフが与えられます。各道路には方向と、その方向を逆にすることに関連するコストが含まれています。 市長の目標は、一部の道路の方向を変更して、最終的な有向グラフに有向サイクルが含まれないようにすることです。つまり、有向道路に沿って少なくとも 1 回移動した後に開始交差点に再訪できないようにすることです。 言い換えれば、変更後、グラフは有向の意味でサイクルフリーでなければなりません。これは、すべての頂点に位相順序を割り当てることができるようにすることと同じです。 

各エッジは元の方向のままにすることも、反転することもできますが、エッジを反転すると、指定された重みに等しいコストが発生します。 総反転コストを最小限に抑えながら、結果として得られる有向グラフが非巡回になるように、反転するエッジのセットを選択する必要があります。 さらに、どのエッジが反転されているかを出力する必要があり、たとえその数が最小でなくても、反転されたエッジの有効なセットを出力することができます。 

制約により、私たちは線形または線形に近い動作を強いられます。 最大 100,000 個の頂点と 100,000 個のエッジを使用すると、エッジのすべてのサブセットを調べたり、変更のたびにサイクル構造を再計算したりするソリューションは不可能です。 たとえアルゴリズムであっても、$O(m \log m)$または$O(m \alpha(n))$は許容されますが、決定ごとに DFS を繰り返し実行するものは失敗します。 

重要な微妙な点は、グラフがツリーになる必要がなく、さらには接続される必要もないことです。 有向循環を地球規模で排除することだけが必要です。 これは、結果として生じる方向がトポロジカルな順序付けを可能にするように、各エッジを方向付ける最小コストの方法を効果的に探していることを意味します。 

素朴な推論を打ち破るエッジケースは、通常、ローカルサイクルの直感から生まれます。 

簡単なサイクルの例:```
1 -> 2 -> 3 -> 1
```異なる取消コストがかかります。 各サイクルで最も安価なエッジを独立して破ろうとする貪欲なアプローチは、サイクルが重複するため失敗します。 

別の失敗例:```
1 -> 2 -> 3 -> 4 -> 2
```ここではサイクルがエッジを共有します。 1 つのエッジを削除すると複数のサイクルが部分的に中断される可能性があるため、局所的な決定は誤解を招きます。 

3 番目の微妙なケースは、エッジの反転にコストがかかるが、グローバルな一貫性を維持するために必要な場合です。 ローカルでは回避可能に見えるかもしれませんが、グローバルでは到達可能性の制約により回避不可能になります。 

## アプローチ

 ブルートフォース戦略では、すべてのエッジ (元のエッジまたは反転) に方向を割り当て、結果のグラフが非巡回であるかどうかを確認しようとします。 これはすぐに示唆します$2^m$明らかに不可能な可能性$m = 10^5$。 建設中にサイクルを検出して枝刈りを行ったとしても、最悪の場合には指数関数的な動作が発生します。 

より構造化されたアイデアは、問題をトポロジカルな順序を強制するものとして見ることから生まれます。 頂点の順序が固定されている場合、すべてのエッジはその順序で前方または後方に進みます。 エッジが前進した場合はそれを維持します。 逆に進んだ場合は、それを逆転させてそのコストを支払わなければなりません。 したがって、固定順序の場合、コストは単に後方エッジのコストの合計になります。 

これにより、問題は、順序の反対を指すエッジのコストの合計を最小化する頂点順序を見つけることに変換されます。 これは、トーナメントのような加重有向グラフで設定された古典的な最小フィードバック アークですが、ここではグラフは任意です。 

重要な洞察は、順序を直接推測する必要がないということです。 代わりに、エッジ分類を備えた DFS ベースのトポロジ構造を使用して貪欲に構築できます。 DFS 中に、未訪問のノードまでエッジをトラバースするとき、それを前方エッジとして扱います。 順序付けの制約と矛盾するエッジに遭遇すると、それを逆転の候補として解釈します。 トラバーサルを慎重に構造化することにより、反転のために選択されたエッジが、DFS ベースのトポロジ ラベリングに違反するエッジに正確に対応することが保証されます。 

標準的なトリックは、着順を記録しながら有向グラフに対して DFS を実行することです。 現在の再帰スタックに既に存在するノードにつながるエッジをトラバースするたびに、バック エッジが検出されます。これがまさにサイクルに寄与するものです。 これらのバック エッジは総コストを最小限に抑えたいセットを形成しますが、実際にすべてのサイクルを中断するエッジのみを選択する必要があります。 

改良点は、グラフをそのまま扱い、DFS 終了時間に依存することです。有向グラフは、逆ポストオーダーによる順序付けを割り当てることができる場合に限り、非巡回になります。 DFS ツリー構造において、後から終了するノードから先に終了するノードに向かうエッジはバック エッジであり、最適なソリューションでは逆転する必要があります。 驚くべき事実は、DFS はサイクル構造を考慮した方法でエッジをツリー、フォワード、バック エッジに分割するため、そのようなエッジをすべて選択すると、すべてのサイクルを削除するのに必要な最小コストのセットが得られることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m)$|$O(m)$| 遅すぎる |
 | DFS 分類 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 DFS ベースの順序付けを構築し、同時にどのエッジがその順序付けに違反しているかを特定します。 

1. 有向グラフの隣接リストを構築し、エッジ インデックスとコストを追跡します。 これが必要なのは、コストだけでなくエッジ ID も出力する必要があるためです。 
2. 未訪問のすべてのノードから DFS を実行します。 これにより、グラフが切断される可能性があるため、すべてのコンポーネントが確実に処理されます。 
3. ノードの状態配列 (未訪問、再帰スタック内、終了) を維持します。 再帰スタック内のノードへのエッジのみがサイクルに対応するため、この区別は不可欠です。 
4. ノード u からの DFS 中にエッジ u -> v を検査すると、次のようになります。 

v が訪問されていない場合は、v に再帰します。これにより、DFS ツリー構造が維持されます。 

v が現在再帰スタック内にある場合、バック エッジが見つかりました。これは、このエッジが有向サイクルに参加していることを意味します。 このエッジを反転としてマークし、そのコストを追加します。 

v がすでに終了している場合は、DFS 順序付けのサイクルに寄与できないため、無視します。 
5. u のすべての出力エッジを探索した後、u を終了としてマークし、それを逆トポロジー順序を表すリストに追加します。 
6. DFS が完了すると、マークされたすべてのエッジは、DFS から派生した非周期方向に正確に反するものになります。 それらの指標と累積コストを出力します。 

なぜ効果があるのか:

 DFS 仕上げ順序は、頂点の部分的な順序を定義します。 再帰スタック内にまだあるノードから別のノードに向かうエッジは、必ずアクティブな探索パス内の有向サイクルを閉じます。 これらのエッジはまさに、DFS 順序付けが有効なトポロジ的順序付けになることを妨げるものです。 DFS トラバーサルではすべての有向サイクルに少なくとも 1 つのバック エッジが含まれている必要があるため、これらのエッジを正確に削除 (反転) すると、すべてのサイクルが中断されます。 各バック エッジが 1 回だけ識別され、フォワード エッジやクロス エッジが不必要に反転されないため、コストが最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for i in range(1, m + 1):
        u, v, c = map(int, input().split())
        g[u].append((v, c, i))
    
    state = [0] * (n + 1)
    # 0 = unvisited, 1 = in stack, 2 = done
    bad_edges = []
    total_cost = 0
    
    def dfs(u):
        nonlocal total_cost
        state[u] = 1
        for v, c, idx in g[u]:
            if state[v] == 0:
                dfs(v)
            elif state[v] == 1:
                bad_edges.append(idx)
                total_cost += c
        state[u] = 2
    
    for i in range(1, n + 1):
        if state[i] == 0:
            dfs(i)
    
    print(total_cost, len(bad_edges))
    print(*bad_edges)

if __name__ == "__main__":
    solve()
```隣接リストにはエッジ インデックスが格納されるため、必要な識別子を直接出力できます。 DFS 状態配列は非常に重要です。スタック内マーカーがなければ、バック エッジとクロス エッジを区別できず、正確さが完全に変わってしまいます。 

グラフは最大 100,000 ノードまでの長いチェーンを形成できるため、再帰制限の増加が必要です。 

実装の微妙な点は、状態 1 のノードへのエッジのみを可逆として扱うことです。 状態 2 ノードへのエッジは、他の走査順序でサイクルを形成できるように見えても無視されます。 DFS は、アクティブな再帰パス内のサイクルを閉じないことを保証します。 

## 実用的な例

 ### 例 1

 入力:```

2 1 1
5 2 6
2 3 2
3 4 3
4 5 5
1 5 4
```DFS はノード 1 から実行します (順序は隣接関係のトラバーサルによって異なる場合があります)。 トラバーサルによってバック エッジを通過するサイクルが発見されたとします。 

| ステップ | ノード | エッジを考慮 | 状態[v] | アクション | 反転エッジ | コスト |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 -> 1 | 未訪問 | 再帰 | | 0 |
 | 2 | 1 | 1 -> 5 | 未訪問 | 再帰 | | 0 |

 トラバーサルの終了後、DFS は再帰スタック サイクルを閉じるエッジを識別します。 

重要な観察は、エッジ 5 -> 2 が DFS ツリー内にバック エッジを作成し、サイクル クロージャに直接対応することです。 逆にすると、そのパスに関係する到達可能なサイクルがすべて中断されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + m)$| 各頂点とエッジは、DFS 中に一定の回数処理されます。 
| スペース |$O(n + m)$| 隣接リストと再帰スタックおよび状態配列 |

 線形の複雑さは、次の制限内に快適に収まります。$10^5$ノードとエッジ。 隣接ストレージが支配的で入力サイズに比例するため、メモリ使用量も安全です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for i in range(1, m + 1):
        u, v, c = map(int, input().split())
        g[u].append((v, c, i))
    
    state = [0] * (n + 1)
    bad = []
    cost = 0

    sys.setrecursionlimit(10**7)

    def dfs(u):
        nonlocal cost
        state[u] = 1
        for v, c, idx in g[u]:
            if state[v] == 0:
                dfs(v)
            elif state[v] == 1:
                bad.append(idx)
                cost += c
        state[u] = 2

    for i in range(1, n + 1):
        if state[i] == 0:
            dfs(i)

    return f"{cost} {len(bad)}\n" + (" ".join(map(str, bad)) if bad else "")

 ## 特殊なケース

 最初の重要なエッジ ケースは、すでに DAG であるグラフです。 この状況では、再帰スタック内でノードが再訪問されることはないため、アルゴリズムは不良エッジを記録することはありません。 出力コストはゼロで、エッジ リストは空であり、これが最適です。 

2 番目のケースは、すべてのノードが 1 つのループを形成する単一の大きなサイクルです。 DFS は、再帰スタック内の最初のノードに再び遭遇するまでサイクルを走査し、正確に 1 つのエッジを不良としてマークします。 単純な有向サイクル内の任意の 1 つのエッジを破るとすべてのサイクルが削除されるため、これで十分です。 

3 番目のケースは、重複するサイクルです。 このようなグラフでは、トラバース中に複数のバック エッジが見つかる可能性がありますが、それぞれは再帰パスを閉じるときに正確に検出されます。 サイクルが構造的に重なっている場合でも、DFS スタックは各クロージャが独立して考慮されることを保証し、すべてのサイクルにこれらのエッジの少なくとも 1 つが含まれている必要があるため、反転後にサイクルが残ることはありません。
