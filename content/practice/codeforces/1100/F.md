 ## 解決策
 ## 問題の理解

 直線上に値の配列が与えられます。各位置はハンバーガー ショップを表し、その位置の値はそこで入手できる最も高価なハンバーガーの価格です。 クエリごとに、この配列のセグメントが与えられ、そのセグメント内のインデックスのサブセットを選択できます。 サブセットを選択すると、非常に大きな初期値から開始し、選択した値で XOR を繰り返し適用することになります。 私たちが気にする量は、値が初期状態からどれだけ減少するかです。これは、選択したサブセットの XOR 結果を最大化することに相当します。 

重要な簡素化は、初期値がすべてのビットに設定されていることによるものです。 関連するすべてのビットが 1 である形式の数値から始めると、値との XOR 演算により効果的にビットが反転されます。 「費やされる金額」は、すべての XOR 演算後の結果の値にのみ依存するため、タスクは、指定されたセグメントの一部のサブセットの XOR を最大化することになります。 

したがって、各クエリは、サブ配列が与えられた場合、その中の要素のサブセットを選択することによって取得できる最大の XOR 値はいくらか、を尋ねます。 

制約は大きく、最大 500,000 個の要素と 500,000 個のクエリがあります。 これにより、セグメント全体にわたって線形時間でクエリごとに何かを再計算することは即座に除外されます。$2.5 \times 10^{11}$最悪の場合の運用。 平$O(n \log n)$クエリごとの速度が遅すぎます。 XOR サブセットに対する高速範囲クエリをサポートする構造が必要です。 

単純なアプローチでは、範囲のすべてのサブセットを構築するか、クエリごとに貪欲な XOR ベースを再計算します。 サブセットの列挙は指数関数的であり、クエリごとに実行ベースを最初から維持することさえ、何度も繰り返すと遅すぎるため、これは失敗します。 

セグメント内のすべての値がゼロの場合、微妙なエッジ ケースが発生します。 正しい答えはゼロであり、適切な正規化を行わずに少なくとも 1 つの非ゼロ基底ベクトルを仮定するアプローチでは、誤って非ゼロ値を返したり、空の基底をクエリするときにクラッシュしたりする可能性があります。 もう 1 つの特殊なケースは、値が繰り返される場合です。 重複したものは基底を誤って拡張してはなりません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、セグメント内のすべての値を収集し、すべてのサブセットを試し、XOR を計算して最大値を追跡します。 これは問題の定義を直接評価するため、正しいです。 ただし、各セグメントの長さは$k$もっている$2^k$サブセット、$k = 30$、ましてや$k = 500000$。 

XOR サブセットの最適化はサブセットに直接関係するものではなく、サブセットが GF(2) 上に形成する線形構造に関係するものであることを認識する必要があります。 任意の数値セットは XOR の下でベクトル空間を生成し、任意のサブセット XOR はこれらのベクトルの線形結合に対応します。 取得可能な最大 XOR は、セットの線形基底から達成可能な最大値です。 

これにより、問題は配列のセグメントにわたる線形基底の維持に変換されます。 重要な観察は、セグメントの完全な動作がその基礎によって完全に記述されるということです。値は最大 20 であるため、そのサイズは最大でも 20 です。$10^6$したがって、関連ビットは最大でも 20 ビットです。 

次に、任意のセグメントの結合された基底を効率的に返すことができるデータ構造が必要になります。 セグメント ツリーは自然に機能します。各ノードはその区間の基底を格納し、2 つのノードをマージすることは、2 つの基底を 1 つの縮小基底にマージすることを意味します。 

クエリ セグメントの基礎を取得したら、最上位ビットから下に向かって貪欲に結果を改善しようとして最大の XOR を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(2^n)$クエリごと |$O(1)$| 遅すぎる |
 | XOR ベースのセグメント ツリー |$O((n + q)\log n \cdot B^2)$|$O(n \log n \cdot B)$| 承認済み |

 ここ$B$ビット数は約 20 です。 

## アルゴリズムのチュートリアル

 各ノードがセグメント内のすべての値の線形基底を格納するセグメント ツリーを構築します。 

1. 各リーフ ノードを、その位置の単一の値のみを含む基底で初期化します。 この基底は、その単一の要素 (ゼロと要素自体) から達成可能なすべての XOR を表します。 
2. 2 つのベース間のマージ操作を定義します。 2 番目の基底からすべてのベクトルを取得し、標準の線形基底挿入を使用してそれらを 1 番目の基底に挿入します。 各挿入では、既存の基底ベクトルを使用して最も高い設定ビットを削除し、構造の独立性を確保しようとします。 
3. 子ノードをマージしてセグメント ツリーをボトムアップで構築します。 各内部ノードには、その左右の子セグメントのマージされたベースが格納されます。 これにより、すべてのセグメントがその基礎によって完全に表現されることが保証されます。 
4. 各クエリについて$[l, r]$では、セグメント ツリーを走査し、クエリ範囲を完全にカバーするすべてのセグメントのベースを収集します。 これらは単一の一時的な基盤にマージされます。 
5. クエリの最終的な基礎が得られたら、最大 XOR 値を計算します。 ゼロから開始して最高位から最低位までビットを反復し、値を増加させる基底ベクトルとの XOR 演算によって値を改善しようとします。 
6. この最大値をクエリごとに出力します。 

マージが機能する理由は、互いに素なセグメントに対する XOR の組み合わせが独立しているためです。 全範囲のサブセットは左右の部分のサブセットに分割でき、それらの XOR は線形に結合されます。 したがって、ベースをマージすると、達成可能なすべての XOR が保存されます。 

### なぜ効果があるのか

 すべてのセグメント ツリー ノードで、その間隔の XOR で表現可能な値のセットに正確に及ぶ基準を維持します。 2 つのセットの XOR 組み合わせはそれらのベクトル空間の和集合に対応するため、マージ操作ではスパンが保存されます。 すべてのクエリは結合されていないセグメントに分解され、その和集合が全範囲を形成するため、それらのベースをマージすると、クエリ間隔で考えられるすべてのサブセット XOR にまたがるベースが生成されます。 次に、貪欲な抽出ステップで、その空間内で表現可能な最大値を見つけます。これは、線形基底により、決定論的なビット単位の構築を通じて到達可能な XOR を構築できることが保証されるため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

B = 20

class Basis:
    __slots__ = ("b",)
    def __init__(self):
        self.b = [0] * B

    def insert(self, x):
        for i in reversed(range(B)):
            if (x >> i) & 1:
                if self.b[i]:
                    x ^= self.b[i]
                else:
                    self.b[i] = x
                    return

    def merge(self, other):
        for x in other.b:
            if x:
                self.insert(x)

    def max_xor(self):
        res = 0
        for i in reversed(range(B)):
            res = max(res, res ^ self.b[i])
        return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Basis() for _ in range(4 * self.n)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.t[v].insert(self.arr[l])
        else:
            m = (l + r) // 2
            self.build(v * 2, l, m)
            self.build(v * 2 + 1, m + 1, r)
            self.t[v].merge(self.t[v * 2])
            self.t[v].merge(self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr, res):
        if ql <= l and r <= qr:
            res.merge(self.t[v])
            return
        m = (l + r) // 2
        if ql <= m:
            self.query(v * 2, l, m, ql, qr, res)
        if qr > m:
            self.query(v * 2 + 1, m + 1, r, ql, qr, res)

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    q = int(input())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        res = Basis()
        st.query(1, 0, n - 1, l - 1, r - 1, res)
        out.append(str(res.max_xor()))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーは配列上で一度構築され、各ノードはその間隔内のすべての XOR 寄与の圧縮表現を格納します。 クエリ機能は、関連するノードのみを収集し、それらのベースを一時的な構造にマージします。 最後のステップでは、達成可能な最良の XOR を計算します。 

実装における微妙な点は、ベースを結合する際に独立性を維持する必要があるということです。 単純な連結ではなく、ある基底の各要素を別の基底に挿入することが必要です。 もう 1 つの詳細は、値が制限されるため、基底で固定ビット制限を使用することを保証することです。$10^6$。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + q)\log n \cdot B^2)$| 各マージは最大 B 個のベクトルを挿入し、各挿入のコストは B |
 | スペース |$O(n \log n \cdot B)$| 各セグメント ツリー ノードは、サイズ B | の基底を格納します。 

複雑さは十分なので、$B \approx 20$、すべての操作が実質的に小さな定数になります。 500,000 のクエリでも、セグメント ツリーの操作は制限内で十分な速度を維持します。

 ## 特殊なケース

 ゼロのみを含むセグメントの場合、基底への挿入はすべて空のままになるため、最終的な貪欲 XOR はゼロのままになります。 セグメント ツリーはそのようなノードの空のベースを正しく格納し、空のベースをマージしても影響はなく、正確性が維持されます。 

繰り返される値の場合、同じ数値を 2 回挿入しても、既存のベクトルによって削除されるため、基底は変更されません。 これにより、複製によって表現可能なスペースが人為的に拡大されることがなくなります。 

単一要素クエリの場合、リーフ ノードにはすでに正しい基底が含まれているため、マージは必要ありません。 クエリは単純にそのノードのベースを返し、貪欲なステップは正しい答えに一致する要素自体を返します。
