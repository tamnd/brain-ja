 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$でつながっている部屋$N-1$廊下。 各廊下は使用可能またはブロックされており、廊下をブロックするとツリーがいくつかの接続されたコンポーネントに分割されます。 各コンポーネントは、ブロックされていない廊下のみを使用して相互にアクセスできる部屋のグループであり、開いたエッジを通る経路を共有する 2 つのコンポーネントはありません。 

私たちにも与えられています$T$旅行の要件。 各要件では、ソフィーが 2 つの部屋間を移動できる必要があると規定されています。$a_t$そして$b_t$彼女のコンポーネントを離れることなく。 彼女はタスク間をテレポートできるため、これらの要件は独立していますが、個々のペアは、ブロックされていないエッジの選択されたセットによって引き起こされる同じ接続コンポーネント内に存在する必要があります。 

タスクは、結果として得られるフォレスト内で必要なすべてのペアが接続されたままになるように、どのエッジを保持またはブロックするかを選択できる方法が何通りあるかを数えることです。 同様に、必要なすべての接続制約を考慮して、接続コンポーネントに分割されたツリーの数を数えます。 

制約$N, T \le 10^5$パーティションを列挙したり、エッジのサブセットごとに接続をシミュレートしようとするソリューションは直ちに除外してください。 単一の構成の接続を確認する場合でも、$O(N)$、エッジ サブセットの数は$2^{N-1}$, したがって、強引な方法は不可能です。 有効な解決策では、問題をツリーのサイズが線形または線形に近い構造に縮小する必要があります。 

要件が複雑に重なる場合、微妙な落とし穴が発生します。 たとえば、チェーンがあるとします。$1-2-3-4$そして要求する$(1,3)$そして$(2,4)$単純なアプローチでは、エンドポイントのみを見て、両方の制約が間接的にすべてのエッジを開いたままにすることを強制し、有効なパーティションが 1 つだけ生成されることを見逃してしまう可能性があります。 パスの重複を無視すると、過大なカウントが発生します。 

もう 1 つの失敗ケースは、要件がエンドポイントでは互いに素であるが、エッジでは重複している場合に発生します。 たとえば、必要に応じて、中心が 1 で葉が 2、3、4 の星の場合、$(2,3)$そして$(3,4)$の場合、エンドポイントが異なっていても、エッジは中心を介して相互作用する必要があります。 ペアを独立して扱うと、局所的な自由度が誤って増加します。 

主要な問題は、制約がパスに沿って伝播し、共有エッジを介して相互作用することです。つまり、独立したペア チェックではなく、ツリー エッジにわたるグローバル制約システムが必要になります。 

## アプローチ

 ブルートフォースアプローチでは、エッジのすべてのサブセットが試行されます。 サブセットごとに、ブロックされたエッジを削除して連結成分を計算し、必要な各ペアが同じ成分内に存在するかどうかを確認します。 これは正しいですが、高価です。$2^{N-1}$エッジサブセット、さらにはサブセットごとの線形接続チェックでも、$O(N \cdot 2^N)$、これは実現可能な限界をはるかに超えています。 

重要な観察は、実際には完全なパーティション構造を明示的に気にしていないということです。 重要なのは、各クエリのエンドポイントが接続されたままであるかどうかです。 ツリー上では、2 つのノード間の接続は、その一意のパス上のすべてのエッジのブロックが解除されることと同等です。 したがって、各クエリは、エンドポイント間のパス上のすべてのエッジに事実上制約を課します。 

ツリーをルート化すると、パス上のすべてのエッジをカットしてはならないという要件として各制約を再解釈できます。 コンポーネントの観点から考える代わりに、視点をエッジに切り替えます。各エッジは、何らかの制約によって「強制的に接続」されるか、自由になります。 問題は、必要なパスが中断されないように、ブロックするエッジのセットを選択できる方法が何通りあるかを数えることになります。 

これは、エッジごとに、少なくとも 1 つのクエリによって完全な状態を維持する必要があるかどうかを追跡することに変換されます。 問題は、クエリがパスに沿ったすべてのエッジに影響を与えるため、すべてのパスにわたってこれらの制約を蓄積する効率的な方法が必要であることです。 これは、標準のツリー差分手法とボトムアップ伝播を組み合わせて行われます。クエリのエンドポイントをマークし、カウントを伝播して、少なくとも 1 つの必要なパス上にどのエッジがあるかを識別します。 

どのエッジが「切断禁止」であるかがわかれば、他のすべてのエッジは拘束に影響を与えないため、独立して切断するかどうかを選択できます。 各自由エッジは、答えの係数 2 に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N \cdot 2^N)$|$O(N)$| 遅すぎる |
 | ツリーの差分 + フリー エッジのカウント |$O(N + T)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、エッジを有向親子関係として扱います。 

1. ツリーの隣接リストを構築し、DFS を使用して親子関係を保存します。 これによりルート構造が得られ、後ですべてのエッジをその子ノードによって識別できるようになります。 ツリーをルート化する理由は、エッジの所有権が明確になるためです。各エッジは正確に 1 つの子に対応します。 
2. クエリごとに$(a_t, b_t)$、概念的には、間のパス上のすべてのエッジをマークしたいと考えています。$a_t$そして$b_t$。 明示的にパスをたどる代わりに、カウントのトリックを使用します。つまり、配列を維持します。`cnt`ノード間で増分`cnt[a_t]`そして`cnt[b_t]`、および減少`cnt[lca(a_t, b_t)]`最小共通祖先を計算した後に 2 回。 これにより、値が上方に伝播されるときに、パス上のすべてのエッジが正の寄与を蓄積することが保証されます。 

これが機能する理由は、エンドポイントからの寄与が、それらのパスが LCA で出会うまで上向きに移動し、そこで正しくキャンセルされ、正確なパスのみがカウントされるためです。 
3. すべてのクエリを処理した後、注文後 DFS を実行します。 各ノードが集約する`cnt`値を子からそれ自体に取り込みます。 この伝播中に、子が正のカウントを提供した場合、それはノードとその子の間のエッジが少なくとも 1 つの必要なパス上にあるため、切断が禁止されていることを意味します。 
4. 必須としてマークされていないエッジの数を数えます。 このような各エッジは、必要なペアの接続に影響を与えないため、独立して存在することも、削除することもできます。 
5. 最終的な答えは次のとおりです。$2^{k}$、 どこ$k$フリーエッジの数です。 高速累乗モジュロを使用してこれを計算します$10^9+7$。 

### なぜ効果があるのか

 正確さは、すべてのクエリ パスがそのパスのすべてのエッジに沿ってフローの 1 単位に正確に寄与するという事実に基づいています。 LCA ベースのマーキングにより、このフローがパス セグメントに局所化され、パス セグメントの外に流出しないことが保証されます。 蓄積後、エッジが少なくとも 1 つのクエリ パス上にある場合に限り、エッジが強制されます。 このようなエッジを切断すると、必要なペアが切断されるため、許可されません。 残りのエッジはすべてすべての制約に無関係であるため、エッジごとに 2 の乗算係数を与えて独立して選択できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 10**9 + 7

def solve():
    n, t = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    up = [[0] * (n + 1) for _ in range(1)]  # placeholder not used fully
    order = []

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)
        order.append(u)

    dfs(1, 0)

    LOG = 17
    up = [[0] * (n + 1) for _ in range(LOG)]
    for i in range(1, n + 1):
        up[0][i] = parent[i]
    for j in range(1, LOG):
        for i in range(1, n + 1):
            up[j][i] = up[j - 1][up[j - 1][i]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for i in range(LOG):
            if diff & (1 << i):
                a = up[i][a]
        if a == b:
            return a
        for i in reversed(range(LOG)):
            if up[i][a] != up[i][b]:
                a = up[i][a]
                b = up[i][b]
        return parent[a]

    cnt = [0] * (n + 1)

    for _ in range(t):
        a, b = map(int, input().split())
        c = lca(a, b)
        cnt[a] += 1
        cnt[b] += 1
        cnt[c] -= 2

    visited = [False] * (n + 1)

    def dfs2(u, p):
        visited[u] = True
        for v in g[u]:
            if v == p:
                continue
            dfs2(v, u)
            cnt[u] += cnt[v]

    dfs2(1, 0)

    free_edges = 0
    for u in range(1, n + 1):
        for v in g[u]:
            if parent[v] == u:
                if cnt[v] == 0:
                    free_edges += 1

    def modpow(a, e):
        r = 1
        while e:
            if e & 1:
                r = r * a % MOD
            a = a * a % MOD
            e >>= 1
        return r

    print(modpow(2, free_edges))

if __name__ == "__main__":
    solve()
```実装は、ツリーをルート化し、深さと親を計算することから始まり、最下位共通祖先クエリに効率的に答えることができます。 これが必要なのは、各制約がパスに依存しており、LCA はパスをプレフィックス合計に分解できるツールであるためです。 

の`cnt`配列はツリー パスに対する差分トリックを実装します。 各クエリは両方のエンドポイントで +1、LCA で -2 に寄与するため、値が上に押し上げられると、パス上のエッジのみが正のフローを蓄積します。 

2 番目の DFS は、これらの値をボトムアップで集計します。 この時点で、`cnt[v]`エッジ接続を通過するアクティブなクエリ パスの数を表します`v`その親に。 ゼロの場合、そのエッジはどの制約によっても使用されないため、オプションとなります。 

最後に、そのようなオプションのエッジをすべて数えて計算します。$2^{\text{free edges}}$。 答えは指数関数的に増大するため、べき乗剰余演算が必要です。

 ## 特殊なケース

 主なエッジケースは、クエリが存在しない場合です。 その状況では、すべてのエッジがフリーになるため、すべてのエッジが$2^{N-1}$パーティションは有効です。 アルゴリズムはこれを自然に処理します。`cnt`値は正になり、すべてのエッジがマークされなくなります。 

もう 1 つの特殊なケースは、ツリーが直線であり、クエリが大きく重なる間隔にまたがる場合です。 伝播はチェーン全体に沿って制約を正しく蓄積し、間隔が推移的に重なる場合に必要に応じてすべてのエッジをマークします。 

3 番目のエッジ ケースは、クエリに星型ツリーのリーフのみが含まれる場合に発生します。 中央のエッジは常にすべてのパスの一部であるため、強制されますが、リーフ エッジは直接使用されない場合は自由のままになります。 DFS 累積では、ゼロ以外の累積フローを持つエッジのみが必須としてマークされるため、これらのケースが正しく区別されます。
