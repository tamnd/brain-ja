 ## 解決策
 ## 問題の理解

 私たちにはいくつかの独立した天使のグループが与えられています。 各グループには複数の戦闘力が含まれており、防御が形成されるたびに、各グループから 1 人の天使を正確に選択する必要があります。 防御力は選ばれた天使の力の合計です。 

目標値のある攻撃ごとに`t`、私たちは最低のことだけを気にします`m`防御合計のビット。 選択した累乗の合計を法としてとった場合、防御は成功します。`2^m`、等しい`t mod 2^m`。 

このタスクは動的です。グループはエンジェルの挿入と削除によって時間の経過とともに変化します。更新のたびに、すべてのグループにわたって有効な選択がいくつ存在するかを尋ねられることがあります。 

制約はすでにコア構造を示唆しています。 グループの数は少なく、最大 100 であり、ビット幅は`m`最大でも 16 なので、すべての値は一定のサイズの宇宙に存在します。`2^m`これは、最大でも 65536 です。これは、この領域サイズではほぼ線形またはほぼ線形のアルゴリズムを使用できることをすぐに示唆していますが、領域内では二次関数であれば何でも可能です。`2^m`遅すぎるでしょう。 

グループが空になると、微妙な問題が発生します。 いずれかのグループにエンジェルが存在しない場合、すべてのグループから 1 つの要素を選択することは不可能になるため、そのグループが再び空でなくなるまで、すべてのクエリに対して有効な防御の数はゼロでなければなりません。 空を無視する単純な実装では、構成全体を正しくゼロにする代わりに、畳み込み結果が生成される可能性があります。 

もう 1 つの重要な側面は、答えが和の剰余に依存することです。`2^m`、正確な合計ではありません。 これにより、整数が大きくなるという懸念はなくなりますが、次のような周期的な動作が強制されます。`2^m`合計しても結果は変わりません。 どのソリューションもこのラップアラウンド構造を尊重する必要があります。 

## アプローチ

 問題について考える直接的な方法は、組み合わせ的にシミュレーションすることです。 各グループに対して、エンジェルを 1 人選択し、すべての組み合わせを合計し、各剰余をモジュロで生成する数を数えます。`2^m`。 各グループを値の周波数配列として定義すると、`0 ... 2^m - 1`、グループを結合することは、この巡回領域の畳み込みに対応します。 

クエリが 1 つだけであれば、すべてのグループ分布を繰り返し畳み込むことができます。 2 つの長さの間の各畳み込み`N`アレイのコスト`O(N log N)`NTTを使用する場合、`N = 2^m`。 これを 100 グループにわたって 1 回実行することは許容されます。 

アップデートにより問題が発生します。 各クエリは 1 つのグループを変更するため、すべてを最初から再計算するには、100 個のディストリビューションの完全な製品を繰り返し再構築する必要があります。 これでは、畳み込みコストにクエリの数が乗算され、非常に遅すぎます。 

重要な観察は、畳み込みではすべてのグループの組み合わせが結合するということです。 これは、中間結果をセグメント ツリーに保存できることを意味します。各ノードは、ある範囲のグループの畳み込みを表します。 単一のグループが変更される場合のみ、`O(log n)`ノードは再計算が必要です。 各再計算は畳み込みではなく、周波数空間での点ごとの乗算であり、はるかに安価です。 

重要なトリックは、NTT を使用してすべてのグループを周波数領域に一度移動することです。 この領域では、畳み込みは点ごとの乗算になるため、2 つのグループを結合するには時間がかかります。`O(N)`の代わりに`O(N log N)`。 この場合、セグメント ツリーは周波数ベクトルの積のみを維持します。 

これにより、問題は、重度の畳み込みの繰り返しから、時々変換を伴う軽い乗算の繰り返しに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに完全な畳み込みを再計算する | O(q · n · N log N) | O(N) | 遅すぎる |
 | 時間領域のセグメントツリー | O(q · n · N log N) | O(nN) | 遅すぎる |
 | 周波数領域のセグメントツリー (NTT) | O(q · N log N + q · N log n) | O(nN) | 承認済み |

 ## アルゴリズムのチュートリアル

 しましょう`N = 2^m`。 各グループを周波数配列として扱います`f[g][x]`、 どこ`f[g][x]`グループには天使が何人いますか`g`力がある`x`。 

1. 各グループに対して、その周波数配列を構築します。`0 ... N-1`、次にその NTT 変換を計算します。 これにより、各グループが周波数領域ベクトルに変換され、畳み込みは点ごとの乗算になります。 

これが便利な理由は、グループの結合が元の領域では常に畳み込みであるのに対し、周波数空間では乗算であるためです。 
2. グループ上にセグメント ツリーを構築します。 各リーフには、1 つのグループの変換されたベクトルが格納されます。 

内部ノードには、子のベクトルの要素ごとの積が格納されます。 これは、グループのそのセグメントの合計貢献度を表します。 
3. 更新が発生すると、まず、関連する値を増減して、影響を受けるグループの生の周波数配列を変更します。 

raw カウントを更新した後、NTT 変換を最初から再計算します。これは、ローカルな変更により以前の変換が破壊されるためです。 
4. セグメント ツリーをそのリーフからルートまで更新します。 各ノードで、格納されているベクトルをその子の要素ごとの積として再計算します。 

ここでは畳み込みを行わず、乗算のみを行うため、このステップは効率的です。`N`要素。 
5. クエリの場合、ルート ノードの周波数領域ベクトルを取得し、逆 NTT を適用します。 結果の配列は、各剰余合計を取得する方法の数を示します。 
6. インデックスの値を出力する`t mod N`。 

それが機能する理由は 2 つの不変条件から来ています。 まず、各リーフは常にそのグループの正確な頻度分布を表します。 第 2 に、時間領域での畳み込みは周波数領域での乗算となり、その構造を一貫して維持するため、すべての内部ノードはそのセグメント内のすべてのグループの畳み込みを表します。 ルートはすべてのグループをカバーするため、その逆変換はまさにすべてのグループ選択に対するグローバルな畳み込みになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

def modinv(x):
    return pow(x, MOD - 2, MOD)

def ntt(a, invert=False):
    n = len(a)

    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(G, (MOD - 1) // length, MOD)
        if invert:
            wlen = modinv(wlen)

        i = 0
        while i < n:
            w = 1
            for j in range(length // 2):
                u = a[i + j]
                v = a[i + j + length // 2] * w % MOD
                a[i + j] = (u + v) % MOD
                a[i + j + length // 2] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = modinv(n)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def build_ntt(freq):
    a = freq[:]
    ntt(a, False)
    return a

def inv_ntt(a):
    b = a[:]
    ntt(b, True)
    return b

n, m = map(int, input().split())
N = 1 << m

groups = []
ntt_groups = []

for _ in range(n):
    tmp = list(map(int, input().split()))
    k = tmp[0]
    arr = tmp[1:]

    freq = [0] * N
    for x in arr:
        freq[x] += 1

    groups.append(freq)
    ntt_groups.append(build_ntt(freq))

def merge(a, b):
    return [(x * y) % MOD for x, y in zip(a, b)]

size = 1
while size < n:
    size <<= 1

seg = [None] * (2 * size)

for i in range(size):
    if i < n:
        seg[size + i] = ntt_groups[i]
    else:
        seg[size + i] = [1] * N

for i in range(size - 1, 0, -1):
    seg[i] = merge(seg[2 * i], seg[2 * i + 1])

def update(pos):
    i = size + pos
    seg[i] = ntt_groups[pos][:]
    i >>= 1
    while i:
        seg[i] = merge(seg[2 * i], seg[2 * i + 1])
        i >>= 1

q = int(input())
for _ in range(q):
    op = input().split()

    if op[0] == '?':
        t = int(op[1])
        res_freq = inv_ntt(seg[1])
        print(res_freq[t % N] % MOD)

    else:
        typ, i, p = op
        i = int(i) - 1
        p = int(p)

        if typ == '+':
            groups[i][p] += 1
        else:
            groups[i][p] -= 1

        ntt_groups[i] = build_ntt(groups[i])
        update(i)
```実装は、各グループの周波数配列を構築することから始まります。ここで、インデックスは可能なパワーに対応します。 これらの配列はそれぞれ、畳み込み演算が乗算になるように NTT を使用して変換されます。 

セグメント ツリーには、これらの変換された配列が格納されます。 各マージ ステップでは、対応するエントリを乗算します。これは、畳み込みのもとでグループの寄与を結合することに対応します。 

更新の場合、影響を受けるグループのトランスフォームのみを再構築し、セグメント ツリーを上向きに更新します。 クエリの場合、ルート変換を逆にして実際の畳み込み結果を復元し、必要な剰余を読み取ります。 

微妙な詳細は、空のグループは自然にゼロ ベクトルになり、乗算を通じて伝播し、すべての答えが強制的にゼロになり、有効な選択が存在しないという要件と一致します。 

## 実用的な例

 2 つのグループを持つ小さなインスタンスを考えてみましょう。`m = 2`, したがって、値はモジュロ 4 になります。 

最初に:

 グループ 1 には、`[0, 1]`、グループ 2 には、`[0, 2]`。 

周波数ベクトルは次のとおりです。 

グループ 1:`[1, 1, 0, 0]`グループ 2:`[1, 0, 1, 0]`畳み込み後の可能な合計は次のとおりです。 

| 選択 | 合計mod 4 |
 | --- | --- |
 | 0 + 0 | 0 |
 | 0 + 2 | 2 |
 | 1 + 0 | 1 |
 | 1 + 2 | 3 |

 したがって、すべての残余は 1 回出現します。 

さて、削除するとします`2`グループ2から、退場`[0]`。 

| ステップ | グループ 1 | グループ 2 | 結果の分布 |
 | --- | --- | --- | --- |
 | イニシャル | [0,1] | [0,2] | ユニフォーム |
 | アップデート後 | [0,1] | [0] | グループ 1 のみが重要 |

 グループ 1 の合計だけが残るので、剰余は次のようになります。`[1,1,0,0]`。 

このトレースは、更新はローカル周波数ベクトルにのみ影響し、グローバルな結果は最初からの再計算ではなく、純粋に組み換えによって調整されることを示しています。

 ## 特殊なケース

 削除後にグループが空になるケースは、乗法的失敗モードを強調します。 1 つのグループに天使がいない場合、その周波数ベクトルはすべて 0 になります。 このベクトルをセグメント ツリー内のグローバル積に乗算すると、結果全体がゼロに崩壊します。 これは、有効な防御を形成できないという要件に一致します。 

もう 1 つのケースは、同じグループで更新が繰り返される場合です。 更新のたびに変換が最初から再構築されるため、古い周波数データは決して再利用してはなりません。 正確性は、変更のたびに常に NTT を再計算し、グループのセグメント ツリーに古い状態と新しい状態が混在しないようにすることに依存します。
