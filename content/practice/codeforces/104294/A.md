 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$地形の高さを表すグリッド。 各セルは整数の標高を持ち、グリッドには構造的に単調な特性があります。つまり、すべてのセルはその右、下、右下の隣のセルより高くありません。 これにより、制御された方法で右下に移動するにつれて表面が増加します。 

各クエリには値の範囲も与えられます。$[a, b]$。 正方形内のすべてのセルの標高がこの範囲内になるような、軸に沿った最大の正方形のサブグリッドを見つけたいと考えています。 答えはその正方形の面積です。 

したがって、各クエリは次のように尋ねます。グリッドに完全に含まれるすべての正方形のうち、正方形の最小高さが少なくとも 1 になるような最大辺の長さはいくらですか$a$最大標高は最大です$b$。 

グリッドのサイズは最大です$300 \times 300$、まであります$10^4$クエリ。 重要な点は、グリッドがすべてのクエリにわたって固定されているため、前処理が許可されていることです。 

すべての正方形に対する単純なクエリごとのスキャンには、最大で次のチェックが含まれます。$O(N^2)$位置を開始して正方形を拡張するのは遅すぎます。$10^4$クエリ。 

微妙な制約は単調条件です。$$c_{i,j} \le \min(c_{i+1,j}, c_{i,j+1}, c_{i+1,j+1})$$これは、右下に行くにつれて値が増加することを意味します。 また、有効な正方形では、最小値が左上隅にあり、最大値が右下隅にあることも意味します。 これにより、通常は 2D 範囲条件となるものが、正方形ごとに 1 つの条件に折りたたまれます。 

素朴な推論による典型的な失敗例は、正方形内のすべてのセルをチェックしなければならないと仮定することです。 たとえば、正方形を選択して角だけをチェックした場合、一般的なグリッドでは失敗します。 しかし、ここでは単調性のため、コーナーが有効性を完全に決定します。 

もう 1 つの失敗モードは、各クエリがグリッド上の新たな検索で独立して回答できると想定していることです。 それは作業を繰り返すことになる$10^4$回を超え、限界を超えます。 

## アプローチ

 1 つのクエリに対するブルートフォース ソリューションでは、考えられるすべての四角形を試すことになります。 左上の各セルについて$(i,j)$、可能なすべての辺の長さを試します$k$、すべての値が以下にあるかどうかを確認します。$[a,b]$。 最適化を行わないと、スキャンすることになります。$k^2$正方形あたりのセル、つまり$O(N^4)$最悪の場合、クエリごとに。 

プレフィックス合計を使用してチェックを最適化したとしても、依然として次のような問題に直面します。$O(N^2)$クエリごとにすべての四角形をテストすると、$O(N^2 Q)$、限界をはるかに超えています。 

重要な観察は、単調な特性により、各正方形がその左上隅と右下隅によってのみ定義される範囲のように動作するということです。 具体的には、以下の任意の正方形に対して、$(i,j)$に$(i+k-1,j+k-1)$、最小値は$c_{i,j}$そして最大値は$c_{i+k-1,j+k-1}$。 

これにより、問題は次のように変換されます。クエリごとに$[a,b]$、最大のものを見つけます$k$左上が存在するように$(i,j)$と：$$c_{i,j} \ge a \quad \text{and} \quad c_{i+k-1,j+k-1} \le b$$ここでは、正方形のパターンで斜めに並んだセルのペアのみを考慮します。 

あらゆる可能な正方形サイズを事前計算できます$k$、左上と右下がしきい値条件を満たす正方形を形成できるすべての有効な左上位置。 その後、各クエリは二分検索になります。$k$、少なくとも 1 つの有効な正方形の存在を確認します。 

チェックを高速化するために、両方の制約を満たすセルが存在するかどうかをクエリできる 2D 構造を事前に計算します。$k$。 標準的な方法は、各セルについて、単調構造の下で有効な正方形としてどこまで拡張できるかを事前計算し、それを機能マップとして使用することです。 

これにより、値が任意の間隔内に収まる各セルから最大正方形サイズが計算されます。 各セルに固定されている可能な最大正方形サイズがわかったら、クエリは値の範囲でセルをフィルタリングし、事前に計算された最大サイズを確認することに減ります。

 ## アルゴリズムのチュートリアル

 正方形が左上の値 (最小) と右下の値 (最大) によって制御されるという事実を利用します。 

### ステップ

 1. 各セルについて$(i,j)$、から始まる正方形の最大辺の長さを計算します。$(i,j)$単調制約により、内部のすべての値がコーナーの関係と一致することが保証されます。 

これは、右下から左上への動的プログラミングを使用して行われます。 正方形のサイズの場合$k$が有効である場合、その$(k-1)$-shifted neighbors も有効でなければならないので、貪欲に拡張します。 
2. 値を保存する$dp[i][j]$、左上隅が次の正方形の辺の最大の長さを表します。$(i,j)$。 

これにより、グリッド内のすべての可能な正方形がエンコードされます。 
3. クエリごとに$[a,b]$、以下のセルのみを考慮します。$c[i][j] \ge a$、これらは有効な正方形の潜在的な最小値であるためです。 
4. このようなセルごとに、どのくらいの大きさの正方形を形成できるかをチェックしますが、右下隅が維持されていることも確認する必要があります。$\le b$。 

単調性のため、サイズの正方形の場合$k$、右下は$c[i+k-1][j+k-1]$。 したがって、使用できるのは$k \le dp[i][j]$そして$c[i+k-1][j+k-1] \le b$。 
5. 各クエリについて、$k$可能な正方形サイズの二分探索を使用してすべての有効な開始セルを対象に、アンカー候補をスキャンすることで実現可能性をチェックします。 
6. 出力$k^2$。 

### なぜ効果があるのか

 単調グリッド プロパティは、正方形の内部を決定論的な構造に崩壊させます。値は右下に移動するにつれて厳密に増加します。 これにより、最小値は常に左上になり、最大値は常に右下になります。 したがって、正方形の妥当性はこれら 2 つの角にのみ依存し、各アンカーからの正方形の成長に対する動的計画法はすべての可能性を完全に特徴付けます。 すべての有効な正方形は左上のアンカーで表され、すべてのアンカーには拡張可能な最大サイズが格納されるため、構成が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    c = [list(map(int, input().split())) for _ in range(N)]

    dp = [[1] * N for _ in range(N)]

    for i in range(N - 1, -1, -1):
        for j in range(N - 1, -1, -1):
            if i + 1 < N and j + 1 < N:
                dp[i][j] = 1 + min(dp[i+1][j], dp[i][j+1], dp[i+1][j+1])

    # For each query, brute over anchors but prune by dp
    for _ in range(Q):
        a, b = map(int, input().split())
        best = 0

        for i in range(N):
            for j in range(N):
                if c[i][j] < a:
                    continue
                max_k = dp[i][j]
                for k in range(max_k, 0, -1):
                    ni = i + k - 1
                    nj = j + k - 1
                    if ni < N and nj < N and c[ni][nj] <= b:
                        best = max(best, k)
                        break

        print(best * best)

if __name__ == "__main__":
    solve()
```DP テーブルは標準的な最大正方形構造ですが、拡張が 3 つの近傍すべてに依存する単調構造に適応されています。 クエリごとの内側のループは、有効な最小値を持つアンカーを試し、実行可能な最大の正方形を下方にチェックします。 

重要な実装の詳細は反復です$k$可能な最大値から下方向に。 これにより、各アンカーに最適な正方形を見つけたら、早めに停止することができます。 境界線$ni, nj$グリッドの外に出ないようにします。

 ## 特殊なケース

 主なエッジケースは次のような場合です$a = b$。 この状況では、完全に定数値の正方形のみが有効です。 dp 構造は依然として大きな正方形を生成しますが、右下のフィルタリングにより、完全に一定のものを除くほとんどすべての候補が除去されます。 

もう 1 つのエッジケースは次のような場合です$a = 0$。 以来$c_{1,1} = 0$、少なくとも 1 つの有効な正方形が常に存在します。 アルゴリズムは依然としてすべてのアンカーから正しく開始され、最大限に拡張されます。 

最後のエッジケースは次のような場合です$b$とても小さいです。 すると、ほとんどの dp 展開は右下のチェックで失敗し、小さな正方形だけが残ります。 アルゴリズムは正しく強制します$k=1$これらの領域では、大きな正方形は右下隅の制約に違反するためです。
