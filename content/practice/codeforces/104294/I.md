 ## 解決策
 ## 問題の理解

 私たちには家のツリーが与えられており、各家には最初は一定数の友人が含まれています。 道路は接続された非環状構造を形成しているため、2 つの家の間には 1 つの単純な道が存在します。 

イベントには2種類あります。 うまるは 2 つの家の間でスナックを実行するか、現在の値に何らかの係数を乗じて特定の家に友達の数を増やします。 スナックを実行するたびに、2 つのエンドポイント間の一意のパス上のすべての家を調べ、そのパスに沿ったすべての家の友人の数で割り切れる最小の正の数を計算する必要があります。 

この量は、そのパス上のすべての値の最小公倍数にすぎません。 課題は、クエリ間で乗算更新が発生するため、値が静的ではないことです。パス LCM クエリにはオンラインで応答する必要があります。 

制約は十分小さいため、ノードまたはクエリの数において 2 次に近い解を得ることができます。 N と Q の両方が最大 1000 である場合、合計作業量は約 10^6 操作にとどまるため、クエリごとにおよそ O(N) かかるアプローチでも許容されます。 これにより、重い動的ツリー構造が即座に除外されますが、パスを明示的に再計算したり通過したりすることが可能になります。 

微妙な点は、乗算を繰り返すと値が大きくなる可能性があることです。 個々の a_i 値は最初は 10^7 で制限されていますが、更新を繰り返すと値が大幅に大きくなる可能性があるため、生の値を保存して直接 LCM 計算を試みることは安全ではありません。 代わりに、素因数分解による LCM の構造が必須になります。 

単純な間違いは、素数ごとの最大値を追跡せずに、パス全体の最小公倍数を増分的に維持しようとすることです。 LCM は単純な加法的な方法で乗算を分散しないため、これは更新では失敗します。 もう 1 つのよくある間違いは、パス値を再計算するときに整数を直接乗算することです。これはすぐにオーバーフローして不正確になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリについて、u と v の間のパスを明示的に見つけ、そのパス上のすべてのノードを収集し、それらの値の LCM を計算します。 これは正しいです。パスが明示的に列挙され、LCM 定義が直接適用されるからです。 ただし、生の整数に対する LCM の計算にはオーバーフローによる問題があり、算術演算を修正したとしても、クエリごとに潜在的に O(N) ノードに対する LCM の再計算は O(NQ) の複雑さになります。この制約ではまだ許容されますが、因数分解のコストと更新を含めるとマージンが残りません。 

重要な観察は、LCM は素因数空間で最もよく処理されるということです。 一連の数値の最小公倍数は、各素数について、すべての数値にわたるその素数の最大指数を取ることによって決定されます。 これは、各ノードが素数から指数までのマップとして表現できることを意味し、パス クエリに対する答えは、最大値を使用したこれらのマップの和集合になります。 

この表現では更新が簡単です。 ノードに f を乗算する場合、f を素因数分解し、それらの指数をノードに保存されている因数分解に追加します。 これにより、ノードの因子マップが常に正しい状態に保たれます。 

残りの課題は、パスのクエリに効率的に答えることです。 N が小さいため、ツリーの親配列と深さ配列を事前計算し、標準的な LCA ベースのリフティング手順を使用してパス上のすべてのノードを抽出できます。 パス上のノードのリストを取得したら、最大値を取得してそれらの素指数マップをマージします。 最終的な答えはべき乗剰余を使用して再構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ + 因数分解オーバーヘッド) | O(N) | 許容範囲だがきつい |
 | 最適 | O(NQ ログ A) | O(N log A) | 承認済み |

 ## アルゴリズムのチュートリアル

まずツリーを任意の場所 (通常はノード 1) にルートし、DFS を使用して親配列と深さの配列を計算します。 これにより、後でパスを効率的に取得できるようになります。 

次に、各ノードについて、現在の素因数分解を、素数を指数にマッピングする辞書として保存します。 最初に各 a_i を因数分解してこれを構築します。 

更新操作ごとに、乗数 f_i を因数分解し、その素数指数をターゲット ノードの辞書に追加します。 整数の乗算は指数空間の加算に対応するため、これにより正確さが維持されます。 

クエリ操作ごとに、u と v の間のパスを計算します。両方のノードを最下位の共通祖先で出会うまで持ち上げ、途中ですべてのノードを収集します。 これにより、パス上のノードの完全なリストが得られます。 

ノードを取得したら、パス上のすべてのノード間で見られる最大指数を素数ごとに追跡するクエリ用のグローバル ディクショナリを構築します。 各ノードの因数分解マップを反復処理することで、この辞書を更新します。 

最後に、1e9+7 を法として、その最大指数まで累乗した p のすべての素数の積を計算することで、答えを再構築します。 

これが機能する理由は、パス内のすべての数値が独立した素数累乗に寄与するためです。 LCM は、セット内の任意の場所に出現する各素数の最高パワーを選択します。 更新では個々のノードの指数が増加するだけで、因数の分割や削除は行われないため、各ノードの因数分解は時間が経っても有効であり、最大値によるマージによりパス LCM の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# simple factorization up to sqrt using trial division
def factor(x):
    res = {}
    d = 2
    while d * d <= x:
        while x % d == 0:
            res[d] = res.get(d, 0) + 1
            x //= d
        d += 1
    if x > 1:
        res[x] = res.get(x, 0) + 1
    return res

sys.setrecursionlimit(10**7)

N, Q = map(int, input().split())
a = list(map(int, input().split()))

g = [[] for _ in range(N)]
for _ in range(N - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * N
depth = [0] * N

def dfs(u, p):
    parent[u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(0, -1)

facts = [factor(x) for x in a]

def get_path(u, v):
    pu, pv = u, v
    while depth[pu] > depth[pv]:
        pu = parent[pu]
    while depth[pv] > depth[pu]:
        pv = parent[pv]

    path_u = []
    path_v = []

    while pu != pv:
        path_u.append(u)
        path_v.append(v)
        u = parent[u]
        v = parent[v]
        pu = parent[pu]
        pv = parent[pv]

    path_u.append(u)
    path = path_u + path_v[::-1]
    return path

def mod_pow(x, e):
    return pow(x, e, MOD)

for _ in range(Q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 2:
        _, w, f = tmp
        w -= 1
        for p, c in factor(f).items():
            facts[w][p] = facts[w].get(p, 0) + c
    else:
        _, u, v = tmp
        u -= 1
        v -= 1

        path = get_path(u, v)

        best = {}
        for node in path:
            for p, c in facts[node].items():
                if best.get(p, 0) < c:
                    best[p] = c

        ans = 1
        for p, c in best.items():
            ans = (ans * pow(p, c, MOD)) % MOD

        print(ans)
```このソリューションはノードごとに因数辞書を維持するため、更新は乗数を因数分解した後の局所的な指数の加算になります。 DFS は、重い LCA 構造を使用せずにパスの再構築を実行できるように、親ポインターと深さを設定します。 

パス抽出関数は、最初に両方のノードを同じ深さに位置合わせし、次にそれらが出会うまで一緒に上に移動し、両方のブランチに沿ってノードを収集します。 これにより、パス上のすべてのノードが 1 回だけ含まれることが保証されます。 

クエリの評価中に、パス全体の素数指数を集計します。 辞書`best`各素数について、これまでに確認された最大の指数を常に保持します。 これは、LCM 定義を指数形式で直接エンコードします。 

## 実用的な例

 最初にパスをクエリし、次のクエリの前に更新を適用するサンプル ツリーを考えてみましょう。 

最初のクエリでは、パスに因数分解されたノードが含まれていると仮定します。`{1}`、`{2 × 3}`、 そして`{2²}`。 集計ステップでは次のようなテーブルを構築します。 

| ノード | 素因数 | 総合ベスト |
 | --- | --- | --- |
 | 1 | {} | {} |
 | 2 | {2:1、3:1} | {2:1、3:1} |
 | 3 | {2:2} | {2:2、3:1} |

 最終的な答えは、2² × 3¹ = 12 です。これは、アルゴリズムがパス全体で素数ごとの最大指数を正しく選択していることを確認します。 

更新によってノードが 4 倍になると、その因子マップはさらに 2 の 2 乗を獲得します。次のクエリでは、そのノードがパスに含まれている場合、その寄与が 2 の指数よりも大きくなり、これが最終的な LCM に正しく反映されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q · N + Q · sqrt(A)) | 各クエリは最大 N 個のノードのパスをたどり、因子マップをマージします。 更新では乗数を因数分解する必要があります。 
| スペース | O(N log A) | 各ノードはその素因数分解を保存します。 

N、Q ≤ 1000 とすると、これは制限内に問題なく収まります。 因数分解とフルパストラバーサルを繰り返しても、合計操作数は Python の一般的な制約内に収まります。

import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def factor(x):
        res = {}
        d = 2
        while d * d <= x:
            while x % d == 0:
                res[d] = res.get(d, 0) + 1
                x //= d
            d += 1
        if x > 1:
            res[x] = res.get(x, 0) + 1
        return res

    N, Q = map(int, input().split())
    a = list(map(int, input().split()))
    g = [[] for _ in range(N)]

    for _ in range(N - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * N
    depth = [0] * N

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v != p:
                depth[v] = depth[u] + 1
                dfs(v, u)

    dfs(0, -1)

    facts = [factor(x) for x in a]

    def get_path(u, v):
        pu, pv = u, v
        while depth[pu] > depth[pv]:
            pu = parent[pu]
        while depth[pv] > depth[pu]:
            pv = parent[pv]

        path_u, path_v = [], []
        while pu != pv:
            path_u.append(u)
            path_v.append(v)
            u = parent[u]
            v = parent[v]
            pu = parent[pu]
            pv = parent[pv]

        path_u.append(u)
        return path_u + path_v[::-1]

    out = []
    for _ in range(Q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 2:
            _, w, f = tmp
            w -= 1
            for p, c in factor(f).items():
                facts[w][p] = facts[w].get(p, 0) + c
        else:
            _, u, v = tmp
            u -= 1
            v -= 1

            path = get_path(u, v)

            best = {}
            for node in path:
                for p, c in facts[node].items():
                    best[p] = max(best.get(p, 0), c)

            ans = 1
            for p, c in best.items():
                ans = ans * pow(p, c, MOD) % MOD

            out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、更新によって単一のノードが繰り返し増加し、その因数分解が大幅に増大する場合です。 たとえば、ノード 3 が 1 で開始され、2 によって 5 回更新される場合、その因子マップは次のようになります。`{2:5}`。 ノード 3 に関係するクエリでは、LCM はこの完全な指数を反映する必要があります。 更新では格納されている指数が増加するだけで、上書きされることはないため、アルゴリズムがこれを処理します。 

もう 1 つのエッジ ケースは、u が v に等しい、長さ 1 のパスです。この場合、パス抽出では 1 つのノードのみが返され、LCM は正確にその現在の値になります。 集約ステップは自然に 1 つの辞書に減るため、特別な処理は必要ありません。 

3 番目のケースは、異なるノードが異なる方法で同じ素数に寄与する場合です。 たとえば、1 つのノードには`2^3`そしてもう一つ`2^1`。 正しい結果は、合計ではなく、最大の指数を取ることに依存します。 マージステップ`best[p] = max(...)`はこの動作を保証するため、重複する素因数は二重にカウントされることなく正しく解決されます。
