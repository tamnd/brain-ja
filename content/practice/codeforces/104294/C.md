 ## 解決策
 ## 問題の理解

 それぞれが壁のセクションの高さを表す 3 つの別々のシーケンスが与えられています。 どの壁にも同じ数のセクションがありますが、順序はタスクには無関係です。 重要なのは、各壁に少なくとも 1 回出現する高さだけです。 

目標は、3 つの壁すべてに同時に表示される最大の高さの値を見つけることです。 言い換えれば、最初の配列のどこか、2 番目の配列のどこか、そして 3 番目の配列のどこかに存在する値を検索し、そのようなすべての値の中で最大の値を求めます。 そのような値が存在しない場合、答えは -1 として定義されます。 

この制約により、壁ごとに最大 100,000 個の要素が許可され、各高さは最大 100,000 になります。これにより、要素のすべてのペアまたはトリプルを直接比較するアプローチは即座に除外されます。 3 次または 2 次の戦略では、最悪の場合、最大 10^10 の演算が必要になりますが、これは Python で 2 秒に収まる演算をはるかに超えています。 各配列をソートするだけでも問題ありませんが、Python リストに対するスキャンやネストされたメンバーシップのチェックを繰り返し行うと、時間がかかりすぎます。 

主な微妙な点は、重複が存在する以上は重要ではないということです。 壁に高さが複数回表示される場合でも、論理的に存在するのは 1 つだけです。 もう 1 つのエッジ ケースは、交差点が空いている場合です。 たとえば、3 つの配列が [1]、[2]、[3] のように互いに素である場合、正しい出力は -1 であり、回答候補を 0 に初期化する実装は、注意しないと誤って 0 を返します。 

## アプローチ

 直接的なアプローチは、これをメンバーシップ交差問題として扱うことです。 最初の壁のすべての値について、それが 2 番目と 3 番目の壁に表示されるかどうかを確認できます。 これは、3 つのセットすべての存在条件を明示的にテストするため、正しいです。 ただし、リストの単純なメンバーシップ チェックには O(n) のコストがかかるため、最初の配列の最大 n 個の要素ごとに、さらに 2 つの配列をスキャンする可能性があります。 これにより、テスト ケースごとに O(n^2) の動作が発生し、最悪の場合は約 10^10 回の操作となり、遅すぎます。 

重要な観察は、位置情報や多重度は必要なく、値が存在するかどうかだけが必要であるということです。 これにより、各配列を個別の値のセットに変換できます。 これを実行すると、メンバーシップのチェックにかかる時間は平均 O(1) になります。 次に、問題は 3 つのセットの共通部分を計算し、結果から最大の要素を選択することに帰着します。 値は 100000 で制限されているため、ブール配列を使用して存在を直接マークすることもできますが、交差を設定する方が単純で十分に高速です。 

ブルート フォース アプローチは、すべての候補を直接テストするため概念的には機能しますが、リニア スキャンが繰り返されるため、時間の制約の下では失敗します。 セットベースのアプローチでは、各メンバーシップ チェックが定数時間に短縮され、問題がセットごとに最大 n 個の値にわたる線形スキャンに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | セットの使用 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 壁セクションを表す 3 つの配列を読み取ります。 値の順序は無関係であるため、存在感のみに焦点を当てます。 
2. 各配列をセットに変換します。 これにより重複が削除され、迅速なメンバーシップ チェックが準備されます。 このステップにより、今後の壁内に存在する検索が平均 O(1) になることが保証されます。 
3. 有効な共通の高さもそこに存在する必要があるため、3 つのセットのうち最小のものを繰り返します。 各候補値について、それが他の 2 つのセットに存在するかどうかを確認します。 
4. これまでに見つかった最大有効高さを追跡する変数を維持します。 3 つのセットすべてに存在する値が見つかるたびに、それを現在の最大値と比較し、それが大きい場合は更新します。 
5. すべての候補をチェックした後、見つかった最大値を出力します。 有効な値がなかった場合は、-1 を出力します。 

機能する理由: このアルゴリズムは、すべての有効な回答が 3 つのセットの共通部分に属している必要があるという事実に基づいています。 検索スペースを 1 つのセットに制限し、他のセットのメンバーシップを検証することで、候補を見逃すことなく完全性を確保します。 維持される不変条件は、どの時点でも、現在の最良値がこれまでに確認されたすべての交差要素の最大値であるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
m = list(map(int, input().split()))
r = list(map(int, input().split()))
s = list(map(int, input().split()))

set_m = set(m)
set_r = set(r)
set_s = set(s)

ans = -1

for x in set_m:
    if x in set_r and x in set_s:
        if x > ans:
            ans = x

print(ans)
```存在することのみが重要であるため、ソリューションは 3 つの配列を読み取り、すぐにセットに変換します。 ループオーバー`set_m`これにより、個別の候補の高さを一度だけ考慮することが保証されます。 各メンバーシップのテストに対して`set_r`そして`set_s`平均一定時間で実行されるため、ソリューション全体が線形に保たれます。 交差が存在しない場合を正しく処理するために、応答変数は -1 から始まります。 

よくある間違いは、セットではなく元の配列を反復処理することです。これにより、冗長なチェックが発生する可能性があります。 もう 1 つの微妙な問題は初期化です`ans`バリアント問題ですべての値が負の場合、これは不正確になりますが、ここでは問題が正の高さを保証しているという理由だけで安全です。 それでも、-1 が「交差点なし」の正しいセンチネルです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各配列はセットを構築するために 1 回スキャンされ、その後、O(1) メンバーシップ チェックで 1 つのセットを繰り返します。 
| スペース | O(n) | 3 つのセットにわたって最大 n 個の個別の値を保存します。 

この制約により、配列あたり最大 100,000 個の要素が許可されるため、線形時間と線形メモリは Python の制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    m = list(map(int, input().split()))
    r = list(map(int, input().split()))
    s = list(map(int, input().split()))

    set_m = set(m)
    set_r = set(r)
    set_s = set(s)

    ans = -1
    for x in set_m:
        if x in set_r and x in set_s:
            ans = max(ans, x)

    return str(ans)

# provided sample
assert run("""5
1 2 3 8 5
5 6 7 8 9
8 12 14 19 12
""") == "8"

# all disjoint
assert run("""3
1 2 3
4 5 6
7 8 9
""") == "-1"

# single common value
assert run("""4
10 20 30 40
5 10 6 7
10 8 9 1
""") == "10"

# duplicates everywhere
assert run("""5
1 1 2 2 3
3 3 2 2 1
2 2 2 2 2
""") == "2"

# all same
assert run("""3
7 7 7
7 7 7
7 7 7
""") == "7"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 素集合 | -1 | 交差点がない場合 |
 | 混合オーバーラップ | 10 | 正しい最大交差 |
 | 大量の重複 | 2 | 重複排除の正確性 |
 | 均一な値 | 7 | 完全交差の場合 |

 ## 特殊なケース

 エッジケースの 1 つは、共通の値がまったく存在しない場合です。 例えば：```
3
1 2 3
4 5 6
7 8 9
```セットに変換した後は、`set_m`両方に登場する`set_r`そして`set_s`。 ループが更新されない`ans`なので、-1 のままですが、これは正しいです。 

もう 1 つのケースは、すべての配列が同じ繰り返し値で構成されている場合です。```
3
5 5 5
5 5 5
5 5 5
```全てのセットはこうなります`{5}`。 The loop checks 5, confirms it exists in both other sets, and updates`ans`他の値は存在しないため、出力は 5 のままです。 

最後の微妙なケースは、次のような単一の有効な交差値と重複が混在する場合です。```
5
1 1 1 2 2
3 2 2 2 4
2 5 6 2 7
```ここでは 2 だけが一般的です。 Even though it appears multiple times, set conversion ensures it is evaluated once, and the algorithm correctly returns 2.
