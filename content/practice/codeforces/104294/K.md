 ## 解決策
 ## 問題の理解

 私たちには、アニメ トレーディング カードのマルチセットが与えられており、各カードには個性番号と呼ばれる整数のラベルが付けられています。 緑谷は、非常に具体的な最終コレクションを完成させたいと考えています。コレクションには、1 から値 K までの各整数のコピーが 1 つだけ含まれており、ギャップや余分なものは含まれていない必要があります。 彼は 2 つの操作を使用して自分のコレクションを変更することができます。コスト A で既存のカードを他のカードに交換するか、コスト B でカードを直接購入できます。ディーラーはすべての個性番号を無制限に供給できるため、供給が制約されることはありません。 

重要な部分は、最終的なコレクションが恣意的ではないということです。 1 から始まる整数の完全なプレフィックス セットである必要があります。つまり、K を選択し、1 から K までのすべての数値が 1 回だけ出現することを確認することによって、最終状態が完全に決定されます。 

入力サイズ N は 100000 まで大きくでき、クワイク番号の値は最大 1e6 になります。 これにより、すべての変換をシミュレートしようとしたり、カードのすべてのサブセットを明示的に試行したりするソリューションは除外されます。 O(N^2) 以上のアプローチはすぐに失敗します。 K が大きくなる可能性があるため、O(NK) さえ不可能です。 

微妙な難点は、重複したカードや無関係なカードが存在することです。 一部のカードは必要な数にすでに一致しているため役に立ちますが、その他のカードはトレードで交換するか、完全に無視した方がよい場合があります。 もう 1 つの注意が必要な点は、既存のカードを必要な枚数に交換するのが安いのか、単に購入するのが安いのかを判断することです。 その決定は A と B のみに依存しますが、すでに持っている数値の数と相互作用します。 

よくある間違いは、特定の固有番号を持つカードを持っていれば常にコストが節約できると考えることです。 これは誤りです。なぜなら、取引が高価な場合でも、同じ番号をそのまま購入した方が安い可能性があるからです。 もう 1 つの失敗例は、常に K を最大化する必要があると想定していることです。K を増やすと必要な購入が増えるため、最適な K が必ずしも達成可能な最大値になるとは限りません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。考えられるすべての K に対して、集合 {1, 2, ..., K} を構築しようとします。 K ごとに、現在のコレクションにこれらの数値がすでにいくつ存在するかを数えます。 すでに x 個あると仮定します。 残りの K − x 数値は、取引または購入のいずれかを使用して作成する必要があります。 欠損している数値ごとに 2 つの操作のうち安価な方を選択するため、それぞれのコストは min(A, B) になります。 これにより、その K の合計コストが得られます。 

これは、必要な数値がそれぞれ独立しているため、正しく機能します。K を決定すると、欠損値のそれぞれを個別に修正できます。 ただし、1e6 までのすべての K を試すのは遅すぎます。 各 K について、配列をスキャンするか、周波数カウントを維持すると、おおよそ O(N maxC) かそれ以上の値になり、これは限界をはるかに超えています。 

重要な観察は、最初の K 数のうちのいくつがすでに存在しているかだけを気にするということです。 すべてのクワイク番号の周波数を前処理すると、プレフィックス カバレッジを効率的に計算できます。 次に、可能な値に対して 1 回の線形スイープですべての K を評価し、必要な数がすでに所有されているかを累積します。 

costPerFix = min(A, B) とします。 与えられた K の場合、コストは (K − have[K]) *costPerFix です。 唯一欠けている要素は、マルチセット内の [1, K] 内にある個別の値の数である have[K] を計算することです。 周波数配列またはマーカーを設定したら、存在に対するプレフィックスの合計を維持できます。 

したがって、問題は、K を 1 から入力に現れる最大値までスキャンし、すでに存在する 1..K の数を維持し、各ステップでのコストを計算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | K に対するブルート フォース | O(N・maxC) | O(N) | 遅すぎる |
 | プレフィックス周波数スイープ | O(maxC + N) | O(maxC) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. 頻度配列またはブール値の存在配列を使用して、どのクワイク番号がすでに存在するかを数えます。 これにより、必要な番号がすでに所有されているかどうかを定期的にチェックすることができます。 
2. CostPerFix を A と B の最小値として計算します。これは、欠落しているカードを 1 枚変換または取得する最も安価な方法を表します。これは、欠落している数字をそれぞれ個別に処理できるためです。 
3. 可能なクワイク番号の範囲にわたってプレゼンス配列を構築します。 すべての c_i を存在するものとしてマークしますが、最初に出現した後は重複しても役に立たないため、それが少なくとも 1 回存在するかどうかのみを考慮します。 
4. K を 1 から上に向かって繰り返し、1..K にすでに存在する数値がいくつあるかを実行カウントを維持します。 値 i に達すると、presents[i] が true の場合、have がインクリメントされます。 これにより、現在のプレフィックスに対して満たされた要件の数が常に表されることが保証されます。 
5. 各 K = i について、コストを (i − have) *costPerFix として計算します。 これは、i が必要なカードの数、have がすでに利用可能なカードの数であるため、その違いは何を構築する必要があるかということです。 
6. すべての K にわたる最小コストを追跡します。答えは、小さい K (必要なカードが少ない) を選択するか、大きい K (すでに使用可能なマッチが多い) を選択する間の最良のトレードオフです。 
7. 取得した最小値を返します。 

### なぜ効果があるのか

 任意の固定 K では、問題の構造により決定論的な分解が強制されます。1..K 内の必要な各数値は、すでに存在するか欠落しています。 既存のカードにはコストはかかりません。 不足しているカードは独立した決定であり、それぞれのカードを取引または購入によって個別に最適に満たすことができます。 演算は値間で相互作用しないため、異なる数値間に結合はありません。 したがって、コスト関数は欠落要素の数のみに依存し、要素の識別には依存しません。 これにより、すべての有効な K を探索するのに十分なプレフィックス評価が行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B = map(int, input().split())
    arr = list(map(int, input().split()))

    maxv = max(arr) if arr else 0
    maxv = max(maxv, n)

    present = [0] * (maxv + 2)
    for x in arr:
        if x <= maxv:
            present[x] = 1

    cost = min(A, B)

    have = 0
    ans = 10**18

    for k in range(1, maxv + 1):
        if present[k]:
            have += 1
        need = k - have
        ans = min(ans, need * cost)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策では、まず問題を、関連するすべての Quirk 番号にわたるプレゼンス配列に圧縮します。 同じ番号のコピーが複数あっても、より多くの要件を満たすのに役立たないため、ブール マーカーを使用すると、重複を二重にカウントすることを回避できます。 

変数には、現在の K までにすでに満たされている必要な数値の数が追跡されます。各ステップでこれが増分更新され、再計算が回避されます。 コストの計算は、欠落している数値のそれぞれに同じ固定量のコストがかかるという観察から直接得られます。 

微妙な点は、K の上限を選択することです。max(arr) まで上げるだけで十分です。既存の最大値より大きい K は、利用可能な要素を増やさずに必要な要素のみを増やすため、その点を超えるとコストは単調減少しません。

 ## 特殊なケース

 重要なエッジケースは、すべてのカードが 1 つの固有番号の重複である場合です。 その場合、K = 1 のみが何らかの利点をもたらし、K が大きくなるたびに完全な構築が必要になります。 have の増加は 1 回だけであり、K が増加するにつれてすべての欠損値が正しくカウントされるため、アルゴリズムはこれを処理します。 

別のエッジ ケースは、A が B に等しい場合に発生します。この場合、取引と購入は同等であり、解決策は単純に欠損値を数えることになります。 costPerFix は構造に依存しないため、アルゴリズムは引き続き有効です。 

最後のエッジ ケースは、最大クワイク数が N よりもはるかに大きい場合です。既存の値の増分のみがあり、他のすべてが線形的にコストに寄与するため、スイープは依然としてスパース プレゼンスを正しく処理します。
