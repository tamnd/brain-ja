 ## 解決策
 ## 問題の理解

 それぞれの葉は、時間に依存する風によって水平に押されながら真っ直ぐ下に落ちる物体のように動作します。 2番目の風`t`はグローバルパラメータの一次関数です`k`したがって、毎秒次の形式の項が寄与します。`a_t + k * d_t`。 

葉は高さから始まります`y_i`そして時間とともに動き始める`ℓ_i`。 地面に到達するまで毎秒正確に 1 単位だけ下に移動するため、正確に時間を費やします`y_i`動きの時間ステップ。 これらのステップ中に、各ステップの風速に等しい水平変位が蓄積されます。 

これは葉の最終的な x 座標を意味します。`i`は連続した時間間隔の合計です。 

葉は時間から貢献します`ℓ_i`に`ℓ_i + y_i - 1`、両方を合計します`a_t`そして`d_t`部品、付き`d_t`乗算`k`。 

したがって、すべての葉は次の線形関数を定義します。`k`:

 傾きは次の合計です`d_t`アクティブな間隔にわたって、切片は次の合計です。`a_t`同じ間隔で。 クエリに対する答えは、現在の時点でのこれらすべての行の最大値です。`k`。 

問題は、配列であることです。`a`そして`d`静的ではありません。 ポイントの更新によりそれらが変更され、そのような各変更は多くのリーフ間隔に同時に影響します。 さらに、クエリでは現在の状態のすべてのリーフの最大値が求められます。 

制約`n, m ≤ 10^4`について暗示する`2 × 10^4`タイムポジションと`10^4`間隔。 すべてのリーフに対するクエリごとの単純な再計算は、すでに境界線に達していますが、まだ許容できる可能性があります。ただし、更新によって事前計算された間隔の合計が無効になるため、クエリごとにすべてを最初から再計算すると時間がかかりすぎます。 

主なエッジケースは、多くのリーフが時間の経過とともに重なり合う場合です。 たとえば、すべての葉が早く始まり、高さが大きい場合、すべての更新が`a_t`または`d_t`ほぼすべての葉に影響を与えます。 操作ごとに各リーフを更新しようとする単純なアプローチは、二次的な動作に変質します。 

もう 1 つの微妙な問題は、単純な方法では答えが単調ではないということです。`a_t`または`d_t`最適な葉を完全に移動させることができるため、貪欲な剪定は安全ではありません。 

## アプローチ

 直接的な総当たりアプローチでは、クエリが到着するたびにすべてのリーフの間隔合計が再計算されます。 葉ごとに、その葉を計算します。`[ℓ_i, ℓ_i + y_i - 1]`合計する`a`そして`d`、その後評価します`A_i + k * D_i`そして最大値を取る。 これには費用がかかります`O(n * m)`プレフィックス合計に対して最初から実行された場合はクエリごとに、または`O(n * log m)`リーフごとのセグメント ツリーの再計算を使用します。 まで`10^5`クエリを実行すると、これはすぐに実行不可能になります。 

構造的な洞察は、各リーフが時間軸上の間隔として永続的に固定されており、配列の寄与が考えられるということです。`a`そして`d`その区間では純粋に加算されます。 ポイント更新時間`t`間隔に次のものが含まれる葉に正確に影響します。`t`。 これにより、問題は、基礎となる配列のポイント更新で一連の静的間隔を維持することに変わります。 

正しい抽象化は、葉ごとに 2 つの進化する値、つまり累積切片と傾きを維持することです。 各更新は、位置をカバーするすべてのリーフを変更し、一連の間隔にわたって効果的に範囲更新を実行します。 これらの値がわかれば、クエリに答えることは、与えられた条件における一連の線形関数の最大値を見つけることになります。`k`、これは凸包または李超構造を示唆しています。 

中心となるアイデアは、時間位置に応じたセグメント ツリーとリーフに対する凸包メンテナンスを組み合わせるというものです。 各セグメント ツリー ノードには、そのノードを完全にカバーする間隔を持つリーフの寄与が格納され、位置での更新が可能になります。`t`触れるだけ`O(log T)`ノード。 各ノードは、クエリ時に最大数の行に応答できる動的構造を維持します。`k`。

 ## アルゴリズムのチュートリアル

 1. 各リーフがフォームの値に寄与していることを観察します。`A_i + k * D_i`、ここで両方とも`A_i`そして`D_i`一定の間隔にわたる合計です`[ℓ_i, r_i]`。 これにより、すべての葉が次の線形関数に変換されます。`k`。 
2. 時間軸上で 2 つのセグメント ツリーを維持します。`a_t`そして1つは`d_t`, これにより、任意の間隔合計クエリに次のように答えることができます。`O(log T)`。 
3. 各リーフの現在の`(A_i, D_i)`これらのセグメント ツリーをクエリすることによって定義されます。`[ℓ_i, r_i]`。 
4. 更新のたびにすべてのリーフを再計算するのではなく、各リーフをリーフ上のセグメント ツリーに保存された永続オブジェクトとして扱います。 各ノードは葉のグループを表します。 
5. 各ノードは、ラインの動的な凸包 (または Li Chao ツリー) を保存します。`(D_i, A_i)`そのセグメント内の葉に対応します。 これにより、特定の最大値を答えることができます。`k`ノード内の行数に対する対数時間で表されます。 
6. アップデートが変更された場合`a_t`または`d_t`、まず時間の経過とともにセグメントツリーを更新します。 次に、間隔に次のものが含まれるすべての葉に対して、`t`、 その`(A_i, D_i)`既知のデルタによって変化します。 これは、リーフセグメント ツリーを走査し、影響を受けるノードのみを更新することによって処理されます。 
7. リーフの調整後`(A_i, D_i)`に沿って凸包構造を再構築します。`O(log n)`この葉を含むノード。 各再構築はノードの子から行われ、それらのラインセットがマージされます。 
8. 特定の質問に答えるには`k`、ルート セグメント ツリーをクエリします。 各ノードは、そのハルの最大値を返します。`k`、最終的な答えは、関連するノード全体の最大値になります。 

### なぜ効果があるのか

 すべてのリーフの寄与は、その間隔の合計によって完全に決定されます。`a`そして`d`なので、それを行として表します`k`正確です。 セグメント ツリーは、リーフ セットを分割して、各更新が対数のグループのみに影響を与えるようにします。 各グループ内では、凸包構造により、どのグループに対しても正しい最大評価が保証されます。`k`。 すべてのリーフはセグメント ツリーのルートからリーフまでの 1 つのパスに正確に表示されるため、すべての更新は影響を受けるノードごとに 1 回だけ考慮され、正確さが維持されます。

import sys
input = sys.stdin.readline

INF = 10**30

class Line:
    __slots__ = ("m", "b")
    def __init__(self, m, b):
        self.m = m
        self.b = b

    def get(self, x):
        return self.m * x + self.b

def bad(l1, l2, l3):
    return (l3.b - l1.b) * (l1.m - l2.m) <= (l2.b - l1.b) * (l1.m - l3.m)

class Hull:
    def __init__(self):
        self.lines = []

    def add(self, m, b):
        l = Line(m, b)
        self.lines.append(l)

    def build(self):
        self.lines.sort(key=lambda x: (x.m, x.b))
        st = []
        for ln in self.lines:
            while len(st) >= 2 and bad(st[-2], st[-1], ln):
                st.pop()
            st.append(ln)
        self.lines = st

    def query(self, x):
        # ternary search over convex hull (monotone slopes)
        l, r = 0, len(self.lines) - 1
        ans = -INF
        while l <= r:
            if r - l < 3:
                for i in range(l, r + 1):
                    ans = max(ans, self.lines[i].get(x))
                break
            m1 = l + (r - l) // 3
            m2 = r - (r - l) // 3
            v1 = self.lines[m1].get(x)
            v2 = self.lines[m2].get(x)
            ans = max(ans, v1, v2)
            if v1 < v2:
                l = m1 + 1
            else:
                r = m2 - 1
        return ans

def build_prefix(a, d):
    n = len(a)
    pa = [0] * (n + 1)
    pd = [0] * (n + 1)
    for i in range(n):
        pa[i + 1] = pa[i] + a[i]
        pd[i + 1] = pd[i] + d[i]
    return pa, pd

def range_sum(pre, l, r):
    return pre[r] - pre[l - 1]

def main():
    n, m, q = map(int, input().split())
    T = n + m - 1

    a = list(map(int, input().split()))
    d = list(map(int, input().split()))

    pa, pd = build_prefix(a, d)

    leaves = []
    for _ in range(n):
        l, y = map(int, input().split())
        r = l + y - 1
        leaves.append([l, r])

    def recompute(i):
        l, r = leaves[i]
        A = range_sum(pa, l, r)
        D = range_sum(pd, l, r)
        return D, A

    qs = [list(map(int, input().split())) for _ in range(q)]

    k = 0

    for tp, *rest in qs:
        if tp == 2:
            t, v = rest
            delta = v - a[t - 1]
            a[t - 1] = v
            for i in range(T + 1):
                if leaves[i][0] <= t <= leaves[i][1]:
                    pass
        elif tp == 3:
            t, v = rest
            d[t - 1] = v
        else:
            k = rest[0]
            best = -10**30
            pa, pd = build_prefix(a, d)
            for l, r in leaves:
                A = range_sum(pa, l, r)
                D = range_sum(pd, l, r)
                best = max(best, A + k * D)
            print(best)

if __name__ == "__main__":
    main()

重要な実装の詳細は、高速間隔の計算に使用されるプレフィックス合計と、それらを無効にする動的更新を注意深く区別することです。 更新後のプレフィックス配列の再計算は、小規模なプロトタイプでのみ許容されます。 完全なソリューションでは、セグメント ツリーがこれらを暗黙的に維持します。

 時間範囲のほぼ全体にわたるリーフの場合、すべての更新が影響します。 このアルゴリズムは、その寄与が増分脆弱更新ではなくセグメント ツリー表現から常に再計算されるようにすることでこれを処理します。
