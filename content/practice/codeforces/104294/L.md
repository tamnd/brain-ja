 ## 解決策
 ## 問題の理解

 画像を表す整数の長方形グリッドが与えられます。 各セルはピクセルであり、その値は強度です。 グリッドは単なる平面配列ではなく、トーラスです。右端から離れると左に戻り、上から離れると下に戻ります。 すべての操作は、このラップアラウンド ジオメトリを尊重する必要があります。 

次に、この画像に一連の変換を適用します。 各変換では現在の画像から新しい画像が生成されますが、ルールは読み取る情報と値を更新する方法が異なります。 シフト、反転、回転など、純粋に幾何学的な操作もあります。 その他は、ブラーやシャープなど、ラップされたグリッド内のピクセルの近傍に依存するローカル フィルターです。 

重要な点は、すべての近傍ベースの操作は一貫したソース イメージから読み取る必要があることです。 ブラーとシャープの場合、定義は部分的に更新されたものではなく、その操作の入力イメージを明示的に参照します。 これが正しく実装されていない場合、インプレース更新により近隣の計算が破損します。 

次元の点では制約は小さく、n と m は両方とも最大 100 ですが、演算の数は最大 1000 まで可能です。これにより、およそ O(k · n · m) よりも高価なものは排除されます。 操作ごとの O(n²) 以上のアプローチは問題ありません。 非効率的な方法で大規模な構造のディープ コピーを繰り返すことを伴うものはすべて合格する可能性がありますが、慎重に扱わないと定数問題が発生する危険があります。 

最も危険なエッジケースは、ジオメトリと畳み込みを混合することで発生します。 たとえば、ぼかしとシャープ化には、両方向のラップアラウンド インデックスが必要です。 モジュロ演算を忘れた単純な実装では、不正確な境界線が生成されます。 もう 1 つの問題は、回転によって次元が変化することです。90 度回転すると、n と m が入れ替わるため、固定次元を想定しているコードは壊れてしまいます。 

最後の微妙なケースは、演算の順序です。各変換は前の変換の結果に適用されるため、1 つのステップでの小さな間違いさえも前方に伝播します。 

## アプローチ

 簡単なアプローチは、説明どおりに各操作を正確にシミュレートすることです。 幾何学的変換の場合、インデックス演算を使用して各出力セルをソース位置にマッピングし直すことによって、新しいグリッドを構築します。 ブラーとシャープの場合、現在のグリッド上の 3×3 近傍を使用して値を計算し、モジュロ n と m を使用してインデックスをラップするように注意します。 

各操作はローカルに定義され、現在の状態のみに依存するため、この直接シミュレーションは正しいです。 ただし、グリッドからの読み取り中にグリッドを変更しないように注意する必要があります。 ブラーまたはシャープ化中に値を上書きすると、後続の近隣クエリで破損したデータが使用され、正確さが損なわれます。 

操作あたりのブルート フォース コストは、近傍操作の場合は O(n · m · 9)、幾何学的変換の場合は O(n · m) です。 k 回の操作で、これは O(k · n · m) となり、最悪の場合、約 10⁸ の操作になります。 過剰なオーバーヘッドなしで適切に実装されている場合、これは Python で許容されます。 

グリッドが小さく、k が中程度であるため、FFT ベースの畳み込みや遅延変換などの高度な最適化は必要ありません。 重要な洞察は、正確さはアルゴリズムのショートカットからではなく、操作ごとの入力グリッドと出力グリッドの厳密な分離から得られるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k・n・m) | O(n・m) | 承認済み |
 | 最適なシミュレーション | O(k・n・m) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のイメージをグリッドとして維持し、操作ごとに段階的に更新します。

1. 現在のグリッドを読み取り、その次元 n と m を追跡します。 これらの寸法は回転後に変更される可能性があるため、常に現在の状態を反映する必要があります。 
2. ぼかし操作の場合は、同じサイズの新しいグリッドを構築します。 各セル (i, j) について、行インデックスと列インデックスの両方にモジュロ演算を使用して、(i, j) を中心とする 3×3 近傍内のすべての値の合計を計算します。 平均の下限を新しいセルに割り当てます。 この分離により、常に元のイメージから読み取ることが保証されます。 
3. シャープ操作の場合は、再度新しいグリッドを構築します。 各セルについて、それ自体を除く 3×3 の近傍をスキャンします。 現在の値がすべての隣接値よりも厳密に大きい場合は、100 を加算します。現在の値がすべての隣接値よりも厳密に小さい場合は、100 を減算します。それ以外の場合は、変更しないでください。 比較は元のグリッドに対して行う必要があります。 
4. シフト演算の場合、各セル (i, j) が (i - y, j - x) から値を取得し、調整された法 n および m となる新しいグリッドを構築します。 垂直方向のシフトは行の移動に対応し、水平方向のシフトは列の移動に対応します。 
5. 水平反転の場合は、各行を個別に反転します。 これは、垂直軸を横切る反射に対応します。 
6. 垂直反転の場合は、行の順序を逆にします。 
7. 時計回りに回転するには、サイズ m × n の新しいグリッドを構築し、(i, j) を (j, n - 1 - i) にマッピングしてから、n と m を交換します。 
8. 反時計回りの場合は、サイズ m × n の新しいグリッドを構築し、(i, j) を (m - 1 - j, i) にマッピングしてから、n と m を交換します。 
9. k 個の操作がすべて処理されるまで繰り返し、常に現在のグリッドを新しく構築されたグリッドに置き換えます。 

これが機能する理由は、各操作の後、グリッドが問題によって定義された画像の状態を完全に表すという不変条件に基づいています。 すべての変換は、ある完全なグリッドから別の完全なグリッドへの純粋な関数として実装され、計算中に古い状態と新しい状態が混在することはありません。 これにより、近傍クエリが常に画像の正しいスナップショットを参照し、すべての幾何学的変換がモジュール式インデックス付けまたは座標再マッピングの下で​​正しいピクセル対応関係を保持することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def blur(grid, n, m):
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            s = 0
            for di in (-1, 0, 1):
                for dj in (-1, 0, 1):
                    ni = (i + di) % n
                    nj = (j + dj) % m
                    s += grid[ni][nj]
            res[i][j] = s // 9
    return res, n, m

def sharpen(grid, n, m):
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            cur = grid[i][j]
            mn = float('inf')
            mx = -float('inf')
            for di in (-1, 0, 1):
                for dj in (-1, 0, 1):
                    if di == 0 and dj == 0:
                        continue
                    ni = (i + di) % n
                    nj = (j + dj) % m
                    val = grid[ni][nj]
                    mn = min(mn, val)
                    mx = max(mx, val)
            if cur > mx:
                res[i][j] = cur + 100
            elif cur < mn:
                res[i][j] = cur - 100
            else:
                res[i][j] = cur
    return res, n, m

def shift(grid, n, m, x, y):
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            ni = (i - y) % n
            nj = (j - x) % m
            res[i][j] = grid[ni][nj]
    return res, n, m

def flip_h(grid, n, m):
    res = [row[::-1] for row in grid]
    return res, n, m

def flip_v(grid, n, m):
    return grid[::-1], n, m

def rot_cw(grid, n, m):
    res = [[0] * n for _ in range(m)]
    for i in range(n):
        for j in range(m):
            res[j][n - 1 - i] = grid[i][j]
    return res, m, n

def rot_ccw(grid, n, m):
    res = [[0] * n for _ in range(m)]
    for i in range(n):
        for j in range(m):
            res[m - 1 - j][i] = grid[i][j]
    return res, m, n

def main():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    k = int(input())

    for _ in range(k):
        parts = input().split()
        if parts[0] == "Blur":
            grid, n, m = blur(grid, n, m)
        elif parts[0] == "Sharpen":
            grid, n, m = sharpen(grid, n, m)
        elif parts[0] == "Shift":
            x, y = map(int, parts[1:])
            grid, n, m = shift(grid, n, m, x, y)
        elif parts[0] == "Flip":
            if parts[1] == "Horizontal":
                grid, n, m = flip_h(grid, n, m)
            else:
                grid, n, m = flip_v(grid, n, m)
        elif parts[0] == "Rotate":
            if parts[1] == "CW":
                grid, n, m = rot_cw(grid, n, m)
            else:
                grid, n, m = rot_ccw(grid, n, m)

    for row in grid:
        print(*row)

if __name__ == "__main__":
    main()
```実装では、各変換が独自の純粋な関数に分離されます。 これにより、部分的に更新された状態を誤って再利用することが回避されます。 ブラーとシャープの場合、計算中に元のグリッドが変更されることはなく、近傍クエリの正確性が維持されます。 幾何学的演算の場合、ラップアラウンド動作がモジュロ演算によって自然に処理されるように、座標マッピングが明示的に行われます。 

微妙な点の 1 つは、寸法の追跡です。 回転後、n と m が交換され、後続の操作に直ちに反映される必要があります。 もう 1 つはシフト方向です。垂直方向のシフトは、y が増加すると上に移動するため、行インデックスに負の符号を付けて影響します。これは、一般的な行列表現における行インデックスの減少に対応します。

 ## 特殊なケース

 重要なエッジケースは、コーナーでの回り込みブラーです。 (0,0) のセルの場合、その隣接セルには最後の行と最後の列のセルが含まれます。 モジュロベースのインデックス付けにより、(n-1, m-1) から値が正しく取得されることが保証されますが、生のインデックスを使用する実装では、誤って境界外にクリップまたはインデックス付けが行われます。 たとえば、値が増加する 3 × 3 グリッドでは、左上のぼかしに右下の値が含まれており、平均に大きな影響を与えます。 

もう 1 つのエッジ ケースは、すべての近傍が中心に等しい場合にシャープになります。 その場合、どちらの条件もトリガーされず、値は変更されないままでなければなりません。 ここでの間違いは、非厳密な比較を使用することです。これにより、フラット領域が誤って変更されてしまいます。 

回転エッジ ケースは非正方行列で発生します。 2×3 のグリッドを時計回りに回転すると 3×2 になります。 固定次元のバッファーは、操作ごとに再割り当てされない限り壊れます。
