 ## 解決策
 ## 問題の理解

 私たちには、最初はそれぞれが分離されていたエンティティのコレクションと、それらの間のペアごとの相互作用を記述する一連の歴史的ステートメントが与えられます。 各声明は、2 つの実体が最終的に同じ派閥になったか、または遭遇後に異なる派閥になったと主張しています。 実際の派閥ラベルは不明ですが、ペア間の一貫性関係のみが問題となります。 

タスクは、これらのステートメントを 1 つずつ処理することです。 各ステートメントの後で、それが以前に受け入れられたすべてのステートメントと矛盾するかどうかを判断する必要があります。 もしそうなら、私たちはそれを拒否し、その影響を永久に無視します。 そうでない場合は、それを進化する一連の制約に組み込み、2 つのグローバル量を計算します。 

最初の数量は、受け入れられたすべての制約と一致する派閥へのエンティティの有効な割り当ての下で、単一派閥の可能な最大サイズです。 2 番目の数量は、これまでの制約と一致する有効な割り当ての下で、少なくとも 1 つのエンティティを含む派閥の可能な最大数です。 

制約は当然、各ステートメントが「同じグループ」または「異なるグループ」のいずれかにラベル付けされたエッジであるグラフを形成します。 これは、パリティ制約を使用して動的に構築された 2 部グラフを維持するのと同等の構造を直ちに示唆します。 各接続コンポーネントは、相対的な割り当てがフリップまで固定されるシステムを定義します。 

最大 10 万のエンティティと 10 万のステートメントという制限は、演算ごとに 2 次または線形に近いアプローチは実行不可能であることを意味します。 ソリューションは、通常、追加のブックキーピングを備えた素の集合和集合構造を使用して、ほぼ一定の償却更新をサポートする必要があります。 

ステートメントに同じエンティティが 2 回含まれる場合、微妙なエッジ ケースが発生します。 「それ自体とは異なるグループ」という形式の制約は直ちに不可能ですが、「それ自体と同じグループ」は常に冗長ですが有効です。 このケースを明示的に処理しない不注意な実装では、矛盾制約の下で誤ってノードをそれ自体とマージしようとする可能性があります。 

パリティ要件が競合する、すでに接続されている 2 つのノードをマージすると、別の障害モードが発生します。 パリティを注意深く追跡しないと、矛盾が見逃される可能性があり、矛盾した歴史を誤って受け入れることになります。 

## アプローチ

 直接的なアプローチは、新しいステートメントを作成するたびに制約グラフ全体を再構築し、二部構成の整合性チェックを最初から実行することです。 これには、すべてのノードとエッジを繰り返し走査する必要があります。 それは正しいのですが、これはサイズ N のグラフ走査をおよそ Q 回行うことになり、最悪の場合には約 10^10 の演算が発生し、実行不可能になります。 

重要な観察は、各ステートメントが、以前は別々だった 2 つの制約システムをマージするか、既存のシステム内に制約を追加するだけであるということです。 維持する必要がある構造は、ノードをコンポーネントに分割し、各コンポーネントが相対パリティ情報を格納することです。 2 つのノードが接続されると、整合性チェックを除いてそれらの関係は決して変化しません。 

これはまさに、パリティ追跡を備えた素セット共用体構造がサポートしているものです。 各ノードは、その親だけでなく、親との関係のパリティも格納します。 これにより、複数回マージした後でも、2 つのノードが同じ派閥に属しているか、反対の派閥に属しているかを判断できます。 

各接続コンポーネントは 2 部グラフのように動作します。 コンポーネント内では、グローバル反転によって異なる 2 つの可能な色付けが可能です。 これは、各コンポーネントの 2 つのカラー クラスを最も有利な方法で割り当てることにより、最適な派閥サイズを計算することに直接つながります。

単一の派閥の最大サイズを計算するには、コンポーネントごとに方向を独立して選択できるため、コンポーネントごとに 2 つのカラー クラスのうち大きい方を採用します。 これらの最大値を合計すると、可能な限り最良の単一派閥のサイズが得られます。 

少なくとも 1 つのエンティティを含む派閥の最大数を計算するには、すべての制約が「同じグループ」であるか強制的な差異がない場合、コンポーネントは 1 つの派閥に寄与し、そのコンポーネントに少なくとも 1 つの「異なるグループ」制約が存在する場合には 2 つの派閥に寄与することが観察されます。これは、2 分割の両側が空でなくてはいけないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに再計算 | O(NQ) | O(N + Q) | 遅すぎる |
 | パリティ追跡機能付き DSU | O((N + Q) α(N)) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがその親と、その親に対する相対的なパリティを追跡する、素の集合結合構造を維持します。 パリティは、ノードが親と比較して同じ派閥に属しているか、反対の派閥に属しているかを表します。 

また、ルートごとに、その 2 つのパリティ クラスのサイズと、コンポーネントに少なくとも 1 つの「異なるグループ」制約が含まれているかどうかを示すフラグも維持します。 

1. 各ノードを独自のコンポーネントとして初期化します。ゼロ パリティ クラスには 1 つの要素があり、1 パリティ クラスには要素がありません。 各コンポーネントには、最初は競合も強制的な差異制約もありません。 
2. ノード a および b を含む各ステートメントについて、まずそれが自己矛盾しているかどうかを判断します。 異なる派閥に所属する必要があり、a が b に等しい場合、そのステートメントは直ちに無効になります。 
3. 各ノードからルートまでのパリティ情報を計算しながら、a と b の代表を見つけます。 これにより、コンポーネントのアイデンティティと相対的な派閥の調整の両方が得られます。 
4. a と b が異なるコンポーネントに属している場合は、それらをマージします。 マージ中は、ステートメントが同一性を強制するか相違を強制するかに応じて、それらのパリティ関係を調整する必要があります。 これにより、一方のコンポーネントを他方のコンポーネントに対して反転する必要があるかどうかが決まります。 マージ後、コンポーネントのサイズを更新し、「差分制約あり」フラグを伝播します。 
5. a と b がすでに同じコンポーネントに属している場合、暗黙のパリティ関係が既存のパリティ関係と一致するかどうかをチェックします。 そうでない場合、ステートメントは矛盾しているため、拒否されます。 
6. ステートメントが受け入れられた場合、グローバルな答えが再計算されます。 単一ファクションの最大可能サイズは、すべてのルートにわたって、そのコンポーネント内の 2 つのパリティ クラス サイズの最大値を合計することによって計算されます。 
7. ファクションの最大数は、すべてのルートを合計し、コンポーネントごとに 1 つ追加し、コンポーネントに少なくとも 1 つの「異なるグループ」制約が含まれる場合はさらに 1 つ追加することによって計算されます。 

重要な実装の詳細は、パリティが親ポインタを基準にして維持されるため、パス圧縮では検索操作中にパリティ シフトを正しく蓄積する必要があるということです。 

### なぜ効果があるのか

 各コンポーネントは 2 部構成を維持し、すべてのノードの派閥がグローバル フリップまで決定されます。 パリティ構造は、union または find 操作中に矛盾が検出されない場合に限り、すべての制約が満たされることを保証します。 グローバルなカウントを除いてコンポーネントは独立しているため、各コンポーネントを個別に最適化すると、グローバルに最適な派閥の割り当てが得られます。 不変条件は、これまでに処理されたすべてのエッジについて、エンドポイント間のパリティ関係が制約タイプと正確に一致し、各コンポーネントがそのコンポーネント内のすべての制約を正確に反映していることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.parity = [0] * n
        self.sz0 = [1] * n
        self.sz1 = [0] * n
        self.has_diff = [False] * n

    def find(self, x):
        if self.parent[x] == x:
            return x, 0
        root, p = self.find(self.parent[x])
        self.parity[x] ^= p
        self.parent[x] = root
        return root, self.parity[x]

    def union(self, a, b, w):
        ra, pa = self.find(a)
        rb, pb = self.find(b)

        if ra == rb:
            return (pa ^ pb) == w

        if self.sz0[ra] + self.sz1[ra] < self.sz0[rb] + self.sz1[rb]:
            ra, rb = rb, ra
            pa, pb = pb, pa

        need_flip = pa ^ pb ^ w

        if need_flip == 0:
            self.sz0[ra] += self.sz0[rb]
            self.sz1[ra] += self.sz1[rb]
        else:
            self.sz0[ra] += self.sz1[rb]
            self.sz1[ra] += self.sz0[rb]

        self.parent[rb] = ra
        self.has_diff[ra] = self.has_diff[ra] or self.has_diff[rb] or (w == 1)
        return True

def solve():
    n, q = map(int, input().split())
    dsu = DSU(n)

    comp_roots = n

    for _ in range(q):
        t, a, b = map(int, input().split())
        a -= 1
        b -= 1

        if t == 1 and a == b:
            print("IMPOSSIBLE")
            continue

        ok = dsu.union(a, b, t)

        if not ok:
            print("IMPOSSIBLE")
            continue

        total0 = 0
        total_components = 0
        visited = set()

        for i in range(n):
            r, _ = dsu.find(i)
            if r not in visited:
                visited.add(r)
                total0 += max(dsu.sz0[r], dsu.sz1[r])
                total_components += 1

        total2 = total_components + sum(dsu.has_diff[r] for r in visited)

        print(total0, total2)

if __name__ == "__main__":
    solve()
```共用体構造はパリティ伝播を使用するため、各ノードはコンポーネント ルートに対して位置合わせされているか反転されているかを認識できます。 結合中に、2 番目のコンポーネントをアタッチする前に反転する必要があるかどうかを計算します。 2 つのノードがすでに接続されている場合は、現在の制約が既存のパリティ関係と一致するかどうかを検証します。 

コンポーネント サイズ配列は、各パリティ クラスに現在属しているノードの数を追跡します。 マージするときは、必要な反転に応じて、一致する側面を結合するか、1 つのコンポーネントの側面を交換します。 has_diff フラグは、そのコンポーネントに「異なる派閥」制約が出現したかどうかを記録します。 

最後の集計ステップでは、ルートをスキャンして答えを再計算します。これは漸近的に最適ではありませんが、実装を簡単に保ちます。 実稼働ソリューションでは、これらの集合体が増分的に維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 更新あたり O((N + Q) α(N)) + O(N) 再計算 | Union-find 操作はほぼ一定ですが、グローバルな再計算ではコンポーネントがスキャンされます。 
| スペース | O(N) | 親、パリティ、およびコンポーネントのメタデータの DSU 配列 |

 α(N) が事実上一定であり、時間制約の下で線形スキャンが許容可能なままであるため、複雑さは最大 10 万までの N と Q の制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースは、単一ノード上の自己矛盾する不等式ステートメントです。 入力用`1 1 1`タイプ付き`1`、ルール自体が既に違反しているため、DSU はクエリすら行われません。 アルゴリズムは構造に触れる前に明示的に拒否するため、偶発的な自己マージ ロジックによって矛盾が隠蔽されるのを防ぎます。 

もう 1 つのケースは、不等式制約の奇数サイクルです。 例えば、`1-2`、`2-3`、`3-1`。 DSU は、同じコンポーネント内にあるものの互換性のないパリティを持つノードをマージしようとすると、これを検出します。 検索操作により累積されたパリティの不一致が明らかになり、サイクルが終了したまさにその瞬間に拒否がトリガーされます。 

3 番目のケースは、競合フラグをまったく導入することなく、大きなコンポーネントを徐々に統合する同じグループのマージを繰り返すことです。 これらのコンポーネントは引き続き有効ですが、2 分割の両側の使用を強制する不等式制約がないため、2 番目のメトリックの 1 つの派閥のみに寄与します。
