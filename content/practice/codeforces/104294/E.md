 ## 解決策
 ## 問題の理解

 それぞれ整数のパワー値を持つモンスターの列が与えられています。 これらのモンスターの連続したブロックを選択し、それらの力の合計を計算したいと考えています。 可能なすべての連続ブロックの中で、合計ができるだけ大きいブロックが必要であり、その合計を出力します。 

入力は単なる整数のシーケンスです。 各整数は、正、負、またはゼロにすることができます。 有効な選択はインデックス i から j までの任意の間隔であり、そのスコアはその間隔内の要素の合計です。 タスクは、そのようなすべての間隔にわたって可能な最大スコアを見つけることです。 

制約では、最大 100,000 個の要素、最大 10^9 の大きさの値が許可されます。 これにより、すべてのサブ配列を明示的に試行するソリューションは即座に除外されます。 単純な O(n^2) 列挙では、最悪の場合でもすでに約 50 億の間隔が計算されており、それぞれに O(n) の合計が必要な場合、O(n^3) になり、制限時間を大幅に超えます。 Python では O(n^2) でも 1 秒未満では遅すぎます。 

微妙な点は、すべての数値が負の場合の処理​​です。 よくある間違ったアプローチは、空の部分配列を選択できると仮定して 0 を返すことです。 この問題では空の部分配列は許可されないため、少なくとも 1 つの要素を選択する必要があります。 たとえば、入力の場合`[-5, -2, -8]`、正解は`-2`、 ない`0`。 

もう 1 つの特殊なケースは、単一要素の配列です。 のために`[7]`、答えは`7`、そして不注意に最良の合計を 0 に初期化するロジックはここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての可能な開始インデックスを考慮し、それをすべての可能な終了インデックスまで拡張し、合計を計算し、最大値を追跡します。 すべての連続する部分配列が明示的に評価されるため、これは正しいです。 ただし、合計を繰り返し再計算することでコストが発生します。 約 n(n+1)/2 の部分配列があり、増分合計を使用した場合でも、これは O(n^2) 回の演算であり、100000 個の要素には遅すぎます。 

重要な観察は、左から右にスキャンすると、位置 i で終わる最良のサブ配列が i-1 で終わる最良のサブ配列を拡張するか、または i で新たに開始されるということです。 現在の合計がマイナスになった場合、それを維持すると、拡張から減算されるため、将来の合計が悪化するだけです。 これにより、各ポジションで単一のランニングベストエンドを維持するという問題が軽減されます。 

これが Kadane のアイデアの本質です。すべてのパーティションを探索するのではなく、各インデックスで終わるすべてのサブ配列の選択肢を 1 つの状態に圧縮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | オプティマル (カダネ) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の位置で終わる最良の合計と、これまでに確認された全体的な最良の答えという 2 つの値を維持しながら、配列を左から右に処理します。 

1. 現在の累計とグローバル最良の回答の両方を配列の最初の要素で初期化します。 これにより、すべての値が負の場合でも正確さが保証されます。 
2. 次の要素 p[i] ごとに、前の部分配列を拡張するか、i で新しい部分配列を開始するかを決定します。 新しい実行合計を p[i] と current_sum + p[i] の最大値として計算します。 この選択は、以前の累積合計が有益であるか有害であるかを反映します。 
3. グローバル最良の回答を、それ自体の最大値と新しい累計として更新します。 これにより、最後のインデックスで終わるサブ配列だけでなく、配列内のどこにでも見られる最良のサブ配列が確実に記録されます。 
4. 配列の最後まで続行し、グローバル最良の回答を出力します。 

コアの決定は各インデックスで行われます。前の合計が負の場合、それを現在の要素に追加しても結果が減少するだけなので、再起動が最適です。 正の場合、拡張すると合計が向上します。 

### なぜ効果があるのか

 すべてのインデックス i において、アルゴリズムは、現在の実行合計が、正確に i で終了する必要があるサブ配列合計の最大値であるという不変条件を維持します。 i で終わるサブ配列は、i-1 で終わるサブ配列を拡張するか、i で新たに始まるかのいずれかになります。 両方の可能性が明示的に比較されるため、有効な候補が見逃されることはありません。 グローバル最大値はすべてのエンドポイントの中で最も優れたものを追跡するため、スキャンが完了すると、アレイ全体で最も優れたサブアレイと等しくなる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

cur = a[0]
best = a[0]

for i in range(1, n):
    cur = max(a[i], cur + a[i])
    best = max(best, cur)

print(best)
```この実装は、前述の状態遷移を直接反映しています。`cur`現在の位置で終了する最良の部分配列の合計を保存します。`best`大域的最適を追跡します。 両方を初期化すると、`a[0]`すべてが負の配列の誤った処理を回避します。 

重要な詳細は更新の順序です。新しい値を計算する必要があります。`cur`更新する前に`best`、 以来`best`i で終わる更新された部分配列に依存します。 もう 1 つの微妙な点は初期化です。これはデフォルトの 0 であってはなりません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    cur = a[0]
    best = a[0]

    for i in range(1, n):
        cur = max(a[i], cur + a[i])
        best = max(best, cur)

    return str(best)

# provided sample
assert run("9\n-2 10 -3 5 -2 1 2 6 -1\n") == "19"

# single element
assert run("1\n5\n") == "5"

# all negative
assert run("3\n-5 -2 -8\n") == "-2"

# all positive
assert run("4\n1 2 3 4\n") == "10"

# alternating
assert run("5\n1 -2 3 -2 5\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 5 | ベースの初期化 |
 | すべて否定的 | -2 | 空のサブ配列は許可されません |
 | すべて肯定的 | 10 | 完全な累積の正確性 |
 | 交互の値 | 5 | 再起動と拡張ロジック |

 ## 特殊なケース

 次のような単一要素配列の場合`[5]`、アルゴリズムが初期化されます`cur`そして`best`5に設定し、すぐに返します。 反復は必要なく、可能な部分配列は 1 つだけであるため、不変式は自明に成り立ちます。 

次のようなすべて負の配列の場合`[-5, -2, -8]`の場合、拡張しても値が減少するだけであるため、累計は各要素で繰り返し再開されます。 その痕跡は、`cur = -5, -2, -8`と`best = -2`、最小の負の要素を正しく選択します。 これは、アルゴリズムが、有害な場合に長いサブ配列を誤って優先していないことを示しています。
