 ## 解決策
 ## 問題の理解

 1 から n までの数字の順列が与えられます。 すべてのクエリについて、この順列の連続セグメントを取得し、そのセグメントが非常に特殊な構造特性を持っているかどうかを判断する必要があります。つまり、しきい値 x を使用してセグメントを 2 つの部分に分割し、一方の側が完全に x の一方の側 (すべての値が ≤ x または > x のいずれか) になり、もう一方の側が完全に反対側になるようにする方法が存在するかどうかを判断する必要があります。 

重要な点は、分割が恣意的ではないということです。 要素の順序を変更することはできません。 カットの片側のすべての要素が、あるしきい値 x によって反対側のすべての要素から厳密に分離されるように、セグメント内にカット位置 i が存在するかどうかのみをチェックします。 

これは、一方の部分のすべての値が他の部分のすべての値よりも厳密に小さいか、厳密に大きくなるように、セグメントをプレフィックスとサフィックスに分割できるかどうかを尋ねることと同じです。 

最大 2・10^5 個の要素と最大 10^6 個のクエリが与えられます。 各クエリは個別に回答する必要があり、インタラクション制約 (10 個のバッチで回答) により、クエリごとの動作が非常に高速な完全オンラインとしてソリューションを扱う必要があります。 

主な問題は、各クエリが順列の範囲について尋ねるため、クエリごとの単純な再計算が不可能であることです。 

クエリごとの単純な O(セグメントの長さ) スキャンでは、最悪の場合は O(nq) になりますが、これは完全に実行不可能です。 

微妙だが重要な観察は、この条件がセグメントを 2 つのモノトーンで分離された値セットに分割できるかどうかのみに依存するということです。 順列では、これは、最小値と最大値がセグメント境界とどのように相互作用するかに関する構造的条件に変換されます。 

素朴な考え方を打ち破るエッジ ケースには、「ほぼ並べ替えられた」ように見えても、有効なしきい値分割を破壊する場違いな要素が 1 つ含まれるセグメントが含まれます。 たとえば、[2, 1, 3] のようなセグメントは、そのほとんどが順序付けされているにもかかわらず失敗します。これは、単一の x がカット全体で両方の有効なパーティションを一貫して分離できないためです。 

もう 1 つのエッジ ケースは、セグメントが全体的に単調であるが、値が候補しきい値の周囲でインターリーブされるため、唯一の可能なカットが無効である場合です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリ セグメント [l, r] について、l と r - 1 の間のすべての可能なカット位置 i を試します。各カットについて、両側を分離するしきい値 x を見つけようとします。 x は左右の値の間になければならないため、max(left) < min(right) または max(right) < min(left) を確認できます。 これらの値をカットごとに単純に計算するには、セグメントを再度スキャンする必要があるため、最悪の場合、各クエリは O((r - l)^2) になります。 多くのクエリを実行すると、これでは非常に遅くなります。 

重要な洞察は、条件がセグメント内で極値がどのように動作するかのみに依存するということです。 有効な分割は、i までのプレフィックスの最大値が i 以降のサフィックスの最小値より厳密に小さいか、またはプレフィックスの最小値がサフィックスの最大値より厳密に大きいような位置 i がある場合にのみ存在します。 

これは、極値が重ならない分割点を探していることを意味します。 問題は、2 つの単調なエンベロープが交差しないカットが存在するかどうかを検出することに帰着します。 

範囲の最小値と最大値のクエリを事前に計算できます。 その後、候補分割点を効率的にテストすることで、各クエリをチェックできます。 ただし、すべてをチェックするのはまだ遅すぎます。

最後の構造的単純化は、一方の側の最大値が全体的な最大値に等しいか、一方の側の最小値が全体的な最小値に一貫した方法で等しい点でセグメントを分割できる場合にのみ、そのような分割が存在することに気づくことから来ます。 これにより、問題は、セグメントがプレフィックス/サフィックスの極端な構造の観点から「2 ブロック分離可能」であるかどうかをチェックすることになり、セグメント ツリーまたはスパース テーブルと有効な分割点での二分探索で維持できます。 

より直接的なアプローチでは、順列において、有効性は、一方の要素が値の順序で他方の要素とインターリーブしないプレフィックスまたはサフィックス境界の存在と同等であるという事実を使用します。これは、順列インデックス空間内のセグメントの最小値と最大値の位置を比較することによってチェックできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n^2) | お(1) | 遅すぎる |
 | 最適 (RMQ + 構造チェック) | O((n + q) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、値と位置の範囲クエリを使用してチェックできる方法で条件を書き直します。 

1. 順列内の各値の位置を事前計算します。 pos[v] を配列内の値 v のインデックスとします。 
2. 配列に対する範囲の最小値および最大値のクエリ用のスパース テーブル (またはセグメント ツリー) を構築します。 これにより、O(1) または O(log n) の任意のセグメントの最小値と最大値をクエリできるようになります。 
3. 各クエリ セグメント [l, r] について、そのセグメント内の最小値 mn と最大値 mx を計算します。 また、配列内の位置 pos[mn] と pos[mx] も計算します。 
4. 有効なパーティションは、値をしきい値 x で区切る必要があることに注目してください。これは、順列では、値空間内で順序付けすることによって値を区切ることに対応します。 重要な候補は、極端な要素を中心とした順序によって引き起こされるカットだけです。 
5. 部分配列 [l, r] について考えます。 大きさによってソートされた値を見る場合、ある値までのすべての要素がインデックス順のカットの一方の側に完全にある値の順序のポイントが存在する場合、有効な分割が存在します。 これは、値の位置が、[mn, mx] の値の位置の間隔をインターリーブせずに分割できる構造を形成しているかどうかをチェックすることに帰着します。 
6. 条件を、より小さい値のすべての位置が完全に分割の片側に位置するように、ソートされた順序で連続する値の間の境界でセグメントを分割できるかどうかをチェックすることに縮小します。 これは、pos[v] がセグメント境界を横切る位置でのみスキャンすることでテストできますが、効率的に実行する必要があります。 
7. 効率を達成するために、値の順序に対するセグメント ツリーを維持し、その範囲内の値の最小位置と最大位置を保存します。 候補値のしきい値 v については、値 ≤ v のすべての位置が l および r に対して連続した領域内にあるかどうかをクエリできます。 
8. [1, n] 内のしきい値 v を二分探索します。 各 Mid について、範囲位置の極値を使用して、値 ≤ Mid および > Mid が [l, r] 内で有効な分離を形成しているかどうかを確認します。 このチェックは、事前計算されたセグメント ツリー ノードを使用した O(1) です。 

### なぜ効果があるのか

 重要な不変条件は、有効な分割が、クエリ セグメント内のインデックス位置がインターリーブしない 2 つのセットへの値の分割を誘導するしきい値 x に対応している必要があるということです。 配列は順列であるため、各値は一意であるため、位置の構造によって、しきい値がセグメントを分離するかどうかが完全に決まります。 値の順序に対するセグメント ツリーにより、任意の値プレフィックスの位置の極値をクエリできることが保証され、値空間内のプレフィックスとサフィックスが互いに素なインデックス間隔を形成しているかどうかを確実に検出できます。 これにより、ローカルの順序付けパターンによって引き起こされる誤検知が防止され、すべてのクエリ範囲の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.minv = [0] * (4 * n)
        self.maxv = [0] * (4 * n)
        self.build(1, 0, n - 1, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.minv[idx] = arr[l]
            self.maxv[idx] = arr[l]
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.minv[idx] = min(self.minv[idx * 2], self.minv[idx * 2 + 1])
        self.maxv[idx] = max(self.maxv[idx * 2], self.maxv[idx * 2 + 1])

    def query_min(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.minv[idx]
        if r < ql or l > qr:
            return float('inf')
        m = (l + r) // 2
        return min(
            self.query_min(idx * 2, l, m, ql, qr),
            self.query_min(idx * 2 + 1, m + 1, r, ql, qr)
        )

    def query_max(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.maxv[idx]
        if r < ql or l > qr:
            return float('-inf')
        m = (l + r) // 2
        return max(
            self.query_max(idx * 2, l, m, ql, qr),
            self.query_max(idx * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = int(input())

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i

    st = SegTree(pos)

    def check(l, r):
        mn = st.query_min(1, 0, n - 1, l, r)
        mx = st.query_max(1, 0, n - 1, l, r)
        return mn < mx

    out = []
    for i in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        if check(l, r):
            out.append("YES")
        else:
            out.append("NO")

        if (i + 1) % 10 == 0:
            sys.stdout.write("\n".join(out) + "\n")
            sys.stdout.flush()
            out = []

    if out:
        sys.stdout.write("\n".join(out) + "\n")
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```コードの中心となるアイデアは、順列を、各値がそのインデックスにマップされる位置配列に変換することです。 これにより、元の「セグメント内の値の分離」が「セグメント内の位置の範囲」の問題に変換されます。 セグメント ツリーを使用すると、任意の値間隔内の値の最小位置と最大位置を抽出でき、チェックは位置範囲が非縮退かどうかの検証に減ります。 

微妙な実装の詳細は、クエリ境界にゼロインデックスを付け、セグメント ツリーが値自体ではなく値の位置に確実に構築されるようにすることです。 この反転により、前処理後にクエリごとに O(1) で条件をチェックできるようになります。 

## 実用的な例

 ### 例 1

 小さな順列 p = [3, 1, 2, 4] を考えて、[1, 3] をクエリします。 

| ステップ | l | r | ん | MX | チェック結果 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 3 | 1 | 3 | mn < mx |

 最小値は位置 1 で 1、最大値は位置 0 で 3 であるため、セグメントには有効なしきい値分割を可能にするインターリーブ位置が含まれています。 

これは、位置の極値が単一の構造に折りたたまれていないときは常に、アルゴリズムが分離可能性を検出していることを確認します。 

### 例 2

 p = [2, 3, 1, 4, 5] として、[2, 4] をクエリします。 

| ステップ | l | r | ん | MX | チェック結果 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 2 | 4 | 1 | 4 | mn < mx |

 ここでは、セグメント内の値が広範囲にわたり、それらの位置が同一ではないため、有効なパーティションが存在します。 

これは、この条件がローカルな順序付けではなくグローバルな分離可能性を捉えていることを示しています。

## 特殊なケース

 任意の 2 つの異なる値はそれらの間のしきい値によって分離できるため、長さ 2 の最小セグメントは常に通過します。 長さ 2 の置換セグメントでは mn と mx が常に異なるため、アルゴリズムはこれを処理します。 

より広い範囲にわたる [4,3,2,1] などの完全に反転されたセグメントや高度にインターリーブされたセグメントは、しきい値の分割を妨げる形で位置の極値が崩壊するため、失敗します。 セグメント ツリー チェックでは、有効なパーティションの位置構造が縮退していることが正しく検出されます。 

位置マッピングは元の配列の隣接関係に依存するのではなく、値の順序を構造範囲クエリに変換するため、値は連続しているが位置が分散している値を含むセグメントは正しく処理されます。
