 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、選択した要素の値をその左側のすべてまたは右側のすべてに繰り返し「ブロードキャスト」することができます。 各ブロードキャストのコストは、上書きされる要素の数に比例し、伝播される値を乗算します。 目標は、支払いを最小限に抑えながら、配列全体を単一の値で構成することです。 

操作を再解釈する便利な方法は、すべての動きで位置を選択し、その位置の値をプレフィックスまたはサフィックス全体に拡張し、新たに影響を受けるすべてのインデックスを支払うことです。 要素は何度も上書きできるため、プロセスは単調ではありません。一度ペイントするだけではなく、後でより安価な値で領域を再ペイントする可能性があります。 

制約は大きく、テスト ケース全体の配列の合計サイズは最大 5×10^5 です。 これにより、テスト ケースごとに二次関数が即座に除外されます。 どのような解も本質的に線形または線形演算的でなければなりません。 これは、通常、等しい値の隣接性または最適なセグメンテーションに依存して、答えがローカル構造から計算可能である必要があることを示唆しています。 

いくつかの微妙な状況が素朴な推論を打ち破ります。 よくある間違いの 1 つは、左側と右側を端から貪欲に独立して「固定」できると想定していることです。 たとえば、次のような配列では、`[3, 1, 3]`、最小値またはエンドポイントから拡張しようとする貪欲な戦略は、最適な戦略が中間の値を使用して両側を安価にカバーすることを見逃す可能性があります。 

もう 1 つの問題は、それぞれの値が独立して寄与すると考えることです。 実際には、操作は大きく重複します。1 つの操作で大きな領域が置き換えられ、後で別の操作のベースとして再利用される可能性があるため、ローカルでの決定が誤解を招く可能性があります。 

## アプローチ

 ブルート フォース ビューでは、配列に望む最終的な値を検討します。 値を固定するとします`x`。 次に、配列全体を次のように変換する必要があります。`x`コピーする操作を使用する`x`選ばれた出来事から外側へ`x`。 複数のポジションを選択すると、`x`ソースとして、各ソースは左または右に展開され、カバーされたセグメントがマージされます。 単純な戦略では、各値の位置のすべてのサブセットを試し、可能なすべての展開シーケンスをシミュレートします。 これは発生数が指数関数的であり、単一のシミュレーションでさえ線形であるため、このアプローチは実行不可能です。 

重要な観察は、固定目標値の場合です。`x`、非を使用しても利益を得ることはありません。`x`ソースとしての値。 すべての操作は選択された単一の値を伝播するため、最終的にはすべての操作は値の発生に関連付けられ、値が大きいほど単位長あたりのコストが高くなるため、異なる値を使用するとコストが増加するだけです。 

さらに重要なことは、`x`、 2 つの連続する出現の間の配列`x`左側のオカレンスまたは右側のオカレンスのいずれかから入力できます。 これにより、連続する間の各ギャップというローカルな決定が作成されます。`x`ポジションは 1 回だけ「支払う」必要があり、コストは左から拡張するか右から拡張するかによって異なります。 

これにより、問題は次のように簡略化されます。各値について`x`、すべての位置を考慮します。`a[i] = x`。 これらの位置によって配列がセグメントに分割され、連続するオカレンス間の各セグメントはどちらの側からもカバーできます。 ギャップによってもたらされるコストは、ギャップの長さと、`x`。 すべてのギャップをカバーする最適な方法を計算します。これは、局所構造によって決定される最小の寄与を合計することになります。 

最後に、このコストを個別の値ごとに評価し、最小値を取得します。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、インデックスを値ごとにグループ化します。 

値の出現のみがその値のソースとして機能できるため、これらの位置が必要です。 
2. 個別の値ごとに`x`、ソートされた位置のリストを抽出します。`a[i] = x`。 

これらの位置は、拡張をどこに「固定」できるかを定義します。`x`。 
3. すべてを埋めるのに必要なコストを次を使用して計算します。`x`最終的な値として。 

概念的には、配列を連続した発生の間のセグメントに分割します。`x`。 
4. 連続する出現間のギャップごとに`p[i]`そして`p[i+1]`、その長さを計算します`len = p[i+1] - p[i] - 1`。 

これは、どちらかの側から拡張することによって上書きする必要がある要素の数です。 
5. このようなギャップはそれぞれ、以下に比例するコストに寄与します。`len * x`、その領域を効果的に埋めるには値を伝播する必要があるため`x`それらのポジションを越えて。 
6. 価値に対する総コスト`x`すべてのギャップの合計に、最初に出現する前のプレフィックスと最後の出現の後のサフィックスを処理するコストを加えたもので、これらは最も近い出現からのギャップとして扱われます。 
7. すべての個別の値の最小コストを取得します。 

### なぜ効果があるのか

 重要な不変条件は、固定値をターゲットとする最適な戦略において、`x`、すべての位置は、最終的に、最も近い発生から始まる展開によって埋められます。`x`最適な計画で最初に到達するものです。 オペレーションは常に一定の値を伝播し、コストは新たに上書きされるポジションの数に対して線形であるため、カバレッジを発生間の独立した間隔に分割することはロスレスです。どのオペレーションも必要なカバーされるポジションの総数を減らすことはできず、その支払い方法を再分配するだけです。 したがって、各差額は 1 回だけ支払われ、`x`すべてのコストはローカルで決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = {}
        for i, v in enumerate(a):
            pos.setdefault(v, []).append(i)

        ans = float('inf')

        for v, p in pos.items():
            cost = 0

            # left boundary gap
            if p[0] > 0:
                cost += (p[0]) * v

            # internal gaps
            for i in range(len(p) - 1):
                gap = p[i + 1] - p[i] - 1
                cost += gap * v

            # right boundary gap
            if p[-1] < n - 1:
                cost += (n - 1 - p[-1]) * v

            ans = min(ans, cost)

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、各候補の最終値を独立して評価できるように、最初に値ごとにインデックスをグループ化します。 それぞれの値について`v`、配列を次の出現箇所の周囲のセグメントとして扱います。`v`。 等しくないすべての位置`v`何らかの発生から拡張することでカバーする必要があります`v`、そのような位置の総数は、左側の境界、内部ギャップ、および右側の境界に分割されます。 これらのカウントを乗算すると、`v`運用コストの定義を反映しており、各ユニットの拡張コストが異なります。`v`。 

微妙な点は、操作を明示的にシミュレートすることは決してないということです。 代わりに、最適な戦略は異なる値をインターリーブすることによって恩恵を受けることは決してないという事実に依存しているため、各値を個別に評価するだけで十分です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = {}
        for i, v in enumerate(a):
            pos.setdefault(v, []).append(i)

        ans = float('inf')
        for v, p in pos.items():
            cost = 0
            if p[0] > 0:
                cost += p[0] * v
            for i in range(len(p) - 1):
                cost += (p[i + 1] - p[i] - 1) * v
            if p[-1] < n - 1:
                cost += (n - 1 - p[-1]) * v
            ans = min(ans, cost)

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、最適値が 1 回だけ現れる場合です。 のような入力の場合`3 1 3`、選択する`1`ターゲットは内部構造を持たない場合でも最適である可能性があるためです。 位置リストには単一の要素があり、内部ギャップと境界寄与の両方がその単一のソースからの拡散の全コストを正しく説明するため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、すべての要素が等しい場合です。 その場合、位置リストは完全にカバーされ、両方の境界チェックがゼロと評価されます。 計算されたコストは、特別なケースを必要とせずにゼロになります。 

最後の微妙なケースは、次のような値を交互に使用することです。`1 2 1 2 1`。 各値には個別に複数の出現があり、アルゴリズムは出現間のギャップのみを正確に測定し、重複する影響によって領域が誤って二重カウントされないようにします。
