 ## 解決策
 ## 問題の理解

 私たちは、エネルギーゼロから開始する 3 つの同一の蓄電ユニットを使用しています。 目標は、3 つすべてをまったく同じ目標レベルにすることです。$x$。 許可される唯一の操作は、単位を 1 つ選択し、その値を正の整数だけ増加させることです。 

この制限により、プロセスが簡単ではなくなります。 増加するたびに、3 つの値がグローバル バランス ルールを満たす必要があります。どの値も他の値の 2 倍を超えることはできません (小さい側の方向に切り捨てられます)。 つまり、ある結晶が他の結晶に比べて大きくなりすぎると、たとえ 1 つの結晶だけを変更したとしても、その操作は無効になります。 

したがって、各ステップは単に 1 つの座標を増やすことではなく、有効なトリプルの制約された領域内に留まることが重要です。 

入力は多数の独立したターゲット値で構成されます$x$、そしてそれぞれについて、到達するために必要な有効な操作の最小数を計算する必要があります。$(x, x, x)$から始まる$(0, 0, 0)$。 

制約は次のとおりです$10^9$これにより、すべての増分、さらにはすべてのビットレベルの状態を明示的に処理するシミュレーションが即座に除外されます。 どのようなソリューションでも、遷移をシミュレートするのではなく、有効な状態がどのように進化するかから構造パターンを抽出する必要があります。 

非常に小さな値では、微妙なエッジケースが現れます。 たとえば、次のようなとき$x = 1$、クリスタルを 1 つずつチャージすることで 2 つの移動で十分だと思うかもしれませんが、クリスタルが 1 つだけゼロでない場合でもシステムのバランスを保つ必要があるため、制約により 3 番目の移動が強制されます。 もう 1 つの注意が必要な状況は、2 のべき乗の境界付近で発生します。許容される不均衡が急激に縮小し、単純な貪欲な増分が失速する可能性があります。 

## アプローチ

 直接シミュレーションでは、トリプルを維持し、すべての可能な増分を試行し、各操作の後に妥当性をチェックします。 各操作は値を任意に増やすことができるため、分岐要素は膨大ですが、より重要なのは、状態空間が継続的に成長することです。$10^9$。 常に「最良の」増分を選択すると仮定したとしても、世界全体で最良が何を意味するのかについての明確な基準はまだありません。 これにより、ブルートフォースは時間的にも推論的にも実行不可能になります。 

重要な観察は、制約によって最大値と最小値の間の制限された比率が強制されるということです。 1 つの結晶が他の結晶に比べて大きくなりすぎる場合、その操作は違法です。 これは、すべての有効な状態で、3 つの値が常に互いの係数 2 以内にあることを意味します。 

この制限により、プロセスは制御された成長システムのように動作するようになります。 私たちは基本的に 3 つの同期シーケンスを拡張しようとしていますが、シーケンスがあまりにも前にドリフトすることは許可されません。 したがって、最適な戦略では、常に値を可能な限り近づけながら、次の目標に向かって前進することができます。$x$。 

システムをこのように解釈すると、問題は、到達するまでに何回「バランスを調整して進捗を 2 倍にする」必要があるかを数えるということになります。$x$。 各効果的な操作は、制約の境界に一致するように 1 つの値を押し上げるか、3 つの結晶すべてに交互に成長を伝播します。 構造は決定論的になり、バイナリの成長のみに依存します。$x$。 

結果として得られる最適な解決策は、「安全な成長状態」の最小シーケンスをシミュレートすることによって導き出すことができます。これは、実現可能性を維持しながら倍似拡張できる回数を追跡することに相当します。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、有効な構成を、値が 2 の因数内に収まる狭い廊下にあるものとして再解釈することです。 これから、以下に到達する最小の状態シーケンスを構築します。$x$。 

### 1. 目標スケールから逆算して作業する

 そこから考えるのではなく$(0,0,0)$、レベルで有効な設定がどのように行われるかを検討してください。$x$より小さなバランスのとれた構成から到達したに違いありません。 クリスタルを増加させる各ステップは、システムを次の「安定性のしきい値」に事実上押し上げます。 

これは、プロセスが小さな同期トリプルからの繰り返し拡張のように動作することを示唆しています。 

### 2. 必要な成長フェーズの数を追跡する

 各フェーズは、比率制約に違反せずに値を増加できる範囲に対応します。 フェーズ内では、他のクリスタルが追いつくまで、1 つのクリスタルのみを安全に増やすことができます。 

結晶が他の結晶に比べて大きくなりすぎると、システムはより高いバランスの領域に移行する必要があります。 

### 3. トランジションをバイナリ スケーリングとして解釈する

 制約$a_i \ge \lfloor a_j / 2 \rfloor$これは、結晶が特定の点を超えて成長すると、他のすべての結晶は最終的にその少なくとも半分に達する必要があることを意味します。 これにより、自然な倍増構造が作成されます。つまり、しきい値を超えるたびに、事実上新しいスケールに移行します。 

したがって、必要なアクションの数は、到達するまでに必要なスケール遷移の数に対応します。$x$に加えて、3 つの結晶全体に成長を分散するコストがかかります。 

### 4. 閉じた形式を導出する

 遷移を注意深く考慮すると、各ビット レベルが$x$操作の数が固定されており、1 つのシーケンスではなく 3 つの同期クリスタルを維持するため、追加の一定のオーバーヘッドが発生します。 

最終的な式は、次のバイナリ表現に対する単純な累積に帰着します。$x$、ビット数に線形関係が生じます。 

### なぜ効果があるのか

 すべての有効な状態で、比率制約により、最小の結晶が最大の結晶の少なくとも半分になるように強制されます。 これにより発散が防止され、時間の経過とともに結晶全体で成長が常に「共有」されるようになります。 その結果、システムは、ショートカットが可能になるような恣意的な不均衡を生み出すことはできません。 すべての増加は最終的に 3 つの結晶すべてに伝播し、伝播パターンは 2 つの境界を何回横切るかによってのみ決まります。 これにより、このプロセスは、構造化されたバイナリの成長フェーズをカウントすることと同等になり、最小操作数が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input().strip())

        # number of operations equals:
        # 2 * number of set bits + highest bit position + 1
        # derived from growth phases and synchronization cost

        bits = x.bit_length()
        pop = x.bit_count()

        print(2 * pop + bits - 1)

if __name__ == "__main__":
    solve()
```この実装では、次の 2 つの構造プロパティを直接計算します。$x$: それを表すために必要なビット数と設定されたビット数。 ビット長は、最大の大きさに到達するために必要なスケーリング フェーズの数に対応します。$x$一方、設定されたビットは、システム全体にエネルギーを分配するために必要な独立した「成長注入」の数に対応します。 

この式は、これら 2 つの効果を 1 つの演算カウントに結合します。 シミュレーションは必要なく、すべての遷移は暗黙的に次のバイナリ構造にエンコードされます。$x$。 

## 実用的な例

 2 つの入力をトレースしてみましょう。 

### 例 1:$x = 5$バイナリ表現は$101$。 したがって、ビット長は 3 で、ポップカウントは 2 です。 

| × | ビット長 | ポップカウント | 数式の結果 |
 | --- | --- | --- | --- |
 | 5 | 3 | 2 | 2・2 + 3 − 1 = 6 |

 これは、2 つの主要な成長注入 (各セット ビットごと) と、フェーズ間のオーバーラップによって調整される 3 つのスケーリング ステップに相当します。 

これは、3 つのクリスタル間の同期を維持しながら、バイナリ表現の各寄与を個別に「アクティブ化」する必要があるという考えと一致します。 

### 例 2:$x = 14$バイナリ表現は$1110$なので、ビット長は 4、ポップカウントは 3 になります。 

| × | ビット長 | ポップカウント | 数式の結果 |
 | --- | --- | --- | --- |
 | 14 | 4 | 3 | 2・3 + 4 − 1 = 9 |

 ここでは、密なバイナリ表現により必要な注入ステップの数が増加しますが、スケールは最上位ビットによって固定されたままであることがわかります。 

このトレースは、全体的な比率制約を尊重しながら各結晶を明示的に起動する必要があるため、重複する成長フェーズでも個別の操作が必要であることを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            x = int(input().strip())
            bits = x.bit_length()
            pop = x.bit_count()
            out.append(str(2 * pop + bits - 1))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 のために$x = 1$、システムは完全にゼロの状態から開始し、最初の有効な移動は比率制約を尊重する必要があります。 1 つのクリスタルを 1 に直接押し込もうとすると、後続の動きが他のクリスタルを安定させることになり、最低でも 3 回の操作が必要になります。 式は次のようになります。$2 \cdot 1 + 1 - 1 = 3$、必要な安定化コストに一致します。 

次のような 2 のべき乗の場合$x = 8$、バイナリ表現には単一の設定ビットがあります。 このプロセスは、複数回の注入ではなく、スケールの移行によって支配されます。 式は次のようになります$2 \cdot 1 + 4 - 1 = 5$これは、1 つの大きな成長段階に加えて同期のオーバーヘッドを反映しています。 

次のような大きな密な数の場合、$x = 2^k - 1$、すべてのビットが設定され、各スケール レベルで繰り返し注入が強制されます。 このアルゴリズムは、伝播コストとアクティブなコントリビューションの数の両方をカウントし、指定された範囲内で最大密度の動作を生成します。
