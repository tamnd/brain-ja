 ## 解決策
 ## 問題の理解

 文字のみで構成される文字列が与えられます。`a`、`b`、 そして`c`。 それに加えて一連の操作も行われます。 各操作は可能な置換を提案します。出現する文字を選択します。`x`そしてそれを別の手紙に変える`y`、または操作を完全にスキップします。 

主な難点は、これらの操作が順番に適用され、それぞれがオプションであることです。 特定の置換を強制的に適用する必要はありませんが、操作ごとに、それを使用する価値があるかどうか、使用する価値がある場合はどの文字の出現を変更するかを決定する必要があります。 すべての操作を処理した後、最終的な文字列を辞書順にできるだけ小さくしたいと考えます。 

ここでの辞書編集的最小化とは、文字列内の以前の位置をできるだけ小さくし、優先順位を付けることを意味します。`a < b < c`。 操作はグローバルであるため (操作は以下を含むあらゆる位置に影響を与える可能性があります)`x`）、選択肢は連続的ですが、問題は、限られた「コンバージョンの機会」を時間をかけて調整することです。 

制約は厳しく、文字列の合計長とすべてのテスト ケースにわたる合計操作は最大 2 · 10^5 です。 これにより、文字列全体をスキャンして各操作をシミュレートしようとするソリューションは除外されます。これは、最悪の場合に O(nq) の動作が発生する可能性があるためです。 

単純なメンタル モデルは次のようになります。各操作の後に文字列全体をスキャンし、効果がある場合は置換を適用します。 これでは、パフォーマンスだけでなく正確性の面でも失敗します。操作に対する最適な決定は、現在の状態だけでなく将来の操作に依存するからです。 

貪欲な即時適用の微妙な失敗例は、早期の変換が局所的には有益であるが、全体的には有害である場合に現れます。 たとえば、変換すると、`b -> a`早い段階が最適に見えるかもしれませんが、後の操作で変換できる可能性があります。`c -> b`その後`b -> a`、より良い段階的な改善を生み出します。 貪欲なローカルアプローチでは、この構造が失われます。 

## アプローチ

 ブルート フォース ソリューションでは、操作を 1 つずつシミュレートし、操作ごとに文字列をスキャンしてどこに適用するかを決定し、考えられるすべてのインデックスを試行する可能性があります。 これにより、O(nq) が得られますが、パラメータあたり 2 · 10^5 と大きすぎます。 

重要な観察は、文字が非常に限られているということです。存在する記号は 3 つだけです。 これは、これらのシンボルが時間の経過とともにどのように相互に変化するかによって、システム全体を説明できることを意味します。 文字列内の位置を追跡する代わりに、文字間の変換を追跡します。 

各操作は文字の数にのみ影響し、位置には影響しません。 さらに重要なのは、操作を適用するかどうかは、それが将来の文字の削減に役立つかどうかによって決まります。 これは、操作を逆方向に処理することを示唆しています。 

時間を逆にすると、各手紙は今後の運用に応じて「最善の最終形」を持っていると考えることができます。 操作を最後から最初に処理するとき、各文字から最終的になり得る最小の文字までの最もよく知られたマッピングを維持します。 

逆の各ステップで、操作を「使用」するか無視するかを決定します。 過去に遡っているため、操作を使用することは将来の変換を許可することに相当します。 その後の操作の最良の結果がすでにわかっているため、これは決定論的な決定となります。 

私たちは、達成可能な最高の特性を維持します。`a`、`b`、 そして`c`操作の接尾辞を適用した後。 次に、これらの変換を逆方向に伝播します。 最後に、結果のマッピングを元の文字列に適用します。

 | 文字の逆DP | O(n + q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を維持します`best`どこ`best[x]`元の文字の最小文字を表します`x`操作の接尾辞を処理した後になることができます。 

操作は最後から最初に処理されます。 

1.初期化`best[a] = a`、`best[b] = b`、`best[c] = c`。 これは、何も操作を適用しないと、各文字がそのまま残るという事実を表しています。 
2. 逆の順序で操作を繰り返します。 手術の場合`(x -> y)`を適用すると、現在のマッピングの改善に役立つかどうかを検討します。 この時点で、後の操作後に達成可能な最良の結果がすでにわかっています。 
3.変換する場合`x`この操作により、最終的な文字は実際の文字よりも厳密に小さくなります。`x`現在はにマップされており、更新することでそれを適用します`best[x]`。 

より正確に比較すると、`best[y]`と`best[x]`。 もし`best[y] < best[x]`、それから作る`x`通り抜ける`y`最終的な結果が向上するため、`best[x] = best[y]`。 

1. それ以外の場合、どのような問題が発生しても最終結果を改善できないため、操作は無視されます。`x`。 
2. すべての操作を処理した後、各文字を置き換えて最終的な文字列を構築します`s[i]`と`best[s[i]]`。 

これが機能する理由は、各文字が達成可能な最適な形式を個別に追跡するためです。 文字が 3 つしかないため、相互作用は位置には依存せず、変換チェーンのみに依存します。 逆に処理することで、操作を決定する際に、将来の最良の結果をすでに知っていることが保証されます。 

### なぜ効果があるのか

 逆処理のどの時点でも、`best[x]`から到達可能な最小限の文字を表します`x`現在のインデックスの右側の演算のみを使用します。 新しいオペレーションを考えるとき`x -> y`、この変換グラフに新しいエッジを効果的に追加しています。 経由する場合`y`改善する`x`の場合、このエッジを含めることが最適である必要があります。 それ以外の場合は、スキップしても将来の可能性が損なわれることはありません。`best[y]`すでに最適な将来の結果をエンコードしています`y`。 この不変条件により、有益な変換チェーンを決して見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = list(input().strip())

        ops = []
        for _ in range(q):
            x, y = input().split()
            ops.append((x, y))

        best = { 'a': 'a', 'b': 'b', 'c': 'c' }

        def apply(x):
            return best[x]

        for x, y in reversed(ops):
            if apply(y) < apply(x):
                best[x] = apply(y)

        res = []
        for ch in s:
            res.append(apply(ch))

        print("".join(res))

if __name__ == "__main__":
    solve()
```核となる構造は、`best`各文字の現在の最適な結果を保存する辞書。 逆走査は、操作を評価する際に、その後のすべての決定がすでに修正されていることを保証するため、非常に重要です。 

機能`apply`これは、生の文字ではなく、常に最終的にマップされた値を処理していることを明確にする小さな抽象化です。 これにより、中間マッピングが無視されるような間違いが回避されます。 

最後のループは、このマッピングを通じて元の文字列を単純に変換します。これは、操作が位置に依存せず、文字の識別のみに依存するため安全です。

 ## 特殊なケース

 操作がサイクルを形成する場合、次のような厄介な状況が発生します。`a -> b`、`b -> c`、`c -> a`。 単純なフォワード シミュレーションでは、局所的な改善のみが振動したり、誤って適用されたりする可能性があります。 逆処理では、不変式によって安定性が保証されます。つまり、文字がより小さい代表にマッピングされると、再び増加することはありません。 

もう 1 つのエッジ ケースは、ローカルでは役に立たないと思われる操作が、後の変換によって役立つようになる場合です。 例えば、`b -> c`有害に見える場合`c`最初は大きいですが、後で`c -> a`が表示されます。 逆パスにより、評価時に次のことが保証されます。`b -> c`、私たちはすでにそれを知っています`c`最終的にはなる`a`なので、その時点での改善が正しく捉えられます。 

最後に、操作がない場合、または自己マップのみの場合 (`a -> a`) マッピングには影響しません。 アルゴリズムは自然に終了します`best`変更されないため、出力は入力文字列と同じままになります。
