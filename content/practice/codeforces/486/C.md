 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$小文字の英字とカーソル位置で構成されます$p$文字列の周囲を周期的に左または右に移動できます。 矢印キーを使用すると、カーソルを移動したり、カーソルの位置の文字を増減したりできます (これも循環なので、「z」の後に「a」が来る、またはその逆になります)。 目標は、最小限のキー押下で文字列を回文に変換することです。 

入力は文字列の長さを提供します$n$、開始カーソル位置$p$、および文字列自体。 出力は、カーソルの移動と文字の変更の両方を含む、キー押下の最小合計数である必要があります。 

と$n$まで$10^5$1 秒の時間制限があるため、各文字を一定時間で処理するアルゴリズムならどれでも実行可能です。 シーケンスの数が指数関数的に増加するため、考えられるすべての動きと文字の変更シーケンスを試す単純な総当りアプローチは実行不可能です。 回文の対称性とカーソル移動の構造を利用する必要があります。 

明白ではないエッジ ケースには、すでに回文になっている文字列、カーソルが一方の端近くから始まっていること、最適な解決策を得るには周期的な移動により右ではなく左に移動する必要がある状況などが含まれます。 たとえば、入力の場合`"abca"`カーソルが位置 4 にある場合、単純な右のみの移動戦略では移動数が過剰にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。考えられるすべてのキー押下シーケンスを考慮し、それをシミュレートし、回文が生成されるかどうかを確認します。 正しいのですが、これには時間がかかります$O(26^{n/2})$文字変更だけのための操作は、不可能なほど大規模になります。$n$まで$10^5$。 

効率的な解決策の重要な洞察は、問題が文字の変更とカーソルの移動という 2 つの独立した要素に自然に分解されるということです。 文字列が回文になるには、不一致の文字ペアのみが必要です$(s[i], s[n-i-1])$のために$i = 0$に$n//2-1$修正する必要があります。 各ペアの上/下を押す最小回数を計算することは、循環アルファベット距離を使用することで簡単に行えます。 残りの課題は、カーソルの移動を最小限に抑えることです。 

カーソルは左または右に周期的に移動できるため、最適な移動パスは、初期位置から開始して、文字列の関連する半分の左端の不一致と右端の不一致に移動し、それらの間を可能な限り最短の順序で移動することです。 カーソルが右半分から始まる場合、問題は文字列の中点に関して対称であるため、カーソルを左半分にミラーリングします。 

したがって、解決策は次のとおりです。各不一致ペアの最小文字変更の合計を計算し、すべての不一致位置をカバーする最小のカーソル移動を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^(n/2)) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カーソルが文字列の右半分にある場合は、計算を簡略化するために左半分にカーソルをミラーリングします。 させて$p$0 から始まります。 
2. Iterate over the first$n//2$文字を検出し、不一致の位置を特定します。$s[i] \neq s[n-i-1]$。 左端と右端の不一致を追跡します。 
3. 不一致の位置ごとに、ミラーリングされた文字と一致するために上下に押す最小回数を計算します。 これは循環距離を使用します$\min(|a-b|, 26 - |a-b|)$。 これらを合計して、レターチェンジコストの合計を計算します。 
4. 不一致が存在しない場合、文字列はすでに回文であるため、ゼロを出力します。 
5. カーソルの動きを計算します。 戦略は 2 つあります。まず左端の不一致に移動してから右端に移動するか、その逆です。 どちらのパスもすべての不一致位置をカバーします。 最小の総移動量は、これら 2 つの距離の小さい方に、左端と右端の不一致の間の距離を加算したものになります。 
6. 文字変更コストとカーソル移動コストの合計を返します。 

機能する理由: 文字列を回文にするのに役立つ位置のみを変更します。 このアルゴリズムは、関連するすべての位置を接続する最小パスをカバーします。 アルファベットの循環距離により、文字変更コストは独立して最小になります。 不一致の位置の範囲のみを考慮することにより、カーソルの移動が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())
s = input().strip()

p -= 1
half = n // 2

if p >= half:
    p = n - 1 - p

left, right = half, -1
letter_changes = 0

for i in range(half):
    if s[i] != s[n - 1 - i]:
        left = min(left, i)
        right = max(right, i)
        diff = abs(ord(s[i]) - ord(s[n - 1 - i]))
        letter_changes += min(diff, 26 - diff)

if right == -1:
    print(0)
    sys.exit(0)

move_cost = min(abs(p - left), abs(p - right)) + (right - left)
print(letter_changes + move_cost)
```このソリューションでは、簡単にするために、まずカーソルを左半分にミラーリングします。 次に、前半を反復して文字変更コストを計算し、左端と右端の不一致を特定します。 カーソル移動コストは、現在の位置から開始して、一致しないすべての位置を最適に移動することを考慮しています。 

境界に関する考慮事項には、1 ベースから 0 ベースの変換を正しく処理すること、巡回アルファベット計算を確実に行うこと、カーソルがすでに不一致のスパンの一方の端にある場合に移動を正しく計算することが含まれます。 

## 実用的な例

 **サンプル 1**

 入力:`8 3 aeabcaez`| 私 | s[i] | s[n-1-i] | 文字の変更 | 左 | 右 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | | z | 1 | 0 | 0 |
 | 1 | e | e | 0 | 0 | 1 |
 | 2 | | | 0 | 0 | 2 |
 | 3 | b | c | 1 | 0 | 3 |

 カーソルは位置 2 (0 ベース: 2) から始まります。 文字の変更 = 1+0+0+1 = 2。左端の不一致 = 0、右端 = 3。カーソルの移動 = min(abs(2-0), abs(2-3)) + (3-0) = 1 + 3 = 4。合計 = 2 + 4 = 6。 

**カスタム入力 2**

 入力:`5 5 abcde`| 私 | s[i] | s[n-1-i] | 文字の変更 | 左 | 右 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | | e | 4 | 0 | 0 |
 | 1 | b | d | 2 | 0 | 1 |

 カーソルは位置 4 から始まります (0 ベース: 4 → ミラーリングされた 0)。 文字の変更 = 4+2=6。 不一致はインデックス 0 ～ 1 にまたがります。 カーソルの移動 = abs(0-0) + (1-0) = 1。合計 = 6+1=7。 

これらのトレースは、アルゴリズムが最小限の文字変更とカーソル移動を正しく計算していることを示しています。

## 特殊なケース

 単一文字の文字列の場合は変更する必要はありません。 このアルゴリズムは不一致を検出せず、0 を返します。カーソルが右半分から始まる文字列の場合、位置をミラーリングし、移動範囲を正しく計算し、最小合計を見つけます。 すべての文字が等しい場合、カーソルが不一致でない場合でも、文字変更の合計はゼロになり、移動コストもゼロになります。 これらのケースでは、アルゴリズムが境界位置を処理していることが確認されます。
