 ## 解決策
 ## 問題の理解

 配列が与えられており、その最長の増加サブシーケンスに注目します。 その位置の値がサブシーケンスの要素の 1 つとして選択されている場合、インデックスは最も長く増加するサブシーケンスに属します。 

タスクは LIS を数えることではありません。 代わりに、すべてのポジションについて、それが 3 つのカテゴリのどれに属するかを判断する必要があります。 

どの LIS にも表示されない場合、ポジションはグループ 1 に属します。 

ポジションが少なくとも 1 つの LIS に表示されているが、そのポジションを使用していない別の LIS が存在する場合、そのポジションはグループ 2 に属します。 

可能なすべての LIS にその位置が含まれなければならない場合、その位置はグループ 3 に含まれます。 

配列の長さは次のとおりです$10^5$。 LIS の数は指数関数的に増加する可能性があるため、増加するサブシーケンスを明示的に列挙するアルゴリズムは絶望的です。 たとえ$O(n^2)$動的プログラミング ソリューションは約を実行します$10^{10}$限界をはるかに超えた最悪の場合の比較。 目標の複雑さはおおよそ次のとおりです$O(n \log n)$。 

難しい部分は、グループ 2 とグループ 3 を区別することです。インデックスが何らかの LIS に属していることを知っているだけでは十分ではありません。 その位置を使用せずに LIS を構築する別の方法があるかどうかを知る必要があります。 

次の配列を考えてみましょう。```
1 3 2 5
```LIS の長さは 3 です。LIS は 2 つあります。```
1 3 5
1 2 5
```3 と 2 を含む位置は一部の LIS に属しますが、すべての LIS に属するわけではありません。 彼らの答えはきっとこうだろう`2`。 

別の微妙なケースは次のとおりです。```
1 2 3
```LIS は 1 つだけです。 すべてのポジションがそれに属するため、答えは次のようになります。```
333
```位置が LIS に表示できるかどうかだけをチェックする不注意な解決策では、誤って印刷されてしまいます。`222`。 

もう 1 つの重要な例は次のとおりです。```
2 2 2
```LIS の長さは 1 です。各位置は個別に LIS を形成します。 3 つのうちのいずれかを選択できるため、ポジションは必須ではありません。 正しい答えは次のとおりです。```
222
```LIS-length-1 の位置をすべて必須として扱うのは間違いです。 

## アプローチ

 ブルートフォースのアイデアは概念的には単純です。 最も長く増加するサブシーケンスをすべて生成し、どのインデックスが出現するかを記録し、それが含まれる LIS の数に応じて各インデックスを分類します。 これは定義に直接従うため、正しいです。 

問題は規模だ。 中程度の入力であっても、LIS の数は膨大になる可能性があります。 のような配列```
1 2 1 2 1 2 ...
```すでに多くの選択肢が生まれています。 すべての LIS を列挙すると指数関数的になります。 

重要な観察は、LIS 自体は必要ないということです。 必要なのは、LIS 内の各位置がどこに配置されるかに関する構造情報のみです。 

させて$L_i$位置で終了する最長の増加サブシーケンスの長さ$i$。 

させて$R_i$位置から始まる最長の増加するサブシーケンスの長さ$i$。 

LIS の全長が$K$、次に位置を決めます$i$特定の LIS に属することができるのは、次の場合です。$$L_i + R_i - 1 = K.$$その理由は、$L_i$チェーン到達の最適な増加を示します$i$、$R_i$最適な増加チェーン離脱を説明します$i$、および位置$i$両方の部分でカウントされます。 

これにより、グループ 1 が他のグループからすでに分離されます。 

残りの問題は、そのポジションが必須かどうかを判断することです。 

LIS 上のすべての位置は、特定のレイヤー、つまりレイヤーを占めます。$L_i$。 LIS に沿って、各レイヤーから正確に 1 つの位置を選択する必要があります$1,2,\ldots,K$。 

すべての位置の中で満足すると仮定します$$L_i + R_i - 1 = K$$レイヤー内の位置は 1 つだけです$t$。 

すべての LIS はレイヤーから 1 つの位置を取得する必要があります$t$、候補は1つだけです。 その位置は避けられず、グループ 3 に属します。 

レイヤーに 2 つ以上の候補が含まれている場合、それらのどれも個別に必須ではありません。 LIS を構築するときに、同じレイヤーから別の候補を選択できます。 これらのポジションはグループ 2 に属します。 

これにより、$O(n \log n)$標準の忍耐ソート LIS アルゴリズムを 2 回使用したソリューション。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$L_i$、各位置で終わる LIS の長さ。 

忍耐によるソート手法を使用して、配列を左から右に処理します。 各値について、二分探索で tails 配列内の挿入位置を見つけます。 挿入インデックスに 1 を加えた値は、$L_i$。 
2. コンピューティング$R_i$、各位置から始まる LIS の長さ。 

配列を右から左に処理します。 同じ LIS プロシージャを値に適用します。$-a_i$。 これは、位置から右方向に移動するときに増加するサブシーケンスを計算することと同じです。$i$。 
3. しましょう$$K = \max(L_i).$$これは LIS の全長です。 
4. すべての位置について、次のことを確認します。$$L_i + R_i - 1 = K.$$そうでない場合、そのポジションはどの LIS にも属すことができません。 グループとしてマークします`1`。 
5. 上記の等式を満たすすべての位置について、各層にそのような位置がいくつ存在するかを数えます。$L_i$。 
6. 一部の LIS の各位置について:

 そのレイヤーに有効な位置が 1 つだけ含まれている場合は、それをグループとしてマークします`3`。 

それ以外の場合はグループとしてマークします`2`。 
7. 結果の文字列を出力します。 

### なぜ効果があるのか

 価値観$L_i$そして$R_i$位置に出入りする最長の増加チェーンを表す$i$。 ポジションは、これら 2 つのチェーンが結合されてグローバル LIS 長になる場合にのみ LIS に参加できます。これがまさに条件です$$L_i + R_i - 1 = K.$$すべての LIS には、各レイヤーからの 1 つの位置が含まれます。 ポジションのレイヤーは$L_i$。 LIS に表示できる位置のうち、レイヤーに候補が 1 つしか含まれていない場合、レイヤーをスキップできないため、すべての LIS はその候補を使用する必要があります。 逆に、レイヤーに複数の候補が含まれている場合、単一の候補は強制されません。 ある候補を別の候補に置き換えると、その層を通じて LIS の存在が維持されます。 したがって、ユニークレイヤの候補は、正確にすべての LIS に属する位置です。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    L = [0] * n
    tails = []

    for i, x in enumerate(a):
        pos = bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x
        L[i] = pos + 1

    K = len(tails)

    R = [0] * n
    tails = []

    for i in range(n - 1, -1, -1):
        x = -a[i]
        pos = bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x
        R[i] = pos + 1

    layer_count = [0] * (K + 1)

    for i in range(n):
        if L[i] + R[i] - 1 == K:
            layer_count[L[i]] += 1

    ans = ['1'] * n

    for i in range(n):
        if L[i] + R[i] - 1 != K:
            ans[i] = '1'
        elif layer_count[L[i]] == 1:
            ans[i] = '3'
        else:
            ans[i] = '2'

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```最初の LIS パスは、すべての位置で終わる最長の増加サブシーケンスを計算します。 tails 配列は、LIS の長さごとに可能な最小の終了値を維持します。 これが標準です$O(n \log n)$LIS技術。 

2 番目のパスは少しわかりにくくなります。 同じロジックを否定された値に適用しながら右から左に処理すると、各位置から始まる最長の増加サブシーケンスが計算されます。 否定を使用すると、必要な順序付けが、前方パスで使用されるのと同じ二分探索構造に変換されます。 

取得後$L$そして$R$、条件$$L_i + R_i - 1 = K$$少なくとも 1 つの LIS 上にある位置を正確に識別します。 それらの位置のみがレイヤーのカウントに参加します。 

層数配列のインデックスは次のとおりです。$L_i$。 よくある間違いは、レイヤー内のすべての位置を数えることです。 LIS 条件を満たす位置のみをカウントする必要があります。 LIS に属さないポジションは、必須ポジションのテストに影響を与えてはなりません。

# helper: run solution on input string, return output string
import sys, io
from bisect import bisect_left

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    L = [0] * n
    tails = []

    for i, x in enumerate(a):
        p = bisect_left(tails, x)
        if p == len(tails):
            tails.append(x)
        else:
            tails[p] = x
        L[i] = p + 1

    K = len(tails)

    R = [0] * n
    tails = []

    for i in range(n - 1, -1, -1):
        x = -a[i]
        p = bisect_left(tails, x)
        if p == len(tails):
            tails.append(x)
        else:
            tails[p] = x
        R[i] = p + 1

    cnt = [0] * (K + 1)

    for i in range(n):
        if L[i] + R[i] - 1 == K:
            cnt[L[i]] += 1

    ans = []

    for i in range(n):
        if L[i] + R[i] - 1 != K:
            ans.append('1')
        elif cnt[L[i]] == 1:
            ans.append('3')
        else:
            ans.append('2')

    return ''.join(ans)
