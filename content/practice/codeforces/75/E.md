 ## 解決策
 ## 問題の理解

 飛行機内の 2 つの点、船の出発位置と目的地、および島を表す凸多角形が与えられます。 

海を通って移動すると費用がかかる`1`単位距離あたり。 島内移動にかかる費用`2`単位距離あたり。 ポリゴンの境界に沿った移動は海の移動として扱われるため、そこにかかるコストは依然として発生します。`1`。 

船は海上費で島外のどこにでも移動できますが、より高い陸地費を支払って島を通過することもできます。 このタスクは、開始点から終了点までの移動に必要な最小総コストを計算することです。 

多角形は凸状で、最大 30 個の頂点が含まれます。 それは問題の性格を完全に変えます。 このような小さなポリゴンでは、高度なジオメトリ データ構造や継続的な最適化は必要ありません。 アン`O(n^3)`あるいは`O(n^4)`アルゴリズムは完全に許容可能です。 

難しいのはパフォーマンスではなく、ジオメトリを正しくモデリングすることです。 

素朴に解釈すると、「島を直進するか、境界線を迂回して歩くかのどちらかだ」ということになります。 それは必ずしも真実ではありません。 最適なパスは、ある境界点でポリゴンに入り、内部を通過し、別の点で出て、そのセグメントの前後に境界円弧を使用することもあります。 

もう 1 つの微妙な点は、凸多角形の周囲の海のみの最短パスは常に直線セグメントと多角形のエッジで構成されることです。 直線セグメントがポリゴン内部に触れると、海セグメントとしては無効になります。 

多角形が凸面であるという事実は、重要な構造特性です。 凸性は、2 つの外側の点を接続するセグメントが最大 1 つの連続した間隔で多角形と交差することを保証します。 これにより、最短経路が一般的なポリゴン障害物問題よりもはるかに単純になります。 

次の例を考えてみましょう。```
Start = (0,0)
End   = (10,0)

Square:
(4,-1) (6,-1) (6,1) (4,1)
```直通区間は島を横断します。 不用意に実装すると、次のようになります。 

「島を通過するには費用がかかります」`2 * 2 = 4`詰まった部分と残りは海にある。」

 それは総コストを与えます`8 + 4 = 12`。 

しかし、正解はもっと小さいです。 最適なルートは、広場の境界線を歩くことです。 迂回距離はたったの`2 + 2 = 4`、したがって、合計コストは次のようになります`10 + 2 = 12`? 実際、ここでは両方がたまたま結びついています。 小さな混乱が簡単に関係を壊します。 

例えば：```
Start = (0,0)
End   = (10,0)

Rectangle:
(4,-3) (6,-3) (6,3) (4,3)
```島を横断するのにかかる費用は次のとおりです。`8`海上距離プラス`2 * 2 = 4`、 合計`12`。 

境界線を迂回するには迂回が必要です`6`、 合計`14`。 

最適な答えは、島を渡ることです。 

もう 1 つの危険なエッジ ケースは、直線セグメントがポリゴンの境界に 1 点でのみ接触する場合に発生します。 境界の移動は海上の移動としてカウントされるため、このパスは海上のパスとして完全に有効であり、追加の土地コストは発生しません。 

例：```
Start = (0,0)
End   = (10,0)

Triangle:
(5,0) (6,2) (6,-2)
```セグメントは頂点にのみ接触します`(5,0)`。 答えはまさに`10`。 

境界接触を内部交差として扱う実装では、誤ってコストが増加します。 

## アプローチ

 強引なアイデアは、継続的に考えることです。 最適なパスは、任意の境界点でポリゴンに出入りすることができるため、多くの境界点をサンプリングして、それらの間で最適なルートを計算してみるとよいでしょう。 

コスト関数は区分的に幾何学的で滑らかであるため、これは概念的に機能します。 十分に細かく離散化すると、最適解が近似されます。 

問題は、継続的な最適化がすぐに面倒になってしまうことです。 サンプリングだけでも`k`エッジあたりのポイントはすでにあります`O(k^2)`エントリーとエグジットのペアの候補。 すべてのペアには、幾何学的交差チェックと最短境界の計算も必要です。 精度が高いと大きなサイズが必要になる`k`、この方法は非実用的であり、数値的に脆弱です。 

重要な観察点は、この問題の最短パスには転換点としてポリゴンの頂点のみが必要であるということです。 

私たちが完全に海の中を移動していると仮定してください。 各自由領域内では、2 点間の最短経路は常に直線セグメントになります。 曲げる唯一の理由は、ポリゴンの境界に沿ってスライドすることです。 ポリゴンは凸状であるため、2 つの境界点間の境界最適ルートは、まさにそれらを接続する 2 つのポリゴン チェーンになります。 

これにより、連続幾何学問題がグラフ最短経路問題に変換されます。 

次のようなノードを持つグラフを作成します。 

- スタート地点
 - 終点
 - すべてのポリゴン頂点

 次に、重み付けされたエッジを使用してノードのペアを接続します。 

2 つのノード間のセグメントがポリゴンの内部を通過しない場合、海を直接移動する可能性があるため、エッジ コストはユークリッド距離に等しくなります。 

セグメントがポリゴンの内部を通過する場合でも、直接移動することはできますが、内部部分のコストは 2 倍になります。 

凸多角形の場合、セグメントは次のいずれかで多角形と交差します。 

- 間隔なし
 - ワンポイント
 - 1 つの連続セグメント

 したがって、次のように計算できます。 

- セグメントの合計長
 - 多角形内の長さ

 その場合、コストは次のようになります。`outside_length * 1 + inside_length * 2`これは次のように単純化されます。`total_length + inside_length`すべてのペアごとのコストが判明すると、問題は完全な重み付きグラフ最短経路問題になります。 グラフには最大 32 個の頂点があるため、フロイド-ウォーシャルは自明です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサンプリング | 高精度のために非常に大きい | 大 | 遅すぎて信頼性が低い |
 | グラフ + ジオメトリ + フロイド-ウォーシャル | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 始点、終点、ポリゴンの頂点を読み取ります。 
2. 以下から構成されるグラフ ノードのリストを作成します。 

- ノード`0`出発点として
 - ノード`1`終点として
 - ノード`2...n+1`ポリゴンの頂点として
 3. ノードのペアごとに`(A, B)`、それらの間を直接移動する場合の最小コストを計算します。 
4. 直接旅行コストを計算するには、まずセグメントの金額を決定します。`AB`凸多角形の内側にあります。 
5. セグメントを次のようにパラメータ化します。$P(t)=A+t(B-A),\quad 0\le t\le 1$このセグメントをすべてのポリゴン エッジと交差させます。 
6. すべてのパラメータ値を収集する`t`セグメントがポリゴンのエッジと交差する場所。 

以下も含めてください:

 -`0`-`1`7. 集めたものを並べ替える`t`値を調べて、連続するすべての間隔を調べます。 

各間隔について:

 - その中間点パラメータを取得します
 - 中間点の位置を評価する
 - この中点が厳密にポリゴンの内側にあるかどうかをテストします

 存在する場合、多角形は凸状であるため、間隔全体が内側になります。 
8. 内側として分類されたすべての間隔の長さを合計します。 
9. 次のようにしましょう。 

-`L`セグメントの合計長になる
 -`I`内側の全長であること

 その場合、旅費は次のようになります。$\text{cost}=L+I$最初`L`あらゆる場所での海上コストが考慮され、追加料金が発生します。`I`ムーブメント内部をコストからアップグレード`1`費用がかかる`2`。 
10. この値を 2 つのノード間のグラフ エッジの重みとして保存します。 
11. グラフ上で Floyd-Warshall を実行します。 
12. ノードからの最短距離`0`ノードへ`1`が答えです。 

### なぜ効果があるのか

 オープンスペースではユークリッド距離が最適であるため、最短経路の場合、すべての最大海のセグメントは直線になります。 パスの方向が変わるときは、必ずポリゴンの境界上で発生する必要があります。 

凸多角形の場合、線分と多角形の交点は必ずつながります。 つまり、直接セグメントには、コストを正確に計算できる一意に定義された内部部分があります。 

グラフには、すべてのポリゴンの頂点と端点が含まれます。 最適な境界トラバースは頂点間のポリゴン エッジのシーケンスとして表現できますが、自由空間の移動は直線のグラフ エッジで表現されます。 

すべての直接エッジの重みはそのエンドポイント間の真の最適コストに等しいため、Floyd-Warshall はそれらをグローバル最適値に正しく結合します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

EPS = 1e-9

def dist(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def segment_intersection_t(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    rx = bx - ax
    ry = by - ay

    sx = dx - cx
    sy = dy - cy

    denom = cross(rx, ry, sx, sy)

    if abs(denom) < EPS:
        return None

    qpx = cx - ax
    qpy = cy - ay

    t = cross(qpx, qpy, sx, sy) / denom
    u = cross(qpx, qpy, rx, ry) / denom

    if -EPS <= t <= 1 + EPS and -EPS <= u <= 1 + EPS:
        return max(0.0, min(1.0, t))

    return None

def point_in_convex_polygon_strict(p, poly):
    x, y = p
    n = len(poly)

    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]

        cr = cross(x2 - x1, y2 - y1, x - x1, y - y1)

        if cr <= EPS:
            return False

    return True

def inside_length(a, b, poly):
    ts = [0.0, 1.0]

    n = len(poly)

    for i in range(n):
        c = poly[i]
        d = poly[(i + 1) % n]

        t = segment_intersection_t(a, b, c, d)

        if t is not None:
            ts.append(t)

    ts.sort()

    uniq = []
    for t in ts:
        if not uniq or abs(t - uniq[-1]) > 1e-8:
            uniq.append(t)

    total = 0.0
    full_len = dist(a, b)

    for i in range(len(uniq) - 1):
        l = uniq[i]
        r = uniq[i + 1]

        mid = (l + r) / 2.0

        mx = a[0] + (b[0] - a[0]) * mid
        my = a[1] + (b[1] - a[1]) * mid

        if point_in_convex_polygon_strict((mx, my), poly):
            total += (r - l) * full_len

    return total

def solve():
    xs, ys, xe, ye = map(int, input().split())

    n = int(input())

    vals = list(map(int, input().split()))

    poly = []

    for i in range(0, 2 * n, 2):
        poly.append((vals[i], vals[i + 1]))

    nodes = [(xs, ys), (xe, ye)] + poly

    m = len(nodes)

    INF = 1e100

    d = [[INF] * m for _ in range(m)]

    for i in range(m):
        d[i][i] = 0.0

    for i in range(m):
        for j in range(i + 1, m):
            a = nodes[i]
            b = nodes[j]

            total = dist(a, b)
            inside = inside_length(a, b, poly)

            cost = total + inside

            d[i][j] = cost
            d[j][i] = cost

    for k in range(m):
        for i in range(m):
            dik = d[i][k]

            for j in range(m):
                nd = dik + d[k][j]

                if nd < d[i][j]:
                    d[i][j] = nd

    print("{:.9f}".format(d[0][1]))

solve()
```コアとなる幾何学的ルーチンは次のとおりです。`inside_length`。 

セグメントは次のようにパラメータ化されます。`t = 0`に`t = 1`。 ポリゴン エッジとのすべての交差は、セグメントが外側から内側に、またはその逆に変化する遷移点の候補となります。 

すべての遷移パラメータを並べ替えた後、連続するすべての間隔は完全にポリゴンの内側または外側のいずれかに位置します。 多角形は凸状であり、セグメントは 1 つの間隔内で繰り返し交互に配置できないため、中点のみをテストするだけで十分です。 

機能`point_in_convex_polygon_strict`意図的に厳密なテストを使用します。 境界点は海上移動と同じコストがかかるため、境界点は外側として扱われます。 

実装の微妙な詳細の 1 つは、交差パラメータの重複です。 セグメントがポリゴンの頂点を正確に通過する場合、2 つのエッジが同じ交差を報告することがあります。 重複排除を行わないと、長さゼロの間隔が現れ、数値が不安定になります。 

グラフが小さいという理由だけで、ダイクストラの代わりにフロイド-ウォーシャルが使用されます。 ノードが最大 32 個であれば、3 次の複雑さは無視できます。

ここで完全な交差を考えてみましょう。```
0 0 10 0
4
4 -3 6 -3 6 3 4 3
```セグメントは次の位置に入力されます。`x = 4`で終了します`x = 6`。 

パラメータの間隔は次のとおりです。 

| 間隔 | 内部？ |
 | --- | --- |
 | [0, 0.4] | いいえ |
 | [0.4、0.6] | はい |
 | [0.6, 1] | いいえ |

 内側の分数は`0.2`ですので、内側の長さは`2`。 

総費用:```
10 + 2 = 12
```最後に、ポリゴン エッジに位置合わせされたセグメントを考えます。```

```パスは長方形の下端に沿って配置されます。 

境界点は厳密な包含テストに合格しないため、中間点テストでは区間が厳密に内側として分類されることはありません。 

アルゴリズムは正しく出力します`10`、エッジトラバースを海の動きとして扱います。
