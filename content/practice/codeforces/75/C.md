 ## 解決策
 ## 問題の理解

 2 つの正の整数が与えられ、その後、多くの範囲クエリが与えられます。 クエリごとに`[low, high]`、両方の数値を割る、その区間内で最大の整数を見つける必要があります。 

最初の観察は、私たちは実際には協力していないということです。`a`そして`b`独立して。 両方を割る数値は必ず割らなければなりません`gcd(a, b)`。 2 つの数値の gcd を計算すると、すべての有効な答えがその約数の 1 つになります。 

入力サイズは、クエリに迅速に応答する必要があることを強く示唆しています。 数字自体は到達できる`10^9`そのため、クエリ範囲内のすべての整数を反復処理することは不可能になります。 1 つのクエリ間隔に 10 億個の数値が含まれる場合があります。 まで`10^4`クエリ、さらには`O(high - low)`クエリごとのアプローチは壊滅的になります。 

同時に、`10^9`は十分に小さいため、数値の約数を列挙することが可能です。 までの数値`10^9`約数はせいぜい数千程度です。 以下の整数をチェックしてすべての約数を見つける`sqrt(g)`十分に速いので、`sqrt(10^9)`おおよそです`31623`。 

難しいのは、範囲条件を正しく処理することです。 gcd の約数だけが必要なわけではありません。 内側にある最大の約数が必要です`[low, high]`。 

誤った実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 

仮定する：```
a = 12
b = 18
query = [7, 11]
```gcd は`6`、約数は`{1, 2, 3, 6}`。 区間内には何もないので、答えは次のようになります。`-1`。 から下方向に検索するだけの不用意な実装`high`割り算を注意深く確認しないと、誤って戻ってしまう可能性があります`6`たとえ範囲外であっても。 

もう 1 つの微妙なケースは、答えが下限に等しい場合に現れます。```
a = 100
b = 50
query = [25, 30]
```公約数は次のとおりです。`{1, 2, 5, 10, 25, 50}`。 正しい答えは、`25`。 二分検索の境界が正しく処理されない場合、完全一致をスキップして結果が返される可能性があります。`-1`。 

除数を生成する際には、完全二乗にも注意が必要です。```
gcd = 36
```を繰り返しながら、`i = 6`、 両方`i`そして`gcd // i`は同じ約数です。 両方の盲目的な複製を追加する`6`。 後で重複を並べ替えてもアルゴリズムは機能しますが、不必要な重複は推論を複雑にし、時間を無駄にします。 

最後に、gcd 自体が範囲内にある場合を考えてみましょう。```
a = 9
b = 27
query = [9, 11]
```答えはすぐに`9`。 一部の間違った解決策では、厳密に小さい約数を検索します。`high`、この正確な境界のケースを見逃します。 

## アプローチ

 最も直接的なアプローチは、各クエリを個別に処理することです。 お問い合わせの場合`[low, high]`から下方向に反復できます。`high`に`low`各数値が両方を割るかどうかを確認します`a`そして`b`。 

これは、最初に見つかった有効な数値が自動的に区間内で最大の有効な約数になるため、機能します。 

問題は走行時間です。 最悪の場合、クエリ範囲にはほぼ次のものが含まれる可能性があります。`10^9`数字。 と`10^4`クエリを実行すると、これは完全に不可能になります。 

重要な観察は、次のすべての公約数が`a`そして`b`分けなければなりません`g = gcd(a, b)`。 

区間自体を検索する代わりに、次のすべての約数を事前に計算できます。`g`。 これにより、問題は次のように変わります。 

「両方の数値を割る範囲内の整数を見つけます」

 に:

 「最大の約数を求めよ`g`範囲内です。」

 それははるかに小さいです。 までの数値`10^9`サイズに比べて約数が非常に少ないです。 すべての約数を生成できます`O(sqrt(g))`、それらを一度並べ替えてから、二分検索を使用して各クエリに答えます。 

お問い合わせの場合`[low, high]`、最大の約数を二分探索します。`<= high`。 その約数がまだ少なくとも`low`、それが答えです。 それ以外の場合は、有効な約数が存在しません。 

割り算のチェックは単純かつ正確であるため、総当り攻撃は機能しますが、膨大な数値範囲を検索するため失敗します。 除数ベースのソリューションが成功するのは、考えられる答えのセットが小さく、すべてのクエリにわたって固定されているためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × 範囲サイズ) | お(1) | 遅すぎる |
 | 最適 | O(sqrt(g) + n log d) | O(d) | 承認済み |

 ここ、`g = gcd(a, b)`そして`d`は約数の数です`g`。 

## アルゴリズムのチュートリアル

 1. 整数を読み取る`a`そして`b`。 
2. コンピューティング`g = gcd(a, b)`。 

のすべての公約数`a`そして`b`分けなければなりません`g`したがって、すべての有効な答えは次の約数から得られます。`g`。 
3. すべての約数を生成します。`g`。 

から反復します`1`に`sqrt(g)`。 いつでも`i`分割する`g`、 両方`i`そして`g // i`は約数です。 
4. 次の場合は重複挿入を避けてください。`i * i == g`。 

完全平方では同じ約数が 2 回生成されるため、挿入するのは 1 回だけです。 
5. 除数リストを並べ替えます。 

二分探索にはソートされた順序が必要です。 
6. 各クエリについて`[low, high]`、最大の約数を求める二分探索`<= high`。 

Pythonでは、`bisect_right(divs, high) - 1`以下を超えない最大の約数のインデックスを与えます`high`。 
7. この除数が少なくともまだあるかどうかを確認します`low`。 

「はい」の場合は、印刷してください。 それ以外の場合は印刷します`-1`。 

### なぜ効果があるのか

 このアルゴリズムは 1 つのプロパティに依存します。 

両方を割る数値`a`そして`b`それが分かれる場合にのみ`gcd(a, b)`。 

つまり、考えられる答えの完全なセットは、まさに次の約数のセットです。`g`。 これらの約数を並べ替えることにより、二分探索では常に最大の約数を見つけることができます。`high`。 その値も少なくとも`low`、それは必要な間隔内にあり、可能な最大の有効な答えです。 より小さい場合`low`の場合、以前のすべての約数はさらに小さくなり、区間内に有効な約数は存在しません。 

## Python ソリューション```python
import sys
from math import gcd, isqrt
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    g = gcd(a, b)

    divisors = []

    for i in range(1, isqrt(g) + 1):
        if g % i == 0:
            divisors.append(i)

            other = g // i
            if other != i:
                divisors.append(other)

    divisors.sort()

    q = int(input())

    for _ in range(q):
        low, high = map(int, input().split())

        idx = bisect_right(divisors, high) - 1

        if idx >= 0 and divisors[idx] >= low:
            print(divisors[idx])
        else:
            print(-1)

solve()
```解決策は、元の問題を gcd 問題に折りたたむことから始まります。 一度`g = gcd(a, b)`が計算されると、すべての有効な答えはその約数から得られる必要があります。 

除数生成ループは最大でのみ実行されます。`sqrt(g)`。 いつでも`i`分割する`g`、すぐにわかります。`g // i`も約数です。 このペア生成のトリックにより、複雑さが線形時間から平方根時間に軽減されます。 

条件:```
if other != i:
```完全平方を正しく処理します。 それがなければ、約数は次のようになります`6`で`36`2回挿入されてしまいます。 

除数リストをソートした後、各クエリは二分探索問題になります。`bisect_right(divisors, high)`すべての値の後に挿入位置を返します`<= high`。 1 を減算すると、最大の有効な候補のインデックスが得られます。 

境界チェック:```
divisors[idx] >= low
```が不可欠です。 二分探索では、除数が最大であることのみが保証されます。`high`。 それが間隔内にあることを確認する必要があります。 

実装では使用します`isqrt`浮動小数点平方根の代わりに。 整数平方根は精度の問題を回避し、除数の列挙をよりクリーンにします。

import sys
import io
from math import gcd, isqrt
from bisect import bisect_right

def solve():
    input = sys.stdin.readline

    a, b = map(int, input().split())

    g = gcd(a, b)

    divisors = []

    for i in range(1, isqrt(g) + 1):
        if g % i == 0:
            divisors.append(i)

            other = g // i
            if other != i:
                divisors.append(other)

    divisors.sort()

        if idx >= 0 and divisors[idx] >= low:
            out.append(str(divisors[idx]))
        else:
            out.append("-1")
