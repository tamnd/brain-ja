 ## 解決策
 ## 問題の理解

 2 つの正の整数が与えられます。`a`そして`b`。 まず、それらの通常の合計を計算します`c = a + b`。 次に、同じ変換を 3 つの数値すべてに適用します。すべての桁を削除します。`0`10 進表現から。 

問題は、変換された方程式が依然として成立するかどうかです。 つまり、すべてのゼロを削除した後、`a`、`b`、 そして`c`、まだありますか？`remove_zero(a) + remove_zero(b) = remove_zero(c)`?

 入力は 2 つの整数で構成されます`a`そして`b`。 出力は`"YES"`ゼロを削除しても等価が真のままの場合、それ以外の場合`"NO"`。 

制約は非常に小さいです。 どちらの数値も最大で`10^9`, これは、各数値が最大 10 桁であることを意味します。 数字を 1 つずつ処理する操作は実質的に定数時間です。 ここでは、数値を文字列に複数回変換することさえ簡単です。 これにより、問題は最適化に関するものではなく、変換を正しく実装することにあることがすぐにわかります。 

間違いの主な原因は、ゼロ除去ステップを不用意に扱うことです。 

変換された数値が空になると、簡単なバグが 1 つ発生します。 考慮する：```
a = 1000
b = 9000
```ゼロを削除した後:```
a -> 1
b -> 9
c = 10000 -> 1
```空の文字列を解析しようとする不用意な実装は、数値がすべてゼロの場合にクラッシュする可能性があります。 この問題では、元の入力は正で非ゼロですが、中間処理は依然として堅牢である必要があります。 

もう 1 つのよくある間違いは、すべてのゼロではなく、先頭のゼロだけを削除することです。 例えば：```
a = 105
b = 106
```正しい変換:```
105 -> 15
106 -> 16
211 -> 211
```以来`15 + 16 != 211`、答えは`"NO"`。 

先頭のゼロだけを削除すると、誤って保持されてしまいます。`105`そして`106`変わらない。 

さらに微妙な問題は、整数ではなく文字列を比較することに起因します。 考慮する：```
a = 500
b = 500
```ゼロを削除した後:```
500 -> 5
500 -> 5
1000 -> 1
```得られるものは次のとおりです。```
5 + 5 = 10
1 != 10
```答えは`"NO"`。 

比較は変換後に数値的に行われる必要があります。 

## アプローチ

 最も直接的な強引なアイデアは、ステートメントが説明する内容を正確にシミュレートすることです。 コンピューティング`c = a + b`、3 つの数値をすべて文字列に変換し、すべてを削除します。`'0'`文字を入力し、結果を整数に変換し直し、最後に変換された方程式を比較します。 

すべての数値は最大 10 桁であるため、これはすでに定数時間で実行されます。 操作を正確に数えたとしても、合計で数十文字しかスキャンしません。 

ここには意味のある遅いアプローチはありませんが、よりぎこちない実装では、算術演算を使用して数値を桁ごとに再構築する可能性があります。 たとえば、繰り返し摂取すると、`% 10`、ゼロをスキップして、答えを再構築します。 これも正しく動作しますが、数字が逆の順序で到着するため、実装ではエラーが発生しやすくなります。 

重要な点は、変換が自然に文字列操作であるということです。 10 進表現からすべてのゼロを削除することは、まさに文字列置換の設計目的です。 制約が小さく、操作がテキストであることがわかれば、最もクリーンな解決策が明らかになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 桁ごとの算術再構成 | O(d) | お(1) | 承認済み |
 | 文字列変換 | O(d) | O(d) | 承認済み |

 ここ、`d`は桁数で、最大 10 です。 

## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`そして`b`。 

変換された等価性は元の合計に依存するため、両方の元の値が必要です。 
2. コンピューティング`c = a + b`。 

問題の定義`c`この方法では、ゼロを削除した後に再計算するのではなく、実際の合計を変換する必要があります。 
3. すべてを削除するヘルパー関数を作成します。`'0'`数値の 10 進表現の文字。 

数値を文字列に変換し、すべて置き換えます`'0'`文字を空の文字列で置き換えた後、結果を整数に変換し直します。 
4. 変換を適用します。`a`、`b`、 そして`c`。 

これらの値を次のようにします`na`、`nb`、 そして`nc`。 
5. かどうかを確認します。`na + nb == nc`。 

true の場合、印刷します`"YES"`、それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 アルゴリズムは問題の定義に直接従います。 ヘルパー関数は、10 進表現からすべてのゼロ桁を削除した後に得られる数値を正確に生成します。 同じ変換を独立して適用するので、`a`、`b`、 そして`a + b`、最後の比較は必要な条件と正確に一致します。 近似やショートカットは含まれないため、アルゴリズムが誤った結果を生成することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def remove_zeros(x):
    return int(str(x).replace('0', ''))

def solve():
    a = int(input())
    b = int(input())

    c = a + b

    na = remove_zeros(a)
    nb = remove_zeros(b)
    nc = remove_zeros(c)

    if na + nb == nc:
        print("YES")
    else:
        print("NO")

solve()
```ヘルパー関数は、変換全体を 1 行で処理します。 文字列に変換すると、すべてのゼロを直接削除できます。`replace('0', '')`。 整数に戻すと、比較に必要な数値が得られます。 

操作の順序が重要です。 まず計算する必要があります`c = a + b`元の数値を使用します。 その後初めてゼロを削除します。 変換後に合計を計算すると、別の問題が解決されます。 

元の入力は正の整数であり、ゼロを削除した後は常に少なくとも 1 つの非ゼロ桁が残るため、実装は安全です。 例えば、`1000`になる`"1"`、空の文字列ではありません。
