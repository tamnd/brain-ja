 ## 解決策
 ## 問題の理解

 同じ長さの整数の 2 つの配列が与えられます。 要素を繰り返し変換することはできますが、それは一方向のみです。各操作は値をその最大の適切な約数で置き換えます。これは、最大の約数が数値自体よりも厳密に小さいことを意味します。 この操作は、どちらかの配列のインデックスに独立して適用できます。 

目標は、要素を再配置することではなく、これらの除数削減演算のシーケンスを個々の位置に適用することによって、2 つの配列を同一にすることです。 各操作のコストは 1 であり、両方の配列で必要な操作の合計数を最小限にする必要があります。 

このプロセスについて考えるのに役立つ方法は、すべての数値が決定論的な下向きのチェーンを定義するということです。つまり、x から開始して next(x) を繰り返し適用すると、最終的には 1 になります。両方の配列の各要素は独自のチェーンを下っていき、A[i] と B[i] が同じ値になるようにすべての位置を同期して、合計ステップを最小限に抑えたいと考えています。 

制約が十分に大きいため、クエリごとに除数関数を独立して繰り返しシミュレートすることはできません。 配列サイズの合計は 2 × 10^5 に達しますが、値は 10^7 に達します。これにより、単純な要素ごとの因数分解や、償却されないループ内での繰り返しの除数検索が排除されます。 

数字がすぐに 1 に達する場合、微妙なケースが発生します。 next(1) は厳密な意味では未定義であるため、1 を固定小数点として扱います。要素が 1 になると、それ以上の操作は不可能になります。 これにより、状態空間に厳密な境界が作成され、パスを比較するときにこの境界を尊重する必要があります。 

もう 1 つの重要なシナリオは、A[i] と B[i] がすでに同じチェーン上にあるものの、深さが異なる場合です。 たとえば、12 → 6 → 3 → 1 と 18 → 9 → 3 → 1 です。12 と 18 は大きく異なりますが、3 に収束します。最適な戦略は、必ずしも 1 ではなく、可能な限り最良の共通ノードで一致することです。 

## アプローチ

 直接的なアプローチは、要素ごとに独立してプロセスをシミュレートし、next(x) を繰り返し適用することで A[i] と B[i] の到達可能な値をすべて生成することです。 次に、考えられるすべての集合点を試し、これらのチェーン内の最小合計距離を計算します。 これは正しいです。有効な変換シーケンスはすべて除数チェーンに従う必要があるからです。 ただし、各数値の最大の適切な約数を見つけるには 1 ステップあたり最大 O(√x) の作業が必要となり、値ごとに多数のステップが存在する可能性があるため、これはすぐにコストが高くなります。 すべてのテスト ケースで、これは遅すぎます。 

重要な観察は、このプロセスがすべての数値から 1 までの一意の有向パスを定義していることです。これは、すべての値に後続が 1 つだけあることを意味します。そのため、1 に結合するチェーンのフォレストである関数グラフを扱っていることになります。この構造を認識すると、遭遇した任意の数値のチェーン全体を事前計算し、結果をキャッシュできるため、繰り返しのクエリで計算済みの遷移が再利用されます。 

問題は次のようになります。各ペア A[i]、B[i] について、事前に計算されたチェーンに沿った共通ノードまでの最小合計距離が必要になります。 これは、構造がルート 1 のチェーン グラフであることを除けば、ルート ツリー内の 2 つのパス上で最適な合流点を見つけることと同じです。 

これを効率的に行うために、遭遇したすべての値に対して next(x) をメモ化し、各数値が 1 回だけ因数分解されるようにします。 次に、各値から 1 までの完全なパスを構築し、距離を保存します。 最後に、一方のチェーンの値から深さまでのハッシュ マップを使用して 2 つのパスを比較し、もう一方のチェーンをスキャンして最適な交差部分を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション | O(n √x) 最悪の場合 | O(1) おまけ | 遅すぎる |
 | メモ化されたチェーン構築 + パス交差点 | O(異なる状態の合計) | O(状態の合計) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. いずれかの配列に現れるすべての値 x について、その次の状態 next(x) を計算します。これは、x より小さい最大の約数として定義されます。 各 x が最大 1 回因数分解されるように結果をキャッシュします。 これにより、テスト ケース全体で除数を繰り返し再計算することが回避されます。 
2. 与えられた数値 x について、1 に達するまで完全な降下チェーンを構築します。構築中に、訪問したすべてのノードの位置 (x からの距離) を辞書に保存します。 これにより、チェーンが構築されると、O(1) で「チェーン内の x が値 v からどのくらい離れているか」を答えることができます。 
3. 各インデックス i に対して、2 つのチェーンができました。1 つは A[i] から始まり、もう 1 つは B[i] から始まります。 ハッシュ マップにインデックスを付けるために短いチェーンを選択し、値→距離を保存します。 
4. 次に、もう一方のチェーンを走査し、各値 v について、それがハッシュ マップに存在するかどうかを確認します。 存在する場合、総コストは distA[v] + distB[v] として計算されます。 すべての共有値の最小値を追跡します。 
5. インデックスの答えは、すべての交差点にわたる最小コストです。 

常にすべての交差を考慮する理由は、有効な一連の操作では両方の数値を決定論的なチェーンの下に移動する必要があるためです。そのため、それらが一致する最初のポイントは、まさにチェーン内の共有ノードになるからです。 

### なぜ効果があるのか

 各数値は 1 で終わる固有の単調減少パスを定義し、すべての操作は厳密にこのパスに沿って進みます。 したがって、あらゆる変換シーケンスは、このパス上のノードの選択に正確に対応します。 2 つの数値の場合、到達可能な共通の値は両方のパス上に存在する必要があり、その値に到達するには、各パスに沿った距離の合計が正確に必要になります。 したがって、操作を最小化することは、すべての共有ノードにわたる深さの最小合計を見つけることと同等であり、これはまさにアルゴリズムが計算するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

sys.setrecursionlimit(10**7)

# cache for next(x)
next_cache = {}

def next_divisor(x):
    if x in next_cache:
        return next_cache[x]
    # find largest proper divisor
    # since x <= 1e7, we can scan up to sqrt(x)
    best = 1
    i = 2
    while i * i <= x:
        if x % i == 0:
            best = max(best, x // i)
        i += 1
    next_cache[x] = best
    return best

def build_chain(x):
    chain = []
    dist = {}
    d = 0
    while True:
        chain.append(x)
        if x in dist:
            break
        dist[x] = d
        if x == 1:
            break
        x = next_divisor(x)
        d += 1
    return chain, dist

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))

        ans = 0

        for a, b in zip(A, B):
            chain_a, dist_a = build_chain(a)
            chain_b, dist_b = build_chain(b)

            if len(dist_a) > len(dist_b):
                dist_a, dist_b = dist_b, dist_a
                chain_a, chain_b = chain_b, chain_a

            best = float('inf')

            for v in dist_a:
                if v in dist_b:
                    best = min(best, dist_a[v] + dist_b[v])

            ans += best

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、エンドポイント値ごとに完全な除数降下チェーンが構築されます。 でのキャッシング`next_divisor`同じ数値の因子検索を繰り返すことで、テスト ケース全体でコストのかかる作業が繰り返されないようにすることができます。 

重要な実装の詳細は、チェーンと距離辞書の両方を保存することです。 これにより、距離を繰り返し再計算するのではなく、一定時間の交差点チェックが可能になります。 の交換`dist_a`そして`dist_b`これにより、より小さい辞書を反復処理できるようになり、実際のオーバーヘッドが削減されます。 

微妙な点は、チェーンが長いことを決して想定していないことです。 値が 10^7 まで増加しても、ほとんどの数値は最大除数のジャンプが繰り返されるとすぐに崩壊するため、実際にはチェーンは短いままになります。 

## 実用的な例

 ### 例 1

 入力:```
A = [4, 5]
B = [8, 3]
```インデックスごとにトレースします。 

(4, 8) の場合:

 | ステップ | パス | B パス | 共通の値 | 最高のコスト |
 | --- | --- | --- | --- | --- |
 | 1 | 4→2→1 | 8→4→2→1 | 4、2、1 | 2 |
 | 最適な集合場所は 2 で、コストは 1 + 1 = 2 です。 | | | |

 (5, 3) の場合:

 | ステップ | パス | B パス | 共通の値 | 最高のコスト |
 | --- | --- | --- | --- | --- |
 | 1 | 5→1 | 3→1 | 1 | 2 |
 | 唯一の集合場所は 1 で、コストは 1 + 1 = 2 です。 | | | |

 合計 = 4。 

これは、アルゴリズムが必要な場合を除き、1 での会議を強制しないことを示しています。

A = [12]

```| ステップ | 12チェーン | 18チェーン | 交差点 | コスト |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑ テストごとのチェーンの長さ) | 各要素はその除数チェーンを 1 回構築し、そのチェーンにわたって線形時間でマップを比較します。

 ## 特殊なケース

 1 つのエッジ ケースは、1 回の操作後に両方の数値がすぐに 1 になる場合に発生します。 たとえば、(2, 3)。 2 のチェーンは [2, 1]、3 のチェーンは [3, 1] です。 唯一の交差は 1 であり、アルゴリズムは 2 つの演算を正しく返します。 

もう 1 つのエッジ ケースは、1 つの数値がすでに 1 である場合です。(1, x) の場合、1 の連鎖は単なる [1] であるため、考えられる唯一の集合点は 1 です。コストは単純に x から 1 までの深さであり、アルゴリズムは特別なケースを使用せずに距離辞書を通じてこれを取得します。 

最後のエッジケースは、(12, 18) のように、数値が 1 ではなく深い中間約数を共有する場合です。 このアルゴリズムは複数の交点を正確に識別し、ルートをデフォルトとするのではなく、合計距離を最小にする交点を選択します。
