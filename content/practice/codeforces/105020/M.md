 ## 問題の理解

 指定された整数が正しいかどうかを判断するように求められます。$x$ある値から始まる連続する正の整数のブロックの合計として表すことができます。$l$そして終わる$r$。 言い換えれば、それらを加算すると正確に結果が得られるような、連続する自然数のセグメントが必要です。$x$、同時にセグメント自体が厳密に前であることも保証します。$x$エンドポイントの観点から見ると、$r < x$。 

各テスト ケースには 1 つの数値が与えられます$x$それぞれについて、有効なペアを出力する必要があります。$(l, r)$または、そのようなセグメントが存在しないことを報告します。 

この制約により、すべての間隔でブルート フォースを実行することは不可能になります。 全体にわたる単純なスキャン$l$そして$r$大まかにチェックする必要があります$O(x^2)$テストごとの範囲とそれ以降$x$と同じ大きさにすることができます$2 \cdot 10^9$、これはまったく不可能です。 考えられるすべてのセグメント長を反復処理する場合でも、直接実行すると大きすぎます。 

より微妙な制約が要件です$r < x$。 これにより、単一の数値を取得するような単純な構造が防止されます。$x$それ自体、または正確に終わる範囲$x$したがって、どのような解法でも、自然数内に埋め込まれた真に小さいセグメントを生成する必要があります。 

エッジケースは、小さな値や三角差として表現できない値の周囲に現れます。 例えば、$x = 1$そして$x = 2$有効なセグメントが可能な限り小さいため、明らかに失敗します。$1 + 2 = 3$すでにそれらを超えています。 もう 1 つの興味深いケースは、三角数を含む表現における 2 の累乗マイナス 1 の動作です。この場合、割り算条件によって多くの値が暗黙的に除外されます。 

## アプローチ

 ブルートフォースメソッドは修正を試みます$l$そして延長します$r$と等しいかそれを超えるまで累計を維持します。$x$。 これにより、考えられるすべてのセグメントが正しく列挙され、有効な答えが存在する場合にはそれが見つかります。 ただし、開始点ごとに、内側のループは最大で実行される場合があります。$O(\sqrt{x})$あるいは$O(x)$最悪の場合、ステップを繰り返すと、合計実行時間が実行可能な制限をはるかに超えてしまいます。$10^3$テストケース。 

重要な観察は、連続する整数の合計が等差数列を形成し、これは閉じた形式で書くことができるということです。$$\sum_{i=l}^{r} i = \frac{(l + r)(r - l + 1)}{2}$$区間を検索する代わりに、有効な合計の構造を推論できます。 整数を探しています$l, r$次のような:$$x = \frac{(l + r)(r - l + 1)}{2}$$セグメントの長さを次のようにします$k = r - l + 1$。 それから：$$x = \frac{k(2l + k - 1)}{2}$$並べ替え:$$2x = k(2l + k - 1)$$これは、可能なセグメント長を反復できることを意味します$k$、結果の式が有効な整数を生成するかどうかを確認します。$l$。 もし$l$ポジティブであり、$r = l + k - 1 < x$、承ります。 

重要な効率向上は次のとおりです。$k$まで上がるだけでいい$O(\sqrt{x})$、 なぜなら$k(k+1)/2 \le x$意味のある最大長を制限します。 これにより、テスト ケースあたりの問題が 2 次時間から本質的に平方根時間に短縮されます。

 ## アルゴリズムのチュートリアル

 私たちは問題をセグメント長の検索に変換することに焦点を当てます。 

1. 各テスト ケースの値を読み取ります。$x$。 

目的は、有効なセグメントを見つけるか、不可能であると結論付けることです。 
2. 可能な長さにわたって反復する$k$、2から始まります。 

長さ 1 は役に立ちません。$l = x$に違反します$r < x$。 
3. それぞれについて$k$、必要な合計式を再配置して計算します。$l$:$$2x = k(2l + k - 1)$$私たちは以下を隔離します：$$2l = \frac{2x}{k} - (k - 1)$$もし$2x$で割り切れない$k$、これはスキップしてください$k$。 
4. 割り切れたら計算する$l$そして導き出す$r = l + k - 1$。 

それを確認します$l \ge 1$そして$r < x$、問題の制約の下で妥当性を保証します。 
5. 有効なペアが見つかった場合は、すぐに出力します。 

有効な回答はどれでも受け入れられるため、さらに検索する必要はありません。 
6. すべて使い尽くしても有効なペアが存在しない場合$k$、-1を出力します。 

### なぜ効果があるのか

 すべての有効なソリューションはペアに一意に対応します$(k, l)$どこ$k$セグメントの長さです。 実行可能なすべての長さにわたって反復して再構築することにより、$l$代数的には、区間を推測するのではなく、区間を定義する方程式を直接解きます。 すべての候補セグメントが 1 つのみにマッピングされるため、$k$、検索空間は完全であり、有効な解決策を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())

        found = False

        # try segment length k
        for k in range(2, 2 * 10**6):  # safe upper bound (sqrt(2x))
            num = 2 * x - k * (k - 1)
            if num <= 0:
                break
            if num % (2 * k) != 0:
                continue

            l = num // (2 * k)
            r = l + k - 1

            if l >= 1 and r < x:
                print(l, r)
                found = True
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは代数的縮約に直接従います。 可能なセグメント長を繰り返し、開始点を再構築します。$l$並べ替えた合計公式を使用します。 分子が非正になったときに早めに中断することで、すでに目標合計を超えている長さに時間を無駄にすることがなくなります。 

微妙な点は、整数演算を注意深く維持することです。 表現`num = 2 * x - k * (k - 1)`精度の問題を回避し、正確な割り算チェックを確実にするために、割り算の前に計算する必要があります。 条件`r < x`問題の厳密な境界要件を強制します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        x = int(input())
        found = False
        for k in range(2, 2000000):
            num = 2 * x - k * (k - 1)
            if num <= 0:
                break
            if num % (2 * k) != 0:
                continue

                out.append(f"{l} {r}")
                found = True
                break
        if not found:
            out.append("-1")
    return "\n".join(out)

 ## 特殊なケース

 のために$x = 1$、ループはすぐに有効なものを見つけません。$k$なぜなら、最小のセグメント合計でも$1 + 2 = 3$すでにターゲットを超えているため、アルゴリズムは正しく -1 を出力します。 

次のような非常に小さな複合値の場合、$x = 5$、アルゴリズムはすぐに識別します$k = 2$与える$[2, 3]$、そしてそれを検証します$r < x$これは、境界チェックが有効な短いセグメントを誤って拒否しないことを示しています。 

等差数列がきれいに適合しない大きな素数のような値の場合、すべての候補が$k$は割り切れず、負の分子条件によりループが早期に終了し、実行不可能なケースが完全な列挙なしで効率的に終了することが確認されます。
