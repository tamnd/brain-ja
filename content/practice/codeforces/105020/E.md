 ## 解決策
 ## 問題の理解

 このゲームの各プレイヤーは、もしそれらのプレイヤーが裁判にかけられた場合に反対票を投じる他のプレイヤーの個人リストを保持しています。 投票プロセスは決定的です。特定のプレーヤーが告発されると、他のすべてのプレーヤーは、その告発されたプレーヤーが個人の容疑者リストに含まれているかどうかを確認します。 そうであれば、彼らは排除に投票する。 それ以外の場合は、そうではありません。 

厳密に全プレイヤーの半数以上が反対票を投じた場合、プレイヤーはラウンドで敗退します。 課題は、各プレイヤーが裁判にかけられた場合に排除されるかどうかを個別に判断することです。 

したがって、各プレイヤーにとって$x$、概念的にトライアルをシミュレートし、他のプレイヤーの数を数えます。$x$彼らの容疑者リストに載っている。 その数を超えると$\frac{n}{2}$、 それから$x$排除されるだろう。 そうでなければ、彼らはその仮定の試練を生き延びます。 

入力構造は基本的に、各プレーヤーの有向関係を記述します。$i$反対票を投じるプレイヤーのセットを指します。 問題は、この有向グラフ内の各ノードに対して入ってくる投票を数えることと、どのノードの次数が厳密に半分よりも大きいかを確認することになります。$n$。 

この制約により、私たちは線形または線形に近い解決策に向かうことになります。 すべてのテスト ケースにわたるすべての疑わしいリストの合計サイズは次の制限を受けます。$4 \cdot 10^5$これは、各エッジを一定回数処理するあらゆるソリューションが受け入れられることを意味します。 ただし、各プレーヤーのクエリごとのシミュレーションは、すべてのリストを繰り返しスキャンするため、遅すぎます。$O(n^2)$最悪の場合の行動。 

過半数のしきい値に達するプレイヤーがいない場合、微妙なエッジケースが発生します。 たとえば、次の場合$n = 4$各プレーヤーが最大でも 1 人の他のプレーヤーによってのみ疑われている場合、しきい値は厳密に 2 より大きいため、誰も資格を得ることができません。 もう 1 つのエッジケースは、プレイヤーがちょうど半数のプレイヤーに疑われている場合です。 この状態は厳密に 50% を超えているため、これを除外としてカウントしてはなりません。 

もう 1 つの重要な点は、構造上自己投票が不可能であるため、自己ループを処理したり削除したりする必要がないことです。 

## アプローチ

 各候補プレイヤーの直接シミュレーションは次のように機能します: 固定プレイヤーの場合$x$、他のすべてのプレイヤーのリストをスキャンし、どれだけのプレイヤーが含まれているかを数えます$x$。 これは正しいですが、高価です。 各クエリのコスト$O(\sum k_i)$、そしてこれを全員のために行う$n$プレイヤーが導くのは$O(n \cdot \sum k_i)$に退化します。$O(n^2)$密集したケースでは明らかに遅すぎます$n$まで$10^5$。 

重要な観察は、投票構造がクエリ間で変化しないことです。 各有向エッジ$i \rightarrow a_{ij}$反対にちょうど 1 票を投じる$a_{ij}$、そしてこの貢献は現在テストされているプレーヤーとは無関係です。 これは、すべてのリストに対する 1 回のパスですべてのノードの入力エッジの数を事前計算できることを意味します。 

これらのカウントが判明すると、各プレーヤーのカウントが次の値を超えているかどうかを確認することで、一定時間内に独立して評価できます。$\lfloor n/2 \rfloor$。 これにより、問題はエッジ上の単純な周波数累積問題に変換されます。

 ## アルゴリズムのチュートリアル

 私たちは問題を、すべての容疑者リスト全体で各プレイヤーが何回ターゲットにされたかを数え、しきい値でフィルタリングするというものに落とし込みます。 

1. 配列を作成する`cnt`サイズの$n + 1$、ゼロに初期化されます。 これには、各プレイヤーが受け取った投票数が保存されます。 インデックスはプレーヤーを表し、値は他のプレーヤーが何人のプレーヤーに反対票を投じるかを表します。 
2. すべてのプレイヤーの容疑者リストを繰り返し処理します。 エントリーごとに$a_{ij}$、増分`cnt[a_{ij}]`1つずつ。 このステップでは、入力構造に対する 1 回のパスですべての受信投票を集約します。 
3. 排除しきい値を次のように計算します。$\text{limit} = \lfloor n/2 \rfloor$。 プレーヤーは、投票数が厳密にこの値より大きい場合にのみ排除されます。 
4. すべてのプレーヤーを 1 から 1 まで繰り返します。$n$。 プレイヤーごとに$i$、どうかを確認してください`cnt[i] > limit`。 その場合は、含めてください$i$回答リストにあります。 
5. 回答リストのサイズを出力し、その後にソートされたリスト自体を出力します。 反復順序により、ソートがすでに保証されています。 

正しさは、各投票が質問された候補者から独立しているという事実にかかっています。 投票は単に固定エンドポイントに +1 を与えるエッジであり、削除条件は最終的な累積カウントのみに依存します。 

### なぜ効果があるのか

 いつでも、プレイヤーに対する投票数$x$は、正確に指す有向エッジの数です。$x$。 パッティングのシミュレーション$x$トライアルでは他の構造は変更されないため、投票分布はクエリの前に固定されます。 このアルゴリズムは、有向グラフ内の各ノードの次数を効果的に計算し、それをグローバルしきい値と比較します。 各エッジは 1 回だけ寄与し、どのエッジも二重にカウントされたり省略されたりすることはないため、計算された値はすべての仮説試行における真の投票数と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        cnt = [0] * (n + 1)

        for i in range(1, n + 1):
            parts = list(map(int, input().split()))
            k = parts[0]
            for x in parts[1:]:
                cnt[x] += 1

        limit = n // 2
        ans = []
        for i in range(1, n + 1):
            if cnt[i] > limit:
                ans.append(i)

        print(len(ans))
        if ans:
            print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各容疑者リストを 1 回読み取り、投票数を配列に直接集計します。 重要な実装上の選択は、プレイヤーごとのシミュレーションを避けることです。 代わりに、すべてのエッジが 1 回だけ処理されます。 しきい値の比較では整数除算が使用され、厳密な「50 パーセントを超える」条件が正しく実装されます。 

プレーヤーは昇順にチェックされるため、出力は自然にソートされます。

 ## 特殊なケース

 重要なエッジケースは、プレイヤーがちょうど半分の票を獲得した場合です。 たとえば、$n = 6$、プレーヤーが 3 つの受信投票を持っている場合、しきい値は厳密に 3 より大きいため、これらの投票を含めてはなりません。 アルゴリズムはこれを正しく処理します。`cnt[i] > n // 2`、 ない`>=`。 

もう 1 つのエッジ ケースは、1 人のプレイヤーがほぼすべての票を獲得する場合です。 すべてのリストがプレイヤー 1 を指す星型の構成では、`cnt[1] = n - 1`を常に超えます$n/2$のために$n \ge 2$したがって、プレーヤー 1 は常に含まれます。 カウントのアプローチでは、特別な処理を行わずにこれを自然に取得します。 

最後のケースは、すべてのプレイヤーのリストが空の場合です。 カウンタ配列はどこでもゼロのままで、しきい値を超えるインデックスはありません。これは追加のロジックなしで意図した動作と一致します。
