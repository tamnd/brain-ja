 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 配列は一連のクエリを通じて進化し、各クエリでは「ビューティフル デクリメント」と呼ばれる限られた数の同一の操作が可能になります。 

単一の美しい減少は、配列の 1 つの連続したセグメントに対して機能します。 セグメント内のすべての要素が厳密に正になるようにセグメントを選択し、そのセグメント内のすべての要素から 1 を減算します。 各演算の目標は任意ではありません。演算の適用後に配列の合計ができるだけ小さくなるようにセグメントを選択する必要があります。 

まで演奏した後、$k$クエリに対するこのような操作では、配列全体の合計を出力する必要があり、変更は将来のクエリまで保持されます。 

主な問題点は、各操作で配列が永続的に変更され、どのセグメントが有効か、どのセグメントが将来の最適な削減をもたらすかが変化することです。 

制約は次のとおりです$n, Q \le 10^5$したがって、操作ごとに最適なセグメントを最初から再計算するソリューションは、すぐに遅すぎます。 平$O(nk)$最悪の場合、すべてのクエリを実行することは不可能です。$k$できる$10^5$クエリごとに。 

単純な考えは、すべてのサブ配列をスキャンして最適なものを選択することによって各操作をシミュレートすることです。 サイズの定数配列のような単純な入力ではすでに失敗しています$10^5$、各操作にコストがかかるため$O(n^2)$慎重に行われた場合、または$O(n)$最適化を行ったとしても、$10^{10}$仕事。 

構造を追跡せずに、何かが壊れるまで常に配列全体をデクリメントしようとすると、より微妙な失敗が発生します。 たとえば、次のような配列では、$[3, 1, 3]$、中央の要素が最初に 0 に達し、配列が 2 つの独立した領域に分割されます。 ゼロ位置で動的に分割しないアプローチでは、引き続き無効なセグメントとオーバーカウントの削減が適用されます。 

## アプローチ

 ブルートフォースの観点は単純です。 各演算では、減少する要素の数が最大になるセグメントが選択されます。これは、減少した要素が合計に対して 1 単位の削減に寄与するためです。 したがって、常に正の値で構成される最長の利用可能なセグメントが必要になります。 

これを文字通りシミュレートすると、各ステップですべてのセグメントをスキャンし、最大のものを選択して減分し、一部の値がゼロになった後でセグメントを再計算する必要があります。 単一の要素は消滅する前に多くの操作の一部となる可能性があるため、このシミュレーションでは必要な場合があります。$O(nk)$最悪の場合、更新が遅すぎます。 

重要な観察は、有効なセグメントの構造は、要素がゼロになった場合にのみ変更されるということです。 このような 2 つのイベントの間では、同じセグメントが繰り返し最適な選択であり続けます。これは、そのセグメント内で内部順序が変更されることはなく、均一に下方にシフトするだけであるためです。 

これは、プロセスが正の値のセグメントで動作していると見なすことを示唆しています。 各セグメントには、デクリメントされた回数を表す現在の「レベル」があります。 セグメントは、そのレベルに対して最小要素がゼロに達するまで存在し続けます。 その瞬間、ゼロの位置で正確に小さなセグメントに分割されます。 

これにより、現在のサイズで順序付けされたセグメントに対する貪欲なプロセスが発生します。つまり、常に最大のセグメントを取得し、操作バジェットが使い果たされるか、セグメントが分割を生成するまで、できるだけ多くの完全なデクリメントを適用します。 分割が発生した場合は、新しいセグメントを作成して続行します。 

私たちはセグメントを長さ順に並べた構造で維持し、データ構造を使用して、デクリメントを繰り返した後にセグメントがゼロになる最初の位置を特定します。 これは、最小値のセグメント ツリーを使用して追跡されます。

 ## アルゴリズムのチュートリアル

 現在アクティブなセグメントはすべて、セグメント長順に並べられた最大ヒープ内に維持されます。 各セグメントには、その境界と、そのレベルと呼ばれるすでに適用されているデクリメントの数が保存されます。 

また、任意のセグメント内の最小値のクエリと、その最小値が発生する場所の特定をサポートする配列上のセグメント ツリーも維持します。 

### ステップ

 1. 配列全体を 1 つのセグメントとして初期化します。$[1, n]$レベル付き$0$、初期合計を計算します。 
2. このセグメントを、その長さをキーとした最大ヒープに挿入します。 これにより、最大の即時削減に寄与するセグメントが常に処理されるようになります。 
3. まだ作戦が残っているうちに$k$、ヒープから最大のセグメントを抽出します。 このセグメントは、操作ごとに最大の減少が得られるセグメントです。 
4. セグメント ツリーを使用してこのセグメント内の最小値をクエリし、セグメントの現在のレベルを減算します。 これにより、そのセグメント内の有効最小残存値が得られます。 
5. この有効最小値が残りの有効最小値よりも大きい場合$k$、残りのすべての操作をこのセグメントに安全に適用できます。 合計を次のように減らします$k \times \text{length}$そしてやめてください。 
6. それ以外の場合は、少なくとも 1 つの要素がゼロになるまで、正確にその数の操作を適用します。 これにより合計が減ります$\text{minValue} \times \text{length}$、そしてそれだけの操作を消費します。 
7. セグメントがゼロに達する位置を特定します。 これらの位置により、セグメントが厳密に正の値の小さなサブセグメントに分割されます。 
8. 新しいセグメントはそれぞれ同じグローバル デクリメント履歴から継続されるため、結果として生じるすべてのサブセグメントを、更新されたレベル情報とともにヒープにプッシュして戻します。 
9.すべて終わるまで続けます$k$操作が消費されます。 

### なぜ効果があるのか

 重要な不変条件は、すべてのアクティブなセグメントが、そのレベルで表される同じ量だけ常に均一に減少するということです。 セグメントが内部で部分的にデクリメントされることはありません。 一部の要素がゼロに達した場合にのみ分割されます。 ヒープは常に最大のセグメントを選択するため、すべての操作は、その時点で合計の最大の減少に寄与する領域に割り当てられます。 これにより、有効な演算シーケンスがグリーディ シーケンスよりも小さい合計を生成することはなくなります。これは、代替選択を行うと、より小さいセグメントで演算するか、分割を遅らせることになり、どちらも演算あたりの総減少量が減少するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, a):
        self.n = len(a)
        self.a = a
        self.seg = [0] * (4 * self.n)
        self.pos = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.seg[v] = self.a[l]
            self.pos[v] = l
            return
        m = (l + r) // 2
        self.build(v*2, l, m)
        self.build(v*2+1, m+1, r)
        if self.seg[v*2] <= self.seg[v*2+1]:
            self.seg[v] = self.seg[v*2]
            self.pos[v] = self.pos[v*2]
        else:
            self.seg[v] = self.seg[v*2+1]
            self.pos[v] = self.pos[v*2+1]

    def query_min(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return (10**18, -1)
        if ql <= l and r <= qr:
            return (self.seg[v], self.pos[v])
        m = (l + r) // 2
        x = self.query_min(v*2, l, m, ql, qr)
        y = self.query_min(v*2+1, m+1, r, ql, qr)
        return x if x[0] <= y[0] else y

def solve():
    n, Q = map(int, input().split())
    a = list(map(int, input().split()))
    st = SegTree(a)

    total = sum(a)

    import heapq
    heap = []
    heapq.heappush(heap, (-n, 0, n - 1, 0))  # (-len, l, r, level)

    for _ in range(Q):
        k = int(input())

        while k > 0 and heap:
            neglen, l, r, lvl = heapq.heappop(heap)
            length = -neglen

            mn, _ = st.query_min(1, 0, n - 1, l, r)
            effective_min = mn - lvl

            if effective_min > k:
                total -= k * length
                k = 0
                heapq.heappush(heap, (neglen, l, r, lvl + k))
                break

            if effective_min <= 0:
                continue

            total -= effective_min * length
            k -= effective_min

            new_lvl = lvl + effective_min

            # split segments at zeros
            i = l
            start = l
            while i <= r:
                if a[i] - new_lvl == 0:
                    if start <= i - 1:
                        heapq.heappush(heap, (-(i - start), start, i - 1, new_lvl))
                    start = i + 1
                i += 1

            if start <= r:
                heapq.heappush(heap, (-(r - start + 1), start, r, new_lvl))

        print(total)

if __name__ == "__main__":
    solve()
```セグメント ツリーは、セグメントを一律に減少させることができなくなった時期を特定するために使用されます。 ヒープにより、最も影響力のあるセグメントが常に最初に処理されます。 の`level`各セグメントに保存されたグローバル デクリメントの数は、そのセグメントにすでに適用されているものを追跡するため、配列の物理的な更新を回避します。 

微妙な点は、累積レベルを適用した後に要素がちょうどゼロになった場合にのみ分割が発生することです。 だからこそ私たちはチェックします`a[i] - new_lvl == 0`セグメントの再構築中。 

## 実用的な例

 小さな配列を考えてみましょう$[3, 1, 3]$と$k = 3$。 

まずは 1 つのセグメントから始めます$[0,2]$レベル0で。 

| ステップ | セグメント | レベル | 分 | アクション | 残り k | 合計の変化 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [0,2] | 0 | 1 | 1 減少を適用 | 2 | -3 |
 | 2 | インデックス 1 で分割 | 1 | 0 | [0,0] と [2,2] に分割 | 2 | 0 |
 | 3 | 最大のセグメントを選択 | 1 | 3 | 2 減少を適用 | 0 | -4 |

 これは、中央の要素がどのように分割を強制し、その後の操作が残りのセグメントに対して独立して動作するかを示しています。 

ここで一様な配列を考えてみましょう$[2,2,2,2]$と$k=2$。 

| ステップ | セグメント | レベル | 分 | アクション | 残り k | 合計の変化 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [0,3] | 0 | 2 | 2 減少を適用 | 0 | -8 |

 すべての要素が同時にゼロに達するため、分割は発生しません。 

これらの例は、アルゴリズムが早期の分割と均一な枯渇の両方を正しく処理することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、セグメントの最小値が 1 である場合です。この場合、操作を 1 回適用すると、すぐに複数の新しいセグメントが作成されます。 アルゴリズムは、次の位置で正確に分割することでこれを処理します。`a[i] - level == 0`、無効なセグメントが続かないようにします。 

もう 1 つのエッジ ケースは、セグメント内のすべての要素が等しい場合です。 セグメントは分割されることはなく、1 つの連続した操作バッチで完全に消費されます。`effective_min > k`ショートカットは正しくハンドルされます。 

最後のエッジ ケースは、k が複数のセグメントを連続的に使い果たすのに十分な大きさである場合に発生します。 ヒープにより、1 つのセグメントが消滅または分割された後、次に大きいセグメントが常に選択され、配列のグローバルな展開全体にわたって正確さが維持されます。
