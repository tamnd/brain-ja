 ## 問題の理解

単純に考えることは単純な間違いです$a$問題と返却$a$の制限を無視して、$m$。 もう 1 つの間違いは、条件を「正確に残す」と解釈することです。$m$「少なくとも」の代わりに$m$」と不当に平等を強制し、柔軟性を低下させることになります。

## アプローチ

 強引な解釈では、クッキーを 1 つずつ食べるシミュレーションを試行し、大きなクッキーがすべて食べられるか、残りの数が下回るまで常に大きなクッキーを優先します。$m$。 これは概念的に機能します。各ステップで 1 つの大きな Cookie を削除し、残りの Cookie が少なくとも残っているかどうかを確認します。$m$。 ただし、最悪の場合、最大でシミュレーションする可能性があります。$10^{12}$これは実行可能な期限をはるかに超えています。 

重要な観察は、プロセスが順序やランダム性に依存していないことです。 重要なのは、制約に違反せずに合計でいくつの Cookie を削除できるかということだけです。 取り除いたら$x$クッキー、それから$n - x \ge m$、 それで$x \le n - m$。 これは、削除できる Cookie の総数に上限があることを意味します。$n - m$。 大きな Cookie のみを削除したいため、実際に取得できる数も、存在する大きな Cookie の数によって制限されます。$a$。 したがって、答えは単純に、利用可能な大きな Cookie の数と安全に削除できる Cookie の最大数の間の最小値です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、 そして$a$。 これらは、合計 Cookie、最小限必要な残りの Cookie、および大きな Cookie の数を定義します。 
2. 条件に違反せずに削除できる Cookie の合計数を計算します。 少なくとも$m$せいぜい残らなければならない$n - m$クッキーは全部食べられます。 
3. この制限を次と比較します。$a$というのは、存在する以上の大きなクッキーを食べることができないからです。 
4. の小さい方の値を出力します。$a$そして$n - m$。 

ステップ 2 の背後にある理由は、クッキーが大きいか小さいかに関係なく、クッキーを食べるたびに残りのカウントが 1 つだけ減るということです。 したがって、制約は、タイプではなく、削除される合計数のみに依存します。 

### なぜ効果があるのか

 ドニアが食べたらいつでも$x$Cookie、残りの数は正確に$n - x$。 条件に必要なのは$n - x \ge m$、これを再配置すると、$x \le n - m$。 したがって、彼女が削除できる Cookie の総数は、グローバルに次のように制限されます。$n - m$。 彼女は大きな Cookie のみに興味があるため、最良の戦略は常に、予算が使い果たされるか、大きな Cookie がなくなるまで、この削除の「予算」をすべて大きな Cookie に費やすことです。 これにより、最大性と有効性の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, a = map(int, input().split())
        max_remove = n - m
        if max_remove < 0:
            max_remove = 0
        print(min(a, max_remove))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理します。 重要な計算は、`n - m`、少なくとも残したまま削除できる Cookie の最大数を表します。$m$後ろに。 もし$n < m$、この値は負になり、削除が許可されないためゼロにクランプされます。 

最終的な答えは、この許容可能な削除予算と利用可能な大きな Cookie の数の間の最小値です。 これにより、シミュレーションを行わずに派生制約が直接実装されます。

 ## 特殊なケース

 いつ$n = m$の場合、クッキーが食べられると残りの最小要件に違反するため、制約により削除はゼロになります。 アルゴリズムは計算します$n - m = 0$、最終的な答えは次のようになります$\min(a, 0) = 0$、これは要件に正確に一致します。 

いつ$n < m$、制約によって許可される、計算された値$n - m$はマイナスです。 実装ではこれをゼロにクランプします。これは、クッキーを食べることができないことを意味します。 これは、条件がすでに違反されているか、削除後に条件を満たすことが不可能であることを正しく反映しています。 

いつ$a \ge n - m$の場合、制限要因は、大きな Cookie の可用性ではなく、残りの制約になります。 アルゴリズムは正しく返します$n - m$、許容される容量がすべて使用されるようにします。
