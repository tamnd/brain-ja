 ## 解決策
 ## 問題の理解

 ある人が一定のお金を持っていて、価格がわかっている飲み物を買いたいという複数の独立したシナリオが与えられています。 シナリオごとに、利用可能な金額がコストをカバーするのに十分であるように、追加で必要な金額を決定する必要があります。 現在のお金がすでに価格をカバーしているか、それを超えている場合は、何も借りる必要はありません。 

各テスト ケースには 2 つの整数が含まれます。 1 つ目は現在利用可能な金額、2 つ目は飲み物の費用です。 各ケースの出力は、コストと利用可能なお金の間の不足額ですが、決してマイナスにはなりません。 

入力サイズは最大 100,000 のテスト ケースにすることができ、各値は最大 100,000 まで可能です。 これにより、一定の時間を超えてテスト ケースごとに追加の作業を行うアプローチは即座に排除されます。 ここでは O(t log t) であっても不要なオーバーヘッドであり、O(t) がターゲットであるため、テスト ケースごとのネストされたループまたはシミュレーションは制限時間を超えます。 

重要なエッジ動作は、利用可能な資金がすでに十分である場合に発生します。 たとえば、x = 10 および y = 7 の場合、答えは -3 ではなく 0 になります。 符号を保護せずに y - x を直接出力する単純な実装では、誤った負の出力が生成されます。 もう 1 つの微妙なケースは、x が y と正確に等しい場合であり、この場合も答えは 0 でなければなりません。 

## アプローチ

 この問題を考える最も直接的な方法は、合計が必要なコストに達するまで、一度に 1 ポンドずつ繰り返し借りていくことを想像することです。 x が y より小さい場合は、等しくなるまで繰り返し 1 を加算する必要があります。 この総当たり解釈は概念的には正しいですが、非効率的です。最悪の場合、x = 0 および y = 100,000 の場合、テスト ケースごとに 100,000 ステップが必要となり、最悪の入力サイズで 10^10 の演算が行われることになります。 

最終的な答えは 2 つの数値の差のみに依存するため、問題の構造によりシミュレーションの必要がなくなります。 段階的に借入する代わりに、正確な赤字を直接計算できます。 現在の金額がすでに十分であれば、赤字はゼロになります。 それ以外の場合は、正確に y - x になります。 この観察により、プロセス全体がテスト ケースごとに 1 つの算術比較に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t · | y − x | ) |
 | 最適 | O(t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ケースは独立しており、個別に処理できるため、テスト ケースの数 t を読み取ります。 
2. 各テスト ケースについて、利用可能な資金と必要なコストを表すペア (x, y) を読み取ります。 
3. x と y を比較して、不足があるかどうかを判断します。 
4. x が y 以上の場合、借入は必要なく、借入を負にすることはできないため、0 を出力します。 
5. それ以外の場合は、コストに到達するために必要な不足量を直接測定する y - x を出力します。 

### なぜ効果があるのか

 各テスト ケースの結果は、x が y をカバーするかどうかによってのみ決まります。 x ≥ y の場合、要件はすでに満たされているため、最小追加量はゼロになります。 x < y の場合、有効な解は x を少なくとも y まで増加させる必要があり、そのような増加の最小値は正確に y - x です。 代替の組み合わせや隠れた制約はないため、この違いによって一意に答えが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        if x >= y:
            print(0)
        else:
            print(y - x)

if __name__ == "__main__":
    solve()
```このソリューションは、高速入力を使用してすべてのテスト ケースを読み取り、最大 100,000 行を効率的に処理します。 各ケースは一定時間内に独立して処理されます。 条件チェックにより、負の値が出力されないことが保証されます。これは、この問題で最も一般的な実装ミスです。 

y - x の減算は、x < y の場合にのみ実行され、正確性が保証され、不必要な計算が回避されます。 この分離により、ロジックが明示的になり、等価性などのエッジケースに対して安全になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースは、一定数の操作 (1 回の読み取り、1 回の比較、1 回の減算) で処理されます。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、x が y に等しい場合の等価性です。 入力用`10 10`、アルゴリズムがチェックします`x >= y`これにより、金額がコストと正確に一致する場合、借入が必要ないことが確認されます。 

別のケースは、x がゼロの場合です。 のために`0 50`、条件`x >= y`失敗し、アルゴリズムが計算します`50 - 0 = 50`。 これにより、特別なケースを必要とせずに、不足している初期資金が正しく処理されることが保証されます。 

のような逆のケース`100 1`すべての場合に減算が誤って適用されないことをテストします。 以来`x >= y`が成立すると、出力は負の値を生成するのではなく、正しく 0 にクランプされます。
