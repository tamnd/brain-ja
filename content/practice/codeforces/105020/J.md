 ## 解決策
 ## 問題の理解

 各テスト ケースは、各木の高さが固定された複数の木がある公園を記述します。 アムルは一本の木を選んで後ろに隠れます。 彼が捕まるかどうかは、彼の身長とその選ばれた木の高さの比較によってのみ決まります。 

ルールは簡単です。アムルが隠れている木がアムル自身よりも短い場合にのみ、ガマルはアムルを捕まえます。 木が十分に高いか、同じ高さであれば、アムルは安全なままです。 

したがって、すべての木について、その高さが指定された値より厳密に小さいかどうかを個別に判断する必要があります。$x$、アムルの身長を表します。 出力は、ツリーごとに 1 つのバイナリ決定のシーケンスです。 

制約により、最大で次のことが許可されます。$10^3$テストケースと合計$10^5$全体的に木々。 これは、ソリューションが各高さを一定時間で処理する必要があることをすでに示しています。 テスト ケースごとに要素を複数回再検討するアプローチは、全体として線形を維持する場合にのみ合格します。 すべての木を他のすべての木と比較するなど、二次関数はすべて限界をはるかに超えています。$10^{10}$最悪の場合の運用。 

主なエッジ ケースは、等価性と極値に関する境界比較から得られます。 

すべての木の高さが次の場合、$x$、どれも捕獲されたものとしてカウントされるべきではありません。 例えば、$x = 5$、高さ$[5, 5, 5]$、出力は次のようにする必要があります$[0, 0, 0]$。 を使用した不注意な実装$\leq$厳密な比較ではなく、すべてをキャッチとして誤ってマークしてしまいます。 

すべての木がこれより短い場合$x$、 例えば$x = 10$、高さ$[1, 2, 9]$、その後、すべての位置が返されるはずです$1$。 条件を反転すると、結果が完全に逆転してしまいます。 

ツリーに次の値より大きい値が含まれている場合$x$、これらは等しくなくても安全な位置である必要があり、等価性をチェックするだけの実装や誤ったブール ロジックを使用する実装がトリップする可能性があります。 

## アプローチ

 強引なアイデアは、各ツリーを独立して扱うことです。 すべての木について、その高さをアムルの高さと比較し、「厳密に小さい」条件を満たすかどうかを判断します。 1 つのツリーの決定は他のツリーに依存しないため、これですでに正しい解決策が得られます。 

素朴な誤解は、ツリーごとに追加の構造を再計算またはスキャンすることになるかもしれませんが、この問題では位置間の相互作用を必要とするものは何もありません。 各ツリーについて他のすべてのツリーと比較する二重ループさえも不必要で無駄です。 それは次のことにつながります$O(n^2)$テスト ケースごとの動作。最悪の場合、約$10^{10}$比較することは完全に不可能です。 

重要な観察は、この状態は純粋に局所的なものであるということです。 各出力は 1 つの比較のみに依存します$h_i < x$。 これにより、前処理やデータ構造が不要になります。 配列を 1 回のパスで処理し、すぐに応答を出力できます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは独立しているため、テスト ケース間で情報を伝達する必要はありません。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして$x$、存在する木の数とアムルの高さを定義します。 
3. 樹高のリストを読みます。 各値は 1 回だけチェックされます。 
4. 身長ごとに$h_i$と直接比較してください。$x$。 もし$h_i < x$、出力 1、それ以外の場合は出力 0。これが機能するのは、問題の条件が Amr が捕捉される唯一の方法として厳密な不等式を定義しているためです。 
5. 必要な形式に一致するように、テスト ケースのすべての結果を 1 行で出力します。 

### なぜ効果があるのか

 それぞれの決定は独立しており、単一の数値が固定しきい値を下回っているかどうかのみに基づいています。$x$。 ツリー間には隠された相互作用がないため、出力は単純な述語を適用した結果とまったく同じになります。$h_i < x$あらゆる要素に。 述語は要素ごとに 1 回評価されるため、位置間の誤った結合は発生せず、結果は問題の定義と一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, x = map(int, input().split())
        h = list(map(int, input().split()))

        res = []
        for hi in h:
            if hi < x:
                res.append("1")
            else:
                res.append("0")

        out_lines.append(" ".join(res))

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを正確に反映しています。 各テスト ケースは個別に処理され、木の高さごとに 1 つの比較が実行されます。 繰り返しの印刷オーバーヘッドを避けるために結果は文字列として蓄積され、厳しい制約の下で Python でのソリューションの効率が維持されます。 

ここでよくある落とし穴は、誤って使用してしまうことです。`<=`の代わりに`<`これにより、同じ高さの木がキャッチされたものとして誤ってマークされてしまいます。 もう 1 つの微妙な問題は、結果を結合するのではなく要素ごとに出力することです。これにより、Python の速度が大幅に低下する可能性があります。$n$大きいです。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        h = list(map(int, input().split()))
        res = ["1" if hi < x else "0" for hi in h]
        out.append(" ".join(res))
    print("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

# provided sample (formatted consistently)

1 4 2 7 3
""") == "1 0 1 0 1"

# all equal case

5 5 5
""") == "0 0 0"

# all smaller

1 2 3 4
""") == "1 1 1 1"

# all larger
assert run("""1

""") == "0 0 0 0"

# boundary mix

3 2 3 1 4
""") == "0 1 0 1 0"

 ## 特殊なケース

 すべての木の高さが正確に等しい場合、$x$の場合、アルゴリズムは各比較を false として評価し、一連のゼロを生成します。 のような入力の場合$x = 5$、高さ$[5, 5, 5]$、各チェック$h_i < x$失敗したため、どのポジションもキャッチとしてマークされません。 

すべての木が厳密に下にある場合$x$、すべての比較は成功します。 のために$x = 10$、高さ$[1, 2, 9]$、各比較は true を返し、出力はすべて 1 になります。 

値を超える場合$x$、比較により、特別な処理を行わずに自然にそれらが除外されます。 のために$x = 3$、高さ$[4, 5]$、どちらも大きいため安全であり、一貫してゼロが生成されます。
