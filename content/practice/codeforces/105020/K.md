 ## 解決策
 ## 問題の理解

 2 つの長い数値が文字列として与えられ、それらが同一になるまで 1 桁ずつ変更することができます。 問題は、数字が抽象値としてではなく、小さな「ダッシュ」で構成される 7 セグメントの表示として扱われることです。 各桁は、照明セグメントの固定パターンに対応します。 

個々のセグメントに対して 2 種類の操作を実行できます。 1 つの操作は数字からセグメントを削除し、もう 1 つの操作は数字にセグメントを追加します。 各操作タイプには、両方の数値にわたるグローバル バジェットがあります。セグメントの削除は最大 x 回、セグメントの追加は最大 y 回可能です。 

課題は、これらの限られたセグメント編集を使用して、2 つの数値を同じ長さの同じ数字列に変換できるかどうかを判断することです。 

入力サイズは全体として小さく、テスト ケース全体の長さの合計は最大 100 です。これにより、テスト ケースごとのリニア スキャンよりも重いものは即座に排除されます。 複雑さの点では、数値を個別に比較するソリューションであればどれでも十分です。 

単純な落とし穴は、桁の違いを対称として扱うことから発生します。 たとえば、ある数字を別の数字に変えるのは 1 回の操作ではありません。 1 つの数字に余分なセグメントがある不一致は削除に相当し、欠落したセグメントは追加に相当します。 これらの方向を誤って混合すると、誤ったカウントが発生します。 

もう 1 つの微妙なケースは、数字間の演算を任意に「交換」できると仮定することです。 実際には、セグメントの変更はすべてそのポジションにローカルなものであり、独立してグローバル予算に影響します。 

## アプローチ

 強引な解釈では、各桁を他の桁に変換するすべての可能な変換を検討し、予算を尊重しながら操作をグローバルに割り当てようとします。 文字列の長さは短くても、各位置は独立しており、セグメントの違いのみが問題となるため、すぐに不必要な複雑さになってしまいます。 

重要な観察は、中間桁の状態を考慮する必要がまったくないということです。 各ポジションは固定コストに影響します。削除する必要があるセグメントもあれば、追加する必要があるセグメントもあります。 0 ～ 9 の数字の 7 セグメントのエンコーディングがわかれば、2 つの数字を比較することは、不一致のセグメントをカウントすることになります。 

これにより、問題全体が、すべての位置のコストを合計し、必要な削除と追加の合計が x と y の範囲内に収まるかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 私たちは 7 つのセグメントを使用した数字の固定表現に依存しています。 各数字は 7 桁にわたるビットマスクとしてエンコードされます。 

1. 0 ～ 9 の数字のセグメント マスクを事前計算します。これにより、各数字でどのセグメントがオンになるかが定義されます。 

これが必要な理由は、すべての操作が桁レベルではなくセグメント レベルで定義されるためです。 
2. 各テスト ケースについて、2 つの文字列 s と t を読み取ります。 

両方とも長さが n であるため、位置によって位置合わせされていると仮定します。 
3. カウンタをremove_used = 0およびadd_used = 0に初期化します。 
4. 0 から n-1 までの各インデックス i について、数字 s[i] と t[i] を比較します。 

両方の数字をセグメント マスクに変換します。 
5. 2 つのマスクの差を計算します。 

s ではオンであるが t ではオフであるすべてのセグメントが削除に寄与します。 

s ではオフであるが t ではオンであるすべてのセグメントが加算に寄与します。 
6. これらの寄与をremove_usedとadd_usedに蓄積します。 
7. すべての位置を処理した後、remove_used ≤ x および add_used ≤ y であるかどうかを確認します。 

両方の条件が成立する場合はYESを出力し、そうでない場合はNOを出力します。 

### なぜ効果があるのか

各セグメントは他のセグメントから独立しており、各操作は 1 桁の 1 つのセグメントにのみ影響します。 これは、ある数字を別の数字に変換するコストが、それらのセグメント セットの対称的な差によって完全に決定されることを意味します。 ポジション全体でこれらのコストを合計すると独立性が保たれるため、実現可能性は必要な業務の合計が 2 つのグローバル予算内に収まるかどうかを確認することになります。 

すべての不一致は 1 回だけ修正する必要があるため、複数の位置を再配置しないと、必要な追加または削除の数を減らすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# 7-segment representation for digits 0-9
seg = [
    0b1111110,  # 0
    0b0110000,  # 1
    0b1101101,  # 2
    0b1111001,  # 3
    0b0110011,  # 4
    0b1011011,  # 5
    0b1011111,  # 6
    0b1110000,  # 7
    0b1111111,  # 8
    0b1111011   # 9
]

def solve():
    T = int(input())
    for _ in range(T):
        n, x, y = map(int, input().split())
        s = input().strip()
        t = input().strip()

        rem = 0
        add = 0

        for i in range(n):
            a = seg[int(s[i])]
            b = seg[int(t[i])]

            diff_remove = a & (~b)
            diff_add = (~a) & b

            # count bits
            rem += bin(diff_remove).count("1")
            add += bin(diff_add).count("1")

        if rem <= x and add <= y:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、各桁を固定ビット パターンにエンコードし、位置ごとに比較します。 重要な実装の詳細は、ビット操作を使用して相違点を削除と追加に分離することです。 セットされたビットをカウントすると、必要な演算の正確な数がわかります。 

よくある間違いは、両方向を単一の絶対差分カウントにマージすることです。 これでは、操作がグローバルに型制約を受けているという事実が無視されます。 

## 実用的な例

 ### 例 1

 入力:```
n = 3, x = 2, y = 2
s = 101
t = 111
```各桁を比較します。 

| 私 | s[i] | t[i] | レム | 追加 | 合計レム | 合計の合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | 0 | 0 | 0 |

 | 2 | 1 | 1 | 0 | 0 | 0 | 2 |

 最終状態は add = 2、rem = 0 を示しています。y = 2、x = 2 であるため、変換は有効です。 

これにより、ある桁が別の桁と比較して「欠落している」部分がある場合、セグメントの追加のみが必要であることが確認されます。 

### 例 2

 入力:```
n = 2, x = 1, y = 1
s = 88
t = 00
```8 から 0 への変換ごとに、1 桁あたり 2 つのセグメントが削除されます。 

| 私 | s[i] | t[i] | レム | 追加 | 合計レム | 合計の合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 8 | 0 | 3 | 0 | 3 | 0 |
 | 1 | 8 | 0 | 3 | 0 | 6 | 0 |

 6 つの除去が必要ですが、x = 1 しかないため、答えは NO です。 

これは、各ポジションが独立して貢献し、コストが直線的に累積することを示しています。

 ## 特殊なケース

 主なエッジケースは、2 つの数字が同一である場合です。 この状況では、除去カウントと加算カウントの両方がゼロのままでなければならず、対称差分が空であるため、アルゴリズムは当然ゼロを生成します。 たとえば、7 を 7 に変換しても異なるビットは生成されないため、両方のカウンターは変更されません。 

もう 1 つのエッジ ケースは、8 から 0 などの最大発散です。8 桁ではすべてのセグメントがアクティブになりますが、0 では中央のセグメントを除くほとんどのセグメントがアクティブになります。 このアルゴリズムは、欠落しているセグメントを削除のみとして正しく分類し、追加はカウントされません。 

最後のエッジケースは、予算が限られているにもかかわらず予算が不均等に配分されている場合です。 x が大きいが y がゼロの場合、不一致の合計が小さい場合でも、必要な加算が解をブロックすることになります。 両方のカウンターを個別に追跡するため、合計の差が小さいように見える場合でも、チェックはそのようなケースを正しく拒否します。
