 ## 問題の理解

 各ノードが黒または白で塗られた根付きツリーが与えられます。 ツリー構造はノード 1 をルートとした親子関係を定義します。 各クエリノードについて$u$のサブツリー内のみを調べます。$u$、つまり、下方向に移動することで到達可能なすべてのノードを意味します。$u$。 

固定ノードの場合$u$、すべてのノードを考慮します$v$そのサブツリー内で、からの一意のパスを調べます。$u$に$v$。 両方のエンドポイントを含むこのパスに沿って、黒のノードの数と白のノードの数を数えます。 ノード$v$これら 2 つのカウントが等しい場合、有効とみなされます。 タスクは、クエリ ノードごとに計算することです。$u$、有効なノードの数$v$そのサブツリーに存在します。 

制約は次のとおりです$10^5$ノードと$10^5$これにより、クエリごとにパス情報を再計算するアプローチは即座に除外されます。 パスを明示的に検査するソリューションは、単一のサブツリーに次の要素が含まれる可能性があるため、最悪の場合、二次的な動作に低下します。$O(n)$ノードがあり、$O(n)$クエリ。 

素朴なアプローチでは、パス上の黒と白のカウントを再計算します。$u$すべての子孫に$v$。 前処理を行ったとしても、クエリごとに新たな走査を行うと、$O(n^2)$鎖状のツリー内での動作は、限界をはるかに超えています。 

サブツリーが大きいがパスが浅い場合、微妙なエッジ ケースが発生します。 それでも、パスの合計を繰り返し再計算することは、繰り返しの作業につながります。 もう 1 つの特殊なケースは、すべてのノードが同じ色を持つ場合です。 そうすれば、単一のノードが等式を自明に満たす場合を除いて、ほぼすべての答えがゼロになるはずです。これは、後でプレフィックスベースの推論の正しさを検証するのに役立ちます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリノードについて$u$、そのサブツリー全体を走査し、各ノードについて$v$から上に向かって歩きます。$v$に$u$(またはサブツリーに制限された DFS を使用して)、そのパスに沿って黒と白のノードを数えます。 これは問題の定義に直接従うため、正しいです。 問題はコストです。各クエリには、最大で次の場所にアクセスする必要がある場合があります。$O(n)$ノード、および各パスの計算は別のものです$O(n)$最悪の場合、$O(n^2)$あるいはさらに悪い総作業量。 

重要な観察は、2 つのノード間のパスのバランスが、ルートからノードへの累積を使用して表現できることです。 黒を次のように割り当てると$+1$そして白いように$-1$の場合、パス上の黒と白が等しいということは、これらの値の合計がゼロであることを意味します。 ルートベースのプレフィックス合計を使用すると、パス クエリをプレフィックス値の違いに還元できます。 すべてのクエリノードがあるため、$v$～のサブツリーにあります$u$を使用すると、条件を事前計算された値の単純な等価性チェックに変換できます。 

これにより、問題はノードごとのサブツリー範囲にわたる頻度カウントの問題に変わります。$u$で決定される特定のプレフィックス値を持つサブツリー内のノードの数を数えたいとします。$u$。

 ## アルゴリズムのチュートリアル

 黒ノードが寄与する値変換を定義します。$+1$と白いノードが貢献します$-1$。 ノード 1 でツリーをルート化し、ルートからノードへのパスに沿ってプレフィックスの合計を計算します。 

1. ルートから DFS を実行して、2 つの配列: プレフィックスの合計を計算します。`pref[u]`ルートからノードまでの累積黒マイナス白値を表す$u$、およびオイラー巡回区間$[tin[u], tout[u]]$各ノードのサブツリーをフラットな順序で記述します。 この順序付けにより、すべてのサブツリーが連続したセグメントに対応することが保証されます。 
2. 各ノードについて$u$、サブツリー内の有効なノードを特徴付けるターゲット値を識別します。 パスサム変換を使用すると、ノード$v$次の場合にのみ条件を満たします`pref[v] == pref[parent[u]]`。 根元の治療を行っております`pref[parent[1]]`ゼロとして。 
3. 各プレフィックス合計値から、その値が出現する位置のリスト (オイラー ツアー インデックス) へのマッピングを構築します。 
4. 各クエリノードについて$u$に対応するリストを検索します。`pref[parent[u]]`間隔内にインデックスがいくつあるかを数えます$[tin[u], tout[u]]$二分探索を使用します。 
5. このカウントを出力します。 

重要な推論ステップは、パス制約からプレフィックス合計に関する単一の等価条件への変換です。 それが達成されると、サブツリー制限は標準的な範囲カウントの問題になります。 

### なぜ効果があるのか

 任意のノードに対して$v$のサブツリー内$u$、からのパスの合計$u$に$v$ルートプレフィックスの合計の差を調べます。 等価条件は、$v$。 オイラー ツアーでは、サブツリーのメンバーシップが連続するインデックス間隔のメンバーシップと同等であることが保証されるため、有効なノードをカウントすることは、範囲内の固定値の出現をカウントすることになります。 この構造により、すべての有効なノードが 1 回だけカウントされ、無効なノードが誤って等式を満たすことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(200000)

n, q = map(int, input().split())
color = list(map(int, input().split()))

adj = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)

tin = [0] * (n + 1)
tout = [0] * (n + 1)
pref = [0] * (n + 1)
timer = 0

def val(x):
    return 1 if x == 1 else -1

def dfs(u, p):
    global timer
    timer += 1
    tin[u] = timer
    pref[u] = pref[p] + val(color[u - 1])
    for v in adj[u]:
        if v == p:
            continue
        dfs(v, u)
    tout[u] = timer

dfs(1, 0)

pos = {}
for i in range(1, n + 1):
    pos.setdefault(pref[i], []).append(tin[i])

def count_in_range(arr, l, r):
    import bisect
    return bisect.bisect_right(arr, r) - bisect.bisect_left(arr, l)

out = []
for _ in range(q):
    u = int(input())
    target = pref[0] if u == 1 else pref[0]  # parent of root is 0, pref[0]=0
    if u != 1:
        # recompute parent-based value via pref[parent[u]]
        # parent not stored explicitly, so we infer using formula:
        # pref[parent[u]] = pref[u] - val(color[u])
        target = pref[u] - val(color[u - 1])

    arr = pos.get(target, [])
    out.append(str(count_in_range(arr, tin[u], tout[u])))

print("\n".join(out))
```DFS は、1 回の走査でサブツリー間隔とプレフィックス合計の両方を構築します。 辞書`pos`オイラー ツアーのエントリ時間を使用して、プレフィックス値によってノードをグループ化します。 各クエリは、事前に計算された並べ替えられたリストに対する二分検索に帰着します。 

実装の微妙な詳細はコンピューティングです`pref[parent[u]]`親を明示的に保存せずに。 これは、接頭辞の関係を逆にすることで処理されます。`pref[u] = pref[parent[u]] + val(u)`、減算によって親プレフィックスを回復します。 

## 実用的な例

 小さな木を考えてみましょう。 

入力:```
5 2
0 1 0 1 0

```プレフィックス値とサブツリー間隔を計算します。 

| ノード | 色 | 都道府県 | ティンタウト |
 | --- | --- | --- | --- |
 | 1 | W | 0 | [1,5] |
 | 2 | B | 1 | [2,4] |
 | 3 | W | -1 | [5,5] |
 | 4 | B | 2 | [3,3] |
 | 5 | W | 0 | [4,4] |

 クエリ 1 の場合、ターゲットは 0 です。サブツリー [1,5] 内では、pref 0 を持つノードはノード 1 と 5 であるため、答えは 2 です。 

クエリ 2 の場合、ターゲットは pref[parent[2]] で、pref[1] = 0 です。サブツリー [2,4] 内では、ノード 5 のみがサブツリー間隔 [2,4] にあり、pref 0 false? 実際にはノード 5 はサブツリー間隔の外側にあるため、答えは 0 になります。 

このトレースは、サブツリー制限とプレフィックス等価性がどのように組み合わされるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + q)\log n)$| DFS は線形であり、各クエリはリストに対して二分検索を実行します。 
| スペース |$O(n)$| 隣接リスト、オイラーツアー配列、プレフィックスグループ化 |

 両方の理由から、複雑さは制限内に問題なく収まります。$n$そして$q$は$10^5$、対数係数は小さいままです。

 ## 特殊なケース

 重大なエッジ ケースは、クエリされたノードがルートである場合です。 この場合、親の寄与がないため、ターゲット プレフィックスはゼロになります。 アルゴリズムは親プレフィックスをゼロとして扱うことでこれを自然に処理するため、ルートからのブラックとホワイトのバランスが等しいすべてのノードが正しくカウントされます。 

もう 1 つのケースは、ノードにサイズ 1 のサブツリーがある場合です。 答えは、その単一ノードがそれ自体との等価条件を満たすかどうかに完全に依存します。これは、その色がその親プレフィックスと正しく相殺される場合にのみ発生します。 範囲クエリでは、同じプレフィックス等価ルールに基づいて、特殊な大文字と小文字を区別せずに、範囲クエリを正しく含めたり除外したりできます。
