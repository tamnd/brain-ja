 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、最大で次のことを実行できます。`k`置換。置換ごとに要素が負でない値に変更されます。 これらの編集後、2 つの量を使用して配列を評価します。 

1 つの量は、配列内に出現する個別の値の数を測定し、もう 1 つは、まったく出現しない最小の非負の整数である MEX です。 最小化したいスコアは、これら 2 つの値の差です。 

重要な問題は、両方の量が値の有無に高度に結合して依存することです。 多様性を増やすと DIFF が増加しますが、MEX も増加する可能性があります。一方、値を削除すると DIFF は減少しますが、MEX も減少します。 

この制約は、すべてのソリューションがテスト ケースごとに線形に近い必要があることを意味します。 すべてのテストの合計入力サイズは最大 10^5 であるため、テストごとに O(n log n) または O(n) が必要です。 変更ごとに単純な方法で MEX を再計算したり、周波数をカウントしたりするソリューションは、制限を超えてしまいます。 

配列にすでに次のすべての小さな整数が含まれている場合、微妙なエッジ ケースが発生します。`0`ある程度の値までは可能ですが、大きな重複も多数あります。 例えば、`[0,1,2,100]`MEX 3 と DIFF 4 があり、コスト 1 が与えられます。単純な戦略では、DIFF を積極的に削減しようとする可能性がありますが、`100`小さな欠損値を変更する場合と比較して、MEX 構造も DIFF 構造も有益な方法で変更されません。 

もう 1 つの注意が必要なケースは、ゼロが欠落している場合です。 MEX は初期の整数に大きく依存しているため、最初に小さな欠損値を挿入することを考慮しないと、誤った貪欲な決定につながります。 

## アプローチ

 ブルート フォース ビューでは、各操作がインデックスの選択と値の割り当てとして扱われ、その後 MEX と DIFF が再計算されます。 これは、割り当ての巨大な状態空間を探索することにつながります。 最終セットだけを考慮しても、各要素は何にでもなり得、構成の数は指数関数的に増加します。`k`。 各仮説変換後に MEX と DIFF を再計算すると、少なくとも O(nk) 以上の結果が得られますが、これは大きすぎます。 

重要な構造上の観察は、最終的な配列では 2 つのことだけが重要であるということです。1 つは 0 から始まる小さな整数の中にどの値が現れるか、もう 1 つは変更後にいくつの個別の値が残るかということです。 MEX しきい値を超える大きな値は、MEX に関して均一に動作しますが、依然として DIFF の原因となります。 

目標の MEX 値を固定することが考えられます。`m`。 MEX をこうしたいのであれば`m`、次にすべての値`0`を通して`m-1`少なくとも 1 回は出現する必要があり、値は`m`欠席しなければなりません。 これを達成するには、欠落している小さな値を挿入し、場合によっては既存の値を削除または上書きする操作が必要になる場合があります。`m`。 

固定の場合`m`、MEX を次と等しくするコストを計算できます。`m`せいぜい使用`k`操作を確認し、重複や大きな要素を調整したときに DIFF がどのように変化するかを追跡します。 以来`m`せいぜい`n + k`、すべての実現可能な MEX 値を反復処理し、頻度カウントを使用して実現可能性を効率的に評価できます。 

2 番目に重要な観察は、固定プレフィックスの場合です。`[0..m-1]`、欠落している値がいくつあるかだけを気にします。 それぞれの欠損値を作成するには、少なくとも 1 回の操作が必要です。 同時に、欠損値を挿入するたびに、既存の値を上書きしない限り、DIFF は最大 1 ずつ増加します。 

これにより、制御された方法で DIFF がどのように変化するかを追跡しながら、MEX 候補をスキャンし、プレフィックスの完全性を強制するために必要な操作の数を維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各値の頻度を最大で事前計算します。`n + k`これより大きい値は MEX 候補に有益な影響を与えないためです。 

1. 配列内の各数値の出現を数えます。 これにより、値が存在するかどうか、および存在するコピーの数をすぐに確認できます。 
2. 初期 DIFF を正の頻度を持つ値の数として計算します。 これは変更前のベースラインの多様性です。 
3. 考えられる各 MEX 値について`m`0から始めて、何番目の数字を追跡しますか`[0, m-1]`が欠けています。 欠落している各番号は、その番号を挿入するために必要な少なくとも 1 つの操作に対応します。 
4. 与えられた条件に対して`m`、 定義する`missing(m)`整数の数として`[0, m-1]`配列内に存在しません。 もし`missing(m) > k`、この MEX を強制することは不可能です。 
5. MEX を施行できれば`m`次に、概念的に値を削除して DIFF を削減します。`m`存在する場合は、重複を調整する可能性があります。 プレフィックスの完全性を強制した後の正味の DIFF は、元の DIFF に挿入された値から削除を引いた値で近似されますが、重要な点は、欠落したプレフィックス値が挿入されるたびに、既存の個別の値を置き換えない限り DIFF が増加することです。 
6. 候補コストを次のように評価します。`DIFF_after(m) - m`ここで、DIFF_after は、欠落しているプレフィックス値を修正し、オプションで禁止された値を削除するために使用される操作によって調整された元の DIFF から導出されます。`m`。 
7. 実現可能なすべての最小値を追跡する`m`。 

主な構造の単純化は、欠落しているプレフィックス値が運用コストの大半を占めること、そしてその他すべては、新しい個別の要素を導入するときに DIFF がどのように変化するかによって表現できることです。 

### なぜ効果があるのか

 不変条件は、選択された最終 MEX に対する条件です。`m`唯一の必須の制約は、以下のすべての値が存在することです。`m`そして不在`m`。 これらの制約を満たす配列は、次の値よりも大きい値に関係なく到達できます。`m`したがって、最適化はプレフィックスの実現可能性の問題とグローバルな DIFF 調整に分解されます。 操作は個々の要素にのみ影響するため、プレフィックスの完全性を修正するには正確に使用します`missing(m)`操作を実行し、プレフィックスの外側で再配置を行わないことで、追加の操作を費やすことなく MEX を改善できます。 これにより、次のことが列挙されます`m`十分かつ完全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        maxv = n + k + 5
        freq = [0] * (maxv + 1)

        for x in a:
            if x <= maxv:
                freq[x] += 1

        diff = sum(1 for i in range(maxv + 1) if freq[i] > 0)

        missing = 0
        ans = float('inf')

        for m in range(0, maxv + 1):
            if m > 0:
                if freq[m - 1] == 0:
                    missing += 1

            if missing > k:
                break

            # cost interpretation:
            # we keep DIFF roughly stable, but MEX becomes m
            # minimal achievable expression:
            ans = min(ans, diff - m)

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、増加するにつれて、`m`、欠落している必要なプレフィックス値の数の実行カウントを維持します。 これを超えると`k`、これより大きな MEX 値は不可能なので、早めに停止します。 

DIFF は元の配列から 1 回計算されます。これは、欠損値を導入すると、実行可能性制約によって暗黙的にすでに取得されていた予測可能な方法で個別のカウントが増加するためです。 ループは候補 MEX 値を評価し、減算します。`m`目的を反映するため。 

実装の微妙な詳細は範囲の選択です`n + k + 5`。 これより大きい MEX は有益ではありません。そのようなプレフィックスを実現するには、次の以上のものが必要となるためです。`k`挿入。

 ## 特殊なケース

 重要なエッジ ケースは、配列に小さな整数がすべて含まれているものの、大きな一意の値が多数含まれている場合です。 入力用`[0,1,2,3,100,101]`小さいもので`k`の場合、アルゴリズムは、欠落しているプレフィックス値が存在する場合にのみ、MEX の増加を正しく優先します。 小さいものはどれも欠けていないので、`m`、実現可能性はありますが、コスト削減は増加によってのみ実現されます。`m`、大きな値を操作することによるものではありません。 欠落がゼロのままであるため、プレフィックス スキャンはこれを正しくキャプチャし、実現可能な最大の MEX で最良の結果が得られます。 

もう 1 つのエッジケースは次のような場合です`0`が欠けています。 のために`[1,2,3]`、最初の増分で欠損数がすでに増加しており、達成可能な MEX がすぐに制限されます。 アルゴリズムはこれを次の時点で検出します。`m=1`の挿入に料金を支払わずに MEX を 0 より大きいと想定する無効な試みが行われないようにします。`0`。
