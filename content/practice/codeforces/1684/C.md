 ## 解決策
 ## 問題の理解

 各行が列全体に配置された一連の数値を表す行列が与えられます。 目標は、すべての行を個別に左から右に非減少にすることですが、許可されるグローバル操作は 1 つだけです。つまり、2 つの列全体を交換します。 

列の交換とは、2 つのインデックスを選択し、行列の垂直スライス全体を交換することを意味します。 この交換の後、すべての行が降順ではない順序で並べ替えられるかどうかを確認します。 

重要な制約は、行内の要素を個別に並べ替えないことです。 単一の列のスワップはすべての行に同時に影響するため、ある行を助ける選択が別の行を壊す可能性があります。 ここでのタスクは、スワップによりすべての行がソートされる列のペアが存在するかどうかを判断するか、またはそれが不可能であると結論付けることです。 

制約は厳しく、すべてのテスト ケースにわたるセルの合計数は最大 2×10^5 です。 これにより、すべての O(m^2) 列のスワップを試行し、それぞれを O(nm) で検証するソリューションは即座に除外されます。これは、最悪の場合、3 次の動作が爆発的に発生するためです。 単一のスワップを単純にチェックするだけでも O(nm) のコストがかかるため、すべてのペアに対して強引に実行することは不可能です。 

グリッドがすでに良好な場合、微妙なエッジケースが現れます。 スワップを出力する必要があるため、列をそれ自体とスワップすることは許可されており、有効な操作としてカウントされます。 もう 1 つのエッジ ケースは、複数の反転が異なる行に存在し、各行は異なるスワップで個別に修正できるとしても、単一のスワップでは同時に修正できない場合です。 たとえば、行 1 は列 (1,2) のスワップを必要とするが、行 2 はスワップ (2,3) を必要とする場合、両方を満たすグローバル スワップはありません。 

## アプローチ

 直接的なアイデアは、すべての列のペア (i、j) を試し、それらを交換し、すべての行がソートされるかどうかを確認することです。 これは実装が簡単です。交換を実行し、線形時間で各行を検証し、それを元に戻します。 ただし、O(m^2) 個のペアがあり、各検証コストは O(nm) であり、最悪の場合は O(nm^3) になり、制約の下では完全に不可能です。 

重要な観察は、有効なスワップが存在する場合、それは行内の反転の構造によって決定される必要があるということです。 各行は、順序を崩さずに列のどのペアを交換できるかについて制約を課します。 行は、2 つの列を交換することで反転が修正される位置を除いて、すでにソートされています。 つまり、各行は、非常に制御された方法で、並べ替え順序とは異なる候補の順列を個別に提案します。 

解決策が存在する場合、スワップを適用した後、すべての行が並べ替えられます。 これは、すべての行について、そのソートされたバージョンと比較した場合、スワップによって引き起こされる変換が、その行のソートに必要な順列と一致する必要があることを意味します。 これにより、強力な一貫性条件が強制されます。すべての行は、最大 2 つの位置を除いて同じ「修正された」列の順序に一致する必要があります。 

これにより、各行をその並べ替えられたバージョンと比較し、不一致が発生した場所を検出するだけで済むため、簡略化が可能になります。 いずれかの行で 3 つ以上の位置が異なる場合は、1 回のスワップでは修正できません。 すべての行が同じ不一致位置を共有している場合 (またはまったく一致していない場合)、これら 2 つの列を交換することですべてが解決されます。 

問題は、交換されたときにすべての行がソートされる最大 2 つの列を見つけて、すべての行にわたる一貫性を検証することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m3) | お(1) | 遅すぎる |
 | 最適 | O(n・m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の行を取得し、その列順序をソートしたバージョンを作成します。 元の行と比較して、不一致の位置を特定します。

不一致の数が 2 を超える場合、単一のスワップではこの行さえも修正できないため、答えは直ちに不可能になります。 
2. 最初の行に不一致がない場合、グリッドは列の順序に関して局所的にすでに一貫しています。 暫定的に列とそれ自体の交換が有効であると仮定し、ID 列の処理を進めます。 
3. 不一致が 2 つだけある場合は、これら 2 つの列インデックスを交換の候補として記録します。 これは、最初の行に対して可能な唯一の修正を定義します。 
4. この候補スワップを概念的にすべての行に適用し、各行が減少していないことを確認します。 実際に交換する代わりに、2 つの列の値を比較し、結果の順序が並べ替えられた順序と一致するかどうかを確認します。 
5. 各行について、候補列を交換する効果をシミュレートし、左から右にスキャンして、すべての隣接するペアが減少していないことを確認します。 
6. スワップ適用後に条件に違反する行がある場合、候補ペアを拒否します。 
7. すべての行が合格した場合、選択した列を出力します。 

### なぜ効果があるのか

 各行には、最終的な列の順序がソートされる順列でなければならないという制約が課されます。 1 つのスワップは、その行のソート順に対して最大 2 つの位置を固定する順列に対応します。 3 つ以上の位置が異なる場合、単一の転置ではソートされたシーケンスに変換できません。 

有効なグローバル スワップが存在する場合、他のスワップは最初の行の順序にすでに違反しているため、それは最初の行をそのソートされたバージョンと正確に位置合わせする転置である必要があります。 1 つの行を固定したら、他のすべての行も同じ転置と一致する必要があります。そうしないと、少なくとも 1 つの行がソートされないままになります。 これにより、候補スワップの一意性が強制され、検証の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        # Step 1: find candidate swap from first row
        first = a[0]
        sorted_first = sorted(first)

        diff = []
        for i in range(m):
            if first[i] != sorted_first[i]:
                diff.append(i)

        if len(diff) == 0:
            l = r = 0
        elif len(diff) == 2:
            l, r = diff[0], diff[1]
        else:
            print(-1)
            continue

        # Step 2: verify all rows
        ok = True
        for i in range(n):
            row = a[i]
            prev = -10**18

            for j in range(m):
                val = row[j]
                if j == l:
                    val = row[r]
                elif j == r:
                    val = row[l]

                if val < prev:
                    ok = False
                    break
                prev = val

            if not ok:
                break

        if not ok:
            print(-1)
        else:
            print(l + 1, r + 1)

if __name__ == "__main__":
    solve()
```この実装では、まず最初の行をテンプレートとして使用して、唯一の可能なスワップを決定します。 この行を並べ替えると、ターゲットの順序が明らかになり、不一致によって、どの 2 つの列が適切でないのかが正確に特定されます。 3 つ以上の不一致がある場合、アルゴリズムは早期に正しく拒否します。 

検証ステップでは、行列内の列を物理的に交換しません。 代わりに、各行の線形スキャン中にスワップをシミュレートします。 これにより、余分なメモリの使用が回避され、ソリューションが合計入力サイズにおいて線形に保たれることが保証されます。 変数`prev`仮説的なスワップを適用した後、行が減少しないままであるかどうかを追跡します。 

微妙な詳細は、スワップが必要ない場合の処理​​です。 その場合、`(0,0)`これは列をそれ自体と交換することに相当し、グリッドは変更されないままになり、問題の要件を満たします。 

## 実用的な例

 ### 例 1

 入力:```
1
2 3
1 2 3
1 1 1
```最初の行はすでにソートされているため、diff は空です。 候補スワップは (0,0) です。 

| 行 | 適用されたスワップ | 結果シーケンス | 有効 |
 | --- | --- | --- | --- |
 | [1,2,3] | なし | 1、2、3 | はい |
 | [1,1,1] | なし | 1,1,1 | はい |

 両方の行は減少しないままであるため、出力は次のようになります。`1 1`。 

これにより、ID スワップのケースが正しく処理されたことが確認されます。 

### 例 2

 入力:```
1
2 3
2 3 1
1 2 3
```ソートされた最初の行は [1,2,3] で、差分位置はインデックス (0,2) であるため、列 1 と列 3 を交換します。 

| 行 | 交換された行 | チェック |
 | --- | --- | --- |
 | [2,3,1] | [1,3,2] | ソートされていません |
 | [1,2,3] | [3,2,1] | ソートされていません |

 最初の行はすでにスワップを無効にしているため、答えは -1 です。 

これは、最初の行のみを使用するだけで実現可能性を判断できる理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・m log m) | 最初の行のソートが優先され、検証は合計サイズにおいて線形です。 
| スペース | O(m) | 1 行のみを格納し、インデックスが一致しません。 

合計入力サイズは 2×10^5 で制限されるため、テスト ケースごとに線形スキャンで十分です。 1 行のみを並べ替えると、定数係数が小さく保たれるため、全体的な実行が制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        first = a[0]
        sorted_first = sorted(first)

        diff = [i for i in range(m) if first[i] != sorted_first[i]]

        if len(diff) == 0:
            l = r = 0
        elif len(diff) == 2:
            l, r = diff
        else:
            out.append("-1")
            continue

        ok = True
        for i in range(n):
            prev = -10**18
            for j in range(m):
                val = a[i][j]
                if j == l:
                    val = a[i][r]
                elif j == r:
                    val = a[i][l]
                if val < prev:
                    ok = False
                    break
                prev = val
            if not ok:
                break

        out.append("-1" if not ok else f"{l+1} {r+1}")

    return "\n".join(out)
