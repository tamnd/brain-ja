 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、クエリごとに配列の要素を一定の回数だけインクリメントすることができます。 目標は、許容される最大数のインクリメントを実行した後、配列全体のビットごとの OR で 1 に設定されるビットの数を最大化することです。 言い換えれば、各クエリは演算のバジェットを与えるので、それらを戦略的に使用して、OR 内のできるだけ多くの 0 ビットを 1 ビットに変換する必要があります。 各クエリの出力は、結果の OR 内の 1 ビットのカウントです。 

この制約は、配列が最大 100,000 要素という非常に大きくなる可能性があり、クエリの数も 100,000 に達する可能性があることを示しています。 さらに、各要素は最大 10 億に達する可能性があり、運用予算も同様に大きくなる可能性があります。 これにより、可能なすべての増分をシミュレートしたり、すべてのサブセットを試行したりする単純なアプローチは除外されます。これは、何十億もの操作が必要になるためです。 代わりに、ビットレベルの構造と、OR でビットを反転するために必要な最小限の操作に焦点を当てたアプローチが必要です。 

すべての要素がすでに十分に大きく、OR にすべての上位ビットが含まれる場合、または許可される操作が次の上位ビットを反転するコストより小さい場合、微妙なエッジ ケースが発生します。 たとえば、配列を考えてみましょう`[1, 1]`そしてクエリ`b=1`。 現在の OR は`1`、1 つのビットが設定されています。 いずれかの要素を 1 ずつ増やすと、次のようになります。`[2, 1]`OR付き`3`、2 つのビットが設定されています。 要素をやみくもに増加させる不注意なアプローチでは、ビット間での演算の最適な分散を逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。クエリごとに、配列要素全体に増分を分散し、新しい OR を計算し、そのビットをカウントするためのあらゆる方法を試みます。 これは、OR 演算が結合的かつ可換であるため機能しますが、入力が大きい場合はすぐに失敗します。 たとえば、100,000 個の要素と 1,000,000 の可能な増分がある場合、すべての分布を列挙することは不可能です。 

重要な洞察は、OR の各ビットを独立して処理できるということです。 ビットを位置に設定するには`k`OR では、そのビットを設定するには配列内に少なくとも 1 つの数値が必要です。 ビットの数値の場合`k`が 0 の場合、それを設定するために必要な最小増分数を計算できます。 各ビットを反転するコストがわかれば、このコストでビットを並べ替え、許可された演算を貪欲に使用して OR に設定されるビット数を最大化できます。 これにより、問題は配列要素を直接操作することから、ビットごとに必要な増分のカウントを操作することに軽減されます。 

貪欲なアプローチは、上位ビットにはより多くの増分が必要になる可能性があるため機能しますが、下位ビットは常に少ない操作で設定できるためです。 2 進数の構造により、十分な演算が残っている場合には、下位ビットを設定しても、後で上位ビットを設定することが妨げられることはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(30 * n + 30 * q) | お(30) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに配列を初期化します。`costs`OR の各ビットを設定するために必要な最小の増分数を格納するための長さ 30。 
2. 配列の各要素を反復処理し、0 ～ 29 の各ビット位置について、そのビットが現在 0 の場合に 1 にするために必要な増分数を計算します。`k`、これは`(1 << k) - (a_i % (1 << (k + 1)))`ビットが 0 の場合。各ビットのすべての要素の最小コストを追跡します。 
3. 配列を処理した後、最小コストでビットを並べ替えます。 
4. 各クエリについて、元の OR にすでに設定されているビットのカウンターから開始します。 次に、ソートされたコストを反復処理し、クエリの予算が許す限り、残りの操作からコストを差し引いてビットを「購入」します。 購入したビットごとにビット カウンタをインクリメントします。 
5. 各クエリの最終的なビット数を出力します。 

機能する理由: このアルゴリズムは、常に最小数の操作を使用して各ビットを個別に設定し、操作が無駄にならないようにするため、正確性が保証されます。 すでに 1 になっているビットは演算を消費しません。 コストを並べ替えることにより、より安価なビットが最初に考慮されるようになり、限られた操作予算の中で設定されるビットの総数が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_or_popcount():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        # Compute original OR and minimal costs to set each bit
        orig_or = 0
        costs = [float('inf')] * 30
        for num in a:
            orig_or |= num
            for k in range(30):
                if (num >> k) & 1 == 0:
                    need = (1 << k) - (num % (1 << (k + 1)))
                    costs[k] = min(costs[k], need)
        
        sorted_costs = sorted([c for i, c in enumerate(costs) if not (orig_or >> i) & 1])
        
        # Handle each query
        for _ in range(q):
            b = int(input())
            bits = bin(orig_or).count('1')
            for cost in sorted_costs:
                if cost <= b:
                    b -= cost
                    bits += 1
                else:
                    break
            print(bits)

if __name__ == "__main__":
    max_or_popcount()
```最初のループは、元の配列の OR を計算し、各ゼロ ビットを設定するための最小コストを構築します。 クエリの内部ループは、操作バジェットを最も安価なビットに貪欲に適用します。 ソートにより、予算内で設定されるビット数が最大化されることが保証されます。 取り扱い`orig_or`すでに設定されているビットを二重にカウントすることを個別に回避します。
