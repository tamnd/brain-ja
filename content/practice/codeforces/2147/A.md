 ## 解決策
 ## 問題の理解

 私たちは原点から始まる二次元グリッド上にいます$(0, 0)$そして目標を達成したい$(x, y)$。 動きは 2 つの方法で制限されます。 まず、軸を交互に切り替えます。最初のステップは、軸に沿って右に進みます。$x$、2番目に沿って$y$、3番目に沿って$x$またまた、など。 第 2 に、各ステップの長さは前のステップよりも厳密に大きくなければなりません。 各ステップは正の整数の距離を移動する必要があります。 

入力により複数のテスト ケースが提供され、それぞれがターゲットを提供します$(x, y)$。 各ケースの出力は、これらのルールに基づいてターゲットに到達するために必要な最小ステップ数、または$-1$それが不可能な場合。 

制約により許可されるのは、$x$そして$y$まで$10^9$そして最大まで$10^4$テストケース。 これにより、考えられるすべてのステップのシーケンスを列挙しようとするソリューションは除外されます。 単純な再帰的アプローチまたはバックトラッキングアプローチでは、指数関数的な数のシーケンスが生成されますが、これでは遅すぎます。 課題は、ステップ長の構造を認識することにあります。各座標には、交互の軸に割り当てられた厳密に増加する整数のシーケンスによって到達する必要があります。 

エッジケースには、次のような状況が含まれます。$x$または$y$ステップシーケンスが必要とするものよりも小さいです。 例えば、$(1,1)$引っ越した後だから無理$1$平行$x$、次の$y$ステップは少なくとも$2$、目標をオーバーシュートします。 同様に、次のようなターゲット$(5,4)$ステップを慎重に分割する必要があります。そうしないと、シーケンスが厳密に増加する長さに対応できなくなります。 

## アプローチ

 ブルートフォース手法では、正の整数が増加するすべてのシーケンスを試みます。$x$そして$y$交互に、合計が目標と一致するかどうかを確認します。 長さのシーケンスの場合$k$、おおよそあります$O(k!)$シーケンス。 小さいものでも$k$、これは成長が早すぎて実行不可能です。$x, y$まで$10^9$。 

重要な洞察は、問題は最小限のステップ数を見つけることにあるということです。$k$整数の適切なサブセットの合計が等しくなるように$x$そして$y$、交互の順序を尊重します。 最初の値の可能な限り最小の合計を使用してそれを形式化できます。$m$整数:$1 + 2 + ... + m = m(m+1)/2$。 

もし$k$は合計ステップ数です。$k_x$歩数になります$x$そして$k_y$平行$y$、 と$k_x = \lceil k/2 \rceil$そして$k_y = \lfloor k/2 \rfloor$。 可能な最小額は、$k_x$沿って歩む$x$は$k_x(k_x + 1)/2$、同様に$y$。 もし$x$この合計より小さい、または$y$が対応する合計より小さい場合、シーケンスは存在できません。 それ以外の場合は、最小シーケンスから開始し、必要に応じて最大ステップを調整しながら、合計が正確に一致するようにステップ長を段階的に割り当てて、有効なシーケンスを構築できます。 

この観察により、問題は単純なチェックに集約されます。$k = 1$、 増加$k$最低額まで$x$そして$y$以内に達成できる$k$ステップ。 もし$k$合計を満たさずに大きくなりすぎると、目標に到達できなくなります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(k) | 遅すぎる |
 | 貪欲 / 建設的 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースごとに、ターゲット座標を抽出します。$(x, y)$。 確保する$x \le y$推論を単純化するため。 それ以外の場合は、軸を交換します。 これは対称なので、答えは変わりません。 
2. もし$x = 0$または$y = 0$、出力$-1$、各ステップは正の整数でなければならないためです。 同様に、$x > y$交換後、小さい方の座標を次のように続けます。$x$。 
3. 歩数について$k = 1, 2, 3, ...$、計算する$k_x = \lceil k/2 \rceil$そして$k_y = \lfloor k/2 \rfloor$。 これらは、それに沿ったステップ数を表します$x$そして$y$それぞれ。 
4. 達成可能な最小合計を計算します。$x$そして$y$最初のものを使用して$k_x$そして$k_y$整数:$min_x = k_x(k_x + 1)/2$、$min_y = k_y(k_y + 1)/2$。 もし$x < min_x$または$y < min_y$、増分$k$そして繰り返します。 
5. 目標値と最小値の差を、厳密に増加するルールに違反することなく最大ステップ間で分配できるかどうかを確認します。 のために$x \le y$、これは貪欲な割り当てを使用すると常に可能です: シーケンスから開始$1..k$最大ステップを調整します。 
6. 最初の$k$これらの条件を満たすことが最小限のステップ数です。 そうでない場合$k$実用的な限界まで存在する（例えば、$k(k+1)/2$を超える$x+y$)、出力$-1$。 

**これが機能する理由:** 不変条件は、厳密に増加する長さのシーケンスの最小可能な合計であるということです。$m$は$m(m+1)/2$。 ターゲットに到達する厳密に増加する正の整数シーケンスは、少なくともこの合計と一致する必要があります。 段階的に増やしていくことで$k$そして計算する$k_x$そして$k_y$、ステップ数が最小限であることを保証し、最大ステップを調整することでターゲットに正確に一致させることができます。 交互ステップ制約は、シーケンスを奇数ステップと偶数ステップに分割することによって本質的に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        if x > y:
            x, y = y, x  # ensure x <= y

        ans = -1
        for k in range(1, 100):  # small bound; solution always fits under 100 steps
            kx = (k + 1) // 2
            ky = k // 2
            min_x = kx * (kx + 1) // 2
            min_y = ky * (ky + 1) // 2
            if x >= min_x and y >= min_y:
                diff_x = x - min_x
                diff_y = y - min_y
                if diff_x <= ky and diff_y <= kx:  # can adjust largest steps without conflict
                    ans = k
                    break
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず座標を正規化します。$x \le y$、その後、潜在的な歩数を繰り返します。 候補者ごとに$k$の最小合計を計算します。$x$そして$y$。 その歩数で目標に到達できる場合は、次のように出力されます。$k$。 100 という限界は、最初の 100 個の整数の合計が 5050 であるという事実に由来しており、これは最も実際的な最小要件をはるかに超えています。$x, y \le 10^9$。

 ステップを割り当てることができます。最初に x に沿って 5 を移動し、次に y に沿って 6 を移動します。 最小ステップ = 2。 

**例 2:$(1,1)$**

 | k | kx | キイ | 最小_x | 分_y | x>=min_x | y>=min_y | 答え |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | 0 | 本当 | 本当 | -1 |

 2 番目のステップでは y に沿って 1 を移動できません。2 番目のステップは最初のステップ (1) より厳密に大きくなければならないため、出力は -1 になります。
