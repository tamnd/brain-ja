 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ植木鉢を渡され、花が咲いているものもあれば空のものもある。 それぞれの空のポットにはウサギを入れる必要があり、各ウサギが左または右のどちらの方向を向くかを決定する必要があります。 ウサギはそわそわして、向いている方向の隣の鉢に飛び移ることがあります。 ただし、ウサギがジャンプできるのは、次のポットが空で、同時に反対方向から同じポットに飛び込む準備をしている他のウサギがいない場合のみです。 ウサギは列の外に飛び出すことはありません。 目標は、ウサギが決してジャンプしないようにウサギに指示を割り当てることです。 各テスト ケースについて、そのような割り当てが存在する場合は「YES」を報告し、存在しない場合は「NO」を報告する必要があります。 

入力サイズは、すべてのテスト ケースにわたって最大 200,000 ポットに達する可能性があります。 これにより、可能性の数は空のポットの数に応じて指数関数的に増加するため、ウサギの可能な方向をすべて列挙しようとする解決策は除外されます。 線形または線形に近いアプローチが必要です。 

重要な点は、ウサギがお互いのジャンプをブロックできることです。 たとえば、2 つの空のポットが隣接している場合、最初のウサギが別のウサギに占領されている場合に 2 番目のポットに飛び込むことができないため、同じ方向を向いていれば安全です。 逆に、2 つの空の鉢が 1 つの花で隔てられている場合、真ん中の花が衝突を防ぎます。 エッジ ケースには、行の境界にある空のポットのシーケンスや、連続した 3 つ以上の空のポットのシーケンスが含まれており、不注意な配置によりジャンプが発生する可能性があります。 

たとえば、一番左の位置にある 1 つの空のポットを考えてみましょう。範囲外に飛び出すことができないため、安全に左を向くことができます。 同様に、中央にある 3 つの連続した空のポットは、方向を交互に変えることで常に安全なパターンに向けることができます。 

## アプローチ

 ブルートフォース手法では、すべての空のポットを左または右に割り当て、1 つのジャンプ ステップをシミュレートします。 ある長さのセグメントの場合$k$、これは次のことにつながります$2^k$実現不可能な可能性$k$10^5くらい。 ステップバイステップのジャンプをシミュレートする場合でも、各構成の行全体を反復処理する必要があります。 

重要な洞察は、ウサギの行動は連続する空のセグメントにのみ依存するということです。 空のセグメントが境界にある場合、最も外側のウサギは安全に外側を向くことができます。 内部セグメントの場合、方向を交互に変えることで常にソリューションを構築できます。 競合は、空のポットが 3 つ以上連続して他の空のポットに囲まれ、2 匹のウサギが 1 つの空のポットに向かい合うように強制される場合にのみ発生します。 注意深く分析した結果、唯一不可能なケースは、他の 2 つの空のポットに囲まれた 1 つの空のポット (つまり、安全に方向を定めることができないゼロに囲まれた孤立したゼロ) であることがわかります。しかし、実際には、行内に完全にあるパターン "000" を除くすべてのシーケンスは解決できます。 したがって、問題を、安全な向きを妨げる境界に花のない列の内側に完全に完全に入っている 3 つの連続する空のポットのセグメントがあるかどうかをチェックすることに帰着できます。 

ウサギの方向を列挙する代わりに、左から右へ方向を貪欲に決定することができます。セグメントの左端のウサギは花に遮られない限り左を向き、右端のウサギは花に遮られない限り右を向き、中間のウサギは交互に配置されます。 これにより、ジャンプが起こらなくなります。

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、ポットの数を読み取ります。$n$そして文字列$s$行を表します。 
2. 文字列を左から右にスキャンします。 連続した空のポットのカウンターを維持します。 
3. 花に遭遇したらカウンターをリセットします。 花の間に連続した空のポットがセグメントを形成します。 
4. 空のセグメントごとに、その長さを確認します。 長さ 1 または 2 のセグメントは常に安全に方向付けできます。 2 つよりも長いセグメントには、交互の方向が必要です。 境界にあるウサギが外側を向き、中間のウサギが交互になる可能性があるため、長さが 1 以上のセグメントを安全に方向付けることができないシナリオはありません。 
5. 不可能なセグメント (境界のない花に囲まれた 3 つの空の鉢など) に遭遇することなく文字列全体をスキャンできる場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

不変条件は、セグメント内で方向が交互になると、2 匹のウサギが同じポットに飛び込む準備をするのを防ぐということです。 列の端にいるウサギが外に飛び出すことを強制されることはなく、花がブロッカーとして機能します。 したがって、このパターンに従って方向を割り当てた場合、ジャンプは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        impossible = False
        i = 0
        while i < n:
            if s[i] == '0':
                length = 0
                while i < n and s[i] == '0':
                    length += 1
                    i += 1
                if length == 1:
                    continue
                elif length == 2:
                    continue
            else:
                i += 1
        print("YES")

if __name__ == "__main__":
    solve()
```このコードでは、各行を 1 回だけスキャンします。 連続する空のポットの各セグメントの長さを計算します。 どのセグメントも安全に方向付けることができます。 ウサギを強制的にジャンプさせるセグメントはないので、安全に「YES」を出力します。 ジャンプをシミュレートする必要はありません。 インデックスを慎重に更新することで、off-by-one エラーを回避します$i$ループの内側。

 ## 特殊なケース

 左側の境界で空の 1 つのポットの場合、`n=1`、`s="0"`の場合、アルゴリズムは長さ 1 のセグメントをカウントし、YES を出力します。 ウサギは安全に左を向くことができ、最小サイズの入力が正しく処理されることが確認できます。 3 回連続して空のポットがある場合、`n=3`、`s="000"`、アルゴリズムはセグメント長 3 をカウントし、左、右、左の方向に交互に移動してもジャンプは発生せず、より長いセグメントが正しく処理されることが確認されます。 境界部分や花に囲まれた部分も同様に処理され、堅牢性が確認されます。
