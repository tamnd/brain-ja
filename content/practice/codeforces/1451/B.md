 ## 解決策
 ## 問題の理解

 バイナリ文字列と複数の範囲クエリが与えられます。 各クエリは連続した部分文字列を選択します。そして、この部分文字列が制約の下で同じ文字列内のどこかにサブシーケンスとして現れることができるかどうかを決定する必要があります。サブシーケンスは連続したブロックとして解釈されてはならず、少なくとも 2 つの文字が含まれている必要があります。 

重要な解釈は、元​​の文字列内ですべてが隣接しているわけではないインデックスを使用して部分文字列を「再構築」できるかどうかを判断しようとしているということです。 したがって、固定部分文字列を、それ自体のすべての非連続埋め込みとサブシーケンスとして比較しています。 

制約は十分小さいため、O(nq) または O(n^2) の前処理アプローチでも十分です。 n と q がテスト ケースごとに最大 100 で、最大 100 のテスト ケースであれば、三次推論でも安全です。 これは、文字列をスキャンしたり、単純な構造情報を事前計算したりすることで、クエリごとに自由に推論できることを意味します。 

部分文字列の長さがちょうど 2 の場合、微妙なエッジ ケースが発生します。部分文字列が元の文字列内で連続している場合、その部分文字列は「良好な部分シーケンス」として自動的に無効になります。これは、これと等しいサブシーケンスは隣接するインデックスを正確に使用する必要があるためです。 もう 1 つの特殊なケースは、部分文字列が同一の文字で構成されている場合 (たとえば、「00」や「11」) です。この場合、文字のグローバルな分布に応じて、不連続な再構築が可能かどうかが決まります。 

多くの場合、解決策を壊す単純な誤解は、非連続要件を強制せずに、問題を「部分文字列がサブシーケンスとして他の場所に存在するかどうか」として扱うことです。 これにより、唯一の有効な構造が部分文字列自体と同じ位置を使用するケースが誤って受け入れられることになります。 

## アプローチ

 ブルートフォース解釈では、元の連続セグメントの外側のインデックスを選択することによって、部分文字列をサブシーケンスとして構築しようとします。 各クエリ部分文字列について、文字列内の他の場所で 2 つ以上の一致する文字を選択し、それらが順番に表示されるかどうかを確認することを試みることができます。 このアプローチは正しいですが、非効率的です。クエリごとに文字列全体をスキャンして複数の貪欲な構築を試行する可能性があり、クエリごとに O(n) 回の作業が繰り返されることになります。 

重要な点は、文字列がバイナリであるため、部分文字列に一致する部分シーケンスは、元のセグメントの外側に連続性を壊すのに十分な数の各文字が見つかるかどうかにのみ依存するということです。 部分文字列が失敗する唯一の原因は、それが連続セグメントとして正確に「強制的に」取得される場合です。これは、隣接性の制約を回避しながら順序を維持する代替インデックス選択がないことを意味します。 

これにより、問題は、文字の使用可能性に関する構造上の制約と、部分文字列を非連続に埋め込むことができるかどうかのチェックに減らされ、単純なプレフィックスの前処理後にクエリごとに一定時間でテストできます。

 ## アルゴリズムのチュートリアル

 正しいアプローチは、0 と 1 の前処理プレフィックス数に依存しているため、セグメント内に各文字が何個存在するかを迅速に判断できます。

1. 「0」と「1」のプレフィックスの合計を作成します。 これにより、任意の部分文字列の文字数に対する O(1) クエリが可能になります。 
2. 各クエリ部分文字列 s[l..r] について、それに含まれる 0 と 1 の数を計算します。 これにより、サブシーケンスとして埋め込みたいターゲットシーケンスの正確な構成がわかります。 
3. l の前のプレフィックスまたは r の後のサフィックスに、連続性を壊す「外部アンカー」として機能する文字が少なくとも 1 つ存在するかどうかを確認します。 少なくとも 1 つの必要な文字にそのような位置が存在する場合、部分文字列と等しい不連続な部分シーケンスを形成できます。 
4. 必要な文字のすべての出現が部分文字列の境界内に厳密に制限されている場合、部分シーケンスを構築する試みは、それらの連続した位置を正確に使用する必要があり、無効になります。 
5. 有効な非連続構造が存在する場合は YES を返し、そうでない場合は NO を返します。 

微妙な推論手順は、連続性を壊すには、サブシーケンス内の少なくとも 1 つの文字が区間の外側から来る必要があり、そうでない場合、サブシーケンスは元の連続した部分文字列に崩壊するということです。 

### なぜ効果があるのか

 不変条件は、部分文字列に等しい有効な部分シーケンスは、まったく同じインデックス セットを再利用するか、少なくとも 1 つの位置をセグメント外の代替出現に置き換える必要があるということです。 プレフィックス構造により、そのような代替出現が存在するかどうかを検出できることが保証されます。 そのような出現が存在しない場合、インデックスの有効な選択はすべて部分文字列と同一であることが強制され、「連続していない」条件に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i in range(n):
            pref0[i + 1] = pref0[i] + (s[i] == '0')
            pref1[i + 1] = pref1[i] + (s[i] == '1')

        for _ in range(q):
            l, r = map(int, input().split())

            cnt0 = pref0[r] - pref0[l - 1]
            cnt1 = pref1[r] - pref1[l - 1]

            left0 = pref0[l - 1]
            left1 = pref1[l - 1]
            right0 = pref0[n] - pref0[r]
            right1 = pref1[n] - pref1[r]

            # check if we can take at least one character outside the segment
            outside0 = left0 + right0
            outside1 = left1 + right1

            inside_len = r - l + 1

            # if all characters of both types are trapped inside segment, no escape subsequence
            if inside_len >= 2 and (outside0 > 0 or outside1 > 0):
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    solve()
```プレフィックスの合計を計算した後、各クエリは、非連続サブシーケンスの構築に使用できるセグメントの外側に少なくとも 1 つの文字が存在するかどうかの定数時間評価になります。 プレフィックス配列により、文字列をスキャンせずに「外部可用性」をテストできることが保証されます。 

実装でよくある落とし穴は、文字列がバイナリであるため、両方の文字を個別に追跡すれば十分であることを忘れることです。 もう 1 つは、1 インデックスのクエリの誤処理です。これが、プレフィックス配列がオフセットを使用して構築される理由です。

 ## 特殊なケース

 文字列全体にまたがる部分文字列の場合、連続性を壊すために使用できる外部文字がないため、アルゴリズムは正しく NO を出力します。 長さ 2 の部分文字列の場合、文字列内の他の場所に文字が存在する場合でも、バイナリのみの構成では外部インデックスが存在しないため、部分シーケンスが部分文字列自体と強制的に一致し、有効な非連続構造が妨げられます。
