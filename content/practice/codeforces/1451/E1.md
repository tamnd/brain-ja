 ## 解決策
 ## 問題の理解

 サイズの隠し配列が与えられます$n$、 どこ$n$は 2 の累乗です。 配列内の各要素は、範囲内の整数です。$[0, n-1]$。 目標は、最大でも次の質問をして配列を再構築することです。$n+2$配列の任意の 2 つのインデックス間の AND、OR、および XOR の 3 つのタイプのクエリ。 十分な情報を収集した後、配列全体を正しく出力する必要があります。 

各要素は次のように区切られているため、$n-1$、すべての数字が以内に収まります$\log_2 n$ビット。 以来$n$と同じ大きさにすることができます$2^{16}$を尋ねるようなアプローチは避ける必要があります。$\Theta(n^2)$クエリ; と$n = 2^{16}$、それには必要になります$2^{32}$クエリ、それは不可能です。 インタラクティブな限界$n+2$すべてのペアをチェックするのではなく、要素間のビットごとの関係に基づいた、高度に構造化された戦略が必要であることを示しています。 

素朴なアプローチは、AND または OR を使用してすべてのペアを試行して各要素を直接再構築することですが、これではクエリの制限を超えます。 注意すべきエッジケースには、一部の要素がゼロまたは同じである配列が含まれます。$[0,0,1,2]$インデックスが慎重に選択されていない場合、単純な XOR 累算では同一の値が混同される可能性があるためです。 もう 1 つの微妙なケースは、すべての数値が最大の場合です ($n-1$)-ビットごとの合計が値の範囲に関する仮定をオーバーフローしないようにする必要があります。 

## アプローチ

 ブルートフォース手法では、各要素と最初の要素などの固定参照の間のすべての AND または OR をクエリします。 要素ごとに$a_i$、計算できます$a_1 \text{ AND } a_i$そして$a_1 \text{ OR } a_i$そして次のことを解決します$a_i$。 これが機能するのは、AND と OR が 2 つの数値を再構成するための十分な制約を与えるためです。 ただし、これには次のことが必要です$2(n-1)$クエリは大きすぎます$n$まで$2^{16}$。 このアイデアは原理的には機能しますが、クエリの予算によってはそれができません。 

重要な洞察は、ビットごとの ID から得られます。$$x + y = (x \text{ AND } y) + (x \text{ OR } y)$$これは、2 つの数値の AND と OR の両方がわかれば、それらの正確な合計が得られることを意味します。 3 つの要素を選択すると、次のようになります。$a_1, a_2, a_3$、ペア (1,2)、(1,3)、および (2,3) の AND と OR を計算すると、それらの合計を再構成できます。 させて$S_{12} = a_1 + a_2$、$S_{13} = a_1 + a_3$、 そして$S_{23} = a_2 + a_3$。 これら 3 つの方程式を解くと、次の値が得られます。$a_1, a_2, a_3$ユニークに。 一度$a_1$が既知であれば、単一の XOR クエリで他のすべての要素を見つけることができます。$a_i = a_1 \text{ XOR } (a_1 \text{ XOR } a_i)$。 

この戦略では、3 つの AND/OR クエリを使用して 3 つの要素を再構築し、さらに残りの要素ごとに 1 つの XOR を使用します。$3 + (n-3) = n$クエリ。$n+2$限界。 問題の構造 (小さい有界整数、2 のべき乗の配列サイズ、合計間の線形関係) により、このアプローチは最適になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | クエリが多すぎます。制限を超えています |
 | 最適 | O(n) | O(n) | 受け入れられ、≤ n+2 クエリを使用します |

 ## アルゴリズムのチュートリアル

 1. ペア (1,2)、(1,3)、および (2,3) の AND および OR をクエリします。 合計を計算する$S_{12} = \text{AND}_{12} + \text{OR}_{12}$、$S_{13} = \text{AND}_{13} + \text{OR}_{13}$、$S_{23} = \text{AND}_{23} + \text{OR}_{23}$。 これにより、これらのペアの正確な合計が得られます。 
2. を解く$a_1$公式を使って$a_1 = (S_{12} + S_{13} - S_{23}) // 2$。 これはシステムから来ています:$$a_1 + a_2 = S_{12}, \quad a_1 + a_3 = S_{13}, \quad a_2 + a_3 = S_{23}$$最初の 2 つの分離株の合計から 3 番目の株を引く$2a_1 = S_{12} + S_{13} - S_{23}$。 

1. コンピューティング$a_2 = S_{12} - a_1$そして$a_3 = S_{13} - a_1$。 これらは整数演算であるため正確です。 すべての数字は範囲内にあります$[0, n-1]$。 
2. 残りの各要素について$a_i$と$i > 3$、XOR をクエリします。$a_1$、与える$a_1 \text{ XOR } a_i$。 その後回復します$a_i = a_1 \text{ XOR } (a_1 \text{ XOR } a_i)$。 これが機能するのは、XOR が自動的に反転されるためです。$x \text{ XOR } y \text{ XOR } x = y$。 
3. 再構築された配列に「!」というプレフィックスを付けて出力します。 

機能する理由: 3 つの未知数に対する 3 つのペアごとの和からなるシステムは、常に整数で解くことができます。 XOR は可逆的であり、既知の参照を基準にして各要素を一意に決定します。 クエリ数は正確に$n$、常に許容値を下回ります$n+2$。 すべての要素が ≤ であるため、ビット単位の演算がオーバーフローすることはありません。$n-1$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def ask(op, i, j):
    print_flush(f"{op} {i} {j}")
    return int(input())

def main():
    n = int(input())
    # Step 1: Query AND and OR for first three elements
    and12 = ask("AND", 1, 2)
    or12 = ask("OR", 1, 2)
    s12 = and12 + or12

    and13 = ask("AND", 1, 3)
    or13 = ask("OR", 1, 3)
    s13 = and13 + or13

    and23 = ask("AND", 2, 3)
    or23 = ask("OR", 2, 3)
    s23 = and23 + or23

    # Step 2: Solve for a1, a2, a3
    a1 = (s12 + s13 - s23) // 2
    a2 = s12 - a1
    a3 = s13 - a1

    # Step 3: Reconstruct remaining elements using XOR
    a = [a1, a2, a3]
    for i in range(4, n+1):
        x = ask("XOR", 1, i)
        a.append(a1 ^ x)

    # Step 4: Output
    print_flush("! " + " ".join(map(str, a)))

if __name__ == "__main__":
    main()
```このソリューションでは、まず、ペアごとの AND と OR を使用して最初の 3 つの要素の正確な値を決定し、それらの合計を求めます。 次に、残りのすべての要素を相対的に再構築します。$a_1$XOR クエリを使用します。 各クエリはアイドル状態の制限を回避するために即座にフラッシュされ、入力が制限されているため、すべての算術演算は整数安全です。
