 ## 問題の理解

 2 つの文字列が与えられています。`a`そして`b`、同じ長さの`n`、整数とともに`k`。 目標は、変革できるかどうかを判断することです`a`の中へ`b`2 種類の操作を使用します。 最初の操作では、隣接する文字を交換できます。`a`。 2 番目の操作では、任意の長さの連続したブロックを選択できます。`k`ここで、すべての文字は同一ではありません`'z'`、そのブロック内の各文字をアルファベットの次の文字にインクリメントします。 

入力は複数のテスト ケースで構成されます。 各テスト ケースで、変換できる場合は「はい」を出力する必要があります。`a`の中へ`b`、それ以外の場合は「いいえ」。 

制約を考慮すると、`n`すべてのテスト ケースにわたって最大 10^6 にすることができます。 これにより、操作の数が膨大になる可能性があるため、すべての操作を段階的にシミュレートしようとするソリューションが不要になります。 文字列の長さに対して線形または線形に近い時間で機能するアプローチが必要です。 

エッジケースが発生するのは次のような場合です`k = 1`。 この場合、任意の 1 文字をインクリメントできます (そうでない場合)。`'z'`、以前よりも柔軟性が高くなります。`k > 1`。 もう一つ厄介なケースが発生するのは、`a`文字が含まれています`'z'`それは小文字にする必要があります。 インクリメント操作は適用できません`'z'`、一部の変換が不可能になります。 同様に、ある文字の番号が`a`で必要な数より少ないです`b`、要件を満たすことができない場合があります。 

たとえば、次のように考えてみましょう`a = "abc"`、`b = "bcd"`、 そして`k = 3`。 から始まるブロックをインクリメントできないため、文字を正しくインクリメントする方法はありません。`'c'`または`'b'`均一ブロック要件に違反したり、アルファベットの制限を超えたりすることはありません。 

## アプローチ

 単純なアプローチでは、操作を直接シミュレートします。交換可能な文字または増分可能なブロックを繰り返しチェックし、次のいずれかになるまで変換を適用します。`a`等しい`b`または何も操作を実行できません。 これは理論的には正しいですが、実際には次の時間がかかります。`O(n^2)`が遅すぎて最悪の場合、`n`最大 10^6。 

重要な洞察は、隣接するスワップにより順序を変更できるということです。`a`勝手に。 したがって、正確な位置について心配する必要はありません。 文字数が一致するかどうかを確認するだけで済みます。`a`そして`b`インクリメント操作を使用した後。 長さのブロックに対する各インクリメント操作`k`効果的に転送が可能になります`k`1 文字から次の文字までの単位。 これにより、貪欲な戦略が得られます。`'a'`そして、必要な数を満たすように試みます`b`の余分な文字を使用して、`a`そしてそれらをより高い文字に押し上げます。 

ブルート フォースは、考えられるすべての操作をシミュレートするため機能しますが、二次関数の複雑さのため、大きな文字列の場合は失敗します。 スワップにより自由な並べ替えが可能になり、増分を貪欲に処理できるという観察により、問題を文字カウントの線形パスに落とし込み、余剰カウントを下位の文字から上位の文字に伝播させることができます。

 ## アルゴリズムのチュートリアル

 1. 長さ 26 の 2 つの配列を初期化して、文字列内の各文字の出現をカウントします。`a`そして`b`。 使用`ord(char) - ord('a')`文字をインデックスにマッピングします。 
2. からアルファベットをループします。`'a'`に`'y'`(インデックス 0 ～ 24)。 文字ごとに次のことを確認します。`a`カバーできる十分なインスタンスがある`b`。 もし`a`以上のものを持っています`b`、剰余を計算します。 
3. 余剰がマイナスの場合は、ゼロからキャラクターを作成することはできないため、すぐに「いいえ」を返します。 
4. 余剰がプラスの場合は、次の倍数で繰り上げることができます。`k`次の手紙へ。 余剰モジュロを減らす`k`そしてその整数商を次の文字の数に加えます。 
5.すべての文字を処理した後、最後の文字を確認します`'z'`。 もし`a`とまったく同じ番号があります`b`、「はい」を返します。 それ以外の場合は、「いいえ」を返します。 

機能する理由: アルゴリズムは、各ステップで使用可能な文字が不変であることを維持します。`a`現在の手紙までで十分です`b`。 余った文字は常に次の倍数で前に押し出されます。`k`、インクリメントブロックのルールに一致します。 スワップでは自由に並べ替えができるため、ポジションではなくカウントのみが重要になります。 これにより、貪欲な戦略が正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_convert(n, k, a, b):
    count_a = [0] * 26
    count_b = [0] * 26
    for ch in a:
        count_a[ord(ch) - ord('a')] += 1
    for ch in b:
        count_b[ord(ch) - ord('a')] += 1

    for i in range(25):
        if count_a[i] < count_b[i]:
            return False
        surplus = count_a[i] - count_b[i]
        # push surplus forward in multiples of k
        if surplus % k != 0:
            return False
        count_a[i+1] += surplus
    return count_a[25] == count_b[25]

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = input().strip()
    b = input().strip()
    print("Yes" if can_convert(n, k, a, b) else "No")
```コードはまず、次の各文字の頻度をカウントします。`a`そして`b`。 次に、文字をループします`'a'`に`'y'`、カウントされているかどうかを確認します`a`で十分であり、余剰分は次の倍数で前倒しされます。`k`。 最後にチェックします`'z'`完全一致の場合。 入力文字列を削除すると、末尾の改行の問題がなくなります。
