 ## 解決策
 ## 問題の理解

 タスクはマインスイーパーのようなグリッド ゲームに設定されていますが、インタラクティブにプレイする代わりに、固定の隠しボード構成を分析しています。 長方形のグリッドが表示され、各セルには地雷が含まれているか空です。 空のセルには、隣接する 8 つのセル (対角線を含む) に存在する地雷の数に等しい数値が表示されます。 

この問題では、指定されたボード構成が実際の地雷の配置と一致しているかどうかを判断するように求められます。 ここでの一貫性とは、すべての明らかにされた数値が隣接する地雷の数と正確に一致し、すべての地雷が入力で地雷としてマークされたセルに正確に配置されるように、各セルを地雷または空のいずれかとして割り当てる方法が存在することを意味します。 

出力は単純な実現可能性の決定であるため、中心的な困難は値の計算ではなく、バイナリ状態 (私のものであるかどうか) のグローバルな割り当てがすべてのローカル制約を同時に満たせるかどうかを検証することです。 

制約構造は重要です。番号付きの各セルは、最大 8 つの隣接する変数に対して合計制約を課し、各変数は最大 8 つの制約に参加します。 これは、ローカル次数が非常に小さいものの、潜在的に大規模なグローバル伝播チェーンを備えたグリッド グラフ上の古典的な制約満足システムです。 

複雑さの観点から見ると、このような問題のグリッドは通常、最大約 1000 x 1000 またはそれに類似したサイズになります。 20x20 グリッドでもすでに 2^400 の可能性があるため、すべての地雷の配置を列挙しようとするアプローチはすでに除外されています。 すべての未知のセルを独立して分岐させようとしても実行不可能です。 

さらに微妙な問題は、局所的な曖昧さから生じます。 番号付きの各セルをそのすぐ隣のセルに対して個別にチェックするだけの単純なソルバーでは、グローバルな伝播後にのみ現れる矛盾を見逃す可能性があります。 たとえば、2 つの隣接する番号付きセルはそれぞれ、ローカルで複数の構成を満たせる可能性がありますが、グローバルに有効なのは 1 つの共有構成のみです。 

典型的な失敗例は次のようになります。2 つの重複する制約があり、どちらも単独では満たせるように見えますが、共有される隣接要素には一貫性のない割り当てが強制されると想像してください。 影響を広めないアプローチは、そのようなボードを誤って受け入れてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、すべての未知のセルをバイナリ変数として扱い、可能なすべての代入を試みます。 割り当てごとに、隣接する地雷を数えることによって、番号が付けられたすべてのセルを検証します。 これは妥当性の定義を直接チェックするので論理的には正しいですが、組み合わせ的に爆発します。 k 個の未知セルの場合、実行時間は O(2^k · (n · m · 8)) ですが、k が 50 程度であっても不可能になります。 

重要な観察は、番号付きの各セルが単にチェックを課すだけでなく、少数の変数セットに厳しいローカル制約を課すことです。 制約の伝播の観点から考えると、いくつかのセルが固定されると、他の多くのセルが強制されます。 この構造は、各未知のセルをグラフ内のノードとして扱い、ローカル一貫性ルールを使用して強制決定を伝播することによって自然に処理されます。 

重要な考え方は、マインスイーパの制約がバイナリ変数に対する線形制約のように動作するということです。各数値は、隣接する数値の合計が固定値に等しくなるように強制します。 これは、伝播が安定すると、矛盾を局所的に検出できることを意味します。 すべての割り当てを探索する代わりに、推論が不可能になるまで強制状態を繰り返し推論します。 

この時点で、制約に違反した場合、ボードは無効になります。 違反が存在せず、矛盾を隠す可能性のある未知の構造が曖昧なままであれば、その構成は、これらの問題で使用される標準のマインスイーパーの一貫性解釈の下では有効です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての地雷配置に対するブルートフォース | O(2^k・n・m) | O(n・m) | 遅すぎる |
 | 制約の伝播 (キュー / BFS スタイルの推論) | O(n・m) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルを固定（既知）または未知としてモデル化し、番号付きセルが残りの未知の隣接セルからまだ必要とする地雷の数を追跡する機能構造を維持します。 

1. すべてのセルが入力に従ってマークされ、番号付きセルが未知のセルまたは鉱山セルから分離されるグリッド状態を初期化します。 番号付きセルごとに、現在地雷としてマークされている隣接セルの数と未決定のセルの数を計算します。 これにより、各制約セルの初期の「残りの地雷要件」が得られます。 
2. 制約が即座に決定されたすべての番号付きセルを処理キューに入れます。これは、隣接する地雷の正しい数が既に存在しているか、すでに不可能であることを意味します。 その理由は、完全に決定された制約のみが開始時に強制控除をトリガーできるためです。 
3. キューからセルを繰り返し抽出し、その制約を隣接セルに伝播しようとします。 番号付きセルが必要なすべての地雷をすでに満たしている場合、残りの未知の隣接セルはすべて安全でなければなりません。 未知の隣接地とまったく同じ数の地雷が依然として必要な場合、それらの未知の隣接地はすべて地雷である必要があります。 これが控除の核となるルールです。 
4. 隣接セルの状態が不明から強制地雷または強制安全に変わるたびに、残りの地雷数と不明数を調整して、隣接するすべての番号付きセルを更新します。 更新された状態が過度に制約されている番号付きセル (マイナスの値が残っている、または利用可能な未知数を超えている) は、直ちに不一致を示します。 
5. キューが空になるまでこの伝播を続けます。つまり、それ以上の強制的な差し引きは不可能になります。 この時点で、無効な制約セルがないか確認してください。 伝播中に矛盾が見つかった場合、構成は不可能になります。 
6. 矛盾が見つからない場合、制約のすべての強制的な意味が一貫して満たされているため、構成は有効であると見なされます。 

### なぜ効果があるのか

 番号付きの各セルは、隣接するセルに対するローカル方程式を表します。 伝播ルールは強制割り当てを網羅しています。制約に自由度が残っていない場合は常に、残っているすべての未知の近傍の値が一意に決定されます。 これは、アルゴリズムが制約によって論理的に強制された割り当てのみをコミットすることを意味します。 

グローバルな矛盾は、伝播のある段階でこれらの制約方程式のいずれかでローカルな矛盾として現れるはずです。 すべての更新で制約の有効性が即座に再計算されるため、無効な構成は、検出された不整合を引き起こさずにプロセスを存続することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

# We assume the typical Minesweeper consistency format:
# grid contains either:
# '*' or 'M' for mine
# '.' for empty
# or digits '0'-'8' for number cells

dx = [-1,-1,-1,0,0,1,1,1]
dy = [-1,0,1,-1,1,-1,0,1]

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    # state: -1 unknown, 0 safe, 1 mine
    state = [[-1]*m for _ in range(n)]

    # queue of number cells to process
    q = deque()

    # helper arrays for constraints
    need = [[0]*m for _ in range(n)]
    unk = [[0]*m for _ in range(n)]

    def inb(x,y):
        return 0 <= x < n and 0 <= y < m

    # initialize
    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                state[i][j] = 1

    for i in range(n):
        for j in range(m):
            if g[i][j].isdigit():
                mn = int(g[i][j])
                c_mine = 0
                c_unk = 0
                for k in range(8):
                    ni, nj = i + dx[k], j + dy[k]
                    if not inb(ni, nj):
                        continue
                    if state[ni][nj] == 1:
                        c_mine += 1
                    elif state[ni][nj] == -1:
                        c_unk += 1
                need[i][j] = mn - c_mine
                unk[i][j] = c_unk
                q.append((i,j))

    def relax(i, j):
        # if contradiction already present
        if need[i][j] < 0 or need[i][j] > unk[i][j]:
            return False

        # if all mines already placed => remaining neighbors safe
        if need[i][j] == 0 and unk[i][j] > 0:
            for k in range(8):
                ni, nj = i + dx[k], j + dy[k]
                if inb(ni, nj) and state[ni][nj] == -1:
                    state[ni][nj] = 0
                    update(ni, nj)
        # if all unknown must be mines
        elif need[i][j] == unk[i][j] and unk[i][j] > 0:
            for k in range(8):
                ni, nj = i + dx[k], j + dy[k]
                if inb(ni, nj) and state[ni][nj] == -1:
                    state[ni][nj] = 1
                    update(ni, nj)
        return True

    def update(x, y):
        for k in range(8):
            ni, nj = x + dx[k], y + dy[k]
            if inb(ni, nj) and g[ni][nj].isdigit():
                if state[x][y] == 1:
                    need[ni][nj] -= 1
                unk[ni][nj] -= 1
                q.append((ni, nj))

    while q:
        i, j = q.popleft()
        if g[i][j].isdigit():
            if not relax(i, j):
                print("NO")
                return

    print("YES")

if __name__ == "__main__":
    solve()
```コードは、番号付きセルごとに 2 つの情報、つまり、まだ必要な地雷の数と未決定の隣接地雷の数を維持します。 セルが決定されるたびに、隣接する制約に更新をプッシュして、推論がグリッド全体で自然にカスケードされるようにします。 

実装の微妙な詳細は、すべての更新で残りの要件と残りの不明な数の両方を調整する必要があることです。 未知の数のデクリメントを忘れることは、誤った過剰受け入れの最も一般的な理由です。これは、制約がすでに過剰に制約されている場合でも、制約が満たされているように見える可能性があるためです。 

キューベースの伝播により、各状態変更が限られた回数だけ処理されることが保証され、ソリューションがグリッド サイズ内で線形に保たれます。

 ## 特殊なケース

 特殊なケースは、番号付きセルが最初に既知の地雷によってすでに完全に満たされている場合に発生します。 その状況では、アルゴリズムは、残りのすべての近隣者を直ちに安全にする必要があります。 このステップをスキップすると、ソルバーは誤ってあいまいなセルを未解決のままにし、後の矛盾を見逃す可能性があります。 

もう 1 つのエッジ ケースは、制約が既に過剰に満たされ始めている場合です。たとえば、最初のグリッドに 2 つの隣接する地雷が存在する 1 とラベル付けされたセルなどです。 そのシナリオでは、`need`初期化自体中に負になるため、アルゴリズムは直ちに拒否する必要があります。 この早期チェックがなければ、伝播はトリガーされませんが、構成は依然として無効となり、誤検知が発生します。
