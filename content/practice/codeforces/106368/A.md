 ## 解決策
 ## 問題の理解

 画面が値で始まる計算機があります`A`。 電卓には固定の数値があります`M`、ボタンを押すたびに、次の 4 つの変換のいずれかが適用されます。`M`、減算`M`、乗算します`M`、または現在の値を除算後の剰余に置き換えます。`M`。 目標は、正確な値に到達することではありません。 最終画面値が次と同じ剰余を持つようにするだけで済みます。`B`で割ると`N`。 タスクは、これを達成する最短のボタン押下シーケンスを出力するか、それが不可能であることを報告することです。 

の値`A`そして`M`と同じ大きさにすることができます`10^9`、 しかし`N`せいぜい`2 * 10^6`。 これにより、実際の計算機の値は乗算後に非常に大きくなる可能性があるため、保存することが直ちに除外されます。 剰余に基づいた状態表現が必要であり、状態の数は次のようにする必要があります。`N`限界に合わせて。 可能な値をすべて試してみることなどを行うソリューション`M`不可能だから`M`有用な小さな限界はありません。 

困難なエッジケースは、`%`手術。 モジュロ値のみがわかっている場合、他の演算のように動作しません。`N`、 なぜなら`% M`モジュロ値に依存します`M`。 

例えば：```
A = 5, M = 6, B = 1, N = 6
```答えは`-1`。 モジュロ値のみを追跡する不注意な実装`N`と思うかも知れません`%`操作では常に残留物が生成される可能性があります`5 mod 6`、しかしその後の計算機の値`%`範囲内になければなりません`[0, M - 1]`、そしてここで到達可能な残基には決して含まれません`1`。 

もう 1 つの重要なケースは、乗算が以前に発生した場合です。`%`:```
A = 5, M = 9, B = 1, N = 8
```最適なシーケンスの 1 つは次のとおりです。```
*%+
```後`*`、値は次のようになります`45`で割り切れます。`M`、 それで`%`生成する`0`、 ない`A mod M`。 実装が想定している場合`%`常に元の値を法として返します`M`、有効なパスが失われます。 

## アプローチ

 直接的な強引なアプローチでは、ボタンを押すあらゆる可能なシーケンスがシミュレートされます。 各ステップで 4 つの選択肢があるため、深さは`d`検索は最大まで探索します`4^d`シーケンス。 たとえ答えが最大でも保証されているとしても、`N`、 と`N`200 万人に到達するには、このアプローチは可能性をはるかに超えています。 

有益な観察は、計算機の完全な値が決して必要ないということです。 値のモジュロのみが必要です`N`、さらに、何が起こるかを予測するのに十分な情報`%`します。 

現在の値を次のようにします`X`。 私たちは次の 2 つのことを追跡します。 

1つ目は`X mod N`, これにより、必要な条件にすでに達しているかどうかがわかるからです。 

2つ目は`X mod M`、 なぜなら`%`置き換える`X`まさにこの残りで。 

驚くべき部分は、`X mod M`プロセス全体を通じて可能な値は 2 つだけです。 最初はそうです`A mod M`。 加算または減算`M`それは変わりません。 乗算`M`それを作る`0`。 の`%`演算は同じ値を法として維持します`M`なぜなら、新しい数値はすでに古い剰余と等しいからです。 

したがって、すべての状態は次のように表すことができます。```
(current value modulo N, current value modulo M is A mod M or 0)
```これにより、最大でも`2N`州。 すべての演算は通常のグラフ エッジとなり、幅優先探索で最短シーケンスが見つかります。 

ブルート フォース検索はシーケンスを探索するため失敗します。 上記の観察により、問題は小さなグラフ内の最短経路を見つけることに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^N) | O(4^N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての状態がペアであるグラフを暗黙的に構築します`(r, t)`。 ここ`r`は現在値のモジュロです`N`、 そして`t`現在の値を剰余かどうかを示します`M`元の値です`A mod M`またはゼロ。 
2.BFSを開始します`(A mod N, 0)`。 乗算が行われる前に、値の剰余が計算されるため、フラグは最初は 0 です。`M`まだです`A mod M`。 
3. ポップされた状態ごとに、可能な 4 つの操作を生成します。 

の`+`演算は剰余モジュロのみを変更します`N`:```
r -> (r + M) mod N
```を追加したため、フラグは変わりません。`M`剰余モジュロを変更しません`M`。 
4.`-`同様の操作:```
r -> (r - M) mod N
```繰り返しますが、モジュロ`M`残りは変わらず。 
5. 乗算を適用します。```
r -> (r * M) mod N
```値が次で割り切れるため、新しいフラグは 1 になります。`M`。 
6. 申請する`%`。 

フラグがゼロの場合、新しい値は次のようになります。`A mod M`。 フラグが 1 の場合、新しい値は 0 です。 フラグ自体は変わりません。 
7. 残りがある状態になったら BFS を停止する`B`に達します。 BFS は距離を増加させることによって状態を探索するため、最初のそのような状態が最短のシーケンスを与えます。 
8. 以前の状態と、すべての新しい状態に到達するために使用された操作を保存します。 これらのリンクを応答状態から逆方向にたどって、操作シーケンスを再構築します。 

なぜ効果があるのか:

 BFS グラフには、考えられるすべての計算機の状況が等価な状態に圧縮されて含まれています。 同じモジュロを持つ 2 つの計算機の値`N`剰余と同じモジュロ`M`残りは、4 つの操作すべてについて、将来の動作が常に同じになります。 2 番目のコンポーネントは次のとおりです。`A mod M`または`0`、グラフには関連するすべての可能性が含まれています。 BFS はこの完全な状態グラフで最短パスを見つけるため、再構築されるシーケンスは最小限になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    A, M, B, N = map(int, input().split())

    base = A % M

    total = 2 * N
    parent = [-1] * total
    parent_op = [''] * total

    def get_id(flag, rem):
        return flag * N + rem

    start = get_id(0, A % N)

    q = deque([start])
    parent[start] = start

    answer = -1

    while q:
        cur = q.popleft()
        flag = cur // N
        rem = cur % N

        if rem == B:
            answer = cur
            break

        nxt = [
            (flag, (rem + M) % N, '+'),
            (flag, (rem - M) % N, '-'),
            (1, (rem * M) % N, '*'),
            (flag, base % N if flag == 0 else 0, '%')
        ]

        for nf, nr, op in nxt:
            nid = get_id(nf, nr)
            if parent[nid] == -1:
                parent[nid] = cur
                parent_op[nid] = op
                q.append(nid)

    if answer == -1:
        print(-1)
        return

    path = []
    while answer != start:
        path.append(parent_op[answer])
        answer = parent[answer]

    path.reverse()

    print(len(path))
    if path:
        print(''.join(path))

if __name__ == "__main__":
    solve()
```コードは各状態を整数として保存します。 国旗のある州`0`インデックスを占有する`0`を通して`N-1`、および旗のある州`1`インデックスを占有する`N`を通して`2N-1`。 これにより、BFS 配列がコンパクトに保たれ、ホット ループ内のタプルが回避されます。 

遷移リストは 4 つの計算機操作の直後に続きます。 の`%`追加のフラグが必要なのは、transition だけです。 よくある間違いは、後でフラグを変更することです。`%`、ただし剰余モジュロ`M`の結果は同じままです`%`すでにその残りです。 

親配列を使用すると、完全な文字列を BFS キューに保存せずに再構築できます。 最大の場合、グラフには最大 400 万の州が含まれる可能性があるため、これは重要です。 

## 実用的な例

 最初のサンプルの場合:```
1 3 2 5
```最短の道は、`+*`。 

| ステップ | 州旗 | 値 mod N | 操作 |
 | --- | --- | --- | --- |
 | 0 | オリジナル | 1 | 開始 |
 | 1 | オリジナル | 4 | + |
 | 2 | ゼロ | 2 | * |

 乗算後、電卓の値が次の値で割り切れるため、フラグが変わります。`M`。 最終的な残りは、`2`、ターゲットと一致します。 

2 番目のサンプルの場合:```
6 7 2 4
```| ステップ | 州旗 | 値 mod N | 操作 |
 | --- | --- | --- | --- |
 | 0 | オリジナル | 2 | 開始 |

 初期値にはすでに必要な剰余が含まれているため、BFS はすぐに空のシーケンスを返します。

 の最大値`N`は 200 万であるため、グラフには最大 400 万の状態が含まれます。 アルゴリズムは、サイズへの依存を回避します。`A`または`M`、これが制約に適合するものです。 

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    A, M, B, N = map(int, sys.stdin.readline().split())

    base = A % M
    total = 2 * N
    parent = [-1] * total
    parent_op = [''] * total

    def gid(flag, rem):
        return flag * N + rem

    start = gid(0, A % N)
    q = deque([start])
    parent[start] = start
    ans = -1

    while q:
        cur = q.popleft()
        flag = cur // N
        rem = cur % N

        if rem == B:
            ans = cur
            break

        for nf, nr, op in [
            (flag, (rem + M) % N, '+'),
            (flag, (rem - M) % N, '-'),
            (1, (rem * M) % N, '*'),
            (flag, base % N if flag == 0 else 0, '%')
        ]:
            nxt = gid(nf, nr)
            if parent[nxt] == -1:
                parent[nxt] = cur
                parent_op[nxt] = op
                q.append(nxt)

    if ans == -1:
        out = "-1"
    else:
        res = []
        while ans != start:
            res.append(parent_op[ans])
            ans = parent[ans]
        res.reverse()
        out = str(len(res)) + ("\n" + ''.join(res) if res else "")

    sys.stdin = old
    return out

assert run("1 3 2 5\n") == "2\n+*", "sample 1"
assert run("6 7 2 4\n") == "0", "sample 2"

assert run("5 6 1 6\n") == "-1", "impossible case"
assert run("0 6 3 7\n") == "3\n---", "negative moves are useful"
assert run("5 9 1 8\n") == "3\n*%+", "multiplication changes modulo M state"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 3 2 5`|`2`オペレーション | 基本的な最短経路の再構成 |
 |`6 7 2 4`|`0`オペレーション | すでに条件を満たしています |
 |`5 6 1 6`|`-1`| 到達不可能な状態の検出 |
 |`0 6 3 7`|`3`オペレーション | 繰り返しの減算と境界剰余 |
 |`5 9 1 8`|`3`オペレーション | 正しい取り扱い`%`後`*`|

 ## 特殊なケース

 開始値がすでに条件を満たしている場合、BFS は直ちに返さなければなりません。 入力の場合:```
6 7 2 4
```最初の余りは`6 mod 4 = 2`に等しい`B`したがって、空のシーケンスが最短の答えになります。 

いつ`%`乗算の後に使用されるモジュロ`M`状態はゼロです。 のために：```
5 9 1 8
```シーケンス`*%+`動作します。 乗算により隠れたモジュロが変更されます`M`値をゼロに、`%`画面をゼロに保ち、`+`残りをターゲットに移動します。 追跡のみ`A mod M`この道を逃してしまうだろう。 

答えが存在しない場合、BFS は到達可能なすべての圧縮状態を調査し、残りの部分には決して到達しません。`B`。 のために：```
5 6 1 6
```残留物を見つけることなく、すべての可能な状態が使い尽くされる`1`したがって、アルゴリズムは正しく出力します`-1`。
