 ## 解決策
 ## 問題の理解

 概念的に次のように分割された紙のストリップから始めます。$2^N$等しいセグメント。 アメリアの家は既知のセグメントインデックスにあります$P$。 ストリップは繰り返し折り畳まれます$N$回。 各折り目は現在のストリップを取得し、正確に中央で分割し、半分をもう一方の上に置きます。 各折り目の方向は私たちが制御できます。左半分が右半分の上に来るか、右半分が左半分の上に来るかのどちらかです。 

すべて折りたたむと、ストリップは次のスタックになります。$2^N$層。 元の各セグメントは、下から上への最終的なレイヤー位置で終了します。 タスクは、アメリアのホームを含むセグメントが最初の位置になるように折り方向のシーケンスを選択することです。$P$、正確な高さで終了します$H$最終スタックにあります。 

重要な部分は、各折り目がすべてのセグメントをランダムに並べ替えるわけではないということです。 代わりに、2 つの半分を決定論的に再配置し、これにより再帰的な構造が誘発されます。すべての折り目で、間隔がどのように反転され、積み重ねられるかが洗練されます。 この問題は本質的に、1 つのインデックスをあるサイズにマップするバイナリ決定パスを構築することを求めています。$2^N$一連の制御された反転後の目標ランクまでの間隔。 

制約$N \le 60$がキー信号です。 サイズの設定スペース$2^N$は天文学的に大きいため、すべてのセグメントにわたるシミュレーションやストリップの明示的な構築は不可能です。 ストリップを明示的に表現することさえ問題外です。 ソリューションは次の条件で機能する必要があります$O(N)$、おそらくビットレベルの推論または間隔変換の再帰的マッピングを使用します。 

折り目の向きがどのように反転するかによって、微妙な問題が発生します。 すべてのセグメントの位置を層ごとに追跡する単純なシミュレーションは、各折り目が半分の内部の相対的な順序を逆転させることを無視するため、簡単に失敗する可能性があり、この影響はレベル全体にわたって増大します。 もう 1 つのよくある落とし穴は、プロセスを構造化された反転のバイナリ ツリーとしてではなく、レイヤーの独立した挿入として扱うことです。 

たとえば、小さなものでは、$N = 2$、フォールドの選択に応じてポジションが単調に上向きに移動すると仮定するかもしれません。 実際には、セグメントは、各ステージで左半分にあるか右半分にあるか、また積み重ねる前にその半分が反転されるかどうかに応じて、上または下に移動する可能性があります。 単純な欲張りシミュレーションでは、方向の反転を追跡できないため、最終的なレイヤーの位置を誤って予測します。 

## アプローチ

 強引な解釈では、ストリップを明示的にシミュレートします。 各ステップで、セグメントの現在のリストを 2 つの半分に分割し、左を右に反転したもの、または右を左に反転したものを追加します。 各ステップで構造サイズが 2 倍になるため、$N$私たちが持っているステップ$2^N$要素。 この構造を表現するだけでもコストがかかる$O(2^N)$、そしてパフォーマンス$N$変革は～につながる$O(N \cdot 2^N)$、それはすでに不可能になります$N = 60$。 

重要な観察は、完全な構造は決して必要ないということです。 追跡する必要があるのは 1 つのセグメントのみです。$P$、最終的な位置を決定します$H$。 それぞれの折り目は、間隔がどのように含まれるかを示すだけです。$P$分割されて反転されます。 順列全体を構築する代わりに、再帰的なバイナリ パーティションを通じて単一のインデックスを追跡します。 

各ステップでのサイズの間隔$2^k$サイズが半分に分かれています$2^{k-1}$。 フォールドの選択により、左半分が新しいスタックの上半分になるか下半分になるかが決まります。 これにより、ターゲット セグメントのインデックスに決定論的な変換が行われ、最終的なスタック位置への最終的な影響が生じます。 

プロセスを逆にすることもできます。前方への折りをシミュレートする代わりに、最終位置を解釈します。$H$バイナリで再構築し、どのフォールドの決定が必要となるか$P$その位置にマップされます。 各ステップは、ターゲット高さの現在のビットが上半分または下半分からのビットに対応するかどうか、および反転が必要かどうかを効果的に決定します。 

これにより、照合中に区間のバイナリ分解をたどることに問題が軽減されます。$P$リーフに追加し、同時にその最終的な深さが等しいことを強制します$H$。 一意性の保証は、各ステップが一貫性を維持する有効な方向を 1 つだけ持つことを意味します。

 ## アルゴリズムのチュートリアル

 このプロセスを、現在の間隔を繰り返し分割し、その分割に対してターゲット位置がどこにあるかを決定するものとして扱います。 最終的なスタック位置はバイナリでエンコードされ、各フォールドは構造の 1 ビットの解決に対応します。 

### ステップ

 1. 問題を位置の追跡として解釈します$P$通り抜ける$N$バイナリ分割。 各分割では、現在のセグメント範囲が左半分と右半分に分割されます。 折り方向によって、左が右の上になるか、その逆になるかが決まります。 
2. 現在の間隔を維持する$[l, r]$どのセグメント範囲を追跡しているかを表します。 当初は、$l = 1$、$r = 2^N$、 そして$P$中のどこかに眠っています。 
3. 各ステップで中点を計算します。$m = (l + r) / 2$。 かどうかを決定します$P$左半分にあります$[l, m]$もしくは右半分$[m+1, r]$。 この選択により、再帰でどちらの側に従うかが決まります。 
4. 同時に希望する最終高さを検討します。$H$。 それぞれのレベルで、$H$積層順序に対応する構造化された間隔にもあります。 かどうかを判断します。$H$現在のフォールドによって形成される上部または下部のブロックに対応します。 
5. 折り目の選択は一貫性によって強制されます。左を右に配置すると、含まれる側が整列する場合は「L」を選択します。$P$到達するために必要な側で$H$それ以外の場合は「R」を選択します。 
6. 間隔を半分に更新します。$P$、すべて続くまで続けます$N$折り目が決まります。 

### なぜ効果があるのか

 各フォールドは、セグメントの間隔のバイナリ分割を誘発し、同時に最終的なスタック位置のバイナリ分割を誘発します。 このシステムは、リーフが元のセグメントに対応し、ルートからリーフへのパスがフォールドの決定に対応する完全なバイナリ ツリーです。 各折り目は 2 つの半分を内部で混合することなく交換するだけなので、各半分の内部の相対的な構造はそのまま残ります。 これにより、あらゆるレベルで、場所と場所の間に一貫した一意のマッピングが存在することが保証されます。$P$そして目標の高さ$H$したがって、貪欲なローカル決定はグローバルに有効なままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, P, H = map(int, input().split())
    
    # We simulate intervals of size 2^k.
    l, r = 1, 1 << N
    p = P
    h = H
    
    ans = []
    
    for _ in range(N):
        mid = (l + r) // 2
        
        # determine which half P is in
        if p <= mid:
            p_side = 0  # left
        else:
            p_side = 1  # right
        
        # determine which half H is in
        if h <= mid:
            h_side = 0  # bottom half in current view
        else:
            h_side = 1  # top half in current view
        
        # If we fold left over right (L):
        # left becomes top, right becomes bottom
        # so left -> top, right -> bottom
        #
        # If we fold right over left (R):
        # right becomes top, left becomes bottom
        
        # We choose fold so that p_side ends up consistent with h_side
        # under stacking transformation.
        
        if p_side == h_side:
            ans.append('L')
        else:
            ans.append('R')
        
        # update interval to the side containing P
        if p_side == 0:
            r = mid
        else:
            l = mid + 1
    
    print("".join(ans))

if __name__ == "__main__":
    solve()
```実装では、次の不変条件が維持されます。$[l, r]$常に元の位置が含まれます$P$、ステップごとに間隔を半分に縮めます。 決定ルールは両方の側を比較します$P$そして目標の高さ$H$は現在のレベルに位置し、それらの相対的な方向を揃える折り目を選択します。 フォールド文字はローカルで決定されますが、間隔更新により、再帰的分解との一貫性が常に保たれます。 

主な微妙な点は、中間点パーティションが空間セグメンテーションとスタッキング構造の両方を同時に表すことです。 それらを同一のバイナリ分割として扱うことで、アルゴリズムがスタックの明示的なシミュレーションを回避できるようになります。

 ## 特殊なケース

 主なエッジケースは次のような場合です$P$そして$H$異なる半分で開始されますが、いくつかの分割を経た後でのみ、最終的な分割の同じセグメントに収束します。 たとえば、$N = 3$、$P = 6$、$H = 3$、最初の分割によりそれらがすぐに分離され、方向を早い段階で反転する折りの選択が強制されます。 アルゴリズムは、グローバル アラインメントを想定するのではなく、常に現在の間隔サイズでサイド メンバーシップを比較するため、これを処理します。 

もう一つのケースは次のような場合です。$P = H$、ターゲット分節はすべてのレベルで整列したままにする必要があります。 このような場合、アルゴリズムは一貫して次のことを確認します。$p\_side = h\_side$すべてのステップで、均一な一連の折り目が生成されます。 これは、バイナリ分解ツリーを下る単調なパスに対応し、間隔の更新では常に次の不変条件が維持されるため、矛盾は生じません。$P$追跡されるセグメント範囲内に留まります。 

最後に、次のような境界ケース$P = 1$または$P = 2^N$更新間隔を強調します。 中間点は整数の除算として計算されるため、左半分には常に低いインデックスが含まれ、右半分には高いインデックスが含まれ、間隔を縮小するときに 1 ずつずれた曖昧さがなくなります。
