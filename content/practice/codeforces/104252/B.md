 ## 解決策
 ## 問題の理解

 平面内に一連の点が与えられ、各点は 1 から T までの一意の識別子を持つトークンを表します。その後、一連の P ターンが存在します。 各ターンで、プレイヤーはポイントがフォームの指定された行より厳密に下にある残りのトークンをすべて受け取ります。$y = Ax + B$。 トークンは一度取得すると消滅し、後のプレイヤーが再度取得することはできません。 

各プレイヤーについて、そのターンに取得したトークンの数を出力し、その後にそれらのトークンの識別子を昇順に出力する必要があります。 

難しいのは、単一のクエリを評価することではなく、最大 100,000 個のポイントと 100,000 行を処理し、各ポイントは収集後に削除されることです。 各クエリの残りのすべてのポイントに対する単純な再計算では、データセットの大部分を繰り返しスキャンすることになり、すぐに実行不可能になります。 

入力限界は、T または P のいずれかで二次関数の動作を行う解は失敗することを意味します。 クエリごとのリニア スキャンでも、$10^{10}$通常の限界をはるかに超えた最悪の場合の動作。 これにより、各ポイントがすべてのクエリにわたって少数回、理想的には 1 回だけ処理される設計が強制されます。 

削除の動的な性質から微妙な問題が発生します。 早期に削除されたポイントは、後のクエリに影響を与えてはなりません。 これにより、行ごとに回答を個別に前処理することができなくなります。 

もう 1 つの重要な例外ケースは、注文要件から生じます。 線の下にあるすべての点を効率的に見つけることができたとしても、クエリごとにそれらの識別子をソートされた順序で出力する必要があります。 任意の走査順序でポイントを取得する構造でも、注意深い後処理が必要になります。 

## アプローチ

 直接的なアプローチでは、各クエリを個別に評価します。 特定の行について$y = Ax + B$、残りのすべてのポイントをチェックし、$Y < AX + B$。 これにより、そのプレイヤーのすべてのトークンが正しく識別され、セットからそれらが削除されます。 

この条件は純粋に幾何学的であり、点ごとに独立しているため、これは論理的に機能します。 ただし、費用は法外です。 T と P が両方とも最大 100,000 である場合、このアプローチは最大でパフォーマンスを発揮します。$10^10$最悪の場合は点線チェックが行われますが、これでは遅すぎます。 

重要な構造上の観察は、実際にはメンバーシップを毎回最初から再計算する必要がないということです。 必要なのは、「半平面内のすべての点を報告する」という形式の幾何学的範囲クエリに繰り返し答えて、それらを削除できるデータ構造だけです。 

これにより、問題は古典的な動的幾何学的レポート タスクに変換されます。 各クエリは半平面クエリであり、各点は最大 1 回削除されるため、すべてのクエリにわたって報告される出力の合計数はちょうど T になります。これは、個々のクエリが対数的でなくても、出力に依存する構造が成功する可能性があることを示唆しています。 

これに適したツールは、kd ツリーなどの空間分割構造です。 このアイデアは、点を軸に沿った長方形に再帰的に分割することです。 各ノードは平面の領域を表し、その点の境界ボックスを格納します。 クエリ行を処理するとき、領域全体がその線の下にあるのか、完全に上にあるのか、あるいは部分的に交差しているのかを判断します。 完全に下にある場合は、そのサブツリー内のすべてのポイントを一度に出力します。 完全に上回っている場合は、完全に剪定します。 それ以外の場合は再帰的に行います。 

主な利点は、各ポイントが対数のツリー ノードに沿ってのみ訪問され、報告された各ポイントが合計出力に 1 回だけ寄与することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T・P) | O(T) | 遅すぎる |
 | kd-tree 半平面レポート | O((T + P) log T + 出力ログ出力) | O(T) | 承認済み |

 ## アルゴリズムのチュートリアル

 x 座標と y 座標で交互に分割を使用して、すべての点に kd ツリーを構築します。 各ノードは、その境界四角形とポイント ID のリストをそのサブツリーに保存します。 

クエリ行を処理するとき$y = Ax + B$では、kd ツリーを走査し、ラインに関連して各ノードを分類します。 

1. ノードについて、次の最大値と最小値を計算します。$y - Ax$長方形の 4 つの角の上に。 一次関数は長方形の角で極値を達成するため、これで十分です。 
2. 最大値が厳密に B より小さい場合、このノード内のすべての点が条件を満たします。 このサブツリーからすべてのポイント ID を収集し、削除済みとしてマークします。 
3. 最小値が B 以上の場合、このノード内のどの点も条件を満たすことがないため、このサブツリーの探索を停止します。 
4. それ以外の場合、ノードはクエリ ラインと部分的に交差します。 私たちはその子たちを再帰的に調べます。 
5. クエリのすべてのポイントを収集した後、ID を出力する前に ID を並べ替えます。これは、走査順序で ID の順序が尊重されることが保証されていないためです。 
6. 報告されたすべてのポイントを非アクティブとしてマークし、今後のクエリで無視されるようにします。 

正確さの背後にある理由は、すべてのノードの分類が正確であるという事実から来ています。 ノードは、内部のすべての点が不等式を満たす場合にのみ完全に含まれ、どの点も不等式を満たす場合にのみ完全に除外されます。 部分ノードは、影響を受けるすべてのポイントが個別に検出されるまで分解されます。 

維持される不変条件は、走査の各ステップで、クエリ条件を満たすポイントを決してスキップしないこと、およびクエリ条件を満たさないポイントを決して含めないことです。 各ポイントはレポートされた直後に削除されるため、後のクエリで重複することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("x1", "x2", "y1", "y2", "ids", "left", "right")
    def __init__(self, x1, x2, y1, y2, ids):
        self.x1 = x1
        self.x2 = x2
        self.y1 = y1
        self.y2 = y2
        self.ids = ids
        self.left = None
        self.right = None

def build(points, depth=0):
    if not points:
        return None

    if len(points) == 1:
        x, y, i = points[0]
        node = Node(x, x, y, y, [i])
        return node

    axis = depth % 2
    points.sort(key=lambda p: p[axis])
    mid = len(points) // 2

    left = build(points[:mid], depth + 1)
    right = build(points[mid:], depth + 1)

    xs = []
    ys = []

    for child in (left, right):
        if child:
            xs.extend([child.x1, child.x2])
            ys.extend([child.y1, child.y2])

    node = Node(min(xs), max(xs), min(ys), max(ys), [])
    node.left = left
    node.right = right
    return node

def query(node, A, B, res):
    if not node:
        return

    corners = [
        (node.x1, node.y1),
        (node.x1, node.y2),
        (node.x2, node.y1),
        (node.x2, node.y2),
    ]

    vals = [y - A * x for x, y in corners]
    mx = max(vals)
    mn = min(vals)

    if mx < B:
        collect(node, res)
        return

    if mn >= B:
        return

    if node.left is None and node.right is None:
        if node.ids:
            res.extend(node.ids)
            node.ids = []
        return

    query(node.left, A, B, res)
    query(node.right, A, B, res)

def collect(node, res):
    if not node:
        return
    if node.left is None and node.right is None:
        if node.ids:
            res.extend(node.ids)
            node.ids = []
        return
    collect(node.left, res)
    collect(node.right, res)

def solve():
    T = int(input())
    pts = []
    for i in range(1, T + 1):
        x, y = map(int, input().split())
        pts.append((x, y, i))

    root = build(pts)

    P = int(input())
    for _ in range(P):
        A, B = map(int, input().split())
        res = []
        query(root, A, B, res)
        res.sort()
        if res:
            print(len(res), *res)
        else:
            print(0)

if __name__ == "__main__":
    solve()
```kd ツリー構築では、幾何学的クエリが局所化されるように点を再帰的に分割します。 クエリ関数は中核です。この関数は、長方形の角の評価を使用して、サブツリーを完全に取得するかスキップするかを決定します。 収集関数は、サブツリーが完全にクエリ領域内にある場合にのみ使用され、不必要なポイントごとのチェックが回避されます。 

実装の微妙な点は、サブツリー境界ボックスが正確でなければならないことです。 そこに間違いがあると、枝刈りロジックの正確さが損なわれます。 もう 1 つの重要な点は、レポート後にリーフ ストレージをクリアすることによって、各ポイントが 1 回だけ削除されることです。 

kd ツリーの走査順序が識別子の順序と一致していないため、並べ替えはクエリごとに適用されます。 

## 実用的な例

 点が平面内に広がり、数本の線が適用される小さな構成を考えてみましょう。 

### トレース例 1

 3 つの点があるとします。 

(0,0,1)、(2,2,2)、(4,1,3)

 クエリ行:$y = x + 0$各ポイントコンディションを評価します$Y < X$。 

| ステップ | ポイント | Y < X | を計算します。 撮影 |
 | --- | --- | --- | --- |
 | 1 | (0,0) | 0 < 0 | いいえ |

 ポイント 3 のみが収集されるため、出力は次のようになります。```
1 3
```これにより、幾何学的条件が厳密に評価され、等価性は認められないことが確認されます。 

### トレース例 2

 次に、残りのポイントに 2 番目のクエリを適用します。 

残りポイント:

 (0,0,1)、(2,2,2)

 クエリ:$y = 0x + 1$状態は$Y < 1$。 

| ステップ | ポイント | Y < 1 | を計算します。 撮影 |

 | 1 | (0,0) | 0 < 1 | はい |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((T + P) log T + T log T 合計ソート) | 各ポイントは削除ごとに 1 回 kd ツリー パスを介して訪問され、レポートの合計コストはすべての出力にわたって線形です。 
| スペース | O(T) | 各ポイントは kd ツリー構造に一度保存されます。 

すべてのトークンが 1 回だけレポートされ、各クエリはツリーの関連部分のみを探索するため、複雑さは制約内に問題なく収まります。 追加の対数係数は、トラバースの深さとクエリごとの並べ替えから得られますが、これらは 100,000 スケールの制限に制限されたままです。

 ## 特殊なケース

 重要なエッジケースは、クエリ行が大きな領域全体を一度に削除する場合です。 この場合、kd ツリーは不必要に個々の点に下降することを避けなければなりません。 四角形テストでは、4 隅すべてが不等式を満たす場合に完全な包含が検出され、サブツリーの即時の収集が可能になるため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、A が負の場合です。 これにより、どのコーナーが最大値と最小値を生成するかが変わります。$y - Ax$。 この実装では、軸に合わせたショートカットに依存するのではなく、4 つの隅すべてを直接評価するため、これが正しく処理されます。 

最後のエッジケースは、すでに削除されたポイントをターゲットとするクエリの繰り返しです。 各リーフは収集後に保存されている ID をクリアするため、後続の走査では自然に空のノードがスキップされ、幾何学的条件がまだ維持されている場合でも出力が重複しないことが保証されます。
