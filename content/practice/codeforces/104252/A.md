 ## 解決策
 ## 問題の理解

 N 人がいる有向グラフが与えられます。各人 i は、お金を要求する人を指すちょうど 2 つの外向きのエッジを持っています。 このプロセスは、部外者が町内の誰かを選んでお金を要求することから始まります。 その人は、最初に要求されたときにすぐに 1 ドルを渡し、その後その要求を 2 人の隣人に転送します。 すべての人は同じように行動します。受信した最初のリクエストにのみ反応し、それ以降のリクエストはすべて無視します。 

この伝播が始まると、有向グラフを通じて連鎖反応が展開されますが、各ノードが「アクティブ化」されるのは 1 回だけです。 アクティブ化されると、2 つの出力エッジに沿ってプロセスを前進させます。 

この質問は、すべての人に対して、その人が最終的にプロセスに参加することになる、つまり到達して 1 ドルを失うような有効な開始選択肢が存在するかどうかを尋ねます (部外者は、任意の 1 人に尋ねることから始めることができます)。 

したがって、タスクは単一の固定スタートをシミュレートすることではありません。 代わりに、最初のノードの選択から開始して、考えられる伝播でどのノードに到達できるかをチェックしています。 

N ≤ 1000 という制約は、O(N²) または O(N³) グラフ アルゴリズムが実行可能であることを意味します。 これにより、すべての開始ノードにわたる指数関数的なシミュレーションのようなものは排除されますが、グラフの走査、SCC 分解、またはマルチソース到達可能性の推論が可能になります。 

いくつかの微妙な状況が重要です。 まず、ノードは、サイクルを通じて再訪問する連鎖反応を開始できるどのノードからも到達できない可能性があります。 たとえば、行き止まりにのみつながるグラフの領域 (非循環シンク構造) にノードが配置されている場合、開始者をどのように選択しても、伝播はその領域に入ることはありません。 第 2 に、サイクルが重要であるのは、サイクルに入るとアクティベーションが循環し、最終的には到達可能な領域内の多くのノードに到達する可能性があるためです。 

単純なアプローチでは、潜在的な開始点としてすべてのノードから開始するプロセスをシミュレートし、「一度だけアクティブにする」ルールに従って毎回 BFS/DFS を実行します。 これは作業量を N 倍にし、およそ O(N²) 回のグラフ走査になりますが、これは境界線にありますが、まだ管理可能です。 ただし、これは、到達可能性の構造がグローバルであり、一度だけ事前計算できることを無視しています。 

## アプローチ

 重要な観察は、伝播ルールは本質的に、「一度訪問」制約を持つ有向グラフ上の到達可能性プロセスであるということです。 この制約は、標準の到達可能性推論を妨げるものではありません。ノードに到達すると、そのノードは決定論的に動作し、以前のノードを永続的にブロックしないからです。 

ブルートフォース解釈では、考えられるすべての開始ノードを試し、キューを使用して伝播をシミュレートし、訪問したすべてのノードをマークします。 次に、訪問したすべてのセットの和集合を取得します。 各シミュレーションのコストは O(N + M) で、開始点が N 個あるため、最悪の場合の複雑さは O(N(N + M)) になります。これは、M = 2N であるため、約 O(N³) になります。 最悪のケースを想定すると、これでは遅すぎます。 

この改善は、実際にはどの開始ノードが到達可能性を生み出したかを知る必要がないことに気づいたことから来ています。 最終的に特定のノードに到達できる開始ノードが存在するかどうかだけを気にします。 これは、少なくとも 1 つのサイクル関連の開始領域から到達可能なグラフの領域にノードが存在するかどうかを尋ねることと同じです。 

これをより明確に考えるには、強く接続されたコンポーネントを使用することです。 SCC 内では、1 つのノードがアクティブ化されると、その SCC 内のすべてのノードが伝播パスを通じて相互に到達できます。 さらに、サイクルを形成する SCC は、伝播が無限に循環できる唯一の場所です。 このような周期的 SCC に到達できるノードは、上流で適切な開始ノードを選択することによってアクティブ化できます。

したがって、問題は、循環しているすべての SCC (サイズ > 1 または自己ループのいずれか) を見つけて、「グラフのどこから開始しても影響を受ける可能性がある」という逆の意味で、これらの SCC のいずれかに到達できるすべてのノードをマークすることに帰着します。 開始ノードに制限がないため、最終的にサイクリック SCC に流入できるすべてのノードが有効になります。 

O(N + M) で Kosaraju または Tarjan を使用して SCC を計算します。 次に、SCC の凝縮グラフを構築し、循環コンポーネントから逆方向に伝播して、それらに到達できるすべてのノードをマークします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各開始からのブルート フォース シミュレーション | O(N(N + M)) | O(N) | 遅すぎる |
 | SCC + 循環コンポーネントからの到達可能性 | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、サイクルが原子単位になるように、グラフを強く接続されたコンポーネントに圧縮します。 

1. グラフの強接続成分をすべて計算します。 各ノードにはコンポーネント ID が割り当てられます。 このステップでは、有向パスの下で相互に到達するノードをグループ化します。 
2. どのコンポーネントが循環しているかを特定します。 コンポーネントに複数のノードが含まれている場合、またはノードがそれ自体にエッジを持っている場合、コンポーネントは循環的です。 これらはまさに、伝播がループし、グループ内で無限に広がり続ける可能性があるコンポーネントです。 
3. 凝縮されたコンポーネント グラフを作成します。 各 SCC は単一のノードになり、元のエッジがコンポーネントを接続している場合は、コンポーネント間に有向エッジを追加します。 
4. この圧縮されたグラフの方向を反転します。 この逆転により、受信依存関係を通じて「最終的にサイクルにつながる可能性がある」ことを逆方向に伝播することができます。 
5. 逆圧縮グラフ内のすべての循環コンポーネントから BFS または DFS を同時に開始します。 このプロセスで到達したすべてのコンポーネントには、「順方向のサイクルに到達できる」とマークされます。 
6. コンポーネントがマークされている元のノードをすべてマークします。 これらはまさに、適切な初期選択から始まる何らかの伝播シナリオに関与できる人々です。 

これが機能する理由は、SCC が内部の相互到達可能性をすべてキャプチャし、エッジを反転することで「到達可能サイクル」が既知のソースからの単純な到達可能性の問題に変換されるためです。 

### なぜ効果があるのか

 各ノードは、循環 SCC 内に存在するか、最終的に循環 SCC に流入するか、そうでないかのいずれかになります。 ノードが周期的 SCC に到達できる場合は、上流の開始ノードを選択して、伝播が最終的にその SCC に入り、ノードをアクティブ化する方法でグラフ内を継続するようにすることができます。 どの循環 SCC にも到達できない場合、そこからのすべてのパスは非循環領域で終了し、そこで伝播は最終的に消滅します。つまり、開始ノードを選択しても、依存関係構造内のそのノードの位置を介して持続的な伝播をもたらすことができません。 したがって、周期的 SCC への到達可能性は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, rg):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in rg[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    edges = []
    for i in range(n):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[i].append(x)
        g[i].append(y)
        rg[x].append(i)
        rg[y].append(i)

    comp, cid = kosaraju(n, g, rg)

    comp_size = [0] * cid
    has_self = [False] * cid

    for i in range(n):
        comp_size[comp[i]] += 1
        for j in g[i]:
            if j == i:
                has_self[comp[i]] = True

    cyclic = [False] * cid
    for i in range(cid):
        if comp_size[i] > 1 or has_self[i]:
            cyclic[i] = True

    cg = [[] for _ in range(cid)]
    rcg = [[] for _ in range(cid)]

    for i in range(n):
        for j in g[i]:
            if comp[i] != comp[j]:
                cg[comp[i]].append(comp[j])
                rcg[comp[j]].append(comp[i])

    from collections import deque
    q = deque()
    good = [False] * cid

    for i in range(cid):
        if cyclic[i]:
            q.append(i)
            good[i] = True

    while q:
        v = q.popleft()
        for to in rcg[v]:
            if not good[to]:
                good[to] = True
                q.append(to)

    res = []
    for i in range(n):
        res.append('Y' if good[comp[i]] else 'N')

    print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず元のグラフと逆グラフの両方を構築し、Kosaraju のアルゴリズムを使用して強結合成分を計算します。 その後、各ノードはそのコンポーネントを表すものに圧縮されます。 

次に、コンポーネントに複数のノードまたは自己ループが含まれる場合、コンポーネントを循環として分類します。 このようなコンポーネントのみが繰り返しのアクティベーション フローを維持できるため、これは非常に重要です。 

次に、反転コンポーネント グラフを構築し、すべての循環コンポーネントからマルチソース BFS を実行します。 これは、順方向に移動したときに最終的にサイクルにつながる可能性のあるすべてのコンポーネントをマークします。 

最後に、各ノードはそのコンポーネントのステータスを継承します。

 ## 特殊なケース

 微妙なケースとしては、ノード自体がサイクル内にないものの、サイクリック SCC へのパスがあるノードがあります。 たとえば、1 → 2 → 3 および 3 がサイクルの一部である場合、1 と 2 もマークする必要があります。 巡回 SCC からのリバース BFS が両方の先行者をマークするため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは自己ループ ノードです。 それ自体にエッジを持つノードはサイズ 1 のサイクルを形成するため、循環として扱う必要があります。 SCC 分類はこれを明示的にチェックし、そのようなノードが BFS を正しくシードすることを保証します。 

最後のエッジ ケースは、純粋に非周期的な領域内のノードです。 発信エッジがある場合でも、すべてのパスがサイクルに入らずに最終的に終了する場合、リバース BFS は到達しません。 これにより、そのようなノードに対して「N」が正しく生成されます。
