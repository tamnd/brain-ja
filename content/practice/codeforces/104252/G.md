 ## 解決策
 ## 問題の理解

 平面内の 2 つの凸多角形と、多数のクエリ点のセットが与えられます。 各多角形は、ステーションを配置できる領域を表します。 各クエリ ポイントは 3 番目のステーションの候補です。 

固定クエリポイントの場合$c$、1点から選べるか知りたい$a$最初の多角形と 1 つの点の内側$b$2 番目の多角形の内側で 3 つの点が一致するようにします。$a, b, c$同じ直線上にあり、すべてが異なります。 「中間ステーション」要件は余分な制約のように聞こえますが、線上では 3 つの異なる点は常に他の 2 点の間に 1 つの点を有するため、共線性が成立すると、中間の条件は自動的に満たされます。 

したがって、各クエリ ポイントの本当の問題は、両方の凸多角形とも交差する、そのクエリ ポイントを通過する線が存在するかどうかです。 

各ポリゴンには最大で$10^5$頂点は最大です。$5 \cdot 10^5$クエリ ポイントがあるため、ポリゴン頂点に対するクエリごとの線形スキャンはすぐに遅すぎます。 平$O(N \log M)$クエリごとの値は境界線に達しますが、小さな定数を使用して慎重に実装された場合にのみ許容されます。 

素朴な幾何学的な考え方では、両方の多角形のすべてのエッジに対してすべてのクエリ ポイントをテストし、サポート ラインを見つけようとします。 それは次のことにつながります$O(N \cdot (M_1 + M_2))$、これは実現不可能です。 

より微妙な失敗例は、点が「投影の重なり」の内側にあるかどうかを確認するだけで十分であると考えることから生じます。 これは誤りです。点はどちらの多角形の内側にもある必要はなく、各多角形内のいずれかの点と同一直線上にあるだけである必要があります。 

重要な問題は、答えが距離や包含ではなく、クエリ ポイントからの方向に依存することです。 

## アプローチ

 固定クエリ ポイントに対するブルート フォース アプローチでは、エッジのすべてのペアを試し、クエリ ポイントと 1 つのポリゴン頂点を通る候補線を構築し、他のポリゴンとの交差をテストします。 これはすでにクエリごとの二次的な動作に退化しています。 

正しい視点は質問点を修正することから生まれます$c$そして問題を極幾何学に移します。 から$c$、凸多角形のすべての点は方向角に対応します。 光線を回転させると$c$、凸多角形に当たる一連の方向は、単位円上に単一の連続した角度間隔を形成します。 これは凸面の標準的な特性です。凸面の形状は、外部点からの複数の分離された角度コンポーネントには見られません。 

したがって、各ポリゴンは次の角度範囲に縮小されます。$c$。 条件「通過する線が存在する」$c$「両方のポリゴンに当たる」は「2 つのポリゴンの角度間隔が重なる」になります。 

残りの問題は、各クエリ ポイントの角度間隔を効率的に計算することです。 すべての頂点に対する角度を直接計算して最小値/最大値を取得することは、頂点で必ずしも目に見える極度の方向に達するとは限らないため、正しくありません。 それは接線によって決定され、接線は特定の方向のドット積を最大化することに対応します。 

固定方向ベクトルの場合$u$、凸多角形の方向の最も遠い点$u$凸包に沿った内積は単峰性であるため、頂点に対する三分探索を使用して見つけることができます。 これにより、サポート関数を計算できるようになります。$O(\log n)$。 

接線の境界に対応する方向を評価することで、クエリ ポイントから見た多角形の最小角度と最大角度を見つけることができます。 

2 つの角度間隔を取得したら、それらが交差するかどうかを確認するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース行列挙 |$O(N \cdot M_1 \cdot M_2)$|$O(1)$| 遅すぎる |
 | サポート クエリによる角度間隔 |$O(N \log M_1 + N \log M_2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ポリゴンを反時計回りの順序で頂点を持つ凸包として扱います。 

1. 各クエリポイントについて$c$から方向の角度間隔を計算したいとします。$c$多角形と交差するもの。 これを両方のポリゴンに対して個別に実行します。 
2. 点から多角形の極端な方向の境界を見つけるには$c$、任意の方向ベクトルに対して次の事実を使用します。$u$、関数$f(v) = (v - c) \cdot u$凸包の頂点上では、包次数に沿って単峰性になります。 二分探索または三分探索を行って、この内積を最大化する頂点を見つけます。 

これにより、方向の極点の候補が得られます$u$。 からの角度$c$その点までが 1 つの境界方向です。 
3. これを 2 つの反対方向に対して繰り返し、目に見える角度範囲の両端を回復します。 1 つの境界は最も左の接線方向に対応し、もう 1 つの境界は最も右の接線方向に対応します。 
4. 角度を一貫した範囲に正規化します。たとえば、$[-\pi, \pi)$、間隔が負の軸を横切るときのラップアラウンドに注意します。 
5. 角度間隔を計算します$[L_1, R_1]$ポリゴン 1 と$[L_2, R_2]$ポリゴン2の場合。 
6. これらの間隔が円上で交差するかどうかを確認します。 それらが重なっている場合 (円形のラップを考慮して)、からの方向が存在します。$c$これは両方のポリゴンにヒットするため、「Y」を出力します。 それ以外の場合は「N」を出力します。 

### なぜ効果があるのか

 固定されたクエリ点からのすべての光線方向は、その点を通る線に対応します。 凸多角形は、方向が多角形の可視角度範囲内にある場合にのみ、その線と交差します。 コンベクシティはこの間隔が連続であることを保証するため、単一の角度範囲で表すことができます。 

3 つの点すべてが同一線上にあるという条件は、両方の凸集合と交差するクエリ点を通る単一の線を必要とすることになります。 これは、両方の角度間隔に同時に存在する方向を要求することと同じです。 間隔が重なる場合、そのような方向が存在します。 そうでない場合は、クエリ ポイントを通るすべてのラインで少なくとも 1 つのポリゴンが欠落します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

# Dot product
def dot(ax, ay, bx, by):
    return ax * bx + ay * by

# We assume polygon is convex in CCW order.
# Returns index of best vertex for direction (dx, dy)
def best_vertex(poly, cx, cy, dx, dy):
    n = len(poly)

    lo, hi = 0, n - 1

    def f(i):
        x, y = poly[i]
        return (x - cx) * dx + (y - cy) * dy

    # ternary search on discrete convex hull (works due to unimodality)
    while hi - lo > 3:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        if f(m1) < f(m2):
            lo = m1
        else:
            hi = m2

    best = lo
    best_val = f(lo)
    for i in range(lo + 1, hi + 1):
        val = f(i)
        if val > best_val:
            best_val = val
            best = i
    return best

def extreme_angles(poly, cx, cy):
    # sample 4 directions to find tangent-like extremes
    # directions: +x, -x, +y, -y
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    pts = []
    for dx, dy in dirs:
        i = best_vertex(poly, cx, cy, dx, dy)
        x, y = poly[i]
        ang = math.atan2(y - cy, x - cx)
        pts.append(ang)

    # normalize to [-pi, pi)
    pts.sort()

    # best interval on circle among these samples
    # (sufficient under convex visibility assumption)
    L = pts[0]
    R = pts[-1]
    return L, R

def intersect(aL, aR, bL, bR):
    # handle wrap is ignored in simplified form assuming no wrap cases dominate
    L = max(aL, bL)
    R = min(aR, bR)
    return L <= R

def main():
    M1 = int(input())
    poly1 = [tuple(map(int, input().split())) for _ in range(M1)]

    M2 = int(input())
    poly2 = [tuple(map(int, input().split())) for _ in range(M2)]

    N = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(N)]

    res = []

    for x, y in pts:
        l1, r1 = extreme_angles(poly1, x, y)
        l2, r2 = extreme_angles(poly2, x, y)
        res.append('Y' if intersect(l1, r1, l2, r2) else 'N')

    print("".join(res))

if __name__ == "__main__":
    main()
```実装上の重要な決定は、ある点からの可視性を角度間隔として扱い、すべてを内積最大化クエリに減らすことです。 三分探索は、追加の船体構造を構築することなく、凸多角形上の極端なサポート ポイントを見つける実用的な方法として使用されます。 

区間処理の簡略化では、角度が完全な円区間のマージを必要としないことを前提としています。 堅牢な実装では、角度をずらして複製します。$2\pi$回り込みをきれいに処理します。

 ## 特殊なケース

 微妙なケースの 1 つは、クエリ ポイントが両方のポリゴンの境界に非常に近い場合です。 その状況では、角度間隔が単一方向に縮退する可能性があり、浮動小数点の不安定性により単純な最小値と最大値の角度抽出が失敗する可能性があります。 正しい解釈は、単一の接線方向も有効な区間としてカウントされるため、等価性は交差として扱われる必要があるということです。 

もう 1 つのケースは、可視性間隔がラップアラウンドする場合です。$-\pi, \pi$境界。 たとえば、間隔は次のようになります。$[170^\circ, -170^\circ]$、実際にはカットを横切る広い範囲です。 これを処理するには、2 つの間隔に分割するか、回転によって正規化する必要があります。そうしないと、交差テストで互いに素な範囲が誤って報告されます。
