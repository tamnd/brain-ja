 ## 問題の理解

 ターゲット文字列が与えられています`T`単純な印刷機で作成する必要があります。 マシンは任意のテキストを直接印刷しません。 代わりに、各命令は文字列で構成されます。`s`そして繰り返し回数`n`。 マシンは文字列を出力します`s`生成されるまで周期的に繰り返されます`n`文字。 

それで、もし`s = "abcd"`そして`n = 10`、出力は`"abcdabcdab"`。 出力内の各位置は以下にのみ依存します。`i mod |s|`。 

私たちのタスクは、指定された文字列を構築することです`T`いくつかのそのような命令の出力を連結することによって。 各命令には文字列という制限があります。`s`その命令で使用される長さは最大でも`D`。 命令の数を最小限に抑えたいと考えています。 

主な問題は、命令が文字を追加するだけでなく、周期的なパターンを生成することです。 したがって、1 つの命令で多くの文字をカバーできます。`T`周期構造が必要なものと一致する場合に限ります。 

制約により許可されるのは、`|T|`これにより、すべての部分文字列とすべての命令グループを直接試行する解決策は即座に除外されます。これは、すべての区間にわたる単純な分割は少なくとも 2 次以上になるためです。 

文字列に大きな繰り返し構造があるものの、わずかに位置がずれている場合、微妙なエッジ ケースが発生します。 

たとえば、次の場合`T = "abababxababab"`そして`D = 2`、文字が一致している間、常に現在の命令を拡張する貪欲なアプローチは、すべてを吸収しようとする可能性があります`"ab"`繰り返して、1回目で失敗する`x`、非効率的に再起動します。 正しい解決策は、周期セグメントが周期が安定している場合にのみ最大になることを認識します。 

もう 1 つのエッジケースは次のような場合です`D = 1`。 すべての命令文字列は単一の文字であるため、各命令は次のような均一なブロックを生成します。`"aaaaaa"`。 その場合、答えは単純に実行される文字の数です。`T`、異なる文字の数ではありません。 

## アプローチ

 ブルートフォースビューは、文字列を分割するという観点から考えることです。`T`セグメントに分割され、各セグメントが 1 つの命令に対応します。 位置から始まるセグメントの場合`i`可能な限りあらゆる長さを試します`L`、およびすべての可能な文字列`s`までの長さ`D`を繰り返しているかどうかを確認します`s`まさにそのセグメントを生成します。 これには、各候補セグメントの周期的制約の一貫性をチェックする必要があり、すでにコストがかかります`O(L)`小切手ごとに、`O(n^2)`セグメントと指数関数的に多くの候補パターンが含まれます。 直したとしても`s`最初のものを観察することで`D`文字の場合でも、セグメントを拡張すると二次走査が発生するため、このアプローチは実行可能な限界をはるかに超えています。 

重要な観察は、各命令が周期的なパターンを定義しており、我々が気にするのはプレフィックスの長さだけであるということです。`T`最大でも周期を含む単一の周期関数で説明できる`D`。 位置から始まる最長のプレフィックスがわかっている場合`i`1 つの命令で生成できる場合は、それを直接ジャンプできます。 これにより、問題は、最大の有効な周期的カバーを使用して文字列に沿って繰り返しジャンプすることに変換されます。 

中心となるアイデアは、あらゆる立場のコンピューティングになります`i`、最大`j ≥ i`部分文字列が`T[i:j]`何らかの周期的な文字列によって生成できます`s`せいぜい長さで`D`。 次に、これらの最大セグメントを貪欲に取得します。これは、有効な解決策は各命令をカバーされていない最も早い位置で開始する必要があり、命令が独立しているため、命令を可能な限り拡張しても問題がないためです。 

技術的な課題は、これを効率的にチェックする方法です。 すべてを試すのではなく`s`、固定セグメントの場合、有効な命令はすべてのオフセットに対して次のことを意味するという事実を利用します。`k`、位置の文字`i + k`そして`i + k mod |s|`同意する必要があります。 これは、ウィンドウ内で、ある期間を法として一致するすべての位置が一貫していなければならないことを意味します。 

各候補期間について、次の期間まで維持できます。`D`、セグメントの拡張が有効なままかどうか。 より効率的な観点は、セグメントが一定期間有効であるかどうかを認識することです。`p`、その後すべてのポジション`i`そして`i + p`セグメント内は一致する必要があります。 したがって、現在のアクティブなセグメントを維持し、次の期間までのすべての期間の一貫性を維持しながら拡張を試みることができます。`D`。 

これは貪欲なスキャンにつながります。現在のセグメントの開始を維持し、オフセット モジュロで競合が発生しないようにしながら、その終了を延長しようとします。`1..D`。 競合が発生すると、セグメントを閉じて新しい命令を開始します。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、貪欲に命令を構築します。 

1. 位置から開始`i = 0`。 これが最初の指導の始まりです。 セグメントの拡大に​​努めます`[i, r)`可能な限り。 
2. 開始位置が固定の場合`i`、現在のセグメントが最大でも一定の長さの周期的な文字列によって生成できることを保証する有効性構造を維持しようとします。`D`。 具体的には、有効期間内で一致する必要があるポジション間の一貫性制約を追跡します。 
3. ポインタを拡張します`r`から`i`右の方へ。 キャラクターの追加を検討する場合`T[r]`、位置によって引き起こされる周期的制約に違反しているかどうかを確認します。`r - p`のために`1 ≤ p ≤ D`。 もしあれば`T[r] != T[r - p]`関連する強制アライメントの場合、現在の命令をさらに拡張すると、周期的な一貫性が損なわれます。 
4. 競合が検出されない場合は、`r`現在の指示に戻って続行します。 
5. 競合するか文字列の終わりに達したら、カバーする 1 つの命令を終了します。`[i, r)`、答えをインクリメントし、設定します`i = r`新しい指導を開始します。 

これが機能する理由は、すべての命令が単一の周期構造に対応する必要があるためです。 考えられるすべての期間に対して不一致が発生すると、`D`、有効な命令は、周期性に違反せずにその位置を含めることはできません。 つまり、貪欲なカットは単に便利なだけでなく、強制されます。 

不変条件は、現在のセグメントが`[i, r)`常に少なくとも 1 つの最大長の周期文字列で表現可能`D`。 この不変条件を維持しながら拡張するだけであり、考えられるすべての期間の選択に対して違反する時点を正確にカットします。 これにより、各セグメントが実現可能性の下で最大であることが保証され、最大実現可能セグメントは、各セグメントが独立して構造的制約を満たさなければならないシーケンスのパーティション内のセグメントの数を最小限に抑えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    line = input().strip().split()
    T = line[0]
    D = int(line[1])
    n = len(T)

    # last occurrence tracking per offset pattern is not needed explicitly,
    # we maintain compatibility checks with a sliding window idea.
    # We use a simple greedy check with an array storing last D characters
    # for periodic validation.

    ans = 0
    i = 0

    while i < n:
        ans += 1
        # start new segment
        seen = [{} for _ in range(D + 1)]
        # seen[p][k] = character at position congruent k mod p in current segment

        r = i
        ok = True

        while r < n and ok:
            c = T[r]
            # try to place r into any period structure up to D
            ok = False

            for p in range(1, D + 1):
                k = r % p
                if k in seen[p]:
                    if seen[p][k] != c:
                        continue
                seen[p][k] = c
                ok = True
                break

            if ok:
                r += 1

        i = r

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは貪欲なセグメンテーションを実装しています。 外側のループは各命令を開始します。 各セグメントについて、考えられるすべての周期の長さについて、候補となる周期的解釈のファミリーを維持します。`D`。 新しいキャラクターごとに、これらの期間バケットの少なくとも 1 つに一貫して割り当てようとします。 文字に対応できるピリオド割り当てがない場合は、現在のセグメントを終了する必要があります。 

微妙な点は、`seen`各命令は独立しているため、セグメントごとに構造が異なります。 内部のロジックにより、少なくとも 1 つの期間仮説が一貫している間のみ拡張されます。 

正しさは、有効な命令が少なくとも 1 つの一貫した期間の解釈を許可する必要があり、すべての解釈が失敗すると、拡張は不可能になるという事実によって決まります。

def run(inp: str) -> str:

 ## 特殊なケース

 重要なエッジ ケースは、文字列が完全に周期的であるにもかかわらず、最適なセグメンテーションが有効な期間を早期に認識できるかどうかに依存する場合です。 のために`T = "abababab", D = 2`の場合、アルゴリズムは期間 1 と期間 2 の両方を実行可能に保ちますが、期間 2 は文字列全体で一貫性を保つため、セグメントは決して壊れず、答えは 1 になります。 

もう 1 つのエッジケースは次のような場合です`D`は大きいですが、文字列に繰り返しがありません。 のために`T = "abcdef", D = 6`、すべての新しいキャラクターは最終的に、些細な仮説を除くすべての時代仮説を破り、各キャラクターを独自の指示にすることを強制します。 アルゴリズムは、有効な期間割り当てがなくなるとすぐにこれを検出し、不必要なスキャンではなく即時カットを保証します。 

最後のエッジケースは、次のような中断を伴う交互構造です。`"ababaxababa"`。 ミスマッチの瞬間`x`が表示されると、一貫性に依存するすべての周期解釈が同時に崩壊し、最適性にとって不可欠な中断点で正確にカットを強制されます。
