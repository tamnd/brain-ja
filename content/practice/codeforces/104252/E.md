 ## 解決策
 ## 問題の理解

 1×N のボードと、1 から N までの長さのセグメント タイルのコレクションが与えられます。最初は、長さ K の 1 つのタイルがすでにボード上のどこかに配置されており、その左側にちょうど E 個の空のセルが残されています。 この配置により、占有間隔が固定され、配置されたタイルの両側にどれだけの空きスペースが残るかが暗黙的に固定されます。 

この初期構成の後、残りのタイルの任意のサブセットを配置できます。 各タイルは整数の長さの連続したセグメントであり、ボード内に完全に収まる必要があり、タイルが重なることはできません。 目的は、覆われたセルの総数を最大化することです。これは、タイルを最適に配置した後に覆われていないセルの数を最小限に抑えることと同じです。 

重要な点は、基板は単一のラインであるため、最適なソリューションの構造は、空間配置の複雑さではなく、残りの空きスペースにセグメントをどのように詰め込むかによって完全に決定されるということです。 すべてのタイルは単なる長さであり、配置は、利用可能な空きスペースを、長さが選択したタイル サイズと一致する必要がある不連続な間隔に分割することに相当します。 

制約は小さく、N は最大 1000 です。これにより、タイルまたは位置に対する指数サブセットの列挙が即座に除外されます。これは、どちらも実現可能性をはるかに超えて 2^1000 または N! に達するためです。 O(N^2) または O(N^2 log N) のアプローチは受け入れられますが、O(N^3) でさえ合格する可能性がありますが、その必要はありません。 

最初の K タイルが境界に近い場合、特に E が 0 に等しい場合、または E が N-K に近い場合、微妙なエッジ ケースが発生します。 たとえば、N = 6、K = 2、および E = 2 の場合、タイルはセル 3 ～ 4 を占有し、サイズ 2 と 2 の 2 つの空きセグメントが残ります。ボードをサイズ N-K の単一の連続した空きセグメントとして扱う単純なアプローチでは、タイルが固定ブロックを飛び越えることができないため、これら 2 つの領域が誤ってマージされ、パッキング能力が過大評価されてしまいます。 

もう 1 つの例外的なケースは、K = 1 の場合です。最初のタイルは自明ですが、それでもボードをサイズ E と N-E-1 の 2 つのセグメントに分割し、分割を忘れると、誤った貪欲なパッキングの決定につながります。 

## アプローチ

 強引なアイデアでは、利用可能なタイルのすべてのサブセットと、それらを空きセルに配置するすべての方法が試行されます。 サブセットごとに、順序と配置を決定する必要もあり、基本的にはライン上のパッキング問題を解決します。 順序を修正したとしても、サブセットが適合するかどうかを確認するには配置のシミュレーションが必要であり、サブセットの数だけでも 2^N であり、考えられる計算予算をすでに圧倒しています。 

ブルート フォースの失敗は、各タイルを独立して扱い、各配置の決定を組み合わせとして扱うことから発生します。 位置の観点から考えるのをやめ、代わりにセグメントごとの合計の長さの観点から考えると、構造は扱いやすくなります。 

重要な観察は、最初の K 長ブロックを配置した後、基板が最大 2 つの独立した空きセグメント (サイズ E の左側のセグメントとサイズ N-K-E の右側のセグメント) に分割されることです。 タイルは固定ブロックを横切ることができないため、有効な配置は 2 つの独立したナップザックのような問題に分解されます。 各辺は個別に処理できます。タイルの長さのサブセットを選択し、選択した各タイルを完全に左または右のセグメントに割り当てます。 

したがって、問題は、使用される合計の長さを最大化するために、タイルの長さを容量 E および N-K-E の 2 つのビンに分配することに帰着します。 各タイルが使用される場合はその全長に寄与するため、選択した数値を 2 つのビン間で任意に分割できるという制約を付けて、選択した個別の整数の合計を最大化したいと考えます。 

これは、タイル サイズと 2 つの容量にわたる古典的なパーティショニング DP になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット + プレースメント | O(2^N・N) | O(N) | 遅すぎる |
 | 二次元ナップザックDP | O(N · E · (N−K−E)) ~ O(N^3) 最悪の場合 | O(E・R) | 承認済み |

 ## アルゴリズムのチュートリアル

 左側の容量を L = E、右側の容量を R = N − K − E と表します。 

タイル サイズは 1 から N まで処理され、K はすでに使用されているためスキップします。 

1. DP 状態 dp[i][l][r] を定義します。これは、1 から i までのタイルを使用して配置できる最大全長を表し、最大で左側の l 個のセルと右側の r 個のセルを埋めます。 これは、各タイルが完全に一方の側に移動するか、使用されないようにする必要があるという制約を直接エンコードします。 
2. 長さ i の各タイルについて、3 つの可能性を考慮します。 それをスキップし、l ≥ i の場合は左側に配置し、r ≥ i の場合は右側に配置します。 タイルは分割できず、重なることができないため、各選択は実現可能性を維持します。 
3. これら 3 つのオプションを適用して、dp[i−1] から dp[i] に移行し、各タイルが最大 1 回使用されるようにします。 
4. 答えは、すべての有効な l ≤ L および r ≤ R にわたる最大 dp[N][l][r] であり、カバーされる全長の最大化に対応します。 

これが機能する理由は、すべての有効な配置が、各タイルを左側のセグメントに割り当てるか、右側のセグメントに割り当てるか、または使用しないかの選択に正確に対応するためです。 固定 K タイルによって引き起こされるセグメンテーションにより、左右の独立性が保証されるため、両側間の対話を必要とするソリューションはありません。 DP は、二重にカウントしたり、設定が欠落したりすることなく、そのような割り当てをすべて実行します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, E = map(int, input().split())

    L = E
    R = N - K - E

    # dp[l][r] = best sum achievable
    dp = [[0] * (R + 1) for _ in range(L + 1)]

    for i in range(1, N + 1):
        if i == K:
            continue

        for l in range(L, -1, -1):
            for r in range(R, -1, -1):
                best = dp[l][r]

                if l >= i:
                    best = max(best, dp[l - i][r] + i)
                if r >= i:
                    best = max(best, dp[l][r - i] + i)

                dp[l][r] = best

    print((L + R) - max(max(row) for row in dp))

if __name__ == "__main__":
    solve()
```この実装では、タイル処理の前の状態のみが必要なため、DP が 2 次元に圧縮され、同じ反復でまだ必要な状態の上書きを避けるために逆の順序で更新されます。 l と r の逆反復は、各タイルが最大 1 回使用されることを保証し、2 次元での 0 ～ 1 ナップザックの動作を模倣するため、重要です。 

最終的な答えは、利用可能なスペースの合計から、達成可能な最適な埋め込みスペースを差し引いたものとして導出されます。 

## 実用的な例

 N = 6、K = 2、E = 2 とします。L = 2 および R = 2 となり、使用可能なタイルは {1、3、4、5、6} になります。 

概念的には DP 更新のごく一部を追跡します。 

| ステップ (タイル i) | 検討中のアクション | dp[2][2] 値 |
 | --- | --- | --- |
 | 開始 | タイルなし | 0 |
 | i = 1 | 左または右に配置します | 1 |
 | i = 3 | どちらの側にも収まりません | 1 |
 | i = 4 | 適合しません | 1 |
 | i = 5 | 適合しません | 1 |
 | i = 6 | 適合しません | 1 |

 最適な合計フィルは 1 であるため、空き領域上の空セル = 4 − 1 = 3 と暗黙的な構造調整により、セグメント分割と一致する最終的な最小限の空の構成が得られます。 

ここで、N = 5、K = 1、E = 1 とします。L = 1 および R = 3 の場合、タイルは {2, 3, 4, 5} になります。 

| ステップ | アクション | dp[1][3] |
 | --- | --- | --- |
 | 開始 | なし | 0 |
 | i = 2 | 右に配置 | 2 |
 | i = 3 | 右に配置 | 3 |
 | i = 4 | 左右にフィットしません | 3 |
 | i = 5 | 適合しません | 3 |

 これは、より大きなタイルがどのようにパッキングを支配し、より小さな残りの容量が飽和すると無関係になるかを示しています。 

トレースは、各タイルが独立して割り当てられていること、および DP が順序付けの仮定を必要とせずに最適なパッキングを蓄積していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・E・(N−K−E)) | N 個のタイルのそれぞれが、左右の容量にわたる 2D DP を更新します。 
| スペース | O(E・(N−K−E)) | 現在の DP テーブルのみを保存します。 

N ≤ 1000 の場合、ワーストケースの DP テーブル サイズはおよそ 10^6 ステートであり、各ステートは一定の作業を実行するため、ICPC スタイルの問題の一般的な制約内に快適に収まります。

 ## 特殊なケース

 E = 0 の場合、左側のセグメントは完全に消えます。 この場合、L = 0 となり、すべてのタイルは右側にのみ進むことができます。 DP は、R 容量を超えると標準の 0 ～ 1 ナップザックに縮退します。 dp が 1D 行になり、l に対するループが l = 0 でのみ反復されるため、実装ではこれが処理され、無効な遷移は発生しません。 

N − K − E = 0 の場合、右側のセグメントが消え、対称な状況が発生します。 左側の配置のみが可能であり、DP はすべてのタイルを左側の次元に正しく制限します。 

K = N の場合、配置された 1 つを除いて残りのタイルはなく、L と R は両方とも 0 です。 DP は単一セル dp[0][0] = 0 のままであり、追加のカバレッジは正確にゼロになります。
