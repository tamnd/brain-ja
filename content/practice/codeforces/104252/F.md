 ## 問題の理解

 私たちには二本の木が与えられました。 最初の木、それを呼んでください$T_1$、私たちが内部を探索することを許可されている大きな構造物です。 ２本目の木は、$T_2$、これが探したいパターンです。 タスクは、接続された一連の頂点が内部に存在するかどうかを判断することです。$T_1$構造的に同一のツリーを形成する$T_2$つまり、隣接性を維持する頂点の 1 対 1 の再ラベル付けが行われます。 

簡単に言うと、次のコピーを探しています。$T_2$心のどこかに隠れている$T_1$、ここで、頂点の接続されたサブセットを選択できます。$T_1$、そしてその誘導された構造は以下と同型でなければなりません$T_2$。 

どちらのツリーにも最大 100 個のノードがあります。 これはすぐに、次のような解決策が考えられることを示唆しています。$O(n^3)$あるいは$O(n^4)$慎重に実装すればまだ許容できるかもしれません。$100^3 = 10^6$そして$100^4 = 10^8$これは境界線にありますが、厳密な枝刈りと小さな定数を使用した場合にのみ Python で実現可能です。 

単純な指数関数的なアイデアは、次のノードのすべてのサブセットを試してみることです。$T_1$、ツリーを形成しているかどうかを確認し、次のようにして同型性をテストします。$T_2$。 これはすぐに失敗します。$T_1$もっている$2^{100}$サブセット、さらには接続されたものに限定すると、可能性の数は指数関数的に爆発します。 

より微妙な失敗例は、「一致するサブツリー」が「一致するルート付きサブツリー」を意味すると仮定することから生じます。 両方のツリーを恣意的にルート化し、ルート化されたサブツリーのみを比較すると、選択された中心が存在する有効な埋め込みを見逃してしまう可能性があります。$T_1$のルートに対応しません$T_2$。 たとえば、長さ 4 のパスには多くの位置に長さ 3 のパスが含まれていますが、端点と中間点でルートを設定すると構造が変わります。 

したがって、本当の困難は候補を生成することではなく、任意の埋め込み制約の下でツリーの同型性を効率的に検証することです。 

## アプローチ

 ブルート フォース パースペクティブは、頂点を選択することから始まります。$T_1$試合の「アンカー」として、埋め込みを試みています$T_2$その周り。 そのような選択ごとに、次のすべてのマッピングを試みます。$T_2$の頂点を接続された頂点に変換$T_1$、隣接関係の保存をチェックします。 ルート マッピングを修正したとしても、子の可能なマッピングの数は次数の階乗に比例し、これは非常に急速に増加します。 

効率的な解決策を明らかにする重要な観察は、ルート付きサブツリーの構造的等価性を使用して、ツリーを葉から上に向かって段階的に照合できるということです。 根を修正すれば$T_2$、への有効な埋め込み$T_1$そのルートを次の頂点にマップする必要があります$T_1$、ルートの子は、隣接するサブツリーの互いに素なサブツリーにマップされる必要があります。$T_1$。 これにより、問題は、ルート化されたサブツリーの複数セット間で繰り返されるマッチングに変わります。 

したがって、問題をノードのペアに対する動的プログラミングとして再定式化します。$(v, u)$、 どこ$v \in T_1$そして$u \in T_2$。 値`match[v][u]`のサブツリーを意味します$T_2$に根ざした$u$のサブツリーに埋め込むことができます$T_1$に根ざした$v$、未使用のブランチを無視できる柔軟性を備えています。$T_1$。 

この状態が定義されると、遷移は 2 部のマッチング問題になります。$u$の子に注入的に割り当てる必要があります$v$、対応するサブツリーが一致するようにします。 

ブルートフォースアプローチは、すべての埋め込みを明示的に試行するため、指数関数的になります。 DP アプローチでは、ノードの各ペアが 1 回ずつ解決され、各チェックが低次グラフでのマッチングに削減されるため、これが多項式時間に削減されます。

 ## アルゴリズムのチュートリアル

 両方のツリーを任意に、たとえば各ツリーのノード 1 にルートします。 これにより、すべてのノードに親子構造が与えられ、すべてのサブツリーが明確に定義されます。 

次に DP テーブルを計算します`match[v][u]`意味は「$T_2$に根ざした$u$～のサブツリーに埋め込まれる$T_1$に根ざした$v$?”。

 1. すべて初期化する`match[v][u]`の葉用$T_2$すべてのことについて真実である$v$。 リーフ パターンは常に次のノードに一致します。$T_1$頂点を 1 つだけ配置するだけでよいためです。 
2. プロセスノード$T_2$サブツリー サイズの昇順 (ポストオーダー)。 これにより、計算時に次のことが保証されます。`match[v][u]`、すべての子の状態`match[v'][u']`はすでに知られています。 
3. ペアごとに$(v, u)$、子間の 2 部グラフを構築します。$v$と子供たち$u$。 子どもたちを繋ぎます$cv$の$v$子供に$cu$の$u$もし`match[cv][cu]`それは本当です。 
4. の子から最大 2 部マッチングを実行します。$u$の子供たちへ$v$。 すべての子を一致させることができれば、$u$、次に設定します`match[v][u] = True`。 それ以外の場合は false です。 
5. テーブルに記入した後、次のものが存在するかどうかを確認します。$v \in T_1$そのような`match[v][root_of_T2]`それは本当です。 「はい」の場合、出力します`Y`、 さもないと`N`。 

マッチングだけで十分である決定的な理由は、ツリーの同型性では隣接性を維持する必要があり、ルート付きツリーではこれが各子サブツリーを個別にマッチングすることになるからです。 サブツリーは異なるブランチ間で相互作用しないため、問題は一致する子セットにきれいに分解されます。 

### なぜ効果があるのか

 不変条件というのは、`match[v][u]`のすべての構造要件が正しく把握されているかどうか$T_2$に根ざした$u$のルート構造内で満たすことができます。$T_1$で$v$。 子を照合するたびに、必要な部分構造と使用可能な部分構造の間に 1 対 1 の割り当てが適用され、重複がなくなり、接続が維持されます。 すべての子サブ問題は親状態を計算する前にすでに検証されているため、サブツリーの互換性に関する誤った仮定が上方に伝播する可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10000)

def read_tree(n):
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    return g

def root_tree(g, root):
    n = len(g)
    parent = [-1] * n
    children = [[] for _ in range(n)]
    stack = [root]
    parent[root] = -2

    order = []
    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            if parent[to] == -1:
                parent[to] = v
                children[v].append(to)
                stack.append(to)

    return children, order

def dfs_order(children):
    order = []
    stack = [0]
    while stack:
        v = stack.pop()
        order.append(v)
        for c in children[v]:
            stack.append(c)
    return order[::-1]

def can_match(v, u, children1, children2, dp):
    A = children1[v]
    B = children2[u]

    if not B:
        return True

    # bipartite matching from B to A
    match = [-1] * len(A)

    def dfs(b, seen):
        for i, a in enumerate(A):
            if seen[i]:
                continue
            if not dp[a][b]:
                continue
            seen[i] = True
            if match[i] == -1 or dfs(match[i], seen):
                match[i] = b
                return True
        return False

    for b in B:
        seen = [False] * len(A)
        if not dfs(b, seen):
            return False
    return True

def solve():
    n1 = int(input())
    g1 = read_tree(n1)
    n2 = int(input())
    g2 = read_tree(n2)

    children1, _ = root_tree(g1, 0)
    children2, _ = root_tree(g2, 0)

    # postorder for T2
    order2 = []
    stack = [0]
    parent = [-1] * n2
    parent[0] = -2
    while stack:
        v = stack.pop()
        order2.append(v)
        for to in g2[v]:
            if to == parent[v]:
                continue
            if parent[to] == -1:
                parent[to] = v
                stack.append(to)
    order2 = order2[::-1]

    dp = [[False] * n2 for _ in range(n1)]

    for u in order2:
        for v in range(n1):
            dp[v][u] = can_match(v, u, children1, children2, dp)

    for v in range(n1):
        if dp[v][0]:
            print("Y")
            return
    print("N")

if __name__ == "__main__":
    solve()

微妙な点は、子供たちは独立して扱われるということです。$u$の子と一致します$v$、そのサブツリー全体が再帰によって消費されます。`dp`部分的な重複や一貫性のない再利用を防ぎます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$T_2$は単一ノードです。 この状況では、すべてのノードが$T_1$は有効な一致です。 アルゴリズムはこれを処理します。`dp[v][u]`葉用$u$はすぐに true に設定されるため、最終チェックは当然成功します。 

もう一つの微妙なケースは次のような場合です。$T_1$高次ノードを持っていますが、$T_2$チェーンが必要です。 入力の場合、$T_1$スターであり、$T_2$は長さ 3 のパスであるため、内部ノードでのマッチングは失敗します。$T_2$単一の子構造が存在しないため、$T_1$逐次依存関係の要件を満たすことができます。 二部マッチング ステップでは、必要なブランチごとに個別の子の代入を要求することでこれを厳密に強制し、チェーンが存在しないと再帰が失敗します。
