 ## 解決策
 ## 問題の理解

 原点と 2 番目の点を通る線によって定義される、平面内に直線の橋脚が与えられます。$(A, B)$。 この無限線上の任意の点をバーベキュー グリルの位置として選択できます。 選択した点の周囲に、一定の半径の円形の煙雲が発生します。$R$が表示されます。 すべてのボートは平面内の固定点であり、ボートがこの円の内側または上にある場合、そのボートは「警戒している」と見なされます。 

タスクは、円がカバーするボートの数を最大にする桟橋上の点を選択することです。 

幾何学的には、これは制約された中心選択の問題です。円を平面内のどこにでも自由に配置することはできず、固定線に沿ってのみ配置できます。距離内の点の数が最大になるその線上の位置が必要です。$R$。 

制約は大きく、最大で$3 \cdot 10^5$ボート。 考えられるすべての桟橋位置の距離を再計算したり、候補中心を直接離散化しようとするアプローチは失敗します。 ナイーブでも$O(N^2)$ペアのボートの上を掃くのは遅すぎます。 

さらに微妙な問題は数値の安定性です。 桟橋は任意の座標で定義され、ボートは広い座標範囲内のどこにでも配置できます。 繰り返しの幾何学的計算に依存するソリューションでは、距離と間隔の終点を比較する際の精度のドリフトを回避する必要があります。 

ボートが桟橋から遠い場合、エッジケースが発生します。 たとえば、すべてのボートが次の距離よりも遠い場合、$R$ライン自体からの距離が大きい場合、円の中心を桟橋のどこに置いてもボートをカバーすることはできず、答えはゼロになります。 これらのケースをフィルタリングしない不注意な実装では、依然として無効な間隔が生成され、不正確なオーバーラップが生成される可能性があります。 

もう 1 つの特殊なケースは、ボートがちょうど離れたところにある場合です。$R$ライン上の単一の縮退位置の移動中心からの距離。 これらのケースでは、ある点まで崩れた間隔が生成され、それらを空の間隔として誤って扱うと、有効な答えが失われます。 

## アプローチ

 強引なアイデアは、桟橋上の候補地点を選択し、その距離内に何隻のボートが落ちたかを数えるというものです。$R$。 ラインに沿って多くの点をサンプリングするか、ライン上のすべてのボートの投影を候補中心として試してみると、直接距離をチェックして答えを計算できます。 これは概念的に機能します。最適な円の中心は、覆われたボートのセットが変化する「重要な」位置になければならず、通常はボートを中心とする円の境界を含む幾何学的なイベントに合わせて配置されるためです。 

ただし、このアプローチは遅すぎます。 すべてのボートのペアを試して遷移候補を生成すると、次のようになります。$O(N^2)$候補者たち。 単一の候補を評価するだけでもコストがかかる$O(N)$、につながる$O(N^3)$最悪の場合。 評価を下げても$O(1)$前処理を使用しても、候補位置の爆発は修正されません。 

重要な観察は、視点を逆転できるということです。 センターを選択して、どのボートがカバーされているかを確認する代わりに、ボートを固定して、「このボートは桟橋上のセンターのどの位置をカバーするでしょうか?」と尋ねます。 

ボートを修理する$P$。 センター$C$満たさなければなりません$|C - P| \le R$。 以来$C$が直線上にあるように制約されている場合、この条件は直線に沿った単一パラメータの間隔制約になります。 すべてのボートは、有効なセンター位置の間隔に貢献します。 最終的な答えは、重複する間隔の最大数です。 

したがって、すべてのボートを桟橋ライン上に投影し、各円をそのラインに沿った間隔に縮小した後、幾何学的な問題は 1D 間隔の重複問題に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサンプリング/ペア生成 |$O(N^2)$に$O(N^3)$|$O(N)$| 遅すぎる |
 | 区間投影 + スイープ ライン |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 2D ジオメトリを、橋脚に合わせて 1D 座標系に変換します。 

### 1. 桟橋に沿った座標系を構築します。 

桟橋を通過する無限の線として扱います$(0,0)$そして$(A,B)$。 方向ベクトルを定義します$d = (A,B)$それを単位ベクトルに正規化します$u$。 これにより、桟橋上の任意の点を単一のスカラー パラメーターで表すことができます。$t$、ここでの位置は$P(t) = (0,0) + t \cdot u$。 

このステップを行う理由は、すべての有効なバーベキュー位置がこの線上にあるため、問題を 1 つのパラメーターに縮小すると、幾何学的な自由度が 1 つ削除されるためです。 

### 2. 各ボートの垂直距離と投影を事前計算します。 

各ボートごとに$X_i = (x_i, y_i)$、ライン上への投影とラインへの垂直距離を計算します。 

垂直距離によって、ボートが航行できるかどうかが決まります。 この距離を超えると$R$、その場合、線を中心とする円はその線に到達できません。 

ボートが到達可能な場合は、その投影座標も計算します$t_i$線路に沿って。 

### 3. 各ボートをライン上の間隔に変換します。 

位置固定中心の場合$t$、ボートまでの距離は垂直成分と平行成分に分解されます。 垂直成分は固定です。 ラインに沿った残りの許容半径は次のようになります。$$\Delta_i = \sqrt{R^2 - d_{\perp}^2}$$したがって、中心は次の条件を満たす必要があります。$$t \in [t_i - \Delta_i,\; t_i + \Delta_i]$$各艇は実線上の間隔となります。 

これは重要な変換です。2D 円形拘束が 1D セグメント拘束になります。 

### 4. すべての間隔にわたるスイープ ライン

 すべての間隔エンドポイントを収集します。 開始するたびにカバレッジに +1 が追加され、終了するたびに -1 が減算されます。 エンドポイントを並べ替えてスイープすると、任意の点で最大の重複が得られます。 

正確に境界線上にあるボートが含まれるように、エンドポイントが一貫して処理されるように注意します。 

### なぜ効果があるのか

 このアルゴリズムは、桟橋上のすべての有効な中心位置が実線パラメータ上の 1 つの点に正確に対応するという事実に基づいています。$t$、各ボートは正確に次のセットを定義します。$t$対象となる値。 したがって、カバレッジは間隔にわたって加算され、カバーされるボートの数を最大化することは、間隔が最大に重なるポイントを見つけることと同じになります。 投影後にボート間の幾何学的相互作用は残らないため、縮小を無効にする可能性のある隠れた依存関係はありません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    N, R, A, B = map(int, input().split())

    # direction vector of pier
    dx, dy = A, B
    norm = math.hypot(dx, dy)
    ux, uy = dx / norm, dy / norm

    events = []

    for _ in range(N):
        x, y = map(int, input().split())

        # projection coordinate onto pier
        tx = x
        ty = y

        t = tx * ux + ty * uy  # dot product gives projection

        # perpendicular distance via cross product magnitude
        cross = abs(tx * dy - ty * dx) / norm

        if cross > R:
            continue

        span = math.sqrt(R * R - cross * cross)

        l = t - span
        r = t + span

        events.append((l, 1))
        events.append((r, -1))

    events.sort()

    cur = 0
    best = 0

    for _, v in events:
        cur += v
        best = max(best, cur)

    print(best)

if __name__ == "__main__":
    solve()
```実装は、正規化された方向ベクトルを使用して桟橋に沿って正規直交基底を構築することから始まります。 次に、すべてのボートは、内積を使用してその方向に沿ったスカラー座標にマッピングされます。 垂直距離は、線ノルムで割った外積を使用して計算されます。これにより、回転座標系を明示的に構築する必要がなくなります。 

各ボートは、幾何学的に到達可能な場合、つまり垂直距離が半径を超えない場合にのみ間隔に寄与します。 それ以外の場合は無視しても問題ありません。 

スイープ ラインではソートされたエンドポイントが使用され、左側のエンドポイントはアクティブ カウントを増加させ、右側のエンドポイントはアクティブ カウントを減少させます。 このスイープ中の最大プレフィックス合計は、バーベキューの最適な配置に対応します。 

実装の微妙な詳細は、浮動小数点の安定性です。 使用する`math.hypot`一貫した正規化により、次のような大きな相対誤差が回避されます。$A, B$大きいです。 公差に関するステートメント保証により、追加のイプシロン処理なしで標準の倍精度が可能になります。 

## 実用的な例

0 0

```すべてのボートは、桟橋でもある X 軸上にあります。 ユニットの方向は、$(1,0)$、したがって投影は直接です。 

| ボート | t | パープ距離 | 間隔 |
 | --- | --- | --- | --- |

 | (4,0) | 4 | 0 | [3、5] |

 これらの間隔をスイープすると、最大のオーバーラップが発生します。$t \in [1,1]$そして$t \in [3,3]$、それぞれ2つのボートをカバーします。 

出力は2です。

 入力:```
4 1 1 0

```橋脚が再び X 軸になります。 間隔を次のように分類します。 

| ボート | 投影 t | パープ距離 | 間隔 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N \log N)$| 各ボートは最大 2 つのイベントになり、一度ソートされてから直線的にスイープします。 
| スペース |$O(N)$| 到達可能なすべてのボートの間隔エンドポイントを保存します。 

制約により、最大で次のことが許可されます。$3 \cdot 10^5$ボートなので、$O(N \log N)$スイープは簡単に十分に高速です。 メモリ使用量は間隔の数に対して線形であり、十分に制限内にあります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import hypot, sqrt
    import math

    input = sys.stdin.readline
    N, R, A, B = map(int, input().split())
    dx, dy = A, B
    norm = math.hypot(dx, dy)
    ux, uy = dx / norm, dy / norm

    events = []
    for _ in range(N):
        x, y = map(int, input().split())
        t = x * ux + y * uy
        cross = abs(x * dy - y * dx) / norm
        if cross <= R:
            span = math.sqrt(R * R - cross * cross)
            events.append((t - span, 1))
            events.append((t + span, -1))

    events.sort()
    cur = 0
    best = 0
    for _, v in events:
        cur += v
        best = max(best, cur)
    return str(best)

 ## 特殊なケース

 すべてのボートが桟橋の線から遠く離れた場所にある場合、すべての垂直距離は次の距離を超えます。$R$、アルゴリズムは間隔を生成しません。 その後、スイープはイベントを検出せず、ゼロを返します。これは、ライン上のどの配置もボートに到達できないという事実と一致します。 

ボートがちょうど遠くにあるとき$R$線から離れると、その間隔は単一の点に崩壊します。 スイープ ラインでは、これは同じ座標の開始点と終了点として表示され、特別な処理を必要とせずに正確な中心位置で正しくオーバーラップします。 

複数のボートが同一の投影座標を共有しているが、垂直距離が異なる場合、それらの間隔は同じ領域の周囲で大きく重なり合います。 投影後は各間隔が独立しているため、スイープではすべての寄与が正しく累積されます。
