 ## 解決策
 ## 問題の理解

 島を表す無向グラフと、いくつかの島のペア間の直接的な影響パスが与えられます。 影響は推移的です。つまり、アイランド A が B に影響を与え、B が C に影響を与えることができる場合、直接のエッジがなくても、A と C は同じ接続された環境にあります。 

各クエリは、特定の実験のために「人が住んでいる」島のサブセットを記述します。 そのサブセットについては、有人島とそれらの間のエッジのみを考慮した場合に、その中に存在する切断された影響クラスターがいくつあるかを判断する必要があります。 

グラフ用語で言えば、各クエリは次のことを尋ねます: 与えられた頂点のセット上で誘導された部分グラフを取得する場合、それにはいくつの連結成分があるか。 

この制約により、クエリごとに接続を最初から再計算する必要がなくなります。 最大 100,000 のノード、100,000 のエッジ、および 100,000 のクエリがありますが、すべてのクエリにわたるクエリされた頂点の合計数も 100,000 によって制限されます。この最後の事実は、ノードの大規模なサブセットを繰り返しスキャンしたり、クエリごとに完全な DSU 構造を再構築したりできないことを意味するため、非常に重要です。 クエリごとにすべてのノードにアクセスするアプローチでは、最悪の場合、約 10^10 の操作にまで低下しますが、これは実行不可能です。 

単純なメンタル モデルでは、すべてのクエリに対して DFS または BFS を実行し、そのサブセット内でのみ訪問したノードをマークします。 これは論理的には正しいですが、各走査で多くのエッジを繰り返しスキャンする可能性があるため、遅すぎます。 

グローバル接続コンポーネントで十分であると仮定すると、さらに微妙な落とし穴が現れます。 グラフ全体の DSU コンポーネントを事前計算し、選択したノード間に存在する DSU コンポーネントの数を数えることによって各クエリに答えると、中間ノードが存在しない場合に接続が切断される可能性があるという事実を見落とします。 

たとえば、チェーン 1-2-3-4 を考えてみましょう。 クエリに {1, 3, 4} が含まれている場合、グローバル DSU はすべてのノードが接続されていると示しますが、誘導されたサブグラフ内ではノード 2 が欠落しているため、1 は分離され、{3,4} が 1 つのコンポーネントを形成し、答えは 1 ではなく 2 になります。これは、グローバル接続ではなく誘導接続を尊重する必要があることを示しています。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 ノードのセットごとに、そのサブセットに制限された訪問済みの配列を構築し、サブセット内のすべての未訪問のノードから DFS/BFS を実行し、新しい走査を開始した回数を数えます。 各走査ではエッジを探索し、隣接するエッジが現在のクエリ セットに属しているかどうかを確認します。 

これは、誘導されたサブグラフの連結成分を直接計算するため、正しいです。 問題はコストです。 最悪の場合、各クエリにはほぼすべてのノードが含まれ、各 BFS はほとんどのエッジを通過する可能性があります。 P が 100000 までの場合、これはおよそ O(P・(N+E)) となり、限界をはるかに超えています。 

重要な観察は、多くのクエリがあるにもかかわらず、すべてのクエリにわたって表示される頂点の総数が全体として少ないということです。 これは、クエリ全体で作業を償却する方法でクエリを処理する必要があることを示唆しています。 

接続性について考える便利な方法は、Disjoint Set Union 構造を使用することですが、それをグローバルに維持する代わりに、クエリごとに段階的にノードをアクティブにします。 クエリ内のノード間のエッジのみを考慮する必要があるため、クエリのノードを一時的に「オン」にし、既存のエッジを介してノードを結合してからリセットできます。 ただし、変更を注意深く追跡しない限り、DSU を単純にリセットするとコストが高くなります。 

標準的な手法では、グローバル DSU を使用しますが、タイムスタンプまたはマーカー配列を保持しながら、現在のクエリでアクティブなノードのみをマージすることで完全なリセットを回避します。 両方のエンドポイントが現在のクエリ セットの一部である場合にのみ結合を試行するようにします。 各エッジはそのエンドポイントが何らかのクエリに出現する場合にのみ考慮されるため、すべてのクエリにわたる合計作業量は、クエリ サイズとそれに付随するエッジの数の合計に比例します。

もう 1 つの明確な観点は、隣接リストと「クエリ ローカル アクティブ化」を備えた DSU を使用したクエリごとのオフライン処理です。 M の合計は 100000 であるため、すべてのクエリのすべてのノードを反復すると、入力サイズは線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(P · (N + E)) | O(N + E) | 遅すぎる |
 | クエリごとのアクティブ化を備えた DSU | O(N + E + 合計 M) | O(N + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフのグローバル隣接リストを維持します。 各クエリについて、リストされたノードのみを処理し、クエリ間で再利用される DSU を使用してノード間の接続を構築しますが、クエリ間の汚染は慎重に回避します。 

1. クエリ リストを読み、そのリスト内のすべてのノードを「このクエリに対してアクティブ」としてマークします。 これにより、O(1) メンバーシップ チェックが可能になります。 
2. 各ノードを独自の親としてサイズ 1 に設定して、クエリ内のノードのみの DSU 親構造を初期化します。また、後のクリーンアップのためにクエリ内のノードのリストも維持します。 
3. クエリ内の各ノード u を反復処理します。 元のグラフ内の u のすべての近傍 v について、v が現在のクエリでもアクティブであるかどうかを確認します。 「はい」の場合、DSU で u と v を結合します。 
4. すべてのエッジを処理した後、クエリされたノード間に存在する個別の DSU ルートの数を計算します。 これは接続されたコンポーネントの数です。 
5. 次のクエリに進む前に、このクエリ内のノードのアクティブ マーカーをリセットします。 

ステップ 3 の重要な考え方は、クエリ セット内に完全に含まれるエッジのみを考慮するということです。 非アクティブなノードに接触するエッジは、そのノードが誘導されたサブグラフに存在しないため、無関係です。 

### なぜ効果があるのか

 クエリごとに、オンデマンドで誘導サブグラフを効果的に構築します。 DSU は、その誘導されたサブグラフ内のエッジによって接続されている頂点のペアを正確にマージします。 DSU は等価閉包を保持するため、ノードの最終的な分割は接続されたコンポーネントに正確に対応します。 クエリ メンバーシップによってエッジを明示的にフィルターするため、余分なマージは発生しません。また、すべての有効な誘導エッジが少なくとも 1 つのエンドポイントから 1 回処理されるため、必要なマージが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, e, p = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(e):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]

    active = [False] * (n + 1)

    for _ in range(p):
        tmp = list(map(int, input().split()))
        m = tmp[0]
        nodes = tmp[1:]

        for v in nodes:
            active[v] = True
            parent[v] = v
            size[v] = 1

        for u in nodes:
            for v in adj[u]:
                if active[v]:
                    union(u, v)

        roots = set(find(x) for x in nodes)
        print(len(roots))

        for v in nodes:
            active[v] = False

if __name__ == "__main__":
    solve()
```このソリューションでは、グラフを一度構築してから、各クエリを個別に処理します。 DSU は再利用されますが、再初期化されるのはクエリ内のノードのみです。 アクティブな配列により、クエリ セット内のエッジのみが結合されます。 

微妙な点は、グローバルではなく、クエリ内のノードに対してのみ親ポインターをリセットしていることです。 これにより、クエリごとの O(N) リセットが回避されます。 各ノードは出現時にのみリセットされるため、すべてのクエリにわたる合計リセット コストは O(合計 M) です。 

もう 1 つの詳細は、ルートを介してコンポーネントをカウントすることです。 クエリ内の各ノードの find(x) を計算し、セットに挿入します。 これはクエリ サイズが線形であり、制約と一致しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + E + 合計 M α(N)) | 各エッジは、両方のエンドポイントがクエリに出現する場合にのみチェックされます。 DSU の運用はほぼ一定に償却されます。 
| スペース | O(N + E) | 隣接リストと DSU アレイ |

 重要な要素は、クエリ サイズの合計が 100000 で制限されているため、クエリ全体のノードごとのすべての作業が線形のままであることです。 これにより、100,000 件のクエリがあっても、ソリューションは制限内に快適に維持されます。

 ## 特殊なケース

 最初のエッジ ケースは、クエリに単一のノードが含まれる場合です。 アルゴリズムはそのノードをアクティブにし、結合を実行せず、ルート セットには要素が 1 つだけ含まれ、出力 1 が生成されます。これにより、特別な処理が回避され、当然 DSU の動作から外れます。 

2 番目のエッジ ケースは、グローバル グラフが密であるにもかかわらず、誘導されたサブグラフにエッジがない場合です。 このような場合、アクティブなフィルターはすべての結合を阻止します。 各ノードは初期化後も独自の親のままであるため、ルートの数はクエリ サイズと等しくなります。これは、完全に切断された誘導グラフにとっては正しいことです。 

3 番目のエッジ ケースは、クエリによって疎なエンドポイントが選択される大規模な接続グラフです。 両方のエンドポイントがアクティブであるエッジのみが考慮されるため、グローバル接続が存在する場合でも、DSU はローカルに関連する部分のみをマージします。 これにより、欠落している中間ノードを無視してグローバル接続情報に依存するというよくある間違いを防ぐことができます。
