 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられ、すべての連続する部分配列を考慮します。 各部分配列について、その中のすべての要素の最大公約数とその中の最大要素の 2 つの値が抽出されます。 そのサブ配列の寄与はこれら 2 つの値の積であり、タスクはすべてのサブ配列にわたってこの寄与を合計することです。 

したがって、計算は基本的に関数を全体的に集計することです。$O(N^2)$間隔。各間隔は 2 つの異なる非線形集計 (gcd と Maximum) に依存します。 

制約$N \le 2 \cdot 10^5$すべての部分配列を明示的に列挙するソリューションは直ちに除外されます。 一枚でも$O(N^2)$スキャンはすでに大きすぎるため、間隔ごとの gcd と最大値を計算すると、$O(N^3)$素朴な形で。 正しい解決策では、部分配列統計を最初から再計算することを避ける必要があります。 

製品を分解しようとすると微妙な困難が現れます$\gcd \cdot \max$。 どちらの関数も、単純な畳み込みを可能にする方法でサブ配列に対して独立して動作することはありません。 特に、gcd は伸張下では減少しながら安定しますが、最大値は増加しながら安定します。これは、効率的なソリューションは構造化された間隔のセットにわたって両方を同時に追跡する必要があることを示唆しています。 

すべての間隔の gcd と最大値を個別に事前計算する素朴なアプローチも失敗します。$O(N^2)$価値観はすでに不可能です。 課題は、各サブアレイが償却サブリニア時間で考慮されるように寄与を再編成することです。 

## アプローチ

 ブルート フォース ソリューションはすべてのペアに対して反復されます。$(l, r)$、の gcd を計算します。$a[l..r]$、の最大値を計算します。$a[l..r]$、回答に製品を追加します。 これは定義に直接従うため、正しいです。 ボトルネックは、間隔ごとに gcd と max を最初から再計算するコストがかかることです。$O(N)$、につながる$O(N^3)$合計時間。 増分更新を行っても、gcd と max の両方を維持すると、依然として結果が得られます。$O(N^2)$、これは大きすぎます$2 \cdot 10^5$。 

重要な観察は、gcd と最大値の両方が、固定された右端点の拡張下では単調であるということです。 部分配列を左に拡張すると、gcd のみが変化します。$O(\log A_i)$gcd 値は除数に沿って厳密に減少し、最大値は新しいより大きな要素に遭遇した場合にのみ変化するため、エンドポイントあたりの回数が増加します。 この構造により、固定位置で終わるすべてのサブ配列の圧縮表現を維持できます。$O(N)$明確な価値観のみを維持します$O(\log A_i)$gcd セグメントと$O(\log N)$最大セグメント数。 

主なアイデアは、正しいエンドポイントをスイープすることです$r$。 それぞれについて$r$で終わる部分配列のすべての個別の gcd 値を維持します。$r$、左側の境界によってグループ化され、同様に、で終わるサブ配列のすべての個別の最大値を維持します。$r$。 次に、同じ gcd と max を共有するサブ配列をグループ化することで、これらの構造を組み合わせて寄与を効率的に計算します。 

gcd と max の間の相互作用は、次で終わるサブ配列を処理することによって処理されます。$r$gcd と max の両方が定数である左側のエンドポイント上のパーティションとして、それらの結合寄与を累積します。

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、現在のインデックスで終わるサブ配列に関するすべての関連情報を維持します。 

1. 各ポジションごと$r$、圧縮されたペアのリストを維持します$(g, l)$で終わる部分配列のすべての個別の gcd 値を表します。$r$ここで、各 gcd 値は、 から始まる左端点の範囲に対して有効です。$l$。 この構造は、間隔を延長して素因数を削除した場合にのみ gcd 値が変化するため、機能します。 
2.追加時にこの gcd 構造を更新します。$a[r]$。 新しい状態を開始する$(a[r], r)$、最後に保存された値を持つ gcd を取得することにより、以前の gcd 状態と逆方向にマージします。 gcd が変化するたびに、新しいセグメントが記録されます。 これにより保証されるのは、$O(\log A_r)$セグメントは残ります。 
3. で終わるサブ配列の最大値についても同様の圧縮構造を維持します。$r$。 最大セグメントを減少させ続ける単調スタックを使用します。 各要素は既存のセグメントを拡張するか、弱い最大値を削除して、プロセス全体で (O(N)\ 個の合計遷移のみを保証します)。 
4. 位置の両方の構造を更新した後$r$、それらを組み合わせる必要があります。 すべてのペアを列挙する代わりに、セグメント境界をスイープし、有効範囲と交差する gcd セグメントと max セグメントにわたる 2 ポインター スタイルのマージを維持します。 
5. gcd と max の両方が定数である左端点の交差間隔ごとに、寄与を次のように計算します。$g \cdot m \cdot \text{length}$、答えのモジュロに追加します$10^9+7$。 
6. すべてに対してこのプロセスを繰り返します$r$、貢献を蓄積します。 

### なぜ効果があるのか

 正しいエンドポイントを修正する$r$。 で終わるすべてのサブ配列$r$ちょうど 1 つの gcd セグメントとちょうど 1 つの max セグメントに属します。 gcd セグメンテーションは、左端点を gcd が定数である範囲に分割します。 最大セグメンテーションは最大値に対しても同じことを行います。 これらのパーティションの交差により、定数ペアによってすべてのサブ配列を一意に正確に記述する改良が形成されます。$(\gcd, \max)$。 すべての部分配列は 1 つの交差ブロック内で 1 回だけカウントされるため、合計すると$g \cdot m$これらのブロックの合計は、重複または省略なしで必要な合計に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # gcd segments: list of (gcd_value, start_index)
    gcd_seg = []
    ans = 0

    # max segments: list of (max_value, start_index)
    max_seg = []

    for i, x in enumerate(a):
        # update gcd segments
        new_gcd = [(x, i)]
        for g, l in gcd_seg:
            ng = gcd(g, x)
            if new_gcd[-1][0] == ng:
                new_gcd[-1] = (ng, new_gcd[-1][1])
            else:
                new_gcd.append((ng, l))
        gcd_seg = new_gcd

        # update max segments (monotonic)
        new_max = []
        for m, l in max_seg:
            nm = max(m, x)
            if new_max and new_max[-1][0] == nm:
                new_max[-1] = (nm, new_max[-1][1])
            else:
                new_max.append((nm, l))
        if not new_max or new_max[-1][0] < x:
            new_max.append((x, i))
        max_seg = new_max

        # merge contributions
        j = k = 0
        while j < len(gcd_seg) and k < len(max_seg):
            g, l1 = gcd_seg[j]
            m, l2 = max_seg[k]
            l = max(l1, l2)

            # next boundaries
            nl1 = gcd_seg[j + 1][1] if j + 1 < len(gcd_seg) else i + 1
            nl2 = max_seg[k + 1][1] if k + 1 < len(max_seg) else i + 1
            r = min(nl1, nl2)

            if l < r:
                ans = (ans + (r - l) * (g % MOD) % MOD * (m % MOD)) % MOD

            if nl1 < nl2:
                j += 1
            else:
                k += 1

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```gcd メンテナンスはセグメント リストを増分的に再構築し、各新しい要素に少数の異なる gcd 値のみが導入されることを保証します。 最大値の維持では単調な構造が使用されるため、より大きな値が表示されるたびに古い最大値が置き換えられます。 マージ ステップでは、個々の部分配列を反復せずに、有効区間の交差部分を計算します。 

微妙な点はセグメント境界の処理です。各セグメントは半開区間で有効なものとして扱われ、寄与の長さはこれらの区間の重なりから導出されます。 これにより、境界が揃っている場合の二重カウントが回避されます。

 ## 特殊なケース

 gcd 構造体と Maximum 構造体の両方が空から始まるため、単一要素配列では初期化が強調されます。 入力用`[7]`、唯一の部分配列はそれ自体であり、寄与を与えます$7 \cdot 7 = 49$。 このアルゴリズムは、両方のセグメント構造を最初の要素で正しく初期化し、すぐに 1 つの交差ブロックを計算します。 

すべて等しい値を持つ配列は、セグメントの結合が正しく折りたたまれるかどうかをテストします。 のために`[2,2]`、すべてのサブ配列には gcd 2 と max 2 があるため、寄与は次のようになります。$4 + 4 + 4 = 12$。 セグメンテーションにより、エンドポイントごとにすべてが 1 つの定数ブロックにマージされ、過剰カウントが発生しません。 

配列を厳密に減少させると、単調なスタック動作が最大になるかどうかがテストされます。 それぞれの新しい要素は、その時点で終了するすべての部分配列の新しい最大値になり、gcd は割り算の連鎖を通じて進化します。 セグメント構造は、新しい最小値が現れるたびに間隔を正しく分割する必要があり、交差ロジックにより、各部分配列が正確に 1 回カウントされることが保証されます。
