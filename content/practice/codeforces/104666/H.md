 ## 解決策
 ## 問題の理解

 長さのシーケンスが何個あるかを数えるように求められます$N$禁止された部分文字列のセットを回避しながら、26 個の記号のアルファベットから形成できます。 各禁止パターンは小さな文字列であり、禁止パターンがその内部のどこかに連続したブロックとして出現する場合、シーケンスは無効になります。 

出力は有効な長さの数です。$N$文字列モジュロ$10^9 + 7$。 

重要な難点は、$N$と同じ大きさにすることができます$10^9$したがって、文字列を明示的に構築またはシミュレートすることはできません。 むしろ、問題は基本的に、部分文字列回避制約の下で巨大な組み合わせ構造内のパスをカウントすることに関するものです。 

この制約は、パターンが最大 100 個あり、その合計の長さが最大 ​​100 であることも示しています。これは、状態空間ではなくパターンの合計長に依存するため、これらのパターンから構築するオートマトンは小さいことを直ちに意味します。$N$。 

素朴なアプローチは、これを位置と一致する禁止されたプレフィックスに対する動的プログラミングとして扱うことです。 それは小規模でも機能します$N$、しかし、次の場合は完全に失敗します$N$到達する$10^9$、さえ$O(N)$移行は不可能です。 

パターンが重なると、微妙な失敗モードが現れます。 たとえば、禁止パターンが次の場合、`aa`そして`aaa`、その後、最後の文字が`a`では不十分です。 状態は、禁止されたパターンのどれだけが現在の文字列のサフィックスとして一致したかをキャプチャする必要があります。 そうしないと、トランジションで禁止されている拡張機能が誤って許可されてしまいます。 

もう 1 つの問題は、パターンの重複または重複です。 すべてのステップで各パターンを単純にチェックすると、特にパターンがプレフィックスを共有する場合に、無効な状態を二重にカウントしたり、複数のパターンの重複を見逃したりする可能性があります。 

## アプローチ

 ブルートフォース戦略は、一定の長さの文字列をすべて構築することです。$N$、一度に 1 文字ずつ拡張し、禁止された部分文字列を形成する文字列を拒否します。 これは、枝刈りを伴う深さ優先列挙と同等です。 各ステップで 26 のトランジションを試し、すべての禁止パターンを現在のサフィックスと照合します。 

これは正しいですが、その複雑さは次の点で指数関数的になります。$N$。 たとえ$N=30$、文字列の数は$26^{30}$、それは天文学的な大きさです。 枝刈りを行ったとしても、禁止されたパターンにより、枝刈りが可能になるのに十分な量の枝が早期に除去されるという保証はありません。 

問題の構造は、より効率的なモデルを示唆しています。文字列全体について考える代わりに、現在一致している禁止パターンの量だけを追跡します。 これはまさに、部分文字列マッチングのオートマトンが行うことです。 Aho-Corasick 構造は、各状態が現在の文字列の最長の接尾辞を表し、それが何らかの禁止されたパターンの接頭辞でもある有限オートマトンを構築します。 

このオートマトンを作成したら、問題は長さの歩行を数えるようになります。$N$有向グラフでは、各エッジは 1 つの文字の追加に対応します。 禁止されたパターンを完了したことに対応する状態は無効としてマークされ、除外する必要があります。 

これにより、問題は最大 100 個の状態を含むグラフ内のパスを数えるという問題に軽減されますが、$N$まだです$10^9$。 ここで行列のべき乗が登場します。有効なオートマトンの状態間の遷移行列を構築し、それをべき乗します。$N$。 すべての有効な終了状態の合計が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(26^N)$|$O(N)$| 遅すぎる |
 | オートマトン + 行列累乗 |$O(K^3 \log N)$|$O(K^2)$| 承認済み |

 ここ$K$は、パターンの合計長 (≤ 100) によって制限されるオートマトンの状態の数です。 

## アルゴリズムのチュートリアル

 まず、すべての禁止パターンからトライを構築します。 各ノードは、少なくとも 1 つのパターンのプレフィックスを表します。 次に、Aho-Corasick アルゴリズムとまったく同じように障害リンクを計算し、不一致が発生したときにサフィックスと同等の状態の間で遷移できるようにします。 

1. 各ノードが少なくとも 1 つのパターンのプレフィックスに対応する、禁止パターンのトライを構築します。 完全な禁止パターンを表すノードを終了状態としてマークします。 
2. BFS を使用して障害リンクを構築します。 各ノードについて、障害リンクは、トライ内のプレフィックスでもある最長の適切なサフィックスを指します。 これにより、不一致が発生した場合でも効率的にマッチングを継続できます。 
3. すべての状態とアルファベットのすべての文字について、トライ遷移と失敗リンクを使用して次の状態を計算します。 結果の状態が終端である (禁止されたパターンに一致する) 場合、その遷移は無効としてマークされます。 
4. 移行マトリックスを構築する$T$、 どこ$T[i][j]$状態から何文字続くかを数えます$i$述べます$j$。 遷移は文字ごとに決定的であるため、エントリは通常 0 または 1 になります。 
5. ベクトルを初期化する$v$ステップ 0 のルート状態にあることを表します。 
6. コンピューティング$T^N$2 進累乗を使用し、行列を繰り返し二乗します。 
7. 乗算$v \cdot T^N$、すべての非終端状態を合計して、最終的な答えを取得します。 

これが機能する理由は、文字を追加すると禁止された部分文字列が作成されるかどうかを判断するために必要な情報が各状態で正確にエンコードされるためです。 オートマトンは、禁止されたパターンが完了時に正確に検出され、それが前後しても見逃されることがないことを保証します。 行列のべき乗ステップでは、可能な長さのすべてのウォークをカウントします。$N$この決定論的な遷移システムでは、これは有効な文字列を数えるのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("next", "link", "out", "id")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = False
        self.id = -1

def build_automaton(patterns):
    nodes = [Node()]
    
    for p in patterns:
        v = 0
        for ch in p:
            if ch not in nodes[v].next:
                nodes[v].next[ch] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[ch]
        nodes[v].out = True

    from collections import deque
    q = deque()

    for ch, u in nodes[0].next.items():
        nodes[u].link = 0
        q.append(u)

    for i in range(26):
        c = chr(ord('a') + i)
        if c not in nodes[0].next:
            nodes[0].next[c] = 0

    while q:
        v = q.popleft()
        nodes[v].out |= nodes[nodes[v].link].out

        for i in range(26):
            c = chr(ord('a') + i)
            if c in nodes[v].next:
                nodes[nodes[v].next[c]].link = nodes[nodes[v].link].next[c]
                q.append(nodes[v].next[c])
            else:
                nodes[v].next[c] = nodes[nodes[v].link].next[c]

    for i, node in enumerate(nodes):
        node.id = i

    return nodes

def mat_mul(a, b):
    n = len(a)
    res = [[0]*n for _ in range(n)]
    for i in range(n):
        ai = a[i]
        ri = res[i]
        for k in range(n):
            if ai[k]:
                bk = b[k]
                aik = ai[k]
                for j in range(n):
                    ri[j] = (ri[j] + aik * bk[j]) % MOD
    return res

def mat_pow(mat, exp):
    n = len(mat)
    res = [[0]*n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1

    while exp:
        if exp & 1:
            res = mat_mul(res, mat)
        mat = mat_mul(mat, mat)
        exp >>= 1
    return res

def solve():
    N, Q = map(int, input().split())
    patterns = [input().strip().split()[1] for _ in range(Q)]

    nodes = build_automaton(patterns)
    n = len(nodes)

    trans = [[0]*n for _ in range(n)]

    for v in range(n):
        if nodes[v].out:
            continue
        for c in nodes[v].next.values():
            if not nodes[c].out:
                trans[v][c] += 1

    mat = mat_pow(trans, N)

    start = 0
    ans = 0
    for i in range(n):
        if not nodes[i].out:
            ans = (ans + mat[start][i]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```trie 構造は、すべての禁止された部分文字列をコンパクトにエンコードします。 各ノードは、禁止されたパターンのエンドポイントに対応するかどうかを追跡し、障害リンクにより、重複するパターンに対して遷移が正しく動作することが保証されます。 その後、遷移テーブルは非終端状態に制限されるため、禁止パターンに入るパスは永久に除外されます。 

このオートマトンの隣接行列に行列のべき乗が適用されます。 各乗算ステップは文字列を 1 文字拡張することに対応し、べき乗は圧縮されます。$N$に移行します$O(\log N)$掛け算。 

微妙な点は、終端状態を遷移行列に含めてはいけないということです。そうしないと、無効な文字列が乗算によって伝播してしまいます。 代わりに、禁止されたパターンが一致すると、そのパスがカウントから消えるように、パスを完全に削除します。

 ## 特殊なケース

 エッジ ケースの 1 つは、パターンが別のパターンのプレフィックスである場合に発生します。 例えば、`a`そして`aa`。 オートマトンの中で、到達する`a`はすでに終了状態をマークしているため、この状態からの遷移が有効な文字列を提供し続けないようにする必要があります。 構築では、終端ノードをマークし、それらを遷移行列から除外することでこれを処理します。`a`が形成されると、拡張子はカウントされません。 

もう 1 つのケースは、パターンの重複です。 入力に同じ禁止文字列が複数回含まれている場合でも、トライによって単一の終端ノードが生成されます。 BFS の伝播`out`フラグは、重複が構造や遷移に影響を与えないことを保証します。 

最後のケースは、禁止パターンがない場合です。 オートマトンは 26 文字すべてで自己ループを持つ単一の状態に縮退し、行列のべき乗は計算に還元されます。$26^N$、同じフレームワークによって正しく処理されます。
