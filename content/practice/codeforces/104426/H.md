 ## 解決策
 ## 問題の理解

 2 つの長さのシーケンスが与えられます。$n$。 最初のシーケンスは、ナシームが実際に購入したスムージーを表し、2 番目のシーケンスは、各友人が理想的に受け取りたいものを表します。 どの友人がどのスムージーを受け取るかについて制限はないため、購入したスムージーの割り当てを友人間で自由に変更できます。 目標は、どれだけ多くの友人が自分の好みに合ったタイプのスムージーを受け取ることができるかを最大化することです。 

これを確認するもう 1 つの方法は、サイズのマルチセットが 2 つあることです。$n$: 1 つは購入からのもの、もう 1 つは好みからのものです。 最初のマルチセットと 2 番目のマルチセットの要素を一致させ、等しいペアの数を最大化したいと考えています。 

制約$n, m \le 10^5$これは、線形時間または線形演算時間よりも悪い解は機能しないことを意味します。 すべてのペア間の二次比較アプローチには、最大で次のことが必要になります。$10^{10}$限界をはるかに超えた最悪の場合の動作。 これにより、ペアごとのマッチングではなく、周波数ベースの推論が推進されます。 

一方には重複が大量に存在するが、もう一方には重複が存在しない場合、微妙な落とし穴が発生します。 たとえば、購入したスムージーがすべてタイプ 1 であるが、友人がさまざまなタイプを望んでいる場合、タイプごとにグループ化せずに順番に一致させようとする単純な貪欲な割り当てでは、走査順序に応じて一致を簡単に過少カウントまたは過大カウントする可能性があります。 もう 1 つの問題は、実際には任意に並べ替えることが許可されているにもかかわらず、インデックスの配置が重要であると想定していることです。 

## アプローチ

 強引な解釈は、あらゆる方法で友人にスムージーを割り当ててみて、どれだけ一致できるかを数えることです。 これは、2 つの配列間の代入のすべての順列を生成することに対応します。 順列ごとに、一致する位置の数を計算します。 これは、解空間全体を探索するため正しいですが、大まかに階乗的に増加します。$n!$、これはたとえ$n = 20$。 

より構造化されたブルートフォースの改善は、友達の順序を修正し、各友達に対して未使用のスムージーを割り当てて、一致を再帰的に最大化することです。 各ステップが最大で分岐するため、これは依然として指数関数的です。$n$選択肢。 

重要な観察は、元素の同一性は頻度によってのみ重要であるということです。 特定のスムージーの種類について$x$と表示されるとします。$c_a[x]$購入済みリストの回数と$c_b[x]$設定で回します。 どのように並べ替えても、一致できるのはせいぜい$\min(c_a[x], c_b[x])$タイプの友達$x$、各試合は 1 つのスムージーとそのタイプの 1 つの好みを消費するためです。 逆に、この境界は、各タイプ内で貪欲にペアリングするだけで達成できます。 

これにより、問題はグローバル割り当ての問題から値ごとの独立したカウントに軽減されます。

 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 周波数マッチング |$O(n)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、各スムージー タイプが両方の配列に出現する回数を数え、最小の重複を合計することで解決します。 

1. 購入したスムージー アレイの頻度マップを作成します$a$。 これは、各タイプの利用可能なアイテムの数をキャプチャします。 
2. 設定配列の周波数マップを構築する$b$。 これは、各タイプごとに何人の友達が欲しいかを捕捉します。 
3. いずれかのマップに表示されるすべてのタイプについて、その 2 つの頻度の最小値として一致の数を計算します。 
4. これらの最小値を最終的な答えに累積し、結果を出力します。 

各ステップは、一致がタイプ間で独立しているという考えに基づいて推進されます。 スムージーは一度割り当てられると再利用できないため、タイプごとにカウントすることでリソース消費量を正確にモデル化します。 

### なぜ効果があるのか

 それぞれの値について$x$、有効な割り当てでは、次のタイプのスムージーを最大 1 つだけペアリングできます。$x$タイプが欲しい友達と$x$。 したがって、そのタイプの有効なペアの数は、両方の供給によって上限が制限されます。$c_a[x]$そして要求します$c_b[x]$。 最小値を取ると、両方の制約が同時に満たされます。 異なるタイプが同じ項目をめぐって競合することはないため、すべてのタイプの合計は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    freq_a = {}
    freq_b = {}

    for x in a:
        freq_a[x] = freq_a.get(x, 0) + 1

    for x in b:
        freq_b[x] = freq_b.get(x, 0) + 1

    ans = 0
    for x in freq_a:
        if x in freq_b:
            ans += min(freq_a[x], freq_b[x])

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、カウントを 2 つの辞書に分離します。 実装上の微妙な選択の 1 つは、次のキーのみを反復処理することです。`freq_a`そして存在を確認します`freq_b`、これにより、考えられるスムージー タイプの範囲全体を反復処理する必要がなくなります。$m$、未使用の値が含まれる場合があります。 

もう 1 つの重要な詳細は、`get`重要なエラーを回避し、コードをクリーンで線形に保つための更新頻度。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    freq_a = {}
    freq_b = {}

    for x in a:

    for x in b:

    for x in freq_a:
        if x in freq_b:

    return str(ans).strip()

 ## 特殊なケース

 重要なエッジケースとは、1 つのタイプが片側にのみ表示される場合です。 たとえば:

 入力:```
3 3
1 1 1
2 2 2
```アルゴリズムが構築される`freq_a = {1: 3}`そして`freq_b = {2: 3}`。 キーの交差がないため、ループは何も寄与せず、答えは 0 になります。これは、友人の好みを満たすことができないため、現実と一致します。 

もう 1 つの特殊なケースは、重度の不均衡です。 

入力:```
5 5
1 1 1 1 1
1 1 2 2 2
```周波数は以下を与えます:

 タイプ 1 は min(5, 2) = 2 に寄与し、タイプ 2 は暗黙的に min(0, 3) = 0 に寄与するため、答えは 2 になります。このアルゴリズムは、キー間でタイプが混在することがないため、タイプ 2 の設定に余分なタイプ 1 スムージーを過剰に割り当てることを正しく回避します。 

これらのケースは、周波数ベースの分解が極度のスキューの下でも正確さを維持することを裏付けています。
