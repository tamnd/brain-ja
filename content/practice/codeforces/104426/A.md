 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 2 人のプレーヤーが、この配列からインデックスの互いに素なサブセットを選択します。 アブドゥルラフマン氏は次の場所まで迎えに行くことを許可されている$P$インデックス、および Hazem が取得できるのは$Q$インデックス。 アブドゥルラフマンの寄与は選択したインデックスの値の合計であり、ハゼムの寄与は選択したインデックスの値の合計であり、目的はアブドゥルラフマンの合計とハゼムの合計の差を最大化することです。 

重要な構造は、すべての指標がアブドゥルラフマンのスコアにプラスに寄与するか、ハゼムの選択によってマイナスに寄与するか、または完全に無視されるかのいずれかであるということです。 両方のプレイヤーが独立して最適化していますが、ばらばらの選択肢に制限されているため、各要素がアブドゥルラフマンに割り当てられるか、ハゼムに割り当てられるか、または誰にも割り当てられないかを事実上決定し、各側が取得できる要素の数についてのグローバルな上限を設けています。 

この制約により、サブセットを明示的に考慮しようとする解決策は不可能であることが明らかです。 合計あり$n$まで$10^5$テスト全体にわたって、そして最大で$10^5$テスト ケースでは、テストごとに線形またはほぼ線形よりも悪いものは遅すぎます。 これにより、指数関数的な選択が即座に排除されたり、$O(n^2)$貪欲なシミュレーション。 

すべての値が負であるか、すべてが正である場合、微妙なエッジ ケースが発生します。 すべての値が負の場合、$P = 0$, アブドゥルラフマンはハゼムの選択をまったく相殺できないため、ハゼムは可能な限り最も負の値を選択します（負の値を引くことで差が大きくなるため）。 逆に、すべての値が正の場合、$Q = 0$, アブドゥルラフマンは、利用可能な最大の要素を単純に取得します。 正の割り当てと負の割り当ての間の容量の相互作用を無視する単純な貪欲は、混合の場合に失敗する可能性があります。 

## アプローチ

 強引な見方では、アブドゥルラフマンが最大で使用するものを尊重しながら、各要素をアブドゥルラフマン、ハゼム、または未使用の 3 つのカテゴリに割り当てるあらゆる方法を試みます。$P$せいぜいエレメントとハゼム$Q$。 これは組み合わせ爆発につながります。制約を無視したとしても、これは$3^n$割り当てがあり、プルーニングを行ったとしても、有効な割り当ての数は依然として指数関数的に増加します。 すべての有効な構成を調査するため、正確性は重要ではありませんが、それはすぐに不可能になります。$n$小さな値を超えています。 

重要な観察は、各要素の決定は位置ではなく、他の要素との相対的な値のみに依存するということです。 要素がアブドゥルラフマンに割り当てられている場合、それはプラスに寄与します。 Hazem に割り当てられた場合、最終的な式に実質的にマイナスの影響を及ぼします。 未使用の場合、貢献度はゼロになります。 したがって、すべての要素には値を持つ 3 つの「モード」があります。$+a_i$、$-a_i$、 または$0$、各モードの使用回数にはグローバル制限があります。 

この問題は、以下を選択するものとして再解釈できます。$P+Q$要素の合計。選択された各要素には符号が割り当てられます。 Abdulrahman は次のように与えます。$+a_i$、ハゼムが与える$-a_i$。 要素を選択することにした場合、最適な割り当ては次のいずれかによって決まります。$a_i$ポジティブかネガティブかです。 正の数は、可能であればアブドゥルラフマンに送られることが望ましいですが、ハゼムに渡されるのではなく無視されるべきです。 負の値を減算するとスコアが増加するため、負の値を Hazem に割り当てる方が適切です。 

これは、最適な割り当てに応じて要素の絶対寄与利得によって要素を並べ替えることを示唆しています。 各要素は可能な限り最大限の貢献をします。$\max(a_i, -a_i)$、どのプレイヤーに渡すかによって異なります。 ただし、ポジティブな割り当てとネガティブな割り当てに対して個別のクォータを尊重する必要があるため、慎重に処理しない限り、直接貪欲ではやや不十分になります。 

正しい方法は、問題を 2 つのフェーズに分割することです。絶対値の降順で要素を取得することを検討しますが、残りの容量を考慮しながらそれらを最適に割り当てます。$P$そして$Q$。 各要素はどちらの側でより高いゲインが得られるか評価されます。 もし$a_i > 0$、アブドゥルラフマンさんはそれを摂取することで利益を得ます。 それ以外の場合、ハゼムはそれを取ることで利益を得ます（それを減算するとスコアが増加するため）。 私たちは常に、より多くの利益を得る側に要素を割り当てますが、それはその側にまだ能力がある場合に限ります。 そうでない場合、それでもスコアが改善される場合は、反対側に戻ります。 

この貪欲さが機能するのは、すべての要素が独立して固定の最適ゲインに寄与し、容量制約を除いて要素間に相互作用がないためです。容量制約は、最も影響の大きい選択肢を最初に処理することで解決されます。

 ## アルゴリズムのチュートリアル

 各要素をアブドゥルラフマンまたはハゼムに割り当てることができるものとして扱いますが、符号に応じてゲインが異なります。 影響の少ない決定に限られたスロットを無駄にしないように、より大きな絶対的な影響を優先する順序で要素を処理します。 

## アルゴリズムのチュートリアル

 1. 各要素の絶対値を計算します。これは、代入の方向に関係なく、その要素が答えにどれだけ強く影響するかを表します。 後で誤って選択すると、遅らせるよりもコストが高くつくため、大きな影響を最初に優先します。 
2. 配列のインデックスを絶対値の降順にソートします。 これにより、要素を割り当てるときに、常に最も価値のある決定を最初に処理することが保証されます。 
3. 残容量を維持する$remP = P$そして$remQ = Q$、答えをゼロに初期化します。 これらは、各プレイヤーがまだ取得できる要素の数を表します。 
4. ソートされた順序で要素を繰り返し処理します。 要素ごとに$a_i$、その割り当てを決定します。 もし$a_i > 0$、アブドゥルラフマンはゲインと一緒に摂取することで利益を得ます$+a_i$、一方、ハゼムがそれを取ると結果は次のように減少します。$a_i$。 もし$a_i < 0$、ハゼムがそれを取ると利益が得られます$+|a_i|$マイナスを減算すると差が改善されるためです。 
5. 現在の要素の優先側にまだ容量が残っている場合は、そこに割り当て、その容量を減らしながらそれに応じて回答を更新します。 正の値の場合はアブドゥルラフマンが優先され、負の値の場合はハゼムが優先されます。 
6. 優先側がいっぱいの場合は、制約の下で結果がさらに改善される場合にのみ、要素をもう一方の側に割り当てます。 どちらの側もそれを受け入れることができない場合は、スキップしてください。 

絶対値による処理が機能する理由は、容量が唯一の結合制約であるため、影響の大きい要素が決定されると、後で合計ゲインを低下させずに小さな要素と交換することによって改善することができないためです。 

## なぜ機能するのか

 各要素には、アブドゥルラフマンに与えるか、ハゼムに与えるかの 2 つの重要な意味のある割り当てがあります。 これらはゲインに相当します$a_i$そして$-a_i$。 アルゴリズムは常に、より高いゲインの割り当てを最初に優先し、最終的な答えをどの程度変更できるかが降順に要素を処理します。 これにより、2 つの制約されたビンを使用して、独立した重み付けされた選択肢に対して貪欲な順序付けが作成されます。 より低い絶対値の決定をより高い絶対値の決定と交換すると、常に合計スコアが増加するため、最適なソリューションは価値を失うことなく貪欲なソリューションに変換でき、最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, P, Q = map(int, input().split())
    a = list(map(int, input().split()))

    items = [(abs(x), x) for x in a]
    items.sort(reverse=True)

    res = 0
    remP, remQ = P, Q

    for _, x in items:
        if x > 0:
            if remP > 0:
                res += x
                remP -= 1
            elif remQ > 0:
                res -= x
                remQ -= 1
        else:
            if remQ > 0:
                res += -x
                remQ -= 1
            elif remP > 0:
                res += x
                remP -= 1

    print(res)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```コードは、最も影響力のある要素が最初に処理されるように、各値とその絶対値を組み合わせて並べ替えることから始まります。 2 つのカウンターは、各プレイヤーがまだどれだけの選択肢を持っているかを追跡します。 正の値は、スコアを直接増加させるため、最初にアブドゥルラフマンに提供され、その容量が使い果たされた場合にのみ、それらをハゼムに割り当てることを検討します。 負の値は、最終的な差分で正の寄与に変換されるため、対称的に Hazem に割り当てるのが最適です。 

主な微妙な点は、すべての要素が残りの制約の下で最適に寄与する必要があるため、「間違った」側にまだ容量がある場合に、価値のある要素の割り当てをスキップしないことです。

 ## 特殊なケース

 いつ$P = 0$、アルゴリズムはアブドゥルラフマンに正の値を割り当てることは決してないため、すべての寄与はハゼムが負の値を選択することから来ている必要があります。 入力の場合:```
n = 3, P = 0, Q = 2
a = [5, -2, -7]
```ソート順序は 7、5、2 です。最初の 2 つの負の大きさの要素は -7 と -2 で、どちらも Hazem に割り当てられており、寄与度を示します。$7 + 2 = 9$、Q が使い果たされたため、5 は無視されます。 Hazem に 5 を割り当てるとスコアが減少するため、これは最適な動作と一致します。 

すべての値が正の場合、$Q = 0$、アブドゥルラフマンのみが貢献しています。 のために：```
n = 3, P = 2, Q = 0
a = [1, 10, 5]
```アルゴリズムは、Abdulrahman に対して 10 と 5 を受け取り、1 をスキップして 15 を生成します。Hazem に割り当てようとする試みは不可能であるため、最大値を貪欲に選択することが最適です。 

すべての値が負で、両方のプレイヤーに能力がある場合、Hazem は最も負の値を最初に取得します。これは、それらの値が無効化されたときに最大のゲインを与えるためです。 このアルゴリズムでは当然、値の大きさが優先され、アブドゥルラフマンが残りのスロットを消費する前に、ハゼムが最初に最大の改善を獲得することが保証されます。
