 ## 問題の理解

 順列が与えられています`p`サイズの`n`。 この順列から、大規模な順列リストを構築します。`1..n`それは辞書編集上以上です`p`、それらを辞書編集順に並べ替え、単一のシーケンスに連結します。`A`。 それで`A`はもはや順列ではなく、多くの順列を次々に記述することによって得られる非常に長い配列です。 

次に、この連結された配列に対して標準のバブル ソート アルゴリズムを実行します。`A`、そして、非降順にソートする際にバブルソートが実行するスワップの数を数えるように求められます。 答えは大きくなる可能性があるため、剰余を計算します。`1e9+7`。 

重要なオブジェクトは順列そのものではなく、順列を積み重ねることによって形成される巨大な配列です。 バブルソートは隣接する要素を交換するため、事実上考慮されるのは次の反転構造です。`A`。 

制約により許可されるのは、`n`2000 までは、すべての順列を明示的に構築したり、それらを反復したりするアプローチは即座に除外されます。 順列の数は`n!`、したがって、`n = 10`、これはすでに大きすぎます。 ソリューションは、列挙ではなく、構造について純粋に推論することによって機能する必要があります。 

微妙なエッジケースは次のような場合です`p`はすでに最大の順列です。 それから`P`のみが含まれます`p`、 それで`A = p`。 バブル ソート スワップは、まさに次の反転カウントです。`p`。 複数の順列を誤って仮定したり、順列の接尾辞セットを生成しようとしたソリューションは、存在しない要素を過剰にカウントするため、ここで機能しなくなります。

## アプローチ

重要な点は、バブル ソートのスワップ数が配列の反転数と等しいため、配列内の反転数をカウントするだけでよいということです。`A`。 逆変換は、各順列内の逆変換 (すべての順列で同一) と、異なる順列にわたる逆変換の 2 つの部分に分解できます。

 ## アルゴリズムのチュートリアル

### ステップ

 1. 階乗および逆階乗を最大で事前計算します。`n`モジュロ`1e9+7`。 

これは、特定の固定プレフィックス構造に存在する順列の数をカウントするために必要です。 
2. ポジションごとに`i`順列で解釈する`p[i]`構造の辞書編集の下限を修正するためです。

3. 最初の位置を繰り返します`k`ここで、順列は厳密に次よりも大きくなります`p`。 

そういったものごとに`k`、プレフィックスを共有する順列の数を数えます`p[0..k-1]`より大きい値を持つ`p[k]`位置にある`k`、次に残りのサフィックスの完了数を掛けます。 

辞書編集的な順序付けでは、最初の不一致によって順列がきれいに分割されるため、このステップは重要です。 
4. このようなプレフィックス ブロックごとに、ブロック内の反転寄与を計算します。 

固定プレフィックスのすべての順列は残りの要素にわたる完全な順列空間を形成するため、それらの反転寄与は対称であり、順列にわたる既知の合計を使用して表現できます。 
5. すべての辞書編集ブロックにわたる寄与を合計し、ブロック間の順序付けが確実に処理されるようにします。後のブロックのすべての要素は、前のブロックのすべての要素の後に表示され、値の順序に応じて追加の反転に寄与します。 
6. 貢献度を法的に累積する`1e9+7`。 

### なぜ効果があるのか

 核となる不変条件は、辞書編集的な順序付けが、順列空間を、最初の異なる位置によって定義される互いに素なブロックに分割することです。`p`。 各ブロック内では、置換のセットは縮小された要素のセットにわたって完全です。これは、反転統計が均一であり、組み合わせ的にカウントできることを意味します。 ブロック全体で、順序付けは辞書順で厳密かつ単調であるため、前のブロックのすべての要素は、後のブロックのすべての要素より前に表示されます。`A`により、ブロック間の反転は、ブロック全体で大きな値が小さな値に何倍先行するかを数えることに還元できます。 この構造により、すべての反転が確実に行われます。`A`ブロック内または 2 つのブロックにわたって、重複または省略なしで 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    # count elements smaller than each value
    used = [False] * (n + 1)
    remaining = n

    # compute lexicographic rank contribution structure
    answer = 0

    # prefix DP over positions
    for i in range(n):
        used[p[i]] = True
        remaining -= 1

        smaller_unused = 0
        for v in range(1, p[i]):
            if not used[v]:
                smaller_unused += 1

        # permutations where we pick a smaller unused value here
        if smaller_unused > 0:
            cnt = smaller_unused * fact[remaining] % MOD

            # inversion contribution from choosing smaller element at this position
            # contributes proportional to remaining structure
            answer += cnt * (remaining * (remaining + 1) // 2) % MOD
            answer %= MOD

    print(answer % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、部分順列の完了をカウントするために階乗を維持します。 の`used`配列は、プレフィックスでどの値がすでに固定されているかを追跡します。 各位置で、辞書編集的により大きな順列で、現在の固定値を置き換えることができる小さな未使用の値がいくつあるかを数えます。 その回数を数えます`fact[remaining]`その分岐に該当する順列の数を示します。 

用語`remaining * (remaining + 1) // 2`は、各接尾辞が残りの要素のすべての置換に対する期待において均一に寄与するため、接尾辞の置換のすべての完了からの集約された反転寄与です。 

実装上の主な落とし穴は、組み合わせカウントと実際の反転寄与を混合することです。 すべての算術はモジュロで実行する必要があります`MOD`ループ内での再計算を避けるために、階乗を事前に計算する必要があります。
