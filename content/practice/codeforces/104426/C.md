 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれの演習では、さまざまな問題の難しさから始めます。 これらの値のサブセットは削除できますが、少なくとも 1 つの要素を残さなければなりません。 削除後、残りのセットの「スコア」はその算術平均として定義されます。 

タスクは、平均ができるだけ小さい、空ではないサブセットを選択することです。 

制約はすぐに解空間を形成します。 すべてのテスト ケースの要素の合計数は最大 100,000 であるため、テスト ケースごとに 2 次的なアプローチや、サブセットを繰り返し再スキャンするアプローチは失敗します。 テスト ケースごとに線形以上のものが必要です。 

微妙な問題は、最適なサブセットが必ずしもすべての要素であるわけではない、あるいは最小要素だけであるとは限らないことです。 たとえば、`[100, 1, 2]`、摂取のみ`1`平均を与える`1`、これが最適です。 しかし、`[1, 100, 100]`、摂取のみ`1`ほとんどの要素が大きいにもかかわらず、依然として最適です。 これは、大きな要素が平均を下げるのに決して役立たないことを示唆していますが、その理由を正確に理解する必要があります。 

選択範囲のサイズに関してエッジケースが発生します。 

すべての数値が等しい場合、どのサブセットも同じ平均値を持つため、要素を削除しても何も起こりません。 素朴なアプローチでも複雑なサブセットの評価を試みる可能性がありますが、答えはその値のままです。 

もう一つのコーナーは、一意の最小要素がある場合です。 それでも、より大きな要素を追加すると平均が厳密に増加するため、最良のサブセットは最小値を含むシングルトンのままになります。 

誤った推論による主なリスクは、平均の「バランスをとる」ために複数の要素が必要であると想定していることです。 制約のない純粋な平均化の下では、その直感は誤りです。 

## アプローチ

 ブルートフォース解釈では、空でないすべてのサブセットを考慮し、その合計とサイズを計算し、最小平均を追跡します。 これは正しいですが、すぐには実行できません。 サブセットの数は指数関数的です。具体的には、$2^N - 1$、これは$N = 10^5$反復することはおろか、表現することすら不可能です。 

要素を追加するときに平均がどのように動作するかを理解する必要があります。 平均値を含む選択されたセットがあると仮定します。$x$。 新しい要素を追加すると$a$、新しい平均は次のようになります$$\frac{S + a}{k + 1}$$どこ$S/k = x$。 この新しい平均は厳密に次の値よりも小さいです$x$場合のみ$a < x$。 これにより、構造的な洞察が得られます。平均を改善するには、現在の平均よりも小さい要素を追加する必要があります。 

ここで、任意の有効なサブセットから開始することを検討してください。 複数の要素が含まれている場合、その平均は少なくともそのサブセット内の最小要素であり、現在の平均より大きい要素を含めても役に立ちません。 これは、貪欲な縮小の議論を示唆しています。要素を削除しても、最小平均に対する制御が強化されることはなく、要素を追加しても、それがさらに小さくならない限り、既存の最小要素を上回ることはできません。 

したがって、最適な戦略は非常に単純な観察に集約されます。単一の要素からなるサブセットを取得することで可能な限り最良の平均が達成され、それを最小化するために配列内の最小の要素を選択します。 

以下でアプローチを比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサブセットを列挙する | O(2^N) | O(N) | 遅すぎる |
 | ソートまたは DP を介してすべてのサブセット平均を確認します。 O(N^2) 以上 | O(N) | 遅すぎる |
 | 最小要素を取得 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、一連の難易度を読み取ります。 削除はテスト ケース間で相互作用しないため、各テストを独立して扱います。 
2. 検出された最小値を追跡しながら、配列を 1 回スキャンします。 この考え方は、最終的なサブセット平均の可能な限り最良の候補を維持することです。 
3. すべての要素を処理した後、最小値を出力します。 これは、その単一の最小要素のみからなるサブセットを選択することに対応します。 

### なぜ効果があるのか

 数値の平均はセット内の最小値より小さくなることはできないため、どのサブセットにも少なくともその最小要素である平均があります。 したがって、すべての有効なサブセットの平均は、配列のグローバル最小値によって下限されます。 この境界は、その最小要素のみを含むサブセットを選択することによって達成できるため、他の構築ではこれより小さい値を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    print(min(arr))
```このソリューションは、テスト ケースごとに単一の最小値を計算することに完全に依存しています。 テスト ケースをループすることで、入力の分離が確実に尊重されます。 使用する`min(arr)`テスト ケースごとの配列サイズが少なくとも 1 であるため、サブセットが空でなくてはいけないという要件に違反することがないため、安全です。 

重要な実装の詳細は、サブセットの構築や追跡をまったく試みないことです。 単一の値に数学的に削減されることを考慮すると、そのような試みは不要なオーバーヘッドになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(N) | 各配列を 1 回スキャンして、その最小値 | を計算します。 
| スペース | O(1) おまけ | 実行中の最小値のみが保存されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        out.append(str(min(arr)))
    return "\n".join(out)

# provided sample-style tests
assert run("1\n3\n800 4000 969\n") == "800"
assert run("1\n4\n5 5 5 5\n") == "5"

# custom cases
assert run("1\n1\n1234\n") == "1234", "single element"
assert run("1\n5\n10 9 8 7 6\n") == "6", "strictly decreasing"
assert run("1\n5\n6 7 8 9 10\n") == "6", "strictly increasing"
assert run("2\n3\n2 100 3\n4\n1 1000 1000 1000\n") == "2\n1", "multiple tests"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 1234 | 最小境界の場合 |
 | 配列を減少させる | 6 | 最後の分 |
 | 配列を増加する | 6 | 開始時の分 |
 | 複数のテスト | 2 / 1 | ケース間の正確性 |

 ## 特殊なケース

 単一要素の配列は最も厳しい制約です。唯一の有効なサブセットは要素自体であるため、アルゴリズムはそれを直接出力します。 入力用`[1234]`の場合、スキャンは最小値を 1234 に設定し、曖昧さなくそれを返します。 

最小値が複数回出現する配列の場合、次のようになります。`[2, 100, 2, 50]`の場合、アルゴリズムは複数の位置で 2 に遭遇しますが、実行最小値は全体を通して 2 のままで、出力は 2 です。他の要素を含むサブセットは平均を 2 未満に減らすことができないため、重複しても動作は変わりません。 

次のような厳密に配列を増加させる場合`[1, 2, 3, 4]`の場合、最小値は最初の要素ですぐに見つかります。 後の要素の方が大きくても、アルゴリズムは現在の最良の値を置き換えることはなく、すべての加算を正しく無視します。 

これらのケースは、解法がグローバル最小値の特定のみに依存し、順序付けやグループ化の構造的特性が最終結果に影響を与えないことを確認します。
