 ## 解決策
 ## 問題の理解

 私たちは指定されたルートを持つ木を与えられます。 タスクは、頂点の順列を割り当てることです。つまり、各頂点が 1 から n までの一意の整数を受け取り、ラベルがルートからリーフの各方向に沿って厳密に増加するようにします。 形式的には、ノード u がルートから別のノード v へのパス上にある場合は常に、u に割り当てられる値は v に割り当てられる値より小さくなければなりません。すべての有効な割り当ての中で、値を頂点順序 1 から n でリストするときに、辞書編集的に最小のシーケンスが必要になります。 

これは隠れた一般的な半順序問題ではなく、まさにルートからノードへの各パスが厳密に増加する必要があるルート付きツリー制約です。 ツリーは優先順位制約の階層を誘導しますが、任意の DAG とは異なり、各ノードには単一の祖先チェーンがあります。 

2・10^5 までの制約 n は、順列を列挙したり、状態に対してグローバルな並べ替えを実行しようとするソリューションを即座に排除します。 O(n log n) であっても許容されますが、これはノードごとの本質的に線形作業である場合に限ります。 二次関数や階乗関数は不可能です。 ツリー構造は、慎重な順序での DFS または BFS トラバーサルを示唆しています。 

辞書編集上の最小性から微妙な問題が発生します。 有効な順列を生成することのみを要求された場合は、任意に深さの増加順にラベルを割り当てることができます。 ただし、辞書編集的な最小性により、初期の頂点はできるだけ小さい値を受け取るように強制され、出力は頂点 ID によってインデックス付けされるため、走査順序ではなく、番号の小さい頂点の値を最初に最小化する必要があります。 

もう 1 つのエッジ ケースは、ルートが頂点 1 ではない場合です。多くの単純な DFS アプローチは、ルート 1 を想定し、昇順の検出順序を割り当てます。 辞書編集的な順序付けは、訪問順序ではなく頂点インデックスに依存するため、これは失敗します。 もう 1 つの落とし穴は、ノードの子を頂点ラベルの昇順で処理することを強制せずに DFS 順序を使用することです。これは、初期の割り当てを最小限に抑えるために必要です。 

## アプローチ

 ブルートフォース解釈では、順列を構築し、妥当性をチェックしようとします。 1 から n までのすべての順列を生成し、各エッジが祖先の順序を尊重しているかどうかを検証することを想像できます。 有効性をチェックするには、祖先関係を計算するか、候補ごとに DFS を実行する必要があり、これはチェックごとに O(n) です。 これはすでに O(n! · n) となり、n = 12 の場合でも完全に実行不可能です。 

もう少し構造化されたブルート フォースは、制約を半順序として扱い、常に利用可能な最小の頂点を選択しながらトポロジカル ソートを試みます。 ただし、重要な問題は、制約が任意のエッジではなく、ルート付きツリー内の祖先関係であることです。 この構造は、ノードに値が割り当てられると、その子孫はすべて後から来る必要があり、異なるサブツリー間の相対順序は自由であることを意味します。 

重要な点は、制約がルートからリーフへのパスに沿った順序のみを強制することです。 これは、構築する順列がルート付きツリーの部分順序の線形拡張である必要があることを意味します。 辞書編集上最小のこのような線形拡張は、親が子の前に割り当てられる必要があることを尊重しながら、常に最小の利用可能なラベルを頂点 ID の昇順で最も早い頂点に割り当てることによって取得されます。 

これにより、問題は、各ノードがそのすべての子孫に先行するルート付きツリーのトポロジー的順序付けを構築することになり、すべての有効な順序の中で、ラベル配列 p[1..n] を辞書編集的に最小にする順序が必要になります。 これは、ラベルを 1 から n まで昇順に割り当て、親がすでに割り当てられている最小番号の頂点を常に選択するプロセスをシミュレートすることによって実現されます。

どのノードが次のラベルを受信できるかを維持します。ノードは、その親がすでにラベルを受信すると利用可能になります。 各ステップで、インデックスが付けられた最小の利用可能なノードを選択します。 この貪欲な選択により、辞書編集上の最小性が保証されます。これは、 p 内の以前の位置がより小さいラベルに対応し、制約と一致する可能な限り小さい頂点インデックスにラベルを常に昇順で割り当てるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を順列 p[1..n] を構築するものとして再解釈します。ここで、p[v] は頂点 v に割り当てられたラベルですが、逆に考える方が簡単です。ラベルを 1 から n まで順番に割り当てます。 

1. x でツリーをルートし、隣接リストを計算します。 また、x から始まる DFS または BFS を使用して親子関係を追跡します。 これにより、どのノードが他のどのノードに依存しているかを確実に知ることができます。 
2. 利用可能な頂点の優先順位構造 (最小ヒープ) を維持します。 頂点は、その親にすでにラベルが割り当てられている場合に使用できます。 最初は、親制約がないため、ルートのみが使用可能です。 
3. ヒープから最小のインデックス付き頂点を繰り返し抽出し、それに昇順で次のラベルを割り当てます。 頂点 u にラベルを割り当てたら、u を処理済みとしてマークします。 
4. u のすべての子 v について、その依存関係をデクリメントし、すべての前提条件が満たされている場合 (ツリー内ではその親が処理されていることを意味します)、v をヒープにプッシュします。 
5. すべての頂点にラベルが割り当てられるまで続行します。 

設計上の重要な選択は、DFS または BFS の順序で最も早く現れる頂点ではなく、常に利用可能な最小の頂点を選択することです。 これが辞書編集上の最適性を強制するものです。 

それが機能する理由は、2 つの結合された不変条件に関係しています。 まず、頂点は、その親にすでに小さいラベルが割り当てられているときに正確に使用可能なセットに挿入されるため、祖先制約は常に満たされます。 第 2 に、どのステップでも、次に小さいラベルを合法的に受け取ることができるすべての頂点の中で、最小のインデックスを選択することで、2 つの有効な解が異なる可能性がある結果の順列内の最も早い位置が最小化されます。 逸脱があると、最初の異なるインデックスで p が増加し、辞書編集上の最小性に違反します。 ツリー制約は祖先に沿って単調であるため、ノードが使用可能になると、有効性を損なうことなく安全に遅延させることができますが、インデックスが小さいノードを遅延させるとすぐに辞書編集上の順序が悪化するため、すぐに選択する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    order = []
    stack = [x]
    parent[x] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] != 0:
                continue
            parent[v] = u
            stack.append(v)

    import heapq
    heap = []
    assigned = [False] * (n + 1)

    heapq.heappush(heap, x)
    label = 1
    p = [0] * (n + 1)

    while heap:
        u = heapq.heappop(heap)
        assigned[u] = True
        p[u] = label
        label += 1

        for v in g[u]:
            if parent[v] == u and not assigned[v]:
                heapq.heappush(heap, v)

    print(*p[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、明示的な親配列を使用してルート付きツリーを構築し、次に最小ヒープを使用して、現在利用可能な最小の頂点を常に選択します。 各頂点には昇順でラベルが割り当てられ、祖先制約が確実に満たされるようにします。 

親配列は、ノードがいつ適格になるかを定義するため、非常に重要です。 親が処理された後にのみ子をプッシュします。 ヒープは、有効な候補の中から頂点インデックスを選択することにより、辞書編集上の最小性を保証します。 

実装の微妙な詳細は初期化です。最初はルートのみが挿入されます。 誤ってすべてのノードをプッシュしたり、ヒープなしで DFS 順序でトラバースしたりすると、結果が有効なトポロジ順序付けのままであっても、辞書編集条件が失敗する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import sys
    input = sys.stdin.readline

    n, x = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    parent[x] = -1

    import heapq
    heap = [x]
    assigned = [False] * (n + 1)
    p = [0] * (n + 1)
    label = 1

    while heap:
        u = heapq.heappop(heap)
        assigned[u] = True
        p[u] = label
        label += 1
        for v in g[u]:
            if parent[v] == 0 and v != x:
                parent[v] = u
            if parent[v] == u and not assigned[v]:
                heapq.heappush(heap, v)

    return " ".join(map(str, p[1:]))

 ## 特殊なケース

 エッジ ケースの 1 つは、ツリーが単一のチェーンである場合です。 ヒープには各ステップでノードが 1 つだけ含まれるため、アルゴリズムは単純な線形トラバーサルに縮退します。 たとえば、ルート 1 とエッジ 1-2、2-3、3-4 では、ヒープは決して分岐せず、ラベルは厳密なパス順序で割り当てられ、必要に応じて 1 2 3 4 が生成されます。 

もう一つの例は、葉に根を張った星です。 ルートが 1 で、他のすべてのノードがそれに接続している場合、ルートを割り当てた後、すべての子が同時に使用可能になります。 ヒープにより、辞書編集上の最小化に必要な頂点の昇順で処理されることが保証されます。 ヒープがなければ、DFS 順序は有効な順列を生成しますが、必ずしも最小の順列が生成されるわけではありません。 

より微妙なケースは、ルートが頂点 1 ではなく、最小の頂点がツリーの奥深くにある場合です。 アルゴリズムは依然として親チェーンが解決された場合にのみそれを検出し、利用可能になるとヒープの順序付けによりすぐに選択されます。 これにより、辞書編集上の順序が損なわれる可能性がある、より大きなインデックス ノードの早期割り当てが防止されます。
