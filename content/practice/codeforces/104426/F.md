 ## 解決策
 ## 問題の理解

 バイナリ配列と固定ウィンドウ サイズが与えられます。 1 回の操作で、任意の連続セグメントを正確に選択します。$k$要素を作成し、その中のすべての値を反転して、0 を 1 に、1 を 0 に変換します。 申請できるのは最大でも$n$目標は配列を完全に修正することではなく、ゼロの数を減らして最大で$\lfloor k/2 \rfloor$。 

重要な問題は、すべての操作が大きな構造化された影響を与えることです。 単一の動きは正確に影響を与えます$k$フリップはモジュロ 2 を累積するため、連続する位置と重複する動きは自明ではない方法で相互作用します。演算を最小化することは求められず、許容範囲内で有効なシーケンスを構築することだけが求められます。 

制約$n \le 10^6$ウィンドウを反転したり、操作ごとにスキャンを繰り返したりする二次シミュレーションは除外されます。 たとえ$O(nk)$アプローチは直ちに不可能です。 解決策は線形または線形に近いものでなければならず、以前の位置を繰り返し再検討することは避けなければなりません。 

単純な戦略では、貪欲にゼロを 1 つずつ修正し、ゼロに遭遇するたびにウィンドウを反転しようとします。 後の位置を固定することを目的とした反転によって以前の作業が取り消される可能性があるため、これは失敗します。 たとえば、次の場合$k=3$そして、位置 1 で反転してインデックス 2 を固定します。その後、位置 2 で反転すると、インデックス 3 を固定しながらインデックス 2 が再び元に戻る可能性があります。この相互作用は局所的に安定していません。 

もう 1 つの微妙な失敗例は、境界依存に起因します。 貪欲なアルゴリズムが常に最初のゼロで反転する場合、問題は有効な長さが少なくなる最後の方向に進む可能性があります。$k$セグメントが存在し、最終的に残りのゼロを有効な演算開始位置でカバーできない状態に達します。 

問題の実際の構造は、フリップが固定長間隔にわたる累積的なパリティ演算であるということです。 これは、プロセスを左から右へ制御されたパリティ パターンを構築するものとして扱うことを示唆しています。 

## アプローチ

 ブルートフォース手法では、配列をシミュレートし、最大でもすべての可能なシーケンスを試行します。$n$操作、ゼロの数を減らす有効な操作を選択します。 各操作には反転が含まれます$k$要素があるため、単一のシミュレーションでも$O(n)$。 まで$n$操作、これは次のことにつながります$O(n^2)$実現不可能な時間$10^6$。 

重要な観察は、実際には将来の行動をグローバルに決定する必要がないということです。 代わりに、位置の処理が完了したら、左から右への不変条件を適用できます。$i$、その最終値は再び影響を受けることはありません。 これは、現在各インデックスをカバーしているアクティブなフリップの数を追跡する差分配列を使用して、以前のフリップの効果を維持する場合に可能です。 

各操作を範囲の切り替えとして解釈し、配列を直接変更する代わりに、各位置に影響を与えるフリップのパリティを追跡します。 インデックスに到達したら$i$、現在の実効値が 0 か 1 であるかがわかります。それが 0 であり、長さを配置する余地がまだある場合は、$k$から始まる操作$i$、すぐに適用し、インデックスを確保します$i$最終結果では 1 になります。 以降の操作はインデックスに影響を与えることができないため、この貪欲な選択は安全です$i$常に前に進み、現在のインデックス以降でのみ操作を開始する場合は、もう一度繰り返します。 

このプロセスにより、スライディング パリティ ウィンドウを維持し、各位置で反転するかどうかを貪欲に決定するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは、各位置に影響を与えるアクティブなフリップの数を知るための差分配列を維持します。 また、実行中のパリティ変数も維持します。 

1. 配列を初期化する`diff`サイズの$n+1$フリップ効果の開始と終了、および変数を追跡するため`cur`現在のフリップパリティを保存します。 操作のリストも管理します。 
2. インデックスから反復処理する$i = 0$に$n-1$。 各位置で最初に更新します`cur`申請することで`diff[i]`これにより、前のフリップ間隔がここで始まるか終了するかがわかるためです。 このステップにより、`cur`現在の要素が奇数回反転されたか偶数回反転されたかを表します。 
3. の実効値を計算します。$a[i]$として$a[i] \oplus cur$。 これは、これまでのすべての操作後に実際に表示される値です。 
4. 終わりに近づきすぎると、$i > n-k$、新しい長さを開始することはできません-$k$フリップします。 その場合、この立場を変更することはできないので、単に続行します。 
5. 実効値が$i$が 0 の場合は、すぐに修正する必要があります。 位置でフリップを開始します$i$、 記録$i+1$操作として差分配列を更新します。次の位置に 1 を追加します。$i$そして次の時点で 1 を減算します。$i+k$。 更新も行っております`cur`フリップは現在のセグメントにすぐに影響を与え始めるため、すぐに実行されます。 
6. 最後までスキャンを続けます。 

重要な設計上の選択は、常に、現在の状態が間違っている可能な限り早い段階で動作することです。 これにより、操作が不可能になる領域への修正の延期が防止されます。 

### なぜ効果があるのか

 不変条件は、インデックスを処理するときの条件です。$i$、すべてのインデックスは厳密に以下です$i$はすでに有効な状態に確定されており、再び影響を受けることはありません。 すべての操作は位置でのみ開始されるため、これは保証されます。$\ge i$したがって、将来のフリップは後方に拡張できません。 

有効な形式でゼロに遭遇するたびに、その正確な位置でフリップを適用すると、現在のインデックスが確実に 1 になり、外乱は修正可能な将来の位置に押し出されます。 以前のインデックスを再検討することはないため、アルゴリズムは競合することなく一貫した一連の修正を構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    diff = [0] * (n + 1)
    cur = 0
    ops = []

    for i in range(n):
        cur ^= diff[i]

        if i > n - k:
            continue

        if (a[i] ^ cur) == 0:
            ops.append(i + 1)
            cur ^= 1
            diff[i] ^= 1
            diff[i + k] ^= 1

    print(len(ops))
    if ops:
        print(*ops)

if __name__ == "__main__":
    solve()
```このソリューションは、差分配列を利用して、操作ごとに一定時間で範囲の反転をシミュレートします。 変数`cur`現在のインデックスが奇数のアクティブなフリップによって影響を受けるかどうかを追跡します。 新しい操作が配置されると、すぐに切り替えます`cur`効果は現在の位置から始まるためです。 

条件`i > n - k`配列の境界を越えて拡張される無効な操作を防ぎます。 そこから正当な手を開始することはできないため、アルゴリズムはこのサフィックス内の位置を修正しようとすることはありません。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

 ## 特殊なケース

 エッジ ケースの 1 つは、配列がすでに許容されるゼロのしきい値に近づいている場合です。 たとえば、次の場合$k=4$、$\lfloor k/2 \rfloor = 2$、配列にちょうど 2 つのゼロがある場合、アルゴリズムは追加のゼロを作成する可能性のある不必要な反転を回避する必要があります。 グリーディはゼロに遭遇したときにのみ反転し、積極的に反転を導入しないため、この境界シナリオでは最適性が維持されます。 

もう 1 つのケースは、接尾辞にゼロが表示され、操作を開始できない場合です。 たとえば、次の場合$n=5$、$k=3$、最後の 2 つの要素がゼロである場合、これらを直接修正することはできません。 アルゴリズムは当然それらを無視し、正確かどうかは、以前の決定によって制約がグローバルに保証される必要があるという事実に依存します。 左から右への不変式により、これらの位置に必要な修正が以前の反転の決定にすでに埋め込まれていることが保証されます。 

最後の微妙なケースは、1 が長く続き、1 回の反転で一時的にゼロが作成される可能性があることです。 グリーディは有効な形式のゼロにのみ反応するため、そこでは反転をトリガーしません。これにより、すでに正しい領域が不必要に妨害されるのを防ぎます。
