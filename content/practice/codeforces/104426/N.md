 ## 解決策
 ## 問題の理解

 それぞれが湖とその中の魚の数を表す、一連の独立した観察結果が与えられます。 すべての湖について、Kaitokid が安全に訪れることができるかどうかを判断する必要があります。 安全性は非常に厳密に定義されています。湖は、魚がまったくいない場合にのみ許容されます。 魚の数が正の場合、その湖は不適切になります。 

入力は、報告される湖の数を表す単一の整数 T で構成されます。 その後、それぞれが 0 から 100 までの範囲にある T 個の整数を読み取ります。 これらの値ごとに、その特定の湖が安全かどうかを示す決定文字列を出力します。 

制約は十分小さいため、総計算量は無視できます。 最大 T の 10^4 であっても、レイクごとに定数時間チェックを実行しているだけです。 これは、直接のリニア スキャンで十分であり、O(T) 複雑さのソリューションは制限内で快適に実行できることを意味します。 

依存関係の順序付けやレイク間の相互作用など、隠れた構造的な複雑さはありません。 各レイクは独立して処理でき、これが簡素化の重要な点です。 

重要な唯一の特殊なケースは、魚の数がちょうどゼロの場合です。 不注意な実装では、言語構造によっては誤ってゼロを偽として扱ったり、誤ってスキップしたりする可能性がありますが、論理的にはこれが肯定的な応答を生成する唯一のケースです。 

## アプローチ

 強引な解釈では、各湖を 1 つずつ調べ、魚の数がゼロかどうかを確認し、結果を出力します。 対応する出力を生成するには、すべてのレイクを少なくとも 1 回検査する必要があるため、チェックの数を減らす方法はありません。 最初にすべての値を保存し、後で処理しようとしても、総作業量は T に比例したままになります。 

ここでの唯一の本当の「最適化」は、追加のデータ構造や前処理が必要ないことを認識することです。 決定ルールは要素ごとに 1 つの比較です。x が 0 に等しい場合は YES を出力し、それ以外の場合は NO を出力します。 問題の構造はすでに最適な評価パターンと一致しています。 

ブルート フォース ビューと最適ビューは一致しますが、重要な点は、集計、並べ替え、プレフィックスの計算では何も変わらないということです。 計算は本質的に O(T) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 湖ごとの直接チェック | O(T) | お(1) | 承認済み |
 | 代替変換 | O(T) | O(T) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 各レイクは指定された順序で個別に処理されます。 

1. 整数 T を読み取ります。これは、評価する必要がある湖の数を示します。 これにより、実行する反復回数が定義されます。 
2. 次の T 整数のそれぞれについて、単一の湖の魚の数を表す値 x を読み取ります。 
3. x がゼロに等しいかどうかを確認します。 誰もいない湖のみが許容されるため、これは安全性の決定的な条件です。 
4. x が 0 に等しい場合は、直ちに YES を出力します。 それ以外の場合は、NO を出力します。 
5. すべての T 湖が処理されるまで、このプロセスを繰り返します。 

各ステップの背後にある理由は、どのレイクも他のレイクに影響を与えないため、即時評価が安全かつ最適であるということです。 

### なぜ効果があるのか

 正しさは、問題定義と条件 x == 0 の間の直接の等価性に依存します。アルゴリズムは、この述語を入力値ごとに 1 回だけ評価し、対応するラベルを生成します。 各決定は独立しており、単一の整数によって完全に決定されるため、反復間で不一致や相互作用の影響が生じる可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input().strip())
    for _ in range(t):
        x_line = input().strip()
        if not x_line:
            x_line = input().strip()
        x = int(x_line)
        if x == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は最初に T を読み取り、次にループ内の各レイクを処理します。 各入力行は整数に解析され、ゼロと照合されます。 条件式は解決策の核心であり、有効な湖の数学的定義を直接反映しています。 

唯一の微妙な実装の詳細は、各入力行が変換前に適切に削除されることを保証することです。これにより、一部の環境で末尾の空白や空の読み取りの問題が回避されます。 出力はすぐに印刷されるため、結果が不必要に保存されることがなくなります。

 ## 特殊なケース

 重要なエッジケースは、魚数がまったくゼロの場合です。 アルゴリズムは、これを唯一の受け入れ条件として明示的に扱います。 入力用`0`、条件 x == 0 は true と評価され、出力は YES となり、許容可能な湖と許容できない湖の境界が正しく処理されていることを確認します。 

もう 1 つのエッジ ケースは、すべての値がゼロ以外の場合です。 たとえば、入力`3 1 2 3`どの値も受け入れ条件を満たさないため、すべてのステップで NO が生成されます。 このアルゴリズムは、正または負に依存せず、正確な平等のみに依存するため、あいまいさはありません。 

最後に、ループが 1 回だけ実行され、初期化や累積ロジックを必要とせずに 1 つの決定を生成するため、T = 1 の可能な最小入力が正しく処理されます。
