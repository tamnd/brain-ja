 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$、各セルには 0 または 1 が含まれます。1 回の移動で、現在 1 が含まれているセルを 1 つだけ選択できます。一度選択すると、エッジまたは角を共有するすべてのセルが 1 になります。選択されたセル自体は変更されず、この操作を複数回実行することはできません。 

問題は、この 1 つの拡張を適用した後にグリッド全体が 1 で埋められるような、開始 1 セルの有効な選択が存在するかどうかです。 

重要な観点は、操作を中央のセルを選択し、その周囲の 3×3 ブロックを「カバーする」と考えることです。 操作後、選択したセルの 3×3 近傍内のセルのみが 0 から 1 に変更される可能性があります。そのブロックの外側のすべては永久に変更されません。 

この制約により、最大 500×500 のグリッド (約 250,000 個のセル) が許可されます。 考えられるすべての中心の動作をシミュレートし、グリッド全体を再計算しようとするソリューションでは、大まかに次のことが必要になります。$O(n^2 \cdot m^2)$最悪の場合、大きすぎる場合もあります。 これにより、私たちは、強引なシミュレーションではなく、グローバル構造についての推論に向かうようになります。 

いくつかの特殊なケースが重要です。 

グリッドに既に 1 のみが含まれている場合、操作は必要ないため、答えは自明に「勝ち」になります。 

たとえば、潜在的な中心から遠く離れたゼロが 1 つだけある場合、次のようになります。```
1 1 1
1 1 1
1 1 0
```その場合、選択した中心が隣接しない限り、単一の 3×3 近傍でそれをカバーすることはできないため、答えは「負け」になります。 

素朴な考えによる微妙な失敗例は、ゼロが「近接」している場合、常にそれが可能であると仮定することです。 例えば：```
1 0 1
0 0 0
1 0 1
```ゼロがクラスター化されているとしても、問題は、1 セルを中心とする単一の 3×3 ブロックがすべてのゼロを同時にカバーできるかどうかということになります。 

## アプローチ

 強引なアイデアは簡単です。選択した中心として 1 を含むすべてのセルを試し、その 8 個の近傍をすべて 1 に変えることをシミュレートし、グリッドがすべて 1 になるかどうかを確認します。 各シミュレーションの費用$O(nm)$、最大で$nm$候補センター、$O((nm)^2)$、大まかに言うと$6.25 \times 10^{10}$最悪の場合の運用。 これは限界をはるかに超えています。 

重要な観察は、この操作が固定のローカル領域、具体的には選択したセルの周囲の 3×3 の正方形にのみ影響するということです。 これは、重要なゼロのみが、潜在的な中心に対する相対的な位置であることを意味します。 テストセンターの代わりに、ゼロから推論することができます。 

操作が 1 回の移動ですべての 0 を 1 に変える必要がある場合、すべての 0 は選択した中心の 3×3 近傍内になければなりません。 これはすぐに幾何学的制約を意味します。つまり、すべてのゼロ セルが 3×3 のウィンドウ内に収まらなければなりません。 すべて 0 の境界ボックスが見つかったら、それがそのような領域内に収まるかどうか、および選択できる有効な中心セル (1) が少なくとも 1 つ存在するかどうかを確認するだけで済みます。 

これにより、多くのセンターをテストするという問題が、ゼロ分布から導出される一定数の条件をチェックすることに軽減されます。

 ## アルゴリズムのチュートリアル

 ### 1. すべてのゼロのセルを見つけます。 

グリッドをスキャンし、0 を含むすべてのセルの行インデックスと列インデックスの最小値と最大値を記録します。ゼロがまったくない場合、グリッドはすでに完全に埋められているため、すぐに「WIN」を返します。 

このステップが役立つ理由は、障害となるのがゼロだけだからです。 これらは変更する必要がないため無関係です。 

### 2. ゼロの外接する四角形を計算します。 

ゼロの最小および最大の行インデックスを次のようにします。$r_{min}$そして$r_{max}$、同様に$c_{min}$そして$c_{max}$。 

この四角形は、問題のあるすべてのセルを含む軸が揃った最小のボックスを表します。 

### 3. 単一操作の幾何学的実行可能性を確認する

 1 つの操作は 3×3 近傍にのみ影響するため、すべてのゼロはそのような近傍内に存在する必要があります。 これは次と同等です。$$r_{max} - r_{min} \le 2 \quad \text{and} \quad c_{max} - c_{min} \le 2$$いずれかの次元が 2 を超える場合、単一の中心はすべてのゼロをカバーできません。 

### 4. 有効な中央セルの存在を確認する

 すべてのゼロが 3×3 領域内に収まる場合でも、選択できるセルは 1 つだけであるため、その領域の中心は値 1 のセルでなければなりません。 

したがって、ゼロ境界ボックスをカバーできるすべての有効な中心の交点に位置する、値 1 を持つセルが少なくとも 1 つ存在するかどうかを確認します。 この地域は次のとおりです。$$[r_{min}+1, r_{max}-1] \times [c_{min}+1, c_{max}-1]$$この領域に少なくとも 1 つの 1 セルが存在する場合、操作をそこに集中させることができます。 

### なぜ効果があるのか

 この操作は全方向に 1 ステップのみ影響を拡大するため、影響を受けるすべてのセルは、選択した中心からチェビシェフ距離 1 以内に存在する必要があります。 この制約は必要かつ十分です。必要性は操作の定義から生じ、十分性はそのような 3x3 近傍が 1 回の移動で完全にカバーされるという事実から生じます。 したがって、問題全体は、1 セルに固定された単一のそのような近傍にすべてのゼロを含めることができるかどうかをチェックすることに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = []
    
    rmin, rmax = n, -1
    cmin, cmax = m, -1
    has_zero = False
    
    for i in range(n):
        row = list(map(int, input().split()))
        grid.append(row)
        for j, v in enumerate(row):
            if v == 0:
                has_zero = True
                rmin = min(rmin, i)
                rmax = max(rmax, i)
                cmin = min(cmin, j)
                cmax = max(cmax, j)
    
    if not has_zero:
        print("WIN")
        return
    
    if rmax - rmin > 2 or cmax - cmin > 2:
        print("LOSE")
        return
    
    # search for valid center
    for i in range(n):
        for j in range(m):
            if grid[i][j] != 1:
                continue
            if rmin <= i <= rmax and cmin <= j <= cmax:
                # must ensure center can cover bbox with radius 1
                if rmin >= i - 1 and rmax <= i + 1 and cmin >= j - 1 and cmax <= j + 1:
                    print("WIN")
                    return
    
    print("LOSE")

if __name__ == "__main__":
    solve()
```この実装では、まず問題をゼロ位置のジオメトリに圧縮します。 初期の終了は、些細なフル 1 グリッドと不可能なストレッチ ゼロ パターンを処理します。 最後のネストされたスキャンでは、候補 1 セルのみがチェックされ、条件により、選択された中心の 3×3 近傍がすべてゼロを完全に含むことが保証されます。 

よくある間違いは、有効な 1 セルが実行可能な中心領域内に存在することを確認せずに、境界ボックスのサイズだけをチェックすることです。 空または無効な中心セットが誤って「WIN」を生成するため、この追加の制約は不可欠です。

 ## 特殊なケース

 グリッドにゼロが含まれていない場合、修正するものが何もないため、アルゴリズムはすぐに「WIN」を返します。 境界ボックス変数は初期化されていないままですが、早期に終了すると使用できなくなります。 

ゼロが緊密にクラスター化されているがエッジに向かってシフトしている場合、境界ボックス条件はまだ合格する可能性がありますが、必要な領域に有効な 1 セルが存在しない場合は、中央の実現可能性チェックで拒否されます。 これにより、ジオメトリでカバレッジは許可されるが、正当な開始セルが存在しないパターンが誤って受け入れられるのを防ぎます。 

ゼロが完全な 3×3 ブロックを形成する場合、そのブロック内の任意の 1 セルが中心として機能します。 このアルゴリズムは、境界ボックスのサイズと少なくとも 1 つの有効な中心セルの存在の両方によってこれを検出し、複数の候補が存在する場合でも正確さを保証します。
