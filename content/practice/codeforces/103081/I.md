 ## 解決策
 ## 問題の理解

 無向グラフのノードとして表される人々のセットが与えられます。 2 つのノード間のエッジは、その 2 人が最初からお互いの電子メール アドレスを知っていることを意味します。 システムは同期ラウンドで進化します。 毎朝、各人は現在のアドレス帳全体を近所の人全員にブロードキャストします。 毎晩、各人はその日中に受け取ったすべてのものを自分のアドレス帳に統合します。 夕方のアップデートで何も新しい情報を受け取らないと、その人は参加しなくなります。 

問題は、プロセスを直接シミュレートすることではなく、最終的にすべての人が他のすべての人の電子メール アドレスを知るかどうかを判断することです。 「はい」の場合、最後の意味のある伝播が完了するまでにかかる時間を計算する必要があります。これは、最後の更新をカウントするか安定化ステップをカウントするかに関する特定の規則に従って日数で測定されます。 

通信ルールは基本的に、時間の経過に伴う情報の推移的閉包ですが、重要な詳細は、更新が夕方にのみ組み込まれ、翌朝にのみ送信されるため、情報が 1 日に 1 ホップずつ階層的に拡散することです。 

入力グラフには最大 100,000 のノードと 100,000 のエッジがあります。 完全なアドレス帳の伝達を明示的にシミュレートしようとするソリューションは不可能です。各ノードが O(N) 個の情報を蓄積する可能性があり、最悪の場合、毎日のコストがノードあたり O(N + M) になる可能性があり、これは実行可能な制限をはるかに超えています。 これにより、セットをシミュレートするのではなく、グラフの構造と距離のレベルで推論することが直ちに強制されます。 

重要な観察は、グラフが接続されている場合にのみプロセスが意味をなすということです。 接続されていない場合は、コンポーネント間に電子メール送信のパスがないため、どれだけユニオンを繰り返しても、接続されている異なるコンポーネントを橋渡しすることはできません。 

グラフがすでに完成しているか、ほぼ完成している場合、微妙なエッジ ケースが発生します。 たとえば、すべてのノードが他のすべてのノードに接続されている場合、プロセスは基本的に 1 ラウンドで終了します。 単純な BFS スタイルの「マルチソース フラッド」では、最終安定化日がカウントされるかどうかに応じて、ゼロ時間またはオフバイ 1 時間の差を誤って仮定する可能性があります。 もう 1 つのエッジ ケースは、2 つのコンポーネントのみが存在する切断されたグラフです。各コンポーネント内ではすべてが収束しますが、グローバルでは完全なグローバル アドレス帳に到達することは不可能です。 

## アプローチ

 プロセスの強引な解釈は、毎日を明示的にシミュレートすることです。 各ノードは一連の既知の電子メールを維持します。 毎日、すべてのノードがその完全なセットを隣接ノードに送信し、受信したすべてのセットを結合し、セットが変更されなくなるまで繰り返します。 セットが大きい場合、最悪の場合、各結合操作に O(N) のコストがかかる可能性があり、1 日に O(M) 個のエッジにわたって実行されます。 最悪の場合、D が O(N) になる可能性がある O(D · N · M) の動作につながりますが、これは 100,000 ノードではまったく実現不可能です。 

重要な構造的洞察は、このプロセスが重み付けされていないグラフの最短経路距離を計算するのと同等であるが、ラウンドの定義方法に工夫が加えられているということです。 よく考えてみると、情報は 1 日に 1 つのエッジを移動します。 つまり、開始ノードを固定した場合、その電子メールが別のノードに到達するまでにかかる時間は、まさにエッジ内のノード間の最短パス距離になります。 最終的には全員が他の全員の電子メールを知る必要があるため、重要なのは、接続された各コンポーネントの直径全体に情報が伝播するまでにどれくらいの時間がかかるかです。

より正確に言うと、単一の接続コンポーネントを考慮すると、情報はすべてのノードから同時に波のように広がります。 新しい情報が現れる最後の瞬間は、グラフの偏心構造に対応します。 すべてのノードが他のすべてのノードに到達するとプロセスが完了するため、時間は同じ接続コンポーネント内の 2 つのノード間の最大最短パス距離、つまり直径によって決まります。 

したがって、問題は、グラフが接続されているかどうかを確認し、接続されている場合は接続されたグラフの直径を計算することに帰着します。 最終的な答えは、最終更新日を測定するか安定化日を測定するかに応じてわずかな調整を加えて、この直径から導出されます。 

一般的な重み付けされていないグラフの直径を計算するには、コンポーネントごとに 2 つの BFS パスを使用します。任意のノードを選択し、BFS で最も遠いノードを見つけ、そのノードから再度 BFS を行って最も遠い距離を取得します。 コンポーネント全体にわたるそのような最大値は直径です。 複数のコンポーネントがある場合、プロセスによってすべてのコンポーネントが完全に接続されることはないため、答えは -1 になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(D・N・M) | O(N²) 最悪の場合のセット | 遅すぎる |
 | コンポーネントごとの BFS 直径 | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力を無向グラフの隣接リスト表現に変換します。 

まず接続性を判断し、距離を測定する準備をします。 

1. M 個のエッジからグラフの隣接リストを作成します。 BFS には高速な近隣アクセスが必要であり、エッジ リストのトラバーサルでは検索を繰り返すには遅すぎるため、これが必要です。 
2. BFS または DFS を使用して、すべてのノードが単一の接続コンポーネントに属しているかどうかを確認します。 複数のコンポーネントが見つかった場合は、切断された部分をブリッジするローカル交換シーケンスがないため、すぐに -1 を返します。 
3. 各接続コンポーネントについて、2 つの BFS パスを使用してその直径を計算します。 コンポーネント内の任意のノードから開始し、BFS を実行して、そこから最も遠いノード u を見つけます。 このステップでは、そのコンポーネント内の最長パスの 1 つのエンドポイントを特定します。 
4. u から開始して BFS を再度実行し、同じコンポーネント内の任意のノードまでの最大距離を計算します。 発生する最大距離は、そのコンポーネントの直径になります。 
5. すべてのコンポーネントの最大直径を追跡します。 グラフが接続されている場合、これは単に全体の直径になります。 
6. プロセスのタイミングルールに従って、直径を必要な日数に変換します。 毎日が 1 つのエッジ層の完全な伝播に対応し、プロセスは 0 日目の朝にすでに存在していた初期知識から始まるため、最後の更新までの日数が直径になります。 

### なぜ効果があるのか

 重要な不変条件は、丸 k 日後、すべてのノードがグラフ内の距離の k エッジ内で発生した情報を正確に認識していることです。 これは、毎日、すべてのエッジに沿って同時に知識がちょうど 1 ホップだけ外側に拡張されるためです。 したがって、k 日後のノード v における既知の電子メールのセットは、v から距離 k 内のすべてのノードに正確に対応します。 

k がノードの離心率に達すると、そのノードは変化を停止します。 最後の全体的な変化は、k がすべてのノードにわたって最大離心率 (正確にグラフの直径) に達したときに発生します。 したがって、直径ステップ後に新しい情報を受信できるノードは存在せず、正確性を確保するには、その時点まで一部のノードが引き続き情報を受信する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    far = start

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
                if dist[to] > dist[far]:
                    far = to
    return far, dist

def bfs_dist(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    far = 0

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
                if dist[to] > dist[far]:
                    far = to
    return dist

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    visited = [False] * (n + 1)
    components = 0
    diameter = 0

    for i in range(1, n + 1):
        if not visited[i]:
            components += 1
            q = deque([i])
            visited[i] = True
            comp_nodes = [i]

            while q:
                v = q.popleft()
                for to in adj[v]:
                    if not visited[to]:
                        visited[to] = True
                        q.append(to)
                        comp_nodes.append(to)

            if components > 1:
                print(-1)
                return

            start = i
            far, _ = bfs(start, adj)
            dist = bfs_dist(far, adj)
            diameter = max(diameter, max(dist))

    print(diameter)

if __name__ == "__main__":
    solve()
```この解決策は、隣接リストの線形時間トラバーサルをサポートする隣接リストを構築することから始まります。 BFS ベースのコンポーネント チェックにより、切断を早期に検出できます。これは、コンポーネント間に通信パスが存在できないために必要です。 

接続されたコンポーネントごとに、標準の 2-BFS 手法を使用してその直径を計算します。 最初の BFS は、任意の開始点から最も遠いノードを識別します。これは、そのコンポーネント内の最長パスの終点として機能します。 そのエンドポイントからの 2 番目の BFS は真の偏心構造を計算し、そのコンポーネントの最大距離を示します。 

距離の各単位は丸 1 日の伝播に相当するため、最終的な答えは直径になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | 各 BFS はノードとエッジを 1 回訪問し、コンポーネントごとに一定の回数の BFS 実行を実行します。 
| スペース | O(N + M) | 隣接関係リストと BFS キューおよび距離配列 |

 この制約により線形時間グラフの走査が可能になるため、このアプローチは 100,000 個のノードとエッジであっても制限内に問題なく適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def bfs(start, adj):
        n = len(adj) - 1
        dist = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0
        far = start
        while q:
            v = q.popleft()
            for to in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)
                    if dist[to] > dist[far]:
                        far = to
        return far

    def bfs_dist(start, adj):
        n = len(adj) - 1
        dist = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0
        while q:
            v = q.popleft()
            for to in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)
        return dist

    def solve():
        n, m = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        visited = [False] * (n + 1)
        components = 0
        diameter = 0

        for i in range(1, n + 1):
            if not visited[i]:
                components += 1
                q = deque([i])
                visited[i] = True
                while q:
                    v = q.popleft()
                    for to in adj[v]:
                        if not visited[to]:
                            visited[to] = True
                            q.append(to)

                if components > 1:
                    return "-1"

                far = bfs(i, adj)
                dist = bfs_dist(far, adj)
                diameter = max(diameter, max(dist))

        return str(diameter)

    return solve()

 ## 特殊なケース

 切り離されたグラフはコンポーネント検出段階で処理されます。 ノードをスキャンするとき、アルゴリズムは、未訪問のノードを見つけるたびにコンポーネント カウンタをインクリメントします。 このカウンタが 1 を超えると、すぐに -1 を返します。 たとえば、入力`1-2`そして`3-4`2 つのコンポーネントを形成します。 BFS は各コンポーネント内のノードのみをマークし、直径の計算が試行される前に 2 番目の検出によって終了がトリガーされます。 

完全に接続されたグラフの直径は 1 です。任意のノードからの最初の BFS は 1 ステップで他のすべてのノードに到達し、2 番目の BFS で最大距離 1 が確認されます。アルゴリズムは正しく 1 を返し、完全な交換には 1 ラウンドで十分であるという直感と一致します。 

直鎖状のチェーンは伝播にとって最悪のケースです。 各 BFS ステップはちょうど 1 つのノードだけ到達範囲を拡張するため、直径は N-1 に等しくなります。 最も遠いエンドポイントがチェーンの終端であり、2 番目の BFS が全長を測定するため、アルゴリズムはこれを正しく捕捉します。
