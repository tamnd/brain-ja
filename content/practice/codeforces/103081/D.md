 ## 解決策
 ## 問題の理解

 頂点が交差点、エッジが長さのある道路である無向重み付きグラフが与えられます。 Phoebe は、すべてのジョギング セッションを常にノード 0 で開始および終了します。各ジョギング セッションは、全長が下限の間に制限された閉じた歩行です。$L$そして上限$U$。 

目標を推進する追加の簿記ルールがあります。 フィービーがその一部を初めて通過するとき、その通りは「新しい」とみなされ、以前のセッションで使用されたことのない通りが少なくとも 1 つ含まれている場合、そのジョギング セッションは興味深いと呼ばれます。 道路は一度使用されると、たとえその後の走行で部分的に通過したとしても、再び目新しさをもたらすことはありません。 

課題は、できるだけ多くの興味深いジョギング セッションを計画することです。 各セッションは古い通りを自由に再利用できますが、新しいセッションとしてカウントするには、以前に使用されていなかった通りを少なくとも 1 つ導入する必要があります。 

制約は大きく、最大で$10^5$交差点と$10^5$通り。 これにより、それに近いものは即座に除外されます。$O(S^2)$あるいは、エッジごとに最短パスの計算を繰り返すこともあります。 単一の線形または$O(S \log S)$ディクストラの周りを通過するのが適切なスケールです。 

この声明の微妙な点は、フィービーは通りの一部分だけを横切るかもしれないが、彼女が通りに触れた瞬間に、それは完全に「見られた」とみなされるということです。 これにより、部分的なエッジの使用について検討する必要がなくなります。 各エッジは未使用であるか、以前の興味深い実行によってすでに消費されています。 

2 番目の微妙な点は、実行には少なくとも 1 つの新しい通りを含める必要があるだけですが、多くの道路が含まれる可能性があることです。 素朴な解釈では、エッジを複雑な構造に分割する必要があるかもしれないと思われますが、それは不要であることが判明しました。 

重要ないくつかの特殊なケース:

 グラフに単一のエッジがある場合$0 - 1$長さのある$3$、$L = 7$、$U = 7$の場合、閉じたウォークは少なくとも長さを持たなければならないため、有効なランは存在しません。$6$、したがって、答えは次のとおりです$0$。 

サイクルを形成する複数のエッジがある場合、単純なアプローチでは長いツアーを貪欲に構築しようとし、構造化された方法で異なる候補実行間でエッジを再利用できないと誤って想定する可能性がありますが、実際の解決策は到達可能性とノードからの最短パス構造のみに依存します。$0$。 

## アプローチ

 直接的なブルートフォース解釈では、プロセスをシミュレートしようとします。 ノード 0 で開始および終了し、長さが の閉じたウォークを繰り返し検索することを想像できます。$[L, U]$、少なくとも 1 つの未使用のエッジが含まれており、それらのエッジを使用済みとしてマークして続行します。 たとえ 1 つのウォークの実現可能性を検出できたとしても、そのようなウォークを列挙することは組み合わせ的に爆発的です。 可能なウォークの数は、サイクルによりパスの長さに応じて指数関数的に増加し、実行ごとにエッジのどのサブセットを含めるかを決定するだけでも、検索スペースが手に負えなくなります。 

重要な観察は、「面白さ」条件の分離がほぼ完全に実行されていることです。 各エッジは、初めて使用するときにのみ重要になります。 各エッジを最大 1 つの実行に割り当て、選択したエッジごとにそれを含む有効な閉じたウォークが存在することを確認できれば、そのような各割り当てを個別の実行として実現できます。 この意味でエッジは独立しているため、ランの最大数は、少なくとも 1 つの有効な閉じたウォークによって個別にサポートできるエッジの数になります。 

したがって、問題は各エッジを個別にテストすることになります。このエッジを含み、全長が 0 である閉じたウォークを 0 から構築できるでしょうか。$[L, U]$?

 無向重み付きグラフの場合、エッジを横断することを強制される 0 からの可能な最短の閉じたウォーク$(u, v, w)$は 0 から$u$、優位に立つ$v$から戻ってきました$v$コストは次のとおりです。$$\text{dist}(0, u) + w + \text{dist}(0, v)$$エッジを含む他の有効なウォークは、すべてのエッジの重みが正であるため、より長くすることしかできません。 これは非常に重要です。エッジを含めるために可能な最小の長さがわかったら、実現可能性を失ったり、肯定的な制約に違反したりすることなく、0 から到達可能なサイクルを迂回することで、いつでも長さをさらに増やすことができます。 

したがって、エッジは、その最小強制サイクル長が最大以下の場合にのみ使用できます。$U$。 この条件が満たされれば、いつでも内部のどこかに着陸するまで歩行を伸ばすことができます。$[L, U]$。 下限$L$迂回路を挿入することでいつでも長さを増やすことができるため、実現可能性が制限されることはありません。 

これにより、問題は単一ソースの最短パス計算とそれに続くエッジ上の線形スキャンに縮小されます。

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. ダイクストラのアルゴリズムを使用して、ノード 0 から他のすべてのノードまでの最短パス距離を計算します。 これにより、自宅交差点からグラフ内の任意の点までの最小移動コストが得られます。 このステップが必要なのは、すべての候補の閉じたウォークがノード 0 で開始および終了する必要があるため、0 からの距離がエッジに「到達」するための最も安価な方法を定義するためです。 
2. すべての街路 (u、v、w) について、この街路を強制的に含める閉じた歩行の最小コストを計算します。 これは、dist[u] + w + dist[v] として計算されます。 その考え方は、一方のエンドポイントからエッジに最適に 0 から到達した後、エッジに入り、もう一方のエンドポイントから最適に 0 に戻るというものです。 
3. この最小必要コストが U 以下であるかどうかを確認します。U を超える場合は、このエッジを含む可能な最短の有効な閉じたウォークでも長すぎるため、エッジは有効な実行では決して使用できません。 
4. 条件を満たすすべてのエッジを数えます。 ランには少なくとも 1 つの新しいエッジのみが必要であり、エッジごとに個別のウォークを常に独立して構築できるため、このような各エッジを個別のランに割り当てることができます。 
5. 合計カウントを対象となる実行の最大数として出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのエッジについて、そのエッジを含む 0 で始まり 0 で終わる閉じたウォークの最小可能な長さを正確に識別することです。 すべてのエッジの重みは厳密に正であるため、同じエッジを含む代替ウォークでは全長が増加するだけです。 これにより、計算された値が真の下限になります。 

この下限が間隔内に収まると、$[L, U]$、ルートからエッジを削除せずに迂回路を挿入することで歩行を上に伸ばすことができます。つまり、実現可能性は最小値が最大かどうかによってのみ決まります。$U$。 各エッジは独立してランに割り当てることができるため、ランを最大化することは、実行可能なエッジをカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    I, S, L, U = map(int, input().split())
    g = [[] for _ in range(I)]
    edges = []

    for _ in range(S):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
        edges.append((u, v, w))

    INF = 10**18
    dist = [INF] * I
    dist[0] = 0
    pq = [(0, 0)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    ans = 0
    for u, v, w in edges:
        if dist[u] + dist[v] + w <= U:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にグラフを構築し、ノード 0 からダイクストラを実行して最短距離を計算します。 エッジのすべての実現可能性チェックはその端点までの距離のみに依存するため、これが必要な唯一のグローバル構造です。 

その後、最小強制クローズ ウォークの公式を使用して、各エッジが個別に評価されます。 に対する小切手$U$実行可能な最小値があれば、必要な間隔への拡張性が自動的に暗示されるため、これで十分です。 

よくある実装上の落とし穴は、グラフが無向であることを忘れていることです。そのため、隣接リストに両方向を追加する必要があります。 もう 1 つの微妙な点は、明示的には使用しないことです。$L$最終チェックでは、サイクルを介してパス長を増加できるため、下限は実現可能性に無関係になるためです。

 ## 特殊なケース

 重要なエッジ ケースは、グラフに、到達可能ではあるがノード 0 からの閉じたウォークに含めるにはコストが高すぎるエッジが含まれている場合です。たとえば、両方のエンドポイントへの最短パスが大きい場合、戻りのトリップが優勢であるため、小さなエッジであっても無効になります。 計算された強制サイクルが次の値を超えるため、アルゴリズムはそのようなエッジを正しく拒否します。$U$。 

もう 1 つのエッジケースは次のような場合です$L$大きいですが$U$最小サイクルよりわずかに大きいだけです。 実現可能な最小値は以下であるため、このソリューションは引き続き機能します。$U$迂回路を使用して膨らませることができます。 このアルゴリズムは、0 から到達可能な正の重みサイクルの存在に暗黙的に依存しており、これにより、有効性を損なうことなく制御された長さの増加が常に可能になります。 

最後に、グラフがツリーの場合、すべてのエッジが一意のパスを形成し、解決策は各エッジのパス-0サイクルが範囲内に収まるかどうかを確認することになります。$U$、式は特別なケースを使用せずに直接処理します。
