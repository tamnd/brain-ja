 ## 解決策
 ## 問題の理解

 連続する棚間の垂直方向のギャップを表す一連の整数を構築するように求められます。 がある$K$隙間、それぞれの隙間$s_i$範囲内の整数でなければなりません$[0, N-1]$、すべてのギャップはペアごとに区別できる必要があります。 シーケンスは任意ではありません。次の各値が、前の値の約数を法として使用して前の値から決定されるという繰り返しに従う必要があります。$N$。 すべての有効なシーケンスのうち、すべてのシーケンスの合計を最小にするものを出力する必要があります。$s_i$、または有効なシーケンスが存在しないことを報告します。 

これについて考えるのに役立つ方法は、次のような有向グラフをたどることです。$N$ラベル付きノード$0$に$N-1$。 ノードから$x$、発信エッジが 1 つだけあります。$(x + d(x)) \bmod N$、 どこ$d(x)$は約数の数です$x$。 ある程度の長さのパスが必要です$K$個別のノードを訪問し、訪問したラベルの合計を最小限に抑えます。 

制約により両方が許可されます$N$そして$K$100万まで。 すべての可能性を探索したり、サブセット全体で完全な状態を維持しようとするソリューションは、直ちに不可能になります。 平$O(N \log N)$前処理は許容されますが、二次関数は何でも可能です。$N$または指数関数的な状態ではありません。 

微妙なエッジケースは次のような場合です$N = 1$。 その場合、可能な値は次のとおりです。$0$ただし、すべての値は個別である必要があるため、複数の要素を取ることはできません。 もし$K > 1$、答えは次のようになります。$-1$。 もう 1 つの特殊なケースは、繰り返しがすでに使用されている値を即座に循環する場合です。これにより、次の場合でも早期終了が強制される可能性があります。$K$小さいです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。考えられるすべての開始値を試してみます。$s_1$次に、遷移ルール​​を繰り返し適用してシーケンスを生成し、値を繰り返すか境界を超えると停止します。 うまく集められたら$K$個別の値を指定し、合計を計算して最小値を維持します。 

最初の要素が選択されると、ルールによって順序が完全に決定されるため、これは論理的に機能します。 ただし、各起動には最大で$K$移行があり、$N$選択肢、それにつながる$O(NK)$最悪の場合の運用。 両方のパラメータが最大の場合$10^6$、これは実現可能な限界をはるかに超えています。 

重要な点は、実際には複数の開始点を探索する必要がないということです。 各開始値は、循環するかすべてを使い果たすまで、決定的なチェーンを引き起こします。$K$必要な要素。 最初からシミュレーションする代わりに、すべてのノードの次のポインターを事前計算してから、グラフ全体を互いに素な機能コンポーネントに分解できます (各ノードには出力エッジが 1 つだけあるため)。 すべてのコンポーネントはサイクルであり、そこにツリーが供給されますが、値を繰り返すことはできないため、有効な解決策は繰り返しが発生する前に単純なパス上に存在する必要があります。 

重要な単純化は、合計を最小化する最良の方法は、常に、有効な長さのチェーンを生成できる最小の未使用ノードから開始することであるということです。$K$。 開始ノードにコミットしたら、その決定論的なチェーンを貪欲にたどり、次のいずれかに到達するまでノードを収集します。$K$または、繰り返しをヒットすると、その開始が無効になります。 

これにより、関数の計算の問題が軽減されます。$f(x) = (x + d(x)) \bmod N$みんなのために$x$そして、訪問したノードをグローバルにマークしながらチェーンを効率的にシミュレートします。 

以下のすべての値に対する除数関数$10^6$で事前計算できます$O(N \log N)$ふるいのような方法を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NK)$|$O(N)$| 遅すぎる |
 | 関数グラフシミュレーション |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、約数の数を事前計算し、関数グラフの走査問題として漸化式を扱うことを中心にソリューションを構築します。 

1. コンピューティング$d[x]$、すべての約数の数$x \in [0, N-1]$。 これは、修正されたふるいを使用して行われます。$i$増加します。 このステップが必要なのは、遷移が除数の数に依存し、後で一定時間内に応答する必要があるためです。 
2. 次のポインタ配列を構築します$nxt[x] = (x + d[x]) \bmod N$。 これにより、すべてのノードに対して決定論的な出力エッジが定義され、問題は各ノードが 1 つの出力エッジを持つグラフに変わります。 
3. 選択されたすべての値が異なることを確認するために、グローバル ビジット配列を維持します。 これにより、「異種」要件が強制され、ノードの再訪問によって引き起こされる無効なシーケンスが防止されます。 
4. 以下の開始点を繰り返します。$0$に$N-1$。 訪問されていないノードに遭遇すると、そこから開始してシーケンスを構築しようとします。 
5. 開始ノードから$x$、繰り返しフォローします$nxt[x]$、訪問されていない間にノードを結果に追加します。 訪問した各ノードを追加したらすぐにマークを付けます。 いずれかのシーケンスが長さに達したら停止します$K$またはノードを再訪します。 
6. 収集に成功した場合$K$要素、シーケンスを出力して終了します。 それ以外の場合は、次の未訪問の開始点を試し続けます。 
7. 長さに達することなくすべてのノードを使い果たした場合$K$、出力$-1$。 

重要な決定は、未訪問のノードからのみ開始することです。 これにより、既に使用されている値とすぐに衝突するチェーンでの無駄な作業が回避され、各ノードが全体で最大 1 回処理されることが保証されます。 

### なぜ効果があるのか

 各ノードは、決定的遷移の下で正確に 1 つの機能チェーンに属します。 ノードにアクセスすると、再度そのノードをたどっても、すでに探索されたチェーンの一部が再構築されるだけです。 すべての値は別個である必要があるため、有効な解決策はすべて、この関数グラフ分解におけるチェーンのプレフィックスを選択することに対応します。 すべてのノードは最大でも 1 回アクセスされ、常に利用可能な最小の開始点から貪欲に拡張されるため、実現可能な長さの構築を見逃すことはありません。$K$存在する場合。 各ノードが 1 回追加されマークされるため、合計作業量はノード数に比例します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    
    if K > N:
        print(-1)
        return
    
    # special case: N == 1
    if N == 1:
        if K == 1:
            print(0)
        else:
            print(-1)
        return
    
    # compute divisor counts
    div = [0] * N
    for i in range(1, N):
        for j in range(i, N, i):
            div[j] += 1
    
    nxt = [(i + div[i]) % N for i in range(N)]
    vis = [False] * N
    res = []
    
    def walk(start):
        x = start
        local = []
        while not vis[x]:
            vis[x] = True
            local.append(x)
            x = nxt[x]
            if len(res) + len(local) == K:
                res.extend(local)
                return True
        return False
    
    for i in range(N):
        if not vis[i]:
            if walk(i):
                print(*res)
                return
    
    print(-1)

if __name__ == "__main__":
    solve()
```除数ふるいは直接乗算方式で実装されます。 それでも$O(N \log N)$、それは十分に高速です$10^6$。 遷移配列は一度構築され、再計算されることはありません。 

トラバーサル機能により、新しいノードからのみ拡張することが保証されます。 一度ノードにアクセスすると、そのノードは再び現れることはできないため、すべての追加はグローバルに安全です。 終了条件は、正確に蓄積したかどうかをチェックします$K$価値観。 

微妙な実装の詳細は、ウォーク内で長さの条件をチェックし、完全なチェーンを完了せずに早期停止できるようにすることです。 

## 実用的な例

 ### 例 1

 入力:```
18 10
```除数のカウントと遷移を計算し、0 から上に向けてスキャンを開始します。 最初の有用なチェーンが 0 から始まると仮定します。 

| ステップ | 現在 | 訪問時のサイズ | アクション |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 新しいチェーンを開始します |
 | 2 | nxt[0] | 2 | 追加 |
 | 3 | ... | ... | 要素が 10 個になるまで続行 |

 アルゴリズムは 10 個の値が収集されたときに正確に停止し、それらを順番に出力します。 

このトレースは、ノードを再訪問することがないこと、および必要な長さに達した場合は早期に停止することで不必要なトラバースを防止することを示しています。 

### 例 2

 入力:```
9 9
```ここではすべてのノードを使用する必要があります。 

| ステップ | 開始 | 訪問取材 |
 | --- | --- | --- |
 | 1 | 0 | 部分チェーン |
 | 2 | 次の未訪問 | 適用範囲を拡大 |
 | 3 | 続ける | 最終的にはすべてのノードをカバーします。 

このプロセスは、すべてのノードが消費されるまで続き、すべての値の完全な順列が生成されます。 

これにより、アルゴリズムが可能な最大のケースを正しく処理していることが確認されます。$K = N$。

 ## 特殊なケース

 ### ケース: N = 1

 入力:```
1 1
```唯一の値は 0 であるため、有効なシーケンスは [0] のみです。 アルゴリズムはそれを直接返します。 

入力：```
1 2
```2 番目の個別の値は存在しません。 訪問済みチェックによりチェーンの拡張が直ちに妨げられ、アルゴリズムは -1 を出力します。 

### ケース: チェーン衝突が早期に発生

 ノードが長さ K に達する前にすでに訪問したノードに遷移した場合、ウォークは早期に停止し、その開始点は破棄されます。 これにより、サイクルの部分的な再利用が防止され、互いに素なセグメントのみが構築されるようになります。 

### ケース: K が N に等しい

 K = N の場合、有効なトラバーサルが存在する場合、アルゴリズムは必然的にすべてのノードを 1 回だけ消費します。 訪問された配列は反復がないことを保証し、ウォーク関数はグラフを到達可能なセグメントに完全に分解するものとして機能します。
