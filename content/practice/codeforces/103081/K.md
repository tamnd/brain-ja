 ## 解決策
 ## 問題の理解

 英語の大文字で構成される単一の長い文字列が与えられます。 活動のタイムラインとして考えてください。 各キャラクターは 1 つのアクティビティであり、このタイムラインの連続したセグメントは検査できる「一連の日」とみなされます。 

タスクは、文字列全体で 1 回だけ出現する、最も短い連続部分文字列を見つけることです。 この最小可能長を持ち、1 回だけ出現するすべての部分文字列の中で、出現が最も早く始まるものを出力する必要があります。 

文字列の長さは 300,000 に達する可能性があるため、注意深い最適化を行わずにすべての部分文字列、さらには固定長のすべての部分文字列を明示的にカウントしようとするアプローチは遅すぎます。 部分文字列の数は約 N²/2 の 2 次であり、単純にチェックするだけでもすでに多すぎます。 どのソリューションでも、等価性チェックのために文字列を繰り返しスキャンすることを避ける必要があります。 

よくある落とし穴は、ハッシュ セットまたは直接比較を使用して長さが増加する部分文字列をチェックしても問題ないと思い込むことです。 たとえば、長さ L を固定してウィンドウをスライドしたとしても、長さあたりの部分文字列は依然として O(N) 個あり、L を多くの値にわたって試行すると、最悪の場合、複雑さは 3 次になります。 もう 1 つの微妙な失敗例は、慎重な二重ハッシュやサフィックス構造を行わずにローリング ハッシュを試行した場合にハッシュの衝突によって発生し、不正確な一意性の決定が生じる可能性があります。 

主な困難は、単に一意の部分文字列を見つけるだけではなく、各部分文字列が何回出現するかを効率的に判断しながらそれを行うことです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての部分文字列を列挙し、他のすべての部分文字列と比較してその出現回数を数え、最良のものを追跡します。 これは、「一度だけ発生する」の定義に直接一致するため、概念的には正しいですが、O(N²) 個の部分文字列があり、それぞれの比較に O(N) 時間がかかるため、単純な比較で実行すると、すぐに O(N³) 個の解が得られます。 

ハッシュを使用してカウントを最適化したとしても、依然として O(N²) 個の部分文字列と大きなメモリ負荷に直面します。 本当の問題は、部分文字列の比較とカウントが重複する部分文字列間で冗長であることです。 

重要な点は、実際には各部分文字列の正確な頻度を個別に知る必要がないということです。 代わりに、部分文字列が一意であるかどうかだけを知る必要があり、すべての一意の部分文字列の中で最も短いものが必要です。 これは、部分文字列の出現を暗黙的に集約できる構造を示唆しています。 

LCP (Longest Common Prefix) を含むサフィックス配列は自然に適合します。 接尾辞を並べ替えると、同一の接頭辞が辞書順にグループ化されます。 2 つの部分文字列が同一である場合、それらは少なくともその長さの共通の接頭辞を共有する接尾辞の接頭辞に対応します。 LCP 配列を使用すると、各接尾辞がその近傍に寄与する同一の部分文字列がソート順にいくつあるかを識別できます。 

接尾辞がソートされると、各接尾辞について、少なくとも 2 回出現する接頭辞の最大長を決定できます。 それより長いプレフィックスは、そのサフィックスから始まる一意です。 各サフィックスに固有の最小長のプレフィックスを追跡することにより、世界で最も短い一意の部分文字列を見つけることができます。 

これにより、問題は部分文字列の明示的なカウントから、ソートされた接尾辞空間での隣接関係の分析へと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3) | O(1)-O(N²) | 遅すぎる |
 | サフィックス配列 + LCP | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 サフィックス配列と LCP を使用して問題を解決します。

1. 文字列のサフィックス配列を構築します。 各接尾辞は文字列内の開始インデックスに対応し、それらを並べ替えると、類似した接頭辞が辞書順にグループ化されます。 
2. LCP 配列を構築します。LCP[i] には、ソートされたサフィックス配列内の位置 i と i-1 にあるサフィックス間の最長の共通プレフィックスの長さが格納されます。 これは、隣接するサフィックスがどれだけ長く一致するかを捕捉します。 
3. ソートされた順序で各サフィックスについて、少なくとも 2 回出現する最長のプレフィックスを決定します。 これは単に、ソートされた配列内のその近傍にそのサフィックスが含まれる最大 LCP です。 具体的には、位置 i のサフィックスについて、LCP[i] と LCP[i+1] を考慮し、関連する最大の重複を考慮します。 
4. サフィックスに長さ k の最長反復プレフィックスがある場合、そのサフィックスで始まる k より長いプレフィックスは文字列全体で 1 回だけ発生します。 したがって、そのような最短のプレフィックスは長さ k+1 になります。 
5. 各サフィックスについて、長さ k+1 の一意の部分文字列候補を計算します。 世界最小の長さを追跡します。 複数の候補が同じ長さを共有する場合、最小の開始インデックスを持つ候補が選択されます。これは、ソートされた順序でサフィックスを反復し、位置を比較することによって自然に強制されます。 

### なぜ効果があるのか

 2 つの部分文字列は、対応する接尾辞がその長さの共通の接頭辞を共有する場合に限り、等しくなります。 サフィックスを並べ替えると、すべての等しいプレフィックスが連続したブロックに表示されます。 LCP 配列は、この並べ替えられた順序で隣接する接尾辞間の重複を正確に測定します。つまり、繰り返されるすべての部分文字列は、隣接する LCP 値が少なくともその長さである接尾辞の間隔として表される必要があります。 

どのようなサフィックスでも、その隣接する最大 LCP から、そこから始まる他の場所で重複している最長のサブストリングがわかります。 その境界を超えるものはすべて一意である必要があります。 これにより、繰り返しがあると、隣接する接尾辞の比較で接頭辞が一致することが強制されるため、繰り返された部分文字列を一意であると誤って分類することがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = [ord(c) for c in s]
    tmp = [0] * n

    while True:
        sa.sort(key=lambda i: (rank[i], rank[i + k] if i + k < n else -1))

        tmp[sa[0]] = 0
        for i in range(1, n):
            prev = sa[i - 1]
            cur = sa[i]
            tmp[cur] = tmp[prev] + (
                (rank[cur], rank[cur + k] if cur + k < n else -1)
                != (rank[prev], rank[prev + k] if prev + k < n else -1)
            )

        rank = tmp[:]
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa

def build_lcp(s, sa):
    n = len(s)
    rank = [0] * n
    for i, v in enumerate(sa):
        rank[v] = i

    h = 0
    lcp = [0] * n

    for i in range(n):
        if rank[i] == 0:
            continue
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h:
            h -= 1

    return lcp

def solve():
    s = input().strip()
    n = len(s)
    if n == 0:
        return ""

    sa = build_suffix_array(s)
    lcp = build_lcp(s, sa)

    best_len = 10**18
    best_pos = 0

    for i in range(n):
        start = sa[i]

        left_lcp = lcp[i] if i > 0 else 0
        right_lcp = lcp[i + 1] if i + 1 < n else 0
        mx = max(left_lcp, right_lcp)

        cand_len = mx + 1

        if start + cand_len <= n:
            if cand_len < best_len or (cand_len == best_len and start < best_pos):
                best_len = cand_len
                best_pos = start

    return s[best_pos:best_pos + best_len]

if __name__ == "__main__":
    print(solve())
```接尾辞配列の構築では標準の 2 倍化手法が使用され、以前に計算されたランクを使用して最初の 2^k 文字で接尾辞を繰り返し並べ替えます。 重要な考え方は、ランクが安定すると、完全な辞書編集的な順序が得られるということです。 

LCP の計算には Kasai のアルゴリズムが使用されます。このアルゴリズムは、以前の比較を再利用し、反復間で一致したプレフィックス長のみをデクリメントすることによって線形時間で実行されます。 

メイン ループでは、各サフィックスを検査し、隣接する LCP 値をチェックすることで、そのプレフィックスが一意でないことがどの程度保証されるかを計算します。 候補部分文字列は、一意性が始まる最初の位置です。 

微妙な点は、サフィックス配列の左と右の両方の隣接要素を考慮する必要があることです。 部分文字列はどちらの側でも繰り返すことができ、正確さには両方向が重要です。

 ### 例 1

 入力:```
AABAABB
```サフィックス配列 (概念的にソート):```
0: AABAABB
1: AABB
2: ABAABB
3: B
4: BAABB
5: BBAABB

```私たちは隣人間の LCP 関係に焦点を当てます。 重要な観察は、「A」、「B」、「AA」、「BA」などの繰り返しの接頭辞が隣接する接尾辞に表示されていることです。 

| サフィックス開始 | 接尾辞 | 近隣との最大 LCP | 候補の長さ | 候補者 |
 | --- | --- | --- | --- | --- |
 | 0 | アバアバ | 2 | 3 | ＡＡＢ |
 | 1 | ＡＡＢＢ | 2 | 3 | ＡＡＢ |
 | 2 | ABAAB | 0 | 1 | あ |
 | 3 | B | 2 | 3 | BBA |
 | 4 | バーブ | 1 | 2 | BA |
 | 5 | BBAABB | 1 | 2 | BB |
 | 6 | BB | 1 | 2 | BB |

 すべての候補の中で最も短い一意の部分文字列は「BA」で、これは 1 回だけ出現し、最小長は 2 です。 

このトレースは、一意性がサフィックス順にローカルに決定され、最小の有効な候補が選択されることを示しています。

 ## 特殊なケース

 のような文字列の場合`AAAAA`、すべてのサフィックスは、サフィックス配列内の隣接するサフィックスと長い共通のプレフィックスを共有します。 このアルゴリズムは、左から右のサフィックスに向かって減少する LCP 値を計算し、各位置について、候補は繰り返しがプレフィックスに影響を及ぼさなくなる最初のインデックスになります。 全長より短い部分文字列は一意ではないため、完全な文字列を除くすべての候補は無効となり、アルゴリズムは完全な文字列を正しく返します。 

のような厳密に増加する文字列の場合`ABCDEF`、サフィックスがない場合、隣接するものとゼロ以外の LCP を共有します。 すべての接尾辞にはすぐに`mx = 0`, したがって、各候補は単一の文字です。 タイブレーク ルールでは最も早い順位が選択され、`A`これは、すべての文字が 1 回出現し、可能な限り短い部分文字列であるため、正しいです。
