 ## 解決策
 ## 問題の理解

 部屋の有向グラフが与えられます。 各エッジは一方通行のドアを表し、色のラベルが付いています。 デイジーは部屋 0 から開始し、部屋 R − 1 に到達したいと考えています。 

彼女の動きは、色付きのカードの束に依存します。 彼女はいつでも電流スタックのある部屋にいます。 スタックのトップが彼女の行動を決定します。 

一番上のカードの色が現在の部屋から出ていくドアの少なくとも 1 つと一致する場合、彼女はそのドアを選択し、それを横切り、カードをポップしなければなりません。 一致する扉が複数ある場合は自由に選択できますが、カードは消費されます。 

スタックが空であるか、上部の色がどの出力ドアとも一致しない場合、彼女はいずれかの出力ドアを選択することを余儀なくされます。 ポップする代わりに、彼女は選択したドアの色をスタックにプッシュします。 

これにより、(部屋、スタックの内容) の状態空間が作成されますが、デイジーが「強制」されるとスタックが拡大し、カードの一致に成功すると縮小する可能性があります。 

タスクは、デイジーが最適な選択で部屋 R − 1 に到達できるように、初期の色のシーケンス (スタック) が存在するように、可能な限り最小の初期スタック サイズを決定することです。 

制約はルームとエッジの点で小さく、R ≤ 50、D ≤ 100、C ≤ 20 です。 これは、拡張された状態に対する状態空間またはグラフ検索のアプローチが実行可能であることをすぐに示唆しています。なぜなら、慎重に構造化されていれば、スタック構成への指数関数的な依存性はまだ管理できる可能性があるからです。 

サイズ S のスタックの数は C^S であるため、考えられるすべてのスタックにわたる単純なシミュレーションは不可能ですが、これは指数関数的に増加し、S が 10 程度の場合でも実行不可能になります。 

完全に揃った色が存在する場合にのみスタック サイズを削減するサイクルがある場合、微妙なエッジ ケースが発生します。 たとえば、部屋の出口に単一色の色のエッジしかないが、出口には異なる色のシーケンスが必要な場合、デイジーは初期条件に応じて無限のスタックの増加またはループ動作を強制される可能性があります。 「常に貪欲にプッシュまたはポップする」という単純な解釈は、プロセスが完全に制御可能であること、および選択が固定されたものではなく敵対的に有利であることを見逃しています。 

## アプローチ

 重要な問題は、スタックが単なるメモリではなく、制御メカニズム全体であることです。 ただし、この問題には単調な構造が隠されています。色のシーケンスがサイズ S で機能する場合、それを任意に拡張しても実現可能性が無効になるわけではありませんが、S を増やすと、柔軟性が低下するのではなく、柔軟性が向上します。 これは、答えを二分探索できることを示唆しています。 

固定 S の場合、最適なプレイで出口に到達できるサイズ S のスタックが存在するかどうかを判断したいと考えます。 重要な再定式化は、視点を逆転させることです。スタックを構築して順方向にシミュレーションする代わりに、スタックの高さが S によって制限される構成における到達可能性の問題としてゲームを考慮します。 

固定 S に対する直接的な総当りアプローチでは、長さ S の考えられるすべてのスタックを列挙し、プロセスをシミュレートします。 シミュレーションがスタックごとに多項式であっても、スタックの数は C^S であり、これはまったく実行不可能です。 

重要な観察は、私たちは色の正確な順序を実際には気にしておらず、最初から最後まで導くことができる何らかの順序が存在するかどうかだけを気にしているということです。 これにより、この問題は、状態がルームによって表現できる拡張状態空間での到達可能性の問題と、スタック内にどれだけの「有用な」一致が残るかという問題に変わりますが、スタックの正確なアイデンティティは問題になりません。 代わりに、トランジションを介してスタックを暗黙的にエンコードします。プッシュするとカウンターが S まで増加し、ポップすると、一致する色が使用されるとカウンターが減少します。

各ノードがペア (部屋、k) である階層化グラフを構築します。ここで、k は現在のスタック サイズです。 状態から、一致する色を消費する (k を 1 ずつ減らす) か、色をプッシュする (S まで k を 1 ずつ増やす) ことができます。 難しいのは、トランジションが出力エッジの色の存在に依存するため、部屋ごとに事前計算し、そのようなエッジが存在するかどうかを色付けすることです。 

この定式化から、実現可能性は、k ≤ S の場合、(0, 0) から任意の (R − 1, k) への到達可能性になります。次に、この暗黙的な状態グラフに対して BFS/DFS を実行します。 

実現可能性は単調であるため、S を二分探索します。サイズ S のスタックが機能する場合、無関係な色で埋められた有効なスタックのプレフィックスから開始することによって、任意の S' ≥ S も機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | スタックに対するブルートフォース | O(C^S・D) | O(S) | 遅すぎる |
 | 階層化された BFS + バイナリ検索 | O(log S_max · R · S · C) | O(R・S) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各部屋の出力構造を解釈して、色が使用可能かどうかを常時チェックできるようにします。 部屋ごとにブール配列を保存します`has[r][c]`色の出ていくエッジが少なくとも 1 つ存在するかどうかを示す`c`。 

次に、固定スタック制限 S の実現可能性チェックを定義します。 

1. 状態 (room, k) に対して BFS キューを作成します。ここで、k は (0, 0) から始まる現在のスタック サイズを表します。 これは、空のスタックでエントリから開始することに対応します。 
2. 状態 (r, k) から 2 種類の手を考えます。 
3. 次のような出射色 c が少なくとも 1 つ存在する場合、`has[r][c]`が true で、k > 0 の場合、デイジーはカードを「一致させる」ことを選択できます。 これは、一番上のカードと一致する色のエッジに沿って移動することに対応します。 これを、k を 1 ずつ減らしながら、そのようなエッジを介して到達可能な隣の部屋 r2 に移動するものとしてモデル化します。すでに隣接関係をエンコードしているため、このステップではすべてのエッジを明示的に列挙する必要はありません。 単に出力エッジを反復して有効性をチェックするだけです。 
4. k < S の場合、デイジーは「プッシュ」移動も実行できます。デイジーは任意の出力エッジ (r → r2、c) を選択し、r2 に移動し、k を 1 ずつ増やします。これは、一番上のカードが見つからないか使用できない場合をモデル化しているため、ポップする代わりに新しい色をプッシュします。 この移行はスタックが成長する唯一の方法であるため、非常に重要です。 
5. 状態を訪問済みとしてマークし、到達可能なすべての状態が処理されるまで BFS を継続します。 
6. BFS が終了した後、k ≤ S に対して状態 (R − 1, k) が到達可能かどうかを確認します。到達可能であれば、S は実現可能です。 
7. スタック サイズが遷移数を超える必要がないため、範囲 [0, D] 内の最小の S を二分探索します。 

これが機能する理由は、プロセスを制御されたプッシュ/ポップ システムとして解釈することに基づいており、意味のある唯一のリソースはコンテンツではなくスタックの高さです。 BFS は、部屋の接続を尊重しながら、デイジーがスタック サイズを操作できるあらゆる方法を調査することを保証します。 不変条件は、訪問されたすべての状態が有効な部分再生シーケンスに対応し、すべての有効な部分再生が BFS 内の何らかの到達可能な状態に対応するということです。 トランジションは強制プッシュ動作とオプションのポップ動作の両方を忠実にエンコードするため、有効な戦略が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    R, D, C = map(int, input().split())
    edges = [[] for _ in range(R)]
    has = [[False] * C for _ in range(R)]

    for _ in range(D):
        f, t, c = map(int, input().split())
        edges[f].append((t, c))
        has[f][c] = True

    def ok(S):
        # visited[r][k]
        vis = [[False] * (S + 1) for _ in range(R)]
        q = deque()
        q.append((0, 0))
        vis[0][0] = True

        while q:
            r, k = q.popleft()

            # push transitions
            if k < S:
                for to, c in edges[r]:
                    if not vis[to][k + 1]:
                        vis[to][k + 1] = True
                        q.append((to, k + 1))

            # pop transitions (only if stack not empty)
            if k > 0:
                for to, c in edges[r]:
                    if not vis[to][k - 1]:
                        vis[to][k - 1] = True
                        q.append((to, k - 1))

        for k in range(S + 1):
            if vis[R - 1][k]:
                return True
        return False

    lo, hi = 0, D
    ans = D
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、明示的な隣接リストと部屋ごとの色の存在テーブルが構築されますが、最終的な BFS は主に隣接エッジを直接使用します。 

の`ok(S)`関数は、(部屋、スタックの高さ) に対して BFS を実行します。 訪問されたテーブルにより状態の再訪問が防止され、複雑さが O(R・S) によって制限されます。 プッシュ遷移はスタックの高さを 1 つ増やし、どの出力エッジからも許可されます。 ポップトランジションはスタックの高さを 1 つ減らし、エッジを通過するために有効なカードを消費することを表します。 

二分探索は、この実現可能性チェックをラップします。 スタックは構築的なパスの移動数を超える必要がないため、上限は D です。 各プッシュは少なくとも 1 つのエッジ トラバースに対応します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    def solve():
        R, D, C = map(int, sys.stdin.readline().split())
        edges = [[] for _ in range(R)]
        for _ in range(D):
            f, t, c = map(int, sys.stdin.readline().split())
            edges[f].append((t, c))

        def ok(S):
            vis = [[False] * (S + 1) for _ in range(R)]
            q = deque([(0, 0)])
            vis[0][0] = True

            while q:
                r, k = q.popleft()
                if k < S:
                    for to, _ in edges[r]:
                        if not vis[to][k + 1]:
                            vis[to][k + 1] = True
                            q.append((to, k + 1))
                if k > 0:
                    for to, _ in edges[r]:
                        if not vis[to][k - 1]:
                            vis[to][k - 1] = True
                            q.append((to, k - 1))

            return any(vis[R - 1])

        lo, hi = 0, D
        ans = D
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 重要なエッジケースは、グラフがすでに入口から出口までの単純なパスである場合です。 この場合、デイジーはプッシュまたはポップする必要がないため、S = 0 が有効です。 (0,0) からの BFS は、必要な場合にのみプッシュ遷移を介して (R−1,0) にすぐに到達しますが、ここでは強制的なスタッキングは必要ありません。 

もう 1 つのエッジ ケースは、代替出力エッジなしで最初に戻る純粋なサイクルです。 たとえば、0 → 1 → 0 です。ここでは、出口がなく、BFS が正しく (R−1,k) に到達しないため、どのような正のスタックも役に立ちません。 アルゴリズムは、すべての S に対して実行不可能を正しく返します。 

より微妙なケースは、強制的なプッシュとポップの特定の交互の後にのみ出口に到達できる場合に発生します。 このようなグラフでは、BFS が必要な一連の高さの変化を維持できないため、S が小さいと失敗します。 S を増やすと、最終的に交互パスを (room, k) 状態空間内の有界歩行として表現できるようになり、最初に成功した S が二分探索で見つかった正確な答えとなります。
