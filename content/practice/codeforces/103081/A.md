 ## 解決策
 ## 問題の理解

 私たちはベンの日々の感謝の記録を時系列で記録したものを渡されました。 毎日、ちょうど 3 つの独立したテキスト エントリが提供されるため、一日を通して合計 3N 個の文字列のシーケンスが存在します。 それぞれの文字列は、ベンが書き留めた 1 つの「もの」を表します。 

タスクは、最も頻繁に出現する K 個の文字列を特定することによって、このコレクションを要約することです。 頻度だけでは順序を完全に決定するのに十分ではありません。 2 つの異なる文字列が同じ回数出現する場合、入力内で最後に出現する文字列が最初に来る必要があります。 

出力は、個別の文字列のランク付けされたリストで、主に頻度の降順、次に最終出現インデックスの降順で並べ替えられ、それらの上位 K 個のみが出力されます。 

入力サイズはテキストの最大 100,000 行に達します。 データセット全体を文字列ごとに繰り返し並べ替えたりスキャンしたりするソリューションは、遅すぎます。 自然な制約は、文字列に対して O(N^2) を超えることは不可能であるため、O(N log N) または O(N) に近い値を目指す必要があることを示唆しています。 

微妙な問題は、順序がカウントだけでなく最後の出現位置にも依存することです。 これは、単一パス中に両方の集計を追跡する必要があることを意味します。 単純な周波数マップは、位置情報も保存しない限り不十分です。 

いくつかの特殊なケースが重要です。 

すべての文字列が一意である場合、すべての頻度は 1 であるため、順序付けは完全に最後の出現に依存し、事実上一意の要素の入力順序が逆になります。 

すべての文字列が同一の場合、K に関係なく、出力行は 1 行だけになります。 

K が個別の文字列の数を超える場合は、すべての個別の文字列が出力されます。 

単純な間違いは、頻度だけで並べ替えて、同点ブレーク ルールを無視することです。 たとえば、「A」と「B」が両方とも 2 回出現するが、最後に出現するのが「A」の方が「B」よりも前である場合、それらの回数が同じであっても、「B」が最初に出現する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。最初に 3N 個の文字列をすべて収集し、次に個別の文字列ごとにリスト全体を再度スキャンして出現回数をカウントし、その最後の位置を追跡します。 その後、これらの計算された値を使用して、すべての個別の文字列を並べ替えます。 

これは正しいですが、非常に高価です。 U 個の個別の文字列があり、それぞれが O(N) 個のスキャンを必要とする場合、前処理だけで O(UN) のコストがかかります。 最悪の場合、U は Θ(N) となり、O(N²) が得られますが、これは N が 100,000 までの場合には実現不可能です。 

重要な観察は、必要な統計、頻度と最終出現インデックスの両方が 1 回の線形スキャンで計算できることです。 文字列ごとのカウントを再計算する代わりに、文字列からペア (そのカウントとそれが出現した最後のインデックス) へのハッシュ マップを維持します。 各更新は平均 O(1) であるため、完全な前処理は O(N) です。 

このマップを取得したら、それをリストに変換し、必要な順序付けキーを使用して 1 回並べ替えます (頻度が高い順、最後のインデックスが大きい順)。 これにより、問題は U 項目にわたる標準的な並べ替えタスクに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ

1. 実行インデックス i を 0 から 3N−1 に保ちながら、すべての 3N 文字列を順番に読み取ります。 タイブレークは最後の出現位置に依存するため、インデックスは必須です。 
2. 文字列をキーとする辞書を管理します。 位置 i にある各文字列 s について、頻度を増分し、最後の位置を i に設定することにより、そのエントリを更新します。 常に最新の位置が必要なので、最後の位置を上書きすることは正しいことです。 
3. すべての行を処理した後、辞書を形式 (frequency、last_position、string) のタプルのリストに変換します。 この形式により並べ替えが簡単になります。 
4. カスタム順序を使用してこのリストを並べ替えます。頻度が高い順に並べ替えます。頻度が同じ場合は、last_position が大きい順に並べ替えます。 文字列自体は出力のためにのみ伝送されます。 
5. ソートされたリストから最初の K 個の文字列を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、i 番目の行を処理した後、辞書内のすべての文字列が接頭辞 [0, i] の合計頻度と、その接頭辞で最後に出現したインデックスを正確に格納するという不変条件を維持します。 すべての更新はローカルであり、最後の位置のみを上書きするため、正確さに影響を与える可能性のある履歴情報が失われることはありません。 最後の反復の後、これらの値はシーケンス全体に対して正確であるため、それらをグローバルに並べ替えることで必要なランキングが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    freq = {}
    last = {}
    
    for i in range(3 * n):
        s = input().rstrip('\n')
        if s in freq:
            freq[s] += 1
        else:
            freq[s] = 0
            freq[s] = 1
        last[s] = i
    
    items = []
    for s in freq:
        items.append((freq[s], last[s], s))
    
    items.sort(key=lambda x: (-x[0], -x[1]))
    
    out = []
    for i in range(min(k, len(items))):
        out.append(items[i][2])
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、頻度用と最終出現インデックス用の 2 つの辞書を使用します。 これらを 1 つの構造にマージすることもできますが、それらを別々にしておくと、一方が数量を追跡し、もう一方が最新性を追跡するというロジックが明確になります。 

並べ替えキーは、問題の順序付けルールを直接エンコードします。 頻度と最後のインデックスの両方を無効にすると、デフォルトの昇順ソートが必要な降順に変わります。 

微妙な点は、生の入力行に最後のインデックスをループ カウンター i として保存していることです。 これにより、日が 3 つにグループ化されている場合でも、正確な時系列比較が保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | シングルパスは O(N) でハッシュマップを構築し、U ≤ 3N アイテムのソートコストは O(N log N) |

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import sys
    from io import StringIO
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = StringIO(inp)
    sys.stdout = StringIO()
    
    def solve():
        n, k = map(int, input().split())
        freq = {}
        last = {}
        for i in range(3 * n):
            s = input().rstrip('\n')
            if s in freq:
                freq[s] += 1
            else:
                freq[s] = 1
            last[s] = i
        
        items = [(freq[s], last[s], s) for s in freq]
        items.sort(key=lambda x: (-x[0], -x[1]))
        k2 = min(k, len(items))
        print("\n".join(items[i][2] for i in range(k2)))
    
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out.strip()

 ## 特殊なケース

 よくある失敗例は、最後の出現ルールを無視することです。 考慮する：```
1 2
A
B
A
```ここでは、A と B は両方とも 1 回出現しますが、最後に出現するのはインデックス 2 で、B はインデックス 1 であるため、A は B より前に来る必要があります。アルゴリズムはスキャン中に最後の位置を正しく更新するため、A の優先順位が高くなります。 

もう 1 つのエッジ ケースは、K が一意の文字列の数を超える場合です。 並べ替えステップでは個別の項目のみが生成されるため、min(k, len(items)) を使用してスライスすることで範囲外の出力を防ぎます。
