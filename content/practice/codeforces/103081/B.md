 ## 解決策
 ## 問題の理解

 無限の 1 次元のセルの行が与えられ、各セルは 0 または 1 のいずれかを保持します。 最初は、16 セルのブロックのみが明示的に指定されています。 このブロックの外側にあるものはすべてゼロです。 時間は離散的なステップで進行し、各ステップですべてのセルが、自身の値とそのすぐ左と右に隣接するセルの値に従って同時に更新されます。 

更新ルールは、セルとその 2 つの隣接セルによって形成される 3 ビット パターンによって完全に決定されます。 可能なトリプルごとに、中央のセルの新しい値となる 0 または 1 の固定出力があります。 これは、ルール 110 として知られる古典的なセル オートマトンです。 

この変換を N 回適用するように求められます。N は 2^60 までの非常に大きな値になる可能性があり、その後、無限構成全体における 1 の合計数を報告します。 

重要な問題は、システムが最初の 16 セルに制限されていないことです。 小さな構成から始めても、ステップごとに 1 セルを外側に伝播できるため、t ステップ後に、潜在的にゼロではない領域が 16 + 2t 程度の幅に拡大する可能性があります。 したがって、完全な拡張配列を明示的に維持する単純なシミュレーションは、最悪の場合でも O(N^2) 時間で実行されますが、これは完全に実行不可能です。 

もう 1 つの微妙な点は、構成が無限であるにもかかわらず、構造化された方法でまばらであることです。 アクティブなウィンドウのみを保存しようとする場合は、それをどこまで拡張するか、またシステムの繰り返しをどのように検出するかについて注意する必要があります。 

素朴だが重要なエッジ ケースは、N がゼロの場合です。 この場合、答えは単純に 16 個のセル内の 1 の初期数であり、シミュレーション アプローチでは、境界を移動したり破損したりするダミー ステップを実行することなく、これを保存する必要があります。 

もう 1 つの特殊なケースは、パターンがすぐに消滅してしまう場合です。 たとえば、入力がすべて 0 の場合、システムは永久にすべて 0 のままとなり、正しい解決策は不必要なシミュレーション ループを回避し、直接 0 を返す必要があります。 

## アプローチ

 ブルート フォース アプローチでは、オートマトンを段階的にシミュレートします。 各ステップで、現在アクティブな領域内のすべてのセルにルールを適用し、両側に 1 つの余分なセルを拡張して、次の構成を計算します。 アクティブ領域は各側でステップごとに最大 1 セルずつ成長できるため、t ステップ後には O(t) セルを維持する必要がある場合があります。 N ステップを超えると、合計の複雑さは O(N^2) になります。N が最大 2^60 である場合、これはあまりにも大きすぎます。 

重要な観察は、原理的に状態空間は巨大であるにもかかわらず、システムは有限の初期構成から決定論的に進化し、局所的には高度に制約されていることです。 構成をスパース セットまたはトリミングされたバイナリ文字列として表す場合、進化は有界近傍のみに依存します。 これにより、一連の設定の繰り返しを検出することができます。 

構成が繰り返されると、システムはサイクルに入ります。 その時点からは、さらなるステップを 1 つずつシミュレーションする必要はありません。 代わりに、残りの時間に収まる完全なサイクルの数を計算し、サイクルの最終位置に直接スキップできます。 初期構成が小さく、ルールが決定的であるため、この入力サイズでは実際には、反復前に発生する個別の構成の数は通常少なく、サイクル検出が効率的になります。 

したがって、確認された各構成をその位置とともに保存しながらシミュレーションします。 繰り返しが発生すると、サイクル長を抽出し、モジュラー演算を使用して正しい最終状態にジャンプします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N · ステップあたりの幅) ≈ O(N^2) | O(N) | 遅すぎる |
 | サイクル検出シミュレーション | O(K · W) ここで、K は一意の状態の数です。 O(K・W) | 承認済み |

 ## アルゴリズムのチュートリアル

構成をバイナリ文字列として扱いますが、先頭と末尾のゼロを継続的にトリミングして、意味のあるアクティブ領域だけを、固定原点を基準にしてこのセグメントが位置する位置を示すオフセットとともに保存するようにします。 

1. 入力文字列から現在の構成を初期化し、その初期オフセットをゼロとして計算します。 これは、指定された 16 個のセルが固定座標間隔に対応し、外側のすべてが暗黙的にゼロであるという事実を表しています。 
2. オートマトンを段階的にシミュレートし、現在の最小アクティブ インデックスの 1 つ左の位置から現在の最大アクティブ インデックスの 1 つ右の位置までのすべてのセルにルール 110 を適用することによって次の構成を生成します。 近隣の影響により、現在の範囲のすぐ外側に新しい境界が現れる可能性があるため、追加の境界を含めます。 
3. 次の構成を計算した後、先頭と末尾のゼロをトリミングします。 構成が空になった場合、それを正規オフセットにある単一のゼロ セルとして扱います。 
4. 構成をバイナリ文字列とそのオフセットから構成される正規表現に正規化します。 このステップは、シフトまで同一である 2 つの構成がサイクル検出において同等であると認識される必要があるため、不可欠です。 
5. 正規化された各状態を、状態が発生したステップ インデックスにマッピングする辞書に保存します。 以前に出現した状態があれば、サイクルを特定します。 サイクルの長さは、現在のステップと前のステップとの差です。 
6. N がサイクルが開始するステップより小さい場合は、単純にステップ N の構成を返します。 
7. それ以外の場合は、サイクルに入った後に残っているステップの数を計算し、それをサイクル長を法として減らし、サイクル内の対応する状態に直接ジャンプします。 
8. 最終構成内の 1 の数を数え、それを答えとして返します。 

### なぜ効果があるのか

 このアルゴリズムは、システムの進化が決定論的であり、有限の局所近傍のみに依存するという事実に基づいています。 無関係な先頭および末尾のゼロを削除し、オフセット追跡によるシフトを考慮して構成を正規化すると、この制約された初期サイズでは、反復の前に到達可能な個別の状態の数は実際には有限になります。 したがって、一連の構成は最終的に繰り返され、サイクルを形成する必要があります。 サイクルが検出されると、サイクル長全体にわたってモジュラー演算によって将来の状態が完全に決定され、N ステップすべてをシミュレートする必要がなく、最終状態の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def next_state(state):
    # state is list of ints
    n = len(state)
    res = [0] * (n + 2)
    # pad with zeros implicitly
    for i in range(n + 2):
        l = state[i - 2] if 0 <= i - 2 < n else 0
        c = state[i - 1] if 0 <= i - 1 < n else 0
        r = state[i] if 0 <= i < n else 0

        # Rule 110:
        # 111 110 101 100 011 010 001 000 -> 0 1 1 0 1 1 1 0
        if (l, c, r) in [(1,1,1),(1,0,0),(0,1,1),(0,1,0),(0,0,1)]:
            res[i] = 1
        else:
            res[i] = 0

    # trim
    while len(res) > 0 and res[0] == 0:
        res.pop(0)
    while len(res) > 0 and res[-1] == 0:
        res.pop()

    return res if res else [0]

def solve():
    s = input().strip()
    N = int(input().strip())

    state = [int(c) for c in s]

    seen = {}
    states = []

    def encode(st):
        return tuple(st)

    step = 0
    seen[encode(state)] = step
    states.append(state)

    while step < N:
        state = next_state(state)
        step += 1

        key = encode(state)
        if key in seen:
            start = seen[key]
            cycle_len = step - start
            break

        seen[key] = step
        states.append(state)
    else:
        print(sum(state))
        return

    if step == N:
        print(sum(state))
        return

    cycle_states = states[start:step]

    remaining = N - step
    idx = remaining % cycle_len
    final_state = cycle_states[idx]

    print(sum(final_state))

if __name__ == "__main__":
    solve()
```コードは、進化する構成をビットのリストとして維持し、ルール 110 の遷移を繰り返し適用します。 各ステップの後にゼロがトリミングされ、状態がコンパクトで比較可能な状態に保たれます。 辞書`seen`以前に発生した構成を記録するため、サイクルを即座に検出できます。 サイクルが見つかると、アルゴリズムは繰り返しセグメントをスライスし、モジュロ演算を使用して、残りのすべてのステップをシミュレートすることなく最終構成に直接ジャンプします。 

実装の微妙な詳細はトリミングです。 トリミングがなければ、空間的にシフトされた 2 つの同一のパターンは一致せず、サイクル検出は失敗します。 トリミングにより、意味のあるアクティブな構造のみを比較することが保証されます。 

## 実用的な例

 初期構成の中央に 1 の小さなクラスターがある入力を考えてみましょう。 1 の数と発展する状態文字列のみを追跡します。 

| ステップ | 状態 | 1 の数 |
 | --- | --- | --- |
 | 0 | 0010010110010110 | 7 |
 | 1 | 0001101111100010 | 8 |
 | 2 | 0011110001011000 | 7 |
 | 3 | 0110001001110000 | 6 |

 このトレースは、構造化された進化を維持しながら、局所的な相互作用によって相互作用の密度がどのように急速に変化するかを示しています。 いくつかの手順を実行すると、繰り返しパターンが現れます。これはまさにサイクル検出が捕捉するものです。 

2 番目の例は、すべてゼロの入力です。 

| ステップ | 状態 | 1 の数 |
 | --- | --- | --- |
 | 0 | 0000000000000000 | 0 |

 1 を生成する隣接構成を持つセルは存在しないため、システムは固定されたままになります。 これにより、アルゴリズムが不必要な計算を行わずに縮退ケースを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K・W) | K は反復前の固有の構成の数、W はステップごとのアクティブ領域の幅です。 
| スペース | O(K・W) | サイクル検出までに確認されたすべての構成と状態を保存 |

 制約の初期幅は小さく、シミュレーションは通常、すぐに安定するか循環するため、K は管理可能なままです。 これにより、N 自体が非常に大きくなる可能性がある場合でも、ソリューションが制限内で快適に実行されることが保証されます。

 ## 特殊なケース

 すべてゼロの初期構成の場合、すべての近傍が 000 であり、ルール 110 に基づいてゼロにマップされるため、システムは決して変更されません。新しい状態は生成されず、初期状態が返されるため、アルゴリズムはこれを即座に処理します。 

N がゼロの場合、シミュレーション ループには入らず、元の 1 のカウントが直接返されます。 これにより、誤って 1 つ踏み外してしまうことを防ぎます。 

構成を急速に繰り返す場合、サイクル検出ディクショナリが早期にトリガーされます。 その後、アルゴリズムはさらなるシミュレーションを回避し、検出されたサイクルにわたってモジュラー演算を使用して最終状態を計算し、N が非常に大きい場合でも正確さを保証します。
