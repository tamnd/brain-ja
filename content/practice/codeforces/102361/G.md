 ## 解決策
 ## 問題の理解

 各セルに最大 1 つのチェスの駒を含む (n\times) ボードがあります。 すべてのピースは白または黒で、プラスの除去値を持っています。 白と黒のピースが両方とも左下方向から露出している場合、一緒に除去される可能性があります。 このようなペアの価格は、それらの値の絶対的な差です。 単一のピースは、それ自体の価値のためにいつでも削除することができます。 

特殊なのは露出条件です。 ((x,y)) にあるピースの場合、(x'\ge x) および (y'\le y) の場合は常に、((x',y')) にある別のピースがブロックします。 換言すれば、作品の弱く下方および弱く左方に何も残らない可能性がある。 すべての部分を削除するために必要な最小の総コストが必要です。 

元のコンテストには (n\le12) があり、制限時間は 1 秒、メモリは 1024 MB です。 ボードには (12^2=144) 個のピース​​を含めることができるため、ピース上のサブセット DP は最大 (2^{144}) 個の状態を持つことになります。 それは可能性をはるかに超えています。 (n) の値が小さいということは、ピースの数が潜在的に多いというよりも、有用な状態がボードの境界を表すものであることを示唆しています。 (n=12) の場合、単調境界は (\binom{24}{12}=2,704,156) 個だけあります。これは大きいですが、低レベル言語で管理可能であり、指定されたメモリ制限内に快適に収まります。 この等高線 DP の観点は、問題の標準的な解決方向でもあります。 

直接的な貪欲な解釈を無効にするエッジケースがいくつかあります。 単一のピースは単独で処理する必要があります。 のために```
1
W
7
```答えは (7) です。組み合わせる黒のピースがないからです。 ペアのみを検索するソリューションでは、誤ってゼロが返されるか、部分が未処理のままになります。 

同じ価値のピースのペアはコストをゼロにすることができますが、それでも両方を同時に公開する必要があります。 考慮する```
2
W.
.B
5 0
0 5
```両方のピースはすでに露出しているため、コスト (0) で一緒に削除できます。 すべてのペアに正の単一除去コストが必要であると想定するソリューションでは、これを見逃してしまいます。 

逆の状況はさらに微妙です。 考慮する```
2
WB
B.
5 7
7 0
```((2,1)) の黒い部分はその上の両方の部分をブロックするため、最初はこれが唯一の関連する露出された部分になります。 これを削除するだけでも (7) コストがかかります。 最初の行の白と黒のピースが同時に露光され、コスト (2) でペアにすることができます。 答えは(9)です。 不注意なアルゴリズムでは、たとえ左下のブロッキング条件により最初にそのペアが使用されなかったとしても、セルに互換性があるように見えるため、最初の 2 つの部分がすぐにペアになる可能性があります。 

単一の任意の部分を自由に削除するには、任意の削除を輪郭状態に置く必要はありません。 別のピース (q) がブロック (p) をブロックしている間に、最適解がブロックされたピース (p) を単独で除去すると仮定します。 (p) 自体が (q) をブロックしている部分の 1 つであるため、(q) を使用可能にするために (p) を削除する必要はありません。 この依存関係に関係のない部分を含む操作は、(p) なしで同じ順序で実行できます。 (p) が露出した輪郭に達するまで、(p) の単一の除去を延期し、まったく同じ金額を支払うことができます。 したがって、そのピースが現在の輪郭上にあるときにすべての削除が行われる最適な解決策が常に存在します。 

## アプローチ

 自然な総当たりソリューションでは、残りのすべての部分セットが状態として扱われます。 状態から、現在露出しているすべての白い部分と現在露出しているすべての黒い部分を試すことができ、すべての単一の部分を削除することもできます。 メモ化すると、これが (m) 個の部分にわたるサブセット DP になります。 どの部分が公開されているかをチェックするコストを無視したとしても、状態空間は (2^m) であり、すべての可能なペアをチェックするには状態ごとに (O(m^2)) のコストがかかります。 (m=144) の場合、上限は次のようになります。 

[
 2^{144}\cdot144^2 \約 4.6\times10^{47}
 ]

 ペア状態のチェック。 ブルート フォースはあらゆる法的操作を直接モデル化しているため、概念的には正しいですが、状態の表現にはあまりにも多くの情報が含まれています。 

有益な観察は幾何学的なものです。 現在公開されている作品は常に左上から右下に向かって走るモノトーンの階段の上にあります。 この階段の左下にあるものがすべて削除されると、階段の任意の部分を削除でき、削除後、階段はそのセルを横切って移動します。 

正確に (n) 回の下方向への移動と (n) 回の右方向への移動を含むパスで階段を表します。 下向きの移動は (0) でエンコードし、右向きの移動は (1) でエンコードします。 まさにあります

 [
 \binom{2n}{n}
 ]

 そういった道。 ローカルパターン(01)は階段の角です。 その隅にあるセルは、まさに現在削除できるセルです。 そのセルを削除すると、ローカル パスが (01) から (10) に変更されます。 

空のコーナーにはコストはかからず、空のセル内で輪郭を移動するだけです。 占有されたコーナーは、その価値を支払って単独で削除できます。 占有されている 2 つの角の色が異なる場合、両方の部分が同時に露光されるため、それらを一緒に削除して、対応する 2 つの変更 (01\to10) を一度に行うことができます。 それらの移行コストは、それらの値の絶対的な差です。 

これにより、すべての輪郭状態にわたって最短パス スタイルの DP が得られます。 重要な単純化は、すべての遷移が輪郭を一方向に移動させるため、状態が DAG を形成することです。 一般的な最短パス アルゴリズムは必要ありません。 マスクをトポロジカルな順序で処理できます。 

輪郭アプローチには (\binom{2n}{n}) 個の状態があります。 1 つの状態に対してコーナーは最大 (n) 個あり、コーナーのすべてのペアを試行するには (O(n^2)) のコストがかかります。 これにより、許容される (O(n^2\binom{2n}{n})) の複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット DP | (O(2^{n^2}n^4)) | (O(2^{n^2})) | 遅すぎる |
 | 輪郭DP | (O(n^2\binom{2n}{n})) | (O(2^{2n})) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 長さ (2n) のバイナリ文字列で輪郭を表します。 0 は輪郭が下に移動することを意味し、1 は輪郭が右に移動することを意味します。 正確に (n) ビットが 1 であるため、すべての有効な輪郭は (\binom{2n}{n}) 個のマスクの 1 つに対応します。

輪郭を使用して、すでに消去されたセルと、まだ破片が含まれている可能性のあるセルを分離します。 パターン (01) で表されるコーナーは、露出できる次のセルを識別します。 
2. 下方向 (n) 回、次に右方向 (n) 回の輪郭から始めます。 元のビット順序では、これは (0^n1^n) です。 唯一の関連するコーナーはボードの左下の境界であり、まさに最初に最初に露出されるピースが発生する場所です。 

最終的な輪郭は (1^n0^n) です。 この時点で、ボード全体が処理されます。 
3. すべての輪郭について、ローカル パターン (01) を含むすべての位置を見つけます。 このような各位置をボード セル ((x,y)) に変換します。 輪郭がゼロコストで空のセルを通過する可能性があるため、空のセルも含まれます。 
4. すべてのコーナーセルに対して、単一削除トランジションを実行します。 セルが空の場合、追加されるコストはゼロです。 ピースが含まれている場合、追加されたコストがその価値になります。 

このトランジションは、露出時にその部分だけを削除すること、または単に空のセルを通して輪郭を進めることを表します。 
5. 占有されているコーナーセルをすべて収集します。 異なる色のペアごとに、両方の (01) コーナーを同時に (10) に反転するトランジションを実行します。 それらの値の差の絶対値を加算します。 

トランジション前は両方のピースが同じ輪郭のコーナーであるため、両方のピースは同時に正当です。 2 つの (01) パターンはオーバーラップできないため、2 つのローカル フリップは独立しています。 
6. すべての輪郭の最小コストを保存します。 トランジションは常に (01) から (10) に変化するため、輪郭は最終輪郭に向かって単調に移動します。 これにより DAG が得られ、状態を再度確認することなく順番に処理できるようになります。 
7. 実装では、輪郭ビットの順序を逆にします。 その後、元の (01\to10) 遷移は (10\to01) になり、マスクの整数値が増加します。 したがって、Gosper の組み合わせ生成トリックを使用して、正確に (n) セットのビットを持つすべてのマスクを数値の昇順に列挙できます。 結果として得られるマスクは正確に輪郭状態ですが、その遷移方向は列挙方向と一致します。 
8. 答えは、最終的な輪郭の反転した形での DP 値です。 空のセルを通る各輪郭の遷移にはコストがゼロであるため、空のボードも当然同様に機能します。 

これが機能する理由: 等高線の DP 値が、その等高線の既に処理された側のすべてをクリアし、残りをそのままにする最小コストであるという不変条件を維持します。 すべての合法的な操作は、その部分が輪郭に到達したときに実行される操作に変換できます。 1 つの操作は 1 つのコーナー フリップに対応し、有効な白と黒のペアは同時に行われる 2 つのコーナー フリップに対応します。 逆に、DP によって生成されるすべての遷移は、その隅のセルが現在の輪郭上に露出しているため、正当な操作です。 したがって、すべての有効な削除シーケンスは DP を通るパスによって表され、すべての DP パスはまったく同じコストの有効な削除シーケンスを記述します。 したがって、最終輪郭で最小 DP 値を取得すると、最適値が得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())

    board = [input().strip() for _ in range(n)]
    color = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            if board[i][j] == 'W':
                color[i][j] = 1
            elif board[i][j] == 'B':
                color[i][j] = 2

    weight = []
    for _ in range(n):
        weight.append(list(map(int, input().split())))

    length = 2 * n
    size = 1 << length

    # We store the contour in reversed bit order.
    #
    # Original start:  0^n 1^n
    # Reversed start:  1^n 0^n
    #
    # Original end:    1^n 0^n
    # Reversed end:    0^n 1^n
    start = (1 << n) - 1
    end = start << n

    # int32 is sufficient:
    # at most 144 single removals, each <= 1e6.
    dp = array('i', [-1]) * size
    dp[start] = 0

    # Bit j of r is the lower bit of an original 01 corner.
    corner_mask = (1 << (length - 1)) - 1

    r = start
    limit = 1 << length

    while r < limit:
        cur = dp[r]

        if cur != -1:
            corners = r & ~(r >> 1) & corner_mask

            pieces = []

            c = corners
            while c:
                low = c & -c
                j = low.bit_length() - 1

                # In the reversed contour, this corner corresponds
                # to original bit positions i and i+1.
                i = length - 2 - j

                # Bits strictly above j+1 in the reversed mask
                # correspond to the original prefix before i.
                y = (r >> (j + 2)).bit_count()
                x = i - y

                col = color[x][y]

                if col:
                    pieces.append((j, col, weight[x][y]))
                    add = weight[x][y]
                else:
                    add = 0

                # 10 -> 01 in the reversed mask.
                # This increases the mask by exactly 2^j.
                nxt = r + low
                nv = cur + add

                old = dp[nxt]
                if old == -1 or nv < old:
                    dp[nxt] = nv

                c -= low

            # Remove two exposed pieces together.
            m = len(pieces)
            for a in range(m):
                j1, c1, w1 = pieces[a]
                for b in range(a):
                    j2, c2, w2 = pieces[b]

                    if c1 == c2:
                        continue

                    low1 = 1 << j1
                    low2 = 1 << j2

                    nxt = r + low1 + low2
                    nv = cur + abs(w1 - w2)

                    old = dp[nxt]
                    if old == -1 or nv < old:
                        dp[nxt] = nv

        # Gosper's hack: next mask with exactly n set bits.
        low = r & -r
        nxt = r + low
        r = (((nxt ^ r) >> 2) // low) | nxt

    print(dp[end])

if __name__ == "__main__":
    solve()
```入力はまず 2 つの配列に変換されます。`color[i][j]`空のセルには 0、白には 1、黒には 2 が格納されます。 別個の`weight`配列には除去値が格納されます。 

DP 配列は、符号付き 32 ビット整数を使用します。`array('i')`。 可能な最大の答えは最大 (144\cdot10^6=144,000,000) であるため、32 ビットで十分です。 通常の Python リストを使用すると、すべての整数が Python オブジェクトになるため、はるかにコストが高くなります。 (n=12) では、高密度 DP には (2^{24}) 個のエントリがあるため、コンパクトな整数配列によりメモリ消費量は約 64 MB に抑えられます。 

実装では輪郭を逆方向に保存します。 元の表現では、露出したコーナーを削除すると変更が加えられます。`01`に`10`、整数マスクを減らします。 減少するマスクを処理することは機能しますが、そのようなマスクをすべて効率的に列挙することは Python ではあまり便利ではありません。 ビット順序を反転すると、同じ遷移は次のようになります。`10`に`01`そしてマスクを増やします。 その後、Gosper のハックは、(n) 個のマスクを含むマスクを昇順に正確に列挙します。 

ビット位置の反転コーナーの場合`j`、対応する元のコーナーは次の位置で発生します。`i = 2*n - 2 - j`。 そのコーナーの前にある元の右の動きの数は、上記の反転されたサフィックスに設定されているビットの数です。`j + 1`、によって計算されます```
y = (r >> (j + 2)).bit_count()
```そして下向きの移動の数は`x = i - y`。 これが、すべての状態に対して明示的な (2n) ステップのパス スキャンが必要ない理由です。 

表現```
corners = r & ~(r >> 1) & corner_mask
```すべての反転を見つけます`10`パターン。 の`corner_mask`存在しない最終位置を削除し、ビット (2n-1) の範囲外のコーナーを回避します。 

一角に変えて`10`に`01`マスクをちょうど (2^j) だけ増やすので、`nxt = r + low`十分です。 2 つの異なる角は重なることができません。`10`パターンはビットを共有できないため、2 つのフリップは同様に次のように記述できます。`r + low1 + low2`。 

ペアの遷移は、2 つの隅の色が異なる場合にのみ考慮されます。 移行コストは正確に`abs(w1 - w2)`、ペア削除ルールに一致します。 空の輪郭セルは、削除を表さない場合でも通過可能でなければならないため、空のコーナーを含むすべてのコーナーに対して単一の遷移が考慮されます。

 ### サンプル 1

 公式サンプルの場合、占有されているすべてのセルの値は (1) であるため、すべての有効なペアのコストはゼロです。 唯一のプラスのコストは、希望の組み合わせが可能になる前に単独で除去する必要があるピースから発生します。 与えられた最適シーケンスには、そのような除去が 3 つあります。 

輪郭 DP は、次の関連する遷移を通じて表示できます。 マスクは元の輪郭規則で示されています。`0`ダウンを意味し、`1`正しいという意味です。

 | 3 | ((2,4)) だけを削除 | 角をひっくり返す | 3 |

 | 5 | ペア ((1,1),(3,2)) | 2 つの角を反転する | 3 |

[
 \binom{24}{12}=2,704,156。 
]

 DP 配列には (2^{24}=16,777,216) 個のエントリがあり、32 ビット整数で約 64 MB が必要です。 理論的な時間限界は、この問題の標準的な等高線 DP 限界です。 また、Python 実装では、正確に (12) ビットが設定されたマスクのみを列挙することで、すべての (2^{24}) 整数のスキャンが回避され、処理される状態の数が約 1,680 万から約 270 万に減少します。

 ## 特殊なケース

 一体型ケース```
1
W
7
```唯一の輪郭遷移で始まり、終わります。 セルは占有コーナーであるため、DP は (7) を追加し、最後の輪郭に移動して、(7) を返します。 色または欠落している反対色の場合の特別なコードはありません。 

ゼロコストペア```
2
W.
.B
5 0
0 5
```最初に空の左下隅を横切ります。 これにより、占有されている隅の両方 (一方は白、もう一方は黒) が露出します。 ペアの遷移は両方の角を反転して加算します (|5-5|=0)。 残りの輪郭の動きはコストゼロで空のセルを通過するため、最終的な答えは (0) になります。 

ブロッキングケース```
2
W.
B.
1 0
1 0
```占有された隅にある左下の黒い部分だけから始まります。 (1)については民進党単独で削除する必要がある。 次に、白い部分が露出し、別の (1) のために単独で除去され、(2) が得られます。 同時に 2 つのコーナーに異なる色が存在することはないため、それらをペアにするトランジションはありません。 

より興味深いブロックの例```
2
WB
B.
5 7
7 0
```左下の黒い部分が露出した状態から始まります。 これを削除するだけでも (7) コストがかかります。 そして、輪郭は 1 行目の 2 つのピースが両方とも角である状態に達します。 これらは異なる色を持っているため、DP はそれらを (|5-7|=2) でペアにすることができます。 合計は(9)です。 これはまさに、貪欲ペアリングの信頼性を低下させる種類の依存関係です。 

最後に、最大サイズの疎ケースには (n=12) 個の部分が 1 つしかありません。 輪郭 DP は依然として輪郭状態の完全なファミリーを列挙しますが、占有セルを通過するものを除く到達可能なすべての遷移のコストはゼロです。 唯一のプラスの寄与は、(1,000,000) 値の白い部分の 1 回の除去であるため、答えは (1,000,000) です。 このテストでは、実装が整数オーバーフローなしで完全な 24 ビットの等高線表現と大きなセル値を処理することを確認します。
