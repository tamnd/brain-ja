 ## 解決策
 ## 問題の理解

 各クエリ ポイント (A) に対して、2 つの異なる元のポイント (P_u) と (P_v) を選択する必要があります。 3 つの点は、1 つの角度が (90^\circ) に等しい非縮退三角形を形成する必要があります。 そのクエリの出力は、そのような順序のない元の点のペアの数です。 

重要な幾何学的条件はベクトルで表現されます。 (A) が直角の頂点であれば、

 [
 (P_u-A)\cdot(P_v-A)=0。 
]

 ただし、(A) は斜辺上にあることもあります。 この場合、ある原点 (P_i) が直角の頂点となり、条件は次のようになります。 

[
 (A-P_i)\cdot(P_j-P_i)=0。 
]

 これら 2 つのケースを区別することで、ソリューション全体が決まります。 

元のポイントとクエリは最大で (2000) 個あります。 1 つのクエリには元の点の考えられるペアが約 200 万あり、すべてのクエリに対してこれを実行するには、最大サイズで約 (4\times10^9) のペア チェックが必要になります。 公式ジャッジはこの問題に 4 秒の制限時間を与えているため、立体的に見えるアプローチは私たちが許容できる範囲をはるかに超えています。 

座標は (10^9) に達する可能性があるため、差は (2\times10^9) に達する可能性があり、内積はおおよそ (4\times10^{18}) に達する可能性があります。 Python の整数はこれらの値を直接処理しますが、固定幅の実装には 64 ビットの演算が必要になります。 

最初の微妙なケースは、同じ頂点からの複数のベクトルが同じ線上を指す場合です。 例えば：```
3 1
1 0
-1 0
0 1
0 0
```正しい出力は次のとおりです`2`。 2 つの水平点は 1 つの方向の線を形成し、垂直点は垂直線を形成するため、水平端点には 2 つの選択肢があります。 方向の代わりに生のベクトルを格納する不注意な実装では、((1,0)) と ((-1,0)) が同じ幾何学的直線に属しているという事実を見落とす可能性があります。 

2 番目の微妙なケースは、クエリ自体が直角の頂点である必要がないことです。 例えば：```
2 1
0 0
1 0
0 1
```正しい出力は次のとおりです`1`。 直角はクエリ点 ((0,1)) ではなく ((0,0)) にあります。 クエリの周囲の垂直ベクトルのみをカウントするアプローチでは、誤ってゼロが返されます。 

3 番目のエッジ ケースは、同じ垂直線上または水平線上の点で発生します。```
4 1
0 0
0 1
0 2
0 3
1 1
```正しい出力は次のとおりです`4`。 (x) 座標が等しいと、多くのベクトルが垂直になるように強制されるため、この場合、不正な傾きの処理、特に (x) 成分で除算するコードや一貫性のない方法で垂直方向を個別に扱うコードが捕捉されます。 

最後に、クエリ ポイントは元のすべてのポイントとは異なることが保証されます。 したがって、クエリまたは元の点から別の関連する点へのベクトルは、決して ((0,0)) にはなりません。 これは、方向の正規化が gcd で除算され、((0,0)) の gcd がゼロになるため重要です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべてのクエリ (A)、すべてのペア (P_u、P_v) が考慮され、三角形が直角かどうかがチェックされます。 1 つのクエリには (\binom n2) 個のペアがあるため、合計作業量は次のようになります。 

[
 O(qn^2)。 
]

 (n=q=2000) では、これは次のようになります。 

[
 2000\binom{2000}{2}=3,998,000,000
 ]

 ペアチェック。 テスト自体は一定時間ですが、特に Python では 40 億近くの反復はすでに多すぎます。 

可能なすべての三角形が直接検査されるため、総当たり攻撃が機能します。 問題は、垂直度がベクトルの長さではなく方向のみに依存するという事実を無視していることです。 

点 (O) が固定されているとします。 (O) から関連点までのすべてのベクトルを考慮します。 このような 2 つのベクトルは、方向線が垂直である場合に正確に直角を形成します。 すべての非ゼロベクトルをその無向線の正規表現に正規化できます。 ベクトル ((x,y)) の場合、両方の座標を (\gcd(|x|,|y|)) で除算し、(x>0)、または (x=0) かつ (y>0) となるように一貫した符号を選択​​します。 

たとえば、すべての

 [
 (1,2)、\quad (2,4)、\quad (-1,-2)、\quad (-2,-4)
 ]

 同じ正準方向 ((1,2)) になります。 

方向 (d=(x,y)) が正規化されると、垂直方向は単純に ((-y,x)) になり、その後に同じ正規化が続きます。 ハッシュ マップには、各方向に属するベクトルの数を格納できるため、垂直検索の予想時間は (O(1)) になります。 

クエリ ポイントには依然として 2 つの幾何学的役割があります。 クエリが直角頂点の場合、(n) 個のベクトルのそれぞれを正規化する必要があるため、そのクエリを (O(n\log C)) で独立して処理できます。ここで (C) は座標の大きさです。 

クエリが直角頂点でない場合、クエリの周囲のすべてのペアを独立して処理することはできません。 代わりに、視点を逆転させます。 原点(P_i)を直角の頂点として固定します。 (P_i) の周囲の他のすべての元の点の方向-周波数マップを構築します。 次に、すべてのクエリ (A) は、(P_i) からのベクトルが (A-P_i) に垂直である元の点の数を求めます。 この 1 つのマップが利用可能な限り、すべての (q) クエリに答えることができます。 これを元の点ごとに繰り返すと、(O(n^2+nq)) 方向の演算が得られます。 

2 つのケースを合わせると、数十億のペア チェックの作業が、およそ数百万のハッシュ マップ操作に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(qn^2)) | (O(1)) | 遅すぎる |
 | 方向ハッシュ | (O((nq+n^2)\log C)) 期待される | (O(n)) | 承認済み |

 ここで (C) は座標の差の大きさを表します。 対数因数は、次で使用される Euclid のアルゴリズムに由来します。`gcd`。 

## アルゴリズムのチュートリアル

 1. 2 番目のケースを処理する前に、すべての元のポイントとすべてのクエリ ポイントを読み取ります。 これにより、すべてのクエリがすでに既知であるため、固定された元の直角頂点の計算が完全にオフラインになります。 
2. 方向正規化関数を定義します。 非ゼロベクトル ((dx,dy)) の場合、両方の座標を gcd で除算し、(dx<0) の場合、または (dx=0) かつ (dy<0) の場合に両方の符号を反転します。 結果は、原点を通る無方向の線を表します。 

私たちは意図的に反対のベクトルを特定します。 直角度の場合、((1,0)) と ((-1,0)) はまったく同じ役割を果たし、これらを分離するとカウントが複雑になるだけです。 
3. すべてのクエリ (A) に対して、(n) 方向の周波数マップ (P_i-A) を構築します。 (c_d) 回出現するすべての方向 (d) について、その正準垂直方向 (d^\perp) を計算します。 これら 2 つの方向クラスによって提供されるペアの数は (c_d c_{d^\perp}) です。 
4. すべての方向クラスにわたるこれらの積を合計し、2 で割ります。 垂直方向のペアは各エンドポイント方向から 1 回出現するため、除算がなければ、すべての有効なペアは 2 回カウントされます。 
5. クエリ自体が直角頂点である場合に取得された値で応答配列を初期化します。 これは、(90^\circ) 角がクエリ点にあるすべての三角形を説明します。 
6. 可能な直角頂点として 1 つの元の点 (P_i) を固定します。 すべての (j\ne i) について正規化された方向 (P_j-P_i) を含む周波数マップを構築します。 
7. すべてのクエリ (A_k) について、(A_k-P_i) を正規化し、((-y,x)) を使用して (90^\circ) だけ回転させ、その垂直方向を正規化し、マップ内で検索します。 保存された周波数は、(P_i,A_k,P_j) が (P_i) で直角になるような元の点 (P_j) の数と正確に一致します。 
8. その頻度をクエリの答え (A_k) に追加します。 すべての元の点 (P_i) に対して前の 2 つの手順を繰り返します。 

クエリが直角頂点ではない三角形には、直角頂点である元の点が 1 つだけあるため、各 (P_i) を個別に処理すると、そのような三角形はすべて 1 回だけカウントされます。 
9. すべてのクエリに対して蓄積された回答を出力します。 

### なぜ効果があるのか

 固定頂点 (O) の場合、2 つの非ゼロ ベクトル (u) と (v) は、それらの方向線が垂直である場合に正確に垂直になります。 方向の正規化ではベクトルで表される線が保存され、正規化された方向を (90^\circ) だけ回転すると、その垂直方向が正確に得られます。 

クエリが直角頂点の場合、頻度マップは、クエリからのベクトルが垂直である元の点のすべてのペアをカウントします。 順序なしの各ペアは合計に 2 回 (各方向クラスから 1 回ずつ) 出現するため、2 で割ると正確に三角形の数が得られます。 

原点 (P_i) が直角頂点の場合、ベクトル (A-P_i) はベクトル (P_j-P_i) がとるべき方向を決定します。 マップには、(P_i) からのすべての可能な原点方向の頻度が正確に含まれているため、ルックアップでは (P_j) の有効な選択肢が正確にカウントされます。 すべての三角形には直角の頂点が 1 つだけあるため、斜辺に関するクエリを持つ各三角形は 1 回カウントされます。 非縮退三角形には直角が 1 つしかないため、2 つのケースは素です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def normalize(dx, dy):
    g = gcd(abs(dx), abs(dy))
    dx //= g
    dy //= g

    if dx < 0 or (dx == 0 and dy < 0):
        dx = -dx
        dy = -dy

    return dx, dy

def solve(data=None):
    if data is None:
        read = input
        n, q = map(int, read().split())
        points = [tuple(map(int, read().split())) for _ in range(n)]
        queries = [tuple(map(int, read().split())) for _ in range(q)]
    else:
        it = iter(map(int, data.split()))
        n = next(it)
        q = next(it)
        points = [(next(it), next(it)) for _ in range(n)]
        queries = [(next(it), next(it)) for _ in range(q)]

    ans = [0] * q

    # Case 1: the query point itself is the right-angle vertex.
    for qi, (ax, ay) in enumerate(queries):
        freq = {}

        for px, py in points:
            d = normalize(px - ax, py - ay)
            freq[d] = freq.get(d, 0) + 1

        total = 0

        for (x, y), cnt in freq.items():
            px, py = normalize(-y, x)
            total += cnt * freq.get((px, py), 0)

        ans[qi] = total // 2

    # Case 2: an original point is the right-angle vertex.
    for ox, oy in points:
        freq = {}

        for px, py in points:
            dx = px - ox
            dy = py - oy

            if dx == 0 and dy == 0:
                continue

            d = normalize(dx, dy)
            freq[d] = freq.get(d, 0) + 1

        for qi, (ax, ay) in enumerate(queries):
            dx = ax - ox
            dy = ay - oy

            d = normalize(-dy, dx)
            ans[qi] += freq.get(d, 0)

    result = "\n".join(map(str, ans))

    if data is None:
        sys.stdout.write(result + "\n")
    else:
        return result + "\n"

if __name__ == "__main__":
    solve()
```の`normalize`関数は幾何学的なコアです。 gcd はベクトルの無関係な長さを削除しますが、符号規則は方向をその反対方向とマージします。 入力保証とは、に渡されるベクトルを意味します。`normalize`決してゼロではありません。 

最初の外側のループは、クエリが直角の頂点である場合を処理します。 その頻度マップには、クエリから元の点までの個別の方向線ごとに 1 つのエントリが含まれています。 回転方向を見上げると、すべての点が垂線上にあることがわかります。 

の`total // 2`方向 (d) が方向 (e) に​​垂直な場合、ループは (d) と (e) の両方を処理するため、この操作が必要になります。 したがって、同じポイント クラスのペアが 2 回含まれます。 

2 番目の外側のループは、各元の点を直角の頂点として固定します。 周波数マップには他の元の点のみが含まれるため、固定点自体が誤ってゼロ ベクトルを形成することはありません。 すべてのクエリについて、固定点からクエリまでのベクトルが (90^\circ) だけ回転され、正規化され、辞書キーとして使用されます。 

このコードでは Python の任意精度の整数を使用しているため、(2\times10^9) 付近の座標差を含む積は安全です。 浮動小数点の傾きや角度の計算は使用されないため、垂直線や非常に大きな座標の精度エラーが回避されます。 

## 実用的な例

 指定されたサンプルには 4 つのオリジナル ポイントと 2 つのクエリがあります。 

最初のクエリ ((0,0)) の場合、方向クラスは水平と垂直です。 それぞれに 2 つの点が含まれるため、直角としてのクエリの寄与は (2\cdot2=4) になります。 

2 番目のクエリ ((1,1)) の場合、関連する方向クラスには、1 つの点を含む水平線、1 つの点を含む垂直線、および 2 つの対角線が含まれます。 垂直ペアの数は合計で (3) になります。

2 番目のトレースについては、以下を考慮してください。```

 | 時間 | (O((nq+n^2)\log C)) 期待される | (nq) クエリ方向の正規化と (n^2) の原点方向の正規化。gcd は (O(\log C)) |

0 1
0 0
```2 つの水平ベクトルは同じ正準方向 ((1,0)) になり、垂直ベクトルは ((0,1)) になります。 周波数マップにはカウント (2) と (1) が含まれているため、直角としてのクエリの計算では (2\cdot1=2) が得られます。 出力は`2`。 垂直性はベクトルの向きではなく線に依存するため、反対のベクトルは意図的に結合されます。 

斜辺のクエリのケースは、第 2 フェーズで処理されます。 のために```
2 1
0 0
1 0
0 1
```((0,0)) を元の直角の頂点として固定すると、垂直なベクトル ((1,0)) と ((0,1)) が得られます。 クエリはこの固定頂点から 1 つの寄与を受け取るため、出力は次のようになります。`1`。 最初のフェーズはゼロを提供します。クエリ自体は直角の頂点ではないため、これはまさに私たちが望むものです。 

垂直線の場合は、他のすべての方向と同じ正規化を使用します。 のために```
4 1
0 0
0 1
0 2
0 3
1 1
```クエリにはベクトル ((-1,-1))、((-1,0))、((-1,1))、および ((-1,2)) があります。 ((-1,-1)) と ((-1,1)) のペアは垂直であり、クエリを直角の頂点とする 1 つの三角形が得られます。 元の点 ((0,1)) は、クエリ ベクトル ((1,0)) と直角の頂点でもあり、((0,0))、((0,2))、および ((0,3)) に向かう 3 つの垂直ベクトルに垂直です。 さらに 3 つ追加すると、正しい出力が得られます。`4`。 

境界座標の場合は、サイズの差 (2\times10^9) を使用します。 のために```
3 1
1000000000 1000000000
-1000000000 1000000000
1000000000 -1000000000
-1000000000 -1000000000
```クエリには ((1000000000,-1000000000)) への水平ベクトルと ((1000000000,1000000000)) への垂直ベクトルがあり、1 つの直角が生成されます。 Python の整数演算は対応する積を正確に表すため、出力は次のようになります。`1`。 

無効なすべてが同点の場合には、特別な分岐は必要ありません。 入力に同じ点が 2 回含まれている場合、問題の保証に違反し、方向の正規化が定義されていないゼロ ベクトルが作成される可能性があります。 すべてのクエリとすべての元の点はペアごとに異なるため、実装では、に渡されるすべてのベクトルを安全に想定できます。`normalize`ゼロ以外です。
