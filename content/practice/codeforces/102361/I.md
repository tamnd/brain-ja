 ## 解決策
 ## 問題の理解

 Invoker は最大 3 つの要素のシーケンスを維持します。 プレス中`Q`、`W`、 または`E`その要素をシーケンスに追加します。 すでに 3 つの要素がある場合は、最も古い要素が最初に消えます。 特殊スキルは、現在の 3 つの要素のマルチセットによってのみ決定されるため、順序は将来の更新では重要ですが、現在どの特殊スキルが使用可能かを決定する際には重要ではありません。 

入力文字列は、順番に呼び出す必要がある特別なスキルを記述します。 文字列のすべての文字の前に、呼び出し側には対応する 3 要素のマルチセットが必要です。`R`。 プレス中`R`1 つのスキルを必要とし、現在の要素の順序付けされたシーケンスは変更されません。 目的は、基本的なスキルのプレス回数と、`R`を押します。 

考えられる要素は 3 つだけで、インベントリには最大でもそのうち 3 つが含まれます。 これにより、完全な状態空間が小さくなります。 インベントリに 3 つの要素が含まれると、考えられる順序付けされた状態は (3^3=27) 個だけになります。 初期の空の状態には状態が 1 つ追加されます。 入力の長さは (10^5) に達する可能性があるため、可能な状態の数に応じた係数を使用するアルゴリズムは十分に高速ですが、可能なすべての履歴の検索は指数関数的であり、最大入力を処理できません。 

間違いの主な原因は、特殊スキルが順序を無視するのに、将来の代替スキルは順序を無視することです。 たとえば、構築した後、`X`、要素は次のとおりです`QWW`、そして構築後`V`含まれているだけで十分です`QQW`。 から始まる`QWW`、追加`Q`与える`WWQ`、それはまだです`X`; 別のものを追加する`Q`与える`WQQ`、つまり`V`。 したがって`XV`(4+2+1=7) のスキルが必要です。 操作のたびに在庫を分類するソリューションでは、時系列情報が失われ、必要な基本的なプレス機が少なくて済むと誤って主張する可能性があります。 

もう 1 つのエッジケースは、特別なスキルを繰り返すことです。 入力用`YY`、 最初`Y`ニーズ`QQQ`に続く`R`、一方、2番目の`Y`もう一つだけ必要です`R`、要素は呼び出し後に残るためです。 答えは`5`。 要求されたすべてのスキルを最初から再構築する不注意な実装では、`8`。 

初期状態も特殊です。 入力用`B`、最初には要素がないため、最初の呼び出しの前に 3 つの要素すべてを作成する必要があります。 答えは`4`。 初期状態を任意の完全な在庫として扱うと、コストが過小評価されてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、2 つの呼び出しの間で基本スキルのあらゆる可能なシーケンスを試すことができます。 すべての特殊スキルには 3 つの要素が必要なので、次のスキルを習得する前に 3 つ以上の基本スキルを押す必要はありません。`R`: 3 回の新しいプレスの後、古い在庫全体が廃棄され、任意の 3 要素マルチセットを構築できます。 ただし、履歴全体にわたる完全に枝刈りのない検索では、考えられるすべての基本スキル文字列が考慮されます。 (n) 個の要求されたスキルについて、各呼び出しの前に最大 3 回の基本的なプレスを許可する検索。 

[
 \sum_{k=0}^{3n}3^k=\frac{3^{3n+1}-1}{2}
 】

 最悪の場合、基本スキルのプレフィックスが追加される可能性があります。 (n=100000) の場合、これは天文学的に大きくなります。 

すべての法的シーケンスは基本的なプレスと呼び出しによって表現でき、それらのシーケンスを列挙すると最終的に最小値が見つかるため、強引な推論は正しいです。 その問題は、同じ現在の在庫と同じ将来の可能性を持つ歴史を繰り返し探索することです。 

重要な観察は、現在の注文済み在庫がわかれば、過去は破棄できるということです。 完全に注文された在庫は 27 個だけです。 このような状態のペアごとに、一方を他方に変換するために必要な基本的なプレスの最小数を計算できます。 基本的な各プレスは、小さな有向グラフのエッジにすぎません。`Q`、`W`、 または`E`、必要に応じて最も古い要素を削除します。 

これにより、問題は 27 州のみにわたる動的計画法に変わります。 リクエストされたすべての特別なスキルについて、その 3 つの要素の順序付けられた順列をすべて列挙します。 そのような状態は最大で 6 つあります。 前回注文した在庫が`state`これらの順列の 1 つは`target`、移行コストは、事前に計算された基本プレスの最小数です。`state`に`target`、プラス 1 の`R`。 

距離テーブルは、すべての状態から BFS を使用して計算できます。 空の状態を含めると、グラフには 28 個の状態しかなく、すべての状態に 3 つの出力エッジがあります。 前処理は事実上一定時間です。 メイン ループは各文字に対して最大 (27\times) の遷移を実行し、入力長に線形の複雑さを与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(3^{3n})) | (O(n)) 検索パスの場合 | 遅すぎる |
 | 最適 | (O(n)) と小さな定数 | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 注文されたすべての在庫を 0 ～ 3 文字のタプルとして表します。 空のタプルは初期状態を表します。 完全な在庫の場合は、`(Q, W, E)`そして`(E, W, Q)`次の基本スキルに対する反応が異なるため、状態が異なります。 
2. 空の状態から開始し、それぞれの状態を繰り返し追加することで、到達可能なすべての状態を生成します。`Q`、`W`、 そして`E`。 4 番目の要素が追加される場合は、最新の 3 つの要素のみを保持します。 状態は合計で 28 しかないため、これは小規模な BFS で実行できます。 
3. すべての状態間の最短距離テーブルを作成します。 各州から、1 つの BFS が考えられる 3 つの基本スキルを調査します。 結果として得られる距離から、他の状態に到達するために必要な基本的なプレスの最小回数がわかります。 
4. 各特殊スキル キャラクターを必要なマルチセットにマッピングします。 例えば、`X`に対応する`QWW`、`B`に対応する`QWE`、 そして`T`に対応する`EEE`。 
5. 特殊スキルごとに、その 3 つの必須要素のすべての個別の順列を生成します。 順序は特別なスキルの一部ではないため、すべての順列が有効な最終在庫となります。 最大で 6 つの状態が生成されます。 
6. メンテナンス`dp[state]`、処理されたすべての特殊スキルを呼び出し、正確に注文された在庫で終了した後にすでに使用されているスキルの最小数`state`。 最初は、コスト 0 で到達できるのは空の状態のみです。 
7. 次に要求される特別なスキルについては、その特別なスキルに対して現在到達可能なすべての状態と、すべての有効な順序付けされたターゲット状態を考慮します。 事前に計算された最短距離を使用してそれらの間を移動し、押すための距離を追加します。`R`。 各ターゲット状態の最小値を維持します。 
8. 古い D​​P 配列を新しいものに置き換えて、次の文字を処理します。 最後の呼び出しは、要求されたマルチセットの任意の順序で終了する可能性があるため、最後の文字の後の答えは、すべての完全な状態にわたる最小 DP 値になります。 

### なぜ効果があるのか

 不変条件とは、`dp[state]`は、入力の処理済みプレフィックスを完了し、`state`最後の呼び出し直後の現在の注文済み在庫として。 次の特別なスキルの場合、すべての法的戦略はまず現在の状態から、マルチセットが要求されたスキルを表す順序付けされた在庫に移動する必要があります。 BFS 距離により、その動作に対する基本的な押下回数が最小限に抑えられ、必要な呼び出しにより操作が 1 つだけ追加されます。 すべての有効なターゲットの順序が考慮されるため、移行には次のスキルを呼び出すためのあらゆる可能な合法的な方法が含まれます。 したがって、以前のすべての状態で最小値を取ると、不変条件が維持されます。 入力文字列に対する帰納法により、最終的な最小値が全体的に最適な答えになります。 

## Python ソリューション```python
import sys
from collections import deque
from itertools import permutations

input = sys.stdin.readline

ELEMENTS = "QWE"

SPECIAL = {
    "Y": "QQQ",
    "V": "QQW",
    "G": "QQE",
    "C": "WWW",
    "X": "QWW",
    "Z": "WWE",
    "T": "EEE",
    "F": "QEE",
    "D": "WEE",
    "B": "QWE",
}

def build_states():
    states = [()]
    index = {(): 0}
    q = deque([()])

    while q:
        state = q.popleft()

        for ch in ELEMENTS:
            nxt = state + (ch,)
            if len(nxt) > 3:
                nxt = nxt[-3:]

            if nxt not in index:
                index[nxt] = len(states)
                states.append(nxt)
                q.append(nxt)

    return states, index

def build_dist(states, index):
    m = len(states)
    dist = [[10**9] * m for _ in range(m)]

    for start in range(m):
        dist[start][start] = 0
        q = deque([start])

        while q:
            u = q.popleft()
            state = states[u]

            for ch in ELEMENTS:
                nxt = state + (ch,)
                if len(nxt) > 3:
                    nxt = nxt[-3:]

                v = index[nxt]
                if dist[start][v] == 10**9:
                    dist[start][v] = dist[start][u] + 1
                    q.append(v)

    return dist

def solve_string(s):
    states, index = build_states()
    dist = build_dist(states, index)

    m = len(states)
    inf = 10**9

    dp = [inf] * m
    dp[index[()]] = 0

    targets = {}

    for skill, elements in SPECIAL.items():
        target_states = set()

        for p in permutations(elements):
            target_states.add(index[p])

        targets[skill] = tuple(target_states)

    for skill in s:
        ndp = [inf] * m

        for u in range(m):
            if dp[u] == inf:
                continue

            for v in targets[skill]:
                cost = dp[u] + dist[u][v] + 1
                if cost < ndp[v]:
                    ndp[v] = cost

        dp = ndp

    return str(min(dp))

def main():
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```の`SPECIAL`辞書には、各特殊スキルに必要な 3 つの要素の代表的な順序が 1 つ格納されます。 辞書値は後でマルチセットとして扱われるため、その特定の順序には意味的な意味はありません。`build_states`基本的なスキルを通じて到達可能なすべての状態を構築します。 タプル表現はハッシュ可能であり、時系列順序を保持するため便利です。 タプルが 3 つの要素を超えて大きくなると、`nxt[-3:]`FIFO 置換ルールを正確に実装します。`build_dist`すべての状態から BFS を実行します。 1 つの基本的なスキル プレスが 1 回の操作でインベントリを変更するため、すべてのエッジのコストは 1 です。 したがって、BFS は正しい最短パス アルゴリズムです。 空の状態は自動的に組み込まれ、別の特殊なケースを必要とせずに最初に要求された特殊スキルを処理します。 

それぞれの特技ごとに、`permutations`可能なすべての注文を生成します。 あ`set`などのスキルの重複を削除します。`Y`、ここで 3 つの順列はすべて同一です。 これは微妙ではありますが、便利な実装の詳細です。`QQQ`同じ遷移を繰り返し処理するのではなく、ターゲット状態を 1 つだけ生成する必要があります。 

DPアップデートで追加されるのは、`dist[u][v]`必要な基本スキルに対して 1 つだけ追加します。`R`。 この呼び出しではインベントリは変更されないため、`v`遷移後の状態が維持されます。 古い DP 配列は、現在のキャラクターのすべてのトランジションが評価された後にのみ置き換えられ、要求された 1 つのスキルが 1 回の反復中に複数回呼び出されるのを防ぎます。 

すべてのコストは最大入力に対して最大でも数十万であるため、Python 整数にはオーバーフローの心配はありません。 距離テーブルは、初期化の場合にのみ大きなセンチネル値を使用しますが、インベントリがいっぱいになると、最大 3 回の基本的なプレス以内で、他のすべての状態からすべての状態に到達できます。 

## 実用的な例

 提供されたサンプルは、`XDTBVV`。 以下の表は、要求された各スキル後の現在の最良の DP 状態を示しています。 いくつかの状態は同じコストを持つことができますが、ここでは最終的な継続に関連する最小コストの状態のみが 1 つの最適なパスとして示されています。 

| 要求されたスキル | 基本的なプレスを追加 | 注文後の在庫`R`| 総費用 |
 | --- | --- | --- | --- |
 |`X`|`QWW`|`QWW`| 4 |
 |`D`|`EE`|`WEE`| 7 |
 |`T`|`E`|`EEE`| 9 |
 |`B`|`WQ`|`EWQ`| 12 |
 |`V`|`Q`|`WQQ`| 14 |
 |`V`| なし |`WQQ`| 15 |

 操作の順序は次のとおりです。`QWWREERERWQRQRR`。 4 番目の移行における重要なポイントは、ターゲットが`B`マルチセットのみが必要です`QWE`。 から始まる`EEE`、追加`W`与える`EEW`、その後追加します`Q`与える`EWQ`、そのマルチセットは正確に`QWE`。 決勝戦`V`費用は1つだけです`R`前回の呼び出し後のインベントリはすでに存在しているため、`WQQ`を表します`QQW`。 

2 番目の例として、構築された入力を考えてみましょう。`XV`。 

| 要求されたスキル | 基本的なプレスを追加 | 注文後の在庫`R`| 総費用 |
 | --- | --- | --- | --- |
 |`X`|`QWW`|`QWW`| 4 |
 |`V`|`QQ`|`WQQ`| 7 |

 作成後`QWW`、追加で1つ`Q`生成する`WWQ`、今でも表しています`X`。 2番目`Q`生成する`WQQ`を表します`V`。 したがって、2 つの呼び出しの間に 2 つの基本的なプレスが必要となり、(4+2+1=7) となります。 この例は、順序付けされた状態を現在の順序付けされていないマルチセットのみで置き換えることができない理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | 状態グラフには 28 個の状態しかなく、すべての入力文字は最大 28 個の前の状態と 6 個のターゲット順列をチェックします。 |
 | スペース | (O(1)) | 距離テーブルと DP 配列のサイズは (n) に関係なく一定です。 |

## テストケース```python
import sys
import io
from collections import deque
from itertools import permutations

ELEMENTS = "QWE"

SPECIAL = {
    "Y": "QQQ",
    "V": "QQW",
    "G": "QQE",
    "C": "WWW",
    "X": "QWW",
    "Z": "WWE",
    "T": "EEE",
    "F": "QEE",
    "D": "WEE",
    "B": "QWE",
}

def make_solver():
    states = [()]
    index = {(): 0}
    q = deque([()])

    while q:
        state = q.popleft()

        for ch in ELEMENTS:
            nxt = state + (ch,)
            if len(nxt) > 3:
                nxt = nxt[-3:]

            if nxt not in index:
                index[nxt] = len(states)
                states.append(nxt)
                q.append(nxt)

    m = len(states)
    dist = [[10**9] * m for _ in range(m)]

    for start in range(m):
        dist[start][start] = 0
        q = deque([start])

        while q:
            u = q.popleft()

            for ch in ELEMENTS:
                nxt = states[u] + (ch,)
                if len(nxt) > 3:
                    nxt = nxt[-3:]

                v = index[nxt]

                if dist[start][v] == 10**9:
                    dist[start][v] = dist[start][u] + 1
                    q.append(v)

    targets = {}

    for skill, elements in SPECIAL.items():
        targets[skill] = tuple(
            index[p] for p in set(permutations(elements))
        )

    def run(inp: str) -> str:
        s = inp.strip()

        inf = 10**9
        dp = [inf] * m
        dp[index[()]] = 0

        for skill in s:
            ndp = [inf] * m

            for u in range(m):
                if dp[u] == inf:
                    continue

                for v in targets[skill]:
                    ndp[v] = min(
                        ndp[v],
                        dp[u] + dist[u][v] + 1
                    )

            dp = ndp

        return str(min(dp))

    return run

run = make_solver()

# Provided sample
assert run("XDTBVV") == "15", "sample 1"

# Constructed second sample
assert run("XV") == "7", "two different skills requiring ordered-state tracking"

# Minimum-size input
assert run("B") == "4", "one special skill starts from an empty inventory"

# Repeated skill
assert run("YY") == "5", "the inventory survives R"

# All-equal values
assert run("TTTTT") == "8", "EEE is already present after the first invocation"

# Maximum-size input
assert run("Y" * 100000) == str(100003), "maximum input length"

# Boundary transition where one additional element is not enough
assert run("XY") == "8", "changing QWW into QQQ requires three Q presses"

 ## 特殊なケース

 入力用`B`、アルゴリズムは空の状態から始まります。 すべての完全なターゲット状態を表す`QWE`最初のインベントリを作成するには 3 つの基本的なスキルが必要であるため、空の状態から 3 BFS エッジまで離れています。 次に、DP は次の 1 つを追加します。`R`、生産`4`。 最初は人為的な完全状態は想定されていません。

入力用`XY`、その後の在庫`X`できる`QWW`。 追加中`Q`二度与えます`WWQ`その後`WQQ`、どちらにも 3 つは含まれていません`Q`は。 3番目に追加されたもの`Q`最も古いものを削除します`W`そして葉を残します`QQQ`。 したがって、遷移距離は 3 であるため、合計は次のようになります。`4+3+1=8`。 これにより、FIFO 順序をシミュレートせずに、一致する要素タイプの数のみを比較する実装が捕捉されます。 

(100000) 個のコピーで構成される最大サイズの入力の場合`Y`、最初の呼び出しには 4 つの操作が必要です。 それ以降の呼び出しのコストは 1 回だけです`R`、 なぜなら`QQQ`は変わらないままです。 結果は (4+99999=100003) となります。 DP は各文字を独立して処理し、履歴の長さとともに増大することがないため、大量の入力は線形のままです。
