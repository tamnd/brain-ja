 ## 解決策
 ## 問題の理解

 小数点以下の数字のみが重要です。 その小数部分を長さ (n) とします。 繰り返し部分の候補は、観察された小数桁の接尾語でなければなりません。なぜなら、繰り返しは、Sumika が測定したものの最後まで継続していなければならないからです。 

候補サフィックスが、繰り返しブロックの不完全な最終コピーを含む合計 (p) 桁表示され、その最も短い有効な繰り返しブロックの長さが (l) であると仮定します。 その信頼性は、

 [
 a p-b l。 
】

 固定 (p) の場合、最初の項 (ap) はすでに決定されています。 (b>0) のため、その位置で終了する最良の候補は常に可能な限り最小の周期 (l) を持つものになります。 したがって、問題は、すべての接尾辞の長さ (p) について、その接尾辞の最短期間を見つけることです。 

小数部には最大 (10^7) 桁を含めることができます。 接尾語の長さとピリオドの長さのすべてのペアを検査するアルゴリズムは、この規模ではすでに大きすぎます。 (O(n^2)) 個の作業でも、最大サイズで約 (10^{14}) 回の反復を意味しますが、(O(n^3)) 個の文字比較の実装ではおおよそのサイズに達します。 

[
 \sum_{p=1}^{n}\frac{p(p-1)}2
 =\frac{n(n+1)(n-1)}6
 】

 文字比較、(n=10^7) の場合、約 (1.67\times10^{20})。 線形時間文字列アルゴリズムが必要であり、線形メモリのみも必要です。 

一見正しい実装が失敗する可能性がある境界ケースがいくつかあります。 答えは否定的なものになる可能性があります。 たとえば、```
1 2
0.5
```可能な繰り返し部分は (p=1,l=1) のみであるため、答えは (-1) になります。 答えをゼロに初期化すると、誤ってゼロが生成されます。 

整数部分は完全に無視する必要があります。 例えば、```
5 3
123.1020
```のサンプルとまったく同じ答えがあります`1.1020`、つまり`9`。 文字列全体を処理する実装では、間違ったピリオドが構築されてしまいます。 

最後の繰り返しは不完全であってもかまいません。 のために```
2 1
0.102
```逆向きの小数文字列は`201`。 長さ 3 のプレフィックスの周期は最も短い 2 であるため、(p=3,l=2)、(6-2=4) となります。 観察された長さを分割する期間に候補を制限すると、この種の候補が見逃されます。 

長さ 1 の小数部分も有効です。 のために```
7 10
42.8
```(p=l=1) しかないので、答えは (-3) になります。 これにより、1 文字の境界と否定的な回答の両方が検出されます。 

## アプローチ

 直接的な解決策では、考えられるすべての接尾辞の長さ (p) を列挙します。 各接尾辞について、考えられるすべての繰り返しの長さ (l) を試し、距離 (l) にある文字が接尾辞全体で一致するかどうかをチェックします。 チェックが成功した場合、候補には信頼性 (ap-bl) があり、(b) が肯定的であるため、そのサフィックスの最小有効値 (l) を維持できます。 

これは正しいです。なぜなら、すべての法的な繰り返し部分は何らかの接尾辞のピリオドであり、すべての可能な (l) をチェックすることですべての法的な選択が検査されるからです。 問題は、繰り返される文字列比較の量です。 長さ (p) の接尾辞の場合、すべての候補の長さをテストするには (\Theta(p^2)) 個の文字比較が必要となり、最悪の場合、全体で (\Theta(n^3)) が得られます。 たとえ部分文字列の比較が各チェックを一定時間にするのに十分最適化されたとしても、すべてのペア ((p,l)) を単純に検査すると依然として (O(n^2)) となり、これは (10^7) 文字には大きすぎます。 

有益な観察は、すべての候補が元の小数文字列の接尾辞であるということです。 小数文字列を反転します。 元の文字列の長さ (p) の接尾辞は、反転された文字列では長さ (p) の接頭辞になります。 したがって、問題をすべてのプレフィックスの最短期間を見つけることに変換しました。 

これは、まさに KMP プレフィックス機能によって提供される情報です。 長さ (p) のプレフィックスの場合、そのプレフィックス関数の値を (k)、つまりサフィックスでもある最長の適切なプレフィックスの長さとします。 長さ (k) の境界線は、最初 (k) 文字と最後の (k) 文字が一致することを意味します。 これら 2 つの等しい領域間の距離は (p-k) であり、その距離はプレフィックスの周期です。 (k) は可能な限り長い境界であるため、(p-k) は可能な限り短い期間です。 

したがって、反転した小数文字列が (t) で、そのプレフィックス関数が (\pi) である場合、すべてのプレフィックス長 (p) に対して、

 [
 l=p-\pi[p-1]。 
】

 出現する長さは単純に (p) であるため、その最高の信頼性は

 [
 p-b(p-\pi[p-1])。 
】

 KMP プレフィックス関数を構築する際に、すべてのプレフィックスについてこれを計算します。 

ブルートフォース手法は、可能なすべてのピリオドを明示的にテストするため機能しますが、密接に関連する接尾辞について同じ文字が繰り返し比較されるため失敗します。 逆変換すると、関連するすべてのサフィックスがプレフィックスに変換され、KMP は連続するプレフィックス間の境界情報を再利用して、問題全体を線形時間に短縮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) 直接周期チェックあり | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (a)、(b)、および 10 進数の文字列を読み取り、小数点以下をすべて切り捨てます。 整数部分は信頼性の計算では何の役割も持たないため、整数部分を保持するとメモリを浪費し、文字列処理が複雑になるだけです。 
2. 小数部の桁を反転します。 繰り返し部分の候補は、元の観察文字列の末尾に到達する必要があるため、すべての候補が接尾辞に対応します。 反転後、そのサフィックスはプレフィックスになります。これは、まさに prefix 関数によって処理される形式です。 
3. KMP プレフィックス関数配列を反転した小数文字列に割り当てます。 位置 (i) については、(\pi[i]) を最も長い適切なプレフィックスとします。`t[:i+1]`それはその接尾語でもあります。 
4. 標準の KMP フォールバック ルールを使用してプレフィックス関数を構築します。 次の文字が現在の境界線と一致しない場合は、境界線の長さ (j) を (\pi[j-1]) に繰り返し置き換えます。 これらのフォールバックは、比較が失敗することがすでにわかっている文字のグループ全体をスキップします。 
5. 位置 (i) で終わるすべてのプレフィックスについて、(p=i+1) を設定します。 最長の境界線の長さは (\pi[i]) であるため、その最短期間は次のようになります。 

[
 l=p-\pi[i]。 
】

 これにより有効な繰り返し部分が最短になる理由は、境界と期間の関係にあります。 長さ (k) の境界線により、文字列が (p-k) 個の位置の後に繰り返され、最も長い境界線によってそのような距離が最小になります。 

1. コンピューティング

 [
 p-b l
 】

 このプレフィックスの最大値を更新します。 (p) は 1 から分数の長さ全体まで増加するため、出現する可能性のある長さはすべて 1 回だけ考慮されます。 

1. 最大値を出力します。 すべての信頼性値が負になる可能性があるため、答えはゼロではなく最初の候補 (a-b) を使用して初期化する必要があります。 

### なぜ効果があるのか

 元の小数文字列内の正当な繰り返し部分を考慮してください。 最後まで繰り返されるため、その出現に関係するすべての数字が小数文字列の接尾辞を形成します。 その接尾辞に (p) 桁を含めます。 小数部文字列を反転すると、同じ文字が長さ (p) のプレフィックスを形成します。 

このプレフィックスの場合、有効な繰り返しブロックの長さはすべてプレフィックスのピリオドになります。 最長の境界線の長さが (k) の場合、(p-k) はピリオドになります。 境界線は (k) より長くすることはできないため、周期は (p-k) より短くすることはできません。 したがって、KMP 値は、この固定 (p) に対して可能な最小の (l) を正確に与えます。 

固定 (p) の場合、信頼性は (ap-bl) であり、(b) は正です。 (l) が小さいほど、常に大きな信頼性が得られます。 したがって、(l=p-\pi[p-1]) だけを考慮しても最適な候補を失うことはありません。 考えられるすべての (p) が検査されるため、アルゴリズムによって見つかった最大値は、すべての正当な繰り返し部分に対する最大の信頼性になります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    s = input().strip()

    # Only the fractional part matters.
    frac = s.split('.', 1)[1]
    n = len(frac)

    # A signed 32-bit integer is enough for every prefix-function value.
    # Using array instead of a Python list keeps memory close to O(n) bytes
    # rather than O(n) Python objects.
    pi = array('i', [0]) * n

    if n == 0:
        print(a - b)
        return

    # Prefix of length 1: p = 1, l = 1.
    ans = a - b

    # We need suffixes of frac, so process the reversed string.
    t = frac[::-1]

    j = 0
    for i in range(1, n):
        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]

        if t[i] == t[j]:
            j += 1

        pi[i] = j

        p = i + 1
        l = p - j
        value = a * p - b * l

        if value > ans:
            ans = value

    print(ans)

if __name__ == "__main__":
    solve()
```最初の入力行には (a) と (b) が入力され、2 行目には完全な観測された 10 進数が含まれています。`split('.', 1)[1]`小数部分を正確に抽出するため、小数点より前の数字が KMP に含まれることはありません。 

反転した文字列`t`関連する候補が元の小数桁の接尾辞であるため、 が作成されます。 インデックスのプレフィックス関数値`i`長さの接頭語を記述します`i+1`、これは元の向きで正確にその長さの接尾辞に対応します。 

の`pi`配列は 4 バイトの符号付き整数を使用します。 すべての接頭辞関数の値は最大でも (n)、および (n\le10^7) であるため、32 ビットの符号付き整数で十分です。 Python では、この選択は重要です。1,000 万個の Python 整数の通常のリストは数百メガバイトを消費する可能性があるのに対し、型付き配列は同じ値をコンパクトに格納するためです。 

KMP ループは次から始まります。`i = 1`最初の文字は常に接頭辞関数値 0 を持つためです。 変数`j`現在の境界線の長さです。 ミスマッチに関しては、`j = pi[j - 1]`比較を最初からやり直すのではなく、次の小さい境界にジャンプします。 

計算後`pi[i]`、プレフィックスの長さは`p = i + 1`。 一番短い期間は、`p - pi[i]`, そのため、信頼性はこれら 2 つの値から直接計算されます。 (a p-b l) が負になる可能性があるため、減算の順序が重要になります。 

Python の整数には任意の精度があるため、実装ではオーバーフローの心配はありません。 ただし、C++ ソリューションでは、積はおよそ (10^{16}) に達する可能性があるため、`long long`が必要です。 

KMP フォールバック ループはメイン ループ内にネストされているように見えますが、その合計作業量は線形のままです。 キャラクターマッチが成功するたびに増加します`j`、すべてのフォールバックは厳密に減少しますが、`j`。 計算全体にわたって、フォールバック操作の数は増加数によって制限され、合計作業量は (O(n)) になります。 

## 実用的な例

 ### サンプル 1

 小数部は`1020`。 それを反転すると、`0201`。 

| プレフィックス長 (p) | プレフィックス | (\pi[p-1]) | ピリオド (l=p-\pi[p-1]) | 信頼性 (5p-3l) | これまでで最高 |
 | --- | --- | --- | --- | --- | --- |
 | 1 |`0`| 0 | 1 | 2 | 2 |
 | 2 |`02`| 0 | 2 | 4 | 4 |
 | 3 |`020`| 1 | 2 | 9 | 9 |
 | 4 |`0201`| 0 | 4 | 8 | 9 |

 プレフィックス長が 3 の場合、`020`境界線がある`0`長さは1です。 プレフィックス長からその境界を取り除くと、ピリオド (3-1=2) が得られます。 逆に戻すと元の接尾辞に対応します`020`、その繰り返しブロックは`02`, 3桁表示されます。 その信頼性は (5\cdot3-3\cdot2=9) であり、これが最適です。 

重要な点は、最適な候補は必ずしも完全な繰り返し回数ではないということです。 接頭語`020`で構成されています`02`続いて最初の文字`0`別のコピーの。 その部分的な最終コピーは許可されます。 

### サンプル 2

 小数部は`1212`、つまり、反転した文字列は次のようになります。`2121`。 

| プレフィックス長 (p) | プレフィックス | (\pi[p-1]) | ピリオド (l=p-\pi[p-1]) | 信頼性 (2p-l) | これまでで最高 |
 | --- | --- | --- | --- | --- | --- |
 | 1 |`2`| 0 | 1 | 1 | 1 |
 | 2 |`21`| 0 | 2 | 2 | 2 |
 | 3 |`212`| 1 | 2 | 4 | 4 |
 | 4 |`2121`| 2 | 2 | 6 | 6 |

 完全なプレフィックスの場合`2121`、最長の境界線は`21`、長さは 2 です。 したがって、最も短い期間は (4-2=2) です。 元の方向では、これは繰り返し部分に相当します`12`、これは観測された 4 桁すべてに表示されます。 その信頼性は (2\cdot4-1\cdot2=6) です。 

このトレースは、部分的な繰り返しのないプレフィックスのみをチェックするだけでは不十分である理由も示しています。 長さ 3 の接頭辞には、3 が 2 で割り切れない場合でも、ピリオド 2 が付きます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | すべてのプレフィックスの抽出、逆変換、KMP の構築、評価はそれぞれ線形です。 
| スペース | (O(n)) | 小数文字列とプレフィックス関数配列はどちらも線形サイズ | を持ちます。 

ここで (n) は小数点以下の桁数で、(n\le10^7) となります。 線形処理は入力サイズに必要なスケールです。 また、型付きプレフィックス関数配列は、何百万もの個別の Python 整数オブジェクトを格納するのではなく、入力に比例したメモリを維持します。 

## テストケース```python
import sys
import io
from array import array

def solve_text(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        a, b = map(int, sys.stdin.readline().split())
        s = sys.stdin.readline().strip()

        frac = s.split('.', 1)[1]
        n = len(frac)

        if n == 0:
            return str(a - b)

        t = frac[::-1]
        pi = array('i', [0]) * n

        ans = a - b
        j = 0

        for i in range(1, n):
            while j > 0 and t[i] != t[j]:
                j = pi[j - 1]

            if t[i] == t[j]:
                j += 1

            pi[i] = j

            p = i + 1
            l = p - j
            value = a * p - b * l

            if value > ans:
                ans = value

        return str(ans)
    finally:
        sys.stdin = old_stdin

def run(inp: str) -> str:
    return solve_text(inp)

# Provided samples
assert run("5 3\n1.1020\n") == "9", "sample 1"
assert run("2 1\n12.1212\n") == "6", "sample 2"

# Minimum-size fractional part
assert run("7 10\n42.8\n") == "-3", "single fractional digit"

# Negative answer
assert run("1 2\n0.5\n") == "-1", "answer may be negative"

# All equal digits
assert run("2 1\n0.1111\n") == "7", "shortest period remains 1"

# Partial final repetition and off-by-one boundary
assert run("2 1\n0.121\n") == "4", "partial final repetition"

# Integer part must be ignored
assert run("5 3\n987654321.1020\n") == "9", "integer part is irrelevant"

# Maximum-size stress case.
# Ten million equal fractional digits have period 1 for every prefix.
# The final prefix gives p = 10,000,000 and l = 1.
n = 10_000_000
maximum_case = "1 1\n0." + ("7" * n) + "\n"
assert run(maximum_case) == "9999999", "maximum-size input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`7 10 / 42.8`|`-3`| 小数部の最小の長さと負の結果 |
 |`1 2 / 0.5`|`-1`| 答えが誤ってゼロに初期化されるのを防ぎます。 
|`2 1 / 0.1111`|`7`| すべて等しい数字と 1 のピリオド |
 |`2 1 / 0.121`|`4`| 部分的な最後の繰り返しと接頭辞関数の境界 |
 |`5 3 / 987654321.1020`|`9`| 整数部分が無視されることを確認します。 
|`1 1 / 0.`続いて (10^7) 個のコピー`7`|`9999999`| 最大入力サイズとリニアメモリ処理 |

 最大サイズのテストでは、予期される答えを導き出しやすく保ちながら、プレフィックス関数の構造全体に重点を置くため、意図的に等しい桁を使用します。 (n=10^7) の場合、すべてのプレフィックスは最短期間 1 を持つため、最終候補は (p=10^7)、(l=1)、および信頼性 (10^7-1=9,999,999) を持ちます。 

## 特殊なケース

 否定的な答えについては、次のように考えてください。```
1 2
0.5
```小数部分の文字列の長さは 1 なので、反転した文字列も次のようになります。`5`。 そのプレフィックス関数の値はゼロであり、(p=1) および (l=1) になります。 唯一の信頼性は (1\cdot1-2\cdot1=-1) です。 アルゴリズムは次から始まります`ans = a - b`したがって、この負の結果を誤ってゼロに置き換えるのではなく、保存します。 

小数部 1 桁については、次のように考えます。```
7 10
42.8
```アルゴリズムが抽出する`8`、それを反転すると、`8`、最初のプレフィックスを超える KMP 反復はありません。 期間は1、信頼度は(7-10=-3)です。 ここには特別な文字列パターンのケースは隠されていないため、通常の初期化で最小の有効な入力がすでに処理されています。 

不完全な最終繰り返しについては、次のことを考慮してください。```
2 1
0.121
```小数点以下の文字列は、`121`、そして逆にすると、`121`。 プレフィックス関数の値は (0,0,1) です。 (p=3) では、最長の境界線の長さは 1 なので、(l=3-1=2) になります。 候補は元の接尾辞です`121`、ピリオドとして解釈されます`12`その後に最初の数字が続く`1`。 その信頼性は (2\cdot3-1\cdot2=4) です。 (p) が (l) の倍数であることを必要とする解法では、この候補が誤って破棄されてしまいます。 

整数部分の境界については、次を考慮してください。```
5 3
987654321.1020
```小数点以下はアルゴリズムによって正確に認識されます。`1020`、同じ反転文字列を生成します`0201`最初のサンプルと同じ 4 つの候補。 最大値が残る`9`。 これは、整数部分が (p)、(l)、または信頼性に影響を与えないことを確認します。 

数字が繰り返される場合は、次の点を考慮してください。```
2 1
0.1111
```反転した文字列はそのままです`1111`。 そのプレフィックス関数の値は (0,1,2,3) であるため、完全なプレフィックス (p=4) の場合、最短期間は (4-3=1) になります。 信頼性は (2\cdot4-1=7) で、すべての短いプレフィックスを上回ります。 このケースでは、KMP 境界の長いチェーンを実行し、フォールバック構造が二次作業に退化することなく最大限の繰り返しを処理することを確認します。
