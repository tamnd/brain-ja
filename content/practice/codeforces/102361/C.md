 ## 問題の理解

 浅井ケイは空ではない部分列を選択します`a`, 一方、ディレクターは空ではないサブシーケンスを選択します。`b`。 次のような選択されたシーケンス`(2, 1, 2)`は 1000 進数として解釈されるため、その値は次のようになります。`2 * 1000^2 + 1 * 1000 + 2`。 

すべての要素は最大でも`100`、ベースより厳密に小さい`1000`。 これにより、最初に長さを比較するという重要な比較ルールが得られます。 空ではない長いシーケンスは、すべての短いシーケンスよりも大きな値を持ちます。 長さが等しい場合は、辞書編集的な比較とまったく同じように、要素を左から右に比較します。 

「異なるサブシーケンス」という表現も重要です。 ステートメントは影響値によってシーケンスを識別するため、同じシーケンスを生成する 2 つのインデックス選択は 1 回だけカウントする必要があります。 たとえば、`a = [1, 1]`、長さ 1 のサブシーケンスを選択するには 2 つの方法がありますが、どちらも同じシーケンスを生成します。`(1)`したがって、長さ 1 の異なる部分列は 1 つだけ存在します。 

制約により許可されるのは、`n,m`到達する`5000`。 二次アルゴリズムは現実的ですが、どちらの長さでも指数関数的なものは不可能です。 公式ジャッジの制限は 1024 MB のメモリで 2.5 秒であり、受け入れられた意図された解決策は 2 次です。 

不注意な実装を簡単に破ってしまういくつかのエッジケースがあります。 と`a = [1]`そして`b = [1]`、答えは`0`2 つのシーケンスだけが等しい値を持つためです。 を使用した解決策`>=`の代わりに`>`このペアを誤ってカウントしてしまいます。 

と`a = [1,1]`そして`b = [1]`、答えは`1`。 の異なるサブシーケンス`a`は`(1)`そして`(1,1)`、 その間`b`だけを持っています`(1)`。 長いシーケンスだけが勝ちます。 個別のシーケンスではなくインデックス選択をカウントすると、`(1)`で`a`個別の選択肢として。 

と`a = [2,1]`そして`b = [1,2]`、答えは`6`。 長さ 2 のシーケンスは次のとおりです。`21`そして`12`、 それで`21 > 12`; 一方、長さ 2 のシーケンスは両方とも、長さ 1 のシーケンスの両方に勝ちます。`b`。 長さのみを比較するソリューションでは、等しい長さの寄与が失われます。 

最後に、次のような値を繰り返します。`a = [1,1,1]`すべての長さで重複を削除する必要があります。 各長さの異なるサブシーケンスは 1 つだけあります。`3`、`3`、 そして`1`インデックスの選択。 これが、不等長部分に通常の二項係数を使用できない理由です。 

## アプローチ

 直接的なアプローチは、空でないすべてのサブシーケンスを列挙することです。`a`、空でないすべてのサブシーケンスを列挙します。`b`、影響値を計算し、すべてのペアを比較します。 がある`2^n - 1`そして`2^m - 1`インデックスのサブシーケンスなので、比較の数は次のようになります。`(2^n - 1)(2^m - 1)`。 

で`n = m = 5000`、これはおよそ`2^10000`比較。 重複するサブシーケンスを処理する前でさえ、これは完全に実行不可能です。 

考えられるすべてのペアが明示的に考慮されるため、総当り攻撃は正しいです。 その失敗は純粋に組み合わせによるものです。 便利な構造は、影響度の値が 1000 進数で表現され、その桁がすべて進数以下であることです。 これにより、数値比較が長さの比較に変わり、その後に辞書編集的な比較が行われます。 

したがって、答えを 2 つの独立した部分に分割できます。 からのサブシーケンスの場合、`a`からのものよりも長いです`b`、自動的に勝ちます。 各配列内のあらゆる長さの個別のサブシーケンスの数だけが必要です。 

難しいのは、2 つの長さが等しい場合です。 次に、シーケンスが異なる最初の位置によって結果が決まります。 その位置より前の 2 つのシーケンスは同一である必要があり、最初の異なる位置では次から選択された値になります。`a`もっと大きくなければなりません。 

標準の個別サブシーケンスの繰り返しでは、最初の部分が処理されます。 ポジションについて`i`、 させて`p[i]`以前に発生したことである`a[i]`。 もし`F[i][k]`長さの異なる部分列の数です`k`で終わるプレフィックスを使用する`i`、 それから`F[i][k] = F[i-1][k] + F[i-1][k-1] - F[p[i]-1][k-1]`。 

減算により、再度生成されるシーケンスが削除されます。`a[i]`以前に出現した同じ値と等しい。 

長さが等しい場合は、2 次元の接頭辞 DP を定義します。 させて`F[i][j]`依然として等しい 2 つのプレフィックスから、同じ長さの別個のサブシーケンスのペアを数えて、`G[i][j]`ですでに厳密に大きくなっているペアをカウントします。`a`側。 もし`a[i] == b[j]`、新しく作成された等しいペアは、より小さいエンドポイントのペアからのものである必要があります。 もし`a[i] > b[j]`、最初の違いはこれら 2 つの位置で発生するため、等しいプレフィックスはより大きな状態に移行できます。 ペアがすでに大きい場合、長さが等しい限り、残りの選択された要素は制限されません。 

繰り返しには、以前の DP セルの四角形の合計が含まれます。 2 次元の接頭辞の合計により、各四角形が 4 つの配列アクセスに変換され、`O(nm)`アルゴリズム。 これは、公式スタイルのソリューションで使用される中心的なアイデアです。 

ここで役立つ Python 固有のメモリ改善が 1 つあります。 行の長方形`i`常に行から始まります`p[i]`、 どこ`p[i]`前回の出来事です`a[i]`。 値はからのみであるため、`1`に`100`、可能な下限は 100 個のみです。 値ごとに、前回の出現の直前に prefix-DP 行のスナップショットを保持します。 これにより、現在の行と最大 100 の保存された行のみを使用して 2 次元の繰り返しを評価できます。

 ## アルゴリズムのチュートリアル

 1. コンピューティング`p[i]`のために`a`、と同じ値を含む前の位置`a[i]`。 類似した以前の出現配列を計算します。`b`。 前の出現はまさに重複サブシーケンスが発生する可能性がある場所であるため、個別サブシーケンス DP の補正項が決定されます。 
2. あらゆる長さの異なるサブシーケンスの数を計算します。`a`そして`b`。 新しい要素ごとに、それを省略するか、前の接頭辞のサブシーケンスに追加します。 値が以前に出現した場合は、重複するサブシーケンスを減算します。 結果の配列`cntA[k]`そして`cntB[k]`インデックス選択ではなく、個別のシーケンスをカウントします。 
3. すべてのペアを数えます`|A| > |B|`。 すべての桁が以下であるため、`1000`、長さのすべてのシーケンス`k+1`あらゆる長さのシーケンスよりも大きな影響値を持ちます`k`。 それぞれの長さごとに`k`の`A`、乗算する`cntA[k]`の数によって`B`長さが以下のシーケンス`k`。 
4. 2 つの DP 状態を使用して、等しい長さのペアを処理します。 州`F[i][j]`は等しい接頭辞を表しますが、`G[i][j]`はプレフィックスを表します`A`はすでに厳密に大きいです。 空のペアは次のものに属します`F`、そのため、境界の行と列は`F`は 1 に初期化されます。 
5.加工時`(i,j)`で終わる最初に選択された位置を考慮します。`i`そして`j`。 もし`a[i] == b[j]`、ペアは等しいままにすることができ、前に選択した位置は長方形から取得する必要があります。`[p[i], i-1] × [q[j], j-1]`。 もし`a[i] > b[j]`、等しい状態の同じ四角形が最初の厳密な違いを生み出すため、それが寄与します。`G`。 既存の長方形`G`すでに大きいペアが依然として大きいため、状態も寄与します。 
6. 各 DP 行を 2 次元のプレフィックス合計として保存します。 長方形の場合`[r1,r2] × [c1,c2]`、その合計は 4 つのプレフィックス値から取得されます。 以来`r1 = p[i]`現在の行、必要な行`p[i]-1`に関連付けられたスナップショットに保持されます`a[i]`。 これにより、すべてを保存する必要がなくなります`n*m`DP細胞。 
7. すべての行を処理した後、`G[n][m]`は、正確に、からの部分列が含まれる異なる等しい長さのペアの数です。`a`の方が大きいです。 それを不等長寄与に追加します。 

これが機能する理由: すべての勝ちペアは、2 つの長さのケースのいずれかに正確に属します。 長さが等しくない場合は、長いシーケンスの方が常に数値的に大きくなります。 等しい長さの場合、すべてのペアは、最初に異なる選択された一意の位置を持ちます。 その位置より前では 2 つのシーケンスは等しく、これは次のように表されます。`F`; その位置でも`a[i] > b[j]`、作成中`G`、またはペアはまだ等しいです。 ペアが入場したら`G`、後の要素は比較結果を変更できません。 以前の出現を使用した重複修正では、それぞれの個別のシーケンスに 1 つの表現が与えられるため、重複も有効なペアも失われません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
SIGMA = 100

def distinct_by_length(s):
    """
    cnt[k] = number of distinct subsequences of s of length k.
    cnt[0] = 1 for the empty subsequence.

    Only 100 historical rows are needed because every correction row
    is immediately before the previous occurrence of the current value.
    """
    n = len(s)

    prev = [0] * (n + 1)
    prev[0] = 1

    # snap[x] is the row F[p-1] for the latest occurrence p of x.
    row0 = prev[:]
    snap = [row0[:] for _ in range(SIGMA + 1)]

    for i, x in enumerate(s, 1):
        old = prev
        special = snap[x]

        cur = old[:]
        # k > i is impossible.
        for k in range(1, i + 1):
            v = old[k] + old[k - 1] - special[k - 1]
            cur[k] = v % MOD

        # If x appears again later, its previous occurrence is i,
        # so the required correction row will be F[i-1] = old.
        snap[x] = old
        prev = cur

    return prev

def previous_occurrences(s):
    last = [0] * (SIGMA + 1)
    p = [0] * (len(s) + 1)

    for i, x in enumerate(s, 1):
        p[i] = last[x]
        last[x] = i

    return p

def equal_length_greater(a, b, pa, pb):
    """
    Count distinct pairs (A, B) with |A| = |B| and A > B.

    F is the 2D prefix table for equal prefixes.
    G is the 2D prefix table for already-greater prefixes.

    We keep only the current row and, for every value in a, the
    row immediately before its previous occurrence.
    """
    n = len(a)
    m = len(b)

    # F[0][j] = 1 and G[0][j] = 0.
    prev_f = [1] * (m + 1)
    prev_g = [0] * (m + 1)

    row0_f = prev_f[:]
    row0_g = prev_g[:]

    snap_f = [row0_f[:] for _ in range(SIGMA + 1)]
    snap_g = [row0_g[:] for _ in range(SIGMA + 1)]

    for i in range(1, n + 1):
        x = a[i - 1]

        old_f = prev_f
        old_g = prev_g

        # snap_* is row pa[i]-1.
        base_f = snap_f[x]
        base_g = snap_g[x]

        cur_f = [0] * (m + 1)
        cur_g = [0] * (m + 1)

        # The empty pair is equal, but never strictly greater.
        cur_f[0] = 1

        low_a = pa[i]

        for j in range(1, m + 1):
            low_b = pb[j]

            # Rectangle [low_a, i-1] x [low_b, j-1]
            # in the 2D prefix table.
            c1 = j - 1
            c2 = low_b - 1

            rect_f = (
                old_f[c1]
                - base_f[c1]
                - old_f[c2]
                + base_f[c2]
            )

            rect_g = (
                old_g[c1]
                - base_g[c1]
                - old_g[c2]
                + base_g[c2]
            )

            raw_f = rect_f if x == b[j - 1] else 0

            raw_g = rect_g
            if x > b[j - 1]:
                raw_g += rect_f

            # Convert the raw ending-at-(i,j) value into a 2D prefix
            # value by adding the top, left, and subtracting top-left.
            cur_f[j] = (
                raw_f
                + old_f[j]
                + cur_f[j - 1]
                - old_f[j - 1]
            ) % MOD

            cur_g[j] = (
                raw_g
                + old_g[j]
                + cur_g[j - 1]
                - old_g[j - 1]
            ) % MOD

        # For a future occurrence of x at position q,
        # p[q] = i, so the required row is F[i-1] and G[i-1].
        snap_f[x] = old_f
        snap_g[x] = old_g

        prev_f = cur_f
        prev_g = cur_g

    return prev_g[m]

def solve_data(a, b):
    n = len(a)
    m = len(b)

    cnt_a = distinct_by_length(a)
    cnt_b = distinct_by_length(b)

    # Unequal lengths: only |A| > |B| can win.
    ans = 0
    prefix_b = 0

    for k in range(1, n + 1):
        if k - 1 <= m:
            prefix_b += cnt_b[k - 1]
            if prefix_b >= MOD:
                prefix_b -= MOD

        ans = (ans + cnt_a[k] * prefix_b) % MOD

    pa = previous_occurrences(a)
    pb = previous_occurrences(b)

    ans += equal_length_greater(a, b, pa, pb)
    return ans % MOD

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    print(solve_data(a, b))

if __name__ == "__main__":
    solve()
```最初の助っ人は、`distinct_by_length`、重複を認識したサブシーケンスの繰り返しを実装します。 値のスナップショット`x`最後に発生する直前の行を保存します。`x`。 いつ`x`再び表示されます。これは、まさに減算項に必要な履歴行です。 

不等長のコントリビューションでは、次の実行プレフィックスが使用されます。`cntB`。 長さを加工する場合`k`、`prefix_b`個別の数が含まれています`B`からの長さのシーケンス`1`を通して`k-1`。 空のサブシーケンスが応答に含まれることはありません。 

等長ルーチンは次を使用します。`prev_f`そして`prev_g`2 次元プレフィックス テーブルの前の行として。`snap_f[x]`そして`snap_g[x]`行を表す`p[i]-1`。 長方形の計算は、標準的な 4 隅の包含/除外式にすぎません。 

初期化`prev_f = [1] * (m + 1)`意図的です。 空のシーケンスはすべての空のシーケンスと等しく、その結果、2 次元のプレフィックス テーブルの 0 行と 0 列に沿って値 1 が設定されます。 逆に、`G`空のシーケンスはすでに厳密にそれより大きいことはできないため、ゼロから始まります。 

Python の整数はオーバーフローせず、格納されているすべての DP 値は剰余化されます。`998244353`。 中間の四角形の式は一時的に負の値になる可能性がありますが、Python の整数には任意の精度があるため安全です。`% MOD`それを正規化します。 

元のコンテスト制限は、コンパイルされた実装向けに設計されています。 このアルゴリズムは意図した二次解法であり、上記の Python バージョンは特にメモリを削減します。`O(nm)`に`O(100(n+m))`ただし、Python インタープリタのオーバーヘッドは、元の 2.5 秒の C++ 環境よりも大幅に高くなる可能性があります。

以来`n,m <= 5000`、二次項は、クロス DP の最大約 2,500 万セル位置であり、一次元の長さ分布に対する追加の二次作業が必要です。 スナップショット技術により、2 つの割り当てを回避できます。`5001 × 5001`Python 行列。通常の Python 整数では法外に高価になります。 元の問題では 1024 MB が許容されますが、意図された漸近複雑さは 2 次です。

 ## 特殊なケース

 のために`a = [1]`そして`b = [1]`、長さ分布には、各辺に 1 つの長さの 1 つのシーケンスが含まれます。 不等長寄与はゼロです。 等しい長さの DP では、可能なペアは次のとおりです。`a[1] == b[1]`、したがって、より大きな状態ではなく、等しい状態に入ります。`G[1][1]`ゼロのままで正しい答えが得られます`0`。 

のために`a = [1,1]`そして`b = [1]`、最初の出現`1`1 つの異なる長さのシーケンスを作成します。 2 回目の出現では、反復により新しい位置で終わる可能性が追加されますが、前の行に関連付けられた行が減算されます。`1`、長さ 1 のシーケンスが 1 つだけ残ります。 長さ 2 のシーケンスもユニークです。 長さ 2 は長さ 1 より大きいため、正確に 1 つのペアがカウントされます。 

等しい長さの場合、次のように考慮します。`a = [2,1]`そして`b = [1,2]`。 最初の要素では、`2 > 1`、したがってペアは入ります`G`。 長さ 2 のシーケンスは次のようになります。`21`そして`12`、最初の要素がすでに比較を決定します。 DP は 2 番目の要素を意味論的に検査する必要はありません。ペアが一度作成されると、`G`、それ以降の要素は制限されません。 これはまさに、`rect_g`遷移を表します。 

値が繰り返される場合、以前に発生したスナップショットによって表現の重複が防止されます。 現在の値が`1`そしてその前の出現は 位置にあります`p`。 新しいものを追加することによって形成されるすべてのサブシーケンス`1`古いものを追加することですでに取得可能でした`1`削除する必要があります。 減算には、で終わる接頭辞が使用されます。`p-1`これは、正確には、オカレンス自体を使用せずに、どちらかのオカレンスの前に置くことができる一連のシーケンスです。 

最大サイズのすべてが等しい長さの配列の場合`5000`、空でない長さごとに異なるサブシーケンスが 1 つだけ存在します。 配列は同一であるため、同じ長さのペアが寄与することはありません。 あらゆる人にとって`k`から`2`を通して`5000`、独特の長さ-`k`からのシーケンス`a`ユニークな長さのシーケンスに勝つ`1`を通して`k-1`から`b`。 答えは、`1 + 2 + ... + 4999 = 5000 * 4999 / 2 = 12,497,500`両方の配列に長さがある場合`5000`。 

境界値については`100`、1000 進数の比較は変更しなくても機能します。 の先頭の数字`100`まだ下にあります`1000`, したがって、ポジション間のキャリーはありません。 これが、数値比較全体を長さと辞書順に安全に縮小できる理由です。
