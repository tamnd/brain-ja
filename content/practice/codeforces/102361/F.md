 ## 解決策
 ## 問題の理解

 すべての接続コンポーネントがサボテンである無向グラフがあります。 削除するエッジのセットを選択できます。 削除後は、すべての接続コンポーネントがツリーになる必要があります。これは、残りのグラフにサイクルが含まれてはならないと言うのと同じです。 

サボテンを観察する便利な方法は、その端を 2 種類に分けることです。 一部のエッジは 1 つのサイクルに属し、そのようなエッジはすべて 1 つのサイクルに属します。 残りのエッジはどのサイクルにも含まれません。 サボテン内のサイクルはエッジを共有しないため、異なるサイクルに対して行われる決定は独立しています。 

1 つのサイクルに (k) 個のエッジが含まれていると仮定します。 すべて (k) のエッジを保持すると、そのサイクルがそのまま残るため、単一の選択は禁止されます。 そのエッジの他のすべてのサブセットは有効です。 

[
 2^k-1
 】

 選択肢。 すべてのサイクルの外側のエッジは削除するか保持することができ、2 つの選択肢があります。 

サイクル長が (c_1,c_2,\ldots,c_t) で、エッジの総数が

 [
 C=c_1+c_2+\cdots+c_t、
 】

 答えは

 [
 2^{m-C}\prod_{i=1}^{t}(2^{c_i}-1)。 
】

 残りのタスクは、すべてのサイクルとその長さを効率的に見つけることです。 

公式問題には (n\le300000)、(m\le500000) があり、制限時間は 1 秒、メモリ制限は 1024 MB です。 指数関数的に多くのエッジ サブセットを求めてグラフ全体を繰り返しスキャンするアルゴリズムは、まったく実行不可能です。 おそらく、べき乗モジュラーの対数係数を使用した、グラフ サイズの基本的な線形作業が必要です。 

誤った解決策を引き起こしやすい特殊なケースがいくつかあります。 

エッジのないグラフの場合、```
1 0
```答えは`1`。 可能な除去セットは 1 つだけあり、それは空のセットです。 すべてのコンポーネントにサイクルが含まれると仮定したソリューションでは、誤ってゼロを返す可能性があります。 

片方の端を持つ木の場合、```
2 1
1 2
```答えは`2`。 エッジを維持することも、削除することもできます。 結果として得られるグラフはどちらもフォレストです。 サイクルを断ち切る方法だけを数えるソリューションは戻ってくるかもしれない`1`、非サイクルエッジも独立して取り外し可能であることを忘れています。 

切断されたコンポーネントは個別に処理する必要があります。 のために```
6 6
1 2
2 3
3 1
4 5
5 6
6 4
```2 つの独立した三角形があるので、答えは次のようになります。 

[
 (2^3-1)^2=7^2=49。 
】

 頂点 1 からのみ開始された DFS は、2 番目のコンポーネントを完全に見逃してリターンします。`7`。 

最後に、ブリッジが接続されたサイクルを考えてみましょう。```
4 4
1 2
2 3
3 1
3 4
```三角形が貢献する`7`選択肢とブリッジが貢献する`2`、したがって、答えは次のとおりです`14`。 すべてのエッジをサイクルに属しているかのように扱ったり、非サイクル エッジを完全に無視したりすると、誤った結果が生じます。 

## アプローチ

 最も直接的なアプローチは、(m) 個のエッジのすべてのサブセットを列挙することです。 サブセットごとに、選択したエッジを保持し、結果のグラフが非周期的であるかどうかをテストします。 標準の DFS または DSU ベースのチェックでは、(O(n+m)) 時間内にサイクルが存在するかどうかを判断できます。 (2^m) 個のサブセットがあるため、これには次の時間がかかります。 

[
 O(2^m(n+m))
 】

 時間。 最大 (m=500000) では、約 (2^{500000})、およそ (10^{150515}) 個の異なるサブセットを調べることになります。 この方法は、考えられるすべての削除スキームを明示的にチェックするため正しいですが、検索スペースは実際的な制限をはるかに超えています。 

サボテンの構造は、より強力な観察を可能にします。 元のサイクルが完全に生き残ったとき、残りのグラフは正確には森ではなくなります。 したがって、すべての元のサイクルには 1 つの条件のみが課されます。つまり、そのエッジの少なくとも 1 つは削除されなければなりません。 長さ (k) のサイクルの場合、何も削除せず (2^k-1) となる 1 つのサブセットを除いて、そのエッジのすべての (2^k) 個のサブセットが可能です。 

サイクルの外側のエッジにはまったく制限がありません。 このようなエッジを削除してもサイクルは作成できません。エッジは元のグラフの一部ではないため、維持してもサイクルを作成できません。 したがって、そのようなすべてのエッジは次の要因に寄与します。`2`。 

グラフに残された唯一の問題は、すべてのサイクル長を特定することです。 DFS はまさに必要なものを提供します。 無向 DFS ツリーでは、すべての非ツリー エッジが頂点をその祖先の 1 つに接続します。 現在の頂点に深さ (d_u) があり、祖先の深さ (d_v) がある場合、それらの間のツリー パスには (d_u-d_v) 個のエッジが含まれ、非ツリー エッジは長さのサイクルを閉じます。 

[
 d_u-d_v+1。 
】

 サボテンの状態が特にきれいです。 ツリー以外の各エッジは 1 つの異なる単純なサイクルに対応するため、これらのバック エッジをカウントすると、すべてのサイクルが 1 回だけ計算されます。 

ブルート フォース手法は、考えられるすべてのサブセットを明示的にチェックするため機能しますが、サブセットの数が指数関数的なため失敗します。 サボテンの観察により、問題全体が 1 つの DFS によるサイクル長の検出と独立した寄与の乗算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^m(n+m))) | (O(n+m)) | 遅すぎる |
 | サボテンの DFS | (O(n+m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力エッジにエッジ ID を割り当てながら、無向グラフを構築します。 この実装では、両方のエンドポイントがすでに訪問されている場合でも、無向エッジとその逆を区別できるように、隣接配列を含むグラフを保存します。 
2. 深さが割り当てられていないすべての頂点から DFS を開始します。 グラフは必ずしも接続されているわけではないので、頂点から 1 つの DFS`1`では不十分です。 
3. 開始頂点の深さを割り当てます。`0`。 DFS が未訪問の頂点を検出するたびに`v`から`u`、割り当てます`depth[v] = depth[u] + 1`そして到達するために使用されたエッジを思い出してください`v`親エッジとして。 
4. すでに訪問した隣人を調べる場合`v`の`u`、親エッジの反転を無視します。 もし`depth[v] < depth[u]`、 それから`v`の先祖です`u`したがって、このエッジはサイクルを閉じる非ツリー エッジです。 
5. サイクル長を次のように計算します。`depth[u] - depth[v] + 1`。 からの木道`v`に`u`もっている`depth[u] - depth[v]`エッジが追加され、現在のエッジにさらに 1 つ追加されます。 
6. 答えに (2^{k}-1) を掛けます。ここで (k) は発見されたサイクル長です。 また、(k) を追加します。`cycle_edges`、サイクルに属するエッジの数。 
7. DFS が完了したら、正確に`m - cycle_edges`エッジはすべてのサイクルの外側にあります。 これらはそれぞれ独立して保持または削除できるため、答えに次の値を掛けます。 

[
 2^{m-\text{cycle_edges}}。 
】

 1. までの 2 の累乗をすべて計算します。`n`モジュロ`998244353`DFSの前。 サイクルには以下のものを含めることはできません`n`エッジなので、すべての係数 (2^k) を一定時間で取得できます。 

### なぜ効果があるのか

 アルゴリズムによって生成された削除スキームを検討してください。 元のサイクルごとに、係数 (2^k-1) によって、削除された空のサブセット以外のエッジのサブセットが選択されるため、そのサイクルの少なくとも 1 つのエッジが削除されます。 元のサイクルはすべて壊れているため、元のサイクルがそのまま残ることはありません。 

逆に、除去スキームがサイクルを残すと仮定します。 残りのエッジはすべて元のグラフに存在していたので、そのサイクルは元のサボテンのサイクルでもありました。 このスキームでは、そのサイクルからエッジは削除されません。これは、まさに (2^k-1) 係数によって除外される 1 つの禁止された選択です。 したがって、式によってカウントされるすべてのスキームは森を残します。 

DFS は、各サボテン サイクルを 1 回カウントします。 無向 DFS 内のすべての非ツリー エッジは頂点と祖先を接続し、対応するツリー パスとそのエッジがサイクルを形成します。 サボテンの各エッジは最大でも 1 つの単純なサイクルに属するため、そのように発見された 2 つのサイクルが同じエッジ サイクルを表すことはできません。 したがって、収集されたサイクル長は正確にすべてのサイクル エッジを占め、残りのすべてのエッジはすべてのサイクルの外側にあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())

    head = [-1] * n
    to = [0] * (2 * m)
    nxt = [0] * (2 * m)

    edge_ptr = 0

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        to[edge_ptr] = v
        nxt[edge_ptr] = head[u]
        head[u] = edge_ptr
        edge_ptr += 1

        to[edge_ptr] = u
        nxt[edge_ptr] = head[v]
        head[v] = edge_ptr
        edge_ptr += 1

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    depth = [-1] * n
    parent_edge = [-1] * n
    current_edge = [-1] * n

    answer = 1
    cycle_edges = 0

    for root in range(n):
        if depth[root] != -1:
            continue

        depth[root] = 0
        parent_edge[root] = -1
        current_edge[root] = head[root]

        stack = [root]

        while stack:
            u = stack[-1]
            e = current_edge[u]

            if e == -1:
                stack.pop()
                continue

            current_edge[u] = nxt[e]

            if parent_edge[u] != -1 and e == (parent_edge[u] ^ 1):
                continue

            v = to[e]

            if depth[v] == -1:
                depth[v] = depth[u] + 1
                parent_edge[v] = e
                current_edge[v] = head[v]
                stack.append(v)
            elif depth[v] < depth[u]:
                length = depth[u] - depth[v] + 1
                cycle_edges += length
                answer = answer * (pow2[length] - 1) % MOD

    answer = answer * pow2[m - cycle_edges] % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```隣接構造では次を使用します。`head`、`to`、 そして`nxt`すべてのエッジのタプルの Python リストの代わりに。 各入力エッジは 2 つの有向隣接エントリを作成し、2 つのエントリは連続したインデックスを持ちます。 そのため、親エッジの反転は次のように取得されます。`parent_edge[u] ^ 1`。 

DFS は再帰的ではなく反復的です。 まで`300000`頂点の場合、Python のデフォルトの再帰の深さはパス状のサボテンには十分ではなく、再帰の制限を増やしても再帰のオーバーヘッドが残ります。 明示的な`stack`両方の問題を回避します。`depth[v] == -1`未訪問の状態です。 頂点に深さがあれば、より浅い頂点につながるエッジはバック エッジとして扱われます。 より深い頂点につながるエッジは、DFS ツリー エッジまたは既に処理された非ツリー エッジの逆方向であるため、無視されます。 

表現`depth[u] - depth[v] + 1`は正確なサイクル長です。 の`+1`深さの差はツリー エッジのみをカウントし、現在の非ツリー エッジはサイクルを閉じる最後のエッジであるため、見落としがちです。`cycle_edges`サイクル数ではなく、サイクル長の合計を保存します。 サボテンのサイクルはエッジが互いに素であるため、これはまさに、独立した橋のようなエッジとして扱うことが禁止されているエッジの数です。 

整数の精度は任意であるため、Python ではモジュラー演算は安全です。 すべての乗算後の明示的な係数は、中間値を小さく保ち、必要な係数に従います。`998244353`。 

この実装では、未訪問のすべての頂点から DFS も開始されます。 これは、孤立した頂点と切断されたサボテン コンポーネントを特別なケースなしで処理します。

 ## 特殊なケース

 孤立した頂点の場合、入力は次のようになります。```
1 0
```DFS は頂点から始まります`1`、深さを割り当てます`0`、隣接リストが空であるため、すぐに終了します。 サイクルが見つからないため、`cycle_edges = 0`。 最後の因数は (2^0=1) で、出力が得られます。`1`。 これにより、空の除去セットが正しくカウントされます。 

次のような木の場合```
5 4
1 2
1 3
1 4
1 5
```すべての DFS エッジはツリー エッジであり、頂点を祖先に接続するエッジはありません。 したがって、サイクル係数は答えに乗算されません。 4 つのエッジはすべてサイクルの外側にあるため、最終的な因数は (2^4=16) になります。 このアルゴリズムでは、これらのエッジの削除または保持のあらゆる組み合わせが正しく許可されます。 

橋のある三角形の場合、```
4 4
1 2
2 3
3 1
3 4
```DFS は三角形を閉じるバックエッジを検出し、サイクル長を取得します`3`。 追加します`3`に`cycle_edges`、出発`4-3=1`独立したエッジ。 答えは次のようになります

 [
 (2^3-1)2=7\cdot2=14。

 ブリッジは、サイクルを断ち切るために必要ではない場合でも削除できます。そのため、ブリッジの要素を式に残さなければなりません。 

接続されていない三角形の場合、```
6 6
1 2

3 1

6 4
```最初の DFS で長さ 3 のサイクルが見つかり、外側のループが頂点に到達します。`4`まだアクセスされていないため、別の DFS を開始します。 2 番目の DFS は、2 番目の長さ 3 のサイクルを見つけます。 結果の積は (7\cdot7=49) です。 これは、すべての頂点にわたる外側のループが必要な理由を示しています。 

多くの短いサイクルを含む大きなサボテンの場合、明示的なスタックにより再帰の深さの問題が防止されます。 149999 個の三角形を使用したテストでは、すべてのサイクルが係数に寄与します。`7`したがって、答えは (7^{149999}) モジュロです`998244353`。 DFS は依然として、線形の複雑さを維持しながら、約 450,000 の各エッジを一定の回数だけ処理します。
