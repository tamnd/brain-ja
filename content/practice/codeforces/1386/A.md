 ## 問題の理解

 整数のしきい値を選択した隠れたシステムと対話しています。$C$1との間$N$。 1 から 1 までの数字を考えることができます。$N$直線上の位置として表示され、位置を選択するたびに、髪をその色で効果的に「染める」ことになります。 最初の選択の後、次のすべての選択が前の選択と比較され、選択された 2 つの数値間の絶対差が少なくとも 1 つであるかどうかがわかります。$C$。 

重要な仕組みは、システムがバイナリ信号のみを報告することです。選択された 2 つの連続した値が十分に離れている場合は 1 と表示され、そうでない場合は 0 と表示されます。 最初のクエリは特別です。比較する前の色がないため、その答えには情報が含まれません。 

タスクは、の正確な値を特定することです。$C$最大 64 のそのような比較を使用します。 

制約は非常に大きく、$N$まで$10^{18}$これにより、値を 1 つずつ調査しようとする戦略は即座に除外されます。 各「テスト」は対話型でクエリを消費するため、全範囲にわたる対数スキャンでも注意が必要です。 本当の制限は演算の複雑さではなくクエリ バジェットであるため、ソリューションはインタラクションごとに最大の情報を抽出する必要があります。 

「前の値」を制御せずに任意のペア間の比較を独立してテストできると仮定すると、微妙な失敗例が発生します。 応答は独立したペアではなく、連続するクエリのみに依存するため、クエリをスタンドアロンの比較として扱うという単純な考えは、静かに壊れます。 

たとえば、クエリを実行しようとすると、$x$その後のクエリ$y$そしてテストしていると仮定します$|x-y|$、中間クエリによって以前の状態が上書きされるため、遷移を注意深く制御しない限り、これは誤りです。 

## アプローチ

 ブルートフォース戦略では、次のことを発見しようとします。$C$距離を増やしてみて、応答が 0 から 1 に切り替わるタイミングを観察します。静的な設定では、これは、可能なすべての値をチェックするのと似ています。$d$1 から始まりますが、この対話型モデルでは、各チェックで差のある有効な数値のペアを構築する必要があります。$d$これを繰り返し行うと、次のような線形時間が必要になります。$N$、時間とクエリの両方の制限の下では不可能です。 

重要な観察は、各対話によって、2 つの連続するクエリ間のギャップに関する決定的な述語が得られるということです。 選択した値を常に固定参照と比較するようにシステムに強制できれば、すべてのクエリはクリーンな不等式テストになります。$C$。 

これは、前の値を固定することによって実現されます。 すべての意味のある比較が、選択された比較の間で行われることを確認すると、$x$および固定値 1 の場合、応答は次のことを直接示します。$|x - 1| \ge C$。 それは問題を単調な述語に変換します$x$、二分探索を可能にします。 

残る唯一の困難は、すべてのテストが実際に比較されるように相互作用状態を制御することです。$x$これは、プローブごとに「リセット」クエリを 1 に挿入することで処理されます。

 ## アルゴリズムのチュートリアル

 テスト サイクルが完了するたびに、最後に選択された色が 1 になるという不変条件を維持します。 

1. 値 1 のダミー クエリを送信することから始めます。これにより前の色が初期化されますが、その応答は無視されます。 このステップの後、システムが定義された状態にあることがわかります。 
2. 候補値に対する関数のようなテストを定義します$x$かどうかを知りたい場合、$x - 1 \ge C$。 これは、比較時にシステムが 1 を応答するかどうかを確認するのと同じです。$x$1で。 
3. 候補者を評価するため$x$、最初のクエリ$x$。 これにより、内部の前の色が次のように設定されます。$x$, しかし、この応答は使用しません。 
4. すぐにクエリ 1. システムが比較します。$x$1 を指定し、次の場合にのみ 1 を返します。$|x - 1| \ge C$。 このステップの後、前の色は 1 に復元され、不変条件が維持されます。 
5. 最小値を二分探索します$x$範囲内で$[2, N]$テストで 1 が返されるようにします。この点は正確に$x = C + 1$、それより下の値はしきい値を満たさず、その時点以降の値はしきい値を通過するためです。 
6. 出力$C = x - 1$。 

二分探索は標準です: 範囲を維持します$[l, r]$、中間点をテストし、以下に基づいて範囲を縮小します。$mid$述語を満たします。 

### なぜ効果があるのか

 重要な不変条件は、意味のある比較は常に現在の候補間で行われるということです。$x$各テストの 2 番目のクエリは常にシステムを 1 にリセットするため、ステップ間で相互作用のドリフトが蓄積することはありません。 

これにより、述語が「～する」ことが保証されます。$x$リセット サイクルで応答 1 を生成する」は、$x$、前歴ではありません。 これにより、述語が単調になります$x$、かつてから$x - 1 \ge C$成り立つ、それはより大きなすべてに成り立つ$x$。 単調性により、二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x: int) -> int:
    print("?", x)
    sys.stdout.flush()
    return int(input().strip())

def solve_case(n: int):
    # establish initial state
    ask(1)

    def check(x: int) -> int:
        # query x, then reset with 1
        ask(x)
        return ask(1)

    l, r = 2, n
    ans = n

    while l <= r:
        mid = (l + r) // 2
        if check(mid):
            ans = mid
            r = mid - 1
        else:
            l = mid + 1

    print("=", ans - 1)
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```実装は以下を中心に展開します。`check(x)`このルーチンは、すべての候補クエリと 1 へのリセット クエリを組み合わせることで制御された比較を強制します。 1 では意味のある分離が得られないため、二分検索は 2 から始まる、候補として安全に使用できる値に対してのみ動作します。 

最初の呼び出しは、`ask(1)`たとえその応答が破棄されたとしても、最初の実際の比較が一貫して動作することを保証するために必要です。 

## 実用的な例

 検討してください$N = 7$そして$C = 4$。 正しい遷移点は次のとおりです。$x = 5$。 

| ステップ | クエリ x | クエリ 1 の結果 | 意味 | 検索範囲 |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 0 | 3 < C なので、x=4 は失敗します。 [2、7] |
 | 2 | 6 | 1 | 5 ≥ C+1 したがって、x=6 が合格します。 [2、5] |
 | 3 | 5 | 1 | 境界線はまだ通過します | [2、4] |

 最後に最小パス$x$は 5 なので、$C = 4$。 

ここで考えてみましょう$C = 1$、可能な最小値。 どれでも$x \ge 2$はすぐにテストに合格するため、二分探索はすぐに次のように収束します。$x = 2$、降伏$C = 1$。 

これらのトレースは、述語がソートされた配列のしきい値関数とまったく同じように動作することを示しています。

 ## 特殊なケース

 いつ$C = 1$、異なる数値間のすべての比較は常に 1 を返します。述語に渡される最初の値は次のとおりであるため、アルゴリズムは引き続き機能します。$x = 2$なので、計算結果は正しく1になります。 

いつ$C = N$、正確には違いのみ$N$は合格しますが、それは不可能です。そのため、次の結果が得られるまで、すべてのテストは 0 を返します。$x = N$。 二分探索は自然に次のように収束します。$x = N$、生産$C = N - 1$、違いだけなので定義と一致します$N-1$が不十分で、その他はすべてしきい値を下回っています。 

インタラクションのリセット手順は、あらゆる場合に不可欠です。 各プローブ後にベースラインを 1 に再確立しないと、述語がパス依存になり、二分探索が有効性を失い、固定されたものであっても応答が一貫性を失います。$x$。
