 ## 問題の理解

 このタスクは、整数のべき乗の繰り返しの合計に基づく単純な数値構造を記述します。$k$。 クエリごとに基本値が与えられます。$k$そして長さ$n$、最初の値を加算して得られる値を計算する必要があります。$n$の力$k$から始まる$k^1$。 

言い換えれば、最初の項が次のような等比数列を評価しています。$k$、2つ目は$k^2$、などまで$k^n$。 出力はこれらの値の合計です。 

計算の観点から見ると、クエリごとの入力サイズは構造的には小さいですが、値は潜在的に大きくなります。$k$非常に早く成長します。 これにより、大規模な累乗シーケンスの単純な整数シミュレーションが即座に排除されます。$n$べき乗を効率的に処理しない限り、

 もし$n$大きな値に達する可能性があります (通常は最大$10^5$この形式の問題ではさらに多くの場合、乗算が繰り返されるため、各べき乗を独立して計算する線形ループは実行できなくなります。 たとえそれぞれの掛け算が$O(1)$、Python では大きな整数演算が原因で、中間値の指数関数的な増加もボトルネックになります。 

主な制約の意味は、べき乗を最初から再計算することを避け、代わりに以前の計算を再利用するか、閉じた形式の公式を適用する必要があることです。 

エッジケースは次の場合に発生します。$k = 1$、一般的な等比級数の公式には、による除算が含まれるためです。$k-1$、ゼロになります。 もう一つの微妙なケースは次のような場合です。$n = 1$、合計は単一の項に縮退します。$k$。 単純な式の実装では、ここで簡単に壊れてしまう可能性があります。

連続したべき乗が乗法的に関係していることを認識すると、より良い観察が得られます。 再計算する代わりに$k^i$ゼロから、現在の電力の実行値を維持できます。 から始まる$k^1 = k$、次の各項は前の項を乗算することで得られます。$k$。 これにより、期間あたりのコストが削減されます。$O(1)$、全体の合計が線形になります$n$。

 ## アルゴリズムのチュートリアル

 次の場合に閉形式等比級数式を使用します。$k \neq 1$、それ以外の場合は特殊な場合があります。 

1. 整数の読み取り$k$そして$n$。 これらは、べき乗和の底と項の数を定義します。 
2. もし$k = 1$、 戻る$n$。 これは、合計の各項が 1 であるため、合計は単に項の数にすぎないためです。 
3. それ以外の場合は計算します$k^{n+1}$高速累乗を使用します。 私たちは計算します$n+1$それよりも$n$この式には以下の項が含まれるため、$k^{n+1}$。 
4. コンピューティング$k$それ自体を別にしてから差し引きます$k^{n+1}$、幾何和の公式の分子を形成します。 
5. 結果を次の値で割ります。$k - 1$。 これにより等比数列の和が求められます。 

重要な推論ステップは、インデックス付けの正確さを維持することです。 シリーズは次から始まります$k^1$したがって、閉じた形式で指数をシフトすることが不可欠です。 このシフトを見逃すことが、最も一般的なエラーの原因です。 

### なぜ効果があるのか

 表現$k + k^2 + \dots + k^n$比を持つ標準等比級数です$k$。 合計を乗算する$k$すべての項を 1 乗でシフトし、$k^2 + k^3 + \dots + k^{n+1}$。 元の合計を減算すると、すべての中間期間がキャンセルされ、残りの期間のみが残ります。$k^{n+1} - k$。 この恒等式により、閉じた形式が常にすべての元の合計と等しくなることが保証されます。$k \neq 1$。 特別な場合$k = 1$そこでは代数変換がゼロで除算されるため、個別に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e):
    res = 1
    base = a
    while e > 0:
        if e & 1:
            res *= base
        base *= base
        e >>= 1
    return res

def solve():
    data = input().strip().split()
    if not data:
        return
    k = int(data[0])
    n = int(data[1])

    if k == 1:
        print(n)
        return

    # sum = k + k^2 + ... + k^n = (k^(n+1) - k) / (k - 1)
    kn1 = mod_pow(k, n + 1)
    kn1_minus_k = kn1 - k
    print(kn1_minus_k // (k - 1))

if __name__ == "__main__":
    solve()

実装の微妙な詳細は、次のように計算します。$k^{n+1}$、 ない$k^n$。 このシフトにより、代数導出と合計が で始まるという事実が一致します。$k^1$、 ない$k^0$。 もう 1 つの重要な点は、大きな整数の処理です。Python は自然に大きな整数をサポートしますが、中間値は依然として大幅に増加する可能性があるためです。
