 ## 問題の理解

 サイズの順列が与えられています$n$そして一連の範囲クエリ。 各クエリは間隔によって定義されます$[l, r]$。 タスクは、すべてのクエリについて、インデックスのペアに依存する値を計算することです。$(i, j)$並べ替え順序条件の意味で、あるインデックスが別のインデックスを「分割」するようなもの$p_i \mid p_j$ステートメントのコンテキストで指定されます。 

主な問題は、これらの有効なペアがクエリから独立していないことです。 かどうかに応じて$i$そして$j$クエリ間隔の内側または外側にある場合、それらの寄与は応答に影響を与えるか、または相殺されます。 したがって、単純に大域除数関係をカウントしているのではなく、相互作用がクエリ セグメントに完全に含まれているペアのみをカウントしています。 

入力は、順列と複数の範囲クエリで構成されます。 クエリごとに、その間隔に完全に関連する有効な除数ペアの数を出力する必要があります。 

この制約は、単純なクエリごとの再計算が不可能であることを意味します。 すべてのインデックスにわたる関連するペアの数は、約数を超える調和系列のように増加するため、ペアの総数は次のようになります。$O(n \log n)$ただし、クエリごとに二次関数を実行すると、両方の場合にすぐに失敗します。$n$そしてクエリの数も多いです。 

単純な総当たりアプローチでは、クエリごとにすべてのペアを反復処理します。$(i, j)$、割り算条件を確認し、両方の端点が区間内にあるかどうかを確認します。 これは正しいですが、遅すぎます。$O(n^2)$最悪の場合、クエリごとに。 

より微妙な失敗例は、間隔の境界を考慮せずにグローバル カウントを事前計算しようとした場合に発生します。 たとえば、有効なペアをすべて 1 回事前計算すると、クエリ内にエンドポイントが 1 つだけ存在するペアが過大にカウントされ、寄与を慎重に構成しない限り単純な減算はできません。 

## アプローチ

 主なアイデアは、ペアがクエリ間隔とどのように相互作用するかを分離することです。 各ペアごとに$(i, j)$、両方のインデックスが区間の外側にある、ちょうど 1 つが内側にある、または両方が内側にあるという、正確に 3 つの可能性があります。 最後のカテゴリのみが回答に寄与する必要があります。 

ブルート フォース方式では、クエリごとに各ペアを明示的にチェックし、間隔メンバーシップによってフィルタリングします。 これはすぐに実行不可能になります。 

重要な観察は、問題を接頭辞-接尾辞の簿記に変換できるということです。 クエリごとの寄与を再計算する代わりに、各位置がこれまでに確認した有効な「除数ヒット」の数を蓄積する実行構造を維持します。 

補助配列を定義します`count`、 どこ`count[j]`インデックスの数を表します$i$これまでに見られた可分性関係を満たす$p_i \mid p_j$。 インデックスを左から右にスイープし、各インデックスの寄与を更新します。$i$順列空間内のすべての倍数に変換します。 

各クエリについて、その答えを 2 つの累積合計に分解します。1 つは左側の境界で計算され、もう 1 つは右側の境界で計算されます。 境界を越えるペアは対称的にキャンセルされるため、この差により、区間内に完全に含まれるペアが正確に分離されます。 

これにより、問題は次のように変換されます。

 ## アルゴリズムのチュートリアル

 次に、インデックスのスイープとフェンウィック ツリーを使用して、動的カウントを維持するソリューションを段階的に構築します。 

### 1. フェンウィック ツリーを初期化します。$n$ポジション

 ポイント更新とプレフィックス合計クエリをサポートする構造が必要です。 これは各インデックスのために必要です。$i$複数のポジションに貢献する$j$また、クエリ境界の高速範囲合計も必要です。 

### 2. スイープ$i$1から$n$それぞれのポジションで$i$、すべてのポジションを考慮します$j$そのような$p_i$分割する$p_j$。 そういったものごとに$j$、増分します`count[j]`フェンウィックツリーの1で。 

このステップでは、インデックスの処理後に不変条件を構築します。$i$、インデックスからのすべての約数の寄与$i$に反映されています`count`。 

### 3. 適切なエンドポイントごとにグループ化されたクエリを処理する

 各クエリをそのエンドポイントに関連付けます。 スイープしていると、インデックスに到達すると、$i$、右境界が次のとおりであるすべてのクエリの寄与も計算します。$i$。 値を記録します`right_k`の合計に等しい`count`以上$[l_k, r_k]$。 

これにより、正しい境界までのインデックスを使用してすべての寄与がキャプチャされます。 

### 4. 左側の境界に対して同じロジックを繰り返します。 

概念的にはスイープを繰り返すか、2 番目の評価を維持して計算します。`left_k`、これは、左側の境界が完全に含まれる前の寄与に対応します。 

違い`right_k - left_k`両方のインデックスが区間内にあるペアを正確に分離します。 

減算が機能するのは、境界を越えるすべてのペアが両側に対称的に寄与し、完全に内部のペアがもう一度正確にカウントされるためです。`right_k`。 

### なぜ効果があるのか

 正確さは、有効な各ペアを分類するかどうかにかかっています。$(i, j)$それは、完全にクエリ間隔の前、横、または内側にあるかどうかによって決まります。 

完全に外部にあるペアは、どちらのプレフィックス合計にも影響を与えません。 境界を越えるペアは両方に等しく寄与します`left_k`そして`right_k`, したがって、それらは相殺されます。 に完全に含まれるペアのみ$[l, r]$に登場する`right_k`しかし、中にはありません`left_k`。 

この不変性により、減算によって二重カウントや省略が発生することなく、目的のカウントが正確に分離されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))

    queries = [[] for _ in range(n + 1)]
    for idx in range(q):
        l, r = map(int, input().split())
        queries[r].append((l, idx))

    bit = Fenwick(n)
    count = [0] * (n + 1)

    right = [0] * q
    left = [0] * q

    for i in range(1, n + 1):
        val = p[i - 1]
        j = val
        while j <= n:
            bit.add(j, 1)
            j += val

        for l, idx in queries[i]:
            right[idx] = bit.range_sum(l, i)

    bit = Fenwick(n)

    for i in range(1, n + 1):
        val = p[i - 1]
        j = val
        while j <= n:
            bit.add(j, 1)
            j += val

        for l, idx in queries[i]:
            left[idx] = bit.range_sum(l, i)

    ans = [right[i] - left[i] for i in range(q)]
    print(*ans)

if __name__ == "__main__":
    solve()

クエリを適切なエンドポイントごとにグループ化して保存し、計算できるようにします。`right_k`まさにスイープがそのエンドポイントに到達したときです。 2 番目の同一のスイープは次の目的で使用されます。`left_k`、減算により内部ペアが分離されます。
