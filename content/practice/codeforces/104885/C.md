 ## 解決策
 ## 問題の理解

 共有の予算制約の下で 2 つの 10 進数のシーケンスを構築しています。 このプロセスでは両方のシーケンスが並行して構築され、各ステップで固定合計額の一部が数字の追加に費やされます。 目的は、結果として得られる 2 つの数値から計算される最終的な式を最大化することです。 

2 つの配列に数字を追加するたびに、固定量の「値」を効率的に配列間に分配することになります。 最終的なスコアは、数値がどの程度大きくなり、その桁がどのように配置されるかによって決まります。そのため、構築上の問題は実際には、非線形の目的を最大化する方法で、利用可能な合計を桁の寄与にどのように割り当てるかということになります。 

重要な構造上の詳細は、大きな数字を前後に配置すると結果の数値の大きさが変化するため、数字の寄与が配置に関して線形ではないことです。 これが、恣意的な分割ではなく貪欲な構築を意味のあるものにします。 

問題ステートメントによって暗示される制約から、構築は、許容されるステップの合計または数に関して線形時間で実行される必要があります。 桁の割り当ての列挙や 2 つの配列間での値の強引な分散を伴うものはどれも遅すぎます。これは、可能な分散の数が位置の数に応じて指数関数的に増加するためです。 

各配列を独立して貪欲に最大化しようとすると、単純な間違いが発生します。 たとえば、2 番目の配列を考慮せずに最初の配列を常に最大化しようとすると、次のような結果が生成される可能性があります。 

入力シナリオ: 合計により、数字 9、8、1 を形成できます。 

単純な戦略では次のような結果が生じる可能性があります。 

最初の配列: 9、8、1

 2 番目の配列: 0、0、0

 特に式に両方の数値が含まれる場合、配列間の相互作用が重要になるため、これは最適とは言えません。 正しく構築するには、すべてのステップで両方のアレイを同期する必要があります。 

残りの合計が少ない場合には、別のエッジ ケースが発生します。 残り 10 ユニットだけだとします。 貪欲な「常に 9 を取る」戦略は、オーバーシュートしたり、非効率な余りを使用したりして、最適なペア構造に違反するアンバランスな桁を生成するため、破綻します。 

## アプローチ

 ブルートフォースアプローチでは、追加された各数字が残りの予算の一部を消費することを考慮して、両方の配列にわたって合計を数字のペアに分割するあらゆる方法が試行されます。 各ステップで、最初の配列にどれだけ割り当てるか、2 番目の配列にどれだけ割り当てるかを決定し、再帰的に続行します。 これは、割り当ての各単位がいずれかの配列に入る可能性があり、たとえ桁ごとに離散化したとしても、シーケンスの数は長さに応じて組み合わせ的に増加するため、指数関数的な分岐係数につながります。 合計が S になると、分布の数は指数関数的な複雑さを持つ分割問題のように動作します。 

すべてを単純化する重要な観察は、最終値が桁の大きさに大きく依存し、桁 9 が他のすべての桁を支配するということです。 これにより、両方の配列でできるだけ多くの 9 を使用するように構築が推進されます。 高い桁が優先されるべきであることを受け入れると、問題は、残りの合計を 2 つの 9 を完全にサポートするチャンクに分配する方法、または剰余が不十分な場合に最終的なバランスの取れたペアを形成する方法を決定する方法を決定することになります。 

2 番目の観察は、固定和の最適化に関するものです。2 つの数値の合計が定数になる場合、それらの積が可能な限り等しいときに最大化されます。 これは、完全な 9+9 ペアを配置できなくなった場合の最終調整フェーズを決定するものです。

この総当り攻撃は、すべての割り当てを探索するため機能しますが、高桁の優位性と、固定合計の下での積の最大化の凸状の動作を利用していないため、失敗します。 「可能な限り 9 を使用し、残りを最適にバランスさせる」という観察は、状態空間を線形の貪欲なプロセスに崩壊させます。

 ## アルゴリズムのチュートリアル

 残りの合計と、並行して構築する 2 つの配列を維持します。 

1. 両方のシーケンスの空の配列から開始し、利用可能な合計を読み取ります。 この合計は、両方の配列に分散できる合計桁値の量を表します。 
2. 残りの合計が 18 以上である間に、両方の配列に数字 9 を追加し、合計から 18 を減算します。 18 が表示される理由は、9 が 1 桁の寄与の最大値であるという事実を十分に利用して、値 9 の 2 桁を同時に配置しているためです。 
3. このループの後、残りの合計は厳密に 18 未満になります。この時点で、9 を 2 つ置く余裕はもうありません。 
4. ここで、残りの合計を 2 つの配列間でバランスのとれた方法で分配します。 残りの合計を S とします。 a + b = S および |a − b| となる 2 つの整数 a と b を選択します。 バランスの取れた分割により製品のような目的が最大化されるため、これにより、最終的な寄与が固定合計制約の下で最大化されることが保証されます。 
5. 2 つの配列にそれぞれ a と b を追加します。 S が偶数の場合、両方とも S/2 を受け取ります。 S が奇数の場合、一方は (S+1)/2 を受け取り、もう一方は (S-1)/2 を受け取ります。 
6. 問題の最終要件に応じて、構築された配列、またはそこから導出された計算式を出力します。 

### なぜ効果があるのか

 この構築では、問題を 2 つの領域に分割します。1 つは桁ごとの最大化が支配的な領域で、もう 1 つはグローバル バランシングが支配的な領域です。 最初のレジームでは、9 を貪欲に使用することが最適です。これより小さい桁は、後で構造上の利点を補うことなく寄与を厳密に削減することになるからです。 2 番目の方式では、これ以上 9 ペアは不可能であるため、残された唯一の自由度は、小さな残差和を分割する方法であり、等しい分割により積が最大化されるという既知の不等式により、最良の最終値が保証されます。 このアルゴリズムは以前の決定を再検討することはなく、各ステップでローカル数字値とグローバル ペアリング構造の両方の最適性を維持しながら、残りの合計を厳密に削減します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = int(input().strip())

    a = []
    b = []

    while s >= 18:
        a.append(9)
        b.append(9)
        s -= 18

    if s > 0:
        x = s // 2
        y = s - x
        a.append(x)
        b.append(y)

    # Depending on the original task, we either output arrays or derived value.
    # Here we output the arrays as space-separated numbers.
    print(len(a))
    print(*a)
    print(*b)

if __name__ == "__main__":
    solve()
```コードの最初の部分は、可能な最大チャンク (両方の配列に 9 を配置することに相当する 18) を繰り返し消費します。 これは、9 が手頃な価格でありながら常に最適であるという貪欲な観察を直接実装しています。 

残りの合計が 18 を下回ると、コードはバランス スプリットに切り替わります。 表現`s // 2`そして`s - x`2 つの値の差が最大 1 つであることを確認し、固定合計の最適性条件に一致します。 

各反復で残りの合計が一定量減少し、バックトラッキングが必要ないため、構築は線形です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = int(input().strip())

    a = []
    b = []

    while s >= 18:
        a.append(9)
        b.append(9)
        s -= 18

    if s > 0:
        x = s // 2
        y = s - x
        a.append(x)
        b.append(y)

    return str(len(a)) + "\n" + " ".join(map(str, a)) + "\n" + " ".join(map(str, b)) + "\n"

# small cases
assert run("1") == "1\n0\n1\n"
assert run("18") == "1\n9\n9\n"
assert run("19") == "2\n9 0\n9 1\n"

# medium case
assert run("25") == "2\n9 3\n9 4\n"

# larger case
assert run("40") == "3\n9 9 1\n9 9 1\n"

 ## 特殊なケース

 入力の合計が 18 より小さい場合、アルゴリズムは貪欲ループを完全にスキップし、ただちに平衡分割を実行します。 たとえば、入力 7 では、9 ペアは形成されません。 最後のステップでは 3 と 4 を計算し、配列が可能な限り等しくなるようにします。 

合計がちょうど 18 の場合、ループは 1 回実行され、剰余はゼロになります。 最後の分割はスキップされ、単一の 9 のペアが生成されます。これは、残りの予算が存在しないため、正しいです。 

合計が 37 など、18 の倍数をわずかに超える場合、アルゴリズムは 36 を消費する 2 つの完全な 9 ペアを形成し、残りの 1 を (0,1) に分割します。 これにより、以前の貪欲な選択の構造を壊すことなく、非常に小さな残余バジェットでも処理されることが保証されます。
