 ## 解決策
 ## 問題の理解

 位置 0 から位置までの直線が与えられます。$a$。 Polycarp は一度に 1 ユニットずつ右にのみ移動します。 この線上のいくつかのばらばらの区間は雨が降っており、雨の区間内に完全に含まれる端を横断する場合、その部隊の移動中に少なくとも 1 本の傘を携行しなければなりません。 

傘は特定の位置に置かれ、それぞれに重みが付いています。 ポリュカルプはいつでも瞬時に傘を拾ったり落としたりすることができ、一度に複数の傘を持ち運ぶことができます。 1本を移動するのにかかる費用は、現在運んでいる傘すべての重さの合計となります。 課題は到達することです$a$総累積コストを最小限に抑えながら、雨の制約を尊重して 0 から開始します。 

重要な問題は、傘は単なる二項対立のツールではないということです。 より多くの傘を持ち歩くと常にコストが高くなりますが、雨のときに傘を1本持っていなければならない場合もあります。 実際に決定するのは、雨が降る地域ごとにどの傘を持ち歩くべきか、そして可能な場合は傘を切り替えるか、濡れた状態を保つかです。 

制約$a \le 2000$そして$m \le 2000$位置に関する二次または二次に近い動的計画法ソリューションを直ちに提案します。 傘の選択は将来の雨のセグメントに依存するため、局所的な貪欲な決定による線形スキャンは信頼できません。 

微妙な失敗例は、旅の途中で傘を切り替えると有益ですが、局所的には明らかではない場合に発生します。 たとえば、軽い傘が遠くでしか使えず、重い傘が近くにあるとします。 最も近い傘を選ぶという貪欲な選択は、長雨の直前により良い傘が現れた場合には失敗します。 

もう 1 つの特殊なケースは、乾いたギャップで区切られた複数の降雨期間にわたって重複する決定から発生します。 間隔ごとに決定をリセットする単純な戦略は失敗します。次の降雨境界での切り替えコストを回避するのであれば、乾いた隙間に傘を持ち運ぶことが依然として最適である可能性があるためです。 

## アプローチ

 強引な解釈では、あらゆる位置で、ポリカルポスが運んでいる傘のどのサブセットを考慮することになります。 あるので$m$傘、これは次のことにつながります$2^m$状態と遷移は、傘を拾うか落とすかによって決まります。 ある時点で「関連する傘」に限定したとしても、依然として指数関数的な可能性が残されています。 以上のコストの蓄積$a \le 2000$手順により、これは完全に不可能になります。 

重要な観察は、いつでも、すでに手の届く範囲で最も軽い傘だけが重要であるということです。 コストは加算され、雨の制限には少なくとも 1 本の傘しか必要ないため、複数の傘を持ち歩くことは決して役に立ちません。 したがって、どの位置でも、どの傘が現在利用可能で、どの傘がアクティブであるかを知ることで、最適な戦略を特徴付けることができます。 

私たちは問題を位置をめぐる動的プログラミングに変換し、現在使用可能な最適な傘の知識を使用して各位置に到達するための最小コストを追跡します。 各位置で傘が利用可能になり、雨の制約によって少なくとも 1 つのアクティブな傘が必要かどうかが決まります。 

これは古典的な「セグメント制約のあるライン上の DP」の問題になり、遷移はアクティブな傘のセットを維持し、必要に応じて最小コストの傘を選択することに依存します。 この構造により、位置ごとにその時点から使用できる最適な傘を事前に計算し、雨が降り始めたり終わったりしたときに更新する DP を実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | アンブレラサブセットに対するブルートフォース |$O(2^m \cdot a)$|$O(2^m)$| 遅すぎる |
 | 最適な傘の選択による DP オーバーポジション |$O(a \log m)$または$O(a + m)$|$O(a)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を 0 から 0 までの整数位置に圧縮します。$a$。 ポジションごとに、次のステップが雨かどうか、またどの傘が利用できるかを知る必要があります。 

1. 差分配列上のすべての雨のセグメントをマークして、各エッジを計算できるようにします$[x, x+1]$雨が降っているかどうか。 これにより、そのステップ中に少なくとも 1 本の傘を持ち歩く必要があるかどうかが決まります。 
2. 傘はその場所に到着したときにすぐに利用できるようになるため、傘の位置ごとにグループ化して保管します。 
3. DP 状態を定義する$dp[x]$ポジションに到達するための最小コストとして$x$。 初期化する$dp[0] = 0$、その他はすべて無限大です。 
4. 重量の点でこれまでに入手可能な最高の傘を表すデータ構造を維持します。 すでに渡した傘を選択する可能性があるため、この構造は増分挿入と最小重みのクエリをサポートする必要があります。 
5. 位置を 0 から$a-1$。 それぞれのポジションで$x$にあるすべての傘を考慮してください。$x$そしてその重りを利用可能な傘の構造に挿入します。 
6. エッジかどうかを判断します。$x \to x+1$雨が降っています。 雨が降っていなければ傘を持たずに移動できるので移動します。$dp[x+1] = \min(dp[x+1], dp[x])$。 
7. 端が雨なら、傘を選ばなければなりません。 可能な限り最良の選択は、これまでに入手可能な最小重量の傘です。 存在しない場合、移行は不可能です。 
8.雨天の場合は更新します$dp[x+1] = \min(dp[x+1], dp[x] + w)$、 どこ$w$利用可能な傘の最小重量です。 
9. 位置まで続けます$a$。 答えは$dp[a]$、 または$-1$到達できない場合。 

### なぜ効果があるのか

 どのポジションにおいても、唯一重要な決定は、次のステップで傘を持ち歩くかどうかです。 雨が降っていない場合、何かを運ぶとコストが増加するだけなので、最適化により何も運ばなくなります。 雨が降っている場合、実現可能な解決策は少なくとも 1 本の傘を携行する必要があり、その時点までに利用可能なすべての傘の中で、コストが携行重量に比例し、切り替えによるペナルティがないため、最小重量を選択することがすべての選択肢を支配します。 将来の決定は現在の立場とすでに到達可能な一連の傘にのみ依存し、それを超えた歴史的な選択には依存しないため、DP 状態で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, n, m = map(int, input().split())

    rain = [0] * (a + 2)
    for _ in range(n):
        l, r = map(int, input().split())
        for x in range(l, r):
            rain[x] = 1

    umbrellas_at = [[] for _ in range(a + 1)]
    for _ in range(m):
        x, p = map(int, input().split())
        umbrellas_at[x].append(p)

    INF = 10**30
    dp = [INF] * (a + 1)
    dp[0] = 0

    import heapq
    pq = []
    for x in umbrellas_at[0]:
        heapq.heappush(pq, x)

    for x in range(a):
        if dp[x] == INF:
            continue

        for w in umbrellas_at[x + 1 if x + 1 <= a else x]:
            heapq.heappush(pq, w)

        if rain[x] == 0:
            dp[x + 1] = min(dp[x + 1], dp[x])
        else:
            if pq:
                dp[x + 1] = min(dp[x + 1], dp[x] + pq[0])

    return dp[a] if dp[a] < INF else -1

if __name__ == "__main__":
    print(solve())
```この実装では、各動きを個別に分類できるように、単位エッジごとにブール型の雨インジケーターが構築されます。 傘は位置ごとに保存され、右に移動するにつれて最小ヒープに挿入されるため、現時点で入手可能な最も安価な傘が常にわかります。 

DP アレイは、各座標に到達するまでの最小限の疲労を追跡します。 移行は、次のセグメントが雨かどうかによってのみ決まります。 収集されたアンブレラの中でグローバル最小の重みだけが必要であり、重みは決して変更されないため、ヒープがポップされることはありません。 

微妙な点は、アンブレラは最適な戦略で選択されると事実上永続的になるため、ヒープから要素を削除する必要がないことです。

 ## 特殊なケース

 重要なエッジ ケースは、位置 0 から雨が降り始める場合です。この場合、アルゴリズムは、移動する前にすぐに傘を必要とします。 DP はこれを正しく処理します。位置 0 では、使用可能なすべての傘が最初の遷移の前にすでに挿入されているため、最初から最小ウェイトが使用されます。 

もう 1 つのケースは、雨がセグメント全体を覆っているが、傘が散乱している場合です。 ヒープにより、より優れたアンブレラが遅れて登場した場合でも、以前のセグメントではその時点で利用可能な最良のものが使用され、DP が正しく蓄積されることが保証されます。 

3 番目のケースは、傘は存在するが、最初の雨が降る前に傘が届かない場合です。 このシナリオでは、最初に必要な遷移時にヒープが空であるため、dp 更新は発生せず、エンドポイントに到達できないままになり、正しく -1 が生成されます。
