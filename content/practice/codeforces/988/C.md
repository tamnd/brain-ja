 ## 解決策
 ## 問題の理解

 いくつかの独立した整数配列が与えられます。 各配列から要素を 1 つだけ削除することができ、これによりその配列の「修正された合計」が作成されます。これは、元の合計から削除された要素を差し引いたものを意味します。 タスクは、2 つの異なる配列を選択し、結果として得られる修正された合計が等しくなるように、それぞれで 1 つの削除位置を選択することです。 

これをより構造的な方法で言い換えると、シーケンスごとにその合計を計算することができ、その中のすべての要素は、合計からその要素を減算することによって得られる候補値を定義します。 問題は、同じような候補値を生成できる 2 つのシーケンスを見つけることに帰着します。 

制約は非常に特殊な点で厳しいです。 すべてのシーケンスにわたる要素の合計数は最大 200,000 であり、最大 200,000 のシーケンスが存在する可能性があります。 シーケンスのすべてのペアを直接比較しようとするソリューションでは、シーケンスの数における二次的な動作が必要になりますが、これは実行可能な制限をはるかに超えています。 全長が長いため、シーケンスごとの 2 次演算も許可されません。 これにより、すべての要素にわたって線形または線形に近い集計戦略が推進されます。 

単純な落とし穴は、問題を「すべての可能な除去を個別に比較することによって 2 つのシーケンスを一致させる」ものとして扱うことから発生します。 たとえば、シーケンスごとに削除後のすべての合計を生成し、それらをグローバルに照合しようとすると、同じターゲット合計が 1 つのシーケンス内で複数回出現する可能性があること、および選択した 2 つの削除が異なるシーケンスからのものであることを確認する必要があることを忘れる可能性があります。 

シーケンスごとに最適な除去のみを保存するか、シーケンスごとに一意の合計のみを考慮する場合、別の微妙な失敗ケースが発生します。 のようなシーケンス`[1, 1, 1]`同じ候補の合計が複数回生成されるため、多重度を無視すると、有効な一致が除外される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。シーケンスごとに、各要素を削除して結果の合計を計算し、シーケンスのすべてのペアとそれらの可能なすべての削除を比較します。 合計要素を N で表すと、各シーケンスは O(n_i) 個の候補を提供するため、全体では O(N) 個の候補が存在しますが、シーケンス間でそれらをペアリングすると、最悪の場合、O(N^2) 個の比較が行われます。 

これは、すべての有効な答えが「1 つの要素を削除した後の合計」値のこの完全なセットのどこかに存在する必要があるため、概念的に機能します。 障害点はスケールにあります。要素が 200,000 個ある場合、二次比較では 10^10 のオーダーの演算が行われます。 

重要な観察は、各候補が 2 つの値によって完全に決定されることです。シーケンスの合計 S と要素 a が削除され、値 S − a が生成されます。 すべての候補を展開する代わりに、要素を 1 つずつ処理し、これらの値の衝突をグローバルに検出しようとすることができます。 

「削除後の目標合計」からそれを生成する最初のペア (シーケンス インデックス、要素インデックス) までのハッシュ マップを維持します。 同じターゲットが別のシーケンスから 2 回目に出現すると、すぐに有効な答えが得られます。 

これにより、問題は要素ごとに定数時間ハッシュを使用してすべての要素にわたる単一パスに変換されます。

 ## アルゴリズムのチュートリアル

 すべての要素を、それが削除された場合の潜在的な「結果の合計」を定義するものとして扱います。 

### ステップ

 1. 各シーケンスの合計を計算します。 

これが必要なのは、すべての候補値がシーケンスの合計から要素を減算することに依存するためです。 
2. すべてのシーケンス i と位置 x のすべての要素 a について、値を計算します。 

S_i − a。 

これは、その要素を削除した後に残る合計を表します。 
3. キーがこの計算値であり、値がどのシーケンスとどのインデックスが最初に生成したかを示すペア (i, x) を格納するハッシュ マップを維持します。 

衝突を検出するだけでよいため、最初の発生のみを保存します。 
4. 反復中に、マップ内にすでに存在する値を計算し、それが別のシーケンスからのものである場合、保存されている両方の位置をすぐに返します。 

これにより、同じ換算和を生成する 2 つの異なるシーケンスが見つかったことが保証されます。 
5. すべての要素を処理して衝突が見つからなかった場合は、NO を出力します。 

### なぜ効果があるのか

 すべての有効な解は、S_i − a[i][x] = S_j − a[j][y] を満たす 2 つのシーケンス i と j および i の要素 x と j の要素 y が存在するような値 V に対応します。 私たちのマップには、確認されたすべてのペア (V → 最初の出現) が保存されます。 重複した V が別のシーケンスから初めて出現すると、必要な等価性が正確に得られます。 考えられる削除はすべて 1 回だけ処理されるため、有効な回答が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    
    seq = []
    total = []
    
    for i in range(k):
        n = int(input())
        arr = list(map(int, input().split()))
        seq.append(arr)
        total.append(sum(arr))
    
    seen = {}
    
    for i in range(k):
        arr = seq[i]
        S = total[i]
        for j, val in enumerate(arr):
            key = S - val
            if key in seen:
                pi, pj = seen[key]
                if pi != i:
                    print("YES")
                    print(pi + 1, pj + 1)
                    print(i + 1, j + 1)
                    return
            else:
                seen[key] = (i, j)
    
    print("NO")

if __name__ == "__main__":
    solve()
```解決策は、すべてのシーケンスを読み取り、それらの合計を事前に計算することから始まります。そうしないと、合計の計算を繰り返すと複雑さが増大するからです。 次に、メイン ロジックはすべての要素を 1 回反復して、候補の削減された合計を計算します。 

ハッシュマップ`seen`各候補値の最初の出現を格納します。 異なるシーケンスから重複が出現した場合、すぐに 2 つの位置を出力します。 インデックス チェックにより、要素が同じシーケンス内の別の要素と一致しないことが保証されます。これは、2 つの異なるシーケンスを選択するという要件に違反します。 

実装の微妙な詳細の 1 つは、内部的には 0 から始まるインデックスを格納しますが、この問題では 1 から始まる出力が期待されるため、1 から始まるインデックスを出力することです。

 ## 特殊なケース

 重要なエッジ ケースは、同じシーケンス内の複数の要素が同一の候補合計を生成する場合です。 例えば、`[1, 1, 1]`同じ減算和を 3 回計算します。 このアルゴリズムは最初に出現したもののみを保存しますが、その後の重複も処理し、必要に応じて他のシーケンスと照合できるようにします。 

もう 1 つのケースは、単一シーケンス内でのみ衝突が発生する場合です。 考慮する`[2,2]`そして`[1,3]`。 値 2 が最初のシーケンスに 2 回現れますが、これは有効な答えを形成しません。 小切手`pi != i`誤検知を防ぎます。 

最後のケースは、シーケンスが大きいが一致するものが存在しない場合です。 このアルゴリズムは依然として初期の仮定なしで完全な線形スキャンを実行し、ハッシュ マップは O(N) によって制限されたままであるため、最悪の場合の入力でも予測可能な動作が保証されます。
