 ## 解決策

 ## 問題の理解

 学生のリストが与えられ、各学生には評価値が与えられます。 タスクは、正確にサブセットを選択することです。`k`選ばれた 2 人の学生が同じ評価を共有しないように学生を配置します。 出力は評価そのものではなく、元のリストで選択された学生のインデックスです。 

したがって、問題は、値を収集するまで、これまでに見たことのない位置を選択しながら配列をスキャンすることになります。`k`有効なインデックスがないか、個別の値が不足します。 

制約は非常に小さいです。`n ≤ 100`そして`a_i ≤ 100`。 これにより、高度なデータ構造や最適化の必要性が即座に排除されます。 二次スキャンまたは単純な線形スキャンでも十分です。 セットでの 1 回のパスで十分です。 

答えが存在しない唯一の状況は、配列に含まれる内容が以下の場合です。`k`明確な価値観。 そうなるとどうやって生徒を選んでもサイズに達しない`k`評価を明確に保ちながら。 

配列内で重複が多数を占める場合、微妙なエッジケースが発生します。 たとえば、すべての値が同一である場合、`k > 1`、すぐに拒否しなければなりません。 もう 1 つのケースは、重複は存在するが、十分な個別の値が配列の後半に散在している場合です。 貪欲スキャンでは、すべての個別の値を選択し、順序付けの仮定によって早期に行き詰まらないようにする必要があります。 

## アプローチ

 強引な解釈では、サイズのすべてのサブセットを試すことになります。`k`選択したすべての値が異なるかどうかを確認します。 これには、次の組み合わせをチェックすることが含まれます。`n`選ぶ`k`、そしてサブセットごとに一意性を検証し、小さなものであっても爆発につながります`n`。 最悪の場合、サブセットの数は 2ⁿ 程度であり、固定サイズ k に制限しても O(nᵏ) の動作が得られますが、これはこの問題には不必要です。 

問題の構造は、グローバルに検索する必要がないという、より単純な観察を示唆しています。 必要なのはどれかだけです`k`明確な価値観。 有効なサブセットを出力できるため、左から右に貪欲にスキャンして、それぞれの新しい評価の最初の出現を選択できます。 これが機能するのは、選択の順序は重要ではなく、その値が以前に使用されていない限り、すべてのインデックスが同様に有効であるためです。 

ブルート フォースは無関係な組み合わせを探索するため失敗しますが、貪欲なソリューションは一意性が段階的に強制できるローカルなプロパティであるため機能します。

 ## アルゴリズムのチュートリアル

 すでに使用した評価を追跡しながら、段階的に回答を作成します。 

1. 空のセットを初期化する`used`すでに選択した評価と空のリストを保存します`ans`選択したインデックスを保存します。 一定時間内で一意性を確認するにはセットが必要です。 
2. インデックスから生徒を反復処理する`1`に`n`。 各学生について、評価がすでに行われているかどうかを確認します。`used`。 このチェックにより、個別の値のみが選択されることが保証されます。 
3. 評価が使用されていない場合は、この生徒のインデックスを`ans`評価を中古としてマークします。 私たちは事実上、この生徒を評価の代表者としてコミットしていることになります。 
4. 次の場合は早めに中止してください。`ans`サイズに達する`k`。 その時点で私たちはすでに有効なチームを持っており、継続しても正しさは変わりません。 
5. ループ後、次のことを確認します。`ans`サイズがあります`k`。 そうでない場合は、遭遇した件数が以下であることを意味します。`k`アレイ全体で個別の評価が行われるため、有効なチームを形成することは不可能です。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`used`常に、次の形式で表される一連の評価が正確に含まれます。`ans`。 生徒を追加するたびに、これまでにない評価が導入され、選択されたすべてのインデックスが個別の値に対応することが保証されます。 すべての要素を処理するため、要素が少ない場合は、`k`個別の評価が存在する場合、アルゴリズムはサイズに達することなく配列を使い果たしてしまいます。`k`、不可能であることを正しく知らせます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

used = set()
ans = []

for i in range(n):
    if a[i] not in used:
        used.add(a[i])
        ans.append(i + 1)
        if len(ans) == k:
            break

if len(ans) < k:
    print("NO")
else:
    print("YES")
    print(*ans)
```このソリューションは、表示された評価を追跡するためのセットと、選択されたインデックスを保存するためのリストを使用します。 十分な個別の要素を収集すると、ループは早期に停止します。これにより、不必要な作業が回避されますが、制約が小さいため、正確性を確保するためには必要ありません。 

インデックス作成は出力によって慎重に処理されます。`i + 1`この問題では 1 から始まるインデックスが使用されているためです。

 ## 特殊なケース

 すべての生徒が同じ評価を共有する場合、アルゴリズムは配列を使い果たす前にインデックスを 1 つだけ追加します。 入力用`n = 4, k = 2, a = [7,7,7,7]`、`used`になる`{7}`そして`ans = [1]`。 ループが終了すると、サイズチェックは失敗し、アルゴリズムは正しく出力します。`"NO"`。 

配列に正確に含まれる場合`k`明確な値、たとえば`1 2 3`と`k = 3`、反復ごとに新しいインデックスが追加されます。 アルゴリズムがサイズに達しました`k`最後のステップで正確に停止し、早期に停止し、正しく終了したことを確認します。 

重複した値が別個の値と混合されている場合、次のようになります。`1 2 1 3 2 4`、このセットでは、最初に出現したもののみが寄与することが保証されます。 重複が以前に出現したとしても、十分な個別の値の収集には影響せず、最終結果は有効なままです。
