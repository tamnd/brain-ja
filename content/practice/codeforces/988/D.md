 ## 解決策

 ## 問題の理解

 数直線上に配置された一連の個別の点が与えられます。 タスクは、これらの点をできるだけ多く選択することですが、非常に強力な幾何学的制限があります。選択された点のすべてのペアの距離が正確に 2 のべき乗でなければなりません。 

言い換えると、サブセットを選択した場合、選択した 2 つの位置に対して$a$そして$b$、値$|a-b|$セットに属している必要があります$\{1,2,4,8,16,\dots\}$。 この条件はサブセット全体にわたってグローバルです。つまり、ソートされた順序で隣接する点だけでなく、すべてのペアにも当てはまります。 

出力には、サブセットのサイズだけでなく、実際に選択された座標も含まれます。 

制約$n \le 2 \cdot 10^5$すべてのサブセット、またはサブセット内のすべてのペアを繰り返しチェックするソリューションは除外されます。 二次関数のものはすべて$n$すでに苦戦するだろうし、指数関数的なものは直ちに不可能だ。 

微妙な点は、条件が非常に制限されていることです。 特に、順序によっては、点が 2 の累乗で配置されるだけでは十分ではありません。 有効なサブセットは、すべてのペアごとの距離が同じ 2 のべき乗族に属する構造を形成する必要があり、これにより可能な構成が大幅に制限されます。 

1 つの失敗モードは、連続した差異についてのみ考えることから発生します。 例えば点を取ると$3, 5, 7$、連続した差分は次のとおりです。$2$そして$2$、どちらも 2 の累乗ですが、距離は$7 - 3 = 4$も 2 の累乗なので、これは機能します。 しかし、試してみると$3, 5, 9$、連続差分は$2$そして$4$、両方とも個別には問題ありませんが、ペアでは$9 - 3 = 6$たとえローカルチェックがパスしたとしても、条件が破られます。 

もう 1 つのよくある落とし穴は、サブセットが等差数列や幾何学構造のようなパターンを形成する必要があると想定していることです。 この条件では均一な間隔は必要ありません。 すべてのペアごとの差異のみを制限します。これは、順次というよりも組み合わせによるものです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのサブセットを試して、条件を満たすかどうかを確認します。 各サブセットについて、その要素を並べ替えて、すべてのペアごとの違いを検証します。 これは正しいですが、サブセットの数が次のとおりであるため、直ちに実行できません。$2^n$、そして 1 つのサブセットのコストを確認するだけでも$O(k^2)$。 

より有用な開始点は、頂点が点であり、2 点間の距離が 2 の累乗である場合にエッジが存在するグラフを構築するものとして問題を捉えることです。 タスクは、このグラフ内で最大のクリークを見つけることになります。 

クリークはよく研究されているため、この再定式化は役立ちますが、ここではグラフが非常に構造化されています。エッジは非常に特定の距離にのみ存在し、それらの距離は 2 のべき乗です。 この構造により、任意の密なグラフが表示されるのを防ぎます。 

重要な観察は、大規模なクリークが非常にまれであるということです。 点を並べ替えると、サブセットの最小要素を修正することを考えることができます。 選択された最小の点が$x$。 次に、選択した他のすべての点は距離を置いて配置する必要があります$2^k$から$x$、ただし、それらの点間のすべてのペアごとの差も 2 の累乗でなければなりません。 これにより、セットが大幅に制限されます。いくつかの点を選択すると、それらの間のすべての違いは、非常に小さな構造化されたセット内に存在する必要があります。 

重要な単純化は、有効な最適サブセットには最大広がりが小さい「基本構成」が含まれている必要があり、各点で解を固定し、すべてのペアごとの差を有効に保つ位置にのみ貪欲に拡張できることです。 有効な構造は大きくても恣意的であってはいけないため、各開始点について、2 のべき乗の距離にある少数の候補を探索するだけで済みます。 

これにより、各ポイントを潜在的なアンカーとして試し、そこから 2 の累乗の距離にあるポイントのみをテストするという解決策が得られます。 このような距離の数は、約 31 で制限されます (値が 32 ビット範囲に収まるため)。 各アンカーについて、これらのオフセットを介して到達可能な候補ポイントを収集し、完全なサブセットを検証します。 

重要な隠れた構造は、大規模な有効なサブセットが存在する場合、そのすべての点が、基点から 2 の累乗を繰り返し加算または減算することによって生成されたセット内に存在する必要があるということです。 この構造は、効率的に列挙できるほど十分にまばらです。

 ## アルゴリズムのチュートリアル

 メンバーシップを迅速にチェックできるように、ポイントはセットに保存されると想定します。 

1. すべてのポイントをハッシュ セットに挿入して、存在をテストできるようにします。$O(1)$。 これが必要なのは、すべての候補構造が、生成された値が実際に入力に存在するかどうかのチェックに依存しているためです。 
2. すべての点を反復処理します。$x$答えの開始アンカーとして考えられます。 考え方としては、最適なサブセットには最小の要素があり、すべてのアンカーを試行すれば、それを見逃さないことが保証されます。 
3. 各アンカーについて$x$、で始まる候補サブセットを構築します。$\{x\}$。 
4. 力ごとに$2^k$妥当な制限まで (十分な大きさであるため、$x + 2^k$座標範囲内に留まっている)、$x + 2^k$セットの中に存在します。 存在する場合は、暫定的にサブセットに追加することを検討してください。 
5. このアンカーの候補をすべて収集した後、それらを並べ替えます。 ペアワイズ条件はアンカーからの距離だけでなく、すべての違いに依存するため、並べ替えが必要です。 
6. すべてのペアごとの違いをチェックして、候補サブセットを検証します。 すべての差が 2 の累乗である場合、そのサイズをこれまでの最良の回答と比較します。 

アンカーからの貪欲な構築では依然として無効なサブセットが生成される可能性があるため、検証ステップは不可欠です。 候補を生成するだけであり、正確性を保証するものではありません。 

### なぜ効果があるのか

 有効なサブセットには最小限の要素が必要です$x$。 他のすべての要素は次の距離にあります。$x$、すべてのペアごとの差は 2 のべき乗である必要があるため、これらの点は、一貫した方法でオフセットの 2 のべき乗を加算することによって生成された構造と一致する必要があります。 すべてのアンカーとすべての 2 のべき乗オフセットを列挙することにより、有効な構成が少なくとも 1 つの候補セットに完全に含まれることが保証されます。 最後の検証ステップでは、偶発的に無効な組み合わせが除外され、真のクリークのみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_power_of_two(x):
    return x > 0 and (x & (x - 1)) == 0

def valid(arr):
    m = len(arr)
    for i in range(m):
        for j in range(i + 1, m):
            if not is_power_of_two(abs(arr[i] - arr[j])):
                return False
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = set(a)

    best = []

    # precompute powers of two up to coordinate range
    pw = [1 << i for i in range(32)]

    for x in a:
        cand = {x}

        for p in pw:
            y = x + p
            if y in s:
                cand.add(y)

        cand = list(cand)
        if len(cand) <= len(best):
            continue

        cand.sort()
        if valid(cand):
            best = cand

    print(len(best))
    print(*best)

if __name__ == "__main__":
    solve()
```このコードは、潜在的な点が存在するかどうかを一定時間でチェックできるように、すべての座標のハッシュ セットを構築します。 各アンカーについて、2 のべき乗の距離にあるポイントのみを追加しようとします。これは、そのアンカーを含む有効な構成で表示される唯一の距離を反映します。 

検証関数は、すべてのペアごとの距離を明示的にチェックします。 二次関数ではありますが、小さな候補セットでのみ実行されるため、十分な速度が維持されます。 

実装に関する重要な決定事項は、候補者を以下に制限することです。$x + 2^k$。 これは、有効な構成は参照点からの 2 のべき乗のギャップと一致する必要があるという構造的制約をエンコードします。

 ## 特殊なケース

 重要なエッジ ケースは、連続する整数など、すべての点が非常に近い場合です。 このアルゴリズムでは、正確な 2 の累乗の差のみが考慮されるため、依然として小さな候補セットのみが形成され、偶発的な完全選択が防止されます。 

もう 1 つのエッジ ケースは、ポイントがまばらだが 2 のべき乗に位置合わせされている場合です。$0, 8, 16, 24$。 多くの差は 2 の累乗ですが、16 や 24 などの相互差は 2 の累乗ではない値を作成し、検証ステップでは正しいサブセットを許可しながら誤った展開を拒否します。 

アンカーベースの構築により、すべての有効な構成がその最小要素から確実に検出され、検証ステップにより無効な構造が残らないことが保証されます。
