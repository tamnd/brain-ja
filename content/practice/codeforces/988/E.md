 ## 解決策

 ## 問題の理解

 数字の文字列として表される単一の大きな整数が与えられます。 再配置することはできますが、隣接する交換、つまり各移動が 2 つの隣接する数字を交換することによってのみ可能です。 制約は、スワップのたびに、ゼロから始めることができないという意味で、数値が依然として有効でなければならないということです。 

目標は、可能な限り最小の隣接スワップを使用して、元の数字列を 25 で割り切れる順列に変換することです。 どの桁を並べても 25 で割り切れる数を形成できない場合、答えは -1 になります。 

25 で割り切れる構造は非常に厳密です。数値は、最後の 2 桁が 00、25、50、または 75 のいずれかである場合に限り、25 で割り切れます。この制限により、問題はグローバル再配置タスクから最後の 2 桁のターゲット配置問題に分解されますが、残りの桁は、隣接スワップ コストを考慮する限り任意に配置できます。 

数値は 10^18 で区切られているため、数値の長さは最大 18 です。 このため、どのソリューションでも少数の一定桁の順列に対する階乗のような推論を許容できることが重要になりますが、スワップの繰り返しシミュレーションに関して指数関数的な増加を回避する必要があります。 

素朴だが危険なアプローチは、スワップによって到達可能なすべての置換に対して完全な BFS を試みることです。 18 桁は小さいですが、状態空間は 18 です。 それは大きすぎます。 もう 1 つの魅力的なアプローチは、以前の交換が後の位置にどのような影響を与えるかを慎重に考慮せずに、ターゲットの接尾辞の数字を貪欲に配置することです。 これは失敗します。1 つの数字を所定の位置に移動すると、以前の部分構造が破壊されたり、先頭にゼロがない制約に違反したりする可能性があるためです。 

025 または 050 パターンを形成する場合など、有効なサフィックスのみが先頭にゼロを必要とする場合、微妙なエッジ ケースが発生します。 このような場合、不注意で貪欲に数字を移動すると、誤ってゼロが先頭に押し込まれ、有効な最終構成が存在する場合でも中間状態が無効になる可能性があります。 中間状態はゼロから開始できないという制約により、最終的な配置だけでなく、スワップ中にも順序付けの制約が重要になります。 

## アプローチ

 ブルートフォースのアイデアは、割り算条件を満たすすべての桁の順列を考慮し、それぞれに到達するための最小隣接スワップ コストを計算することです。 固定ターゲット順列の場合、最小隣接スワップ コストは、初期文字列とターゲット順序の間の反転距離に等しくなります。これは、移動をシミュレートするか位置追跡を使用することによって計算できます。 

この強引なアプローチは、有効な最終構成は入力数字の順列であり、隣接するスワップによって任意の順列を別の順列に変換できるため、概念的に機能します。 ただし、順列の数は桁数の階乗になります。 たとえ 18 桁しかないとしても、18 桁であるため、すべての順列を探索することは不可能です。 天文学的に大きいです。 

重要な観察は、25 で割り切れるので、最後の 2 桁の可能性が 4 つのみに制限されるということです。 すべての順列を探索するのではなく、最大 4 つの接尾辞パターンを試行するだけで済みます。 パターンごとに、その接尾辞で終わる最小コストの配置を構築しようとします。 残りの桁は任意の順序で表示できますが、スワップは隣接しているため、必要な桁を最後の 2 桁に移動するコストをシミュレートする必要があります。 

主な技術的ステップは、他の数字の相対的な順序を維持しながら、選択した 2 つの数字を最後の 2 つの位置に移動するために必要な隣接スワップの最小数を計算することです。 これにより、スワップ カウントを追跡しながら、右から左に貪欲にスキャンし、必要な桁を所定の位置に取り込むことになります。

先行ゼロの回避に関する制約は自然に処理されます。結果の配置がゼロで始まる場合は、それを破棄します。 不正な中間プレフィックスを明示的に構築しない限り、中間スワップは常に有効であるため、このチェックは最終的に構築された構成にのみ適用する必要があります。

 ## アルゴリズムのチュートリアル

 数字文字列を直接操作し、00、25、50、75 の中で有効な接尾辞をそれぞれ試行します。 

1. 数値を文字の変更可能なリストに変換して、位置の交換と追跡をシミュレートできるようにします。 この表現により、インデックスの動きを通じて隣接するスワップ コストを推論することが容易になります。 
2. 候補となる接尾語パターンごとに、有効な最終的な配置を構築することを試みます。 このプロセスは、必要な 2 桁を配列の最後の 2 つの位置に移動するものとして処理されます。 
3. 「75」などの特定のサフィックスについては、最初に文字列内で最後の位置に移動できる「5」を見つけます。 今後の混乱を最小限に抑えるために、右から左にスキャンします。 見つかったら、隣接するものと繰り返しスワップすることで、位置 n-1 に移動するのに必要なスワップ数を計算します。 このコストを積み上げていきます。 
4. 最後の桁を配置した後、下から 2 番目の桁 (この場合は「7」) に対して同じプロセスを繰り返しますが、ここでは短縮された有効な配列を操作します。 各スワップ ステップがカウントされ、それに応じて配列が更新されます。 
5. 両方の数字を配置した後、結果の構成がゼロで始まるかどうかを確認します。 そうであれば、制約により中間段階で先行ゼロが禁止されており、有効な変換はこの最終結果を回避する必要があるため、この候補は完全に破棄されます。 
6. 4 つの接尾辞すべてに対してこのプロセスを繰り返し、有効な構成の中で最小コストを取得します。 
7. 有効な変換を生成するサフィックスがない場合は、-1 を返します。 

重要な不変条件は、各ステップで現在の順列状態と元の配列をそれに変換するコストの正確な計算を維持することです。 シミュレートされた配列では常に隣接するスワップによって桁を直接移動するため、コストは実行されたスワップの数に正確に対応します。 

### なぜ効果があるのか

 有効な解決策はそれぞれ 4 つの接尾辞のいずれかで終わる必要があるため、これらのケースに限定しても、有効な回答が除外されるわけではありません。 各サフィックスについて、右端の出現箇所から必要な数字を取得する貪欲な戦略により、以前の配置との干渉が最小限に抑えられ、その固定サフィックスのスワップ カウントが最小限に抑えられます。 隣接するスワップは反転距離に相当するメトリックを定義するため、サフィックスを右から左に構築すると、最適性が局所的に保持され、したがって固定ターゲット パターンごとにグローバルに最適化が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)
    
    targets = [("0","0"), ("2","5"), ("5","0"), ("7","5")]
    INF = 10**18
    ans = INF

    for a, b in targets:
        arr = s[:]
        cost = 0

        def move_to_end(ch, end_pos):
            nonlocal arr, cost
            for i in range(end_pos, -1, -1):
                if arr[i] == ch:
                    for j in range(i, end_pos):
                        arr[j], arr[j+1] = arr[j+1], arr[j]
                        cost += 1
                    return True
            return False

        ok = True

        if not move_to_end(b, n-1):
            continue
        if not move_to_end(a, n-2):
            continue

        if arr[0] == '0':
            continue

        ans = min(ans, cost)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()

有効なシーケンスはゼロで始まらない構成で終了する必要があるため、先頭のゼロのチェックは構築後に適用されます。 失敗すると、そのサフィックスは破棄されます。

 ## 特殊なケース

 重要なエッジ ケースは、00 や 50 を形成するなど、接尾語にゼロが含まれる場合です。このような場合、アルゴリズムが最終検証に注意を払っていない場合、数字を末尾に移動すると、一時的に先頭にゼロが配置される可能性があります。 たとえば、1020 から開始してサフィックス 00 を目指す場合、単純なアプローチではゼロが早めに移動され、構築中に誤って無効なプレフィックスが作成される可能性があります。 このアルゴリズムは、最終的な配置のみを検証し、常に明示的に右から左へ数字を選択することを保証することでこれを回避し、混乱を最小限に抑えます。 

もう 1 つの特殊なケースは、必要な接尾辞の数字が複数回出現する場合です。 たとえば、7005 にはサフィックス 05 の両方の数字が存在しますが、間違ったオカレンスを選択すると、スワップ カウントが不必要に増加する可能性があります。 右から左への選択により、ターゲット位置に可能な限り近い数字が常に選択され、各固定接尾辞構造の交換が最小限に抑えられます。
