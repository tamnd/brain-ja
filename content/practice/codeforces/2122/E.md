 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$2 \times n$いくつかのセルがすでに整数で埋められているグリッド$1$そして$k$、他のセルは空です。 パスが左上のセルから開始され、各ステップで右または下に移動し、常に現在のセルと少なくとも同じ大きさの値を持つセルにステップインする場合、そのパスは貪欲であると定義されます。 私たちの目標は、**すべての長方形のサブグリッド**に、そのサブグリッド内のすべての下/右パスの中で可能な最大の合計を達成する貪欲なパスが存在するように、空のセルを埋めることができる方法が何通りあるかを数えることです。 

入力には複数のテスト ケースが含まれています。 いずれの場合も、次元は 2 行に固定されており、$n$列とすべての合計$n$テスト ケース全体で 500 を超えません。これは、$O(n k^2)$動的プログラミング ソリューション$n \le 500$そして$k \le 500$大まかに意味します$1.25 \cdot 10^8$注意していれば操作は可能ですが、最適化では許容されます。 

単純な実装では、空のセルの可能なすべての充填を列挙し、すべてのサブグリッドをチェックしようとする可能性があります。 これは、たとえ$n = 10$、各空のセルには$k$価値観があるかもしれない$2n$空のセル、$k^{2n}$可能性。 エッジ ケースには、すべてのセルが空であるグリッド、一部の行が最大値で完全に埋められているグリッド、または貪欲なパス条件を満たすために特定の配置によって両方の行の単調性が強制されるグリッドが含まれます。 

たとえば、グリッドについて考えてみましょう。```
-1 -1
1 2
```素朴なアプローチでは上の行を恣意的に埋める可能性がありますが、選択を制限する左上から右下への貪欲なパスが常に存在することを保証する必要があります。 これらの制約を誤って無視すると、無効な構成が多数生成される可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、グリッドの可能なすべての塗りつぶしを生成し、最大のパス合計を達成する貪欲なパスが存在するかどうかをサブグリッドごとに検証します。 これは原理的には機能しますが、空のセルがわずかな数 (たとえば 10 個) であっても、$k^{10}$天文学的に大規模な構成$k \le 500$。 すべてのサブグリッドをチェックすると、これがさらに増大し、このアプローチは維持できなくなります。 

重要な洞察は、貪欲なパス制約が **連続する 2 つの列間のローカル パターン**に帰着するということです。 グリッドには 2 行しかないため、すべての貪欲パスは、下に進んでから右に、右に行ってから下に進むか、1 つの行に沿って直進します。 有効な充填の場合、次のように定義すると、$dp[c][r]$列を埋める方法の数として$c$行で終わる$r$最大パスの場合、遷移は前の列と現在の列の値のみに依存します。 すでに入力されているセルは、貪欲さを維持するために最小値を強制することによって遷移を制約します。 この観察により、列ごとに反復し、最大パスの可能な終了位置のカウントを更新する動的プログラミング アプローチを使用できるようになります。 

この DP は、2 つの行の寄与が対称であることに注目することでさらに最適化できるため、すべての値を明示的に反復するのではなく、許可された値の合計を使用して寄与を計算できます。 これにより、複雑さが軽減されます。$O(n k^2)$に$O(n k)$実際に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^{2n} * n^2) | お(1) | 遅すぎる |
 | コラムDP | O(n k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各ケースを反復処理して抽出します。$n$、$k$、および初期グリッド値。 空のセルを置き換える`-1`自由な選択を表すプレースホルダーを使用します。 
2. 動的プログラミング配列を初期化する`dp[r][v]`行で終わる最大貪欲パスで現在の列までの列を埋める方法の数を表します。`r`価値のあるもの`v`。 セルが空か事前入力されているかに応じて、最初の列を初期化します。 両方が空の場合、すべての値$1..k$許可されています。 一方が事前に入力されている場合、単調性を維持するために、もう一方の行では互換性のある選択肢のみが許可されます。 
3. 列を左から右に繰り返します。 列ごとに更新します`dp`各行と値について、貪欲なパス条件 (つまり、前の値 ≤ 現在の値) を満たす以前のすべての値を合計することによって計算されます。 空のセルの場合は、1 から k までのすべての値を考慮し、必要に応じて塗りつぶされた近傍によって制限されます。 塗りつぶされたセルの場合は、指定された値のみが許可されます。 
4. すべての列を処理した後、次のカウントを合計します。`dp`最後の列の両方の行に対応する値を調べて、有効な塗りつぶしの合計数を取得します。 オーバーフローを避けるために、すべてのステップでモジュロ 998244353 を適用します。 
5. 各テストケースの結果を出力します。 

なぜ機能するのか: 維持される不変条件は次のとおりです`dp[r][v]`行で終わる貪欲なパスのように、これまでに列を埋めるすべての方法を常にカウントします。`r`価値のあるもの`v`存在しており、拡張することができます。 各列は前の列にのみ依存するため、構成を二重にカウントすることはありません。また、列ごとのアプローチにより、**すべてのサブグリッド** が貪欲なパス プロパティを満たすことが保証されます。これは、どのサブグリッドも連続した列のセットであり、DP はすべてのプレフィックスの最大パスのみをカウントするためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(2)]
        dp_prev = [0] * (k + 2)
        dp_curr = [0] * (k + 2)

        # Initialize first column
        for v1 in range(1, k + 1) if grid[0][0] == -1 else [grid[0][0]]:
            for v2 in range(1, k + 1) if grid[1][0] == -1 else [grid[1][0]]:
                if v1 == v2 or v1 < v2 or v2 < v1:
                    dp_curr[max(v1, v2)] += 1
        dp_prev, dp_curr = dp_curr, [0] * (k + 2)

        for c in range(1, n):
            for v in range(1, k + 1):
                dp_curr[v] = 0
            for val_prev in range(1, k + 1):
                if dp_prev[val_prev] == 0:
                    continue
                # possible values for current column
                r1_vals = range(1, k + 1) if grid[0][c] == -1 else [grid[0][c]]
                r2_vals = range(1, k + 1) if grid[1][c] == -1 else [grid[1][c]]
                for v1 in r1_vals:
                    for v2 in r2_vals:
                        if max(v1, v2) >= val_prev:
                            dp_curr[max(v1, v2)] = (dp_curr[max(v1, v2)] + dp_prev[val_prev]) % MOD
            dp_prev, dp_curr = dp_curr, [0] * (k + 2)

        print(sum(dp_prev[1:k+1]) % MOD)

solve()
```最初の列の初期化では、2 つの行で許可される値のすべての組み合わせが考慮され、この列の最大の貪欲パスがカウントされるようになります。 後続の各列は以前の最大値を反復し、互換性のあるすべての現在値まで拡張します。 モジュロ演算により、整数の制限内に確実に収まるようになります。 空のセルは全範囲にわたって反復することによって処理されますが、事前に入力されたセルは選択肢を 1 つの値に制限し、正確さを維持します。
