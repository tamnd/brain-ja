 ## 解決策
 ## 問題の理解

 この問題は、接続された単純な無向グラフを次のように記述します。`n`頂点と`m`エッジ。 トークンは頂点から始まります`1`時に`0`。 整数秒ごとに`t`、トークンが頂点にある場合`u`、次の 2 つの選択肢があります: で 1 秒待つか`u`、または特定のエッジに沿って移動します。`u`。 使用できるエッジは次のように決まります。`(t mod deg(u)) + 1`、 どこ`deg(u)`頂点の次数です`u`また、エッジは入力に現れる順序でインデックス付けされます。 待機または移動の各アクションには、ちょうど 1 秒かかります。 

タスクは、頂点からトークンを移動するのに必要な最小合計時間を見つけることです。`1`頂点へ`n`、この最小合計時間を達成するすべての戦略の中で、合計待機時間を最小にする戦略。 

入力では複数のテスト ケースが可能です。 各グラフには最大で`5000`すべてのテスト ケースの合計頂点数、最大`5·10^5`エッジの合計。 これは、時間計算量のあるアルゴリズムが`O(n·m)`またはそれよりわずかに高い値も実現可能ですが、テスト ケースごとの二次関数は簡単に時間制限を超える可能性があります。 モジュロベースの動作では、時間依存のエッジ制約が導入されるため、標準の BFS やダイクストラのような単純な最短パス アルゴリズムをそのまま使用することができなくなります。 

エッジ ケースには、モジュロ次数が目的のパスと一致しないため、頂点に到達するまで待機する必要があるグラフが含まれます。 たとえば、次数の頂点`2`ターゲット頂点に接続すると、「正しい」エッジが使用可能になるまで数秒待つ必要がある場合があります。 もう 1 つの微妙なケースは、最適なパスに 2 つの頂点間を往復して時間を将来の移動と同期させることが含まれる場合に発生します。 モジュロ制約を無視した単純な BFS は、このようなシナリオでは失敗します。 

## アプローチ

 ブルート フォース アプローチでは、BFS を使用して、考えられるすべてのパスと待機中のすべての決定をシミュレートします。`(vertex, time)`州。 現在の時間と頂点を考慮すると移動は決定論的であるため、これは機能しますが、状態の数は急速に増加します。単純な BFS では理論的には時間に制限がなく、たとえ次のように制限したとしてもです。`n*m`、状態の数が多すぎて、`n=5000`そして`m≈10^5`。 

重要な洞察は、モジュロベースのエッジ選択により、各頂点に対する発信エッジの決定論的なスケジュールが作成されるということです。 これにより、次の状態が頂点だけでなく、頂点の次数を法とする時間にも依存する、修正された BFS として問題をモデル化することができます。 具体的には、頂点については、`u`と`deg(u)`エッジの場合、モジュロで時間を追跡するだけで済みます。`deg(u)`各頂点ごとに、`deg(u)`パターンが繰り返される秒数。 したがって、私たちは保管します`dist[u][r]`到達までの最小合計時間として`u`いつ`t % deg(u) == r`。 状態のキューを使用して BFS を実行できます`(vertex, time, wait)`合計時間と累積待機時間の両方を伝播します。 

このアプローチにより、状態の数が次のように減ります。`sum(deg(u))`すべての頂点にわたって、次によって境界が定められています。`2*m`。 各エッジは関連するモジュロ状態に対してのみ緩和されるため、時間計算量はおおよそ次のようになります。`O(m + n)`テストケースごとに、制限内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース BFS オン`(vertex, time)`| O(n_m_max_time) | O(n*最大時間) | 遅すぎる |
 | モジュロ状態の BFS | O(m + n) | O(m + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、指定された順序で各頂点の隣接リストを構築します。 
2. 距離配列を初期化する`dist[u][r]`頂点ごとに`u`そして残り`r`モジュロ`deg(u)`。 を除くすべてのエントリを無限大に設定します。`dist[1][0] = 0`時間 0 の頂点 1 から開始するためです。 
3. BFS キューを開始状態で初期化します。`(1, 0, 0)`、ここで 3 番目の要素は合計待機時間です。 
4. キューが空でない間にポップ`(u, t, wait)`:

 ａ． コンピューティング`r = t % deg(u)`。 

b. 進むべき決定的なエッジは`adj[u][r]`。 このエッジに沿って移動すると、結果としてより小さな値が得られます。`dist[v][(t+1) % deg(v)]`、 押す`(v, t+1, wait)`キューに入れて更新する`dist`。 

c. で待つことを検討してください`u`。 もし`dist[u][(r+1) % deg(u)] > t+1`、 押す`(u, t+1, wait+1)`そして更新します`dist`。 
5. BFS が終了した後、すべての状態のうち頂点に到達`n`、合計時間が最小のものを見つけます。 複数の合計時間が同じ場合は、待ち時間が最小のものを選択します。 
6. 最小合計時間と対応する待ち時間を出力します。 

正確さは、BFS が各頂点の各モジュロ状態の最も早い時間を常に探索するという不変条件に依存します。 待機時間は決定論的に 1 ずつ増加し、移動は決定論的なモジュロ スケジュールに従うため、BFS は最小の合計時間で各状態を訪問することを保証します。 待機を追跡すると、同等の合計時間パス間でのタイブレークが明示的に許可されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        deg = [0] * (n + 1)
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
            deg[u] += 1
            deg[v] += 1
        
        # distance: dist[u][r] = (total_time, wait_time)
        dist = [ [ (float('inf'), float('inf')) for _ in range(deg[u] or 1) ] for u in range(n + 1)]
        dist[1][0] = (0, 0)
        q = deque()
        q.append( (1, 0, 0) )  # vertex, time, wait
        
        while q:
            u, t, w = q.popleft()
            d = deg[u] or 1
            r = t % d
            # move along deterministic edge
            if deg[u] > 0:
                v = adj[u][r]
                nr = (t + 1) % deg[v]
                if (t+1, w) < dist[v][nr]:
                    dist[v][nr] = (t+1, w)
                    q.append( (v, t+1, w) )
            # wait
            nr = (r + 1) % d
            if (t+1, w+1) < dist[u][nr]:
                dist[u][nr] = (t+1, w+1)
                q.append( (u, t+1, w+1) )
        
        # pick best for vertex n
        res = min(dist[n])
        print(res[0], res[1])

if __name__ == "__main__":
    solve()
```このソリューションは、次数を追跡しながら隣接リストを構築します。 の`dist`配列にはタプルが格納されます`(total_time, waiting_time)`モジュロ状態ごとに。 BFS は、すべての状態が最適に訪問されることを保証します。 待機時間は明示的にカウントされ、合計時間とともに伝播されます。 タプルを辞書順に比較します。これにより、必然的に合計時間が短いこと、次に待機時間が短いことが優先されます。
