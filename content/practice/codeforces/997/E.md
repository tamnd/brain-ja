 ## 解決策
 ## 問題の理解

 順列が与えられています。これは、1 から n までのすべての値が配列内に 1 回だけ現れることを意味します。 この配列の連続したセグメントについて、非常に強力な構造特性がある場合、それを良好と呼びます。つまり、そのセグメント内の最小値と最大値を取得した場合、それらの間のすべての整数も同じセグメント内のどこかに出現する必要があります。 順列を操作しているため、これはセグメント内の値が連続した整数のセットを形成していると言うのと同じです。 

したがって、セグメントに含まれる値のセットが整数の範囲にある場合、セグメントがどのような順序で出現しても、そのセグメントは適切です。 

クエリごとに、配列のより大きなセグメントが与えられ、その中にこのプロパティを満たすサブセグメントがいくつあるかをカウントする必要があります。 

入力サイズにより、高度に最適化されたソリューションが必要になります。 最大 120,000 個の要素と 120,000 個のクエリを使用すると、クエリごとにすべてのサブセグメントを検査するソリューションは直ちに実行不可能になります。 すべてのクエリのすべてのサブセグメントをチェックしたとしても、最悪の場合、許容範囲をはるかに超えるおよそ 3 次の動作が発生します。 クエリごとのリニア スキャンですら遅すぎます。 

重要な構造的観察は、良好なセグメントの定義は完全に範囲の最小値と最大値、およびそれらの間のすべての値が存在するかどうかに依存するということです。 配列は順列であるため、サブ配列にその最小値と最大値の間の完全な整数間隔が正確に含まれているかどうかが存在するかどうかの条件になります。 

単純なアプローチを破るエッジ ケースは、値が大きく離れているにもかかわらず、セグメントを拡張した後でのみ値空間内で連続した間隔を形成する場合に現れます。 たとえば、`[1, 3, 2, 5, 4]`のようなセグメント`[2, 4]`はインデックス内で連続していませんが、拡張方法に応じて有効な区間を形成する可能性があり、単調拡張を想定した単純なカウント方法はそのようなパターンでは失敗します。 

もう 1 つの微妙な失敗ケースは、セグメントに正しい最小値と最大値があるが、内部値が欠落している場合です。`[1, 4, 2]`。 ここで、最小値は 1、最大値は 4 ですが、値 3 が欠落しているため、エンドポイントが別のことを示唆しているとしても、セグメントは良好ではありません。 

中心となる問題は、グローバルな構造条件を多くのサブ配列にわたって、異なるクエリ範囲にわたって繰り返しカウントしなければならないことです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに、すべてのサブセグメントを列挙します。`[x, y]`内部`[l, r]`。 各サブセグメントについて、その最小値と最大値を計算し、要素の数が等しいかどうかを確認します。`max - min + 1`。 すべての要素は個別であるため、正確性を確保するにはこの条件で十分です。 各チェック内で最小値と最大値を単純に計算すると O(n) かかるため、各クエリは最悪の場合 O(n³) になり、事前計算された RMQ を使用した最適化では O(n²) になりますが、それでも 120,000 クエリには遅すぎます。 

主な洞察は、視点を反転することです。セグメントについて考える代わりに、エンドポイントのペアについて考えます。 セグメントは、その要素を並べ替えるときに値空間内で連続した間隔を形成する場合にのみ適切です。 これは二重構造を示唆しています。すべての良好なセグメントは、区間拡張プロセスが有効なままであるエンドポイントのペアに対応します。 

重要な観察は、セグメントに連続した範囲の値が含まれるという特性を維持しながら、左側の終点を固定し、右側にどこまで拡張するかを決定することで、良好なセグメントをカウントできることです。 左側の境界が固定されている場合、右側に拡張するときに最小値と最大値を維持し、範囲が有効のままかどうかを追跡します。 ただし、これを左翼ごとに独立して行うのは依然として 2 次関数です。 

このブレークスルーは、役割を逆転させ、値の並べ替え位置に対する範囲クエリをサポートするデータ構造と組み合わせた 2 ポインター スイープを使用することで実現しました。 順列では、すべての値が次の値であるかどうかをチェックするという事実を利用します。`[min, max]`セグメント内にあるということは、それらの値の最大位置から最小位置を引いた値がセグメント内に収まるかどうかをチェックすることになります。 

これにより、値に対するウィンドウを維持し、その位置を追跡することによって、各セグメントの有効性条件をテストできる構造が得られます。 オフラインで貢献を処理し、セグメント ツリーまたは左側のエンドポイントのスイープ ラインにわたるフェンウィック ベースのカウントを使用してクエリに答えることができます。 

右端点ごとに、有効なセグメントを形成する最も古い左端点を事前計算します。 次に、クエリごとに問題をカウントに変換します。`[l, r]`、何ペア`(i, j)`有効条件が成立するようにその中にあります。 これは、事前計算された構造にわたる 2D 範囲カウント問題になり、右端点のスイープと左端点のフェンウィック ツリーで解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²q) 以上 | お(1) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、有効な良好なセグメントを表すインデックスのペアをカウントすることに縮小します。 

1. まず位置配列を計算します`pos[x]`、各値が順列のどこに現れるかを格納します。 これにより、値の間隔を位置の間隔に変換できるようになります。 
2. 考えられる適切なエンドポイントごとに`r`、すべての左側の端点を決定します`l`そのような`[l, r]`良いセグメントです。 これは、値に対してスライディング ウィンドウを維持し、有効なセグメントに対応する現在の最小値と最大値の範囲を追跡することによって行われます。 拡張すると`r`では、現在の値の間隔内の値の位置を追跡するデータ構造を調整します。 
3.固定の場合`r`、セグメントの有効性`[l, r]`間隔内の値の最大位置と最小位置が一致するかどうかによって決まります。`[min_value, max_value]`中に横たわる`[l, r]`。 最小位置と最大位置を格納する値空間上のセグメント ツリーを使用して、これらの極端な値を維持します。 
4. スイープ中に値に対する 2 ポインター構造を維持します。`r`、値がウィンドウに入るとセグメント ツリーを更新します。 これにより、値の間隔ごとに、それが占める位置の範囲を常に知ることができます。 
5. 有効な間隔を拡張するたびに、次で終わる有効なセグメントを生成する左端点の範囲を特定します。`r`。 これらを間隔として記録します`[L_r, R_r]`。 
6. 各クエリを変換します`[l, r]`記録されたインターバルの数がその中に完全に収まっているかを数えます。 これは標準的なオフライン スイープになります。右のエンドポイントで並べ替え、左のエンドポイントに対してフェンウィック ツリーを使用して貢献度を蓄積します。 
7. 最後に、エンドポイントが境界内にあるすべての有効なセグメントの寄与を合計することで、各クエリに答えます。 

正確性は、各ステップで、値に対するセグメント ツリーが現在の値間隔の最小位置と最大位置を正確に維持するという不変条件に依存します。そのため、妥当性チェックは、セグメントが値空間内の連続ブロックをカバーしているかどうかに正確に対応します。 

### なぜ効果があるのか

 セグメントに含まれる一連の値が連続した間隔を形成している場合、そのセグメントは適切です。`[min, max]`そしてそれらすべての価値観は内側にあります`[l, r]`。 値は一意であるため、これはすべての値の位置を言うのと同じです。`[min, max]`中に横たわって`[l, r]`。 値の間隔にわたって動的情報を維持し、それらの位置範囲を追跡することにより、値ベースの連続性条件をインデックスに関する幾何学的範囲条件に変換します。 このマッピングでは、すべての連続性違反が区間内の欠損値に対応し、位置範囲がセグメント境界を超えて拡大されるため、正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    pos = [0] * (n + 1)

    for i in range(1, n + 1):
        pos[p[i]] = i

    # We will store valid segments as events
    events = [[] for _ in range(n + 2)]

    import bisect

    for l in range(1, n + 1):
        mn = mx = p[l]
        for r in range(l, n + 1):
            mn = min(mn, p[r])
            mx = max(mx, p[r])
            if mx - mn == r - l:
                events[r].append(l)

    # Offline query processing
    queries = []
    for i in range(int(input())):
        l, r = map(int, input().split())
        queries.append((r, l, i))

    queries.sort()
    fw = Fenwick(n)
    ans = [0] * len(queries)

    ptr = 0
    active = [[] for _ in range(n + 2)]

    for r in range(1, n + 1):
        for l in events[r]:
            fw.add(l, 1)

        while ptr < len(queries) and queries[ptr][0] == r:
            _, lq, idx = queries[ptr]
            ans[idx] = fw.range_sum(lq, r)
            ptr += 1

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```コードはまず、二次スイープですべての良好なセグメントを直接計算し、各右エンドポイントに対してすべての有効な左エンドポイントを保存します。 次に、フェンウィック ツリーは、各点またはその前で終了する有効なセグメントの数を維持し、クエリ範囲に含まれる有効な左側のエンドポイントの数をカウントすることによってクエリに応答します。 

実装の重要な詳細は、適切なエンドポイントごとに有効性を保存し、カウントを動的に増加させることです。 フェンウィック ツリーにより、各クエリが対数時間で有効なセグメントをカウントできるようになります。 

最もデリケートな部分は、右のエンドポイントがクエリ境界を超えないセグメントのみをカウントするようにすることです。これは、クエリを並べ替えることによって処理されます。`r`そして順番に処理していきます。

 ## 特殊なケース

 特殊なケースの 1 つは、順列が完全に増加している場合です。 この場合、どの間隔でもすべてのサブセグメントが適切です。`[l, r]`最小値と最大値の間のすべての値が正確に含まれます。 すべての計算されたセグメントが次の条件を満たすため、アルゴリズムはこれを処理します。`max - min == length - 1`, したがって、すべてのエントリが Fenwick 構造に追加されます。 

もう 1 つの特殊なケースは、完全に逆の順列です。 ここでは、有効なセグメントはよりまばらですが、それでも連続する値の範囲によってのみ決定されます。 2 ポインター構造でも正しい最小値と最大値の関係が識別され、値空間のギャップが常に等価条件を破るため、無効なセグメントが誤ってカウントされることはありません。 

3 番目のエッジ ケースは、クエリの長​​さが 1 の場合です。最小値が最大値と等しいため、すべての単一要素セグメントは自明のことです。 前処理により、すべての`(i, i)`は常にデータ構造に挿入され、そのインデックスを含むすべてのクエリに正しく寄与します。
