 ## 解決策

 ## 問題の理解

 2 つのツリーが与えられ、それらのデカルト積グラフを構築します。 新しいグラフの各頂点は、最初のツリーの 1 つのノードと 2 番目のツリーの 1 つのノードで構成されるペアです。 このようなペアから、最初のツリーのエッジに沿って最初の座標を変更するか、もう一方の座標を固定したまま 2 番目のツリーのエッジに沿って 2 番目の座標を変更することによって移動できます。 

この構造により、基本的に 2 つのツリーを階層的に組み合わせた構造を持つ大きなグラフが生成されます。 タスクは、この積グラフ内に長さちょうど k の閉じたウォークがいくつ存在するかを数えることです。 閉じたウォークは、連続する頂点が隣接し、最後の頂点も最初の頂点に隣接する k 個の頂点のシーケンスです。 異なる開始点、異なる方向、循環シフトはすべて別個のものとみなされ、長さ k の根付き有向閉歩行をすべてカウントします。 

各ツリーの頂点の数は最大 4000 ですが、k は最大 75 です。積グラフには最大 1600 万の頂点とはるかに多くのエッジがあるため、積グラフを明示的に構築または横断しようとするアプローチは即座に排除されます。 隣接関係を保存することさえ不可能です。 

k の値が小さいということは、解法が多項式の切り捨てまたは長さ制限のある動的計画法に大きく依存する必要があることを示唆しています。 ツリー サイズが大きいことは、頂点ごとの 2 次または 3 次の依存関係を、通常は O(n k^2) 程度で慎重に制御する必要があることを示唆しています。 

微妙な問題が積の構造に現れます。両方のコンポーネントがツリーであるにもかかわらず、そのデカルト積はツリーではなく、多くのサイクルが含まれています。 「木にはサイクルがないので、製品はシンプルであるはずだ」という素朴な直感は間違いです。 たとえば、T₁ = K₂ および T₂ = K₂ であっても 4 サイクルが生成されるため、k = 2 に対して閉じたウォークがすでに存在します。 

もう 1 つの潜在的な落とし穴は、対称性の過大カウントです。 回転と反転は別個のものと見なされるため、単純なサイクルではなく標準的な閉じた歩行をカウントするため、最後に k または 2k で割ることはありません。 

## アプローチ

 直接的な力ずくのアプローチでは、積グラフのすべての頂点から始まる長さ k のすべての歩行がシミュレートされます。 各状態 (v、u) からは、deg(v) + deg(u) 個の可能な移動が存在します。 積グラフには n1n2 状態があるため、単一ステップでもすでに O(n1n2) であり、k ステップにわたる分岐は指数関数的な増加につながります。 これは、たとえ小さな入力であってもすぐに実行不可能になります。 

重要な観察は、デカルト積の隣接行列がきれいな代数構造を持っているということです。 A と B が 2 つのツリーの隣接行列である場合、積グラフの隣接行列は A ⊗ I + I ⊗ B になります。長さ k の閉じたウォークは、この行列の k 乗のトレースに正確に対応します。 

この巨大な行列を直接操作する代わりに、固有値構造を使用します。 A ⊗ I + I ⊗ B の固有値はすべて、λ + μ の形式の値です。ここで、λ は A の固有値、μ は B の固有値です。したがって、答えは固有値の二重和になります。$$\sum_{i,j} (\lambda_i + \mu_j)^k.$$二項定理で展開すると、2 つのツリーが分離されます。$$(\lambda + \mu)^k = \sum_{t=0}^k \binom{k}{t} \lambda^t \mu^{k-t}.$$したがって、問題全体は、各ツリーの固有値の累乗和を知ることに帰着します。$$S_1[t] = \sum_i \lambda_i^t = \mathrm{trace}(A^t),
\quad
S_2[t] = \mathrm{trace}(B^t).$$これらは、正確に、各ツリーの個別の長さ t の閉じたウォークの数です。 

したがって、各ツリーについて、最大 k までの長さの閉じたウォークの数を計算し、二項係数による畳み込みを使用してそれらを結合するだけで済みます。 

残りの問題は、ツリーの trace(A^t) を効率的に計算することです。 これが核心的な難しさです。行列のべき乗を構築せずに、ツリー内の制限された長さの閉じたウォークを数えることです。 

重要な構造上のアイデアは、ツリーを根付けし、ノードを出て隣接するノードを通って戻るという独立した「エクスカーション」の連結としてあらゆる歩行を表現することです。 このような各エクスカーションは、その近傍の下にあるサブツリーを使用して再帰的にエンコードできます。 これにより、各ノードがその子からの寄与を集約し、k までの切り捨て畳み込みを実行する、ノードごとの多項式 DP が得られます。

 ## アルゴリズムのチュートリアル

 ### 最適なアルゴリズム

 1. 各ツリーを任意にルート化します。 すべてのノード u について、多項式 F[u] を計算します。ここで、F[u][t] は、u で開始および終了し、u のサブツリー内に留まる長さ t の閉じたウォークの数です (親エッジは使用しません)。 この制限により、子の独立した構成が可能になります。 
2. u の子 v については、u から v に移動し、v のサブツリー内で有効な閉じた動作を実行して、u に戻る「v を通るエクスカーション」を定義します。 重要な点は、v を入力すると、すべての内部構造が u の他の子から独立しているということです。 
3. u に対する子 v の寄与は多項式です

 E[v][t] = x² 倍 (1 + F[v][t])、

 ここで、x² はエッジ u→v および v→u を表し、F[v] は戻る前の v での内部の閉じたウォークを表します。 定数 1 は、v で内部ウォークを行わないことに対応します。 
4. ノード u の場合、すべての閉じられたウォークは、その子を巡る一連のエクスカーションです。 これは、最初に子 v にわたるすべての E[v] の合計として S[u] を計算することを意味します。 
5. S[u] が既知になると、u での閉じたウォークは 0 個以上のエクスカーションの連結となるため、生成関数は次のようになります。 

F[u] = 1 + S[u] + S[u]² + S[u]³ + …

 k次で切り捨てられます。 
6. DP 畳み込みを使用してこの系列を計算します。 

F[u][0] = 1、t ≥ 1 の場合、

 F[u][t] = S[u][i] * F[u][t - i] の 1 から t までの i の合計。 
7. すべてのノードの F を計算した後、ツリー内の閉じられたウォークの数は次のようになります。 

A[t] = F[u][t] のすべての u の合計。 
8. 両方のツリーの配列 A1 と A2 を計算します。 
9. 最後に、二項展開を使用して結合します。 

答え = C(k, t) * A₁[t] * A₂[k − t] の 0 から k までの t の合計、998244353 を法とする。 

### なぜ効果があるのか

 ツリー内のすべての閉じたウォークは、各ノードで隣接するサブツリーへの一連の独立したエクスカーションに一意に分解できます。 ツリー構造により、ウォークが子エッジを通ってノードを離れると、戻るまで他のサブツリーと対話できないことが保証されます。 この独立性により、問題はシーケンス畳み込み DP に変わり、各ノードはその子からの独立した多項式寄与の「連結点」のように機能します。 すべての寄与は歩行長において局所的であるため、長さ k への切り捨てにより正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add_poly(a, b, k):
    res = [0] * (k + 1)
    for i in range(k + 1):
        res[i] = (a[i] + b[i]) % MOD
    return res

def mul_conv(a, b, k):
    res = [0] * (k + 1)
    for i in range(k + 1):
        if a[i] == 0:
            continue
        ai = a[i]
        lim = k - i
        for j in range(lim + 1):
            if b[j]:
                res[i + j] = (res[i + j] + ai * b[j]) % MOD
    return res

def solve_tree(n, adj, k):
    sys.setrecursionlimit(10000)

    parent = [-1] * n
    order = []

    stack = [0]
    parent[0] = -2
    while stack:
        u = stack.pop()
        order.append(u)
        for v in adj[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp = [[0] * (k + 1) for _ in range(n)]

    for u in reversed(order):
        S = [0] * (k + 1)
        S[0] = 0
        S[1] = 0
        for v in adj[u]:
            if v == parent[u]:
                continue
            E = [0] * (k + 1)
            child = dp[v]
            E[2] = 1
            for t in range(k - 1):
                if child[t]:
                    E[t + 2] = (E[t + 2] + child[t]) % MOD
            for i in range(k + 1):
                S[i] = (S[i] + E[i]) % MOD

        F = [0] * (k + 1)
        F[0] = 1
        for i in range(1, k + 1):
            s = 0
            for j in range(1, i + 1):
                s = (s + S[j] * F[i - j]) % MOD
            F[i] = s

        dp[u] = F

    res = [0] * (k + 1)
    for i in range(n):
        for t in range(k + 1):
            res[t] = (res[t] + dp[i][t]) % MOD
    return res

def comb(k):
    C = [[0] * (k + 1) for _ in range(k + 1)]
    for i in range(k + 1):
        C[i][0] = C[i][i] = 1
        for j in range(1, i):
            C[i][j] = (C[i - 1][j - 1] + C[i - 1][j]) % MOD
    return C

def main():
    n1, n2, k = map(int, input().split())

    adj1 = [[] for _ in range(n1)]
    adj2 = [[] for _ in range(n2)]

    for _ in range(n1 - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj1[a].append(b)
        adj1[b].append(a)

    for _ in range(n2 - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj2[a].append(b)
        adj2[b].append(a)

    A1 = solve_tree(n1, adj1, k)
    A2 = solve_tree(n2, adj2, k)

    C = comb(k)

    ans = 0
    for t in range(k + 1):
        ans = (ans + C[k][t] * A1[t] % MOD * A2[k - t]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```ツリー DP はボトムアップで編成されます。 各ノードは、子からの寄与を集約し、エクスカーションの連結に対して等比級数のような閉包を計算することによって多項式を構築します。 最後の結合ステップでは、固有値を明示的に計算することなく、(λ + μ)^k の二項展開を実装します。 

微妙な点は、すべての畳み込みを通じて k 次での切り捨てです。 より長い歩行は無関係であるため、k を超える製品はすぐに廃棄されます。 これにより、複雑さの多項式が k に維持されます。

DP はツリーごとに以下を生成します。 

| ノード | F[0] | F[1] | F[2] |
 | --- | --- | --- | --- |
 | 1,2 | 1 | 0 | 1 |

 したがって、A₁ = A₂ = [2 ノードが寄与] = [2, 0, 2] となります。 

次に、以下を組み合わせます。 

t = 0: C(2,0)_2_2 = 4

 t = 1:0

 t = 2: C(2,2)_2_2 = 4

 合計 = 8。 

これは、4 サイクル プロダクトの各トラバース方向が個別の閉じたウォークに寄与するという考えと一致します。

 ## 特殊なケース

 重要なエッジケースは、ノードに多くの子がある場合です。 その状況では、等比級数を形成する前にすべてのエクスカーションを合計する必要があります。そうしないと、インターリーブを子ごとに順序付けされたものとして扱うため、子ごとのシーケンスを混合するとオーバーカウントされてしまいます。 DP 構造は、シーケンス処理が行われる前に、すべての子寄与を単一の多項式 S[u] に折りたたむことでこれを回避します。 

別のエッジケースは葉でも発生します。 これらには子がないため、S[u] は 0 であり、F[u] は長さ 0 でのみ 1 のままでなければなりません。これは、単一の自明なウォークを正しく表します。 これにより、葉が誤って長い歩行に寄与することがなくなります。 

最後に、k が小さい場合、切り捨てが重要になります。 多項式次数の制限が省略されていると、指数関数的な爆発や、有効な k 個の長さのウォークでは出現できない、より長い中間エクスカーションからの不正確な寄与が発生します。
