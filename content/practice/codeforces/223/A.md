 ## 問題の理解

 4 つの括弧文字のみで構成される文字列が与えられます。`(`、`)`、`[`そして`]`。 弦は必ずしもバランスが取れているとは限りません。 

この文字列のすべての部分文字列の中から、正しい括弧シーケンスを形成するものを見つける必要があります。 正しい括弧のシーケンスは、通常のネスト ルールを満たす必要があります。つまり、すべての開始括弧が同じタイプの閉じ括弧と一致し、ペアが適切にネストされます。 

目的は、部分文字列の長さを最大化することではありません。 代わりに、最大数の左角括弧を含む有効な部分文字列が必要です。`'['`。 このような部分文字列を見つけた後、次の両方のカウントを出力する必要があります。`'['`その中の文字と部分文字列自体。 

文字列の長さは次のとおりです$10^5$。 二次アルゴリズムでは大まかに調べる必要があります$10^{10}$部分文字列ですが、これは完全に不可能です。 たとえ$O(n^2)$検証戦略は期限をはるかに超えています。 解は線形時間に近いものでなければなりません。 

いくつかの特殊なケースにより、問題は通常の括弧の一致よりも難しくなります。 

考慮する：```
([)]
```部分文字列はバランスの取れた数の括弧にまたがっていますが、ネスト順序が間違っているため、正しい括弧シーケンスではありません。 括弧の種類のカウントのみに基づいた解決策は、それを誤って受け入れてしまいます。 

考慮する：```
][
```空ではない正しい部分文字列はありません。 答えは次のようになります。```
0
```空の 2 行目。 不用意に実装すると、いずれかの文字を出力しようとする可能性があります。 

考慮する：```
[]()[]
```文字列全体が有効であり、次の 2 つが含まれます。`'['`文字。 最長の有効な部分文字列のみを検索する場合でも、ここでは成功しますが、一般に、最適な部分文字列は、次の部分文字列の数によって決まります。`'['`、長さではありません。 

考慮する：```
([[]])
```文字列全体が有効であり、2 つの左角括弧が含まれています。 ソリューションでは、最上位レベルだけでなく、入れ子になった構造内の角括弧を正しくカウントする必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての部分文字列を列挙し、それが正しい括弧シーケンスであるかどうかを確認し、その数を数えます`'['`含まれている文字を選択し、最良のものを保持します。 

すべての候補部分文字列が検査されるため、正確性が即座にわかります。 問題はコストです。 がある$O(n^2)$部分文字列。 たとえ有効性チェックに時間がかかったとしても$O(n)$、全体の複雑さは次のようになります。$O(n^3)$。 と$n = 10^5$、これは絶望的です。 

重要な点は、すべての部分文字列を個別に検証する必要がないということです。 

正しいブラケット シーケンスは、標準のスタック プロセスを使用して認識できます。 文字列を左から右にスキャンする際、各閉じ括弧は現在のスタックの先頭と一致するか、その位置を横切る部分文字列の有効性を破棄します。 

これは、古典的な「有効な括弧が最も長い」問題に非常に似ています。 開始括弧のスタックとその位置を維持できます。 一致するペアが見つかるたびに、現在の位置で終わる有効なセグメントが取得されます。 セグメントを無効にする最も近い位置を追跡することにより、すべてのインデックスで終わる最大の有効な部分文字列を決定できます。 

残りの要件は、数を最大化することです。`'['`文字。 これはプレフィックス合計配列で処理できます。 有効な部分文字列の境界がわかると、その中の左角括弧の数が定数時間で取得されます。 

スタックは線形時間ですべての最大有効セグメントを識別し、プレフィックスの合計により各候補の効率的なスコアリングが可能になります。

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を構築します。`pref[i]`の数を保存します`'['`最初のキャラクター`i`文字。 

これにより、任意の部分文字列内の左角括弧を定数時間でカウントできるようになります。 
2. ペアを含むスタックを維持する`(position, bracket)`比類のない開始ブラケット用。 
3. 配列を維持する`dp`どこ`dp[i]`正確にその位置で終わる最長の正しい括弧シーケンスの長さを表します`i`。 
4. 文字列を左から右にスキャンします。 
5. 開始括弧が見つかったら、その位置とタイプをスタックにプッシュします。 
6. 右括弧が見つかった場合は、スタックの最上部に一致する左括弧が含まれているかどうかを確認します。 

そうでない場合は、スタックをクリアします。 今後の有効な部分文字列は、この不一致の位置を横切ることはできません。 
7. 一致するものが存在する場合は、左括弧の位置をポップします`j`。 
8. ペア`(j, i)`有効なブロックを形成します。 セット：```
dp[i] = i - j + 1
```9. 直前に終了する有効なブロックがある場合`j`、それを通って拡張します。```
dp[i] += dp[j - 1]
```これにより、隣接する有効な部分が 1 つのより大きな有効な部分文字列にマージされます。 
10. で終わる有効な部分文字列`i`左境界があります:```
L = i - dp[i] + 1
```11. 接頭辞の合計を使用して、この部分文字列内の左角括弧を数えます。```
count = pref[i + 1] - pref[L]
```12. この数がこれまでに見つかった最良の回答よりも大きい場合は、部分文字列の境界を保存します。 
13. すべての位置を処理した後、最適なカウントと対応する部分文字列を出力します。 

### なぜ効果があるのか

 スタックは、一致するすべてのペアが正しいブラケット シーケンスのネスト ルールに従うことを保証します。 不一致が発生するたびに、その位置を横切る部分的に構築されたシーケンスはすべて不可能になるため、スタックをクリアするのが正しいことになります。 

位置で開始括弧と正常に一致するすべての閉じ括弧に対して`j`、からのセグメント`j`現在位置までが有効です。 直前に別の有効なセグメントが終了した場合`j`、2 つのセグメントを連結しても有効なままです。これはまさに`dp`拡張ステップキャプチャ。 

したがって`dp[i]`常に、position で終わる有効な括弧部分文字列の最長の長さに等しくなります。`i`。 すべての最大の有効な部分文字列が、これらの候補の 1 つとして表示されます。 プレフィックスの合計により次の数が計算されるため、`'['`各候補内の文字を正確に検出すると、アルゴリズムは関連するすべての有効な部分文字列を検査し、最大スコアを持つ文字列を選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pref = [0] * (n + 1)
    for i, ch in enumerate(s):
        pref[i + 1] = pref[i] + (1 if ch == '[' else 0)

    dp = [0] * n
    stack = []

    best_count = 0
    best_l = 0
    best_r = -1

    match = {
        ')': '(',
        ']': '['
    }

    for i, ch in enumerate(s):
        if ch in '([':
            stack.append((i, ch))
        else:
            if stack and stack[-1][1] == match[ch]:
                j, _ = stack.pop()

                dp[i] = i - j + 1
                if j > 0:
                    dp[i] += dp[j - 1]

                l = i - dp[i] + 1
                cnt = pref[i + 1] - pref[l]

                if cnt > best_count:
                    best_count = cnt
                    best_l = l
                    best_r = i
            else:
                stack.clear()

    print(best_count)
    if best_r >= best_l:
        print(s[best_l:best_r + 1])
    else:
        print()

if __name__ == "__main__":
    solve()
```プレフィックス合計セクションを使用すると、任意の間隔内の左角括弧を定数時間でカウントできます。 これがなければ、すべての候補部分文字列を再度スキャンする必要があり、複雑さが増します。 

スタックにはブラケットのタイプとその位置の両方が保存されます。 一致が見つかったら、新しく形成された有効なブロックの正確な開始位置が必要になるため、位置が必要です。 

の`dp`array は、古典的な有効括弧の問題で使用されるのと同じ考え方です。 ポジション間でペアが一致する場合`j`そして`i`、セグメントの長さは最初は`i - j + 1`。 別の有効なシーケンスが次で終了する場合`j - 1`、2 つのセグメントは隣接しており、結合できるため、次のように追加します。`dp[j - 1]`。 

左側の境界は長さから再構築されます。```
left = i - dp[i] + 1
```これにより、すべての状態の境界を明示的に保存することが回避されます。 

微妙な点は、不一致のスタックをクリアすることです。 一致しない左括弧をスタック内に残すと、今後の一致が無効な位置を越えてしまい、実際には正しい括弧シーケンスではない部分文字列が生成される可能性があります。
