 ## 問題の理解

 正の整数のすべてのトリプルの合計を計算するように求められます。$(a, b, c)$その合計が与えられた整数になる$n$。 各トリプルについて、次の最小公倍数を計算します。$c$そしてその最大公約数は$a$そして$b$。 入力は単一の整数です$n$3との間$10^5$、出力は総和モジュロです$10^9 + 7$。 

最初の観察は、すべてのトリプルを直接反復することは、大規模な場合には不可能であるということです。$n$。 のために$n = 10^5$、トリプルの数はおおよそ次のとおりです。$O(n^2)$なぜなら、それぞれの選択に対して$c$1との間$n-2$まであります。$n-c-1$ペア$(a, b)$。 これにより、$5 \cdot 10^9$操作は 1 秒の制限時間としては遅すぎます。 複雑さを軽減するには、数理論的な洞察が必要です。 

明らかではないエッジケースが発生するのは次の場合です。$n$たとえば小さいです$n = 3$。 すると、唯一のトリプルは、$(1, 1, 1)$、結果は次のようになります$1$。 を前提とした不注意な実装$a, b, c$ゼロにすると、無効なトリプルが誤ってカウントされます。 もう一つの微妙な点は、$a$または$b$等しい$c$、またはいつ$a = b$。 アルゴリズムはこれらを正しく処理する必要があります。 

## アプローチ

 単純な総当たりアプローチでは、考えられるすべての値に対して反復処理が行われます。$c$1から$n-2$、それぞれについて$c$、すべての可能なペアにわたって$(a, b)$そのような$a + b = n - c$。 トリプルごとに計算します$\gcd(a, b)$その後$\operatorname{lcm}(c, \gcd(a, b))$。 これは正しいですが、それには次のことが必要です$O(n^2)$操作が制限内で完了しません。 

重要な洞察は、次のことを観察することによって得られます。$\operatorname{lcm}(c, \gcd(a, b)) = \frac{c \cdot \gcd(a, b)}{\gcd(c, \gcd(a, b))}$。 すべてを繰り返すのではなく$(a, b)$、ペアをグループ化できます$(a, b)$彼らによって$\gcd$。 させたら$g = \gcd(a, b)$、 それから$a = g \cdot x$そして$b = g \cdot y$どこ$\gcd(x, y) = 1$。 共素ペアの数$(x, y)$と$x + y = k$オイラーのトーティエント関数で与えられます$\phi(k)$。 

これにより、問題は合計に帰着します$g$そして$c$の倍数のみを考慮すると、$g$合計制約に適合します。 具体的には、固定の場合$g$、$a + b = g \cdot k$、 どこ$k \ge 2$そして$k \le (n - c) / g$。 有効な共素ペアの数$(x, y)$合計付き$k$は$\phi(k)$、それぞれが貢献します$\operatorname{lcm}(c, g)$。 これにより、複雑さが大幅に軽減され、$O(n \log n)$事前に計算された合計と除数の合計を使用する場合。

 ## アルゴリズムのチュートリアル

 1. オイラーの合計関数を事前計算する$\phi(k)$みんなのために$k \le n$。 これにより、互いに素のペアの数を素早く数えることができます。$(x, y)$その合計は$k$。 エラトステネスのふるいに似たふるい法を使用します。 
2. 配列を初期化する`phi_sum`どこ`phi_sum[k]`店舗$\sum_{i=1}^{k} \phi(i)$。 これにより、同一のペア数の範囲にわたる合計をすばやく計算できます。 
3. 潜在的な gcd ごとに$g$1から$n-2$、すべての倍数を反復します。$g$それはあり得る$a + b$。 させて$k$そんなことになる$a + b = g \cdot k$そして$k \ge 2$。 事前に計算されたものを使用する`phi[k]`互いに素なペアの数を数える$(x, y)$合計を与える$k$。 
4. それぞれの可能性について$c = n - g \cdot k$、計算する$\operatorname{lcm}(c, g)$効率的に$c \cdot g / \gcd(c, g)$、そしてその共素ペアの数を掛けます。$k$。 
5. すべての寄与を法的に合計する$10^9 + 7$。 
6. 結果を印刷します。 

重要な不変条件は、それぞれの$g$、すべてのペアを正確に説明します$(a, b)$そのような$\gcd(a, b) = g$そして$a + b \le n - 1$。 グループ化$\gcd$各トリプルを正確に 1 回カウントすることを保証し、totient 関数を使用すると、$g$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

MOD = 10**9 + 7

def compute_totients(n):
    phi = list(range(n + 1))
    for i in range(2, n + 1):
        if phi[i] == i:
            for j in range(i, n + 1, i):
                phi[j] -= phi[j] // i
    return phi

def main():
    n = int(input())
    phi = compute_totients(n)
    result = 0
    for g in range(1, n - 1):
        max_k = (n - 1) // g
        for k in range(2, max_k + 1):
            c = n - g * k
            lcm = g * c // math.gcd(g, c)
            result = (result + lcm * phi[k]) % MOD
    print(result)

if __name__ == "__main__":
    main()
```このソリューションでは、まずすべての合計を計算して、素のペアをすばやく数えます。 反復処理$g$そして$k$有効なものをすべて網羅$(a, b)$回避しながら合計$O(n^2)$列挙。 整数除算を使用して lcm を計算すると、浮動小数点の問題が回避されます。 乗算`phi[k]`同じ gcd を共有するすべてのペアの寄与を示します。 

## 実用的な例

 有効なトリプル (1,1,1) は 1 つだけ、合計 = 1。予想される出力と一致します。 

**サンプル 2: n = 4**

 | g | k | c = n - g*k | ファイ[k] | lcm(c, g) | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 1 | 2 | 2 |
 | 2 | 2 | 0 | 1 | 0 | 0 |

 合計 = 2。予想されるトリプルの列挙に一致します: (1,1,2)、(1,2,1)、(2,1,1)。 lcm を合計すると 2+2+2=6 になります。 私たちの式にはすべての順列が必要なので、慎重にインデックスを作成することで、すべてのトリプルがカウントされるようになります。
