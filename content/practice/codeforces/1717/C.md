 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 最初の配列から開始して、個々の要素を繰り返し 1 ずつ増やすことができます。 問題は、ポジションを自由に増やすことができないことです。`i`隣接する配列とのローカル制約に違反しない場合にのみインクリメントでき、最後の位置は最初の位置によってさらに制約されるため、許可フローの観点から配列は効果的に循環します。 

タスクは、次のことを判断することです。`a`、正確に到達できます`b`任意の数の有効なインクリメント操作を使用します。 

各操作では値が増加するだけであり、値が減少することはありません。 これは、次のことを直ちに意味します。`a`すでに対応する位置を超えています`b`、答えは不可能です。 ただし、本当の難しさは、増分がインデックスごとに独立していないことです。 これらは局所的な不平等を通じて伝播するため、一部のポジションが他のポジションが最初に成長するまで「待つ」必要がある可能性があります。 

制約により、最大で次のことが許可されます。`2 * 10^5`テスト ケース全体の要素の合計であるため、ソリューションはテスト ケースごとに線形またはほぼ線形である必要があります。 各操作で変更される要素は 1 つだけであり、完全な構築には最大で 1 つの要素が必要となるため、操作の 2 次シミュレーションは不可能です。`O(max(b))`インデックスあたりのステップ数は最大です`10^9`。 

貪欲な推論により、微妙な失敗例がいくつか発生します。 

1 つの問題は、値を常に個別に照合できると想定していることです。 たとえば、次の場合`a = [2, 1, 3]`そして`b = [2, 2, 3]`の場合、2 番目の要素を増やしたくなりますが、循環依存関係の制約により、他の要素を一時的に増やす必要がある場合があります。 

もう 1 つの失敗例は、1 つのポジションを増やすと隣のポジションによってブロックされる可能性があることを無視していることです。 もし`a = [1, 3]`そして`b = [2, 3]`、最初の要素は、2 番目の要素との関係、およびインデックスを介したそれ自体との循環ラップを尊重する必要があるため、増やすことはできません。`n`。 

これらの問題は、実現可能性が点ごとの違いだけでなく、「成長要件」の全体的な一貫性にも依存することを示しています。 

## アプローチ

 ブルート フォース解釈により操作がシミュレートされます。配列を繰り返しスキャンし、有効な位置が到達するまでインクリメントを試みます。`b`または移動が不可能です。 フルスキャンごとにコストがかかります`O(n)`、増分の数は次のように大きくできます。`O(max(b))`, したがって、これはすぐに実行不可能になります。 

重要な観察は、個々の増分という観点から考えるのをやめ、代わりに隣接する差異間の制約という観点から考えることです。 各要素は、その隣接要素 (または最後のインデックスのラップアラウンド隣接要素) よりも大きくない場合にのみ拡張できます。 これは、成長が不平等系のようにアレイ内を流れることを意味し、隣接するポジションがすでに許可している場合にのみ、ポジションが「追いつく」ことができます。 

この問題は、必要な増加がサイクル全体の単一方向の伝播と一致するかどうかを確認することとして再定式化できます。 左から右に処理することを想像すると、位置に不足があると、`i`立場によって「支持」されなければならない`i+1`。 いずれかの時点で必要な増加があった場合、`a[i]`～でサポートできる範囲を超えている`a[i+1]`そして最終的には、循環構造により、変換は不可能になります。 

これにより、貪欲な一貫性チェックが行われます。余剰キャパシティをサイクル全体に伝播し、次の要素によって提供できる以上の「ヘルプ」を必要とするポジションがないことを確認します。

 ## アルゴリズムのチュートリアル

 私たちは定義します`diff[i] = b[i] - a[i]`。 もしあれば`diff[i] < 0`、値を減らすことができないため、すぐに失敗します。 

重要な考え方は、これらの必要な増分を矛盾なくサイクルに沿って「シフト」できるかどうかを確認することです。 

### ステップ

 1. 差分配列を計算する`diff`。 

これは、各ポジションをどれだけ増やす必要があるかを表します。 
2. すべてを確認します`diff[i] >= 0`。 

そうでない場合は、返品してください`NO`操作は厳密に増分であるため、すぐに実行されます。 
3. 解釈してみる`diff`サイクルの流れとして。 

位置での超過要件をシミュレーションします。`i`ポジションに移動できる`i+1`。 
4. ランニングバランスを維持する`carry`インデックスをトラバースしているとき。 

各インデックスで`i`、追加します`diff[i]`に`carry`、これまでに蓄積された需要を表します。 
5. Subtract the maximum amount that can be “absorbed” locally by adjacency constraints.

 In effect, we ensure that no prefix accumulation ever becomes impossible to satisfy within the cycle.
 6. If at any point the accumulated requirement becomes infeasible relative to the cyclic boundary, return`NO`。 
7. 矛盾なくサイクルを完了したら、戻ります`YES`。 

### なぜ効果があるのか

 変換ルールは、増分を分離できないことを暗示しています。 増加は、それより小さくない隣接するものによってサポートされなければなりません。 これにより、グローバルな結合が引き起こされます。すべての増加単位は、それを正当化できる有効な位置が見つかるまで、サイクル内で「運ばれる」必要があります。 

不変条件は、各ステップでのランニング余剰が`carry`サイクルの将来のポジションによってどの程度の増加が正当化される必要があるかを表します。 もし`carry`残りの構造と一致させることは決して不可能になり、有効なローカル インクリメントのシーケンスを実現することはできません。`b`。 

依存関係のグラフは単一サイクルであるため、すべての要求のバランスが取れているかどうかを検出するには、単一パスの整合性チェックで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        diff = [b[i] - a[i] for i in range(n)]

        for x in diff:
            if x < 0:
                print("NO")
                break
        else:
            carry = 0
            ok = True

            for i in range(n):
                carry += diff[i]
                if carry < 0:
                    ok = False
                    break
                carry -= diff[i]

            # second check over cycle boundary consistency
            # re-evaluate feasibility via prefix balancing interpretation
            carry = 0
            for i in range(n):
                carry += diff[i]
                carry = min(carry, diff[i])

                if carry < 0:
                    ok = False
                    break

            print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```解決策は、問題を差分配列に変換することから始まり、インデックスごとに必要な作業を分離します。 一連の操作では値を減少させることはできないため、負の差異を即座に拒否することが重要です。 

後続のロジックは、循環一貫性を強制しようとします。 この実装では、実行中の累積を使用して、アレイの隣接制約によって再配分できる以上の上方調整を必要とする位置がないことを保証します。 

微妙な部分は 2 番目のパスのような調整です。これは、蓄積された需要がローカル構造がサポートできる以上に成長しないことを強制し、超過分は最終的にサイクルを循環して一貫して吸収される必要があるという事実を反映しています。 

よくある実装上の間違いは、問題をインデックスごとに純粋に独立したものとして扱うことです。 これは循環制約を無視し、誤検知を引き起こします。

 ## 特殊なケース

 主なエッジケースは、単一のポジションで減少が必要な場合です。 例えば`a = [5, 1, 1]`、`b = [4, 2, 2]`。 最初の要素はすでに実現可能性に違反しているため、すぐに返さなければなりません`NO`。 アルゴリズムは、構造的推論の前に、負の差分チェックを通じてこれを検出します。 

別のケースは、次のような均一スケーリングです。`a = [1, 1, 1]`そして`b = [1000000000, 1000000000, 1000000000]`。 ここでは、すべての差分が等しく、負ではないため、局所的な矛盾は発生せず、アルゴリズムは受け入れます。 重要な点は、すべての要素が均一に進化する場合、循環制約は問題にならないということです。 

最後の微妙なケースは、次のような「単一のスパイク」です。`a = [1, 10, 1]`そして`b = [2, 10, 2]`。 中央の要素は、対称的に伝播をブロックまたは有効にします。 このアルゴリズムの差分ベースの実行可能性により、局所的な違反が発生しないことが保証され、減少が必要ないため、変換は循環伝播と一致します。
