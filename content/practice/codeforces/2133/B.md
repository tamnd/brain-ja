 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには、$n$各村人は不機嫌と呼ばれる負ではない整数値から始まります。 状況を変える唯一の方法は、繰り返し 2 人の村人を選んで、彼らの不機嫌さを軽減し、潜在的に彼らの間に友情の絆を生み出すようなやり取りを行うことです。 

村人同士のそれぞれのやりとり$i$そして$j$次のように動作します: 私たちは等しい数のエメラルドを支払います$\max(g_i, g_j)$。 その後、両方の村人は次のようにして不機嫌さを和らげます。$\min(g_i, g_j)$。 小さい方の値が完全に減算されるため、結果として少なくとも 1 つはゼロになります。 この操作では、それらを無向エッジで接続することもできます。 

目標は、不機嫌さを最小限に抑えたり、友情を直接最大化することではなく、一連の操作の後で友情グラフが確実につながるようにすることです。 言い換えれば、すべての村人は、エッジを作成した一連の操作を通じて他のすべての村人に到達できなければなりません。 

重要な出力は、この接続を保証するために費やされるエメラルドの最小合計数です。 

制約は大きく、最大で$2 \cdot 10^5$テストケース全体の村人の合計。 これにより、すべてのペアを試行したり、密なグラフ構築をシミュレートしたりするアプローチは即座に除外されます。 ソリューションは、テスト ケースごとに最大でも線形またはほぼ線形である必要があります。通常、$O(n \log n)$または$O(n)$。 

隣接する値や小さな値だけを接続しようと欲張って考えると、微妙な失敗例が現れます。 たとえば、次のように考えてみましょう$g = [1, 100, 100]$。 単純な考えでは、最初に最小のものを接続しようとするかもしれませんが、コスト構造は最大と最小のインタラクションに依存するため、ペアリングの選択によって総コストが大幅に変わる可能性があります。 もう 1 つの落とし穴は、必要なのは$n-1$最も安価な直接接続。 この操作では値が動的に減少するため、エッジは独立していません。 

## アプローチ

 ブルートフォースの観点は、村人上にスパニング ツリーを構築することを考えることです。この場合、すべてのエッジには、2 つのノード間での操作の実行から得られるコストがかかります。 潜在的なエッジごとに$(i, j)$、操作を実行するコストを計算し、最小スパニング ツリー アルゴリズムを実行できます。 ただし、エッジの重みが固定されていないのが難点です。 コストは現在の不機嫌さの値に依存し、これらの値は操作後に変化するため、「エッジの重み」は静的ではありません。 一連の操作の単純なシミュレーションでは、各操作によって状態空間が変化するため、指数関数的な分岐プロセスが発生します。 

重要な洞察は、各操作が小さい不機嫌さを効果的に接続に転送し、小さいものの単位減少ごとに大きい値を 1 回支払うだけであることを観察することです。 各村人の不機嫌さは、何らかの構造に「吸収」される必要があるリソースとして解釈できます。 最適な構造は、最小要素に依存する全体的な修正を除いて、不機嫌のすべての単位が正確に 1 回支払われるように削減が組織される、単一の「ルートのような」戦略を選択するのと同等であることが判明しました。 

より具体的には、ユニットの減少ごとに少なくとも 1 回は常に現在値をチャージするインタラクションを通じて、1 人を除くすべての村人が最終的にゼロになる必要があることに注目することで、最適な戦略を導き出すことができます。 これにより、総コストがすべての不機嫌さの値の合計に、最小の要素の二重カウントを回避する調整を加えたものになるという公式が得られます。 

これにより、問題は動的なペア演算から配列に対する単純な算術式に軽減されます。

 ## アルゴリズムのチュートリアル

 1. すべての不機嫌さの値の合計を計算します。 これは、不機嫌さの各単位が独立してコストに寄与すると想定されるベースラインを表します。 操作の構造により、すべてのユニットが少なくとも 1 回は「代金を支払う」必要があります。 
2. 配列内の最小の不機嫌さの値を見つけます。 この要素は、最適な構築においてコストの過大な計算を避ける方法で組み合わせることができるため、特別な役割を果たします。 
3. 合計値からこの最小値を減算します。ただし、2 回以上減算しないでください。 その理由は、無駄な高価な相互作用を回避する方法で最小の要素を完全に吸収できるためです。 
4. 調整された合計をテスト ケースの答えとして出力します。 

### なぜ効果があるのか

 このプロセスは、ペア内の小さな不機嫌さを常に排除する操作を通じて、各村人が最終的に単一の接続されたコンポーネントにマージされる、接続された構造を構築するものとして理解できます。 不機嫌のすべてのユニットは少なくとも 1 つの削減ステップに参加し、少なくともその価値が総コストに貢献する必要があります。 ただし、最も小さな不機嫌さは常に最終的な吸収軸として配置できるため、その貢献を中間の高価な組み合わせによって「複製」する必要はありません。 これにより、最小要素に等しいグローバル節約が 1 つだけ作成され、最適なコスト公式が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        mn = min(a)
        print(total - mn)

if __name__ == "__main__":
    solve()
```実装は直接的です。 このソリューションは、各テスト ケースを読み取り、配列の合計と最小値を計算し、それらの差を出力します。 

重要な点は、両方の操作がテスト ケースごとに独立して実行されることです。 Python の組み込みを使用する`sum`そして`min`実装を線形に保ち、ソートやペアのシミュレーションの必要性を回避します。 

すべての値は正であり、配列は常に空ではないため、入力行の正しい読み取りを保証すること以外に、エッジケースの処理は必要ありません。

 ## 特殊なケース

 微妙なケースは、すべての値が同一である場合です。たとえば、$g = [5, 5, 5]$。 アルゴリズムは計算します$15 - 5 = 10$。 正確さは、任意の要素が「吸収された」最小値として機能することができ、対称性により特別な構造が必要ないという事実から生まれます。 

もう 1 つのケースは、最小値が複数回発生する場合です。たとえば、$g = [1, 1, 10]$。 アルゴリズムは最小値のコピーを 1 つだけ減算し、次のようになります。$12 - 1 = 11$。 接続要件により、そのうちの少なくとも 1 つがフルコストの対話で使用されることが強制されるため、操作中には、最小要素がいくつ存在するかに関係なく、グローバル節約は 1 単位のみ達成可能です。 

極端な格差の場合は、$g = [1, 10^9]$、答えは次のようになります$10^9$。 小さな要素は一度限りの吸収剤としてのみ寄与しますが、大きな要素はコストを支配します。
