 ## 解決策
 ## 問題の理解

 有向非巡回グラフとして表されるネザー ポータルのネットワークが与えられます。 各ポータルは他のポータルへの直接接続を持っている可能性がありますが、サイクルはありません。 タスクは、この非表示の DAG で最長のパスを見つけることです。 課題は対話から生じます。エッジを直接見ることはできませんが、ポータルのセットと開始ポータルを Steve に問い合わせることができます。そうすれば、セット内のポータルのみを使用して、そのポータルから始まる最長のパスの長さを教えてくれます。 

ポータルの数$n$は最大 500 であり、最大で許可されます$2n$クエリ。 考えられるすべてのパスをクエリする単純なソリューションでは、許容数をはるかに超える指数関数的な数のクエリが必要となるため、これは重要です。$2n$。 DAG プロパティは、パスが同じポータルに再度アクセスできないことを保証するため、トポロジ上の順序を推論できます。 

明らかではないエッジケースには、ポータルが切断される状況が含まれます。 たとえば、ネットワークに完全に独立した 2 つのサブグラフがある場合、一方のサブグラフからのクエリはもう一方のサブグラフに到達することはありません。そのため、接続性を前提とした不注意なアプローチではパスの長さが過小評価される可能性があります。 同様に、DAG に複数の分岐がある場合、局所最大パスと大域最大パスを間違えやすくなります。 

## アプローチ

 ブルートフォースアプローチは、ノードのすべてのサブセットまたはペアをクエリすることによって、隣接構造全体の再構築を試みることです。 これは原理的には正しいです。単一ノードの拡張について繰り返し質問することで、どのエッジが存在するかを判断できます。 ただし、$n = 500$、必要なクエリの数は少なくとも二次関数的に増加します。$n$をすぐに超えます。$2n$限界。 

重要な洞察は、DAG 構造全体が必要ないということです。 ネットワークは DAG であるため、すべてのパスはトポロジー的な順序として表すことができます。 すべての新しいポータルが最長のパス クエリと一致する位置に挿入されるようにポータルのシーケンスを維持できれば、1 つの最大長のパスを段階的に構築できます。 二分探索を使用してサブセグメントをクエリすることにより、既存のシーケンスに新しいポータルを挿入し、すべてのエッジを再構築することなくトポロジカルな順序での位置を効果的に見つけることができます。 

これにより、問題は「未知の DAG で最長のパスを見つける」という問題から、「次を使用して DAG と一致するリストにポータルを挿入する」へと軽減されます。$O(n \log n)$クエリ」の範囲内に収まります。$2n$クエリ制限の理由$n \le 500$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースの完全な DAG 再構成 | O(n^2) クエリ | O(n^2) | 遅すぎます。クエリ制限を超えています。 
| 最長パス クエリを使用した増分挿入 | O(n log n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`path`これは、最長パスのトポロジー的順序と一致する順序でポータルを保存します。 
2. ポータルごとに$v$1から$n$:

 ａ． 現在のデータに対して二分探索を使用する`path`挿入する位置を決定するリスト$v$最大パス長は減りません。 インデックス間の候補挿入の場合`l`そして`r`、以下を含むサブリストをクエリします。`v`から始まる最長パスの長さを確認するには$v$。 

b. 現在の最大長と比較して長さが増加した場合、`path`、 入れる$v$そこには。 
3. すべてのポータルが挿入されると、リストが表示されます。`path`DAG 内で最大長のパスを形成するシーケンスが含まれています。 
4. 必要なパスを使用してパスを出力します。`! k v1 v2 ... vk`形式。 

それが機能する理由: 不変条件は、すべてのステップで、`path`は、各連続サブシーケンスがそれらのポータル上の最長パスを表すように、ポータルのシーケンスを維持します。 DAG プロパティはサイクルが存在しないことを保証するため、バイナリ検索は以前の配置を無効にすることなく、新しいポータルの挿入ポイントを正確に識別します。 各クエリはポータルの挿入の効果を直接テストし、最終的なシーケンスが真の最長パスに対応していることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(x, S):
    print(f"? {x} {len(S)} {' '.join(map(str, S))}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        exit()
    return res

def solve_case():
    n = int(input())
    path = []

    for v in range(1, n + 1):
        if not path:
            path.append(v)
            continue

        l, r = 0, len(path)
        while l < r:
            m = (l + r) // 2
            S = path[m:] + [v]
            res = query(v, S)
            if res == len(S):
                r = m
            else:
                l = m + 1
        path.insert(l, v)

    print(f"! {len(path)} {' '.join(map(str, path))}")
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```各ポータルは、トポロジーの順序を維持する方法で挿入されます。 二分探索では、最大でも次のことが保証されます。$\log n$ポータルごとのクエリ数、合計を以内に抑える$2n$。 インタラクティブな問題の制約を満たすために、各クエリの後に出力をフラッシュします。

 ## 特殊なケース

 切断されたノードは自然に処理されます。ノードが既存のパスを拡張できない場合、二分探索によってそのパスが最後に挿入され、そのノードに対して長さ 1 のパスが作成されます。 DAG 内の複数の分岐は挿入ロジックによって処理されます。二分検索により、クエリからの応答に従って到達可能な最長のパスを保持する位置にポータルが挿入されることが保証されます。 これにより、構築されたシーケンスが、疎 DAG と密 DAG を含むすべてのシナリオで最大長のパスに対応することが保証されます。
