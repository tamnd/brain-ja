 ## 解決策
 ## 問題の理解

 私たちは、左端の歯車が 1 秒あたり 1 回転で回転すると、右端の歯車がちょうど 1 秒あたり 1 回転で回転するように、一連の歯車を一列に配置できるかどうかを判断するように求められます。 各歯車には多数の歯があり、隣の歯車に対する相対的な速度は歯の比に比例します。 具体的には、$y$歯は歯車を駆動します$x$歯が高速で回転する$z$、次の歯車は次の速度で回転します。$z \cdot y / x$。 複数のテスト ケースが与えられ、各テスト ケースには最大 100 個の歯車があり、歯数は 2 ～ 100 です。 

問題は整数の配置に帰着します$a_1, \dots, a_n$直線に沿った連続する比率の積が 1 に等しくなるようにします。配置されたシーケンスが次の場合、この積を明示的に記述します。$b_1, b_2, \dots, b_n$、最終ギア速度は$$1 \cdot \frac{b_1}{b_2} \cdot \frac{b_2}{b_3} \cdots \frac{b_{n-1}}{b_n} = \frac{b_1}{b_n}.$$したがって、最初と最後のギアの歯数が同じである場合に限り、右端のギアは速度 1 で回転します。 これが重要な単純化です。中間ギアはすべてキャンセルされます。 

このことを考えると、この問題は、シーケンスの両端に配置できるギア数が存在するかどうかを確認することに相当します。 

エッジ ケースには、すべての歯車の歯数が同じである場合 (自明の「YES」)、または数字が少なくとも 2 回表示されない場合 (「NO」) が含まれます。 たとえば、ギアが`[2, 3]`、どちらの配置も要件を満たしていません。 

制約は単純なカウントを可能にするのに十分小さいものです。$n$100までと$t$最大 1000、$O(n^2)$ブルートフォースアプローチは実現可能ですが、発生回数をカウントするのは困難です。$O(n)$テストケースごとに、よりクリーンになります。 

## アプローチ

 ブルートフォースアプローチでは、ギアのすべての並べ替えを試み、それぞれの回転をシミュレートします。 のために$n = 100$、 がある$100!$順列は天文学的に大きく、実行不可能です。 最終速度は最初と最後のギアのみに依存するため、各順列の比率をシミュレートする必要さえありません。 

重要な観察は、比率が望遠鏡であるということです。$\frac{y}{x}$単純化すると$\frac{b_1}{b_n}$。 これにより、問題はギアの動きのシミュレーションから、最初のギアと最後のギアが等しくなるかどうかの単純なチェックに軽減されます。 したがって、最適な解決策は、入力に歯数が少なくとも 2 回出現するかどうかを確認することです。 そうすれば、両端に配置して、残りのギアを中央に任意に配置できます。 そうでない場合、要件を満たす取り決めはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列をシミュレート) | お(ん!) | O(n) | 遅すぎる |
 | 出現回数を数え、重複をチェックする | テスト ケースあたり O(n) | O(100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 各テスト ケースは独立して処理されます。 
2. 各テストケースについて、ギアの数を読み取ります。$n$そして彼らの歯はリストに数えられます$a$。 
3. 辞書または配列を使用して、各歯数の出現をカウントします。 これにより、どの数字が複数回出現するかを知ることができます。 
4. いずれかのカウントが 2 以上であるかどうかを確認します。そのようなカウントが存在する場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 
5. すべてが処理されるまで、次のテスト ケースに進みます。 

機能する理由: 中間の比率が相殺されるため、右端のギアの速度は配置の最初と最後のギアにのみ依存します。 両端に繰り返し歯車を配置すると、比の積が 1 になることが保証され、条件が満たされます。 他の手配は必要なく、チェックだけで十分かつ必要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    gears = list(map(int, input().split()))
    counts = {}
    found = False
    for x in gears:
        counts[x] = counts.get(x, 0) + 1
        if counts[x] >= 2:
            found = True
            break
    print("YES" if found else "NO")
```このソリューションは各テスト ケースを読み取り、辞書を使用して各歯番号の出現をカウントし、いずれかの番号が 2 回出現すると早期に中断します。 早めに中断することで、解が見つかった後に残りの数値を不必要に処理することがなくなります。 私たちが使用するのは`dict.get`条件チェックを必要とせずにカウントの増加を簡素化します。 

## 実用的な例

 サンプル入力`[2, 5, 5]`:

 | ギア | カウント | >=2 が見つかりましたか? |
 | --- | --- | --- |
 | 5 | {5:1} | いいえ |
 | 5 | {5:2} | はい |

 アルゴリズムは「YES」を出力します。 

入力`[2, 2, 3]`:

 | ギア | カウント | >=2 が見つかりましたか? |
 | --- | --- | --- |
 | 2 | {2:1} | いいえ |
 | 3 | {2:1、3:1} | いいえ |

 数値が 2 回出現しないため、アルゴリズムは「NO」を出力します。 

これらのトレースは、アルゴリズムが両端に配置する重複が存在するかどうかを正しく識別していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各ギアの発生をカウントすると、ギアの数が線形になります。 |
 | スペース | O(100) | 個別の歯の最大数は 99 (2 ～ 100) であるため、辞書には制限があります。 |

 と$t \le 1000$そして$n \le 100$、これにより最大 100,000 回の操作が発生し、1 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        gears = list(map(int, input().split()))
        counts = {}
        found = False
        for x in gears:
            counts[x] = counts.get(x, 0) + 1
            if counts[x] >= 2:
                found = True
                break
        output.append("YES" if found else "NO")
    return "\n".join(output)

# provided samples
assert run("5\n2\n5 5\n4\n6 3 6 9\n2\n2 3\n7\n30 10 12 10 10 9 18\n5\n2 4 8 16 32\n") == "YES\nYES\nNO\nYES\nNO", "sample 1"

# custom cases
assert run("1\n2\n2 2\n") == "YES", "all equal"
assert run("1\n3\n2 3 4\n") == "NO", "all distinct, small n"
assert run("1\n4\n3 3 4 5\n") == "YES", "one duplicate in middle"
assert run("1\n100\n" + " ".join(str(i) for i in range(2, 102)) + "\n") == "NO", "large n, all distinct"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`[2,2]`| はい | 最小サイズ、すべて等しい |
 |`[2,3,4]`| いいえ | 小さい n、すべて異なる |
 |`[3,3,4,5]`| はい | 1 つの重複が終端ではない |
 |`[2..101]`| いいえ | 大きい n、すべて異なる |

 ## 特殊なケース

 このアルゴリズムは、すべてのギアが同一である場合に、カウントして重複を即座に見つけることによって処理します。 例えば、`[5, 5, 5]`5 が 3 回出現するため、「YES」となります。 すべてのギアが異なる場合、たとえば、`[2, 3, 4]`の場合、辞書カウントには重複が示されず、アルゴリズムは「NO」を出力します。 100 個の個別の値を持つ最大サイズの入力でも効率的に「NO」が生成されます。これは、カウント辞書が小さいままであり、早期ブレークがトリガーされないためです。
