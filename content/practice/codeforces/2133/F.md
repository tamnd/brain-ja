 ## 解決策
 ## 問題の理解

 私たちには、爆発力を持つクリーパーの列が与えられています。 所定の位置でクリーパーを爆発させる$i$爆発力以下の距離にいるすべてのクリーパー、特に位置を殺す$j$そのような$|i - j| < e_i$。 爆発力がゼロのクリーパーは爆発できません。 死んだクリーパーを爆発させることはできません。目標は、できるだけ少ない爆発ですべてのクリーパーを殺す一連の爆発を見つけるか、それが不可能な場合は報告することです。 

入力は複数のテスト ケースで構成され、それぞれのテスト ケースは次のとおりです。$n$クリーパーとアレイ$e$爆発的なパワーの。$n$まで可能です$5 \cdot 10^5$すべてのテスト ケースにわたって、二次複雑度のアルゴリズムは除外されます。$n^2$届くだろう$2.5 \cdot 10^{11}$操作。 線形または線形演算による解決策が必要です。 

素朴な実装を罠にはめる可能性のあるエッジケースには、爆発力を持つクリーパーが含まれます$0$爆発力が小さくて届かないクリーパーに囲まれています。 たとえば、入力では`0 1 1 1`、最初のクリーパーは爆発できず、他のクリーパーはどれもその範囲内で到達することができません。 不注意で貪欲な戦略は、最初に利用可能なクリーパーを爆発させようとし、一部のクリーパーが到達できないことを認識できず、誤った解決策を報告す​​る可能性があります。 

もう 1 つのエッジ ケースは、最初または最後のクリーパーの爆発力がゼロである場合です。この場合、爆発不可能なクリーパーを取り残さずに境界をカバーするには、爆発を慎重に選択する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての爆発のサブシーケンスを考慮し、各シーケンスでどのクリーパーが殺されるかをシミュレートします。 それぞれについて、$n$クリーパーの場合、爆発するかスキップするかを選択できます。$2^n$シーケンス。 これは明らかに不可能です$n$まで$5 \cdot 10^5$。 

重要な観察は、この問題が区間カバレッジ問題としてモデル化できるということです。 それぞれのクリーパー$i$爆発的なパワーを持った$e_i > 0$間隔をカバーできる$[i - (e_i-1), i + (e_i-1)]$。 すべてのポジションを集合的にカバーする最小の間隔セットを選択する必要があります$1$を通して$n$。 パワーがゼロのクリーパーは間隔を提供しないため、カバレッジが不可能になる可能性があります。 

これにより、問題は古典的な貪欲な区間カバー問題に縮小されます。 クリーパーを左から右に並べ替えまたはスキャンし、間隔が現在のカバー範囲を最も遠くまで拡張するクリーパーを常に選択します。 これにより、各ステップで残りのクリーパーの範囲が最大化されるため、最小限の爆発が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲な間隔のカバレッジ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポインタを初期化する`covered = 0`すでに爆発によって覆われている右端の位置を表します。 リストを管理する`detonations`爆発したクリーパーのインデックスを保存します。 
2. 現在の位置について`pos = 0`、左の間隔の終点が ≤ であるすべてのクリーパーをスキャンします。`pos + 1`。 これらの中で、右側の間隔の端点が最大であるクリーパーを選択します。 このクリーパーを爆発させてアップデートしてください`covered`右側のエンドポイントに移動します。 
3. 爆発したクリーパーのインデックスを`detonations`。 動く`pos`に`covered`そしてステップ2を繰り返します。 
4. クリーパーがカバー範囲を拡張できない場合、`covered < n`、 戻る`-1`クリーパーによっては爆発させられなかったり、到達できなかったりするためです。 
5. 1回`covered >= n`、爆発の数とシーケンスを返します。`detonations`。 

機能する理由: 間隔がカバレッジを最も遠くまで拡張するクリーパーを常に選択するという貪欲な選択により、不必要に位置がスキップされることがなくなります。 ある位置をカバーできる場合、アルゴリズムは最終的にその位置をカバーするクリーパーを選択します。 爆発の数が少ない解決策では、最大間隔をスキップする必要がありますが、クリーパーを覆わないままにすることは不可能です。 したがって、最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        e = list(map(int, input().split()))
        
        intervals = []
        for i, power in enumerate(e):
            if power > 0:
                left = max(0, i - (power - 1))
                right = min(n - 1, i + (power - 1))
                intervals.append((left, right, i + 1))  # store 1-based index
        
        intervals.sort()
        detonations = []
        covered = -1
        i = 0
        while covered < n - 1:
            best = None
            while i < len(intervals) and intervals[i][0] <= covered + 1:
                if best is None or intervals[i][1] > best[1]:
                    best = intervals[i]
                i += 1
            if best is None:
                print(-1)
                break
            detonations.append(best[2])
            covered = best[1]
        else:
            print(len(detonations))
            print(*detonations)

if __name__ == "__main__":
    solve()
```最初のループでは、爆発力がゼロではないクリーパーの間隔を構築します。 並べ替えることで、左から右へ効率的にスキャンできるようになります。 の`while`ループは、カバレッジを最も遠くまで拡張するクリーパーの貪欲な選択を実装します。 の`else`ループ上で次の場合にのみ実行されます`break`つまり、カバレッジは最後まで達します。 

微妙な点: 私たちは使用します`max(0, i - (power - 1))`左側の境界を処理し、`min(n - 1, i + (power - 1))`右側の境界線の場合。 インデックス付けは出力用に 1 ベースに調整されます。 これらの境界を考慮しないと、エッジで不正確な答えが生成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各間隔は貪欲スキャンで最大 1 回考慮され、合計はクリーパーの数に比例します。 
| スペース | O(n) | 間隔と爆発のリストを保存 |

 の合計`n`すべてのテスト ケースにわたる は ≤ 5·10^5 であるため、テスト ケースごとの O(n) は 2 秒の制限時間内に問題なく収まります。
