 ## 解決策
 ## 問題の理解

 正の整数の独立した配列がいくつか与えられています。 各配列について、選択した値の合計が偶数になるように、空でない位置のグループを選択する必要があります。 そのようなグループが存在しない場合は、失敗が報告されます。 

出力はサブセット自体ではなく、有効なサブセットを形成する要素のインデックスです。 有効な選択はどれでも受け入れられるため、サイズや辞書順を最適化するのではなく、実現可能性のみを最適化します。 

制約は小さく、テスト ケースは最大 100 個、各配列の要素は最大 100 個です。 これにより、サブセットに対する 3 次または 2 次のアプローチも最悪の場合には実行可能であることがすぐにわかります。 ただし、パリティが重要な唯一のプロパティであるため、サブセットを列挙するよりもはるかに単純な構造を期待する必要があります。 

重要なエッジケースは非常に小さな配列から生じます。 単一の要素がある場合、唯一のサブセットの合計がその要素と等しいため、答えは完全にその数が偶数かどうかによって決まります。 2 つの要素がある場合、奇数と偶数の相互作用が関連します。1 つの偶数要素がすでに問題を解決していますが、2 つの奇数要素も偶数の和を形成します。 

素朴な考え方による微妙な失敗例は、少なくとも 1 つの奇数と 1 つの偶数があるときは必ず両方をとらなければならないと仮定することです。 単一の偶数要素がすでに有効な答えを与えているため、これは不要です。 もう 1 つの落とし穴は、すべての数値が奇数で 3 つ以上ある場合、常に解が存在すると仮定することです。 実際、偶数の合計を得るには奇数の偶数カウントが必要です。 

## アプローチ

 ブルートフォースソリューションでは、すべてのサブセットを列挙し、それらの合計が偶数であるかどうかを確認します。 がある$2^n - 1$空ではないサブセット、そしてそれぞれについて合計を計算します$O(n)$、与える$O(n 2^n)$テストケースごとに。 と$n = 100$、これは天文学的な限界を超えているため、まったく実行不可能です。 

パリティがどのように動作するかを観察すると、問題の構造は大幅に単純化されます。 整数の合計は、含まれる奇数要素の数によってのみ決まります。 偶数はパリティにまったく影響しませんが、各奇数は合計のパリティを反転します。 

これは、少数の要素しか必要としないことを意味します。 偶数がある場合は、それを単独で取得できます。 それ以外の場合は、2 つのオッズを合計すると偶数になるため、奇数のペアを探します。 奇数が 1 つだけ存在し、偶数が存在しない場合、解は存在しません。 

したがって、問題は配列を 1 回スキャンして偶数と奇数の位置を記憶することになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を 1 回スキャンし、偶数要素のインデックスを記録します。 

偶数が見つかった場合は、単一の偶数要素がすでに有効なサブセットを形成しているため、それ以上のスキャンを直ちに停止できます。 これは、最小のサブセット サイズと正確性が保証されるため、最適です。 
2. 偶数要素が存在しない場合は、すべての奇数要素のインデックスを収集します。 

このステップが必要なのは、奇数の要素を個別に偶数の合計を生成することはできませんが、それらのペアでは偶数の合計を生成できるためです。 
3. 少なくとも 2 つの奇数要素がある場合は、最初の 2 つのインデックスを出力します。 

それらの合計は奇数プラス奇数であり、偶数であるため、サブセット条件は満たされます。 
4. 奇数要素が 2 つ未満で偶数要素がない場合は、-1 を出力します。 

残る唯一のケースは単一の奇数要素であり、空でないサブセットでは偶数の合計を形成できません。 

### なぜ効果があるのか

 合計のパリティは、含まれる要素のパリティのみに依存します。 偶数はパリティにゼロを寄与しますが、各奇数はパリティを反転します。 したがって、選択された奇数要素の数が偶数の場合、合計は正確に偶数になります。 このアルゴリズムは、1 つの偶数要素 (奇数要素が 0) または 2 つの奇数要素 (2 が偶数) を構築し、すべての可能なケースをカバーします。 実現可能性を変えることなく、より大きなサブセットを常にこれらの標準形式の 1 つに還元できるため、他の構造は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_idx = -1
        odd_indices = []

        for i, x in enumerate(a, 1):
            if x % 2 == 0:
                even_idx = i
            else:
                odd_indices.append(i)

        if even_idx != -1:
            print(1)
            print(even_idx)
        elif len(odd_indices) >= 2:
            print(2)
            print(odd_indices[0], odd_indices[1])
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に偶数要素をチェックします。これは、サイズ 1 の有効なサブセットがすぐに得られるためです。 何も存在しない場合は、残っている唯一の建設的なケース、つまり奇数の要素をペアにする方法に戻ります。 この問題では 1 から始まるインデックスが必要なため、列挙は 1 から始まります。 

よくある実装上の間違いは、偶数の要素を見つけた後もスキャンを継続し、誤ってロジックを上書きしたり、ロジックを複雑にしてしまうことです。 もう 1 つは、値ではなくインデックスのみが必要であることを忘れていることです。 

## 実用的な例

 偶数要素が 1 つだけ存在する場合と、奇数要素のみが存在する場合の 2 つのケースを追跡します。 

### 例 1

 入力:`[1, 4, 3]`| ステップ | 現在の要素 | 偶数インデックス | 奇数リスト |
 | --- | --- | --- | --- |
 | 1 | 1 | -1 | [1] |
 | 2 | 4 | 2 | [1] |
 | 3 | 3 | 2 | [1、3] |

 4 を見つけた後で停止し、インデックス 2 を出力します。トレースは、偶数が出現すると、それ以降の要素は重要ではないことを示しています。 

### 例 2

 入力:`[3, 5, 7]`| ステップ | 現在の要素 | 偶数インデックス | 奇数リスト |
 | --- | --- | --- | --- |
 | 1 | 3 | -1 | [1] |
 | 2 | 5 | -1 | [1、2] |
 | 3 | 7 | -1 | [1、2、3] |

 偶数要素は存在しないため、最初の 2 つの奇数インデックス 1 と 2 を使用します。これにより、値に関係なく、任意の 2 つの奇数で十分であることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_idx = -1
        odd = []

        for i, x in enumerate(a, 1):
            if x % 2 == 0:
                even_idx = i
            else:
                odd.append(i)

        if even_idx != -1:
            output.append("1")
            output.append(str(even_idx))
        elif len(odd) >= 2:
            output.append("2")
            output.append(f"{odd[0]} {odd[1]}")
        else:
            output.append("-1")

    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースは、配列に要素が 1 つだけ含まれている場合です。 その要素が偶数の場合、答えはそのインデックスになります。 奇数であれば解決策はありません。 アルゴリズムは、次のいずれかを設定するため、これを自然に処理します。`even_idx`または、単一の奇数インデックスを収集し、2 番目の条件に失敗します。 

もう 1 つのエッジ ケースは、複数の偶数要素が存在する場合です。 このアルゴリズムは、最後に検出された偶数インデックスを返します。偶数要素は 1 つあれば十分であるため、このインデックスは依然として有効です。 順序への依存は存在しません。 

3 番目のケースは、すべての要素が奇数であるが、その数が大きい場合です。 このアルゴリズムは依然として最初の 2 つのインデックスのみを選択します。これは、合計数に関係なく、2 つの奇数がすでに偶数の合計を保証しているため機能します。
