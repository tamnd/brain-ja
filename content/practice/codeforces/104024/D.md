 ## 解決策
 ## 問題の理解

 本のタイトルのコレクションが与えられます。各タイトルは小文字の文字列です。 これらのタイトルの 1 つが開始点として選択されます。 現在のタイトルから別のタイトルに移動できるのは、現在の文字列のどこかに小文字を 1 文字だけ挿入することによって取得できる場合に限られます。 タスクは、このような有効な遷移を繰り返したどり、可能な限り長い書籍のシーケンスを取得することです。次の各タイトルは、前のタイトルよりちょうど 1 文字長く、その 1 回の挿入操作によって異なります。 

入力サイズは文字列の数という点で小さく、最大でも 1000 タイトルで、各タイトルの長さは最大 80 です。これは、単語に対する O(N^2) アプローチが受け入れられることをすぐに示唆しています。すべてのペアをチェックするだけでも約 100 万回の比較が必要であり、各比較は文字列の長さ 80 によって制限され、最悪の場合でも約 8,000 万文字のチェックが行われます。これは、慎重に実装すれば Python では 1 秒未満でまだ許容可能です。 

主な微妙な点は、トランジションには方向性があるということです。単語は、正確に 1 文字の追加文字を含むサブシーケンスとして含まれる、厳密に長い単語にのみ進むことができます。 単純な間違いは、辞書編集順または部分文字列の包含を想定することです。 どちらでも十分ではありません。 たとえば、「to」と「ttomm」には類似した文字が含まれている可能性がありますが、複数の文字が異なるため、1 回の挿入ステップでは接続できません。 

2 番目の微妙なケースは、単語に対して複数の先行語が存在する可能性があることです。 たとえば、「tomb」は、「tom」と「tobm」の両方が存在する場合、両方から派生する可能性があります。 最長パスでは、貪欲に 1 つを選択するのではなく、考えられるすべての先行パスを考慮する必要があります。 

最後に、グラフには一意の最適なエンドポイントがあることが保証されていますが、中間パスが分岐する可能性があるため、文字列の長さの順序付けによって形成された DAG 内の最長パスを計算する必要があります。 

## アプローチ

 強引な方法は、単語のすべてのペア間に有向グラフを構築することです。ここで、B が正確に A で 1 文字が挿入されている場合、単語 A から単語 B までのエッジが存在します。 次に、開始単語から DFS を実行し、最長パスを計算します。 

挿入条件の検証には 2 ポインター スキャンが必要なため、各ペアのチェックには O(N^2 * L) のコストがかかります (L は文字列の長さ)。 DFS は各ノードから多くのパスを探索し、最悪の場合、指数関数的な動作につながる可能性があります。 

重要な構造上の観察は、すべての有効な移動によって文字列の長さが厳密に 1 だけ増加するということです。 これは、グラフが長さ順に並べられた有向非巡回グラフであることを意味します。 これはすぐに動的プログラミングを示唆しています。単語を長さの昇順に処理すると、すべての状態は短い文字列にのみ依存します。 

dp[word] をその単語から始まる最長のチェーンとして定義できます。 次に、単語ごとに、すべての位置で 1 文字を削除して、結果として短い単語が存在するかどうかを確認します。 逆の視点はより単純です。「挿入して先に進むことができるか」をチェックする代わりに、「1 文字を削除することで有効な先行文字が何であるか」をチェックします。 

これにより、遷移チェックが、すべての単語と比較することから、単語ごとに最大 L 個の候補を生成し、ルックアップをハッシュすることに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グラフ上のブルート フォース DFS | O(N^2 · L + 指数関数パス) | O(N^2) | 遅すぎる |
 | 削除に対するハッシュ ルックアップを使用した DP | O(N・L^2) | O(N・L) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 単語を長さ別にグループ化する

 すべての単語を保存し、長さの降順に並べ替えます。 これにより、単語の dp を計算するときに、順定式化で必要に応じて、考えられるすべての長い単語がすでに処理され、逆に、逆の DP では、すべての短い単語がすでに計算されています。 

使用する方向は逆の DP になります。つまり、長い単語は短い単語に依存します。 

### ステップ 2: すべての単語をハッシュ セットに保存する

O(1) 回の平均時間存在チェックのために、すべての単語をセットに挿入します。 各遷移チェックでは入力コレクションに候補文字列が存在するかどうかが尋ねられるため、これは非常に重要です。 

### ステップ 3: DP の意味を定義する

 dp[w] が、単語 w から始まり、一度に 1 文字ずつ削除することによって下に移動する (同等に、元の方向に挿入することによって上に移動する) 有効なチェーンの最大長を表すものとします。 

これにより、問題はエッジを明示的に構築せずに DAG 内の最長パスを計算することに変わります。 

### ステップ 4: 削除による遷移の計算

 各単語 w について、w からちょうど 1 文字を削除することによって形成されるすべての可能な文字列を生成します。 このような各文字列は、逆グラフの可能な先行文字を表します。 

その短縮された文字列がセット内に存在する場合、それを DP 遷移の有効な次の状態と見なします。 

次のように計算します。 

すべての有効な i にわたる dp[w] = 1 + max(dp[i 番目の文字を除く w])

 有効な先行データが存在しない場合は、dp[w] = 1 となります。 

すべてのエッジが長さをちょうど 1 だけ減らすので、この繰り返しは正しいです。 

### ステップ 5: 単語を長さの昇順に処理する

 dp[w] を計算するときに、すべての dp[短い単語] がすでにわかっているように、長さの増加によって単語をソートして処理します。 

### ステップ 6: 最適な開始点の答えを追跡する

 指定された開始単語に対して最適な dp 値を維持します。 問題は開始ブックを修正するため、単純に dp[start] を出力します。 

### なぜ効果があるのか

 重要な不変条件は、dp 値が語長の位相順序で計算されることです。 すべての遷移によって長さが 1 ずつ厳密に短縮されるため、サイクルやスキップされる依存関係は存在しません。 単語自体を評価する前に、単語の継続が考えられるすべての dp がすでに計算されていることが保証されます。 したがって、再帰では常に完全に解決された部分問題が使用され、結果が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, start = input().split()
    n = int(n)

    words = [input().strip() for _ in range(n)]
    word_set = set(words)

    # dp[word] = longest chain starting from word
    dp = {}

    # sort by length ascending so smaller words first
    words_sorted = sorted(words, key=len)

    for w in words_sorted:
        best = 1

        # try all deletions of one character
        for i in range(len(w)):
            nxt = w[:i] + w[i+1:]
            if nxt in word_set:
                if nxt in dp:
                    best = max(best, dp[nxt] + 1)

        dp[w] = best

    print(dp[start])

if __name__ == "__main__":
    solve()
```このソリューションでは、語長の順序を使用して DP テーブルをボトムアップで構築します。 各単語は可能なすべての単一文字の削除を試み、結果として得られる短い単語が辞書内に存在し、すでに計算された dp 値を持っている場合はチェーンを拡張します。 開始単語の dp 値が直接答えを与えます。 

微妙な点は、隣接リストを明示的に構築する必要がないことです。 削除トリックは、エッジごとに O(NL) 回の比較ではなく、ワードごとに O(L) ですべてのエッジを暗黙的に再構築します。 

## 実用的な例

 ### 例 1

```単語の長さを増やして処理します。 

| 単語 | 削除がチェックされました | 次に有効 | dp[単語] |
 | --- | --- | --- | --- |
 | へ | - | なし | 1 |
 | トム | へ | へ | 2 |
 | 墓 | トム | トム | 3 |
 | トンバ | 墓 | 墓 | 4 |
 | トンバウ | トンバ | トンバ | 5 |
 | 原子 | トム | トム | 2 |
 | アトマ | 原子 | 原子 | 3 |

 ローカルチェーンのみを考慮した場合、開始ワード「tom」は dp = 2 になりますが、正しい最長パスは「tom」で始まり、有効な中間ワードを介してトンバウチェーンをたどり、「トム→トゥーム→トンバ→トンバウ」が得られます。これは、逆依存関係による完全な伝播で 4 として計算された dp[tom] と一致します。 

このトレースは、共有プレフィックスを通じて複数のブランチが単一の最長継続にマージされる様子を示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・L^2) | 各単語は L 回の削除を試み、各文字列の再構築には O(L) | コストがかかります。 
| スペース | O(N・L) | ワード、セット、および dp テーブルのストレージ |

 N ≤ 1000 および L ≤ 80 の場合、最悪の場合は約 1000 × 80 × 80 = 640 万文字の操作となり、十分に制限内に収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、開始単語から拡張できる単語がない場合です。 この状況では、削除ベースの先行チェーンを形成できないため、開始の DP 値は 1 のままになります。 たとえば、入力が次の場合:```
3 xyz
xyz
a
b
```開始ワードには有効な遷移がなく、出力は 1 です。 

もう 1 つの特殊なケースは、複数の単語が複数の文字で異なる場合です。 有効な遷移には 1 文字を正確に削除する必要があるため、削除方法を使用すると、誤って接続されることがなくなります。 2 つのワードの長さが異なるが、単一の削除関係が異なる場合、それらは DP 遷移ステップによって完全に無視され、無効なパスが回避されます。
