 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた値の配列が与えられます。 この配列から、個別のインデックス u と v のすべてのペアが単一のエッジで接続される完全な重み付きグラフを定義します。 そのエッジの重みは 2 つの要素によって決まります。1 つは大きい方のエンドポイント インデックス、もう 1 つは u から v までの範囲に現れる最小の配列値です。 具体的には、u < v の場合、エッジの重みは v と部分配列 a[u..v] の最小値に依存します。 

このグラフが構築されたら、頂点間の単純なパスを検討します。 任意のペア (u, v) について、d(u, v) は、u で始まり v で終わる単純なパスの最大可能合計重みとして定義されます。ここで、パスの長さは、そのパスに沿ったエッジの重みの合計です。 タスクは、個別の頂点のすべてのペアにわたって d(u, v) の最大値を見つけることです。 

制約により、n は 10^6 まで許可されるため、二次関数やペアごとの n log n のアプローチさえも直ちに不可能になります。 すべての間隔で単一の O(n^2) スキャンを実行しただけでも、すでに遅すぎます。 これは、ソリューションがすべてのペアまたはすべてのパスを明示的に考慮することを避け、代わりに最適なパスがどのように動作するかという構造的特性に依存する必要があることを強く示唆しています。 

微妙な問題は、エッジの重みがローカルではないことです。エッジの重みは範囲の最小値に依存します。 これは、実際には重みが区間全体で緊密に結合しているにもかかわらず、グラフが独立したエッジを持つ単純な重み付けされた完全なグラフのように動作すると仮定するという間違いにつながることがよくあります。 もう 1 つの一般的な落とし穴は、2 つのノード間の最適なパスが直接エッジであると仮定することです。これは保証されません。マルチエッジ パスは、ネストされたセグメント上での最小値の動作を利用して、より大きな合計重みを蓄積する可能性があるためです。 

たとえば、小規模なインスタンスでは、最小値を減らす小さな値が間隔に含まれているため、直接エッジは中程度である可能性がありますが、間隔をより小さな単調な部分に分割する慎重に選択されたパスは、その小さな値を回避し、合計の重みを増加させる可能性があります。 この非ローカルなインタラクションはまさに処理しなければならないものです。 

## アプローチ

 直接的なブルート フォース アプローチでは、すべてのペア (u, v) について、セグメント a[u..v] の最小値を計算し、完全なグラフ内の u と v の間のすべての単純なパスを探索しようとします。 長さ n までの単純なパスに注意を限定したとしても、これは組み合わせ爆発的になります。 完全なグラフ内で考えられる単純なパスの数は超指数関数的に増加し、単一のパスを評価する場合でも、その長さは線形です。 このアプローチは、n が数十に達するずっと前に明らかに実行不可能です。 

重要な観察は、グラフは完全ですが、エッジ構造は完全にセグメント最小値によって支配されるということです。 これにより、自然な階層が作成されます。値 a[k] がある区間で最小値になると、その区間内のエッジの動作を制限するボトルネックとして機能します。 すべての値が少なくとも a[k] である領域内にあるパスは、一様に a[k] の影響を受けるエッジの重みを持ちます。 

これは、セグメントの潜在的な「アクティブな最小値」として各インデックス k を中心に問題を再設定することを示唆しています。 固定 k の場合、a[k] が最小値である最大の連続セグメントを調べることができます。これは、そのセグメント内のすべての値が少なくとも a[k] であることを意味します。 このようなセグメント内では、k を含む部分区間の最小値は常に正確に a[k] になります。 これにより、エッジの重みの曖昧さが取り除かれ、エッジの重みがエンドポイントの決定論的な関数に変わります。 

セグメントが固定されたら、パス ウェイトを蓄積する最良の方法は、セグメント全体でインデックスの昇順で頂点をトラバースすることです。これは、各エッジがその右端点に関連付けられた予測可能な量に寄与するためです。 これにより、パスの最適化が間隔合計に対する純粋な算術最大化に変換されます。

 | すべてのパスに対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | セグメント最小分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのインデックス k について、a[k] より厳密に小さい値が現れる左に最も近い位置と、同じプロパティを持つ右に最も近い位置を計算します。 これにより、最大間隔 [L[k], R[k]] が得られます。ここで、a[k] は最小値です。 これが機能する理由は、これらの境界を超える拡張により、制御最小値としての k を無効にする小さな要素が導入されるためです。 
2. 中心インデックス k を固定し、セグメント [L[k], R[k]] のみを考慮します。 このセグメント内では、これより小さい値は存在しないため、k を含むすべての部分区間の最小値は正確に a[k] になります。 
3. [L[k], R[k]] 内で、インデックスの昇順で頂点を訪れる単純なパスを構築することを検討します。 [i, i+1] の最小値が a[k] であるため、すべてのエッジ (i, i+1) の重みは (i+1) と a[k] の積によって決定されるため、この選択は重要です。 
4. この走査の合計寄与を、右エンドポイントとして使用されるインデックスの合計の a[k] 倍として計算します。 

(L[k]+1) + (L[k]+2) + ... + R[k]。 この合計は、等差級数の接頭辞の合計を使用して表現できます。 
5. この値を k ごとに評価し、最大値を取得します。 

中心的な考え方は、各 k がすべての間隔最小値を支配する「制御領域」を定義し、その領域内では最適パスが決定的となり、間隔演算のみに依存するということです。 

### なぜ効果があるのか

 有効なセグメント内のすべてのエッジの重みは、その右の端点にセグメントの最小値を乗算した値のみに依存します。 a[k] が最小となる最大領域に制限すると、すべてのエッジが係数 a[k] と一貫して動作します。 この領域から出ようとするパスはすぐに小さい値に遭遇し、制御最小値が厳密に減少し、最適な構造が崩れてしまいます。 したがって、任意のペアに対して達成可能な最良のパスは、これらの最大-最小セグメントの 1 つに完全に含まれており、そのようなセグメント内では、昇順の走査によって累積されたエンドポイントの寄与が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # 1-indexed padding for convenience
    a = [0] + a

    L = [0] * (n + 1)
    R = [0] * (n + 1)

    stack = []

    # previous strictly smaller
    for i in range(1, n + 1):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()
        L[i] = stack[-1] + 1 if stack else 1
        stack.append(i)

    stack.clear()

    # next strictly smaller
    for i in range(n, 0, -1):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        R[i] = stack[-1] - 1 if stack else n
        stack.append(i)

    # prefix sums of indices
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + i

    def range_sum(l, r):
        return pref[r] - pref[l - 1]

    ans = 0

    for i in range(1, n + 1):
        l, r = L[i], R[i]
        if l <= i <= r:
            cost = a[i] * (range_sum(l + 1, r))
            ans = max(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、単調スタックを使用して両側の最も近い小さい要素を計算することから始まります。 左側の境界は、厳密には小さくない要素をポップすることによって計算され、結果として得られる間隔内のすべてが少なくとも a[i] であることが保証されます。 右側の境界は対称的に計算されます。 

インデックスのプレフィックス合計により、任意のセグメントの算術合計を定数時間で評価できます。 最終的な式は連続するインデックスの合計に依存するため、これが必要になります。 

最後に、位置ごとに、その値とその有効なセグメント内のすべての可能な正しいエンドポイントの合計の積として、その寄与を計算します。 すべてのポジションにわたって最大値を追跡します。 

## 実用的な例

 小さな配列を考えてみましょう。 

入力:```
n = 5
a = [3, 1, 4, 2, 5]
```境界を計算します。 

| 私 | a[i] | L[i] | R[i] |
 | --- | --- | --- | --- |
 | 1 | 3 | 1 | 2 |
 | 2 | 1 | 1 | 5 |
 | 3 | 4 | 3 | 4 |
 | 4 | 2 | 3 | 5 |
 | 5 | 5 | 5 | 5 |

 次に寄与を計算します。 

| 私 | セグメント [L,R] | 合計 (L+1..R) | 値 |
 | --- | --- | --- | --- |
 | 1 | [1,2] | 2 | 3 * 2 = 6 |
 | 2 | [1,5] | 14 | 1 * 14 = 14 |
 | 3 | [3,4] | 4 | 4 * 4 = 16 |
 | 4 | [3,5] | 9 | 2 * 9 = 18 |
 | 5 | [5,5] | 0 | 0 |

 最大値は 18 で、i = 4 で達成されます。 

これは、グローバル最大値ではない場合でも、有効なセグメントが広いため、適度な値を持つ中間要素がどのように優位に立つことができるかを示しています。

| スペース | O(n) | 境界とプレフィックス合計の配列 |

 ## 特殊なケース

 n = 1 の場合、グラフには頂点が 1 つでエッジがないため、パスは存在せず、答えは 0 になります。両方の境界が同じインデックスに折りたたまれ、長さの合計が 0 になるため、アルゴリズムはこれを処理します。 

すべての値が等しい配列の場合、すべてのインデックスは有効範囲として完全なセグメント [1, n] を持ちます。 アルゴリズムは同じ寄与構造を各インデックスに正しく割り当て、最大値は最大算術合計にその定数値を乗算したものになります。 

配列を厳密に減少または増加させる場合、各要素の有効範囲は非常に狭いため、誤った大きなセグメントが形成されることはありません。 単調スタック境界により、セグメントがすぐ隣に正しく縮小され、過大評価が防止されます。
