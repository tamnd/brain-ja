 ## 解決策
 ## 問題の理解

 2 つの隠れた数字から得られる 2 つの整数が与えられます。$a$そして$b$。 明らかにする代わりに$a$そして$b$直接的には、その合計だけが伝えられます$a + b$とそれらのビットごとの AND$a \land b$。 タスクはビットごとの XOR を回復することです$a \oplus b$。 

主な難点は、加算ではビットとキャリーが混在するのに対し、両方の数値が 1 ビットを持つ場合は AND でキャプチャされることです。 XOR は異なるビットを正確にキャプチャするため、目的は明示的に再構築せずにそれを再構築することです。$a$そして$b$。 

制約により許可されるのは、$a, b \le 10^9$これは、値が 31 ビット内に収まることを意味します。 これは十分に小さいため、ビット単位の推論は完全に安全であり、定数時間の演算で十分です。 ビット単位の線形時間または O(1) 演算で機能するソリューションであれば十分です。 検索ではなく再構築のみを行っているため、すべてのペアに対するブルート フォースは無関係です。 

ここでの素朴な間違いは、次のように仮定することです。$a + b = a \oplus b$。 キャリーがある場合、これはすぐに失敗します。 たとえば、次の場合$a = 1$そして$b = 1$、 それから$a + b = 2$しかし$a \oplus b = 0$。 もう 1 つの失敗例は、AND が XOR に直接寄与するが、AND は実際に追加で _create キャリー_ される共有ビットを表すと想定している場合です。 

より微妙なエッジ ケースは、AND が合計に対して大きい場合です。 たとえば、次の場合$a = 3$そして$b = 2$、 それから$a + b = 5$、$a \land b = 2$、XOR は$1$。 キャリーの 2 の係数を無視する誤った再配置は、ここで失敗します。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアを列挙しようとします。$(a, b)$指定された合計と AND との一致を確認してから、XOR を直接計算します。 以来$a$そして$b$まで可能です$10^9$、これにより、実行不可能なサイズの検索スペースが発生します$10^{18}$。 枝刈りを行っても、複数のビット構成が同じ合計と AND に一致する可能性があるため、列挙を可能にする構造はありません。 

重要な洞察は、標準の ID 接続加算、XOR、および AND を使用することです。$$a + b = (a \oplus b) + 2 \cdot (a \land b)$$これは、各ビットを個別に調べることから得られます。 各ビット位置で両方のビットが 1 の場合、次のレベルの合計に 2 が寄与します。これはまさに AND エンコードです。 XOR は、残りのペアになっていない 1 ビットをキャプチャします。 これらの寄与はビット間で干渉しないため、同一性はグローバルに保持されます。 

並べ替えると次のようになります。$$a \oplus b = (a + b) - 2 \cdot (a \land b)$$したがって、問題全体は 1 つの算術式に帰着します。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります$s = a + b$そして$c = a \land b$。 これらは、隠された番号について提供される唯一の情報です。 
2. ID を使用して XOR を計算します。$x = s - 2c$。 これが機能するのは、AND でカウントされたすべての共有ビットが、バイナリ キャリーの伝播により合計に 2 倍寄与するためです。 
3. 計算された XOR 値を直接出力します。 

### なぜ効果があるのか

 各ビット位置は独立して算術構造に寄与します。 両方にビットが設定されている場合$a$そして$b$、合計のそのビット レベルで 2 が寄与し、その寄与は正確にエンコードされます。$2 \cdot (a \land b)$。 これらのキャリーを除去した後の残りの寄与は、XOR ビットに正確に対応します。 すでに考慮されているキャリーを超えるクロスビット干渉はないため、AND を 2 回減算することで XOR を一意に分離します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s, c = map(int, input().split())
    print(s - 2 * c)

if __name__ == "__main__":
    solve()
```実装では、派生 ID が直接適用されます。 再構築する必要はありません$a$または$b$であり、ビットごとのシミュレーションは必要ありません。 唯一の微妙な点は、減算の前に AND 値に 2 の乗算が確実に適用されるようにすることです。 より複雑な式では演算子の優先順位により、順序を逆にすると正しくなくなりますが、Python ではこの特定の行は記述どおりに安全です。 

## 実用的な例

 提供されているサンプル入力を使用します。 

入力：```
5 2
```これを次のように解釈します$a + b = 5$そして$a \land b = 2$。 

段階的に計算してみましょう:

 | ステップ | 値 |
 | --- | --- |
 | 和$s$| 5 |
 | そして$c$| 2 |
 | XOR$s - 2c$| 5 - 4 = 1 |

 したがって、出力は 1 になります。 

これは有効な再構成と一致します。たとえば、$a = 3$、$b = 2$。 2 進数では、3 = 011 および 2 = 010 となるため、AND は 010 (2)、合計は 5、XOR は 001 (1) になります。 

2 番目の構築例:

 入力:```
10 2
```試す$a = 8$、$b = 2$。 この場合、合計は 10、AND は 0 となるため、XOR は 10 になるはずです。式を適用すると、次のようになります。 

| ステップ | 値 |
 | --- | --- |
 | 和$s$| 10 |
 | そして$c$| 0 |
 | XOR$s - 2c$| 10 |

 これにより、重複するビットが存在しない場合に正しいことが確認されます。

 ## 特殊なケース

 入力用$0\ 0$、両方の数値がゼロであるため、AND はゼロとなり、合計はゼロになります。 式は次のようになります$0 - 0 = 0$、それは正しいです。 隠されたキャリー構造がないため、XOR もゼロでなければなりません。 

入力用$7\ 7$、両方の数値が同一であると解釈します。 この場合、合計は 14、AND は 7 になります。アルゴリズムを適用すると、次のようになります。$14 - 14 = 0$。 ビット単位では、同一の数値は常にゼロと XOR され、式はすべての共有寄与を 2 回正しくキャンセルし、何も残しません。
