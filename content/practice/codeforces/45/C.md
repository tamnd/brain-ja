 ## 解決策
 ## 問題の理解

 私たちには、男の子か女の子として識別され、数値的なダンススキルを持つ人々の列が与えられます。 このラインは、隣り合っていてスキルの差が最も小さい男の子と女の子からなるカップルが踊りに出るにつれて、時間の経過とともに進化していきます。 カップルが離れると、残りのラインは自動的に「閉じる」ので、人々は互いに近づき、有効な男の子と女の子の隣接するペアがなくなるまでこのプロセスが繰り返されます。 課題は、カップルが出発する順序と、どの個体がペアになるかを決定することです。 人々は番号付けの目的で元の位置を保持します。 

制約は次のことを教えてくれます`n`最大 200,000 まで可能です。 各ステップでライン内のすべてのペアをチェックする単純なアプローチでは、次の順序で検査する必要がある可能性があります。$n^2$隣接するペアを繰り返し実行するため、最大 4・10^10 の演算が行われます。 これは 2 秒の制限をはるかに超えているため、O(n log n) または O(n) に近い値が必要です。 スキル値は最大 10^7 まで可能で、アルゴリズムの選択には影響しませんが、整数で十分であることが確認されます。 

複数の隣接するペアが同じ最小限のスキル差を持つ場合、微妙なエッジケースが発生します。 この場合、タイブレーカーは左端のペアになります。 単純なアプローチでは、削除後の隣接関係の変更を考慮せずに最初の最小の違いだけを探すため、誤ってペアを中央から削除する可能性があります。 もう 1 つの特殊なケースは、隣接する異性のメンバーがいない男の子または女の子が連続して存在する場合です。これらの人々は決してペアを形成しません。 

具体的な例でこれを説明します。 次の入力を考えてみましょう。```
3
BBG
1 2 3
```有効なペアは最後の男の子と女の子だけです。 単純なアプローチでは、最初の 2 つをペアにしようとして、それらが同性であることを認識できない可能性があります。 正しい出力にはペア (2,3) のみがリストされるはずです。 

## アプローチ

 ブルートフォースアプローチは、ラインを左から右に繰り返し走査し、隣接する各男の子と女の子のペアのスキルの絶対的な差を計算し、最小の差を選択してペアを削除することによって機能します。 これは、説明されているルールに正確に従っているため正しいですが、n = 200,000 の場合は遅すぎます。 各スキャンは O(n) になる可能性があり、すべてのカップルが個別に出発する場合は O(n) 回のスキャンを実行する可能性があり、複雑さは O(n^2) になります。 

最適解の重要な観察は、どの時点においても、隣接する男の子と女の子のペアのみが候補となり得るということです。 ペアが削除されると、削除された要素に直接隣接するペアのみがその最小差を変更できる可能性があります。 これは当然、**優先キュー** を使用して、現在の隣接するすべての男の子と女の子のペアをスキルの差によって追跡することを示唆しています。 優先キューの各エントリには、スキルの差とペアのインデックスが格納されます。 カップルを削除するときは、影響を受けるペアをキューから削除し、それらの隣接ペアによって形成された新しいペアを追加します。 これにより、冗長なチェックが減り、常に最小の差分を効率的に選択できるようになります。 

ブルートフォースが機能するのは、問題の説明に文字通り従うためです。 n が大きい場合、隣接するすべての差分を繰り返し再計算するとコストが高すぎるため、失敗します。 誰かが去ったときに隣接するペアのみが変化するという観察により、問題を隣接するペアとその差異を効率的に維持することに帰着させることができ、これによりはるかに高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (プライオリティ キュー + リンク リスト) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して、人物、性別、スキルのリストを取得します。 出力用に各人に独自のインデックスを割り当てます。 
2. 線を表す二重リンクリストを作成します。 これにより、要素を一定時間削除し、隣接要素に迅速にアクセスできるようになります。 
3. 隣接するすべての男の子と女の子のペアを特定し、それらのスキルの差を計算します。 各ペアを、差分をキーとした最小ヒープ優先キューに挿入します。 インデックスだけでなく、リンク リスト ノードへのポインタも格納します。 
4. 優先キューが空ではない間に、次の操作を行います。 

1. 最小差分ペアをヒープからポップします。 両方のノードがまだリストに含まれていることを確認します。 いずれかがすでに削除されている場合は、このペアを破棄します。 
2. 出力用にペアのインデックスを昇順に並べて記録します。 
3. 両方のノードをリンク リストから削除します。 
4. 削除によって作成された新しい隣接を調べます。 新しい隣接する男の子と女の子のペアが存在する場合、その差を計算してヒープに追加します。 
5. 形成されたペアの総数とペアのリストを順番に出力します。 

このアルゴリズムが機能するのは、不変条件を維持しているためです。つまり、優先キューには、ラインの現時点で存在するすべての有効な隣接する男の子と女の子のペアが常に含まれています。 削除後に隣接ノードによって形成された新しいペアを追加するだけで、ヒープが常に次の最小の差を反映することが保証されます。 ノードがまだ存在するかどうかを確認することで、古いペアの使用を防ぎます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

class Node:
    def __init__(self, idx, gender, skill):
        self.idx = idx
        self.gender = gender
        self.skill = skill
        self.prev = None
        self.next = None
        self.alive = True

n = int(input())
genders = input().strip()
skills = list(map(int, input().split()))

nodes = [Node(i+1, genders[i], skills[i]) for i in range(n)]
for i in range(n-1):
    nodes[i].next = nodes[i+1]
    nodes[i+1].prev = nodes[i]

heap = []

def push_pair(left, right):
    if left.alive and right.alive and left.gender != right.gender:
        diff = abs(left.skill - right.skill)
        heapq.heappush(heap, (diff, left.idx, right.idx, left, right))

for i in range(n-1):
    push_pair(nodes[i], nodes[i+1])

result = []

while heap:
    diff, idx1, idx2, left, right = heapq.heappop(heap)
    if not left.alive or not right.alive:
        continue
    result.append((min(left.idx, right.idx), max(left.idx, right.idx)))
    left.alive = right.alive = False
    # Link neighbors
    if left.prev:
        left.prev.next = right.next
    if right.next:
        right.next.prev = left.prev
    if left.prev and right.next:
        push_pair(left.prev, right.next)

print(len(result))
for a,b in result:
    print(a,b)
```このコードは、人々を表すノードのリンクされたリストを構築します。 各ノードは、近隣ノードへのポインタと、そのノードが削除されたかどうかを示すフラグを格納します。 有効な隣接する男の子と女の子のペアのみがヒープに追加されます。 ペアを削除した後、削除によって作成された新しい隣接関係を確認し、それをヒープにプッシュします。 使用する`alive`すでにラインから削除されている古いペアの使用を防ぎます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 隣接する各ペアは最大 1 回だけヒープに追加されます。 ヒープ操作はログ n です。 |
 | スペース | O(n) | リンク リストのノードとヒープ エントリは、n に応じて線形にスケールします。 |

 n ≤ 2・10^5 の場合、O(n log n) 操作は 2 秒以内に収まります。
