 ## 解決策
 ## 問題の理解

 各イベントには、それが発生する可能性のある日の範囲があります。 のために$i$- 番目のイベント、間の任意の整数日$l_i$そして$r_i$許容されます。 すべてのイベントに正確に 1 日を割り当てる必要があり、2 つのイベントが同じ日を共有することはできません。 

タスクは、割り当てをカウントしたり、何かを最適化したりすることではありません。 有効な割り当てを 1 つ作成するだけで済みます。 

制約は驚くほど小さいです。 イベントは最大 100 個ありますが、日の値自体は最大 100 個まで大きくなります。$10^7$。 座標範囲が巨大であるため、日数でインデックス付けされた配列を構築できないことを意味しますが、間隔の数が少ないため、$O(n^2)$または$O(n^3)$解決策はまったく問題ありません。 のようなものでも$100^3 = 10^6$操作は制限内に簡単に収まります。 

難しいのは、局所的に合理的な選択をすると、後で終了する可能性が失われる可能性があることです。 イベントを入力順に処理し、常に最も早い未使用日を選択するとします。 

次の例を考えてみましょう。```
2
1 100
1 1
```1 日目を最初のイベントに割り当てると、2 番目のイベントは不可能になります。 正しい割り当ては次のとおりです。```
2 1
```狭い間隔を優先する必要があります。 

いくつかの間隔が重なり合う場合、別の微妙なケースが発生します。```
3
1 2
1 2
2 2
```不注意で貪欲な戦略により、次のものが割り当てられる可能性があります。```
1 2 ?
```そして最後のイベントで行き詰まってしまいます。 唯一の有効な構造は次のとおりです。```
1 2 2
```日は区別されなければならないため、これは不可能です。 これは、実際の有効な割り当ては次のようにする必要があることを意味します。```
1 ? 2
```残りの間隔は未使用の 1 日目を取得しますが、これも失敗します。 よく見ると、この入力には実際には解決策がありません。 このステートメントは解決可能性を保証していますが、この例は、貪欲な決定がなぜ重要なのかを示しています。 

Now consider a valid version:```
3
1 3
1 2
2 3
```間違った順序で日付を選択すると、解決策が存在する場合でも失敗する可能性があります。 堅牢なアルゴリズムは将来の柔軟性を維持する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての間隔内で可能な限りすべての日を試行し、2 つのイベントが衝突するたびにバックトラックします。 各間隔は最大で次の範囲に及ぶ可能性があるため、$10^7$値を指定すると、検索空間は天文学的に大きくなります。 間隔が狭い場合でも、課題の数が近づく可能性があります$n!$、それはすぐに実行不可能になります。 

この問題は間隔制約を満たす個別の割り当ての存在のみを要求するため、総当たりアプローチは概念的に機能します。 バックトラッキングでは、自然に、可能性が見つかるまですべての可能性を探索します。 問題は、膨大な量の作業が繰り返され、間隔の構造がまったく利用されていないことです。 

重要な観察は、間隔が適切なエンドポイントで処理されると適切に動作するということです。 イベントが他のイベントより早く終了する場合、利用可能な選択肢がすぐになくなるため、イベントを遅らせることは危険です。 

これは、古典的な貪欲な戦略につながります。 

1. 右端点を増やして間隔を並べ替えます。 
2. 間隔ごとに、その間隔内にまだ残っている最小の未使用日を割り当てます。 

利用可能な最小日が役立つのはなぜですか? 将来必要になる可能性のある間隔で、より大きな日数が利用できるためです。 適切なエンドポイントによる並べ替えが役立つのはなぜですか? 期限が厳しい間隔は、柔軟な間隔よりも先に処理されるためです。 

間隔を処理するとします$[l, r]$。 その中で最も早い未使用日を選択すると、実行可能な小さな日はすべて、より小さいか等しい右端点を持つ間隔によってすでに占有されています。 これらの間隔は後で安全に移動できませんが、現在の間隔はまだ移動できます。 

以来$n \le 100$、洗練されたデータ構造は必要ありません。 から順にスキャンするだけです$l$空いている日が見つかるまで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 |$O(n)$再帰スタック | 遅すぎる |
 | 最適な貪欲さ |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を読み取り、元のインデックスを記憶します。 

処理中に間隔を並べ替えますが、出力は入力順序に従う必要があります。 
2. 右端点を増加させて間隔を並べ替えます。 

間隔が早く終了するほど、制限が厳しくなります。 最初にそれらに対処することで、将来の行き詰まりを防ぎます。 
3. すでに使用した一連の日数を維持します。 

割り当てられた日はそれぞれ一意である必要があります。 
4. インターバルごとに$[l, r]$ソート順、スキャン日は次から始まります$l$。 

間隔内の最初の未使用日を検索します。 
5. 最初の未使用日を割り当てます。$d$そのような$l \le d \le r$。 

実行可能な最小の日を選択すると、将来の間隔のために大きな日が保存されます。 
6. 間隔の元のインデックスを使用して、割り当てられた日を応答配列に保存します。 

これにより、必要な出力順序が復元されます。 
7. 回答配列を出力します。 

### なぜ効果があるのか

 間隔は正しいエンドポイントの昇順で処理されるため、貪欲な選択は安全です。 

インターバルを扱う場合$[l, r]$、以前に処理されたすべての間隔には、多くても正しいエンドポイントがあります$r$。 これらの間隔は、少なくとも現在の間隔と同じくらい緊急です。 現在の間隔に利用可能な最小の日を割り当てると、右側のエンドポイントが大きくなる、後の間隔のためにできるだけ多くの余地が残ります。 

アルゴリズムが日を割り当てるとします。$d$現在の間隔に戻ります。 実行可能な小さな日はすべて、以前の間隔ですでに使用されています。 それらの以前の間隔の 1 つをより大きな日に変更すると、その期限が現在の間隔の期限よりも遅くないため、状況はさらに悪化するだけです。 

この交換引数は、有効な解決策が存在する場合、貪欲な割り当てによってそれがブロックされることがないことを示しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

events = []

for i in range(n):
    l, r = map(int, input().split())
    events.append((r, l, i))

events.sort()

used = set()
ans = [0] * n

for r, l, idx in events:
    day = l

    while day in used:
        day += 1

    ans[idx] = day
    used.add(day)

print(*ans)
```この解決策は、各間隔を元の位置とともに保存することから始まります。 タプルの順序は`(r, l, idx)`Python はタプルを辞書順にソートするため、右のエンドポイントを増やすことによって間隔が自動的に順序付けされます。 

の`used`日付がすでに割り当てられているトラックを設定します。 イベントは 100 個しか存在しないため、ハッシュ セットで十分です。 

各間隔で、コードは次から上方向にスキャンします。`l`。 このステートメントは、有効な割り当てが存在することを保証するため、最終的に未使用の日が次を超えないようにします。`r`が現れます。 可解性が保証されているため、ループ内で明示的な境界チェックを行う必要はありません。 

微妙な点の 1 つは、出力順序の保持です。 並べ替え後、間隔は元の位置になくなります。 の`idx`フィールドを使用すると、選択した日をそれぞれ回答配列の正しいスロットに戻すことができます。 

もう 1 つの微妙な点は、アルゴリズムが任意の日ではなく、利用可能な最も早い日を意図的に選択することです。 後の日を選択すると、後で狭い間隔を簡単にブロックしてしまう可能性があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    events = []

    for i in range(n):
        l, r = map(int, input().split())
        events.append((r, l, i))

    events.sort()

    used = set()
    ans = [0] * n

    for r, l, idx in events:
        day = l

        while day in used:
            day += 1

        ans[idx] = day
        used.add(day)

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run(
"""3
1 2
2 3
3 4
"""
) == "1 2 3", "sample 1"

# minimum size
assert run(
"""1
5 5
"""
) == "5", "single interval"

# intervals requiring sorting by deadline
assert run(
"""4
1 100
1 1
2 2
3 3
"""
) == "4 1 2 3", "deadline priority"

# all intervals identical
out = run(
"""3
1 3
1 3
1 3
"""
)
vals = list(map(int, out.split()))
assert sorted(vals) == [1, 2, 3], "distinct assignments"

# off-by-one boundary case
assert run(
"""2
1 1
2 2
"""
) == "1 2", "boundary endpoints"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 ある間隔が非常に柔軟である一方で、別の間隔には可能な日が 1 日しかない場合を考えてみましょう。```
2
1 100
1 1
```アルゴリズムは正しいエンドポイントで並べ替えます。```
[1,1], [1,100]
```シングルトン間隔はすぐに 1 日目を受け取ります。その後、フレキシブル間隔は 2 日目を受け取ります。最終出力は次のようになります。```
2 1
```単純な入力順序の貪欲な戦略は、1 日目をあまりにも早く消費してしまうため、ここでは失敗します。 

ここで、締め切りが厳しい重複した間隔を検討してください。```
4
1 2
1 2
2 3
3 4
```並べ替えられた順序:```
[1,2], [1,2], [2,3], [3,4]
```割り当ては次のように進められます。 

| 間隔 | 割り当てられた日 |
 | --- | --- |
 | [1,2] | 1 |
 | [1,2] | 2 |
 | [2,3] | 3 |
 | [3,4] | 4 |

 すべての間隔には、未使用の実行可能な最も早い日が含まれます。 このアルゴリズムは、わずかな日を不必要に無駄にすることはありません。 

最後に、すでに自然に順序付けられているが、境界で接している間隔について考えてみましょう。```
3
1 1
1 2
2 2
```並べ替えられた順序:```
[1,1], [1,2], [2,2]
```課題:

 | 間隔 | 割り当てられた日 |
 | --- | --- |
 | [1,1] | 1 |
 | [1,2] | 2 |
 | [2,2] | 不可能 |

 この入力には有効な解決策がありません。これは、そのようなケースが決して発生しないという問題の保証と一致します。 この例は、エンドポイントを不注意に使用すると、すぐに実現可能性が損なわれる可能性があることを示しています。
