 ## 解決策
 ## 問題の理解

 各生徒は、ニュースを聞くたびに電話をかける他の生徒を正確に 1 人指差します。 これにより、有向関数グラフが作成され、すべてのノードの出次数が 1 つだけになります。 

当日`i`、一人の生徒が最初の力でニュースを広め始めます。`b[i]`。 ニュースが転送されるたびに、その強度は 1 ずつ減少します。 強度がゼロになると転送が停止します。 サイクルが許可されているため、生徒は同じ日に異なる強度で同じニュースを複数回受け取る可能性があります。 

学生がニュースを合計何回聞くかは尋ねられません。 私たちが気にするのは、各生徒がニュースを初めて知った日だけです。 毎日、その日に何人の生徒が初めて情報を知ったかを出力する必要があります。 

開始生徒は直接与えられません。 その代わり、$$a_i = ((v_i + res_{i-1}) \bmod n) + 1$$どこ`res[i-1]`前日の回答です。 

グラフのサイズと日数は両方とも最大です`10^5`。 すべての通話を直接シミュレーションすることは不可能です。`b[i]`と同じ大きさにすることもできます`10^7`。 単純に実装すると、単一のクエリでも何百万ものエッジを走査する必要がある場合があります。 

二次関数または偶数`O(n * sqrt(n))`2秒以内の接近は危険です。 目標は、全体の複雑さを線形に近づけることです。 

難しいのは、パスがサイクルに入る可能性があることです。 ただ歩くだけなら`b[i]`毎日、同じ頂点を繰り返し訪問します。 もう 1 つの微妙な問題は、生徒が以前の日にすでにニュースを聞いた場合、その生徒を再度カウントしてはいけないことです。 

次の例を考えてみましょう。```
3 1
2 3 1
1
10
```グラフは 1 つのサイクルです。`1 -> 2 -> 3 -> 1`。 

概念的にはニュースは永遠にループしますが、強さはステップごとに減少します。 強さをもって`10`、どの生徒も何度も聞きます。 正しい答えは次のとおりです。```
3
```初めての発見ではなく、すべての訪問をカウントする不注意な実装では、はるかに大きな値が生成されます。 

もう 1 つの危険なケースは、開始する生徒がすでに事前に通知されていた場合です。```
3 2
2 3 1
1 1
2 2
```1 日目は学生に通知します`2`そして`3`から始まる`2`。 

2日目はまたここから始まります`2`、しかし、もう誰も新しい人はいません。 正しい出力は次のとおりです。```
2
0
```グローバルな「既知の」状態を数日にわたって維持することを忘れると、繰り返された発見を誤ってカウントしてしまいます。 

もう 1 つの微妙なケースが次の場合に現れます。`b[i]`個別に到達可能な頂点の数を超えています:```
4 1
2 3 4 2
1
100
```からの到達可能なセット`2`だけです`{2,3,4}`なぜなら、グラフは最終的にそれらのノード内で循環するからです。 答えはまだ次のとおりです。```
3
```単純な実装では、同じサイクルを繰り返し実行するために膨大な時間を浪費する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、説明どおりのプロセスに従います。 

毎日:

 1. 開始生徒を計算する`a[i]`。 
2. 出力エッジに沿って上まで歩きます。`b[i]`回。 
3. 訪問した生徒全員に、ニュースを聞くのが初めてかどうかを通知済みとしてマークします。 

ニュースの伝播は文字通り長い距離を歩くものであるため、このシミュレーションは正しいです。`b[i]`関数グラフで。 

問題は複雑さです。 最悪の場合、`b[i] = 10^7`そして`m = 10^5`。 つまり、最大`10^12`実現可能な限界をはるかに超えたエッジトラバーサル。 

重要な観察は、どの生徒も重要なのは一度だけだということです。 生徒が情報を受け取った後は、その後その生徒を訪問しても、二度と答えに寄与することはありません。 

これにより問題は完全に変わります。 すべての送信をシミュレートするのではなく、すでに知られている生徒を効率的にスキップするだけで済みます。 

伝播経路に沿って歩いていると仮定します。 すでに情報を与えられている生徒に遭遇した場合、その頂点を処理しても無駄です。 まだ情報が得られていない次の頂点に素早くジャンプする構造が必要です。 

これはまさに Disjoint Set Union が実行できることです。 

私たちは、DSU のような「次の生きている頂点」構造を維持します。 学生に通知が届くと、グラフ内の後任者にリンクして検討対象から除外します。 今後の走査では、それらは自動的にスキップされます。 

グラフは機能するため、すべてのノードには出力エッジが 1 つだけあります。 これにより、この圧縮プロセスが特に効率的になります。 ノードは一度処理されると、事実上永久に消滅します。 

結果として得られるアルゴリズムは、各生徒を全日にわたって最大 1 回処理します。 これにより、合計作業時間がほぼ直線的な時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\sum b_i)$|$O(n)$| 遅すぎる |
 | 最適 |$O((n + m)\alpha(n))$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 友情グラフを配列として保存する`g`、 どこ`g[x]`に呼ばれた次の生徒は`x`。 
2. 配列を維持する`seen`生徒が以前に何かニュースを聞いたかどうかを示します。 
3. DSU スタイルのジャンプ構造を構築する`parent`。 

すべての生徒にとって`x`、`find(x)`まだ情報が得られていない可能性がある次の候補頂点を返します。 
4. 最初は、すべての頂点がそれ自体の代表です。 
5. 学生時代`x`初めて知らされる：

 - マーク`seen[x] = True`。 
- 取り除く`x`次のように設定することで、将来の考慮事項から除外します。```
parent[x] = find(g[x])
```これは、今後の走査が次の潜在的に有用な頂点に向かって直接スキップされることを意味します。 
6. 毎日:

 - コンピューティング$$a = ((v_i + prev) \bmod n) + 1$$どこ`prev`昨日の答えです。 

- から始める`cur = find(a)`。 
7. 一方:

 -`cur`まだ処理されていない、
 - そして私たちにはまだ力が残っています、

 現在の学生を処理します。 

1 回の転送ステップが発生するため、処理されたすべての生徒は 1 単位の強度を消費します。 
8. 生徒を処理した後:

 - 今日の答えを増やします。 
- DSU 構造から学生を削除します。 
- 次に利用可能な候補に直接ジャンプします。 
9. 今日の答えを出力し、次のように保存します。`prev`。 

### なぜ効果があるのか

 DSU の不変式は次のとおりです。`find(x)`常に、最初に連絡可能な何も知らない学生を返します。`x`友人関係のエッジを繰り返したどり、すでに情報を得ている生徒をすべてスキップすることによって。 

学生に通知が届くたびに、学生を次の候補者に永久にリダイレクトします。 パス圧縮により、今後の検索が非常に高速になることが保証されます。 

すべての生徒が情報のない状態から情報のある状態に移行するのは 1 回だけであるため、各ノードが構造から削除されるのは最大 1 回だけです。 これは、全日を通じた実際の作業量の合計を制限します。 

伝播プロセス自体は正確に保存されます。 私たちは今も同じ順序で同じ友情の連鎖をたどっています。 DSU は、回答に影響を及ぼさなくなった頂点のみをスキップします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

g = [0] + list(map(int, input().split()))
v = list(map(int, input().split()))
b = list(map(int, input().split()))

parent = list(range(n + 1))
seen = [False] * (n + 1)

def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]

prev = 0

for i in range(m):
    a = ((v[i] + prev) % n) + 1

    ans = 0
    steps = b[i]

    cur = find(a)

    while steps > 0 and not seen[cur]:
        ans += 1
        seen[cur] = True
        steps -= 1

        nxt = find(g[cur])
        parent[cur] = nxt

        cur = nxt

    print(ans)
    prev = ans
```中心的な考え方は、情報を与えられた学生が今後の探索から永久に排除されるということです。 

の`find`この関数は、標準の DSU パス圧縮を実行します。 十分な操作が行われると、チェーンは非常に短くなり、ほぼ一定時間のアクセスが可能になります。 

最もデリケートな部分は次の行です。```
parent[cur] = find(g[cur])
```ただ書くだけではありません`parent[cur] = g[cur]`。 友人はすでに削除されている可能性があるため、次のアクティブな代表者に直接ジャンプする必要があります。 

もう 1 つの微妙な詳細は、ループ条件です。```
while steps > 0 and not seen[cur]:
```もし`cur`すでに情報が得られているため、これ以上続けても無駄です。 DSU 圧縮を通じて将来到達可能なノードもすべて、すでに考慮対象から除外されています。 

このソリューションはサイクルを明示的に処理することはありません。 DSU 圧縮により、内部のすべての頂点が通知されると、それらは自然に折りたたまれます。 

整数オーバーフローは Python では無関係ですが、C++ では、このソリューションでは次の式に 64 ビット整数を使用する必要があります。`v[i]`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + m)\alpha(n))$| 各生徒は 1 回退学し、DSU の操作は逆に償却されます。 
| スペース |$O(n)$| フレンドシップ グラフ、DSU 親配列、および訪問先配列 |

 逆アッカーマン係数は実際には事実上一定です。 と`n, m <= 10^5`、これは制限時間内に簡単に収まります。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    g = [0] + list(map(int, input().split()))
    v = list(map(int, input().split()))
    b = list(map(int, input().split()))

    parent = list(range(n + 1))
    seen = [False] * (n + 1)

    sys.setrecursionlimit(1 << 25)

    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])
        return parent[x]

    prev = 0
    out = []

    for i in range(m):
        a = ((v[i] + prev) % n) + 1

        ans = 0
        steps = b[i]

        cur = find(a)

        while steps > 0 and not seen[cur]:
            ans += 1
            seen[cur] = True
            steps -= 1

            nxt = find(g[cur])
            parent[cur] = nxt

            cur = nxt

        out.append(str(ans))
        prev = ans

    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue()
