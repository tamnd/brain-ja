 ## 解決策
 ## 問題の理解

 現在の月が文字列と整数として与えられます。`k`新しいゲームのリリースが何ヶ月後に行われるかを表します。 タスクは、進んだ後の月を正確に決定することです`k`カレンダーでは数か月先になります。 

カレンダーは周期的です。 12月が終わるとまた1月が来ます。 このため、実際の問題は、12 月の名前の固定された循環シーケンス内で前進することです。 

制約は非常に小さいです。 の値`k`は最大でも 100 で、12 か月しかありません。 適切な実装はすべて即座に実行されます。 一度に 1 か月ずつ進むシミュレーションでも実行される操作は最大 100 件ですが、これは 2 秒の制限時間としては取るに足らないものです。 

主な困難はパフォーマンスではなく、カレンダーの周期的な性質を正しく処理することです。 

よくある間違いの 1 つは、12 月以降にラップアラウンドするのを忘れることです。 次の入力を考えてみましょう。```
December
1
```正しい出力は次のとおりです。```
January
```モジュラー演算を行わずに単に次のインデックスに移動する不用意な実装は、範囲外になります。 

別の微妙なケースが現れるのは、`k = 0`。 例えば：```
March
0
```正しい出力は次のとおりです。```
March
```誰かが処理前に少なくとも 1 回は進む場合`k`とすると、誤って April が印刷されてしまいます。 

3 番目のエッジケースは次の場合に発生します。`k`は 12 より大きいです。例:```
January
25
```正しい出力は次のとおりです。```
February
```カレンダーは 12 か月ごとに繰り返されるため、25 か月進めることは 1 か月進めることと同じになります。 制約が小さいため、モジュロによる削減を行わずに繰り返し前に進む実装は依然として機能しますが、直接インデックス付けソリューションはモジュロを正しく適用する必要があります。 

## アプローチ

 最も直接的な解決策は、時間の経過を月ごとにシミュレートすることです。 すべての月の名前を配列内に順番に格納し、現在の月を見つけて、次に進みます。`k`回。 12月を過ぎると1月に戻ります。 

各操作はカレンダーの動作を正確に反映しているため、この強引なアプローチは正しいです。 当月からスタートして翌月へ移動を繰り返すと、最終的には正解にたどり着きます。 

ランタイムは`O(k)`。 と`k ≤ 100`、これは完全に許容されます。 最悪の場合でも、トランジションは 100 回しか実行されません。 

ソリューションを改善する観察は、カレンダーが 12 か月ごとに繰り返されることです。 12 か月後には同じ月に戻ります。 この周期構造のため、シミュレーションはまったく必要ありません。 

当月にインデックスがある場合`i`の場合、答えは簡単です。```
(i + k) % 12
```これにより、問題は循環配列のインデックス付けに変換されます。 モジュロ演算は、12 月から 1 月までの折り返しを自動的に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | お(1) | 承認済み |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 12 か月すべてをカレンダー順に配列に格納します。 
2. 現在の月と整数を読み取ります。`k`。 
3. 配列内で現在の月のインデックスを見つけます。 

このインデックスは月を数値で表します。`0`に`11`。 
4. 次を使用して宛先インデックスを計算します。`(current_index + k) % 12`。 

12 月を超えて移動すると、モジュロ演算によりポジションが正しくラップされます。 
5. 計算されたインデックスに格納されている月を出力します。 

### なぜ効果があるのか

 月は長さ 12 のサイクルを形成します。1 か月進むことは、配列内で 1 ステップ進むことに対応します。 進む`k`月は移動に相当します`k`前進します。 

モジュロ演算では、循環構造内の正しい位置が保持されます。 インデックス 11 を超える動きは、カレンダーとまったく同じように最初に戻ります。 このため、`(current_index + k) % 12`常に正しい将来の月と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# solution

months = [
    "January",
    "February",
    "March",
    "April",
    "May",
    "June",
    "July",
    "August",
    "September",
    "October",
    "November",
    "December"
]

current = input().strip()
k = int(input())

current_index = months.index(current)
answer_index = (current_index + k) % 12

print(months[answer_index])
```配列`months`カレンダーの順序を明示的に定義します。 これにより、月の名前とインデックスが直接マッピングされます。 

への呼び出し`months.index(current)`開始位置を見つけます。 エントリが 12 個しかないため、この検索は実質的に定数時間になります。 

表現`(current_index + k) % 12`実装の重要な部分です。 それなし`% 12`、11 より大きいインデックスは無効になります。 モジュロは、正しい循環位置を維持しながら、大きなインデックスを有効な範囲に変換します。 

使用する`input().strip()`月の名前は標準入力から取得され、末尾に改行文字が含まれる場合があるため、これは重要です。 空白を削除しないと、検索は失敗します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    months = [
        "January",
        "February",
        "March",
        "April",
        "May",
        "June",
        "July",
        "August",
        "September",
        "October",
        "November",
        "December"
    ]

    current = input().strip()
    k = int(input())

    current_index = months.index(current)
    answer_index = (current_index + k) % 12

    print(months[answer_index])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("November\n3\n") == "February", "sample 1"

# custom cases
assert run("March\n0\n") == "March", "k = 0"
assert run("December\n1\n") == "January", "year wrap"
assert run("January\n12\n") == "January", "full cycle"
assert run("January\n25\n") == "February", "large k with modulo"
assert run("August\n100\n") == "December", "maximum-style large movement"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`March 0`|`March`| 動きなし |
 |`December 1`|`January`| 12月以降の折り返し |
 |`January 12`|`January`| 完全なカレンダー サイクル |
 |`January 25`|`February`| 正しいモジュロ動作 |
 |`August 100`|`December`| 大きな移動値 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
December
1
```アルゴリズムは次のことを見つけます`December`インデックスで`11`。 次に、次のように計算します。```
(11 + 1) % 12 = 0
```索引`0`に相当する`January`、これは正しいカレンダーの遷移と一致します。 

次に、次のことを考えてみましょう。```
March
0
```のインデックス`March`は`2`。 計算は次のようになります。```
(2 + 0) % 12 = 2
```結果は残る`March`。 アルゴリズムは、月が経過しない場合を正しく処理します。 

最後に、次のことを考慮してください。```
January
25
```のインデックス`January`は`0`。 計算は次のようになります。```
(0 + 25) % 12 = 1
```索引`1`に相当する`February`。 カレンダーは 12 か月ごとに繰り返されるため、25 か月進めることは 1 か月進めることに相当し、アルゴリズムはモジュロ演算を通じてそれを自動的に取得します。
