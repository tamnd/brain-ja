 ## 解決策
 ## 問題の理解

 道路網を表す接続された無向グラフが与えられます。 すべての交差点は頂点であり、すべての道路はエッジであり、頂点のペアの間には多くても 1 つのエッジがあります。 

市は、最終的なグラフがより強力な接続条件を満たすことを望んでいます。つまり、すべてのジャンクションのペアの間に、少なくとも 2 つのエッジの切り離されたパスが存在する必要があります。 グラフ理論では、これは、グラフが 2 つのエッジで接続されている必要があること、または同等に、グラフにブリッジが含まれていない必要があることを意味します。 

ブリッジは、削除するとグラフが切断されるエッジです。 ブリッジのないグラフは自動的に要件を満たします。これは、頂点のすべてのペアの間に、エッジが互いに独立した 2 つのパスがあるためです。 

新しいエッジを追加することはできますが、平行なエッジを作成することはできません。 タスクは、結果のグラフにブリッジが存在しないように、最小数のエッジを追加することです。 考えられるすべての有用なエッジがすでに存在するためにこれを実行できない場合は、次のように出力します。`-1`。 

グラフには最大 900 個の頂点がありますが、最大 100,000 個のエッジがあります。 エッジ数が多いため、候補エッジが追加されるたびに接続性を最初から繰り返し再計算するアルゴリズムは直ちに排除されます。 ナイーブ`O(m * (n + m))`ブリッジの再計算は、密なグラフではすでに大きすぎます。 

小さな頂点境界は、より興味深い制約です。 以来`n ≤ 900`、`O(n^2)`頂点ペアの検索は完全に許容されます。 これは、後で補数グラフで欠落しているエッジを見つける必要があるときに役立ちます。 

誤って対処しやすい特殊なケースがいくつかあります。 

すでに 2 エッジ接続されているグラフを考えてみましょう。```
3 3
1 2
2 3
3 1
```正しい答えは次のとおりです。```
0
```不注意な解決策では、ブリッジがないにもかかわらず、DFS ツリーのリーフを接続しようとする可能性があります。 

ここで木について考えてみましょう。```
4 3
1 2
2 3
3 4
```すべてのエッジは橋です。 最適な答えは 1 つの新しいエッジです。```
1
1 4
```この 1 つのエッジを追加すると、元のエッジをすべて含むサイクルが作成されます。 

グラフがほぼ完成したときに、より微妙なケースが現れます。```
4 5
1 2
1 3
1 4
2 3
2 4
```唯一欠けているエッジは、`(3,4)`。 グラフにはまだ橋が含まれていますか? いいえ、そうではありません。答えは次のとおりです。`0`。 しかし、ブリッジを修正するには既存のエッジを追加する必要があるグラフを想像してください。 平行エッジは禁止されているため、一部のグラフは不可能になります。 

例えば：```
2 1
1 2
```唯一の可能なエッジはすでに存在します。 別のコピーを追加することはできません`(1,2)`、したがって、答えは次のようになります。```
-1
```「複数エッジなし」条件を無視するソリューションでは、誤って余分なエッジが 1 つ出力されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのブリッジを繰り返し検出し、欠落している可能性のあるすべてのエッジを試し、追加後に消えるブリッジの数を評価します。 最適なエッジを追加し、グラフを更新し、ブリッジがなくなるまで続けます。 

これが機能するのは、エッジを追加してもブリッジの数を減らすだけだからです。 最終的に、グラフは 2 つのエッジが接続されたものになります。 

問題はコストです。 橋の検出には時間がかかります`O(n + m)`Tarjan のアルゴリズムを使用します。 がある`O(n^2)`候補エッジを多数追加することもできます。 密なグラフでは、これは簡単に数億の操作を超えて増加します。 

重要な観察は、ブリッジがツリー構造を形成しているということです。 

最大の 2 エッジ接続コンポーネントをすべて 1 つのノードに圧縮すると、残りのすべてのブリッジ エッジがブリッジ ツリーと呼ばれるツリーを形成します。 このツリーの各リーフは、正確に 1 つのブリッジを介して接続されたコンポーネントに対応します。 

すべてのブリッジを削除するには、リーフを新しいエッジでペアにする必要があります。 エッジを追加するたびに、リーフの数が最大 2 つずつ減ります。 これにより、古典的な下限が得られます。$$\left\lceil \frac{\text{number of leaves}}{2} \right\rceil$$制限のないグラフの場合、この限界は常に達成可能です。 

ここでさらに複雑なのは、平行エッジが禁止されていることです。 2 つのブリッジ ツリー リーフを接続するときは、まだ隣接していないコンポーネントから実際の頂点を選択する必要があります。 以来`n ≤ 900`、そのようなペアを直接検索できます。 

問題全体は次のようになります。 

1. 橋を見つけます。 
2. ブリッジ接続されたコンポーネントを構築します。 
3. ブリッジツリーを構築します。 
4. 葉をペアにします。 
5. リーフ コンポーネントの各ペアについて、それらの間に欠けているエッジを見つけます。 

ある時点でそのような欠落エッジが存在しない場合、答えは不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²(n + m)) またはそれ以上 | O(n + m) | 遅すぎる |
 | 最適 | O(n² + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Tarjan のブリッジ検出 DFS を実行します。 

すべてのエッジについて、検出時間とローリンク値を使用して、それがブリッジであるかどうかを判断します。 
2. 概念的にすべてのブリッジを削除し、接続コンポーネントを計算します。 

ブリッジを使用せずに接続された頂点は、同じ 2 辺接続コンポーネントに属します。 
3. 各コンポーネントを 1 つのノードに圧縮し、ブリッジ ツリーを構築します。 

元のブリッジはすべて、2 つの圧縮されたコンポーネント間のエッジになります。 ブリッジは圧縮後にサイクルを形成できないため、構造はツリーになります。 
4. 橋の木の葉を数えます。 

次数のあるコンポーネント`1`ブリッジツリーにはリーフコンポーネントがあります。 
5. 葉を反対側からペアにします。 

あれば`k`葉の場合、必要なエッジの最小数は`(k + 1) // 2`。 

標準的な方法は、すべてのリーフをリストしてペアにすることです。`leaf[i]`と`leaf[i + k/2]`。 
6. リーフ コンポーネントのペアごとに、既存のエッジのない 2 つの頂点を検索します。 

ペアが見つかるまで、最初のコンポーネントのすべての頂点と 2 番目のコンポーネントのすべての頂点を繰り返します。`(u, v)`エッジがすでに存在しないようにします。 
7. これらのエッジを答えに追加します。 

追加されたエッジごとに、2 つのリーフ間のパス上のブリッジを通過するサイクルが作成され、それらのブリッジが削除されます。 
8. 必要なペアに利用可能な非エッジがない場合は、印刷します。`-1`。 

平行エッジは禁止されているため、修復操作は実行できません。 

### なぜ効果があるのか

 2 つのエッジで接続されたコンポーネントを圧縮した後、残りのすべてのエッジはブリッジになるため、圧縮されたグラフはツリーになります。 

木では、葉が 1 つのエッジを介して取り付けられているため、まさに橋が存在します。 2 つのリーフを接続すると、それらの間の一意のパスに沿ってサイクルが作成され、そのパス上のすべてのブリッジが削除されます。 

追加されたエッジごとに最大 2 つの葉の欠損を除去できるため、少なくとも`ceil(leaves / 2)`エッジは必要です。 ペアリング戦略はまさにこの境界を達成し、最適化します。 

残る唯一の問題はエッジの可用性です。 最終的なグラフには複数のエッジを含めることができないため、選択したコンポーネントのすべてのペアに少なくとも 1 つの隣接しない頂点のペアが含まれていることを確認する必要があります。 そのようなペアが存在しない場合、それらのコンポーネント間に有効な修復エッジを追加することはできず、構築は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]
    edges = []
    adj = [[False] * n for _ in range(n)]

    for idx in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        edges.append((u, v))

        g[u].append((v, idx))
        g[v].append((u, idx))

        adj[u][v] = True
        adj[v][u] = True

    tin = [-1] * n
    low = [0] * n
    is_bridge = [False] * m
    timer = 0

    def dfs(v, pe):
        nonlocal timer

        tin[v] = low[v] = timer
        timer += 1

        for to, eid in g[v]:
            if eid == pe:
                continue

            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, eid)
                low[v] = min(low[v], low[to])

                if low[to] > tin[v]:
                    is_bridge[eid] = True

    dfs(0, -1)

    comp = [-1] * n
    comps = []

    def dfs_comp(v, cid):
        comp[v] = cid
        comps[cid].append(v)

        for to, eid in g[v]:
            if is_bridge[eid]:
                continue
            if comp[to] == -1:
                dfs_comp(to, cid)

    cid = 0
    for i in range(n):
        if comp[i] == -1:
            comps.append([])
            dfs_comp(i, cid)
            cid += 1

    if cid == 1:
        print(0)
        return

    tree = [[] for _ in range(cid)]
    deg = [0] * cid

    for eid, (u, v) in enumerate(edges):
        cu = comp[u]
        cv = comp[v]

        if cu != cv:
            tree[cu].append(cv)
            tree[cv].append(cu)
            deg[cu] += 1
            deg[cv] += 1

    leaves = []

    for i in range(cid):
        if deg[i] == 1:
            leaves.append(i)

    k = len(leaves)
    need = (k + 1) // 2

    if k == 2:
        pairings = [(leaves[0], leaves[1])]
    else:
        pairings = []

        half = (k + 1) // 2

        for i in range(k // 2):
            pairings.append((leaves[i], leaves[i + half]))

        if k % 2 == 1:
            pairings.append((leaves[0], leaves[half - 1]))

    ans = []

    for a, b in pairings:
        found = False

        for u in comps[a]:
            for v in comps[b]:
                if not adj[u][v]:
                    ans.append((u + 1, v + 1))
                    adj[u][v] = adj[v][u] = True
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)
            return

    print(len(ans))
    for u, v in ans:
        print(u, v)

```最初のセクションでは、グラフを構築し、隣接リストと隣接行列の両方を保存します。 隣接リストは DFS トラバーサルに使用されますが、隣接マトリックスを使用すると、一定時間内にエッジがすでに存在するかどうかをテストできます。 

ブリッジ DFS は標準の Tarjan アルゴリズムです。`tin[v]`DFS エントリ時刻を保存し、`low[v]`バックエッジを介して最も早く到達可能な祖先を保存します。 エッジ`(v, to)`架け橋となるとき`low[to] > tin[v]`。 

ブリッジを特定した後、ブリッジのエッジを無視して別の DFS を実行します。 すべての走査は、1 つの最大の 2 エッジ接続コンポーネントをマークします。 

圧縮されたブリッジ ツリーは、個別のオブジェクトとして明示的に構築されません。 必要なのは、コンポーネントの次数と各コンポーネント内の頂点のリストだけです。 

葉のペアリング ロジックは微妙な部分です。 反対側の葉をペアにすることでツリーのバランスが取れ、追加されるエッジの最適な数が保証されます。 奇数のリーフには、追加のラップアラウンド ペアが 1 つ必要です。 

有効な新しいエッジを検索するときは、両方のコンポーネントの実際の頂点を反復処理します。 隣接行列により、偶発的な平行エッジが回避されます。 

実装では、各エッジを追加した後に隣接行列を更新します。 この更新を行わないと、後のペアリングで誤って同じエッジを再利用する可能性があります。

 ## 特殊なケース

 不可能なケースを考えてみましょう。```
2 1
1 2
```グラフには 1 つのブリッジが含まれています。 ブリッジ ツリーには 2 つの葉があるため、理論的には 1 つのエッジを追加するとグラフが修正されます。 しかし、唯一可能なエッジは`(1,2)`すでに存在します。 

アルゴリズムは 2 つのコンポーネントを形成します`{1}`そして`{2}`。 それらの間の非エッジの検索中に、すべての候補ペアはすでに隣接しています。 検索は失敗し、アルゴリズムは正しく出力します。`-1`。 

ここで、すでに有効なグラフを考えてみましょう。```
4 4
1 2
2 3
3 4
