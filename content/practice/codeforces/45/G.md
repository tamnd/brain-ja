 ## 解決策
 ## 問題の理解

 私たちには次からの番号が付いた家があります`1`に`n`。 すべての家には色が必要です。 色ごとに、その色で塗られたすべてのハウス インデックスを合計すると、結果は素数になるはずです。 

目標は、パーティション自体について何かを最大限に活用することではありません。 最適化の対象となるのは色数だけです。 できるだけ少ない色を使用する必要があります。 

カラークラスに家が含まれる場合`{2, 5, 8}`の場合、条件は次のようになります。$$2 + 5 + 8 = 15$$以来`15`が素数ではない場合、この色付けは無効になります。 

興味深いのは、同じ色の家が連続している必要がないことです。 番号を自由に分割できます`1..n`任意のグループに分けられます。 

限界はただ`6000`、それは問題の性格を完全に変えます。 高度な漸近法やランダム化された構築は必要ありません。 アン`O(n^2)`解決策はまったく問題ありません。`6000^2 = 36,000,000`これは大きいですが、最適化された言語で管理可能であり、注意して実装すれば Python でも許容できます。 ただし、指数関数的な検索や無制限のバックトラッキングは不可能です。`n`非常に早く成長します。 

重要なエッジケースは実装の詳細に関するものではなく、最小色の数が何になるかを理解するためのものです。 

考慮する`n = 2`。 

合計額は次のとおりです。$$1 + 2 = 3$$以来`3`プライムなので、1色で十分です。 常にペアに分割しようとする不注意な解決策では、これを見逃してしまい、不必要に 2 つの色が生成されてしまいます。 

ここで考えてみましょう`n = 3`。 

合計額は次のとおりです。$$1 + 2 + 3 = 6$$

`6`は素数ではないので、1色は不可能です。 But two colors work:$$1 + 2 = 3,\quad 3 = 3$$部分和が非素数のままで最初のグループを拡張し続ける単純な貪欲は行き詰まる可能性があります。 

もう 1 つの微妙なケースは、合計が偶数で、`2`。 このような合計が素数になることはあり得ません。 例えば：$$1 + 2 + \dots + 8 = 36$$なので一色は無理です`n = 8`。 正しい解は、合計がすでに素数を形成していることを認識する必要があります。 

最後の注意が必要な観察は、答えがこれより大きくなることは決してないということです。`2`。 それを証明することが問題のすべてだ。 

## アプローチ

 ブルートフォース解釈は簡単です。 セットのすべてのパーティションを試すことができます`{1,2,...,n}`そして、すべてのサブセットの合計が素数であるかどうかを確認します。 すべての有効なパーティションの中から、グループ数が最小のパーティションを選択します。 

これは問題定義と直接一致するため、正しいです。 問題は、設定されたパーティションの数がベル数であり、中程度の場合でも膨大な数になることです。`n`。 すでに`n = 20`探索空間は絶望的に広い。 と`n = 6000`、強引な方法は完全に不可能です。 

次の観察により、問題は完全に変わります。 

させて$$S = 1 + 2 + \dots + n = \frac{n(n+1)}{2}$$もし`S`それ自体がプライムである場合は、すべての家を同じ色でペイントするだけです。 複数の色を使用することはできないため、これが最適であることは明らかです。 

興味深いケースは次のような場合です。`S`プライムではありません。 

最初は、数値をいくつかの素数和グループに分割する必要があるため、これはまだ難しいように見えます。 しかし、驚くべき近道があります。 

素数を見つけることができると仮定します`p`次のような:$$p < S$$すると、残りの合計は次のようになります。$$S - p$$両方の場合`p`そして`S-p`が素数であれば、すぐに有効な 2 色が得られます。 1 つのグループの合計は次のようになります`p`、その他の合計は`S-p`。 

ここで、パリティについて重要なことに注目してください。 

もし`S`プライムではなく、`S > 2`、その後、次のいずれかを行います。 

1.`S`偶数である、または
 2.`S`奇妙な合成です。 

もし`S`が偶数である場合、この範囲に対するゴールドバッハの予想に関連する定理により、これを 2 つの素数の和として表すことができます。 以来`n ≤ 6000`、合計は最大で約`18 million`、ペアを直接チェックするのは簡単です。 

しかし、もっと単純なこともできます。 

から連続した数字なので、`1`に`n`、からのすべての整数`1`に`S`部分集合の合計として表すことができます。 合計が任意のターゲットに等しいサブセットを貪欲に構築できます。 

したがって、タスク全体は 2 つの素数を見つけることになります。`a`そして`b`次のような:$$a + b = S$$次に、合計して 1 つのサブセットを構築します。`a`、その他すべては自動的に合計されます。`b`。 

素数の検索は、制約に比べれば小さなものです。

 ## アルゴリズムのチュートリアル

 1. 合計を計算します。$$S = \frac{n(n+1)}{2}$$これはすべてのハウスインデックスの合計です。 

1. 以下のすべての素数を生成します。`S`エラトステネスのふるいを使って。 

特定の合計が素数であるかどうかを繰り返しチェックするため、高速な素数クエリが必要です。 

1. かどうかを確認します。`S`それ自体がプライムです。 

素数の場合は色を割り当てる`1`各家に行って終了です。 1 色が最小の答えです。 

1. それ以外の場合は、2 つの素数を検索します`a`そして`b`次のような:$$a + b = S$$素数値を反復処理します`a`かどうかをテストします`S-a`もプライムです。 

1. そのようなペアが見つかったら、合計が正確に次のとおりであるサブセットを構築します。`a`。 

私たちはからの数字を処理します`n`まで`1`。 現在の数が残りの目標を超えない場合は、それを最初のグループに入れます。 

番号が連続しているため、この欲張りな機能が機能します。 残りの値は常に、より小さい未使用の数値から形成できます。 

1. 選択したすべての数字を色でペイントします`1`。 

残っている家をすべて色でペイントする`2`。 

最初のグループの合計は正確に`a`、これは素数です。 2 番目のグループの合計は次のとおりです。$$S-a=b$$これもプライムです。 

### なぜ効果があるのか

 この構造は 2 つの事実に基づいています。 

まず、合計が素数の場合、1 つの色は簡単に機能します。 

次に、合計を 2 つの素数値に分割すると、`a`そして`b`の場合、それらの合計の 1 つをサブセットとして実現するだけで十分です。 残りの数値により、他の素数和が自動的に生成されます。 

貪欲なサブセット構築は正しいです。`{1,2,...,n}`からのすべての整数を表すことができます`0`に`S`部分集合の合計として。 残りの数値は完全に連続した範囲を形成しているため、利用可能な最大の数値を取得しても、将来の構築が妨げられることはありません。 

すべてのカラー クラスには素数の和があり、1 つまたは 2 つの色のいずれかを使用するため、ソリューションは最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(limit):
    prime = [True] * (limit + 1)
    prime[0] = prime[1] = False

    i = 2
    while i * i <= limit:
        if prime[i]:
            j = i * i
            while j <= limit:
                prime[j] = False
                j += i
        i += 1

    return prime

def solve():
    n = int(input())

    total = n * (n + 1) // 2

    is_prime = sieve(total)

    # One color is enough
    if is_prime[total]:
        print(*([1] * n))
        return

    # Find two primes a + b = total
    target = -1

    for a in range(2, total + 1):
        if is_prime[a] and is_prime[total - a]:
            target = a
            break

    colors = [2] * (n + 1)

    # Build subset with sum = target
    rem = target

    for x in range(n, 0, -1):
        if x <= rem:
            colors[x] = 1
            rem -= x

    print(*colors[1:])

solve()
```最初のセクションでは合計を計算し、その値までふるいを構築します。 合計の上限はおおよそですので、`18 million`、ふるいはメモリに快適に収まります。 

次のブランチは最も簡単なケースを処理します。 総和自体が素数であれば、どの家も同じ色になります。 どのソリューションも 1 色未満を使用できないため、これは自動的に最適になります。 

中心となる観察結果は、以下を検索するループに表示されます。`a`。 合計が合計に等しい 2 つの素数を探します。 この問題では有効な色付けがすべて受け入れられるため、最初の有効なペアで十分です。 

貪欲なサブセット構築は微妙な部分です。 から下方向に繰り返します`n`。 現在の数値が残りのターゲットに適合する場合は常に、それを含めます。 

たとえば、ターゲットが次のような場合`11`利用可能な番号は次のとおりです`1..6`、プロセスは次のようになります。$$11 \to 5 \to 0$$取ることによって`6`その後`5`。 

順序が重要です。 大規模なものから小規模なものまで、処理が迅速に完了し、オーバーシュートが発生しないことが保証されます。 

カラー配列のインデックスは次のとおりです。`1`なぜなら、家番号は自然に 1 から始まるからです。 このオフセットを忘れると、off-by-one エラーの一般的な原因になります。
