 ## 解決策
 ## 問題の理解

 単一の整数シーケンスが与えられ、残りの要素を元の順序で維持したまま要素を削除することができます。 目標は、連続する差分に関する厳密な交互パターンを満たしながら、結果として得られるサブシーケンスをできるだけ長くすることです。 

具体的には、選択した部分列を見ると、隣接するすべてのペアが異なっていて、これらの差の符号が厳密に交互になっている必要があります。 最初の差が正の場合、次の差は負でなければならず、その後再び正になる、というようになります。 最初の差が負の場合も同様です。 交互パターン内では等価性が許可されていないため、差がゼロになると直ちに有効性が失われます。 

タスクは、そのようなサブシーケンスの可能な最大長を計算することです。 

制約$n \le 10^5$すべてのサブシーケンスを試行するソリューションは除外されます。 ナイーブ$O(2^n)$列挙は直ちに不可能です。 二次関数でも$O(n^2)$動的プログラミングは、最悪の場合、遅すぎるリスクがあるため、ソリューションでは基本的に、要素ごとに定数または対数の作業のみを使用して、配列を線形時間で処理する必要があります。 

いくつかの特殊なケースは、見た目よりも重要です。 

すべての要素が等しい場合、すべての差はゼロであるため、有効な遷移はなく、答えは 1 でなければなりません。 

シーケンスが厳密に増加または厳密に減少している場合、最初は 1 方向のみが使用可能であり、その後は交互の条件がすぐに失敗するため、1 より大きい非自明な長さについては、やはり答えは 2 に崩壊します。 

変更が組み込まれた反復値が多数ある場合、ゼロ差分を明示的に破棄しない単純なアプローチでは、値が有効な遷移として誤って扱われ、誇張された応答が生成される可能性があります。 

## アプローチ

 ブルートフォース戦略では、すべてのサブシーケンスを試し、それが交互符号条件を満たすかどうかを確認します。 選択された長さのサブシーケンスごとに$k$、有効性の検証には時間がかかります$O(k)$、そして、あります$2^n$したがって、総コストは指数関数的となり、たとえ$n = 40$、ましてや$10^5$。 

問題をローカルなものに圧縮する必要があります。 重要な観察は、有効なサブシーケンスを拡張するために重要なのは、最後に選択された要素と最後の非ゼロの差の符号だけであるということです。 現在増加が予想されているのか減少が予想されているのかがわかったら、すべての新しい要素がパターンを継続するか、パターンを破ります。 

これにより、問題は貪欲スキャンに変わります。 サブシーケンス全体を記憶する必要はなく、最後に選択した値と最後に方向だけを記憶する必要があります。 方向の有効な変更を生み出す値に遭遇したときはいつでも、それを取得して、予想される方向を反転します。 差がゼロの場合は、有効な代替に寄与できないため、完全に無視します。 

これは、古典的な「小刻みな部分列」問題と同じ構造です。つまり、配列を圧縮して、正と負の傾きが交互に最大になるようにします。

 ## アルゴリズムのチュートリアル

 最後に意味のある変化の方向を追跡しながら、配列をスキャンします。 

1. 単一の要素は常に有効であるため、回答の長さを 1 として初期化します。 また、以前の差分符号を格納する変数も、最初は設定されていない状態で保持します。 
2. 2 番目の要素から配列を繰り返し、現在の要素と前の要素の差を計算します。 
3. 差がゼロの場合は、有効な交互サブシーケンスに寄与できないため、完全にスキップします。 これにより、方向ロジックの破損が回避されます。 
4. 差が正で、まだ方向を追跡していないか、前の方向が負であった場合、この要素をサブシーケンスの一部として受け入れ、方向を正に設定します。 
5. 差が負で、まだ方向を追跡していないか、前の方向が正であった場合、この要素を受け入れて方向を負に設定します。 
6. それ以外の場合、電流差は以前と同じ方向に継続し、交互パターンを拡張できないため、無視します。 
7. 受け入れられた遷移の数に 1 を加えたものが、回答の長さを求めます。 

重要な考え方は、方向が反転するたびに、その遷移に利用可能な最も極端なポイントが使用されることが保証されるため、将来の要素は交互を中断せずにカウントを改善できないということです。 

### なぜ効果があるのか

 スキャンのどの時点でも、アルゴリズムは方向が変わった最新のピボットで終了するサブシーケンスを維持します。 無視される要素は、差がゼロであるか、同じ傾斜方向が続くかのいずれかです。 これを維持すると、まだ達成不可能な将来の変更は許可されません。長さを増やす唯一の方法は、新しい符号変更を作成することであり、符号変更は斜面が反転する場合にのみ可能であるためです。 したがって、スロープ フリップのみを取得するという貪欲な選択により、可能な最大数の交互が維持され、サブシーケンスの長さが直接決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return
    
    count = 1
    prev_diff = 0  # 0 means unset, 1 means positive, -1 means negative
    
    for i in range(1, n):
        diff = a[i] - a[i - 1]
        
        if diff == 0:
            continue
        
        sign = 1 if diff > 0 else -1
        
        if prev_diff == 0 or sign != prev_diff:
            count += 1
            prev_diff = sign
    
    print(count)

if __name__ == "__main__":
    solve()
```このソリューションは、配列全体を 1 回スキャンし、連続した差分の符号が変化した場合にのみ反応することに依存しています。 変数`prev_diff`最後に受け入れられた傾斜方向を保存します。 ゼロの差は明示的に無視されるため、代替ロジックに干渉しません。 

重要な点は、選択したサブシーケンスではなく、常に元のシーケンス内の隣接する要素と比較することです。 最適なサブシーケンスは、その長さを減らすことなく、連続する「転換点」のみを使用するサブシーケンスに変換できるため、これで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sysio
    
    out = sysio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return
    
    count = 1
    prev_diff = 0
    
    for i in range(1, n):
        diff = a[i] - a[i - 1]
        if diff == 0:
            continue
        sign = 1 if diff > 0 else -1
        if prev_diff == 0 or sign != prev_diff:
            count += 1
            prev_diff = sign
    
    print(count)

# provided samples
assert run("7\n3 14 5 9 6 16 7\n") == "7"
assert run("5\n1 3 11 9 15\n") == "4"

# all equal
assert run("4\n5 5 5 5\n") == "1"

# strictly increasing
assert run("5\n1 2 3 4 5\n") == "2"

# strictly decreasing
assert run("5\n5 4 3 2 1\n") == "2"

# alternating with zeros
assert run("6\n1 2 2 1 1 2\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい値 | 1 | ゼロの差はカウントしてはなりません |
 | 増加シーケンス | 2 | 有効な方向切り替えは 1 つだけ可能 |
 | 降順 | 2 | 増加する場合の対称性 |
 | 重複のあるシーケンス | 3 | ゼロの差は安全に無視されます。 

## 特殊なケース

 重要なエッジ ケースの 1 つは、方向の変化の間に反復値がシーケンスに含まれている場合です。 たとえば、次のような入力では`1 2 2 1`、 違い`2 -> 2`はゼロなので無視する必要があります。無視しないと、その後のドロップの検出が誤って妨げられてしまいます。 アルゴリズムはゼロ差分を明示的にスキップすることでこれを処理するため、効果的なシーケンスは次のようになります。`1 -> 2 -> 1`、正しい長さ 3 が生成されます。 

別のケースは、次のような単調配列です。`1 2 3 4 5`。 最初の増加は受け入れられますが、その後の増加は新しい符号反転を作成しないため無視されます。 結果は 2 で安定します。これは、1 回の増加実行を表すのに必要な点は 2 つだけであるという事実と一致します。 

最後のケースは、次のようなフラット配列です。`7 7 7 7`。 すべての差はゼロであるため、遷移は受け入れられません。 このアルゴリズムは、カウントを正しく 1 のままにし、単一の要素が有効な自明なジグル シーケンスを形成することを反映しています。
