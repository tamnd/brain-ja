 ## 問題の理解

 2 つの選択肢からなる投票が与えられます。 合計すると$n$人々は投票しました。$L$左側のオプションを選択し、$R = n - L$正しいものを選択すること。 アプリは、比率から計算された左票の割合を整数の割合として表示します。$100 \cdot L / n$、小数部分は切り捨てられます。 

各テストケースでは、正確な投票者数はわかりません。$n$、それが与えられた範囲内にあるというだけです$[m, M]$。 表示されているパーセンテージは正確であると言われています$r$、そして、どの値が$n$この範囲内では、そのような表示が生成される可能性があります。 有効なものの中で$n$、最小値と最大値を出力する必要があります。 

重要な問題は、固定の場合です。$n$、表示されるパーセンテージは一意に決定されません。$L$。 代わりに、任意の整数$L$丸め条件を満たすと同じ結果が得られる可能性があります$r$したがって、少なくとも 1 つの整数が存在するかどうかを実際にチェックしています。$L$と一致する$n$そして$r$。 

制約は次のとおりです$10^{18}$、範囲にわたる値ごとのシミュレーションが即座に除外されます。$[m, M]$。 平$O(\sqrt{n})$または$O(\log n)$テストケースごとは許容されますが、直線的なものは何でも可能です$M-m$不可能です。 まで$10^5$テスト ケースでは、各チェックは定数または対数である必要があります。 

パーセンテージが次の場合、微妙なエッジケースが発生します。$0$または$100$。 このような場合、表示される値が非常に許容的になるため、答えの動作が異なります。つまり、ほぼすべての構成がゼロに崩壊するか、極端な構成のみが機能するかのいずれかになります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆることを試みることになります。$n$で$[m, M]$、それぞれについて$n$、可能な限りすべてを反復します$L$から$0$に$n$かどうかを確認します$\lfloor 100L/n \rfloor = r$。 これは正しいですが、コストがかかるためすぐには実行できません$O((M-m+1)\cdot n)$、それは限界をはるかに超えています。 

重要な観察は、固定された$n$、すべてを試す必要はありません$L$。 条件$$r = \left\lfloor \frac{100L}{n} \right\rfloor$$は不等式と等価です$$r \le \frac{100L}{n} < r+1.$$乗算すると、きれいな整数間隔制約が得られます。$$rn \le 100L < (r+1)n.$$とても有効です$L$連続した範囲内になければなりません:$$L_{\min}(n) = \left\lceil \frac{rn}{100} \right\rceil,\quad
L_{\max}(n) = \left\lfloor \frac{(r+1)n - 1}{100} \right\rfloor.$$有効な$n$この間隔に少なくとも 1 つの整数が含まれる場合にのみ存在します。つまり、$L_{\min}(n) \le L_{\max}(n)$。 

これにより、問題はそれぞれの単純な実現可能性チェックに集約されます。$n$。 

有効な最小値と最大値を見つけるには$n$で$[m, M]$、二分探索を 2 回使用します。 まず最小のものを見つけます$n$それは実現可能条件を満たします。 次に、最大のものを見つけます$n$それはそれで満足です。 それぞれのチェックは$O(1)$、完全な解決策は次のとおりです$O(\log M)$テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースオーバー$n, L$|$O((M-m+1)\cdot n)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 関数を定義します`ok(n)`整数が存在するかどうかをチェックします$L$表示されたパーセンテージを生成する$r$。 

1.固定の場合$n$、有効な最小値を計算します。$L$として$L_{\min} = \lceil rn/100 \rceil$。 これは、少なくとも比率を生成できる最初の整数を表します。$r$。 
2. 可能な最大の有効値を計算します。$L$として$L_{\max} = \lfloor ((r+1)n - 1)/100 \rfloor$。 これにより、厳密に以下にとどまることが保証されます$r+1\%$。 
3. もし$L_{\min} \le L_{\max}$、少なくとも 1 つの整数$L$有効な間隔内に存在するため、$n$実現可能です。 そうでなければそうではありません。 

単一のテストができるようになると、$n$の範囲で答えを探します。$[m, M]$。 

1. 二分探索を使用します。$n$最小値を見つけるには$m'$そのような`ok(n)`それは本当です。 何も存在しない場合、テスト ケース全体には解決策がありません。 
2. 再度二分検索を使用して最大値を見つけます。$M'$そのような`ok(n)`それは本当です。 
3. 出力$(m', M')$。 

ここで二分探索が機能する理由は、全体的に単調なプロパティを検索しているわけではないためです。$n$ですが、独立して評価できる述語の境界位置を直接検索します。 各中間点は個別にチェックされるため、述語の単調性は必要ありません。 

### なぜ効果があるのか

 固定の場合$n$、実現可能性は、間隔があるかどうかによってのみ決まります。$[L_{\min}(n), L_{\max}(n)]$は空ではありません。 この条件は、投票の整数構成が観察されたパーセンテージを生成できるかどうかを完全に特徴づけます。 それぞれなので$n$が独立して評価されるため、有効な値と無効な値の間の構造的な順序付けを必要とせずに、二分探索による境界検出を使用して検索空間を安全にスキャンできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(n, r):
    if r == 0:
        return True
    if r == 100:
        return True

    # compute Lmin = ceil(r*n/100)
    lmin = (r * n + 99) // 100

    # compute Lmax = floor(((r+1)*n - 1)/100)
    lmax = ((r + 1) * n - 1) // 100

    return lmin <= lmax

def find_first(m, M, r):
    lo, hi = m, M
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid, r):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return ans

def find_last(m, M, r):
    lo, hi = m, M
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid, r):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans

t = int(input())
for _ in range(t):
    m, M, r = map(int, input().split())

    if r == 0 or r == 100:
        print(m, M)
        continue

    first = find_first(m, M, r)
    if first == -1:
        print(-1, -1)
        continue

    last = find_last(m, M, r)
    print(first, last)
```実装の中核となるのは、`ok(n)`この関数は、浮動小数点演算を行わずにパーセンテージ条件を整数の範囲に変換します。 慎重な使用`(r * n + 99) // 100`は標準的な天井トリックですが、`((r + 1) * n - 1) // 100`厳密な上限を強制します。 

二分探索は独立して 2 回適用されます。1 回目は最初の有効な検索です。$n$、最後を見つけるために 1 回。 これにより、有効性を超えるグローバル構造が必要なくなります。$n$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def ok(n, r):
        if r == 0 or r == 100:
            return True
        lmin = (r * n + 99) // 100
        lmax = ((r + 1) * n - 1) // 100
        return lmin <= lmax

    def find_first(m, M, r):
        lo, hi = m, M
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(mid, r):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    def find_last(m, M, r):
        lo, hi = m, M
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(mid, r):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        m, M, r = map(int, input().split())
        if r == 0 or r == 100:
            out.append(f"{m} {M}")
            continue
        first = find_first(m, M, r)
        if first == -1:
            out.append("-1 -1")
            continue
        last = find_last(m, M, r)
        out.append(f"{first} {last}")

    return "\n".join(out)

 ## 特殊なケース

 のために$r = 0$、参加者が少なくとも 1 人いる構成では、表示される値が 0 パーセントになる可能性があります。$L$ゼロにすることもできます。 アルゴリズムはすべてを即座に受け入れます$n$で$[m, M]$、という事実と一致します$L=0$常に制約を満たします。 

のために$r = 100$、有効な構成は次のとおりです。$L = n$、しかしこれはどんな人にとっても常に達成可能です$n$したがって、やはり全範囲が有効です。 チェックは不必要な演算を避けるために短絡します。 

非常に小さい場合$n$、間隔$[L_{\min}, L_{\max}]$近くの値が空でない場合でも、空になる可能性があります。 実現可能性関数はこれを正確に捉え、二分探索は連続性を仮定せずに最初と最後の有効な位置を分離します。
