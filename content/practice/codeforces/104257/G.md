 ## 解決策
 ## 問題の理解

 一定の順序で受講する必要がある一連のコースが与えられます。 各コースには推定スコアとクレジット値があります。 学生はこれらのコースを正確に分割します$K$連続した学期であり、各学期には少なくとも 1 つのコースが含まれている必要があります。 

学期内の「学業成績」は 3 つの階層で計算されます。 まず、その学期の生のコーススコアの単位加重平均をとります。 これにより実数が生成されます$[0,100]$。 その値は最も近い整数に丸められ、固定スコア対 GPA テーブルを使用して GPA 値に変換されます。 最後に、全体的な結果は単純に次の算術平均になります。$K$学期ごとの GPA。コース数や単位数による重み付けはありません。 

したがって、タスクは生のスコアを最大化することではなく、シーケンスをどこに分割するかを選択することです。$K$結果として得られる離散化 GPA の平均ができるだけ大きくなるように、連続したブロックを調整します。 

制約は小さく、コース数は最大 100、学期数は最大 100 です。 これにより、パーティションに対する指数関数的な列挙が即座に除外されます。 二次または三次動的計画法でも許容できます。$10^6$に$10^7$Python では安全に操作できます。 

微妙な失敗例は、丸めのステップで発生します。 学期の GPA は四捨五入された加重平均に依存するため、平均がほぼ同じ 2 つのセグメントでは、四捨五入後に異なる GPA が生成される可能性があります。 

たとえば、学期に加重平均がある場合、$89.4$、89になりますが、$89.5$これら 2 つの値は異なる GPA バンドにマッピングされるため、平均を「平滑化」したりセグメントを貪欲に拡張しようとする単純なアプローチは失敗する可能性があります。 

もう 1 つのエッジ ケースは、セグメンテーションの決定がグローバルに結合されることです。 わずかに悪いセグメントを早期に取得すると、四捨五入後に後のセグメントが GPA 境界を超える可能性があり、合計が増加します。 ローカルでの貪欲な決定は信頼できません。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法で分割しようとします。$N$にコースします$K$空ではない連続セグメント。 このようなパーティションの数は$\binom{N-1}{K-1}$、これはすでに巨大です$N=100$。 各パーティションについて、すべての学期の GPA を計算するには、セグメントをスキャンして加重平均を実行する必要があり、追加の$O(N)$要素。 これは完全に不可能になります。 

問題の構造は、学期の価値はそのセグメント自体にのみ依存し、前後の学期がどのように選択されるかには依存しないということです。 最終学期がコースであることを確認したら$j+1$に$i$、残りの問題は最初の部分に帰着します。$j$コース付き$K-1$学期。 これは、プレフィックスを介した古典的なパーティション DP です。 

重要な観察は、合計クレジットと合計加重スコアのプレフィックス合計を使用して、任意のセグメントの加重平均を一定時間で事前計算できることです。 これにより、各候補最後のセグメントを効率的に評価することが可能になります。 

DP 状態は、「最初の値を使用して可能な限り最高の合計 GPA」になります。$i$に分かれたコース$k$学期」、トランジションでは、可能な限り前のカット位置が試行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング |$O(\binom{N}{K} \cdot N)$|$O(N)$| 遅すぎる |
 | インターバルDP |$O(N^2 K)$|$O(NK)$| 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックスの合計を前処理して、どのセグメントも$[l, r]$加重平均をすばやく計算できます。 

また、整数スコアからルックアップを事前計算します。$0$に$100$指定されたマッピング テーブルを使用して GPA 値に変換するため、学期の平均を四捨五入すると、即座に GPA を取得できます。 

### ステップ

 1. クレジットと加重スコアのプレフィックス配列を計算します。 

それぞれについて$i$、合計クレジットを最大まで保存できます$i$そして合計$a_i \cdot b_i$。 これにより、任意のセグメントの合計を一定時間で計算できます。 
2. セグメントの学期 GPA を計算する関数を定義する$[l, r]$。 

加重平均を計算します$x = \frac{\sum a_i b_i}{\sum b_i}$、最も近い整数に丸めてから GPA にマッピングします。 丸めのステップは、離散化された GPA の結果を変えるため、重要です。 
3. DP テーブルを構築します。$dp[i][k]$最初のパラメータを使用して達成可能な最大合計 GPA です。$i$に分かれたコース$k$学期。 
4.初期化$dp[0][0] = 0$, つまり、コースも学期もなければ GPA はゼロになります。 
5. それぞれについて$i$から$1$に$N$、そしてそれぞれ$k$から$1$に$K$、可能なすべての以前のカットポイントを試してください$j < i$。 

最後の学期は、$[j+1, i]$なので、次のように更新します。$$dp[i][k] = \max(dp[i][k], dp[j][k-1] + GPA(j+1, i))$$6. 答えは次のとおりです。$dp[N][K] / K$, 最終的な GPA は学期間の平均であるためです。 

### なぜ効果があるのか

 すべての有効なスケジュールは、プレフィックスを分割するカット ポイントの一意の増加シーケンスに対応します。$K$セグメント。 DP は各状態の最後のカットを列挙し、すべての有効なパーティションが 1 回だけ考慮されるようにします。 各状態はそのプレフィックスと学期数に対して達成可能な最良の値を保存し、遷移は独立したプレフィックス状態と単一のセグメント値にのみ依存するため、最適な部分構造が保持されます。 四捨五入と GPA マッピングは各セグメント評価内に完全に含まれるため、セグメント間の依存関係が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# GPA mapping based on rounded score
def score_to_gpa(x):
    if 90 <= x <= 100: return 4.3
    if 85 <= x <= 89: return 4.0
    if 80 <= x <= 84: return 3.7
    if 77 <= x <= 79: return 3.3
    if 73 <= x <= 76: return 3.0
    if 70 <= x <= 72: return 2.7
    if 67 <= x <= 69: return 2.3
    if 63 <= x <= 66: return 2.0
    if 60 <= x <= 62: return 1.7
    return 0.0

N = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))
K = int(input())

# prefix sums
pref_w = [0] * (N + 1)
pref_c = [0] * (N + 1)

for i in range(1, N + 1):
    pref_w[i] = pref_w[i - 1] + a[i - 1] * b[i - 1]
    pref_c[i] = pref_c[i - 1] + b[i - 1]

def get_gpa(l, r):
    total_w = pref_w[r] - pref_w[l - 1]
    total_c = pref_c[r] - pref_c[l - 1]
    avg = total_w / total_c
    x = int(avg + 0.5)
    return score_to_gpa(x)

dp = [[-1e9] * (K + 1) for _ in range(N + 1)]
dp[0][0] = 0.0

for i in range(1, N + 1):
    for k in range(1, min(K, i) + 1):
        best = -1e9
        for j in range(k - 1, i):
            if dp[j][k - 1] < -1e8:
                continue
            best = max(best, dp[j][k - 1] + get_gpa(j + 1, i))
        dp[i][k] = best

ans = dp[N][K] / K
print(f"{ans:.7f}")
```プレフィックス配列により、すべてのセグメントの評価が定数時間になります。 DP は、各プレフィックスと学期数が 1 回計算されることを保証し、内部ループが最適な最後のカットを選択します。 制約$j \ge k-1$前学期ごとに少なくとも 1 つのコースを提供できる十分なコースが存在することを保証します。 

よくある落とし穴は、最終的な答えは合計ではなく学期の平均であることを忘れていることです。そのため、次の値で割ります。$K$最後だけ。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのコースが 1 学期に強制的に行われる場合です。$K = 1$。 アルゴリズムはセグメントのみを正しく評価します$[1, N]$、無効な分割を試みることなく、加重平均を計算し、四捨五入して GPA にマッピングします。 

もう 1 つのケースは、各学期に 1 つのコースのみを含める必要がある場合です。$K = N$。 DP は、各セグメントが単一の要素になるようにトランジションを制限します。つまり、丸め後に各コースが独立して寄与することになります。 これは、どの学期もコースを組み合わせることができないという制約を正しくモデル化しています。 

加重平均が正確に 0.5 の境界上にある場合、より微妙なケースが発生します。 たとえば、平均 89.5 が 90 になり、より高い GPA 段階にジャンプします。 アルゴリズムはマッピング前に丸めを実行するため、各セグメントは問題定義と一貫して評価され、最適なパーティション構造が反転する可能性がある場合でも、そのような境界ケースが正しく処理されることが保証されます。
