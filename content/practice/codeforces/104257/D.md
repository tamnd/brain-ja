 ## 解決策
 ## 問題の理解

 各頂点が生徒を表し、各有向辺が一方向の友情の主張を表す有向グラフが与えられます。 重要な関係は、一方向の直接到達可能性ではなく、相互到達可能性です。2 人の学生は、0 人以上の中間学生を介して有向エッジをたどることによって他の学生に到達できる場合、同じグループに属します。 

これはまさに、有向グラフにおける強接続成分の概念です。 グループは、すべての頂点がセット内の他のすべての頂点に到達できる最大の頂点のセットです。 

タスクには 2 つの出力があります。 まず、グラフ全体にそのようなグループがいくつ存在するかを数えなければなりません。 次に、最大のグループのメンバーを出力する必要があります。 複数のグループが最大サイズで同点の場合は、そのうちの 1 つを使用できます。 

グラフのサイズは大きく、最大 100,000 個の頂点と 100,000 個のエッジがあります。 これにより、二次推論やノードのペア間の到達可能性チェックの繰り返しが即座に除外されます。 すべてのノードから単一の BFS/DFS を単純に実行した場合でも、制限をはるかに超えるおよそ O(n(n + m)) になります。 

微妙だが重要な制約は、エッジの方向を無視した場合、グラフは必ず接続されるということです。 これにより、完全に分離されたサブグラフが存在しないことが保証されますが、有向構造は単純化されません。 強く接続されたコンポーネントは依然として多数かつ小規模である可能性があります。 

この問題を無向グラフの通常の接続として扱うと、一般的な落とし穴が発生します。 たとえば、有向チェーン 1 → 2 → 3 では、ノード 1 は 2 と 3 に到達できますが、いずれも 1 に戻ることはできないため、各ノードは独自のグループになります。 方向を無視すると、それらが誤ってマージされます。 

別の失敗例は、分岐のある有向サイクルで発生します。 ノードは他の多くのノードから到達可能であっても戻ることができない場合があるため、到達可能性だけでは不十分です。 相互到達可能性が必要です。 

## アプローチ

 ブルートフォース試行では、到達可能性セットを計算しようとします。 すべてのノードについて、DFS/BFS を実行して、到達可能なすべてのノードを検索し、各ペアについて到達可能性が相互であるかどうかを確認できます。 最悪の場合、これにはすでに O(n(n + m)) のコストがかかります。 n と m が最大 100,000 になると、これは完全に不可能になり、約 10^10 の演算が必要になる可能性があります。 

より良い視点は、相互到達可能性によってグラフが強く接続されたコンポーネントに分割されることを観察すると得られます。 この見方を受け入れると、この問題は標準的な SCC 分解タスクになります。 

重要な洞察は、すべてのペア間の到達可能性について推論するのではなく、内部構造が無関係な SCC にグラフを圧縮するということです。 各 SCC は、有向非巡回グラフ内の単一ノードになります。 SCC の数は、まさに必要なグループの数です。 

SCC を効率的に見つけるために、古典的な線形時間アルゴリズムが存在します。 最も直接的で実装しやすいのは、Kosaraju のアルゴリズムです。DFS を実行して着順を計算し、グラフを反転し、その順序で DFS を実行してコンポーネントを収集します。 各頂点は一定の回数訪問されるため、合計の複雑さは n + m で線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース到達可能性 | O(n(n + m)) | O(n) | 遅すぎる |
 | コサラジュ SCC 分解 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 Kosaraju の 2 パス SCC 分解を使用して問題を解決します。

1. 2 つの隣接リストを作成します。1 つは元の有向グラフ用、もう 1 つは反転グラフ用です。 反転したグラフは、すべてのエッジ u → v を v → u に反転します。 この反転が必要なのは、2 番目のパスで制御された内側方向にコンポーネントを探索できるためです。 
2. 元のグラフに対して深さ優先検索を実行して、完了時間による頂点の順序を計算します。 ノードの探索が完了するたびに、ノードをリストに追加します。 この順序付けは、後で終了するノードが SCC 凝縮グラフ内で「早く」なる傾向がある階層を捉えています。 
3. 逆の終了順序でノードを繰り返します。 これにより、未訪問のノードから DFS を開始するときに、部分的に処理された領域ではなく、圧縮された DAG 内のソース SCC から開始することが保証されます。 
4. この順序で未訪問のノードごとに、反転したグラフで DFS を実行します。 この DFS で到達するすべてのノードは、厳密に 1 つの強く接続されたコンポーネントを形成します。 これらのノードをコンポーネント リストに収集します。 
5. 各コンポーネントを保存し、そのサイズを追跡します。 これまでに発生した最大のコンポーネントを維持します。 
6. すべてのノードの処理が完了したら、コンポーネントの数と最大のノードの内容を出力します。 

なぜ反転グラフ DFS が機能するのかは微妙です。 エッジを反転すると、コンポーネントの「インフルエンス クロージャ」内でのみトラバースが効果的に許可されます。 終了時の順序付けにより、DFS を開始するときに、他の場所に属するはずの未処理の SCC に誤ってリークすることがないようにすることができます。 

### なぜ効果があるのか

 有向グラフの SCC 凝縮により、有向非巡回グラフが形成されます。 最初の DFS は、この DAG と一致する順序を生成します。シンク コンポーネントのノードはより早く終了し、ソース コンポーネントのノードはより遅く終了します。 逆終了順序で処理すると、元のグラフの出力エッジが逆走査で未訪問の SCC につながることがないコンポーネントから常に開始することが保証されます。 これにより、強く接続された各コンポーネントが 1 回だけ分離され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())

g = [[] for _ in range(n + 1)]
gr = [[] for _ in range(n + 1)]

for _ in range(m):
    a, b = map(int, input().split())
    g[a].append(b)
    gr[b].append(a)

visited = [False] * (n + 1)
order = []

def dfs1(u):
    visited[u] = True
    for v in g[u]:
        if not visited[v]:
            dfs1(v)
    order.append(u)

for i in range(1, n + 1):
    if not visited[i]:
        dfs1(i)

visited = [False] * (n + 1)
components = []

def dfs2(u, comp):
    visited[u] = True
    comp.append(u)
    for v in gr[u]:
        if not visited[v]:
            dfs2(v, comp)

for u in reversed(order):
    if not visited[u]:
        comp = []
        dfs2(u, comp)
        components.append(comp)

largest = max(components, key=len)

print(len(components))
print(*largest)
```最初の DFS は終了タイムを計算します。 再帰では、すべての子孫を探索した後でのみノードが追加されます。この順序付けにより、後で正しい SCC 抽出が可能になるため、これは不可欠です。 

2 番目の DFS は反転されたグラフ上で実行され、コンポーネントを構築します。 逆の終了順序から新しい開始ノードを選択するたびに、新しい SCC から開始することが保証されます。 

すべての SCC が収集された後、最大のコンポーネントが選択されます。 同数が許可されているため、長さによる単純な最大値を使用するだけで十分です。 

実装上の微妙な懸念の 1 つは、再帰の深さです。 最大 100,000 ノードでは、再帰制限を増やさなくても Python 再帰がオーバーフローする可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各 DFS トラバーサルは、両方のパスにわたって一定の回数だけ各ノードとエッジを訪問します。 
| スペース | O(n + m) | グラフと逆グラフ、再帰とコンポーネント ストレージの隣接リスト |

 この制約では最大 100,000 個のノードとエッジが許可されるため、線形時間 SCC アルゴリズムは時間とメモリの制限内に快適に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    sys.stdout = io.StringIO()

    input = sys.stdin.readline
    sys.setrecursionlimit(10**7)

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    gr = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        gr[b].append(a)

    visited = [False] * (n + 1)
    order = []

    def dfs1(u):
        visited[u] = True
        for v in g[u]:
            if not visited[v]:
                dfs1(v)
        order.append(u)

    for i in range(1, n + 1):
        if not visited[i]:
            dfs1(i)

    visited = [False] * (n + 1)
    components = []

    def dfs2(u, comp):
        visited[u] = True
        comp.append(u)
        for v in gr[u]:
            if not visited[v]:
                dfs2(v, comp)

    for u in reversed(order):
        if not visited[u]:

            dfs2(u, comp)
            components.append(comp)

    largest = max(components, key=len)
    out = str(len(components)) + "\n" + " ".join(map(str, largest))
    print(out)
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 単一の頂点グラフは、アルゴリズムが孤立したノードを有効な SCC として正しく扱うかどうかをテストします。 最初の DFS はノードをマークし、2 番目のパスはそのノードのみを含むコンポーネントを即座に形成します。 

1 → 2 → 3 のような有向非循環チェーンは、到達可能性がノードを誤ってマージしないことをチェックします。 各ノードは異なる時間で終了し、リバース DFS によってそれらのノードがシングルトン コンポーネントに分離されます。 

完全に周期的なグラフにより、相互到達可能性が正しく認識されることが保証されます。 この場合、反転グラフの DFS2 が 1 回のスイープですべてのノードに到達し、単一のコンポーネントが生成されるため、DFS1 の順序はあまり重要ではありません。 

これらのケースを総合すると、アルゴリズムが方向性到達可能性と真の相互接続性を曖昧さなく区別していることが確認されます。
