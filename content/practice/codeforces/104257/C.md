 ## 解決策
 ## 問題の理解

 最大 2021 人のユーザーにわたる有向関係グラフが与えられます。 各ユーザーは、すべてのユーザーの一部をフォローできます。 この世界では、サイズ m のサブセットのみがチャットルームに存在し、タスクはこのサブセット内に「有名人」が存在するかどうかを判断することです。 

有名人は、チャット ルームに限定された関係という観点から厳密に定義されます。チャット ルームの他のすべての参加者はこの人をフォローする必要があり、この人はチャット ルームで誰もフォローしてはならず、さらに、その人はチャット ルーム内に少なくとも 1 人のフォロワーを持っている必要があります。 最後の条件は、チャットルームでのすべてのやり取りから孤立した人が誤って受け入れられるという悪質なケースを防ぎます。 

入力はチャットルームの隣接行列を直接提供しません。 代わりに、m 人のユーザーごとに、n 人のユーザーの完全なグローバル セットにわたる発信フォロー リストが提供されます。 これにより、条件をチェックする場合にのみ、チャットルームまでのエッジをフィルタリングする必要があります。 

n ≤ 2021 および m ≤ n という制約は十分小さいため、O(m²) または O(nm) の解も容易に実現可能です。 n² は最悪でも約 400 万エントリであり、Python では許容できるため、完全な隣接行列を再構築しようとするソリューションもメモリ上では問題ありません。 

「少なくとも 1 人のフォロワー」という条件からは、微妙な特殊なケースが発生します。 全員にフォローされているが誰もフォローしていないユーザーでも、チャットルーム内に少なくとも 1 つの着信エッジが必要です。これは、m ≥ 2 の場合に保証されます。ただし、m = 1 の場合、「チャットルームに少なくとも 1 人のフォロワー」が満たされないため、条件は失敗します。そのため、答えは -1 でなければなりません。 

もう 1 つの注意が必要な点は入力形式です。t = 0 の場合、2 行目は文字通り「0」であり、空行や省略されたリストではありません。 リストが常に存在すると仮定する素朴なパーサーはここで壊れます。 

## アプローチ

 最も直接的なアプローチは、チャットルーム メンバーごとに、自分をフォローしている他のチャットルーム メンバーの数と、自分がフォローしているチャットルーム メンバーの数を計算することです。 これらの数がわかったら、3 つの条件を直接確認できます。 

この強引な方法を実行するには、チャットルーム ユーザーのセットを作成し、その中のすべてのペア (u, v) について、u の隣接リストをスキャンして、u が v に従うかどうかを確認します。 このチェックを単純に行うと、隣接関係がリストとして保存されるため、最悪の場合、各検索に O(n) のコストがかかる可能性があります。 これにより、O(m²・n) の複雑さが生じますが、これはまだ境界線にありますが、小さな制約を考慮すると許容可能です。 

ただし、各ユーザーのフォロー リストをセットに変換し、メンバーシップ チェックを O(1) にすることで、これを改善できます。 次に、候補者ごとに他のチャットルーム ユーザーとの関係を O(m) 単位でカウントするだけでよく、合計は O(m²) になります。 

重要な観察は、チャットルームの外での人間関係は決して必要ないということです。 すべては m 個のノードに制限されたペアごとのチェックに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | リストを使用した単純なペアチェック | O(m²・n) | O(n + エッジ) | 受け入れられた（かろうじて） |
 | ハッシュセットで最適化 | O(㎡) | O(n + エッジ) | 承認済み |

 ## アルゴリズムのチュートリアル

 グローバルなフォロー情報を高速なクエリを可能にする構造に変換し、チャットルーム内の m 人のユーザーに注意を制限します。

1. チャットルーム内のすべてのユーザーを読み取り、セット S に保存します。これにより、フォロー エッジがチャットルーム内に留まるかどうかを簡単にテストできます。 
2. 各チャットルーム ユーザー u について、フォロー リストを保存しますが、フィルタリングされるため、v も S に含まれるように v のみが保持されます。これにより、問題は S 上の誘導部分グラフに縮小されます。 
3. S の候補 c ごとに、S で c をフォローしているユーザーの数と、S で c をフォローしているユーザーの数の 2 つの量を計算します。 
4. c が S で誰もフォローしていないかどうかを確認します。これが失敗した場合、c は有名人になることができず、すぐに破棄されます。 
5. S 内の少なくとも 1 人のユーザーが c に従っているかどうかを確認します。 これにより、非分離条件が強制されます。 
6. 他のすべての m-1 ユーザが c に従っているかどうかを確認します。 S 内のユーザーが c をフォローしていない場合、c は有効な候補ではありません。 
7. すべての条件を満たすユーザーが 1 人だけの場合、その ID を出力します。 存在しない場合、または複数存在する場合は、-1 を出力します。 

唯一の微妙な点は、問題ステートメントでは自己フォローが禁止されているものの、実装では安全に処理する必要があるため、ステップ 6 で自己関係を慎重に無視する必要があることです。 

### なぜ効果があるのか

 このアルゴリズムは、チャットルーム セット S 上の誘導サブグラフ内の有名人の定義を明示的に評価します。すべての条件は、記載されているとおりに正確にチェックされます。つまり、発信エッジは S 内で 0 でなければならず、着信エッジは正確に m−1 でなければならず、着信エッジは少なくとも 1 でなければなりません。 すべてのチェックは S に対してローカルであるため、外部エッジが決定に影響を与えることはできません。 定義自体は純粋にセット内にあるため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    follows = {}
    chat_users = []

    # read chatroom users
    raw_info = []
    for _ in range(m):
        u, t = map(int, input().split())
        arr = list(map(int, input().split()))
        if t == 0:
            arr = []
        raw_info.append((u, arr))
        chat_users.append(u)

    S = set(chat_users)

    follow = {}
    for u, arr in raw_info:
        follow[u] = set(x for x in arr if x in S)

    if m == 1:
        print(-1)
        return

    for c in chat_users:
        out_cnt = len(follow[c])
        if out_cnt != 0:
            continue

        in_cnt = 0
        ok = True

        for u in chat_users:
            if u == c:
                continue
            if c in follow.get(u, set()):
                in_cnt += 1
            else:
                ok = False
                break

        if ok and in_cnt >= 1:
            print(c)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、m 人のチャットルーム ユーザーすべてを読み取り、ID とフォロー リストの両方を保存することから始まります。 t = 0 の特別な処理により、「0」行がリテラル ノードではなく空のリストとして正しく扱われることが保証されます。 

次に、チャットルーム ユーザーのみを含む集合 S を構築します。 各隣接リストはフィルタリングされ、S 内のエッジのみが保持されます。 これは、誘導されたサブグラフについてのみ推論することを保証する重要な削減ステップです。 

候補者の評価中、まずフィルタリングされた送信セットが空であることを確認して、「チャットルームで誰もフォローしない」条件を強制します。 これは最も強い剪定条件なので、最初にチェックされます。 

次に、他のすべてのチャットルーム メンバーをスキャンし、発信セットのメンバーシップを確認することで、着信エッジをカウントします。 メンバーが候補者をフォローしない場合は、直ちに拒否されます。 それ以外の場合は、少なくとも 1 つの入力エッジが存在することを確認します。 

## 実用的な例

 ### 例 1

 入力:```
7 4
1 4
2 3 4 7
2 1
3 5 6 7
4 2
1 3
```チャットルーム ユーザーは {1,2,3,4} です。 フィルタリングされたものは次のとおりです。 

| ユーザー | チャットルームでフォロー |
 | --- | --- |
 | 1 | {2,4} |
 | 2 | {3} |
 | 3 | {} |
 | 4 | {1,3} |

 候補者を順番にテストします。 

| 候補者 | 空の送信 | 他人からの着信 | 有効 |
 | --- | --- | --- | --- |
 | 1 | いいえ | - | 拒否 |
 | 2 | いいえ | - | 拒否 |
 | 3 | はい | 2と4から | 同意する |
 | 4 | いいえ | - | 拒否 |

 したがって、出力は 3 になります。 

これは、アルゴリズムが、誘導されたサブグラフ内で発信エッジがゼロで、着信カバレッジが完全である唯一のノードを正しく分離していることを確認します。 

### 例 2

 入力:```
3 3
1 2
2 3
2 0
```チャットルームは {1,2,3} です。 フィルタリングされたものは次のとおりです。 

| ユーザー | チャットルームでフォロー |
 | --- | --- |
 | 1 | {2} |
 | 2 | {3} |
 | 3 | {} |

 候補 3 には発信エッジがありませんが、着信は 1 からではなく 2 からのみです。そのため、「他のすべてが続く」条件を満たしません。 

すべての制約を満たす候補がないため、出力は -1 になります。 

これは、発信エッジがゼロであることをチェックするだけではなく、「着信が完了している必要がある」という条件が重要である理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(㎡) | 各候補者は、他のすべてのチャットルーム メンバーを 1 回スキャンすることによって検証されます。 
| スペース | O(n + m) | 隣接リストとチャットルーム フィルタリングのためのストレージ |

 n ≤ 2021 および m ≤ n の場合、最悪の場合の m² は約 400 万チェックであり、これは Python の制限内に簡単に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、m = 1 の場合です。入力の場合:```
1 1
1 0
```どのノードも「チャットルーム内の少なくとも 1 人のフォロワー」を満たすことができないため、アルゴリズムはすぐに -1 を返します。 これにより、単純なシングルトンを誤って受け入れることが回避されます。 

もう 1 つのケースは、ノードが誰にも従わないが、他のすべてのノードも従わない場合です。 例えば：```
3 3
1 1
2 1
2 0
```ここで、ノード 2 には発信エッジが 0 ありますが、ノード 1 は 2 に従わないため、着信条件は失敗します。 アルゴリズムは、受信スキャン中にそれを正しく拒否します。 

3 番目のケースは、密な相互フォローです。 すべてのノードが他のすべてのノードの後に​​続く場合、出力制約がすべてのノードで失敗するため、候補は合格しません。 送信セットのサイズに基づいて早期に拒否することで、完全に接続されたノードが誤って受け入れられることがなくなります。
