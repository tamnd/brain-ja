 ## 解決策
 ## 問題の理解

 P、D、A、O の 4 つの文字のみで構成される文字列が与えられます。各文字は、一列に並んでいる戦士のタイプを表します。 この行の連続するセグメントを選択することができます。つまり、部分文字列を選択し、それを「リーグ」と呼びます。 

その部分文字列内で 4 つの文字すべてが同じ回数出現する場合、リーグは有効であるとみなされます。 私たちのタスクは、可能な限り最長の有効なリーグを見つけて、その長さを出力することです。 条件を満たす空でない部分文字列がない場合は、ゼロを返します。 

ここでの重要な構造は、部分文字列を検索しているが、条件はローカルではないということです。 これは 4 つのカテゴリのグローバル数に依存するため、部分文字列を直接列挙するとコストが高すぎることがわかります。 

入力長は最大 200,000 です。 すべての部分文字列を単純に 2 次スキャンすると、文字数をすばやく数えた場合でも、最悪の場合約 200 億のチェックが必要になりますが、これは一般的な時間制限では実現できません。 どのソリューションでも、部分文字列のチェックをクエリごとに O(n) から減らすか、部分文字列の列挙を完全に回避する必要があります。 

エッジケースは微妙な意味で重要です。 文字列が「AAAA」のような場合、4 文字すべてのバランスをとることができないため、有効な部分文字列は存在せず、答えはゼロになります。 弦がすでに全音域で完全にバランスが取れている場合は、弦全体が答えになります。 有効な部分文字列が複数ある場合は、最初に見つかった部分文字列だけでなく、最大長を選択する必要があります。 

よくある失敗例は、両端から文字を削除することは、プレフィックスやサフィックスだけでなく、任意の部分文字列を選択することと同じであることを忘れていることに起因します。 たとえば、「PDAOPDAOOPDA」では、有効な回答が多くのシフトされたウィンドウに存在し、接頭辞のような構造に注意を限定すると、それらのほとんどを見逃してしまいます。 

## アプローチ

 ブルートフォース手法では、すべての部分文字列がチェックされます。 インデックス l と r の各ペアについて、P、D、A、および O の出現をカウントし、等しいことを検証します。 これは条件を直接強制するため正しいですが、部分文字列ごとに O(n) の作業が必要になります。 O(n²) 個の部分文字列があるため、合計の複雑さはカウントが単純な場合は O(n³)、または接頭辞の合計を使用すると O(n²) になりますが、O(n²) でも 200,000 には遅すぎます。 

重要な観察は、「P、D、A、O の数が等しい」という条件をプレフィックスの違いに対する制約として書き換えることができるということです。 各文字の継続カウントを定義する場合、これらのカウント間の差異が特定の方法で一貫性を保っている場合に、部分文字列は正確に有効になります。 

4 つの数値を直接追跡する代わりに、問題を低次元の表現に変換します。 部分文字列内のすべてのカウントが等しい場合、その部分文字列については次のようにする必要があります。 

カウント(P) − カウント(D) = 0

 カウント(P) − カウント(A) = 0

 カウント(P) − カウント(O) = 0

 したがって、3 つの独立した差分がゼロである場合にのみ、4 つのカウントすべてが等しくなります。 

したがって、これらの違いのプレフィックス ベクトルを追跡します。 2 つの位置 i と j は、それらの接頭辞の差の状態が同一である場合に限り、有効な部分文字列を形成します。 これにより、問題はプレフィックス ハッシュ マップ内の 2 つの等しい状態の間の最大距離を見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) または O(n³) | お(1) | 遅すぎる |
 | プレフィックス状態ハッシュ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各文字を 4 つのカウンタの更新に変換し、文字列を左から右にスキャンしながら P、D、A、および O の累計を維持します。 これにより、すべてのプレフィックスを簡潔に表すことができます。 
2. 各位置について、カウント間の相対的な差のみを捕捉する正規化された状態を計算します。 便利な選択は、(P-D、P-A、P-O) のようなタプルです。 これにより、絶対値は必要なく、プレフィックス間の等価性のみが必要となるため、冗長性が削除されます。 
3. 各州を、それが出現する最も古いインデックスにマッピングする辞書を維持します。 最も古いインデックスを保存する理由は、その後同じ状態が発生すると、その状態の最大長の有効な部分文字列が形成されるためです。 
4. 文字列が始まる前に、空のプレフィックスに対応する状態でマップを初期化します。 これにより、インデックス 0 で始まる部分文字列が自然に考慮されるようになります。 
5. 文字列を反復処理しながら、現在の状態を計算し、それが以前に見られたかどうかを確認します。 存在する場合は、現在のインデックスと最初の出現の間の長さを計算し、この長さが大きい場合は答えを更新します。 
6. 状態がまだ確認されていない場合は、現在のインデックスを最初の状態として保存します。 
7. 文字列全体を処理した後、保存されている最大長が答えとなります。 

最初に出現したものを保存することがなぜ重要なのかは微妙です。後から出現したものほど部分文字列が短くなり、最大長が必要なので、常に早い方が良いのです。 

### なぜ効果があるのか

 文字列のすべての接頭辞は、3 次元差分空間内の点に対応します。 2 つの端点がこの空間内の同じ点にマップされる場合、部分文字列のすべての文字のカウントは正確に同じになります。これは、それらの差がゼロであることを意味します。 このアルゴリズムは、単一のスキャンに沿って最も遠い等点のペアを見つける問題を簡素化します。 各状態は相対カウントに関する必要な情報をすべてエンコードするため、2 つの異なる有効な部分文字列が誤ってマージされたり、有効な部分文字列が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    cp = cd = ca = co = 0
    
    first = {}
    first[(0, 0, 0)] = -1
    
    ans = 0
    
    for i, ch in enumerate(s):
        if ch == 'P':
            cp += 1
        elif ch == 'D':
            cd += 1
        elif ch == 'A':
            ca += 1
        else:
            co += 1
        
        state = (cp - cd, cp - ca, cp - co)
        
        if state in first:
            ans = max(ans, i - first[state])
        else:
            first[state] = i
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、4 つの実行中のカウンターを保持し、インデックスごとに 3 つのコンポーネントの状態に圧縮します。 辞書`first`各状態の最も古い発生のみを保持するようにします。 初期化中`(0,0,0)`インデックスで`-1`インデックス 0 で始まる部分文字列が正しく寄与できるようになります。 

よくある落とし穴は、センチネルの初期化を忘れることです。 これがないと、文字列の先頭から始まる部分文字列はカウントされません。

### 例 2: PPPOOPPOOAAAADDDD

 ここでは、文字列はすでにバランスの取れたブロックに構造化されています。 

アルゴリズムは、差異が相殺される状態を繰り返し再訪します。 状態 (0,0,0) が複数回出現し、最も遠い繰り返しでは全長は 16 になります。 

これは、アルゴリズムがバランスの取れたプレフィックスを自然に圧縮し、構造を明示的に検索する必要がないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は 1 回処理され、ステップごとに O(1) の辞書操作が行われます。 
| スペース | O(n) | 最悪の場合、すべてのプレフィックス状態が異なる場合があります。 

リニア スキャンは 200,000 文字の制約内に快適に収まります。 保存される状態の数は n に制限されているため、メモリの使用も安全です。

    sys.stdin = io.StringIO(inp)

def solve_capture(inp: str) -> str:

    input = sys.stdin.readline
    sys.stdin = io.StringIO(inp)
    
    s = input().strip()

    ans = 0
    
    for i, ch in enumerate(s):

        elif ch == 'D': cd += 1
        elif ch == 'A': ca += 1

        if state in first:
            ans = max(ans, i - first[state])
        else:
            first[state] = i
    
    return str(ans)

 ## 特殊なケース

 エッジケースの 1 つは、有効な部分文字列がまったく存在しない場合です。 入力「AAAA」の場合、すべてのプレフィックス状態は個別であり、4 つの文字すべてのバランスが取れるように初期状態を繰り返すことはありません。 アルゴリズムが初期化されます`(0,0,0)`インデックスで`-1`, しかし、その後のプレフィックスはこの状態に戻らないため、答えはゼロのままです。 

別のケースは、弦全体のバランスが取れている場合です。 「PDOOPDA」の場合、状態は次の状態に戻ります。`(0,0,0)`最後のインデックスで。 この状態が見られたので、`-1`の場合、計算された長さは文字列全体に及び、正しい最大値が生成されます。 

3 番目のケースは、部分的なバランスが繰り返される場合です。 「PDAO PDAO PDAO」のような文字列では、同じ状態が複数回出現し、アルゴリズムは最も早い出現を正しく優先し、最後の繰り返しで終わる部分文字列の長さを最大化します。
