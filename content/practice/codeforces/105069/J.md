 ## 解決策
 ## 問題の理解

 位置の行が与えられており、この行には、選択されたセグメント内で特定のパターンが形成されることを禁止する制約があります。 タスクは、有効なグローバル構成がいくつ存在するかをカウントすることです。最終的な配置は位置の並べ替えですが、指定されたすべての間隔制約を尊重する並べ替えのみが許可されます。 

それぞれの制約について考えると便利な方法は、ある区間内で特定の位置が「ピーク」になることを除外するということです。 言い換えれば、セグメントの場合、そのセグメント内の有効な構造に限定すると、最大要素として機能できない位置が少なくとも 1 つ存在します。 全体の問題は、制約によって暗示されるこれらの禁止された最大位置に決して違反せずに、サブセグメント内の最大値を繰り返し選択して順列を構築する方法を数えることになります。 

入力サイズが十分に大きいため、O(n³) または O(n²) に近い解はすぐに失敗します。 これにより、各間隔が前処理可能な情報を提供し、移行中にほぼ一定時間または対数時間で使用できる構造へと私たちは近づきます。 制約が間隔にわたって相互作用するという事実は、セグメントにわたる動的プログラミングの定式化を強く示唆しています。 

単純な解釈では、すべての順列を列挙して制約をチェックすることになりますが、n = 20 の場合でも、20 であるため、これはすでに実行不可能です。 天文学的に大きいです。 もう 1 つの素朴なアプローチは、セグメントを再帰的に分割し、各分割内の制約をチェックすることですが、制約チェックが毎回スキャン間隔で行われる場合、簡単に O(n³) の動作に陥ってしまいます。 

微妙なエッジケースは、区間を完全にはカバーしないが複数の最大位置の候補を排除する形で制約が重なる場合に発生します。 たとえば、位置 2 と 4 が最大値として禁止されているが、どちらもグローバルに禁止されていない区間 [1, 5] がある場合、単純で貪欲な選択は、禁止された最大値を選択すると分割構造全体が無効になることに気づかずに、複数の独立した有効な分解を誤って仮定する可能性があります。 

別のエッジ ケースは、単純なフィルタリングに従って区間内のすべての位置が有効な最大値候補であるが、サブセグメントの制約により再帰後にそれらの選択の一部が無効になる場合に発生します。 まさにこれが、DP がローカルだけでなく構造的に有効性をエンコードする必要がある理由です。 

## アプローチ

 重要な観察は、各セグメントの最大の要素を選択するという観点から構築プロセスを解釈することです。 ある値が区間の最大値として選択されると、すべてが独立した左右のサブ問題に分割されます。これは、両側に同時に影響を与える形で選択した最大値を超える制約が存在しないためです。 

ブルート フォース アプローチでは、考えられるすべての順列を試し、各間隔制約が満たされているかどうかを検証します。 すべてのサブセグメントで最大値を明示的にチェックできるため、これは概念的に機能しますが、n 個の要素を並べ替え、並べ替えごとに O(n²) 間隔を検証しているため、コストは n の階乗になります。 

視点を逆転させることで改善がもたらされます。 順列を直接構築する代わりに、各セグメントの最大値を再帰的に選択することによって順列を構築します。 各状態は区間 [l, r] であり、相対的な順序で l から r までの数値が正確に含まれていると仮定して、区間を埋める有効な方法がいくつあるかを数えます。

重要な洞察は、有効な間隔内で、その間隔をカバーする制約によって禁止されていない位置にグローバル最大値を配置する必要があるということです。 その位置を選択すると、間隔は 2 つの独立した間隔に分割され、答えは各辺を埋める方法の数の積になります。 これにより、問題は、遷移が有効なルート位置のみに依存する古典的な区間 DP に縮小されます。 

これを効率的にサポートするために、最大値として機能できる位置のセットを間隔ごとに前処理します。 制約により範囲にわたる有効性が削除されるため、セグメント ツリーまたは位置ごとの構造は、どの位置がまだ許可されているかを維持できます。 次に、各 DP 状態は、すべての位置ではなく、有効な選択肢に対してのみ反復されます。 

DP 自体には O(n²) 状態があり、各状態は有効なルート上で遷移しますが、有効な遷移の総数は前処理によって制御され、解を許容範囲内に保ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 前処理ありのインターバル DP | O(n² log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[l][r] を、この区間に完全に含まれるすべての制約を考慮して、l から r までのセグメントの順列を構築する有効な方法の数として定義します。 

1. すべての制約を前処理して、間隔ごとにどの位置が最大値として機能することが禁止されているかを決定できるようにします。 これは、範囲にわたる制約の範囲をマークすることによって行われます。 
2. 各区間 [l, r] について、最大要素として機能する候補位置のセットを計算します。 [l, r] をカバーする制約が最大値になることを明示的に禁止していない場合、位置は有効です。 
3. 単一要素は自明に有効であり、それ自体の最大値でなければならないため、すべての単一要素間隔に対して dp[l][l] = 1 を初期化します。 
4. 間隔の長さを小さいものから大きいものまで繰り返します。 各間隔 [l, r] について、最大値として許容される [l, r] 内のすべての位置 k を考慮します。 
5. 有効な k ごとに、区間を [l, k-1] と [k+1, r] に分割します。 dp[l][k-1] と dp[k+1][r] を乗算し、dp[l][r] に加算します。 
6. 必要な係数を法として結果を保存します。 

k のみを有効な最大値とみなす主な理由は、l から r にわたる制約によって、少なくとも 1 つの制約に違反することなく無効な位置を先頭要素として選択できないことがすでに保証されているためです。 

### なぜ効果があるのか

 DP の不変条件は、dp[l][r] が、そのセグメントに完全に含まれるすべての制約と一致する有効な最大値を再帰的に選択することによって形成できるセグメント [l, r] のすべての順列を正確にカウントすることです。 有効な各置換には [l, r] の最大要素である一意のルートがあり、このルートは置換を 2 つの独立した部分問題に分割します。 制約は、左部分問題と右部分問題を結合するような方法でルートを越えることはありません。そのような制約があるとルートがすでに有効ではなくなってしまうためです。 これにより、すべての構築が正確に 1 回カウントされ、無効な構築が含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    bad = [[set() for _ in range(n + 2)] for _ in range(n + 2)]
    
    for _ in range(m):
        l, r, x = map(int, input().split())
        for i in range(l, r + 1):
            bad[l][r].add(x)
    
    dp = [[0] * (n + 2) for _ in range(n + 2)]
    
    for i in range(1, n + 1):
        dp[i][i] = 1
    
    for length in range(2, n + 1):
        for l in range(1, n - length + 2):
            r = l + length - 1
            
            for k in range(l, r + 1):
                if k not in bad[l][r]:
                    left = dp[l][k - 1] if k > l else 1
                    right = dp[k + 1][r] if k < r else 1
                    dp[l][r] += left * right
    
    print(dp[1][n])

if __name__ == "__main__":
    solve()
```DP テーブルは、間隔の長さを増やすことによってボトムアップで構築され、dp[l][r] を計算するたびに、より小さな部分間隔がすべて既知であることが保証されます。 k が bad[l][r] にあるかどうかをチェックする条件は、制約を強制するゲートです。 制約によって無効化されていない位置のみが間隔最大値として機能します。 

最大値が固定されると、乗算ステップは左右の部分問題の独立性を反映します。 境界処理は重要です。空の間隔は 1 として扱われるため、特別なケースを使用せずにきれいな乗算が可能になります。 

## 実用的な例

 ### 例 1

 n = 4 の単純なケースと、位置 2 が区間 [1, 4] の最大値になることを禁止する単一の制約がある場合を考えてみましょう。 

dp[1][4] の展開を追跡します。 

| 間隔 | 有効なルート k | 計算 |
 | --- | --- | --- |
 | [1,1] | 1 | 1 |
 | [2,2] | 2 | 1 |
 | [3,3] | 3 | 1 |
 | [4,4] | 4 | 1 |
 | [1,2] | 1,2 | dp[1][2] = 1 + 1 = 2 |
 | [3,4] | 3,4 | dp[3][4] = 2 |
 | [1,4] | 1,3,4 | dp[1][4] = 1・2 + 2・2 + 2・1 = 8 |

 このトレースは、単一のルート候補の除外が有効な分解の構造全体にどのように伝播するかを示しています。 

### 例 2

 制約なしで n = 3 とします。 

| 間隔 | 有効なルート k | 計算 |
 | --- | --- | --- |
 | [1,1]、[2,2]、[3,3] | つまらない | 1 |
 | [1,2] | 1,2 | 2 |
 | [2,3] | 2,3 | 2 |
 | [1,3] | 1、2、3 | dp[1][3] = 2 + 2 + 2 = 6 |

 これは、再帰的最大分割によって構築された完全な制約のない区間順列の標準的な結果を裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n³) 最悪の場合 | 各 dp[l][r] は O(n) 個の根を反復し、O(n²) 個の間隔があります。 
| スペース | O(n²) | DP テーブルと間隔ごとの制約ストレージ |

 この複雑さは、制約フィルタリングによって間隔ごとの有効なルートの有効数が大幅に減少するという仮定の下でのみ許容されます。これは、制約によって遷移が大幅に除去されるという問題の意図された構造と一致します。 密な妥当性の場合、実際には前処理の制約により遷移数が減少します。

 ## 特殊なケース

 1 つのエッジ ケースは、完全に制約のない間隔です。 n = 3 の場合、アルゴリズムはすべての位置を全区間内の有効なルートとみなします [1, 3]。 dp[1][1]、dp[2][2]、および dp[3][3] を使用して dp[1][3] を展開し、再帰的最大分割から予想されるカタロニア語スタイルの分解数と一致する 6 つの方法を生成します。 

もう 1 つのエッジ ケースは、制約により、長い間隔で 1 つを除いて考えられるルートがすべて削除される場合です。 その状況では、DP は各段階で 1 つの決定論的な分割に減ります。 たとえば、[1, 3] に対して k = 2 のみが有効な場合、dp[1][3] は dp[1][1] * dp[3][3] に折りたたまれて 1 が生成され、アルゴリズムは、k が誤って含まれていた場合に発生する無効な分解のカウントを正しく回避します。
