 ## 解決策
 ## 問題の理解

 一列に並べられた一連の本が与えられます。各本にはその種類を表す識別子があります。 目標は、最終的な構成が非常に制限された構造に一致するように最小限の移動を実行することです。本は最終的に一貫したパターンで 2 つの連続するブロックに分割され、分割が行われる場所とタイプを 2 つの面にどのように割り当てるかを選択できます。 

重要な隠された構造は、最終的な配置が恣意的ではないということです。 代わりに、常に 2 つのブロック形式に折りたたまれます。つまり、並べ替えると、選択した 1 つのカテゴリに属する​​すべての書籍がカットの片側に集中し、残りの書籍が反対側を占めます。 ここでのタスクは、分割位置と分割を定義するカテゴリの両方を決定し、そのような構成を実現するために移動する必要がある本の最小数を計算することです。 

入力は長さ n の単一シーケンスであり、各要素はブック タイプです。 出力は単一の整数です。これは、最終的な配置が必要な 2 ブロック構造と一致するように再配置する必要がある本の最小数です。 

複雑さの観点から見ると、シーケンスのサイズが十分に大きいため、分割位置と型の割り当てのすべてのペアにわたる二次シミュレーションは実行できません。 すべての構成に対してシーケンスを明示的に再構築しようとするアプローチでは、およそ O(n^2) 以上の悪い動作が発生します。これは、一般的な Codeforce の制約 (約 2 秒、n が最大約 10^5) で許容される値をはるかに超えています。 

この構造には微妙な特殊ケースも隠されています。すべての本がすでに同じ種類である場合、どの分割も有効であり、答えはゼロになるはずです。 型が 1 回しか出現しない場合には、別の特殊なケースが発生します。 その場合、単純な推論では、移動が常に必要であると誤って想定される可能性がありますが、分割位置によっては、移動しなくてもすでに正しい側にある可能性があります。 

3 番目の重要なエッジケースは、最適な分割が配列の境界にある場合です。 内部分割ポイントのみをチェックする単純な実装では、選択されたタイプのすべてがすでに片側にある構成を見逃してしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。配列内の分割位置を選択し、「特別な」グループとして扱いたい型を選択します。 ペアごとに、その種類のすべての本が分割の片側に配置され、他のすべての本が反対側に配置されるように、何冊の本を移動する必要があるかをシミュレーションします。 コストを直接計算するには、毎回アレイをスキャンする必要があるため、構成あたり O(n) になります。 考えられる分割点は O(n) で、最悪の場合は候補タイプが O(n) まであるため、このアプローチは単純な実装では O(n^3) に縮退するか、注意深く前処理を行った場合はよくても O(n^2) になります。 いずれにせよ、n が大きいと遅すぎます。 

重要な点は、分割ごとにカウントを最初から再計算する必要がないということです。 代わりに、プレフィックスの頻度を事前に計算できます。すべてのタイプについて、それが各位置に何回出現するかがわかります。 これにより、O(1) で「分割の左側に型 x が何回出現するか」を答えることができます。 これが得られれば、固定分割と固定タイプのコストを定数時間で計算できます。 

これにより、すべての分割位置を反復処理し、プレフィックス数に基づいて式を評価するという問題が軽減されます。 すべての決定は要素の並べ替えではなく累積カウントのみに依存するため、この構造は効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 実装に応じて O(n^3) または O(n^2 log n) | O(n) | 遅すぎる |
 | 最適 | O(n^2) プレフィックス最適化あり (制約によってはそれ以上) | O(n^2) または圧縮ありの O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

本の種類にインデックスを付け、各種類のプレフィックス数を維持できると仮定します。 

1. まず、書籍の種類を圧縮またはインデックス付けして、頻度情報を効率的に保存できるようにします。 これにより、可能な場合にはハッシュ マップではなく配列内のカウントにアクセスできるようになります。 
2. pref[i][t] が最初の i 冊にタイプ t が出現する回数を表す接頭語頻度テーブルを作成します。 これにより、任意のプレフィックス セグメントに対する定数時間の範囲クエリが可能になります。 
3. 考えられるすべての分割位置について繰り返します。 この分割により、配列が左側のセグメント [1, i] と右側のセグメント [i+1, n] に分割されます。 
4. 各分割について、配置の「特別な側」を定義できる可能性のある候補タイプ t をそれぞれ考慮します。 目的は、選択した構造に対して現在誤って配置されているタイプ t の本の数を評価することです。 
5. プレフィックス テーブルを使用して左側にタイプ t が何回存在するかを計算し、合計数から減算して右側に何回存在するかを計算します。 
6. 固定 (i, t) のコストは、意図した面にない t ブックの数と、間違った面にある非 t ブックの数によって決まります。 これは、純粋にプレフィックス数と合計頻度の観点から表現できます。 
7. 分割とタイプのすべての選択肢にわたる最小コストを追跡します。 

### なぜ効果があるのか

 すべての有効な最終的な配置は、分割ポイントの選択と、そのタイプに対してどちらの側が「優先される」かを定義する区別されたタイプに対応します。 これら 2 つの決定が修正されると、すべての本に一意に決定された正しい位置クラスが設定されます。 コスト関数は、その分類に関する不一致を単にカウントするだけです。 プレフィックスの合計により各セグメントの正確な数が得られるため、すべての構成は再計算なしで 1 回だけ評価され、配置の欠落や無効な構造が考慮されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    # coordinate compress
    vals = {v:i for i,v in enumerate(sorted(set(a)))}
    a = [vals[x] for x in a]
    m = len(vals)

    # prefix counts
    pref = [[0]*(m+1) for _ in range(n+1)]
    for i in range(1, n+1):
        x = a[i-1]
        for t in range(m):
            pref[i][t] = pref[i-1][t]
        pref[i][x] += 1

    total = [0]*m
    for x in a:
        total[x] += 1

    ans = n

    for i in range(n+1):
        for t in range(m):
            left_t = pref[i][t]
            right_t = total[t] - left_t

            left_size = i
            right_size = n - i

            # cost: move non-t from left to right + t from right to left
            cost = (left_size - left_t) + right_t
            ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、プレフィックスのカウントに密な配列を使用できるように書籍の種類を圧縮することから始まります。 プレフィックス テーブルは行ごとに構築されるため、各プレフィックス クエリはタイプごとに一定時間で応答できます。 これは最もメモリ効率の高い表現ではありませんが、ロジックを直接的に保ち、ハッシュのオーバーヘッドを回避します。 

分割位置ごとに、コードはすべての候補タイプを「特別な」タイプとして評価します。 コスト式は、間違って配置された要素のカウントから直接得られます。左側にあるタイプ t ではないものはすべて右に移動し、右側にあるすべての t は左に移動する必要があります。 この対称分解により、スワップの明示的なシミュレーションが回避されます。 

最終的な答えは、すべての構成における最小コストです。

```一度に 1 つのスプリットを追跡します。

 | --- | --- | --- |

 | 分割します | t=2 左 | t=2 コスト |

 最適な構成は、t=2 で分割が中央付近にある場合に発生し、コスト 1 が生成されます。 

これは、分割と選択されたタイプの両方が相互作用し、最適なソリューションが単一の貪欲な選択に結び付けられていないことを示しています。 

### 例 2

 入力:```

```すべての要素が有効なグループ化にすでに一致しているため、すべての分割とすべてのタイプでは不一致コストがゼロになります。 t=1 の場合、left_t は常に left_size に等しく、コストの両方の項がゼロになるため、アルゴリズムはこれを確認します。 

これにより、均一な配列の正確性が検証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf

    # simplified embedded solution
    n = int(sys.stdin.readline().strip())
    a = list(map(int, sys.stdin.readline().split()))
    vals = {v:i for i,v in enumerate(sorted(set(a)))}
    a = [vals[x] for x in a]
    m = len(vals)

    pref = [[0]*(m+1) for _ in range(n+1)]
    for i in range(1, n+1):
        for t in range(m):
            pref[i][t] = pref[i-1][t]
        pref[i][a[i-1]] += 1

    for x in a:
        total[x] += 1

    for i in range(n+1):

            right_t = total[t] - left_t
            cost = (i - left_t) + right_t

    return str(ans)

 ## 特殊なケース

 すべての同一の書籍のような均一なシーケンスは、分割位置に関係なく、コスト式が正しくゼロに折りたたまれることを示しています。 プレフィックス数は常にセグメント サイズと一致するため、移動はカウントされません。 

すべての要素が異なるシーケンスは、自然にグループ化が存在しない場合でも、アルゴリズムが依然として正しく動作することを示しています。 分割すると、ほぼすべての要素が強制的に移動され、コストにはその不均衡が正確に反映されます。 

厳密に交互のシーケンスは、最適な分割が必ずしも中心や境界にあるわけではなく、選択したタイプのプレフィックスの不一致を最小限に抑えることに依存していることを強調しています。 プレフィックスの定式化により、すべての分割が一貫して評価されることが保証されるため、正しい最小値が引き続き見つかります。
