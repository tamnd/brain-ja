 ## 解決策
 ## 問題の理解

 私たちは、人がトレードオフのあるアクションを繰り返し実行する計画の問題を検討しています。各作業単位は、ある程度の「食料価値」を生み出しますが、ある程度のスタミナや労力も消費します。 各アクション タイプは複数回実行できます。獲得した食料の合計と消費したスタミナの合計との間の可能な限り最適なトレードオフを理解したいと考えています。 

形式的には、各「アイテム」は 1 種類の食事活動に対応しており、食事の質が一定増加し、スタミナが一定コストでかかります。 これらのアクティビティを実行する回数を選択でき、アクションの総数はスタミナまたは気になる最大の食事によって暗黙的に制限されます。 前処理の後、次の形式の複数のクエリに答える必要があります。スタミナを最大で一定量消費できる場合、得られる食品の品質は最大どれくらいですか?

 自然な構造はナップザック スタイルの最適化問題ですが、重要な問題は、スタミナ制限と値スケールの両方が十分に大きいため、単純な次元を超える直接 DP が実行不可能であることです。 この制約は、限界を超える二次または擬似二次状態空間が失敗することを意味するため、注意深い状態変換による 1 次元の最適化が必要です。 

すべてのアイテムのスタミナコストが非常に小さいが価値が大きい場合、微妙なエッジケースが発生し、貪欲な推論が失敗します。 別の障害モードは、DP の方向を誤って反転すると同じ遷移層内のアイテムの再利用につながり、意図したモデルが解釈によって異なる場合に事実上問題を無制限のナップザックに変える場合に発生します。 正しいソリューションでは、遷移順序を厳密に制御する必要があります。 

## アプローチ

 最も直接的な定式化は、dp[s] がちょうど s 単位のスタミナを使用して達成可能な最大食料値である状態を定義することです。 これは古典的なナップサックの定式化です。各項目について、この項目を追加することで前の状態を拡張しようとします。 これは正しいのですが、スタミナ ディメンションが非常に大きくなり、多くのクエリを処理する必要がある場合にすべての を効率的に反復することが不可能になるため、すぐに問題が発生します。 

より実用的なブルート フォース ビューは、クエリ制限ごとに、その制約の下でアイテムの最適なサブセットを計算することです。 これにより、クエリごとに標準の 0/1 ナップザックが発生し、クエリごとに O(nS) のコストがかかり、まったく実行不可能になります。 

重要な観察は、実際には、クエリ時に各スタミナ バジェットの最適な値を個別に必要とするわけではないということです。 代わりに、スタミナ コストと食料の価値の間のパレート フロンティアだけが必要です。達成可能な食料の価値については、必要な最小限のスタミナが必要です。 これにより、問題はデュアル ナップザック DP に変換されます。 

状態を dp[v]、つまりちょうど v 単位の食料価値を達成するために必要な最小スタミナとして再定義します。 これにより視点が逆転し、達成可能な合計値によって DP 次元を制限できるようになります。これは通常、はるかに小さくなるか、圧縮が可能な方法で構造化されます。 この DP が構築されると、クエリへの応答は単調探索問題になります。スタミナ制限が与えられた場合、dp[v] が制限内に収まるような最大の v を見つけます。これは二分探索で答えることができます。 

残りの技術的な問題は、正しい移行順序を確保することです。 スタミナを最小限に抑えているため、明示的に許可されていない限り、各アイテムは 1 回の反復で複数回再利用されることを避ける方法で処理する必要があります。 これは、値の降順で dp 配列を反復することによって処理され、各項目がレイヤーごとに 1 回適用されるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの Stamina インデックス付き DP | O(q・n・S) | O(S) | 遅すぎる |
 | 値インデックス付き DP + 二分探索 | O(n · V + q log V) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 食品の品質を主軸として扱い、問題を価値達成可能性 DP に変換します。 dp[v] を、合計値 v を正確に取得するために必要な最小スタミナとして定義します。クエリの制限がスタミナに依存するため、このシフトが必要となるため、マッピングを反転したいと考えます。 
2. dp を大きなセンチネル値で初期化し、dp[0] = 0 に設定します。これは、食料ゼロを達成するにはスタミナがゼロであることを表します。 
3. バリューゲイン val とスタミナコストコストを持つ各食料オプションについて、v の降順で dp 配列を更新します。 dp[v] がすでに到達可能な v ごとに、v + val への移行を試み、 dp[v + val] = min(dp[v + val], dp[v] +cost) を更新します。 逆反復により、各項目が DP レイヤーごとに最大 1 回使用されることが保証されます。 
4. すべてのアイテムを処理した後、dp 配列は完全なパレート フロンティアを表します。達成可能な食料の値ごとに、必要な最小スタミナがわかります。 
5. v の増加に対して dp 値が単調最小化されるようにヘルパー構造を前処理し、任意の v に対して dp[v] が少なくともその値を達成するための可能な最良のスタミナであることを保証します。 このステップにより、最適でない支配状態が除去されます。 
6. 各クエリのスタミナ制限 S について、v に対して二分探索を実行して、dp[v] ≤ S となる最大 v を見つけます。これは、最適なフロンティア表現ではより高い値を達成するために必要なスタミナが少なくてはいけないという意味で dp[v] が単調であるため機能します。 

なぜ効果があるのか

 DP は、達成可能なすべての価値とスタミナのペアを表す一連の状態を維持しますが、将来の最適な答えには支配された状態は決して必要ありません。 同じ値またはそれより低い値を達成するためにより多くのスタミナを必要とする状態は、クエリに対する最適なソリューションの一部ではありません。 逆反復により、単一使用の遷移の正確性が確保され、意図した組み合わせ構造が維持されます。 最終的な DP は、支配的な状態を枝刈りした後に単調なフロンティアをエンコードするため、二分探索ステップは有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, q = map(int, input().split())
    
    items = []
    max_val = 0
    
    for _ in range(n):
        v, c = map(int, input().split())
        items.append((v, c))
        max_val += v

    dp = [INF] * (max_val + 1)
    dp[0] = 0

    for v, c in items:
        for cur in range(max_val - v, -1, -1):
            if dp[cur] != INF:
                nv = cur + v
                nd = dp[cur] + c
                if nd < dp[nv]:
                    dp[nv] = nd

    for i in range(1, max_val + 1):
        if dp[i] > dp[i - 1]:
            dp[i] = dp[i - 1]

    def get_best(stamina):
        lo, hi = 0, max_val
        ans = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if dp[mid] <= stamina:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        return ans

    for _ in range(q):
        s = int(input())
        print(get_best(s))

if __name__ == "__main__":
    solve()
```コア コードは、総コストではなく総価値に対するナップサック スタイルの DP です。 逆ループオーバー`cur`各項目が反復ごとに 1 回適用されるようにし、誤って再利用することを防ぎます。 2 番目のループは単調性を強制するので、高い値のスタミナ要件が低い値よりも人為的に高くなることはありません。 

二分探索が機能するのは、より高い達成可能な値には少なくとも同じくらいのスタミナが必要であるという意味で、支配状態を平坦化した後、dp が非増加関数になるためです。 

## 実用的な例

 ### 例 1

 (値、コスト): (3, 2)、(2, 1) のアイテムがあり、スタミナ制限 1、2、3 での最大値を求めるクエリがあるとします。 

dp を段階的に構築していきます。 

| アイテム | dp[0] | dp[2] | dp[3] | dp[5] |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | インフ | インフ | インフ |
 | (2,1) | 0 | 1 | インフ | インフ |
 | (3,2) | 0 | 1 | 2 | 3 |

 優位性の枝刈り後の dp は、値 2 はスタミナ 1 コスト、値 3 はスタミナ 2 コスト、値 5 はスタミナ 3 コストであることを示します。 

スタミナ 2 の場合、二分探索では値 5 は高すぎることがわかり、値 3 は実現可能であるため、答えは 3 になります。 

これは、小さなアイテムを最初に組み合わせることが、コスト効率に応じて単一の大きなアイテムよりも優先される可能性があることを裏付けています。 

### 例 2

 アイテム: (5, 5)、(4, 3)、(2, 2)。 クエリスタミナ5。 

| ステップ | 到達可能な最高の値 |
 | --- | --- |
 | (5,5) | 0、5 |
 | (4,3) | 0、4、5、9 |
 | (2,2) | 0、2、4、6、5、7、9 |

 スタミナ 5 未満の最高値は (4,3)+(2,2) 経由の 9 です。 

このトレースは、貪欲ではなく DP が必要な理由を示しています。最高の効率の組み合わせは、必ずしも最大の単一項目であるとは限りません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · V + q log V) | DP は値範囲 V にわたって各項目を処理し、クエリは二分検索を使用します。 
| スペース | O(V) | DP 配列は値ごとに最適なスタミナを保存します |

 V は値の合計によって制限されており、これは単純なスタミナ次元よりも大幅に小さく、クエリは完全な再計算ではなく対数検索に削減されるため、この解決策は受け入れられます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf

    INF = 10**18

    n, q = map(int, sys.stdin.readline().split())
    items = []
    max_val = 0

    for _ in range(n):
        v, c = map(int, sys.stdin.readline().split())
        items.append((v, c))
        max_val += v

    dp = [INF] * (max_val + 1)
    dp[0] = 0

    for v, c in items:
        for cur in range(max_val - v, -1, -1):
            if dp[cur] != INF:
                nv = cur + v
                dp[nv] = min(dp[nv], dp[cur] + c)

    for i in range(1, max_val + 1):
        dp[i] = min(dp[i], dp[i - 1])

    def best(s):
        lo, hi = 0, max_val
        ans = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if dp[mid] <= s:
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        return ans

    out = []
    for _ in range(q):
        out.append(str(best(int(sys.stdin.readline()))))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのアイテムが個別にスタミナの点で高価すぎるにもかかわらず、一緒に効率的な組み合わせを形成する場合です。 たとえば、スタミナ制限が低い場合、項目 (3,2) と (4,3) を単一の貪欲な選択で置き換えることはできません。 DP は、早期にコミットするのではなく、到達可能な値の合計をすべて列挙するため、これを正しく処理します。 

もう 1 つのエッジ ケースは、複数のアイテムの価値とコストの比率が同じである場合です。 このような状況では、不適切な枝刈りが有効な組み合わせを削除する可能性があります。 モノトーン プレフィックス ステップ dp[i] = min(dp[i], dp[i-1]) により、複数の状態が異なるコストで同じ値に達した場合でも、最良のスタミナのみが保持され、クエリの誤った回答が防止されます。 

3 番目のエッジ ケースは、アイテムが存在しない場合、またはすべてのクエリのスタミナがゼロの場合に発生します。 初期化 dp[0] = 0 では、バイナリ検索が常に少なくとも 0 の値を返し、空の選択状態を正しく表すことが保証されます。
