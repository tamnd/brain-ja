 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルにはすでに色が割り当てられています。 このゲームでは、ペイント操作を繰り返し適用する必要があり、各操作で行全体または列全体を単一の色でペイントし、以前に存在していたものを上書きします。 後のペイントは前のペイントをオーバーライドするため、操作の順序は重要です。 

重要な質問は、最終的なペイント操作で使用される色はどの色である可能性が高いかということです。 

重要な観察は、最後の操作は他のものによって上書きできないということです。 最後の移動によって行がペイントされる場合、その後の移動では、その行内のすべてのセルが最終的な色と一致する必要があり、その後は何も変更されません。 最後の移動が列をペイントする場合、同じロジックが対称的に適用されます。 

したがって、タスクは、その色を使用して最後に描画された操作である可能性のある行または列が少なくとも 1 つ存在するすべての色を見つけることになります。 追加の制限として、1 つの特定の値 (「未塗装」または無効を表す色) は有効な最終色とみなされないため、回答から除外する必要があります。 

入力は、$n \times m$整数のグリッドであり、出力は、最終的な塗装色として使用できるすべての有効な色のリストであり、昇順に並べ替えられます。 

このタイプの典型的なグリッド問題に含まれる制約により、最大約$10^5$セル以上。 これにより、可能なすべての再描画シーケンスにわたって、三次シミュレーションや繰り返しのディープ シミュレーションが即座に除外されます。 すべての再描画オーダーをチェックすることさえ、本質的に階乗的であり、完全に実行不可能です。 

考えられるすべての最後の操作候補の単純なスキャンは、行と列の単純な構造チェックに帰着する必要があります。 

行または列がほぼ均一であるにもかかわらず、異なるセルが 1 つ含まれている場合、微妙な障害が発生します。 たとえば、次のような行$[3, 3, 3, 4]$部分的な整合性のみをチェックする場合は、単純な解決策で色 3 を受け入れる可能性があります。 ただし、最後の操作によりすべてのセルがまったく同じ色になるため、この行を色 3 の最後の描画行にすることはできません。 同じ問題が列でも発生します。 

もう 1 つの落とし穴は、「最後の操作」が多数決の一貫性だけでなく、その回線の最終的なグリッド状態を完全に決定する必要があることを忘れていることです。 

## アプローチ

 ブルートフォース解釈では、行と列のペイント操作の考えられるすべてのシーケンスをシミュレートしようとします。 それぞれの候補色について、最後にペイントされた行または列を選択するあらゆる方法を想像し、グリッドが一貫して生成できるかどうかを確認できます。 各行または列を複数の順序で描画できるため、これはすぐに組み合わせ的に爆発的に増加し、シーケンスの数は総行数の階乗的に増加します。 最後の操作としてすべての行と列をチェックする縮小バージョンでも、線形時間でグリッドに対して各可能性を検証する必要があるため、$O((n+m)\cdot nm)$、最大グリッドには大きすぎます。 

重要な構造的洞察は、最後の操作が少なくとも 1 つの完全な行を完全に支配しているということです。 最後の操作で行をペイントする場合、その行は最終グリッドですでに均一になっている必要があります。 同じことが列にも当てはまります。 これにより、問題は直接的な検証タスクに変換されます。各行について、そのすべての要素が等しいかどうかをチェックします。 各列についても同じことを行います。 このような均一な線はすべて、候補色を直接識別します。 

これが機能するのは、有効な最終状態には最後にペイントされた線が含まれている必要があり、その線には最終ステップの後に混合色を含めることができないためです。 したがって、統一性が必要なだけではなく、候補者として十分です。

 ## アルゴリズムのチュートリアル

 1. サイズのグリッドを読み取ります$n \times m$。 これは、すべてのペイント操作が適用された後の最終状態です。 
2. すべての行を個別にチェックし、その行のすべての値が同一であるかどうかを判断します。 行が均一であれば、その色を候補として記録します。 その理由は、有効な最後の動きがこの行全体をペイントし、その後は変更されないままになる可能性があるということです。 
3. すべての列に対して同じチェックを繰り返します。 各列について、すべての値が同一であるかどうかを確認します。 その場合は、その列の色も候補として記録します。 
4. 重複を避けるために、検出されたすべての候補色をセットに保存します。 色は均一な行と均一な列の両方として表示される場合があります。 
5. 問題により、特定の値が有効であるとみなせない場合は、禁止された色を削除します。 
6. 残りの候補色をソートし、昇順に出力します。 

### なぜ効果があるのか

 有効な最終操作では、1 回の移動で行全体または列全体を上書きする必要があります。 この移動の後は、セルを変更するための操作は存在しません。 これにより、その行のすべてのセルが同じ最終値を共有するようになります。そうでないと、一貫性なく上書きされてしまいます。 したがって、有効な最後の移動は、最終グリッド内の完全に均一な行または列に正確に対応します。 逆に、均一な行または列は、単に最後に塗られたと仮定するだけで最後の手として説明でき、十分なものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    bad = -1  # if problem defines forbidden color, adjust if needed
    # (in many CF variants this is given; here we keep placeholder logic)

    ans = set()

    for i in range(n):
        ok = True
        for j in range(1, m):
            if g[i][j] != g[i][0]:
                ok = False
                break
        if ok:
            ans.add(g[i][0])

    for j in range(m):
        ok = True
        for i in range(1, n):
            if g[i][j] != g[0][j]:
                ok = False
                break
        if ok:
            ans.add(g[0][j])

    if bad in ans:
        ans.remove(bad)

    res = sorted(ans)
    print(len(res))
    if res:
        print(*res)

if __name__ == "__main__":
    solve()
```行チェックは各行にわたって反復され、すべてのセルを最初の要素と比較します。これは均一性を判断するのに十分です。 列のチェックも垂直方向に同様に行われます。 セットを使用すると、行と列の両方に表示される色が重複しないことが保証されます。 

微妙な点の 1 つは、絵画のシーケンスを再構築しようとしていないことです。 最終的なグリッドの構造的制約のみに依存し、指数関数的な推論を回避します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、行または列にセルが 1 つだけ存在する場合です。 たとえば、次のようなグリッド$n = 1$すべての列が自明に均一であることを意味します。 単一の値が常に均一性を満たすため、アルゴリズムは各列を有効なものとして正しく処理します。 逆もまた当てはまります$m = 1$、すべての行が自動的に均一になります。 

もう 1 つのケースは、すべての行が均一ではないが、一部の列が均一であるグリッドです。 例えば：```
3 3
1 2 3
1 2 3
1 2 3
```ここでは、均一な行はありませんが、すべての列は均一です。 アルゴリズムは、候補として {1,2,3} を収集します。 これは正しいです。なぜなら、たとえ行が該当しなくても、どの列も有効なシーケンスの最後の描画操作になる可能性があるからです。 

最後の微妙なケースは、禁止された色が均一な行または列に表示される場合です。 セットベースのアプローチにより、スキャン中に検出ロジックを妨げることなく、最後に簡単にフィルタリングできます。
