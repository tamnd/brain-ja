 ## 解決策
 ## 問題の理解

 数値の配列と複数の独立したクエリが与えられます。 各クエリは、左右の境界と数値によって定義されるサブ配列に焦点を当てます。$k$。 その部分配列から、正確に選択することができます$k$要素は含まれますが、選択に関して重要な唯一の数量は、選択された要素の合計です。 

サイズのサブセットになると$k$が固定されているので、その合計を計算します$S$、次に次の形式で二次式を評価します。$F(S) = aS^2 + bS + c$。 タスクは、すべての有効な選択肢の中からこの式の可能な限り最良の値を決定することです。$k$クエリされたセグメント内の要素。 クエリによっては、最大値、最小値、またはその両方が必要になる場合があります。 

重要な問題は、決定空間が組み合わせによるものであることです。 素朴な解釈では、すべてを列挙することを提案します。$\binom{r-l+1}{k}$サブセットを作成し、それらの合計を計算し、二次関数を評価します。 中程度のサブ配列サイズであってもサブセットの数が指数関数的に増加するため、これは直ちに実行不可能になります。 

この制約は、配列の長さとクエリの数が十分に大きいため、おおよその値を超えるアプローチは実行できないことを意味します。$O((n+q)\log n)$または$O(n \log n + q \log^2 n)$生き残れなくなるだろう。 これにより、ブルートフォースのサブセット列挙が排除され、クエリごとにソートされたサブ配列の再計算も排除されます。 

二次係数が次の場合に微妙なエッジケースが現れます。$a$は非陽性です。 その場合、関数は凹型になる可能性があり、実行可能な合計の範囲の極値が極値の和から反対の極値に切り替わる可能性があります。 たとえば、部分配列が次の場合、$[1, 10, 100]$、$k=2$の場合、考えられる合計の範囲は次のとおりです。$11$(最小の 2 つ) から$110$(最大の 2 つ)。 もし$a < 0$、合計が小さいほど二次式の値が大きくなる可能性があるため、実行可能な合計区間の両方の端点を考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、サイズのすべてのサブセットが試行されます。$k$クエリ範囲内でその合計を計算し、二次関数を評価して、最良の結果を追跡します。 これは、すべての有効な構成を明示的にチェックするため、正しいです。 ただし、長さの部分配列では$m$、これには$\binom{m}{k}$選択肢は、最悪の場合、指数関数的に増加します。$m$。 たとえ$m = 50$、これは計算上不可能になります。 

重要な観察は、二次関数は和のみに依存するということです。$S$、どの要素がそれを生成するかではありません。 したがって、問題は、正確な最小値と最大値の合計を決定することになります。$k$部分配列内の要素。 

合計を最大化するには、常に次の値を選択します。$k$最大の要素。 合計を最小化するために、$k$最小の要素。 他の選択は、要素を交換し、合計を単調に改善または低下させることによって、これらの極端ないずれかに変換できます。 

「最小の k の合計」と「最大の k の合計」を効率的にクエリできるようになると、各クエリは 2 つの候補値での 2 次関数の定数時間評価になります。 

大きな制約の下でこれらのクエリをサポートするには、順序統計とサブ配列にわたるプレフィックス合計クエリに効率的に答えることができる構造が必要です。 座標圧縮された値に基づいて構築された永続的なセグメント ツリー (主席树) により、配列のプレフィックスの頻度と合計情報を維持できます。 それから範囲$[l, r]$は、2 つのバージョン ルートを減算することで答えられ、その部分配列のマルチセットを正確に表す構造が得られます。 この構造から、最小または最大の合計を抽出できます。$k$の要素$O(\log n)$。

 ## アルゴリズムのチュートリアル

 まず、すべての配列値を圧縮して、連続した範囲内に収まるようにします。 これが必要なのは、セグメント ツリーが生の大きさではなく値のインデックスに基づいて構築されており、頻度と合計をコンパクトな構造に保存できるためです。 

次に、各バージョンが含まれる永続的なセグメント ツリーを構築します。$root[i]$プレフィックス内の要素の複数セットを表します$[1, i]$。 各ノードには、そのセグメントに含まれる要素の数とそれらの要素の合計という 2 つの情報が格納されます。 

クエリごとに$(l, r, k, a, b, c)$では、2 つのバージョンを組み合わせて部分配列を表す仮想構造を構築します。$root[r] - root[l-1]$。 

次に、この構造から 2 つの候補の合計を計算します。$k$最小の要素とその合計$k$最大の要素。 どちらもセグメント ツリーをたどることによって取得されます。 最小の要素については、低い値の範囲から上に向かって移動し、値に達するまでカウントを蓄積します。$k$。 最大の要素については、高い値の範囲から下に向かって移動します。 

これら2つの合計を求めた後、$S_{min}$そして$S_{max}$、両方の値で二次関数を評価し、クエリが最大値を要求するか最小値を要求するかに応じて最良の結果を取得します。 

最後に、計算された答えを出力します。 

### なぜ効果があるのか

 重要な不変条件は、固定マルチセット内では、ソートによってサイズの達成可能なすべての合計が完全に決定されるということです。$k$極値に関するサブセット。 極端でない選択は、選択した小さい要素を選択されていない大きい要素で置き換えることによって、厳密に合計を増やすか、またはその逆により、より極端な選択に変換できます。 これにより、実行可能な範囲が保証されます。$S$は、正確に次の合計間の間隔です。$k$最小値とその合計$k$最大の要素であるため、これらのエンドポイントのみをチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "r", "cnt", "sum")
    def __init__(self):
        self.l = 0
        self.r = 0
        self.cnt = 0
        self.sum = 0

def build(l, r):
    idx = len(seg)
    seg.append(Node())
    if l != r:
        m = (l + r) // 2
        seg[idx].l = build(l, m)
        seg[idx].r = build(m + 1, r)
    return idx

def update(prev, l, r, pos, val):
    idx = len(seg)
    seg.append(Node())
    seg[idx].l = seg[prev].l
    seg[idx].r = seg[prev].r
    seg[idx].cnt = seg[prev].cnt + 1
    seg[idx].sum = seg[prev].sum + val
    if l != r:
        m = (l + r) // 2
        if pos <= m:
            seg[idx].l = update(seg[prev].l, l, m, pos, val)
        else:
            seg[idx].r = update(seg[prev].r, m + 1, r, pos, val)
    return idx

def query_kth_sum(u, v, l, r, k, reverse=False):
    if k <= 0:
        return 0
    if l == r:
        return seg[v].sum - seg[u].sum
    m = (l + r) // 2
    left_u, left_v = seg[u].l, seg[v].l
    right_u, right_v = seg[u].r, seg[v].r

    if not reverse:
        cnt_left = seg[left_v].cnt - seg[left_u].cnt
        if k <= cnt_left:
            return query_kth_sum(left_u, left_v, l, m, k, reverse)
        else:
            return (seg[left_v].sum - seg[left_u].sum) + query_kth_sum(right_u, right_v, m + 1, r, k - cnt_left, reverse)
    else:
        cnt_right = seg[right_v].cnt - seg[right_u].cnt
        if k <= cnt_right:
            return query_kth_sum(right_u, right_v, m + 1, r, k, reverse)
        else:
            return (seg[right_v].sum - seg[right_u].sum) + query_kth_sum(left_u, left_v, l, m, k - cnt_right, reverse)

def solve():
    global seg
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    vals = sorted(set(arr))
    mp = {v: i + 1 for i, v in enumerate(vals)}
    arr = [mp[x] for x in arr]

    seg = [Node()]
    root = [0]

    m = len(vals)
    root.append(build(1, m))

    for x, val in zip(arr, vals):
        root.append(update(root[-1], 1, m, x, val))

    out = []
    for _ in range(q):
        l, r, k, a, b, c = map(int, input().split())

        Smin = query_kth_sum(root[l - 1], root[r], 1, m, k, False)
        Smax = query_kth_sum(root[l - 1], root[r], 1, m, k, True)

        def f(S):
            return a * S * S + b * S + c

        out.append(str(max(f(Smin), f(Smax))))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、更新ごとに配列から 1 つの要素を挿入する永続的なセグメント ツリーを構築します。 各ノードはカウントと合計の両方を保存します。これにより、セットを実体化せずに k 番目の最小合計と k 番目の最大合計を抽出できます。 

機能`query_kth_sum`が核となる操作です。 非反転モードでは、最初に左側のサブツリーを貪欲に消費します。これは、座標圧縮順序による小さい値に対応します。 逆モードでは、正しいサブツリーが優先され、最大値から下方向に効果的にスキャンされます。 

各クエリは、構造の極値から導出された 2 つの意味のある候補でのみ 2 次関数を評価し、組み合わせの列挙を回避します。 

## 実用的な例

 配列を考えてみましょう$[3, 1, 4, 2]$を求めるクエリが含まれています。$l=1, r=4, k=2$、および係数$a=1, b=0, c=0$。 部分配列マルチセットは次のとおりです。$\{1,2,3,4\}$。 

| ステップ | k-最小パス | k 最大パス | 結果の合計 |
 | --- | --- | --- | --- |
 | 開始 | 必要2 | 必要2 | - |
 | |を選択してください 1,2 | 4,3 | 3 対 7 |

 二次方程式は恒等式です$S^2$したがって、両方のエンドポイントで評価すると、合計が大きい方が優勢であることがわかり、$7^2 = 49$。 これは、境界合計のみが重要であることを裏付けています。 

次に、同じ配列を考えますが、$a=-1, b=0, c=0$。 関数は次のようになります$-S^2$。 

| ステップ | スミン | エスマックス | f(スミン) | f(Smax) |
 | --- | --- | --- | --- | --- |
 | 値 | 3 | 7 | -9 | -49 |

 ここで、合計が小さいほど出力が大きくなり、最適な選択が凹面によって方向を変える場合でも両方のエンドポイントをテストする必要があることが確認されます。

 ## 特殊なケース

 要素が 1 つある最小のケースは、セグメント ツリーが k 最小値と k 最大値の両方を同じ値として正しく返さなければならないことを示しています。 入力用$[5]$、$k=1$、両方の合計は$5$、二次評価は正しく崩壊します。 

等の値が同じ場合$[2,2,2,2]$両方のトラバース方向が対称的に動作するようにします。 左右のサブツリー間でカウントを分割する際にバグがあると、この対称性が崩れ、不正確な k-sum が生成されます。 

全範囲選択の場合は、累積ロジックに重点が置かれます。 もし$k$がサブ配列全体の長さに等しい場合、トラバーサルではセグメントをスキップせずにすべてのカウントを消費する必要があります。そうしないと、プレフィックスの減算で合計が誤ってカウントされます。 

二次係数が負の場合は、両方のエンドポイントの評価が必要であることが確認されます。 アルゴリズムは、実現可能な合計に対して目的関数の単調性を仮定してはなりません。
