 ## 解決策
 ## 問題の理解

 最大 25 個のウェイトがあり、各ウェイトは 3 つの方法のいずれかで処理できます。最初のプレートに配置するか、2 番目のプレートに配置するか、未使用のままにすることができます。 このスケールは実際の合計を比較するものではありません。 まず各プレートの合計モジュロを減らします。`m`、次にそれらの残差を比較します。 2 つの剰余が等しい、空ではない代入が必要です。 

体重の場合`i`最初のプレートにあるので係数を与えます`+1`。 2 番目のプレートにある場合は係数を与えます`-1`。 未使用の場合は係数を与える`0`。 条件はこうなります

 [
 \sum_{i=1}^{n} c_i a_i \equiv 0 \pmod m,
 ]

 ここで、すべての係数は (c_i\in{-1,0,1}) を満たし、すべての係数がゼロになるわけではありません。 このような係数が見つかると、正の係数は最初のプレートを表し、負の係数は 2 番目のプレートを表します。 

この制約は、多項式動的計画法ではなく、指数関数的な探索を指しています。 重みは 25 個しかないため、指数関数的に依存します。`n`重みを分割することによって指数が減少する場合は、許容できる可能性があります。 直接列挙には (3^{25}=847288609443) 個の代入が可能ですが、これは 1 秒の制限をはるかに超えています。 の値`m`はほぼ (4\cdot10^7) になる可能性があるため、剰余によってインデックス付けされた従来の DP 配列も、すべての重みの遷移には大きすぎます。 公式の問題の制約は次のとおりです。`n <= 25`そして`m < 4 * 10^7`、制限時間は 1 秒、メモリは 512 MB です。 

いくつかの小さなケースでは、誤った実装が露呈する可能性があります。 

のために`m = 1`、すべての整数は 1 を法とするゼロに合同であるため、空でないすべての配置は有効です。たとえば、```
1 1
5
```最初のプレートに重み 1 を置き、2 番目のプレートには何も置かないことで答えられます。 2 つの異なるサブセットのみを検索する実装では、誤ってレポートする可能性があります。`-1`。 

質量がすでに割り切れる重り`m`即答です。 例えば、```
1 7
14
```どちらかのプレートに重み 1 を置くことで解決されます。 モジュロ条件は剰余に関するものであり、生の合計に関するものではありません。 

空の割り当ては決して受け入れてはなりません。 例えば、```
1 7
1
```解決策がありません。 唯一の符号付き合計は次のとおりです。`0`、何も使用しないことから、そして`1`または`-1`、重りを使用することから。 不注意な中間ミート実装では、両方の半分の空の代入から残余 0 が見つかり、それが誤って受け入れられる可能性があります。 

同じ重さを両方のプレートに乗せることはできません。 例えば、```
2 10
3 3
```この問題は、一方のプレートに重り 1 を置き、もう一方のプレートに重り 2 を置くことで解決されます。 両方のプレート残基は 3 です。2 つの辺が互いに素である必要があることを忘れずに、2 つの辺を独立したサブセットとして扱う表現では、誤って 1 つのインデックスを 2 回使用する可能性があります。 

最後に、等価性はモジュロです`m`、通常の合計の等価ではありません。 のために```
2 5
7 2
```2 つの重りを反対側のプレートに置くと機能します。`7 mod 5 = 2 mod 5`たとえ実際の質量が異なっていたとしても。 

## アプローチ

 最も直接的な解決策は、すべての重量を個別に考慮し、未使用、最初のプレート、または 2 番目のプレートの 3 つの選択肢をすべて試行します。 すべての割り当てについて、符号付き和モジュロを計算します。`m`それがゼロであり、少なくとも 1 つの重みが選択されている場合は受け入れます。 すべての正当な配置は、次の係数の 1 つのベクトルに正確に対応するため、これは正しいです。`{-1,0,1}`。 

問題は課題の数です。 25 個の重みがあると、

 [
 3^{25}=847288609443
 ]

 可能性。 たとえ 1 つの割り当てをチェックするのに必要な機械命令がわずか数個だったとしても、数千億の状態を制限時間内に収めることはできません。 

有益な観察は、符号付きの合計が加算されるということです。 ウェイトを 2 つの別々の半分に分割します。 前半の代入の場合、その符号付き合計を次のようにします。`x`。 後半の代入の場合、その符号付き合計を次のようにします。`y`。 これらを組み合わせると、まさに有効なソリューションが形成されます。 

[
 x+y\equiv0\pmod m.
 ]

 したがって、すべての (3^n) 個の割り当てを列挙する代わりに、各半分で大まかに (3^{n/2}) 個の割り当てを列挙し、相補的な残基を照合します。 

重みが 25 個ある場合、半分には最大 12 個の重みがあり、もう一方には最大 13 個の重みがあります。それらの検索スペースには、それぞれ最大 (3^{12}=531441) と (3^{13}=1594323) の割り当てが含まれます。 前半で生成された剰余ごとに 1 つの代入をハッシュ テーブルに保存し、後半を列挙してそのモジュラー否定である剰余を探します。 

空の割り当てを保存する際には、微妙な点が 1 つあります。 残基ゼロは何もしなくても常に生成されます。 その代入のみを保存すると、後の検索でもゼロが生成され、誤って 2 つの空の代入が結合される可能性があります。 実装はそのケースを明示的に拒否し、剰余 0 が存在する場合には空でない前半代入を優先します。 

比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(3^n)) | (O(n)) | 遅すぎる |
 | 真ん中で会う | (O(3^{n/2})) | (O(3^{n/2})) | 承認済み |

 モジュラー演算は、すべての中間合計を即座に削減できることも意味します。 Python の整数には制限がないため、元の質量が (10^9) ほど大きくても整数オーバーフローの心配はありません。 

## アルゴリズムのチュートリアル

 1. ウェイトを 2 つの連続する半分に分割します。 もし`n = 25`、前半には 12 のウェイトが含まれ、後半には 13 のウェイトが含まれます。半分は互いに素です。つまり、各半分で個別に選択された割り当てでは、すべてのウェイトが最大 1 回だけ自動的に使用されます。 
2. 前半のすべての 3 項代入を列挙します。 各重み、係数ごとに`0`未使用という意味ですが、`1`最初のプレートを意味し、`2`2番目のプレートを意味します。 これらの選択肢を係数に変換します`0`、`+1`、 そして`-1`、符号付き和モジュロを計算します。`m`。 
3. 前半で見つかった残基ごとに 1 つの 3 値エンコーディングを保存します。 剰余がゼロで、現在テーブルに空のエンコーディングのみが含まれている場合は、同じ剰余を持つ空でないエンコーディングが出現したときにそれを置き換えます。 保存されたエンコーディングは、各プレートに属する重みを再構築するのに十分です。 
4. 後半のすべての 3 項代入を列挙します。 その符号付き合計が`s`。 前半からの互換性のある割り当てには剰余が必要です`(-s) mod m`、結合された符号付き合計はゼロモジュロである必要があるため`m`。 
5. 上を向いて`(-s) mod m`前半の表で。 それが存在しない場合、この後半の課題は解決策を形成できません。 存在する場合は、2 つのエンコーディングを組み合わせます。 
6. 両方のエンコーディングが空の場合にのみ、組み合わせを拒否します。 他の組み合わせには少なくとも 1 つの選択された重みが含まれており、符号付き合計の合計が次の値で割り切れます。`m`, したがって、それは有効な答えです。 
7. 2 つの 3 値エンコーディングをデコードします。 を表す数字`+1`を表す数字が最初のプレートに移動します。`-1`2皿目に行きます。 2 つのインデックス セットを出力します。 

機能する理由: すべての法的配置には、係数を含む一意の署名表現があります。`{-1,0,1}`。 インデックスを分割すると、その符号付き合計が各半分からの寄与に分割されます。`x`そして`y`、 と`x + y ≡ 0 (mod m)`。 後半の列挙中、アルゴリズムは、以下に等しい前半の残基を正確に検索します。`-y`, そのため、あらゆる解決策が検討されます。 逆に、ルックアップによって返されたすべてのペアは、`x + y ≡ 0`、そして半分は互いに素であるため、デコードされた割り当ては正当な配置を形成します。 明示的な空の割り当てチェックにより、少なくとも 1 つの重みが実際に配置されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_map(values, mod):
    """
    Map residue -> one ternary encoding for this half.

    Ternary digit:
        0 = unused
        1 = first plate
        2 = second plate
    """
    result = {}

    def dfs(pos, total, code, place):
        if pos == len(values):
            old = result.get(total)
            if old is None or (total == 0 and old == 0 and code != 0):
                result[total] = code
            return

        # Leave this weight unused.
        dfs(pos + 1, total, code, place * 3)

        # Put it on the first plate.
        nxt = total + values[pos]
        if nxt >= mod:
            nxt -= mod
        dfs(pos + 1, nxt, code + place, place * 3)

        # Put it on the second plate.
        nxt = total - values[pos]
        if nxt < 0:
            nxt += mod
        dfs(pos + 1, nxt, code + 2 * place, place * 3)

    dfs(0, 0, 0, 1)
    return result

def find_in_second(values, mod, first_map):
    """
    Search all ternary assignments of the second half.
    Returns (first_code, second_code), or None.
    """

    answer = None

    def dfs(pos, total, code, place):
        nonlocal answer

        if answer is not None:
            return

        if pos == len(values):
            need = (-total) % mod
            first_code = first_map.get(need)

            if first_code is not None:
                if first_code != 0 or code != 0:
                    answer = (first_code, code)
            return

        # Unused.
        dfs(pos + 1, total, code, place * 3)

        if answer is not None:
            return

        # First plate.
        nxt = total + values[pos]
        if nxt >= mod:
            nxt -= mod
        dfs(pos + 1, nxt, code + place, place * 3)

        if answer is not None:
            return

        # Second plate.
        nxt = total - values[pos]
        if nxt < 0:
            nxt += mod
        dfs(pos + 1, nxt, code + 2 * place, place * 3)

    dfs(0, 0, 0, 1)
    return answer

def decode(code, length, offset, first, second):
    for i in range(length):
        digit = code % 3
        code //= 3

        index = offset + i + 1

        if digit == 1:
            first.append(index)
        elif digit == 2:
            second.append(index)

def solve():
    n, mod = map(int, input().split())
    a = list(map(int, input().split()))

    # Reducing the masses once makes every later transition smaller.
    a = [x % mod for x in a]

    # A split near the middle minimizes the larger ternary search space.
    mid = n // 2
    left = a[:mid]
    right = a[mid:]

    first_map = build_map(left, mod)
    answer = find_in_second(right, mod, first_map)

    if answer is None:
        print(-1)
        return

    left_code, right_code = answer

    first_plate = []
    second_plate = []

    decode(left_code, len(left), 0, first_plate, second_plate)
    decode(right_code, len(right), mid, first_plate, second_plate)

    print(len(first_plate))
    print(*first_plate)
    print(len(second_plate))
    print(*second_plate)

if __name__ == "__main__":
    solve()
```最初の前処理行は、`a[i]`モジュロ`m`。 最終的な比較には剰余のみが影響するため、これは数学的に安全です。 また、各再帰的遷移を間隔内に留まらせることができます。`[0, m)`より大きな整数を繰り返し構築するのではなく、1 つの条件調整を使用します。`build_map`前半の検索全体を実行します。 の`code`変数は、すでに行われた決定を基数 3 でエンコードしたものです。 の`place`変数は現在の 3 のべき乗であるため、最初のプレートを選択すると`place`エンコーディングに追加し、2 番目のプレートを選択すると`2 * place`。 

符号付きの合計は剰余として保持されます`m`あらゆる選択の後に。 正の遷移の場合、値を追加すると最大で次の値に達します。`2m - 2`, したがって、1 つの減算で十分です。 負の遷移の場合、結果は次のように低くなります。`-(m - 1)`なので、追加は 1 つで十分です。 これにより、`%`すべての再帰ノードでの操作。 

剰余ゼロの特別な処理は見落とされがちです。 空の割り当ては、他の半分からの空でない割り当てと正当に結合できるため、保存する必要があります。 ただし、空ではない前半の割り当てでもゼロが生成される場合は、空のエンコーディングをそれに置き換える方が良いでしょう。 の状態`build_map`まさにそのケースを処理します。`find_in_second`残りの半分を検索します。 署名された残基ごとに`total`、計算します`(-total) % mod`そして辞書検索を 1 回実行します。 再帰は有効なペアが見つかった直後に停止するため、一般的な入力は完全な (3^{13}) 列挙よりもはるかに早く終了します。 

3 値エンコードでは、各半分の最初の重みの最下位桁が使用されます。`decode`繰り返し取る`code % 3`次に 3 で割ると、生成されたのと同じ順序で決定が復元されます。 後半のインデックス オフセットは次のとおりです。`mid`、最初のローカル位置がグローバル ウェイトに対応するため`mid + 1`。 

Python には固定幅の整数オーバーフローがないため、元の質量などの合計は安全です。 アルゴリズム自体が剰余クラスで動作するため、実装では検索全体を通じてモジュラー リダクションが引き続き実行されます。 

## 実用的な例

 サンプル 1 の場合、```
4 14
1 3 7 10
```分割は`[1, 3]`そして`[7, 10]`。 

| ステージ | 割り当て | 14 を法とする符号付き和 | Required first-half residue |
 | --- | --- | --- | --- |
 | 前半｜`+1, +3`| 4 | |
 | 後半｜ 空 | 0 | 0 |
 | 後半｜`+7`| 7 | 7 |
 | 後半｜`+10`| 10 | 4 |
 | 一致 |`(+1,+3)`と`(+10)`|`4 + 10 = 14 ≡ 0`| 4 |

 したがって、アルゴリズムは最初のプレートに重み 1、2、および 4 を置き、2 番目のプレートを空のままにすることができます。 それらの合計は 14 であるため、スケールは次のように計算されます。`14 mod 14 = 0`最初のプレートと`0`2番目に。 サンプルの出力は異なりますが、問題では有効な構成が求められているため、どちらも有効です。 

サンプル 2 の場合、```
3 7
1 2 4
```分割は`[1]`そして`[2, 4]`。 

| ステージ | 割り当て | 7 を法とする符号付き和 | 必要な前半残差 |
 | --- | --- | --- | --- |
 | 前半｜`+1`| 1 | |
 | 後半｜`+2`| 2 | 5 |
 | 後半｜`-2`| 5 | 2 |
 | 後半｜`+4`| 4 | 3 |
 | 後半｜`-4`| 3 | 4 |
 | 後半｜`+2,+4`| 6 | 1 |
 | 一致 |`+1`と`+2,+4`|`1 + 6 = 7 ≡ 0`| 1 |

 結果として生じる構造では、3 つのウェイトすべてが最初のプレートに配置されます。 その和は 7 で、7 を法とした剰余は 0 ですが、2 番目のプレートは空です。 これはまさにサンプルの構造です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(3^{n/2})) | 各半分は 1 回列挙され、各状態は定数時間モジュラー演算を実行し、後半ではハッシュ テーブル ルックアップを実行します。 |
 | スペース | (O(3^{n/2})) | 前半には、最大 (3^{n/2}) 個のエントリを含む、個別の残基ごとに 1 つの 3 値エンコーディングが格納されます。 |

 のために`n = 25`、大きい方の半分にはウェイトが 13 個しかないため、含まれるのは最大でも`3^13 = 1,594,323`課題。 小さい半分には最大でも`3^12 = 531,441`課題。 これは直接の値よりも数桁小さいです。`3^25`検索し、512 MB のメモリ制限内に快適に収まります。 の最大値`m`は DP の次元として表示されないため、大きなモジュロ境界によってメモリ使用量が 4,000 万に比例することはありません。 

## テストケース

 出力は一意ではないため、テストでは正確な出力文字列を比較するのではなく、返された配置を検証する必要があります。 次のハーネスは、報告されたすべてのインデックスが有効であること、インデックスが 2 回使用されていないこと、少なくとも 1 つの重みが設定されていること、および 2 つのプレートの合計の剰余が等しいことをチェックします。```python
import sys
import io

# Paste the solve_data implementation from the solution here.
def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        # Call the submitted solve() here.
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    n, mod = data[0], data[1]
    a = data[2:2 + n]

    tokens = out.split()
    if not tokens:
        return False

    if tokens[0] == "-1":
        return True

    p = 0

    k = int(tokens[p])
    p += 1
    first = list(map(int, tokens[p:p + k]))
    p += k

    q = int(tokens[p])
    p += 1
    second = list(map(int, tokens[p:p + q]))
    p += q

    if p != len(tokens):
        return False

    if k + q == 0:
        return False

    if any(x < 1 or x > n for x in first + second):
        return False

    if len(set(first)) != len(first):
        return False

    if len(set(second)) != len(second):
        return False

    if set(first) & set(second):
        return False

    s1 = sum(a[i - 1] for i in first) % mod
    s2 = sum(a[i - 1] for i in second) % mod

    return s1 == s2

# Provided sample 1.

1 3 7 10

# Equal weights must be placed on opposite plates.

result4 = solve_data(case4)
assert result4.strip() == "-1", "maximum-size no-solution case"

# Empty assignment must not be accepted.
case5 = """\

 ## 特殊なケース

 いつ`m = 1`、すべての剰余はゼロです。 入力用```
1 1
5
```前半のマップには、空の代入と重みを使用した代入の両方からの剰余 0 が含まれています。 この実装では、残基ゼロに対して空でないエンコーディングが意図的に優先されます。 後半は空であるため、結果として得られる構造には重み 1 が含まれており、受け入れられます。 

単一の重みが次の値で割り切れるとき`m`、残りの半分の空の課題を完了するには十分です。 のために```
1 7
14
```重み 1 の符号付き剰余はゼロです。 前半のマップには剰余 0 の空でないエンコードが格納されており、後半の検索ではその空の割り当てを使用できます。 結合された配置には 1 つのウェイトが含まれており、符号付き和は 7 を法としてゼロになります。 

重みが等しい場合は、次のように考慮します。```
2 10
3 3
```課題`+3 - 3`サムゼロに署名しました。 2 つの重みが異なる半分に属しているため、中間一致検索により剰余が見つかります。`3`半分と残りから`7`、そのモジュラー否定、残りの半分から。 デコードされた結果は、2 つの異なるインデックスを反対側のプレートに置き、剰余を与えます。`3`そして`3`。 

ありえないケースとしては、```
1 7
1
```空でない符号付き合計は次のとおりです。`1`そして`-1`、その残差は`1`そして`6`。 どちらもゼロではありません。 唯一のゼロ残基は何も選択しない場合に生じますが、後半の検索では両方のエンコードがゼロであるペアが明示的に拒否されるため、プログラムは次のように出力します。`-1`。 

最大サイズの場合、分割には 12 と 13 の重みが含まれます。 最初のマップには最大 (3^{12}) 個の個別の代入を行う余地があるのに対し、2 番目の列挙型は最大 (3^{13}) 個を検査します。 実装のどの部分も、潜在的に巨大な値に線形的に依存しません。`m`、すべての割り当ては、選択されたインデックスのリストではなく、3 進整数によってコンパクトに表現されます。 

中心となる不変式は単純です。格納されているすべての剰余はその半分の実数の符号付き割り当てを表し、後半のすべての状態は、それ自体の符号付き和のモジュラー補数に対してのみ照合されます。 ペアが見つかると、それらの係数は素のインデックスのセットに対する有効な配置を表すため、2 つのプレート剰余の等価性は方程式 (x+y\equiv0\pmod m) から直接得られます。
