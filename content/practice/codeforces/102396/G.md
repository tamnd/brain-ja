 ## 解決策
 ## 問題の理解

 最大 25 個の重りを用意しており、各重りは最初のプレート、2 番目のプレートに置くことも、未使用のままにすることもできます。 このスケールは通常の合計を比較するものではありません。 代わりに、両方のプレート和を法 (m) で減算し、これら 2 つの残基が等しい場合のバランスを報告します。 

最初のプレートにセット (L) が含まれ、2 番目のプレートに素セット (R) が含まれている場合、必要な条件は次のとおりです。 

[
 \sum_{i\in L} a_i \equiv \sum_{i\in R} a_i \pmod m.
 】

 同様に、

 [
 \sum_{i\in L} a_i-\sum_{i\in R}a_i\equiv0\pmod m.
 】

 したがって、すべての重みには正確に 3 つの可能な状態があります。 これらの状態は (0)、(+1)、(-1) でエンコードできます。(0) は未使用を意味し、(+1) は最初のプレートを意味し、(-1) は 2 番目のプレートを意味します。 符号付きの合計が (m) で割り切れる非ゼロの代入が必要です。 

境界 (n\le25) が中心的な手がかりです。 直接列挙には (3^n) 個の状態と (3^{25}=847288609443) が含まれますが、これは 1 秒のソリューションで調査できる範囲をはるかに超えています。 モジュロ (m) はほぼ (4\cdot10^7) になる可能性があるため、すべての重みを処理すると、すべての剰余によってインデックス付けされた動的計画法配列もコストが高くなりすぎます。 重みの数が比較的少ないため、重みを 2 つの半分に分割し、それぞれの半分で 3 つの選択肢を独立して列挙することが推奨されます。 

値 (a_i) は (10^9) まで大きくすることができますが、スケールに影響を与えるのはその剰余 (m) のみです。 Python の整数はオーバーフローも回避するため、実装では算術オーバーフローの問題は発生しません。 

最初のエッジ ケースは (n=1) です。 例えば、```
1 5
3
```唯一の空ではない配置では一方のプレートにウェイト 3 が配置され、もう一方のプレートは空のままになり、残基 3 と 0 が与えられるため、答えはありません。サブセットの合計が (m) で割り切れるかどうかだけをチェックする不注意な解決策でたまたまこのケースを処理できますが、独立して生成された 2 つのサブセットの比較に基づく解決策では、両側で同じウェイトを使用することを明示的に禁止する必要があります。 

2 番目のエッジ ケースは、単一の重みがすでに (m) で割り切れる場合に発生します。 例えば、```
1 5
10
```有効な出力があります```
1
1
0
```最初のプレートには残留物 (10\bmod5=0) があり、2 番目のプレートは空であるためです。 両方のプレートに重りを含める必要がある不用意な実装は、有効な答えを拒否することになります。 

3 番目のエッジ ケースは (m=1) です。 例えば、```
1 1
7
```すべての整数は 1 を法としてゼロに合同であるため、常に解くことができます。アルゴリズムでは空のプレートを許可する必要があり、すべて未使用の代入を誤って有効な答えとして扱ってはなりません。 

4 番目の特殊なケースは、通常の合計が等しい必要がないということです。 例えば、```
4 14
1 3 7 10
```1 つのプレートに重り (1、3、10) を置くことができます。 通常の合計は 14 で、剰余 0 になりますが、もう一方のプレートは空です。 等しい通常の和のみを求める解では、この有効なモジュラー等式が失われます。 

## アプローチ

 ブルート フォース アプローチは、各重みの 3 つの可能な状態から直接導き出されます。 すべての重みについて、未使用、最初のプレート、または 2 番目のプレートを選択し、結果として得られる符号付き和法 (m) を計算し、剰余が 0 である非ゼロ割り当てを受け入れます。 すべての法的配置はこれら 3 つの州の割り当ての 1 つに正確に対応するため、これは正しいです。 

問題は課題の数です。 (n=25) の場合、

 [
 3^{25}=847288609443
 】

 可能性。 1 つの割り当てのチェックに 1 回の定数時間操作しかかからなかったとしても、これは 1 秒の制限には大きすぎます。 

有益な観察は、符号付きの合計が加算されるということです。 重みを 2 つのグループに分割すると、すべての完全な割り当ては、前半の符号付き合計と後半の符号付き合計として書き込むことができます。 前半で生成された剰余 (x) については、(-x\bmod m) に等しい後半の剰余だけが必要です。 

これが中間者会議のアイデアです。 すべての (3^n) 個の割り当てを探索するのではなく、半分で (3^{\lfloor n/2\rfloor}) 個の割り当てを探索し、もう半分で (3^{\lceil n/2\rceil}) を探索します。 (n=25) の場合、これらの数値は (3^{12}=531441) および (3^{13}=1594323) となり、実用的です。 

この配合を特に便利にする詳細が 1 つあります。 前半に剰余が存在するかどうかだけでなく、その剰余を生成する 1 つの代入も保存します。 後半が相補的な残基を見つけると、保存された 2 つの割り当てが一緒になって 2 つのプレートを直接記述します。 

すべてゼロの代入は特別に扱う必要があります。 剰余は常にゼロになりますが、どこにも重みを置かないことは禁止されています。 どちらかの半分がゼロ以外の選択肢を提供する場合、結合された割り当ては有効です。 両方の格納コードがゼロである場合のみを拒否する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(3^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(3^{\lceil n/2\rceil})) | (O(3^{\lfloor n/2\rfloor})) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ウェイトをサイズの前半 (\lfloor n/2\rfloor) と、残りのウェイトを含む後半に分割します。 分割は、より大きな列挙に最大 13 個の重みのみが含まれるように選択されます。 
2. 前半のすべての課題を列挙します。 各重みには、寄与 (0)、寄与 (+a_i)、または寄与 (-a_i) の 3 つの選択肢があります。 結果として得られる剰余モジュロ (m) を、それを生成する 1 つのエンコードされた代入とともに辞書に保存します。 複数の代入によって同じ剰余が生成される場合、それらはいずれも解を完成するのに同様に役立つため、必要なのは 1 つだけです。 
3. 同じ 3 つの選択肢を使用して、後半のすべての割り当てを列挙します。 その符号付き和に剰余があるとします。 完全な符号付き合計を (m) で割り切れるようにするには、前半に剰余がなければなりません。 

[
 (-s)\bmod m。 
】

 この残余を辞書で調べてください。 

1. 一致する残基が見つかったら、両方の割り当てをデコードします。 選択肢 (+1) は最初のプレートに移動し、選択肢 (-1) は 2 番目のプレートに移動し、選択肢 (0) は無視されます。 
2. 両方の割り当てコードがゼロの場合にのみ、一致を拒否します。 他のすべての場合では、少なくとも 1 つの重みが使用され、2 つの半和が加算されてゼロ モジュロ (m) になるため、スケールのバランスがとれます。 
3. 完全な列挙が一致せずに終了した場合は、(-1) を出力します。 考えられるすべての配置は 1 対の半分の割り当てで表されているため、解決策が見逃されることはありません。

これが機能する理由: すべての正当な配置は係数のベクトル (c_i\in{-1,0,+1}) に対応し、係数はプレートまたは未使用の状態を示します。 ベクトルを 2 つの半分に分割すると、配置がスケールのバランスをとるときに正確に (x+y\equiv0\pmod m) を満たす残基 (x) と (y) が得られます。 前半の辞書には、生成できるすべての残基の 1 つの代表が含まれており、後半の検索では、考えられるすべての後半の割り当てに対して相補的な残基が正確にチェックされます。 したがって、すべての有効な空でない配置が検出され、報告されたすべての配置は (m) で割り切れる符号付きの合計を持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [x % m for x in map(int, input().split())]

    mid = n // 2
    left = a[:mid]
    right = a[mid:]

    # choice encoding:
    # 0 = unused
    # 1 = first plate
    # 2 = second plate
    #
    # Two bits are enough for every choice.
    first = {}

    def build_first(pos, end, residue, code):
        if pos == end:
            first.setdefault(residue, code)
            return

        x = a[pos]

        build_first(pos + 1, end, residue, code)

        nr = residue + x
        if nr >= m:
            nr -= m
        build_first(pos + 1, end, nr, code | (1 << (2 * (pos - 0))))

        nr = residue - x
        if nr < 0:
            nr += m
        build_first(pos + 1, end, nr, code | (2 << (2 * (pos - 0))))

    build_first(0, mid, 0, 0)

    answer = None

    def search_second(pos, end, residue, code):
        nonlocal answer

        if answer is not None:
            return

        if pos == end:
            need = (-residue) % m
            if need in first:
                left_code = first[need]
                if left_code != 0 or code != 0:
                    answer = (left_code, code)
            return

        x = a[pos]

        # Leave the weight unused.
        search_second(pos + 1, end, residue, code)

        if answer is not None:
            return

        # Put it on the first plate.
        nr = residue + x
        if nr >= m:
            nr -= m
        search_second(
            pos + 1,
            end,
            nr,
            code | (1 << (2 * (pos - mid)))
        )

        if answer is not None:
            return

        # Put it on the second plate.
        nr = residue - x
        if nr < 0:
            nr += m
        search_second(
            pos + 1,
            end,
            nr,
            code | (2 << (2 * (pos - mid)))
        )

    search_second(mid, n, 0, 0)

    if answer is None:
        return "-1\n"

    left_code, right_code = answer
    first_plate = []
    second_plate = []

    for i in range(mid):
        choice = (left_code >> (2 * i)) & 3
        if choice == 1:
            first_plate.append(i + 1)
        elif choice == 2:
            second_plate.append(i + 1)

    for i in range(n - mid):
        choice = (right_code >> (2 * i)) & 3
        idx = mid + i + 1
        if choice == 1:
            first_plate.append(idx)
        elif choice == 2:
            second_plate.append(idx)

    out = [
        str(len(first_plate)),
        " ".join(map(str, first_plate)),
        str(len(second_plate)),
        " ".join(map(str, second_plate)),
    ]
    return "\n".join(out) + "\n"

if __name__ == "__main__":
    sys.stdout.write(solve())
```前半は残差をキーとする辞書に格納されます。`setdefault`残基に対して最初に見つかった代入を保持し、不必要な置換を回避します。 各残基に対して証人が 1 人だけ必要なため、これで十分です。 

割り当ては重みあたり 2 ビットでエンコードされます。 値 0、1、および 2 は、未使用、最初のプレート、および 2 番目のプレートを表します。 コードを整数として保持すると、状態ごとに Python リストまたはタプルを保存するよりも辞書が大幅に小さくなります。 

再帰では、遷移ごとに剰余 (m) を計算します。 現在の剰余はすでに (0) から (m-1) の範囲内にあるため、1 つの剰余を加算するには (m) を最大 1 回減算する必要があり、1 を減算するには (m) を最大 1 回加算する必要があります。 これにより、より高価な一般的な`%`列挙の最もホットな部分内の操作。 

2 つの半分は別々のローカル ビット位置を使用します。 後半をデコードするとき、インデックスは次のようにシフトされます。`mid`元の重量番号を復元します。 したがって、同じローカル エンコーディングを両方の半分で使用できます。 

Python は、32 ビット整数を使用する言語で発生する固定幅整数オーバーフローの影響を受けません。 元の重みは列挙前にモジュロ (m) で削減されるため、格納されるすべての剰余はいずれにせよ小さいままです。 

## 実用的な例

 サンプル 1 の場合、```

1 3 7 10
```分割は ( [1,3] \mid [7,10] ) です。 前半では、(0,1,3,4,10,12,\ldots) などの符号付き残基が生成されます。 後半の検索では、最終的に、最初のプレートに重み 10 を置くことを考慮し、残基 10 に寄与します。その補数は (14-10=4) で、前半は最初のプレートに重み 1 と 3 を置くことで残基 4 を生成できます。 

| ステージ | 前半残差 | 後半残留 | 必要な残基 | 割り当てが見つかりました |
 | --- | --- | --- | --- | --- |
 | イニシャル | 0 | 0 | 0 | すべて未使用、拒否されました |
 | 前半の列挙 | 4 | 0 | 0 | 重み 1 と 2 は 4 を生成します |
 | 後半検索 | 4 | 10 | 4 | 一致が見つかりました |

 結果として、最初のプレートにはウェイト 1、2、4 が配置され、2 番目のプレートには何も配置されません。 それらの通常の合計は (1+3+10=14) であるため、スケールでは 14 を法として両方のプレートで (0) が表示されます。これは、アルゴリズムが通常の合計の等価性ではなくモジュラーの等価性を求めていることを示しています。

| ステージ | 前半残差 | 後半残留 | 必要な残基 | 割り当てが見つかりました |
 | --- | --- | --- | --- | --- |

## テストケース

 以下のテスト ハーネスは、特定の有効な証人を必要とするのではなく、返された配置の構造的妥当性をチェックします。 多くの異なる出力が同じ入力を満たす可能性があるため、これはこの問題をテストする正しい方法です。```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

def check_output(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    n, m = data[0], data[1]
    a = data[2:2 + n]

    tokens = out.split()
    if not tokens:
        return False

    if tokens[0] == "-1":
        return len(tokens) == 1

    p = 0

    k = int(tokens[p])
    p += 1
    left = [int(tokens[p + i]) for i in range(k)]
    p += k

    q = int(tokens[p])
    p += 1
    right = [int(tokens[p + i]) for i in range(q)]
    p += q

    if p != len(tokens):
        return False

    if k + q == 0:
        return False

    if any(x < 1 or x > n for x in left + right):
        return False

    if len(set(left)) != len(left):
        return False
    if len(set(right)) != len(right):
        return False
    if set(left) & set(right):
        return False

    s_left = sum(a[i - 1] for i in left) % m
    s_right = sum(a[i - 1] for i in right) % m

    return s_left == s_right

# Provided sample 1

1 3 7 10
"""

assert check_output(sample1, out), "sample 1"

# Provided sample 2

"""

assert check_output(sample2, out), "sample 2"

# Minimum size, and m = 1.

# Minimum size with no possible answer.

"""
assert run(case2).strip() == "-1", "single weight with nonzero residue"

# All equal values. One copy can balance another.
case3 = """\

"""
out = run(case3)
assert check_output(case3, out), "all equal values"

# Boundary-style pair: 2 + 3 = 5 modulo 5.
case4 = """\

"""
out = run(case4)
assert check_output(case4, out), "modulo boundary"

# The sum of all powers of two is 2^25 - 1 = 33554431,
# which is smaller than m, so every subset has a distinct ordinary sum.
powers = [1 << i for i in range(25)]

assert run(case5).strip() == "-1", "maximum-size no-answer case"

 ## 特殊なケース

 のために```
1 5
3
```前半は空で、後半には重み 3 が含まれています。前半の辞書には、空の代入を持つ剰余 0 のみが含まれています。 後半では残基 0、3、および 2 が生成されますが、一致する補数を持つのは残基 0 のみです。 この一致ではどちらの半分にも重みが使用されないため、アルゴリズムはそれを拒否し、次のように出力します。`-1`。 これはまさに必要な動作です。 

のために```
1 5
10
```唯一の重みは剰余 0 を持ちます。前半の辞書には再び剰余 0 が含まれますが、最初のプレートに重み 1 を置く後半の割り当てにも剰余 0 が含まれます。2 つの割り当てコードは両方とも 0 ではないため、一致は受け入れられます。 出力では、最初のプレートに重み 1 が設定され、2 番目のプレートは空のままになります。 

のために```
1 1
7
```法が 1 であるため、すべての剰余は 0 です。後半の列挙では、剰余 0 を持つ空でない代入がすぐに見つかり、前半の空の代入は必要な補数を提供します。 すべてのプレートの合計が 1 を法とするゼロに一致するため、結果の配置は有効です。 

のために```
4 14
1 3 7 10
```前半では、最初のプレートに配置された重み 1 と 2 から符号付き剰余 4 を生成できます。 最初のプレートに重み 4 を配置する後半の割り当ては、剰余 10 に寄与します。(4+10=14) であるため、それらを結合した符号付き剰余は 0 になります。 したがって、出力では最初のプレートに重み 1、2、および 4 を配置し、モジュラー和が 0 になり、2 番目のプレートは空になります。 

最大サイズ無回答の場合```
25 39999999
1 2 4 8 16 32 64 128 256 512 1024 2048 4096
8192 16384 32768 65536 131072 262144 524288 1048576
2097152 4194304 8388608 16777216
```すべての重みの合計は (2^{25}-1=33554431) で、これは (m) より小さくなります。 したがって、すべてのサブセットは異なる通常の合計を持ちます。したがって、2 つの互いに素なサブセットは、両方が空でない限り、等しい合計を持つことはできません。 合計が (m) に達することはないため、合計が (m) で割り切れる空でない部分集合も存在しません。 中間一致検索では、3 つの状態の割り当てがすべて網羅され、正しく返されます。`-1`。
