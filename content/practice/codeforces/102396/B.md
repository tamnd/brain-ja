 ## 問題の理解

 初期口座残高があります`s`そして`n`次の期間中にすべて発生する必要があるトランザクション`m`日々。 取引`i`によってバランスが変わります`count[i]`、ただし、正確な日は包含期間内の任意の日になります。`[from[i], to[i]]`。 複数の取引が同じ日に発生した場合、その内部注文は制限されません。 

ある時点で残高がマイナスになる、取引日とその日以内の注文の有効な選択肢が少なくとも 1 つあるかどうかを判断する必要があります。 マイナス残高は現金ギャップです。 残高がちょうどゼロになったとしても、会社には支払いに十分な資金があるため、それでも安全です。 

入力の便利な部分は、`n`そして`m`せいぜい両方です`1000`。 アン`O(nm)`このソリューションでは、1 日に最大約 100 万回のトランザクション チェックが実行されますが、これは制限時間としては十分妥当な値です。 さらに重要なことは、すべてのトランザクションには多くの可能な日数が​​ある可能性があるため、境界により可能なスケジュールの列挙が除外されることです。 すべてにまたがる間隔で`m`すべてのトランザクションに日を割り当てるだけで、`m^n`可能性。 のために`n = m = 1000`、つまり`1000^1000`一日の取引の順序を考える前に、割り当てを行うことができます。 

いくつかの境界ケースにより、妥当な解決策が間違っている可能性があります。 まず、ゼロになることは現金ギャップではありません。 例えば、```
1 1 5
-5 1 1
```出力があります`NO`、唯一のトランザクションでは残高がゼロのままになるためです。 を使用した小切手`balance <= 0`の代わりに`balance < 0`間違って答えるだろう`YES`。 

第 2 に、間隔が当日より前に終了するトランザクションはすでに強制的に実行されますが、間隔に当日が含まれるトランザクションは意図的にその日にスケジュールすることができます。 例えば、```
2 2 5
5 1 1
-6 2 2
```出力があります`YES`。 最初のトランザクションは 1 日目に発生し、残高は 10 になります。2 番目のトランザクションは 2 日目に発生し、残高が 4 に減少するため、この特定の例は実際には安全です。 境界を正しく表示するには、初期バランスを 0 に変更しますが、制約には`s >= 1`。 代わりに有効な例は次のとおりです```
2 2 5
0 1 1
-6 2 2
```出力があるもの`YES`、バランスがなるからです。`-1`当日に終了するトランザクションを、その日を調べる前に誤ってすでに完了したものとして扱うソリューションでは、そのようなケースが誤って分類される可能性があります。 

第三に、同日の取引は敵対的に命令される可能性があります。 考慮する```
2 1 5
-3 1 1
-3 1 1
```出力があるもの`YES`。 最初の支払いでは 2 ユーロが残り、2 回目の支払いでは 3 ユーロが必要になります。 ここでは 2 つの支払いを合計するだけで十分ですが、任意の固定入力順序を想定した実装は、1 日にプラスのトランザクションとマイナスのトランザクションが共有される場合に失敗する可能性があります。 

最後に、値がゼロのトランザクションはまったく効果がありません。 例えば、```
2 1 5
0 1 1
0 1 1
```出力があります`NO`。 危険な取引のアクティブなセットを維持する場合、そのような取引を誤ってマイナスの支払いとして扱うべきではありません。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのトランザクションに対して許可される日を選択し、その結果のスケジュールをシミュレートします。 すべての間隔が`[1, m]`、 がある`m^n`可能な曜日の割り当て。 また、トランザクションの可能な順序をすべて明示的に試してみると、別の要因が存在する可能性があります。`n!`、与える`m^n n!`候補の組み合わせ、`O(n)`それぞれをシミュレーションする作業。 最大の制約の場合、これは実現可能性をはるかに超えています。 

ブルート フォースが機能するのは、トランザクションが発生する可能性のあるすべての有効な方法を文字通り調査するためです。 その情報のほとんどすべてが質問とは無関係であるため、失敗します。 完全なスケジュールを立てる必要はありません。 私たちが知る必要があるのは、ある瞬間にマイナスの残高が生じる可能性があるかどうかだけです。 

特定の日を修正する`d`, そしてその日の取引直前や取引中に残高がどのくらいまでなら大丈夫なのかを聞いてみましょう。 とのすべての取引`to < d`前日に起こったと強制される`d`正確な日付をどのように選択するかに関係なく。 その貢献はすでに残高に含まれている必要があります。 

ここで、間隔に次のものが含まれるトランザクションを考えてみましょう。`d`。 値が負の場合、その日にスケジュールすることができます`d`その日のすべてのプラスのトランザクションの前にそれを実行します。 可能な限り最小の残高を探しているため、現金ギャップをチェックする前に、このようなマイナスのトランザクションをすべて含める必要があります。 間隔に以下が含まれるポジティブなトランザクション`d`危険な瞬間が来るまで延期できるため、ギャップを防ぐのには役立ちません。 

これにより、簡単な特徴が得られます。 毎日のために`d`、その時点までに到達できる最小残高は`initial balance + sum of all transactions with to < d + sum of all negative transactions with from <= d <= to`。 

この値がいずれかについて負の場合`d`、答えは`YES`。 逆に、それが決して負でない場合、式にはその時点より前に残高を小さくする可能性のあるすべてのトランザクションがすでに含まれているため、有効な注文によって現金ギャップが生じる可能性はありません。 

この式は線形時間で評価できます。 最初の合計では、トランザクション値を終了日ごとにグループ化します。 2 番目の合計では、差分配列を使用して現在アクティブな負のトランザクションを維持します。 ネガティブな取引`[from, to]`から始まる価値に貢献します`from`その後貢献を停止します`to`なので、その値を次のように追加します。`from`そしてそれを引きます`to + 1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(m^n n! n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n + m)`|`O(m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`ending`どこ`ending[d]`可能な最新日が正確に一致するすべてのトランザクション変更の合計を保存します`d`。 検査日が近づいてきたら`d`、とのすべての取引`to < d`すでに強制的に起こっているので、蓄積することができます`ending[d - 1]`と呼ばれる実行中の値に`forced`。 
2. 差分配列を作成する`active`。 間隔のあるすべての負のトランザクションに対して`[from, to]`そして価値観`count`、 追加`count`で`active[from]`そして引きます`count`で`active[to + 1]`。 そのプレフィックスの合計は、その間隔に当日が含まれるすべての負のトランザクションの合計値と等しくなります。 
3. からの日数をスキャンします。`1`を通して`m`。 日中`d`、最初に追加します`ending[d - 1]`に`forced`。 これにより、`forced`厳密に前日に発生したすべてのトランザクションの寄与に等しい`d`。 
4.追加`active[d]`実行中の変数に`dangerous`。 プレフィックス更新後、`dangerous`は、その日に実行できるすべてのマイナスのトランザクションの正確な合計です。`d`。 
5. コンピューティング`balance = s + forced + dangerous`。 これは、1 日の処理中に到達できる最小残高です。`d`、すべての強制トランザクションはすでに発生しているため、現在利用可能なすべてのネガティブ トランザクションはすぐに実行でき、まだ遅延する可能性があるポジティブ トランザクションは実行されていません。 
6. もし`balance < 0`、印刷`YES`すぐに。 それ以外の場合は、次の日に続行します。 毎日が安全なら印刷してください`NO`。 

### なぜ効果があるのか

 いつでも検討してください`d`。 とのすべての取引`to < d`前日に起こったに違いない`d`, そのため、その寄与は避けられません。 間隔が含まれるトランザクション間で、`d`、すべてのマイナスのトランザクションはその日に行うことができます`d`ポジティブなトランザクションの前に実行されます。 それらをすべて含めると、その時点で到達可能な最小限のバランスが得られます。 他のトランザクションは、この式より早く残高を下げることはできません。 したがって、アルゴリズムは、有効な取引スケジュールによって現金ギャップが生じる可能性があるときに、正確にマイナス残高を検出します。 

スキャン中の不変条件は次のとおりです。`forced + dangerous`は、当日の可能な最小の累積トランザクション変化を表します。 終了寄与分は、すでに避けられないすべてのものを説明しますが、アクティブな負の寄与分は、危険な瞬間の前に意図的に配置できる現在利用可能なすべてのものを説明します。 この最小値が負の値にならない場合、すべての有効なスケジュールは安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())

    ending = [0] * (m + 2)
    active = [0] * (m + 2)

    for _ in range(n):
        count, left, right = map(int, input().split())

        ending[right] += count

        if count < 0:
            active[left] += count
            active[right + 1] -= count

    forced = 0
    dangerous = 0

    for day in range(1, m + 1):
        forced += ending[day - 1]
        dangerous += active[day]

        if s + forced + dangerous < 0:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```の`ending`配列には、正の値と負の値を含む完全なトランザクション寄与が格納されます。 との取引`to = d`には追加されません`forced`当日まで`d + 1`、当日だから`d`その日中も実行される可能性があり、危険な注文の一部となる可能性があります。 

の`active`配列には負のトランザクションのみが含まれます。 価値のある取引の場合`count < 0`と間隔`[left, right]`、追加`count`で`left`ちょうど最初の法定日からアクティブになります。 それを引き算すると、`right + 1`法定最終日の直後に削除します。 当日のプレフィックス合計`d`したがって、次の条件を満たす負のトランザクションが正確に含まれます。`left <= d <= right`。 

1 日のループ内の更新の順序により、境界が正しく処理されます。`ending[day - 1]`チェック日の前に追加されます`day`、 その間`active[day]`現在の日自体に追加されます。 この区別は、すでに避けられないトランザクションと、当日に意図的にスケジュールできるトランザクションを区別するものです。 

Python の整数には任意の精度があるため、潜在的に大きな中間合計がオーバーフローすることはありません。 絶対合計の最大値は約に達する可能性がありますが、`10^9`、Python 整数を使用すると、実装はその境界から独立します。
