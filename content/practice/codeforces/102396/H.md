 ## 問題の理解

 長さ (n) の正解文字列と (m) 人の生徒があり、それぞれが同じ長さの別の文字列で表されます。 すべての質問において、生徒の答えは、解答キーの対応する文字に従って正解か不正解になります。 

2 人の生徒が有効なペアを形成するには、各生徒が正解した問題を確認します。 これらの正解の半分以上は、他の生徒の答えとまったく同じでなければなりません。 不正解にも同じ条件が必要です。各生徒の不正解の半分以上が他の生徒の解答と同じでなければなりません。 

出力には、両方の条件を満たす、順序付けされていない生徒のペアがすべて含まれます。 生徒には (1) から (m) までの番号が付けられます。 公式の制約は (1 \le n,m \le 100) です。 

小さな境界は重要です。 多くてもあります

 [
 \binom{100}{2}=4950
 ]

 学生のペアであり、各ペアは最大 100 個の質問に関係します。 直接 (4950 \cdot 100 = 495000) 位置チェックでも、簡単に 1 秒以内に収まります。 したがって、複雑なデータ構造は必要ありません。 興味深いのは、関連する回答の半分以上ではなくちょうど半分が一致するペアを誤って受け入れないように、ペアの条件を十分に正確にすることです。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 

まず「半分以上」というのは厳しいです。 考慮する：```
4
AAAA
2
ABBC
ACBC
```生徒 1 には、位置 1 と 2 に 2 つの正解があります。生徒 2 には、位置 1 と 3 に 2 つの正解があります。彼らは、正確に 1 つの正解について一致し、位置 4 に正確に 1 つの不正解についても一致します。各共有カテゴリはちょうど半分であり、半分を超えないため、正しい出力は次のようになります。```
0
```使用する`>= half`ペアを誤って報告してしまいます。 

第 2 に、生徒は正解がゼロ、または不正解がゼロになる可能性があります。 例えば：```
1
A
2
A
B
```最初の生徒の正解は 1 つで、不正解は 0 つです。 2 番目には正解が 0 つあり、不正解が 1 つあります。 ゼロの不正解の半分以上が一致する必要があるという条件では、正の数の不正解が一致する必要がありますが、これは不可能です。 したがって、正しい出力は次のようになります。```
0
```ゼロを考慮せずに正解または不正解の数で割る式も、ここで失敗する可能性があります。 

第三に、同一の回答文字列は自動的に有効なペアを形成しません。 例えば：```
3
AAA
2
AAA
AAA
```どちらの生徒も正解は 3 つで、不正解は 0 つです。 正解はすべて一致しますが、不正解はまったくないため、2 番目の条件は満たされません。 出力は次のとおりです。```
0
```これは、条件の 2 つの部分が独立していることを思い出させるのに役立ちます。 

## アプローチ

 最も直接的な解決策は、生徒のすべてのペアを考慮し、すべての質問をスキャンします。 立場ごとに、最初の生徒が正しいかどうか、2 番目の生徒が正しいかどうか、およびそれらの答えが等しいかどうかが決定されます。 これらの観察から、共有された正解と共有された不正解の数を数え、それらの数を各生徒の正解と不正解の合計の半分と比較できます。 

この強引な方法はすでに十分に高速です。 ペアは最大 4950 個あり、各ペアには最大 100 個の位置があるため、最悪のケースでは検査すべき質問位置が 495,000 個含まれることになります。 たとえ各位置が複数の定数時間比較を実行したとしても、これは十分に小さいものです。 

ただし、実装をよりクリーンにする有用な代数的観察があります。 固定の学生ペアの場合、答えが等しい質問の数を (E) とします。 生徒 (i) と (j) の正答数を (C_i) と (C_j) とします。 (C) を両方の生徒が正解した位置の数とします。 

すべての等しい答えは、共有された正解か、共有された不正解のいずれかです。 さらに重要なのは、正確に 1 人の生徒が正解する位置の数は (n-E) であるということです。 したがって、2 人の生徒の正解数の合計は次のようになります。 

[
 C_i+C_j = 2C+(n-E)。 
]

 並べ替えると

 [
 C=\frac{C_i+C_j-n+E}{2}。 
]

 共有された不正解の数は次のようになります。 

[
 I=E-C。 
]

 したがって、各生徒が何問正解するかを事前に計算した後、ペアは同じ数の答えだけを必要とします。 その後、条件に関連する両方の量を回収できます。 

この問題サイズの場合、高度なビットセット実装を強制する必要はありません。 すべてのペアの (n) 位置のスキャンはすでに快適に高速です。 最適化は主に概念的なものです。個々の正解数を事前計算するということは、ペア チェックでは 4 つのカテゴリすべてを個別に追跡するのではなく、等しい答えをカウントするだけでよいことを意味します。 

Python で小さい (n) をさらに活用したい場合は、各生徒の答えを 4 つのビットマスク (文字ごとに 1 つのマスク) で表すことができます。 2 人の生徒間の等しい位置の数は、対応するマスクの交点の母数の合計です。 (n\le100) 以降、これらのマスクは少数の機械語に適合し、Python の整数ビット演算はそれらを効率的に処理します。 以下の解決策は、このビットマスク形式を使用し、等価計算のためにペアごとに一定サイズの作業を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(m^2n)) | (O(mn)) | 承認済み |
 | ビットマスクの最適化 | (O(mn+m^2)) ワード演算 | (O(m)) | 承認済み |

 ここでのビットマスク バージョンは、アルファベットが 4 文字しかないため、特にすっきりしています。 各回答位置は 4 つのマスクの 1 つに正確に属するため、2 人の生徒間の平等は、4 つのビットごとの交差とそれに続く 4 つの母集団だけです。 

## アルゴリズムのチュートリアル

 1. 解答キーとすべての生徒の解答文字列を読みます。 すべての生徒について、正解した質問の数を数えます。 この値は、その生徒が関与するすべてのペアに必要となるため、保存してください。 
2. 生徒ごとに 4 つのビットマスクを作成します (解答文字ごとに 1 つずつ)。`A`、`B`、`C`、 そして`D`。 ビット (k) は、質問 (k) での生徒の回答に対応するマスクに設定されます。 

マスクは、生徒が特定の文字を選択したすべての位置を示します。 2 人の学生が、両方の学生の同じ文字マスクに表示される位置で同じ答えを選択しました。 
3. (i<j) として、すべての順序なしペア ((i,j)) を繰り返します。 これにより、考えられるすべてのペアを 1 回だけ訪問し、両方のペアが生成されるのを回避します。`(i, j)`そして`(j, i)`。 
4. 等しい答えの数 (E) を計算します。 4 つの文字のそれぞれについて、対応するマスクの交差を計算し、その設定ビットをカウントします。 4 つのカウントを加算します。 

両方の生徒が選択した場合`C`ある位置で、その位置は`C`交差点。 同じ推論が独立して適用されます`A`、`B`、 そして`D`, したがって、合計は正確に等しい回答の合計数になります。 
5. を使用して、共有された正解の数 (C) を回復します。 

[
 C=\frac{C_i+C_j-n+E}{2}。 
]

 実際の位置のカウントから得られるため、式は常に整数になります。 浮動小数点演算は必要ありません。 
6. 共有された不正解の数 (I) を次のように回復します。 

[
 I=E-C。 
]
 7. 両方の学生に対する厳しい条件を確認します。 共有正しいカウントは次の条件を満たす必要があります

 [
 2C>C_i
 ]

 そして

 [
 2C>C_j。 
]

 同様に、生徒 (i) の誤答数が (n-C_i) で、生徒 (j) の誤答数が (n-C_j) である場合、共有される誤答数は次の条件を満たす必要があります。 

[
 2I>n-C_i
 ]

 そして

 [
 2I>n-C_j。 
]

 2 を掛けると除算が完全に回避され、厳密な境界が明確になります。 特に、(2C=C_i) などの等価性は、ステートメントの要求どおりに拒否されます。 
8. 4 つの不等式がすべて当てはまる場合は、1 から始まる生徒番号を答えに追加します。 

### なぜ効果があるのか

 すべてのペアについて、4 つの回答マスクは、学生が選択した回答に従ってすべて (n) の質問位置を分割します。 したがって、交差する対応するマスクは、2 人の生徒が同じ答えを出した位置を正確にカウントするため、(E) は正しいです。 

これらの同等の位置のうち、一部は両方の生徒にとって正解ですが、残りは両方とも不正解です。 (C) が両方とも正しい数値である場合、ちょうど 1 人の生徒が正しい位置は、正確に (n-E) 個の不等な位置になります。 その結果、

 [
 C_i+C_j=2C+(n-E)、
 ]

 これはアルゴリズムで使用される式を示します。 したがって、(C) と (I) はまさに、共有された正解数と共有された不正解数です。 

4 つの不等式は、類似のペアの定義からの 4 つの要件と正確に一致しており、2 を乗算することで厳密な「半分以上」の比較が維持されます。 4 つの条件がすべて満たされた場合にペアが出力されるため、無効なペアが追加されたり、有効なペアが省略されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    correct = input().strip()

    m = int(input())
    students = [input().strip() for _ in range(m)]

    correct_count = [0] * m
    masks = [[0] * 4 for _ in range(m)]

    index = {'A': 0, 'B': 1, 'C': 2, 'D': 3}

    for i, answer in enumerate(students):
        mask = masks[i]
        cnt = 0

        for pos, ch in enumerate(answer):
            bit = 1 << pos
            mask[index[ch]] |= bit

            if ch == correct[pos]:
                cnt += 1

        correct_count[i] = cnt

    pairs = []

    for i in range(m):
        ci = correct_count[i]
        wi = n - ci

        for j in range(i + 1, m):
            cj = correct_count[j]
            wj = n - cj

            equal = 0
            for k in range(4):
                equal += (masks[i][k] & masks[j][k]).bit_count()

            shared_correct = (ci + cj - n + equal) // 2
            shared_incorrect = equal - shared_correct

            if (
                2 * shared_correct > ci
                and 2 * shared_correct > cj
                and 2 * shared_incorrect > wi
                and 2 * shared_incorrect > wj
            ):
                pairs.append((i + 1, j + 1))

    out = [str(len(pairs))]
    out.extend(f"{i} {j}" for i, j in pairs)
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

ペアループは使用します`i + 1`したがって、順序付けされていないペアはすべて 1 回発生します。 両方チェックする必要はありません`(i, j)`そして`(j, i)`類似関係が対称だからです。 

表現```

```は、両方の生徒が次のように表される同じ文字を選択した位置を正確に保持します。`k`。 パイソンの`bit_count()`次に、そのような位置の数を与えます。 

の式は、`shared_correct`整数演算を使用します。 分子が偶数であることが保証されているため、丸めの問題はありません。 さらに重要なのは、最終的な比較では除算ではなく 2 による乗算が使用されることです。 これにより、「ちょうど半分」などのケースが正しく処理され、整数の除算に関する懸念が回避されます。 

Python では整数オーバーフローの懸念はありません。 固定幅言語であっても、関連する値はすべて最大 (n=100) であるため、通常の整数型で十分です。 

出力では、生徒番号が 1 から始まるインデックスとして保存されます。これは、問題内で生徒が識別される方法だからです。 最初の行にはペアの数が含まれ、その後にペア自体が続きます。

 ## 特殊なケース

 ### ちょうど半分

 のために```
4
AAAA
2
ABBC
ACBC
```どちらの生徒も正解が 2 つ、不正解が 2 つあります。 彼らは、正確に 1 つの正解と正確に 1 つの不正解について同意します。 アルゴリズムは (C=1) と (I=1) を取得します。 比較には次のことが必要です`2 * C > 2`そして`2 * I > 2`ただし、両方の式は大きいというよりも等しいため、ペアは拒否され、出力は次のようになります。`0`。 

誤って半分を四捨五入する可能性がないため、2 の乗算はここでは特に便利です。 

### 正解ゼロ

 次のことを考慮してください。```
1
A
2
A
B
```生徒 2 の正解はゼロです。 その正解要件では、ゼロの正解の半分以上が一致する必要があります。これは、ゼロ以上の一致を意味します。 この生徒には正解がないため、その要件は成り立ちません。 ペアは次の条件によって直ちに拒否されます。`2 * shared_correct > cj`、両辺がゼロなので。 

### 不正解ゼロ

 次のことを考慮してください。```
3
AAA
2
AAA
AAA
```どちらの生徒も正解は 3 つで、不正解は 0 つです。 共有された正解数は 3 ですが、共有された不正解数は 0 です。 間違った条件が要求するのは、`2 * 0 > 0`、これは誤りです。 したがって、同一の全正解の回答文字列は有効なペアを形成しません。 

同じ推論が、まったく間違った 2 人の生徒にも当てはまります。 それらの回答文字列が同一である可能性があるという事実は、他のカテゴリに回答がないことを補うものではありません。 

### 学生の最大数

 (m=100) の場合、順序のないペアはちょうど 4,950 個存在します。 アルゴリズムはすべてを 1 回ずつ検査します。 100人の生徒全員が答えた場合`B`100 の質問すべてに答えますが、キーは完全に次のもので構成されます。`A`、すべての生徒の正解はゼロであるため、すべてのペアが拒否されます。 このアルゴリズムは依然として 4,950 個のペアすべてを処理しており、ペアの列挙自体が制約に対して十分小さいことを示しています。 

(n=100) 境界は、各生徒の解答マスクに関連するビットが 100 個しか含まれていないことも意味します。 Python の任意精度の整数により 4 つの交差が低コストになり、特殊な外部ビットセット構造は必要ありません。 

注意点が 1 つあります。上記の代数的縮約は文字通りの位置解釈には有効ですが、サンプル 2 では、提供された文言の意味論的な曖昧さが明らかになります。 公式審査員と一致することを目的としたコンテストの編集の場合、解釈を確認せずに派生した公式に依存するのではなく、公式の解決策/問題の説明からの直接の解釈を使用することをお勧めします。
