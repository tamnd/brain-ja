 ## 問題の理解

 チェストが 3 つあります。`a`、`b`、 そして`c`コイン。 1 秒以内に、正確に 2 つの異なるチェストを選択し、選択した各チェストに 1 枚のコインを追加します。 3 つのチェストすべてが同じ数のコインで終了する必要があり、最小秒数が必要です。 

入力には、次の 3 つの初期コイン カウントが含まれます。`1`そして`5 * 10^8`。 関係する値は 3 つだけなので、高度なデータ構造は必要ありません。 大きな上限が実際の信号です。1 秒あたり 1 つの操作を実行するシミュレーションには 10 億回近くの反復が必要となる可能性があり、これは 1 秒の制限をはるかに超えています。 定数時間または対数解が適切なターゲットです。 

主なエッジケースは、最大のチェストが最初に検討するターゲット値をすでに持っている場合です。 たとえば、```
1
2
3
```不用意に近づくと、最初の 2 つのチェストが持ち上げられてしまう可能性があります。`3`。 赤字は、`2`そして`1`, 一方、3番目のチェストにはコインは必要ありません。 すべての操作は 2 つのチェストに影響を与えるため、3 番目のチェストを変更せずに、最初の 2 つを別々に異なる量だけ増やすことはできません。 正しい答えは、`3`、到達`4, 4, 4`。 

もう 1 つのエッジ ケースは、すでに同等の構成です。```
2
2
2
```答えは`0`。 等価性をチェックする前に常に少なくとも 1 つの操作を実行するシミュレーションでは、誤って正の値が返されます。 

繰り返される値にも注意が必要です。 のために```
1
3
3
```答えは`4`、 ない`2`。 最初の胸を上げることで、`2`すべての操作で他の 2 つのチェストの 1 つも上昇するため、これだけでは十分ではありません。 正しい最終値は次のとおりです。`5`、4つの操作が必要です。 

## アプローチ

 直接的なアプローチは、一度に 1 秒ずつ操作をシミュレートすることです。 すべてのステップで、平等に向けて進むチェストのペアを選択し、その値を更新し、3 つの値がすべて一致したら停止することができます。 ペアが適切に選択されていればこれは正しいですが、秒数自体が膨大になる可能性があります。 

値を次のように並べ替えた後、`x <= y <= z`、制約の下での最悪のケースは次のとおりです。`x = 1`、`y = z = 5 * 10^8`。 したがって、最低限の答えは、`y + z - 2x = 999,999,998`。 

したがって、シミュレーションはほぼ 10 億回の反復を実行することになります。 各反復は一定時間であっても、それは制限時間を超えすぎます。 

重要な観察は、操作によって常に合計でちょうど 2 枚のコインが追加されるということです。 どのペアを選択するかを毎秒決定する代わりに、各チェストが最終状態で受け取る必要があるコインの数を推論できます。 

最終的な共通値が`T`。 3 つのチェストに必要なのは`T-x`、`T-y`、 そして`T-z`追加のコイン。 すべての操作で 2 つのチェストに 1 つのコインが与えられるため、必要な増加はペアにする必要があります。 特に、必要な最大の増加量は、他の 2 つの増加量の合計を超えることはできません。 

最小の胸の場合、必要な増加量は次のとおりです。`T-x`、3 つの中で最大のものです。 したがって、必要なのは`T - x <= (T - y) + (T - z)`。 

並べ替えると`T >= y + z - x`。 

したがって、可能な最小の共通値は正確に次のようになります。`T = y + z - x`。 

この目標はいつでも達成可能です。 その必要な増加量は、`y + z - 2x`、`z - x`、 そして`y - x`。 

1 つ目は他の 2 つの合計なので、最も小さいチェストに与えられたコインはすべて、他のチェストの 1 つに与えられたコインと組み合わせることができます。 

1 回の操作で 2 枚のコインが追加されるため、合計操作数も直接取得できます。 必要なコインの総数は、`(y + z - 2x) + (z - x) + (y - x) = 2(y + z - 2x)`。 

2で割ると答えが得られます`y + z - 2x`。 

したがって、問題全体は 3 つの数値を並べ替えて 1 つの式を適用することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 3 つの胸の値を読み取り、次のように並べ替えます。`x <= y <= z`。 3 つの値を並べ替えるには一定の時間がかかり、元の位置について個別のケースを処理することなく、最小、中間、および最大のチェストを推論することができます。 
2. 最終的な共通値を検討する`T`。 最小のチェストに必要なもの`T - x`追加のコインが必要ですが、他の 2 つは必要です`T - y`そして`T - z`。 
3. 最大の赤字が他の 2 つの赤字の合計以下であることを要求します。 これが必要なのは、最小のチェストに追加されるコインはすべて、他のチェストのいずれかに追加されるコインを伴う必要があるためです。 したがって、`T - x <= T - y + T - z`。 
4. 不等式を並べ替えて取得します。`T >= y + z - x`。 可能な限り小さいターゲットを選択すると、`T = y + z - x`、作業量が最小限に抑えられます。 
5. 最小胸部の必要な増加量を計算します。`T - x = y + z - 2x`。 

この目標では、この増加は他の 2 つの増加の合計となるため、有効なペア操作のシーケンスが存在します。 
6. 出力`y + z - 2x`。 追加されるコインの合計数はこの値の 2 倍であり、各操作でちょうど 2 つのコインが追加されるため、これはすでに操作の数です。 

この構造の背後にある不変条件は、最小のチェストの必要な増加量が、他の 2 つのチェストの必要な増加量の合計に等しいということです。 最小のチェストに必要なすべてのコインを、他のチェストに必要な 1 枚のコインと組み合わせることができます。 どの手術でも同じ胸を二度触る必要はなく、3つの欠損すべてが同時に解消されます。 ターゲットが小さいとペアリング条件に違反するため、より少ない操作を使用するソリューションはありません。

    print(y + z - 2 * x)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert run("1\n2\n3\n") == "3\n", "sample 1"
assert run("2\n2\n2\n") == "0\n", "sample 2"

assert run("1\n1\n1\n") == "0\n", "minimum values"
assert run("1\n500000000\n500000000\n") == "999999998\n", "maximum values"
assert run("1\n3\n3\n") == "4\n", "repeated maximum values"
assert run("2\n2\n5\n") == "3\n", "repeated minimum values"
assert run("5\n1\n3\n") == "6\n", "unsorted input"

 ## 特殊なケース

 のために`2, 2, 2`、ソートすると、`x = y = z = 2`、そして答えは`2 + 2 - 4 = 0`。 アルゴリズムは、操作が必要ないことを正しく認識します。 

のために`1, 2, 3`、実現可能な最小のターゲットは`2 + 3 - 1 = 4`。 赤字は、`3, 2, 1`, そのため、最小のチェストは中央のチェストと 2 回、最大のチェストと 1 回組み合わせることができます。 結果は`3`。 

のために`1, 3, 3`、ターゲットは`3 + 3 - 1 = 5`。 赤字は、`4, 2, 2`、4 つの有効な操作が可能です。 数式は戻ります`3 + 3 - 2 = 4`。 

のために`1, 500000000, 500000000`、結果は`999999998`。 直接シミュレーションでは多くの反復が必要ですが、最適なアルゴリズムでは閉形式の式を通じて即座に答えに到達します。
