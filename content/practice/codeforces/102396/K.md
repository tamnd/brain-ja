 ## 解決策
 ## 問題の理解

 サブ配列は、1 つの完全なマルチテスト入力として解釈されます。 最初の値は数値です`m`グラフの端と次の端`2m`値は次のようにグループ化されます`m`順序のない頂点ペア。 結果として得られる無向グラフはフォレストである必要があるため、自己ループ、繰り返しエッジ、またはサイクルを含めることはできません。 タスクは、この解釈を満たすサブ配列の数を数えることです。 公式の制約は次のとおりです`1 <= n <= 300000`そして`0 <= a_i <= 10^9`、2 秒の時間制限と 512 MB のメモリ制限があります。 

候補部分配列の最初の値によって、その長さが完全に決まります。 部分配列が位置から始まる場合`l`そして`a[l] = m`、そのエンドポイントは次でなければなりません`l + 2m`。 したがって、各開始位置には有効なサブ配列が最大 1 つあります。 本当の困難は、エンドポイントを見つけることではなく、すべてのエンドポイントが存在するかどうかを確認することです。`m`エッジは十分な速さで森を形成します。 

直接実装すると、新しい DSU を使用してすべての候補グラフを検査できます。 最悪の場合、Θ(n) 個の候補が存在し、それぞれに Θ(n) 個のエッジが含まれ、Θ(n²) 個のエッジ演算が行われる可能性があります。 と`n = 300000`、二次方程式の方法はおおよその範囲に達することができます。`n² / 4`、つまり約 225 億回のエッジ チェックに相当し、これは 2 秒のソリューションで実行できる量をはるかに超えています。 したがって、ソリューションでは、開始位置ごとにグラフを再構築することを回避する必要があります。 

間違ったソリューションが無効な部分配列を黙って受け入れてしまう簡単なケースがいくつかあります。 ゼロ エッジ カウントは有効です。たとえば、入力`1 0`有効な部分配列が含まれています`[0]`なぜなら、エッジのないグラフは森だからです。 少なくとも 1 つのエッジを確認することを要求するソリューションは、誤ってエッジを拒否してしまいます。 

自己ループは、エッジが 1 つしか含まれていない場合でも無効です。 例えば、```
3
1 5 5
```候補者がいる`[1, 5, 5]`、エッジを説明します`(5,5)`。 自己ループは長さ 1 のサイクルであるため、正しい寄与はゼロです。 2 つのエンドポイントが既に接続されているかどうかだけをチェックする DSU 実装では、明示的に処理する必要があります。`u == v`。 

平行エッジも無効です。 例えば、```
5
2 1 2 1 2
```から始まる`m = 2`そして説明します`(1,2), (1,2)`。 位置 0 からの正しい寄与は 0 です。 繰り返されるエッジを無害なものとして扱うと、フォレストではないマルチグラフが誤って受け入れられます。 

最後に、配列の位置が重要です。 サンプルについて```
5
2 1 3 4 1
```位置 0 で始まるサブ配列には 2 つのエッジがありますが、位置 1 で始まるサブ配列には 1 つのエッジがあります。 どちらも有効なので、答えは次のようになります。`2`。 位置の固定パリティのみを検査するソリューションでは、そのうちの 1 つが見落とされてしまいます。 

## アプローチ

 ブルートフォース手法は定義に直接従います。 すべての開始位置について`l`、 読む`m = a[l]`、それを確認してください`l + 2m < n`、そして次の処理を行います`m`DSUとペアリングします。 エッジのとき`(u,v)`が読み取られると、自己ループにより直ちにグラフが無効になります。 それ以外の場合は、`u`そして`v`がすでに同じコンポーネント内にある場合、エッジはサイクルを作成するため、グラフは無効になります。 異なるコンポーネントにある場合は、それらをマージします。 これは正しいです。2 つの異なるコンポーネント間にエッジを挿入するとフォレストのプロパティが維持されますが、1 つのコンポーネント内にエッジを挿入すると 1 つのサイクルが作成されるだけです。 

問題は繰り返し作業です。 1 つの DSU 操作がほぼ一定の償却時間であっても、Θ(n) 個の異なる開始に対して Θ(n) 個のエッジを処理する可能性があります。 最悪の場合の処理​​エッジ数は Θ(n²) で、次の場合は約 225 億です。`n = 300000`。 

重要な観察は、グラフの妥当性条件がエッジの削除に関して単調であるということです。 エッジの範囲がフォレストである場合、それらのエッジの小さな連続範囲もすべてフォレストになります。 これにより、問題を範囲クエリの問題に変えることができます。 

配列の 1 つの固定ペアのエッジを考えてみましょう。 適切なエンドポイントごとに`r`、 定義する`bad[r]`最大の指標として`x`エッジ間隔が`[x,r]`サイクルが含まれています。 それから`[l,r]`まさにそのときの森です`l > bad[r]`。 その理由は、サイクルが完全に含まれている場合、`[l,r]`、その最小エッジ インデックスは少なくとも`l`、 それで`bad[r] >= l`。 逆に、もし`bad[r] >= l`、サイクルの目撃者`bad[r]`完全に内側にある`[l,r]`。 

残る問題はメンテナンス方法です`bad[r]`エッジは左から右に挿入されます。 挿入されたエッジは常に最新のエッジであるため、そのインデックスは既存のすべてのエッジよりも大きくなります。 エンドポイントが切断されている場合、サイクルは作成されません。 それらが接続されている場合、既存のフォレストにはそれらの間に一意のパスが含まれており、新しいエッジを追加するとサイクルが作成されます。 そのパス上の最小のエッジ インデックスは、まさに新しいサイクルの最小のエッジです。 この値と前の値の最大値を取る`bad`新しいしきい値を与えます。 

したがって、接続性、パス上の最小エッジ、および 1 つのツリー エッジを新しいエッジに置き換えることをサポートする動的なフォレストが必要です。 リンクカットツリーは自然にフィットします。 リンクカット ツリーは、動的なフォレスト操作と対数償却時間でのパス集約をサポートします。 

元の配列に起因する追加の詳細が 1 つあります。 有効なサブ配列はどちらのパリティでも開始できます。 均等な位置から始まる場合、そのエッジは```
(a[l+1], a[l+2]), (a[l+3], a[l+4]), ...
```一方、開始位置が奇数の場合は、```
(a[l+1], a[l+2]), (a[l+3], a[l+4]), ...
```もう一方の位置は元の配列を基準にして配置されます。 これら 2 つの位置合わせは個別に処理します。 各位置合わせは通常のエッジ シーケンスになり、元の開始位置はそれぞれそのエッジ シーケンスの 1 つのプレフィックスに正確に対応します。

 ## アルゴリズムのチュートリアル

 1. 配列内に出現するすべての頂点ラベルを座標圧縮します。 頂点値は次のように大きくできます。`10^9`ただし、ラベル間の平等のみが重要です。 圧縮により、すべての個別の頂点にコンパクトな整数 ID が与えられます。 
2. 2 つの可能なエッジ位置合わせを個別に処理します。 パリティ用`p`、候補は次から始まります`l = p + 2j`、その最初の値は`a[l]`。 その最初のエッジは`(a[l+1], a[l+2])`、 に続く`(a[l+3], a[l+4])`。 
3. 通常のノードが圧縮されたグラフ頂点を表すリンクカット ツリーを構築します。 すべてのエッジには、独自のリンクカットツリー ノードも取得されます。 エッジ ノードはエッジ シーケンス内のその位置を値として保存しますが、通常の頂点ノードの値は無限大です。 エッジをノードとして表すと、特定のエッジを直接切り取って置換することが可能になります。 
4. 変数を維持する`bad`、最初は`-1`。 エッジ加工後`r`、`bad`処理されたプレフィックスに完全に含まれるサイクルの可能な最大の最小エッジ インデックスです。 
5. 次のエッジのとき`(u,v)`は自己ループであるため、最小エッジが次のようなサイクルを直ちに形成します。`r`。 セット`bad = max(bad, r)`このエッジをフォレストに挿入しないでください。 
6. それ以外の場合は、`u`そして`v`整備された森の中ですでにつながっています。 接続されていない場合は、新しいエッジ ノードを接続します。`u`そして`v`。 サイクルが現れていないので、`bad`変わりません。 
7. もし`u`そして`v`すでに接続されている場合は、それらの一意のフォレスト パス上の最小エッジ インデックスをクエリします。 その値を`x`。 新しいエッジを追加すると、最小エッジが次のようなサイクルが作成されます。`x`これは、新しいエッジがサイクル内で最大のインデックスを持っているためです。 アップデート`bad = max(bad, x)`。 
8. エッジを交換する`x`整備された森の新しい端で。 古いエッジ ノードを 2 つのエンドポイントから切断し、新しいエッジ ノードを同じエンドポイントにリンクします。 結果として得られるフォレストは、処理されたグラフの最大インデックス範囲フォレストであり、これはまさに将来の挿入に必要なものです。 
9. 結果を保存します`bad[r]`すべてのエッジ位置に対して。 から始まる元の候補の場合`l = p + 2j`、 させて`k = a[l]`。 もし`k = 0`の場合、候補にはエッジが含まれず、常に有効です。 それ以外の場合、その最後のエッジは`r = j + k - 1`。 候補はまさに次の場合に有効です`r`存在し、`bad[r] < j`。 
10. すべての有効な候補を答えに追加し、他のパリティに対してプロセスを繰り返します。 

### なぜ効果があるのか

 維持されるリンクカット ツリーは常に、処理されたグラフの最大インデックス全域フォレストによって選択されたエッジを含むフォレストです。 新しいエッジが 2 つの異なるコンポーネントを接続する場合、そのエッジは合計インデックスが最大のすべてのスパニング フォレストに属し、簡単にリンクできます。 同じコンポーネント内にすでにある頂点を接続する場合、現在のツリー パスと新しいエッジが 1 つのサイクルとなります。 新しいエッジはそのサイクルで最大のインデックスを持つため、ツリー パス上の最小インデックスがサイクルの最小インデックスになります。 その最小エッジを新しいエッジに置き換えると、最大インデックスにまたがるフォレストのプロパティが保持されます。 

の不変式`bad[r]`これは、で終わるプレフィックスに含まれるすべてのサイクルの中で、可能な限り最大の最小エッジ インデックスに等しいということです。`r`。 既存のサイクルは、以前の値でカバーされます。`bad`一方、新しく作成されたすべてのサイクルは、新しいエッジの端点間のパス上の最小エッジによって表されます。 したがって、範囲`[l,r]`正確に言うとサイクルが含まれていない`l > bad[r]`。 自己ループと平行エッジは自然にサイクルとして扱われるため、この状態はグラフが有効なフォレストであることと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class LinkCutTree:
    __slots__ = ("n", "left", "right", "parent", "rev", "value", "mn")

    def __init__(self, values):
        n = len(values)
        self.n = n
        self.left = [0] * n
        self.right = [0] * n
        self.parent = [0] * n
        self.rev = [0] * n
        self.value = values
        self.mn = values[:]

    def is_root(self, x):
        p = self.parent[x]
        return p == 0 or (self.left[p] != x and self.right[p] != x)

    def push(self, x):
        if self.rev[x]:
            l = self.left[x]
            r = self.right[x]
            self.left[x], self.right[x] = r, l

            if l:
                self.rev[l] ^= 1
            if r:
                self.rev[r] ^= 1

            self.rev[x] = 0

    def pull(self, x):
        best = self.value[x]
        l = self.left[x]
        r = self.right[x]

        if l and self.mn[l] < best:
            best = self.mn[l]
        if r and self.mn[r] < best:
            best = self.mn[r]

        self.mn[x] = best

    def rotate(self, x):
        y = self.parent[x]
        z = self.parent[y]

        if self.left[y] == x:
            b = self.right[x]
            self.right[x] = y
            self.left[y] = b
            if b:
                self.parent[b] = y
        else:
            b = self.left[x]
            self.left[x] = y
            self.right[y] = b
            if b:
                self.parent[b] = y

        self.parent[y] = x
        self.parent[x] = z

        if z:
            if self.left[z] == y:
                self.left[z] = x
            elif self.right[z] == y:
                self.right[z] = x

        self.pull(y)
        self.pull(x)

    def splay(self, x):
        stack = []
        y = x
        stack.append(y)

        while not self.is_root(y):
            y = self.parent[y]
            stack.append(y)

        while stack:
            self.push(stack.pop())

        while not self.is_root(x):
            y = self.parent[x]
            z = self.parent[y]

            if not self.is_root(y):
                if (self.left[y] == x) == (self.left[z] == y):
                    self.rotate(y)
                else:
                    self.rotate(x)

            self.rotate(x)

        self.pull(x)

    def access(self, x):
        last = 0
        y = x

        while y:
            self.splay(y)
            self.right[y] = last
            self.pull(y)
            last = y
            y = self.parent[y]

        self.splay(x)

    def make_root(self, x):
        self.access(x)
        self.rev[x] ^= 1

    def find_root(self, x):
        self.access(x)

        while True:
            self.push(x)
            l = self.left[x]
            if not l:
                break
            x = l

        self.splay(x)
        return x

    def connected(self, x, y):
        if x == y:
            return True
        self.make_root(x)
        return self.find_root(y) == x

    def link(self, x, y):
        self.make_root(x)
        self.parent[x] = y

    def cut(self, x, y):
        self.make_root(x)
        self.access(y)

        if self.left[y] == x:
            self.left[y] = 0
            self.parent[x] = 0
            self.pull(y)

    def path_min(self, x, y):
        self.make_root(x)
        self.access(y)
        return self.mn[y]

def process_parity(a, vertex_id, parity):
    n = len(a)

    starts = parity
    if starts >= n:
        return 0

    edge_count = (n - parity - 1) // 2
    if edge_count <= 0:
        # There can still be zero-edge candidates.
        ans = 0
        for l in range(parity, n, 2):
            if a[l] == 0:
                ans += 1
        return ans

    total_nodes = len(vertex_id) + edge_count

    values = [INF] * total_nodes
    for i in range(edge_count):
        values[len(vertex_id) + i] = i

    lct = LinkCutTree(values)

    bad = -1
    answer = 0
    bad_at = [bad] * edge_count

    V = len(vertex_id)

    for r in range(edge_count):
        u_pos = parity + 2 * r + 1
        v_pos = u_pos + 1

        u = vertex_id[a[u_pos]]
        v = vertex_id[a[v_pos]]
        edge_node = V + r

        if u == v:
            if r > bad:
                bad = r
        elif not lct.connected(u, v):
            lct.link(edge_node, u)
            lct.link(edge_node, v)
        else:
            old_index = lct.path_min(u, v)

            if old_index > bad:
                bad = old_index

            old_node = V + old_index

            old_u_pos = parity + 2 * old_index + 1
            old_v_pos = old_u_pos + 1

            old_u = vertex_id[a[old_u_pos]]
            old_v = vertex_id[a[old_v_pos]]

            lct.cut(old_node, old_u)
            lct.cut(old_node, old_v)

            lct.link(edge_node, u)
            lct.link(edge_node, v)

        bad_at[r] = bad

    for j in range((n - parity + 1) // 2):
        l = parity + 2 * j
        if l >= n:
            break

        k = a[l]

        if k == 0:
            answer += 1
            continue

        r = j + k - 1

        if 0 <= r < edge_count and bad_at[r] < j:
            answer += 1

    return answer

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    values = sorted(set(a))
    vertex_id = {x: i for i, x in enumerate(values)}

    ans = 0
    ans += process_parity(a, vertex_id, 0)
    ans += process_parity(a, vertex_id, 1)

    print(ans)

if __name__ == "__main__":
    solve()
```頂点ラベルの実際の大きさは重要ではないため、座標圧縮は 1 回だけ行われます。 同じ整数が 2 回出現する場合は同じグラフの頂点を表す必要があり、異なる整数は異なる頂点を表す必要があります。 

1 つのパリティの場合、`edge_count`は、そのアライメントから形成できる完全なペアの数です。 各エッジは専用の LCT ノードを受け取り、その格納値はエッジ シーケンス内の位置になります。 通常のグラフの頂点は無限大を格納するため、パスの最小値は常に実際のエッジ インデックスを返します。 

挿入ロジックはアルゴリズムのウォークスルーに直接続きます。 自己ループ更新`bad`森に入らずに。 異なるコンポーネント間の新しいエッジは直ちにリンクされます。 1 つのコンポーネント内の新しいエッジがサイクルを作成するため、`path_min`最小のエッジを見つけます。 そのエッジが削除され、新しいエッジが挿入されます。 

二人`cut`エッジ ノードは無向エッジを表し、2 つの表現ツリー接続があるため、呼び出しが必要になります。 どちらかを忘れると、動的フォレスト内に古いエッジの一部が残り、後の接続クエリが破損します。 

候補の計算には次のものを使用します。`j`、元の配列位置ではなく、候補の最初のエッジに対応するエッジ インデックス。 これが多くのオフバイワンエラーの原因です。 から始まる候補`l = parity + 2j`と`k`エッジはエッジで終わります`r = j + k - 1`。 これは、その範囲にサイクルが含まれていない場合にのみ有効です。`bad_at[r] < j`。 

Python の整数はオーバーフローしないため、答えと頂点ラベルに特別な整数処理は必要ありません。 この実装では、再帰ではなく反復的なスプレイ操作を使用し、Python の再帰の深さの制限を回避します。 

## 実用的な例

 サンプル 1 の場合、```
5
2 1 3 4 1
```まず偶数の開始位置を考慮してください。 

| エッジインデックス | エッジ |`bad`| 候補開始 |`k`| 候補エッジ範囲 | 有効 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 |`(1,3)`| -1 | 0 | 2 |`[0,1]`| はい |

 位置 0 から始まる候補には 2 つのエッジが必要です。`(1,3), (4,1)`森を形成します。 奇数の開始位置は位置 1 から始まり、`k = 1`、単一のエッジを与える`(3,4)`、これも森です。 

2 つの有効な部分配列は次のとおりです。`[2,1,3,4,1]`そして`[1,3,4]`、したがって、答えは次のとおりです`2`。 

サンプル 2 の場合、```
8
1 3 1 2 2 0 2 3
```関連する候補者は次のとおりです。 

| 元のスタート |`k`| エッジ |`bad`状態 | 有効 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 |`(3,1)`| サイクルなし | はい |
 | 1 | 3 |`(1,2),(2,0),(2,3)`| サイクルなし | はい |
 | 2 | 1 |`(2,2)`| 自己ループ | いいえ |
 | 3 | 2 |`(2,0),(2,3)`| サイクルなし | はい |
 | 4 | 2 |`(0,2),(2,3)`| サイクルなし | はい |
 | 5 | 0 | エッジなし | 常に有効 | はい |

 位置 2 の候補は、明示的な自己ループのケースを示しています。 他の 5 つの候補は森を形成し、必要な答えを返します。`5`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) 償却 | 各エッジにより一定数のリンクカット ツリー操作が発生し、各 O(log n) が償却されます。 
| スペース | O(n) | 圧縮された頂点、エッジ ノード、LCT 配列、およびしきい値配列はすべて線形です。 

入力には最大 300,000 個の配列要素があるため、2 つのパリティ パスにわたるエッジ挿入は O(n) のみです。 対数ダイナミック ツリー操作は、ブルート フォース手法による二次反復 DSU 構築を置き換えます。 結果として得られる O(n log n) 境界は、指定された入力サイズとメモリ制限と互換性があります。

 ## 特殊なケース

 ゼロエッジの場合は、リンクカット操作の前に処理されます。 入力用```
1
0
```唯一の候補は次で始まります`m = 0`なので、長さは 1 です。 グラフにはエッジがなく、森になっています。 アルゴリズムは答えを即座にインクリメントします。 

次のような自己ループの場合```
3
1 5 5
```最初の候補者には1つの優位性がある`(5,5)`。 挿入ルーチンは次のことを検出します。`u == v`、更新情報`bad`現在のエッジ インデックスに変換し、エッジをフォレストに挿入しません。 候補はエッジ インデックス 0 から始まりますが、`bad`もゼロなので、`bad < start`は false であり、候補者は拒否されます。 

繰り返されるエッジの場合、```
5
2 1 2 1 2
```最初の端`(1,2)`が挿入されます。 2 番目のエッジには同じエンドポイントがあるため、すでに接続されています。 パスには最初のエッジが含まれており、そのインデックスは 0 です。 したがって、新しいサイクルの最小インデックスはゼロとなり、`bad = 0`。 エッジ 0 で始まる候補は失敗します。`0 < 0`は誤りです。 次の配列位置で始まる候補にはエッジが 1 つだけあり有効であり、合計の答えが得られます。`1`。 

三角形の場合```
7
3 1 2 2 3 3 1
```最初の 2 つのエッジは 3 つの異なる頂点を接続します。 いつ`(3,1)`が到着すると、そのエンドポイントはすでにパスによって接続されています`(3,2),(2,1)`。 そのパス上の最小エッジ インデックスはゼロであるため、`bad`ゼロになります。 エッジ 0 で始まる候補には三角形全体が含まれているため、拒否されます。 同じメカニズムは、サイクルを明示的に横断することなく、任意の長さのサイクルを処理します。 

部分配列の最初の値はどちらのパリティでも発生する可能性があるため、2 つのパリティ パスが必要です。 偶数の位置から始まる候補は、奇数の位置から始まる候補とは異なる方法で次の値を組み合わせます。 1 つのアライメントのみを処理すると、たとえフォレスト チェッカーが他の点では正しかったとしても、グラフのエッジ自体が間違ってしまいます。
