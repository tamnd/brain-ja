 ## 解決策
 ## 問題の理解

 地下鉄システムを加重グラフとして考えてください。 すべての駅は頂点であり、同じ線上の連続する駅はエッジで接続されており、エッジの重みはそれらの駅間の移動時間です。 ライン間の 3 つの特別な接続は追加のエッジであり、その重みは転送時間です。`d`。 

1行目には3路線の駅番号が入ります。`x`、`y`、 そして`z`。 2 行目は 3 つの交換パラメータを指定します。`a`、`b`、 そして`c`。 これらにより、3 つの転送ペアが決定されます。`(1, a)`に接続されています`(2, b + 1)`、`(1, a + 1)`に接続されています`(3, c)`、 そして`(2, b)`に接続されています`(3, c + 1)`。 

3 行目は、各路線の隣接駅間の 1 回の移動時間と 1 回の乗り換えに必要な時間を示します。 最後の行は、出発線と駅、および目的地の路線と駅を示します。 

出力は最小合計移動時間です。 ルートは地下鉄線に沿ってどちらの方向にも移動でき、3 つのインターチェンジ ペアのいずれかで乗り換えることができます。 ディマはインターチェンジで地下鉄を降りないため、これらの乗り換えは単にルートの端にすぎません。 

主な問題は線のサイズです。 各行には最大で次の内容を含めることができます`10^9`したがって、完全なグラフには最大で`3 * 10^9`頂点。 このようなグラフを明示的に読み取ることさえ、1 秒の制限内では不可能です。 答えはすべてのステーションを反復することに依存できないため、解決策はほぼすべてのステーションが完全に普通であるという事実を利用する必要があります。 

一見合理的であると思われる解決策が間違っている可能性がある特殊なケースがいくつかあります。 1 つ目は、交換エンドポイントが次の場所にないことです。`(a, b)`、`(a, c)`、 そして`(b, c)`。 それらは交互の行で 1 つずつシフトされます。 例えば、```
3 3 3
1 1 1
5 1 1 1
1 2 2 1
```出発地は1号線2駅、目的地は2号線1駅です。直通乗換では1号線1駅と2号線2駅を使用するため、料金は`5 + 1 + 1 = 7`。 ライン 1 のステーション 1 をライン 2 のステーション 1 に直接接続するソリューションは、存在しない乗り換えをモデル化することになり、より小さく不正確な答えが生成される可能性があります。 

2 番目の特殊なケースは、同じラインに留まることが必ずしも最適ではないということです。 例えば、```
5 5 5
2 2 2
10 1 1 1
1 1 1 5
```1 号線に直接移動するとコストがかかる`4 * 10 = 40`。 より速いルートは 2 号線と 3 号線を迂回として使用し、料金がかかります`35`。 出発駅と目的地駅が同じ線上にある場合に直接移動のみを考慮するソリューションでは、最適な結果が得られません。 

3 番目のエッジ ケースは、2 つの重要なステーション間の距離が非常に長い場合です。 考慮する```
1000000000 1000000000 1000000000
1 1 1
1 1 1 1
1 1000000000 2 1000000000
```正しい答えは、`1999999998`。 数値自体は大きいですが、計算には数回の乗算と加算だけが必要です。 すべてのステーションを明示的に構築することに基づく実装では、実際のメモリまたは時間内でグラフを表現することさえできません。 

## アプローチ

 最も直接的な解決策は、メトロ グラフ全体を構築し、ダイクストラなどの最短パス アルゴリズムを実行することです。 これは正しいです。なぜなら、考えられるあらゆる動きは、その移動時間を重みとして正確に持つエッジによって表現されるからです。 

問題は頂点の数です。 最大制限には次のものがあります`10^9 + 10^9 + 10^9 = 3 * 10^9`駅の頂点。 3 つの地下鉄路線を合わせると、`3 * 10^9 - 3`通常の線のエッジと 3 つの交換によりさらに 3 つが追加されるため、グラフは正確に次のようになります。`3 * 10^9`最悪の場合、無向エッジが発生します。 隣接リスト表現にはすでに大まかに次のものが含まれています。`6 * 10^9`隣接エントリ。 ダイクストラは、1 秒の制限をはるかに超える数十億の頂点とエッジを検査する必要があります。 

重要な観察は、ディマが乗り換えできるのは 3 つの固定された駅のペアのみであるということです。 このような重要な 2 つの駅の間では、何も興味深いことは起こりません。利用できる地下鉄路線は 1 つだけで、その路線上の 2 つの位置間の移動には、駅の距離とその路線の移動時間の積に等しい固定コストがかかります。 

1号線上の連続する2つの重要駅を駅とする`p`そして`q`。 それらの間のすべてのステーションを表す代わりに、これら 2 つのエンドポイントだけを表し、それらをコストの 1 つの重み付きエッジで接続することができます。`|p - q| * t1`。 

ラインのその部分に沿った移動にはまさにこのコストがかかるため、中間ステーションは最短経路の計算に情報を提供しません。 

各路線について必要なのは、その 2 つのインターチェンジ終点と、その駅が路線上にある場合の始点駅または終点駅だけです。 したがって、各ラインは最大 4 つの頂点に寄与します。 3 つの線すべてにわたって、圧縮されたグラフには最大 12 個の頂点があります。 

これらの頂点が重み付けされた線分と 3 つの転送エッジによって接続されると、元の問題はまさにこの小さなグラフ上の最短経路問題になります。 ディクストラは十分すぎるほど速い。 

この強引な方法は、考えられるすべての動きを正確にモデル化するため機能しますが、それらのステーションのほとんどすべてがルートの選択に無関係であるため、失敗します。 ルートの構造を変更できるのは乗換駅と 2 つの終点だけであるという観察により、数十億の通常の頂点を最大 12 個の意味のある頂点に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O((x+y+z) log(x+y+z))`|`O(x+y+z)`| 遅すぎる |
 | 最適 |`O(1)`|`O(1)`| 承認済み |

 圧縮されたグラフには最大 12 個の頂点と一定数のエッジが含まれるため、最適な複雑さは技術的に一定です。`x`、`y`、 そして`z`。 

## アルゴリズムのチュートリアル

 1. 各路線の重要駅のセットを作成します。 1号線の乗換駅は以下の通りです。`a`そして`a + 1`。 2 行目では、次のようになります。`b`そして`b + 1`。 3 行目では、次のようになります。`c`そして`c + 1`。 また、それぞれの路線に出発駅と目的駅を入力します。 

出発地または目的地自体が乗換駅と一致する可能性があるため、セットを使用します。 このようなステーションは、圧縮グラフ内に 1 回だけ出現する必要があります。 
2. 1 つのグラフ頂点をすべてのグラフ頂点に割り当てます。`(line, station)`これらのセットでペアリングします。 

1 行に最大 4 つの位置があるため、圧縮された頂点は最大 12 個になります。 実際のステーション番号は依然として次のように大きくなる可能性があります。`10^9`ただし、通常の整数ラベルとしてのみ保存されます。 
3. 各路線の重要な駅番号を並べ替えます。 

連続するポジションのペアごとに`p`そして`q`直線上に、ウェイト付きの無向エッジを追加します`abs(p - q) * t`、 どこ`t`はその路線の移動時間です。 

路線の一部に入場し、最終的には出発する旅行者には、無関係な中間駅を訪問する有益な理由はないため、連続する重要な駅を接続するだけで十分です。 セグメント全体の出張費は固定です。 
4. 3 つの転送エッジを追加します。 1号線駅を接続`a`2号線駅あり`b + 1`、1号線駅`a + 1`3号線駅あり`c`、2号線駅`b`3号線駅あり`c + 1`。 これらのエッジのそれぞれに重みを与えます`d`。 

これらはまさに Dima が行を変更できる合法的な場所であるため、圧縮されたグラフはあらゆる可能な転送を保存します。 
5. 開始頂点から Dijkstra を実行します。 

すべてのエッジには正の重みがあるため、ダイクストラは圧縮されたすべての頂点に最小移動時間を与えます。 重要ステーション セットに明示的に挿入したため、宛先はこれらの頂点の 1 つになります。 
6. 宛先頂点の距離を返します。 

結果として得られる最短パスは 1 つの路線上に留まるか、1 つのインターチェンジを使用するか、または複数の乗り換えを行う可能性があります。 圧縮されたグラフでは、一時的に低速または高速の回線を使用して元の回線に戻るルートなど、これらすべての可能性が可能になります。 

### なぜ効果があるのか

 元の地下鉄システムの有効なルートを考えてみましょう。 ルートが路線を変更するたびに、6 つのインターチェンジ エンドポイントのいずれかを訪問する必要があります。 また、明示的に含まれるエンドポイントで開始および終了します。 このような重要な駅の間では、路線は 1 つの路線上にあり、その路線に沿って直接区間を移動するのが最も安価な方法です。 圧縮されたグラフには、そのセグメントとその移動コストが正確に含まれます。 したがって、すべての有効な元のルートは、圧縮グラフ内に同じコストまたはより低いコストのルートを持ちます。 

逆に、圧縮されたグラフ内のすべてのエッジは、地下鉄路線の実際のセグメント、または 3 つの合法的な乗り換えのいずれかを表します。 したがって、圧縮されたすべてのルートを、まったく同じコストで有効な地下鉄ルートに拡張できます。 したがって、2 つのグラフは同じ最短経路距離を持ち、ダイクストラは必要な答えを返します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve(reader=input):
    x, y, z = map(int, reader().split())
    a, b, c = map(int, reader().split())
    t1, t2, t3, d = map(int, reader().split())
    k, i, l, j = map(int, reader().split())

    sizes = [x, y, z]
    times = [t1, t2, t3]

    # Important station positions on each line.
    special = [set(), set(), set()]

    # Interchange endpoints.
    special[0].add(a)
    special[0].add(a + 1)

    special[1].add(b)
    special[1].add(b + 1)

    special[2].add(c)
    special[2].add(c + 1)

    # Start and destination.
    special[k - 1].add(i)
    special[l - 1].add(j)

    # Assign compressed graph ids.
    node_id = {}
    vertices = []

    for line in range(3):
        for pos in sorted(special[line]):
            node_id[(line, pos)] = len(vertices)
            vertices.append((line, pos))

    n = len(vertices)
    graph = [[] for _ in range(n)]

    def add_edge(u, v, w):
        graph[u].append((v, w))
        graph[v].append((u, w))

    # Connect consecutive important stations on each metro line.
    for line in range(3):
        positions = sorted(special[line])
        for p, q in zip(positions, positions[1:]):
            u = node_id[(line, p)]
            v = node_id[(line, q)]
            weight = (q - p) * times[line]
            add_edge(u, v, weight)

    # Add the three legal interchanges.
    transfers = [
        ((0, a), (1, b + 1)),
        ((0, a + 1), (2, c)),
        ((1, b), (2, c + 1)),
    ]

    for left, right in transfers:
        u = node_id[left]
        v = node_id[right]
        add_edge(u, v, d)

    start = node_id[(k - 1, i)]
    target = node_id[(l - 1, j)]

    INF = 10**30
    dist = [INF] * n
    dist[start] = 0

    pq = [(0, start)]

    while pq:
        cur_dist, u = heapq.heappop(pq)

        if cur_dist != dist[u]:
            continue

        if u == target:
            return cur_dist

        for v, weight in graph[u]:
            new_dist = cur_dist + weight
            if new_dist < dist[v]:
                dist[v] = new_dist
                heapq.heappush(pq, (new_dist, v))

    return dist[target]

if __name__ == "__main__":
    print(solve())
```実装の最初の部分では、3 つの回線の長さと速度を記録し、重要なステーション セットを作成します。 交換エンドポイントは、次を使用して明示的に挿入されます。`a`、`a + 1`、`b`、`b + 1`、`c`、 そして`c + 1`。 これは、オフバイワンエラーのほとんどが発生する場所であるため、転送ペアは間接的に再構築されるのではなく、後で直接書き込まれます。 

の`node_id`辞書は、次のような論理的な地下鉄駅をマップします。`(1, a)`小さなグラフインデックスに。 接続する前に位置を並べ替えることで、通常のステーションの間隔全体が 1 つの重み付けされたエッジに変わります。 ポジションの場合`p`そして`q`重要局が連続している場合、`q - p`隣接する列車の移動のため、コストは`(q - p) * times[line]`。 

転送エッジのコストはステーションの距離に比例しないため、転送エッジは個別に追加されます。 それぞれに正確なコストがかかります`d`、2つの駅の位置に関係なく。 

その後、ダイクストラは圧縮されたグラフ上でのみ動作します。 古いエントリのチェック`if cur_dist != dist[u]`これは、より適切なルートがすでに見つかった後に古い距離を処理することを回避する標準のヒープ実装の詳細です。 早期復帰のとき`u == target`ダイクストラは距離が減少しない順序でヒープから頂点を削除するため、安全です。 

Python の整数には任意の精度があるため、次のような乗算が可能です。`(q - p) * times[line]`オーバーフローすることはできません。 両方の要素が次のように大きくなる可能性があるため、これはここで役立ちます。`10^9`。

 最小サイズのケースは、```

1 1 1 1
