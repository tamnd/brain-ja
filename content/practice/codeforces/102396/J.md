 ## 解決策
 ## 問題の理解

 施工は順番から始まります`[1]`。 オーダーから移動するには`m`注文する`m+1`、あらゆる長さをスキャンします -`m`現在のシーケンスのウィンドウ。 このようなウィンドウが次の順列である場合は常に、`1..m`、新しい値を挿入します`m+1`ウィンドウの直後に同じ順列が続きます。 

結果のシーケンスには、長さとしてすべての順列が 1 回だけ含まれます。`m`ウィンドウ。 課題は、この膨大なシーケンスを構築することではありません。 代わりに、特定の順列に対して`a`の`1..n`、その一意の出現が始まる、1 から始まるインデックスの位置、モジュロが必要です。`10^9+7`。 公式ステートメントでは、同じ再帰的構造と同じ境界が与えられています。`n <= 300000`。 

制約`n <= 300000`超順列を明示的に構築するもの、またはその順列を列挙するものはすべて除外されます。 その長さは

 [
 |s_n|=1!+2!+\cdots+n!,
 ]

 だから保管しても`s_n`不可能です。 ソリューションは、指定された順列をほぼ線形に処理する必要があります。`O(n log n)`時間と使い方`O(n)`メモリ。 1 秒の制限により、`O(n log n)`実装は厳密に保つ価値がありますが、関連するものはすべて`n!`仕事はまったく手の届かないところにあります。 

よくある間違いを明らかにするいくつかの特殊なケースがあります。 のために`n=1`、唯一の入力は`[1]`、そして答えは`1`。 以前の空でない置換を前提とした再帰は、ここでは失敗します。 のために`n=2`、順列`[2,1]`位置から始まります`2`で`s_2=[1,2,1]`、 その間`[1,2]`位置から始まります`1`。 これにより、最大要素の寄与におけるオフバイワンエラーが捕捉されます。 最大値が最後にある場合、たとえば`[2,3,1,4]`、その挿入は基礎となる順列の後に行われますが、ターゲット自体はその挿入の前に開始することができます。 すべての出現箇所を挿入された箇所から始まるものとして扱う`4`間違った答えをする`9`の代わりに`6`。 最後に、入力は値が順列を形成することを保証するため、次のようなすべてが等しい入力になります。`3 / 1 1 1`は有効なテスト ケースではないため、提出されたソリューションのテストに使用してはなりません。 

## アプローチ

 直接的な解決策では、シーケンスが構築されます。`s_1,s_2,...,s_n`。 ステージにて`m`、すべての長さを検査する必要があります-`m`ウィンドウを開き、そこに次のすべての値が含まれているかどうかを判断します。`1`を通して`m`。 すでにあります`Theta(m!)`その段階での位置を確認し、1 つのウィンドウを単純にチェックすると、`Theta(m)`時間。 最終段階だけでも費用がかかる`Theta(n * n!)`最悪の場合の操作が必要になるだけでなく、`Theta(n!)`シーケンスを保存するためだけのメモリです。 と`n=300000`、これは遠隔的には実現可能ではありません。 

すべての挿入はローカルであるため、ブルート フォースが機能します。 順列の場合`q`サイズの`m-1`で発生します`s_{m-1}`、建設用インサート`[m,q]`その直後。 これは正確に作成します`m`連続サイズ-`m`その挿入の周りの順列。 有益な観察は、これらは`m`順列は単なる循環回転です`q`と`m`異なる位置に挿入されます。 

現在の順列が次であると仮定します。`p`、および最大値`m`の位置で発生します`k`。 取り除く`m`残りのシーケンスを回転して、要素が直後に配置されるようにします。`m`最初の要素になります。 結果の順列を呼び出します`q`。 それから`q`まさにそのサイズです -`m-1`挿入により作成される順列`p`。 

もう一つ必要な数量があります。 させて`R_m(p)`のゼロベースのランクになります`p`の間で`m!`出現順に並べたもの`s_m`。 もし`q`ランクがある`R_{m-1}(q)`、そのすべて`m`導出された順列は 1 つの連続したグループを形成します。 の位置`p`このグループの中には`m-k`、 なぜなら`m`位置にあります`k`。 したがって、

 [
 R_m(p)=mR_{m-1}(q)+(m-k)。 
]

 実際の位置にはさらに単純な漸化式があります。 グループの前に`q`、サイズの以前のすべての順列`m-1`の挿入を引き起こした`m`要素なので、`q`によってシフトされます`mR_{m-1}(q)`ポジション。 ターゲットが始まります`m-k`開始位置よりも後の位置`q`。 したがって、

 [
 P_m(p)=P_{m-1}(q)+R_m(p)。 
]

 から始まる`P_1=1`したがって、最終的な答えは次のようになります。 

[
 P_n=1+\sum_{m=2}^{n}R_m。 
]

 残りの課題はすべての値を取得することです`m-k`すべてのレベルで順列を明示的に回転させる必要はありません。 

回転は円上できれいに解釈されます。 元の順列を循環リストとして開始します。 最大処理時`m`、より大きな値はすべてすでに削除されており、現在の線形置換は、以前に削除された最大値の直後から始まります。 削除中`m`これは、次に生き残った要素が新しい開始点になることを意味します。 したがって`m-k`は、現在有効なポジションの正確な数です。`m`現在の開始前に周期的に測定されます。 

フェンウィック ツリーは、元の位置がまだ生きていることを維持します。 二重リンクリストは、ポジションが削除されたときに現在の循環後続リストを維持します。 一緒に、あらゆることを計算できるようにします。`m-k`で`O(log n)`時間。

### なぜ効果があるのか

 どのサイズでも`m`、ターゲットの順列から最大値を削除し、正確な順列を生成した後で回転します。`q`その挿入によりターゲットが生成されました。 構築はサイズの発生を処理します`m-1`左から右へ、そのような出現ごとに、正確に 1 つの連続したグループが生成されます。`m`サイズ-`m`順列。 そのグループ内で、位置が最大になる順列`k`です`(m-k)`-番目のメンバーなので、`R_m=mR_{m-1}+(m-k)`。 以前のグループは、対応するオカレンスを正確にシフトします。`m`それぞれに位置を与え、`P_m=P_{m-1}+R_m`。 循環リンク リストは、現在の最大値を繰り返し削除し、その直後から開始することによって得られたシーケンスを正確に表します。一方、フェンウィック ツリーは、その残りの要素を数えます。 したがって、すべての`d_m=m-k`繰り返しによって使用される位置は正確であり、最終的に蓄積された位置は必須のオカレンスです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, x in enumerate(a, 1):
        pos[x] = i

    # Fenwick tree containing 1 for every currently alive position.
    bit = [0] * (n + 1)

    # Build the Fenwick tree in O(n).
    for i in range(1, n + 1):
        bit[i] += 1
        j = i + (i & -i)
        if j <= n:
            bit[j] += bit[i]

    def prefix(x):
        s = 0
        while x:
            s += bit[x]
            x -= x & -x
        return s

    def remove(x):
        while x <= n:
            bit[x] -= 1
            x += x & -x

    # Circular doubly linked list of alive positions.
    nxt = [0] * (n + 1)
    prv = [0] * (n + 1)

    for i in range(1, n + 1):
        nxt[i] = i + 1 if i < n else 1
        prv[i] = i - 1 if i > 1 else n

    # d[m] = m - position_of_m_in_the_current_permutation.
    d = [0] * (n + 1)

    start = 1

    for m in range(n, 1, -1):
        x = pos[m]

        px = prefix(x)

        if start <= x:
            d[m] = m - px
        else:
            d[m] = prefix(start - 1) - px

        # Remove x and rotate the remaining circular order so
        # that its successor becomes the new first position.
        nx = nxt[x]
        p = prv[x]

        nxt[p] = nx
        prv[nx] = p
        start = nx

        remove(x)

    rank = 0
    answer = 1

    for m in range(2, n + 1):
        rank = (m * rank + d[m]) % MOD
        answer += rank
        if answer >= MOD:
            answer -= MOD

    print(answer)

if __name__ == "__main__":
    solve()
```の`pos`配列により、下降フェーズで一定時間内の現在の最大値を見つけることができます。 フェンウィック ツリーには、まだ削除されていない値ごとに 1 つの単位が含まれているため、その接頭辞の合計は、元の順列の間隔内に残っている要素の数を表します。 

リンクされたリストは別の理由で必要になります。 現在の順列は、左側または右側からいくつかのエントリが削除された元の配列ではありません。 これは、最大値が削除されるたびに開始点が変化する円状の回転です。`start`その回転を記録し、`nxt`そして`prv`削除後一定時間で更新します。 

の表現`d[m]`現在のサイズを使用して意図的に書き込まれています`m`。 取り外す前に`m`、 その通り`m`ポジションは生きています。 いつ`start <= x`、後の要素`x`ラップする前は、ラップ後のすべての生きている要素だけです`x`、つまり`m-prefix(x)`。 いつ`start > x`、関連する間隔は折り返されないため、2 つのプレフィックスの合計の差が必要になります。 

2 番目のパスでは、最小サイズから最大サイズまでランクが再構築されます。`rank`店`R_{m-1}`アップデート前となります`R_m`を掛けた後`m`そして追加`d[m]`。 答えはから始まります`P_1=1`、その後、ちょうど 1 つの貢献を受け取ります`R_m`各レベルで。 

Python の整数はオーバーフローしませんが、反復のたびに法を取得すると、値が小さく保たれ、不必要な大きな整数の演算が回避されます。 フェンウィック ツリー自体には、次の値のみが保存されます。`n`、そのため、そのエントリが大きくなることはありません。

 ## 特殊なケース

 のために`n=1`、入力は正確に`[1]`。 ループは次の時点で開始されるため、最大除去ループはありません。`m=2`。 ランクは 0 のままで、答えは初期値のままです。`1`、まさに の位置です。`[1]`で`s_1`。 

のために`n=2`そして順列`[2,1]`、現在の開始位置は`1`そして最大の`2`位置にもあります`1`。 フェンウィック ツリーは、位置の後に 1 つの生き残った要素を報告します`1`、 それで`d_2=1`。 ランクは、`R_2=1`、そして答えは次のようになります`1+1=2`。 これは一致します`s_2=[1,2,1]`。 

最初の位置での最大値については、次のことを考慮します。`[3,1,2]`。 最大`3`もっている`k=1`、 それで`d_3=2`。 削除後、残りの注文は から始まります`1`。 サイズ 2 では、最大`2`最後に、与えています`d_2=0`。 したがって`R_2=0`、`R_3=2`、そして答えは`1+0+2=3`。 確かに、`[3,1,2]`位置から始まります`3`で`s_3`。 

最後の位置での最大値については、`[2,3,1,4]`もっている`d_4=0`、なぜなら、`4`の位置で発生します`4`。 次のレベルには、`d_3=1`、それは与える`R_3=1`その後`R_4=4`。 最終的な順位は、`1+0+1+4=6`。 ターゲットは位置から始まります`6`、挿入される前に`4`したがって、常に最大値の位置を探すアルゴリズム自体は正しくありません。 

円形のラップアラウンドの場合、`[4,3,1,2]`は特に便利です。 最大`4`最初はその位置にあります`1`、 それで`d_4=3`。 外すと位置が決まります`2`新たなスタート。 次の最大値`3`も新たな 1 番目の位置にあり、`d_3=2`。 ついに`d_2=0`。 ランクは`R_2=0`、`R_3=2`、 そして`R_4=11`、したがって、答えは次のとおりです`1+0+2+11=14`。 リンクされたリストは、順列を物理的に回転させるのではなく、このラップアラウンド動作を明示的にするものです。 

次のようなすべて等しい入力`[1,1,1]`からのすべての値が保証される入力保証に違反します。`1`を通して`n`は 1 回だけ発生します。 アルゴリズムは構築時にその保証に依存します。`pos`、現在の最大値を解釈するとき、および値ごとに 1 つの位置を正確に削除するとき。 したがって、これは必要な解決策の特殊なケースではなく、無効な問題のインスタンスになります。
