 ## 解決策
 ## 問題の理解

 正の整数から開始します$x$。 各ステップで、古典的な Collat​​z 変換を適用します。 

現在の値が奇数の場合は、$3x+1$。 

現在の値が偶数の場合は、$x/2$。 

課題は、永遠にシミュレーションすることではありません。 必要なのは、値が最初にちょうど 1 になるまでに必要な操作の数だけです。このステートメントは、すべてのテスト データについて、シーケンスが最終的に 1 に達し、答えが 1000 より小さいことを保証します。 

入力には単一の整数が含まれています$x$、出力は 1 に到達するために必要な演算の最小数を表す単一の整数です。 

アルゴリズムの観点から見ると、制約は非常に小さいです。 初期値は最大でも$2^{31}-1$、そしてステートメントはさらに、すべての中間値もその範囲内にあることを保証します。 答えは 1000 未満であることが保証されているため、直接シミュレーションで実行される反復回数は 1000 未満です。 たとえ$O(\text{answer})$解は事実上一定時間です。 

最も重要なエッジケースは、入力がすでに 1 である場合です。 

たとえば:```
Input:
1
```正しい出力は次のとおりです。```
0
```値がすでに 1 に等しいため、操作は必要ありません。チェックする前に常に 1 つの変換を実行する不注意な実装では、誤って 1 が出力されます。 

もう 1 つの微妙なケースは、1 回の操作の直後に 1 に達するシーケンスです。 

例えば：```
Input:
2
```順序は次のとおりです。```
2 -> 1
```答えは 1 です。値が 1 になったときに停止し、最後の操作をカウントするのを忘れた場合、誤って 0 が出力されます。 

3 番目のケースには奇数が含まれます。 

例えば：```
Input:
3
```順序は次のとおりです。```
3 -> 10 -> 5 -> 16 -> 8 -> 4 -> 2 -> 1
```答えは 7. 誤って計算する実装$3x-1$または、整数の除算を誤って実行すると、まったく異なる軌道が生成されます。 

## アプローチ

 最も直接的なアイデアは、説明どおりにプロセスを正確にシミュレートすることです。 指定された値から開始して、パリティに基づいて対応するルールを繰り返し適用し、実行された操作の数をカウントします。 値が 1 になるとすぐにカウントを停止して出力します。 

この強引な方法はすでに十分です。 シーケンスの長さは 1000 未満であることが保証されているため、最大 999 個の変換が実行されます。 各変換は、パリティ チェックと単純な算術演算で構成されます。 総作業量はわずかです。 

状態遷移の繰り返しを伴う問題の多くは、サイクル検出、メモ化、グラフ手法、または数学的ショートカットを必要とします。 ここでは、ステートメントがシーケンスが 1 に到達することを明示的に保証しており、非常に少数のステップ内で到達するため、これらはいずれも必要ありません。 制約の構造から、単純なシミュレーションがまさに意図したソリューションであることがわかります。 

したがって、最適なソリューションは同じシミュレーションです。 現在の値が 1 になるまで繰り返し変換し、変換の回数をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t) | お(1) | 承認済み |
 | 最適 | O(t) | お(1) | 承認済み |

 ここ$t$は 1 に達するまでの操作の数を示し、ステートメントは次のことを保証します。$t < 1000$。 

## アルゴリズムのチュートリアル

 1. 初期値を読み出す$x$。 
2. カウンタの初期化`ans = 0`。 
3. While`x != 1`、コラッツ操作を 1 回実行します。 

もし`x`奇数なので、次のように置き換えます`3 * x + 1`。 

Otherwise, replace it with`x // 2`。 
4. After applying the operation, increase`ans`ちょうど 1 つの変換が実行されたため、1 ずつ増えます。 
5. いつ`x`becomes 1, stop the loop.
 6. 出力`ans`。 

### なぜ効果があるのか

 ループは、問題で定義されたプロセスを正確に再現します。 各反復は 1 つの正当な操作に対応し、カウンターが 1 つずつ増加します。 現在の値`x`後$k$iterations は、変換を適用した後に得られる値です。$k$初期状態から 3 倍。 

ループは最初の瞬間に終了します。`x`カウンタはそれまでに実行された操作の数を記録するため、終了時の値は 1 に達するために必要な操作の最小数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input())

ans = 0

while x != 1:
    if x % 2:
        x = 3 * x + 1
    else:
        x //= 2
    ans += 1

print(ans)
```プログラムは初期値を読み取ることから始まります。 

変数`ans`適用された変換の数を保存します。 現在の値が 1 になるまでループが続きます。 

ループ内では、パリティによってどのルールを使用するかが決まります。 奇数の場合は計算します`3 * x + 1`。 偶数の場合は、整数の 2 による除算を使用します。 変換を実行した後、1 つの操作が完了したため、カウンターがインクリメントされます。 

順序は重要です。 まず操作を適用してから、カウンターをインクリメントします。 これにより、新しい値を生成した変換が正しくカウントされます。 ループ条件`x != 1`入力がすでに 1 である特殊なケースも正しく処理し、0 の応答を生成します。 

このステートメントは、中間値が 32 ビット範囲内に収まることを保証しますが、Python の整数はいずれにせよ、はるかに大きな値を処理できるため、オーバーフローが心配されることはありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    x = int(input())
    ans = 0

    while x != 1:
        if x % 2:
            x = 3 * x + 1
        else:
            x //= 2
        ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# custom tests
assert run("1\n") == "0\n", "already at target"
assert run("2\n") == "1\n", "single operation"
assert run("4\n") == "2\n", "power of two"
assert run("6\n") == "8\n", "sample-style trace"
assert run("3\n") == "7\n", "odd-number chain"
