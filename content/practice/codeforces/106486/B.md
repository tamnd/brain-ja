 ## 解決策
 ## 問題の理解

 1 から 1 までの位置の直線パスに沿って移動するロボット猫が与えられています。$n+1$。 時刻 0 の位置 1 から開始し、位置に到達したいと考えています$n+1$。 次の位置に移動するたびに、ちょうど 1 単位の時間が消費されます。 

エネルギーは重要な制約です。 猫はから始まります$E$エネルギー。 単位時間ごとに、そのシステムは動作を維持するためだけに 1 エネルギーを消費します。 さらに、その単位時間内に行動を行うたびに、追加のエネルギーを 1 消費します。 したがって、その場に留まるには単位時間あたり 1 エネルギーがかかり、位置を前進させると同時に前進する場合には単位時間あたり 2 エネルギーがかかります。 

各中間位置で$i$1から$n$、エネルギーステーションは1つあります。 駅$i$一定の時間間隔の間のみアクティブになります$[l_i, r_i]$、猫がその位置にいる場合$i$ある整数時間で$t$この間隔内で、ステーションを 1 回だけアクティブ化して獲得することを選択する場合があります。$a_i$エネルギー。 各ステーションは最大 1 回まで使用できます。 

猫は前に進むことも、現在の位置で待つこともできます。 ただし、エネルギーがゼロまたはマイナスになると、たとえその瞬間が駅や最終地点に到達した瞬間であっても、すぐに壊れて旅は失敗します。 

タスクは、位置に到達するために必要な最小時間を決定することです$n+1$エネルギーをゼロ以下に下げることはありません。 無理ならアウトプットするしかない$-1$。 

入力サイズは十分小さいため、位置全体にわたる線形または線形に近いシミュレーションが可能です。 と$n \le 5000$までの時間枠$10^4$、二次方程式の解$n$境界線にありますがまだ許容されますが、位置と時間の両方にわたる完全な状態空間を含むものは大きすぎます。 

駅の窓口に合わせて「貪欲に待とう」とすると、微妙な失敗例が発生します。 待機すると時間がかかりますが、エネルギーも削減されるため、将来の実現可能性の条件が厳しくなります。 駅が開くまで常に待つというのは甘い考えですが、それでは猫が必要以上に早くエネルギーを使い果たしてしまう可能性があります。 

もう 1 つの微妙なケースは、ステーションの収集を遅らせることが有害である可能性を考慮せずに、ステーションを収集することが常に実現可能性に役立つと仮定することです。 たとえば、ステーションが遅くまで開局した場合、それを待つことで得られる利益よりも多くのエネルギーがかかる可能性があります。 

## アプローチ

 ブルートフォースの観点では、猫の位置、時間、エネルギーを追跡しながら、猫が移動したり待機したりできるすべての可能な方法を時間の経過とともにシミュレートします。 あらゆるステップで、前進することも停止することもでき、ステーションの範囲内にあるときは常に、それを受け取ることもあれば受け取らないこともあります。 これにより、巨大な状態空間が生じます。$(position, time, energy)$。 まで時間を離散化しても$10^4$、状態の数は のオーダーになります。$n \cdot time \cdot energy$、これは 1 秒で処理できる量をはるかに超えています。 

重要な観察は、収集されたステーションの順序と移動スケジュールを決定すると、エネルギーが決定論的に進化するということです。 時間は常に位置と密接に関係しています。移動するたびに位置が 1 増加し、正確に 1 単位の時間を消費します。 待機しても位置は変わりませんが、エネルギーを消費します。 これにより、エネルギーが減少する一方、将来の位置に到達するための構造的制約は改善されないため、ほとんどの状況で待機が厳密に支配的になります。 

便利な単純化は、到達位置に注目することです。$i$時に$t$待たずに与える$t = i - 1$。 待ち時間が増える$t$、しかし、エネルギーはまったく同じ量だけ減少し、将来の生存が厳密に困難になります。 したがって、待機戦略は、他の方法では到達できないステーションを収集できるようにしない限り、実現可能性を損なうだけであり、その利益さえも、到着時にステーションが使用可能かどうかをチェックすることですでに考慮されています。 

したがって、問題をパスに沿った直線シミュレーションに縮小し、常に即座に前進し、到着時にアクティブなステーションを収集することができます。 残る唯一の問題は、この決定論的な歩行中にエネルギーがゼロ以下に低下するかどうかです。

 ## アルゴリズムのチュートリアル

 1 から 1 までの位置を処理します$n$現在の時間とエネルギーを維持しながら。 

1.初期化時間$t = 0$そしてエネルギー$E_{cur} = E$。 また、収集されたステーションのエネルギーの累計も維持します。 
2. ポジションごとに$i$1から$n$、すぐにそれに移ります。 つまり、時間は次のようになります。$t = i - 1$。 
3. 位置で$i$、ステーションがその時点でアクティブであるかどうかを確認します$t$、 意味$l_i \le t \le r_i$。 アクティブな場合は、そのエネルギーを一度収集して追加します。$a_i$に$E_{cur}$。 
4. 可能な限り回収した後、現時点で猫が生存しているかどうかを確認します。 それまでに費やしたエネルギー$t$含まれています$t$時間の消費と別のことから$i-1$移動コストから、生存条件は$E_{cur} > 2t$。 これが失敗した場合は終了して戻ります$-1$。 
5. すべての位置が正常に処理されると、猫は位置に到達します$n+1$時に$n$ので、出力します$n$。 

待機を無視する背後にある理由は、遅延は時間とエネルギー消費の両方を等しく増加させるが、時間と位置の構造的な関係は改善しないということです。 生存は線形結合に依存するため$E_{cur} - (time + moves)$、不必要に時間を増やすと、実現可能性が大幅に低下します。 

### なぜ効果があるのか

 位置で$i$、最も早い到着時間は次のように固定されています。$i-1$、そしていかなる逸脱もエネルギーを減らしながら時間を増やすだけです。 実現可能条件は時間に単調に依存するため、遅延によってステーション収集が可能にならない限り、不可能な状態を可能な状態に変えることはできませんが、ステーション収集自体は、到着時に一定の間隔内にあるかどうかにのみ依存します。 したがって、すべての有益なコレクションを取得するには、最も早い到着時間にステーションのアクティブ化をチェックするだけで十分であり、待機戦略は即時の移動によって支配されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, E = map(int, input().split())
    stations = []
    for _ in range(n):
        a, l, r = map(int, input().split())
        stations.append((a, l, r))

    cur_energy = E

    for i in range(1, n + 1):
        t = i - 1

        a, l, r = stations[i - 1]
        if l <= t <= r:
            cur_energy += a

        if cur_energy <= 2 * t:
            print(-1)
            return

    print(n)

if __name__ == "__main__":
    solve()
```このコードは、唯一の関連タイムライン (位置ごとに 1 ステップ) を直接シミュレートします。 時間変数は暗黙的に次のようになります。$i-1$。 各ステップでは、まず現在の到着時刻にステーションが使用できるかどうかを確認し、次にエネルギーを更新し、最後に生存を確認します。 

よくある落とし穴は、チェックと収集の順序を逆にしてしまうことです。 「エネルギーがゼロになるとすぐに失敗する」という条件は、収集後、続行する前にチェックを行う必要があることを意味します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、到着時刻にちょうど駅が開く場合です。$t = i-1$。 この状況では、エネルギーはそのタイム ステップでのステーションの収集によって直ちに影響を受けるため、生存を確認する前にステーションをカウントする必要があります。 アルゴリズムはチェックすることでこれを正しく処理します。$l_i \le t \le r_i$生存条件の前。 

もう 1 つのケースは、エネルギーが次とまったく等しい場合です。$2t$。 エネルギーは厳密に正でなければならないというルールがあるため、平等は失敗です。 コードではこれを強制します`cur_energy <= 2 * t`即時終了につながります。 

最後のエッジ ケースは、非常に大きな$a_i$早い時間に表示されますが、到達可能な時間枠の外にあります。 たとえそれが大きくても、その間隔に確定的な到着時間が含まれていない限り使用することはできません。これにより、誤った過大カウントが防止されます。
