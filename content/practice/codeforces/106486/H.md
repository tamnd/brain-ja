 ## アルゴリズムのチュートリアル

 私たちは定義します$f[i]$有効な順序付きツリーの数として正確に$i$ノード。 サブツリー サイズに対する動的プログラミングを使用して、テスト ケースごとにこれを個別に計算します。 

### ステップ

 1. DP 配列を初期化する$f$長さの$n+1$すべてゼロで設定します$f[1] = 1$。 

これは単一ノード ツリーを表します。ルートには子がないため、常に有効です。 
2. 各サイズについて$i$から$2$に$n$、計算する$f[i]$考えられるすべての根次数を考慮して$d \in A$。 

ルートは 1 つのノードを使用するため、残りのノードは$i-1$ノードはそのノード間で分散されます。$d$子供たち。 
3.固定の場合$d$、分割する方法の数を計算します。$i-1$の中へ$d$順序付けされた部分。各部分はサブツリーのサイズに対応します。 

各部分は次の要因に寄与します$f[\cdot]$, したがって、これは次の係数になります。$x^{i-1}$で$F(x)^d$、 どこ$F(x) = \sum f[i] x^i$。 
4. シンボリックべき級数の代わりに、畳み込みを使用してこれを直接計算します。 現在の電力を表す補助配列を維持する$g_d$、 どこ$g_d[s]$合計サイズを形成する方法の数です$s$使用して$d$順序付けられたサブツリー。 
5. 構築する$g_d$繰り返し:

 から始める$g_0[0] = 1$、および各乗算に対して$F$、畳み込みを介して更新します。$$g_{t+1}[s] = \sum_{x=1}^{s} g_t[x] \cdot f[s-x]$$6. 計算後$g_d$、 追加$g_d[i-1]$の中へ$f[i]$許可されたすべての$d \in A$。 

### なぜ効果があるのか

 中心的な不変条件は次のとおりです$g_d[s]$常に正確に順序付けされたフォレストの数をカウントします。$d$根の生えた木の合計サイズは$s$、各コンポーネント ツリーは、次に従ってすでに有効です。$f$。 これにより、計算時に次のことが保証されます。$f[i]$、構造を推測しているのではなく、すでに正しい部分構造を体系的に構成しています。 すべての有効なツリーはルート次数と順序付けられたサブツリー サイズによる固有の分解を持っているため、すべての構成は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        A = list(map(int, input().split()))

        # dp[i] = number of trees with i nodes
        dp = [0] * (n + 1)
        dp[1] = 1

        # precompute convolution powers up to max degree needed
        # we will build dp incrementally
        for i in range(2, n + 1):
            total = 0

            for d in A:
                if d == 0:
                    continue
                # g[0] = 1, then convolve f (dp) with itself d times
                # we compute iteratively
                g = [0] * i
                g[0] = 1

                for _ in range(d):
                    ng = [0] * i
                    for s in range(i):
                        if g[s] == 0:
                            continue
                        for x in range(1, i - s):
                            if dp[x]:
                                ng[s + x] = (ng[s + x] + g[s] * dp[x]) % MOD
                    g = ng

                total = (total + g[i - 1]) % MOD

            dp[i] = total

        print(dp[n] % MOD)

if __name__ == "__main__":
    solve()

実装の微妙な詳細としては、次のものが除外されます。$x=0$畳み込みループ内のサブツリーのサイズ。 これが必要なのは、すべてのサブツリーに少なくとも 1 つのノードが含まれている必要があるためです。 ゼロを許可すると、空のツリーが誤ってカウントされ、結果が水増しされてしまいます。

def run(inp: str) -> str:

 ## 特殊なケース

 主なエッジケースは次のような場合です$A = \{0\}$。 すべてのノードには子が存在しない必要があるため、有効な構造は単一ノードのみです。 アルゴリズムはこれを正しく処理します。$d \neq 0$がいないため、それ以上の成長はありません$dp[1]$が発生します。 

もう一つのケースは次のような場合です。$n$は小さいですが、大きな次数が存在します$A$。 例えば、$n=3$、$A=\{0,2,5\}$。 次数 5 のオプションは、畳み込みのため無関係です。$i-1=2$十分なノードを分散できません。 有効な分割がないため、ループは当然寄与をゼロにし、特別なフィルタリングは必要ありません。 

最後に考えてみましょう$n=2$、$A=\{0,1,2\}$。 次数 2 は適用できるように思えるかもしれませんが、1 つのノードを 2 つの空ではないサブツリーに分割することは不可能です。 この場合、畳み込みは正しくゼロを生成し、実現可能性が手動ではなく構造的に強制されていることを示しています。
