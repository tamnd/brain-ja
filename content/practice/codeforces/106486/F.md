 ## 解決策
 ## 問題の理解

 長い一連のレベルが与えられ、各レベルには難易度が設定されています。 プレーヤーは、固定長の連続したブロックを 1 つだけ削除できます。$k$、そのブロックの外側にあるものはすべて残り、全体の難易度に影響します。 各変更後の目標は、残ったブロックの合計が最小になるように、削除する最適なブロックを選択することです。 

再構成すると、これは、配列のある点を更新した後、長さの連続する部分配列の最大合計は正確にいくらになるかを繰り返し尋ねることと同じです。$k$? その値がわかれば、答えは配列の合計からこの最大ウィンドウの合計を引いたものになります。 

入力は最大サイズの配列で始まります。$5 \times 10^5$、続いて最大$5 \times 10^5$ポイント更新。 各更新では単一の位置が永続的に変更され、すべての変更後 (初期状態を含む) に最適な結果を出力する必要があります。 

この制約により、更新ごとにほぼ線形またはほぼ線形の動作が強制されます。 更新ごとにウィンドウの合計を最初から再計算するものは、ただちに遅すぎます。1 回の再計算がすでに完了してしまうからです。$O(n)$、につながる$O(nm)$最悪の場合。 

各要素が複数の長さに関与していることを認識せずに、更新されたインデックスを中心にローカルでのみ再計算しようとすると、微妙な失敗のケースが発生します。$k$窓。 

たとえば、次の場合$k = 3$配列は次のとおりです。```
[1, 2, 3, 4, 5]
```ウィンドウの合計は次のとおりです。```
[1+2+3, 2+3+4, 3+4+5]
```位置 3 のような単一要素を更新すると、インデックス 3 を中心とするウィンドウだけでなく、ここにある 3 つのウィンドウすべてに影響します。単純なローカライズされた更新では、この重複構造が見逃され、不正確な最大値が生成されます。 

次の場合には、別のエッジケースが発生します。$k = n$。 この場合、ウィンドウは 1 つだけ存在し、全体の合計を減算した後の答えは常に 0 になります。 複数のウィンドウを想定した実装は、このケースが自然に処理されない限り壊れます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 更新するたびに、すべての長さを再構築します。$k$ウィンドウの合計を計算し、最大値をスキャンして、合計値からそれを減算します。 これは定義に直接従うため、正しいです。 ただし、各アップデートにはコンピューティングが必要です$n-k+1$ウィンドウ合計と各ウィンドウ合計コスト$O(k)$直接計算された場合、または$O(1)$プレフィックス合計の後でも必要です$O(n)$最大値の再計算。 と$m$アップデートすると、こうなります$O(nm)$、これは実現可能な限界をはるかに超えています。 

重要な点は、すべてのウィンドウを最初から再計算する必要がないということです。 各更新は、非常に構造化された一連のウィンドウに影響を与えます。 位置の場合$x$変更されると、左端が範囲内にあるウィンドウのみが変更されます$[x-k+1, x]$影響を受けています。 これは、ウィンドウの空間内の連続したセグメントです。 したがって、各更新は、すべてのウィンドウの合計を表す 2 次配列に対する範囲加算操作になります。 

問題を、ポイント更新時の配列の維持から別のサイズの配列の維持に変換します。$n-k+1$範囲更新とグローバル最大クエリの下で。 この構造はまさに、遅延伝播を備えたセグメント ツリーがサポートしているものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 更新ごとにすべてのウィンドウを再計算する |$O(nm)$|$O(n)$| 遅すぎる |
 | ウィンドウ合計上のセグメント ツリー |$O((n+m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、元の配列をすべての長さを追跡する構造に変換します。$k$ウィンドウの合計。 

1. 配列の合計を計算します。 これは値が変化するにつれて段階的に更新されるため、常に合計から最適なウィンドウを引いた値を使用して回答できます。 
2. 補助配列を構築する$S$どこ$S[i]$部分配列の合計を表します$a[i..i+k-1]$。 これは、スライディング ウィンドウを使用して線形時間で実行できます。 この配列には長さがあります$n-k+1$。 
3. セグメントツリーを構築します$S$。 各ノードはセグメントに最大値を格納し、範囲加算の遅延伝播をサポートします。 
4. 更新ごとに位置が変更されます$x$古い価値観から$v$新しい価値観へ$y$、差を計算します$\Delta = y - v$。 を追加して合計値を更新します$\Delta$。 
5. どのウィンドウにインデックスが含まれているかを判断する$x$。 で始まるウィンドウ$i$含まれています$x$もし、そしてその場合に限り$i \le x \le i+k-1$、これを再配置すると、$i \in [x-k+1, x]$。 この範囲を有効なウィンドウ インデックスにクランプします。 
6. の範囲加算を実行します。$\Delta$このウィンドウ インデックス範囲にわたるセグメント ツリー上で。 これにより、影響を受けるすべてのウィンドウ合計が対数時間で更新されます。 
7. 更新を適用した後、セグメント ツリーの最大値をクエリします。 これは、削除できる最適なウィンドウ合計です。 
8. total_sum からこの最大値を引いた値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、セグメント ツリーに格納されているすべてのウィンドウの合計が、現在の配列内の対応する部分配列の真の合計と常に等しいということです。 各ポイントの更新は、そのインデックスを含むウィンドウにのみ影響し、それらのウィンドウはウィンドウ インデックス空間内の連続した範囲を形成します。 範囲の追加はこのインフルエンス セットを正確に反映するため、ウィンドウが失われることはなく、無関係なウィンドウが変更されることもありません。 セグメント ツリーは、各更新後にすべてのウィンドウ合計の最大値が正しいことを保証するため、合計合計からそれを減算すると、最適な残りの値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.mx = [0] * (2 * self.size)
        self.lz = [0] * (2 * self.size)

        for i in range(self.n):
            self.mx[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.mx[i] = max(self.mx[2 * i], self.mx[2 * i + 1])

    def _apply(self, i, v):
        self.mx[i] += v
        self.lz[i] += v

    def _push(self, i):
        if self.lz[i]:
            v = self.lz[i]
            self._apply(2 * i, v)
            self._apply(2 * i + 1, v)
            self.lz[i] = 0

    def _add(self, i, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self._apply(i, v)
            return
        self._push(i)
        mid = (l + r) // 2
        if ql <= mid:
            self._add(2 * i, l, mid, ql, qr, v)
        if qr > mid:
            self._add(2 * i + 1, mid + 1, r, ql, qr, v)
        self.mx[i] = max(self.mx[2 * i], self.mx[2 * i + 1])

    def add(self, l, r, v):
        if l <= r:
            self._add(1, 0, self.size - 1, l, r, v)

    def max_all(self):
        return self.mx[1]

n, m, k = map(int, input().split())
a = list(map(int, input().split()))

total = sum(a)

if k == n:
    base = 0
    for _ in range(m + 1):
        print(0)
    sys.exit()

S = []
window = sum(a[:k])
S.append(window)
for i in range(k, n):
    window += a[i]
    window -= a[i - k]
    S.append(window)

seg = SegTree(S)

out = []
for _ in range(m + 1):
    if _ > 0:
        x, y = map(int, input().split())
        x -= 1
        total += y - a[x]
        delta = y - a[x]

        l = x - k + 1
        r = x

        l = max(l, 0)
        r = min(r, n - k)

        seg.add(l, r, delta)

        a[x] = y

    out.append(str(total - seg.max_all()))

print("\n".join(out))

 このソリューションでは、元の配列ではなく、ウィンドウ合計に対して別のセグメント ツリーが維持されます。 最もデリケートな部分は、ポイント更新をウィンドウ インデックスの範囲更新に正しくマッピングすることです。 境界$x-k+1$に$x$外側には窓がないため、慎重にクランプする必要があります$[0, n-k]$。 ここでのオフバイワンミスが最も一般的なエラーの原因です。 

遅延伝播構造により、各更新は変更のみを行うため、繰り返される重複更新の効率性が維持されます。$O(\log n)$ノード。 

特別な場合$k = n$ウィンドウ構造を単一の間隔に折りたたむため、ウィンドウ構造を削除すると常にゼロが残ります。

 ## 特殊なケース

 いつ$k = n$、ウィンドウ空間は配列全体をカバーする単一の間隔に折りたたまれます。 更新のたびに合計と唯一のウィンドウ合計の両方が等しく変更されるため、それらの差は全体を通じてゼロのままになります。 アルゴリズムは当然のことながら、即座にゼロを返すことでこれを処理します。 

更新が境界付近で発生した場合、たとえば、$x < k$または$x > n-k$、計算されたウィンドウ インデックス範囲の一部が有効なインデックスの範囲外になります。 クランプにより、実際のウィンドウのみが更新され、無効なセグメント ツリー範囲には触れなくなります。 これにより、特別な大文字と小文字を区別しなくても正確さが保たれます。 

すべての値が等しい場合、すべてのウィンドウ合計は同一になります。 各更新では、影響を受けるすべてのウィンドウが同じ量だけシフトされ、セグメント間の均等性が維持されます。 セグメント ツリーは均一な最大値を維持するため、どのウィンドウも同様に最適であり、更新しても答えは安定したままになります。
