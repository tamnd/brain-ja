 ## 解決策
 ## 問題の理解

 1 から n までの位置の行が与えられ、各位置には初期量のリソースが保持されます。 最初は、すべての位置が独自の独立したグループであるため、n 個の互いに素なグループが存在し、それぞれに 1 つのインデックスが含まれます。 

時間が経つにつれて、2 つのポジションが選択される操作が与えられます。 これら 2 つの立場を含むグループは相互作用しており、2 つのグループが線上で「近い」かどうかに応じて、平和的に合併するか、紛争を通じて合併します。 すべての対話の後、2 つのグループは常に 1 つのグループになりますが、固定ボーナス c を獲得するか、固定ペナルティ d を失うことによって、結合されたグループの総リソースが変化します。 

平和か紛争を決定する重要なルールは幾何学的なものです。最初のグループのすべての立場と 2 番目のグループのすべての立場を調べます。 数直線上で隣接する位置のペアが少なくとも 1 つ (各グループから 1 つずつ) 存在する場合、つまりそれらのインデックスがちょうど 1 だけ異なる場合、交互作用は競合です。 そうでなければ平和です。 

これらのやり取りに加えて、特定のポジションを含むグループの現在の総リソースを求めるクエリに答える必要があります。 

この制約は十分に大きいため、どのソリューションでも 50 万のポジションに対して最大 50 万の操作を処理する必要があります。 これにより、各マージ中にグループのすべてのメンバーを繰り返しスキャンするアプローチは即座に除外されます。これは、グループがサイズ n まで拡大し、n 回のマージが発生する可能性があり、二次的な動作が発生する可能性があるためです。 

微妙な問題は、グループが連続したセグメントである必要がないことです。 複数のマージの後、グループは分散したインデックスのセットになる可能性があるため、グループ間の隣接性は間隔のエンドポイントだけでは決定されません。 

素朴な間隔の考え方を打ち破るエッジケースの 1 つが次のとおりです。 グループ A に {1, 4} が含まれ、グループ B に {2, 10} が含まれているとします。 区間が重なり合っている場合や範囲が近い場合でも、隣接性は差 1 を持つペアの存在によってのみ決定されます。ここで 1 と 2 は隣接しているため、単純な意味でのセットが隣接する区間ではない場合でも、交互作用は競合する必要があります。 

各グループを最小インデックスと最大インデックスだけで表現しようとすると、別の失敗例が発生します。 たとえば、A = {1, 10} および B = {2, 9} です。 それらの間隔は重なり合っていますが、グループを横切る実際のエッジ (i、i+1) が存在しない限り、それらは隣接しません。 間隔の要約が不十分です。 

したがって、難しいのは、固定パス グラフ上で動的な接続コンポーネントを維持しながら、繰り返しのマージと 2 つのコンポーネント間にクロスエッジが存在するかどうかの高速検出をサポートすることです。 

## アプローチ

 直接シミュレーションでは、各グループを明示的なインデックスのセットとして維持します。 x と y の間の相互作用を処理するには、それらのグループを見つけて、一方のセットの要素にもう一方のセットに隣接する要素があるかどうかを確認します。 これには、1 つのセット全体をスキャンし、もう 1 つのセットのメンバーシップを確認する必要があり、操作ごとに O(n) に低下する可能性があります。 n 回の操作を超えると、これは O(n²) となり、非常に遅すぎます。 

重要な点は、隣接構造が静的であるということです。 重要なエッジは固定エッジ (i、i+1) だけです。 2 つのグループが隣接しているかどうかは、これらの固定エッジのいずれかがそれらの間で交差しているかどうかによってのみ決まります。 これにより、マージをサポートし、どのコンポーネントが境界エッジによって接続されているかを維持しながら、パス グラフの動的パーティションを維持するという問題が軽減されます。 

これは、union-find のような構造を示唆していますが、元のラインの少なくとも 1 つのエッジを介して 2 つのコンポーネントが隣接しているかどうかも検出する必要があるため、標準の DSU では不十分です。 したがって、コンポーネントごとに、そのサイズとリソースの合計だけでなく、境界エッジを介してコンポーネントが接触している他のコンポーネントも維持します。 コンポーネントは進化するため、マージが発生したときにこれらの隣接関係を更新する必要があります。

これを効率的に管理する標準的な方法は、コンポーネントのメンバーシップ リストを小規模から大規模にマージすることです。 各コンポーネントは、そのノードのリストを保存します。 2 つのコンポーネントをマージする場合、小さい方のコンポーネントを反復処理し、隣接する i-1 および i+1 を調べることによって、影響を受けるすべての境界関係を更新します。 これにより、すべてのマージにわたって各インデックスが対数的にのみ処理されるようになります。

 | マージごとの単純なセット スキャン | O(n²) | O(n) | 遅すぎる |
 | 隣接関係を維持するノード上の小規模から大規模までの DSU | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはコンポーネント全体にわたって素のセット構造を維持します。 各コンポーネントは、そのメンバー インデックス、リソースの合計、およびラインに沿った隣接関係によって引き起こされる一連の隣接コンポーネントのリストを保持します。 

1. 各位置 i を独自のコンポーネントとして初期化します。合計は a[i] に等しく、最初は近傍はありません。 また、位置からコンポーネントへのマッピングがアイデンティティであることも記録します。 
2. 位置 x および y を含む対話クエリごとに、DSU 検索操作を使用して現在のコンポーネント A および B を見つけます。 
3. A が B に等しい場合、両方の位置がすでに同じコンポーネント内にある場合、操作は無効であるため、何も行いません。 
4. 相互作用が平和的であるか敵対的であるかを判断するために、A と B が隣接するコンポーネントであるかどうかを確認します。 これは、A が B の隣接セットに出現する場合、またはその逆の場合に当てはまります。 それらが隣接している場合、結果は競合になります。 それ以外の場合は同盟です。 
5. A と B を結合して新しいコンポーネント C を計算します。効率を保証するために、小さいコンポーネントを大きいコンポーネントに接続します。 小さいコンポーネントのすべてのノードを大きいコンポーネントに移動し、そのコンポーネント ポインタを更新します。 
6. ノードを移動しながら、マージされたコンポーネント内の各ノード u を検査します。 各 u について、u−1 と u+1 が存在するかどうかを確認します。 隣接する v が別のコンポーネント D にある場合、C は D に隣接します。また、D が A または B への参照を C に置き換えることも保証します。 
7. マージ後、両方の合計を加算し、同盟の場合は +c を、競合の場合は -d を適用することで、新しいコンポーネントのリソースの合計を更新します。 
8. タイプ 2 の各クエリについて、x の成分を見つけて、保存されているその合計を出力します。 

重要な不変条件は、すべてのコンポーネントがすべての操作後にメンバー インデックスのセットとリソースの正しい合計を正しく維持することです。 さらに、すべてのコンポーネントについて、その隣接セットは、少なくとも 1 つの元の隣接エッジ (i、i+1) を共有するコンポーネントに正確に対応します。 ノードがコンポーネント間を移動するたびに隣接関係を明示的に更新するため、隣接エッジが見逃されたり、誤って導入されたりすることはありません。 これにより、同盟と紛争の間のすべての決定が、その時点でのコンポーネント間の境界エッジの正確な存在に基づいて行われることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n, a):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.sum = [0] * (n + 1)
        self.nodes = [[] for _ in range(n + 1)]
        self.nei = [set() for _ in range(n + 1)]
        self.a = a

        for i in range(1, n + 1):
            self.sum[i] = a[i]
            self.nodes[i].append(i)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def add_edge_relation(self, u, v, pu, pv):
        if pu == pv:
            return
        self.nei[pu].add(pv)
        self.nei[pv].add(pu)

    def merge(self, x, y, gain):
        x = self.find(x)
        y = self.find(y)
        if x == y:
            return x

        if self.size[x] < self.size[y]:
            x, y = y, x

        # y merges into x
        for u in self.nodes[y]:
            self.parent[u] = x
            self.nodes[x].append(u)

        self.nodes[y].clear()

        for u in self.nodes[x]:
            pu = x
            for nb in (u - 1, u + 1):
                if 1 <= nb <= len(self.a) - 1:
                    pv = self.find(nb)
                    if pv != pu:
                        self.nei[pu].add(pv)
                        self.nei[pv].add(pu)

        self.size[x] += self.size[y]
        self.sum[x] += self.sum[y] + gain

        return x

n, c, d = map(int, input().split())
a = [0] + list(map(int, input().split()))
q = int(input())

dsu = DSU(n, a)

out = []

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        x = int(tmp[1])
        y = int(tmp[2])

        fx = dsu.find(x)
        fy = dsu.find(y)

        if fx == fy:
            continue

        adjacent = (fy in dsu.nei[fx]) or (fx in dsu.nei[fy])

        gain = c if adjacent else -d
        dsu.merge(x, y, gain)

    else:
        x = int(tmp[1])
        fx = dsu.find(x)
        out.append(str(dsu.sum[fx]))

print("\n".join(out))
```DSU 構造は、コンポーネントの集約とコンポーネント間の進化する隣接関係の両方を維持します。 マージ操作では、最初に、維持された近隣セットを使用して、相互作用が敵対的であるか平和的であるかを判断します。 次に、各ノードが最大で対数的に何度も再割り当てされるように、ノード リストの小規模から大規模へのマージを実行します。 

重要な点は、隣接関係がグローバルに再計算されないことです。 代わりに、移動されたノードのローカル隣接ノードのみを検査することによって段階的に維持されます。 これにより、マージのたびにコンポーネント全体をスキャンする必要がなくなります。

 ## 特殊なケース

 エッジ ケースの 1 つは、コンポーネントが隣接関係なしに結合される場合です。 たとえば、{1} と {3} のマージは、インデックス空間内で近い場合でも平和的に行われるはずです。 どちらの 1 も {3} 内のどの要素にも隣接していないため、アルゴリズムは境界エッジを正しく検出しません。 

もう 1 つのケースは、既にマージされたコンポーネントを含む繰り返しマージです。 x と y が同じコンポーネント内にある場合、操作は無視され、リソースの変更が二重にカウントされるのを防ぎます。 

最後の微妙なケースは、コンポーネントが非常に不連続になる場合です。 その場合でも、隣接関係チェックは元の隣接回線のみに基づいているため、正しいままになります。 更新ステップにより、ノードがコンポーネントを変更するたびに、その 2 つの隣接ノードが再評価され、プロセス全体を通じて正しい境界関係が維持されます。
