 **タグ:** ビットマスク、DP
 **解決時間:** 8 分 18 秒

 ## 解決策
 ## 問題の理解

 私たちは固定の文字列を与えられ、それを 1 本指のキーボードを使用して繰り返し入力します。 キーボードは、最初のキーボードの順列を選択することによって定義されます。$m$この順列により、各文字が行上の固有の位置に配置されます。 文字列を入力するとき、連続する文字の各ペアには、この行上の位置の絶対差に等しいコストがかかります。 合計の入力コストは、選択したアルファベットの順序に完全に依存します。 

任務は、$m$文字列内のすべての隣接する遷移にわたるこの合計コストが可能な限り小さくなるようにします。 

重要な構造上の詳細は、文字列の長さが最大で$10^5$しかし、異なる文字の数は最大でも 20 です。これは、文字のすべての順列を反復するアルゴリズムは絶望的であることを直ちに示唆しています。$20!$は大きすぎますが、指数関数的なものは何でも$m$その周り$2^m$もっともらしいです。 したがって、正しいソリューションでは、文字列をペアごとの遷移カウントに圧縮し、ビットマスク動的プログラミングを使用して順列全体を最適化する必要があります。 

単純な間違いは、頻度やローカルの隣接性によって文字を順序付けすることを貪欲に考えることから生じることがよくあります。 たとえば、ある文字が別の文字の後に頻繁に続く場合は、それらを隣接して配置してみるとよいでしょう。 これは、2 つの文字を近くに配置すると両方向の寄与が減少し、相互作用はグローバルでペアごとに独立していないため、失敗します。 もう 1 つの微妙な失敗例は、最適な配置が周波数順に線形であると仮定している場合で、低周波数の文字が 2 つの高周波数クラスター間のブリッジとして機能すると、この配置が崩れます。 

## アプローチ

 ブルートフォースソリューションでは、すべての順列を列挙します。$m$文字の配置に基づいて文字列のコストを計算し、最小値を取得します。 1 つの順列のコストを計算するには、文字列を 1 回スキャンし、隣接する差分を合計する必要があります。$O(n)$。 と$m!$順列を追加すると、全体の複雑さは次のようになります。$O(m! \cdot n)$、これは$m = 20$天文学的に大きく、まったく実現不可能です。 

重要な観察は、コストは、順序付けされた各文字ペアが文字列内で隣り合って出現する頻度のみに依存するということです。 行列を事前計算できます$cnt[a][b]$、文字からの遷移を数える$a$に$b$。 これが修正されると、総コストは文字列構造に直接依存するのではなく、順列のみの関数になります。 

ここで問題は、各文字に一意の位置を割り当てることです。$0$に$m-1$加重和が$$\sum_{a,b} cnt[a][b] \cdot |pos[a] - pos[b]|$$最小化されます。 

これは古典的なビットマスク動的プログラミングの問題です。 左から右への順列を構築します。 どの時点でも、すでに配置されている文字のサブセットを保持します。 重要なのは、新しい文字を追加するとき、その貢献度は、すでに配置されている文字と対話する回数と、将来の文字と対話する回数だけによって決まるということです。 将来の文字はまだ配置されていないため、現在の境界との累積的な相互作用のみを追跡します。 

これを正確にするために、文字を位置に段階的に割り当てるサブセットにわたる DP を定義します。$0, 1, \dots, m-1$。 現在の位置に新しい文字を配置する場合、その寄与は、以前に配置されたすべての文字までの距離によって決まります。距離は、それらの文字が何ステップ前に配置されたかによって完全に決まります。 これにより、状態がどの文字が配置されるかをエンコードする DP が得られ、事前に計算された遷移合計を使用してコストを更新しながら、遷移によって次の位置に 1 つの文字が追加されます。 

複雑さは次のようになります$O(m^2 2^m)$、これは許容されます$m \le 20$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m! \cdot n)$|$O(1)$| 遅すぎる |
 | ビットマスク DP |$O(m^2 2^m)$|$O(m 2^m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず文字列を遷移周波数に圧縮して、文字列構造が直接必要なくなるようにします。 

1. 各文字を以下の整数にマッピングします。$0$に$m-1$、次に行列を構築します$cnt$どこ$cnt[a][b]$何回数えますか$a$すぐに続く$b$文字列の中で。 このステップでは、問題全体をペアごとの相互作用の重みに縮小します。 
2. 補助配列を事前計算する$w[a][mask]$、 どこ$w[a][mask]$手紙を掲載することによる貢献度の合計を表します$a$サブセット内のすべての文字の横にある$mask$、これらの文字がすでに前の位置に配置されていると仮定します。 これにより、順列を拡張する際の増分コストを迅速に評価できます。 
3. DP 配列を定義する$dp[mask]$文字を正確に配置した後の最小コストを表します$mask$キーボードの左端の位置に押します。 常に左から右に構築するため、マスク内の順序は暗黙的です。 
4.初期化$dp[0] = 0$。 文字が配置されないということは、コストが蓄積されないことを意味します。 
5. すべてのサブセットを反復処理します。$mask$。 州ごとに、新しい文字を追加してみてください$a$入っていない$mask$。 置いたら$a$のサイズと同じ位置に$mask$、事前に計算された遷移カウントと、以前に配置された各文字が新しい位置から既知の距離を持っているという事実を使用して、以前に配置されたすべての文字に対する寄与を計算します。 
6.アップデート$dp[mask \cup \{a\}]$可能なすべての選択肢に対して最小限のコストで$a$。 これにより、各プレフィックス セットの最適なコストを維持しながら、一度に 1 つの位置で順列を効果的に構築できます。 
7. 答えは次のとおりです。$dp[(1 << m) - 1]$、配置されているすべての文字に対応しているためです。 

### なぜ効果があるのか

 DP 状態は、将来の決定にとって重要となる唯一の情報、つまりどの文字がすでに役職に割り当てられているかを正確に取得します。 新しいレターを追加するコストは、すでに配置されているレターまでの距離にのみ依存し、それらの距離は構築によって固定されるため (位置は挿入順序によって決定されるため)、将来の決定によって過去の貢献を遡って変更することはできません。 これにより、最適な下部構造が保証されます。つまり、以前の配置を再考することなく、すべてのプレフィックス割り当てを最適に拡張できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    a = [ord(c) - 97 for c in s]

    cnt = [[0] * m for _ in range(m)]
    for i in range(n - 1):
        cnt[a[i]][a[i + 1]] += 1

    # dp[mask][i] = minimum cost when placing letters in mask,
    # last placed letter is i
    INF = 10**18
    size = 1 << m
    dp = [[INF] * m for _ in range(size)]

    for i in range(m):
        dp[1 << i][i] = 0

    for mask in range(size):
        k = bin(mask).count("1")
        for last in range(m):
            if not (mask & (1 << last)):
                continue
            cur = dp[mask][last]
            if cur == INF:
                continue

            for nxt in range(m):
                if mask & (1 << nxt):
                    continue

                nmask = mask | (1 << nxt)

                # cost of placing nxt at position k relative to previous letters
                add = 0
                for j in range(m):
                    if mask & (1 << j):
                        dist = abs(k - (bin(mask & ((1 << j) - 1)).count("1")))
                        add += cnt[j][nxt] * dist
                        add += cnt[nxt][j] * dist

                dp[nmask][nxt] = min(dp[nmask][nxt], cur + add)

    ans = min(dp[size - 1])
    print(ans)

if __name__ == "__main__":
    solve()
```コードは、文字列を整数ラベルに変換し、文字列全体を次のように圧縮する遷移行列を構築することから始まります。$O(m^2)$データ。 次に、DP は文字のすべてのサブセットを探索し、どの文字がすでに配置されているか、どの文字が最後に配置されたかを追跡します。 

内部コストの計算では、新しく配置されたキャラクターが以前に配置されたすべてのキャラクターとどのように相互作用するかを評価します。 距離の計算は、以前に配置された各文字の位置が、ビットカウントから導出されるサブセット内の順序によって決定されるという事実に基づいています。 サブセットの順序を位置に変換する際に誤りがあると、直ちに正確さが損なわれるため、これは最もデリケートな部分です。 

どの文字でも最適性に影響を与えることなく最後に配置できるため、最終的な答えはすべてのフルマスク状態の最小値になります。 

## 実用的な例

 ### サンプル 1

 入力:```
6 3
aacabc
```遷移数:

 | ペア | カウント |
 | --- | --- |
 | a → a | 1 |
 | a → c | 1 |
 | c → a | 1 |
 | a → b | 1 |
 | b → c | 1 |

 DP 実行では、abc、bac などの順列を比較します。最良の配置は、頻繁な遷移をローカルに保ちながら、a と c の間の大きなジャンプを減らす配置です。 

1 つの最適なビルドのトレース (概念的な DP パス):

 | マスク | 最後 | 追加しました | コスト |
 | --- | --- | --- | --- |
 | 000 | - | 開始 | 0 |
 | 001 (a) | | | 0 |
 | 011 (a,b) | b | b | 小さい |
 | 111 (a、b、c) | c | c | 5 |

 これは、a と c を遠くに配置すると走り幅跳びの繰り返しが増加する一方、最適な配置ではそれらのバランスが取れていることを示しています。

```すべての遷移カウントはゼロです。$a \to a$。 あらゆる順列はゼロコストを生成し、DP は順序に関係なくすべての状態が 0 に崩壊することを確認します。 

これにより、アルゴリズムが縮退対称のケースを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(m^2 2^m)$| 各サブセット遷移は次のように評価されます。$m$追加$O(m)$コスト計算 |

 文字列で 1 文字のみが使用されている場合、移動は発生しないため、すべての遷移コストはゼロであり、順列はゼロを返さなければなりません。
