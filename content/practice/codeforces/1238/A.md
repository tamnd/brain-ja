 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。`x`そして`y`、 と`x > y`。 タスクは、単一の素数を選択できるかどうかを判断することです。`p`そしてそれを繰り返し引き算します`x`到着するまで`y`。 重要なのは、素数を選択したら、それを排他的に使用する必要があるということです。 素数を途中で切り替えることはできません。 各テスト ケースは独立しており、次の値は`x`そして`y`非常に大きくなる可能性があり、最大で$10^{18}$。 

問題は、違いがあるかどうかを確認することになります。`x - y`ある素数の倍数として表すことができます。 そのような素数が存在する場合、答えは「YES」です。 それ以外の場合は「いいえ」。 

制約は、以下のすべての素数を反復できないことを示唆しています。`x - y`違い自体は次のように大きくなる可能性があるため、$10^{18}$、最大 1000 のテスト ケースがあります。 A naive approach attempting trial division for every potential prime would be far too slow.

 エッジケースには、次のようなシナリオが含まれます。`x - y = 1`。 1 は素数ではないので、素数を引くことは不可能です。`y`。 もう一つのケースは次のような場合です。`x - y`は偶数で 2 より大きい: いつでも 2 を使用してギャップを埋めることができます。 同様に、`x - y`それ自体が素数なので、その素数を直接使用できます。 これらの洞察は最適なアプローチにつながります。 

## アプローチ

 ブルートフォースソリューションでは、以下の素数をすべて生成しようとします。`x - y`そして、それぞれの差が分割されるかどうかを確認します。 小さい入力の場合は正しいですが、素数が最大で生成されるため、これは失敗します。$10^{18}$実行不可能です。 操作数は天文学的なものとなり、簡単に超えます。$10^{15}$、実用的ではありません。 

重要な観察は、最小の素数 2 と、その差自体が素数であるかどうかを確認するだけでよいということです。 もし`x - y = 1`、プライムは機能せず、答えは「NO」です。 のために`x - y >= 2`、常に素数があります`p`それが差を分けるのです。 具体的には、差が偶数の場合は 2 が機能します。 差が 2 より大きく奇数の場合、差自体が素数であるか、それよりも小さい素因数を持ちます。 したがって、問題はテスト ケースごとの一定時間のチェックに単純化されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`x`そして`y`。 
3. 差を計算します`d = x - y`。 
4. もし`d == 1`、1 の差を埋める素数はないため、「NO」を出力します。 
5. それ以外の場合は、「YES」を出力します。 1 より大きい差は常に何らかの素数の倍数として表現できます。 

その理由は、1 より大きいすべての整数には少なくとも 1 つの素因数があるということです。 したがって、どちらか`d`はそれ自体が素数であるか、問題の要件を満たす素数の倍数に分解できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    if x - y == 1:
        print("NO")
    else:
        print("YES")
```コードはアルゴリズムに直接に従います。 高速入力を使用します。`sys.stdin.readline`複数のテスト ケースを効率的に処理するため。 違い`x - y`は単一の整数の減算として計算されます。 差が 1 である唯一の障害エッジ ケースをチェックし、それ以外の場合は「YES」を返します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 差が 1 の場合、アルゴリズムは正しく「NO」を出力します。 入力`x = 41`、`y = 40`収量`d = 1`、特定の条件をトリガーし、任意の素数が機能するという誤った仮定を回避します。 

最大サイズの入力の場合、次のように`x = 10^18`、`y = 1`、 違い`d = 10^18 - 1`は 1 よりはるかに大きいため、アルゴリズムは素数の反復や生成を行わずに効率的に「YES」を出力します。 これにより、入力空間全体にわたる正確性とパフォーマンスが確認されます。
