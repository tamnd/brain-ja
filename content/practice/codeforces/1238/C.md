 ## 解決策
 ## 問題の理解

 崖は、高さ h に特別なスタート台がある、高さ 1 から h までの垂直線と考えることができます。 これらの高さの一部にはすでに使用可能なプラットフォームが含まれていますが、残りは空です。 あなたは最上部のプラットフォームに立っていて、地上レベル 0 に到達したいと考えています。 

いつでも、移動する唯一の方法は、高さ x の使用可能なプラットフォームの上に立って、x と x−1 の状態を切り替えることです。 これを行うと、現在のプラットフォームが削除され、1 レベル下に新しいプラットフォームが作成される可能性があり、利用可能になった場合はすぐにそこに着陸します。 それ以外の場合は単に落ちるだけですが、落ちても安全なのはギャップが最大 2 の場合に限られます。この制約は事実上、下降するときに空のレベルが 3 つ連続して実行されないようにする必要があることを意味します。 

また、クリスタルを使用して事前に構成を「修正」することもできます。各クリスタルは、単一の非上部プラットフォームを空から充填、または充填から空に反転します。 目標は、そのような修正を最小限に抑えて降下を可能にすることです。 

入力により、複数の独立したシナリオが得られます。 各シナリオでは、高さ h とプラットフォームが存在する高さの初期セットを指定します。 3 つ以上の空のレベルを強制的に落とすことなく、h から 0 までの有効な一連の移動が存在するように、必要なフリップの最小数を計算する必要があります。 

この制約は、テストごとに強い線形の解決策を意味します。 すべてのクエリにわたるプラットフォーム位置の合計数は最大 2×10^5 であるため、O(n log n) を超える解はすでに安全ですが、h は 10^9 まで大きくなる可能性があるため、h までの高さごとのシミュレーションを伴うものは不可能です。 これにより、崖の明示的なシミュレーションが即座に除外されます。 

微妙な問題は、個々の位置ではなく空のセグメントが重要であるという事実から生じます。 単純なアプローチでは、上から貪欲に動きをシミュレートし、動きがブロックされるたびに反転しようとする可能性がありますが、ローカル修正によりさらに下に将来の新しいブロックが作成される可能性があるため、これは失敗します。 もう 1 つのよくある間違いは、0 までの最終セグメントも制約の一部であることを無視して、連続するプラットフォーム間の距離のみに注目することです。 

たとえば、プラットフォームの高さが 5 と 1 にある場合、両方のエンドポイントが有効であっても、プラットフォーム間のギャップが 4 であるため、中央に少なくとも 1 つの変更が強制されます。 同様に、プラットフォームが 3、2、1 にあるのは問題ありませんが、3、1、0 は入力で直接表現されないため、降下制約を通じて暗黙的にチェックする必要があります。 

## アプローチ

 重要な観察は、移動の制約は 3 回連続して空の高さに遭遇するかどうかのみに依存するということです。 これにより、問題は、連続する既存のプラットフォーム間のギャップをカバーするタスクに変換されます。 

高さ h の暗黙的なプラットフォームを含むすべての既存のプラットフォームをソートすると、連続する占有位置間のギャップを調べることができます。 2 つの連続するプラットフォームが高さ x と y にあり、x > y であると仮定します。 それらの間のセグメントには、x−y−1 個の空の位置が含まれます。 この数値が最大 1 の場合、アクションは必要ありません。 2 つ以上の場合は、セグメントに 3 つ以上の連続した欠落位置が存在しないように、クリスタルを使用して追加のプラットフォームを挿入する必要があります。 

貪欲な戦略が自然になります。上から下にトラバースし、2 より大きいギャップを検出するたびに、概念的にはギャップが安全なチャンクに分割されるような方法で追加のプラットフォームを「配置」します。 挿入されたプラットフォームごとに、新しいアンカー ポイントが作成され、実効ギャップが減少します。 

ブルートフォースアプローチでは、すべての空の位置でのクリスタルのすべての可能な配置をシミュレートし、到達可能性をテストして、指数関数的な構成を効果的に調査します。 中程度の n であっても、空の位置のサブセットの数が膨大になるため、これは不可能です。

貪欲なリダクションは、各ギャップが独立しているため機能します。1 つのギャップを修正しても、それ以前のギャップには影響しません。また、最適な戦略は、すべての降下ステップで最大 2 つの空のレベルをカバーすることを強制することで、常に最小限のギャップを埋めます。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1. 高さ h の開始プラットフォームを既存のプラットフォームのリストに追加します。 これにより、上からの降下を均一に処理できるようになります。 
2. 現在の「最後に確認されたプラットフォームの高さ」を維持しながら、プラットフォームの高さを降順に移動します。 
3. 現在の x より下の次のプラットフォーム y ごとに、ギャップ g = x − y − 1 を計算します。このギャップは、2 つの使用可能なプラットフォームの間に空のレベルがいくつあるかを表します。 
4. g が 0 または 1 の場合、そのようなギャップでは 3 つの連続した空のレベルを生成できないため、何もしません。 
5. g ≥ 2 の場合、結晶を使用した人工プラットフォームを導入する必要があります。 挿入された各プラットフォームは問題のあるセグメントを効果的に減らし、空の連鎖が 2 を超えないようにする。ギャップに必要な結晶の数は (g − 1) // 2 です。 
6. この貢献を回答に追加し、ポインタを y に移動します。 

最終的な答えは、すべてのギャップの合計です。 

機能する理由: 降下制約は、連続する 3 つの空の高さがある場合にのみ失敗します。 サイズ g のギャップにより、正確に g 個の連続した空の位置が作成されます。 クリスタルを挿入するたびに、長い空のセグメントをより小さなセグメントに分割する新しいプラットフォームが導入されます。 最適な戦略は、常にこれらの挿入を均等に配置して、結果として得られるすべてのセグメントのサイズが最大 2 になるようにすることです。挿入が少なくなると、必然的にセグメントの長さが少なくとも 3 になるため、制約に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        h, n = map(int, input().split())
        p = list(map(int, input().split()))
        
        # include the top
        prev = h
        ans = 0
        
        for x in p:
            gap = prev - x - 1
            if gap > 1:
                ans += (gap - 1) // 2
            prev = x
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装はギャップ処理ロジックを直接反映しています。 ポインタを保持します`prev`h で始まり、最後に保証された到達可能なプラットフォームを表します。 その下の各プラットフォームについて、それらの間に存在する空のレベルの数を計算します。 式`(gap - 1) // 2`は、そのセグメント内に 3 つの連続した空の位置が残らないようにするために必要な、挿入されたプラットフォームの最小数です。 更新中`prev`これにより、隣接する関連セグメントのみが考慮されるようになります。 

よくある実装の落とし穴は、h を初期占有プラットフォームとして扱うことを忘れることです。 これがないと、最初のギャップが誤って計算されます。 もう 1 つの微妙な点は、最終セグメントが 0 まで同じギャップ ロジックによって暗黙的に処理されることが構造によって保証されているため、高さ 0 を明示的に考慮することがないことです。

 ## 特殊なケース

 エッジ ケースの 1 つは、5、4、3、2、1 など、すべてのプラットフォームが連続している場合です。この場合、すべてのギャップはゼロであるため、アルゴリズムは正しくゼロ操作を生成します。 

別のケースは、高さ h に単一のプラットフォームがあり、他にプラットフォームがない場合です。 降下全体は h から 0 までの 1 つの大きなギャップであり、式はそれを、3 つの空のレベルの実行を回避するために必要な最小限の挿入数に正しく削減します。 

より微妙なケースは、ギャップが小さい値と大きい値の間で交互に現れる場合です。 結晶の挿入はそのギャップ内の局所的な連続性にのみ影響を与えるため、各ギャップは独立して処理されます。 このアルゴリズムは各セグメントを 1 回だけ処理し、二重にカウントすることはありません。これにより、大小のギャップがインターリーブされている場合でも正確さが保証されます。
