 ## 解決策
 ## 問題の理解

 文字 A と B だけからなるバイナリ文字列が与えられました。私たちの仕事は、回文を含む特定の構造条件の下で、その連続する部分文字列のうち「良好」なものがいくつあるかを数えるということです。 

部分文字列内のすべての位置が、その部分文字列に完全に含まれる長さより厳密に長い少なくとも 1 つの回文に属している場合、その部分文字列は良好であるとみなされます。 言い換えれば、部分文字列内の各文字は、その同じ部分文字列内で完全に重要な回文 (長さは少なくとも 2) によって「覆われ」なければなりません。 

重要な問題は、これは部分文字列自体が回文であるかどうかではなく、文字が孤立したままにならないように部分文字列を分解できるか、重複する回文構造でカバーできるかどうかを尋ねていることです。 

この制約により、文字列の長さは最大 300,000 まで許可されます。 すべての部分文字列に対する二次スキャンでは、最悪の場合でもすでに約 4.5e10 個の部分文字列が生成されるため、すべての部分文字列を明示的にチェックするアプローチは実行不可能になります。 線形時間で各部分文字列をチェックしたとしても、それでも遅すぎます。 

これにより、部分文字列が個別に検査されるのではなく、集計された範囲に寄与する O(n log n) または O(n) 戦略に向かうことになります。 

AAAAAA など、文字列が均一である場合、微妙なエッジ ケースが表示されます。 すべての部分文字列は回文で満たされているのは明らかなので、すべての部分文字列は適切です。 対照的に、ABABAB のような交互文字列は、回文に大きな制約があり、カバレッジがすぐに失敗するため、動作が大きく異なります。 A と B は同じ頻度で出現しますが、重要なのは構造であるため、文字の頻度のみに基づいた単純なヒューリスティックはここでは失敗します。 

もう 1 つの特殊なケースは、非常に短い部分文字列です。 単一文字の部分文字列は、長さが 1 を超える回文を含まないため、決して適切ではありません。これにより、長さ 1 のすべての区間が考慮から即座に除外されます。 

## アプローチ

 ブルートフォース手法では、すべての部分文字列 s[l:r] を調べ、各文字について、その部分文字列に含まれる少なくとも 2 の長さの回文内にすべての文字が存在するかどうかを検証します。 賢い回文展開チェックを行ったとしても、単一の部分文字列の検証は最悪の場合 O(n) になります。 これにより、全体として O(n^3) の動作が発生し、n = 3·10^5 ではまったく使用できなくなります。 

重要な観察は、「すべての位置が長さ > 1 の回文に属する」という条件は、位置が対称ペアから分離されている「禁止された構造」を部分文字列に含めることができないと言っているのと同じであるということです。 AB 文字列では、有用な回文は、AA/BB (長さ 2) と ABA、BAB (長さ 3) の 2 つの形式のみです。 より大きな回文はこれらのローカル パターンから構成されるため、カバレッジはローカル隣接制約に限定されます。 

重要な単純化は、問題を再解釈することです。各部分文字列内のカバレッジをチェックする代わりに、境界の相互作用に基づいてどの部分文字列が有効であるかを特徴付けます。 部分文字列が適切であるとは言えないのは、有効な回文が領域をカバーできない「ギャップ」が含まれている場合のみであり、これは事実上、プレフィックス構造と文字間の遷移を使用して追跡できる制約に変換されます。 

これは、この問題群の既知の削減につながります。各位置について、カバレッジを維持しながら、その位置で終わる有効な部分文字列をどこまで拡張できるかをスキャンして維持します。 次に、各インデックスの寄与が有効な開始範囲として計算されます。

i で終わる有効な部分文字列が開始できる最も古い位置を追跡するポインターを維持します。 i を拡張するとき、ローカル回文パターンがすべての文字をカバーできるかどうかに基づいてこの境界を更新します。 構造の違反 (AA/BB または ABA パターンの一部になり得ない位置) を検出するたびに、左側の境界を前方に移動します。 

これにより、問題は線形スイープに変換され、各右端点が有効な左端点の連続した間隔に寄与します。

 ## アルゴリズムのチュートリアル

 現在の位置で終わる部分文字列の最小の有効な開始インデックスを維持しながら、文字列を左から右に処理します。 

1. ポインタを初期化する`l = 0`、これは部分文字列 s[l:i] が依然として良好である可能性があるような最も古いインデックスを表します。 

このポインタは前方にのみ移動し、後方には決して移動しないため、直線的な複雑さが保証されます。 
2. ポジションごとに`i`、現在のウィンドウ [l, i] を拡張しようとします。 各ステップで、新しく追加された文字がウィンドウ内で少なくとも 2 の長さの回文でカバーできるかどうかを確認します。 
3. バイナリ アルファベットで考えられる回文カバーは、隣接性または 1 ステップ対称性を含む局所パターンのみです。 拡張機能が、最後の数文字が AA、BB、ABA、または BAB パターンを形成したり参加できない構成を作成した場合、ウィンドウは無効になるため、ウィンドウを移動する必要があります。`l`フォワード。 
4. 現在のウィンドウが回文カバレッジ条件に違反していることを検出するたびに、インクリメントします。`l`ウィンドウが再び有効になるまで。 これにより、前から始まるすべての部分文字列が保証されます。`l`はこのエンドポイントでは無効です。 
5. ウィンドウが有効になると、次で終わるすべての部分文字列が削除されます。`i`[l, i] のどこからでも開始できます。 追加します`(i - l)`答えに。 
6. 0 から n-1 までのすべての i に対してこのプロセスを繰り返します。 

### なぜ効果があるのか

 このアルゴリズムは、各右端点 i について、ポインタ l が最小のインデックスであるという不変条件を維持するため、s[l:i] 内のすべての文字は完全にウィンドウ内にある少なくとも 1 つの有効なローカル回文の一部となり得る。 有効性はローカル隣接制約のみに依存するため、違反には境界付近の有限のローカル パターンが含まれている必要があります。 l は違反が検出された場合にのみ前に進むため、有効な開始を除外したり、無効な開始を含めたりすることはありません。 これにより、各有効な部分文字列がその右のエンドポイントで正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # We interpret A/B as 0/1 for simplicity
    a = [0 if c == 'A' else 1 for c in s]

    l = 0
    ans = 0

    for r in range(n):
        # We try to maintain a valid window [l, r]
        # A substring is invalid only if it introduces an unmatchable boundary.
        # For binary alphabet, violations only arise when we cannot form
        # local palindromic pairs covering the boundary region.

        while l < r:
            ok = True

            # check minimal local coverage condition:
            # last character must be able to pair or sit in ABA
            if r - l + 1 == 2:
                ok = (a[l] == a[r])
            elif r - l + 1 >= 3:
                # check if last char participates in some palindrome
                if a[r] == a[r-1] or a[r] == a[r-2]:
                    ok = True
                else:
                    ok = False

            if ok:
                break
            l += 1

        if r > l:
            ans += (r - l)

    print(ans)

if __name__ == "__main__":
    solve()
```コードはスライディング ウィンドウを維持します。 ループ内のチェックは、最新の文字が少なくとも 2 の長さの回文に属することができることを確認するローカル実行可能性テストです。そうでない場合は、再び可能になるまで左から縮小します。 

重要な点は、現在の拡張機能が有効な回文に参加できるかどうかを判断するのに重要なのは最後の 2 文字または 3 文字だけであるということです。これは、新しい文字をカバーする回文には、その文字がバイナリ アルファベットの長さ 2 または 3 の対称構造に含まれている必要があるためです。 

貢献`(r - l)`で終わる部分文字列の有効な開始位置をすべてカウントします。`r`。

 ## 特殊なケース

 単一の文字列は、1 を超える長さの回文はまったく存在できないという事実を明らかにし、答えは即座にゼロになります。 ウィンドウが長さ 1 に対して有効になることはないため、アルゴリズムはこれを処理します。 

AAAAA のような完全に均一な文字列は、少なくとも 2 の長さのすべての部分文字列が内部的に回文に富んでいるという逆の極端を示します。 スライディング ウィンドウは縮小する必要がないため、貢献が最大限に蓄積されます。 

ABABAB などの代替文字列は、最も制限的な動作を示します。 左ポインタは早期に安定し、短い部分文字列のみが有効になります。これは、ローカル隣接制約がグローバル構造をどのように支配しているかを示しています。
