 ## 解決策
 ## 問題の理解

 保管庫には、元の傑作 ID によって識別される絵画が保管されています。 もともとあった`N`さまざまな傑作。 レプリケーション プロセスでは、すべてのマスターピースのコピーが 2 つ作成されるはずでしたが、ちょうど 2 つのマスターピース ID が 2 番目のコピーを受け取ることができませんでした。 結果として、`N - 2`ID はボールト内に 2 回表示されますが、破損した 2 つの ID は 1 回だけ表示されます。 タスクは、これら 2 つの ID を回復することです。 

入力によりオリジナルの傑作の数が与えられ、その後に`2N - 2`現在ボールトに保存されている絵画 ID。 出力は、頻度が 1 である 2 つの ID である必要があります。 

制約は問題の重要な部分です。`N`到達できる`10^6`したがって、入力にはほぼ 200 万の数値が含まれます。 すべての値を大まかに並べ替えるアルゴリズムが必要`N log N`一部の言語では可能ですが、ここでは不要です。また、メモリ制限が 16 MB しかないため、すべての値をマップに保存すると大量のメモリが必要になります。 ID のストリームを 1 回処理し、一定の追加メモリのみを使用するソリューションが必要です。 

この厄介な事件は、行方不明の双子が互いに何らかの関係を持ち得るという事実から生じている。 不注意な解決策では、2 つの答えの価値が異なると仮定する可能性がありますが、それらはユニークな傑作であるため、ID は異なります。 もう 1 つのよくある間違いは、単一のオカレンスが入力の先頭または末尾に現れると想定することです。 

たとえば、次のことを考えてみましょう。```
3
5
8
5
9
8
```ID は次のとおりです。`5, 8, 5, 9`、出力は次のようになります。```
8 9
```並べ替え後に隣接する等しい値のみをチェックするソリューションはここでは機能しますが、元の順序に依存している場合は失敗します。 入力順序に意味はありません。 

もう 1 つのエッジ ケースは、2 つの欠落している ID が多数の重複 ID の中に混在している場合です。```
4
10
7
3
10
8
7
```正しい出力は次のとおりです。```
3 8
```周波数のカウントは機能しますが、最大 200 万の値の周波数テーブルを保存するとメモリ制限に違反します。 ソリューションでは、明示的にカウントするのではなく、重複パターンを利用する必要があります。 

## アプローチ

 直接的なアプローチは、各 ID が出現する回数をカウントすることです。 すべての絵画 ID を辞書に挿入し、再び出現するたびにカウントを増やすことができます。 最後に、カウント 1 の 2 つの ID が答えになります。 周波数パターンが正確にわかっているため、これは簡単です。通常の絵画にはすべて 2 つのコピーがあり、ペアになっていない絵画は 2 つだけです。 

問題は、辞書には次の内容が保存されていることです。`N`異なるID。 と`N = 10^6`、使用可能なメモリをはるかに超えるメモリが必要になる可能性があります。 リスト全体を並べ替えるのも別のオプションです。 並べ替えると、等しい ID が隣接するため、配列をスキャンすると 2 つの単一の値が明らかになります。 ただし、配列自体にはすでに数メガバイトが必要であり、ソートにより不必要なデータが導入されます。`O(N log N)`料金。 

有益な観察は、XOR 演算の動作から得られます。 数値とそれ自体の XOR を行うと、結果はゼロになります。 XOR は順序にも依存しません。 したがって、2 回出現するすべての ID が同じアキュムレータに XOR 演算されると、重複した ID はすべて消えます。 2 つの一意の ID のみが残ります。```
a ^ a ^ b ^ b ^ x ^ y = x ^ y
```残りの値は直接の答えの 1 つではありませんが、2 つの答えの違いが少しわかります。 任意の設定ビット`x ^ y`2 つの数値を異なるグループに分割します。 数値を再度 XOR して、今度はそのビットに従って除算します。 重複したペアは各グループ内でキャンセルされ、各グループに 1 つの回答が残ります。 

ブルートフォース手法は周波数を直接追跡するため機能しますが、メモリ使用量が原因で失敗します。 XOR プロパティを使用すると、以前の値を記憶する必要がなくなり、問題全体を定数メモリのスキャンに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 周波数マップを使用したブルート フォース | O(N) | O(N) | メモリが多すぎる |
 | 分類とスキャン | O(N log N) | O(N) | 不要 |
 | XOR パーティショニング | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`N`そして、`2N - 2`絵画ID。 すべての ID を変数に XOR します。`total_xor`。 

この手順の後、重複した ID はすべて消えます。`v ^ v = 0`。 変数には以下が含まれます`x ^ y`、 どこ`x`そして`y`行方不明の双子の2人のIDです。 
2. 設定されたビットを検索します。`total_xor`。 

以来`x`そして`y`が異なる場合、それらのバイナリ表現は少なくとも 1 つの位置で異なります。 セットビットイン`x ^ y`まさにそのような位置を示しています。 
3. 選択したビットに基づいて、すべてのペイント ID を 2 つのグループに分割します。 最初のグループの XOR 値を`first`2 番目のグループの値を`second`。 

2 つの特別な ID は、このビットが異なるため、異なるグループに分類されます。 重複したすべての ID はそのコピーと同じグループに入るため、ペアはキャンセルされます。 
4. 出力`first`そして`second`。 

各グループには、一度出現した 2 つの ID のうちの 1 つだけが含まれるようになりました。 

なぜ効果があるのか:

 不変条件は、XOR によって偶数回出現するすべての値が削除されるということです。 最初のパスでは、正しく複製されたすべてのペイントが 2 つの等しい値を提供して消滅し、2 つの一致しない ID の XOR だけが残ります。 選択されたビットにより、これら 2 つの ID が別々のグループに分割されます。 各グループ内では、重複した ID はすべて 2 回表示されてキャンセルされますが、一致しない ID が 1 つ残ります。 2 つのグループは互いに素であり、それぞれに 1 つの回答が含まれているため、最後の 2 つの XOR 結果はまさに必要な ID です。

import sys

input = sys.stdin.readline

def solve():
    n = int(input())

    values = []
    total_xor = 0

    for _ in range(2 * n - 2):
        x = int(input())
        values.append(x)
        total_xor ^= x

    bit = total_xor & -total_xor

    first = 0
    second = 0

    for x in values:
        if x & bit:
            second ^= x
        else:
            first ^= x

    print(first, second)

if __name__ == "__main__":
    solve()
```最初のループでは、すべての ID の XOR を計算します。 このリストは、2 番目のグループ化フェーズで値を再度検査する必要がある場合にのみ保持されます。 低レベル言語では、ファイルまたはバッファリングされた入力ソースに対して 2 つのパスを使用することで値の保存を回避できますが、標準の Python 入力では巻き戻しができません。 

表現`total_xor & -total_xor`設定された最下位ビットを抽出します。 残りの 2 つの ID はどこかで異なる必要があるため、これは分離ビットを選択する安全な方法です。 2 番目のループでは、そのビットをパーティション ルールとして使用します。 

ループ境界内にはオフバイワンの問題はありません。 IDの数はちょうどいいです`2N - 2`, そのため、多くの値を消費する必要があります。 Python の整数は任意の精度を持っているため、最大の大きな ID`10^9`特別な取り扱いは必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | それぞれの`2N - 2`ID は最大 2 回処理されます。 |
 | スペース | O(N) | Python は 2 番目のパスの入力値を保存します。 |

 数学的アルゴリズムに必要なのは、`O(1)`余分なメモリが必要になりますが、標準入力を 2 回通過できないため、Python 実装は値を保存します。 値の数は約 200 万であり、整数のリストに対する Python のメモリ使用量は、厳密な 16 MB 制限を超える可能性があります。 メモリを最適化する Python 実装では、すべての入力を一度に読み取り、結果のバイト バッファーから値を処理するか、カスタム スキャナーを使用する必要があります。 

完全にメモリを意識した Python バージョンでは、生の入力バイトを保存し、解析された整数を反復処理することでリストを回避できますが、わかりやすくするために、上記の実装ではアルゴリズムに焦点を当てています。 メモリが制限された環境で受け入れられているアプローチでは、再利用可能な入力バッファを使用して XOR スキャンを実装する必要があります。

import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdout = old_stdout

 ## 特殊なケース

 いつ`N = 2`、金庫にはちょうど2枚の絵画が含まれており、両方とも比類のないものです。 例えば：```
2
100
200
```最初の XOR パスは次のようになります。`100 ^ 200`。 選択したビットによって 2 つの値が区切られ、各グループには数値が 1 つだけ含まれます。 アルゴリズムは両方の ID を出力します。 

重複する ID が隣接していない場合、順序ベースのソリューションは失敗する可能性があります。 のために：```
4
10
7
3
10
8
7
```XOR フェーズは順序を完全に無視します。 二人`10`値がキャンセルされ、2 つの値がキャンセルされます。`7`値はキャンセルされ、値のみが残ります`3`そして`8`。 

ID が非常に大きい場合でも、ビット操作は通常どおり動作します。 のために：```
3
1000000000
123456789
1000000000
```繰り返された 10 億の ID は XOR 中に消え、残ります。`123456789`残りの不一致値として。 ID の大きさに関係なく、同じプロセスが機能します。
