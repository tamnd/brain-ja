 ## 解決策
 ## 問題の理解

 私たちは以下のコレクションを持っています`n`シーケンス。 各シーケンスには、包含区間内のすべての整数が含まれます`[a_i, b_i]`。 間隔は重複する場合があり、出場者が自分の作品を結合すると、同じ数字が複数回表示されます。 最後のリストは、非降順でソートされたすべての間隔のマルチセット和集合です。 

クエリごとに、このソートされたマルチセット内の位置が与えられ、その位置に格納されている値を検索する必要があります。 マージされたリスト内の要素の合計数が最大に達する可能性があるため、位置が非常に大きくなる可能性があります。`10^14`したがって、リストを明示的に構築することは不可能です。 

重要な制約は、間隔とクエリの数です。両方とも最大です。`10^5`、間隔エンドポイントが到達できる間、`10^9`。 すべての間隔内のすべての数値を処理するソリューションには、約`10^14`限界をはるかに超えた操作。 生成された値の数は間隔の数ではなく間隔の長さの合計であるため、生成された値をすべて並べ替えることさえ不可能です。 

クエリについて考える便利な方法は、値について別の質問をすることです。`x`、マージされたリスト内で以下の数値がいくつあるか`x`? それをすぐに答えることができれば、答えの値を二分探索することができます。 課題は、このような多くのカウント クエリに効率的に答えることです。 

単純な実装を壊すエッジケースがいくつかあります。 重複する間隔では、重複した値を保持する必要があります。 例えば：```
2 3
1 3
3 5
1 2 3
```統合されたリストは次のとおりです。```
1 2 3 3 4 5
```出力は次のとおりです。```
1
2
3
```間隔をセットとしてマージする不用意な解決策では、次のような結果が生成されます。`1 2 3`そして複製を失います`3`。 

長さ 1 の間隔も正しく処理する必要があります。 例えば：```
1 2
7 7
1 2
```唯一の数列には 1 つの数値が含まれているため、位置の答えは`1`は`7`。 誤って間隔を半開範囲として扱うと、この値が完全に削除されてしまいます。 

可能な最大の位置に近いクエリにも注意が必要です。```
2 2
1 1000000000
5 5
1000000000 1000000001
```最後の有効な位置は、`1000000001`、その答えは`1000000000`。 マルチセットの合計サイズが超過する可能性があるため、カウントに 32 ビット整数を使用する実装ではオーバーフローが発生します。`10^9`。 

## アプローチ

 直接的なアプローチは、すべての間隔からすべての値を生成し、それらを保存し、並べ替えて、並べ替えられた配列にインデックスを付けることでクエリに応答することです。 これは、必要なマージされたシーケンスを文字通り構築するため、正しいです。 ただし、次のような間隔`[1, 10^9]`すでに 10 億の値が含まれています。 と`10^5`間隔で、生成されるサイズは約に達する可能性があります`10^14`, そのため、このアプローチではデータの保存を完了することさえできません。 

重要な点は、マージされたリスト自体は必要ないということです。 候補値としては`x`、各間隔はプレフィックス数に単純な量を与えます。 

間隔`[a, b]`貢献します:`0`いつ`x < a`。`x - a + 1`いつ`a <= x <= b`。`b - a + 1`いつ`x > b`。 

したがって、すべてのクエリは最小のものを見つけることで解決できます。`x`プレフィックス数が少なくとも要求された位置である。 残りの問題は、これらのプレフィックス数の計算を高速化することです。 

単一のカウント クエリは、すべての間隔をスイープすることで回答できますが、バイナリ検索ステップごとに個別に実行すると、やはり時間がかかりすぎます。 代わりに、すべてのバイナリ検索をまとめて処理します。 

並列二分探索では、すべてのクエリに対して可能な回答の範囲が維持されます。 各ラウンドで、すべての未解決のクエリが中間点を選択します。 これらの中間点を並べ替えて、間隔にわたって 1 回のスイープですべてを評価します。 これにより、繰り返しの作業が軽減されます。`O(nq)`おおよそに`O((n+q)log(10^9))`。 

スイープは、現在アクティブな間隔の寄与を表す線形関数を維持します。 間隔の開始に期間を追加します`x - a + 1`、一方、インターバル終了後のポジションは、そのインターバルを一定の寄与に変換します。 すべての中間値は昇順に処理されるため、すべてのイベントはラウンドごとに 1 回だけ適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計区間の長さ + q) | O(インターバルの合計の長さ) | 遅すぎる |
 | 最適 | O((n + q) log 10^9) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を 2 つのスイープ イベントとして保存します。 位置で`a`、間隔が寄与し始めます`x - a + 1`。 位置で`b + 1`、その寄与は定数になります`b - a + 1`。 

この表現により、間隔内のすべての整数に触れることなく、多くのプレフィックス数を評価できます。 
2. すべてのクエリについて、考えられる答えの二分探索範囲を維持します。 最初の範囲は次のとおりです`1`に`10^9`。 

答えは、プレフィックス数が必要なランクに達する最初の値です。 
3. 二分探索ラウンドを繰り返します。 複数の可能な値がまだあるすべてのクエリについて、その中間点を計算し、すべての中間点を収集します。 

すべての中間点をまとめて処理することで、ソリューションが十分に高速になります。 
4. 中間値を並べ替え、間隔イベントでそれらをスイープします。 次の 3 つの値を維持します。 

アクティブな間隔の現在の傾き。 

アクティブな間隔の現在の切片。 

すでに終了したインターバルからの継続的な貢献。 

位置のカウント`x`は：`slope * x + intercept + constant`。 
5. すべての中間点について、計算されたプレフィックス数とクエリ ランクを比較します。 カウントが十分に大きい場合、答えはこの中間点またはそれより前にあります。 それ以外の場合は、より大きくなります。 
6. 十分なラウンドの後、すべてのクエリ範囲には 1 つの値が含まれます。 その値を出力します。 

なぜ効果があるのか:

 プレフィックスカウント関数が単調であるため、二分探索は有効です。 増加中`x`プレフィックスに番号を追加することのみが可能であり、削除することはできません。 スイープは、すべての間隔を 3 つの可能な状態 (未開始、アクティブ、および終了) に分割することによって、まったく同じプレフィックス カウント関数を計算します。 すべての中間点は同じ間隔寄与ルールを使用して評価されるため、各二分探索の決定により真の応答範囲が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    events = []
    for _ in range(n):
        a, b = map(int, input().split())
        events.append((a, 1, 1 - a))
        events.append((b + 1, -1, b - a + 1))

    events.sort()

    queries = list(map(int, input().split()))

    lo = [1] * q
    hi = [10**9] * q

    def count_values(points):
        points.sort()
        ans = [0] * len(points)

        slope = 0
        intercept = 0
        constant = 0
        event_index = 0

        for value, idx in points:
            while event_index < len(events) and events[event_index][0] <= value:
                pos, ds, di = events[event_index]
                if ds == 1:
                    slope += 1
                    intercept += di
                else:
                    slope -= 1
                    constant += di
                    intercept += di - di
                event_index += 1
            ans[idx] = slope * value + intercept + constant

        return ans

    while True:
        mids = []
        active = False

        for i in range(q):
            if lo[i] < hi[i]:
                active = True
                mids.append(((lo[i] + hi[i]) // 2, i))

        if not active:
            break

        counts = count_values(mids)

        for (_, i), cnt in zip(sorted(mids), counts):
            if cnt >= queries[i]:
                hi[i] = (lo[i] + hi[i]) // 2
            else:
                lo[i] = (lo[i] + hi[i]) // 2 + 1

    print("\n".join(map(str, lo)))

if __name__ == "__main__":
    solve()
```イベントの構築は、実装の詳細の核心です。 開始イベントによりアクティブな間隔の数が増加し、対応するインターセプト調整が追加されます。 終了イベントは、アクティブな線形部分から間隔を削除し、その全長を定数寄与に移動します。 

二分探索配列には、カウントではなく、可能な値のみが格納されます。 中間点の評価により、どちらの半分が有効であるかが決まります。 

到達できる値は、`10^14`要素をカウントするときは、オーバーフローを自動的に回避するため、Python 整数が役立ちます。 また、このコードは、マージされたシーケンスの作成を完全に回避します。 

微妙な点の 1 つは、終了イベントが次の時点で発生することです。`b + 1`、 ない`b`。 で`b`間隔は依然としてその線形公式によって寄与されます。 次の値でのみ、一定の寄与になります。

 ## 特殊なケース

 次のような重複する間隔の場合:```
2 3
1 3
3 5
1 2 3
```スイープは開始イベントを作成します`1`そして`2`、その後イベントを終了します`3`そして`5`。 中間点に達すると`3`、両方の間隔はアクティブな式を通じて寄与するため、プレフィックス数には両方のコピーが含まれます。`3`。 

単一値間隔の場合:```
1 2
7 7
1 2
```間隔は次から始まります`7`そしてで終わります`8`。 値`7`間隔がアクティブである間カウントされ、終了イベントはそれが終わるまで発生しないため、答えは残ります。`7`。 

最大の境界ケースの場合:```
2 2
1 1000000000
5 5
1000000000 1000000001
```最初のクエリは、長い間隔内の最後の値に収束します。 2 番目のクエリは、2 番目の間隔からの追加値に達します。 プレフィックス カウンタは、間隔を拡張することはなく、その寄与式を評価するだけであるため、両方を処理します。
