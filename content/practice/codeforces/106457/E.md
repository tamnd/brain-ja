 ## 問題の理解

 暗号混合関数のように動作しますが、構造的には代数的に可逆的な、決定論的な 64 ビット変換の入力を構築するように求められます。 

各クエリは 32​​ ビットのターゲット値を与えます`t`。 このようなターゲットごとに、2 つの異なる 64 ビット符号なし整数を出力する必要があります。`a`そして`b`同じハッシュ手順を両方に適用すると、正確に結果が得られます。`t`。 

ハッシュはレイヤーで構築されます。 まず、入力`x`は、固定乗数とオフセットを使用して 64 ビット算術で線形変換され、その後、そのビットが回転されます。 その後、64 ビット値は 32 ビットの上位半分と下位半分に分割され、最終的なハッシュはこれらの半分の XOR になります。 

重要な要件は、ハッシュを順方向に計算することではなく、同じ最終 32 ビット値に到達する 2 つの異なるプリイメージを構築することです。 

制約により最大 200,000 のクエリが許可され、すべての出力は独立した構造になります。 これにより、クエリごとの検索や確率的な衝突の検出が除外されます。 どのソリューションもクエリごとに一定時間である必要があります。 

素朴なアイデアは、2 つのランダムな 64 ビット数値が同じ数値に衝突するまで総当たり攻撃を行うことです。`t`。 入力が 2⁶⁴ であるのに対し、ハッシュ範囲は 23² のみであり、ランダム検索では大規模な場合に制限時間内に保証されないため、これはすぐに失敗します。`q`。 

より微妙な失敗モードは、内部構造に気付かずにハッシュを直接反転しようとした場合に発生します。 回転と XOR を不可逆的なブラックボックス操作として扱うと、問題は暗号反転タスクのように見えますが、その構築は意図的に代数的であり、段階的に完全に反転可能です。 

重要なエッジ ケースは、すべてのクエリが同じ値であっても 2 つの異なる値を生成する必要があることです。`t`したがって、単一の計算されたプリイメージでは不十分です。 この構築では、少なくとも 2 つの異なる有効なプリイメージを明示的に生成する必要があります。

 ## アルゴリズムのチュートリアル

 1. 対象のハッシュ値を修正する`t`現在のクエリの場合。 最終的な XOR 条件を直接満たす中間の 64 ビット値を構築します。 
2. 任意の 32 ビット値を選択します`A`下半身用。 ハッシュを定義する方程式が一意に制約しないため、この値は自由です。 
3. 上半分を定義する`B`として`B = A XOR t`。 これにより、次のことが保証されます`A XOR B = t`、分割後の最終ハッシュ条件を満たします。 
4. 半分を結合して 64 ビットの数値にする`z = (A << 32) | B`。 これは、最終的な分割の直前の段階で有効なプリイメージを表します。 
5. 異なる値で同じ構築を繰り返します。`A2`、 例えば`A + 1`、2 番目の個別の 64 ビット値を生成します`z2`。 
6. 前に適用したビット回転を反転します。 回転は全単射であるため、逆の回転を適用して回転前の状態を回復します。 
7. 定数乗算器の逆剰余を使用して、2⁶⁴ を法とする乗算と加算を反転します。 これにより、元の入力値が回復されます`a`そして`b`。 

各ステップが安全である主な理由は、最後の XOR を除くすべての変換が 64 ビット整数の全単射であるため、構築されたソリューションの一意性が保持されるためです。 

### なぜ効果があるのか

 ハッシュ関数は、最後の XOR ステージでのみ 64 ビット状態を 32 ビットに削減します。 その時点までは、すべての変換は反転可能であり、1 対 1 のマッピングが保持されます。 方程式`A XOR B = t`64 ビット空間に対する 32 ビットのアフィン制約を定義し、有効な解を 23² 個残します。 Selecting two different free choices for`A`guarantees two distinct valid intermediate states. Since the rest of the pipeline is bijective, these extend back uniquely to two distinct original inputs.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK64 = (1 << 64) - 1

M = 0x9E3779B97F4A7C15
C = 0xD1B54A32D192ED03

def rotl64(x, r):
    return ((x << r) & MASK64) | (x >> (64 - r))

def rotr64(x, r):
    return ((x >> r) | (x << (64 - r))) & MASK64

def solve():
    q = int(input())
    invM = pow(M, -1, 1 << 64)

    for _ in range(q):
        t = int(input())

        # two different choices for low half
        A1 = 0
        B1 = A1 ^ t
        z1 = (A1 << 32) | B1

        A2 = 1
        B2 = A2 ^ t
        z2 = (A2 << 32) | B2

        # invert rotation: p = rotl64(y, 23)
        y1 = rotr64(z1, 23)
        y2 = rotr64(z2, 23)

        # invert y = Mx + C mod 2^64
        x1 = (invM * ((y1 - C) & MASK64)) & MASK64
        x2 = (invM * ((y2 - C) & MASK64)) & MASK64

        print(x1, x2)

if __name__ == "__main__":
    solve()
```このコードは、数学的逆変換パイプラインを正確に反映しています。 構築は XOR 制約から始まり、有効な 64 ビット中間状態を構築してから、逆回転と逆アフィン変換を適用します。 引き算`(y - C)`is masked to ensure unsigned 64-bit wraparound before multiplying by the modular inverse.

 A subtle implementation detail is that every operation must be masked to 64 bits, since Python integers do not naturally overflow. Missing the mask breaks equivalence with unsigned arithmetic.

 ## 特殊なケース

 いつ`t = 0`、XOR 制約は次のようになります。`A = B`。 これは解空間を崩壊させるように見えるかもしれませんが、実際には対称性を最大化します。 この構造では、フォームの有効な中間値が無限に生成されます。`(A, A)`、そして異なるものを選択する`A`値は、反転後の明確な最終答えを保証します。
