 ## 解決策
 ## 問題の理解

 カルストの表面は、測定された高さの一次元リストによって記述されます。 すべての高さを新しい値に置き換えることはできますが、位置を変更すると、古い高さと新しい高さの絶対差に等しいコストがかかります。 最終的なシーケンスは滑らかでなければなりません。つまり、隣接する位置は指定された制限を超えて異なってはなりません。`k`。 タスクは、元のシーケンスを有効なスムーズ シーケンスに変換するために必要な最小の総コストを見つけることです。 

入力には、測定値の数、隣接する最終高度間の最大許容差、および元の高度値が含まれます。 出力は、すべての個別の変更の可能な最小合計です。 

測定可能回数は`200000`したがって、考えられるすべての最終的な高さを試したり、すべての高さにわたって完全な動的プログラミング テーブルを維持したりするソリューションは機能しません。 高度の値は次のように大きくすることができます。`10^9`、これは座標ベースの DP を除外します。 可能な値の範囲ではなく、コスト関数の構造を活用する必要があります。 

重要な観察は、位置間の移行が、以前に選択された高さの間隔にのみ依存するということです。 現在の身長が`x`、前の高さは内側にある必要があります`[x-k, x+k]`。 可能な値に対するコスト関数`x`は凸状かつ区分的に線形のままであるため、可能なすべての高さではなく、DP 状態全体の形状を保存できます。 

いくつかの特殊なケースは見落とされがちです。 もし`k`が十分に大きい場合、元のシーケンスがすでに条件を満たしているため、変更する必要はありません。 例えば：```
Input:
3 10
5 7 5

Output:
0
```常に中間値を変更する貪欲なアプローチでは、依然として変化する可能性があります。`7`ですが、元々の違いは`2`, したがって、正解はゼロです。 

もう 1 つの注意が必要なケースは、最適なソリューションが、山を下げるだけ、または谷を上げるだけではなく、両方向に値を変更する場合です。 例えば：```
Input:
4 1
0 10 0 10

Output:
16
```不注意なアプローチでは、すべての低い値を維持し、高い値だけを減らそうとし、さらに悪い結果が生じる可能性があります。 すべての位置が隣接するものの許容範囲に影響を与えるため、最適なスムーズ シーケンスでは値のバランスがとれます。 

3 番目の特殊なケースは、最適な答えが単一の高さではなく平らな領域である場合に発生します。 例えば：```
Input:
2 5
0 10

Output:
0
```両方の元の値はすでに許容差内にあります。 一意の最適な最終高さが常に存在すると仮定する方法は、そのような間隔では失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、可能な最終高さに対して動的プログラミングを使用することです。 させて`dp[i][x]`最初の処理後の最小コストになります`i`位置と高さで終わる`x`。 移行は次のとおりです。```
dp[i][x] = |a[i] - x| + min(dp[i-1][y])
```どこ`y`満たさなければなりません`|y-x| <= k`。 

これは正しいです。有効なシーケンスはすべて で終わるからです。`x`その間隔内の有効な以前の高さから取得する必要があります。 ただし、可能な高さの数は膨大です。 からの範囲だけを考えたとしても`0`に`10^9`、状態空間を処理することは不可能になります。 最悪の場合は次のことが必要になります`10^14`操作。 

重要な構造は、すべての遷移が凸性を維持することです。 現在の高さの関数として DP 値を記述する関数は、常に凸の区分線形関数です。 絶対値項は V 字型の関数を追加し、スライド間隔にわたって最小値を取得しても、最小プラトーが位置する場所のみが変化します。 

すべての高さを保存するのではなく、関数の傾きが変化する場所を保存します。 凸区分線形関数は、これらのブレークポイントとその最小値によって完全に決定されます。 これがスロープトリックの考え方です。 

データ構造は 2 つのヒープを維持します。 左側のヒープには最小値の左側にブレークポイントが格納され、右側のヒープには右側にブレークポイントが格納されます。 関数の最小値は別に保存されます。 追加`|x-a[i]|`新しい V 字形を挿入し、スライディング ウィンドウの最小値操作はブレークポイントを遅延的に移動することによって有効な最小間隔をシフトします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 高さの範囲) | O(高さの範囲) | 遅すぎる |
 | スロープトリック付き凸DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スロープトリック構造を使用して現在の DP 機能を維持します。 最初はコスト関数はどこでもゼロであるため、構造はブレークポイントの空のセットと最小値のゼロから始まります。 
2. 高度ごとに`a[i]`、まず、以前の高さを距離内に制限する操作を適用します。`k`現在の高さから。 これにより、古い関数が間隔内の最小値に置き換えられます。`[x-k, x+k]`。 

これが効率的に実行できる理由は、凸関数は最小のスライド間隔を取った後でも形状を維持するためです。 傾斜変化の位置のみが移動します。 
3. を適用して現在の高さを変更するコストを追加します。`|x-a[i]|`。 

これにより、新しい V 字型の部分が関数に挿入されます。 傾きは両側で 1 つずつ変化します`a[i]`, そのため、関数を再構築せずに 2 つのヒープを更新できます。 
4. すべての位置が処理された後、スロープ トリック構造に保存されている最小値が答えになります。 

なぜ効果があるのか:

 不変条件は、最初の処理後の`i`位置では、維持された凸関数は、可能なすべての高さで終わる滑​​らかなプレフィックスを形成するための最小限のコストを表します。 スライド最小ステップでは、滑らかさの制約によって許可される高さが正確に考慮され、絶対値の加算により新しい位置の修正コストが考慮されます。 どちらの操作でも表現が保存されるため、最終的に保存された最小値が最適な総コストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

class SlopeTrick:
    def __init__(self):
        self.left = []
        self.right = []
        self.add_left = 0
        self.add_right = 0
        self.value = 0

    def push_left(self, x):
        heapq.heappush(self.left, -(x - self.add_left))

    def push_right(self, x):
        heapq.heappush(self.right, x - self.add_right)

    def top_left(self):
        return -self.left[0] + self.add_left

    def top_right(self):
        return self.right[0] + self.add_right

    def pop_left(self):
        x = self.top_left()
        heapq.heappop(self.left)
        return x

    def pop_right(self):
        x = self.top_right()
        heapq.heappop(self.right)
        return x

    def add_x_minus_a(self, x):
        if self.left:
            self.value += max(0, self.top_left() - x)
        self.push_left(x)
        self.push_right(self.pop_left())

    def add_a_minus_x(self, x):
        if self.right:
            self.value += max(0, x - self.top_right())
        self.push_right(x)
        self.push_left(self.pop_right())

    def add_abs(self, x):
        self.add_x_minus_a(x)
        self.add_a_minus_x(x)

    def sliding_min(self, left_shift, right_shift):
        self.add_left += left_shift
        self.add_right += right_shift

n, k = map(int, input().split())
a = list(map(int, input().split()))

st = SlopeTrick()

for x in a:
    st.sliding_min(-k, k)
    st.add_abs(x)

print(st.value)
```2 つのヒープには、凸 DP 関数の傾き変化点が格納されています。 Python では最小ヒープのみが提供されるため、左側のヒープは最大ヒープであり、負の値を格納することで実装されます。 右側のヒープは通常の最小ヒープです。 

の`sliding_min`関数はすべてのブレークポイントを個別に移動しません。 両側のすべてのブレークポイントが一緒に移動するため、遅延オフセットのみが変更されます。 これにより、各更新が対数的に維持されます。 

操作の順序が重要です。 新しい位置の修正コストを追加する前に、有効な以前の高さを適用する必要があります。 これら 2 つの操作を逆にすると、現在の値がそれ自身の遷移に誤って影響を与えることになります。 

最大数があるため、答えは大きくなる可能性があります。`200000`ポジションや変更ごとに最大で次の費用がかかる場合があります`10^9`ですが、Python の整数はオーバーフローの問題なくこれを処理します。
