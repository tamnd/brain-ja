 ## 解決策
 ## 問題の理解

 この問題では、可能な限り最大の合計出荷額が得られる箱のサイズが求められます。 船は、その容量が選択したクレート サイズで正確に割り切れる場合にのみ使用できます。 クレートのサイズを選択する場合`x`、容量が次の倍数であるすべての船舶`x`貢献する`x`1 つのクレート内に不安定なコアを 1 つだけ運ぶことができるため、価値の単位になります。 したがって、合計値は次のようになります。`x * (number of capacities divisible by x)`を見つける必要があります`x`この値を最大化します。 複数のクレート サイズが同じ最大値を生成する場合は、最も小さいサイズが選択されます。 

入力は船舶の容量のリストで構成されます。 各容量は最大で`10^6`、最大で`10^6`船。 値の上限がキーの詳細です。 考えられるすべての容量のペアを反復処理すると、時間がかかりすぎます。 100万隻の船で、`O(N^2)`アプローチには前後が必要です`10^12`通常のコンテストの制限に収まりきらない操作。 最大容量において線形に近いソリューションが必要です。 

トリッキーなケースは、入力に直接現れない約数や同数に起因します。 

例えば：```
Input
5
2 3 3 4 5

Output
3
```不注意なアプローチでは、容量として表示される値のみをテストする可能性があります。 この場合、これはたまたま機能しますが、一般的には有効なアイデアではありません。 最適なクレート サイズは、リストにない数値になる場合があります。 

別の例:```
Input
5
2 4 6 8 10

Output
5
```クレートのサイズ`5`価値を与える`5 * 2 = 10`、容量があるため`10`そして`?`待って、ただ`10`で割り切れます`5`したがって、この出力は正しくありません。 実際の計算は次のとおりです。```
x = 2  -> 2 * 5 = 10
x = 5  -> 5 * 1 = 5
```答えは次のとおりです。```
Input
5
2 4 6 8 10

Output
2
```これにより、約数の数と割り切れる容量の数を混同する実装が捕捉されます。 

ネクタイケースも誤って扱いやすいです。```
Input
4
1 2 3 6

Output
3
```ここ：```
x = 1 -> 1 * 4 = 4
x = 2 -> 2 * 2 = 4
x = 3 -> 3 * 2 = 6
x = 6 -> 6 * 1 = 6
```両方`3`そして`6`最大値を与えるので、小さい方を返す必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべてのクレート サイズを試し、そのサイズで割り切れる容量を数えることです。 クレートサイズの場合`x`、すべてをスキャン`N`容量が与える`O(N)`仕事。 最大容量まで対応できるので、`10^6`、可能な限りのことを試みる`x`価値観が与える`10^12`最悪の場合、動作が遅すぎます。 

問題の構造から、より良い解決策が得られます。 実際のところ、私たちは個人の能力を気にしていません。 各容量が何回発生するかを知る必要があるだけです。 周波数配列を構築した後、考えられるクレート サイズごとに別の質問をすることができます。`x`、入力値の倍数はいくつありますか`x`?

 これは、ふるい内の倍数を数えるのとまったく同じパターンです。 あらゆる人にとって`x`、訪問します`x, 2x, 3x, ...`そしてそれらの容量の周波数を加算します。 操作の数はおよそ次のとおりです。`M/1 + M/2 + M/3 + ... + M/M`どこ`M`が最大容量です。 これは`M log M`、これは十分に高速です`M = 10^6`。 

ブルートフォースはあらゆる可能性をチェックするため機能しますが、同じ割り算作業を何度も繰り返します。 ふるい式計数では、頻度情報が再利用され、各約数の関係が 1 回処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N * M) | お(1) | 遅すぎる |
 | 最適 | O(M log M + N) | お(お) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての船舶の容量を読み取り、各容量が何回表示されたかを保存します。 

周波数配列により、「収容能力のある船舶の数」を答えることができます。`v`「一定時間内に。
 2. 可能なすべてのクレート サイズを反復処理します。`x`から`1`最大容量まで。 

少なくとも 1 つの容量を分割できるサイズのみを考慮する必要があります。 値を大きくしても何も貢献できません。 
3. 現在のところ`x`、のすべての倍数の頻度を合計します。`x`。 

訪問します`x, 2x, 3x, ...`なぜなら、それらはまさにそのサイズのクレートを使用できる容量だからです。`x`。 
4. 合計支払い額を次のように計算します。`x * count`どこ`count`このクレート サイズを使用できる船舶の数です。 
5. これまでに確認された最良の回答を維持します。 配当が大きい場合、または配当が等しい場合に答えを置き換えます。`x`より小さいです。 

タイルールはスキャン中に処理されるため、追加の処理は必要ありません。 

なぜ効果があるのか:

 固定クレート サイズの場合`x`、配備できる船は、容量が の倍数である船のみです。`x`。 アルゴリズムは、すべての倍数の周波数を合計することにより、それらの船舶を正確にカウントします。`x`。 したがって、考えられるすべての場合の計算された支払いは、`x`は正しいです。 すべての有効なクレート サイズが検査され、最大ペイアウトが維持されるため、最終的な答えは最適なクレート サイズになります。 同点の支払いが見つかった場合は必ず同点条件が適用されるため、最小の有効なクレート サイズが返されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mx = max(a)

    freq = [0] * (mx + 1)
    for v in a:
        freq[v] += 1

    best_value = 0
    answer = 1

    for x in range(1, mx + 1):
        count = 0
        for multiple in range(x, mx + 1, x):
            count += freq[multiple]

        value = x * count

        if value > best_value or (value == best_value and x < answer):
            best_value = value
            answer = x

    print(answer)

if __name__ == "__main__":
    solve()
```入力サイズが大きく、元のリストを繰り返しスキャンすると時間が無駄になるため、周波数配列が最初に構築されます。 配列のインデックスは容量を表し、格納された値はその容量を持つ船舶の数を表します。 

外側のループでは、考えられるすべてのクレート サイズが考慮されます。 内側のループはその倍数を直接ジャンプし、寄与できない容量のチェックを回避します。 掛け算`x * count`およそに到達できる`10^12`ですが、Python の整数はオーバーフローを心配することなくこれを処理します。 

更新条件にはタイブレーク ルールが含まれています。 2 つのクレート サイズが同じ配当を生成する場合、小さいサイズが前の答えに置き換わります。

 ## 特殊なケース

 単一の船の場合:```
Input
1
1
```唯一可能なクレートのサイズは、`1`。 周波数アレイには、最大容量の 1 隻の船舶が含まれています`1`、したがって、支払いは`1`、アルゴリズムは戻ります`1`。 

繰り返し容量の場合:```
Input
5
7 7 7 7 7
```クレートのサイズ`7`支払いを与える`7 * 5 = 35`。 クレートの価値は船の数が増加するよりも速く減少するため、除数が小さくなるほど配当は低くなります。 アルゴリズムは、頻度配列を通じて 5 つの出現をカウントし、`7`。 

ネクタイの場合:```
Input
4
1 2 3 6
```アルゴリズムは以下を計算します。```
x = 3: count = 2, payout = 6
x = 6: count = 1, payout = 6
```いつ`x = 6`が処理され、支払いは現在の最高のものと一致しますが、`6`よりも大きいです`3`、したがって答えは残ります`3`。 

最大制限時の容量の場合:```
Input
6
1000000 500000 250000 125000 2 4
```周波数配列は最大でインデックスをサポートします。`1000000`、各候補サイズの倍数のみを訪問するため、複数の走査は引き続き機能します。 このアルゴリズムは、操作の数に比例してメモリを割り当てるのではなく、最大容量にのみ比例してメモリを割り当てます。
