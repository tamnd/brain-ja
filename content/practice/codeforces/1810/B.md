 ## 解決策
 ## 問題の理解

 一つのキャンディーから始まり、正確に到達したい$n$最大40の呪文を使用するキャンディー。 各呪文は、現在のキャンディーの数を 2 倍にして 1 を引くか、2 倍にして 1 を追加します。 入力は複数のテスト ケースで構成され、それぞれにターゲット番号が与えられます。$n$。 各テスト ケースの出力は、次のいずれかに達する一連の呪文の選択肢です。$n$40歩以内または`-1`それが不可能な場合。 

境界は狭いですが、管理可能です。 と$n$まで$10^9$40 の操作が許可されている場合、単純な総当たりのフォワード シミュレーションは危険です。 すべてのシーケンスを直接試すと指数関数的になります。$2^{40}$考えられるシーケンスは、私たちが計算できる範囲をはるかに超えています。 これは、シーケンスを数学的に推論するか、リバース エンジニアリングする必要があることを意味します。 

エッジケースは次のような場合です$n$非常に小さいです、例えば$n=2$。 1つのキャンディーに最初の呪文を使用すると、$2 \cdot 1 - 1 = 1$- 進歩なし。 2番目の呪文を使用すると、$2 \cdot 1 + 1 = 3$、オーバーシュート 2。したがって、すべてがそうであるわけではありません。$n$到達可能であり、すべてを想定した不用意な実装$n$に到達可能である場合、誤ってシーケンスを構築しようとします。$n=2$。 

もう 1 つの特殊なケースは、近くに多数の数値が存在する場合です。$10^9$。 実装が逆方向トレース時に整数の除算または減算を適切に処理しない場合、切り捨てエラーにより大きなターゲットで失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、1 から 40 の手までのあらゆる可能な一連の呪文を試し、それぞれのフォワードをシミュレートします。 これが機能するのは、各呪文が決定的で常にキャンディーの数が増加するためです。そのため、最終的には次のいずれかに到達します。$n$または40ステップを超えます。 問題はシーケンスの数です。$2^{40} \approx 10^{12}$、これはどのコンピュータにとっても大きすぎます。 

重要な洞察は、逆向きに作業することで得られます。 もし持っていれば$n$キャンディー、私たちは尋ねます：どの呪文が生成された可能性がありますか$n$前のステップで？ 最後の呪文が`1`(2x-1) の場合、以前のキャンディーの数は$(n+1)/2$。 最後の呪文が`2`(2x+1) の場合、以前のキャンディーの数は$(n-1)/2$。 これらは両方とも整数でなければなりません。 この推論を繰り返すと、呪文の順序を逆に再構築することができます。 

逆方向に作業すると、各動きが呪文の逆に直接一致するため、有効であることが保証されます。 キャンディーが 1 個に達すると停止するため、シーケンスが正しく開始されることが自動的に確認されます。 どこかの時点で逆方向の数値が整数または負でない場合、到達したことがわかります。$n$不可能です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、ターゲット番号を読み取ります。$n$。 空のリストを初期化して呪文シーケンスを保存します。 
2. その間$n > 1$、どの呪文がそれを生成した可能性があるかを確認してください。 もし$(n+1)$が 2 で割り切れる場合、最後の呪文は次のようになった可能性があります。`1`。 追加`1`シーケンスに合わせて更新します$n = (n+1)//2$。 それ以外の場合は、$(n-1)$が 2 で割り切れる場合、最後の呪文は次のようになった可能性があります。`2`。 追加`2`シーケンスに合わせて更新します$n = (n-1)//2$。 
3. どちらの条件も当てはまらない場合は到達不可能$n$呪文を使って1から。 出力`-1`。 
4.到達後$n=1$、シーケンスを逆にして、最初から最後までの呪文の順序を取得します。 
5. シーケンスとシーケンス自体の長さを出力します。 シーケンスが 40 呪文を超える場合も、不可能として扱います。 

このアルゴリズムが機能するのは、各ステップが呪文関数の逆に厳密に従っているためです。 不変条件は、各後退ステップ後の現在の数値が、1 つの呪文を使用して次の数値を生成した場合とまったく同じであるということです。 これにより正確さが保証され、推測やフォワード シミュレーションが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        spells = []
        original = n
        while n > 1:
            if (n + 1) % 2 == 0:
                spells.append(1)
                n = (n + 1) // 2
            elif (n - 1) % 2 == 0:
                spells.append(2)
                n = (n - 1) // 2
            else:
                spells = None
                break
        if spells is None or len(spells) > 40:
            print(-1)
        else:
            spells.reverse()
            print(len(spells))
            print(' '.join(map(str, spells)))

if __name__ == "__main__":
    solve()
```コードはテスト ケースの数を読み取り、各ターゲットを反復処理します。$n$。 整数の除算を使用して逆方向に作業することで、呪文シーケンスを逆に再構築します。 シーケンスを逆にすると、正しい順方向の順序が得られます。 アルゴリズムは 40 手を超えるシーケンスを明示的にチェックして出力します。`-1`不可能なとき。 エッジケースのような$n=2$どちらも自然に処理されないため、$(2+1)/2$または$(2-1)/2$は 1 になる整数です。

 ## 特殊なケース

 のために`n=2`、アルゴリズムがチェックします`(2+1)/2=1.5`そして`(2-1)/2=0.5`。 どちらも整数ではないため、アルゴリズムは次のように出力します。`-1`。 これにより、無効なシーケンスが防止されます。 

のために`n=1`、呪文は必要ありません。 このアルゴリズムは自然に長さ 0 の空のシーケンスを生成します。 

非常に大きい場合`n`、各後退ステップは約半分になり、40 ステップを超えないことが保証されます。 例えば、`n=10^9`各ステップで約 2 ずつ減少し、約 30 になります。
