 ## 解決策
 ## 問題の理解

 配列と固定コストの 2 つの演算が与えられています。 

費用のために既存の要素を削除する場合があります`c`、またはコストに任意の正の整数を挿入します`d`。 

目標は、配列をある程度の長さの有効な順列に変換することです。`m`。 長さの順列`m`～のすべての数字が含まれます`1`を通して`m`まさに一度。 要素が現在ある場所に保持し、新しい値をどこにでも挿入できるため、順序は重要ではありません。 

タスクは、最小の総コストを見つけることです。 

最も重要な観察は、最終的な順列がその最大値によって完全に決定されるということです。 最後の順列に長さがある場合`m`の場合、最終的な値のセットは正確に次のようにする必要があります。`{1, 2, ..., m}`。 

制約が十分に大きいため、二次解は不可能です。 すべての配列の長さの合計は最大でも`2·10^5`を強く示唆しています。`O(n log n)`テスト ケースごとのソリューション。並べ替えが大部分を占めます。 すべてのサブセットを試行したり、候補の長さごとに配列全体を繰り返しスキャンしたりするアプローチでは、制限を超えることになります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
n = 3
a = [1, 1, 1]
c = 5
d = 100
```正しい答えは、`10`、2 つのコピーを削除し、1 つのコピーを保持することによって取得されます。`1`、順列を生成します`[1]`。 

不注意な解決策は、より大きな順列を構築しようとし、不必要に莫大な挿入コストを支払おうとする可能性があります。 

もう 1 つの注意が必要なケースは次のとおりです。```
n = 2
a = [100, 100]
c = 1
d = 1
```最善の戦略は 1 つを削除することです`100`、もう一方を削除します`100`を挿入してから、`1`、合計費用`3`。 

長さの順列が異なるため、大きな値を保持しても役に立ちません。`m`より大きい数値を含めることはできません`m`。 

重複には特別な注意が必要です。```
n = 4
a = [1, 2, 2, 3]
c = 10
d = 1
```正しい答えは、`10`、重複を 1 つ削除します`2`。 

最初に重複を削除せずに欠損値を単純にカウントすると、誤った結果が生成されます。これは、順列ではすべての値が 1 回だけ出現する必要があるためです。 

## アプローチ

 ブルートフォースの観点は、最終的な順列の長さを選択することです`m`。 

一度`m`は固定されており、すべての配列要素は次の値より大きい`m`削除する必要があります。 からの値の中で`1`に`m`、それぞれ 1 つのコピーのみが残されます。 欠損値を挿入する必要があります。 可能なすべてのコストを計算できます`m`そして最低限のものを取る。 

難しいのは、`m`非常に大きい可能性があります。 配列の値が到達するので、`10^9`、すべての可能な長さを直接チェックすることは不可能です。 

重要な観察は、配列内にすでに存在する値のみが、保持される最大値として意味のある役割を果たすことができるということです。 

概念的に配列を並べ替えて重複を削除するとします。 個別の値を次のようにします。```
v1 < v2 < ... < vk
```私たちがそう決めたら`vi`最終的な順列で保持される最大値であり、その後のすべての個別の値です。`vi`削除する必要があります。 

最初のものの中には`i`個別の値の場合、それぞれのコピーを 1 つだけ保持します。 それらを形にするために`{1,2,...,vi}`、欠落している数字をすべて以下に挿入する必要があります`vi`。 

欠損値の数は次のとおりです。```
vi - i
```あるはずだから`vi`の数字`{1,...,vi}`、しかし、ただ`i`現在、そこには個別の値が存在します。 

これにより、問題は個別の値ごとに 1 つの候補を評価するように変換されます。 

すべてを削除して順列を構築する特殊なケースもあります。`[1]`。 最終的な配列は空であってはいけないため、そのコストは次のようになります。```
n * c + d
```元の要素をすべて削除してから挿入します`1`。 

並べ替え後、すでに処理された要素の数を維持しながら、個別の値を左から右にスキャンできます。 その後、すべての候補者を一定時間内に評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | あらゆる可能な長さにわたる総当たり攻撃 | O(max(a)) 以上 | お(1) | 遅すぎる |
 | 個別値候補のソート + 評価 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートします。 
2. すべての要素を削除し、単一の要素を挿入するというコストをかけて、回答を初期化します。`1`。```
ans = n*c + d
```これにより、少なくとも 1 つの有効な解決策が保証されます。 
3. ソートされた配列をスキャンし、最初に出現した各個別の値のみを処理します。 
4. しましょう`cnt`これまでに処理された個別の値の数になります。 
5. 新しい個別の値に到達したとき`x`、 扱う`x`最終的な置換に残る最大値として。 
6. 範囲内の欠損値の数`[1, x]`は：```
missing = x - cnt
```あるから`cnt`個別に保持される値ですが、順列は次で終わります。`x`正確に必要です`x`価値観。 
7. 現在の位置以降のすべての要素を削除する必要があります。 現在のインデックスが`i`ソートされた配列では、次のようになります。```
deletions = n - i - 1
```これらは、重複やより大きな値を含む、厳密に右側のすべての要素です。 
8. この候補者の総コストは次のとおりです。```
deletions*c + missing*d
```9. 最小の回答を更新します。 
10. すべての個別の値が処理されるまで続行します。 
11. 見つかった最小コストを出力します。 

### なぜ効果があるのか

 並べ替え後、最適な最終的な並べ替えを検討します。 保持される元の最大値を次のようにします。`x`。 

より大きいすべての値`x`長さの順列が異なるため、削除する必要があります`x`それらを含むことはできません。 保持された値間の重複もすべて削除する必要があります。 スキャンでは、それぞれの個別の数値の最初の出現のみを保持することで、これを自然に考慮します。 

以下を超えない個別の値の間で`x`、 その通り`cnt`値はすでに存在します。 有効な置換`{1,...,x}`すべてが必要です`x`価値観、まさにその通り`x-cnt`数字を挿入する必要があります。 他の挿入カウントは機能しません。 

したがって、考えられるすべての最適な解決策は、何らかの個別の値を選択することに対応します。`x`最大の保持値として、アルゴリズムがその選択の正確なコストを評価します。 すべての候補がチェックされるため、見つかった最小コストが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, c, d = map(int, input().split())
        a = list(map(int, input().split()))

        a.sort()

        ans = n * c + d

        cnt = 0

        for i in range(n):
            if i > 0 and a[i] == a[i - 1]:
                continue

            cnt += 1

            missing = a[i] - cnt
            deletions = n - i - 1

            cost = deletions * c + missing * d
            ans = min(ans, cost)

        print(ans)

solve()
```配列は最初に並べ替えられ、重複が隣接し、より大きな値がより小さな値の後に表示されます。 

変数`cnt`検出された個別の値の数をカウントします。 現在の個別の値が`a[i]`、これまでに見られたすべての個別の値を維持し、`a[i]`最終的な順列の最大値。 

表現:```
missing = a[i] - cnt
```からいくつの数値を計算します`1`に`a[i]`は不在です。 

表現:```
deletions = n - i - 1
```すべての要素を右側にカウントします。 それらの要素は次の場合には残りません。`a[i]`が最大保持値として選択されます。 

微妙な点は初期化です。```
ans = n * c + d
```これは、すべてを削除して 1 つを挿入することを表します。`1`。 この候補がないと、既存のすべての値が非常に大きい場合が正しく処理されなくなります。 

Python の整数は問題の制限までの値を自動的に処理するため、オーバーフローの心配はありません。
