 ## 解決策
 ## 問題の理解

 私たちはカタツムリが高さ不明の木に登るというシナリオを扱っています。 それぞれのカタツムリには 2 つの数字があり、`a`そして`b`、日中はメーターが上昇し、夜にはメーターが滑り落ちることを表します。 最初のカタツムリは日数を報告します`n`頂上に到達するのに時間がかかりました。 後続のカタツムリは、自分の日数を報告するか、何日かかるかを尋ねます。 私たちの仕事は、報告されたカタツムリから考えられる樹高の一貫したセットを維持し、その情報に基づいて今後の質問に答えることです。 

それぞれのタイプ 1 イベントは、以下から推定される木の高さに関する主張です。`(a, b, n)`。 タイプ 2 のイベントでは正確な日数カウントが要求されますが、これは木の高さが以前に認められた主張から一意に決定される場合にのみ可能です。 

重要な課題は矛盾に対処することです。 新しいクレームが、以前に受け入れられたクレームと互換性のある整数の高さに対応できない場合は、それを無視します。 クエリの場合、考えられる木の高さの現在の範囲を考慮して、日数が決定的であるかどうかを判断する必要があります。 木の高さは正の整数であり、最大の値を扱います。$10^9$, そのため、毎日を総当たり的にシミュレーションすることは不可能です。 

カタツムリが初日で頂上に到達するのに十分であると報告した場合、明らかではないエッジケースが発生します。 たとえば、次の場合`a = 5, b = 2, n = 1`、木の高さはどこからでも`1`に`5`メートル。 毎日の正味の進捗のみを考慮する単純なアプローチ (`a-b`) は有効な高さを拒否するか、クエリを正しく計算できない可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのクエリに対して毎日すべてのカタツムリをシミュレートします。 のために`n`これには何日もかかります`O(n)`クエリごとに。 まで`2*10^5`イベントや木の高さまで$10^9$、これはすぐに不可能になります。 までを考慮する必要があります$10^9$最悪の場合には繰り返しが行われますが、これは実現可能性をはるかに超えています。 

洞察としては、タイプ 1 の各イベントが、単一の数値ではなく、考えられる木の高さの範囲を提供するということです。 当日`n`、カタツムリが登る`a`そして滑る`b`間の高さに達した可能性があります`a + (n-1)*(a-b)`(今日までの正味の進捗状況`n-1`最終日にはフルクライムを加えます）そして`n*a`（滑る前に頂上に到達した場合の最大上昇量）。 すべての受け入れられたタイプ 1 イベントと一致するグローバルな最小および最大の木の高さを追跡することにより、新しいイベントが以前の知識と矛盾するかどうかを迅速に判断できます。 タイプ 2 クエリは、次のことを確認することによって解決されます。`(a, b)`有効範囲内のすべての高さについて、正確に 1 日のカウントに達することしかできません。 所要日数が範囲内で異なる場合はレポートします。`-1`。 

このアプローチにより、問題は単純な算術演算と範囲交差チェックに縮小され、すべての処理を処理できるようになります。`2*10^5`イベントを効率的に行う`O(1)`イベントごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * h) | お(1) | 遅すぎる |
 | 範囲の交差 | O(q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`min_height = 1`そして`max_height = INF`可能なすべての正の木の高さを表します。 INF は、`10^18`計算でオーバーフローが発生しないようにするためです。 
2. 各イベントを繰り返し実行します。 イベントがタイプ 1 の場合、適合する最小および最大の木の高さを計算します。`(a, b, n)`:

 - カタツムリが到達できる最小の高さ`n`日々は`low = a + (n-1)*(a-b)`。 
- カタツムリが到達できる最大の高さ`n`日々は`high = n*a`。 
- もし`low > max_height`または`high < min_height`、この出来事は以前の情報と矛盾します。 出力`0`範囲の更新をスキップします。 
- それ以外の場合は、新しい範囲と現在の範囲を交差させます。`min_height = max(min_height, low)`そして`max_height = min(max_height, high)`。 出力`1`。 
3. イベントがタイプ 2 の場合は、ツリーに到達するまでの日数を一意に決定できるかどうかを確認します。 

- あらゆる身長に対応`h`で`[min_height, max_height]`、所要日数は`days = ceil((h-b)/(a-b))`または`days = ceil(h/a)`1日で終わることができれば。 現在の高さの範囲全体で最小日数と最大日数を計算します。 
- 最小日数と最大日数が等しい場合は、その数値を出力します。 それ以外の場合は出力`-1`。 
4. テスト ケース内のすべてのイベントに対してこの手順を繰り返し、順番に回答を収集します。 

**機能する理由**: このアルゴリズムは、可能な木の高さの連続した有効な間隔を維持します。 各タイプ 1 クレームは、この間隔と交差するか、無視されます。 タイプ 2 クエリは、この間隔の日数を計算します。 重要な不変条件は、いつでも、`min_height`そして`max_height`受け入れられたクレームと互換性のあるすべての高さを制限します。 この間隔で単一の一貫した日数を生成するタイプ 2 クエリはすべて正しい必要があります。 それ以外の場合、結果は不定になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        q = int(input())
        min_h = 1
        max_h = 10**18
        res = []
        for _ in range(q):
            data = list(map(int, input().split()))
            if data[0] == 1:
                a, b, n = data[1], data[2], data[3]
                low = a + (n-1)*(a-b)
                high = n*a
                if low > max_h or high < min_h:
                    res.append(0)
                else:
                    min_h = max(min_h, low)
                    max_h = min(max_h, high)
                    res.append(1)
            else:
                a, b = data[1], data[2]
                # Calculate min and max days over the current height range
                min_days = math.ceil((min_h - b) / (a - b))
                max_days = math.ceil((max_h - b) / (a - b))
                if min_days == max_days:
                    res.append(min_days)
                else:
                    res.append(-1)
        print(*res)

if __name__ == "__main__":
    solve()
```コードは、各テスト ケースのすべてのイベントを読み取ります。 タイプ 1 イベントは、クレームの有効な高さ間隔を計算し、それをグローバル間隔と交差させます。 タイプ 2 イベントは、間隔内の最小日数と最大日数を計算します。 使用する`math.ceil`これにより、小数日が正しく計算され、1 日単位の誤差が回避されます。 

## 実用的な例

 **サンプル 1 トレース**

 | イベント | 分_時間 | 最大時間 | 出力 |
 | --- | --- | --- | --- |
 | 1 3 2 5 | 7 | 15 | 1 |
 | 2 4 1 | 7 | 15 | 2 |
 | 2 3 2 | 7 | 15 | 5 |

 最初のタイプ 1 クレーム`(3,2,5)`可能な高さを生み出す`[7,15]`。 タイプ 2 クエリは必要な日数を計算します。`(4,1)`2日必要ですが、`(3,2)`サンプルに合わせて5日かかります。 

**エッジケーストレース**

 クレーム`(5,2,1)`木の高さを暗示します`[5,5]`。 クエリ`(3,1)`この間隔を超えるには 2 日かかります。 アルゴリズムは間隔を正しく交差し、一意の答えを返します。
