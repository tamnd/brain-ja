 ## 解決策
 ## 問題の理解

 すべての頂点に数値要件を持つモンスターが含まれる無向グラフが与えられます。 モンスターに価値があるなら`a[i]`、少なくともすでに倒している場合にのみ倒すことができます。`a[i]`他のモンスター。 

プロセスは単一の頂点を選択することから始まります`s`どこ`a[s] = 0`、最初から何も倒していないので。 その後、エッジに沿って移動します。 新しい頂点に移動するときは、すでに倒されてそこに到着するか、現在の倒したモンスターの数が十分であれば、到着した瞬間にそのモンスターを倒すことになります。 

モンスターは一度倒されると倒されたままとなり、自由に頂点を再訪することができます。 

問題は、すべてのモンスターを最終的に倒すことができるような開始頂点と一連の移動が存在するかどうかです。 

主な問題点は、移動はグラフの接続性によって制限されるが、ノードを倒す資格は訪問の順序に応じて増加するしきい値条件によって制限されることです。 

制約は大きく、合計すると`n`そして`m`テストケース全体で最大`2 × 10^5`。 これにより、訪問ノードの考えられるすべての順序をシミュレートしようとしたり、考えられる開始ごとに BFS/DFS を実行したりするソリューションは即座に除外されます。 慎重な順序付けロジックを備えた線形または線形に近いグラフの走査が必要です。 

いくつかの微妙なエッジの状況が重要です。 

値を持つノードがない場合`0`、答えはすぐにわかります`NO`、始めることさえできないからです。 

ゼロ値ノードが存在しても、他のコンポーネントに到達できない方法で分離されている場合は、ローカル トラバーサルが可能であっても失敗する可能性があります。 

より微妙なケースは、コンポーネントが到達可能であるにもかかわらず、次数が非常に小さい頂点や孤立した構造が含まれているため、高値のノードへのアクセスが早すぎる場合です。 たとえば、パス内で、十分なノードが収集される前に価値の高いノードを通過する必要がある場合、プロセスはブロックされます。 

## アプローチ

 強引な解釈では、考えられるすべての開始頂点を次のように試します。`a[i] = 0`、トラバーサルをシミュレートし、制約を適用しながら敗北したノードのセットを維持します。`defeated_count ≥ a[v]`ノードに入ろうとしたとき。 各シミュレーションでは、利用可能な動きが現在の状態に応じて異なる BFS または DFS のような探索が必要になります。 

状態空間が指数関数的であるため、これは失敗します。 ノードを訪問する順序は重要であり、単純なシミュレーションは有効な走査順序の順列を効果的に探索します。 単一のテスト ケースでも調査が必要になる場合があります`O(n!)`最悪の場合は注文。 

重要な観察は、移動ルールと「敗北しきい値」が共に貪欲な構造を暗示しているということです。グラフの意味でノードに到達可能であり、その要件が現在満たされている場合、遅延は決して役に立ちません。 本当の制限は、パスの順序の複雑さではなく、常に利用可能な最小の要件を最初に選択する、到達可能なフロンティアの拡大を維持できるかどうかです。 

これは、頂点をその基準でソートすることを示唆しています。`a[i]`値を設定し、それらを段階的にアクティブ化しますが、接続性が重要であるため、アクティブ化だけでは十分ではありません。 頂点を含めることを決定したとき、その頂点が有効な開始点からすでに到達可能な接続された領域に存在することを確認する必要があります。 

これは、ユニオン検索または DSU ベースのアイデアにつながります。頂点の追加を昇順にシミュレートします。`a[i]`。 各ステップで、要件が現在の「敗北数」以下であるノードをアクティブ化し、エッジを介してノードを結合します。 いずれかの時点で、すべてのアクティブなノードが単一の接続されたコンポーネントを形成し、すべてのノードが含まれるまで拡張し続けることができる場合、このプロセスは実行可能です。 

より深いアイデアは、非減少と一致する順序を修正すると、`a[i]`、グラフの接続性は、新しくアクティブ化されたノードがすでに到達可能な領域に接続できるかどうかによってのみ重要になります。 ある時点でノードが値的に適格になったが、現在到達可能なセットに接続されていない場合、延期せざるを得なくなり、将来の進行が妨げられる可能性があります。 

したがって、DSU とソートされたノード上のポインターを使用して到達可能性を追跡し、可能な限り長く拡張します。

 ## アルゴリズムのチュートリアル

 1. すべての頂点を値で並べ替えます。`a[i]`昇順で。 

これは唯一の意味のあるグローバル制約を反映しています。つまり、要件が許可するより早くノードを破ることはできないため、値の順序が自然な候補の順序になります。 
2. すべての頂点に対する DSU 構造と配列を初期化します。`active[i] = False`頂点が現在到達可能な処理済みセットに含まれているかどうかを示します。 
3. ポインタを維持する`i`ソートされた頂点とカウンターの上に`done`アクティブ化された (これまでに敗北した) ノードの数を表します。 
4. 値のあるノードから開始する`0`。 すべての頂点に対して、`a[i] = 0`、それをアクティブ化し、すでにアクティブな近隣と結合します。 これにより、最初の到達可能な領域が形成されます。 
5. 次に、繰り返し展開してみます。 

進行可能な間は、その頂点がアクティブ化されます。`a[v] ≤ done`(DSU の意味で) 現在アクティブなコンポーネントに隣接しているもの。 頂点をアクティブにするたびに、増加します`done`そしてそれを活発な隣人たちと結びつけます。 

この条件が重要である理由は、ノードを倒すと増加するためです。`done`したがって、要件がすでに満たされているノードのみを安全に含めることができます。 
6. ある時点で新しい頂点をアクティブ化できないが、非アクティブな頂点がまだ存在する場合、プロセスは停止します。 戻る`NO`。 
7. すべての頂点がアクティブになったら、戻ります。`YES`。 

### なぜ効果があるのか

 このアルゴリズムは、含まれるすべてのノードの制約を常に満たす、敗北した頂点の増加するセットを維持します。 要件が満たされるまで頂点をアクティブにすることはありません。エッジを介してすでに到達可能な構造に接続されている頂点のみをアクティブにします。 これにより、移動の制約が確実に尊重され、切断された領域に「テレポート」することはありません。 プロセスが停止した場合、残りのすべての頂点がすでに無効になっているノードが多すぎるか、現在到達可能なセットから切断されているため、有効な順序付けにそれを含めることができないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        adj = [[] for _ in range(n)]

        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        nodes = sorted(range(n), key=lambda x: a[x])

        dsu = DSU(n)
        active = [False] * n
        done = 0

        ptr = 0
        changed = True

        while changed:
            changed = False

            while ptr < n and a[nodes[ptr]] <= done:
                v = nodes[ptr]
                ptr += 1
                if active[v]:
                    continue

                active[v] = True
                done += 1

                for to in adj[v]:
                    if active[to]:
                        dsu.union(v, to)

                changed = True

        print("YES" if done == n else "NO")

if __name__ == "__main__":
    solve()
```この実装では、頂点を難易度の値に基づいて並べ替えて、現在実行可能なすべての頂点を貪欲にアクティブにします。 の`done`カウンターはこれまでに倒されたモンスターの数を追跡し、どのノードが適格であるかを直接決定します。 

DSU はアクティブ化されたノード間の接続を維持するために使用されますが、このソリューションにおける DSU の役割は主に、ノードをアクティブ化するたびに、アクティブな隣接ノードを通じてそのノードが現在到達可能な構造にマージされるようにすることです。 

微妙な点は、頂点を昇順でのみ考慮することです。`a[i]`したがって、ソートされたリスト内のノードを一度スキップすると、そのノードを再度訪問することはありません。 これは安全なので、`done`増加するだけなので、適格性は単調です。

 ## 特殊なケース

 重要なエッジ ケースは、値がゼロのノードが複数存在するが、それらが別のコンポーネント内にある場合です。 アルゴリズムは、少なくとも 1 つのコンポーネントが増加を通じて成長できる場合にのみ成功します。`done`間接的に他の人に到達するため。 コンポーネントをブリッジできるものがない場合、最初のゼロ領域を使い果たした直後にアクティベーションが停止します。 

もう 1 つのエッジ ケースは、他のすべてのノードに接続されていない単一のゼロ ノードです。 他のノードの値が小さい場合でも、グラフ構造によってすでにアクティブなノードを介してアクティブ化チェーンに到達できない場合は、そのノードに到達できないままになり、プロセスが途中で停止します。
