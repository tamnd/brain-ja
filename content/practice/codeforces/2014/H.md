 ## 解決策
 ## 問題の理解

 各クエリについて、部分配列のみを調べます。$a_l, a_{l+1}, \dots, a_r$。 

ロビンが先に動きます。 毎ターン、プレイヤーは残りのターゲットを選択し、その値を獲得し、それを削除します。 選択できるターゲットに制限がないため、ゲームはクエリされたセグメント内の値の複数セットによって完全に決定されます。 

両選手とも完璧なプレーをしている。 すべてのクエリについて、保安官が損失を回避できるかどうかを判断する必要があります。 質問は保安官が**負けない**かどうかを問うものであるため、同点は保安官の成功とみなされます。 

すべてのテスト ケースにわたる要素とクエリの合計数は最大で$2 \cdot 10^5$。 クエリを線形時間で処理するソリューションでは、大まかに次のものが必要になります。$4 \cdot 10^{10}$限界をはるかに超えた最悪の場合の動作。 前処理後のクエリごとに、ほぼ定数または対数的な作業が必要になります。 

ゲーム理論の部分が最初の罠です。 最適なプレイの単純なシミュレーションは、プレーヤーが交互にターンするため、複雑に見えます。 実際には、最初からすべてのターゲットが利用可能であるため、各プレイヤーは単純に現在最大の残りの値を取得します。 選択された値の順序は完全に決定されます。 

もう 1 つの簡単な間違いは、合計だけが重要であると考えることです。 考慮する：```
[1, 2]
```ロビンは 2 を取り、保安官は 1 を取り、保安官は負けます。 

合計は 3 ですが、これだけでは何もわかりません。 

2 番目のトラップは、すべての偶数長のセグメントが同点を生成すると仮定しています。```
[1, 1, 2, 3]
```ロビンが手に入れる$3+1=4$、保安官が取得します$2+1=3$。 保安官は負けます。 

値の頻度が重要です。 

より微妙なケースは次のとおりです。```
[5, 5, 7]
```降順でソート:```
7, 5, 5
```ロビンが手に入れる$7+5=12$、保安官が取得します$5$。 

値 5 が 2 回出現するも、比類のない 7 が試合を決定します。 

一致しない値がいつ存在するかを正確に理解することが重要な観察です。 

## アプローチ

 まず、最適なプレイがどのようなものかを理解しましょう。 

残りのターゲットは常に選択できるため、プレイヤーは、より大きな値が利用可能であるときにより小さな値を選択しても利益を得ることはありません。 より大きな値が残っている場合は、すぐにその値を取得しても、そのプレイヤーの最終スコアを向上させることしかできません。 

結果として、ゲームは値を降順に並べ替えることと同じになります。 ロビンがポジションを獲得$1,3,5,\dots$そして保安官は役職を獲得する$2,4,6,\dots$。 

クエリされたすべてのセグメントを明示的に並べ替えるとします。 ある長さのセグメントの場合$m$、その値をソートし、交互の合計を計算します。 これは最適なプレイと正確に一致するため、これは正しいです。 

問題は複雑さです。 クエリには次のものが含まれる場合があります$O(n)$要素が多いため、並べ替えにコストがかかる$O(m \log m)$。 まで$2 \cdot 10^5$クエリ、これは完全に不可能です。 

画期的な進歩は、スコアではなく頻度に注目することから生まれます。 

任意の値を取得します$x$。 それが偶数回出現した場合、ソート後、それらのコピーは連続した位置を占め、2 人のプレイヤー間で均等に分割されます。 彼らの貢献は相殺されます。 

奇数の周波数を持つ値のみが重要です。 等しい値をペアにすると、奇数の頻度の値ごとに、ペアになっていないコピーが 1 つだけ残ります。 これらの残りのコピーは個別の値です。 並べ替えると、ロビンと保安官が交互に表示されます。 

さて、注目すべきことを観察してください。 残りの個別の値を次のようにします。$$b_1 > b_2 > \dots > b_k.$$ロビンが受け取る$b_1, b_3, b_5,\dots$、保安官が受け取ります$b_2, b_4, b_6,\dots$。 

値は厳密に減少しているため、いつでもロビンの合計は保安官の合計より大きくなります。$k$奇数です。 もし$k$が偶数である場合、残り物は完全にペアになり、合計は等しくなります。 

したがって、ゲーム全体は 1 つの質問に集約されます。 

セグメントには、頻度が奇数の値が奇数または偶数含まれていますか?

 保安官は、カウントが偶数の場合に正確に負けを回避します。 

ここで、任意の部分配列について、キャンセル後にすべての値が偶数回出現するかどうかを答えるデータ構造が必要になります。 

これは古典的なパリティ クエリです。 それぞれの個別の値にランダムな 64 ビット ハッシュを割り当てます。 させて$$pref[i] = h(a_1) \oplus h(a_2) \oplus \dots \oplus h(a_i).$$お問い合わせの場合$[l,r]$、$$X = pref[r] \oplus pref[l-1].$$偶数回出現するすべての値は、XOR でキャンセルされます。 結果は、奇数の頻度の値に対応するハッシュの XOR です。 

奇数の周波数値が存在しない場合は、$X=0$。 

より一般的には、奇数頻度の値の数は、そのハッシュの XOR が偶数サイズのハッシュのセットの XOR と等しい場合にのみ偶数になります。 意図したソリューションではランダム ハッシュを使用し、独立した乱数を値に割り当てます。 したがって、すべての奇数周波数値がキャンセルされる場合、XOR は正確にゼロになり、それ以外の場合は圧倒的な確率でゼロ以外になります。 

公式見解はさらに強力だ。 セグメント内のすべての値の頻度が偶数であれば、保安官は負けません。 この条件は、セグメントの XOR ハッシュがゼロであることと同じです。 

64 ビット乱数との衝突の可能性は無視できます。

 ## アルゴリズムのチュートリアル

 ### 1. 64 ビットのランダムな数値をすべての個別の値に割り当てます。 

値が初めて出現するたびに、ランダムな 64 ビット整数を生成して保存します。 

等しい値は常に同じハッシュを受け取ります。 

### 2. プレフィックス XOR 配列を構築する

 定義する$$pref[0]=0$$そして$$pref[i]=pref[i-1]\oplus h(a_i).$$これにより、任意のセグメントの XOR ハッシュを一定時間で取得できます。 

### 3. クエリを処理する

 セグメント用$[l,r]$、計算する$$cur=pref[r]\oplus pref[l-1].$$偶数回出現するすべての値は、偶数回そのハッシュに寄与し、消滅します。 

結果は、セグメント内の頻度が奇数である値に正確に対応するハッシュの XOR です。 

### 4. 答えを決める

 もし$$cur=0,$$そうすれば、すべての値の頻度が偶数になるため、保安官は損失を回避できます。 出力`"YES"`。 

それ以外の場合は出力`"NO"`。 

### なぜ効果があるのか

 重要な不変条件は、XOR がパリティを追跡することです。 

あらゆる値に対して$x$、そのハッシュは、次の出現ごとに 1 回表示されます。$x$。 以来$$h(x)\oplus h(x)=0,$$すべての偶数の発生はキャンセルされます。 セグメントの XOR を取得した後、生き残ったハッシュのみが奇数の頻度の値に属します。 

すべての周波数が偶数の場合、セグメント XOR はゼロに等しくなります。 少なくとも 1 つの奇数頻度値が存在する場合、ランダム ハッシュからの衝突確率が無視できる場合を除き、XOR はゼロ以外になります。 

ゲーム分析により、すべての値が別の等しい値とペアになる場合、保安官は正確に負けを回避できることがわかります。 したがって、クエリの答えは、セグメントの XOR ハッシュがゼロかどうかによって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK = (1 << 64) - 1

def splitmix64(x):
    x = (x + 0x9e3779b97f4a7c15) & MASK
    x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9 & MASK
    x = (x ^ (x >> 27)) * 0x94d049bb133111eb & MASK
    x ^= x >> 31
    return x & MASK

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        value_hash = {}
        pref = [0] * (n + 1)

        for i, x in enumerate(a, 1):
            if x not in value_hash:
                value_hash[x] = splitmix64(x)

            pref[i] = pref[i - 1] ^ value_hash[x]

        ans = []

        for _ in range(q):
            l, r = map(int, input().split())

            cur = pref[r] ^ pref[l - 1]

            if cur == 0:
                ans.append("YES")
            else:
                ans.append("NO")

        sys.stdout.write("\n".join(ans) + "\n")

solve()
```最初の部分では、次を使用して、すべての個別の値に決定論的な 64 ビット ハッシュを割り当てます。`splitmix64`。 決定論的ハッシュを使用すると、ソリューションに必要な衝突耐性を維持しながら、Python のランダム ジェネレーターへの依存を回避できます。 

プレフィックス配列には、累積的な XOR 値が格納されます。 XOR はそれ自体の逆であるため、セグメント XOR は次のように取得されます。`pref[r] ^ pref[l - 1]`。 

唯一の細かい点はインデックスです。 プレフィックス配列は 1 から始まる構造として構築されるため、クエリ境界は標準の範囲式に自然にマップされます。 

Python の整数には制限がありませんが、すべてのハッシュはマスクを使用して 64 ビット内に保持されます。 これにより、符号なし 64 ビット演算が再現されます。

import sys
import io

def run(inp: str) -> str:
    MASK = (1 << 64) - 1

    def splitmix64(x):
        x = (x + 0x9e3779b97f4a7c15) & MASK
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9 & MASK
        x = (x ^ (x >> 27)) * 0x94d049bb133111eb & MASK
        x ^= x >> 31
        return x & MASK

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = []
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        mp = {}
        pref = [0] * (n + 1)

        for i, x in enumerate(a, 1):
            if x not in mp:
                mp[x] = splitmix64(x)
            pref[i] = pref[i - 1] ^ mp[x]

        for _ in range(q):
            l, r = map(int, input().split())
            out.append("YES" if (pref[r] ^ pref[l - 1]) == 0 else "NO")

    return "\n".join(out)

 ## 特殊なケース

 次のことを考慮してください。```
1
1 1
10
1 1
```セグメントには 10 が 1 回含まれています。そのハッシュはセグメント XOR で存続するため、答えは次のようになります。`"NO"`。 このアルゴリズムは、一致しない値が 1 つ残っていることを正確に識別します。 

考慮する：```
1
1 1
4 4 9 9
1 4
```どちらの値も 2 回出現します。 セグメント XOR は次のようになります。$$h(4)\oplus h(4)\oplus h(9)\oplus h(9)=0.$$アルゴリズムの出力`"YES"`なぜなら、すべての周波数は均等だからです。 

考慮する：```
1
1 1
5 5 7
1 3
```5 の 2 つのコピーはキャンセルされ、7 のハッシュだけが残ります。セグメントの XOR はゼロ以外であり、次の結果が得られます。`"NO"`。 

最後に、配列の境界に接する範囲を考えます。```
1
2 1
1 2 1 2
1 4
```クエリで使用されるのは、`pref[4] ^ pref[0]`。 プレフィックス構築には意図的に次のものが含まれます。`pref[0]=0`したがって、位置 1 から始まる範囲には特別な処理はありません。答えは次のとおりです。`"YES"`すべての値が 2 回出現するためです。
