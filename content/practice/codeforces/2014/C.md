 ## 解決策
 ## 問題の理解

 私たちは、厳密に人口の半分以上が不幸になるために、町で最も裕福な人にどれだけの追加の金を追加する必要があるかを決定するように求められています。 各人の幸福は、自分の富が町の平均富の半分以下であるかどうかによって決まります。 入力は複数のテスト ケースで構成され、それぞれが人の数とその資産のリストを提供します。 出力は、ロビン フッドの出現に必要な最小追加ゴールド、またはそれが不可能な場合は -1 です。 

制約を考慮すると、次のことがわかります。`n`最大 200,000 に達する可能性があり、テスト ケース全体の合計も 200,000 に制限されます。 これにより、追加のゴールドのあらゆる値を総当りでチェックするようなアプローチは除外されます。これは、広範囲の合計を反復処理する可能性があるためです。 各テストケースに必要な追加のゴールドを、本質的に線形時間で効率的に計算する方法が必要です。`n`。 

母集団が非常に小さい場合、微妙なエッジケースが発生します。 のために`n = 1`、半数以上の人が不幸になることはあり得ないので、答えは -1 でなければなりません。 同様に、すべての富が等しい場合、または最も裕福な人が既に高水準で他の人が平均の半分を下回らない場合、追加の金はゼロになる可能性があります。 個人の資産を平均の半分、つまり実数と比較しているため、浮動小数点除算を慎重に扱うことが重要です。 

## アプローチ

 素朴なアプローチは、最も裕福な人の資産を段階的に増やし、人口の半分以上が不幸になるまでそのたびに平均と不幸の数を再計算することです。 これは定義を直接実装しているため機能しますが、法外に遅いです。 の範囲`x`は非常に大きくなる可能性があり (最大数十億)、平均と不幸の数を毎回再計算するには O(n) 回の操作が必要となるため、全体の複雑さは O(n * max(x)) になる可能性があり、これは許容できません。 

重要な観察は、最も裕福な人が金を獲得するにつれて、不幸な人々の数が増加するだけであるということです。 不幸の状態は線形です`x`新しい平均は`(sum + x)/n`そしてそれぞれを比較します`a_i`に`(sum + x)/(2n)`。 あらゆる個人にとって`i`、不等式`a_i < (sum + x)/(2n)`については明示的に解決できます`x`。 したがって、人口の半分以上が不幸になるには、次の点に焦点を当てるだけで十分です。`ceil(n/2)`最も裕福でない最大の富。 のしきい値を計算できます。`x`各人がどこで不幸になるかを判断し、これらのしきい値の最大値を採用します。 これにより、反復検索を行わずに閉じた形式の解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 最大(x)) | O(n) | 遅すぎる |
 | クローズドフォームのしきい値 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースの人数を読み取ります。`n`そして富のリスト`a`。 総資産を計算する`total`。 
2. 最大の富を見つける`max_a`とそのインデックス。 これは追加のゴールドを受け取る最も裕福な人です。 
3. 必要な不幸な人々の数を計算します。`ceil(n/2)`。 
4. 最も裕福な人を除く他のすべての資産を昇順に並べ替えます。 私たちは次のことに重点を置いています`ceil(n/2)`不幸かもしれない最も小さな人々。 
5. これらの各人について、追加の最小ゴールドを計算します。`x_i`彼らの富が厳密に新しい平均の半分未満であるように要求されます。 不等式を解く`a_i < (total + x)/(2n)`のために`x`取得するため`x_i = max(0, 2 * n * a_i - total + 1)`。 の`+1`厳密な不平等を保証します。 
6. 最大限のものを取る`x_i`この選ばれた人々の中から。 負の場合は 0 を返します。 正の場合は返します。 それが不可能な場合 (人口が少なすぎる場合)、-1 を返します。 

最も裕福な人が追加の金を追加すると平均が増加し、以前は境界線にあった人々を不幸にするため、正しさがわかります。 不幸になるはずの人々の中で最大の閾値を取ることによって、厳密に半数以上が不幸になることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n == 1:
            print(-1)
            continue
        
        total = sum(a)
        max_val = max(a)
        idx = a.index(max_val)
        
        others = a[:idx] + a[idx+1:]
        others.sort()
        
        unhappy_needed = (n + 1) // 2
        selected = others[:unhappy_needed]
        
        x_needed = 0
        for val in selected:
            x_i = 2 * n * val - total + 1
            x_needed = max(x_needed, x_i)
        
        print(max(0, x_needed))
        
if __name__ == "__main__":
    solve()
```このソリューションは、高速 I/O を使用して入力を読み取り、大規模なケースを処理します。 1 人のエッジケースを個別に処理します。 の`2 * n * val - total + 1`公式は厳密な不等式を直接解くことから得られ、最大値を取ると、必要なすべての人々が確実に不幸になります。

 ## 特殊なケース

 いつ`n = 1`、人口の半分以上が不幸になることは不可能です。 アルゴリズムは正しく -1 を返します。 最も裕福な人がすでに金をゼロに追加するだけで十分なほど裕福である場合、式は非正の x を生成し、これをゼロにクリップします。 すべての人が平等な富を持っている場合、半数以上を不幸にすることは不可能かもしれませんが、やはり数式は必要に応じて 0 または -1 を返します。 すべての場合において、並べ替えにより、不幸を追跡する正しい数の人々が選択されることが保証されます。
