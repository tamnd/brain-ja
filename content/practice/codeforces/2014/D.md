 **解決時間:** 2 分 1 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 各ジョブは数日の間隔を占めます`[l, r]`。 訪問者は正確に滞在します`d`連続した日なので、開始日を選択してください`s`訪問が間隔をカバーすることを意味します`[s, s + d - 1]`。 

ジョブは、訪問と少なくとも 1 回重複する場合にカウントされます。 重なる量は関係ありません。 一日を共有すれば十分です。 

考えられるすべての有効な開始日について、その長さに交差するジョブの数を知る必要があります。`d`ウィンドウ。 すべての有効な開始の中で、次のものが必要です。 

- ウィンドウがジョブの最大数と交差する最も早い開始日。 
- ウィンドウがジョブの最小数と交差する最も早い開始日。 

訪問はカレンダー内にとどまる必要があるため、有効な開始日は次のとおりです。`1`を通して`n - d + 1`。 

制約はソリューションを推進するものです。 1 つのテストには最大で次のものを含めることができます。`10^5`日々と`10^5`ジョブとすべての合計`n`入力全体の値は最大でも`2 · 10^5`。 これは、`O(n)`または`O(n log n)`テストケースごとのソリューションは快適です。 アン`O(nk)`解決策は不可能です。`10^10`操作。 

難しいのは、仕事には間隔があり、訪問には間隔があるということです。 間隔のペアごとに単純に重複をチェックするのはコストがかかりすぎます。 

いくつかの特殊なケースは注目に値します。 

考慮する：```
n = 5
d = 2
job = [2,3]
```訪問`[1,2]`一日を共有しているため、仕事が重なっています`2`。 訪問`[3,4]`日が同じなので重なります`3`。 訪問開始がジョブ内にあるかどうかだけをチェックする不注意な実装では、これらの重複の 1 つが見逃されてしまいます。 

関係を考慮してください。```
n = 4
d = 1
jobs:
[1,1]
[4,4]
```カウントは次のとおりです。 

| 開始 | ジョブが重なっています |
 | --- | --- |
 | 1 | 1 |
 | 2 | 0 |
 | 3 | 0 |
 | 4 | 1 |

 最大カウントは日ごとに発生します`1`そして`4`。 正解は日です`1`、一番早いもの。 同じルールが最小値にも適用されます。 

もう 1 つの微妙なケースは、仕事が訪問時間よりも長い場合に発生します。```
n = 10
d = 2
job = [2,8]
```日から始まるすべての訪問`1`一日中`8`この仕事と重複します。 各ウィンドウを個別にチェックするのではなく、そのようなすべての開始を効率的にマークする方法が必要です。 

## アプローチ

 最も直接的な解決策は、有効な開始日をすべて調べて、その期間と交差するジョブの数をカウントすることです。 

スタートの日に向けて`s`、訪問間隔は`[s, s+d-1]`。 仕事`[l,r]`次の場合、今回の訪問と重複します。```
l ≤ s+d-1
and
r ≥ s
```この条件をすべてに対してチェックする`k`有効な開始ごとにジョブを実行すると、次のような複雑さが生じます。```
O((n-d+1) · k)
```最悪の場合、両方の値が近似します。`10^5`、大まかに生産`10^10`重複テスト。 それは限界をはるかに超えています。 

重要な観察は、視点を逆転させることです。 

尋ねる代わりに:

 > 開始日の場合、どのジョブがその日と重複しますか?

 尋ねてください：

 > 仕事の場合、開始日が重なるのはどれですか?

 訪問を開始しましょう`s`。 

重複条件は次のとおりです。```
[s, s+d-1] intersects [l,r]
```これは次と同等です。```
s ≤ r
s+d-1 ≥ l
```並べ替え:```
s ≤ r
s ≥ l-d+1
```したがって、範囲内のすべての開始日```
[l-d+1, r]
```重複する訪問が発生します。 

仕事が貢献するので、これは非常に便利です`+1`連続した範囲の開始日全体に適用されます。 

多数の間隔更新を配列に適用する必要がある場合には、差分配列が最適なツールです。 

各ジョブについて:```
add 1 to all starts in [l-d+1, r]
```その範囲を有効な開始日に固定した後`[1, n-d+1]`で範囲更新を実行します。`O(1)`差分配列を使用します。 

最終的なプレフィックスの合計により、開始日ごとに重複するジョブの正確な数が再構成されます。 

これらのカウントがわかったら、単純な線形スキャンで最も早い最大値と最も早い最小値を見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | お(1) | 遅すぎる |
 | 最適 | O(n + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`m = n - d + 1`、有効な開始日数。 
2. インデックスの範囲更新をサポートするのに十分な大きさの差分配列を作成します。`1...m`。 
3. ジョブごとに`[l, r]`、どの開始日が重なるかを決定します。 

重複条件から:```
l-d+1 ≤ s ≤ r
```4. この範囲を有効な開始日に固定します。```
L = max(1, l-d+1)
R = min(m, r)
```屋外でスタートする場合でも`1...m`有効な訪問を表すことはできません。 
5. もし`L ≤ R`で始まるすべてに 1 を追加します。`[L, R]`差分配列を使用する:```
diff[L] += 1
diff[R+1] -= 1
```6. 差分配列のプレフィックスの合計を計算します。 

位置での結果の値`s`日に始まる訪問と重複する仕事の数に等しい`s`。 
7. すべての開始日を左から右にスキャンします。 

これまでに確認された最大数と、それを達成した最も早い日を追跡します。 
8. 同じスキャンで、これまでに確認された最小数とその最小数に到達した最も早い日を追跡します。 
9. 記録された 2 つの開始日を出力します。 

### なぜ効果があるのか

 ジョブは、訪問開始が次の条件を満たした時点で訪問と重複します。```
l-d+1 ≤ s ≤ r
```そのようなすべての開始は、そのジョブから 1 つの貢献を受け取る必要があり、他の開始は受け取るべきではありません。 

差分配列は、正確にその開始範囲に 1 を追加します。 さまざまなジョブからの寄与は独立しているため、各開始日の最終的なプレフィックスの合計は、重複するジョブの合計数と等しくなります。 

開始日を昇順に処理するため、最大値と最小値のスキャンは正確です。 同じカウントが後で出現した場合、それらは無視され、最も古い出現が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n, d, k = map(int, input().split())

        m = n - d + 1
        diff = [0] * (m + 3)

        for _ in range(k):
            l, r = map(int, input().split())

            L = max(1, l - d + 1)
            R = min(m, r)

            if L <= R:
                diff[L] += 1
                diff[R + 1] -= 1

        cur = 0

        max_cnt = -1
        max_day = 1

        min_cnt = 10**18
        min_day = 1

        for day in range(1, m + 1):
            cur += diff[day]

            if cur > max_cnt:
                max_cnt = cur
                max_day = day

            if cur < min_cnt:
                min_cnt = cur
                min_day = day

        ans.append(f"{max_day} {min_day}")

    sys.stdout.write("\n".join(ans))

solve()
```変数`m = n - d + 1`すべての合法的な開始位置を表します。 すべての計算は、元のカレンダーではなく、この圧縮されたドメインで実行されます。 

各ジョブの重要な導出は次のとおりです。```
s+d-1 ≥ l
⇒ s ≥ l-d+1
```と共に`s ≤ r`、これにより、ジョブと重複する開始の正確な間隔が得られます。 

クランプステップは不可欠です。 理論的には、ジョブが開始に与える影響は次のとおりです。`1`以上`m`, しかし、これらの開始は有効な訪問に対応していません。 

スキャンでは厳密な比較が使用されます。```
if cur > max_cnt:
```そして```
if cur < min_cnt:
```それよりも`>=`または`<=`。 

これにより、複数の日に同じカウントが達成されるたびに、最も早い位置が保存されます。 

更新が影響する可能性があるため、差分配列にはいくつかの余分なセルが割り当てられます。`R + 1`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + k) | ジョブごとに 1 回の範囲更新、すべての有効な開始日に 1 回のスキャン |
 | スペース | O(n) | サイズの差分配列`n - d + 1`|

 全部の合計なので`n`入力を超える値は最大でも`2 · 10^5`、すべてのテスト ケースにわたる合計作業量は、入力サイズに比例します。 これは 2 秒の制限内に簡単に収まり、メモリ使用量は少ないままです。

 次のことを考慮してください。```
1
5 2 1
2 3
```ジョブの重複が開始されます。```
[2-2+1, 3] = [1,3]
```カウントは次のようになります。 

| 開始 | カウント |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 0 |

 アルゴリズムは間隔を正確にマークします`[1,3]`差分配列に入力し、正しく出力します。```
1 4
```これにより、1 つのエンドポイント日のみを共有しても重複としてカウントされることが確認されます。 

次に、同点の場合を考えてみましょう。```

1 1

```カウントは次のとおりです。 

| 開始 | カウント |
 | --- | --- |
