 ## 解決策
 ## 問題の理解

 私たちはリトル・ジョンの牛乳の消費量を長期にわたって追跡しています。 彼は牛乳を個別のバッチで受け取り、それぞれが日と量に関連付けられています。 牛乳には鮮度限界がある`k`日、その日に搾乳されたことを意味します`d_i`日が経つと腐ってしまう`d_i + k - 1`。 ジョンは毎日、入手可能な最も新鮮な牛乳を貪欲に飲みます。`m`パイント。 牛乳を正確に飲むことができたとき、満足の日が訪れます。`m`パイント。 

入力は一連の日記エントリであり、それぞれに日付と受け取った牛乳の量が指定されます。 私たちの目標は、テスト ケースごとに、John が完全に満足した日数をカウントすることです。 ミルクが不足した日はカウントされません。 出力はテスト ケースごとに 1 つの整数です。 

制約により許可されるのは、`n`まで`10^5`テストケースごとの合計`n`すべてのテストケースにわたって、`2 * 10^5`。 1日の摂取制限`m`そして鮮度`k`までです`10^5`。 これは、完全なタイムラインにわたって毎日反復されるソリューションを意味します。`10^6`遅すぎるでしょう。 代わりに、牛乳が存在する日または腐敗した日だけに焦点を当てて、牛乳イベントを効率的な方法で処理する必要があります。 

エッジケースには、前日の牛乳が蓄積されているが、その後のエントリがすぐに到着しない状況が含まれます。 たとえば、牛乳は 1 日目と 4 日目に到着します。`k = 3`, たとえジョンが毎日部分的に飲んでいたとしても、1 日目の牛乳は 4 日目までに腐ってしまうことを意味します。 もう 1 つのエッジ ケースは、ジョンが 1 日で飲みきれる量を超える量の牛乳を受け取ったときに発生します。残りの牛乳は、鮮度の制約を失うことなく繰り越さなければなりません。 

## アプローチ

 ブルートフォース ソリューションでは、毎日を表す配列を維持し、利用可能な牛乳の量を追跡します。 毎日、消費した牛乳を差し引き、腐った牛乳を捨て、満足した日数を数えます。 これは原理的には正しいですが、日数が次の数に達する可能性があるため遅すぎます。`10^6`。 各バッチを毎日繰り返すと、おおよその結果が得られます`10^6 * 10^5`最悪の場合、制限時間を超えて操作が行われる場合があります。 

重要な洞察は、毎日シミュレーションする必要はないということです。 ジョンは常に最も新鮮な牛乳を最初に飲むため、牛乳の消費量は、期限ごとに分類されたバッチのキューとして表すことができます。 優先キューまたはデキューを使用すると、牛乳の在庫を効率的に維持できます。 イベント (ミルクの取得またはミルクの有効期限) が発生する毎日は、直接処理されます。 牛乳の量を更新し、空の日を繰り返すことなく満足日をカウントします。 日間のギャップをスキップすることにより、不必要な操作が削減され、日記エントリの数に関して直線的な複雑さが実現されます。 

ブルートフォースアプローチは現実を正確にシミュレートするため機能しますが、ミルクイベントの数に比べて日数が大きすぎる場合は失敗します。 牛乳を期限切れのバッチとして追跡できるという観察により、問題を処理の問題に絞り込むことができます。`2n`テストケースごとのイベント。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(max(d_i) * n) | O(max(d_i)) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まだ分類されていない場合は、牛乳バッチを取得日ごとに分類します。 これにより、牛乳を時系列順に処理することが保証されます。 この問題ではソートされた入力が保証されているため、実際にはこのステップを省略できます。 
2. 牛乳バッチを保管するためのデキュ​​ーまたは優先キューを初期化します。 各要素には、残りのパイントと有効期限の 2 つの値が格納されます。 行列の先頭に並ぶのは、今日飲める最も新鮮な牛乳です。 
3. 変数を設定する`current_day`最初の取得日まで。 イベント間の日のギャップを考慮して、すべての牛乳イベントを時系列順に繰り返します。 
4. 牛乳が利用できる日ごとに:

 - 期限切れの牛乳を列の先頭から削除します。 バッチの有効期限が切れる日が過ぎた場合、バッチは期限切れになります。`current_day`。 
- まで飲む`m`パイント。 最も新しいバッチから始めます。 バッチの数が以下の場合`m`パイントの場合は完全に消費し、次のバッチに進みます。 消費した牛乳の総量を記録します。 
- 正確に言うと`m`パイントを消費すると、満足度カウンターが増加します。 
- 次の日に移動します。 
5.当日の各牛乳取得イベントについて`d_i`、新しいバッチを追加します`(a_i, d_i + k - 1)`行列に。 その日の消費量を処理した後、増加します`current_day`。 
6. すべての牛乳バッチが消費されるか期限切れになるまで、この作業を繰り返します。 

機能する理由: 不変条件は、キューには常に新鮮な順にそのままの牛乳が含まれていることです。 常に最も新鮮なバッチから最初に消費し、毎日の初めに期限切れの牛乳を取り除くことで、消費が鮮度を尊重することを保証します。 まさにそのときだけ、一日を充実したものとして数える`m`pints are consumed reflects the problem definition. Skipping days without events is safe because no milk is present, so no satisfaction days are possible.

 ## Python ソリューション```python
import sys
import heapq
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        events = [tuple(map(int, input().split())) for _ in range(n)]
        
        milk_queue = deque()
        satisfaction_days = 0
        idx = 0
        current_day = events[0][0]
        last_day = max(d + k - 1 for d, _ in events)

        for day in range(current_day, last_day + 1):
            # Add new milk batches for today
            while idx < n and events[idx][0] == day:
                d_i, a_i = events[idx]
                milk_queue.append([a_i, d_i + k - 1])
                idx += 1
            
            # Remove expired milk
            while milk_queue and milk_queue[0][1] < day:
                milk_queue.popleft()
            
            if not milk_queue:
                continue
            
            # Drink milk up to m pints
            to_drink = m
            while milk_queue and to_drink > 0:
                batch = milk_queue[-1]  # freshest milk is at the back
                if batch[0] <= to_drink:
                    to_drink -= batch[0]
                    milk_queue.pop()
                else:
                    batch[0] -= to_drink
                    to_drink = 0
            
            if to_drink == 0:
                satisfaction_days += 1
        
        print(satisfaction_days)

if __name__ == "__main__":
    solve()
```このコードでは、最も新鮮な牛乳を後ろに持つデックを使用しています。これは、後ろからのポップが O(1) であり、貪欲な「新鮮なものから」の消費に一致するためです。 期限切れの牛乳は手前から取り除きます。 ループは次の日までのみ処理するため、イベントのない日は自然にスキップされます。`last_day`ミルクがまだ存在するかもしれない場所。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各牛乳バッチは 1 回追加され、1 回削除され、パイントの削除操作ごとに合計 O(1) で部分的に消費されます。 合計操作はバッチ数に比例します。 |
 | スペース | O(n) | キューには、有効期限が切れる前に、多くてもすべての牛乳バッチが保存されます。 |

 これは制限内に問題なく収まります。`n <= 2*10^5`そして`k,m <= 10^5`。 deque を使用すると、すべての操作が高速になり、空の日を不必要にシミュレートすることがなくなります。
