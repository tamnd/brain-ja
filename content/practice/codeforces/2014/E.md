 ## 解決策
 ## 問題の理解

 私たちは、2 人の人物が反対側の端から開始し、できるだけ早く会おうとする重み付き無向グラフに取り組んでいます。 1 つは頂点 1 から始まり、もう 1 つは頂点 n から始まります。 それらはエッジに沿って移動しますが、ねじれがあります。いくつかの頂点には馬が含まれており、馬を使用すると、馬を拾った後のすべての移動時間が半分になります。 各人はいつ馬に乗るかを独自に決定でき、一度馬に乗ると、速度ブーストは永続的に残ります。 

目標は、最適な移動とオプションの待機を想定して、2 人の旅行者が同時に同じ頂点を占有することができる最も早い時間を決定することです。 

最大の難点は、各人の交通費が単一の最短経路の問題ではないことです。 代わりに、コストは、特定のポイントに到達する前に馬の頂点をすでに訪問したかどうかによって異なります。 つまり、各頂点には事実上、馬有利なしと馬有利ありの 2 つの状態があるということです。 

この制約により、どのような解も線形演算に近いものでなければならないことがわかります。 テスト バッチごとに最大 2×10^5 の頂点とエッジがあるため、状態遷移ごとに最短パスを最初から再計算したり、会議時間を明示的にシミュレートしたりする方法は遅すぎます。 状態ごとの標準ダイクストラは許容されますが、すべての頂点にわたるペアごとの会議時間を再計算するようなものは許容されません。 

ステートフル性を無視すると、微妙な失敗例がいくつか発生します。 

馬の頂点を、最初に遭遇したときに貪欲に適用される単純なコスト修飾子として扱う場合、1 つの問題が発生します。 たとえば、パスが馬の頂点を通過するのが早すぎて十分なメリットが得られない場合があり、単純なアルゴリズムでは、すぐにパスを通過することが常に最適であると想定される可能性があります。 

もう 1 つの問題は、ノードごとに単一の最短パス距離で十分であると想定していることです。 将来の加速度によっては、馬なしでノードに遅く到着する方が、馬なしで早く到着するよりもまだ良い可能性があるため、これは失敗します。 

最後に、単純なアプローチでは、両端からの最短パスを計算し、最大距離以上の最小値を取得しようとする可能性があります。 2 人の旅行者が異なる時間に到着し、1 人が待つことができるため、これは問題になります。 

## アプローチ

 直接的な総当たりアプローチでは、頂点までの両方の旅行者の最適な移動戦略を個別にシミュレートすることにより、頂点ごとに可能な限り最良の集合時間を計算しようとします。 各頂点 v について、馬に乗るタイミングのすべての可能な選択肢の下でマリアンが v に到達できる最小時間を計算し、ロビンについても同様に、2 つの到着時間の最大値を計算します。 答えはすべての頂点の最小値になります。 

問題は、単一の「最小到着時間」を計算することが、馬の状態によりすでに標準的な最短経路ではないことです。 すべての頂点で馬が取得されたかどうかについて明示的に分岐しようとすると、パスの決定ごとに状態空間が 2 倍になり、単純な列挙では指数関数的なパス、または少なくとも馬のアクティベーションのサブセットに対する O(2^n) スタイルの推論が導き出されます。 

重要な観察は、この問題が、ノードごとに 2 つの状態 (馬の前と馬の後) だけを持つ拡張された状態グラフ上の最短経路問題にきれいに分解されていることです。 これが認識されると、その動きは標準的なダイクストラになります。 両方のスタートからマルチソースの最短パスを実行し、馬を使用した場合と使用しない場合の最良の到着時間を追跡し、頂点ごとの結果を結合します。 

2 番目の重要な洞察は、馬のピックアップをモデル化する方法です。 馬の頂点では、コストゼロで「通常速度」状態から「高速」状態に移行できます。 その時点から、すべてのエッジが半分のコストで横断されます。 すべての重みが等しいため、半分にすることで整数が維持されます。 

すべての頂点でマリアンとロビンの両方の状態の最短到着時間が得られると、頂点での最適な会議時間は、すべての有効な状態の組み合わせの最小値になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 道と馬の選択に対するブルートフォース | 指数 | 高 | 遅すぎる |
 | 各ソースからの 2 状態ダイクストラ | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各頂点は 2 つのレイヤーを持つものとして扱います。レイヤー 0 は馬がまだ使用されていないことを意味し、レイヤー 1 は旅行者が現在馬に乗っている (または以前に馬をアクティブ化した) ことを意味します。 各エッジのトラバースは現在のレイヤーに依存します。 

1. 各頂点が 2 つの状態を持つグラフを作成します。 状態 0 の遷移はフルコストでのウォーキング エッジを表し、状態 1 の遷移は半分のコストでのライディングを表します。 これは、馬の使用によって移動速度が永続的に変化するという事実を捉えています。 
2. マリアンとロビンの距離を個別に初期化します。 両方とも、状態 0 の開始頂点の距離を 0 に設定します。 開始頂点に馬がある場合、状態 1 への瞬間的な遷移も許可します。 
3. Marian の展開された状態グラフに対してダイクストラのアルゴリズムを実行します。 各状態は (頂点、モード) であり、遷移は上記の規則に従います。 これは、馬の有利の有無にかかわらず、マリアンがすべての頂点に到達できる最小時間を計算します。 
4. 頂点 n から開始して、ロビンに対して同じダイクストラを繰り返します。 これにより、2 番目の距離テーブルが作成されます。 
5. すべての頂点 v について、状態のすべての組み合わせを考慮して、可能な限り最良の会議時間を計算します。マリアンは状態 0 または 1、ロビンは状態 0 または 1 です。会議時間は、max(distM[v][i], distR[v][j]) を超える最小値です。 
6. すべての頂点の最小値を取得します。 両方の頂点に到達できない場合は、-1 を出力します。 

### なぜ効果があるのか

 状態グラフの構築により、すべての有効な現実世界の戦略が、展開されたグラフ内の 1 つのパスに正確に対応することが保証されます。 重要な不変条件は、トラベラーが状態 1 に入ると、その後のすべてのエッジの重みが一貫して半分になり、問題の不可逆的なホース効果と一致するということです。 すべての遷移には負ではない重みがあり、グラフには 2 状態エンコーディングを超える隠れた依存関係が含まれていないため、ダイクストラは最適性を保証します。 したがって、この拡張された空間内の最短経路は、元の問題における最適な移動戦略に正確に対応します。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**18

def dijkstra(n, adj, horses, start):
    dist = [[INF, INF] for _ in range(n + 1)]
    pq = []

    dist[start][0] = 0
    heapq.heappush(pq, (0, start, 0))

    if horses[start]:
        dist[start][1] = 0
        heapq.heappush(pq, (0, start, 1))

    while pq:
        d, u, s = heapq.heappop(pq)
        if d != dist[u][s]:
            continue

        for v, w in adj[u]:
            if s == 0:
                nd = d + w
                ns = s
                if nd < dist[v][ns]:
                    dist[v][ns] = nd
                    heapq.heappush(pq, (nd, v, ns))
            else:
                nd = d + w // 2
                ns = s
                if nd < dist[v][ns]:
                    dist[v][ns] = nd
                    heapq.heappush(pq, (nd, v, ns))

        if s == 0 and horses[u]:
            if d < dist[u][1]:
                dist[u][1] = d
                heapq.heappush(pq, (d, u, 1))

    return dist

t = int(input())
for _ in range(t):
    n, m, h = map(int, input().split())
    horses = [0] * (n + 1)
    for x in map(int, input().split()):
        horses[x] = 1

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))

    distM = dijkstra(n, adj, horses, 1)
    distR = dijkstra(n, adj, horses, n)

    ans = INF
    for v in range(1, n + 1):
        ans = min(ans,
                  max(distM[v][0], distR[v][0]),
                  max(distM[v][0], distR[v][1]),
                  max(distM[v][1], distR[v][0]),
                  max(distM[v][1], distR[v][1]))

    print(-1 if ans == INF else ans)
```この実装では、馬の効果をバイナリ状態としてエンコードします。 ダイクストラ キューには (距離、ノード、状態) のタプルが格納され、状態遷移は慎重に分離されます。 唯一の微妙な移行は馬の頂点であり、コストゼロで加速状態に切り替えることができます。 

回答を組み合わせる場合、4 つの状態ペアすべてが明示的にチェックされます。 これは、旅行者が出会いの頂点に到達する前に馬を起動した場合と起動していない場合があるため、必要です。 

## 実用的な例

 ### 例 1 (直接的な改善を伴う単純なグラフ)

 1 が重み 10 で 2 に接続され、2 が重み 10 で 3 に接続され、頂点 2 に馬があるグラフを考えてみましょう。 マリアンは 1 からスタートし、ロビンは 3 からスタートします。 

| ステップ | マリアン距離[2][0] | マリアン分布[2][1] | ロビン距離[2][0] | ロビン距離[2][1] |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 で 1 | 馬の場合は 0、それ以外の場合は 1 INF | 0 で 3 | 馬の場合は 3、それ以外の場合は INF |
 | ディクストラの後 | 10、その後馬経由で 5 | 5 | 10 | 5 経由 2 |

 頂点 2 では、マリアンが馬を使って 5 に到着し、ロビンが反対側から 5 に到着します。 集合時間は5時です。 

これにより、最適化には正しい頂点で状態を切り替えることが不可欠であることが確認されます。 

### 例 2 (遅れた馬の使用による利点)

 頂点 3 のみに馬がいて、序盤のエッジに重みが大きい 1-2-3-4 のパス。 マリアンは後で 3 に達する可能性がありますが、アクティベーション後は大幅に恩恵を受けます。 ロビンも同様に反対側から近づいてくる。 

重要な観察点は、最適な集合場所は、必ずしも基本モードでどちらかが最も早く到着する場所ではないということです。 状態表は、アクティブ化を遅延させるとダウンストリーム時間が厳密に向上することを示しており、2 層ダイクストラ モデルの必要性が検証されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 2 つのダイクストラは、ノードごとに 2 つの状態を持つグラフ上で実行され、各エッジは一定の回数処理されます。 
| スペース | O(n + m) | 隣接リストと両方のソースの距離配列 |

 テスト ケース全体の頂点とエッジの合計は 2×10^5 で制限されるため、このアプローチはヒープ ベースの優先キューを使用しても制限内で快適に実行されます。

 ## 特殊なケース

 重要なエッジケースは、開始ノードにすでに馬が含まれている場合です。 そのような状況では、アルゴリズムにより、コストゼロで加速状態への即時移行が可能になります。 この移行を省略すると、その旅行者のすべての下流距離が過大評価され、不正確な集合時間が生成されます。 

もう 1 つのエッジ ケースは、両方の旅行者が異なる状態で頂点に到着した場合 (たとえば、一方は馬を持っていてもう一方は馬を持っていない) に発生します。 正しい会議時間は、4 つの州の組み合わせすべてを考慮する必要があります。 混合状態の会議をチェックしないと、両方の旅行者が対称的に行動していると誤って想定されますが、どちらかがより早く加速した可能性があるため、これは誤りです。 

最後の微妙なケースは、接続されていないグラフです。 いずれかの距離がすべての頂点のすべての状態に対して無限である場合、答えは -1 でなければなりません。 すべての最大値演算は無限のままであり、最終的な最小値は決して更新されないため、結合ステップはこれを自然に処理します。
