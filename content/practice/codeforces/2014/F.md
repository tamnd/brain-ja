 ## 解決策
 ## 問題の理解

 各ノードがある程度の金を保持するキャンプを表すツリーが与えられます。 特定のキャンプを「強化」するために選択する場合があります。 キャンプを強化しても、そのキャンプ自体のゴールドは直接変化しませんが、隣接するすべてのキャンプのゴールドが一定量減少します。$c$。 すべての強化の決定が行われた後、強化されたキャンプのみが生き残り、最終スコアはすべての削減後の生き残ったノードのゴールド値の合計になります。 

したがって、実際の決定は、近隣ノードがノードに与えるダメージの量を考慮した上で、選択したノードの合計貢献度を最大化するためにどのノードを選択するかということです。 

選択された各ノードは元の値を提供しますが、隣接するノードの 1 つが選択されるたびに、その値は によって減らされます。$c$。 最終的な合計では選択されたノードのみが重要となるため、相互作用は完全に選択されたノードのサブセット内で行われます。 問題は、ノードの重みとエッジの相互作用の両方に応じて値を最大化するノードのサブセットを選択することになります。 

この制約により、テスト ケースごとに線形または線形算術の解決策が求められます。 すべてのテスト ケースにわたるノードの合計数は次のとおりです。$2 \cdot 10^5$したがって、それ以上のことを行うソリューションはすべて、$O(n \log n)$テスト ケースごとの合計または単一の DFS ベースの DP は許容されますが、ツリー構造内の二次関数はすべて失敗します。 

素朴な直感による微妙な失敗例は、独立性を仮定することです (たとえば、すべての正のノードを選択するなど)。 これは失敗します。隣接する 2 つの高価値ノードを選択することは、ペナルティのため、そのうちの 1 つだけを選択するよりも悪くなる可能性があるからです。$c$。 もう 1 つの失敗は、貪欲なリーフ削除です。これは、ローカルな選択によって将来の利益が減少する長いチェーンで中断されます。 

## アプローチ

 構造を無視すると、ノードのすべてのサブセットを試してしまう可能性があります。 各サブセットについて、ノード値を合計して減算することでスコアを計算します。$c$両方のエンドポイントが選択されているすべての内部エッジに対して。 これは正しいですが、検討が必要です$2^n$サブセットは不可能ですが、$n = 30$。 

重要な観察は、目的は、選択されたセット内でどのエッジが「アクティブ化」されるかのみに依存するということです。 選択された各ノードはその重みに寄与し、選択されたすべてのエッジは次のペナルティに寄与します。$c$。 これはまさに、ノードとエッジがローカルで相互作用するツリー上の最大重みサブセットの問題です。 

このタイプの構造は、ツリー DP によって自然に処理されます。 ノードでの選択は、ノードが選択されているかどうか、およびその子がどのように動作するかによってのみ決まります。 ツリーをルート化すると、サブツリーのルートを選択するか選択しないという 2 つの状態を使用して、各サブツリーの最適なソリューションを表現できます。 

これにより、指数サブセット問題がツリー エッジ上の線形 DP に縮小されます。

 ## アルゴリズムのチュートリアル

 任意のノード (通常はノード 1) でツリーをルートします。各ノードの DP は 2 つの値を計算します。1 つはノードが選択されている場合と選択されていない場合のサブツリー内で達成可能な最高のスコアです。 

1. 定義する$dp[u][1]$のサブツリー内の最大スコアとして$u$選択すると$u$。 定義する$dp[u][0]$選択しない場合の最大スコアとして$u$。 

エッジに対するペナルティは両方のエンドポイントが選択されている場合にのみ適用されるため、この分離が必要です。 
2.初期化$dp[u][1] = a_u$を選択して以来、$u$近隣を考慮する前にその完全な値を与えます。 
3.初期化$dp[u][0] = 0$、選択していないので$u$直接的には何も貢献しません。 
4. それぞれの子どもたちに$v$の$u$、その貢献を にマージします$u$。 

もし$u$が選択されていない場合は、$v$エッジからのペナルティなしで選択することも選択しないこともできます$(u, v)$。 So we add$\max(dp[v][0], dp[v][1])$。 

もし$u$が選択されており、次に選択します$v$ペナルティが発生する$c$エッジが 1 回だけ寄与するためです。 それで:

 - 選択しない場合$v$、追加します$dp[v][0]$- 選択した場合$v$、追加します$dp[v][1] - c$したがって、この場合は追加します$\max(dp[v][0], dp[v][1] - c)$。 
5. すべての子を処理した後のルートの答えは次のようになります。$\max(dp[root][0], dp[root][1])$。 

これが機能する理由は、すべてのエッジが親から子まで 1 回だけ考慮され、両方のエンドポイントが選択された場合にのみペナルティが適用されるためです。 DP は、親の状態が固定されるとサブツリーの決定が独立していることを保証するため、インタラクションが見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)
        
        dp0 = [0] * n
        dp1 = [0] * n
        parent = [-1] * n
        
        order = []
        stack = [0]
        parent[0] = -2
        
        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if parent[v] == -1:
                    parent[v] = u
                    stack.append(v)
        
        for u in reversed(order):
            dp1[u] = a[u]
            dp0[u] = 0
            
            for v in g[u]:
                if v == parent[u]:
                    continue
                dp0[u] += max(dp0[v], dp1[v])
                dp1[u] += max(dp0[v], dp1[v] - c)
        
        print(max(dp0[0], dp1[0]))

if __name__ == "__main__":
    solve()
```実装では、再帰の深さの問題を回避するために、DFS 順序が反復走査に変換されます。 次に、子が親の前に評価されるように、ノードを逆の順序で処理し、必要なときに DP 状態の準備が整っていることを確認します。 重要な点は、ノードごとに 2 つのケース (選択された場合と選択されていない場合) を区別することです。これにより、選択したエッジごとに 1 回だけペナルティを正しく請求できるようになります。 

## 実用的な例

 値を持つ 3 つのノードの単純なチェーンを考えてみましょう。$[2, 3, 1]$そして$c = 1$。 

| ノード | dp0 | dp1 |
 | --- | --- | --- |
 | 3 | 0 | 1 |
 | 2 | 3 | 3 + 最大(0,1-1)=3 |
 | 1 | 3 | 2 + 最大(0,3-1)=4 |

 最終的な答えは 4 です。これは、ノード 3 ではなくノード 1 と 2 を選択することで得られます。 

これは、両端が選択されている場合にのみペナルティが適用されること、およびノードをスキップするとダウンストリームの値が増加する可能性があることを示しています。 

ここで、中心の値が大きいが葉が小さい星を考えてみましょう。 ペナルティが寄与を上回る場合、DP は当然、あまりにも多くのリーフを選択することを回避します。これは、ノード ゲインとエッジ コストの間のトレードオフを示しています。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$a_i$は否定的です。 DP はほとんどのノードの選択を正しく回避します。$dp[u][1]$は負の値から始まり、遷移により選択を完全にスキップできます。 もう一つのケースは次のような場合です。$c$非常に大きいため、隣接する選択が有害になります。 その後、DP は孤立した高価値ノードのみを選択するようになります。 最後のケースは、交互選択が最適なパスであり、これは親子状態の分割によって自然に捕捉されます。
