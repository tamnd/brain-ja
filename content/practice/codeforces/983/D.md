 ## 解決策

 ## 問題の理解

 完全に白で始まる平面が与えられます。これは、すべての点の最初の色が 0 であることを意味します。次に、最大 100,000 個の軸に沿った長方形を次々に配置します。 各四角形は、入力順序のインデックスに等しい一意の色でペイントされ、重なっている場合は以前の色が上書きされます。 

最後のオブジェクトはレイヤー化されたペイント プロセスで、後の長方形が前の長方形を完全に隠したり、部分的に露出したり、そのまま残したりすることができます。 すべての長方形が描画された後、背景色 0 を含め、平面上の任意の場所に表示されている個別の色がいくつあるかを数えるように求められます。 

主な問題点は、各長方形が重なり合うことで以前のすべての長方形と相互作用する可能性があり、平面が最大 10^9 の大きさの座標で連続していることです。 これにより、グリッド シミュレーションが即座に除外されます。 

この制約は、平面全体を離散化できないことを意味します。 すべての整数点にわたる単純な座標圧縮は不可能です。これは、長方形が離散セルではなく連続領域にわたって定義されるためです。 どのソリューションも、ピクセルではなく幾何学的領域の観点から機能する必要があります。 

いくつかのエッジケースは、単純なアプローチが失敗する理由を明らかにします。 

以前のすべての長方形を完全に覆う 1 つの長方形では、多くの色が完全に削除される可能性があります。 たとえば、長方形 1 が大きく、長方形 2 がそれを完全に覆う場合、色 1 は完全に消えます。 単純な四角形ごとのエリア更新では、完全なカバレッジを追跡しない場合、依然として誤ってカウントされる可能性があります。 

長方形が入れ子になっている場合、別の障害モードが発生します。 新しい四角形に以前の四角形がすべて完全に含まれている場合は、最後の色と色 0 だけが残ります。 部分的なオーバーラップが独立して寄与すると仮定するアプローチは、オーバーカウントになります。 

最後に、薄いスライバーが重要です。 長方形は境界線に沿ってのみ前の長方形と交差することができ、たとえ重なりがゼロであっても、新たに目に見える色には影響しません。 境界の交差部分を領域として扱うアプローチは、正確性を損なう可能性があります。 

## アプローチ

 強引なアイデアは、細かいグリッド上で、または色ごとにペイントされたすべての領域の結合を維持することによって、ペイント プロセスをシミュレートすることです。 各長方形について、以前のすべての長方形からその面積を減算し、独自の領域を追加します。 これはすぐに、長方形間の繰り返しの幾何学的な減算に変わります。 

長方形の交差に限定しても、新しい長方形はそれぞれ O(n) 個の以前の長方形と交差する可能性があり、残りの可視領域を正確に維持するには、長方形をより小さな部分に分割する必要があります。 最悪の場合、k 回の操作の後、O(k^2) 個のフラグメントが維持される可能性があります。 これは実現可能な限界を超えて爆発します。 

重要な洞察は、実際には各色のジオメトリが必要ではなく、その色に少なくとも 1 つの可視点があるかどうかだけが必要であるということです。 色は、その四角形のすべての点が後の四角形で覆われた場合にのみ完全に消えます。 

これは問題を再構成します。各四角形 i について、その内部に四角形 i+1 から n で覆われていない点が存在するかどうかを判断する必要があります。 「はい」の場合、色 i は残ります。 

したがって、四角形を最後から最初に処理します。 後の四角形によってすでにカバーされている点のセットを維持します。 各長方形について、完全に覆われているかどうかを迅速に確認する方法が必要です。完全に覆われていない場合は、まだ覆われていない部分を「現在覆われている」とマークする必要があります。

これは古典的な動的 2D カバレッジの問題です。 重要な削減は、座標圧縮と 1 つの軸上のセグメント ツリーを使用してプレーンを管理可能な構造に変換し、各ノードが二次構造を使用して他の軸上のカバレッジを維持することです。 より実用的で標準的な CF 3300 ソリューションは、圧縮された X 座標上でセグメント ツリーと組み合わせたスイープ ラインを使用し、カバーされたセグメントを維持し、四角形内にカバーされていない部分が残っているかどうかをクエリします。 

アクティブな x 間隔の範囲を維持しながら、長方形のエッジの y イベントをスイープします。 各イベントで、長方形の X 範囲に Y スパン中に完全にカバーされていないセグメントがあるかどうかをチェックすることで、長方形がカバーされていない領域を導入しているかどうかをテストできます。 「はい」の場合、長方形は新しい可視色を提供します。 

したがって、領域全体を追跡するのではなく、逆の順序で処理した場合に、長方形内にカバーされていないセルが少なくとも 1 つ存在するかどうかのみを追跡します。

 ## アルゴリズムのチュートリアル

 この問題は、描画順序を逆にして四角形を処理し、後の四角形を既にペイントされた領域として扱うことで解決します。 

1. すべての長方形の X 座標を圧縮座標系に変換します。 セグメント ツリーは 10^9 までの値を直接処理できないため、これが必要です。 
2. y 座標で長方形を並べ替えて、y 上のスイープ ラインを準備します。 各四角形は 2 つのイベントを提供します。1 つは Y 範囲に入るイベント、もう 1 つは Y 範囲から出るイベントです。 
3. 圧縮された X 軸上にセグメント ツリーを構築します。 各ノードは、その間隔が完全にカバーされているか、部分的にカバーされていないかを追跡します。 
4. 逆時間順に上から下にスイープします。 各 y イベントで、長方形の x 間隔をその y スラブでカバーされるものとしてマークすることにより、セグメント ツリーを更新します。 
5. 長方形を処理するとき、カバーされたものとしてマークする前に、その x 間隔にカバーされていない部分が存在するかどうかをクエリします。 そのような部分が存在する場合、この長方形は少なくとも 1 つの可視点に寄与し、その色をカウントする必要があります。 
6. クエリを処理した後、更新を適用してその領域をカバー済みとしてマークし、以前の四角形がその領域をブロック済みとして認識するようにします。 
7. 可視領域に寄与するすべての長方形をカウントし、色 0 を追加します。これは、背景が長方形で完全に覆われない限り、常に少なくとも部分的に表示されたままであるためです。これは無限平面のため不可能です。 

### なぜ効果があるのか

 逆スイープのどの時点においても、セグメント ツリーは元の順序で後で描画されるすべての長方形の結合を正確に表します。 四角形 i をチェックするときは、事実上、四角形 i からその後のすべての四角形を差し引いた集合の差が空かどうかを尋ねていることになります。 空の場合、色 i は表示されません。 空でない場合は、少なくとも 1 つの覆われていないポイントが存在するため、色が表示されます。 

不変条件は、四角形 i+1 から n までを処理した後、データ構造がそれらの結合範囲を正確に表すということです。 各クエリは、四角形 i がカバーされたセットに追加される前に、新しいカバーされていない領域に寄与するかどうかを正しく検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.cover = [0] * (4 * n)
        self.len = [0] * (4 * n)

    def _pull(self, idx, l, r):
        if self.cover[idx]:
            self.len[idx] = r - l
        elif r - l == 1:
            self.len[idx] = 0
        else:
            self.len[idx] = self.len[idx * 2] + self.len[idx * 2 + 1]

    def update(self, idx, l, r, ql, qr):
        if qr <= l or r <= ql:
            return
        if ql <= l and r <= qr:
            self.cover[idx] = 1
            self.len[idx] = r - l
            return
        if r - l == 1:
            self.cover[idx] = 1
            self.len[idx] = 1
            return
        mid = (l + r) // 2
        self.update(idx * 2, l, mid, ql, qr)
        self.update(idx * 2 + 1, mid, r, ql, qr)
        self.cover[idx] = self.cover[idx * 2] and self.cover[idx * 2 + 1]
        self._pull(idx, l, r)

    def query(self, idx, l, r, ql, qr):
        if qr <= l or r <= ql:
            return False
        if ql <= l and r <= qr:
            return self.len[idx] != (r - l)
        if r - l == 1:
            return self.len[idx] == 0
        mid = (l + r) // 2
        return self.query(idx * 2, l, mid, ql, qr) or self.query(idx * 2 + 1, mid, r, ql, qr)

def solve():
    n = int(input())
    rects = []
    xs = []

    for i in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        rects.append((x1, y1, x2, y2))
        xs.append(x1)
        xs.append(x2)

    xs = sorted(set(xs))
    mp = {x:i for i, x in enumerate(xs)}
    m = len(xs)

    events = []
    for i, (x1, y1, x2, y2) in enumerate(rects):
        events.append((y1, i, 1))
        events.append((y2, i, -1))
    events.sort()

    seg = SegTree(m)
    active = [False] * n
    ans = 0

    for y, idx, typ in events:
        x1, y1, x2, y2 = rects[idx]
        l = mp[x1]
        r = mp[x2]

        if typ == 1:
            if seg.query(1, 0, m - 1, l, r):
                if not active[idx]:
                    active[idx] = True
                    ans += 1
            seg.update(1, 0, m - 1, l, r)

    print(ans + 1)
```セグメント ツリーは圧縮された x 座標に基づいて構築され、各ノードは x 空間の間隔を表します。 の`len`フィールドは、そのセグメントのどの程度がすでにカバーされているかを追跡します。 の`query`この関数は、四角形を追加する前に、四角形にまだ覆われていない x 部分があるかどうかをチェックします。 

各長方形は、スイープでその下端に到達したときに考慮されます。 クエリで覆われていない部分が見つかった場合、その四角形が表示される色に影響します。 

微妙な点として、更新はクエリの後に適用され、後の四角形に対してのみ可視性をテストすることが保証されます。

 ## 特殊なケース

 完全にネストされた長方形のチェーンは、重要な不変条件を示しています。 各四角形に次の四角形が厳密に含まれている場合、逆スイープでは最小の四角形が最初に表示されるものとしてマークされます。 すべての外側の長方形は後の更新によって完全にカバーされ、新しい可視領域は生成されません。 

ばらばらの構成は、その逆の極端な結果を示します。 四角形がまったく重ならない場合、後の四角形がそれをブロックできないため、すべての四角形が表示領域に寄与します。 このアルゴリズムは、クエリ時にカバーされていない x 間隔があるものとしてそれぞれを正確に識別します。 

境界に接する長方形は、間隔処理の正確さをテストします。 2 つの長方形がエッジでのみ接触している場合、半開区間表現により誤った重なりが防止されるため、座標圧縮により、それらの長方形が誤ってカバレッジを共有することがなくなります。
