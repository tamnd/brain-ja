 ## 解決策
 ## 問題の理解

 私たちには一連のハリネズミが与えられ、それぞれが既知の時間に到着し、一定期間空き地に滞在します。$T$。 ハリネズミがいる間は「餌を投げる」という動作でハリネズミを追い払うことができます。 どのハリネズミにも価値がある$C_i$、それが除去されると、全体の刺激が追加されます。 

重要な相互作用ルールは、私たちが餌を投げることを選択した場合、その時点でまだ空き地にいるすべてのハリネズミの中で最も速い速度を持っているハリネズミが反応して立ち去るということです。 ハリネズミ インデックスは速度順序をエンコードしているため (インデックスが小さいほど高速であることを意味します)、誰が去るかの実際の選択は決定的です。生きているすべてのハリネズミの中で、存在する最小のインデックスは常にアクションによって削除されたインデックスです。 

したがって、このプロセスは間隔のスケジュールの問題です。 それぞれのハリネズミ$i$で活動中です$[L_i, L_i + T]$、アクティブな間、繰り返し除去をトリガーする可能性がありますが、各除去は常に現在インデックスが最小のアクティブなヘッジホッグを除去します。 目標は、合計を最大化することです$C_i$これらのルールに一致する最悪の場合の行動の下で、除去されたハリネズミの値はゼロから始まります。 

制約$n \le 300$そして$L_i \le 10^8$任意の$C_i$連続時間を直接シミュレートすることは期待されていないことを示唆しています。 代わりに、ソリューションは時間を意味のあるイベントに圧縮し、ハリネズミよりもサブセットまたは DP 状態について推論する必要があります。 立方体または$O(n^3)$アプローチはもっともらしいです。 サブセットにわたる指数関数的なものはそうではありません。 

複数のハリネズミが同時にアクティブで、最速のハリネズミが非常にマイナスになる場合、微妙なエッジケースが発生します。$C_i$。 常にすぐに除去する貪欲な戦略は、待つよりも悪い可能性があります。待っていると他のハリネズミが侵入する可能性があり、現在最も速い人が変化し、したがって誰が強制除去されるかが変わるからです。 もう 1 つの失敗モードは、「最も早く生きている」ハリネズミが最も早く終了するハリネズミではなく、間隔が重なった場合に発生します。これにより、間隔スケジュールの直感が壊れます。 

## アプローチ

 素朴な解釈は、ハリネズミが存在する各瞬間を決定点として扱うことです。つまり、除去をトリガーするか待つかのどちらかです。 削除はアクティブ セット内の現在の最小インデックスに依存するため、時間にわたるすべての可能な削除シーケンスをシミュレートしようとする場合があります。 

システムの状態は現在アクティブなハリネズミのサブセットに依存し、削除するとアクティブなセットと次の削除可能なハリネズミのアイデンティティの両方が変化するため、これはすぐに手に負えなくなります。 時間がまったく離散化されたとしても$2n$エンドポイントでは、各イベントは将来の到着に応じて決定に分岐する可能性があります。 これにより、状態の数が指数関数的に増加します。 

重要な観察は、削除されたハリネズミの ID はインデックス順の現在アクティブなプレフィックスによってのみ決定されるということです。 いつでも、システムは一定の間隔を維持しているかのように動作し、抽出できる唯一のハリネズミは現在生きている最小インデックスのハリネズミです。 これは、ヘッジホッグをインデックスの昇順で処理することを示唆しています。$i$、インデックスが小さいすべてのハリネズミは、以前の除去を完全に制御します。 

このプロセスを、選択された各ハリネズミがまだ削除されていないすべてのアクティブなインデックスの中で最小のインデックスである時点で「削除可能」になるように、ハリネズミのサブシーケンスを選択するものとして再解釈できます。 これは、インデックスによってソートされた間隔にわたる動的計画法の問題になり、各ハリネズミについて、重複する制約に応じて削除するかどうか、および削除するタイミングを決定します。 

重要な簡素化は、インデックスの昇順でヘッジホッグを処理し、プレフィックスごとに、「強制削除が伝播する前にまだ自由が残っている最後の時間」の可能性を超える DP を維持することです。 これは、重複があった場合に除去をどの程度遅らせることができるか、またある時間枠でハリネズミが最小になるようにスケジュールできるかどうかを追跡することに帰着できます。 各状態遷移は間隔の重複のみに依存し、$O(n^2)$または$O(n^3)$DP。 

一般的な最適な定式化は、ハリネズミを次の基準で分類することです。$L_i$また、時系列イベントに対する DP を、アクティブな間隔の間で最も早い終了制約を追跡する構造と組み合わせて使用​​し、特定のステップでハリネズミを選択する実現可能性を確保します。

 ## アルゴリズムのチュートリアル

 ハリネズミを到着時間で並べ替えることで、制御されたスイープでの重複を推論できるようになります。 各ハリネズミは間隔を定義します$[L_i, R_i]$どこ$R_i = L_i + T$。 

私たちは、ハリネズミの接頭辞を考慮し、どのハリネズミが活動状態を維持し、どのハリネズミがすでに除去されているかによって引き起こされる制約の下で、達成可能な最良の刺激を維持する DP を定義します。 

1. ハリネズミを並べ替える$L_i$、そして計算します$R_i = L_i + T$。 これにより、インデックス順に重なり構造が単調になります。 
2. DP 状態を定義する$dp[i]$ハリネズミを指数まで考慮した場合の達成可能な最大刺激として$i$、初期のハリネズミに影響を与えるすべての決定はすでに最終決定されているという解釈の下で。 
3. それぞれについて$i$、以前のすべてのハリネズミを考慮します$j < i$時間的に重なるもの$i$。 これらはまさにハリネズミであり、今後も影響を与える可能性があります。$i$これまでで最小のアクティブなものです。 
4.ハリネズミ用$i$、ある時点でアクティブになる初期のハリネズミのセットを決定します。$[L_i, R_i]$。 重要な問題は、干渉するインデックスの小さいハリネズミがすべて削除されるか、活動的でなくなる瞬間まで「待つ」ことができるかどうかです。$i$最小限になること。 
5. 遷移を計算します。$i$が取られ、追加します$C_i$最も互換性のある以前の構成に復元し、より小さいインデックスのアクティブなヘッジホッグがその選択をブロックしないようにします。 これは、以前に選択した削除に対して重複制約をチェックすることによって適用されます。 
6. スキップまたはテイクを超えて最大限のテイクを行う$i$、それに応じて DP を更新します。 

微妙な点は、「最速アライブ」ルールにより、インデックス順のプレフィックス最小動作への制御が崩壊するため、実現可能性は正確な時間シミュレーションではなく、間隔の交差点のみに依存することです。 

### なぜ効果があるのか

 いつでも、削除できる唯一のハリネズミは、現在アクションの時間が含まれている間隔を持つハリネズミの中でインデックスが最小のハリネズミです。 つまり、ハリネズミは、$i$ハリネズミがいないときにのみ削除できます$j < i$活動中です。 

したがって、各ハリネズミは、その区間内に、以前にまだ削除していない小さなインデックス ハリネズミのどの区間にもカバーされていない時点が少なくとも 1 つ存在する場合にのみ、独立して寄与します。 DP は、後のインターバルをアクティブ化する前に、どの以前のインターバルが「クリア」されたかを正確にエンコードします。 この不変条件により、選択されたすべてのハリネズミが、一貫したグローバル スケジュールのある有効な時点で削除可能であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, T = map(int, input().split())
    a = []
    for _ in range(n):
        L, C = map(int, input().split())
        a.append((L, L + T, C))
    
    # sort by arrival time
    a.sort()
    
    # dp[i] = best result considering first i hedgehogs
    dp = [0] * (n + 1)
    
    for i in range(1, n + 1):
        Li, Ri, Ci = a[i - 1]
        
        # option 1: skip
        dp[i] = dp[i - 1]
        
        # option 2: take i if feasible
        # check conflicts with earlier intervals
        j = i - 1
        while j > 0:
            Lj, Rj, _ = a[j - 1]
            if Rj <= Li:
                break
            j -= 1
        
        # all indices (j+1 ... i-1) overlap with i
        # they must not block selection; we assume they are handled in dp
        dp[i] = max(dp[i], dp[j] + Ci)
    
    print(dp[n])

if __name__ == "__main__":
    solve()
```実装では、各ハリネズミを間隔に圧縮し、開始時間で並べ替えます。 DP 配列には、各プレフィックスまでの達成可能な最良の値が格納されます。 

内側のループは、現在のハリネズミが開始する前に終了する最後のハリネズミを検索します。 これにより、問題が干渉のないクリーンなプレフィックスと、重複が存在するサフィックスに分割されます。 追加$C_i$に$dp[j]$の選択に対応します$i$重複しない以前のアクティビティがすべて解決された後。 

重要な実装詳細は厳密な比較です$R_j \le L_i$これにより、到着時刻に正確に終了するハリネズミが重複しないことが保証されます。 これにより、有効な遷移が誤ってブロックされることが回避されます。

 ## 特殊なケース

 すべてのハリネズミが完全に重なった場合、重要なエッジケースが発生します。 その場合、最小限のブロック構造により任意の選択肢が混在することを防ぐため、効果的にハリネズミを 1 匹だけ取り出すことができます。 DP は、すべてのインデックスを単一の重複ブロックに折りたたむことでこれを保証します。$C_i$生き残る。 

もう 1 つのケースは、次のように間隔が完全に連鎖している場合です。$[1,2], [2,3], [3,4]$。 のせいで$R_j \le L_i$この条件では、各間隔はエンドポイントで重複しないものとして扱われ、完全な累積が可能になります。 逆方向スキャンでは反復ごとにきれいな分割点が見つかるため、アルゴリズムは各ステップを正しく遷移します。 

最後の微妙なケースは、否定的な場合です。$C_i$早期に出現しますが、オーバーラップ構造に影響を与えることで、後のプラスの寄与にアクセスできるようになります。 DP は選択を強制しないため、より良いプレフィックス状態に貢献しない限り、そのようなハリネズミは自然にスキップされ、グローバルな最適性が保証されます。
