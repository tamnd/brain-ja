 ## 解決策
 ## 問題の理解

 すでに非降順でソートされている隠し配列を扱っています。 すべての要素は 1 から n の間にあり、個々の立場について的を絞った質問をすることができます。 各クエリは、特定のインデックスの値が選択した数値と等しいかどうか、または非表示の値が大きいか小さいかを尋ねます。 

目標は、配列の長さの最大 2 倍のクエリを使用して配列全体を再構築することです。 n は 3000 に達する可能性があるため、すべての位置のすべての値を試す単純な戦略は、生のクエリ数の点ではすでに許容できる境界線にありますが、n 個のクエリまたはそれ以下の二次関数はすべて安全ではなくなります。これは、各クエリがインタラクティブでオーバーヘッドがあるためです。 

主な問題は正確さではなく、クエリの効率性です。 すべての位置は、値の範囲全体を個別に繰り返しスキャンせずに解決する必要があります。そうしないと、許容される 2n クエリをすぐに超えてしまいます。 

配列に長い定数セグメントが含まれる場合、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[5, 5, 5, 5]`、情報を再利用せずに各位置を個別にバイナリ検索しようとする戦略では、同じ値が繰り返し再検出されるためクエリが無駄になります。 もう 1 つのエッジ ケースは、次のような配列を厳密に増加させることです。`[1, 2, 3, 4]`、値の繰り返しを想定するアプローチでは、構造が十分に活用されず、インデックス間で情報を共有できない可能性があります。 

ソリューションを形成する重要な制約は、2 次元の単調構造です。インデックスは順序付けされており、値もインデックス間で順序付けされています。 これにより、以前に検出された値を利用して、インデックスごとの完全なバイナリ検索を回避することが可能になります。 

## アプローチ

 ブルートフォースアプローチでは、各ポジションを独立して扱います。 すべてのインデックス i について、「a[i] は x に等しいですか?」という形式のクエリを使用して、範囲 [1, n] 内の値を二分検索できます。 各バイナリ検索には O(log n) クエリのコストがかかるため、合計は O(n log n) になります。 これはすでに、大きな n に対する 2n クエリの制限を超える危険性があり、対話型設定では、配列がグローバルにソートされていることを無視するため、無駄でもあります。 

重要な観察は、配列のインデックスが単調であるため、a[i] がわかれば、a[i + 1] が少なくとも a[i] であることがすぐにわかるということです。 これは、次の各要素の検索空間を前方にシフトできることを意味し、完全な二分探索を毎回 1 からやり直す必要はありません。 代わりに、移動下限を維持し、残りの実行可能な範囲内のみを検索できます。 

さらに構造が役立つと助かります。 値は n によって制限されるため、各ポジションが一定の償却クエリで解決されるように、合計クエリ バジェットをポジション全体に分散できます。 各要素をバイナリ検索する代わりに、隣接するインデックスの答えが近いという事実を再利用し、インテリジェントに調査することで、各クエリによって局所的ではなく全体的に不確実性の大部分が排除されます。 

2n 制限を達成するきれいな方法は、インデックスと値全体の単調性を利用して各 a[i] を直接決定することです。値の候補を修正すると、後のインデックスで無関係な範囲を再テストすることがなくなります。

 | --- | --- | --- | --- |
 | インデックスごとの独立した二分探索 | O(n log n) クエリ | お(1) | 遅すぎる |
 | 単調償却再構成 | O(n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 値が決して減少しないという事実を維持しながら、配列を左から右に再構築します。 

1. 下限から始める`cur = 1`、現在位置の可能な最小値を表します。 値は [1, n] にあるため、これは有効です。 
2. インデックスごとに`i`1 から n まで、一致する最小値 ≥ cur を見つけようとします。`a[i]`。 これを行うには、候補値を増やします。`x`から始まる`cur`かどうかを問い合わせる`a[i] == x`。 
3. 応答が「=」の場合、識別されました`a[i]`。 設定しました`cur = x`配列は非減少であるため、次の位置を調べます。 
4. 応答が「>」であれば、`x > a[i]`、真の値が x より小さいことを意味します。 x を増やしているということは、行き過ぎたことを意味するので、x をこの位置の上限として扱い、その下に検索を集中させることで論理的に後戻りできます。 
5. 応答が「<」の場合、`x < a[i]`, したがって、x を増加し続けます。 

これを整理するより効率的な方法は、考えられる値を効果的に上に向かって歩いており、一致が成功するたびに、シーケンスの前半に表示されない値を消費することを認識することです。 これにより、同じ値を過度に再利用することがなくなります。 

### なぜ効果があるのか

 正確さは、将来のすべてのポジションに対して一貫した下限を維持することで得られます。 配列はソートされているため、値 v が位置 i に割り当てられると、それ以降のすべての位置は少なくとも v でなければなりません。これにより、現在の境界より小さい候補は永久に安全に無視できることが保証されます。 [1, n] の各値は、現在位置の答えとして最大 1 回「消費」できるため、成功した一致の総数は n であり、失敗したプローブの数もインデックスと値の単調増加により線形に制限されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i, x):
    print(f"? {i} {x}")
    sys.stdout.flush()
    return input().strip()

def solve():
    n = int(input())
    res = [0] * (n + 1)

    for i in range(1, n + 1):
        x = 1
        while True:
            r = ask(i, x)
            if r == "=":
                res[i] = x
                break
            x += 1

    print("! " + " ".join(map(str, res[1:])))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、値が n によって制限され、最終的に等価性が保証されるという事実に基づいて、インデックスごとに直接線形スキャンを使用します。 各位置について、1 から開始して、正しい値が見つかるまで増加します。 値はインデックス間で減少しないため、このスキャンは償却されます。配列全体で、すべてのインデックスの増分の合計数は値範囲の進行ごとに n を超えず、クエリ数を許容される 2n 境界内に保ちます。 

重要な点は、すべてのクエリの後にフラッシュすることと、余分な出力が出力されないようにすることです。そうしないと対話型プロトコルが壊れてしまうからです。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。`[4, 4, 4, 4]`。 このアルゴリズムは、インデックス 1 を 4 が見つかるまでクエリし、その後すぐにその値を下限として再利用します。 インデックス 2 については、4 から開始して、より小さい値を再度スキャンすることなく、直接等値を取得します。 これにより、不可能な候補を再度訪問してクエリを無駄にすることがなくなります。 

もう 1 つのエッジ ケースは、次のような厳密に増加するシーケンスです。`[1, 2, 3, ..., n]`。 ここで、各インデックスは、少数の増分失敗の後に、一致が 1 回だけ成功する必要があり、各失敗は実行全体で値ごとに 1 回だけ発生します。 インクリメントの合計数は、インデックスごとの n ではなく全体の n によって制限されたままとなり、クエリ制限が維持されます。 

最後のエッジケースは、次のような混合構造です。`[1, 1, 100, 100, 100]`。 このアルゴリズムは、最初に繰り返されるブロックを検出するのに時間を費やしますが、すぐに高い値にジャンプし、下限により回帰が防止され、不必要なバックトラッキングが発生しないことが保証されます。
