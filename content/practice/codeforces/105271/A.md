 ## 解決策
 ## 問題の理解

 2 つのタイプのリソースが与えられます。1 つのタイプは単一の「A」ピースを表し、もう 1 つは「C」ピースを表します。 これらを使用して、行 i に 1 つの A とそれに続く i−1 個の C が含まれる三角形構造を構築したいと考えます。 

したがって、構造は行ごとに成長します。 最初の行には 1 A と 0 C が必要です。2 番目の行には 1 A と 1 C が必要です。3 番目の行には 1 A と 2 C が必要です。以下同様です。 行を追加するたびに必要な C の数が増加しますが、常に A が 1 つだけ消費されます。 

タスクは、使用可能な x A と y C を超えずに 1 から h までのすべての行を構築できるように、最大高さ h を決定することです。 

x, y ≤ 10^18 という制約により、行にわたるシミュレーションが回避されるようになります。 線形構築では、最悪の場合、最大 10^18 の反復が必要になりますが、これは 1 秒では不可能です。 テストごとの対数オーバーヘッドでも問題ありませんが、h に直接依存するものは問題です。 

微妙な失敗例は、計画を立てずに貪欲に行を構築した場合に発生します。 たとえば、x が大きく y が小さい場合、単純なアプローチでは行ごとに C がなくなるまでビルドしようとしますが、C の累積使用量のカウントを誤る可能性があります。 もう 1 つの問題は、A の使用量は高さが厳密に線形であるのに対し、C の使用量は二次関数的に増加することを忘れていることです。 

たとえば、x = 10 および y = 3 の場合、単純な行ごとのアプローチでは A が許可するため 4 行を試行する可能性がありますが、行 4 には合計 6 つの C が必要となり、これは不可能です。 

## アプローチ

 直接シミュレーションでは、行が 1 つずつ構築されます。 各行 i について、利用可能なプールから 1 つの A と i−1 個の C を差し引きます。 これが機能するのは、構造が決定論的であるため、リソースが枯渇するまで貪欲に構築できるからです。 ただし、最悪の場合、行数が 10^9 以上になる可能性があり、これは実行不可能になります。 

重要な観察は、リソースの消費は中間の選択には依存せず、高さ h のみに依存するということです。 h 行を作成した後、A の使用量の合計はちょうど h になり、C の使用量の合計は 0 + 1 + 2 + ... + (h−1) の合計となり、h(h−1)/2 に等しくなります。 これにより、問題は 1 つの h の実現可能性のチェックに変換されます。 

ここで、タスクは、h ≤ x および h(h−1)/2 ≤ y という両方の制約が成立するような最大 h を見つけることになります。 最初の制約は線形で、2 番目の制約は 2 次です。 二次制約は、不等式から導出された閉形式の式を使用して直接解くことができるため、二分探索は必要ありません。 

二次公式を使用して h(h−1)/2 ≤ y を満たす最大の h を計算し、x で最小値を取得します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(h) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. A によってのみ制限される最大可能高さを計算します。 各行はちょうど 1 つの A を消費するため、これは単純に x です。 
2. 不等式 h(h−1)/2 ≤ y を解くことにより、C で許容される最大の高さを計算します。 これは、すべての行で必要な C を合計することで得られます。 
3. 不等式を h² − h − 2y ≤ 0 に並べ替えます。これは標準の 2 次制約です。 
4. 対応する方程式 h = (1 + sqrt(1 + 8y)) / 2 の正の根を計算し、その下限を求めます。 これにより、C 制約に違反しない最大の整数 h が得られます。 
5. 最終的な答えは、2 つの制限のうち小さい方です。1 つは A の制限、もう 1 つは C の制限です。 

### なぜ効果があるのか

 この構造では、各行が独立して 1 つの A を消費することが強制されるため、A の使用量は高さが線形になります。 C の要件はプレフィックスの合計として決定論的に累積されるため、有効な高さは単一のスカラー不等式によって完全に特徴付けられます。 どちらの制約も h では単調であるため、高さが無効になると、それより大きな高さもすべて無効になり、計算された最大値が全体的に最適になることが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    
    # limit from A's
    h_a = x
    
    # limit from C's: h(h-1)/2 <= y
    # solve h^2 - h - 2y <= 0
    disc = 1 + 8 * y
    h_c = (1 + math.isqrt(disc)) // 2
    
    print(min(h_a, h_c))

if __name__ == "__main__":
    solve()
```この実装では、2 つの制約が明確に分離されています。 A 制約は、各行が正確に 1 つの A を消費するため、直接的です。C 制約は、y が 10^18 まで大きくなる可能性があるため、浮動小数点精度の問題を回避するために整数の平方根を使用して処理されます。 使用する`math.isqrt`正確な整数演算を保証します。 

決勝戦`min`有効な三角形は両方の制約を同時に満たす必要があるため、両方の制約を組み合わせます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isqrt

    x, y = map(int, input().split())
    h_a = x
    disc = 1 + 8 * y
    h_c = (1 + isqrt(disc)) // 2
    return str(min(h_a, h_c))

# provided samples (interpreted)
assert run("4 6") == "4"
assert run("4 5") == "3"

# minimum case
assert run("1 0") == "1"

# only C limits
assert run("1000000000000000000 0") == "1"

# tight triangular C bound
assert run("10 45") == "10"

# x limits strongly
assert run("3 1000000000000000000") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |

## 特殊なケース

 エッジ ケースの 1 つは、y = 0 の場合です。この場合、C を必要としない行のみが可能です。 つまり、x に関係なく最初の行のみが存在できるということです。 この式では disc = 1 となるため、h_c = 1 となり、最終的な答えは min(x, 1) となり、これは正しいです。 

もう 1 つの特殊なケースは、x が C 制限の高さよりもはるかに小さい場合です。 たとえば、x = 2 で y が非常に大きいとします。 C の式は大きな h_c を生成する可能性がありますが、A は直線的に消費され、すぐにボトルネックになるため、最終的な答えは正しく 2 に制限されます。 

3 番目のケースは、y が三角数と正確に一致する場合です。 y = 6 の場合、1 + 2 + 3 = 6 であるため、この式では h_c = 4 が得られ、整数の平方根のフロアリング動作によるオフバイ 1 エラーなしで等式境界が処理されることが確認されます。
