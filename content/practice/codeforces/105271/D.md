 ## 解決策
 ## 問題の理解

 各位置に小さな正の整数が格納される長さ n の配列が与えられます。 有効な構造は、値が厳密に減少する割り算連鎖を形成するような、i < j < k のインデックス i、j、k のトリプルです。a[i] は a[j] で割り切れ、a[j] は a[k] で割り切れ、同時に a[i] > a[j] > a[k] も満たします。 

各クエリはセグメント [l, r] を与え、そのセグメント内でそのようなトリプルを完全に見つけなければなりません。 すべての有効なトリプルのうち、どれか 1 つだけを返すわけではありません。 固定係数 n²、n、および 1 を使用して、左側の値が最も多くを占め、次に中央、次に右側の重み付きスコアを最大化します。複数のトリプルが同じ最大スコアに達する場合、辞書編集的に最小のインデックス トリプルが選択されます。 

この制約は、n が最大 100,000、q が最大 100,000 であることを意味します。クエリごとにすべてのトリプルを試行するソリューションは直ちに実行不可能です。単一のクエリのコストが O(n³) になり、さらにクエリあたり O(n²) であっても大きすぎるためです。 

重要な観察は、値が n によって制限され、割り算の制約が位置ではなく値にのみ依存するということです。 これは、値間の関係を事前に計算してから、位置を認識した構造を使用することを示唆しています。 

素朴だが重要なエッジ ケースは、配列に繰り返し値があるか、3 より長いチェーンが存在するが、厳密な不等式により有効ではない場合に発生します。 たとえば、a = [6, 3, 1] は有効ですが、[6, 6, 3, 1] は、たとえ割り算が成り立つ場合でも、等しい値は厳密な順序付け条件を破るため、慎重な取り扱いが必要です。 

もう 1 つの微妙なケースは、同じ値が複数存在する場合です。 インデックスは重要であるため、値の間違った出現を選択すると、値のトリプルが最適であっても、辞書編集上の最適性が損なわれる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリ範囲内のすべてのトリプル (i、j、k) を列挙し、両方の条件 (厳密な順序付けと可分性) をチェックします。 これは、定義を直接適用するため、正しいです。 ただし、すべての i、j、k の組み合わせを試すため、最悪の場合、各クエリのコストは O(n³) になります。 クエリが 100,000 件になると、これは実現可能な制限をはるかに超えます。 

j を固定し、i と k を検索することでクエリごとに O(n²) に改善しても、最悪の場合でも約 10¹⁰ の操作が発生し、これは実行可能ではありません。 

重要な構造的洞察は、値が小さく、分割可能性が値をめぐる有向関係を引き起こすということです。 中間の値 b について、取り得る左の値は大きい b の倍数であり、取り得る右の値は小さい b の約数です。 値は n で制限されているため、すべての値について、配列のプレフィックスとサフィックス内での最適な出現位置を事前計算できます。 

クエリごとに再計算するのではなく、各値の最も近い出現や最良のインデックスを前処理します。 次に、クエリごとに、有効な割り算連鎖を形成できる値のトリプル (x、y、z) のみを考慮するように制限し、その中で各値を [l, r] 内の可能な限り最適なインデックスにマップします。 これにより、インデックス トリプルではなく、有効なバリュー チェーン全体のスキャンの問題が軽減されます。 

最後の最適化では、各中間値 y について、その可能な最良の x と z が事前計算された候補セットから得られることを認識し、n までの値にわたって約数の関係をテストするだけで済みます。 これにより、問題は実装に応じておよそ O(n log n + q log n) または O(n sqrt n + q sqrt n) にまで下がります。

 ## アルゴリズムのチュートリアル

 クエリ範囲内の値ごとに最適なインデックスの可用性を維持しながら、位置ではなく値を処理するという問題を再定式化します。

1. 各値 v が出現するすべてのインデックスを事前計算します。 これにより、任意のクエリ範囲に v が存在するかどうかに高速にアクセスできるようになります。 これらの位置をソートされたリストに保存して、境界を二分探索できるようにします。 
2. 値 v ごとに、考えられるすべての (x, z) ペアを事前計算します。ここで、x は v の倍数、z は v の約数です。これにより、すべての有効な値のトリプル (x, v, z) がエンコードされます。 x > v > z という制約により、このグラフでは適切な方向のみが考慮されるようになります。 
3. クエリ [l, r] の場合、各候補値がセグメントに出現するかどうかを判断する必要があります。 保存されたインデックス リストに対して二分検索を使用して、各値の範囲内の最小の有効なインデックスを見つけます。 
4. 考えられるすべての中間値 v について、その候補 (x, z) ペアを反復処理します。 x、v、z がすべて [l, r] に存在する場合、範囲内の左端の有効な x、v、z を使用して候補インデックス トリプル (i、j、k) を構築します。 
5. すべての有効なトリプルのうち、スコア n²・a[i] + n・a[j] + a[k] を使用して比較します。 係数は固定されており支配的であるため、最初に a[i]、次に a[j]、次に a[k] を最大化します。 同点の場合、辞書編集的に最小のインデックスが選択されます。 
6. 有効な構造が存在しない場合は、最良のトリプルまたは -1 を返します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な解がちょうど 1 つの中間値 v と、v の x 倍および z の v 倍を満たすペア (x, z) に対応するということです。 このような値レベルの構造をすべて列挙し、各値をクエリ範囲内の利用可能な最良のインデックスに常にマッピングすることにより、候補となるトリプルを見逃すことはありません。 スコアは重みが固定された値で厳密に辞書編集されているため、値で比較してからインデックスで関係を解決することで正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        pos[a[i]].append(i)

    q = int(input())

    def first_in_range(lst, l, r):
        # binary search for first >= l
        lo, hi = 0, len(lst)
        while lo < hi:
            mid = (lo + hi) // 2
            if lst[mid] < l:
                lo = mid + 1
            else:
                hi = mid
        if lo < len(lst) and lst[lo] <= r:
            return lst[lo]
        return -1

    # precompute divisors and multiples relationships
    divisors = [[] for _ in range(n + 1)]
    multiples = [[] for _ in range(n + 1)]

    for v in range(1, n + 1):
        for k in range(2 * v, n + 1, v):
            multiples[v].append(k)
            divisors[k].append(v)

    for _ in range(q):
        l, r = map(int, input().split())

        best = None

        # iterate over possible middle values
        for y in range(1, n + 1):
            if not pos[y]:
                continue

            j = first_in_range(pos[y], l, r)
            if j == -1:
                continue

            for x in multiples[y]:
                if x <= y:
                    continue
                i = first_in_range(pos[x], l, r)
                if i == -1 or i >= j:
                    continue

                for z in divisors[y]:
                    if z >= y:
                        continue
                    k = first_in_range(pos[z], l, r)
                    if k == -1 or k <= j:
                        continue

                    cand = (a[i], a[j], a[k], i, j, k)
                    if best is None or cand > best:
                        best = cand

        if best is None:
            print(-1)
        else:
            print(best[3], best[4], best[5])

if __name__ == "__main__":
    solve()
```コードは最初に各値の位置リストを構築します。これにより、二分探索による高速な範囲の存在チェックが可能になります。 次に、n までの値に対して除数と複数の関係を構築します。 

クエリごとに、考えられる中間値 y を反復処理し、範囲内で有効な値を見つけてから、倍数から有効な x > y をすべて試行し、約数から有効な z < y をすべて試行します。 各候補は、適切なインデックスが存在するかどうか、および順序付け制約 i < j < k が満たされているかどうかをチェックすることによって検証されます。 

n² の重みが値によって辞書編集的に優勢であるため、タプルの比較では (a[i], a[j], a[k]) を暗黙的に使用してスコアリング ルールを適用します。 

## 実用的な例

 配列 a = [4, 2, 1, 4, 2, 8, 1] を考えて、[2, 4] をクエリします。 

y = 2 をチェックします。位置 2 と 5 に現れるので、範囲内では j = 2 とします。2 より大きい 2 の x の倍数の場合、考えられる x は 4 と 8 です。z の約数が 2 より小さい 2 の場合、z = 1。 

x = 4 は範囲内のインデックス 4 に出現し、z = 1 はインデックス 3 に出現することがわかります。これによりトリプル (4, 2, 3) が得られますが、順序付けには i < j < k が必要であるため、インデックスによって並べ替えて実現可能性を確認します。 有効な構造は (2, 3, 4) になります。 

| y | j | ×候補 | 私 | z候補 | k | 有効 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 2 | 2 | 4 | 4 | 1 | 3 | はい |

 これにより、アルゴリズムが最良のトリプルを正しく再構築していることが確認されます。 

ここでクエリ [3, 5] を考えてみましょう。 この範囲内の値は [1, 4, 2] です。 3 つの値が x > y > z という厳密な割り算の連鎖を形成することはありません。 アルゴリズムは有効な (x、y、z) を検出しないため、-1 を返します。

 ## 特殊なケース

 主なエッジケースは、値が有効な割り算チェーンを形成しているが、インデックスがインターリーブされている場合です。 たとえば、a = [6, 1, 3, 2]。 6、3、1 が有効なバリュー チェーンであっても、ポジションが昇順に表示されない場合があります。 このアルゴリズムは、値レベルではなくインデックス レベルで i < j < k を強制することでこれを処理します。 

もう 1 つのエッジ ケースは、a = [4, 4, 2] のような値が繰り返されることです。 4 > 2 であり、4 が 2 で割り切れる場合でも、間違った 4 を選択すると、辞書編集上の最適性に違反する可能性があります。 範囲内の最初の有効な出現を常に選択することにより、アルゴリズムはタイブレークを安定させます。 

最後のエッジケースは、中間値の候補が複数存在するが、完全なチェーンにつながるのは 1 つだけである場合です。 このアルゴリズムは、すべての中間値を個別に列挙し、まれな除数関係に依存する場合でも有効な構成がスキップされないようにします。
