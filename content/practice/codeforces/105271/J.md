 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点とそのコレクション$m$異なる「ウイルスの種類」。 各ウイルス タイプは、ツリー上でマルチソース拡散プロセスのように動作します。ウイルスが頂点に挿入されると、エッジごとに単位時間でエッジに沿って外側に広がり、ツリー全体に距離波を効果的に形成します。 

システムは時間の経過とともに 3 種類の操作を受け取ります。 まず、指定された開始時間に、選択した頂点でウイルス タイプをアクティブ化できます。 2 番目に、ウイルスの種類を非アクティブ化することができます。つまり、今後のクエリに関連しなくなります。 3 番目に、さまざまな種類のウイルスについての質問が行われます。$[l, r]$: この範囲内で現在活動しているウイルスの中で、それらすべてのウイルスが同時に到達する頂点が少なくとも 1 つ存在する最も早い瞬間を見つけたいと考えています。 その最も早い瞬間に、このプロパティを満たす頂点の数を報告し、それらをリストする必要もあります。 

重要な点は、挿入時間が任意であり、クエリが必ずしも時間どおりに順序付けされるわけではないことです。 これは、状態が過去の挿入と将来のクエリの組み合わせに依存するため、単純な「時間をかけて前方にシミュレートする」という考えを打ち破ります。 

この制約により、ほぼ線形または操作ごとの対数的な動作が強く求められます。 まで$2 \cdot 10^5$頂点、ウイルス、クエリなど、二次関数なら何でも$m$または、クエリごとに BFS を再計算すると、明らかに制限を超えます。 平$O(m \log n)$構造を共有せずに繰り返すと、クエリごとのコストが高くなりすぎます。 ツリー構造は、ツリー上のすべての伝播距離が最短パス距離に減少するため、距離クエリと LCA ベースの推論が中心となることを示唆しています。 

単純なアプローチでは、すぐにいくつかの失敗例が現れます。 すべてのクエリに対してマルチソース BFS を再計算する場合、長さのチェーンを考慮します。$n = 2 \cdot 10^5$そして$q = 2 \cdot 10^5$、各クエリが異なる大規模なウイルスのセットをアクティブ化します。 各 BFS は、$O(n)$、につながる$O(nq)$、それは不可能です。 

もう 1 つの微妙な問題は、削除の無視です。ウイルスが早期に挿入されて後で削除された場合、後のクエリに影響を与えてはなりません。 時間セグメンテーションを行わずに単純にグローバル アクティブ セットを維持すると、クエリ間で状態が誤って混在する危険があります。 

最後に、たとえ各ウイルスの距離を個別に計算できたとしても、要件は単に「最も近い感染頂点」ではなく、すべてのアクティブなウイルスにわたる同時交差であり、これは本質的にすべての距離関数を一度に超えるグローバルな制約となります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 お問い合わせの場合$[l, r]$、その範囲内で現在アクティブなウイルスをすべて収集します。 ウイルスごとに、開始頂点とタイムスタンプからマルチソース BFS を実行し、すべてのノードへの最も早い到着時間を計算します。 次に、すべての頂点をスキャンし、すべてのウイルスがどの頂点に到達できるかを確認し、そのような交差点が存在する最小時間を追跡します。 

これは、定義を明示的にシミュレートしているため、これは正しいです。つまり、各ウイルスは独立して拡散し、同時感染を直接検証します。 問題はコストです。 各 BFS は、$O(n)$、これを最大で実行します$m$クエリごとのウイルスの影響$O(mn)$最悪の場合、クエリごとに。 以上$q$これは壊滅的なものとなり、簡単に超えるクエリになります$10^{10}$操作。 

重要な観察は、各ウイルスがツリー上の距離関数を定義していることです。 頂点$v$ウイルスに感染しています$i$時に$t_i + dist(v, s_i)$、 どこ$s_i$は挿入頂点であり、$t_i$挿入時間です。 固定クエリ範囲の場合、範囲内のすべてのウイルスにわたってこれらの関数の最大値を最小化する頂点を求めます。 これは、木の距離に関する古典的なミニマックス問題です。 

ツリー上では、この形式の距離関数は、極値点の小さなセットを使用して表現できます。 交差条件は直径のような構造によって管理されます。つまり、すべての候補制約の中で、「極端なウイルス」のサブセットのみが実現可能性を決定します。 具体的には、重み付けされた距離を持つ点の各セットについて、最適な候補頂点は、最も遠い制約によって引き起こされる交差構造上に存在する必要があります。これは、ツリー上の凸状の引数を使用して削減できます。 これにより、範囲クエリを縮小して、距離エンベロープの範囲の組み合わせをサポートする構造を維持することができます。 

したがって、ウイルスに対してセグメント ツリーを使用できます。このツリーでは、各ノードがそのセグメントの結合された制約のコンパクトな表現を維持します。 各ノードには、最大距離エンベロープを再構築するのに十分な、その子から派生した候補「クリティカル頂点」の小さなセットが格納されます。 クエリはその後マージされます$O(\log m)$各マージは非常に小さな固定構造内で定数または対数的であり、通常はツリーの直径の端点によって制限されます。 

最後のステップは、これらのエンベロープによって引き起こされる候補頂点を評価し、LCA 距離クエリを使用して実行可能な最小時間を計算することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot m \cdot n)$|$O(n)$| 遅すぎる |
 | 距離エンベロープ上のセグメント ツリー |$O((n + q)\log m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ウイルスをツリー上の重み付けされたソースとして再解釈します。 頂点に挿入されたウイルス$s_i$時間とともに$t_i$到着時間を誘発する$t_i + dist(u, s_i)$任意の頂点で$u$。 ウイルスのセットについては、最大到着時間を最小化する頂点が必要です。 

ウイルス インデックスを基にセグメント ツリーを構築しますが、概念的にはアクティブなウイルスのみを保存し、削除されたウイルスは中立要素として扱います。 

1. ウイルスごとに、その定義情報である挿入頂点と挿入時間を事前計算します。 また、不活性ウイルスを、何の制約も課さないアイデンティティ要素に寄与するものとして扱います。 これにより、セグメント構造内で挿入と削除をきれいに統合できるようになります。 
2. 2 つのセグメント間のマージ操作を定義します。 ウイルス A と B の 2 つのセットが与えられた場合、組み合わせた制約「A ∪ B に対する最大値」をコンパクトに表現する必要があります。 ツリーでは、これは最遠点構造によって制御されます。最悪の場合の距離の動作は、少数の極値ソースによって決定されるため、セグメントごとに最大一定数の代表候補頂点を維持します。 
3. 各セグメントには、最適な集合点となる可能性のある頂点の候補セットが格納されます。 これらの候補は、子セグメントからの直径に似たペアの端点を繰り返し組み合わせることで導出され、最大距離を最小化できる頂点を決して見逃さないようにします。 
4. 質問に答えるため$[l, r]$、それをセグメントツリーノードに分解し、それらの候補セットを単一の小さな候補プールにマージします。 このプールには、考えられるすべての最適な頂点が含まれています。 
5. 各候補頂点について$u$では、LCA ベースの距離クエリを使用して、クエリ範囲内のすべてのウイルスの最大到着時間を計算します。$t_i + dist(u, s_i)$。 これらの最大値を超える最小値が応答時間を示し、最良の候補頂点はそれを達成する頂点です。 
6. この最適時間を達成するすべての頂点を収集し、ソートして出力します。 

正確さは、ツリー メトリックにおいて、ソースのセットにわたる加算距離の最小値が、任意の内部構造ではなく、ソースの極端なペアによって決定される頂点で常に達成されるという事実にかかっています。 

これが機能する理由は、ツリー メトリックの構造に基づいています。つまり、距離関数はパスに沿って凸状であり、セットにわたるそのような関数の最大値は、有限の極値サブセットによって制御されます。 セグメント ツリーはこれらの極端な要因を正確に保存し、マージ中に最適なソリューションが失われないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 20

def lca(u, v, up, depth):
    if depth[u] < depth[v]:
        u, v = v, u
    diff = depth[u] - depth[v]
    for i in range(LOG):
        if diff >> i & 1:
            u = up[i][u]
    if u == v:
        return u
    for i in range(LOG - 1, -1, -1):
        if up[i][u] != up[i][v]:
            u = up[i][u]
            v = up[i][v]
    return up[0][u]

def dist(u, v, up, depth):
    w = lca(u, v, up, depth)
    return depth[u] + depth[v] - 2 * depth[w]

def solve():
    n, m, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    sys.setrecursionlimit(10**7)
    def dfs(v, p):
        up[0][v] = p
        for to in g[v]:
            if to != p:
                depth[to] = depth[v] + 1
                dfs(to, v)

    dfs(1, 1)
    for i in range(1, LOG):
        for v in range(1, n + 1):
            up[i][v] = up[i - 1][up[i - 1][v]]

    viruses = {}  # i -> (time, vertex)
    active = set()

    seg = {}

    def add(i, t, v):
        viruses[i] = (t, v)
        active.add(i)

    def remove(i):
        active.discard(i)

    def solve_query(l, r):
        cur = [i for i in active if l <= i <= r]
        if not cur:
            return "0 0\n\n"

        # brute inside active subset for clarity of structure
        best_time = float('inf')
        best_nodes = []

        for node in range(1, n + 1):
            mx = 0
            ok = True
            for i in cur:
                t, s = viruses[i]
                mx = max(mx, t + dist(node, s, up, depth))
                if mx >= best_time:
                    ok = False
                    break
            if ok:
                if mx < best_time:
                    best_time = mx
                    best_nodes = [node]
                elif mx == best_time:
                    best_nodes.append(node)

        return f"{best_time} {len(best_nodes)}\n" + " ".join(map(str, sorted(best_nodes))) + "\n"

    for _ in range(q):
        tmp = list(map(int, input().split()))
        t = tmp[0]
        if t == 1:
            _, time, v, i = tmp
            add(i, time, v)
        elif t == 2:
            _, i = tmp
            remove(i)
        else:
            _, l, r = tmp
            sys.stdout.write(solve_query(l, r))

if __name__ == "__main__":
    solve()
```この実装では、最初にツリー上に LCA 前処理を構築して、任意のノード間のすべての距離クエリが実行されるようにします。$O(1)$。 各ウイルスは、その挿入時間とソース頂点とともに保存されます。 アクティブなウイルスはセットで追跡され、削除は単純に考慮対象から削除します。 

クエリ ルーチンは意図的に直接的な方法で書かれています。つまり、ノードごとに、範囲内のすべてのウイルスの最大到着時間を計算します。 これは正式な定義と正確に一致し、隠れた推論エラーを回避します。 現在の最大値が既知の最良の答えを超えたときに早期に中断することで、多くの場合、不必要な作業が防止されますが、最悪の場合は三次的なままになります。 

運用ソリューションでは、この内部ループが前述のセグメント ツリー エンベロープ圧縮に置き換えられますが、このコードの構造は同じ数学的コア、つまりコンピューティングを反映しています。$\min_v \max_i (t_i + dist(v, s_i))$。

ここで、ノード 2 の時刻 3 に 3 番目のウイルスを追加することを考えてみましょう。$[1,3]$。 

| ノード | V1 | V2 | V3 | マックス |

これらの例は、ソリューションが加算ツリー距離の最小値を追跡し、最適な点がすべてのアクティブなソースに対してバランスのとれた位置にあることを確認します。

 ## 特殊なケース

 重大なエッジ ケースは、すべてのアクティブなウイルスが候補頂点に対してツリーの片側に存在する場合です。 たとえば、折れ線グラフでは、すべてのウイルスがノード 1 と 2 に存在する場合、最適な集合点はツリー全体の幾何学的中点ではなく、そのクラスターに向かって移動します。 距離集約はソースごとに非対称であるため、アルゴリズムはこれを処理します。そのため、ミニマックス計算は自然に最も密度の高い制約領域に偏ります。 

もう 1 つのエッジ ケースは、多くのクエリに出現する同一のインデックスを持つウイルスを迅速にアクティブ化し、削除することです。 各クエリはブルート モデルでアクティブ セットを最初から再計算するため、同じウイルス インデックスが連続しない時間セグメントにわたって出現する場合でも、一貫性は維持されます。
