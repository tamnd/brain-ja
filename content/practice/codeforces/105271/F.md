 ## 解決策
 ## 問題の理解

 Minim には次のシーケンスがあります`n`試験の数時間前。 各時間に、指定された文字列に応じて、食べるか寝るかのいずれかのアクティビティが 1 つだけ実行可能です。 キャラクター`e`その時間内に食事が許可されていることを意味し、`s`つまり、彼は寝ることが許可されています。 

彼はちょうど食べて寝たばかりの 0 時に始まります。 その瞬間から、彼は食べたり眠ったりせずにあまり長く続かないようにしなければなりません。 具体的に言うと、彼はせいぜい生き残ることができます`a`食べずに連続数時間、最大でも`b`眠れずに何時間も続く。 ある時点で彼が最後に食事をしたのがそれ以上だったとしたら、`a`数時間前、または彼が最後に眠ったのはそれ以上でした`b`数時間前、彼は失敗した。 

スケジュールが許せば、1時間ごとに食事をするか寝るかのどちらかです。 目標は、すべての状況を乗り切りながら、これらの必須の活動に費やす時間を最小限に抑えるための行動を選択することです。`n`何時間も。 生存が不可能な場合は報告しなければなりません`-1`。 

制約は小さいです。`n ≤ 100`、したがって、おおよその解決策までは`O(n^3)`実現可能であり、さらには`O(n^2)`または`O(n^2 log n)`快適です。 これは、貪欲な推論ではなく、時間の経過に伴う動的プログラミングの定式化と「最後のアクション」状態を強く示唆しています。 

許可されたスケジュールに両方のタイマーをリセットする十分な機会が含まれていない場合、微妙なエッジ ケースが発生します。 たとえば、すべての文字が`e`、その場合、十分な頻度で睡眠をスケジュールする必要があります。そうしないと、睡眠不足が発生します。 同様に、文字列が`ssss...`、食事ができなくなります。 もう 1 つの重要なケースは、両方のリソースがかろうじて実現可能であるが、一方のリソースを早期に消費すると、後で避けられない障害が発生する可能性があるため、慎重にインターリーブする決定が必要な場合です。 

## アプローチ

 強引な解釈では、利用可能性を考慮して、各時間ごとに食べるか、寝るか、スキップするかについて、考えられるすべての選択肢を試すことになります。 各時間には最大 2 つの有効な選択肢があるため、約`2^n`可能なスケジュール。 のために`n = 100`、天文学的な数のシーケンスを探索するため、これは完全に実行不可能です。 

重要な観察は、スケジュールの将来の有効性は、最後の食事と最後の睡眠行動からの経過時間のみに依存するということです。 現在の時刻とこれら 2 つの「クールダウン」値がわかれば、過去は問題ではなくなります。 これにより、各状態が次のとおりである古典的な状態グラフが作成されます。`(i, last_e, last_s)`つまり今は時間です`i`そして私たちが最後に食事をしたり眠ったりしたのは、以前の位置でした。 

このような状態からは、その時間をスキップするか (許可されている場合)、その時間に許可されているアクションを実行して、最終アクションのタイムスタンプの 1 つをリセットすることができます。 蓄積されるコストは、実行されたアクションの数です。 私たちは、生存限界を決して超えないようにしながら、このコストを最小限に抑えたいと考えています。 

これは当然のことながら、時間の経過に伴う DAG のような構造上の最短経路の問題、またはより単純に言えば、動的プログラミングの問題です。`i`最後の食事と最後の睡眠の制約を更新するトランジションを使用します。 なぜなら`n ≤ 100`のすべての状態を明示的に追跡できます。`O(n^3)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 時間の経過に伴う DP と最後のアクション | O(n^3) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP 状態を定義します`dp[i][j][k]`1 時間までに使用されるアクションの最小数として`i`、 どこ`j`私たちが食事をした最後の時間です`k`私たちが眠った最後の時間です。 両方のアクションが発生した仮想時間 0 が含まれるため、初期状態は次のようになります。`(0, 0)`。 

を除くすべての状態を無限大に初期化します。`dp[0][0][0] = 0`。 

時間ごとに`i`1から`n`、時間から到達可能なすべての状態を伝播します。`i-1`時間まで`i`。 

1. 以前のすべての状態について`(j, k)`時に`i-1`、まず実現可能性を確認します。 必要です`i - j ≤ a`そして`i - k ≤ b`。 どちらかが失敗すると、生存制約がすでに違反されているため、この状態は破棄されます。 
2. 有効な状態から、時間ごとにアクションは実行されないとみなします。`i`。 これにより、`(j, k)`変更されず、同じコストが繰り越されます。 これが許されるのは、単にこの時間帯に消費をスキップすることを選択しているだけだからです。 
3. 現在の時間で食事ができる場合 (`c[i] = 'e'`)、最後の食事が次の状態になる新しい状態に移行できます。`i`そして最後の眠りが残っている`k`。 これは、この時間を食事に費やし、コストが 1 増加することを表します。 
4. 現在の時間が睡眠可能であれば (`c[i] = 's'`)、同様に次のように遷移します。`(j, i)`コスト+1で。 
5. すべての遷移にわたって最小値を取得します。 

すべての時間を処理した後、時間ごとに生存制約を満たす状態を再度フィルタリングします。`n`。 答えは、すべての有効な最終状態の中での最小 dp 値です。 有効な状態がない場合は、次のように出力します。`-1`。 

これが機能する理由は、すべての状態が将来の実現可能性を決定するために必要な情報を正確にエンコードしているためです。重要なのは最後の食事と最後の睡眠の位置だけです。 同じことにつながる 2 つの歴史`(i, j, k)`将来の制約はこれらの位置からのギャップのみに依存するため、これらは同等です。 DP は、実行可能なすべてのスケジュールを検討し、最小限の強制アクションを蓄積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    c = input().strip()

    INF = 10**9

    # dp[i][j][k] = min actions up to i, last eat j, last sleep k
    dp = [[[INF] * (n + 1) for _ in range(n + 1)] for _ in range(n + 1)]
    dp[0][0][0] = 0

    for i in range(1, n + 1):
        for j in range(i):
            for k in range(i):
                if dp[i - 1][j][k] == INF:
                    continue

                # survival check
                if i - j > a or i - k > b:
                    continue

                cur = dp[i - 1][j][k]

                # option 1: skip action
                dp[i][j][k] = min(dp[i][j][k], cur)

                # option 2: eat
                if c[i - 1] == 'e':
                    dp[i][i][k] = min(dp[i][i][k], cur + 1)

                # option 3: sleep
                if c[i - 1] == 's':
                    dp[i][j][i] = min(dp[i][j][i], cur + 1)

    ans = INF
    for j in range(n + 1):
        for k in range(n + 1):
            if n - j <= a and n - k <= b:
                ans = min(ans, dp[n][j][k])

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```DP テーブルには、時間と最後のアクションの位置によってインデックスが付けられます。 主な微妙な点は実現可能性のチェックです`i - j ≤ a`そして`i - k ≤ b`、繰り越された州であっても生存限界に違反しないことを強制します。 もう一つの微妙な点は、スキップが変わらないことです。`j`または`k`、最後のアクションのタイムスタンプが正しく保存されます。 

食事と睡眠の遷移は 1 つの次元のみを上書きするため、対応する飢餓タイマーのリセットが正しくモデル化されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、1 つのアクティビティ タイプがほとんど存在しない場合です。 文字列に含まれる内容が非常に少ない場合`e`キャラクターの場合、DP は睡眠制約が影響を及ぼさないようにする必要があります。 最終実行タイムスタンプを使用して各ステップで実現可能性がチェックされるため、状態遷移はこれを正しく処理します。 

もう 1 つのエッジケースは次のような場合です`a`または`b`この状況では、DP はそのタイプの許可された時間ごとにアクションを強制し、事実上、そのリソースのスキップを不可能にします。 実現可能条件`i - j ≤ a`無効な状態は直ちに削除され、隠された無効なスケジュールが残らないようにします。 

最後のエッジケースは、最適な戦略が将来の実現可能性を維持するためにアクションを遅らせる必要がある場合に発生します。 DP は、有効な最後のアクションのタイムスタンプを引き継ぎながら、コストをかけずにスキップできるため、これを捉え、当面の制約と将来の制約の間でグローバルに最適なバランスを確保します。
