 ## 解決策
 ## 問題の理解

 ゲームはボードやグラフではなく、数字でプレイされます。 移動すると、現在の数値がその約数の 1 つに置き換えられますが、約数を 1 にすることはできず、数値そのものにすることもできません。 正当な手を持っていないプレイヤーが勝ちとなり、ゲームはミゼール形式の除数ゲームになります。素数または 1 に到達すると、次のプレイヤーは移動の機会を失うことになるため、良いことになります。 

チノは指定された番号 n で最初に移動します。 彼女は、最初のターンでデイビッドを負けた状態にする約数を選択したいと考えています。 そのようなすべての選択肢の中で、彼女はできるだけ多くの数を望んでいます。 n 自体に正当な初手がない場合、n はすでに勝っており、答えは 0 です。考えられるすべての初手で David が勝つことができる場合、答えは -1 です。 

n の値は最大 100000 で、最大 1000 個のテスト ケースを含めることができます。 これにより、入力ごとに除数ツリー全体を繰り返し探索する必要がなくなります。 すべての約数に対する再帰的なゲーム検索では、同じ状態を繰り返し訪問する可能性があり、コストがかかる可能性があるため、ソリューションでは勝ちポジションと負けポジションの数学的構造を認識し、有用な情報を前処理する必要があります。 

いくつかの特殊なケースは見落とされがちです。 n = 1 の場合、法的な約数は存在しないため、Chino がすぐに勝ち、答えは 0 になります。勝利の約数を検索する不注意な実装では、誤って -1 が返されます。 

n = 7 の場合、素数でも同じ状況が発生します。 約数は 1 と 7 のみで、どちらも禁止されているため、正しい出力は 0 です。 

n = 6 の場合、最初に選択できるのは 2 と 3 のみです。どちらもプライム ポジションであり、次のプレイヤーは何も動かずに勝ちます。 Chino は勝利を強制できないため、正しい出力は -1 です。 除数が存在するかどうかだけをチェックするアプローチは、ここでは失敗します。 

n = 12 の場合、チノは 4 を選択できます。数字 4 には 2 への 1 つの手しかありません。2 は最終的な勝ち位置です。 したがって、4 はそのターンのプレイヤーにとって負けのポジションであるため、チノが 4 を選択した後、デビッドは負けます。正しい出力は 4 です。 

## アプローチ

 直接的な解決策では、すべての数値をゲームの状態としてモデル化します。 数値 x については、すべての適切な約数を生成し、現在のプレーヤーが強制的に勝利できるかどうかを再帰的に判断できます。 これは正しいです。移動するたびに数値が厳密に減少するため、再帰は最終的に素数または 1 に達します。 

問題は、同じ推論が何度も繰り返されることです。 たとえば、多くの異なる合成数には約数として 4、6、または 9 が含まれており、単純な検索ではこれらの位置の結果が繰り返し再計算されます。 メモ化を行ったとしても、多くのテスト ケースに対してこれを個別に行うと作業が無駄になります。 すべての状態に対して約数を生成し、到達可能なすべての状態を横断すると、n が 100000 に達すると大きすぎます。 

重要な観察は、このゲームは非常に単純な負けポジションの構造を持っているということです。 あらゆる可能な手が勝ちポジションに進んだ場合にのみ、ポジションは負けとなります。 素数と 1 は、利用可能な手がないため、勝ちの位置になります。 合成数は、その適切な約数がすべて素数の場合に正確に負けます。 これは、多重度を数えて、数値が 2 つの素数の積である場合に正確に発生します。 

数値に複合固有約数が含まれている場合、その約数はすでに可能な手となります。 重要な合成約数の最小値は常に 2 つの素数の積であり、それらの位置は負けています。 これは、2 つ以上の素因数を持つすべての合成数が負けの位置に移動し、勝ちとなることを意味します。 

次に、問題は n の最大の半素因数を見つけることに帰着します。ここで、半素とは、多重性を持つちょうど 2 つの素因数を持つことを意味します。 この除数は、David を負けた状態にするため、最良の最初の動きです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 潜在的に O(テスト ケースごとに到達可能な除数状態の数) | メモ化による O(n) | 多くの場合遅すぎる |
 | 最適 | O(N log log N + N log N) 前処理 | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースを読み、表示される最大値 N を見つけます。 これより大きな数値を必要とするクエリはないため、すべての前処理をこの値に制限できます。 
2. ふるいを使用して N までの素数を見つけます。ゲーム状態の分類はその素因数にのみ依存するため、高速な素数情報が必要です。 
3. 半素数であるすべての数字にマークを付けます。 多重度を伴う素因数の数がちょうど 2 である場合、その数値は準素数になります。 たとえば、4 = 2 × 2、6 = 2 × 3、および 9 = 3 × 3 は半素数です。 
4. すべての半素数 d について、d より大きい d の倍数をすべて更新します。 値 d はこれらの倍数に対する有効な最初の動きであり、最大の候補を維持すると、最大の勝利となる最初の動きが得られます。 Chino は元の数値自体を選択できないため、d に等しい倍数はスキップされます。 
5. 各クエリ n について、最初に特殊な状態を処理します。 n が 1 または素数の場合、チノは動かずに勝つため、0 を出力します。n が準素数の場合、正当な手はすべて素数になるため、チノは勝つことができず、答えは -1 になります。 それ以外の場合は、前処理中に保存された最大の半素数を出力します。 

正しさは、数値 x に対して保存されているすべての答えが、負けているゲーム状態である x の最大の約数であるという不変条件から得られます。 負けたゲーム状態はまさにセミプライムであるため、保存されている候補はすべて勝ちの先手となります。 すべての非半素合成数には少なくとも 1 つの半素の約数があるため、チノが移動して勝つことができるときはいつでも、保存された値が存在します。 保存されている最大の約数を選択すると、結果が変わることなく Chino の好みが満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    queries = [int(input()) for _ in range(int(input()))]
    if not queries:
        return

    limit = max(queries)

    prime = [True] * (limit + 1)
    if limit >= 0:
        prime[0] = False
    if limit >= 1:
        prime[1] = False

    i = 2
    while i * i <= limit:
        if prime[i]:
            step = i
            start = i * i
            prime[start:limit + 1:step] = [False] * (((limit - start) // step) + 1)
        i += 1

    factor_count = [0] * (limit + 1)
    for p in range(2, limit + 1):
        if prime[p]:
            for x in range(p, limit + 1, p):
                y = x
                while y % p == 0:
                    factor_count[x] += 1
                    y //= p

    semiprime = [False] * (limit + 1)
    for x in range(2, limit + 1):
        if factor_count[x] == 2:
            semiprime[x] = True

    best = [0] * (limit + 1)
    for d in range(2, limit + 1):
        if semiprime[d]:
            for multiple in range(d * 2, limit + 1, d):
                best[multiple] = d

    ans = []
    for n in queries:
        if n <= 1 or prime[n]:
            ans.append("0")
        elif semiprime[n]:
            ans.append("-1")
        else:
            ans.append(str(best[n]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ふるいは、発見されたすべての素数の倍数を削除することによって、通常の方法で素数配列を作成します。 0 と 1 の境界ケースは、素数ではなく、sieve ループが 2 から始まるため、明示的に設定されます。 

因数カウントループは、繰り返して素因数をカウントします。 8 = 2 × 2 × 2 には 3 つの素因数があり半素数ではないのに対し、4 = 2 × 2 は半素数であるため、この詳細は重要です。 異なる素因数だけを数えると、両方が誤って分類されてしまいます。 

の`best`配列は、クエリごとに約数を反復するのではなく、半素数を反復することによって埋められます。 すべての準素数はそれ自体でより大きな倍数すべてに寄与し、反復が上向きに進むため、後の寄与はより小さな答えを上書きします。 厳格な`2 * d`開始点により、元の数値をそれ自身の除数として保存することができなくなります。 

最終的なクエリ処理は、ゲーム理論の分類に直接準拠します。 素数と 1 は即座に勝ち、半素数は避けられない損失で、残りのすべての合成数は事前に計算された最良の半素数を使用します。 

## 実用的な例

 入力値 6 を考えてみましょう。 

| 番号 | プライム？ | セミプライム？ | 最良の半素約数 | 出力 |
 | --- | --- | --- | --- | --- |
 | 6 | いいえ | はい | 未使用 | -1 |

 6 番には 2 と 3 の 2 つの正当な選択肢があります。どちらも素数であるため、デビッドは何も動かずに勝ちとなるポジションを受け取ります。 セミプライムの分類では、6 が最初のプレーヤーの負けポジションとして正しく識別されます。 

入力値 12 を考えてみましょう。 

| 番号 | プライム？ | セミプライム？ | 最良の半素約数 | 出力 |
 | --- | --- | --- | --- | --- |
 | 12 | いいえ | いいえ | 4 | 4 |

 前処理中、4 は準素数として認識されます。 4は12を割って12より小さいので、答えの候補になります。 12 というより大きな準素数の約数は存在しないため、チノは 4 を選択し、デビッドを負けた状態のままにします。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは以下をチェックします。`n <= 1`最初に実行し、すぐに 0 を返します。 選択できる約数はないため、チノは行動を起こす前にすでに勝利しています。 

n = 7 などの素数の場合、素数配列はそれを素数としてマークし、アルゴリズムは 0 を返します。素数には正当な動きがまったくないため、半素数の約数を検索することは間違っています。 

n = 6 などの半素数の場合、アルゴリズムはその素因数の数がちょうど 2 であることを検出し、-1 を返します。 適切な約数を選択すると素数が得られ、これが David の勝ちの位置となります。 

n = 30 などのより大きな合成数の場合、半素数の約数は 6、10、15 になります。前処理フェーズでは最大の 15 が保存されます。15 は次のプレイヤーの負けとなるため、Chino は最大の有効な手を選択することで強制的に勝利させることができます。
