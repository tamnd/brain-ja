 ## 解決策
 ## 問題の理解

 固定指数の場合`k`、 定義する`sigma_k(i)`の合計として`k`すべての約数の - 乗`i`。 このタスクは、この関数の 1 つの値を要求するのではなく、2 つの大きなプレフィックスの合計の XOR を要求します。 各テスト ケースに対して、2 つの小さな指数が与えられます。`a`そして`b`、および制限`n`。 次の合計を計算する必要があります`sigma_a(i)`あらゆる人にとって`i`から`1`に`n`、同じことを行います`sigma_b(i)`, 2 つの結果を XOR し、下位 64 ビットのみを保持します。 

指数は以下に制限されます`0, 1, 2, 3`、 しかし`n`到達できる`10^12`。 までのすべての数値を直接シミュレーション`n`最悪の場合、1 兆回の反復が必要になりますが、これは 2 秒の制限をはるかに超えています。 たとえ`O(n log n)`除数列挙メソッドには大まかに必要なものがあります`10^13`したがって、解決策は除数の和の数学的構造を利用する必要があります。 

主なエッジケースのサイズは次のとおりです。`n`そして必要な 64 ビット動作から。 たとえば、次のようなとき`n=1`、`a=0`、 そして`b=1`、考慮される唯一の数値は`1`。 両方の約数の合計は、`1`したがって、XOR は次のようになります。`0`。```
Input:
1
0 1 1

Output:
0
```からループを開始するソリューション`d=0`約数は次から始まるため失敗します。`1`。 

もう 1 つの簡単な間違いは、答えがモジュロであることを忘れることです`2^64`。 たとえば、除数の合計の接頭辞の合計は、大規模な場合は通常の符号付き 64 ビット整数の範囲を超える可能性があります。`n`したがって、任意の精度で言語実装を使用するには、マスクを明示的に適用する必要があります。 

のために`n=4`、`a=0`、 そして`b=1`、2 つのプレフィックスの合計は次のとおりです。```
sigma_0: 1, 2, 2, 3 -> total 8
sigma_1: 1, 3, 4, 7 -> total 15
```正しい答えは次のとおりです。```
8 XOR 15 = 7
```XOR と加算を混同する不注意な実装では、次のような出力が出力されます。`23`。 

## アプローチ

 単純なアプローチは定義に直接従うものです。 すべての整数に対して`i`から`1`に`n`、その約数を列挙し、計算することができます。`sigma_a(i)`そして`sigma_b(i)`を追加してください。 これは文字通り数学的定義を評価するため、正しいです。 

問題はスケールです。 最大のテスト ケースには次のものが含まれます。`n=10^12`したがって、のすべての値に触れても、`i`不可能です。 除数ベースの列挙では、各数値を因数分解するか、除数をスキャンする必要があるため、さらに遅くなります。 

重要な点は、合計の順序を交換できることです。 各数値にどの約数が属するかを尋ねる代わりに、特定の約数を含む数値がいくつあるかを尋ねます。 除数`d`貢献する`d^k`の倍数ごとに`d`、そしてまさにあります`floor(n/d)`そのような倍数。 したがって：$$\sum_{i=1}^{n}\sigma_k(i)=\sum_{d=1}^{n} d^k\left\lfloor\frac nd\right\rfloor$$残りの課題は、合計がまだ残っているように見えることです。`n`条項。 重要な特性は、`floor(n/d)`長距離にわたって一定を保ちます。 もし`floor(n/l)=q`、その後は毎回`d`で終わる特定の間隔で`r=floor(n/q)`同じ商を持つ`q`。 

これにより、個々の約数の代わりに範囲を処理できるようになります。 くらいしかありません`2*sqrt(n)`その範囲は約 200 万です`n=10^12`。 各範囲について、次の合計が必要です。`d^k`2つの境界の間。 以来`k`せいぜい`3`、閉形式の接頭辞式で十分です。 

ブルート フォースは、各除数の寄与を正確にカウントするため機能しますが、実行する小さな操作が多すぎるために失敗します。 商のグループ化観測では、多くの同一の項が 1 つの計算に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) 以上 | お(1) | 遅すぎる |
 | 商のグループ化 | O(sqrt(n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要な指数ごとに`k`の値を計算します。$$F_k(n)=\sum_{d=1}^{n}d^k\left\lfloor\frac nd\right\rfloor$$すべての約数を反復する代わりに、商の範囲を使用します。 

1. 範囲を開始します`l=1`。 商は`q=n//l`。 この商が変化しない最後の位置は、`r=n//q`。 

インターバル全体`[l,r]`貢献します:$$q \times \sum_{d=l}^{r}d^k$$なぜなら、この区間内のすべての約数は同じ乗数を持つからです。 

1. プレフィックス式から区間の累乗和を取得します。 必要な式は次のとおりです。$$\sum d = \frac{x(x+1)}2$$

$$\sum d^2=\frac{x(x+1)(2x+1)}6$$

$$\sum d^3=\left(\frac{x(x+1)}2\right)^2$$の`k=0`case は単に区間内の数値のカウントです。 

1. 寄与分を答えのモジュロに追加します`2^64`、から続けます`r+1`。 
2. 必要な 2 つのプレフィックスの合計を計算し、XOR して、結果の 64 ビット値を出力します。 

正確さは、除数の寄与の変換から得られます。 すべてのペア`(i,d)`どこ`d`分割する`i`元の定義では 1 回だけカウントされます。 順序を入れ替えた後、除数を処理するときに同じペアがカウントされます`d`、有効な倍数の数を乗算します。 商のグループ化では、隣接する除数と同じ乗数を組み合わせるだけなので、計算の順序は変更されますが、値は変更されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1 << 64

def prefix_power(x, k):
    if k == 0:
        return x & (MOD - 1)
    if k == 1:
        return (x * (x + 1) // 2) & (MOD - 1)
    if k == 2:
        return (x * (x + 1) * (2 * x + 1) // 6) & (MOD - 1)
    t = x * (x + 1) // 2
    return (t * t) & (MOD - 1)

def calc(n, k):
    ans = 0
    l = 1

    while l <= n:
        q = n // l
        r = n // q

        segment = (prefix_power(r, k) - prefix_power(l - 1, k)) & (MOD - 1)
        ans = (ans + q * segment) & (MOD - 1)

        l = r + 1

    return ans

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    t = int(data[0])
    idx = 1
    cache = {}
    out = []

    for _ in range(t):
        a = int(data[idx])
        b = int(data[idx + 1])
        n = int(data[idx + 2])
        idx += 3

        if n not in cache:
            cache[n] = [calc(n, k) for k in range(4)]

        out.append(str((cache[n][a] ^ cache[n][b]) & (MOD - 1)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`prefix_power`関数は、アルゴリズムに必要な 4 つの閉じた形式を実装します。 数式には分数が含まれており、あまりにも早くモジュロを適用すると整数の結果が破壊されるため、除算はモジュロ演算の前に行われます。 

の`calc`関数は商のグループ化を実行します。 変数`l`そして`r`現在の除数の間隔を記述します。 直接移動する`r+1`すべての約数を個別に処理することを避けます。 

キャッシュには、特定の値に対して考えられる 4 つの指数結果がすべて保存されます。`n`。 複数のテスト ケースが同じ制限を共有する可能性があるため、これにより同じことを繰り返すことが回避されます。`O(sqrt(n))`計算。 

ビットマスク`MOD - 1`大規模な操作が行われるたびに、最下位の 64 ビットのみが保持されます。 Python の整数は自然にオーバーフローしないため、この明示的なマスキングにより必要なモジュロが再現されます。`2^64`。

## テストケース```python
import sys
import io

MOD = 1 << 64

def prefix_power(x, k):
    if k == 0:
        return x & (MOD - 1)
    if k == 1:
        return (x * (x + 1) // 2) & (MOD - 1)
    if k == 2:
        return (x * (x + 1) * (2 * x + 1) // 6) & (MOD - 1)
    s = x * (x + 1) // 2
    return (s * s) & (MOD - 1)

def calc(n, k):
    ans = 0
    l = 1
    while l <= n:
        q = n // l
        r = n // q
        ans = (ans + q * ((prefix_power(r, k) - prefix_power(l - 1, k)) & (MOD - 1))) & (MOD - 1)
        l = r + 1
    return ans

def run(inp):
    data = inp.split()
    t = int(data[0])
    p = 1
    out = []
    for _ in range(t):
        a, b, n = map(int, data[p:p+3])
        p += 3
        x = calc(n, a)
        y = calc(n, b)
        out.append(str((x ^ y) & (MOD - 1)))
    return "\n".join(out)

assert run("1\n0 0 1\n") == "0"

assert run("1\n1 1 10\n") == "0"

assert run("1\n0 1 1\n") == "0"

assert run("1\n2 3 1000000000000\n") == run("1\n2 3 1000000000000\n")

 ## 特殊なケース

 のために`n=1`、商のグループ化には区間が 1 つだけあります。 アルゴリズムは次から始まります`l=1`、計算します`q=1`、単一の約数を処理します。 除数 0 にアクセスする試みはないため、最小の場合は自然に処理されます。 

次のような等しい指数の場合:```
Input:
1
2 2 100
```どちらの計算でも同じ指数が使用され、同じプレフィックス合計が生成されます。 最後の XOR 演算ではゼロが生成されます。 XOR にはすでにこのプロパティがあるため、実装では特別な分岐を行わずにこれを処理します。 

次のような非常に大きな値の場合:```
Input:
1
3 2 1000000000000
```中間演算が通常の符号付き 64 ビット範囲を超えています。 このアルゴリズムは演算後にマスクを行い、言語のオーバーフロー動作に依存するのではなく、必要な下位 64 ビットを正確に保持します。 

以下の場合については、`n`商の境界に近い場合、次のようになります。`n=10`、間隔の計算`r=n//q`正確でなければなりません。 実装が使用されている場合`r=l`または不適切に増分すると、除数がスキップされたり二重にカウントされたりする可能性があります。 ここで使用されるグループ化公式は常に次から進みます。`l`に`r+1`したがって、すべての約数は正確に 1 つの区間に現れます。
