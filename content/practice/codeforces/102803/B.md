 ## 解決策
 ## 問題の理解

 私たちは以下のコレクションを持っています`n`請求書。 それらの値は直接指定されませんが、提供された xorshift128+ ジェネレーターを使用して 2 つのランダム シードから生成されます。 生成される値はそれぞれ異なります。 このプロセス中に、一部の請求書は未払いですが、一部の請求書はすでに支払われています。 

コマンドは、現在の未払いセットを変更または検査します。 クエリ`F x`少なくとも次の値を持つ最小の未払い請求書を要求します`x`。 コマンド`D x`支払われているため、同じ請求書を未払いセットから削除します。 クエリ`C x`すべての未払い請求額の合計額を超えないように要求します。`x`。 コマンド`R x`支払われたすべての請求書を最大の価値で復元します`x`、それらの請求書が再び未払いになります。 

生成される値はほぼ最大です`10^12`, そのため、実際の値は 64 ビット整数として処理する必要があります。 請求書の数は 100 万に達する可能性があり、コマンドの総数は、一般的なクエリごとのリニア ソリューションが処理できるよりもはるかに多くなります。 コマンドごとにすべての請求書をスキャンするソリューションは、約`10^12`最悪の場合、利用可能な時間を大幅に超えて操作が行われる可能性があります。 コマンドごとに対数処理が必要です。 

難しいのは返金業務です。 一度に多くの紙幣を有効にすることができますが、それが行われるのは最大 10 回です。 データ構造は、個別の削除と大規模なプレフィックス復元の両方をサポートする必要があります。 

不用意に実装すると、さまざまな点で失敗する可能性があります。 コマンドの場合`F`すべての未払い請求よりも大きな値を要求するため、既存の最大値を返すのは間違っています。 例えば、請求書に関しては、`{5, 9}`、コマンド`F 10`出力しなければなりません`10^12`有効な請求書が存在しないため、必要なセンチネル値。 

もう 1 つの間違いは、支払済みの請求書と存在しない請求書を混同することです。 請求書が次のようになっているとします。`{3, 7, 11}`。 後`D 7`、クエリ`C 10`戻らなければなりません`3`、 ない`10`, 支払われた請求書は未払いの徴収金の一部ではないためです。 

払い戻しの境界線も誤って扱いやすくなります。 お札あり`{4, 8, 12}`、コマンド`R 8`両方を復元する必要があります`4`そして`8`。 包括的な比較ではなく厳密な比較を使用すると、誤って結果が返されてしまいます。`8`支払った。 

## アプローチ

 直接的な解決策は、すべての請求書をリストに保存し、コマンドが到着するたびにそれをスキャンすることです。 のために`F`そして`D`、すべての未払い請求書を検索し、最適な候補を保持します。 のために`C`, 条件を満たすすべての未払い請求を合計します。 すべてのコマンドは現在の未払い請求のセットに対して定義されているため、これは正しいです。 

問題は仕事量です。 100 万件の請求書と数十万のコマンドを使用すると、最悪の場合の一連のクエリには約`5 * 10^11`小切手。 この方法は十分な速度には達していません。 

重要な観察は、紙幣の価値が決して変わらないということです。 彼らの状態だけが変化します。 値を並べ替えた後、すべての操作は、この並べ替えられた配列内の位置に関する質問になります。 セグメント ツリーには、位置の間隔に関する情報を保存できます。 各ノードは、間隔内の現在未払いの請求書の数とその値の合計を保持します。 

返金操作は多くの請求書に影響を与える可能性があるためコストがかかるように見えますが、ソートされた配列のプレフィックスは常に同じ状態に変更され、すべての請求書が未払いになります。 これは、セグメント ツリーの遅延割り当てで十分であることを意味します。 セグメント全体が払い戻しの対象となる場合は、その子を訪問せずに、そのセグメントを完全にアクティブとしてマークできます。 

同じツリーは、下限の後の最初のアクティブなポジションを見つけ、1 つのポジションを非アクティブに設定して 1 つの紙幣を削除し、プレフィックスの合計を答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nQ) | O(n) | 遅すぎる |
 | セグメントツリー | O((n + Q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての請求額を生成し、並べ替えます。 ソート順により、値の比較がインデックス範囲になります。 
2. ソートされた位置にセグメント ツリーを構築します。 すべてのポジションは未払いとして開始されるため、すべてのノードは最初にそのセグメント内の請求額の数とそのセグメント内のすべての値の合計を保存します。 
3. のために`F x`、少なくとも次の値を持つ最初のソート位置を見つけます。`x`。 次に、その位置以降のセグメント ツリーを検索して、未払いの請求書を含む最初のセグメントを探します。 そのような位置が存在しない場合は、印刷します`10^12`。 
4. のために`D x`と同じ検索を実行します。`F x`。 ポジションが見つかった場合は、その単一のポジションを更新して、そのアクティブなカウントと寄与がゼロになるようにします。 
5. のために`C x`、値が最大で最後にソートされた位置を見つけます。`x`。 その位置までのセグメント ツリー プレフィックスをクエリし、保存されている合計を返します。 
6. のために`R x`、値が最大で最後にソートされた位置を見つけます。`x`。 そのプレフィックスに遅延割り当てを適用し、対象となるすべてのポジションを無給に設定します。 

不変条件は、セグメント ツリーが常に現在の未払い請求を正確に表すということです。 ポイントを削除すると、アクティブなポジションが 1 つだけ削除されます。 プレフィックス復元により、要求された値の範囲内のすべての位置がアクティブになります。 すべてのクエリはこの維持された表現からのみ読み取るため、返される値は必要な未払いセットと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        size = 4 * self.n
        self.cnt = [0] * size
        self.s = [0] * size
        self.lazy = [False] * size
        self.build(1, 0, self.n - 1)

    def build(self, p, l, r):
        if l == r:
            self.cnt[p] = 1
            self.s[p] = self.arr[l]
        else:
            m = (l + r) // 2
            self.build(p * 2, l, m)
            self.build(p * 2 + 1, m + 1, r)
            self.pull(p)

    def pull(self, p):
        self.cnt[p] = self.cnt[p * 2] + self.cnt[p * 2 + 1]
        self.s[p] = self.s[p * 2] + self.s[p * 2 + 1]

    def apply(self, p, l, r):
        self.cnt[p] = r - l + 1
        self.s[p] = sum(self.arr[l:r + 1])
        self.lazy[p] = True

    def push(self, p, l, r):
        if self.lazy[p] and l != r:
            m = (l + r) // 2
            self.apply(p * 2, l, m)
            self.apply(p * 2 + 1, m + 1, r)
            self.lazy[p] = False

    def update_all(self, p, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.apply(p, l, r)
            return
        self.push(p, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.update_all(p * 2, l, m, ql, qr)
        if qr > m:
            self.update_all(p * 2 + 1, m + 1, r, ql, qr)
        self.pull(p)

    def remove(self, p, l, r, idx):
        if l == r:
            self.cnt[p] = 0
            self.s[p] = 0
            return
        self.push(p, l, r)
        m = (l + r) // 2
        if idx <= m:
            self.remove(p * 2, l, m, idx)
        else:
            self.remove(p * 2 + 1, m + 1, r, idx)
        self.pull(p)

    def first(self, p, l, r, ql):
        if r < ql or self.cnt[p] == 0:
            return -1
        if l == r:
            return l
        self.push(p, l, r)
        m = (l + r) // 2
        res = self.first(p * 2, l, m, ql)
        if res != -1:
            return res
        return self.first(p * 2 + 1, m + 1, r, ql)

    def query(self, p, l, r, qr):
        if r <= qr:
            return self.s[p]
        self.push(p, l, r)
        m = (l + r) // 2
        ans = 0
        if qr > m:
            ans += self.query(p * 2 + 1, m + 1, r, qr)
        if qr >= l:
            ans += self.query(p * 2, l, m, qr)
        return ans

def solve():
    import bisect

    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    t = int(next(it))
    out = []

    for _ in range(t):
        n = int(next(it))
        k1 = int(next(it))
        k2 = int(next(it))

        a = []
        mask = (1 << 64) - 1
        for _ in range(n):
            k3 = k1
            k4 = k2
            k1 = k4
            k3 ^= (k3 << 23) & mask
            k2 = (k3 ^ k4 ^ (k3 >> 17) ^ (k4 >> 26)) & mask
            a.append((k2 + k4) % 999999999999 + 1)

        a.sort()
        seg = SegTree(a)

        q = int(next(it))
        for _ in range(q):
            op = next(it).decode()
            x = int(next(it))

            if op == 'F' or op == 'D':
                pos = bisect.bisect_left(a, x)
                idx = seg.first(1, 0, n - 1, pos)
                if op == 'F':
                    out.append(str(10**12 if idx == -1 else a[idx]))
                elif idx != -1:
                    seg.remove(1, 0, n - 1, idx)

            elif op == 'C':
                pos = bisect.bisect_right(a, x) - 1
                out.append("0" if pos < 0 else str(seg.query(1, 0, n - 1, pos)))

            else:
                pos = bisect.bisect_right(a, x) - 1
                if pos >= 0:
                    seg.update_all(1, 0, n - 1, 0, pos)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```ジェネレーターは、符号なし 64 ビット演算を使用して再現されます。 Python の整数は自然にオーバーフローしないため、次のようにマスクします。`(1 << 64) - 1`C++ unsigned Long Long と同じ動作を維持します。 

セグメント ツリーには、未払いの請求書の数と合計のみが保存されます。 遅延フラグは、セグメント全体が復元されたことを意味します。 この実装では、保存された集計値に基づいて将来の操作が正しく機能するため、そのセグメントがすぐに拡張されることは回避されます。 

の`first`機能が核心となる`F`そして`D`。 配列はソートされており、左端の有効な位置が必要であるため、未払いの請求書を含まないすべてのセグメントは無視され、右の前に左が再帰的に検索されます。 

二分検索では、`bisect_left`「少なくとも x 」については、`bisect_right - 1`「最大でも x」の場合。 これら 2 つの境界が混在していると、この問題で誤答が発生する一般的な原因になります。

 ## 特殊なケース

 未払いの請求書がない場合`F x`、ツリー検索はアクティブ カウントがゼロのセグメントに到達し、返されます。`-1`。 例えば、支払い後`{5, 8}`、検索中`F 1`未払いのポジションが残っていないため、それでも失敗するはずです。 

返金された範囲にすでに未払いの請求書が含まれている場合、プレフィックスを再度アクティブに割り当てても問題はありません。 セグメント ツリーにはカウント操作ではなく最終状態が保存されるため、すでにアクティブな請求書を復元しても二重にカウントされることはありません。 

正確な境界の払い戻しを行うには、以下を使用します。`bisect_right`以下の請求書が含まれます`x`。 価値観あり`{4, 8, 12}`、支払い後`8`、`R 8`ポジションを更新します`4`そして`8`から合計を導き出します`16`に戻る`24`。 

ソートされたインデックス表現は、これらすべてのケースを連携して機能させるものです。 ツリーは、その位置と値を超えて紙幣の実際の意味を知る必要がないため、すべてのコマンドは、現在アクティブなプレフィックスまたはサフィックスに対する制御された更新またはクエリになります。
