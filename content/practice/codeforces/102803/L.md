 ## 解決策
 ## 問題の理解

 グリッドには、次から始まる幅優先検索によって番号が付けられます。`(0, 0)`。 唯一の珍しい部分は、BFS 内の番号付けの順序が固定されていることです。セルを展開するとき、新しいセルは上、右、下、左の順序で考慮されます。 各クエリは、数値を与えて現在位置からの変位を尋ねるか、座標を与えてその BFS 番号を尋ねます。 各クエリの後、現在位置がクエリされたポイントになります。 

座標は非常に遠くてもよく、最大でマンハッタンの距離までです。`10^8`なので、BFS をシミュレートすることは不可能です。 BFS の単一層には次のものが含まれます。`4d`離れたところにある細胞`d`、生成する必要があるレイヤーの数が多すぎます。 座標と数値の間を直接ジャンプする数式が必要です。 

一般的なパターンには短いレイヤーの例外があるため、主なエッジ ケースは原点と最初の数レイヤーです。 たとえば、最初の層は次のようになります。```
0 1
2 0
0 -1
-1 0
```それで座標は`(1,0)`番号があります`2`、後の層の式に従った値ではありません。 レイヤー 2 の終了順序も少し異なります。```
(0,2), (1,1), (-1,1), (2,0), (1,-1), (0,-2), (-1,-1), (-2,0)
```このようなケースに大層パターンを盲目的に適用するソリューションでは、誤った答えが生成されます。 

## アプローチ

 直接的なアプローチでは、BFS キューを構築し、訪問されたすべての座標を保存します。 番号付けは正確に BFS 順序であるため、これは正しいですが、マンハッタン距離内のセルの数は異なります。`10^8`についてです`2 * 10^16`, したがって、このアプローチは完成に近づくことさえできません。 

有益な観察は、BFS が異なるマンハッタン距離を決して混合しないことです。 レイヤー内のすべてのポイント`d`より小さい層内のすべての点の後で発見されます`d`、およびレイヤーの前に完成したセルの数`d`は：```
1 + 2(d - 1)d
```残りの作業は、1 つのレイヤー内の固定された順序を理解することだけです。 その順序を数式として書くと、両方向は定数時間になります。 大きなレイヤーの最初の部分は上半分で、正の x 値と負の x 値が交互に切り替わります。 下半分には、直接インデックスを付けることもできる別の固定シーケンスがあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(距離²) | O(距離²) | 遅すぎる |
 | 数式ベースのマッピング | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マンハッタン層を見つける`d`ID を含む座標またはレイヤーの。 レイヤー境界は最初の値です。`1 + 2d(d + 1)`IDに到達します。 
2. 座標から ID への変換では、レイヤーの開始 ID を計算します。 次に、位置式を使用してレイヤー内のオフセットを決定します。 
3. ID から座標への変換では、レイヤー内の最初の ID からのオフセットを計算し、同じ式を逆に計算します。 
4.キープ`(0,0)`これはレイヤー 0 の唯一のポイントであるため、特殊なケースとして扱われます。 

なぜ効果があるのか:

 すべての BFS 番号は、正確に 1 つのマンハッタン層に属します。 累積カウントは各レイヤーの正確な開始点を示します。前のレイヤーのすべての親は固定順序で処理されるため、レイヤー内の検出順序は決定的です。 式はその決定論的な順序を完全に記述しているため、どちらの方向に変換しても間違った位置を選択することはできません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def layer_of_id(n):
    if n == 0:
        return 0
    z = math.isqrt(4 * n - 3)
    if z * z < 4 * n - 3:
        z += 1
    return (z - 1 + 1) // 2 if (z - 1) % 2 == 0 else (z + 1) // 2

def id_to_coord(n):
    if n == 0:
        return (0, 0)

    d = layer_of_id(n)
    start = 1 + 2 * (d - 1) * d
    k = n - start

    if d == 1:
        return [(0, 1), (1, 0), (0, -1), (-1, 0)][k]

    if d == 2:
        arr = [(0, 2), (1, 1), (-1, 1), (2, 0),
               (1, -1), (0, -2), (-1, -1), (-2, 0)]
        return arr[k]

    if k < 2 * d - 1:
        if k == 0:
            return (0, d)
        a = (k + 1) // 2
        return (a if k & 1 else -a, d - a)

    r = k - (2 * d - 1)
    if r == 0:
        return (d - 1, -1)
    if r == 1:
        return (d - 2, -2)
    if r == 2:
        return (d, 0)
    if r <= d:
        return (d - r, -r)

    s = r - d - 1
    return (-(s + 1), -(d - 1 - s))

def coord_to_id(x, y):
    d = abs(x) + abs(y)
    if d == 0:
        return 0

    if d == 1:
        return {(0, 1): 1, (1, 0): 2, (0, -1): 3, (-1, 0): 4}[(x, y)]

    start = 1 + 2 * (d - 1) * d

    if d == 2:
        arr = [(0, 2), (1, 1), (-1, 1), (2, 0),
               (1, -1), (0, -2), (-1, -1), (-2, 0)]
        return start + arr.index((x, y))

    if y > 0:
        if x == 0:
            k = 0
        else:
            a = d - y
            k = 2 * a - 1 if x > 0 else 2 * a
        return start + k

    if x > 0 and y == 0:
        r = 2
    elif x >= 0:
        a = -y
        r = 0 if a == 1 else a
    else:
        s = -x - 1
        r = d + 1 + s

    return start + (2 * d - 1) + r

def solve():
    t = int(input())
    curx = cury = 0
    ans = []

    for _ in range(t):
        q = list(map(int, input().split()))
        if q[0] == 1:
            x, y = id_to_coord(q[1])
            ans.append(f"{x - curx} {y - cury}")
        else:
            x, y = q[1], q[2]
            ans.append(str(coord_to_id(x, y)))
        curx, cury = (id_to_coord(q[1]) if q[0] == 1 else (q[1], q[2]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```同じ層の演算が両方向で再利用されるため、コードは 2 つの変換を分離します。 小さなレイヤーは明示的に処理され、脆弱な境界条件が回避されます。 より大きなレイヤーの場合、最初の`2d-1`位置はリングの上部であり、残りの位置はリング下部の式に従います。 

レイヤーの計算では、浮動小数点演算の代わりに整数の平方根が使用されます。 ID が非常に大きくなる可能性があるため、これにより精度の問題が回避されます。 現在の位置は、ステートメントの操作順序と一致する答えを生成した後にのみ更新されます。 

## 実用的な例

 クエリシーケンスの場合:```

1 14
```状態は次のように発展します。 

| クエリ | クエリ前の現在 | 操作 | 結果 | 新しい現在 |
 | --- | --- | --- | --- | --- |
 |`2 3 3`|`(0,0)`| 変換する`(3,3)`|`?`|`(3,3)`|
 |`1 14`|`(3,3)`| IDを変換する`14`| からの変位`(3,3)`| ID 位置 |

 トレースは、番号付け変換と変位計算が別個の操作であることを示しています。 最初に BFS 番号が変換され、次に現在位置が更新されます。 

境界ケース:```
4
1 0
1 1
2 0 -1
1 3
```| クエリ | クエリ前の現在 | 操作 | 結果 |
 | --- | --- | --- | --- |
 |`1 0`|`(0,0)`| 原点検索 |`0 0`|

 ## 特殊なケース

 原点には、次のように入力します。`1 0`ディスプレイスメントを返さなければなりません`0 0`現在の点が原点でもある場合。 原点は正の距離のリングに属していないため、アルゴリズムはレイヤーを計算する前にこれを処理します。 

1層目はコーディネート`(1,0)`IDがある`2`、 その間`(0,-1)`IDがある`3`。 最初のリングには、後で使用する繰り返しパターンを形成するのに十分な点が含まれていないため、一般的なリングの式ではこれらが誤って配置されます。 明示的なレイヤー 1 マッピングにより、これが防止されます。 

レイヤー 2 の場合、`(2,0)`IDがある`8`、 そして`(1,-1)`IDがある`9`。 これにより、下半分が常に大きな層と同じパターンで始まると想定する実装が捕捉されます。 

次のような非常に大きな座標の場合、`(100000000,0)`、アルゴリズムはレイヤーとオフセットのみを計算します。 距離に比例してメモリが割り当てられることはないため、実行時間は一定のままです。
