 ## 解決策
 ## 問題の理解

 ラベルが貼られた根が張った木を数えています。 ノード`i`ルートからの必要な深さと、ツリーの幅優先検索順序で出現が許可される最新の位置という 2 つの情報が付属します。 

幅優先順序付けは、単に同じ深さを持つノードの順序付けではありません。 ノードはレベルごとに処理され、ノードの子は連続したブロックとして表示されます。 あるノードが別のノードの前に出現する場合、その親は同じ順序付けルールに従う必要があります。 これはまさに、すべてのノードの子の順序を選択することによって生成される通常の BFS 順序です。 

入力では、すべてのラベルの制限についてのみ説明します。 出力は、BFS 順序付けがすべての制限を満たすさまざまなツリーの数 (法) です。`10^9 + 7`。 

と`n`到達`100000`1 回のテストで合計サイズが以下に達する`510000`、ツリーの構築、BFS オーダーの列挙、またはノードのペアに対する動的プログラミングの使用を試みるソリューションは、非常に遅すぎます。 線形または`O(n log n)`。 要素の総数は数十万にすぎないため、ノードの制限をソートすることは許容されます。 

不注意な実装により、何も通知されずに失敗する可能性があるケースがいくつかあります。 深さにノードがない場合`1`、可能なルートはありません。 例えば：```
2
2 2
2 2
```正しい答えは、`0`。 すべてのツリーにはルートが 1 つだけ存在する必要があるため、より深いレベルの相対的な順序のみをチェックするソリューションでは、誤って無効なツリーがカウントされる可能性があります。 

深度ブロックが開始される前にノードが特定の位置に強制的に配置される場合、答えはゼロでなければなりません。 例えば：```
2
1 1
2 1
```2 番目のノードには深さが必要です`2`ただし、BFS が取得できる唯一の位置はルート位置です。 正しい答えは、`0`。 

もう 1 つのよくある間違いは、ノードの子が BFS 順序で連続したブロックを形成していることを忘れていることです。 親の選択はノードごとに独立しているわけではありません。 例えば：```
3
1 1
2 3
2 3
```答えは`2`。 2 つの深さ 2 のノードは 2 つの方法で順序付けできますが、両方とも唯一のルートの子である必要があります。 各子供を親の独立した選択として扱うと、過大評価になります。 

## アプローチ

 直接的なアプローチでは、まず、深さの制約を満たすラベルの可能なすべての BFS 順序を生成します。 このような順序を選択した後、各レベルを子ブロックに分割し、ツリーを取得する方法を決定できます。 これは正しいです。BFS ツリーは、各深さレベル内のノードの順序と、各レベルが前のレベルの親間で分割される方法によって完全に記述されるからです。 

問題は、可能な BFS 注文の数です。 多くのノードを含む深さレベルが 1 つだけの場合でも、順列の数は階乗になります。 のために`100000`ノードを列挙するには、以上のものが必要になります。`100000!`操作、それは不可能です。 

重要な観察は、ツリー構造と BFS 順列を分離できることです。 親関係を構築する方法の数は、各深度に存在するノードの数にのみ依存し、どのラベルがそれらの位置を占めるかには依存しません。 

固定レベルの場合、`a`現在の深さのノードと`b`次の深さのノード。 の`b`次の BFS 層の子は次のように分割する必要があります。`a`連続したグループ。現在のノードごとに 1 つのグループ。 ノードには子がない可能性があるため、空のグループが許可されます。 このような分割の数は、弱い合成の数です。`b`の中へ`a`部品：$$\binom{a+b-1}{a-1}$$残りのタスクは、BFS 位置へのラベルの有効な割り当てをカウントすることです。 同じ深さのノードは、位置の 1 つの連続した間隔を占めます。 許容位置がソートされている場合は、最小の許容位置ノードが最初に割り当てられる必要があります。 とき`j`このソート順で - 番目のノードが処理され、次のものが含まれます。$$\min(x_i, R)-L+1-(j-1)$$利用可能なポジション、ここで`[L, R]`深さの間隔です。 これらの選択肢を乗算すると、そのレベルの有効な順列の数が求められます。 

2 つの独立した部分が掛け合わされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各深さに存在するノードの数を数えます。 深さの場合`1`ノードが 1 つだけ含まれていない場合、ツリーは存在できません。 また、ルート以外のすべてのノードには親が必要であるため、以前のレベルがすべて存在せずに、より深いレベルが存在するギャップも拒否します。 
2. 深さごとに、`x_i`その深さのノードの値を取得して並べ替えます。 1 つの深さのノードは、その深さに属する連続した BFS 位置のみを占有することができるため、各深さを独立して処理できます。 
3. 位置間隔のある深さの場合`[L, R]`、並べ替えられた制限を最小値から最大値まで処理します。 現在のノードは次の間のどこかに配置する必要があります。`L`そして`min(R, x_i)`。 以前のノードに既に割り当てられている位置を減算します。 選択肢の数がゼロまたは負になる場合、有効な BFS 順序は存在しません。 
4. 階乗および逆階乗を事前計算します。 連続する深さのペアごとに、可能な子ブロック分割の数を乗算します。$$\binom{cnt[d]+cnt[d+1]-1}{cnt[d]-1}$$これにより、BFS 順序と互換性のあるすべての可能なツリー形状が考慮されます。 

1. BFS 順序数とツリー形状数のモジュロを乗算します。`10^9+7`。 

これが機能する理由: すべての有効なツリーが 1 つの BFS 順序付けを正確に生成します。 この順序では、深さのすべてのノードが固定間隔を占めるため、ラベルを割り当てるときに各レベルを独立して表示できます。 ラベルが BFS 順序で固定されると、残る自由は、各レベルが前のレベルの親間でどのように分割されるかだけです。 星と棒の式では、これらのパーティションが正確にカウントされます。 これら 2 つの選択肢は独立しているため、これらを乗算すると、すべての有効なツリーが 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve_case(n, nodes):
    depths = {}
    xs = {}
    max_depth = 0

    for d, x in nodes:
        depths[d] = depths.get(d, 0) + 1
        xs.setdefault(d, []).append(x)
        max_depth = max(max_depth, d)

    if depths.get(1, 0) != 1:
        return 0

    for d in range(1, max_depth + 1):
        if d not in depths:
            return 0

    cnt = [0] * (max_depth + 2)
    for d, c in depths.items():
        cnt[d] = c

    fact = [1] * (n + 2)
    for i in range(1, n + 2):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 2)
    invfact[-1] = pow(fact[-1], MOD - 2, MOD)
    for i in range(n + 1, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    ans = 1
    start = 1
    for d in range(1, max_depth + 1):
        arr = xs[d]
        arr.sort()
        end = start + len(arr) - 1
        used = 0
        for x in arr:
            choices = min(end, x) - start + 1 - used
            if choices <= 0:
                return 0
            ans = ans * choices % MOD
            used += 1
        start = end + 1

    for d in range(1, max_depth):
        ans = ans * comb(cnt[d] + cnt[d + 1] - 1, cnt[d] - 1) % MOD

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        nodes = [tuple(map(int, input().split())) for _ in range(n)]
        out.append(str(solve_case(n, nodes)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装の最初の部分では、深さによってノードをグループ化し、それらの最大許容 BFS 位置を保存します。 深さのカウントは、後で考えられるツリー構造の数を決定するのに十分です。 

最大の二項引数が以下であるため、階乗配列はテスト ケースごとに 1 回構築されます。`n`。 結合関数は、モジュラー逆関数を使用して定数時間になります。 

注文の計算は最もデリケートな部分です。 変数`start`現在の深度の最初の BFS 位置、および`end`最後です。 最も厳しい制限を最初に割り当てると、有効な順列の標準的な貪欲なカウントが得られるため、制限を並べ替える必要があります。 変数`used`間隔内で既に占有されている位置の数を表します。 

2 番目の乗算ループは、隣接する深さの間で考えられる親グループをカウントします。 式では、`cnt[d] - 1`成分が弱いので、`cnt[d+1]`子供たち`cnt[d]`グループは持っています`cnt[d+1] + cnt[d] - 1`スターとバーの変換における合計位置。

 ## 特殊なケース

 ルートのないツリーの場合、深さ 1 にはノードが 1 つだけ含まれている必要があるため、アルゴリズムはすぐに 0 を返します。 入力では:```
2
2 2
2 2
```深度カウンタがそれを検出します`cnt[1]`はゼロであり、組み合わせ計算の前に停止します。 

許可された位置がその深さの範囲外にあるノードの場合、貪欲な配置によって障害が検出されます。 で：```
2
1 1
2 1
```深さ2の間隔は位置のみです`2`ただし、ノードによって許可される唯一の使用可能な位置は、positionです。`1`。 選択肢の数がゼロになり、回答は拒否されます。 

同じレベルに複数のノードがある場合、アルゴリズムが親を独立して選択することはありません。 で：```
