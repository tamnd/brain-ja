 ## 解決策
 ## 問題の理解

 ジングルベルの根が生えた木があります。 各ノードには 2 つの値があります。`a`そして`b`。 ルートはすでに装飾されていますが、その値が両方ともゼロであるため、何も寄与しません。 他のすべてのノードは、その親がすでに追加された後に追加する必要があります。 

ノードの場合`i`を加えて得た美しさは`b_i`次の合計を乗算します`a`この操作後も装飾されていないすべてのノードの値。 目標は、全体の美しさを最大化する、すべてのノードを装飾する有効な順序を選択することです。 

入力は、いくつかの根を持つツリーを記述します。 親配列はツリー構造を定義し、すべてのノードにはその値のペアが含まれます。 ツリー全体を装飾した後の、最大限の総合的な美しさがアウトプットされます。 

すべてのテスト ケースにわたるノードの合計数は最大で`2.1 * 10^5`。 これは、葉の多い木であっても膨大な数の有効な順序を持つ可能性があるため、多くの可能な装飾順序を試すアプローチを除外します。 線形または線形に近いアルゴリズムが必要です。`O(n log n)`ここで、対数は優先キューから取得できます。 

よくある間違いは、大規模なノードのみを考慮することです。`b`価値観。 ノードの価値はどれだけ大きくなるかによって決まります。`a`選択後に残るので、`b`十分ではありません。 もう 1 つの間違いは、ツリー制限を無視してすべてのノードをすぐに並べ替えることです。 ノードをその親の前に選択することはできません。 

たとえば、次のことを考えてみましょう。```
3
1 1
0 0
10 1
1 100
```ルートには 2 つの子があります。 最初に 2 番目の子を選択すると、次の利益が得られます。`100 * 10 = 1000`、最初の子を選択すると、最初に得られるのは`1 * 100`。 答えは`1000`。 ノードの順序または入力の順序のみに基づく戦略は失敗します。`b`そして`a`重要です。 

もう 1 つのエッジ ケースはチェーンです。```
2
1
0 0
5 7
```唯一の有効な順序は、ルート、次にノード 2 です。答えは次のとおりです。`0`最後のベルを配置した後はノードが残っていないためです。 最終ノードの寄与を誤って追加するソリューションでは、間違った答えが生成されます。 

## アプローチ

 直接的な解決策では、考えられるすべての有効な装飾順序を試します。 注文ごとにプロセスをシミュレーションし、美しさを計算することができました。 すべての法的な順序がチェックされるため、これは正しいです。 ただし、可能な注文数は指数関数的に増加します。 ルートの多くの子を持つツリーはすでに階乗的に多くの選択肢を作成しているため、ブルートフォースは不可能です。`n = 100000`。 

重要な観察結果は、使用可能な 2 つのノードを比較することで得られます。 2 つのノードがあるとします`x`そして`y`現在はどちらも選択可能であり、どちらも他方の祖先ではありません。 装飾されていないすべての合計を後で計算しましょう`a`値は`R`。 

私たちが選ぶなら`x`前に`y`、彼らの合計貢献度は次のとおりです。```
b_x * (a_y + R) + b_y * R
```私たちが選ぶなら`y`前に`x`、それは次のとおりです。```
b_y * (a_x + R) + b_x * R
```次の場合には最初の順序が適しています。```
b_x * a_y >= b_y * a_x
```これは以下と同等です:```
b_x / a_x >= b_y / a_y
```したがって、現在利用可能なすべてのノードの中で、常に最大のノードが最適な選択となります。`b / a`比率。 

ツリーの制限により、最初からすべてを並べ替えることはできません。 代わりに、親がすでに装飾されているノードのセットを維持します。 このセットから最適なノードを取得すると、その子が使用可能になります。 これにより、優先キューのソリューションが提供されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(有効な注文数 * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の合計を計算します。`a`すべてのノードの値。 根を処理した後の量を表します。`a`装飾されたセットの外にまだ存在する値。 
2. ルートのすべての子を、降順の優先キューに入れます。`b / a`。 隣接するスワップ引数により、ノードを早く移動しても問題がないことが証明されているため、最大の比率を持つノードが最初に選択される必要があります。 
3. 優先キューから最適なノードを繰り返し削除します。 残りの合計を更新する前に、その美しさの寄与を追加します。```
b_i * (remaining a after choosing i)
```残り`a`ノードが装飾された後は減少するため、減算します`a_i`初め。 

1. 選択したノードのすべての子が到達可能になったので、優先キューに追加します。 
2. すべてのノードが処理されるまで続行します。 

なぜ効果があるのか:

 常に、優先キューには、次に合法的に選択できるノードが正確に含まれています。 交換引数は、最大値を配置することを証明します。`b/a`他の利用可能なノードの前にノードを配置すると、応答を減らすことはできません。 したがって、貪欲な選択があらゆる段階で最適になります。 選択されたすべてのノードが残りのノードに対してこのプロパティを保持するため、生成される順序全体が最適になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve_case():
    n = int(input())
    parent = [0] * n
    if n > 1:
        p = list(map(int, input().split()))
        for i, x in enumerate(p, 1):
            parent[i] = x - 1

    children = [[] for _ in range(n)]
    for i in range(1, n):
        children[parent[i]].append(i)

    a = [0] * n
    b = [0] * n
    total = 0

    for i in range(n):
        a[i], b[i] = map(int, input().split())
        total += a[i]

    ans = 0
    remaining = total

    heap = []

    for v in children[0]:
        heapq.heappush(heap, (-b[v] / a[v], v))

    while heap:
        _, u = heapq.heappop(heap)

        remaining -= a[u]
        ans += b[u] * remaining

        for v in children[u]:
            heapq.heappush(heap, (-b[v] / a[v], v))

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve_case()))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```下方向への移動のみが重要であるため、コードはツリーを子リストとして保存します。 Python のヒープは最小ヒープであるため、優先キューでは負の比率が使用されます。 

式では現在のノードが配置された後に装飾されていないノードが使用されるため、残りの合計は寄与を追加する前に減ります。 ルートはすでに処理されており、キューに挿入されることはありません。`a = b = 0`。 

Python の浮動小数点比較は、値が最大でも次の値であるため、ここでは安全です。`10000`ですが、相互乗算を使用した整数比較器も可能です。 答え自体は 32 ビット整数よりもはるかに大きくなる可能性があるため、Python の任意精度整数はオーバーフローの問題を回避します。

 最初のサンプルのツリーは次のとおりです。```
1

└── 3
```使用可能なノードは次のように処理されます。 

| ステップ | 選択されたノード | 残りの選択肢 | ゲイン | 合計 |

 ノード 2 はノード 3 より前に選択されます。`1/3 > 1/5`。 ノード 2 を選択すると、ノード 4 が使用可能になり、その比率が`1/4`は依然としてノード 3 の比率よりも大きいです。 

2 番目のサンプルでは、​​ノード 3 には非常に大きな`a`値は同じですが`b`他の多くのノードと同じように価値を持ちます。 その比率が小さいため、アルゴリズムはそれを遅らせます。

 | ... | ... | ... | ... |

 プロセスは常に現在到達可能な最良の比率を採用して続行され、必要な最大値を生成します。`16040`。

 ## 特殊なケース

 最初のエッジ ケースは単一ノード ツリーです。 ルートはすでに装飾されており、移動がないため、答えはゼロです。 優先キューは空から開始されるため、アルゴリズムはこれを処理します。 

2 番目のエッジ ケースは、すべてのノードに子が 1 つだけあるチェーンです。 順序に選択の余地はなく、優先キューには常に 1 つのノードが含まれます。 貪欲な方法では、唯一可能な走査が可能になります。 

3 番目のエッジ ケースは、複数の利用可能なノードが等しい場合です。`b/a`比率。 比較式が等しくなるため、それらの間のどの順序でも同じペアごとの結果が得られます。 ヒープは、最終的な答えを変更せずに、それらのいずれかを選択できます。 

最後の重要なケースは、大きなノードを持つノードです。`b`しかし、さらに大きい`a`。 このようなノードは魅力的に見えるかもしれませんが、早期に選択すると将来の大幅なコストが削減されます。`a`価値。 比率比較では、両方の効果を一緒に考慮することで、この間違いを防ぎます。
