 ## 解決策
 ## 問題の理解

 与えられた配列のサブ配列について、各セグメントのビット単位の XOR が等しくなるようにサブ配列を少なくとも 2 つの連続するセグメントに分割できるかどうかを決定するように求められます。 形式的には、部分配列を考慮すると、$a_l, a_{l+1}, \dots, a_r$、整数が存在するかどうかを判断する必要があります。$k > 1$とインデックス$l = i_0 < i_1 < \dots < i_k = r+1$したがって、セグメントごとに$[i_j, i_{j+1}-1]$、要素の XOR は同一です。 

入力には複数のテスト ケースが含まれており、各テスト ケースには配列とサブ配列に対するいくつかのクエリが含まれます。 配列のサイズとクエリの最大数$2 \cdot 10^5$、すべてのテスト ケースの合計も同様に制限されます。 これにより、考えられるすべてのパーティションを列挙するようなアプローチは除外されます。$n$。 各クエリに効率的に答えるアルゴリズムが必要です。理想的には$O(n)$前処理と$O(1)$プレフィックス XOR などの事前計算された構造を使用して、クエリごと、またはそれよりわずかに高くなります。 

すべての要素がゼロの場合、エッジ ケースが発生します。 ここでは、ゼロとゼロの XOR がゼロであるため、自明でない分割は機能します。そのため、すべての部分配列が自動的に対象になります。 もう 1 つの微妙なケースは、部分配列の合計 XOR がゼロではないが、XOR が一致する内部パーティションが存在する場合です。 有効な構成を見逃すことなく、等価 XOR 条件を満たす分割を注意深く検出する必要があります。 

## アプローチ

 ブルートフォース手法では、サブ配列の可能な分割をすべて試し、各セグメントの XOR を計算し、それらが等しいかどうかを確認します。 長さの部分配列の場合$m$、 がある$2^{m-1}-1$少なくとも 2 つの部分に分割する方法。 各分割の XOR を計算すると、別の分割が追加されます$O(m)$、合計時間計算量はおよそ次のようになります。$O(2^m \cdot m)$。 これは不可能です$m$まで$2 \cdot 10^5$。 

重要な観察により、問題が単純化されます。 させて$X$部分配列全体の XOR になります。 配列を分割できる場合$k \ge 2$等しい XOR を持つセグメント$x$の場合、配列全体の XOR は次のようになります。$x$繰り返された$k$回。 XOR は結合的であるため、$x \oplus x = 0$、合計 XOR は次のようにする必要があります。$0$もし$k$偶数か等しい$x$もし$k$奇数です。 より実際的には、プレフィックス XOR をスキャンできます。最初からの累積 XOR が合計 XOR と一致する少なくとも 2 つの位置が見つかった場合、有効なパーティションを形成できます。 これにより、問題はプレフィックス XOR 配列のチェックに減ります。この配列は次のように計算できます。$O(n)$、試合のカウントなども効率的に行うことができます。 

最適なアプローチでは、プレフィックス XOR を使用し、累積 XOR が部分配列の合計 XOR に等しいインデックスを検索します。 少なくとも 2 つのセグメントに分割できるようなインデックスが存在する場合、「はい」と答えます。 それ以外の場合は「いいえ」。 ゼロ部分配列または単一要素セグメントを処理するには、慎重な境界チェックが必要です。

 ## アルゴリズムのチュートリアル

 1. プレフィックス XOR 配列を計算する$px$入力配列の場合、$px[i] = a_1 \oplus a_2 \oplus \dots \oplus a_i$。 これにより、次を使用して任意のサブ配列の定数時間 XOR 計算が可能になります。$px[r] \oplus px[l-1]$。 
2. クエリごとに$(l, r)$、部分配列の合計 XOR を次のように計算します。$total = px[r] \oplus px[l-1]$。 
3. もし$total = 0$、部分配列は常に興味深いものです。 ゼロセグメントの XOR は繰り返すことができるため、常に少なくとも 2 つの空でないセグメントに分割できます。 
4. それ以外の場合は、サブ配列の先頭からの累積 XOR が等しいプレフィックス位置のサブ配列をスキャンします。$total$。 させて$count$そのような位置の数になります。 
5. 少なくとも 1 つの要素によって分離された少なくとも 2 つのそのような位置、または有効な分割を許可する境界にない位置が見つかった場合は、「はい」と答えてください。 それ以外の場合は「いいえ」。 
6. エッジケース: 長さ 2 の部分配列が興味深いものとなるには、等しい要素が必要です。 また、セグメントが空でないことを確認するために細心の注意が必要です。 

機能する理由: 配列の合計 XOR が次の場合、XOR のプロパティによって$X$、任意のパーティションへ$k$等しい XOR セグメントは、各分割が次の倍数になるまでの累積 XOR を満たす必要があります。$X$。 この不変式により、そのようなプレフィックス XOR をカウントすることで、考えられるすべての有効なパーティションが正しく検出されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        px = [0]*(n+1)
        for i in range(n):
            px[i+1] = px[i] ^ a[i]
        
        for _ in range(q):
            l, r = map(int, input().split())
            total = px[r] ^ px[l-1]
            if total == 0:
                print("YES")
                continue
            found = 0
            xor_acc = 0
            for i in range(l-1, r):
                xor_acc ^= a[i]
                if xor_acc == total:
                    found += 1
                    xor_acc = 0
            print("YES" if found >= 2 else "NO")

if __name__ == "__main__":
    solve()
```プレフィックス XOR 配列を使用すると、サブ配列の定数時間合計 XOR 計算が可能になります。 内側のループは XOR を蓄積し、合計と一致するセグメントが見つかるとリセットします。 このようなセグメントを少なくとも 2 つカウントすることで、有効な分割が保証されます。 境界条件は、ループを開始することで処理されます。$l-1$そしてそれを含めて$r$。
