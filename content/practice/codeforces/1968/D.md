 ## 問題の理解

 私たちは順列によって形成された有向構造を与えられています。 それぞれの指標から$x$、発信エッジが 1 つだけあります。$p_x$したがって、システム全体は、おそらく木がそれらに供給される、互いに素な有向サイクルに分解されますが、次の理由によります。$p$は順列であり、すべてのノードは正確に 1 つのサイクル上にあり、そのサイクルの外側に入力ツリー構造はありません。 

各ノードには値も含まれます$a_x$。 2 人のプレイヤーが異なるノードから開始します。 以上$k$ターンごとに、各プレイヤーは現在のノードの値を繰り返し収集し、一度だけ順列エッジに留まるか従うかを選択します。 この決定は戦略的であり、正確に収集した金額の合計を最大化する必要があります。$k$曲がる。 

重要な難点は、$k$と同じ大きさにすることができます$10^9$, そのため、段階的にシミュレーションすることはできません。 代わりに、動きの構造と最適な繰り返しを理解する必要があります。 

出力は単に最終的な達成可能なスコアの比較であり、どの開始位置が最適な合計をより大きくするか、またはそれらが同点かどうかを示します。 

制約は、任意の解が次の値に比例することを意味します。$k$テストケースごとには不可能です。 平$O(nk)$はすぐに除外されます。 テスト ケースごとに、ほぼ線形または線形対数に制限されます。 合計以来$n$すべてのテストにわたって$2 \cdot 10^5$、$O(n)$または$O(n \log n)$試験溶液ごとに許容されます。 

素朴な推論による微妙な失敗例は、プレイヤーが常に順列に沿って移動するか、常に留まると仮定することです。 たとえば、1 つのノードに非常に大きなノードが存在するサイクルを考えてみましょう。$a_x$。 毎回移動する単純な貪欲な人は、高価値のノードに到達した後もそこに留まることが最適であることを見落とす可能性がありますが、単純な「常に移動する」戦略は、より低い値を循環する可能性があります。 

もう 1 つのエッジケースは、ゲームが最初のものだけに依存すると仮定することです。$k$最適な戦略がサイクルに入り、平均ゲインに応じて固定のままにするかサイクルを続けるかを選択する可能性があることを考慮せずに、順列のステップを歩きます。

 ## アルゴリズムのチュートリアル

 プレイヤーは対話しないため、開始位置ごとに達成可能な最高のスコアを個別に計算します。 

1. 開始ノードごとに、最大で順列に沿った移動をシミュレートします。$\min(n, k)$のプレフィックス合計を累積する間のステップ$a_x$。 これにより、反復保証の前に、到達可能なすべての個別の状態が得られます。 
2. 各ステップで$t$、正確に停止した場合のスコアを計算します$t$動く。 これは、その時点までに訪問した値の単純な合計です。 
3. サイクル内にいる場合は、サイクルの合計を計算します。 サイクル合計が正の場合、サイクルに入った後、残りのステップ内でできるだけ多くの完全なサイクルをループすることが最適です。 サイクル合計が負またはゼロの場合、それを繰り返すことを避け、代わりに最適なプレフィックス エントリ ポイントを選択します。 
4. 各位置について、部分的な移動やオプションのサイクル繰り返しを含む、すべての有効な停止決定にわたって可能な最大スコアを追跡します。 
5. Bodya と Sasha のこの値を計算し、比較します。 

中心となる推論は、歩行は決定的であるため、唯一の決定はどこで停止するかであるということです。 繰り返しまでの訪問値のシーケンスがわかれば、すべての戦略は停止時間の選択に対応し、さらに、利益が得られる場合には全サイクルの繰り返しを利用する可能性もあります。 

### なぜ効果があるのか

 順列はサイクルに分解されるため、開始ノードからのすべてのパスは最終的に周期的になります。 最適な戦略は、次のように考えることができます。一定のステップ数だけ前進し、その後、必要に応じてサイクル内に留まり、ループを継続します。 今後の位置はすべて決まっているので、自由なのは停止時間だけです。 これにより、指数関数的な決定プロセスが、可能な停止点にわたる線形スキャンと、サイクル繰り返しの定時間調整に削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n, k, pb, ps, p, a):
    # convert to 0-based
    pb -= 1
    ps -= 1

    def best(start):
        visited = {}
        order = []
        cur = start

        # build path until repetition or k steps
        for i in range(min(n, k)):
            if cur in visited:
                break
            visited[cur] = i
            order.append(cur)
            cur = p[cur]

        # prefix sums over path
        pref = [0] * (len(order) + 1)
        for i in range(len(order)):
            pref[i + 1] = pref[i] + a[order[i]]

        res = 0

        # try stopping within first segment
        for i in range(len(order)):
            steps_used = i
            if steps_used >= k:
                break
            gain = pref[i + 1]
            remaining = k - (i + 1)
            gain += remaining * a[order[i]]
            res = max(res, gain)

        # if cycle exists
        if cur in visited:
            cycle_start = visited[cur]
            cycle = order[cycle_start:]
            cycle_sum = sum(a[x] for x in cycle)

            cycle_len = len(cycle)

            for i in range(len(order)):
                if i < cycle_start:
                    continue
                base = pref[i + 1]
                remaining = k - (i + 1)

                if remaining > 0:
                    full = remaining // cycle_len
                    rem = remaining % cycle_len
                    gain = base + full * cycle_sum
                    for j in range(rem):
                        gain += a[cycle[j]]
                    res = max(res, gain)

        return res

    return best(pb), best(ps)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k, pb, ps = map(int, input().split())
        p = list(map(lambda x: int(x) - 1, input().split()))
        a = list(map(int, input().split()))
        b, s = solve_one(n, k, pb, ps, p, a)
        if b > s:
            out.append("Bodya")
        elif s > b:
            out.append("Sasha")
        else:
            out.append("Draw")
    print("\n".join(out))

if __name__ == "__main__":
    main()

プレフィックス合計配列により、部分セグメント ゲインの定数時間計算が可能になります。 サイクルが検出されると、それを明示的に抽出し、その合計を計算します。 重要な実装の詳細は、全サイクルの繰り返し後の残りを正しく処理することであり、残りのステップのみをシミュレートします。 

よくある微妙な点は、サイクルに到達すると、サイクルの合計が正でない限り、そのサイクルで最良のノードに留まることが必ずしも最適であるとは限らないことです。 コードは、サイクルへの入り口に沿ったすべての停止位置を比較することによって、これを暗黙的に処理します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k, pb, ps = map(int, input().split())
        p = list(map(lambda x: int(x)-1, input().split()))
        a = list(map(int, input().split()))

        def best(start):
            vis = {}
            cur = start
            order = []
            for i in range(min(n, k)):
                if cur in vis:
                    break
                vis[cur] = i
                order.append(cur)
                cur = p[cur]

            pref = [0]
            for x in order:
                pref.append(pref[-1] + a[x])

            res = 0
            for i in range(len(order)):
                gain = pref[i+1] + (k-i-1) * a[order[i]]
                res = max(res, gain)

            if cur in vis:
                c = vis[cur]
                cycle = order[c:]
                cycle_sum = sum(a[x] for x in cycle)
                L = len(cycle)

                for i in range(len(order)):
                    if i < c:
                        continue
                    base = pref[i+1]
                    rem = k - (i+1)
                    if rem > 0:
                        full = rem // L
                        r = rem % L
                        gain = base + full * cycle_sum
                        for j in range(r):
                            gain += a[cycle[j]]
                        res = max(res, gain)

            return res

        bodya, sasha = best(pb-1), best(ps-1)
        out.append("Bodya" if bodya > sasha else "Sasha" if sasha > bodya else "Draw")

    return "\n".join(out)

 ## 特殊なケース

 サイクル合計が負であるが、個々のノードが大きい場合、微妙なエッジ ケースが発生します。 このような場合、サイクルを盲目的にループすると合計スコアが減少するため、最適な戦略は、高価値のノードに早期に到達できる場合にのみサイクルに入り、その後停止することです。 アルゴリズムは、完全な繰り返しをコミットするのではなく、サイクルの前およびサイクル内のプレフィックスに沿ったすべての停止位置を評価するため、これを処理します。
