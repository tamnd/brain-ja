 ## 解決策
 ## 問題の理解

 連続する要素間のモジュラー差だけがわかっている場合、整数の配列を再構築するように求められます。 より正確には、各要素が前の要素で除算されたときにどのように動作するかを説明する値が与えられ、これらすべての剰余に一致する有効なシーケンスを構築する必要があります。 

構築されたシーケンスは 2 つの制約を同時に満たさなければなりません。 まず、すべての要素は最大 10 億の大きな固定数値範囲内になければなりません。 次に、隣接するすべてのペアについて、2 番目の要素は最初の要素で除算したときに指定された剰余を生成する必要があります。 

重要な構造上の意味は、モジュロの動作に由来します。 以前の値を修正する場合$a_{i-1}$、次の値$a_i$算術形式でなければなりません$$a_i = k \cdot a_{i-1} + x_i$$負でない整数の場合$k$、そしてまた$x_i < a_{i-1}$。 この不等式はオプションではありません。有効な構成には必須の要件です。 

非常に重要な点で制約は小さいです。$n \le 500$テスト ケースごとに、すべてのテスト ケースの合計は$2 \cdot 10^5$。 これは、テスト ケースごとに線形な構築を目指す必要があることを直ちに示唆しています。 の可能な値を検索またはバックトラックしようとするソリューション$a_i$たとえ控えめな分岐要素でも 500 ステップを超えると爆発的に増加するため、遅すぎます。 

次の場合、微妙なエッジケースが発生します。$x_i = 0$。 そのような状況では、$a_i$の倍数でなければなりません$a_{i-1}$。 これを無視して単純に任意の値を割り当てる単純な試みは、後のステップで割り切れない可能性があります。 たとえば、小さな値を貪欲に選択すると、将来の制約によって不可能な剰余が強制されるため、簡単に行き詰ってしまいます。 

もう 1 つの問題となるケースは、連続する剰余が前の小さい値と比較して大きい場合です。 たとえば、次の場合$a_{i-1} = 3$しかし$x_i = 4$、条件はすぐに不可能です。 これは、建設では次のことを保証する必要があることを示しています。$a_{i-1}$は常に十分な大きさであり、以前の小さなランダムな選択から導出されるわけではありません。 

## アプローチ

 ブルートフォース戦略では、それぞれを選択しようとします。$a_i$までの値を試してみることで$10^9$そして必要な剰余が生成されるかどうかをチェックします$a_{i-1}$。 これは概念的には正しいですが、実行不可能です。 ステップごとに制限された数の候補だけを試したとしても、最悪のケースでは依然として指数関数的に増加します。$n$、各位置は前の位置に依存し、間違った選択はすべて前方に伝播するためです。 

重要な観察は、私たちは何かを最小化したり最適化したりすることを求められていないということです。 私たちに必要なのは存在だけであり、それによって衝突を避けるために積極的に価値観を膨らませる自由が与えられます。 これに気づくと、問題は検索の問題ではなく構築の問題になります。 

重要な構造上のアイデアは、すべてのステップで、以前の値が現在の残りの値よりも厳密に大きいことを保証することです。 私たちが保証する場合$$a_{i-1} > x_i$$そうすればいつでも選択できる$$a_i = a_{i-1} + x_i$$これは次の理由によりモジュロ条件を自動的に満たします。 

- 除算$a_{i-1}$商1を残します
 - 残りは正確に$x_i$したがって、問題全体は、シーケンスが厳密に増加しており、常に次の剰余を支配していることを確認することに帰着します。 ずっと$x_i \le 500$、十分に大きな基本値から安全に開始して、追加を続けることができます。 

シンプルかつ確実な選択は、次のように設定することです。$a_1$のような大きな定数として$10^9 - 500$、次に次を使用してフォワードビルドします$a_i = a_{i-1} + x_i$。 これは境界を超えることはなく、有効性が維持されます。

 ## アルゴリズムのチュートリアル

 1. 最初の要素を設定します$a_1$たとえば、多数に対して$10^9 - 500$。 これにより、その後のすべての追加が範囲内に収まるように十分なスペースが保証されます。 
2. ポジションごとに$i$2から$n$、 定義する$a_i = a_{i-1} + x_i$。 これにより、シーケンスが厳密に増加し、剰余の制御が維持されることが保証されます。 
3. 構築された配列を出力します。 

### なぜ効果があるのか

 それぞれのステップで$i$、 我々は持っています$a_i = a_{i-1} + x_i$。 以来$x_i < a_{i-1}$は常に真であるため、$a_{i-1}$非常に大きく始まり、増加するだけの場合、モジュロ演算は予測どおりに動作します。$$a_i \bmod a_{i-1} = (a_{i-1} + x_i) \bmod a_{i-1} = x_i$$この恒等式は、モジュラー演算から直接保持されます。 可能な最大の成長は$500 \cdot 500 = 250000$、はるか下$10^9$。 したがって、すべての制約は決定論的に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        
        a = [0] * n
        a[0] = 10**9 - 500
        
        for i in range(1, n):
            a[i] = a[i - 1] + x[i - 1]
        
        print(*a)

if __name__ == "__main__":
    solve()
```実装は建設的なアイデアに直接従います。 唯一の設計上の選択肢は、オーバーフローや無効なモジュール動作がないことを保証する大きな初期オフセットです。 次の各値は、線形の複雑さを維持しながら、一定時間で導出されます。

 ## 特殊なケース

 ### 大きな剰余は 500 に等しい

 入力:```
n = 2, x = [500]
```設定しました$a_1 = 999999500$、 それで$a_2 = 1000000000$。 以来$a_2 - a_1 = 500$、私たちは得ます$a_2 \bmod a_1 = 500$。 意図的に 500 のマージンを残したので、構築は範囲内に留まります。 

### すべてのもの

 入力:```
n = 5, x = [1, 1, 1, 1]
```シーケンスは次のようになります。```
999999500, 999999501, 999999502, 999999503, 999999504
```1 を加算すると、前の項で割ったときに剰余が 1 になるため、各ステップでは不変式が維持されます。 

### チェーンの最大長

 いつ$n = 500$そしてすべて$x_i = 500$、最終的な値は最大で増加します$250000$、まだはるか下にあります$10^9$。 これにより、初期バッファが十分であり、どのステップでもオーバーフローが発生しないことが確認されます。
