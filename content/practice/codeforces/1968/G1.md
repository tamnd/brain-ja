 ## 解決策
 ## 問題の理解

 この問題では、文字列を正確に分割するように求められます。$k$連続する部分文字列を取得し、それらの部分文字列間で共有される最長共通プレフィックス (LCP) を計算します。 簡単なバージョンの場合、範囲は次のとおりです。$k$単一の値です$l=r$したがって、必要なのはその特定の分割数の最大 LCP だけです。 入力は複数のテスト ケースで構成され、各テスト ケースには文字列と部分文字列の数を指定する整数が含まれます。 

重要な制約は、すべてのテスト ケースにわたる文字列の長さの合計が最大でも$2 \cdot 10^5$。 これは、おおよその用途で機能するソリューションを意味します。$O(n \log n)$文字列ごとの処理は十分に高速ですが、文字列の考えられるすべての分割を試みる単純なアプローチは、組み合わせによって分割数が増加するため、実行できません。 不注意なアプローチでは、すべてのパーティションを列挙して LCP を直接計算しようとする可能性があり、中程度のサイズの文字列でタイムアウトになります。 たとえば、次の場合$s = "abcdef"$そして$k=3$単純なアプローチでは、6 文字を 3 つの部分に分割し、それぞれの接頭辞を比較するあらゆる方法を試みる可能性がありますが、$n=10^5$これは不可能です。 

エッジ ケースには、すべての文字が同一である場合が含まれます。これにより、分割に関係なく LCP が最大化されます。$n=k$、各部分文字列が単一の文字になるように強制します。 後者の場合、すべての文字が同じでない限り、LCP は常に 0 になります。 もう 1 つの微妙なケースは、最適な LCP が単一の部分文字列の長さよりも厳密に小さい場合であり、過大評価を避けるために慎重な計算が必要です。 

## アプローチ

 ブルートフォースソリューションでは、文字列を次のように分割するあらゆる方法が生成されます。$k$連続する部分文字列を分割し、分割ごとにすべての部分文字列を文字ごとに比較して LCP を計算します。 これは原理的には正しいですが、分割数は組み合わせによって決まります。$n$、最悪の場合の複雑さを大まかに計算します$O(n^k)$、これは中程度の人でも実現不可能です$n$。 

重要な洞察は、問題は最長のプレフィックスを見つけることにあるということです。$x$それは少なくとも起こる$k$文字列の一部の部分で連続して 2 回。 言い換えれば、LCP は、文字がどの文字間でも異なる最初の位置によって制限されます。$k$連続した部分文字列。 視点を逆にすることで、文字列のハッシュ化と二分探索を利用できます。各候補のプレフィックスの長さについて、文字列を次のように分割できるかどうかを確認します。$k$そのプレフィックスを共有する部分文字列。 これにより、問題は組み合わせ列挙から、考えられるプレフィックス長に対する対数検索に軽減されます。$O(1)$事前計算されたハッシュによる部分文字列の比較。 

部分文字列の比較を効率的に行うために、ローリング ハッシュ (または LCP 配列を含むサフィックス配列) を事前に計算し、任意の 2 つの部分文字列を比較できるようにします。$O(1)$。 プレフィックス長に対するバイナリ検索は次のようになります。$O(\log n)$小切手と各小切手の費用$O(k)$部分文字列のハッシュ比較。 組み合わせると、次のようになります。$O(n \log n)$与えられた制約に対して許容できる解決策。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | O(n) | 遅すぎる |
 | 二分探索 + ハッシュ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列のプレフィックス ハッシュと累乗を事前計算します。$s$多項式ローリング ハッシュを使用します。 これにより、任意の部分文字列のハッシュを定数時間で計算できるようになります。 大きな素数係数と適切な基数を使用すれば、ハッシュの衝突は無視できます。 
2. 二分探索境界を初期化します。LCP は、最小の部分文字列の長さよりも長くすることはできません。$n // k$。 
3. 探索範囲が有効な間に中点を確認します$m$。 これを行うには、最初のハッシュを計算します。$m$長さのパーティション内の各候補部分文字列の文字$k$すべてのハッシュが等しいことを確認します。 「はい」の場合、$m$可能なので、より長いプレフィックスを試してください。 それ以外の場合は、候補を短くします。 
4. 最終的な実現可能な最大値$m$二分探索後の答えは次のとおりです$f_k$。 
5. すべてのテスト ケースに対して繰り返します。 

正確性を保証する不変条件は、バイナリ検索では、達成可能か不可能かのどちらかの長さのみが考慮されることです。また、ハッシュ比較では、ハッシュが一致する場合にのみ 2 つの部分文字列が等しいことが保証されます。 したがって、検索は最大 LCP に正確に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9+7
BASE = 31

def compute_hashes(s):
    n = len(s)
    h = [0] * (n+1)
    p = [1] * (n+1)
    for i in range(n):
        h[i+1] = (h[i]*BASE + ord(s[i])-ord('a')+1) % MOD
        p[i+1] = (p[i]*BASE) % MOD
    return h, p

def get_hash(h, p, l, r):
    return (h[r] - h[l]*p[r-l]) % MOD

def solve():
    t = int(input())
    for _ in range(t):
        n, k, _ = map(int, input().split())
        s = input().strip()
        h, p = compute_hashes(s)
        max_len = n // k
        low, high = 0, max_len
        ans = 0
        while low <= high:
            mid = (low + high)//2
            # get hash of first substring
            ok = True
            base_hash = get_hash(h, p, 0, mid)
            for i in range(1, k):
                if get_hash(h, p, i*mid, (i+1)*mid) != base_hash:
                    ok = False
                    break
            if ok:
                ans = mid
                low = mid + 1
            else:
                high = mid - 1
        print(ans)
```の`compute_hashes`関数は、ローリング ハッシュ計算のためのプレフィックス ハッシュと累乗を事前計算します。`get_hash`の任意の部分文字列のハッシュを抽出します。$O(1)$。 内部`solve`ループで、LCP の最大長を二分探索します。 各チェックは次のように繰り返されます。$k$部分文字列、ハッシュの比較。 部門`n // k`割り当てられたセグメントよりも長い部分文字列は存在できないため、可能な最大のプレフィックス長が得られます。 

## 実用的な例

 ### 例 1

 入力:`aba`、`k=3`| 私 | 部分文字列 | ハッシュ |
 | --- | --- | --- |
 | 0 | | h0 |
 | 1 | b | h1 |
 | 2 | | h2 |

 最大部分文字列長 = 1。mid=1、最初のハッシュ = 'a'、2 番目のハッシュ = 'b' != 'a' を確認します。 したがって、最大 LCP = 0 となります。`f_3=0`。 

### 例 2

 入力:`aaa`、`k=3`すべての部分文字列 = 'a'、ハッシュは等しい。 二分探索の結果`mid=1`実現可能。 最大LCP=1。 確認します`f_3=1`。 

これらのトレースは、アルゴリズムが不等文字部分文字列と等しい文字部分文字列の両方を正しく処理し、最大 LCP に収束していることを示しています。
