 ## 解決策
 ## 問題の理解

 2D デカルト平面上に配置された点のコレクションが与えられており、それらすべてを最小の総接続コストで単一のネットワークに接続したいと考えています。 任意の 2 点を接続するコストは、マンハッタン距離によって定義されます。これは、x 座標の絶対差と y 座標の絶対差を意味します。 

概念的には、すべての点を他のすべての点に接続して、完全な重み付きグラフを形成できます。 タスクは、選択したエッジの重みの合計を最小化しながら、すべてのポイントを接続するエッジのサブセットを選択することです。これはまさに最小スパニング ツリー問題です。 

重要な問題はスケールです。 この問題ファミリーの一般的なバージョンでは最大約 200,000 点があり、可能なエッジの数は 2 次です。 グラフを直接構築することは不可能であり、すべてのペアごとの距離を計算することさえ遅すぎます。 

素朴な推論が微妙に失敗するケースは、証明せずに局所ユークリッド近傍のみが重要であると仮定した場合に現れます。 たとえば、点 (0, 0)、(1000, 1000)、および (1, 1000) を考えてみましょう。 最も近いペアは (1, 1000) と (1000, 1000) ですが、MST の構造を考慮すると、グローバルに重要なエッジには別のペアが含まれる可能性があります。 最適な接続は生の距離だけではなく方向投影に依存するため、生のユークリッド空間で各点を 1 つの最近傍に接続するだけのアプローチでは、マンハッタン幾何学で必要なエッジを見逃す可能性があります。 

もう 1 つの隠れた問題は、エッジの重複または対称です。 注意を怠ってすべてのペアに対してエッジを生成すると、メモリ制限を超えて、クラスカルのアルゴリズムで冗長な作業が作成され、意図した線形算術解が黙って二次解に変換されてしまいます。 

## アプローチ

 ブルートフォース手法では、完全なグラフを明示的に構築します。 すべての点のペアについて、マンハッタン距離を計算し、それをエッジとして扱います。 次に、これらすべてのエッジに対して Kruskal のアルゴリズムを実行します。 MST はグラフ全体にわたって定義されているため、これは正しいのですが、エッジの数は n(n−1)/2 となり、n が 200,000 の場合、約 2×10^10 になります。 これだけ多くのエッジを生成することさえ不可能であり、それらを並べ替えることは完全に不可能です。 

重要な観察は、マンハッタン ジオメトリでは、MST に表示される候補エッジには強い構造的制限があるということです。 すべてのペアを考慮する代わりに、変換された座標系の点をスイープすることで得られる、慎重に選択された近傍の小さなセットのみを考慮するだけで十分です。 

直感的には、マンハッタン距離は、x と y の符号の選択に応じて 4 つの線形形式に書き換えることができます。 x+y、x−y、−x+y、および−x−y のような変換を定義すると、変換された各空間で、マンハッタンの最近傍関係は 1 次元の順序と一致します。 これらの変換されたキーのいずれかによってポイントを並べ替えると、潜在的な MST エッジがその順序で隣接するポイントから取得されます。 これにより、候補エッジが二次から線形に大幅に減少します。 

4 つの変換すべてに対してこのプロセスを繰り返し、すべての候補エッジを収集し、この削減されたエッジ セットに対して Kruskal のアルゴリズムを実行します。 正確さは、MST エッジがこれらの方向順序の少なくとも 1 つで最近傍として表示される必要があるという事実から得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n²) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 必要な MST エッジをすべて保持するスパース グラフを構築することに問題を絞り込み、標準の最小スパニング ツリー アルゴリズムを実行します。

1. それぞれの座標が (x, y) である点のリストから始めます。 これらは、エッジの重みがマンハッタン距離である完全なグラフの頂点を表します。 
2. 式 x+y、x−y、−x+y、−x−y を使用して、各点の 4 つの変換バージョンを構築します。 各変換は、異なる方向軸に沿ってマンハッタン距離を揃えることに対応します。 マンハッタンのジオメトリは、変換後に線形になる軸に沿った支配パターンに依存するため、この手順が必要です。 
3. 4 つの変換のそれぞれについて、変換されたキーによってすべてのポイントを並べ替えます。 ソートにより、マンハッタン距離が近い可能性が高い点が隣接する構造が課せられます。 
4. ソートされたリストごとに、連続する点のペアを考慮します。 隣接するペアごとに、実際のマンハッタン距離を計算し、それらの間にエッジを作成します。 近傍のみを取得する理由は、この変換された空間内の最適な接続は、ローカルに隣接する要素間の境界を越える必要があるためです。 
5. 4 つの変換すべてからそのようなエッジをすべて収集します。 これにより、最大 4(n-1) 個の候補エッジが生成され、サイズが線形になります。 
6. 収集したすべてのエッジを重量別に分類します。 これにより、サイクルを形成しない利用可能な最小のエッジを常に選択する、クラスカルのアルゴリズムへの準備が整います。 
7. ポイントに対して Union-Find (DSU) 構造を実行します。 エッジを昇順に繰り返し、以前に切断された 2 つのコンポーネントが接続されている場合は、MST にエッジを追加します。 
8. すべてのポイントが接続されるまで続行します。 DSU は、サイクルを決して形成せず、単一のスパニング ツリーに徐々にマージするフォレスト構造を常に維持することを保証します。 

### なぜ効果があるのか

 正確かどうかは、マンハッタンの距離が方向の極値に分解されるという事実にかかっています。 MST エッジとなる可能性のある点のペアには、適切に投影された場合にソート順で近傍となる 4 つの座標変換のうち少なくとも 1 つが存在します。 これにより、必要なすべてのエッジが候補セットに確実に含まれるようになります。 このようなエッジがすべて存在すると、Kruskal のアルゴリズムは常に MST を含むエッジ スーパーセットからグローバルに最小のスパニング構造を構築するため、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    edges = []

    for t in range(4):
        arr = []
        for i, (x, y) in enumerate(pts):
            if t == 0:
                key = x + y
            elif t == 1:
                key = x - y
            elif t == 2:
                key = -x + y
            else:
                key = -x - y
            arr.append((key, x, y, i))

        arr.sort()

        for i in range(n - 1):
            _, x1, y1, u = arr[i]
            _, x2, y2, v = arr[i + 1]
            w = abs(x1 - x2) + abs(y1 - y2)
            edges.append((w, u, v))

    edges.sort()

    dsu = DSU(n)
    ans = 0

    for w, u, v in edges:
        if dsu.union(u, v):
            ans += w

    print(ans)

if __name__ == "__main__":
    solve()
```DSU 実装は、クラスカルのアルゴリズム中に接続されたコンポーネントを効率的に維持するために使用されます。 サイズによるパスの圧縮と結合により、ほぼ一定の償却操作が保証されます。これは、最大 O(n) エッジを処理する可能性があるため必要です。 

変換ループは重要な最適化です。 すべてのペアを考慮するのではなく、変換された各座標系でソートした後に隣接する点のみを比較します。 微妙な点は、それぞれの変換で異なる候補エッジが露出されるため、各変換を独立して処理する必要があることです。 

最後に、クラスカルのアルゴリズムは重みの昇順でエッジを処理することに依存しており、サイクルを生じさせない可能な限り安価な接続を常に追加するようにするため、エッジをグローバルにソートする必要があります。 

## 実用的な例

 小さな点のセット (0,0)、(2,2)、(3,1)、(5,0) を考えてみましょう。 

1 つの変換 (x+y など) を適用すると、値 0、4、4、5 が得られます。並べ替えると、(0,0) が最初、次にタイ ペア、次に (5,0) という順序が得られます。 この順序では隣接する要素間にのみエッジを生成します。これにより、意味のある短い接続がすでにキャプチャされています。 

| ステップ | 並べ替え順 | エッジが追加されました | 重量 |
 | --- | --- | --- | --- |
 | x+y | (0,0)、(2,2)、(3,1)、(5,0) | (0,0)-(2,2) | 4 |
 | x+y | (2,2)-(3,1) | 2 | |
 | x+y | (3,1)-(5,0) | 3 | |

 このトレースは、完全なペアごとの比較を必要とせずに、変換後のローカル隣接関係が関連するすべての短エッジをキャプチャしていることを示しています。 

次に、2 番目のケース (0,0)、(1,100)、(2,0)、(3,100) を考えてみましょう。 最適な MST は、低い y 値と高い y 値の間で切り替わります。 

| ステップ | ソート順 (x-y) | エッジが追加されました | 重量 |
 | --- | --- | --- | --- |
 | x-y | (0,0)、(1,100)、(2,0)、(3,100) | (0,0)-(1,100) | 101 |
 | x-y | (1,100)-(2,0) | 101 | |
 | x-y | (2,0)-(3,100) | 101 | |

 これは、点が空間内でインターリーブされている場合でも、少なくとも 1 つの変換によって MST 構築のための正しい隣接構造が公開されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 4 種類の n 点と O(n) エッジのソートおよび DSU 操作 |
 | スペース | O(n) | ポイント、エッジ、DSU 構造のストレージ |

 変換ステップとクラスカルのエッジ ソートの両方において、主なコストはソートです。 他のすべての操作は線形またはほぼ一定で償却されるため、このソリューションは大規模な入力に適しています。

 ## 特殊なケース

 (0,0) などの単一点入力は空の MST を生成します。エッジは生成されず、DSU は結合を実行しないため、アルゴリズムは当然 0 を返します。 

すべての点が (0,0)、(1,0)、(2,0) などの直線上にある場合でも、変換によって正しい隣接関係が生成され、クラスカルは正確に n−1 個の連続エッジを選択します。 チェーンを接続するにはすべてのエッジが必要であるため、DSU は必要なリンクのスキップを防ぎます。 

(0,0)、(0,1)、(1,0)、(1,1) のような正方形の構成では、複数の変換により重複する候補エッジが生成されます。 ソートのステップにより、たとえ冗長なエッジが現れても、DSU によって最小の 3 つのエッジのみが受け入れられ、循環のない正しいツリーが形成されることが保証されます。
