 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースは次のことを説明します。$n \times n$チェス盤を表示し、正確に配置するように要求します$n$2 人のルークが同じ行または列を共有しないように、ボード上のルークを配置します。 これにより、すべての有効な配置が列の順列に対応するように直ちに強制されます。$i$、正確に 1 つの列を選択します$p_i$、そしてすべて$p_i$区別する必要があります。 

このようなすべての有効なルークの順列のうち、正確に一致する構成のみをさらにカウントします。$k$ルークのペアは「斜めに隣接」しています。 2 人のルークが同時に連続する行と連続する列に座っている場合、そのようなペアに貢献します。$i$、 両方$(i, p_i)$そして$(i+1, p_{i+1})$満足する$|p_i - p_{i+1}| = 1$。 タスクは、次の順列の数を計算することです。$[1..n]$まさに持っています$k$連続する位置間の大きさ 1 の隣接する差、モジュロ$10^9 + 7$。 

制約は次のとおりです。$t \le 5000$そして$n \le 1000$したがって、を再計算するソリューションはすべて、$O(n)$または$O(n^2)$テストケースごとの動的プログラムは遅すぎます。 順列に対する三次列挙または組み合わせ列挙は不可能です。$n!$成長が早すぎる。 これにより、構造化された計数式または線形 DP の使用が推進されます。$n$事前計算あり。 

微妙な点は、「隣接ペア」はルークの任意のペアではなく、連続する行のみに依存することです。 これにより、グローバル ジオメトリの必要性がなくなり、問題は完全に順列における隣接構造に関するものになります。 

素朴な考えを打ち破るエッジケースは小さなことから生まれる$n$。 のために$n=1$、隣接するペアがまったくないため、$k=0$可能です。 のために$n=2$、2つの順列$[1,2]$そして$[2,1]$それぞれが隣接するペアを 1 つだけ生成するため、$k=0$不可能です。 エッジの独立性を前提とする単純な式では、無効なエッジにゼロ以外の値が誤って割り当てられてしまいます。$k$。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$n!$順列を計算し、正確に 1 だけ異なる連続するペアの数を数えます。 順列ごとに、隣接する差異をスキャンするのにコストがかかります$O(n)$したがって、全体の複雑さは次のようになります。$O(n \cdot n!)$、これはすでに実行不可能です$n=10$。 

重要な観察は、条件が絶対値ではなく、順列内の連続する要素間の隣接性にのみ依存するということです。 これにより、問題は、連続する値が何回異なるかによって順列を数えることになります。$\pm 1$、これは古典的な「隣接スワップ構造」制約です。 任意の順列の観点から考える代わりに、左から右へ順列を構築し、値空間内で隣接する 2 つの数値のうちの 1 つの隣に数値を配置した回数を追跡できます。 

これにより、問題は DP オーバー位置と最後の値に軽減されますが、次のように直接実行すると、それでも大きすぎます。$O(n^2)$テストケースごとの状態。 より深い構造は、相対的な順序のみが重要であり、「値で隣接するエッジ」の寄与は、連続する整数を結合して形成されるランを配置する方法を数えるように動作するということです。 これにより、選択方法を数えることと同等の組み合わせDPが得られます。$k$間の隣接エッジ$n-1$可能な隣接位置。一貫性を保つための補正が行われます (選択されたエッジは置換の制約により任意に重なることができないため)。 結果として得られる構造は、既知の線形 DP です。$n$と$O(n^2)$前処理中。 

DP を事前計算します。$dp[i][j]$は長さの順列の数です$i$まさに$j$隣接エッジ。 トランジションでは要素の挿入が考慮されます$i$サイズの順列に$i-1$: 値の順序で先行するものと新しい隣接関係を作成するか、作成せず、各効果を生み出す挿入位置の数をカウントすると、閉じた反復が得られます。

 | ブルートフォース |$O(n \cdot n!)$|$O(n)$| 遅すぎる |
 | 順列上の DP |$O(n^2)$テストごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グローバル DP テーブルを一度構築します。$n = 1000$すべてのテスト ケースが同じ境界を共有するためです。 

1. 定義する$dp[i][j]$サイズの順列の数として$i$まさに$j$隣接する値と差のペア。 
2.初期化$dp[1][0] = 1$なぜなら、単一の要素は隣接関係を形成できないからです。 
3. それぞれについて$i$2から$n$、サイズの順列を構築します$i$サイズのものから$i-1$。 
4. 要素挿入時$i$に置くことができます。$i$既存の順列に対する相対的な可能な位置。 
5. これを端に挿入すると、新しい隣接エッジはゼロになります。 
6. 連続する2つの数字の間に挿入する場合$x$そして$y$、次の場合に限り、新しい隣接関係が作成されます。$x$そして$y$再ラベル付け後の値の構造は 1 異なります。これは、正確に一致します。$i-1$隣接機会を形成する有効な位置。 
7. したがって、状態から$dp[i-1][j]$、私たちはどちらかを維持します$j$ほとんどの挿入では変更されませんが、特定の挿入位置では 1 ずつ増加します。 
8. これにより、次の繰り返しが得られます。$$dp[i][j] = (i - j) \cdot dp[i-1][j] + (j+1) \cdot dp[i-1][j-1]$$ここで、最初の項は新しい隣接関係を作成しない挿入をカウントし、2 番目の項は既存の隣接構造を拡張する挿入をカウントします。 
9. すべての値を剰余として取得します$10^9 + 7$。 
10. テーブルを一度事前計算してから、各クエリに答えます。$O(1)$。 

### なぜ効果があるのか

 各ステップで、サイズのすべての順列$i-1$すべての挿入位置に等しく寄与し、各挿入は、値が隣接する 2 つの要素を新しい隣接ペアにマージするかどうかによって純粋に分類できます。 DP は、各段階で存在する隣接機会の数を正確に追跡し、反復により次の不変条件が維持されます。$dp[i][j]$すべての順列を正確に集計します$j$有効な隣接する値と差のペア。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 1000

dp = [[0] * (MAXN + 1) for _ in range(MAXN + 1)]
dp[1][0] = 1

for i in range(2, MAXN + 1):
    for j in range(0, i):
        if dp[i-1][j]:
            # insert i without creating new adjacency
            dp[i][j] = (dp[i][j] + dp[i-1][j] * (i - j)) % MOD
            # insert i creating one new adjacency
            if j + 1 <= i:
                dp[i][j+1] = (dp[i][j+1] + dp[i-1][j] * (j + 1)) % MOD

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    if k > n - 1:
        print(0)
    else:
        print(dp[n][k] % MOD)
```DP テーブルは 1 回計算され、各テスト ケースは直接ルックアップになります。 2 つの遷移は、新しく挿入された要素が追加の隣接関係を作成するかどうかに対応し、係数は隣接関係カウントを維持または増加させる挿入位置の数をカウントします。 

よくある実装上の間違いは、次のことを忘れることです。$k$によって制限されています$n-1$、しかないので、$n-1$任意の順列での連続したペア。 もう 1 つは、値空間での隣接性と位置空間での隣接性を混同することです。 DP はすでにこの区別を暗黙的にエンコードしているため、実装では値を明示的にチェックしようとするべきではありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    MOD = 10**9 + 7

    MAXN = 200  # smaller local DP for tests

    dp = [[0] * (MAXN + 1) for _ in range(MAXN + 1)]
    dp[1][0] = 1

    for i in range(2, MAXN + 1):
        for j in range(0, i):
            if dp[i-1][j]:
                dp[i][j] = (dp[i][j] + dp[i-1][j] * (i - j)) % MOD
                if j + 1 <= i:
                    dp[i][j+1] = (dp[i][j+1] + dp[i-1][j] * (j + 1)) % MOD

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        if k > n - 1:
            out.append("0")
        else:
            out.append(str(dp[n][k]))
    return "\n".join(out)

 ## 特殊なケース

 のために$n=1$、隣接するペアは存在しないため、$k=0$有効です。 DP は正しく初期化されます$dp[1][0]=1$、他のすべての状態はゼロのままであるため、次のクエリはすべて$k>0$0を返します。 

のために$n=2$、隣接する位置が 1 つだけ存在します。 DPがプロデュースするのは、$dp[2][0]=1$そして$dp[2][1]=1$、2 つの順列に対応します。 隣接関係を独立した選択肢として扱おうとすると、誤って 3 つ以上の構成が提案されてしまいますが、順列制約により正確に 2 つの結果が強制され、再帰的にはそれが尊重されます。 

のために$k=n-1$、唯一の有効な順列は、完全に増加または完全に減少するチェーンであり、DP は単一の構成カウントに折りたたまれます。これは、すべてのステップで隣接関係が作成される反復構造と一致します。
