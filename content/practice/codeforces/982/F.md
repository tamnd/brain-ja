 ## 解決策

 ## 問題の理解

 一方通行の道路で接続された交差点を表す有向グラフが与えられます。 車は見知らぬ交差点から出発し、外向きの道路に沿って永遠に進み続けます。 この動きが決して行き詰まることがないことが保証されています。つまり、到達可能なあらゆる状況から、旅を続けるための少なくとも 1 つの発信エッジが常に存在します。 

Petr は、車がどこからスタートしても、移動中にどの出力エッジが選択されても、最終的には無限の歩行のある時点で選択した交差点に到達するように、単一の交差点を選択したいと考えています。 

グラフの用語で言い換えると、ウォークは任意にエッジをたどりますが、無限に継続できると仮定して、グラフ内のすべての無限有向ウォークにとって避けられない頂点を探します。 

n が 100000 まで、m が 500000 までという制約により、グラフのサイズが線形またはほぼ線形になるように解が強制されます。 すべてのノードから DFS を繰り返すこと、またはペアごとに到達可能性をチェックすることを伴うものは、O(n(m+n)) かそれより悪いスケールになるため、すぐに制限を超えます。 

グラフにサイクル状に配置された複数の強く接続されたコンポーネントが含まれている場合、微妙な障害が発生するケースが発生します。 たとえば、コンポーネント A → B → C → A の有向サイクルを考えてみましょう。各コンポーネントには内部サイクルもあります。 素朴な直観は、1 つの SCC 内の頂点を選択し、すべてのパスが最終的にそこに流入すると仮定するかもしれませんが、実際には、プロセスは単一のエントリ ポイントにコミットすることなく永久に循環する可能性があります。 

もう 1 つの注意が必要なケースは、パスの選択に応じて異なる順序でアクセスできる大規模な SCC が複数ある場合です。 このようなグラフでは、コンポーネント内のサイクルによって無限の動きが保証されているとしても、単一の頂点が避けられない可能性があります。 

## アプローチ

 総当り的な解釈では、各頂点を候補のミーティング ポイントとしてテストします。 固定頂点 v の場合、すべての可能な開始位置とすべての可能なエッジの連続から、無限ウォークが最終的に v に到達することを検証する必要があります。これは、最悪の場合に、可能なすべての到達可能なセットとすべての無限パスについて推論する必要があることをすでに示唆しています。 パスの数は長さに応じて指数関数的に増加するため、すべての歩行を直接シミュレーションすることは不可能です。 

より構造化されたブルート フォースは、到達可能性を逆にチェックすることです。頂点 v ごとに、v に到達できる頂点のセットを計算します。次に、すべての頂点から v へのパスがあるかどうかをチェックします。これは、エッジを順方向にたどったときに、グラフ内のすべてのノードから v に到達可能であることと同等です。 このチェックはすべての頂点からの DFS または BFS を使用して実行でき、コストは O(n(m+n)) ですが、これは大きすぎます。 

重要な構造的洞察は、グラフが強く接続されたコンポーネントに分解できるということです。 強く接続されたコンポーネントの内部では、すべての頂点が他の頂点に到達できるため、無限の動きの観点からは、各 SCC は単一の「マクロ状態」のように動作します。 各 SCC を折りたたむと、有向非巡回グラフが生成されます。 

その凝縮されたグラフでは、他のすべてのコンポーネントから到達可能なコンポーネントを見つけることが問題になります。 DAG では、これは、逆到達可能性の意味でシンク コンポーネントが 1 つだけ存在する場合、または同等に、凝縮グラフ内で入力エッジを持たない唯一のコンポーネントである場合にのみ発生します。 そのコンポーネントは、他のすべてのコンポーネントがそこに流入できるため、普遍的なアトラクターとして機能し、SCC 内に入ると、ウォークはそれを回避する SCC 構造の制約から逃れることができません。 

これにより、タスクが SCC の計算と線形時間での凝縮グラフの分析に軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース到達可能性チェック | O(n(m+n)) | O(n+m) | 遅すぎる |
 | SCC凝縮+分析 | O(n+m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Kosaraju または Tarjan アルゴリズムを使用して、グラフの強接続成分を計算します。 これにより、頂点が最大のセットにグループ化され、すべての頂点が同じセット内で他のすべての頂点に到達できるようになります。 このようなコンポーネント内では長期的な動きに関して頂点を区別できないため、このステップが必要です。 
2. 各 SCC が単一ノードとなる凝縮グラフを構築します。 元のグラフのすべてのエッジ u → v について、u と v が異なるコンポーネントに属している場合は、それらの SCC 間に有向エッジを追加します。 
3. 圧縮されたグラフ内のすべてのノードの次数を計算します。 
4. 次数が 0 に等しいすべての SCC を特定します。 これらは、他のコンポーネントが入力できないコンポーネントです。 
5. そのような SCC が 1 つだけ存在する場合は、その中の任意の頂点を答えとして選択します。 このような SCC が複数ある場合は、避けられない宛先コンポーネントが 1 つもないため、-1 が出力されます。 
6. 選択した頂点を返します。 

度数 0 の SCC に焦点を当てる理由は、入力エッジを持つ SCC は、強制的に進入しない他の SCC のサイクル内に留まることで、無限に回避できる可能性があるためです。 

### なぜ効果があるのか

 凝縮グラフは DAG であるため、少なくとも 1 つのソース SCC が存在する必要があります。 SCC 遷移のすべてのパスが最終的に同じ SCC につながる場合に限り、すべての無限ウォークで頂点が避けられなくなります。 これは、凝縮グラフ内に発生源 SCC が 1 つだけ存在する場合にのみ可能です。複数の発生源では、別の発生源内でウォークを開始し、別の発生源に強制的に入ることなく、その到達可能な領域内に永久に留まることができるためです。 SCC 内では、すべての頂点が相互に到達可能であるため、一意のソース SCC で任意の頂点を選択すると、無限トラバースの下でも最終的な訪問が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, rg):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(v, c):
        comp[v] = c
        for to in rg[v]:
            if comp[to] == -1:
                dfs2(to, c)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]

    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        rg[v].append(u)
        edges.append((u, v))

    comp, c = kosaraju(n, g, rg)

    indeg = [0] * c
    for u, v in edges:
        cu, cv = comp[u], comp[v]
        if cu != cv:
            indeg[cv] += 1

    sources = [i for i in range(c) if indeg[i] == 0]

    if len(sources) != 1:
        print(-1)
        return

    target = sources[0]
    for i in range(n):
        if comp[i] == target:
            print(i + 1)
            return

if __name__ == "__main__":
    solve()
```この実装では、Kosaraju のアルゴリズムを使用して 2 つのパスで SCC を計算します。最初に終了順位を構築し、次に反転したグラフにコンポーネントを割り当てます。 その後は、コンポーネント間のエッジを検査するだけで済みます。 

よくある落とし穴は、度数を計算するときにコンポーネント内のエッジを無視することを忘れることです。 これらのエッジは凝縮構造に影響を与えず、度数のカウントが誤って増大する可能性があります。 もう 1 つの微妙な点は、ターゲット SCC から任意の頂点を選択することです。これは、強く接続されたコンポーネント内のすべての頂点がこの目的では同等であるためです。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    sys.setrecursionlimit(10**7)

    def kosaraju(n, g, rg):
        visited = [False] * n
        order = []

        def dfs1(v):
            visited[v] = True
            for to in g[v]:
                if not visited[to]:
                    dfs1(to)
            order.append(v)

        for i in range(n):
            if not visited[i]:
                dfs1(i)

        comp = [-1] * n
        cid = 0

        def dfs2(v, c):
            comp[v] = c
            for to in rg[v]:
                if comp[to] == -1:
                    dfs2(to, c)

        for v in reversed(order):
            if comp[v] == -1:
                dfs2(v, cid)
                cid += 1

        return comp, cid

    def solve():
        n, m = map(int, input().split())
        g = [[] for _ in range(n)]
        rg = [[] for _ in range(n)]
        edges = []
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            rg[v].append(u)
            edges.append((u, v))

        comp, c = kosaraju(n, g, rg)

        indeg = [0] * c
        for u, v in edges:
            if comp[u] != comp[v]:
                indeg[comp[v]] += 1

        sources = [i for i in range(c) if indeg[i] == 0]

        if len(sources) != 1:
            return "-1\n"

        for i in range(n):
            if comp[i] == sources[0]:
                return str(i + 1) + "\n"

    return solve()

 ## 特殊なケース

 重要なエッジケースは、グラフ全体が単一の強く接続されたコンポーネントである場合です。 その状況では、すべての頂点が他のすべての頂点から到達可能であるため、凝縮グラフには次数 0 のノードが 1 つだけ存在します。 アルゴリズムは、この SCC 内の任意の頂点を選択します。これは正しいことです。なぜなら、車は、どのような歩行でも、最終的には無限に頻繁にすべての頂点を訪れるからです。 

もう 1 つのエッジ ケースは、複数の SCC が凝縮グラフ内に入力エッジを持たない場合です。 たとえば、間にエッジのない 2 つの素のサイクルが考えられます。 この場合、一方のサイクルからスタートすると、車はもう一方のサイクルに進入することなく永久に留まることができるため、普遍的な集合場所は存在しません。 アルゴリズムは複数のソース SCC を検出するため、-1 を正しく出力します。 

最後の微妙なケースは、エッジが SCC の大きなサイクルを形成し、すべてのコンポーネントが次数 1 を持つ場合です。 グラフは循環的な意味で完全に接続されていますが、自動車は一意の宛先コンポーネントにコミットすることなく無限に循環できるため、単一の SCC は避けられません。
