 ## 問題の理解

 時間の経過とともに観察されたサメの 1 日の移動距離を表す一連の個別の正の整数が与えられます。 閾値を導入します$k$。 距離が以下の場合、各日は「滞在日」のいずれかに分類されます。$k$、または少なくとも「移動日」$k$。 

重要な構造解釈は、すべての日が移動日によって区切られた最大の連続する滞在日のセグメントに分割されるということです。 このような各セグメントは 1 つの場所を表し、セグメントの長さはサメがその場所に滞在した連続日数になります。 

サメは決して前の位置に戻ることはありません。これは、セグメンテーションが線形であり、一度固定されることを意味します。$k$が選ばれます。 ただし、私たちが課す制約はさらに強力です。すべての滞在セグメントは同じ長さでなければなりません。 すべてのしきい値の中で$k$このプロパティを満たす場合、セグメントの数を最大化する必要があり、複数のしきい値がその最大値に達する場合は、最小のしきい値を選択します。$k$。 

制約$n \le 10^5$これよりも悪い解決策は存在しないことを意味します。$O(n \log n)$は危険であり、すべての候補しきい値を超える二次関数は不可能です。 距離は異なるため、ソートは自然なツールとなり、問題の構造は、候補しきい値が配列要素の周囲の値でのみ重要であることを強く示唆しています。 

すべての値が相対的に非常に小さいか非常に大きい場合、微妙なエッジ ケースが発生します。$k$。 もし$k$すべての値より小さい場合は、毎日が移動日となり、滞在セグメントがゼロになりますが、これは無効です。 もし$k$がすべての値より大きい場合、単一の長いセグメントが得られます。これは、等しい長さは自明に満たされますが、最小のセグメント化数が得られます。 

もう 1 つの重要なケースは、セグメントが形成されているものの、その長さが異なる場合です。 たとえば、次の 1 つの選択肢がある場合、$k$2、1、2 のようなセグメント長が生成される場合、等価性が必要なため、セグメント化が存在する場合でも無効になります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのしきい値を試します。$k$1から$10^9$、セグメンテーションをシミュレートし、すべての滞在セグメントの長さを計算し、それらが等しいかどうかを確認します。 各シミュレーションは次のとおりであるため、これはすぐに実行不可能になります。$O(n)$、候補者の数$k$値は最大です$10^9$、最悪の場合は限界をはるかに超える複雑さにつながります。 

意味のあるしきい値は、少なくとも 1 つの要素の分類を変更するしきい値だけであることに注意する必要があります。 分類は次のいずれかによってのみ決まるため、$a_i \ge k$、唯一の関連する値$k$配列の連続する並べ替えられた値の間にある。 

より深い洞察は、閾値を固定すると、$k$、シーケンスはバイナリ配列になります: 値の場合は 1$\ge k$、それ以外の場合は 0。 この問題は、このバイナリ配列に関するセグメンテーションの問題になります。 連続するゼロのブロックがすべて同じ長さになるようにし、ゼロブロックの数を最大化したいと考えています。 

すべてのしきい値を直接試す代わりに、候補を反復処理できます。$k$ソートされた配列から値を導き出し、誘導されたセグメンテーションを効率的に評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての k に対するブルート フォース |$O(n \cdot 10^9)$|$O(1)$| 遅すぎる |
 | ソートされたしきい値の評価 |$O(n^2)$素朴なシミュレーション |$O(1)$| 遅すぎる |
 | 個別の値に対する最適化されたスイープ |$O(n \log n)$|$O(n)$| 承認済み |

 最適なアプローチは、しきい値遷移が発生する場所のソートと増分評価に依存しており、毎回最初から再計算するのではなく、セグメントの長さを効率的に維持します。 

## アルゴリズムのチュートリアル

 1. 元の値を追跡しながら配列をソートします。 ソートされた順序により、要素が「しきい値以下」から「しきい値以上」に切り替わったタイミングがわかります。$k$が増えます。 
2.スイープ$k$ソートされた値をブレークポイントとして使用して、低い値から高い値へ。 2 つの連続する値の間$a[i]$そして$a[i+1]$、バイナリ配列の構造は変わらないため、これらの点のみが重要です。 
3. 候補者が確定した場合$k$、位置が次のような概念的なバイナリ配列を構築します。$a_i < k$はゼロ、その他は 1 です。 毎回明示的に構築するのではなく、ゼロの実行をシミュレートします。 
4. 配列を 1 回走査し、すべてのゼロ セグメントの長さを計算します。 ワンセグは動きを表すため無視してください。 
5. すべてのゼロセグメントの長さが等しいかどうかを確認します。 そうでない場合は、これを破棄してください$k$。 
6. 有効な場合は、ゼロセグメントの数を数えます。 この数がこれまでに見つかった最良の数よりも大きい場合は、回答を更新します。 同じ場合は小さい方を選択してください$k$。 

### なぜ効果があるのか

 重要な不変条件は、固定された$k$、ゼロのセグメント化は、次の相対的な順序によって完全に決定されます。$a_i$に関して$k$。 変わってから$k$の正確な値でのみ比較を変更します。$a_i$、有効なセグメント構造はすべて、これらの離散遷移点に現れる必要があります。 したがって、これらの候補のみを評価することで、考えられるすべての個別のセグメンテーションがカバーされます。 等価条件により、バイナリ パーティション内の均一なブロック長をチェックする問題が軽減され、候補ごとに線形時間で検証できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_segments(arr, k):
    seg_lengths = []
    i = 0
    n = len(arr)
    
    while i < n:
        if arr[i] >= k:
            i += 1
            continue
        j = i
        while j < n and arr[j] < k:
            j += 1
        seg_lengths.append(j - i)
        i = j
    
    return seg_lengths

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    vals = sorted(set(a))
    
    best_segments = 0
    best_k = 0
    
    for k in vals:
        segs = get_segments(a, k)
        if not segs:
            continue
        
        if len(set(segs)) == 1:
            cnt = len(segs)
            if cnt > best_segments or (cnt == best_segments and (best_k == 0 or k < best_k)):
                best_segments = cnt
                best_k = k
    
    print(best_k)

if __name__ == "__main__":
    solve()
```機能`get_segments`値が厳密に以下であるすべての連続ブロックを構築します$k$。 各ブロックは 1 つの場所に対応します。 次に、ソリューションはセグメントの長さをセットに変換し、サイズが 1 であるかどうかを確認することで均一性を検証します。 

外側のループは、配列の個別の値に対してのみ反復されます。これは、2 つの連続する値の間のしきい値が同じ分類パターンを生成するためであり、代表的な点のみをテストするだけで十分です。 

タイブレーク ロジックには注意が必要です。複数のしきい値が同じ数のセグメントを生成する場合、明示的に小さいほうが優先されます。$k$、確定的な出力を保証します。

 ## 特殊なケース

 すべての要素が選択した要素より小さい場合$k$、配列全体が 1 つのセグメントになります。 アルゴリズムは、長さが次の 1 つのゼロ ブロックを生成することでこれを処理します。$n$これは有効であり、セグメント数は 1 になります。

セグメントが存在するが長さが異なる場合、`set`check はそれらを即座に拒否します。 たとえば、候補が長さを生成する場合、$[2, 1, 2]$、セットになります。$\{1,2\}$、検証に失敗し、破棄されます。
