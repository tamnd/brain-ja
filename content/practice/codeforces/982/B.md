 ## 解決策

 ## 問題の理解

 The bus consists of$n$独立した列で、各列にはちょうど 2 つの座席が含まれます。 各行の幅は固定です$w_i$、すべての幅が異なるため、いつでも曖昧さなく行を比較できます。 

乗客は決まった順番で一人ずつ到着します。 動作には 2 つのタイプがあります。 内向的な人は常に完全に空の列に座ることを主張し、そのようなすべての列の中で最も幅の狭い列を選択します。 外向的な人は、すでに座席が 1 つだけ埋まっている列にのみ座ることができ、部分的に埋まった列の中で、最も幅の広い列を選択します。 

タスクは、到着順のすべての乗客について、どの列に乗車するかについて、このプロセスと出力をシミュレートすることです。 

制約は次のとおりです$n = 200{,}000$したがって、シミュレーションには以下が含まれます。$2n = 400{,}000$操作。 各乗客のすべての行をスキャンするソリューションは次のように動作します。$O(n^2)$、これは実現可能な限界をはるかに超えています。 これにより、各決定を対数時間で行うことができるように、候補行の順序付けられたセットを維持することが直ちに強制されます。 

2 つのグループ間のやり取りに微妙な問題が現れます。 内向的な人は、「空のセット」から行を削除し、「半分埋められたセット」に移動します。 外向的な人は、その半分満たされたセットから消費します。 すべての行をスキャンしてこれらのセットを再計算する単純な実装は、正確さのためではなく、終了するかなり前にタイムアウトするために失敗します。 

最小幅の空の行と最大幅の半分埋められた行がインターリーブ方式で展開される場合、エッジ ケースが発生します。 たとえば、幅が次の場合、$[1,2,3]$そしてその順序は$010101$、利用可能なセットの構造は移動のたびに変化し、正確性は最初から再計算するのではなく、常に正しい動的フロンティアから選択することに依存します。 

## アプローチ

 ブルート フォース シミュレーションでは、乗客ごとにすべての列をスキャンし、空か半分が占有されているかを確認し、選択ルールを適用します。 内向的な人にとって、これはすべてをスキャンすることを意味します。$n$行をスキャンして空の行の最小幅を見つけ、外向的なスキャンの場合は半分埋まった行の最大幅を見つけます。 乗客一人当たりの料金$O(n)$、につながる$O(n^2)$合計操作、大まかに$1.6 \times 10^{11}$最悪の場合でもチェックしますが、それは不可能です。 

重要な観察は、どちらの選択も、動的に変化する順序構造の維持に依存するということです。 内向的な人は常に利用可能な空の行の最小値を必要とし、外向的な人は常に部分的に埋められた行の最大値を必要とします。 これはまさに、プライオリティ キュー (ヒープ) またはバランスの取れた順序付きセットが設計されているものです。 幅でキー設定された最小ヒープに空の行を格納し、幅でキー設定された最大ヒープに半分埋められた行を格納すると、各操作は対数時間で 1 回のプッシュまたはポップになります。 

また、割り当てを出力するときに行インデックスにマップし直すことができるように、指定された幅がどの行に対応するかを覚えておく必要もあります。

 | 最適 (ヒープ) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの優先体制を維持しています。 1 つは、現在空のすべての行を幅の増加順に格納します。 もう 1 つは、すでに 1 人の乗客がいるすべての行を幅の小さい順に格納します。 

また、選択は幅に基づいて行われますが、出力には行番号が必要であるため、幅から行インデックスへのマッピングも維持します。 

### ステップ

 1. 各幅からマッピングを初期化する$w_i$その行インデックスに$i$。 これにより、選択した幅を正しい出力行に変換できることが保証されます。 
2. 幅でキー設定された空の行の最小ヒープにすべての行を挿入します。 最初は、すべての行が空です。 
3. 半分が占有されている行に対して空の最大ヒープを維持します。 このヒープには、内向的な人が最初の席に着いた後の行が格納されます。 
4. 入力文字列から順に乗客を処理します。 
5. 現在の乗客が内向的な場合、空のヒープから最小幅の行を抽出します。 この行をパッセンジャーに割り当て、半分が占有されているヒープにプッシュします。 その理由は、この行は空ではなくなり、外向的な人に適格になるはずであるということです。 
6. 現在の乗客が外向的な場合は、半分が占有されているヒープから最大幅の行を抽出します。 両方の座席が埋まっているため、この行を乗客に割り当て、完全に削除します。 外向的な人は常に、部分的に埋められた行の中で最大の幅を好むため、選択ルールによって正確さが保証されます。 

### なぜ効果があるのか

 どの時点でも、すべての行は、完全に未使用、部分的に埋められている、完全に埋められているという 3 つの状態のいずれかに属します。 内向的ルールは未使用の行のみを操作し、外向的ルールは部分的に埋められた行のみを操作します。 ヒープにより、各ルールに従って最適な候補が常に利用可能になります。$O(1)$アクセス時間と取り外し可能$O(\log n)$。 行が状態間で逆方向に移動することはないため、プロセス全体を通じて構造の一貫性が保たれ、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    s = input().strip()

    import heapq

    # min-heap for empty rows: (width, row_index)
    empty = []
    # max-heap for half-occupied rows: (-width, row_index)
    half = []

    for i, wi in enumerate(w, 1):
        heapq.heappush(empty, (wi, i))

    res = []

    for c in s:
        if c == '0':
            wi, idx = heapq.heappop(empty)
            res.append(idx)
            heapq.heappush(half, (-wi, idx))
        else:
            wi_neg, idx = heapq.heappop(half)
            res.append(idx)

    print(*res)

if __name__ == "__main__":
    solve()
```空のヒープには、内向的な人がいつでも利用可能な最小の行を取得できるように、未使用の行がすべて幅順に並べ替えられて保存されます。 行が選択されると、Python の最小ヒープが最大ヒープのように動作するように、その行は幅が否定された状態で半分埋められたヒープに移動されます。 

ヒープが半分だけ埋められているため、外向的なユーザーは常に利用可能な行の中で最大幅の行を取得できます。 外向的な人が席に着くと、その列は満席になり、完全に撤去されます。 

重要な実装の詳細は、行が空のヒープに再挿入されることがなく、各行が半分埋まったヒープに 1 回だけ移動し、正しい状態遷移が保証されることです。

 ## 特殊なケース

 重要なエッジ ケースは、シーケンスの後半で、最小の空行が将来の半分埋まった行の中で最大になる場合です。 幅は個別であり、状態遷移は一方向であるため、アルゴリズムはヒープ間の競合を調整する必要がありません。 行が空のヒープを離れると、そこで再び競合することはありません。 

入力の場合:```
n = 2
w = [2, 1]
s = 0101
```段階的に:

 内向的な人は最初に行 2 (幅 1) を選択し、次に外向的な人はヒープの半分に応じて行 2 または 1 を選択する必要があります。 ヒープにより、行 2 が半分埋められた構造内に正しく配置されるため、外向的な動作は一貫したままになります。 

これにより、再計算ではなく状態分離によってシミュレーション全体を通じて正確さが保たれることが確認されました。
