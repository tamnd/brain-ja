 ## 解決策
 ## 問題の理解

 私たちには一列の椅子が与えられ、それぞれに人が座っているか、空になっています。 構成はバイナリ文字列として表されます。`1`人が座っていることを意味し、`0`席が空いていることを意味します。 

座席配置は、2 人が隣に座らない場合にのみ有効とみなされます。 さらに、有効性だけをチェックしているわけではありません。 また、構成がすでに「最大」になっているかどうかも判断する必要があります。つまり、占有されている椅子が 2 つ隣接してはいけないというルールを破らずに、空いている椅子に追加の人を配置する方法はありません。 

したがって、課題は座席を構築することではなく、2 つの特性を同時に検証することです。 まず、現在の配置が隣接ルールをすでに満たしている必要があります。 第二に、空席はすべて、既に占有されている少なくとも 1 人の隣席によって「ブロック」されなければならないため、そこに人を入れると直ちに規則に違反します。 

制約`n ≤ 1000`これは、O(n²) シミュレーションが引き続き成功することを意味しますが、それは不要です。 座席に関するすべての決定は、その隣の座席のみに依存するため、1 回のリニア スキャンで十分です。 

いくつかの特殊なケースは、一見したよりも重要です。 

文字列が`"0"`のために`n = 1`の場合、そこに人を配置してもルールを満たすことができるため、これは最大ではありません。 

文字列が`"1"`の場合、すでに人がいて追加の配置は不可能であるため、これは最大になります。 

見たら`"101"`、単一のゼロが 2 つの 1 に隣接しているため、これは有効かつ最大であり、誰もホストすることができません。 

見たら`"1001"`、これは有効ですが、中間であるため最大ではありません。`"00"`人を配置できる位置が少なくとも 1 つ含まれています。 

これらの例は、重要な微妙さを示しています。最大性とは、現在の構成のローカルな有効性だけではなく、有効な挿入の存在に関するものです。 

## アプローチ

 ブルートフォース戦略では、すべての空のポジションを試し、配置されているかどうかを確認します。`1`構成が有効に保たれます。 候補位置ごとに隣接するものをスキャンして、隣接関係が侵害されていないことを確認します。 いずれかの配置が機能する場合、構成は最大ではありません。 このアプローチは正しいですが、それぞれについて`n`スキャンできる位置`n`文字、O(n²) 動作を与えます。 

問題の構造により、より直接的な観察が可能になります。 座席は、隣接する位置が両方とも同じである場合にのみ使用できます。`0`(または境界に存在しません)。 したがって、構成は、すべての場合に正確に最大になります。`0`「ブロックされている」とは、少なくとも 1 つの隣接する位置がブロックされていることを意味します。`1`。 もし`0`隣接するものがありません`1`、それはすぐに有効な挿入ポイントになります。 

これにより、問題は、インデックスがこのブロック条件に違反しているかどうかを確認する 1 回のスキャンで済みます。

 ## アルゴリズムのチュートリアル

 文字列を一度スキャンして、人物を配置できる位置が存在するかどうかを確認します。 

1. すべてのインデックスを反復処理します。`i`文字列の中で。 

現在の場合、各ポジションは配置の候補になります。`0`。 
2. それぞれについて`0`、近隣をチェックしてください。 

配置は、左隣 (存在する場合) と右隣 (存在する場合) の両方が有効である場合に有効です。`0`。 
3. そのような位置が見つかった場合は、座席が最大ではないと直ちに結論付けることができます。 

これは、隣接ルールを維持する有効な挿入が明示的に見つかったためです。 
4. 文字列全体をスキャンした後にそのような位置が存在しない場合、構成は最大になります。 

### なぜ効果があるのか

 重要な特性は、人をその位置に配置することの妥当性です。`i`のみに依存する`i-1`そして`i+1`。 どちらかの隣人がいる場合、`1`、配置は禁止されています。 両方ともそうだった場合`0`(または範囲外)、配置は常に許可されます。 したがって、両方の近傍が空であるインデックスの存在は、非最大性と同等です。 スキャンでは、考えられるすべての挿入ポイントについて、この状態が正確にチェックされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

for i in range(n):
    if s[i] == '0':
        left_ok = (i == 0) or (s[i - 1] == '0')
        right_ok = (i == n - 1) or (s[i + 1] == '0')
        if left_ok and right_ok:
            print("No")
            sys.exit()

print("Yes")
```コードは文字列に対して 1 回のパスを実行します。 それぞれのゼロについて、両方の近傍もゼロであるか、境界に存在しないかをチェックします。 そのような位置が見つかった場合は、すぐに出力します`"No"`なぜなら、ルールを破ることなくそこに人を挿入できるからです。 それ以外の場合、ループは完了し、出力します。`"Yes"`。 

境界処理は明示的に行われます。`i = 0`または`i = n - 1`、行方不明の隣人を自動的に安全なものとして扱います。 これによりインデックス エラーが回避され、エッジには 2 つではなく 1 つの制約しかないという考えと一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    for i in range(n):
        if s[i] == '0':
            left_ok = (i == 0) or (s[i - 1] == '0')
            right_ok = (i == n - 1) or (s[i + 1] == '0')
            if left_ok and right_ok:
                return "No"
    return "Yes"

# provided samples
assert run("3\n101\n") == "Yes"

# minimum size, empty seat always improvable
assert run("1\n0\n") == "No"

# single occupied seat is maximal
assert run("1\n1\n") == "Yes"

# clear non-maximal case
assert run("3\n000\n") == "No"

# alternating pattern already maximal
assert run("5\n10101\n") == "Yes"

# boundary case with middle free space
assert run("4\n1001\n") == "Yes"

 ## 特殊なケース

 のために`n = 1`、入力を考慮します`"0"`。 アルゴリズムはインデックス 0 をチェックし、それが`0`、境界規則により、両方の近隣が安全なものとして扱われます。 すぐに挿入可能と判断して出力します。`"No"`。 

のために`"1"`、ループは決して`0`したがって、拒否がトリガーされることはなく、最終的な出力は次のようになります。`"Yes"`。 

のために`"1001"`、インデックス 1 と 2 が検査されます。 インデックス 1 の左側は`1`そのため、配置は失敗します。 インデックス 2 の右は`1`そのため、配置は失敗します。 空の隣接条件の両方を満たすインデックスがないため、アルゴリズムは正しく返します。`"Yes"`。
