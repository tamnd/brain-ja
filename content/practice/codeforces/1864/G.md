 ## 解決策
 ## 問題の理解

 サイズの正方形のボード 2 枚から始めます$n \times n$、それぞれに数字が含まれています$1$に$n^2$まさに一度。 各数字をラベル付きのタイルとして考えてください。 最初のボードはこれらのタイルの何らかの配置であり、それをターゲットの配置に変換したいと考えています。 

許可される移動は、単一行の右への循環シフトと、単一列の下方向への循環シフトのみです。 各行と列は最大 1 回シフトできますが、シフトはゼロ以外のモジュロ量で移動できます。$n$。 したがって、各行にはシフトがないか、オフセットによって 1 回の循環シフトがあり、列についても同様です。 

この複雑さは、各タイルの動きを追跡することから生まれます。 のタイル$(x,y)$最終的には次のようになります:$$(x', y') = (x + C_x,\; y + R_y) \pmod n$$どこ$C_x$はその行に適用されるシフトです (列の移動は垂直方向の変位に寄与します)。$R_y$はその列に適用されるシフトです。 

ただし、問題を根本的に変える追加の制約が 2 つあります。 まず、各タイルは最大 2 つの操作によって影響を受ける可能性があります。 第 2 に、2 回影響を受けるタイルは同じ正味変位ベクトルを共有してはなりません。 これにより、タイルの大きなグループが「二重シフト」で同じように移動することがなくなり、対称性の過剰カウントが発生することになります。 

タスクは、ターゲット グリッドを生成する行と列のシフトの個別のシーケンスの数を数えることです。 

この制約により、私たちはシミュレーションから遠ざかってしまいます。 すべての変換を保存したりテストしたりすることさえ不可能です。$n$最大 500 まで可能です。$2 \cdot 10^4$テスト ケース。グリッドの合計サイズは次のように制限されます。$2.5 \cdot 10^5$。 セルごとのバックトラッキングや行および列ごとのシフト割り当ての列挙を試みるアプローチは、組み合わせ的に爆発的に発生します。 

複数の行または列が独立して一貫したシフトを許容するが、それらを組み合わせるといくつかのセルで矛盾が生じる場合、微妙な故障モードが発生します。 もう 1 つのよくある落とし穴は、行シフトと列シフトが独立して解決できると想定していることです。 これらはすべてのセル方程式を通じて相互作用するため、ローカルな一貫性はグローバルな一貫性を意味しません。 

このような失敗の小さな例としては、シフト後に各行が個別にターゲットと一致し、各列も一貫しているように見えますが、交差するセルの暗黙のオフセットが一致しないケースが挙げられます。 単純な行単位の配置では、これが誤って受け入れられます。 

## アプローチ

 ブルート フォース ビューは、すべての行とすべての列にシフト値を割り当てようとし、すべてのセルが正しくマップされているかどうかを確認します。 これにより、問題はすでにチェックに限定されます$O(n^2)$割り当てごとの制約はありますが、割り当ての数は$n^{2n}$、それぞれなので$n$行と$n$列には$n$可能なシフト。 積極的にプルーニングしたとしても、検索スペースは指数関数的に増加します。$n$, なのでこれは使えません。 

重要な構造上の観察は、各タイルがちょうど 1 つの行シフトと 1 つの列シフトをリンクする制約を強制していることです。 値の初期位置の場合$v$は$(x_1, y_1)$そしてその目標位置は$(x_2, y_2)$、次に行の行シフト$x_1$とコラムのコラムシフト$y_1$は次のモジュラー方程式のペアを満たさなければなりません。$$C_{x_1} \equiv x_2 - x_1 \pmod n,\quad R_{y_1} \equiv y_2 - y_1 \pmod n$$したがって、各タイルは 2 つの変数に値を割り当てようとします。 これにより、グリッドが行シフト変数と列シフト変数の間の 2 部構成の整合性システムに変わります。 

「行/列ごとに最大 1 回」および「タイルごとに最大 2 回」に関する 2 番目の制約は、あいまいさを制限します。複数の矛盾する値を自由に割り当てることはできないため、制約に触れると各行または列に一意の強制シフトが適用されます。 

これにより、問題は、二部グラフを通じて制約を伝播し、一貫性をチェックし、シフトがまだ固定されていない連結成分をカウントするという問題に軽減されます。 各接続コンポーネントは、そのルート割り当てにどれだけ多くの一貫した選択肢が存在するかに応じて乗算係数に寄与します。 

1 つの行 (または列) のシフトを選択すると、そのコンポーネント内の他のすべてのシフトが決定されるため、カウントの側面が生じます。 有効なウェイの数は、周期的な制約を考慮して調整された、自由な選択が残るコンポーネントの数に対応します。

 ## アルゴリズムのチュートリアル

 1. 初期グリッドとターゲット グリッドで各数字の位置を見つけます。 

あらゆる価値観に対して$v$、 店$(x_1, y_1)$そして$(x_2, y_2)$。 これにより、1 つの行と 1 つの列に関連する直接制約が与えられます。 
2. 各タイルを行シフト変数と列シフト変数に関する 2 つの式に変換します。 

価値のために$v$、次のように導出されます。$$C_{x_1} \equiv x_2 - x_1,\quad R_{y_1} \equiv y_2 - y_1$$これらはモジュール式制約です。$[0, n-1]$。 
3. 行と列の制約グラフを作成します。 

各行ノードは、共有タイル ID を通じて列ノードに接続します。 これにより、あるシフトを割り当てると他のシフトが強制されるシステムが作成されます。 
4. BFS または DSU スタイルのマージを使用して固定値を伝播します。 

行にすでに決定されたシフトがあり、タイルが矛盾する値を課す場合、構成は直ちに拒否されます。 これにより、すべての制約にわたるグローバルな一貫性が確保されます。 
5. 制約グラフ内の連結成分を検出します。 

各コンポーネントは行と列のセットを表し、そのシフトは単一自由度まで相互に決定されます。 
6. コンポーネントごとに有効な割り当てをカウントします。 

コンポーネントに固定の開始点がない場合、コンポーネントは次の要因に寄与します。$n$なぜなら、巡回シフトはすべてベースとして機能し、残りを一意に決定できるからです。 部分的に修正されている場合、一貫性がある場合は 1 が寄与し、そうでない場合は 0 が寄与します。 
7. コンポーネント間の寄与を剰余で乗算する$998244353$。 

### なぜ効果があるのか

 すべてのタイルは、正確に 2 つの変数 (1 つの行シフトと 1 つの列シフト) 間の線形モジュラー関係を強制します。 システム全体が一連の等価制約になります。$\mathbb{Z}_n$。 このようなシステムは、各コンポーネントにランクがある連結コンポーネントに分解されます。$k-1$、つまり自由変数が 1 つ残ることになります。 このアルゴリズムは、この線形制約システムの解空間の次元を効果的に計算し、その自由度によって引き起こされるすべての有効な割り当てをカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    
    pos_a = {}
    pos_b = {}
    
    for i in range(n):
        row = list(map(int, input().split()))
        for j, v in enumerate(row):
            pos_a[v] = (i, j)
    
    for i in range(n):
        row = list(map(int, input().split()))
        for j, v in enumerate(row):
            pos_b[v] = (i, j)
    
    row_shift = [None] * n
    col_shift = [None] * n
    
    adj_r = [[] for _ in range(n)]
    adj_c = [[] for _ in range(n)]
    
    # build constraints
    for v in range(1, n * n + 1):
        x1, y1 = pos_a[v]
        x2, y2 = pos_b[v]
        
        dr = (y2 - y1) % n
        dc = (x2 - x1) % n
        
        adj_r[x1].append((y1, dr))
        adj_c[y1].append((x1, dc))
    
    from collections import deque
    
    def bfs_r(start):
        q = deque([start])
        while q:
            r = q.popleft()
            for c, val in adj_r[r]:
                if col_shift[c] is None:
                    col_shift[c] = val
                    q.append(c)
                elif col_shift[c] != val:
                    return False
        return True
    
    def bfs_c(start):
        q = deque([start])
        while q:
            c = q.popleft()
            for r, val in adj_c[c]:
                if row_shift[r] is None:
                    row_shift[r] = val
                    q.append(r)
                elif row_shift[r] != val:
                    return False
        return True
    
    ans = 1
    
    for i in range(n):
        if row_shift[i] is None:
            row_shift[i] = 0
            if not bfs_r(i):
                print(0)
                return
            ans = (ans * n) % MOD
    
    for j in range(n):
        if col_shift[j] is None:
            col_shift[j] = 0
            if not bfs_c(j):
                print(0)
                return
            ans = (ans * n) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()

微妙な点は、新しいコンポーネントを開始するときに任意のシフトを 0 に初期化することです。 コンポーネント内では相対的な差異のみが問題となるため、これは正確さには影響しません。 絶対参照は乗算に寄与します。$n$要素。

 ## 特殊なケース

 重要なエッジ ケースは、すべての制約が単一の連結コンポーネントを形成しているが、行や列が最初に固定されていない場合に発生します。 この状況では、BFS は任意のゼロ シフトを割り当てることから開始し、その後、他のすべてを伝播します。 見かけの恣意性は、実際の自由度に対応します。どの開始シフトを選択しても、有効なグローバル構成が生成され、すべての$n$選択肢は明確です。 

もう 1 つのエッジ ケースは、2 つの異なるタイルが同じ行または列の制約を課すが、暗黙のオフセットが異なる場合です。 BFS は、競合する値を持つノードを再訪問するとこれを即座に検出し、アルゴリズムは完全な伝播を必要とせずにインスタンスを正しく拒否します。 

3 番目のケースは、グリッドが複数の接続されていないコンポーネントに分解される場合です。 各コンポーネントは独立して参照シフトを自由に選択できるため、ソリューションの総数はコンポーネント間で増加します。
