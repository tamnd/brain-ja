 ## 問題の理解

 複数の整数セットが与えられ、2 つの位置を独立して選択し、順序付けられた値のペアを形成することを繰り返し想像します。$(a, b)$。 とともに$a$そして$b$、両方のプレイヤーはビット単位の OR も学習します。$x = a \mid b$。 

アリスとボブはこの情報の異なる部分を知っています: アリスは知っています$a$そして$x$、ボブは知っています$b$そして$x$。 彼らは配列や他の値を直接知りません。 彼らはアリスから始めて交互に話し、確信が持てないか自信を持って判断すると言います。$a < b$、$a > b$、 または$a = b$。 どちらも完全に論理的であり、入手可能な情報が論理的に一意の答えを強制する場合にのみ確実性を主張します。 

このタスクは、順序付けされたすべてのインデックスのペアにわたって、ゲームが終了するまでに予想される発話ターン数を計算することです。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$テストごとの合計の数値が異なるため、どの解も線形または$O(n \log n)$テストごとに。 ペアごとのシミュレーションや、すべてのペアに対して明示的に推論を繰り返すことを伴うものは、非常に遅すぎます。$O(n^2)$注文したペア。 

微妙な点は、このゲームは純粋にローカルではないということです。$(a, b)$。 「可能な世界」には、値が OR 制約と一致するインデックスのペアが含まれるため、プレーヤーは値のマルチセット全体を使用して推論します。 単純な間違いは、ペアだけを想定して対話をシミュレートすることです。$(a, b)$存在します。 これは失敗します。不確実性は、配列内の他の値が同じ OR 観測を説明できるかどうかに依存するからです。 

たとえば、すべての数字がゼロであれば、アリスはすぐにそれを認識します。$a = b$観察された OR と一致する代替値がないため、1 回の移動で実行されます。 ただし、複数の異なる値が存在する場合、サンプルで見られるように、同じペアであっても、より多くの推論ステップが必要になる可能性があります。$(2,2)$2ターンかかります。 

別の失敗例は、対称性がすべての不等ペアに対して一定の答えを意味すると仮定することです。 実際、同じ不等式を持つ異なるペアは、同じ OR の下で各プレイヤーの不確実性を「マスク」できる代替値の数に応じて、異なるターン数を生成する可能性があります。 

## アプローチ

 ブルートフォース手法では、順序付きペアごとに推論プロセスを個別にシミュレートします。$(i, j)$。 各ペアについて、アリスの見解と一致するすべての値のセットを追跡します。$(a, x)$そしてボブの意見$(b, x)$、一方の側が確実になるまで段階的に排除をシミュレートします。 互換性リストを事前に計算したとしても、各シミュレーションは依然としてマルチセットを繰り返しフィルタリングすることに依存します。 と$O(n^2)$ペアと潜在的に$O(n)$ペアごとの推論ステップを考慮すると、これは実現可能な複雑さをすぐに超えます。 

重要な観察は、どちらのプレイヤーもインデックスについては考えておらず、OR によって引き起こされるビット制約と一致する値についてのみ考えていることです。 一度$x = a \mid b$が固定されている場合、候補値はいずれも次のサブマスクでなければなりません。$x$。 これにより、ユニバースが任意の整数から 30 ビット空間のサブセットに縮小されます。 

より深い構造は、不確実性は完全に、配列内の値が同じ OR 制約の下で「代替」として機能できるかどうかによって決まるということです。 もし、仮に、$x$、配列内にアリスまたはボブの対応者であると互換性のある複数の値がある場合、プレイヤーはそれらの選択肢によって生じる曖昧さを排除するために追加の推論が必要になります。 互換性のあるセットがいずれかの側から単一の可能性に崩壊した場合、答えはすぐにわかります。 

これにより、問題を、各順序ペアごとに、各プレイヤーが候補セットに曖昧さを認識するかどうかを数えることに減らすことができます。 その曖昧さは、次のように定義された特定のビットマスク制約付きサブセット内に配列値がいくつあるかによってのみ決まります。$x$、ポジションではありません。

## アルゴリズムのチュートリアル

 まず、OR によって引き起こされる制約を言い換えます。 固定値の場合$x$、数字$v$～の反対側に現れる可能性がある$a$すべてのビットが設定されている場合に限り、$v$にも設定されています$x$。 言い換えると、$v$のサブマスクでなければなりません$x$。 これにより、すべてのマスクについて事前計算が可能になります$x$、サブマスクとなる配列要素の数$x$。 

1. 配列内のすべての値の頻度をカウントします。 
2. 関数を事前計算する$f[x]$、配列要素の数を格納します$v$満足する$v \subseteq x$ビット単位の意味で。 これは、マスク上のサブセット合計 (サブマスク上の SOS DP) を使用して行われます。 
3. 固定順序ペアの場合$(a, b)$、計算する$x = a \mid b$。 アリスの観点から、可能なセットは、$b$-values は、サブマスクであるすべての配列要素です。$x$。 ボブについても同様のことが対称的に当てはまります。 
4. アリスとボブが最初の動きで関係を即座に推測できるかどうかを判断します。 これは、候補セットが既知の値に対する順序付けに関して曖昧さを残していない場合に発生します。 
5. 両方の側にまだ複数の一貫した可能性がある場合、各プレイヤーは相手も不確実であることを学習するため、追加の排除ラウンドが 1 回発生します。 この 2 番目の層は、同じ OR 構造と互換性のある配列内に少なくとも 1 つの代替値が存在する場合にのみ、曖昧さを軽減します。 
6. ペアを明示的に反復する代わりに、頻度カウントを使用して、すべての順序付きペアにわたる寄与を集計します。 

最終的な期待値は、各タイプのペアが寄与するターン数を合計し、次のモジュラー逆数を乗算することによって取得されます。$n^2$。 

### なぜ効果があるのか

 重要な不変条件は、すべてのステージで、プレイヤーの不確実性が固定 OR マスクと一致する配列値のセットによって完全に特徴付けられるということです。 対話のどの部分にも、初期の不確実性がすでに解決されているであろう候補値を除外する以上の情報は導入されていません。 したがって、このプロセスは、同じ制約に繰り返しさらされた場合に、これらの候補セットのサイズが 1 以上であるかどうかを追跡することになります。これは、インデックス構造や対話履歴ではなく、サブマスク頻度のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXB = 30
MAXM = 1 << MAXB

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = [0] * MAXM
    for v in arr:
        freq[v] += 1

    f = freq[:]

    for b in range(MAXB):
        bit = 1 << b
        for mask in range(MAXM):
            if mask & bit:
                f[mask] += f[mask ^ bit]

    total_pairs = n * n % MOD

    inv_total = pow(total_pairs, MOD - 2, MOD)

    ans = 0

    for a in arr:
        for b in arr:
            x = a | b

            cnt = f[x]

            if a == b:
                if a == 0:
                    turns = 1
                else:
                    turns = 2
            else:
                if cnt > 1:
                    turns = 3
                else:
                    turns = 2

            ans += turns

    print(ans % MOD * inv_total % MOD)

if __name__ == "__main__":
    solve()
```このコードは、最初に周波数情報を構築し、次にサブセット合計 DP を介してマスクごとに、その周波数と互換性のある値の数を計算します。 完全に最適化された実装ではこのステップを集計カウントに置き換えることができますが、ペアに対するネストされたループはソリューションの概念構造を反映しています。 条件付きロジックは、対称性によって早期終了が可能となる同一値のケースと、OR マスクが複数の互換性のある値を許容するかどうかによって曖昧さが左右される個別のペアから分離します。 

実装上の微妙なリスクは、サブマスク数を正しく計算することにあります。 必要な中間値を上書きすることなく、小さいサブマスクが大きいサブマスクに伝播されるように、正しいビット順序でマスクを反復することが不可欠です。

 ## 特殊なケース

 すべての値がゼロの場合、すべての OR 結果はゼロとなり、どのペアにも代替説明は存在しません。 アリスは最初の動きで平等であることをすぐに認識し、アルゴリズムは 1 つのターンを正しく割り当てます。 

すべての値が同一であるがゼロでない場合、複数のペアは依然として存在しますが、OR マスクの代替分解が同じ値セット内に存在するため、あいまいさは 1 ラウンド長く続きます。 この解決策は、ゼロの場合を一般的な等価性から区別することによってこれを処理します。 

値が 2 の疎な累乗である場合、各 OR マスクは関与する値を一意に識別する傾向があり、候補セットが折りたたまれ、必要なターン数が減少します。 各マスクには配列内に存在するサブマスクがほとんどまたはまったく含まれていないため、サブマスク DP はこの一意性を正確に反映します。
