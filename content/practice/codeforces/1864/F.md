 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`長さの`n`。 クエリごとに`(l, r)`のすべての数値をゼロにする必要があります。`a`それは範囲内にあります`[l, r]`一連の減算演算を使用します。 各操作では、次の連続セグメントが選択されます。`a`そして、そのセグメント内のすべての要素から同じ非負の値を減算します。 唯一の制限は、2 つのセグメントが部分的に重なってはいけないことです。一方が他方の中に完全に含まれているか、互いに素になっているかのどちらかです。 

出力は、各クエリに必要なそのような操作の最小数です。 各クエリは独立しているため、クエリ間で配列をリセットできます。 

ここでの主な課題は、ゼロにしたい値の範囲制限とセグメントのネスト/非結合制約の組み合わせから生じます。 すべてのセグメントを考慮する単純なアプローチでは、複雑さが爆発的に増大します。 

制約を見てみると、`n`そして`q`それぞれ最大で可能です`10^6`。 これは、これよりも悪いアルゴリズムは存在しないことを意味します。`O(n log n)`クエリごとにほぼ確実にタイムアウトになります。 したがって、考えられるすべてのセグメントを試したり、すべての減算をシミュレートしたりするような単純な方法は実行できません。 

ゼロ化される要素がまばらであるか、ターゲット範囲外の要素がインターリーブされている場合、明白ではないエッジ ケースが発生します。 たとえば、配列を考えてみましょう`[1, 3, 1, 3, 1]`そしてクエリ`[3, 3]`。 不注意なアプローチでは、配列全体を 1 つのセグメントとして取り込み、減算しようとする可能性があります。`3`、これにより、`1`s. 正しいアプローチでは、素/ネストのルールを尊重し、ターゲット値の連続するブロックごとに最小限の分離された操作をカウントする必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのクエリを反復処理し、すべての位置を特定します。`i`そのような`a[i] ∈ [l, r]`、これらの位置を有効なネストされた/互いに素なセグメントで貪欲にカバーしようとします。 最も単純な貪欲な場合は、関連する要素の最大の連続セグメントを取得し、セグメント内の最小値を減算し、残りを再帰的に試みます。 最悪の場合、長さの配列の場合`n`交互の値を使用して`[l, r]`そして外部では、これには必要な場合があります`O(n^2)`クエリごとの操作。 と`n = 10^6`そして`q = 10^6`、これは絶望的です。 

線形解の鍵を握る重要な観察は、問題が要素の**連続したブロックの数を数えることに帰着するということです。`[l, r]`** ただし、巧妙に入れ子になっています。 再帰的に考えると、配列の任意のセグメントについて、ゼロにする必要があるセグメントのうちの最小値を 1 回の操作で減算できます。 次に、問題は、この減算によって導入されたゼロ間の独立したセグメントに分割されます。 これは、セグメント ツリーベースの区間 DP 問題で使用される手法と同様の、**連続ブロックに対する分割統治**とまったく同じです。 

もう 1 つの洞察は、ネスト/素のルールにより、不正な重複を気にせずに、連続するターゲット要素のブロック内の最小値を常に減算し、残差を再帰的に処理できることです。 これは、最小値を減算した後に残った正の値が小さな連続セグメントを形成し、これらのセグメントが元のセグメント内に自然にネストされるためです。 

したがって、最終的な解決策は、配列を反復処理し、要素のシーケンスを処理することによって機能します。`[l, r]`「セグメント」として、それらの最小値を減算し、ゼロで分割されたセグメントに対する操作を再帰的にカウントします。 これは、クエリごとに 1 回配列をスキャンすることで効率的に実装できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | O(n) | 遅すぎる |
 | 最適 | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 特定のクエリの場合`(l, r)`、配列をフィルタリングされた配列に変換します`b`外側の要素`[l, r]`なる`0`内部の要素は変更されません。 これにより、関連する値のみに焦点を当てることができます。 
2. 再帰関数を定義する`solve_segment(start, end)`ゼロにするために必要な最小限の操作数を計算します。`b[start:end]`。 
3. 内部`solve_segment`、セグメント長がゼロの場合は 0 を返します。それ以外の場合は find`min_val`セグメントの。 1回の操作で引き算ができる`min_val`セグメント全体から。 
4. 引き算後`min_val`、セグメントをゼロで分割して、独立した連続ブロックを作成します。 各ブロックは新しいサブ問題を形成します。 各サブブロックを再帰的に解いた結果を合計し、加算します。`min_val`(このレベルで適用される操作)。 
5. 合計を最小操作数として返します。 
6. 申請する`solve_segment(0, n)`配列全体でクエリの答えを取得します。 

**機能する理由:** 各レベルで、最小値を減算することは、入れ子/素のルールに違反しないため、安全です。 各再帰呼び出しは、完全に含まれている (ネストされている) か、または互いに素な、より小さい連続ブロックを処理します。 どの解法でもある時点でセグメントの少なくとも最小値を減算する必要があるため、再帰では当然許可された操作が尊重され、最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve_query(a, l, r):
    n = len(a)
    b = [x if l <= x <= r else 0 for x in a]

    def solve_segment(start, end):
        if start >= end:
            return 0
        i = start
        while i < end and b[i] == 0:
            i += 1
        if i == end:
            return 0
        j = i
        while j < end and b[j] != 0:
            j += 1
        min_val = min(b[i:j])
        # Subtract min_val
        for k in range(i, j):
            b[k] -= min_val
        # Recursively solve sub-blocks split by zeros
        ops = min_val
        k = i
        while k < j:
            if b[k] != 0:
                start_block = k
                while k < j and b[k] != 0:
                    k += 1
                ops += solve_segment(start_block, k)
            else:
                k += 1
        return ops

    return solve_segment(0, n)

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    queries = [tuple(map(int, input().split())) for _ in range(q)]
    for l, r in queries:
        print(solve_query(a, l, r))

if __name__ == "__main__":
    main()
```コードは、範囲内の要素の連続ブロックを慎重に処理します。`[l, r]`そして最小の減算を再帰的に適用し、ゼロで分割します。 再帰の深さの制限は次のとおりです。`n`なぜなら、再帰呼び出しごとに少なくとも 1 つの非ゼロ要素が減り、増加するからです。`sys.setrecursionlimit`Python の再帰制限を回避するため。
