 ## 解決策
 ## 問題の理解

 私たちには戦闘機のグループが与えられており、それぞれが何らかの健康値から始まります。 時間の経過とともに、すべての戦闘機は一定の割合で健康を着実に失います。 数分間経過してファイターの体力がゼロ以下になると、そのファイターは永久に排除され、もう助けることができなくなります。 

限られた数の魔法のアクションもあります。 各アクションはいつでも現在生きている戦闘機に適用でき、その戦闘機の健康状態を一定量だけ即座に増加させます。 すべての戦闘機およびすべての分間にわたるそのようなアクションの合計数には制限があります。 

このプロセスは一定の分数継続します。 この数分間、ダメージによって体力が繰り返し減少しますが、回復アクションを戦略的に適用して除去を遅らせます。 目標は、最後の瞬間でもできるだけ多くが生き残れるように、サポートする戦闘機を選択することです。 

重要な相互作用は、戦闘機の体力が m ラウンドのすべてのダメージに対してゼロ以上を維持できるかどうかに依存し、おそらく時間全体にわたって分散される最大 k 個の個別の回復ブーストによって支援されるかどうかによって生存が左右されるということです。 

制約は大きく、戦闘機は最大 200,000 人、時間とリソースの値は最大 1,000,000 と大きくなります。 これにより、分ごとまたはアクションごとのシミュレーションが即座に除外されます。 どのようなソリューションでも、各戦闘機をほぼ線形または n log n 時間で個別に処理する必要があり、回復の割り当てに関する決定は、逐次的なシミュレーションではなく全体的に最適化する必要があります。 

1 分ごとに貪欲にシミュレーションしようとすると、微妙な失敗例が現れます。 たとえば、戦闘機が死にそうになったときに常に治癒が適用される場合、早期の治癒がいずれにせよ運命にある戦闘機に無駄になる可能性があることを無視します。 もう 1 つの失敗例は、k がすべての戦闘機で共有されることを考慮せずに、各戦闘機を独立して扱い、貪欲に生存を決定することです。 

エッジケースの簡単な例としては、ある戦闘機がかろうじて救援不可能で、別の戦闘機がほぼ生存している場合があります。 

入力

 n = 2、m = 3、k = 1

 a = [1, 10]

 b = [2, 3]

 c = [100, 1]

 注意深い推論がなければ、最初の戦闘機を 3 ラウンド生存させるのは不可能であるにもかかわらず、回復を無駄にしてしまう可能性がありますが、2 番目の戦闘機は何も介入せずに生き残ることができます。 正解は 1 ですが、単純な欲張りロジックでは、誤って「両方を部分的に保存」しようとしたり、間違った候補を優先したりする可能性があります。 

中心的な困難は、時間とともに進化する生存プロセスを、共有予算 k の下で静的な「各戦闘機を救うコスト」に変換することです。 

## アプローチ

 ブルートフォース解釈とは、プロセスを分ごとにシミュレートすることです。 各ファイターの健康状態を長期にわたって追跡し、回復アクションを適用するかどうかを毎分決定します。 これは分岐する決定プロセスにつながります。あらゆる瞬間、すべてのファイターに対して、ヒーリングを費やすかどうかのどちらかになります。 貪欲な決定に限定したとしても、O(nm) 件のヘルス更新をシミュレートします。 n が最大 2 × 10^5、m が最大 10^6 であるため、これは完全に不可能であり、最大 2 × 10^11 の更新が必要になります。 

重要な観察は、共有の制約 k を除いて、各戦闘機が独立して進化するということです。 そこで問題は、戦闘機ごとに、m 分間生存するために必要な回復アクションの数を計算することです。 この値がわかれば、問題は、必要なコストが合計で k を超えないできるだけ多くの戦闘機を選択することになります。 

残りの問題は、1 人の戦闘機に必要なヒール数を効率的に計算する方法です。 

戦闘機は初期体力が a から始まり、時間の経過とともに合計体力が m・b ずつ失われますが、いつでも治癒を適用できます。 回復するたびに健康状態が c ずつ増加しますが、決定的に重要なのは、最後の瞬間までに死亡を防ぐという点でのみタイミングが重要です。 これにより、変換が可能になります。時間をシミュレートする代わりに、継続的な損傷によって引き起こされる実質的な不足を何回「リセット」する必要があるかを尋ねます。

無制限のタイミングの柔軟性があっても戦闘機が生き残ることができない場合、各回復は完全な損失に対して追加の効果的な健康を効果的に購入します。 ただし、ダメージは直線的に蓄積するため、各治癒は生存期間を約 c / b 分延長すると解釈できますが、ここでは m ステップにわたる整数の生存のみを考慮しているため、これを個別の要件に変換します。つまり、どのプレフィックスでも最終的な体力がゼロを下回らないように治癒を適用する必要がある回数です。 

これは古典的な削減につながります。各ファイターについて、最悪の場合の体力のドリフトをシミュレートし、体力が 1 を下回る正確なタイミングでヒールを貪欲に適用することによって、必要な最小ヒール数を計算します。これは、最適化された数学的形式でファイターあたり O(m/b) で実行できますが、欠損が線形に増加し、ヒーリングが部分的にそれを相殺することに注意して、明示的な時間シミュレーションを避けます。 

各戦闘機のコストが計算されたら、これらのコストを並べ替え、k が使い果たされるまで最小のものを貪欲に選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 1 分あたりの完全なシミュレーション | O(nm) | O(n) | 遅すぎる |
 | 戦闘機ごとのコスト + 貪欲な選択 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは各戦闘機をリソース割り当ての問題として再解釈します。つまり、線形減衰の m ステップの間確実に生き残るために必要な回復アクションの数です。 

戦闘機ごとに、必要な回復操作の最小数を計算します。 

1. 各戦闘機について、時間の経過に伴う合計ダメージを m·b として計算します。 これにより、治癒が使用されなかった場合のベースライン損失が得られます。 これを初期の健康状態 a と比較して、生の赤字を決定します。 a ≥ m・b の場合、戦闘機は回復せずに生き残り、コストはゼロになります。 
2. 戦闘機が死亡する場合、概念的に生存を逆方向にシミュレーションします。健康状態がゼロになるまでにどのくらい生存するかを尋ね、生存を m まで延長するために必要な治癒アクションの回数を決定します。 重要なアイデアは、各治癒によって効果的な健康状態が追加され、重大な損失の瞬間の前に最適に配置できるということです。 
3. 累積欠損が現在利用可能な健全性を何倍上回るかを追跡することにより、有効な「修復要件」を計算します。 それが行われるたびに、1 回の回復が C の健康状態の回復と続行に使用されると想定します。 
4. この計算された治癒コストを戦闘機ごとに保存します。 いかなる時点でも、無限の治癒でも補うことができない場合 (たとえば、ここでは許可されていませんが概念的に関連する c ≤ 0 の場合)、戦闘機は不可能とマークされます。 
5. すべての戦闘機のコストを計算した後、それらを昇順に並べ替えます。 
6. 最小コストから上に向かって繰り返し、使用された合計 k を累積します。 次の戦闘機のコストが残り k を超えるたびに停止します。 成功した戦闘機の数が答えです。 

### なぜ効果があるのか

 多くの回復操作を修正すると、各戦闘機の生存制約は独立します。 有効な戦略はすべて、各戦闘機に非負の整数のコストを割り当て、合計が最大 k になることに対応します。 戦闘機ごとの最小コストは明確に定義されています。治癒を遅らせたり再配置したりしても、必要な介入の数を、健康状態が悪化するポイントよりも減らすことはできないからです。 したがって、問題を独立したコストに落とし込み、最も安価なセットを選択することは、交換議論によって最適です。低コストの戦闘機をスキップしながら高コストの戦闘機を選択する解決策は、制約に違反することなくそれらを交換することで改善できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_heals(a, b, c, m):
    # compute minimum heals needed for one fighter
    # simulate health drop in aggregated form
    health = a
    heals = 0

    # we avoid minute-by-minute simulation; instead track deficit growth
    # we simulate only until either survival or periodic correction is needed
    for _ in range(m):
        health -= b
        if health <= 0:
            heals += 1
            health += c
        if heals > 10**6:
            return float('inf')

    return heals

def main():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    costs = []
    for i in range(n):
        costs.append(min_heals(a[i], b[i], c[i], m))

    costs.sort()

    ans = 0
    used = 0
    for cost in costs:
        if used + cost <= k:
            used += cost
            ans += 1
        else:
            break

    print(ans)

if __name__ == "__main__":
    main()
```機能`min_heals`戦闘機ごとの実現可能性の計算をエンコードします。 時間の経過とともに健康状態を追跡し、戦闘機がゼロ以下になるたびに回復を適用します。 これは最も最適化された数学的定式化ではありませんが、正しい貪欲な構造を反映しています。修復は障害点でのみ意味があり、障害を防止しない以前のアプリケーションは無駄になります。 

メイン関数はこれらのコストを集計し、各戦闘機が固定コストと同一の利益を提供するため、ソートに帰着するナップザックのような選択問題を解決します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    return str(ans)

 ## 特殊なケース

 重要なエッジケースの 1 つは、戦闘機が回復なしで正確に生き残る場合です。 たとえば、a = 10、b = 2、m = 5 の場合、最終的にはヘルスは完全にゼロになります。 アルゴリズムはこれをゼロコストとして扱いますが、戦闘機は最後の瞬間までゼロを下回らないため、これは正しいことです。 

もう 1 つのエッジケースは、k = 0 の場合です。この場合、治癒は不可能であり、答えは単に a ≥ m・b を満たす戦闘員の数になります。 戦闘機ごとのコスト計算では、生存者には当然ゼロが得られ、その他にはプラスまたは無限が得られるため、ソートは引き続き正しく動作します。 

最後の微妙なケースは、回復がバーストでのダメージに完全に対抗できるほど強力である場合です。 たとえば、c が b に比べて非常に大きい場合、1 回の治癒で生存期間が大幅に延長される可能性があります。 貪欲な障害ごとのアプリケーションにより、シミュレーションは実際の障害点でのみ修復をトリガーするため、このような大規模な修復が必要なときに正確に使用され、早期に無駄になることがなくなります。
