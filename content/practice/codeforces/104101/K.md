 ## 解決策
 ## 問題の理解

 常に開始整数に適用されるビット単位の演算の固定シーケンスが与えられます。 開始値は指定されていません。 代わりに、それを自由に選択できますが、ゼロからある制限までの範囲内になければなりません`r`。 この初期値を選択した後、システムは同じ一連の操作をそれに適用し、最終値を生成します。 

各演算は、定数との AND、定数との OR、定数との XOR の 3 つのビット単位変換のいずれかを使用して、現在の数値に影響を与えます。 シーケンスはすべてのクエリで固定されていますが、クエリごとに異なる上限が与えられます。`r`、初期値を選択する必要があります`x ≤ r`すべての操作後の最終結果を最大化します。 

重要な問題は、最終値を単純な関数として直接最適化していないことです。`x`算術形式で。 代わりに、関数はビット単位の演算から構築されており、変換は次のバイナリ構造に依存します。`x`。 

この制約では、最大約 2^30 の値で、最大 200,000 の操作と 200,000 のクエリが許可されます。 これにより、可能なすべてのクエリごとのシミュレーションが即座に除外されます。`x`というのは、各クエリのすべての候補をチェックするだけでも実現可能な限界をはるかに超えてしまうからです。 ビットに対するクエリごとの動的シミュレーションでも、次への線形依存を回避する必要があります。`n`が鈍くなるにもほどがあります。 

単純なアプローチでは、各クエリを個別に試行し、それぞれの可能なクエリがどのように実行されるかを再計算します。`x`で`[0, r]`完全な操作シーケンスの後に動作します。 単一のクエリの場合、すべてを列挙しても`x`まで`r`コストは最大 2^30 の可能性がありますが、これは完全に不可能です。 前処理を行わずにクエリごとのビット単位の DP に制限しても、すべてのクエリにわたって依然として遅すぎます。 

より微妙な失敗例は、変換が単調であると仮定することから生じます。`x`。 たとえば、AND 演算はビットを破壊でき、OR 演算はビットを強制的にオンにし、XOR はビットを反転できます。 小さな変化`x`出力に非ローカルな変更が生じる可能性があるため、貪欲な推論は`x`数値はビットレベルの動作に落とし込まない限り信頼できません。 

## アプローチ

 ブルートフォースの観点は、固定の初期値について観察することから始まります。`x`、一連の操作全体をシミュレートし、結果の値を計算できます。`y`。 このシミュレーションでは、各ステップが 1 回のビット単位の演算で現在の値を変更するため、演算回数が直線的にかかります。 これを可能な限り繰り返すと`x`で`[0, r]`の場合、クエリごとに最大 2^30 の候補を評価する必要があり、それぞれのコストは O(n) ですが、これは制限をはるかに超えています。 

重要な構造の単純化は、問題をビットごとに分離することで実現します。 AND、OR、XOR はビットを混合しないため、各演算は数値の各ビットに対して独立して動作します。 これは、完全なシーケンスの後で、単一の入力ビットが対応する出力ビットにどのような影響を与えるかを追跡できることを意味します。 

このビットごとの変換を理解すると、関数全体が独立したビット関数の集合になります。 各出力ビットは 1 つの入力ビットのみに依存し、その入力ビットが 0 または 1 のときに何が起こるかによって完全に説明できます。 これにより、問題はどのビットを決定するかという問題に分解されます。`x`制約を尊重しながら設定する`x ≤ r`。 

その時点で、タスクは、入力に各ビットを設定することがどれほど有益であるかから導出された重みを使用したビットに対する制約付きの最適化になります。 残りの困難は、制約があることです。`x ≤ r`プレフィックス条件を通じてビットを結合します。これにより、バイナリ表現に対して数字 DP スタイルの推論が強制されます。

 ## アルゴリズムのチュートリアル

 この解決策は、すべての演算の効果をビットごとの変換に集約することから始まります。 

1. 各ビット位置について、最後のビットが最初のビットにどのように依存するかを計算します。 ビットごとに 2 つの値を維持します。入力ビットが 0 の場合に出力ビットが何になるか、入力ビットが 1 の場合にどうなるかです。これを恒等として初期化します。これは、入力 0 が出力 0 を与え、入力 1 が出力 1 を与えることを意味します。各演算は、その演算の定数マスクを使用して、ビットごとにこれら 2 つの状態を独立して更新します。 
2. すべての演算を処理した後、各ビットは入力ビットから出力ビットへの固定マッピングを持ちます。 これは、最終的な答えは、最初の数値のビットを選択することによって完全に決定されることを意味します。 
3. 最終値をビットの合計として書き換えます。 各ビットごとに入力ビットを設定`i`ビットが 0 の場合はベースライン値に寄与し、ビットが 1 に設定されている場合は追加のゲインに寄与します。これにより、問題は線形ビット重み関数の最大化に変わります。 
4. 次に制約を組み込みます`x ≤ r`。 最上位ビットから最下位ビットまで処理し、次のプレフィックスと一致するかどうかを決定します。`r`またはそれを下回ります。 これは、数字 DP スタイルのアイデアを使用して処理されます。`r`プレフィックスを小さくして将来のビットを解放する選択と比較します。 
5. 各ビットで、ビットを 1 に設定するか 0 に設定する方がより良い合計値が得られるかを評価します。`r`または、残りのビットが重みに基づいて貪欲に選択できる自由状態に移行します。 
6. 各ビットでの決定を一定時間内に行えるように、自由状態のサフィックスの最適な値を事前に計算します。 

### なぜ効果があるのか

 この正しさは、前処理後、入力の各ビットが独立して出力に寄与し、異なる入力ビット間に依存関係を作成する操作がないという事実から得られます。 これにより、システムは重み付きバイナリ文字列最適化問題に帰着します。 digit-DP 構造により、すべての有効な数値が`x ≤ r`は、構築されたプレフィックスが次のプレフィックス以下であるかどうかを追跡することによって暗黙的に考慮されます。`r`。 残りのすべての決定は自由状態の接尾辞の重みのみに依存するため、すべての値を明示的に列挙することなく、検索空間内のすべての分岐が考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 30

n, q = map(int, input().split())
ops = [tuple(map(int, input().split())) for _ in range(n)]

# f0[i], f1[i]: final bit i when input bit is 0 / 1
f0 = [0] * MAXB
f1 = [1] * MAXB

for t, a in ops:
    for i in range(MAXB):
        ai = (a >> i) & 1
        if t == 1:
            f0[i] = f0[i] & ai
            f1[i] = f1[i] & ai
        elif t == 2:
            f0[i] = f0[i] | ai
            f1[i] = f1[i] | ai
        else:
            f0[i] = f0[i] ^ ai
            f1[i] = f1[i] ^ ai

base = [f0[i] for i in range(MAXB)]
gain = [f1[i] - f0[i] for i in range(MAXB)]

# precompute suffix best for free state
best_free = [0] * (MAXB + 1)
for i in range(MAXB - 1, -1, -1):
    best_free[i] = best_free[i + 1] + max(0, gain[i])

def solve(r):
    rbits = [(r >> i) & 1 for i in range(MAXB)]
    
    # tight DP suffix: best possible from i..end when prefix still tight
    # we compute it on the fly with memoized recursion via iteration
    # dp_tight[i][tight_prefix_value handled implicitly by rbits]
    
    ans = 0
    tight = True
    prefix_value = 0
    
    for i in range(MAXB - 1, -1, -1):
        rb = rbits[i]
        
        if not tight:
            ans += base[i] + max(0, gain[i])
            continue
        
        # try x_i = 0
        val0 = base[i] + best_free[i + 1]
        
        # try x_i = 1 (only if allowed)
        if rb == 1:
            val1 = base[i] + gain[i] + best_free[i + 1]
            if val1 >= val0:
                ans += base[i] + gain[i]
            else:
                ans += base[i]
                tight = False
        else:
            ans += base[i]
    
    return ans

for _ in range(q):
    r = int(input())
    print(solve(r))
```前処理ステップでは、入力ビットが 0 または 1 のときに出力がどのようになるかをビットごとに個別に追跡することで、ビットごとの変換を構築します。 これにより、操作シーケンス中のビット間の相互作用が回避されます。 

の`gain`配列は、特定の入力ビットを 0 ではなく 1 に設定することによって得られるメリットを表します。 の`best_free`配列は、制約がなくなったときに、下位ビットから達成可能な最良の寄与を蓄積します。`r`。 

クエリ関数では、ループはビットを最上位から最下位まで処理し、構築されたプレフィックスがまだ次と等しいかどうかを維持します。`r`。 しっかりと行動を続けるなら、尊重しなければなりません`r`の構造。 それ以外の場合は、事前に計算されたサフィックス ゲインを使用して、残りの寄与を自由に最大化できます。

 ## 特殊なケース

 微妙なエッジ ケースの 1 つは、すべてのゲインがマイナスになる場合です。 この場合、最適な戦略は、制約によって強制されない限り、ビットを 1 に設定しないことです。`x ≤ r`。 サフィックスの寄与が大きいため、アルゴリズムはこれを自然に処理します。`max(0, gain[i])`自由な状態が有害なビットを決して選択しないようにします。 

もう 1 つのエッジ ケースは、制約が`r`上位ビットを強制的にゼロにします。 たとえば、次の場合`r = 1000₂`、最上位ビットを設定しようとする試み`x`実現可能性はすぐに壊れます。 タイトステート ロジックはこの分岐を正しく禁止し、下位ビットを続行して、有効な数値のみが考慮されるようにします。 

最後のケースは、XOR 演算によってビットの解釈が複数回反転されるときに発生します。 中間の動作は不安定に見えますが、`(f0, f1)`表現はすべてのフリップを最終的な決定論的マッピングに折りたたむため、DP は前処理を超えて操作順序に依存しません。
