 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、2 人のプレイヤーがそのシーケンスが空になるまで交互に一度に 1 つの数字を取得します。 アリスが先に動きます。 各プレイヤーは自分が選んだ数字の合計を累積します。 

すべての数値が取得された後、アリスの合計とボブの合計の間の絶対差を計算します。 この差が奇数であればアリスが勝ち、そうでなければボブが勝ちます。 

プレイヤーは残りの要素を自由に選択できるため、重要な難しさは選択プロセス自体ではありません。 本当の問題は、最適なプレーが最終的な差の同等性に影響を与えるかどうかです。 

制約 n は最大 1e6 までであるため、選択肢をシミュレートしたり、サブセットやゲーム状態を考慮したりするアプローチは不可能です。 O(n log n) ソートでも問題ありませんが、二次関数や指数関数は問題があるため、線形または線形に近いものが必要です。 

微妙な点は、値は最大 1e9 まで大きくすることができますが、最終的に重要なのはパリティだけであるということです。 これは、多くの場合、解が正確な合計ではなく、モジュロ 2 の推論に帰着することを示しています。 

単純なアプローチでは、ゲームをシミュレートしたり、最適なピッキング戦略をモデル化しようとします。 たとえば、プレイヤーは常に残っている最大の要素を選択する必要があると考える人もいるかもしれません。 この問題では、最適なプレイは最終差分の同等性には関係ないため、これはすでに誤った推論につながります。 結果は構造的不変条件のみに依存し、意思決定には依存しません。 

もう 1 つの誤った直感は、これを標準的な「交互に最大値をとる」ゲームとして扱い、交互の合計を計算することです。 これは、プレーヤーが配列の末尾や順序構造に制約されていないため、失敗します。 どの要素もいつでも取ることができ、すべての位置戦略が削除されます。 

隠れたエッジのケースは、すべての数値が偶数である場合です。 この場合、すべての合計は均等になるため、差は常に均等になり、プレイに関係なくボブが勝つことになります。 逆に、奇数が少なくとも 1 つある場合、最終的な差のパリティは常に奇数となり、アリスが勝ちます。 これは、問題をパリティ保存に還元しなければ明らかではありません。 

## アプローチ

 ブルートフォース解釈はゲームをシミュレートすることになります。 各ステップで、プレイヤーは利用可能な数字を選択し、残りのマルチセットを再帰的に調べて、両方の合計を追跡します。 これは事実上、各状態が残りのすべての要素に分岐するゲーム ツリーです。 ピックの各順序が可能なプレイ シーケンスに対応するため、状態の数は n の階乗になります。 

メモ化しても、残りのマルチセットは 2^n のサブセットで表現でき、遷移はどのプレイヤーのターンであるかに依存するため、状態空間は指数関数的なままです。 これにより、1e6 までの n に対しては完全に実行不可能になります。 

重要な観察は、どの要素を選択できるかについて制限がないため、選択の順序は各プレイヤーが最適なプレイで最終的に得られる複数の数字セットに影響を与えないということです。 シーケンスのすべての順列は、有効な再生順序に対応します。 これは、アリスとボブの間の最終的な番号の配分が有意義な方法で戦略的に制御されていないことを意味します。 

最適な選択について考える代わりに、合計の平価性を検討します。 S をすべての数値の合計とします。 アリスとボブがすべての要素を分割したため、S1 + S2 = S となります。注目する値は |S1 − S2| で、これは |S − 2S2| に等しくなります。 モジュロ 2 では、これは大幅に単純化されます。2S2 は常に偶数であるため、差のパリティは正確に S のパリティになります。 

したがって、ゲーム全体は、合計が奇数か偶数かをチェックすることになります。 和が奇数の場合、差も奇数なので、アリスが勝ちます。 合計が偶数であれば、ボブが勝ちます。

 | パリティ削減 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. シーケンス内のすべての要素の合計を計算します。 これは、すべての要素が最終的に 1 人のプレイヤーによって取得されるため、プレイ順序に関係なく合計が固定されるため有効です。 
2. 最下位ビットをチェックして、この合計が奇数であるか偶数であるかを判断します。 勝利条件は絶対差が奇数かどうかによって決まるため、パリティのみが重要です。 
3. 合計が奇数の場合は「Alice」を出力し、そうでない場合は「Bob」を出力します。 これは、合計のパリティと最終的な差のパリティの間の等価性から直接得られます。 

### なぜ効果があるのか

 重要な不変条件は、プレイヤーが要素をどのように選択したかに関係なく、すべての要素の合計が保持されることです。 S1 + S2 = S が常に成り立つため、式 |S1 − S2| となります。 |S − 2S2| と書き換えることができます。 2S2 項は常に偶数であるため、パリティには影響しません。 したがって、最終的な差の等価性はゲームの開始前に固定され、いかなる決定にも依存しません。 これにより、ゲームの側面が完全に削除され、問題が単一パスの計算に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    
    total = sum(arr)
    
    if total % 2 == 1:
        print("Alice")
    else:
        print("Bob")

if __name__ == "__main__":
    main()
```実装は直接的です。単一パスですべての数値の合計を累積します。 Python の組み込み sum の使用はすでに線形であり、1e6 までの n に対して十分効率的です。 並べ替えやシミュレーションは不要なので避けます。 

唯一の微妙な点は、中間ロジックがパリティを妨げないようにすることです。 最終結果は完全なマルチセットのみに依存するため、ターンを追跡したり除去をシミュレートしたりする必要はありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(input())
    arr = list(map(int, input().split()))
    total = sum(arr)
    return "Alice" if total % 2 == 1 else "Bob"

# provided samples
assert run("5\n1 2 3 4 5\n") == "Alice"
assert run("2\n2 4\n") == "Bob"

# minimum size
assert run("1\n1\n") == "Alice"
assert run("1\n2\n") == "Bob"

# all equal odd
assert run("4\n1 1 1 1\n") == "Bob"

# mixed parity
assert run("3\n1 2 2\n") == "Alice"

# large even-only
assert run("3\n1000000000 1000000000 2\n") == "Bob"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | アリス | 最小の奇数和の場合 |
 | 1 2 | ボブ | 最小偶数和の場合 |
 | 1 1 1 1 | ボブ | multiple odds cancel to even |
 | 1 2 2 | アリス | mixed parity correctness |
 | 大きな偶数セット | ボブ | 大きな値の安定性 |

 ## 特殊なケース

 最小限の単一要素のケースでは、コア ルールがすぐに公開されます。 入力用`1 1`, アリスが唯一の要素を取り、その差は 1 で奇数なので、アリスが勝ちます。 アルゴリズムは sum = 1 を計算し、Alice を正しく出力します。 

次のような単一の偶数要素の場合`1 2`, 合計が 2 で偶数なので、ボブが勝ちます。 アリスは 2 を獲得し、ボブは何も獲得せず、差は 2 ですが、依然として互角です。 アルゴリズムは一貫して Bob を返します。 

などの奇数が多い場合`1 1 1 1`合計は 4 になります。プレーヤーが交互にピックしても、どの分割でも等価分割となり、差は均等になります。 アルゴリズムは、動きをシミュレートすることなく、これを直接キャプチャします。 

これらの例は、戦略的戦略によってパリティの結果が変わることはなく、合計ベースの削減で十分であることを確認しています。
