 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。`n`各頂点では、その子が定義された順序で明示的にリストされます。 ツリーでは 3 種類のクエリが可能です。 最初のタイプは、最短パスに沿ったエッジの数に関して 2 つのノード間の距離を求めます。 2 番目のタイプは、ノードを親から切り離し、特定の祖先に再接続することによってツリーを変更します。 3 番目のタイプは、子の順序を考慮して深さ優先でツリーをトラバースするときに、特定の深さの最後のノードを要求します。 

木のサイズ`n`は 10^5 に達する可能性があり、最大 10^5 のクエリを受信する可能性があります。 クエリごとに O(n) 時間を必要とするアルゴリズムは、最大 10^10 の演算が含まれる可能性があるため、実用的ではありません。 効率的なソリューションでは、距離およびツリー変更操作のクエリごとに O(log n) または償却された O(log n) をターゲットにする必要があります。 DFS ベースのクエリでは、トラバーサル シーケンスにアクセスする必要があるため、ツリーを変更した後でも、指定された深さの最後のノードを迅速に見つける方法が必要です。 

単純なアプローチを破る可能性のあるエッジ ケースには、ルートの直接の子からノードを切り離すことや、ノードを複数レベル上に移動することが含まれます。 たとえば、ノード 4 (2 の子) を 1 の子に移動すると、移動前にキャッシュされた単純な DFS シーケンスは、タイプ 3 のクエリに対して古い位置を返します。 

## アプローチ

 ブルート フォース ソリューションでは、ツリーを隣接リストとして保存します。 距離クエリは、毎回 BFS または DFS を実行することで回答できますが、クエリごとに O(n) かかります。 ノードを新しい祖先に移動することは、隣接リストでは簡単であり、タイプ 3 のクエリの DFS シーケンスの再計算にも O(n) かかります。 これは正しいですが、10^5 ノードを持つツリーに対して 10^5 クエリが存在する可能性があるため、遅すぎます。 

効率性に関する重要な洞察は、距離クエリと祖先変更の両方にツリーに沿ったパスが含まれるということです。これは、親ポインターとバイナリ リフティング テーブルの組み合わせを使用して処理でき、クエリごとに O(log n) で最小共通祖先 (LCA) を計算できます。 バイナリリフティングによりジャンプが可能になります`2^i`祖先はステップごとに一定の時間で計算されます。 タイプ 2 クエリのツリー構造を更新するには、DFS シーケンスを維持しながら、親ポインターと子ポインターを慎重に再リンクする必要があります。 タイプ 3 のクエリを効率的に処理するために、深さをその深さで確認された最後のノードにマップし、ノードが移動されたときに動的に更新するバランスの取れた構造を維持できます。 実際的なアプローチでは、セグメント ツリーまたはバランスのとれた BST を使用したオイラー ツアーのような表現を使用して深さ情報を維持します。これにより、O(log n) のクエリと更新時間が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、隣接リストとしてツリーを構築します。 各ノードの親とその子のリストの両方を順番に保存します。 各ノードについて、その初期深さを記録し、シーケンス管理のために DFS-in order インデックスを割り当てます。 
2. バイナリリフティングのために祖先を事前計算します。 ノードごとにテーブルを保存します`up[v][i]`の 2^i 番目の祖先を表す`v`。 これにより、距離計算とタイプ 2 クエリのために O(log n) 時間でツリーを上に移動できます。 距離を効率的に計算するために、ノードの深さも保存されます。 
3. 間の距離クエリを処理するには`u`そして`v`、バイナリ リフティング テーブルを使用して最小の共通祖先を計算します。 そのときの距離は`depth[u] + depth[v] - 2 * depth[lca(u, v)]`。 
4. タイプ 2 クエリ (ノードの親変更) の場合は、まずバイナリ リフティング テーブルを使用してターゲットの祖先を見つけます。 現在の親の子リストからノードを削除します。 それを新しい親の子リストに追加します。 の親ポインタと深さポインタを更新します`v`およびそのすべての子孫。 DFS-in インデックスを更新し、高速なタイプ 3 クエリの深度マッピングを維持します。 深さの更新は、移動されたノードからの DFS トラバーサルを使用して実行できます。 
5. タイプ 3 クエリの場合 (深さの最後のノードを検索します)`k`)、深さから DFS 順序で最後に検出されたノードへのマッピングを維持します。 ツリーを変更した後は、影響を受けるノードについてのみこのマッピングを更新してください。 深さの最後のノードを取得する`k`マッピングを使用した O(1) 操作になります。 
6. 上記の構造を使用して各クエリを処理します。 タイプ 1 クエリの場合は、距離を計算します。 タイプ 2 クエリの場合、深さと DFS マッピングを再親化し、更新します。 タイプ 3 のクエリの場合は、クエリされた深さで最後に保存されたノードを返します。 

不変条件は、親ポインター、深さの値、および深さの最後のノードのマッピングが常に正しいということです。 親の再設定では、影響を受けるサブツリーとマッピング内の対応するエントリのみが更新されるため、ツリーの他の部分は変更されず、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(300000)

n, m = map(int, input().split())
children = [[] for _ in range(n + 1)]
parent = [0] * (n + 1)
depth = [0] * (n + 1)

for v in range(1, n + 1):
    line = list(map(int, input().split()))
    l = line[0]
    children[v] = line[1:]
    for c in children[v]:
        parent[c] = v

LOG = 17
up = [[0] * (LOG + 1) for _ in range(n + 1)]

def dfs(u, p):
    depth[u] = depth[p] + 1
    up[u][0] = p
    for i in range(1, LOG + 1):
        up[u][i] = up[up[u][i - 1]][i - 1]
    for v in children[u]:
        dfs(v, u)

dfs(1, 0)

def lca(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    for i in range(LOG, -1, -1):
        if depth[u] - (1 << i) >= depth[v]:
            u = up[u][i]
    if u == v:
        return u
    for i in range(LOG, -1, -1):
        if up[u][i] != up[v][i]:
            u = up[u][i]
            v = up[v][i]
    return up[u][0]

last_at_depth = dict()
order = []

def dfs_order(u):
    order.append(u)
    last_at_depth[depth[u]] = u
    for v in children[u]:
        dfs_order(v)

dfs_order(1)

for _ in range(m):
    query = input().split()
    if query[0] == '1':
        u, v = int(query[1]), int(query[2])
        print(depth[u] + depth[v] - 2 * depth[lca(u, v)])
    elif query[0] == '2':
        v, h = int(query[1]), int(query[2])
        # find h-th ancestor
        anc = v
        for i in range(LOG, -1, -1):
            if h >= (1 << i):
                anc = up[anc][i]
                h -= (1 << i)
        # remove v from current parent
        p = parent[v]
        children[p].remove(v)
        # attach to new parent
        children[anc].append(v)
        parent[v] = anc
        # update depths and up table
        def update_subtree(u):
            for i in range(1, LOG + 1):
                up[u][i] = up[up[u][i - 1]][i - 1]
            for c in children[u]:
                depth[c] = depth[u] + 1
                update_subtree(c)
            last_at_depth[depth[u]] = u
        depth[v] = depth[anc] + 1
        update_subtree(v)
    else:
        k = int(query[1])
        print(last_at_depth[k])
```このコードでは、距離と祖先の計算にバイナリ リフティングを使用します。 タイプ 2 のクエリは、親ポインター、子リスト、および深さのマッピングを再帰的に慎重に更新します。 タイプ 3 のクエリは、次の理由により O(1) です。`last_at_depth`。
