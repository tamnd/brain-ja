 ## 解決策
 ## 問題の理解

 マシュモクは次のシーケンスを選択したいと考えています`n`彼の上司である Bimokh が正確に利益を得られるように、別個の整数を設定します。`k`ゲーム内のポイント。 ゲームはペアで進行します。ビモクは、残りの数値が 2 つ未満になるまで、現在のシーケンスから最初の 2 つの整数を繰り返し削除し、これら 2 つの数値の最大公約数をポイントとして獲得します。 タスクは、そのようなシーケンスを構築するか、それが不可能であると判断することです。 

入力は 2 つの整数です。`n`そして`k`。 出力は次のいずれかです`-1`シーケンスが存在しない場合、または`n`個別の整数`a1`に`an`それぞれが 10^9 を超えないため、正確に得られます`k`説明されているプロセスが適用されるときのポイント。 

境界は重要です。 と`n`最大 10^5 および`k`10^8 までは、二次時間のアルゴリズムは遅すぎます。 本質的に線形時間で実行されるソリューションが必要です。 各整数は標準の 32 ビット符号付き整数の範囲に収まる必要があるため、解をエンコードするために無制限の数値に依存することはできません。 

明らかではないエッジケースが発生するのは次の場合です。`k = 0`。 これには、すべてのペアが互いに素であることが必要です。 もし`n = 1`、ペアはないので、任意の数が機能します。 のために`n = 2`、シーケンスには、gcd が正確に 0 である数値が含まれている必要がありますが、gcd は常に少なくとも 1 であるため、これは不可能です。これは、次の関係を示しています。`n`そして`k`実現可能性に制約を課します。 

もう 1 つのエッジケースは次のような場合です`k`に比べて非常に大きい`n`。 各ペアは最大でも貢献します`gcd(x, y)`ポイントなので、最初の合計`floor(n/2)`数値の gcd は等しい必要があります`k`。 これにより、尊重する必要があるシーケンスの上限が決まります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのシーケンスを試みます。`n`個別の整数の場合、連続する各ペアの gcd を計算し、それらを合計して等しいかどうかを確認します。`k`。 これは原理的には正しいですが、シーケンスの数が階乗的に増加するため実行不可能です。`n`。 シーケンスを昇順に生成して gcd を計算する場合でも、O(n!) 回の操作が必要ですが、これは 1 秒の制限をはるかに超えています。 

重要な洞察は、数値を選択することで gcd を制御するため、削除された各ペアの最初の要素のみを気にするということです。 ペアが gcd 1 を持つことを確認する最も簡単な方法は、連続する整数を選択することです。 合計スコアを達成するには`k`、最初の 2 つの数値を構成して、gcd が次と等しくなるようにすることができます。`k`このアプローチでは、必要な gcd を生成する 2 つの数値を選択し、残りのシーケンスを最初の要素と互いに素である連続数値で埋めるという問題が軽減されます。 

この洞察により、問題は総当たり検索ではなく建設的なシーケンス生成に変わります。 最初の 2 つの数字を慎重に選択すると、`k + 1`そして`2 * k + 1`、このペアの gcd が正確であることを保証します。`k`。 残りの数値は、最初の 2 つの数値との衝突を避ける 1 から始まる連続した整数にすることができ、すべての数値が個別であり ≤ 10^9 であることが保証されます。

 ## アルゴリズムのチュートリアル

 1.次のことを確認します`n = 1`そして`k > 0`。 だったら返して`-1`単一の数値では正の gcd ポイントを生成できないためです。 もし`n = 1`そして`k = 0`、 戻る`[1]`。 
2. シーケンスの最初の 2 つの数値を次のように初期化します。`k + 1`そして`2 * k + 1`。 これら 2 つの数値の gcd は正確に次のようになります。`k`なぜなら`2*k + 1 - (k + 1) = k`。 この選択は目標スコアを満たします。 
3. 残りを埋めます`n - 2`すでに選択されている番号をスキップして、1 から始まる連続する整数の番号 (`k + 1`そして`2*k + 1`) 区別性を維持するため。 これらの追加の数値が 10^9 を超えないように注意してください。 
4. 構築された順序でシーケンスを出力します。`[k + 1, 2*k + 1, 1, 2, ..., skipping collisions]`。 

なぜ機能するのか: 不変条件は、最初のペアのみが寄与することです。`k`スコアに。 残りの連続する数値のペアはすべて 1 から始まるか、最初のペアの倍数を避けて、gcd が 1 であることが保証されます。この構造により、合計が正確に一致することが保証されます。`k`すべての数値を区別し、≤ 10^9 を保ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

if n == 1:
    if k == 0:
        print(1)
    else:
        print(-1)
else:
    first = k + 1
    second = 2 * k + 1
    sequence = [first, second]
    current = 1
    while len(sequence) < n:
        if current != first and current != second:
            sequence.append(current)
        current += 1
    print(" ".join(map(str, sequence)))
```コードハンドル`n = 1`これはペアが存在しない退化ケースであるため、別々に。 最初の 2 つの数値を gcd 要件に一致するように構築し、衝突を避けるために残りのシーケンスを小さな整数で埋めます。 使用する`current`最初の 2 つの数値が誤って重複することを防ぎます。

 サンプル入力`5 2`:

 ## 特殊なケース

 のために`n = 1`そして`k = 0`、シーケンス`[1]`ペアが存在しないため、正しくゼロ点が生成されます。 のために`n = 1`そして`k > 0`、アルゴリズムは戻ります`-1`単一の数値からは正の gcd を生成できないためです。 大型用`k`10^8 に近い最初の 2 つの数値`k + 1`そして`2*k + 1`制約が確実に尊重されるように、2 * 10^8 + 1 を超えないようにしてください。10^9 未満であれば安全です。 

このアルゴリズムは、重複をスキップして区別性を維持することで、小さな数値を埋めると最初の 2 つの数値と重複する可能性のあるシーケンスを適切に処理します。 これにより、有効なすべての場合に、`n`そして`k`、出力シーケンスは正しいです。
