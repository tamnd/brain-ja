 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$2^n$、 どこ$n$最大 20 であり、一連のクエリです。 各クエリは数値を指定します$q_i$これは、配列を一定のサイズのブロックに繰り返し分割することを指示します。$2^{q_i}$、各ブロックを反転してから、ブロックを結合し直します。 反転を実行した後、結果の配列内の反転の数を数えるように求められます。 

反転はインデックスのペアです$(i,j)$そのような$i < j$そして$a[i] > a[j]$。 クエリ操作は**累積的**であり、各クエリの後に配列が永続的に変更されることを意味します。 

制約を考慮すると、配列サイズは最大でも$2^{20} \approx 10^6$これは管理可能ですが、クエリの数が非常に多くなる可能性もあります ($m \le 10^6$）。 したがって、二次アルゴリズム ($O(N^2)$) は遅すぎるでしょう。 たとえ$O(N \log N)$クエリごとの反転数はほとんど収まらない可能性があるため、**計算を再利用**する方法を探す必要があります。 

エッジケースには以下が含まれます$n = 0$(サイズ 1 の配列、反転なし)、$q_i = 0$(サイズ 1 のブロック、配列には影響なし)、および同じことを繰り返すクエリ$q_i$複数回。 ブロックの反転は配列全体を反転することと同じではないため、配列の反転を慎重に処理することも重要です。 

単純な実装は、部分的な反転後に反転を誤って再計算したり、ブロックへの分割方法を誤解したりすることにより、静かに失敗する可能性があります。$q_i = 0$または$q_i = n$。 

## アプローチ

 ブルート フォースのアプローチは簡単です。クエリごとに、配列を一定のサイズのブロックに分割します。$2^{q_i}$、各ブロックを反転し、配列を再構成してから、マージ ソートまたは単純なソートを使用して反転をカウントします。$O(N^2)$ループ。 マージソートによる反転のカウントは次のとおりです。$O(N \log N)$。 

のために$n = 20$、$N = 2^n = 1,048,576$。 クエリごとに 1 つのマージ ソートにかかるコストはおよそ$N \log N \approx 2 \times 10^7$操作。 と$m = 10^6$クエリを実行すると、妥当な時間制限を超える可能性があります。 平$O(N \log N)$クエリごとの速度が遅すぎます。 

重要な洞察は、各クエリが ** ブロックのサイズを逆転させるということです。$2^{q_i}$**、これはインデックスのバイナリ表現におけるビットの反転に正確に対応します。 **マージ ソート ツリー**の各レベルでの反転の数を事前計算すると、どのレベルを反転するかを切り替えるだけで各クエリに答えることができます。 具体的には、完全なマージ ソートは **分割統治ツリー** として見ることができます。最上位レベルでは前半と後半がマージされ、次のレベルでは四半期がマージされます。 サイズのブロックを反転する$2^k$レベルでの反転に影響を与える方法で要素を交換します$0..k-1$この木の。 

したがって、最適なアプローチは、レベルごとに反転を前処理し、**反転のビットマスク**を維持することです。 各クエリはこのマスクを更新し、反転の総数は次のように計算できます。$O(n)$クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * N log N) | O(N) | 遅すぎる |
 | 最適 | O(N log N + m * n) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. **レベルごとに反転を事前計算します。** 配列を完全なマージ ソート ツリーとして扱います。 マージソートの各レベルは、長さのマージセグメントに対応します。$2^k$。 前処理中に、レベルごとに、各セグメントの左半分と右半分の間に作成された反転の数をカウントし、配列に格納します。`inv_level[k]`。 これにより、任意のセグメント サイズについて、反転されなかった場合にどの程度の反転に寄与するかを知る方法が得られます。 
2. **反転を追跡するためにビットマスクを初期化します。** ビットマスク`rev_mask`長さがある$n$、 どこ`rev_mask[k]`セグメントのサイズが次のとおりであるかどうかを示します。$2^k$問い合わせにより取り消されました。 最初はすべてゼロです。 
3. **各クエリを処理する$q_i$.** クエリの場合$q_i$、マスク内のすべてのビットをレベルで反転します。`0`に`q_i-1`。 これは、サイズのすべてのブロックを反転した場合の効果をシミュレートします。$2^{q_i}$。 その理由は、マージソートの反転がどのように影響を受けるかに由来します。セグメントを反転すると、そのセグメント内のすべての下位レベルの反転が反転されます。 
4. **合計反転を計算します。** マスクを更新した後、合計して合計反転を計算します。`inv_level[k]`レベルの場合`rev_mask[k]`がゼロであり、`total_pairs[k] - inv_level[k]`レベルの場合`rev_mask[k]`は 1 つです。 ここ`total_pairs[k]`レベルで可能な反転の最大数です`k`、つまり、サイズの左半分と右半分にわたるペア$2^k$。 
5. **結果を出力します。** クエリごとに手順 3 ～ 4 を繰り返します。 マスクを更新して合計するだけなので$n \le 20$レベル、各クエリは$O(n)$そして実現可能$m \le 10^6$。 

**機能する理由** マージ/ソート ツリーでは反転が加算されます。 セグメントのサイズを反転する$2^k$そのセグメント内のすべての反転を反転します。これは、以下のレベルの事前計算された値を切り替えることによって正確に考慮されます。$k$。 マージ/ソート ツリー構造はすべてのペアをあるレベルで一意に分割するため、反転が二重にカウントされたり見逃されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_inversions(arr):
    n = len(arr)
    tmp = arr[:]
    inv_levels = [0] * (n.bit_length())
    
    def merge_sort(l, r, level):
        if r - l <= 1:
            return 0
        m = (l + r) // 2
        inv = merge_sort(l, m, level - 1) + merge_sort(m, r, level - 1)
        i, j, k = l, m, l
        while i < m and j < r:
            if arr[i] <= arr[j]:
                tmp[k] = arr[i]
                i += 1
            else:
                tmp[k] = arr[j]
                inv += m - i
                j += 1
            k += 1
        while i < m:
            tmp[k] = arr[i]
            i += 1
            k += 1
        while j < r:
            tmp[k] = arr[j]
            j += 1
            k += 1
        arr[l:r] = tmp[l:r]
        inv_levels[level] += inv
        return inv
    
    total_inv = merge_sort(0, n, n.bit_length() - 1)
    return inv_levels, total_inv

n = int(input())
arr = list(map(int, input().split()))
m = int(input())
queries = list(map(int, input().split()))

inv_levels, _ = count_inversions(arr[:])
total_pairs = [(1 << (i)) * (1 << (i)) for i in range(n.bit_length())]

rev_mask = [0] * n
res = []

for q in queries:
    for i in range(q):
        rev_mask[i] ^= 1
    total = 0
    for i in range(n):
        if rev_mask[i]:
            total += total_pairs[i] - inv_levels[i]
        else:
            total += inv_levels[i]
    res.append(str(total))

sys.stdout.write('\n'.join(res) + '\n')
```**説明。**`count_inversions`関数はマージソートのレベルごとに反転を計算します。 の`rev_mask`どのレベルが反転されたかを追跡します。`total_pairs`レベルごとに可能な最大反転数を計算します。 クエリごとにマスクが更新され、レベルを合計し、必要に応じて寄与を反転することによって総反転数が計算されます。 

微妙な点としては、マージ・ソート・ツリーの下から上までのレベルのインデックスを正しく作成することと、クエリを次のように処理することが挙げられます。`q = 0`(変化なし) または`q = n`(完全な配列反転)。
