 ## 解決策

 ## 問題の理解

 1 から n までの数値の順列が与えられており、1 から n までの各値 m を「良い」または「悪い」のいずれかに分類したいとします。 配列内のどこかに、要素が 1 から m までの数値であり、それぞれ 1 回出現する連続セグメントが存在する場合、値 m は適切であるとみなされます。 

したがって、任意の値を選択する代わりに、その値が最初の m 整数の完全なセットを形成する連続位置のブロックが順列に含まれているかどうかを尋ねています。 

各テスト ケースの出力は、長さ n のバイナリ文字列です。 i 番目の文字は、i が良いかどうかを示します。 

n はテスト ケース全体で最大 2×10^5 まで大きくなる可能性があるため、制約が重要になります。 すべての部分配列を試して、それらが有効な順列を形成しているかどうかをチェックするソリューションでは、セグメントを繰り返しスキャンすることになり、テスト ケースごとの動作が 2 次またはさらに悪化することになり、これは 1 秒の許容範囲をはるかに超えています。 

「すべてのサブ配列をチェックして、正確に 1..m が含まれているかどうかをテストするだけ」と考えると、単純な落とし穴が発生します。 サブ配列のチェックが最適化されている場合でも、サブ配列の数は O(n^2) であり、高度に最適化されていない限り、各検証のコストは少なくとも O(n) かかり、実行不可能になります。 

もう 1 つの微妙な問題は、セグメントのどこかに 1 から m までのすべての値が含まれている場合、そのセグメントは自動的に有効であると想定していることです。 これは、セグメントの長さが正確に m であり、その範囲外の余分な数値が含まれていない場合には当てはまりません。 

## アプローチ

 ブルートフォースの観点は、m を固定し、考えられるすべてのサブ配列をスキャンすることから始まります。 各部分配列について、集合 {1, 2, ..., m} が正確に含まれているかどうかを追跡します。 これには、完全性と範囲外の余分な値がないことの両方をチェックする必要があります。 周波数配列を使用した場合でも、最悪の場合でも O(n^2) 個のサブ配列と O(n) 個の更新が必要となり、単純な実装では O(n^3) になるか、重い前処理を行うと O(n^2) になり、最大 2×10^5 の n では依然として失敗します。 

重要な点は、実際にはサブ配列を検索する必要がないということです。 代わりに、視点を逆にすることができます。つまり、m を固定し、1 から m までの数字が順列のどこに位置するかを調べます。 これらの位置は、それらのすべてを含む可能性のある候補セグメントを一意に決定します。 

有効なセグメントが存在する場合、そのセグメントには 1 から m までの数字がすべて含まれている必要があります。 このような最小のセグメントは、これらの値の最小位置からこれらの値の最大位置までです。 そのセグメントが有効なのは、その m 数を超える余分な要素が含まれていない場合、つまり長さが m に等しい場合に正確に発生します。 

これにより、m が増加するにつれて最小位置と最大位置を動的に追跡するという問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) または O(n^2 log n) | O(n) | 遅すぎる |
 | 最適（位置追跡） | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、順列内のすべての値の位置を計算して、各数値が出現する場所をすぐに特定できるようにします。

1. pos[x] が順列内の値 x のインデックスである配列 pos を構築します。 これにより、各数値がどこにあるかを定数時間で検索できるようになります。 
2. 2 つの変数 min_pos と max_pos を値 1 の位置で初期化します。この時点では、数値 1 のみが考慮され、それを含むセグメントは自明に有効です。 
3. m を 2 から n まで繰り返します。 各 m について、pos[m] を使用して min_pos と max_pos を更新します。 これらは、値 1 ～ m の中で最小および最大のインデックスを表します。 
4. 各 m を更新した後、max_pos - min_pos + 1 が m に等しいかどうかを確認します。 この条件は、1..m のすべての出現にまたがる区間には正確に m 個の要素があり、その中に余分な数値が存在できないことを意味します。 
5. 条件が当てはまる場合、m を美しいとマークします。 それ以外の場合は、美しくないとマークします。 

### なぜ効果があるのか

 どのステップ m においても、1 から m までの番号の位置のセットは固定されています。 これらすべての値を含む有効なセグメントは、少なくとも min_pos から max_pos までをカバーする必要があります。 その間隔にちょうど m 個の要素がある場合、その間隔にはちょうどその m 個の位置が含まれ、他には何も含まれません。 配列は順列であるため、これらの位置は個別の値に対応するため、セグメントは 1..m の順列である必要があります。 間隔が大きい場合、セットの外に余分な要素が含まれるため、サイズ m のきれいな順列を形成することができなくなります。 

これは、m の有効性が明示的な部分配列のチェックではなく、位置の幾何学のみに依存することを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i

        min_pos = pos[1]
        max_pos = pos[1]

        ans = ["0"] * (n + 1)

        for m in range(1, n + 1):
            idx = pos[m]
            if m == 1:
                min_pos = max_pos = idx
            else:
                if idx < min_pos:
                    min_pos = idx
                if idx > max_pos:
                    max_pos = idx

            if max_pos - min_pos + 1 == m:
                ans[m] = "1"

        out.append("".join(ans[1:]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、値 1 ～ m の位置の範囲を維持することに完全に依存しています。 pos 配列により、各要素の位置への一定時間のアクセスが保証されます。 増分更新により、m ごとに何も最初から再計算する必要がなくなります。 

よくある実装上の間違いは、m ごとに以前の値をすべてスキャンして最小位置と最大位置を再計算することです。これにより、パフォーマンスが O(n^2) まで低下します。 もう 1 つの微妙な問題は、Python ではインデックス付けがゼロベースであることを忘れていることです。そのため、間隔の長さの計算はその選択と一貫性を保つ必要があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0]*(n+1)
        for i,v in enumerate(p):
            pos[v]=i
        mn=pos[1]; mx=pos[1]
        ans=["0"]*(n+1)
        for m in range(1,n+1):
            idx=pos[m]
            if idx<mn: mn=idx
            if idx>mx: mx=idx
            if mx-mn+1==m:
                ans[m]="1"
        res.append("".join(ans[1:]))
    return "\n".join(res)

 ## 特殊なケース

 1 つのエッジ ケースは、可能な限り最小の順列です。 単一の要素の場合、有効な m は 1 だけであり、アルゴリズムはその単一のインデックスで min_pos と max_pos を正しく初期化し、長さ 1 のスパンを生成します。 

もう 1 つのケースは、完全に逆の順列です。 要素がソートされていないにもかかわらず、すべてのプレフィックス 1..m は依然としてインデックス空間内の連続セグメントを占有しているため、各 m はスパン テストに合格します。 位置範囲は順序ではなくエンドポイントのみに依存するため、アルゴリズムはこれを捉えます。 

より微妙なケースは、小さい数値と大きい数値が交互に並ぶなど、値がインターリーブされている場合です。 このアルゴリズムは、1..m の位置がインデックス空間内で連続していない中間 m 値を、たとえそれらが互いに近くに頻繁に出現する場合でも正しく不合格とします。
