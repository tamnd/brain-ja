 ## 解決策
 ## 問題の理解

 それぞれが次の文字で構成される、いくつかの独立した文字列が与えられます。`a`、`b`、`c`、 そして`?`。 タスクはすべてを交換することです`?`手紙の一つで`a`、`b`、 または`c`最終的な文字列には隣接する 2 つの等しい文字が含まれないようにします。 この特性を維持しながら交換を完了する方法がない場合は、失敗を報告する必要があります。 

この問題について考えるのに役立つ方法は、次のとおりです。`?`は空きスロットですが、文字列には文字が固定されている制約がすでに課されています。 最後の文字列は、連続する位置が一致できないという制限付きで、3 文字のアルファベットにわたる有効なシーケンスである必要があります。 

テスト ケースごとの制約は小さいですが、すべてのテスト ケースの合計長は 100,000 に達します。これは、テスト ケースごとの線形時間戦略をすぐに示唆します。文字列あたり O(n) より悪いものは、最悪の集計で約 10^8 の演算を超える危険性があるためです。これは、Python の 1 秒制限では安全ではありません。 

素朴な懸念は、貪欲なローカル選択が後で矛盾を強いるのではないかということです。 もう 1 つの微妙なケースは、固定文字がすでにルールに違反している場合です。たとえば、`"aa?b"`、最初の無効な隣接関係を修正できる代替手段はありません。`"aa"`。 その場合はすぐに生産しなければなりません`-1`。 

それほど明白ではない失敗パターンもあります。次のような文字列です。`"a??a"`エンドポイントによって中間領域が衝突する可能性のある繰り返しパターンに強制されるため、常に有効な塗りつぶしが許可されるわけではありません。 例えば`"a??a"`長さ 4 の場合、中間の 2 つの位置が両方を回避するように強制されます。`a`これはまだ実現可能ですが、交互の制約が長くなると、特定の固定構成ではすべてのオプションがブロックされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれを処理します`?`3 つの可能性の分岐選択肢として、文字列の入力を試み、後で​​妥当性をチェックします。 k 個の疑問符がある場合、3^k 通りの組み合わせになります。 k が約 20 であっても、これはすでに実行不可能になり、ここで k はテスト全体で合計で最大 10^5 になる可能性があります。 この爆発は、隣接制約が純粋にローカルであるという事実を使用せずに、選択肢を独立して扱うことから生じます。 

重要な観察は、各位置がそのすぐ隣の位置とのみ相互作用するということです。 文字列を左から右に処理する場合、位置 i の文字を決定すると、それは i+1 にのみ影響します。 これにより、グローバルな依存関係が削除され、貪欲な構築が可能になります。 

分岐する代わりに、ローカル ルールを適用します。`?`、すでに決定されている左隣の文字と異なる文字を選択します。 後のポジションも同様に解決されます。文字が 3 つあるため、固定制約に違反しない限り、常に少なくとも 1 つの有効な選択肢があります。 

唯一失敗するのは、固定文字によってすでに無効な隣接関係が作成されている場合、または`?`両方の隣人が平等であり、すべての選択肢を使い果たしているため、矛盾に追い込まれています。 しかし、キャラクターが 3 人いる場合でも、2 つの禁断の隣人には有効な選択肢が 1 つ残されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^k) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、入力にすでに固定文字間の違反が含まれているかどうかを確認します。 隣接するペアをスキャンし、そうでない 2 つの等しい文字が見つかった場合は、`?`、その答えが不可能であることはすでにわかっています。 これが必要な理由は、`?`既存の矛盾を解決することはできません。 
2. 置換を簡単に実行できるように、文字列を変更可能な配列に変換します。 
3. 左から右にスキャンします。 各位置 i に、どの文字を配置するかを決定します。 
4. キャラクターがそうでない場合`?`、そのままにしておきます。 これにより、入力によってすでに適用されている制約が保持されます。 
5. そうであれば`?`のいずれかを割り当てようとします。`a`、`b`、 または`c`前の文字 (存在する場合) とは異なり、次の文字がすでに固定されている場合は次の文字とも異なります。 最初の有効な候補者を選択します。 
6. 文字を配置できない場合は、文字列を美しくすることができないと即座に判断します。 
7. 入力後、最終検証パスを実行して、隣接する等しい文字が存在しないことを確認し、結果を出力します。 

これが機能する理由は制約の構造にあります。 各位置では、最大 2 文字のみが禁止されます。すでに固定されている場合は、左側の文字と右側の文字です。 合計 3 つの文字があるため、固定位置にすでに矛盾が存在しない限り、常に少なくとも 1 つの選択可能な選択肢があります。 貪欲な決定は、直接の隣接を超えた位置の将来のオプションをすべて削除することはないため、安全です。 すべての制約はローカルで対称的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(s: str):
    n = len(s)
    s = list(s)

    # early check for fixed contradictions
    for i in range(n - 1):
        if s[i] != '?' and s[i] == s[i + 1]:
            return "-1"

    for i in range(n):
        if s[i] == '?':
            for c in "abc":
                ok = True
                if i > 0 and s[i - 1] == c:
                    ok = False
                if i + 1 < n and s[i + 1] != '?' and s[i + 1] == c:
                    ok = False
                if ok:
                    s[i] = c
                    break
            if s[i] == '?':
                return "-1"

    for i in range(n - 1):
        if s[i] == s[i + 1]:
            return "-1"

    return "".join(s)

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve(s))

if __name__ == "__main__":
    main()
```解決策は、すでに存在する無効な隣接関係をいくら置換しても修復できないため、すでに修正された文字の健全性チェックから始まります。 貪欲な充填ステップは、固定順序で文字を試行することに依存しますが、実現可能性は最適な選択には依存せず、存在のみに依存するため、どの順序でも有効です。 

重要な点は、右隣がすでにわかっている場合にのみ、右隣をチェックすることです。 許可せずに将来の一貫性が必要な場合`?`、決定を過度に制約してしまうでしょう。 この左から右への処理により、過去の選択が無効になることがなくなります。 

## 実用的な例

 2 つの代表的な入力を追跡します。 

### 例 1:`"a???cb"`私たちは決定を左から右に追跡します。 

| 私 | 文字 | 左隣 | 右隣 | 選ばれた |
 | --- | --- | --- | --- | --- |
 | 0 | | - | ? | |
 | 1 | ? | | ? | b |
 | 2 | ? | b | ? | |
 | 3 | ? | | c | b |
 | 4 | c | b | b | c |
 | 5 | b | c | - | b |

 最終的な文字列は次のようになります`"ababcb"`。 これは、貪欲な選択によって 3 つの使用可能な文字によって常に柔軟性が保たれることを示しています。 

### 例 2:`"a??bbc"`またまた順番に進めていきます。 

| 私 | 文字 | 左隣 | 右隣 | 選ばれた |
 | --- | --- | --- | --- | --- |
 | 0 | | - | ? | |
 | 1 | ? | | ? | b |
 | 2 | ? | b | b | |
 | 3 | b | | b | b |
 | 4 | b | b | c | 衝突 |
 | 5 | c | b | - | c |

 位置 4 には、すでに`"bb"`固定入力からのものであり、以前の選択に関係なくルールに違反します。 アルゴリズムはこの矛盾を検出し、次の値を返します。`-1`。

 ## 特殊なケース

 直接的な失敗のケースは、固定文字が既に隣接ルールに違反している場合です。 入力用`"aa?b"`、スキャンは検出します`"aa"`開始時と復帰時`-1`すぐに。 すでに固定されている文字を変更する置換はできないため、アルゴリズムは構築を試行せずに正しく拒否します。 

もう一つの微妙なケースは、`"a????a"`。 エンドポイントは内部に回避を強制します`a`そして内部での繰り返しを避けます。 貪欲なプロシージャは左から右に埋められ、常に次の少なくとも 1 つが含まれます。`{a, b, c}`前の文字を回避し、最終的に次のような有効な交互パターンを生成するものを利用できます。`"ababca"`または`"acbac a"`選択肢によっては。 割り当ての時点では 1 つの近隣ノードのみが重要であるという不変条件により、エンドポイントがローカル隣接関係の制約を超えてグローバルな矛盾を引き起こさないことが保証されます。
