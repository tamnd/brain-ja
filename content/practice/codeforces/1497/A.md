 ## 解決策
 ## 問題の理解

 非負の整数の配列が与えられており、すべてのプレフィックスにわたる **MEX** 値の合計が最大になるように配列を並べ替えたいと考えています。 プレフィックスは、配列の最初のセグメントです。 セットの **MEX** は、そのセットに存在しない最小の非負の整数です。 たとえば、MEX は`{0, 1, 3}`は`2`、 なぜなら`0`そして`1`存在しますが、`2`が欠けています。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは配列サイズを提供します`n`(最大 100) と配列要素自体 (すべて 0 ～ 100)。 小さいサイズの`n`これは、O(n²) の複雑さのアルゴリズムが 1 秒未満で快適に実行できることを意味しますが、問題には明確な貪欲な構造があるため、より単純で直接的なものを目指す必要があります。 

明らかではないエッジケースには配列の欠落が含まれます`0`、すべての要素が等しい配列、またはいくつかの数値が複数回出現する配列。 たとえば、配列が`[2, 2, 3]`、単純なアプローチでは、MEX を最大化するために最大の要素から始めようとする可能性がありますが、MEX は小さな数値の欠落に非常に敏感であるため、これは失敗します。 正しい出力は、以下から開始することを優先する必要があります。`0`それが存在する場合。 

## アプローチ

 ブルートフォースアプローチでは、配列のすべての順列を試し、各プレフィックスの MEX を計算し、それらを合計します。 これは原理的には機能しますが、順列の数は`n!`たとえそれが爆発したとしても`n=10`、これは完全に非現実的になります。 

重要な観察は、最小の欠損数を含めた場合にのみ MEX が増加するということです。 したがって、プレフィックス MEX の合計を最大化するには、まず次から始まるすべての個別の数値を含める必要があります。`0`上に順番に。 各数字が最初に出現すると`0,1,2,...`が配置されると、プレフィックスの MEX は段階的に増加します。 

最初に出現した後は、残りの要素は MEX を増加させないため、任意の順序で追加できます。 各プレフィックスの MEX はすでに配置されている一連の数値によって完全に決定されるため、この単純な貪欲な戦略により、正しく効率的なソリューションが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | お(ん!) | O(n) | 遅すぎる |
 | 初めての出来事に貪欲 | O(n + 最大(a)) | O(最大(a)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の各数値の出現数を数えます。 どの数値が少なくとも 1 回存在するかを知る必要があります。 
2. 空の結果配列を初期化します。 
3. ループ元`0`上向きに移動し、配列内に存在する各数値の最初の出現を追加します。 追加された数字ごとに、そのカウントを減らします。 これにより、プレフィックス MEX が各ステップで確実に 1 ずつ増加します。 
4. すべての数字が揃ったら、`0`現在の最大値までが一度処理されると、残りの数値を任意の順序で追加します。 これらは MEX の増加には寄与しませんが、アレイを完成させます。 
5. 結果の配列を出力します。 

**機能する理由**: 各ステップで、欠落している最小の数値を最初に含めることによって、現在のプレフィックスの MEX が最大化されることが保証されます。 プレフィックスに次のすべての番号が含まれると、`0`に`k-1`、MEX は次のようになります。`k`。 後で重複を追加しても MEX を増やすことはできないため、最後に配置するのが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    count = [0] * 102  # numbers are 0..100
    for x in a:
        count[x] += 1
    
    result = []
    # step 1: include each number once to increase MEX
    for i in range(102):
        if count[i]:
            result.append(i)
            count[i] -= 1
    
    # step 2: append remaining numbers in any order
    for i in range(102):
        while count[i]:
            result.append(i)
            count[i] -= 1
    
    print(' '.join(map(str, result)))
```最初のループでは、各プレフィックスが MEX を最適に拡張するようにします。 2 番目のループは残りの数値を処理します。 配列`count`すべての入力数値をカバーするのに十分な大きさであり、インデックス エラーを防ぎます。 すべての数値が ≤100 であるため、境界処理は暗黙的です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        count = [0] * 102
        for x in a:
            count[x] += 1
        result = []
        for i in range(102):
            if count[i]:
                result.append(i)
                count[i] -= 1
        for i in range(102):
            while count[i]:
                result.append(i)
                count[i] -= 1
        print(' '.join(map(str, result)))
    return output.getvalue().strip()

 ## 特殊なケース

 もし`0`が完全に欠落している場合、最初のプレフィックスの MEX は`0`、MEX > 0 で始まるプレフィックスはありません。たとえば、`[1,1,2]`結果として`[1,2,1]`。 すべての要素が同じ場合、MEX は 1 回だけ増加し (0 が存在する場合)、その後は一定のままです。 アルゴリズムは常に最初の出現をチェックするため、これらを正しく処理します。`0`その後、残りの要素を追加します。
