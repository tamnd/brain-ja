 ## 解決策
 ## 問題の理解

 私たちに与えられたボードは、$n$個別の整数なので、2 つの数値を取る演算を繰り返し実行できます。$x$そして$y$ボードから書き込みます$2x - y$。 タスクは、目標数値が達成されるかどうかを判断することです。$k$これらの一連の操作の後に、ボード上に が表示されることがあります。 各テスト ケースには初期の数値と目標が示されます。$k$可能であれば「YES」を出力し、そうでない場合は「NO」を出力する必要があります。 

制約は大きいです:$n$まで可能です$2 \cdot 10^5$、すべての合計$n$テストケース全体での制限も次のとおりです。$2 \cdot 10^5$、数値自体は次のように大きくなる可能性があります。$10^{18}$規模的には。 これは、すべての数値に対して単一のペアごとの演算を繰り返し行うだけでも組み合わせ爆発が発生するため、考えられるすべての演算シーケンスを反復する解決策は実行不可能であることを意味します。 

エッジケースが発生するのは次の場合です$n = 2$なぜなら、数値が 2 つだけであるため、演算のシーケンスは基本的に 2 つの数値の差によって決定される等差数列に制約されるからです。 次の場合には、別の微妙なエッジケースが発生します。$k$はすでにボード上にあります。 既存の数値をチェックせずに常に新しい数値を構築しようとする単純なアプローチでは、次のことをすぐに認識できません。$k$はすでに存在します。 

## アプローチ

 ブルートフォース手法では、操作を通じて取得可能なすべての数値を生成しようとします。$2x - y$すべての数字のペアに対して$x, y$ボード上で。 新しい番号が生成されなくなるまで、これを繰り返すことができます。 この操作では最終的に初期セットの加法閉包内のすべての数値が生成されるため、このアプローチは原理的には正しいです。 ただし、生成される可能性のある数値の数は、特に大規模な場合に爆発的に増加する可能性があります。$n$、次のような操作につながります。$O(n^2 \cdot m)$、 どこ$m$新しく生成された数値の数です。 私たちの制約からすると、これは遅すぎます。 

重要な洞察は、次のことを観察することです$2x - y$次のように書き換えることができます$x + (x - y)$。 これは、この演算により数値の差の倍数を効果的に加算または減算できることがわかります。 言い換えれば、到達できるすべての数値のセットは、すべてのペアごとの差の最大公約数 (GCD) によって生成される算術格子です。 させて$\text{min\_val}$をボード上の最小の数字とし、$d$すべての差の GCD になる$x_i - \text{min\_val}$。 それから数字$k$以下の場合にのみ到達可能です$k - \text{min\_val}$で割り切れます$d$。 これにより、問題は操作のシミュレーションから初期セットでの単純な算術演算に軽減されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$、次にボード上の数字のリストを読みます。 
2. もし$k$すでにリストにある場合は、すぐに「YES」を出力します。 
3. ボード上の最小の数字を特定します。$\text{min\_val}$、参考になるので。 
4. 差を計算する$x_i - \text{min\_val}$すべての数字に対して$x_i$ボード上で GCD を計算し、それを呼び出します$d$。 この GCD は、初期セットから到達可能な数値の算術格子の「ステップ サイズ」を表します。 
5.次のことを確認します$k - \text{min\_val}$で割り切れます$d$。 そうであれば、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

機能する理由: すべての操作$2x - y$初期数値と係数の合計が 2 の累乗となる整数線形結合である数値を生成します。 すべての数値は整数であり、演算は整数演算で終了するため、到達可能な数値のセットは、正確に以下に合同な数値のセットです。$\text{min\_val}$差の GCD を法とする。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        min_val = min(arr)
        if k in arr:
            print("YES")
            continue
        d = 0
        for x in arr:
            d = math.gcd(d, x - min_val)
        if (k - min_val) % d == 0:
            print("YES")
        else:
            print("NO")

solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`大規模なテストケースの場合。 次のような些細なケースをすぐに処理します。$k$がすでに存在しているため、不必要な計算が回避されます。 差に対する GCD の計算により、到達可能性の「ステップ サイズ」が正しいことが保証され、この GCD による割り切れ性のチェックが到達可能性の唯一の必要条件です。

 ## 特殊なケース

 ボードに数字が 2 つしかない場合、一連の演算により、それらの差に等しい差を持つ等差数列を形成する数字が生成されます。 たとえば、ボードが`[2, 5]`そして$k = 11$、差は 3 で、最小の数は 2 です。$(11-2) \% 3 = 9 %3 =0$、 それで$k=11$到達可能です。 このアルゴリズムは GCD を正しく計算し、割り算をチェックして、演算をシミュレートすることなく、負の数を含む小さい整数と大きい整数の両方を処理します。
