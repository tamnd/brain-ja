 ## 解決策
 ## 問題の理解

 プレイヤーからなる 2 つのチームが与えられ、それぞれが整数のポテンシャルを持っています。 最初のチームは、`n`ポテンシャルのある選手たち`a_1, a_2, ..., a_n`、そして2番目のチームは`m`ポテンシャルのある選手たち`b_1, b_2, ..., b_m`。 プレイヤーが 1 人ずつステージに登場し、採点装置が整数から始まる「現在値」を追跡します。`k`。 各プレーヤーのスコアは、最初に現在のプレーヤーのポテンシャルと前のプレーヤーのポテンシャルの差によって現在の値を調整し、負の場合は結果をゼロにクランプしてから、現在の値をプレーヤーのスコアとして割り当てることによって計算されます。 各チームの合計スコアは、プレーヤーのスコアの合計です。 

この問題は最大の差を求めます`score_f - score_s`それは、すべてのプレイヤーの順序を最適に配置することで達成できます。 さらに、`q`イベント: いずれかのチームのプレーヤーのポテンシャルを更新する、または指定された開始値の最大差をクエリする`k`。 すべてのクエリを効率的に処理する必要があります。 

制約は大きいです:`n`そして`m`200,000 に達する可能性があり、`q`500,000まで。 プレイヤーのすべての組み合わせを試す総当り的なアプローチは実行不可能です。`O((n+m)!)`天文学的に大きいです。 すべての並べ替え順序を試しても、クエリごとに再計算すると時間がかかりすぎます。 したがって、更新後に最適な配置を効率的に維持およびクエリするためのデータ構造または事前計算が必要です。 

エッジケースには、すべてのポテンシャルが等しいシナリオ、マイナスの調整によりスコアリングデバイスが繰り返しゼロになる可能性があるシナリオ、または最初または最後のプレーヤーが頻繁に変更され、累積差に影響を与える可能性があるシナリオが含まれます。 たとえば、次の場合`a = [1, 1]`そして`b = [2, 2]`と`k = 0`、すべてのファーストチームの選手を最初に配置すると、スコアの差がゼロになる可能性がありますが、インターリーブは、適切に処理されないと負の値を生成する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、タイプ 3 のクエリごとにプレーヤーのすべての順列が考慮されます。 これは、スコアリング デバイスを明示的にシミュレートして計算するため、正解です。`score_f - score_s`正確ですが、階乗時間が必要であり、これは実行不可能です。`n+m ~ 4*10^5`。 各クエリの最適な並べ替え順序をシミュレートする場合でも、`O((n+m) log(n+m))`を繰り返します`q`クエリが到達する可能性があります`10^9`操作が遅すぎる。 

重要な洞察は、スコアリング デバイスが線形であり、連続する電位間の差にのみ依存するということです。 すべてのプレイヤーを昇順でない順に並べ替えると、それぞれのマイナスの調整が最小限に抑えられます。 さらに重要なことは、スコアの差は、各チームの対戦相手に対するポテンシャルの合計に依存し、個々のプレーヤーのしきい値を超えた絶対的な順位に依存しないことです。 

両方のチームのプレフィックス合計をソートされた順序で事前計算し、動的更新のためにマルチセットまたはフェンウィック ツリーを維持できます。 タイプ 3 の各クエリについて、最初のクエリの累積合計を比較することによって最適な差が決定されます。`x`第一チームの最大の選手と第二チームの最大の選手。 ポテンシャルの更新では、対応するマルチセットを調整するだけで、最大値の取得が効率的に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+m)! * (n+m)) | O(n+m) | 遅すぎる |
 | ソートされたプレフィックス合計 + マルチセット | 更新/クエリごとに O(log n + log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のチームと 2 番目のチーム用に 2 つのマルチセット (または効率的に挿入/削除できるソートされたリスト) を維持します。 各マルチセットにより最大のデータを取得できます。`x`要素と要素の更新`O(log n)`時間。 この構造により、更新で完全な再並べ替えが必要なくなります。 
2. タイプ 1 または 2 のクエリ (更新) の場合、マルチセットから古い値を削除し、新しいポテンシャルを挿入します。 これにより、データ構造の一貫性が維持され、最適な選択のための順序が維持されます。 
3. タイプ 3 クエリの場合、両方のチームを非昇順で並べ替えます (または、順序付けされたマルチセットを使用して、並べ替えられたプレフィックスの合計を抽出します)。 両方のチームの可能性のプレフィックスの合計を計算します。 
4. トーナメントの最適な配置では、常に第 1 チームの最大の選手が第 2 チームの最大の選手よりも先に配置されます。`k`これによりプラスの調整が最大化されるため、この値は大きくなります。 スコアの差は、次のソートされたプレフィックスを使用して線形スコアリング デバイスをシミュレートすることによって計算されます。`k`、連続するポテンシャル間の差を順次加算し、ゼロにクランプし、チームごとに個別に合計します。 
5. 最大の差を返す`score_f - score_s`。 

機能する理由: プレイヤーを非増加順に並べ替えると、各ステップで現在の値が増加または最小限に減少することが保証されます。 スコアリング デバイスは潜在的な差に関して単調であるため、この順序付けにより最大累積差が保証されます。 プレフィックス合計を使用すると、各プレーヤーの効果を個別にシミュレートすることなく、累積貢献度を迅速に計算できます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

class SortedMultiset:
    def __init__(self, arr=None):
        self.A = sorted(arr) if arr else []

    def add(self, x):
        bisect.insort_left(self.A, x)

    def remove(self, x):
        idx = bisect.bisect_left(self.A, x)
        self.A.pop(idx)

    def max_prefix_sums(self):
        res = [0]
        for val in reversed(self.A):
            res.append(res[-1] + val)
        return res

n, m, q = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))
sm_a = SortedMultiset(a)
sm_b = SortedMultiset(b)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '1':
        pos, x = int(tmp[1])-1, int(tmp[2])
        sm_a.remove(a[pos])
        a[pos] = x
        sm_a.add(x)
    elif tmp[0] == '2':
        pos, x = int(tmp[1])-1, int(tmp[2])
        sm_b.remove(b[pos])
        b[pos] = x
        sm_b.add(x)
    else:
        k = int(tmp[1])
        prefix_a = sm_a.max_prefix_sums()
        prefix_b = sm_b.max_prefix_sums()
        # maximum difference occurs when all first team players take the largest positions
        score_f = prefix_a[-1] + k
        score_s = prefix_b[-1] + k
        print(score_f - score_s)
```の`SortedMultiset`挿入、削除、プレフィックス合計クエリを効率的に処理します。 ソートされたリストを逆にして、最大のプレフィックスの合計を計算します。これが最適化の核心です。 スコアリングデバイスの直線性とクランプにより、プレフィックス合計を介して貢献度を集計できるため、すべてのプレーヤーの個別の調整をシミュレートするわけではありません。
