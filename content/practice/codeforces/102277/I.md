 ## 問題の理解

 トラビスには最大 25 人の友人がおり、各友人は 1 から 99 までの背番号を選択しています。トラビスは、自分用に追加の背番号を 1 つ選択することもできます。これも 1 ～ 99 からです。彼は、自分の番号を選択することで、利用可能な背番号のいくつかを連結して、好みの整数を正確に取得できるかどうかを知りたいと考えています。 

選択される背番号の順序は任意です。 背番号は全体として使用する必要があるため、誰かが背番号 75 を持っている場合、トラビスは以下を使用できます。`75`、のみは使用できません`7`またはのみ`5`。 友人のジャージは省略できますし、トラビス自身のジャージも省略できます。 出力は`1`お気に入りの整数を構成できるトラビス数の選択肢が存在する場合、そして`0`さもないと。 公式声明によると、`t < 1,000,000,000`、`n <= 25`、および1から99の範囲の背番号。 

の小さな値`n`指数関数的な検索を提案するかもしれませんが、より強力な制限はお気に入りの整数に対するものです。 10 億未満なので、10 進数は最大 9 桁です。 どのジャージも 1 桁か 2 桁の数字を貢献します。 つまり、ターゲットには、その 10 進表現を有効なジャージ サイズの部分に分割する方法がほんのわずかしかないということです。 可能な分割の数に比例する解決策は簡単に十分に高速ですが、任意のサブセットと最大 25 の友人の順列を列挙するにはコストがかかりすぎます。 

最初のエッジ ケースは、単一の数字で構成されるターゲットです。 たとえば、```
7
1
24
```答えは`1`トラビスはジャージを選ぶだけなので`7`そして単独で使用します。 少なくとも 1 人の友人のジャージが参加する必要があると仮定した解決策は、このケースを誤って拒否することになります。 

内部ゼロには注意が必要です。 例えば、```
101
1
10
```答えがあります`1`、ターゲットは次のように分割できるため、`10 | 1`、既存のジャージと`10`続いてトラビスが選んだジャージ`1`。 すべての数字を独立して扱うと、ゼロを背番号として誤って認識し、それを次のように分割します。`1 | 01`ジャージなので無効になります`01`存在しません。 

背番号の重複もミスの原因です。 例えば、```
2222
3
2 2 2
```答えがあります`1`。 ターゲットにはジャージが 4 枚必要です`2`、3 つは友人から提供され、トラビスは選択できます`2`彼自身。 多重度を忘れたセットベースの実装では、この区別が失われます。 

最後に、ターゲットを完全な値に分割できない場合は、正しい値を持っているだけでは十分ではありません。 例えば、```
715
1
75
```答えがあります`0`。 利用可能なフレンドジャージが貢献します`75`ただし、ターゲットにはどちらかが必要です`7 | 15`または`71 | 5`、そして、どちらの分解も、1 人の友人と 1 つの新しく選択されたジャージを使用して提供することはできません。 

## アプローチ

 直接的な総当たりアプローチでは、友人のサブセットを選択し、そのサブセットの順序を選択し、トラビスのジャージを使用するかどうかを決定し、彼の背番号を選択し、すべてを連結して、結果をターゲットと比較しようとします。 これは正しいです。なぜなら、あらゆる法的解釈はそのような選択によって表されるからです。 問題は可能性の数です。 のために`n = 25`、順序付けられたサブセットの数は

 25!\sum_{j=0}^{25}\frac{1}{j!}、
 】

 これはおよそ`e * 25!`、または約`4.2 * 10^25`。 トラビスのジャージを最大 99 個の選択肢から試すと、次の方向に進みます。`4.2 * 10^27`候補となる建築物。 これは、2 秒のプログラムで調査できる範囲を何桁も超えています。 

重要な観察は、実際には最初に友達を選ぶ必要はないということです。 ターゲット自体が背番号の可能な順序を決定します。 すべてのジャージは 1 ～ 99 の間であるため、ターゲットの各ピースには 1 つまたは 2 つの数字が正確に含まれている必要があります。 ターゲットの場合`L`数字しかありません`L - 1`カットするかカットしないかのポジション。 したがって、最大でも

 [
 2^{L-1} \le 2^8 = 256
 】

 可能なパーティション。 

すべてのパーティションについて、1 桁または 2 桁の数値のシーケンスを取得します。 パーティションに必要なすべての背番号のコピーが何枚あるかを数えることができます。 友人たちはいくつかの背番号のセットを提供します。 パーティションは、必要なコピーがすべて友人間で利用可能である場合に実行可能ですが、不足しているコピーは最大 1 つまで Travis によって提供されます。 

Travis の 99 個の可能な選択肢すべてを試す必要はありません。 パーティションに背番号が 1 つ欠けている場合、トラビスはその番号を選択するだけで済みます。 2 つ以上のコピーが欠落している場合、1 枚のジャージではパーティションを修復できません。 何も不足していない場合、トラビスは有効な背番号を選択し、単にそれを使用しないことができます。 

ブルートフォース手法は、考えられるすべての構造を明示的に検索するため機能しますが、25 人の友人を検索スペースとして扱うと失敗します。 ターゲットの数字が最大 9 桁であるという観測により、検索空間が完全に変わります。 友人の順列を調べる代わりに、ターゲット自体を合法的な背番号に分割できる最大 256 通りの方法を列挙します。

 ## アルゴリズムのチュートリアル

 1. お気に入りの整数を 10 進数の文字列表現に変換します。 有効な構造は背番号の連結であるため、数字を直接処理します。そのため、すべての有効な構造はこの文字列の分割に対応します。 
2. 友達の中で 1 から 99 までの各背番号が何回出現するかを数えます。 周波数配列は、値範囲全体に 99 個の可能性しか含まれていないため便利です。 
3. のすべてのサブセットを列挙します。`L - 1`連続するターゲット桁間のギャップ。 選択されたギャップは、現在の背番号がそこで終わることを意味します。 選択されていないギャップは、次の桁が同じ背番号に属していることを意味します。 
4. 各パーティションについて、ターゲットを左から右にスキャンし、対応する 1 桁または 2 桁の部分を形成します。 背番号は 1 から始まるため、ゼロに等しい部分は拒否されます。また、背番号は先行ゼロなしで与えられるため、ゼロで始まる 2 桁の部分も拒否されます。 
5. 結果として得られるすべての背番号の必要な出現数を数えます。 これらの要件を友人の頻度と比較してください。 すべての値について、欠落しているコピーの数を計算します。 
6. 不足しているコピーの合計数が 1 つ以下であれば、パーティションを受け入れます。 ゼロの場合、友人だけがターゲットを形成できます。 それが 1 つである場合、トラビスはその欠けている背番号を正確に選択します。 2 つ以上の場合、1 枚のジャージでは構築を完了できません。 
7. パーティションが受け入れられた場合は、印刷します。`1`。 すべてのパーティションに障害が発生した場合は、印刷します`0`。 

### なぜ効果があるのか

 お気に入りの整数の有効な構造を考えてみましょう。 その構造内のすべての背番号は 1 桁または 2 桁のいずれかであるため、この構造ではターゲットの 10 進数文字列の一意の分割が生じます。 私たちの列挙ではそのパーティションを調べます。 その頻度の比較では、必要なジャージのコピーがすべて友人から提供され、さらにトラビスが選択したジャージが 1 枚までである場合を正確に受け入れます。 したがって、あらゆる有効な構造が受け入れられます。 逆に、受け入れられたすべてのパーティションは、その連結がまさにターゲットとなる法定の背番号のシーケンスを記述しており、必要に応じて Travis が欠損値を 1 つ選択した後、頻度テストによって必要なコピーが実際に存在することが保証されます。 したがって、アルゴリズムは次の値を返します。`1`有効な構造が存在する場合にのみ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = int(input())
    friends = list(map(int, input().split()))

    freq = [0] * 100
    for x in friends:
        freq[x] += 1

    length = len(t)

    # There are length - 1 possible cut positions.
    # A mask describes which positions are cuts.
    for mask in range(1 << (length - 1)):
        need = [0] * 100
        pos = 0
        missing = 0
        valid = True

        while pos < length:
            if pos + 1 < length:
                # If there is a cut after this digit, use one digit.
                if mask & (1 << pos):
                    value = ord(t[pos]) - ord('0')
                    pos += 1
                else:
                    # Otherwise use two digits.
                    if t[pos] == '0':
                        valid = False
                        break
                    value = (ord(t[pos]) - ord('0')) * 10
                    value += ord(t[pos + 1]) - ord('0')
                    pos += 2
            else:
                value = ord(t[pos]) - ord('0')
                pos += 1

            if value == 0:
                valid = False
                break

            need[value] += 1

        if not valid:
            continue

        for value in range(1, 100):
            if need[value] > freq[value]:
                missing += need[value] - freq[value]
                if missing > 1:
                    break

        if missing <= 1:
            print(1)
            return

    print(0)

if __name__ == "__main__":
    solve()
```周波数配列には、友人の個別のジャージ値だけではなく、友人のマルチセットが格納されます。 ジャージが2枚あるのでこれが必要です`7`ジャージ 1 枚とは異なるリソースです`7`。 

マスクには、隣接するターゲット桁間のギャップごとに 1 ビットがあります。 噛んだとき`pos`が設定されている場合、その桁は`pos`現在のジャージが終了するため、次のピースが始まります`pos + 1`。 クリア時は2桁まとめて消費します。 背番号は最大でも 2 桁なので、可能性はこの 2 つだけです。 

最後の桁は常に 1 桁のジャージとして消費されなければなりません。 ループはこれを次のように処理します。`pos + 1 < length`条件を満たし、最後の桁での範囲外アクセスを回避します。 

小切手`t[pos] == '0'`2 桁の数値を作成する前に、次のような値を回避します。`01`ジャージとして扱われることから`1`。 別個の`value == 0`チェックはスタンドアロンのゼロを拒否します。 

の`missing`トラビスがどのジャージを選ぶべきかを事前に決定しようとするのではなく、リソース不足に対抗することです。 正確に 1 つのコピーが欠落している場合、その値が Travis の最適な選択となります。 コピーが欠けていない場合、彼のジャージは使用する必要がないため無関係です。 

Python の整数には任意の精度があるため、オーバーフローの問題はありません。 さらに重要なことは、ターゲットは文字列として保持されるため、潜在的に長い連結値に対して演算を実行する理由がありません。

def solve():

                pos += 1

                break

    finally:

        input = old_input
