 ## 解決策
 ## 問題の理解

 このタスクは、すべての文字の頻度のパリティに従って小文字の文字列を分類することです。 すべての文字が偶数回出現する場合でも、文字列が呼び出されます。 すべての小文字が奇数回出現する場合、奇数と呼ばれます。 どちらの条件も当てはまらない場合、答えは 2 です。入力には長さ 70 以下の空でない小文字文字列が 1 つ含まれ、出力は単一の整数で、偶数文字列の場合は 0、奇数文字列の場合は 1、それ以外の場合は 2 になります。 

短いバインドの長さにより、実際のイメージが大幅に変わります。 文字列全体を 26 個の小文字ごとに 1 回スキャンするソリューションでも、実行される文字チェックは最大 (26 \times 70 = 1820) 回であり、1 秒の制限の下では些細なことです。 必要な情報は各文字の周波数のパリティだけであるため、シングル パスの方が依然としてクリーンなソリューションです。 

最初のエッジ ケースは 1 文字の文字列です。 たとえば、入力`a`生産すべき`1`、 なぜなら`a`は 1 回出現しますが、その他の小文字は 0 回出現します。 0 は偶数、1 は奇数であるため、すべてのアルファベット文字が正確に奇数回存在する場合にのみ、すべての文字が奇数の頻度を持ちます。 これは、次の正しい結果を意味します`a`実は`2`、 ない`1`。 文字列内に出現する文字のみをチェックする不注意な実装では、文字列が誤って奇数として分類されてしまいます。 

2 番目のエッジ ケースは、すべての小文字を 1 回だけ含む文字列です。 例えば、`abcdefghijklmnopqrstuvwxyz`生成する`1`。 26 文字がすべて 1 回出現するのは奇妙です。 観測されたすべてのカウントが奇数であるかどうかのみをチェックする実装では、このケースを正しく処理できますが、存在しない文字の頻度がゼロであることを忘れた実装では、次のような短い文字列も誤って受け入れられます。`a`。 

3 番目のエッジ ケースは、長さが均等なすべて等しい文字列です。 例えば、`aaaa`生成する`0`、 なぜなら`a`は 4 回出現し、他の文字は 0 回出現します。 「even」を単に偶数の文字列長を持つものとして解釈する不注意な実装は、たまたまこの例には合格しますが、失敗します。`aabbc`、その長さも奇数ですが、その文字頻度のパリティが実際の分類を決定します。 

## アプローチ

 直接的な総当たりアプローチは、26 個の小文字をそれぞれ独立して考慮することです。 すべての文字について、文字列全体をスキャンし、その文字が出現する回数を数えます。 すべてのカウントがわかったら、26 個のカウントがすべて偶数であるか、または 26 個のカウントがすべて奇数であるかを確認します。 この定義は各文字の周波数パリティのみに依存するため、これは正しいです。 最大文字列長が 70 の場合、最悪の場合でも (26 \times 70 = 1820) 個の文字比較が実行され、さらに少量のブックキーピングが実行されるため、十分に高速になります。 指定された制約の下では、この特定のブルート フォース手法が問題となる入力サイズはありません。 

よりクリーンなアプローチは、文字列の再スキャンを避けることです。 小文字ごとに 1 つずつ、計 26 個のカウンタを維持し、文字が読み取られるたびに対応するカウンタをインクリメントします。 1 回のパスの後、26 個のカウンターすべてのパリティを検査します。 すべてのカウンタが偶数の場合、答えは 0 です。そうでない場合、すべてのカウンタが奇数の場合、答えは 1 です。どちらの条件も当てはまらない場合、答えは 2 です。 

重要な観察は、パリティが判明すると実際の周波数は無関係であるということです。 各カウントのパリティを通じてゼロ、偶数、奇数を区別するだけで済みます。 アルファベットは 26 文字に固定されているため、すべてのカウンタをチェックするのは継続的な作業です。 

アルファベットは小さいため、総当たり攻撃は機能しますが、同じ文字を繰り返し検査します。 1 回の共有トラバーサル中にすべての文字をカウントできるという観察により、この繰り返しがなくなり、文字列処理が 1 回のパスに減ります。

 | 最適 | O(n) | O(26) = O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`cnt`エントリは 26 個あり、最初はすべてゼロです。 エントリ`i`アルファベットインデックスが以下である小文字の出現数を格納します。`i`。 
2. すべての文字をたどる`ch`文字列と増分で`cnt[ord(ch) - ord('a')]`。 このマップは`a`を通して`z`辞書を必要とせずにインデックス 0 ～ 25 に変換します。 
3. すべての値が次のとおりであるかどうかを確認します。`cnt`は均等です。 その場合は印刷してください`0`, すべての小文字が偶数回出現するためです。 
4. 文字列が偶数でない場合は、すべての値が偶数かどうかを確認します。`cnt`奇数です。 その場合は印刷してください`1`, すべての小文字が奇数回出現するためです。 
5. どちらの条件も当てはまらない場合は、印刷します。`2`。 少なくとも 1 つの文字は偶数の頻度を持ち、少なくとも 1 つの文字は奇数の頻度を持ちます。そのため、文字列は偶数でも奇数でもありません。 

不変条件は、文字列の接頭辞を処理した後、`cnt[i]`は、そのプレフィックス内の対応する文字の出現数と同じです。 したがって、文字列全体が処理されると、配列にはすべての小文字の正確な頻度が含まれるようになります。 最後の 2 つのパリティ チェックは 2 つの特別な分類の定義と直接一致するため、残りのケースは 2 である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    if all(x % 2 == 0 for x in cnt):
        print(0)
    elif all(x % 2 == 1 for x in cnt):
        print(1)
    else:
        print(2)

if __name__ == "__main__":
    solve()
```最初の行は文字列のみを読み取り、末尾の改行を削除します。 入力には小文字が含まれることが保証されているため、追加の検証は必要ありません。 

の`cnt`配列は 26 文字に直接対応します。 表現`ord(ch) - ord('a')`改宗する`a`0まで、`b`1 まで、以下同様`z`すべての文字は 1 回だけ処理されます。 

最初`all`出現しない文字を含むアルファベット全体の偶数条件をチェックします。 存在しない文字のカウントは 0 であり、0 は偶数であるため、これらの文字はテストに含める必要があります。 

2番目`all`奇妙な状態をチェックします。 このため、次のような文字列が使用されます。`a`は奇数として分類されません。他の 25 文字のカウントは 0 であり、偶数です。 

Python では整数オーバーフローの懸念はなく、最大数は 70 のみです。入力には 1 つのテスト ケースが含まれるため、テスト ケース ループは必要ありません。 

## 実用的な例

 サンプル 1 の場合、文字列は次のとおりです。`coachessoaehwwwwww`。 関連する頻度カウントを以下に示します。 

| キャラクター | カウント | パリティ |
 | --- | --- | --- |
 | | 1 | 奇数 |
 | c | 1 | 奇数 |
 | e | 2 | 偶数 |
 | h | 1 | 奇数 |
 | o | 2 | 偶数 |
 | s | 2 | 偶数 |
 | w | 6 | 偶数 |
 | 他のすべての文字 | 0 | 偶数 |

 この文字列には奇数と偶数の両方の周波数が含まれているため、偶数でも奇数でもありません。 出力は`2`。 

サンプル 2 の場合、文字列は次のとおりです。`coachesc`。 

| キャラクター | カウント | パリティ |
 | --- | --- | --- |
 | | 1 | 奇数 |

 | 他のすべての文字 | 0 | 偶数 |

 ここでも、周波数パリティが混合されます。 出力は`2`。 

他の付属サンプル入力`coachessoaehwwwwww`すべての文字数が偶数であるため、次のようになります。`0`。 サンプル`coachesarefun`混合パリティがあり、`2`。

## テストケース```python
import sys
import io

def solve():
    s = input().strip()

    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    if all(x % 2 == 0 for x in cnt):
        print(0)
    elif all(x % 2 == 1 for x in cnt):
        print(1)
    else:
        print(2)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        solve()
        result = sys.stdout.getvalue()
        sys.stdout = old_stdout
        return result
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
assert run("coachessoaehwwwwww\n") == "0\n", "sample 1"
assert run("coachesarefun\n") == "2\n", "sample 2"
assert run("coachessoaehwwwwww\n") == "0\n", "sample 3"
assert run("coachesc\n") == "2\n", "sample 4"

# Minimum-size input
assert run("a\n") == "2\n", "single character"

# All 26 letters occur exactly once
assert run("abcdefghijklmnopqrstuvwxyz\n") == "1\n", "every letter once"

# All equal, even frequency
assert run("aaaa\n") == "0\n", "all equal with even count"

# Boundary length, all characters occur an even number of times
assert run("aabbccddeeffgghhiijjkkllmm\n") == "0\n", "26-letter boundary"

# Mixed parity
assert run("aab\n") == "2\n", "mixed frequency parity"

 |`a`|`2`| 最小長と欠落文字を考慮するための要件 |
 |`abcdefghijklmnopqrstuvwxyz`|`1`| すべてのアルファベット文字は奇数の頻度を持ちます。 
|`aaaa`|`0`| 偶数頻度のすべて等しい文字列 |

 ## 特殊なケース

 1文字入力の場合`a`、アルゴリズムは次のようにカウントを作成します。`a = 1`1 つおきの文字はゼロに等しい。 偶数テストは失敗します。`a`奇数の周波数を持っています。 他の 25 文字の頻度がゼロであるため、奇数のテストも失敗します。 結果は`2`これにより、出現する文字だけをチェックするというよくある間違いを回避できます。 

入力用`abcdefghijklmnopqrstuvwxyz`、すべてのカウンターは正確に 1 つです。 偶数テストはすべての文字で失敗しますが、奇数テストは 26 個のカウンタすべてで成功します。 結果は`1`。 これにより、アルファベット全体が実行され、アルゴリズムがアルファベットの終わり近くの文字を誤って無視しないことが確認されます。 

のために`aaaa`、のカウンター`a`は 4 になり、他のすべてのカウンタは 0 のままになります。 26 個のカウントはすべて偶数であるため、結果は次のようになります。`0`。 このケースでは、アルゴリズムが個別の文字の数ではなく頻度をチェックしていることも確認されています。 

のために`aabbccddeeffgghhiijjkkllmm`, すべての小文字は正確に 2 回現れます。 すべてのカウンタは偶数であり、入力で明示的に表されるすべての文字が含まれるため、結果は次のようになります。`0`。 これは、すべての周波数を均等に保ちながらアルファベット全体を含むため、有用な境界ケースです。 

のために`aab`、周波数は`a = 2`、`b = 1`、残りの文字はすべてゼロに等しい。 一部のカウントは偶数であり、一部は奇数であるため、どちらのグローバル条件も当てはまらず、アルゴリズムは出力します。`2`。 これにより、個々の文字頻度のパリティではなく、文字列全体の長さのパリティから誤って答えを決定する実装が捕捉されます。
