 ## 解決策
 ## 問題の理解

 Timothy には、幅と高さが固定された長方形のボックスがあります。 すべてのチョコレート バーは整数の寸法を持ち、回転せずにボックス内に収まる必要があり、可能な寸法の各ペアは最大 1 回使用できます。 寸法 (a \times b) のバーのコストは (a b) です。 

方向はバーのアイデンティティの一部です。 (5\times3) バーと (3\times5) バーは異なるギフトですが、2 つの (5\times5) バーは同一であり、使用できるのは 1 つだけです。 したがって、箱の寸法が (W\times H) である場合、考えられるギフトは正確に (WH) 順序のペアになります。 

[
 1\le a\le W、\qquad 1\le b\le H.
 】

 タスクは、ティモシーの貯蓄残高 (B) 内にそれらの面積の合計 (総コストでもある) を維持しながら、できるだけ多くの異なるペアを選択することです。 出力は、作成できるバーの最大数です。 

公式コンテストのページでは、制限時間は 3 秒、メモリ制限は 256 MB と規定されています。 この難しさは、長方形が非常に多くの可能な次元のペアを表すことができるため、すべての (WH) バーを列挙することが実行可能な戦略ではないという事実に起因します。 バーのコストは製品 (ab) にのみ依存するという事実を利用する必要があります。 

最初の明白ではないエッジ ケースは、正方形のボックスです。 (2\times2) ボックスの場合、考えられる 4 つの次元のコストは (1,2,2,4) になります。 予算 (5) の場合、正解は (3) です。これは (1\times1)、(1\times2)、および (2\times1) を選択できるため、合計コストは (5) になります。 (1\times2) と (2\times1) を同じバーとして扱う不注意な実装では、(2) が返されます。 

2 番目のエッジケースは、予算が少なすぎて何も買えない場合に発生します。 (3\times3) ボックスと予算 (0) の場合、正解は (0) です。 すべての法定バーにはプラスの面積があるため、最も安いバーを選択すると、すでに予算を超えてしまいます。 少なくとも 1 つのバーが常に選択できると想定している実装では、誤って (1) が返されます。 

3 番目のエッジケースは、予算が十分に大きく、可能なすべてのバーを購入できる場合です。 (2\times2) ボックスの場合、4 本のバーすべての合計コストは (1+2+2+4=9) になります。 予算 (9) の場合、答えは (4) になります。 考えられるすべてのディメンション ペアを取得できるため、手頃なプレフィックスを見つけた後で停止する理由はありません。 

## アプローチ

 直接的なアプローチは、考えられるすべてのペア ((a,b)) を生成し、そのコスト (ab) を計算し、すべての (WH) コストを並べ替えて、合計が予算内に収まる最も安価なプレフィックスを取得することです。 これは正しいです。なぜなら、すべてのバーは私たちにとって同じ価値を持っているからです。つまり、追加の生徒が 1 人プレゼントを受け取るということです。そのため、固定数のバーの中で、入手可能な最も安価なものを常に選択する必要があります。 

問題はペアの数です。 乗算表全体の生成にはすでに (O(WH)) 回の操作が必要であり、それを保存するには (O(WH)) 個のメモリが必要です。 両方の寸法が大きい場合、これは 3 秒のソリューションで対応できる範囲をはるかに超えます。 テーブルの保存を回避してすべてのペアをスキャンするバージョンでも、(WH) 乗算は実行されます。 

重要な観察は、実際にはソートされた順序で個々のバーを知る必要がないということです。 値 (x) については、面積が最大 (x) であるすべてのバーを考慮します。 固定幅 (a) の場合、許容される高さは次の条件を満たします。 

[
 b\le \left\lfloor\frac{x}{a}\right\r フロア。 
】

 ボックスは高さを (H) に制限しているため、行 (a) 内のそのようなバーの数は次のようになります。 

[
 t_a=\min\left(H,\left\lfloor\frac{x}{a}\right\rfloor\right)。 
】

 これにより、すべてのペアを列挙することなく、コストが最大 (x) のバーの数とその合計コストの両方を計算できます。 

残りの困難は、考えられるすべての (a) を合計することです。 (a) が大きくなると、値 (\lfloor x/a\rfloor) は長期間にわたって一定のままになります。 小さい (a) 値を個別に処理し、同じ商を持つグループ内の大きい値を処理できます。 これは標準的なフロア分割グループ化手法であり、1 つのクエリに対して (O(\sqrt{x})) の作業量を与えます。

この関数をさらにきれいに使用する方法があります。 (F(x)) を、コストが最大 (x) であるすべての法的バーの合計コストとします。 (F(x)>B) となる最小の (x) を見つけることができます。 次に、(x) より安いすべてのバーを購入できますが、(x) は次の別個のバーのグループのコストです。 残りのお金で、これらの (x) コストのバーをいくつか購入できます。 これにより、バーの数に対する 2 回目の二分探索が回避されます。 

ソートによって可能な限り最も安価なプレフィックスが正確に得られるため、ブルートフォース手法が機能します。 九九が大きすぎるため失敗します。 同じ面積を持つすべてのバーがしきい値グループを形成するという観察により、グループ全体を一度に数えて合計することができ、問題をフロア分割の合計と 1 回の二分探索に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(WH\log(WH))) | (O(WH)) | 遅すぎる |
 | しきい値のグループ化 | (O(\sqrt B\log B)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (W) と (H) をボックスの寸法、(B) を節約額とします。 すべての合法なチョコレート バーは、(1\le a\le W) および (1\le b\le H) を含む 1 つの順序ペア ((a,b)) に対応し、そのコストは (ab) です。 
2. 考えられるすべてのバーの合計コストを計算します。 

[
 T=\frac{W(W+1)}2\cdot\frac{H(H+1)}2.
 】

 (B\ge T) の場合、可能なすべてのバーを購入できるため、答えは単純に (WH) になります。 

1. 定義する`stats(x)`2 つの値を返します。 1 つ目は、最大 (x) の面積を持つ合法的なバーの数です。 2 番目はそれらの面積の合計です。 

固定幅 (a) の場合、使用可能な高さの数は次のとおりです。 

[
 t=\min(H,\lffloor x/a\rfloor)。 
】

 この幅によって寄与される数値は (t) ですが、そのコスト寄与は

 a\frac{t(t+1)}2.
 】

 1. (t=H) となるすべての幅をまとめて扱います。 これは次のような場合に起こります。 

[
 \le \left\lfloor\frac{x}{H}\right\r フロア。 
】

 この範囲に (m) 個の幅が含まれる場合、それは (mH) 個のバーと

 [
 \frac{m(m+1)}2\frac{H(H+1)}2
 】

 総コスト。 

この最初の範囲をグループ化することが重要なのは、この範囲には膨大な数の幅が含まれる可能性がある一方で、各範囲の有効な高さの数はまったく同じであるためです。 

1. 残りの小さな幅については、(\lfloor\sqrt{x}\rfloor) まで直接繰り返します。 そのような値は (O(\sqrt{x})) 個だけです。 
2. (a>\sqrt{x}) になると、商 (\lfloor x/a\rfloor) は小さくなります。 電流 (a) については、(q=\lfloor x/a\rfloor) とします。 同じ商は次の期間まで有効です。 

[
 r=\left\lfloor\frac{x}{q}\right\rloor。 
】

 したがって、(a) から (r) までのすべての幅をまとめて処理できます。 カウントに対するそれらの寄与は、間隔の長さに (q) を乗算したものであり、コストの寄与は次のようになります。 

[
 \left(\sum_{i=a}^{r}i\right)\frac{q(q+1)}2.
 】

 1. これで、最大 (x) の面積を持つすべてのバーの合計コスト (F(x)) を計算する方法がわかりました。 (F(x)) は非減少であるため、次のような最小の (x) を二分探索します。 

[
 F(x)>B。 
】

 検索の上限は (\min(WH,B+1)) として取得できます。 すべてのバーが手頃な価格ではない場合、予算を超える最初の領域を (B+1) より大きくする必要はありません。 

1. この最初の値を (x) とします。 面積が最大 (x-1) のすべてのバーの数と合計コストを計算します。 これらのバーはすべて購入できます。 
2. しましょう`remaining = B - cost`。 次のコスト グループに残っているすべての候補のコストは正確に (x) であるため、購入できます。 

[
 \left\lfloor\frac{\text{残り}}x\right\rloor
 】

 もっとバーを。 

1. この数値をコストが (x) 未満のバーの数に追加します。 その結果、ギフトの最大数が得られます。 

### なぜ効果があるのか

 不変条件は、任意のしきい値 (x) に対して、`stats(x)`コストが最大 (x) であるリーガル バーの完全なセットを正確に記述します。 どのバーにも同じ利点があるため、最適なソリューションは常に入手可能な最も安価なバーで構成されます。 (x) を、そのグループ全体が予算を不十分にする最小のコストしきい値とします。 コストが (x) 未満のすべてのバーは、最適なソリューションで取得する必要があります。これは、それらのいずれかをより高価なバーに置き換えてもギフトの数を改善できないためです。 それらを採用した後、残りの候補者はすべて正確に (x) のコストがかかるため、残りの予算が許す限り多くの候補者を採用することが最適です。 しきい値のグループ化は、これらのバーのカウント方法のみを変更し、どのバーが表示されるかを変更します。 

## Python ソリューション```python
import sys
from math import isqrt

input = sys.stdin.readline

def solve_case(W, H, B):
    total_bars = W * H
    total_cost = (W * (W + 1) // 2) * (H * (H + 1) // 2)

    if B >= total_cost:
        return total_bars

    if B <= 0:
        return 0

    def stats(x):
        if x <= 0:
            return 0, 0

        # For a <= m, every height 1..H is affordable.
        m = min(W, x // H)

        count = m * H
        cost = (
            m * (m + 1) // 2
            * (H * (H + 1) // 2)
        )

        left = m + 1
        if left > W or left > x:
            return count, cost

        root = isqrt(x)

        # Small widths are processed individually.
        right = min(W, root)

        for a in range(left, right + 1):
            t = min(H, x // a)
            if t <= 0:
                break

            count += t
            cost += a * t * (t + 1) // 2

        left = max(left, root + 1)

        # For a > sqrt(x), floor(x / a) is constant on intervals.
        while left <= W and left <= x:
            q = x // left
            if q <= 0:
                break

            right = min(W, x // q)
            t = min(H, q)

            length = right - left + 1
            count += length * t

            sum_a = (left + right) * length // 2
            cost += sum_a * t * (t + 1) // 2

            left = right + 1

        return count, cost

    # If not all bars fit, the first area whose complete group
    # makes the total exceed B is at most B + 1.
    lo = 1
    hi = min(total_bars if total_bars < B + 1 else B + 1,
             W * H)

    while lo < hi:
        mid = (lo + hi) // 2
        _, cost = stats(mid)

        if cost > B:
            hi = mid
        else:
            lo = mid + 1

    x = lo

    count_before, cost_before = stats(x - 1)
    remaining = B - cost_before

    return count_before + remaining // x

def solve(data):
    values = list(map(int, data.split()))
    if not values:
        return ""

    W, H, B = values[:3]
    return str(solve_case(W, H, B))

def main():
    data = sys.stdin.buffer.read()
    sys.stdout.write(solve(data) + "\n")

if __name__ == "__main__":
    main()
```の最初の部分`solve_case`九九全体が手頃な価格である場合を処理します。 三角和の積により、考えられるすべての順序付けされた寸法ペアの正確な合計面積が得られます。`stats(x)`が中心的なルーチンです。 表現`m = min(W, x // H)`までのすべての高さの幅を識別します`H`敷居の下に収まります。 等差級数の数式を使用してそれらの寄与を計算すると、潜在的に巨大なループが防止されます。 

ダイレクトループは最大の幅をカバーします。`sqrt(x)`。 その時点以降、`x // a`は小さく、比較的まばらな位置でのみ変化します。 表現`right = min(W, x // q)`商が維持される最大の間隔を見つけます`q`。 その区間内のすべての幅の合計は、標準の等差級数公式を使用して計算されます。 

二分探索では、バーの数ではなく総コストが使用されます。 これは実装の微妙な部分です。 もし`x`面積を持つすべてのバーのコストが最大となる最初の値です`x`予算を超えてしまった場合、`x`実際のバーのコストに相当する必要があります。 さもないと`F(x)`等しいだろう`F(x-1)`、ミニマルさと相反します。 その結果、境界にある選択されていないすべてのバーのコストが正確になります。`x`、つまり整数除算`x`まだ余裕のある数を正確に示します。 

Python の整数には任意の精度があるため、次のような積が得られます。`W * (W + 1) * H * (H + 1)`オーバーフローしないでください。 この式では、乗算の後にのみ整数の除算が使用され、浮動小数点の丸めが回避されます。 検索は両側を包含し、評価します。`stats(x - 1)`これは、安価なバーを境界グループから分離するものです。

 ## 特殊なケース

 正方形のボックスの場合でも、方向が重要です。 入力時`2 2 5`、アルゴリズムはコスト (1,2,2,4) を計算します。 閾値 (2) では、`stats(2)`カウント (3) とコスト (5) を返します。 次のしきい値は (4) で、その累積コストは (9) であるため、答えは (3) のままです。 (1\times2) と (2\times1) は両方とも、外側の合計の異なる幅に対応するためカウントされます。 

空の予算の場合は、次のように入力します。`3 3 0`すぐに戻ります`0`。 実装チェック`B <= 0`したがって、ゼロ境界コストで除算したり、正のコストのバーが選択できると想定したりすることはありません。 

考えられるすべてのバーが適合すると、入力は`2 2 9`二分探索の前に処理されます。 総費用は

 [
 \frac{2\cdot3}{2}\frac{2\cdot3}{2}=9、
 】

 これは予算と同じなので、すべての (2\cdot2=4) バーが手頃な価格になります。 また、この早期終了により、答えが単に可能な次元ペアの合計数である場合に、不必要なしきい値の計算が防止されます。 

1次元の場合`1 5 15`、考えられるコストは (1,2,3,4,5) で、その合計は (15) です。 完全な手頃な価格チェックでは (5) が返されます。 このケースは、1 つの次元が正確に 1 であり、活用できる 2 次元構造がない場合でも、商グループ化コードが機能する必要があるため便利です。 

大きいケースの場合`1000000 1000000 1`、最も安いバーは (1\times1) で、コストは正確に (1) です。 結果的に答えは(1)となります。 検索では、100 万単位のグリッドを列挙する必要はありません。 しきい値は最小コストの近くにすぐにあり、グループ化された式は長方形の残りの部分を暗黙的に表します。
