 ## 解決策
 ## 問題の理解

 この問題では、2 つのサッカー チームがデカルト平面上に配置されます。 各チームには (n) 人のプレーヤーがいるため、合計で (2n) 個の異なるポイントがあります。 プレイヤーのポジションは決して変わりません。 

プレーヤーが別のプレーヤーに直接ボールをパスできるのは、両プレーヤーが同じチームに属しており、両プレーヤーを結ぶ直線上で厳密に両チームの間に他のプレーヤーが存在しない場合に限られます。 パスの距離は関係ありません。 

ボールはチーム 1 のプレーヤー 1 から始まり、目標は、できるだけ少ないパスを使用してチーム 1 のプレーヤー (n) に到達することです。 ターゲットに到達する一連の正当なパスがない場合、答えは (-1) になります。 

元のコンテストのステートメントでは (2 \le n \le 11) が与えられますが、すべての座標は 1 から 999 までの整数であり、すべての (2n) プレイヤーの位置は個別です。 制限時間は 1 秒、メモリ制限は 256 MB です。 頂点の数は最大 22 個であるため、(O(n^3)) アルゴリズムでも数千回の幾何学的チェックしか実行されません。 本当の問題はグラフのサイズではなく、幾何学的探索を必要とするのではなく、通過ルールが最短経路問題を形成することを認識することです。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 まず、チームメイト 2 人の間にいる敵がパスをブロックします。 例えば、```
2
1 1 3 1
2 1 2 2
```チーム 1 は ((1,1)) と ((3,1)) にあり、対戦相手は ((2,1)) にいます。 正しい出力は次のとおりです```
-1
```唯一可能なチーム 1 のパスがブロックされているためです。 3 つの点が同一線上にあるかどうかだけをチェックし、3 番目の点が端点の間にあるかどうかをチェックしないテストでは、実装によっては間違ったセグメントが誤って拒否または受け入れられる可能性があります。 

次に、2 人のプレーヤーの間のチームメイトもダイレクトパスをブロックしますが、そのチームメイトが中間の頂点になる可能性があります。 例えば、```
3
1 1 3 1 5 1
1 3 3 3 5 3
```((1,1),(3,1),(5,1)) にチーム 1 のプレーヤーがいます。 プレーヤー 1 はプレーヤー 2 が間にあるためプレーヤー 3 に直接パスすることはできませんが、プレーヤー 1 がプレーヤー 2 にパスし、その後プレーヤー 2 がプレーヤー 3 にパスすることはできます。正しい出力は次のとおりです。```
2
```「間にチームメイトがいる」ということをターゲットが到達不可能であることを意味するものとして扱う不注意な解決策は、この道を逸してしまうでしょう。 

第三に、共線性だけでは十分ではありません。 同じ無限線上にあるがセグメントの外側にいるプレーヤーはパスをブロックしません。 例えば、```
2
1 1 3 1
5 1 5 2
```((1,1)) と ((3,1)) の間にプレーヤーがないため、正しい出力は次のようになります。```
1
```外積のみをチェックし、「間」条件を無視するソリューションでは、このパスがブロックされていると誤って宣言されてしまいます。 

## アプローチ

 最も直接的な総当たりのアイデアは、プレーヤー 1 からプレーヤー (n) に到達するまでのパスの可能なすべてのシーケンスを列挙することです。 これは正しいです。なぜなら、すべての法的解はまさにそのようなグラフ エッジのシーケンスであるからです。 頂点を繰り返しても最短パスを改善することはできないため、単純なパスのみに注目することができます。 プレーヤーは最大 22 人で、何人でも参加できます

 [
 \sum_{k=0}^{20} P(20,k)
 】

 開始点からターゲットまでのさまざまな単純なパス (P(20,k)=20!/(20-k)!)。 この量は (20!)、およそ (6.6\cdot10^{18}) のオーダーであるため、パスを列挙することは完全に非現実的です。 

ブルート フォースは、通過する可能性のあるシーケンスを正確に探索するため機能しますが、シーケンスの数が階乗的に増加するため失敗します。 重要な観察は、問題の幾何学的部分は直接パスが存在するかどうかを判断するためにのみ必要であるということです。 これらの正当なパスが判明すると、問題は重み付けされていない通常の最短経路問題になります。 

すべてのプレーヤーに対して 1 つのグラフ頂点を作成できます。 対応するプレーヤーがチームメイトであり、厳密にそれらの間にプレーヤーがいない場合、2 つの頂点を接続します。 すべての正当なパスのコストは正確に 1 つであるため、パスの最小数は正確にチーム 1 プレーヤー 1 とチーム 1 プレーヤー (n) の間の最短パス距離になります。 

頂点は最大でも 22 個あるため、単純にすべてのプレーヤーのペアをテストし、3 人おきのプレーヤーをスキャンして、ペアが接続されているかどうかを判断できます。 これには (O(n^3)) 時間がかかります。 グラフが構築された後、BFS は (O(n^2)) 内の最短パスを見つけます。これは幾何学的な前処理と比較すると無視できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の (O(20!)) パス探索 | (O(n)) 再帰の深さ | 遅すぎる |
 | 最適 | (O(n^3)) | (O(n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての (2n) プレーヤーを 1 つの配列に保存します。 最初 (n) 人のプレーヤーはチーム 1 に属し、残りの (n) プレーヤーはチーム 2 に属します。これにより、すべての幾何学的チェックが 1 つの共通のインデックス付けスキームで機能するようになります。 
2. 異なるプレーヤーの各ペア (u、v) について、最初にそれらが同じチームに属しているかどうかを確認します。 彼らが異なるチームに所属している場合、パスはチームメイト間でのみ許可されるため、彼らの間に優位性が存在することはあり得ません。 
3. 同じチームのペアの場合は、他のすべてのプレーヤーを検査します (w)。 外積を計算する

 [
 (v-u)\times(w-u)。 
】

 ゼロ以外の場合、(w) は (u) と (v) を通る線上にないため、パスをブロックできません。 

1. 外積がゼロの場合、(w) が (u) から (v) までのセグメント内にあるかどうかを確認します。 別個の点の場合は、共線性がすでに確立されている後で、その座標が端点の座標範囲内にあることを確認するだけで十分です。 そのような選手がいる場合、ダイレクトパスはブロックされます。 
2. セグメントをブロックするプレイヤーがいない場合は、(u) と (v) の間に無向グラフ エッジを追加します。 通過はどちらの方向にも機能するため、グラフには方向性がありません。 
3. チーム 1 プレーヤー 1 を表す頂点 0 から BFS を実行します。その距離を 0 に初期化し、他のすべての距離を (-1) に初期化します。 BFS が最初に頂点に到達するとき、すべてのグラフ エッジのコストは同じであるため、その距離は頂点に到達するために必要な最小パス数になります。 
4. チーム 1 プレーヤー (n) を表す頂点 (n-1) の距離を返します。 BFS がそれに到達しない場合、保存された値は (-1) のままになります。これはまさに必要な結果です。 

機能する理由: 対応するパスが正当な場合に、グラフにエッジが含まれます。 したがって、正当なパスのすべてのシーケンスはグラフ パスに対応し、すべてのグラフ パスは有効なパスのシーケンスに対応します。 各パスのコストは 1 であるため、パス数を最小限に抑えることは、重み付けされていない最短のグラフ パスを見つけることと同じです。 BFS はその最短距離を返すため、アルゴリズムはそれより小さいまたは大きい有効な答えを生成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, team1, team2):
    points = team1 + team2
    total = 2 * n

    graph = [[] for _ in range(total)]

    def blocked(a, b):
        ax, ay = points[a]
        bx, by = points[b]

        dx = bx - ax
        dy = by - ay

        for c in range(total):
            if c == a or c == b:
                continue

            cx, cy = points[c]

            cross = dx * (cy - ay) - dy * (cx - ax)
            if cross != 0:
                continue

            if min(ax, bx) <= cx <= max(ax, bx) and \
               min(ay, by) <= cy <= max(ay, by):
                return True

        return False

    for i in range(total):
        for j in range(i + 1, total):
            same_team = (i < n) == (j < n)
            if not same_team:
                continue

            if not blocked(i, j):
                graph[i].append(j)
                graph[j].append(i)

    dist = [-1] * total
    dist[0] = 0
    queue = [0]
    head = 0

    while head < len(queue):
        u = queue[head]
        head += 1

        if u == n - 1:
            return dist[u]

        for v in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                queue.append(v)

    return -1

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    pos = 0

    n = data[pos]
    pos += 1

    team1 = []
    for _ in range(n):
        x = data[pos]
        y = data[pos + 1]
        pos += 2
        team1.append((x, y))

    team2 = []
    for _ in range(n):
        x = data[pos]
        y = data[pos + 1]
        pos += 2
        team2.append((x, y))

    print(solve_case(n, team1, team2))

if __name__ == "__main__":
    solve()
```実装では、まず両方のチームを結合します。`points`。 インデックス`0`を通して`n - 1`はチーム 1、インデックスは`n`を通して`2 * n - 1`これにより、プレーヤーのチームのアイデンティティを次のチームと簡単に比較できます。`n`。 

の`blocked`関数はアルゴリズムの幾何学的部分を実行します。 外積では整数演算のみが使用されるため、浮動小数点の精度の問題はありません。 999 で区切られた座標では、中間値は Python では非常に小さく、標準の 64 ビット整数にも快適に収まります。 

範囲チェックはその後にのみ行われます`cross == 0`。 座標範囲テストだけでは点がセグメント上にあることを確立できないため、この順序は重要です。 共線性と両方の座標範囲内にあることにより、端点自体が明示的にスキップされるため、必要な「厳密に間」の条件が正確に得られます。 

グラフの構築では、次を使用して各順序なしペアを 1 回チェックします。`j`から`i + 1`これからも。 2 人のチームメイト間のパスは可逆であるため、パスが正当な場合は常に両方向が挿入されます。 

BFS はリストと整数を使用します`head`最初の要素を繰り返し削除する代わりに。 Python リストの先頭から削除すると (O(n)) コストがかかりますが、`head`各キューの操作時間を一定に保ちます。 BFS は距離が減少しない順序で頂点を処理するため、ターゲットがデキューされたときの早期リターンが有効になります。 

入力ステートメントにはテスト ケース数ではなく 1 つのテスト ケースが含まれるため、ソリューションは (n) の 1 つの値と 2 つの座標リストを正確に読み取ります。 の使用`sys.stdin.buffer.read()`ここでは安全であり、高速に解析を続けます。

### 例 1```

| 選手ペア | 同じチーム | ブロックされました | エッジ |
 | --- | --- | --- | --- |
 | 1、2 | はい | はい、(2,1) の相手です | いいえ |
