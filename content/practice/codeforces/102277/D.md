 ## 解決策
 ## 問題の理解

 デカルト平面上に円と軸が揃った正方形があります。 円はその中心によって記述されます`(x, y)`と半径`r`。 正方形は左下隅で表されます`(tx, ty)`そしてサイドの長さ`s`、つまり、その反対側の角は`(tx + s, ty + s)`。 課題は、それらの幾何学的関係を分類することです。 印刷します`0`それらがばらばらの場合、`1`それらの共通部分がちょうど 1 つの点で構成されている場合、および`2`プラスの領域と重なるとき。 公式の制限はあくまで`1000`座標と次元の大きさが異なり、制限時間は 1 秒、メモリは 256 MB です。 

数値限界は小さいですが、有用なシミュレーションを示唆するものではありません。 オブジェクトには無限に多くの点が含まれており、接線点には非整数の座標が含まれる可能性があるため、境界ボックス内のすべての整数座標を反復処理しても、有効な幾何学的アルゴリズムにはなりません。 クリーンなソリューションでは、一定数の算術演算を使用し、浮動小数点ジオメトリを完全に回避する必要があります。 

あるコーナーが他のオブジェクトの内側にあるかどうかだけをチェックする実装が失敗する可能性がある境界ケースがいくつかあります。 例えば、```
0 0 5
5 0 6
```出力があります`1`。 広場は次から始まります`(5, 0)`、これは円の中心からちょうど 5 単位の位置にあるため、2 つのオブジェクトは次の位置で接触します。`(5, 0)`。 厳格な`< r`テストでは誤った報告が行われる可能性がある`0`, なぜなら、タッチポイントは円の内側ではなく円の上にあるからです。 

2 番目のケースは、円が完全に正方形の内側にある場合です。```
0 0 1
-5 -5 10
```正しい出力は次のとおりです`0`。 2 つの幾何学的領域が包含されているにもかかわらず、円は正方形の境界とまったく交差しません。 「一方のオブジェクトが他方のオブジェクトの内側にあるため、それらが重なり合う」と仮定する方法では、包含と境界交差を混同してしまいます。 必要な分類は、円と正方形に共通領域があるか、または単一の共通点があるかに関するものであるため、円盤領域と正方形領域の場合、このケースには実際に正の面積の交差があり、次のように分類する必要があります。`2`。 これは、オブジェクトの正確な意味が重要である理由を示しています。円は、比較される領域の一部として塗りつぶされた内部を表します。 

より便利なエッジ ケースは、逆封じ込めです。```
0 0 10
-1 -1 2
```正しい出力は次のとおりです`2`。 正方形全体が円の内側にあるため、それらの交点の面積は正になります。 円の極点が正方形の内側にあるかどうかだけをチェックすると、これを完全に見逃してしまいます。 

これらの特殊なケースをすべて回避する最もクリーンな方法は、問題を 1 つの量、つまり円の中心から正方形の任意の点までの最小距離に減らすことです。 

## アプローチ

 直接的な幾何学的な力技により、正方形の 4 つの角と円の 4 つの基本点を列挙し、それらの候補点のいずれかが厳密に他の形状の内側にあるのか、それとも正確に他の形状上にあるのかを分類できます。 これは一定サイズの検索であり、適切な凸性引数を使用すると問題を解決できます。 角から円へのチェックが 4 回、円の端から点から正方形へのチェックが 4 回実行されるため、最悪の場合は 8 回の距離または包含チェックと、対応する算術計算が必要になります。 この問題にはテスト ケースが 1 つしかないため、このアプローチは漸近的に受け入れられますが、包含構成や境界ケースを忘れると簡単に不完全になってしまいます。 

さらに良い観察は、交点を検索する必要がまったくないということです。 固定円の中心の場合は、その中心に最も近い正方形の点を見つけます。 中心が正方形の水平方向の外側にある場合、最も近い点は対応する垂直辺を使用する必要があります。 中心が正方形の内側に水平にある場合、その最も近い点は同じになります。`x`座標。 同じ推論が独立して適用されます`y`座標。 

これにより、各座標を個別にクランプすることで最も近い正方形の点が得られます。 中心に座標がある場合`x`、正方形のスパン`[tx, tx+s]`、最も近い有効な正方形`x`座標は```
min(max(x, tx), tx+s)
```そして同様に`y`。 

最も近い点が判明すると、ジオメトリは単純な距離の比較になります。 させて`d`円の中心からその点までの距離になります。 もし`d < r`、円は正の面積を持つ正方形に達します。 もし`d = r`、円はちょうど 1 点で正方形に接しています。 もし`d > r`、正方形が完全に円の内側にない限り、円と正方形は互いに素です。 後者の場合はすでにカバーされています`d < r`なぜなら、円の中心は正方形の内側にあるか、円が正方形の一部を含むほど正方形の境界に十分近いためです。 

重要な単純化は、二乗距離で比較できることです。 両方なので`d`そして`r`非負である、比較する`d²`と`r²`まったく同じ結果が得られ、平方根と浮動小数点の精度の問題が回避されます。

 ## アルゴリズムのチュートリアル

 1. 円の中心を読み取ります`(x, y)`、半径`r`、および正方形の左下隅`(tx, ty)`そしてサイドの長さ`s`。 
2. 正方形の右側と上の境界を次のように計算します。`right = tx + s`そして`top = ty + s`。 正方形はまさにデカルト積です`[tx, right] × [ty, top]`。 
3. 円の中心をクランプします。`x`正方形の水平間隔に合わせて調整します。 コンピューティング`px = min(max(x, tx), right)`。 もし`x`すでにインターバル内にありますが、`px`等しい`x`。 もし`x`左側にあり、`px`になる`tx`、そしてもし`x`右側にあり、`px`になる`right`。 
4. 同様の操作を行います。`y`、取得`py = min(max(y, ty), top)`。 ポイント`(px, py)`正方形内で円の中心に最も近い点です。 
5. からの二乗距離を計算します。`(x, y)`に`(px, py)`として`dist2 = (x - px)^2 + (y - py)^2`。 と比較してください`r^2`。 
6. 印刷`2`もし`dist2 < r^2`, 円が正方形の中に伸びており、交点の面積が正であるためです。 印刷する`1`もし`dist2 == r^2`最も近い正方形の点が正確に円上にあるためです。 それ以外の場合は印刷します`0`なぜなら、正方形の各点は半径よりも円の中心から遠いからです。 

アルゴリズムの背後にある不変条件は次のとおりです。`(px, py)`は常に円の中心に最も近い正方形の点です。 正方形の各点は少なくともこの点と同じくらい中心から離れています。 したがって、この最も近い点でも円の外側にある場合、正方形全体が円の外側になります。 それが厳密に円の内側にある場合、その点の周囲の小さな近傍も円の内側にあり、正の領域の交差が得られます。 正確に円上にある場合、正方形と円は最も近い点で交わっており、互いに貫通することができず、単一点接触になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y, r = map(int, input().split())
    tx, ty, s = map(int, input().split())

    right = tx + s
    top = ty + s

    px = min(max(x, tx), right)
    py = min(max(y, ty), top)

    dx = x - px
    dy = y - py

    dist2 = dx * dx + dy * dy
    r2 = r * r

    if dist2 < r2:
        print(2)
    elif dist2 == r2:
        print(1)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```最初の 2 つの入力行は、アルゴリズムとまったく同じように 2 つの幾何学的オブジェクトを記述します。 すぐに正方形の右側と上の境界を計算するので、後続の式で正方形を 2 つの閉じた座標間隔として扱うことができます。 

二人`min(max(...))`式は座標クランプを実装します。 すべての入力が整数であり、最大二乗差が Python の任意精度の整数範囲内に簡単に収まるため、ここでは Python の整数演算が特に便利です。 

減算はクランプ後に意図的に実行されます。 これにより、円の中心から正方形までの最短ベクトルの水平成分と垂直成分が得られます。 二乗して加算すると、二乗された最小距離が得られます。 

厳密な比較と非厳密な比較は両方とも必要です。`<`最も近い正方形の点が円の内側にあることを意味します。`==`正確な接線を表します。 等号の場合を次のように置き換えます。`<=`すべての接線構成を重複として誤って分類してしまいます。 

平方根は計算されないため、正確な距離などの接線の場合の浮動小数点誤差は発生しません。`5`半径と比較して`5`。

 ## 特殊なケース

 最初の微妙なケースは、正確な接線です。 と```
0 0 5
5 0 1
```正方形の中心に最も近い点は`(5, 0)`。 二乗距離は`25`、正確に等しい`r² = 25`、アルゴリズムは次のように出力します`1`。 別個の等価ケースを使用しない厳密な内部テストでは、誤って出力されます。`0`。 

2 番目のケースは、円の中心が正方形の内側にある場合です。 のために```
0 0 1
-5 -5 10
```クランプすると中心は変わらないので、`(px, py) = (0, 0)`。 最小二乗距離は`0`より小さい`1`。 アルゴリズムは出力します`2`、円と四角形に正の面積の交差があることが正しく認識されます。 

3 番目のケースは、正方形が完全に円の内側にある場合です。```
0 0 10
-1 -1 2
```繰り返しますが、円の中心は正方形の内側にあるため、中心に最も近い正方形の点は中心そのものであり、最小二乗距離は次のようになります。`0`。 以来`0 < 100`、結果は`2`。 この場合は、正方形に対して円の境界点のみをチェックすると交差点を完全に見逃してしまうため、便利です。 

4 番目のケースは対角線分離です。```
0 0 5
5 5 1
```最も近い点は、`(5, 5)`、二乗距離を与える`25 + 25 = 50`。 以来`50 > 25`、結果は`0`。 平方距離を比較すると、平方根を導入せずに対角線も処理されます。 

5 番目のケースは、大きな座標の境界構成です。```
1000 1000 1000
-999 -999 1000
```広場は次で終わります`(1, 1)`に最も近い点です。`(1000, 1000)`。 二乗距離は`999² + 999²`より大きい`1000²`、アルゴリズムは次のように出力します`0`。 これにより、座標境界に特別な処理が必要ないことが確認されます。
