 ## 解決策
 ## 問題の理解

 この問題では、長方形の壁に切り込むことができる最大の長方形の窓を求めます。 壁には幅がある`w`そして高さ`h`、ウィンドウは少なくともそのままでなければなりません`d`ユニットを壁のあらゆる端から離してください。 必要なギャップは 4 つの側面すべてに独立して適用されます。 可能な最大のウィンドウ領域を出力する必要があります。または、`0`必要な隙間に窓を入れる余地がない場合。 The original contest specifies`w, h < 1000`そして`d < 100`、制限時間は 1 秒、メモリは 256 MB です。 

ジオメトリにより、利用可能な幅が直ちに減少します。`d`左側と`d`右側なので、可能な最大のウィンドウ幅は次のようになります。`w - 2d`。 同じ推論により、最大高さは次のようになります。`h - 2d`。 いずれかの値が正でない場合、正の領域を持つウィンドウは適合できません。 それ以外の場合、最大の長方形は利用可能な両方の寸法を使用します。 

境界が小さいということは、`O(w h)`列挙では、最悪の場合でもおよそ 100 万ペアしか調べられません。`w`そして`h`以下にあります`1000`。 それは比べものになりません`10^5`-二次アルゴリズムが自動的に除外されるスケール制約。 ただし、この問題には十分な幾何学的構造が含まれているため、列挙する必要はありません。一定数の算術演算で答えを計算できます。 

一般に誤った実装を引き起こす境界ケースが 2 つあります。 まず、ギャップによって次元全体が消費される可能性があります。 たとえば、入力の場合`30 20 12`、利用可能な幅は次のとおりです。`30 - 24 = 6`、利用可能な高さは`20 - 24 = -4`したがって、正しい出力は次のようになります。`0`。 2 つの値をチェックせずに乗算する不用意な実装では、次のような結果が得られます。`-24`、ウィンドウ領域を表すことはできません。 

第 2 に、ギャップは両方の寸法の半分よりも大きくなる可能性があります。 のために`40 25 50`、利用可能な寸法は次のとおりです。`-60`そして`-75`、したがって、答えは再びです`0`。 かどうかのみを確認します`w - 2d`高さも十分に大きくなければならないため、正の値では不十分です。 公式サンプルには、これらの不可能なケースの両方が含まれています。 

もう 1 つの境界は、完全に適合するケースです。 もし`w = 2d`または`h = 2d`の場合、対応するウィンドウの次元はゼロです。 面積がゼロの長方形は使用可能なウィンドウではないため、答えは依然として次のようになります。`0`。 例えば、`10 20 5`葉の幅`0`、出力を与える`0`。 

## アプローチ

 直接的な総当たりアプローチでは、次からすべての整数幅を列挙できます。`1`を通して`w - 1`からのすべての整数の高さ`1`を通して`h - 1`。 各ペアについて、各辺に必要なギャップを残しながら長方形が収まるかどうかを確認し、最大の有効領域を維持します。 この方法は正しいです。ディメンションのすべての候補ペアが考慮されるため、最終的には最適な有効なペアが見つかるはずです。 

と`w, h < 1000`、その列挙のパフォーマンスは最大でも約`(w - 1)(h - 1)`、これは 100 万次元ペア未満です。 したがって、多くの Codeforce の問題とは異なり、これらの制約の下ではブルート フォースが実際に壊滅的な影響を与えることはありません。 それにもかかわらず、それは必要以上にはるかに一般的な問題を解決しています。`O(w h)`仕事は避けられるものです。 

重要な点は、有効なウィンドウを拡大してもその領域を小さくすることはできないということです。 必要な境界線が予約されると、ウィンドウは残りの幅のすべての単位と高さの残りのすべての単位を占めることができます。 水平制約と垂直制約の間には相互作用がないため、最適な幅と最適な高さを個別に決定できます。 

壁が与えてくれる`w`水平方向にユニットを配置します。 左の境界線は消費します`d`、右の境界線は別の境界線を消費します`d`、出発`w - 2d`。 垂直方向にも、上部と下部の境界線が同様に残ります。`h - 2d`。 両方の量が正の場合、その積は可能な最大の面積になります。 どちらかが正でない場合、正領域ウィンドウは存在しません。 

ブルートフォースは最終的に最大次元をテストするため機能しますが、より小さな有効な次元はすべてより大きな次元によって支配されるという事実を利用できません。 両方の次元を単純に最大値まで押し上げることができるという観察により、問題全体が定数時間演算に帰着します。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 壁の幅を読み取る`w`、壁の高さ`h`、および必要な境界ギャップ`d`。 
2. 可能な最大ウィンドウ幅を次のように計算します。`w - 2d`。 引き算は次のとおりです`2d`窓は離れなければならないので`d`左側と右側の両方にユニットがあります。 
3. 可能な最大ウィンドウの高さを次のように計算します。`h - 2d`。 同じ議論が上辺と下辺にも当てはまります。 
4. 使用可能な次元のいずれかがゼロ以下であるかどうかを確認します。 ある場合は出力します`0`正でない幅または高さでは、正の領域の長方形ウィンドウを形成できないためです。 
5. それ以外の場合は、使用可能な幅と高さを乗算してその積を出力します。 どちらの方向でも利用可能な最大値を選択しても領域に悪影響を与えることはないため、これら 2 つの次元を組み合わせることで可能な限り最大のウィンドウが得られます。 

### なぜ効果があるのか

 有効なウィンドウを考えてみましょう。 少なくとも離れなければならないから`d`周囲と壁の各端の間の単位は、幅を超えることはできません。`w - 2d`、その高さは決して超えることはできません`h - 2d`。 両方の量が正の場合、各辺に必要なギャップを配置することで正確にその寸法のウィンドウが適合するため、有効なウィンドウはこれより大きな幅または高さを持つことができません。 面積は幅と高さの積なので、`(w - 2d)(h - 2d)`可能な最大の面積です。 いずれかの次元が正でない場合、正の領域の四角形は境界線の要件を満たすことができないため、ゼロを返すのが正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

w, h, d = map(int, input().split())

window_w = w - 2 * d
window_h = h - 2 * d

if window_w <= 0 or window_h <= 0:
    print(0)
else:
    print(window_w * window_h)
```最初の行は、唯一の入力行から 3 つの整数を読み取ります。 ループするテスト ケースがないため、プログラムは計算を 1 回だけ実行します。 

次の 2 つの代入は、ジオメトリを直接算術に変換します。`2 * d`ではなく使用されます`d`必要な境界線が各次元の両側に表示されるためです。 

条件は以下を使用します`<= 0`、 ない`< 0`。 残りの次元が正確にゼロの場合、結果として得られる長方形の面積はゼロとなり、有効な正の面積のウィンドウではなくなります。 

Python の整数はオーバーフローしません。また、指定された境界により、結果として得られる領域はとにかく非常に小さくなります。 また、このソリューションでは一定量のメモリのみが使用されます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    w, h, d = map(int, input().split())

    window_w = w - 2 * d
    window_h = h - 2 * d

    if window_w <= 0 or window_h <= 0:
        print(0)
    else:
        print(window_w * window_h)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# Provided samples
assert run("40 25 5\n") == "450\n", "sample 1"
assert run("30 20 12\n") == "0\n", "sample 2"
assert run("40 25 50\n") == "0\n", "sample 3"
assert run("999 888 7\n") == "860890\n", "sample 4"

# Minimum-size dimensions
assert run("1 1 1\n") == "0\n", "no room for a window"

# Exact-fit boundary
assert run("10 20 5\n") == "0\n", "zero remaining width"

# All dimensions comfortably fit
assert run("100 100 10\n") == "6400\n", "all-equal wall dimensions"

# Maximum-size input values
assert run("999 999 99\n") == "641601\n", "maximum bounds"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`1 1 1`|`0`| 最小寸法と設置不可能 |

 ## 特殊なケース

 のために`30 20 12`、アルゴリズムは次のように計算します。`window_w = 6`そして`window_h = -4`。 以来`window_h <= 0`、すぐに出力されます`0`。 これにより、ネガティブなプロダクトがエリアと間違われるのを防ぎます。 

のために`40 25 50`、利用可能な寸法は次のとおりです。`-60`そして`-75`。 同じ実現可能性チェックが返されます`0`。 これは、単に入力が常に十分な余地を残していると想定する実装を捕捉します。`w`そして`h`自分たち自身もポジティブです。 

ぴったりフィットするケースの場合`10 20 5`、利用可能な幅は次のとおりです。`10 - 2(5) = 0`。 アルゴリズムはゼロを不可能なものとして扱い、次のように出力します。`0`、縮退した長方形を受け入れるのではなく。 

次のような通常の有効なケースの場合、`40 25 5`、利用可能な寸法は次のとおりです。`30`そして`15`。 どちらも正であるため、アルゴリズムはそれらを乗算して次の値を取得します。`450`。 この計算では、窓に属することが許可されている壁のすべての部分が使用され、これより小さい候補は最適ではないことが証明されています。
