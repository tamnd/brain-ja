 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列があります。 1 回の操作で任意の要素を取得し、それを最前面または最背面に移動します。 他のすべての要素の相対的な順序は変わりません。 

目標は、順列を並べ替えることです。 

1、2、3、…、n

 このような操作はできるだけ少なくしてください。 入力には n が含まれ、その後に順列が 1 行に 1 つの値で続きます。 出力は、必要な最初または最後の移動の最小数です。 

重要な制限は、すべての値が個別であり、1 から n までのすべての値が 1 回だけ出現することです。 公式の制限は n≤10 5 で、時間制限は 1 秒、メモリは 256 MB です。 二次アルゴリズムは、n=10 5 の場合、すでに約 10 10 回の反復を実行します。これは、1 秒に収まる回数をはるかに超えています。 本質的に線形な解決策が必要です。 

この操作には非常に特殊な効果があります。 要素が移動された場合、その要素は最終的にソートされた配列の接頭辞または接尾辞の一部になることしかできません。 途中には挿入できません。 これは、興味深い問題は、実際にはどの要素を移動するかということではなく、どの連続した値のブロックをそのままにしておくことができるかということであることを意味します。 

順列を考慮してください```
521354
```2 が 1 の前に出現するため、値 1、2、3 は昇順ではありませんが、3、4、5 は必要な順序になっています。 3,4,5 はそのままにして、1,2 を移動できるので、答えは 2 になります。単純に最も長く増加する部分列を見つける不注意なアプローチでは、長さ 4 の 1,3,4,5 を考慮し、誤って 1 と答えてしまいます。これらの値は位置が増加していますが、値が連続していないため、前後の移動だけを使用して 1 と 3 の間に欠落している 2 を挿入する方法はありません。 

もう 1 つの特殊なケースは、すでにソートされた順列です。```
41234
```答えは 0 です。答えを少なくとも 1 つに初期化する実装、または複数の要素を含む実行のみを検索する実装は、ここで失敗する可能性があります。 

逆順列は、もう 1 つの有用な境界ケースです。```
44321
```タッチされていない連続ブロックに属することができる値は 1 つだけであるため、答えは 3 です。最長増加部分列の計算でもここでは 1 が得られますが、理由は異なり、問題の実際の構造が隠蔽される可能性があります。 

このステートメントではすべての値が異なる必要があるため、すべての値が等しい入力は有効なテスト ケースではありません。 実装のテストに関連する類似物は、上記の逆順列など、すべての隣接する値の関係が壊れている順列です。 

## アプローチ

 直接的なアプローチは、値 [l,r] の可能なすべての間隔を試し、それらの値がすでに正しい相対順序で表示されているかどうかを確認し、最も長い有効な間隔を維持することです。 区間の長さが k の場合、他の n−k 個の要素を移動するので、n−k の答えが得られます。 

ビルド後のチェックは特に簡単になります`pos`、 どこ`pos[x]`値 x が発生する位置です。 区間 [l,r] は、次の場合にそのまま残すことができます。 

pos[l]<pos[l+1]<⋯<pos[r]。 

単純な実装では、すべての開始値を試し、この条件が失敗するまで間隔を延長できます。 最悪の場合、すでにソートされた順列によりすべての拡張が成功するため、これは次のように実行されます。 

1+2+⋯+n=O(n 2 )

 チェック数は、n=10 5 の場合、約 5⋅10 9 チェックですが、すでに大きすぎます。 すべての間隔を調べてその内容をスキャンする、さらに文字通りの総当り攻撃は 3 次になります。 

重要な観察は、間隔の有効性は隣接する値にのみ依存するということです。 もし`pos[x] < pos[x+1]`の場合、x と x+1 は、タッチされていないブロックの連続したメンバーになることができます。 したがって、位置が増加する連続する値の現在の長さを維持しながら、1 から n までの値をスキャンします。 

たとえば、位置配列が次の場合、```
value:  1  2  3  4  5  6pos:    5  6  2  3  4  1
```比較は次のとおりです```
pos[1] < pos[2]   yespos[2] < pos[3]   nopos[3] < pos[4]   yespos[4] < pos[5]   yespos[5] < pos[6]   no
```したがって、最長の有効な連続ブロックの長さは 3、つまり 3、4、5 になります。 

ブルートフォース手法が機能するのは、タッチされていないブロックによって、どの要素がその場に留まることができるかが完全に決定されるためです。 重複する間隔を繰り返しチェックするため、失敗します。 隣接する値のみが重要であるという観察により、1 回のパスで最長の有効なブロックを見つけることができます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n 2 ) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取って構築する`pos`、 どこ`pos[x]`値 x のインデックスです。 最終的な並べ替え順序は数値によって決定され、入力によって現在の位置が得られるため、位置を使用します。 
2.スタート`current = 1`そして`best = 1`。 単一の値は常に変更しないままにしておくことができるため、最長の有効なブロックは少なくとも 1 の長さを持ちます。 
3. 2 から n まで x をスキャンします。 もし`pos[x - 1] < pos[x]`、設定により現在のブロックを拡張します。`current += 1`。 これは、x−1 と x が、ソートされた順列で必要とされる同じ相対順序ですでに存在していることを意味します。 
4. もし`pos[x - 1] >= pos[x]`、リセット`current`値 x−1 と x の両方が同じ未処理の連続ブロックに属することはできないため、x−1 で終わるブロックはそこで停止する必要があります。 
5.アップデート`best = max(best, current)`各比較の後。 最後に、`best`変更されない連続値の最大数です。 
6. 出力`n - best`。 保持されたブロックの外側のすべての値は移動する必要がありますが、ブロック内のすべての値はそのままの場所に残すことができます。 

### なぜ効果があるのか

 変更されていないセットに 2 つの連続する値 x と x+1 が含まれているとします。 どちらの値も移動されないため、それらの相対的な順序は決して変わりません。 ソートされた配列では、x は x+1 より前に出現する必要があるため、必然的に`pos[x] < pos[x+1]`。 

さらに厳密に言えば、変更されていないすべての値は、値の 1 つの連続した間隔を形成する必要があります。 x と x+2 をそのままにして x+1 を移動した場合、移動した値は前または後ろにしか配置できないため、x と x+2 の間に収まることはありません。 したがって、触れられていない部分は l,l+1,…,r という形式を持ち、その位置が厳密に増加している場合に正確に有効です。 

このような有効な間隔については、小さい値ごとに降順で前に移動します。 各移動により、次に必要なプレフィックス値が正しく配置されます。 次に、大きい値をすべて昇順に後ろに移動します。 これら 2 つの部分の間には変更されていない間隔が残り、完全にソートされた順列が生成されます。 したがって、最長の有効な間隔に長さがある場合、`best`、正確に n 個の最善手で十分であり、そのような間隔の外側にあるすべての要素を移動する必要があるため、これより少ない手数を使用するソリューションはありません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    pos = [0] * (n + 1)
    for i in range(1, n + 1):        x = int(input())        pos[x] = i
    best = 1    current = 1
    for x in range(2, n + 1):        if pos[x - 1] < pos[x]:            current += 1        else:            current = 1
        if current > best:            best = current
    print(n - best)

if __name__ == "__main__":    solve()
```最初のループは逆順列を構築します。 入力が`2 1 3 5 4`、 それから`pos[1] = 2`、`pos[2] = 1`、`pos[3] = 3`、`pos[4] = 5`、 そして`pos[5] = 4`。 

2 番目のループは、アルゴリズムからの連続位置スキャンを実装します。 比較は次の間である必要があります`pos[x - 1]`そして`pos[x]`、元の順列の隣接する要素間ではありません。 連続する数値がすでに正しい順序で発生しているかどうかを尋ねています。 

比較が成功すると、現在の連続ブロックが増加します。 失敗すると、ブロックは現在の値で再起動する必要があります。 のアップデート`best`どちらの場合でも実行されるため、最終値 n で終わるブロックは正しく処理されます。 

Python では整数オーバーフローの懸念はなく、配列には n+1 個の整数のみが含まれます。 実装では n=1 も処理します。`best`1 から始まり、スキャンは空で、答えは`1 - 1 = 0`。
