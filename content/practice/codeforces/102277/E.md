 ## 問題の理解

 UCF の学生全員のファーストネームが与えられます。 大統領と副大統領のチケットは、2 人の候補者の名が異なるが、両方の名前が同じ文字で始まる場合に可能と見なされます。 学生は同じ名前であっても区別されるため、JOSH という名前の学生と JAD という名前の学生が複数いる場合、JOSH の学生と JAD の学生を選択するたびに、別のチケットが作成されます。 2 つの立場も異なるため、JOSH を社長に、JAD を副社長に選ぶことは、JAD を社長に、JOSH を副社長に選ぶこととは異なります。 タスクは、そのような順序付けされた生徒のペアをすべてカウントすることです。 

学生数は最大 66,183 人で、これはコンテストに使用された実際の UCF 登録者数です。 各名前には最大 20 文字の大文字が含まれます。 最大入力サイズでは順序付きペアが約 43 億 8,000 万個あるため、1 秒の時間制限では、生徒のすべてのペアを検査するアルゴリズムは実行できません。 意図したソリューションでは、各生徒を一定の回数だけ処理する必要があり、使用されるデータ構造に応じて線形の予想時間または決定的な時間が与えられます。 

答えは、32 ビットの符号付き整数よりもはるかに大きくなる可能性があります。 多くの生徒が同じ文字で始まる異なる名前を持っている場合、順序付きペアの数は生徒の数に応じて二次関数的に増加するため、実装には (n^2) 程度の値を保持できる整数型が必要です。 Python の整数にはすでに任意の精度があるため、コード内で特別な処理を行う必要はありません。 

一見合理的に見える解決策が間違っている可能性があるいくつかの特殊なケースがあります。 まず、同じ名前のコピーを繰り返し使用しても、有効なチケットを形成してはなりません。 例えば、```
3
JOSH
JOSH
JAD
```出力があります```
4
```JOSHの学生が2名、JADの学生が1名います。 有効な注文チケットは、それぞれ JOSH と JAD、および JAD と各 JOSH であり、4 枚のチケットが与えられます。 同じイニシャルを持つすべての生徒を単にカウントする不注意な解決策では、(3 \times 2 = 6) が計算され、2 つの順序付けられた JOSH/JOSH ペアが誤って含まれてしまいます。 

次に、候補者の順序が重要です。 のために```
2
JOSH
JAD
```答えは```
2
```JOSH/JAD と JAD/JOSH は別のチケットであるためです。 順序付けされていないペアを数えると、1 つだけが得られます。 

最後に、異なるイニシャルを持つ名前を決して組み合わせてはいけません。 のために```
3
JOSH
JAD
ALI
```答えは```
2
```JOSH と JAD を含む 2 つの順序付きペアのみが有効であるためです。 異なる名前を持つ生徒のペアをすべてカウントすると、ALI に関係するペアが誤って含まれてしまいます。 

## アプローチ

 直接的なアプローチは、順序付けられた個別の生徒のペアをすべて検査することです。 ペアごとに 2 つの名前を比較します。 名前が異なり、最初の文字が一致する場合、このペアは正確に答えに 1 を与えます。 これは、有効なチケットを定義する 2 つの条件を正確にテストするため、正しいです。 

問題はペアの数です。 (n) 人の生徒の場合、(n(n-1)) 個の順序ペアが存在します。 (n=66,183) では、これは次のようになります。 

[
 66,183 \× 66,182 = 4,380,123,306
 】

 ペアチェック。 たとえ各チェックが非常に安価だったとしても、何十億回もの反復では 1 秒のコンテスト制限に収まりません。 

すべての有効なチケットが明示的に検査されるため、ブルート フォースは機能しますが、すべてのペアについて同じ情報が再計算されると失敗します。 重要な観察点は、条件が 2 つの情報 (各名前の最初の文字と 2 つのフルネームが異なるかどうか) のみに依存しているということです。 

特定のイニシャルに (T) 人の生徒がいるとします。 名前が異なるという要件を一時的に無視すると、そのイニシャルを持つ個別の生徒の順序付きペアが (T(T-1)) 個存在します。 このうち、同姓同名の学生は無効となります。 特定の名前が (c) 回出現すると、無効な順序ペア (c(c-1)) が発生します。これは、どちらかの学生を学長に、同じ名前の別の学生を副学長に選択できるためです。 

したがって、1 つのイニシャルに対して、有効なチケットの数は次のようになります。 

[
 T(T-1) - \sum_{\text{名前}} c(c-1)。 
】

 ペアを構築することなく、これを段階的に計算できます。 名前 (x) とイニシャル (L) を持つ新しい生徒を処理するとき、イニシャル (L) を持つ (T) 人の生徒がすでに存在し、そのうち (c) がまったく同じ名前 (x) を持っていたとします。 新しい生徒は、前の生徒と 2 つの役割の 1 つとして (T) 注文されたチケットを作成し、前の生徒が最初の役割を占めるときに別の (T) チケットを作成できます。 これにより、重複する名前を考慮する前に (2T) 個の可能性が得られます。 (c) (x) という名前の前の生徒はどちらの方向でも無効であるため、(2c) を減算します。 したがって、新入生の貢献は次のとおりです。 

[
 2(T-c)。 
】

 この寄与を追加した後、初期カウントと正確な名前のカウントの両方をインクリメントします。 

これにより、入力を単一パスで通過できます。 以前に処理されたすべての生徒は、イニシャルとフルネームで構成されるペアによって完全に分類できるため、この観察は機能します。 新入生が有効なチケットを作成できるかどうかに影響を与えるプロパティは他にありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(1)) 入力ストレージとは別に | 遅すぎる |
 | 最適 | (O(n)) が期待されます | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. メンテナンス`initial_count`、最初の文字ごとに何人の生徒が見られたかを保存します。`name_count`、完全な名前ごとに何人の生徒が見られたかを保存します。 名前は最初の文字を一意に決定するため、これら 2 つのマップには将来の学生に必要な情報が正確に含まれています。 
2. 各生徒の名前を読み、最初の文字を抽出します。 させて`same_initial`名前がこの文字で始まる、以前に処理された学生の数になります。 
3. しましょう`same_name`は、まったく同じ名前で以前に処理された学生の数です。 その中で、`same_initial`学生たち、まさに`same_name`名前が違うわけではないので、禁断の相手です。 
4. したがって、新入生は`same_initial - same_name`有効な以前のパートナー。 このような各パートナーは社長または副社長のいずれかを務めることができるため、次のように追加します。`2 * (same_initial - same_name)`答えに。 
5. 生徒のイニシャルとフルネームのカウントを増やします。 これらの更新された数は、後の生徒を処理するときに必要になります。 

不変条件は、入力の接頭辞を処理した後、`answer`2 人の生徒が両方ともそのプレフィックスに属する、有効な注文済みの会長/副会長チケットの数と同じです。 新しい生徒が到着した場合、新しく作成されたすべての有効なチケットには、その生徒と 1 人の以前の生徒が含まれている必要があります。 この式では、イニシャルが同じで名前が異なる以前の生徒を、考えられる両方の役割順序で正確にカウントします。 すべてのチケットは、後の生徒が処理されるときに正確に導入されるため、有効なチケットが見逃されたり、二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    initial_count = {}
    name_count = {}
    answer = 0

    for _ in range(n):
        name = input().strip()
        initial = name[0]

        same_initial = initial_count.get(initial, 0)
        same_name = name_count.get(name, 0)

        answer += 2 * (same_initial - same_name)

        initial_count[initial] = same_initial + 1
        name_count[name] = same_name + 1

    print(answer)

if __name__ == "__main__":
    solve()
```2 つの辞書は、増分式の 2 つの量に直接対応します。`initial_count`これは、新入生の最初の文字と一致する可能性のある以前の生徒が何人いるかを示します。`name_count`同じ名前を持つために除外する必要がある候補を識別します。 

答えは、現在の生徒をいずれかの辞書に挿入する前に更新されます。 学生は自分でチケットを作成できないため、この順序は重要です。 在校生を先に数えるとすると、`same_initial`そして`same_name`どちらもその学生を含むため、計算ではそれを補正する必要があります。 

Python の辞書操作は予期され (O(1))、予期される線形の実行時間が得られます。 Python の整数は必要に応じて自動的に増加するため、二次関数の答えがオーバーフローすることはありません。
