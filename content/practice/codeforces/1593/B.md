 ## 解決策
 ## 問題の理解

 10 進数で書かれた数字が与えられ、その数字の中のどこからでも 1 桁ずつ削除することができます。 削除するたびに、残りの数字が閉じられ、先頭のゼロが自動的に消えます。 このプロセスは停止を決定するまで続きますが、最終的に残った数値が正の値を保ちながら 25 で割り切れるようにする必要があります。 

10 進数の 25 で割り切れる可能性は非常に厳密です。数値は、最後の 2 桁がパターン 00、25、50、または 75 のいずれかを形成する場合に限り、25 で割り切れます。これは、問題全体が、削除を使用して数値の接尾辞をこれら 4 つの末尾のいずれかに整形することに帰着することを意味します。 

テスト ケースの数という点では入力サイズは大きく、最大 10^4 ですが、各数値自体は符号付き 64 ビット整数に収まるため、最大でも 18 桁になります。 これにより、すべての削除シーケンスまたは位置のサブセットにわたる DP をシミュレートしようとするアプローチは即座に除外されます。 テスト ケースごとの 2 次解でも問題ありませんが、桁を超える指数関数は不要で安全ではありません。 

微妙な問題は、先頭のゼロとの相互作用です。 数字を削除すると、「050」や「005」などの中間結果または最終結果が発生し、「50」または「5」として扱われる場合があります。 これは、「2 桁をサフィックスとして保持する」ということの解釈が変わるため重要です。つまり、必ずしも隣接している必要はなく、事実上 2 桁を順番に選択しており、他のすべては削除されます。 

単純な間違いは、連続した部分文字列を保持しなければならないと考えることです。 たとえば、2050047 では、注意を 20、05、50、04、47 のような部分文字列に誤って制限する可能性がありますが、有効な構造では桁を完全にスキップできるため、連続しない選択肢が優先されます。 

## アプローチ

 ブルートフォースのアイデアは、有効な数値に到達するまで、あらゆる方法で数字を削除することです。 18 桁の数値の場合、各桁は保持または削除できるため、2^18 の可能性があり、テスト ケースごとに約 260,000 のサブセットが存在します。 10^4 のテスト ケースでは、これは実行不可能になります。 さらに悪いことに、各サブセットの順序を検証し、結果の数値を計算する必要があります。 

重要な観察は、数値全体は気にせず、削除後の最後の 2 桁だけを気にするということです。 有効な最終数値は、元の数値から最後の 2 桁となる 2 桁を順番に選択し、残りのプレフィックス (存在する場合) が重要でないことを確認することによって完全に決定されます。 

したがって、タスクは次のようになります。{00、25、50、75} で終わるターゲットごとに、その順序で最後に 2 桁が表示されるようにするために必要な最小の削除数を見つけます。 これら 2 つの数字が修正されたら、元の文字列内のその後の数字をすべて削除し、選択した数字の間にあるすべての数字も削除する必要があります。 

i < j で数字がターゲットの末尾に一致する位置の各ペア (i, j) をテストします。 これらを最後の 2 桁として固定すると、j 以降のすべての桁が削除され、i と j の間のすべての桁 (i と j 自体を除く) が削除されます。 削除の合計は、破棄する桁数によってのみ決まります。 

これにより、問題は 4 つのエンディングのすべての有効なペアをチェックするだけになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^d · d) | O(d) | 遅すぎる |
 | チェックディジットのペア | テストあたり O(d^2) | お(1) | 承認済み |

 d ≤ 18 なので、O(d^2) は自明です。 

## アルゴリズムのチュートリアル

 数値を数字の文字列として扱います。

1. テスト ケースごとに、数字列を読み取り、その長さ n を保存します。 00、25、50、75 の間で終わるターゲットごとに独立して答えを計算します。 
2. 固定ターゲットの終了の場合、最初に最後の桁を選択しようとします。 右から左にスキャンして、数字がターゲットの 2 番目の数字と等しいすべての位置 j を選択します。 これは、j が保持される最後の数字である必要があるため、j の右側にあるすべてが削除されるためです。 
3. このような位置 j ごとに、有効な位置 i < j (数字がターゲットの最初の数字に等しい) を検索します。 この i は、最後の数字の下から 2 番目の桁になります。 
4. 選択したペア (i, j) について、次のように削除を計算します。 j 以降のすべての桁が削除され、n - 1 - j 個の削除が発生します。 i と j の間のすべての数字が削除され、j - i - 1 個の削除が行われます。 最後のプレフィックスの一部ではない i より前のすべての数字は削除する必要がありますが、削除数のみをカウントするため、合計の削除数は次のように単純化されます。 

欠失 = (n - 2) - (i + (n - 1 - j))

 しかし、直接考える方が簡単です。i と j を正確に保持するため、削除 = n - 2 となります。 

ただし、これは順序付けの制約を無視するため、代わりに正しく解釈します。i と j、および場合によっては接頭辞を形成するそれより前の数字も保持しますが、問題となるのは削除のみであるため、正しい計算は次のようになります。 

deletions = (n - 1 - j) + (j - i - 1) + (i - prefix_kept_count) ですが、サフィックスの有効性のために保持されるすべての桁は i と j のみであるため、prefix_kept_count は無関係です。 したがって、最終的な削除は次のようになります。 

欠失 = (n - 1 - j) + (j - i - 1)

 これは n - i - 2 に等しくなります。 

したがって、有効なペアごとに、n - i - 2 を評価します。 
5. すべての有効なペアと 4 つのターゲット エンディングすべての最小値を取得します。 
6. 最小値を出力します。 

### なぜ効果があるのか

 有効な最終番号は、25 の 4 つの倍数の接尾辞のいずれかで終わる必要があります。 最後の 2 桁が固定されると、残りの数値は割り算に影響を与えないため、順番に 2 桁を保存するだけで済みます。 すべての有効な構造は、有効なサフィックスに一致するインデックス i < j の選択に一意に対応します。 削除の数は、これらのインデックスが文字列の末尾からどれだけ離れているかによってのみ決まり、最適なペアを選択することで削除が最小限に抑えられます。 あらゆる可能性をチェックするため、より良い構成を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s):
    n = len(s)
    targets = [("0", "0"), ("2", "5"), ("5", "0"), ("7", "5")]
    ans = n  # worst case delete everything except 2 digits

    for a, b in targets:
        best = n
        for j in range(n - 1, -1, -1):
            if s[j] != b:
                continue
            for i in range(j - 1, -1, -1):
                if s[i] == a:
                    # deletions = n - i - 2
                    best = min(best, n - i - 2)
        ans = min(ans, best)

    return ans

def main():
    t = int(input())
    for _ in range(t):
        n = input().strip()
        print(solve_one(n))

if __name__ == "__main__":
    main()
```この解決策は、すべての有効な接尾辞パターンをループし、次に結果の数値の最後の桁のすべての候補位置をループします。 このような位置ごとに、一致する前の数字を逆方向に検索します。 これにより、選択したペアの順序が確実に維持されます。 削除式`n - i - 2`これは、選択した 2 桁とその相対的な順序以外のすべてが削除されるため、機能します。 

よくある実装の落とし穴は、インデックスを混同し、保持された位置ではなく末尾を基準にして削除をカウントすることです。 最も安全な方法は、「セグメント内でいくつ削除されるか」ではなく、「どのインデックスが保持されるか」という観点から常に考えることです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        s = input().strip()
        n = len(s)
        targets = [("0","0"),("2","5"),("5","0"),("7","5")]
        ans = n
        for a,b in targets:
            best = n
            for j in range(n-1,-1,-1):

                    continue

                        best = min(best, n - i - 2)
            ans = min(ans, best)
        print(ans)

    t = int(input())
    for _ in range(t):
        solve()

    return ""

 ## 特殊なケース

 一般的なエッジケースは、有効なサフィックス数字が存在するが順序が逆である場合です。 たとえば、数値には「2」の前に「5」が含まれる場合がありますが、「25」ターゲットの場合は「5」の前に「2」が必要です。 このアルゴリズムでは、インデックスの順序 i < j が明示的に強制されるため、両方の桁が存在する場合でも、このような逆のペアは無視されます。 

もう 1 つの特殊なケースは、ゼロが繰り返されることです。 20099050 のような入力では、複数のゼロ候補が接尾辞として機能します。 このアルゴリズムは、2 桁目のすべての j 位置を試行し、次善の極右の選択が早すぎることのないようにします。 

最後のエッジケースは、最適解が互いに非常に近い数字を使用する場合であり、これにより i と j の間の削除が最小限に抑えられます。 i を最大化すると削除が直接最小化され、アルゴリズムは自然に各 j に対して最も右の有効な i を優先するため、式 n - i - 2 はこれを自動的に捉えます。
