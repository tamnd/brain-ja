 ## 解決策
 ## 問題の理解

 私たちは根のない木を与えられ、剪定プロセスを繰り返します。 1 回の操作で、現在次数が 1 以下のすべての頂点が同時に削除されます。 これは、すべてのリーフが消滅することを意味し、縮退の場合には、その端点も定義ではリーフとみなされるため、残った 1 つの頂点または 1 つのエッジも消滅します。 

この操作を正確に k 回繰り返し、すべてのラウンドの同時リーフ除去後に残っている頂点の数を知りたいと考えています。 

制約から得られる主な観察点は、すべてのテスト ケースにわたる頂点の合計数が最大 4 · 10^5 であることです。 これは、k 自体がテストごとに 2 · 10^5 に達する可能性があるため、操作ごとにグラフ全体の走査を繰り返すソリューションは遅すぎることを直ちに示唆しています。 単純なシミュレーションでは、リーフを再計算してレイヤーごとに削除するため、ステップごとにすべてのエッジに触れる可能性があり、最悪の場合は O(nk) 動作が発生します。 

微妙な点は、このプロセスは削除を超えたエッジの構造的な再配置に関するものではないということです。 頂点は一度削除されると元に戻ることはなく、削除は外側から中心に向かって層状に行われます。 

素朴な考えを打ち破るエッジケースは、小さな木です。 

k ≥ 1 の単一ノードは、最初の操作の後、1 に留まるのではなく、すぐに空になる必要があります。 

両方のエンドポイントが同時にリーフであるため、2 ノード ツリーも最初の操作後に空になります。 

星形の木はすぐに崩壊します。一度の操作の後、中央だけが残ります。 2回目以降は消えます。 

これらのケースは、プロセスが基本的に、動的な次数の更新だけを扱うのではなく、ツリーの「コア」までの距離を扱うものであることを示しています。 

## アプローチ

 直接シミュレーションでは次数を維持し、現在のリーフをすべて繰り返し収集して削除し、隣接するリーフを更新します。 各操作が定義と正確に一致するため、これは正しいです。 ただし、リーフ セットを k 回まで再計算すると、グラフの大部分を繰り返しスキャンすることになる可能性があります。 長いパスでは、各ラウンドで頂点が 2 つだけ削除されるため、プロセスには O(n) ラウンドがかかり、各ラウンドのコストは O(n) となり、全体で O(n^2) になります。 

構造上の重要な洞察は、頂点から距離 k 以内にあるすべての頂点が削除されるまで、頂点が正確に存続するということです。 言い換えれば、各頂点の「死亡時間」は、同時に除去された層で測定された、最も近い葉からの距離に等しいということです。 

逆のプロセスを実行すると、葉を外側に剥がすのではなく、葉を出発点として内側に向かって繁殖します。 すべての葉は時間 1 で枯れ、隣接する葉は時間 2 で枯れる、というようになります。 これは、すべての最初のリーフが距離 1 で同時に開始するマルチソース BFS です。 

したがって、問題はすべてのノードについて、最も近いリーフまでの距離を計算することになります。 その後、距離が厳密に k より大きいノードが残ります。 

これにより、繰り返される構造更新の問題がツリー上の単一の BFS に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返し葉除去シミュレーション | O(nk) 最悪の場合 | O(n) | 遅すぎる |
 | 葉からのマルチソース BFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての頂点の次数を計算します。 リーフはまさに次数 ≤ 1 のノードであるため、これは最初のリーフを識別するために必要です。 
2. すべてのリーフを含むキューを初期化し、距離 1 を割り当てます。これらは、最初の操作で削除される頂点を表します。 
3. このキューから BFS を実行します。 ノード u を処理するときに、まだ距離が割り当てられていない隣接ノード v に伝播します。 dist[v] = dist[u] + 1 を割り当てます。これは、外層のすべての頂点が削除された後に v が葉になることをモデル化します。 
4. BFS が完了すると、すべての頂点は値 dist[v] を持ち、これは頂点が削除されるラウンドを表します。 
5. dist[v] > kを満たす頂点の数を数えます。 これらは、k 回の完全な枝刈り操作を経ても生き残る頂点です。 

これが機能する理由は、BFS の各層が 1 ラウンドのリーフ除去に正確に対応しているためです。 最初は本葉だけを取り除きます。 それらが削除されると、いくつかの内部頂点が新しいリーフになります。これがまさに次の BFS フロンティアです。 すべての除去はラウンドごとに同時に発生するため、BFS は除去深さの並行拡張を正しくモデル化します。 

不変条件は、BFS レベル d の開始時に、dist ≤ d のすべての頂点が d 操作内で削除可能としてすでに識別されており、残りのすべての未訪問の頂点が厳密にツリーのコアのより深いところにあることです。 ツリー構造により、リーフから内側に移動する以外に代替のより短い削除パスが存在しないことが保証されるため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n, k = map(int, line.split())

        adj = [[] for _ in range(n)]
        deg = [0] * n

        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)
            deg[u] += 1
            deg[v] += 1

        dist = [-1] * n
        q = deque()

        for i in range(n):
            if deg[i] <= 1:
                dist[i] = 1
                q.append(i)

        remaining = n

        while q:
            u = q.popleft()
            if dist[u] > k:
                continue
            remaining -= 1
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        print(remaining)

if __name__ == "__main__":
    solve()
```隣接リストにはツリー構造が格納され、次数によって最初のリーフが識別されます。 BFS キューにはすべてのリーフが一度にシードされ、最初のレイヤーが最初のプルーニング操作に対応することが保証されます。 

距離配列は除去時間をエンコードします。 値 1 は最初の操作後に削除されることを意味し、2 は 2 番目の操作後に削除されることを意味します。 

残りのカウンターは、k 回の操作後にまだ削除されていない頂点の数を追跡します。 時刻 k までに BFS 内のノードを処理する場合にのみデクリメントします。 

微妙な点の 1 つは、テスト ケース間の空行の処理です。 入力形式にはそれらが含まれるため、n と k を読み取る前に空白行を明示的にスキップします。 

## 実用的な例

 1-2-3-4 という小さなパス ツリーをたどります。 

最初は葉は 1 と 4 です。 

| ステップ | キュー | dist 割り当て | 削除されました |
 | --- | --- | --- | --- |
 | 初期化 | [1,4] | 1:1、4:1 | 0 |
 | ポップ1 | [4,2] | 2:2 | 1 |
 | ポップ4 | [2,3] | 3:2 | 2 |
 | ポップ2 | [3] | - | 3 |
 | ポップ3 | [] | - | 4 |

 ここで dist は、ラウンド 1 で 1 と 4 が死亡し、ラウンド 2 で 2 と 3 が死亡したことを示しています。k = 1 の場合、頂点は 2 つだけ残ります。 

ここで、中心 1 と葉 2、3、4、5 を持つ星を考えてみましょう。 

| ステップ | キュー | dist 割り当て | 削除されました |
 | --- | --- | --- | --- |
 | 初期化 | [2,3,4,5] | すべての葉の距離 = 1 | 0 |
 | ポップの葉 | 写真 [1] | 1 は dist=2 を取得します。 4 |
 | ポップ1 | [] | - | 5 |

 これにより、中心部が葉より正確に 1 ラウンド長く生き残ることが確認されました。 

これらのトレースは、BFS レイヤーが枝刈りラウンドに正確に対応していることを示しています。

import sys, io

    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            line = input().strip()
            while line == "":
                line = input().strip()
            n, k = map(int, line.split())

            adj = [[] for _ in range(n)]
            deg = [0] * n

            for _ in range(n - 1):
                u, v = map(int, input().split())
                u -= 1
                v -= 1
                adj[u].append(v)
                adj[v].append(u)
                deg[u] += 1
                deg[v] += 1

            dist = [-1] * n
            q = deque()

            for i in range(n):
                if deg[i] <= 1:
                    dist[i] = 1
                    q.append(i)

            remaining = n

            while q:
                u = q.popleft()

                remaining -= 1
                for v in adj[u]:
                    if dist[v] == -1:
                        dist[v] = dist[u] + 1
                        q.append(v)

            out.append(str(remaining))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 単一の頂点ツリーは、操作の縮退動作を示します。 BFS はその頂点を距離 1 のリーフとして初期化し、k ≥ 1 であるため、すぐに削除されたものとしてカウントされ、出力 0 が生成されます。 

2 頂点ツリーも同様です。最初は両方のノードがリーフであり、両方とも距離 1 を受け取り、最初の操作後に頂点は残りません。 BFS は両方を同時に処理し、エンドポイント間の非対称性を保証します。 

長いチェーンは、プロセスの階層的な性質を示しています。 両端の葉は距離 1 から始まり、その隣の葉は距離 2 になり、同様に中心まで続きます。 このアルゴリズムは、各枝刈りラウンドを明示的にシミュレートする必要がなく、増加する距離を正確に割り当てます。
