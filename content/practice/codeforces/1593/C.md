[CF 1593C - より多くのマウスを節約](https://codeforces.com/problemset/problem/1593/C)

 **評価:** 1000
 **タグ:** 二分探索、貪欲
 **解決時間:** 2 分 45 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 3 種類のエンティティ (位置 0 から始まる猫、位置 n の穴、およびそれらの間に厳密に配置された数匹のマウス) を含む線分が与えられています。 時間は秒単位で進みます。 各秒は 2 つのアクションに分割されます。まず、マウスを 1 匹だけ選択して右に 1 歩移動し、次に猫が右に 1 歩移動します。 ネズミが移動中に穴に到達すると、直ちに安全になり、参加しなくなります。 猫が移動後に 1 匹以上のネズミがいる場所に着地すると、そのネズミは食べられてしまいます。 

タスクは、移動後に猫と位置を共有するまでに穴に到達するネズミの数を最大化するために、毎秒どのネズミを動かすかを選択することです。 

これを再解釈する便利な方法は、各マウスに期限があると考えることです。つまり、猫がその位置に到達する前に、マウスは位置 n に厳密に到達する必要があります。 ただし、静的な期限の問題とは異なり、マウス間の進行状況をインターリーブすることができるため、直接の比較の問題ではなく、スケジュールの問題が発生します。 

制約は大きく、すべてのテスト ケースにわたるマウスの総数は最大 4⋅10^5 です。 これにより、マウスごとに 1 秒ごとに繰り返しシミュレーションする 2 次シミュレーションが即座に除外されます。 テスト ケースごとに O(k^2) であっても、遅すぎます。 O(k log k) または O(k) に近い値が必要です。 

いくつかの特殊なケースから構造が明らかになります。 

すべてのマウスが猫の非常に近くから開始した場合、たとえば n = 10 で位置 [1,1,1,1] の場合、1 匹のマウスを繰り返し前進させる不適切なスケジュールにより、穴に到達する前に猫が位置 1 ですべてのマウスを捕まえることができます。 正しい戦略は、数匹のネズミを十分に前方に押し出して「猫の手の届く窓から逃げる」ことを優先することです。 

すべてのマウスがすでに穴の近くにある場合 (たとえば、n = 10 で位置 [9,9,9])、少なくとも 1 匹のマウスがすぐに移動する限り、どのスケジュールでも機能します。 制限要因はマウス間の干渉ではなく、1 秒あたり 1 マウスという制約です。 

重要な点は、猫が単位速度で決定的に前進し、移動カットオフラインとして機能することです。 このカットオフに遅れたマウスは、取り返しのつかない運命に陥ることになります。 

## アプローチ

 直接シミュレーションでは、マウスを貪欲に、または徹底的に選択し、位置を更新し、マウスが食べられるか逃げるかをチェックしながら、毎秒モデル化を試みます。 正しいとはいえ、各マウスには最大 O(n) の移動が必要であり、最大 4⋅10^5 のマウスがあるため、このアプローチは根本的に遅すぎます。 

重要な観察は、視点を逆転させることです。絶対空間内の位置について考える代わりに、「各マウスが捕まえられるまでに何秒生き残るか」という観点から考えます。 位置 x から開始したネズミは、猫が x に到達する前に n に到達しなければなりません。 猫は 0 から開始して 1 秒あたり 1 歩正確に移動するため、猫は時刻 x に位置 x に到着します。 これは、マウスは開始位置に関連付けられた期限までに必要な移動を完了しなければならないことを示唆しています。 

ただし、マウスは継続的に動くわけではありません。 1 秒間に移動できるマウスは 1 匹だけであるため、マウスは締め切り前のタイムスロットを効果的に競い合います。 これはスケジュールの問題になります。各マウス i は特定の移動数 (n − x_i) を必要とし、時刻 x_i までに十分なターンを受け取る必要があります。 

これを書き直すと、各マウスは完全に処理できた場合に「利益」1 を提供し、サイズ x_i の制約ウィンドウがあります。 最良の戦略は、利用可能なウィンドウ内で最も簡単に完了できるマウスを選択することです。 これは当然、開始位置でソートし、累積時間を尊重しながら何個完了できるかを貪欲に数えることを示唆しています。

マウスは、猫までの距離が大きい順に (または同等の開始位置が小さい順に) 処理されます。 マウスを検討するたびに、必要な移動数をマウスに割り当てようとします。 いずれかの時点で期限を超過した場合は、実現可能性の追跡に応じて、それに応じて停止またはスキップします。 最終的な構造は、実現可能性の条件の下で最大のプレフィックスを選択することになります。

 | 仕分け後の欲張りなスケジューリング | O(k log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各ネズミが一定の処理時間を必要とし、猫の到着によって課せられる期限があるものとして再解釈します。 

1. 各マウスについて、穴に到達するのに必要な時間 (n − x_i) を計算します。 これは、移動するために選択する必要がある回数です。 
2. マウスを開始位置で降順に並べ替えます。 期限が厳しいため、穴に近いマウスが優先されます。 それらを遅らせると、即座に損失が発生する危険があります。 
3. 保存しようとしているマウスへの動きの割り当てに費やした秒数を表す実行カウンターを維持します。 このカウンターは、スケジュールにおけるグローバルな時間の使用状況を表します。 
4. ソートされた順序でマウスを繰り返します。 各マウスについて、必要な移動時間をカウンターに追加します。 
5. 猫が関連する境界に到達する前に、いずれかの時点で累積時間が利用可能な安全な移動の数を超えた場合、このマウスは保存できず、カウントの増加が停止されます。 
6. それ以外の場合、このマウスはスケジュールが成功したものとしてカウントされます。 

重要な考え方は、保存されたすべてのマウスはスケジュール内の連続した時間ブロックを消費し、猫の進行によって実行可能範囲がなくなる前に、より早いマウス (穴に近い) の完了が保証されなければならないということです。 

### なぜ効果があるのか

 猫はいつでも、単調増加の制約を強制します。つまり、猫がその位置を通過すると、その位置は永久に安全ではなくなります。 これにより、暗黙の期限前に、選択した各マウスに十分な初期タイムスロットを割り当てることができるかどうかのみが実現可能性を左右する構造が作成されます。 位置によって並べ替えることにより、最も制限的なケースが常に最初に考慮されるようになります。 貪欲な蓄積により、残りのスケジュールに収まらないマウスの初期の時間を「無駄にする」ことがなくなります。 すべてのマウスが同じ単一の単位時間リソースをめぐって競合するため、最適性は、増加する制約の下で、重複しない時間要件の最大数でスケジュールを埋めることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        x = list(map(int, input().split()))

        # sort mice by closeness to hole (largest x first)
        x.sort(reverse=True)

        time_used = 0
        saved = 0

        for xi in x:
            need = n - xi

            if time_used + need <= xi:
                time_used += need
                saved += 1
            else:
                break

        print(saved)

if __name__ == "__main__":
    solve()
```このコードは、最も時間に敏感であるため、穴に最も近いマウスが最初に処理されるように、まずマウスを並べ替えます。 マウスごとに、穴に到達するまでに必要な移動回数を計算します。 変数`time_used`すでにスケジュールされているマウス移動の合計数を追跡します。 必要な動きを追加しても、猫が開始位置に到達する前に終了できる場合にのみ、マウスを受け入れます。 この条件が失敗すると、残りのマウスの拘束がさらに弱くなるため、それ以上マウスを保存することはできません。 

重要な実装の詳細は不等式です`time_used + need <= xi`。 これは、ネズミに割り当てられたすべての作業は、猫が開始位置に到達する前に行われなければならないという事実をコード化しています。

 ## 特殊なケース

 位置 1 付近の密集したクラスターは、スケジューリング制約を最も明確に示します。 n = 10 や x = [1,1,1] のような入力の場合、各マウスはデッドラインが 1 であるのに 9 回の移動を必要とするため、おそらくすべてが実現不可能になります。 アルゴリズムは、最初の追加後に実行不可能性を即座に検出します。`time_used`, 課題が1つでも期限条件を超えているためです。 

x = [n−1, n−1, n−1] など、穴に近い対称の場合は、反対の動作を示します。 各ネズミは 1 回の移動のみを必要とし、期限は十分に長いため、猫がその位置に到達する前に複数の移動をスケジュールすることができます。 貪欲な累積は違反することなく継続し、累積作業が利用可能な安全時間を超えた場合にのみ制約がバインドされることが確認されます。
