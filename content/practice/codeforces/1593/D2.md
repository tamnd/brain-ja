 ## 問題の理解

 小さな整数の配列から始めます。 任意の位置を繰り返し選択して、同じ正の整数を減算することができます。$k$選択した要素から、位置ごとに独立して何度でも実行できます。 すべての操作の後、配列エントリの少なくとも半分が何らかの値に等しくなることが観察されます。 

タスクは最大の整数を決定することです$k$このシナリオは実現可能です。 そのような上限がない場合は、$k$、戻ります$-1$。 

重要な解釈は、各要素が$a_i$に変換されます$$a_i - t_i \cdot k$$負でない整数の場合$t_i$、 どこ$t_i$インデックスに操作を適用した回数です$i$。 

少なくとも必要です$n/2$要素は最終的に同じ値になります。 したがって、値が存在する必要があります$x$少なくともそうなるように$n/2$インデックスが満たす$$a_i - t_i k = x$$再配置すると$$a_i \equiv x \pmod{k}.$$したがって、条件は基本的にモジュラー構造に関するものです。数値の少なくとも半分は同じ剰余クラスのモジュロ内に存在する必要があります。$k$そして、そのクラス内では、次の倍数を減算することによって、それらを単一の最終値に揃えることもできなければなりません。$k$。 

制約は非常に小さいです。$n \le 40$そして合計$n$テスト全体での値は最大 100 です。これにより、おおよそより悪いものは即座に排除されます。$O(n^3)$実際のテストごとに。 また、答えはグローバル構造ではなく数値間の関係に依存するため、ペアワイズまたはトリプルワイズの構築で十分であることも示唆しています。 

値が負の場合、微妙な問題が発生します。 減算には制限がないため、負の値は完全に有効な中間値であり、合同式は依然として通常どおり動作します。 

自明ではないエッジケースの 1 つは、次の条件に関係なく、すべての数値を等しくできる場合です。$k$。 たとえば、すべての要素が同一の場合、$k$操作が必要ないため機能します。 この場合、答えには制限がなく、次のようにする必要があります。$-1$。 もう 1 つの注意が必要なケースは、数値間の差がゼロであるか、大きく繰り返されて有効な約数が多くなり、単純な gcd 推論を慎重に処理する必要がある場合です。 

## アプローチ

 強引な解釈とは、あらゆる可能性を試すことです$k$少なくとも作ることができるかどうかを確認してください$n/2$要素が等しい。 固定の場合$k$、考えられるすべてのターゲット残基を考慮し、要素の少なくとも半分が の倍数を減算することによって整列できるかどうかを確認する必要があります。$k$。 しかし、$k$値間の差異までの範囲に及ぶ可能性があり、場合によっては最大で$10^6$、直接列挙することが不可能になります。 

重要な洞察は、視点を逆転させることです。 直す代わりに$k$、等しくなることを望む要素のグループを修正します。 2 つの要素を選択するとします$a_i$そして$a_j$いくつかの操作の後、最終的には等しくなります。 したがって、それらの差は次の式で割り切れるはずです。$k$、 それで$k$分けなければなりません$|a_i - a_j|$。 

ここでこれを拡張します: 少なくとも次のセットがある場合$n/2$要素が等しくなると、選択された$k$操作を元に戻した後、そのセット内の任意の 2 つの要素の差を除算する必要があります。 演算は次の倍数を減算するだけなので、$k$、グループ内のすべての要素は合同モジュロです$k$したがって、元の配列内のすべてのペアの差は、次の値で割り切れる必要があります。$k$一貫したシフトまで。 

これにより、候補となる基本要素ごとに建設的なアプローチが可能になります。$a_i$、差の gcd を計算します。$|a_j - a_i|$全体的に$j$。 任意の有効な$k$大きなグループを整列させるには、この gcd を分割する必要があります。 それを修正するには$i$、との違いがあるすべての要素$a_i$は、候補グループを形成するためにこの gcd で割り切れます。 次に、少なくとも達成できるかどうかを確認します$n/2$要素を整列させ、すべての有効なグループにわたる最大 gcd を追跡します。 

最後に、すべての要素がすでに同一である場合、すべての要素が$k$これは、一部の解釈では gcd が 0 であることに対応し、出力します。$-1$。 

本質は、この構造が、可分性の下でのペアごとの差分と gcd 閉包によって駆動されるということです。

 ## アルゴリズムのチュートリアル

 私たちは、潜在的な最終的な等しい値クラスの参照点として各要素を試すことを中心にソリューションを構築します。 

1. インデックスを修正する$i$。 仮定する$a_i$操作後に平等になるグループの一部です。 

これは、最終的な等しい要素の少なくとも半分が何らかのサブセットに由来する必要があり、そのうちの 1 つをアンカーとして扱うことができるため、有効です。 
2. 絶対差を計算する$|a_j - a_i|$みんなのために$j \ne i$、gcdを取得します。 

この gcd は最大ステップ サイズを表します$k$これは、これらすべての違いを単一の値に合わせて互換性を持たせることと一致します。 
3. すべての差がゼロの場合、すべての要素がすでに等しいことを意味します。 その場合は、いずれか$k$動作するので戻ります$-1$。 
4. それ以外の場合は、この gcd を候補にします$g$。 満たす要素の数を数えます$a_j \equiv a_i \pmod{g}$。 

これらはまさに、ステップ サイズの演算を使用して同じ最終値に等しくできる要素です。$g$。 
5. この数が少なくとも$n/2$、答えを更新します$g$。 
6. すべてのアンカーに対して繰り返します$i$、有効な最大値を返します$g$。 

### なぜ効果があるのか

 有効なソリューションには、少なくとも次のサブセットが必要です。$n/2$最終的に等しい要素。 このサブセット内の任意の要素を参照として選択します。 サブセット内の他の要素の場合、元の値は次の倍数異なります。$k$同じ数の操作を元に戻した後、元の違いは次の割り算と互換性がある必要があります。$k$。 これにより、$k$サブセット内のすべてのペアごとの差を除算します。これは、選択したアンカーからの差の gcd を除算する必要があることを意味します。 逆に、数値がこの gcd 差分構造体で割り切れる場合は、演算回数を割り当ててそれらを揃えることができます。 これにより、有効な$k$有効な多数派と互換性のあるサブセットから派生した値と gcd。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # check if all equal
        if all(x == a[0] for x in a):
            print(-1)
            continue
        
        ans = 0
        
        for i in range(n):
            g = 0
            for j in range(n):
                if i != j:
                    g = gcd(g, abs(a[j] - a[i]))
            
            if g == 0:
                continue
            
            cnt = 0
            for j in range(n):
                if (a[j] - a[i]) % g == 0:
                    cnt += 1
            
            if cnt >= n // 2:
                ans = max(ans, g)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての要素が同一であるという自明なケースを処理することから始まり、これにより無制限の答えが直接トリガーされます。 メインループは各要素を潜在的なアンカーとして扱い、それに対するすべての差の gcd を計算します。 その gcd は、整列された大規模なサブセットの互換性を維持する可能な限り最も強力なステップ サイズを表します。 次に、この剰余クラスに属する要素の数を確認します。 少なくとも$n/2$一致は有効とみなされます。 

gcd 条件だけでは一貫性は保証されますが、十分な要素のメンバーシップは保証されないため、モジュロ チェックが必要です。

 ## 特殊なケース

 すべての数値が同一の場合でも、すべての減算パターンによって数値は同一に保たれるため、答えには制限がありません。 アルゴリズムは均一性チェックによってこれを早期に検出し、すぐに返します。$-1$これにより、ゼロが生成される誤った gcd 計算が回避されます。 

差がすべて大きな公約数の倍数である場合、複数のアンカーは同じ gcd を生成し、すべてのアンカーが互換性のある候補に寄与するため、アルゴリズムは一貫して最大の有効なアンカーを識別します。 

配列に、1 つの値の大多数を持つ 2 つの異なる値が含まれている場合、多数派クラスのアンカーからの gcd は、アラインメントを維持するステップ サイズを正しくキャプチャし、カウント ステップにより、少数派の要素が妥当性を誤って拡大しないことが保証されます。
