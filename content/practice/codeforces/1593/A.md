 ## 解決策
 ## 問題の理解

 選挙では 3 人の候補者が与えられ、それぞれの現在の投票数は次のとおりです。$a$、$b$、 そして$c$。 課題は、各候補者が確実に勝者となるために必要な追加投票数を個別に決定することです。 勝者は、厳密には他の 2 人の候補者よりも多くの票を獲得していると定義されます。 各候補者について、他の 2 人の票は固定されたままです。 目標は、問題の候補者を確実に有利にすることです。 

制約により、最大で$10^4$テストケース、投票数は最大$10^9$。 これは、テスト ケースごとに数十億の操作が必要となる可能性があるため、潜在的な追加投票を反復するソリューションは遅すぎることがすぐにわかります。 候補者ごとに必要な投票数を一定時間で数学的に計算するアプローチが必要です。 

候補者がすでに同じ票数を持っている場合、明らかではないエッジケースが発生します。 たとえば、投票が$a=0, b=0, c=0$、各候補者が他の候補者を上回るには、ゼロではなく、ちょうど 1 票が必要です。 もう 1 つの微妙なケースは、候補者がすでに他の候補者よりも厳密に多くの票を獲得している場合に発生します。 例えば、$a=10, b=5, c=5$： 候補者$a$追加の票はゼロですが、他の票は上回るのに十分な票が必要です$a$。 これらの事例は、平等を慎重に扱い、「厳密に大きい」条件を強制することの重要性を示しています。 

## アプローチ

 ブルートフォースソリューションでは、各候補者が他の候補よりも厳密に先になるまで、各候補者に票を追加するシミュレーションが行われます。 候補者にとって$a$、あなたは増やすでしょう$a$まで一つ一つ$a > \max(b, c)$、同様に$b$そして$c$。 正しいのですが、これには最大で$10^9$最悪の場合は増加し、大きな入力の場合は失敗します。 

重要な洞察は、シミュレーションが必要ないということです。 他の候補を上回るには、他の 2 つの候補の現在の最大値を知り、その差を計算するだけで済みます。 候補者にとって$a$、必要な追加の最小投票数は$\max(b, c) - a + 1$ただし、次の場合はゼロに制限する必要があります。$a$はすでに厳密に大きいです。 この推論は次の場合にも同様に機能します$b$そして$c$。 これにより、問題はテスト ケースごとの候補ごとに数回の算術演算に変換され、定数時間の計算が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大(a,b,c)) | お(1) | 大量の投票には遅すぎる |
 | 最適 | 候補ごとに O(1)、テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、3 つの整数を読み取ります。$a$、$b$、$c$票を代表します。 
3. 候補者向け$a$、必要な追加投票を次のように計算します。$\max(0, \max(b, c) - a + 1)$。 内側の最大値から最も強力な競合他社を見つけます。$a$ギャップを与え、1 を追加すると確実になります$a$厳密には大きくなります。 使用する$\max$ゼロを指定すると、次の場合に否定票を提案しなくなります。$a$すでに先にあります。 
4. 候補に対して同じ計算を繰り返します。$b$そして$c$。 のために$b$、 使用$\max(a, c) - b + 1$; のために$c$、 使用$\max(a, b) - c + 1$。 
5. テスト ケースの 3 つの結果を出力します。 

機能する理由: 各ステップで、各候補者が現在のリーダーを追い抜くまでの距離を正確に計算します。 1 つ追加すると、厳密な優位性が保証されます。 このアプローチは、勝利条件を直接強制し、他の候補者の調整から独立し、問題の要件に一致するため、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    A = max(0, max(b, c) - a + 1)
    B = max(0, max(a, c) - b + 1)
    C = max(0, max(a, b) - c + 1)
    print(A, B, C)
```コードはアルゴリズムに直接に従います。 高速 I/O を使用します`sys.stdin.readline`以来$t$大きくなる可能性があります。 計算中`max(b, c) - a + 1`厳格な優越条件を強制します。 外側`max(0, …)`すでにリードしている候補者に対して負の数値が返されないようにします。 このソリューションは投票数のループを回避し、多数の場合のパフォーマンスの問題を防ぎます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースは 3 つの max/diff 演算を計算します (すべて O(1))。 |
 | スペース | お(1) | 入力変数以外に追加の構造は必要ありません。 |

 与えられた$t \le 10^4$テスト ケースごとに一定の操作を行うと、ソリューションは 1 秒の制限時間に簡単に適合します。 最大メモリ使用量は、256 MB の制限に比べれば無視できます。

 ## 特殊なケース

 入力用`0 0 0`、各候補者は同点です。 このアルゴリズムは、他の投票の最大値 (0) を計算し、候補者の投票 (0) を減算し、1 を加算して、候補者ごとに 1 票を与えます。 次の理由により、負の数値は返されません。`max(0, …)`ラッパー。 入力用`1000000000 0 0`、 候補者`a`はすでにリードしているため、`a`0 を生成します。`b`そして`c`計算する`max(1000000000,0)-0+1 = 1000000001`を超えるために必要な票を正しく提供します。`a`。 最大投票数や平等性を含むすべてのエッジ条件が処理されます。
