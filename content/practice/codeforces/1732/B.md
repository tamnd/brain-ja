 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられており、それを非減少シーケンスに変換したいと考えています。つまり、文字列に次の値が含まれ始めると、`1`に戻ってはいけません。`0`。 最終的な形式は、いくつかの形式に似ている必要があります。`0`s の後にいくつかの`1`s.

 許可される唯一の操作はサフィックス反転です。 インデックスを選択します`i`、すべての文字を位置から反転します`i`最後まで。 この操作はサフィックスに対してグローバルであるため、1 回の移動で多くの位置を修正できますが、以前は正しい構造が壊れる可能性もあります。 

タスクは、次の形式の文字列に到達するために必要な、このようなサフィックス反転の最小数を見つけることです。`000...111...`。 

制約が十分に大きいため、各操作で文字列を直接反転することをシミュレートするアプローチは遅すぎます。 全長が最大 2・10^5、テスト ケースが最大 10^4 の場合、O(n^2) シミュレーションは最悪の場合すでにコストが高すぎるため、ソリューションでは問題をテスト ケースごとの線形スキャンに減らす必要があります。 

素朴な間違いは、最初の倒置法を修正しようと貪欲に考えることから起こります。 たとえば、`1010`、最初に反転します`1 -> 0`移行は合理的であるように見えますが、後の構造によっては、その選択が最適ではない可能性があります。 もう 1 つの一般的な失敗は、文字通りフリップをシミュレートすることです。これにより、O(n^2) の動作と TLE が発生します。 

より微妙なエッジケースは、次のような文字列を交互に配置することです。`0101010`ここで、すべての位置はターゲット構造に対して「間違っています」が、最適な反転は重なり合っているため、答えは単に不一致の数ではありません。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 指定された文字列から、すべての接尾辞を反転して、最大で次のものを生成してみることができます。`n`ステップごとの新しい状態。 これは当然、状態に対する BFS または操作シーケンスに対する再帰的検索につながります。 原理的には正しいですが、各反転が非常に非局所的な方法で長い接尾辞を変更するため、個別の状態の数は指数関数的になります。 状態空間は次のとおりであるため、状態をキャッシュしてもあまり役に立ちません。`2^n`可能な文字列は大きすぎます。 

重要な観察は、最後の文字列が非常に構造化されているということです。それは、次のような単調な接頭辞である必要があります。`0`に続いて`1`s. 最終的な文字列を前方に構築することを考えるのではなく、左から右に「修復」する必要がある遷移の数を追跡します。 

重要な洞察は、文字列をスキャンし、ターゲット構造に対して方向の変更を強制された回数を数えることです。 現在のキャラクターが単調なターゲットで期待されるものと一致しないたびに、反転が必要になる可能性のある境界を効果的に作成します。 ただし、サフィックスの反転には特定の効果があります。位置の反転です。`i`すべてを右に切り替えます。これは、これまでに適用された反転のパリティに応じて、将来の文字の意味が切り替わることを意味します。 

これにより、スキャン中に文字列の「状態」を何回切り替える必要があるかを追跡する問題が軽減されます。 予想される方向の各変化は答えに寄与しますが、隣接する変化はパリティに応じてキャンセルされる可能性があります。 これにより、等しい文字間の遷移と、文字列によってサフィックス パリティの再解釈が強制された回数をカウントすることのみを考慮する線形貪欲スキャンが行われます。 

これを理解するもう 1 つの方法は、目的のモノトーン構造が現在見ているものに対して反転を必要とする境界に遭遇するたびに、答えをインクリメントし、将来のすべての文字の解釈を概念的に切り替えることです。

 ## アルゴリズムのチュートリアル

 これまでにサフィックスが偶数回反転されたか奇数回反転されたかを表す論理「現在のパリティ」を維持します。 実際に文字列を変更する代わりに、このパリティに基づいて各文字を解釈します。 

また、実行中の回答も維持します。 

1. 変数を初期化する`flip_parity = 0`、反転はまだ適用されていないことを意味します。`ans = 0`。 
2. 文字列を左から右にスキャンし、現在のパリティに基づいて各文字を解釈します。 パリティが偶数の場合、文字は変更されません。 パリティが奇数の場合、文字は論理的に反転されます。 
3. 現在解釈されている文字と以前に解釈されている文字をターゲットの単調な意味で比較します。 有効な構造は決して次のようなものになってはなりません。`1`に戻る`0`。 したがって、すでに「入った」かどうかを追跡します。`1`地域。 
4. 現在の解釈で単調性の違反が検出された場合、ここから始まる別の反転を適用しない限り接尾辞を修正できないことを意味します。 インクリメントします`ans`そして切り替えます`flip_parity`。 
5. 今後の文字を解釈するために常に更新されたパリティを使用して、スキャンを続行します。 

重要な推論ステップは、単調性が崩れるたびに、以前の位置を再訪せずに実行可能性を復元する唯一の方法は、その位置からそれ以降を反転することである、ということです。これは、サフィックス反転が唯一許可される操作であるためです。 したがって、検出された各違反は、最適な戦略で必要な 1 つの操作に対応します。 

### なぜ効果があるのか

 スキャンのどの接頭辞でも、アルゴリズムは、ある程度の数の接尾辞の反転を適用した後、文字列の一貫した解釈を維持します。 その解釈の下で単調条件に違反する位置に遭遇した場合、有効な解決策は順序制約を修正するためにその点またはその前に少なくとも 1 つの反転を導入する必要があります。 最も早い位置を選択しても、後で必要な操作の数が増えることはありません。フリップを遅らせてもサフィックス内の矛盾の数が増えるだけだからです。 これにより、貪欲な選択がローカルに強制され、グローバルに最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    flip = 0
    ans = 0

    prev = 0  # previous interpreted value

    for ch in s:
        cur = int(ch)
        if flip:
            cur ^= 1

        if cur < prev:
            ans += 1
            flip ^= 1
            cur ^= 1

        prev = cur

    print(ans)
```このソリューションでは、明示的な文字列の変更を回避し、代わりにパリティ フラグを使用して反転の効果をシミュレートします。 変数`prev`モノトーン シーケンス内の最後の有効な解釈されたビットを追跡します。 現在のビットが必要な順序に違反している場合、パリティを切り替えて操作数を増やすことによって、その位置でのサフィックス フリップの適用をシミュレートします。 

微妙な点は、すぐに再解釈することです。`cur`パリティを切り替えて確認した後`prev`変換されたサフィックスとの一貫性が保たれます。 これにより、違反は検出されたものの正しく伝播されない、オフバイワンの間違いが防止されます。

 ## 特殊なケース

 キーエッジケースはすでにモノトーンっぽい文字列です`000111`。 アルゴリズムが反転をトリガーすることはありません。`prev`決して減少しないので、答えはゼロのままです。 

もう 1 つのエッジ ケースは、次のような交互ビットの単一の長時間実行です。`010101`ここでは、すべてのステップが局所的に正しいように見えますが、パリティ反転が蓄積されます。 このアルゴリズムは、強制修正を構造違反ごとに 1 回ずつ正確にカウントし、最終的なカウントは文字列を安定させるために必要なサフィックス操作の最小数と一致します。
