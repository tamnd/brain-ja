 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 インデックスを繰り返し選択する場合があります$i$そして交換してください$a_i$による$\gcd(a_i, i)$。 この操作の実行にはコストがかかります$n-i+1$、そのため、配列の終わりに近い位置での操作は低コストになります。 

目標は、配列全体の gcd を以下と等しくすることです。$1$最小限の総コストで。 

この操作は非常に制限された形式になっています。 任意の値を自由に割り当てることはできません。 位置操作後$i$、値は次のようになります$\gcd(a_i,i)$、これは常に次の約数です$i$。 以来$n \le 20$、配列は非常に小さいです。 これは、いくつかの可能性を試すことを含む解決策が実現可能であることを直ちに示唆しています。 各テスト ケースに含まれる要素は最大 20 個であるため、テスト ケースの数が多くてもあまり問題になりません。 

最初の観察は、配列全体の gcd が$1$、終わりました。 それ以降は実際の値は関係ありません。 

配列にすでに gcd がある場合、微妙なエッジ ケースが発生します。$1$。 

例：```
n = 4
a = [5, 10, 15, 20]
```gcd はすでに$1$、したがって、答えは次のとおりです$0$。 常に少なくとも 1 つの操作を実行するソリューションは間違っています。 

もう 1 つの興味深いケースは次のとおりです。```
n = 1
a = [2]
```インデックスでの操作の適用$1$値をに変更します$\gcd(2,1)=1$。 費用は$1$。 答えはそうではありません$0$。 

3 番目のエッジ ケースは、1 つの操作では十分ではないが、非常に安価な組み合わせで十分な場合です。```
n = 5
a = [120, 60, 80, 40, 80]
```位置を変更する$5$与える$5$、それだけでは十分ではありません。 Changing positions$4$そして$5$で割り切れる値を与える$4$そして$5$、その gcd は$1$。 最適な答えは$3$、以前のポジションのコストではありません。 

これらの例は、重要な問題は最終的な値そのものではなく、いくつかの位置を変更した後に配列全体の gcd がどのように変化するかであることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、すべての操作シーケンスが試行されます。 わずか 20 個の位置でも、可能な操作のサブセットの数は次のとおりです。$2^{20}$、各ポジションは複数回選択できます。 このような検索は急激に増加するため、不要です。 

操作の構造により、より強力な観察が可能になります。 配列全体の現在の gcd が次であると仮定します。$g$。 

位置を変更すると$i$、新しいグローバル gcd は次のようになります。$$\gcd\bigl(g,\gcd(a_i,i)\bigr).$$これは、他のすべての要素が依然として次の倍数に寄与するためです。$g$、選択した位置のみが変更されます。 

次にコストを見てみましょう。$$\text{cost}(n)=1,\qquad \text{cost}(n-1)=2,\qquad \text{cost}(n-2)=3.$$最も安い位置は常に配列の最後にあります。 

重要な観察は、答えがこれより大きくなることは決してないということです。$3$。 

ポジションに演算を適用すると$n$、$n-1$、 そして$n-2$とすると、グローバル gcd は次のようになります。$$\gcd(g,n,n-1,n-2).$$3 つの連続する整数の場合、gcd は常に次のようになります。$1$。 したがって$$\gcd(g,n,n-1,n-2)=1.$$総費用は$$1+2+3=6.$$しかし、Codeforces 編集ソリューションでは、さらに強力な事実が使用されます。$n\le 20$、最後の位置をまったく使用しない、1 つ、2 つ、または 3 つを使用するだけで十分かどうかをテストする必要があるだけです。 最適な答えは常にそれらの可能性の中にあります。 

以下を直接確認できます。 

- コスト$0$：何もしない。 
- 料金$1$: 位置のみに適用$n$。 
- 料金$2$: 位置のみに適用$n-1$。 
- 料金$3$: どちらかの位置にのみ適用されます$n-2$、または、連続する gcd 削減をチェックすることで見つかった答えに効果的に対応する安価な組み合わせを使用します。 

受け入れられている解決策は、これらの可能性をコストの増加順にテストするだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. gcd を計算します。$g$配列全体の。 
2. もし$g=1$、 戻る$0$。 目標はすでに達成されています。 
3. 位置に演算を適用するかどうかを確認します$n$それだけで十分です。 この操作の後、新しいグローバル gcd は次のようになります。$$\gcd(g,n).$$これが等しい場合$1$、返品費用$1$。 

1. 位置に演算を適用するかどうかを確認します$n-1$それだけで十分です。 結果の gcd は次のようになります。$$\gcd(g,n-1).$$これが等しい場合$1$、返品費用$2$。 

1. 位置に演算を適用するかどうかを確認します$n-2$それだけで十分です。 結果の gcd は次のようになります。$$\gcd(g,n-2).$$これが等しい場合$1$、返品費用$3$。 

1. これまでのチェックがいずれも成功しなかった場合、答えは次のようになります。$3$。 

最後のステップは、公式ソリューションで使用されている既知のプロパティに従います。 最後のいくつかの位置を変更することで、いつでもグローバル gcd を次のように強制できます。$1$、最小残りコストは正確に$3$。 

### なぜ効果があるのか

 しましょう$g$元の配列の gcd になります。 

位置での操作の実行$i$数値を通じてのみグローバル gcd に影響を与えることができます$i$、新しい値は の約数になるため、$i$。 結果のグローバル gcd は正確に次のようになります。$\gcd(g,i)$。 

左に行くほどコストが高くなるため、最初は最も安い位置から試してみます。$n$、次に安いのは$n-1$、 それから$n-2$。 

これらの個々の操作のいずれも gcd を減少させない場合、$1$、この問題の標準引数は、最後のいくつかの位置を使用すると常に gcd が達成されることを示しています。$1$総費用付き$3$。 したがって、コストを確認する$0$、$1$、$2$、 そして$3$あらゆる可能性を使い果たします。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    g = 0
    for x in a:
        g = gcd(g, x)

    if g == 1:
        print(0)
    elif gcd(g, n) == 1:
        print(1)
    elif gcd(g, n - 1) == 1:
        print(2)
    else:
        print(3)
```コードは、配列全体の gcd を計算することから始まります。 これが配列から実際に必要な唯一の情報です。 

最初の条件は、gcd が既に設定されている配列を処理します。$1$。 

次の 2 つの条件では、可能な限り低コストの操作をテストします。 位置$n$費用$1$、および位置$n-1$費用$2$。 

どちらも機能しない場合は、問題の既知の特性によりコストが保証されます。$3$十分なので印刷します$3$。 

よくある間違いは、実際の配列の変更をシミュレートしようとすることです。 それは不必要です。 グローバル gcd のみが重要であり、その変更は別の gcd 操作で直接計算できます。

## テストケース```python
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        g = 0
        for x in a:
            g = gcd(g, x)

        if g == 1:
            ans.append("0")
        elif gcd(g, n) == 1:
            ans.append("1")
        elif gcd(g, n - 1) == 1:
            ans.append("2")
        else:
            ans.append("3")

    return "\n".join(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("1\n1\n1\n") == "0", "already gcd 1"
assert run("1\n1\n2\n") == "1", "single element"
assert run("1\n2\n2 4\n") == "2", "sample case"
assert run("1\n3\n3 6 9\n") == "2", "sample case"
assert run("1\n6\n2 4 6 9 12 18\n") == "0", "gcd already 1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |$[1]$|$0$| すでに解決済み |
 |$[2]$|$1$| 位置 1 での単一動作 |
 |$[2,4]$|$2$| コスト2の場合 |
 |$[3,6,9]$|$2$| 位置$n-1$作品 |
 |$[2,4,6,9,12,18]$|$0$| 既存の gcd 1 |
