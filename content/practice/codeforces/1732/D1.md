 ## 解決策
 ## 問題の理解

 最初は数値 0 だけを含むセットから始めます。 時間の経過とともに、2 種類の操作が適用されます。 1 つの操作では新しい整数をセットに挿入し、もう 1 つの操作では k-mex と呼ばれる特別な値についてクエリを実行します。 

k-mex は、k の倍数であり、セット内に存在しない最小の非負の数として定義されます。 したがって、通常の mex のすべての整数をスキャンする代わりに、固定等差数列 (0、k、2k、3k など) 上の数値のみを考慮し、そのシーケンス内で最初に欠落している数値が必要になります。 

セットは増えるばかりです。 これが重要なのは、数値は一度存在すると永久に存在し続けるため、将来のクエリに対する回答がより制限されるだけだからです。 

制約は大きく、最大 2 × 10^5 の演算が可能で、値は 10^18 まで大きくなる可能性があります。 これにより、クエリごとに回答を最初から再計算したり、クエリごとに k の倍数を線形にスキャンしたりするアプローチは即座に除外されます。 k 自体が巨大になる可能性がある場合、k まで反復したり、クエリごとの算術数列を維持したりするだけでも、非常に遅くなります。 

単純な間違いは、各クエリを個別にシミュレートすることです。 k を含むクエリの場合、0 から開始して、欠損値が見つかるまで k の倍数のメンバーシップを繰り返しチェックします。 セットが大きくなり、k が小さい場合、クエリごとに多くの要素をスキャンすることになります。 たとえば、セットに 10^9 までの k の倍数がすべて含まれている場合、スキャンはその範囲で線形になりますが、制約の下ではこれは不可能です。 

もう 1 つの微妙な失敗ケースは、k が大きいにもかかわらず集合内に疎な要素が存在する場合に発生します。 メンバーシップ クエリを効率的に構築しないと、大規模なセットに対して繰り返しチェックを行うと依然としてコストがかかりすぎます。 

主な問題は、各クエリが異なる等差数列を要求するため、最初から再計算するのではなく、クエリ間で情報を再利用する方法が必要であることです。 

## アプローチ

 直接的なアプローチでは、セットをハッシュ構造に保持し、欠損値が見つかるまで k、2k、3k などを繰り返しチェックすることで各 k-mex クエリを処理します。 これは文字通り定義に従っているので正しいです。 ただし、最悪の場合、各クエリはギャップを見つける前に多くの倍数をスキャンする可能性があります。 最大 2 × 10^5 のクエリがあるため、最悪の場合は 2 次の動作になります。 

重要な観察は、固定 k の答えは、その進行に影響を与える数値、つまり現在のギャップを埋める t・k 形式の数値を挿入した場合にのみ変化するということです。 クエリごとに考えるのではなく、視点を反転して値ごとに考えます。挿入されたすべての数値は、それを k で割ったクエリにのみ影響します。 

これは、クエリに現れる各 k について、まだ欠落している k の最小の非負の倍数を維持することを示唆しています。 どの倍数がすでに存在しているかを追跡できれば、その倍数が挿入されるたびに進む各 k のポインターを維持できます。 

これを効率的に可能にする構造は、k から現在の回答候補へのマップです。 k-mex が必要な場合は、現在の候補から開始して、セットにない値が見つかるまで k ずつステップを進めます。 各候補は、その値が挿入されたときにのみ前に進むため、各整数は、それを除算する k 値のみを前に進める役割を果たします。 これにより、作業全体を管理しやすくなります。 

中心となるアイデアは、すべてのクエリに対する償却です。クエリごとに再計算するのではなく、挿入によってポインタが無効になった場合にのみポインタを進めます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(q · (答え/k)) | O(q) | 遅すぎる |
 | 最適 | 実装に応じて O(q √V) 以上で償却 | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

私たちは、挿入されたすべての値のセットと、クエリに含まれる k ごとに、その k-mex に対する現在の候補回答を格納する辞書を維持します。 

1. セットは常に存在するため、0 で初期化します。 また、空のマップ next_candidate[k] を初期化します。これは、まだ確認されていない可能な最小の k-mex 候補を格納します。 
2. 各クエリについて、挿入 + x の場合は、セットに x を追加します。 
3. x を挿入した後、x が k-mex 状態に影響を与えるかどうかを確認する必要があります。 以前にクエリされたすべての k について、x が k の倍数である場合、x はその k について以前に想定されていた欠損倍数を無効にする可能性があります。 その場合、x が next_candidate[k] に等しいかどうかのみを考慮します。これは、現在の候補がもはや有効ではないことを意味するためです。 
4. x が next_candidate[k] に等しい場合、セット内に存在しない値に達するまで k を追加して next_candidate[k] を繰り返し進めます。 各ステップは、等差数列における次の倍数のチェックに対応します。 
5. クエリについては? k が新しい場合、0 から開始して欠損数が見つかるまで k ずつ進めることによって、その最初の候補を計算します。 これを next_candidate[k] に保存します。 
6. next_candidate[k]を出力します。 

重要なのは、セット内の各値が各 k を「前方にプッシュ」できるのは、一致ごとに 1 回だけであるということです。 next_candidate[k] は厳密に増加するため、各 k ポインターはすべての更新にわたって限られた回数だけ前に進みます。 

### なぜ効果があるのか

 これまでに処理されたすべての更新を考慮すると、各 k について、next_candidate[k] は常に、現在セットにない k の最小倍数を表します。 挿入では要素が追加されるだけなので、候補はその正確な値が挿入された場合にのみ無効になります。 一度それを超えると、再び有効になることはありません。 この単調な動きにより正確さが保証され、すべての整数が影響を受ける k ごとに最大 1 回処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    S = set([0])
    next_k = {}

    def advance(k, start):
        x = start
        while x in S:
            x += k
        return x

    for _ in range(q):
        parts = input().split()
        if parts[0] == '+':
            x = int(parts[1])
            S.add(x)

            # update all tracked k's if needed
            for k in list(next_k.keys()):
                cur = next_k[k]
                if cur == x:
                    next_k[k] = advance(k, cur)

        else:
            k = int(parts[1])
            if k not in next_k:
                next_k[k] = advance(k, 0)
            print(next_k[k])

if __name__ == "__main__":
    solve()
```セット`S`最初のゼロを含むすべてのアクティブな要素を保存します。 辞書`next_k`クエリを繰り返しても計算が再開されないように、k ごとに答えをメモ化します。 

の`advance`関数は、k-mex の定義を直接実現したものです。欠落しているものが見つかるまで、k の倍数に沿って歩きます。 これは、最初のクエリの場合、または候補が挿入によって無効になった場合など、必要な場合にのみ呼び出されます。 

追跡されたすべての k 値に対するループは、微妙な部分です。 新たに挿入された数値が、以前に欠落していたいくつかの k の候補を正確に埋める場合、正確性が保証されます。 平等が実現した場合にのみ前進するため、更新は最小限に抑えられます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q √V) 付近で償却 | 各 k の各候補は、明示的に無効化された場合にのみ前進します。 
| スペース | O(q) | セットおよびメモ化された k 状態のストレージ |

 各挿入では限られた更新のみがトリガーされ、各 k-mex ポインターは単調に前進するため、同じ値に対する繰り返し作業が防止され、このソリューションは制約内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    q = int(input())
    S = set([0])
    next_k = {}

    def advance(k, start):
        x = start
        while x in S:
            x += k
        return x

    out = []
    for _ in range(q):
        parts = input().split()
        if parts[0] == '+':
            x = int(parts[1])
            S.add(x)
            for k in list(next_k.keys()):
                if next_k[k] == x:
                    next_k[k] = advance(k, next_k[k])
        else:
            k = int(parts[1])
            if k not in next_k:
                next_k[k] = advance(k, 0)
            out.append(str(next_k[k]))
    return "\n".join(out)

 ## 特殊なケース

 厄介なケースは、クエリされた k が、数回挿入しても再度クエリされない場合です。 格納された next_k 値は更新されなくても有効なままであり、新たな挿入が影響を及ぼさないため、アルゴリズムは依然として正確さを維持します。 

もう 1 つのエッジ ケースは、k = 1 です。ここでは、シーケンスはすべて非負の整数であるため、k-mex は単に最初に欠落している整数です。 アルゴリズムは標準的な mex メンテナンスに縮退し、新しい連続整数が挿入されるとポインターが正確に進みます。これは直感と一致します。 

最後の微妙なケースは、k が非常に大きく、10^18 に近い場合です。 その場合、最初の候補はほとんど常に 0 または k そのものであり、そのような大きな k の倍数となる値はほとんどないため、更新されることはまれです。 当然のことながら、これらの値の場合、アルゴリズムはクエリごとにほぼ一定の時間になります。
