 ## 解決策
 ## 問題の理解

 いくつかの小さな行列から始めます`b`。 1 回のミラーリング操作で高さが 2 倍になります。 上半分は変更されず、下半分は上半分の行を逆順に書き込んだものになります。 

たとえば、現在の行列が次の場合:```
A
B
C
```ミラーリング後は次のようになります。```
A
B
C
C
B
A
```このプロセスは数回繰り返される場合があります。 未知の行列から始める`b`、数回のミラーリングの後、最終的に指定された行列を取得します。`a`。 

タスクは、元の行列の可能な最小の行数を決定することです。`b`。 

マトリックスには次のものだけが含まれます。`0`そして`1`, しかし、実際の値はあまり重要ではありません。 重要なのは、2 つの行が同一であるかどうかです。 

制約はわずかです。 どちらの寸法も最大で`100`、したがって、`O(n^2 * m)`ソリューションは簡単に十分に高速です。 行の比較コスト`O(m)`、そして最大でも`100`行があれば、行列を何度も完全にスキャンする余裕があります。 

難しいのは、ミラーリングの繰り返しが実際に構造的に何を意味するのかを理解することです。 

ミラーリングが行われるたびに、マトリックス全体がその中心の周りで対称になります。 操作を再度繰り返すと、その対称性が再帰的に維持されます。 これは、対称的な半分を繰り返し削除することによって、最終的な行列が約分可能である必要があることを意味します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

1 行の行列を考えてみましょう。```
1 3
0 1 0
```答えは`1`。 不用意に実装すると、永遠に縮小し続けようとしたり、高さが均一である必要があると想定したりする可能性があります。 

もう 1 つの微妙なケースは、行列が最も外側のレベルでのみ対称であり、再帰的ではない場合です。```
4 1
0
1
1
0
```答えは`2`、 ない`1`。 

行列全体は対称であるため、1 つの縮小が有効です。```
0
1
```ただし、この残りの行列は行が異なるため、それ自体はミラーリングによって生成されません。 

よくある間違いは、行列全体が対称であるかどうかを 1 回だけチェックすることです。 

奇数サイズの行列も重要です。```
3 1
0
1
0
```答えは`3`。 

ミラーリングでは行数が常に 2 倍になるため、元の行列を除くすべての生成された行列の高さは同じになります。 以来`3`奇数であるため、縮小操作はまったく不可能です。 

## アプローチ

 ブルートフォースの方法は、プロセスを逆方向にシミュレートすることです。 

現在次のような行列があるとします。`k`行。 もし`k`が偶数の場合、上半分が反転した下半分と等しいかどうかを確認できます。 この条件が当てはまる場合、行列は上半分をミラーリングすることによって生成された可能性があるため、行列を最初の部分まで縮小します。`k / 2`行を並べて続行します。 

最終的にはこれ以上縮小することはできなくなり、現在の高さが最小の有効な答えとなります。 

なぜこれが機能するのでしょうか? ミラーリングは完全に決定的であるためです。 行列が小さな行列から作成された場合、その前半は一意に後半を決定します。 親行列が何であるべきかについてあいまいさはありません。 

ここでは、ブルートフォース手法がすでに十分に高速です。 削減ごとに最大で比較します`n / 2`行のペアと各行の比較コスト`O(m)`。 高さは毎回半分になるため、総作業量は次のように制限されます。```
n*m + (n/2)*m + (n/4)*m + ...
```それは`O(n*m)`全体。 

重要な観察は、ミラーリングを繰り返すと再帰的対称性が生じるということです。 有効な縮小とは、現在の行列が 1 回対称になるだけではありません。 縮小後、より小さい行列は再び同じ特性を満たさなければなりません。 

この再帰的な構造により、貪欲なリダクションが最適化されます。 有効な元の行列が前半部分内に存在する必要があるため、削減が可能な場合は、すぐに実行しても問題はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰チェック | O(n² · m) | お(1) | 承認済み |
 | 最適な反復半減 | O(n・m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マトリックスを行ごとに読み取ります。 
2. 現在の行数を次のようにします。`k = n`。 
3. その間`k`が偶数である場合は、行列を減らしてみてください。 
4. 比較行`i`行のある上半分から`k - 1 - i`ごとに下半分から`0 ≤ i < k/2`。 

これは、下半分が上半分の逆であるかどうかをチェックします。これは、ミラー行列の定義です。 
5. いずれかのペアが異なる場合は、直ちに停止します。 

現在の行列はもう 1 回のミラーリング操作によって生成されることはできないため、これ以上の削減は不可能です。 
6. すべてのペアが一致する場合は、置き換えます`k`と`k / 2`。 

マトリックスは上半分から生成された可能性があるため、さらに小さな起源を探し続けます。 
7. ループが停止すると出力`k`。 

### なぜ効果があるのか

 アルゴリズムは、最初の`k`行は、一定回数のミラーリングの後に元の入力を生成できる有効な候補行列を形成します。 

マトリックスがミラーリング特性を満たす場合、可能な以前の状態は上半分だけです。 その半分に縮小すると、正確さが保たれます。 

ミラーリング プロパティが失敗した場合、より小さい先行ファイルは存在しません。 ミラーリング操作では常に、半分の間に完全な反転対称が作成されるため、この条件に違反すると、それ以上の縮小は不可能になります。 

削減が成功するたびに行列が厳密に半分になるため、プロセスは最終的に可能な最小サイズに達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [input().split() for _ in range(n)]

    k = n

    while k % 2 == 0:
        half = k // 2
        ok = True

        for i in range(half):
            if a[i] != a[k - 1 - i]:
                ok = False
                break

        if not ok:
            break

        k = half

    print(k)

solve()
```行列は行のリストとして保存されます。 必要なのは行間の等価比較だけであるため、各行は文字列のリストとして保持されます。 

変数`k`現在のアクティブな高さを表します。 最初は等しい`n`、マトリックス全体の高さ。 

ループ内では、次の場合にのみリダクションを試みます。`k`は均等です。 ミラーリングでは行数が常に 2 倍になるため、奇数サイズの行列をそれ以上減らすことはできません。 

比較:```
a[i] != a[k - 1 - i]
```必要な対称性を直接チェックします。 上半分の一番上の行は下半分の一番下の行と一致する必要があり、2 番目の行は最後から 2 番目の行と一致する必要があります。 

微妙な点は、物理的に小さな行列を決して作成しないことです。 私たちは単に減らすだけです`k`。 関連する行は常に最初になります`k`元の配列の行。 

もう 1 つの簡単な間違いは、以下を比較することです。```
a[i] != a[half + i]
```これは、ミラーリングされた半分ではなく、通常の回文の半分をチェックします。 下半分は逆の順序で表示される必要があります。

 ## 特殊なケース

 高さが奇数の場合を考えてみましょう。```
3 1
0
1
0
```アルゴリズムは次から始まります`k = 3`。 以来`k`奇数です、ループは決して始まらず、答えは残ります`3`。 

ミラーリングでは行数が常に 2 倍になるため、これは正しいです。 一連のミラーリングでは、より小さな行列から奇数サイズの行列を生成することはできません。 

ここで、1 つのレベルでのみ対称な行列を考えてみましょう。```
4 1
0
1
1
0
```アルゴリズムは以下をチェックします。```
row0 == row3
row1 == row2
```どちらも成功するので、`k`になる`2`。 

次にチェックします:```
row0 == row1
```これは失敗するため、アルゴリズムは停止して出力します。`2`。 

これは、再帰チェックが重要である理由を示しています。 サイズを完全に縮小するには、単一の対称レイヤーだけでは十分ではありません`1`。 

最後に、すべての行が等しいとみなします。```
8 1
1
1
1
1
1
1
1
1
```すべての対称チェックは成功します。```
8 -> 4 -> 2 -> 1
```アルゴリズムは正しく出力します`1`、可能な最小の元の行列。
