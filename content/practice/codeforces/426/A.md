 ## 解決策
 ## 問題の理解

 容量のあるカップもございます`s`そして水の入ったマグカップがいくつかあります。 プレイヤーは順番に空ではないマグカップを 1 つ選択し、そのカップにすべての水を注ぎます。 カップは空から始まり、水は取り除かれません。 いつでもカップ内の水の量がその容量を超えた場合、その動きをしたプレイヤーが負けになります。 

問題は、誰も失わないように、マグカップに何らかの順序で注ぐことができるかどうかです。 

重要な点は、どのマグカップも最終的には完全に注ぐ必要があるということです。 カップは水のみを獲得するため、すべての移動後の水の量はすべてのマグの体積の合計に等しくなります。 注ぐ順序は中間状態を変えるだけです。 

制約はわずかです。 マグカップは最大でも 100 個あり、各マグカップの容量は最大でも 10 個です。ここでは、多くの可能性を総当たりで検索しても十分に高速に実行されますが、この問題には、すべてを 1 つの比較に集約するはるかに単純な観察があります。 

よくある間違いは、注ぐ順序が重要であると考えることです。 次の入力を考えてみましょう。```
3 5
4 1 1
```正しい答えは次のとおりです。```
NO
```不注意なアプローチは注ぐ可能性があります`1`、 それから`1`、 それから`4`、より良い秩序が存在することを願っています。 しかし、最終的な水の量は常に`6`、カップの容量を超えています`5`。 最終的にはすべてのマグカップに注がなければならないため、誰かがカップから溢れさせなければなりません。 

総水量がカップの容量と正確に一致する場合、別のエッジケースが現れます。```
2 7
3 4
```正しい答えは次のとおりです。```
YES
```オーバーフローは、量が厳密に容量を超えた場合にのみ発生します。 正確に届く`7`許可されています。 

3 番目の見逃しやすい状況は、小さなマグカップがたくさんある場合です。```
5 4
1 1 1 1 1
```正しい答えは次のとおりです。```
NO
```それぞれの動きは無害に見えますが、5 杯目のマグカップの後には次のものが含まれています。`5`、容量を超えています。 

## アプローチ

 最も直接的な強引なアイデアは、可能な限りの注ぎ順を試すことです。 順列ごとにプロセスをシミュレーションし、カップがオーバーフローするかどうかを確認します。 

これが機能するのは、マグカップの順序を選択した時点でゲームが完全に決定されるためです。 少なくとも 1 つの順序付けによってオーバーフローが回避される場合、答えは次のようになります。`"YES"`。 

問題は、順列の数が階乗的に増加することです。 と`n = 100`、 がある`100!`可能な注文数は天文学的に大きくなります。 たとえ`n = 15`、1秒以内に網羅的に検索することはすでに不可能です。 

画期的な発見は、順序は実際には重要ではないということです。 

コップの中の水の量は増えるばかりです。 すべてのマグカップに注いだ後、カップにはすべてのマグカップの体積の合計が正確に含まれます。 この合計がカップの容量を超える場合は、どこかの段階でオーバーフローが発生する必要があります。 いかなる注文もそれを避けることはできません。 

一方、総量がカップの容量以下であれば、マグカップにどのような順序で注いでも安全です。 水位が最終合計を超えることはなく、最終合計はすでに適合しています。 

これにより、問題全体が次のチェックに集約されます。```
sum(a) <= s
```true の場合、印刷します`"YES"`。 それ以外の場合は、印刷します`"NO"`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マグカップの数を読み取ります。`n`そしてカップの容量は`s`。 
2. マグカップの巻リストを読みます。 
3. すべてのマグカップの体積の合計を計算します。 
4. 総水量とカップの容量を比較します。 

合計が以下の場合`s`、印刷`"YES"`。 

それ以外の場合は、印刷します`"NO"`。 

### なぜ効果があるのか

 カップは空から始まり、水は追加されるだけで、取り除かれることはありません。 すべての移動の後、カップ内の水の総量は、マグカップのすべての体積の合計と等しくなります。 

この合計がカップの容量を超える場合、最終状態自体が無効になるため、オーバーフローは避けられません。 

合計がカップ内に収まる場合、中間量は常に最終量以下であるため、すべての中間状態も適合します。 

この単調な動作のため、合計のチェックは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, s = map(int, input().split())
a = list(map(int, input().split()))

if sum(a) <= s:
    print("YES")
else:
    print("NO")
```プログラムは、アルゴリズムからの数学的観察に直接従います。 

最初の行にはマグカップの数とカップの容量が表示されます。 2 行目は、すべてのマグカップのボリュームをリストに読み込みます。 

肝心の操作は、`sum(a)`。 これにより、最終的にカップ内に入る水の総量が計算されます。 

比較には、`<=`、 ない`<`。 量が制限を厳密に超えた場合にのみカップがオーバーフローするため、正確な容量に達することが許可されます。 

順序によって結果を変えることができないことが証明されているため、順序に関する特別な処理は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | マグカップの体積を 1 回スキャンして、合計を計算します。 
| スペース | お(1) | 入力リスト以外に使用される変数はわずかです |

 最大 100 個のマグカップであれば、ソリューションは即座に実行されます。 時間とメモリ使用量の両方が制限をはるかに下回っています。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, s = map(int, input().split())
    a = list(map(int, input().split()))

    if sum(a) <= s:
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3 4\n1 1 1\n") == "YES\n", "sample 1"

# minimum valid input
assert run("2 1\n1 1\n") == "NO\n", "minimum size with overflow"

# exact boundary
assert run("2 7\n3 4\n") == "YES\n", "sum exactly equals capacity"

# all equal values
assert run("5 10\n2 2 2 2 2\n") == "YES\n", "all equal and fits exactly"

# overflow by one
assert run("4 9\n2 2 2 4\n") == "NO\n", "sum exceeds by one"

# large input within limits
assert run(
    "100 1000\n" + "10 " * 100 + "\n"
) == "YES\n", "maximum-sized input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 1 / 1 1`|`NO`| オーバーフローが避けられない最小入力サイズ |
 |`2 7 / 3 4`|`YES`| 容量との完全な同等性が許可されます。 
|`5 10 / 2 2 2 2 2`|`YES`| 均一な値と正確な適合 |
 |`4 9 / 2 2 2 4`|`NO`| 単体でのオーバーフロー |
 |`100 1000 / 10 repeated 100 times`|`YES`| 最大制約 |

 ## 特殊なケース

 総体積がカップの容量と正確に等しい場合を考えてみましょう。```
2 7
3 4
```アルゴリズムは計算します`3 + 4 = 7`。 以来`7 <= 7`、印刷されます`"YES"`。 

プロセスを追跡する:

 | 移動後 | カップの中の水 | 写真 カップの中の水
 | --- | --- |
 | 開始 | 0 |
 | 最初のマグカップの後 | 3 |
 | 2杯目以降 | 7 |

 カップが容量を超えることはありません。そのため、平等は安全なものとして扱われなければなりません。 

ここで、すべてのマグカップは小さいが、合計が大きすぎる場合を考えてみましょう。```
5 4
1 1 1 1 1
```アルゴリズムは計算します`1 + 1 + 1 + 1 + 1 = 5`。 以来`5 > 4`、印刷されます`"NO"`。 

プロセスを追跡する:

 | 移動後 | カップの中の水 | 写真 カップの中の水
 | --- | --- |
 | 開始 | 0 |
 | 最初のマグカップの後 | 1 |
 | 2杯目以降 | 2 |
 | 3杯目以降 | 3 |
 | マグカップ 4 個目以降 | 4 |
 | マグカップ5個目以降 | 5 |

 オーバーフローは最終手でのみ発生しますが、それでも避けられません。 

最後に、マグカップ 1 つがすでに容量に近づいている場合を考えてみましょう。```
3 5
4 1 1
```合計は`6`、アルゴリズムは次のように出力します`"NO"`すぐに。 

別の順序を試しても役に立ちません。 

| 注文 | ファイナルウォーター |
 | --- | --- |
 |`4,1,1`| 6 |
 |`1,4,1`| 6 |
 |`1,1,4`| 6 |

 最終的な金額は常に同じであるため、注文は無関係です。
