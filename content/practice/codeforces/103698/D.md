 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$。 グリッドの各セルは 0 または 1 です。グリッドは任意ではありません。グリッドは、各セルをその行と列のパリティ構造に結び付けるグローバルな一貫性ルールを満たさなければなりません。 

どのポジションでも$(i, j)$、行内のすべての値を取得する場合$i$それらを一緒に XOR し、列内のすべての値も取得します。$j$それらを一緒に XOR します。その後、これら 2 つの結果を XOR すると、セルに格納されている値が再現されます。$(i, j)$。 微妙な点の 1 つは、セル$(i, j)$は行と列の両方の XOR に含まれるため、事実上 2 回カウントされ、XOR 演算でそれ自体がキャンセルされます。 

タスクは、そのような行列を 1 つ構築することではなく、同じサイズの 2 値行列がいくつあるかを数えることです。$n \times m$多くのテストケースでこの条件を満たします。 答えはモジュロで計算する必要があります$998244353$。 両方$n$そして$m$非常に大きくなる可能性があり、最大で$10^{18}$したがって、行または列の反復に依存する解決策は直ちに不可能になります。 

制約サイズは、あらゆる問題を完全に排除します。$O(nm)$あるいは$O(n + m)$テストアプローチごとに。 唯一実行可能な戦略は、問題を閉じた形式の組み合わせ構造またはクエリごとの定数時間式に帰着させるものです。 

一般的な障害モードは、行と列が独立していると想定することです。 たとえば、各行を自由に選択したものとして扱い、列を調整すると、XOR 制約によってすべての行と列が同時に結合されるため、カウントが大幅にオーバーカウントされます。 次のいずれかの場合に、別の微妙なエッジケースが発生します。$n = 1$または$m = 1$。 その状況では、制約が縮退し、すべての行または列の選択がはるかに単純な状態に崩壊します。 

たとえば、次の場合$n = 1$の場合、各セルは行と列の両方の集約であるため、条件は自明になります。 不用意に解釈すると、一般的な公式を適用しようとして、過大にカウントしたり、過少にカウントしたりする可能性があります。 

もう 1 つの微妙なケースは、最小の非自明なグリッドです。$2 \times 2$。 強引な列挙を試みると独立性が疑われるかもしれませんが、実際には制約により 4 つのセルすべてにグローバル パリティ結合が課されるため、すべてのセルが一致するわけではありません。$2^4$設定は有効です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのバイナリ行列を試し、すべてのセルの XOR 条件を満たすかどうかを確認します。 各セルについて、その行 XOR と列 XOR を計算し、等しいことを検証します。 この条件は直接テストできるため、これが機能します。 ただし、コストはセルの数に応じて指数関数的に増加します。 たとえ$2 \times 2$、確認が必要です$16$行列、および$10 \times 10$、すでにそうなっています$2^{100}$、それは不可能です。 

重要な観察は、制約がフィールド上で線形であることです。$\mathbb{F}_2$。 XOR は加算法 2 のように動作するため、各条件は実際にはバイナリ変数に対する線形方程式系になります。 これが認識されると、問題は組み合わせ論から線形代数に移ります。 

細胞の観点から考えるのではなく、構造を再解釈します。 各行には関連付けられた XOR 値があり、各列には関連付けられた XOR 値があります。 の方程式は、$(i, j)$リンク行$i$、 カラム$j$、およびセル自体も対称的に配置されます。 グリッド全体に拡張すると、ほとんどの制約は独立しません。 システムは、少数の自由度のみが残る低次元空間に崩壊します。 

これを確認する便利な方法は、最初の行と最初の列の値をすべて固定することです。 これらが選択されると、他のすべてのセルが制約構造によって強制されます。 これは、行列全体がサイズの境界によって決定されることを意味します。$n + m - 1$しかし、その境界さえも完全に独立しているわけではありません。1 つのグローバル一貫性条件が境界を結び付けているからです。 

依存関係構造を処理した後、有効な行列の数は、自由変数の数に等しい指数を持つ 2 のべき乗に減ります。$(n - 1)(m - 1)$。 行と列の相互作用が解決されると、これらの位置はそれぞれ独立した選択に対応します。 

したがって、行列を列挙する代わりに、線形システムの独立した自由度を数えます。$\mathbb{F}_2$。

 ## アルゴリズムのチュートリアル

 1. 各セル制約が XOR 上の線形方程式であるため、システム全体を 2 値線形システムとして扱うことができることに注目してください。 この再定式化は、明示的な構成ではなくランクと自由度の観点から推論できるため、非常に重要です。 
2. 行と列の XOR 制約が独立していないことを確認します。 すべての行方程式とすべての列方程式を合計すると、冗長なグローバル制約が生成されます。 この冗長性により、独立した方程式の有効な数が減少します。 
3. 最初の行と最初の列の交点を除くすべてのセルを固定して、解空間の基準を選択します。 これらの境界値が固定されると、XOR 制約を伝播することによってすべての内部セルが一意に決定されます。 
4. 冗長性を考慮した上で、真に自由な変数の数を数えます。 システムは正確に出発します$(n - 1)(m - 1)$独立した選択肢であり、それぞれが合計数の 2 倍に寄与します。 
5. 結果をモジュール形式に変換し、計算します。$2^{(n-1)(m-1)} \bmod 998244353$指数は次のように大きくできるため、高速累乗を使用します。$10^{18}$。 
6. 各テスト ケースに対してこの値を個別に返します。 

### なぜ効果があるのか

 XOR 制約により、一貫した線形システムが形成されます。$\mathbb{F}_2$。 任意の有効な行列はこの系の解に対応し、任意の解は行列を一意に決定します。 システムのランクによって、真に独立した制約の数が決まります。 行と列の対称性から生じる依存方程式を除去した後、解空間は次元を持ちます。$(n-1)(m-1)$したがって、これらの自由変数を代入するたびに、有効な行列が 1 つだけ生成され、有効な行列が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e > 0:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    exp = (n - 1) * (m - 1)
    print(modpow(2, exp))
```この実装では、テスト ケースごとにすべてが 1 つのべき乗に削減されます。 唯一自明ではない部分は、指数が次のようになっているということを認識することです。$(n-1)(m-1)$これは、XOR 制約のあるグリッド内の独立した自由度を数えることから得られます。 

べき乗モジュラーが必要なのは、指数とその結果の数値の両方が直接計算するには大きすぎるためです。 2 進累乗ループにより、指数の対数時間が確保されます。 

よくある実装上の間違いは、指数を 64 ビット算術で計算する必要があることを忘れることです。 以来$n$そして$m$まで可能です$10^{18}$、その積は、リダクションモジュロの前にオーバーフローを回避する型で保存する必要があります。$MOD-1$は直接べき乗であるため、ここでは無関係であると考えられます。 

## 実用的な例

 小さなケースを考えてみましょう$n = 2, m = 2$。 指数は$(2-1)(2-1) = 1$、したがって、答えは次のとおりです$2$。 これは、正確に 2 つの行列が制約を満たすことを意味します。 列挙すると、1 つのセルが自由に選択されると、他のすべてのセルが強制的に選択されることがわかります。 

| ステップ | 解釈 |
 | --- | --- |
 | 指数を計算する |$(2-1)(2-1) = 1$|
 | 結果 |$2^1 = 2$|

 これは、システムが完全に自由ではないが、それでも 1 つの 2 進自由度を許可していることを示しています。 

ここで考えてみましょう$n = 3, m = 3$。 指数は次のようになります。$(3-1)(3-1) = 4$、あります。$2^4 = 16$有効な行列。 

| ステップ | 解釈 |
 | --- | --- |
 | 指数を計算する |$(3-1)(3-1) = 4$|
 | 結果 |$2^4 = 16$|

 このケースは、有効な構成の数がセルの総数ではなく内部自由度に応じて指数関数的に増加する様子を示しています。

import sys, io

MOD = 998244353

def modpow(a, e):
    res = 1
    while e > 0:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(modpow(2, (n - 1) * (m - 1))))
    return "\n".join(out)

 ## 特殊なケース

 いつ$n = 1$を選択すると、グリッドが単一の行に折りたたまれます。 すべてのセルは同時にその行と列の一部であるため、XOR 制約により、相互依存性なしに各セルが強制的に等しくなります。 指数公式は次のようになります。$(1-1)(m-1) = 0$これは、一貫性が適用されるとすべての割り当てが一意に決定されるという事実と一致する、有効な構成を 1 つだけ生成します。 

いつ$m = 1$、状況は対称的です。 システムは再び崩壊し、内部の自由は失われます。 指数はゼロになり、結果は次のようになります。$1$、単一の一貫した構成に対応します。 

最小の非自明な正方形の場合$2 \times 2$、制約は 4 つのセルすべてを結合します。 1 つのセルを独立して変更しようとすると、XOR 条件により残りの 3 つが即座に強制されます。 これは指数に反映されます$1$つまり、制約が適用された後も、自由な二者択一が 1 つだけ残ることになります。
