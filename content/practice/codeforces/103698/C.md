 ## 解決策
 ## 問題の理解

 私たちは一連の銀行口座を与えられており、それぞれにある程度の金額が保管されています。 課題は、通常の意味でサブセット全体を最適化することではなく、ソートされた母集団とその補数の接頭語に人々をグループ化したときに、分布がどのように「不均一」になるかを理解することです。 

形式的には、人々を富によって分類し、人口を 2 つのグループに分けるしきい値を選択することを想像してください。 このような分割については、最初のグループに属する人々の割合と、彼らが集合的に保有する総資産の割合という 2 つのパーセンテージを計算します。 これにより、値 A と B のペアが得られます。考えられるすべての分割の中で、B − A を最大化するペアが必要です。複数の分割が同じ最大値に達する場合、A が大きい方が優先されます。 

入力により、口座の数とその残高が得られます。 出力は、単一の最適なパーセンテージのペアです。 

この制約により、最大 100,000 のアカウントが許可されるため、単純な二次方程式で考えられる分割ごとに合計を繰り返し再計算するアプローチは即座に除外されます。 どのソリューションでもデータを前処理し、定数時間または対数時間で分割候補を評価する必要があります。 

すべてのバランスが同一の場合、微妙なエッジケースが現れます。 その状況では、すべての分割で A に等しい B が生成されるため、目的の B − A は常に 0 になります。 次に、タイブレーク ルールにより、最大 A を持つ分割を選択することが強制されます。これは、すべての要素を取得することに相当します。 たとえば、入力の場合`10 10`、両方の人々は同一であり、すべての分割は富の割合において同等であり、正解は次のようになります。`100.00 100.00`。 

もう 1 つの厄介な状況は、繰り返される値が多数あるものの、すべてが等しいわけではない場合に発生します。 一意性を仮定し、局所的な密度変化を貪欲にカットする単純なアプローチは失敗する可能性があります。最適な分割は、個々の位置や任意のグループ化ではなく、ソート後のプレフィックスの合計にのみ依存するためです。 

## アプローチ

 この強引なアイデアは簡単です。人々のサブセットを選択するあらゆる可能な方法を試し、彼らが集合的にどれだけの富を所有しているかを計算し、彼らが総人口の何パーセントを占めるかを計算し、B − A を評価します。これは概念的には正しいですが、完全に実行不可能です。 n が 100000 までの場合、サブセットの数は 2^n であり、プレフィックスのような構造に制限しても O(n) 個の候補が残り、前処理しない限りそれぞれの候補で合計の再計算が必要になります。 

ソートされた接頭辞のみを考慮するように制限したとしても、富の接頭辞の合計を計算し、各分割を評価する必要があります。 これにより問題は大幅に軽減されますが、主な洞察は、特定の人口割合に対する富のシェアを最大化するには常により高い値を最初に取得することが優先されるため、答えはソートされた配列のいくつかの接尾辞 (最大の要素) の選択に対応している必要があるということです。 

配列が降順にソートされると、富のプレフィックス合計が維持されます。 上位 k 個のアカウントを取得することを表す各 k について、A = k / n および B = sum(top k) / 合計を計算します。 目的は、すべての k にわたって B − A を最大化することになります。 

これにより、ソート後の問題が単純な線形スキャンに変換されます。 重要な構造特性は、ソートによって引き起こされる単調性です。最適なサブセットは、富のシェアを減らすことなく、カウントを変更せずに最大の要素を取得するように再配置できます。

 ## アルゴリズムのチュートリアル

 1. すべての口座残高を読み取り、資産総額を計算します。 この合計は、今後のすべてのパーセンテージ計算を正規化するために必要になります。 
2. プレフィックスの選択が常にそのサイズに対して最も豊富なグループを表すように、残高を降順に並べ替えます。 これにより、私たちが考慮する k 人のグループが、そのサイズで可能な限り最良のグループであることが保証されます。 
3. ソートされた配列に対してプレフィックスの合計を作成します。 各接頭辞の合計は、上位 k 人の資産の合計を表します。 
4. 1 から n までのすべての k を繰り返します。 各 k について、A を 100 × k / n として計算し、B を 100 × prefix_sum[k] / total_sum として計算します。 
5. B − A の最大値を追跡します。複数の k 値が同じ差を生成する場合、より大きな A に対応するため、より大きな k を持つ値が優先されます。 
6. 小数点以下第 2 位を四捨五入して最適な (A, B) ペアを出力します。 

プレフィックスのみをテストする必要がある理由は、任意の固定 k に対して、最も裕福な上位 k 人以外のグループを選択しても総資産を増やすことができないためです。 B は選択されたセットの総富のみに依存するため、任意の要素をより大きな要素に置き換えることで、A を固定したまま B を厳密に改善または維持します。 

### なぜ効果があるのか

 重要な不変条件は、降順で並べ替えた後、固定カーディナリティ k に対して可能な限り最高の資産が常に最初の k 要素を取得することによって達成されるということです。 これにより、検索スペースがすべてのサブセットからネストされたプレフィックスの単一チェーンに縮小されます。 A は k のみに依存し、B はプレフィックスの合計によって最大化されるため、すべてのサブセットに対する最適化は、k のみに対する最適化に崩壊します。 目的 B − A は k にわたる 1 次元関数となり、すべての k をスキャンすることで大域最適が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    a.sort(reverse=True)
    
    pref = 0
    
    best_diff = -10**18
    best_a = 0.0
    best_b = 0.0
    
    for i in range(n):
        pref += a[i]
        k = i + 1
        
        A = 100.0 * k / n
        B = 100.0 * pref / total
        
        diff = B - A
        
        if diff > best_diff or (abs(diff - best_diff) < 1e-12 and A > best_a):
            best_diff = diff
            best_a = A
            best_b = B
    
    print(f"{best_a:.2f} {best_b:.2f}")

if __name__ == "__main__":
    solve()
```この実装は、プレフィックス スキャンのアイデアに直接準拠しています。 降順に並べ替えることで、すべてのプレフィックスがそのサイズに最適であることが保証されます。 プレフィックスの合計は富を効率的に蓄積するため、各候補分割は一定時間で評価されます。 浮動小数点フォーマットは出力時にのみ処理されますが、すべての比較では等価性の許容誤差が小さい生の計算値が使用されます。 

よくある間違いは、タイブレークのルールを忘れることです。 このコードは差の等価性を明示的にチェックし、より大きい A を優先します。

 ## 特殊なケース

 すべての値が等しい場合、すべてのプレフィックスは同一の B − A を生成するため、アルゴリズムは完全にタイブレーク ルールに依存する必要があります。 並べ替えは依然として正しく機能しますが、最終的な答えは k = 1 ではなく k = n を選択する必要があります。差が等しい場合に A を明示的に比較するため、実装はこれを処理します。 

1 つの値が残りの値を支配する場合、最適な k は小さい可能性があり、多くの場合 k = 1 または 2 になります。初期のプレフィックスは、より小さな値から希釈される前に大きな B − A を生成するため、プレフィックス スキャンはこれを正確に捕捉します。 

値が大きく偏っているものの、厳密には減少していない場合、並べ替えにより、局所的な不規則性が選択プロセスを誤解させないようにすることができます。 後でソートせずに高い値を取得すると、考えられるプレフィックスの合計が過小評価され、最適な分割が失敗するため、ソートされていない貪欲なアプローチはここでは失敗します。
