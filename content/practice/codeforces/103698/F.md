 ## 解決策
 ## 問題の理解

 このタスクは、無向グラフ上の古典的な線形代数の計数問題として理解できます。 スパニング ツリーについて直接組み合わせて推論するのではなく、その構造から構築された行列を通じてグラフを再解釈し、答えをエンコードする行列式を計算します。 

具体的には、入力は次のような単純な無向グラフを記述します。$n$頂点とエッジのセット。 目標は、このグラフに存在するスパニング ツリーの数を計算することです。 スパニング ツリーは、サイクルを含まずにすべての頂点を接続し、正確に使用するエッジのサブセットです。$n-1$エッジ。 

出力は、このカウントを表す単一の整数です。 一般的な競技プログラミング設定では、この値は大きな素数を法として取得されますが、基礎となる数学は整数に対しても機能します。 

複雑さの観点から見ると、重要な制約は、スパニング ツリーやエッジのサブセットの列挙が不可能になるほどグラフが大きくなる可能性があることです。 適度なサイズのグラフでもスパニング ツリーの数が指数関数的に増加するため、許容可能な解決策は問題を多項式時間線形代数に帰着させる必要があります。 唯一の実行可能なパスは、$n \times n$マトリックスはすぐに示唆します$O(n^\omega)$または$O(n^3)$-type メソッド。 

実際には、いくつかの特殊なケースが重要です。 単一の頂点を持つグラフには、エッジがない場合でも、常に 1 つのスパニング ツリーが存在します。 エッジを追加せずにすべての頂点を接続することは不可能であるため、切断されたグラフにはゼロスパニング ツリーが含まれます。 同じ頂点ペア間に複数のエッジがあるグラフでは、各エッジがラプラシアンに個別に寄与するため、自明ではない方法でスパニング ツリーの数が増加します。 この場合、エッジの重複を排除する不注意な実装では、誤った結果が暗黙的に生成されます。 

もう 1 つの微妙なケースは、グラフがすでにツリーになっている場合です。 その状況では、答えは正確に 1 つであり、行列式ベースの実装は、モジュラー演算またはランダム化の下で動作するにもかかわらず、整性を維持する必要があります。 

## アプローチ

 ブルート フォースの観点は、スパニング ツリーの定義から始まります。 すべてのサブセットを列挙しようとすることもできます。$n-1$エッジを検出し、各サブセットが有効なツリーを形成しているかどうかをテストします。 接続性は Union-find または DFS でチェックでき、サブセットが正確に一致する場合には非循環性が自動的に続きます。$n-1$エッジと接続されています。 このアプローチは正しいですが、エッジ サブセットの数は次のように増加します。$\binom{m}{n-1}$、これは小さなグラフでも実行不可能になります。 ボトルネックは検証ステップではなく、候補者の多さです。 

より構造化されたアプローチでは、基本的な変換を使用します。つまり、組み合わせオブジェクトを直接カウントする代わりに、それらを行列式の代数項としてエンコードします。 グラフのラプラシアン行列は、対角線上の頂点次数と対角外の隣接構造を捕捉します。 キルヒホッフの行列木定理では、このラプラシアンの余因子はスパニング ツリーの数に等しいと述べています。 これは、問題を単一の行列式の計算に変換します。$(n-1) \times (n-1)$マトリックス。 

これが役立つ理由は、行列式の計算により効率的な代数アルゴリズムが可能になるためです。 ガウス消去法またはより高度な行列乗算技術により、指数カウントから多項式演算までの複雑さが軽減されます。 組み合わせ爆発は行列式展開内のキャンセルに吸収されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(n + m) | 遅すぎる |
 | 行列木 (行列式) | O(n³) または O(n^ω) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは、ラプラシアン行列の構築とその余因子の 1 つを計算することを中心に構築されています。 

1. を構築します。$n \times n$マトリックス$L$、最初はゼロで埋められます。 この行列はグラフ構造を代数形式で表します。 
2. あらゆるエッジに対して$u - v$、 増加$L[u][u]$そして$L[v][v]$1 つずつ減らし、両方を減らします$L[u][v]$そして$L[v][u]$1つずつ。 これにより、頂点の次数と隣接性が同時にエンコードされます。 各エッジは、対称性を維持する構造化された更新に貢献します。 
3. 任意の 1 つの行と列 (通常は最後の頂点) を削除し、$(n-1) \times (n-1)$マトリックス。 このステップが必要なのは、完全なラプラシアンは行の合計がゼロであるため常に行列式がゼロですが、余因子にはスパニング ツリーの数が含まれるためです。 
4. 必要な係数の下でガウス消去法を使用するか、分数を含まない消去法で整数を超えて、結果の行列の行列式を計算します。 行列式は、行列内にエンコードされたすべてのスパニング ツリーの寄与を集約します。 
5. 行列式を最終的な答えとして出力します。 

重要な非明白な手順は、行と列を削除しても情報が失われない理由です。 ラプラシアンにはランクがある$n-1$接続されたグラフの場合、すべての余因子は等しい。 これにより、問題をフルランクの行列式の計算に縮小することができます。 

### なぜ効果があるのか

 各スパニング ツリーは、ラプラシアンを変換した後の行列式の展開における 1 つの項に正確に対応します。 行列式の代数的キャンセルにより、循環を含むすべての構造が除去され、非循環的に接続されたエッジ選択のみが残ります。 残りの生き残った項はスパニング ツリーと 1 対 1 に対応しており、行列式がその数に等しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def det_mod(mat, mod):
    n = len(mat)
    det = 1
    sign = 1

    for i in range(n):
        pivot = i
        for j in range(i, n):
            if mat[j][i] != 0:
                pivot = j
                break
        if mat[pivot][i] == 0:
            return 0

        if pivot != i:
            mat[i], mat[pivot] = mat[pivot], mat[i]
            sign *= -1

        inv = pow(mat[i][i], mod - 2, mod)
        det = det * mat[i][i] % mod

        for j in range(i + 1, n):
            factor = mat[j][i] * inv % mod
            for k in range(i, n):
                mat[j][k] = (mat[j][k] - factor * mat[i][k]) % mod

    return det * sign % mod

n, m = map(int, input().split())
mod = 10**9 + 7

L = [[0] * n for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    L[u][u] += 1
    L[v][v] += 1
    L[u][v] -= 1
    L[v][u] -= 1

for i in range(n):
    for j in range(n):
        L[i][j] %= mod

mat = [row[:-1] for row in L[:-1]]

print(det_mod(mat, mod))
```この実装では、まずエッジの寄与から直接ラプラシアンを構築します。 最後の行と列の削除はスライスによって行われ、接続性の仮定の下で行列を正方形およびフルランクに保ちます。 

行列式ルーチンは、素数を法とするガウス消去法を使用します。 ピボットの選択により、可能な限りゼロ ピボットを回避することで、モジュラー演算における数値の安定性が確保されます。 行操作はインプレースで実行され、行列式はピボット スケーリングを通じて累積されます。 符号追跡は行の交換を処理します。これは、各交換によって決定的な符号が反転されるため、不可欠です。 

微妙な点は、モジュラー反転では法が素数であると仮定していることです。 これは競技プログラミングの標準です。$10^9 + 7$または同様の素数が使用されます。 

## 実用的な例

 3 つの頂点と 3 つの辺を持つ三角グラフを考えてみましょう。 

ラプラシアンは、$$\begin{bmatrix}
2 & -1 & -1 \\
-1 & 2 & -1 \\
-1 & -1 & 2
\end{bmatrix}$$最後の行と列を削除すると、$$\begin{bmatrix}
2 & -1 \\
-1 & 2
\end{bmatrix}$$行列式の計算は次のように行われます。 

| ステップ | マトリックスの状態 | 操作 |
 | --- | --- | --- |
 | 1 | [[2, -1], [-1, 2]] | イニシャル |
 | 2 | [[2, -1], [0, 3]] | 2 行目を削除 |
 | 3 | 6 | ピボットの積 |

 結果の 3 は、三角形内のスパニング ツリーの既知の数と一致します。 

ここで、3 つの頂点が一列に並んだ木について考えてみましょう。 ラプラシアン余因子は、行列式が 1 と評価される行列になります。これにより、ツリーが 1 つのスパニング ツリーに正確に寄与することが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    n, m = map(int, sys.stdin.readline().split())
    mod = 10**9 + 7

    L = [[0]*n for _ in range(n)]
    for _ in range(m):
        u, v = map(int, sys.stdin.readline().split())
        u -= 1
        v -= 1
        L[u][u] += 1
        L[v][v] += 1
        L[u][v] -= 1
        L[v][u] -= 1

    mat = [row[:-1] for row in L[:-1]]

    def det(a):
        n = len(a)
        detv = 1
        sign = 1
        for i in range(n):
            p = i
            for j in range(i, n):
                if a[j][i]:
                    p = j
                    break
            if a[p][i] == 0:
                return 0
            if p != i:
                a[i], a[p] = a[p], a[i]
                sign *= -1
            inv = pow(a[i][i], mod-2, mod)
            detv = detv * a[i][i] % mod
            for j in range(i+1, n):
                f = a[j][i] * inv % mod
                for k in range(i, n):
                    a[j][k] = (a[j][k] - f*a[i][k]) % mod
        return detv * sign % mod

    return str(det(mat))

 ## 特殊なケース

 ラプラシアン余因子が特異になるため、切断されたグラフは正しく処理されます。 消去中に、最終的にゼロ ピボットが表示され、行列式が強制的にゼロになります。これは、スパニング ツリーがないことを正確に反映します。 

単一の頂点グラフは、行と列を削除すると空の行列になります。 慣例により、0×0 行列の行列式は 1 であり、スパニング ツリーが 1 つだけ存在するという事実と一致します。 

ツリー入力は、消去後のラプラシアン補因子に三角形構造をもたらします。 各ピボットは正確に 1 つのエッジ制約に対応し、取り消されることなく決定的な制約を生成し、最小接続ケースでの正しさを確認します。
