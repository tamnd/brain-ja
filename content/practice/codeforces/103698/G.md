 ## 解決策
 ## 問題の理解

 私たちは与えられています$n$多項式。それぞれの係数は次数の増加順に記述されます。 それではお答えします$q$クエリ。各クエリは間隔を指定します。$[l, r]$。 各区間について、概念的にはその中のすべての多項式を乗算し、結果の多項式にミラー係数があるかどうかを確認します。 

直接読むと、多くの範囲にわたる多項式乗算を扱っていることがわかりますが、次数が増加し、係数が大きくなる可能性があるため、通常はコストが高くなります。 ただし、ステートメントで指定された特別な代数的性質により、問題の性質全体が変わります。重要なのは、各多項式が個別に回文であるかどうかだけです。 

したがって、実際の隠れたタスクは、どの多項式が対称であるかを前処理し、範囲クエリに答えて区間内のすべてのエントリが対称であるかどうかを確認することです。 

制約は以下を意味します$10^5$多項式と$10^5$クエリ、次数の合計は次のとおりです$5 \cdot 10^5$。 クエリごとに対称性を再計算したり、乗算をシミュレートしたりするアプローチは不可能です。 最悪の場合、クエリごとに多項式をチェックするだけでも遅すぎるため、線形時間で事前計算し、定数時間または対数時間でクエリに答える必要があります。 

微妙なエッジ ケースは、多項式の次数が 0 である場合です。 このような多項式は、係数が 1 つしかないため、定義上常に回文です。 

もう 1 つの重要なエッジ ケースは、対称性は宣言されたサイズではなく、実際の程度を尊重する必要があることです。 たとえば、先頭の係数がゼロ以外であっても内部構造が対称であれば、それは有効です。 しかし、後続の係数が対称性を破る場合は、そうではありません。 

単純な間違いを考えてみましょう。多項式が次のように表されると仮定します。$[1, 2, 1, 0]$。 宣言された次数を誤って 3 として扱い、トリミングせずに後続のゼロを含むすべての位置を比較すると、誤って分類される可能性があります。 正しい解釈は、次数は入力によって固定されるということです。$k_i$、したがって、その後の末尾のゼロ$k_i$存在しません。 

## アプローチ

 ブルートフォース解釈では、区間内の多項式を乗算して各クエリを直接シミュレートし、結果の対称性をチェックします。 2 つの次数の多項式を乗算すると、$K$、畳み込みコスト$O(K^2)$。 これを一定の長さのセグメントにわたって繰り返す$n$中間次数が増加し、各クエリが大規模な畳み込みを再計算するため、実際には最悪の場合の入力に対して効果的に指数関数的になります。 高速な乗算であっても、これを実行すると、$10^5$クエリは実行不可能です。 

このステートメントから得られる重要な観察により、問題は完全に変わります。つまり、範囲内のすべての多項式が回文である場合に限り、積は回文になります。 これにより、複雑な代数条件がバイナリ配列に対する単純な論理 AND に分解されます。 

各多項式がブール値に変換されると、問題は古典的な範囲クエリになります。つまり、次のすべての値が一致するかどうかを確認します。$[l, r]$本当です。 これは、範囲内の最小値が 1 であるかどうか、または範囲内に 0 が存在するかどうかを確認することと同じです。 プレフィックスサムまたはセグメントツリーで十分です。 

配列を事前計算します$a[i]$どこ$a[i] = 1$多項式の場合$i$は回文であり、それ以外の場合は 0 です。次に、プレフィックスの合計を作成し、範囲の合計によってセグメント内に非回文多項式があるかどうかがわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルートフォース多項式乗算 |$O(q \cdot n \cdot K^2)$|$O(K)$| 遅すぎる |
 | 回文性 + 接頭辞の合計を事前計算する |$O(nK + q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各多項式を読み取り、両端から対称に係数を比較することで回文であるかどうかを確認します。 このステップでは定義を直接エンコードし、代数的操作を回避します。 
2. 多項式ごとに、以下を繰り返します。$j = 0$に$k_i$そして比較してください$a_j$と$a_{k_i - j}$。 不一致が見つかった場合は、多項式を非回文としてマークします。 
3. 結果を配列に格納する`good[i]`ここで、1 は回文であることを示し、0 は回文でないことを示します。 
4. プレフィックス合計配列を構築する`pref`、 どこ`pref[i] = pref[i-1] + good[i]`。 これにより、高速な範囲集約が可能になります。 
5. 各クエリについて$[l, r]$、計算する`pref[r] - pref[l-1]`。 結果が等しい場合$r-l+1$、すべての多項式は回文的ですが、それ以外の場合、少なくとも 1 つはそうではありません。 

ここでプレフィックス合計が機能する理由は、問題をセグメントに無効な要素が含まれているかどうかをチェックすることに変換したためです。 プレフィックスの合計は、カウントによって存在を検出する直接的な方法です。 

### なぜ効果があるのか

 乗法構造は、回文性が乗算時に保持され、単一の非回文因子によって破壊されることを保証します。 これにより、単調な特性が生まれます。製品に「不良」要素が現れると、他の多項式を掛け合わせても修復できなくなります。 したがって、すべての因数が回文的である場合に限り、範囲にわたる積は回文的になります。これにより、問題はバイナリ配列の範囲均一性チェックに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_pal(coef):
    i, j = 0, len(coef) - 1
    while i < j:
        if coef[i] != coef[j]:
            return False
        i += 1
        j -= 1
    return True

n, q = map(int, input().split())
good = [0] * (n + 1)

for i in range(1, n + 1):
    arr = list(map(int, input().split()))
    k = arr[0]
    coef = arr[1:]
    good[i] = 1 if is_pal(coef) else 0

pref = [0] * (n + 1)
for i in range(1, n + 1):
    pref[i] = pref[i - 1] + good[i]

out = []
for _ in range(q):
    l, r = map(int, input().split())
    total = pref[r] - pref[l - 1]
    out.append("1" if total == (r - l + 1) else "0")

print("\n".join(out))
```実装の中心的な選択は、対称性チェックをクエリ処理から分離することです。 多項式解析では、宣言された次数が読み取られ、畳み込みや正規化の必要性は無視されます。 範囲の減算を簡略化し、1 つずつの間違いを避けるために、プレフィックス配列には 1 のインデックスが付いています。 

ここでよくあるバグは、各多項式行の最初の数値が係数ではなく次数であることを忘れていることです。 もう 1 つは、クエリが 1 ベースであるにもかかわらず、プレフィックス合計に誤って 0 ベースのインデックスを使用することです。これにより、すべての回答が誤ってシフトされてしまいます。 

## 実用的な例

 3 つの多項式の小さなシーケンスを考えてみましょう。 

入力:```
3 2
2 1 2 1
1 3 4
2 5 0 5
1 3
2 3
```回文性チェックでは以下が生成されます。 

| 私 | 多項式 | チェック結果 | 良い[i] |
 | --- | --- | --- | --- |
 | 1 | 1 2 1 | 対称 | 1 |
 | 2 | 3 4 | 対称ではない | 0 |
 | 3 | 5 0 5 | 対称 | 1 |

 プレフィックスの合計は次のようになります`[0,1,1,2]`。 

クエリ$[1,3]$与える`pref[3] - pref[0] = 2`ですが、範囲サイズは 3 であるため、出力は 0 になります。これは、単一の非回文多項式でも積が壊れることを示しています。 

クエリ$[2,3]$与える`pref[3] - pref[1] = 1`、範囲サイズは 2 なので、出力は再び 0 になります。 これにより、不正な要素を含むセグメントが失敗することが確認されます。 

次に、完全に対称なセットを考えてみましょう。```
2 1
2 2 3 2
1 5 5
1 2
```どちらの多項式も回文であるため、接頭辞の合計は次のようになります。`[0,1,2]`。 範囲全体がクリーンであるため、クエリは 1 を返します。これは、単調な保存特性を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(nK + q)$| 各係数は対称性をチェックするために 1 回スキャンされ、各クエリは接頭辞の合計 | を使用して O(1) で応答されます。 
| スペース |$O(n)$| 回文配列とプレフィックス合計のストレージ |

 総次数合計制約により、係数スキャン ステップがすべての入力サイズにわたって線形になることが保証されます。 と$n, q \le 10^5$、これは Python の制限内に簡単に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def is_pal(coef):
        i, j = 0, len(coef) - 1
        while i < j:
            if coef[i] != coef[j]:
                return False
            i += 1
            j -= 1
        return True

    n, q = map(int, input().split())
    good = [0] * (n + 1)

    for i in range(1, n + 1):
        arr = list(map(int, input().split()))
        k = arr[0]
        coef = arr[1:]
        good[i] = 1 if is_pal(coef) else 0

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + good[i]

    res = []
    for _ in range(q):
        l, r = map(int, input().split())
        res.append("1" if pref[r] - pref[l - 1] == (r - l + 1) else "0")

    return "\n".join(res)

 ## 特殊なケース

 重要なエッジケースは定数多項式です。 たとえば、入力`0 7`は次数 0 の多項式を表します。アルゴリズムはそれを単一要素の配列として扱います。`is_pal`すぐに true を返し、定義に一致します。 

もう 1 つのエッジ ケースは、非対称性を視覚的に示唆する可能性のある表現に末尾のゼロを持つ多項式です。 例えば、`3 1 0 1`実際には対称的で有効です。 このチェックでは正確な位置が比較されるため、対称性が正しく識別されます。 

3 番目のエッジ ケースは、単一の多項式クエリです。 いつでも$l = r$の場合、答えはその多項式が回文であるかどうかによってのみ決まります。 プレフィックス合計の式は、1 つの要素間隔をチェックするだけなので、これは自然に処理されます。
