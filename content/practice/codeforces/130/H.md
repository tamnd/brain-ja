 ## 解決策
 ## 問題の理解

 一連の丸括弧のバランスが取れているかどうかを判断するように求められます。 バランスの取れたシーケンスとは、すべての左括弧 «(» に対応する閉じ括弧 «)» があり、括弧が適切にネストされているシーケンスです。 言い換えれば、文字列を左から右にトラバースする場合、どの時点でも閉じ括弧の数が開き括弧の数よりも多くなってはならず、最後には開き括弧と閉じ括弧の数が正確に一致する必要があります。 

入力は、«(» と «)» のみで構成される 1 ～ 100 文字の長さの単一の文字列です。 出力は、シーケンスがバランスが取れているかどうかに応じて、単純な「はい/いいえ」の答えになります。 

この制約は、高度に最適化されたアルゴリズムが必要ないことを意味します。 n ≤ 100 であるため、O(n²) アプローチでも 2 秒の制限内で実行される可能性があります。それでも、きれいにスケーリングされ、不必要な計算が回避されるため、線形アプローチの方が望ましいと考えられます。 

エッジ ケースは、シーケンスが閉じ括弧で始まるか、開始括弧で終わる場合に発生します。 たとえば、«)(» は、最初の文字が一致しないためアンバランスです。もう 1 つの微妙なケースは、完全にネストされている «((()))» のようなシーケンスですが、括弧の深さを注意深く追跡する必要があります。単一文字シーケンス «(» または «)» は、対応する文字が存在しないためアンバランスです。

 ## アプローチ

 ブルートフォース手法では、要素を追加することで考えられるすべての有効な式の生成をシミュレートしますが、これは不要です。 より単純な素朴なアプローチでは、文字列のすべてのプレフィックスをチェックして、左括弧よりも多くの閉じ括弧が含まれているかどうかを確認します。 そうなった場合、シーケンスは直ちにアンバランスになります。 最後に、開き括弧と閉じ括弧の合計数が一致していることを確認します。 これは正しいですが、明示的なプレフィックス配列を使用しなくても効率的に実装できます。 

最適なアプローチは、実行中のカウンターを活用します。 カウンタをゼロに初期化します。 文字列を左から右にトラバースします。 開始括弧に遭遇したら、カウンターをインクリメントします。 閉じ括弧が見つかった場合は、カウンターをデクリメントします。 どこかの時点でカウンタが負になった場合、それは開き括弧よりも閉じ括弧が多く、シーケンスのバランスが崩れていることを示します。 文字列全体を処理した後、カウンターが 0 になると、シーケンスのバランスが取れていることが確認されます。 他の値は括弧が一致しないことを示します。 洞察としては、適切なネストによってカウンターが決してゼロを下回らないことが保証され、最後の平等性により、すべての開始括弧が対応する終了括弧を持つことが保証されます。

 | ブルート フォース (プレフィックス チェック) | O(n) | O(n) | 承認済み |
 | 最適（カウンター） | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタ変数を初期化する`balance`このカウンタは、一致しない左括弧の正味数を追跡します。 
2. 文字列の各文字を順番に調べます。 
3. 文字が左括弧«(»の場合、インクリメントします`balance`1までに。 
4. 文字が閉じ括弧«)»の場合、デクリメントします。`balance`1までに。 
5. デクリメント直後に、`balance`はマイナスです。 そうであれば、«NO»を出力して停止します。 マイナスの残高は、右括弧が一致していないことを示します。 
6. トラバースが完了したら、次のことを確認します。`balance`ゼロに等しい。 存在する場合は、すべての左括弧に一致する閉じ括弧があるため、«YES» を出力します。 そうでない場合は、一致しない左括弧があるため、«NO» を出力します。 

それが機能する理由: 不変条件は、すべてのステップで、`balance`現在一致しない左括弧の数を表します。 負のバランスは、閉じ括弧に対応する開始括弧がなく、バランスの取れた条件に違反していることを示します。 で終わる`balance`ゼロを指定すると、すべての左括弧がペアになることが保証されます。 このアプローチは、バランスの取れたブラケット シーケンスの論理定義を直接反映しており、必要なネスト プロパティを明示的に追跡するため、誤った出力を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
balance = 0
for ch in s:
    if ch == '(':
        balance += 1
    else:  # ch == ')'
        balance -= 1
    if balance < 0:
        print("NO")
        sys.exit(0)
print("YES" if balance == 0 else "NO")
```コードは入力文字列を読み取り、末尾の改行を削除します。 私たちは、`balance`一致しない左括弧を追跡するための変数。 各開始括弧はバランスを増加させ、各終了括弧はバランスを減少させます。 負の残高を即座にチェックすることで、一致しない閉じ括弧で始まるシーケンスを早期に終了することが保証されます。 最後に、ゼロバランスのチェックにより、すべての開口部が一致していることが確認されます。 この実装により、off-by-one エラーが回避され、長さ 1 のシーケンスが正しく処理されます。 

## 実用的な例

 サンプル 1: «(()(()))()»

 | キャラクター | バランス | アクション |
 | --- | --- | --- |
 | ( | 1 | 増分 |
 | ( | 2 | 増分 |
 | ) | 1 | デクリメント |
 | ( | 2 | 増分 |
 | ( | 3 | 増分 |
 | ) | 2 | デクリメント |
 | ) | 1 | デクリメント |
 | ) | 0 | デクリメント |
 | ( | 1 | 増分 |
 | ) | 0 | デクリメント |

 どの時点でも残高がマイナスになることはなく、ゼロで終了するため、出力は«YES»になります。 これにより、ネストとマッチングが正しいことが確認されます。 

サンプル 2: «)(»

 | キャラクター | バランス | アクション |
 | --- | --- | --- |
 | ) | -1 | デクリメントとマイナス残高の検出 |

 最初の文字が一致しないため、すぐに«NO»を出力します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    balance = 0
    for ch in s:
        if ch == '(':
            balance += 1
        else:
            balance -= 1
        if balance < 0:
            return "NO"
    return "YES" if balance == 0 else "NO"

# Provided samples
assert run("(()(()))()\n") == "YES", "sample 1"

# Custom cases
assert run(")\n") == "NO", "single unmatched closing"
assert run("(\n") == "NO", "single unmatched opening"
assert run("()()()()()\n") == "YES", "repeated balanced pairs"
assert run("((())())(()())\n") == "YES", "nested balanced"
assert run("((())\n") == "NO", "missing closing"
assert run("())((\n") == "NO", "negative balance mid-sequence"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | ) | いいえ | 単一の一致しない閉じ括弧が早期終了をトリガーします。 
| ( | いいえ | 単一の一致しない開始ブラケットが処理されました |
 | ()()()()() | はい | シンプルなペアを繰り返すことでバランスが保たれます |
 | ((())())(()()) | はい | ネストされたバランスの取れたシーケンスが機能する |
 | ((()) | いいえ | 閉じ括弧の欠落が検出されました |
 | ())(( | NO | シーケンスの途中でマイナスになる残高が処理されました |

 ## 特殊なケース

 入力«)»の場合、残高は0から始まり、最初の文字で-1に減分され、すぐに«NO»が返されます。 «((())» の場合、残高は文字列全体で増減し、1 で終了し、結果は «NO» になります。これらのケースでは、アルゴリズムが、一致しない右括弧で始まるシーケンス、一致しない開始括弧で終わるシーケンス、およびネストされた構造を正しく処理し、常に正しい出力を生成することが確認されます。
