 ## 解決策
 ## 問題の理解

 一連の整数が与えられたので、それらの合計を計算する必要があります。 入力は整数で始まります`n`、これは後に続く数字の数を示します。 次のそれぞれ`n`行には配列の 1 つの要素が含まれます。 タスクは、それらをすべて加算して結果を出力するだけです。 

制約は非常に小さいです。 配列には最大 100 個の数値が含まれており、すべての数値は 1 から 100 の間です。可能な限り単純なアルゴリズムでも、簡単に制限内に収まります。 アレイ上の線形スキャンでは、最悪の場合でも 100 回の加算のみが実行され、事実上瞬時に実行されます。 

タスクは簡単ですが、不注意に実装すると失敗する可能性がある場所がまだいくつかあります。 

よくある間違いの 1 つは、入力文字列を追加する前に整数に変換するのを忘れることです。 例えば：```
3
1
2
3
```正しい出力は次のとおりです。```
6
```誰かが誤って整数を合計する代わりに文字列を連結すると、次のような結果が生じる可能性があります。`"123"`その代わり。 

もう 1 つの間違いは、次の行を 1 行だけ読んでいることです。`n`全部読むのではなく`n`要素。 考慮する：```
5
1
2
3
4
5
```正しい答えは次のとおりです。```
15
```最初の数値のみを読み取るバグのある実装では、誤った出力が行われます。`1`。 

最小サイズのケースもあります。```
1
42
```答えは依然として正しく計算される必要があります。```
42
```少なくとも 2 つの要素を前提とするアルゴリズムは、ここで失敗する可能性があります。 

## アプローチ

 最も直接的な解決策は総当りです。すべての数値を 1 つずつ読み取り、現在までの合計を記録します。 全部処理したら`n`数値の場合は、累積合計を出力します。 

これが機能するのは、問題の定義自体が追加的なものであるためです。 すべての要素は最終結果に独立して寄与するため、以前の値を再検討したり、複雑な状態を保存したりする必要はありません。 アルゴリズムは正確に実行されます`n`追加。 と`n ≤ 100`、最悪の場合、操作はわずか 100 回です。 

より高度な最適化は必要ありません。 すべての入力数値を少なくとも 1 回は検査する必要があるため、ブルート フォース アプローチはすでに最適です。 正しいアルゴリズムには下限があります。`O(n)`要素をスキップすると合計の一部が失われる可能性があるため、その時間が経過しました。 

重要な観察は、問題には隠れた構造がないということです。 クエリ、更新、順序付けの制約はありません。 単一の直線パスは、可能な限り最も単純かつ最速のソリューションです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、配列内の要素の数。 
2. 変数を初期化する`total = 0`。 この変数には、これまでに処理されたすべての数値の累計が格納されます。 
3. 繰り返します`n`回:

 1. 次の整数を読み取ります。 
2. に追加します`total`。 
4. すべての数値が処理されたら、印刷します。`total`。 

なぜ効果があるのか:

 あらゆる段階で、`total`これまでに読み取られたすべての要素の合計に等しい。 最初は要素が処理されていないため、正しい合計は次のようになります。`0`。 各反復では、不変式を維持しながら、実行中の合計に新しい配列要素を 1 つだけ追加します。 最後の反復の後、すべての配列要素が 1 回だけ組み込まれるため、`total`完全な配列の合計に等しい。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

total = 0

for _ in range(n):
    total += int(input())

print(total)
```プログラムは読み取りから始まります`n`、これにより、後に続く整数の数が決まります。 変数`total`累積和を格納します。 

ループは正確に実行されます`n`回。 各反復中に、1 つの整数が読み取られ、すぐに次の値に追加されます。`total`。 制約が小さいため、標準の高速入力処理を超える特別な最適化は必要ありません。 

微妙な詳細の 1 つは、次を使用して入力を整数に変換することです。`int(input())`。 入力は文字列として受信されるため、変換に失敗すると不正な動作が発生します。 

この実装では、配列全体の保存も回避されます。 各値は 1 回だけ使用されるため、読み取られた数値を処理することでメモリ使用量が一定に保たれます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    total = 0

    for _ in range(n):
        total += int(input())

    print(total)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided samples
assert run("5\n1\n2\n3\n4\n5\n") == "15\n", "sample 1"

# minimum-size input
assert run("1\n42\n") == "42\n", "single element"

# all equal values
assert run("4\n7\n7\n7\n7\n") == "28\n", "all equal"

# boundary values
assert run("3\n100\n100\n100\n") == "300\n", "maximum element values"

# off-by-one style case
assert run("2\n1\n100\n") == "101\n", "reads exactly n elements"

# larger case
assert run("5\n10\n20\n30\n40\n50\n") == "150\n", "general accumulation"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 |`4 7 7 7 7`|`28`| 同じ値の繰り返し |
