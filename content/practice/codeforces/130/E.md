 ## 解決策
 ## 問題の理解

 を計算するように求められます。`n`-th トリボナッチ数、ただしその値の剰余のみ`26`。 

シーケンスは次のように始まります。$$t_0 = 0,\quad t_1 = 0,\quad t_2 = 1$$以降のすべての値は、前の 3 つの値を合計することによって形成されます。$$t_i = t_{i-1} + t_{i-2} + t_{i-3}$$入力には単一の整数が含まれています`n`、出力は次の値になります。`t_n mod 26`。 

制約は非常に小さいです。 以来`n ≤ 1000`、単純な反復シミュレーションでも制限内で快適に動作します。 各トリボナッチ値の計算には一定の作業のみが必要であるため、線形アルゴリズムは約 1,000 回の更新を実行しますが、これは 2 秒の制限ではわずかです。 

繰り返しは前の 3 つの値に依存するため、開始ケースを不注意に扱うと、すぐに間違った答えが得られる可能性があります。 たとえば:

 入力:```
1
```正しい出力:```
0
```シーケンスが次から始まると想定するバグのある実装`t1 = 1`ここで失敗するだろう。 

もう 1 つのよくある間違いは、十分な値が存在する前に繰り返しを使用することです。 次のことを考慮してください。 

入力:```
2
```正しい出力:```
1
```ループがインデックスから始まる場合`2`の代わりに`3`、プログラムが誤って基本値を上書きする可能性があります。`t2`。 

モジュロ処理も微妙な点です。 値は指数関数的に増加するため、完全なトリボナッチ数を保存する必要はありません。 Python の整数はオーバーフローしませんが、モジュロを取ると`26`すべての移行中、数値は小さく保たれ、問題と直接一致します。 

たとえば:

 入力:```
25
```実際のトリボナッチ数はすでに非常に大きいですが、剰余のモジュロだけが必要です`26`重要です。 

## アプローチ

 最も直接的なアプローチは、トリボナッチ回帰を再帰的に定義することです。$$t_i = t_{i-1} + t_{i-2} + t_{i-3}$$そして計算する`t(n)`より小さいインデックスで関数を繰り返し呼び出すことによって。 

これは数学的には機能しますが、同じ状態を何度も再計算します。 計算するには`t(10)`、再帰はいくつかのコピーに展開されます。`t(9)`、`t(8)`、`t(7)`、 等々。 通話数は飛躍的に増加します。 適度な値であっても、これは無駄になります。 

メモ化された再帰または反復動的プログラミングのアプローチにより、繰り返しの作業が不要になります。 各トリボナッチ数は前の 3 つだけに依存するため、左から右にシーケンスを構築できます。 

繰り返し構造により、これが特に便利になります。 わかったら:$$t_{i-1},\ t_{i-2},\ t_{i-3}$$計算できます`t_i`すぐに。 以前の値はもう必要ありません。 

なぜなら`n`だけです`1000`、配列全体を保存するのはすでに十分に高速です。 最初の 3 つの値を初期化し、残りを繰り返し埋めていきます。 

モジュロ演算も遷移に自然に適合します。$$t_i = (t_{i-1} + t_{i-2} + t_{i-3}) \bmod 26$$すべてのステップでモジュロを適用することで、数値の不必要な増大を防ぎます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰 |$O(3^n)$|$O(n)$| 遅すぎる |
 | 反復動的プログラミング |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. 配列を作成する`trib`値を保存するのに十分な大きさ`0`に`n`。 
3. 基本ケースを初期化します。$$trib[0] = 0,\quad trib[1] = 0,\quad trib[2] = 1$$これらはシーケンスの定義によって直接与えられます。 
4. 反復処理`i = 3`まで`n`。 
5. すべての位置について、次を計算します。$$trib[i] = (trib[i-1] + trib[i-2] + trib[i-3]) \bmod 26$$剰余のみが重要であるため、モジュロはすぐに適用されます。 
6. 出力`trib[n]`。 

### なぜ効果があるのか

 アルゴリズムは、インデックスの処理後も不変条件を維持します。`i`、からのすべての値`trib[0]`を通して`trib[i]`正しいトリボナッチ数の剰余に等しい`26`。 

基本ケースは定義に従って正確に初期化されます。 後の各値は、元のシーケンスと同じ繰り返しを使用して計算されるため、以前の状態が正しいと仮定すると、新しく計算された状態はすべて正しいものになります。 帰納法により、配列全体はインデックスまで有効です`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

trib = [0] * (max(n + 1, 3))

trib[0] = 0
trib[1] = 0
trib[2] = 1

for i in range(3, n + 1):
    trib[i] = (trib[i - 1] + trib[i - 2] + trib[i - 3]) % 26

print(trib[n] % 26)
```注目すべき最初の詳細は配列サイズです。```
trib = [0] * (max(n + 1, 3))
```もし`n`よりも小さいです`2`、まだインデックスが必要です`0`、`1`、 そして`2`基本割り当てが有効なままになるように存在する必要があります。 

ループは次から始まります`3`最初の 3 つの値はすでにわかっているためです。 これより早く開始すると、基本ケースが誤って上書きされます。 

モジュロ`26`すべての遷移中に適用されます。```
(trib[i - 1] + trib[i - 2] + trib[i - 3]) % 26
```これにより、保存されているすべての値が内部に保持されます。`[0, 25]`。 モジュラー演算は加算に分散するため、最初に完全なトリボナッチ数を計算した場合と同じ最終剰余が生成されます。 

最後の print ステートメントでも使用されます。`% 26`。 厳密に言えば、値はすでに削減されていますが、最後のモジュロを維持することで意図が明示されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    trib = [0] * (max(n + 1, 3))

    trib[0] = 0
    trib[1] = 0
    trib[2] = 1

    for i in range(3, n + 1):
        trib[i] = (trib[i - 1] + trib[i - 2] + trib[i - 3]) % 26

    print(trib[n] % 26)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4\n") == "2", "sample 1"

# minimum meaningful indices
assert run("1\n") == "0", "t1 should be 0"
assert run("2\n") == "1", "t2 should be 1"

# recurrence check
assert run("5\n") == "4", "1 + 1 + 2 = 4"

# larger value with modulo behavior
assert run("10\n") == "17", "checks iterative transitions"

# boundary-sized input
assert run("1000\n").isdigit(), "handles maximum n"

 ## 特殊なケース

 最初の注意が必要なケースは、最小の有効なインデックスです。 

入力：```
1
```アルゴリズムは次のように初期化します。$$t_0 = 0,\quad t_1 = 0,\quad t_2 = 1$$以来`n = 1`、からのループ`3`に`n`決して走らない。 プログラムは直接出力します`trib[1] = 0`。 

これにより、基本値を誤って再計算することを回避できます。 

次の微妙なケースは、まさに遷移境界にあります。 

入力：```
3
```ループは 1 回実行されます。$$trib[3] = trib[2] + trib[1] + trib[0]$$これは次のようになります。$$1 + 0 + 0 = 1$$出力は次のとおりです。```
1
```これにより、3 つの基本状態がすべて存在した後にのみ再発が開始されることが確認されます。 

より大きなケースでは、モジュロ処理がチェックされます。 

入力：```
25
```トリボナッチ値はすぐに大きくなりますが、更新のたびに`% 26`、そのため、保存された値は常に小さいままになります。 アルゴリズムは引き続き同じ反復に従いますが、モジュラー演算内のみです。$$(a + b + c) \bmod 26$$これにより、巨大な整数を必要とせずに正しい剰余が生成されます。
