 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、サイクルのない接続されたグラフを意味し、任意の 2 つの都市間には 1 つの単純なパスが存在します。 選択した K 都市に正確に K 人の警備員を配置したいと考えています。 各警備員は、その位置から距離 R 以内にあるすべての都市を保護します。ここでの距離は、固有の木道のエッジの数として測定されます。 

目標は、ツリー内のすべての都市が少なくとも 1 つの選択されたガードの距離 R 内に収まるように、K 個のガードの位置と可能な最小の半径 R の両方を選択することです。 同様に、K 個の半径 R のボールを使用して木のすべての頂点をカバーし、R を最小限に抑えたいと考えています。 

重要な問題は、K が固定であるのに対し、R は柔軟であることです。 R を増やすとカバレッジが容易になりますが、K 中心のみで完全なカバレッジを可能にする最小限の R が必要です。 

この制約では、最大 5 つのテスト ケースと合計 5×10^5 のノードが許可されます。 これにより、テスト ケースごとに二次関数が即座に除外されます。 ツリー上の単純な貪欲シミュレーションは、BFS または DP の再起動を繰り返して実装すると簡単に O(N^2) に低下する可能性があるため、バイナリ検索チェックごとに O(N log N) であっても慎重に設計する必要があります。 

ツリーが非常に歪んでいる場合、微妙な障害が発生します。 たとえば、K = 1 の N ノードの折れ線グラフでは、R はおよそ N/2 になります。 リーフからの局所的な最適性を前提とした貪欲な配置は、グローバルな直径構造を考慮していない場合、失敗する可能性があります。 もう 1 つの注意が必要なケースは、K が大きい場合 (たとえば、K = N) です。その場合、正しい答えは R = 0 となり、常に正の半径を仮定したり、直径から中心を計算しようとするアルゴリズムは、縮退したケースを忘れると誤動作する可能性があります。 

## アプローチ

 この問題を直接考える方法は、R を修正し、それぞれが半径 R のサブツリーをカバーする最大 K 個の中心を使用してツリーをカバーできるかどうかを尋ねることです。 この実現可能性の質問に答えることができれば、その答えを R で二分探索することができます。 

ブルートフォース実行可能性チェックでは、K 個のノードを選択し、カバレッジを検証するためのあらゆる方法が試行されます。 これは組み合わせによるものであり、選択肢が O(N^K) 個あるため、すぐには不可能です。 

より構造化された強引なアプローチは、K 個のノードのすべてのサブセットを試し、それらから BFS を実行してカバレッジをチェックすることです。 BFS が O(N) であっても、これは依然として O(N^K) か、せいぜい O(N^(K+1)) であり、10^5 までの K には使用できません。 

重要な点は、任意の配置を試す必要がないということです。 ツリー上では、最適なカバレッジは、カバーされていない最も深いノードから中心を上に押し上げるという観点から推論できます。 これは古典的な「半径制約でツリーをカバーする」問題で、カバーされていない最も深いノードから貪欲に選択することで最適な構造が得られます。 

ツリーをルート化すると、覆われていないノードがあると、ルートに向かってその上に距離 R 以内のどこかに中心が配置されます。 重要な構造は、カバーされていない最も深いノードを選択したら、その上に正確に R ステップでガードを配置することが最善のアクションであるということです。これより低いものはより多くのカバーされていない領域を残し、より高いものは不要であるためです。 

これにより、実現可能性が貪欲なボトムアップ プロセスに変換されます。つまり、最も深く覆われていないノードを繰り返し選択し、上向きの距離 R に中心を配置し、距離 R 内のすべてをカバー済みとしてマークします。 多くても K 個の中心を使用してこれを行うことができれば、R は実現可能です。 

残りの課題は、「ジャンプ R ステップアップ」を効率的に計算することです。 これは、親ポインターと深さの順序付けを使用して処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(N^K) | O(N) | 遅すぎる |
 | 貪欲 + 二分探索 + ツリーリフティング | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 答え R を二分探索し、候補 R ごとに K 個のガードが十分であるかどうかをテストします。

1. ツリーを任意にルート化し、単一の DFS または BFS を使用して親ポインターと深さを計算します。 これにより、バイナリ リフティングを構築する場合、ステップあたり O(1) またはジャンプあたり O(log N) で上に移動する方法が得られます。 
2. 深さの降順でソートされたノードを収集します。 これにより、現在最も深い未カバーのノードが常に最初に処理されるようになります。 
3. ノードが選択したガードによってすでにカバーされているかどうかをマークする配列を維持します。 
4. 深さの降順でノードを繰り返します。 カバーされていないノードに遭遇した場合は、それをカバーするガードを配置する必要があります。 
5. ガードを配置するには、バイナリ リフティングを使用して、このノードから R ステップだけ上に移動します。 このノードがガードの中心になります。 この選択は、有効な解が最も深く覆われていないノードをカバーしなければならず、中心がそこから距離 R 以内になければならないという意味で強制されます。 
6. この中心から、距離 R 以内にあるすべてのノードを、中心からの深さ R に制限された BFS を使用してカバーされるものとしてマークします。 使用するガードの数を増やします。 
7. どこかの時点でガードの数が K を超えた場合、現在の R は実行不可能になります。 
8. 最大 K 個のガードを持つすべてのノードの処理を完了すると、現在の R が実現可能になります。 

実現可能性が成立する最小の R を二分探索します。 

この貪欲なプロセスが機能する理由は、カバーされていない最も深いノードがボトルネックであるためです。 どのような解決策でも、それを何らかの中心で覆う必要があり、その中心はその上の距離 R 以内になければなりません。 距離 R にある祖先を正確に選択すると、ノードをカバーしながら上向きのカバレッジが最大化され、下にある他のカバーされていない領域が損なわれることはありません。 ノードの処理深度が減少するため、以前に処理されるべきだったノードを再訪することはなく、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

sys.setrecursionlimit(10**7)

def solve_case(n, k, edges):
    g = [[] for _ in range(n)]
    for u, v in edges:
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    LOG = (n).bit_length()

    parent = [[-1] * n for _ in range(LOG)]
    depth = [0] * n

    stack = [(0, -1)]
    order = []
    while stack:
        u, p = stack.pop()
        parent[0][u] = p
        order.append(u)
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            stack.append((v, u))

    for j in range(1, LOG):
        for i in range(n):
            if parent[j - 1][i] != -1:
                parent[j][i] = parent[j - 1][parent[j - 1][i]]

    nodes = list(range(n))
    nodes.sort(key=lambda x: depth[x], reverse=True)

    def jump(u, dist):
        for j in range(LOG):
            if u == -1:
                break
            if dist & (1 << j):
                u = parent[j][u]
        return u

    def check(R):
        covered = [False] * n
        used = 0

        for u in nodes:
            if covered[u]:
                continue
            used += 1
            if used > k:
                return False

            center = jump(u, R)
            if center == -1:
                center = 0

            q = deque([(center, -1, 0)])
            covered[center] = True

            while q:
                x, p, d = q.popleft()
                if d == R:
                    continue
                for y in g[x]:
                    if y == p or covered[y]:
                        continue
                    covered[y] = True
                    q.append((y, x, d + 1))

        return True

    lo, hi = 0, n - 1
    ans = n - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        edges = [tuple(map(int, input().split())) for _ in range(n - 1)]
        out.append(str(solve_case(n, k, edges)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、祖先ジャンプのバイナリ リフティングを構築し、バイナリ検索内で貪欲な実行可能性チェックを使用します。 の`jump`関数はノードを R エッジ分上に移動します。これにより、最も深く覆われていないノードをカバーするための自然な中心候補が定義されます。 中心からの BFS は深さ R によって制限され、ガード半径内のノードのみをマークすることが保証されます。 

共通の微妙な点は、厳密に深さの降順でノードが処理されるようにすることです。 この順序が間違っていると、貪欲なステップによってセンターが選択されるのが早すぎて、カバレッジが無駄になる可能性があります。 

もう 1 つの微妙な問題は、ジャンプ R ステップがルートを超える場合の処理​​です。 その場合は根元までクランプします。 

## 実用的な例

 小さな木を考えてみましょう。```
1 - 2 - 3 - 4
        |
        5
```K = 1 とします。 

Rを二分探索します。 

R = 1 の場合、最も深いノード 4 を処理すると、中心が 3 になります。これはノード 2、3、4 までしかカバーしませんが、ノード 1 と 5 は完全にはカバーされていないため、実行できません。 

R = 2 の場合、中心は 2 になり、すべてのノードがカバーされます。 

| ステップ | ノード | カバーされていますか？ | アクション | センター |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | いいえ | プレースガード | 2 |
 | 2 | 3,2,4 | BFS 経由でカバー | 続ける | 2 |
 | 3 | 5 | すでに取り上げられています | スキップ | 2 |
 | 4 | 1 | カバーされた | 仕上げ | 2 |

 これにより、R = 2 で十分であることが確認されます。 

ここで星について考えてみましょう。```
    1
  / | \
 2  3  4
    |
    5
```K = 2 とします。最適な R は 1 です。1 と 5 にガードを配置できます。それぞれが隣接するノードをカバーし、すべてのノードはある中心から距離 1 以内にあります。 貪欲チェックでは、自然に最も深いノード 5 と 4 が選択され、構造全体を効率的にカバーする中心が配置されます。

 ## 特殊なケース

 K = 1 の縮退パス ツリーでは、アルゴリズムは常に上向きジャンプによって中間点を選択するように強制されます。 その場合、最も深いノードはその上の距離 R に中心をトリガーし、BFS はチェーンに沿って対称的に拡張します。 出力は直径の半分と一致します。 

K = N の場合、すべてのノードをガードとして選択できるため、R = 0 となります。アルゴリズムはこれを処理します。これは、ノードに対する最初のスキャンで、自明な中心を配置した直後にすべてのノードがすでに「カバーされている」ことが検出されるためです。 

すべての枝が 1 つのチェーンから伸びている非常に偏ったツリーでは、最も深い順の順序により、側枝が考慮される前に主バックボーンにガードが配置されることが保証されます。 これにより、冗長な配置が防止され、K の使用量が最小限に抑えられます。
