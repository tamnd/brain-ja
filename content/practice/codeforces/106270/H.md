 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 制御された操作を使用して、素因数を 2 つの位置の間で繰り返し移動することができます。つまり、約数を選択します。$p$ある要素の$A_i$、 分ける$A_i$による$p$、そして別の要素を乗算します$A_j$による$p$。 このような各転送には次のコストがかかります$p$、これを何度でも繰り返すことができます。 

これらの動きを実行した後、3 つの条件が同時に満たされるように最終的な配列を整形する必要があります。 友人が少なくとも1人は望んでいます$a$偶数の素数のみを含む要素、つまり 2 の累乗であることを意味します。 別の友人が少なくとも望んでいるのは、$b$奇数の素数のみを含む要素、つまり 2 で割り切れない要素。 3 番目の友人は、すべての要素が 2 の累乗か奇数のみ、あるいはその両方でなければならないという意味で最終的に「純粋」であることを要求します。 最後のケースは、値 1 の場合にのみ可能です。 

この操作では基本的に素因数を配列全体に再分配できますが、そのコストは移動される因数の値と等しくなります。 因子はインデックス間で任意に移動できるため、問題の構造は位置ではなく、要素間の素数の寄与をどのように再割り当てするかということになります。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$テスト ケース全体の要素の合計 (最大値)$10^6$。 これにより、因子の転送や配列に対する動的操作をシミュレートしようとするアプローチは即座に排除されます。 有効な解法では、各数値を事前に計算されたコスト表現に換算してから、大域的割り当て問題を線形に近い方法で解決する必要があります。$O(n \log n)$時間。 

素朴な解釈では、数値を繰り返し因数分解し、素数を移動し、コストを追跡するという操作をシミュレートしようとします。 単一の要素でも多くの約数を持つ可能性があり、転送を繰り返すと組み合わせが爆発的に増加します。 これは明らかに実行不可能です。 

最後の制約を誤解すると、さらに微妙な問題が発生します。 各数値が偶数純粋になるか奇数純粋になるかを個別に決定すると仮定するのは簡単ですが、3 番目の制約により一貫性が強制されます。すべての要素はこれらのカテゴリのいずれかで終わる必要があるため、各要素を個別に最適化するのではなく、制約の下で配列を分割しています。 

## アプローチ

 重要な問題は、すべての要素が 3 つの状態 (純粋に偶数 (2 の累乗)、純粋に奇数、または中立 (事実上 1 にのみ対応)) のいずれかで終了する必要があることです。 この操作により素因数を転送できますが、コストは転送された因数に比例するため、$p$、このプロセスを「ある要素から素数を削除し、その値に等しいコストで別の要素に挿入する」と解釈できます。 

これは、操作のシーケンスという観点ではなく、各数値を許可されたターゲット形式の 1 つに変換するのにどれだけのコストがかかるかという観点から考える必要があることを示唆しています。 

任意の番号に対して$x$、意味のある変換は 2 つあります。奇数の素因数をすべて削除して 2 のべき乗に変換するか、2 の因数をすべて削除して奇数に変換します。それぞれの削除は因数を移動することに対応し、グローバル制約が満たされている限り、実現可能性に影響を与えることなくこれらの因数を別の場所に配置できると想定できます。 

したがって、要素ごとに 2 つのコストを計算します。1 つはすべての奇数の素数を取り除く (2 の累乗にする) コスト、もう 1 つはすべての 2 の因数を取り除く (奇数にする) コストです。 これらのコストは素因数分解から導出されますが、実際には、取り除かれた素因数の寄与の合計に換算されます。 

要素ごとにこれら 2 つのコストがわかったら、問題は少なくとも$a$「偶数純粋」カテゴリに割り当てる要素、および少なくとも$b$すべての要素が 1 つのカテゴリにのみ割り当てられるため、総コストが最小限に抑えられます。 

これは、項目ごとに 2 つのオプションとカテゴリ サイズの下限制約を備えた古典的な割り当ての最小化です。 最適な構造は、コストの差を分類し、重複する選択を慎重に考慮しながら、どの要素が「偶数純粋に強制するのに最も安い」対「奇数純粋に強制するのに最も安い」かを貪欲に決定することによって生まれます。 

ブルート フォース アプローチでは、要素のすべてのパーティションを 3 つのグループに分けようとします。$3^n$可能性はありますが、それはすぐには不可能です。 DP オーバーカウントでも必要になります$O(nab)$、大きすぎます。 

効率性を解き放つ観察は、各要素が独立して意味のあるコストを 2 つだけ持つということであり、決定は線形制約の下で各カテゴリのサブセットを選択することに帰着します。 これにより、問題は、組み合わせ検索ではなく並べ替えとプレフィックスの最適化に限定されます。

 ## アルゴリズムのチュートリアル

 各要素について、2 つの値を計算します。1 つは純粋に偶数にする (すべての奇数の素数を取り除く) コスト、もう 1 つは純粋に奇数にする (すべての 2 の因数を取り除く) コストです。 これは、各数値を因数分解することによって行われます。$10^6$、最小の素因数をふるいを使用して事前に計算できます。 

次に、各要素を 2 つの割り当てコストを持つものとして扱います。 目標は、すべての要素を、少なくとも 2 つの意味のあるカテゴリのうちの 1 つに割り当てることです。$a$偶数純粋に進み、少なくとも$b$奇数純粋に行きます。 残りの要素は、実現可能性に応じて、より安価な側、またはフィラーとして許可される側に事実上強制的に挿入されます。 

次に、2 つのコストの差に基づいて要素を並べ替えます。 この違いは、要素がより自然に「偶数-純粋に友好的」であるか、「奇数-純粋に友好的」であるかという好みを捉えます。 

次に、すべての要素が 2 つのオプションのうち安価な方に割り当てられるベースラインを検討します。 このベースラインから、追加コストを最小限に抑える方法でカテゴリを切り替える要素を選択することで、制約を満たすように調整します。 

より多くの要素を純粋な偶数カテゴリに強制的に入れ、奇数純粋カテゴリに対して対称的に追加した場合にどれだけの追加コストが発生するかを追跡するプレフィックス調整を計算します。 次に、両方を満たす有効な分割を評価します。$a$そして$b$を選択し、最小コストの構成を選択します。 

これが機能する理由は、各要素が独立して寄与し、唯一の結合がカウントによるものであるためです。$a$そして$b$。 コストが線形化されると、問題はソートされた限界コストに対する制約された選択となり、局所的なコストの違いのみに依存しながら要素間の交換により実現可能性が維持されるため、貪欲な順序付けにより最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV**0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def cost_split(x):
    tmp = x
    odd_cost = 1
    while tmp > 1:
        p = spf[tmp]
        cnt = 0
        while tmp % p == 0:
            tmp //= p
            cnt += 1
        if p == 2:
            continue
        odd_cost *= (p ** cnt)
    tmp = x
    even_cost = 1
    while tmp % 2 == 0:
        tmp //= 2
    even_cost = x // tmp
    return even_cost, odd_cost

def solve():
    n, a, b = map(int, input().split())
    arr = list(map(int, input().split()))

    even_costs = []
    odd_costs = []

    base = 0

    for x in arr:
        ec, oc = cost_split(x)
        even_costs.append(ec)
        odd_costs.append(oc)
        base += min(ec, oc)

    diff = []
    for i in range(n):
        diff.append((even_costs[i] - odd_costs[i], i))

    diff.sort()

    best = 10**30

    # try number of elements assigned to even side in sorted order
    for k in range(n + 1):
        if k < a or n - k < b:
            continue
        cost = base
        # adjust first k as even, rest as odd
        for i in range(k):
            idx = diff[i][1]
            cost += even_costs[idx] - min(even_costs[idx], odd_costs[idx])
        for i in range(k, n):
            idx = diff[i][1]
            cost += odd_costs[idx] - min(even_costs[idx], odd_costs[idx])
        best = min(best, cost)

    print(best)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```ふるいは最小の素因数を構築するので、各数値は要素ごとに対数時間で因数分解できます。 の`cost_split`関数は、2 乗と奇数素数の寄与を分離し、許可された演算を決定論的な変換コストに変換します。 

の`base`コストは、各要素が独立してその安価な状態に割り当てられることを前提としています。 差分による並べ替えでは、プレフィックスの選択が最も「均等な」要素の選択に対応するように要素が整理されます。 考えられる分割点ごとに、偶数側に移動する要素の数を強制し、ベースラインに対する調整コストを計算します。 

実現可能性を確保するための微妙な実装の詳細: 両方のカテゴリ サイズが制約を満たす分割点のみが考慮されます。 もう 1 つの重要な点は、コスト調整が相対的に計算されることです。`min(even_cost, odd_cost)`、二重カウントを防ぎます。 

## 実用的な例

 自然に 2 の累乗に近い数値と、すでに奇数になっている数値がある小さな配列を考えてみましょう。 

説明のために、$n = 5$、$a = 2$、$b = 2$、および配列$[6, 8, 3, 12, 5]$。 

| 私 | 値 | 偶数コスト | 奇数コスト | 差分 |
 | --- | --- | --- | --- | --- |
 | 0 | 6 | 2 | 3 | -1 |
 | 1 | 8 | 8 | 1 | 7 |
 | 2 | 3 | 1 | 3 | -2 |
 | 3 | 12 | 4 | 3 | 1 |
 | 4 | 5 | 1 | 5 | -4 |

 diff でソートした後、各側に少なくとも 2 つある有効な分割を試みます。 強い負の差分要素を奇数側に割り当てる分割により、コスト圧力が軽減されます。 最適な構成は、大きな正の差分を持つ要素が偶数側に割り当てられる場合に現れます。偶数側での変換がより安価になるためです。 

このトレースは、アルゴリズムが要素を対称的に扱うのではなく、コストの非対称性を使用して、カーディナリティの制約を尊重しながら最小の変換コストで代入を調整することを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての数値がすでに奇数である場合です。 その状況では、偶数純粋要素を強制するには、すべての奇数素数を取り除くコストを全額支払わなければならず、アルゴリズムは、別の方法で強制されない限り、自然にそのような要素を奇数側に配置します。$a$。 ソートされた差分は大きく負になるか未定義になりますが、プレフィックス分割では実現可能性の制約が考慮されます。 

別のエッジケースが発生するのは次の場合です。$a + b = n$つまり、すべての要素を 1 つのカテゴリにコミットする必要があります。 このアルゴリズムは、すべての要素が割り当てられている分割のみを評価し、ベースラインと調整によって柔軟性を残さずに完全な変換コストを正確に考慮するため、引き続き機能します。 

最後の微妙なケースは、すべての要素に対する最も安価な割り当てが同じカテゴリであるにもかかわらず、制約により他の要素への割り当てが強制される場合です。 プレフィックス評価により、必要な強制切り替えの正確な数が確実に考慮され、コストの増加は局所的な最適な選択からの強制的な逸脱に対してのみ累積されます。
