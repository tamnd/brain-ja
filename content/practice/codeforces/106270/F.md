 ## 解決策
 ## 問題の理解

 私たちには、固定長の円形のランニング トラックが与えられています。 カブールはこのループに沿って一定の速度で走行し、一定期間一方向に移動し続けます。 他のウォーカーも同じループに沿って移動しており、それぞれが一定の符号付き速度で移動しているため、カブールと一緒に移動するか、カブールに対抗して移動します。 

それぞれのウォーカーについて、カブールがそのウォーカーに初めて出会った時間が告げられます。 最初の出会いの後、2 人は同じ円形トラック上を移動し続けるため、時間がなくなるまでに何度も再会する可能性があります。 このタスクは、すべての歩行者について、最初の会議と正確に T に行われる会議を含め、開始から最終時間 T までの時間間隔内に発生する会議の合計数を決定することです。 

主要な構造は、すべての歩行者が円上を一定の速度で移動するため、相対運動は均一であり、会合は定期的に繰り返されるということです。 各テスト ケースには合計で最大 200,000 人の歩行者を含めることができ、時間は最大 10^7 に達する可能性があるため、時間の経過に伴う動きをシミュレートしたり、毎秒処理したりするソリューションは不可能です。 O(NT) や T に依存するものでさえ、すぐに除外されます。 O(N sqrt T) でさえ安全ではありません。 

微妙な点は、最初の会議時間を計算するように求められていないことです。 それはすでに与えられています。 入力により、カブールと各ウォーカーの間の基準位置合わせが修正されます。 これにより、幾何学的な曖昧さが取り除かれ、問題は、制限された時間間隔内に周期的なイベントが何回発生するかを数えるという問題に変わります。 

素朴な推論を打ち破るエッジケースは、モジュールのラップアラウンドと方向の変更から発生することがよくあります。 

単純な失敗例は、歩行者がカブールに非常に近い速度で同じ方向に移動する場合です。 稀ではあるが複数回会うこともあり、その期間は長くなります。 

もう 1 つのエッジ ケースは、会議が時刻 T に正確に発生する場合です。T は包括的であるため、境界ヒットをカウントしないとオフバイワン エラーが発生します。 

最後に、方向は相対速度によってのみ重要になります。 符号付き速度なしですべてのウォーカーを均一に扱うと、周期の計算が不正確になります。 

## アプローチ

 強引な解釈では、カブールと各ウォーカーの位置を時間の経過とともにシミュレートします。 時間を少しずつ進めて、位置がモジュロ L に一致するときを追跡できます。各歩行者について、時間 T までの出会いを検出するには、将来のすべての衝突イベントをステップ実行する必要があります。 

問題は、会議が時間の等差数列を形成することです。 カブールと歩行者の間の相対位置は時間とともに直線的に変化し、円周上では位置の等価性が完全な相対周回ごとに繰り返されます。 これにより、一連の集合時間は、相対速度のみに依存する固定期間で、指定された最初の集合時間 ti から始まる等差数列に変換されます。 

実効相対速度を v0 - vi とすると、円を一周するたびに、同じ位置合わせが繰り返されます。 したがって、ti で 1 回会議が開催されると、次の会議はすべて、L を絶対相対速度で割った値に等しい一定の時間間隔の後に正確に開催されます。 

これにより、各ウォーカーは単純な計数問題に帰着します。つまり、最初の出現時刻と期間が与えられた場合、[0, T] 内に等差数列の項がいくつあるかを数えます。 

ブルート フォース アプローチはモーションに直接従うため機能しますが、歩行者ごとに潜在的に O(T) または O(T / period) イベントをステップ実行する必要があるため失敗します。 運動が円上で周期的であるという観察により、問題は等差数列の数え方に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(N・T) | お(1) | 遅すぎる |
 | 等差数列の計算 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 インタラクションは相互に影響を与えないため、各ウォーカーを独立して扱います。 

### 1. 相対運動を計算する

各ウォーカーについて、カブールとウォーカーの間の相対速度を計算します。 カブールは v0 で移動し、ウォーカーは vi で移動するため、閉じる速度は符号付き形式で v0 - vi になります。 周期の長さについては大きさだけが重要です。 

その理由は、会議は方向の決まりではなく、円の周囲の距離がどれだけ速く解決されるかのみに依存するためです。 

### 2. 会議期間の導出

 カブールが歩行者を追い越すか再び会うたびに、相対変位はちょうど 1 つの完全なループ長 L だけ増加します。したがって、連続する出会いの間の時間は L / |v0 - vi| です。 

これは会議時間の等差数列の期間です。 

### 3. モデルミーティングの時間

 すべての会議時間は次のように記述できます。 

ti、ti + ピリオド、ti + 2・ピリオド、...

 最初の項は与えられているので、幾何学的に計算する必要はありません。 

### 4. 時間枠内の有効な用語を数える

 [0, T] にある数列内の項の数が必要です。 ti は [0, T] 以内にあることが保証されているため、T を超えない項がいくつあるかを数えるだけで済みます。 

したがって、次のように最大の k を計算します。 

ti + k · 周期 ≤ T

 これにより、次のようになります。 

k ≤ (T - ti) / 周期

 したがって、会議の数は次のようになります。 

k+1

 ### 5. 整数演算を安全に処理する

 L と速度は整数であるため、実算では周期が整数にならない場合があります。 ただし、すべての入力は一貫した位置合わせを保証するため、スケーリングによる有理算術で作業します。つまり、浮動小数点を避け、乗算を使用して計算します。 

条件を書き換えます。 

ti + k·L / d ≤ T、ここで d = |v0 - vi|

 乗算:

 ti・d + k・L ≦ T・d

 それで:

 k ≤ (T・d - ti・d) / L

 整数の除算を使用します。 

### なぜ効果があるのか

 カブールと円周上の歩行者の動きは、L を法とする時間の一次関数に帰着します。位置が等しいということは、時間における線形合同を解くことに対応します。 1 つの解 ti が与えられると、他のすべての解は L / |v0 - vi| だけ正確に間隔をあけた格子を形成します。 他に力や相互作用が存在しないため、集合時間はこの等差数列によって完全に決定されます。 したがって、有効な会議をカウントすることは、進行の限定された区間内の整数ポイントをカウントすることと同等であり、これは導出された不等式によって正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K = int(input())
    out = []
    for _ in range(K):
        L, v0, T, N = map(int, input().split())
        res = []
        for _ in range(N):
            ti, vi = map(int, input().split())

            d = abs(v0 - vi)

            # number of additional full cycles possible
            # k such that ti + k*(L/d) <= T
            # => ti*d + k*L <= T*d
            # => k <= (T*d - ti*d) // L
            if ti > T:
                res.append(0)
                continue

            numerator = (T - ti) * d
            if L == 0 or numerator < 0:
                res.append(0)
                continue

            k = numerator // L
            res.append(k + 1)

        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各ウォーカーを一定時間で個別に処理します。 重要な部分は、期間の浮動小数点除算を避けることです。 代わりに、不等式に相対速度を掛けて、すべてを整数に保ちます。 これにより、精度の問題が回避され、T と L の値が大きい場合でも正確さが維持されます。 

微妙な詳細は、正確に T またはそれを超えて ti を処理することです。 ti はステートメント内の範囲内にあることが保証されているため、このチェックは主に防御的ですが、算術的なエッジ ケースから保護します。

    import sys
    input = sys.stdin.readline

    out = []

        L, v0, T, N = map(int, input().split())
        res = []

            res.append(k + 1)
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初の会議が時刻 T に正確に発生する場合です。その状況では、等差数列には最初の項のみが含まれます。 (T - ti) がゼロになり、k = 0 となり、答えは 1 になるため、この式は引き続き機能します。 

もう 1 つのケースは、相対速度が大きく、周期が非常に小さくなる場合です。 これにより会議の数が増加しますが、各ステップが浮動近似ではなく正確な不等式変換から導出されるため、整数除算は依然としてすべての有効な倍数を正確に取得します。 

vi が v0 に近づくと分母が小さくなるため、式 (T - ti) * d / L が大きくなる可能性があります。 中間乗算でのオーバーフローを回避するには、64 ビット整数を使用する必要があります。
