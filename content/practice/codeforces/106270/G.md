 ## 解決策
 ## 問題の理解

 長さの 1 次元のストリップが与えられます$n$。 各セルは最終的に黒または白のいずれかに着色されなければなりません。 色を自由に選ぶのではなく、正確に形を整える必要があります$k$長さが次のように固定されている連続する黒いセグメント$b_1, b_2, \dots, b_k$、という順番で。 連続する黒セグメントの間には少なくとも 1 つの白セルが必要ですが、両端には任意の数の白セルが許可されます。 

通常のノノグラム ルールに加えて、一部のセルはすでにボブによって制約されています。 一部のポジションは強制的に白になりますが、残りは未定です。 タスクはまず、セグメントの制約とボブの強制的な白の両方を満たす有効なカラーリングが存在するかどうかを判断することです。 少なくとも 1 つの有効な構成が存在する場合、すべての有効なソリューションにわたってすべてのセルを分類する必要があります。すべての有効なソリューションでセルが黒である場合はセルが黒としてマークされ、すべての有効なソリューションでセルが白である場合は白でマークされ、それ以外の場合はあいまいとマークされます。 

入力サイズが大きい: すべてのテスト ケースの合計長が達する可能性があります。$2 \cdot 10^6$したがって、どのソリューションもテスト ケースごとに基本的に線形である必要があります。 これにより、ブロックの配置を列挙したり、セルごとに独立して実行可能性を再計算したりするアプローチは除外されます。 

ブロックがまったくない場合、つまり、微妙なエッジケースが発生します。$k = 0$。 その場合、ストリップ全体は白でなければなりません。唯一の問題は、これがボブの制約に矛盾するかどうかです。 もう 1 つのエッジ ケースは、強制的な白セルが必要なセグメントのあらゆる配置をブロックする場合です。 たとえば、長さ 3 のブロックを配置する必要があるが、長さ 3 のすべての間隔が強制ゼロと交差する場合、インスタンスは直ちに不可能になります。 

## アプローチ

 強引な解釈では、可能なすべての配置を試します。$k$順序と間隔を尊重し、強制的な白セルとの一貫性を確認しながら、ストリップに沿ってブロックを配置します。 最も単純なケースでも、各ブロックは複数のブロックにまたがってシフトする可能性があります。$O(n)$そのため、構成の数は次のように指数関数的に増加します。$k$。 これは中程度の人でもすぐに実行不可能になります$n$。 

重要な観察は、有効な配置は多数あるかもしれないが、実現可能な配置の構造は単調であるということです。 ブロックの順序を固定すると、各ブロックには有効な開始位置の連続した範囲が含まれます。 これにより、ブロックごとに、すべての制約と一致する可能な最も早い開始位置と最も遅い開始位置を計算できます。 これらの範囲は、すべての有効なソリューションを完全に捉えています。 

これらの範囲がわかったら、問題の 2 番目の部分はカバレッジ推論タスクになります。各ブロックはスライド間隔にわたって黒のセルを提供し、セルが有効な配置のすべてでカバーされるか、一部でカバーされるか、あるいはまったくカバーされないかを判断する必要があります。 これにより、解決策の列挙が完全に回避され、問題が区間分析に限定されます。

 | --- | --- | --- | --- |
 | ブルートフォース配置 | 指数関数 | O(n) | 遅すぎる |
 | 間隔の境界 + カバレッジの推論 | テストごとに O(n + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションを 2 つのフェーズに分けます。ブロックの有効な配置範囲を計算し、次にこれらの範囲を使用してセルを分類します。 

### ステップ 1: 各ブロック間隔の実現可能性を検証する

 まずブロックごとに計算します$i$可能な限り早い開始位置$L_i$および可能な最新の開始位置$R_i$、順序の制約と強制的な白セルを考慮します。 

実現可能性を効率的にチェックするために、セグメントの O(1) に強制的な白が含まれているかどうかをテストできるように、文字列のプレフィックスの合計を事前計算します。 ある長さのセグメントの場合$b_i$強制的な白が含まれている場合、その配置は無効です。 

私たちは計算します$L_i$greedily from left to right. 各ブロックは、前のブロックの終了後に少なくとも 1 つの分離セルを加えた後に開始する必要があります。 強制白に触れずにブロックが収まる位置が見つかるまで、スタートを前方にスライドさせます。 そのような位置が存在しない場合、テスト ケース全体を実行することは不可能です。 

### Step 2: Compute latest valid positions

 私たちは計算します$R_i$右から左へ対称に。 スペースを維持し、強制的な白を避けながら、ブロックをできるだけ右に配置します。 これも貪欲なシフトと有効性チェックを使用します。 

このステップの後、有効な構成はすべて、各ブロック開始の選択に対応します。$s_i \in [L_i, R_i]$、順序制約は範囲の計算方法ですでにエンコードされています。 

### ステップ 3: 溶液中でどのセルが黒になる可能性があるかを判断する

 A cell$x$何らかのブロックが存在する場合、少なくとも 1 つの有効なソリューションでは黒になる可能性があります$i$そしていくつかの配置$s_i \in [L_i, R_i]$そのような$x \in [s_i, s_i + b_i - 1]$。 

この条件を書き直すと、次の場合にそのような配置が存在します。$$x \in [L_i, R_i + b_i - 1]$$したがって、セル全体の差分配列を維持し、すべての間隔をマークできます。$[L_i, R_i + b_i - 1]$。 このような間隔でカバーされないセルは、すべての有効なソリューションで強制的に白になります。 

### ステップ 4: どのセルが常に黒であるかを決定する

 細胞$x$ブロックが存在する場合は常に黒になります$i$そのブロックのすべての有効な配置がカバーされるように、$x$。 つまり:$$L_i \le x - b_i + 1 \quad \text{and} \quad R_i \ge x$$両方が当てはまる場合、有効な構成をどのように選択してもブロックされます。$i$常にまたがる$x$、作る$x$永久に黒い。 

これは、各ブロックをスキャンし、保証されたカバレッジ間隔をマークすることによって計算されます。$[L_i + b_i - 1, R_i]$。 

### ステップ 5: 最終的な分類

 各セルについて:

 - どの構成でもブロックで覆われていない場合は、常に白になります。 
- それ以外の場合、すべての構成で少なくとも 1 つのブロックでカバーされることが保証されている場合は、常に黒になります。 
- そうしないと曖昧になります。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な解が、固定された独立した間隔内のブロック開始位置の選択に正確に対応することです。$[L_i, R_i]$。 これらの間隔は、セルの順序付けと禁止によって引き起こされるすべてのグローバル制約を捕捉します。 この分解が成立すると、各ブロックはカバレッジ寄与に関して独立して動作し、すべてのセルのステータスは、これらの独立した選択にわたる間隔和合に関する推論に帰着します。 順序付けを超えたグローバル結合は残っておらず、すでに間隔の構築に吸収されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    b = list(map(int, input().split())) if k else []

    # prefix sum of forced zeros
    pref = [0] * (n + 1)
    for i, ch in enumerate(s):
        pref[i+1] = pref[i] + (ch == '0')

    def has_zero(l, r):
        if l > r:
            return False
        return pref[r+1] - pref[l] > 0

    if k == 0:
        # must all be white unless forced contradiction (already white forced allowed)
        # output all '0'
        print("Yes")
        print("0" * n)
        return

    L = [0] * k
    R = [0] * k

    # compute L
    pos = 0
    for i in range(k):
        if i > 0:
            pos += 1
        while pos + b[i] <= n and has_zero(pos, pos + b[i] - 1):
            pos += 1
        if pos + b[i] > n:
            print("No")
            return
        L[i] = pos
        pos += b[i]

    # compute R
    pos = n - 1
    for i in range(k-1, -1, -1):
        if i < k - 1:
            pos -= 1
        while pos - b[i] + 1 >= 0 and has_zero(pos - b[i] + 1, pos):
            pos -= 1
        if pos - b[i] + 1 < 0:
            print("No")
            return
        R[i] = pos - b[i] + 1
        pos = R[i]

    diff = [0] * (n + 2)
    always_black = [0] * n

    for i in range(k):
        diff[L[i]] += 1
        diff[R[i] + b[i] - 1 + 1] -= 1

        left = L[i] + b[i] - 1
        right = R[i]
        if left <= right:
            always_black[left] += 1
            if right + 1 < n:
                always_black[right + 1] -= 1

    cover = 0
    for i in range(n):
        cover += diff[i]
        always_black[i] += always_black[i-1] if i > 0 else 0

    res = []
    for i in range(n):
        if s[i] == '0':
            res.append('0')
            continue

        can_black = cover > 0
        must_black = always_black[i] > 0

        if must_black:
            res.append('1')
        elif can_black:
            res.append('?')
        else:
            res.append('0')

    print("Yes")
    print("".join(res))

t = int(input())
for _ in range(t):
    solve()
```実装は、セグメントの有効性チェックが一定時間になるように、強制ゼロの上にプレフィックスの合計を構築することから始まります。 フォワード パスは、各ブロックが収まるまで貪欲に右に押し込むことで、最も早い配置を構築します。 逆方向パスはこれを反映して最新の配置を計算します。 これら 2 つのパスは、すべてのブロックの完全な実行可能な範囲を定義します。 

差分配列`diff`セルが何らかのブロックの少なくとも 1 つの配置でカバーできるかどうかをキャプチャします。 2 番目の配列は、配置に関係なく、常に少なくとも 1 つの固定ブロックでカバーされるセルを追跡します。 最後に、強制的な白セルは他のすべてを即座にオーバーライドします。 

## 実用的な例

 次の小さな例を考えてみましょう$n = 6$、長さ 3 の 1 つのブロック、強制的な制限はありません。 ブロックは位置 0 ～ 3 のどこからでも開始できます。可能なカバレッジ結合は 0 ～ 5 のスライディング ウィンドウであるため、すべてのセルが黒になる可能性がありますが、オーバーラップ構造に応じて中央領域のみが常に黒になります。 

| ブロック | Ｌ | R | b | 対象期間 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 3 | [0, 5] |

 これは、開始が制限されている場合でも、可能なカバレッジがどのように連続範囲に拡大するかを示しています。 

ここで、たとえば 2 つのブロックを考えてみましょう。$b = [2, 1]$、真ん中に強制ゼロが入っています。 強制的な制約により、実行可能な配置が分割され、両方が縮小されます。$L$そして$R$。 一部のセルは完全に到達できなくなりますが、他のセルはシフトに関係なく常に最初のブロックによってカバーされたままになります。 

| ブロック | Ｌ | R | b |

 これは、強制制約がどのように実行可能間隔を断片化し、カバレッジ分類に直接影響を与えるかを示しています。 

これらの例では、すべての推論が区間境界に正しく帰着することを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、強制ゼロによって必要なブロックが完全に断片化される場合です。 たとえば、長さ 3 のすべてのセグメントに強制ゼロが含まれるストリップ上の長さ 3 のブロックでは、有効なゼロが生成されません。$L_1$。 前方構築中、有効なセグメントが見つかるまでポインタが進みます。 存在しない場合、アルゴリズムはインスタンスを即座に拒否し、正しい動作に一致します。 

もう 1 つのエッジ ケースは、ブロックの実行可能範囲が 1 つの位置に崩れるときに発生します。 その状況で$L_i = R_i$、ブロックがすべてのソリューションで固定されていることを意味します。 代替配置がないため、分類ロジックはそのスパン内のすべてのセルを常に黒として正しくマークします。 

最後のエッジケースは、$k = 0$ここで、ストリップには黒いセルがまったく含まれていてはなりません。 このアルゴリズムはすべての DP をバイパスし、黒いブロックが存在しないという制約と一致して、完全に白いストリップを直接出力します。
