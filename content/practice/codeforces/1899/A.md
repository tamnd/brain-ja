 ## 解決策
 ## 問題の理解

 整数を使用した単純な 2 人用ゲームを分析するように求められています。 ゲームは数字から始まります$n$。 Vanya が最初に動き、各プレイヤーは自分のターンに数値を 1 ずつ増やすか減らすことができます。 Vanya が移動した後、数字が 3 で割り切れる場合は、即座に勝ちます。 Vanya が 10 移動 (各 5 ターン) 経っても勝てなかった場合、Vova が勝ちます。 目標は、特定の開始番号を決定することです。$n$、両方が最適にプレイすると仮定すると、どちらのプレイヤーが勝つか。 

入力は複数のテスト ケースで構成され、それぞれが 1 つの整数を持ちます。$n$1 ～ 1000 の範囲です。$t \le 100$、操作の総数はそれほど多くありません。 制約は十分に小さいため、必要に応じてあらゆる可能な動きシーケンスを探索できますが、ゲームの勝利条件は完全に 3 で割り切れるかどうかに依存するため、より賢明なアプローチが存在します。 

次の場合には、明らかではないエッジケースが発生します。$n$この場合、Vova にすぐに反応させずに Vanya は増減することはできませんが、それでも最初に移動するため、数値を 3 で割り切れるように移動することはできません。 彼はそれを調整しようと努めなければならない。 もう 1 つの微妙な点は、1 を加算または減算すると、3 を法とする剰余が交互に代わることです。$n \% 3 = 1$, Vanya は 1 を引くことで 3 の倍数に直接移動できます。これらのモジュロの考慮事項が最適なプレイを決定します。 このモジュール式パターンを認識せずに動きをシミュレートする単純なアプローチでは、勝者を誤って予測する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、プレーヤー間で交互に最大 10 ステップまでの一連の動きをすべて列挙し、Vanya の動きの後に 3 の倍数になるシーケンスがあるかどうかを確認します。 各動きには 2 つのオプションがあるため、最悪の場合のシーケンスの総数は次のようになります。$2^{10} = 1024$テストケースごとに。 これは実現可能ですが、ゲームは 3 を法とする数値によって完全に決定されるため、必要ありません。 

重要な洞察は、勝者は残りによって完全に決定されるということです$r = n \% 3$。 もし$r = 0$, ±1手でも結果が生じるため、Vanyaはすぐには勝つことができません。$r = 1$または$2$。 もし$r = 1$または$2$, Vanya は最初のターンで 1 を引くか足すことですぐに 3 の倍数に移動できます。Vanya はすぐに勝つか、1 つの手で 3 の倍数に到達できないため、残りの 10 手の制限は無関係です。 これにより、問題は単純なモジュロ チェックに集約されます。

 | ブルートフォース | O(2^10 * t) | お(1) | 許容できるが不要 |
 | 最適 | O(t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 
3. 剰余を計算する$r = n \% 3$。 
4. もし$r = 0$、「秒」を出力します。 ヴァーニャが作れないからだ$n$最初の動きで 3 で割り切れるので、最終的には Vova が勝つでしょう。 
5. もし$r = 1$または$2$、「最初」を出力します。 ヴァーニャはすぐに調整できる$n$±1して3で割り切れれば即勝ちです。 

これが機能する理由: ここでの不変条件は、現在の整数に関する唯一の関連情報が 3 を法とした剰余であるということです。各移動は剰余を ±1 ずつシフトします。 Vanya が最初に動くので、可能であれば 0 モジュロ 3 を打つ手を選択できます。 それができない場合は、すでに残りが0であることを意味し、すぐには勝つことができません。 許可される手の数 (10) は 1 より大きく、両方のプレイヤーが最適にプレイするため、3 を法とした余りによって完全に結果が決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    r = n % 3
    if r == 0:
        print("Second")
    else:
        print("First")
```このソリューションは、入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースの場合。 各数値について、3 を法とする剰余を計算し、勝者を直接決定します。 追加の状態やシミュレーションは必要ないため、off-by-one エラーや誤った移動カウントが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        output.append("Second" if n % 3 == 0 else "First")
    return "\n".join(output)

# Provided samples
assert run("6\n1\n3\n5\n100\n999\n1000\n") == "First\nSecond\nFirst\nFirst\nSecond\nFirst", "sample 1"

# Custom cases

assert run("2\n3\n300\n") == "Second\nSecond", "multiples of 3"
assert run("4\n1\n2\n1000\n999\n") == "First\nFirst\nFirst\nSecond", "mixed values"
assert run("1\n7\n") == "First", "small odd number"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 もし`n`たとえば、正確に 3 で割り切れます。`n = 3`、 それから`n % 3 = 0`。 私たちのアルゴリズムによれば、「秒」が出力されます。 トレース: Vanya の最初の動きは増加または減少する可能性があります`n`どちらも 3 で割り切れないため、Vova は最適に対応し、最終的には 10 手以内に勝つことができます。 アルゴリズムは、すべての手をシミュレートすることなく、この結果を正確に予測します。 

もし`n = 1000`、`n % 3 = 1`, Vanya は 1 を引いて、3 で割り切れる 999 に達します。出力は「First」です。 これは、モジュロ チェックが範囲内の大きな数値を処理することを確認し、ソリューションが上限の制約までスケールアップすることを示しています。
