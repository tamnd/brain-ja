 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは整数配列を提供します。タスクは、追加の制限が 1 つあり、選択されたセグメント内の隣接する要素がパリティで交互に配置される必要がある中で、合計ができるだけ大きい空ではない連続セグメントを選択することです。 言い換えれば、選択された 2 つの隣接する要素が元の配列内で隣り合っている場合は常に、一方は偶数、もう一方は奇数でなければなりません。 

これにより、古典的な最大部分配列合計の問題が、同じパリティを持つ 2 つの連続する要素を介してセグメントを拡張することができない制約付きバージョンに変わります。 ただし、どこからでも新しいセグメントを開始することができ、配列全体を使用する必要はありません。 

この制約では、すべてのテスト ケースにわたって要素の合計が最大 200,000 個まで許容されます。これは、すべての解がテスト ケースごとに線形であるか、最悪でも O(n log n) でなければならないことを直ちに意味します。 すべての部分配列を試行するか、セグメント全体の合計を繰り返し再計算する 2 次アプローチでは、最悪の場合、およそ 10^10 の演算に達しますが、これは制限をはるかに超えています。 これにより、動的プログラミングまたは貪欲なリニア スキャンが推進されます。 

いくつかの特殊なケースは見落とされがちです。 

空ではない部分配列を選択する必要があるため、単一要素配列は、それが負であっても常にその要素と等しい答えを持ちます。 

パリティが交互に存在するが、負の値が多く含まれるセグメントは、拡張すると合計が減少する可能性があるため、早めに切り詰めるのが最適である可能性があります。 

素朴な貪欲な拡張の微妙な失敗例は、パリティの代替を中断したときに発生します。再起動が遅すぎたり、早すぎたりすると、より良いセグメントを見逃す可能性があります。 たとえば、次のような配列では、`[5, -100, 4, 3]`、負の値が早期に再起動を強制する必要がある場合、パリティ ブレーク時にのみ盲目的にリセットするだけでは不十分です。 

## アプローチ

 ブルートフォースのアイデアでは、考えられるすべてのサブ配列を列挙し、それがパリティ交互制約を満たしているかどうかをチェックします。 有効なサブ配列ごとに、その合計を計算し、最大値を追跡します。 1 つのサブ配列の有効性をチェックするには O(長さ) かかり、O(n^2) 個のサブ配列があるため、最悪の場合は O(n^3) 時間かかりますが、これは実行不可能です。 

部分配列の有効性がローカルであることに気づくことで、これを減らすことができます。開始インデックスを固定したら、パリティ条件が壊れるまで貪欲に拡張できます。 これにより、i から始まるすべての部分配列のチェックが O(n) まで削減され、O(n^2) が得られます。 合計要素数 2e5 にはまだ遅すぎます。 

重要な観察は、以前の決定を再検討する必要がないということです。 各位置で、既存の有効な交互セグメントを継続するか、現在の要素から再開します。 これは、Kadane のアルゴリズムに似た古典的な動的プログラミングの状況ですが、遷移に追加の制約があります。 

現在のインデックスで終わる有効な交互サブ配列の可能な限り最良の合計を維持します。 i−1 から i に拡張する場合、a[i] が a[i−1] と異なるパリティを持つ場合にのみ拡張できます。 パリティが一致する場合は、i から再開する必要があります。 

さらに、拡張が許可されている場合でも、以前の累積合計が負になり、最適性が損なわれる可能性があるため、i で新たに開始することと比較します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適DP(カダネ様) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の位置で終わる実行中の最適なサブ配列を維持しながら、各配列を個別に処理します。 

1. 変数を初期化する`current`インデックス 0 で終わる最良の交互サブ配列合計として、これは単純に`a[0]`。 初期化も行います`answer = a[0]`なぜなら、最適な部分配列は単一の要素である可能性があるからです。 
2. インデックス 1 から n-1 まで配列を反復処理します。 
3. 各インデックス i で、次のことを確認します。`a[i]`前のセグメントを拡張できます。 拡張機能は次の場合にのみ有効です`a[i]`そして`a[i-1]`パリティが異なります。 パリティが同じ場合、ルールを尊重しながら i-1 で終わる部分配列を i に拡張することはできません。 
4. 拡張が有効な場合、候補値を計算します`current + a[i]`。 それ以外の場合は、拡張を不可能に設定します。 
5. 拡張の実現可能性に関係なく、値を指定して i で新しい部分配列を開始することも検討してください。`a[i]`。 
6.セット`current`これら 2 つのオプションの最大値まで。 この選択により、i で終わる最良の有効な交互サブ配列が常に維持されることが保証されます。 
7.アップデート`answer`と`max(answer, current)`。 

スキャンが終了したら、`answer`すべての有効な部分配列の可能な限り最良の合計が含まれます。 

### なぜ効果があるのか

 すべてのインデックス i で、アルゴリズムは次の不変条件を維持します。`current`は、正確に i で終わる有効な交互パリティ部分配列の最大合計です。 このような部分配列は、i-1 で終わる有効な部分配列を拡張するか、i で新たに始まるかのいずれかで得られます。 i で終わるすべてのサブ配列には i が含まれている必要があり、その前の要素はサブ配列の一部であるかどうかのいずれかであるため、3 番目の可能性はありません。 パリティ制約は、拡張が許可されるかどうかを制限するだけであり、最適なサブ配列の構造は制限されません。 これら 2 つの選択肢のうち最善のものを常に採用するため、最適なソリューションが破棄されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    current = a[0]
    best = a[0]
    
    for i in range(1, n):
        if (a[i] % 2) != (a[i - 1] % 2):
            extend = current + a[i]
        else:
            extend = -10**18  # invalid transition
        
        current = max(a[i], extend)
        best = max(best, current)
    
    out.append(str(best))

print("\n".join(out))
```コードは DP の定式化に直接準拠しています。 変数`current`現在のインデックスで終わる最も有効な交互サブ配列を表します。 パリティが交互になると、拡張しようとします。 それ以外の場合、拡張子は強制的に無効になります。 

微妙な点は、`a[i]`これにより、以前の蓄積が有害になるたびに再起動することが保証されます。 これにより、負の値が存在する場合でも最適性が維持されます。 

変数`best`最適な部分配列はどこで終わる可能性があるため、すべてのエンドポイントにわたるグローバル最大値を追跡します。

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        current = a[0]
        best = a[0]

                extend = current + a[i]
            else:
                extend = -10**18

            current = max(a[i], extend)
            best = max(best, current)

        out.append(str(best))

    return "\n".join(out)

 ## 特殊なケース

 初期化により両方の要素が設定されるため、単一要素の入力は直接処理されます。`current`そして`best`最初の要素に。 ループは実行されないため、値が負の場合でも答えは正しく返されます。 

すべての番号が同じパリティを持つ配列では、拡張は許可されません。 すべてのインデックスが再開ポイントになるため、このアルゴリズムは事実上、最大の単一要素を取得することになります。 各反復セット`current = a[i]`、 それで`best`最大要素を追跡します。 

大きな負の値を含む配列が交互に存在する場合、アルゴリズムが繰り返し再起動される可能性があります。 各再起動は、`max(a[i], extend)`比較して、有害なプレフィックス合計が決して引き継がれないようにします。 

負の値が 2 つの有効な交互の正の値の間に挟まれている場合、アルゴリズムは、負の値を維持することで交互のチェーンが長くなるかどうか、または再起動するとより良い合計が得られるかどうかを正しく評価します。
