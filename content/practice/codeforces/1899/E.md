 ## 解決策
 ## 問題の理解

 整数の配列が与えられたので、それを降順でない順序で並べ替えたいと考えています。 問題は、要素を任意に交換できないことです。 代わりに、単一の複雑な操作を使用できます。最初の要素を取得し、それを最後に移動し、直前の要素よりも小さい限り、それを左にバブルして戻します。 概念的には、これは配列を回転し、渡された要素に対して正しい位置が見つかるまで、移動した要素を左に「スライド」させるのと似ています。 目的は、配列をソートするためのこれらの操作の最小数を決定すること、またはソートが達成できない場合は不可能であることを報告することです。 

配列は最大 200,000 要素にすることができ、複数のテスト ケースにわたるすべての配列サイズの合計が 200,000 を超えることはありません。 これにより、私たちのソリューションは線形または線形計算時間に制限されます。 二次関数は遅すぎるでしょう。 たとえば、各操作を単純にシミュレートしようとすると、最大で 3 分かかる可能性があります。`O(n^2)`アレイごとの時間ですが、これは現実的ではありません。 

微妙なエッジケースには、すでにソートされている配列 (操作がゼロ)、最初の要素が最大で複数回削除しないとソートがブロックされる配列、「厳密に大きい」条件によってスワップが制限される繰り返し要素を含む配列などが含まれます。 素朴なシミュレーションの失敗を示す小さな例は次のとおりです。`[4, 3, 1, 2]`。 グローバルな順序を考慮せずに各要素を前方に移動させようとすると、1 回のパスでソートできると結論付けてしまうかもしれませんが、正しい答えを得るのは不可能です。`3`そして`1`許可された操作では修正できません。 

## アプローチ

 ブルート フォース アプローチでは、文字通り操作をシミュレートします。最初の要素を最後まで移動し、収まるまでバブリングして戻すことを繰り返します。 各操作の後に、配列がソートされているかどうかを確認します。 これが機能するのは、操作が決定的であり、各アプリケーションが定義された方法で配列を変更するためです。 ただし、最悪の場合の操作数は次の数に達する可能性があります。`n`要素ごとに、結果として`O(n^2)`テストケースごとに。 と`n`最大 200,000 では、これは遅すぎます。 

最適なアプローチを実現するための重要な洞察は、この操作により、本質的に、既に順序付けられている配列のプレフィックスを後方に移動できることを認識することです。 配列を最後から逆方向に考えると、すでにソートされていて減少していない最長のサフィックスには、今後の操作では触れられません。 移動できるのは前の要素のみです。 したがって、操作の最小数は、このソートされたサフィックスの前にあるソートされていないプレフィックスの長さによって決まります。 ソートされていないプレフィックスに、ソートされたサフィックスの最初の要素より大きい要素が含まれている場合、操作では「厳密に大きい」ルールに違反せずにサフィックスの中央に要素を挿入できないため、ソートは不可能になります。 

したがって、問題は、末尾から最も長い非減少サフィックスを特定し、残りのプレフィックスを競合することなく順番に後ろに移動できるかどうかを確認することに帰着します。 「はい」の場合、操作の数はプレフィックスのサイズと等しくなります。 そうしないと、並べ替えが不可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定された配列について、末尾からスキャンを開始して、減少しない最長のサフィックスを見つけます。 ポインタを初期化する`i = n-2`そしてできるだけ長く後ろに進みます`a[i] <= a[i+1]`。 この後、`i+1`ソートされたサフィックスの開始をマークします。 
2. このサフィックスの前のプレフィックスを運用ルールに違反せずに最後まで「ローテーション」できるかどうかを確認します。 具体的には、この操作により、各要素がその前の要素より小さくなくなるまで左にバブリングすることができます。 これは、配列の最初の要素が最終的にこのプレフィックスの末尾に到達する必要があるため、プレフィックスが増加していないかどうかをチェックすることと同じです。 
3. 必要な操作の数を数えます。これは、ソートされていないプレフィックスの長さと正確に一致します。 これは、ソートされたサフィックスの前の要素の数です。 
4. いずれかの時点で、プレフィックス内の要素がソートされたサフィックスの先頭より大きく、正しく挿入できないことが検出された場合は、出力`-1`。 

機能する理由: この操作により、相対的な順序を尊重しながら各プレフィックス要素を後方に移動できます。 不変条件は、要素がソートされたサフィックスに入ると、正しい相対位置に留まるということです。 したがって、ソートされた最長のサフィックスを特定することで、最小限の安全点がわかります。 それ以前のすべては操作によって移動する必要があり、その数はプレフィックスのサイズと同じです。 プレフィックスに違反がある場合は、一部の要素がルールに適合しないことを意味し、不可能であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations_to_sort(a):
    n = len(a)
    i = n - 2
    while i >= 0 and a[i] <= a[i + 1]:
        i -= 1
    if i == -1:
        return 0  # already sorted
    prefix_length = i + 1
    
    # Check if the prefix is non-increasing
    for j in range(prefix_length - 1):
        if a[j] < a[j + 1]:
            return -1
    return prefix_length

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_operations_to_sort(a))
```機能`min_operations_to_sort`最初にソートされたサフィックスを末尾から検索します。 配列全体がすでにソートされている場合は、ゼロを返します。 次に、ソートされていないプレフィックスを調べて、増加していないことを確認します。 そうでない場合、プレフィックス内の一部の要素が操作の「厳密に大きくなるまでバブル」条件に違反し、並べ替えが不可能になるため、リターンします。`-1`。 それ以外の場合、正しい位置に到達するには各要素を 1 回回転する必要があるため、操作の数はプレフィックスの長さに等しくなります。
