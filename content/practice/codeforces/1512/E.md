 ## 解決策
 ## 問題の理解

 1 から 1 までの数値の順列を作成するように求められます。$n$インデックスからの連続セグメントの合計が$l$に$r$指定された値と等しい$s$。 ここでの順列は、1 から 1 までのすべての整数を並べただけです。$n$繰り返しはありません。 入力は複数のテスト ケースを与え、それぞれが指定します$n$、$l$、$r$、 そして$s$。 出力は、合計条件を満たす有効な順列であるか、そのような順列が存在しない場合は -1 でなければなりません。 

主な課題は次のような事実から生じます。$s$セグメントの可能な合計の範囲内の任意の合計を指定できます。最小または最大の選択によって制限されます。$k = r - l + 1$1 から 1 までの数字$n$。 具体的には、可能な最小の合計は、$k$数字は$1 + 2 + \dots + k = k(k+1)/2$、そして最大のものは$n + (n-1) + \dots + (n-k+1) = k(2n - k + 1)/2$。 もし$s$この範囲外の場合、解決策はありません。 

とすれば$n$最大 500 であり、次の合計$n$すべてのテスト ケースも最大 500 であるため、$O(n^2)$あるいは$O(n^3)$制限時間を超過することなくアプローチできますが、明確さと単純さのために、線形または線形に近いアプローチが望ましいです。 

単純なアプローチでは、次のすべての組み合わせを試します。$k$1 から までの要素$n$それらの合計が次のようになるかどうかを確認する$s$、組み合わせ的に遅すぎます。 単純な実装を失敗させる可能性のあるエッジケースには、長さが 1 または 1 のセグメントが含まれます。$n$、合計が可能な最小値または最大値に等しい場合、および残りの要素も有効な順列を形成する必要がある場合。 

たとえば、$n=3, l=1, r=2, s=4$、選ぶかもしれない$[1,3]$セグメントについては残りますが、$[2]$残りの要素については。 不注意に扱うと、重複が発生したり、不可能な構成がスキップされたりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべての組み合わせを列挙します。$k = r - l + 1$から$[1, n]$それらの合計が等しいかどうかを確認します$s$。 このような組み合わせが存在する場合、残りの数字を他の位置に任意に配置することができます。 複雑さは$O(\binom{n}{k})$テストケースごと、小規模な場合には問題ありません$n$しかし、次の場合は遅くなります$n$このアプローチは正しいですが、非効率的です。 

効率的なソリューションを実現するための重要な洞察は、セグメントを貪欲に構築できることを認識することです。 最小のものから始める$k$最小の合計を与える数値。 次に、セグメント内の最大の数値を増分して合計を増加させます。$s$数字を明確に保ちながら。 合計が次のような有効なセグメントが得られたら、$s$, 残りの位置を任意の順序で残った数字で埋めることができます。 これは、次のいずれかの合計が得られるため機能します。$k$範囲内の個別の数値$[1, n]$小さい数値を大きい未使用の数値と交換することで調整できます。 

これにより、問題は組み合わせ検索ではなく線形構造に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\binom{n}{k})$|$O(n)$| 遅すぎる$n \sim 500$|
 | 貪欲な建設 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング$k = r - l + 1$、セグメントの長さ。 
2. 最初の値の最小合計を計算します。$k$数字:$min\_sum = k(k+1)/2$、および最大値の最大合計$k$数字:$max\_sum = k(2n - k + 1)/2$。 
3. もし$s < min\_sum$または$s > max\_sum$、この合計を達成できるセグメントがないため、-1 が出力されます。 
4. セグメントを最初のセグメントとして初期化します。$k$数字:$[1, 2, ..., k]$。 このセグメントの現在の合計を計算します。 
5. セグメントの終わりから始めて、各数値を超えない範囲でできるだけ増加させます。$n$セグメント内で番号を繰り返すことはありません。 インデックスの番号の場合$i$、最大値は次のとおりです。$n - (k - i - 1)$。 合計が次と等しくなる程度に増やしてください。$s$。 
6. この構築されたセグメントを所定の位置に配置します$l-1$に$r-1$順列の中で。 
7. 残りの位置に 1 から 1 までの数字を入力します。$n$セグメントに含まれていないもの。 どのような順序でも機能します。 
8. 結果の順列を出力します。 

重要な不変条件は、セグメント番号を常に区別し、有効な範囲内に保つことです。 最後から調整することで、より小さい数値が合計に達するために必要な値を取得するのを妨げられなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r, s = map(int, input().split())
        k = r - l + 1
        min_sum = k * (k + 1) // 2
        max_sum = k * (2 * n - k + 1) // 2
        if s < min_sum or s > max_sum:
            print(-1)
            continue
        
        # Start with the smallest k numbers
        seg = list(range(1, k + 1))
        curr_sum = min_sum
        for i in range(k - 1, -1, -1):
            # Max possible for this position without breaking uniqueness
            max_val = n - (k - 1 - i)
            if curr_sum == s:
                break
            add = min(max_val - seg[i], s - curr_sum)
            seg[i] += add
            curr_sum += add
        
        # Fill the permutation
        used = set(seg)
        perm = []
        idx = 0
        for pos in range(1, n + 1):
            if l <= pos <= r:
                perm.append(seg[idx])
                idx += 1
            else:
                for candidate in range(1, n + 1):
                    if candidate not in used:
                        perm.append(candidate)
                        used.add(candidate)
                        break
        print(*perm)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず合計が達成可能かどうかを確認します。 セグメントは、一意性を維持しながら目的の合計に達するように、最後から貪欲に増分することによって構築されます。 残りの数値は、未使用の値から順に埋められます。
