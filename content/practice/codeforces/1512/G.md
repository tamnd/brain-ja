 ## 問題の理解

 最小の正の整数を見つけるように求められます$n$約数の合計が指定された数に等しくなるように$c$。 正式には、約数の和関数は$d(n)$割るすべての数値を合計します$n$均等に、含む$1$そして$n$自体。 例えば、$d(6) = 1 + 2 + 3 + 6 = 12$。 整数を与える$c$が存在するかどうかを判断する必要があります。$n$そのような$d(n) = c$、そうであれば、そのような最小のものを返します$n$。 そうでない場合$n$存在するので戻ります$-1$。 

入力は複数のテスト ケースで構成され、それぞれが 1 つの整数を与えます$c$まで$10^7$。 と$t \le 10^4$テストケースを計算する余裕がない$d(n)$すべてに対して素朴に$n \le 10^7$繰り返し。 それぞれをチェックする単純な総当たりアプローチ$n$その約数を合計すると、$O(n \sqrt{n})$テストケースごとに、最悪の場合の入力を考慮すると法外に遅くなります。 可能なすべての情報を効率的に事前計算する、よりスマートなアプローチが必要です。$c$。 

エッジケースには以下が含まれます$c = 1$、 どこ$n = 1$が唯一の有効な解決策です。 もう 1 つの微妙な点は、次のような数値が多いことです。$c = 2$または$c = 5$、どれにも該当しません$n$。 すべての人にとって解決策が存在すると仮定する素朴なアプローチ$c$これらの入力では失敗します。 また、小さな合成数の約数の合計である数値も考慮する必要があります。$c = 12$に対応する$n = 6$、 だけでなく$c = 18$に対応する$n = 12$。 アルゴリズムは最小値を選択する必要があります$n$。 

## アプローチ

 ブルートフォースアプローチでは、次の手順が繰り返されます。$n = 1$ある上限まで（たとえば$10^7$)、計算します$d(n)$以下のすべての約数をチェックすることで、$\sqrt{n}$、除数の和から最小値までのマップに結果を保存します。$n$それを生産している。 このアプローチは正しいですが、およそ次のような複雑さがあります。$O(n \sqrt{n}) = O(10^7 \cdot 3162)$が遅すぎます。$t = 10^4$クエリ。 

重要な観察は、すべての除数の和関数を事前に計算できることです。$n$まで$10^7$ふるいのようなアプローチを使用します。 除数の合計関数は本質的に乗算的であり、倍数を反復することによって計算できます。 具体的には、それぞれについて、$i$1から$N$、追加します$i$に$d[j]$すべての倍数に対して$j = i, 2i, 3i, \dots, N$。 これにより計算が可能になります$d(n)$みんなのために$n$で$O(n \log n)$時間。 取得したら$d(n)$みんなのために$n$、各除数の合計値を最小値にマッピングできます。$n$それがそれを生み出すのです。 前処理の後、各クエリへの応答は単純な辞書検索になります。$O(1)$時間。 

ブルートフォース手法が機能するのは、コンピューティングが$d(n)$簡単ですが、次の場合に失敗します。$n$は大きく、複数のクエリでは繰り返し計算が必要です。 という観察$d(n)$すべてについて計算できます$n$複数を使用すると、問題が高速な前処理ステップに軽減され、数千のクエリに迅速に答えることが可能になります。

 ## アルゴリズムのチュートリアル

 1. 最大値を定義する$N = 10^7$入力がないので$c$この値を超えています。 配列を初期化する$d$サイズの$N + 1$それぞれの約数の和を保存します$n$。 
2. 反復する$i$1から$N$。 それぞれについて$i$、複数回繰り返します$j = i, 2i, 3i, \dots, N$、と追加します$i$に$d[j]$。 これは、次の値までのすべての数値の除数の和関数を計算します。$N$効率的に。 
3. 辞書の初期化$answer$可能な各除数の合計値を最小値にマッピングします。$n$それを生産している。 のために$n$1から$N$、 もし$d[n]$まだ入っていない$answer$、 店$answer[d[n]] = n$。 これにより、最小限のことが保証されます$n$が記録されています。 
4. 各クエリについて$c$、どうかを確認してください$c$に存在します$answer$。 存在する場合は出力します$answer[c]$; それ以外の場合は出力$-1$。 

なぜ機能するのか: ふるいのような蓄積が保証される$d[n]$すべての場合に正しく計算されます$n$まで$10^7$。 各除数の合計値の最初の出現を保存することにより、最小値が保証されます。$n$その合計は保存されます。 考えられるすべての合計が事前に計算され、正しくマッピングされるため、クエリで間違った答えが生成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_C = 10**7
d = [0] * (MAX_C + 1)
for i in range(1, MAX_C + 1):
    for j in range(i, MAX_C + 1, i):
        d[j] += i

answer = {}
for n in range(1, MAX_C + 1):
    if d[n] not in answer:
        answer[d[n]] = n

t = int(input())
for _ in range(t):
    c = int(input())
    print(answer.get(c, -1))
```最初のブロックは、ふるいを使用してすべての約数の和を計算します。 2 番目のブロックでは、最小値が確実に保存されます。$n$それぞれの合計に対して。 最後に、クエリは辞書検索を使用して一定時間内に応答されます。 微妙な点が繰り返されています$n$1から$N$マッピング用。 順序を逆にすると、「最小値」が破られてしまいます。$n$「保証します。
