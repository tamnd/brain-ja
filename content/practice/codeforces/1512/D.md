 ## 解決策
 ## 問題の理解

 非常に特殊な方法で「改ざん」された配列が与えられています。 もともと長さの不明な配列がありました`n`、呼んでください`a`。 この配列から、2 つの追加の数値が追加されました。1 つは、配列内のすべての要素の合計です。`a`、もう 1 つは任意の追加番号です`x`それは 1 から 10^9 の間にあります。 これら 2 つの値を追加すると、配列全体がシャッフルされ、最終的に混合された配列のみが表示されます。`b`サイズの`n + 2`。 

タスクは、有効な元の配列を復元することです。`a`長さの`n`、または、そのような配列が指定された配列を生成できなかったと判断します。`b`。 

重要な問題は、どの 2 つの要素が含まれるのかがわからないことです。`b`は「特別な」ものです。1 つは元の配列の合計で、もう 1 つは追加の数値です。 他のすべての要素は以下に属している必要があります`a`。 

制約は大きく、合計すると`n`最大 2 · 10^5 のすべてのテスト ケースにわたって。 これにより、ペアを削除したり、二次時間で繰り返し合計を再計算しようとするアプローチは除外されます。 どのソリューションも基本的に、通常はソートして 1 回のスキャンを実行するか、ハッシュを使用することによって、各テスト ケースを線形または線形に近い時間で処理する必要があります。 

「合計要素」の候補が複数存在する場合、特に合計が通常の要素の 1 つに等しい場合、微妙なエッジ ケースが発生します。 たとえば、すべての数値が小さく繰り返されている場合、間違った出現箇所を選択すると、一貫性はあるものの誤った再構築が誤って生成される可能性があります。 別の失敗例は、余分な要素の重複または誤認により、候補合計を削除した後に残った配列が必要な合計と一致しない場合に発生します。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのインデックスのペアが試行されます。`(i, j)`で`b`、治療する`b[i]`の合計として`a`そして`b[j]`追加の番号として削除するかどうかを確認します`b[i]`そして`b[j]`合計が等しい配列を残します`b[i]`。 試行ごとに、残りの要素の合計を計算し、等しいことを検証します。 

この問題では 2 つの特別な要素のみが隠されているため、これは論理的に機能します。 ただし、コストは合計の再計算と O(n^2) ペアの妥当性チェックから発生し、各チェックは O(n) であり、最悪の場合は O(n^3) となり、制限をはるかに超えています。 

重要な観察は、どの要素が追加の数値であるかを修正すると、`x`、残りの合計`n + 1`要素は、元の配列とその合計で構成されている必要があります。 その構造は、かつては`x`が固定されている場合、必要な合計を決定できます。`a`線形時間での一貫性をチェックします。 

候補の選択を体系的に処理するために配列を並べ替えます。 候補ポジションごとに処理`b[i]`として`x`、合計を計算します`S`。 残りのマルチセットには次のものが含まれている必要があります`S`その要素の一つとして。 その後、削除するかどうかの検証を試みることができます。`x`そしてその一致する合計は正確に残ります`n`合計が一致する要素。 

ソートされた構造により、候補を効率的に特定し、繰り返しの再計算を回避できます。 すべてのペアの合計を再計算する代わりに、2 つの要素を削除して算術一貫性をチェックするというプレフィックス スタイルの推論を維持します。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする`b`。 並べ替えは正確さのために厳密に必要なわけではありませんが、構造化された方法で候補について推論し、合計または追加要素である可能性が高い大きな値にすばやくアクセスできるようになります。 
2. 合計を計算します`S`すべての要素の`b`。 以来`S = sum(a) + x`、有効な再構成は、次の条件を満たさなければなりません。`x`そして`sum(a)`の要素を正確に残します`a`。 
3. 各インデックスを反復処理します。`i`、治療する`b[i]`追加番号候補としては`x`。 それぞれの選択肢について計算します`remaining_sum = S - b[i]`。 
4. 次に、残りの配列に、次のように機能できる要素が存在するかどうかを確認する必要があります。`sum(a)`。 その要素は次と等しい必要があります`remaining_sum / 2`、理由:

 もし`remaining_sum = sum(a) + x`そして私たちは削除しました`x`、残りは等しい`sum(a)`ので、削除した後`x`合計から、残りのマルチセットには次のものが含まれている必要があります。`sum(a)`元の要素は、配列内の一致する値をチェックするという一貫性条件を意味します。 

具体的には、取り外した後、`b[i]`、2番目のインデックスを見つける必要があります`j ≠ i`そのような`b[j] = remaining_sum - b[j]`、つまり`b[j] = remaining_sum / 2`。 
5. もし`remaining_sum`が奇数の場合は、整数の分割ができないため、この候補をスキップします。 
6. 偶数の場合は、値が正しいかどうかを確認します。`remaining_sum // 2`インデックスを除いて配列に存在します`i`。 そうであれば、有効な分解が見つかったことになります。 
7. 構築する`a`選択した要素を除くすべての要素を出力する`x`選択された合計要素。 

### なぜ効果があるのか

 不変条件は、マルチセットであることです。`b`常に 3 つの概念部分が正確に含まれます: 元の配列`a`、1部`sum(a)`、および 1 つの任意の値`x`。 有効な再構成では、これら 2 つの特殊な要素を正確に削除し、残りの構造と合計が一致するマルチセットを残す必要があります。 候補者を 1 人に強制することで、`x`、残りを有効な sum 要素と元の配列に分割できるかどうかを確認することに問題を集約します。 sum要素は一度一意に決まるので`x`が修正されると、チェックは 1 つの存在テストに減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        
        total = sum(b)
        b.sort()
        
        freq = {}
        for v in b:
            freq[v] = freq.get(v, 0) + 1
        
        found = False
        
        for i in range(n + 2):
            x = b[i]
            remaining = total - x
            
            if remaining % 2 != 0:
                continue
            
            target = remaining // 2
            
            freq[x] -= 1
            if freq[x] == 0:
                del freq[x]
            
            if freq.get(target, 0) > 0:
                freq[target] -= 1
                if freq[target] == 0:
                    del freq[target]
                
                # remaining elements form a valid a
                res = []
                for k, v in freq.items():
                    res.extend([k] * v)
                
                if len(res) == n:
                    print(*res)
                    found = True
                    break
                
                # rollback
                freq[target] = freq.get(target, 0) + 1
            
            # restore x
            freq[x] = freq.get(x, 0) + 1
        
        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```この実装は周波数追跡に依存しているため、2 つの要素の削除を効率的にシミュレートできます。 候補者ごとに`x`、一時的にその頻度を減らし、対応するものを削除しようとします。`target = (total - x) // 2`。 成功した場合、残りのマルチセットは正確に再構築されたものになります。`a`。 

よくある落とし穴は、合計の候補をすべての出現ではなく 1 つの出現として削除する必要があることを忘れていることです。 このため、周波数マップは慎重に変更され、試行のたびに復元されます。 

## 実用的な例

 ### 例 1

 入力:```
b = [2, 3, 7, 12, 2]
```| ステップ | 合計 | x が選択されました | 残り | ターゲット | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 26 | 2 | 24 | 12 | 2 を削除してみてください |
 | 2 | 26 | 12 | 14 | 7 | 有効な分割が見つかりました |

 いつ`x = 2`これを削除すると 24 が残りますが、これには sum 要素 12 が必要になります。12 が存在するため、両方の葉を削除すると、`[2,3,7]`、これは有効です。 

これにより、どの出現が追加の番号であるかをアルゴリズムが正しく識別していることが確認されます。

 | 時間 | テスト ケースごとに O(n log n) | ソートが優先され、ハッシュ | を使用した各候補チェックは O(1) 平均です。 
| スペース | O(n) | 周波数マップと出力ストレージ |

 合計の複雑さは許容範囲内です。`n`テスト ケース全体の処理は 2 · 10^5 で制限されるため、すべての入力を並べ替えても制限時間内であれば効率的です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            b = list(map(int, input().split()))
            total = sum(b)
            freq = defaultdict(int)
            for v in b:
                freq[v] += 1
            
            found = False
            for i in range(n + 2):
                x = b[i]
                freq[x] -= 1
                if freq[x] == 0:
                    del freq[x]
                
                rem = total - x
                if rem % 2 == 0:
                    target = rem // 2
                    if freq.get(target, 0) > 0:
                        freq[target] -= 1
                        if freq[target] == 0:
                            del freq[target]
                        if sum(k * v for k, v in freq.items()) == n * target - (target - target):
                            out.append(" ".join(map(str, sum(([k] * v for k, v in freq.items()), []))))
                            found = True
                            break
                        freq[target] = freq.get(target, 0) + 1
                
                freq[x] = freq.get(x, 0) + 1
            
            if not found:
                out.append("-1")
        return "\n".join(out)

    return solve()

## 特殊なケース

 厄介な状況の 1 つは、候補者が`x`想定される合計要素と同じ値に等しい。 重複のある配列では、1 つの出現を削除することが重要です。 頻度ベースの削除では、一度に 1 つのインスタンスのみが除外されるため、偶発的な過剰削除が防止されます。 

もう 1 つのエッジ ケースは、正解を得るために最大の要素を選択する必要がある場合に発生します。`x`なぜなら、貪欲な直感はより小さな値に偏る可能性があるからです。 このアルゴリズムは体系的にすべての候補を試行するため、順序だけでは最適な選択が明らかでない場合でも成功します。 

最後のエッジケースは、複数の有効な回答が存在する場合です。 アルゴリズムは一貫したペアを見つけるとすぐに戻るため、`(x, sum(a))`、当然のことながら、曖昧さのない 1 つの有効な再構成が出力されます。
