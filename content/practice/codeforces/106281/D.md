 ## 問題の理解

 タブレットは、セルの長方形のグリッドです。 あ`*`セルがペイントされたことを意味しますが、`.`空のままになったことを意味します。 可能な限りの`5 x 3`このグリッド内のウィンドウは 1 つの数字を表す場合があります。 数字のパターンは固定されていますが、タブレットには破損や間違いにより余分に塗装されたセルが含まれる場合があります。 ウィンドウは、その数字をペイントする必要があるすべてのセルが実際にウィンドウ内でペイントされている場合に、その数字を表します。 余分にペイントされたセルは数字を無効にしません。 

複数の数字が同じウィンドウに一致する場合は、最大の数字が採用されます。 タスクは、すべての可能な位置をチェックすることです。`5 x 3`四角形を作成し、認識されたすべての数字を追加します。 

グリッドの寸法は最大でも`100 x 100`, したがって、最大でも`(N - 4) * (M - 2)`窓。 これは十分に小さいため、すべてのウィンドウをすべての桁に対してチェックしても問題ありません。 すべてのウィンドウのセルの合計数はおおよそ次のとおりです。`100 * 100 * 10 * 15`、これはわずか数百万の単純な操作です。 ここでは、ハッシュや前処理などのより高度な方法は必要ありません。 

主なエッジ ケースは、数字が必要なペイントされたセルによってのみ定義されるという事実から生じます。 よくある間違いは、全体を要求することです。`5 x 3`ウィンドウを使用して数字を正確に一致させます。 

例えば：```
5 3
***
***
***
***
***
```答えは`9`。 必要なセルがすべて存在するため、この完全にペイントされた長方形の中にすべての数字を配置できます。そのため、最大の数字を選択する必要があります。 

もう 1 つの注意が必要なケースは、ウィンドウに選択した桁に属さない余分な星がある場合です。```
5 3
***
*.*
***
*.*
***
```正しい答えは、`0`, なぜなら、ゼロパターンには境界セルが必要であり、追加の星は害を及ぼさないからです。 全体像を数字テンプレートと正確に比較するソリューションは、それを誤って拒否することになります。 

## アプローチ

 簡単な解決策は、10 桁のテンプレートを保存し、可能な限りスキャンすることです。`5 x 3`矩形。 各四角形について、次のすべての桁をテストします。`0`に`9`。 数字をテストするには、テンプレートに星が含まれているセルを調べ、対応するタブレットのセルも星であるかどうかを確認します。 必要なセルがすべて存在する場合、その数字が候補になります。 有効な最大の数字が必要であるため、昇順に数字をスキャンして答えを上書きすると機能します。 

この強引な方法は、すでにこれらの制限に対する最適なアプローチです。 多くても`96 * 98 = 9408`窓。 各ウィンドウは 10 桁をチェックし、各桁には最大 15 個のセルがあります。 総作業量は 200 万セル チェック未満であるため、直接シミュレーションは簡単に適用できます。 

重要な点は、この問題ではタブレット全体を再構築する必要がないということです。 各ウィンドウは独立しており、有効な数字の定義は小さな固定パターンにのみ依存します。 これにより、タスクはグリッド上で繰り返される一定サイズのパターン マッチング問題に変わります。

 ## アルゴリズムのチュートリアル

 1. 10 桁の図面を次のように保存します。`5 x 3`配列。 テンプレート内の星は、対応するセルをペイントする必要があることを意味します。 
2. 可能なすべての左上隅を反復処理します。`5 x 3`矩形。 行は次から開始できます`0`に`N - 5`、列は次のようになります。`0`に`M - 3`。 
3. 現在の四角形について、以下のすべての桁を試します。`0`に`9`。 その数字のテンプレート内の星印のセルのみをチェックします。 タブレットに必要なセルが欠落している場合、この数字は表現できません。 
4. 数字が一致するたびに、それをこの四角形の現在の答えとして保存します。 数字は昇順にチェックされるため、最後に一致した数字が最大の数字になります。 
5. 選択した数字を合計に加算し、次の四角形に進みます。 

なぜ効果があるのか:

 アルゴリズムは有効な数字の定義に直接従います。 必要なペイントされたセルがすべて存在する場合、数字は正確に受け入れられます。 アルゴリズムは必要なすべてのセルをチェックし、1 つでも欠けている場合はその数字を拒否します。 タブレットのルールに従って、余分な星は無視されます。 考えられるすべての長方形が訪問されるため、最終合計への寄与はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    digits = [
        ["***",
         "*.*",
         "*.*",
         "*.*",
         "***"],
        ["..*",
         "..*",
         "..*",
         "..*",
         "..*"],
        ["***",
         "..*",
         "***",
         "*..",
         "***"],
        ["***",
         "..*",
         "***",
         "..*",
         "***"],
        ["*.*",
         "*.*",
         "***",
         "..*",
         "..*"],
        ["***",
         "*..",
         "***",
         "..*",
         "***"],
        ["***",
         "*..",
         "***",
         "*.*",
         "***"],
        ["***",
         "..*",
         "..*",
         "..*",
         "..*"],
        ["***",
         "*.*",
         "***",
         "*.*",
         "***"],
        ["***",
         "*.*",
         "***",
         "..*",
         "***"]
    ]

    ans = 0

    for i in range(n - 4):
        for j in range(m - 2):
            best = -1
            for d in range(10):
                ok = True
                for x in range(5):
                    for y in range(3):
                        if digits[d][x][y] == '*' and grid[i + x][j + y] != '*':
                            ok = False
                            break
                    if not ok:
                        break
                if ok:
                    best = d
            if best != -1:
                ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```数字のパターンは、必要なペイントされたセルとまったく同じようにエンコードされます。 テンプレート内のドットであるセルは、それらのセルに余分な星が含まれていても有効な数字を生成する可能性があるため、アルゴリズムは決してチェックしません。 

ループが終わる`i`そして`j`～によって慎重に制限されています`n - 4`そして`m - 2`。 これにより、グリッドの外側の行や列にアクセスできなくなります。 内側のループは現在のウィンドウの 5 行 3 列をチェックするため、1 つ違いの間違いを引き起こす可能性のある座標変換はありません。 

変数`best`から始まります`-1`ウィンドウには数字が含まれていない可能性があるためです。 数字が一致すると、前の値が置き換えられ、最終的に保存された値が一致する最大の数字であることが保証されます。
