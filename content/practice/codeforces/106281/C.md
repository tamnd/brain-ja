 ## 問題の理解

 この課題は、限られた量の生地といくつかの限られた詰め物から最も収益性の高いバンズのコレクションを作成することです。 バンズには、利用可能な詰め物の 1 つが含まれることも、何も詰め物が含まれないこともあります。 各詰めパンは生地と 1 種類の詰め物の固定量を消費し、一定の金額を与えます。 プレーンなパンは生地を消費するだけで、一定の利益が得られます。 目標は、合計の利益が最大になるように、各種類のパンを何個焼くかを決定することです。 元の問題は Codeforces 106C「バンズ」です。 

入力により、生地の総量、詰め物の種類の数、およびプレーン バンズのレシピが得られます。 それぞれの詰め物の種類は、その詰め物がどれだけ存在するか、1 つのパンに必要な詰め物の量、そのパンに必要な生地の量、そしてそれがどれだけの収益を得るかを記述します。 出力は、バンズの最適な組み合わせを選択した後に獲得できる最大の金額です。 

生地の制限は最大でも1000グラムですが、詰め物の種類は少ないです。 詰め物の選択肢の数に指数関数的に依存するソリューションは必要ありませんが、生地の量に対する動的プログラミング ソリューションは実用的です。 約 1000 個の値の状態空間は小さいため、すべての詰め物の種類を試し、考えられるすべての生地の使用法を更新する余裕があります。 詰め込みタイプの数が少ないため、境界付きナップサック手法を使用して各タイプを個別に処理することもできます。 

難しいのは、詰める量が限られていることです。 すべての詰め物の種類を無制限のアイテムとして扱うと、不可能な解決策が黙って作成される可能性があります。 たとえば、次の入力を使用します。```
10 1 5 1
3 2 2 100
```正しい出力は次のとおりです。```
301
```最良の選択は、6 つの生地と 3 つの詰め物すべてを使用して 3 つの詰めパンを作り、次に残りの生地を使ってプレーン バンを 1 つ作ることです。 不用意に無制限のナップサックを実装すると、たとえ詰め物が存在しない場合でも、詰め物をしたパンを 5 個作り、さらに大きな利益を得る可能性があります。 

残りの生地が別の詰めパンを作るのに十分ではないが、それでもプレーンなパンを作ることができる場合、別のエッジケースが発生します。 例えば：```
10 1 3 7
2 10 6 100
```正しい出力は次のとおりです。```
21
```たとえ1つの詰め物パンでも利用可能な以上の生地を消費するため、詰め物は役に立ちません。 正解すると、プレーンなパンが 3 つできます。 詰めたパンのみを考慮し、未使用の生地の処理を忘れたソリューションでは、誤ってゼロが返されます。 

最後の境界例は、考えられるすべての詰め物の選択肢が普通のバンズよりも悪い場合です。 例えば：```
20 1 5 10
100 5 20 1
```正しい出力は次のとおりです。```
40
```それぞれの饅頭は非常に採算が合わないため、入手可能な餡の量はあまり関係ありません。 アルゴリズムは、詰められたパンが常に優れていると仮定するのではなく、すべての選択肢を比較する必要があります。 

## アプローチ

 直接的なアプローチは、私たちが焼くあらゆる種類の詰め物のバンズの数を数えることです。 1 つの詰め物の種類について、十分な供給量がある場合、`k`バンズ、すべての値を試すことができます`k`そして再帰的に次のタイプを続行します。 これが機能するのは、詰められたバンズのあらゆる組み合わせが考慮され、残りの生地はプレーンなバンズに使用できるからです。 

問題は組み合わせの数です。 詰め物のタイプは最大 10 種類あり、各タイプは潜在的に何度も使用できます。 生地が 1000 に制限されている場合でも、単純な再帰検索では大きく分岐する可能性があります。 すべてのスタッフィング タイプで約 100 個の選択肢が許可される場合、検索ツリーはほぼ 100 個に達する可能性があります。`100^10`これはコンテストの制限時間の許容範囲をはるかに超えています。 

重要な観察点は、異なる種類の詰め物間で共有される唯一のリソースは生地であるということです。 使用済み生地が一定量に達した経緯を正確に記憶する必要はありません。 2 つの異なる選択肢が両方とも同じ量の生地を使用する場合、より収益性の高い方のみが重要になります。 これはまさにナップザック動的プログラミングの背後にある特性です。 

詰め物の種類ごとに、一定の数の同一のアイテムがあります。 二値分解を使用して、その制限された量をいくつかのグループに変換できます。 たとえば、13 個のパンの供給は、サイズ 1、2、4、および 6 のグループになります。これらのグループは、一度にその数のパンを摂取することを表します。 分割後、問題は生地の上の標準的な 0/1 ナップザックになります。 

ブルート フォースが機能するのは、考えられるすべてのスタッフィング カウントを調査するためです。 最適なソリューションは、これらの可能性を、生地の量ごとに達成可能な最高の利益に圧縮します。 すべての詰め物を処理した後、残りの生地はプレーンバンズに最適に変換されます。

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング配列を作成します。`dp[x]`正確に使用した後に達成可能な最大の利益を保存します`x`詰めパン用の生地のグラム数。 当初は、`dp[0]`利益ゼロでも可能です。 
2. 各詰め物の種類を個別に処理します。 この詰め物から作ることができるバンズの最大数を計算してください。 利用可能な詰め物と利用可能な生地の両方によって制限されます。 
3. この最大数量をバイナリ グループに分割します。 各グループは、この詰め物のバンズを一定数取り、消費します。`count * dough_cost`生地と稼ぎ`count * value`お金。 この変換では、可能なすべての量を維持しながら、遷移の数を少なく保ちます。 
4. 生成されたグループごとに、生地の量に対して逆ナップザック更新を実行します。 逆方向では、同じグループを複数回使用することができません。 
5. すべての種類の詰め物が処理された後、すでに詰め物バンズに使用されている生地の量をすべて検査します。 残った生地でプレーンバンズを作った利益を加えて、最大限の結果を維持します。 

これが機能する理由は、グループが処理されるたびに、`dp[x]`正確に使用する加工済み詰め物グループのすべての選択肢の中で、可能な限り最高の利益が含まれています。`x`生地。 各バイナリ グループは 1 回考慮されるため、不変式は標準の 0/1 ナップザック遷移によって保存されます。 最後に、考えられるすべての詰めパンの組み合わせが表現され、残った生地はプレーンバンを使用して個別に最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    items = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        max_count = min(a // b, n // c)

        k = 1
        while max_count > 0:
            take = min(k, max_count)
            items.append((take * c, take * d))
            max_count -= take
            k <<= 1

    dp = [-1] * (n + 1)
    dp[0] = 0

    for cost, value in items:
        for dough in range(n, cost - 1, -1):
            if dp[dough - cost] != -1:
                dp[dough] = max(dp[dough], dp[dough - cost] + value)

    ans = 0
    for used in range(n + 1):
        if dp[used] != -1:
            plain = ((n - used) // c0) * d0
            ans = max(ans, dp[used] + plain)

    print(ans)

if __name__ == "__main__":
    solve()
```入力セクションはまず、すべてのスタッフィング タイプを、境界のあるナップザック アイテムのコレクションに変換します。 詰め込みタイプでは供給が許容する量を超えるバンズを生産することはできず、生地の制限を超える量のバンズを生産することもできないため、数量の計算では両方の制約が使用されます。 

バイナリ分解ループは、限られた数の同一のパンを処理する部分です。 生成されたグループには、すべてのカウントを個別に試行する場合と同じ選択肢がありますが、ナップザック遷移の数が減ります。 

動的プログラミングの更新では、大きな値から小さな値まで生地を反復します。 生成された各グループは最大 1 回しか選択できないため、この方向が必要です。 順方向に反復すると、1 つの遷移で同じグループを複数回再利用できます。 

最後のループでは、プレーンのパンを個別に処理します。 個数に制限がないため、プレーンのパンはナップザックには入れません。 詰めパンにどれだけの生地が費やされたかが分かれば、残りの生地が常に直接的な最良の答えを導き出します。

## テストケース```python
import sys
import io

def solve_data(data: str) -> str:
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n, m, c0, d0 = map(int, input().split())

    items = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        cnt = min(a // b, n // c)
        p = 1
        while cnt:
            take = min(p, cnt)
            items.append((take * c, take * d))
            cnt -= take
            p *= 2

    dp = [-1] * (n + 1)
    dp[0] = 0

    for c, d in items:
        for x in range(n, c - 1, -1):
            if dp[x - c] != -1:
                dp[x] = max(dp[x], dp[x - c] + d)

    ans = 0
    for x in range(n + 1):
        if dp[x] != -1:
            ans = max(ans, dp[x] + ((n - x) // c0) * d0)

    return str(ans)
