 ## 問題の理解

 3 種類の文字を含む括弧文字列が与えられます。`'('`、`')'`、 そして`'?'`。 毎`'?'`最終的には開き括弧または閉じ括弧のいずれかになる必要があります。 未知の位置ごとに、入力により 2 つのコストが提供されます。1 つはそれを次の値に置き換えるコストです。`'('`そしてそれを置き換えるためのもの`')'`。 

目標は、有効な通常のブラケット シーケンスを生成することだけではなく、すべての有効な選択肢の中で最も安価なものを生成することです。 

通常の括弧シーケンスには 2 つのプロパティがあります。 左括弧と右括弧の合計数は一致する必要があり、すべての接頭辞には少なくとも同じ数が含まれている必要があります。`'('`として`')'`。 2 番目の条件は難しいものです。 のような文字列`"())("`カウントは同じですが、プレフィックスが次のとおりであるため、依然として無効です`"())"`すでにマイナスになっています。 

文字列の長さは最大でも`5 * 10^4`、指数関数的なものはすぐに除外されます。 あれば`k`疑問符がある場合は、ブルートフォースが試みられます`2^k`課題。 未知数がわずか 40 個であっても、すでに約 1 兆個の可能性があります。 線形に近いものが必要です。`O(n log n)`。 

コスト値は次のように大きくなります。`10^6`したがって、最終的な答えは 32 ビット整数の範囲を超える可能性があります。 Python ではこれは自動的に行われますが、他の言語では 64 ビット整数が必要です。 

いくつかの特殊なケースにより、この問題は微妙になります。 

すべてのケースで貪欲に安いブラケットを選択するとします。`'?'`。

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 あらゆる人にとって`'?'`、両方の可能性を再帰的に試してください。 完全なシーケンスを構築した後、それが規則的であるかどうかを確認し、規則的である場合は総コストを計算します。 すべての有効なシーケンスのうち、最小限のものを維持してください。 

これは、固定割り当てでは原理的に問題のサイズが小さいため機能します。 有効性チェックは線形であり、コスト計算も線形です。 問題は課題の数です。 と`k`未知のポジションもある`2^k`可能性。 最悪の場合`k = 50000`、それはまったく不可能です。 

通常のブラケットシーケンスの構造を活用する必要があります。 

重要な観察は、有効性がプレフィックスのバランスに依存するということです。 現在の残高がマイナスになるたびに、これまでどこかで閉じ括弧を多用しすぎていたことがわかります。 そのプレフィックスを修復する唯一の方法は、以前に選択したプレフィックスの 1 つを変更することです。`')'`括弧に入れる`'('`。 

これは貪欲なフレームワークを示唆しています。 

最初はすべてのふりをします`'?'`は`')'`。 これでベースラインコストが得られます。`')'`費用`b_i`。 

後でその位置を実際に次のようにする必要があると判断した場合`'('`の場合、追加コストは次のようになります。$$a_i - b_i$$この値は、そのポジションを「アップグレード」するのにどれだけコストがかかるかを表します。`')'`に`'('`。 

現在のバランスを維持しながら、文字列を左から右にスキャンします。 

私たちが何かに遭遇するたびに、`'?'`、一時的に次のように扱います。`')'`、終了コストを追加し、アップグレード コストを優先キューに保存します。 

残高がマイナスになった場合は、直ちにプレフィックスを修復する必要があります。 前述のすべての疑問符の中で、追加コストが最も小さいものを反転する必要があります。 修理するたびに残高がちょうど 2 増えるため、この貪欲な選択が最適です。そのため、利用可能な最も安価な修理を常に必要とします。 

これにより、問題がヒープを使用した局所的な修正の繰り返しに変換され、`O(n log n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k · n) | O(k) | 遅すぎる |

### なぜ効果があるのか

 不変条件は、各プレフィックスを処理した後、プレフィックスを有効に保つためにすべての割り当ての中で可能な最小限のコストを維持することです。 

残高がマイナスになるたびに、以前の疑問符を次のように変換する必要があります。`'('`。 このような変換はすべて、残高をまったく同じ金額で修正します。`+2`。 すべての修理は同等に強力であるため、問題となるのはコストだけです。 最小のアップグレード コストを選択することが常に最適です。 

このアルゴリズムにより、必要な修復が遅れることはありません。 接頭辞にすでに左括弧よりも閉じ括弧が多い場合、将来の文字はその接頭辞を修復できません。 修正は、以前に表示された疑問符を使用して直ちに行う必要があります。 

すべての修復が最適に選択され、必要なときに正確に実行されるため、最終的なシーケンスの総コストは最小限になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    s = list(input().strip())

    q_data = []
    for ch in s:
        if ch == '?':
            a, b = map(int, input().split())
            q_data.append((a, b))

    ptr = 0
    balance = 0
    total_cost = 0

    heap = []

    for i in range(len(s)):
        if s[i] == '(':
            balance += 1

        elif s[i] == ')':
            balance -= 1

        else:
            a, b = q_data[ptr]
            ptr += 1

            s[i] = ')'
            total_cost += b
            balance -= 1

            extra = a - b
            heapq.heappush(heap, (extra, i))

        if balance < 0:
            if not heap:
                print(-1)
                return

            extra, pos = heapq.heappop(heap)

            s[pos] = '('
            total_cost += extra
            balance += 2

    if balance != 0:
        print(-1)
        return

    print(total_cost)
    print(''.join(s))

solve()
```このソリューションは、文字列を左から右に 1 回だけ処理します。 すべての未知の括弧は、最初は次のように想定されます。`')'`これにより、単純なベースライン構成が作成されるためです。 ヒープには、後で変換する資格のあるすべてのポジションが保存されます。`'('`。 

最もデリケートな部分はバランスの修復ステップです。 残高がマイナスになると、ヒープから最も安価なアップグレードを直ちにポップします。 そのアップグレードは 1 つ前に変更されます`')'`の中へ`'('`、残高が 2 増加します。これがありません`+2`調整はよくある間違いです。 

もう 1 つの微妙な詳細は、括弧を反転するときに文字列リスト内の文字を上書きすることです。 この更新がなければ、印刷されたシーケンスは計算されたコストと一致しません。 

すべてのプレフィックスが有効なままだったとしても、最終的な残高チェックが必要です。 例えば、`"((("`負になることはありませんが、それでも規則的なシーケンスではありません。 

ヒープストア`(extra_cost, position)`そのため、最小の追加コストが常に最初に選択されます。 パイソンの`heapq`当然この順序をサポートします。
