 **タグ:** 貪欲な最短パス
 **解決時間:** 4 分 37 秒

 ## 問題の理解

 標準的な 8 × 8 ボード上でチェスのキングをあるマスから別のマスに最小の手数で移動するように求められます。 キングは、垂直、水平、斜めの 8 つの方向に隣接するマスに移動できます。 入力では、標準のチェスの記法を使用して開始マスとターゲットマスを指定します。最初の文字はからの文字です。`a`に`h`列を表し、2 番目の文字は次の数字です。`1`に`8`行を表します。 出力は、最小の手数と、それに続く最小手数を達成する一連の動きである必要があります。 

主な制約は、ボードのサイズが小さい (8×8) ことと、キングの移動の自由です。 ボードが小さいため、正方形の数が 2 次または 3 次のアルゴリズムでも十分に高速です。 各移動はいずれかの軸または両方の軸で位置を 1 つ変えるだけなので、任意の方向の最大距離は 7 であることがわかります。エッジ ケースには、開始正方形と終了正方形が同じ場合、移動が厳密に水平または垂直である場合、および移動が完全に斜めである場合が含まれます。 不用意に実装するとオーバーシュートしたり、余分な移動が発生したりする可能性があるため、オフバイワン エラーを発生させずにこれらのケースを処理することが重要です。 

## アプローチ

 強引なアプローチは、チェス盤をグリッドとしてモデル化し、開始マスから BFS などの最短パス アルゴリズムを実行することです。 BFS は、ターゲットに到達するまで、考えられるすべてのキングの動きを層ごとに探索し、最小限の動きの数を保証します。 8×8 ボードには 64 個の正方形があり、それぞれに最大 8 個の隣接する正方形があり、最大 512 個のエッジが与えられます。 BFS では O(64 + 512) の操作が必要になりますが、これは無視できる程度です。 これは正しいですが、この問題にはやりすぎです。 BFS では、訪問した状態を追跡し、パスを再構築する必要があるため、コードが複雑になります。 

重要な洞察は、王の動きが斜めのショートカットを可能にするということです。 移動数を最小限に抑えるには、各ステップでできるだけターゲットに向かって斜めに移動する必要があります。これは、斜めに移動すると水平距離と垂直距離の両方が同時に減少するためです。 軸の 1 つがターゲットと一致する場合にのみ、残りの軸に厳密に沿って移動する必要があります。 最小移動数は、水平距離または垂直距離の大きい方です。これは、斜めに移動するたびに両方の距離が 1 ずつ減少するためです。これは貪欲なアプローチです。各ステップで、どちらかの座標がターゲットに一致するまで両方の座標を減少させる移動を実行し、残りの軸に沿って終了します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | BFS / ブルートフォース | お(64) | お(64) | 正しいが不必要に複雑 |
 | 貪欲な対角線 | O(Δx + Δy) | お(1) | 受け入れられる、最も単純な |

 ## アルゴリズムのチュートリアル

 1. 開始座標とターゲット座標をチェス記法から数値座標に変換します。 地図`a`-`h`列の場合は 1 ～ 8、`'1'`-`'8'`行の整数に変換します。 これにより、算術演算で距離を計算できるようになります。 
2. 水平方向の差を計算します`dx`として`target_x - start_x`そして高低差`dy`として`target_y - start_y`。 これらは、王が各軸に沿ってどのくらいの距離とどの方向に移動する必要があるかを示します。 
3. 両方とも`dx`そして`dy`ゼロ以外の場合は、斜めに移動します。 もし`dx > 0`そして`dy > 0`、右上に移動 (`RU`)、両方を減少させます`dx`そして`dy`1. の符号に基づいて 4 つの斜め方向をすべて処理します。`dx`そして`dy`。 
4. 一方の軸がゼロに達したら、もう一方の軸に沿って移動を続けます。 もし`dx != 0`まで左または右に移動します。`dx`ゼロに達します。 もし`dy != 0`まで上下に移動します。`dy`ゼロに達します。 
5. 各動きを順番に記録します。 合計移動数は、初期値の絶対値の最大値に等しくなります。`dx`そして`dy`。 

機能する理由: 斜めに移動するたびに、水平方向と垂直方向の距離が 1 ずつ減少します。斜め方向に移動すると軸が 1 つ残る場合があり、それに沿って 1 ステップずつ移動することで、斜め方向のショートカットが不可能なため、最小限の移動が保証されます。 このアルゴリズムは貪欲ですが最適です。なぜなら、王の手が設定されている場合、各移動が可能な限り最速の方法で残りのマンハッタンの距離を短縮するからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def chess_king_path():
    start = input().strip()
    target = input().strip()
    
    x1 = ord(start[0]) - ord('a') + 1
    y1 = int(start[1])
    
    x2 = ord(target[0]) - ord('a') + 1
    y2 = int(target[1])
    
    dx = x2 - x1
    dy = y2 - y1
    
    moves = []
    
    while dx != 0 or dy != 0:
        move = ""
        if dy > 0:
            move += "U"
            dy -= 1
        elif dy < 0:
            move += "D"
            dy += 1
        
        if dx > 0:
            move += "R"
            dx -= 1
        elif dx < 0:
            move += "L"
            dx += 1
        
        moves.append(move)
    
    print(len(moves))
    for m in moves:
        print(m)

chess_king_path()
```このコードは、チェスの記法を数値座標に変換することから始まります。 次に、ターゲットに向かって貪欲な斜めまたは直線の動きを繰り返し選択し、それぞれの動きをリストに追加します。 while ループは両方の値が得られるまで継続します。`dx`そして`dy`ゼロに達します。 開始とターゲットが等しいというエッジ ケースは、ループが実行されず、ゼロ手も出力されるため、自然に処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(Δx + Δy) | 移動するたびに、少なくとも 1 つの軸が 1 ずつ減少します。 最大は 1 軸あたり 7 移動です |

 ## 特殊なケース

 スタートがターゲットと等しい場合、dx と dy はゼロになります。 ループは決して実行されず、0 の移動を出力します。 たとえば、1 軸のみの移動の場合、`a1`に`a8`、斜めの移動は不可能であるため、アルゴリズムは厳密に垂直軸に沿って移動します。 これはキングの法的な動きと一致し、最小限の動きを生み出します。 同様に、ターゲットが斜めに配置されている場合、アルゴリズムは dx と dy の両方を同時に減少させるため、オーバーシュートすることはありません。 各ステップはターゲットに向かって正確に 1 または 2 単位ずつ減少し、すべてのエッジ シナリオでの正確性が保証されます。
