 ## 問題の理解

 私たちには最大の木が与えられています$n$頂点。各頂点は星を表します。 ツリーは入力構造によって暗黙的にルート化されますが、概念的には、次のように定義された単なる無向ツリーです。$n-1$エッジ。 

それぞれの星について、ムーはそれを観察中心として選択します。 この中心から半径を考慮します$d$つまり、中心からの木の距離が最大で 100 メートル以内のすべてのノードを観察できることになります。$d$。 したがって、それぞれについて$d$では、選択したルートの周りに成長するボールが表示されます。 

各星には一連の「フィルター」もあります。 各フィルターは単一ノードに適用される値であり、フィルターを適用することは、そのノード上で選択されたすべてのフィルター値のビット単位の XOR をとることに対応します。 フィルタを任意の順序で適用し、同一のフィルタを再利用できるため、効率的に各ノードが$i$値の複数のセットがあり、ノードで達成可能な値を意味する任意のサブセットを選択できます。$i$はすべてそのマルチセットのサブセット XOR です。 

中心と半径が固定の場合$d$、Mu は距離内のすべてのノードを観察します$d$であり、その共通の値を最大化しながら、すべての観察されたノードに同等の可視性を持たせたいと考えています。 各ノードはローカル マルチセットから任意の XOR サブセットを独立して選択できるため、制約は次のようになります。単一の値を選択する$x$ボール内のすべてのノードが実現できるように$x$そのフィルターを使用して。 つまり、$x$すべてのノードの到達可能な XOR セットの共通部分に属している必要があり、そのような最大値が必要です$x$。 

各中心ノードについて$c$、 定義する$f(d)$距離内のノード間で可能な最大の共通 XOR 値として$d$。 計算しなければなりません$$\sum_{d=0}^{n-1} f(d)$$考えられるすべての中心ノードに対して。 

木には最大で$5 \cdot 10^4$ノードはありますが、フィルターの総数は最大です。$2 \cdot 10^6$, そのためフィルター処理が重いです。 これは、ノードと半径に対するクエリごとの再計算が不可能であることをすでに示唆しています。 

素朴なアプローチでは、すべての中心とすべての半径について、ボール内のすべてのノードの線形基底の交点が再計算されます。 たとえ XOR ベースを維持したとしても、ボールを繰り返し再計算すると、$O(n^2)$または、限界をはるかに超えたさらに悪い行動。 

単一ノードに多数のフィルターが存在する場合、微妙なエッジ ケースが発生します。 たとえば、1 つのノードにすべてのフィルターがあり、他のノードにはフィルターがない場合、そのノードが半径に入ると交差はすぐに縮小します。 ノードの局所性を考慮せずにフィルターをグローバルに扱うアプローチは過大評価になります。$f(d)$。 

## アプローチ

 主な困難は、各ノードが XOR 値の線形基底に寄与しており、動的に成長するツリー ボール上の基底の交差が必要であることです。 XOR 部分空間の直接交差は、単純な集約では安定しません。これは、線形スパンの交差が単にジェネレーターの交差のスパンではないためです。 

強引なアイデアは次のようになります。各中心と各半径について、ボール内のすべてのノードを収集し、ノードごとに線形基底を構築し、64 次元の GF(2) に対するブルート ガウス消去法によってこれらすべての基底の交差を計算します。 基底サイズが 64 で制限されている場合でも、すべての半径に対してこれを行うと、$O(n^2 \cdot 64^2)$最悪の場合、それは完全に不可能です。 

構造的なブレークスルーは、問題を逆に再解釈することです。 半径を拡大して交差点を再計算する代わりに、半径が大きくなるにつれて候補 XOR 値が無効になるタイミングを追跡します。 値$x$半径に対しては実現可能です$d$距離内のすべてのノードがそうである場合に限り$d$生産できる$x$、これは、そのボールにノードが含まれていないと言うのと同じです。$x$。 

各ノードの到達可能な XOR 値のセットは、次の線形部分空間です。$\{0,1\}^{64}$。 このような各部分空間は、線形基底によって表すことができます。 値$x$ノードに対して有効です$u$それがその基底の範囲内にあるかどうかは、ガウス消去法によってチェックできます。 

ここで視点を反転します。ノード間の交差を維持する代わりに、ノードごとに維持します。$u$それが課す一連の制約$x$そして、固定中心の場合、グローバル交差が可能な最大の XOR を達成するビット パターンを失う前に、BFS のようなボールをどれだけ長く成長させることができるかを知りたいと考えています。 

これにより、距離が増加するノードからの制約によって 64 次元空間内の候補が排除される場合に、問題が追跡に変換されます。 重要な観察は、答えは次のとおりです。$f(d)$中心は単調非増加です$d$、新しく含まれたノードが現在の最適な XOR 候補を削除した場合にのみ変更されます。 これは、ノードを距離の増加順に処理し、制約のグローバルな線形基礎を維持できることを示唆しています。 

複数の中心をサポートするために、各ノードをルートとするツリーを再解釈し、距離順序を暗黙的に維持しながらサブツリーの線形ベースを集約するセントロイド スタイルまたは再ルート DP を実行します。 各ノードは距離の重みを使用してその基底を先祖に提供し、距離の順序で基底マージを蓄積するツリー トラバーサルを使用して寄与を処理します。 

最後のアイデアは、距離順にノード ベースを徐々に挿入し、挿入されたすべてのベースと一致する最大 XOR 値を追跡する構造を各センターに対して維持することです。 基底は最大 64 ベクトルであるため、マージは次のようになります。$O(64^2)$、各ノードはツリー分解を介してそのようなマージの対数に参加し、全体的に実現可能な複雑さをもたらします。

 ## アルゴリズムのチュートリアル

 私たちは、すべてのノードのフィルターが 64 ビットの線形基底を定義し、すべての制約がサブツリーの距離を介して伝播するという事実に依存しています。 

まず、フィルターから各ノードの線形基底を個別に計算し、そのマルチセットを標準の XOR 基底に縮小します。 

次に、重心分解を使用してツリーを分解し、重心からコンポーネント内のノードまでの距離が適切に構造化されるようにします。 各重心について、現在の半径内のすべてのノード ベースの交差を維持しながら、半径を 0 から外側に拡張することをシミュレートします。 

各重心で、コンポーネント内のすべてのノードと重心までの距離を収集します。 これらのノードを距離によって並べ替えます。$f(d)$新しい距離レイヤーが含まれる場合にのみ変更されます。 

次に、距離が増加する順にノードを処理します。 

新しいノードごとに$u$、その基底を、重心に対して維持されているグローバル基底にマージします。 各挿入の後、現在の交差基準で達成可能な最大 XOR 値を再計算します。 これは、維持されたベースに対して標準的な貪欲な XOR 構築を使用して行われます。 

この重心の配列を維持します。インデックス$d$最大の距離を持つすべてのノードを含めた後の現在の最良の値を保存します$d$。 次に、これらの値の寄与を累積して重心の最終的な答えを求めます。 

最後に、各ノードは重心として機能するのは 1 回だけであるため、$O(\log n)$重心レベルでは、各距離レベルでノードを使用するセンターの数によって重み付けされた各ノードの寄与を加算し、結果を組み合わせてセンターごとの最終的な答えを求めます。 

### なぜ効果があるのか

 重心分解により、ツリー内のすべてのパスが対数的に多くのコンポーネントに分割されるため、ノードの各ペアは一緒にのみ考慮されます。$O(\log n)$回。 各重心コンポーネント内では、ノードは厳密な距離順に処理され、その重心の周りの半径の拡大と正確に一致します。 XOR の実現可能性は線形基底によって完全に把握されるため、基底をマージすると制約の交差部分の正確さが維持されます。 維持された基底から最大 XOR を貪欲に再構築すると、常に最大有効値が生成されるため、それぞれの$f(d)$は重心レベルの寄与ごとに 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class XorBasis:
    def __init__(self):
        self.b = [0] * 64

    def add(self, x):
        for i in range(63, -1, -1):
            if not (x >> i) & 1:
                continue
            if self.b[i]:
                x ^= self.b[i]
            else:
                self.b[i] = x
                return

    def merge(self, other):
        for v in other.b:
            if v:
                self.add(v)

    def max_xor(self):
        res = 0
        for i in range(63, -1, -1):
            if (res ^ self.b[i]) > res:
                res ^= self.b[i]
        return res

def build_basis(values):
    xb = XorBasis()
    for v in values:
        xb.add(v)
    return xb

def main():
    n = int(input())
    p = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for i, par in enumerate(p, start=1):
        g[par - 1].append(i)
        g[i].append(par - 1)

    node_basis = []
    for i in range(n):
        mi = list(map(int, input().split()))
        k = mi[0]
        vals = mi[1:]
        node_basis.append(build_basis(vals))

    sys.setrecursionlimit(10**7)

    ans = [0] * n

    visited = [False] * n
    sub = [0] * n

    def dfs_size(u, p):
        sub[u] = 1
        for v in g[u]:
            if v != p and not visited[v]:
                dfs_size(v, u)
                sub[u] += sub[v]

    def dfs_centroid(u, p, nsz):
        for v in g[u]:
            if v != p and not visited[v] and sub[v] > nsz // 2:
                return dfs_centroid(v, u, nsz)
        return u

    def collect(u, p, d, arr):
        arr.append((u, d))
        for v in g[u]:
            if v != p and not visited[v]:
                collect(v, u, d + 1, arr)

    def process(center):
        nodes = []
        collect(center, -1, 0, nodes)
        nodes.sort(key=lambda x: x[1])

        cur = XorBasis()
        i = 0
        maxd = 0

        while i < len(nodes):
            d = nodes[i][1]
            while i < len(nodes) and nodes[i][1] == d:
                u = nodes[i][0]
                cur.merge(node_basis[u])
                i += 1
            ans[center] += cur.max_xor()

    def decompose(u):
        dfs_size(u, -1)
        c = dfs_centroid(u, -1, sub[u])
        visited[c] = True
        process(c)
        for v in g[c]:
            if not visited[v]:
                decompose(v)

    decompose(0)

    for x in ans:
        print(x % (1 << 64))

if __name__ == "__main__":
    main()
```この実装では、フィルターから各ノードの線形 XOR ベースを構築し、ツリーに対して重心分解を実行します。 重心ごとに、そのコンポーネント内のすべてのノードを収集し、その重心までの距離によって並べ替えます。 その後、半径が大きくなるにつれてそれらの基底を段階的にマージし、貪欲な基底削減を使用して現在の最大 XOR 値を維持します。 各重心は、すべての半径にわたる合計をその回答バケットに直接提供します。 

重心分解には注意が必要です。訪問した重心をマークしなかったり、サブツリーのサイズを誤って計算したりすると、指数関数的再帰が発生します。 もう 1 つの微妙な点は、XOR 基底マージでは独立性を保持する必要があり、挿入順序は基底の正確性を超えた可換性を想定してはいけないことです。 

## 実用的な例

 チェーン 1-2-3 内の 3 つのノードからなる小さなツリーを考えてみましょう。 ノード 1 にフィルター {1}、ノード 2 にフィルター {2}、ノード 3 にフィルター {1,2} があるとします。 基本は単純です。ノード 1 は {0,1} を生成でき、ノード 2 は {0,2} を生成でき、ノード 3 はフルスペース {0,1,2,3} を生成できます。 

中心 2 については、半径を拡大します。 

| ステップ | 含まれるノード | 現在の基準 | max_xor |
 | --- | --- | --- | --- |
 | d = 0 | {2} | {0,2} | 2 |
 | d = 1 | {1,2,3} | フルスパン | 3 |

 これは、ノードを追加するとスパンがどのように増加し、最大 XOR が増加する可能性があるかを示しています。 

ここで、中心にフィルターがなく、すべての葉に互いに素な単一ビット フィルターがある星を考えてみましょう。 半径 0 では、中心のみが寄与し、答えは 0 になります。半径 1 では、中心はゼロ以外の値を生成できないため、すべての葉が含まれ、交差は 0 のみに折りたたまれます。 これは、ノードを追加すると実現可能性が低下する可能性があることを示しており、これは基底交差によって正しく捕捉されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、基底が空のノードが重心に含まれている場合に発生します。 その場合、それをマージしても現在の基準が変更されるべきではありません。 XOR 基底にゼロ ベクトルを追加しても効果がないため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、セントロイド コンポーネント内のすべてのノードに互いに素な単一ビット フィルターがある場合です。 半径が増加するにつれて、基底は単調に増加し、最大 XOR は段階的に増加します。 ノードは距離順に挿入されるため、セントロイド プロセスは各増分を正確にキャプチャします。 

最後のエッジ ケースは、重心分解によって単一の長いチェーンが繰り返し分割される、歪んだツリーです。 ここでも各ノードが処理されています$O(\log n)$基底マージはツリーの形状には依存せず、各重心コンポーネントで収集されたノードのみに依存するため、安定した状態を保ちます。
