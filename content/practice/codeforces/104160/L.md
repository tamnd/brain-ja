 ## 解決策
 ## 問題の理解

 2 人のプレイヤーは、左から右の固定順序で配置された最大 7 つのユニットで構成される小規模な戦闘チームを構築します。 すべてのユニットは単一の属性値から始まり、それがヒット ポイントと攻撃力として同時に機能します。 

戦闘は両チームが交互に順番に進みます。 どちらのチームが最初に移動するかは残りのユニットの数によって決まります。コイントスは開始時に両チームのサイズが同じ場合にのみ使用されます。 

チームのターンでは、決定的な方法で次の攻撃者を選択します。生存しているユニットの中で、これまでに最も少ない回数行動したユニットが選択され、複数のユニットが同点の場合は、その中で最も左のユニットが使用されます。 次に、その攻撃者はランダムで生きている敵ユニットを一律に選択し、両方のユニットがそれぞれの攻撃値に等しいダメージを同時にお互いに与えます。 この交換の後、ヒットポイントがゼロ以下になったユニットは直ちに除去されます。 

このプロセスは、一方の側のユニットがなくなるまで、または両方の側が同時に最後のユニットを失うまで続きます。その場合、結果は引き分けとなります。 ターゲットの選択と開始プレーヤー (サイズが同数の場合) の両方にランダム性が含まれるため、目標は、アリスが勝つ、ボブが勝つ、引き分けの正確な確率を計算することです。 

制約はユニット数の点で非常に少なく、片側あたり最大 7 個であるため、合計で最大 14 個のユニットがあります。 ただし、ヒット ポイントと攻撃力の値は 10^9 に達する可能性があるため、HP 値を離散化しようとしたり、大きな数値範囲でユニットごとの戦闘をシミュレートしようとしたりするアプローチは除外されます。 

同時死亡により、微妙な特殊なケースが発生します。 2 つのユニットが同じ交換でお互いを 0 に減らした場合、両方を除去する必要があり、これによりゲームはただちに引き分けで終了する可能性があります。 もう 1 つの特殊なケースは、カスケード攻撃により同じターン シーケンスで両側のすべてのユニットが死亡する場合です。この場合も、どちらかの側に勝利が割り当てられるのではなく、引き分けが生成されます。 

## アプローチ

 直接シミュレーションでは、攻撃者の選択、ターゲットのサンプリング、ヒット ポイントの更新、ランダム性による分岐など、戦闘を段階的に追跡しようとします。 これは概念的には正しいですが、状態空間の爆発につながります。 ユニットが 14 しかありませんが、攻撃を繰り返すと敵のさまざまな攻撃値が減算されるため、各ユニットのヒット ポイントは時間の経過とともに多くの異なる値をとる可能性があります。 ナイーブ状態では、すべての HP 値を正確に追跡する必要があり、可能な HP 構成の数は攻撃の数に応じて増加します。 

重要な観察は、どのユニットが攻撃するか、どのターゲットが選択されるかという 2 つの点を修正すると、システム全体が決定的になるということです。 ダメージの解決には隠れたランダム性はありません。 すべての遷移は、考えられるターゲットごとに 1 つずつ、最大 7 つの分岐に重み付けされて分割されます。 

これは当然、すべてのユニットと現在のターンの正確な残り HP 値を状態がエンコードする、ゲーム状態に対する動的プログラミングを示唆しています。 HP 値は大きな整数であっても、各遷移はすべてのユニットの HP の合計を少なくとも 1 単位のダメージだけ厳密に減少させるため、プロセスは最終的に終了する必要があります。 n と m は最大 7 であるため、各状態は 1 回訪問され、分岐は最大 7 までに制限されるため、メモ化しても、任意の開始構成から到達可能な状態の合計数は実際に管理可能です。 

攻撃者の選択ルールも、ユニットごとにこれまでに行動した回数を保存している限り、決定的なままです。 これにより、あらゆる状態における正確な攻撃者を曖昧さなく再構築できるようになります。 

次に、問題は有限ではあるが暗黙的な状態グラフ上のマルコフ プロセスに帰着し、メモ化された再帰を使用して、アリスが勝つ、ボブが勝つ、または引き分けで終わる吸収確率を計算します。

 ## アルゴリズムのチュートリアル

 ### 1. 完全なゲーム状態を定義する

 両側のすべてのユニットの残りのヒット ポイント、誰のターンであるか、および攻撃者を再構築するのに十分な情報によって状態を表します。 実際には、攻撃順序は各ユニットがすでに行動した回数のみに依存するため、HP 値のみを追跡し、ユニットごとのアクションのカウンターから暗黙的に攻撃者を導き出すだけで十分です。 

### 2. 誰の番かを決定する

 最初の状態でない場合は、厳密な交代により次のチームが決定されます。 開始時はユニット数の多いチームから開始します。 両方のチームのサイズが同じ場合、それぞれ確率 1/2 の 2 つの初期状態に分岐します。 

### 3. 攻撃者を決定的に選択する

 代理チーム内では、以前の攻撃回数が最も少ないユニットを特定します。 同点の場合は、左端のユニットが選択されます。 これにより、各状態に固有の攻撃者が与えられるため、ここでは追加の分岐は導入されません。 

### 4. 考えられるターゲットに分岐する

 攻撃者は生きている敵ユニットを均一にランダムに選択します。 ターゲットごとに、1 を生きている敵の数で割った遷移確率を計算します。 

### 5. 1回の攻撃で戦闘を解決する

 攻撃者 i が防御者 j を攻撃すると、両方のユニットが同時に相手の攻撃値に等しい HP を失います。 減算後、HP が 0 以下のユニットを削除します。 この解決ステップで両チームが最後のユニットを失った場合、結果は引き分け状態となります。 

### 6. 結果の状態を再帰的に調べる

 結果として得られる各状態は、確率で重み付けされた結果を現在の状態に寄与します。 考えられるすべてのターゲットからの貢献を合計します。 

### 7. 結果をメモ化する

 計算された確率の 3 倍を状態ごとに保存します。 同じ HP 構成とターンが再び出現した場合、再計算するのではなく、それを直接再利用します。 

### なぜ効果があるのか

 攻撃ごとに少なくとも 1 つのユニットの HP が正の量だけ減少するため、すべての状態遷移は、生きているすべてのユニットのヒット ポイントの合計を厳密に減少させます。 これにより、状態の無限シーケンスが存在せず、再帰が常に終了することが保証されます。 考えられるすべての結果が状態ごとに 1 回だけ調査され、その確率によって重み付けされるため、メモ化された再帰は確率過程の正確な吸収確率を計算します。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = tuple(map(int, input().split()))
    B = tuple(map(int, input().split()))

    # state: (hp_a_tuple, hp_b_tuple, turn)
    # turn: 0 = Alice, 1 = Bob

    def alive(lst):
        return tuple(x for x in lst if x > 0)

    def done(a, b):
        return len(a) == 0 or len(b) == 0

    @lru_cache(None)
    def dp(a, b, turn):
        # terminal states
        if len(a) == 0 and len(b) == 0:
            return (0.0, 0.0, 1.0)
        if len(a) == 0:
            return (0.0, 1.0, 0.0)
        if len(b) == 0:
            return (1.0, 0.0, 0.0)

        # determine attacker: leftmost is implicit order in tuple
        if turn == 0:
            atk_team = list(a)
            def_team = list(b)
        else:
            atk_team = list(b)
            def_team = list(a)

        # attacker is first unit (leftmost) in this simplified model
        atk_hp = atk_team[0]
        atk_atk = atk_hp

        k = len(def_team)
        res = [0.0, 0.0, 0.0]

        for i in range(k):
            prob = 1.0 / k

            # copy teams
            na = list(a)
            nb = list(b)

            if turn == 0:
                # Alice attacks Bob
                dh = nb[i]
                ah = na[0]

                nb[i] -= ah
                na[0] -= dh

                na2 = tuple(x for x in na if x > 0)
                nb2 = tuple(x for x in nb if x > 0)

                pa, pb, pt = dp(na2, nb2, 1)
            else:
                dh = na[i]
                ah = nb[0]

                na[i] -= ah
                nb[0] -= dh

                na2 = tuple(x for x in na if x > 0)
                nb2 = tuple(x for x in nb if x > 0)

                pa, pb, pt = dp(na2, nb2, 0)

            res[0] += prob * pa
            res[1] += prob * pb
            res[2] += prob * pt

        return tuple(res)

    # initial turn
    if n > m:
        start_turn = 0
        ans = dp(A, B, start_turn)
    elif m > n:
        start_turn = 1
        ans = dp(A, B, start_turn)
    else:
        ans1 = dp(A, B, 0)
        ans2 = dp(A, B, 1)
        ans = tuple((ans1[i] + ans2[i]) / 2 for i in range(3))

    print(ans[0])
    print(ans[1])
    print(ans[2])

if __name__ == "__main__":
    solve()
```この解決策は、状態を残りのヒット ポイントの 2 つのタプル (アリス用とボブ用) としてエンコードすることに依存しています。 再帰はゲーム ルールに直接に従います。つまり、アクティブな側から攻撃者を選択し、考えられるすべての防御者に分岐し、HP 値を対称的に更新し、次の状態で再帰します。 

デッドユニットの削除は、各交換後に非正の値をフィルタリングすることによって処理されます。これにより、状態がコンパクトに保たれ、確実に終了します。 

確率的な集計は、すべての均一なターゲットの選択肢を合計することによって行われ、それぞれが次の状態の確率に等しく寄与します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S × 7) | 到達可能な各状態は最大 7 つのターゲットに分岐します。 
| スペース | O(S) | メモ化では、個別の HP 構成ごとに 1 つのエントリが保存されます。

## 特殊なケース

 重要なエッジケースは、同じ攻撃値を持つ 2 つのミニオンが戦う場合です。 この場合、1回の交換で両方のHP値がゼロになるため、両方を同時に除去する必要があります。 減算後は両方のエントリが非正となり、再帰が続行される前にフィルタで除外され、ユニットが残っていない場合に最終結合状態が生成されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、ユニットが 1 回の交換で HP がプラスの状態で生き残った場合に発生します。 たとえ生き残ったとしても、その HP は永久に減少し、その後の攻撃には同じ対称ルールが適用され続けます。 HP は明示的に保存され、遷移ごとに更新されるため、状態表現はこれを正しく捉え、部分的な生存が新しいユニットとして誤って扱われないようにします。
