 ## 解決策
 ## 問題の理解

 DRX と T1 の間のベストオブ 5 シリーズの結果を記述する 5 文字の固定長シーケンスが与えられます。 各キャラクターはゲームに対応します。DRX の勝利、T1 の勝利、またはシリーズが早くに終了し、残りのゲームがプレイされなかったことを示す特別なシンボルのいずれかです。 

重要なルールは、最初に 3 勝したチームが即座にチャンピオンとなり、その後のすべての試合が次の試合に置き換えられるということです。`?`シンボル。 これは、文字列が単なる結果のリストではなく、3 勝までのレースの切り詰められた記録であることを意味します。 

課題は、このプロセスの下で実際にどのチームが最初に 3 勝に到達したかを判断することです。 

文字列の長さは 5 ですが、重要な点は、そのプレフィックスのみが実際の結果を含むということです。 最初以降のすべて`?`未プレイのゲームを表すため、無関係です。 したがって、有効な情報は、停止条件に達するまで勝利をカウントするプレフィックスです。 

制約は非常に小さく、固定長 5 であるため、文字列を 1 回スキャンするソリューションであればどれでも十分です。 高度なデータ構造や組み合わせは必要ありません。 プレイの不必要な分岐をシミュレートしようとする試みは過剰であり、正しさの推論が複雑になるだけです。 

微妙なエッジケースは、シリーズがちょうど 3 試合で終了する場合です。たとえば、`DDD??`または`TTT??`。 もう 1 つは、勝者が最終順位の 3 つ前に到達したときです。`TDTT?`、4番目のゲームで勝者が決まり、5番目のゲームは無関係です。 

単純な間違いは、次の文字を含むすべての文字を数えることです。`?`これにより、プレースホルダーが実際のゲームとして誤って解釈されてしまいます。 もう 1 つの間違いは、5 つのゲームすべてが常にプレイされると想定することです。これは切り捨てルールに違反します。 

## アプローチ

 強引な解釈では、5 つのポジションすべてを実際の試合として扱い、文字列全体の勝利数をシミュレートします。 これは簡単そうに見えますが、最初の接尾辞が次のとおりであるため、概念的には失敗します。`?`実際の一致を表すものではありません。 これを組み込もうとすると、存在しないゲームをカウントしてしまう危険があります。 

正しい単純化は、次のことを認識することから生まれます。`?`ハードカットオフマーカーです。 出現した時点で勝敗は決まっており、それ以上の処理は無意味である。 したがって、完全な一致ツリーをシミュレートしたり、仮説的な完了を考慮したりする代わりに、終了までプレフィックスのみを処理します。 

これにより、DRX と T1 の勝利を追跡する 2 つのカウンターを使用した単一の線形スキャンに問題が軽減されます。 遭遇したら早めにやめる`?`、その時点でどちらが3勝に達しているかに基づいて即座に決定します。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、両チームの勝利カウンターを維持します。 

### ステップ

 1. 2 つのカウンタを初期化します。1 つは DRX 勝利用、もう 1 つは T1 勝利用で、どちらもゼロから始まります。 これらは実際にプレイされたゲームを表します。 
2. 最初の文字から最後の文字まで文字列を繰り返します。 各文字は、終了シンボルでない限り、ゲームの結果を表します。 
3. 現在のキャラクターが`D`、DRX のカウンターをインクリメントします。 そうであれば`T`、T1 のカウンターをインクリメントします。 これは試合の進行を直接モデル化します。 
4. 各実際のゲームを処理した後、どちらかのチームが 3 勝に達したかどうかを確認します。 そうであれば、勝者はすぐに決定され、それ以降の文字の処理を停止できます。 
5. 現在のキャラクターが`?`、それ以上のゲームはプレイされなかったため、それ以上のポジションを処理せずにすぐに停止します。 
6. 先に3勝したチームに対応するチーム名を出力します。 

重要なデザインの選択は次の点にとどまります。`?`後の位置は実際の一致に対応しないため、全長にわたって継続する代わりに。 

### なぜ効果があるのか

 前の任意のプレフィックスで`?`、カウンターは実際の一致状態を正確に表します。 チームが 3 勝に達した瞬間に、ゲーム シリーズは定義上終了し、文字列の残りの部分は構文上のパディングとなります。 入力は有効性を保証しているため、次のようなシナリオはありません。`?`勝者が存在する前に表示されるため、そこで停止します`?`または 3 勝で停止することが一貫した終了条件となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    drx = 0
    t1 = 0
    
    for c in s:
        if c == '?':
            break
        if c == 'D':
            drx += 1
        else:
            t1 += 1
        
        if drx == 3:
            print("DRX")
            return
        if t1 == 3:
            print("T1")
            return

solve()
```この実装は、照合プロセスの直接のシミュレーションです。 シリーズが決定したとき、またはプレースホルダーが決定したとき、ループは早期に停止します。`?`が表示されます。 早期にリターンすることで、無関係な接尾辞文字のスキャンを誤って続行することがなくなります。 

微妙な詳細の 1 つは、各更新の直後に 3 回の勝利に到達したかどうかをチェックすることです。 これにより、余分な反復が回避され、チームが 3 勝に達すると試合が即座に終了するという現実世界のルールが反映されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from contextlib import redirect_stdout
    out = io.StringIO()
    
    def solve():
        s = sys.stdin.readline().strip()
        drx = 0
        t1 = 0
        for c in s:
            if c == '?':

                drx += 1
            else:
                t1 += 1
            if drx == 3:
                print("DRX")
                return
            if t1 == 3:
                print("T1")
                return
    
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 重要なエッジケースの 1 つは、試合ができるだけ早く終了する場合です。`DDD??`。 この場合、アルゴリズムは 3 文字目で正確に停止し、残りの文字は処理されません。 カウンタはすぐに DRX = 3 に達するため、出力は次のようになります。`DRX`。 

もう一つは、何もせずに勝者が決まる場合です。`?`などの登場`DTDDD`。 アルゴリズムは次の存在に依存しません。`?`、3勝に到達した場合のみ。 スキャンは 3 回目の DRX 勝利に達するまで続行され、その後正しく終了します。 

最後のケースは次のような交互勝利です。`TDTDT`、どちらのチームも早い段階で支配します。 このアルゴリズムは、インクリメントごとにチェックすることで正確性を保証するため、T1 が 3 勝に達した瞬間に、後続の文字が存在する場合でも停止します。
