 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、間隔で定義された単一のグローバル「圧縮」操作を適用するように求められます。$[l, r]$、ここで、間隔の長さは次のように制限されます。$r - l \le d$。 シーケンスのすべての要素は個別に変換されます: 以下の値$l$まで押し上げられています$l$、上記の値$r$に引き下げられる$r$、間隔内の値は変更されません。 

この変換後、配列内の合計「隣接張力」を調べます。これは、連続する要素間の絶対差の合計として定義されます。 タスクは間隔を選択することです$[l, r]$クランプ後の総張力を最大化します。 

入力サイズ$n \le 5000$周囲のアルゴリズムを許可します$O(n^2)$実行可能ですが、それ以上のもの$n$失敗します。 間隔のエンドポイントは実数であるため、単純な連続検索は$(l, r)$それは不可能であり、正しい解決策は、探索空間を有限の候補セットに縮小する必要があります。 

微妙な点は、変換が線形ではないことです。$l$そして$r$。 間隔の小さな変化により、要素が 3 つの領域間で突然切り替わる可能性があります。$l$、変更されない、または固定される$r$。 これにより区分的な動作が作成されるため、単純な勾配や貪欲な推論は適用されません。 

典型的な失敗例は、最適な間隔が常に最小値および最大値と一致すると仮定することから発生します。 たとえば、シーケンスが次の場合、$[0, 100, 1, 99]$そして$d$大きい、ピッキング$[0, 100]$何もしませんが、次のような間隔を狭めます$[1, 2]$構造が劇的に変化し、差異が増大します。 最適な間隔は、グローバルな極値ではなく、隣接するペアを分割する方法によって決まります。 

## アプローチ

 直接的なアプローチは、可能な限りすべての間隔を試すことです$[l, r]$満足のいく$r - l \le d$、次に、クランプされた配列とその隣接する差分を再計算します。 ただし、候補エンドポイントを離散化したとしても、$O(n)$価値観、まだあります$O(n^2)$間隔と各評価コスト$O(n)$、につながる$O(n^3)$が遅すぎる$n = 5000$。 

重要な構造的観察は、固定された$l$、選択することは決して役に立ちません$r < l + d$増えない限り$r$クランプ結果は変わりません。 拡大中$r$値を上方に移動するか、値を変更せずに維持することしかできず、隣接する差異の一部を増加または保持することしかできません。 これにより、修正が可能になります$r = l + d$最適性を損なうことなく。 

ここで問題は選択のみになります$l$。 難しいのは、$l$移動すると、各要素は 3 つの状態の間で切り替わり、隣接する各ペアは、ペアの端点から導出される有限のしきい値セットでのみ変化する値に寄与します。 

それぞれについてすべてを再計算するのではなく、$l$、視点を反転します。隣接する各ペアは、次の区分的線形関数に寄与します。$l$、いずれかのエンドポイントがヒットする値にブレークポイントがあります$l$または$l + d$。 すべてのペアにわたって、グローバル区分線形関数を累積します。 関数全体の傾きは次の時点でのみ変化します。$O(n^2)$イベント ポイントを使用するため、これらのイベントを並べ替えられた順序でスイープし、現在の値を効率的に維持できます。 

これにより、実行中の線形関数を維持するという問題が軽減されます。$l$、各イベントでの傾きと切片を更新し、スイープ中に発生した最大値を追跡します。

 ## アルゴリズムのチュートリアル

 検索スペースを次のように縮小します。$r = l + d$、次に目的を関数として扱います$F(l)$。 

1.修正$r = l + d$したがって、すべての要素は次の 3 つの体制に固定されます。$l$、 内部$[l, r]$、以上$r$。 これにより、自由度が 1 つ削除され、単一のパラメータで変換が制御されるようになります。 
2. 隣接するペアごとに$(a_i, a_{i+1})$、それがどのように貢献しているかを判断します$|b_i - b_{i+1}|$として変化します$l$は異なります。 意味のある遷移は、どちらかのエンドポイントが交差するときにのみ発生します。$l$または$l + d$なので、各ペアは次のイベントに貢献します。$a_i$、$a_{i+1}$、$a_i - d$、 そして$a_{i+1} - d$。 
3. 各ペアを一連の間隔に変換します。$l$- 軸の寄与が線形である場合$l$。 このような間隔ごとに、寄与度を次のように表します。$s \cdot l + c$、傾斜がある場所$s$イベント境界でのみ変更されます。 
4. すべてのペアからすべてのイベント ポイントを収集し、並べ替えます。 これにより、完全な目的関数が一定の傾きで動作するすべての区間にわたるグローバルなスイープ順序が与えられます。 
5. これらの並べ替えられたイベントを左から右にスイープします。 2 つのグローバル値を維持します: 現在の傾き$F(l)$と現在の値$F(l)$スイープ位置で。 イベントを通過するときは、影響を受けるペアの体制がどのように変化するかに応じて、傾きと切片を調整します。 
6. イベント間では、関数は直線的に進化します。$l$次のイベントへ$l'$、更新します$F(l') = F(l) + \text{slope} \cdot (l' - l)$、検出された最大値を追跡します。 

### なぜ効果があるのか

 隣接する各ペアの寄与は、次のペア間の比較のみに依存します。$l$、$l + d$、およびペアの 2 つの値。 これは、目的におけるすべての構造変化は、これらの比較の 1 つが反転したときに正確に発生することを意味します。 あるのは$O(n^2)$合計でそのようなフリップ。 フリップ間では、関数は完全に線形であるため、傾きと切片を維持するだけで目的全体を正確に記述するのに十分です。 すべての変更を順番に処理するため、$(l, r)$はスキップされ、すべての実行可能な間隔の最大値が観察されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    events = []

    # Each pair contributes events at critical breakpoints
    for i in range(n - 1):
        x = a[i]
        y = a[i + 1]

        # all relevant breakpoints for l are:
        # x, y, x - d, y - d
        for v in (x, y, x - d, y - d):
            events.append(v)

    events = sorted(set(events))

    # We simulate F(l) = slope * l + const
    # We recompute contributions at each segment endpoint in O(n)
    # (n is small enough for n^2 overall)

    def calc(l):
        r = l + d
        res = 0
        b_prev = 0

        def clamp(x):
            if x < l:
                return l
            if x > r:
                return r
            return x

        b_prev = clamp(a[0])
        total = 0
        for i in range(1, n):
            cur = clamp(a[i])
            total += abs(cur - b_prev)
            b_prev = cur
        return total

    ans = -10**30
    for l in events:
        ans = max(ans, calc(l))

    print(ans)

if __name__ == "__main__":
    solve()
```示されている実装では、簡略化されていますが、それでも効率的な離散化戦略が使用されています。 傾きの変化を明示的に維持する代わりに、構造的に異なるすべての候補値で目的を評価します。$l$、これらは、要素がレジームを変更する唯一のポイントです。 各評価では、クランプされたシーケンスが再計算されます。$O(n)$、全体的な結果につながります$O(n^2)$解決。 

重要な実装の詳細は、候補セットを正しく構築することです。 クランプされた構造のあらゆる変化は、次の場合にのみ発生します。$l$値を越える$a_i$またはいつ$l + d$十字架$a_i$、候補者に変換されます$l$価値観$a_i$そして$a_i - d$。 両方を含めないと、最適な間隔がテストされることはありません。 

クランプされた配列を効率的に再計算するには注意が必要です。 クランプは要素操作ごとに一定時間であるため、各完全な評価は線形のままであり、プレフィックスの前処理は必要ありません。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 その状況では、どのクランプ間隔でも等価性が維持され、答えはゼロのままでなければなりません。 アルゴリズムはこれを処理します。$l$一定のクランプされたシーケンスが生成され、すべての評価でゼロが返されるため、最大値は正確にゼロになります。 

別の特殊なケースが発生するのは、$d = 0$、強制的に$l = r$。 これにより、すべての要素が同じ値に折りたたまれます。$l$、すべての隣接する差分をゼロにします。 候補者の総括には、関連するすべての候補者が引き続き含まれます$l$ただし、どの構成でもゼロが生成されるため、最大値は正しく処理されます。 

最後のエッジ ケースは、最適な動作が単一の隣接するペアを分割し、他のすべてのペアには影響を与えないことに依存する場合です。 たとえば、2 つの連続する値が境界候補をまたぐ場合、一方は固定され、もう一方は区間内に留まります。 イベントベースの候補構築では、そのような境界位置が明示的にテストされることが保証されるため、最適な分割点が見逃されることはありません。
