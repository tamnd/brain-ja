 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、長さの`n`。 私たちの目標は変革することです`a`の中へ`b`連続したサブ配列を選択し、そのすべての値をそのサブ配列の最大値に置き換えることができる操作を使用します。 言い換えれば、セグメント内の要素を増やすことができるのは、そのセグメントの極大値に一致するまでだけです。 問題は達成可能かどうかを尋ねます`b`から`a`0 個以上のそのような操作を使用します。 

制約は重要です。 各配列は最大で`2*10^5`すべてのテスト ケースの合計の上限は次のとおりです。`2*10^5`。 サブ配列の数は二次関数であるため、考えられるすべてのサブ配列を試す単純な解決策は実行不可能です。`n`。 そのため、線形または線形に近い解決策を探す必要があります。 

微妙なエッジケースには、次のような状況が含まれます。`b[i] < a[i]`どのインデックスでも。 私たちの操作では値を増やすことしかできないため、そのような事態が発生すると、変換は直ちに不可能になります。 別の特殊なケースは、数値が繰り返されている場合に発生します。`b`近隣のものよりも大きい`a`- 十分な柔軟性があることを確認する必要があります`a`以前の制約によってブロックされることなく、必要な値まで「成長」します。 例えば、`a = [1,1]`そして`b = [1,2]`2がないので機能しません`a`前方に伝播します。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべての要素に対して、`a[i] != b[i]`を含む最短のセグメントを見つけることを試みることができます。`i`ここで、すべての値をそのセグメントの最大値に置き換えることができます。 これを繰り返すと、`a`マッチ`b`原理的には正しいです。 各置換操作はセグメント長において線形であり、最大で`n`考慮すべきセグメント。 最悪の場合、これはテスト ケースごとに O(n²) となり、これでは遅すぎます。`n`まで`2*10^5`。 

より高速なソリューションを実現するための重要な観察は、すべての操作をシミュレートする必要がないということです。 この操作では値の増加と既存の値の伝播のみが許可されるため、変換はどこでも不可能です。`b[i] < a[i]`。 インデックスの場合、`b[i] > a[i]`のどこかで、より大きな値を利用できる必要があります。`a`これは、連続したセグメントを使用して前方に伝播できます。 具体的には、次の異なる数値ごとに、`b`、その数のインスタンスが十分にあるかどうかを知る必要があります。`a`または、より小さい数値を使用して作成することもできます。 なぜなら`b`によって制限されています`n`、各数値のカウントを維持し、必要な各数値を貪欲に確保できます。`b`以下から直接調達できます。`a`または、以前に確立されたセグメントから間接的に。 

これにより、問題は線形スイープ (トラバース) に変換されます。`b`左から右に、それぞれの`b[i]`少なくとも次と同じ大きさです`a[i]`そして、以前にその数値に遭遇したことがあるか、あるいはその数値を生成できるかどうか。 スタックや周波数カウンターなどの単純なデータ構造を使用して、伝播に使用できる数値を追跡します。

 ## アルゴリズムのチュートリアル

 1. 周波数カウンタを初期化する`freq`サイズの`n+1`各数値を何回使用して伝播できるかを追跡します。 これは、すべての数値に対してゼロから始まります。 
2. 配列を反復処理する`a`そして`b`左から右へ。 インデックスごとに`i`、まず次のことを確認してください。`b[i] < a[i]`。 ある場合は出力します`NO`値を減らすことができないため、すぐに。 
3. もし`b[i] == a[i]`、次のインデックスに進みます。 操作は必要ありません。 
4. もし`b[i] > a[i]`、どうかを確認してください`freq[b[i]] > 0`。 その場合はデクリメントします`freq[b[i]]`以前に発生した次のものを使用できるため、続行します。`b[i]`埋める`a[i]`。 そうでない場合、変換は不可能なので出力します。`NO`。 
5.いつでも`a[i] == b[i]`値が 1 より大きい場合は増分します`freq[a[i]-1]`この数値が次のステップに向けて伝播できることを表します。 これは、目標に到達するためにより小さな数を増やすために利用可能な「リソース」を追跡します。 
6. ループがブロッキング条件に遭遇せずに終了した場合、出力`YES`。 

正しさを保証する不変式は次のとおりです。`freq[x]`は常に使用できる回数を表します`x`将来のポジションでより小さな数字を増やすため。 数値を過剰に消費したり、操作で禁止されている値を減らそうとしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        possible = True
        freq = [0] * (n + 2)
        
        for i in range(n):
            if b[i] < a[i]:
                possible = False
                break
            if b[i] > a[i]:
                if freq[b[i]] > 0:
                    freq[b[i]] -= 1
                else:
                    possible = False
                    break
            if a[i] > 1:
                freq[a[i]-1] += 1
        
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```最初のループでは、テスト ケースと配列の数を読み取ります。 の`freq`配列は数値の潜在的な伝播を追跡するために使用され、常に`b[i]`よりも大きいです`a[i]`、増加を裏付ける過去の数字があります。 インクリメント`freq[a[i]-1]`インデックスを処理した後、この数値が将来の増加に寄与する可能性があるという事実をモデル化します。 操作の順序は重要です - インクリメント`freq`次の要素をチェックする前に、不変条件が破られてしまいます。
