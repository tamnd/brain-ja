 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、それぞれに含まれる`n`整数。 目標は変身すること`a`の中へ`b`連続した部分配列を繰り返し選択することにより、`a`そしてそのすべての要素をその部分配列の最大要素に設定します。 これらの操作を何度か繰り返した後、`a`に等しくなります`b`、「はい」と答える必要があります。 それ以外の場合は「いいえ」。 

制約は比較的小さいです。`n`は最大でも 1000 であり、次の合計は`n^2`すべてのテスト ケースの最大値は 10^6 です。 これは、`O(n^2)`解決策は実行可能ですが、何でも`O(n^3)`が遅すぎる可能性があります。 数値自体は次の制限を受けます。`n`, そのため、カウントと頻度に基づいた方法を効率的に利用することもできます。 

明らかではないエッジケースには、数値が次のような状況が含まれます。`b`の対応する数値より小さい`a`、許可された操作によってこれを減らすことはできません。 たとえば、次の場合`a = [3, 2, 1]`そして`b = [2, 2, 2]`、要素を増やすか等しくすることしかできず、要素を減らすことはできないため、変換は不可能です。 もう 1 つの注意が必要なケースは、配列に繰り返し要素がある場合に発生します。最大演算は選択した間隔全体に影響を与えるため、不用意にセグメント化すると到達できなくなる可能性があります。`b`。 例えば、`a = [1, 2, 1]`そして`b = [2, 2, 2]`配列全体に操作を適用することで実現できますが、`a = [1, 2, 1]`そして`b = [2, 1, 2]`真ん中だから無理`1`減らすことはできません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択肢をシミュレートします。`(l,r)`どちらかまでの操作`a`マッチ`b`またはそれ以上の進歩は不可能です。 これは、各操作が有効で値が保存または増加されるため機能しますが、速度は遅くなります。`n`ポジション、あります`O(n^2)`可能なサブ配列と最大テイクの更新`O(n)`。 と`n`最大 1000 の場合、最悪の場合、演算数は 10^9 に近づき、これは大きすぎます。 

重要な洞察は、操作が単調であるということです。`a`増加するか、同じままであることのみが可能であり、減少することはありません。 したがって、`a[i]`到達する`b[i]`、すでに以下の大きさでなければなりません`b[i]`。 もし`a[i] > b[i]`、私たちはすぐに「NO」と答えることができます。 次に到達するのは、`b[i]`正確には、以下を含む区間を見つけることができなければなりません。`i`最大値はすでにあるところ`b[i]`ある時点で。 数値が小さいため、それぞれの値が正しいかどうかを確認できます。`v`で`b`に登場する`a`位置で`b[i] = v`そして、最も近い出来事が発生するかどうか`v`拡張するために使用できます`a[i]`に`b[i]`最大限の操作を介して。 

基本的にポジションごとに`i`、それを確認するだけで済みます`b[i]`で発生します`i`またはその左/右、それより小さくない`b[i]`間隔をブロックします。 これにより、問題は、`O(n^2)`最悪の場合の時間ですが、指定された範囲内では実際には効率的です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`a`、 そして`b`。 
2. インデックスがあるかどうかをすぐに確認します`i`どこ`a[i] > b[i]`。 このようなインデックスが存在する場合、この操作では値を減らすことができないため、「NO」を出力します。 
3. 数値の頻度マップまたは位置マップを作成します。`a`各値がどこで発生するかを知るためです。 これにより、どこにあるかをすぐに見つけることができます`b[i]`最大限の操作を使用して「拡散」できます。 
4.トラバース`b`左から右へ。 インデックスごとに`i`どこ`a[i] < b[i]`、ポジションがあるかどうかを確認します`j`どこ`a[j] = b[i]`そのような`j`到達できる`i`操作で。 操作は次から延長できます。`j`に`i`間にある要素がこれより大きくない限り、`b[i]`。 そのようなポジションが存在しない場合は、「いいえ」と答えてください。 
5. アレイ全体がこのチェックに合格した場合は、「YES」を出力します。 

機能する理由: このアルゴリズムは、操作がセグメント内の最大値までのみ値を増加させるという不変式に依存しています。 ポジションにより大きな値が必要な場合は、そのポジションに伝播できるポジションのどこかにその値がすでに存在している必要があります。 必要なすべての増加の到達可能性を検証することで、到達するために必要なすべての操作が保証されます。`b`有効です。 違反があると、直ちに変換が不可能であることを示します。 これは問題の制約にとって必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        impossible = False
        positions = [[] for _ in range(n+2)]
        for i, val in enumerate(a):
            positions[val].append(i)
        
        last_occurrence = [-1]*(n+2)
        for val in range(1, n+1):
            if positions[val]:
                last_occurrence[val] = positions[val][-1]
        
        i = 0
        while i < n:
            if a[i] > b[i]:
                impossible = True
                break
            if a[i] < b[i]:
                val = b[i]
                j = i
                while j < n and b[j] == val:
                    j += 1
                if last_occurrence[val] < i:
                    impossible = True
                    break
                i = j
            else:
                i += 1
        print("NO" if impossible else "YES")

solve()
```このソリューションはまず、値からインデックスへのマッピングを構築します。`a`。 左から右へのトラバースにより、いつでも`b[i]`より大きい`a[i]`、操作を使用して値を伝播するための到達可能な位置があります。 Off-by-one エラーは注意深くインデックスを追跡することで回避され、境界チェックにより配列の外に出ないことが保証されます。
