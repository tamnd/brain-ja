 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 既存の 2 つの位置を選択し、それら 2 つの値の絶対差を配列の末尾に追加する操作を繰り返し実行します。 元の要素は決して削除されないため、配列は増加するだけであり、新しい値は完全に以前の既存の値の差によって決定されます。 

これを正確に実行した後、$k$毎回最適なペアを選択すると仮定して、配列内に存在する可能性のある最小値を尋ねられることがあります。 

重要な難点は、$k$非常に大きくなる可能性があり、最大で$10^9$, そのため、操作をシミュレーションすることはできません。 ただし、配列のサイズは$n$は十分小さいので、最初にすべてのペアを検査できます。$\sum n^2$によって制限されています$4 \cdot 10^6$。 

微妙だが重要な観察は、差を導入した場合に値が減少するだけであり、新しい値はすべて既存の数値にのみ依存するということです。 これは、多くの演算後の最小値は、複素状態空間におけるシーケンスの進化に関するものではなく、繰り返される差分によってどのような数値が生成されるかに関するものであることを意味します。 

シミュレートしなければならないと考えるのは素朴な誤解です$k$貪欲に歩みを進めます。 それはすぐに失敗します$k$多くの操作では、特定の時点以降は最小値が変更されない可能性があるため、この値は大きくなります。 もう 1 つの失敗モードは、最小値が 1 回か 2 回しか減少しないと仮定することです。 実際には、差異が繰り返されると、最終的には一定の達成可能な最小値で安定することがあります。 

## アプローチ

 プロセスを総当たりで実行する場合は、すべてのペアを繰り返し試行します。$(i, j)$、計算する$|a_i - a_j|$を追加して配列を更新します。 それぞれの操作にかかる費用$O(n)$ペアを維持する場合、これを行うとさらに多くなります$k$不可能になるとき$k$大きいです。 ペア選択を最適化したとしても、生成される要素の数は爆発的に増加し、$O(k n)$行動。 

重要な構造的洞察は、この操作では既存の数値との差である数値のみが生成され、十分な差が得られるとシステムは基本的に安定するということです。 特に、到達可能な最小値は、差異の最大公約数構造によって決まります。 すべての新しい数値は、ペアごとの差によって生成された加法群内にあり、繰り返された差は最終的にすべてのペアごとの差の gcd に向かって崩壊します。 

ただし、2 番目の制約もあります。つまり、実行するのは$k$操作。 もし$k$が小さい場合、まだ安定した構造に到達していない可能性があり、答えは最終的な限界よりも大きくなる可能性があります。 したがって、小さなものを区別する必要があります$k$行動と大きな$k$飽和。 

重要な観察は、せいぜい数回の操作で、任意の 2 つの要素間に可能な限り最小の差をすでに生成できており、その最小の正の差が存在すると、その差が相互作用できる場合に限り、さらなる操作でゼロが生成される可能性があるということです。 それ以外の場合、達成可能な最小値はペアごとの差の最小値で安定し、操作を繰り返してもそれ以上改善されません。 

これにより、問題は、最大で次の値の後に現れる可能性のある最小の値を計算することになります。$k$差分生成ステップ。最初のペアごとの差分とゼロに到達可能かどうかによって完全に制御されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(k n^2)$|$O(n)$| 遅すぎる |
 | 差分クロージャ分析 |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. Compute the minimum element$m$配列内の最小の差$d = \min |a_i - a_j|$すべてのペアにわたって。 最小要素はすでに答えに対する厳密な下限を設定しています。 
2. もし$d = 0$の場合、等しい要素が 2 つ存在します。 1 つの操作ですぐにゼロを追加でき、その後のすべての操作で等しい要素を再度選択することでゼロを追加し続けることができます。 それで、もし$k \ge 1$、答えはゼロになります。 
3. もし$k = 0$の場合、演算は実行されず、答えは単に初期の最小要素になります。 
4. もし$k \ge 1$、常に少なくとも 1 つの操作を実行できます。 最初に生成される値は少なくとも$d$であり、一連の操作で より小さい値を生成することはできません。$d$なぜなら、すべての操作は既存の値の差であり、既存の最小ギャップを下回るものを導入することはできないからです。 
5. したがって、等しいペアが存在しない場合は、最小値が残ります。$\min(m, d)$。 以来$d$常に少なくとも$0$、ゼロの場合はすでに処理されている場合、答えは次のとおりです。$\min(m, d)$、これを単純化すると、$d$それを考慮すると$d \le m$同一またはより近い値が存在する場合のみ、それ以外の場合は$m$持続します。 

### なぜ効果があるのか

 新しく作成されたすべての値は、絶対値で合計が 0 になる係数を持つ元の値の整数線形結合です。 これは、到達可能な値のセットが減算で閉じられ、達成可能な最小の正の値がすべてのペアごとの差の最大公約数であることを意味します。 最小の差が生成されると最小値はすぐに安定し、それ以降の操作ではこの境界を回避できません。 唯一の例外は、ゼロの差が存在する場合であり、その場合、ゼロは永久に到達可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        m = min(a)
        
        if k == 0:
            print(m)
            continue
        
        # compute minimum pairwise difference
        d = 10**30
        a.sort()
        for i in range(n):
            for j in range(i + 1, n):
                d = min(d, a[j] - a[i])
                if d == 0:
                    break
            if d == 0:
                break
        
        if d == 0:
            print(0)
        else:
            print(min(m, d))

if __name__ == "__main__":
    solve()
```実装はケースを分離します$k = 0$、変更は許可されません。 のために$k \ge 1$、初期最小値とペアごとの最小差の両方を計算します。 ソートにより差が負でないギャップとして計算されるようになり、ゼロで早期に停止することで不必要な作業が回避されます。 

最終的な決定は、初期の最小値と達成可能な生成された最小値を直接比較します。 この背後にある理由は、すべての新しい値はペアごとの差異から構築されるため、この一連のギャップ以外には何も出現できないということです。 

## 実用的な例

 ### 例 1

 入力:```
n = 5, k = 2
a = [3, 9, 7, 15, 1]
```最小要素とペアごとの差を計算します。 

| ステップ | アクション | 最小値 | 最小の差 |
 | --- | --- | --- | --- |
 | 1 | 初期配列 | 1 | インフ |
 | 2 | スキャンペア | 1 | 2 (3 と 1 から) |
 | 3 | スキャンを続行 | 1 | 1 (差異後の 2 要素から) |

 最小要素はすでに 1 であり、これより小さい要素を生成する操作はありません。 より小さな中間差を生成することはできますが、1 を下回るものはありません。最終的な答えは 1 です。 

### 例 2

 入力:```
n = 4, k = 3
a = [7, 4, 15, 12]
```| ステップ | アクション | 最小値 | 最小の差 |
 | --- | --- | --- | --- |
 | 1 | 初期配列 | 4 | インフ |
 | 2 | ペアの差を計算する | 4 | 3 |
 | 3 | 達成可能なゼロを検出する | 4 | 連鎖後は 3 → 0 |
 | 4 | k 個の操作を使用する | 4 | 0 |

 ここでは、差分がペア間で一貫して繰り返されるため、繰り返された差分が最終的にゼロを生成することが観察されます。 ゼロが達成可能になると、最小値は 0 になります。 

これは飽和効果を示しています。システムが自己キャンセルペアを生成できると、それ以降のすべての操作は最小値を崩壊させます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2)$テストケースごと | すべてのペアごとの差を 1 回計算します。 テストの平方和は制限されています |
 | スペース |$O(1)$番外編 | 配列といくつかの変数のみを保存します。 

制約$\sum n^2 \le 4 \cdot 10^6$二次スキャンでも十分に効率的であることが保証されます。 大きな$k$操作をシミュレートすることはないため、これは無関係です。

 ## 特殊なケース

 すべての要素が等しい場合、すべてのペアごとの差はゼロになります。 アルゴリズムはスキャン中にこれを即座に検出するため、最初の操作ですでにゼロが生成されます。 たとえ$k$が大きい場合、ゼロは常に再び生成される可能性があるため、答えはゼロのままです。 

いつ$k = 0$、違いはまったく問題ありません。 配列は決して変更されないため、答えは厳密に初期の最小値であり、差を計算しようとする試みは無意味になります。 

配列に要素が 2 つしかない場合、生成される可能性のある値はそれらの差だけです。 それらが等しい場合、ゼロに到達可能です。 それ以外の場合、これより小さい値は形成できないため、プロセスはその差で安定します。
