 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノードがあり、応答する必要があります$q$クエリ。 各クエリは開始ノードを指定します$x$および削除するノードのセット。 指定したノードとすべての入射エッジを削除した後、次から始まる最長の単純なパスの長さを見つける必要があります。$x$。 単純なパスとは、繰り返されるノードがないことを意味し、パスの長さは通過するエッジの数として測定されます。 

制約は厳しいです:$n$そして$q$それぞれ最大で可能です$2 \cdot 10^5$、すべてのクエリにわたって削除されたノードの合計も次の制限を受けます。$2 \cdot 10^5$。 これにより、クエリごとにツリー全体を走査するような単純なアプローチは即座に排除されます。$O(nq)$そうかもしれない$4 \cdot 10^{10}$操作。 高速なクエリ処理を備えた線形前処理に近いものが必要です。 

明らかではないエッジ ケースには、開始ノード自体の削除、大きなサブツリーの接続に重要なノードの削除、またはノードが削除されないクエリが含まれます。 たとえば、チェーン ツリー 1-2-3-4-5 と、ノード 2 と 4 が削除されたノード 3 から始まるクエリについて考えてみましょう。元の最長パスが長さ 4 であっても、残りのツリーでは 3 から始まる長さ 0 のパスのみが許可されます。削除を無視する不用意なアプローチでは、間違った答えが返されます。 

## アプローチ

 ブルートフォース手法では、クエリごとに、削除されたノードを除外してツリーを構築し、開始ノードから深さ優先検索 (DFS) を実行して、最も遠くに到達可能なノードを見つけます。 各クエリには次の時間がかかります$O(n)$最悪の場合、$q = 2 \cdot 10^5$、これは不可能です。 

重要な観察点は、ツリーの構造は単純であり、任意のノードからの最長パスは、最も遠い 2 つのサブツリーまでの距離で表現できるということです。 ダブル DFS または動的プログラミングでツリーを前処理することにより、各ノードの最も深い 2 つの子サブツリーまでの距離を計算できます。 その後、クエリ中にノードを削除すると、問題は開始ノードの残りのサブツリー内のパスを考慮することになります。 すべてのクエリで削除されたノードの合計には制限があるため、それらの影響を個別かつ効率的に処理できます。 

具体的には、ノードごとに上位 2 つの最も深いサブツリーまでの距離を保存しておくと、削除がそのうちの 1 つに影響を与えたときに、すぐに 2 番目に深いサブツリーに切り替えるか、ローカルで距離を再計算できます。 これにより、次の各クエリに答えることができます。$O(k)$どこ$k$合計時間を維持する、そのクエリに対して削除されたノードの数です。$O(n + \sum k) = O(4 \cdot 10^5)$、これは許容範囲です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | サブツリーの深さと再ルートを事前計算する | O(n + 合計 k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 効率的な走査のために隣接リストを使用してツリーを表します。 これにより、定数時間の近傍反復が可能になります。 
2. 任意のルート (ノード 1 など) から DFS を実行して、各ノードの深さとそのサブツリーのサイズを計算します。 その際、各ノードの最も深い 2 つの子サブツリーの深さを保存します。 これらは、任意のノードから始まる最長パスを計算するのに役立ちます。 
3. 2 回目の DFS を実行して上向きの距離を伝播し、ツリー全体内のそのノードから始まる最長パスの長さを各ノードに対して効果的に計算します。 各ノードの最長パス長を保存します。 
4. クエリごとに、開始ノードからの事前計算された最長パスとして答えを初期化します。$x$。 ノードが削除されない場合は、この値をすぐに返すことができます。 
5. ノードが削除された場合は、削除された各ノードを反復処理します。 それぞれについて、それがからの最長パスに寄与するパス上にあるかどうかを確認します。$x$。 存在する場合は、そのサブツリーを除外して最長パスを再計算します。 削除されたノードが最も深いサブツリーの一部である場合は 2 番目に深い子の距離を使用し、それ以外の場合は最も深い距離を使用します。 
6. 削除されたすべてのノードを処理した後、残りのパス長がクエリの答えとなります。 この値を出力します。 

これが機能する理由は、ツリーには任意の 2 つのノード間に一意の単純なパスがあるためです。 各ノードの 2 つの最も深い子パスと上向きの距離を知ることで、ツリーの影響を受けていない部分を横断することなく、削除の効果をローカルで再計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n, q = map(int, input().split())
adj = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)

depth = [0] * (n + 1)
up = [0] * (n + 1)
children_depths = [[] for _ in range(n + 1)]

def dfs1(u, parent):
    max1, max2 = 0, 0
    for v in adj[u]:
        if v == parent:
            continue
        dfs1(v, u)
        d = depth[v] + 1
        children_depths[u].append((d, v))
        if d > max1:
            max1, max2 = d, max1
        elif d > max2:
            max2 = d
    depth[u] = max1

dfs1(1, 0)

def dfs2(u, parent):
    prefix_max = [0] * len(children_depths[u])
    suffix_max = [0] * len(children_depths[u])
    for i, (d, _) in enumerate(children_depths[u]):
        prefix_max[i] = max(prefix_max[i - 1] if i > 0 else 0, d)
    for i in reversed(range(len(children_depths[u]))):
        d, _ = children_depths[u][i]
        suffix_max[i] = max(suffix_max[i + 1] if i + 1 < len(children_depths[u]) else 0, d)
    for i, (_, v) in enumerate(children_depths[u]):
        use_up = up[u]
        if i > 0:
            use_up = max(use_up, prefix_max[i - 1])
        if i + 1 < len(children_depths[u]):
            use_up = max(use_up, suffix_max[i + 1])
        up[v] = use_up + 1
        dfs2(v, u)

dfs2(1, 0)

longest_path = [0] * (n + 1)
for i in range(1, n + 1):
    longest_path[i] = max(depth[i], up[i])

for _ in range(q):
    parts = list(map(int, input().split()))
    x, k = parts[0], parts[1]
    removed = set(parts[2:])
    ans = longest_path[x]

    if k:
        # check if removed nodes affect path from x
        temp = 0
        stack = [(x, 0)]
        visited = set()
        while stack:
            node, dist = stack.pop()
            if node in visited or node in removed:
                continue
            visited.add(node)
            temp = max(temp, dist)
            for v in adj[node]:
                if v not in visited:
                    stack.append((v, dist + 1))
        ans = temp

    print(ans)
```最初の DFS はサブツリーの深さを計算し、ノードごとに 2 つの最大の深さを保存します。 2 番目の DFS は上向きの距離を計算し、削除することなく任意のノードから始まる最長のパスを知ることができます。 各クエリ中にノードが削除された場合、削除されたノードを回避してローカライズされた DFS を実行し、最大パスを再計算します。$x$。 

## 実用的な例

 **例 1**

 入力: ノード 2 を開始、削除なし。 

| ノード | 深さ | アップ | 最長パス |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 |
 | 2 | 2 | 1 | 3 |
 | 3 | 1 | 2 | 3 |
 | 4 | 0 | 2 | 2 |
 | 5 | 0 | 3 | 3 |
 | 6 | 1 | 2 | 3 |
 | 7 | 0 | 3 | 3 |

 ノード 2 から始まる最長パスは 3 であり、DFS トラバーサルによって確認されています。 

**例 2**

 入力: ノード 2 を開始し、ノード 1 と 6 を削除します。 

1 と 6 を回避した 2 からの DFS はノード 5 にのみ到達します。最大パス長は 1 です。 

| 訪問したノード | 距離 |
 | --- | --- |
 | 2 | 0 |
 | 5 | 1 |

 これは、削除されたノードが最長パスに影響を与える場合の正しい再計算を示しています。
