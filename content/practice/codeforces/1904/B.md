 ## 解決策
 ## 問題の理解

 正の整数の配列を使用してコレクション ゲームをシミュレートするように求められます。 選択した配列要素に等しい「スコア」から始めて、他の要素を 1 つずつ削除しようとします。 現在のスコアがその要素と同じ以上であれば、要素を削除できます。削除するたびに、削除された要素の値だけスコアが増加します。 配列内のすべての位置について、要素を削除して初期スコアをその値に設定することから始めた場合、削除できる追加要素の最大数を計算する必要があります。 削除された要素自体は回答に含まれません。 

配列には最大 100,000 個の要素を含めることができ、テスト ケース全体のすべての配列サイズの合計も最大 100,000 になります。 10^5 × 10^5 の演算は大きすぎるため、O(n²) 時間で各要素のプロセスを最初から明示的にシミュレートするアルゴリズムは除外されます。 代わりに、n に対して線形または対数的にスケールする方法が必要です。 

エッジ ケースには、すべての要素が等しい配列、降順で並べ替えられた配列、および単一要素の配列が含まれます。 たとえば、`[5, 5, 5]`、どの開始スコアでも、残りの要素をすべて削除して答えを生成できます。`[2, 2, 2]`。 累積スコアの増加を考慮しない不注意なソリューションでは、返される除去が少なくなる可能性があります。 同様に、次のような降順配列`[10, 5, 1]`は、削除数を最大化するには、小さい要素を最初に削除することが重要であることを示しています。 

## アプローチ

 ブルート フォースのアプローチは簡単です。要素ごとに削除してスコアを設定し、残りの配列を繰り返しスキャンして現在のスコアを超えない要素を削除し、そのたびにスコアを更新します。 これが機能するのは、ルールが単純で決定的であるためです。 n 個の開始位置のそれぞれが最大 n 個の要素をスキャンする可能性があるため、最悪の場合の複雑さはテスト ケースごとに O(n²) になります。 n = 10^5 の場合、これは実現できません。 

最適化のための重要な洞察は、要素を削除する順序を推測する必要がないことです。 残りの要素を昇順に並べ替えると、許容できる最小の利用可能な要素を削除するたびに、スコアが最適に増加することが保証されます。 並べ替えが完了すると、接頭辞合計アプローチまたは 2 ポインターを使用して、開始スコアから削除できる要素の最大数を計算できます。 これにより、複雑さがソートの O(n log n) と除去の計算の O(n) に軽減されます。 

基本的に、各ステップで最小の取り外し可能な要素を貪欲に削除すると、合計数が最大になることが観察されます。 配列のサイズは大きいですが、操作は単純であるため、このアプローチは指定された時間制限内に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 (ソート + 貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取り、元のインデックスを保存します。 
2. 元の位置を記憶しながら配列をソートします。 これにより、貪欲な削除の結果を元の各要素にマップし直すことができます。 
3. ソートされた配列のプレフィックスの合計を計算します。 プレフィックスの合計により、開始スコアの候補について、削除できる小さな要素の数を迅速に決定できます。 
4. 元の配列の各要素について、ソートされた配列に対して二分探索を使用して、この要素を初期スコアとして削除できる要素の最大数を見つけます。 二分探索では、プレフィックスの累積合計と候補スコアが比較され、各要素が削除されるたびにスコアが増加します。 
5. カウントを出力配列の元のインデックスに保存します。 
6. テスト ケースの最終的なカウントの配列を出力します。 

機能する理由: 代替の順序では、削除できた可能性のあるより小さな要素が残るため、最小の削除可能な要素を貪欲に削除すると、カウントが最大になります。 並べ替えとプレフィックスの合計により、すべての開始要素の削除を効率的に計算できます。 プレフィックス合計は、現在のスコアよりも小さいすべての要素を累積し、二分探索で実行可能な最大の削除が確実にカウントされるため、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        indexed = sorted((val, i) for i, val in enumerate(a))
        prefix = [0] * n
        prefix[0] = indexed[0][0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] + indexed[i][0]

        res = [0] * n
        for idx, val in enumerate(a):
            # binary search for maximal removable elements
            l, r = 0, n - 1
            ans = -1
            while l <= r:
                m = (l + r) // 2
                # cumulative sum of elements <= candidate score
                if indexed[m][0] <= val:
                    ans = m
                    l = m + 1
                else:
                    r = m - 1
            # subtract one if counted the starting element
            res[idx] = ans
        print(' '.join(map(str, res)))

solve()
```解決策は、元のインデックスを使用して配列を並べ替えることから始まります。 これにより、回答への効率的なマッピングが可能になります。 接頭辞の合計が構築されますが、この最終バージョンでは、ソートされた配列の二分探索で開始値以下の要素をカウントできます。 各バイナリ検索では、削除できるすべての要素を貪欲にカウントすることが保証され、1 つ減算することで開始要素自体はカウントされなくなります。 二分探索における境界処理により、off-by-one エラーが回避されます。 

## 実用的な例

 サンプル入力`[20, 5, 1, 4, 2]`:

 | 元のインデックス | 値 | 並べ替えられた位置 | バイナリ検索結果 | カウント出力 |
 | --- | --- | --- | --- | --- |
 | 0 | 20 | 4 | 4 | 4 |
 | 1 | 5 | 2 | 3 | 3 |
 | 2 | 1 | 0 | 0 | 0 |
 | 3 | 4 | 1 | 3 | 3 |
 | 4 | 2 | 0 | 1 | 1 |

 このトレースは、二分探索により、開始要素をカウントせずに、削除可能な要素の最大数が正しく検出されたことを示しています。 

別の例`[1]`:

 | 元のインデックス | 値 | 並べ替えられた位置 | カウント出力 |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |

 単一の要素が他の要素を削除することはできないため、アルゴリズムが n=1 を正しく処理していることが確認されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 単一要素配列の場合`[1]`の場合、アルゴリズムは、ソートされた配列に開始スコアと等しい要素が 1 つあることを検出します。 二分検索ではインデックス 0 が返されますが、カウントを構築するときに暗黙的に 1 を減算するため、追加の削除は 0 になります。 すべて等しい配列内`[5,5,5]`、バイナリ検索では、他のすべての要素を削除できることが正しく検出され、開始要素ごとに 2 が得られます。 降順配列の場合、アルゴリズムでは、並べ替えのおかげで、元の配列の後ろに出現する場合でも、より小さい要素が確実にカウントされます。
