 ## 問題の理解

 タスクは、長さの配列を構築することです`n`すべての値は次の範囲にあります`1`そして`2n`、配列内の値は、異なる位置にある別の値を分割できません。 これら 2 つのルールを満たすこと以外は実際の値は重要ではないため、有効な構成はどれでも受け入れられます。 

制約`n <= 100000`の合計で`n`すべてのテストケースにわたって、以下に限定される`100000`解の出力サイズは線形に近いはずであることがわかります。 生成中`n`数字はすでにコストがかかります`O(n)`したがって、要素のすべてのペアを比較するなど、多くのペアのチェックを伴うものは、最大で`O(n^2)`操作。 

主な罠は、実装の複雑さではなく、適切な数値セットの選択にあります。 

よくある間違った考えは、最初の出力を出力することです。`n`正の整数。 たとえば、次の場合`n = 4`、配列`[1, 2, 3, 4]`すべての値が異なるため有効に見えますが、`2`分割する`4`, つまり条件違反です。 

もう 1 つの間違いは、明らかな反復因子のない集合を証明せずに選択することです。 たとえば、`n = 3`、`[2, 4, 5]`失敗する理由`2`分割する`4`。 建設は可能な限り物件を保証する必要があります`n`小さな例だけではありません。 

## アプローチ

 直接的なアプローチは、次から数値を繰り返し選択することです。`1`に`2n`選択した数値が、以前に選択した数値で割り切れるかどうか、または割り切れるかどうかをテストします。 これは、各要素を追加する前に必要な条件を明示的にチェックするため、正しいです。 ただし、最悪の場合、選択された値のほぼすべてのペアが比較されます。 と`n = 100000`、これは周りに届くことができます`10^10`これは、一般的な 1 秒の制限をはるかに超えています。 

重要な観察は、選択されたすべての数値が次の値より大きい場合、割り算は不可能になるということです。`n`。 からの間隔を考慮してください。`n + 1`に`2n`。 正確に含まれています`n`数値なので、配列を満たすのに十分な大きさです。 数字の場合`x`この間隔内にある、任意の適切な倍数`x`少なくとも`2x`より大きい`2n`。 配列全体には最大の数値のみが含まれるため、`2n`、選択した他の数値を次の倍数にすることはできません。`x`。 

これは、区間内のすべての数値のペアが自動的に安全であることを意味します。 全体の問題は、この間隔を出力することに帰着します。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、必要な配列サイズを読み取ります。`n`。 

構築は次の要素のみに依存します。`n`, したがって、他の情報を検査する必要はありません。 
2. 以下のすべての整数を出力します。`n + 1`を通して`2n`。 

まさにあります`n`このような整数なので、出力の長さは正しいです。 すべての値も許容範囲を満たしています。 
3. テスト ケースを終了し、次のテスト ケースに進みます。 

各テスト ケースは独立しており、出力の合計量は入力サイズによってすでに制限されています。 

なぜ効果があるのか:

 構築の背後にある不変条件は、選択されたすべての数値が以下より大きいということです。`n`。 選択された 2 つの異なる値が次のとおりであるとします。`x`そして`y`と仮定します`x`分割する`y`。 それらは異なるため、`y`の適切な倍数でなければなりません`x`、 意味`y >= 2x`。 しかし`x > n`、 それで`2x > 2n`。 これは、選択されたすべての値が最大でも次の値であるという事実と矛盾します。`2n`。 したがって、選択された値が別の値を除算することはできず、生成された配列は常に要件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        ans.append(" ".join(map(str, range(n + 1, 2 * n + 1))))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードはアルゴリズムからの構築を直接実装します。 テストケースごとに、`range(n + 1, 2 * n + 1)`からの値を正確に生成します`n + 1`に`2n`、包括的。 

の上限`range`排他的であるため、`2 * n + 1`が使用されます。 これを忘れると、`n - 1`数が多く、出力サイズ要件を満たしていません。 

このソリューションは出力行を保存し、それらをまとめて印刷します。 これにより、フラッシュの繰り返しが回避され、テスト ケースが多い場合でも入力と出力の効率が維持されます。
