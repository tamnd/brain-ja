 ## 解決策
 ## 問題の理解

 いくつかの独立した評価マシンが与えられています。 各マシンのスレッド数には制限があり、より多くのスレッドを使用すると、ランタイムの動作が大きく変わります。 

i 番目のマシンには、次のものがあります。$k_i$利用可能なスレッド。 正確に割り当てると$j$そのマシンへのタスク、そしてそれらのそれぞれ$j$タスクは時間の経過とともに実行されます$t_{i,j}$。 シーケンス$t_{i,1}, t_{i,2}, \dots, t_{i,k_i}$これは、負荷を追加しても単一スレッドが高速化するわけではないという直観と一致します。 

今では、$M$合計のコード提出数。 各提出物は何らかのマシンに割り当てる必要があり、各マシンには番号が割り当てられます。$a_i$の提出物、$0 \le a_i \le k_i$そして$\sum a_i = M$。 

割り当てはすべての有効な整数ベクトルの中から均一に選択されます。$(a_1, \dots, a_N)$これらの制約を満たすこと。 固定割り当ての場合、合計実行時間はマシン全体の合計です。$a_i \cdot t_{i,a_i}$。 この総和モジュロの期待値が必要です$10^9+7$。 

制約は、最大でも組み合わせの DP を意味します。$10^4$マシン全体の合計容量、最大$2 \cdot 10^3$機械。 すべての代入を単純に列挙するには、境界のある M のすべての構成を反復処理する必要がありますが、これは M 内で指数関数的に増加するため、不可能です。 

2 番目の単純なアイデアは、マシンごとに、その負荷の予想される寄与を個別に計算することですが、負荷の分布は$a_i$グローバル制約のため独立していない$\sum a_i = M$。 このカップリングが最大の難点です。 

マシンに能力がある場合、微妙なエッジケースが発生します$k_i < M$。 有効なディストリビューションはすべての容量を尊重する必要があるため、多くのマシンがすべての構成で飽和状態になる可能性があります。 単純な多項仮定では、無効な状態が誤って許容され、確率質量が過大にカウントされてしまいます。 

## アプローチ

 直接的なアプローチは、有効なベクトルをすべて列挙することです。$(a_1, \dots, a_N)$。 マシンごとに、次から値を選択します。$0$に$k_i$、そして合計制約を強制します。 マシン上での動的プログラミングや総負荷でも、状態空間のサイズが大きくなります。$O(NM)$、各遷移では最大で次のことが考慮されます。$k_i$オプション、与える$O(N \cdot M \cdot k_i)$、最悪の場合、遅すぎます。 

重要な観察は、代入空間は個々の容量によって制約されますが、その構造は有界な整数合成問題であるということです。 M 個の区別できないアイテムを上限のある N 個のボックスに分配します。 これは、各マシンが多項式に寄与するマシン上の生成関数としてモデル化できます。$$P_i(x) = \sum_{j=0}^{k_i} x^j$$分布をカウントするための、およびコストのための重み付けされたバリアントです。 

数だけでなく、すべての構成にわたるコストの合計も必要です。 これは、割り当てられたタスク全体にわたって 2 つの DP 配列を維持することを示唆しています。1 つは構成のカウント用で、もう 1 つは累積加重コスト寄与用です。 

各マシン i について、j 個のタスクを受け取ると決定すると、インデックスを j だけシフトすることですべてのグローバル状態に寄与します。 遷移は線形畳み込みであり、合計 M は最大でも$10^4$、ナップサック型のDPで十分です。 

微妙な改善点は、マシンごとに完全な組み合わせ列挙を必要とせず、境界のある j を越えるプレフィックス遷移だけを必要とすることを認識したことです。これにより、管理可能な結果が得られます。$O(NM)$解決。

 ## アルゴリズムのチュートリアル

 私たちは、これまでに処理された割り当てられた提出物の合計に対する DP を維持しています。 させて`dp_cnt[s]`割り当てられたタスクの合計が s になるように、処理済みマシンにタスクを割り当てる方法の数になります。 させて`dp_sum[s]`は、そのような割り当てすべての累積実行時間の合計になります。 

空の代入のみを使用して初期化します。 

### 1. 初期化

 セット`dp_cnt[0] = 1`そして`dp_sum[0] = 0`。 他のすべての状態はゼロです。 これは、まだ何も割り当てられていないことに相当します。 

### 2. 機械を 1 つずつ処理する

 各マシン i に対して、新しい DP アレイを構築します`ndp_cnt`そして`ndp_sum`現在の状態から。 

### 3. マシン i で実行可能なすべての負荷を試します。 

0 から k_i までの考えられる j ごとに、j 個のタスクをこのマシンに割り当てることを検討します。 負荷 j に対するこのマシンの寄与は次のとおりです。`j * t[i][j]`。 

この値は、以前に s 個のタスクがあったすべてのグローバル状態に適用され、新しい状態 s + j が生成されます。 

### 4. 遷移数

 それぞれの s と j について:

 追加します`dp_cnt[s]`の中へ`ndp_cnt[s + j]`なぜなら、j 個のタスクをマシン i に割り当てることで、既存のすべての構成を拡張できるからです。 

これにより、すべての有効な分布を 1 回だけカウントするという構造が維持されます。 

### 5. 遷移合計

 コストの寄与については、すべての拡張機能が以前の累積合計に新しいマシンのコストを加えたものに寄与します。`dp_sum[s] + dp_cnt[s] * (j * t[i][j])`。 

すべての構成が考慮されるため、これは正解です。`dp_cnt[s]`j を選択すると、マシン i から同じ追加コストがかかります。 

### 6. DP を交換する

 すべての j を処理した後、交換します`dp`と`ndp`。 

### なぜ効果があるのか

 どの時点でも、`dp_cnt[s]`すべてのマシンが制限された選択肢を超えて独立して貢献し、遷移が重複することなく正確な列挙を保持するため、合計 を達成する処理済みマシン間でタスクを分散する方法の数を正確にカウントします。 

のために`dp_sum[s]`、各構成はその累積コストに寄与し、マシンの選択 j によって拡張する場合、そのマシンの正しい限界コストに、前の状態に到達する構成の数を乗じた値を追加します。 これにより、すべての有効な割り当ての明示的な列挙に対する期待の線形性が保証されます。 

DP はすべての有効な構成を暗黙的に正確に列挙し、それぞれを正しい合計コストで重み付けするため、すべての最終状態を合計すると、必要な実行時間の合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N = int(input())
    
    machines = []
    total_cap = 0
    
    for _ in range(N):
        arr = list(map(int, input().split()))
        k = arr[0]
        t = arr[1:]
        machines.append((k, t))
        total_cap += k
    
    M = int(input())
    M = min(M, total_cap)
    
    dp_cnt = [0] * (M + 1)
    dp_sum = [0] * (M + 1)
    dp_cnt[0] = 1
    
    for k, t in machines:
        ndp_cnt = [0] * (M + 1)
        ndp_sum = [0] * (M + 1)
        
        for s in range(M + 1):
            if dp_cnt[s] == 0:
                continue
            base_cnt = dp_cnt[s]
            base_sum = dp_sum[s]
            
            for j in range(0, min(k, M - s) + 1):
                ways = base_cnt
                ndp_cnt[s + j] = (ndp_cnt[s + j] + ways) % MOD
                
                add_cost = (j * t[j - 1]) if j > 0 else 0
                ndp_sum[s + j] = (ndp_sum[s + j] + base_sum + ways * add_cost) % MOD
        
        dp_cnt, dp_sum = ndp_cnt, ndp_sum
    
    print(sum(dp_sum) % MOD)

if __name__ == "__main__":
    solve()
```コードは、説明どおりに 2 層 DP を実装します。 の`dp_cnt`配列は、各合計負荷につながる部分割り当ての数を追跡します。 の`dp_sum`配列は、それらすべての割り当てにわたる合計実行時間寄与を累積します。 

各マシンについて、可能なすべての割り当て j を試みます。 移行により、構成の数と累積コストの両方が更新されます。 オーバーフローを防ぐために、モジュロはすべてのステップに適用されます。 

微妙な実装の詳細は、コスト項が以前のマシンではなく、現在のマシンと選択された j にのみ依存することです。そのため、次のように直接追加できます。`ways * add_cost`。

 ### 例 1

 2 台のマシンを考えてみましょう。 

マシン 1: k=2、t=[1,2]

 マシン 2: k=1、t=[3]

 M = 2

 最初にマシン 1 を処理します。 

| s | dp_cnt | dp_sum |
 | --- | --- | --- |
 | 0 | 1 | 0 |

 マシン 1 の後:

 | s | 選択肢 | 新しい状態 |
 | --- | --- | --- |
 | 0 → 0 | j=0 | cnt=1 合計=0 |
 | 0→1 | j=1 | cnt=1 合計=1 |
 | 0→2 | j=2 | cnt=1 合計=4 |

 したがって、 dp は次のようになります。 

s=0: (1,0)、s=1: (1,1)、s=2: (1,4)

 マシン 2 以降:

 前の各状態は j=0 または 1 で分岐します。 

最終的な寄与はすべての有効な割り当てを結合し、dp_sum は合計実行時間を正しく累積します。 

### 例 2

 マシン 1: k=1、t=[5]

 マシン 2: k=1、t=[7]

 M=1

 両方のマシンを処理した後の有効な状態は、単一のタスクをマシン 1 またはマシン 2 に割り当てています。DP は正しく分割され、2 つの構成の合計は 5 + 7 に等しくなります。 

これにより、有効な割り当てがそれぞれ 1 回だけカウントされ、適切に重み付けされていることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、1 台を除くすべてのマシンの容量がゼロである場合です。 その場合、すべての M 個のタスクが 1 台のマシンに送信される必要があり、DP は 1 つの有効な構成に集約される必要があります。 k=0 のすべての遷移では j=0 のみが許可され、dp 状態が変更されずに維持されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、M が総容量を超える場合です。 コードは M を総容量に固定し、到達不可能な状態が決して考慮されないようにします。 これにより、不可能な構成への DP オーバーフローが回避され、実行時間が制限されます。 

3 番目のケースは、t[i][j] が j とともに急速に増加する場合です。 各状態はマシンの選択ごとに独立して重み付けされるため、t の単調性は正確さとは無関係であり、減速動作の現実的なモデリングのみを保証します。
