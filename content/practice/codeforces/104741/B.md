 ## 問題の理解

 次の重み付き無向グラフが与えられます。$N$場所と$M$道路。 2 人のプレイヤーがノードから開始します$1$そしてノードに到達したい$N$。 それらはグラフに沿って段階的に移動しますが、その移動には制約があります。現在のノードから、次に選択されるエッジはノードへの最短パス上に存在する必要があります。$N$。 言い換えれば、各ステップで、目的地までの残り距離に関して最適な状態を維持することが強制されます。 

ゲームはターン制です。 最初のプレイヤー (Little M) がノードから最初の手を選択します$1$、次にリトルIが次のものを選択し、それらが交互に行われます。 すでにノードにいるときに「移動」を強いられる人は誰でも$N$負ける、つまり到達する$N$ゲームは終了し、到着したばかりのプレイヤーは再び動くことはできませんが、対戦相手は何も動かないとみなされるため、説明したルール構造に従って勝ちます。 

両プレイヤーは最適なプレイをしており、リトル M (スターティング プレイヤー) が勝利を勝ち取ることができるかどうかを判断する必要があります。 

制約により、最大で次のことが許可されます。$10^5$ノードと$2 \cdot 10^5$テスト ケースごとのエッジ (最大 10 個のテスト ケース)。 これにより、すべてのパスにわたる 2 次または状態展開のアプローチが即座に除外されます。 どのような解も基本的にグラフ サイズが線形または線形に近いものでなければなりません。通常、$O(M \log N)$または$O(N + M)$。 

微妙な問題は、グラフにサイクルが含まれている可能性があるにもかかわらず、「最短パスに従わなければならない」ルールにより、ノードまでの最短距離によって引き起こされる有向非循環構造への再生が事実上制限されてしまうことです。$N$。 

最短経路制約を強制せずにこれをグラフ上の一般的なゲームとして扱うと、単純な間違いが発生します。 

たとえば、ノード 1 がノード 2 と 3 に接続し、両方が等しい重みで 4 (宛先) に接続する三角グラフを考えてみましょう。 単純なゲーム ソルバーは、任意の遷移を考慮し、サイクルや繰り返される状態を誤って評価する可能性があります。 正しい動作では、最短以外の遷移は完全に無視されます。 

ノードからの最短距離が計算される場合、別の失敗ケースが発生します。$1$ノードの代わりに$N$。 ゲームはゴールまでの距離の制約によって定義されるため、最短経路の計算のルートを逆にすると、許可される動きが不正確になります。 

## アプローチ

 ブルートフォース解釈は、現在のノードとそのターンから構成されるペアとしてゲームの状態をシミュレートします。 各状態から、すべての有効な最短パス エッジを試し、現在のプレーヤーが勝利を強制できるかどうかを再帰的に判断します。 論理的には正しいですが、これは、サイズが最短パスのサブグラフのエッジの数に比例するゲーム グラフを探索します。各ステップに複数の最短パスの継続が存在する場合、最悪の場合、指数関数的な分岐に退化します。 まで$10^5$ノードでは、これは完全に不可能です。 

重要な観察は、「常に最短経路に沿って移動しなければならない」ということです。$N$” ルールは、強い意味でサイクルを削除します。$dist[u]$～からの最短距離として$u$に$N$、その後、すべての有効な動きは厳密に減少します$dist$。 これは、ゲーム グラフが、エッジが長い距離から短い距離に向かう有向非巡回グラフになることを意味します。 

DAG が得られると、問題は標準的な勝利状態の DP になります。つまり、ポジションは、少なくとも 1 つの手が負けているポジションにある場合は勝ちであり、すべての手が勝ちのポジションに移動した場合は負けです。 エッジは常に長い距離から短い距離に向かうため、ノードを昇順に処理できます。$dist$から始まる$N$動きが存在しない場所。

 ## アルゴリズムのチュートリアル

 ゲームを最短経路制限有向グラフに変換し、それに対して標準の勝利状態動的プログラミングを実行します。 

1. すべてのノードからノードまでの最短距離を計算します。$N$ダイクストラのアルゴリズムを使用します。 これにより、各ノードについて、最適な移動の下で目標からどれだけ離れているかがわかります。 
2. すべての無向エッジについて$(u, v, w)$、有効な動きで使用できるかどうかを判断します。 エッジはから使用できます$u$に$v$もし、そしてその場合に限り$dist[u] = dist[v] + w$、同様に次から使用できます$v$に$u$もし$dist[v] = dist[u] + w$。 この方向性はもっぱら最短経路の一貫性によって引き起こされます。 
3. 各ノードをゲーム状態として扱います。 ブール値を定義する$dp[u]$「ノードで順番が回っているプレイヤー」を意味します$u$勝利を強制することができる。」
 4.初期化$dp[N] = False$に到着したため、$N$発信する有効な手が存在しないことを意味します。 
5. ノードを増加順に並べ替えます$dist[u]$。 これにより、最も近い状態から順に状態を処理することが保証されます。$N$外側に。 
6. 各ノードについて$u$この順序で、すべての近隣を調べます$v$に移動するように$v$は有効です (エッジの重みだけ距離が減少します)。 そのような近隣が少なくとも 1 つ存在する場合$v$どこ$dp[v] = False$、次に設定します$dp[u] = True$, 現在のプレイヤーが相手を負け状態に追い込むことができるからです。 
7. そのような動きが存在しない場合は、$dp[u] = False$。 
8. 答えは次のとおりです。$dp[1]$、ゲームはノードで開始されるため、$1$。 

### なぜ効果があるのか

 最短距離制限により、すべての有効な動きが厳密に値を減少させることが保証されます。$dist[u]$。 これにより、状態に対する厳密な順序付けが引き起こされ、ゲーム グラフ内のサイクルが防止されます。 その結果、すべての状態は厳密に小さい状態にのみ依存するため、処理ノードが増加します。$dist$順序により、必要なときにすべてのトランジションがすでに解決されることが保証されます。 すべての正当な手が 1 回だけ考慮され、勝利条件が DAG 上の標準的な通常プレイの組み合わせゲーム ロジックと一致するため、DP の繰り返しは正しいです。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))

    dist = [INF] * (n + 1)
    dist[n] = 0
    pq = [(0, n)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    nodes = list(range(1, n + 1))
    nodes.sort(key=lambda x: dist[x])

    dp = [False] * (n + 1)
    dp[n] = False

    for u in nodes:
        if u == n:
            continue
        for v, w in g[u]:
            if dist[u] == dist[v] + w:
                if not dp[v]:
                    dp[u] = True
                    break

    print("Little M is the winner." if dp[1] else "Little I is the winner.")

t = int(input())
for _ in range(t):
    solve()
```最初のフェーズでは、ダイクストラを使用して目的地からの最短距離を計算します。 動きは「に近づく」ことによって定義されるため、この逆転は不可欠です。$N$”、したがって、距離は次のように根づく必要があります。$N$。 

2 番目のフェーズでは、条件を使用して暗黙的にエッジをフィルターします。$dist[u] = dist[v] + w$。 これにより、有向グラフの明示的な構築が回避され、メモリが線形に保たれます。 

DP ループは、距離の増加順にノードを処理することに依存するため、すべてのノードが$dp[v]$計算する前にすでにわかっている$dp[u]$。 

よくある実装上の間違いは、複数のエッジが最短パス条件を満たすことができることを忘れていることです。 すべてチェックする必要があります。

 ## 特殊なケース

 クリティカルなエッジ ケースは、グラフにノードからの最短パス エッジが複数含まれているが、そのうちの一部のみが状態の喪失につながる場合です。 DP はそのようなすべてのエッジを考慮する必要があります。 最初の有効なエッジで早期に停止することは正しくありません。 このアルゴリズムは、DP 値を決定する前に、最短パスの等価条件を満たすすべての近隣ノードを明示的にチェックすることで、これを正しく処理します。 

もう 1 つの微妙なケースは、グラフに元の形式でサイクルが含まれている場合です。 有効な移動は距離を厳密に短縮する必要があるため、これらのサイクルは距離制約を適用すると消えます。$N$。 これにより、周期性の高い入力グラフであっても DP フェーズでは DAG のように動作し、アルゴリズムが明確に定義されたままになります。
