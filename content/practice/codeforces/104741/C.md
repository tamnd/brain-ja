 ## 解決策
 ## 問題の理解

 2 行 n 列のグリッドが与えられているため、2n 個のセルが長方形に配置されています。 各セルは黒または白のいずれかに色付けする必要があります。 唯一の制限は、2 つの黒セルが互いに隣接して接触できないことです。つまり、黒セル間の水平方向または垂直方向の隣接は許可されません。 

各テスト ケースには、数値 k も与えられており、非隣接ルールを尊重しながら正確に k 個のセルが黒となる有効な色がいくつ存在するかをカウントする必要があります。 答えは 998244353 を法として求められます。 

重要な制約は、n と k がテスト ケースごとに最大 100,000 まで、テスト ケースが 100,000 まで、すべてのテストの k の合計が 5×10^5 で制限されることです。 これは、テスト ケースごとに独立して k に依存するいかなる解も、あるいは n の二次関数も不可能であることを直ちに示します。 k は大きく、テスト全体で何度も繰り返される可能性があるため、テスト ケースごとに O(nk) であっても遅すぎます。 

微妙なエッジ ケースは、隣接関係が線ではなくグリッド内にあるという事実から生じます。 同じ列内の 2 つの垂直方向に隣接するものを両方とも黒にすることはできません。また、同じ行内の隣接する列にある 2 つの水平方向に隣接するものを両方とも黒にすることはできません。 たとえば、単一の列では、両方のセルを同時に黒にすることはできません。 

簡単な例として、n = 1、k = 2 があります。両方のセルを黒に着色する方法は 1 つだけありますが、これらは垂直方向に隣接しているため無効であり、答えは 0 になります。水平方向の隣接のみを禁止する単純な組み合わせアプローチでは、これが誤ってカウントされます。 

別の例は、n = 2、k = 2 です。有効な構成の 1 つは、黒のセルを (行 1、列 1) と (行 2、列 2) に配置することですが、両方の黒を同じ列に配置したり、水平に隣接して配置したりするような構成は禁止されています。 単純な「任意の k 個のセルを選択する」アプローチでは、隣接関係の制約がグローバルに適用されない限り、カウントが大幅にオーバーカウントされます。 

主な問題点は、制約が行と列の両方を結合するため、セルごとの局所的な独立性が保持されないことです。 

## アプローチ

 ブルートフォース手法では、2n 個のセルのすべての色が考慮され、隣接条件を満たしているかどうか、および正確に k 個の黒セルがあるかどうかがチェックされます。 このような色付けは 2^(2n) 通りあり、それぞれをチェックするだけでも O(n) かかり、まったく実行不可能です。 

もう少し構造化された総当たり攻撃は、各セルを独立して処理し、2n 個のセルから k 個のセルを選択しようとしますが、隣接するペアを含むそれらの選択を減算します。 これは、2×n グリッド グラフの隣接エッジに対する包含と除外に変わりますが、隣接制約が密な依存構造を形成するため、依然として指数関数的な複雑さが生じます。 

重要な観察は、黒いセルが 2×n グリッド グラフ内で独立したセットを形成していることです。 このグラフでは、サイズ k の独立したセットを数えています。 2×n グリッドの構造は、本質的にはラダー グラフであるため特別であり、よく知られた列状態への分解が行われます。 

個々のセルの観点から考えるのではなく、各列に含まれる黒のセルの数によって各列を分類します。 垂直方向の隣接により、列内の両方のセルが黒になることが禁止されるため、各列は最大 1 つの黒セルに寄与することができます。 したがって、有効な構成はすべて、いくつかの列を選択し、選択した各列を上部または下部のセルに割り当てることと同じです。 

残る唯一の制限は水平方向の隣接性です。列 i の行 1 のセルが黒の場合、列 i+1 の行 1 も黒にすることはできません。 行 2 についても同様です。これは 2 つの独立したパス (上の行と下の行) になりますが、各列が最大 1 つの黒セルをホストできるという事実によって組み合わされます。 

これにより、列ごとに 3 つの状態 (空、上部が選択された状態、下部が選択された状態) を持つ標準の DP が生成されます。

dp[i][j] を、j 個の黒セルを使用して最初の i 列を処理する方法の数として定義します。各行内で水平方向の隣接性がないことを確認しながら、i 番目の列が空、上部、下部のいずれであるかを追跡します。 

遷移はローカルです。列 i-1 の状態から列 i の状態まで、上部の後に上部を配置したり、下部の後に下部を配置したりしないようにするだけで済みます。 

この DP は O(nk) で実行されますが、それでも最悪の場合には遅すぎます。 

最後の最適化は、遷移が列間で同一であることに気づくことから始まり、これを畳み込みのようなプロセスとしてモデル化できます。 各列は小さな固定伝達行列に寄与し、反復多項式変換の k 番目の係数を効果的に計算しています。 これは、組み合わせの閉じた形式になります。選択された各黒セルは上部または下部のいずれかに配置されますが、同じ行内で 2 つの隣接する選択は許可されないため、各行内の選択は、長さ n のパス内の隣接しない位置を選択するのと同等です。 

したがって、問題は、上の行の黒セルに対して t 列を選択し、下の行の黒セルに対して k-t 列を選択することに分解されます。ここで、どちらの選択も長さ n のパス上の独立した独立セットの選択であり、同じ列を 2 回使用できないという追加の制約があります。 

これにより、t に関する畳み込みが行われ、各行は標準的な組み合わせの「隣接選択なし」選択数、C(n - t + 1, t) になります。 

したがって、最終的な答えは t の合計です。 

C(n - t + 1, t) * C(n - (k - t) + 1, k - t),

 有効性制約を使用して、引数が負でないことを保証します。 

これにより、列のオーバーラップ回避による結合により、グリッド制約が 2 つの独立した 1D 独立セット数にきれいに折りたたまれます。

 ## アルゴリズムのチュートリアル

 1. モジュラー演算を使用して、可能な最大 2n まで階乗および逆階乗を事前計算します。 これは二項係数を効率的に評価するために必要です。 
2. 各テスト ケースについて、考えられるすべての t の値を反復します。ここで、t は、最上行の黒セルが割り当てられた列の数です。 このパラメータは、2 つの行間で k 個の黒セルを分割する方法を制御します。 
3. 固定 t の場合、最上位行の選択は、n 列の中から隣接しない t 列を選択することと解釈されます。これは、それらの間に少なくとも 1 つのギャップがある t 位置を選択することと同等です。 このような選択の数は C(n - t + 1, t) として計算されます。 この変換は、隣接を避けるために、選択された各位置を必須のギャップで圧縮することで実現されます。 
4. 同様に、一番下の行に割り当てられた k - t 個の黒セルを解釈し、C(n - (k - t) + 1, k - t) の可能性を与えます。 
5. 列の重複制約が構築によって処理されると、上部と下部の行の選択肢は独立するため、これら 2 つのカウントを乗算します。 
6. 両方の二項引数が負でない、有効な t 値をすべて合計します。 

### なぜ効果があるのか

 有効な各色は、上の行で使用される列と下の行で使用される列の 2 つの列セットに一意に分解できます。 各行内では、非隣接制約により、標準的な「連続選択なし」構造が強制されます。これは、シフトされた二項係数式によって正確に捕捉されます。 両方の行が同じ列を選択することを防ぐ結合制約は、列を上部と下部の選択の間で分割することによって適用されます。 すべての有効な構成は 1 つの分割値 t に正確に対応するため、合計が過大にカウントされたり、構成が欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX = 100000 + 5

fact = [1] * (MAX)
invfact = [1] * (MAX)

for i in range(1, MAX):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAX - 1] = pow(fact[MAX - 1], MOD - 2, MOD)
for i in range(MAX - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

t = int(input())
out = []

for _ in range(t):
    n, k = map(int, input().split())
    if k > 2 * n:
        out.append("0")
        continue

    ans = 0

    for top in range(0, k + 1):
        bottom = k - top
        if top <= n and bottom <= n:
            ways_top = C(n - top + 1, top)
            ways_bottom = C(n - bottom + 1, bottom)
            ans = (ans + ways_top * ways_bottom) % MOD

    out.append(str(ans))

print("\n".join(out))
```階乗前処理により、すべての二項係数を一定時間で計算できます。各テスト ケースは最大 O(k) 回の反復を実行しますが、テスト全体の k の合計には制限があるため、これは不可欠です。 

ループオーバー`top`は、アルゴリズムの分解パラメータ t に直接対応します。 小切手`top <= n`そして`bottom <= n`不可能な独立セットのサイズを試行しないようにしてください。 各項は、隣接しない位置を選択するためのシフト二項式を使用して計算されます。 

最終的な累積は、すべての有効な分割に対する畳み込みを反映します。

 ## 特殊なケース

 k が 2n を超えると、隣接制約に関係なく、グリッドに十分な黒セルを含めることができなくなります。 この場合、実装は明示的に 0 を返し、無効な階乗クエリを防ぎます。 

k = 0 の場合、全白のグリッドのみが存在します。 分割上のループには、top = 0、bottom = 0 のみが含まれており、C(n+1,0)^2 = 1 が生成されます。 

k = n または n に近い場合、多くの二項引数はゼロまたは負になり、結合関数によって自然にそれらが除外されます。 これにより、行間の特別な大文字と小文字の境界分布が回避されます。 

微妙なケースは、すべての黒セルが 1 つの行になければならない場合です。 たとえば、n = 5、k = 3、top = 3、bottom = 0 では C(3,3) * C(6,0) = 1 が生成され、隣接することなく 1 行内の完全に分離された配置が正しくカウントされます。
