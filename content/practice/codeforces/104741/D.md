 ## 解決策
 ## 問題の理解

 平面内には、それぞれが村を表す N 個の異なる点のセットが与えられます。 これらの村のうちちょうど 2 つを通過する直線を選択したいと考えています。 この線は 2 つの領域間の境界として使用されます。 

厳密に線の一方の側にあるすべての村は 1 つの国に属し、反対側のすべての村はもう一方の国に属します。 ライン上に正確に位置する村は両側で共有されていると見なされますが、その中でラインの選択された 2 つの端点のみが「ポート」として扱われるため、ラインは常に順序付けられた個別の点のペアによって定義されます。 

要件は、そのような線を引いた後、結果として得られる 2 つの国に同じ数の村が含まれていなければならないということです。 村を定義する 2 つの村のうち、順序付けされていない選択肢がいくつあると、有効なバランスの取れた分割が生成されるかを数えなければなりません。 幾何学的対称性や向きに関係なく、選択した村のペアが異なる場合、2 つの選択肢は異なるものとみなされます。 

制約は N から 2000 までで、座標の大きさは最大 10^9 です。 これにより、単純な三重ネストの方法ですべての幾何学的分離を明示的に評価しようとするアプローチは即座に除外されます。 3 次 O(N^3) 法では、候補線ごとに他のすべての点を分類しようとするため、最悪の場合、制限をはるかに超える約 8×10^9 の演算が必要になります。 O(N^2 log N) であっても慎重に扱う必要がありますが、N^2 は約 4×10^6 であるため、おそらく許容可能です。 

微妙な点は、共線性の処理です。 複数の点が同じ線上にある場合、正確に線上にある点の「辺」の定義が曖昧になります。 ゼロのケースを慎重に処理せずに単純に外積を使用する単純なアプローチでは、ポイントを二重にカウントしたり、誤って分類したりする可能性があります。 

別のエッジ ケースは、多くの点が対称であるか、凸状の位置にある場合に発生します。 たとえば、すべての点が凸多角形の頂点である場合、各ペアは予測可能な方法で有効な分割線を定義しますが、内部の縮退は消えます。 逆に、多くの点が同一線上にある場合、すべての候補ラインには多くの点が含まれており、単純に「左/右」をカウントすることで、ライン上の点が二重にカウントされることを回避する必要があります。 

## アプローチ

 ブルートフォースアプローチは、順序のない点のペアをすべて候補線として選択することから始まります。 各ペアについて、有向線に対する方向 (外積符号) を計算することにより、1 つおきの点を分類します。 これにより、点が左側にあるのか、右側にあるのか、それとも直線上にあるのかがわかります。 

次に、ペアごとに、各側にあるポイントの数を数えます。 k 個の共線点を除外した後、両側に正確に (N - k) / 2 点が含まれている場合 (k には 2 つの端点とその他の共線点が含まれます)、結果の分割がバランス条件を満たすかどうかを確認します。 これにはペアごとに O(N) の作業が必要となり、合計の複雑さは O(N^3) になります。 

明らかにボトルネックは、すべてのペアのすべてのポイントを繰り返しスキャンすることです。 重要な観察は、実際には各ペアを個別に完全に再計算する必要はないということです。 代わりに、ピボット ポイントを中心とした角度順序を利用できます。 

点 i を修正します。 他のすべての点を i の周りの極角で並べ替えると、2 番目の点 j について、線 ij は円を 2 つの半平面に分割します。 問題は、180 度の角度間隔内にいくつの点が収まるかを数えるということになります。 円形配列上で 2 ポインターをスイープすると、O(N) の各 i について有効な反対側の分割を効率的にカウントできます。 

これにより、問題は、各 i について、いくつの j が有向線 ij の片側に (N - 2) / 2 個の点を正確に生成するかを計算することになります。 角度スイープはすべての方向を自然に処理し、ジオメトリを最初から再計算する必要がなくなります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3) | お(1) | 遅すぎる |
 | ピボットごとの角度スイープ | O(N^2 log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各点 i をアンカーとして固定し、そこから発生するすべての線を分析します。 

1. 固定点 i について、i から他の点 j までのベクトルを計算します。 各ベクトルは平面内の方向を表します。 
2. これらのベクトルを極角ごとに並べ替えます。 これにより、ジオメトリを尊重しながら、i の周りの循環順序付けを線形配列として扱うことができます。 
3. 角度を 2π ずらして同じベクトルを再度追加して、ソートされたリストを複製します。 これにより、循環次数全体にわたってウィンドウをスライドさせるときのモジュラー演算が回避されます。 
4. 元のリストの各 j について、線 ij で定義される半平面内に点がいくつあるかを求めます。 2 ポインター手法を使用します。角度差が π を超えるまでポインター k を進めます。 
5. この角度順序での j と k の間の点の数は、直線 ij の片側の点に対応します。 
6. このカウントが正確に (N - 2) / 2 に等しいかどうかを確認します。等しい場合、ペア (i, j) は有効なパーティションを形成します。 

i が固定され、j がソート順の前半分とみなされる場合、有効な各ペアは 1 回カウントされます。 

### なぜ効果があるのか

 1 つの端点 i を固定すると、幾何学的条件が循環順序付け問題に変換されます。 i を通る線は残りの点を 2 つの半平面に分割し、それらの半平面は i の周りの角度順序で連続する円弧に正確に対応します。 2 ポインター ウィンドウにより、方向 ij から 180 度回転内にある点を正確にカウントできることが保証されます。 すべての有効な行には正確に 2 つのエンドポイントがあるため、エンドポイントごとに 1 回検出され、列挙を制限することで正確さを維持しながら二重カウントを防止します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    if n % 2 == 1:
        print(0)
        return

    ans = 0

    for i in range(n):
        x0, y0 = pts[i]
        vec = []
        for j in range(n):
            if i == j:
                continue
            x, y = pts[j]
            vec.append((x - x0, y - y0))

        def half(v):
            x, y = v
            return (y < 0) or (y == 0 and x < 0)

        vec.sort(key=lambda v: (half(v), v[0] * v[0] + v[1] * v[1]))

        m = len(vec)
        vec2 = vec + vec

        target = (n - 2) // 2
        j = 0

        for k in range(m):
            if j < k:
                j = k
            while j < k + m:
                dx1, dy1 = vec[k]
                dx2, dy2 = vec2[j]
                cross = dx1 * dy2 - dy1 * dx2
                if cross > 0:
                    j += 1
                else:
                    break

            cnt = j - k - 1
            if cnt == target:
                ans += 1

    print(ans // 2)

if __name__ == "__main__":
    solve()
```実装の中核は、ピボット ポイントごとの角度スイープです。 の`half`関数は、浮動小数点角度を使用せずにベクトルの一貫した順序を定義し、平面を 2 つの半分に分割するため、並べ替えが正しく安定します。 

二重化された配列`vec2`これにより、モジュラー演算を行わずに循環トラバーサルをシミュレートできます。 2 ポインター ウィンドウは、明示的な角度計算の代わりに外積符号によって測定される角度差が π を超えるまで拡張されます。 

条件`ans // 2`各有効行は各エンドポイントから 1 回カウントされるため、必須です。 この修正がなければ、すべての解のペアが二重にカウントされてしまいます。

 ## 特殊なケース

 奇数 N の場合、アルゴリズムはすぐに 0 を返します。 奇数の点を持つ構成は、N - 2 が奇数になり、等しい整数の辺を形成できないため、2 つの端点を削除した後、2 つの等しい整数の半分に分割することはできません。 

同一直線上にある構成の場合、ピボットからのすべてのベクトルは 1 つの線上にあります。 並べ替えは退化しますが、タイブレークによって安定した順序が確保されるため、有効なままになります。 2 ポインタ ウィンドウは、相互積比較が一貫してゼロまたは片側のみと評価され、誤った有効な分割を防ぐため、反対側の半平面を誤ってカウントすることはありません。
