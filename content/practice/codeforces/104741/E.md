 ## 解決策
 ## 問題の理解

 各評価サーバーは、複数のスレッドを使用して送信を並行して処理できますが、各スレッドの効率は、そのサーバー上でアクティブなスレッドの数によって異なります。 特定のサーバーで実行されている場合、$j$スレッドの場合、それらの各スレッドには一定の時間がかかります$t_j$1 つの送信の処理を終了します。 これらの値は、スレッドを追加しても個々のスレッドが高速になるわけではなく、指定された配列によってキャプチャされた競合の影響を反映するだけであるという意味で、効率の順に増加するものではありません。 

今$M$提出物は一緒に届きます。 各提出物は次のいずれかに割り当てられます。$N$サーバー。 割り当てはランダムですが、サーバーが最大スレッド容量を超えるタスクを受信しないように制限されています。$k_i$。 割り当てが修正されると、各サーバーは、割り当てられたすべてのスレッドを使用して、割り当てられたタスクを並行して処理し、その完了時間は$t_{x_i}^{(i)}$、 どこ$x_i$割り当てられたタスクの数です。 最も遅いサーバーが終了するとシステム全体が終了するため、最終的な実行時間はすべてのサーバーの最大値となります。 

目標は、すべての有効なランダムな割り当てに対する全体的な完了時間の期待値を計算することです。 

制約は非常に具体的な意味で重要です。 総投稿数と総スレッド容量は両方とも最大約$10^4$、サーバーの数は最大です$2 \times 10^3$。 有効な割り当ての数は指数関数的であるため、これにより、タスクのすべての分布を明示的に列挙するアプローチは即座に除外されます。$M$。 制約内の構造を利用しない限り、すべての状態にわたる完全な確率分布を保存するだけでも大きすぎます。 

微妙な問題は、ランダム性が通常の意味でサーバーごとに独立していないことです。 私たちは、各提出物を独立して拒否に割り当てるのではなく、すべての有効な境界付き構成から均一にサンプリングします。 これにより、素朴な製品分布の推論が破壊され、組み合わせまたは DP ベースの計数アプローチが強制されます。 

素朴な推論による典型的な失敗例は、独立性を前提とすることです。 

たとえば、次の場合$N = 2$、$k_1 = k_2 = 2$、$M = 2$、独立した割り当てでは、有効なペアに対する一様サンプリングとは異なる確率が得られます。$(x_1, x_2)$と$x_1 + x_2 = 2$。 有効な状態は次のとおりです。$(0,2), (1,1), (2,0)$、それぞれの確率は同じです。 独立性があると、中間構成が誤って過大評価されてしまいます。 

もう 1 つの落とし穴は、ランタイムが負荷のみに依存することを無視していることです。$x_i$、割り当て命令ではありません。 これは、すべてのランダム性をシーケンスではなくカウントする整数ベクトルに圧縮できることを意味します。 

## アプローチ

 直接的なアプローチは、有効な割り当てをすべて列挙することです。$M$タスクを$N$容量制限下のマシンでは、各構成の最大実行時間を計算し、結果を平均します。 各構成は確定的な完了時間に対応するため、これは概念的には簡単です。 

ただし、有効な構成の数はすでに膨大です。 小さくても$M = 10^4$そして$N = 2000$、境界のある構成の数は、制限された星と棒の問題のように組み合わせ的に増加します。 明示的な列挙は実行不可能であり、圧縮なしですべてのマシンと負荷に対する動的プログラミングでさえ、指数関数的に多くの状態を追跡する必要があります。 

重要な観察は、実際には負荷の完全な分散を知る必要がないということです。 答えは、マシンの最大実行時間によってのみ決まります。 これは、問題を反転することを示唆しています。期待される最大値を直接計算する代わりに、最大実行時間がしきい値以下である確率を計算します。$T$、そしてその累積分布から期待値を再構築します。 

固定閾値の場合$T$、各マシン$i$ある制限までの荷重しか受け入れられません$f_i(T)$、最大のものとして定義されます$j$そのような$t_j^{(i)} \le T$。 マシンがそれ以上のデータを受信した場合、$f_i(T)$タスクを実行すると、しきい値を超える可能性があります。 したがって、固定の場合$T$、有効なグローバル構成はまさにこれらの整数ベクトルです$x_i$そのような$0 \le x_i \le \min(k_i, f_i(T))$そして$\sum x_i = M$。 これらの構成をカウントすると、有界ナップザック DP になります。 

それぞれのしきい値条件を満たす割り当ての数を数えることができたら、$T$、有効な割り当ての総数で割ると、答えの累積確率分布が得られます。 次に、期待値はしきい値を合計することによって再構築されます。 

これにより、問題は、ランダムな負荷に対する複雑な最大値についての推論から、単調なパラメータ変化を伴う一連の制約された計数問題に軽減されます。

 ## アルゴリズムのチュートリアル

 指定された条件によって決定される実行時間のしきい値を徹底的に調べて問題を処理します。$t_j^{(i)}$価値観。 

1. 任意の時間に現れるすべての個別の時間値を収集します。$t_j^{(i)}$、それらを並べ替えて、しきい値の候補として扱います。$T$。 各しきい値は、特定の負荷の実現可能性が変化するポイントを表します。 答えは次の場合にのみ変わるため、これで十分です。$f_i(T)$が増加します。 
2. マシンごとに$i$、および各しきい値について$T$、計算する$f_i(T)$、時間を超過することなくサポートできるタスクの最大数$T$。 これは、モノトーン配列に対するプレフィックス タイプのルックアップです。$t_j^{(i)}$。 
3. 容量制限を定義する$c_i(T) = \min(k_i, f_i(T))$。 これらは、マシンに実行されるタスクの数の有効な上限です。$i$ランタイムを維持しながら受信できる$T$。 
4. 整数解の数を数えます。$\sum x_i = M$と$0 \le x_i \le c_i(T)$。 これは、古典的な境界付きナップザック DP オーバー マシンです。 DP 配列を維持します。$dp[s]$これまでに処理されたマシンにタスクを割り当てる方法の総負荷数です。$s$。 
5. 有効な割り当ての合計数でカウントを正規化します (一度に計算されます)。$T = \infty$、つまり、を使用します$c_i = k_i$) を取得する$P(\text{max runtime} \le T)$。 
6. しきい値を合計して累積分布を期待値に変換します。$$\mathbb{E}[X] = \sum_T T \cdot (P(X \le T) - P(X \le T_{\text{prev}})).$$正確さは、ランタイムがこれらの離散しきい値イベントに対するステップ関数であるため、すべての確率質量が入力配列に存在する値でのみシフトするという事実に依存します。 

### なぜ効果があるのか

 任意の固定割り当てベクトルの場合$(x_1, \dots, x_N)$、ランタイムは正確に$\max_i t_{x_i}^{(i)}$。 この値は常に既存の値の 1 つと等しくなります。$t_j^{(i)}$、決してその間のものではありません。 したがって、すべてを並べ替えると、$t_j^{(i)}$あらゆる可能性のある明確な結果を捉えます。 

各しきい値の DP は、誘導された最大値がそのしきい値を超えない構成の数を正確にカウントします。 すべての構成は割り当ての合計空間内で 1 回だけカウントされるため、比率は正しい累積確率分布を形成します。 期待値の再構築は、離散確率変数の標準恒等式となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_dp(dp, limit, m):
    ndp = [0] * (m + 1)
    ndp[0] = 1
    for i in range(len(limit)):
        cap = limit[i]
        # prefix dp for bounded knapsack
        new = [0] * (m + 1)
        for s in range(m + 1):
            if dp[s] == 0:
                continue
            for add in range(cap + 1):
                if s + add <= m:
                    new[s + add] += dp[s]
        dp = new
    return dp

n = int(input())
ks = []
t = []

all_times = set()

for _ in range(n):
    arr = list(map(int, input().split()))
    k = arr[0]
    ks.append(k)
    ts = arr[1:]
    t.append(ts)
    for v in ts:
        all_times.add(v)

m = int(input())

times = sorted(all_times)

# precompute full count (denominator)
def calc(limit_fn):
    dp = [0] * (m + 1)
    dp[0] = 1
    for i in range(n):
        cap = limit_fn(i)
        ndp = [0] * (m + 1)
        for s in range(m + 1):
            if dp[s] == 0:
                continue
            for add in range(cap + 1):
                if s + add <= m:
                    ndp[s + add] += dp[s]
        dp = ndp
    return dp[m]

def get_limit(i, T):
    arr = t[i]
    k = ks[i]
    # find largest j with arr[j] <= T
    j = 0
    while j < k and arr[j] <= T:
        j += 1
    return min(k, j)

den = calc(lambda i: ks[i])

prev = 0
ans = 0

for T in times:
    def lim(i):
        return get_limit(i, T)
    num = calc(lim)
    prob = num / den
    ans += T * (prob - prev)
    prev = prob

print(ans)
```実装はしきい値 DP 構造に従います。 機能`calc`マシン上の階層化されたナップザック DP を使用して、マシンごとの容量制約の指定されたセットに対する有効な負荷分散の数を計算します。 ヘルパーさん`get_limit`単調なパフォーマンス配列をスキャンすることで、時間しきい値をマシンごとの使用可能な容量に変換します。 

累積確率の減算は、離散的な実行時レベルにわたる段階的な分布から期待値を再構築するものです。 

実装上の微妙な懸念は、DP カウント内の整数の増加です。 実際には、これらの値は非常に大きくなる可能性があるため、正しい解決策を得るには、元の問題の仕様に応じてモジュラー演算または合理的な処理が必要になるのが通常です。 ここでは、正しさの構造を維持するために、それを記号的に保ちます。 

## 実用的な例

 2 台のマシンと 2 つのタスクを備えた小規模なシステムを考えてみましょう。 

マシン 1 には、$k_1 = 2$、回$[5, 8]$。 マシン 2 には、$k_2 = 2$、回$[6, 7]$。 させて$M = 2$。 

有効な負荷分割はすべて次のとおりです。$(0,2), (1,1), (2,0)$。 

各構成について:

 | x1 | ×2 | ランタイムM1 | ランタイムM2 | 最大 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 7 | 7 |
 | 1 | 1 | 5 | 6 | 6 |
 | 2 | 0 | 8 | 0 | 8 |

 ここで閾値を考えてみましょう$T = 6$。 マシン 1 では 1 つのタスクが許可され、マシン 2 では 1 つのタスクが許可されます。 有効な割り当ては次のとおりです。$(1,1)$。 それで$P(X \le 6) = 1/3$。 

閾値について$T = 7$、マシン 1 では引き続き 1 つのタスクが許可され、マシン 2 では 2 つのタスクが許可されます。 有効な割り当ては次のとおりです。$(0,2), (1,1)$、 それで$P(X \le 7) = 2/3$。 

のために$T = 8$、すべての割り当てが有効であるため、確率は 1 になります。 

これは、累積確率が観測された時間値で正確にジャンプし、DP の動作と一致する様子を示しています。 

容量が少ない 2 番目の例は、確率ではなく制約が DP 空間を直接制限する方法を示しており、確率の重み付けではなく実現可能性が計算を駆動することを強化しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのマシンの時間曲線が同一である場合です。 その状況では、すべての有効な負荷ベクトルがすべてのしきい値に等しく寄与し、DP は純粋な制限された構成数に減少します。 アルゴリズムはこれを処理します。$f_i(T)$はマシン間で同一になるため、容量ベクトルは対称のままとなり、ナップザック DP は自然に対称状態をカウントします。 

別のエッジケースが発生するのは次の場合です。$M$総容量に等しい$\sum k_i$。 この場合、大きなしきい値に対して有効な構成は 1 つだけ存在し、累積確率は鋭い階段関数になります。 各マシンが常にその能力を最大限に活用するため、DP は正しく折りたたまれます。 

最後のエッジケースは、すべてが$t_j^{(i)}$は大きなギャップを持って厳密に増加しています。 ここで、各しきい値はマシンごとに 1 つの追加負荷レベルをアクティブにし、DP は離散点でのみ更新されます。 アルゴリズムは連続性をまったく想定しておらず、入力値によって駆動される離散的なしきい値の変更のみを想定しているため、これを正しく処理します。
