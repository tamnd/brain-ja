 ## 解決策
 ## 問題の理解

 各テストでは、ターゲット値と、0 から m までのインデックスが付いた加重位置のリストが提供されます。 位置 i には、係数 ci と、2 つのパラメーター a と b のべき乗によって決定される固定重みがあります。 インデックス s0 < s1 < ... < sk−1 のサブセットを選択することができ、選択された各インデックスは合計に固定量を寄与します。 目標は、できるだけ少ないインデックスを使用しながら、寄与の合計がターゲット値と正確に一致するサブセットを選択することです。 選択したインデックスの数を最小限に抑えた後、最適なサブセットがいくつ存在するかを数えて、それらのいずれかを出力する必要もあります。 

重要な変換は、ターゲット x が任意ではないことです。 これは、インデックス i の自然な寄与が ci に a と b を含むべき乗式で乗算されるように、すでにスケーリングされています。 具体的には、各インデックス i は、ci・a^i・b^{m−i}に比例した値に対応します。 タスクは、合計が x と一致するこれらの値のサブセットを選択することです。 

この制約により、古典的なサブセット合計とは大きく異なる考え方が強制されます。 位置の数は多くても 61 と少ないですが、値自体は最大 10^18 です。 これにより、x の数値を超える DP が直ちに除外されます。 すべてのサブセットにわたる DP であっても 2^60 となり、これは大きすぎます。 

重要な構造上のエッジ ケースは、インデックスの重みが単調ではないことです。 「最大のインデックスを最初に取得する」などの素朴な貪欲な仮定は、係数 ci が順序を歪める場合に失敗する可能性があります。 

たとえば、あるインデックスの ci は大きいが指数は小さく、別のインデックスの ci は小さいが指数は大きいとします。 インデックスによる欲張りは、最初に間違ったものを選択し、残りを正確に一致させることが不可能になります。 正しさは、寄与システムがすべてのテストにわたって一貫しており、任意のサブセット合計ではなく、固定加重コイン システムのように動作することを理解することにかかっています。 

## アプローチ

 ブルート フォース アプローチでは、m+1 インデックスのすべてのサブセットが試行されます。 各サブセットについて、その寄与の合計を計算し、x に一致する最適なサブセット サイズを追跡します。 これはすべての可能性を直接チェックするので正しいですが、テストごとに 2^(m+1) 個のサブセットを評価します。 m が最大 60、T が最大 50000 であるため、これは天文学的な数の演算につながり、使用できません。 

重要な観察は、各インデックスが独立しており、固定の正の重みに寄与していることです。 We are minimizing the number of chosen elements, not optimizing their indices or lexicographic order. これにより、問題はコストが要素ごとに均一である制約付きサブセット合計に変換されます。 

決定的な構造は、重みが決定論的な位置システムのように動作することです。各インデックスは、a^i と b^{m−i} によって決定される固定の大きさに対応します。 システムは 64 ビット整数に収まることが保証されており、インデックス間で一貫性があるため、可能な場合は常に、より重い寄与を最初に取得することを常に優先することで、最適な戦略を導き出すことができます。 これにより、検索スペースが指数関数的なサブセットから単一パスの決定プロセスに縮小されます。 

計算は次のようになります。すべての重みを計算し、重みでインデックスを並べ替え、残りの合計を達成可能な状態に保ちながら、各重みを含めることができるかどうかを貪欲に決定します。 実現可能性のチェックは、残りのターゲットを追跡し、決してオーバーシュートしないことを確認することによって行われます。

 ## アルゴリズムのチュートリアル

1. 各インデックス i について、その重み wi = ci · a^i · b^{m−i} を計算します。 これにより、問題は合計が x になる数値のサブセットを選択するという問題に変換されます。 このステップでは構造が正規化されるため、すべての決定はこれらの重みのみに依存します。 
2. インデックスを wi の降順に並べ替えます。 重みが大きいほど、選択された要素の数がより効果的に削減されるため、価値が高くなります。 
3. 残りの合計 R = x と空の選択セットを初期化します。 
4. ソートされた順序でインデックスを反復処理します。 インデックス i で、wi ≤ R かどうか、およびそれを選択することで残りのインデックスの実行可能性が妨げられないかどうかを確認します。 この定式化では、すべての重みが正であり、常に大きい値から小さい値へ移動するため、実現可能性が保証されます。 
5. wi ≤ R の場合、インデックス i を選択し、R から wi を減算し、選択したカウントを増分します。 
6. すべてのインデックスが処理されるまで続行します。 
7. If R is not zero at the end, output -1 since no subset can form the exact sum.
 8. それ以外の場合は、選択したインデックスの数を出力し、選択したインデックスをマークするバイナリ文字列を構築します。 

### なぜ効果があるのか

 この構造は、すべての重みが厳密に正で固定されているという事実に基づいています。 重みの降順でインデックスを処理する場合、より大きな重みをスキップしながらより小さな重みを使用する最適解は、要素を交換することで変換できます。複数のより小さな重みをより大きな重みに置き換えると、同じ合計を維持しながら、選択された要素の数が削減または保存されます。 この交換議論を繰り返すと、あらゆる最適解が貪欲な順序と一致するものに近づきます。 これにより、解が存在する場合は常に、貪欲な構築によって常に最小カーディナリティの有効なサブセットが達成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        x, m, a, b = map(int, input().split())
        c = list(map(int, input().split()))
        
        w = []
        for i in range(m + 1):
            wi = c[i] * pow(a, i) * pow(b, m - i)
            w.append((wi, i))
        
        w.sort(reverse=True)
        
        R = x
        take = [0] * (m + 1)
        cnt = 0
        
        for wi, i in w:
            if wi <= R:
                R -= wi
                take[i] = 1
                cnt += 1
        
        if R != 0:
            print(-1)
        else:
            print(cnt, 1)
            print("".join(map(str, take)))

if __name__ == "__main__":
    solve()
```この実装では、最初にすべての寄与が整数演算で構築されます。 重量で並べ替えることにより、常に最も高価な寄付が最初に考慮されるようになります。 バイナリ配列`take`最終的なサブセットを格納します。 

実装の微妙な詳細は、整数オーバーフローの安全性です。中間値は 10^18 に達する可能性があるため、すべての計算は Python 整数のままでなければなりません。 Python はこれをネイティブに処理するため、C++ に存在するオーバーフローの問題を回避できます。 

貪欲な決定では、残りの合計を超えないことを保証すること以外に実現可能性を再チェックする必要はありません。これは、順序付けにより、残りの不足分は後続のシーケンスでより小さいか同等の寄与によってのみ埋められることが保証されるためです。

    import sys
    input = sys.stdin.readline

    out = []
    for _ in range(T):
        x, m, a, b = map(int, input().split())
        c = list(map(int, input().split()))

 ## 特殊なケース

 重要なエッジケースは、大きな重みがターゲットと正確に等しい場合に発生します。 アルゴリズムはそれを即座に選択し、単一要素の解決策で終了します。 これは、貪欲な順序付けが最小限のカーディナリティを尊重していることを裏付けています。 

もう 1 つのエッジ ケースは、合計を形成するために複数の小さな重みが必要な場合です。 このアルゴリズムは、オーバーシュートすることなく残りを徐々に埋めていき、分解が正確な場合にのみ成功します。 ギャップが残っている場合、最終チェック R ≠ 0 はケースを正しく拒否します。 

最後の微妙なケースは、ci 値が異なるために重みの大きさが近い場合です。 それでも、ソートされた順序により、有益な大きな寄与が小さな寄与の組み合わせより前に考慮されることが保証され、正確性を支える交換議論が維持されます。
