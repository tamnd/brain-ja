 ## 問題の理解

## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 固定クエリの場合、その桁から可能な最小の塩基を決定し、16 までのすべての有効な塩基をテストします。

5. すべての桁を処理した後、残りのキャリーが次の残りの桁と一致することを確認します。$S$。 すべてが一貫している場合は、このベースを受け入れて出力します。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def ok(a, b, s, base):
    carry = 0
    i = len(a) - 1
    j = len(b) - 1
    k = len(s) - 1

    while k >= 0:
        av = val(a[i]) if i >= 0 else 0
        bv = val(b[j]) if j >= 0 else 0
        sv = val(s[k])

        total = av + bv + carry
        if total % base != sv:
            return False
        carry = total // base

        i -= 1
        j -= 1
        k -= 1

    while i >= 0 or j >= 0:
        av = val(a[i]) if i >= 0 else 0
        bv = val(b[j]) if j >= 0 else 0
        total = av + bv + carry
        carry = total // base
        if total % base != 0:
            return False
        i -= 1
        j -= 1

    return carry == 0

def solve():
    T = int(input())
    for _ in range(T):
        a, b, s = input().split()

        max_digit = 0
        for ch in a + b + s:
            max_digit = max(max_digit, val(ch))

        for base in range(max_digit + 1, 17):
            if ok(a, b, s, base):
                print(base)
                break

if __name__ == "__main__":
    solve()

よくある落とし穴は、底が存在するすべての桁より厳密に大きくなければならないことを忘れることです。 このチェックにより、無効な塩基での不必要なシミュレーションが回避され、誤認が防止されます。

 ## 特殊なケース

 微妙なケースは、すべての数字が基数 16 でのみ有効である場合です。`F`。 このアルゴリズムは最小基数を 16 に正しく設定し、より小さい基数の不必要なチェックを回避します。 

入力用`F 0 F`、最大桁は 15 であるため、基数 16 のみがテストされます。 キャリーシミュレーションで即確認`F + 0 = F`、ゼロキャリーと正確な桁一致が生成されるため、出力は 16 になります。 

もう 1 つの特殊なケースは、数値の長さが異なる場合です。 のために`1 0 1`、2 番目の数値は 1 桁を超えて何も寄与せず、キャリー ロジックは欠落している位置をゼロとして正しく処理します。 位置演算では欠落した数字が自然にゼロとしてモデル化されるため、アルゴリズムは特別なケースを使用せずに基数 2 を生成します。
