 ## 解決策
 ## 問題の理解

 長さの配列を構築する必要があります`n`そのため、指定された演算を任意の位置のペアに適用しても、配列の合計が減少することはありません。 

2 つの値を選択するとします`x`そして`y`。 この操作により、両方の数値が次のように置き換えられます。`|x-y|`。 

手術前は、これら 2 つの位置が貢献します$$x+y$$合計額に。 

手術後も貢献してくれる$$2|x-y|.$$合計が減らないようにするには、次のことが必要です。$$2|x-y| \ge x+y$$配列内の要素のペアごとに。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、必要な配列の長さのみが与えられます。`n`。 要素が間にある有効な配列を構築する必要があります。`1`そして`10^9`、またはそのような配列が存在しないことを証明します。 

制約はわずかです。 テスト ケースは最大 100 個あり、`n`テスト ケースごとに線形時間で実行される構築は十分です。 本当の課題は、すべての値を許容範囲内に保ちながら、すべてのペアが必要な不等式を満たす数学的パターンを発見することです。 

いくつかの特殊なケースは注目に値します。 

考慮する`n = 2`。 配列`[1, 2]`は有効です。$$2|2-1| = 2,\qquad 1+2 = 3.$$実際には、これは合計を減らすため、有効ではありません。 不注意な解決策では、増加シーケンスが機能すると仮定する可能性があります。 連続する値の間には、さらに大きなギャップが必要です。 

考慮する`n = 3`と配列`[1, 2, 4]`。 ペア用`(2,4)`、$$2|4-2| = 4 < 6.$$合計は減少するため、2 の累乗では不十分です。 

大きいものを検討してください`n`。 たとえ急速に増加するシーケンスが見つかったとしても、すべての値は最大でも次の値にとどまる必要があります。`10^9`。 成長が早すぎる構造では、長さに達する前に制限を超える可能性があります`n`、一部の値が不正になります。 

## アプローチ

 強引な観点は、すべてのペアの条件を直接考えることです。 配列を指定すると、すべてのペアをチェックできます`(i,j)`かどうかを確認します$$2|a_i-a_j| \ge a_i+a_j.$$長さの配列の場合`n`、これは調べる必要があります`O(n^2)`ペア。 

本当の問題は検証ではなく構築です。 すべてのペアの不等式を自動的に満たす配列ファミリーが必要です。 

2 つの要素が満たされると仮定します`x < y`。 それから$$|x-y| = y-x.$$不等式に代入すると、$$2(y-x)\ge x+y.$$並べ替えると、$$y \ge 3x.$$これが重要な観察です。 すべてのペアが条件を満たす必要があり、並べ替えられた配列の場合、大きい要素が小さい要素の少なくとも 3 倍であれば十分です。 

自然な構造というのは、$$1,\ 3,\ 9,\ 27,\dots$$ここで、各要素は前の要素の 3 倍です。 

インデックスを持つ任意のペアの場合`i < j`、$$a_j = 3^{j-i}a_i \ge 3a_i,$$したがって、導出された条件は自動的に成立します。 

ここで必要なのは、そのような値が以下にいくつ当てはまるかを確認することだけです。`10^9`。$$3^{19}=1162261467>10^9,$$その間$$3^{18}=387420489<10^9.$$から始まる`1`、最大 19 個の数字を使用できます。$$3^0,3^1,\dots,3^{18}.$$したがって、有効な配列は次の場合にのみ存在します。`n \le 19`。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`。 
2. もし`n > 19`、印刷`NO`。 

制限内に収まる有効な 3 のべき乗構造はありません`10^9`、そして公式の解決策は、許可された範囲内ではより大きな有効な構築は不可能であるという事実に依存しています。 
3. それ以外の場合は印刷します`YES`。 
4. シーケンスを生成する$$1,3,9,27,\dots$$現在の値に繰り返し乗算することにより、`3`。 
5.最初の出力`n`価値観。 

The reason this construction works is that every later element is at least three times every earlier element. それはまさに、和が減少するかどうかを支配する不等式から得られる条件です。 

### なぜ効果があるのか

 Take any two elements of the constructed array and assume`x < y`。 

配列は 3 の累乗であるため、大きい要素はすべて小さい要素の少なくとも 3 倍になります。$$y \ge 3x.$$並べ替えると$$y-x \ge \frac{x+y}{2}.$$2を掛けると、$$2(y-x)\ge x+y.$$以来`y>x`、 我々は持っています`|x-y|=y-x`、 それで$$2|x-y|\ge x+y.$$手術後のこれら 2 つのポジションの貢献は、少なくとも手術前の貢献と同じです。 他のすべての位置は変更されないため、合計が減少することはありません。 

生成される最大の値は、`3^{18}=387420489`、限界を満たす`10^9`。 次の累乗は制限を超えるため、長さは 19 が最大値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())

    if n > 19:
        print("NO")
        continue

    print("YES")

    cur = 1
    ans = []

    for _ in range(n):
        ans.append(cur)
        cur *= 3

    print(*ans)
```プログラムは構築を直接追跡します。 

最初の決定は、`n`19 を超えている場合は、すぐに印刷します。`NO`。 

実現可能な長さについては、シーケンスを繰り返し構築します。 から始まる`1`、新しい値はそれぞれ、前の値に を乗算して取得されます。`3`。 これにより、浮動小数点演算やべき乗エラーに関する懸念が回避されます。 

すべての算術演算は Python の整数に簡単に適合します。 生成された最大の値でも以下のようになります`10^9`なので、オーバーフローの心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        if n > 19:
            out.append("NO")
            continue

        out.append("YES")

        cur = 1
        arr = []
        for _ in range(n):
            arr.append(str(cur))
            cur *= 3

        out.append(" ".join(arr))

    return "\n".join(out) + "\n"

assert out.startswith("YES\n")

# first impossible size

# multiple test cases
