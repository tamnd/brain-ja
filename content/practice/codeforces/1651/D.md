 ## 解決策
 ## 問題の理解

 2D グリッド上に一連の個別の整数格子点が与えられます。 これらの各点について、入力セットの一部ではない最も近いグリッド ポイントに「エスケープ」したいと考えます。距離はマンハッタン メトリックで測定されます。 

より簡単に言うと、与えられたすべての点を無限グリッド上の占有されたセルとして想像してください。 占有されているセルごとに、最も近い空のセルを見つけます。ここでの近さは、そこに到達するまでに必要な軸に沿ったステップの数によって定義されます。 

主な困難は、これをすべてのポイントに対して独立して実行する必要があり、グリッドが十分に大きいため、各ポイントの周囲の空間全体を明示的に検索できないことです。 

この制約により、私たちは近隣地域を個別に探索するアプローチから遠ざかることになります。 最大 200,000 ポイントでは、ポイントごとのローカル BFS が小さくても、密な領域では二次爆発に変質します。 各点から単純に拡張すると、グリッドの重複する領域で同じ作業を何度も繰り返すことになります。 

複数の候補の空セルが同等に近い場合、微妙な問題が発生します。 たとえば、ある点の 4 辺が他の点に囲まれている場合、同様に最適な出口が複数存在します。 有効なものであればどれでも受け入れられるため、アルゴリズムでは一意性ではなく最小限の距離を確保するだけで済みます。 

もう 1 つのエッジ ケースは、ポイントが大きな連続クラスターを形成する場合です。 たとえば、ポイントの完全なブロックは次のようになります。```
1 1, 1 2, 2 1, 2 2
```これらのいずれについても、最も近い空の点は距離 1 にありますが、次のように複数の候補があります。`(0,1)`、`(3,2)`ノードごとの単純な BFS では、同じ境界構造が繰り返し再検出されます。 

中心的な課題は、空きスペースの構造がグローバルに共有されている場合に、「最も近い空きスペース」をノードごとに個別に再計算することを回避することです。 

## アプローチ

 ブルートフォース手法では、入力セットにない座標が見つかるまで、各ポイントに対して BFS を外側に実行します。 各 BFS はマンハッタンの距離が増加するにつれてレイヤーを探索するため、正確さは簡単です。最初に遭遇した空のセルが最適です。 

ただし、ポイントが密集している最悪のケースでは、各 BFS がグリッドの大部分に広がる可能性があります。 n が最大 200,000 の場合、多くの検索がほぼ完全に重複するため、クラスター構成ではおよそ O(n²) の動作が発生する可能性があります。 

重要な観察は、問題が対称的であるということです。占有されているすべての点から外側に拡張する代わりに、すべての空きスペースから同時に外側に拡張できます。 

すべてのグリッド ポイントをグラフ内のノードとして、すべての入力ポイントを「ブロックされたソース」として想像すると、すべてのブロックされたノードに対して、最も近いブロックされていないノードが必要になります。 これは、入力セットに隣接するすべての空のセルから開始して内側に向かって距離を伝播するマルチソース BFS と同等です。 

ただし、すべての空のグリッド セルを明示的に反復することは不可能です。 

重要な単純化は、視点を逆にすることです。各点から外側に検索する代わりに、すべての入力点を開始位置として扱い、同時に伝播して各入力点に最も近い空の隣接点を割り当てます。 これは、各状態が入力ポイントを表す状態の BFS となり、遷移は隣接するグリッド セルに移動しますが、問題となるのは未訪問の空のセルに初めて到達したときだけです。 

より正確で実装可能なアイデアは次のとおりです。与えられたすべてのポイントから開始してマルチソース BFS を実行しますが、各グリッド セルをその最も近い入力ポイントによって所有されているものとして扱います。 入力セットにないセルに展開するときは常に、最初に到達したソースの回答としてそのセルを割り当てます。 BFS はマンハッタンの距離を増加させながら探索するため、どのソースからでも空のセルに初めてヒットするときは、そのソースにとって最適であることが保証されます。 

これにより、問題がソースのまばらなセットにわたるグローバルなフラッド フィルに変換され、ポイントごとの検索の繰り返しが回避されます。

 ## アルゴリズムのチュートリアル

 グリッドを暗黙的にモデル化し、訪問した状態のみを保存します。 

1. すべての入力ポイントを O(1) メンバーシップ チェックのハッシュ セットに挿入します。 これにより、占有されているセルと空のセルを即座に区別できるようになります。 
2. すべての入力ポイントを使用してキューを初期化します。 各ポイントは、独自の ID を持つ BFS ソースとみなされます。 
3. すでに処理したグリッド セルの訪問済みセットを維持します。 これにより、各セルが最大 1 回展開されることが保証されます。 
4. 各点について、最初は不明であるその応答座標も保存します。 
5. すべてのポイントから同時に BFS を実行します。 セルから拡張する場合`(x, y)`、その 4 つの近隣を考慮します。 
6. 近傍がすでに入力セット内にあり、別のソースから最初にそこに到着した場合、それは有効な空の場所ではないため、スキップします。 
7. 近傍が入力セット内になく、訪問されていない場合、この近傍は、最初に到達した元のソースに最も近い空の点になります。 それをそのソースの回答として記録し、訪問済みとしてマークします。 
8. すべてのソースが空のネイバーを 1 つ見つけるまで続行します。 

重要な設計上の選択は、各レイヤーがグリッド グラフ内の増加する距離に正確に対応するため、BFS がマンハッタンの最短距離を自然に保証することです。 

### なぜ効果があるのか

 4 方向のエッジを持つグリッドは、BFS が最短パス距離を計算する重み付けされていないグラフです。 すべての入力ポイントは同時ソースとして機能します。 BFS が初めて占有されていないノードを検出するとき、代替パスには少なくとも同じ数のステップが必要になるため、そのパスはそのソースに対して最小限である必要があります。 BFS はグローバルに距離が増加する順序で探索するため、後で発見しても答えを改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    pts = []
    s = set()

    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
        s.add((x, y))

    q = deque()
    ans = {}
    visited = set()

    for x, y in pts:
        q.append((x, y))
        visited.add((x, y))

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        x, y = q.popleft()

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy

            if (nx, ny) in visited:
                continue
            visited.add((nx, ny))

            if (nx, ny) not in s:
                ans[(x, y)] = (nx, ny)
            else:
                q.append((nx, ny))

    for x, y in pts:
        print(ans[(x, y)][0], ans[(x, y)][1])

if __name__ == "__main__":
    solve()
```この解決策は、指定されたすべての点を同時の BFS 開始位置として扱うことに依存しています。 訪問セットにより、各グリッド セルが 1 回だけ処理されることが保証され、重複する領域間で作業が繰り返されることがなくなります。 回答ディクショナリには、各ソースで見つかった最初の空の近傍が格納されます。 

微妙な点は、非入力セルに入った場合にのみ回答を割り当てることです。 これにより、別の入力ポイントを有効なターゲットとして誤って割り当てることがなくなります。 

## 実用的な例

 ### 例 1

 入力:```
6
2 2
1 2
2 1
3 2
2 3
5 5
```6 つのポイントすべてから BFS を初期化します。 最初の拡張は次のようになります。 

| ステップ | セル | タイプ | アクション | 割り当てられた回答 |
 | --- | --- | --- | --- | --- |
 | 1 | (2,2) | ソース | 近隣を展開する | なし |
 | 2 | (1,2) | ソース | 近隣を展開する | なし |
 | 3 | (2,1) | ソース | 近隣を展開する | なし |
 | 4 | (3,2) | ソース | 近隣を展開する | なし |
 | 5 | (2,3) | ソース | 近隣を展開する | なし |

 これらの点はすべて、十字構造で隣接しています。 たとえば、BFS が初めて非入力セルに到達したとき`(1,1)`、BFS 順序で最初に到達したソースに対して記録されます。 同様に、`(5,4)`最も近い空きになります`(5,5)`。 

これは、BFS がポイントごとの重複なしに共有境界を自動的に解決することを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各グリッド セルは最大 1 回訪問され、各訪問で 4 つの隣接セルが処理されます。 
| スペース | O(n) | 入力セット、BFS キュー、訪問セットのストレージ |

 BFS はセルを再訪問しないため、アルゴリズムは入力ポイントの数に比例してスケールします。 これは 200,000 ポイントの制約内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n = int(input())
    pts = []
    s = set()

    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
        s.add((x, y))

    q = deque()
    ans = {}
    visited = set()

    for x, y in pts:
        q.append((x, y))
        visited.add((x, y))

    dirs = [(1,0),(-1,0),(0,1),(0,-1)]

    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if (nx, ny) in visited:
                continue
            visited.add((nx, ny))
            if (nx, ny) not in s:
                ans[(x, y)] = (nx, ny)
            else:
                q.append((nx, ny))

    return "\n".join(f"{ans[x][0]} {ans[x][1]}" for x in pts)

 ## 特殊なケース

 ワンポイントの場合、例えば`(1,1)`、BFS はすぐにその 4 つの近隣に拡張されます。 たとえば、最初の非入力近傍`(2,1)`、回答として記録されます。 他にソースが存在しないため、競合は発生せず、出力は安定しています。 

完全にパックされた 2x2 ブロックの場合、すべてのソースは占有された隣接ブロックに囲まれます。 BFS は外側のリングに到達するまで層ごとに拡張されます。 各ソースで最初に検出される空のセルはその境界上にあることが保証されており、すべての展開がロックステップで行われるため、より近い候補を見逃すソースはありません。 

点の長い線の場合、拡張は線に対して垂直に進みます。 BFS は、ラインの上または下にある最初の空のセルに正確に 1 ステップで到達することを保証し、これは真のマンハッタン最適条件と一致します。
