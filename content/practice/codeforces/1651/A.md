 ## 解決策
 ## 問題の理解

 プレイヤーの数が 2 の累乗である決勝トーナメントをシミュレーションしています。 プレイヤーには 1 から までのラベルが付けられます。$2^n$、残り1人になるまでラウンドでの対決を繰り返します。 

ペアリングのルールは固定されており、スキルや以前の結果には依存しません。各ラウンドで、プレーヤーは順番にペアにグループ化されます。 まず、1 が 2 をプレイし、3 が 4 をプレイし、というようになります。 隣接するペアの勝者は、同じ構造化された方法で次のラウンドで対戦するため、ブラケットは完全に決定的になります。 

この問題が面白いのは、各試合を決める珍しいルールです。 プレイヤーが2人の場合$x$そして$y$競争し、パリティがすべてを制御します。 いつ$x+y$が奇数である場合、インデックスが小さい方が優先されます。 いつ$x+y$が偶数の場合、大きいインデックスが優先されます。 これは、結果がインデックス順で単調ではなく、トーナメントが標準的な「上位が常に勝ち」または「下位が常に勝ち」のブラケットではないことを意味します。 

タスクは、どの初期インデックスがすべて生き残るかを判断することです。$n$ラウンドします。 

計算上の制約は非常に小さいです。 と$n \le 30$、トーナメントの規模は次のとおりです$2^{30}$、これは約10億人のプレーヤーです。 これにより、すべての参加者に対するシミュレーションや、中間ラウンドの明示的な構築さえも直ちに除外されます。 どのソリューションも、次の時間に比例して実行する必要があります。$n$、プレイヤーの数ではありません。 

微妙な落とし穴は、ローカルな一貫性がグローバルな単調性を意味すると仮定していることです。 たとえば、低いインデックスまたは高いインデックスが常に優勢であると誤って仮定する可能性があります。 しかし、ちょっとしたチェックですでにこの直感は打ち砕かれます。$n=1$、プレイヤー 1 が 2 に勝ちますが、より高いラウンドではパリティの伝播に応じてインタラクションが反転するため、単純な「常に左が勝つ」または「常に右が勝つ」ルールは局所的には当てはまりません。 

## アプローチ

 ブルート フォース シミュレーションでは、すべてのものが明示的に構築されます。$2^n$プレーヤーとラウンドを繰り返しシミュレーションします。 各ラウンドで、隣接するペアを比較し、勝者を計算して、次のリストを作成します。 各ラウンドでプレイヤーの数が半分になるため、総作業量は次のようになります。$2^n + 2^{n-1} + \dots + 1$、つまり$O(2^n)$。 のために$n=30$、これはまったく不可能です。 

重要な点は、すべてのプレイヤーを追跡する必要はなく、最終的な勝者の身元だけを追跡する必要があるということです。 ペアリングの構造と決定論的なルールは、トーナメントには中間状態のシミュレーションとは独立して固定されたグローバル勝者が存在することを意味します。 

小さなケースを注意深く調べてみると、パターンが見えてきます。 のために$n=1$、勝者は 1 です。$n=2$、最終的な勝者は 3 です。$n=3$、それは 7 です。これは、勝者が常に可能な限り最大のインデックスであることを示唆しています。$2^n - 1$を除く$n=1$ここで、プレーヤーは 2 人だけであり、ルールにより小さいインデックスがその 1 つの試合に勝つことが強制されるため、これは 1 になります。 

より深い理由は、前のラウンドで生き残った 2 人の対戦では、そのうちの 1 人がそのセグメントの利用可能な最大の代表でなければならず、パリティ ルールにより、後のラウンドで構造的に同等の対戦相手とペアになる場合は常に、より大きなインデックスが優位になることが保証されるためです。 これにより、到達可能な最高のインデックスが各統合ステップで存続するというカスケード効果が生じます。 

したがって、シミュレーションする代わりに、パターンから直接答えを計算します。

 ## アルゴリズムのチュートリアル

 1.読む$n$。 これはトーナメントの規模を定義します$2^n$、ただし構築はしません。 
2. もし$n = 1$、試合は 1 つしかなく、ルールによりプレイヤー 1 の勝利が強制されるため、1 を直接返します。 
3. それ以外の場合は計算します$2^n - 1$勝者として。 
4. 結果を出力します。 

を使用せずに 1 を引く理由$2^n$消去法から来ています。 あるのに$2^n$参加者にとって、交互作用ルールにより、最終的に生き残る者が完全な最大インデックスになることはなく、2 番目に高い構造代表インデックスになることが保証されます。 

### なぜ効果があるのか

 トーナメント構造では、同じサイズの隣接するセグメントが繰り返しマージされます。 各マージでは、セグメントの有効な代表が、パリティ ルールに基づいてインデックス付けされた最大の生き残りになります。 セグメントが結合すると、これらの代表者自体が競合し、同じ支配パターンがあらゆるレベルで繰り返されます。 システム内の最高のインデックスは、ローカル ペアリング コンテキストで常に最大の要素であるため、後のラウンドでも一貫して構造的な弱点がありません。 この帰納的な安定性により、すべてのマージに耐えることが保証され、他のすべての候補は初期の統合段階で排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    if n == 1:
        print(1)
    else:
        print((1 << n) - 1)
```この実装では、トーナメントをシミュレートする代わりに、派生構造を直接エンコードします。 左シフト演算は次のように計算します。$2^n$一定時間内に効率的に。 基本ケースを除くすべてのケースで 1 を減算します。$n=1$これにより、次の場合に誤って 1 が返されることがなくなります。$2^1 - 1 = 1$偶然にも一致しますが、一般的なパターンを表しているわけではありません。 

の分岐$n=1$ロジックを明示的にし、例外処理なしで普遍的に有効であるという式の誤解を防ぐために含まれています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n == 1:
            out.append("1")
        else:
            out.append(str((1 << n) - 1))
    return "\n".join(out)

# provided samples
assert run("2\n3\n1\n") == "7\n1"

# minimum size
assert run("1\n1\n") == "1"

# small higher case
assert run("1\n2\n") == "3"

# medium case
assert run("1\n4\n") == "15"

# larger case
assert run("1\n5\n") == "31"
```| テスト入力 | 期待される出力 | 検証内容 |

 | n=1 | 1 | 基本ケースの正確性 |

 ## 特殊なケース

 のために$n=1$の場合、アルゴリズムは数式を適用する代わりに 1 を直接返します。 これにより、式への依存を回避できます。$2^n - 1$たとえここで偶然同じ結果が得られたとしても、普遍的なルールとして。 明示的な分岐により、パターンの外挿ではなく、問題の単一一致の定義から正確さが導かれることが保証されます。 

のために$n=2$、計算により次のことが得られます。$2^2 - 1 = 3$。 トーナメントを追跡: 1 が 2 に勝ち、3 が 4 に勝ち、その後 1 が 3 と対戦します。$1+3=4$が偶数の場合、インデックスが大きい方が勝ちとなるため、3 が勝ちとなります。 これは、式の出力と正確に一致します。 

大型の場合$n$、繰り返されるペアリング構造により、到達可能な最高のインデックスが各統合レベルを通じて常に保持されることが保証されるため、中間のペアリングがそれを削除することはできません。
