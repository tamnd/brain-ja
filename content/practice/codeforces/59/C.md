 ## 解決策
 ## 問題の理解

 小文字と疑問符で構成される文字列テンプレートが与えられます。 最後の文字列は 3 つの条件を同時に満たさなければなりません。 

まず、回文である必要があるため、中心の周りに鏡映された文字が一致する必要があります。 

2 番目に、最初のものだけを使用することもできます。`k`小文字、以下の文字のみを意味します`'a'`に`'a' + k - 1`。 

第三に、それらのすべて`k`文字は、最終的な文字列のどこかに少なくとも 1 回出現する必要があります。 

クエスチョンマークは文字に置き換えることができますが、固定文字は変更できません。 

すべての有効な回答の中で、辞書編集的に最小のものを出力する必要があります。 有効な回文が存在しない場合は、次のように出力します。`"IMPOSSIBLE"`。 

文字列の長さは最大 100 で、非常に小さいです。 指数関数的な総当たり攻撃でも、小規模なケースでは天文学的なほど巨大ではありませんが、疑問符の数は 100 に達する場合もあるため、すべての置換を試すと次のような意味になります。`26^100`可能性はありますが、完全に不可能です。 むしろ、制限が小さいということは、注意深く建設的なアルゴリズムで十分であることを示唆しています。 

最もデリケートな部分は辞書順です。 常に可能な限り小さい文字を配置するという貪欲な戦略により、必要な文字を後で配置できなくなる可能性があります。 

もう 1 つの微妙な点は、回文の制限です。 奇数長の文字列の中心にいる場合を除き、すべての代入は一度に 2 つの位置に影響します。 

次の例を考えてみましょう。```
k = 2
s = "a?b"
```回文では最初と最後の文字が一致する必要がありますが、それらはすでに次のように固定されています。`'a'`そして`'b'`。 これを修復できる代替品はないため、正しい答えは次のとおりです。```
IMPOSSIBLE
```疑問符を埋めるだけの不用意な実装では、この矛盾を見落としてしまいます。 

もう 1 つの危険なケースは、必要な文字をすべて含めるにはスペースが不十分である場合です。```
k = 3
s = "aaa"
```文字列はすでに回文ですが、含まれているのは`'a'`。 紹介できるポジションが残っていないため`'b'`そして`'c'`、答えは不可能です。 

センターの位置にも注意が必要です。```
k = 2
s = "?"
```1 文字の回文には異なる文字を 1 つだけ含めることができるため、両方を含めることはできません`'a'`そして`'b'`。 たとえ弦が完全に柔軟であっても、答えは不可能です。 

最後に、辞書編集的な順序は、素朴な貪欲さを打ち破ることができます。```
k = 2
s = "??"
```考えられる回文は次のとおりです。`"aa"`そして`"bb"`、しかし、ただ`"bb"`文字が含まれています`'b'`。 正しい答えは次のとおりです。```
bb
```選択する`'a'`小さいため、無効な最終文字列が生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての疑問符を使用可能なすべての文字に置き換え、すべての候補文字列を生成し、すべての文字列を含む最小の有効な回文を保持します。`k`手紙。 

検索では可能なすべての補完が探索されるため、これは論理的に機能します。 問題は可能性の数です。 文字列に次の内容が含まれている場合`q`クエスチョンマーク、あります`k^q`課題。 と`q = 100`そして`k = 26`、これは天文学的な大きさです。 

重要な観察は、回文構造が位置を結合していることです。 キャラクターの位置を決めたら`i`、ミラーリングされた位置`n - 1 - i`強制されます。 すべての疑問符を個別に処理する代わりに、対称ペアを処理できます。 

もう 1 つの重要な観察は、辞書編集上の順序が最初に前の位置に依存するということです。 ペアを決定するときは、後で必要な欠落文字をすべて配置できる十分な自由を残した、可能な限り小さい文字が必要です。 

これは、建設的な貪欲な解決策につながります。 

まず回文の一貫性を強制します。 すべてのミラーリングされたペアについて:

 両方の文字が固定されていて異なる場合、答えは不可能です。 

片側が固定され、もう一方が固定されている場合`'?'`、疑問符は固定文字になる必要があります。 

両方ともそうだった場合`'?'`、選択を延期します。 

このフェーズの後、文字列はすでに部分回文のように動作します。 

次に、どの必須文字がまだ欠落しているかを追跡します。 両方の位置が等しくなければならないため、すべての未解決の対称ペアは最大 1 つの新しい文字を導入できます。 奇数長の文字列の中央の文字に 1 文字を導入することもできます。 

ペアを左から右に処理します。 辞書編集上の最小限性を実現するために、各ステップで可能な限り最小の文字を試みます。 ただし、コミットする前に、残りの未解決の位置が、後でまだ不足しているすべての文字を配置するのに十分であるかどうかを確認します。 

これは古典的な貪欲なパターンです。実現可能性を損なわない最小の有効なオプションを選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^q * n) | O(n) | 遅すぎる |
 | 最適 | O(n * k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を可変配列に変換します。 
2. すべてのミラーリングされたペアを処理する`(i, j)`どこ`j = n - 1 - i`。 

両方の文字が固定されていて異なる場合は、すぐに戻ります`"IMPOSSIBLE"`なぜなら、両方を満足させる回文は存在しないからです。 

ちょうど片側が`'?'`, 固定文字を反対側にコピーします。 

このステップでは、貪欲な選択が始まる前に、強制された決定をすべて削除します。 
3. 最初のものはどれかを数えます`k`文字がすでに文字列に含まれています。 
4. すべての未解決の場所を収集します。 

ペア用`"??"`両方の位置が常に同じ文字を受け取るため、左側のインデックスのみを保存します。 

長さが奇数で中心が`'?'`、別に保管してください。 
5. 欠落している文字のセットを計算します。 
6. 未解決の位置を左から右に処理します。 

各ポジションについて、次の文字を試してください。`'a'`上向きに。 

文字を一時的に配置し、残りの未解決の位置が、後でまだ欠けているすべての文字を配置するのに十分であるかどうかを確認します。 

最初の実行可能な文字が永続的に選択されます。 

前の位置が辞書編集上の順序を支配するため、実行可能な最小の文字を選択すると、世界的に最小の答えが保証されます。 
7. すべての位置が埋まった後、必要な文字がすべて少なくとも 1 回表示されていることを確認します。 

必要な文字がまだない場合は、印刷してください`"IMPOSSIBLE"`。 
8. それ以外の場合は、配列を最終文字列に結合します。 

### なぜ効果があるのか

 このアルゴリズムは、構築全体を通じて 2 つの不変条件を維持します。 

まず、文字列は常に回文であることと互換性があります。 すべての割り当てでは、同じ文字がミラーリングされた位置に書き込まれます。 

第 2 に、すべての貪欲な選択の後でも、残りの未解決の位置は、不足している必要な文字をすべて配置するのに十分です。 この実現可能性チェックのおかげで、アルゴリズムが隅に追いやられることはありません。 

辞書編集上の最小性は、左から右への貪欲な順序に従います。 すべての位置で、後で完全に有効なソリューションを可能にする最小の文字を選択します。 選択値が小さいと完了が不可能になり、選択値が大きいと辞書編集的に大きな文字列が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    s = list(input().strip())

    n = len(s)

    # Enforce palindrome constraints
    for i in range(n // 2):
        j = n - 1 - i

        if s[i] != '?' and s[j] != '?':
            if s[i] != s[j]:
                print("IMPOSSIBLE")
                return

        elif s[i] == '?' and s[j] != '?':
            s[i] = s[j]

        elif s[i] != '?' and s[j] == '?':
            s[j] = s[i]

    required = [chr(ord('a') + i) for i in range(k)]

    present = set(ch for ch in s if ch != '?')

    unresolved = []

    for i in range(n // 2):
        j = n - 1 - i
        if s[i] == '?' and s[j] == '?':
            unresolved.append((i, j))

    center = -1
    if n % 2 == 1 and s[n // 2] == '?':
        center = n // 2

    total_slots = len(unresolved) + (1 if center != -1 else 0)

    missing = set(required) - present

    if len(missing) > total_slots:
        print("IMPOSSIBLE")
        return

    positions = []

    for pair in unresolved:
        positions.append(pair)

    if center != -1:
        positions.append((center, center))

    for idx, (i, j) in enumerate(positions):
        remaining_after = len(positions) - idx - 1

        for c in required:
            new_missing = len(missing)

            if c in missing:
                new_missing -= 1

            if new_missing <= remaining_after:
                s[i] = c
                s[j] = c

                if c in missing:
                    missing.remove(c)

                break

    final_present = set(s)

    for c in required:
        if c not in final_present:
            print("IMPOSSIBLE")
            return

    print("".join(s))

solve()
```最初のフェーズでは、強制された回文の割り当てを解決します。 矛盾が生じる可能性があるのはここだけです。 ミラー化された固定文字が一致しない場合、その後の選択では文字列を修復できません。 

次に、アルゴリズムは未解決の対称位置を特定します。 各ペアを 1 つの決定として扱うことが主な単純化です。 両側が一致する必要があるため、ペアでは独立した文字の選択肢が 1 つだけ提供されます。 

貪欲フェーズでは、辞書編集上の順序が慎重に処理されます。 コードは、未解決の各位置で、最小文字から最大文字まで文字をテストします。 コミットする前に、残りの位置で不足している文字をすべてカバーできるかどうかがチェックされます。 

条件:```
new_missing <= remaining_after
```は中核となる実現可能性テストです。 

まだ 3 つの異なる文字が必要であるが、未解決のスロットが 2 つしか残っていない場合、現在の選択は機能しません。 

中心位置は次のように表されます。`(center, center)`したがって、同じ割り当てロジックが両方のペアと中央の文字に均一に機能します。 

ロジックが正しい場合、最後の検証ステップは技術的に冗長ですが、これを維持することで実装がより安全になり、推論が容易になります。
