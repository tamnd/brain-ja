 ## 解決策
 ## 問題の理解

 マリーナは、フィールドから花の任意のサブセットを摘むことができます。 それぞれの花には一定の数の花びらがあり、彼女は選択したすべての花から 1 つずつすべての花びらを摘み取ります。 フレーズが交互に表示されます。`"Loves"`そして`"Doesn't love"`から始まる`"Loves"`最初の花びらに。 

最後のフレーズは、花束の花びらの総数によってのみ決まります。 合計が奇数の場合、最後に話されたフレーズは次のようになります。`"Loves"`。 合計が偶数の場合、最後のフレーズは`"Doesn't love"`。 

この観察の後、タスクははるかに簡単になります。 私たちは占いのプロセスをまったくシミュレーションしていません。 和が奇数であるサブセットを選択し、その和をできるだけ大きくするだけで済みます。 

花の数は最大 100 個で、各花には最大 100 枚の花びらがあります。 すべてのサブセットに対するブルートフォース ソリューションであっても、チェックが必要になります。$2^{100}$可能性はありますが、それは完全に不可能です。 競技プログラミングでは通常、100 万回の操作は問題ありませんが、$2^{100}$天文学的に大きいです。 

花びら数の小さな値の境界は、解決策が複雑な最適化ではなくパリティに依存している可能性があることを示唆しています。 問題を「最大の奇数和を見つける」というものに縮小すると、構造は非常に直接的になります。 

不注意な実装を簡単に破ってしまう可能性のある特殊なケースがいくつかあります。 

すべての花の花びらの数が偶数であると仮定します。```
3
2 4 6
```合計は偶数であり、偶数を削除しても偶数の合計が残ります。 奇妙な花束は存在しないので、正解は次のとおりです。```
0
```可能であれば常に合計を出力する単純なアプローチは、ここでは失敗します。 

もう 1 つの注意が必要なケースは、合計が偶数であるのに、奇数の花が利用可能な場合です。```
4
1 2 4 8
```合計は 15 で、すでに奇数であるため、答えは 15 になります。一部の実装では、合計がすでに正しい場合でも、奇数の花を見つけるたびに誤って削除してしまいます。 

合計が偶数で奇数の花が複数ある場合は、別の失敗モードが表示されます。```
5
1 3 5 2 2
```合計は 13 で、すでに奇数なので、すべてを保持します。 しかし、合計が偶数だった場合、正しい戦略は、単なる奇妙な花ではなく、最も小さい奇妙な花を削除することになります。 より大きな奇妙な花を削除すると、答えが不必要に減少します。 

例えば：```
3
3 5 8
```合計は 16 です。5 を削除すると 11 になり、3 を削除すると 13 になります。最適な答えは 13 です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 花の考えられるすべてのサブセットを列挙し、そのサブセット内の花びらの総数を計算し、最大の奇数の合計を保持します。 

これが機能するのは、すべてのブーケが 1 つのサブセットに正確に対応するためです。 すべてのサブセットをチェックすると、最適で有効なサブセットが必ず見つかります。 

問題はサブセットの数です。 と$n = 100$、サブセットの合計数は次のとおりです。$$2^{100}$$これは、どのプログラムでも制限時間内に処理できる量をはるかに超えています。 

重要な観察は、パリティのみが重要であるということです。 

合計が奇数の場合`"Loves"`、合計が偶数になると、`"Doesn't love"`。 したがって、可能な限り最大の奇数和が必要です。 

すべての花の合計から始めます。 ケースは2つだけです。 

合計がすでに奇数である場合は、正の数を削除しても合計が減少するだけなので、明らかにすべての花を保持する必要があります。 

合計が偶数の場合は、そのパリティを変更する必要があります。 偶数の花を削除しても合計は均等になるため、役に立ちません。 奇数の花を削除すると、パリティが奇数に反転します。 

残りの合計をできるだけ大きく保ちたいため、すべての奇妙な花の中で最も小さい花を削除する必要があります。 

奇数の花がまったくない場合、考えられるすべての部分集合の合計は偶数となり、答えは 0 になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 花の数と花びらの数を読み取ります。 
2. すべての花びらの合計を計算します。 

すべての花を維持すると可能な限り最大の金額が得られるため、これが最良の出発点です。 
3. 合計が奇数かどうかを確認します。 

奇数の場合は、これより小さなサブセットでは答えを改善できないため、すぐに合計を出力します。 
4. 合計が偶数の場合、花びらの数が奇数で最も小さい花を探します。 

奇数を 1 つ削除すると、偶数の合計が奇数の合計に変わります。 
5. そのような花が存在する場合は、次のように出力します。$$\text{total sum} - \text{smallest odd flower}$$パリティを修正するために必要な最小限の量が削除されるため、これにより可能な最大の奇数和が生成されます。 

1. 奇妙な花が存在しない場合は、0 を出力します。 

この状況では、すべての花が偶数であるため、すべての部分集合の合計も偶数になります。 

### なぜ効果があるのか

 このアルゴリズムはパリティ プロパティに依存します。 

数値の合計は、奇数が追加または削除された場合にのみパリティを変更します。 可能な最大合計から始めると、可能性は 2 つだけです。 

合計がすでに奇数である場合、削除すると答えが減少するため、すべてを維持することが最適です。 

合計が偶数の場合、奇数にするために奇数の値を削除する必要があります。 最小の奇数を削除すると損失が最小限に抑えられ、結果として得られる奇数の合計が可能な限り大きくなることが保証されます。 

他の操作ではこれより良い答えは得られません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)

if total % 2 == 1:
    print(total)
else:
    smallest_odd = float('inf')

    for x in a:
        if x % 2 == 1:
            smallest_odd = min(smallest_odd, x)

    if smallest_odd == float('inf'):
        print(0)
    else:
        print(total - smallest_odd)
```プログラムは、花びらの数を読み取り、その合計を計算することから始まります。 

最初のブランチは最も簡単なケースを処理します。 すべての花を維持すると常に花束のサイズが最大化されるため、合計がすでに奇数である場合は、直接印刷します。 

2 番目の分岐では、最小の奇数の花を検索します。 変数`smallest_odd`は無限大から始まるため、ループ中に実際の値に対して安全に最小化できます。 

パリティチェックでは、`x % 2 == 1`。 奇妙な花は、取り除かれると全体の等価性が反転する可能性があります。 

条件:```
smallest_odd == float('inf')
```奇妙な花が見つからなかったという意味です。 その場合、すべての花は偶数であり、奇数のサブセット合計は存在しません。 

可能な最大合計は次のとおりであるため、オーバーフローの懸念はありません。$$100 \times 100 = 10000$$それでも、Python の整数は、より大きな値を自動的に処理します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)

    if total % 2 == 1:
        print(total)
    else:
        smallest_odd = float('inf')

        for x in a:
            if x % 2 == 1:
                smallest_odd = min(smallest_odd, x)

        if smallest_odd == float('inf'):
            print(0)
        else:
            print(total - smallest_odd)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue().strip()

# provided sample
assert run("1\n1\n") == "1", "sample 1"

# all even values
assert run("4\n2 4 6 8\n") == "0", "all sums are even"

# total already odd
assert run("4\n1 2 4 8\n") == "15", "keep all flowers"

# remove smallest odd
assert run("3\n3 5 8\n") == "13", "must remove minimum odd"

# minimum size with even flower
assert run("1\n2\n") == "0", "single even flower"

# maximum size style case
assert run("5\n100 100 100 100 99\n") == "499", "large values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`4 / 2 4 6 8`|`0`| 奇数のサブセットは存在しません |
 |`4 / 1 2 4 8`|`15`| 合計がすでに奇数の場合は、すべての花を保持します。 
|`3 / 3 5 8`|`13`| 最も小さな奇妙な花を取り除く必要があります |
 |`1 / 2`|`0`| シングルイーブンフラワーエッジケース |
 |`5 / 100 100 100 100 99`|`499`| 値を大きくすると正しく動作します。 

## 特殊なケース

 次の入力を考えてみましょう。```
3
2 4 6
```アルゴリズムは合計を 12 として計算します。12 は偶数であるため、最小の奇数の花を検索します。 すべての値が偶数であるため、何も存在しません。 

変数`smallest_odd`無限大から変化することはないため、アルゴリズムは 0 を出力します。 

これは正しいです。なぜなら、偶数のすべての部分集合も偶数の和をもつからです。 

次に、次のことを考えてみましょう。```
3
3 5 8
```合計は16で偶数です。 アルゴリズムは配列をスキャンし、奇数の花 3 と 5 を見つけます。最小値は 3 です。 

3 を削除すると次のようになります。```
16 - 3 = 13
```これは奇数で最大です。 

代わりに 5 を削除すると、答えは 11 になるため、最小の奇数の花を選択することが重要です。 

最後に、以下を調べます。```
4
1 2 4 8
```合計は 15 で、すでに奇数です。 

アルゴリズムは何も削除せずに 15 をすぐに出力します。 

これにより、パリティがすでに正しいにもかかわらず、実装が不必要に奇数の花を削除するというよくある間違いを回避できます。
