 ## 解決策
 ## 問題の理解

 このタスクは、単一の単語の大文字と小文字を正規化して、すべての文字が小文字になるか、すべてが大文字になるようにすることです。 決定は、入力内でどちらの大文字が優勢であるかによって異なります。大文字が小文字よりも多い場合は、単語を完全に大文字に変換する必要があります。 それ以外の場合は、完全に小文字に変換する必要があります。 カウントが正確に等しい場合は、小文字が優先されます。 

入力は、英語の文字のみを含む 1 つの単語で、長さは 1 ～ 100 文字です。 この長さは短いため、効率を気にせずにすべての文字を複数回繰り返す余裕があります。 複雑なデータ構造や並べ替えは必要ありません。 

エッジ ケースには、大文字と小文字がすでに一致している単語、単一文字の単語、大文字と小文字の数が完全に等しい単語が含まれます。 たとえば、入力`"a"`残るべきだ`"a"`、 そして`"Ab"`になるはずです`"ab"`小文字の関係が壊れて小文字が優先されるためです。 単純な実装では、結合条件を正しく処理することを忘れたり、大文字と小文字を厳密に区別しないことで文字のカウントを間違えたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、文字列をスキャンし、文字ごとに大文字か小文字かを確認し、個別のカウンタを維持します。 次に、数えた後、合計を比較し、それに応じて単語を変換します。 実際、このアプローチは、単語の文字数が最大 100 文字であり、各演算が O(1) であるため、制約に対して十分に効率的です。 したがって、カウント用と変換用の 2 回のスキャンでも許容されます。 

実装を簡素化する重要な点は、Python が大文字と小文字をチェックする組み込みの文字列メソッドを提供していることです (`isupper()`) 文字列全体を特定の大文字と小文字に変換します (`upper()`そして`lower()`）。 変換は文字列全体に適用されるため、変換のために個々のインデックスを追跡する必要はありません。 

ここでの総当たりと最適の違いは主に文体上のものです。 最適なアプローチは、単純に 1 回のリニア スキャンで大文字をカウントし、その後条件付きで次の条件を適用することです。`upper()`または`lower()`文字列全体に。 より複雑な構造は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (カウント + 変換) | O(n) | お(1) | 承認済み |
 | 最適 (大文字をカウントし、1 回変換) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 大文字のカウンタを初期化します。 これは、最終的な変換を決定するために必要な最小限の状態です。 
2. 入力単語の各文字を繰り返し処理します。 標準言語の方法を使用して、すべての文字が大文字であるかどうかを確認します。 大文字のカウンタがあればそれをインクリメントします。 全長から大文字の数を引いた値が小文字の数を表すため、小文字のカウンターは必要ありません。 
3. すべての文字をスキャンした後、大文字の数と小文字の数を比較します (全長から大文字の数を差し引いて計算されます)。 大文字の数が厳密に大きい場合は、単語全体を大文字に変換します。 それ以外の場合は、単語全体を小文字に変換します。 
4. 変換された単語を出力します。 

機能する理由: ステップ 3 で、比較により最小限の数の文字変換が適用されることが保証されます。 大文字が優勢な場合、すべてを大文字に変換すると、小文字に変換するよりも変更される文字の数が少なくなります。 小文字が優勢であるか、小文字が同点の場合は、小文字に変換すると、同じ最小限の変更目標が達成されます。 不変条件は、変換の時点でグローバル多数派のケースがすでにわかっているため、ローカルな計算ミスは発生しないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

word = input().strip()

uppercase_count = sum(1 for c in word if c.isupper())
lowercase_count = len(word) - uppercase_count

if uppercase_count > lowercase_count:
    print(word.upper())
else:
    print(word.lower())
```最初の行は入力を効率的に読み取ります。 使用する`strip()`末尾の改行を削除します。 理解`sum(1 for c in word if c.isupper())`1 回のパスで大文字をカウントします。 小文字の数は全長と大文字の数の差として計算され、2 回目の反復を回避します。 条件は 1 ステップで正しい変換を適用します。 

微妙な点：忘れる`strip()`出力の末尾に改行が残ります。 大文字と小文字の数え間違い、または使用`>=`の代わりに`>`タイブレークルールに違反することになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    word = sys.stdin.readline().strip()
    uppercase_count = sum(1 for c in word if c.isupper())
    lowercase_count = len(word) - uppercase_count
    return word.upper() if uppercase_count > lowercase_count else word.lower()

# provided sample
assert run("HoUse\n") == "house", "sample 1"
# all lowercase
assert run("abcde\n") == "abcde", "all lowercase"
# all uppercase
assert run("ABCDE\n") == "ABCDE", "all uppercase"
# tie case
assert run("Ab\n") == "ab", "tie case -> lowercase"
# single character uppercase
assert run("X\n") == "X", "single uppercase"
# single character lowercase
assert run("x\n") == "x", "single lowercase"
# mixed with more uppercase
assert run("PyTHon\n") == "PYTHON", "more uppercase"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | ハウス | 家 | 小文字の過半数 |
 | ABCDE | ABCDE | すべて小文字の入力 |
 | ABCDE | ABCDE | すべて大文字入力 |
 | アブ | アブ | ネクタイは正しく処理されました。 
| X | X | 単一文字の大文字 |
 | × | × | 単一文字の小文字 |
 | Python | パイソン | もっと大文字 |

 ## 特殊なケース

 引き分けシナリオの場合`"Ab"`、アルゴリズムは次のように計算します。`uppercase_count = 1`、`lowercase_count = 1`。 条件`uppercase_count > lowercase_count`失敗したため、単語は小文字に変換されます`"ab"`。 これにより、タイは小文字を優先するというルールが正しく適用されます。 

1文字の単語の場合`"X"`、大文字のカウントは 1、小文字のカウントは 0 です。条件は true であるため、出力は残ります。`"X"`。 のために`"x"`、条件は false で、出力は残ります。`"x"`。 どちらの場合も、アルゴリズムが最小入力サイズを正しく処理していることを確認します。
