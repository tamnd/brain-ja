 ## 解決策
 ## 問題の理解

 私たちは持っています`3n`学生は個人の成績によってランク付けされます。 上位の生徒ほど早くキャプテンになります。 キャプテンがチームを編成するとき、個人的な希望リストに従って、現在割り当てられていない 2 人の生徒を選択します。 

最終的なチームはすでにわかっており、チームは作成された正確な順序でリストされています。 各チーム内でのメンバーの順序は任意です。 

特定の生徒に対して`k`、他の完全な優先順列を構築する必要があります。`3n - 1`チーム作成プロセス全体で特定のチームを再現できるように生徒をサポートします。 すべての有効な優先リストの中で、辞書編集的に最小の優先リストが必要です。 

重要な点は、私たちが管理するのは 1 人の生徒の希望リストのみであるということです。 他の生徒の好みは不明で、建設が可能な限り何でも構いません。 

制約は大きいです。 以来`n ≤ 10^5`まであります。`3 * 10^5`学生たち。 二次スキャンを使用してチーム作成を繰り返しシミュレートするソリューションは失敗します。 解決策`O(n log n)`または`O(n)`が必要です。 

この問題の危険な部分は、キャプテンの命令がチームの命令と同じではないことです。 チームは指定された順序で作成されますが、各チームのキャプテンは単にその時点で残っている最高位の生徒です。 誤って任意のキャプテンを仮定すると、不可能な優先リストが生成される可能性があります。 

もう 1 つの微妙な点は、辞書編集的なミニマリティです。 私たちは、単なる有効なリストを作成しようとしているわけではありません。 早い位置が答えを支配するので、生徒が安全に早く出られる場合は、そうすべきです。 

次の例を考えてみましょう。```
Ranking:
1 2 3 4 5 6

Teams:
1 4 5
2 3 6
```学生`1`初代キャプテンです。 もし`k = 1`、それから生徒たち`4`そして`5`希望リスト内で現在受講可能な他の生徒よりも先に表示される必要があります。 さもないと`1`最初に他の人を選ぶでしょう。 

不注意なアプローチでは、次のような小さな数値が配置される可能性があります。`2`または`3`辞書編集上の順序を改善するために先に、しかしその後キャプテン`1`代わりにそれらを選択し、間違ったチームを作成することになります。 

もう一つ厄介なケースが発生するのは、`k`キャプテンではありません。```
Ranking:
1 2 3 4 5 6

Teams:
1 5 6
2 3 4
```仮定する`k = 5`。 学生`5`最初のチームに選ばれたからといってキャプテンになることはありません。 その場合、彼らの好みリストはプロセスとはまったく無関係になります。 辞書編集的に最小の有効な答えは、単に他の生徒全員を昇順に並べたものです。```
1 2 3 4 6
```不必要な制約を課そうとすると、答えが必要以上に大きくなってしまいます。 

もう 1 つの特殊なケースには、利用できない生徒が関係しています。 何人かの生徒がすでに別の場所に割り当てられている後、キャプテンがチームメイトを選ぶとします。```
Ranking:
1 2 3 4 5 6

Teams:
1 4 5
2 3 6
```キャプテンのとき`2`行為、学生`1,4,5`はすでに利用できません。 たとえ`2`それらをより好みますが、選択することはできません。 優先リストは、現在割り当てられていない学生の間でのみ重要です。 これを無視すると、不適切な制約が発生します。 

## アプローチ

 ブルートフォースの考え方は、チーム構築の正確なシミュレーションを考えることから始まります。 学生向けの候補者優先リストを生成してみることもできます`k`、プロセス全体をシミュレートし、作成されたチームが入力と一致するかどうかを確認します。 

すべての優先リストが固定されるとルールは決定的になるため、これは概念的に機能します。 問題は検索スペースです。 学生`k`もっている`(3n - 1)!`可能な順列。 たとえ`n = 5`、これはすでに巨大です。 

より構造化されたブルート フォースのアイデアは、シミュレーションから直接制約を導き出すことです。 いつでも学生`k`がキャプテンになる場合、実際に選択した 2 人のチームメイトは、まだ参加可能な他のすべての生徒よりも優先リストに早く表示されなければなりません。 

その観察こそが問題のすべてだ。 

これが機能する理由は、プロセスが参照のみを行うためです。`k`の好みリストの瞬間`k`現在のキャプテンです。 それ以外のときは、`k`の好みは関係ありません。 

次に、いつ何が起こるかを考えてみましょう`k`チーム作成ステップ中にキャプテンです。 

参加可能な学生が次のとおりであるとします。```
A = {x1, x2, ..., xm}
```そして最後のチームは私たちにこう言います`k`選ばれた生徒たち`u`そして`v`。 

次に、`k`現在募集中の学生の中での の優先リスト、両方`u`そして`v`他の受講可能な生徒よりも先に出席しなければなりません。 キャプテンが最初に 1 人を選択し、次に残りの生徒から別の生徒を選択するため、相対的な順序は重要ではありません。 

辞書編集的に最小の有効な順列を取得するには、次の小さい方を配置する必要があります。`(u, v)`最初に、次に大きいもの、次に他のすべてをできるだけ小さいものにします。 

残りの課題は、`k`いつかキャプテンになる。 

チームのキャプテンは、単にその時点で割り当てられていない生徒の中で最高位のランクにあります。 順位が固定されているため、どの生徒が使用されているかを維持したまま、順番にチームを処理することができます。 

もし`k`初期のチームに選ばれても、キャプテンを務めることはありません。 その場合、制約はまったくなく、答えは他のすべての生徒を昇順に入力するだけです。 

もし`k`がチームのキャプテンになると、ちょうど 2 人の学生が、まだ参加可能な学生の中で希望リストの先頭に追い込まれることになります。 

これにより、ほとんど自明な最適解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((3n)!) | O(3n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順位の順列を読み取り、各生徒の順位を保存します。 

ポジションが小さいほどパフォーマンスが向上し、キャプテンの優先順位が早くなります。 
2. どの学生がすでに割り当てられているかを維持しながら、指定された作成順序でチームを処理します。 

各チームのキャプテンは、割り当てられていないメンバーの中で最高のランキングの位置にあります。 
3. 学生かどうかを確認します`k`現在のチームに所属しています。 

そうでない場合は、続行してください。 
4. もし`k`現在のチームに所属しており、キャプテンではない場合、`k`後にキャプテンになることはありません。 

学生`k`はすでに他の人のチームに割り当てられているため、彼らの優先リストがプロセスに影響することはありません。 
5. もし`k`がキャプテンなので、他の 2 人のチームメンバーをキャプテンとします`a`そして`b`。 

現時点では、割り当てられていないすべての生徒は、`k`選択可能です。 
6. 辞書編集的に最小の有効な優先リストを作成します。 

置く`min(a,b)`まずそして`max(a,b)`2 番目に、これら 2 人の生徒は他の利用可能な生徒よりも先に選ばれなければならないためです。 
7. を除く残りの生徒をすべて追加します。`k`、`a`、 そして`b`昇順に。 

それ以上の制約は存在しないため、辞書編集的に最小の継続がソート順になります。 
8. キャプテンのケースが見つからなかった場合は、生徒を除くすべての生徒を出力します。`k`昇順で。 

### なぜ効果があるのか

 唯一の時間`k`の設定リストがプロセスに影響を与えるのは次のような場合です。`k`キャプテンになります。 その時点で、優先順位の最初の 2 人の生徒が、正確に割り当てられた 2 人のチームメイトでなければなりません。`k`。 

他の順序制約は存在しません。 すでに割り当てられている学生は選考プロセスでは無視され、将来のイベントが決定に依存することはありません。`k`もう一度言いますが、各生徒がキャプテンになれるのは最大でも 1 つのチームだからです。 

したがって、辞書編集的に最小の有効な順列は、強制されたチームメイトを必要なだけ早く昇順に配置し、次に制約されていないすべての学生を昇順に配置することによって取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ranking = list(map(int, input().split()))

    pos = [0] * (3 * n + 1)
    for i, x in enumerate(ranking):
        pos[x] = i

    teams = []
    for _ in range(n):
        teams.append(list(map(int, input().split())))

    k = int(input())

    used = [False] * (3 * n + 1)

    for team in teams:
        captain = min(team, key=lambda x: pos[x])

        if k in team:
            if captain != k:
                ans = [x for x in range(1, 3 * n + 1) if x != k]
                print(*ans)
                return

            others = [x for x in team if x != k]
            others.sort()

            ans = others[:]

            banned = {k, others[0], others[1]}

            for x in range(1, 3 * n + 1):
                if x not in banned:
                    ans.append(x)

            print(*ans)
            return

        for x in team:
            used[x] = True

solve()
```最初のセクションでは、ランキングの位置を計算します。 これにより、誰がキャプテンになるかを決定する際に、生徒間で常に比較することができます。 

各チームごとに、最低順位のメンバーを選出してキャプテンを決定します。 チームは作成順に処理されるため、これは元のプロセスと正確に一致します。 

を含むチームに遭遇した瞬間`k`、問題は完全に決定されます。 

もし`k`ではキャプテンではない`k`は以前に他の人によって選択されており、独自の優先リストを使用することはありません。 すべての順列は有効であるため、辞書編集的に最も小さい順列は、単純に次を除く昇順になります。`k`。 

もし`k`がキャプテンである場合、他の 2 人のチームメイトは、他の参加可能な生徒全員よりも前に出なければなりません。 それらの内部順序には制約がないため、辞書順列を最小限に抑えるために昇順を選択します。 

残りのスチューデントには制約がなく、昇順で追加されます。 

実装の微妙な詳細の 1 つは、現在参加可能な学生を明示的に追跡する必要がないことです。 使用できない生徒は選択時に無視されるため、すでに使用されている生徒は優先リストのどこにでも安全に表示できます。 対応可能な学生間の相対的な順序のみが重要です。 

もう一つ重要な点は、キャプテンの決定にはチームの順位や生徒番号ではなく、独自の世界ランキングが使用されることです。

import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    ranking = list(map(int, input().split()))

    pos = [0] * (3 * n + 1)
    for i, x in enumerate(ranking):
        pos[x] = i

    teams = []
    for _ in range(n):
        teams.append(list(map(int, input().split())))

    k = int(input())

    for team in teams:
        captain = min(team, key=lambda x: pos[x])

        if k in team:
            if captain != k:
                ans = [x for x in range(1, 3 * n + 1) if x != k]

                if x not in banned:
                    ans.append(x)

            return " ".join(map(str, ans))

    sys.stdin = io.StringIO(inp)
    return solve()
