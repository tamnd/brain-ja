 ## 解決策
 ## 問題の理解

 各エッジがアクティブまたは非アクティブである有向グラフが与えられ、時間の経過とともにこれら 2 つの状態の間でエッジを切り替えることができます。 最初は、すべてのエッジがアクティブです。 システムは、特定のエッジの状態を反転する操作と、現在アクティブなエッジのみを使用して、ある頂点から別の頂点への有向パスが存在するかどうかを尋ねる到達可能性クエリに答えるという 2 種類の操作をサポートする必要があります。 

この難しさは、更新とクエリの両方が完全にオンラインであり、グラフが十分に大きいため、クエリごとに到達可能性を最初から再計算することが不可能であるという事実から生じます。 素朴なアイデアは、アクティブ エッジのみを使用してすべてのクエリに対して BFS や DFS などのグラフ検索を実行することですが、最大 100,000 回の操作では、密度の高いグラフや接続が中程度のグラフでは、これでは非常に遅くなります。 

この制約は、クエリごとに到達可能性を再計算するソリューションは直ちに除外されることを意味します。 クエリあたり O(n + m) であっても、最悪の場合は約 10^10 の操作が発生し、これは制限をはるかに超えています。 推移閉包を動的に維持することさえ、直接には実現できません。 

微妙ですが重要な観察は、エッジの状態は頻繁に変化しますが、クエリは現在のアクティブなエッジのセットにのみ依存するということです。 これは、動的サブグラフを維持し、その内部の到達可能性を繰り返しチェックしていることを示唆しています。 

素朴な考えを打ち破るエッジケースの 1 つは、小さなサイクルで交互にトグルを切り替えることです。 たとえば、三角形 1 → 2 → 3 → 1 について考えてみましょう。エッジが繰り返し切り替わる場合、到達可能性が単調に現れたり消えたりする可能性があるため、到達可能性の単調性を仮定する単純な増分 BFS は失敗します。 もう 1 つの問題は、無向接続技術が適用されると仮定していることです。 方向は非常に重要なので、union-find を直接使用することはできません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 現在のアクティブ エッジのセットを維持し、「v から u に到達可能ですか」タイプのクエリごとに、u から開始して BFS または DFS を実行し、現在アクティブなエッジのみを走査します。 各トグルは、対応するエッジのブール フラグを反転するだけです。 

これは、到達可能性の定義を直接シミュレートするため、正しいです。 ただし、最悪の場合、各クエリのコストは O(n + m) になります。 100,000 の操作と 100,000 のエッジを持つグラフの場合、これはおよそ 10^10 のエッジ トラバースとなり、これは許容できません。 

重要な洞察は、グラフ構造自体は静的であり、アクティブなエッジのサブセットのみが変化するということです。 これは、固定の有向グラフの誘導サブグラフに繰り返し取り組んでいることを意味します。 到達可能性を最初から再計算するのではなく、エッジが切り替わる場合でも到達可能性のクエリに迅速に応答できる構造を維持したいと考えています。 

重要なトリックは、問題を、特定の派生構造の各接続コンポーネントがエッジ フリップ下で効率的に維持できる形式に変換することです。 重要な観察は、有向グラフの到達可能性が強接続コンポーネント (SCC) を使用して分解できることです。 SCC 内では、すべての頂点が他のすべての頂点に到達できるため、SCC は DAG 内の圧縮されたノードのように動作します。 SCC を契約すると、到達可能性がコンポーネントの DAG 上のパスの問題になります。 

ただし、エッジが削除または追加されると SCC は動的に変化するため、クエリごとに SCC を最初から再計算することはできません。 代わりに、エッジは存在と不在の間でのみ切り替わるという事実を利用し、時間の経過に伴うセグメント ツリーと逆の時間間隔で SCC 圧縮に適用されるロールバック DSU (またはアンドゥ付き DSU) を組み合わせたオフライン処理戦略を使用して動的構造を維持します。

各エッジは、特定の時間間隔にわたってアクティブであるものとして処理されます。 各エッジが切り替わるので、そのアクティブ期間は時間軸上で互いに素なセグメントを形成します。 次に、クエリ タイムライン上でセグメント ツリーを使用し、アクティブな間隔に対応するノードに各エッジを挿入します。 各セグメント ツリー ノードで、その間隔内のアクティブ エッジによって引き起こされる接続を表す DSU 構造を維持します。 セグメント ツリーを再帰的に処理し、ノードに入るときに結合を適用し、ノードから出るときに結合を元に戻しながら、現在の収縮された構造の到達可能性を使用してリーフ時にクエリに応答します。 

重要な削減点は、接続性をグローバルに再計算することを回避し、代わりに重複する時間セグメント間で部分結合を再利用することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(q(n + m)) | O(n + m) | 遅すぎる |
 | 経時的なセグメント ツリー + DSU ロールバック | O((m + q) log q · α(n)) | O(n + m + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 時間を次元に変換し、各エッジを一定期間にわたってアクティブなものとして扱うことで、この問題を解決します。 

1. まずすべての操作をシミュレートし、エッジごとにアクティブな時間間隔を記録します。 トグルごとにセグメントが閉じたり開いたりするため、各エッジは多くても O(q) エンドポイントに寄与し、全体の間隔は q 内で線形のままになります。 
2. 操作の時間範囲にわたってセグメント ツリーを構築します。 各ノードは連続した時間間隔を表し、その間隔全体で完全にアクティブになっているすべてのエッジを格納します。 
3. エッジのアクティブ化間隔 [l, r] ごとに、そのエッジを完全にカバーするすべてのセグメント ツリー ノードにそのエッジを挿入します。 これにより、ノードを処理するときに、その時間セグメントに関連するすべてのエッジが 1 回だけ適用されることが保証されます。 
4. 頂点上に DSU を準備します。 元に戻す操作が必要なため、すべての親とサイズの変更を記録するロールバック スタックを備えた DSU を実装します。 
5. 深さ優先の方法でセグメント ツリーをトラバースします。 ノードに入るとき、そのノードに格納されているすべてのエッジに結合操作を適用し、それらのエッジの端点をマージします。 
6. リーフ ノードに到達すると、これは 1 つの時点に対応します。 現在の DSU 状態を使用して、現時点で発生するすべてのクエリに応答します。 
7. ノードの子を処理した後、親に戻る前に、そのノードで行われたすべての DSU 変更をロールバックします。 これにより、他の時間間隔でも正確さが保たれます。 

これが機能する理由は、各セグメント ツリー ノードがその時間間隔全体を通じてアクティブであることが保証されている一連のエッジを表すため、それらを一緒に適用しても安全だからです。 ロールバック メカニズムにより、エッジが有効な時間範囲外にリークしないことが保証されます。 

維持される不変条件は、DFS トラバーサル中のどの時点でも、DSU はルートから現在のノードまでの現在のセグメント ツリー パス内でアクティブなすべてのエッジの結合を正確に表すということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.history = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            self.history.append((-1, -1, -1, -1))
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.history.append((a, b, self.size[a], self.size[b]))
        self.parent[b] = a
        self.size[a] += self.size[b]

    def snapshot(self):
        return len(self.history)

    def rollback(self, snap):
        while len(self.history) > snap:
            a, b, sa, sb = self.history.pop()
            if a == -1:
                continue
            self.parent[b] = b
            self.size[a] = sa

def solve():
    n, m, q = map(int, input().split())
    edges = [None] + [tuple(map(int, input().split())) for _ in range(m)]

    active = [False] * (m + 1)
    last_on = [0] * (m + 1)
    seg = [[] for _ in range(4 * (q + 5))]

    def add(node, l, r, ql, qr, edge_id):
        if ql > r or qr < l:
            return
        if ql <= l and r <= qr:
            seg[node].append(edge_id)
            return
        mid = (l + r) // 2
        add(node * 2, l, mid, ql, qr, edge_id)
        add(node * 2 + 1, mid + 1, r, ql, qr, edge_id)

    ops = []
    for i in range(1, q + 1):
        tmp = input().split()
        if tmp[0] == '1':
            k = int(tmp[1])
            if active[k]:
                add(1, 1, q, last_on[k], i - 1, k)
                active[k] = False
            else:
                active[k] = True
                last_on[k] = i
            ops.append(('U', k))
        else:
            u, v = map(int, tmp[1:])
            ops.append(('Q', u, v))

    for i in range(1, m + 1):
        if active[i]:
            add(1, 1, q, last_on[i], q, i)

    dsu = DSU(n)
    res = [None] * (q + 1)

    def dfs(node, l, r):
        snap = dsu.snapshot()
        for eid in seg[node]:
            u, v = edges[eid]
            dsu.union(u, v)
        if l == r:
            op = ops[l - 1]
            if op[0] == 'Q':
                u, v = op[1], op[2]
                res[l] = (dsu.find(u) == dsu.find(v))
        else:
            mid = (l + r) // 2
            dfs(node * 2, l, mid)
            dfs(node * 2 + 1, mid + 1, r)
        dsu.rollback(snap)

    dfs(1, 1, q)

    out = []
    for i in range(1, q + 1):
        if res[i] is not None:
            out.append("YES" if res[i] else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、すべての操作を解析し、各エッジをアクティブな間隔に変換することから始まります。 各トグルはセグメントを開くか閉じます。 最後に、まだアクティブなエッジは時間 q で閉じられます。 これらの間隔はセグメント ツリーに挿入されるため、各時間範囲をその範囲全体でアクティブであることが保証されているエッジに関連付けることができます。 

DSU はロールバック サポートを備えて実装されています。 各ユニオンは、それ自体を元に戻すのに十分な情報を保存します。セグメント ツリーのトラバーサルでは、相互に干渉してはならない重複する時間間隔を探索するため、これは不可欠です。 

セグメント ツリー上の DFS は、ノードのすべてのエッジを適用し、その子を処理してから、DSU 状態を復元します。 クエリは、その時間インデックスに対応するリーフ ノードでのみ応答されます。 

## 実用的な例

 サンプル入力を考えてみましょう。 

エッジのアクティブ化とクエリを長期的に追跡します。 わかりやすくするために、クエリに関連する状態のみを示します。 

| 時間 | 操作 | 到達可能性に影響を与えるアクティブ エッジ | 回答済みの質問 |

2 番目の小さな例:

 入力:

 1→2、2→3

| 時間 | アクティブエッジ | 1→3 到達可能 |
 | --- | --- | --- |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((m + q) log q · α(n)) | 各エッジ間隔は O(log q) セグメント ツリー ノードに挿入され、各結合/検索はほぼ一定に償却されます。 
| スペース | O(n + m + q) | DSU とインターバル用のセグメント ツリー ストレージ |

 対数係数は、時間間隔のセグメント ツリー分解から得られます。 q が最大 100,000 であるとすると、厳しい制限下でも効率が維持され、DSU の動作は事実上一定になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、エッジが何度も切り替わり、最後のタイム ステップまでアクティブな間隔が終了しない場合です。 その場合、その間隔を q で明示的に閉じる必要があります。そうしないと、その間隔はセグメント ツリーに挿入されません。 たとえば、エッジ 1 が時間 2 にオンになり、一度もオフにならなかった場合、[2, q] でアクティブとして扱う必要があります。 

もう 1 つのケースは、クエリがすぐにキャンセルされるトグルと交互に発生する場合です。 エッジが 1 つのタイム ステップに対してアクティブな場合でも、エッジは有効な間隔 [t, t] として表現される必要があり、セグメント ツリーの挿入では単一点の範囲を正しく処理する必要があります。
