 ## 解決策
 ## 問題の理解

 開始位置から点を移動しようとしています$S$目的の場所へ$T$2D平面上で。 動きは継続的で、方向に制限はありません。 通常の状況では、キャラクターは一定の速度で歩きます$V_1$。 これはユークリッド距離の変位を意味します$d$時間がかかる$d / V_1$。 

特別な「滑走ポイント」もあります。 キャラクターがこれらのポイントのいずれかに触れると、すぐに一時的なブーストが得られます。ゲーム時間の次の 3 秒間、キャラクターの移動速度は次のようになります。$V_2$、 どこ$V_2 > V_1$。 3 秒後、歩く速度に戻ります。 

滑空ポイントに触れても、そこに移動するのに費やした時間以上の時間を消費することはありません。 主な難点は、滑空には時間が制限されており、複数のポイントを訪問することで複数回トリガーできることです。 からの移動時間を最小限に抑えたい$S$に$T$。 

入力により、最大 1000 のグライド ポイントの座標が与えられ、その後、$S$そして$T$、および 2 つの速度。 

出力は最大精度の実数です。$10^{-6}$、可能な限り最速の移動時間を表します。 

制約$n \le 1000$の二次関係を示唆しています。$n$、 のような$O(n^2)$、許容されます。 ただし、状態には位置と残りのブースト時間の両方が含まれており、これは連続的であるため、連続的な動きや時間の発展を直接シミュレートする試みは不可能です。 

いくつかのエッジな状況は誤って処理しやすいものです。 

グライドポイントがない場合、$S$からは遠い$T$、答えは単純に直線歩行時間でなければなりません。$dist(S,T)/V_1$。 少なくとも 1 つのグライドが存在する必要があると想定するアプローチは失敗します。 

グライド ポイントが直線セグメント上に正確に位置する場合、$S$に$T$、最適な解決策は、ジオメトリに応じてそれを無視するか、使用する可能性があります。 「常にグライドポイントを通過する」などの単純で貪欲な選択は、さらに悪いことになる可能性があります。 

グライド ポイントが集中している場合、それらを連鎖させると 3 秒間のブーストが繰り返し更新される可能性があります。 オーバーラップを追跡せずにブーストを個別に扱う単純なシミュレーションでは、合計速度の利点を過小評価または過大評価する可能性があります。 

## アプローチ

 ブルート フォース ビューは、問題を時間依存状態の連続最短経路問題として考えることから始まります。 どこからでも直接移動できます$T$、または、最初に任意のグライド ポイントに移動し、そのポイントに到達すると、3 秒間の高速移動が可能になります。 これは、位置と残りのブースト時間の両方を含む状態が連続していることを示唆しているため、直接の最短経路探索は実現できません。 

位置のみを離散化しようとすると、有用な軌道はグライドポイントまたはグライドポイントでのみ「モード」を変更することが観察できます。$S$そして$T$。 これにより、問題はノードがこれらの点であるグラフに縮小されます。 ただし、速度はアクティブなブーストで到着するかどうかに依存するため、エッジは単に距離を 1 つの速度で割ったものではありません。 

重要な観察は、2 つの固定点間を移動するときは常に、そのセグメントに沿った最適な戦略は単純であるということです。つまり、歩行速度のみを使用するか、利用可能なブーストの一部を最適に消費するかのどちらかです。 「アクティブなブーストの有無にかかわらず、現在ノードにいて、残り時間がいくらかある」状態としてモデル化すると、この構造は管理可能になります。 正確な残り時間を追跡する代わりに、最適な移行にはブーストを最大限に活用することのみが重要であることを利用します。 

これにより、展開された状態グラフ上の最短パスが得られます。各ノードには、「アクティブなグライドなし」と「グライドが利用可能」という 2 つの状態があります。 ある地点から別の地点に移動するには常に歩行時間がかかりますが、滑空地点に着陸するとブースト状態に切り替わり、加速移動が 3 秒間続きます。 ブースト状態では、単位時間あたりにより多くの距離を移動できます。 

関連するポイント間のすべてのペアワイズ距離 (グライド ポイントとグライド ポイントを加えたもの) を事前に計算できます。$S$そして$T$）。 次に、遷移はあるノードから別のノードへの移動に対応し、現在ブースト ウィンドウ内にいるかどうかに応じてグライド タイムの恩恵を受けることができるかどうかを更新します。 

これにより、問題がグラフ上の最短経路に帰着します。$O(n)$ノードと$O(n^2)$エッジ。各エッジはブースト モードかどうかに応じて重みを持ちます。

 ## アルゴリズムのチュートリアル

 あらゆるグライドポイントを扱います。$S$そして$T$, as nodes in a complete graph. すべてのペア間のユークリッド距離を事前計算します。 

次に、拡張された状態空間に対して最短パス アルゴリズムを実行します。 各状態は、ノード インデックスと、現在利用可能なアクティブなグライド ウィンドウがあるかどうかによって定義されます。 グライド期間は 3 秒に固定されているため、エッジ緩和中に継続的に残り時間を追跡するのではなく、トランジションで「グライド使用可能なセグメント」にいるかどうかを追跡するだけで済みます。 

2 つの距離配列を定義します。1 つはアクティブなグライド エフェクトなしでノードに到達するためのもので、もう 1 つはグライド モードであると仮定してノードに到達するためのものです。 

We initialize the start node$S$事前のグライド効果はなく、ダイクストラのようなリラクゼーションを実行します。 

## アルゴリズムのチュートリアル

 1. すべてのグライド ポイントに加えて、ノードのリストを作成します。$S$そして$T$。 This allows us to reduce the problem to transitions between discrete positions.
 2. ノードのすべてのペア間のユークリッド距離を事前計算します。 すべての移動コストは純粋に幾何学的距離に依存するため、これが必要になります。 
3. 状態を次のように定義します。$(i, t)$、 どこ$i$はノードインデックスであり、$t \in \{0,1\}$現在グライド ウィンドウの恩恵を受けているかどうかを示します。 2 番目のコンポーネントは、この状態からの移動に速度を使用するかどうかを決定します。$V_2$または$V_1$。 
4. 開始状態を除くすべての距離を無限大に初期化します。$(S, 0)$、これは 0 に設定されます。 
5. 優先キューを使用して、既知の最小時間で状態を繰り返し抽出します。 
6. 州から$(i, t)$、他のすべてのノードへの遷移を試みます$j$。 距離を計算する$d = dist(i, j)$。 もし$t = 1$、実効速度は$V_2$そして移動時間は$d / V_2$; それ以外の場合はそうです$d / V_1$。 
7. ノードの場合$j$はグライド ポイントです。到着したら、将来の遷移のためにグライド ステートをアクティブにし、次のステートを次の状態に設定します。$(j, 1)$。 それ以外の場合は、次のようになります$(j, 0)$。 
8. より短い時間が見つかった場合は距離を緩和し、更新された状態を優先キューにプッシュします。 
9. 答えは到達する最小値です$T$どちらの状態でも。 

正確さは、すべての最適なパスが離散イベント ポイント間の直線セグメントに分解できるという事実に基づいており、唯一のステートフルな効果は、トラバース中にグライド ウィンドウがアクティブであるかどうかです。 順番に訪問するノードからの逸脱は、時間を増やすことなく直線セグメントに置き換えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq
import math

def solve():
    n = int(input())
    pts = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
    
    sx, sy, tx, ty = map(int, input().split())
    v1, v2 = map(int, input().split())
    
    S = (sx, sy)
    T = (tx, ty)
    
    nodes = pts + [S, T]
    s_idx = n
    t_idx = n + 1
    m = n + 2
    
    dist = [[0.0] * m for _ in range(m)]
    
    for i in range(m):
        x1, y1 = nodes[i]
        for j in range(m):
            x2, y2 = nodes[j]
            dx = x1 - x2
            dy = y1 - y2
            dist[i][j] = math.hypot(dx, dy)
    
    INF = 1e100
    dp = [[INF] * 2 for _ in range(m)]
    dp[s_idx][0] = 0.0
    
    pq = [(0.0, s_idx, 0)]
    
    while pq:
        cur, i, state = heapq.heappop(pq)
        if cur != dp[i][state]:
            continue
        
        for j in range(m):
            if j == i:
                continue
            
            d = dist[i][j]
            speed = v2 if state == 1 else v1
            t = cur + d / speed
            
            nxt_state = 1 if j < n else 0
            
            if t < dp[j][nxt_state]:
                dp[j][nxt_state] = t
                heapq.heappush(pq, (t, j, nxt_state))
    
    ans = min(dp[t_idx])
    print("{:.12f}".format(ans))

if __name__ == "__main__":
    solve()
```実装は、開始点とターゲットを含むすべての関連ポイントにわたる完全なグラフを構築することから始まります。 距離行列はユークリッド距離を使用するため、その後のすべての遷移は定数時間ルックアップになります。 

DP 配列には、各ノードと状態のペアの最良の既知の時間が格納されます。 状態フラグは、ノードに到着すると新たなグライド効果が得られるかどうかを表します。 グライドポイント（最初のいずれかのポイント）に移動すると、$n$ノード)、状態をアクティブにリセットします。 それ以外の場合は非アクティブになります。 

優先キューにより、現在最速の既知の部分パスが常に拡張され、非負のエッジ重みに関するダイクストラの正確性条件が一致します。 唯一の微妙な詳細は、エッジの重みが目的の状態ではなく現在の状態に依存することです。そのため、遷移を計算する前に速度が選択されます。

 ## 特殊なケース

 特殊なケースは、グライド ポイントがない場合に発生します。 DP グラフには単に以下が含まれているだけであるため、アルゴリズムは引き続き機能します。$S$そして$T$、すべてのトランジションでは歩行速度が使用されます。 最短パスは 1 つのエッジに縮小されます$S \to T$、生産$dist(S,T)/V_1$。 

もう 1 つの微妙なケースは、グライド ポイントがダイレクト パスから非常に離れているにもかかわらず、高さのために魅力的な場合です。$V_2$。 DP は、直接移動とグライド ノードを介した迂回の両方の可能性を正しく評価します。これは、両方とも完全なグラフ内の明示的なエッジであるためです。 

複数のグライドポイントが互いに接近している場合、よりデリケートな状況が発生します。 グライド ノードにアクセスするたびに状態がリセットされるため、アルゴリズムは繰り返しのアクティベーションを自然に処理します。 同じ領域を再訪することが有益な場合でも、最短パス緩和により、改善されたシーケンスのみが優先キューに残ることが保証されます。
