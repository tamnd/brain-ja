 ## 解決策
 ## 問題の理解

 株式市場に似たシステムで、2 つのグループの参加者が与えられます。 1 つのグループには株式を購入したい人が含まれており、各人が支払ってもよい最高価格を指定します。 もう 1 つのグループには株を売りたい人が含まれており、それぞれが受け入れる最低価格を指定します。 

単一の最終価格$x$システムによって修正されます。 買い手は、提示価格が少なくとも以下の場合に参加します。$x$、彼らはそれ以上の金額を喜んで支払うからです。 売り手は、提示価格が最高額であれば参加します。$x$、彼らはその価格かそれ以下の価格を喜んで受け入れるからです。 タスクは、両方のグループの合計でこれらの条件を満たす人の数を数えることです。 

入力サイズは最大です$10^5$購入者と$10^5$売り手。 各要素を 1 回検査するソリューションであればどれでも受け入れられますが、並べ替えやネストされたスキャンを伴うものであれば問題ありません。 ただし、二次関数や要素ごとにフル スキャンを繰り返すものは遅すぎます。$10^{10}$最悪の場合の運用。 

このような問題でよくある間違いは、不等式の方向を誤解することです。 購入者が適格となるのは次の場合です。$a_i \ge x$、 ない$a_i \le x$。 販売者が適格となるのは次の場合です。$b_i \le x$、 ない$b_i \ge x$。 これらの条件を入れ替えると、カウントが完全に逆転します。 

すべての値が以下に等しい場合、別の微妙なエッジ ケースが発生します。$x$。 この状況では、両方のグループの参加者全員をカウントする必要があります。 ここでは、しきい値が 1 つオフのエラーはすぐに失敗します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての購入者をスキャンし、各値が少なくとも以下であるかどうかを確認します。$x$。 次に、すべての販売者をスキャンし、それぞれの値が最大かどうかを確認します。$x$。 条件が満たされるたびにカウンターをインクリメントします。 これが機能するのは、各決定が独立しており、最終的な答えが満足した参加者の合計数だけであるためです。 

この問題では順序付けやペアリングが必要ないため、このアプローチは漸近構造の点ですでに最適です。 これが「総当たり」とみなされる唯一の理由は、各要素を 1 つずつ明示的にチェックするためです。 

総操作数は、$n + m$、最大でも$2 \cdot 10^5$。 Python でも、これは簡単に制限内に収まります。 並べ替えや前処理を試みると不必要なオーバーヘッドが発生し、正確性やパフォーマンスは向上しません。 

重要な観察は、最終価格が参加者を 2 つの独立したフィルターに分ける固定しきい値として機能するということです。 買い手は下限でフィルタリングされ、売り手は上限でフィルタリングされます。 グループ間には相互作用がないため、問題は 2 つの単純なカウントに分解されます。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$n, m, x$。 これらは 2 つのグループのサイズとしきい値価格を定義します。 
2. カウンタをゼロに初期化します。 これにより、有効な参加者がすべて累積されます。 
3. 購入価格のリストを読みます。 それぞれの値について$a_i$、どうかを確認してください$a_i \ge x$。 そうであれば、カウンターをインクリメントします。 これは、買い手がシステム価格以上で取引する意思があることを反映しています。 
4. 販売価格のリストを読みます。 それぞれの値について$b_i$、どうかを確認してください$b_i \le x$。 そうであれば、カウンターをインクリメントします。 これは、販売者がシステム価格以下を受け入れる意思があることを反映しています。 
5. 最終カウンターを出力します。 

個別のループの背後にある理由は、各グループの不等式の方向が異なるため、それらを混合すると不必要な複雑さが生じ、誤った比較が行われる危険性があるためです。 

### なぜ効果があるのか

 各参加者は、自分の価格と固定しきい値のみに依存する単一の条件を独立して満たします。$x$。 ある参加者の決定が他の参加者に影響を与えることはありません。 この独立性により、有効な買い手と売り手を別々に数えて結果を合計することは、システム全体を評価することと同等です。 このアルゴリズムは基本的に、入力配列に対して定義された 2 つの素の条件セットの和集合のサイズを計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, x = map(int, input().split())

ans = 0

a = list(map(int, input().split()))
for v in a:
    if v >= x:
        ans += 1

b = list(map(int, input().split()))
for v in b:
    if v <= x:
        ans += 1

print(ans)
```コードはアルゴリズムを直接反映しています。 まずパラメータを読み取り、次に購入者と販売者を個別に処理します。 カウンター`ans`値がグループ固有の条件を満たす場合にのみ更新されます。 

よくある実装上の間違いは、厳密な不等式と非厳密な不等式を混合することです。 ここでは、両方のケースに平等が含まれます。購入者は受け入れる$a_i = x$、売り手は受け入れます$b_i = x$。 これは意図的であり、声明と一致しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, x = map(int, input().split())

    ans = 0

    a = list(map(int, input().split()))
    for v in a:
        if v >= x:
            ans += 1

            ans += 1

    return str(ans).strip()

 ## 特殊なケース

 重大なエッジケースは、すべての値がしきい値と等しい場合です。$x$。 例えば：```
3 2 5
5 5 5
5 5
```このアルゴリズムは、各買い手と売り手を個別に処理します。 両方の比較が行われるため、すべての比較は true と評価されます。$a_i \ge x$そして$b_i \le x$等しい場合は保持します。 カウンタは要素ごとに 1 回増加し、合計は 5 になります。厳密な不等式を使用する実装では、誤って 0 が返されます。 

もう 1 つのエッジケースは、誰も資格を得ることができない場合です。```
3 3 10
1 2 3
11 12 13
```ここではすべての購入者が失敗します$a_i \ge x$そしてすべての売り手は失敗する$b_i \le x$。 カウンタは全体を通してゼロのままであり、アルゴリズムが特別なケースを使用せずに空の選択セットを正しく処理していることを確認します。
