 ## 解決策
 ## 問題の理解

 英語の小文字のみで構成される単一の文字列が与えられます。 タスクは、この文字列を左から右にスキャンし、連続した文字が部分文字列を形成するたびにスキャンすることです。`"cjb"`、その出現の直後にカンマを挿入する必要があります。 文字列の残りの部分は変更されず、重複または繰り返しの出現は、出力の左から右の構造を尊重する方法で処理する必要があります。 

入力サイズは 100,000 文字に達する可能性があるため、部分文字列を繰り返し作成したり、文字列に対してネストされたスキャンを実行したりするソリューションは遅すぎることになります。 Python では 1 秒の制限時間内で約 100,000 回の操作が唯一の快適な予算であるため、文字列の長さが線形であるアルゴリズムが必要です。 

すべての位置をチェックし、スライスして文字列を再構築する単純なアプローチは、微妙な点で失敗する可能性があります。 問題の 1 つは、文字列の連結が繰り返されることによるパフォーマンスの低下であり、最悪の場合は 2 次結合になります。 もう 1 つの問題は、反復中にその場で文字列を変更しようとした場合に、重複するパターンが正しく処理されないことです。 

たとえば、次の入力を考えてみましょう。`"cjbjb"`。 部分文字列`"cjb"`冒頭に登場する。 カンマを挿入すると、次のようになります。`"cjb,jb"`。 インデックスを誤ってシフトする不用意なアプローチでは、文字がスキップされたり、変更された領域内で再照合が試行されたりして、カンマが重複したり、有効な一致が欠落したりする可能性があります。 

もう 1 つのエッジ ケースは、次のような出現のない文字列です。`"abcdef"`ここで、出力は入力と同一である必要があります。 間違ったアプローチを使用しても、境界チェックの欠陥により区切り文字が発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのインデックスを反復処理します。`i`文字列内で、各位置について、次から始まる部分文字列かどうかを確認します。`i`マッチ`"cjb"`。 その場合は追加します`"cjb,"`結果にアクセスし、適切にスキップして先に進みます。 それ以外の場合は、現在の文字を追加します。 

このアプローチはタスクの定義に直接従うため、正しいです。 問題は、結果の構築方法とインデックスの進め方の効率です。 文字列の連結を繰り返して実装した場合、各追加操作のコストは O(n) となり、最悪の場合は O(n²) になります。 n が 100000 までの場合、これは遅すぎます。 

重要な点は、以前の文字を再訪する必要がまったくなく、最後に表示されたいくつかの文字を超えて複雑な状態を維持する必要がないことです。 これにより、最近の文字の小さなローリング バッファーを維持しながら、単一パスで文字列を処理できるようになります。 バッファが一致したら`"cjb"`、それを発行し、すぐにコンマを挿入します。 

これにより、問題はストリーミング構築タスクに変わります。出力を段階的に構築し、各ステップで最後の 3 文字のみをチェックします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 増大する出力バッファーを維持しながら、文字列を 1 文字ずつ処理します。 

1. 空のリストを初期化する`out`出力文字を効率的に保存します。 二次連結コストを回避するために、文字列の代わりにリストが使用されます。 
2. 各文字を反復処理します。`ch`入力文字列に追加します。`out`。 追加はO(1)です。 
3. 追加するたびに、最後の 3 文字が追加されているかどうかを確認します。`out`形状`"cjb"`。 このチェックは、現在の長さが 3 以上の場合にのみ有効です。 
4. 一致するものが見つかった場合は、にカンマを追加します。`out`。 パターンは固定長であり、元の文字と挿入されたカンマを保持したいため、文字の削除やバックトラックは行いません。 
5. 文字列の終わりまで続けます。 
6. リストに参加する`out`最終的な文字列に変換して出力します。 

ステップ 3 が安全である理由は、現在位置で終了するパターンを検出するだけでよいためです。 左から右に処理し、出力の以前の部分を再訪問することはないため、有効な出現はすべて現在のインデックスで終了する必要があります。 

### なぜ効果があるのか

 すべてのステップで、構築されたプレフィックスは、`out`は、「次の文字列が出現するたびにカンマを挿入する」というルールに従って、入力文字列の対応するプレフィックスを正確に変換したものです。`cjb`このアルゴリズムは文字を削除したり並べ替えたりすることはなく、新しい文字を追加するだけです。`"cjb"`入力内の は出力にも連続して表示され、チェックにより、カンマがストリームの最後に表示される最初の瞬間に、出現ごとに 1 回だけ挿入されることが保証されます。 これにより、一致の欠落と重複した挿入の両方が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

out = []

for ch in s:
    out.append(ch)
    if len(out) >= 3 and out[-3] == 'c' and out[-2] == 'j' and out[-1] == 'b':
        out.append(',')

print(''.join(out))
```この解決策は、リストを使用した増分構築に依存しており、文字列の繰り返しコピーを回避します。 パターン チェックは最後の 3 文字に対してのみ実行されるため、反復ごとの時間は一定になります。 

実装の微妙な詳細は、文字列アキュムレータの代わりにリストを使用することです。 使用する`ans += ch`繰り返し実行すると、割り当てが繰り返されるため、パフォーマンスが大幅に低下します。 もう 1 つの重要な詳細は、インデックスを作成する前に長さを確認することです。`out[-3]`これにより、短いプレフィックスによる実行時エラーが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    out = []
    for ch in s:
        out.append(ch)
        if len(out) >= 3 and out[-3] == 'c' and out[-2] == 'j' and out[-1] == 'b':
            out.append(',')
    return ''.join(out)

# provided samples
assert run("pbpbppb\n") == "pbpbppb"
assert run("cjbismyson\n") == "cjb,ismyson"

# custom cases
assert run("cjb\n") == "cjb,"
assert run("ccjb\n") == "ccjb,"
assert run("cjcjb\n") == "cjcjb,"
assert run("abccjbb\n") == "abccjb,b"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`cjb`|`cjb,`| 最後の単一一致 |
 |`ccjb`|`ccjb,`| 一致がインデックス 0 から始まっていません。 
|`cjcjb`|`cjcjb,`| 重複しても安全な動作 |
 |`abccjbb`|`abccjb,b`| パターンに近い複数の文字の相互作用 |

 ## 特殊なケース

 入力用`"cjb"`、アルゴリズムは追加します`c`、`j`、`b`順次。 3 番目の文字でバッファは次で終わります。`"cjb"`, したがって、カンマがすぐに追加され、次のようになります。`"cjb,"`。 これ以上の文字は存在しないため、プロセスはきれいに終了します。 

入力用`"ccjb"`、バッファは次のように進化します。`"c" → "cc" → "ccj" → "ccjb"`。 最終ステップでのみサフィックスが一致し、`"ccjb,"`。 これは、アルゴリズムが固定位置でのパターンの位置合わせを必要とせず、サフィックス マッチングのみを必要とすることを確認します。 

入力用`"cjcjb"`、アルゴリズムにより、重なり合う構造が正しく処理されることが保証されます。 加工後`"cjc"`、一致は発生しません。 いつ`"cjb"`が最後に形成される場合、最後の出現のみがカンマをトリガーします。 これは、以前の部分的なプレフィックスが後の有効な一致に干渉しないことを示しています。
