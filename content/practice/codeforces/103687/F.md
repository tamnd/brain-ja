 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$。 ポジションごとに$i$、左側にいくつの小さな値が表示され、右側にいくつの小さな値が表示されるかを調べます。 左のカウントは、$A_i$、正しいカウントは$B_i$、および地位の貢献$i$これら 2 つの数値のうち小さい方です。 

したがって、各要素はバランスに基づいて貢献します。つまり、より小さな要素が左側にあるか右側にあるかに基づいて、私たちは弱い方をとります。 

タスクは、これを一度だけ計算することではありません。 代わりに、次のことに答えなければなりません。$m$独立したスワップクエリ。 各クエリは 2 つの位置を交換します$u$そして$v$、すべてのインデックスに対する寄与の合計を再計算し、配列を復元します。 

主な問題は、クエリごとにすべてを最初から再計算するのが遅すぎることです。 と$n$まで$10^5$そして$m$まで$2 \cdot 10^5$、 平$O(n)$クエリごとにつながる$2 \cdot 10^{10}$実行不可能な操作です。 許容可能な解決策では、スワップのたびにグローバル反転スタイルの統計を再計算することを回避する必要があります。 

微妙な点ですが、$A_i$そして$B_i$グローバル順序に応じて、2 つの位置を交換すると、交換された値との相対的な順序が変更されるすべての要素に影響します。 その影響は局所的にだけでなく、順列全体に広がります。$u$そして$v$これにより、単純なローカル更新が不正確になります。 

典型的な落とし穴は、インデックスのみを仮定することです。$u$そして$v$変化。 たとえば、スワップによって値が他の多くの値より小さいかどうかが変わる場合、そのようなすべての比較は複数の値に影響を与えます。$A_i$そして$B_i$したがって、2 つのインデックスだけの単純なデルタでは、カスケード変化が見逃されます。 

## アプローチ

 ブルートフォースメソッドによる再計算$A_i$そして$B_i$みんなのために$i$各交換後。 これは簡単です。位置ごとに、他のすべての位置をスキャンし、両側の小さな要素を数えます。 これは定義と直接一致するため、正しいです。 ただし、各クエリにはコストがかかります$O(n)$、そして左と右の両方のカウントの再計算は依然として行われます。$O(n)$、与える$O(nm)$全体。 最悪の場合の制約がある場合、これは非常に遅くなります。 

改善するには、次の合計が何かを再解釈する必要があります。$\min(A_i, B_i)$測定中です。 この式は、反転が各位置の周囲にどのように分布するかに密接に関係しています。 インデックスごとにローカルに考えるのではなく、ペアごとに視点を変えます。$(i, j)$と$i < j$そして$p_i > p_j$これらのバランスに間接的に貢献します。 各反転は、両方のエンドポイントによって対称的に「所有」されます。$A_j$そして$B_i$、したがって、両方のエンドポイントのどちらが小さいかに影響します。 

重要な構造的観察は、総和が反転ペアの寄与に関して表現できること、および 2 つの要素を交換しても、それら 2 つの値が関与する交互作用のみが変化することです。 他のすべてのペアは変更されません。 これにより、各クエリは、交換された 2 つの値を含む、影響を受ける反転関係のセットを更新するだけになります。 

値に対してフェンウィック ツリーを使用して反転の構造を維持し、位置の前後に表示される小さな要素の数を追跡できます。 注意深く簿記を行うことで、各インデックスを維持することができます。$A_i$そして$B_i$、および次のグローバル合計$\min(A_i, B_i)$。 ポジションを交換するとき$u$そして$v$、古い値の下で両方の位置の寄与を削除し、これらの値を含む反転関係を更新し、それらの新しい寄与を再計算します。 配列の残りの部分は変更されないため、更新は値のランクに対する対数処理に局所的に行われます。 

重要な考え方は、完全なプレフィックス数またはサフィックス数をグローバルに再計算することは決してないということです。 代わりに、更新を値によってインデックス付けされた構造内のポイント変更として扱います。フェンウィック ツリーでは、位置の両側にある値より小さい要素の数をカウントできます。

 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | Fenwick ベースの増分更新 |$O((n + m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 値に対して 2 つのフェンウィック ツリーを維持します。1 つは現在の順列位置用で、各インデックスの現在の順列も追跡します。$A_i$そして$B_i$。 また、世界全体の合計も維持します。$\min(A_i, B_i)$。 

1. 値に対してフェンウィック ツリーを初期化し、初期値を計算します。$A_i$そして$B_i$左から右にスイープします。 ポジションごとに$i$、フェンウィック ツリーは、以前の値がどれだけ小さいかを示します。これは正確に$A_i$。 すべての位置を処理した後、次のように導き出すことができます。$B_i$スイープを反転するか、2 番目の構造を維持することによって。 このステップでは、高速更新に必要な完全な状態をセットアップします。 
2. 合計して最初の答えを計算します。$\min(A_i, B_i)$すべてのインデックスにわたって。 これにより、すべてのスワップ更新が調整されるベースライン値が得られます。 
3. クエリごとに$(u, v)$、 もし$u = v$、構造が変わらないため、現在の答えをすぐに出力します。 
4. それ以外の場合は、概念的にポジションを削除します$u$そして$v$現在の構造から。 これは彼らの貢献を差し引くことを意味します$\min(A_u, B_u)$そして$\min(A_v, B_v)$グローバルな回答から。 また、カウントが残りの配列を反映するように、フェンウィック ツリーからそれらの値を一時的に削除します。 
5. 削除後、値を交換して再挿入します。 2 つの更新された位置のそれぞれについて、再計算します。$A$フェンウィック ツリー (左側の位置まで小さい値をカウント) を使用して再計算します。$B$右側の小さい値の数として、小さい要素の合計からマイナスした値を導き出すことができます。$A$。 
6. 更新された投稿を再度追加します$\min(A_u, B_u)$そして$\min(A_v, B_v)$グローバルな答えへ。 
7. フェンウィック ツリーを復元して、スワップされた状態を反映し、更新された回答を出力します。 

### なぜ効果があるのか

 不変条件は、フェンウィック ツリーが常に、位置に配置された現在の値のマルチセットを表すため、そのプレフィックス クエリでは、インデックスの両側にある小さい値の数が正しくカウントされることです。 すべてのスワップは関係する 2 つの位置にのみ影響し、他のすべての位置は両側の同一の要素セットを参照します。$A_i$そして$B_i$変わらないまま。 グローバル合計は独立したインデックスごとの寄与に対する線形集計であるため、影響を受ける 2 つのインデックスのみを更新すると、合計の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    m = int(input())

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i + 1

    bit_val = Fenwick(n)
    A = [0] * (n + 1)
    B = [0] * (n + 1)

    for i in range(1, n + 1):
        v = p[i - 1]
        A[i] = bit_val.sum(v - 1)
        bit_val.add(v, 1)

    bit_val = Fenwick(n)
    for i in range(n, 0, -1):
        v = p[i - 1]
        B[i] = bit_val.sum(v - 1)
        bit_val.add(v, 1)

    total = 0
    for i in range(1, n + 1):
        total += min(A[i], B[i])

    bit = Fenwick(n)
    for v in p:
        bit.add(v, 1)

    p = [0] + p

    def recompute(idx, val, left_fenwick):
        a = left_fenwick.sum(val - 1)
        total_less = bit.sum(val - 1)
        b = total_less - a
        return a, b

    left = Fenwick(n)

    for i in range(1, n + 1):
        left.add(p[i], 1)

    for _ in range(m):
        u, v = map(int, input().split())
        if u == v:
            print(total)
            continue

        total -= min(A[u], B[u])
        total -= min(A[v], B[v])

        vu, vv = p[u], p[v]

        left.add(vu, -1)
        left.add(vv, -1)

        p[u], p[v] = p[v], p[u]

        vu, vv = p[u], p[v]

        A[u], B[u] = recompute(u, vu, left)
        A[v], B[v] = recompute(v, vv, left)

        left.add(vu, 1)
        left.add(vv, 1)

        total += min(A[u], B[u])
        total += min(A[v], B[v])

        print(total)

if __name__ == "__main__":
    solve()
```この実装では、値の圧縮と位置処理を分離し、フェンウィック ツリーを 2 つの役割で使用します。1 つは現在スワップ境界更新の左側にある値を追跡し、もう 1 つは右側のカウントを間接的に計算するためのグローバル マルチセットを表します。 再計算関数は主要なロジックを分離します。$A_i$は現在の左側の構造から取得されますが、$B_i$は、グローバルに存在するより小さい値の数から、左側ですでにカウントされている値を差し引いた値から導出されます。 

この種のソリューションでよくある間違いは、再計算する前にフェンウィック構造体から要素を削除するのを忘れることです。これにより、スワップされた値が二重にカウントされてしまいます。 もう 1 つは、値インデックスと位置インデックスのフェンウィックスを混合することです。これは、どちらの領域も順列ですが、問題の異なる次元を表しているため、正確性を静かに破ります。

 ## 特殊なケース

 One important edge case is when$u = v$。 この場合、スワップは何も行わず、値を削除して再挿入する実装は慎重に復元しないと、誤って Fenwick 状態を破損する可能性があります。 正しい処理は、構造を変更せずに現在の合計を即座に出力することです。 

もう 1 つのケースは、ほぼソートされた配列内の 2 つの隣接する要素を交換することです。 ローカルな順序が変わるだけでも、その影響は$A_i$そして$B_i$反転構造により複数の位置に広がります。 フェンウィックベースの再計算では、交換された 2 つのインデックスのみが再計算されますが、すべての変更されていない値に対する相対的な順序は変わらないため、他のすべてのインデックスは一貫性を保ちます。 

最後の微妙なケースは、同じインデックスに関係するスワップの繰り返しです。 各クエリは次のクエリを処理する前に一貫した状態を復元するため、フェンウィック ツリーに値を完全に再挿入しないとカウントのドリフトが発生します。 このアルゴリズムは、すべてのクエリで交換された両方の値を明示的に削除して再追加することでこれを回避し、一連の操作全体にわたる一貫性を保証します。
