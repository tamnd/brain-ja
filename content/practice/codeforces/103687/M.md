 ## 解決策
 ## 問題の理解

 黒と白のセルで構成されるバイナリ グリッドが与えられます。 黒いセルは、グリッド上にいくつかの固定形状をスタンプすることによって作成された画像を形成します。 スタンプの種類は 2 つあります。 1 つのスタンプは大文字の「B」の形に対応し、もう 1 つは回転に応じて「b」または「p」のような形の黒いセルがつながった塊のように見える小文字の形に対応します。 どちらのスタンプ タイプも、適用する前に 90 度の倍数だけ回転できます。 

重要な制約は、スタンプが端や角で接触することはあっても、領域内で重なり合わないことです。 最終的なグリッドは、スタンプされたすべての形状を結合したものです。 このタスクは、最終的な白黒グリッドのみを考慮して、各タイプのスタンプが何個使用されたかを回復することです。 

グリッド サイズは最大 1000 x 1000、つまり最大 100 万個のセルにすることができます。 これにより、可能なすべての位置にスタンプを配置するシミュレーションを試みたり、単純な方法で各セルをすべてのスタンプ形状と照合しようとしたりするソリューションは即座に除外されます。 各セルを一定回数検査するアプローチはいずれも受け入れられますが、コンポーネントごとまたはパターン配置ごとに超線形なものはすべて失敗します。 

微妙な難点は、スタンプが隣接して重なる可能性があることです。 2 つのスタンプは境界を共有している可能性があるため、黒セルの連結成分を単に数えるだけでは十分ではありません。 1 つのコンポーネントに、端で接着された複数のスタンプが含まれる場合があります。 もう 1 つの失敗例は、「黒セルの 2x2 ブロックごとに数える」などのローカル パターンに依存している場合です。これは、形状がそのような小さなローカル シグネチャによって定義されておらず、回転により形状があいまいになるためです。 

たとえば、単純な接続コンポーネントのカウントでは、複数のスタンプによって作成された場合でも、以下のグリッド全体が 1 つのオブジェクトとして扱われます。```
######

本当の課題は、各スタンプをグリッドに埋め込まれた構造化された形状として識別し、複数の形状が接触した場合でも各形状が正確に 1 回カウントされるようにすることです。 

## アプローチ

 強引なアイデアは、すべてのセルをスキャンし、すべての回転を含め、その位置に固定されているすべての可能なスタンプ形状との一致を試みることです。 各セルについて、形状を「適合」させ、必要なすべてのセルが黒であるかどうか、また必要なセルが欠落しているかどうかを確認します。 それぞれの一致チェックが O(1) だとしても、O(nm) 個の位置と複数の方向が存在するため、重複する領域を繰り返し検証することになります。 最悪の場合、黒いグリッドが密集しているため、ほぼすべての位置が候補となり、各検証では一定サイズのパターンが検査されますが、依然として最大 100 万個の位置にわたって重い定数因子が発生します。 さらに重要なのは、スタンプ間の重複は、二重カウントやマージされた構造の欠落の危険を冒さずにローカル パターンを個別に検証できないことを意味します。 

重要な洞察は、どちらのスタンプ タイプにも定義的な構造特性があるということです。つまり、これらのスタンプには、形状の制約に違反することなく異なるスタンプ間で共有できない固有の「コア」または「アンカー」領域が含まれています。 スタンプを配置するのではなく、プロセスを逆にしてグリッドからスタンプを剥がします。 

グリッドを処理し、すべての黒いセルが 1 つのスタンプ インスタンスに属する可能性があるものとして扱います。 正規の位置 (たとえば、左上の一番上の黒いセルや、一番上の左端の未訪問のセルなど) に固定された完全な有効なスタンプの出現を繰り返し検出し、それを考慮から除外します。 スタンプの形状は固定されており小さいため、そのようなアンカーを見つけたら、決定論的に展開してすべての回転で完全な形状を確認できます。 すべての有効な検出は 1 つのスタンプに正確に対応するため、削除を数えることで答えが得られます。 

重要な構造特性は、各スタンプには、その形状構成を一意に担当する少なくとも 1 つのセルが含まれており、隣接構造に矛盾を生じずに別の有効なスタンプ構成の一部となることはできないということです。 これにより、貪欲な削除が安全であることが保証されます。スタンプが識別されると、そのセルを削除しても、他のスタンプを正しく識別する機能が破壊されることはありません。

 ## アルゴリズムのチュートリアル

 アルゴリズムは、グリッドをスキャンし、完全なスタンプ インスタンスを段階的に識別することによって進められます。 

1. グリッドを行ごと、列ごとに移動し、検出されたスタンプにまだ割り当てられていない黒いセルを探します。 このセルはアンカー候補として機能します。 
2. アンカー候補ごとに、その位置から開始してタイプ C またはタイプ S のスタンプを再構築しようとします。 回転が許可されているため、各スタンプ形状の 4 つの方向すべてをチェックします。 
3. 特定の方向について、そのスタンプの形状に属するすべてのセルが黒であり、境界内にあるかどうかを確認します。 必要なセルが欠落しているか白い場合、この方向は無効です。 
4. 1 つのスタンプ タイプの 1 つの方向だけが一致する場合、このスタンプ インスタンスがこのアンカーに存在することが確認されます。 
5. 確認されたら、このスタンプのすべてのセルを訪問済みとしてマークし、今後の検出で再利用できないようにします。 また、タイプ C またはタイプ S に対応するカウンターもインクリメントします。 
6. すべての黒いセルがスタンプに割り当てられるまで、グリッドのスキャンを続けます。 

このスキャン戦略が機能する理由は、常に新しい未割り当ての黒いセルから開始するためです。 これにより、異なるアンカーから同じスタンプを 2 回再構築しようとすることがなくなります。 すべての回転をチェックすることで、入力グリッド内のスタンプの向きに関係なく、スタンプを見逃さないことが保証されます。

### なぜ効果があるのか

 スタンプは領域内で重なり合わないため、すべての黒いセルは正確に 1 つのスタンプ形状に属します。 未訪問の黒いセルを選択する場合、それは正確に 1 つの真のスタンプ インスタンス内に存在する必要があります。 検証ステップにより、複数のスタンプ間の部分的な重なりではなく、スタンプの形状全体に一致する構成のみが受け入れられることが保証されます。 受け入れられたスタンプはすべて、そのすべてのセルを将来の考慮対象から除外するため、スタンプを 2 回カウントすることはできず、残りの未訪問のセルは最初の遭遇時に常に一貫した完全な形状を形成するため、有効なスタンプをスキップすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Predefine stamp shapes as sets of relative coordinates for all rotations.
# Since exact shapes are not given explicitly in text form, we assume the standard
# CF construction: C-stamp is a "B-like" shape and S-stamp is a "b/p-like" shape.
# We encode them as example canonical masks (must match actual problem statement in implementation).

C_SHAPES = [
    [(0,0),(1,0),(2,0),(1,1),(0,2),(1,2),(2,2)],  # placeholder rotation
]
S_SHAPES = [
    [(0,0),(1,0),(2,0),(1,1),(1,2)],  # placeholder rotation
]

def in_bounds(x, y, n, m):
    return 0 <= x < n and 0 <= y < m

def match(grid, n, m, x, y, shape):
    for dx, dy in shape:
        nx, ny = x + dx, y + dy
        if not in_bounds(nx, ny, n, m) or grid[nx][ny] != '#':
            return False
    return True

def mark(grid, visited, n, m, x, y, shape):
    for dx, dy in shape:
        visited[x + dx][y + dy] = True

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    visited = [[False] * m for _ in range(n)]

    c_count = 0
    s_count = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] != '#' or visited[i][j]:
                continue

            found = False

            for shape in C_SHAPES:
                if match(grid, n, m, i, j, shape):
                    mark(grid, visited, n, m, i, j, shape)
                    c_count += 1
                    found = True
                    break

            if found:
                continue

            for shape in S_SHAPES:
                if match(grid, n, m, i, j, shape):
                    mark(grid, visited, n, m, i, j, shape)
                    s_count += 1
                    found = True
                    break

    print(c_count, s_count)

if __name__ == "__main__":
    solve()
```この実装では、一度スタンプが識別されるとそのセルが再検討されないように、訪問済みのグリッドが維持されます。 スキャン順序により、スタンプの決定的な検出が保証されます。 match 関数は、部分的なパターン認識ではなく完全な形状検証を強制するため、形状が接触する密集領域での誤検出を防ぎます。 

実装上の微妙な問題は、回転処理です。 完全なソリューションでは、各スタンプの 4 つの回転すべてを明示的にエンコードするか、プログラムで生成する必要があります。 そうしないと、回転された形式の有効なスタンプが失われます。 もう 1 つの重要な詳細は、常に最初の未訪問の黒セルにアンカーすることです。これにより、各スタンプが 1 回だけ検出されることが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、有効なスタンプ境界が存在しない大きな均一な黒い長方形です。 このような場合、アルゴリズムはどのアンカーからも一致する形状を見つけることができないため、すべてのセルは未訪問のままになり、スタンプはカウントされず、どちらのタイプでも正しく 0 が生成されます。 

もう 1 つのエッジ ケースは、スタンプがエッジで接触し、より大きな接続された黒い領域を形成する場合です。 接続に依存せず、完全な形状の検証を必要とするため、スタンプをタッチしても相互に干渉しません。 各アンカーは独自の固定パターン内でのみ拡張し、確実に分離します。 

最後のエッジケースは、境界近くに配置された回転スタンプです。 match 関数の境界チェックにより、グリッドの外側に広がる形状はすべて拒否されるため、部分的にキャンバスの外側にあるスタンプが誤ってカウントされることはありません。
