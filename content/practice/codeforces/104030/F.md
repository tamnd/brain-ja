 ## 解決策
 ## 問題の理解

 隠されたセットが与えられています。$n$サッカー チームごとに 1 つずつ文字列が作成され、異なるチームの各ペアによって、2 つのチーム名を順番に連結しただけの記録された一致文字列が生成されます。 入力により全体が得られます。$n \times n$これらの連結のテーブル。エントリは$(i, j)$等しい$s_i + s_j$のために$i \neq j$、対角線にはアスタリスクが付けられます。 

タスクは、すべての元の文字列を再構築することです。$s_1, s_2, \ldots, s_n$。 問題は、連結された文字列間の境界が分からず、複数の有効な分解が存在する可能性があることです。 解決策が存在しないのか、解決策が 1 つだけ存在するのか、それとも複数の解決策が存在するのかを判断する必要があります。 

構造は高度に制約されています: 行内のすべての文字列$i$同じ未知のプレフィックスを共有します$s_i$、および列内のすべての文字列$i$同じ未知のサフィックスを共有します$s_i$。 この対称性は、再構築を可能にする重要な構造的制約です。 

制約は 2 つの点で厳しいです。 初め、$n \le 500$これにより、ペアごとの分割候補に対する三次またはそれより悪い列挙が除外されます。 次に、すべての文字列の合計の長さは最大でも$10^6$つまり、すべての文字にわたる線形パスは可能ですが、ペアごとに高価な再計算を繰り返す必要はありません。 どのようなソリューションでも、連結された各文字列を独立して大量に扱うことは避けなければなりません。 

微妙な特殊なケースとしては、チーム名の繰り返しまたは同一による曖昧さがあります。 たとえば、すべての文字列が等しい場合、すべての連結が同一に見えるため、解空間が爆発的に増加する可能性があります。 もう 1 つの問題は、無効な一貫性です。テーブルによっては、ローカルでは一貫性があるように見えても、グローバルでは一貫性が不可能な場合があります。 

素朴なアプローチでは、それぞれを推測しようとします。$s_i$単一行から考えられるすべての分割を試します。 固定の場合$i$、各文字列$s_i + s_j$は可能な分割点を示し、すべての可能性を試して制約を伝播する可能性があります。 しかし、これはすぐに組み合わせの爆発につながります。$s_i$誘発する$O(n)$チェック、そして、$O(L)$文字列ごとに可能な分割ポイント。 これは次のようになります$O(n^2 L)$さらに悪いことに、遅すぎる$L = 10^6$。 

## アプローチ

 重要な観察は、各行がプレフィックスの違いに至るまで構造的に同一であるということです。 単一の行に注目すると$i$、すべてのエントリ$a_{ij}$まさに$s_i + s_j$。 つまり、修正すれば$s_i$、次に行内のすべての文字列$i$はそのプレフィックスを共有する必要があり、それを削除すると、他のすべてのチーム名の完全なマルチセットが表示されるはずです。 

したがって、問題は候補者を選ぶことになります$s_i$ある列のために$i$、そしてそれがグローバルに一貫しているかどうかをチェックします。 

ブルートフォース戦略は行を選択することです$i$、エントリの 1 つを分割するためにあらゆる方法を試してください。$a_{ij}$プレフィックスとサフィックスを分割し、プレフィックスを候補として扱います$s_i$、検証します。 各検証では、すべての項目についてチェックする必要があります。$j$、このプレフィックスを削除すると、列構造にも一致する一貫した文字列のセットが生成されます。 これは、各候補がテーブル全体をスキャンする必要があり、行ごとに多くの候補があるため、コストがかかります。 

主要な構造の簡素化は、1 つの固定行から派生した候補のみを考慮する必要があり、候補プレフィックスごとに残りの文字列が一意に決定されることです。 仮説を立てると$s_1$、1つおき$s_j$の接尾辞を取得することによって強制されます$a_{1j}$。 これにより、推測するのではなく、検索スペースが劇的に崩壊します。$n$文字列の場合、1 つの文字列だけを推測し、残りを導き出します。 

次に、すべての行を使用してグローバルに検証し、有効な構造がいくつ存在するかをカウントすることで曖昧さを考慮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 行 1 をアンカーとして使用して再構築しようとすると仮定します。 他の行も機能しますが、1 行を修正すると整合性チェックが簡素化されます。 

### 1. 候補プレフィックスを抽出する

 可能なすべての文字列の分割を反復処理します。$a_{1j}$のために$j \neq 1$。 各分割では次のような仮説が定義されます。$s_1$の接頭辞です$a_{1j}$、接尾辞は$s_j$。 

各スプリットは構築シードの候補です。 これが可能な解決策の唯一の情報源です。$s_1$すべての接頭辞として出現する必要があります$a_{1j}$一貫した方法で。 

### 2. 完全な候補ソリューションを構築する

 一部の選択されたスプリット ポジションに対して$a_{1j}$、次のように設定します。$s_1$プレフィックスとして、そして$s_j$接尾語として。 それから、お互いに$k$、私たちは導き出します$s_k$の接尾辞として$a_{1k}$取り外した後$s_1$一致する場合に限ります。 

このステップは強制的に行われます: 1 回$s_1$が固定されているため、他の文字列には柔軟性が残されていません。 

### 3. 行の一貫性を検証する

 すべてのペアについてそれを検証します$(i, j)$、再構築された文字列は次の条件を満たします。$s_i + s_j = a_{ij}$。 これにより、局所的な矛盾が存在しないことが保証されます。 

また、構築された各文字列が空ではないことも確認します。 

### 4. 有効な解決策を数える

 すべての分割候補に対してこのプロセスを繰り返し、有効な完全な再構成が得られる個数を数えます。 ゼロの場合は、NONE を出力します。 存在する場合は、UNIQUE を出力し、解決策を出力します。 複数ある場合はMANYを出力します。 

### なぜ効果があるのか

 重要な不変条件は、有効なソリューションはすべて行 1 にわたって一貫したグローバル プレフィックス構造を持たなければならないということです。$s_1$すべてのプレフィックスとして出現する必要があります$a_{1j}$、 なぜなら$a_{1j} = s_1 + s_j$。 したがって、すべての有効な分解は、いくつかの分割を選択することによって生成されます。$a_{1j}$、その他すべての文字列は減算によって一意に強制されます。 候補が完全な検証に生き残った場合、それは真の解に対応する必要があり、有効な解が失われることはありません。$s_1$この列挙に含める必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, n, s1, cand):
    # cand[i] is supposed s_i
    for i in range(n):
        if len(cand[i]) == 0:
            return False
    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            if cand[i] + cand[j] != a[i][j]:
                return False
    return True

def solve():
    n = int(input())
    a = [list(input().strip().split()) for _ in range(n)]

    res = None
    cnt = 0

    # try all splits from row 0
    for j in range(1, n):
        s = a[0][j]
        L = len(s)
        for k in range(1, L):
            s1 = s[:k]
            s_j = s[k:]

            cand = [None] * n
            cand[0] = s1
            cand[j] = s_j

            ok = True

            # derive others from row 0
            for t in range(1, n):
                if t == j:
                    continue
                if not a[0][t].startswith(s1):
                    ok = False
                    break
                cand[t] = a[0][t][len(s1):]

            if not ok:
                continue

            if not check(a, n, s1, cand):
                continue

            cnt += 1
            if cnt == 1:
                res = cand
            else:
                print("MANY")
                return

    if cnt == 0:
        print("NONE")
    else:
        print("UNIQUE")
        for x in res:
            print(x)

if __name__ == "__main__":
    solve()
```この実装は、最初の行で観察された単一の連結を分割するために考えられるすべての方法を列挙することに重点を置いています。 各分割で候補を定義します$s_1$、残りのチーム名は、行 1 のエントリからこのプレフィックスを減算することによって強制されます。 ヘルパー チェックにより、マトリックス全体にわたる完全なグローバルな一貫性が保証されます。 

微妙な点は、行 0 に一貫性があると、すべての行が同じ分解を通じて自動的に制約されるため、行 0 から派生した構築のみを検証する必要があることです。 最終チェックでは、隠れた不一致が残っていないことを確認します。 

もう 1 つの重要な詳細は、早期の枝刈りです。構築された文字列が予想される連結と一致しないとすぐに、候補を破棄します。 これにより、不要な満杯を防ぐことができます$O(n^2)$ほとんどの場合、検証が行われます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのチーム名が同一である場合です。 この場合、テーブル内のすべてのエントリは同じ繰り返し文字列であり、分割点によって有効な分解が生成されます。 アルゴリズムは複数の分割を試行し、複数の有効なソリューションを正確にカウントし、多くの結果が得られます。 

もう 1 つの特殊なケースは、有効なプレフィックスとして機能できる文字が 1 つだけである場合です。 たとえば、すべての文字列が同じ文字で始まっているが、完全な一貫性を保持している分割が 1 つだけである場合、サフィックスが必要な連結と一致しないため、他のすべての候補は行検証中に失敗します。 

最後の微妙なケースは、プレフィックス構造が行 0 では一貫しているが、別の行では壊れる場合です。 検証ステップにより、これが確実に捕捉されます。行 0 の導出が成功した場合でも、連結が再計算されるときに行単位のチェックによって不一致が検出され、偽の UNIQUE ではなく NONE が出力されることが保証されます。
