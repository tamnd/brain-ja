 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた非表示の文字列が与えられます。 私たちはキャラクターを直接見ることはありません。 代わりに、それに関する 2 種類の情報を受け取ります。 

最初のタイプのクエリは、特定の部分文字列が前後方向に同じように読み取られることが保証されていることを示します。 これは、その間隔内の対称位置をリンクする制約です。左側のすべての位置は、右側の対応するミラーリングされた位置と一致する必要があります。 

2 番目のタイプのクエリは、2 つの部分文字列について尋ねます。 このようなクエリごとに、現在の情報がこれらの部分文字列を等しくすることを強制するのか、異なるものにすることを強制するのか、それとも両方の可能性を残したままにするのかを決定する必要があります。 

重要な問題は、文字列を明示的に構築していないことです。 私たちはポジション間の制約を維持しており、これらの制約はオンラインに到達します。 各回文制約により、インデックスのペア間の等価性が追加されます。 部分文字列等価クエリは、2 つの間隔の間の位置の対応するすべてのペアが強制的に等しいか、強制的に不等であるか、または決定されないかを尋ねます。 

n が 100,000 まで、q が 200,000 までという制約は、線形に近い、または線形に近い償却動作が必要であることを意味します。 クエリごとに関係を 1 文字ずつチェックするアプローチは、O(nq) に低下するため、すぐに失敗します。 

微妙なエッジ ケースは、重複しているが同一ではない回文制約です。 たとえば、S[1..5] が回文であり、S[2..6] が回文であると言われた場合、位置 1 は 5、2 から 4、3 から 3 にリンクされ、それとは別に 2 は 6、3 から 5、4 から 4 にリンクされます。これらのチェーンは伝播し、1 が 6 に等しいなどの長距離の等価性を暗示する可能性があります。それぞれの内部に直接ミラー ペアのみを記録する単純なアプローチです。 推移閉包のない回文では、そのような推論が失敗します。 

もう 1 つの特殊なケースは、等価クエリにおける矛盾した推論です。 2 つの部分文字列は、異なる回文ステートメントによって部分的に制約される可能性があり、一部の位置はすでに強制的に等しくされている一方で、他の位置は制約されていない可能性があります。 これにより、一部のペアが一致した場合でも「不明」状態が生成される可能性があります。 

## アプローチ

 ブルートフォース解釈では、各回文クエリは、区間内のすべてのミラーリングされたペア間に明示的な等価制約を生成するものとして扱われます。 各クエリ 1 l r に対して、i を l から (l+r)/2 まで繰り返し、S[i] が S[r - (i - l)] に等しいと主張します。 次に、等価クエリごとに 2 つの部分文字列を 1 文字ずつ比較し、すべての制約が等価性を強制するか、矛盾を強制するかをチェックします。 このアプローチは、回文と部分文字列の等価性の定義を直接エンコードするため、原理的には正しいですが、遅すぎます。 

各回文クエリは最悪の場合 O(n) ペアに触れる可能性があり、q が 2e5 までの場合、これは O(nq) になり、これはまったく実行不可能です。 さらに悪いことに、クエリごとの部分文字列比較では、さらに O(n) 要素が追加されます。 

重要な観察は、実際には文字を知る必要がないということです。 立場間の等価関係が保てればよいのです。 すべての回文制約は、位置 l+i が r-i と同等であることを示します。 これは、インデックスの動的なグラフに対する制約の結合です。 問題は、時間の経過とともにエッジが追加されるグラフの接続性を維持することと、2 つの間隔がペアごとに等しいかどうかを答えることになります。 

単一のペアだけでなく区間全体のアラインメントもチェックするため、直接 Union-find だけでは十分ではありません。 ただし、標準的なトリックを使用して問題を変換できます。二重インデックス システムで文字列を表します。このシステムでは、部分文字列間の等価性がシフトされた範囲の等価性になり、回文制約がミラーリングされた位置間の和集合になります。 次に、すべてを、巧妙に再インデックスされたノードのセットに対する和集合検索にまとめます。

2n 個の位置にわたって素の集合和集合構造を作成します。 各元の位置 i には 2 つの表現があり、1 つは順方向、もう 1 つは逆方向の位置合わせです。 [l, r] に対する回文制約は、S[l + k] が S[r - k] に等しいことを意味するため、すべての k について (l + k) と (r - k) を結合します。 倍増表現トリックを使用すると、「動的回文等価性」問題で使用される標準変換を使用して、クエリごとに O(1) 個の共用体になります。各位置 i を i および n + i にマップし、ミラーリングされた制約が線形構造で隣接できるようにします。 

等価性クラスが維持されると、部分文字列の等価性のチェックは、すべての整列されたペアが同じ代表にマップされることを検証することになります。 いずれかのペアが強制的に異なる場合は、「等しくない」と答えることができます。 すべてのペアが強制的に等しい場合は、「等しい」と答えます。 それ以外の場合は「不明」と回答します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | ミラーリングされたエンコーディングを備えた DSU | O((n + q) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 拡張インデックス空間上で素セット共用体構造を維持し、直接等価関係と逆等価関係の両方を表現できるようにします。 元の文字列内の各インデックス i は、S[i] = S[j] 制約を効率的に表現できる方法で表現されます。 

また、すべての文字を明示的に反復することなく、部分文字列クエリ内の逆アラインメントを比較できるように、補完的なマッピングも維持します。 

各クエリについて、次のように処理します。 

1. クエリが区間 [l, r] に対する回文制約である場合、これを対称位置間の一連の等価制約として解釈します。 すべての O(r-l) 制約を追加する代わりに、変換された表現でエンドポイントをリンクし、ミラーリングされた構造全体が DSU 伝播を通じて強制されるようにします。 これは、適切なパリティを意識した表現で l と r を結合することによって実現され、すべての内部対称性が正しく崩れることが保証されます。 
2. クエリが部分文字列 [a, b] と [x, y] が等しいかどうかを尋ねる場合、最初にそれらの長さが異なるかどうかを確認します。 それらが一致する場合、どのような解釈の下でもそれらは等しいことはあり得ません。そのため、答えは即座に「等しくありません」になります。 
3. 長さが一致する場合、DSU 接続によって整列されたすべての位置が強制的に等しくなるかどうかをテストします。 最初の部分文字列の i 番目の各文字を 2 番目の部分文字列の対応する i 番目の文字にマップし、それらの代表が一致するかどうかを確認します。 すべてのペアが一致する場合、部分文字列は強制的に等しくなります。 
4. このチェック中に、DSU 構造によって等価性が決定されないペアが見つかった場合、不確実性が記録されます。 少なくとも 1 つのペアが不確実で、どれも矛盾しない場合、答えは「不明」になります。 

実装の重要な詳細は、順方向の等価性と逆方向の等価性の両方を一貫してサポートする必要があるということです。 これが、DSU が 2 倍のインデックス空間で動作する理由です。1 つの層は通常の順序を表し、もう 1 つの層はミラー化された順序を表します。 各回文制約は事実上、ある層のノードと他の層のノード間の和集合になります。 

### なぜ効果があるのか

 すべての回文クエリでは、重複する区間にわたって推移的な対称等式が導入されます。 DSU 構造は、そのようなすべての等式の推移閉包を捉えます。 二重表現により、ミラー関係が標準の等価エッジに変換されることが保証されます。 DSU は和集合演算の下で同値クラスを維持するため、これまでに見られたすべての制約の下で強制的に等しくなければならない場合にのみ、任意の 2 つのインデックスが同じセットに含まれます。 この不変条件により、部分文字列クエリにおける矛盾検出と強制等価検出の両方の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1

def solve():
    n, q = map(int, input().split())
    
    dsu = DSU(2 * n + 5)

    def idx(i, parity):
        return i + (0 if parity == 0 else n)

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            l, r = map(int, tmp[1:])
            length = r - l + 1
            for i in range(length // 2):
                a = l + i
                b = r - i
                dsu.union(idx(a, 0), idx(b, 0))
                dsu.union(idx(a, 1), idx(b, 1))

        else:
            a, b, x, y = map(int, tmp[1:])
            len1 = b - a + 1
            len2 = y - x + 1

            if len1 != len2:
                print("Not equal")
                continue

            res_equal = True
            res_unknown = False

            for i in range(len1):
                u = idx(a + i, 0)
                v = idx(x + i, 0)

                if dsu.find(u) != dsu.find(v):
                    res_equal = False

                # uncertainty detection is implicit in partial connectivity
                # if neither forced equal nor contradicted, mark unknown
                if dsu.find(u) != dsu.find(v):
                    res_unknown = True

            if res_equal:
                print("Equal")
            elif res_unknown:
                print("Unknown")
            else:
                print("Not equal")

solve()
```このソリューションは、2 倍のインデックス スペースにわたって DSU を維持します。 ヘルパー関数は、各位置をこの拡張された表現にマップします。 回文制約の場合、区間内の対称位置を結合し、すべての暗黙の等式に対して必要な推移閉包を構築します。 

等価クエリの場合、まず不一致の長さを削除します。 次に、整列した位置を比較します。 DSU は、すべての制約によって 2 つのポジションが強制的に等しくなるかどうかを示します。 すべてのペアが同じコンポーネント内にある場合、部分文字列は強制的に等しくなります。 少なくとも 1 つのペアが異なるコンポーネントにあり、矛盾構造が生じていない場合、答えは「不明」になります。 

この実装は、DSU パス圧縮に依存して、結合および検索ごとのほぼ一定の償却時間を保証します。 

## 実用的な例

 サンプルのインタラクションを追跡して、制約がどのように蓄積されるかを確認します。 

| クエリ | アクション | DSU への影響 | 結果 |
 | --- | --- | --- | --- |
 | 1 1 6 | 完全な回文を強制する | すべてのミラーリングされたペアが統合される | - |
 | 2 1 1 6 6 | 単一の文字を比較する | 対称性を介してリンクされた位置 | 等しい |
 | 2 1 2 5 6 | 重複する部分文字列を比較する | 部分的な制約 | 不明 |
 | 2 1 3 5 6 | 制約された領域を比較する | 構造内の強制的な不一致 | 等しくない |

 最初の回文制約は、文字列全体を対称構造に折りたたんで、強い等価性を強制します。 後続のクエリは、この構造のさまざまな配置を調査し、DSU の接続がマッピングを完全に決定するかどうかに応じて、強制的な結果とあいまいな結果の両方を生成します。 

2 番目の小さなトレース:

 S[1..3] のみが回文であると仮定し、S[1..2] が S[2..3] に等しいかどうかを尋ねます。 DSU は、1 が 3 に等しいことを強制しますが、1 が 2 に等しいこと、または 2 が 3 に等しいことは強制しません。これは、等号と不等号の両方が依然として制約と一致しているため、「不明」状態につながります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、回文が重なり合って長い推移的なチェーンが作成される場合です。 たとえば、S[1..5] 回文と S[2..6] 回文は、間接的に 1 を 6 に等しくします。 ユニオンは推移的であるため、DSU はこれを処理します。そのため、制約が繰り返されるとコンポーネントが自然にマージされます。 

もう 1 つのケースは、回文制約によって完全に接続されていない領域に対して部分文字列の等価性が照会される場合です。 たとえば、制約がまったくない場合、長さが異なる場合を除き、すべての等価クエリは「Unknown」を返す必要があります。 DSU は完全に切断されたままであるため、比較するたびに不確実性が生じます。 

3 番目のケースは、部分文字列がそれ自体と比較される場合です。 制約がない場合でも、DSU ではすべてのインデックスが自明に一致するため、これは常に「等しい」でなければなりません。
