 ## 解決策
 ## 問題の理解

 平面内の原点を中心とする半径の円が与えられます。$r$。 原点からの距離が厳密に次の値より大きいすべての点$r$サークルの外側と見なされます。 この円の外側にあるすべての整数座標点の中で、原点までのユークリッド距離ができるだけ小さいものを見つける必要があります。 

言い換えれば、すべての格子点を検索していることになります。$(x, y) \in \mathbb{Z}^2$そのような$x^2 + y^2 > r^2$を最小限に抑えたいと考えています。$x^2 + y^2$。 

入力は単一の整数の半径です$r$、次のように大きくすることができます$10^6$。 出力は、厳密に円の外側にあり、境界に最も近い任意の整数のペアです。 

この制約は、最適な点が円の境界に非常に近い位置にあることを即座に示唆します。 原点の周囲の大きな境界ボックス内のすべての整数ペアを単純にスキャンすることは、探索空間が二次関数的に増大するため不可能です。 座標までのすべての点をチェックする場合でも、$r+1$おおよその内容が含まれるでしょう$O(r^2)$候補者は次のとおりです。$10^{12}$最悪の場合、実行可能な限界をはるかに超えます。 

対称性について推論するときに、微妙な問題が発生します。 最適な点は、明らかなように必ずしも軸上または対角線上にあるとは限りません。 たとえば、いくつかの半径では、次のように円の境界の「コーナー」近くが最適なポイントになります。$(a, b)$ここで、両方の座標がゼロ以外であり、制約のバランスが厳密に保たれています。$a^2 + b^2 > r^2$。 ピッキングなどの素朴な貪欲な選択$(r+1, 0)$その距離は次のとおりであるため、最適からは程遠い可能性があります。$(r+1)^2$、次のような点が存在する可能性がありますが、$(r, 1)$二乗距離がはるかに小さくなります。 

重要な問題は、最適な整数点が、単純な軸の位置合わせではなく、整数格子が円の境界とどのように交差するかによって決まることです。 

## アプローチ

 ブルートフォース戦略では、すべての整数ペアを列挙します。$(x, y)$十分に広い領域で、$x^2 + y^2 > r^2$、の最小値を追跡します。$x^2 + y^2$。 これは、すべての候補を直接評価するため、正しいです。 ただし、検索領域は少なくとも半径まで拡張する必要があります。$r+1$、そして二次元では、これはおおよそ次のようになります。$(2r+3)^2$ポイント。 と$r \le 10^6$、これはまったく不可能です。 

問題の構造により、より鋭い観察が可能になります。 実際には 2D 領域内のすべての点を検索しているわけではありません。 より厳密に大きい最小の整数半径を検索しています。$r$。 つまり、次のように表現できる最小の整数値が必要です。$x^2 + y^2$そして超える$r^2$。 

すべてのポイントを探索する代わりに、1 つの座標を修正して、可能な限り最適なコンパニオン座標を導き出すことができます。 私たちが選ぶなら$x$、次に有効な最小値$y$満たさなければなりません$y^2 > r^2 - x^2$。 これにより、問題は 1D スイープオーバーに縮小されます。$x$、それぞれについて$x$、実行可能な最小値を計算できます。$y$整数の平方根を直接使用します。 

重要な洞察は、最適な点は境界付近に発生するということです。$x^2 + y^2$ただ交差するだけ$r^2$つまり、値をチェックするだけで済みます。$x$おおよそまで$r$しかし、実際にはもっと厳しく制限することができます。$x^2$を超える$r^2$、最良の候補は単純に$(x, 0)$。 遷移は周囲の狭い領域で発生します。$x \approx r$ので、すべてをスキャンします$x \in [0, r+1]$十分であり、依然として線形です$r$、大きすぎるため、さらに絞り込みます。 

より効率的な観点は、最適な答えは「円の外側の最初の格子層」、つまり上記の最小の整数半径にある必要があることを認識することです。$r$。 その半径は次の最小値に対応します。$x^2 + y^2$それを超える$r^2$1 つの軸に沿って境界交差の候補と対角に近い点を試すことでそれを構築できますが、最もクリーンな解決策は反復することです。$x$まで$r+1$有効な最小値を計算します$y$平方根を使用します。 これにより複雑さが軽減され、$O(r)$、しかしそれ以来$r \le 10^6$、対称性に注目し、以下までのみチェックすることでさらに最適化します。$\sqrt{r^2}$、つまり$O(r)$まだ大きすぎるため、代わりに、最適点は次のいずれかを満たさなければならないという事実を利用します。$x \le r$または$y \le r$そして、対称性と単調性によって検索を単一の次元に制限し、効果的にテストのみを行うことができます。$x \in [0, r]$しかし、可能な限り最良の候補者が改善できない場合は、早めに中断します。 

実際には、標準的な単純化が行われます。最適な点は、反復によって常に見つけられます。$x$0から$r+1$、有効な最小値を計算します$y$、そして最良の合計を追跡します。 制約がある場合はこれで十分です。$r$までです$10^6$、ただし、各反復は O(1) なので、$10^6$Python では単純な算術演算を使用できます。

 ## アルゴリズムのチュートリアル

 円の外側の最小の整数点を見つけるというタスクを再定式化し、体系的に候補を構築します。 

1. 可能な整数の x 座標を 0 から上に向かって繰り返します。 その理由は対称性です。有効な解の場合、座標の符号を反転しても距離は変わらないため、第 1 象限で検索し、必要に応じて後で反映するだけで十分です。 
2. 固定された x ごとに、次のような最小の整数 y を計算します。$x^2 + y^2 > r^2$。 これは、不等式を次のように整理することによって行われます。$y^2 > r^2 - x^2$、そして取る$y = \lfloor \sqrt{r^2 - x^2} \rfloor + 1$内側が非負の場合、それ以外の場合$y = 0$。 これにより、最小限の増加で境界を越えることが保証されます。 
3. 候補二乗距離を計算します$x^2 + y^2$そして、これまでに見つかった最良の回答と比較します。 最適な距離と対応する座標の両方を追跡します。 
4. ループの対称性を介して x と y が暗黙的に交換される対称バリアントも考慮しますが、すでにすべての x を列挙しているため、これで十分です。 
5. スキャンの終了後、最小有効二乗距離に対応する座標を出力します。 

正確さは、すべての最適な格子点について、その x 座標を固定すると、上記の式で計算された正確な y 座標が再現され、それが検索空間に確実に含まれるという事実に依存します。 

### なぜ効果があるのか

 円の外側のすべての有効な点は、ある整数 x に対応し、その x に対して、まだ円の外側にある可能性のある最小の y は一意に決定されます。 x は同じだが y が大きい点は厳密には不良であり、y が小さい点は円の内側になります。 したがって、検索空間は 2 次元から x ごとの 1 つの決定論的な選択肢に折りたたまれます。 最適な点はこれらの最小の y 候補の 1 つとして現れる必要があるため、すべての x をスキャンすることで、最終的に最適なペアが評価されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

r = int(input())
r2 = r * r

best = None
best_val = None

for x in range(0, r + 2):
    x2 = x * x
    if x2 > r2:
        y = 0
    else:
        rem = r2 - x2
        y = int(math.isqrt(rem)) + 1

    val = x2 + y * y

    if best is None or val < best_val:
        best_val = val
        best = (x, y)

    if x > r and y == 0:
        break

x, y = best
print(x, y)
```このコードは、境界を越えるアイデアを直接実装しています。 各 x について、円から逃れる最小の y を計算します。 の使用`math.isqrt`浮動小数点の精度の問題を回避し、最大で大きな値の正確性を保証します。$10^{12}$。 

ループの終了条件`if x > r and y == 0`これは小さな最適化です。x がすでにその軸上の円の外側にある場合、x をさらに増加し​​ても距離が増加するだけなので、より良い解決策は見つかりません。

## テストケース```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    r = int(input())
    r2 = r * r

    best = None
    best_val = None

    for x in range(0, r + 2):
        x2 = x * x
        if x2 > r2:
            y = 0
        else:

        val = x2 + y * y
        if best is None or val < best_val:
            best_val = val
            best = (x, y)

        if x > r and y == 0:
            break

    return f"{best[0]} {best[1]}"

assert solve("4") == "1 4"

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$r$非常に小さいです、例えば$r = 1$。 アルゴリズムは正しく評価します$x = 0$そしてすぐに見つけます$y = 2$、しかしチェックもします$x = 1$, ここで、式は次のようになります。$y = 1$、有効な距離が小さくなります。 これにより、対角点が軸に沿った候補を支配できることが確認されます。 

もう 1 つのエッジケースは次のような場合です$x^2 > r^2$。 たとえば、$r = 4$そして$x = 5$、コードセット$y = 0$、円の外側の x 軸上に正確に候補が生成されます。 これにより、負の数の平方根を誤って計算することがなくなります。 

最後の微妙なケースが大きい$r$、 のような$10^6$。 ここで、正確かどうかは、浮動小数点演算を完全に回避するかどうかにかかっています。 使用する`math.isqrt`正確な整数の動作を保証し、境界をまたぐ y 値を計算するときに精度がドリフトしないようにします。
