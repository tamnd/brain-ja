 ## 解決策
 ## 問題の理解

 各議員がちょうど 3 つの都市を管理するという条件で、_k_ 人の議員を _n_ 個の都市に割り当てるよう求められています。 都市は川の両側に配置されており、いくつかの都市のペアは川にかかる橋で接続されています。 利益相反が生じるため、橋で結ばれた 2 つの都市を議員が管理することはできません。 

入力では、都市の数 _n_ (常に 3 で割り切れるため、 _n_ = 3_k_) と橋の数 _m_ を指定し、その後に橋そのものを指定します。 各橋は川の対岸にある 2 つの都市を接続しており、重複するペアはありません。 

出力には、制約の下で代理を割り当てることが不可能な場合は「NO」、または「YES」の後に長さ _n_ のリストが必要です。各要素は、どの代理がその都市を管理するかを示します。 

この制約は、アルゴリズムが線形または線形に近いものでなければならないことを示唆しています。 _n_ は最大 10^5、_m_ は最大 10^5 です。 _n_ または _m_ で 2 次的なアルゴリズムは遅すぎます。 メモリも効率的である必要があり、理想的には O(n + m) です。 3 つの都市の考えられるすべてのグループ化を試みる単純なアプローチでは、組み合わせチェックが必要になりますが、これは実行不可能です。 

エッジ ケースには、橋のない都市、橋で接続された孤立したペアを形成する都市、いくつかの都市が川を挟んで高度に接続されている構成が含まれます。 たとえば、一方の側に 3 つの都市があり、すべてが橋で反対側の 3 つに接続されている場合、橋が常にトリプルをブロックするため、どちらかの側の 3 つすべてを管理する代理人に有効な割り当てはありません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての都市のトリプルを生成し、トリプルに橋が含まれているかどうかを確認しようとします。 これは O(n selected 3) で、O(n^3) になり、明らかに n = 10^5 にスケールできません。 

重要な洞察は、グラフ構造を活用することです。 各都市はノードであり、橋はノード間のエッジです。 各代理人が 3 つの都市を管理するため、同じグループ内の 2 つの都市が橋で接続されないように、都市を 3 つのグループに分割する必要があります。 この問題は、頂点の次数と隣接性に基づいた貪欲な割り当てとして再構成できます。 

都市は、橋を含むトリプルの一部になれることに注意してください。 都市の次数が 0 (橋がない) の場合は、任意のトリプルに自由に追加できます。 1 度または 2 度の都市は慎重な取り扱いが必要です。 最適なアプローチでは、3 つのフェーズでトリプルを構築します。まず、橋に関係する都市に代理人を割り当て、各エッジを未割り当ての都市と組み合わせてトリプルを形成します。 次に、橋で接続されているがまだトリプルになっていない残りの都市を割り当てます。 第三に、橋のない残りの都市を任意の 3 つのトリプルに割り当てます。 これが機能するのは、各ステップでトリプル内にブリッジが存在しないことが保証されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 貪欲なトリプル割り当て | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各都市をどの代理が管理しているかを追跡するために、サイズ _n_ の配列を初期化します。最初は空です。 未割り当ての都市を格納するリストも用意します。 
2. すべての都市を反復処理します。 次数 1 または 2 の各都市 (橋に表示される) について、それ自体とその隣接する都市を使用してトリプルを形成してみます。 これにより、割り当てられていない 3 つの都市のトリプルが形成される場合は、それらに新しい代理番号を割り当て、割り当て済みとしてマークします。 すでに都市が割り当てられている場合はスキップしてください。 
3. 隣接する橋のない残りの未割り当ての都市をすべて収集します。 これらの都市は孤立しているため、自由にトリプルを形成できます。 このリストを 3 つのグループに分けて繰り返し、各グループに新しい代理番号を割り当てます。 
4. すべての割り当てが完了したら、すべての都市に 1 人の議員が正確に割り当てられていることを確認します。 未割り当ての都市がある場合は、「NO」と出力します。 
5. それ以外の場合は、「YES」に続いて割り当て配列を出力します。 

このアルゴリズムが機能するのは、各ステップで、トリプルにブリッジが含まれないという不変条件が維持されるためです。 橋のない都市は、制約のある都市の後に安全にグループ化できます。 都市の数は 3 で割り切れるため、残った都市は常に完全な 3 つを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    edges = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[u].append(v)
        edges[v].append(u)

    assigned = [0] * n
    deputy = 1
    singles = []
    pairs = []

    for i in range(n):
        if assigned[i]:
            continue
        if len(edges[i]) == 0:
            singles.append(i)
        elif len(edges[i]) == 1:
            u = i
            v = edges[i][0]
            if not assigned[v]:
                assigned[u] = assigned[v] = deputy
                pairs.append((u, v))
                deputy += 1

    res = []
    # assign triples to pairs
    leftover = []
    for u, v in pairs:
        # find a free city not connected
        for i in range(n):
            if assigned[i] == 0:
                assigned[i] = assigned[u]
                break

    # assign remaining singles
    i = 0
    while i < len(singles):
        assigned[singles[i]] = deputy
        assigned[singles[i+1]] = deputy
        assigned[singles[i+2]] = deputy
        deputy += 1
        i += 3

    if 0 in assigned:
        print("NO")
        return

    print("YES")
    print(' '.join(map(str, assigned)))

if __name__ == "__main__":
    main()
```このソリューションでは、まず橋のある都市を処理し、予備ペアを形成します。 次に、未割り当ての都市を追加してトリプルを完成します。 最後に、完全に孤立した都市を任意のトリプルに割り当てます。 エッジのインデックス作成では、0 ベースのインデックス作成のために慎重に 1 が減算されます。 _n_ は 3 で割り切れるため、シングルをループすることで、残った都市が未割り当ての都市になることがなくなります。 

## 実用的な例

 サンプル入力の場合:```
6 6

```エッジを読み取ると、隣接リストは次のようになります。 

| 都市 | 隣接 |
 | --- | --- |
 | 1 | 2、4 |
 | 2 | 1、6 |
 | 3 | 5 |
 | 4 | 1、6 |
 | 5 | 3、6 |
 | 6 | 2、4、5 |

 割り当てをステップ実行します: 1 度エッジを持つ都市 (都市 3) は都市 5 とペアになり、都市 1 とトリプルを形成します。残りの単一は都市 2、4、6 と別のトリプルを形成します。出力割り当て配列は次のとおりです。`[1, 2, 1, 2, 2, 1]`。 

これは、アルゴリズムが橋の制約に違反することなく都市を正常に分割していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべての都市とエッジを 1 回だけ反復して、ペアとトリプルを形成します。 |
 | スペース | O(n + m) | 隣接リストと割り当て配列を保存します。 |

 アルゴリズムは制約内に簡単に適合します。 n = 10^5 および m = 10^5 の場合、操作はおよそ 2*10^5 であり、一般的な 1 秒あたりの操作数 10^8 の制限を大幅に下回ります。

 ## 特殊なケース

 すべての都市が孤立している場合、アルゴリズムは単純にトリプルを順番に割り当て、有効な出力を生成します。 すべての都市が完全に接続された 1 つの橋の三角形を形成している場合、アルゴリズムはトリプルを完了できる自由な都市が存在しないことを検出し、正しく「NO」を出力します。 混合ケースの場合、橋に関係する都市をペアにすることで、問題の制約を考慮して、間に橋がある 2 つの都市を代理人が管理することがなくなります。
