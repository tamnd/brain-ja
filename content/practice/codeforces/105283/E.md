 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 許可される操作は 1 つです。任意の 2 つの要素を選択し、両方を削除し、それらのビットごとの XOR を計算し、その結果を配列に挿入します。 これにより、2 つの要素が 1 つで置き換えられるため、配列サイズが正確にマイナス 1 だけ変更されます。 

目標は、このような操作を 1 回だけ実行した後、配列の最終的な合計を最小化することです。 

主な難点は、この操作で値が非線形に変更されることです。 XOR は数値に関して単調ではないため、2 つの数値を XOR で置き換えると、ペアに応じて合計が増加または減少する可能性があります。 

全体で最大 200,000 要素という合計入力サイズの制約は、テスト ケースごとにすべてのペアを試すことができないことを意味します。 各配列の二次解法では、最悪の場合、約 4e10 回の演算が必要になりますが、これは限界をはるかに超えています。 

さらに微妙な制約の意味は、マージ操作が 1 回しか実行されないことです。 つまり、最終的な答えは、一連の操作ではなく、最適なペアの選択のみに依存します。 これにより、問題は動的プロセスから単純なコスト関数を使用したペア選択問題に縮小されます。 

単純な実装ではすべてのペアの効果を再計算しますが、XOR を加算または減算のように動作するかのように扱うという、ソリューションを誤解させる可能性のある非効率の 2 番目の層があります。 たとえば、XOR によっても大きな値が生成される可能性があるため、2 つの大きな数値を選択しても必ずしも合計が小さくなるわけではありません。 

単純な失敗例はペア (8, 7) です。 それらの XOR は 15 であるため、値を結合すると合計の大きさが小さくなると予想される場合でも、合計は増加します。 これは、サイズのみに基づく貪欲なヒューリスティックが安全ではないことを示しています。 

## アプローチ

 ブルートフォースアプローチは簡単です。 インデックス i と j のすべてのペアを試し、a[i] と a[j] を削除して加算 (a[i] XOR a[j]) した場合の合計を計算します。 各ペアについて、元の合計を事前計算した後、一定時間内に新しい合計を計算します。 これにより、テスト ケースごとに O(n^2) のスキャンが行われます。 

ネックとなるのはペア数です。 n が 2e5 までの場合、1 つのテスト ケースでも約 2e10 ペアが必要になりますが、これは 1 秒では不可能です。 より小さなサブタスクであっても、これはかろうじて許容できる程度です。 

重要な点は、ペアごとに新しい配列の合計を最初から明示的に計算する必要がないということです。 S を元の配列の合計とします。 a と b を置き換えると、新しい合計は次のようになります。 

S - a - b + (a XOR b)

 したがって、変更は (a + b - (a XOR b)) の最小化にのみ依存します。 

この式を書き直すことが中心的な洞察です。 

a + b - (a XOR b) = 2 * (a AND b)

 この同一性はビットごとの分解から得られます。 各ビットについて、XOR は両方のビットが 1 である寄与を削除しますが、AND は重複する寄与を正確に保持します。 したがって、a と b をペアにする利点は、それらのビット単位の重複に正確に比例します。 

したがって、問題は (a AND b) を最大化するペア (a, b) を見つけることに帰着します。 そのペアがわかったら、合計に対する可能な限り最良の改善を計算します。 

これにより、問題は配列に対する古典的な最大 AND ペア検索に変わります。 値は最大 10^9 であるため、ビットごとのトライまたは貪欲なビットごとの構築を使用できます。 ただし、必要なのは 1 つの最良のペアだけであるため、ビットに対するプレフィックス フィルタリングを使用したより単純なビット操作アプローチで十分です。 

最上位ビットから下に向かって繰り返し、高い AND 値を達成できるプレフィックスを共有する候補のセットを維持します。 各ステップで、現在のビットを含む要素をフィルタリングし、最終的なペアの両方の数値が共有ビットを最大化するようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | ビットごとの最適化 | O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列の合計を計算します。 これは、操作を適用した後の改善を測定するためのベースラインです。 
2. ペア (a, b) を選択すると、a + b の減算と XOR b の加算により合計が変化することを観察します。 したがって、コスト削減を最大化することを目指します。これは、2 * (a AND b) を最大化することに相当します。 
3. タスクを、最大のビット単位の AND 値を持つ要素のペアを見つけるように縮小します。 これにより、最大の共有上位ビットを持つ 2 つの数値を選択するという問題が再構成されます。 
4. 最上位ビット (通常は 1e9 までの値の場合はビット 30) から開始します。 最適なペアを形成できる候補インデックスの作業セットを維持します。 
5. 各ビット位置で、このビットが設定されている数値に候補セットをフィルタリングします。 少なくとも 2 つの番号が残っている場合は、それらのみを保持して続行します。 それ以外の場合は、このビットを無視し、フィルタリングせずに続行します。 

これが機能する理由は、上位ビットが下位ビットよりも AND 値に指数関数的に大きく寄与するためであり、最初に上位ビットの実現可能性を維持することを優先する必要があります。 
6. すべてのビットを処理すると、小さな候補プールが残ります。 このプールから最適なペアを明示的に計算し、それらの AND 値を評価します。 
7. 元の合計から見つかった最大 AND の 2 倍を引いたものとして最終的な答えを計算します。 

### なぜ効果があるのか

 この変換により、演算の正味ゲインは選択したペア間の重複ビットのみに依存するため、問題はビット単位の AND の最大化に軽減されます。 貪欲なビット フィルタリングにより、より高い最上位寄与ビットを達成できるペアが決して破棄されることがなくなります。 上位ビットが値を支配するため、各ビット レベルでの実現可能性を維持することで全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    total = sum(a)

    candidates = a[:]

    for bit in range(30, -1, -1):
        filtered = [x for x in candidates if (x >> bit) & 1]
        if len(filtered) >= 2:
            candidates = filtered

    best_and = 0
    m = len(candidates)

    for i in range(m):
        for j in range(i + 1, m):
            best_and = max(best_and, candidates[i] & candidates[j])

    return total - 2 * best_and

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、まず参照点として合計が計算されます。 次に、少なくとも 2 つの要素間で可能な限り最大の共有ビットを繰り返し適用することにより、フィルタリングされた候補リストを構築します。 これにより、枝刈り中に最適なペアを失わないことが保証されます。 

ビット フィルタリング後の候補セットは実際には小さく、通常は最大の AND 構造を共有する要素の数によって制限されるため、最後の二重ループは安全です。 これにより、最終的な検証ステップが安価になります。 

微妙な点は、要素が 1 つだけ残っている場合でもフィルタリングを停止しないことです。 操作にはペアが必要であるため、少なくとも 2 つの要素が残っている場合にのみフィルターを適用します。 

## 実用的な例

 ### 例 1

 入力配列: [5、5、1、1、3]

 合計は15になります。 

最適な AND ペアを検索します。 少なくとも 2 つの数値で共有される最上位ビットは、値 1 に対応するビットです。フィルタリング後、[5, 5, 1, 1] になる可能性があります。 最良のペア AND は 5 AND 5 = 5 です。 

| ステップ | 候補者 | アクション | 最高かつ |
 | --- | --- | --- | --- |
 | 初期化 | [5,5,1,1,3] | 計算された合計 | 0 |
 | ビットフィルター | [5,5,1,1] | ビット 0 グループを保持 | 0 |
 | 最終チェック | フィルタリングされた | 間のペア AND | を計算します。 5 |

 最終的な答え: 15 - 2*5 = 5。 

これは、共有上位ビットによるグループ化によって最適なペアがどのように分離されるかを示しています。 

### 例 2

 入力配列: [1、9、4]

 合計は14になります。 

ペアを確認します。 

1 と 9 = 1

 1 と 4 = 0

 9 と 4 = 0

 最良のペアは (1, 9) です。 

| ペア | そして |
 | --- | --- |
 | (1,9) | 1 |
 | (1,4) | 0 |
 | (9,4) | 0 |

 最終的な答えは 14 - 2*1 = 12 です。 

これは、最適な選択が最大の数値ではなく、単一の下位ビットを共有する数値である場合を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A) | 各ビット フィルタリング パスは配列を 1 回スキャンし、最大 31 ビットが存在します。 
| スペース | O(n) | 候補リストと入力配列のストレージ |

 すべてのテスト ケースにわたる合計制約は 2e5 要素であるため、線形対数解で十分です。 各テストは配列上で最大 31 パスを処理しますが、これは時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        res = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            total = sum(a)

            best = 0
            for i in range(n):
                for j in range(i+1, n):
                    best = max(best, a[i] & a[j])
            res.append(str(total - 2*best))
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 エッジケースの 1 つは、最適なペアが実際に合計を増加させる場合です。 入力 [8, 7] の場合、どのマージでも元の合計 15 から 15 が生成されます。アルゴリズムは最適な AND = 0 を正しく検出するため、リダクションは適用されず、答えは変更されません。 

もう 1 つの特殊なケースは、すべての要素が同一である場合です。 [4, 4, 4, 4] の場合、どのペアでも AND = 4 が得られるため、最適なリダクションは 8 になります。すべてが同じビット パターンを共有するため、アルゴリズムはどのペアも最適であることを正確に識別します。 

3 番目のエッジ ケースは、2 のべき乗など、数値がバイナリ表現で互いに素である場合です。 [16, 8, 4, 2, 1] では、ペアごとの AND 値はすべて 0 であるため、どの演算も合計を改善しません。 アルゴリズムは、ゼロに等しい最良の AND で終了し、合計を変更しないままにすることで、これを保持します。
