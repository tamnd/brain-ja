 ## 問題の理解

 文字列「orz」の繰り返しコピーで構成されるテキストを構築しています。 目標は少なくとも生産することです$N$この文字列のコピーは最小限の時間で行われます。 

いつでも、ジェイソンは現在の量のテキストを持っており、3 つのアクションを実行できます。 「orz」を 1 つ入力すると、カウントが 1 つ増え、コストがかかります$A$秒。 現在のテキスト全体をコピーできます。$B$秒でクリップボードに保存されます。 彼はクリップボードを貼り付けることができます$C$ペーストするたびに、コピー済みの「orz」の数が正確に追加されます。 

プロセスは空から開始されるため、開始する唯一の方法は入力することです。 

難しさは、コピーとペーストの相互作用に起因します。 コピーは固定のオーバーヘッドですが、貼り付けは現在のテキストの量を調整します。 取得したら$x$コピー、その後に続くコピー操作$k-1$ペーストにより合計が増加する可能性があります$x$に$k \cdot x$、そして多くの場合、これはすべてを手動で再度入力するよりもはるかに安価です。 したがって、いつ入力をやめて指数関数的な成長に切り替えるかを決定する必要があります。 

この制約により、すべての操作シーケンスに対する総当りの探索は不可能になります。 以来$N$到達できる$10^9$、各ステップをシミュレートするか、最大のすべての状態にわたって DP を実行するソリューション。$N$失敗します。 平$O(N)$または$O(N \log N)$トランジションが大きすぎます。 

単純な試みでは、入力、コピー、および貼り付け操作のあらゆる可能なシーケンスをシミュレートし、現在のサイズと時間を追跡します。 到達可能な状態の数が非常に急速に増加するため、これは失敗します。 もう 1 つの単純な考えは、現在の「orz」の数を DP で超えることですが、状態空間が大きすぎます。 

コピーが早すぎると、微妙なエッジケースが発生します。 たとえば、次の場合$A$とても小さいし、$B$が大きいと、入力が完全に支配される可能性があります。 逆に、もし$C$が非常に小さいため、早期のコピーは非常に強力になります。 正しい解決策は、固定された戦略に固執することなく、これら 2 つの体制のバランスを取る必要があります。

 ## アルゴリズムのチュートリアル

 コピー＆ペーストの増加に切り替える前に、手動で入力する回数を選択するという問題を再構成します。 

1. 最初に何らかの数値を構築することを考えてみましょう$x$純粋にタイプするだけで「orz」の。 これには正確な費用がかかります$A \cdot x$。 最終的な成長フェーズに移行する前にコピー操作を混合してもメリットはありません。これは、基本サイズが安定した場合にのみ、早期にコピーすることは意味があるからです。 
2. 修正したら$x$、コピー操作を 1 回実行します。 これには費用がかかります$B$秒で、次の内容を含むクリップボードが提供されます。$x$。 
3. その時点から、各ペーストが追加されます$x$。 少なくとも達成したいのは、$N$、だから必要です$k = \lceil N/x \rceil$サイズのブロックの合計$x$、 意味$k-1$ペースト。 これは貢献します$(k-1)\cdot C$。 
4. 固定費の総額$x$したがって$$A \cdot x + B + (\lceil N/x \rceil - 1)\cdot C.$$5. 関連するすべての式についてこの式を評価します。$x$。 すべての値をチェックするのではなく、$N$、値のみが必要です。$\lceil N/x \rceil$変化します。 これらの変化は約数の周りで起こります。$N$ので、確認してください$x$まで$\sqrt{N}$そしてチェックもしています$x = \lfloor N/i \rfloor$これらの値はすべての候補をカバーするためです。 

### なぜ効果があるのか

 この関数は、天井項および各区間内で区分的に一定です。$\lceil N/x \rceil$が固定されている場合、コストは次のように直線的に増加します。$x$。 これは、最小値が境界付近になければ、大きな平らな区間の奥深くに存在することはできないことを意味します。 分割の変更によって引き起こされる境界点を評価することにより、潜在的に最適な構成がすべて候補セットに含まれ、真の最小値に確実に到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(A, B, C, N):
    ans = float('inf')

    # try all x up to sqrt(N)
    x = 1
    while x * x <= N:
        # case 1: x as typing count
        k = (N + x - 1) // x
        cost = A * x + B + (k - 1) * C
        ans = min(ans, cost)

        # also try paired value N // x
        y = N // x
        if y > 0:
            k = (N + y - 1) // y
            cost = A * y + B + (k - 1) * C
            ans = min(ans, cost)

        x += 1

    return ans

def main():
    T = int(input())
    out = []
    for _ in range(T):
        A, B, C, N = map(int, input().split())
        out.append(str(solve_case(A, B, C, N)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションでは、次の候補値を列挙します。$x$平方根分解を中心に対称的な方法で。 候補者ごとに$x$、到達するために必要な完全なコピー＆ペーストブロックの数を計算します。$N$、次に総コストを評価します。 ペアの値についても同じことが繰り返されます$N/x$、これは、天井が変化する分割ブレークポイントの反対側をキャプチャします。 

重要な実装の詳細は、上限除算に整数演算を慎重に使用することです。 表現$(N + x - 1) // x$浮動小数点エラーのない正しい丸めを保証します。これは、次の場合に不可欠です。$N$大きいです。
