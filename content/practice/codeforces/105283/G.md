 ## 解決策
 ## 問題の理解

 配列と 3 つの特別な値が与えられ、厳密な順序付けが行われます。$Y < K < X$。 各テスト ケースのタスクは、3 つの同時条件を満たす連続したサブ配列の数を数えることです。サブ配列内の最大要素は正確に次のとおりです。$X$、最小要素は正確に$Y$、および値$K$はサブ配列内のどこにも現れません。 

したがって、部分配列は、すべての要素が、によって課された境界を尊重する場合にのみ有効です。$X$そして$Y$、その範囲の中間にある特定の禁止値も回避します。 

入力サイズが大きく、最大$5 \cdot 10^5$テスト ケース全体の要素の合計。 これにより、すべてのサブ配列を直接検査するソリューションは即座に除外されます。これは、二次関数またはさらに悪い動作につながるためです。 偶数にわたる二次スキャン$10^5$要素が周囲を生成します$10^{10}$これは 1 秒の制限が許容できる速度をはるかに超えています。 

重要な構造は、有効性がセグメント内のローカル プロパティ (部分配列が範囲内にあるかどうか) によって完全に決定されるということです。$[Y, X]$、避けます$K$、両極端を含む$Y$そして$X$。 これは、部分配列を列挙する代わりに、配列を最大有効領域に変換し、各領域内の寄与を効率的にカウントする必要があることを示唆しています。 

単純なアプローチが禁止値を無視すると、微妙な失敗例が発生します。$K$。 たとえば、次の場合$X = 7$、$Y = 4$、$K = 5$、配列は$[6, 7, 5, 4]$、総当たりスキャンが重要になる可能性があります$[6,7,5,4]$両方が含まれているため有効と見なされます$7$そして$4$が、間違って含まれています$5$、条件に違反します。 もう 1 つのよくある間違いは、外部の価値観を忘れることです。$[Y, X]$それらに交差するサブ配列を無効にします。 で$[3, 4, 7]$、以下を含む任意の部分配列$3$最小値を持つことはできません$Y = 4$したがって、有効な領域の一部とみなされるべきではありません。 

## アプローチ

 最も直接的なアプローチは、すべてのサブ配列を列挙し、それが 3 つの条件を満たしているかどうかを確認することです。 各サブ配列について、その最小値、最大値、および$K$が表示されます。 これらを段階的に維持すると、まだ次のことが残ります。$O(N^2)$テスト ケースごとにサブ配列があり、各チェックは少なくとも$O(1)$、次の場合に解決策が遅くなりすぎます。$N$到達する$10^5$。 

重要な観察点は、無効な要素が配列を独立したセグメントに分割していることです。 外側の要素$[Y, X]$これは、それを含むサブ配列の最小制約または最大制約のいずれかに違反するため、有効性が直ちに失われます。 禁じられた値$K$は範囲内にありますが、それを含むサブ配列を不適格にするため、ハードセパレータとしても機能します。 

これにより、問題はすべての要素が存在する独立したセグメントに縮小されます。$[Y, X]$と等しくありません$K$。 このようなセグメント内では、少なくとも 1 つの次の出現を含むサブ配列を数える必要があります。$Y$少なくとも 1 回の発生$X$。 

正しいエンドポイントとして扱われる各位置について、最新の発生状況を維持します。$Y$そして$X$。 有効な開始位置の数は、これらの最後の 2 つの出現のうち最も早いものによって決まります。これは、有効な部分配列が$r$両方の値が確実に含まれるように、2 つのインデックスのうち小さい方のインデックスまたはその前で開始する必要があります。 このスライディング ウィンドウ パースペクティブにより、サブ配列を明示的に列挙する必要がなくなります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、配列を左から右にスキャンして、セグメントの境界を維持し、主要な発生を追跡します。 

### ステップ

 1. 変数を初期化する`start`現在の有効なセグメントの始まりをマークします。 このセグメントには、そうでない要素のみが含まれています。$K$そしてその中に横たわる$[Y, X]$。 
2. 2 つのポインタを維持します。`lastY`そして`lastX`、配列が始まる前の位置に初期化されます。 これらは、最新の位置を保存します。$Y$そして$X$。 
3. 配列インデックスを反復処理します。$r$左から右へ。 
4. もし$A[r] = K$または$A[r] < Y$または$A[r] > X$、設定によりセグメントをリセットします`start = r + 1`そしてリセット`lastY`そして`lastX`無効な値に変更します。 これにより、サブ配列が無効な境界を越えることがなくなります。 
5. それ以外の場合は更新します`lastY`もし$A[r] = Y$そして更新します`lastX`もし$A[r] = X$。 
6. 両方の場合`lastY`そして`lastX`現在のセグメント内で有効である場合、次で終了する有効なサブ配列の数を計算します。$r$。 このカウントは`max(0, min(lastY, lastX) - start + 1)`そしてそれを答えに追加します。 

### なぜ効果があるのか

 セグメント内では、すべてのサブ配列から無効な要素が自動的に削除され、$K$。 残りの制約は、有効な部分配列に少なくとも 1 つが含まれなければならないということだけです。$Y$そして1つ$X$。 固定右端点の場合、最新の位置$Y$そして$X$両方が同時に出現することが保証される最も早い時点を決定します。 以前に開始したインデックスには両方の値が含まれていますが、後で開始したインデックスには少なくとも 1 つが除外されます。 これにより、各位置で終わるすべての有効なサブ配列に対して、重複や欠落がなく直接カウントするルールが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, X, Y, K = map(int, input().split())
        A = list(map(int, input().split()))

        start = 0
        lastY = -1
        lastX = -1
        ans = 0

        for i, v in enumerate(A):
            if v == K or v < Y or v > X:
                start = i + 1
                lastY = -1
                lastX = -1
                continue

            if v == Y:
                lastY = i
            if v == X:
                lastX = i

            if lastY != -1 and lastX != -1:
                ans += max(0, min(lastY, lastX) - start + 1)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、セグメント分解とスライディング ウィンドウ ロジックを直接反映しています。 の`start`ポインタにより、無効な要素と交差する部分配列が考慮されないことが保証されます。$K$。 変数`lastY`そして`lastX`両極端の存在を強制するために必要なエンドポイントを継続的に追跡します。 最後の累積ステップでは、これらの位置が各右エンドポイントの有効な開始インデックスのカウントに変換されます。 

実装でよくある落とし穴は、無効な要素に遭遇したときに、最後に出現した両方の変数をリセットし忘れることです。 このリセットがないと、古いインデックスがセグメント全体にリークし、独立した領域が誤ってマージされます。

 ## 特殊なケース

 が複数出現するなど、無効な区切り文字が連続する場合$K$セグメントのリセットが誤ってマージされないようにします。 アルゴリズムはリセットすることでこれを処理します`start`、`lastY`、 そして`lastX`無効な位置ごとに独立して実行されるため、ブレークをまたいで状態が持続することはありません。 

場合$Y$そして$X$長いセグメントの端にのみ出現する場合は、プレフィックス カウントの正確さをチェックします。 アルゴリズムは引き続き、以前の有効な開始から拡張されたすべてのサブ配列をカウントします。`min(lastY, lastX)`最も早い実行可能な境界を正しく固定します。 

配列が有効な値と無効な値を交互に繰り返す場合は、セグメントの初期化が繰り返されることをテストします。 新しいセグメントはそれぞれ新たに開始され、寄与分はローカルに限定されるため、境界を越えた過剰カウントが防止されます。
