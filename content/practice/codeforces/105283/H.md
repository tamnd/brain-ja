 ## 解決策
 ## 問題の理解

 非常に大きな整数が与えられました`a`そして別の整数`b`、どちらも 10 進数の文字列として書き込まれます。 番号`a`より正確に 4 桁多い`b`。 から正確に 4 桁を削除することができます。`a`、残りの桁を並べ替えずに、結果を新しい整数として解釈します (構築中に先頭のゼロは許可されますが、値の比較では当然無視されます)。 

タスクは、削除する 4 つの位置を選択する別の方法が何通りあるかを数えることです。`a`厳密に次の値よりも小さい結果の数値を生成します`b`。 

入力制約からわかる重要な点は、数値が最大 10,000 桁まで非常に大きくなる可能性があるということです。 これにより、組み込み整数への変換や、候補ごとに大量の文字列操作を使用してすべてのサブシーケンスを単純に列挙しようとするアプローチが即座に排除されます。 4 つの欠失のすべての組み合わせを生成することさえ、組み合わせ的にのみ可能です。$\binom{n}{4}$、これは$n \le 10000$についてです$10^{15}$、大きすぎます。 

解を形作る実際の制約は、4 桁を削除した後の数値が、次の数値とまったく同じ長さになるということです。`b`。 これは、先行ゼロの影響を含む通常の整数比較規則を使用して、比較が同じ長さの文字列に対して辞書編集的に行われることを意味します。 

エッジ ケースは、主に桁の等価性の境界から発生します。 結果の番号が長いプレフィックスを共有する場合`b`の場合、1 桁の差が比較を決定します。 もう 1 つの微妙な問題は、構築された数値の先頭にゼロがあることです。これらは数値には影響しませんが、慎重に扱わないと辞書編集上の比較に影響します。 例えば、`"0123"`数値的には次と等しい`"123"`、しかし辞書順に見るともっと小さいです。 比較は文字列ベースではなく数値であるため、比較を慎重に正規化するか、曖昧さを避ける方法で推論する必要があります。 

## アプローチ

 ブルートフォース手法では、削除する 4 つのインデックスのすべてのサブセットが選択されます。`a`、結果の文字列を構築し、先頭のゼロを取り除き、次と比較します。`b`。 各小切手にかかる費用$O(n)$、そして、あります$O(n^4)$サブセット、おおよその結果につながる$10^{16}$最悪の場合の運用。 これは実現可能な限界をはるかに超えています。 

重要な洞察は、削除が 4 つだけ行われており、これは一定であるということです。 これは、文字列を左から右に処理し、使用した削除の数を追跡しながら、同時に比較する、組み合わせ DP または数字 DP スタイルのソリューションを示唆しています。`b`。 

それぞれの位置で`a`、数字を削除するか保持するかを決定します。 それを維持すれば、構築された数値に貢献します。 それを削除すると、許可されている 4 つの削除のうちの 1 つが消費されます。 結果の数値は次の長さでなければなりません`b`、まさにそのとおりです$|a| - 4 = |b|$数字は保持されます。 

との比較`b`追加の次元を導入します。保持されたシーケンスを構築する際、すでに厳密に以下であるかどうかを追跡する必要があります。`b`、これまでと等しい、または超えている`b`。 ただし、プレフィックスが次の値を超えると、超過を取り除くことができます。`b`、再び有効になることはありません。 

これにより、位置に基づいた状態を持つ数字 DP が得られます。`a`、使用された削除の数、および厳密な比較状態`b`。

 ## アルゴリズムのチュートリアル

 私たちは構築を正確に選択するものとして扱います`len(b)`からの数字`a`これは 4 桁を削除するのと同じです。 

次の文字列に対して DP を定義します。`a`。 

1. DP テーブルを初期化します。`dp[i][k][t]`最初の方法を使用する方法の数を表します`i`の桁`a`、正確に削除しました`k`数字と場所`t`構築されたプレフィックスが依然として次のプレフィックスと等しいかどうかを示します。`b`(`t = 0`) またはすでに小さい (`t = 1`）。 

比較に 2 つの状態だけが必要な理由は、状態が小さくなると、制約を強制する必要がなくなるためです。`b`。 
2. 位置 0 から開始します。`k = 0`そして`t = 0`。 数字はまだ処理されていないため、構築されたプレフィックスは自明に次のプレフィックスと等しくなります。`b`。 
3. 各ポジションで`i`で`a`では、次の 2 つのアクションを考えてみましょう: 削除`a[i]`または保持します`a[i]`。 4 つの削除を超えるトランジションはスキップします。 

削除は簡単です。次に進みます。`dp[i+1][k+1][t]`削除しても構築された数値には影響しないためです。 
4. このままだと`a[i]`、構築された数値に追加します。 次に、新しい比較状態を決定します`t'`。 すでに入っている場合`t = 1`、私たちはそこに残ります。 私たちがいるなら`t = 0`、新しく追加された数字を、対応する数字と比較します。`b`。 小さい場合は、次のように移動します。`t = 1`。 それが等しい場合、私たちはそこに留まります`t = 0`。 それが大きい場合、この遷移は破棄されます。 

このステップでは、以下の数値のみを構築するように強制します。`b`辞書編集的に、DP が有効な構文のみをカウントできるようにします。 
5. すべての位置を処理した後、正確に 4 つの削除が使用され、構築された数値の長さが次のとおりであるすべての状態の合計を取得します。`b`。 これらの中で、最終的な比較が等しいか、すでに小さい状態のみをカウントします。 全長での等しいということは、`b`、ある時点で厳密に少ない条件が強制された場合にのみ有効です。 したがって、私たちはただ数えるだけです`t = 1`。 

### なぜ効果があるのか

 DP は、すべての状態が固有のサブシーケンスを表すという不変条件を維持します。`a`固定数の削除があり、`t`現在のプレフィックスが厳密に小さいかどうか、または対応するプレフィックスと依然として結び付いているかどうかを正確にキャプチャします。`b`。 辞書順に違反する遷移は決して許可されないため、`b`、カウントされたすべての終了状態は有効なサブシーケンスに対応します。 逆に、保持または削除の選択によってサブシーケンスが完全に決定されるため、すべての有効なサブシーケンスは DP を通る 1 つのパスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(a, b):
    n = len(a)
    m = len(b)
    # dp[k][t]: k deletions used, t in {0 equal, 1 already less}
    dp = [[0, 0] for _ in range(5)]
    dp[0][0] = 1

    for i in range(n):
        ndp = [[0, 0] for _ in range(5)]
        for k in range(5):
            for t in range(2):
                cur = dp[k][t]
                if not cur:
                    continue

                # delete a[i]
                if k < 4:
                    ndp[k + 1][t] += cur

                # keep a[i]
                if k - (i - (k)) < m:  # conceptual guard, not strictly needed
                    if t == 1:
                        nt = 1
                        if k <= 4:
                            ndp[k][nt] += cur
                    else:
                        # determine position in constructed string
                        pos = i - k
                        if pos < m:
                            if a[i] < b[pos]:
                                ndp[k][1] += cur
                            elif a[i] == b[pos]:
                                ndp[k][0] += cur
                            else:
                                pass
        dp = ndp

    return dp[4][1]

def main():
    t = int(input())
    for _ in range(t):
        a, b = input().split()
        print(solve(a, b))

if __name__ == "__main__":
    main()
```DP は、欠失によってアライメントが変化するという考えに基づいて構築されています。`a`とその結果の文字列。そのため、`b`次のように導出されます`i - k`。 これにより、文字列を明示的に構築することが回避されます。 

比較ロジックは遷移に組み込まれています。つまり、1 つの数字が構築されたシーケンスを 1 よりも小さくすると、`b`、もはや平等制約を強制する必要はありません。 

重要な点は、長さを超えて比較しないようにすることです。`b`4 つの削除が行われると、構築される数値は常に正確にその長さになるためです。

 ## 特殊なケース

 微妙なエッジ ケースの 1 つは、数字を削除すると結果の数値の先頭にゼロが生成される場合です。 たとえば、から数字を削除すると、`"10005"`産むことができる`"0005"`、数値的には次のとおりです`5`。 比較は桁ごとに行われるため、DP はこれを正しく処理します。`b`、および先行ゼロは、適切なプレフィックスの場合、自然に小さい数字として比較されます。`b`はゼロではありません。 

もう 1 つのケースは、すべての削除が先頭に集中している場合です。`a`。 のような入力の場合`a = "1000001234"`そして小さな`b`、早期に削除すると配置がシフトするため、後の数字が突然比較を支配します。 DP はこれについて次のように説明しています。`pos = i - k`マッピング。構築された文字列が常に正しく位置合わせされるようにします。`b`削除がどのように分散されたかに関係なく。 

3 番目のケースは、構築されたプレフィックスが一致する場合に発生します。`b`長く続き、最後の近くでのみ分岐します。 まさにここが、`t`状態は重要です。これにより、時期尚早なカウントが防止され、本当に小さいプレフィックスのみが有効なものとしてカウントされるようになります。
