 ## 解決策
 ## 問題の理解

 各セルが 3 つのタイプのいずれかである長方形のグリッドが与えられます。 一部のセルはユニットを配置できる有効な高地位置であり、一部のセルは敵が立っている低地セルであり、一部のセルはブロックされており配置には関係ありません。 タスクは、特定の指向性攻撃条件を満たす配置セルの数をカウントすることです。 

配置セルは、4 つの基本方向の 1 つを選択し、その方向にある次の 5 つの連続するセルを確認できる場合にのみ有効です。 これら 5 つのセルのうち、少なくとも 2 つは敵のセルでなければなりません。 開始セル自体をこの数に含めることはできません。外側に広がる 5 つのセルのみを含めます。 

出力は、少なくとも 1 つの方向についてこの条件を満たす有効な配置位置の数だけです。 

グリッド サイズは 1000 x 1000 までの大きさにすることができ、これは最大 100 万個のセルを意味します。 セルごとに一定量の作業をチェックするソリューションであれば問題ありませんが、各セルから長いセグメントを繰り返しスキャンするソリューションは遅くなりすぎます。 セルごと、方向ごとの単純なスキャンでは、毎回最大 5 つのセルが検査されますが、冗長チェックや繰り返しの境界ロジックを使用して不注意に実装された場合、それでも約 2,000 万回の操作にまで低下する可能性があります。これは問題ありませんが、より大きなウィンドウでの再計算や繰り返しのスライスを伴うものは脆弱になり、エラーが発生しやすくなります。 

主な微妙な点は境界処理です。 セルがエッジに近い場合、ある方向の 5 つの位置のうちのいくつかは存在しません。 これらは有効な非敵セルとして扱うのではなく、単純に無視する必要があります。 欠落しているセルを敵ではないとカウントする単純な実装では、エッジの配置に誤ってペナルティが課されてしまいます。 

別のエッジ ケースは、高地配置がある方向に有効なセルが 5 つ未満しか隣接していない場合に発生します。 たとえば、1 × 5 のグリッドでは、左または上を見ると有効なセルがゼロになる可能性があります。 正しい解釈は、既存のセルのみが考慮され、その中に少なくとも 2 つの敵が出現するかどうかを確認するということです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 配置可能な高地タイルであるすべてのセルについて、4 方向すべてを試します。 各方向について、最大 5 ステップ前進を繰り返し、出現する低地タイルの数を数え、その数が少なくとも 2 つであるかどうかを確認します。 いずれかの方向が条件を満たす場合、セルをカウントします。 

これが機能するのは、問題定義自体がローカルであるためです。 各セルは、4 方向の一定サイズの近傍のみに依存します。 ただし、ウィンドウ サイズが小さい場合でも、ブルート フォースはセルごとに最大 4 つのチェックを実行し、それぞれのチェックは最大 5 ステップになります。 これにより、最悪の場合でもセルあたり約 20 回の操作が行われ、1000 × 1000 のグリッド全体では約 2,000 万回の操作が行われることになります。 これは Python ではすでに受け入れられていますが、文字列のスライスや再帰の繰り返しなどのオーバーヘッドなしで適切に実装されている場合に限ります。 

重要な点は、注意深く反復する以上にさらなる最適化は必要ないということです。 この構造は固定サイズの方向スキャンであるため、プレフィックス合計や高度な前処理は必要ありません。 全体の問題は、一定数の固定オフセットをチェックすることに帰着します。 

したがって、最適な解決策は総当たりのアイデアと同じですが、固定オフセットに対する直接インデックス演算として慎重に実装されます。

 ## アルゴリズムのチュートリアル

 グリッド内のすべてのセルを反復処理します。 配置可能な高地タイルではない各セルについては、答えに寄与できないため、すぐにスキップします。 

有効な開始セルごとに、上、下、左、右の 4 つの方向をチェックします。 各方向について、最大 5 つの連続するセルを検査します。

私たちは、最大 5 つの位置に出現する低地細胞の数のカウンターを維持します。 カウンタが 2 以上に達した場合、この開始セルを直ちに有効としてマークし、そのセルに対する他の方向のチェックを停止します。 

グリッドの外に出るときは、無効なメモリにアクセスするのではなく、スキャンを停止することを注意深く確認する必要があります。 範囲外の位置は単に無視され、何もカウントされません。 

最後に、有効な開始セルをすべて合計します。 

### なぜ効果があるのか

 各セルは、固定されたローカル条件に対して独立して評価されます。 この条件は、各方向に最大 5 ステップ離れた位置の境界セットにのみ依存します。 すべての可能な方向とすべての可能な関連オフセットを明示的に列挙するため、すべての有効な構成が 1 回だけテストされます。 セル間に重複や依存性がないため、各セルを個別にカウントすると、全体的な正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] != 'H':
                continue

            ok = False

            for dx, dy in dirs:
                cnt = 0
                x, y = i, j

                for _ in range(5):
                    x += dx
                    y += dy

                    if x < 0 or x >= n or y < 0 or y >= m:
                        break
                    if grid[x][y] == 'L':
                        cnt += 1
                    if cnt >= 2:
                        ok = True
                        break

                if ok:
                    break

            if ok:
                ans += 1

    print(ans)

if __name__ == "__main__":
    main()
```グリッドは文字列のリストとして保存されるため、インデックス付けは O(1) です。 方向ベクトルは、分岐ロジックを繰り返すことなく動きをエンコードします。 各候補セルについて、各方向に最大 5 つのステップを明示的にシミュレートしますが、これは継続的な作業です。 

ある方向にすでに 2 人の敵が見えているので、微妙な詳細が早い段階で明らかになります。 これにより、その方向の残りのセルの不必要なスキャンが防止されます。 もう 1 つの微妙な点は、範囲外に出るとすぐに停止することです。これは、その位置がカウントに寄与しないためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] != 'H':
                continue
            ok = False
            for dx, dy in dirs:
                cnt = 0
                x, y = i, j
                for _ in range(5):
                    x += dx
                    y += dy
                    if x < 0 or x >= n or y < 0 or y >= m:
                        break
                    if grid[x][y] == 'L':
                        cnt += 1
                    if cnt >= 2:
                        ok = True
                        break
                if ok:
                    break
            if ok:
                ans += 1

    return str(ans)

 ## 特殊なケース

 主なエッジ ケースは、候補セルが境界近くにあり、ある方向に存在するセルが 5 つ未満である場合です。 のような場合には`1 5`と`H L L L H`、一番左の`H`その右側には有効なセルが 4 つしかありません。 アルゴリズムは依然としてこれら 4 つをチェックし、欠落しているセルが何らかの影響を及ぼしているとは想定せずに、低地セルを正確にカウントします。 

もう 1 つのエッジ ケースは、スキャンの早い段階でちょうど 2 つの低地タイルが現れる場合です。 たとえば、ある方向の最初の 2 つのセルが両方とも`L`、すぐに方向を有効としてマークし、それ以上のスキャンを停止します。 これにより、不必要な作業を回避しながら正確性が保証されます。 

最後のエッジケースは、複数の方向が条件を満たす可能性がある場合です。 アルゴリズムは、選択された方向には依存せず、少なくとも 1 つの方向がアルゴリズムを満たしているかどうかにのみ依存します。 1 つの方向がしきい値に達するとすぐにセルが 1 回カウントされ、二重カウントが防止されます。
