 ## 解決策
 ## 問題の理解

 配列が与えられ、各クエリはセグメント内のインデックスの順序付きペアすべてについて尋ねます。 クエリセグメントの場合$[l, r]$、すべてのペアを受け取ります$(i, j)$その範囲で計算します$a_i + a_j$、そしてそれらの結果すべてを XOR します。 

したがって、クエリは合計やカウントを要求しているのではなく、ビットごとの XOR に基づくすべてのペアごとの合計のグローバル パリティのような組み合わせを要求しています。 なぜなら両方とも$i = j$そして$i \neq j$ペアが含まれており、すべての要素はそれ自体および他のすべての要素と相互作用します。 

制約こそが本当の難しさなのです。 配列の長さは最大です$2 \cdot 10^5$、最大で$10^6$クエリ。 これにより、クエリごとの二次処理が即座に除外されます。$O((r-l+1)^2)$またはクエリごとに構造を再構築することに近いもの。 平$O(\log n)$クエリの数が非常に多いため、クエリごとの処理は厳しいため、ソリューションでは前処理後の各クエリをほぼ一定の時間に短縮する必要があります。 

微妙なエッジ ケースは、XOR が順序付けと重複とどれほど強く相互作用するかによって生じます。 ペアでのご注文となりますので、$(i, j)$そして$(j, i)$両方が含まれており、同じ値に寄与します$a_i + a_j$。 XOR は値が偶数回出現する場合にのみ値をキャンセルし、順序付きペアは単純な「組み合わせカウント」アプローチでは誤って処理される可能性がある構造化された多重度を作成するため、この重複が重要になります。 

もう 1 つの問題は、加算によってキャリーが発生することです。 単純なビットごとの独立性の仮定はすぐに失敗します。 たとえば、2 つの数値にビットの重複がない場合でも、桁上げ伝播によりそれらの合計が上位ビットを設定する可能性があり、XOR 構造が独立したビットではなくグローバル バイナリ相互作用に依存するようになります。 

## アプローチ

 直接的なブルート フォース ソリューションは、各クエリ範囲内のすべてのペアを反復し、それらの合計を XOR します。 これは定義に文字通り従っているため、正しいです。 ただし、同じサイズの単一クエリの場合、$k$、それは実行します$k^2$加算と XOR 演算。 と$k$潜在的に最大$2 \cdot 10^5$そして$10^6$クエリの場合、これは天文学的に大きくなり、$10^{16}$最悪の場合の運用。 

これを改善するために、式を再構築しようとします。 重要な観察は、すべてのペアごとの合計に対する XOR は、セグメント内の値の順序ではなく、その分布にのみ依存するということです。 さらに重要なことは、すべてのペアに対する XOR は双線形集約であることです。つまり、すべての要素が他のすべての要素に対して対称的に寄与します。 

ペアについて明確に考える代わりに、ビットの寄与に視点を移します。 各ビット位置については、そのビットがすべてのペアの合計にわたって奇数回設定されているかどうかのみを考慮します。 これにより、問題は、加算がマルチセット全体にキャリーをどのように分配するかというパリティを研究することになります。 

重要な構造上の洞察は、固定ビット位置に関するものです。$k$、下部のみ$k+1$数値のビットが、$k$合計の - 番目のビットが反転します。 これにより、依存関係が局所化されます。上位ビットは下位ビットのキャリー動作に影響を与えません。 これにより、2 の累乗を法とした切り捨てられた値に基づく前処理と、事前に計算された周波数情報を組み合わせてクエリに応答することが可能になります。 

次に、これらの切り詰められた分布の高速範囲抽出をサポートする前処理スキームを構築し、事前に計算された一定数のビットレベルの寄与を組み合わせることによって各クエリを解決できるようにします。

## アルゴリズムのチュートリアル

 各ビット位置を独立して処理し、最終的な XOR 答えへの寄与を計算します。 

1. ビット位置を固定する$k$。 クエリ範囲内のすべてのペアごとの合計の XOR でこのビットが設定されているかどうかを判断したいと考えています。 これは、奇数のペアが合計を生成するかどうかにのみ依存します。$k$-番目のビットは 1 です。 
2.$k$-番目のビット$a_i + a_j$より低いものだけに依存する$k+1$のビット$a_i$そして$a_j$。 これにより、すべての数値をその剰余値に置き換えることができます$2^{k+1}$このビットの正確さを変更することなく。 
3. お問い合わせの場合$[l, r]$、概念的には、セグメント内のこれらの削減された値の頻度分布が必要です。 その分布から、値が次の範囲にある合計を生成する順序付きペアがいくつあるかを判断できます。$k$-番目のビットが設定されます。 
4. クエリごとに頻度を再計算する代わりに、プレフィックス構造を前処理します。 ビットごとに$k$、剰余モジュロにわたるプレフィックス頻度テーブルを維持します。$2^{k+1}$。 これにより、係数サイズに比例した時間範囲の周波数分布を抽出できます。 
5. 各クエリと各ビットについて、その範囲内のすべての剰余クラスを反復処理することにより、有効なペアの数を計算します。 剰余クラスの各ペアについて$(x, y)$かどうかを確認します。$(x + y) \bmod 2^{k+1}$ビットがハーフインターバルに着地する$k$が設定されています。 そうであれば、順序ペアを尊重して、それらの周波数の積を加算します。 
6. XOR を使用して、これらの寄与のパリティを最終的な答えに累積します。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの不変式に依存します。 まず、数値を剰余的に減らす$2^{k+1}$の動作を保存します$k$-番目のビットは加算中です。上位ビットは位置へのキャリーに影響を与えることができないためです。$k$。 第 2 に、すべてのペアにわたる XOR 集約は、各ビット位置の寄与が何回出現するかというパリティのみに依存するため、ペアの頻度を 2 を法として数えれば十分です。 これら 2 つの事実を組み合わせると、グローバルなペアワイズ キャリー問題がビットごとの独立したモジュラー ヒストグラムに削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix(freqs):
    # freqs[k][i][v] is frequency of value v up to i for bit k
    return freqs

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    B = 30
    pref = []

    for k in range(B):
        mod = 1 << (k + 1)
        p = [[0] * mod for _ in range(n + 1)]
        for i in range(n):
            for v in range(mod):
                p[i + 1][v] = p[i][v]
            p[i + 1][a[i] & (mod - 1)] += 1
        pref.append(p)

    out = []

    for _ in range(m):
        l, r = map(int, input().split())
        l -= 1

        ans = 0

        for k in range(B):
            mod = 1 << (k + 1)
            cnt = [0] * mod

            for v in range(mod):
                cnt[v] = pref[k][r][v] - pref[k][l][v]

            bit_parity = 0

            for x in range(mod):
                if cnt[x] == 0:
                    continue
                for y in range(mod):
                    if cnt[y] == 0:
                        continue
                    if (x + y) & (1 << k):
                        bit_parity ^= (cnt[x] * cnt[y]) & 1

            ans |= (bit_parity << k)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、ビット位置ごとに、切り捨てられた値にプレフィックス頻度テーブルを作成します。 各クエリは範囲のヒストグラムを抽出し、すべての残基ペアをチェックして、それらが最終的な XOR のビットに寄与するかどうかを判断します。 

実装の重要な詳細は、XOR がパリティのみに依存するため、すべてが寄与レベルでモジュロ 2 で追跡されることです。 だからこそ、あらゆる蓄積は次のように削減されます。`& 1`最終ビットに結合される前に。 

剰余クラスに対するネストされたループは、すべてのモジュラー合計の結果をチェックすることを直接変換したものであり、これは各モジュラスがビット幅に比べて小さい場合にのみ実現可能です。

 ## 特殊なケース

 次のような単一要素セグメント$[i, i]$1 つのペアのみを生成します$(i, i)$したがって、結果は次のようになります。$a_i + a_i$。 頻度表が単一の非ゼロ剰余を生成し、ペアをカウントするステップに自然に自己ペアが含まれるため、アルゴリズムはこれを正しく処理します。 

すべての値が同一であるセグメントでは、XOR でのキャンセル動作が強調されます。 すべてのペアの合計は何度も繰り返され、正確さは順序付けられたペアの合計のパリティに依存します。 周波数ベースの定式化では、これをペアの列挙ではなく多重度のカウントに正しく還元します。 

2 のべき乗などの交互のビット パターンを持つセグメントには、伝播効果が生じます。 個々のビットが重複していなくても、合計により上位ビットがアクティブになります。 モジュロの使用$2^{k+1}$剰余グループ化により、これらのキャリーが各ビットレベルの計算で正しくキャプチャされることが保証されます。
