 ## 解決策
 ## 問題の理解

 次の形式の等価性をすべて列挙するように求められます。`a + b = c`どこ`a`、`b`、 そして`c`は正確な正の整数です`A`、`B`、 そして`C`それぞれ数字。 これらすべての有効な等式の中から、`k`- 形式で文字列として書かれた場合の辞書順での 1 番目`"a + b = c"`。 未満の場合`k`平等が存在する場合、戻ります`-1`。 

入力により複数のテスト ケースが得られます。 各テスト ケースは 4 つの整数を提供します。`A`、`B`、`C`、 そして`k`。 制約`1 ≤ A, B, C ≤ 6`小規模な場合には、これらの桁長のすべての数値を効率的に列挙できますが、次の可能性があります。`k`と同じくらい大きい`10^12`つまり、すべての等式を明示的に生成することはできないということです。 に直接ジャンプするメソッドが必要です。`k`すべての組み合わせを反復せずに -th 番目の等価性を確認します。 

明らかではないエッジケースは、有効な等価性が存在しない場合に発生します。 たとえば、次の場合`A = B = 1`そして`C = 1`、可能な最小の合計は`1 + 1 = 2`、すでに 2 桁が含まれているため、有効な等式は存在しません。 このような場合、やみくもに数値を生成する不用意なソリューションでは、誤った結果が生成される可能性があります。 同様に、`k`は非常に大きいので、正しく返さなければなりません`-1`未満の場合`k`等式が存在するか、そうでない場合は生成しようとします`10^12`平等なんて不可能でしょう。 

## アプローチ

 単純なアプローチによりすべての数値が生成される`a`と`A`数字、すべての数字`b`と`B`数字、その合計を計算します`c = a + b`、そして次のことを確認します`c`まさに`C`数字。 有効な等式がそれぞれ収集されてから、`k`-th が選択されています。 このアプローチは正しいですが、すぐに実行不可能になります。`A = B = 6`、おおよそあります`9 * 10^5 * 9 * 10^5 ≈ 8.1 * 10^11`組み合わせは大きすぎて 1 秒で処理できません。 

重要な洞察は、次の値を見つけるためにすべての合計を列挙する必要はないということです。`k`-番目の等価性。 それぞれについて`a`、可能な範囲`b`を生み出す値`C`-桁`c`連続している。 具体的には、`b`満たさなければなりません`10^(C-1) - a ≤ b ≤ 10^C - 1 - a`、さらに制約されます。`B`-桁の数字。 これにより、有効な数を数えることができます`b`それぞれに存在します`a`のブロック全体をスキップします`a`ときの値`k`ブロックサイズを超えています。 これらのカウントを繰り返し減算することにより、`k`正確に特定するまで`a`が含まれている`k`-番目の等式がある場合、対応する式を直接計算できます。`b`そして`c`。 

これにより、強引な列挙ではなく数値と範囲の構造を利用して、問題を組み合わせ爆発から管理可能な桁ごとの計算に変換します。

 ## アルゴリズムのチュートリアル

 1. 最小値と最大値を計算します。`A`-桁数:`min_a = 10^(A-1)`そして`max_a = 10^A - 1`。 同様に計算すると、`min_b`、`max_b`、`min_c`、 そして`max_c`。 
2. 残数の初期化`remaining = k`。 デクリメントしていきます`remaining`辞書順で有効な等価性を説明するためです。 
3. ループオーバー`a`から`min_a`に`max_a`昇順で。 それぞれについて`a`、最小値を計算します`b`それは有効な`C`-桁`c`:`b_min = max(min_b, min_c - a)`。 同様に、最大値を計算します。`b`それは有効な`c`:`b_max = min(max_b, max_c - a)`。 
4. もし`b_min > b_max`、無効です`b`このために存在する`a`、次へ進みます`a`。 
5. 有効枚数`b`これのために`a`は`count_b = b_max - b_min + 1`。 もし`remaining > count_b`、減算`count_b`から`remaining`そして続けます。 これはすべての等式をスキップします`a`それらは前にあるので、`k`-番目の等価性。 
6. もし`remaining ≤ count_b`、`k`-番目の等価性はこのブロック内にあります。 コンピューティング`b = b_min + remaining - 1`。 それから`c = a + b`。 文字列をフォーマットして返します`"a + b = c"`。 
7. を含むブロックが見つからないままループが完了した場合、`k`- 番目の等価性、戻り値`-1`。 

効果がある理由: それぞれ`a`昇順で処理され、それぞれ`a`、 全て`b`は昇順に処理されます。 有効な連続範囲`b`値を使用すると、それらのカウントが辞書編集上の順序を正確に反映するようになります。 ブロック全体をスキップすると、順序が維持され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        A, B, C, k = map(int, input().split())
        min_a, max_a = 10**(A-1), 10**A - 1
        min_b, max_b = 10**(B-1), 10**B - 1
        min_c, max_c = 10**(C-1), 10**C - 1

        remaining = k
        found = False

        for a in range(min_a, max_a + 1):
            b_min = max(min_b, min_c - a)
            b_max = min(max_b, max_c - a)
            if b_min > b_max:
                continue
            count_b = b_max - b_min + 1
            if remaining > count_b:
                remaining -= count_b
                continue
            b = b_min + remaining - 1
            c = a + b
            print(f"{a} + {b} = {c}")
            found = True
            break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは各桁の長さの境界を慎重に処理し、不必要な列挙を避けます。 の`b_min`そして`b_max`計算では、桁の長さと合計の制約の両方が尊重されることが保証されます。 のブロックをスキップします`b`値により、検索が加速されます。`k`-番目の等価性。
