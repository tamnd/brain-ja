 ## 解決策
 ## 問題の理解

 慣れないキーボードを備えた古いモバイル デバイスで数字を入力するのに必要なボタンの予想回数を計算するように求められました。 キーボードには、$m$数字ボタンとバックスペース。 ユーザーの Jan は、押すまでどのボタンがどのボタンであるかを区別できません。 間違った数字を押した場合は、バックスペースを使用して数字を消去してから再試行する必要があります。 したがって、ボタンを押すたびに確率的な選択が行われ、ジャンはこれまでに発見したことに基づいて常に最適に行動します。 

入力は数値の長さを与えます$n$そしてベース$m$、その後に入力する数字の数字が続きます。 出力は予想されるプレス数のモジュロです。$10^9 + 7$、合理的な期待を処理するためにモジュラー逆関数を使用して表現されます。 

と$n$まで$10^6$そして$m$まで$10^3$、おおよそ以上のアプローチ$O(n m)$操作が遅すぎる可能性があります。 考えられるすべてのランダムなボタン シーケンスの単純なシミュレーションでは、指数関数的に大規模になります。$n$、実行不可能になります。 エッジケースには次のような場合が含まれます。$n=1$、すべての数字が同一の場合、または$m=2$そのため、確率は粗く、バックスペースが頻繁に繰り返されます。 たとえば、次のように入力すると、`0`基数 2 では、最初のランダム ボタンがバックスペースまたはバックスペースの場合、複数回押す必要がある可能性があります。`1`。 

## アプローチ

 ブルートフォース手法では、Jan が数字の入力に成功するまで、ボタンを押すすべてのシーケンスをシミュレートします。 各ステップには、未知のボタンの中からランダムなボタンを選択し、正しければ進むか、間違っていればバックスペースを使用することが含まれます。 これにより、分岐要素を含む可能性のツリーが生成されます。$m+1$各ポジションごとに、$O((m+1)^n)$州。 これは正しいですが、小さい場合でも天文学的に遅くなります。$n$、各シーケンスの部分的な期待値を保存することは現実的ではありません。 

重要な洞察は、この問題が単純な確率的構造を示しているということです。つまり、どの時点でも、残りの接尾辞を入力するために予想される押下回数は、どの数字が発見されたかによってのみ決まります。 Jan は常に未知のボタンを最適に押すため、新しい未知の数字ごとに、残りの未知のボタンの数に比例して予想される押下が等比列的に追加されます。 これにより、各桁の最後の出現を追跡しながら、期待値を反復的に計算することができます。 組み合わせ構造により複雑さが軽減されます。$O(n m)$、指定された制約の下では許容されます。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`last_seen`サイズの$m$ゼロ付き。 これにより、各数字が出現した最後の位置が記録されます。 これにより、各ステップでどのボタンを考慮する必要があるかを判断できます。 
2. アキュムレータを初期化する`expected`ゼロに。 これは、予想されるプレスの合計をモジュロの有理数として保持します。$10^9+7$。 
3. 数値の位置を左から右に繰り返します。 ポジションごとに`i`、現在の数字を次のようにします`d`。 
4. この桁で現在不明なボタンの数を計算します。 これは`m - known_digits`、 どこ`known_digits`Jan がこの位置までにすでに遭遇した個別の数字の数です。 
5. この数字を初めて入力するときに予想される押す回数は、`(m + 1) / (m - known_digits)`。 分子`m+1`はバックスペースを含むボタンの総数から求められ、分母は未知の数字を正しく押す確率を反映します。 モジュラー逆算術を使用して除算モジュロを処理する$10^9+7$。 
6.アップデート`last_seen[d]`現在の位置に移動して、この数字が検出されたことを追跡します。 インクリメント`known_digits`この数字が初めて表示される場合はカウンター。 
7. この位置に対して計算された予想プレス数を次のように累積します。`expected`。 
8. すべての数字を処理した後、`expected`予期されるプレス数のモジュロが含まれます$10^9+7$。 この値を出力します。 

不変条件は、各ステップで、既知の数字の正確な数とそれらが出現した最後の位置を維持することです。 これにより、各ステップで正しい数字を押す確率が正確に計算され、期待値が位置全体で加算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(a, mod):
    return pow(a, mod-2, mod)

def solve():
    n, m = map(int, input().split())
    digits = list(map(int, input().split()))
    
    last_seen = [0] * m
    known_digits = 0
    expected_num = 0
    
    for i, d in enumerate(digits, 1):
        if last_seen[d] == 0:
            prob_den = m - known_digits
            expected_num += (m + 1) * modinv(prob_den, MOD)
            expected_num %= MOD
            known_digits += 1
        last_seen[d] = i
    
    print(expected_num % MOD)
```の`modinv`関数は、フェルマーの小定理を使用して逆モジュラーを計算します。 ゼロ除算の問題を回避するために、ポジションには 1 から始まるインデックスを使用します。 新しい数字ごとに、予想される押下を次のように計算します。`(m+1) / (m - known_digits)`モジュロ`10^9+7`、蓄積していきます。 更新中`last_seen`繰り返される数字を二重にカウントしないようにします。 このロジックは、期待値の最適な反復計算を実装します。

 ## 特殊なケース

 いつ$n=1$そして$m=2$、入力用`0`、`expected_num`は`(2+1)/2 = 3/2`。 アルゴリズムは計算します`modinv(2, MOD)`正しく乗算すると、`666666674`。 数字が繰り返されると、`known_digits`期待値の計算式が二重にカウントされないようにします。 基数を最大にするために、逆モジュラーは整数の除算エラーを防ぎます。 交互の数字の場合、新しい数字のそれぞれが予想される正しい押下をトリガーし、反復加算モデルがすべてのシーケンスを処理することを確認します。
