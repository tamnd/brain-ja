 ## 解決策
 ## 問題の理解

 プレイヤーの列が 2 つの連続するグループに分けられることになります。 最初の部分は 1 つのチームに属し、2 番目の部分は別のチームに属します。 各プレイヤーにはじゃんけんの動きが固定されており、それを変更することはありません。 両チームは同じ速度で互いに向かって移動し始めるため、相互作用は常に初期位置によって課された順序で発生します。 

左側のプレイヤーが右側のプレイヤーと対戦するときは、引き分けない限り、決定的なジャンケン試合を行います。 一方の手がもう一方の手を破った場合、敗者は永久に削除され、勝者が続行します。 両方の動きが同じ場合、勝者はランダムに選ばれるため、どちらの側もその特定の遭遇を生き残ることができます。 

このプロセスは、1 つのチームが完全に敗退するまで続きます。 その瞬間、残りのプレイヤーはそれ以上の相互作用なしに永遠に動き続けます。 タスクは、最終状態まで生き残ることを可能にする、少なくとも 1 つの引き分け結果の可能性のあるシーケンスを持っている個々のプレーヤーが何人いるかを数えることです。 

重要な点は、絆だけが自由をもたらすということです。 対等でない対戦には必ず結果が決まります。 したがって、問題は、強制ジャンケンルールが尊重されている間、何らかの有効な引き分けの解決の下でどのプレイヤーが維持されることができるかということになります。 

制約は最大 200,000 人のプレイヤーに適用され、完全な対戦を繰り返し再計算したり分岐結果を明示的に調査したりするシミュレーションは即座に除外されます。 同点で分岐したり、イベントごとに戦いをシミュレートしたりするソリューションは、最悪の場合、指数関数的または二次関数的に爆発します。 

2 つのチームの境界を越えて同等のキャラクターが多数存在する場合、微妙な特殊なケースが発生します。 たとえば、ラインがすべて同じキャラクターの場合、すべての遭遇は引き分けとなり、引き分けごとにランダムに選ばれた 1 人のプレイヤーが除外されます。 同点の解決方法に応じて、個々のプレイヤーが生き残ることができるため、答えはプレイヤーの総数になります。 単純な決定論的なシミュレーションでは、タイの固定側が誤って削除され、生存可能性が過小評価される可能性があります。 

片側に厳密なカウンタータイプのクラスターが含まれる場合、別のエッジケースが発生します。 たとえば、次のようなシーケンス`SSS`直面している`PPP`常に排除します`P`決定論的な解決策では側にありますが、関係が部分的な生存パターンを依然として許容する可能性があります。 隣接するペアのみを解決する単純な貪欲シミュレーションでは、負けたタイプのすべてのメンバーが運命にあると誤って仮定する可能性があります。 

## アプローチ

 ブルートフォース解釈では、プロセス全体をシミュレートし、次に対戦する対戦相手のペアを繰り返し特定し、試合を解決します。 遭遇するたびに 1 人のプレイヤーが削除されるか、同点が 2 つの可能性に分岐します。 これにより分岐プロセスが作成され、そのサイズは同点の数に応じて指数関数的に爆発的に増加します。これは、等しい遭遇が発生するたびに、可能な未来の数が 2 倍になるためです。 1 つのチェーンの長さが 200,000 であっても、これは実現不可能です。 

重要な観察は、動きの形状によって遭遇順序が完全に固定されるということです。 プレイヤーは、2 つのチーム間で進化する単一のフロンティアを通じてのみ対話します。 唯一の不確実性はどちらが引き分けに勝つかということですが、その不確実性は新たな遭遇順序を作成するのではなく、固定された相互作用でどのプレイヤーが生き残るかを変えるだけです。 

これは、絆は_誰と誰が出会う_ではなく、_両者が同一である場合に誰が生き残る_のみを意味します。 したがって、どちらかの参加者を維持するために使用できる、完全に制御可能な決定として関係を扱うことができます。 

この観点から見ると、このプロセスは、左端の未解決のチーム間相互作用を繰り返し解決する単一パッセージ消去のように動作します。 手が異なる場合は常に勝者が決まります。 動きが同じ場合はいつでも、生き残るプレイヤーを自由に選択できるため、この自由をいつでも利用して、維持したいプレイヤーの排除を避けることができます。 

これにより、問題は貪欲な削減プロセスに変換されます。つまり、ジャンケンで強制的に負けた場合にのみプレイヤーを削除します。 平等な遭遇では、ターゲットのプレイヤーにとって常に有利な結果を選択できるため、「生存の可能性」を目的として特定の排除を強制することはありません。

 ## アルゴリズムのチュートリアル

 私たちは、チーム間対戦にまだ参加できるアクティブなプレーヤーの現在未解決の「フロンティア」を表すスタックを使用してラインを処理します。 

1. まだ除外されていない候補者のスタックを維持しながら、プレーヤーを左から右に繰り返し処理します。 このスタックは、これまでに解決されたすべての相互作用の存続構造を表しています。 
2. 新しいプレーヤーが検討されるとき、隣接する未解決の参加者だけが最初に会うことができるため、それらをスタック内の最後のプレーヤーと比較します。 
3. 両方のプレイヤーが同じ動きをした場合、これは同点の状況です。 タイドはどちらの方向でも解決できるため、強制的に排除することはせず、代わりにこの相互作用を柔軟なものとして扱います。 この段階では不可逆的な敗退を約束せず、両方のプレイヤーが生存を維持できるようにするだけです。 
4. 手が異なる場合はじゃんけんルールを適用します。 これはどのようなシナリオでも避けることのできない強制的な結果であるため、負けたプレイヤーはスタックから削除されます。 
5. 現在のプレーヤーとスタックのトップの間でこれ以上強制排除ができなくなるまでこの比較プロセスを繰り返し、その後、現在のプレーヤーをプッシュします。 

すべてのプレーヤーを処理した後、残りのスタックには、有効な同点解決シーケンスの下で保存できるプレーヤーが正確に含まれます。 

### なぜ効果があるのか

不変条件は、アルゴリズムによって削除されたすべてのプレーヤーは、引き分けの可能なすべての解決で排除されるということです。これは、それぞれの削除が、逆転または延期できない厳密に負けたジャンケンの対戦に対応するためです。 逆に、スタックに残っているすべてのプレイヤーは、強制負け構成に入らないようにタイの結果を選択することで脱落を回避できます。 タイは順序を決して制約しないため、厳密なマッチアップと一貫性のある生き残った構成を維持するように常に方向付けることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def beats(a, b):
    # returns True if a beats b in RPS
    return (a == 'R' and b == 'S') or \
           (a == 'S' and b == 'P') or \
           (a == 'P' and b == 'R')

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    
    stack = []
    
    for c in s:
        # resolve forced eliminations against stack top
        while stack:
            top = stack[-1]

            # if same move, tie is flexible: stop resolving
            if top == c:
                break

            # if current beats top, pop top
            if beats(c, top):
                stack.pop()
                continue

            # if top beats current, current is eliminated
            if beats(top, c):
                break
        
        else:
            # only push if not eliminated in the while-break sense
            stack.append(c)
            continue

        # if we broke due to current being eliminated, skip push
        if not stack or stack[-1] != c:
            continue

        stack.append(c)

    print(len(stack))

if __name__ == "__main__":
    solve()
```この実装では単一のスタックが維持され、強制じゃんけん排除のみが解決されます。 内側のループは、入ってくるプレイヤーによって厳密に打ち負かされる要素を削除し続けます。これは、移動するフロンティアに沿った決定論的な衝突に対応します。 

微妙な点は、等しい文字の処理です。 スタックの一番上が現在のプレイヤーと同じ動きをする場合、解決は完全に停止されます。 これは、引き分けの結果は制御可能であり、生存の可能性を制限するような決定的な排除を強制するものではないという事実を表しています。 

制御フローにより、解決された遭遇で厳密に敗北した場合にのみプレイヤーが破棄されることが保証されます。 それ以外の場合、それらは少なくとも 1 つの同点解決シナリオにおいて生き残りの候補のままです。

 ## 特殊なケース

 同じ動きで構成されるラインは、タイの柔軟性がいかに生存性を最大化するかを示しています。 すべての遭遇は引き分けであるため、特定の解決策が選択されない限り、プレーヤーは強制的に敗退することはありません。 この場合、厳密な優位性が除去をトリガーすることはないため、アルゴリズムはすべてのプレイヤーを保持します。 

次のような完全に交互のシーケンス`RSRSRS`は真逆の行動を示します。 すべてのインタラクションは強制され、各プレイヤーの運命は RPS ルールによって即座に決定されます。 スタックは負けたプレーヤーを決定論的に排除し、引き分けロジックは決してアクティブになりません。これにより、アルゴリズムが引き分けがない場合の純粋な優勢フィルターのように動作することが確認されます。
