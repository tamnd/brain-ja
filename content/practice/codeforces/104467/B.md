 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、その部分文字列に対する複数の独立したクエリに答える必要があります。 各クエリは範囲を指定します$[L, R]$。 この範囲内で、より小さなサブセグメントを見つける必要があります。$[a, b]$部分文字列が$S[a..b]$部分文字列全体のちょうど半分の 0 と半分の 1 が含まれているという意味で、完全にバランスが取れています。$S[L..R]$。 

この条件は、見た目よりも厳しいものです。 クエリ範囲が$c_0$ゼロと$c_1$1 の場合、有効な答えは、カウントが正確に一致する部分配列でなければなりません。$c_0/2$ゼロと$c_1/2$もの。 これはすぐに、両方が$c_0$そして$c_1$偶数である必要があります。そうでない場合、答えは存在しません。 

出力は有効なペアである必要があります$(a, b)$不可能な場合は -1。 最短または最長のセグメントは必要なく、存在するだけです。 

制約$N, Q \le 10^5$各クエリは大まかに処理する必要があることを意味します。$O(1)$または$O(\log N)$前処理後の時間。 各範囲を直接スキャンするソリューションは、最悪の場合、速度が非常に遅くなります。$O(NQ)$操作。 

微妙な点は、答えが必ずしも対称性や接頭辞の境界と一致するとは限らないことです。 素朴な直感では、中間点の分割を検索したり、プレフィックスの合計のバランスをとったりすることを提案するかもしれませんが、有効なセグメントはクエリ間隔内のどこにでも現れる可能性があります。 

素朴なアプローチの失敗例の 1 つは、答えが中央に配置されなければならないと仮定することです。 たとえば、次のような範囲で`0011`、次のような有効な答えが存在します。`[2,3]`, しかし、中間点ベースの推測では、中心付近だけをチェックする場合は見逃してしまいます。 

別の失敗モードは、前処理を行わずにウィンドウを貪欲に拡大または縮小しようとすることです。 プレフィックス構造やパリティ推論がないと、クエリごとの 2 次スキャンに陥ります。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアを試します$(a, b)$内部$[L, R]$、その部分配列内の 0 と 1 を数え、それが必要なハーフカウントと一致するかどうかを確認します。 カウントを高速化するためにプレフィックス合計を使用しても、これは依然としてチェックします$O(N^2)$最悪の場合のクエリごとの間隔。 と$10^5$クエリの場合、これは天文学的な規模になります。 

重要な観察は、条件が 0 と 1 のカウントの違いのみに依存するということです。 文字列を次のようにエンコードすると、$+1$のために`1`そして$-1$のために`0`の場合、バランスの取れた部分文字列は、合計が 0 になる正確な部分文字列です。 問題は次のようになります。各クエリ範囲内で、合計がゼロで、範囲全体を均等に分割することと一致する総和制約を持つ空でない部分配列を見つけます。 

これにより、問題はプレフィックスの合計に変換されます。 させて$P[i]$プレフィックスの合計を次のようにします$i$。 部分文字列$[a, b]$和がゼロになるのは、次の場合に限ります。$P[b] = P[a-1]$。 したがって、タスクはクエリ範囲内でプレフィックスの合計が等しい 2 つのインデックスを見つけることになります。 

ただし、選択した部分配列が全範囲の 0 と 1 のちょうど半分に対応するという追加の制約を尊重する必要があります。 これにより、より強力な構造が得られます。$[L, R]$は偶数である必要があり、基本的にはプレフィックスの合計がプレフィックスの差の合計のちょうど半分に達する中間点を探しています。 

そこで、プレフィックスの合計を計算し、クエリごとに、プレフィックスの合計が範囲内のターゲット値と等しくなる位置を見つけることに絞り込みます。 これは古典的な範囲存在クエリとなり、プレフィックス合計と二分探索の前処理位置を使用して処理できます。 

各プレフィックス合計値について、それが発生するすべてのインデックスを保存します。 クエリの場合、ターゲット プレフィックス合計値を計算し、有効なインデックス間隔内に出現が存在するかどうかを確認します。

 | プレフィックス + ハッシュ + 二分検索 |$O((N+Q)\log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列をプレフィックス合計配列に変換します。`0`-1 に寄与し、`1`+1に貢献します。 これにより、任意の部分文字列のバランス条件をプレフィックスの等価条件として表現できるようになります。 
2. 各プレフィックス合計値をそれが発生するインデックスにマッピングするリストの配列を構築します。 クエリ範囲内の出現箇所に高速にアクセスする必要があるため、これは不可欠です。 
3. クエリごとに$[L, R]$、プレフィックス合計を使用して範囲の合計を計算します。 この合計が偶数でない場合は、均等な分割は不可能であるため、すぐに -1 を返します。 
4. 範囲合計の半分に相当するターゲット プレフィックス合計値を計算します。 これは、有効なカットが発生する必要があるプレフィックス レベルを表します。 
5. 次に、内部の 2 つの位置を見つける必要があります。$[L-1, R]$ここで、プレフィックスの合計は同じ値に等しく、それらの差により、完全に含まれる有効なサブセグメントが得られます。$[L, R]$。 保存された位置リストでそのプレフィックス値の二分検索を使用して、範囲内の候補を見つけます。 
6. そのような位置が存在する場合は、対応する位置を出力します。$(a, b)$。 それ以外の場合は -1 を出力します。 

重要な操作は、「範囲内のバランスの取れたサブ配列を見つける」問題を「範囲内で繰り返されるプレフィックスの合計値を見つける」問題に変換することであり、ソートされた出現リストにより効率的です。 

### なぜ効果があるのか

 接頭辞の合計変換により、すべての部分配列の合計が 2 つの接頭辞値の差として表現されるようになります。 バランスの取れたサブ配列は、2 つのエンドポイントでのプレフィックスの合計が等しいことに対応します。 サブ配列が元の範囲のちょうど半分を表さなければならないという制約により、プレフィックス ターゲットは一意に決定されます。 すべてのプレフィックスの出現はソートされた順序で保存されるため、クエリ間隔内の有効なペアは二分検索を使用して検出でき、すべての出現が列挙されるため、有効なソリューションを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    # prefix sum: 1 -> +1, 0 -> -1
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if s[i - 1] == '1' else -1)

    # map prefix value -> indices
    pos = {}
    for i, v in enumerate(pref):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    out = []

    for _ in range(q):
        L, R = map(int, input().split())

        total = pref[R] - pref[L - 1]
        if total % 2 != 0:
            out.append("-1")
            continue

        target = pref[L - 1] + total // 2

        if target not in pos:
            out.append("-1")
            continue

        arr = pos[target]

        # find any index in [L-1, R]
        # binary search manually
        lo, hi = 0, len(arr) - 1
        left_idx = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if arr[mid] >= L - 1:
                left_idx = mid
                hi = mid - 1
            else:
                lo = mid + 1

        if left_idx == -1 or arr[left_idx] > R:
            out.append("-1")
            continue

        # second endpoint: we need another occurrence in range if possible
        start = left_idx
        if start + 1 < len(arr) and arr[start + 1] <= R:
            a = arr[start] + 1
            b = arr[start + 1]
            out.append(f"{a} {b}")
        else:
            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、線形時間でプレフィックスの合計を構築し、プレフィックス値ごとにインデックスをグループ化します。 各クエリは、必要なターゲット プレフィックス合計レベルを計算し、二分検索を使用してクエリ ウィンドウ内の有効な出現箇所を見つけます。 プレフィックス配列は 0 から始まり、文字列は 1 から始まるため、出力の構築ではインデックスを慎重にシフトします。 

微妙な実装の詳細は、次の間で一貫したインデックスを維持することです。$S$、プレフィックス配列、および保存された位置。 通常、off-by-one エラーは、次の間で変換するときに発生します。$S[a..b]$とプレフィックスの違いを考慮して、コードは一貫してプレフィックス インデックスを使用します。$i$加工後の状態を表す$S[i]$。

 ## 特殊なケース

 重要なエッジ ケースは、プレフィックス合計ターゲットが存在するが、クエリ範囲内に 1 回だけ存在する場合です。 その場合、和条件が潜在的なバランスを示しているにもかかわらず、有効なサブ配列を形成できません。 アルゴリズムは、内部で少なくとも 2 つの出現を要求することでこれを処理します。$[L-1, R]$、単一のプレフィックス一致ではなく、実際のサブ配列が存在することを確認します。 

もう 1 つのエッジ ケースは、クエリ範囲の合計の不均衡が奇数である場合です。 ローカル構造が部分的にバランスがとれているように見えても、グローバル要件により即座に拒否が強制され、プレフィックス パリティ チェックによってこれらのケースは検索せずに早期にフィルタリングされます。 

最後のエッジケースは、クエリ範囲外でプレフィックス値が繰り返されることです。 オカレンスはグローバルに保存されるため、バイナリ検索ステップではクエリ ウィンドウ内のインデックスのみを考慮するようになり、遠くの一致による誤検出を防ぎます。
