 ## 解決策
 ## 問題の理解

 単一の整数値 (最初はゼロ) で始まる文字が与えられます。 その後、キャラクターは一連のステージを通過し、各ステージでちょうど 2 つの利用可能な変換が存在します。 各変換は、定数による加算、定数による減算、または定数による乗算の形式の算術演算です。 すべての段階で、2 つの演算のうち 1 つを正確に選択し、それを現在の値に即座に適用する必要があります。 

すべてのステージを順番に処理すると、最終的な値が得られます。 タスクは、この最終値ができるだけ大きくなるように、ステージごとに 1 つの操作を選択することです。 

重要な詳細は、現在の値自体以外に分岐状態や隠しメモリがないことです。 すべての決定は現在の数値を即座に変換し、将来の決定は結果として得られる数値のみに依存します。 

最大 100,000 ステージという制約により、考えられるすべての選択シーケンスを探索するアプローチは排除されます。 すべてに対する素朴な強引さ$2^N$指数関数的な時間を必要とするため、選択はすぐには不可能になります。 プレフィックスごとに複数の候補値をシミュレートしようとするアプローチであっても、二次関数の爆発を避けるために慎重な枝刈りが必要になります。 

微妙な特殊なケースは、負の数との乗算から発生します。 負の値を乗算すると符号が反転するため、より小さい値を先に取得すると、後でより大きな値が得られるように見える場合があります。 ただし、各決定ステップを常に完全に制御し、最良の即時結果を再計算するため、最終的なソリューションでは複数の状態を維持する必要はありません。 

よくある間違いは、両方の結果を評価せずに、各段階で最適なゲートを独立して選択できると想定することです。 もう 1 つの間違いは、中間値が負になり、乗算時に異なる動作をする可能性があることを無視して、最大値のみを維持しようとすることです。 

たとえば、現在の値が 5 で、次のステージが次の値を提供するステージを考えてみましょう。`* -2`または`+ -100`。 地元では、`+ -100`-95 を与えますが、`* -2`-10 が得られるため、乗算の方が優れています。 ただし、後の演算がすべて正の加算である場合は、(負であっても) より大きな大きさを維持することが重要になる可能性があります。 これにより、すべてのステップで両方のオプションを明示的にチェックするようになります。 

## アプローチ

 強引なアプローチでは、考えられるすべてのゲート選択シーケンスを試します。 それぞれの$N$ステージには 2 つのオプションがあります。これにより、$2^N$可能な最終値。 各シミュレーションには次の時間がかかります$O(N)$、結果として指数関数的な時間が発生します$O(N 2^N)$、これは不可能です$N = 10^5$。 

重要な観察は、各段階で複数の独立した状態を持たないということです。 進化する値は 1 つだけであり、各ステップで両方の選択の結果を決定論的に計算できます。 次の状態は現在の数値のみに依存するため、その 1 つの現在の値を維持し、結果として得られる 2 つの値のうち良い方を常に選択するだけで済みます。 

これにより、問題は単純なステップバイステップのシミュレーションに縮小されます。各段階で、現在の値に対する両方の演算を評価し、結果として大きい方の値を選択します。 これが機能するのは、現在の数値以外に将来の選択を過去の決定に結び付ける制約がないためです。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 状態を初期化する

 現在の電力レベルを 0 に設定して開始します。これは、プロセス全体で追跡する唯一の状態を表します。 

### ステップ 2: 各ステージを順番に処理する

 各段階で、使用可能な 2 つの操作を読み取り、それぞれを個別に適用した後の現在の値を計算します。 

### ステップ 3: 両方の結果を評価する

 最初の操作を現在の値に適用して、候補結果を生成します。 2 番目の操作も同様に適用し、別の候補結果を生成します。 これら 2 つの数字は、この段階で考えられるすべての結果を表します。 

### ステップ 4: より良い結果を選択する

 2 つの候補結果のうち大きい方を選択し、現在の値をそれに更新します。 これにより、現在の状態を考慮した各段階後に、常に最高の達成可能な値が維持されるようになります。 

### ステップ 5: 最後まで繰り返します

 すべてのステージでこのプロセスを順番に続けます。 最終的な電流値が答えになります。 

### なぜ効果があるのか

 どの段階でも、システムの状態は 1 つの整数で完全に記述されます。 すべてのアクションは、この整数を新しい整数に決定的にマップします。 考えられる両方のアクションを評価し、より大きな結果の状態をもたらす方を即座に選択するため、同じプレフィックスが与えられた場合に、より良い最終結果をもたらす可能性のある状態を破棄することはありません。 

現在の値自体を超えて、ステージ間に隠れた依存関係はありません。 したがって、各ステップでの値を最大化することは、一連の決定シーケンス全体で最終結果を最大化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply(x, op, v):
    if op == '+':
        return x + v
    if op == '-':
        return x - v
    return x * v

def solve():
    n = int(input())
    x = 0

    for _ in range(n):
        c1, v1, c2, v2 = input().split()
        v1 = int(v1)
        v2 = int(v2)

        a = apply(x, c1, v1)
        b = apply(x, c2, v2)

        if a > b:
            x = a
        else:
            x = b

    print(x)

if __name__ == "__main__":
    solve()
```実装では単一の整数が保持されます`x`現在の電力レベルを表します。 各ステージで、小さなヘルパー関数を使用して利用可能な両方の操作の結果を計算し、更新します。`x`より良い結果へ。 ヘルパー関数は、考えられる 3 つの算術演算を直接エンコードし、メイン ループで分岐ロジックが繰り返されることを回避します。 

比較ステップは非常に重要です。両方の結果は常に同じ開始値から評価され、その段階で選択が局所的に最適であることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、負の値による乗算が使用できる場合です。 このような場合、現在の値の符号が反転する可能性があり、局所的に小さい結果が後でより魅力的に見える可能性があります。 このアルゴリズムは、すべてのステップで両方の変換を現在の値から直接評価するため、これを正しく処理します。そのため、単調性についての暗黙的な仮定は行われません。 

もう 1 つのエッジ ケースは、両方の操作で同じ結果が生成される場合です。 その場合、どちらの選択も有効であり、アルゴリズムは正確さに影響を与えることなく一貫してどちらかを選択します。 

最後のエッジケースは、オペランドがゼロの場合です。 ゼロを乗算すると状態が崩壊し、その後の操作によって結果が完全に決まります。 アルゴリズムは常に正確な現在値から両方のオプションを再計算するため、この崩壊は特別なケースなしで自然に処理されます。
