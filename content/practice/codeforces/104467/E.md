 ## 解決策
 ## 問題の理解

 2 つのバイナリ文字列が与えられ、隣接する文字のペアを選択して XOR に置き換えることで、最初の文字列を繰り返し圧縮できます。 2 つのシンボルが 1 つになるため、各操作により文字列が 1 つ短くなります。 目的は、このような一連の操作の後に、最初の文字列を正確に 2 番目の文字列に減らすことができるかどうかを判断することです。 

重要なメンタル モデルは、キャラクターを再配置しているのではなく、隣接するキャラクターを繰り返し 1 列にマージしているということです。 すべてのマージにより、位置情報はローカルに破壊されますが、グローバルには線形構造が維持されます。 各演算により長さが 1 ずつ減少するため、次からの有効な変換はすべて$S$に$T$正確に必要です$|S| - |T|$操作。 

制約は次のとおりです$10^6$これにより、マージのシミュレーションや部分文字列に対する動的プログラミングが即座に除外されます。 どのソリューションも線形または線形に近いものである必要があり、変更が繰り返される場合でも文字列を明示的に維持することは避けなければなりません。 

最終的な文字列はビットの任意の組み合わせに依存するが、隣接関係は維持されるため、プロセスは順序によって制限されると考えるのが素朴な誤解です。 

微妙な失敗例は、最初の文字列にさまざまな方法で「マージ可能」に見える多くのゼロが含まれている場合に発生しますが、マージの構造は実際には厳格です。 たとえば、次のような文字列では`1010`、マージ順序に応じて異なる結果を作成できるように見えるかもしれませんが、到達可能なセットは、組み合わせ爆発が示すよりもはるかに小さいです。 

もう 1 つのエッジケースは次のような場合です$T$長さは異なりますが、ローカル XOR パターンと「一貫しているように見えます」$S$。 マージによって長さが決定論的に削減されるため、長さの違いを考慮しないアプローチでは、不可能な変換が誤って受け入れられてしまいます。 

## アプローチ

 プロセスを直接シミュレートしようとすると、文字列を繰り返しスキャンし、隣接するペアを選択し、XOR に置き換えて、長さが一致するまで続行することになります。$T$。 各マージにかかるコスト$O(n)$単純な実装では、構造を再構築または変更する必要があるためです。 まで$10^6$キャラクターと潜在的に$10^6$操作すると、これは次のようになります$O(n^2)$が遅すぎます。 

別の視点は、操作を逆にすることです。 マージについて考える代わりに、最後の文字列を分割して元の文字列に戻すことを想像してください。 の各キャラクター$T$の連続したブロックを表します$S$その XOR がその文字に等しい。 問題は分割の問題になります: 分割できるか$S$正確に$|T|$XOR が一致する連続セグメント$T$?

 この再定式化が機能するのは、各マージでは隣接する要素のみが結合されるため、最終的な値は元の文字列の連続セグメントの XOR に対応します。 セグメントの順序は保持され、各セグメントは正確に 1 文字を構成する必要があります。$T$。 

したがって、問題は、パーティションが存在するかどうかを確認することになります。$S$の中へ$|T|$各セグメントの XOR が対応する文字と一致する連続セグメント$T$。 必要なのは存在だけであるため、貪欲なスキャンで十分です。実行中に XOR を蓄積します。$S$、現在のプレフィックス XOR が次のターゲット ビットと一致するたびに、セグメントを切り取ります。

 | 貪欲なセグメント XOR マッチング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 スキャンします$S$現在のセグメントの実行中の XOR を維持しながら、左から右に。 また、次の分野での位置も追跡します。$T$、現在どのターゲット ビットと照合しようとしているかを示します。 

1. ポインタを初期化する$j = 0$のために$T$、および変数`cur = 0`現在のセグメントの XOR を保存します。 
2. 各文字を反復処理します。$S[i]$、更新中`cur ^= S[i]`。 
3. いつでも`cur`と等しくなる$T[j]$、このセグメントを終了して移動します$j$進む、リセットする`cur`ゼロに。 
4.最後まで続ける$S$。 
5. すべての文字を処理した後、すべての文字が$T$一致しました、つまり$j = |T|$また、部分セグメントが残っていないことも確認します (`cur = 0`）。 

重要な考え方は、セグメントが閉じられるたびに、それが 1 つの出力文字に正確に対応するということです。 部分的なセグメントが次のターゲット位置に飛び出すことは決して許可されません。 

### なぜ効果があるのか

 隣接する XOR マージのシーケンスは、元の文字列の連続した間隔にわたって XOR 値を構築することに対応します。 隣接しない領域を混合する操作はありません。そのため、最終的な文字列は、元の文字列を連続したブロックに分割したものを表す必要があります。 逆に、XOR 一貫性のあるセグメントへの有効な分割は、単一ビットに崩壊するまで各セグメント内でマージすることで実現できます。 これにより、有効なマージ シーケンスと有効なセグメンテーションの間に 1 対 1 の対応関係が作成され、貪欲な構築が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    T = input().strip()
    
    n, m = len(S), len(T)
    if n < m:
        print("No")
        return
    
    j = 0
    cur = 0
    
    for ch in S:
        cur ^= (ord(ch) - 48)
        
        if j < m and cur == (ord(T[j]) - 48):
            j += 1
            cur = 0
    
    if j == m and cur == 0:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```この実装ではスキャンが完全にストリーミングされ続けるため、中間文字列は構築されません。 各文字は 1 回処理され、XOR は増分的に維持されます。 唯一の微妙な条件は、すべてを消費した後、$S$、未完成のセグメントは残りません。これは、次の文字に対応できない追加の部分マージを意味するからです。$T$。

 ## 特殊なケース

 次のような最小限の文字列`S = 0, T = 0`最初の XOR がすでにターゲットと一致しているため、アルゴリズムが単純な単一セグメントのケースを正しく受け入れることを確認します。 

のようなケース`S = 10, T = 1`は、XOR パターンがローカルで互換性があるように見えても、追加のマージがなければ残った構造を消去できないため、セグメンテーションではターゲットに一致する単一のクリーンなブロックを生成できないことを示しています。 

のようなケース`S = 1111, T = 0`完全な累積動作を実行します。実行中の XOR は交互に行われますが、適切な数のセグメントで正確に終了するクリーンなパーティションに自然に整列することはありません。最後のセグメントが閉じられていない場合、アルゴリズムはそれを正しく拒否します。
