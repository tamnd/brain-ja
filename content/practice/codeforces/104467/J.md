 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられ、考えられるすべての重複位置でそれらを比較するように求められます。 シフトごとに、最初の文字列の文字が 2 番目の文字列の文字と一致する文字ペアの数を数えます。 これにより、すべてのアライメントにわたる一致数の配列が生成されます。 

配列全体を出力する代わりに、配列を多項式のように扱うことで単一の数値に圧縮します。各位置は、固定基数のべき乗を乗算した一致数に寄与します。$M$、すべてが大きな素数を法として計算されます。 

したがって、このタスクは本質的に、畳み込みのようなマッチング問題と、それに続く畳み込み結果の加重和です。 

制約は大きく、各文字列は最大で$5 \cdot 10^5$。 直接$O(nm)$までの時間が必要となるため、位置合わせは不可能です。$2.5 \cdot 10^{11}$比較。 たとえ$O(n \log n)$FFT ベースの畳み込みは許容されますが、26 文字の分解と多項式変換を慎重に実装した場合に限ります。 

単純なアプローチを破るエッジ ケースは、通常、インデックス付けの誤解、またはループ内で直接畳み込みを計算しようとすることから発生します。 たとえば、両方の文字列が同一の場合、すべての対角要素が大きく寄与し、単純なシフトベースの比較は依然として 2 次形式になります。 もう 1 つのよくある失敗は、シフトごとに完全な文字列の同等性をチェックするだけでなく、貢献をすべての文字にわたって個別に集計する必要があることを忘れていることです。 

## アプローチ

 ブルートフォースソリューションでは、各アライメントオフセットを修正し、両方の文字列をスキャンして一致をカウントします。 シフトごとに、以下を比較します。$O(n)$文字があり、$O(n)$変化し、$O(n^2)$。 これは上限に達するとすぐに失敗します。 

重要な観察は、答えの各位置が独立しており、文字の上に合計として書くことができるということです。 文字ごとに$c$、バイナリ配列を取得します$S$どこにマークを付けるか$c$が表示され、別の反転されたバイナリ配列が表示されます。$T$。 すべての配置位置に対するその文字の寄与は、これら 2 つの配列の畳み込みです。 26 文字すべてを合計すると完全な配列が得られます$A$。 

取得したら$A$、圧縮された値がまだ必要です。$$ans = \sum A_i M^{i-1}$$これは、畳み込み累積中に直接組み込むことも、後で線形時間で適用することもできます。 

単純な位置合わせから畳み込みへの移行は、「シフトの下で一致する文字をカウントする」ことはまさにインジケーター ベクトル間の相互相関であることを認識することから始まります。

 | FFT ベースの畳み込み |$O(26 \cdot n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 マッチング問題を多項式乗算に変換します。 

### 1. 各文字を個別にエンコードする

 文字ごとに$c$、2 つのバイナリ配列を構築します。 

1 つはポジション用で、$S[i] = c$、および 1 つはポジション用です。$T[i] = c$、しかし逆転。 畳み込みでシフトを正しく揃えるためには、反転が必要です。 

### 2. 文字ごとに畳み込みを実行する

 これら 2 つの配列の畳み込みを計算します。 各畳み込み結果が文字に寄与する回数$c$各位置合わせオフセットで一致します。 

これが機能するのは、畳み込みがすべてのペアの積の合計を自然に計算するためです。$i + j = k$、これはシフトされた配置インデックスに正確に対応します。 

### 3. グローバル一致配列に蓄積する

 26 文字すべてからの寄与を単一の配列に合計します。$A$。 今$A[k]$シフト時に一致する文字ペアの数を表します$k$。 

### 4. 最終的な加重和に変換する

 いっぱいに保存するのではなく、$A$、私たちは蓄積します:$$ans += A[k] \cdot M^k$$与えられた素数を法とする。 の力$M$は事前に計算されます。 

### 5. 結果を返す

 最終的な累積値は、必要な圧縮畳み込み結果です。 

### なぜ効果があるのか

 等しい文字の各ペアは、正確に 1 つの配置位置に 1 回だけ寄与します。 畳み込みにより、そのような各ペアが正しいシフト インデックスでカウントされることが保証され、すべての文字を合計することで問題が独立した線形部分問題に分割されます。 最終的な加重合計は、正確さを維持しながら、その畳み込み出力を決定論的に変換したものにすぎません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

def fft(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(G, (MOD - 1) // length, MOD)
        if invert:
            wlen = pow(wlen, MOD - 2, MOD)

        i = 0
        while i < n:
            w = 1
            for j in range(i, i + length // 2):
                u = a[j]
                v = a[j + length // 2] * w % MOD
                a[j] = (u + v) % MOD
                a[j + length // 2] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def multiply(a, b):
    n = 1
    while n < len(a) + len(b):
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))

    fft(fa, False)
    fft(fb, False)

    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD

    fft(fa, True)
    return fa

def solve():
    s = input().strip()
    t = input().strip()
    m = int(input())

    n = len(s)
    rev_t = t[::-1]

    ans = 0
    powm = [1] * (n + len(t))
    for i in range(1, len(powm)):
        powm[i] = powm[i - 1] * m % MOD

    for c in range(26):
        cs = [0] * n
        ct = [0] * len(t)

        for i in range(n):
            if ord(s[i]) - 97 == c:
                cs[i] = 1
        for i in range(len(t)):
            if ord(t[i]) - 97 == c:
                ct[len(t) - 1 - i] = 1

        conv = multiply(cs, ct)

        for i in range(n + len(t) - 1):
            ans = (ans + conv[i] * powm[i]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 エッジ ケースの 1 つは、1 つの文字列の長さが 1 である場合です。その場合、畳み込みはすべての位置にわたる直接の等価性チェックに退化します。 すべてのシフトが単一の乗算に還元されるため、FFT 定式化は引き続き機能します。 

もう 1 つの特殊なケースは、一致する文字が存在しない場合です。 すべての畳み込みはゼロ配列になり、最終的な答えはゼロのままです。これは、特別なケースなしで累積によって自然に処理されます。 

3 番目のケースは、両方の文字列が同一で均一である場合です。 すべてのシフトにより最大のオーバーラップが生成され、畳み込みによりカウントの三角形の形状が生成されます。 FFT は、明示的なシフト列挙を必要とせずに、合計多項式積を通じてこれを正確に取得します。
