 ## 解決策
 ## 問題の理解

 日々の価格変化の配列が与えられます。各値は、株価がある日から次の日までどのように変動するかを表します。 このシーケンスから、位置で終わるスライディング ウィンドウを繰り返し確認します。`i`最大でスパン`M`要素。 あらゆるポジションについて`i`、セグメントのみを考慮します`A[max(1, i-M+1) ... i]`。 

このような各ウィンドウ内で、最悪の継続的減少セグメントを見つけたいと考えています。 減少セグメントは、合計が可能な限り負になる連続した部分配列ですが、最も深刻な減少のみを考慮します。 すべての部分配列が負でない場合、答えはゼロとして定義されます。 

したがって、すべてのウィンドウについて、部分配列の合計の最小値を計算し、その最小値が正またはゼロの場合は、それをゼロにクランプします。 

これは本質的に古典的な「部分配列の最大合計」問題のスライディング ウィンドウ バージョンですが、上向きのゲインではなく下向きの動きを最大化している点が異なります。 

制約`N ≤ 100000`そして`M ≤ N`これは、位置ごとに答えを最初から再計算するソリューションは遅すぎることを意味します。 すべてのウィンドウにわたる二次アプローチでは、最大約`10^10`限界をはるかに超えた最悪の場合の操作。 償却された線形または線形に近い構造が必要です。 

いくつかの微妙な特殊なケースが重要です。 

すべての非負の値を含むウィンドウは出力する必要があります。`0`。 たとえば、次の場合`A = [1, 2, 3]`そして`M = 2`、どのウィンドウでも有効な辞退は生成されないため、すべての答えは次のようになります。`0`。 

最悪の下落が完全なプレフィックスまたはサフィックスではなく、内部セグメントであるウィンドウは、正しく処理する必要があります。 たとえば、`[-3, -5, 2, -3]`、最悪の下落は`[-3, -5]`、完全な配列ではありません。 

素朴な間違いは、最悪の下落が常に接尾辞の合計または接頭辞の合計であると仮定することです。 これは、最適なセグメントが内部にある混合符号配列では失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 インデックスごとに`i`、最後を取ります`M`で終わる要素`i`そして、そのウィンドウ内で考えられるすべてのサブ配列を試します。 各部分配列について、その合計を計算し、最小値を追跡します。 

これは、考えられるすべての連続セグメントを明示的にチェックするため、正しいです。 ただし、最大サイズの各ウィンドウ内では、`M`、 がある`O(M^2)`サブアレイ。 全体`N`窓の場合はこうなります`O(NM^2)`最悪の解釈でも、あるいは`O(NM)`プレフィックス合計を使用して部分配列の合計計算を最適化すると、両方が一致する場合でもまだ大きすぎます。`10^5`。 

重要な観察は、各ウィンドウが最小の​​サブ配列の合計を要求しており、これは最大のプレフィックスの差に相当するということです。 プレフィックス合計を定義すると`S[i] = A[1] + ... + A[i]`、その後任意の部分配列の合計`A[l..r]`は`S[r] - S[l-1]`。 これを最小限に抑えることは修正することと同じです`r`そして最大値を見つける`S[l-1]`許容範囲内です。 

したがって、各ウィンドウはプレフィックス合計に対するスライディング ウィンドウの最大値を維持することになりますが、最後のインデックス内のプレフィックス インデックスのみという制限があります。`M`ポジションは許可されます。 これはデータ構造の問題になります。スライディング ウィンドウで最大プレフィックス合計を維持し、計算する必要があります。`S[i] - max_prefix`。 

ただし、微妙な複雑さがあります。ウィンドウは動的に変化します。`i`, したがって、プレフィックス インデックスは有効な範囲に入ったり、有効な範囲から外れたりします。 これはまさに単調なデキュー シナリオであり、最大プレフィックス合計の候補を降順で保持します。 

最終的な答えは`i`は：`min_subarray_sum = S[i] - max_{j in window}(S[j-1])`、正の場合はゼロにクランプされます。 

プレフィックス合計のインデックスのデックを維持し、プレフィックス値が減少していることを確認し、また、ウィンドウ外のインデックスが削除されていることを確認します。

 | ブルートフォース | O(N·M²) | お(1) | 遅すぎる |
 | 最適 (プレフィックス + 両端子) | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題をプレフィックスの合計に変換し、プレフィックス インデックス上のスライド構造を維持します。 

### ステップ

 1. プレフィックス合計を構築する`S`どこ`S[0] = 0`そして`S[i] = S[i-1] + A[i]`。 

これにより、差分を使用して部分配列の合計を定数時間で計算できます。 
2. ポジションごとに`i`、最後のサブ配列のどこかで終わる最小のサブ配列の合計が必要です。`M`要素。選択に対応します。`j`で`[i-M, i-1]`プレフィックスインデックスの場合`j`。 
3. のインデックスのデックを維持します。`S`これらは、現在のウィンドウの最大プレフィックス値の候補です。 

インデックスは昇順で保存されますが、プレフィックス値は降順で維持されます。 
4.加工前`i`、範囲外の両端キューの先頭からインデックスを削除します。 

具体的には、どのようなインデックスでも、`< i-M`はもう無効です。 
5. 新しいプレフィックスインデックスを挿入する場合`i-1`、プレフィックス値が以下のインデックスを両端キューの後ろから削除します。`S[i-1]`。 

将来のすべてのクエリでは、より大きなプレフィックスが優先されるため、これらは役に立ちません。 
6. クリーンアップ後、追加します`i-1`デクに。 
7. ウィンドウ内の最適な (最大の) プレフィックスは、両端キューの先頭にあります。 計算:`best = S[i] - S[deque[0]]`。 
8. もし`best > 0`、出力`0`、それ以外の場合は出力`best`。 

### なぜ効果があるのか

 デキューは、そのフロントに、現在のウィンドウ内のすべての有効なインデックスのうち最大のプレフィックス合計を持つインデックスが常に格納されるという不変条件を維持します。 新しいインデックスよりもプレフィックスの合計が小さいインデックスは、位置の制約が劣っていて古いか等しいため、再び最適になることはありません。 これにより、すべてのクエリが一定時間内に応答され、すべてのインデックスがデキューに出入りするのは最大 1 回であることが保証され、線形の複雑さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # prefix sums
    ps = [0] * (n + 1)
    for i in range(n):
        ps[i + 1] = ps[i] + a[i]

    from collections import deque
    dq = deque()

    res = []

    for i in range(1, n + 1):
        # window for prefix indices: [i-m, i-1]
        left = i - m
        if left < 0:
            left = 0

        # remove out of range indices
        while dq and dq[0] < left:
            dq.popleft()

        # add prefix index i-1
        idx = i - 1
        while dq and ps[dq[-1]] <= ps[idx]:
            dq.pop()
        dq.append(idx)

        best_prefix = ps[dq[0]]
        best = ps[i] - best_prefix

        if best > 0:
            best = 0
        res.append(str(best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```プレフィックス合計配列を使用すると、定数時間のサブ配列合計評価が可能になります。 デキューは、次で終わる負の部分配列の最適な開始点の候補を保持します。`i`。 重要な点は、配列インデックスではなくプレフィックス インデックスを保存し、常に`i-1`最新の候補プレフィックス エンドポイントとして。 

外部のインデックスの削除`[i-m, i-1]`ウィンドウ制約が確実に尊重される一方、単調除去により潜在的に最適なプレフィックス和のみが残ることが保証されます。

 ## 特殊なケース

 単一要素ウィンドウは次の場合に発生します。`M = 1`。 唯一の部分配列はそれ自体であるため、アルゴリズムは要素が負であるかどうかをチェックすることに帰着します。 プレフィックス/デキュー方式は、プレフィックス インデックスのウィンドウが単一のポイントになるため、引き続き機能します。`S[i] - S[i-1]`正しく収穫する`A[i]`。 

すべての値が負でない場合、プレフィックスの合計は厳密に増加するため、すべてのウィンドウの最大プレフィックスが常に最も古い有効なインデックスになります。 計算された部分配列の合計は非正になるため、クランプにより一貫してゼロが生成されます。 両端キューは引き続き正しく更新されますが、結果の構造は決して変更されません。 

すべての値が負の場合、最大のプレフィックスは常に最小の負のプレフィックス、通常はウィンドウ内で最も古いプレフィックスになります。 これにより、累積的な最悪のセグメントに一致する一連の回答が着実に減少していきます。 両端キューではプレフィックスの降順が保持されますが、すべての候補は範囲外にスライドするまで関連性が維持されるため、アルゴリズムはこれを処理します。
