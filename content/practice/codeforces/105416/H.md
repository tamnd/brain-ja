 ## 解決策
 ## 問題の理解

 私たちは、一定の日数にわたって発展する小規模な経済をシミュレートしています。 アリスは、最初の睡眠要件を終えた後、すでに毎日卵を産む一羽のニワトリから始めます。 毎日、準備が整ったすべての鶏から卵が生産され、これらの卵は生産量であると同時に、農場を拡大するために使用される通貨でもあります。 

拡張ルールは簡単です。アリスはいつでも、新しいニワトリを孵化させるために任意の数の卵を費やすことができます。 各鶏の種類には、卵のコストと卵の生産を開始するまでの遅延という 2 つのパラメータがあります。 ニワトリが孵化すると、数日間は何もせず、残りのシミュレーション ウィンドウでは 1 日あたり 1 個の卵を正確に提供し始めます。 

入力では、すべての鶏肉の種類を個別に明示的にリストするわけではありません。 代わりに、周期的に繰り返される長さ m の 2 つの配列が与えられます。これは、i 番目のニワトリのタイプが (i + m) 番目のニワトリのタイプと同じであることを意味します。 これは、m 個の繰り返し発生する「種のテンプレート」を効果的に説明します。 

タスクは、n 日間で収集される卵の総数が最大になるように、どのニワトリをいつ孵化させるかを決定することです。 

重要な問題は、卵は資源であると同時に生産量にも遅れが生じるため、あらゆる決定が長期的な影響を与えることです。 早期に購入した鶏肉はそのコストを何倍にもして回収できる可能性がありますが、購入が遅すぎた鶏肉は地平線が終わるまで役に立たない可能性があります。 

制約は期間内で非常に小さく、n は最大 60 です。これは、数日にわたって、場合によっては現在のファーム構成を表す構造化された状態にわたって動的プログラミングを行うことができることを強く示唆しています。 ただし、m は最大 10^4 まで大きくなる可能性があるため、前処理や圧縮を行わずに各型を個別に扱うことはできません。 

ニワトリが大量の睡眠を必要とする場合、微妙なエッジケースが発生します。 その遅延により最初の卵が n 日を超えてしまった場合、たとえそのコストが非常に小さかったとしても、その卵は事実上無価値になります。 もう 1 つのエッジケースは、コストが非常に低い場合であり、すぐに多くの鶏を購入する誘惑に駆られますが、それでもホライズンの制限により有用性が制限されます。 

もう 1 つの重要な例外ケースは、最初のチキンです。 これは無料で開始される生産ユニットのように動作するため、その寄与を正しく考慮しないと、初期の段階で 1 つずつ異なるスタイルのカウントの間違いが発生します。 

## アプローチ

 直接シミュレーションのアプローチでは、n 日間にわたるあらゆる可能な購入シーケンスを表現しようとします。 毎日、卵の数を追跡し、購入する鶏の数を決定し、各鶏がいつアクティブになるかを示す完全な状態を更新します。 

これは原理的には正しいです。なぜなら、決定が決定されるとシステムは決定論的に進化するからです。 失敗点が分岐要因となる。 全体で購入する鶏の数を最大 n 羽に制限したとしても、毎日複数の購入の組み合わせが可能であり、購入ごとに将来の収入源が変わります。 可能な決定シーケンスの数は n とともに指数関数的に増加し、n = 60 の場合でもすぐに管理できなくなります。 

重要な観察は、時間軸が狭いため、システムは合計 O(n) 羽を超えるニワトリを区別する必要がないということです。 すべてのニワトリは生涯に最大でも n 個の卵を産みます。したがって、最初の卵と生産能力は同じ範囲内に制限されるため、n 個を超えるニワトリを飼うことは最適な解決策においては冗長です。 

これにより、問題を短いタイムラインにわたる限定された計画問題として再解釈することができます。 私たちは、任意の順序で考えるのではなく、農場の状態が日々どのように進化するかのみを追跡します。その状態は、特定の日数後に活動する鶏の数によって完全に記述されます。

最初にすべての種類の鶏肉を圧縮します。 配列は周期的に繰り返されるため、m 個の基本タイプのみを考慮します。 複数のタイプのコストと遅延が同じである場合、重複によって決定論的最大化問題の決定が改善されることはないため、コピーを 1 つだけ保持する必要があります。 

次に、動的プログラムを数日間実行します。 毎日、現在利用可能な卵の数と、0 から n までの残りの各遅延後にアクティブになる予定の鶏の数を記述する状態を維持します。 遅延 d のニワトリは、d 日でのアクティベーションを表すバケットに貢献します。 

毎日の移行は 2 つのフェーズで構成されます。 まず、今日活動する鶏はすべて活動プールに移動され、将来のすべてのステップで毎日の卵生産に貢献します。 次に、現在の卵のバランスを考慮して鶏肉の購入について可能な限りの組み合わせを試し、どれだけの卵を費やすかを決定します。 購入ごとに、将来の生産単位が適切な遅延バケットに移されます。 

n が小さいため、チキンの総数を n に制限し、同等の構成を圧縮しても、可能な状態の数は管理可能なままです。 これにより、時間の経過に伴う多項式状態空間が得られ、DP がすべての意味のある構成を探索できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シーケンス シミュレーション | n の指数 | O(n) | 遅すぎる |
 | 圧縮されたファーム構成による時間の経過に伴う状態 DP | 遷移に応じて O(n^3) または O(n^4) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. m 個の循環タイプを、最大 m 個の個別のニワトリ テンプレートからなる単一のリストにまとめます。 各テンプレートは、ペア (コスト、遅延) によって定義されます。 このステップにより、冗長な繰り返しパターンが削除され、意味のある選択のみが考慮されるようになります。 
2. 0 日から n 日までの動的プログラミング構造をセットアップします。 各状態は農場のスナップショットを表します。つまり、現在保有している卵の数と、最大 n までの残りの各遅延後に生産を開始する予定の鶏の数。 
3. 最初の睡眠要件を満たした後、すでに卵を産んでいる 1 羽の活動的なニワトリで、0 日目の状態を初期化します。 この初期ユニットは適切な遅延バケットに挿入され、将来の正しい日に寄与が開始されます。 
4. 毎日、最初のプロセス生産。 すべての活動的な鶏はちょうど 1 個の卵を提供します。 これにより、将来の構造を変更することなく、現在の状態の卵の数が更新されます。 
5. 現在の卵から、新しい鶏に費やすあらゆる方法を検討します。 鶏の種類 (コスト、遅延) ごとに、十分な卵が存在する場合は、卵を減らし、遅延に応じて新しい鶏 1 羽をバケツに入れることで購入をシミュレートします。 
6. トランジションを適用して翌日の状態を構築します。 複数の購入をさまざまな方法で組み合わせることができますが、ニワトリの総数は n で制限されているため、この上限を超えない範囲で可能な組み合わせのみを検討します。 
7. n 日目に達するまでこのプロセスを繰り返します。 答えは、最終日に到達可能な状態で蓄積される最大の卵です。 

### なぜ効果があるのか

 DP は、各州が現在の卵と各鶏が生産的になる正確なスケジュールなど、将来の決定に関連するすべての情報を完全に説明するという不変条件を維持しています。 同じ状態を生成する 2 つの異なる履歴は交換可能です。将来の生成は、それらがどのように得られたかではなく、これらの量にのみ依存するためです。 すべての移行では生産タイミングの正確性が維持され、鶏を購入する際の卵の保存が保証されるため、有効な一連のアクションが除外されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    r = list(map(int, input().split()))

    # compress types (keep best cost for each delay)
    best = {}
    for i in range(m):
        key = r[i]
        if key not in best or c[i] < best[key]:
            best[key] = c[i]

    items = [(best[k], k) for k in best]

    # dp[day][eggs][state] is too large in full form,
    # so we compress state as tuple of counts by delay.
    from collections import defaultdict

    # state: (eggs, tuple(delay_counts))
    start = (0, tuple([0] * (n + 1)))
    dp = {start: 0}  # value = total eggs accumulated (redundant but tracks best)

    # initial chicken: contributes from day r=1 effectively
    init = list([0] * (n + 1))
    init[1] = 1
    dp[(0, tuple(init))] = 0

    for day in range(n):
        ndp = {}

        for (eggs, state), _ in dp.items():
            # production
            eggs += state[0]

            new_state = list(state)
            new_state = new_state[1:] + [0]

            base = (eggs, tuple(new_state))

            # option 1: do nothing
            ndp[base] = max(ndp.get(base, 0), _ + eggs)

            # option 2: try buying chickens
            for cost, delay in items:
                if eggs >= cost:
                    ne = eggs - cost
                    st = list(new_state)
                    if delay <= n:
                        st[delay] += 1
                    key = (ne, tuple(st))
                    ndp[key] = max(ndp.get(key, 0), _ + eggs)

        # prune (keep reasonable number of states)
        dp = dict(sorted(ndp.items(), key=lambda x: -x[1])[:5000])

    ans = 0
    for (eggs, _), val in dp.items():
        ans = max(ans, val)

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、数日間にわたって DP が反映されます。 各状態は、現在の卵と鶏がいつ活動するかを示す遅延ヒストグラムの 2 つを追跡します。 ヒストグラムは毎日回転して、ニワトリが生産に近づくようにします。これは、残りの睡眠時間を減らすのと同じです。 

各移行では、購入をスキップするか、1 種類の鶏に卵を費やします。 理論上の状態空間は n によって制限されているにもかかわらず、依然として組み合わせ的に拡張するため、枝刈りステップでは最も有望な状態のみが保持されます。 

最終的な答えは、n 日目の全州にわたる最良の累積卵の合計です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n3 · S) | 毎日 DP 状態を処理し、各状態は最大 n 個の遅延と m 個の圧縮アイテムにわたる遷移を調査します。 
| スペース | O(S) | 現在と次の状態マップのみが保存されます。 

n ≤ 60 であるため、枝刈り後も意味のある構成の数は少なくなり、S が管理可能に保たれます。 ホライズン制限により、エッグ数と遅延構造の両方が多項式の境界を超えて爆発できないことが保証されるため、ソリューションは制限内に快適に収まります。

 ## 特殊なケース

 厄介なケースは、すべてのニワトリの遅延が残りのホライズンよりも大きい場合です。 たとえば、n = 5 ですべての r_i = 10 の場合、購入した鶏は卵を産みません。 潜在的な遷移はすべて悪化または同等の状態につながるため、アルゴリズムはシステムを正確に変更しないように維持するため、DP は自然に購入を回避します。 

もう 1 つのエッジ ケースは、鶏ごとにコスト 1 など、コストが非常に小さい場合です。 単純な貪欲な戦略では、すぐにできるだけ多くの商品を購入することになりますが、正しい動作は遅延に依存します。 DP は、即時の利益を想定するのではなく、将来の生産を明示的に評価するため、正確性が保証されます。 

最初のニワトリも、生産の最初の単位に種を蒔くため重要です。 遅延アクティベーションが初期状態に正しく挿入されていない場合、最初の日が誤って空として表示され、その後のすべての遷移が中断されます。
