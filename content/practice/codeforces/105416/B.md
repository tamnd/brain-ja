 ## 解決策
 ## 問題の理解

 私たちは卵のコレクションを与えられますが、各卵が完全に調理されるまでには特定の時間がかかります。 ジェイコブには合計時間の予算が固定されており、鍋は 1 つしかありません。つまり、重複せずに一度に調理できる卵は 1 つだけです。 卵を調理し始めたら、別の卵に移る前に、調理時間をすべてその卵に費やさなければなりません。 

課題は、可能な限り最善の方法でスケジュールを設定した場合に、完全に調理できる卵の数を決定することです。 彼が持つ主な自由は卵を調理する順序であり、目標は、利用可能な合計時間内で完成した卵の数を最大化することです。 

卵の数の制約は最大 100,000 個ですが、時間値と合計時間は 20 億に及ぶ可能性があります。 これにより、すべての順列を試行したり、すべてのサブセットを明示的にシミュレートしたりするアプローチは即座に除外されます。 たとえ$O(n^2)$スキャンや選択を繰り返す場合、このアプローチは遅すぎます。 

卵を入力順に摂取すれば十分だと考えると、当然の落とし穴が生じます。 たとえば、入力が次の場合:```
t = 10
c = [9, 1, 1]
```順番に調理すると、ほぼ常に9個消費されるため、卵は1個しか得られません。 しかし、最適な選択は、最初に 2 つの小さな卵を取り、合計 2 つの卵を与えることです。 これは、順序付けが不可欠であることを示しています。 

もう 1 つの微妙なエッジ ケースは、合計時間が組み合わせと正確に一致する場合です。```
t = 6
c = [4, 2, 2]
```正しい戦略を使えば 3 つすべてを調理できますが、単純な順序による貪欲なアプローチでは、4 つが最初に取られると失敗する可能性があります。 

したがって、本当の問題は、合計が制限を超えない範囲でできるだけ大きな調理時間のサブセットを選択することです。$t$、選択した要素の数を最大化しながら。 

## アプローチ

 最も直接的なアイデアは、卵のすべてのサブセットを試し、その合計調理時間を計算し、時間内に収まる最大のサブセットを追跡することです。 これは、すべての可能性を明示的に評価するため、正しいです。 ただし、サブセットの数は指数関数的に増加します。$2^n$、そしてさらには$n = 100000$、これはまったく不可能です。 サイズの組み合わせも限定$k$does not help, since iterating all combinations still explodes.

 より構造化された観察は、卵のセットが実行可能かどうかを実際に決定するものに注目することから生まれます。重要なのは調理時間の合計だけであり、順序ではありません。 各エッグは合計時間にプラスの影響を与えるため、できるだけ多くのエッグを適合させる最善の方法は、選択した各エッグ セット サイズの総コストを最小限に抑えることです。 That naturally suggests picking the smallest cooking times first.

 調理時間を短縮しない順に並べ替えると、卵を最小のものから上に向かって取得することにより、どの接頭辞についても、最小の合計時間で卵の数が最大化されることが保証されます。 この順序から逸脱すると、より小さいか等しいコストがより大きいコストに置き換えられ、制限時間内に収まる卵の数が減るだけです。 

Once sorted, we simply accumulate times from left to right until adding another egg would exceed the budget. The prefix length reached at that point is optimal.

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(2^n)$|$O(n)$| 遅すぎる |
 | ソート + 貪欲なプレフィックスの合計 |$O(n \log n)$|$O(1)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 卵の数を読み取る$n$合計利用可能時間$t$、次に調理時間のリストを読みます。 これにより、リソースの制約と個別のコストが確立されます。 
2. 調理時間を昇順に並べ替えます。 このステップにより、入手可能な最も安価な卵を常に最初に検討するようになります。これは、予算内に収まる卵の数を最大化するために必要です。 
3. 2 つの変数を初期化します。これまでに使用された合計調理時間の累計と、調理された卵の数のカウンターです。 
4. ソートされた調理時間のリストを最短から最長まで繰り返します。 
5. 各卵について、調理時間を追加すると合計時間を超えるかどうかを確認します。$t$。 そうでない場合は、その時間を累計に加算し、カウンタを増分することにより、スケジュールに含めます。 
6. 現在の卵の追加が制限を超える場合は、すぐに中止してください。 それ以上の卵はさらに大きいか等しいため、制約に違反しない限り含めることはできません。 
7. 調理できる卵の最大数としてカウンターを出力します。 

重要な考え方は、一度大きな卵が入らなくなると、その後の卵も入らなくなるため、以前の決定を決して再考しないということです。 

### なぜ効果があるのか

 正確さは、すべての卵のコストが独立していて加算的であるという事実に依存しており、単一の合計制約の下でカーディナリティを最大化しています。 どのような最適解でも、よりコストの低い未使用のエッグが存在するときに、よりコストの高いエッグが選択された場合、それらを交換しても合計時間は増加せず、エッグの数も決して減りません。 このスワップ引数を繰り返し適用すると、最適なソリューションが、ソートされたリストのプレフィックスを選択するソリューションに変換されます。 このプレフィックスはまさに貪欲スキャンが構築するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    c = list(map(int, input().split()))
    
    c.sort()
    
    total = 0
    count = 0
    
    for x in c:
        if total + x <= t:
            total += x
            count += 1
        else:
            break
    
    print(count)

if __name__ == "__main__":
    solve()
```この解決策は、常に最小の残りコストが最初に処理されるように調理時間を並べ替えることから始まります。 これは、貪欲なアプローチを有効にする構造的変化です。 その後、ループは制約に違反するまで時間を蓄積します。 予算を超えると、並べ替えにより、その後のすべての値が少なくとも同じ大きさになるため、早めの休憩が重要です。 

よくある間違いは並べ替えを忘れることです。貪欲な仮定は昇順に完全に依存しているため、すぐに正しさが失われます。 もう 1 つの問題は、早期に停止しないことです。これは正確性のためには不要ですが、パフォーマンスがわずかに低下する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, t = map(int, input().split())
    c = list(map(int, input().split()))
    c.sort()
    total = 0
    count = 0
    for x in c:
        if total + x <= t:
            total += x
            count += 1
        else:
            break
    return str(count)

# provided samples
assert run("3 10\n9 1 1\n") == "2", "sample 1"
assert run("5 10\n2 2 2 2 2\n") == "5", "sample 2"

# custom cases
assert run("1 5\n10\n") == "0", "cannot cook any egg"
assert run("4 100\n1 2 3 4\n") == "4", "all fit easily"
assert run("4 5\n4 4 4 4\n") == "1", "only one fits"
assert run("6 7\n5 1 1 1 1 1\n") == "4", "prefix selection after sorting"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 5 / 10 | 0 | 実行可能な選択がありません |

 ## 特殊なケース

 重大なエッジケースは、卵がまったく調理できない場合です。 入力の場合:```
n = 1, t = 3
c = [10]
```ソート後、最初の要素がすでに予算を超えています。 ループはカウンタをインクリメントせずにすぐに中断し、0 を生成します。これにより、アルゴリズムが完全な実行不可能性を正しく処理していることが確認されます。 

もう 1 つのエッジケースは、すべての卵が同一であり、予算の倍数に正確に適合する場合です。 のために：```
n = 3, t = 6
c = [2, 2, 2]
```並べ替えるとリストは変更されません。 アルゴリズムは各卵を順番に追加し、正確に 6 に達します。等しいことが許可されるため、3 つの卵すべてが含まれます。 これは、オーバーフローや途中で停止することなく合計が制限に正確に一致する境界等価条件の正しい処理を示しています。
