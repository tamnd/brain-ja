 ## 解決策
 ## 問題の理解

 各エッジに沿った移動には、旅行者に応じて 2 つの異なるコストがかかる有向グラフが与えられます。1 つは「鶏」のコスト、もう 1 つは「卵」のコストです。 どちらも、出口ノードにできるだけ早く到達することだけを考慮しており、ノードに到達すると最適に動作します。つまり、(自身のエッジ コストを考慮して) 可能な限り最速のパスを常に選択します。 

実験はこんな感じで行われます。 ニワトリの場合、一連の入口から均一にランダムに開始ノードを選択し、ニワトリが出口に到達するまでに必要な最短時間を計算します。 卵については、同じプロセスを独立して繰り返し、再び均一でランダムな入口を選択し、出口までの最短時間を計算します。 開始ノードがどの出口にも到達できない場合、移動時間は事実上無限となり、その実行は未完了とみなされます。 

タスクは、この方法で両方を独立してサンプリングした場合に、どちらがより早く終了する可能性が高いかを判断することです。 形式的には、同じ入口セットに対して定義された 2 つの確率変数を比較します。鶏の重みの下での出口までのニワトリの最短経路距離と、卵の重さの下での卵の最短経路距離です。どちらも均一なランダムな開始入口によって引き起こされます。 

グラフは大きく、最大 200,000 のノードとエッジがあります。 これにより、クエリごとまたは入り口のペアごとに最短パスを再計算するものはすべて即座に除外されます。 開始ノードごとに最短パス アルゴリズムを 1 回実行するだけでも遅すぎます。 ソリューションは、「重み付けシステム」ごとに線形または線形に近い時間で最短経路情報をグローバルに計算する必要があります。 

一部の入口がどの出口にも到達できない場合、微妙な問題が発生します。 これらのノードは無限の距離に寄与します。 「無限対有限」の比較が確率空間を支配し、両方が無限である場合の同点は一貫して処理する必要があるため、無限を無視した単純な比較は正確性を静かに破る可能性があります。 

複数の入口が同じ最短距離を共有する場合、別の特殊なケースが発生します。 入口のペアにわたる確率を比較するため、等しい距離は鶏にも卵にも有利には寄与しませんが、それでも正しくカウントする必要があります。そうしないと、最終的な比較が誤ってシフトします。 

## アプローチ

 直接シミュレーションでは、鶏と卵の開始点を選択し、毎回最短パスを実行し、結果を比較します。 各入口からの最短経路を個別に事前計算したとしても、それは依然として$O(a \cdot (m \log n))$、両方の場合、限界をはるかに超えています。$a$そして$m$大きいです。 

重要な観察は、構造が 2 つの独立した最短経路問題に明確に分離されていることです。 各ノードについては、そのノードから出口までの最小距離のみが必要です。 これは、反転グラフ上の古典的な複数ソース最短経路問題です。すべての出口から開始してダイクストラを実行し、距離を後方に累積します。 これを 2 回実行し、1 回目は鶏の重みを使用し、もう 1 回目は卵の重みを使用して、2 つの配列を生成します。`distC[u]`そして`distE[u]`。 

注目を入口ノードに限定すると、確率プロセス全体が純粋な組み合わせ比較に崩壊します。 各実験は、複数の集合から一様に値を引き出すことと同じです。ニワトリは、次の複数の集合から値を引き出します。`distC`入り口よりも値が高く、卵はそこから描画されます`distE`。 ニワトリが勝つ確率はまさにペアの割合です$(i, j)$そのような`distC[i] < distE[j]`。 

これにより、問題は 2 つの配列間のペアごとの比較をカウントすることになります。 両方の配列をソートすると、二分探索または 2 ポインター スイープで効率的に計算できます。 鶏と卵の勝ちペアの数の差が答えを決定します。

 ## アルゴリズムのチュートリアル

 距離を計算し、次に入口分布を比較するという 2 つのフェーズでソリューションを構築します。 

### 1. 逆向きのグラフを作成する

 すべてのエッジを反転して、「出口に向かって」歩くことがソースからの標準的な最短経路問題になるようにします。 

外側の出口からではなく、すべてのノードから出口までの距離が必要なため、反転が必要です。 

### 2. ダイクストラを実行して鶏の重量を取得します

 すべての出口を距離ゼロの開始点として初期化し、反転グラフのチキンエッジコストを使用してダイクストラを実行します。 これにより、すべてのノードから任意の出口までの最小チキン時間が計算されます。 

同じプロセスが卵の重さに対して独立して繰り返されます。 

### 3. 進入距離の抽出

 各入口ノードについて、計算された距離を 2 つの配列に収集します。 

1 つは鶏用、もう 1 つは卵用です。 ノードがどの出口にも到達できない場合、その距離は無限大のままです。 

これらの配列は、ランダム実験の完全な結果空間を表します。 

### 4. 両方の配列をソートします。 

鶏と卵の距離配列を並べ替えます。 相互比較を効率的にカウントするには、並べ替えが必要です。 

順序付けにより、ペアのカウントの問題が、しきい値を超えるプレフィックスのカウントに変わります。 

### 5. 勝ったペアを数える

 満たすペアの数を計算します`distC[i] < distE[j]`。 各鶏の値について、厳密に大きい卵の値がいくつあるかを見つけます。 これは二分探索を使用して行われます。 

対称数も計算します`distE[j] < distC[i]`どちらが優勢かを判断するため。 

### 6. 結果を比較する

 ニワトリがより多くのペアに勝った場合は、「ニワトリ」を出力します。 卵がより多くのペアに勝った場合は、「卵」を出力します。 それ以外の場合は「ネクタイ」を出力します。 

### なぜ効果があるのか

 それぞれの入り口は鶏と卵の両方に等しく発生し、2 つの選択肢は独立しています。 これにより、ニワトリが勝つ確率は、ニワトリの距離が卵の距離よりも厳密に小さい、順序付けられたすべての入口ペアの割合と等しくなります。 等しい距離は同点にのみ寄与し、優位性には影響しません。 確率空間全体が 2 つの有限マルチセットの比較に帰着するため、ソートによって必要な情報がすべて保存され、最短パスが計算された後は構造グラフ情報は必要ありません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = 10**30

def dijkstra(n, graph, starts):
    dist = [INF] * (n + 1)
    pq = []
    for s in starts:
        dist[s] = 0
        heapq.heappush(pq, (0, s))

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

n, m, a, b = map(int, input().split())

rev = [[] for _ in range(n + 1)]
edges = []

for _ in range(m):
    u, v, c, e = map(int, input().split())
    rev[v].append((u, c, e))
    edges.append((u, v, c, e))

starts = list(map(int, input().split()))
exits = set(map(int, input().split()))

# build two reversed graphs
gC = [[] for _ in range(n + 1)]
gE = [[] for _ in range(n + 1)]

for u, v, c, e in edges:
    gC[v].append((u, c))
    gE[v].append((u, e))

distC_full = dijkstra(n, gC, list(exits))
distE_full = dijkstra(n, gE, list(exits))

A = []
B = []

for s in starts:
    A.append(distC_full[s])
    B.append(distE_full[s])

A.sort()
B.sort()

# count A < B
j = 0
mB = len(B)
chicken_wins = 0
for x in A:
    while j < mB and B[j] <= x:
        j += 1
    chicken_wins += mB - j

# count B < A
j = 0
mA = len(A)
egg_wins = 0
for x in B:
    while j < mA and A[j] <= x:
        j += 1
    egg_wins += mA - j

if chicken_wins > egg_wins:
    print("chicken")
elif egg_wins > chicken_wins:
    print("egg")
else:
    print("tie")
```実装は、鶏と卵の重みに対して個別に逆隣接リストを構築することから始まります。 重みを混合すると 2 つの最短経路問題の独立性が破壊されるため、この分離が必要です。 

ダイクストラは 2 回実行され、毎回すべての出口ノードから同時に開始されます。 これにより、コストがかかりすぎるすべての入り口から最短経路を実行することが回避されます。 

距離を計算した後は、入口ノードの値のみを保持します。 これらは相互比較を効率的にカウントできるようにソートされています。 2 ポインター ロジックにより、並べ替え後の各比較が直線的な時間でカウントされることが保証されます。 

実装の微妙な詳細は、到​​達不能なノードの処理です。 これらは非常に大きなセンチネル値のままであり、自然にソートされた配列の最後に収まり、到達不可能な状態を含む比較が正しく動作することが保証されます。

import sys, io

def solve():
    import sys, heapq
    input = sys.stdin.readline
    INF = 10**30

    def dijkstra(n, g, starts):
        dist = [INF] * (n + 1)
        pq = []
        for s in starts:
            dist[s] = 0
            heapq.heappush(pq, (0, s))
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in g[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    n, m, a, b = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, c, e = map(int, input().split())
        edges.append((u, v, c, e))

    starts = list(map(int, input().split()))
    exits = set(map(int, input().split()))

    gC = [[] for _ in range(n + 1)]
    gE = [[] for _ in range(n + 1)]
    for u, v, c, e in edges:
        gC[v].append((u, c))
        gE[v].append((u, e))

    distC = dijkstra(n, gC, list(exits))
    distE = dijkstra(n, gE, list(exits))

    A = [distC[s] for s in starts]
    B = [distE[s] for s in starts]

    A.sort()
    B.sort()

    j = 0
    egg_wins = 0
    for x in B:
        while j < len(A) and A[j] <= x:
            j += 1
        egg_wins += len(A) - j

    j = 0
    chicken_wins = 0
    for x in A:
        while j < len(B) and B[j] <= x:
            j += 1
        chicken_wins += len(B) - j

    if chicken_wins > egg_wins:
        return "chicken"
    if egg_wins > chicken_wins:
        return "egg"
    return "tie"

 ## 特殊なケース

 重要なエッジ ケースは、一方または両方の旅行者が入口から出口に到達できない場合です。 その状況では、距離は無限大のままで、ソートされた配列の最後に配置されます。 ペアのカウント中、有限の値は常に無限大より小さいため、到達可能な出口を持つプレーヤーに結果が正しく偏ります。 

すべての入り口に到達できない場合、別の特殊なケースが発生します。 どちらの配列も完全に無限大で構成されているため、どちらの方向にも厳密な不等式は成立しません。 どちらの勝ち数もゼロのままであるため、アルゴリズムは正しく引き分けを返します。 

3 番目のケースは、多くの入口が同じ最短パス値を共有する場合です。 比較では厳密な等価性が使用されるため、等しい値がどちらの側にも寄与することはありません。 カウントロジックは次の場合にのみ前進します。`<=`が発生した場合は、重複してカウントされることなく、一貫して同点が除外されるようにします。
