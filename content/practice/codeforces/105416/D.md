 ## 解決策
 ## 問題の理解

 複数の小文字のセットが与えられています。 これらの文字はもともと、非常に強力な構造を持つ文字列から来ていました。それは回文であり、まったく同じ文字を使用して形成できるすべての回文の中で、辞書編集上最も小さいものでした。 

スクランブル後、順序は失われますが、文字数は変わりません。 タスクは、両方の制約を同時に満たす一意の文字列を再構築することです。文字列は回文である必要があり、指定されたマルチセットから構築できるすべての回文の中で辞書順で可能な限り最小のものでなければなりません。 

重要な観察は、入力では位置情報がまったく保持されないことです。 重要なのは周波数だけです。 これに気づくと、問題は文字数をめぐる制約された構成の問題になります。 

n が 10^5 までの制約は、すべての解が線形または線形に近いものでなければならないことを意味します。 ソートは O(n log n) で問題ありませんが、部分文字列に対する繰り返しの再計算や順列に対するバックトラックを伴うものは不可能です。 回文の構造は、複雑さを線形に保つために、文字列の半分だけを構築してそれをミラーリングする必要があることを強く示唆しています。 

微妙な特殊なケースは、複数の文字の頻度が奇数である場合です。 回文には、奇数カウントの文字を最大 1 つ含めることができます。 このステートメントは実現可能性を保証しているため、不可能性を検証する必要はありませんが、奇数周波数の文字を中心に正しく配置する必要があります。 

もう 1 つの落とし穴は、文字列全体をソートすると答えが直接得られると想定していることです。 たとえば、「racecar」では、ソートすると「aacce rr」が得られますが、これは回文にも程遠いものです。 構造は、並べ替えから出現するものではなく、明示的に適用される必要があります。 

## アプローチ

 強引なアプローチは、指定された文字のすべての順列を生成し、どれが回文であるかを確認し、その中から辞書編集的に最小のものを選択することです。 これは完全なソリューション空間を探索するため、概念的には正しいですが、規模の点ですぐに失敗します。 たとえ別個の順列のみに限定したとしても、配置の数は最悪の場合でも n で階乗になり、回文フィルタリングは指数関数的な性質を使用できるほど十分に低減しません。 n = 10^5 の場合、これはまったく実現不可能です。 

重要な構造的洞察は、回文はその前半と、オプションで中央の文字によって完全に決定されるということです。 文字のマルチセットを修正する場合、左半分にはちょうどフロア(n/2) 個の文字が含まれている必要があり、右半分はそのミラーとして強制されます。 したがって、問題は、頻度の制約を尊重し、残った奇数文字を中央に配置しながら、左半分に対して辞書編集上可能な最小のマルチセットを構築することに帰着します。 

辞書編集的な最小性を達成するために、残りの文字が有効なミラー半分を形成できるという要件を破ることなく、常に可能な限り多くの文字の出現を使用して、「a」から「z」までの左半分を貪欲に埋めます。 辞書編集上の順序は左から右に決定されるため、実現可能性が維持される限り、小さい文字を早く選択することが常に最適です。 

これにより、問題は順列問題ではなく貪欲な周波数割り当て問題に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列) | お(ん!) | O(n) | 遅すぎる |
 | 最適な貪欲なハーフ構築 | O(26 · n) ≈ O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず各文字の頻度を数えます。 これにより、入力が固定サイズの状態に圧縮されます。これは、元の順序を気にすることがなくなるため、非常に重要です。 

1. 周波数配列を計算する`cnt[26]`文字列内のすべての文字に対して。 これにより、使用可能なすべての情報が入力から取得されます。 
2. 左半分に属する文字数を計算します。`n // 2`。 回文は対称性を強制するため、中心の外側にあるものはすべて鏡映されます。 
3. 中央の文字が存在する場合は、それを特定します。 奇数の頻度を持つ文字は最大でも 1 つだけであるため、存在する場合はそれを選択します。 中央は、半分の順序制約には影響しません。 
4. 左半分を「a」から「z」まで貪欲に構築します。 各文字について、辞書順でできるだけ早く配置するように努めます。 ただし、利用可能なすべての出現を単純に取得することはできません。 左半分に文字を配置した後、残りのカウントが必要な右半分と一致していることを確認する必要があります。 
5. 各文字について、左半分に文字が必要な間は繰り返し取得しますが、取得中に残りの文字が左半分の残りを埋めることができるという要件に違反しません。 残りの合計容量がわかっているため、この条件では、実現可能性チェックを実行するのではなく、残っているスロットの数を追跡することが簡単になります。 
6. 左半分が構築されたら、左半分、中央の文字 (存在する場合)、および左半分の反転を連結することによって完全な回文が形成されます。 

正確かどうかは、辞書編集上の順序が 2 つの文字列が異なる最初の位置によって完全に決定されるという事実にかかっています。 左半分を最小文字から最大文字まで貪欲に埋めることにより、最初の異なる位置での最小性が保証されます。 

### なぜ効果があるのか

 左半分のすべての位置で、残りの位置を完了できる最小の文字を選択します。 残りのすべての文字は総数を除いて制約がなく、一致する数を超えた組み合わせの実現可能性の問題を解決していないため、貪欲な選択は安全です。 より大きな文字への逸脱は、結果として得られる回文の辞書編集上の値を即座に増加させますが、構築の後半でその増加を補償するメカニズムはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1
    
    left_len = n // 2
    left = []
    mid = ""
    
    for i in range(26):
        if cnt[i] % 2 == 1:
            mid = chr(i + 97)
            cnt[i] -= 1
    
    remaining = left_len
    
    for i in range(26):
        if remaining == 0:
            break
        take = min(cnt[i] // 2, remaining)
        if take > 0:
            left.append(chr(i + 97) * take)
            remaining -= take
    
    left = "".join(left)
    right = left[::-1]
    
    print(left + mid + right)

if __name__ == "__main__":
    solve()
```この解決策は、文字列を頻度カウントに折りたたみ、無関係な順序情報をすべて削除することから始まります。 中央の文字の選択は、奇数カウントの文字を消費することによって処理され、残りのすべてのカウントが確実に偶数になるようにします。これは対称性に必要です。 

左半分の構築では、直接的な貪欲な割り当てを使用します。「a」から「z」までの各文字に対して、残りの容量まで可​​能な限り多くのペアを割り当てます。 残りのカウンタは、半分の長さの制約を決して超えないことを保証します。 

最後に、左半分をミラーリングすることで、さらなる計算を行わずに回文構造が保証されます。 

微妙な点は、残りのスロットを追跡する以上に実現可能性を繰り返し確認する必要がないことです。 常にペアを消費しているため、パリティ制約は自動的に一貫した状態に保たれます。 

## 実用的な例

 ### 例 1: 「レースカー」

 頻度を計算します: a:2、c:1、e:1、r:2。 

中央の文字は奇数から選択されます。 'c' と 'e' のうち、辞書編集的に最小のものは 'c' または 'e' ですが、使用できるのは 1 つだけであり、中心として保持される 1 つを除いて両方を偶数のペアに減らすことで一貫性が保証されます。 

左半分の長さは3です。 

「a」から「z」までを入力します。 

| ステップ | シャア | 残りのスロット | アクション | 左 |
 | --- | --- | --- | --- | --- |
 | 1 | | 3→2 | 1ペア可能 | |
 | 2 | c | 2→2 | ペアリングをスキップ (奇数は後で処理) | |
 | 3 | e | 2→2 | ペアリングはスキップ | |
 | 4 | r | 2 → 0 | 1ペアを取る | ar |

 Middle は最小の有効な残りのセンターになります。ここでは奇数の処理によって決定されます。 最終結果は`acrerca`。 

これは、貪欲ペアリングがすべての文字を単純に並べ替えるのではなく、回文構造を強制する方法を示しています。 

### 例 2: 「aabbccdde」

 周波数: a2 b2 c2 d2 e1。 

左半分の長さは 4、中央は「e」です。 

| ステップ | シャア | 残りのスロット | アクション | 左 |
 | --- | --- | --- | --- | --- |
 | 1 | | 4→3 | 1ペアを取る | |
 | 2 | b | 3→2 | 1ペアを取る | アブ |
 | 3 | c | 2→1 | 1ペアを取る | ABC |
 | 4 | d | 1 → 0 | 1ペアを取る | ABCD |

 右ハーフミラーへ`dcba`、最後の文字列は`abcdedcba`。 

これは、以前の文字が常に最初に使い尽くされるため、貪欲な割り当てによって自然に辞書編集的に最小限の構造が得られることを裏付けています。 

## 複雑さの分析

 この解決策は入力の長さが線形であり、10^5 文字と 2 秒の制限の制約内に快適に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)

    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    left_len = n // 2
    left = []
    mid = ""

    for i in range(26):
        if cnt[i] % 2 == 1:
            mid = chr(i + 97)
            cnt[i] -= 1

    remaining = left_len
    for i in range(26):

        left.append(chr(i + 97) * take)
        remaining -= take

    left = "".join(left)
    return left + mid + left[::-1]

 ## 特殊なケース

 次のような単一文字列の場合`z`、アルゴリズムは直接生成します`z`中央が選ばれて左半分が形成されないからです。 周波数配列セット`mid = z`、両方の半分は空のままであるため、連結すると正しい結果が得られます。 

のような入力の場合`zzzaaa`、カウントは a3 z3 です。 1 文字が中心となり (両方とも候補ですが、使用されるのは 1 文字のみ)、残りの文字がペアになります。 左半分はこうなります`az`、ミラーリングにより生成される`azza`、実装の詳細に応じて中心が適切に埋められます。 貪欲なペアリングでは、「a」が常に「z」の前に配置されるため、辞書編集上の制約に違反することなく対称性が保証されます。 

すべての文字が同一である文字列の場合、次のようになります。`aaaaaa`、アルゴリズムは直接 2 つの半分に分割し、意思決定なしで完全な回文を生成します。これは、貪欲なロジックが均一なケースにきれいに退化することを示しています。
