 ## 解決策
 ## 問題の理解

 各位置が整数の高さを持つ 1 次元の風景が与えられます。 これは、高さの異なる一連の垂直列が並べて配置されたものであると考えてください。 雨が降ると、高い柱の間に水が閉じ込められ、下の柱の上に閉じ込められた水の「プール」が形成されることがあります。 

左側と右側の両方に高い境界または同等の境界がある場合、その場所は何らかのプールに属します。 プールの水位は、水が最初に弱い側にこぼれるため、境界となる 2 つの側のうちの低い側によって決まります。 各プールの体積は、その境界領域内の地形上に閉じ込められている水の量に等しくなります。 

このようなすべてのプールの中で、最も高い表面レベルを持つプールを見つけるように求められます。 複数のプールが同じ最大表面高さを共有する場合、それらの体積を合計します。 

入力サイズは最大 100,000 位置になるため、考えられるすべての左右の境界ペアを明示的に拡張しようとするソリューションは遅すぎます。 すべての区間にわたる 3 次または 2 次の列挙は実現不可能です。$O(n^2)$この規模ではすでに大きすぎます。 

厄介な点は、「プール」が単なる間隔ではなく、極大値制約によって暗黙的に定義されることです。 単純な間違いは、内部構造を検証せずに、すべてのピークのペアを有効なプールを形成しているものとして扱うことです。 もう 1 つのよくある失敗は、閉じ込められた水をグローバルに計算し、その後セグメントを誤って選択し、問題に必要なプールごとのグループ化を失うことです。 

素朴なロジックを壊すエッジケースには、次のような配列を厳密に増加させることが含まれます。`[1,2,3,4]`プールが存在せず、答えがゼロである必要がある場合、または次のような平らな台地がある場合`[5,5,5,5]`境界は曖昧ですが、解釈によっては縮退プールが定義されます。 もう 1 つの微妙なケースは、同じ最大レベルにある複数の互いに素なプールです。これは、1 つだけを選択するのではなく、合計する必要があります。 

## アプローチ

 強引な解釈では、有効な左右の境界のペアをすべて識別し、それらの間に閉じ込められている水の量を計算しようとします。 インデックスの各ペアについて$l < r$、内部のすべての位置の左側の最大高さが、少なくとも何らかの境界条件と同じ高さであるかどうかを確認し、同様に右側でも確認します。 有効な場合、内部をスキャンして合計することにより、トラップされた体積を計算します。$\min(\text{left max}, \text{right max}) - h[i]$。 

このアプローチはプールの定義を直接エンコードするため、原理的には正しいです。 ただし確認が必要です$O(n^2)$候補間隔、および各検証自体にコストがかかる場合があります$O(n)$、につながる$O(n^3)$最悪の場合。 たとえ最適化されていても、$O(n^2)$、それでも失敗します$n = 10^5$。 

重要な観察は、プールが独立した任意の間隔ではないということです。 各位置は、両側の最も近い以上の境界によって自然に制約されます。 これは、単調な構造を示唆しています。すべてのインデックスには、左右に最も近い「壁」があり、これらの壁は、ばらばらまたは入れ子になった水域を定義します。 これらの境界を効率的に計算すると、各水域が独立し、その寄与を線形時間で計算できるようになります。 

これにより、問題は古典的な最近接大境界構造に変換され、次の単調スタックを使用して計算できます。$O(n)$。 各インデックスは、その左右の制約によって定義される正確に 1 つの最大構造に寄与し、これらの構造からプール セグメントとその表面の高さを導き出すことができます。

 ## アルゴリズムのチュートリアル

 私たちは問題を、最も近い以上の境界によって形成される有界の「水の容器」を特定することに変換します。 

1. すべてのインデックスについて、左側に最も近い以上の要素を計算します。 これは、単調減少スタックを使用して行われます。 スタック内の高さが厳密に減少するようにインデックスを維持します。 それより高い、または同じ高さに遭遇すると、不変条件が復元されるまでポップします。 
2. すべてのインデックスについて、同じ考え方を使用して、右から左にスキャンして、右に最も近い以上の要素を計算します。 これにより、あらゆる位置に適切な境界が得られます。 
3. 各位置は、その上に水を含む可能性がある最も近い左右の境界を認識します。 有効なプールは、両方の境界が存在する場所に存在します。 
4. 「底」として機能する（つまり、両方の境界よりも低い）各位置について、その 2 つの境界の高さの最小値として水位を計算します。 
5. 計算された水位に基づいて位置をグループ化します。 この問題では最も高い地表プールが求められるため、発生した最大水位を追跡します。 
6. その最大レベルの各プールについて、そのプールに属するすべての位置の水位と高さの差を合計することによってその体積を計算します。 
7. 最大水位に達するすべてのプールの体積の合計を出力します。 

### なぜ効果があるのか

 単調スタックにより、インデックスごとに、水を保持することが保証されている最も近い境界が正確に識別されます。 より近い境界線またはより高い境界線では水がより早く流出するため、これより遠い境界線は無関係です。 これにより、水位が局所的な制約によってのみ決定される独立した候補盆地への配列の分割が作成されます。 すべての有効なプールはそのような最も近い制約によって制限される必要があるため、有効な構成が失われることはなく、無効な構成が含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    h = list(map(int, input().split()))

    left = [-1] * n
    right = [n] * n

    stack = []

    for i in range(n):
        while stack and h[stack[-1]] < h[i]:
            stack.pop()
        if stack:
            left[i] = stack[-1]
        stack.append(i)

    stack = []

    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] < h[i]:
            stack.pop()
        if stack:
            right[i] = stack[-1]
        stack.append(i)

    max_level = 0
    volume = {}

    for i in range(n):
        if left[i] != -1 and right[i] != n:
            level = min(h[left[i]], h[right[i]])
            if level > h[i]:
                max_level = max(max_level, level)
                volume.setdefault(level, 0)
                volume[level] += level - h[i]

    ans = 0
    for lvl, val in volume.items():
        if lvl == max_level:
            ans += val

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず 2 つの単調スタック パスを使用して、最も近い以上の境界を計算します。 左側のパスは水を保持できる左側の最も近い境界を見つけ、右側のパスは対称的に同じことを行います。 

境界の計算後、各位置は盆地に寄与する可能性があるものとして扱われます。 各位置の水位は、2 つの境界のうち弱い方によって決まります。 このレベルよりも厳密に低い位置のみがボリュームに寄与します。 

後で最高レベルのプールのみを選択できるように、水位ごとにグループ化された寄与分を蓄積します。 これは、最も高い表面標高プールのみが考慮され、同点が合計されるという要件と一致します。 

微妙な点は、同じ高さの境界が許可されるため、スタック条件では`<`それよりも`<=`。 使用する`<=`平らな台地を有効な壁として誤って破棄してしまう可能性があります。

 ## 特殊なケース

 次のような単一要素入力の場合`[5]`、両方の境界配列が少なくとも片側で無効なままであるため、2 つの囲み壁があるという条件を満たす位置はありません。 アルゴリズムはすべての寄与をスキップし、正しくゼロを生成します。 

次のような厳密に増加するシーケンスの場合`[1,2,3,4]`、すべての要素の右側の境界は存在しますが、左側の境界が崩壊し、有効なプールの形成が妨げられます。 スタックにより、誤ったペアリングが作成されないことが保証されます。 

次のようなフラットシーケンスの場合`[3,3,3,3]`、同じ高さの要素は相互の境界になりますが、内部のくぼみは作成しません。`level == height`貢献度はゼロになります。 条件`level > h[i]`誤った量の蓄積を防ぎます。
