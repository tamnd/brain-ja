 ## 解決策
 ## 問題の理解

 頂点がサンタの世界の位置を表す重み付き無向グラフが与えられます。 1 つの特別な頂点はノード 0 としてラベル付けされた北極で、家に対応する他の特別な頂点がいくつかあります。 どの家も北極から到達できることが保証されています。 

各家には正確に 1 人のエルフが割り当てられます。 そのエルフは単独で北極から最短経路で家まで移動し、また最短経路で北極に戻ってきます。 したがって、各家について、0 からその家までの最短経路距離の 2 倍を考慮します。 

このタスクは、すべてのハウスについて 2 つの値、つまりすべての往復移動時間の合計と、すべてのエルフの最大往復移動時間を計算することです。 

入力サイズでは、最大 10^3 の正の重みを持つ最大 10^4 ノードと 10^5 エッジが許可されます。 これは、O(n^3) では遅すぎるため、Floyd Warshall のような全ペアの最短経路法を即座に除外します。 すべてのクエリは同じ開始点からの距離のみに依存するため、ノード 0 からの単一ソースの最短パスで十分です。 

主なエッジケースはグラフ構造に由来します。 同じノードのペア間に複数のエッジが存在する場合や、グラフに冗長なパスがある場合でも、問題となるのは最短のパスのみです。 重みを無視した単純な DFS または BFS は、重み付けされたエッジで失敗します。 もう 1 つの微妙な問題は整数の範囲です。距離はパスごとに最大約 10^7 以上に累積する可能性があり、往復で距離を 2 倍にしても 32 ビットの制限内に収まりますが、64 ビットの安全性は標準です。 

単純な BFS アプローチの小さな失敗例を示します。 

入力:```
3 1 3
1
2 0 1
1 2 100
0 2 2
```ここで、BFS はグラフを重み付けされていないものとして誤って扱い、より長くてもエッジの少ないパスを優先する可能性があります。 正解は重み付けされた最短経路に依存するため、ダイクストラが必要です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。家ごとに、ノード 0 からダイクストラを実行するか、さらに悪いことに、家ごとに個別に最短経路検索を実行します。 これにより、最短パス ツリーが複数回計算されます。 各ハウスに対して完全なダイクストラを実行すると、複雑さは O(k * m log n) になり、最悪の場合、約 10^9 の演算となり、明らかに遅すぎます。 

重要な観察は、すべての家が同じ水源を共有しているということです。 家ごとの最短パスを再計算する必要はありません。 ノード 0 からダイクストラを 1 回実行すると、すべてのハウスを含むすべての頂点 v の dist[v] が得られます。 これらの距離が得られると、各エルフの移動時間は単純に 2 * dist[house] になります。 

したがって、問題は、古典的な単一ソースの最短パスの計算と、それに続くノードのサブセットにわたる単純な集約に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 家ごとにディクストラを再実行する | O(k · m log n) | O(n + m) | 遅すぎる |
 | 0 からの単一のディクストラ | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 移動は双方向であるため、各エッジは両方向に保存されます。 この表現は、ダイクストラ中の効率的な走査に必要です。 
2. ノード 0 から開始してダイクストラを実行します。0 に設定された 0 を除くすべてのノードに対して無限大の距離配列を初期化します。距離をキーとした最小ヒープを使用します。 これにより、ノードを展開するたびに、ソースからの最短距離が確定します。 
3. ノード u を処理するとき、すべての出力エッジ (u、v、w) を緩和します。 dist[v] が u によって改善できる場合は、それを更新し、新しい候補距離をヒープにプッシュします。 このステップにより、最適な最短パスに向けた段階的な改良が保証されます。 
4. ダイクストラが完了したら、指定されたすべてのハウス ノードを反復処理します。 各ハウス h について、roundTrip = 2 * dist[h] を計算します。 これらの値の現在までの合計を維持し、それらの最大値を追跡します。 
5. 合計と最大値を出力します。 

この分離が機能する理由は、0 からの最短経路が判明すると、各家が独立するようになるためです。 エルフ間には相互作用がないため、問題は同じ事前計算された配列に対する独立したクエリに分解されます。 

### なぜ効果があるのか

 正確さは、ダイクストラによって維持される不変式に依存します。つまり、ノードが現在の最良の距離で優先キューから抽出されるとき、その距離はソースからの真の最短パス距離になります。 すべてのエッジの重みは負ではないため、その後の緩和によってそのノードのより小さい値が生成されることはありません。 したがって、アルゴリズムの終了後、dist[v] は 0 から到達可能なすべての v までの最短経路距離に等しくなります。各エルフの移動時間はこの値のみに依存するため、2 * dist[h] の計算は正確であり、独立した値を合計して最大値を取得することで正確さが保たれます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def dijkstra(n, graph, src):
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[src] = 0
    pq = [(0, src)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist

n, k, m = map(int, input().split())
houses = [int(input()) for _ in range(k)]

graph = [[] for _ in range(n + 1)]
for _ in range(m):
    u, v, w = map(int, input().split())
    graph[u].append((v, w))
    graph[v].append((u, w))

dist = dijkstra(n, graph, 0)

total = 0
mx = 0

for h in houses:
    t = 2 * dist[h]
    total += t
    if t > mx:
        mx = t

print(total, mx)
```コードは、バイナリ ヒープを備えた標準のダイクストラ実装を中心に構造化されています。 隣接リストは 1 のインデックスにノード 0 を加えたものであるため、配列のサイズは n + 1 になります。重要な詳細は、古いエントリのチェックです。`if d != dist[u]`これにより、古いヒープ状態の処理が防止され、ランタイムが範囲内に維持されます。 

最後のループは、最短パスの計算と集計ロジックを独立させるためにダイクストラから意図的に分離されており、これにより正確性に関する懸念が混在するリスクが軽減されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各エッジは改善が成功するたびに 1 回緩和され、各ヒープ操作のコストは log n | になります。 
| スペース | O(n + m) | 隣接リストと距離配列およびヒープ |

 この制約では最大 10^4 ノードと 10^5 エッジが許可されるため、単一のダイクストラは時間制限内に問題なく収まります。 k 軒にわたる集計ステップは O(k) ですが、これはグラフ検索に比べて無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    input = sys.stdin.readline

    def dijkstra(n, graph, src):
        INF = 10**18
        dist = [INF] * (n + 1)
        dist[src] = 0
        pq = [(0, src)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in graph[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    n, k, m = map(int, input().split())
    houses = [int(input()) for _ in range(k)]

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        graph[u].append((v, w))
        graph[v].append((u, w))

    dist = dijkstra(n, graph, 0)

    total = 0
    mx = 0
    for h in houses:
        t = 2 * dist[h]
        total += t
        mx = max(mx, t)

    return f"{total} {mx}\n"

 ## 特殊なケース

 エッジ ケースの 1 つは、0 から家までの直接エッジが存在するが、それが最短パスではない場合です。 間接的な改善テストでは、パス 0 → 2 は 0 → 1 → 2 よりも悪くなります。アルゴリズムはノード 1 の処理後に dist[2] を正しく更新し、最終的な距離は最適なルートを反映します。 

もう 1 つのケースは、同じノード間に複数のエッジがある場合です。 すべてのエッジが独立して緩和されるため、アルゴリズムは自然に最小の重みを維持し、冗長なエッジは正確さに影響を与えません。 

最後のエッジ ケースは、k = n ですべてのノードが住宅である場合です。 このアルゴリズムは依然としてダイクストラを 1 回だけ実行し、その後すべてのノードにわたって集計するため、変更することなく効率と正確性が維持されます。
