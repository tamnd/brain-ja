 ## 問題の理解

 2 つの短い文字列が与えられています。`x`そして`y`、式を評価するように求められます`x - y`JavaScript とまったく同じです。 重要な問題は、JavaScript が算術演算中にすべての文字列を文字列として扱うわけではないことです。 マイナス演算子を使用すると、最初に両方のオペランドが数値に変換されます。 文字列が有効な数値を表す場合、その数値になります。 数字以外の文字が含まれている場合は、次のようになります。`NaN`。 いずれかのオペランドが設定されると、`NaN`、結果も`NaN`。 

したがって、タスクはこの型強制ルールをシミュレートすることになります。各文字列を整数または無効な数値として解釈し、両方が有効な場合は減算を計算します。 

制約は非常に小さく、各文字列の長さは 6 未満で、数字と英字のみで構成されます。 これにより、ストリームの解析や大きな整数の処理などの最適化に関する懸念が必要ないことがすぐにわかります。 各文字列を直接スキャンするだけで十分です。 

微妙なエッジ ケースは、無効な値の伝播です。 例えば、`"a 2"`は無効です。`"a"`数値に変換できないので、結果は次のようになります。`NaN`2 番目のオペランドが有効であっても。 もう 1 つのケースは、減算によって非整数の結果が生成される場合ですが、問題の解釈では、これが整数の場合は数値とみなされ、小数点なしで出力されます。それ以外の場合は、引き続き実数として有効な数値出力となります。ただし、この問題の説明では、整数のような入力があるため、すべての有効なケースが整数のままである点が異なります。 

最後に重要な点は、文字列内のどこかに 1 文字でも文字があれば完全に無効になるということです。 

## アプローチ

重要な点は、入力形式が非常に制限されていることです。 文字列は完全に数字であるか、少なくとも 1 つの文字が含まれています。 これにより、有効な整数か無効な数値という非常に単純な分類が得られます。 

したがって、JavaScript をシミュレートする代わりに、各文字列が完全に数字で構成されているかどうかを確認するだけで済みます。 「はい」の場合、それを整数として解析します。 それ以外の場合は、次のように扱います。`NaN`。 この分類ができれば、引き算は簡単です。

 ## アルゴリズムのチュートリアル

 文字列が有効な数値かどうかを判断するヘルパー関数を定義します。 

1. 文字列を読み取る`x`そして`y`。 これらは減算式のオペランドを表します。 
2. 各文字列について、すべての文字をスキャンします。 すべての文字が数字の場合、文字列を整数値に変換します。 

この手順が機能するのは、入力内の有効な数値文字列に記号、スペース、または複雑な書式設定が含まれていないためです。 
3. 数字ではない文字がある場合は、特殊な記号で表される、対応する値を無効としてマークします。`NaN`州。 
4. どちらかの値が`NaN`、出力`"NaN"`すぐに。 
5. それ以外の場合は、整数の減算を計算します。`value_x - value_y`。 
6. 結果を単純な整数として出力します。 

ステップ 4 が減算の前にある理由は次のとおりです。`NaN`は算術演算の下で吸収されるため、無効が検出された場合は不要な計算が回避されます。 

### なぜ効果があるのか

 各文字列は、数値として解釈できるかどうかを個別に決定します。 減算演算は、両方のオペランドが整数領域にある場合にのみ問題になります。 入力では有効な数値文字列が整数を表すことが保証されるため、問題全体は数字のみの文字列のセット内のメンバーシップをチェックすることに帰着します。 最終結果は正確にこれら 2 つの整数の算術差であり、数字のみの構造から逸脱すると、結果は JavaScript の強制ルールに一致する無効なクラスに強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse(s: str):
    s = s.strip()
    if s.isdigit():
        return int(s)
    return None  # represents NaN

def solve():
    x, y = input().split()
    a = parse(x)
    b = parse(y)

    if a is None or b is None:
        print("NaN")
    else:
        print(a - b)

if __name__ == "__main__":
    solve()
```解析ステップはソリューションの中核です。 の`.isdigit()`check は、有効な数値に数字のみが含まれるという制約と完全に一致します。 どの文字でも文字列はただちに無効になり、`None`。 

私たちが使用するのは`None`衝突の危険を冒さずに有効な整数と無効な値を明確に分離するため、数値センチネルの代わりに使用されます。 

減算は、両方のオペランドが有効であることが確認された後にのみ実行され、JavaScript ルールに基づいて正確性が維持されます。`NaN`収量`NaN`。

 ## 特殊なケース

 主なエッジケースは、1 つのオペランドのみが無効な英数字文字列が混在する場合です。 のような入力の場合`12a 3`、最初の文字列のパーサーはすぐに数字の検証に失敗するため、値は次のようになります。`NaN`。 アルゴリズムは減算を続行せず、JavaScript の動作に一致します。`NaN`オペランドが結果を汚します。 

もう 1 つのエッジ ケースは、次のような純粋なゼロ値です。`0 0`。 両方の文字列が通過します`.isdigit()`したがって、それらは整数に変換され、減算によって次の結果が得られます。`0`、書式設定の問題なく通常の整数として出力されます。 

最後のエッジケースは、次のような最大長の数値文字列です。`99999 1`。 どちらも有効な整数であり、Python はオーバーフローを考慮せずに小さな整数を処理し、正しい出力を直接生成するため、減算は簡単です。
