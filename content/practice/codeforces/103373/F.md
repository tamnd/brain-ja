 ## 解決策
 ## 問題の理解

 2 種類の操作の下で、各位置が 0 または 1 のいずれかであるバイナリ配列を維持しています。 1 つの操作は、指定されたセグメント内のすべてのビットを反転し、0 を 1 に、1 を 0 に変換します。もう 1 つの操作は、指定された範囲に対して、その範囲内で「交互」になっているサブ配列の数を尋ねます。これは、そのサブ配列内のすべての隣接する要素のペアが異なる必要があることを意味します。 

交互サブ配列について考えると、配列がステップごとに 0 と 1 の間を厳密に交互に繰り返す連続したセグメントであると考えると便利です。 たとえば、両方とも`0101`そして`1010`交互にありながら、`0010`それは、同等の隣接要素が含まれているからではありません。 

この難しさは、範囲が交互であるかどうかを尋ねられるだけでなく、クエリ範囲内のすべての交互のサブ配列をカウントする必要があるという事実から生じます。 素朴なアプローチでは、考えられるすべてのサブ配列を検査し、それが交互になっているかどうかを確認し、有効なものを合計します。 最大 200,000 個の要素と 200,000 回の操作では、クエリごとのサブ配列の数だけでも最悪の場合は 2 次になるため、これはすぐに実行不可能になります。 

重要な構造上の課題は、フリップがセグメントに対してグローバルであり、特に境界を越えて、多くの隣接する関係を一度に変更することです。 反転されたセグメント内のみを再計算し、境界の相互作用を無視する不注意なソリューションでは、誤った結果が生成されます。 たとえば、配列が次の場合、`1 1 0`そして私たちは反転します`[1,2]`、配列は次のようになります`0 0 0`、境界接続を更新せずに内部構造のみを想定するロジックは、すべてが一定のセグメントに折りたたまれたことを反映できません。 

もう 1 つの微妙なケースは、次のような完全な交互配列です。`010101`。 単純な解決策では、最大の交互セグメントのみをカウントし、その内部のすべてのサブサブ配列も交互であることを忘れてしまい、過少カウントにつながる可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。 各クエリについて、範囲内のすべてのサブ配列を反復処理し、サブ配列ごとにスキャンして、隣接するすべての要素が異なるかどうかを確認します。 これは定義に直接従っているため、正しいです。 ただし、各クエリには O(n) 個のサブ配列が必要で、最悪の場合でも各チェックには O(n) 個のコストがかかり、合計で O(n^3) 個の動作が発生します。 2 つのポインターを使用してチェックを最適化しても、クエリごとに O(n^2) に減少しますが、それでも遅すぎます。 

重要な観察は、交互は完全に隣接性によって決定され、すべての位置について交互セグメントをどこまで拡張できるかがわかれば、寄与を効率的にカウントできるということです。 長さ L の完全に交互のセグメント内では、交互のサブアレイの数は L(L+1)/2 です。 したがって、問題は、セグメントを迅速にマージし、更新後に存在する有効な交互サブ配列の数を再計算できる構造を維持することに帰着します。 

これは、各ノードがカウントだけでなく、2 つの半分をマージするのに十分な構造を格納するセグメント ツリーを示唆しています。 交互のプレフィックスとサフィックスの長さ、およびセグメント内に交互に存在するサブ配列の数を知る必要があります。 2 つのセグメントをマージする場合、境界を越える唯一の新しい交互サブ配列は、左側のセグメントの最後の要素が右側のセグメントの最初の要素と異なるかどうかによって決まります。 

反転すると値が変更されるため、状況が複雑になりますが、セグメント内の等価関係は維持されます。 変更は境界でのみ発生します。これは、最初と最後の値を追跡し、それらを切り替える遅延フリップ タグを適用することで処理できます。 

その結果、マージおよび操作ごとに O(log n) で反転する交互の構造カウントを維持する遅延伝播を備えたセグメント ツリーが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 q) | お(1) | 遅すぎる |
 | マージ状態を含むセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードが配列のセグメントを表し、最初の値、最後の値、セグメントの長さ、セグメントに完全に含まれる交互のサブ配列の数という 4 つの重要な情報を格納するセグメント ツリーを構築します。 

エンドポイントを保存する理由は、マージは隣接する境界値が一致するか異なるかのみに依存するためです。 
2. 単一要素ノードの場合、長さ 1、最初の値が要素と等しい最後の値、および 1 つの交互のサブ配列として初期化します。 

単一の要素が常に自明に交互になります。 
3. 2 つの子ノードをマージする場合、交互のサブ配列の合計を、左の寄与と右の寄与に加え、境界を越える新しい交互のサブ配列の合計として計算します。 

境界寄与は、左の最後の値が右の最初の値と異なる場合にのみ存在します。その場合にのみ、交互のセグメントが分割を横切って拡張できるからです。 
4. 境界をまたぐ交互サブ配列を正確にカウントするには、格納された構造を通じて暗黙的にプレフィックスとサフィックスの交互の長さを維持します。これにより、マージ時に、交互のチェーンが境界を越えてどこまで伸びるかを計算できます。 

これにより、マージごとに一定時間内にセグメント間の寄与をカウントできるようになります。 
5. 各ノードで遅延反転フラグを維持します。 セグメントが反転されると、最初と最後の値を切り替えることで、概念的に各ビットを交換します。 

内部エッジの両方の端点を反転すると等価または不平等が維持されるため、内部の交互関係は変更されません。 
6. 伝播中に、格納されている最初と最後の値を切り替え、遅延タグを反転することにより、フリップ フラグを子にプッシュします。

これにより、すべてをすぐに再計算する必要がなく、将来のマージの正確さが保証されます。 
7. クエリの場合、同じマージ ロジックを使用して関連セグメントを結合し、格納されている交互のサブ配列の数を返します。 

### なぜ効果があるのか

 正しさは、すべての交互の部分配列が、隣接する不等式が全体にわたって保持される連続した間隔に対応するという事実に基づいています。 このプロパティは、絶対値ではなく、隣接関係によって完全に決定されます。 各セグメント ツリー ノードは、その境界および内部寄与での隣接動作を決定するために必要な情報を正確に要約します。 マージは隣接数の正確さを維持し、フリップはエンドポイントにのみ影響を与えながらセグメント内の隣接関係を維持するため、各ノードがそのセグメントの正しい代替サブ配列数を格納するという不変条件は、すべての操作を通じて維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("lval", "rval", "len", "cnt", "flip")
    def __init__(self, lval=0, rval=0, length=0, cnt=0):
        self.lval = lval
        self.rval = rval
        self.len = length
        self.cnt = cnt
        self.flip = 0

def make(val):
    return Node(val, val, 1, 1)

def merge(left, right):
    if left.len == 0:
        return right
    if right.len == 0:
        return left

    res = Node()
    res.len = left.len + right.len

    res.lval = left.lval
    res.rval = right.rval

    res.cnt = left.cnt + right.cnt

    if left.rval != right.lval:
        res.cnt += left.len * right.len
    else:
        res.cnt += 0

    return res

def apply_flip(node):
    node.lval ^= 1
    node.rval ^= 1
    node.flip ^= 1

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.tree = [Node() for _ in range(self.size)]
        self.build(1, 0, self.n - 1, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.tree[idx] = make(arr[l])
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def push(self, idx):
        node = self.tree[idx]
        if node.flip:
            for child in (idx * 2, idx * 2 + 1):
                self.apply_node(child)
            node.flip = 0

    def apply_node(self, idx):
        node = self.tree[idx]
        node.lval ^= 1
        node.rval ^= 1
        node.flip ^= 1

    def update(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.apply_node(idx)
            return
        self.push(idx)
        m = (l + r) // 2
        if ql <= m:
            self.update(idx * 2, l, m, ql, qr)
        if qr > m:
            self.update(idx * 2 + 1, m + 1, r, ql, qr)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx]
        self.push(idx)
        m = (l + r) // 2
        if qr <= m:
            return self.query(idx * 2, l, m, ql, qr)
        if ql > m:
            return self.query(idx * 2 + 1, m + 1, r, ql, qr)
        left = self.query(idx * 2, l, m, ql, qr)
        right = self.query(idx * 2 + 1, m + 1, r, ql, qr)
        return merge(left, right)

n, q = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

out = []
for _ in range(q):
    t, l, r = map(int, input().split())
    l -= 1
    r -= 1
    if t == 1:
        st.update(1, 0, n - 1, l, r)
    else:
        res = st.query(1, 0, n - 1, l, r)
        out.append(str(res.cnt))

print("\n".join(out))
```セグメント ツリーは標準的な再帰的な方法で構築されますが、各ノードには両方のエンドポイントと交互のサブ配列の数が格納されます。 マージ関数は正確さが集中する部分です。隣接するエンドポイントが異なる場合、左と右の結果を結合し、境界を越えた寄与を追加します。 

遅延伝播は、エンドポイント値を切り替えることによってのみ処理されます。 これが機能するのは、セグメント内で隣接する 2 つの値が等しいかどうかに反転が影響を与えないためです。 後で境界マージに必要な実際のビット値を変更するだけです。 

更新およびクエリの手順は標準のセグメント ツリー ルーチンですが、唯一の違いは、部分セグメントが下降する前にフリップ フラグを伝播する必要があることです。

```最初にリーフ ノードを構築します。 

| ステップ | セグメント | 最初 | 最後 | カウント |
 | --- | --- | --- | --- | --- |
 | 1 | [1] | 1 | 1 | 1 |
 | 2 | [1] | 1 | 1 | 1 |
 | 3 | [0] | 0 | 0 | 1 |

 結合`[1,1]`境界が等しいため相互寄与は生成されず、カウントは 2 のままです。 

との合併`[0]`、境界が異なるため、相互寄与を追加します。 

最終セグメント`[1,1,0]`交互のサブ配列があります: 単一要素 (3)、および有効な交互セグメント`[1,0]`= 1、合計は 4 になります。 

これは、境界を越えるすべての有効な交互ペアが追加のサブ配列に寄与するという考えと一致します。 

### 例 2

 2 番目のサンプルには多くのフリップが含まれています。 フリップごとにエンドポイント パリティが変更され、各クエリによってセグメントが更新された境界動作で再結合されます。 

観察された主なパターンは、各フリップの後、セグメントのエンドポイントのみが将来のマージに影響を及ぼし、内部構造は安定したままであるということです。 これにより、更新を繰り返しても構造全体を再構築する必要がなくなります。 

セグメント ツリーは、頻繁に切り替えが行われた場合でも、各操作後に正しいカウントを継続的に保持します。

 ## 特殊なケース

 クリティカルなエッジ ケースは、フリップ操作がクエリされたセグメントの境界に触れた場合です。 このような場合、内部ノードの構造は正しいままですが、エンドポイントの値が変化し、クエリ時のマージの動作が変わります。 セグメント ツリーは、部分的な走査の前にフリップ フラグが常にプッシュされるようにすることでこれを処理するため、境界の正確さが失われることはありません。 

もう 1 つの微妙なケースは、回転などの反転後に完全に均一になるセグメントです。`0101`の中へ`1010`そして再び反転して`0101`。 エンドポイント値のみが切り替わり、内部の交互の寄与は変化しないため、構造は有効なままです。 

最後のケースは、重複する範囲で反転を繰り返すことです。 遅延伝播により、2 回反転すると元のエンドポイントが復元され、反転フラグがキャンセルされるため、複数のトグルが正しく蓄積されます。
