 ## 解決策
 ## 問題の理解

 与えられた国の小さなリストには、獲得した金、銀、銅のメダルの数とその国名が続く 3 つの整数でそれぞれが記述されています。 私たちの仕事は、オリンピックの標準的なランキング規則に基づいてどの国が最高位にランクされるかを決定することです。 

このランキングはメダル数の 3 倍を辞書順に並べたものです。 金メダルが多ければ多いほど、その国は良くなります。 金メダル数が同数の場合は銀メダルが決定します。 金と銀が同じ場合、銅メダルが同点を破ります。 この問題では、最良の国が 1 つだけ存在することが保証されているため、最終的な答えで同点を処理する必要はありません。 

入力サイズが小さい場合でも、構造は重要です。基本的に、トリプルのカスタム順序付けで最大要素を見つけています。 

制約は非常に軽く、参加国は 300 か国未満です。 これは、二次または並べ替えベースのソリューションでも安全であるが、最も単純な線形スキャンですでに十分であることをすぐに示します。 入力を読み取るときに、現在の最適な候補を維持するだけで済みます。 

微妙だが重要なエッジ ケースは、入力形式に由来します。つまり、国名にはスペースが含まれる場合があるため、単純に空白で分割すると、誤って名前が分割されてしまう可能性があります。 たとえば、次のような行`10 5 3 United States of America`3 つの整数の後の完全な文字列を名前として保持する必要があります。 

もう 1 つのエッジ ケースは、入力の順序を除いてすべてのメダル数が同一である場合です。 最高のランクの一意性が保証されているため、比較を超えて関係を断つ必要はありません。 最初に発生した最大値を追跡するか、厳密に優れたタプルを一貫して更新するだけです。 

## アプローチ

 強引な解釈では、すべての国を他のすべての国と比較し、辞書編集ルールに基づいて優位性をチェックします。 各ペアについて、ゴールド、次にシルバー、次にブロンズを比較し、どちらが厳密に優れているかどうかを追跡します。 これは正しく動作しますが、不必要にコストがかかります。 最大 300 か国の場合、約 90,000 件の比較が必要になりますが、それでも許容範囲内ですが、ロジックは必要以上に複雑になります。 

重要な観察は、ランキングによってトリプルの合計順序が定義されるため、ペアごとの優位性チェックが必要ないということです。 辞書式比較で最大の要素を見つけるだけで済みます。 これにより、問題はリストを 1 回通過するだけで済み、これまでに確認された最良の状態が維持されます。 

すべてのペアを比較するのではなく、各新しい国を現在の最良の候補とのみ比較します。 これにより、問題は O(n) に減り、より単純になり、エラーが発生しにくくなります。

 ## アルゴリズムのチュートリアル

 私たちは各国を一つ一つ処理し、これまでに見られた最高のトリプルを維持します。 

1. 国の数 n を読み取ります。 これにより、最適な候補に対して実行する更新の数が定義されます。 
2. 現在の最高のメダル数と対応する国名を保存する変数を初期化します。 メダルの負の無限大など、有効な入力よりも悪い状態から開始するか、最初の入力行から初期化します。 
3. 国ごとに、行を 3 つの整数に解析し、残りの文字列を国名として返します。 名前にはスペースが含まれる可能性があるため、最初の 3 つの整数を超える固定数のトークンを想定できないため、これには慎重な解析が必要です。 
4. 現在の国のメダルトリプル (g、s、b) を保存されているベストトリプルと比較します。 辞書順に比較します。最初に金、次に銀、次に銅です。 現在の国が厳密に優れている場合は、保存されている最良の値を現在の値に置き換えます。 
5. すべての国を処理した後、保存されている最適な国名を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、i か国を処理した後、格納された候補が (金、銀、銅) の辞書順で i か国の中で最良であるという不変条件を維持します。 厳密に優れたトリプルが見つかった場合にのみ、保存された候補を置き換えるので、各更新ステップではこの不変条件が保持されます。 比較によって全体の順序が定義されるため、すべてのエントリを処理した後の最終候補はグローバル最大値になる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def better(g1, s1, b1, g2, s2, b2):
    if g1 != g2:
        return g1 > g2
    if s1 != s2:
        return s1 > s2
    return b1 > b2

def main():
    n_line = input().strip()
    while n_line == "":
        n_line = input().strip()
    n = int(n_line)

    best_g, best_s, best_b = -1, -1, -1
    best_name = ""

    for _ in range(n):
        line = input().rstrip("\n")
        while line == "":
            line = input().rstrip("\n")

        parts = line.split()
        g = int(parts[0])
        s = int(parts[1])
        b = int(parts[2])
        name = " ".join(parts[3:])

        if better(g, s, b, best_g, best_s, best_b):
            best_g, best_s, best_b = g, s, b
            best_name = name

    print(best_name)

if __name__ == "__main__":
    main()
```このソリューションは入力を 1 行ずつ読み取り、書式設定された入力に表示される可能性のある空白行を慎重に処理します。 各行はトークンに分割されており、最初の 3 つのトークンは常に整数で、残りは国名を構成します。 

比較ロジックはヘルパー関数内に分離されており、辞書編集的な順序付けが明示的に行われ、ネストされた条件文での間違いが回避されます。 有効な値はすべて負ではないため、初期化ではメダル数に -1 が使用されます。 

よくある落とし穴は、スペースが含まれている国名を誤って分割することです。 3 番目のインデックスの後にすべてのトークンを結合することで、必要に応じて完全な名前が正確に保存されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from contextlib import redirect_stdout

    with redirect_stdout(out):
        # re-run solution

                return g1 > g2
            if s1 != s2:

 ## 特殊なケース

 1つのエッジケースは同一のメダル3枚です。 このアルゴリズムは、厳密に優れている場合にのみ最良の候補を置き換えるため、引き続き正しく動作します。また、この問題では一意の最良が保証されているため、同等の比較があいまいさを引き起こすことはありません。 

もう 1 つのエッジケースは、ゴールドとシルバーが等しい場合にブロンズの差が大きくなるということです。 辞書編集的な比較により、最初の 2 つのレベルが一致した後にのみブロンズが考慮されることが保証され、ヘルパー関数によってこの順序が明示的に強制されます。 

最後に、スペースを含む名前は、3 つの整数を解析した後に残りのすべてのトークンから名前を再構築することによって安全に処理され、正確な元の識別子が保存されます。
