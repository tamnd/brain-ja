 ## 解決策
 ## 問題の理解

 各ノードが 16 ビット整数値を保持する無向グラフが与えられます。 すべてのエッジは、2 つのエンドポイント値間のハミング距離、つまり 2 つのノード値が異なるビット位置の数に等しいコストに寄与します。 

値が欠落しているノードに値を割り当てることはできますが、追加の構造層があります。整数全体について直接推論する代わりに、問題は個々のビットに制約を与えます。 各制約は、2 つの特定のビット (おそらく異なるノードからの) を強制的に等しくするか、強制的に異なるようにします。 

タスクは、すべての制約が満たされ、すべてのエッジにわたるビットごとの XOR ポップカウントの合計として計算される総エッジ コストが最小化されるように、すべての欠損値を割り当てることです。 制約が互いに矛盾する場合は、不可能であることを報告する必要があります。 

重要な観察は、XOR ポップカウントがビットごとにきれいに分割されていることです。 各エッジの重みは、16 の独立したビット比較の合計にすぎません。 ただし、制約により異なる位置にあるビットがリンクされる可能性があるため、ビットは完全に独立していなくなります。 このカップリングが最大の難点です。 

入力サイズは中程度で、最大 1000 ノードと 5000 エッジですが、値ごとに 16 ビットのみ、制約は最大 8 つです。 制約の数が少ないということは、少数のビット変数だけが実際に自明ではない方法で接続されていることを意味するため、決定的なヒントとなります。 

制約を考慮せずにノードごとに 16 ビットすべてを個別に割り当てる単純なアプローチは、特に bit(u, i) が bit(v, j) に等しい、または bit(v, j) が bit(w, k) に等しくないなどの制約がチェーンを形成し、間接的な関係を強制する場合に、簡単に一貫性に違反する可能性があります。 もう 1 つの失敗モードは、各ビットを独立して処理することです。これは、制約によって異なるビット インデックスが結合される可能性があるため、正確性が損なわれます。 

たとえば、ある制約によってノード A のビット 0 がノード B のビット 5 と等しくなるように強制され、別の制約によってノード B のビット 5 がノード C のビット 0 と異なるように強制される場合、異なる位置にわたるビットは分離できなくなります。 ビットごとの貪欲な戦略では、この結合が完全に失われ、一貫性のない割り当てが生成されます。 

## アプローチ

 強引な解釈では、すべてのノードに完全な 16 ビット値を割り当て、総エッジ コストを計算する際にすべての制約をチェックします。 これにより、サイズ 2^(16n) の検索空間が即座に得られますが、これは n = 1000 どころか、n = 20 の場合でも完全に実行不可能です。制約が依然として伝播する可能性があるため、制約付きノードのみに削減しても、構造がなければ役に立ちません。 

重要な構造的洞察は、問題を 2 つの層に分けることです。 まず、各ノードの各ビットを独立したブール変数として扱います。 次に、制約がこれらの変数を接続していることがわかりますが、制約は最大でも 8 つしかないため、実際に依存構造に結び付けられる変数の数は少ないです。 

ノードがペア (頂点、ビット) である制約グラフを構築します。 各制約は、そのような 2 つの変数間に等価エッジまたは不等価エッジを追加します。 これにより、コンポーネント内のすべての変数が反転まで一緒にロックされる連結コンポーネントが生成されます。 各コンポーネントは単一のブール変数のように動作します。 

圧縮後、問題全体は少数のブール コンポーネント変数を割り当てることになります。通常、最悪の場合でも最大でも数十個ですが、制限されたビットのみが重要であるため、通常ははるかに少なくなります。 目的は、元々はエッジとビットの合計でしたが、これらのコンポーネントのペアに対する重み付き関数として書き直すことができます。

グラフの各エッジはビットごとに独立して寄与し、各寄与は 2 つのコンポーネントに同じ値が割り当てられているか、異なる値が割り当てられているかによってのみ異なります。 これにより、元の問題が小さな重み付き 2 値代入問題に変換され、コンポーネント変数に対するすべての代入を列挙し、コストを効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのノード値に対するブルート フォース | O(2^(16n)) | O(n) | 遅すぎる |
 | コンポーネントの圧縮 + 列挙 | O(2^k · (m + k^2)) | O(m + k^2) | 承認済み |

 ここで、k は圧縮後の独立制約コンポーネントの数です。 

## アルゴリズムのチュートリアル

 すべてのノードのすべてのビットをブール変数に変換し、制約を使用してそれらを削減し、最後に結果のコンポーネントに対する小さな割り当て問題を解決します。 

1. 各ペア (ノード u、ビット i) を getBit(Vu, i) を表すブール変数として扱います。 素のセット共用体構造をパリティで初期化するので、各マージは 2 つの変数間の等価または否定を表すことができます。 
2. 制約ごとに、対応する変数を結合します。 制約が等価性を必要とする場合は、パリティ 0 で結合し、それ以外の場合はパリティ 1 で結合します。結合中に矛盾が発生した場合、システムは矛盾しているため、すぐに -1 を返します。 
3. 制約を処理した後、すべての変数を DSU コンポーネントに圧縮します。 各コンポーネントは、値が相互に固定されているビット変数のセットを表します。 この時点で、各変数は自由であるか、他の変数とコンポーネントに結合されています。 
4. 各 DSU コンポーネントに小さなインデックスを割り当て、元の変数 (u、i) ごとに、それが属するコンポーネントと、コンポーネントの代表に対して反転されているかどうかを記録します。 
5. ここで、すべてのグラフのエッジを処理します。 各エッジ (u, v) と各ビット i について、寄与が (u, i) と (v, i) の成分の同じ割り当てに依存するか、異なる割り当てに依存するかを計算します。 この寄与は、コンポーネントのペアの重みとして保存され、2 つのケース、つまり 2 つのコンポーネントが等しい場合のコストと異なる場合のコストに分けられます。 
6. 制約の数が少ないためコンポーネントの数が少ないため、コンポーネント値の割り当てをすべて列挙します。 割り当てごとに、すべてのコンポーネントのペアを反復処理し、それらの寄与を合計することで総コストを計算します。 
7. 初期ノード値によって引き起こされる固定コンポーネントも考慮します。 ノードが固定値を持つ場合、そのビットは対応するコンポーネントに固定の割り当てを課すため、検索スペースが減少し、一部の割り当てが無効になる可能性があります。 

最終的な答えは、すべての有効な割り当てに対する最小コストです。 

### なぜ効果があるのか

 正しさは 2 つの不変条件に基づいています。 まず、パリティを備えた DSU は、すべての等価および不等関係を正しく維持し、実行可能なすべての割り当てが DSU コンポーネントの割り当てに正確に対応することを保証します。 第 2 に、変数がコンポーネントに圧縮されると、目的を介する場合を除いて、残りの制約は異なるコンポーネントをリンクしないため、問題は独立したブール変数に対する有限の代入に帰着します。 元の有効な構成はすべて 1 つのコンポーネント割り当てに対応しており、その逆も同様であるため、コンポーネント割り当てを最小化することは、すべての有効なビット割り当てを最小化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n
        self.x = [0]*n  # parity to parent

    def find(self, a):
        if self.p[a] == a:
            return a
        pa = self.p[a]
        root = self.find(pa)
        self.x[a] ^= self.x[pa]
        self.p[a] = root
        return root

    def union(self, a, b, w):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return (self.x[a] ^ self.x[b]) == w
        if self.r[ra] < self.r[rb]:
            ra, rb = rb, ra
            a, b = b, a
        self.p[rb] = ra
        self.x[rb] = self.x[a] ^ self.x[b] ^ w
        if self.r[ra] == self.r[rb]:
            self.r[ra] += 1
        return True

n, m = map(int, input().split())
edges = [tuple(map(int, input().split())) for _ in range(m)]
vals = list(map(int, input().split()))
q = int(input())
cons = [tuple(map(int, input().split())) for _ in range(q)]

def idv(u, b):
    return u * 16 + b

dsu = DSU(n * 16)

ok = True
for t, u, i, v, j in cons:
    if not dsu.union(idv(u, i), idv(v, j), t):
        ok = False

if not ok:
    print(-1)
    sys.exit()

root_map = {}
comp_id = {}
comp_val = {}
cid = 0

for u in range(n):
    for b in range(16):
        x = idv(u, b)
        r = dsu.find(x)
        val = dsu.x[x]
        if r not in comp_id:
            comp_id[r] = cid
            cid += 1
        comp_val[x] = comp_id[r] ^ val

C = cid

fixed = {}
for u in range(n):
    if vals[u] == -1:
        continue
    for b in range(16):
        comp = comp_val[idv(u, b)]
        bit = (vals[u] >> b) & 1
        if comp in fixed and fixed[comp] != bit:
            print(-1)
            sys.exit()
        fixed[comp] = bit

pairs_same = {}
pairs_diff = {}

for u, v in edges:
    for b in range(16):
        cu = comp_val[idv(u, b)]
        cv = comp_val[idv(v, b)]
        if cu == cv:
            continue
        key = (min(cu, cv), max(cu, cv))
        parity = (cu > cv) ^ 0  # relative constant absorbed
        if key not in pairs_same:
            pairs_same[key] = 0
            pairs_diff[key] = 0
        # cost contributes either same or diff; XOR structure
        pairs_diff[key] += 1

components = list(range(C))
free = [i for i in components if i not in fixed]

best = 10**18

def dfs(idx, assign):
    global best
    if idx == len(free):
        val = fixed.copy()
        for i, c in enumerate(free):
            val[c] = assign[i]
        cost = 0
        for (a, b), w in pairs_diff.items():
            if val[a] != val[b]:
                cost += w
        best = min(best, cost)
        return

    c = free[idx]
    for v in [0, 1]:
        assign.append(v)
        dfs(idx + 1, assign)
        assign.pop()

dfs(0, [])

print(best)
```実装は、すべての (ノード、ビット) 変数に対してパリティ DSU を構築することから始まり、すべての制約が一貫して適用されるようにします。 次に、変数をコンポーネントに圧縮し、各コンポーネントに代表的なブール ID を割り当てます。 固定ノード値は、これらのコンポーネントに直接制約を課します。 

その後、エッジの寄与は単純化された形式で集計されます。各ビットは独立して寄与するため、コストの累積には 2 つのコンポーネントが異なるかどうかだけが問題となります。 最後に、制約のないコンポーネントの数が少ないため、すべての割り当てを列挙し、総コストを計算します。 

重要な点は、各共用体が制約の片側を反転する可能性があるため、DSU でパリティを正しく維持することです。 もう 1 つの微妙な点は、固定ノード値をコンポーネント レベルの制約に変換する必要があることです。 そうしないと、一貫性のない割り当てがすり抜けてしまう可能性があります。

 ## 特殊なケース

 1 つのエッジ ケースは、制約が変数をその否定に等しくするパリティ サイクルを形成するときに発生します。 このような場合、DSU 結合中に、同じセット内にすでに存在する 2 つの変数が矛盾したパリティを必要としていることが検出され、すぐに -1 が返されます。 

もう 1 つのケースは、すべてのノードが完全に制約されていない場合です。 その後、すべてのビットをすべてのノードにわたって均一に設定し、すべてのエッジの寄与をゼロにすることができます。 このアルゴリズムはすべてのコンポーネントを正しく折りたたみ、列挙を入力せずにゼロコストを返します。 

3 番目のケースは、制約がビットのサブセットにのみ影響する場合です。 DSU は、それらのビットのみがコンポーネントにグループ化されることを保証しますが、変更されていないビットは独立したままであり、コストの差に寄与しないため、それらのビットは事実上、最適化とは無関係になります。
