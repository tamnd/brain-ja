 ## 解決策
 ## 問題の理解

 多くの正の整数が与えられており、それぞれについて、その適切な約数がどの程度「リッチ」であるかを決定する必要があります。 数字の場合$n$を除くすべての約数を考慮します。$n$それ自体を合計し、その合計を比較します$n$。 合計が大きければその数は豊富と呼ばれ、小さければ不足しており、等しい場合は完全と呼ばれます。 

入力は基本的にクエリの大規模なバッチです。 各クエリは最大 100 万の整数であり、そのようなクエリは最大 100 万個存在する可能性があります。 出力は数値ごとの分類文字列であるため、重要な課題は単一の約数の合計を計算することではなく、多数の反復クエリにわたって非常に高速に計算することです。 

この制約により、クエリごとに除数を最初から再計算することが直ちに除外されます。 単純な除数スキャンは次のようになります。$n$最悪の場合、すでに 1 つのクエリに対して遅すぎるため、さらに次のように乗算されます。$10^6$クエリは不可能になります。 までスキャンしても$\sqrt{n}$この規模では、クエリごとの負荷は依然として重すぎます。 

微妙な特殊なケースは、合計が数値と正確に等しい完全数から発生します。 たとえば、6、28、496 です。数値自体を除外するのを忘れた不注意な実装では、常に数値が誤って「豊富」として分類されます。これは、完全な約数の合計には常に次の値が含まれるためです。$n$。 

もう 1 つの特殊なケースは、クエリが繰り返されることです。 入力には同じ数値が何度も含まれる可能性があるため、除数の合計を毎回再計算するのは無駄な作業であり、TLE が発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 各数値に対して$n$、1 から 1 までを繰り返します。$n-1$、割り算を確認し、約数の合計を累積します。 これはアリコート合計の定義に直接従うため、正しいです。 ただし、各クエリにはコストがかかります$O(n)$、そして$n$まで$10^6$そして$10^6$クエリの合計操作数は次のように縮退します。$10^{12}$、これは実現可能な限界をはるかに超えています。 

標準的な改善策は、次の範囲までの約数のみをチェックすることです。$\sqrt{n}$、両方を追加します$d$そして$n/d$いつ$d$分割する$n$。 これにより、単一のクエリが次のように削減されます。$O(\sqrt{n})$、しかし、$10^6$クエリはまだ注文中です$10^9$これは Python では境界線にあり安全ではありません。 

重要な観察は、値の範囲が小さくて固定されていることです。すべての数値は 1 から 1 までの間にあります。$10^6$。 クエリごとに約数の合計を再計算する代わりに、ふるいのような累算を使用して、この範囲内のすべての数値の適切な約数の合計を一度事前計算できます。 各整数$d$すべての倍数に寄与する$d$, そのため、約数を反復して寄与を効率的に伝播できます。 これにより、問題が古典的な除数和ふるいに変換され、繰り返しの計算が完全に削減されます。 

事前計算が完了すると、各クエリは単純な配列の検索と比較になります。

 | ブルートフォース |$O(T \cdot n)$|$O(1)$| 遅すぎる |
 | クエリごとの平方根 |$O(T \sqrt{n})$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 までのすべての数値の適切な約数の合計が必要です。$10^6$。 各数値を個別に処理するのではなく、視点を逆転させ、考えられるそれぞれの約数を「前進させる」ようにします。 

1. 配列を作成する`s`サイズの$N+1$、ゼロに初期化されます。`s[x]`の適切な約数の合計を格納します$x$。 含まれません$x$したがって、それ自身のインデックスに数値を追加しないようにします。 
2. すべての整数について$d$1から$N/2$、すべての倍数を繰り返します$m = 2d, 3d, 4d, \dots$。 そのような複数のそれぞれについて$m$、追加します$d$の中へ`s[m]`。 これが機能する理由は、$d$は、それ自体よりも厳密に大きいすべての倍数の適切な約数です。 
3. このプロセスの後、`s[n]`すべての適切な約数の正確な合計が含まれます。$n$なぜなら、すべての約数が$d < n$倍数に 1 回だけ寄与します。 
4. 各クエリについて$n_i$、比較します`s[n_i]`と$n_i$。 もし`s[n_i] > n_i`、豊富に出力します。 もし`s[n_i] < n_i`, we output deficient. それ以外の場合は、完璧な出力が行われます。 

Why it works comes down to a clean counting invariant. Every pair$(d, m)$どこ$d$分割する$m$そして$d < m$処理時に 1 回だけ追加されます$d$。 各約数がすべての倍数を独立して担当し、正確性を損なう形で範囲境界を超える数値に寄与する約数は存在しないため、重複はありません。 その結果、各数値は、その適切な約数の合計だけが累積され、それ以外は何も累積されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

# precompute sum of proper divisors
s = [0] * (MAXN + 1)

for d in range(1, MAXN // 2 + 1):
    for m in range(2 * d, MAXN + 1, d):
        s[m] += d

t = int(input())
nums = list(map(int, input().split()))

out = []
for x in nums:
    if s[x] > x:
        out.append("abundant")
    elif s[x] < x:
        out.append("deficient")
    else:
        out.append("perfect")

sys.stdout.write("\n".join(out))
```実装の中心となる詳細は sieve ループです。 外側のループは約数の候補を選択し、内側のループはそれをすべての倍数に分配します。 内側のループを開始する`2*d`数値自体をその除数の合計から明示的に除外するため、これは重要です。 

もう 1 つの微妙な点は、次までを 1 回事前計算することです。$10^6$入力サイズに関係なく。 これにより、高価な作業が確実に償却され、各クエリが一定時間になります。 

比較ステップは直接的であるため、`s[x]`すでに除外しています`x`それ自体は構造によるものです。 

## 実用的な例

 サンプル値 12、21、および 28 を使用します。 

12 の場合、その適切な約数は 1、2、3、4、6 です。事前計算ビルドは`s[12] = 16`。 21 の場合、約数は 1、3、7 になります。`s[21] = 11`。 28 の場合、約数は 1、2、4、7、14 になります。`s[28] = 28`。 

| 番号 | 累積された適切な約数 | s(n) | 比較 |
 | --- | --- | --- | --- |
 | 12 | 1、2、3、4、6 | 16 | 16 > 12 |
 | 21 | 1、3、7 | 11 | 11 < 21 |
 | 28 | 1、2、4、7、14 | 28 | 28 = 28 |

 このトレースは、ふるいが除数の寄与を正しく蓄積し、分類が最終的な定数時間の比較のみに依存していることを確認します。 

2 番目の小さな例は 6 です。前処理中に、1、2、および 3 から寄与が得られ、次の結果が生成されます。`s[6] = 6`、これは正しく完璧なカテゴリに分類されます。 これにより、アルゴリズムが対称除数構造を正しく処理することが検証されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N \log N + T)$| 各整数はその倍数に寄与を分配し、調和系列が全体の演算を制限します。 クエリはそれぞれ O(1) です。 
| スペース |$O(N)$| すべての整数の約数の合計を次の値まで保存します。$10^6$|

 前処理コストは十分に制限内にあります。$N = 10^6$、その後はそれぞれ$10^6$クエリは単なる比較です。 これにより、時間とメモリの制約の両方に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    MAXN = 10**6
    s = [0] * (MAXN + 1)

    for d in range(1, MAXN // 2 + 1):
        for m in range(2 * d, MAXN + 1, d):
            s[m] += d

    t = int(input())
    nums = list(map(int, input().split()))

    res = []
    for x in nums:
        if s[x] > x:
            res.append("abundant")
        elif s[x] < x:
            res.append("deficient")
        else:
            res.append("perfect")

    return "\n".join(res)

# provided sample
assert run("3\n12 21 28") == "abundant\ndeficient\nperfect"

# minimum case
assert run("1\n1") == "deficient"

# perfect number check
assert run("2\n6 28") == "perfect\nperfect"

# abundant small case
assert run("1\n12") == "abundant"

# mixed case
assert run("5\n2 3 4 5 6") == "deficient\ndeficient\ndeficient\ndeficient\nperfect"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 不足している | 最小境界の場合 |
 | 6、28 | 完璧 | 既知の完全数 |
 | 12 | 豊富 | 最小の豊富な例 |
 | 2,3,4,5,6 | 混合 | 分類の正確性 |

 ## 特殊なケース

 入力用`1`、ふるいは与えます`s[1] = 0`1 には適切な約数がないからです。 このアルゴリズムは 0 < 1 を比較し、不足しているものを正しく出力します。 これは、除数セットが空である境界ケースを捕捉します。 

のために`6`、前処理により 1、2、および 3 からの寄与が追加され、次のようになります。`s[6] = 6`。 等価性チェックにより完璧がトリガーされ、誤って 6 自体がその合計に含まれることがないことが確認されます。 

のために`28`、1、2、4、7、および 14 からの寄与は正確に 28 まで累積されます。各約数は独立して処理されるため、二重カウントは発生せず、アルゴリズムは確実にそれを完全なものとして分類します。
