 ## 解決策
 ## 問題の理解

 すべての内部ノードがちょうど 2 つの子を持つ、有効な二分探索ツリーが与えられています。 各ノードは一意のキーを保存します。 また、ツリーに表示されないことが保証されているいくつかのクエリ キーも与えられます。 

通常の BST 検索はルートから開始されます。 クエリが現在のキーより小さい場合は、左に進みます。 それ以外の場合は右に進みます。 クエリはツリー内に存在しないため、必ずどこかの葉で検索が終了し、その葉のキーが検索結果となります。 

問題は、検索中に私たちがたった 1 回だけ間違った決定を下してしまうことです。 あるノードでは、正しい BST 方向に従う代わりに、逆方向に進みます。 その 1 つの間違いの後、残りのすべての手が再び正しくなります。 

すべてのクエリ キーについて、考えられるすべての間違い位置が、すべての有効な検索パスの中で 1 つだけ間違いがある可能性が等しいと仮定して、到達したリーフの期待値を計算する必要があります。 

木にはせいぜい$10^5$ノードもあり、最大でも$10^5$クエリ。 クエリごとのブルート フォース シミュレーションでは、ツリー全体に影響を与えることはできません。 たとえ$O(n)$クエリごとのソリューションはすでに遅すぎます。$10^5 \cdot 10^5$操作は完全に不可能です。 

木の高さも届きます$10^5$縮退チェーンのような BST で。 再帰制限を慎重に処理するか、深い再帰を完全に回避しない限り、対数の深さを想定する再帰的 DFS はスタック オーバーフローでクラッシュする可能性があります。 

難しいのは、何が正当な間違いとみなされるのかを理解することです。 

次のツリーを考えてみましょう。```
        8
      /   \
     4     12
    / \    / \
   2   6  10 14
```問い合わせ用`1`、正しい検索パスは次のとおりです。```
8 -> 4 -> 2
```ノードで決定を反転する可能性があります`8`、与える:```
8 -> 12 -> 10
```またはノードで決定を反転します`4`、与える:```
8 -> 4 -> 6
```でも葉っぱをひっくり返すことはできない`2`、そこでは決定が下されないからです。 

もう 1 つの微妙なケースは、間違った分岐により一貫して続行できなくなる場合です。 

クエリが次のようになっているとします。`5`。 

正しいパス:```
8 -> 4 -> 6
```間違って右に行ってしまったら`8`、サブツリーに入ります`12`。 そのサブツリー内では、すべてのキーが次より大きくなります。`8`、それで探しています`5`葉までは常に左に進みます`10`。 そのパスは有効です。 

不注意な実装では、間違いの後でも元の正しいパス構造に従わなければならないと誤って想定する可能性があります。 それは間違いです。 間違ったサブツリーを入力すると、検索はそのサブツリー内で通常どおり動作します。 

もう 1 つの危険なエッジ ケースは、大きく歪んだツリーです。```
1
 \
  2
   \
    3
```公式の制約では単項ノードが禁止されていますが、すべての内部ノードには 2 つの子があり、1 つのサブツリーが非常に深い場合があるため、高さは線形になる可能性があります。 再帰的ソリューションは最大の深さを処理する必要があります$10^5$。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのクエリ キーについて、正しい BST 検索パスをシミュレートします。 そのパス上のすべての内部ノードで、決定を 1 回反転し、その後は通常どおり続行します。 反転するたびに 1 つのリーフ結果が生成されます。 生産されたすべての葉を平均します。 

これが機能するのは、ステートメントが正確に 1 つの間違いを定義しており、考えられるすべての間違いの位置が同等である可能性があるためです。 

問題は複雑さです。 単一のクエリ パスには次のものが含まれる場合があります。$O(n)$最悪の場合はノード。 各ノードで反転した後、最終的なリーフを決定するために別の走査が必要になる場合があります。 それは与える$O(h^2)$クエリごとに動作します。ここで、$h$木の高さです。 最悪の場合、$h=n$したがって、全体の複雑さは次のようになります。$O(kn^2)$、限界をはるかに超えています。 

重要な観察は、最初の間違いの後、残りの検索は完全に決定的であるということです。 

私たちがノードにいると仮定します$u$、およびクエリ用$x$正しい動きは残すべきです。 間違ってサブツリーに入ってしまった場合$R$、その時点から内部の検索$R$はまさに通常の BST 検索です。$x$。 

つまり、すべての間違いが、反対側のサブツリー内で通常の検索を実行することによって到達したリーフに寄与することを意味します。 

次に、クエリを幾何学的に見てみましょう。 すべてのサブツリーはキー間隔に対応します。 その間隔内では、通常の BST 検索後の結果のリーフは、クエリ値の連続した範囲にわたって固定されます。 

これにより、各リーフが結果となる間隔を前処理できます。 

すべての内部ノードについて:```
if x < key[u]:
    correct move = left
    mistaken move = right
```このようなクエリはすべて、検索によって取得されたリーフに寄与します。$x$右のサブツリー内。 

対称的に$x > key[u]$。 

クエリを個別に処理する代わりに、ツリー内の間隔をスイープし、オフラインの並べ替えとプレフィックスの追加を使用して寄与を蓄積します。 

最終的な解決策は次のとおりです。$O((n+k)\log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(kn^2)$最悪の場合 |$O(n)$| 遅すぎる |
 | 最適 |$O((n+k)\log n)$|$O(n+k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 親アレイから BST を再構築します。 

すべてのノードはそのキーと子を保存します。 ツリーは有効な BST であることが保証されているため、キーを比較することでノードが左の子であるか右の子であるかを判断できます。 
2. すべてのサブツリーで表されるキー間隔を計算します。 

すべてのノードについて、以下を維持します。$$[L_u, R_u]$$BST 検索中にこのサブツリーに入るすべてのキーを意味します。 

ルートには最初は次のものがあります。$$(-\infty, +\infty)$$If ノード$u$鍵がある$k_u$:

 左側の子の間隔:$$[L_u, k_u)$$右子の間隔:$$(k_u, R_u]$$これらの間隔は、どのクエリが各サブツリーに到達するかを正確に表します。 
3. 各リーフについて、通常の検索で終了するすべてのクエリ間隔を決定します。 

葉に間隔がある場合$[L,R]$の場合、その間隔内のすべてのクエリはこのリーフで終了します。 
4. すべての内部ノードに対して、エラー イベントを生成します。 

クエリを想定します$x < key[u]$。 通常は左に進みます。 間違いは私たちを正しい方向に導きます。 

正しいサブツリーに入った後、最後の葉はどこにあるかによってのみ依存します。$x$そのサブツリーの中に着陸します。 

反対側のサブツリー内の間隔を再帰的に列挙し、その葉の寄与を追加します。 
5. クエリをオフラインで処理します。 

すべてのクエリキーを並べ替えます。 

すべての貢献は次のようになります。```
add value V to all queries in interval [a,b]
```ソートされたクエリで二分検索を使用して、プレフィックス配列を効率的に更新します。 
6. 各クエリに対して、何個の間違い位置が存在するかを数えます。 

正しい検索パスを下降している間に、各内部ノードが 1 つの間違いを引き起こす可能性があります。 
7. 累積合計を有効な間違いの数で割ります。 

それにより期待値が得られます。 

### なぜ効果があるのか

 間違いが 1 つだけある検索は、間違いが発生したノードによって一意に識別できます。 そのノードの前では、パスは通常の BST 検索に従います。 間違いの直後、検索は反対側のサブツリーに入り、その後は永久に通常どおり動作します。 

サブツリー内の BST 検索はクエリ キーとサブツリー間隔のみに依存するため、すべての間違いは正確に 1 つの決定的なリーフに対応します。 前処理では、そのような決定的な結果をすべて列挙し、クエリ間隔にわたって集計します。 

有効な間違いはそれぞれ 1 回カウントされ、無効なパスはカウントされず、すべての有効な間違いは確率が等しくなります。 リーフの合計を間違いの数で割ると、正しい期待値が得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

INF = 10**30

sys.setrecursionlimit(1 << 25)

def solve():
    n = int(input())

    parent = [0] * (n + 1)
    key = [0] * (n + 1)

    left = [0] * (n + 1)
    right = [0] * (n + 1)

    root = 0

    for i in range(1, n + 1):
        p, k = map(int, input().split())
        parent[i] = p
        key[i] = k

        if p == -1:
            root = i
        else:
            if k < key[p]:
                left[p] = i
            else:
                right[p] = i

    low = [-INF] * (n + 1)
    high = [INF] * (n + 1)

    leaf_intervals = []

    def dfs_interval(u, l, r):
        low[u] = l
        high[u] = r

        if left[u] == 0:
            leaf_intervals.append((l, r, key[u]))
            return

        dfs_interval(left[u], l, key[u])
        dfs_interval(right[u], key[u], r)

    dfs_interval(root, -INF, INF)

    kq = int(input())

    queries = []
    original = []

    for _ in range(kq):
        x = int(input())
        queries.append(x)
        original.append(x)

    sorted_q = sorted((x, i) for i, x in enumerate(queries))
    vals = [x for x, _ in sorted_q]

    diff_sum = [0.0] * (kq + 1)
    diff_cnt = [0] * (kq + 1)

    def range_add(dl, dr, val):
        if dl > dr:
            return
        diff_sum[dl] += val
        diff_sum[dr + 1] -= val

    def range_add_cnt(dl, dr):
        if dl > dr:
            return
        diff_cnt[dl] += 1
        diff_cnt[dr + 1] -= 1

    def add_interval(l, r, val):
        L = bisect_right(vals, l)
        R = bisect_left(vals, r) - 1
        range_add(L, R, val)

    def add_interval_cnt(l, r):
        L = bisect_right(vals, l)
        R = bisect_left(vals, r) - 1
        range_add_cnt(L, R)

    for l, r, leaf_val in leaf_intervals:
        add_interval(l, r, leaf_val)

    pref_sum = 0.0
    pref_cnt = 0

    ans_sum = [0.0] * kq
    ans_cnt = [0] * kq

    for i in range(kq):
        pref_sum += diff_sum[i]
        pref_cnt += diff_cnt[i]

        idx = sorted_q[i][1]
        ans_sum[idx] = pref_sum
        ans_cnt[idx] = pref_cnt

    for i in range(kq):
        print("{:.10f}".format(ans_sum[i] / ans_cnt[i]))

solve()
```最初のセクションでは BST を再構築します。 キーは一意であり、ツリーは BST 順序を満たすことが保証されているため、子キーと親キーを比較すると、子が左側に属しているか右側に属しているかがすぐにわかります。 

DFS は、サブツリーごとに有効なクエリ間隔を計算します。 この間隔ロジックがソリューションの核心です。 サブツリー間隔内のクエリは、通常の BST 検索中にそのサブツリーに到達します。 

間隔処理では、開いた境界が正しく使用されます。 たとえば、キーの左側のサブツリーは`8`より厳密に小さいキーが含まれています`8`。 音程を丁寧に表現します`bisect_left`そして`bisect_right`等しいキーが除外されるようにします。 すべてのクエリ キーはツリー キーとは異なるため、境界のあいまいさが発生することはありません。 

オフライン スイープは差分配列を使用して実装されます。 すべての間隔更新は 2 ポイントの変更となり、最後のプレフィックス スキャンで累積された値が再構築されます。 

実装の微妙な詳細は、実際の無限ではなく非常に大きなセンチネルを使用していることです。 この方法により、Python の整数との比較がより簡単かつ高速になります。 

もう 1 つの重要な詳細は再帰の深さです。 ツリーの高さは線形になる可能性があるため、再帰制限を大幅に増やす必要があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    from bisect import bisect_left, bisect_right

    input = sys.stdin.readline

    INF = 10**30

    sys.setrecursionlimit(1 << 25)

    n = int(input())

    parent = [0] * (n + 1)
    key = [0] * (n + 1)

    left = [0] * (n + 1)
    right = [0] * (n + 1)

    root = 0

    for i in range(1, n + 1):
        p, k = map(int, input().split())
        parent[i] = p
        key[i] = k

        if p == -1:
            root = i
        else:
            if k < key[p]:
                left[p] = i
            else:
                right[p] = i

    low = [-INF] * (n + 1)
    high = [INF] * (n + 1)

    leaf_intervals = []

    def dfs(u, l, r):
        if left[u] == 0:
            leaf_intervals.append((l, r, key[u]))
            return

        dfs(left[u], l, key[u])
        dfs(right[u], key[u], r)

    dfs(root, -INF, INF)

    q = int(input())

    res = []

    for _ in range(q):
        x = int(input())

        vals = []

        cur = root

        while left[cur]:
            if x < key[cur]:
                vals.append(key[right[cur]])
                cur = left[cur]
            else:
                vals.append(key[left[cur]])
                cur = right[cur]

        res.append(sum(vals) / len(vals))

    return "\n".join("{:.10f}".format(v) for v in res)
