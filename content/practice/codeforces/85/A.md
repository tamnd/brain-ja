 ## 解決策
 ## 問題の理解

 をタイル表示する必要があります`4 × n`普通のドミノを使ったボード。 各ドミノは、水平方向または垂直方向に、ちょうど 2 つの隣接するセルをカバーします。 

タイリングは追加の条件を満たす必要があります。 柱の間のすべての垂直カット`i`そしてコラム`i + 1`少なくとも 1 つの水平ドミノをスライスする必要があります。 カットがどのドミノとも交差しない場合、ボードはその位置で 2 つの独立した部分に分割される可能性があり、これは禁止されています。 

出力形式ではドミノの座標は要求されません。 代わりに、カラーボードを印刷します。 同じドミノに属するセルには、同じ小文字が含まれている必要があります。 異なるドミノは文字を再利用できますが、同じ文字を持つ 2 つのドミノの端が接触することはできません。 

ボードの幅は最大です`100`、小さいです。 課題はパフォーマンスではなく、有効なパターンを正しく構築することです。 

まず注目すべきはパリティです。 あ`4 × n`ボードには`4n`セルは常に均等であるため、領域だけがタイリングをブロックすることはありません。 実際の制限はカット条件によって決まります。 

考慮する`n = 1`。 カットがまったくないので、どんなタイルでも機能します。 

ここで考えてみましょう`n = 2`。 2 つの列の間に、カットが 1 つだけあります。 そのカットを横切るには、それらの列にまたがる少なくとも 1 つの水平ドミノが必要です。 横に 1 つのドミノを配置すると、残りの 6 つのセルが奇数のサイズで切断された領域を形成するため、制約の下では完成が不可能になります。 より一般的には、交差するドミノがそれぞれの側から 1 つのセルを消費し、残りの領域が常に一貫してタイル化されるとは限らないため、幅が奇数であると問題が発生します。 

小さな例でこれを示します。 

入力:```
3
```不用意なアプローチをすると、次のようなことが起こる可能性があります。```
aab
ccb
dde
ffe
```柱の間のカット`2`そして`3`交差していますが、柱の間の切れ目`1`そして`2`そうではありません。 左側の 2 つの列は、完全に別個のコンポーネントを形成します。 

の正解は、`n = 3`実際には不可能です。 

もう 1 つの簡単な間違いは、ドミノをタッチするために同じ文字を使用することです。 例えば：```
aabb
aabb
ccdd
ccdd
```これは視覚的にはきれいに見えますが、ラベルが付けられた 2 つの垂直ドミノ`a`エッジに沿って互いに接触しているため、カラーリングのルールに違反します。 等しい文字は、同じドミノ、または少なくとも 1 つのセルで区切られたドミノにのみ属することができます。 

構築は、タイリングの正確性、カットカバレッジ、および色の制約を同時に満たさなければなりません。 

## アプローチ

 最も直接的なアイデアは、総当たり検索です。 ドミノをあらゆる可能な方向に再帰的に配置し、すべての垂直方向のカットが少なくとも 1 つの水平方向のドミノによって横切られているかどうかを検証できます。 あ`4 × 100`ボードには含まれています`400`細胞があるので、`200`ドミノ。 はるかに小さなボードの場合でも、タイリングの数は指数関数的に増加します。 徹底的な検索は完全に非現実的になります。 

問題の構造は別の方向性を示唆しています。 タイリングを数えたり、何かを最適化したりすることは求められません。 有効な構築は 1 つだけ必要です。 

それは考え方を完全に変えます。 すべてのタイリングの中から検索する代わりに、繰り返しパターンを構築してみることができます。 

重要な観察は、すべてのカットを横断する必要があるということです。 これを保証する最も簡単な方法は、水平ドミノを全面的に定期的に出現させることです。 基板の高さは固定されているので、`4`、幅のブロックで考えることができます`2`。 

あ`4 × 2`ブロック全体を水平ドミノでタイル状に並べることができます。```
a a
b b
c c
d d
```すべてのドミノはブロック内の切れ目を横切ります。 このようなブロックを連結すると、連続する列間のすべてのカットが交差します。 

これは次の場合に完全に機能します`n`は均等です。 奇数の場合`n > 1`、有効な構造が存在しません。 公式の建設的な解決策は、この同等の事実に基づいています。 

実装は簡単になります。 ボードを一度に 2 列ずつ処理し、各行を新しい文字のペアで埋めます。

 ## アルゴリズムのチュートリアル

 1. 幅を読み取る`n`。 
2. もし`n`奇数であり、より大きい`1`、印刷`-1`。 

有効な構造は、偶数の幅と自明な場合にのみ存在します。`n = 1`。 
3.ハンドル`n = 1`別に。 

1 つの列にはカットがないため、2 つの垂直ドミノで十分です。```
a
a
b
b
```4. 偶数の場合`n`を作成します。`4 × n`グリッド。 
5. 列をペアで処理します。`(0,1)`、`(2,3)`、`(4,5)`、 等々。 
6. 列の各ペア内に、各行に 1 つずつ、4 つの水平ドミノを配置します。 

例えば：```
a a
b b
c c
d d
```すべてのドミノは、これら 2 つの柱の間の切れ目を横切ります。 
7. 隣接するドミノには異なる文字を使用します。 

アルファベットを安全に循環させることで、偶発的なエッジ共有の競合を回避できます。 
8. 完成したグリッドを印刷します。 

### なぜ効果があるのか

 2 列ブロック内のすべての行は互いに素なペアに分割されるため、各セルは 1 つのドミノにのみ属します。 

すべての垂直カットは、正確に 1 つの処理された 2 列ブロック内にあります。 このブロックにはカットをまたぐ 4 つの水平ドミノが含まれているため、カット条件は自動的に満たされます。 

隣接するドミノは常に異なる文字を受け取るため、同じ文字が競合を引き起こすことはありません。 対応するドミノは接触しないため、遠く離れた文字を再利用しても害はありません。 

奇数の不可能性`n > 1`パリティ引数から次のようになります。 すべてのカットは、少なくとも 1 つの水平ドミノで交差する必要があります。 このような交差はカバーされていない領域のパリティと相互作用するため、幅が奇数の場合は完全なタイリングが不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n % 2 == 1 and n > 1:
        print(-1)
        return

    if n == 1:
        print("a")
        print("a")
        print("b")
        print("b")
        return

    grid = [[''] * n for _ in range(4)]

    letters = "abcdefghijklmnopqrstuvwxyz"
    ptr = 0

    for col in range(0, n, 2):
        for row in range(4):
            ch = letters[ptr % 26]
            ptr += 1

            grid[row][col] = ch
            grid[row][col + 1] = ch

    for row in grid:
        print("".join(row))

solve()
```実装は構築を直接反映します。 

最初のブランチは不可能な幅を処理します。 1 より大きい奇数の幅は条件を満たさないため、すぐに終了します。 

の`n = 1`ケースは縦のカットが無いので特殊です。 2 つの垂直ドミノがボードを完全に埋めます。 

均一な幅の場合、ボードは 2 列のブロックで処理されます。 各ブロック内では、各行に 1 つの水平ドミノが配置されます。 両方のセルに同じ文字を割り当てると、必要な出力形式でドミノが表されます。 

文字ポインタは、モジュロを使用してアルファベットを循環します。`26`。 ボードには最大でも次の内容が含まれます`200`ドミノのように文字が繰り返されますが、繰り返しの間隔は遠く離れており、隣接する同じ色のドミノが作成されることはありません。 

細かい点の 1 つはインデックスです。 いつもアクセスしてるので`col + 1`、ループは次の分だけ進む必要があります。`2`均等な幅でのみ実行されます。 以前のパリティ チェックにより、これが安全に保証されます。
