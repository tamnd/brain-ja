 ## 解決策
 ## 問題の理解

 正の整数の動的セットを 3 つの操作で維持するように求められます。数値の追加、数値の削除、およびセットを並べ替えた後の 5 つの要素の連続する各グループの中央値の合計の計算です。 5 つのグループを並べ替えると、そのグループの中央値が 3 番目の要素になります。 合計演算では、セットが昇順にソートされていることを考慮し、それを 5 つの連続するブロックに分割し、各ブロックの中央値を計算し、これらの中央値をすべて合計する必要があります。 設定サイズが 5 未満の場合は、完全なブロックがないため、合計はゼロになります。 

入力は最大 100,000 の演算で構成され、関与する整数は最大 10^9 になります。 n は 10^5 に達する可能性があるため、合計クエリごとに完全なセットを繰り返しソートするソリューションは、コストが O(n log n) となり、遅すぎる可能性があります。 特に、最悪の場合、各操作の後にソートを繰り返すと、合計操作数が O(n^2 log n) となり、実用的な制限を超えます。 これは、毎回完全に並べ替えることなく、効率的な挿入、削除、中央値の取得を可能にする構造が必要であることを意味します。 

エッジ ケースは、セットの要素が 5 つ未満の場合、中央値が存在しない場合、およびセットのサイズが 5 の倍数ではなく、合計に寄与しないはずの不完全なブロックが最後に残る場合に発生します。 もう 1 つの微妙なケースは、同じ数値を追加および削除する操作を繰り返すことですが、これによって中央値の計算や順序が崩れることはありません。 

## アプローチ

 ブルートフォース手法は単純です。セットをリストとして維持し、合計クエリごとにリストを並べ替え、5 つのグループを反復処理し、各グループの 3 番目の要素を取得してそれらを合計します。 これは正しいです。並べ替えによって中央値の計算に必要な順序が生成されるからです。 ただし、最大 100,000 個の要素の毎回の並べ替えにかかる時間は O(n log n) であり、最大 100,000 回の操作では合計時間が O(n^2 log n) に達する可能性があり、これでは遅すぎます。 

最適化に関する重要な洞察は、クエリごとにセット全体を並べ替える必要がないということです。 5 つの要素の連続するすべてのブロックの中央値のみを考慮します。 これは、効率的な挿入、削除、および順序統計クエリをサポートするバランスの取れた二分探索ツリーまたは順序付きセット データ構造を使用することを示唆しています。 Python では、`SortedList`から`sortedcontainers`は、インデックスによる O(log n) の挿入、削除、および O(1) のアクセスを提供するため、理想的です。 これにより、セットの並べ替えられたビューを常に維持し、合計クエリごとに O(n) の中央値の合計を計算できます。これは、制約を考慮すると許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 合計あたり O(n log n) | O(n) | 最悪の場合には遅すぎる |
 | SortedList / 注文統計 | 追加/削除ごとに O(log n)、合計ごとに O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のオブジェクトを初期化します。`SortedList`。 この構造では、すべての要素がソートされた順序で維持され、挿入、削除、インデックス付けのための二分検索操作が可能になります。 
2. 入力内の各操作について:

 - の場合`add x`、 入れる`x`に`SortedList`。 挿入により、ソートされた順序が自動的に保持されます。 
- もしそれが`del x`、 取り除く`x`からの`SortedList`。 削除操作でも秩序が維持されます。 
- そうだとしたら`sum`、累計をゼロに初期化します。 並べ替えられたリストを 5 段階ずつ繰り返します。 5 つの要素からなる完全なグループごとに、3 番目の要素 (ブロック内のインデックス 2) を選択し、それを累計に追加します。 すべての完全なグループを処理した後、合計を出力します。 
3. すべての操作に対して繰り返します。 

なぜ効果があるのか​​:`SortedList`常にセットが昇順であることを保証します。 5 つのステップで繰り返し、各ブロックの 3 番目の要素を選択することにより、問題の中央値の定義に直接従うことになります。 この構造の対数挿入と削除により、動的セットでも効率が維持され、直接インデックス作成により中央値取得のための定時間アクセスが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from sortedcontainers import SortedList

def main():
    n = int(input())
    sl = SortedList()
    
    for _ in range(n):
        line = input().split()
        if line[0] == "add":
            x = int(line[1])
            sl.add(x)
        elif line[0] == "del":
            x = int(line[1])
            sl.remove(x)
        else:  # sum
            total = 0
            for i in range(2, len(sl), 5):
                total += sl[i]
            print(total)

if __name__ == "__main__":
    main()
```の`SortedList`注文管理と高速インデックス作成の組み合わせにより選ばれています。 挿入と削除は対数的であるため、セットが大きくなるにつれて速度が低下するのを防ぎます。 sum クエリの反復では、インデックス 2 から始まる 5 つおきの要素にアクセスします。これは、5 つの各ブロックの中央値に正確に対応します。 よくある落とし穴は、インデックス 0 または 1 から開始することです。これにより、間違った要素が選択されてしまいます。 Python の任意の整数サイズにより、オーバーフローの問題が回避されます。
