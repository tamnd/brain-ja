 ## 解決策
 ## 問題の理解

 この問題の各ポーションは、最大 14 の可能な統計の中の統計タイプのサブセットとして見ることができます。 ポーションを購入すると、対象となるすべての統計情報が得られます。主人公は「幸運」であるため、すべてのポーションが成功することが保証されているため、選択した各ポーションはその統計セット全体に決定的に寄与します。 

毎日、必要な統計のサブセットが与えられます。 タスクは、合計コストを最小限に抑えながら、統計セットの結合が必要なすべての統計をカバーするように、ポーションのコレクション (繰り返しは許可されますが、重複して購入しても役に立たないため無関係です) を選択することです。 利用可能なポーション タイプを使用して必要な統計をすべてカバーすることが不可能な場合は、-1 が出力されます。 

重要な構造の詳細は、K ≤ 14 であり、これはすべての統計セットが最大 14 の長さのビットマスクとしてエンコードできることを直ちに意味します。これにより、問題は「小宇宙のサブセット上のサブセット」領域に押し込まれます。ここで、2^K は最大 16384 であり、すべてのマスクに対して動的プログラミングを可能にするのに十分な大きさです。 

N、M ≤ 2 × 10^4 という制約により、すべてのポーションに対するクエリごとの再計算や、組み合わせ検索で毎日個別に解決しようとするアプローチが除外されます。 毎日、ポーションのサブセットを組み合わせようとする単純なアプローチは、指数関数的に爆発的に増加します。 

必要なステータスがどのポーションにもまったく存在しない場合、微妙なエッジケースが発生します。 この場合、答えは常に -1 になります。 ステータスごとのコスト効率によってポーションを貪欲に選択しようとすると、別の失敗モードが発生します。ポーションは任意に重複するため、貪欲な選択により安価な組み合わせがブロックされる可能性があります。 

貪欲な失敗の小さな例は、ポーション A がコスト 5 の {1,2} をカバーし、ポーション B がコスト 5 の {2,3} をカバーし、ポーション C がコスト 6 の {1,3} をカバーする場合です。貪欲な場合は、コスト 10 で 3 つのステータスすべてをカバーするために A と B を選択する可能性がありますが、最適なのは構造に応じて C + A または C + B であり、より複雑なケースでは、貪欲な場合はより劇的に失敗する可能性があります。 正しいソリューションは、組み合わせ全体をグローバルに最適化する必要があります。 

## アプローチ

 強引な解釈では、毎日を独立して扱います。ポーションのサブセットを列挙し、それらのマスクの結合を計算し、必要なマスクをカバーする最小コストを追跡します。 これは問題の定義と直接一致するため正しいですが、検索スペースは 1 日あたり 2^N であり、N = 20000 と天文学的に大きくなります。必要なポーションの数に制限がないため、妥当なサイズまでのサブセットに制限しても失敗します。 

重要な観察は、ポーションのサブセットを明示的に考慮する必要がないということです。 各ポーションは固定マスクに寄与し、ポーションの組み合わせは追加コストを伴うマスクのビットごとの OR に対応します。 これは、小さな宇宙にわたる古典的な「各マスクを形成するための最小コスト」であり、ビットマスクに対する最短パス スタイルの動的プログラミングを使用して、すべてのマスクについて 1 回で解決できます。 

dp[mask] を、その統計セットを正確に達成するための最小コストとして定義します。 各ポーションはトランジションとして機能します。現在のマスクから、追加コストでマスクまたはポーションマスクに移動できます。 これにより、すべてのノードから N 個の遷移が繰り返される 2^K ノードにわたるグラフが形成されます。 クエリごとに完全なグラフ検索を実行する代わりに、ビットマスク空間上のマルチソース最短パスを使用して dp を 1 回計算します。

ただし、すべての状態から N 回の遷移を直接実行すると、遅すぎます (2^K × N 回の遷移)。 重要な改良点は、個々のポーションで dp を初期化し、ビットマスク上で古典的なサブセット DP またはダイクストラのような伝播を使用して、すべてのマスクに対して標準緩和を実行することです。 K が小さいため、これを最大 K ビット遷移を持つ 2^K ノードにわたる最短パスとして扱うことができ、マスクごとに事前計算されたポーション リストを使用するか、ビット操作に対する SPFA スタイルの緩和を使用して最適化されます。 一般に受け入れられているアプローチは、優先キューまたは BFS スタイルの緩和を備えた 0-1 のような緩和構造を使用し、各遷移がマスクを増加させるだけであることを利用します。 

dp が計算されると、dp[required_mask] をチェックすることで各クエリが回答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(M · 2^N) | お(1) | 遅すぎる |
 | 最適なビットマスク最短パス | O((N + 2^K) · 2^K) | O(2^K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ポーションの統計リストを長さ K のビットマスクに変換します。これにより、各ポーションが、どの統計をカバーするかを正確に表す単一の整数状態に圧縮されます。 
2. 統計の各サブセットを達成するための最小コストを表す、サイズ 2^K の dp 配列を無限大で初期化します。 
3. すべてのポーション マスクの dp[mask] = コストを直接設定します。 これは、単一のポーションを購入することが常に有効な戦略であるという事実を説明しています。 
4. すべてのマスクに対してリラックス プロセスを実行します。 到達可能な現在のマスクごとに、各ポーション マスクを適用して、結合されたマスクを更新してみます。 

new_mask = マスク OR ポーションマスク、および dp[新しいマスク] = min(dp[新しいマスク], dp[マスク] + コストポーション)。 

このステップでは、ポーションの組み合わせを伝播し、最終的に複数のポーションの選択が確実に構築されるようにします。 
5. 改善が不可能になるまでリラクゼーションを繰り返します。 マスクはビット単位でしか増加しないため、プロセスはサブセットの有限格子上で収束します。 
6. クエリ日ごとに、必要な統計をビットマスクに変換し、dp[required_mask] を出力します。無限大のままの場合は -1 を出力します。 

### なぜ効果があるのか

 dp 状態は、対象となる統計のサブセットごとに最もよく知られているコストを表します。 有効なポーションのセットはすべて、個々のポーション マスクから始まる一連の OR 演算に対応します。 OR はセットの包含という点で結合的かつ単調であるため、ポーションのあらゆる組み合わせを、繰り返されるペアごとの OR 遷移に分解できます。 この緩和により、マスクに安価な組み合わせが存在する場合は常に、何らかの更新シーケンスを通じて最終的には発見されることが保証されます。 コストは減少するだけであり、マスクは有限であるため、プロセスはすべてのサブセットに対して大域最適に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def main():
    N, M, K = map(int, input().split())
    
    potions = []
    for _ in range(N):
        n, c = map(int, input().split())
        arr = list(map(int, input().split()))
        mask = 0
        for x in arr:
            mask |= 1 << (x - 1)
        potions.append((mask, c))
    
    max_mask = 1 << K
    dp = [INF] * max_mask
    
    for mask, cost in potions:
        if cost < dp[mask]:
            dp[mask] = cost
    
    updated = True
    while updated:
        updated = False
        for mask in range(max_mask):
            if dp[mask] == INF:
                continue
            base_cost = dp[mask]
            for pmask, pcost in potions:
                new_mask = mask | pmask
                new_cost = base_cost + pcost
                if new_cost < dp[new_mask]:
                    dp[new_mask] = new_cost
                    updated = True
    
    for _ in range(M):
        m = int(input())
        arr = list(map(int, input().split()))
        mask = 0
        for x in arr:
            mask |= 1 << (x - 1)
        ans = dp[mask]
        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    main()
```この解決策は、すべてのポーションをビットマスクにエンコードして、統計セットの和集合がビットごとの OR 演算になるようにすることから始まります。 dp 配列には、統計の各サブセットに対して達成可能な最小コストが格納されます。 単一のポーションで dp をシードし、既存の到達可能なマスクと任意のポーションを組み合わせることで潜在的に安価なより大きなマスクを生成するトランジションを繰り返し緩和します。 最適な解決策には 3 つ以上のポーションが必要な場合があり、中間の組み合わせを徐々に発見する必要があるため、ループを繰り返すことが必要です。 

クエリ フェーズは簡単になります。必要な各セットがビットマスクに変換され、O(1) ルックアップで応答されます。 

微妙な点は、コスト累積が繰り返しのない選択を自然に処理するため、「正確に k 個のポーション」を追跡したり、選択順序に構造を強制したりしようとしないことです。 

## 実用的な例

 ### サンプル 1

 まずポーションをマスクに変換します。 関連コストを伴うマスク P1、P2、P3 があるとします。 

単一のポーションのコストで dp を初期化し、組み合わせを伝播します。 

| ステップ | マスク検討 | アクション | dpアップデート |
 | --- | --- | --- | --- |
 | 初期化 | P1 | dp[P1]=c1 | セット |
 | 初期化 | P2 | dp[P2]=c2 | セット |
 | リラックス | P1 | P1 または P2 | dp[P1∪P2]=分 |
 | リラックス | P2 | P2 または P3 | dp[P2∪P3]=分 |

 収束後、dp には、到達可能なすべてのステータスの組み合わせに対する最良のコストが含まれます。 クエリ マスクは直接検索され、出力 4、4、8 が生成されます。 

これは、明示的な列挙ではなく、OR 伝播の繰り返しによって複数のポーションの組み合わせがどのように形成されるかを示しています。 

### サンプル 2

 日数が少なくなると、同じ dp テーブルが 1 回構築されます。 

| ステップ | マスク | dp値 |
 | --- | --- | --- |
 | 初期化 | ポーションマスク | 基本コスト |
 | リラックス | 組み合わせマスク | 更新されました |
 | クエリ | フルマスク | 7 |

 これは、クエリが 1 つしか存在しない場合でも、完全な前処理によって最適な組み合わせが正しく取得されることを示しています。

| スペース | O(2^K) | すべての統計サブセットにわたる DP 配列 |

 ## 特殊なケース

 直接的な失敗のケースは、必要なステータスがどのポーションにも表示されない場合に発生します。 その状況では、そのビットを含むすべての dp マスクは無限大のままになります。 緩和なしでは欠落したビットを到達可能な状態に導入できないため、アルゴリズムは正しく -1 を返します。 

もう 1 つのエッジ ケースは、最適なソリューションを得るために 3 つ以上のポーションを組み合わせる必要がある場合です。 dp はペアごとの組み合わせに限定されず、すでに形成された状態を繰り返し緩和するため、完全なセットに達するまで中間マスクが徐々に蓄積されます。 貪欲なシングルステップの組み合わせではそのようなチェーンを見逃してしまいますが、反復緩和により任意の長さのシーケンスにわたって確実にクロージャを閉じます。 

最後のエッジケースは、複数のポーションが同一のマスクを共有するがコストが異なる場合です。 初期化ステップでは最も安価な直接の代表のみが維持され、後の緩和では最小限のコスト構造が維持され、重複によって遷移が歪められないことが保証されます。
