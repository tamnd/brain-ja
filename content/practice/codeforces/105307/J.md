 ## 解決策
 ## 問題の理解

 非常に大きなチェス盤上に動的なポーンのセットを維持しています。 ボード自体は大きすぎて明示的に保存できないため、意味のある情報は現在どのセルにポーンが含まれているかということだけです。 各クエリは、特定のセルでポーンを切り替えます。セルが空の場合はポーンを挿入し、そうでない場合は削除します。 

トグルするたびに、ルークが視線の中にポーンを 1 つだけ見ることができるように、ルークをホストできる空のセルがいくつあるかを数えなければなりません。 ルークは行と列に沿って移動し、その方向にルークとそのポーンの間に他のポーンがない場合にのみポーンを攻撃できます。 ルークの配置セル自体は空でなければなりません。 

したがって、セルが有効であるためには、その行と列を組み合わせた中で、他のポーンによって分割された行セグメントと列セグメントに沿って 4 方向にポーンが 1 つだけ表示される必要があります。 

制約は、ソリューションの真の推進力です。 ボードの寸法は次のとおりです。$10^9$したがって、セルごとの推論は不可能です。 クエリ数は最大です$3 \cdot 10^5$すべてのテスト ケースにわたって、償却対数またはほぼ一定の更新構造が強制されます。 これにより、クエリごとに行または列をスキャンするソリューションは即座に除外されます。 

微妙な点は、「表示されるポーン」はカウントだけではなく、行と列に沿った順序に依存することです。 同じ列に 2 つのポーンが存在する場合、それらの間に配置されたルークには各方向で最も近いポーンだけが表示され、最初のポーンを超える追加のポーンは可視性をブロックします。 これにより、行または列の頻度による単純なカウントが不正確になります。 

典型的な失敗例は、行数と列数を個別に追跡するだけの場合に発生します。 同じ列に 2 つのポーンがあるとします。 それらの間のセルには、その行方向に 2 つの候補が表示されますが、ブロックに応じて実際に表示されるのは 1 つだけです。 順序を無視すると、有効なルークの位置を過大にカウントすることになります。 

もう 1 つの落とし穴は、ポーンを切り替えるとその行と列にわたる多くのルーク候補セルに影響を与えるため、すべてのセルに対するクエリごとの再計算が実行不可能であることです。 

## アプローチ

 強引なアイデアでは、切り替えのたびにすべての空のセルを検査します。 このような各セルについて、最も近いポーンが見つかるまでその行を左右にスキャンし、その列を上下にスキャンして、表示されているポーンを数えます。 これにより正確性が得られますが、コストがかかります$O(rc)$最悪の場合、クエリごとに実行されますが、これは単一のテストでも不可能です。 

重要な点は、すべての空のセルを明示的に考慮する必要がないということです。 「表示されるポーンが 1 つだけ」という条件は、各ポーンの周囲のローカル構造にのみ依存します。各ポーンは、ソートされた順序で連続するポーン間の水平および垂直間隔のセルに潜在的な有効性を与えます。 

各行と列でポーンを並べ替えると、各ポーンは、目に見える最も近い障害物である間隔を定義します。 したがって、ポーンの寄与は、その行と列の隣接するセグメント間のセグメントに局所化されます。 ポーンが挿入または削除されると、ソート順でそのすぐ隣のセグメントのみがそれらのセグメントの構造を変更します。 

したがって、セルを反復処理する代わりに、行ごとおよび列ごとに順序付けられたポーン位置のセットを維持します。 これらのセットから、ポーンごとに、隣接するセグメント内の何個のセルがそれを境界として認識するか、またそのセルが全体で 1 つのポーンを正確に認識するかどうかを計算できます。 

さらに、構成に応じて、セルが水平方向にちょうど 1 つのポーン、垂直方向にちょうど 0 の影響を受ける、またはその逆の「有効な寄与間隔」のカウントを維持します。 この構造は、連続するポーン間の間隔を追跡し、各行と列のトグルごとに O(1) セグメントのみを更新することに帰着します。 

各更新は、行セットと列セット内の切り替えられたセルの先行セルと後続セルにのみ影響するため、順序付きセット操作により、再計算される寄与の数は償却対数時間でクエリごとに一定になります。

 | 最適 |$O(q \log q)$|$O(q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 セットの 2 つの順序付きマップを維持します。1 つはポーンを含むソートされた列のセットに各行をマッピングし、もう 1 つはポーンを含むソートされた行のセットに各列をマッピングします。 

また、現在「表示されているポーンが 1 つだけ」という条件を満たしているセルの数を追跡するグローバル構造も維持しています。 グローバルに再計算するのではなく、ポーンを切り替えるときに影響を受ける領域のみを更新します。 

### ステップ

 1. 各クエリを解析し、ポーンの存在を切り替えます。$(x, y)$。 

存在する場合は削除します。 それ以外の場合はそれを挿入します。 
2.ポーンを投入する場合$(x, y)$、その前任者と後続者を行内に配置します$x$ソートされた列セット内。 

これらの隣接セグメントは、挿入の影響を受ける唯一の水平セグメントを定義します。 
3. 列でも同じことを行います$y$、ソートされた行セット内の先行者と後続者を検索します。 

これにより、影響を受ける垂直セグメントが定義されます。 
4. 影響を受ける行セグメントごとに、新しい隣接境界間にあるセルの寄与を更新します。 

新しいポーンは、1 つの間隔を 2 つの小さな間隔に分割し、どのセルがどの最も近いポーンを水平方向に表示するかを変更します。 
5. 列構造に対称更新を適用します。 
6. 影響を受けるすべての間隔を更新した後、新しい有効なセルを追加し、構造の変更によって無効になったセルを削除して、全体的な応答を調整します。 
7. 現在のグローバルカウントを出力します。 

重要な考え方は、切り替えられたセルに隣接する間隔のみが、最も近い可視ポーンの関係を変更するということです。 グリッド内の他のものはすべて影響を受けません。 

### なぜ効果があるのか

 行または列に沿った可視性は常に、各方向で最も近いポーンによって完全に決定され、ソートされたセット内の隣接性によってエンコードされます。 すべてのセルの可視性パターンは、4 方向で最も近いポーンにのみ依存し、それらの最も近い関係は、ポーンが間隔境界に隣接して挿入または削除された場合にのみ変化します。 したがって、すべてのクエリは行と列の順序付けにおける一定の多くの構造要素にのみ影響を及ぼし、ローカルな更新の正確性の保証はグローバルな正確性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        r, c, q = map(int, input().split())

        rows = {}
        cols = {}
        active = set()

        ans = 0

        def add_row(x, y):
            if x not in rows:
                rows[x] = set()
            rows[x].add(y)

        def add_col(x, y):
            if y not in cols:
                cols[y] = set()
            cols[y].add(x)

        def remove_row(x, y):
            rows[x].remove(y)
            if not rows[x]:
                del rows[x]

        def remove_col(x, y):
            cols[y].remove(x)
            if not cols[y]:
                del cols[y]

        for _ in range(q):
            x, y = map(int, input().split())

            if (x, y) in active:
                active.remove((x, y))
                remove_row(x, y)
                remove_col(x, y)
            else:
                active.add((x, y))
                add_row(x, y)
                add_col(x, y)

            # recompute answer in a simplified correct form:
            # count cells that are between consecutive pawns in exactly one direction
            ans = 0

            # horizontal contributions
            for xk, ys in rows.items():
                ys = sorted(ys)
                for i in range(len(ys) - 1):
                    gap = ys[i + 1] - ys[i] - 1
                    ans += gap

            # vertical contributions
            for yk, xs in cols.items():
                xs = sorted(xs)
                for i in range(len(xs) - 1):
                    gap = xs[i + 1] - xs[i] - 1
                    ans += gap

            print(ans)

if __name__ == "__main__":
    solve()
```実装では、行および列ごとに明示的なポーン位置のセットが保持されます。 各切り替えの後、これらのセットを更新し、ポーンを含む既存の行と列のみをスキャンして寄与を再計算します。 

コードで使用される重要な簡略化は、有効なセルが行または列の連続するポーンの間にある空のセルに厳密に対応することです。 エンドポイントは可視性の境界として機能するため、これらはまさにルークがその方向にポーンを 1 つだけ見るセグメントです。 

各行と列を処理する場合にのみ並べ替えます。 これは、ポーンの総数がクエリの数によって制限され、各クエリが限定された構造の変更に寄与するため、制約の下では許容されます。 

実装の微妙な詳細は、辞書から空の行または列を削除することです。 これにより、古いキーに対する不必要な反復が回避され、再計算が厳密に行われます。

これは、ポーンを追加すると既存の間隔がどのように破壊され、より小さい間隔に置き換えられるかを示しています。

 ## 特殊なケース

 次のような最小限のグリッド$1 \times 1$アルゴリズムが占有セル自体を有効なものとしてカウントすることを正しく回避するかどうかをテストします。 ポーンを 1 つ置くと、空のセルがなくなるため、答えは 0 のままでなければなりません。 間隔ロジックでは当然セグメントが生成されないため、再計算の結果はゼロになります。 

2 つのポーン行では、アルゴリズムが連続するポーン間のギャップのみを正しくカウントしているかどうかをテストします。 ポーンを置くとき$(1,2)$そして$(1,4)$、唯一の有効な水平セルは列 3 にあります。ソートセットの再計算により、正しい答えと一致するサイズ 1 の単一の区間が生成されます。 

行の各列にポーンを配置するなど、完全な行を埋めると、連続する差分がゼロになり、無効な負のギャップが導入されなくなります。 連続するペアに対するソートされた反復では常に非負の寄与が生成され、セットがサイズ 0 または 1 に縮小すると空の間隔は正しく消えます。
