 ## 解決策
 ## 問題の理解

 いくつかの動物タイプが与えられ、各タイプには特定の数の動物が含まれています。 毎日、動物を追加または減算することで1種類が更新されます。 更新のたびに、サイズのケージの数を計算する必要があります。`k`同じ種類の動物を 2 匹入れてはいけないという制限付きで、ケージを形成することができます。 

ケージは基本的に以下の選択です。`k`動物、すべて異なる種類の動物。 容量で考えると、それぞれのタイプ`i`貢献する`a_i`動物を収容できますが、各ケージにはその種類の動物を最大 1 匹しか収容できません。 それで入力してください`i`せいぜい貢献できる`a_i`ケージへの配置は可能ですが、ケージごとに 1 つまでです。 

それぞれの変更後に、利用可能なすべての動物を使用して形成できるそのようなケージの最大数を出力するように求められます。 

制約は大きく、最大 100,000 の型と 100,000 の更新、最大 10^9 の値があります。 すべてのタイプをスキャンしてクエリごとに答えを最初から再計算するソリューションでは、約 10^10 の操作が発生し、これでは遅すぎます。 操作ごとに対数時間または定数時間での更新とクエリが必要です。 

最後の回答が次のクエリのインデックスに影響を与えるため、微妙な複雑さが生じます。 これは純粋に入力難読化であり、コアの組み合わせ構造には影響しませんが、すべての更新を個別に事前計算することはできないことを意味します。 

分布が大きく偏っている場合、重要なエッジケースが発生します。 1 つのタイプが優勢である場合、「合計を k で割った」ような単純な推論は誤りです。 たとえば、k = 3 でカウント [10, 1, 1] がある場合、合計は 12 になるため、単純な答えは 4 つのケージになりますが、小さいタイプが 2 つしかないため、2 つを超えるケージを形成することはできません。 正解は 2 です。 

もう 1 つの特殊なケースは、すべてのカウントが等しい場合、または k = 1 の場合です。k = 1 の場合、すべての動物は独自のケージを形成するため、答えは単にすべての a_i の合計になります。 

## アプローチ

 効率を少し無視すると、この問題では、複数の容量セットに関する組み合わせの実現可能性の質問に繰り返し答えることが求められます。 

答えを考える直接的な方法は、次のようにしたいと仮定することです。`c`檻。 各ケージに必要なもの`k`異なるタイプなので、すべてのケージにわたって必要です`c * k`課題。 それぞれのタイプ`i`せいぜい貢献できる`a_i`割り当て、およびケージごとに最大 1 つであり、選択するだけの場合は自動的に尊重されます。`c`タイプを繰り返すケージはないため、ケージです。 

したがって、唯一の本当の制約は、これらを配布できるかどうかです。`a_i`単位を`c`サイズのバケットは、タイプごとにバケットごとに最大 1 つです。 これは、タイプごとの上限を考慮した上で、すべてのタイプの合計「使用可能容量」が十分であるかどうかをチェックすることになります。`c`。 

固定の場合`c`、実現可能性は次と同等です。$$\sum \min(a_i, c) \ge c \cdot k$$これは古典的な定式化です。各タイプはケージごとに最大 1 つしか寄与しないため、それを超えると`c`ケージに入れると、その種類の余分な動物は役に立たなくなります。 

したがって、クエリごとに最大値が必要になります。`c`この不等式を満たすこと。 

毎回合計を再計算すると、複雑さは O(NQ) となり、大きすぎます。 

重要な観察は次のとおりです`c`は、合計を k で割った値と、a_i の最大値によって制限されます。 分布を動的に維持することはできますが、それでもすべての要素を含む関数を評価する必要があります。`a_i`。 

しきい値を超えているタイプの数を追跡するデータ構造を維持することで、最初から再計算することを回避します。 式は、型を次のものに分割することに依存します。`a_i >= c`そして持っている人`a_i < c`。 

書き直してみましょう:

 与えられた`c`、定義:

 - 大型タイプ:`a_i >= c`、それぞれが正確に貢献します`c`- 小型タイプ:`a_i < c`、それぞれが貢献します`a_i`それで：$$\sum \min(a_i, c) = c \cdot cnt_{\ge c} + \sum_{a_i < c} a_i$$更新時にこれを効率的に評価する必要があります。 これは、次のことを維持することを示唆しています。 

- 値の頻度構造
 - カウントと値のプレフィックスの合計

 値は最大 1e9 まで可能であるため、値ドメイン上のフェンウィック ツリーまたはセグメント ツリーにカウントを保存できますが、初期値と更新から座標を圧縮します。 

ただし、更新では値が動的に変更されるため、ソートされた値に対するポイント更新とプレフィックス クエリをサポートする必要があります。 

圧縮された値に対してフェンウィック ツリーを介してソートされたマルチセット構造を維持し、以下を保存します。 

- 各値の頻度
 - 値の合計

 次に、任意のしきい値に対して`c`、次のように計算できます。 

- 要素の数 >= c
 - 要素の合計 < c

 これにより、O(log N) で実現可能性を評価できます。 次に二分探索をします`c`。 

以来`c`は最大約 sum/k (≤ 1e14 / 1 ≈ 大きい) ですが、実質的に N * max によって制限されるため、[0, sum/k] を二分探索します。 

各クエリは O(log N * log MAX) になります。 

2e5 操作にはこれで十分です。 

ブルート フォース再計算はクエリごとに O(N)、つまり O(NQ) で、これは約 10^10 回の操作に相当します。 

最適化されたソリューションにより、各更新/クエリの複雑さが対数的に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | お(1) | 遅すぎる |
 | セグメントツリー + 二分探索 | O(Q log N log A) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、種類ごとの動物数を表す動的な複数の値セットを維持します。 

1. 初期値と時間の経過とともに適用されるすべての更新デルタを含む、表示される可能性のあるすべての値を圧縮して、セグメント ツリー内でインデックスを作成できるようにします。 

これが必要なのは、値が大きく、更新をサポートするためにインデックス付きの構造が必要であるためです。 

1. セグメント ツリーまたはフェンウィック ツリーを構築します。このツリーには、各ノードに 2 つの情報 (セグメント内に現在値を持つタイプの数とそれらの値の合計) が格納されます。 

これら 2 つの集計により、カウントと合計の両方を対数時間で計算できます。 

1. 与えられたケージ数の候補について`c`、恒等式を使用して実現可能性を計算します。$$\sum \min(a_i, c) = c \cdot cnt_{\ge c} + sum_{a_i < c} a_i$$これを計算するには、次のデータ構造をクエリします。 

- 以下の値がいくつあるか`c`- 未満の値の合計`c`- 要素の総数

 これから、式の両方の部分を再構築します。 

1. この合計が少なくとも`c * k`。 「はい」の場合、`c`実現可能です。 

これは動物を次の地域に分配できるかどうかを直接テストします。`c`檻。 

1. 可能な限りの二分探索`c`範囲内で`[0, total_sum // k]`。 

増加するので単調性が成り立つ`c`タイプごとの寄与をより積極的に制限しながら、右側の要件を線形に増加させるだけです。 

1. 更新ごとに、セグメント ツリー内の 1 つのタイプの値を調整し、二分探索手順を使用して答えを再計算します。 

### なぜ効果があるのか

 核となる不変条件は、固定されたものに対する不変条件です。`c`、変身`min(a_i, c)`は、あるタイプがケージごとに複数の動物を寄与できないという制約を正しくモデル化しています。 ケージへの割り当ては再配置して、動物がなくなるかすべてのケージにそのタイプの動物が含まれるまで、各タイプが異なるケージに動物を分配することができます。 これは、実現可能性が取り決めの詳細ではなく、上限付きの拠出金のみに依存することを意味します。 実現可能性関数は単調なので、`c`、二分探索により、ケージの最大有効数が正しく特定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)
        self.sum = [0] * (n + 1)

    def add(self, i, val, delta):
        while i <= self.n:
            self.bit[i] += val
            self.sum[i] += delta
            i += i & -i

    def prefix(self, i):
        cnt = 0
        sm = 0
        while i > 0:
            cnt += self.bit[i]
            sm += self.sum[i]
            i -= i & -i
        return cnt, sm

    def range_query(self, l, r):
        c2, s2 = self.prefix(r)
        c1, s1 = self.prefix(l - 1)
        return c2 - c1, s2 - s1

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    q = int(input())
    ops = []
    vals = set(a)

    x = 0
    queries = []
    for _ in range(q):
        xi, yi = map(int, input().split())
        queries.append((xi - 1, yi))
        vals.add(xi)

    vals = sorted(vals)
    idx = {v: i + 1 for i, v in enumerate(vals)}

    ft = Fenwick(len(vals))

    for i, v in enumerate(a):
        ft.add(idx[v], 1, v)

    total_sum = sum(a)

    def get_cnt_sum_less(c):
        # all values < c
        # binary search in vals
        l, r = 0, len(vals)
        while l < r:
            m = (l + r) // 2
            if vals[m] < c:
                l = m + 1
            else:
                r = m
        if l == 0:
            return 0, 0
        return ft.prefix(l)

    def feasible(c):
        cnt_ge = len(a) - get_cnt_sum_less(c)[0]
        cnt_lt, sum_lt = get_cnt_sum_less(c)
        return c * cnt_ge + sum_lt >= c * k

    def get_answer():
        lo, hi = 0, total_sum // k
        ans = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        return ans

    for i, (x, y) in enumerate(queries):
        old = a[x]
        a[x] += y

        ft.add(idx[old], -1, -old)
        ft.add(idx[a[x]], 1, a[x])

        total_sum += y
        ans = get_answer()
        print(ans)

solve()
```Fenwick 構造はカウントと合計の両方を格納するため、プレフィックス クエリでしきい値を下回るタイプの数とその合計寄与度を回復できます。 更新により古い値が削除され、新しい値が挿入されます。 

実現可能性のチェックでは、ケージの数に対する二分探索が使用されます。 しきい値は次のように分割されます`< c`そして`>= c`圧縮された値に対する二分探索によって計算されます。 重要な点は、周波数と合計の両方の同期を維持することです。 そうしないと、上限付き合計の式が壊れます。 

## 実用的な例

 次のような小規模な構成を考えてみましょう。`k = 2`そして`a = [3, 1, 1]`。 

のために`c = 1`、すべてのタイプが寄与するのは最大 1 なので、合計は 3 で十分です。`1 * 2 = 2`、とても実現可能です。 

のために`c = 2`、貢献は`min(3,2)=2, 1, 1`、合計 4 に等しい`2 * 2`、まだ実現可能です。 

のために`c = 3`、貢献は`2 + 1 + 1 = 4`、ただし要件は`3 * 2 = 6`, 実現不可能なので、答えは2です。 

| ステップ | c | 最低貢献額 | 合計 | 必須 | 実現可能 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [1,1,1] | 3 | 2 | はい |
 | 2 | 2 | [2,1,1] | 4 | 4 | はい |
 | 3 | 3 | [2,1,1] | 4 | 6 | いいえ |

 このトレースは、飽和状態がどのように変化するかを示しています。`c`タイプごとに制限が決まります。 

次に、更新のケースを考えてみましょう。`a = [5, 0, 0], k = 2`。 

最初の答えは 2 です。分布制限を介して人為的に他の 2 つのタイプにわたってタイプ 1 のみを使用して 2 つのケージを形成できるからです。 

type 1 を 1 に減らすと、配列は次のようになります。`[1,0,0]`、サイズ 2 のケージを 1 つも満たすことができないため、答えは 0 になります。 

これは、主要なタイプの更新に対する感度を示しています。

 ## 特殊なケース

 重大なエッジケースは、あるタイプが他のすべてを支配する場合です。 のために`k = 3`そして`a = [100, 1, 1]`、合計の素朴な除算は多くのケージを示唆しますが、実現可能性は小さなタイプによって制限されます。 アルゴリズムはこれを処理します。`c > 1`、上限額は次のようになります`c + 2`、すぐに下に落ちます`c * 3`、答えを強制的に 1 に絞ります。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 もし`a_i = x`すべての i に対して、それぞれの増加`c`総寄与を均一に削減し、二分探索境界をシャープかつ安定させます。 アルゴリズムの単調な実行可能性により、変動や曖昧さがないことが保証されます。 

更新により値がゼロに減少すると、Fenwick 構造は寄与分を正しく削除します。 のような構成`[0,0,0]`count クエリと sum クエリの両方が 0 を返すため、実行可能なケージはすぐにゼロになります。そのため、正の値に対して不等式は失敗します。`c`。
