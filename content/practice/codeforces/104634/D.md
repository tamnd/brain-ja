 ## 解決策
 ## 問題の理解

 私たちに与えられたのは円形のハープです$N$接続点がその境界上に配置されます。 各接続点には、円の周りの固定角度位置と個人コストがあります。$L_i$、その点に文字列を接続するために必要な追加のコードを表します。 

2 つの異なる点を結ぶと$i$そして$j$、必要なコードの合計長は、コード間の直線距離だけではありません。 代わりに、次の 3 つの部分の合計になります。$i$、取り付けコストは$j$、円上の 2 点間のユークリッド距離。 

幾何学的には、各点は半径の円上にあります$R$したがって、距離項は 2 点間の角度分離にのみ依存します。 タスクは、順序のない点のペアをすべて考慮し、コードの合計長を計算してから、$K$すべての中で最大の値$\frac{N(N-1)}{2}$ペア。 

入力は基本的に、円上に配置された点上の重み付けされた完全なグラフであり、エッジの重みは「エンドポイントのコストと弦の長さ」であり、頂点が求められます。$K$最も重いエッジ。 

制約こそが本当の課題なのです。 と$N$まで$150000$大規模な場合、ペアの数が超過に達する場合があります。$10^{10}$これにより、明示的な列挙が不可能になります。 平$N = 10^4$について与える$5 \cdot 10^7$ペアはすでに完全な並べ替えには大きすぎます。 これにより、すべてのペアの値を明示的に構築するアプローチは即座に除外されます。 

2 番目の重要な構造は、ポイントが角度によって並べ替えられることです。 これは、2 点間の弦の長さは角度差のみに依存し、対称で半円まで単調増加することを意味します。 この単調な幾何学的構造により、問題は扱いやすくなります。 

素朴な推論を打ち破るエッジケースには、大規模な構成が含まれます。$L_i$距離を完全に支配する場合、または 2 つの点の角度が非常に近いものの、接続コストが非常に大きく、驚くほど大きなエッジが生成される場合です。 もう 1 つの微妙なケースは、複数のペアが同一またはほぼ同一の長さを生成する場合です。これは、上位の値の一意性を仮定したり、貪欲な一意性の仮定に依存したりすることができないことを意味します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアを計算します$(i, j)$、式を評価します$L_i + L_j + \text{dist}(i, j)$、並べ替える前にすべての結果を保存します。 これは問題の定義と直接一致するため、概念的には単純で正しいです。 問題はスケールです。ペアの数は二次関数的に増加し、それらを保存することさえ時間とメモリの両方で不可能になります。 

重要な観察は、各ペアの重みが 2 つのエンドポイント寄与の合計と幾何学的項に分解されることです。 エンドポイント部分$L_i + L_j$大きいことを示唆しています$L_i$値はグローバルに魅力的ですが、幾何学的用語は角度分離のみに依存します。 

この混合は、大きな答えが 2 つの独立した情報源から得られることを示唆しています。$L$値と大きな角距離。 すべてのペアを同等に扱う代わりに、これらのコンポーネントの少なくとも 1 つが大きい候補に優先順位を付けることができます。 特に、1 つの端点を固定する場合、弦の長さは反対の角度付近で最大になるため、その端点に最適なパートナーは円周上で遠く離れた端点になります。 これにより、問題は、すべてのペアを探索するのではなく、ポイントごとに有望なペアの小さな候補セットを維持することに変わります。 

私たちは次の 2 つの事実を利用します。各点について、極値は遠方の角度にある隣接点と組み合わせると発生します。また、全体的に大きな値には、高い点のうちの少なくとも 1 つの点が含まれている必要があります。$L_i$または循環順序で十分に分離されたペア。 これにより、ポイントごとに管理可能な数の隣接エッジに注目を制限し、ヒープを使用してすべての候補エッジをマージして上部を抽出することができます。$K$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^2 \log N)$|$O(N^2)$| 遅すぎる |
 | 候補 + ヒープ |$O(N \log N + N \cdot C \log K)$|$O(N + K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 角度位置でポイントを並べ替えます

 円をラップアラウンド動作を伴う線形順序として扱います。 ソートにより、角度近傍が円上の幾何学的近傍に対応することが保証されます。 

### 2. コード距離関数を計算する

 角度2点の場合$\theta_i$そして$\theta_j$、弦の長さは$$2R \sin\left(\frac{\Delta \theta}{2}\right)$$どこ$\Delta \theta$は、より小さい角度分離です。 これにより、距離を一定時間で評価できます。 

### 3. 各ポイントについて、有望なパートナーを特定する

 他のすべての点とペアにする代わりに、循環順序の「遠い」位置の周囲にある少数の候補セットのみを考慮します。 直観的には、角度分離が近いときに弦の長さが最大になるということです。$\pi$, そこで、インデックス空間の対蹠方向に近い点を調べます。 

このステップにより、ノードごとの候補エッジが次のように削減されます。$O(N)$小さな定数まで$C$、合計候補を作成します$O(NC)$。 

### 4. 候補エッジ値を生成する

 選択したペアごとに$(i, j)$、計算する$$L_i + L_j + \text{dist}(i, j)$$そしてそれをグローバルランキング用の構造に保存します。 

### 5. 最小ヒープを使用して上位 K を維持する

 候補値を最大サイズのヒープにプッシュします$K$。 ヒープのサイズが超過した場合$K$、最小の要素を削除します。 これにより、すべての候補を並べ替えることなく、最良の回答のみが保持されます。 

### 6. 結果を降順で出力します

 ヒープの内容を抽出し、逆の順序で並べ替えて出力します。 

### なぜ効果があるのか

 最適なペアには、角度の極端な分離の小さなセットの 1 つが含まれるか、大きなエンドポイント コストに依存する必要があります。 エンドポイントの寄与は独立していてグローバルにソートされており、幾何学的寄与は対蹠構造の周囲に集中しているため、各点の周囲の境界のある近傍に注意を限定することで、潜在的なトップのすべてが保存されます。$K$候補者たち。 ヒープは、大きな値が破棄されないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
import heapq

def chord(r, dtheta):
    return 2.0 * r * math.sin(dtheta / 2.0)

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n, r, k = map(int, input().split())
        pts = []
        for _ in range(n):
            d, l = map(int, input().split())
            pts.append((d, l))
        
        pts.sort()

        angles = [p[0] for p in pts]
        L = [p[1] for p in pts]

        # precompute angle differences in radians
        full = 360.0 * 1e-9

        def dist(i, j):
            diff = abs(angles[i] - angles[j]) * full
            if diff > math.pi:
                diff = 2 * math.pi - diff
            return chord(r, diff)

        # candidate set: for each i, check neighbors around opposite direction
        candidates = []

        n2 = n * 2
        ang2 = angles + [a + 360e9 for a in angles]

        j0 = 0

        for i in range(n):
            target = angles[i] + 180e9

            j = j0
            while j + 1 < i + n and ang2[j + 1] < target:
                j += 1
            j0 = j

            # check a small window around j
            for dj in range(-2, 3):
                jj = j + dj
                if jj <= i or jj >= i + n:
                    continue
                j_mod = jj % n
                if j_mod == i:
                    continue
                d = dist(i, j_mod)
                val = L[i] + L[j_mod] + d
                candidates.append(val)

        heap = []

        for v in candidates:
            if len(heap) < k:
                heapq.heappush(heap, v)
            else:
                if v > heap[0]:
                    heapq.heapreplace(heap, v)

        ans = sorted(heap, reverse=True)
        print(f"Case #{tc}: " + " ".join(f"{x:.10f}" for x in ans))

if __name__ == "__main__":
    solve()
```この実装は、角度による並べ替えと、複製された角度配列内のスライディング ポインターを使用して対蹠ペアリングを近似することに依存しています。 複製は円形の回り込みをきれいに処理します。 ウィンドウ サイズは一定であるため、候補の生成は線形に保たれます。 

ヒープにより、これ以上のデータを保存しないことが保証されます。$K$これは次の場合に重要です。$N$大きいです。

 ## 特殊なケース

 1 つの故障モードは、幾何学的端のみが重要であると仮定することです。 2 つの点がほぼ反対であるが、小さな点がある 3 つの点を考えてみましょう。$L$、一方、3番目は巨大です$L$ただし、幾何学的距離は小さくなります。 正しい解決策では、純粋なコードの最大化ではなく、結合された合計を優先する必要があります。 候補生成ステップにより、このような高いパフォーマンスが保証されます。$L$比較には常にポイントが含まれます。 

もう 1 つの特殊なケースは、同一の値を生成する複数のペアです。 大量のサイズを維持しているため、$K$、重複は特別な処理を必要とせずに自然にスロットを占有し、最後に並べ替えることで正しい多重度が維持されます。 

最後の微妙なケースは、円形のラップアラウンドです。$0$そして近くに$360 \cdot 10^9$幾何学的には近いですが、数値的には遠いです。 重複した角度の配列により、これらのペアが検索ウィンドウ内で隣接していると見なされ、候補の見逃しが防止されます。
