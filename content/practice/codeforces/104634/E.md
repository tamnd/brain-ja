 ## 解決策
 ## 問題の理解

 開始文字列と操作のコレクションが与えられます。各操作は、出現する 1 つの文字を別の固定文字にグローバルに置き換えます。 各操作には方向があるため、「A → B」の適用と「B → A」の適用は異なり、両方の方向が存在することは保証されません。 

すべての操作を少なくとも 1 回は適用する必要がありますが、順序は自由に選択でき、操作を任意に繰り返すことができます。 すべての操作が完了したら、最終的な文字列を確認し、その中に出現する個別の文字の数を数えます。 目標は、この数値を最大化する操作の順序を選択することです。 

このプロセスについて考えるのに役立つ方法は、演算を適用するとシンボルのすべての出現が永続的に書き換えられるため、各文字がグラフ内の有向エッジに沿って「移動」できるということです。 キャラクターが別のキャラクターになると、その後の操作は古いシンボルではなく、新しいシンボルに作用します。 このため、順序が重要になります。異なるシーケンスによって、キャラクターの同一性が結合または分離される可能性があります。 

制約は十分小さいため、最大 62 個の異なる文字 (数字、大文字、小文字) を扱うことができます。 非表示のテストでも、有向置換の数は最大でも 62 × 61 程度であり、これは依然として、文字列に直接関係するものではなく、文字に対する状態空間またはグラフベースの解決策が意図されていることを示唆しています。 

単純なアプローチでは、考えられるすべての操作順序をシミュレートし、結果の文字セットを追跡します。 最大 62 の演算と階乗順序があるため、これはすぐに爆発します。 早期のマージは将来の多様性の可能性を永久に排除してしまう可能性があるため、貪欲なローカル推論でも失敗します。 

操作がサイクルを形成するときに、微妙な失敗のケースが発生します。 たとえば、A → B、B → C、C → A がある場合、順序に応じて、すべての文字を 1 つに折りたたむことも、複数の異なる結果を一時的に保存することもできます。 もう 1 つのエッジ ケースは、文字が最初の文字列にまったく出現しないにもかかわらず、他の文字を拡散するための中間「キャリア」として使用できる場合です。 

中心的な問題は、操作が交換できないことです。B → C の前に A → B を適用することは、その逆と同等ではありません。 このため、私たちは、達成可能な変換と、できるだけ多くの異なる「最終代表者」を保存する方法について推論する必要があります。 

## アプローチ

 強引に試みる場合は、N 個の置換のすべての順序を試すことになります。 各順序付けでは、長さ 1000 までの文字列にわたる置換をシミュレートする必要があり、コストは O(N · |S|) です。 N が最大 62 であるため、これはすでに不可能であり、順列の階乗数によってさらに状況が悪化します。 

重要な構造的洞察は、各操作によって位置ではなく文字の ID のみが変更されるということです。 したがって、文字列を追跡する代わりに、置換を繰り返し適用することで元の各文字がどのように進化するかを追跡します。 

各文字は、エッジが置き換えられる有向グラフを流れるものと考えることができます。 操作を任意の順序で複数回適用できるため、問題は、最終状態で維持できる文字の個別のイメージを最大化する一連のエッジ緩和を選択することになります。 

重要な点は、最初の文字ごとに、重要なのは操作の正確な順序ではなく、すべての操作が少なくとも 1 回使用される必要があることを考慮しながら、最終的にマッピングできる文字のセットであるということです。 個別の代表者を最大化する方法で、各初期キャラクターに最終的な代表者を割り当てたいと考えています。

これは、すべてのエッジが少なくとも 1 回は「アクティブ化」されなければならないという制約と組み合わされて、文字の有向グラフにわたる到達可能性の問題に変わります。 後者の制約は、到達可能な状態の構造を変更せずに処理できます。これは、繰り返しが許可されている場合、エッジは中間の遷移を制限するだけで、最終的な到達可能性は制限しないためです。 

最終的にはすべての文字間の到達可能性を計算し、最初の各文字を到達可能なエンドポイントに割り当てるマッピングを選択して、個別のエンドポイントの数を最大化します。 これは、個別の到達可能なターゲットにマッピングできるできるだけ多くの初期ノードを選択することと同等であり、最初の文字と到達可能な最終文字の間の 2 部マッチング スタイルの割り当てになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(N! · N · | S | ) |
 | グラフの到達可能性 + マッチング | O(C3) | O(C²) | 承認済み |

 ここで C は最大 62 です。 

## アルゴリズムのチュートリアル

 問題を文字のグラフに圧縮します。 各文字はノードであり、各置換 A → B は有向エッジです。 

次に、すべての文字間の到達可能性を計算します。これは、ある順序で一連の置換を適用することによって、文字 x を最終的に y に変換できるかどうかを意味します。 順序が柔軟であり、操作を繰り返すことができるため、これは有向グラフ上の標準的な推移閉包に帰着します。 

### ステップ

 1. 文字列または演算に出現するすべての文字に対して有向グラフを構築します。 A → B を置換するたびに、有向エッジ A → B が追加されます。このグラフは 1 ステップの変換をエンコードします。 
2. 最大 62 ノードにわたる Floyd-Warshall などの推移閉包を使用して、すべての文字ペア間の到達可能性を計算します。 このステップの後、reach[u][v] は u が最終的に v になれるかどうかを示します。 

これが必要なのは、中間変換が複数の置換を通じて連鎖する可能性があるためです。 
3. 最初の文字列に出現する文字のセットを収集します。 これらは、目に見える出力文字を生成するだけなので、最終イメージが答えに寄与する唯一の文字です。 
4. ここで、すべての割り当てが到達可能性の制約の下で有効になり、個別の最終文字の数が最大化されるように、各最初の文字を到達可能な最終文字に割り当てます。 

これは 2 部マッチング問題になります。左側は最初の文字、右側はすべての文字で、reach[u][v] が true の場合はエッジが存在します。 できるだけ多くの左側のノードを個別の右側のノードに一致させたいと考えています。 

個別の最終文字の最大数は、各左ノードが到達可能な任意の右ノードと一致する最大一致のサイズと等しくなります。 
5. 最大 2 部マッチング アルゴリズムを実行します (定数 62 が小さい場合、DFS 拡張パスで十分です)。 どの右側の文字がすでに使用されているかを追跡します。 
6. 答えは一致のサイズであり、これは最終的に何個の個別の文字を強制的に表示できるかに相当します。 

### なぜ効果があるのか

 各初期文字は同じ置換システムを通じて独立して進化しますが、すべての操作を少なくとも 1 回使用する必要があるという制約によって、有向グラフが既にエンコードしている範囲を超える到達可能性が制限されることはありません。これは、シーケンス内のどこかにすべてのエッジを適用しながら、選択した変換パスを保持する方法で操作をいつでもスケジュールできるためです。 

したがって、唯一の意味のある制限は、クロージャ グラフ内のソース文字からターゲット文字に到達できるかどうかです。 到達可能性が判明すると、問題は各ソースを個別の到達可能なシンクに割り当てることになります。これはまさに最大の 2 部マッチングです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    
    def idx(c):
        if '0' <= c <= '9':
            return ord(c) - ord('0')
        if 'A' <= c <= 'Z':
            return 10 + ord(c) - ord('A')
        return 36 + ord(c) - ord('a')

    def chars():
        for i in range(62):
            yield i

    for tc in range(1, T + 1):
        parts = input().split()
        S = parts[0]
        N = int(parts[1])

        reach = [[0] * 62 for _ in range(62)]

        present = [0] * 62
        for c in S:
            present[idx(c)] = 1

        for _ in range(N):
            r = input().split()
            a = idx(r[0][0])
            b = idx(r[0][1])
            reach[a][b] = 1

        for i in range(62):
            reach[i][i] = 1

        for k in range(62):
            for i in range(62):
                if reach[i][k]:
                    for j in range(62):
                        if reach[k][j]:
                            reach[i][j] = 1

        match_to = [-1] * 62

        def dfs(u, vis):
            for v in range(62):
                if reach[u][v] and not vis[v]:
                    vis[v] = True
                    if match_to[v] == -1 or dfs(match_to[v], vis):
                        match_to[v] = u
                        return True
            return False

        ans = 0
        for u in range(62):
            if present[u]:
                vis = [False] * 62
                if dfs(u, vis):
                    ans += 1

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```この解決策は、数字、大文字、小文字を区切って、すべての文字を 0 ～ 61 のコンパクトなインデックス空間にエンコードすることから始まります。 

次に、到達可能性行列を構築し、推移閉包を計算して、マルチステップ変換がキャプチャされるようにします。 関連する置換を適用しないだけで文字は常に変更されないため、対角線は true に設定されます。 

DFS マッチングでは、最初に存在する各文字を一意の到達可能な宛先に割り当てようとします。 成功した各一致は、最終的な文字列内の 1 つの異なる文字に対応します。 

微妙な点は、DFS の開始時に最初の文字列に存在する文字のみを反復処理することです。 初期文字列にない文字は新しい出現に寄与できないため、マッチングの中間ターゲットとしてのみ機能します。

 ## 特殊なケース

 重要なエッジ ケースは、最初の文字列内の複数の文字が同じ最後の文字にしか到達できない場合です。 その状況では、単純な到達可能性のカウントでは、より大きな答えが誤って提案されてしまいます。 照合ステップにより二重割り当てが防止され、そのうちの 1 つだけが割り当てられるようになります。 

もう 1 つの微妙なケースは、サイクルを介して導入された自己ループです。 明示的な A → A が存在しない場合でも、推移閉包はサイクルを通じて A → A を作成できます。これはマッチングの正確さに不可欠です。 リーチ[i][i] の初期化により、変更しないままにすることが常に有効なオプションとなり、キャラクターをそのままにしておく必要がある場合に、偶発的に実現可能性が失われるのを防ぎます。
