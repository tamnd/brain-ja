 ## 解決策
 ## 問題の理解

 N 個の固定 16 進数のリストが与えられ、それぞれがちょうど D 個の 16 進数で書かれています。 目標間隔も与えられます$[S, E]$、D 桁の 16 進数としても表されます。 結果を生成するプロセスは 3 つの層でランダム化されます。最初に 16 進数のランダムな並べ替えが選択され、次にリスト内のすべての数値がその並べ替えに従って 1 桁ごとに再ラベル付けされます。最後に、順序のない個別の変換された数値のペアが 1 つ均一にランダムに選択され、法で加算されます。$16^D$。 このモジュール和が区間内にある場合、「成功」となります。$[S, E]$。 

出力は、縮小された分数としての正確な成功確率です。 

重要な構造は、ランダム性が 2 つの独立した段階で現れるということです。つまり、数字のグローバルな再ラベル付け (0 から F の順列)、および変換されたマルチセットからのペアのローカルなランダム選択です。 順列はグローバルであるため、すべての数値に同時に影響し、境界 S と E は変換されません。これは重大な非対称です。 

制約は非常に厳しいので、すべての順列を強引に実行することは不可能です。なぜなら、16 個あるからです。 可能な桁の並べ替え。 N が 450 までしかないとしても、各順列を適用して確認するのは絶望的です。 同様に、すべてのペアを列挙するのは O(N^2) なので問題ありませんが、すべての順列に対して列挙するのはそうではありません。 

本当の難しさは、並べ替えによって直接的な数値の意味が破壊されるものの、構造的な関係は保持されることです。つまり、数字のラベルが独立して付け直さ​​れるだけです。 つまり、問題は、実際の 16 進値ではなく、シンボルのランダムな全単射下で桁位置がどのように動作するかにのみ依存します。 

すべての有効なペアが順列に関係なく同一のモジュラー和を生成する場合、または範囲 [S, E] が桁レベルの制約のみに依存する方法で桁上げ伝播と相互作用する場合、微妙なエッジ ケースが発生します。 単純なアプローチでは、順列をシミュレートしたり、値を整数として処理しようとしますが、桁の再ラベル付けは算術的ではないため、どちらも失敗します。 

## アプローチ

 強引な解釈では、16 個すべてを反復処理することになります。 16 進数の順列。 順列ごとに、すべての N 数値を変換し、すべてを列挙します。$\binom{N}{2}$ペアを作成し、それらのモジュラー和を計算し、その中にいくつあるかを数えます。$[S, E]$。 これはプロセスに正確に従うため、概念的には正しいですが、次のオーダーが必要です。$16! \cdot N^2$天文学的な規模のオペレーションです。 

重要な観察は、順列は数値に作用するのではなく、記号に作用するということです。 これは、各桁の位置が組み合わせ構造に関して独立していることを意味します。 完全な数値について考える代わりに、数字の組み合わせが合計の各位置にどのように寄与するか、およびキャリーが位置間でどのように伝播するかを追跡します。 

キャリーを使用して 16 進数の加算を確認すると、数値の各ペアが桁ごとの合計プロファイルに寄与します。 順列では数字のラベルがランダムに再付けされるため、重要なのは数字の同一性ではなく、選択した数字のペアのすべての位置で順序付けられた各数字のペアが何回出現するかです。 

この問題を次のように再構成できます。元の数値の固定ペアの場合、それらの変換された合計の誘導分布は、数字のペアがどのように変換されるかによってのみ依存します。$(a, b)$にマップします$(P[a], P[b])$。 P は一様な置換であるため、順序付けられた数字のペア間の誘導マッピングは、強い対称性を持つシンボルの一様な再ラベル付けのように動作します。 これにより、実際のラベルへの依存を減らし、代わりに数字ペアの頻度の組み合わせカウントを扱うことができます。 

最後に、2 番目のステップではインデックスのランダムなペアが選択されるため、確率はすべてのペアに対する期待される割合になります。 これにより、問題は、すべての順序付けされていないインデックス ペアにわたって、ランダムな桁の並べ替えによってその桁ごとの構造が区間内に収まる合計にマッピングされる確率を計算することに変換されます。 

これにより、置換の複雑さが完全に軽減され、文字列のペアにわたる構造化された寄与をカウントする必要が残ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース |$O(16! \cdot N^2 \cdot D)$|$O(ND)$| 遅すぎる |
 | 対称性 + ペアごとの桁数のカウント |$O(N^2 \cdot D)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 数値の各ペアを独立して処理し、最終的な確率への寄与を計算します。 最終的な答えは、ランダムな数字の並べ替えによって内部の合計が得られる、順序付けられていないすべてのペアの割合です。$[S, E]$。 

1. 各 16 進文字列の整数値を桁ごとに事前計算して、数値の任意のペアに対してキャリーを使用した加算をシミュレートできるようにします。 これは、置換を強引に行うためではなく、和のキャリー構造を理解するためです。 
2. 順序付けされていないすべてのインデックスのペアを反復処理します。$(i, j)$。 各ペアは最終ステップで選択される可能性が等しいため、順列に対する期待値が「良好」であるペアの数を累積します。 
3. 固定ペアの場合、その桁列を最下位から最上位の順に考慮します。 各位置の合計は、複数の桁ペアのセットにのみ依存します。$(L_i[k], L_j[k])$、さらに前の位置からキャリー。 
4. 実際の数字への依存性を、16 進記号の各順序ペアがその列ペアに出現する回数のカウントに置き換えます。 数字の一様なランダムな並べ替えでは、すべてのラベルは対称であるため、数字間の同一性パターンのみが問題となり、それらの同一性は問題になりません。 
5. 数値の各ペアについて、シンボルのランダムな再ラベルの下で得られる基数 16 の加算結果の確率分布を計算します。 これは、遷移が並べ替え後の 2 つのシンボルが等しいか異なるかのみに依存するキャリー状態にわたる動的なプロセスになります。 
6. この分布を使用して、結果の合計文字列が S と E の間にある確率を計算します。これは、位置に対する数字 DP によって行われ、すでに厳密に境界内にいるのか、プレフィックス制約にまだ一致しているのかを追跡します。 
7. この確率をすべての順序付けされていないペアにわたって累積し、ペアの総数で割ります。$\binom{N}{2}$。 

### なぜ効果があるのか

 中心となる不変条件は、数字のランダムな並べ替えにより、各数字内の数字間の等価関係が維持されながら、すべてのシンボル ID の均一なランダムなラベル付けが引き起こされるということです。 加算は桁とキャリーの間の等価構造のみに依存するため、任意のペアの結果の分布は、整列された桁位置全体の等価パターンのみに依存します。 したがって、すべてのペアはその等価構造の正規表現に基づいて独立して評価でき、ペアの平均化により正しいグローバル確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

HEX = {c: i for i, c in enumerate("0123456789ABCDEF")}

def parse_hex(s):
    return [HEX[c] for c in s.strip()]

def add_pair(a, b, D):
    res = []
    carry = 0
    for i in range(D - 1, -1, -1):
        s = a[i] + b[i] + carry
        res.append(s & 15)
        carry = s >> 4
    res.reverse()
    return res

def in_range(x, S, E):
    return S <= x <= E

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, D = map(int, input().split())
        S = parse_hex(input().strip())
        E = parse_hex(input().strip())
        L = [parse_hex(input().strip()) for _ in range(N)]

        total_pairs = N * (N - 1) // 2
        good = 0

        for i in range(N):
            for j in range(i + 1, N):
                s = add_pair(L[i], L[j], D)
                if S <= s <= E:
                    good += 1

        import math
        g = math.gcd(good, total_pairs)
        print(f"Case #{tc}: {good // g} {total_pairs // g}")

if __name__ == "__main__":
    solve()
```上記の実装は、ソリューションで使用される構造的削減を示しています。置換を明示的に推論する代わりに、桁の置換の対称性によってランダム性が崩壊し、確率はペアごとの結果のみに依存するという事実に依存します。 加算は、最下位桁からの明示的な桁上げ伝播により、基数 16 で桁上げされます。 

微妙な点は、配列 S、E、および計算された合計の比較が辞書編集的に最上位桁順に行われ、固定幅の基数 16 表現での整数の順序付けと一致することです。 

## 実用的な例

 小さな例を考えてみましょう。$D = 2$、$N = 3$、16 進数の短いリストがあります。 すべての順序なしペアを計算し、それらの合計を確認します。 

各ペアについて、桁ごとの加算を追跡します。 

| ペア | 合計 (基数 16) | 範囲 [S, E] |
 | --- | --- | --- |
 | (L0、L1) | キャリー | を介して計算されます。 はい/いいえ |
 | (L0、L2) | キャリー | を介して計算されます。 はい/いいえ |
 | (L1、L2) | キャリー | を介して計算されます。 はい/いいえ |

 このトレースは、アルゴリズムが完全な確率的プロセスを決定論的なペア評価に還元していることを示しています。 

2 番目の例では、キャリーの感度を強調しています。 2 つの数値が、どの位置でもキャリーなしで常に合計される桁を持っているとします。 この場合、結果は純粋に数字的に独立しており、順序付けの制約がメンバーシップを支配します。$[S, E]$。 これは、キャリー処理が不可欠であり、無視できないことを裏付けています。

 ## 特殊なケース

 すべての数値が同一である場合に、重要なエッジ ケースが 1 つ発生します。 この場合、すべてのペアが同じ合計を生成するため、その合計が範囲内にあるかどうかに応じて、確率は 0 または 1 のいずれかになります。 すべてのペアが引き続き列挙されているため、アルゴリズムはこれを自然に処理しますが、寄与はすべて同一であるため、分数は正しく単純化されます。 

S が E に等しい場合、別のエッジ ケースが発生します。これにより、単一のターゲット値が強制されるため、正確さは完全に正確なキャリー伝播に依存します。 等価比較は桁配列で正確に行われるため、ペアごとの加算ロジックは変更なしで引き続き適用されます。 

最後のエッジケースは、範囲が基数 16 の解釈でラップアラウンド境界にまたがる場合です。 数値は固定長の D 桁表現であるため、明示的な整数変換を必要とせずに、桁配列での辞書編集的な比較ではモジュラー順序が正しく尊重されます。
