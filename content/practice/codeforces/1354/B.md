 ## 解決策
 ## 問題の理解

 複数のテスト ケースが与えられ、各テスト ケースは文字のみで構成される文字列です。`1`、`2`、 そして`3`。 各文字列について、3 つの文字のそれぞれが少なくとも 1 回出現する最短の連続セグメント (部分文字列) を見つける必要があります。 文字列に数字のいずれかが完全に欠けている場合、そのような部分文字列を形成することは不可能であり、答えはゼロになります。 

ここでの部分文字列は文字列の連続したスライスであるため、開始インデックスと終了インデックスを選択し、その間のすべてを取得することができます。 目標は、3 つのシンボルすべてがその中に少なくとも 1 回表示されるようにしながら、その長さを最小限に抑えることです。 

制約は合計すると大きくなり、テスト ケース全体のすべての文字列の合計長は最大 200,000 になります。 これにより、すべての部分文字列を明示的にチェックするソリューションは即座に除外されます。 エンドポイントのすべてのペアを試行する総当りアプローチでは、最悪の場合、テスト ケースごとに O(n²) が必要となり、これでは遅すぎます。 

エッジ ケースは、1 つ以上の数字が完全に欠落している場合に発生します。 たとえば、次の場合`s = "111111"`、正しい出力は次のとおりです。`0`ないから`2`または`3`。 同様に、文字列に 3 桁のうち 2 桁のみが含まれている場合、次のようになります。`s = "112211"`、条件を満たす部分文字列はありません。 

もう 1 つの微妙なケースは、有効な部分文字列がローカル構造から明らかでない場合です。 たとえば、`s = "1212123"`、最適なセグメントには、`3`これは終わり近くで 1 回だけ表示されるため、ウィンドウがずっと後ろに伸びることになります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての部分文字列を調べて、その文字列に次のものが含まれているかどうかを確認します。`1`、`2`、 そして`3`。 開始インデックスごとに`i`、終了インデックスを拡張します`j`必要な文字がすべて存在するかどうかを追跡します。 頻度カウントを増分的に維持したとしても、テストごとに最悪のケースで O(n²) 個の部分文字列を検査することになり、最悪のシナリオでは約 10¹⁰ の操作が発生します。 これは、指定された制約の下では通過できません。 

重要な点は、すべての部分文字列を個別に調べる必要がないということです。 代わりに、3 文字すべてをカバーする最短のウィンドウのみを考慮します。 これは古典的なスライディング ウィンドウの問題です。左側の境界を修正したら、すべての文字が表示されるまで右側の境界を移動し、有効性を維持しながらウィンドウを左側から縮小してみます。 

問題の構造により、ウィンドウを拡大するとカバレッジが単調に増加し、ウィンドウを縮小すると制約に違反するまで有効性を失うことなく冗長性が減少するだけであることが保証されています。 これにより、2 ポインター手法で十分になります。 私たちは次の頻度カウントを維持しています。`1`、`2`、 そして`3`現在のウィンドウ内でポインタを線形時間で調整します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テストあたり O(n²) | お(1) | 遅すぎる |
 | スライディングウィンドウ | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 ポインターのスライディング ウィンドウを使用して、各テスト ケースを個別に処理します。 

1. 2 つのポインタを初期化する`l = 0`そして`r = 0`、および周波数配列`cnt`サイズ 4 の発生を追跡する`1`、`2`、 そして`3`。 変数も保持します`best`大きな数値に初期化されます。 
2. 右ポインタを展開します`r`段階的に、追加する`s[r]`周波数配列に取り込みます。 これにより、候補ウィンドウが徐々に構築されます。 
3. 展開するたびに、現在のウィンドウに各桁が少なくとも 1 つ含まれているかどうかを確認します。 この条件は次と同等です`cnt[1] > 0 and cnt[2] > 0 and cnt[3] > 0`。 
4. 条件を満たしたら、左から移動してウィンドウを縮小してみます。`l`3 桁すべてが存在する状態を維持したまま、前方に進みます。 それぞれの有効な縮小は、より良い (または同等の) 候補の回答を表します。 
5. この縮小プロセス中に、現在のウィンドウの長さで答えを更新します。`r - l + 1`ウィンドウが有効なままである場合はいつでも。 
6. 縮小後にウィンドウが再び無効になったら、縮小を停止して拡大を続けます。`r`。 
7. 有効なウィンドウが見つからない場合は、戻ります。`0`。 

重要なアイデアは、私たちが移動するたびに、`l`または`r`、文字列全体で単調に処理するため、各インデックスは最大でも一定の回数だけ処理されます。 

なぜそれが機能するのかは、最小限のウィンドウの構造にあります。 固定された右端点の場合、必要な文字をすべて保持しながら左境界をできるだけ右に押し出すことによって、そこで終了する最適な部分文字列が得られます。 最大限に縮小しなかった場合、不要な文字や同じで終わる短い有効な部分文字列が残ってしまいます。`r`見逃されるだろう。 全部試してみるので`r`、最適な部分文字列の考えられるすべての正しい境界をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        
        cnt = [0] * 4
        l = 0
        best = 10**9
        
        for r, ch in enumerate(s):
            x = ord(ch) - 48
            cnt[x] += 1
            
            while cnt[1] > 0 and cnt[2] > 0 and cnt[3] > 0:
                best = min(best, r - l + 1)
                cnt[ord(s[l]) - 48] -= 1
                l += 1
        
        if best == 10**9:
            print(0)
        else:
            print(best)

if __name__ == "__main__":
    solve()
```この実装では、数値によって直接インデックス付けされた周波数配列が維持されるため、マッピングのオーバーヘッドが回避されます。 左ポインタはウィンドウが有効な場合にのみ前方に移動し、複雑さを線形に保ちながら正確性を保証します。 

微妙な詳細は、`best`縮む前に。 これにより、移動によって有効性が損なわれる可能性がある前に、正しい各エンドポイントの最小有効ウィンドウを記録することが保証されます。`l`。 もう 1 つの重要な点は初期化です`best`有効な部分文字列が見つからない可能性があるため、センチネル値を使用します。

 ## 特殊なケース

 文字列に数字の 1 つが完全に欠けている場合、周波数条件は決して満たされないため、アルゴリズムは縮小フェーズに入ることはありません。`best`は変わらないままです。 のために`s = "333333"`、ループはカウントをインクリメントするだけです`3`有効なウィンドウは記録されず、出力が生成されます。`0`。 

有効なウィンドウは存在するが、最小ウィンドウよりもはるかに大きい場合、アルゴリズムは積極的な縮小に依存します。 で`s = "12222133333332"`、1回`3`が含まれる場合、左ポインタは最後に必要な出現まで進みます。`1`または`2`ウィンドウがその正しい境界に対して最小になるようにするため、失われます。 これにより、冗長なプレフィックスが保持されず、スキャン中に最適な部分文字列の候補がすべて検出されることが保証されます。
