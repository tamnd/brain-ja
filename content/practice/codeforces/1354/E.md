 ## 解決策

 ## 問題の理解

 無向グラフが与えられ、各頂点に 3 つのラベル (1、2、または 3) のいずれかを割り当てるように求められます。ラベルは任意ではありません。すべてのエッジは、その端点に 1 つだけ異なるラベルを持つことを強制します。 つまり、エッジは (1,2) または (2,3) のみを接続でき、(1,1)、(2,2)、(3,3)、または (1,3) には接続できません。 同時に、各ラベルを取得する頂点の数を自由に選択することはできません。 1、2、3 のカウントは事前に固定されており、正確に満たされる必要があります。 

これにより、問題は即座に制約された色付けタスクに変わり、実現可能性はエッジによって強制されるローカル構造と、必要な 3 つのカウントによって強制されるグローバル分布の両方に依存します。 グラフは切断される可能性があるため、各コンポーネントは独立して隣接性制約を遵守する必要がありますが、すべてのコンポーネントの合計が必要なグローバル カウントに達する必要もあります。 

制約では、最大 5000 個の頂点と 100000 個のエッジが許可されます。 このスケールにより、ラベリングや 3 色の分岐による頂点ごとのバックトラッキングをめぐる指数関数的な検索が排除されます。 平$O(n^2)$アプローチは安全ですが不必要です。 サブセットにわたる状態ごとの DP や大規模な状態空間にわたるフローに関係するものには、構造が必要です。 

コンポーネントが 2 部構成でない場合、微妙なエッジ ケースが発生します。 すべてのエッジはラベルが 1 つだけ異なる頂点を接続するため、どのエッジ (u, v) もパリティ関係を引き起こします。ラベルを何らかの基本レベルからの距離として解釈すると、グラフは層状の 2 部構造のように動作するはずです。 奇妙なサイクルがあると、すぐに実現可能性が損なわれます。 たとえば、頂点が 1-2-3-1 の三角グラフにはラベルを付けることができません。これは、サイクルに関する制約に従うと、ラベルの違いに不可能な矛盾が生じるためです。 

もう 1 つのそれほど明白ではない問題は、グローバル バランシングです。 すべてのコンポーネントが 2 部構成であっても、コンポーネント間の実行可能な割り当ての合計が正確な数と一致しない場合は失敗する可能性があります。$n_1, n_2, n_3$。 コンポーネントごとの単純なローカル色付けでは、有効な構造でも互換性のない合計が簡単に生成される可能性があります。 

## アプローチ

 ブルート フォースの試行では、各頂点に 3 つのラベルのいずれかを割り当て、すべての制約をチェックします。 これは$3^n$、実現可能性をはるかに超えています。 隣接性制約を使用した枝刈りでも、各頂点が複数の近傍と相互作用し、選択肢が伝播するため、依然として指数関数的な分岐が残ります。 

重要な観察は、「差の絶対値が 1 に等しい」という制約により、グラフがレベルのある 2 色構造のように動作するように制限されていることです。 すべての連結コンポーネントは少数の有効なラベル パターンのみを使用できます。2 部構成のカラーリングに対してラベル 2 が配置される位置を選択することを考えることができます。 最初にコンポーネントを 2 分割する場合、一方の側のすべての頂点は 1 つのラベル セットとパリティを共有し、もう一方の側は反対側のラベル セットとパリティを共有する必要があります。 中間レベル 2 付近で辺がラベル 1 に対応するかラベル 3 に対応するかを決定すると、構造は小さなシフトまでは決定的になります。 

これにより、各コンポーネントが可能な「モード」の小さなセットに縮小されます。 各コンポーネントについて、その二部カラーリングを計算し、各二部クラスに含まれる頂点の数を数えます。 次に、グローバル要件に一致する方法でラベルを割り当てようとします。 これは、各コンポーネントが (1,2,3) のカウントに寄与するいくつかの可能な方法を提供する、コンポーネントにわたるナップザックのような DP になります。 

各コンポーネントには最大 2 つの 2 つのパーティションがあり、「下位」側がレベル 2 を通じて 1 または 3 のどちらにマッピングされるかを決定できるため、最終的に消費する 1 および 2 ラベルの数を追跡する管理可能な DP 状態になります (3 番目は自動的に決定されます)。

 | ブルートフォース |$O(3^n)$|$O(n)$| 遅すぎる |
 | 二部状態のコンポーネント DP |$O(n + m + n \cdot n_1)$|$O(n \cdot n_1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを接続されたコンポーネントに分割し、BFS または DFS を使用して各コンポーネントを 2 分割してみます。 コンポーネントが 2 部構成でない場合は、すぐにソリューションが存在しないと結論付けます。 その理由は、奇数サイクルでは一貫性のないパリティ割り当てが強制され、連続するラベルにマッピングできないためです。 
2. コンポーネントごとに、2 つの頂点のセット (2 分割の左側と右側) とそのサイズを計算します。 これらは、ラベルにマッピングする必要がある 2 つの構造グループのみを表します。 
3. 各コンポーネントについて、2 分割の 2 つの有効な解釈を考慮します。左側がラベル 1 に近く、右側がラベル 3 に近いか、またはその逆です。 各解釈では、レベル 2 を 2 部レイヤーの中央に配置すると仮定して、そのコンポーネント内でラベル 1、2、および 3 を取得する頂点の数の決定的なカウントが生成されます。 
4. コンポーネントを 1 つずつ処理する動的プログラミング テーブルを構築します。 DP 状態は、これまでにラベル 1 とラベル 2 が割り当てられた頂点の数を追跡します。ラベル 3 は、これまでに処理されたコンポーネントの合計からの減算によって固定されるためです。 各コンポーネントについて、両方の解釈を試し、到達可能な状態を更新します。 
5. すべてのコンポーネントを処理した後、使用されているラベル 1 とラベル 2 の頂点の数が一致する DP 状態が存在するかどうかを確認します。$n_1$そして$n_2$。 そのような状態が存在しない場合、答えは不可能です。 
6. 有効な状態が存在する場合、DP テーブルから逆方向に選択肢を再構築し、各コンポーネントがどの解釈を使用したかを決定します。 
7. 最後に、頂点のコンポーネント、二分割側、および選択した解釈に基づいて、実際のラベルを頂点に割り当てます。 

### なぜ効果があるのか

 各コンポーネントは、エッジに沿って強制的に単調なラベル構造を備えた 2 部グラフのように動作します。 有効なラベル付けは、エッジによって引き起こされる 2 レベルの制約を尊重する必要があります。この制約は、コンポーネントごとに 1 つの方向を選択する 2 部のパーティションに折りたたまれます。 その選択が決定されると、コンポーネント内の頂点ラベルが完全に決定されます。 DP は、これらのローカルな決定が、必要なラベル数と正確に一致するグローバルに一貫した方法で結合されることを保証します。 すべての有効な解決策はコンポーネントの方向の一意の選択に対応し、すべての DP 遷移は実行可能な方向を表すため、有効な解決策が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    n1, n2, n3 = map(int, input().split())
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    color = [-1] * n
    comps = []

    for i in range(n):
        if color[i] != -1:
            continue
        q = deque([i])
        color[i] = 0
        comp = [[], []]
        ok = True

        while q:
            u = q.popleft()
            comp[color[u]].append(u)
            for v in g[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    q.append(v)
                elif color[v] == color[u]:
                    ok = False

        if not ok:
            print("NO")
            return
        comps.append((comp[0], comp[1]))

    # DP over components: dp[i][a][b] -> reachable
    C = len(comps)
    dp = [set() for _ in range(C + 1)]
    dp[0].add((0, 0))
    parent = [{} for _ in range(C + 1)]

    for i, (a, b) in enumerate(comps, 1):
        sz0, sz1 = len(a), len(b)
        for x, y in dp[i - 1]:
            # option 1: color 0 side -> 1, color 1 side -> 3
            nx1, nx2 = x + sz0, y
            if nx1 <= n1 and nx2 <= n2:
                if (nx1, nx2) not in parent[i]:
                    parent[i][(nx1, nx2)] = (x, y, 0)

            # option 2: color 0 side -> 3, color 1 side -> 1
            nx1, nx2 = x + sz1, y
            if nx1 <= n1 and nx2 <= n2:
                if (nx1, nx2) not in parent[i]:
                    parent[i][(nx1, nx2)] = (x, y, 1)

        dp[i] = set(parent[i].keys())

    if (n1, n2) not in dp[C]:
        print("NO")
        return

    comp_choice = [0] * C
    cur = (n1, n2)

    for i in range(C, 0, -1):
        x, y, t = parent[i][cur]
        comp_choice[i - 1] = t
        cur = (x, y)

    res = [0] * n

    for idx, (c0, c1) in enumerate(comps):
        t = comp_choice[idx]
        if t == 0:
            for v in c0:
                res[v] = 1
            for v in c1:
                res[v] = 3
        else:
            for v in c0:
                res[v] = 3
            for v in c1:
                res[v] = 1

    print("YES")
    print("".join(map(str, res)))

if __name__ == "__main__":
    solve()
```実装では、まず二部構成のチェックを通じて構造的な実現可能性を強制します。 ここは、奇妙なサイクルからの矛盾が捕らえられる唯一の場所です。 次に、DP はコンポーネントを集約し、ラベル 1 とラベル 2 に割り当てられた頂点の数のみを注意深く追跡します。ラベル 3 は、各コンポーネントが固定数の頂点に寄与し、合計が既知であるため、暗黙的です。 

微妙な点は、コンポーネント内でラベル 2 を明示的に割り当てないことです。 これは、この構造では、ラベル 2 が「中間」層に対応し、二分割方向が選択されると暗黙的に決定されるためです。 DP は、ラベル 1 にマッピングされるエンドポイントのみを追跡します。 ラベル 2 は残りの構造を一貫して埋めます。

 ## 特殊なケース

 重要なエッジ ケースは、コンポーネント内の奇数サイクルです。 三角グラフを考えてみましょう。 BFS カラーリング中に、隣接する 2 つの頂点が最終的​​に同じカラーを受け取り、直接の矛盾が引き起こされます。 アルゴリズムはこのケースを即座に拒否します。これは、奇数の長さのサイクルの周囲の差の制約を満たす割り当てがないため、これが必要です。 

すべてのコンポーネントが 2 部構成であるにもかかわらず、カウントに互換性がない場合、別のエッジ ケースが発生します。 サイズが (2,2)、(2,2)、(2,2) の 3 つのコンポーネントと、ラベル 1 に多すぎる頂点を強制する要件を想像してください。各コンポーネントは独立して対称的な寄与を提供しますが、DP は、どの組み合わせも必要なグローバル和に達しないことを明らかにし、正しい拒否につながります。 

最後の微妙なケースは、ラベル カウントの 1 つがゼロである場合です。 DP は遷移を自然に制限するため引き続き機能しますが、状態更新を慎重に制限しないと、一時的に制約を超える無効な中間割り当てが誤って生成されやすくなります。
