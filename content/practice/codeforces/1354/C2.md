 ## 解決策
 ## 問題の理解

 次のような正多角形が与えられます。$2n$頂点、すべてのエッジが 1 に等しい。多角形は凸面であり、自由に回転できます。 多角形のすべての点が正方形の境界内または境界上に位置するように、これも自由に回転可能な正方形の中に配置する必要があります。 タスクは、そのような正方形の可能な最小の辺の長さを見つけることです。 

入力は与えますが、$n$、実際のオブジェクトは$2n$-ゴン。 以来$n$このバージョンでは、 が奇数である場合、多角形の辺の数は偶数ですが 4 で割り切れないため、C1 を単純化する対称性が崩れ、最適な向きがそれほど自明ではなくなります。 

幾何学的には、これは包含問題です。固定された正多角形のすべての可能な回転にわたって、軸に沿った最小の境界正方形を見つけようとしています。 正方形自体も回転できますが、その自由度は多角形の回転に吸収されるため、事実上、単一の角度パラメータに対して最適化することになります。 

制約$n \le 199$テスト ケースあたり最大 200 の評価を意味します。 最大 200 のテスト ケースでは、定数時間または対数時間で候補構成を評価するソリューションで十分ですが、各評価が安価であれば、高密度のサンプリングや多くの方向にわたるブルート フォース ジオメトリを必要とするものはすべて合格します。 ただし、細かい角度ステップにわたる単純なスキャンでは、テスト ケースごとに何百万ものチェックが必要になりますが、これは不必要です。 

最適な方向が頂点またはエッジと一致していない場合、微妙なエッジ ケースが発生します。 たとえば、次のようなとき$2n = 10$、最適な正方形はどのポリゴン エッジにも位置合わせされません。 代わりに、頂点と反対側のエッジが同時に正方形の境界に触れたときに発生します。 「頂点に揃えられた」回転のみをチェックする単純なアプローチでは、この構成が見逃され、より大きな正方形が返されます。 

もう 1 つの失敗モードは、対称性により検索がポリゴン周期の半分に短縮されると仮定することで発生します。 奇数の場合$n$、ポリゴンは正方形対称にきれいに整列していないため、検索スペースを誤って縮小すると、真の最適値がスキップされる可能性があります。 

## アプローチ

 この強引なアイデアは、多角形を円上の点のセットとして扱い、可能なすべての回転を試みることです。 回転角度ごとに、回転された頂点の軸に合わせた境界ボックスを計算し、その向きに必要な正方形の辺である最大の幅または高さを取得します。 細かい離散化で角度をスイープすることで、原理的にはこれが可能になります。 それぞれの評価にかかる費用$O(n)$、そしてサンプリングすると$K$角度を付けると、全体の複雑さは次のようになります$O(nK)$。 取得するため$10^{-6}$精度、$K$非常に大きくなければならず、多くの場合、$10^6$、それは次のことにつながります$10^8$テストケースごとの操作が遅すぎます。 

重要な観察は、ある方向に沿った回転された多角形の幅が円上のサポート ポイントによって決定されるということです。 凸多角形の場合、境界正方形は 2 つの直交方向への極端な投影によって決定されます。 回転が変化すると、頂点が境界方向に整列する離散イベントでのみ、これらの極値が切り替わります。 

これにより、連続的な最適化が角度の制限された間隔にわたる単峰関数に縮小されます。 正方形の辺の長さが最小になる角度を二分探索できます。 関数の各評価では、すべての頂点の投影が計算されます。$O(n)$、収束に必要な反復回数は倍精度の場合約 60 回です。 

より深い構造は、正方形の辺が 2 つの正弦波射影関数の最大値であり、それらの最大値の最小値が関連する区間内の 1 つの大域最小値と滑らかに動作するということです。

 ## アルゴリズムのチュートリアル

 私たちは定期的なものを代表しています$2n$単位外接円上の -gon。 すべての辺が 1 なので、外周半径は$R$は：$$R = \frac{1}{2\sin(\pi/(2n))}$$頂点を次のように配置します。$$(\cos(2\pi k / (2n)) \cdot R, \sin(2\pi k / (2n)) \cdot R)$$1. 回転角度の候補を決定する$\theta$。 すべての頂点を次のように回転させます$\theta$。 このようにする理由は、多角形の回転が座標軸の回転と同じであるためです。 
2. 回転した点の境界ボックスを計算します。$$x_{\min}, x_{\max}, y_{\min}, y_{\max}$$必要な正方形の辺は次のとおりです。$$s(\theta) = \max(x_{\max} - x_{\min}, y_{\max} - y_{\min})$$これにより、正方形に多角形全体が確実に含まれるようになります。 
3. を返す関数を定義します。$s(\theta)$。 この関数は次の期間に連続します。$\theta$単一の最小値を超えています$[0, \pi/(2n)]$対称性があるため。 
4. 三分検索 (または派生動作の二分検索) を実行します。$\theta$。 評価します$s(\theta)$各ステップで隣接する点を比較し、最小値に向かって移動します。 
5. 収束後、最小値を出力します。 

### なぜ効果があるのか

 凸多角形の任意の方向への投影幅は、次の一次関数によって決まります。$\cos$そして$\sin$回転角度のこと。 有限個のそのような滑らかな関数の最大値は、正多角形の制限された対称区間内で区分的に滑らかで単峰性です。 これにより、グローバル最小値が存在し、検索間隔内に二次最小値が出現しないことが保証されます。 したがって、三分探索は正しい答えに収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve_case(n):
    m = 2 * n
    R = 1.0 / (2.0 * math.sin(math.pi / m))

    # precompute base vertices
    pts = []
    for k in range(m):
        ang = 2.0 * math.pi * k / m
        pts.append((math.cos(ang) * R, math.sin(ang) * R))

    def width(theta):
        c = math.cos(theta)
        s = math.sin(theta)

        xmin = ymin = float('inf')
        xmax = ymax = float('-inf')

        for x, y in pts:
            xr = x * c - y * s
            yr = x * s + y * c
            if xr < xmin: xmin = xr
            if xr > xmax: xmax = xr
            if yr < ymin: ymin = yr
            if yr > ymax: ymax = yr

        return max(xmax - xmin, ymax - ymin)

    l, r = 0.0, math.pi / m
    for _ in range(80):
        m1 = (2*l + r) / 3
        m2 = (l + 2*r) / 3
        if width(m1) > width(m2):
            l = m1
        else:
            r = m2

    return width((l + r) / 2)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(f"{solve_case(n):.10f}")

if __name__ == "__main__":
    main()
```コードはまず、正多角形は外接半径によって一意に決定されるという事実を利用して、外接円上に多角形を再構築します。 半径の公式は、ユニットの辺を弦として表現することから生まれます。 

の`width`関数は、固定回転の正方形の辺の長さを計算します。 標準の 2D 回転行列を使用してすべての頂点を回転し、両方の軸の極値を追跡します。 

三項検索が実行されます$[0, \pi/m]$、正多角形の対称性により、これで十分です。 反復回数 80 は、必要な回数を安全に上回ります。$10^{-6}$精度。 

よくある間違いは、検索してしまうことです$[0, 2\pi]$これにより、ランタイムに定数が乗算され、冗長な同等の向きも導入されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sin, cos, pi

    # simplified inline solver
    import math

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            m = 2*n
            R = 1.0 / (2.0 * math.sin(math.pi / m))
            pts = []
            for k in range(m):
                ang = 2.0 * math.pi * k / m
                pts.append((math.cos(ang)*R, math.sin(ang)*R))

            def width(theta):
                c, s = math.cos(theta), math.sin(theta)
                xmin = ymin = 1e18
                xmax = ymax = -1e18
                for x,y in pts:
                    xr = x*c - y*s
                    yr = x*s + y*c
                    xmin = min(xmin, xr)
                    xmax = max(xmax, xr)
                    ymin = min(ymin, yr)
                    ymax = max(ymax, yr)
                return max(xmax-xmin, ymax-ymin)

            l, r = 0.0, math.pi/m
            for _ in range(70):
                m1 = (2*l+r)/3
                m2 = (l+2*r)/3
                if width(m1) > width(m2):
                    l = m1
                else:
                    r = m2
            out.append(str(width((l+r)/2)))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ポリゴンの最小サイズです。$n = 3$、形状は正六角形です。 ここで、目的関数は比較的滑らかで単峰性ですが、最適値付近では幅と高さの差が小さくなるため、数値精度の問題が発生する可能性があります。 このアルゴリズムは、増分更新に依存するのではなく、評価ごとに完全な浮動小数点の極値を再計算することでこれを処理し、累積エラーを回避します。 

もう一つのエッジケースは大きい$n = 199$、多角形が円に近づきます。 この領域では、最適な正方形の辺は円の直径に収束します。 width 関数は非常にフラットになりますが単峰性のままであるため、二分探索は引き続き機能します。 投影の完全な再計算を繰り返すことでドリフトを防ぎます。 

最後のエッジ ケースは、最適な方向が検索間隔の境界で発生する場合です。$[0, \pi/m]$。 関数は対称的かつ周期的であるため、$2\pi/m$、この間隔に制限してもグローバル最小値が得られます。
