 ## 解決策
 ## 問題の理解

 重複が許可されている整数のコレクションを維持しており、コレクションは時間の経過とともに変化します。 最初に、開始マルチセットをすでに形成している値のソートされたリストが与えられます。 その後、長い一連の操作が行われます。 

各操作は、マルチセットに新しい整数を挿入するか、並べ替えられた順序での位置に基づいて要素を削除します。 「k 次の統計量」と言うときは、マルチセット全体をソートすると、k 番目に小さい要素が選択されることを意味します。 その後、その要素が構造から削除されます。 挿入は単に値を追加するだけであり、削除は値の同一性ではなく、現在の順序に依存します。 

最後に、空でない場合はマルチセットから残りの要素を 1 つ出力するだけでよく、そうでない場合はゼロを出力します。 

主な問題点は、操作の数が最大 100 万回に達する可能性があるため、クエリごとに構造全体を再ソートまたはスキャンするアプローチは失敗することです。 1 回の操作あたり O(n) であっても、最悪の場合は 10^12 の操作が発生し、制限時間を大幅に超えてしまいます。 これにより、対数時間での挿入と k 次統計クエリの両方をサポートする構造が必要になります。 

微妙なエッジ ケースは、小さな k 値が繰り返し削除されることで発生します。 たとえば、最初の要素を繰り返し削除すると、構造は正面から縮小し続けます。 配列を再構築したりソートを繰り返したりする単純なアプローチは、各ステップが「単純」に見えても、静かに二次関数の動作に劣化する可能性があります。 

もう 1 つの重要なエッジ ケースは、たとえ最初は大規模だったとしても、すべての削除後にマルチセットが空になる可能性があることです。 その場合、要素にアクセスするのではなく、0 を出力する必要があります。 

## アプローチ

 簡単なアイデアは、マルチセットを動的配列または Python リストとして維持することです。 挿入ごとに値を追加します。 削除するたびに、配列をソートし、k 番目の要素を削除します。 

これは論理的には正しいですが、パフォーマンスはすぐに崩壊します。 ソートには O(n log n) のコストがかかり、これを最大 100 万回実行すると、およそ 10^6 × n log n 回の操作が必要となり、これは実行不可能です。 バイナリ挿入を使用してリストをソートされた順序で維持したとしても、k 番目の要素の削除には依然として要素をシフトする必要があり、操作ごとに O(n) が発生します。 

中心的な観察は、要素の実際の順序付けを明示的に行う必要がないということです。 必要な機能は 2 つだけです。値の頻度を維持することと、存在するすべての要素の中から k 番目に小さい要素をすばやく見つけることです。 その要素が見つかったら、その頻度を減らします。 

これにより、問題は動的なプレフィックスサム構造に変換されます。 各値が出現する回数を維持する場合、k 番目に小さい要素が、プレフィックスの合計が少なくとも k に達する最小のインデックスになります。 フェンウィック ツリーは、まさにこのパターンをサポートしています。つまり、ポイントの更新とプレフィックスの合計に加えて、O(log n) の k 番目の位置を見つけるためのバイナリ リフティングです。 

すべての値は n によって制限されるため、サイズ n のフェンウィック ツリーを安全に使用できます。 各挿入は単一ポイントの更新であり、各削除は「プレフィックス合計による検索」とそれに続く別のポイントの更新です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再ソート・配列シミュレーション | O(nq) または O(nq log n) | O(n) | 遅すぎる |
 | フェンウィック ツリー (BIT) | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 マルチセットを値範囲にわたる周波数配列としてモデル化し、フェンウィック ツリー内で維持します。

1. フェンウィック ツリーを構築し、頻度を 1 ずつ増やしてすべての初期要素を挿入します。 これにより、正しい開始プレフィックス合計が確立されます。 
2. 各クエリについて、その符号を確認します。 値が正の場合は挿入を表すため、フェンウィック ツリー内のその値の頻度を 1 つ増やします。 これにより、プレフィックスの合計と更新されたマルチセットの一貫性が保たれます。 
3. 値が負の場合、k 番目に小さい要素を削除する要求として解釈されます (k は絶対値)。 まず、フェンウィック ツリーを使用して、プレフィックスの合計が少なくとも k になるような最小のインデックスを見つけます。 このインデックスは、現在のマルチセット内の k 番目に小さい要素に正確に対応します。 
4. そのインデックスが見つかったら、フェンウィック ツリー内のその頻度を 1 つ減らします。 これは、その値の出現を 1 つだけ削除することをシミュレートします。 
5. すべてのクエリを処理した後、正の頻度でインデックスをスキャンします。 存在しない場合は、ゼロを出力します。 それ以外の場合は、頻度がゼロ以外のインデックスを出力します。 

重要な操作は「k 番目の検索」ステップで、フェンウィック ツリーでバイナリ リフティングを使用します。 各ビット レベルで、累積頻度 k を超えない場合は右に移動しようとします。 これにより、対数時間で答えが構築されます。 

### なぜ効果があるのか

 フェンウィック ツリーは常に、現在マルチセット内のすべての値の正確な多重度を保存します。 したがって、接頭辞の合計は、任意の値以下の要素の数を表します。 k 番目に小さい要素は、この累積カウントが k に達する最初の位置によって一意に決定されるため、プレフィックスの合計に対する二分探索により常に正しい要素が特定されます。 挿入と削除のたびに頻度が 1 回だけ更新されるため、この不変条件はすべての操作を通じて維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def find_kth(self, k):
        idx = 0
        bit_mask = 1 << (self.n.bit_length())
        while bit_mask:
            nxt = idx + bit_mask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bit_mask >>= 1
        return idx + 1

n, q = map(int, input().split())
a = list(map(int, input().split()))

fw = Fenwick(n)

for x in a:
    fw.add(x, 1)

for x in map(int, input().split()):
    if x > 0:
        fw.add(x, 1)
    else:
        k = -x
        pos = fw.find_kth(k)
        fw.add(pos, -1)

for i in range(1, n + 1):
    if fw.sum(i) - fw.sum(i - 1) > 0:
        print(i)
        break
else:
    print(0)
```フェンウィック ツリーは、要素の数ではなく、値の範囲にわたって初期化されます。 これは、配列内の位置を追跡しているのではなく、値の頻度を追跡しているため重要です。 

の`find_kth`関数は、暗黙的なプレフィックス合計に対してバイナリ リフティング検索を実行します。 少しずつ答えを構築し、必要な累積頻度を決して超えないようにします。 

最後のループでは、まだ存在する値を単純に検索します。 この問題では残りの要素が許容されるため、最初の正の周波数で停止します。 

## 実用的な例

 ### 例 1

 入力:```
5 5
1 2 3 4 5
-1 -1 -1 -1 -1
```マルチセット周波数を追跡します。 

| ステップ | 操作 | マルチセット状態 (概念) | 削除されました |
 | --- | --- | --- | --- |
 | 1 | 1 番目を削除 | 2 3 4 5 | 1 |
 | 2 | 1 番目を削除 | 3 4 5 | 2 |
 | 3 | 1 番目を削除 | 4 5 | 3 |
 | 4 | 1 番目を削除 | 5 | 4 |
 | 5 | 1 番目を削除 | 空 | 5 |

 すべての演算が終了すると要素が残らないため、出力は 0 になります。 

これにより、プレフィックスの削除を繰り返すと、空になるまで構造が正しく折りたたまれることが確認されます。 

### 例 2

 入力:```
3 4
1 1 3
2 -1 2 -1
```初期マルチセットは [1, 1, 3] です。 

| ステップ | 操作 | マルチセット |
 | --- | --- | --- |
 | 1 | 挿入 2 | 1 1 2 3 |
 | 2 | 1 番目を削除 | 1 2 3 (1 を削除) |
 | 3 | 挿入 2 | 1 2 2 3 |
 | 4 | 1 番目を削除 | 2 2 3 (1 を削除) |

 最終的なマルチセットには [2, 2, 3] が含まれるため、2 または 3 のいずれかが有効な出力になります。 

これは、重複が正しく処理され、削除は単一のオカレンスにのみ影響することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新と k 番目のクエリは、対数時間でフェンウィック ツリー操作によって処理されます。 
| スペース | O(n) | フェンウィック ツリー内に保存される 1 つの周波数配列 |

 境界では合計 200 万回の操作が許可されるため、対数係数を約 20 にすると、ソリューションは制限内に快適に保たれます。 メモリ使用量は n において線形に留まり、28 MB の制約内に収まります。

    import sys

        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

            idx = 0
            bit_mask = 1 << (self.n.bit_length())
            while bit_mask:
                nxt = idx + bit_mask
                if nxt <= self.n and self.bit[nxt] < k:
                    k -= self.bit[nxt]
                    idx = nxt
                bit_mask >>= 1
            return idx + 1

    n, q = map(int, input().split())

            return str(i)
    return "0"

 ## 特殊なケース

 重要なエッジケースは、削除が繰り返し最小の要素をターゲットにする場合です。 のような入力の場合`1 2 3 4 5`続いて繰り返される`-1`操作を行うたびに、構造は左から縮小します。 フェンウィック ツリーは周波数を正しく更新し、それぞれの`find_kth(1)`常に現在の最小値を返し、空になるまで確実に縮小します。 

もう 1 つのケースは、多数の同一の値から開始し、任意の順序の統計を繰り返し削除するなどの大量の重複です。 すべての等しい要素は同じインデックスを共有するため、削除するたびに頻度が 1 ずつ減少するだけであり、プレフィックスの合計は引き続き一貫して動作します。 k 番目のクエリは、同一性ではなく累積カウントに依存するため、同一の値を混同することはありません。 

最後に、挿入と削除を交互に行うことで、フェンウィック ツリーが常に現在のマルチセットを正確に反映するという不変条件が強調されます。 各操作はローカルであるため、グローバルな再構築は必要なく、正確性の問題とパフォーマンスの低下の両方を防ぎます。
