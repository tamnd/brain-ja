 ## 解決策
 ## 問題の理解

 島の西から東への断面を表すポリラインが与えられています。 エンドポイントは海面にあり、すべての内部ポイントは厳密に海面より上にあります。 連続する点の間では地形は直線であるため、島の境界全体は X 軸の上にある直線セグメントのチェーンとなり、高さ 0 で始まり高さ 0 で終わります。 

島の外側の視点から、日の出（西から東の方向）または日の入り（東から西の方向）の写真を撮ります。 その写真では、目に見える風景の一部が海を遮っています。 重要なのは、距離ではなく、角度の単位で海の地平線がどのくらい見えるかです。 カメラからの視線が島によって遮られていない場合にのみ、海が見えると見なされます。 

課題は、海が見える方向の合計角度範囲を最大化する平面上の視点と方向 (東または西) を選択することです。 出力は、その最大角度を度単位で表します。 

入力サイズは最大 50,000 ポイントに達するため、すべてのセグメントのペアまたはすべての視点を幾何学的チェックで試行するソリューションは遅すぎます。 n の二次関数は、最悪の場合、約 25 億回の演算が必要となるため、直ちに除外されます。 

重要な微妙な点は、答えは地形上の単一の最適なポイントに関するものではないということです。 その代わりに、異なる視点からは、地平線の異なる可視間隔が露出する可能性があります。 このため、単純なアプローチでは、最適であることが保証されていない固定カメラ位置 (通常は 1 つのエンドポイントまたはピーク) が誤って想定されることがよくあります。 

2 番目の落とし穴は、可視性を単純な高さの比較として扱うことです。 ブロッキングは角度的です。遠くにある高いピークは、近くにある低いピークよりも地平線の多くをブロックする可能性があるため、高さだけによる線形スキャンは失敗します。 

## アプローチ

 強引な解釈では、視点を固定し、ポリゴンのすべてのセグメントをチェックして、海の地平線のどの部分が見えるかを計算します。 固定視点の場合、カメラに対するすべての頂点またはセグメントの角度範囲を計算し、可視エンベロープを維持できます。 すべての候補視点に対してこれを実行すると、すでにコストが高くなりますが、さらに悪いことに、「関連する視点」のセットは離散的ではなく、平面に沿って連続的です。 すべての頂点に離散化しても、O(n²) 個の可視性計算が残ります。 

重要な観察は、視認性にとって重要なのは完全な形状ではなく、視点から地形までの斜面の上部エンベロープであるということです。 視点を単調な方向 (東または西) に沿ってスイープする場合、ブロック光線のセットは、新しいセグメントが角度順序で最大になる場合にのみ変化します。 これは、凸包または単調な斜面の積み重ねを維持することと構造的に同じです。 

固定された方向 (日没など) の場合、すべての光線が角度によって効果的に順序付けされるように、はるか西の方向に立っていると想像できます。 各テレイン頂点は視点からの光線に寄与し、これらの光線の上部エンベロープのみが問題となります。 最大の可視海は、このエンベロープ上の連続する「アクティブな」遮断方向の間のギャップに対応します。 

したがって、問題は、地形によって引き起こされる凸状チェーン上のギャップの角度スパンの計算に帰着します。これは、2D での凸包を計算するのと同様のスタック状の構造を使用して線形時間で実行できます。 

すべてのセグメントを順番に考え、「アクティブスロープ」の視点で構造を維持します。 新しいセグメントが以前のセグメントよりも小さな勾配を作成するたびに、以前の寄与は完全にブロックされているため削除されます。 これにより、角度ギャップが目に見える海の間隔に正確に対応する単調な構造が得られます。 最終的な答えは、連続する生き残った方向の間の角度の合計です。

 ## アルゴリズムのチュートリアル

 私たちは日没の方向に焦点を当てます。 日の出は対称的であり、入力を反転するか方向を入れ替えることで処理できます。 

1. 連続する点間の各セグメントを方向ベクトル (dx、dy) に変換します。 各ベクトルは水平線から上の角度に対応しますが、この段階では角度を直接計算することは避けます。 
2. 左から右にスイープし、左端の視点から見た上部の角エンベロープを表すセグメントのスタックを維持します。 各セグメントはその傾き dy/dx で表されますが、浮動小数点エラーを避けるために交差乗算を使用して傾きを比較します。 
3. 新しいセグメントごとに、スタック内の最後のセグメントを繰り返しチェックします。 新しいセグメントがスタックの最上部よりも小さいか等しい傾きを生成する場合、最上部のセグメントは完全にブロックされ、削除されます。 同じ側​​から見た場合、傾斜が小さいセグメントはより急なセグメントの先には見えないため、これは正当化されます。 
4. スタックが傾きの降順で単調になったら、新しいセグメントをプッシュします。 スタックは、目に見える海の間隔の角度境界を定義する目に見える稜線を表します。 
5. atan2(dy, dx) を使用して、スタック内の各セグメントをその角度に変換します。 連続した角度により、ブロックされた海域と可視の海域の間の境界が定義されます。 
6. 連続する境界角度の差を合計します。 この合計は、目に見える海の角度の合計です。 
7. 同じ手順を反対方向から繰り返し (順序を逆に) 日の出の視程を計算し、両方の結果の最大値を取得します。 

### なぜ効果があるのか

 水平方向に十分離れたどの視点でも、角度による地形セグメントの順序は、傾斜による順序と一致します。 モノトーン スタックにより、この角度順序の上部エンベロープを形成するセグメントのみが保持されることが保証されます。 スタックによって削除されたセグメントは、その方向の有効な視点の上部エンベロープの一部になることはありません。これは、後の急勾配のセグメントが関連するすべての光線方向でそのセグメントを支配するためです。 したがって、残りのセグメントは、可視光線と遮断光線の間の境界を正確に定義します。 それらの角度の間のギャップは、海を遮る地形がない方向に正確に対応しているため、これらのギャップを合計すると、目に見える角度範囲の合計が得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def build_angles(points):
    # returns list of angles of upper envelope segments
    stack = []

    def slope(i):
        x1, y1 = points[i]
        x2, y2 = points[i+1]
        return (y2 - y1, x2 - x1)

    def cross(a, b, c, d):
        return a * d - b * c

    for i in range(len(points) - 1):
        dy1, dx1 = slope(i)
        while stack:
            dy0, dx0 = stack[-1]
            # if new slope >= old slope, keep monotone decreasing
            if dy0 * dx1 <= dy1 * dx0:
                stack.pop()
            else:
                break
        stack.append((dy1, dx1))

    angles = []
    for dy, dx in stack:
        angles.append(math.atan2(dy, dx))
    return angles

def solve(points):
    ang1 = build_angles(points)
    pts_rev = points[::-1]
    ang2 = build_angles(pts_rev)

    def span(angles):
        if not angles:
            return 0.0
        angles.sort()
        res = 0.0
        for i in range(1, len(angles)):
            res += angles[i] - angles[i-1]
        return res

    return max(span(ang1), span(ang2)) * 180.0 / math.pi

def main():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    print(f"{solve(points):.10f}")

if __name__ == "__main__":
    main()
```この実装では、まず地形を方向セグメントに圧縮します。 単調スタックでは、上部の角度エンベロープに寄与する傾斜だけが残るように強制されます。 残った各セグメントは、atan2 を使用して角度に変換されます。これは、左から右の順序により dx が常に正であるため安全です。 

一方の側からの日没の眺めは、X 軸の順序を反映した後、もう一方の側からの日の出の眺めと同等であるため、反転は対称の場合を処理します。 

スパンの計算では角度を並べ替え、連続する差分を合計します。 これが機能するのは、残りの表示方向が互いに素な角度間隔を形成し、その合計測定値がソート順のギャップの合計に正確に一致するためです。 

直接浮動除算を行うと大きな座標で浮動誤差が生じるため、精度の問題を避けるために、傾きの比較はクロス乗算で行われるように注意する必要があります。

 ## 特殊なケース

 複数の連続するセグメントの傾きが同じ場合、微妙なエッジ ケースが発生します。 その状況では、単純なスタック ロジックが重複を保持し、単一の角度境界であるべきものを人為的に分割する可能性があります。 このアルゴリズムは、傾き比較において非厳密な不等式を持つセグメントを削除し、同一直線上にあるエッジが単一の代表的な方向に崩壊するようにすることで、この問題を解決します。 これにより、幅がゼロの角度ギャップがカウントされなくなります。 

最高点が非常に狭い場合には、別の特殊なケースが発生します。 その場合、多くの周囲のセグメントが削除され、2 つの支配的な光線だけが残ります。 スタックが正確にこれら 2 つの境界方向に構造を縮小し、角度スパンの計算により単一の連続した可視間隔が自然に生成されるため、アルゴリズムは引き続き正しく動作します。 

最後に、地形がほぼ対称である場合、日の出と日の入りの計算により、非常に似たエンベロープ構造が生成されます。 最大値を取ると、たとえ傾斜の離散化によって差が生じたとしても、わずかに広い角度ギャップを生成する方向が選択されるようになります。
