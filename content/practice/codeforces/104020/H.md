 ## 解決策
 ## 問題の理解

 次のような接続された無向グラフが与えられます。$n$交差点。 各エッジは 2 つの交差点間の道路を表します$u$そして$v$、そして各通りには家が直線的に連なっています。 私たちが持つ唯一の柔軟性は方向です。エッジに沿った家の番号付けが次から増加するかどうかを決定できます。$u \to v$またはから$v \to u$。 

制約はローカルですが、頂点で表現されます。 どの交差点でも、いくつかの通りが交わっており、各通りはその交差点に隣接するエンドポイント ハウスを 1 つだけ提供します。 この規則では、同じ交差点に接する 2 つの家に同じ番号を付けることは許されないと定められています。 頂点にはインシデント エッジごとに 1 つの数値 (エンドポイント ハウス番号) が表示されるため、すべてのインシデント エッジがその頂点で個別のエンドポイント ラベルを割り当てる必要があることを意味します。 

長さの各辺$h$エンドポイントラベルに貢献します$1$そして$h$。 エッジを次の方向に向けると$u \to v$、 それから$u$ラベルを受け取ります$1$そして$v$ラベルを受け取ります$h$。 逆にするとそれらが入れ替わります。 

したがって、タスクは、すべての頂点ですべての入射エッジがペアごとに異なる終点値を生成するように、すべてのエッジの方向を選択することになります。 

入力サイズは最大です$10^5$したがって、どの解もエッジの数が線形またはほぼ線形である必要があります。 二次関数または偶数$O(n \log n)$頂点ごとにエッジを繰り返し再訪するアプローチは、密なグラフでは遅すぎます。 

頂点に属する複数のエッジが同じ長さを共有する場合、微妙な問題が発生します$h$。 このような 2 つのエッジが両方とも同じ端点構成を向いている場合、頂点で同じ端点番号が生成され、直ちに制約に違反する可能性があります。 もう 1 つの隠れた罠はサイクルです。ローカルで貪欲な選択がサイクルの周囲に一貫性なく伝播し、最初に戻るときに矛盾が生じる可能性があります。 

## アプローチ

 効率を無視して局所的に考えると、各エッジには 2 つの可能な状態があり、各頂点はそのインシデントの選択に対して一意性制約を課します。 ブルートフォースの試みはすべてを試みるでしょう$2^m$方向性と妥当性のチェックは、小さなグラフを超えて実行不可能であることは明らかです。 

より構造化されたブルート フォースはバックトラックです。エッジごとに方向を割り当て、各頂点に対して、割り当てられたエンドポイント値のマルチセットを維持します。 競合が発生した場合は、後戻りします。 これは、各エッジが分岐係数を 2 倍にし、衝突が発生したときに制約が遅く枝刈りされるだけであるため、最悪の場合でも指数関数的な空間を探索します。 

重要な観察は、制約が完全に頂点ベースであり、グローバルな値ではなく、隣接関係に沿ったパリティのような一貫性にのみ依存するということです。$h$。 各エッジは正確に 2 つの端点ラベルを提供し、各頂点は入射エッジごとに一意のラベルを「消費」する必要があります。 この条件をエンドポイントでのマッチング スタイルの一貫性の問題として再解釈すると、この構造は管理可能になります。 

数値について考える代わりに、各エッジがその端点で 2 つの異なる「役割」を課し、各頂点がインシデント エッジに異なる役割を割り当てる必要があるという事実に焦点を当てます。 これは、すべての頂点で、選択された 2 つの「下位」端点が衝突しないようにエッジを方向付けることになります。 次に、グラフ構造によって伝播ルールが強制されます。つまり、1 つのエッジの方向を決定すると、多くの場合、隣接するエッジが制約されるようになり、接続されたコンポーネント間のパリティ スタイルの伝播によって矛盾が検出されます。 

これは、局所的な一貫性を確保しながら方向を割り当て、矛盾が発生するたびに不可能であると結論付けるグラフ トラバーサル アプローチにつながります。

 ## アルゴリズムのチュートリアル

 1. 各エッジのエンドポイント、インデックス、長さを格納する隣接リストを構築します。$h$。 また、各エッジに対して選択された方向も追跡します。 
2. 頂点の訪問状態と、トラバース用のキューまたはスタックを維持します。 各頂点は、すでに方向付けられているエッジによって引き起こされる制約を受けます。 
3. 任意の頂点から開始し、1 つの入射エッジに任意の方向を割り当て、両方のエンドポイントを処理構造にプッシュします。 最初の選択は、その後のすべての一貫性の決定を定義するシードとして機能します。 
4. 頂点の処理中$v$、まだ配向されていないすべての入射エッジを調べます。 For each such edge$(v, u, h)$、次のように方向を決定します。$v$競合するエンドポイント ラベルを再利用しません。 各頂点には個別のエンドポイント値が必要であるため、2 つのエンドポイント値のいずれかがすでに「使用」されている場合は常に方向が強制されます。$v$。 
5. エッジの方向が決まったら、制約をもう一方の端点に伝播します。 宛先頂点がそのエッジに対して競合する割り当てをすでに持っている場合、不一致を検出して停止します。 
6. 最初から到達可能なすべての頂点が処理されるまで続行します。 複数のコンポーネントが存在する場合は繰り返しますが、グラフは接続されているため、1 回の実行で十分です。 
7. 矛盾がなければ、各エッジに対して選択された方向を入力順に出力します。 

### なぜ効果があるのか

 このアルゴリズムは、局所的な単射性不変条件を強制します。どの時点においても、各頂点は、既に配向された入射エッジによって誘導された一連のエンドポイント値を維持し、値が 2 回挿入されることはありません。 すべてのエッジは、一度配向されるとエンドポイントごとに 1 つの値を提供するため、将来の配向の決定は、すでに固定された値によってのみ制約されます。 競合が発生した場合、それは 2 つの異なる伝播パスが頂点で同じエンドポイント値を強制することを意味しますが、これはグローバル割り当てでは避けられないため、有効な方向が存在しません。 逆に、プロセスが競合せずに終了した場合、すべての頂点はペアごとに異なるエンドポイント ラベルを受け取り、条件をグローバルに満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    edges = []

    for i in range(n):
        u, v, h = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, h))
        g[u].append((v, i))
        g[v].append((u, i))

    # orientation: 0 means u->v as stored, 1 means v->u
    orient = [-1] * n
    used = [set() for _ in range(n)]

    sys.setrecursionlimit(10**7)

    def dfs(v):
        for u, idx in g[v]:
            if orient[idx] != -1:
                continue

            a, b, h = edges[idx]

            # decide direction based on current vertex v
            if v == a:
                from_v, to_v = a, b
                dir0 = 0
            else:
                from_v, to_v = b, a
                dir0 = 1

            # try orient from_v -> to_v
            if h not in used[from_v]:
                orient[idx] = 0 if from_v == a else 1
                used[from_v].add(h)
            else:
                # reverse orientation
                if h in used[to_v]:
                    print("impossible")
                    sys.exit(0)
                orient[idx] = 1 if from_v == a else 0
                used[to_v].add(h)

            dfs(to_v)

    dfs(0)

    print(*orient)

if __name__ == "__main__":
    solve()
```この実装では、頂点ごとに、どのハウスの長さがエンドポイント ラベルとしてすでに使用されているかが維持されます。 これは、2 つの入射エッジが同じエンドポイント番号に寄与してはならないという制約を直接エンコードしたものです。 

DFS は、エッジの方向が一度固定されると、二度と戻らないことを保証します。 重要な決定点は、方向の選択です。エッジをデフォルトの方向に向けると、現在の頂点に重複した値が導入される場合、反転によって他のエンドポイントで競合が発生しない限り、アルゴリズムによってエッジが反転されます。 両方の方向が制約に違反する場合、構成は不可能です。 

実装上の微妙な懸念は、エッジが確実に 1 回処理されるようにすることです。 これは、`orient`エッジの訪問済みマーカーとして機能する配列。 もう 1 つの懸念事項は再帰の深さです。$n$大きくなる可能性があります。 それに応じて再帰制限も増加します。

 ## 特殊なケース

 重要なエッジ ケースは、多くの入射エッジが同一の制約または重複する制約を共有する高次の頂点です。 たとえば、頂点が同じ長さの複数のエッジに接続している場合、どの方向でも最終的にはその頂点で端点値が繰り返されることになります。 アルゴリズムはこれを即座に検出します。`used`その頂点に設定すると、各エッジを処理するときに重複が拒否されます。 

もう 1 つのエッジ ケースは、ローカルで貪欲な決定が一貫性なく伝播するサイクルです。 三角形では、2 つのエッジを満たす方向を選択すると、3 番目のエッジが 1 つの端点で既に使用されている端点に違反する方向に強制される可能性があります。 DFS 伝播により、最終エッジの処理時にそのような矛盾が確実に検出され、サイレントな不整合が防止されます。 

最後の微妙なケースは、グラフがツリーである場合です。 この場合、競合する伝播を作成するサイクルは存在せず、各エッジが新しい構造を導入するため、DFS は常に成功します。 アルゴリズムはトラバーサルに沿って一貫して方向を割り当て、すべての頂点は構築によって個別のエンドポイント値を維持します。
