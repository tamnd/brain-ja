 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、`n`カードには、それぞれ赤と青の 2 つの数字が書かれています。 すべてのカードをランダムにシャッフルした後、赤い数字を左から右に読んで数字を形成します`R`青い数字も同様に形成されます`B`。 赤と青の 2 人のプレーヤーが、次のことに賭けます。`R`より大きい`B`または`R`未満です`B`。 数字が同じ場合は引き分けです。 私たちの仕事は、シャッフル後にどちらのプレイヤーが勝つ可能性が高いのか、それともゲームが常に引き分けなのかを判断することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、カードの数と赤と青の数字の順序が提供されます。 「RED」、「BLUE」、または「EQUAL」のいずれを印刷するかをそれぞれの場合に出力する必要があります。 

制約を考慮すると (`1 ≤ n ≤ 1000`最大 100 のテスト ケース）、ブルート フォース アプローチにより、すべてのテスト ケースが生成されます。`n!`順列は実行不可能であるため、`1000!`天文学的に大きいです。 相対的に線形または線形に近い時間で実行されるソリューションが必要です。`n`テストケースごとに。 

エッジケースには、赤と青の数字がすべて同一であるか、合計が同一である状況が含まれます。 たとえば、次の場合`r = 123`そして`b = 123`、どの順列でも同じ数字が得られるため、ゲームは常に引き分けになります。 もう 1 つの微妙なケースは、個々の最大桁が優勢である場合です。`r = 9, 0, 0`そして`b = 1, 5, 3`。 赤が青を超える可能性がある位置の数を考慮しないと、単純に桁の合計を比較すると誤解を招く可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、カードのすべての順列が生成されます。`R`そして`B`各順列について、満たす順列の数を数えます。`R > B`または`R < B`。 これは正しいですが、次の場合には実行できません`n > 10`順列の階乗増加が計算限界を超えるためです。 最悪の場合の操作回数は、`O(n! * n)`。 

重要な洞察は、数字の相対的な順序が`R`そして`B`ソートされたシーケンス内の対応する位置の個々の比較に関してのみ重要です。 数字は独立しており、どの位置にも同様に出現する可能性があるため、代わりに、赤い数字が青い数字より大きい位置の数、青が赤より大きい位置の数を数え、等しいものを無視することができます。 どちらのカウントが大きいかによって勝者が決まります。 

これにより、検討する必要がなくなる問題が軽減されます。`n!`出現回数を数える順列`n`数字を与える`O(n)`各テストケースのソリューション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、赤い数字の文字列`r`、および青い数字の文字列`b`。 
3. 2 つのカウンターを初期化します。`red_count`そして`blue_count`、ゼロにします。 
4. 各インデックスを反復処理します。`i`0から`n-1`。 比較する`r[i]`そして`b[i]`整数として。 

- もし`r[i] > b[i]`、増分`red_count`。 
- もし`r[i] < b[i]`、増分`blue_count`。 
- それらが等しい場合は、何もしません。 
5. ループ後、比較します`red_count`そして`blue_count`。 

- もし`red_count > blue_count`、「RED」を出力します。 
- もし`red_count < blue_count`、「青」を出力します。 
・等しい場合は「EQUAL」を出力します。 

機能する理由: 各カードはどの位置にも等しく出現する可能性があります。 したがって、数字の各ペアを個別に比較することで、赤に対する青の予想される優位性、およびその逆の合計の予想される優位性が取得されます。 これは、一様ランダム順列の場合、大きい桁がより高い位置に配置される確率は、他の桁を超える位置の数に比例するという事実に基づいています。 これらのカウントを合計すると、どのプレイヤーが勝つ可能性が高いかを判断するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n = int(input())
    r = input().strip()
    b = input().strip()
    red_count = 0
    blue_count = 0
    for i in range(n):
        if r[i] > b[i]:
            red_count += 1
        elif r[i] < b[i]:
            blue_count += 1
    if red_count > blue_count:
        print("RED")
    elif red_count < blue_count:
        print("BLUE")
    else:
        print("EQUAL")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 ループオーバー`n`各桁の比較が正確にカウントされるようにします。 使用する`strip()`入力行から改行文字を削除します。 カウンタは、すべての桁を処理した後、一定時間内に結果を決定します。 完全な数値を形成するのではなくカウントを比較すると、整数のオーバーフローが回避され、ロジックが簡素化されます。

 ## 特殊なケース

 のために`n=1`、入力`r=0`そして`b=1`の場合、アルゴリズムは red_count=0、blue_count=1 を正しくカウントし、「BLUE」を出力します。 等しいシーケンスの場合、次のようになります。`r=09281`そして`b=09281`、red_count=blue_count=0、結果は「EQUAL」になります。 交互に優勢な混合シーケンス。`r=1234`そして`b=4321`、ポジションごとのドミナンスを正しく計算し、等しいカウントに合計して「EQUAL」を生成します。 このようなエッジケースはすべて、ポジションごとの比較戦略によって自然に処理されます。
