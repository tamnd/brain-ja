 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられます。元の配列は`a`および変更された配列`a'`。 変更は、次の連続する部分配列を選択することで構成されます。`a`そしてそれを非降順でソートして生成します`a'`。 私たちの仕事は、その部分配列の境界を決定することです。`l`そして`r`、1 ベースのインデックスを使用します。 複数のサブ配列により次のような問題が発生する可能性がある場合`a'`、最も長いものを選択し、まだ同点である場合は、有効な答えであれば何でも十分です。 

この問題はそれを保証します`a'`とは異なります`a`そして、正確に 1 つのサブ配列がソートされたことになります。 各テスト ケースには最大で次のものを含めることができます。`2 * 10^5`要素とその合計`n`すべてのテストケースで次を超えない`2 * 10^5`。 これは、二次解法が`10^10`これは 2 秒の制限には大きすぎます。 

注意すべきエッジケースとしては、`a`そして`a'`配列の先頭または末尾、または並べ替える部分配列に重複する値が含まれている場合に発生します。 たとえば、次の場合`a = [1, 2, 1]`そして`a' = [1, 1, 2]`の場合、アルゴリズムは 1 番目から 3 番目の要素にわたる部分配列を正確に識別する必要があります。 配列全体をスキャンせずに最初または最後の不一致のみを調べる単純なアプローチでは、このような場合に誤った境界が返される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアを試行しようとします。`(l, r)`その部分配列をソートするかどうかを確認します`a`収量`a'`。 これは明らかに正しいですが、遅すぎます。 おおよそあります`n*(n+1)/2`可能なサブ配列があり、それぞれについてソートと比較を実行します。 各候補部分配列のソートには次の時間がかかります`O(k log k)`どこ`k`は部分配列の長さです。 最悪の場合、これは以上の事態につながります。`O(n^3)`実行不可能な操作`n`まで`2 * 10^5`。 

重要な観察は、ソートされた部分配列が、次の位置に正確に対応していることです。`a`そして`a'`異なる。 左からトラバースすると、最初のインデックスは次のとおりです。`a[i] != a'[i]`始まりを告げる`l`サブ配列の。 同様に、右からスキャンすると、最後のインデックスが`a[i] != a'[i]`終わりを告げる`r`。 部分配列のソート`l`に`r`で`a`正確に生産します`a'`なぜなら、この問題により、1 つの部分配列のみがソートされたことが保証されるからです。 これにより、複雑さが軽減され、単一の線形パスで検索が行われます。`l`そして`r`、その後に検証またはオプションの並べ替えステップが続きます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`l = 0`そして`r = n - 1`。 
2. 配列を走査する`a`左から。 最初のインデックス`i`どこ`a[i] != a'[i]`になる`l`。 これにより、並べ替え操作によって値が変更された最も古い位置が取得されます。 
3. 配列を走査する`a`右から。 最初のインデックス`i`（最後から）ここで`a[i] != a'[i]`になる`r`。 これにより、ソートの影響を受けた最新の位置が取得されます。 
4. 出力では配列のインデックスが 1 であるため、両方に 1 を加算します。`l`そして`r`。 
5. 戻る`(l + 1, r + 1)`答えとして。 

機能する理由: 並べ替えは、連続ブロックにのみ影響します。`a`とは異なります`a'`。 定義上、このブロックの外側の要素は変更されません。 最初と最後の異なる位置を特定すると、ソートされているはずの部分配列全体が確実にキャプチャされます。 これらのインデックスを超えて拡張すると、変更されていない要素が含まれ、問題の制約に違反します。 これより小さい部分配列は一致しないため、この方法では常に最長の部分配列が生成されます。`a'`全体的に。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a_prime = list(map(int, input().split()))

        l = 0
        while l < n and a[l] == a_prime[l]:
            l += 1

        r = n - 1
        while r >= 0 and a[r] == a_prime[r]:
            r -= 1

        # convert to 1-based indexing
        print(l + 1, r + 1)

if __name__ == "__main__":
    solve()
```解決策は、テスト ケースの数を読み取ることから始まります。 各テスト ケースについて、次のようになります。`n`、`a`、 そして`a'`。 左側の境界線`l`不一致が見つかるまで最初からスキャンすることで識別されますが、正しい境界は`r`端からスキャンすると見つかります。 の`while`ループは、正確な境界で停止することを保証します。 Python 配列は 0 から始まるインデックスですが、問題では 1 から始まるインデックス付きの出力が想定されているため、1 から始まるインデックスへの変換が必要です。
