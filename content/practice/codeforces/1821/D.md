 ## 解決策
 ## 問題の理解

 0 から 0 までのインデックスが付いた巨大な 1 次元のセル グリッドがあります。$10^{18}-1$。 各セルは白から始まり、最初はセル 0 でポインタを制御します。ポインタは一度に 1 ステップずつ右に移動できます。 さらに、「Shift」ボタンがあります。押している間、ポインタが訪問したセルにマークが付けられ、Shift キーを放すと、訪問したすべてのセルが黒く塗りつぶされます。 せめて絵は描きたい$k$セルは黒ですが、指定されたセット内のみです$n$重複しないセグメント$[l_i, r_i]$。 私たちのタスクは、必要なポインターの移動と Shift 操作の最小数を計算するか、不可能であることを報告することです。 

入力セグメントは厳密に増加しており、ギャップと重複していないため、曖昧さなくセグメント間の移動を推論することができます。 制約により許可されるのは、$n$まで$2 \cdot 10^5$そして$k$まで$10^9$これにより、すべての個々のセルを反復するソリューションは除外されます。セグメントごとに操作する必要があります。 

微妙な点は、移動のカウントです。各移動は 1 つの移動としてカウントされ、Shift キーを押すと 1 つの移動としてカウントされ、Shift キーを離すと 1 つの移動としてカウントされます。 これは、大きなセグメントのペイントが無料ではないことを意味します。 Shift の開始と停止により、セグメント サイズに関係なく 2 つの操作が追加されます。 もう 1 つのエッジケースは次のような場合です$k$すべてのセグメントにわたる使用可能なセルの合計数を超えています。答えは -1 である必要があります。 

不注意なアプローチでは、ギャップを処理せずにセグメントを連続したものとして扱おうとしたり、シフトの開始点の最適化に失敗したりして、必要以上に多くの移動数が発生する可能性があります。 

## アプローチ

 単純な解決策は、考えられるすべてのポインタの動きをシミュレートすることです。 セル 0 から開始して、すべてのセルを順番に移動し、Shift キーを押して放し、セルをペイントします。 これは小さな入力では機能しますが、最大のセグメントまたはギャップが最大になる可能性があるため、ここでは実行できません。$10^9$ポインタは 0 から始まるため、文字通りのシミュレーションは法外に高価になります。 

重要な観察は、セグメントの外側の白セルを訪問する必要がないということです。 現在のポインターの位置から、ペイントする次のセルに移動することだけを考慮します。 セグメントに入ったら、Shift キーを押しながら選択したペイント範囲の右端に移動するのが最適です。 したがって、問題は、使用可能な左端のセグメントから開始して各セグメントにペイントするセルの数を決定し、必要な移動 (セグメントまでの距離 + Shift 操作の 2 とペイントされたセル) を合計することになります。 

各セグメントの塗装コスト$x$で始まるセル$l_i$は$(l_i - \text{current pointer}) + 1 + (x-1) + 1$。 最初の項は、現在の位置から次の位置へのポインタの移動です。$l_i$、次に Shift を押してから横に移動します$x-1$Shift キーを押しながらセルを押し、Shift キーを放します。 単純化するとこうなります$(l_i - \text{current pointer}) + x + 2$。 現在のセグメントから必要なだけ多くのセルを貪欲に取得できます。$k$に達します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(最大(セグメントの終わり)) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`pointer`0で、そして`moves`これはポインタの位置とこれまでの合計操作を表します。 
2. 各セグメントを反復処理します。`[l_i, r_i]`順番に。 
3. セグメントの長さを計算します`seg_len = r_i - l_i + 1`。 ペイントするセルの数を決定する`paint = min(seg_len, remaining_k)`。 
4. 現在のポインタからセグメントに到達するためのコストを計算します。`moves += l_i - pointer`。 
5. Shift キーを押します。`moves += 1`。 
6. 横に移動する`paint`Shift キーを押しながらセルを移動する:`moves += paint - 1`(最初のセルはすでに`l_i`）。 
7. シフトをリリースします:`moves += 1`。 
8. アップデート`pointer = l_i + paint - 1`、最後に塗られたセル。 
9. 減算`paint`残っているものから`k`。 もし`k`ゼロに達すると壊れます。 
10. すべてのセグメントが終わったら`k > 0`、-1を返します。 それ以外の場合は戻ります`moves`。 

機能する理由: 常に左端の未ペイントのセグメントから開始し、必要な数のセルをペイントすることで、最小の移動と最小の Shift 操作が保証されます。 ポインタは決して後戻りせず、各セグメントは到達するために必要なものだけを提供します。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        l = list(map(int, input().split()))
        r = list(map(int, input().split()))

        pointer = 0
        moves = 0
        remaining = k
        for i in range(n):
            seg_len = r[i] - l[i] + 1
            if remaining <= 0:
                break
            paint = min(seg_len, remaining)
            moves += l[i] - pointer  # move to start
            moves += 1  # press shift
            moves += paint - 1  # move while holding shift
            moves += 1  # release shift
            pointer = l[i] + paint - 1
            remaining -= paint
        
        if remaining > 0:
            print(-1)
        else:
            print(moves)

if __name__ == "__main__":
    solve()
```コードは 3 つの貢献を慎重に分離しています。`moves`: セグメントに移動し、Shift キーを押しながら移動し、Shift キーを放します。 の`paint = min(seg_len, remaining)`必要以上にペイントしないようにします。 更新中`pointer`最後のペイントされたセルに移動すると、次のセグメントに入るときに移動を数えすぎることがなくなります。
