 ## 解決策
 ## 問題の理解

 私たちは満たしています$n \times n$すべてのマスに白騎士か黒騎士のいずれかが含まれなければならないチェス盤。 目標は、攻撃を避けるために駒を配置することではなく、標準的なナイトの動きで反対色のナイトの何組が互いに攻撃できるかを最大化することです。 

「決闘」は、ナイトムーブによって隣接する 2 つのセルに反対の色が含まれる場合に発生します。 すべてのセルが常に占有されているため、すべてのナイトは複数の潜在的な相互作用に寄与し、問題はエッジがナイトに到達可能なペアを接続する固定グリッド グラフ上のグローバルな色付けの最適化になります。 

入力サイズが小さいため、$n \le 100$。 これにより、次のような解決策がすぐに可能になります。$O(n^2)$あるいは$O(n^2)$定数要素近傍チェックを使用します。 高次元の状態の検索やバックトラックを伴うもの$2^{n^2}$構成は不可能です。 

微妙なエッジケースは次のような場合です$n$特に小さいです$n = 3$。 非常に小さな基板の場合、ローカル パターンがグリッド全体で相互作用する可能性があるため、周期性やパリティに関する誤った仮定によって最適性が損なわれる可能性があります。 たとえば、素朴なチェッカーボードのカラーリングは最適に見えるかもしれませんが、間違ったパリティ参照で誤って実装された場合、ナイトの動きはルークやビショップの動きのように隣接関係に基づいていないため、クロスカラーエッジを最大化しない対称パターンが生成される可能性があります。 

もう 1 つの失敗例は、行に沿って色を交互に配置するだけで十分であると想定している場合です。 たとえば、次のようなパターンです。```
WBWB
WBWB
WBWB
WBWB
```構造化されているように見えますが、ナイトの移動が L 字型にジャンプするという事実は考慮されていないため、競合は行または列の独立したパリティだけでなく、2 次元のパリティの相互作用に依存します。 

## アプローチ

 ブルートフォースソリューションはすべてを試します$2^{n^2}$カラーリングを行い、各構成ごとに攻撃する反対色のナイトペアの数を数えます。 これは目的関数を直接評価するため概念的には正しいですが、構成の数は、$n = 3$、完全に実行不可能になります。 

重要な観察は、すべてのセルの寄与は、固定された相対オフセットにあるセルの色にのみ依存するということです。$(\pm 1, \pm 2)$そして$(\pm 2, \pm 1)$。 これは、局所的なパターンが全面的に一貫して伝播するため、繰り返し構造が最適である可能性があることを示唆しています。 

重要な洞察は、無限グリッド上のナイト グラフは平行移動に関して規則的であるため、周期的な色付けを試すことができるということです。 グローバルに推論する代わりに、小さな繰り返しブロック内での寄与を最大化しようとします。 あ$2 \times 3$または$3 \times 2$タイリングはすべてのナイト オフセットをキャプチャします。 この小さなブロックの色を列挙すると（$2^6 = 64$可能性)、どのパターンが内部のクロスカラー ナイト エッジを最大化するかを計算し、それをグリッド上に並べて表示できます。 

これにより、問題はグリッド全体にわたる指数関数的な問題から、小さなパターン検索にわたる一定の問題に軽減され、その後線形に構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{n^2} \cdot n^2)$|$O(n^2)$| 遅すぎる |
 | パターン検索オン$2\times3$ブロック |$O(64 \cdot n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ナイトの移動は常に境界内のセルを接続することに注目してください。$2 \times 3$近所。 これは、グローバル構造が小さな繰り返しパターンから構築できることを示唆しています。 
2. を修正します$2 \times 3$ブロックを作成し、その 6 つのセルに W/B を可能な限り割り当ててみます。 各割り当ては、ボード全体にわたる周期的なタイルを定義します。 
3. 候補パターンごとに、パターン内のナイト エッジの数 (タイル間のラップアラウンドの一貫性を含む) が反対の色を接続する数を計算します。 これは、十分に大きな繰り返しグリッドをシミュレートするか、ブロック内の相対オフセットを評価することによって行われます。 
4. 有効なデュエルの最大数を生み出すパターンを維持します。 パターンの数は一定（64）であるため、このステップは高速です。 
5. 最終的なものを構築する$n \times n$ベストを繰り返してボードに乗る$2 \times 3$すべての座標にわたるパターン。 

それが機能する理由は、翻訳の不変性に基づいています。 すべての騎士の動きは固定オフセットに対応するため、最適な構成はある有限のモチーフを繰り返すと想定できます。 より大きな不規則構造がより優れている場合、それをシフトしてもすべての局所寄与が一貫して改善されるわけではなく、均一な局所相互作用の下での最適性と矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# predefine knight moves
moves = [(2, 1), (2, -1), (-2, 1), (-2, -1),
         (1, 2), (1, -2), (-1, 2), (-1, -2)]

# try all 2x3 patterns
best_score = -1
best_pat = None

def score(pat):
    # pat is 2x3 list
    s = 0
    for i in range(2):
        for j in range(3):
            for dx, dy in moves:
                ni, nj = i + dx, j + dy
                if 0 <= ni < 2 and 0 <= nj < 3:
                    if pat[i][j] != pat[ni][nj]:
                        s += 1
    return s

for mask in range(1 << 6):
    pat = [[''] * 3 for _ in range(2)]
    for i in range(2):
        for j in range(3):
            bit = i * 3 + j
            pat[i][j] = 'W' if (mask >> bit) & 1 else 'B'
    val = score(pat)
    if val > best_score:
        best_score = val
        best_pat = pat

n = int(input())
ans = [[''] * n for _ in range(n)]

for i in range(n):
    for j in range(n):
        ans[i][j] = best_pat[i % 2][j % 3]

for row in ans:
    print(''.join(row))
```コードは最初に考えられるものをすべて列挙します$2 \times 3$各セルを 6 ビット マスクのビットとしてエンコードすることでパターンを作成します。 各パターンは、ブロック内に留まり、反対の色を接続するナイトの動きを数えることによって得点されます。 最適なパターンが保存されます。 

次に、構築ステップでは、座標のモジュロ演算を使用して、このパターンをボード全体にタイル状に配置します。 これにより、再計算を行わずに一貫性と定期的な繰り返しが保証されます。 

よくある実装上の落とし穴は、ナイトの移動は列挙では方向性があるが、対称的に扱う必要があることを忘れていることです。 ただし、色を比較するだけなので、二重カウントしてもどのパターンが最適であるかには影響しません。

 ## 特殊なケース

 のために$n = 3$、ボードはすべてのナイト オフセットが範囲内に存在するのに十分な大きさです。 単純な行ベースのチェッカーボードは、対角線のナイト接続パターンを無視するため、ここでは失敗します。 タイル化アプローチは引き続き機能します。$2 \times 3$モチーフは、考えられるすべてのローカル相互作用をすでにキャプチャしています。 

のために$n = 100$、パターンの繰り返しによって境界固有のロジックが導入されてはなりません。 このアルゴリズムはエッジを異なる方法で処理しないため、正確性やパフォーマンスが低下することはありません。 

奇数と偶数の場合$n$、インデックス作成は純粋にモジュール化されているため、構造は何も変わりません。 これにより、寸法がパターン サイズの倍数でない場合に破損する、パリティ ベースのデザインによくある落とし穴が回避されます。
