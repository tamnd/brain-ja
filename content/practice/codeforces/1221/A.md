 ## 解決策
 ## 問題の理解

 いくつかの独立したゲーム状態が与えられます。 各状態は、値が 2 の累乗であるタイルで構成されます。 1 回の操作で、同じ値を持つ 2 つのタイルを選択し、それらを合計した値を持つ 1 つのタイルに結合することがあります。 

問題は、価値のあるタイルを取得できるかどうかです。`2048`任意の数のマージを実行した後。 

操作はゲーム 2048 とまったく同じです。2 つの等しい 2 のべき乗が結合されて、次に大きい 2 のべき乗になります。 すべての値はすでに 2 の累乗であるため、すべてのマージでも 2 の累乗が生成されます。 

制約は非常に小さいです。 クエリは最大 100 個あり、各クエリには最大 100 個の数値が含まれます。 2 のべき乗の周波数カウントを使用したシミュレーションでも、十分に高速になります。 高度なデータ構造は必要ありません。 

重要な観察は、どのタイルが将来に貢献できるかを理解することから得られます。`2048`。 

より大きいタイル`2048`役に立たない。 マージは値を増やすだけなので、次のようなタイル`4096`決してなることができない`2048`。 また、小さなタイルと結合して作成することもできません。`2048`マージは等しい値間でのみ許可されるためです。 

もう 1 つの微妙なケースは、使用可能なすべてのタイルの合計が次の値に達した場合です。`2048`たとえ個々のタイルがその値の近くで開始されなかったとしても。 

例えば：```
1
11
1 1 2 2 4 4 8 8 16 16 1024
```使用可能な合計は次のとおりです。```
1+1+2+2+4+4+8+8+16+16+1024 = 1086
```これでは十分ではないので、答えは次のとおりです`NO`。 

別の例:```
1
2
1024 1024
```答えは`YES`なぜなら二人は`1024`タイルは直接マージされます`2048`。 

よくある間違いは、次より大きい値を含めることです。`2048`合計すると:```
1
2
4096 4
```正しい答えは、`NO`。 

不注意な解決策により合計額が計算される可能性があります`4100 ≥ 2048`そして不正解`YES`、たとえ`4096`タイルは生産に決して役立ちません`2048`。 

## アプローチ

 最も直接的なアプローチは、ゲームをシミュレートすることです。 2 の累乗ごとにタイルが何個存在するかを数えることができます。 何らかの値のコピーが少なくとも 2 つあるとき`x`、それらのペアを値にマージします`2x`。 このプロセスを繰り返すと、最終的には作成できるすべてのタイルが生成されます。 

このシミュレーションは正しいです。マージのすべての正当なシーケンスがまったく同じ最終キャリー伝播を生成するからです。 問題は、実際に必要以上の機械が使われていることです。 

重要な観察は、すべてのタイルの値が最大でも`2048`いつでも必要なだけマージできます。 2 のべき乗は、2 進数のキャリーとまったく同じように動作します。 

以下のすべての値を取るとします。`2048`それらを合計します。 それらの合計が少なくとも`2048`そうすると、いつでもマージを実行できます。`2048`タイルが表示されます。 その理由は、マージを繰り返すと、単純にこの総質量が 2 のべき乗にどんどん大きくなるからです。 

すべてのタイルの合計が以下の場合`2048`未満です`2048`を作成してから、`2048`マージによって合計が増加することはないため、タイルは不可能です。 

これにより、問題全体が単純な合計に還元されます。 

各クエリについて、以下の数値をすべて無視します。`2048`、残りの数値を加算し、合計が少なくとも`2048`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n + log V) | O(log V) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ここ`V`シミュレーション中に表示される可能性のある 2 の累乗の最大値です。 

## アルゴリズムのチュートリアル

 1. クエリの数を読み取ります。 
2. クエリごとに、すべてのタイル値を読み取ります。 
3. 現在の合計をゼロに初期化します。 
4. すべてのタイルについて、その値が最大かどうかを確認します。`2048`。 
5. 値が最大の場合`2048`、それを累計に加算します。 

より大きい値`2048`の作成には決して貢献できません`2048`タイルなので無視されます。 
6. すべてのタイルを処理した後、合計を次と比較します。`2048`。 
7. 合計が少なくとも`2048`、印刷`"YES"`。 
8. それ以外の場合は、印刷します`"NO"`。 

### なぜ効果があるのか

 すべてのタイルの合計は、マージ操作ごとに保存されます。 2 つの等しいタイル`x + x`一枚のタイルになる`2x`したがって、価値が失われることも得られることもありません。 

より大きいすべてのタイル`2048`マージによって値が減少することはないため、これは無関係です。 そんなタイルは絶対にあり得ない`2048`、より小さい値とマージして作成することもできません。`2048`。 

値が以下のタイルのうち`2048`、マージを繰り返すと、バイナリ加算をキャリーするのとまったく同じように動作します。 それらの合計が少なくとも`2048`、それらのキャリーは最終的に`2048`タイル。 それらの合計が以下の場合`2048`、一連のマージでは、利用可能な合計質量を超える値のタイルを作成することはできません。 

したがって、条件は```
sum(all values ≤ 2048) ≥ 2048
```必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())

    for _ in range(q):
        n = int(input())
        arr = list(map(int, input().split()))

        total = 0
        for x in arr:
            if x <= 2048:
                total += x

        print("YES" if total >= 2048 else "NO")

solve()
```実装は証明に直接続きます。 

変数`total`将来に寄与する可能性のあるすべてのタイルの合計を保存します`2048`。 より大きい値`2048`すぐにスキップされます。 

1 つのクエリを処理した後、1 回の比較によって答えが決まります。 

Python ではオーバーフローの懸念はありません。 最悪の場合でも、合計は Python の整数制限をはるかに下回ります。 

最も一般的な実装上の間違いは、次の値より大きい値を無視することを忘れることです。`2048`。 そうすると、次のようなタイルが誤って扱われます。`4096`有用な貢献者として。

```アルゴリズムは追加します`2048`累計を求めて`2048`。 合計はすでに少なくとも`2048`、それは出力します`YES`。 ターゲット タイルは既に存在するため、マージは必要ありません。
