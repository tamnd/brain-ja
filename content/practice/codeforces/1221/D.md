 ## 解決策
 ## 問題の理解

 一連のフェンス ボードが与えられ、それぞれに初期の高さと高さの増加単位あたりのコストが設定されています。 1 回の操作でボードを選択し、その高さを 1 つだけ増やすことができ、そのたびに単位あたりのコストを支払います。 どのボードに対してもこれを何度でも繰り返すことができます。 

目標は、隣接する 2 つのボードが最終的に同じ高さにならないようにすることです。 私たちはターゲットの形状を一致させようとしているのではなく、できるだけ費用を抑えながら近隣間の平等を回避することだけを目的としています。 

主な難しさは、最終的な高さを直接選択せず、増分のみを制御することです。 したがって、すべてのボードには初期の高さから無限に多くの最終値があり、ユニットが追加されるたびにコストが直線的に増加します。 

すべてのクエリの合計 n は最大 3×10^5 であるため、制約によりクエリごとに O(n) または O(n log n) の解が強制されます。 近隣間のすべての高さの組み合わせを探索しようとしたり、大きな値範囲にわたって DP を使用したりするソリューションは、高さが際限なく増加するため、すぐに失敗します。 

素朴な試みは、2 つのボードの 1 つを増やして関係を解消することによって、隣接する各平等を独立して修正することです。 これは、1 つのボードを増やすと他の隣接ボードと新たな競合が発生する可能性があるため、ローカル修正が安全に構成されないため、失敗します。 

2 番目の微妙なエッジ ケースは、連続する 3 つのボードの初期高さが等しい場合です。 中央だけを貪欲に修正するのは最適に見えるかもしれませんが、後で繰り返し増加を強制する可能性があり、事前に別の構成を調整するよりもコストが高くなります。 

## アプローチ

 最終構成での増加量に応じて、各ボードが 2 つの可能な「状態」を持つものとして再解釈すると、問題は扱いやすくなります。 近隣間の平等のみが重要であるため、重要なのは絶対的な高さではなく、隣接する 2 つの選択された最終高さが衝突するかどうかです。 

重要な観察は、最適なソリューションでは、各ボードが元の値の最大 2 倍まで増加するということです。 これは最初は明らかではありませんが、構造からわかります。ボードが 2 回以上持ち上げられた場合、より低コストの組み合わせで、分離の責任を隣接するボードに移すことができます。 これにより、各ノードが小さな状態空間に境界付けされます。 

したがって、各位置を最大 3 つの意味のある選択肢 (0、1、または 2 単位ずつ増やす) があるものとして扱います。 調整をローカルに再配分することで、より大きな増加をより安価にシミュレートできます。 

ここで、問題は線形 DP になり、各位置で 3 つの状態の 1 つを選択し、隣接する最終高さが異なることを保証しながら、選択した増分に比例したコストを支払います。 

各 i について、i−1 の状態から i の状態へのすべての遷移を試行し、次のことを確認します。 

a[i] + デルタ[i] != a[i−1] + デルタ[i−1]

 コストは delta[i] * b[i] として累積されます。 

これにより、問題はチェーン上の小規模な状態の DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての高さの割り当てに対するブルートフォース | 指数 | お(1) | 遅すぎる |
 | ポジションごとに 3 つの状態を持つ DP | クエリあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[j] を、現在のボードが j 単位だけ増加したときの現在位置までの最小コストとして定義します。ここで、j は 0、1、または 2 です。 

基板を左から右に加工していきます。 

1. 最初のボードの dp を初期化します。 {0,1,2} の各 j については、増分に対してのみ支払うため、dp[j] = j * b[1] となります。 
2. 2 から n までの次のボード i ごとに、無限大で初期化された新しい配列 ndp を作成します。 
3. {0,1,2} の以前の状態 p と、{0,1,2} の現在の状態 c のそれぞれについて、最終的な高さが異なるかどうかを確認します: a[i-1] + p != a[i] + c。 それらが等しい場合は、この遷移をスキップします。 
4. 移行が有効な場合は、以下を更新します。 

ndp[c] = min(ndp[c], dp[p] + c * b[i])

これにより、最も安価な有効な構成が確実に引き継がれます。 
5. dp を ndp に置き換えて続行します。 
6. すべての位置を処理すると、答えは min(dp[0], dp[1], dp[2]) になります。 

なぜ効果があるのか

 DP は、最適な部分構造を維持しながら、隣接するペアの有効なローカル構成をすべてエンコードします。 すべてのグローバル ソリューションは、位置ごとに {0,1,2} の 1 つの増分シーケンスに正確に対応します。 最適解がある位置でより大きな増分を使用した場合、妥当性を損なうことなくそれを 3 減らして近傍を調整できます。これは、切り詰められた状態空間内で最適性が維持されることを意味します。 隣接性制約は最終値の同等性にのみ依存するため、ローカル互換性がグローバルな実現可能性を完全に決定し、チェーン DP が完全なソリューション スペースをキャプチャできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n = int(input())
    a = []
    b = []
    for _ in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    if n == 1:
        print(0)
        return

    dp = [0, b[0], 2 * b[0]]

    for i in range(1, n):
        ndp = [INF, INF, INF]
        for p in range(3):
            for c in range(3):
                if a[i - 1] + p == a[i] + c:
                    continue
                ndp[c] = min(ndp[c], dp[p] + c * b[i])
        dp = ndp

    print(min(dp))

q = int(input())
for _ in range(q):
    solve()
```DP アレイは、現在のボードで許可されている各増分状態の最適コストを追跡します。 この移行により、隣接するボード間で最終的な高さが同じになることが禁止されることが明示的に強制されます。 各ユニットのコストは b[i] であるため、コスト条件は現在のボードに適用する増分数にのみ依存します。 

実装の微妙な点は、最初の要素の dp を正しく初期化することです。 将来の移行では平等を避けるために柔軟性が必要になる可能性があるため、ゼロだけでなく 3 つの状態すべてを含める必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3
2 4
2 1
3 5
```各ポジションの後に dp を追跡します。 

| 私 | a[i] | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 4 | 8 |
 | 2 | 2 | 4 | 1 | 10 |
 | 3 | 3 | 9 | 5 | 10 |

 i=2 では、状態に応じて i=1 と競合すると dp[0] が高価になり、遷移では最も安価な非等価ペアが選択されます。 最終的な答えは 2 です。これは、隣接する同じ高さの間の単一の競合を最小限に解決する状態の組み合わせを選択することで得られます。 

このトレースは、DP が単一の貪欲な修正へのコミットを回避し、代わりに複数の高さ調整の可能性を備えていることを示しています。

 ## 特殊なケース

 重要なエッジケースは、初期の高さがすべて等しい場合です。 アルゴリズムは、それが最も安価なローカル修正だったという理由だけで、同じボードを繰り返し増やすことを避けなければなりません。 DP では、これは 3 つの状態すべてを前方に繰り上げることによって処理されます。 各ステップで、最終的な高さを同じにすることは明示的に禁止されており、アルゴリズムは増分を 1 つのボードに積み重ねるのではなく、複数のボードに分散することを強制されます。 

もう 1 つのエッジ ケースは、隣接する 2 つが等しくない、厳密に増加するシーケンスです。 この場合、すべての遷移は有効であり、dp[0] はすべての位置にわたって変更されずに伝播するため、DP はどこでもゼロ増分を正しく選択します。 

最後のエッジケースは、パターン 5、5、6、6、7、7 のような等しいペアを交互に配置することです。 ここでは、ローカル修正が干渉する可能性がありますが、DP は複数の状態の選択を維持するため、以前の決定によって後で高価な修正が強制されることはありません。
