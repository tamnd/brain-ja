 ## 解決策
 ## 問題の理解

 各クエリは、3 つのグループに分けられた学生のプールを記述します。 プログラマーの学生もいれば、数学者の学生もいますし、まったく専門分野を持たない学生もいます。 有効なチームには、正確に 3 人の学生が含まれ、少なくとも 1 人のプログラマーと少なくとも 1 人の数学者が含まれている必要があります。 残りのスロットがある場合は、最小要件が満たされている限り、専門知識を持たない学生や、プログラマーや数学者の間で役割の種類を重複させることも含めて、どの学生でも埋めることができます。 

タスクは、クエリごとに、これらの制約の下でサイズ 3 の独立したチームをいくつ形成できるかを決定することです。 各生徒は最大 1 回しか使用できないため、基本的に利用可能な生徒を有効なトリプルに分割します。 

制約は次のとおりです$10^8$カテゴリごとに最大$10^4$クエリ。 これにより、シミュレーションや組み合わせの検索が即座に除外されます。 どのようなソリューションでも、各クエリを定数時間の演算に減らす必要があります。$10^4$偶数を使用したクエリ$O(\sqrt{n})$または$O(n)$クエリごとに実行すると遅すぎます。 

1 つのグループが非常に大きく、他のグループが小さい場合、微妙な失敗のケースが発生します。 たとえば、プログラマーは豊富だが数学者が不足している場合、数学者がボトルネックになるため、欲張ってすべてのプログラマーを優先してチームを編成することはできません。 同様に、「ユニバーサル」学生 (専門知識を持たない学生) は柔軟ですが、チームごとに少なくとも 1 人のプログラマーと 1 人の数学者を配置するという要件に代わることはできません。 

素朴な間違いは、チームごとに 1 人のプログラマーと 1 人の数学者を消費し、中立的な学生で埋めることで、常に貪欲にチームを形成する必要があると想定することです。 これは単純な場合には機能しますが、中立グループの使用量のバランスをとることでより効率的な再配布が可能になる場合には失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 私たちは、任意のカテゴリーからプログラマー 1 人、数学者 1 人、追加の学生 1 人を選んでチームを編成することを繰り返し試みます。 有効なトリプルを形成できなくなるまで続けます。 すべてのステップで制約が尊重されるため、これは正しいです。 ただし、チーム編成ごとに編成に応じてカウントが1～2ユニット減りますので、最悪の場合はパフォーマンスを行います。$O(c + m + x)$クエリごとの操作。 までの値$10^8$、これは不可能です。 

重要な観察は、実際に重要となる制約は 2 つだけであるということです。すべてのチームには少なくとも 1 人のプログラマーと少なくとも 1 人の数学者が必要です。 中立の生徒は、コアの組み合わせが決定された後にサポートできる追加チームの数にのみ影響します。 

最初にプログラマーと数学者をペアにする場合、そのような必須のペアの数は次の制限によって制限されます。$\min(c, m)$。 各チームに必要なプログラマーは 1 人、数学者は 1 人です。$\min(c, m)$チームは中立の学生に関係なく存在できます。 ただし、中立の生徒は 3 番目のスロットを埋めることで、不足している役割を間接的に置き換えることができます。これにより、「不均衡な」状況を直接のペアリングの制限を超えて追加のチームに変換することができます。 

重要な洞察は、各チームにちょうど 3 人の学生が参加し、すべての有効なチームには少なくとも 1 人のプログラマと 1 人の数学者が含まれている必要があるということです。 したがって、制限要因は、プログラマーと数学者の合計の数、または学生の総数を 3 で割ったものになります。 したがって、最適な答えは次の両方によって制限されます。$$\min(c, m, \lfloor (c + m + x)/3 \rfloor)$$この式は、両方の制約を捉えています。つまり、プログラマーと数学者のどちらか小さい方を超えることはできず、すべての生徒から形成される可能性のあるチームの総数を超えることはできません。

 | 最適 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値を読み取る$c, m, x$クエリ用です。 これらは、プログラマー、数学者、および中立的な学生の数を表します。 
2. 生徒の総数を計算する$s = c + m + x$。 これは、各チームが 3 人の生徒を使用するため、全体的な収容力の制約を捉えています。 
3. コンピューティング$s // 3$、これは、役割の制約を無視した場合に可能なチームの最大数です。 これにより、定員を超えることがなくなります。 
4. コンピューティング$\min(c, m)$、これは、各チームが少なくとも 1 人のプログラマーと 1 人の数学者を使用する必要がある場合に可能なチームの最大数です。 これにより、役割の実現可能性が強化されます。 
5. これら 2 つの境界の最小値を取得します。 この交差により、両方のリソース制約が同時に満たされることが保証されます。 
6. クエリの結果を出力します。 

### なぜ効果があるのか

 各チームには正確に 3 人の異なる生徒が参加するため、チームの総数は次を超えることはできません。$s // 3$。 独立して、各チームには少なくとも 1 人のプログラマーと 1 人の数学者が必要であるため、チームの数がどちらかを超えることはできません。$c$または$m$。 中立の生徒は 3 番目のスロットがどのように埋まるかにのみ影響しますが、各チームが両方の必須プールから引き分けなければならないという事実は変わりません。 したがって、真の最大値はこれらの独立した制約の交差部分であり、3 つの量の正確な最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        c, m, x = map(int, input().split())
        total = c + m + x
        print(min(c, m, total // 3))

if __name__ == "__main__":
    solve()
```実装は派生した式に直接に従います。 クエリごとの計算はいくつかの算術演算のみであるため、一定時間で実行されます。 この分割では整数フロア分割が使用され、完全なチームの最大数が正しく適用されます。 

よくある間違いは、最初にプログラマーと数学者を消費し、次にニュートラルで調整することで、貪欲にチームを構築しようとすることです。 このアプローチでは、後の最適な形成を妨げる形で 1 つのカテゴリを過剰に使用する危険があります。 閉じた形式のソリューションでは、意思決定プロセス全体をグローバルな制約に集約することで、順序付けの問題を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q) | 各クエリは定数算術演算で処理されます。 
| スペース | お(1) | 少数の整変数のみが使用されます。 

このソリューションはクエリの数に比例してスケールします。すべての入力を少なくとも 1 回読み取る必要があるため、これが最適です。 と$q \le 10^4$, これは制限時間内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        c, m, x = map(int, input().split())
        out.append(str(min(c, m, (c + m + x) // 3)))
    return "\n".join(out)

# provided samples

# custom cases
assert run("1\n0 5 10\n") == "0", "no coders"
assert run("1\n5 0 10\n") == "0", "no mathematicians"
assert run("1\n5 5 0\n") == "3", "balanced case"
assert run("1\n100 1 100\n") == "1", "single bottleneck"
assert run("1\n3 3 3\n") == "3", "perfect symmetry"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、必要なロールの 1 つがゼロである場合です。 入力用`0 10 10`、有効なチームには少なくとも 1 人のコーダーが必要であるため、チームを結成することはできません。 アルゴリズムは計算します`min(0, 10, 20//3)`これは正しく生成されます`0`。 

もう 1 つの微妙なケースは、中立的な生徒が多いにもかかわらず、1 つの役割が非常に小さい場合です。 のために`10 1 100`、合計は 111 であるため、合計 //3 は 37 ですが、min(c,m) は 1 であるため、答えは 1 になります。これにより、中立的な生徒は必要な役割の欠落を補うことができないことが確認されます。 

最後のケースは、すべてのバランスが取れている場合です。`3 3 3`。 ここで、total//3 は 3 に等しく、min(c,m) は 3 に等しいので、すべての生徒をサイズ 3 の有効なチームに完全に分割できます。これは、式が対称入力を人為的に制限していないことを検証します。
