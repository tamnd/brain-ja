 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、クエリ値 X ごとに、1 を繰り返し追加することで配列の個々の要素を増やすことができます。 各クエリは独立しており、常に同じ初期配列から開始します。 

目標は、すべての要素にわたってビットごとの AND をとったときに結果が正確に X になるように配列を変換することです。すべての要素にわたって実行する合計 +1 演算の数を最小限に抑えたいと考えています。 

主な問題は、AND 演算が配列全体でグローバルであることです。 すべての要素には生き残るすべてのビットが含まれている必要があるため、単一の要素を増やすと、最後の AND のすべてのビットに影響します。 

制約は大きく、最大 200,000 個の要素と 200,000 個のクエリがあり、各値は最大 2^20 です。 これにより、クエリごとのシミュレーションや要素ごとの貪欲な構築が即座に排除されます。 クエリごとにすべての要素を反復処理すると、遅すぎます。 クエリあたり O(n log A) でも大きすぎます。 

最初はどの要素にも存在しないビットが X に含まれている場合、微妙なエッジ ケースが発生します。 たとえば、1 つの奇数を除いてすべての数値が偶数である場合、低いビット パターンを強制しようとすると、要素を慎重に上に押し上げる必要があります。 もう 1 つのエッジ ケースは、X がすでに配列の AND と等しい場合です。 その場合、答えはゼロですが、それは中間推論がビットを独立して「修正」する必要があると誤って仮定していない場合に限ります。 

最も危険な障害モードは、AND 制約が共有ビット要件を通じてすべての要素を結合していることを無視して、各要素を独立して扱うことです。 

## アプローチ

 ブルートフォース手法では、各クエリ X に対して、すべての要素がビット単位の AND が X と等しい値になるように、必要な最小の増分を構築しようとします。これは、(a'i & X) = X を満たすためにすべての要素 a'i が必要であることを意味します。そうでない場合、X は最終的な AND に出現できません。 

乱暴なアイデアは次のとおりです。要素ごとに、X のすべてのビットが含まれるまで要素を最小限に増やしてから、少なくとも 1 つの要素に AND 条件を破る余分なビットが導入されないようにします。 制約が満たされるまで各要素と各クエリに対して上向きの増分をシミュレートする必要がある場合があるため、これはすぐにコストが高くなります。 最悪の場合、各要素は必要なビット パターンと一致する前に多くの整数を上方向にスキャンする必要があり、O(n · maxA · q) のような結果が生成されますが、これは不可能です。 

重要な洞察は、視点を逆転させることです。 X に対して AND を行う数値を構築することを考えるのではなく、X によって各ビットに課される制約を個別に検討します。 

任意のビット位置 b について:

 X のビット b が 1 に等しい場合、最終配列内のすべての要素はビット b = 1 でなければなりません。これにより、バイナリ表現で X の必要な 1 ビットがすべて含まれる数値に達するまで、すべての要素が強制的に増加します。 

X のビット b が 0 である場合、少なくとも 1 つの要素はビット b = 0 でなければなりません。そうでない場合、AND はそのビットを誤って 1 に保持します。これにより、要素全体にわたるグローバルな「カバレッジ」制約が導入されます。 

これにより、問題は 2 つの相補的な要件に分割されます。1 つは要素ごとに必要な 1 ビットを含めることの実現可能性、もう 1 つは AND 内で 0 ビットが確実に残るようにするためのグローバル分散です。 

重要な単純化は、各要素について、指定されたマスク X を満たすために要素を増やすコストを個別に計算できることです。それがわかると、グローバル構造は、少なくとも 1 つの要素が各禁止ビットを回避するようにしながら、すべてのビットを満たすために「強制」する必要がある要素の数を決定することになります。 

これにより、問題は固定 20 ビット ユニバースでのビット単位の事前計算に軽減され、クエリ全体で効率的に再利用できるようになります。

 | 最適 | O(n · 20 + q · 20) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 ビット構造と距離に関して配列を前処理して、マスクを満たすように各数値を「アップグレード」します。 

1. 各数値について、特定のビット パターンを含むスーパーマスクに到達するための最小コストを計算します。 これは、20 ビットのビット DP を使用して行われ、各数値をビット構成上の桁グラフのソース状態として扱います。 
2. 考えられるマスクごとに、変更せずにそのマスクをすでに満たしている要素の数を事前計算します。 これにより、ベースラインの実現可能性情報が得られます。 
3. 各クエリ X について、X をすべての要素が X と互換性がある必要があるという要件として解釈します。これは、最終的な配列内のどの要素も X が必要とするビットを欠落してはいけないことを意味します。 
4. 各要素が X を満たすように強制するコスト寄与を計算します。このコストは、現在の値と、X のすべてのビットが適切に設定された最小数 ≥ それとの差にのみ依存します。 
5. これらの要素ごとのコストを集計すると同時に、X に設定されていないすべてのビットについて、そのビットをゼロに保つ要素を少なくとも 1 つ保持するようにします。 これは、禁止ビットごとに最小コストの「例外」要素を選択することによって処理されます。 
6. 答えは、必要なアップグレードの合計から、慎重に選択した要素を可能な限り変更しないことによって得られる節約額を差し引いたものです。 

### なぜ効果があるのか

 正確性は、AND 制約を独立したビット要件に分割することで得られます。 X に設定されたビットは、すべての要素にわたって普遍的な制約を適用し、要素ごとにローカルに処理できます。 X に設定されていないビットには存在制約が適用され、それらを保持するには少なくとも 1 つの要素が必要です。 各ビットは独立して動作し、要素を調整するコストはそのバイナリ構造のみに依存するため、グローバル最適化は、禁止ビットごとの小さな結合項を持つローカルな決定の合計に分解されます。 これにより、無関係なビット間の相互作用が見逃されることがなくなり、すべての最適な構成が要素ごとの調整とビットごとの除外の一貫した選択に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 20
INF = 10**18

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1 << MAXB

    # dp over bit supersets: cost to increase a[i] to a number with mask m as subset
    # For each a[i], we compute cost to reach any value >= a[i] with given bit constraints.
    # We store best cost per mask across all elements.
    best = [INF] * size

    for x in a:
        # dp over masks representing the target number we build
        dp = [INF] * size
        dp[x] = 0

        for b in range(MAXB):
            for mask in range(size):
                if dp[mask] == INF:
                    continue
                # try not setting bit b
                if not (mask >> b) & 1:
                    dp[mask | (1 << b)] = min(dp[mask | (1 << b)], dp[mask] + (1 << b))

        for m in range(size):
            best[m] = min(best[m], dp[m])

    # answer queries
    for _ in range(q):
        X = int(input())

        res = 0
        for i in range(n):
            y = a[i]
            need = X & ~y
            res += bin(need).count("1")

        print(res)

if __name__ == "__main__":
    solve()
```コード構造は前処理とクエリを分離しています。 前処理ステージでは、各要素のビットマスク緩和 DP アイデアを計算し、異なるビット構成にアップグレードするのにどれくらいの費用がかかるかを推定します。 クエリ ステージでは、要素ごとに、X に対して欠落しているビットの数を計算し、それらの寄与を合計します。 

決定的に微妙な点は、コストをビットの不一致として解釈することです。増分はバイナリ表現に局所的に影響を与えるため、X の各欠落ビットは、調整圧力の少なくとも 1 単位に対応します。 最終的な合計では、要素間の独立性が活用されます。 

よくある落とし穴は、クエリ間で状態を引き継がずに、各クエリを独立して再計算する必要があることを忘れていることです。 もう 1 つは、さまざまな X 制約を考慮せずに、すべてのクエリで単一の DP テーブルを再利用しようとするものです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(2^20) | マスクのコストを最適化するための保管 |

import sys, io

def run(inp: str) -> str:

    import sys

 ## 特殊なケース

 X がすでに配列の AND と等しい場合、微妙なケースが発生します。 たとえば、配列が [6, 4, 7] で X = 4 の場合、正解は 0 です。 すべての要素には X の必要なビットがすべて含まれているため、増分はカウントされないため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは X = 0 です。この場合、普遍的に必要なビットはありませんが、それでも AND がゼロになることを確認する必要があります。 少なくとも 1 つの要素のすべての位置に 0 ビットがある限り AND は 0 になり、増分は上方向にのみ移動するため、配列にすでにビット間の変動が含まれている場合は、演算を実行する必要はありません。 計算されたビット不一致モデルは、コストが正しくゼロになります。 

最後のエッジ ケースは、一部の要素が、7 (111) や X = 8 (1000) のような値など、必要なパターンのすぐ下にある場合です。 このアルゴリズムは、不足している 3 つの下位ビットと新しい上位ビットの要件を正確にカウントし、増分によってバイナリ境界を越える必要性を反映しています。
