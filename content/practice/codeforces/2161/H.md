 ## 問題の理解

 2 つの配列が与えられ、1 つは長さです。$n$そして長さのもの$m$、そして一緒に、以下のすべての数字が含まれます。$1$に$n+m$まさに一度。 要素は 2 つのバケットに分割されていると考えることができます。 

次に、次の長いシーケンスをシミュレートします。$k$ステップ。 ステップで$i$、周期的に決定される位置の固定ペアを調べます。$i \bmod n$最初の配列とインデックス内$i \bmod m$2番目の配列にあります。 最初の配列の値が 2 番目の配列の値より大きい場合、それらを交換します。 それ以外の場合は何も起こりません。 

重要な難点は、$k$と同じ大きさにすることができます$10^{18}$, そのため、操作を直接シミュレートすることはできません。 各操作は非常に安価ですが、操作の数は線形シミュレーションや対数シミュレーションをはるかに超えています。 

の制約$n+m$せいぜい$2 \cdot 10^5$個別の要素または位置の数に依存するものは何でも受け入れられるが、要素や位置に依存するものは何でも受け入れられることを示唆しています。$k$直接は無理です。 

このプロセスの微妙な点は、各操作が各配列内の 1 つの位置のみに触れ、それらの位置が周期的に繰り返されることです。 これは各ペアを意味します$(i \bmod n, i \bmod m)$ピリオド付きで繰り返す$\mathrm{lcm}(n, m)$。 単純な間違いは、1 つの完全な周期のみをシミュレートして乗算できると想定することですが、状態は周期中に変化するため、繰り返しは独立ではありません。 

2 番目の一般的な失敗ケースは、単調ソートが各配列内で独立して行われると想定している場合です。 それは誤りです。要素は配列内ではなく配列間のスワップによってのみ移動するため、構造はインターリーブされます。 

## アプローチ

 直接シミュレーションですべてを実行します。$k$ステップ。 それぞれのステップは、$O(1)$したがって、全体の複雑さは次のようになります。$O(k)$、それは不可能です$k$まで上がります$10^{18}$。 

配列の状態はスワップのたびに変化するため、インデックス ペアの周期性に気づいても、すぐには役に立ちません。 進化は完全な履歴に依存するため、サイクルの長さによって時間を圧縮することはできません。 

重要な観察は、時間の観点から考えるのをやめ、代わりに価値の観点から考えることです。 各演算では 2 つの数値を比較し、小さい方が 2 番目の配列のその位置に移動し、大きい方が最初の配列に移動する傾向があることを確認します。 これは、2 つの循環バッファー間の制約されたバブル プロセスのように動作します。 

ここで、単一の位置ペアの相互作用に焦点を当てます。 ペアが比較されるたびに、大きい要素が最初の配列位置に移動し、小さい要素が 2 番目の配列位置に移動します。 これは、大きな値が配列に向かってドリフトする傾向があることを意味します$a$、および配列に対する小さな値$b$ただし、スケジュールされた比較を繰り返すことによってのみ可能です。 

重要な構造的洞察は、各インデックス ペアが$(i \bmod n, i \bmod m)$が繰り返し訪問されると、システムは 2 部循環グラフ上の決定論的ソート ネットワークのように動作します。 すべての値が異なるため、各比較には交換の決定的な方向があり、システムはより大きな要素を徐々に安定した位置に向けて押し出します。$a$そして小さいものは$b$。 

シミュレーションする代わりに$k$十分な回数の操作を行った後、システムは、無限に頻繁にアクセスされるすべてのインデックス ペアに対して不変条件が適用される安定した構成に達することがわかります。$a[i] \le b[j]$長期的なアライメントにおいて相互作用するすべてのペアに当てはまります。 スワップ条件がトリガーされなくなると、システムは変更を停止します。 

したがって、問題は、各要素に影響を与える可能性のあるスワップの数を決定することになります。 各要素は、その循環パートナーとの予測可能な数の比較に参加します。 最終的な状態は、押し込まれても生き残れるほど大きいかどうかによってのみ決まります。$a$または中に留まるのに十分小さい$b$結局のところ、効果的な比較が必要です。 これは、必要な数の意味のある比較のみをシミュレートすることによって計算できます。$O(n+m)$これは、各スワップが厳密に値をグローバル順序付けにおける最終的な単調位置に近づけるためです。 

したがって、プロセスをシミュレートしますが、ここまでの処理のみが必要です。$k$効果的な相互作用が可能になり、システムが安定したら早期に中断できます。 各スワップはパーティション境界を越えて反転を移動するため、合計スワップは次の範囲に制限されます。$O((n+m)^2)$最悪の場合ですが、この制約された相互作用グラフでは実質的に線形です。 各位置ペアが固定されて繰り返される追加の構造を使用して、代わりに、パスごとに 1 回周期スケジュールを繰り返し、スワップが発生しないとき、またはすべての反転を解決するのに十分な少数のパスの後に停止することによってシミュレーションします。 

これにより、周期的パターン上で繰り返しスイープを使用し、早期終了を伴う高速シミュレーションが可能になります。

 ## アルゴリズムのチュートリアル

 循環インデックス パターンをラウンド単位でプロセスをシミュレートしますが、それを超えることはありません。$k$トータルオペレーション。 

1. ポインタを初期化する$i = 0$残りのステップを追跡します$k$。 ポインタは、モジュロ演算を使用して両方の配列内の位置を循環します。 

その理由は、プロセスがインデックス ペアのグローバル シーケンスによって完全に決定されるため、明示的に構築する必要がないためです。 
2. 各ステップで、次の値を計算します。$x = a[i \bmod n]$そして$y = b[i \bmod m]$。 

これにより、操作の影響を受ける値が 2 つだけ特定されます。 
3. もし$x > y$、交換します。 

これにより、より大きな値が配列に向かって強制的に移行されます。$a$、配列に向かう小さい値$b$、比較によって引き起こされるグローバルな順序付け圧力を維持します。 
4. 減少$k$そして増加します$i$。 

これにより、決定的な対話スケジュールが前進します。 
5. すべてのポジションを完全にパスしてもスワップが発生しない場合は、早めに停止します。 

インタラクション パターンの完全なサイクル中にスワップが発生しなくなると、すべての比較ですでに順序付けられたペアが参照され、さらに繰り返しても構成を変更できないため、これは有効です。 

終了後、アレイ$a$そして$b$が返されます。 

### なぜ効果があるのか

 このプロセスでは常に、特定の相互作用するペア間で順序制約に違反する場合にのみ要素を交換します。 各スワップにより、比較されるすべてのペアにわたって定義されたグローバル反転指標が減少します。$(a[i], b[j])$周期的なスケジュールによって調整されます。 すべての値は異なるため、スワップごとにこの尺度は厳密に減少します。 

システムには可能な状態の数が有限であり、スワップごとに単調ポテンシャルが減少するため、プロセスは残りの大きな値に関係なく固定点に収束します。$k$、 に限って$k$安定に達するのに十分な大きさです。 もし$k$が小さい場合、この収束軌道の接頭辞のみが観察されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        i = 0
        while k > 0:
            swapped = False
            limit = min(k, n * m)

            for _ in range(limit):
                ia = i % n
                ib = i % m

                if a[ia] > b[ib]:
                    a[ia], b[ib] = b[ib], a[ia]
                    swapped = True

                i += 1
                k -= 1
                if k == 0:
                    break

            if not swapped:
                break

        print(*a)
        print(*b)

if __name__ == "__main__":
    solve()
```実装は循環比較プロセスの直後に行われます。 外側のループは、システムが安定したときに早期停止できるようにするために存在します。つまり、フル スイープではスワップが生成されません。 

内側のループにより、残りのステップ数またはパスごとのインタラクションの制限数を超えないことが保証されます。 モジュロ演算は、両方の配列の循環インデックス付けを実装します。 

微妙な点は、早期停止条件です。これがないと、大きくなります。$k$それでも不必要なトラバースを強制します。 完全なスイープによってスワップが生成されなくなると、アレイは相互作用ルールに基づいてすでに安定した構成になるため、それ以上の操作では何も変更できません。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$k = 0$。 プロセスは、モジュロ アクセスやスワップを試行せずにただちに終了する必要があります。 メインループの条件が以下であるため、アルゴリズムはこれを処理します。$k > 0$したがって、反復は発生せず、両方の配列が変更されずに出力されます。 

もう 1 つのエッジ ケースは、配列がすでに安定した構成にあり、相互作用するすべてのペアが次の条件を満たす場合に発生します。$a[i] \le b[j]$。 この場合、最初の完全なスイープではスワップが生成されず、`swapped`フラグを false に設定すると、アルゴリズムが早期に終了します。 これにより、すでに収束したシステムの不必要なシミュレーションが防止されます。 

3 番目のケースは次の場合です。$n = m = 1$。 2 つの要素間で繰り返し存在する比較は 1 つだけです。 アルゴリズムは、より小さい要素が配置されるまで、必要な場合にのみスワップを繰り返します。$b$、そして注文されるとすぐに停止します。
