 ## 解決策
 ## 問題の理解

 配列が与えられ、そこから要素を削除できます。 削除後、残りのシーケンスは非常に具体的な制限を満たす必要があります。つまり、後の要素が前の要素よりちょうど 1 つ大きい 2 つの要素を含めてはなりません。 

言い換えれば、残りの配列で i < j の任意の 2 つの位置を選択すると、値がサイズ 1 の増加する連続ステップを形成するペアを持つことは禁止されます。 i < j は元の左から右の順序であるため、要素の順序は依然として重要です。したがって、これは単にマルチセット プロパティに関するものではなく、サブシーケンス内でどのような値が共存できるかについても重要です。 

タスクは、この禁止されたパターンが完全に消えるように、できるだけ少ない要素を削除することです。 

制約は大きく、すべてのテスト ケースにわたる合計要素数は最大 3 × 10^5 です。 これにより、インデックスまたは値のペアに対する二次戦略は即座に除外されます。 すべてのペアを比較したり、削除を明示的にシミュレートしようとするソリューションは失敗するため、テストごとにほぼ線形または線形対数時間で値を処理する構造が必要です。 

貪欲に考えると、微妙な問題が現れます。競合は相対的な順序付けと、残りのシーケンス内のどこかに値 x と x+1 が存在するかどうかに依存するため、不良ペアに含まれる値を削除しても、その値のすべてのコピーを削除するとは限りません。 元の順序で「+1 の隣に出現する値をすべて削除する」などの素朴な貪欲な方法は失敗します。これは、禁止条件がローカルの隣接関係ではなく、サブシーケンス全体にわたってグローバルであるためです。 

たとえば、次のように考えてみましょう`1 3 2`。 2 - 1 = 1 であるため、1 と 2 の間に矛盾がありますが、配列内でこれらは隣接していません。 元の配列内の近傍をチェックするだけのアプローチでは、これを完全に見逃してしまいます。 

本当の難しさは、値の出現がちょうど 1 の値の違いによってのみ相互作用するのに、位置間のすべてのペアが重要であることです。 

## アプローチ

 この問題を考える強引な方法は、インデックスのすべてのサブセットを試し、選択したサブセットが有効かどうかを確認することです。 各サブセットについて、いずれかのペア (i, j) が条件に違反するかどうかを検証します。 これにより、すでに 2^n 個のサブセットが得られますが、これは n = 30 の場合でも不可能です。 

もう少し構造化されたブルートフォースは、どの要素を保持するかを修正し、保持された各要素について、その後に保持されたすべての要素をチェックして、1 つだけ異なるペアがないことを確認することです。 チェックが最適化されたとしても、依然として多くのペアを検査する必要があるため、最悪の場合、これはテストごとに O(n^2) になります。 

重要な観察は、制約が複雑な方法では位置ではなく値のみに依存するということです。残りのセットに両方が正しい順序で出現する場合、任意の値 x は任意の x+1 と競合します。 順序は保持されるため、実際の問題は、残りのサブシーケンスで x+1 の前に少なくとも 1 つの x が存在する場合、値 x と x+1 の両方を保持できないということです。 ただし、削除を自由に選択できるため、両方の値が存在する場合、構造化された方法で 1 つの値クラス全体を削除することによってのみ、問題のある順序付けをすべて「解除」できるようにいつでも調整できます。 

これは、より単純な観点につながります。つまり、少なくとも 1 つの有効なクロスペアを順番に作成する方法で、2 つの連続する整数が両方とも「アクティブ」にならないように、値のサブセットを効果的に選択しているということです。 いつでも順序を変更せずにサブシーケンスを選択できるため、最適な戦略は、連続する整数間の競合を回避する方法で値を選択することになります。 

これをエンコードする標準的な方法は、配列を値ごとの頻度に圧縮してから、値に対する DP を計算することです。値 x ごとに、それを取得するかスキップするかを決定します。 x を取得する場合、有効な残りの構造を作成する方法で x-1 を取得することはできないため、隣接する値を同時に取得しないようにします。 

これは、値 1 から n にわたる古典的な「パス上の独立した最大重みセット」になります。ここで、重みは各値の頻度です。 答えは、要素の合計から、x と x+1 の両方を決して選択しないという制約の下で維持できる頻度の最大合計を引いたものです。 

したがって、DP を計算します。 

dp[x] = max(dp[x-1], dp[x-2] + freq[x])

 これにより、保持できる要素の最大数が決まります。 最小除去数は n - dp[max_value] です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · n) | O(n) | 遅すぎる |
 | 値ライン上の DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の各値の頻度をカウントします。 

これにより、問題は位置的推論から値ベースの推論に変換されます。なぜなら、競合にとって重要なのは値の存在だけだからです。 
2. dp[x] を、x までの値を使用し続けることができる要素の最大数を表すものとします。 

x の選択は x-1 と x-2 にのみ依存するため、これを段階的に構築します。 
3. 1 から n までの各値 x について、x をスキップするか x を取得するという 2 つのケースのうち最良の方法として dp[x] を計算します。 

x をスキップすると dp[x-1] を意味します。 x を取得すると、freq[x] が得られることになりますが、隣接関係の競合を避けるために、それを dp[x-2] と組み合わせる必要があります。 
4. 再発は次のとおりです。 

dp[x] = max(dp[x-1], dp[x-2] + freq[x])

 これは、x を選択すると x-1 の選択が禁止されるという事実をエンコードします。 
5. 答えは、合計 n から dp[max_value] を引いたものです。 

### なぜ効果があるのか

重要な不変条件は、値 x を処理した後、連続する 2 つの値が両方選択されないという制約の下で、1 から x までの値のみを使用し続けることができる要素の最大数を dp[x] に格納することです。 少なくとも 1 つの有効な順序ペアを保持する方法で x と x+1 の両方が選択された場合、その構成は許可されないため、保持された要素の有効なサブセットはこの制約を満たす値の選択にマップできます。 したがって、最適なソリューションでは、連続する値のペアごとに少なくとも 1 つのエンドポイントを削除する必要があり、DP は、二重にカウントしたり構成が欠落したりすることなく、そのような一貫した選択肢をすべて列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * (n + 2)
        for x in a:
            freq[x] += 1
        
        if n == 1:
            print(0)
            continue
        
        dp_prev2 = 0
        dp_prev1 = freq[1]
        
        for x in range(2, n + 1):
            dp_cur = max(dp_prev1, dp_prev2 + freq[x])
            dp_prev2, dp_prev1 = dp_prev1, dp_cur
        
        best_keep = dp_prev1
        print(n - best_keep)

if __name__ == "__main__":
    solve()
```各遷移は x-1 と x-2 にのみ依存するため、実装では最後の 2 つの状態のみを保持することで DP を O(1) メモリに圧縮します。 頻度のカウントはテスト ケースごとに 1 回行われます。 最後の減算では、保持された最大のサブセットが最小の削除に変換されます。 

よくある落とし穴は、配列内に現れる最大値までしか値を処理しなければならないと想定していることです。 これは論理的には正しいですが、未使用の周波数はゼロであり、DP は一貫しているため、n まで反復しても安全です。 

## 実用的な例

 ### 例 1

 入力:`5 1 2 3 4 5`ここでは、すべての値が一度だけ存在します。 

| × | 周波数[x] | dp[x-2] | dp[x-1] | dp[x] |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | - | 0 | 1 |
 | 2 | 1 | 0 | 1 | 1 |
 | 3 | 1 | 1 | 1 | 2 |
 | 4 | 1 | 1 | 2 | 2 |
 | 5 | 1 | 2 | 2 | 3 |

 合計 3 つの要素を保持するため、削除 = 5 - 3 = 2 となります。これは、連続した値を取得できないという考えと一致するため、値ラインの奇数または偶数のインデックスを効果的に選択します。 

### 例 2

 入力:`5 5 5 5 4 4`周波数は freq[4]=2、freq[5]=3 です。 

| × | 周波数[x] | dp[x-2] | dp[x-1] | dp[x] |
 | --- | --- | --- | --- | --- |
 | 4 | 2 | 0 | 0 | 2 |
 | 5 | 3 | 0 | 2 | 3 |

 3 つの 5 をすべて維持することも、2 つの 4 をすべて維持することもできますが、完全な相互作用という意味では両方を維持することはできないため、最善は 3 を維持することです。 除去 = 5 - 3 = 2。 

これらのトレースは、アルゴリズムが位置を追跡しているのではなく、値の競合を純粋に最適化しているだけで十分であることを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 値 x+1 が存在しないため、制約はトリガーされず、アルゴリズムはすべてを保持する dp を正しく生成します。 たとえば、入力`3 3 3 3 3`freq[3]=5 が生成され、隣接する相互作用はないため、 dp は単に 5 をすべて保持します。 

もう 1 つのエッジ ケースは、次のような密集した連続ブロックです。`1 2 3 4 5`。 ここでは、すべての値が隣接する値と構造的に競合するため、DP は値間で選択を交互に行います。 このアルゴリズムは、再帰の構築によって隣接する値の選択を正しく回避し、パス全体で最大の独立したセットを生成します。 

3 番目のケースは、次のようなスパース値です。`1 100 2 99`。 数値的には値が大きく離れていても、問題となるのは連続する整数のみであるため、DP は各値を独立して分離します。 これは、解が大きさや配列の順序ではなく、値の隣接性に依存していることを示しています。これはまさに再帰が捉えるものです。
