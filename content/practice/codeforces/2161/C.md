 ## 問題の理解

 購入するたびにロイヤルティ レベルが向上する可能性があるストアでは、ボーナス ポイントを最大化することが求められます。 各アイテムの価格は 1 からロイヤルティ係数までの間です$X$。 当初、ロイヤルティ レベルは総支出の整数除算として計算されます。$S$による$X$。 アイテムを購入してロイヤルティ レベルが上がるたびに、そのアイテムの価格に等しいボーナス ポイントを獲得します。 同じアイテムを異なる順序で購入しても、ロイヤルティ レベルの増加数が異なる可能性があるため、購入順序は重要です。 

入力は複数のテスト ケースで構成され、各テスト ケースは品目の数、ロイヤリティ係数、および品目の価格のリストを提供します。 出力は、達成可能な最大合計ボーナス ポイントと、この最大値を達成するアイテムの注文例です。 テスト ケースごとの項目数は次のとおりです。$10^5$、すべてのテスト ケースの合計も最大です。$10^5$, したがって、効率的なアプローチが必要です。 

単純な解決策では、すべてを試すことになります$n!$アイテムの順列を調べて、ボーナス ポイントを最大化する順序を見つけます。 たとえ$n = 10$、これはすでに非現実的であるため、より賢明なアプローチが必要です。 エッジケースには、すべての項目が次と等しいことが含まれます。$X$、すべての購入、またはすべてのアイテムが以下のサイズの場合にボーナス ポイントを保証します。$X$そのため、単一のアイテムがロイヤルティの増加をすぐに引き起こすことはできません。 

もう 1 つの微妙なケースは、小さなアイテムの合計がちょうど次の倍数に達する場合です。$X$- ここでは、ロイヤルティ レベルの増加をできるだけ多く引き起こすために、アルゴリズムは最初に購入するアイテムを慎重に選択する必要があります。 

## アプローチ

 ブルートフォースアプローチは、アイテムのすべての順列を生成し、各シーケンスのボーナス計算をシミュレートすることです。 これは、考えられるすべての順序を明示的にチェックするため、原理的には正しく機能しますが、時間の計算量は次のとおりです。$O(n!)$、これは完全に不可能です$n \sim 10^5$。 要素が 10 個の小さな配列であっても、すでに 300 万を超える順列が発生します。 

最適化の重要な観察点は、次の倍数に達することだけを考慮しているということです。$X$効率的に。 ボーナスポイントは、累積合計が次の倍数を超えると発生します。$X$。 これは、貪欲なアプローチを示唆しています。つまり、複数の金額に到達する前に、できるだけ支出を抑えたいと考えています。$X$次のアイテムがロイヤルティの増加を引き起こすようにします。 項目を昇順に並べ替えると、小さい項目が最初に蓄積され、オーバーシュートすることなく累積合計が次の倍数に近づくようになります。 その後、より大きなアイテムを使用して忠誠度の増加を引き起こすことができます。 

言い換えれば、項目を降順ではない順序で並べ替えることで、各項目は単独でロイヤルティの増加を引き起こすには小さすぎるか、合計が次の倍数を超える最小の項目であるかのいずれかになります。$X$。 この順序によりロイヤルティ レベルの増加数が最大化され、まさにボーナス ポイントを獲得できるようになります。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、項目の数を読み取ります。$n$そしてロイヤルティ要素$X$。 
2. 商品価格表を読む$a_1, a_2, ..., a_n$。 
3. 商品価格を昇順に並べ替えます。 これにより、複数の項目に到達するために、最初に小さい項目を使用することが保証されます。$X$効率的に。 
4. 累積和の初期化$S = 0$そしてボーナスポイント$B = 0$。 
5. 並べ替えられた項目を繰り返し処理します。 

- 現在の商品価格を追加します$S$。 
- 以前の忠誠度レベルを次のように計算します。$(S - a_i) // X$。 
- 新しいロイヤルティ レベルを次のように計算します。$S // X$。 
- 新しいロイヤルティ レベルが以前のロイヤルティ レベルを超えている場合、現在のアイテム価格を追加します。$B$。 
6. すべての項目を処理した後、出力します$B$そしてソートされたシーケンス。 

機能する理由: 並べ替えにより、より小さな貢献が最初に蓄積されるため、複数の要素を交差するたびに、$X$、それを横断する責任のあるアイテムは、残りのアイテムの中でできるだけ大きいものです。 これにより、各忠誠度レベルの上昇から得られるボーナス ポイントが最大化されます。 不変条件は、すべてのステップで、$S$これまでに購入したすべてのアイテムの合計であり、次の倍数を超えます。$X$現在のアイテムからのボーナスを正確にトリガーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, X = map(int, input().split())
        prices = list(map(int, input().split()))
        prices.sort()
        bonus = 0
        S = 0
        for price in prices:
            prev_loyalty = S // X
            S += price
            new_loyalty = S // X
            if new_loyalty > prev_loyalty:
                bonus += price
        print(bonus)
        print(' '.join(map(str, prices)))

if __name__ == "__main__":
    solve()
```このコードは、高速 I/O を使用して複数のテスト ケースを効率的に読み取ります。 ボーナス ポイントを最大化するには並べ替えが不可欠であり、累積合計ロジックによりロイヤルティ レベルの上昇を正確に検出できます。 1 つ違いのエラーを避けるために、アイテムごとに以前と新しいロイヤルティ レベルを個別に計算するように注意が払われます。
