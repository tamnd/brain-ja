 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 目標は、すべての要素を少なくともしきい値に達するまで上げることです。`k`。 配列を変更する唯一の方法は、選択したインデックスに非常に特殊な操作を適用することです。`i`。 

インデックスを選ぶとき`i`、その要素は次のように増加します`m`、他のすべての要素は ずつ減少します`r`。 たとえ 1 つのポジションを「ターゲット」としても、他のすべてのポジションが悪影響を受けるという意味で、この作戦はグローバルです。 この操作を任意のインデックスに任意の順序で繰り返し適用できますが、すべての配列値が少なくとも最終的に次の値になるように、必要な合計操作数を最小限に抑えたいと考えています。`k`。 

重要な問題は、各操作が 1 つのポジションを助けるものの、他のすべてのポジションに害を及ぼすことです。 これにより、意思決定の間にカップリングが生じます。1 つの要素を改善すると一時的に他の要素が悪化する可能性があり、将来的には別の場所でさらなる操作が必要になる可能性があります。 

この制約は、演算に対する 2 次またはそれ以下のシミュレーションが不可能であることを示唆しています。 テスト ケース全体のすべての配列の合計サイズは小さいですが、値は大きくなる可能性があり、操作の数は原則として無制限です。 操作をステップバイステップでシミュレートしたり、シーケンスを検索しようとするソリューションはどれも遅すぎます。 

いくつかの要素がすでにそれに近い場合、微妙な問題が発生します。`k`しかし下に押し込まれる`k`他のインデックスを対象とした操作による。 全体的な副作用を考慮せずに、単に最小の要素を繰り返し修正する単純な貪欲なアプローチは失敗する可能性があります。 

たとえば、1 つの要素がぎりぎり上にある場合、`k`, しかし、多くの操作が別の場所で実行されると、しきい値を下回って、よりバランスのとれた戦略であれば回避できたはずの追加の操作が強制される可能性があります。 

## アプローチ

 ブルートフォースの観点では、プロセスを直接シミュレートします。 各ステップで、すべてのインデックスに演算を適用して結果の配列を計算し、すべての要素が次の値に達するまで再帰的または反復的に続行します。`k`。 これは、有効な操作シーケンスをすべて調査するため、正しいですが、分岐要素は次のとおりです。`n`各ステップでの深さも大きくなる可能性があるため、状態の数は指数関数的に増加します。 

重要な観察は、実際にはシーケンス内の操作の ID は気にしておらず、各インデックスが何回選択されるかだけを気にしているということです。 させて`x_i`インデックスに操作を適用する回数になります。`i`。 その後、各要素の最終値を純粋にこれらのカウントの観点から表現できます。 

操作を適用するたびに`i`、 要素`i`利益を得る`m`そして他のすべての要素は失われます`r`。 したがって、固定インデックスの場合`i`、その最終値は次のとおりです。```
a[i] + x_i * m - r * sum_{j != i} x_j
```させて`S = sum x_j`。 次に、次のように書き換えます。```
final[i] = a[i] + x_i * m - r * (S - x_i)
         = a[i] + x_i * (m + r) - r * S
```現在、システム全体は次によって制御されています。`S`そしてそれぞれ`x_i`。 条件`final[i] >= k`は次のようになります:```
a[i] + x_i * (m + r) >= k + r * S
```並べ替え:```
x_i >= (k + r*S - a[i]) / (m + r)
```これは循環依存関係を示しています。`x_i`に依存します`S`、 しかし`S`すべての合計です`x_i`。 

重要な構造の簡素化は、固定された`S`、 それぞれ`x_i`は不等式を満たす最小値として独立に決定される。 これにより、必要な合計を計算できます`S' = sum x_i`候補者によって暗示された`S`。 もし`S' > S`、オペレーションの割り当てが不足しています。 もし`S' <= S`、構成は実行可能です。 

次に最小のものを探します`S`これにより、この一貫性状態が安定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(n) | 遅すぎる |
 | S | 上の固定小数点 O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、一貫した操作の総数を求めることに変換します。`S`。 

1. 最初の推測から始めます`S`、 通常`0`。 これは、世界的な減少による相互影響がまだないと仮定していることを表しています。 
2. インデックスごとに`i`、少なくとも到達するために何回選択する必要があるかを計算します。`k`現在の仮定を考慮すると、`S`。 要件は以下を解決することで得られます。```
a[i] + x_i*(m+r) >= k + r*S
```それで：```
x_i = max(0, ceil((k + r*S - a[i]) / (m + r)))
```負の演算を必要としないため、max をゼロとします。 
3. すべての合計を計算します`x_i`新しい合計を取得するための値`S_new`。 
4. もし`S_new`等しい`S`、安定した構成に達しました。`S`実現可能です。 
5. それ以外の場合は交換してください`S`と`S_new`そしてプロセスを繰り返します。 

反復の背後にある重要な理由は、`S`必要な閾値を上げる`k + r*S`、その結果、個々の要件が増加する可能性があります。 ただし、一度、`S`が十分大きいため、再計算しても変更されなくなります。 

### なぜ効果があるのか

 システムは、単調な自己一貫性条件を定義します。`S`それぞれの右側の要件を増やすことしかできません。`x_i`、決して減らさないでください。 したがって、からのマッピングは`S`に`S_new`単調非減少です。 から始まる`0`、繰り返し適用すると、実行可能な演算の割り当てに正確に対応する最小の固定点に収束します。 より小さい値`S`少なくとも 1 つの制約に違反することになりますが、それより大きな値は不必要な追加の操作を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k, m, r = map(int, input().split())
        a = list(map(int, input().split()))

        denom = m + r

        S = 0
        while True:
            newS = 0
            for x in a:
                need = k + r * S - x
                if need > 0:
                    newS += (need + denom - 1) // denom
            if newS == S:
                break
            S = newS

        print(S)

if __name__ == "__main__":
    solve()
```実装の中核は、固定小数点の反復です。`S`。 分母`m + r`すべての要素で再利用されるため、事前計算されます。 

表現`need = k + r*S - x`現在のグローバル ペナルティの仮定の下で、要素が必要なしきい値からどの程度離れているかをエンコードします。 もし`need`が正の場合、赤字と進行中のグローバルペナルティの両方を補うために必要な完全な操作の回数を計算します。 

各反復が安定するか厳密に増加するため、ループは収束します。`S`、そして値は、最小の要素を最悪の状態から引き上げるのに必要な操作の数によって制限されます。

これは、グローバルなペナルティによって、単純な独立要件を超えた追加の操作がどのように強制されるかを示しています。 

次に、次のことを考えてみましょう。

a = [0, 0, 0]

 ## 特殊なケース

 重要なエッジ ケースは、すべての要素がすでにしきい値を満たしている場合です。 そのような状況では、`k - a[i] <= 0`みんなのために`i`、したがって、計算された`need`は常に非正です`S = 0`。 アルゴリズムは即座に生成します`newS = 0`, したがって、成長のループに入らずに収束します。 

もう 1 つの重要なケースは、1 つの要素が残りの要素よりも大幅に小さい場合です。 たとえば、次の場合`a = [1, 100, 100]`適度に`k`、最初の要素が計算を支配します。`S`。 初期の反復では、大きな要素はまだ操作を必要としませんが、`S`増加すると、全体的なペナルティを「感じ」始め、追加の操作が必要になる場合があります。 固定小数点の反復により、安定化するまでこの依存関係が正しく伝播されます。 

3 番目のケースは次の場合です。`m`よりわずかに大きいだけです`r*(n-1)`。 これは最悪の状況です。なぜなら、各作戦はその世界的な被害に比べてわずかな純利益しか得られないからです。 分母が次のとおりであるため、アルゴリズムは依然として収束します。`m + r`各操作が厳密にプラスの自己利益をもたらすことを保証し、発振や発散を防ぎます。
