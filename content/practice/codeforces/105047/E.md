 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、単一の破壊的な操作を繰り返し適用することができます。つまり、2 つの異なる位置を選択し、最初の位置をその現在の値と 2 番目の位置の値の XOR で置き換えます。 2 番目の位置は決して変更されません。 

タスクは、このような演算シーケンスを使用して配列を非減少シーケンスに変換し、有効な演算シーケンスを出力することです。 元の値を保持することは要求されず、ソート順を適切に維持することだけが要求されます。 

重要な制限は、スワップや割り当てがなく、XOR を介してある位置から別の位置に情報を注入できることだけであることです。 これにより、問題は非常に珍しいプリミティブの下でソートされているように感じられます。 

配列の長さは最大 1000 で、値は最大 20 ビットの整数です。 演算の制限は十分に大きいため、二次または二次に近い動作も許容されますが、スコアリング システムは、特に 2500 演算未満の短いシーケンスに報酬を与えます。 

素朴な解釈では、比較と交換を直接シミュレートしようとしますが、多くの操作を行わずに制御された方法で直接比較したり、条件付きで並べ替えたりすることはできないため、すぐに失敗します。 さらに微妙な問題は、すべての操作でターゲット位置の情報が破壊されるため、不注意なシーケンスによって値が簡単に破壊され、元に戻せないことです。 

2 番目の隠れたエッジ ケースは、XOR が算術代入のように動作すると仮定することです。 たとえば、中間値を慎重に復元せずに値を「移動」しようとすると、サイレント破損が発生します。 

入力:```
3
5 1 2
```単純な「スワップのような」シーケンスを実行しようとして復元手順を忘れると、1 つの位置が永久に変更されてしまい、インデックスが正しい場合でも並べ替えが失敗します。 

## アプローチ

 この強引なアイデアは、並べ替えを直接シミュレートすることです。 値によってインデックスのソート順序を計算し、位置間の交換を使用して各要素を正しい位置に配置しようとします。 スワップがないため、ポジション間のスワップをシミュレートします。`i`そして`j`XOR を使用する:

 次の 3 つの操作を使用して 2 つの値を交換できます。 

まず、作ります`i := i XOR j`、 それから`j := j XOR i`、 それから`i := i XOR j`。 これらの手順を実行すると、次の値が得られます。`i`そして`j`交換されます。 

これにより、問題は任意のスワップによるソートに縮小されます。つまり、インデックスの順列をサイクルに分解し、各サイクルを個別に修正できることになります。 各サイクルの長さ`k`必要`k - 1`交換します。 

このアプローチは正しいです。スワップによって任意の順列を実現でき、並べ替えは値を並べ替える順列を適用するだけだからです。 

ブルートフォースの考え方の失敗点は、構造なしでスワップを個別に実装すると依然としてコストが高すぎることと、単純にスワップやバブル ソートを繰り返すと非常に多くの操作が発生することです。 

サイクル分解の観察により、スワップの数が最大で 2 回まで削減されます。`n - number_of_cycles`、最大でも`n - 1`、スワップが直線的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 隣接スワッピングの繰り返し | O(n² スワップ) → O(3n² オペレーション) | お(1) | 遅すぎる |
 | サイクル分解 + XOR スワップ | O(n log n) ソート + O(n) スワップ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、XOR スワップ演算を使用して位置に沿って値を運ぶ際のインデックスのソートとして扱います。 

1. 値に基づいてインデックスのソート順序を昇順で計算します。 
2. アレイを構築する`pos`どこ`pos[i]`要素が現在位置している場所を示します`i`ソートされた配置に入る必要があります。 これはインデックス上の順列を定義します。 
3. この順列を素のサイクルに分解します。 各サイクルは、要素間で回転する必要がある要素の閉じたチェーンを表します。 
4. 長さのサイクルごとに`k`、ピボットとして 1 つの要素を選択します。 次に、XOR スワップを使用して、ピボットをサイクル内の他の要素と繰り返し交換します。 各スワップは、次の 3 つの許可された操作を使用して実装されます。 

まず`x := x XOR y`、 それから`y := y XOR x`、 それから`x := x XOR y`。 

これにより、すでに固定されたサイクルに影響を与えることなく、各要素が徐々に正しい位置に移動します。 
5. すべての基本 XOR 演算を出力として記録します。 

これが機能する理由は、各サイクルが独立して解決され、サイクルを修正した後、そのサイクル内のすべての要素が正しく配置され、二度と触れられないためです。 

### なぜ効果があるのか

 各スワップは値の正確な交換であるため、ポジション全体で値のマルチセットが保持されます。 サイクル分解により、サイクルのエッジに沿ってスワップを適用すると、最終的にすべてのインデックスがソートされた宛先にマッピングされることが保証されます。 すべてのサイクルは互いに素であるため、すでに固定されている要素に干渉する操作はありません。 不変条件は、サイクルの終了後、そのサイクル内のすべての位置に、ターゲット順列で割り当てられた値が正確に含まれることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def xor_swap_ops(a, b, ops):
    # performs swap between positions a and b using XOR operations
    # a != b
    ops.append((a, b))
    ops.append((b, a))
    ops.append((a, b))

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))

    # sorted order of indices
    order = sorted(range(n), key=lambda i: arr[i])

    # permutation: i -> where i goes in sorted array
    pos = [0] * n
    for new_idx, old_idx in enumerate(order):
        pos[old_idx] = new_idx

    vis = [False] * n
    ops = []

    for i in range(n):
        if vis[i] or pos[i] == i:
            vis[i] = True
            continue

        cycle = []
        cur = i
        while not vis[cur]:
            vis[cur] = True
            cycle.append(cur)
            cur = pos[cur]

        # fix cycle
        for j in range(1, len(cycle)):
            a = cycle[0]
            b = cycle[j]

            # XOR swap a and b via 3 operations
            ops.append((a + 1, b + 1))
            ops.append((a + 1, b + 1))
            ops.append((a + 1, b + 1))

    print(len(ops))
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```実装ではまず、ソートされた順序で各要素のターゲット位置を計算します。 次に、順列をサイクルに分解して、各要素が最終的にどこに到達するかを正確に認識できるようにします。 

サイクルごとに、サイクル代表とサイクル内の他のすべての要素との間でスワップを繰り返し適用します。 それが唯一許可されるプリミティブであるため、各スワップは 3 つの XOR 演算に拡張されます。 

微妙な点は、インデックス付けは慎重に処理する必要があることです。出力は 1 から始まりますが、内部配列は 0 から始まります。 もう 1 つの微妙な問題は、二重処理を避けるために、サイクルに入ったときにすぐに訪問したノードにマークを付けることです。 

## 実用的な例

 ### 例 1

 入力:```
4
3 2 1 0
```ソート順はインデックスです`[3, 2, 1, 0]`。 

順列サイクル:`(0 3)(1 2)`。 

| ステップ | サイクル | 操作 | 配列効果 |
 | --- | --- | --- | --- |
 | 1 | (0,3) | スワップ(0,3) | 0 と 3 を交換 |
 | 2 | (1,2) | スワップ(1,2) | 1 と 2 を交換 |

 両方のサイクルを解決すると、配列は次のようになります。`[0,1,2,3]`。 

これにより、素のサイクルが独立しており、個別に処理できることが確認されます。 

### 例 2

 入力:```
5
2 4 3 1 0
```ソートされたインデックス:`[4, 3, 0, 2, 1]`。 

サイクル:`(0 2 3 1 4)`。 

| ステップ | ピボット | スワップターゲット | 効果 |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 部分的な回転 |
 | 2 | 0 | 3 | サイクル修正を継続 |
 | 3 | 0 | 1 | 続く |
 | 4 | 0 | 4 | サイクルを完了します |

 最終的な配列は次のようになります`[0,1,2,3,4]`。 

これは、1 つのピボットに繰り返し固定することによって 1 つの長いサイクルが解決されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優勢で、サイクル分解は線形です。 
| スペース | O(n) | 順列と訪問配列 |

 操作の数は O(n) スワップで、それぞれが 3 つの XOR 操作に拡張されるため、合計操作は n ≤ 1000 の許容制限内に収まります。

 ## 特殊なケース

 すでにソートされた配列の場合、すべての要素はすでに長さ 1 の正しいサイクルにあるため、演算は生成されません。 アルゴリズムは、各インデックスを訪問済みとして直ちにマークし、スワップ生成をスキップします。 

値が繰り返される配列の場合でも、並べ替えによってインデックスの有効な並べ替えが定義されます。 スワップは位置に対して行われるため、重複によって正確性が損なわれることはなく、サイクル分解により有効な独立したサイクルが生成されます。 

単一の長いサイクルの間、アルゴリズムは最初のピボットを基準にして要素を繰り返し修正します。 値が継続的に移動しても、ピボットが最終的に最終位置に到達するという不変条件はそのまま残り、k − 1 回のスワップ後にサイクルが終了します。
