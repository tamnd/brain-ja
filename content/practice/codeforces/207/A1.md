 ## 解決策
 ## 問題の理解

 私たちには数人の科学者が与えられ、それぞれが一連の計算タスクを作成します。 すべてのタスクには固定のリソース要件があり、各科学者のリスト内でタスクは指定された順序で実行する必要があります。 さまざまな科学者の間で、各科学者の内部秩序を破らない限り、どのような方法でもタスクを自由にインターリーブすることができます。 

最終的には、すべてのタスクの 1 つのグローバル シーケンスを構築します。 「不良ペア」は、この最後のシーケンスの 2 つの連続するタスクのリソース使用量が減少するたびに表示されます。これは、最初のタスクが次のタスクよりも厳密に多くのリソースを必要とすることを意味します。 私たちの目標は、各科学者の内部順序を尊重してすべてのタスクを調整し、そのようなドロップの数ができる限り少なくなるようにすることです。 

入力は、すべてのタスク値として明示的に指定されるわけではありません。 代わりに、各科学者はシーケンス用のジェネレーターを提供します。 最初の値と、ある数値を法として残りの値を生成する反復が与えられます。 これにより、すべてのタスク値を実際に再構築またはストリーミングする必要があります。 

タスクの総数は非常に多くなり、最も難しいバージョンでは最大数十万に達する可能性があるため、任意のインターリーブを明示的に考慮したり、すべての順列をシミュレートしようとするソリューションは直ちに不可能になります。 すべてのタスクを独立した項目として扱い、それらを並べ替えるという素朴な考えも、各科学者のシーケンス内の固定された順序制約に違反するため、無効になります。 

微妙なエッジ ケースは、2 人の科学者が値の順序で大幅にインターリーブしているにもかかわらず、厳格な内部順序付けを強いられるシーケンスを作成する場合です。 たとえば、科学者 A の値が [10, 1] で、科学者 B の値が [2, 3] の場合、グローバルにソートすると [1, 2, 3, 10] が得られますが、A の順序は 10、その後 1 のままでなければならず、グローバル ソートに関係なくすでに不正な遷移が強制されているため、これは不正です。 これは、問題が純粋な並べ替えタスクではないことを示しています。 

もう 1 つのエッジ ケースは、科学者の配列が厳密に増加または厳密に減少している場合です。 たとえ全体的にすべてを完全にマージできたとしても、そのシーケンスを他のシーケンスと比較して慎重に配置しない限り、内部減少により避けられない不良ペアが発生します。 

## アプローチ

 科学者間の制約を無視すると、各タスクは単なる数値であり、不良ペアを最小限に抑えることは、マルチセット全体を非降順で並べ替えることと同じになります。 最終シーケンス内の反転は、まさに 1 つの不良ペアをもたらすため、最適な答えはゼロになります。 これは、並べ替えられた配列には隣接する減少がないという古典的な観察です。 

この難しさは完全に、各科学者のタスクを順序立てて実行しなければならないという要件から生じています。 これにより、問題は複数の固定シーケンスのマージに変わります。 強引に試す場合は、有効なインターリーブをすべて遡って、シーケンスが使い尽くされていない科学者から次のタスクを選択することになります。 このようなインターリーブの数は組み合わせ的であり、タスクの総数ではほぼ多項式であり、数十個のタスクであっても実現可能な制限をはるかに超えています。 

重要な洞察は、目的をローカルで再解釈することです。 グローバル シーケンスに次のタスクを追加するたびに、非減少遷移を継続するか、ドロップを作成します。 したがって、コストは隣接するペアにのみ依存し、各選択はシーケンス内の前の要素にのみ影響します。 

これは貪欲な構造につながります。いつでも、最後に選択された現在の値を維持し、どの科学者が次に実行できるタスクを決定するかが決まります。 重要なのは、候補を選択することで現在のテールと悪いペアが作成されるかどうかだけです。 不正なペアを作成する必要がある場合は、将来のダメージを軽減する方法で作成したいと考えます。つまり、可能な場合は大きな値を遅らせ、ペナルティなしで適合できるときに小さな値を早めに消費する必要があります。

最適な戦略は、各科学者のシーケンスを、最初の要素は常に利用可能であるが、後の要素は前の要素の消費に依存するストリームとして考えることによって導き出すことができます。 私たちは常に、現在の遷移を悪化させない最小の利用可能な次の要素を選択したいと考えており、そのような要素が存在しない場合にのみ、不正なペアを受け入れます。 

よりグローバルな見方では、これは k 個のソートされたチェーン (グローバルにソートされたものではなく、固定順序のチェーン) の貪欲なマージとなり、常に最小の実現可能なヘッドを選択し、非減少遷移を優先します。

 ## アルゴリズムのチュートリアル

 私たちは各科学者を、生成されたシーケンスへのポインターとして扱います。 どの時点においても、各科学者の「最前線」は、固定された順序で次の未処理のタスクです。 

1. すべてのシーケンスを生成するか、繰り返しを使用してオンデマンドでストリーミングし、現在のインデックスと値のみを保存します。 私たちは各科学者のポインターを維持し、その科学者が現在利用可能な値を知っています。 
2. 現在利用可能なすべてのタスクを、候補者を効率的に選択できる構造に組み込みます。 各エントリは (値、科学者 ID) のペアです。 当初、これにはすべての科学者の最初のタスクが含まれています。 
3. 変数を維持する`last`これは、以前に選択したタスクの値を最終シーケンスに保存します。 最初の選択には制約が存在しないため、負の無限大として初期化します。 
4. 各ステップで、次のタスクを決定します。 

まず、利用可能なすべてのタスクの中から、値が ≥ のタスクを選択しようとします。`last`。 これらの有効な候補の中から、最小の値を選択します。 これにより、将来の強制的な減少が発生する可能性が最小限に抑えられます。 
5. そのような候補が存在しない場合、不良ペアを作成せざるを得ません。 その場合、全体として利用可能な最小の値が選択されます。 これにより、ドロップが可能な限り小さくなり、後のステップでの柔軟性が保たれます。 
6. 科学者からタスクを選択した後、その科学者のポインタを進めます。 さらにタスクが残っている場合は、繰り返しを使用して次の値を生成し、それを使用可能なセットに挿入します。 
7. 選択した値が厳密に以下になるたびに、不良ペア カウンタをインクリメントします。`last`、次に設定します`last`選択した値に設定し、すべてのタスクが消費されるまで続行します。 

これが機能する理由は、ローカルな決定の構造に由来します。 すべてのステップは、以前に選択した値と、使用可能な次の要素の現在のセットにのみ依存します。 有効な非減少継続が存在する場合、そのような最小の要素を選択すると、後で不要な削除を強制することになる大きな値の早期消費を回避できます。 非減少オプションが存在しない場合、どの選択も不良ペアを作成する必要があるため、選択した値を最小限に抑えると、次の比較ベースラインが可能な限り低く保たれるため、将来の制約が最小限に抑えられます。 

不変条件は、各ステップの後、制約と一致し、同じプレフィックス長を持つすべてのシーケンスの中で、貪欲な選択により、現在のステップでのみ異なる代替案と比較して、将来避けられない不良ペアの数が決して増加しないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    
    # store generator state per scientist
    k = [0] * n
    a = [0] * n
    x = [0] * n
    y = [0] * n
    m = [0] * n
    
    # current index and current value per scientist
    idx = [0] * n
    cur = [0] * n
    
    heap = []
    
    total = 0
    
    for i in range(n):
        ki, a1, xi, yi, mi = map(int, input().split())
        k[i] = ki
        x[i] = xi
        y[i] = yi
        m[i] = mi
        
        idx[i] = 1
        cur[i] = a1
        
        heapq.heappush(heap, (cur[i], i))
        total += ki
    
    last = -10**18
    bad = 0
    
    while heap:
        # extract all available candidates
        tmp = []
        while heap:
            tmp.append(heapq.heappop(heap))
        
        chosen = None
        
        # try best non-decreasing candidate
        for v, i in tmp:
            if v >= last:
                chosen = (v, i)
                break
        
        # if none, take smallest overall
        if chosen is None:
            chosen = tmp[0]
        
        v, i = chosen
        
        # count bad pair
        if v < last:
            bad += 1
        
        last = v
        
        # advance scientist i
        if idx[i] < k[i]:
            nxt = (cur[i] * x[i] + y[i]) % m[i]
            cur[i] = nxt
            idx[i] += 1
            heapq.heappush(heap, (cur[i], i))
    
    print(bad)

if __name__ == "__main__":
    solve()
```この実装では、現在利用可能なタスクのヒープが、各科学者のアクティブなプレフィックスごとに 1 つずつ維持されます。 次の選択を決定するためにヒープからすべてを一時リストに削除するたびに、値が減少しない最小値をスキャンします。`last`。 何も存在しない場合は、全体の最小値に戻ります。 

ジェネレーター ロジックは、繰り返しを直接使用して科学者ごとに処理され、タスクが消費された場合にのみ更新されます。 これにより、不要な場合に完全なシーケンスを明示的に保存することがなくなります。 

実装の微妙な点は、すべての候補を評価するために各ステップでヒープを完全に空にすることです。 これは正しいですが、漸近的に最適ではありません。 より良い解決策は、2 つの順序付けられた構造または遅延分割を維持することです。 ただし、概念的な貪欲ルールは、この実装の詳細とは独立しています。

 ## 特殊なケース

 重要なエッジケースは、利用可能なすべての次の要素が現在の要素よりも小さい場合です。`last`。 その状況では、考えられるすべての動きによって不良ペアが作成され、アルゴリズムは依然として利用可能な最小値を選択する必要があります。 たとえば、次の場合`last = 100`利用可能な値は次のとおりです`[10, 20, 30]`、正しい動作は選択することです`10`、 ない`30`両方とも悪いペアを作成するため、`10`今後のステップのために低いベースラインを保持します。 

もう 1 つのエッジケースは、ある科学者のシーケンスが変動する場合です。`[5, 1, 4]`。 内部ドロップは避けられず、たとえグローバルな順序が慎重に選択されたとしても、最終的には不正なペアを強制することになります。 アルゴリズムにより、`5`必要になるまで、シーケンスの早い段階で追加の不良ペアが作成されるような大きな値の早期露出を防ぎます。 

3 番目のケースは、多くの科学者が同じ値から始める場合です。 貪欲ルールはそれらを対称的に扱い、すべての選択が同じ即時効果を生み出すため、タイブレークは有効です。`last`。
