 ## 解決策
 ## 問題の理解

 戦車の列が与えられ、それぞれが左から右に一列に固定された位置を占めています。 各タンクには、受信側であるときにメッセージをどこまで受信できるかを決定するパラメーターがあります。 メッセージは常に、行内の現在の最初のタンクから最後のタンクに送信されますが、必ずしもその間のすべてのタンクを通過するとは限りません。 代わりに、最終的に最後のタンクに到達するまで、一連の有効な送信を通じて前方にホップします。 

所定のタンクからの送信`i`所定の位置のタンクに`j`の場合にのみ許可されます`i < j`、受入タンクが所定の位置にある場合`j`インデックス付き`x`、 それから`i`によって決定される固定後方範囲内になければなりません。`a[x]`。 許可されたホップごとに 1 秒のコストがかかるため、メッセージのコストは、選択されたパスのホップ数になります。 

各完全なメッセージが最後のタンクに到達すると、その最後のタンクがラインの先頭に移動し、順序がローテーションされます。 その後、同じルールを使用して新しいメッセージが再度送信されます。 このプロセスが正確に繰り返されます`n`元の順序に戻るまでの時間。 

タスクは、ラウンドごとにタンクの順序が変わることを考慮して、すべてのメッセージに最適な中間ホップを選択することで、すべてのメッセージにわたる送信ステップの合計数を最小限に抑えることです。 

この制約により、最大 250,000 台の戦車を処理する必要があります。 二次方程式の解`n`最大約 10¹⁰ の操作が必要になるため、すぐに失敗します。 平`O(n log n)`はタイトであるため、線形または線形に近いアプローチが必要です。 主な問題点は、許可される送信のグラフがローテーションによりメッセージごとに変化するため、最短パスを最初から再計算するのは実行不可能であることです。 

すべてのタンクの半径が同じである場合、微妙なエッジケースが発生します。 その場合、すべてのメッセージは対称的に動作し、各送信には同じ固定コスト パターンが適用されます。 さまざまな構造を想定したり、メッセージごとにローカルで最適化を試みたりするソリューションでも、冗長な同一の作業が誤って再計算される可能性があります。 

もう 1 つのエッジ ケースは、1 つのタンクの半径が非常に大きく、他のタンクの半径が 1 である場合です。そのタンクがプロセスの途中に表示されるときは常に普遍的なショートカットとなり、最適なパスは、そのタンクが現在回転されたアレイの前面付近にあるか、背面付近にあるかに大きく依存します。 回転効果を無視する素朴な貪欲さは、ステップ数を過剰にカウントします。 

## アプローチ

 直接シミュレーションでは、タンクの現在の順序が明示的に維持され、メッセージごとに、許可された前方ジャンプのみを使用して、最初のタンクから最後のタンクまでの最短パスが計算されます。 各ホップは宛先タンクの半径によって局所的に制約されるため、グラフの方向性が位置に依存します。 

メッセージごとに BFS を実行したとしても、全体の複雑さは次のようになります。`O(n^2)`最悪の場合、各 BFS はほぼすべてのエッジをスキャンできるため、`n`そのような計算。 

主な観察は、回転ごとに完全な最短パスを実際に再計算する必要がないということです。 プロセスの構造は非常に反復的です。各メッセージの後、最後の要素が前に移動します。これは、事実上配列を回転していることを意味しますが、残りの要素の相対的な順序は保持されます。 

パスを再計算する代わりに、各タンクがメッセージのターゲットになったときに、各タンクの貢献という観点からプロセスを再解釈します。 各タンクは最終的に、フル サイクルごとに 1 回だけ最後の要素になります。そのとき、現在のフロントから現在のローテーション順序でその位置にメッセージを送信するコストを知りたいと考えます。 

重要な洞察は、最後の戦車までの最短経路は、目的地であるときに各位置からどれだけ「後方にジャンプ」できるかによってのみ決まるということです。 これにより、直線上の到達距離グラフに似た構造が作成されます。 最適なパスは常にチェーンを形成し、各ステップは最適に先に到達できる最も遠くに到達可能な先行者を選択します。 これは古典的な単調な到達可能性構造であり、貪欲な DP またはセグメントベースのスイープで解決できます。 

各ポジションについて、そのポジションに直接到達できる最良の以前のポジションを維持し、次のように決定されるスライディング ウィンドウにわたる最小コスト DP を計算します。`a[i]`。 回転は、各ステップがインデックスを効果的にシフトすることを観察することで処理できますが、コスト構造は巡回置換を通じて不変のままであるため、プレフィックス遷移を使用して単一の線形パスですべての寄与を計算できます。

 ## アルゴリズムのチュートリアル

 1. 視点を修正して、常に戦車がその位置の現在のターゲットになっているかのようにコストを計算します。`i`。 ローテーションをシミュレートする代わりに、各タンクを周期的な順序で 1 回貢献するものとして扱います。 これにより、配列の明示的な更新が回避されます。 
2. ポジションごとに`i`、 解釈する`a[i]`任意の状態からの移行を許可する`j`で`[i - a[i], i - 1]`に`i`。 これは、昇順の位置にわたる有向非環状構造を定義します。 
3. 定義する`dp[i]`現在のセグメントの先頭から位置までメッセージを配信するための最小コストとして`i`。 移行は次のとおりです。 

前のポジションを選択します`j`到達できるのは`i`、から 1 ホップを追加します`j`に`i`。 

それで：```
dp[i] = 1 + min(dp[j]) over j in [i - a[i], i - 1]
```課題は、このスライディング最小値を効率的に計算することです。 
4. 候補を格納するインデックスに対する単調デキューを維持する`j`昇順に`dp[j]`。 それぞれについて`i`、ウィンドウの外側のインデックスを削除します`[i - a[i], i - 1]`。 
5.両端キューの先頭には常に最小値のインデックスが保持されます。`dp[j]`範囲内なので計算します`dp[i] = dp[deque.front] + 1`。 
6. すべての位置を左から右に 1 回処理し、各インデックスが両端キューに出入りするのが最大 1 回になるようにします。 
7. 最終的な答えは、ローテーション サイクルのそれぞれのステップで最終受取人となるすべてのポジションの貢献の合計です。 

### なぜ効果があるのか

 DP は、有効な伝送パスは厳密に増加する位置のシーケンスであり、すべての有効なステップは受信タンクの半径によってのみ決定されるという構造を捉えています。 エッジは前方のみを指しているため、最適なパスは以前のインデックスを再検討する必要がなく、問題を DAG 内の 1 次元の最短パスに還元できます。 

deque 不変式により、すべての位置に対して次のことが保証されます。`i`、私たちは常に、法的に到達できる以前のポジションを正確に保持します。`i`、その中でもコストが最小限のものを残しておきます。 これにより、使用されるすべての遷移が保証されます。`dp`この非巡回グラフでは部分構造の最適性が維持されるため、ローカルおよびグローバルに最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + [int(input()) for _ in range(n)]

    dp = [0] * (n + 1)
    from collections import deque
    dq = deque()

    dq.append(1)
    dp[1] = 0

    for i in range(2, n + 1):
        while dq and dq[0] < i - a[i]:
            dq.popleft()

        dp[i] = dp[dq[0]] + 1

        while dq and dp[dq[-1]] >= dp[i]:
            dq.pop()
        dq.append(i)

    print(sum(dp[1:]))

if __name__ == "__main__":
    solve()
```このコードは、すべてのタンクに対して左から右への 1 回のスイープを実行します。 デキューは、半径制約によってフィルター処理された、各位置の有効な先行者のスライディング ウィンドウを維持します。 の`dp`配列には、線形化プロセスのターゲットとして扱われる場合に、各位置に到達するために必要な最小ホップ数が格納されます。 

最もデリケートな部分は窓のメンテナンスです`dq[0] < i - a[i]`これにより、以前の位置が現在のタンクの受信半径内になければならないという制約が適用されます。 これがないと、トランジションで無効なホップが誤って使用されてしまいます。 

最終的な答えはすべての合計です`dp[i]`、すべてのメッセージ ラウンドにわたる合計コストを反映します。

import sys, io

def run(inp: str) -> str:

    from collections import deque

    n = int(input())

    dp = [0] * (n + 1)
    dq = deque([1])

    for i in range(2, n + 1):
        while dq and dq[0] < i - a[i]:
            dq.popleft()
        dp[i] = dp[dq[0]] + 1

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムが初期化されます`dp[1] = 0`デキュー操作は必要ないため、無効なアクセスのリスクはありません。 

いつすべて`a[i] = 1`、各インデックスは直前のインデックスにのみ依存します。 デキューは複数の要素を保持しないため、アルゴリズムはステップごとに 1 の単純な累積和に減算され、線形進行が正しく生成されます。 

いつ`a[i]`が非常に大きい場合、有効なウィンドウには常に以前のすべてのインデックスが含まれます。 その後、両端キューは常にこれまでのグローバル最小 dp を保持し、各`dp[i]`達成可能な最良の状態から増加し、最大の到達可能性を正確に反映します。
