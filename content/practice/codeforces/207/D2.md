 ## 解決策
 ## 問題の理解

 この問題では、文書の内容に基づいて文書の主題を予測する分類器を構築する必要があります。 各文書は、1、2、または 3 のラベルが付けられた 3 つの主題の 1 つに正確に属します。入力は、文書 ID、そのタイトル、および最大 10 キロバイトの全文で構成されます。 出力は単一の整数、つまり予測されたサブジェクトです。 

テスト文書には新しい識別子が含まれる可能性があるため、文書識別子は任意であり、予測には使用できません。 タイトルと本文が重要な要素です。 初期のテスト グループには、トレーニング セットから直接取得されたドキュメントが含まれていますが、識別子は異なります。一方、後のグループには、これまでに見たことのないドキュメントが含まれています。 これは、ソリューションがドキュメント ID を記憶するだけでなく、トレーニングで見られる正確なテキストを超えて一般化する必要があることを意味します。 

ドキュメントのサイズは 10 キロバイトに制限されており、件名の数が少ないため、ドキュメントごとにテキストを線形に処理するアルゴリズムは、2 秒の制限内で快適に実行されます。 主な課題は、信頼性の高い分類を可能にするテキストの表現を作成することです。 素朴な解決策は、目に見えない文書や主題間で語彙を共有する文書では失敗する可能性があります。 

特殊なケースは、文書に重複する語彙がある場合に発生します。 たとえば、「trade」という単語が主題 2 と 3 に出現する場合、出現回数をカウントするだけの分類子は誤って分類する可能性があります。 ドキュメントが非常に短く、タイトルのみが含まれ、本文が含まれていない場合、別の微妙なシナリオが発生します。 その場合、アルゴリズムは主にタイトルに依存する必要があります。 空または空に近いテキストの処理に失敗すると、エラーや間違った予測が発生する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのトレーニングドキュメントを保存し、正確なテキストマッチングや共有単語などの単純なヒューリスティックを使用して、入力ドキュメントを各ドキュメントと比較することです。 これは、完全一致によって主題が特定されるため、トレーニングで表示されたドキュメントに対しては機能しますが、グループ 3 ～ 10 の未表示のドキュメントについては、完全に一致する可能性が低いため失敗します。 ブルート フォース アプローチの操作数は、トレーニング ドキュメントの数とその合計サイズに応じて増加します。 各ドキュメントが最大 10 キロバイトの数万のドキュメントからなるトレーニング セットの場合、比較の数は最悪の場合でも数億件に達する可能性があり、これは限界ギリギリの速度です。 

より堅牢なアプローチは、これをテキスト分類問題として扱うことです。 文書を単語にトークン化し、些細な違い (句読点や大文字の使用など) を削除し、各主題の統計 (各主題での各単語の出現頻度) を計算できます。 新しい文書が到着すると、その文書に含まれる単語の出現回数をカウントし、件名ごとのカウントを合計します。 合計が最も高い被験者が予測されます。 これは事実上、単純化された袋詰めのモデルです。 クラスが 3 つしかなく、ドキュメントのサイズが小さいため、計算は高速です。 このアプローチは、完全一致ではなく単語パターンを活用することで、未確認のドキュメントを一般化します。 

重要な洞察は、文書が自然に語彙ごとにクラスター化されているということです。つまり、ある主題に関連付けられた単語が他の主題にはめったに現れないということです。 これにより、周波数ベースの分類器は、深い NLP テクニックを使用せずに適切に機能することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T × D × L) | O(T × L) | 遅すぎる/未表示のドキュメントで失敗する |
 | バグオブワードの頻度 | O(L + V) | O(V × 3) | 承認済み |

 ここで、T はトレーニング ドキュメントの数、D は平均ドキュメント サイズ、L は入力ドキュメントのサイズ、V は語彙サイズです。 

## アルゴリズムのチュートリアル

1. すべてのトレーニング ドキュメントをロードし、句読点を無視してテキストを小文字にトークン化します。 各主題に 1 つずつ、合計 3 つのカウンターを維持し、単語をカウントにマッピングします。 
2. トレーニング セット内の単語ごとに、その主語のカウントを増加します。 これにより、主題ごとに単語頻度テーブルが作成されます。 
3. 新しいドキュメントが到着したら、同じ方法でそのテキストをトークン化します。 
4. 新しい文書内の各トークンについて、3 つのサブジェクト テーブルでそのカウントを検索し、それらを合計します。 これにより、各科目のスコアが得られます。 
5. 累積スコアが最も高い科目を予測として選択します。 同点の場合は、最小の数値ラベルが付いた件名を選択します。 

これが機能する理由: 不変条件は、1 つの主題に強く関連する単語がその主題の累積スコアを支配するということです。 アルゴリズムは、文書全体の単語の頻度を合計することにより、語彙が入力に最もよく一致する主題を効果的に識別します。 このアプローチでは、完全一致ではなく単語レベルの統計を利用するため、未表示のドキュメントを処理します。 

## Python ソリューション```python
import sys, os, re
from collections import defaultdict, Counter
input = sys.stdin.readline

# Preprocess training data
subjects = [1, 2, 3]
word_counts = {s: Counter() for s in subjects}

# adjust path to the training directories
train_dir = "./train"

for s in subjects:
    dir_path = os.path.join(train_dir, str(s))
    for fname in os.listdir(dir_path):
        with open(os.path.join(dir_path, fname), encoding="utf-8") as f:
            f.readline()  # skip id
            f.readline()  # skip title
            text = f.read().lower()
            tokens = re.findall(r'\b\w+\b', text)
            word_counts[s].update(tokens)

# Read input document
doc_id = input()
doc_title = input()
doc_text = sys.stdin.read().lower()
tokens = re.findall(r'\b\w+\b', doc_text)

# Compute score per subject
scores = {s: 0 for s in subjects}
for token in tokens:
    for s in subjects:
        scores[s] += word_counts[s][token]

# Output predicted subject
predicted = min([s for s in subjects if scores[s] == max(scores.values())])
print(predicted)
```コードはまず、トレーニング セットを使用して被験者ごとの頻度テーブルを構築します。 トークン化により、単語が一貫して比較されることが保証されます。 予測中に、入力ドキュメントがトークン化され、主題ごとの累積単語数が計算されます。 最終的な予測は、数値ラベルによって分けられた最も高いスコアを持つ主題です。 最初の 2 行の後の入力全体を読み取ると、任意のサイズのドキュメントが効率的に処理されます。 使用する`Counter`周波数集約を簡素化します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + L) | N はトレーニング セット内の総単語数です。 L は入力ドキュメント内の単語です。 トークン化とカウントが支配的です。 |
 | スペース | O(V) | V は、頻度テーブルに保存された、すべてのトレーニング ドキュメントにわたるユニークな単語の合計です。 |
