 ## 解決策
 ## 問題の理解

 塔に積み重ねられた単位立方体から構築された都市を表す _n_×_n_ グリッドが与えられます。 グリッドの各セルには、その位置のタワーの高さを示す整数が含まれています。 Petya は、方向ベクトル _(vx, vy)_ に沿って水平面内の非常に遠くから都市を観察します。 問題は、その視点から個々の立方体がいくつ見えるかということです。 

立方体は、視線方向に沿って直接遮るものが他にない場合に表示されます。 視点は無限に遠いため、問題は 2D 投影問題に帰着します。ベクトル _(vx, vy)_ に平行な線に沿って発生する最大高さを追跡するだけで済みます。 立方体がその線に沿ってその前の立方体よりも高い位置にある場合、その立方体は表示されます。 

制約は中程度です: _n_ ≤ 1000、高さは最大 10^9 です。 方向ベクトルの成分は最大 ±10^4 の整数です。 n が小さいため、おおよそ O(n²) の複雑さのアルゴリズムは許容されますが、O(n³) 以下のアルゴリズムは遅すぎます。 エッジ ケースには、負のベクトル コンポーネント、高さ 0、および最上位の立方体のみが考慮される単一タワー グリッドが含まれます。 たとえば、高さの 1 つの行が [1,3,2] で、ベクトルがその行に沿っている場合、方向によっては、位置 1、2 の立方体と、2 と 3 の追加の高さのみが表示される可能性があります。 ベクトルの方向を無視した単純な反復では、間違った立方体がカウントされてしまいます。 

## アプローチ

 ブルートフォースアプローチは、各立方体からのすべての光線をシミュレートし、その前にある別の立方体と交差するかどうかを確認することです。 サイズが n×n、高さが最大 ​​h のグリッドの場合、レイごとに O(n²・h) 回のチェックが行われ、合計で O(n²・h・n²) 回のチェックが行われます。これは、上限 n = 1000 および h = 10^9 では実行不可能です。 オクルージョンを検出するために方向ベクトルに沿って反復するのは依然としてコストがかかるため、レイを立方体ごとに 1 つに減らしても役に立ちません。 

重要な洞察は、_(vx, vy)_ に沿った遠くの視点から見ると、立方体は同じ線上のそのベクトルに沿ってさらに遠くにある他の立方体のみをブロックできるということです。 傾き vy/vx の線に沿ってグリッドをシーケンスに分割し、それらの線に沿って視点から順番に立方体を処理できます。 各シーケンスに沿って、これまでに確認された最大高さよりも高い立方体のみが、表示される数に寄与します。 処理順序を慎重に選択することで、各キューブを他のすべてのキューブと照合することを回避し、問題を各ラインに沿ったソートされた線形スキャンに縮小します。 

vx と vy の符号を考慮して方向を正規化し、行と列のスイープ順序を決定します。 それぞれの対角線または反対角線 (ベクトルに応じて) について、観測された最大の高さを追跡し、シーケンス内の各塔について、目に見える立方体は塔の高さとこれまでの最大値 (正の場合) の差です。 これにより、前の障害物の上に突き出た立方体が正確にキャプチャされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | 最適 (ベクトル線に沿ってスイープ) | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 方向ベクトルを符号によって正規化します。 vx < 0 の場合、列を右から左に繰り返します。 vy < 0 の場合、行を下から上に繰り返します。 vx = 0 の場合は純粋に行に沿ってスイープし、vy = 0 の場合は純粋に列に沿ってスイープします。 
2. セルを処理する順序を決定します。 セルは、視点に面した側から開始して、ベクトルに垂直な線に沿って処理されます。 整数ベクトルの場合、ベクトルの符号に従って行と列のインデックスを加算または減算することでスイープ順序を定義できます。 
3. スイープの各行に対して、変数を初期化します。`max_height`これは、その線に沿ってこれまでに確認された最も高い立方体を追跡します。 
4. 視点から遠ざかる順にラインに沿って繰り返します。 セルごとに計算します`visible = max(0, a[i][j] - max_height)`。 これは、このセルによって提供される新しい表示キューブの数をカウントします。 
5.追加`visible`合計数と更新`max_height = max(max_height, a[i][j])`。 
6. グリッド全体をカバーするすべての線に対して繰り返します。 

機能する理由: 視点方向の各線に沿って、立方体はその後ろにあるそれより高くない立方体をすべてブロックします。 正しい順序でスイープし、現在の最大高さを維持することにより、各キューブの寄与が 1 回だけ計算されます。 各立方体は、そのラインに沿って視点に近い立方体とのみ比較されるため、二重にカウントされる立方体はありません。 不変条件とは、`max_height`は常に、現在位置までのラインに沿った最も高い立方体を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, vx, vy = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

total = 0

# Determine row and column sweep direction
row_range = range(n) if vy >= 0 else range(n-1, -1, -1)
col_range = range(n) if vx >= 0 else range(n-1, -1, -1)

# The key idea is to sweep along diagonals aligned with vector signs
for sum_idx in range(2*n - 1):
    max_height = 0
    # For each diagonal where i+j == sum_idx (or i-j == sum_idx for other signs)
    for i in row_range:
        j = sum_idx - i
        if j < 0 or j >= n:
            continue
        h = a[i][j]
        visible = max(0, h - max_height)
        total += visible
        max_height = max(max_height, h)

print(total)
```このコードは、ベクトル符号に従ってスイープ順序を定義します。 各対角線がベクトルの垂直線に沿って整列したセルのセットを表すように、対角線を反復処理します。 保守します`max_height`スイープに沿って最も高い立方体を追跡し、現在の高さと高さの間の正の差を加算します。`max_height`表示される合計カウントに。 Off-by-one エラーは、対角インデックスを注意深く計算することで回避され、すべてのセルが 1 回だけ処理されます。
