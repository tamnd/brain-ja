 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$n \times n$ここで、すべてのセルには 0 または 1 が含まれます。許可される操作は、列を任意に並べ替えることです。 列を再配置した後、行内のすべての 1 が 0 で分割されずに 1 つの連続したブロックに表示されるという意味で、すべての行を「適切に構造化」できるかどうかを知りたいと考えます。 

これを別の言い方で言えば、列の置換後、各行は 1 つの位置のセットが 1 つの間隔 (おそらく空) を形成するバイナリ文字列のように見える必要があります。 行は定義上は独立していますが、同じ列の順序を共有する必要があるという事実によって結合されます。 

重要な制約は、$n \le 500$。 これにより、おおよそのことが可能になります$O(n^3)$定数が小さい場合にのみ、Python で 2 秒以内にメソッドを快適に渡すことができますが、列のすべての順列またはすべての列順序にわたるペアごとの一貫性をチェックすることを伴うものは、すぐに不可能です。$n!$天文学的に大きくて均等です$O(n^3)$慎重に構成しない限り、境界線に達します。 

各行の列が連続するように列を配置しようと単純に考えますが、難しいのは、単一の列の順序付けがすべての行を同時に満たさなければならないことです。 このグローバルな結合は、ほとんどの誤った貪欲なアイデアが失敗する場所です。 

2 つの行に同じ数の 1 があるが、列全体で異なる配置になっている場合、微妙なエッジ ケースが発生します。 たとえば、1 つの行が`101`そしてもう一つは`011`、列を並べ替えても両方の行を同時に連続させることはできません。 行を個別に扱う単純なアプローチでは、両方を修正できると誤って想定してしまいます。 

別の失敗ケースは、行の 1 のカウントが同じであるが、列全体で 1 の相対分布が異なる場合に発生します。 この制約はカウントに関するものではなく、各行によって引き起こされる順序付け制約の互換性に関するものです。 

## アプローチ

 この強引なアイデアは、列のすべての順列を考慮し、各順列を行列に適用し、1 つの連続セグメント内ですべての行に 1 が含まれているかどうかを確認することです。 これは、許可された操作の検索スペース全体を探索するため、正しいです。 ただし確認が必要です$n!$順列、および各順列の行列スキャンのコスト$O(n^2)$、そのため、たとえ$n = 8$。 

重要な観察は、順列を明示的に検索する必要がないということです。 代わりに、視点を逆にすることができます。有効な最終的な配置は列の順序を定義し、その順序において各行は 1 秒の間隔を定義します。 したがって、各行には、1 を含む列をゼロやその他の値と比較してどのように並べる必要があるかという制約が課されます。 

列の順序が固定されている場合、行の 1 が単一の間隔を形成している場合、その行は有効です。 これは、列間で、その行の値 1 を持つすべての位置が、その行で選択された左端と右端の列の間に出現し、その間隔の外側に「穴」が存在しないと言うのと同じです。 

ここで論理を反転します。各列はバイナリ ベクトルとして見ることができます。 賢い方法で列を並べ替える場合、行は間隔が凸になるようにする必要があります。 

重要な洞察は、行ごとに 1 のパターンを定義し、それを使用して列間の順序制約を誘導することです。 2 つの列を考慮すると、順序付けを強制する方法でそれらを区別する行が存在するかどうかを尋ねることができます。 ある行で、ある列が 1 で、別の列が 0 である場合、間隔の配置方法に応じて制約を導き出すことができます。 

より構造化された方法は、この条件が、最終的な列の順序付けにおいてすべての行が「凸型」であることを要求することと同等であることを観察することです。 これは、行の Consecutive Ones プロパティ (C1P) の古典的な認識です。 

明示的な PQ ツリー (古典的な 3000 レベルのツール) を構築する代わりに、前処理後に辞書編集的に解釈されたビットマスクによって列を並べ替えることで、この特定の問題を解決できます。 

有効な順序付けが存在する場合、各列をビットマスクとして解釈し、一貫した方向に並べ替えることによって列を順序付けすると (たとえば、行の反転やハッシュ行制約によって辞書編集的に)、配置候補が得られることがわかります。 その後、すべての行がこの順序で連続しているかどうかを確認するだけで済みます。 

したがって、解決策は、列を並べ替えて、連続するものプロパティをチェックすることになります。

 ## アルゴリズムのチュートリアル

 各列を長さのベクトルとして扱います$n$。 目標は、各行で 1 を含む列のインデックスが単一の連続セグメントを形成するような、これらの列の順序を見つけることです。 

1. 行列を読み取り、列表現を構築します。 各列は、すべての行にわたるビットのリストになります。 私たちが制御する操作は列の置換であるため、この再方向付けが必要です。 
2. ビット ベクトルの辞書編集順を使用して、すべての列を並べ替えます。 直観的には、列を区別する行によって境界が強制されるため、行全体で同様に動作する列は近くに配置する必要があると考えられます。 
3. ソート後、この列順序で行列を再構成します。 これにより候補行列が得られます$b$。 
4. 各行を左から右にスキャンし、すべての 1 が単一の連続したブロックを形成していることを確認します。 これは、1 が表示され始めたかどうか、ブロックを出たかどうかを追跡し、その後 2 番目のブロックが出現しないようにすることで実行できます。 
5. すべての行が連続条件を満たしている場合、YES を出力し、行列を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 正確さは、列の有効な順序付けが、行の区別によって引き起こされる部分的な順序付けを尊重する必要があるという事実に依存します。 行内で一方が 1 でもう一方が 0 の異なる 2 つの列は、その行の 1 が連続するように一貫した順序で出現する必要があります。 完全な列ベクトルに対する辞書編集的ソートは、解が存在する場合にそのようなペアごとの制約をすべて同時に尊重する標準的な線形拡張です。 有効な順序が存在する場合、ソート順序は同順位までその順序と一致し、同一の列は交換可能であるため、同順位は連続性を壊しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(matrix):
    n = len(matrix)
    for r in range(n):
        seen_one = False
        seen_zero_after_one = False
        for c in range(n):
            if matrix[r][c] == '1':
                if seen_zero_after_one:
                    return False
                seen_one = True
            else:
                if seen_one:
                    seen_zero_after_one = True
    return True

def solve():
    n = int(input())
    a = [input().strip() for _ in range(n)]

    cols = []
    for j in range(n):
        col = tuple(a[i][j] for i in range(n))
        cols.append((col, j))

    cols.sort()

    b = [['0'] * n for _ in range(n)]
    for new_j, (_, old_j) in enumerate(cols):
        for i in range(n):
            b[i][new_j] = a[i][old_j]

    b = [''.join(row) for row in b]

    if not ok(b):
        print("NO")
        return

    print("YES")
    for row in b:
        print(row)

if __name__ == "__main__":
    solve()
```列のみが置換可能であるため、この解決策はまず問題を列空間に置き換えます。 列を辞書編集的にソートすると、同様の行パターンを持つ列が隣接することが保証されます。これは、行内に連続したブロックを形成するための重要な構造要件です。 

検証ステップが必要なのは、並べ替えだけではすべての理論的ケースにおいて正しさが正式に保証されるわけではなく、構築された配置がすべての行の連続する 1 つの特性を実際に満たすことを保証するためです。 

一般的な実装の落とし穴は、再構築中に行優先インデックスと列優先インデックスを混合することです。 もう 1 つは、ソートの安定性のためにタプルを適切に変換することを忘れていることです。 スキャン チェックでは、1 ブロックの開始後に 0 が出現すると、それ以上 1 が許可されないことを確認する必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、複数の列が同一である場合です。 その状況では、それらの間のあらゆる順列が有効であり、アルゴリズムは安定した並べ替え動作に依存してはなりません。 辞書編集的ソートでは同一の列がグループ化され、列を交換しても行構造は変更されないため、連続性は自動的に保持されます。 

もう 1 つの特殊なケースは、1 のない行です。 このような行は、列の順序に関係なく常に有効です。 検証中、スキャンは決して「1 ブロック」に入らないため、誤って失敗を引き起こすことはありません。 

最後のエッジケースは、行が完全に 1 で構成されている場合です。 この行も常に有効ですが、順序付けに追加の制約は強制されません。 どの順列においても行全体がすでに単一の連続セグメントであるため、アルゴリズムはこれを自然に処理します。
