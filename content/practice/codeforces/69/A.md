 ## 解決策
 ## 問題の理解

 3 次元空間内の物体に作用するいくつかの力のベクトルが与えられます。 各ベクトルには、x 軸、y 軸、z 軸に沿った効果という 3 つのコンポーネントがあります。 

物体に作用するすべての方向の力の合計がゼロの場合にのみ、物体は平衡状態にあります。 つまり:

 - すべての x 成分の合計は 0 でなければなりません
 - すべての y 成分の合計は 0 でなければなりません
 - すべての Z 成分の合計は 0 でなければなりません

 タスクは、すべてのベクトルを読み取り、それらの座標を個別に追加し、3 つの合計がすべて 0 であるかどうかを確認するだけです。 存在する場合は、印刷します`"YES"`。 それ以外の場合は、印刷します`"NO"`。 

制約は非常に小さいです。 最大 100 個のベクトルが指定され、各座標は -100 ～ 100 の範囲になります。非効率な解決策であっても、簡単に制限内に収まります。 1 つの軸に沿った最大の絶対和は 100 × 100 = 10000 のみであるため、通常の整数演算は完全に安全です。 

主な課題はパフォーマンスではなく、物理条件をコードに正しく変換することです。 よくある間違いは、各ベクトルが個別に等しいかどうかを確認することです。`(0,0,0)`。 それは必須ではありません。 ゼロ以外のベクトルは互いに打ち消し合う可能性があります。 

例えば：```
2
1 2 3
-1 -2 -3
```正しい出力は次のとおりです。```
YES
```総力は`(0,0,0)`どちらのベクトルもゼロではないにもかかわらず。 

もう 1 つの微妙なケースは、1 つの軸だけがバランスをとる場合です。```
3
1 0 0
-1 5 0
0 -3 0
```X 軸の合計は 0 になりますが、Y 軸の合計は 2 になります。正しい出力は次のとおりです。```
NO
```1 つの座標だけをチェックする不注意な実装は、ここで失敗します。 

最小サイズのケースもあります。```
1
0 0 0
```正しい出力は次のとおりです。```
YES
```ベクトルが 1 つだけの場合、そのベクトル自体がゼロの場合にのみ平衡が起こります。 

## アプローチ

 最も直接的なアプローチはブルートフォースです。 すべてのベクトルを調べ、その座標を累計に加算することで、合計の力を計算することができます。 すべてのベクトルを処理した後、最終的な合計がすべてゼロかどうかを確認します。 

入力サイズが小さいため、これはすでに効率的に機能します。 ベクトルごとに正確に 3 回の加算を実行するため、最悪の場合でも約 300 回の算術演算のみを実行します。 

重要な観察は、平衡はすべての力の結合効果のみに依存し、力の次数や個々の大きさには依存しないということです。 ベクトルの加算は結合的かつ可換的であるため、ベクトルを処理した後にベクトルを保存する必要はありません。 必要なのは 3 つの累計だけです。 

これにより、問題は次のメンテナンスに軽減されます。```
sum_x
sum_y
sum_z
```それぞれのベクトルを読み取っていくと、`(x, y, z)`、これらの合計を更新します。 最後に:

 - 3 つの合計がすべてゼロの場合、身体のバランスは取れています。 
- そうしないと、正味の力がいくらか残るため、体が動いてしまいます。 

ここでは総当たりアプローチと最適アプローチは似ているように見えますが、重要な最適化は、一定の追加メモリと入力の 1 回のパスのみが必要であることを認識することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、力ベクトルの数。 
2. 3 つの変数を初期化します。`sum_x = 0`、`sum_y = 0`、 そして`sum_z = 0`。 

これらの変数は、各軸に沿って蓄積された合計の力を表します。 
3. 繰り返します`n`回:

 - 1 つのベクトルを読み取ります`(x, y, z)`。 
- 追加`x`に`sum_x`。 
- 追加`y`に`sum_y`。 
- 追加`z`に`sum_z`。 

各ベクトルは、すべての軸に沿った正味の力に独立して寄与します。 
4. すべてのベクトルを処理した後、3 つの合計がすべて 0 に等しいかどうかを確認します。 

物体は、どの方向にも力が残っていない場合にのみ平衡状態にあります。 
5. 印刷`"YES"`すべての合計がゼロの場合。 それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 アルゴリズムは、最初の処理後の不変条件を維持します。`i`ベクトル、変数`sum_x`、`sum_y`、 そして`sum_z`それらによって寄与される力の合計に等しい`i`各軸に沿ったベクトル。 

ベクトルの加算はコンポーネントごとに機能するため、全体的な正味の力は次のようになります。$$\left(\sum x_i,\ \sum y_i,\ \sum z_i\right)$$この結果のベクトルが以下に等しいとき、物体は正確に平衡状態にあります。`(0,0,0)`。 アルゴリズムはこれらの合計を正しく計算するため、最終チェックでは常に正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

sum_x = 0
sum_y = 0
sum_z = 0

for _ in range(n):
    x, y, z = map(int, input().split())

    sum_x += x
    sum_y += y
    sum_z += z

if sum_x == 0 and sum_y == 0 and sum_z == 0:
    print("YES")
else:
    print("NO")
```プログラムはベクトルの数を読み取ることから始まります。 3 つのアキュムレータ変数は、各軸に沿った合計の力を追跡するために初期化されます。 

ループ内で、各ベクトルが読み取られ、即座に累計に追加されます。 累積和のみが重要であるため、ベクトルを保存する必要はありません。 

最後の条件では、3 つの座標すべてを同時にチェックします。 平衡には 1 つの座標だけではなく、ベクトル全体の合計がゼロであることが必要であるため、これは重要です。 

整数オーバーフローは Python では問題になりませんが、固定幅言語でも制限は標準の整数型内に快適に収まるほど十分に小さいです。 

この実装により、不必要なデータ構造も回避されます。 定数メモリを使用すると、解が単純になり、平衡の数学的定義と直接一致するようになります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    sx = sy = sz = 0

    for _ in range(n):
        x, y, z = map(int, input().split())
        sx += x
        sy += y
        sz += z

    if sx == 0 and sy == 0 and sz == 0:
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run(
"""3
4 1 7
-2 4 -1
1 -5 -3
"""
) == "NO\n", "sample 1"

# minimum-size equilibrium
assert run(
"""1
0 0 0
"""
) == "YES\n", "single zero vector"

# minimum-size non-equilibrium
assert run(
"""1
5 -3 2
"""
) == "NO\n", "single nonzero vector"

# vectors cancel each other
assert run(
"""2
1 2 3
-1 -2 -3
"""
) == "YES\n", "perfect cancellation"

# only one axis unbalanced
assert run(
"""3
1 0 0
-1 5 0
0 -3 0
"""
) == "NO\n", "y-axis remains nonzero"

# boundary values
assert run(
"""2
100 100 100
-100 -100 -100
"""
) == "YES\n", "boundary coordinate values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | シングル`(0,0,0)`ベクトル | はい | 最小サイズの平衡ケース |
 | 単一の非ゼロベクトル | いいえ | 最小サイズの非平衡 |
 | 2 つの相反するベクトル | はい | すべての軸にわたるキャンセル |
 | 1 つの軸はゼロ以外のままです | いいえ | 3 つの座標はすべてバランスが取れている必要があります |
 | 境界座標値 | はい | 極端な入力の正しい処理 |
