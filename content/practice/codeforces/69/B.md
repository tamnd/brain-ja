 ## 解決策
 ## 問題の理解

 各アスリートは、連続したセクションの間隔を走ります。 アスリートがセクション内にいる間、彼らは正確に費やします`t[i]`したがって、セクションの勝者は単純に、最小の記録を持ったアクティブなアスリートです。`t`。 複数のアスリートが同じタイムを持っている場合、指数が小さい方が勝ちます。 

セクションごとに最大 1 回の賭けを行うことができ、そのセクションを実際に走る選手にのみ賭けることができます。 セクション優勝者に賭けた場合、その選手の報酬を獲得します`c[i]`。 セクションは独立しているため、タスクは次のようになります。 

セクションごとに、どのアスリートがそこで勝ったかを決定し、そのアスリートの利益を加算します。 

制約は小さく、最大 100 セクションと 100 名のアスリートのみです。 たとえ`O(n * m^2)`最悪のケースでも 100 万回程度の操作しかないため、ソリューションは問題なく通過するでしょう。 これは、複雑なデータ構造やスイープラインの最適化が必要ないことを意味します。 直接シミュレーションするだけで十分です。 

難しいのはパフォーマンスではなく、勝者のルールを正しく実装することです。 

簡単な間違いの 1 つは、インデックスによるタイブレーク ルールを忘れることです。 

考慮する：```
3 2
1 3 5 10
1 3 5 20
```両選手はどこでも同じスピードを発揮します。 アスリート 1 はインデックスが小さいため、すべてのセクションで優勝します。そのため、答えは次のようになります。```
30
```公式の勝者の代わりにより大きな報酬を選択する不注意な実装では、誤った出力が発生します。`60`。 

もう 1 つの微妙なケースは、選手がいないセクションです。```
5 1
2 4 3 10
```セクション 1 と 5 には参加者がいないため、賭けても勝つことはできません。 利益に貢献するのはセクション 2、3、4 だけです。 正しい答えは次のとおりです。```
30
```すべてのセクションに常に勝者がいると想定した実装では、無効なデータにアクセスしたり、余分な利益をカウントしたりする可能性があります。 

3 番目のよくあるバグは、セクションごとの時間ではなく総レース時間をチェックすることです。```
4 2
1 4 10 5
2 2 1 100
```アスリート 2 はセクション 2 にのみ登場しますが、そこでははるかに速く、そのセクションで優勝します。 正しい合計は次のとおりです。 

セクション 1 -> アスリート 1、ゲイン 5

 セクション 2 -> アスリート 2、100 を獲得

 セクション 3 と 4 -> アスリート 1、それぞれ 5 を獲得

 合計:```
115
```レース期間全体は関係ありません。 セクションごとの時間のみ`t[i]`各セクション内の事項。 

## アプローチ

 最も直接的なアプローチは、すべてのセクションを個別に処理することです。 固定セクションの場合、すべてのアスリートをスキャンし、間隔がこのセクションをカバーする選手のみを保持します。 現役アスリートの中でも最も小さい選手を選出`t`。 複数のアスリートが同じものを共有する場合`t`、小さい方のインデックスを選択します。 次に、そのアスリートの報酬を答えに追加します。 

この強引なアイデアはすでに十分に高速です。 最大で 100 セクション、100 人の選手が存在するため、最大で 10,000 人の選手チェックを実行します。 タイブレークのために追加の比較を追加したとしても、実行時間は無視できます。 

この単純な方法が機能する理由は、問題にセクション間の相互作用がないためです。 あるセクションに賭けても、別のセクションには影響しません。 セクションの勝者が判明したら、その勝者に賭けて報酬を受け取るという最適な選択が迫られます。 他の誰かに賭ける理由は決してありません。 

より複雑な解釈は、アスリートがさまざまなセクションを占有するため、動的プログラミングまたはインターバル処理を示唆する可能性があります。 しかし、重要な観察は、勝者はセクションごとにローカルに決定されるということです。 インターバルは、アスリートがセクションに参加しているかどうかのみを示します。 

このアルゴリズムはレースのタイムラインをシミュレートするものと考えることができます。 各セクションについて:

 1. すべての現役アスリートを検索します。 
2. 最速のものを選択します。 
3. 報酬を追加します。 

それが解決策全体です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | お(1) | 承認済み |
 | 最適 | O(n * m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セクションと選手の数を読み取ります。 
2. すべてのアスリートをタプルとして保存します`(l, r, t, c)`。 
3. 以下のすべてのセクションを繰り返します。`1`に`n`。 
4. 現在のセクションについて、すべてのアスリートをスキャンし、アスリートがそこでアクティブであるかどうかを確認します。`l <= section <= r`。 
5. すべての現役アスリートの中で、次のようなアスリートを保持してください。 

1. 最小のもの`t`2. 時間が同じ場合、最小のアスリート指数

 これはレースルールに完全に一致します。 
6. 少なくとも 1 人のアスリートがこのセクションでアクティブな場合、その勝者の報酬を追加します`c`答えに。 
7. すべてのセクションを処理した後、合計利益を出力します。 

### なぜ効果があるのか

 すべてのセクションの結果は、他のすべてのセクションから完全に独立しています。 公式勝者は、セクションの最小タイムとインデックスのタイブレーク ルールによって一意に決定されます。 

勝者以外の誰かに賭けた場合、そのセクションからの利益はゼロになります。 勝者に賭けると正確に結果が得られます`c[i]`。 異なるセクションを接続する制限がないため、セクションごとに独立して勝者を選択することで、総利益が最大化されます。 

アルゴリズムは各セクションの正式な勝者を明示的に計算するため、生成される合計は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

athletes = []
for _ in range(m):
    l, r, t, c = map(int, input().split())
    athletes.append((l, r, t, c))

answer = 0

for section in range(1, n + 1):
    best_time = float('inf')
    best_index = -1

    for idx, (l, r, t, c) in enumerate(athletes):
        if l <= section <= r:
            if t < best_time:
                best_time = t
                best_index = idx
            elif t == best_time and idx < best_index:
                best_index = idx

    if best_index != -1:
        answer += athletes[best_index][3]

print(answer)
```プログラムは、すべてのアスリートをインターバル、スピード、報酬とともに保存します。 

外側のループはセクションを 1 つずつ処理します。 セクションごとに、優勝した選手を検索します。`best_time`これまでに確認された最小セクションタイムを追跡しますが、`best_index`どの選手が現在タイブレークに勝っているかを保存します。 

条件`l <= section <= r`アスリートがこのセクションに参加するかどうかを決定します。 現役アスリートのみが対象となります。 

タイブレークのロジックは注目に値します。 2 人のアスリートが同等の能力を持っていると仮定します。`t`。 ルールでは、アスリート指数が小さい方が勝つとされています。 Python のインデックスはゼロから始まり、入力の番号付けは実質的に挿入順序に従うため、比較`idx`公式ルールを正確に再現しています。 

小切手`best_index != -1`空のセクションを安全に処理します。 現在のセクションを担当するアスリートがいない場合、報酬は追加されません。 

制約が小さいため、前処理や並べ替えは必要ありません。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    athletes = []
    for _ in range(m):
        l, r, t, c = map(int, input().split())
        athletes.append((l, r, t, c))

    ans = 0

    for section in range(1, n + 1):
        best_time = float('inf')
        best_idx = -1

        for idx, (l, r, t, c) in enumerate(athletes):
            if l <= section <= r:
                if t < best_time:
                    best_time = t
                    best_idx = idx
                elif t == best_time and idx < best_idx:
                    best_idx = idx

        if best_idx != -1:
            ans += athletes[best_idx][3]

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

assert run(

1 4 20 5
1 3 21 10
3 3 4 30
3 4 4 20
"""

"""

# all athletes equal

 ## 特殊なケース

 同等の速度で異なる報酬を考慮します。```
3 2
1 3 5 10
1 3 5 20
```どのセクションでも、両方のアスリートがアクティブであり、両方とも時間があります`5`。 アルゴリズムはインデックスを比較し、常にアスリート 1 を選択します。合計は次のようになります。`10 + 10 + 10 = 30`。 

より大きな報酬を貪欲に選択するバグのあるソリューションでは、誤って出力されます。`60`。 

ここで空のセクションを考えてみましょう。```
5 1
2 4 3 10
```アルゴリズムは各セクションを独立して処理します。 

セクション 1:

 現役アスリートもいないし、何も加えられていない。 

セクション 2、3、4:

 アスリート 1 が勝ち、追加`10`毎回。 

セクション 5:

 現役選手はもういない。 

最終的な答え:```
30
```の`best_index != -1`チェックにより、存在しない勝者に利益が追加されるのを防ぎます。 

最後に、わずかな間隔で速いアスリートを考えてみましょう。```
4 2
1 4 10 5
2 2 1 100
```アルゴリズムはセクションごとにアクティビティをチェックします。 

| セクション | 勝者 | 合計 |
 | --- | --- | --- |
 | 1 | アスリート 1 | 5 |
 | 2 | アスリート 2 | 105 |
 | 3 | アスリート 1 | 110 |
 | 4 | アスリート 1 | 115 |

 これにより、勝者はレースの合計期間やインターバルの長さではなく、現在のセクションのみに依存することがわかります。
