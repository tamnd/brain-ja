 ## 解決策
 ## 問題の理解

 平面上の座標点から始めます`(x, y)`。 プレイヤーは交互にターンを行い、各ターンで 2 つのことのうち 1 つを行うことができます。 

指定された移動ベクトルの 1 つを現在の位置に追加する場合があります。 すべてのベクトルには負ではない座標があるため、通常の移動ごとにポイントが第 1 象限のさらに奥へ押し込まれます。 

また、線を越えた点を反映する特別な操作を使用することもあります。`y = x`、単純に座標を交換します。 このリフレクションは、ゲーム全体を通じて各プレイヤーが最大 1 回使用できます。 

プレイヤーが移動した後、原点からのポイントの距離が厳密に次の値よりも大きくなった場合、`d`、そのプレイヤーはすぐに負けます。 ゲームは最適にプレイされ、最初のプレイヤーであるアントンが勝利する戦略を持っているかどうかを判断する必要があります。 

重要な詳細は、移動が行われた後に負けがチェックされることです。 サークルから抜け出す行為は合法ですが、自殺行為です。 

制約は十分小さいため、ゲーム状態グラフを直接探索できます。 座標は以下から始まります`[-200, 200]`、すべてのベクトル成分は最大でも`200`、 そして`d ≤ 200`。 点が半径の円から離れるとすぐにゲームが終了するため、`d`、すべての意味のある状態は満たさなければなりません`x² + y² ≤ d²`。 これにより、到達可能なボード位置の数は、半径 200 の円内の格子点の数にほぼ制限され、これは最悪でも約 125,000 州になります。 

リフレクション操作により、余分な状態が導入されます。 各プレイヤーがすでにその反省を活かしているかどうかが、今後の動きに影響を及ぼします。 これにより、4 つの反射構成が得られます。`(Anton used?, Dasha used?)`したがって、完全な状態空間は依然として管理可能です。`~125000 * 4`各州が試みるのは最大でも`n + 1`どこに移動するか`n ≤ 20`。 

同じ位置が何度も再訪される可能性があるため、メモ化のない単純な再帰検索は爆発的に発生します。 リフレクションはすぐにサイクルを生み出すこともできます。 例えば：```
0 0 1 5
1 2
```ポイントが到達したとします`(1, 2)`。 一人のプレイヤーが反省できるのは、`(2, 1)`、そしてもう一方はに反映することができます`(1, 2)`。 メモ化やサイクル処理のない DFS は永久に再帰的に発生します。 

もう 1 つの微妙なケースは、次の場合にリフレクションが何も行われないことです。`x = y`。 選手が反省したら`(3, 3)`、ポイントは残ります`(3, 3)`, ただし、プレイヤーの反射特権は消費されます。 「変更されていない」状態をスキップする不注意な実装では、誤って無限反射が許可されてしまいます。 

3 番目の罠は、境界線を越えると、移動したプレイヤーが即座に負けることを忘れてしまうことです。 考慮する：```
0 0 1 2
2 2
```唯一の動きは、`(2, 2)`、その距離は`√8 > 2`。 アントンは即敗なので正解は`"Dasha"`。 このような手を失うのではなく、使用できないものとして扱うと、ゲームの結果が変わります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべてのゲーム構成をゲーム グラフ内のノードとして扱い、勝ちか負けかを再帰的に判断します。 少なくとも 1 つの手が相手の負け状態につながる場合、その状態は勝利したことになります。 そうでなければ負けです。 

問題は、反射により座標が前後に交換される可能性があるため、ゲーム グラフにサイクルが含まれていることです。 メモ化のない純粋な再帰的​​ミニマックスは、同じ状態を繰り返し再計算します。 さらに悪いことに、サイクル検出のない DFS は無限に再帰する可能性があります。 

状態をメモ化するとします。 これにより、繰り返しの作業がなくなりましたが、それでもサイクルを正しく処理する必要があります。 幸いなことに、このゲームには非常に便利な特性があります。すべてのベクトル成分が負でもゼロでもないため、法線ベクトルの移動は常に座標を増加させます。 座標を再配置できる操作はリフレクションのみであり、各プレイヤーは 1 回のみ使用できます。 利用できる反射は合計で 2 つだけであるため、サイクルは非常に限られています。 

この観察により、ゲーム グラフは有限有向グラフに変わり、DFS メモ化と訪問状態を備えた標準ゲーム DP を使用してすべての状態を解決できます。 

状態は次のもので構成されます。`(current_x, current_y, anton_used_reflect, dasha_used_reflect, turn)`状態から、すべてのベクトル移動を試みますが、現在のプレーヤーがまだ利用可能な場合は反射移動も試行します。 

If a move immediately exits the circle, that move is losing for the current player, so we simply ignore it when searching for winning continuations. 何らかの合法的な動きによって相手を負けの状態に追い込むと、その状態は勝利になります。 

到達可能な状態の総数は、メモ化された DFS が制限内で快適に終了できるほど十分に小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(S × n) | O(S) | 承認済み |

 ここ`S`円内の到達可能な状態の数とリフレクション構成の積です。 

## アルゴリズムのチュートリアル

 1. ゲームの状態を次のように定義します。`(x, y, a, b, t)`ここ`x, y`は現在の座標、`a`アントンがすでにリフレクションを使用しているかどうかを示します。`b`Dasha がすでにリフレクションを使用しているかどうかを示します。`t`誰の番ですか。 
2. DFS をメモ化とともに使用して、状態が勝利しているかどうかを判断します。 

現在のプレイヤーが対戦相手を強制的に負け状態に追い込むような動きを少なくとも 1 つ行うことができた場合、その状態は勝利したことになります。 
3. あらゆる動きベクトルに対して`(dx, dy)`、次を計算します。`(nx, ny) = (x + dx, y + dy)`もし`nx² + ny² > d²`、この動きはすぐに負けるのでスキップします。 

それ以外の場合は、この移動後の対戦相手の状態を再帰的に評価します。 
4. 反射を個別に処理します。 

現在のプレーヤーがまだリフレクションを使用していない場合は、次のステップに進むことができます。`(y, x)`そしてリフレクション特権を消費します。 

反射は、反射された位置が円の内側に留まる場合にのみ正当です。 
5. 正当な手によって対戦相手の負け状態が生じた場合、現在の状態を勝ちとしてマークします。 
6. すべての正当な手が相手の勝利状態につながる場合、現在の状態を負けとしてマークします。 
7. 両方の反射権限を使用せず、アントンのターンで初期位置から DFS を開始します。 
8. 印刷`"Anton"`初期状態が勝利の場合、それ以外の場合は出力します`"Dasha"`。 

### なぜ効果があるのか

 DFS は、完全な情報を備えた公平な 2 人用ゲームの標準定義に従って状態を評価します。 

すべての再帰的遷移は 1 つの正当な動きを表します。 現在のプレイヤーが相手が負ける状態に移行できる場合、その手を選択することで現在のプレイヤーが勝ちます。 すべての手が相手に勝利の位置を与えた場合、現在のプレイヤーは選択に関係なく負けます。 

メモ化により、すべての状態が一貫して 1 回だけ解決されることが保証されます。 ベクトルの移動によって座標が減少することはなく、各プレイヤーは一度だけ反映できるため、到達可能なゲーム グラフは有限です。 再帰は最終的に終了し、到達可能なすべての状態を正しく分類します。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

x, y, n, d = map(int, input().split())
vectors = [tuple(map(int, input().split())) for _ in range(n)]

limit = d * d

@lru_cache(None)
def dfs(x, y, a_used, b_used, turn):
    for dx, dy in vectors:
        nx = x + dx
        ny = y + dy

        if nx * nx + ny * ny > limit:
            continue

        if not dfs(
            nx,
            ny,
            a_used,
            b_used,
            turn ^ 1
        ):
            return True

    if turn == 0:
        if not a_used:
            nx, ny = y, x

            if nx * nx + ny * ny <= limit:
                if not dfs(nx, ny, 1, b_used, 1):
                    return True
    else:
        if not b_used:
            nx, ny = y, x

            if nx * nx + ny * ny <= limit:
                if not dfs(nx, ny, a_used, 1, 0):
                    return True

    return False

ans = dfs(x, y, 0, 0, 0)

print("Anton" if ans else "Dasha")
```再帰関数は、現在の状態がそのターンのプレイヤーの勝利かどうかを返します。 

メモ化デコレーターは必須です。 これがなければ、特に反射により以前の座標ペアを再訪する可能性があるため、同じ状態が繰り返し探索されることになります。 

実装では、自殺行為は慎重に扱われます。 手がサークルから出た場合、現在のプレイヤーがそれを選択するとすぐに負けてしまうため、その手は完全にスキップされます。 円の内側に残る移動のみが再帰呼び出しを生成します。 

反映ロジックは、誰の順番になるかによって異なります。 アントンのリフレクションの使用とダーシャのリフレクションの使用は個別に追跡されます。 各プレイヤーはゲーム全体で 1 回だけ反映する可能性があるため、これは重要です。 

ターン変数は次のように表されます。`0`アントンと`1`ダーシャのために。 ターンを切り替える`turn ^ 1`トランジションをコンパクトに保ち、分岐の間違いを防ぎます。 

微妙なディテールが反映されています`(x, y)`の中へ`(y, x)`座標が等しい場合でも許可されます。 反映権限が消費されるため状態が変化します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S × n) | 各状態はすべてのベクトルとおそらく 1 つの反射を試みます。 
| スペース | O(S) | メモ化は、到達可能なすべての状態を一度保存​​します。`S`は、円内の格子点の数に反射構成とターン状態を乗算した値によって制限されます。 と`d ≤ 200`、合計状態数は Python の実用的な制限内に十分収まります。

# helper: run solution on input string, return output string
import sys
import io
from functools import lru_cache

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    x, y, n, d = map(int, input().split())
    vectors = [tuple(map(int, input().split())) for _ in range(n)]

    limit = d * d

    @lru_cache(None)
    def dfs(x, y, a_used, b_used, turn):
        for dx, dy in vectors:
            nx = x + dx
            ny = y + dy

            if nx * nx + ny * ny > limit:
                continue

            if not dfs(nx, ny, a_used, b_used, turn ^ 1):
                return True

        if turn == 0:
            if not a_used:
                nx, ny = y, x

                if nx * nx + ny * ny <= limit:
                    if not dfs(nx, ny, 1, b_used, 1):
                        return True
        else:
            if not b_used:
                nx, ny = y, x

                if nx * nx + ny * ny <= limit:
                    if not dfs(nx, ny, a_used, 1, 0):
                        return True

        return False

    return "Anton\n" if dfs(x, y, 0, 0, 0) else "Dasha\n"

# provided sample
assert run(
"""0 0 2 3
1 1
1 2
"""
) == "Anton\n", "sample 1"

# immediate losing move
assert run(
"""0 0 1 2
2 2
"""
) == "Dasha\n", "crossing boundary immediately"

# reflection with equal coordinates
assert run(
"""1 1 1 3
1 0
"""
) in ("Anton\n", "Dasha\n"), "reflection must consume usage even when unchanged"

# minimal input
assert run(
"""0 0 1 1
1 0
"""
) == "Anton\n", "single safe move"

# cycle through reflections
assert run(
"""0 0 1 5
1 2
"""
) in ("Anton\n", "Dasha\n"), "reflection cycles handled safely"

 ## 特殊なケース

 唯一の利用可能な手がサークルからすぐに出た場合を考えてみましょう。```
0 0 1 2
2 2
```その動きは`(2,2)`距離の二乗で`8 > 4`。 DFS は自殺行為であるため、この動きをスキップします。 法的な勝ち手は存在しないため、初期状態は負けです。 アルゴリズムは正しく印刷します`"Dasha"`。 

ここで、等しい座標での鏡映を考えてみましょう。```
1 1 1 3
1 0
```反射する`(1,1)`座標は変更されませんが、反映権限が消費されます。 DFS の扱い`(1,1,a_used,b_used)`そして`(1,1,1,b_used)`異なる状態として。 これにより、不正な繰り返し反射が防止されます。 

最後に、反射サイクルについて考えてみましょう。```
0 0 1 5
1 2
```ポジション`(1,2)`そして`(2,1)`反射によって交互に変化する可能性があります。 メモ化がなければ、DFS は永久に再帰する可能性があります。 アルゴリズムは解決されたすべての状態を保存するため、1 つの構成が計算されると、その後のアクセスは即座に戻ります。
