 ## 解決策
 ## 問題の理解

 店舗のフロアプランを表す長方形のグリッドが与えられています。 各セルには、決定的な指示のように機能する方向文字が含まれています。つまり、顧客がそのセルの上に立つと、矢印に従って北、南、東、西に 1 歩ずつ移動します。 店内にはグリッドの内側に壁はないが、グリッドを離れるということは店から出ることを意味する。 

すべてのセルから出ていく移動が 1 つだけあるため、グリッド全体は、すべてのノードの出次数が 1 である有向グラフになります。顧客は任意のセルから開始して、グリッドから外れるか、グリッド内で永遠に移動し続けるまで、これらの矢印を繰り返したどります。 

タスクは、顧客がグリッドから離れることを決して許可しない開始セルの数を数えることです。 グラフの用語では、有向パスが境界出口に決して到達しないノードの数が必要です。これは、パスが最終的に完全にグリッド内に留まるサイクルに入らなければならないことを意味します。 

グリッド サイズは 2000 × 2000 まで大きくでき、最大 400 万ノードになります。 各開始セルを個別にシミュレートし、終了まで実行するソリューションでは、多くのノードが繰り返し再利用され、最悪の場合は 2 次の動作に低下する可能性があり、これは非常に遅すぎます。 目的のソリューションでは、各セルが一定回数処理されるようにする必要があります。 

グリッド全体が単一の大きなサイクルを形成する場合、微妙なエッジケースが現れます。 その場合、すべてのセルがカウントされます。 もう 1 つのエッジ ケースは、すべての矢印が境界付近で外側を向いており、多くのセルからの即時終了が発生するため、ほとんどのノードが除外される場合です。 出口への到達可能性をマークせずにサイクルのみをチェックする単純なアプローチでは、長いチェーンの後に最終的にグリッドから流出するノードを誤ってカウントする可能性があります。 

## アプローチ

 直接シミュレーションのアプローチは、各セルから開始され、グリッドから出るか、以前に確認されたセルが検出されるまで、繰り返し方向に従います。 各パスは決定的であるため、これは概念的には単純です。 各パスを独立して通過する余裕がある場合、正確性は簡単です。単に歩行が逃げるかどうかに基づいて、各スタートを安全か安全でないかに分類するだけです。 

問題は、パスが重なり合うことです。 単一のセルが多くの開始パスの一部になる可能性があり、結果をキャッシュせずに長いチェーンを何度も再計算します。 最悪の場合、すべてのパスがループする前に長い廊下に合流する、長い蛇のような形のグリッドを考えてみましょう。 各開始セルは構造のほぼ全体を横断する可能性があり、開始ごとに O(NM) 個の作業が生成され、合計の複雑さは O((NM)^2) になります。 

重要な観察は、この構造が関数グラフであるということです。これは、すべてのノードが出力エッジを 1 つだけ持つことを意味します。 このようなグラフでは、すべてのノードがサイクルに入るか、最終的に最終結果 (ここではグリッドから出る) に流れ込みます。 視点を逆にすると、すべてのノードから順方向にシミュレーションするのではなく、出口遷移である既知の負け状態から逆方向に情報を伝播できます。 ただし、出口はグラフ内のノードではないため、代わりにグリッドの外に出る移動をターミナルの負け状態として扱い、そこから逆方向に伝播します。 

外部につながることが保証されているノードを追跡することで、これをモデル化できます。 次のステップが外部に出るノードは直ちに安全ではなくなります。 次に、ノードの次の状態が安全でない場合、そのノードも安全ではありません。 これは関数グラフにおける標準的な逆伝播であり、メモ化または状態 (未訪問、訪問中、安全に終了、トラップ) による反復処理を備えた DFS を使用して実行できます。 

最終的な数は、単に出口に到達したとマークされていないノードの数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((NM)^2) | O(NM) | 遅すぎる |
 | メモ化を使用した DFS | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

各セルは、外側を向いていない限り、1 つの出力エッジを持つ有向グラフ内のノードとして扱います。 

1. すべてのセルに対して、このセルから開始するとグリッドの外側につながるかどうかを決定する再帰関数を定義します。 

パスが最終的にグリッドから離れる場合、この関数は true を返します。 
2. 未訪問、訪問中、ブール結果の訪問済みの 3 つの値を持つ状態配列を維持します。 

これにより、再計算が防止され、トラバーサル中のサイクルも検出されます。 
3. セルに入ると、すぐにその方向に基づいて次の位置を計算します。 

次の位置がグリッドの外側にある場合、現在のセルを終了可能としてマークし、true を返します。 
4. 次の位置がグリッド内にあり、すでに計算されている場合は、その保存された結果を再利用します。 

これは、繰り返されるパス探索を一定時間のルックアップにまとめる重要な最適化です。 
5. 次の位置が現在訪問されている場合、サイクルが見つかりました。 

私たちはグリッドから抜け出すことができるかどうかを判断しようとしているため、サイクルだけではグリッドから抜け出すことが保証されません。 これは、このパスから抜け出すことにはつながらないものとして扱います。 
6. ノードの結果を計算した後、それを保存して呼び出し元に返し、すべての着信パスで再利用できるようにします。 
7. 最後に、DFS の結果が出口に到達しないことを示すすべてのセルをカウントします。 

### なぜ効果があるのか

 すべてのセルには出力エッジが 1 つだけあるため、グリッドは有向グラフを形成します。このグラフでは、各コンポーネントがサイクルに入るツリーか、外部につながるチェーンのいずれかになります。 メモ化を伴う DFS は、後続ノードのみに基づいて最終的なブール値を各ノードに割り当てます。 結果はキャッシュされるため、ノードが分類されると、そこに到達するすべてのパスは同じ分類を継承します。 サイクルに関与するノードは最終的に「訪問」状態に戻り、無限再帰を防ぎ、サイクルが出口に接続しない限り非出口として分類されるようにするため、サイクルは一貫して処理されます。これはグリッド内に限定されたサイクルの定義では不可能です。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

N, M = map(int, input().split())
grid = [input().strip() for _ in range(N)]

# 0 = unvisited, 1 = visiting, 2 = done
# exit[i][j] = True if starting here eventually leaves grid
state = [[0] * M for _ in range(N)]
exit_reachable = [[False] * M for _ in range(N)]

dirs = {
    'N': (-1, 0),
    'S': (1, 0),
    'W': (0, -1),
    'E': (0, 1)
}

def dfs(r, c):
    if state[r][c] == 2:
        return exit_reachable[r][c]
    if state[r][c] == 1:
        return False

    state[r][c] = 1
    dr, dc = dirs[grid[r][c]]
    nr, nc = r + dr, c + dc

    if nr < 0 or nr >= N or nc < 0 or nc >= M:
        exit_reachable[r][c] = True
        state[r][c] = 2
        return True

    res = dfs(nr, nc)
    exit_reachable[r][c] = res
    state[r][c] = 2
    return res

total_escape = 0
for i in range(N):
    for j in range(M):
        if dfs(i, j):
            total_escape += 1

print(N * M - total_escape)
```このソリューションでは、グリッド セル上のメモ化を備えた DFS を使用します。 各セルは、一度その状態が「完了」になると再計算されないため、意味のある方法でアクセスされるのは多くても 1 回だけです。 再帰は、グリッド文字によって定義された有向エッジに従います。 境界チェックは、次のセルを計算した直後に処理されます。これは重要です。境界をチェックする前に再帰を試みると、インデックス エラーや不正な状態の伝播が発生する可能性があるためです。 

サイクルの検出は「訪問」マーカーに依存します。 現在再帰中のノードに再入すると、停止して False を返します。これは、そのパスを通って出口に到達しないことを意味します。 すべてのノードには出力エッジが 1 つだけあるため、サイクルに遭遇すると、出口に接続しない限り、パスがそのサイクル内に閉じ込められることを意味します。サイクル内に完全に入ってしまえば、出口に接続することはできません。 

## 実用的な例

 ### 例 1

 入力:```
3 3
SSW
NSE
NWS
```いくつかの代表的な細胞を追跡します。 

| セル | 次の動き | 外につながる？ | 最終結果 |
 | --- | --- | --- | --- |
 | (0,0) | (1,0) | 依存します | DFS 経由で計算 |
 | (1,1) | (1,2) | 内側 | チェーンに従う |
 | (2,2) | (2,1) | 内側 | サイクルに入ります |

 DFS は右下の領域でサイクルを検出します。これは、いくつかのノードがトラップされていることを意味します。 チェーンが最終的に境界出口に到達するノードのみが回答から除外されます。 伝播後、アルゴリズムはすべての非終了ノードをカウントします。 

この例は、局所的な動きが内向きに見える場合でも、全体的な構造が依然としてサイクルを形成する可能性があることを示しています。 

### 例 2

 入力:```
3 4
SWNW
EEEN
NWWW
```ここでは多くの矢印が端に向かって押し出され、頻繁に離脱が発生します。 

| セル | 次へ | 到達可能な出口 |
 | --- | --- | --- |
 | (0,0) | (0,1) | 最終的に終了します |
 | (1,1) | (1,2) | すぐに終了します |
 | (2,3) | 外側 | 即時 |

 DFS は、境界に到達したパスをすぐに true としてマークします。 これは逆方向に伝播するため、エッジにつながるチェーン全体がエスケープ可能としてマークされます。 

これはメモ化効果を示しています。出口パスが判明すると、大きな領域が 1 つの計算結果に折りたたまれます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各セルはメモ化された DFS で 1 回処理され、各エッジは最大 1 回追跡されます。 
| スペース | O(NM) | 状態および再帰スタックはセルごとの情報を保存します。 

グリッドには最大 400 万のノードが含まれており、各ノードはメモ化後に一定の作業を実行します。 これは、高速 I/O と単純な操作で実装された場合、Python の 1 秒の制限内に快適に収まります。

 ## 特殊なケース

 外側を指している単一セルなどの最小限のグリッドは、即時終了の基本ケースを示しています。 DFS は境界チェックの直後に true を返し、セルはエスケープ可能としてカウントされるため、最終的な答えはトラップされたセルがゼロになります。 

「EW」のような 2 セル サイクルは、訪問状態が無限再帰をどのように防ぐかを示しています。 DFS はどちらかのセルから開始してもう一方のセルに入り、訪問ノードへの再訪問を検出して false を返します。 両方のセルがトラップされているとマークされ、正しいカウントが 2 になります。 

2x2 グリッドのフル サイクルは、アルゴリズムが複数の相互接続されたサイクルを処理できるかどうかをテストします。 各セルは最終的にサイクル検出ケースにループバックするため、どのセルも終了としてマークされません。 その結果、4 つのトラップされたセルが得られ、より大きな環状構造にわたる一貫性が確認されました。
