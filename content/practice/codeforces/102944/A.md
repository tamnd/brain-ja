 ## 解決策
 ## 問題の理解

 私たちは、タピオカ ティー ショップへの顧客の到着に関する簡単な毎日の記録を渡されました。 毎日の顧客数があり、顧客数の合計が一定の倍数に達するたびに`k`、その顧客は無料のドリンクを受け取ります。 カウントは 1 日以内に複数の顧客にわたって継続的に行われますが、少なくとも 1 つの倍数かどうかのみを気にする場合は毎日リセットされます。`k`その日のうちに襲われます。 

タスクは、報酬をグローバルにシミュレートすることではなく、毎日を個別に検査し、その日に到着順での順位が で割り切れる顧客が少なくとも 1 人含まれているかどうかを判断することです。`k`。 毎日そのような顧客が少なくとも 1 人いる場合、次のように出力します。`"awesome"`。 それ以外の場合は、そのような顧客が存在しない初日のインデックスを出力します。 

入力サイズが小さい: 両方とも`k`そして`D`顧客数は最大でも 1,000 人、毎日の顧客数は最大でも 2,000 人です。 これにより、リニア スキャンを超える高度なデータ構造や最適化の必要性が即座に排除されます。 総作業量は最大でも約 200 万チェックであるため、単純な 1 日あたりの計算でも問題なく制限内に収まります。 

1 日の日数が以下の場合、微妙なエッジケースが発生します。`k`顧客。 その場合、倍数はありません`k`その範囲内であるため、その日の答えは自動的に「フリードリンクなし」になります。 たとえば、次の場合`k = 10`そして`a_i = 5`、その日は何も貢献しません。 かどうかをチェックするだけの不用意な実装`a_i % k == 0`ちょうど 10、20、30 人の顧客がいることが重要であり、総数の割り算だけではないため、これは不正確です。 

もう 1 つの例外的なケースは次のような場合です。`k = 1`。 すべての顧客に資格があるため、少なくとも 1 人の顧客がいる毎日は成功する必要があり、顧客がゼロの日でも無料ドリンクの生産はゼロであり、そのような日が存在する場合は失敗を意味します。 

## アプローチ

 直接的なアプローチは、毎日をシミュレーションすることです。 特定の日について`i`と`a_i`顧客について、顧客の立場を 1 から 1 まで繰り返します。`a_i`で割り切れる位置があるかどうかを確認します。`k`。 少なくとも 1 つのそのようなポジションが見つかった場合、その日は有効です。 それ以外の場合は無効です。 

これは、問題が整数の存在の確認に帰着するため、機能します。`x`で`[1, a_i]`そのような`x % k == 0`。 ただし、この強引なビューは少し無駄です。たとえ、`k`範囲内に存在します。 

重要な観察は、次の倍数であるということです。`k`ポジションに現れる`k, 2k, 3k, ...`。 したがって、次の場合に限り、1 日に無料のドリンクが含まれます。`a_i >= k`。 一度`a_i`少なくとも`k`、`k`その日の 番目の顧客が存在し、少なくとも 1 杯の無料ドリンクを保証します。 もし`a_i < k`の倍数はありません`k`全然。 

これにより、毎日の比較が 1 回に減り、問題全体がアレイの単純なスキャンに変わります。

 | ブルートフォースシミュレーション | O(D * 最大 a_i) | お(1) | 承認済み |
 | 直接観察 | O(D) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 毎日が条件を満たすかどうかを追跡しながら、毎日 1 つずつ処理します。 

1.読む`k`そして`D`、次に、毎日の顧客数の配列を読み取ります。 これにより、毎日を個別に評価するために必要なすべての情報が得られます。 
2. 毎日について`i`、どうかを確認してください`a_i >= k`。 この条件は、少なくとも 1 つの倍数があるかどうかをキャプチャします。`k`その日の顧客ポジションの中に存在します。 その理由は、最初の適格な顧客は常に、`k`-回目の到着。 
3. もし`a_i < k`、この日には無料のドリンクがないことがすぐにわかり、それ以降の日の処理を停止できます。 出力します`i`最初の失敗の日として。 
4. 失敗せずに一日を終えると、次のように出力されます。`"awesome"`。 

### なぜ効果があるのか

 1 日のうちに、フリードリンクは正確に の倍数の位置で発生します。`k`。 そのような最小の位置は`k`したがって、条件を満たす顧客が存在するかどうかは、その日が少なくとも`k`顧客。 これにより、単調なプロパティが作成されます: 1 回`a_i`十字架`k`、その日の成功は保証されており、以下`k`、成功は不可能です。 毎日が独立しているため、順番にスキャンすると最初の障害が正確に特定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, D = map(int, input().split())
    a = list(map(int, input().split()))

    for i in range(D):
        if a[i] < k:
            print(i + 1)
            return

    print("awesome")

if __name__ == "__main__":
    solve()
```ソリューションはパラメータを読み取り、毎日の顧客数を 1 回繰り返します。 重要な決定は比較です`a[i] < k`、次の倍数かどうかを直接エンコードします。`k`その日のシーケンスに存在します。 早期の返品により、最初の違反日で確実に停止されます。 

よくある間違いは、顧客インデックスをシミュレートしたり、割り算条件をチェックしようとしたりすることです。`a[i]`自体。 正しい解釈は、合計カウントのプロパティではなく、その日のポジションに関するものです。

 ## 特殊なケース

 いつ`k = 1`、すべての顧客は次の倍数です。`k`, したがって、少なくとも 1 人の顧客がいる日は通過します。 アルゴリズムはこれを正しく処理します。`a_i < 1`は次の場合にのみ真です`a_i = 0`、したがって空の日だけが失敗します。 

一日がちょうど終わったとき`k - 1`顧客、の倍数はありません`k`範囲内です。 例えば、`k = 10`そして`a_i = 9`失敗につながります。 小切手`a_i < k`明示的な反復を必要とせずに、この境界を正しくキャプチャします。 

一日がちょうど終わったとき`k`顧客、`k`- 番目の顧客が存在し、成功を保証します。 例えば、`k = 10`、`a_i = 10`位置 10 は 10 の倍数であるため、すぐに成功します。
