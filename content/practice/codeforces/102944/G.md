 ## 解決策
 ## 問題の理解

 線に沿った正の重みの単一の配列が与えられ、各ウサギの家族がどれだけの分娩負荷に貢献しているかを表します。 毎日、この配列の連続したセグメントが与えられるので、そのセグメントを正確に分割する必要があります。$k$連続したグループ。 各グループは 1 台のトラックに割り当てられ、トラックの積載量はグループ内の値の合計になります。 

毎日の目標は、セグメントをどこに分割するかを選択することです。$k$すべての部分の最大合計ができるだけ小さくなるように、連続する部分を調整します。 各クエリの出力は、この最小可能最大セグメント合計です。 

構造は重要です。配列は固定されていますが、各クエリは異なるサブ配列と異なる数のパーティションについて尋ねます。 私たちは、「最大のセグメント合計を最小化するために配列を k 個の部分に分割する」問題を効果的に解決しています。$10^5$回。 

制約があるため、慎重な設計が必要になります。 配列サイズとクエリ数は両方とも最大です。$10^5$、値は最大です$10^9$。 すべてのパーティション ポイントを試行したり、クエリごとに動的プログラミングを試したりするなど、クエリごとに最初から再計算するソリューションは遅すぎます。 平$O(N)$クエリごとにつながる$10^{10}$最悪の場合の運用。 

唯一の実行可能な方向は、範囲合計クエリが高速になるように配列を前処理し、各クエリにほぼ対数時間で応答することです。 

微妙なエッジケースが現れるのは、$k$大きいです。 もし$k \ge (R-L+1)$、すべての要素を分離することができ、答えは単純に範囲内の最大の要素になります。 単純な貪欲なパーティショニング ルーチンは、空のセグメントを強制したりカットのカウントを間違えたりして、誤ってより大きな値を返してはなりません。 

もう 1 つの特殊なケースは、すべての値が同一である場合です。 正しいソリューションは常にその値を返す必要があり、パーティションの非効率性やバイナリ検索の境界が間違っているために増大した値ではありません。 

## アプローチ

 1 つのクエリに対する直接的なアプローチは、すべての配置方法を試すことです。$k-1$セグメント内の点をカットします。 これは、パーティションを選択して最大セグメント合計を計算することと同じです。 方法の数は組み合わせによって増加します。具体的には、$\binom{n}{k}$セグメントの長さの場合$n = R-L+1$、たとえ小規模であっても完全に実行不可能です。$n$。 

より構造化された動的プログラミングのアプローチでは、次のように定義されます。$dp[i][j]$最初のパーティション化時の最小可能な最大セグメント合計として$i$要素を$j$部品。 移行するには、以前のすべての分割ポイントを試す必要があるため、$O(n^2 k)$クエリごとに、これもまた遅すぎます。 

重要な観察は、答えが閾値に関して単調であるということです。 候補最大荷重を固定する場合$X$、セグメントを貪欲にスキャンし、各グループの合計が以下を超えないように必要な連続グループの数を数えることができます。$X$。 以内にできるなら$k$グループ、その後$X$実現可能です。 それ以外の場合はそうではありません。 この単調性により、答えを二分探索することができます。 

残る唯一の問題は、実現可能性チェックごとの効率です。 任意の範囲にわたるグループ数を迅速に計算する必要があります。 これはプレフィックス合計によって処理され、範囲合計が可能になります。$O(1)$、そして各実現可能性チェックはセグメントにわたる線形スキャンになります。$O(n)$そのクエリに対して。 

各クエリには依然としてコストがかかるため、$O(n \log S)$、 どこ$S$は合計範囲ですが、これをクエリごとに単純に実行すると、最悪の場合遅すぎます。 ただし、その制約は、$k \le 10$構造が変わります。各実現可能性チェックは非常に軽く、プレフィックス合計と厳密な実装により、意図したソリューションは高速範囲合計クエリと組み合わせたクエリごとの二分検索に依存します。 

プレフィックスの合計を 1 回事前計算します。 次に、各クエリは回答空間に対して二分検索を使用し、各チェックでセグメントを貪欲にカウントします。$O(R-L+1)$、しかしそれ以来$k$小さいため、これを超えると分割は早期に終了します$k$、制約下でも十分な速度を維持します。

 ## アルゴリズムのチュートリアル

 1. 入力重みに対してプレフィックス合計配列を構築します。 これにより、任意のセグメントの合計を一定時間で計算できるようになります。$[L, R]$。 すべての実現可能性テストは範囲合計クエリの繰り返しに依存するため、これが必要です。 
2. クエリごとに$(L, R, k)$、答えの検索範囲を定義します。 可能な最小の最大荷重はセグメント内の最大の単一要素であり、可能な最大値はセグメントの合計です。 
3. この範囲に対して二分探索を実行します。 各中間値は、トラックあたりの最大許容積載量の候補を表します。 
4. 特定の候補者について$X$、からセグメントをスキャンします$L$に$R$、累計を累積します。 次の要素を追加すると次の値を超える場合は常に$X$、新しいセグメントを開始し、トラック数を増やします。 
5. 必要なセグメント数が最大でも$k$、 それから$X$は実現可能なので、より小さい値を試してみます。 それ以外の場合は、より大きな値が必要です。 
6. 二分探索が終了したら、実行可能な最小値を出力します。$X$。 

実現可能性チェック内の貪欲な構造は非常に重要です。セグメントが制限を超えると、すぐに切断するのが最適です。これは、切断を遅らせても現在のセグメントの合計が増加するだけであり、後で必要なセグメントの数を減らすことができないためです。 

### なぜ効果があるのか

 固定しきい値の場合$X$、貪欲スキャンは、各セグメントの合計が最大で$X$。 これは古典的な交換引数です: 以下に有効なパーティションがある場合$X$グリーディ カットよりも後にカットを作成すると、グリーディ カットはセグメント数を増やすことができず、前のセグメントを小さくするか同じにするだけです。 これにより、実行可能性テストが正しいことが保証されます。 

実行可能性が単調であるため、二分探索は有効です。 値の場合$X$セグメント合計の制約を緩和するだけであるため、より大きな値でも機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def range_sum(l, r):
        return pref[r] - pref[l]

    def can(l, r, k, x):
        groups = 1
        cur = 0
        for i in range(l, r):
            val = a[i]
            if cur + val <= x:
                cur += val
            else:
                groups += 1
                cur = val
                if groups > k:
                    return False
        return True

    for _ in range(d):
        L, R, k = map(int, input().split())
        L -= 1

        lo = max(a[L:R])
        hi = sum(a[L:R])

        while lo < hi:
            mid = (lo + hi) // 2
            if can(L, R, k, mid):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```プレフィックス配列は一度構築されますが、この実装では境界の説明を簡単にするためにスライス動作に直接依存しています。 厳密な最適化では、スライスの繰り返しを回避し、代わりに、再計算を行わずに境界と貪欲スキャンの両方に事前計算されたプレフィックス合計を使用します。 

実現可能性関数がコアロジックです。 現在のセグメントがしきい値を超えると、左から右に進み、可能な限り最も早いカットを貪欲に形成します。 グループが超過した場合の早期退場$k$無駄な作業を防ぎます。 

有効なパーティションの最大セグメント合計が最大の単一要素よりも小さいことはできないため、バイナリ検索範囲はセグメント内の最大要素から始まります。 上限は合計であり、セグメント全体を 1 台のトラックとして扱うことに相当します。

 ## 特殊なケース

 重要なケースの 1 つが次のような場合です。$k$セグメントの長さに等しい。 この状況では、各要素が独自のグループを形成する必要があるため、答えは最大要素と等しくなければなりません。 単一の要素を超える追加はすぐに厳しいしきい値を超えるため、貪欲チェックでは要素ごとに 1 つのグループが自然に生成されます。 

もう 1 つのケースは、中央の 1 つの非常に小さな要素を除いて、すべての要素が大きい場合です。 最適な分割により大きな要素を分離することができ、貪欲な方法は大きな値に遭遇するとすぐに切断することで正しく反応し、実現可能性を侵害するセグメントがないことを保証します。 

3 番目のケースは単一要素セグメントです。 下限と上限の両方がその要素に等しいため、バイナリ検索はすぐに終了し、分割ロジックが誤って呼び出されることはありません。
