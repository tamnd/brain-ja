 ## 解決策
 ## 問題の理解

 標準的な 6 面サイコロが 3 つ与えられます。 各面には 1 から 6 までのピップ数が含まれます。一部の面は「赤い面」と見なされ、残りは「黒い面」と見なされます。 具体的には、1と4を示す面は赤、2、3、5、6を示す面は黒になります。 

サイコロが着地すると、その上面は、その面上の赤いピップの数とその面上の黒いピップの数という 2 つの個別の値に寄与します。 面が赤 (1 または 4) の場合、そのすべてのピップは赤の合計にカウントされ、黒には何も寄与しません。 顔が黒 (2、3、5、6) の場合、そのすべてのピップは黒の合計にカウントされ、赤には何も寄与しません。 

3 つのサイコロを個別に投げると、すべての上面の赤いピップの合計と、すべての上面の黒いピップの合計のみが観察されます。 このタスクは、赤の合計が A に等しく、黒の合計が B に等しくなるように、各サイコロに面を割り当てる方法が存在するかどうかを判断することです。 

入力制限 A と B は両方とも最大 100 であり、これは十分小さいため、3 つのサイコロのすべての結果を直接列挙することも可能です。 結果は合計で 63 = 216 しかないため、すべての組み合わせを探索したり、小さな動的プログラミング状態空間を使用したりするアプローチは、制限内で快適に実行できます。 

素朴な推論による微妙な失敗例は、赤の和と黒の和の間の独立性を仮定することです。 たとえば、問題を 2 つの別個の分割問題として処理しようとすると、各ダイが 2 つの合計の一方に排他的に寄与するため、失敗します。 もう 1 つのよくある間違いは、値が「柔軟に見える」ため、範囲内の任意のペア (A, B) が達成可能であると想定することです。ただし、分布は高度に構造化されており、赤は {1, 4} からのみ、黒は {2, 3, 5, 6} からのみ発生します。 

具体的な無効なケースは、A = 1、B = 2 です。赤には面 1、黒には面 2 を選択しようとするかもしれませんが、サイコロが 3 つある場合、貢献度を分配すると、少なくとも 1 つのサイコロが目標を超える赤の値か黒の値のいずれかを貢献することになります。 まさにこれが、体系的な列挙または DP が必要な理由です。 

## アプローチ

 最も直接的なアプローチは、3 つのサイコロのすべての可能な結果に対して総当り攻撃を行うことです。 各サイコロには 6 つの面があるため、6 × 6 × 6 = 216 通りの組み合わせをすべて試します。 各トリプルについて、結果として得られる赤の和と黒の和を計算し、それが (A, B) と一致するかどうかを確認します。 これは、実験の有限状態空間全体を使い果たすため、正しいです。 

欠点は正確さではなく一般性です。サイコロの数が大きい場合、たとえば N から 10⁵ までの場合、このアプローチは指数関数的な増加によりすぐに失敗します。 適度な N を使用しても 6ⁿ は不可能になります。 

重要な観察は、状態空間が非常に小さく、構造化されているということです。 各サイコロは独立してペア (赤、黒) を提供し、そのようなペアをちょうど 3 つ合計します。 これは古典的な小次元のナップザック型の問題であり、サイコロの数と累積和に対する動的計画法で十分です。 

処理したサイコロの数と、これまでに達成可能な赤と黒の合計に対して DP 状態を定義します。 サイコロが 3 つしかなく、両方の合計が 100 で制限されているため、DP テーブルは小さいままです。 トランジションでは、ダイスごとに 6 つの面すべてが試行されます。 

これにより、暗黙的な列挙が、小さな 3 層グリッド内の構造化された到達可能性の問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての結果に対するブルートフォース | O(63) | お(1) | 承認済み |
 | 3 つのサイコロと合計の DP | O(3・6・A・B) | O(A・B) | 承認済み |

 ## アルゴリズムのチュートリアル

 サイコロを 1 つずつ投げるプロセスをモデル化し、各ステップの後にどの赤と黒の合計が得られるかを追跡します。

1. dp[i][r][b] が i 個のダイスの処理後に赤の和 r と黒の和 b を達成できるかどうかを示す DP テーブルを定義します。 この定式化は、サイコロの結果を追加する逐次的な性質を直接反映しており、異なる数のサイコロからの寄与が混在しないようにします。 
2. サイコロを振る前は両方の合計が 0 であるため、dp[0][0][0] を true として初期化します。 この時点では他の状態に到達できません。 
3. 1 から 3 までの各サイコロについて、前のサイコロの後に到達可能なすべての状態を繰り返します。 すべての状態 (r、b) について、サイコロの可能な 6 つの面すべてを試します。 
4. 各額面 x について、それを寄与ペアに変換します。 x が 1 または 4 の場合、(x, 0) に寄与します。 それ以外の場合は (0, x) を提供します。 このエンコードは、赤い面は赤いピップのみに寄与し、黒い面は黒いピップにのみ寄与するというルールを反映しています。 
5. dp[i−1][r][b] が到達可能である場合は常に、dp[i][r + red][b + black] を到達可能として更新します。 このステップでは、i-1 個のサイコロのすべての有効な結果を拡張することによって、i 個のサイコロのすべての可能な累積結果を構築します。 
6. 3 つのサイコロをすべて処理した後、dp[3][A][B] に到達可能かどうかを確認します。 そうであれば、必要な合計を生成する面の割り当てが少なくとも 1 つ存在します。 

正確さは、3 つのサイコロの出目のすべての有効なシーケンスが連続する拡張を通じて 1 回だけ構築され、すべての拡張が各サイコロの独立した寄与構造を尊重するという事実に基づいています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())

    faces = [(1, 0), (0, 2), (0, 3), (4, 0), (0, 5), (0, 6)]

    dp = [[False] * (101) for _ in range(101)]
    dp[0][0] = True

    for _ in range(3):
        ndp = [[False] * (101) for _ in range(101)]
        for r in range(101):
            for b in range(101):
                if not dp[r][b]:
                    continue
                for dr, db in faces:
                    if r + dr <= 100 and b + db <= 100:
                        ndp[r + dr][b + db] = True
        dp = ndp

    print("Yes" if dp[A][B] else "No")

if __name__ == "__main__":
    solve()
```このコードは、前述の DP を直接実装します。 テーブル dp[r][b] は、「3 つのサイコロ レイヤー」を反復更新に圧縮し、3 次元を回避します。 各反復は 1 つのダイの処理に対応し、ndp により、同じレイヤー内で更新が再利用されないことが保証されます。 

顔のエンコードにより、赤と黒の寄与が明示的に分離されるため、2 つの次元が誤って混合されることが防止されます。 

A、B の制限値 100 を超えないようにするための境界チェックが含まれています。 

## 実用的な例

 ### 例 1: A = 4、B = 5

 各ダイの後に到達可能な状態を追跡します。 

| ステップ | 到達可能な (r, b) ペア (圧縮) |
 | --- | --- |
 | 開始 | (0, 0) |
 | 1 ダイ後 | (1,0)、(0,2)、(0,3)、(4,0)、(0,5)、(0,6) |
 | 2 つのサイコロの後 | 2 つの顔の組み合わせ |
 | 3 つのサイコロの後 | (4,5) を含む |

 DP は、(4,0) + (0,2) + (0,3) のような組み合わせにより、最終的に (4,5) を形成します。 これにより、赤の多い面 1 つと黒い面 2 つを混合することで目標を達成できることが確認されました。 

### 例 2: A = 1、B = 2

 | ステップ | 到達可能な (r, b) ペア (圧縮) |
 | --- | --- |
 | 開始 | (0, 0) |
 | 1 ダイ後 | 顔と同じ |
 | 2 つのサイコロの後 | 2 つの面の合計 |
 | 3 つのサイコロの後 | (1,2) に等しい状態はありません |

 このケースは、赤 = 1 を達成するには面 1 を使用する必要があるため失敗しますが、3 つのサイコロを完成させると、黒の寄与が強制的にオーバーシュートまたは 2 を正確に逃すことになります。 

このトレースは、両方のターゲットが小さい場合でも、寄与の離散的な性質により任意の組み合わせが妨げられることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(3 · 6 · 100 · 100) | 3 つのサイコロのそれぞれについて、到達可能な状態は 6 つの面と合計の境界グリッドに広がります。 
| スペース | O(100・100) | 到達可能な (赤、黒) ペアを格納する DP テーブル |

 ## 特殊なケース

 A = 0、B = 0 の場合は、合計ですべてのサイコロから寄与を選択しないことに対応します。これは、合計が正しくキャンセルされる方法で、すべてのサイコロの面が黒ゼロの寄与者または赤ゼロの寄与者でない限り不可能です。 dp[0][0] は有効な面遷移を通じてのみ伝播し、両方の軸で同時にゼロ寄与を許可する面はないため、DP はこれを自然に処理します。そのため、両方の合計をゼロに保つ唯一の到達可能な方法は、3 つのステップにわたる不可能なキャンセルによるものですが、DP はこれを正しく拒否します。 

A = 4、B = 0 の場合、アルゴリズムは、少なくとも 1 つのサイコロが面 4 を示し、他のサイコロは赤の寄与がゼロの黒い面でなければならないシーケンスを探索します。 DP は 1 つのステップの直後に (4,0) に到達し、(0, x) 面を追加するだけで残りの遷移全体で安定した状態を維持し、到達可能性を確認します。 

A = 1、B = 2 の場合、DP は面 1 を使用して red = 1 を構築しようとしますが、3 つのサイコロを完成させると、2 または 3 または 5 または 6 の倍数で黒の寄与が導入され、状態空間が B = 2 に正確に整列することはありません。そのため、dp[3][1][2] はすべてのレイヤーを通じて false のままになります。
