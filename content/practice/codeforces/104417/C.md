 ## 解決策
 ## 問題の理解

 0 から n までのラベルが付いたノードを持つルート付きツリーが与えられます (0 がルート)。 現在、各エッジにはラベルがありませんが、各ノードには最大 26 個の子があるため、原理的には競合することなくどのノードからの出力エッジにも小文字を割り当てることができます。 

ノードのサブセットはキー ノードとしてマークされます。 ツリーのすべてのリーフがキー ノードであることが保証されているため、すべてのリーフが注目する 1 つの文字列に対応します。 すべてのノードは、ルートからそのノードまでのパスに沿って文字を連結することによって形成された文字列を表します。 

構造が有効なトライになるように、すべてのエッジに文字を割り当てることができます。これは、ルートからノードまでのすべての文字列が異なることを意味します。 キー ノードのうち、文字列を収集し、辞書順に並べ替えて、シーケンス B を取得します。目的は、この並べ替えられたシーケンス B が辞書順でできるだけ小さくなるようにエッジ ラベルを選択することです。 複数の代入によって同じ最適シーケンス B が生成される場合、完全なエッジ ラベル文字列 (ノードの昇順ですべてのエッジ ラベルを連結したもの) が辞書編集的に最小となるものを出力する必要があります。 

主な問題は、エッジのラベル付けによってすべての文字列が同時に決定され、ツリーの上位にあるラベルを変更すると、そのサブツリー内のすべての文字列に影響することです。 制約は大きく、テスト ケース全体の合計 n は最大 200,000 であるため、合計作業量で 2 次に近い解法は不可能です。 単一のパスの長さは O(n) であり、葉の数も O(n) である可能性があるため、ルートからリーフまでのすべての文字列を明示的に構築することを伴うものはすべて直ちに除外されます。 

微妙な失敗例は、サブツリー全体の結果を考慮せずに貪欲なローカル決定が行われた場合に発生します。 たとえば、直接のサブツリー サイズが最小の子に最小の文字を選択しても、2 つのキー リーフ間の最初の異なる文字がルート近くではなくツリーの奥深くに表示される可能性があるため、さらに悪い辞書編集シーケンス B が生成される可能性があります。 

## アプローチ

 これを強引なラベル付けの問題として扱うのは単純な考えです。 各ノードには最大 26 個の発信エッジがあるため、理論的には、エッジへの文字の割り当てをすべて試し、結果として得られるキー文字列のソートされたリストを計算できます。 これはエッジの数が指数関数的であり、およそ 26^(n) であり、直ちに不可能です。 

各ノードは階乗数の選択肢に寄与しており、それでも天文学的に大きいため、ノードごとの順列に制限しても役に立ちません。 

問題の構造は、ルートからリーフへの文字列間の辞書編集上の順序が、2 つのパスが分岐する最初のエッジで決定されることを示唆しています。 これは、ノードの下にある 2 つのサブツリーの相対的な順序は、より深い構造ではなく、そのノードでどのエッジ ラベルを受け取るかによって完全に決定されることを意味します。 

この観察により、問題は、すべてのノードで、その子の順序をどのように決定するかに集約されます。 順番が決まったら文字を割り当てます`a, b, c, ...`その順番で。 残りの問題は、どの子サブツリーを最初に配置するかを決定する方法です。 

2 つの子を比較するには、各サブツリー内で最適なラベル付けを行った後、どのサブツリーが辞書編集的に小さいキー文字列を生成するかを知る必要があります。 これは自然にボトムアップ定義につながります。つまり、各サブツリーには最適な「最良の」表現があり、子はそれらの表現を比較することによって並べ替えられます。 

唯一の問題は、完全な文字列の明示的な構築を避けることです。 代わりに、ボトムアップで最適なトライ構造を生成する DFS ベースの順序付けを使用してサブツリーを比較し、比較の一貫性と安定性を確保します。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、完全にツリー構造で作業します。 

1. ツリーを 0 でルートし、すべてのノードの子の隣接リストを作成します。 これにより、親配列を繰り返しスキャンすることなく、サブツリー構造に直接アクセスできるようになります。 
2. 各サブツリーの順序を計算する再帰関数を定義します。 この関数は、最終トライに出現する順序でソートされたノードの子を返し、同時にそのノードのエッジ ラベルをその子に割り当てます。 

中心的な考え方は、子の正しい順序がわかれば、より深い決定の正しさに影響を与えることなく、安全に昇順に文字を割り当てることができるということです。 
3. リーフ ノードの場合、注文するものはありません。 これは、親を超えた単なる空の拡張であるキー文字列に対応するため、再帰はすぐに返されます。 
4. 内部ノードの場合、最初にすべての子サブツリーの最適な順序を計算します。 これは、各子で同じ関数を再帰的に呼び出すことによって行われます。 
5. すべての子の処理が完了したら、子を並べ替えます。 2 つの子 u と v の比較は、すでに構築されている最適なサブツリー構造を比較することによって行われます。 直観的には、上から下に読んだときにどのサブツリーが辞書編集的に小さいキー文字列のセットを生成するかを比較します。 

この比較が有効なのは、各サブツリー内のすべての決定がすでに最適に修正されているため、残りの選択肢はどのサブツリーを現在のノードで先に配置するかだけです。 
6. 子がソートされたら、順番に文字を割り当てます。最初の子が取得されます。`'a'`、2番目が取得します`'b'`、 等々。 これにより、最初のサブツリー内のすべての文字列が、後続のサブツリー内のすべての文字列よりも辞書編集的に小さいことが保証されます。 
7. 各エッジ (親から子) に割り当てられた文字を保存します。 ルートからの DFS が終了すると、すべてのエッジにラベルが付けられ、ノード インデックス 1 ～ n の順に出力されます。 

### なぜ効果があるのか

 正確さは、ルートからキーノードへの 2 つの文字列間の辞書編集的な比較が、最初の分岐エッジで決定されるという事実にかかっています。 この相違は常に、あるノードの子の順序付けで発生します。 ノードの子の順序を修正すると、それらのサブツリー内の今後の決定によって、異なるサブツリー間の相対的な順序が変更されることはありません。これは、すべてのより深いラベルには、すでに修正されたエッジ文字が接頭辞として付けられるためです。 

これにより、強力な不変条件が作成されます。どのノードでも、その子の順序は、そのサブツリー内のすべてのキー文字列の辞書編集上の最適な順序とグローバルに一致します。 各サブツリー自体は比較される前に最適に解決されるため、後で変更を行っても、以前に固定されたプレフィックスの一貫性を損なうことなく順序付けを改善できます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    parent = list(map(int, input().split()))
    keys = set(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        g[parent[i - 1]].append(i)

    # store answer labels for edges: parent -> child
    ans = [''] * (n + 1)

    def dfs(u):
        # sort children by their subtree order (computed after recursion)
        children = g[u]

        # process children first
        for v in children:
            dfs(v)

        # sort children; since subtrees already processed, their relative order is fixed
        # we compare by a key derived from DFS structure
        children.sort(key=lambda x: subtree_key[x])

        # assign letters
        for i, v in enumerate(children):
            ans[v] = chr(ord('a') + i)

        # build a lightweight key for current node:
        # lexicographically minimal representation of subtree
        # represented via tuple of child keys + assigned letters implicitly
        subtree_key[u] = tuple(subtree_key[v] for v in children)

    subtree_key = [None] * (n + 1)

    # initialize leaves
    for i in range(n + 1):
        if not g[i]:
            subtree_key[i] = ()

    dfs(0)

    print(''.join(ans[1:]))

t = int(input())
for _ in range(t):
    solve()
```この実装は、サブツリーごとに再帰的な構造キーを構築し、これらのキーに基づいて子を並べ替えることに依存しています。 キーは、最適な順序付け後のサブツリーの標準形式を表し、完全な文字列を構築しなくても一貫した比較が可能になります。 

微妙な実装の詳細は、子がソートされた後にのみラベルを割り当てることです。 より深い再帰は安定した順序付けに依存するため、ソートの前に代入すると一貫性が損なわれます。 

もう 1 つの重要な詳細は、リーフがそのサブツリー表現を空のタプルとして初期化する必要があることです。 これにより、すべてのリーフが同じように扱われ、順序がその上の構造によって完全に駆動されることが保証されます。 

## 実用的な例

 ルート 0 に 2 つの子 1 と 2、両方の葉と両方のキー ノードがある小さなツリーを考えてみましょう。 

| ステップ | ノード | 並べ替え前の子 | サブツリーキー | 並べ替え順 | 割り当てられた文字 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [] | () | - | - |
 | 2 | 2 | [] | () | - | - |
 | 3 | 0 | [1、2] | (()、()) | [1、2] | 1→a、2→b |

 結果は次のように割り当てられます`'a'`エッジ0→1と`'b'`エッジ0→2へ。 結果の文字列は次のとおりです。`"a"`そして`"b"`、ソートされたシーケンスはすでに最小になっています。 

ここで、サブツリー構造が異なるさらに深いケースを考えてみましょう。 

ノード 0 には子 1 と 2 があります。ノード 1 は 1 つのリーフ 3 につながり、ノード 2 は 2 つのリーフ 4 と 5 につながります。 

| ステップ | ノード | サブツリーキー | 解釈 |
 | --- | --- | --- | --- |
 | 3 | 3 | () | 葉 |
 | 4 | 4 | () | 葉 |
 | 5 | 5 | () | 葉 |
 | 1 | 1 | ((),) | 葉一枚下 |
 | 2 | 2 | (()、()) | 下の葉2枚 |
 | 0 | 0 | ((()、)、(()、())) | 比較によって順序が決まります |

 ノード 0 では、サブツリー 1 が生成する辞書文字列が少なく、以前のものであるため、サブツリー 1 は小さくなります。 それでそれは受け取ります`'a'`、サブツリー 2 は受信します`'b'`。 これにより、最終的な並べ替えシーケンスでは、サブツリー 1 のすべての文字列がサブツリー 2 よりも前に表示されるようになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードは 1 回処理され、子はサブツリー キーに基づいて並べ替えられます。 
| スペース | O(n) | ツリーストレージとノードごとの再帰的メタデータ |

 ## 特殊なケース

 重要なエッジケースは、複数の子が同一のサブツリー構造を生成する場合です。 その場合、B を最小化するには一貫した順序付けが有効ですが、この問題では辞書編集上最小の文字の割り当てを選択する必要があります。 並べ替えが安定しており、文字を確定的な順序で割り当て、一貫したタイブレークを保証するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、各ノードに子が 1 つだけ存在する長いチェーンです。 この場合、ソートはどのステップでも簡単であり、すべてのエッジが受信します。`'a'`。 このアルゴリズムは単純なパスのラベル付けに帰着し、深い再帰が正確性やパフォーマンスに干渉しないことを確認します。 

最後に、多くの子を持つノードを考えますが、すべての葉が異なる深さにあります。 1 つのサブツリーが浅い場合でも、それが自動的に最適になるわけではありません。 順序付けは完全なサブツリーの比較に依存します。 DFS ベースのキー構造により、必要に応じて、より深いが辞書編集的により小さいサブツリーが浅いサブツリーよりも正しく優先されることが保証されます。
