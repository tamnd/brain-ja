 ## 解決策
 ## 問題の理解

 一部の位置が次のように固定されている、部分的に指定されたバイナリ文字列が与えられます。`0`または`1`そしていくつかは不明です。 それぞれの未知の位置は、次のいずれかで独立して置き換えることができます。`0`または`1`。 すべての未知数を埋めた後、最終的な文字列を確認し、異なる文字の隣接するペアがいくつあるか、つまりインデックスがいくつあるかを数えます。`i`満足する`s[i] != s[i+1]`。 

タスクは、この遷移数が正確になるように置換を選択することです。`k`、すべての有効な補完の中で、辞書順に最小の結果文字列を出力する必要があります。 完全に達成できない場合`k`トランジション、戻ります`Impossible`。 

ここでの辞書順とは、文字列を左から右に比較して優先することを意味します。`0`以上`1`最初の異なる位置では、貪欲にゼロを早めにプッシュすることが有益ですが、それが正確に到達する可能性を破壊しない場合に限ります。`k`後で移行します。 

制約により、次の長さの文字列が許可されます。`10^5`テストケースごと、全長は最大`10^6`したがって、すべての解はテスト ケースごとに線形またはほぼ線形である必要があります。 すべての完了をチェックしたり、位置や状態に対する二次動的計画法を実行したりすると、遅すぎます。 私たちは、実現可能性を検証するための何らかの形式の事前計算を使用して、ポジションごとに 1 つの左から右への決定を行うソリューションに向かうことを余儀なくされています。 

欲張ってキャラを選ぶと微妙な難しさが現れます。 配置などの局所的に最適な選択`0`位置にある`i`次のような別の選択をしたとしても、後で必要なトランジション数に達することが不可能になる可能性があります。`1`成功するだろう。 これは、あらゆる貪欲な決定を将来の実現可能性に対して検証する必要があることを意味します。 

いくつかの危険な状況については注意する価値があります。 

文字列に何もない場合は、`?`、遷移数が既に次と等しいかどうかをチェックしているだけです。`k`。 単純な解決策では、依然として「最適化」しようとして、無効な固定文字を誤って変更してしまう可能性があります。 

もし`k = 0`、最後の文字列は定数である必要がありますが、制約により両方が強制される場合があります。`0`そして`1`場所が違うので不可能になります。 例えば`1?0`決して一定にはなり得ません。 

もし`k = n-1`、文字列はすべての位置で交互になる必要がありますが、次のような固定制約によって交互がブロックされる場合があります。`0?0`、生成できる遷移は最大 1 つだけです。 

これらの状況はすべて、ローカルな決定ではなく、グローバルな実現可能性の推論を必要とします。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての割り当てを試みます。`0`そして`1`みんなのために`?`位置を調べて、完成した各文字列の遷移の数を計算します。 あれば`m`未知数、これは与えます`2^m`可能性と各チェックのコスト`O(n)`、たとえ`n = 30`。 

重要な観察は、文字列構造には単純なマルコフ プロパティがあるということです。位置に文字を固定すると、`i`、将来の移行への影響は、以前の履歴ではなく、そのキャラクターにのみ依存します。 これは、前の文字を表す小さな状態空間を持つ位置に対する動的プログラミングの定式化を示唆しています。 

あらゆる位置について事前計算できます`i`および、可能なすべての前の文字`p ∈ {0, 1}`、サフィックスから達成可能な遷移の最小数と最大数`i`指定された固定制約に従って残りの文字をすべて自由に選択できる場合は、最後まで続きます。 これにより、実現可能性の神託が得られます。`i`、キャラクターを決めたら`c`を使用すると、残りのサフィックスが必要な残りの遷移数をまだ達成できるかどうかを即座に判断できます。 

このオラクルを使用すると、左から右に貪欲に答えを構築できます。 それぞれのポジションで、私たちは試みます`0`まず、それが有効な完全な解決策につながるかどうかを確認します。 はいの場合はそのままにし、そうでない場合は試します`1`。 これにより、辞書編集的に最小の出力が保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | DP + 貪欲な実現可能性 | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すでに使用したトランジションの数を維持しながら、文字列を左から右に構築するという問題を扱います。 欠けている部分は、プレフィックスを固定し、その位置で候補文字を選択する場合に答えることができることです。`i`、残りのサフィックスは、必要な合計トランジションを正確に生成できますか?

 ### 事前計算

 1. 動的プログラミングテーブルを定義します`dp_min[i][p]`そして`dp_max[i][p]`、 どこ`i`は文字列内の位置であり、`p`前の文字 (どちらか`0`または`1`）。 これらの値は、位置から形成できる遷移の最小数と最大数を表します。`i`に`n`の位置にある文字を考慮すると、`i-1`は`p`。 
2. これらの値を右から左に計算します。 位置で`i`、どのような文字を配置できるかを検討します。 もし`s[i]`が固定されている場合、その値のみを考慮します。 そうであれば`?`、両方試してみます`0`そして`1`。 
3. 候補キャラクターごとに`c`のコストを追加します。`1`もし`c != p`(これにより、`i-1`そして`i`)、サフィックスから可能な限り最良の結果を追加します。`i+1`前の文字がどこになるか`c`。 
4. すべての有効な選択肢の中から、`c`、最小値と最大値を取得して埋めます。`dp_min`そして`dp_max`。 

このステップの後、任意の開始状態について、サフィックスが特定の範囲の遷移カウントを達成できるかどうかがわかります。 

### 貪欲な建設

 1. 位置から答えを構築し始めます`1`、これまでに使用された前のキャラクターとゼロのトランジションはありません。 
2. 各ポジションで`i`を割り当てようとします`0`まず (辞書編集上の最小限性を確保するため)、次に`1`必要に応じて。 
3.候補キャラクターについて`c`、前のキャラクターとのトランジションの数を計算します。 もし`i = 1`、この投稿は`0`。 それ以外の場合はそうです`1`前の文字と異なる場合。 
4. 選択後、実現可能性を確認します。`c`、残りのサフィックスは、次の値に等しい遷移の総数を達成できなければなりません。`k`。 これは、現在の遷移と考えられる最良および最悪のサフィックスの寄与が括弧内に含まれる必要があることを意味します。`k`。 
5. 実現可能性があれば、受け入れます`c`、現在の遷移数を更新し、次に進みます。 

### なぜ効果があるのか

 重要な不変条件は、位置を処理する前に`i`、有効な完全なソリューションに拡張できるすべての接頭辞の中で辞書編集上最小の接頭辞を維持します。 DP は、立場での決定が確実に行われるようにします。`i`は安全です: 残りの移行要件を満たすことができる接尾語の完了が少なくとも 1 つ存在する場合にのみ、文字にコミットします。 すべての将来の状態は DP 範囲によって完全に要約されるため、`[dp_min, dp_max]`、後の決定は、前の文字と現在のカウントを超える前の任意の構造に依存しません。 

すべてのステップで実現可能性が維持され、常に最小の有効な文字が選択されるため、最終的な文字列は有効であり、辞書編集的にも最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    
    # dp[i][p] -> min/max transitions from i..n given previous char p
    # p = 0 or 1
    INF = 10**9
    
    dp_min = [[0, 0] for _ in range(n + 2)]
    dp_max = [[0, 0] for _ in range(n + 2)]
    
    for i in range(n, 0, -1):
        for p in (0, 1):
            best_min = INF
            best_max = -INF
            
            for c in (0, 1):
                if s[i - 1] != '?' and int(s[i - 1]) != c:
                    continue
                
                cost = 1 if p != c else 0
                
                mn = cost + dp_min[i + 1][c]
                mx = cost + dp_max[i + 1][c]
                
                best_min = min(best_min, mn)
                best_max = max(best_max, mx)
            
            dp_min[i][p] = best_min
            dp_max[i][p] = best_max
    
    res = []
    prev = -1
    used = 0
    
    for i in range(1, n + 1):
        for c in (0, 1):
            if s[i - 1] != '?' and int(s[i - 1]) != c:
                continue
            
            cost = 0 if prev == -1 else (prev != c)
            new_used = used + cost
            
            if new_used > k:
                continue
            
            if i == n:
                if new_used == k:
                    res.append(str(c))
                    prev = c
                    used = new_used
                    break
                continue
            
            mn = new_used + dp_min[i + 1][c]
            mx = new_used + dp_max[i + 1][c]
            
            if mn <= k <= mx:
                res.append(str(c))
                prev = c
                used = new_used
                break
        else:
            print("Impossible")
            return
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```DP セクションは、位置と前の文字のみに依存するサフィックスの実現可能範囲を構築します。 これにより、貪欲な構築が後戻りすることなく機能することが可能になります。 

構築中、次のようにして最初の文字の大文字と小文字を慎重に分離します。`prev = -1`、文字列が開始する前に人為的な遷移がカウントされないようにします。 実現可能性チェックではターゲットを比較します`k`達成可能な最小合計と最大合計の両方に対して、回復不能な状態に陥ることがないことを保証します。 

実装の微妙な詳細は、DP フェーズと貪欲フェーズの両方で固定文字を確実に尊重することです。 これら 2 つのチェックの間に不一致があると、無効な文字列が実行可能であると見なされます。

 ## 特殊なケース

 エッジ ケースの 1 つは、決定が許可されない完全に固定された文字列です。 貪欲なステップでは最初に固定制約によってフィルタリングされ、DP 実現可能性は正確なパスを受け入れるか、ある位置ですべての候補を拒否するため、アルゴリズムはこれを自然に処理します。 たとえば、入力`n = 4, k = 2, s = "0101"`分岐なしでグリーディを通過し、DP の実現可能性と正確に一致します。 

もう一つのエッジケースは、`n = 1`、選択したキャラクターに関係なくトランジションはありません。 DP の基本ケースでは、どの接尾辞に対してもゼロ遷移が正しく生成されるため、実現可能性は次のようなことを確認することになります。`k = 0`。 貪欲フェーズでは、許容される最小の文字が選択されるだけです。 

3 番目のエッジケースは次の場合に発生します。`k`固定制約が与えられた場合に可能な最大遷移よりも大きくなります。 このような場合、最初のポジションのすべての候補者は実現可能性チェックに失敗します。`k`すべての外に横たわるだろう`[dp_min, dp_max]`範囲内にあるため、即座に拒否されます。
