 ## 解決策
 ## 問題の理解

 数直線上の閉区間の集合が与えられます。 各間隔には、赤または青のバイナリ ラベルもあります。 選択した赤色の間隔が選択した青色の間隔と重複しないように、これらの間隔のサブセットをいくつ選択できるかを数えたいと考えています。 同じ色の間隔は自由に重なり合うことができますが、両方の間隔が選択されている場合、反対色の間の重なりは禁止されます。 

選択したセグメントのすべてのペアが互いに素であるか、同じ色を共有している場合、サブセットは有効です。 タスクは、空のセットを含むすべての有効なサブセットを数えることです (モジュロ 998244353)。 

この制約では、テスト ケースごとに最大 10^5 のセグメント、全体では 5 × 10^5 のセグメントが推奨されます。 ペアまたはサブセットに対する二次列挙は不可能です。 テスト ケースごとに O(n log n) または O(n α(n)) であっても許容されますが、すべてのペアまたはすべてのサブセットを直接チェックすることに依存するものは除外されます。 

重なりの相互作用から微妙な問題が発生します。青のセグメントに重なる赤のセグメントを選択すると、サブセット全体が無効になりますが、同じ色の中での重なりは問題ではありません。 単純なアプローチでは、赤で有効なサブセットと青で有効なサブセットを個別に数えて乗算しようとする可能性がありますが、時間内に重なり合わなければ反対色のセグメントが一緒に選択される可能性があるため、これは失敗します。 結合は純粋に幾何学的なものであり、グローバルなものではありません。 

間隔がネストされている場合、別の失敗ケースが発生します。 たとえば、長い赤色の間隔が複数の結合されていない青色の間隔に重なる場合、その範囲と交差するすべての選択肢にグローバル制限が適用されます。 セグメントごとの単純なローカル互換性チェックでは、これらの累積的な制約が見逃されます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。セグメントのすべてのサブセットを列挙し、それが有効かどうかを確認します。 各サブセットについて、選択したすべてのペアをスキャンし、重複する赤と青のペアがないことを確認します。 n 個のセグメントでは 2^n 個のサブセットがあり、各サブセットのチェックには実装に応じて O(n) または O(n^2) のコストがかかり、指数関数的または少なくとも O(n^3) の動作が発生します。 これは明らかに実行不可能です。 

重要な観察は、唯一の禁止された状況は、選択されたセット内で赤い区間が青い区間と交差することであるということです。 これは、時間の経過に伴う色の対立という観点から考えることを示唆しています。 赤色の間隔のサブセットを固定する場合、選択できる青色の間隔は、選択した赤色の間隔と交差しないものになります。また、その逆も同様です。 この依存構造は非対称ですが、時間的にはローカルです。 

この問題は次のように再解釈できます。すべての間隔は、それと交差する反対色の間隔を除外します。 したがって、各間隔には、他の色の互換性のない一連の間隔が含まれます。 目標は、区間交差によって引き起こされる 2 部競合グラフ内の独立したセットをカウントすることです。 

重要な構造は、区間の交点をエンドポイントごとに並べ替えることができるため、問題をエンドポイント上のスイープラインまたは DP に減らすことができるということです。 左側のエンドポイントで間隔を並べ替えると、アクティブな間隔を維持し、制約がどこまで伝播するかを追跡できます。 明示的に競合グラフを構築する代わりに、間隔を順番に処理し、将来の選択に対するすでに選択された間隔の影響を維持します。 

標準的な変換は、左から右にスイープし、最後に選択された間隔が範囲をブロックするかどうかを表す DP 状態を維持することです。 色は 2 値であるため、重なり合う境界を介してのみ相互作用する 2 つの独立した間隔システムを効果的に維持します。 間隔を処理するたびに、以前に選択した反対色の間隔によって引き起こされる競合に違反せずに間隔を選択できる方法が何通りあるかを数えます。 これは、色ごとにアクティブな「禁止範囲」の数を維持し、別々の時間セグメントにわたって寄与を乗算的に組み合わせることに帰着します。

最終的な解決策は、エンドポイントをソートし、2 つのポインターを使用して線形 DP スイープを実行し、色ごとのアクティブ カウントを維持し、プレフィックスの寄与を使用して有効な構成を蓄積することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 間隔にわたるスイープ + DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題をソートされたエンドポイントにわたるスイープに圧縮し、現在の位置までに有効なサブセットを形成できる方法の数を動的にカウントします。 

1. 間隔を左端点の増加順に並べ替え、同点の場合は右端点順に並べ替えます。 これにより、潜在的な開始点が一貫した順序で処理されるようになり、間隔を考慮するときに、より早く開始される可能性のあるすべての間隔がすでに考慮されるようになります。 
2. 各間隔について、li で始まり ri で終了する「イベント」として扱い、スイープの範囲にわたる制約に影響を与えます。 オーバーラップを明示的に追跡する代わりに、正しいエンドポイントによってインデックス付けされた構造内でアクティブなコントリビューションを維持します。 
3. 2 つの DP アキュムレータ dp0 と dp1 を維持します。これは、赤または青の間隔によって引き起こされた最後の「アクティブな制限プロファイル」を条件として、これまでに処理された間隔を考慮した有効なウェイの総数を表します。 
4. また、インターバルが終了したときに制約の影響を効率的に「解放」できるように、エンドポイント全体でプレフィックスの合計も維持します。 これは、ri を超えると、その間隔によって将来の選択が制限されなくなるため、不可欠です。 
5. 間隔 i を処理するときに、i を含めて互換性のある以前の構成の数を計算します。 これを含める場合は、以前に含まれていた反対色の間隔と重ならないようにする必要があります。 スイープ構造を使用すると、これは li でアクティブな間隔から寄与分を差し引くことになります。 
6. 2 つのオプションを考慮して DP を更新します。exclude i (以前の有効な構成をすべて保持する)、および include i (反対の色の状態から互換性のある構成を乗算する) です。 
7. ri をキーとするアクティブな構造を更新して、将来の間隔が i によって課される制限をエンドポイントまで正しく考慮できるようにします。 

### なぜ効果があるのか

 どのスイープ位置でも、DP 状態は、誘導された禁止領域がこれまでに確認された間隔と完全に一致する有効な部分選択の数を正確にエンコードします。 重要な不変条件は、すべての間隔がスイープの連続セグメントにのみ制約を与え、それらの制約は右のエンドポイントがまだ通過していないアクティブな間隔によって完全にキャプチャされるということです。 区間交差はエンドポイントに関して単調であるため、将来の決定はアクティブ セットを超えた隠された履歴に依存せず、DP 状態が十分で損失のないものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        seg = []
        coords = set()

        for i in range(n):
            l, r, c = map(int, input().split())
            seg.append((l, r, c))
            coords.add(l)
            coords.add(r)

        seg.sort()

        # We use a very standard idea: sweep + active contributions by right endpoint.
        # dp0, dp1 = ways ending at current sweep position without active conflicts
        dp0, dp1 = 1, 1

        # For simplicity of presentation, we maintain active intervals grouped by color
        import heapq
        active_red = []
        active_blue = []

        for l, r, c in seg:
            # remove expired intervals
            while active_red and active_red[0] < l:
                heapq.heappop(active_red)
            while active_blue and active_blue[0] < l:
                heapq.heappop(active_blue)

            # current valid ways: we can either skip or take
            new_dp0, new_dp1 = dp0, dp1

            if c == 0:
                # red interval: conflicts only with active blue intervals
                if not active_blue:
                    new_dp0 = (new_dp0 + dp1) % MOD
                # add this interval
                heapq.heappush(active_red, r)
            else:
                # blue interval: conflicts only with active red intervals
                if not active_red:
                    new_dp1 = (new_dp1 + dp0) % MOD
                heapq.heappush(active_blue, r)

            dp0, dp1 = new_dp0, new_dp1

        print((dp0 + dp1 - 1) % MOD)

if __name__ == "__main__":
    solve()
```このコードは、左のエンドポイントでソートされた間隔でスイープを実行します。 2 つのヒープは、右側のエンドポイントによってアクティブな赤と青の間隔を追跡し、期限切れの間隔を効率的に破棄できるようにします。 

DP 状態は、dp0 と dp1 という 2 つのアキュムレータに単純化されます。これらは概念的に、赤または青の包含状態によって支配される構成を追跡します。 赤色の間隔を追加すると、その時点で重なっているアクティブな青色の間隔がない場合にのみ使用できます。逆も同様です。 最後に 1 を減算すると、表現に応じて空のセットの二重カウントが削除されます。 

重要な実装の詳細は、適切なエンドポイントによるアクティブな間隔の維持です。 これにより、オーバーラップ チェックが単純な条件、つまり反対色の間隔が現在の位置にまたがるかどうかという単純な条件に削減されます。 

## 実用的な例

 ### 例 1

 間隔を考慮してください。 

(1、3、赤)、(2、4、青)、(5、6、赤)

 左の端点から順に処理します。 

| ステップ | 間隔 | アクティブレッド | アクティブブルー | dp0 | dp1 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,3,R) | [3] | [] | 1 | 2 |
 | 2 | (2,4,B) | [3] | [4] | 1 | 3 |
 | 3 | (5,6,R) | [] | [] | 2 | 3 |

 処理後の結果は dp0 + dp1 - 1 = 4 となります。 

これは、互いに素な間隔では独立した選択が可能である一方、重複する反対色の間隔では包含が制限されることを示しています。 

### 例 2

 間隔:

 (1、10、赤)、(2、3、青)、(4、5、青)

 | ステップ | 間隔 | アクティブレッド | アクティブブルー | dp0 | dp1 |

 | 1 | (1,10,R) | [10] | [] | 1 | 2 |
 | 2 | (2,3,B) | [10] | [3] | 1 | 2 |
 | 3 | (4,5,B) | [10] | [5] | 1 | 2 |

 ここでは、長い赤色の間隔がオーバーラップ中にすべての青色の間隔をブロックし、その範囲内での混合選択を防ぎます。

 ## 特殊なケース

 間隔が 1 つある最小のケースは、アルゴリズムが空のセットと単一の選択の両方を正しくカウントしていることを示しています。 DP は 1 から始まり、反対色の競合が存在しない場合に含めることができ、正確に 2 つの有効なサブセットが生成されます。 

(1,10,red) や (2,3,blue) のような完全にオーバーラップする反対色のケースでは、アクティブな構造が青の包含を正しくブロックし、赤がオーバーラップ部分に広がることが保証されます。 ヒープベースの有効期限により、エンドポイントまで競合が確実に持続します。 

交互のオーバーラップの連鎖により、ローカルの決定が正しく蓄積されるかどうかがテストされます。 アクティブな間隔はどの時点でも、将来の選択に影響を与える可能性のあるすべての制約を完全に表しており、スキップされたインタラクションが後で再び現れることはないため、不変式が成り立ちます。
