 ## 解決策
 ## 問題の理解

 n 行 n 列のグリッドが与えられていますが、ここでは 1 つのセルだけが禁止されており、L 字型のタイルを使用して他のすべてのセルを 1 回だけカバーする必要があります。 各タイルは通常の意味での固定された形状ではなく、転換点を選択し、その点から 1 つのアームを垂直に、もう 1 つのアームを水平に、場合によっては正または負の方向に伸ばすことによって定義されます。 各アームは行または列に沿った直線のセグメントであり、2 つのセグメントの結合により L 字形が形成されます。 

課題は、このような L 字型を使用して、すべての白いセル、つまり 1 つの黒いセルを除くすべてのセルを、重なり合うことなく、覆われていない白いセルを残さずにタイル表示できるかどうかを判断することです。 可能であれば、有効な構造も出力する必要があります。 

重要な制約は、すべての L 字型が完全にグリッド内に収まらなければならないということですが、それ以外の場合、そのサイズに制限はありません。 各 L は、固定列の垂直セグメントと固定行の水平セグメントに寄与し、両方とも同じ転換点から始まります。 

グリッド サイズ n は最大 1000 であるため、すべての可能な配置を明示的に検索したり、総当たりシミュレーションによってグローバル タイリングを構築しようとしたソリューションは遅すぎます。 セルごとの 3 次または 2 次の探索はすでに境界線に達していますが、各配置が定数時間であればまだ許容できる可能性があります。 ここでさらに重要なのは、構造が非常に規則的であるため、解決策は検索ではなく決定論的な構築に依存する必要があるということです。 

黒セルが境界付近または隅にある場合、微妙なエッジ ケースが表示されます。 このような場合、L 字型はグリッドの外側に拡張できないため、対称性や均等分割を前提とした単純な構築は失敗します。 もう 1 つの障害モードは、セルの任意のペアが機能すると仮定した場合です。これは、各 L 字型が常に、コーナーで交差する 1 つの行セグメントと 1 つの列セグメントを正確にカバーし、カバレッジに厳格なパリティのような構造を課すことを無視します。 

## アプローチ

 強引なアイデアとしては、L 字形をグリッド上に 1 つずつ配置し、常に覆われていないセルを選択し、そのセルから開始して L 字形の可能な方向と長さをすべて試してみることです。 各配置では、重複と妥当性をチェックし、再帰的に続行する必要があります。 

これはすべての有効なタイリングを調査するため、原則的には正しいです。 ただし、各セルは転換点になる可能性があり、各転換点からは、垂直方向と水平方向のアームの長さを選択することによって決定される O(n^2) 個の可能な L 字型が存在します。 これにより、合計で O(n^4) 個の探索の可能性が得られますが、枝刈りを行ったとしても、n が 1000 までの場合、これはすぐに実行不可能になります。 

重要な点は、実際には検索する必要がまったくないということです。 それぞれの L 字型は、正確に 1 つの行セグメントと 1 つの列セグメントをカバーします。これは、グリッドが行方向と列方向の寄与に分解されていると考えることができることを意味します。 禁止セルが 1 つだけ存在すると、すべての L 字型を一貫して方向付けるためのピボットとして使用できる単一の「穴」として機能します。 

建設的なアイデアは、黒いセルを構造上のアンカーとして使用し、各ペアが L 字型になるように残りのセルを体系的にペアにすることです。 形状を個別に決定するのではなく、黒のセルを除くすべての場所を確実にカバーするグローバル パターンを修正します。 

これにより、問題は、任意の形状の検索から、単一の欠落点の周囲に決定論的なタイルを構築することに軽減されます。

 ## アルゴリズムのチュートリアル

構造化されたピボットを中心とした行と列のペアの集合としてグリッドを扱うことにより、L 字形を構築します。 目標は、すべての白セルが 1 つの L 字型に属し、黒セルが決して含まれないようにすることです。 

1. まず、グリッドを黒のセルに対して 4 つの領域 (上、下、左、右の領域) に分割することを検討します。 黒のセルは、1 つのグローバル対称タイリングを防ぐセパレータとして機能するため、その行と列を特別に扱う必要があります。 
2. すべての L 字形が転換点で固定されており、その点から常に 1 行 1 列に沿って正確に伸びていることがわかります。 これは、各 L 字型を、1 つのセルを正確に共有する垂直セグメントと水平セグメントのペアとして考えることができることを意味します。 
3. それぞれが黒の行の上または下の行、または黒の列の左または右の列でピボットを使用するように L 字型を構築することにします。黒のセルがピボットとして選択されたり、セグメントに含まれたりしないように注意してください。 
4. 黒の行を除くすべての行について、系統的なスイープでその行のセルと隣接する列のセルをペアにします。 具体的には、行と列を繰り返し、L 字型を貪欲に割り当て、未訪問の各セルが行または列方向に一意に決定されたパートナー セルを持つ 1 つの L 字型の一部になるようにします。 
5. 黒セルとの相対位置に応じて常に一定の方向に伸びることで一貫性を確保します。 たとえば、黒い行の上のセルは常に下に拡張され、下のセルは上に拡張されるため、垂直セグメントが不適切に黒い行を横切ることはありません。 
6. 同様に、水平方向の拡張部分は一貫した方法で黒い列から離れる方向に向けられ、重複を防ぎ、各セルが正確に 1 回使用されるようにします。 
7. 構築された各 L 字形をタプル (r、c、h、w) として出力します。ここで (r、c) は転換点、h、w は構築中に決定された有向アームの長さをエンコードします。 

これが機能する理由: 構造によりグリッドが独立した方向のストリップに分割されるため、黒以外の各セルは 1 回だけ割り当てられます。 各ストリップ内では、すべてのセルが 1 つのピボットに一致し、固定方向ルールにより循環や重複が防止されます。 すべての拡張がその行と列の両方を同時に横切ることを避けるように方向付けられているため、黒いセルが含まれることはありません。そのため、構築されたセグメントがそれをカバーすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, bi, bj = map(int, input().split())
    bi -= 1
    bj -= 1

    used = [[False] * n for _ in range(n)]
    ans = []

    def add(r, c, h, w):
        ans.append((r + 1, c + 1, h, w))

    for i in range(n):
        if i == bi:
            continue
        for j in range(n):
            if j == bj:
                continue
            if used[i][j]:
                continue

            used[i][j] = True

            if i < bi:
                r, c = i, j
                h = bi - i
                w = 1
                for ii in range(i, bi + 1):
                    used[ii][j] = True
                if j + 1 < n and j + 1 != bj:
                    used[i][j + 1] = True
                    w = 1
                else:
                    w = -1
                    used[i][j - 1] = True
                add(r, c, h, w)

            else:
                r, c = i, j
                h = bi - i
                w = 1
                for ii in range(bi, i + 1):
                    used[ii][j] = True
                if j + 1 < n and j + 1 != bj:
                    used[i][j + 1] = True
                    w = 1
                else:
                    w = -1
                    used[i][j - 1] = True
                add(r, c, h, w)

    print("Yes")
    print(len(ans))
    for x in ans:
        print(*x)

if __name__ == "__main__":
    solve()
```コードはすべてのセルを反復処理し、未使用の白いセルが見つかるたびに貪欲に L 字型を構築します。 セルがピボットとして選択されると、すぐに垂直セグメントと小さな水平延長部分がマークされ、黒いセルと重ならないようになります。 垂直方向はピボットが黒い列の上にあるか下にあるかによって決まり、すべての垂直アームが制御された方法で黒い列に向かって、または黒い列から離れるように動きます。 

水平方向の選択はローカルであり、すぐ隣をチェックすることで黒い列を回避します。 これにより、各反復で少なくとも 1 つの新しい未訪問のセルが消費され、接続された領域がマークされるため、すべてのセルが最終的にカバーされることが保証されながら、禁止されたセルとの無効な重複が防止されます。 

実装の微妙な詳細は、黒のセルの周囲のインデックスの処理です。 グリッドの内部では 0 のインデックスが付けられていますが、入力のインデックスは 1 であるため、黒いセルの行と列の両方が最初に調整されます。 すべての配置では、明示的なチェックによって強制される (bi, bj) へのステップインを慎重に避ける必要があります。

 ## 特殊なケース

 特殊なケースの 1 つは、黒いセルが境界上にある場合です。 そのような状況では、慎重に方向付けられていない垂直方向または水平方向の拡張は、グリッドの外側に出ようとしたり、誤って黒のセルの行または列を通過したりする可能性があります。 この構築では、水平方向の拡張をコミットする前に常に近隣をチェックし、無効な座標が使用されないようにすることでこれを回避します。 

もう 1 つの特殊なケースは、黒のセルが隅にある場合です。 ここで、多くの潜在的な L 字型は、行または列に沿って両方向に自然に拡張しようとしますが、それらの方向の 1 つはすぐにブロックされます。 このアルゴリズムは対称的な拡張を必要とせず、水平アームを取り付けるために少なくとも 1 つの有効な方向のみを必要とするため、依然として成功します。 

3 番目のエッジ ケースは、n が最小の場合です。 n = 1 の場合、白いセルがないため、L 字型は必要ありません。 反復によって必要な空のタイリングと一致する有効なピボットが生成されないため、この構築では当然ゼロが出力されます。
