 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、それを使用してインデックスのグラフを定義します。 すべてのインデックスは頂点であり、インデックスと値の間の特定の算術条件が成立する場合、2 つの頂点 i と j を接続します。 エッジが存在する場合、その重みは単に 2 つの対応する配列値の合計になります。 

タスクは、エンドポイントを共有する 2 つのエッジが存在せず、選択したエッジの合計重みができるだけ大きくなるようにエッジのセットを選択することです。 これは最大重みマッチングの問題ですが、グラフは明示的に与えられるのではなく、配列によって暗黙的に定義されます。 

テスト ケースごとに n が最大 10^5、テスト全体で合計 5×10^5 という制約により、すべてのエッジを構築しようとするアプローチは即座に除外されます。 最悪の場合、暗黙的なグラフに Θ(n^2) エッジが含まれる可能性があるため、隣接関係を具体化することさえ不可能になります。 正しいソリューションは、テスト ケースごとに構造を線形または線形に近い時間まで圧縮する必要があります。 

素朴なアプローチでは、すべてのペア (i, j) をチェックし、エッジを構築してから、一般的なグラフに対して最大重みマッチング アルゴリズムを実行しようとします。 非常に効率的なマッチング アルゴリズムであっても、隠れた二次グラフのサイズが原因で失敗する可能性があります。 

エッジがまったく存在しない場合、微妙なエッジ ケースが表示されます。 たとえば、定義条件が決して成立しないように配列が厳密に構造化されている場合、答えは 0 でなければなりません。別のエッジ ケースは、エッジは存在するがすべての重みが負である場合に発生します。これは、エッジを選択しないことが許可されており、厳密には負の寄与を取るよりも優れているためです。 

## アプローチ

 最初のステップは、エッジ条件が実際に代数的に何を意味するかを理解することです。 i − j = a_i − a_j の場合、エッジが存在します。 並べ替えると、i − a_i = j − a_j となります。 これは、2 つの頂点が式 i − a_i の同じ値を共有する場合にのみ接続されることを意味します。 

これにより、視点が完全に変わります。 密なグローバル グラフの代わりに、グラフは独立した連結成分に分割され、各成分は同じキー i − a_i を共有するインデックスによって形成されます。 各コンポーネント内では、頂点のすべてのペアが接続されているため、各コンポーネントはクリークとなります。 

次に、エッジ (i, j) の重み (a_i + a_j) を考えます。 コンポーネント内のマッチングを選択すると、選択されたすべてのエッジがそのエンドポイントの合計に寄与します。 これは、頂点がマッチングで使用される場合、その値 a_i が合計スコアに 1 回だけ追加されることを意味します。 未使用の場合は何も貢献しません。 

したがって、コンポーネント内では、問題は次のようになります。一致するすべての頂点の a_i の合計を最大化するには、互いに素な頂点のペアを選択する必要があります。 どの頂点がペアになるかの間に相互作用はありません。 どの頂点を含めるかの決定のみが重要であり、頂点はペアで含める必要があります。 

これにより、各コンポーネントは単純な選択問題に集約されます。つまり、値の合計が最大になる均一なサイズの頂点のサブセットを選択するというものです。 負の値は常に合計を減らすため、最適な戦略はすべて正の値を取ることです。 正の値の数が奇数の場合、カウントを偶数にするために最小の正の値を削除する必要があります。 

ブルート フォース ソリューションでは、各コンポーネントの頂点のすべてのサブセットを列挙し、コンポーネントごとに指数関数的に有効な一致をテストします。 パリティ制約のある選択への構造的縮小により、組み合わせ爆発が完全に除去されます。

 ## アルゴリズムのチュートリアル

 ### 1. グループ化キーを計算する

 各インデックス i について、値 key[i] = i − a_i を計算します。 同じキーを共有するすべてのインデックスは、同じコンポーネントに属します。 

このステップでは、暗黙的なグラフ構造を明示的な接続コンポーネントに置き換えます。 

### 2. キーごとに値をグループ化する

すべての a_i 値を各キーのリストに保存します。 各リストは、任意のペアリングが許可されるクリークを表します。 

### 3. 各コンポーネントを個別に解決します

 値のグループごとに、どの頂点をマッチングに含めるかを決定します。 

### 4. 正の値を抽出する

 リストをフィルタリングして、正の数値のみを保持します。 負の値を含めると総重量が減り、構造上の利点が得られないため、決して有益ではありません。 

### 5. ペアリング制約を強制する

 正の値を降順に並べ替えます。 できるだけ多くの頂点を取得したいと考えていますが、頂点はペアになっている必要があるため、数は偶数である必要があります。 

正の値の数が奇数の場合は、最小の正の値を破棄します。 これにより、ゲインの損失が最小限に抑えられます。 

### 6. 答えを蓄積する

 すべてのコンポーネントにわたって残りの選択された値の合計を加算します。 この合計は、最大一致重みに等しくなります。 

### なぜ効果があるのか

 各コンポーネント内では、すべてのペアが使用可能なエッジとなるため、唯一の制約は、選択した頂点をペアで使用する必要があることです。 選択された各エッジは、その端点の合計を正確に反映するため、マッチングの合計重みは、マッチングされたすべての頂点の値の合計と等しくなります。 ペアリング構造はコストに影響を与えないため、最適化は最大合計を持つ偶数サイズのサブセットを選択することになります。 このような最適なサブセットは、すべての正の値を取得し、パリティを最小限に調整することで取得され、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        groups = {}
        
        for i, val in enumerate(a, 1):
            key = i - val
            if key not in groups:
                groups[key] = []
            groups[key].append(val)
        
        ans = 0
        
        for vals in groups.values():
            pos = [x for x in vals if x > 0]
            if not pos:
                continue
            
            pos.sort(reverse=True)
            
            if len(pos) % 2 == 1:
                pos.pop()
            
            ans += sum(pos)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、i − a_i によって定義される連結コンポーネントへの削減に直接続きます。 グループ化のステップは、コンポーネント間の相互作用をすべて排除するため、非常に重要です。 

各グループ内では、目的を高めることができないため、正でない値は明示的に破棄します。 並べ替えにより、パリティを修正するために 1 つの要素を削除する必要がある場合に、最小の正のゲインが削除され、損失が最小限に抑えられます。 

このソリューションは、グループ内での並べ替えを除いて、テスト ケースごとにほぼ直線的な時間で実行されます。 

## 実用的な例

 ### 例 1

 値を持つ単一のグループを検討します`[7, 6, 5, 1, 2]`。 

まず、すべての正の値を保持します。 降順で並べ替えると`[7, 6, 5, 2, 1]`。 

偶数の要素を取得する必要があります。 値が 5 つあるため、最小の正の値 1 を削除します。 

| ステップ | 値 |
 | --- | --- |
 | 初期グループ | 7 6 5 1 2 |
 | ポジティブフィルター | 7 6 5 1 2 |
 | 並べ替え済み | 7 6 5 2 1 |
 | パリティ修正後 | 7 6 5 2 |
 | 合計 | 20 |

 これは、パリティがクリーク内の唯一のグローバル制約であることを示しています。 

### 例 2

 グループを考えてみる`[4, -1, -3, 2]`。 

ポジティブな点のみを保持します。`[4, 2]`。 すでに均一なサイズになっているので、調整の必要はありません。 

| ステップ | 値 |
 | --- | --- |
 | 初期グループ | 4 -1 -3 2 |
 | ポジティブフィルター | 4 2 |
 | 並べ替え済み | 4 2 |
 | パリティ修正後 | 4 2 |
 | 合計 | 6 |

 これは、負の値を含めることは決して有益ではないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各グループはソートできますが、グループ全体の要素の合計は n | になります。 
| スペース | O(n) | キーごとにグループ化するためのストレージ |

 要素の合計数は線形であり、各要素はグループ化に 1 回、フィルタリングに 1 回処理されます。 並べ替えはグループ内でのみ行われ、解は合計 n の制限内に十分に収まります (最大 5×10^5)。

 ## 特殊なケース

 コンポーネントに負の値のみが含まれている場合、アルゴリズムは正の値をフィルターした後にすべてを破棄します。 のような入力の場合`[ -5, -2 ]`、頂点が選択されていないため、寄与はゼロです。 これは、一致しても合計が減少するだけであるという事実と一致します。 

たとえば、コンポーネントに正の値が 1 つだけある場合、`[7]`、フィルタリングされたリストのサイズは 1 ですが、これは奇数です。 パリティ ルールはそれを完全に削除し、寄与をゼロにします。 これは、単一の頂点がマッチングにおいて有効なエッジを形成できないことを反映しています。 

コンポーネント内のすべての値が正であるが、カウントが奇数である場合、次のようになります。`[5, 4, 3]`、収量の選別`[5, 4, 3]`最小の正の値を削除すると、高い値の頂点が無駄になることがなくなります。 残りのペア`[5, 4]`最適な貢献を形成します。
