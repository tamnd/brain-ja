 ## 問題の理解

 単一の整数から開始し、base で 2 つの可逆的に見える数字演算を使用して整数を変換できます。$k$。 1 回の操作で基数に数字が追加されます$k$、つまり数値を乗算します。$k$そして、以下の選択された剰余を追加します$k$。 他の操作では最後の塩基が削除されます。$k$数字を整数で割る$k$。 各操作にはコストがかかり、それらは任意の順序で何度でも適用できます。 

目標は、次の数で割り切れる数値に到達することです。$m$、ゼロを含む、最小の総コストで、またはそれが不可能であると判断します。 

重要な問題は、数値自体が最大まで増加する可能性があることです。$10^{18}$、両方の操作で大きさを上下に移動できます。 たとえ少数のステップでも巨大な分岐構造を生成する可能性があるため、整数に対する単純な検索はすぐに実行不可能になります。 

この制約は、状態空間が両方向で無限であるため、値に対する直接的な BFS が実行不可能であることを意味します。 までの数字だけを考えても$10^{18}$、追加操作の分岐要素により、そのスペースに到達できなくなります。 唯一使用可能な構造は、両方の操作が基底の暗黙的な無限ツリー内での移動に正確に対応するという事実です。$k$表現。 

微妙なエッジケースが現れるのは、$k = 1$。 この場合、追加操作では値は変更されず、除算では常に同じ数値が返されます。 成長または縮小を前提とした不用意な解決策は、何も変化しないと誤って結論付けることになりますが、実際には、答えは初期値の簡単な割り算チェックに帰着します。 

もう 1 つのエッジ ケースは、最初の数値が既に次の数で割り切れる場合です。$m$。 少なくとも 1 つの操作を強制するアルゴリズムでは、ゼロコストが有効であっても、誤ってコストが増加します。 

## アプローチ

 問題の構造は、base で最もよく理解できます。$k$。 すべての数字は、$k$-ary ツリー。各ノードは整数を表し、親は次の値で割ることによって取得されます。$k$、子は数字を追加することで取得されます$x \in [0, k-1]$。 

この強引なアイデアは、到達可能なすべての整数をグラフ内のノードとして扱い、最短経路検索を実行することです。 ノードから$n$、私たちはに行くことができます$n \cdot k + x$みんなのために$x$、または$\lfloor n/k \rfloor$。 これは正しいですが、分岐要素が次のとおりであるため、完全に実行不可能です。$k + 1$、値は縮小する前に指数関数的に増加します。 

重要な観察は、値自体は大きくてもよいが、目標にとって重要なのは、次の値で割り切れるかどうかだけであるということです。$m$。 これは追跡番号のモジュロを示唆しています$m$。 ただし、除算すると、$k$剰余算術単独とは互換性がありません。$\lfloor n/k \rfloor$最後の桁に関する情報が失われるため、商に非線形的に影響します。 

したがって、すべてを残基に折りたたむのではなく、問題を暗黙的な基底の最短経路として解釈します。$k$木ですが、積極的に剪定を行います。 どの状態もその数値によって完全に決定され、両方の操作は厳密にこのツリー内で移動します。 重要な構造的事実は、最適なパスに沿って、およそを超える値を考慮する必要がないということです。$k \cdot m$。 数値が大きくなりすぎると、割り算に意味のある影響を与えることができる唯一の方法は、その剰余モジュロを使用することです。$m$、そしてそれはすでに構築された状態の限定された範囲内で表現することができます。 

これにより、到達可能な整数の有限セットに対してダイクストラを実行することができます。各状態は現在の値であり、値を制御範囲内に保つための枝刈りを伴う 2 つの操作によって遷移が正確に生成されます。 各状態はその剰余モジュロも追跡します$m$成功を素早く検出します。

## アルゴリズムのチュートリアル

 構築する各整数を状態として扱い、優先キューを使用して常に最も安価な既知の構成を最初に拡張します。 

1. 最初の番号から開始する$n$、その剰​​余を計算します。$m$、コスト 0 で優先キューに挿入します。 
2. ペアをキーとする訪問済み構造を維持する$(value, value \bmod m)$。 これにより、より高いコストをかけて達成した同一の構成を再度検討することがなくなります。 
3. 状態を削除する場合$x$、すぐに確認してください$x \bmod m = 0$。 そうであれば、ダイクストラは初回訪問時に最小限のコストを保証するため、これが最適な答えです。 
4. 追加操作を各桁に適用します。$d \in [0, k-1]$、計算する$x' = x \cdot k + d$、コストを追加$a$、まだ訪問されておらず、枝刈り境界内にある場合は、新しい状態をプッシュします。 
5. 除算演算を適用します: 計算します$x' = \lfloor x / k \rfloor$、コストを追加$b$、訪問していない場合は押してください。 
6. キューが空になるまで続行します。 剰余ゼロの状態に到達しない場合、出力$-1$。 

枝刈り境界は、次の条件に比例する固定上限までの状態のみを許可することによって強制されます。$k \cdot m$。 これにより、すべての最適なパスを維持しながら、検索が分岐しないことが保証されます。 

### なぜ効果があるのか

 このアルゴリズムは基本的に、暗黙的なベースに基づいて最短パスを実行します。$k$ただし、制御された規模を超えて成長しても、次の倍数に達することに関連する新しいモジュール動作は作成されないことを認識することで爆発を回避します。$m$。 すべての有効な操作シーケンスは、このツリー内の固有のパスに対応し、ダイクストラは、次の値で割り切れる値を持つノードに最初に到達することを保証します。$m$、そこに至るすべての可能なシーケンスの中で最小のコストで到達します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k, m, a, b = map(int, input().split())

        if m == 1:
            print(0)
            continue

        # trivial k=1 case: value never changes
        if k == 1:
            print(0 if n % m == 0 else -1)
            continue

        # Dijkstra over bounded state space
        # We store (cost, value)
        # prune heuristic: values beyond k*m are unnecessary in optimal path
        LIMIT = k * m + 5

        dist = {}
        pq = [(0, n)]
        dist[n] = 0

        while pq:
            cost, x = heapq.heappop(pq)

            if dist.get(x, 10**30) != cost:
                continue

            if x % m == 0:
                print(cost)
                break

            # operation 1: divide by k
            y = x // k
            nc = cost + b
            if y not in dist or nc < dist[y]:
                dist[y] = nc
                heapq.heappush(pq, (nc, y))

            # operation 2: append digit
            # try all digits
            if x <= LIMIT:
                base = x * k
                for d in range(k):
                    y = base + d
                    nc = cost + a
                    if y <= LIMIT and (y not in dist or nc < dist[y]):
                        dist[y] = nc
                        heapq.heappush(pq, (nc, y))
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```このコードは、前述した正確な状態グラフに従います。 優先キューにより、状態がコストの増加順に処理されることが保証されます。これは、両方の操作に独立した重みがあるために必要です。 剪定の様子`x <= LIMIT`追加操作によって際限のない増大が発生するのを防ぎながら、複数の周囲に関連する検索スペースを維持します。$m$。 

除算演算は大きさを小さくし、無制限の拡張を引き起こすことができないため、常に安全であり、すぐに組み込まれます。 追加操作は組み合わせ爆発の唯一の原因であるため、明示的に制御されます。

 ## 特殊なケース

 いつ$k = 1$、どちらの演算も恒等式または単純な除算に堕落するため、数値が意味のある形で進化することはありません。 アルゴリズムは、無限ループを回避するために、このケースを明示的に短絡します。 

初期値が既に割り切れる場合$m$、アルゴリズムは移行前にこれをチェックします。 ダイクストラは最初に開始状態をポップするため、コスト ゼロがすぐに返されることが保証されます。 

除算を繰り返すと数値が急速にゼロになると、ゼロは常に有効なターゲットとなるため、検索は早期に終了します。 プライオリティ キューにより、高価な拡張パスが優先される前に、これらの低コストの移行が確実に探索されます。
