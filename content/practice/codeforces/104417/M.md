 ## 問題の理解

 頂点が反時計回りの順序でリストされている凸多角形が与えられています。 この多角形から 3 つの異なる頂点を選択する必要があります$a, b, c$これも反時計回りの順序で、追加の構造的制約があります: からの境界に沿って歩くとき$b$に$c$反時計回りに正確に横断しなければなりません$k$エッジ。 これで修正されました$c$一度$b$単純なポリゴン上であるため、「」が選択されます。$k$「エッジを前方に」は、頂点サイクルに沿った固定インデックス シフトに対応します。 

選択後$a, b, c$、新しいポリゴンを構築します$Q$。 片側$Q$からの元の境界チェーンです$b$に$c$、まさに貢献します$k$元のポリゴンのエッジ。 残りの2辺は対角線です$ab$そして$ac$。 結果として得られる図は、次のような単純な多角形です。$k+2$エッジ、その面積は「頂点」頂点をどこに配置するかによって決まります。$a$からの固定境界円弧を基準にして$b$に$c$。 

課題は、領域を最大化することです。$Q$すべての有効な選択肢に対して。 

制約は大きく、最大で$10^5$テスト ケースごとの合計頂点数。 これにより、3 次または 2 次の解が即座に排除されます。 すべてのトリプルを試したり、選択ごとにポリゴン領域を再計算したりすると、遅すぎます。 期待すべきことは、$O(n)$または$O(n \log n)$テストケースごとのアプローチ。 

微妙な点は、ポリゴンは凸状ですが、頂点がトリプルで同一直線上にあることが許可されることです。 これは凸面ベースの最適化を壊すものではありませんが、角度を厳密に増加させるなどの厳密な凸面引数に依存してはいけないことを意味します。 

素朴だが重要な誤解は、$a$円弧から独立したものとして$[b,c]$。 実は一度、$b$が固定され、円弧が固定され、$a$はその円弧と線形に相互作用します。これが最適化を可能にする重要な構造です。 

一般的に素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

もし$k = n-2$、次にからの円弧$b$に$c$1 つの頂点を除くほぼ全体のポリゴンをカバーします。 唯一の自由はどこにあるのか$a$多くの実装は対称性を誤って仮定するか、間違った方向に「ポリゴンを閉じる」ことを試みます。 

多角形が三角形の場合 ($n=3, k=1$)、その後、すべての有効な選択肢は完全な三角形の使用に折りたたまれ、最適化の試みはすべて折りたたまれます。$a$それでも領域全体を返さなければなりません。 

すべての点がほぼ同一線上にある場合、別の故障モードが表示されます。 その場合、実装がすべての候補を慎重に評価しないと、外積が小さくなり、数値が不安定になるため、選択された最大値が反転する可能性があります。 

## アプローチ

 強引な解釈は簡単です。 私たちが選ぶ$b$、修正します$c$頂点として$k$一歩前進してから、可能な限りのことを試してください$a$円弧の終点とは異なります。 各トリプルについて、ポリゴン面積を計算します。$Q$外積和を直接使用して、$k+2$頂点。 

これは正しいですが、遅すぎます。 がある$O(n)$～の選択肢$b$、それぞれについて$b$がある$O(n)$～の選択肢$a$。 各エリアのコストを計算する$O(k)$最悪の場合、$O(n^3)$テストケースごとに、これは限界をはるかに超えています。 

重要な観察は、$b$に$c$の面積は固定されています$Q$2 つの部分に分割されます。円弧のみに依存する定数項と、$a$。 これはポリゴンだからです$a, b, \dots, c$関係する用語に貢献します$a$エッジのみを通過する$(a,b)$そして$(c,a)$、その他はすべて修正されています。 

つまり、固定ペアごとに$(b,c)$、次の形式の線形関数を最大化しているだけです。$$\text{contribution}(a) = \frac{1}{2} \cdot (a \times (b - c))$$だから固定のために$b,c$、次から導出される方向ベクトルとの内積を最大化する凸多角形の頂点が必要なだけです。$b-c$。 

これにより、問題は次のように簡略化されます。$b$、計算する$c=b+k$次に、すべてのポリゴン頂点にわたる線形関数を最大化します。 ポリゴンは凸面であり、頂点が順番に与えられるため、船体の横断に沿って方向が変化すると最適な頂点が単調に移動するため、回転ポインタ (回転キャリパーの一種) を使用してこの最大値を効率的に維持できます。 

したがって、最大値を最初から再計算することを回避し、全体の複雑さを線形に軽減します。

 ## アルゴリズムのチュートリアル

 指定された反時計回りの順序でポリゴンを操作し、0 ベースのインデックスを使用します。 

1. 開始頂点を修正する$b$。 対応する$c$が頂点として決定される$k$ポリゴンの境界に沿って前進します。 これにより、アークが確実に発生します。$b$に$c$常に正確に含まれます$k$エッジ。 
2. 方向ベクトルを計算する$d = p_b - p_c$。 このベクトルは、どのように選択するかを完全に決定します。$a$地域に影響を与えます。 
3. の面積寄与度が高いことを観察します。$a$ポリゴン内$(a, b, \dots, c)$外積に比例します$a \times d$。 これは、面積を最大化すると、すべての頂点にわたってこの線形式が最大化されることを意味します。 
4. ポインタを維持する$i$～の最有力候補者を代表する$a$。 新しいものごとに$b$、最初からやり直すことはありません。 代わりに、$i$次の頂点が の値を改善する間に、それを前方に移動します。$cross(p_i, d)$。 両方なので$b$そして$c$増やしながら前進する$b$、方向$d$スムーズに変化し、償却された一定のポインタの移動が可能になります。 
5. それぞれについて$b$、現在の最良のものを使用して最良の面積寄与を計算します。$a$、それを円弧の定数部分と組み合わせます$[b,c]$、グローバル最大値を更新します。 
6.全体の最大値を返す$b$。 

### なぜ効果があるのか

 重要な不変条件は、固定されたそれぞれの$b$、最大化する関数$a$の座標において線形です$a$。 凸多角形では一次関数は極点で最大となり、方向ベクトルはスライドしながら進化します。$b$、最大化頂点はハルに沿って単調に移動します。 この単調性により、以前の候補を再度検討することなく、単一のポインターですべての状態にわたる最適値を追跡できるようになります。 ポリゴンの凸面により、スキップされた後に局所的な改善が再び最適になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def solve():
    n, k = map(int, input().split())
    p = [tuple(map(int, input().split())) for _ in range(n)]

    # prefix cross sum for polygon area contributions of fixed arcs
    def arc_area(b, c):
        # area of polygon chain b -> ... -> c (mod n)
        area = 0
        i = b
        while i != c:
            j = (i + 1) % n
            area += cross(p[i][0], p[i][1], p[j][0], p[j][1])
            i = j
        return area

    def contrib(a, b, c):
        return cross(p[a][0], p[a][1], p[b][0] - p[c][0], p[b][1] - p[c][1])

    ans = 0
    j = 0

    for b in range(n):
        c = (b + k) % n

        # move j to best a for current direction
        while True:
            nj = (j + 1) % n
            if nj == b or nj == c:
                break
            cur = contrib(j, b, c)
            nxt = contrib(nj, b, c)
            if nxt > cur:
                j = nj
            else:
                break

        base = arc_area(b, c)
        best = contrib(j, b, c)
        ans = max(ans, base + best)

    print(ans / 2.0)

t = int(input())
for _ in range(t):
    solve()
```このコードは、境界円弧の固定幾何学的寄与を、頂点によって導入された変数寄与から分離します。$a$。 の`arc_area`関数は、境界チェーンの符号付き領域を次から計算します。$b$に$c$の選択とは独立しています。$a$。 機能`contrib`への線形依存性をエンコードします$a$方向ベクトルとの外積を介して$b-c$。 

ポインタ`j`の反復にわたって維持されます$b$したがって、最良の検索を再開することはありません$a$ゼロから。 これは、ソリューションを線形に保つための重要な最適化です。 

実装上の微妙な懸念の 1 つは、ポリゴン境界でのモジュールの移動です。 ポリゴンは周期的であるため、両方とも$b$そして$c$モジュロで計算されます$n$。 ポインタ ロジックはエンドポイントの選択を回避する必要があります$b$そして$c$として$a$、これらは無効な選択であるためです。

 ## 特殊なケース

 のために$n=3$、すべての有効な選択が強制されます$Q$元の三角形になります。 アークはすでに構造全体に広がっているため、アルゴリズムの一定のアーク項が支配的であり、最適な$a$選択は無意味になります。 すべての候補が存在するため、クロス積定式化は依然として全領域を返します。$a$同等の貢献をもたらします。
