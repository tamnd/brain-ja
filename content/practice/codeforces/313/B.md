 ## 解決策
 ## 問題の理解

 文字「.」のみで構成される文字列が与えられます。 そして "＃"。 タスクは、複数のクエリに効率的に答えることです。 各クエリは、位置 _l_ から _r_ までの部分文字列内で、文字の直後に同じ文字が何回続くかを尋ねます。 たとえば、部分文字列「..#..」では、連続する同一文字のペアは位置 1 ～ 2 と 4 ～ 5 です。 クエリでは、そのような位置の数が必要です。 

入力文字列は最大 100,000 文字まで可能で、クエリの数も最大 100,000 まで可能です。 これは、クエリごとに各部分文字列をスキャンする単純なアプローチでは、最悪の場合、最大 10^10 の操作が必要になることを意味します。これは、2 秒の時間枠の許容制限をはるかに超えています。 したがって、ソリューションでは、重複する部分文字列の繰り返しスキャンを回避する必要があります。 

明らかではないエッジ ケースには、すべて同一の文字を含む文字列、交互の文字、または文字列全体にわたるクエリが含まれます。 たとえば、文字列が「######」でクエリが 1 ～ 6 の場合、最初の 5 文字はそれぞれ隣の文字とペアを形成するため、正解は 5 になります。 一意の文字のみをカウントしたり、最後のペアを忘れたりする不注意なアプローチでは、間違った出力が生成されます。 同様に、「.#.#.#」のような文字列の場合、連続する文字が一致しない場合、1 文字より長いクエリはすべて 0 を返す可能性があり、素朴なアプローチで境界を正しく処理する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。クエリごとに、開始インデックス _l_ から _r_−1 まで反復し、現在の文字が次の文字と等しいかどうかを確認し、カウンタをインクリメントします。 これは正しく機能しますが、最悪の場合、複雑さは O(m・n) になります。 n、m ≤ 10^5 という制約があると、およそ 10^10 回の演算が必要になる可能性がありますが、これは実行不可能です。 

重要な観察は、必要な情報 (連続する等しい文字の数) が、文字列全体について線形時間で事前計算できることです。 配列を定義する`prefix`そのような`prefix[i]`文字列の先頭からインデックスまでの連続する同一文字ペアの数です。`i`。 次に、クエリ (l, r) の場合、答えは単純に次のようになります。`prefix[r-1] - prefix[l-1]`。 これが機能する理由は、`prefix[r-1]`位置 r-1 までのすべてのペアをカウントし、`prefix[l-1]`は、位置 l より前にあるすべてのペアをカウントするため、それらの差がクエリ範囲内のペアの数を示します。 これにより、クエリ処理がクエリあたり O(1) に削減され、合計 O(n + m) の複雑さになりますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m) | お(1) | 遅すぎる |
 | プレフィックスの合計 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値をゼロに設定して、長さ n+1 のプレフィックス合計配列を初期化します。 この配列には、連続する同一文字の累積数が格納されます。 
2. 文字列をインデックス 1 から n−1 まで繰り返し、各位置 i で現在の文字が`s[i]`前の文字と等しい`s[i-1]`。 その場合は、カウントをインクリメントします。`prefix[i] = prefix[i-1] + 1`。 それ以外の場合は、設定します`prefix[i] = prefix[i-1]`。 
3. l と r で定義された各クエリについて、次のように答えを計算します。`prefix[r-1] - prefix[l-1]`。 これにより、次のような位置の数 i が得られます。`s[i] == s[i+1]`[l, r-1] の i の場合。 
4. 各クエリに対して計算された回答を出力します。 

機能する理由: プレフィックス配列は、次の不変条件を維持します。`prefix[i]`は常に、文字列の先頭から位置 i までの連続する等しい文字ペアの数と等しくなります。 r-1 のプレフィックス値から l-1 のプレフィックス値を減算することで、完全にクエリ範囲内にあるペアの数を分離します。 これにより、二重カウントが回避され、すべてのクエリ境界の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)
prefix = [0] * (n + 1)

for i in range(1, n):
    prefix[i] = prefix[i-1] + (1 if s[i] == s[i-1] else 0)

m = int(input())
for _ in range(m):
    l, r = map(int, input().split())
    print(prefix[r-1] - prefix[l-1])
```最初のセクションでは、文字列を読み取り、プレフィックス合計配列を初期化します。 1 から n−1 まで繰り返すことで、各文字をその左隣の文字と確実に比較します。 クエリの場合、減算`prefix[l-1]`から`prefix[r-1]`Python で 0 から始まる配列を使用しているときに、問題の 1 から始まるインデックス付けが正しく考慮されています。 Off-by-one エラーは、配列インデックスを問題のインデックス付けスキームに注意深く合わせることで回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    s = input().strip()
    n = len(s)
    prefix = [0] * (n + 1)
    for i in range(1, n):
        prefix[i] = prefix[i-1] + (1 if s[i] == s[i-1] else 0)
    m = int(input())
    for _ in range(m):
        l, r = map(int, input().split())
        print(prefix[r-1] - prefix[l-1])
    return output.getvalue().strip()

# Provided samples
assert run("......\n4\n3 4\n2 3\n1 6\n2 6\n") == "1\n1\n5\n4", "sample 1"
assert run(".#.#\n3\n1 2\n1 4\n2 4\n") == "0\n0\n0", "sample 2"

# Custom cases
assert run("##\n1\n1 2\n") == "1", "two identical chars"
assert run(".#\n1\n1 2\n") == "0", "two different chars"
assert run("######\n2\n1 6\n2 5\n") == "5\n3", "all equal, multiple queries"
assert run(".#.#.#.#\n3\n1 8\n1 2\n7 8\n") == "0\n0\n0", "alternating pattern"
```| テスト入力 | 期待される出力 | 検証内容 |

 | "##"、1 2 | 1 | 同一の文字を含む最小サイズの入力 |
 | ".#"、1 2 | 0 | 異なる文字を含む最小サイズの入力 |
 | "######"、1 6 および 2 5 | 5、3 | 均一な文字列に対する複数のクエリ |
 | 「.#.#.#.#」、1 8 など | 0,0,0 | 交互パターン、正しいゼロカウント処理を確認します。
