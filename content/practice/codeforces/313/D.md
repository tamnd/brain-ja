 ## 解決策
 ## 問題の理解

 道路には 1 から 1 までの番号が付けられた穴の列があります。$n$。 各穴は次のいずれかを雇うことで修復できます。$m$企業。 各社は連続した穴の部分を修正することを提案しています$[l_i, r_i]$固定費で$c_i$それらの穴の一部がすでに別の会社によって修復されているかどうかに関係なく。 イリヤはせめて修復したい$k$これらの会社をいくつか組み合わせて穴を掘るのですが、これを達成するための最小の総コストを見つける必要があります。 少なくとも修理が不可能な場合は$k$穴がある場合は、-1 を出力する必要があります。 

制約が私たちに与えてくれるのは、$n$最大 300 まで可能で、$m$まで可能です$10^5$。 これは重要な理由です。$n$修復された穴または位置の数に対して DP を考慮するには十分小さいですが、$m$企業のすべてのサブセットを直接反復するには大きすぎます。 各コストは次のように大きくなります。$10^9$これは、オーバーフローを避けるために 64 ビット整数を使用することを推奨しています。 企業のあらゆる組み合わせを試す素朴なアプローチは、次のようになります。$O(2^m)$、これは不可能です$m = 10^5$。 

明らかではないエッジケースには、すべての企業が重複するセグメントをカバーしているものの、累積的に到達できる十分な穴がない状況が含まれます。$k$。 たとえば、次の場合$n = 3$、$k = 3$、そして企業は$[1,1,1]$そして$[3,3,1]$, その場合、穴2はどこの会社でも修理できません。 労働組合の適用範囲を前提とした単純なアプローチでは、成功を誤って報告することになります。 

## アプローチ

 ブルートフォースアプローチでは、企業のすべてのサブセットを考慮し、修復された穴の結合を計算し、コストを追跡します。 これは原理的には正しいですが、複雑です$O(2^m \cdot n)$これは天文学的な数字です$m = 10^5$。 したがって、ブルートフォースは実行不可能です。 

重要な観察点は、穴の数です。$n$小さいです。 これにより、特定の位置までの特定の数の穴を正確に修復するための最小コストを状態が表す動的プログラミング ソリューションを定式化することができます。 企業を適切なエンドポイントごとに分類し、順番に処理できます。 各 DP 状態で、修復されたセグメントの拡張に会社を利用するかどうかを決定し、修復された穴の可能な総数ごとの最小コストを更新します。 これにより、指数部分集合問題が次元を備えた管理可能な DP に変換されます。$n \times n$(位置 × 修復された穴)、これは実現可能です。$n \le 300$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(n) | 遅すぎる |
 | 最適なDP | O(n^2 * m) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルの初期化`dp[i][j]`どこ`i`は修復された最後の穴を表し、`j`修復された穴の総数を表します。 を除き、無限大で埋めます。`dp[0][0] = 0`0 穴の修復には費用がかからないことを表します。 
2. セグメントごとに代表される企業ごと`[l, r]`費用がかかる`c`、現在修復されているセグメントをどのように拡張できるかを検討してください。 反復する`i`から`n`0 まで減らします (この反復での二重カウントを避けるため)。 それぞれについて`j`0から`n`、 もし`dp[i][j]`が有限である場合、新しい状態を計算します。この会社によって修正された追加の穴の数を超えています。`i`は`max(0, r - max(i, l-1))`。 アップデート`dp[r][j + new_holes] = min(dp[r][j + new_holes], dp[i][j] + c)`。 
3. すべての企業を処理した後、答えは最小値になります`dp[i][j]`全体`i`そしてすべて`j >= k`。 そのような有限状態がない場合は、-1 を返します。 

なぜ効果があるのか​​:`dp[i][j]`常に正確に修理するための最小限のコストを保存します`j`位置までの穴`i`。 企業を順番に処理し、重複しない貢献のみを考慮することにより、`new_holes`、私たちは決して過剰にカウントしないことを保証します。 これにより正確性が保たれ、最小コストが見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
companies = [tuple(map(int, input().split())) for _ in range(m)]

INF = 10**18
dp = [[INF] * (n+1) for _ in range(n+1)]
dp[0][0] = 0

for l, r, c in companies:
    l -= 1
    for i in range(n, -1, -1):
        for j in range(n+1):
            if dp[i][j] != INF:
                add = max(0, r - max(i, l))
                if j + add <= n:
                    dp[r][j + add] = min(dp[r][j + add], dp[i][j] + c)

res = min(dp[i][j] for i in range(n+1) for j in range(k, n+1))
print(res if res != INF else -1)
```DP テーブル`dp[i][j]`逆に埋められます`i`同じ繰り返しで同じ会社を 2 回使用することを避けるため。 Python では 0 から始まるインデックスが使用されるため、インデックスを調整します。 の`max(0, r - max(i, l))`これにより、すでに修復されたセグメントを超えて広がる新しい穴のみがカウントされ、コストの挙動が正しくモデル化されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, k = map(int, input().split())
    companies = [tuple(map(int, input().split())) for _ in range(m)]
    INF = 10**18
    dp = [[INF] * (n+1) for _ in range(n+1)]
    dp[0][0] = 0
    for l, r, c in companies:
        l -= 1
        for i in range(n, -1, -1):
            for j in range(n+1):
                if dp[i][j] != INF:
                    add = max(0, r - max(i, l))
                    if j + add <= n:
                        dp[r][j + add] = min(dp[r][j + add], dp[i][j] + c)
    res = min(dp[i][j] for i in range(n+1) for j in range(k, n+1))
    return str(res if res != INF else -1)

# provided sample
assert run("10 4 6\n7 9 11\n6 9 13\n7 7 7\n3 5 6\n") == "17", "sample 1"
# minimal input
assert run("1 1 1\n1 1 5\n") == "5", "min size"
# impossible case
assert run("3 2 3\n1 1 1\n3 3 1\n") == "-1", "impossible"
# full coverage
assert run("5 2 5\n1 3 10\n3 5 15\n") == "25", "full coverage"
# overlapping cheaper
assert run("5 3 4\n1 3 5\n2 5 8\n1 5 20\n") == "13", "overlap cheaper"
