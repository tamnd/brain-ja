 ## 解決策
 ## 問題の理解

 問題はイリヤの銀行口座残高に集中しています。これは符号付き整数です。 正の値は貯蓄を示し、負の値は借金を示します。 銀行はイリヤに 1 回限りの操作を許可しています。残高から最後の 1 桁または最後から 2 番目の桁を削除して、残高を改善できる可能性があります。 目標は、この操作を使用して達成可能な最大残高を決定するか、それが最良の結果を生み出す場合は数値を変更しないままにすることです。 

入力は単一の整数です`n`どこ`10 ≤ |n| ≤ 10^9`。 下限により、数値に少なくとも 2 桁が含まれることが保証され、桁を削除する操作が意味のあるものになります。 上限は 32 ビット整数の範囲内に収まるため、任意精度の処理を必要とせずに算術演算が安全になります。 

明らかではないエッジ ケースには、絶対値が小さい負の数値が含まれます。`-10`または`-11`。 最後の桁を削除するだけで、`-1`または`-1`それぞれ、最後から 2 番目の数字を削除すると、`0`または`-1`。 実装を不注意にすると、最後から 2 番目の数字のオプションが無視されたり、新しい値が誤って計算されたりして、最適とはいえない結果が生じる可能性があります。 

## アプローチ

 ブルートフォース手法では、1 桁を削除するか、番号をそのままにするかのあらゆる組み合わせが試行されます。 正の数の場合、数字を削除しても値が増加することはほとんどないため、ブルート フォースは負の数について 2 つの操作をチェックすることになります。 チェックの最大数は 3 です: keep`n`そのままでは、最後の桁を削除し、最後から 2 番目の桁を削除します。 これは入力ごとに一定の作業であるため、実際には強引な操作も許容されます。 

単純な最適解を導き出す重要な観察は、正の数では何もしないことが常に最適であるということです。 負の数値の場合、最後の桁または最後から 2 番目の桁を削除することによってのみ改善が見込まれます。 これらの変更された数値を整数に変換し、3 つのオプションの最大値を取ることで、正確性が保証されます。 この観察により、問題はループや再帰なしの O(1) 操作に集約されます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`入力から。 これは現在の銀行口座の状態を表します。 
2. もし`n`負ではない、印刷`n`数字を削除してもプラスの残高を改善できないため、すぐに削除してください。 
3. もし`n`マイナスです、変換します`n`文字列に変換してその数字を操作します。 させて`s`の文字列表現になります`n`。 
4. 2 つの候補残高を作成します。最後の桁を削除して形成します。`candidate1`最後から 2 番目の数字を削除して形成します`candidate2`。 これは文字列をスライスすることで行われます。`s[:-1]`最後の桁と`s[:-2] + s[-1]`最後から 2 番目の桁の場合。 これらの文字列を整数に変換し直します。 
5. 3 つの値の最大値を計算します。`n`、`candidate1`、 そして`candidate2`。 この最大値は、可能な限り最良の口座残高です。 
6. 結果を印刷します。 

正しさは、負の数値の場合、桁を削除すると数値の負数が小さくなるか、数値が変化しないままになるという不変式に依存します。 他に考慮すべき操作はないため、3 つの可能性を比較することは徹底的であり、最大の結果が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

if n >= 0:
    print(n)
else:
    s = str(n)
    candidate1 = int(s[:-1])  # remove last digit
    candidate2 = int(s[:-2] + s[-1])  # remove second-to-last digit
    print(max(n, candidate1, candidate2))
```この解決策は、不必要な文字列操作を避けるために正の数を個別に処理することから始まります。 負の数値の場合、文字列のスライスによりターゲットの数字が正しく削除されます。 よくある間違いは、最後から 2 番目の数字を削除するときにインデックスを間違えることです。`s[:-2] + s[-1]`最後の 2 桁より前の桁が正しく保存され、最後の桁が追加されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    if n >= 0:
        return str(n)
    else:
        s = str(n)
        candidate1 = int(s[:-1])
        candidate2 = int(s[:-2] + s[-1])
        return str(max(n, candidate1, candidate2))

# provided samples
assert run("2230\n") == "2230", "sample 1"
assert run("-123\n") == "-12", "sample 2"

# custom cases
assert run("-10\n") == "0", "negative two-digit boundary"
assert run("-11\n") == "-1", "negative two-digit equal digits"
assert run("10\n") == "10", "positive two-digit minimum"
assert run("-1000000000\n") == "-100000000", "large negative number"
assert run("999999999\n") == "999999999", "large positive number"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | -10 | 0 | 最後から 2 番目の数字を削除すると、0 | が生成されます。 
| -11 | -1 | どちらかの数字を削除すると、最良の結果 -1 | が得られます。 
| 10 | 10 | 正の数は変更しないでください |
 | -1000000000 | -100000000 | 大きな負の数を正しく処理します。

 ## 特殊なケース

 のために`n = -10`、最後の数字を削除すると、`-1`しかし、最後から 2 番目の数字を削除すると、`0`、これが最大値です。 アルゴリズムは計算します`candidate1 = -1`そして`candidate2 = 0`、その後、戻ります`max(-10, -1, 0) = 0`、小さな負の数の正しい処理を示しています。 

のために`n = -11`、両方の候補者が生成します`-1`。 アルゴリズムは計算します`candidate1 = -1`そして`candidate2 = -1`、その後、戻ります`max(-11, -1, -1) = -1`、繰り返される数字が正しく処理されることを確認します。
