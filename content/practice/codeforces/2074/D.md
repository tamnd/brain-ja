 ## 解決策
 ## 問題の理解

 2D 整数グリッド上に描かれたいくつかの円が与えられます。 すべての円の中心は X 軸のどこかにあるため、各中心は次の形式の座標を持ちます。$(x_i, 0)$、各円には半径があります$r_i$。 タスクは整数格子点の数を数える事です$(x, y)$境界上の点を含め、これらの円の少なくとも 1 つの内側に存在します。 

点が円に属するための幾何学的条件は標準ユークリッド距離です。点は円に対して有効です。$i$もし$(x - x_i)^2 + y^2 \le r_i^2$。 このようなすべての円の和集合を取得し、その和集合内の整数点を数えなければなりません。 

制約構造が重要な信号です。 すべてのテスト ケースの半径の合計は最大で次のとおりです。$2 \cdot 10^5$これは、多くの円が存在する可能性がありますが、それらの合計の「垂直高さの寄与」には制限があることを意味します。 これは、半径の各単位が 1 回または一定の回数処理される限り、すべての円のすべての垂直層を反復処理することが可能であることを直ちに示唆しています。 

大きな境界ボックス内のすべての整数点をチェックする単純なアプローチは、すぐに失敗します。 半径のある単一の円でも$10^9$膨大な X 範囲にまたがるため、ブルートフォース グリッド スキャンは不可能です。 

円が重なり合うと、より微妙な失敗のケースが発生します。 たとえば、多くの円が同じ中心を共有する場合、カバレッジが x 座標ごとに慎重にマージされない限り、二重カウントが発生する危険があります。 

## アプローチ

 直接的な総当たり手法では、円ごとに反復処理が行われ、次にすべての整数に対して反復処理が行われます。$x$水平スパンで可能な最大値を計算します$y$使用して$y = \lfloor \sqrt{r_i^2 - (x - x_i)^2} \rfloor$、すべての点にマークを付けます$(x, y)$セットで。 これは原理的には正しいですが、生成されるポイントの数はすべての円の合計面積に比例する可能性があります。 単一の半径円$r$すでに貢献している$O(r^2)$半径が大きい場合、これは完全に不可能になります。 

重要な観察は、円が x 軸の中心にあるということです。 これは、問題を列ごとに分解できることを意味します。 固定整数の場合$x$、各円は垂直間隔に寄与します$[-h, h]$、 どこ$h = \lfloor \sqrt{r_i^2 - (x - x_i)^2} \rfloor$。 その x 座標におけるすべての円の結合は、単一線上の垂直セグメントの結合になります。 

個々の点を追跡する代わりに、x ごとに整数の y 値をカウントします。 問題は、円でカバーされるすべての整数 x 列にわたって、オーバーラップのマージ後にその列にカバーされる整数 y 値の数を合計することに帰着します。 

半径の各単位は、合計ですべての円にわたって O(1) 個の個別の x 列のみに寄与するため (半径 r の各円は 2r+1 個の x 値に広がり、r の合計は m であるため)、円ごとに反復して、円がカバーする各 x を処理できます。 

各 x で、対応する高さの間隔を計算し、その列で寄与された最大の y 範囲を取得します。 円間での二重カウントを避けるために、辞書を使用して x ごとの寄与を集計し、半径から導出される最大の高さを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\sum r_i^2)$|$O(\sum r_i^2)$| 遅すぎる |
 | 最適 |$O(m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとにマップを作成します。`best[x]`これは、座標 x における最大垂直半径の寄与を格納します。 

これが必要なのは、複数の円が同じ x をカバーする可能性があり、y 点を数えるには最大の垂直スパンのみが重要であるためです。 
2. を中心とする各円について$x_i$半径あり$r_i$、すべての整数オフセットを反復処理します。$dx$から$-r_i$に$r_i$。 

これは、円の水平投影内にあるすべての整数の x 座標を列挙します。 
3. それぞれについて$dx$、実際の x 位置を計算します。$x = x_i + dx$、そのスライスでの最大の高さを計算します。$$h = \left\lfloor \sqrt{r_i^2 - dx^2} \right\rfloor$$これは、円の方程式を整理すると直接得られます。 
4.アップデート`best[x] = max(best[x], h)`。 

そのスライスでは小さな円が大きな円の中に完全に含まれているため、各 x での垂直方向の最大リーチのみを気にします。 
5. すべての円を処理した後、保存されているすべての x 値を反復処理します。`best`。 各 x について、次を追加します。$2 \cdot h + 1$整数の y 値の範囲は次のとおりです。$-h$に$h$。 
6. 累計を出力します。 

### なぜ効果があるのか

 すべての固定整数 x について、少なくとも 1 つの円制約を満たす点のセットは、y = 0 を中心とする垂直間隔の和集合を形成します。すべての円は x 軸を中心とするため、これらの間隔は対称であり、高さによってネストされます。 したがって、和集合は単一の区間に折りたたまれ、その境界はその x における半径から導出される最大の高さによってのみ決定されます。 アルゴリズムは、X 座標ごとの最大高さのみを保存することでこの不変条件を保持し、重複が二重にカウントされず、有効な点が見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        xs = list(map(int, input().split()))
        rs = list(map(int, input().split()))

        best = {}

        for x0, r in zip(xs, rs):
            r2 = r * r
            for dx in range(-r, r + 1):
                x = x0 + dx
                y2 = r2 - dx * dx
                h = int(y2 ** 0.5)
                if x in best:
                    if h > best[x]:
                        best[x] = h
                else:
                    best[x] = h

        ans = 0
        for h in best.values():
            ans += 2 * h + 1

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、整数の x スパンをスイープすることによって各円を処理します。 平方根の計算によってそのスライスの垂直方向のリーチが決定され、最大値のみを保存することでオーバーラップが正しくマージされます。 最終的な合計は、各垂直スパンを整数格子点の正確な数に変換します。 

微妙な点は整数の平方根です。 ここでは、半径の合計が十分に小さいため、浮動小数点平方根の使用は安全ですが、より厳密な設定では、完全な正方形に近い精度のエッジ ケースを回避するために、整数セーフな sqrt に置き換えることになります。

 ## 特殊なケース

 微妙なエッジケースは完全に封じ込められます。 同じ X 範囲で小さな円が大きな円の内側に完全に収まっている場合、円の単純な結合により垂直スライスが 2 倍にカウントされる可能性があります。 アルゴリズムは、x ごとの最大高さのみを保存することでこれを回避します。 たとえば、同じ点を中心とする半径 1 と 5 の円の場合、すべての X スライスは半径 5 の円によって支配され、小さい方の円が独立して寄与することはありません。 

もう 1 つのエッジ ケースは、円が 1 つの点でかろうじて接触している場合です。 その x 座標では、両方の円が有効な高さを生成しますが、やはり最大値のみが重要であり、共有境界点は 1 回だけカウントされます。$2h+1$対称。 

最後のケースは、中心が遠く離れている極度の疎性です。 それでも、辞書には、ある円が実際に到達した x 値のみが含まれており、各円が正確に寄与するため、辞書は小さいままです。$2r_i+1$このような位置は、合計半径に関するグローバル制約を尊重します。
