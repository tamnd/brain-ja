 ## 問題の理解

 正の整数の配列から始めます。 複数の数値が残っている場合は、2 つの値を選択し、新しい正の整数に置き換えます。$x$、3 つの長さが非縮退三角形を形成する必要があります。 

両面用$a$そして$b$、三角不等式は、3 番目の辺が満たさなければならないことを示しています。$$|a-b| < x < a+b.$$以来$x$整数である必要があります。可能な最大の選択肢は常に$$x = a+b-1.$$このプロセスは、数字が 1 つだけ残るまで続きます。 私たちの目標は、最終的な数値を最大化することです。 

制約が非常に大きいため、非常に単純な解決策が必要です。 すべてのテスト ケースにわたる配列要素の合計数は最大で$2 \cdot 10^5$、つまり、$O(n)$または$O(n \log n)$テストケースごとのアルゴリズムは十分に高速です。 可能な操作シーケンスの数が指数関数的に増加するため、さまざまなマージ順序を探索しようとするアプローチは実行不可能になります。 

主な課題は、各操作でどれだけの値が失われるかを理解すれば、正確なマージ順序は重要ではないことを認識することです。 

いくつかの特殊なケースは見落とされがちです。 

単一の要素を考えてみましょう。```
1
10
```操作は実行されないため、答えは単純です。`10`。 マージの数を含む数式を盲目的に適用するソリューションでは、誤って値が変更される可能性があります。 

次の 2 つの要素を考えてみましょう。```
2
5 7
```最大の有効な置換は次のとおりです。$5+7-1=11$、したがって、答えは次のとおりです`11`。 三角不等式を不注意に解釈すると、誤って許容してしまう可能性があります。$x=12$、しかしそれは退化した三角形を作成します。 

すべてを考慮してください:```
3
1 1 1
```最初のマージにより、$1+1-1=1$。 再度マージすると、$1+1-1=1$。 The answer is`1`。 この例は、すべてのマージで必ず合計からちょうど 1 単位が失われることを示しています。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのステップですべての可能なペアとすべての有効な値を試します。$x$。 各操作によって配列の状態が変更されるため、可能なシーケンスの数は組み合わせ的に爆発的に増加します。 小さいものでも$n$、検索ツリーは巨大になります。 このようなアプローチは完全に非現実的です。 

パターンを見つけるには、配列の合計に何が起こるかに注目してください。 

値をマージするとします$a$そして$b$。 最終的な答えを最大化するには、最大の有効な置換を明確に選択する必要があります。$$x=a+b-1.$$手術前はこれら 2 つの要素が貢献します$a+b$合計額に。 

手術後も貢献してくれる$a+b-1$。 

合計はちょうど 1 減ります。 

この観察が問題のすべてです。 

すべての操作で配列から 1 つの要素だけが削除されるため、配列のサイズが削減されます。$n$サイズに合わせて$1$正確に必要です$n-1$合併します。 

マージのたびに合計が 1 だけ減るため、最終的な値は次のようになります。$$\left(\sum a_i\right) - (n-1).$$他には何も関係ありません。 すべての最適なマージでは 1 つのユニットが失われ、常に正確なユニットが存在するため、マージ順序は無関係です。$n-1$合併します。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、その合計を計算します。$S$。 
2. しましょう$n$要素の数になります。 
3. すべての最適なマージが置き換えられることを観察します。$a$そして$b$と$a+b-1$。 
4. このようなマージごとに、合計がちょうど 1 ずつ減ります。 
5. 削減$n$要素から 1 つの要素までは正確に必要です$n-1$合併します。 
6. すべてのマージの後、最終的な値は次のようになります。$$S-(n-1).$$1. この値を出力します。 

### なぜ効果があるのか

 ペアの可能な最大の代替品$(a,b)$は$a+b-1$、非縮退三角形の 3 番目の辺は厳密に以下でなければならないためです。$a+b$。 小さな選択は将来の可能性を狭めるだけなので、最適な戦略はどれも選択します。$a+b-1$。 

最適なマージごとに、配列の合計が 1 だけ減少します。 マージ回数は固定なので、$n-1$、合計の減少も次のように固定されます。$n-1$。 最後の配列には、元の合計からこの合計減少分を差し引いた値に等しい単一の値が含まれます。 マージ順序によって異なる結果が生じることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(str(sum(a) - (n - 1)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```実装は数学的観察に直接従うものです。 

配列の合計は 1 回計算されます。 すべてのマージでは合計が 1 ずつ減りますので、正確に$n-1$マージが発生すると、減算します$n-1$合計から。 

難しい境界条件はありません。 いつ$n=1$、式は次のようになります$$\text{sum}(a)-0,$$これは元の値を正しく返します。 Python の整数は可能な最大合計を簡単に処理できるため、オーバーフローは問題になりません。
