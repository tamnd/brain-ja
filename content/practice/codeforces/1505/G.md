 ## 解決策
 ## 問題の理解

 最大 24 個の小さな「ブロック」が与えられます。 各ブロックには 5 つの整数が含まれます。 最初の 3 つの数値は 0 ～ 2 の範囲にあり、最後の 2 つの数値は 0 ～ 3 の範囲にあります。各ブロックはバランス条件も満たします。つまり、最初の 3 つの値を合計すると、最後の 2 つの値の合計とまったく同じ合計が得られます。 

タスクは、これらすべてのブロックを使用して、小文字の英語文字で構成される単一の文字列を構築することです。 

各ブロックはそれ自体では文字ではありません。 代わりに、5 つの異なるタイプの文字が何文字含まれるかをエンコードし、2 つのグループに分けます。 最初の 3 つの位置は構造の一方の側の寄与のように動作し、最後の 2 つの位置はもう一方の側の寄与のように動作します。 バランス条件は、すべてのブロックの合計サイズが内部的に一貫していることを保証しますが、文字がどのように分散されるかについては必ずしも一致するとは限りません。 

私たちが決定しなければならないのは、これらのブロックをどのように組み合わせて、すべての寄与が有効な最終シーケンスに整列し、結果として得られるデコードされた文字列を出力するかということです。 

N ≤ 24 という制約は、ブロックのすべてのサブセットを考慮するアプローチが潜在的に実行可能であることを即座に示唆しています。2^24 は約 1,600 万であり、これは境界線ですが、注意深い枝刈りまたは中間の技術を使用する場合にのみ管理可能であるためです。 ただし、各ブロックは構造化された低範囲データ (0 ～ 3) を運ぶため、実際のソリューションでは状態を大幅に圧縮し、完全な割り当てに対する単純なサブセット列挙を回避する必要があります。 

この問題でよくある失敗モードは、各ブロックを独立して扱い、ローカル文字列を構築し、それらを貪欲に連結することです。 これは、制約がグローバルであるため失敗します。各ブロックの合計のバランスが取れていても、両側の文字の分布がブロック間で相互作用し、貪欲に配置すると簡単に実現可能性が損なわれる可能性があります。 

たとえば、2 つのブロックの両方が「最初の 3 つ」側で同じ文字を頻繁に使用しているが、「最後の 2 つ」側で一致する容量を提供するブロックが数ブロックだけである場合、貪欲な連結はローカルではまだ有効に見えるかもしれませんが、グローバルでは不可能になります。 

もう 1 つの微妙な問題は、ブロックごとのバランスがシステム全体が自動的に一貫していることを意味すると仮定していることです。 それは誤りです。バランスは、文字ごとではなく、ブロックごとの合計数にのみ適用されます。 

## アプローチ

 ブルートフォース解釈では、各ブロックをグローバルな構築順序に割り当て、同時にその 5 つのカウントが最終的な文字列にどのように寄与するかを決定しようとします。 ブロックのすべての順列とすべての内部割り当てを探索することを想像することもできますが、これはすぐに爆発します。 注文だけでも 24! ですが、内部流通の選択によりさらに 24 倍になります。 これはまったく実現不可能です。 

より構造化された総当たり攻撃は、各ブロックを 5 次元ベクトルに寄与するものとして扱い、グローバル制約を維持しながらブロックの分割または順序付けのあらゆる方法を試みることです。 それでも、状態空間は N において指数関数的であり、意味のある枝刈りは行われません。 

重要な観察は、N がサブセットベースの動的プログラミングにとって十分に小さく、各ブロックが影響するのは 5 つの有界次元のみであるということです。 これは、問題全体を、これら 5 つの文字タイプの部分的な消費のみを追跡する状態に圧縮することを示唆しています。 

ブロックのシーケンスという観点から考えるのではなく、視点を変えます。ブロックを構造の概念的な 2 つの部分に割り当て、両方の部分が文字の合計使用量で一致していることを確認します。 各ブロックの合計サイズは内部的にバランスがとれているため、実際の制約は、文字がこれらの半分にどのように分散されるかに一致します。 

これにより、問題は低次元の状態で分割されたサブセットを見つけることになります。各状態の次元は最大でも 24 × 3 または 24 × 4 で制限されますが、それでもメモ化を伴うビットマスク DP には十分小さいです。

自然な構造は中間で満たされます。ブロックを 12 個ずつ 2 つのグループに分割します。各半分について、構造の 2 つの側面のいずれかへのブロックの割り当てをすべて列挙します。 各割り当てにより 5 次元のデルタ ベクトルが生成されます。 各デルタを達成するための最良の方法を保存します。 次に、デルタが相殺されるように 2 つの半分を結合します。 

これが機能するのは、各半分が十分小さく、半分あたり 2^12 = 4096 状態が管理可能であり、各状態は小さな定数で囲まれた 5D ベクトルのみを保持するためです。

 ## アルゴリズムのチュートリアル

 各ブロックを 5 次元の寄与ベクトルとして解釈し、構造の 2 つの側面間でカウントがどのようにシフトするかを追跡します。 

### ステップ

 1. N 個のブロックを、およそ N/2 のサイズの 2 つの半分に分割します。 

これは、指数関数的な複雑さを 2^24 から半分あたり約 2^12 に減らすために行われます。 
2. 半分ごとに、ブロックのすべてのサブセットを列挙します。 

サブセットごとに、これらのブロックが集合的に 2 つの概念的な側面間で文字数をどのようにシフトするかを表す 5 次元の署名を計算します。 
3. 各署名から、どのサブセットがそれを生成するかを表すビットマスクへのマッピングを保存します。 

複数のサブセットが同じ署名を生成する場合、カウントではなく実現可能性のみが必要であるため、そのうちの 1 つを保持します。 
4. 後半でも同じプロセスを繰り返し、署名からサブセットへの別のマッピングを作成します。 
5. 前半の各署名について、5 つの次元すべてが相殺されるように、後半から必要な補完的な署名を計算します。 
6. 一致する相補的署名が後半に存在する場合、2 つのサブセットを結合して完全なソリューションを形成します。 
7. 有効な完全なサブセットが見つかったら、選択したブロックを再構築し、エンコード規則に従って文字に変換します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な解が、ブロックの 5 次元寄与ベクトルの合計がゼロになる 2 つのグループへの分割に対応するということです。 ブロックを 2 つの半分に分割することで、すべての完全なパーティションを 2 つの独立した部分パーティションに分解できるようになります。 中間ミート ステップは、グローバル ゼロサム割り当てが存在する場合、その 2 つの半分への投影が列挙されたシグネチャに表示され、それらの組み合わせによって正確に再構築されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def pack_state(v):
    return tuple(v)

def add_vec(a, b):
    return (a[0] + b[0],
            a[1] + b[1],
            a[2] + b[2],
            a[3] + b[3],
            a[4] + b[4])

def solve():
    n = int(input())
    blocks = [tuple(map(int, input().split())) for _ in range(n)]

    mid = n // 2
    left = blocks[:mid]
    right = blocks[mid:]

    def gen(arr):
        mp = {}
        m = len(arr)
        for mask in range(1 << m):
            v = [0] * 5
            for i in range(m):
                if mask >> i & 1:
                    b = arr[i]
                    for j in range(5):
                        v[j] += b[j]
            key = tuple(v)
            if key not in mp:
                mp[key] = mask
        return mp

    mpL = gen(left)
    mpR = gen(right)

    for lv, lmask in mpL.items():
        need = tuple(-x for x in lv)
        if need in mpR:
            rmask = mpR[need]

            chosen = []
            for i in range(mid):
                if lmask >> i & 1:
                    chosen.append(left[i])
            for i in range(n - mid):
                if rmask >> i & 1:
                    chosen.append(right[i])

            # Decode: each block contributes letters a-e
            # First 3 entries are 'a','b','c'
            # Last 2 entries are 'd','e'
            res = []
            for a, b, c, d, e in chosen:
                res.append('a' * a)
                res.append('b' * b)
                res.append('c' * c)
                res.append('d' * d)
                res.append('e' * e)

            print("".join(res))
            return

solve()
```### コードの説明

 この解決策は、ブロックを 2 つの半分に分割し、5 次元ベクトルのすべてのサブセットの合計を列挙します。 各ベクトルは、各サブセットが 5 つの文字タイプにわたって寄与する文字の数を記録します。 存在するだけで十分であるため、ベクトルごとに 1 つのサブセットのみを保存します。 

次に、すべての次元で合計がゼロになるように、半分にまたがる相補的なベクトルを検索します。 これにより、組み合わせた選択のバランスが完全に保たれます。 

最後に、選択した各ブロックをその文字表現に拡張することで、答えを再構築します。 

微妙な点は、辞書編集的に最適化を試みることは決してないということです。 この問題には有効な文字列のみが必要なので、最初に一致するペアで十分です。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のサブセットが半分の内側で同じ 5D ベクトルを生成する場合です。 アルゴリズムは意図的に最初の出現のみを保持します。 これは、有効なグローバル ソリューションを再構築するには任意の 1 つの代表で十分であり、重複は相補的な状態の到達可能性に影響を与えないため、安全です。 

もう 1 つのエッジ ケースは、有効なソリューションが半分のブロック全体を使用する場合です。 その場合、残りの半分の相補的な署名はゼロ ベクトルです。 列挙には常に空のサブセットが含まれるため、このケースは自然に処理されます。 

最後のエッジケースは、順序のせいで一見しただけでは正確に一致するサブセットの組み合わせがない場合です。 このアルゴリズムはベクトルの和のみに依存するため、順序はまったく問題なく、ベクトル署名がハッシュ マップに存在する限り、有効なパーティションは検出されます。
