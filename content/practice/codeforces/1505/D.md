 ## 解決策
 ## 問題の理解

 特定の数値かどうかを判断するように求められます。$N$整数のべき乗の和として表現できる$M$、各パワーは最大 1 回使用されます。 同様に、次のことを知りたいのです。$N$ベースに表現があります$M$数字 0 または 1 のみを使用します。入力は 2 つの整数で構成されます。$N$そして$M$、 どこ$N$は 1024 までであり、$M$は 2 ～ 16 です。そのような表現が存在する場合、出力は単純に「YES」となり、そうでない場合は「NO」となります。 

制約は小さいです。$N$は最大でも 1024 です。つまり、次のすべてのべき乗を反復するアルゴリズムであっても、$M$まで$N$すぐに走ります。$M$は最大 16 であるため、考慮する必要がある最大べき乗数列は次のようになります。$16^0, 16^1, 16^2, \dots$これは指数関数的に増加し、1024 を大きく下回ると止まります。これらの限界は、すべてのべき乗を反復的に試行するアルゴリズムや、除算/剰余演算を繰り返し使用するアルゴリズムが実行可能であることを意味します。 

明らかではないエッジケースは次のような場合です$N$同じ検出力に対して複数の係数が必要です。 たとえば、次の場合$N=6$そして$M=2$、最大の電力を貪欲に減算するという単純なアプローチでは、次のような結果が得られる可能性があります。$4 + 2 = 6$これは機能しますが、条件を誤解し、べき乗を複数回カウントできるようにすると、誤って試行する可能性があります。$2 + 2 + 2 = 6$、これは無効です。 もう一つの微妙なケースは次のような場合です。$N$まさに力です$M$、常に「YES」を返す必要があります。 

たとえば、入力`N=5, M=2`5 = 4 + 1 であるため、「YES」を返す必要があります。入力`N=8, M=2`8 = 8 であるため、「YES」を返す必要があります。バイナリのような分解を正しく処理しない不注意なアルゴリズムでは、有効な場合に「NO」を返す可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のパワーのすべてのサブセットを反復しようとします。$M$を超えないもの$N$そしてそれらを合計します。 パワーごとに、それを含めるか含めないかを選択し、合計が等しいかどうかを確認できます。$N$。 関連する権限の数は最大でも$\log_M N$、このアプローチは理論的にはこれらの制約に対して実現可能ですが、サブセットの列挙は不要です。 

重要な観察は、問題は、次の桁が正しいかどうかを確認することにあるということです。$N$基地内で$M$すべて 0 または 1 です。基数に数字がある場合は、$M$表現が 1 より大きい場合、合計するには何らかの累乗を複数回使用する必要があります。$N$、これは許可されていません。 これにより、除算とモジュロ演算を繰り返し使用するシンプルかつ高速なソリューションが可能になります。 

ブルートフォースが機能するのは、パワーのすべてのサブセットを合計すると次のようになります。$N$ただし、明示的なサブセット列挙を使用して実装すると面倒になります。 基数変換の観察により、問題を単純な数字の条件のチェックに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | べき乗のサブセットの列挙 | O(2^log_M(N)) | O(log_M N) | やりすぎ、不要 |
 | M 進数の桁チェック | O(log_M N) | お(1) | 効率的で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`current`に等しい`N`。 各塩基を繰り返し検査します。$M$桁。 
2. その間`current`ゼロより大きい：

 1. コンピューティング`current % M`、これはベース $M` の最下位桁を与えます。 
2. この桁が 1 より大きい場合、「NO」を出力して終了します。1 より大きい桁は、次の累乗を意味するためです。$M$複数回使用する必要があります。 
3. それ以外の場合は分割します`current`による`M`(整数除算) して続行します。 
3. 1 より大きい数字が見つからずにループが完了した場合は、「YES」を出力します。 

機能する理由: 各反復で、現在の累乗の係数を検査します。$M$。 すべての係数が 0 または 1 の場合、定義により、$N$の個別の累乗の合計として表すことができます。$M$。 不変条件というのは、`current`は常に残りの部分を表します$N$0 ～ 1 の係数条件に違反すると、直ちに分解が不可能であることが示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, M = map(int, input().split())
    current = N
    while current > 0:
        digit = current % M
        if digit > 1:
            print("NO")
            return
        current //= M
    print("YES")

if __name__ == "__main__":
    main()
```ソリューションは入力を読み取り、それを保存します。`current`分解用。 各ステップで、最下位の基底が計算されます。$M$モジュロを使用した数字。 数字が 1 を超える場合は、ただちに「NO」を出力して終了し、それ以上の不必要な計算が行われないようにします。 それ以外の場合は、次のように除算します。$M$次のより高い力に移行するためです。 終了後、無効な桁が見つからなかった場合は、「YES」が出力されます。 エッジの状態は次のとおりです$N=1$または$N=M$はこのループによって自動的に処理されます。 

## 実用的な例

 ### 例 1

 入力:`2 3`| 現在 | 桁 = 現在の %M | アクション |
 | --- | --- | --- |
 | 2 | 2 % 3 = 2 | 桁 > 1、「NO」を出力 |

 出力：`NO`**説明:** 最小の累乗は 1 と 3 であるため、2 は 3 の個別の累乗の合計として表すことができません。 

### 例 2

 入力:`5 2`| 現在 | 桁 = 現在の %M | アクション |
 | --- | --- | --- |
 | 5 | 5 % 2 = 1 | 続行、現在 = 5 // 2 = 2 |
 | 2 | 2 % 2 = 0 | 続行、現在 = 2 // 2 = 1 |
 | 1 | 1 % 2 = 1 | 続行、現在 = 1 // 2 = 0 |

 出力：`YES`**説明:** 5 = 2^2 + 2^0 = 4 + 1、有効な分解。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log_M N) | 各反復は分割します`current`による`M`、最大 log_M N 反復 |
 | スペース | お(1) | 少数の整変数のみが使用されます。 

N ≤ 1024 および M ≤ 16 の場合、最大反復回数は log_2(1024) = 10 です。この解は 1 秒未満で実行され、使用するメモリは無視できます。

 ## 特殊なケース

 のために`N=1, M=16`、`current`1 から始まり、数字 = 1 が有効です。ループは終了し、「YES」を出力します。 

のために`N=1024, M=2`、ループは各 2 進数を繰り返します。 1024は2^10なので1桁以外は0なので「YES」を出力します。 

のために`N=6, M=2`、分解は 6 % 2 = 0、次に 3 % 2 = 1、次に 1 % 2 = 1、残りの 0 を試行します。1 を超える桁はないため、「YES」を出力します。 待って、確認してください。2 進数の 6 は 110、数字 1、1、0 であり、これは有効です。 訂正: 先ほどの「NO」の例は間違っています。 正しい出力は「YES」になります。 

これは、注意深くトレースすることの重要性を強調しています。 このアルゴリズムは、M 進数の各桁を検査することにより、すべてのエッジ ケースを正しく処理します。
