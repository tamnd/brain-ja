 ## 解決策
 ## 問題の理解

 正方形の格子に分割された小さな長方形のケーキが与えられます。 各正方形にはベリーがあるか、空です。 マウスはケーキの左上隅から開始し、右下隅に到達するまで右または下にのみ移動できます。 目標は、マウスがベリーの摂取量を最大化しようとしている場合に、選択した経路に沿ってベリーの数を食べることになるかを計算することです。 

入力はケーキを次のように表します。`H × W`文字のグリッド、ここで`H`は行数であり、`W`列の数です。 各セルには次のいずれかが含まれます`'*'`ベリーまたは`'.'`空の場合。 出力は単一の整数で、左上隅から右下隅までの有効なパスに沿って収集できるベリーの最大数です。 

制約は非常に厳しいです。`H`そして`W`この小さなサイズにより、大きなグリッドには遅すぎるアプローチを検討することができます。 特に、パスの総数は最大でも`C(H+W-2, H-1)`、最大でも`C(8,4) = 70`。 

明らかではないエッジ ケースは、パスがグリッドのエッジによって制約されている場合、またはベリーが特定の行または列に沿って集まっている場合に発生します。 たとえば、上の行が空で、すべてのベリーが下の行にある場合、常にすぐに見えるベリーを優先する不注意で貪欲なアプローチは、間違ったパスを選択する可能性があります。 グリッドが次の場合には、別のエッジケースが発生します。`1×N`または`N×1`, ここで、マウスの可能なパスは 1 つだけです。 正しいソリューションでは、これらの小さな寸法をエラーなく処理する必要があります。 

## アプローチ

 単純な総当りアプローチでは、左上隅から右下隅まですべての有効なパスが列挙されます。 パスごとに、収集されたベリーの数をカウントし、最大値を返します。 このアプローチが機能するのは、パスの数が組み合わせ的に制限されるためです。`(H+W-2 choose H-1)`。 5×5 グリッドの最悪の場合、これは次のようになります。`C(8,4) = 70`パス、そしてそれぞれのパスが取る`O(H+W)`評価するステップがあり、合計で最大 560 の操作が行われます。 このアプローチはここでは実現可能ですが、より大きなグリッドには一般化できず、正しく実装するのは面倒です。 

より洗練された一般的なアプローチでは、動的プログラミングを使用します。 私たちは定義します`dp[i][j]`左上隅から収集できるベリーの最大数として`(0,0)`セルへ`(i,j)`。 重要な洞察は、細胞に到達することです`(i,j)`、マウスは上のセルから来なければなりません`(i-1,j)`または左のセルから`(i,j-1)`。 したがって、漸化式は次のようになります。`dp[i][j] = max(dp[i-1][j], dp[i][j-1]) + (1 if cell (i,j) has a berry else 0)`。 これにより、問題は単純な条件を埋めるだけになります。`H×W`この表は簡単で正確性を保証します。 ブルートフォースのアイデアはすべてのパスを検査するため機能しますが、動的プログラミングでは重複する部分問題を活用して、同じ結果をより効率的かつクリーンに計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(H+W-2, H-1)・(H+W)) | O(H+W) | ここで実行可能ですが、冗長です |
 | 動的プログラミング | O(H・W) | O(H・W) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.高さを読み取る`H`と幅`W`、ケーキのグリッドを文字列のリストとして保存します。 
2. を初期化します。`dp`サイズ表`H×W`、 どこ`dp[i][j]`セルに到達するまでに収集された最大のベリーを保存します`(i,j)`。 
3. すべてのセルを反復処理します。`(i,j)`行優先の順序で。 各セルについて、そのセルに到達するための最適な方法を決定します。 

- もし`i > 0`、 考慮する`dp[i-1][j]`上のセルから収集されたベリーの数として。 
- もし`j > 0`、 考慮する`dp[i][j-1]`左側のセルから収集されたベリーの数として。 
- これら 2 つの値の最大値を取得します。 もし`(i,j)`ベリーがある場合は、1を追加します。 
- 特殊なケース: 左上のセル`(0,0)`上または左に隣接するものがないため、`dp[0][0]`ベリーがある場合は 1、そうでない場合は 0。 
4. テーブルに記入した後、次の値が表示されます。`dp[H-1][W-1]`マウスが有効なパスに沿って収集できるベリーの最大数です。 

これが機能する理由は、`dp[i][j]`セルに至るまで常に最適解を正確に表現します`(i,j)`。 マウスは右または下にしか移動できないため、任意のパスを`(i,j)`左または上から来る必要があります。 各ステップで 2 つの可能性の最大値を取得し、現在のセルのベリーが存在する場合はそれを追加することで、最適なパスを決して過小評価しないようにします。 この不変条件はグリッド全体に当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

H, W = map(int, input().split())
cake = [input().strip() for _ in range(H)]

dp = [[0] * W for _ in range(H)]

for i in range(H):
    for j in range(W):
        best_from_above = dp[i-1][j] if i > 0 else 0
        best_from_left = dp[i][j-1] if j > 0 else 0
        dp[i][j] = max(best_from_above, best_from_left) + (1 if cake[i][j] == '*' else 0)

print(dp[H-1][W-1])
```このコードは DP テーブルを初期化し、行優先の順序で反復して、収集可能な最大のベリーを各セルに入力します。 次のことを確認することで境界を処理します。`i > 0`そして`j > 0`。 最後のセルには答えが含まれています。 使用する`strip()`入力の末尾の改行文字がセルの内容の比較に影響を与えないようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(H・W) | 各セルは 1 回訪問され、各計算は O(1) |
 | スペース | O(H・W) | サイズ H×W | の DP テーブルを 1 つ保管します。 

H,W ≤ 5 の場合、これは無視できる程度であり、時間とメモリの制限内で十分に完了します。
