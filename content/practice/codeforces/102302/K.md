 ## 解決策
 ## 問題の理解

 整数配列があります`C`長さの`N`。 キャンディ シーケンスは、この配列の空でない連続部分であり、その値はその要素の合計です。 必要な答えは、有効なシーケンスが発生する位置の数ではありません。 等しい値のシーケンスはマージされるため、`[4]`5 回発生しても 1 つの異なるシーケンスとしてカウントされますが、`[4]`そして`[4, 4]`長さが違うので違います。 

最初の行は、`N`、その後に許容される下限値と上限値が続きます`L`そして`R`。 2 行目にはキャンディーの値が含まれています。 合計が包含区間内にある異なる連続配列の数が必要です。`[L, R]`。 

と`N`と同じくらい大きい`5 * 10^5`、すべてを列挙します`N(N+1)/2`間隔はすでに約を与えています`1.25 * 10^11`最悪の場合の候補者も。 二次アルゴリズムは、4 秒の制限がサポートできる速度をはるかに超えています。 キャンディーの値は負の値になることもあるため、単調スライディング ウィンドウに基づく手法は適用されません。 の境界`L`そして`R`到着`10^18`, 個体値が到達するまでの間`10^9`したがって、固定幅の整数を使用する言語では、接頭辞の合計と比較を 64 ビット算術で処理する必要があります。 

一般に、誤った解決策が発生するケースが 3 つあります。 

考慮する```
2 2 2
2 2
```の発生が 2 つあります`[2]`、しかし、それらは同じ異なるシーケンスを表します。 正しい答えは、`1`。 個別のシーケンスの代わりに有効な間隔をカウントするソリューションは、次の結果を返します。`2`。 

負の値を指定すると、通常の 2 ポインター引数が壊れます。 例えば、```
3 -1 1
1 -1 1
```有効な個別シーケンスは次のとおりです。`[1]`、`[-1]`、`[1,-1]`、`[-1,1]`、 そして`[1,-1,1]`、与える`5`。 右端を拡張すると常に合計が増加すると仮定するスライディング ウィンドウでは、この配列について正しく推論できません。 

境界は包括的です。 のために```
2 2 2
2 3
```のみ`[2]`合計が正確にあります`2`、したがって、答えは次のとおりです`1`。 どちらかの境界に厳密な不等式を誤って使用した解では、このシーケンスが失われます。 

## アプローチ

 直接的なアプローチでは、エンドポイントのすべてのペアが考慮され、プレフィックス合計を使用して現在の合計が維持されます。 各間隔について、その合計が次の範囲にあるかどうかを確認できます。`[L,R]`対応するシーケンスをセットに挿入します。 これは正しいです。すべての連続するシーケンスには 1 対のエンドポイントがあり、セットによって繰り返されるシーケンスが削除されるからです。 問題は間隔の数です。`N = 500000`、 がある`N(N+1)/2 = 125000250000`彼らのうち。 各間隔をハッシュで表すと、おおよそ次のようになります。`1.25 * 10^11`実際の配列を維持または比較するコストを考慮する前に、これはすでに不可能です。 

重要な観察は、連続したシーケンスは元の配列の一部の接尾辞の接頭辞であるということです。 位置から始まるサフィックスを修正するとします`i`。 プレフィックスには長さがあります`1, 2, ..., N-i`。 辞書編集順に接尾辞を処理する場合、前の接尾辞によってすでに表されていた接頭辞は、前の接尾辞との最も長い共通接頭辞までの接頭辞となります。 

させて`lcp[i]`で始まるサフィックスに関連付けられた LCP 長になります。`i`ここで、前の接尾辞は、接尾辞配列の順序で直前の接尾辞を意味します。 次にサフィックス`i`プレフィックス長を正確に提供します

 [
 lcp[i]+1,\ lcp[i]+2,\ \ldots,\ N-i。 
]

 これは、個別の部分文字列を数える通常の接尾辞配列の方法ですが、ここでは単純にこれらすべての長さを数えることができません。 合計が以下のものだけを保持しなければなりません`[L,R]`。 

プレフィックス合計は、その条件を範囲クエリに変換します。 定義する

 [
 P[0]=0,\qquad P[j]=C_0+C_1+\cdots+C_{j-1}。 
]

 長さの接頭辞`k`で始まるサフィックスの`i`プレフィックスサム位置で終了`j=i+k`、その和は

 [
 P[j]-P[i]。 
]

 したがって、プレフィックスは正確に次の場合に有効です。 

[
 P[i]+L \le P[j] \le P[i]+R。 
]

 したがって、サフィックスごとにエンドポイントの位置をカウントする必要があります。`j`インデックス範囲内

 [
 i+lcp[i]+1 \le j \le N
 ]

 プレフィックスの合計が値の範囲に属するもの`[P[i]+L, P[i]+R]`。 

クエリは 2 次元になります。1 つの座標がエンドポイントの位置になります。`j`、もう 1 つはそのプレフィックスの合計です`P[j]`。 オフラインで処理できます。 サフィックスの開始位置を次の基準で並べ替えます`P[i]`。 次に、両方のクエリ境界`P[i]+L`そして`P[i]+R`単調に動きます。 プレフィックスの合計が現在必要な値の範囲内にあるエンドポイントの位置をフェンウィック ツリー内で正確に維持します。 次に、Fenwick プレフィックス クエリは、許可された開始エンドポイントより前に発生するエンドポイントを削除します。 

サフィックス配列自体は、標準の 2 倍化アルゴリズムとカウントソートを使用して構築されており、次のようになります。`O(N log N)`建設時間。 その後、Kasai のアルゴリズムはすべての LCP 値を線形時間で計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) 以上 | 直接集合表現における O(N²) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サフィックス配列を構築します。`C`。 接尾辞配列には、そこから始まる接尾辞の辞書編集順に従ってソートされたすべての開始位置が格納されます。 すべてのキャンディー値よりも小さい固有のセンチネルが内部的に追加されるため、標準のサイクリック シフト 2 倍化アルゴリズムを使用できます。 
2. Kasai のアルゴリズムを使用して、すべてのサフィックスの LCP 値を計算します。 位置のサフィックスの場合`i`、`lcp[i]`は、サフィックス配列の順序で直前にサフィックスを付けた共通のプレフィックスの長さです。 前のサフィックスがない場合、その値はゼロになります。 
3. プレフィックス合計配列を構築する`P`。 エンドポイントの場合`j`、で始まる部分配列の合計`i`そして終わる`j-1`は`P[j] - P[i]`。 
4. で始まるサフィックスの場合`i`、セット

 [
 left_i=i+lcp[i]+1。 
]

 エンドポイントのみ`j >= left_i`このサフィックスが処理されたときに新しい部分文字列を表します。 以前のエンドポイント`left_i`は、以前のサフィックスによってすでに表されているプレフィックスに対応します。 

1. すべての接尾辞の開始位置を並べ替えます`i`による`P[i]`、すべてのエンドポイントの位置を個別に並べ替えます`j`から`1`を通して`N`による`P[j]`。 これにより、プレフィックス合計しきい値を処理できる一般的な順序が決まります。 
2. サフィックスを増加方向にスイープします。`P[i]`。 エンドポイントの位置を含むフェンウィック ツリーを維持する`j`満足のいく

 [
 P[i]+L \le P[j] \le P[i]+R。 
]

 サフィックスは増加方向に処理されるため、`P[i]`、両方の境界は、並べ替えられたエンドポイント リスト内で右にのみ移動します。 上限に達した場合はエンドポイントを追加し、下限を下回った場合はエンドポイントを削除します。 

1. 現在のサフィックスについては、次のようにします。`active`現在フェンウィックツリーにあるエンドポイントの数になります。 Fenwick プレフィックス クエリ`left_i-1`発生が早すぎるアクティブなエンドポイントをカウントするため、

 [
 active-\operatorname{prefixSum}(left_i-1)
 ]

 は、合計が以下に属するこのサフィックスの新しい個別のプレフィックスの正確な数です。`[L,R]`。 

1. この投稿をすべての接尾辞の回答に追加します。 合計は、個別の有効な連続シーケンスの必要な数です。 

**機能する理由** すべての連続するシーケンスは、1 つのサフィックスが出現するプレフィックスですが、同じシーケンスが複数のサフィックスのプレフィックスである場合もあります。 サフィックス配列の順序では、プレフィックスを共有するすべてのサフィックスが連続したグループを形成します。 したがって、サフィックスの場合、前のサフィックスを含む LCP 以下の長さのすべてのプレフィックスはすでに表現されていますが、それより長いプレフィックスはすべて新しいものになります。 値`left_i`まさにこの違いを捉えています。 Fenwick スイープは、合計が両方の包含境界を満たす新しいプレフィックス エンドポイントを正確にカウントします。 すべての個別の有効なシーケンスは 1 つのサフィックスで新しく、カウントされたすべてのプレフィックスが有効であるため、累積された応答には、必要な各シーケンスが 1 回だけ含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_suffix_array(a):
    """Suffix array of an integer array using doubling + counting sort."""
    values = sorted(set(a))
    compress = {x: i + 1 for i, x in enumerate(values)}

    # 0 is a unique sentinel smaller than every real value.
    s = [compress[x] for x in a] + [0]
    m = len(s)

    # Initial counting sort by the first value.
    alphabet = len(values) + 1
    cnt = [0] * alphabet
    for x in s:
        cnt[x] += 1

    pos = [0] * alphabet
    total = 0
    for i in range(alphabet):
        pos[i] = total
        total += cnt[i]

    p = [0] * m
    for i, x in enumerate(s):
        p[pos[x]] = i
        pos[x] += 1

    # Initial equivalence classes.
    c = [0] * m
    classes = 1
    c[p[0]] = 0
    for i in range(1, m):
        if s[p[i]] != s[p[i - 1]]:
            classes += 1
        c[p[i]] = classes - 1

    length = 1

    while length < m:
        # Shift every suffix start left by 'length'.
        pn = [0] * m
        for i, x in enumerate(p):
            y = x - length
            if y < 0:
                y += m
            pn[i] = y

        # Counting sort by the first half's class.
        cnt = [0] * classes
        for x in pn:
            cnt[c[x]] += 1

        pos = [0] * classes
        total = 0
        for i in range(classes):
            pos[i] = total
            total += cnt[i]

        p_new = [0] * m
        for x in pn:
            cl = c[x]
            p_new[pos[cl]] = x
            pos[cl] += 1

        # Recompute classes for pairs of length 2 * length.
        c_new = [0] * m
        new_classes = 1
        c_new[p_new[0]] = 0

        for i in range(1, m):
            cur = p_new[i]
            prev = p_new[i - 1]

            cur_second = cur + length
            if cur_second >= m:
                cur_second -= m

            prev_second = prev + length
            if prev_second >= m:
                prev_second -= m

            if (
                c[cur] != c[prev]
                or c[cur_second] != c[prev_second]
            ):
                new_classes += 1

            c_new[cur] = new_classes - 1

        p = p_new
        c = c_new
        classes = new_classes
        length <<= 1

    # The sentinel suffix is always first.
    return p[1:]

def build_lcp(a, sa):
    """lcp[i] = LCP of suffix i with its previous suffix in SA order."""
    n = len(a)
    rank = [0] * n

    for r, pos in enumerate(sa):
        rank[pos] = r

    lcp = [0] * n
    h = 0

    for i in range(n):
        r = rank[i]

        if r == 0:
            h = 0
            continue

        j = sa[r - 1]

        while i + h < n and j + h < n and a[i + h] == a[j + h]:
            h += 1

        lcp[i] = h

        if h:
            h -= 1

    return lcp

def solve():
    n, L, R = map(int, input().split())
    a = list(map(int, input().split()))

    if n == 0:
        print(0)
        return

    sa = build_suffix_array(a)
    lcp = build_lcp(a, sa)

    # P[j] is the sum of a[0:j].
    pref = [0] * (n + 1)
    s = 0
    for i, x in enumerate(a):
        s += x
        pref[i + 1] = s

    # Query suffixes by P[i].
    query_order = sorted(range(n), key=pref.__getitem__)

    # Endpoint j is represented by prefix sum P[j], j in [1, n].
    endpoint_order = sorted(range(1, n + 1), key=pref.__getitem__)

    # Fenwick tree over endpoint positions.
    bit = [0] * (n + 1)

    def add(idx, delta):
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def prefix_sum(idx):
        result = 0
        while idx > 0:
            result += bit[idx]
            idx -= idx & -idx
        return result

    hi = 0
    lo = 0
    active = 0
    answer = 0

    for i in query_order:
        low_value = pref[i] + L
        high_value = pref[i] + R

        # Add all endpoints that have entered the upper bound.
        while hi < n and pref[endpoint_order[hi]] <= high_value:
            j = endpoint_order[hi]
            add(j, 1)
            hi += 1
            active += 1

        # Remove endpoints that are below the lower bound.
        while lo < hi and pref[endpoint_order[lo]] < low_value:
            j = endpoint_order[lo]
            add(j, -1)
            lo += 1
            active -= 1

        # Only lengths greater than lcp[i] are new.
        left = i + lcp[i] + 1

        if left <= n:
            too_early = prefix_sum(left - 1)
            answer += active - too_early

    print(answer)

if __name__ == "__main__":
    solve()
```サフィックス配列の構築では、まずキャンディーの値を圧縮して、センチネルをゼロで安全に表現し、すべての実数値を正の整数で表現できるようにします。 倍加ループは、等価クラスのペアによって巡回シフトをソートします。 センチネルは一意で最小であるため、末尾のサフィックスを削除すると、元の配列の通常のサフィックス配列が残ります。 

LCP 構築では、逆接尾辞配列を使用して、各開始位置の前の接尾辞を検索します。 Kasai が以前の一致長を再利用すると、個々の LCP 値が大きくなる可能性があるにもかかわらず、文字比較の合計数が線形になります。 

プレフィックスの合計`pref[j]`は、部分配列の直後の配列の終点を表します。 これが、フェンウィック ツリーで使用されるエンドポイント インデックスが次のとおりである理由です。`1`を通して`N`、サフィックスの開始位置は`0`を通して`N-1`。 これら 2 つの座標系を混合すると、off-by-one エラーの一般的な原因になります。 

フェンウィック スイープでは、単なる上限ではなく値の間隔が維持されます。 で始まるサフィックスの場合`i`、エンドポイント`j`はまさに次の場合に有効です`pref[j]`の間にあります`pref[i] + L`そして`pref[i] + R`。 サフィックスは次のように並べられているため、`pref[i]`、どちらの境界も単調であるため、すべてのエンドポイントがフェンウィック ツリーに出入りするのは最大 1 回だけです。 

の`left`式には他の重要な境界が含まれています。 長さが次と等しいプレフィックス`lcp[i]`は前のサフィックスにすでに存在しているため、最初の新しい長さは次のようになります。`lcp[i] + 1`。 エンドポイントは`i + length`、最初の新しいエンドポイントは`i + lcp[i] + 1`。 

Python の整数には任意の精度があるため、合計するとおおよそ次のようになります。`5 * 10^14`そして最終的な答えは`1.25 * 10^11`特別なオーバーフロー処理は必要ありません。 固定幅言語では、符号付き 64 ビット整数で十分です。 

## 実用的な例

 サンプル 1 の場合、```
5 5 10
1 2 3 4 5
```プレフィックスの合計は`[0, 1, 3, 6, 10, 15]`。 すべてのサフィックスは他のすべてのサフィックスとは異なるため、すべての LCP 値はゼロになります。 The table shows the direct`[L,R]`スイープ。 

| 私 | lcp[i] | P[i] | 有効な P[j] 範囲 | 左 | active | 早すぎる | 貢献 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | [5、10] | 1 | 2 | 0 | 2 |
 | 1 | 0 | 1 | [6、11] | 2 | 2 | 0 | 2 |
 | 2 | 0 | 3 | [8、13] | 3 | 1 | 0 | 1 |
 | 3 | 0 | 6 | [11、16] | 4 | 1 | 0 | 1 |
 | 4 | 0 | 10 | [15, 20] | 5 | 1 | 0 | 1 |

 The five contributions are`2 + 2 + 1 + 1 + 1 = 7`。 それらは以下に対応します`[3,4]`、`[1,2,3,4]`、`[2,3,4]`、`[4,5]`、 そして`[5]`適切な接尾辞と接頭辞の表現で。 それぞれの間に合計があります`5`そして`10`。 

サンプル 2 の場合、```
5 5 10
1 2 3 4 4
```プレフィックスの合計は`[0, 1, 3, 6, 10, 14]`。 位置で始まるサフィックス`3`そして`4`は`[4,4]`そして`[4]`。 サフィックス配列の順序で、`[4]`前に来る`[4,4]`、 それで`lcp[3] = 1`。 まさにこれが発生を防ぐものです`[4]`長い接尾辞の内側は 2 回目にカウントされないようにします。 

| 私 | lcp[i] | P[i] | 有効な P[j] 範囲 | 左 | アクティブ | 早すぎる | 貢献 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | [5、10] | 1 | 2 | 0 | 2 |
 | 1 | 0 | 1 | [6、11] | 2 | 2 | 0 | 2 |
 | 2 | 0 | 3 | [8、13] | 3 | 1 | 0 | 1 |
 | 3 | 1 | 6 | [11、16] | 5 | 1 | 0 | 1 |
 | 4 | 0 | 10 | [15、20] | 5 | 0 | 0 | 0 |

 寄付金の合計は`2 + 2 + 1 + 1 = 6`。 繰り返される値`4`は、出現回数を単純に独立してカウントできない理由を示しています。 単一のキャンディーのシーケンス`[4]`はすでに最後の位置から始まるサフィックスによって表されていますが、`[4,4]`は真に新しいシーケンスです。

 のために`N = 5 * 10^5`、二次列挙には約`1.25 * 10^11`一方、最適解は線形サイズの配列に対して対数のパスを実行します。 1024 MB というメモリ制限は、ここで使用される配列の線形コレクションを余裕で超えています。 4 秒の制限は、`O(N log N)`すべての部分配列を列挙するアプローチではなく、ソリューションです。

    old_stdout = sys.stdout
    old_input = input

# Provided samples
assert run("5 5 10\n1 2 3 4 5\n") == "7", "sample 1"
assert run("5 5 10\n1 2 3 4 4\n") == "6", "sample 2"

# Minimum-size input
assert run("1 1 1\n1\n") == "1", "single candy"

# Duplicate occurrences must count only once
assert run("2 2 2\n2 2\n") == "1", "duplicate sequence"

# Negative values, with inclusive lower and upper bounds
assert run("3 -1 1\n1 -1 1\n") == "5", "negative values"

# Maximum-size, all-equal input.
# Every distinct sequence is determined only by its length.
n = 500000
max_input = f"{n} 0 0\n" + " ".join(["0"] * n) + "\n"
assert run(max_input) == str(n), "maximum size"

 ## 特殊なケース

 重複発生の場合は、```
2 2 2
2 2
```接尾辞は`[2]`そして`[2,2]`。 サフィックス配列の順序で、`[2]`最初に来て、`[2,2]`LCP は次のとおりです`1`それと一緒に。 最初のサフィックスが貢献します`[2]`、一方、2 番目のサフィックスは長さ 1 のプレフィックスを提供することを禁止されており、提供できるのは長さ 1 のプレフィックスのみです。`[2,2]`。 以来`[2,2]`合計があります`4`、 のみ`[2]`有効なままです。`1`。 

負の値の場合、```
3 -1 1
1 -1 1
```プレフィックスの合計は`0,1,0,1`。 このアルゴリズムでは、プレフィックスの合計がエンドポイントとともに増加することは想定されていません。 代わりに、すべてのプレフィックスの合計を並べ替えて、値の範囲のクエリを実行します。 サフィックス配列部分は数値の合計とは独立して重複を処理しますが、フェンウィック ツリーはプレフィックスの合計の任意の順序を処理します。 The five distinct valid sequences are`[1]`、`[-1]`、`[1,-1]`、`[-1,1]`、 そして`[1,-1,1]`、結果は次のようになります`5`。 

正確な境界については、```
2 2 2
2 3
```プレフィックスの合計は`0,2,5`。 最初の位置から始まるサフィックスの場合、必要なプレフィックス合計間隔は次のとおりです。`[4,4]`したがって、エンドポイントは受け入れられません。 2 番目の位置から始まるサフィックスの場合、間隔は次のようになります。`[4,4]`同様に、その単一のエンドポイントにはプレフィックス合計があります`5`, なのでこれも範囲外です。 この例には実際には有効なシーケンスがないため、出力は次のようになります。`0`。 配列が代わりにある場合```
2 2 2
2 3
```単一の要素`2`合計が正確にあります`2`そして受け入れられなければなりません。 エンドポイント条件の正しい解釈は次のとおりです。`P[i]+L <= P[j] <= P[i]+R`、厳密な不平等ではありません。 

最大サイズがすべて等しい場合、```
500000 0 0
0 0 0 ... 0
```空でないシーケンスはすべて合計がゼロになります。 ただし、個別のシーケンスは、1 つのゼロ、2 つのゼロ、3 つのゼロなどから構成される文字列だけです。`500000`ゼロ。 suffix-array LCP 値は、繰り返されるプレフィックスを削除し、可能な長さごとに 1 つの寄与を残します。 結果的に答えは`500000`、アルゴリズムは引き続き入力全体を処理します。`O(N log N)`時間。
