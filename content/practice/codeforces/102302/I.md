 ## 解決策
 ## 問題の理解

 すべてのポケミノを平面内の点 ((A,D)) として考えてください。攻撃は水平座標、防御は垂直座標です。 ポケミノは、ラーシュが所有するポイントがなく、交配によって取得できるポイントがなく、その 2 つの座標が両方とも厳密に大きい場合に役立ちます。 

繁殖には 2 ポイントの加重平均がかかります。 ブリーディングを繰り返すと、キャプチャされたすべてのポイントの凸包が正確に得られます。 では、実際の幾何学的問題は次のとおりです。キャプチャされた点の中で、凸包のどの点にも厳密に支配されていない点はどれでしょうか?

 答えは、凸包の右上の境界によって表されます。 ポイントを攻撃別に左から右に分類すると、有用なポイントが凸状の連鎖を形成します。 新しいポイントにより、そのチェーン上の複数の連続したポイントが役に立たなくなりますが、2 つの分離された領域を独立して消滅させることはできません。 この地域性により、オンラインの船体メンテナンス アルゴリズムが可能になります。 

キャプチャは最大 (10^5) 個あり、攻撃と防御はそれぞれ (10^9) 個まで可能です。 二次アルゴリズムでは、すでに約 (10^{10}) 個の演算が必要となり、1 秒の制限をはるかに超えています。 合計作業量はおよそ (O(N\log N)) 必要です。 座標サイズは、幾何学的テストを正確な整数演算で実行する必要があることも意味します。 C++ では、外積が (10^{18}) 程度に達する可能性があるため、これには 64 ビット整数が必要です。 Python の整数は、この範囲を自動的に処理します。 

攻撃値が等しい場合は特別な処理が必要です。 攻撃には厳密な改善が必要であるため、同じ攻撃を持つ 2 つのポケミノが互いに厳密に支配することはできません。 例えば、```
3
5 1
5 3
5 2
```出力があります```
0
0
0
```各攻撃に対して最高の防御力のみを維持する不注意な実装では、他の 2 つのポケミノが誤って破棄されてしまいます。 この垂直グループが正しく表現されるように、防御力を下げることによって同等の攻撃を分類します。 

2 番目の罠は、厳密な不平等です。 ポケミノが他の 2 つを結合する減少するセグメント上に正確に存在する場合、それは依然として役に立ちます。 例えば、```
3
0 10
5 5
10 0
```出力があります```
0
0
0
```中央のポケミノはエンドポイントから交配できますが、結果として得られるポイントは正確に ((5,5)) であり、厳密にはそれより優れているわけではありません。 すべての共線点を削除する実装では、間違った答えが得られます。 

3 番目の罠は、親が個別にそうしていない場合でも、凸の組み合わせがポケミノを支配できる可能性があることです。 例えば、```
3
0 10
10 0
5 4
```出力があります```
0
0
1
```最初の 2 つのポケミノを同じ重みで交配すると ((5,5)) が生成され、これが厳密に ((5,4)) を支配します。 直接のペアごとの優位性のみをチェックすると、このケースは見逃されます。 

最後に、あるポイントは、後のポイントがそのポイントを直接支配しているという理由だけで役に立たない場合があります。 のために```
3
0 0
2 2

```出力は```
0
0
1
```((1,1)) が到着すると、((2,2)) はすでに所有されており、それを支配します。 3 点の方向のみをチェックするハルの実装では、維持されるチェーンの最初の点を明示的に処理しない限り、このエンドポイントのケースを見逃す可能性があります。 

## アプローチ

 最も直接的なアプローチは、キャプチャのたびに幾何学的構造を再構築することです。 入力のプレフィックスごとに、現在所有されているすべてのポケミノの凸包を構築し、どのキャプチャされたポイントがその包の一部のポイントによって厳密に支配されているかを判断できます。 標準的な船体の構築コストは、長さ (i) のプレフィックスに対して (O(i\log i))、その後に線形スキャンが続きます。 これをすべてのプレフィックスに対して繰り返すとコスト (O(N^2\log N)) がかかります。 (N=10^5) の場合、これは (10^{11}) 個の比較レベルの操作に相当するため、最初から再構築しても 1 秒の制限には遠く及びません。 

凸包には繁殖を繰り返すことで得られるすべての点が含まれているため、強引なアプローチは正しいです。 問題は、連続する接頭辞が挿入された点が 1 つだけ異なるにもかかわらず、総当たりの解決策では以前の幾何学的作業がすべて捨てられてしまうことです。 

重要な観察は、有用なポイントには非常に厳密な順序があるということです。 攻撃力を上げることで並べ替え、同じ攻撃力については防御力を下げることで並べ替えます。 連続する 3 つの候補 (L、P、R) を考えます。 (P) がセグメント (LR) の厳密に下にある場合、(L) と (R) の凸状の組み合わせは、(P) とまったく同じ攻撃力と厳密に大きな防御力を持ちます。 したがって、(P) は役に立たないので削除できます。 

外積を使用すると、この条件は次のようになります。 

[
 (L-P)\times(R-P)<0。 
]

 その点が順序付けされた構造の最初の点である場合、左近傍は存在しません。 直接の後継者がより大きな攻撃力とより大きな防御力を備えている場合、それはまったく役に立ちません。 最後のポイントであれば攻撃力の大きい所有ポイントがないので無駄にはなりません。 

重要な動的プロパティは、1 つのポイントを挿入すると、その挿入位置の周囲にある連続する隣接ポイントのみを無効にできるということです。 ポイントが削除されると、それを戻す必要はありません。それ以降のキャプチャでは凸包が拡大されるだけであるためです。 したがって、すべての Pokemino は 1 回挿入され、最大 1 回削除されます。 バランスの取れた二分探索ツリーで順序付けされたチェーンを維持し、挿入または削除ごとに (O(\log N)) の作業を与えることができます。 

Python には組み込みのバランスのとれた順序セットが提供されていないため、以下の実装ではランダム化された treap が使用されます。 予想される時間 (O(\log N)) で挿入、削除、先行操作、および後続操作をサポートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのプレフィックスの船体を再構築する | (O(N^2\log N)) | (O(N)) | 遅すぎる |
 | トレプ付きダイナミック凸チェーン | (O(N\log N)) が期待されます | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポケミノをポイント ((x,y)=(A,D)) として表し、(x) を増加させることでポイントを順序付けします。 2 つの点が同じ (x) を持つ場合は、(y) が大きい方から順序付けします。 treap はキー ((x,-y)) を使用して、この順序を正確に実装します。 

このタイブレークが必要なのは、攻撃が等しいポケミノが攻撃を通じて厳密にお互いを支配できないためです。 
2. 現在有用なポケミノのみを維持します。 この順序セットでは、ポイントは最大 1 つの先行ポイントと 1 つの後続ポイントを持つことができるため、ポイントが役に立たなくなったかどうかをローカルで判断できます。 
3. 新しい点(P)を挿入したら、まず(P)自体が駄目かどうかを確認します。 それが最初の点であり、その後続 (R) が (R_x>P_x) および (R_y>P_y) を満たす場合、(R) が (P) を直接支配するため、(P) はすぐに削除されます。 
4. (P) に先行者 (L) と後続者 (R) の両方がある場合、次を計算します。 

## (L_x-P_x)(R_y-P_y)

 (L_y-P_y)(R_x-P_x)。 
]

この値が負の場合、(P) はセグメント (LR) の厳密に下に位置します。 (L)と(R)の適切な凸の組み合わせは、(P)と同じ攻撃力とより高い防御力を持つため、(P)は役に立ちません。 
5. 新しいポイントが残っている場合は、その前のポイントを繰り返し検査します。 その前任者が同じ役に立たないテストを満たした場合は常に、それを消去します。 挿入によっていくつかの連続したポイントが廃止された可能性があるため、これは先行ポイントが有効になるまで継続されます。 
6. 後続品も同様に繰り返し検査します。 役に立たなくなった後継者をすべて消去します。 
7. 無効なポイントをすべて削除すると、トレプには有用なポケミノが正確に含まれます。 (i) ポケミノが捕獲され、トレプに (s) ポイントが含まれている場合、答えは (i-s) です。 

ローカルテストで十分である理由は、凸連鎖の不変条件が維持されているためです。 連続した保持ポイントは、凸包の関連する右上の境界を形成します。 2 つの隣接点を接続するセグメントの下の点は、それらの隣接点を繁殖させることによって到達可能であり、厳密に支配されます。 逆に、保持されているすべての内部点が隣接する弦上またはその上にあり、端点が直接支配条件を満たす場合、保持されているチェーンからの凸状の組み合わせは厳密にはより優れた点を作成できません。 ポイントの挿入では、この境界の連続部分のみを置き換えることができるため、無効な先行および後続を削除すると、不変式が完全に復元されます。 

同一線上の点は意図的に保持されます。 減少するセグメント上の同一線上の点は、厳密にはセグメントの端点によって支配されるわけではありません。 正の勾配の共線構成は、支配的なポイントが維持されているチェーンに入るときに、エンドポイントの支配性テストによって処理されます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline
sys.setrecursionlimit(1_000_000)

class Node:
    __slots__ = ("x", "y", "key", "prio", "left", "right")

    def __init__(self, x, y, prio):
        self.x = x
        self.y = y
        self.key = (x, -y)
        self.prio = prio
        self.left = None
        self.right = None

seed = 712367821

def rng():
    global seed
    seed ^= (seed << 13) & 0xFFFFFFFF
    seed ^= seed >> 17
    seed ^= (seed << 5) & 0xFFFFFFFF
    seed &= 0xFFFFFFFF
    return seed

def rotate_right(root):
    child = root.left
    root.left = child.right
    child.right = root
    return child

def rotate_left(root):
    child = root.right
    root.right = child.left
    child.left = root
    return child

def insert(root, node):
    if root is None:
        return node

    if node.key < root.key:
        root.left = insert(root.left, node)
        if root.left.prio < root.prio:
            root = rotate_right(root)
    else:
        root.right = insert(root.right, node)
        if root.right.prio < root.prio:
            root = rotate_left(root)

    return root

def merge(left, right):
    if left is None:
        return right
    if right is None:
        return left

    if left.prio < right.prio:
        left.right = merge(left.right, right)
        return left
    else:
        right.left = merge(left, right.left)
        return right

def erase(root, key):
    if root is None:
        return None

    if key == root.key:
        return merge(root.left, root.right)

    if key < root.key:
        root.left = erase(root.left, key)
    else:
        root.right = erase(root.right, key)

    return root

def predecessor(root, key):
    ans = None
    while root is not None:
        if root.key < key:
            ans = root
            root = root.right
        else:
            root = root.left
    return ans

def successor(root, key):
    ans = None
    while root is not None:
        if root.key > key:
            ans = root
            root = root.left
        else:
            root = root.right
    return ans

def cross(a, p, b):
    return (a.x - p.x) * (b.y - p.y) - \
           (a.y - p.y) * (b.x - p.x)

def inside(root, p):
    left = predecessor(root, p.key)
    right = successor(root, p.key)

    if right is None:
        return False

    if left is None:
        return right.x > p.x and right.y > p.y

    return cross(left, p, right) < 0

def solve():
    n = int(input())
    root = None
    useful = 0
    answer = []

    for _ in range(n):
        x, y = map(int, input().split())
        p = Node(x, y, rng())

        root = insert(root, p)
        useful += 1

        if inside(root, p):
            root = erase(root, p.key)
            useful -= 1
        else:
            while True:
                left = predecessor(root, p.key)
                if left is None or not inside(root, left):
                    break
                root = erase(root, left.key)
                useful -= 1

            while True:
                right = successor(root, p.key)
                if right is None or not inside(root, right):
                    break
                root = erase(root, right.key)
                useful -= 1

        answer.append(str(_ + 1 - useful))

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```の`Node`クラスには、2 つの座標、順序付けキー、ランダム化された優先順位、および 2 つの treap の子が格納されます。 鍵となるのは`(x, -y)`したがって、キーが小さいほど攻撃が小さくなり、攻撃が等しい場合は防御が大きくなります。 

treap 操作は、幾何学的アルゴリズムに必要な順序セット操作を実装します。 回転では、座標の順序を維持しながら、ランダム化された優先順位のヒープ特性が維持されます。`predecessor`そして`successor`構造全体を横断することなく、点のすぐ隣を見つけます。 の`inside`関数は幾何学的なコアです。 これ以上の攻撃力を持つものはないので、最後のポイントを無駄にすることはできません。 最初のポイントには直接優勢テストが必要です。 他のすべての点は外積を使用してテストされます。 

挿入手順では、まずポイントを追加し、有効なポイントの数を増やします。 新しいポイント自体が無効な場合、そのポイントはすぐに削除されます。 そうしないと、新しいポイントによってチェーンが変更されたため、その先行ポイントと後続ポイントが無効になる可能性があります。 2 つの while ループは、それらの連続した無効なポイントを削除します。 

変数`useful`トレプにサブツリーサイズのフィールドが必要なくなる。 挿入するたびに 1 回増加し、削除するたびに 1 回減少します。 削除の合計数は最大 (N) であるため、期待される treap 操作の合計数は (O(N\log N)) のままです。 

浮動小数点演算は使用されません。 外積は整数で直接評価されるため、共線点付近の精度誤差が回避されます。 Python の任意精度の整数は、座標が (10^9) に近い場合にもオーバーフローを回避します。

 ## 特殊なケース

 同等の攻撃を行うには、次の点を考慮してください。```
3
5 1
5 3
5 2
```Treap 内の順序は次のとおりです。`(5,3)`、`(5,2)`、`(5,1)`。 を超える攻撃力を持つポイントはありません`5`したがって、防御が異なっていても、どれも厳密に支配することはできません。 最後のポイントには後続者がないため、自動的に安全になりますが、攻撃が等しい隣接点は、後続者がより大きな攻撃を持たないため、直接支配条件を満たしません。 出力は`0 0 0`。 

減少するセグメント上の同一線上の点の場合、```
3
0 10
5 5
10 0
```中点には外積ゼロがあります。 このアルゴリズムは、外積が厳密に負の場合にのみポイントを削除します。`(5,5)`船体内に留まります。 エンドポイントを繁殖させると再現できる`(5,5)`、ただし、両方の座標で厳密に優れた点を生成することはできません。 出力は`0 0 0`。 

凸支配の場合、```
3
0 10
10 0
5 4
```最初の 2 つのポイントは引き続き役に立ちます。 いつ`(5,4)`到着、その前身は`(0,10)`そしてその後継者は`(10,0)`。 外積は

 [
 (-5)(-4)-(6)(5)=20-30=-10。 
]

 点は、隣接するセグメントを結合するセグメントの厳密に下にあります。 それらの中間点は`(5,5)`、攻撃力は同じで防御力が大きいので、`(5,4)`が削除され、答えは次のようになります`1`。 

エンドポイントでの直接支配の場合、```
3
0 0
2 2
1 1
```要点`(0,0)`が削除されるとき`(2,2)`後続の方が両方の座標で大きいため、 が到着します。 3 番目のポイント`(1,1)`の後に挿入されます`(0,0)`すでに消えてしまったので、`(2,2)`その後継者となり、直接支配します。 出力は`0 0 1`。 このケースは、最初の点の条件を製品間テストだけで置き換えることができない理由を説明しています。 

For the maximum-size boundary case, all (100000) points can have attack`0`と間の明確な防御`0`そして`10^9`。 厳密な支配にはより大きな攻撃が必要なため、防御に関係なくすべてのポイントが役に立ちます。 treap は引き続きポイントごとに 1 つの挿入を実行し、削除は発生しないため、アルゴリズムは予想される (O(N\log N)) 実行時間内に留まります。
