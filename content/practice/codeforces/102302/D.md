 ## 問題の理解

 サミュエロのテキストは文字列です`s`、そしてロッパが推測した隠しメッセージは別の文字列です`t`。 からいくつかの文字を削除できれば、推測は正しいと考えられます。`s`残りの文字は元の順序のままで正確に取得します`t`。 言い換えると、`t`の部分列である必要があります`s`。 

たとえば、`threeyellowfurryfiends`、に必要な文字`hellofriend`これらは正しい順序で表示されますが、それらの間に無関係な文字が多数出現します。 連続した位置ではなく、相対的な順序のみを考慮します。 

どちらの文字列にも最大で次の文字列を含めることができます`10^6`文字。 このサイズでは、二次ループ内で位置のペアを繰り返し検査するアプローチは除外されます。 100 万文字の場合、`O(nm)`アルゴリズムは最大で実行できます`10^12`1 秒の制限をはるかに超えた操作。 意図したソリューションでは、文字列を基本的に 1 回処理して、文字列の全長に線形時間を与える必要があります。 メモリ制限により、`O(nm)`動的プログラミング テーブルは、100 万×100 万のエントリが膨大な量のメモリを必要とするため、非現実的です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 まず、2 つの文字列は同じ長さにすることができます。 例えば、```

## アプローチ

 直接的ではありますが、不必要にコストがかかるアプローチは、動的プログラミング テーブルを構築することです。 させて`dp[i][j]`最初かどうかを説明します`j`の登場人物`t`最初の部分列として取得できます`i`の登場人物`s`。 すべてのペアについて`(i, j)`、無視するかどうかを決定します`s[i - 1]`、または、文字が一致した場合、それを次の文字として使用します。`t`。 これは正しいです。なぜなら、考えられるすべてのサブシーケンスは現在の文字を使用するか、または使用しないかのいずれかだからです。 

問題は州の数です。 おおよそあります`n * m`ペア、ここで`n = len(s)`そして`m = len(t)`。 最大制限では、それは約`10^12`州。 このようなテーブルを保存することさえメモリ制限の下では不可能であり、それを計算するのは非常に遅すぎます。 

テーブル全体を削除する観察結果は、テーブルの接頭辞を一致させるすべての可能な方法を覚える必要がないということです。`t`。 現在キャラクターを探しているとします。`t[j]`。 すべてのポジションの中で、`s`その文字が一致する可能性がある場合、可能な限り早い位置を取ることは常に、後の位置を取ることと少なくとも同じくらい効果があります。 初期の一致により、少なくとも同じ量の残りの文字列が残りの部分で使用できるようになります。`t`。 

これにより貪欲スキャンが行われます。 加工いたします`s`次の文字へのポインタを保持しながら、左から右へ`t`私たちに必要なこと。 現在のキャラクターが`s`そのターゲット文字と一致する場合、それを消費し、ターゲット ポインタを進めます。 ターゲットポインタが末尾に達すると、`t`、推測全体が正常に埋め込まれました。 もし`s`が最初に終了するため、有効な埋め込みが存在しません。 

ブルートフォース DP は、すべてのプレフィックスの組み合わせを明示的に考慮するため機能しますが、組み合わせが多すぎるために失敗します。 貪欲な観察により、現在のターゲット キャラクターの最も早い実行可能な位置のみを保持し、問題を 1 つのパスに減らすことができます。`s`。

 ## アルゴリズムのチュートリアル

 1.読む`s`そして`t`、ポインタを作成します`j`最初はゼロに等しい。 ポインタは次の最初の文字を表します。`t`それはまだ一致していません。 
2.すべての文字をスキャンします`c`の`s`左から右へ。 もし`j`まだ中にいます`t`そして`c == t[j]`、この出現を使用します`c`次に必要な文字と一致し、インクリメントします`j`。 
3. もし`j`と等しくなる`len(t)`、のすべての文字`t`のポジションでのマッチングが増加しています`s`、したがって、答えは次のとおりです`YES`。 これ以上の文字は関係ないので、すぐに停止できます。 
4. スキャンが終了に達した場合`s`その間`j < len(t)`、前の一致の後、少なくとも 1 つの必須文字が見つかりませんでした。 答えは`NO`。 

貪欲な選択は安全です。`s[i] == t[j]`、位置を使用して`i`それをスキップして、同じ文字の後で出現するものを使用することよりも悪いことはありません。 残りの部分`t`より多くのポジションを持つことでのみ利益を得ることができます`s`現在の試合後に利用可能になります。 

### なぜ効果があるのか

 のプレフィックスを処理した後、`s`、`j`の先頭から連続する最大文字数です。`t`処理されたプレフィックスが貪欲な選択を使用して一致できること。 より具体的には、一致したすべての文字`t`での地位が向上するように割り当てられています`s`、だからいつでも`j`到達する`len(t)`、有効なサブシーケンスを明示的に構築しました。 

逆に、アルゴリズムが次の文字をスキップするたびに、`s`、その文字は次に必要な文字と異なるか、残りの要件がありません。 それが次に必要な文字と一致する場合、そのような最も早い出現を消費しても、その後に使用できるすべての位置がまだ使用可能であるため、その後の一致が不可能になることはありません。 したがって、貪欲スキャンがすべてに一致する前に終了した場合、`t`、以前の一致に代わる選択がなかった場合、有効なサブシーケンスを生成することはできませんでした。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    j = 0

    for c in s:
        if j < len(t) and c == t[j]:
            j += 1
            if j == len(t):
                print("YES")
                return

    print("NO")

if __name__ == "__main__":
    solve()
```入力は次のように読み取られます`readline`これは、長さが 100 万までの文字列に適しています。 の`.strip()`call は、実際の文字列内の英小文字を変更せずに改行を削除します。 

変数`j`必要な唯一の状態です。 常に次の文字を指します。`t`。 いつ`s`その文字が含まれている場合は、先に進みます`j`; それ以外の場合は、現在のキャラクター`s`無視しても問題ありません。 

条件`j < len(t)`アクセスを妨げます`t[j]`推測全体がすでに一致した後。 当面の`YES`return は、残りの部分のスキャンも回避します。`s`ただし、この最適化がなくても、アルゴリズムは線形のままになります。 

Python の整数は任意の精度であり、アルゴリズムは長さによって制限されたポインターのみを維持するため、整数オーバーフローの問題はありません。`t`。 さらに重要なのは、2 次元テーブルがないため、メモリ使用量が 256 MB の制限に比べて小さいままであることです。
