 ## 解決策
 ## 問題の理解

 素数を 1 つ選択し、配列のすべての要素をその素数に変更する必要があります。 要素を 1 つ変更すると、ちょうど 1 回の操作が必要となるため、選択した素数が p の場合、総コストは次のようになります。 

f(p)= i=1 ∑ N ∣a i −p∣

 タスクは、すべての素数 p にわたってこの式の可能な最小値を見つけることです。 

配列には最大 10 5 個の値を含めることができますが、各値は 10 9 までの大きさにすることができます。10 5 個の要素を使用すると、多数の可能なターゲット値を調べ、すべてのターゲットについて配列全体をスキャンするアルゴリズムは非常に高価になります。 制限時間は 1 秒だけなので、およそ O(NlogN)、O(N)、または別の同様に効率的なアプローチが必要です。 大きな値の境界は、単純に 10 9 までのふるいを構築できないことも意味します。 

中心的な数学的困難は、絶対差の合計を最小化するための最適な目標は中央値によって決定されるが、その目標は素数である必要があることです。 すべての素数をチェックせずに、その制限に対処する必要があります。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 のために`1 1`、正解は`2`、近くにある有用なターゲットはプライムだけだからです`2`、要素ごとに 1 回の操作がかかります。 中央値自体が使用可能であると想定する実装では、誤ってゼロが返されます。 

のために`2`入力あり`1 1000000000`、正解は`999999999`。 下位の中央値は`1`、 しかし`1`プライムではありません。 最も近い有用な素数は次のとおりです。`2`、与える`1 + 999999998 = 999999999`。 中央値を下回る素数のみを考慮する実装では、候補がまったく見つかりません。 

次のような偶数サイズの配列の場合`2 3 10 11`、実数値ミニマイザーのセットは、からの間隔全体です。`3`に`10`。 以来`3`、`5`、 そして`7`が素数であるため、それらのいずれかを選択すると最小コストが得られます。 1 つの特定の中央値のみを有効なものとして扱う実装では、この間隔構造が見逃される可能性があります。 

ターゲット素数は、元のすべての値よりも大きくすることもできます。 入力用`1 1000000000`、 例えば、`1000000007`は最高ですが、それよりもはるかに悪いです`2`。 正しい実装では、すべての入力値が最大 10 9 であっても、10 9 を超えて素数の検索を継続できる必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての主要なターゲットを試し、アレイ全体をスキャンして総コストを計算することです。 各候補 p について、 ∑∣a i −p∣ を計算し、最小値を維持します。 これは正しいです。すべての正当な最終配列が正確に 1 つの素数ターゲットに対応するため、すべての素数をチェックすると、最終的には最適なものがチェックされることになります。 

問題は候補者の数だ。 10 9 未満の素数は約 5×10 7 個あるため、たとえ素数検査が無料だったとしても、各候補について 10 5 個の配列要素をスキャンするには、約 5×10 12 個の要素演算が必要になります。 それは1秒にも収まりません。 

重要な観察は、絶対差の合計に対する標準中央値解の背後にあるものと同じです。 ターゲットが素数でなければならないという要件を一時的に無視すると、すべての最小化子は

 f(x)=∑∣a i −x∣

 は中央値です。 奇数サイズの配列の場合、一意の関連ポイントは並べ替え後の中央の要素になります。 偶数サイズの配列の場合、中央の 2 つの要素間のすべての実数が関数を最小化します。 

プライム制限はこの構造を破壊しません。 関数は中央値間隔に向かって移動すると減少し、中央値を超えると増加します。 したがって、素数の中で最良の候補は、その中央値間隔に最も近い素数でなければなりません。 

中央値の間隔は、その左の端点である下側の中央値を使用して表すことができます。 それをmとしましょう。 左側の最良の素数は、最大 m の最大の素数です。 右側の最良の素数は、少なくとも m の最小の素数です。 正しい素数が中央値間隔内にある場合、すでに無制限の最小値が得られます。 区間内に素数がない場合、これら 2 つの候補はまさに両側で最も近い正当なターゲットになります。 

したがって、問題全体は、配列をソートし、下位中央値を特定し、各辺で最も近い素数を見つけて、それらの候補のコストを評価することに帰着します。 

素数性テストの場合、以下の実装では 32 ビット サイズの整数に対して決定論的な Miller-Rabin を使用します。 ここでは、入力値が最大 10 9 であり、次の素数はそれよりわずかに大きいだけであるため、これは便利です。 素数性テストには対数べき乗剰余演算が必要で、実際には中央値の周囲の小さな近傍のみを調べる必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(π(10 9 )N)、約 5×10 12 の配列演算 | 入力以外の O(1) | 遅すぎる |
 | 最適 | O(NlogN+GlogA) | O(N) | 承認済み |

 ここで、G は隣接する素数を見つけるときに検査される候補整数の数、A はそれらの大きさです。 10 9 で区切られた値の場合、G は実際には非常に小さくなります。 

## アルゴリズムのチュートリアル

 1. 配列を読み取り、並べ替えます。 並べ替えにより、絶対差の目標が最小化される点である中央値を直接特定できます。 
2.テイク`a[(N - 1) // 2]`中央値の下限として`m`。 奇数 N の場合、これは通常の中央値です。 偶数 N の場合、それはすべての無制限のミニマイザーを含む区間の左端点です。 
3. から下方向に検索します。`m`最大の素数を見つけるまで`left`と`left <= m`。 もし`m`が素数である場合、それは直ちに正しい左の候補になります。 もし`m`は`1`、左側に素数がないため、この候補は単純に省略されます。 
4. から上方向に検索します。`m`最小の素数を見つけるまで`right`と`right >= m`。 この検索は次の場合にも必要です。`m`それ自体はプライムではありません。 
5. 総コストを計算します。`left`そして`right`、それらの候補が存在するときはいつでも。 答えは、コストが低いからです。 
6. 最小コストを返します。 中央間隔より下のすべての素数は左に行くほど悪くなり、間隔より上のすべての素数は右に行くほど悪くなるため、他の素数より優れた素数は存在しません。 

### なぜ効果があるのか

 不変条件は、目的 f(p)=∑∣a i −p∣ が実際のすべてのターゲットにわたって中央間隔で正確に最小化されることです。 To the left of that interval, moving right cannot increase the cost, and to the right of it, moving left cannot increase the cost.

 素数が中央値間隔の左側にあると仮定します。 このようなすべての素数の中で、間隔に最も近い最大の素数が最適です。 同じ議論は、右側の素数の中で最小の素数が最良であることを示しています。 中央値間隔内の素数はすでに最適です。 中央値の下限の両側で最も近い素数を検索すると、まさにこれらの可能性が見つかるため、それらの評価には最適な素数ターゲットを含める必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(n):
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2
    if n % 3 == 0:
        return n == 3

    d = 5
    step = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += step
        step = 6 - step
    return True

def previous_prime(x):
    while x >= 2:
        if is_prime(x):
            return x
        x -= 1
    return None

def next_prime(x):
    if x <= 2:
        return 2

    if x % 2 == 0:
        x += 1

    while not is_prime(x):
        x += 2

    return x

def cost(a, p):
    return sum(abs(x - p) for x in a)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    median = a[(n - 1) // 2]

    left = previous_prime(median)
    right = next_prime(median)

    ans = float("inf")

    if left is not None:
        ans = min(ans, cost(a, left))

    if right is not None:
        ans = min(ans, cost(a, right))

    print(ans)

if __name__ == "__main__":
    solve()
```実装の最初の部分は、`is_prime`。 以下の値`2`すぐに拒否され、`2`そして`3`は別扱いとなります。 その後、6k−1 および 6k+1 の形式の約数のみをテストする必要があります。 ループは次の場合に停止します。`d * d > n`なぜなら、合成数は平方根以下の係数を持つ必要があるからです。`previous_prime`開始値が含まれます。 これが必要なのは、中央値自体がすでに素数である可能性があるためです。 たとえば、完全に以下から構成される配列は、`7`s はゼロを生成する必要があるため、検索を開始します`6`不要なエラーが発生する可能性があります。`next_prime`同じ包括的な規則に従います。 取り扱い後`2`、偶数の開始値を次の奇数に移動し、奇数の候補のみをチェックします。 2 ずつ増分すると、すべての偶数の合成数をテストする必要がなくなります。 

配列は一度ソートされ、`(n - 1) // 2`意図的に低い中央値を選択します。 奇数の長さの場合、これは正確な中央値になります。 偶数の長さの場合、それは中央間隔の左側の境界であり、右側の最も近い素数がその間隔の内側にあるか、それを超える最初の素数になるため、これで十分です。 

コストは、差の絶対値を合計することによって直接評価されます。 Python の整数には任意の精度があるため、オーバーフローのリスクはありません。 固定幅言語では、合計が約 10 14 になる可能性があるため、累積された答えには 64 ビットの整数演算を使用する必要があります。 

候補検索は、10 9 までの範囲全体ではなく、中央値の周囲でのみ実行されます。これが、総当たりアプローチとの主な違いです。 

## 実用的な例

 ### サンプル 1

 入力は`2 3 10`。 ソート後も変化せず、下位中央値は`3`。 

| 配列 | 中央値の下限 | 左素数 | 右素数 | 候補者のコスト |
 | --- | --- | --- | --- | --- |
 | 2、3、10 | 3 | 3 | 3 | 1+0+7=8 |

 中央値はすでに素数であるため、両方の検索で識別されます。`3`。 変化`2`に`3`変更中は 1 回の操作が必要です`10`に`3`費用は7です。 答えは、`8`。 

これは中央値原理の最も単純なケースを示しています。 無制限のミニマイザー自体が合法になってしまえば、それ以上最適化する必要はありません。 

### サンプル 2

 入力は`1 1000000000`。 ソートされた配列は変更されず、下位中央値は次のようになります。`1`。 

| 配列 | 中央値の下限 | 左素数 | 右素数 | 候補者のコスト |
 | --- | --- | --- | --- | --- |
 | 1、1000000000 | 1 | なし | 2 | 1+999999998=999999999 |

 以下の素数はありません`1`, したがって、左の候補は存在しません。 右側の最初の素数は`2`。 移動`1`に`2`移動中に 1 回の操作が必要`1000000000`に`2`費用`999999998`、必要な答えを与える`999999999`。 

この例は、中央値自体が素数でない場合でも、検索で右側の候補を許可しなければならない理由も示しています。 

### サンプル 3

 のために`3 5 7 11`、ソートされた配列はすでに順序付けされており、下位中央値は`5`。 

| 配列 | 中央値の下限 | 左素数 | 右素数 | 候補者のコスト |
 | --- | --- | --- | --- | --- |
 | 3、5、7、11 | 5 | 5 | 5 | 2+0+2+6=10 |

 ここからの間隔全体は、`5`に`7`無制限のミニマイザーで構成され、両方のエンドポイントが素数です。 選択する`5`コストを与える`10`、サンプル出力と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NlogN+GA ) | Sorting dominates the array processing, while G candidate values around the median are tested for primality |
 | スペース | O(N) | 配列はメモリに保存され、並べ替えられます。 

With N≤10 5, sorting requires roughly NlogN comparisons, which is easily within the intended scale. 値は最大 10 9 であるため、素数性テストには最大約 31623 までの約数のみが含まれます。検索は値の範囲全体ではなく 1 つの中央値付近で実行されるため、これらの制約に対する素数性チェックの数は少なくなります。 

The implementation also avoids constructing a sieve of size 10 9, which would be wasteful in both memory and preprocessing time.

import io

def solve_data(inp: str) -> str:

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

        if n < 2:
            return False
        if n % 2 == 0:
            return n == 2
        if n % 3 == 0:
            return n == 3

        d = 5
        step = 2
        while d * d <= n:
            if n % d == 0:
                return False
            d += step
            step = 6 - step
        return True

        while x >= 2:
            if is_prime(x):
                return x
            x -= 1
        return None

    def next_prime(x):
        if x <= 2:
            return 2

        if x % 2 == 0:
            x += 1

        while not is_prime(x):
            x += 2

        return x

    n = int(input())

    sys.stdout = old_stdout

 ## 特殊なケース

 最低限の入力に関しては`1 / 1`、下位中央値は`1`。 素数は次から始まるため、下向き検索では素数が見つかりません。`2`、一方、上向きの検索では次のことが見つかります。`2`。 唯一の要素が移動します`1`に`2`、したがって、答えは次のとおりです`1`。 これにより、中央値が常に有効なターゲットであると誤って想定する実装が捕捉されます。 

のために`2 / 1 1000000000`、中央値の下限は再び`1`。 左の候補はなく、右の候補は`2`。 結果として生じるコストは、`|1-2| + |1000000000-2| = 1 + 999999998 = 999999999`。 このケースでは、入力ドメインの下限と可能な最大の配列値の両方を実行します。 

のために`3 / 7 7 7`、中央値は`7`、 そして`7`プライムです。 両方の候補検索が返されます`7`、生産`0`。 中央値の厳密に下または上で検索を開始すると、最適なターゲットを誤って見逃してしまいます。 

のために`2 / 14 16`、無制限のミニマイザーは以下のすべての実数です。`14`を通して`16`。 その区間には素数はありません。 左側の最も近い素数は次のとおりです。`13`、右側の最も近い素数は次のとおりです。`17`。 どちらもコストがかかります`|14-13| + |16-13| = 4`そして`|14-17| + |16-17| = 4`。 答えは、`4`。 これは重要な偶数長の場合であり、下位中央値を唯一の無制限の最適値として扱うと、なぜ 2 つの隣接する素数で十分なのかが不明瞭になります。 

のために`2 / 1000000000 1000000000`、下位中央値は 10 9 です。前の素数は次のとおりです。`999999937`、つまり`63`次のプライムがいる間、離れています`1000000007`、 のみ`7`離れて。 後者を選択すると、各要素が 7 つずつ変化し、合計で`14`。 これにより、アルゴリズムが最大許容入力値を超える主なターゲットを処理し、整数演算が正確なままであることが検証されます。
