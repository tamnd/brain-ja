 ## 解決策
 ## 問題の理解

 同時に約数となるすべての正の整数を見つける必要があります。`a`そしてその倍数`b`。 入力は 2 つの整数を与えます`a`そして`b`、 と`b <= a`そして両方とも潜在的に次と同じくらいの大きさです`10^12`。 出力には、両方の条件を満たすすべての整数が最小から最大の順に配置されている必要があります。 そのような整数が存在しない場合、必要な出力は単なる空行になります。 

2 つの条件は有益な方法で相互作用します。 有効な数値が`x`。 以来`x`の倍数です`b`、書くことができます`x = b * k`何らかの正の整数の場合`k`。 以来`x`も分けなければなりません`a`、 我々は持っています`b * k | a`。 これが可能なのは次の場合のみです`b`それ自体が分裂する`a`。 いつ`b | a`、 書く`a = b * n`。 それから`b * k | b * n`まさにいつ`k | n`。 その結果、元の問題はすべての約数を見つけることに帰着しました。`k`の`n = a / b`、次にそれらを乗算します`b`。 

の上限`10^12`以下のすべての整数をスキャンするアプローチは除外されます。`a`。 最悪の場合、このようなスキャンは次のように実行されます。`10^12`2 秒の制限でサポートできる反復をはるかに超えています。 の倍数だけをスキャンしても`b`では十分ではありません。`b`できる`1`、できるだけ多く残します`10^12`候補者たち。 除数構造を使用すると、平方根までのペアで除数を列挙できるため、はるかに効率的に作業を行うことができます。 関連する値は最大でも`10^12`、その平方根は最大でも`10^6`、管理が簡単です。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 もし`b`分けない`a`、答えはありません。 たとえば、入力の場合`10 3`、の倍数はありません`3`分割できる`10`したがって、正しい出力は空です。 単純に次の倍数を生成する実装`3`そして止まります`10`生み出すだろう`3 6 9`たとえそれらの数字がどれも割り切れないとしても`10`。 

2 番目のエッジ ケースは次の場合に発生します。`a = b`。 入力用`5 5`、有効な数値は次のとおりです。`5`、 なぜなら`5`分割する`5`そして次の倍数です`5`。 で削減した後、`b`、私たちは得ます`n = 1`、その唯一の約数は`1`。 対応する答えは`5 * 1 = 5`。 

3 番目のエッジ ケースは完全な正方形です。 入力用`36 2`、 我々は持っています`n = 18`、入力中に`49 7`、 我々は持っています`n = 7`。 より一般的に言えば、`n`それ自体は正方形であり、約数のペアは次の場所で発見されます。`sqrt(n)`同じ約数が 2 回含まれています。 実装では、その値を 2 回追加することを避ける必要があります。 例えば、`a = 36, b = 1`を含む約数があります`6`、 しかし`6`は出力に 1 回だけ出現する必要があります。 

## アプローチ

 最も直接的な総当たりの解決策は、次のすべての可能な整数を検査することです。`1`を通して`a`、どちらも割り切れるかどうかを確認します。`b`と約数`a`。 の倍数のみをチェックすることで、スキャンをわずかに小さくすることができます。`b`、しかし最悪の場合には`b = 1`、だから私たちはまだ演奏します`10^12`小切手。 たとえすべてのチェックが一定時間だったとしても、これは利用可能な時間をはるかに超えています。 総当り法は、考えられるすべての答えが検査されるため正しいですが、その操作の数が根本的な問題です。 

重要な観察は、すべての回答には以下が含まれていることです。`b`要因として。 もし`b`分けない`a`、答えはありません。 もし`b`分割する`a`、 セット`n = a / b`。 すべての答えには形式があります`b * k`、そして割り算条件は次のようになります。`k | n`。 私たちは問題を、次の特殊約数を見つけることから変換しました。`a`より小さい数のすべての常約数を求める`n`。 

約数はペアで列挙できます。 いつでも`i`分割する`n`、番号`n / i`も約数です。 テストするだけで十分です`i`まで`sqrt(n)`なぜなら、平方根より大きい約数はすべて、平方根より小さい約数とペアになるからです。 したがって、私たちはせいぜい`10^6`可分性チェック。 すべての約数ペアの両方の要素を収集し、それらを乗算します。`b`、結果の値を並べ替えて出力します。 

ブルートフォースアプローチは、考えられる答えの範囲全体をチェックするため機能しますが、その範囲に達すると失敗します。`10^12`。 すべての有効な数値は`b`の約数倍`a / b`検索スペースを次のように縮小します。`O(sqrt(a / b))`候補者たち。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の O(a) | O(1) 出力を除く | 遅すぎる |
 | 最適 | O(sqrt(a / b) + d log d) | O(d) | 承認済み |

 ここ`d`は約数の数です`a / b`。 までの数値については、`10^12`、`d`元の探索範囲に比べて小さいです。 

## アルゴリズムのチュートリアル

 1.読む`a`そして`b`。 除数の列挙を行う前に、次のことを確認してください。`a % b`はゼロです。 そうでない場合は、空の行を出力して停止します。数値が次の倍数であるためです。`b`分けられない`a`ない限り`b`それ自体が分裂する`a`。 
2. コンピューティング`n = a // b`。 すべての有効な答えが正確に表示されるようになりました`b * k`、 どこ`k`はの約数です`n`。 これは以下から導き出されます`a = b * n`そして`b * k | b * n`、これは以下と同等です`k | n`。 
3. 空の回答リストから始めて繰り返します`i`から`1`その間`i * i <= n`。 平方根の下のすべての約数にはその上にペアの約数があるため、この範囲のみをテストするだけで十分です。 
4.いつでも`n % i == 0`、 追加`b * i`回答リストに追加します。 も追加`b * (n // i)`、除数ペアのもう一方のメンバーです。 
5. もし`i * i == n`、2 番目の値を個別に追加しないでください。 その状況で`i`そして`n // i`は同じ約数であるため、両方を加算すると 1 つの答えが重複します。 
6. 集めた回答を並べ替えます。 約数は、各ペアの小さいメンバーの昇順で検出されますが、それらのペアの大きいメンバーはグローバルに順序付けされていないため、ソートによって必要な数値順序が得られます。 
7. 回答をスペースで区切って出力します。 リストが空の場合、結合された文字列を出力すると、必要な空白行が自然に生成されます。 

### なぜ効果があるのか

 可算性チェックの後、次のことが分かります。`a = b * n`。 数字`x`次のように書ける場合、それは有効な答えになります。`x = b * k`そして`x | a`。 これらの式を代入すると、`b * k | b * n`、これは以下と同等です`k | n`。 したがって、有効な答えと約数の間には 1 対 1 の対応関係があります。`n`、各約数で`k`にマッピングされる`b * k`。 

除数の列挙では、すべての要素が検査されます。`i <= sqrt(n)`。 もし`i`分割する`n`、そのペアの約数`n / i`も見つかるため、すべての約数はペアの小さいメンバーまたは大きいメンバーとして生成されます。 正方形の場合は別個に処理されるため、約数は次のようになります。`sqrt(n)`は 1 回だけ表示されます。 したがって、次のように乗算した後、`b`並べ替えを行うと、出力にはすべての有効な整数が 1 回だけ含まれ、無効な整数は含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    if a % b != 0:
        print()
        return

    n = a // b
    ans = []

    i = 1
    while i * i <= n:
        if n % i == 0:
            ans.append(b * i)

            other = n // i
            if other != i:
                ans.append(b * other)

        i += 1

    ans.sort()
    print(*ans)

if __name__ == "__main__":
    solve()
```最初の条件は、必要な割り切り可能性をチェックします。`a`による`b`。 これがなければ、すべての候補に次の要素が含まれる必要があるため、約数を検索する理由がありません。`b`要因として。 

変数`n`縮小された問題サイズ、`a / b`。 このループは、考えられる小さな約数をテストします。`1`を通して`sqrt(n)`。 条件`i * i <= n`浮動小数点平方根を回避し、Python の任意精度の整数に対して安全です。 

いつ`i`分割する`n`、 両方`i`そして`n // i`は約数です。 それぞれを乗算すると`b`それらを元の問題で必要な実際の数値に変換し直します。 の`other != i`check は完全な平方を処理し、平方根が 2 回挿入されるのを防ぎます。 

除数のペアは混合順序で検出されるため、最終的な並べ替えが必要です。 たとえば、次のようなとき`n = 12`、反復により次のことがわかります。`1, 12`、 それから`2, 6`、 それから`3, 4`。 この特定のシーケンスはたまたまほぼ順序付けされていますが、一般に、変換された値は必要なグローバル順序で到着する必要はありません。 ソートにより出力条件が明確になります。 

Python の整数はオーバーフローしないため、次のような値が返されます。`b * (n // i)`たとえ大きくても安全です`10^12`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(sqrt(a / b) + d log d) | までの約数をテストします`sqrt(a / b)`、 生成する`d`答えてから並べ替えます。 |
 | スペース | O(d) | 回答リストには有効な値が保存されます。 |

 以来`a / b <= 10^12`、除数検索は最大で約約実行されます。`10^6`ループの繰り返し。 約数の数`d`よりもはるかに小さいです`10^6`, そのため、選別コストも控えめです。 このアルゴリズムは 2 秒の制限時間に快適に適合し、64 MB のメモリ制限内に十分収まります。 

## テストケース```python
import sys
import io

def solve():
    a, b = map(int, input().split())

    if a % b != 0:
        print()
        return

    n = a // b
    ans = []

    i = 1
    while i * i <= n:
        if n % i == 0:
            ans.append(b * i)

            other = n // i
            if other != i:
                ans.append(b * other)

        i += 1

    ans.sort()
    print(*ans)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        from io import StringIO

        old_stdout = sys.stdout
        sys.stdout = StringIO()

        try:
            solve()
            return sys.stdout.getvalue()
        finally:
            sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

assert run("1 1\n") == "1\n", "minimum-size input"
assert run("5 5\n") == "5\n", "all-equal values"

assert run("1000000000000 1000000000000\n") == "1000000000000\n", "maximum-size equal values"

 ## 特殊なケース

 いつ`b`分けない`a`、アルゴリズムは除数を列挙する前に終了します。 入力用`10 3`、最初の計算は`10 % 3 = 1`したがって、回答リストは空のままで、プログラムは空白行を出力します。 これにより、すべての倍数を処理するというよくある間違いを防ぐことができます。`b`実際に分割するかどうかを確認せずに答えとして`a`。 

いつ`a = b`、削減された値は`n = 1`。 入力用`5 5`、ループは次から始まります`i = 1`、 そして`1 * 1 <= 1`それは本当です。 以来`1`分割する`1`、アルゴリズムは追加します`5 * 1 = 5`。 対の約数も`1`、 それで`other != i`は false であり、重複は挿入されません。 その後、ループが終了し、`5`。 

いつ`n`は完全な正方形であるため、重複ガードは必須です。 考慮する`36 1`。 関連する削減された数値は次のとおりです。`36`、そしていつ`i = 6`、両方の約数式は次のようになります。`6`。 アルゴリズムは追加します`6`1 回挿入し、2 回目の挿入をスキップします。`other == i`。 完全にソートされた出力は次のとおりです。`1 2 3 4 6 9 12 18 36`。 

可能な最大値では、次のようになります。`1000000000000 1000000000000`、減った数は`1`。 アルゴリズムはループしません`10^12`回。 単一の除数チェックを実行し、元の値を出力します。 これは、次のようにして問題を軽減する理由を示しています。`b`平方根除数の列挙を適用する前でも役立ちます。
