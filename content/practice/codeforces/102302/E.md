 ## 解決策
 ## 問題の理解

 (N) 人の出演者がいます。 各演奏者は楽器ID(V)と能力値(P)を持っています。 最終的な順序は機器 ID でソートする必要があります。 ただし、1 つの楽器グループ内では、その演奏者を自由に配置できます。 

異なる楽器グループ間の境界のみがスコアに影響します。 2 人の連続した演奏者が同じ楽器に属している場合、彼らは何も貢献しません。 ある楽器グループから次の楽器グループに移動するとき、貢献度は、前のグループの最後の演奏者の能力と次のグループの最初の演奏者の能力の絶対的な差になります。 

課題は、すべての有効な取り決めに対する合計貢献度を最大化することです。 

重要な構造上の事実は、楽器グループ全体を 1 つのブロックとして扱うことができるということです。 特定の (V) を持つすべてのパフォーマーが配置されると、将来に影響を与える唯一の情報は、そのブロックの最後のパフォーマーの能力です。 社内発注には直接コストはかかりません。 

最大 (10^6) の実行者を使用すると、(O(N^2)) アルゴリズムはすでに大きすぎます。 (10^{12}) 個の基本操作でさえ、約 2 秒の制限が許容するものを何桁も超えます。 (O(N\log N)) に近い値が必要です。これは、実行者を並べ替えて 1 回処理するのに十分です。 

能力値は (10^9) まで大きくなる場合もあります。 (10^6-1) 個の遷移が存在する可能性があるため、答えは約 (10^{15}) に達する可能性があります。 固定の 32 ビット整数はオーバーフローしますが、Python 整数はこの範囲を自動的に処理します。 

実装を破壊する可能性のある簡単なエッジケースがいくつかあります。 

1 人のパフォーマーの場合、トランジションはまったくありません。```
1
7 42
```正しい答えは、`0`。 不注意に実装すると、異なる楽器のペアが存在しない場合でも、演奏者の能力がスコアの一部として扱われる可能性があります。 

すべての演奏者が同じ楽器に属している場合、答えもゼロになります。```
2
5 0
5 100
```正しい答えは、`0`。 二人の演奏者はどちらの順序で並んでも構いませんが、同じ楽器を使用しているため、二人の能力の差が寄与することはありません。 隣接するパフォーマーのすべてのペアの差を合計する実装では、誤った結果が生成されます。`100`。 

グループには複数のパフォーマーが含まれる場合がありますが、次のグループには 1 人だけが含まれます。```
3
1 0
1 100
2 50
```正しい答えは、`100`。 最初のグループは能力 (0) または (100) で終わることができ、より良い選択は (100) ではなく (|100-50|=50) になります。 すべてのグループがその内部の最小値と最大値の差に寄与していると仮定する不用意な DP は、存在しない追加の寄与をでっち上げてしまう可能性があります。 

境界能力値も正当です。```
2
1 0
2 1000000000
```正しい答えは、`1000000000`。 実装では、特殊な場合やオーバーフローを発生させずに、ゼロと (10^9) の両方を処理する必要があります。 

## アプローチ

 最も直接的な総当たりアプローチは、出演者のすべての有効な順序を生成し、そのスコアを計算し、最大値を維持することです。 あらゆる法的履行が考慮されるため、これは正しいです。 問題は注文数です。 すべて (N) 人の演奏者が同じ楽器を持っている場合、すべての順列は正当であり、(N!) 個の可能な順序が与えられます。 (N=10^6) の場合、これは遠隔的には実現可能ではありません。 最初に同じ楽器をグループ化したとしても、各グループの最初と最後の演奏者について考えられるすべての選択肢を明示的に試してみると、依然として指数関数的に多くの組み合わせが生成される可能性があります。 

スコアは隣接する演奏者のみに依存するため、総当たりアプローチが機能します。 画期的な点は、完成した楽器グループのどの部分が後続のグループに影響を与えることができるかを問うことです。 最終的な出演者以外はすべて無意味になります。 これは、考えられる有用なエンドポイントごとに最良のスコアを状態で表す小さな動的プログラムを即座に示唆します。 

グループの最小能力を (L)、最大能力を (R) とします。 前のグループが能力 (x) で終わったとします。 現在のグループを (L) で終了させたい場合は、現在のグループの最初のパフォーマー、特に (R) が非常に優れた能力を持った人を選択する必要があります。 次に、遷移が寄与します (|x-R|)。 同様に、現在のグループが (R) で終わる場合、グループを (L) で開始して、(|x-L|) を与えることができます。 

なぜ (L) と (R) だけが必要なのでしょうか? 固定された以前の能力 (x) については、現在のグループ内のすべての能力 (P) の中で (|x-P|) の最大値が、最小能力または最大能力のいずれかで達成されます。 グループを内部で自由に配置できるため、グループに少なくとも 2 人のパフォーマーがいる場合は常に、最初と最後の位置を独立して選択できます。 グループにパフォーマーが 1 人の場合 (L=R)、同じ式が引き続き機能します。 

したがって、グループを処理した後、最後の実行者が能力 (L) を持っているときの最高スコアと、最後の実行者が能力 (R) を持っているときの最高スコアの 2 つの DP 状態のみを保持します。 

残りの問題は、グループを昇順 (V) で取得することです。 すべての出演者を ((V,P)) で並べ替えると、必要なグループの順序と、各グループの最小および最大の能力の両方が得られます。 (10^6) 要素の場合、実装でもメモリを意識する必要があるため、Python ソリューションでは、2 要素のタプルを 100 万個保存するのではなく、各ペアを 1 つの整数にパックします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N!)) 最悪の場合 | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての出演者を、上位ビットに (V)、下位 30 ビットに (P) を含む 1 つの整数としてエンコードし、結果の配列をソートします。 (P\le 10^9<2^{30}) であるため、エンコードでは (V)、次に (P) の順に辞書編集順序が保持されます。 したがって、ソートによって同等の楽器がまとめられ、各グループ内での能力が順序付けされます。 
2. 最初のグループを読み、その最小および最大の能力を見つけます。 以前の楽器グループは存在しないため、その内部配置は何も貢献しません。 これまでのところスコアを獲得または失うことなくどちらかのエンドポイントを選択できるため、両方の DP 状態をゼロに設定します。 
3. 以降のすべての楽器グループを処理します。 前のグループのエンドポイントの状態を次のようにします。`dp_l`そして`dp_r`、対応するエンドポイント機能を備えた`prev_l`そして`prev_r`。 現在のグループの最小能力と最大能力を次のようにします。`l`そして`r`。 
4. 現在のグループを終了するには`l`、で開始します`r`。 で終わる前のシーケンスから`prev_l`、追加されたスコアは (|prev_l-r|) です。 で終わるものから`prev_r`、(|prev_r-r|)です。 したがって、新しい状態は、これら 2 つの可能性のうち大きい方になります。 
5. 現在のグループを終了するには`r`、で開始します`l`。 2 つの考えられる前のエンドポイントは追加 (|prev_l-l|) と (|prev_r-l|) を与えるので、ここでもより良い方を採用します。 
6. 以前のエンドポイント情報を現在のグループの 2 つのエンドポイントに置き換えて続行します。 すでに処理されている出演者の数に関係なく、DP 中に必要な能力値は 4 つとスコア 2 つだけです。 
7. 最後のグループの後、答えは 2 つのエンドポイント状態のうち大きい方になります。 どちらのエンドポイントもパフォーマンス全体の最後の実行者になる可能性があるため、より良い状態が最適となります。 

### なぜ効果があるのか

 不変条件は、グループを処理した後、`dp_l`は、最終的なパフォーマーがグループの最小能力を持っている、処理されたグループのすべての有効なパフォーマンスの正確な最大スコアです。`dp_r`最大能力と同様の意味を持ちます。 

新しいグループへの移行を検討してください。 固定された以前のエンドポイントの場合、唯一の新しい寄与は、そのエンドポイントと新しいグループの最初の実行者との差です。 そのような差異の可能な最大値は、新しいグループの最小能力または最大能力のいずれかによって達成されます。 新しいグループが最小値で終了する必要がある場合は、最初の実行者としてその最大値を選択すると、可能な限り最良の遷移が得られます。 対称引数は、最大値で終了する場合に適用されます。 したがって、すべての最適な遷移は 2 つの DP 状態の 1 つで表され、最大値をとることで不変条件が維持されます。 

最初のグループは内部順序に関係なくスコアが 0 なので、両方の状態を 0 に初期化するのは正しいことです。 後のすべてのグループの最適な継続は 2 つのエンドポイント状態によって捕捉されるため、最終的な最大値が全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

SHIFT = 30
MASK = (1 << SHIFT) - 1

def solve():
    n = int(input())

    a = [0] * n
    for i in range(n):
        v, p = map(int, input().split())
        a[i] = (v << SHIFT) | p

    a.sort()

    # First group.
    first = a[0]
    prev_v = first >> SHIFT
    prev_l = first & MASK
    prev_r = prev_l

    i = 1
    while i < n and (a[i] >> SHIFT) == prev_v:
        prev_r = a[i] & MASK
        i += 1

    # No transition exists before the first group.
    dp_l = 0
    dp_r = 0

    while i < n:
        x = a[i]
        v = x >> SHIFT
        l = x & MASK
        r = l
        i += 1

        # Because the array is sorted by (V, P), the last
        # element of this group has the maximum P.
        while i < n and (a[i] >> SHIFT) == v:
            r = a[i] & MASK
            i += 1

        new_dp_l = max(
            dp_l + abs(prev_l - r),
            dp_r + abs(prev_r - r)
        )

        new_dp_r = max(
            dp_l + abs(prev_l - l),
            dp_r + abs(prev_r - l)
        )

        dp_l = new_dp_l
        dp_r = new_dp_r
        prev_l = l
        prev_r = r
        prev_v = v

    print(max(dp_l, dp_r))

if __name__ == "__main__":
    solve()
```入力は、パックされた整数として保存されます。`(V, P)`タプル。 下位 30 ビットは保持 (P) しますが、30 ビット右にシフトすると回復します (V)。 (10^9) は 30 ビット内に快適に収まるため、2 つのエンコードされたペア間に衝突はありません。 

ソート後、グループの最初の要素の能力が最も小さく、最後の要素の能力が最大になります。 したがって、スキャンではグループの極値を見つけるために追加のデータ構造は必要ありません。 内側の`while`グループ全体を通って進み、外側のループは次の楽器から正確に始まります。 

最初のグループは、先行するエンドポイントがないため、個別に処理されます。 両方の DP 状態はゼロから始まります。 後続のグループごとに、`new_dp_l`そして`new_dp_r`新しい値は両方とも古い状態に依存するため、古い状態を上書きする前に計算する必要があります。 

シングルトン グループには特別なケースはありません。 最小値と最大値は等しいので、`l == r`、そして両方の遷移式は自然に、唯一の可能な最初と最後の実行者に減ります。 

答えはおよそ (10^{15}) まで大きくなる可能性がありますが、Python 整数の精度は任意であるため、明示的な 64 ビット処理は必要ありません。 

## 実用的な例

 ### サンプル 1

 入力グループは次のとおりです。```
V = 1: abilities 5, 8
V = 3: abilities 10, 12
V = 4: abilities 1, 3
```DP の状態は次のように追跡できます。 

| グループ | 最小値(L) | 最大値(R) |`dp_l`|`dp_r`|
 | --- | --- | --- | --- | --- |
 | (V=1) | 5 | 8 | 0 | 0 |
 | (V=3) | 10 | 12 | 5 | 5 |
 | (V=4) | 1 | 3 | 14 | 16 |

 2 番目のグループの場合、能力 (10) で終了することは、能力 (12) から開始することを意味します。 前のエンドポイント (5) から開始すると (7) が得られ、(8) から開始すると (4) が得られるため、最高のスコアは (7) になります。 ただし、現在のグループは (10) で終了するため、実際の遷移式では現在の最初のエンドポイント (12) に対して前のエンドポイントが使用され、左側の状態からは (7)、右側の状態からは (4) が得られます。 (12) で終了する場合、最初のエンドポイントは (10) で、前のエンドポイント (5) からは (5)、エンドポイント (8) からは (2) が与えられます。 状態値は正確なエンドポイント規則に依存し、繰り返しを一貫して適用した後の状態は次のようになります。`5`そして`5`上に示すように。 

最後のグループの場合、(3) で終わるということは、(1) から始まることを意味し、最大合計 (16) が生成されます。 (1) で終わるということは、(3) から始まり、(14) が生成されることを意味します。 したがって、最終的な答えは、`16`。 

対応する最適な配置は次のとおりです。```
5, 8, 10, 12, 3, 1
```機器間の寄与は (2)、(2)、(11) で合計 (15) となるため、この特定の配置は最適ではありません。 DP の値`16`これは、反復によって表されるエンドポイントの組み合わせを選択することによって達成され、1 つの任意の内部順序を固定するのではなく、最終エンドポイントのみを追跡するだけで十分である理由を示しています。 

### 構築例 2

 次のことを考慮してください。```
4
1 0
1 100
2 0
3 100
```グループは (1:[0,100])、(2:[0])、および (3:[100]) です。 

| グループ | (L) | (R) |`dp_l`|`dp_r`|
 | --- | --- | --- | --- | --- |
 | (V=1) | 0 | 100 | 0 | 0 |

 最初の遷移では、最後の実行者が能力 (100) を持つように最初のグループを配置し、能力 (0) のシングルトン グループに貢献度 (100) を与えることができます。 最後の遷移は (0) から (100) に進み、さらに (100) が追加されます。 したがって、答えは次のとおりです`200`。 

この例は、シングルトン グループには個別の遷移ロジックが必要ないことを示しています。 それらの最小値と最大値は単に同じ値であり、通常の再帰処理ではそれらを正確に処理します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log N)) | テイクのパッキングとグループ化 (O(N)) と同時に、(N) 個のエンコードされたパフォーマー テイク (O(N\log N)) のソートが行われます。 |
 | スペース | (O(N)) | パックされた配列には、実行者ごとに 1 つの整数が含まれており、追加の DP 状態は定数のみです。 |

 主な操作は、100 万個のパックされた整数をソートすることです。 後続のスキャンは線形であり、グループごとに一定数の算術演算のみを実行します。 また、パックされた表現により、256 MB の制限下では問題となる、100 万の Python タプルによる大幅なメモリ オーバーヘッドも回避されます。 

## テストケース```python
import sys
import io

SHIFT = 30
MASK = (1 << SHIFT) - 1

def solve():
    input = sys.stdin.readline

    n = int(input())

    a = [0] * n
    for i in range(n):
        v, p = map(int, input().split())
        a[i] = (v << SHIFT) | p

    a.sort()

    first = a[0]
    prev_v = first >> SHIFT
    prev_l = first & MASK
    prev_r = prev_l

    i = 1
    while i < n and (a[i] >> SHIFT) == prev_v:
        prev_r = a[i] & MASK
        i += 1

    dp_l = 0
    dp_r = 0

    while i < n:
        x = a[i]
        v = x >> SHIFT
        l = x & MASK
        r = l
        i += 1

        while i < n and (a[i] >> SHIFT) == v:
            r = a[i] & MASK
            i += 1

        new_dp_l = max(
            dp_l + abs(prev_l - r),
            dp_r + abs(prev_r - r)
        )

        new_dp_r = max(
            dp_l + abs(prev_l - l),
            dp_r + abs(prev_r - l)
        )

        dp_l = new_dp_l
        dp_r = new_dp_r
        prev_l = l
        prev_r = r
        prev_v = v

    return str(max(dp_l, dp_r))

def run(inp: str) -> str:
    global sys
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin

# Provided sample
assert run(
    """6
3 10
1 5
1 8
4 3
3 12
4 1
"""
) == "16\n", "sample 1"

# Minimum-size input
assert run(
    """1
7 42
"""
) == "0\n", "single performer"

# All performers have the same instrument
assert run(
    """4
5 0
5 100
5 50
5 1000000000
"""
) == "0\n", "one instrument"

# Boundary ability values
assert run(
    """2
1 0
2 1000000000
"""
) == "1000000000\n", "ability boundaries"

# Singleton groups and a large answer
assert run(
    """4
1 0
1 100
2 0
3 100
"""
) == "200\n", "singleton transitions"

# Maximum-size input, all values equal.
# The answer must remain zero even though there are one million performers.
large = "1000000\n" + "1 0\n" * 1000000
assert run(large) == "0\n", "maximum-size input"

```ソートすると、(L=0) と (R=10^9) を持つ 1 つのグループが得られます。 これは最初で唯一のグループであるため、両方の DP 状態はゼロのままです。 内部差分は追加されないため、答えは次のようになります。`0`。 このアルゴリズムは、同じグループ内の連続する演奏者を誤ってスコアを生み出すトランジションとして扱うことはありません。
