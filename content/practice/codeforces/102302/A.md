 ## 解決策
 ## 問題の理解

 (N) 棟の建物があり、建物 (i) の高さは (h_i) です。 ラリオは選択した 1 つの建物からスタートし、1 回だけジャンプします。 彼が建物 (i) から開始した場合、ジャンプは右側に最大で (h_i) 個の位置をカバーできるため、障害物がなければ目的地は次のようになります。 

[
 \min(i+h_i,N)
 】

 1 ベースのインデックスを使用します。 

その間隔を移動中に、ラリオは最初の建物の高さよりも厳密に高い最初の建物に衝突します。 その高い建物が位置 (j) にある場合、彼はそこに到達できず、(j-1) に着陸します。 必要な出力は、目的地のインデックスではなく、移動距離です。 したがって、意図された目的地よりも高い建物が存在しない場合、答えは、意図された目的地から (i) を引いたものになります。 最初の高い建物が (j) にある場合、答えは (j-i-1) です。 

たとえば、高さ (5,2,2,3,6,2) の場合、建物 1 から開始すると、最大目的地は建物 6 になります。建物 5 の高さは 6 で、開始時の高さ 5 よりも高いため、ラリオは建物 4 に着陸します。距離は (4-1=3) で、これがサンプル出力の最初の値です。 

制約 (N\le 10^5) は、開始位置ごとに配列の大部分を繰り返しスキャンするアルゴリズムを除外します。 二次アルゴリズムは、(N=10^5) の場合、最悪の場合、約 (N(N-1)/2)、おおよそ (5\cdot10^9) 個の比較を実行できます。 これは 2 秒の制限が対応できる範囲をはるかに超えています。 線形時間に近い解決策が必要です。 

一見合理的であると思われる実装が間違っている可能性があるいくつかの特殊なケースがあります。 1つ目は同じ高さです。 障害物の高さは厳密に高くなければならないため、同じ建物であっても衝突は起こりません。 入力用`2 2 2`、正しい出力は次のとおりです。`2 1 0`。 を使用した検索`>=`の代わりに`>`間違って隣の建物に止まってしまいます。 

2 番目のエッジ ケースは、高層ビルがまさに意図した目的地である場合です。 入力用```
2
1 2
```最初の建物は建物 2 に到達しようとしますが、建物 2 の方が高いため、ラリオは建物 1 に着陸します。正しい出力は次のとおりです。`0 0`。 目的地よりも厳密に前の位置だけを検索する不注意な実装では、誤ったレポートが発生します。`1`最初の建物について。 

3 番目のケースは、より高い建物が存在するが、ジャンプ範囲外にある場合に発生します。 入力用```
4
2 1 1 3
```建物 1 から開始すると、建物 3 までしかジャンプできません。位置 4 にある高い建物は無視する必要があるため、最初の答えは次のようになります。`2`。 正しい出力は次のとおりです`2 1 0 0`。 許可された範囲内にあるかどうかを確認せずに次に高い建物を検索すると、間違った結果が得られます。 

最後の境界ケースは 1 つの建物です。 のために```
1
7
```移動する場所がないため、出力は次のようになります。`0`。 これは、宛先計算とスタック ルックアップが最終位置を正しく処理していることを確認するのにも役立ちます。 

## アプローチ

 直接的な解決策は、すべての開始位置を個別に処理することです。 (i) を構築するには、まずジャンプが到達できる最も遠い位置を計算します。 次に、厳密に高い建物が見つかるかジャンプ制限に達するまで、建物 (i+1、i+2、\ldots) を順番に検査します。 最初の高い建物が (j) にある場合は、(j-i-1) を返します。 それ以外の場合は、可能なジャンプ距離全体を返します。 

ゲームはジャンプ パスに沿って最初に遭遇する高い建物のみに依存するため、この強引な方法は正しいです。 左から右にスキャンすると、まさにその建物が見つかり、ジャンプ限界で停止すると、ジャンプ中に到達できない障害物が正しく無視されます。 

問題は繰り返し作業の量です。 同じ高さと十分に大きなジャンプ範囲を持つ (N=10^5) 個の建物を考えてみましょう。 衝突は発生しないため、最初の建物のスキャンでは接尾辞のほぼ全体が検査され、2 番目の建物のスキャンでは残りの接尾辞のほぼ全体が検査され、以下同様になります。 検査できるポジションの数は

 [
 1+2+\cdots +(N-1)=\frac{N(N-1)}2=4,999,950,000。 
】

 すべての答えは最初の高い建物によって決まるため、総当り攻撃は機能しますが、多くの開始位置が重複する接尾辞について本質的に同じ質問をする場合は失敗します。 

重要な観察は、各建物について、実際にはそのジャンプ間隔全体を検索する必要がないということです。 必要なのは、その右側にある、厳密に高い建物だけです。 この位置を次に大きい要素と呼びます。 最も近い高層ビルが既にジャンプ制限を超えている場合、他の高層ビルはさらに遠くにあるため、ジャンプ内での衝突は発生しません。 制限内にある場合は、自動的に最初の衝突となります。 

これにより、問題が標準的な次に優れた要素の計算に変換されます。 単調スタックでは、(O(N)) 時間以内に、すべての位置に対して最も近い厳密に大きい建物を見つけることができます。 配列を右から左に処理します。 スタックには、近くの建物によって高さが削除されていない右側の候補位置が含まれています。 

建物 (i) を処理しているとします。 高さが (h_i) 以下のスタック位置は、(i) の次に大きい建物になることはできません。これは、建物 (i) 自体の高さが少なくとも同じであり、さらに左の位置に近いためです。 このようなポジションはポップされます。 このような位置がすべて削除された後、スタックの最上部が存在する場合、その最上部は、高さが (h_i) より厳密に大きい、右側に最も近い位置になります。 

比較は`<=`、 ない`<`なぜなら、同じ高さは衝突ではないからです。 これは、スタックがより高い建物を厳密に表現するための詳細です。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(1)) 補助 | 遅すぎる |
 | 最適 | (O(N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 建物の数とその高さを読み取ります。 Python 配列では自然にゼロベースのインデックスが使用されるため、内部的にはゼロベースのインデックスを使用しますが、最終的な距離はインデックスの差から直接計算できます。 
2. 配列を作成する`next_greater`どこ`next_greater[i]`高さが厳密に次よりも大きい、右側に最も近い建物のインデックスが含まれます。`h[i]`。 使用`-1`そのような建物が存在しない場合。 
3. 候補インデックスのスタックを維持しながら、建物を右から左にスキャンします。 加工前位置`i`、高さが以下である間にスタック上部を繰り返し削除します。`h[i]`。 

撤去された建物が位置を決定することは決してありません`i`。 高さが低ければ邪魔になりません。 高さが同じであれば、厳密に高い建物のみが衝突を引き起こすため、障害物にはなりません。 また、次のさらに左の候補としても必要ありません。`i`処理されているため、`i` is closer and at least as tall.
4. After the popping step, the stack top is the nearest strictly taller building to the right, if the stack is nonempty. Store that index in `next_greater[i]`を押してから、`i`スタックに追加して、さらに左の位置の候補にできるようにします。 
5. すべての開始位置について`i`、衝突を考慮せずにジャンプが到達できる最も遠い建物を計算します。 ゼロベースのインデックスを使用すると、次のようになります。 

[
 ターゲット=\min(i+h_i,N-1)。 
】

 衝突しない最大距離は`target - i`。 
6. 見てください`j = next_greater[i]`。 もし`j != -1`そして`j <= target`、その後、最初の高い建物がジャンプ範囲内にあります。 ラリオが建物に衝突`j`そして着地する`j-1`、したがって、答えは次のとおりです

 [
 じ-い-1。 
】
 7. 次に大きな建物がない場合、または次の大きな建物が向こうにある場合`target`、このジャンプ中に衝突は発生しません。 答えは単純です`target - i`。 

### なぜ効果があるのか

 すべての位置 (i) について、スタック計算により (h_j>h_i) で最も近い位置 (j>i) が与えられるか、存在しないことが報告されます。 これはまさに、無限右方向で起こり得る最初の衝突です。 (j) が許可されたジャンプ範囲内にある場合、最も高いものの定義により、(j) より前に高い建物は存在しないため、(j-1) での着陸は正しいです。 (j) が許容範囲外にある場合、より高い建物もすべてその範囲外にあるため、ジャンプは意図した目的地に到達します。 したがって、すべての答えは正しく決定されます。 

すべてのインデックスが正確に 1 回プッシュされ、多くても 1 回ポップされるため、スタック自体は線形です。 アルゴリズムは、除外された候補を再検討する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    next_greater = [-1] * n
    stack = []

    for i in range(n - 1, -1, -1):
        while stack and h[stack[-1]] <= h[i]:
            stack.pop()

        if stack:
            next_greater[i] = stack[-1]

        stack.append(i)

    ans = [0] * n

    for i in range(n):
        target = min(i + h[i], n - 1)
        j = next_greater[i]

        if j != -1 and j <= target:
            ans[i] = j - i - 1
        else:
            ans[i] = target - i

    print(*ans)

if __name__ == "__main__":
    solve()
```最初のループは、次に大きな配列を構築します。 右から左への処理がスタックを有用にする理由です。`i`すでに検討されている時点で`i`に達します。 

条件`h[stack[-1]] <= h[i]`より短い建物と等しい建物の両方を削除します。 のみを使用する`<`同じ高さを障害物として誤って扱う可能性があります。 

目的地は`n - 1`実装がゼロベースであるためです。 元々の問題は`n`したがって、 番目の建物はインデックスに対応します`n - 1`。 

衝突条件は、`j <= target`、 ない`j < target`。 意図した目的地に正確に高い建物がある場合でも、衝突が発生します。 その場合`j - i - 1`障害物直前の建物までの距離が正確になります。 

Python では整数オーバーフローの問題はありません。 関連する最大のインデックス式は (10^5) 程度であり、Python 整数はそれを直接処理します。 

決勝戦`print(*ans)`必要なスペースで区切られた出力を生成します。 問題には単一のテスト ケースが含まれているため、テスト ケース ループは必要ありません。
