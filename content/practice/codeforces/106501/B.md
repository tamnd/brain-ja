 ## 解決策
 ## 問題の理解

 この問題では、負でない大きな整数の配列が維持されます。 任意の値に対して、変換`f`は、10 進数の合計を取得し、その中の最小の桁を削除することによって定義されます。 1 つの配列要素を置き換える更新と、次のようなクエリを処理する必要があります: サブ配列の場合、適用する必要がある最小回数は何回ですか`f`結果として得られるすべての値が同一になるように、すべての要素に適用します。 

この制約により、すべてのクエリに対する直接シミュレーションが不可能になります。 まで$10^5$要素と$10^5$操作、到達可能なすべてのクエリの範囲全体をスキャンするアプローチ$10^{10}$操作。 対数時間を回避するには、各更新とクエリが必要です。 

重要な隠れた特性は、値がすぐに小さくなるということです。 数値が 18 桁の場合でも、桁の合計は最大 162 なので、1 回の変換後のすべての値は最大 162 になります。2 回目の変換では最大 1 桁になり、3 回目の変換では常に 0 になります。 つまり、すべての要素には、元の値、1 回適用後の値、2 回適用後の値、および 3 回適用後の値という 4 つの関連する状態しかありません。 

よくある間違いは、ゼロに達するまでに必要な操作の数だけを保存することです。 2 つの数値がゼロに達する前に等しくなる可能性があるため、情報が失われます。 たとえば、配列`[50, 15]`3 つではなく 2 つのアプリケーションが必要です。`f(50)=5`そして`f(15)=5`。 ゼロまでの距離のみを保存する解では、答えが過大評価されてしまいます。 

もう 1 つのエッジ ケースは、すべての値がすでに等しい範囲です。 入力の場合:```
3
7 7 7
1
2 1 3
```答えは`0`変換する必要がないためです。 最初に変換されたレイヤーのみをチェックすると、誤って正の値が返されます。 

最後のエッジケースは、可能な最後の層でのみ等しくなる値です。 例えば：```
2
999999999999999999 888888888888888888
1
2 1 2
```どちらの値も最終的にはゼロになりますが、以前の状態は異なります。 正しい答えは、`3`したがって、アルゴリズムはすべての変換レベルをチェックする必要があります。 

## アプローチ

 簡単なアプローチは、範囲内のすべての要素を調べてクエリを処理することです。 それぞれの値に対して、繰り返し適用します。`f`範囲全体が等しくなるまで。 これは操作の定義に直接従うため、正しいです。 問題は手術回数です。 範囲には以下を含めることができます$10^5$要素があり、$10^5$クエリ、大まかに与える$10^{10}$要素チェック。 

すべての数値には意味のある変換状態が少数しかないという観察により、問題は変わります。 クエリ中に値を繰り返し変換する代わりに、すべての要素の最初の 4 つの状態を事前計算できます。 クエリでは、範囲内のすべての値が同一となる最小レベルを知る必要があるだけです。 

更新は 1 つの位置に影響し、クエリは範囲について尋ねるため、これはセグメント ツリーの問題です。 各セグメント ツリー ノードには、4 つのレベルごとに、多くの変換後にセグメント全体が同じ値を持つかどうかが格納されます。 2 つの子を結合するには、両方の子があるレベルで均一であるかどうか、およびそれらの値が一致するかどうかをチェックするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | セグメントツリー | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての配列要素について、0、1、2、および 3 回の適用後の値を計算します。`f`。 

4 つの状態で十分である理由は、多くても 3 つの変換後にすべての値が 0 になるためです。 

1. 各ノードが 4 つのペアを格納するセグメント ツリーを構築します。 各ペアには、そのレベルの値と、セグメント全体が同じ値を持つかどうかが含まれます。 

2 つの子は最終値が一致する場合にのみマージ可能であるため、値を保存することが必要です。 

1. 更新の場合、変更されたインデックスに対応するリーフを、新しく計算された 4 つの変換状態に置き換えます。 

ツリー内の 1 つのパスのみが変更されるため、更新には対数時間がかかります。 

1. クエリの場合、要求された範囲のセグメント ツリー情報を収集し、対象のノードをマージします。 

マージされた結果は、変換レベルごとに範囲全体が等しいかどうかを示します。 

1. 4 つのレベルをゼロから上にスキャンし、均一としてマークされた最初のレベルを返します。 

最初のレベルは、必要なアプリケーションの最小数です。 

機能する理由: セグメント ツリーは、考えられる各変換回数の後にセグメント全体が等しいかどうかをすべてのノードが正しく記述するという不変式を維持します。 両方の半分がそのレベルで等しく、その結果の値が同じである場合、結合されたセグメントはそのレベルで正確に等しいため、マージ操作ではこれが保持されます。 考えられるすべての答えは 4 つのレベルの中にあるため、最初に見つかった有効なレベルが最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def f(x):
    if x == 0:
        return 0
    digits = []
    y = x
    mn = 10
    s = 0
    while y:
        d = y % 10
        s += d
        if d < mn:
            mn = d
        y //= 10
    return s - mn

def build_value(x):
    res = [x]
    for _ in range(3):
        res.append(f(res[-1]))
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [[0] * 8 for _ in range(4 * self.n)]
        self.build(1, 0, self.n - 1, arr)

    def pull(self, node):
        left = node * 2
        right = left + 1
        for i in range(4):
            lv = self.tree[left][2 * i]
            le = self.tree[left][2 * i + 1]
            rv = self.tree[right][2 * i]
            re = self.tree[right][2 * i + 1]
            if le and re and lv == rv:
                self.tree[node][2 * i] = lv
                self.tree[node][2 * i + 1] = 1
            else:
                self.tree[node][2 * i] = 0
                self.tree[node][2 * i + 1] = 0

    def build(self, node, l, r, arr):
        if l == r:
            vals = build_value(arr[l])
            for i in range(4):
                self.tree[node][2 * i] = vals[i]
                self.tree[node][2 * i + 1] = 1
            return
        mid = (l + r) // 2
        self.build(node * 2, l, mid, arr)
        self.build(node * 2 + 1, mid + 1, r, arr)
        self.pull(node)

    def update(self, node, l, r, idx, val):
        if l == r:
            vals = build_value(val)
            for i in range(4):
                self.tree[node][2 * i] = vals[i]
                self.tree[node][2 * i + 1] = 1
            return
        mid = (l + r) // 2
        if idx <= mid:
            self.update(node * 2, l, mid, idx, val)
        else:
            self.update(node * 2 + 1, mid + 1, r, idx, val)
        self.pull(node)

    def query(self, node, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[node][:]
        mid = (l + r) // 2
        if qr <= mid:
            return self.query(node * 2, l, mid, ql, qr)
        if ql > mid:
            return self.query(node * 2 + 1, mid + 1, r, ql, qr)
        a = self.query(node * 2, l, mid, ql, qr)
        b = self.query(node * 2 + 1, mid + 1, r, ql, qr)
        res = [0] * 8
        for i in range(4):
            if a[2 * i + 1] and b[2 * i + 1] and a[2 * i] == b[2 * i]:
                res[2 * i] = a[2 * i]
                res[2 * i + 1] = 1
        return res

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    seg = SegTree(arr)
    q = int(input())
    ans = []
    for _ in range(q):
        t, a, b = map(int, input().split())
        if t == 1:
            seg.update(1, 0, n - 1, a - 1, b)
        else:
            res = seg.query(1, 0, n - 1, a - 1, b - 1)
            for i in range(4):
                if res[2 * i + 1]:
                    ans.append(str(i))
                    break
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```機能`f`除算で数字を抽出することで慎重に実装されています。 ゼロの特別な処理により、空の数字表現が問題として扱われることが回避されます。 

セグメント ツリーには、ノードごとに 8 つの値が格納されます。 4 つの変換レベルのそれぞれについて、2 つの位置が使用されます。1 つは結果の値として、もう 1 つはセグメントが均一であることを示すブール フラグとして使用されます。 

マージ中、両方の子が均一であり、それらの値が一致する場合にのみ、ノードは均一としてマークされます。 これは、結合された範囲全体が均一になるために必要な正確な条件です。 

クエリ関数は、対象となるセグメントからの情報のみを返し、部分的な回答をマージします。 ツリーの深さは対数であるため、これにより操作が高速に保たれます。

## 特殊なケース

 値が等しい場合:```
3
7 7 7
1
2 1 3
```ツリーはすべての位置のレベル 0 に同じ値を格納するため、クエリはすぐに次の値を返します。`0`。 常に適用されるソリューション`f`まずここで失敗します。 

早期マージの場合:```
2
50 15
1
2 1 2
```レベル 0 では、値が異なります。 レベル 1 では、両方とも`5`、したがって、答えは次のとおりです`1`。 セグメント ツリーは、最終的なゼロ状態だけではなく、すべての変換レイヤーを保存するため、これを認識します。 

最大深さの場合:```
2
999999999999999999 888888888888888888
1
2 1 2
```最初の変換では異なる小さな数値が生成されますが、2 番目の変換でも異なる値が得られる可能性があります。 レベル 3 では両方とも 0 であるため、クエリは次の値を返します。`3`。 これにより、アルゴリズムがプロセスの可能な限りすべての深さを処理していることが確認されます。
