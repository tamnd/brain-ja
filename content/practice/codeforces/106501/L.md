 ## 問題の理解

 のセットを構築する必要があります`n`異なる正の整数。 選択したすべての値は次の範囲内にある必要があります。`1`に`100000`。 条件は、選択した最大 8 つの数値からなる空ではないグループを取得する場合、そのグループの合計が完全な 2 乗であってはいけないということです。 

入力では、必要なセットのサイズのみが与えられます。 出力は、確認すべき単一の回答ではなく、有効な構造です。 

の制限`n`は十分に小さいため、最終セットのすべての可能なサブセットを直接検索することは不可能です。 のために`n = 2862`、最大 8 サイズのサブセットの数は膨大です。 平`C(2862, 8)`処理できる範囲をはるかに超えています。 ただし、数値自体には次の制限があります。`100000`、したがって、最大 8 つの要素の可能な合計は次のように制限されます。`800000`。 この範囲は、私たちが活用できる重要なリソースです。 

厄介な点は、現在の数値と以前の数値を誤ってチェックするだけの場合、貪欲な構築は簡単に失敗する可能性があることです。 単一の不良サブセットは、数回追加した後にのみ出現する可能性があります。 たとえば、次のように出力するとします。```
3
```サブセットが存在しないため、出力は無効になります。`{3}`合計があります`3`、これは正方形ではないため、これは実際には有効です。 ペアだけを探す不注意なチェッカーは、単一要素のサブセットが重要であることを見落とす可能性があります。 一方で：```
1 8
```サブセットであるため無効です`{8,1}`合計があります`9`、正方形。 新しい値を既存の個々の値と照合するだけのメソッドでは、それをキャッチできません。 サイズ 8 までのすべてのサブセットの合計を追跡する必要があります。 

もう 1 つの特殊なケースは、空のサブセットです。 その合計はゼロ、つまり完全な平方であるため、考慮する必要はありません。 最終的な答えを検証するときに誤ってこれを含めると、すべての構築が即座に失敗します。 入力の場合:```
1
```正しい出力は、次のような単一の非平方数です。```
2
```その 1 つの数値を含むサブセットのみが存在するためです。 

## アプローチ

 自然な強引なアイデアは、セットを左から右に構築し、新しい数値を追加する前に、すでに選択されている最大 7 サイズの数値のすべてのサブセットを試すことです。 これらのサブセットと新しい数値のいずれも平方和を作成しない場合は、その数値を保持します。 

これは正しいです。新しい無効なサブセットには、新しく追加された値が含まれている必要があるからです。 問題は、検査するサブセットの数です。 何千もの値を選択すると、サイズ 7 の可能なグループの数が急速に増加します。 最悪のケースでは、何十億もの組み合わせをチェックする必要があります。 

私たちを救う観察は、どの要素が合計を作成したかを知る必要はなく、合計が可能かどうかだけを知る必要があるということです。 関連する最大の合計は`8 * 100000 = 800000`、到達可能なすべてのサブセットの合計をサブセット サイズごとに保存できます。 

あらゆるサイズに対応`k`、ビットセットを維持します。`s`正確に次のサブセットが存在することを意味します`k`選択された要素と合計値`s`。 新しい価値観を考えるとき`x`、到達可能な合計がない場合に有効です。`s`サイズの`k`そのような`s + x`どれも正方形です`k`０から７まで。 

Python の整数は、C でビットを素早くシフトして組み合わせることができるため、ここでは役に立ちます。動的プログラミングの状態の更新は、すべての合計を反復処理するのではなく、数ビットの操作になります。

 ## アルゴリズムのチュートリアル

 1. サブセット和として現れる可能性のあるすべての完全な平方を事前計算します。 可能な最大のサブセット合計は次のとおりです。`800000`, したがって、その値までのすべての正方形で十分です。 
2. 8 つのビットセットを作成します。 インデックスのビットセット`k`正確に選択することによって得られるすべての合計を表します`k`すでに選択されている番号。 最初は空のサブセットのみが存在するため、サイズ 0 のビットセットには合計 0 が含まれます。 
3. 以下の候補番号を反復処理します。`1`に`100000`。 候補者ごとに`x`を追加すると正方形が作成されるかどうかを確認します。 可能なすべての以前のサブセット サイズについて`k`に等しい到達可能な合計を探します。`square - x`。 このような合計が存在する場合、`x`は使用できません。 
4. もし`x`が有効な場合は、それを回答に追加し、ビットセットを更新します。 サイズのサブセット`k`サイズのサブセットになる可能性があります`k + 1`追加することで`x`、これはビットセットを正確に左シフトしたものです。`x`。 
5. 集めたら終了`n`数字。 貪欲な選択が機能するのは、受け入れられたすべての数値が、選択された数値のうち最大 8 のサイズのサブセットが二乗和を持たないという不変条件を保持するためです。 

なぜ効果があるのか:

 維持されるビットセットは、すでに選択されている数値のすべてのサブセット サイズについて、考えられるすべてのサブセットの合計を正確に記述します。 新しい値をテストする場合、新しく作成された無効なサブセットは、新しい値と最大 7 のサイズの古いサブセットで構成されている必要があります。 チェックでは、そのような可能性をすべて調べます。 値が受け入れられた場合、新しい不良サブセットは導入されないため、更新後も不変式は true のままになります。 帰納法により、最終セットは必要な条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_SUM = 800000

squares = []
i = 1
while i * i <= MAX_SUM:
    squares.append(i * i)
    i += 1

def solve():
    n = int(input())
    
    dp = [0] * 9
    dp[0] = 1
    
    ans = []
    
    for x in range(1, 100001):
        ok = True
        
        for k in range(8):
            bits = dp[k]
            for sq in squares:
                need = sq - x
                if need >= 0 and ((bits >> need) & 1):
                    ok = False
                    break
            if not ok:
                break
        
        if ok:
            ans.append(x)
            for k in range(7, -1, -1):
                dp[k + 1] |= dp[k] << x
            
            if len(ans) == n:
                break
    
    print(*ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```合計は次のとおりであるため、正方形のリストは一度作成されます。`800000`重要になる可能性があります。 最大 8 つの許容値のサブセットでは、より大きな正方形を生成することはできません。 

配列`dp`サブセットのサイズは 0 から 8 までであるため、 には 9 つのエントリがあります。 各エントリに格納される値は、ビットセットとして使用される Python 整数です。 少し`s`設定されているということはその合計を意味します`s`達成可能です。 

検証ステップ中に、ループがオーバーします。`k`可能な以前のサブセット サイズをすべてチェックします。 新しい値自体が 8 番目の要素に寄与するため、必要なサイズは 0 ～ 7 だけです。 更新はサイズを逆方向に実行するため、現在の数値が同じ更新で複数回再利用されることはありません。 

Python の整数には任意の精度があるため、整数のオーバーフローの問題はありません。 必要な最大ビット位置は次のとおりです。`800000`、管理可能です。

 ## 特殊なケース

 最小の場合`n = 1`、アルゴリズムは拒否します`1`正方形なので受け入れられます`2`。 空のサブセットは内部的に表現されますが、最終的なサブセットとはみなされないため、サブセット追跡は引き続き機能します。 

選択など、ペアが重要な場合`1`そして`8`、2 番目の番号は拒否されます。 追加する前に`8`、サイズ 1 のビットセットには合計が含まれます`1`、 そして`1 + 8 = 9`正方形として検出されます。 これにより、個々の値だけをチェックするというよくある間違いを防ぐことができます。 

最大サイズについては`n = 2862`、十分な有効な数値が収集されるまでループが続きます。 ビットセット表現では、考えられるすべてのサブセットの保存が回避されるため、構築は引き続き実行可能です。
