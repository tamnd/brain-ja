 ## 解決策
 ## 問題の理解

 この問題では、すべてのショップへの訪問をできるだけ早くスケジュールするように求められます。 店舗の数は少ないですが、各店舗には時間の経過とともに多くの他の顧客が到着する可能性があります。 オーシュナイはお店の順番を自分で選び、お店に着いたときには、すでにその列に並んでいる顧客を待たなければならない場合もあります。 オーシュナイも含め、各店は顧客に対応するのに一定の時間を要します。 

入力により、店舗の数、外部顧客の数、各店舗の買い物時間、および各外部顧客の到着時刻とその顧客が訪れた店舗がわかります。 出力は、Auchenai がすべてのショップを終了した最も早い瞬間です。 

店舗数は最大18。この小さな値が主な手がかりとなります。 考えられるすべての注文を試すには、次のことが必要です`18!`可能性はすでに大きすぎます。 サブセット動的プログラミング ソリューションは現実的です。`2^18 = 262144`サブセット。 リーチできる外部顧客の数`200000`そのため、すべての遷移のキューをシミュレートすると遅すぎます。 各ショップの行列の動作を前処理する必要があります。 

時間の大きな値は、`10^9`、実装では 64 ビット整数を使用する必要があることを意味します。 Python の整数はすでにこれを安全に処理しています。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 別の顧客が到着したときにちょうどオーシュナイが到着した場合、その顧客はその顧客より先に行かなければなりません。 例えば：```
Input
1 1
5
1 0
```正しい出力は次のとおりです`10`。 Auchena の到着時間よりも厳密に到着時間が短い顧客のみをカウントする不注意な実装では、Auchena がすぐに開始して生産を開始してしまいます。`5`。 

もう 1 つの注意が必要な状況は、待っている顧客がいない場合です。 例えば：```
Input
1 0
5
```答えは`5`。 以前のキューの完了時間を常に検索するソリューションでは、誤って不要な遅延が追加される可能性があります。 

最後のケースは、顧客がずっと前に到着したが、列がすでに空になっている場合です。 たとえば、店舗に 3 個のユニットがあり、1 人の顧客が時間 1 に到着した場合、時間 10 に到着した人は時間 14 ではなく、時間 13 に終了するはずです。行列の履歴は重要ですが、それは Auchenai が到着する瞬間までです。 

## アプローチ

 直接的なアプローチは、店を訪れるあらゆる順序を試してみることです。 固定注文の場合、キューをシミュレートして最終的な終了時間を計算できます。 考えられるすべてのスケジュールが考慮されているため、これは正しいです。 問題はスケジュールの数です。 18店舗あります`18!`注文、つまり約`6.4 * 10^15`、ブルートフォースを不可能にします。 

最初の改善点は、将来は現在の状況に到達するために使用された正確な順序に依存しないことを認識することです。 いくつかの店を訪れた後、重要な情報は現在時刻とどの店が残っているかだけです。 これにより、自然なサブセット動的プログラミング状態が得られます。 

すでに訪問したショップのサブセットについては、Auchenai がそのサブセット内のすべてのショップを終了できる最も早い時間を保存します。 その状態から、未訪問のお店をすべて追加してみます。 

残りの課題は、この質問にすぐに答えることです。Auchenai が店に届くかどうかです。`i`時に`x`、彼はいつ終わりますか？ 店の外部の顧客は常に時系列順に到着し、オーシュナイの決定に依存することはありません。 すべての店舗について、最初の列の終了後の外の列の終了時刻を前処理します。`k`顧客。 次に、二分探索により、時間までに到着した顧客の数がわかります。`x`、そして彼らの列が空く時間をすぐに知ることができます。 

この総当り攻撃は、考えられるすべての注文が検査されるため機能しますが、注文の数が爆発的に増加するため失敗します。 訪問セットと最も早い終了時間のみが重要であるという観察により、問題はサブセット DP に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n! * n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(2^n * n * log m)`|`O(2^n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 店舗ごとに顧客の到着時間を並べ替えます。 ショップごとに、プレフィックス配列を構築します。`k`-th の値は、最初の時刻を表します。`k`外部の顧客は完全に買い物を終えました。 

プレフィックス値により、後で個々のキューのシミュレーションを無視できるようになります。 DP のすべての移行では、すでに到着している顧客の数を知るだけで済みます。 
2. 動的プログラミング配列を作成する`dp[mask]`。 少し入った`mask`はオーシュナイがすでに訪れたお店を表します。 保存される値は、まさにそれらの店舗の最も早い終了時間です。 

初期状態は`dp[0] = 0`なぜなら、お店に行く前は現在時刻がゼロだからです。 
3. すべてのサブセットを反復処理します。`mask`。 アクセス可能な状態であれば、マスクに含まれていないすべてのショップを試してください。 

お店を 1 つ追加するということは、スケジュールで次の目的地を選択することに相当します。 
4. 選んだ次のお店へ`i`、現在時刻を`cur = dp[mask]`。 ショップで二分検索を使用する`i`の到着リストを使用して、最大到着時間の外部顧客の数を確認します`cur`。 

ちょうどの時間に到着するお客様`cur`これらは Auchenai よりも前にキューに入るため、含める必要があります。 
5. それらの顧客に対して、事前に計算されたキュー完了時間を使用します。 オーシュナイは到着時刻と既存の列の両方が終了した後に開始し、その後、`t[i]`ユニットのショッピング。 
6. 新しく訪問したショップを含む状態を更新します。 すべてのサブセットが処理されると、答えは次のようになります。`dp[(1 << n) - 1]`。 

なぜ効果があるのか:

 不変条件とは、`dp[mask]`正確に店舗を訪れたすべての注文の中で、可能な限り最良の仕上がり時間を常に保存します。`mask`。 別の店を訪れて状態を拡張する場合、店の待ち行列は現在時刻と固定された外部の到着時間のみに依存するため、その選択の正確な終了時間を計算します。 考えられるすべての次のショップが考慮されるため、すべての考えられる完全な注文は一連の DP 遷移として表示されます。 したがって、フルマスクの最小値が最適なスケジュールになります。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    t = list(map(int, input().split()))

    arrivals = [[] for _ in range(n)]
    for _ in range(m):
        s, u = map(int, input().split())
        arrivals[s - 1].append(u)

    prefix = []
    for i in range(n):
        arrivals[i].sort()
        cur = 0
        pref = [0]
        for x in arrivals[i]:
            cur = max(cur, x) + t[i]
            pref.append(cur)
        prefix.append(pref)

    size = 1 << n
    inf = 10**30
    dp = [inf] * size
    dp[0] = 0

    for mask in range(size):
        cur = dp[mask]
        if cur == inf:
            continue

        for i in range(n):
            if (mask >> i) & 1:
                continue

            cnt = bisect_right(arrivals[i], cur)
            finish_queue = prefix[i][cnt]
            nxt_time = max(cur, finish_queue) + t[i]

            nxt = mask | (1 << i)
            if nxt_time < dp[nxt]:
                dp[nxt] = nxt_time

    print(dp[-1])

if __name__ == "__main__":
    solve()
```前処理セクションは、すべてのショップの外部キューをプレフィックス完了時間に変換します。 インデックスの値`k`最初の料理を提供した後を意味します`k`その時点で店は無料になります。 

DP セクションは、上で説明したサブセット遷移の後に続きます。 マスクは整数として保存されるため、状態表現がコンパクトに保たれます。 しかないので、`2^18`状態では、すべてのマスクを反復処理することが可能です。 

二分探索では、`bisect_right`それよりも`bisect_left`なぜなら、オーシュナイの到着時間ぴったりに到着した顧客が依然として最初に列に入るからです。 表現`max(cur, finish_queue)`キューがすでに空であるか、Auchenai が待機する必要があるかの両方の状況を処理します。 

Python の整数は自動的に増加するため、オーバーフロー処理は必要ありません。 大きなセンチネル値は、到達不能な状態を表すためにのみ使用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(2^n * n * log m)`| 各サブセットは次のすべてのショップを試行し、各遷移はショップの到着リストで 1 つの二分探索を実行します。 |
 | スペース |`O(2^n + m)`| DP 配列にはすべてのサブセット状態が保存され、前処理によってすべての顧客の到着が保存されます。 |

 最大の状態数は次のとおりです。`262144`、トランジションの数はわずか数百万です。 前処理では多数の顧客を一度に処理するため、ソリューションは制限内に問題なく収まります。

 ## 特殊なケース

 最初の特殊なケースについては、次のことを考慮してください。```
1 1
5
1 0
```DP は時刻 0 で開始されます。到着時刻が現在時刻と等しいため、バイナリ検索によりキュー内に既に 1 人の顧客が存在することがわかります。 プレフィックス キューの完了は 5 であるため、Auchenai は時刻 5 に開始され、時刻 10 に終了します。 

空のキューの場合:```
1 0
5
```二分検索では顧客が返されません。 ストアドキューの完了がゼロであるため、遷移は次のようになります。`max(0, 0) + 5`、正解は 5 です。 

すでに退会した古い顧客の場合:```
1 1
3
1 0
```Auchenai が時間 10 に店舗に到達できた場合、二分検索には顧客が含まれますが、プレフィックス補完は 3 になります。`max(10, 3) + 3`古いキュー履歴は、クリアされた後は遅延を引き起こしません。
