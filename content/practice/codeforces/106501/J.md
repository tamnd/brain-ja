 ## 解決策
 ## 問題の理解

 同じ頂点セット上に 2 つの完全な有向グラフが与えられています。これは、異なる頂点のペアごとにエッジの 1 つの方向が正確に存在することを意味します。 これらは通常トーナメントと呼ばれます。 タスクは、非常に特殊な操作を使用して、最初のトーナメントを 2 番目のトーナメントに変換することです。 

許可された移動では、3 つの異なる頂点が選択されます。 これら 3 つの頂点のうち、有向エッジが長さ 3 の有向サイクルを形成する場合、3 つのエッジすべてを一度に反転できます。 言い換えれば、時計回りのサイクルは反時計回りになり、その逆も同様ですが、この移動は、操作前に 3 つの頂点がすでに一貫したサイクルを形成している場合にのみ有効です。 

出力は単に「はい」または「いいえ」だけではありません。 可能であれば、最初のトーナメントを 2 番目のトーナメントに変換する一連のトライアングル リバーサルを明示的に構築する必要があります。 

この制約により、テスト ケースごとに最大 500 個の頂点が許可され、テスト全体で合計 500 個になります。 これにより、単純な方法で演算ごとに二次関数が即座に除外されます。 構造を持たずにすべてのトリプルを繰り返し検索しようとするソリューションでは、テストごとに三次的な動作が発生する危険があり、遅すぎます。 意図したソリューションでは、成功した各操作が迅速に検出され、操作の合計数が二次関数に保たれることが保証される必要があります。 

いくつかの特殊なケースが重要です。 

2 つのトーナメントが同一である場合、正しい出力は操作がゼロになります。 これをチェックせずに常に不一致エッジを「修正」しようとする実装では、時間が無駄になったり、無効な操作が発生したりする可能性があります。 

変換が不可能な場合、出力は -1 でなければなりません。 不一致エッジを常に反転する単純な貪欲型は、局所的な不一致が残っている場合でも、有効な有向三角形が存在しない状態でスタックする可能性があります。 

小さな失敗例は、反転したエッジが 1 つあるものの、必要な向きの有向三角形を完成させる頂点がない場合に発生します。 たとえば、1 つおきの頂点がペアに関して推移的に動作する場合、そのエッジを直接反転するために使用できるサイクルが存在しない可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。現在のトーナメントとターゲットを繰り返し比較し、間違ったエッジを一度に 1 つずつ修正しようとします。 i と j の間のエッジが間違っている場合は、i、j、k が有向サイクルを形成するように 3 番目の頂点 k を見つけようとします。 見つかったら、不一致のエッジを含む 3 つのエッジすべてを反転する操作を適用します。 

これが機能するのは、この操作が少なくとも 1 つの間違ったエッジを直接修正し、一定数のエッジのみを変更するためです。 しかし、弱点はｋの捜索にある。 単純な実装では、毎回すべてのトリプルをスキャンするため、操作ごとに O(n) の検索が発生し、最大 O(n²) の操作が発生し、テスト ケースごとの合計作業量が O(n³) となり、n が 500 までの場合は遅すぎます。 

重要な点は、任意のトリプルが必要ないということです。 不一致のペア (i, j) については、それらと正しい順序で有向パスを形成し、サイクルを作成する頂点 k を見つけるだけで済みます。 A に j → i があるが、i → j が必要な場合、i → k および k → j となるような k が必要になり、j → i → k → j というサイクルが作成されます。 A に i → j があるが、その逆が必要な場合、j → k および k → i が必要です。 

したがって、すべてのトリプルを盲目的に検索する代わりに、2 つの有向制約を満たす 1 つの中間頂点を見つけるまで検索を減らします。 これにより、有効な操作を見つけるという問題が頂点間の構造化された「2 つの条件の交差」に軽減されます。 

変換プロセスは、制御されたエッジ修正手順になります。ペアをスキャンし、エッジがターゲットと異なる場合は常に、そのエッジを修正する三角形の反転を可能にする有効な k を検索します。

 ## アルゴリズムのチュートリアル

 最初は A と等しい現在のトーナメントを維持し、B と一致するまで徐々に変更します。 

1. すべての順序付きペア (i, j) を繰り返します。 現在の向きがすでにターゲットと一致している場合は、何も行いません。 これにより、プロセスがローカルに保たれ、未解決のエッジにのみ労力を費やすことが保証されます。 
2. i と j の間のエッジが間違っている場合、どの方向を強制する必要があるかを決定します。 対称的なケースは 2 つあります。i → j を j → i に反転する必要があるか、その逆です。 
3. 最初のケースでは、現在 j → i が存在するが、i → j が必要であると仮定します。 現在のトーナメントで i → k および k → j が成り立つような頂点 k を検索します。 このような k が存在する場合、(j, i, k) 間のエッジは有向サイクル j → i → k → j を形成します。 これはまさに、許可された操作を実行するために必要な構造です。 
4. そのような k が見つかったら、(j, i, k) に 3 つのエッジすべてを反転する操作を適用します。 これにより、i と j の間のエッジが反転されて正しい方向に固定され、同時に他の 2 つのエッジも制御された方法で変更されます。 
5. 各操作の後に隣接行列を更新し、ペアのスキャンを続けます。 各操作により、以前に間違っていたペアが少なくとも 1 つ修正されるため、無限にループすることはありません。 
6. ある時点で、不一致ペアの有効な k が見つからない場合は、有効なシーケンスが存在しないと結論付け、-1 を出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべての操作が現在のトーナメントの有効な指示された 3 サイクルにのみ適用されるため、合法性が常に維持されるということです。 成功した各操作は、i と j の間で選択された不一致エッジを修正し、他のエッジを混乱させますが、それらの変更は常に、前に処理されていない、または後で再検討される既に修正された構造内にあります。 

重要な構造的事実は、変換が可能である場合、すべての間違ったペアに対して、修正が必要な瞬間に有向サイクルを完了できる頂点が少なくとも 1 つ存在するということです。 これにより、貪欲なローカル修復プロセスが到達可能なインスタンスでスタックすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_k(a, i, j, n):
    # we want a k such that i->k and k->j (for j->i case)
    for k in range(n):
        if k == i or k == j:
            continue
        if a[i][k] and a[k][j]:
            return k
    return -1

def find_k_rev(a, i, j, n):
    # we want k such that j->k and k->i (for i->j case)
    for k in range(n):
        if k == i or k == j:
            continue
        if a[j][k] and a[k][i]:
            return k
    return -1

def apply(a, ops, x, y, z):
    # reverse cycle x -> y -> z -> x into x <- y <- z <- x
    if a[x][y] and a[y][z] and a[z][x]:
        a[x][y] = 0
        a[y][z] = 0
        a[z][x] = 0
        a[y][x] = 1
        a[z][y] = 1
        a[x][z] = 1
    else:
        # reverse orientation if needed (should not happen if constructed correctly)
        a[x][y] = 1 - a[x][y]
        a[y][z] = 1 - a[y][z]
        a[z][x] = 1 - a[z][x]
    ops.append((x + 1, y + 1, z + 1))

def solve():
    n = int(input())
    A = [list(map(int, list(input().strip()))) for _ in range(n)]
    B = [list(map(int, list(input().strip()))) for _ in range(n)]

    ops = []

    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            if A[i][j] == B[i][j]:
                continue

            if B[i][j] == 1:
                k = find_k_rev(A, i, j, n)
                if k == -1:
                    print(-1)
                    return
                apply(A, ops, i, j, k)
            else:
                k = find_k(A, i, j, n)
                if k == -1:
                    print(-1)
                    return
                apply(A, ops, j, i, k)

    print(len(ops))
    for x, y, z in ops:
        print(x, y, z)

if __name__ == "__main__":
    solve()
```実装では、トーナメントを隣接行列として保持し、各操作の後に直接変更します。 2 つのヘルパー検索関数は、特定のエッジを反転するために必要な三角形の 2 つの可能な方向を反映します。 

よくある微妙な問題は、三角形が元のグラフではなく現在の状態に存在する必要があることを忘れていることです。 そのため、検索は初期入力ではなく、進化する行列 A に対して行われます。 

apply 関数は、トリプルが有効なサイクルを形成していると想定します。 構築ロジックが正しい場合、フォールバック ブランチは決して使用しないでください。 これは、デバッグ中のサイレント破損を回避するためにのみ含まれています。 

## 実用的な例

 A が単一の有向サイクル、B が逆サイクルである 3 つの頂点を持つ小さなインスタンスを考えてみましょう。 すべてのエッジが一致しないため、1 回の操作で十分です。 

| ステップ | A[i][j] 状態 | 選択されたエッジ | k が見つかりました | 操作 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 → 2 → 3 → 1 | (1,2) 不一致 | 3 | (2,1,3) |

 操作を適用すると、すべてのエッジが反転され、トーナメントは B と一致します。これは、1 つの三角形のフリップで複数のエッジを同時に修正できることを示しています。 

ここで、A と B の間でエッジが 1 つだけ異なるが、有効な k が存在する、4 頂点のケースを考えてみましょう。 

| ステップ | 不一致 (i,j) | 状態を確認済み | k が見つかりました | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 | (0,3) | i→jが必要 | 頂点 2 は 3→2 および 2→0 を満たす | 有効なサイクル |
 | 1 | 反転を適用する | 3 つのエッジを更新します | エッジ (0,3) 固定 | 進捗 |

 このトレースは、1 つのエッジのみがターゲットになっているにもかかわらず、操作が 3 番目の頂点を含むサポート構造に依存していることを示しています。

 ## 特殊なケース

 2 つのトーナメントがすでに同一である場合、すべてのペア チェックは即座にパスし、k の検索はトリガーされません。 このアルゴリズムは演算を出力せず、隣接行列に変更は加えられないため、正確性が維持されます。 

不一致のエッジが存在するが、必要な有向三角形を完成できる頂点がない場合、検索関数は失敗し、-1 を返します。 これは、ローカル トライアングル操作ではトーナメント間の構造的な違いを埋めることができない、不可能な変換状態に対応します。 

複数の不一致が重なった場合、以前の操作により、すでに修正されていたエッジが一時的に乱される可能性があります。 アルゴリズムは、ペアに対して再度動作するかどうかを決定する前に、ターゲットに対して現在の状態を常にチェックするため、これを自然に処理し、ワンパスの剛性ではなく最終的な収束を保証します。
