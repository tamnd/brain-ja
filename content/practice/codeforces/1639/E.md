 ## 解決策
 ## 問題の理解

 私たちは未知の接続された無向グラフの中に置かれています。 既知の頂点から開始しますが、その後、有益な方法で頂点 ID が再び表示されることはありません。 頂点に到達するたびに、インタラクターはその次数とその近傍のリストのみをランダムな順序で表示します。 それぞれの隣人について、その隣人の程度と、その隣人がすでに訪問されているかどうかがわかります。 

実行できる唯一のアクションは、表示された隣接位置の 1 つを選択し、そこに移動することです。 目標は、移動の総数が指定されたベースラインの係数内に収まるようにするというソフト制約を使用して、できるだけ少ない移動を使用してすべての頂点を少なくとも 1 回訪問することです。 

主な問題は、隣接リストが訪問のたびに再シャッフルされるため、エッジを識別するために位置の一貫性に依存できないことです。 唯一の永続的な情報は、近隣諸国がすでに訪問されているかどうかであり、これは世界的な進捗状況のローカル マーカーとして機能します。 

制約は頂点の数が多くても 300 と小さく、次数の境界が 50 であるため、比較的単純な探索戦略でも実行可能です。 ただし、テストごとに最大 60,000 移動というインタラクション制限があるため、進歩せずに繰り返しサイクルを繰り返す病的徘徊を避ける必要があります。 

グラフ構造を明示的に再構築しようとする素朴なアプローチは、近傍の安定したアイデンティティを決して観察しないため、失敗します。 頂点に一貫してラベルを付けることができないため、エッジを保存することさえ不可能です。 使用できる唯一の状態は、ノードが訪問されているかどうかです。 

「常に最初の未訪問の近隣インデックスに行く」ようにしようとすると、微妙な失敗例が発生します。 近隣の順序付けは訪問ごとにランダム化されるため、バイアスが生じますが、系統的な探索が保証されるわけではありません。また、境界を再度見つける前に、訪問した領域内で繰り返し変動することになる可能性があります。 

## アプローチ

 強引なアイデアでは、これを再構成を伴う完全なグラフ探索問題として処理しようとします。 静的設定では、近隣に ID を割り当て、エッジを保存し、標準の DFS または BFS を実行します。 これにより、エッジの数において線形トラバースの複雑さが得られ、これが最適になります。 

ここで、頂点のアイデンティティが相互作用にわたって永続的ではないため、そのアプローチは根本的に失敗します。 頂点に到達するたびに、その隣接リストが並べ替えられるため、「この近隣は前に見た近隣と同じである」と一致することはできません。 グラフを再構築しようとしても失敗します。 

重要な観察は、実際には再構成されたグラフが必要ないということです。 最終的にすべての頂点に少なくとも 1 回到達することを確認するだけで済みます。 進行状況を区別する唯一の信号は、各近隣に提供される訪問済みフラグです。 

これにより、タスクは、強い優先ルールを備えたガイド付きランダム探索に変わります。 まだ訪問されていない隣接頂点がある頂点にいるときは、常にそれらの隣接頂点の 1 つに移動する必要があります。 これにより、移動するたびに訪問する頂点の数が増加するため、確実に前進することができます。 

未訪問の近傍が存在しない場合、現在の頂点は既に訪問したノードによって完全に囲まれます。 その場合、私たちは探索地域内にいるので、近隣の地域に安全に移動できます。 これによりワンダリングが発生する可能性がありますが、グラフは接続されており、訪問したノードを通じて常にフロンティアに到達できるため、最終的にはフロンティアに戻ります。 

このプロセスは、永続的なスタックを持たない DFS のように動作します。訪問されたセットによって、探索された領域と探索されていない領域の間の境界が暗黙的に定義されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートグラフ再構成 | ID の喪失により不可能 | O(n + m) (使用不可) | 該当なし |
 | 訪問済みフラグを使用したガイド付き探索 | O(移動数 ≤ 60000) | O(n) 暗黙的 | 承認済み |

## アルゴリズムのチュートリアル

 1. インタラクションで提供されるフラグから推測される、訪問した頂点のグローバルな概念を維持します。 最初は開始頂点のみが訪問されます。 
2. 各ステップで、現在の頂点の説明を読み取ります。この説明には、すべての近傍がランダムな順序でリストされ、各近傍が訪問されたかどうかが示されます。 
3. 近隣リストをスキャンし、フラグが未訪問であることを示す近隣のインデックスを収集します。 少なくとも 1 つ存在する場合は、そのうちの 1 つ (通常は最初のインデックス) を選択します。 
4. 未訪問の近隣が存在しない場合は、任意の近隣インデックスを選択します。 このステップは、完全に探索されたエリアを抜け出して、まだ探索されていない頂点を含む領域に戻るために必要です。 
5. 選択したインデックスを出力し、フラッシュして、次のインタラクション応答に移動します。 

この戦略が機能する理由は、未訪問の近傍を選択するたびに、訪問済みの頂点の数が厳密に増加するためです。 頂点が n 個しかないため、これは最大でも n − 1 回発生します。 これらの発見の間にアルゴリズムがさまよう場合がありますが、さまよいはすでにアクセスされたコンポーネント内でのみ発生します。 グラフは接続されているため、これらのコンポーネントには常に未踏の領域に向かうエッジがあり、横断を繰り返すと最終的にはフロンティアに再び遭遇します。 

暗黙的な不変条件は、すべての未訪問の頂点が現在位置から何らかのエッジ シーケンスを通じて到達可能な状態を維持することです。アルゴリズムは、エッジを削除したり移動をブロックしたりすることはなく、パスのみを選択するため、そのフロンティアに到達する能力から永久に削除されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, start, base_move_count = map(int, input().split())

        # We do not need to store the graph.
        # The process is fully interactive; we only react locally.

        print(start, flush=True)

        for _ in range(2 * base_move_count):
            line = input().strip()

            # End of current map
            if line == "AC" or line == "F":
                break

            parts = list(map(int, line.split()))
            d = parts[1]

            best = -1

            # neighbors are encoded as (deg_i, flag_i) pairs starting from index 2
            for i in range(d):
                deg_i = parts[2 + 2 * i]
                flag_i = parts[2 + 2 * i + 1]

                if flag_i == 0:
                    best = i + 1
                    break

            if best == -1:
                best = 1  # fallback: all neighbors visited

            print(best, flush=True)

def main():
    solve()

if __name__ == "__main__":
    main()
```プログラムは対話ステップごとに完全にローカルで動作します。 頂点 ID のマッピングは決して試みられません。 現在の隣接ビュー内の訪問済みフラグにのみ反応します。 ループ境界`2 * base_move_count`この制限を超えると失敗するという問題の保証を尊重するため、それに応じてマップごとの探索の試みを終了します。 

微妙な点は、すべての近隣にアクセスしたときのフォールバックの選択です。 最初の近傍を選択することは任意ですが、十分です。なぜなら、どの近傍も接続された訪問領域内での歩行を維持し、最終的なフロンティア再突入は、方向の選択ではなく、反復的な横断のみに依存するからです。 

## 実用的な例

 1 から開始して、1 が 2 に接続され、2 が 3 に接続されている小さな連鎖グラフを考えてみましょう。 

頂点 1 では、近傍 2 のみが表示されており、訪問されていないため、2 に移動します。頂点 2 では、訪問済みの近傍 (1) が 1 つと、訪問されていない近傍 (3) が 1 つあるため、3 に移動します。頂点 3 では、すべての近傍が訪問されているため、任意の近傍に戻り、最終的に 2 に戻り、必要に応じて 1 に戻ります。 これは、可能であれば探索を外側に拡張し、必要な場合にのみ後戻りすることを示しています。 

1 から始まる三角グラフ 1-2-3-1 では、まず 2 に進み、次に 3 に進みます。3 では、両方の近傍が訪問されるため、任意に 1 または 2 に戻ることができます。 ノードを再訪問することがあっても、重要な遷移は最初の訪問だけであり、それらは最大でも n − 1 回の前進ステップで発生します。 

これらのトレースは、アルゴリズムが構造化されたバックトラッキングに依存していないことを示しています。 拡大を推進するには、未訪問の近隣諸国の存在にのみ依存します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(移動数) ≤ O(テストごとに 60000) | 各インタラクション ステップでは、最大次数 50 の近傍を処理します。

この制約により、ワンダリングが繰り返されても移動回数が安全な範囲内に収まり、各ステップが一定の作業となることが保証されるため、ソリューションは対話型の実行に適しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、隣接するすべての頂点がすでに訪問されている領域にアルゴリズムが入る場合です。 たとえば、完全に探索された三角形では、すべての頂点は訪問した近傍のみを認識します。 次に、アルゴリズムは任意の近傍を繰り返し選択し、訪問セット内を移動します。 これによって再訪問が発生しても、最終的な完了は妨げられません。そのコンポーネントではフロンティアがすでに使い果たされており、残りの未探索のノードは、訪問したノードのシーケンスを通じて到達可能な別の場所にあるはずだからです。 

もう一つのケースは、長い間訪れた回廊を通ってのみフロンティアにアクセスできる場合です。 アルゴリズムは、コリドーの入り口に再び遭遇する前に、密集した訪問済みクラスター内をさまよう可能性があります。 ただし、すべての移動が許可され、状態が失われることはないため、トラバースを繰り返すと最終的には再びその境界を越え、未訪問の近傍が頂点のローカル ビューに表示されると進行が再開されます。
