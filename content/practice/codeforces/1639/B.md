 ## 解決策
 ## 問題の理解

 このタスクは、対話型のグラフ探索問題です。 接続された無向グラフの既知の頂点から開始します。 すべての頂点には宝物が含まれており、初めて頂点を訪問すると、自動的にフラグが付けられます。 現在の位置からは、各隣接頂点について、その次数と、すでにフラグが含まれているかどうかのみがわかります。 私たちは隣人の実際のラベルを知りません。 

さらに複雑なのは、頂点に入るたびに隣接するものの順序が独立してランダム化されることです。 同じ場所に戻ったとしても、リスト内の最初の近傍は、以前とは異なるエッジに対応する可能性があります。 グラフ自体は決して変化しませんが、出力エッジの安定した番号付けはありません。 

目的はグラフを再構築することではありません。 適度に少ない移動数を使用しながら、すべての頂点を少なくとも 1 回訪問するだけで済みます。 

グラフには最大 300 個の頂点が含まれ、各次数は最大 50 です。このような小さな制限は、数万の手による戦略が許容されることを意味します。 コンテストの資料には事前に完全なグラフが含まれているため、出場者は各テストに合わせて戦略を調整することができます。 ただし、意図したアイデアははるかに単純です。未踏の領域を優先するランダム ウォークを設計します。 

最も危険な落とし穴は、エッジが近隣リスト内の位置によって記憶できると仮定することです。 

パスを検討する```
1 - 2 - 3
```私たちが頂点 2 にいて、インタラクターが現在レポートしていると仮定します。```
degree 1, unflagged
degree 1, flagged
```その後、頂点 2 に戻った後、次の順序になる可能性があります。```
degree 1, flagged
degree 1, unflagged
```両方の場合に「隣接番号 1」を選択することは、同じエッジを横断することには対応しません。 

もう 1 つの間違いは、次数パターンのみによって頂点を再構築しようとすることです。 2 つの異なる隣り合うものは、同一の次数と同一のフラグ状態を持つ可能性があります。 

例えば```
    2
    |
1 - 3 - 4
```頂点 1 と 4 は両方とも次数 1 を持ちます。頂点 3 に立つと、それらは区別できません。 決定論的に ID を割り当てようとすると、簡単に矛盾が生じる可能性があります。 

正しいアプローチでは、近隣ノードの特定を完全に回避します。 

## アプローチ

 最も簡単な戦略は、完全に均一なランダム ウォークです。 頂点に到達するたびに、その隣接頂点の 1 つを一様にランダムに選択します。 

接続されたグラフは確率 1 のランダム ウォークによって最終的にカバーされるため、この方法は正しいです。残念ながら、一部のグラフの予想カバー時間は長くなります。 たとえば、ロリポップ グラフは、純粋なランダム ウォークに約$O(n^3)$期待して動く。 頂点が 300 個しかない場合でも、不必要にコストがかかる可能性があります。 

重要な観察は、どの隣接する頂点がすでに訪問されているかをインタラクターが教えてくれることです。 私たちの目標は新しい頂点を発見することであるため、フラグの設定されていない隣接頂点が存在する場合は常にその頂点に移動する必要があります。 

現在の頂点にいくつかの近傍があり、そのうちの少なくとも 1 つがまだ訪問されていないとします。 フラグが設定されている隣接点に移動しても、検出される頂点の数はすぐには増加しませんが、フラグが設定されていない頂点に移動すると、検出される頂点の数は確実に増加します。 したがって、未訪問の近隣を優先することは常に有益です。 

最終的には、隣接するすべての頂点がすでに表示されている領域に到達します。 その時点で、脱出して探索を続けるための何らかのメカニズムが必要です。 すべての近傍の中からランダムに選択するとうまく機能します。 これにより、可能な限り積極的に拡張し、それ以外の場合は再びフロンティア頂点に到達するまでさまよう、偏ったランダム ウォークが作成されます。 

この戦略では、グラフを再構築したり、エッジのアイデンティティを記憶したりする必要はありません。 現在のステップで利用可能な情報のみが使用されます。

 ## アルゴリズムのチュートリアル

 1. 指定された頂点から開始します。 すぐに訪問されたとみなされます。 
2. インタラクターが現在の頂点を報告するたびに、すべての隣接する記述を検査します。 
3. フラグが 0 に等しい近傍に対応するインデックスを収集します。これらは、一度も訪問されたことのない頂点を表します。 
4. このセットが空でない場合は、それらのインデックスの 1 つを選択します。 このような頂点を訪問すると、検出される頂点の数が 1 つ増えます。 
5. すべてのネイバーがすでにフラグを持っている場合は、利用可能なすべての選択肢の中からランダムなネイバーを選択します。 これにより、行き止まりを離れて、最終的には再び未踏の領域に到達することができます。 
6. インタラクターが出力するまで続行します。`"AC"`。 

### なぜ効果があるのか

 グラフがつながっています。 未訪問の近傍が存在する場合、アルゴリズムは直ちに新しい頂点を検出します。 ローカル近傍が使い尽くされると、プロセスはすでに検出されている頂点をランダムに歩くことになります。 

接続されたグラフ上のランダム ウォークは、確率 1 ですべての頂点に到達します。その結果、最終的には未発見の頂点に隣接する頂点に到達します。 その瞬間、アルゴリズムは即座にその頂点に拡張されます。 この引数を繰り返すと、最終的にはすべての頂点が訪問されることがわかります。 

## Python ソリューション

 これはインタラクティブな問題であるため、コードは移動するたびにインタラクターと通信します。```python
import sys
import random

input = sys.stdin.readline

rng = random.Random()

t = int(input())

for _ in range(t):
    n, m, start, base_move_count = map(int, input().split())

    for _ in range(m):
        input()

    while True:
        parts = input().split()

        if parts[0] == "AC" or parts[0] == "F":
            break

        d = int(parts[1])

        unvisited = []
        all_neighbors = []

        ptr = 2
        for i in range(d):
            deg = int(parts[ptr])
            flag = int(parts[ptr + 1])
            ptr += 2

            all_neighbors.append(i + 1)
            if flag == 0:
                unvisited.append(i + 1)

        if unvisited:
            move = rng.choice(unvisited)
        else:
            move = rng.choice(all_neighbors)

        print(move)
        sys.stdout.flush()
```グラフの説明はインタラクションが開始される前に与えられますが、この戦略では必要ありません。 これらの行は単に読み取られて破棄されます。 

報告されたすべての頂点について、コードは近隣の記述をスキャンします。 変数`unvisited`フラグがゼロに等しいインデックスを格納します。 このリストが空でない場合、その要素の 1 つが均一にランダムに選択されます。 それ以外の場合は、すべての近傍の中からランダムな近傍が選択されます。 

インタラクターは 1 から 1 までの値を期待するため、近隣インデックスは 1 から始まります。`d`。 この変換を忘れると、誤った答えが発生する可能性が高くなります。 

もう 1 つの微妙な詳細は、移動のたびに出力をフラッシュすることです。 フラッシュしないと、インタラクターは応答を受信せず、ソリューションがハングします。

## テストケース

 インタラクティブな問題は、ジャッジがこちらの動きに反応してしまうため、通常の入出力ペアではテストできません。 それでも、ローカルの決定ロジックをテストすることはできます。```
def choose(flags):
    unvisited = [i + 1 for i, x in enumerate(flags) if x == 0]
    if unvisited:
        return unvisited
    return list(range(1, len(flags) + 1))

# one unvisited neighbor
assert choose([1, 0, 1]) == [2]

# all neighbors already visited
assert choose([1, 1, 1]) == [1, 2, 3]

# all neighbors unvisited
assert choose([0, 0, 0]) == [1, 2, 3]

# degree one vertex
assert choose([1]) == [1]

# mixed configuration
assert choose([0, 1, 0, 1]) == [1, 3]
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 2 つの頂点からなるパスを考えてみましょう。```
1 - 2
```頂点 1 から開始すると、唯一の近傍が未訪問であるため、アルゴリズムはすぐに頂点 2 に移動して終了します。 次数 1 の頂点では特別な問題は発生しません。 

もう 1 つの興味深いケースはサイクルです```
1 - 2 - 3 - 4 - 1
```すでに頂点 1、2、および 3 を訪問しているとします。頂点 2 では、両方の隣接頂点にフラグが設定されているため、アルゴリズムはランダムな移動を実行します。 最終的に頂点 3 に到達しますが、そこにはまだ未訪問の近傍頂点 4 があります。このようなフロンティア頂点に到達した瞬間、アルゴリズムは再び拡張されます。 

最後に、同じ次数を持つ対称頂点を考えます。 例えば、```
    2
    |
1 - 3 - 4
```頂点 1 と 4 は両方とも次数 1 を持ちます。 アルゴリズムはそれらを区別しようとしません。 フラグの状態のみを使用するため、隣接するノードの順序が変更されても、保存されている情報が無効になることはありません。 これにより、問題の主な困難が回避されます。
