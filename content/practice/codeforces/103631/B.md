 ## 問題の理解

 同じインデックス線上に重み付けされた間隔を定義する 2 つの配列が与えられます。 1 つの配列は「コスト」値に寄与し、もう 1 つの配列は「利益」値に寄与します。 考えられるすべてのサブセグメントについて\([l, r]\)、これら 2 つの配列がセグメント構造とどのように重なるかに応じてスコアを評価します。 中心的な目的は、あらゆるポジションについて決定することです。\(x\)、対象となるすべてのセグメントによって引き起こされる式の可能な限り最良の値\(x\)そして、これらのポジションごとの最良の値をグローバル最大値に集計します。 

問題をより具体的に確認する方法は、すべてのセグメントを確認することです。\([l, r]\)内部のすべての位置と各位置でアクティブになる関数を定義します\(x\)は、それを含むすべてのセグメントの最大の寄与を知っている必要があります。 最終的な答えは、すべての位置の最大値です。 

このステートメントは代数変換を通じて表現されますが、本質的な難しさは幾何学的なものです。各区間は点の連続範囲に影響を与えるため、それをカバーするすべての区間にわたって点ごとの最大値を計算する必要があります。 制約 (このクラスの問題に典型的なもの) は、次のことを意味します。\(n\)は十分に大きいため、すべての \(O(n^2)\) 間隔を列挙することは不可能であり、単純に位置ごとにすべてのアクティブな間隔を維持することさえ遅すぎます。 どのソリューションでも、すべてのセグメントを明示的に反復したり、セグメント値を繰り返し再計算したりすることは避けなければなりません。 

単純な推論による微妙な失敗のケースは、重複相互作用を考慮せずに各セグメントを独立して処理することに起因します。 たとえば、で終わる最適なセグメントを計算しようとすると、\(x\)で始まる最良のセグメント\(x\)別々に組み合わせて貪欲に組み合わせると、最適なセグメントがカバーされるため壊れます\(x\)慎重に構造化しない限り、独立した接頭辞と接尾辞の最適化に分解することはできません。 この相互依存が重要な構造上の困難です。 

もう 1 つの落とし穴は、それぞれについて次のように仮定することです。\(x\)、すべてのセグメントを固定順序でスキャンすることで、それをカバーする最適なセグメントを見つけることができます。 これは、小さな入力では正しく動作しますが、二次計算量に縮退し、次のような制約の下では失敗します。\(n\)大きいです。 

## アプローチ

 最も直接的なアプローチは、すべてのセグメントを列挙することです。\([l, r]\)、その寄与を一度計算し、その効果をすべてに伝播します。\(x \in [l, r]\)。 これは、各セグメントの値が固定されており、クエリの位置とは独立しているため、概念的には正しいですが、\(O(n^2)\) 個のセグメントにコストがかかり、セグメントごとに \(O(n)\) が更新される可能性があるため、単純な実装では \(O(n^3)\) が発生するか、慎重なプレフィックス合計では \(O(n^2)\) が発生します。 どちらも大規模なものには遅すぎます\(n\)。 

最初の構造的改善は、セグメントがカバーするすべてのポイントに同じ値をもたらしていることを認識することから始まります。 すべてを繰り返すのではなく\(x\)各セグメント内で、位置ごとに視点を反転できます。\(x\)を含むセグメントのみを考慮する必要があります。\(x\)。 問題は「それぞれについて」になります。\(x\)、カバーするすべての間隔の最大値を見つけます。\(x\)」

 これは古典的な変換ポイントです。区間からポイントへの伝播の代わりに、ポイントから区間へのクエリに切り替えます。 

ここで、問題は 2D の支配構造に似ています。 各セグメントは、その端点によって定義される概念空間内の四角形に対応し、各位置はそれをカバーするすべての四角形を照会します。 セグメント空間を分割統治することで、これを効率的に解決できます。 配列を中間点で分割します\(M\)、制御された方法で中間点を横切るセグメントのみを処理します。 固定された中間点の場合、次を満たすすべてのセグメントを考慮します。\(l \le M < r\)、すべてのポジションへの貢献度を計算します。\([L, R]\)。 

重要な洞察は、1 つのエンドポイントを修正すると (たとえば、\(l\))、最適な対応\(r\)範囲にわたる選択は、プレフィックス調整された値に対するセグメント ツリーを使用して維持できます。 掃き掃除\(l\)から\(M\)に\(L\)最適な正しいエンドポイントを維持するデータ構造を更新し、各エンドポイントの候補値を生成します。\(x\)。 2 番目のスイープでは、これらを位置ごとの最大値に集約します。 

分割統治再帰では、各セグメントがその中間点がある再帰レベルでのみ処理され、重複が回避されます。 これが、この方法が対数的な深さを実現し、各レベルが対数的な更新で線形スキャンを実行する理由です。 

より最適化された解釈により、セグメント ツリー構造が再帰間隔に合わせて調整されるため、再帰呼び出し全体で更新が自然に永続化され、ロールバック コストが排除され、複雑さがさらに軽減されます。

 ## アルゴリズムのチュートリアル

 インデックスセグメントに対して分割統治を使用して配列を処理します。 

1. 範囲にわたる再帰関数を定義します\([L, R]\)。 目標は、この範囲内に完全または部分的に存在するセグメントのみを使用して、この範囲内のすべての位置の正解を計算することです。 分割する理由は、各セグメントがその中間点が含まれる再帰レベルで 1 回だけ処理されるためです。 

2. 中点 \(M = \lfloor (L + R)/2 \rfloor\) を選択します。 これにより、問題が左半分、右半分、および両側にまたがる交差するセグメントに分割されます。\(M\)。 

3. まず、中点を横切るすべてのセグメント、つまり次のセグメントを処理します。\(l \le M < r\)。 これらは、影響が単一の再帰的な半分に完全に含まれていない唯一のセグメントであるため、このレベルで処理する必要があります。 

4. 交差するセグメントを処理するには、次のように修正します。\(r\)右側とスイープ\(l\)から\(M\)まで\(L\)。 それぞれについて\(l\)、可能な限りセグメントツリーを維持します\(r\)の値\([M+1, R]\)、投稿を次のように更新します\(l\)動く。 これは変更することで機能します\(l\)プレフィックスに依存する値のみを変更します。値は段階的に更新できます。 

5. 固定ごとに\(l\)、セグメント ツリーは、全体にわたって可能な限り最高の貢献を提供します。\(r\)、すべての位置の候補値を生成します\(x \in [l, r]\)。 これらの候補を、次のインデックスが付いた補助配列に保存します。\(x\)。 

6. コントリビューションを生成した後、左から右にスイープします。\(x \in [L, M]\)そして、各位置がそれをカバーする最良のセグメントを交差セットから受け取るようにプレフィックス最大値を維持します。 これにより、セグメントレベルの貢献度がポイントレベルの回答に変換されます。 

7. 右半分に対して対称処理を繰り返します\(x \in [M+1, R]\)、すべての交差するセグメントが完全に考慮されるようにします。 

8. 交差するセグメントを処理した後、左半分を再帰的に解決します。\([L, M]\)そして右半分\([M+1, R]\)それぞれの半分に完全に含まれるセグメントがそこで処理されるためです。 

この順序付けが機能する理由は、交差するセグメントが内部の再帰構造から独立しているためです。 特定の中間点でそれらが処理されると、それ以上の再帰でそれらを再検討する必要はありません。 

### なぜ効果があるのか

 各セグメントは、正確に 1 つの再帰レベル、つまり端点の間に中間点が存在するレベルに割り当てられます。 そのレベルでは、対象となるすべてのポジションに対する貢献を評価します。 すべてのステップで最大値を取得し、候補を削除しないため、各ポジションは関連するすべてのセグメントからの最良の寄与を 1 回だけ蓄積します。 分割統治構造により、セグメントの欠落や二重カウントが発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Prefix sums for fast segment evaluation
    pa = [0] * (n + 1)
    pb = [0] * (n + 1)
    for i in range(n):
        pa[i+1] = pa[i] + a[i]
        pb[i+1] = pb[i] + b[i]

    # segment tree for range add / range max
    size = 4 * n
    seg = [0] * size
    lazy = [0] * size

    def push(v):
        if lazy[v]:
            lv = v * 2
            rv = v * 2 + 1
            seg[lv] += lazy[v]
            seg[rv] += lazy[v]
            lazy[lv] += lazy[v]
            lazy[rv] += lazy[v]
            lazy[v] = 0

    def range_add(v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            seg[v] += val
            lazy[v] += val
            return
        push(v)
        m = (l + r) // 2
        if ql <= m:
            range_add(v*2, l, m, ql, qr, val)
        if qr > m:
            range_add(v*2+1, m+1, r, ql, qr, val)
        seg[v] = max(seg[v*2], seg[v*2+1])

    def get_max(v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return seg[v]
        push(v)
        m = (l + r) // 2
        res = -10**18
        if ql <= m:
            res = max(res, get_max(v*2, l, m, ql, qr))
        if qr > m:
            res = max(res, get_max(v*2+1, m+1, r, ql, qr))
        return res

    ans = [0] * n

    def solve_dc(L, R):
        if L == R:
            ans[L] = max(ans[L], b[L] - a[L])
            return

        M = (L + R) // 2

        # process crossing segments
        for l in range(M, L-1, -1):
            range_add(1, 0, n-1, M, R, -a[l])

        for l in range(M, L-1, -1):
            best = get_max(1, 0, n-1, M, R)
            for x in range(l, R+1):
                ans[x] = max(ans[x], best + (pb[x+1] - pb[l]))

        # recursive halves
        solve_dc(L, M)
        solve_dc(M+1, R)

    solve_dc(0, n-1)
    print(max(ans))

solve()
```この実装では、プレフィックス合計を使用してセグメントの寄与を迅速に評価し、セグメント ツリーを使用して左エンドポイントをスイープしながらダイナミック レンジ調整を維持します。 分割統治機能により、各中間点は交差するセグメントのみを処理するようになります。 主な微妙な点は、セグメント ツリーのインデックスと配列の位置の間の正しい位置合わせを維持することです。これは、プレフィックスの合計やセグメント境界におけるオフバイ 1 エラーによって、コントリビューションがひっそりと破損する可能性があるためです。 

注意点は、プレフィックスの合計が次の形式で使用されることです。\(pb[r+1] - pb[l]\)、これには一貫したハーフオープンインデックス作成が必要です。 クローズド規約とハーフオープン規約を混在させると、正しさが損なわれてしまいます。

 ## 特殊なケース

 A critical edge case is when all arrays are monotonic in opposite directions. このような場合、最適なセグメントが配列全体になる傾向があり、寄与分を誤って分割すると全体的な累積が過小評価されてしまいます。 分割統治により、全区間が最上位の再帰レベルで考慮されるため、このケースは自然に処理されます。

 すべての値が同一である場合、別の特殊なケースが発生します。 Here every segment has equal value density, so any segment is optimal depending on implementation tie-breaking. アルゴリズムは、セグメント ツリーの更新における厳密な不平等のために等しい候補を破棄してはなりません。 

最後の微妙なケースは、最適なセグメントが非常に短く、単一のピークの周囲に集中している場合に発生します。 長いセグメントのみを考慮する素朴なスイープではこれらを見逃してしまいますが、中間点ベースの処理により、長さ 1 のセグメントであっても再帰リーフで明示的に処理され、正確さが維持されます。
