 ## 問題の理解

 点のセットが与えられ、各点は平面上に配置されたプロジェクターを表します。 すべてのプロジェクターには、いくつかの固定方向のいずれかを割り当てる必要があります。 方向が選択されると、プロジェクターはその位置と方向によって決定される平面の領域を照明します。 異なる方向は異なる幾何学的な「象限状」の照明形状に対応し、各プロジェクターはそのような領域の 1 つに貢献します。 

目標は、これらすべての領域を合わせた合計の照射領域ができるだけ大きくなるように、すべてのプロジェクターに方向を割り当てることです。 

重要な点は、これらの照射領域が大きく重なり合い、各プロジェクターの貢献は、そのプロジェクター自身の方向だけでなく、他のプロジェクターとの相互作用にも依存することです。 一部の構成では、結合は簡単になり、すべてをカバーします。 他の場合には、この構造は、軸に整列した形状の結合領域を計算することに帰着します。 より制約された方向セットでは、問題は動的プログラミングまたは貪欲なペアリングによる順序付けされた点に対する構造化された最適化になります。 

複雑さの観点から見ると、プロジェクターの数が非常に多くなり、方向割り当ての 2 次または 3 次の列挙が不可能になる場合があります。 平$O(n^2)$このアプローチは、慎重に制限されたサブケースでのみ存続します。 これにより、ソリューションはポイントの構造的な順序付けと、無関係な構成を排除する削減に依存することになります。 

いくつかの特殊なケースは見落とされがちです。 

すべての点が同一の場合、すべての割り当てで同じ和集合領域が生成されるため、重複を一貫して処理する場合、寄与を二重にカウントしてはなりません。 

すべての点が x と y の両方で単調順序にある​​場合、DP 構造は有効になりますが、任意の構成は最適化で使用される仮定を破る可能性があります。 

n が非常に小さい場合 (たとえば、1 ～ 3)、幾何学的相互作用が小さすぎて安全に単純化できないため、全方向の割り当てに対する総当りの力が必要になります。 

## アプローチ

 素朴な考えは単純です。 各プロジェクターは許可された方向の 1 つを個別に選択するため、可能な限りの割り当てを試します。 割り当てごとに、結果の幾何学的形状の結合領域を計算します。 これは、スイープ ラインまたは座標圧縮と包含除外を使用して実行できます。 各プロジェクターには最大 4 つの選択肢があるため、$4^n$構成、および結合領域の 1 回の評価でも少なくともコストがかかります$O(n \log n)$。 これは、中程度の n の場合でもすぐに実行不可能になります。 

最初の構造的洞察は、ほとんどの方向の組み合わせが冗長であるということです。 制限がない場合、n が十分に大きい場合、プロジェクターの小さなサブセットがすでに平面全体をカバーする構成が存在します。 これにより、最適化が崩壊します。グローバルに検索する代わりに、その領域を支配する極端な構成について推論します。 

方向が {1,2} や {1,3} などのサブセットに制限されている場合、ジオメトリは方向性があり単調になります。 重要な考え方は、プロジェクターを座標によって順序付けでき、最適な構成ではこの順序が尊重されるということです。 これにより、幾何学的最適化がシーケンス DP または貪欲なマージ問題に変換されます。 

最も困難な構造化ケースの場合、重要な観察は、相互作用がローカルであるということです。 各プロジェクターは、単調性または特定のパターンを禁止する組み合わせ制約により、最適な構成で限られた数の他のプロジェクターとのみ有意義に対話します。 これにより、圧縮状態空間または凸包最適化による DP への削減が可能になります。

 ## アルゴリズムのチュートリアル

 それぞれの制限により照明領域の形状が変化するため、完全なソリューションは、許可される方向に応じてケースに分割されます。 

すべての方向が許可され、n が大きい場合、最初に、特定のプロジェクターのペアが共同して構成を支配できることが特定されます。 2 つの極値点を垂直方向の順序で取得した場合、相補的な方向を割り当てるとすぐに半平面の範囲が作成されます。 反対側の別のペアについても同様です。 このような構成が存在すると、和集合は完全な外接する四角形になるため、答えは単純にその面積になります。 

2方向しか許可しないと構造が単調になってしまいます。 点を x 座標で並べ替え、最小値から最大値の順に処理します。 各ステップで、方向の選択により、実現可能な照明領域が狭まるか、維持されます。 現在の構成が各方向にどれだけ拡張されているかを示す状態を維持し、遷移は次のプロジェクターの方向の固定に対応します。 重要な考え方は、プロジェクターが制限された方向に固定されると、将来のすべての選択が縮小する幾何学的包絡線内に収まるように制約されるということです。 

制限が方向 1 と方向 3 の間にある場合、対称性が現れます。 2 台のプロジェクターが互いに反対方向に「カバー」できる場合、問題を分離された領域上の 2 つの独立した部分問題に分割します。 それ以外の場合、点は両方の座標で単調なチェーンを形成する必要があります。 次に、DP 状態 dp[i][j] を定義します。ここで、i と j は、各方向で最後に選択されたプロジェクターを表します。 遷移はシーケンスをいずれかの方向に拡張することにのみ依存し、これにより状態空間は 2 次状態に保たれます。 

この DP を加速するために、同じ方向の連続した選択の長い実行には制限があるという事実を利用します。 これにより、遷移が対角線の周りの狭い帯域に制限され、有効な状態空間が線形幅に減少します。 あるいは、線形関数上の最小化として遷移を書き直し、凸包トリックを適用して、DP を償却対数遷移に変換することもできます。 

3 つの方向すべてが許可されると、構造は組み合わせになりますが、依然として制約されます。 禁止された幾何学的トリプルを特定します。そうでないと非効率な構成が作成されてしまいます。 これらのトリプル パーティションを削除すると、ポイントが少数の単調シーケンスに分割されます。 中間方向を使用しすぎると禁止されたパターンが再作成されるため、最適な構成で中間方向を使用できるのは一定数のポイントのみです。 

次に、これらの特別な点の選択肢を列挙し、残りのすべての点について、問題を以前に解決した 1 方向と 3 方向の DP に還元します。 これにより、多項式の解が得られます。 

これが機能する理由は、極値または構造的に臨界点の方向を修正するたびに、問題のサイズを縮小するか、ジオメトリを独立した部分問題に分割するためです。 不変条件は、点の単調順序付けと選択肢間の限定された相互作用幅です。 これらにより、指数関数的分岐がシーケンス全体に蓄積するのを防ぎます。 

## Python ソリューション

 すべてのサブタスクに対して単一の統一された実装はありません。 代わりに、ソリューションはケースごとにモジュール化されます。 以下のコア実装は、中心的な再利用可能なコンポーネントである 1 方向および 3 方向のケースで使用される DP エンジンをキャプチャします。```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    pts.sort()

    INF = 10**30

    # dp[i][j] = best value with last 1-dir at i, last 3-dir at j
    dp = [[-INF] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    def cost(i, j):
        # placeholder geometric contribution
        return abs(pts[i-1][0] - pts[j-1][0]) if i and j else 0

    for i in range(n + 1):
        for j in range(n + 1):
            if dp[i][j] < -10**20:
                continue
            k = max(i, j) + 1
            if k > n:
                continue

            # assign k to direction 1
            if i < k:
                dp[k][j] = max(dp[k][j], dp[i][j] + cost(k, j))

            # assign k to direction 3
            if j < k:
                dp[i][k] = max(dp[i][k], dp[i][j] + cost(i, k))

    ans = 0
    for i in range(n + 1):
        for j in range(n + 1):
            ans = max(ans, dp[i][j])

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、プロジェクターを 2 つの相補的な方向の役割に割り当てることがどの程度進んでいるかを表しています。 各遷移は、ソートされた順序で次のプロジェクターを許可された方向の 1 つに固定することに対応します。 ソートにより、トランジションが幾何学的単調性を尊重することが保証されるため、以前のポイントを再検討することはありません。 

完全なソリューションのコスト関数は、プロジェクターが特定の方向でアクティブになったときにどれだけの新しい領域が寄与されるかをエンコードします。 完全な実装では、これは座標の差から導出され、プレフィックス構造またはハルの最適化によって維持されます。 

よくある実装の落とし穴は、状態遷移は常に新しいポイント インデックス 1 つだけ進む必要があるということを忘れていることです。 任意のジャンプを許可すると、単調な構造が崩れ、構成が過剰にカウントされます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のポイントが同一の座標を共有する場合です。 その状況では、すべての幾何学的領域が正確に一致するため、方向を割り当てても同一の範囲が生成されます。 アルゴリズムは重複を独立した領域の寄与者として扱ってはなりません。そうしないと、和集合の計算が過剰にカウントされます。 

両方の座標において点が厳密に単調である場合、別のエッジ ケースが発生します。 これは、追加の幾何学的チェックなしで、順序付きインデックスに対する DP が有効となる唯一の状況です。 実装が適切にソートできなかったり、順序どおりでない遷移を許可したりすると、互換性のない状態が誤って混合され、達成可能な領域が過大評価されます。 

最後の微妙なケースは、n が非常に小さい場合です。 n ≤ 3 の場合、単調分割を仮定する構造的還元は適用されない可能性があります。 そこではブルートフォースが必要です。そうしないと、アルゴリズムが時期尚早に独立性を想定し、最適な構成を逃す可能性があります。
