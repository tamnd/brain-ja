 ## 解決策
 ## 問題の理解

 ケーキを表す長方形のグリッドが与えられます。 一部のセルにはすでに大文字が含まれており、各文字はグリッド全体で 1 回だけ表示されます。 1 つおきのセルは空です。 各文字は人物に対応しており、その人物はグリッドに沿った長方形の形でつながったケーキを受け取る必要があります。 文字に割り当てられた四角形には、その文字が表示される元のセルが含まれている必要があり、グリッド内のすべてのセルが 1 つの文字に正確に割り当てられている必要があります。 各文字の領域を空のセルに拡張することはできますが、文字を移動したり複製したりすることはできず、各文字の最終領域は単一の実線の長方形でなければなりません。 

主な難しさは、グローバルな一貫性を尊重する方法ですべての疑問符のセルを埋める必要があることです。 1 つの文字の四角形を拡張すると、他の文字の可能な四角形に影響を与えるため、構造化されたルールに従わない限り、ローカルで貪欲な決定を行うと実現可能性が損なわれる可能性があります。 

制約は十分に小さいため、直接 2 次または 3 次グリッドベースの構築でも問題ありません。 最大でも 25 x 25 のセルであれば、グリッドを繰り返しスキャンしたり四角形を明示的に塗りつぶすアルゴリズムは問題なく合格します。 これにより、重いグラフ アルゴリズムや最適化構造の必要性が排除されますが、効率ではなく正確さに注意する必要があることも意味します。 

単純な埋め込みでよくある失敗例は、他の文字と調整せずに各文字を独立して拡張することです。 たとえば、2 つの文字が同じ行にあり、左右の両方を貪欲に拡張すると、重複する領域が作成されたり、文字が元のセルを強制的に失ったりする可能性があります。 もう 1 つの微妙な問題は、境界位置にのみ表示される文字の処理です。これは、その四角形が隣接する文字と一貫性を保ったまま拡張される必要があるためです。 

## アプローチ

 強引なアイデアは、すべての空のセルを既存の文字の 1 つに割り当て、各文字が元のセルを含む四角形を形成しているかどうかを確認することです。 これは概念的には単純ですが、最大 625 個のセルのそれぞれに最大 26 個の選択肢があり、天文学的に大きな検索空間が必要となるため、完全に実行不可能です。 

問題の構造は、より決定論的なアプローチを示唆しています。 各文字は長方形内に収まる必要があり、各文字は 1 回だけ表示されます。 これは、各文字が縦横にどのように広がるかを決定すれば、最終的な解は一意に決まることを強く示唆しています。 主な洞察は、グリッドを行ごとに分割されているものとして扱うことです。どの文字が各行を支配するのかがわかれば、連続する水平セグメントを一貫して埋めることができます。 

これについて考えると便利な方法は、すべての文字がシードとして機能し、その文字が「所有する」すべての空のセルを含む長方形を形成するまで、その影響を外側に拡大したいということです。 各文字は 1 回だけ出現するため、最初に垂直方向に拡張して各文字の行境界を決定し、次にそれらの境界内を水平方向に塗りつぶします。 

重要な観察は、有効な解決策において、ある行に文字が出現する場合、その最上位と最下位の間のすべての行には、ある間隔に完全にまたがるその文字の四角形が含まれている必要があるということです。 これにより、制御された方法で文字を下方向と上方向に伝播させることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(26^(RC)) | O(RC) | 遅すぎる |
 | 行方向の拡張フィル | O(RC) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのパスでソリューションを構築します。 まず各文字が垂直方向にどれだけ伸びるかを決定し、次に水平方向の範囲を行ごとに割り当てます。

1. グリッドをスキャンし、文字ごとに、その文字が表示される最小および最大の行インデックスを記録します。 これにより、各文字の垂直方向の間隔が決まります。 この手順が機能するのは、有効な四角形が文字のすべての出現をカバーする必要があるためです。 
2. 各行について、その行でどの文字が「アクティブ」であるかを決定します。これは、その行が垂直間隔内にあることを意味します。 この時点で、各行は概念的に文字の一部のサブセットに分割されます。 
3. 行内で左から右にスキャンします。 文字に遭遇すると、それが現在アクティブなセグメントの開始文字として記憶されます。 別の既知の文字に到達するまでその文字を右に伝播させ、連続したセグメントを確保します。 行に文字がない場合は、隣接する行からの垂直方向の伝播に依存します。 
4. 利用可能な最も近い文字セグメント構造を使用して、各行を完全に埋めます。 これにより、各行が連続したブロックのシーケンスとなり、それぞれが 1 つの文字に属することが保証されます。 
5. すべての行を埋めた後、各文字は垂直方向の間隔が連続しており、各行内で連続したセグメントを占めるため、接続された長方形を形成します。 

正確かどうかは、文字の領域が行内に割り当てられた後は決して水平方向に分割しないことと、文字の垂直方向の範囲外にあるセルを文字に割り当てないという事実にかかっています。 

### なぜ効果があるのか

 各文字は、最後の長方形で完全に覆われなければならない垂直間隔を定義します。 長方形はグリッド方向に凸であるため、行内の連続するセグメントを覆うように文字が割り当てられると、後で長方形のプロパティに違反せずに文字を分割することはできません。 この構造では、割り当てを決定論的に伝播することで行間の一貫性が保証されるため、以前に割り当てられた行と矛盾する行は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        R, C = map(int, input().split())
        grid = [list(input().strip()) for _ in range(R)]

        first = {}
        last = {}

        for i in range(R):
            for j in range(C):
                ch = grid[i][j]
                if ch != '?':
                    if ch not in first:
                        first[ch] = i
                    last[ch] = i

        res = [row[:] for row in grid]

        for i in range(R):
            # find a letter in this row
            current = None
            for j in range(C):
                if res[i][j] != '?':
                    current = res[i][j]
                    break

            # fill left to right
            if current is not None:
                for j in range(C):
                    if res[i][j] != '?':
                        current = res[i][j]
                    res[i][j] = current

        # fix empty rows by copying nearest filled row
        for i in range(R):
            if all(res[i][j] == '?' for j in range(C)):
                up = i - 1
                while up >= 0 and all(res[up][j] == '?' for j in range(C)):
                    up -= 1
                down = i + 1
                while down < R and all(res[down][j] == '?' for j in range(C)):
                    down += 1

                source = up if up >= 0 else down
                res[i] = res[source][:]

        print(f"Case #{tc}:")
        for row in res:
            print("".join(row))

if __name__ == "__main__":
    solve()
```実装はまずグリッドを読み取り、それを保存します。 文字の垂直範囲を計算しますが、このバージョンでは、明示的に適用されるのではなく、伝播を正当化するために暗黙的に使用されます。 メインの充填パスは、各行を個別に処理し、空白セグメントが正しい所有者を継承するように、最新の既知の文字を引き継ぎます。 文字を含まない行は、最も近い空でない行からコピーすることによって処理され、垂直方向の長方形の連続性が保持されます。 

微妙な点は、行内の水平方向の伝播は、新しい文字に遭遇するたびにリセットされ、異なる文字間の境界が確実に尊重されるようにする必要があることです。 このリセットがないと、単一の文字が別のシードに属する領域に誤って拡張される可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
G??
?C?
??J
```まず、シード G、C、J を識別します。各行は個別に処理されます。 

| 行 | イニシャル | 伝播結果 |
 | --- | --- | --- |
 | 1 | え?? | ＧＧＧ |
 | 2 | ?C? | CCC |
 | 3 | ??J | ＪＪＪ |

 伝播後、各文字の領域は行全体で水平方向および垂直方向に連続して整列されます。 

これは、各行が一貫して入力されると、垂直方向の一貫性が自然に現れることを示しています。 

### 例 2

 入力:```
CODE
????
?JAM
```行 1 と行 3 にはすでにアンカーが含まれています。 2 行目は空であり、近くの有効な行からコピーすることで埋められます。 

| 行 | 出典 | 結果 |
 | --- | --- | --- |
 | 1 | 自分 | コード |
 | 2 | 行 1 または 3 | COAM または COAM スタイルの塗りつぶし |
 | 3 | 自分 | ジャム |

 これは、最も近い構造化行からの垂直伝播によって空の行がどのように解決されるかを示しています。

 ## 特殊なケース

 主なエッジケースは、文字が 1 回だけ表示され、隅に孤立している場合です。 行の伝播によって行全体に拡張され、垂直コピーによって必要なすべての行に確実に到達するため、このアルゴリズムにより、行が正しく拡張されることが保証されます。 

もう 1 つの特殊なケースは、行全体に文字が含まれていない場合です。 その場合、最も近い有効な行からコピーすると、未定義の行がなくなり、長方形の連続性が維持されます。 

最後の特殊なケースは、行全体でまばらな文字が交互に配置されることです。 伝播メカニズムにより、行に文字構造が割り当てられると、後続の行は独立して再計算するのではなく連続したセグメントを継承するため、その構造に違反しないことが保証されます。
