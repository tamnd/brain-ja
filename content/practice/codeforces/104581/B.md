 ## 解決策
 ## 問題の理解

 私たちは、料理一食分に各材料が何グラム必要かという固定レシピを与えられています。 各成分について、各パッケージに特定のグラム数の成分が含まれる複数のパッケージも受け取ります。 すべての成分には同じ数のパッケージが含まれています。 

目的はキットを組み立てることです。 各キットには、すべての成分が 1 つのパッケージに含まれている必要があります。 キットには分量が割り当てられており、この数値は整数である必要があります。 キットは、各成分について、その成分に対して選択されたパッケージが、その分量の必要量の 90% から 110% 以内にある場合、一定の分量に対して有効です。 

できるだけ多くの有効なキットを選択し、各パッケージは最大 1 回使用できるようにしたいと考えています。 私たちはキットあたりの分量を最大化しようとしているのではなく、有効なキットの数を最大化しようとしているだけです。 

この制約では、最大 50 個の成分と成分ごとに最大 50 個のパッケージが許可され、テスト全体のパッケージの総数は 1000 に制限されます。これにより、成分間でパッケージを組み合わせるあらゆる方法を徹底的に試行しようとするアプローチは即時に除外されます。これは、次元間の組み合わせ爆発が含まれるためです。 

主な問題点は、パッケージには単一の固定された「マッチング パートナー」が存在しないことです。 3 食分に適したトマトのパッケージでも、別の玉ねぎのパッケージと組み合わせると、4 食分にならない可能性があります。 したがって、互換性は、キット内のすべての成分にわたる摂取量の共通の選択に依存します。 

単純な間違いは、各成分を独立して扱うことです。 たとえば、パッケージごとに有効な提供範囲を計算し、成分間で同期せずに重複を貪欲に一致させると、一貫性のないキットが生成される可能性があります。 もう 1 つの微妙な失敗は、材料ごとに 1 回分の数を個別に選択していることです。 これは、キット内のすべての成分が同じ整数の摂取量に同意する必要があるという要件を破っています。 

エッジケースには、ある成分の分散パッケージが非常に小さく、別の成分の分散が非常に広い状況が含まれます。 このような場合、異なる順序でより多くのキットが生成される場合でも、ローカルで貪欲な選択を行うと、互換性のないグローバル ペアリングに閉じ込められる可能性があります。 

## アプローチ

 ブルートフォースの視点は、各材料から 1 つのパッケージを選択し、その組み合わせに対して有効な整数のサービング数を検索してキットを形成しようとしているところを想像することから始まります。 パッケージの固定タプルの場合、食材ごとに可能な摂取量の値の範囲を計算できます。 これらすべての範囲の交差により、タプルが有効かどうかがわかります。 有効な場合、実行可能な整数の値を 1 つ抽出します。 

これは概念的には機能しますが、タプルの数は P^N であり、N = 10、P = 50 のような中程度の値であっても天文学的に大きくなります。互換性は離散ラベルではなく連続間隔に依存するため、対称性を減らしても十分な効果はありません。 

重要な観察は、問題をひっくり返すことです。 任意の組み合わせからキットを構築するのではなく、各成分のパッケージを分類し、「最も制約された可能な限りのキット」を一致させることを繰り返し試みることとして問題を扱います。 パッケージごとに、それを有効にするための摂取間隔を計算できます。 各パッケージは数直線上の区間になります。 キットは、選択されたすべての間隔が少なくとも 1 つの共通の整数点を共有するように、各成分から 1 つの間隔を選択することに対応します。 

ここで問題は次のようになります。交差部分が空ではない成分ごとに 1 つの間隔のセットを繰り返し見つけ、それらの間隔を削除して繰り返します。

これは貪欲な構造を示唆しています。 パッケージを成分ごとに分類すると、常に残りの実行可能な最小構成からキットの構築を試みることができます。 正しい戦略は、「最も厳しい」制約から得られる候補となる摂取量を繰り返し選択し、その後、すべての食材にわたって互換性のあるパッケージを貪欲に選択することです。 

公式ソリューションで使用されているより具体的な簡略化は、各パッケージの有効な提供範囲 [L, R] を事前計算することです。 次に、各成分について、これらの範囲を L で並べ替えます。残りの候補の中から可能な限り最小の L を選択し、すべての成分にわたって一貫した交差をスキャンすることにより、キットの形成を繰り返し試みます。 キットが形成されたら、選択したパッケージを削除して続行します。 

これが機能するのは、有効なキットがオーバーラップ ポイントに対応する必要があり、利用可能な最小の左エンドポイントを選択することで、将来の一致をブロックする可能性がある実現可能な最小ソリューションをスキップしないことが保証されるためです。

 ## アルゴリズムのチュートリアル

 1. 材料ごとに、各パッケージの有効な摂取間隔を計算します。 数量 Q とレシピ要件 R のパッケージの場合、サービング数 s は 0.9・s・R ≤ Q ≤ 1.1・s・R を満たす必要があります。 これを整数値の範囲に再配置します。 これにより、各パッケージが連続的な実現可能性間隔に変換されます。 
2. 各成分内のすべての間隔を左のエンドポイントで並べ替えます。 これにより、常に最も制限の厳しい候補が最初に考慮されるようになり、貪欲な選択には不可欠です。 
3. 最初の未使用パッケージ間隔を示すポインタを成分ごとに維持します。 
4. キットの構築を繰り返し試みます。 

各成分について、現在利用可能な最小の間隔を取得します。 左の端点の最大値と右の端点の最小値を取得して、これらすべての間隔の交差を計算します。 
5. 交差点が空いている場合、それ以上キットを形成することはできず、停止します。 その理由は、ポインタを増やしても左の端点がさらに右に移動するだけであり、最小限の選択肢の間にすでに存在しない重複を復元することはできないということです。 
6. 交差部分が空でない場合は、その内部の任意の整数値 (通常は左側の境界) を選択します。 次に、選択した間隔に対応する各成分から 1 つのパッケージを選択し、すべてのポインターを進めることで使用済みとしてマークします。 
7. 有効な交差点が存在しなくなるまで繰り返します。 

機能する理由: すべての有効なキットは、交差部分に何らかの整数が含まれる成分ごとに 1 つの区間を選択することに対応します。 考えられるすべてのキットの中には、選択された間隔に残りの間隔の中で可能な最小の左端点が含まれるキットが常に存在します。 貪欲なステップはこの最も早い実現可能なオーバーラップを捕捉し、制約の厳しさが増す順に間隔が消費されるため、これを削除しても後の独立したオーバーラップの実現可能性を破壊することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_interval(q, r):
    # 0.9 * s * r <= q <= 1.1 * s * r
    # => q / (1.1 r) <= s <= q / (0.9 r)
    # use integer bounds carefully
    import math
    lo = math.ceil(q / (1.1 * r))
    hi = math.floor(q / (0.9 * r))
    return lo, hi

def solve():
    T = int(input())
    out = []

    for tc in range(1, T + 1):
        n, p = map(int, input().split())
        R = list(map(int, input().split()))

        intervals = []
        for i in range(n):
            row = list(map(int, input().split()))
            lst = []
            for q in row:
                lo, hi = build_interval(q, R[i])
                lst.append((lo, hi))
            lst.sort()
            intervals.append(lst)

        ptr = [0] * n
        ans = 0

        while True:
            cur = []
            for i in range(n):
                if ptr[i] == p:
                    cur = None
                    break
                cur.append(intervals[i][ptr[i]])

            if cur is None:
                break

            L = max(x[0] for x in cur)
            Rr = min(x[1] for x in cur)

            if L <= Rr:
                ans += 1
                for i in range(n):
                    ptr[i] += 1
            else:
                # discard the most restrictive left endpoint
                # advance one pointer: the ingredient that blocks feasibility
                worst = 0
                for i in range(1, n):
                    if cur[i][0] > cur[worst][0]:
                        worst = i
                ptr[worst] += 1

        out.append(f"Case #{tc}: {ans}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中心となるアイデアは、各パッケージを提供間隔に変換し、食材ごとに 1 つの間隔を揃えることを繰り返し試行することです。 ポインターにより、各パッケージが最大 1 回使用されることが保証されます。 貪欲な削除ステップは微妙です。交差が失敗した場合、左側のエンドポイントの圧力が最大の間隔を破棄します。これは、他のエンドポイントとの重複をブロックする原因が最も大きいためです。 

主な落とし穴は、区間計算における浮動小数点精度です。 実際に使用すると、`ceil`そして`floor`慎重に構造化された式はコンテストの制約には十分ですが、より安全なアプローチでは、すべてを 10 でスケールして小数を完全に回避します。

 ### 例 1

 パッケージが単一成分の場合を考えてみましょう。`[11, 18, 11]`そしてレシピの要件は`10`。 

| ステップ | 現在の間隔 | Ｌ | R | アクション | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [(1,1),(1,1),(1,1)] | 1 | 1 | キットを取る | 1 |
 | 2 | 同じ構造のまま | - | - | キットを取る | 2 |
 | 3 | 最後に残った 18 | (2,2) | 2 | キットを取る | 3 |

 すべてのパッケージは個別に 1 回分の摂取量をサポートするため、それぞれが独自のキットを形成します。 

これは、すべての間隔が同一の単一点に崩壊しても、貪欲なペアリングが将来の実現可能性を妨げないことを示しています。

 2 つの成分:

 成分Aパッケージ: 450、449

| ステップ | 間隔 | B 間隔 | 交差点 | アクション | 答え |

 | 1 | (10,10) | (10,10) | 有効 | フォームキット | 1 |

 ## 特殊なケース

 主なエッジケースは、間隔が境界にギリギリ接触する場合です。 たとえば、1 つのパッケージが上限でのみ 10 の提供を許可し、別のパッケージが下限でのみ 10 の提供を許可する場合、交差には依然として 10 が含まれます。アルゴリズムは、包含的な不等式を使用しているため、これらを有効なものとして扱います。`ceil`そして`floor`境界の正確性を維持します。 

別の特殊なケースは、ある成分の間隔が単調に縮小しているのに、他の成分の間隔が広い場合に発生します。 貪欲なポインタの前進により、重複を防ぐ間隔が常に最も早く破棄され、時期尚早に不正な位置合わせが行われることが回避されます。 

最後の微妙なケースは、範囲がわずかにずれている 1 つの外れ値区間を除いて、残りのすべての区間が重なる場合です。 このアルゴリズムは、左側のエンドポイントを最大化するため、まずその外れ値を削除し、一貫したクラスターから構築される将来のキットの実現可能性を回復します。
