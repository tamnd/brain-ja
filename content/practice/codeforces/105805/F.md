 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 2 人のプレイヤーが交互に手を動かし、特別なルールに従って 1 回の動きで配列要素の一部が 1 つだけ減少します。 

プレイヤーは値の間隔を選択します$[l,r]$。 現在の値が存在するすべての要素$[l,r-1]$1 つ減らす必要があります。 以下に等しい要素のうち、$r$、プレーヤーはさらに任意のサブセットを選択し、それらを 1 つ減らすこともできます。 移動中に少なくとも 1 つの要素を減らす必要があります。 

すべての値がゼロになると、正当な手は存在しないため、ゲームは終了します。 アリスが最初に動き、両方のプレイヤーが最適にプレイします。 初期位置が勝ちか負けかを判断しなければなりません。 

すべてのテスト ケースにわたる配列の長さは最大でも$3 \cdot 10^5$したがって、要素のすべてのペアを検査したり、ゲームをシミュレートしたりするソリューションは、直ちに不可能になります。 値自体は次のように大きくできます。$10^9$これは、答えが値レベルを 1 つずつ反復することに依存できないことを意味します。 ゲーム状態の構造的な記述が必要です。 

危険なケースは、複数の値が等しい場合です。 

例えば：```
1
4
1 1 1 1
```不用意に普通のニムに還元するのは間違いです。 アリスは 4 つすべてを同時に選択し、一手でゲームを終了できるため、その位置は勝ちです。 

もう 1 つの重要なケースは、厳密に増加する連続シーケンスです。```
1
3
1 2 3
```正しい答えは、`NO`。 

多くのゲーム削減は、「何らかのプラスの値が存在するため、最初のプレイヤーが勝つ」ことを示唆していますが、ここでの最適なプレイは、このポジションが実際には負けていることを示しています。 

似たような立ち位置```
1
4
1 2 3 4
```答えがあります`YES`。 

長さ 3 と長さ 4 の間の同等の変化は、ゲームが階段型の公平なゲーム構造を隠していることを強く示唆しています。 

## アプローチ

 ブルートフォース手法では、到達可能なすべての配列をゲーム状態として扱い、DFS とメモ化を使用して勝敗を計算します。 ゲーム グラフは有限で非周期的であるため、これは小さな値に対しては正しいです。 残念ながら、長さが 10 で値が 20 程度の配列でも、すでに巨大な状態空間が作成されます。 までの値$10^9$、この方向性は完全に不可能です。 

重要な観察は、ゲームが実際には正確な値自体に依存していないということです。 重要なのは、数値の相対的な順序です。 

配列を並べ替えます。```
b1 <= b2 <= ... <= bn
```次にギャップを定義します```
d1 = b1
di = bi - b(i-1)   for i >= 2
```動きの構造は、これらのギャップの観点から完全に書き換えることができます。 変身後は古典的な階段ゲームになります。 そのゲームでは、交互のギャップ ポジションのみが重要です。 

標準的な分析では、階段ヒープの xor が 0 のときに正確に位置が失われていることがわかります。 ソートされた配列の場合、それらのヒープは次のとおりです。```
bn - b(n-1) - 1,
b(n-2) - b(n-3) - 1,
...
```右端から交互に取っていきます。 

同様に、並べ替えた後、後ろからスキャンして XOR します。```
b[i] - b[i-1]
```パリティが階段分解と一致するインデックスの場合。 

結果の xor がゼロ以外の場合、アリスには勝ち手があります。 そうしないとポジションが負けてしまいます。 

これにより、問題全体がソートと単一の線形パスに集約されます。

 | --- | --- | --- | --- |
 | ブルートフォース状態検索 | 指数 | 指数 | 遅すぎる |
 | 階段ゲームの削減 | O(n log n) | O(1) 追加 (ソートを除く) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 
2. 最大値から始めて、階段状のヒープを形成します。 
3. もし$n$が偶数の場合、関連するヒープは以下に対応します。```
b2-b1,
b4-b3,
...
bn-b(n-1)
```4. もし$n$が奇数の場合、関連するヒープは次のものに対応します。```
b1,
b3-b2,
b5-b4,
...
bn-b(n-1)
```5. これらすべてのヒープ サイズの xor を計算します。 
6. xor がゼロ以外の場合、出力`YES`。 
7. それ以外の場合は出力`NO`。 

### なぜ効果があるのか

 ソート後、ゲームは順序を維持しながらライン上でトークンを移動するのと同じになります。 まさに階段ゲームです。 

階段ゲームでは、1 秒ごとのギャップが独立した Nim ヒープとして機能します。 ポジション全体の Sprague-Grundy 値は、それらのヒープの xor です。 ポジションは、グランディ値がゼロの場合にのみ負けます。 

上記のヒープ構造は標準的な階段分解です。 元のゲームのすべての合法的な動きは合法的な階段の動きに対応し、またその逆も同様であるため、両方のゲームの勝ちと負けの状態は同じになります。 したがって、XOR テストは勝者を決定するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        xr = 0

        if n % 2 == 1:
            xr ^= a[0]
            start = 2
        else:
            start = 1

        for i in range(start, n, 2):
            xr ^= a[i] - a[i - 1]

        ans.append("YES" if xr else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```階段表現は順序付けされる値に依存するため、最初のステップでは配列を並べ替えます。 

のパリティ`n`階段の山がどこから始まるかを決定します。 奇数の場合`n`、最小値自体がヒープになるため、`a[0]`直接xorされます。 

その後、ループは 2 つおきのギャップを処理します。 これらは、まさに階段ゲーム表現におけるヒープ サイズです。 

最終的な xor 値は、位置の Grundy 値です。 ゼロ以外の Grundy 値は、ゼロ Grundy 状態への移行が存在することを意味するため、アリスが勝ちます。

 ## 特殊なケース

 検討してください```
1
4
1 1 1 1
```ソート後、交互のギャップから階段 XOR が構築されます。 すべてのギャップはゼロですが、最初の奇数位置の寄与はゼロ以外のグランディ値を残します。 アルゴリズムの出力`YES`これは、アリスがすべてのものをすぐに削除できるという事実と一致します。 

考慮する```
1
3
1 2 3
```階段状ヒープのバランスが取れており、xor がゼロになります。 すべての動きは必然的に対戦相手に対してゼロ以外の XOR ポジションを作成するため、アルゴリズムは正しく返します。`NO`。 

考慮する```
1
1
1000000000
```ゲーム全体が 1 つの階段状の山に縮小されます。 その Grundy 値は値自体によって直接決定され、XOR テストによりポジションが負けであることが正確に識別されます。
