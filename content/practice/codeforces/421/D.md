 ## 解決策
 ## 問題の理解

 私たちにはプログラマーのネットワークが与えられており、各プログラマーは会議中に主張をします。彼らは他の 2 人のプログラマーを指して、犯人はその 2 人のうちの 1 人であると主張します。 次に、容疑者として連れて行くプログラマーを 2 人だけ選択する必要があります。 

私たちが選んだ 2 人のうち少なくとも 1 人が彼らが言及したペアに含まれている場合、コーダーは私たちが選んだペアを「サポート」します。 言い換えれば、各コーダーは、選択したペアが宣言された容疑者のペアと交差するたびに、候補の容疑者のペアに同意の投票を提供します。 

タスクは、少なくとも`p`プログラマはその選択に同意します。 

制約は大きく、プログラマー数は最大 300,000 人です。 すべてのペアにわたる二次列挙は、最悪の場合でも約 4.5 × 10^10 のチェックが必要となり、1 秒の制限をはるかに超えているため、直ちに不可能です。 これにより、ペアの評価を線形または線形に近い時間に近づけるという解決策に向かうことになります。 

微妙な点は、一致が「エッジを数える」という意味では対称ではないことです。 コーダーはどちらかのエンドポイントが一致する場合に寄与するため、ペアは完全一致ではなく重複に基づいて寄与します。 完全一致のみをカウントしたり、問題を単純なペアの頻度として扱う単純なアプローチでは、カウントを誤る可能性があります。 

よくある失敗例は、複数のプログラマーが同じペアを選択した場合に発生します。 たとえば、多くのプログラマーが報告した場合、`(1, 2)`、次にペア`(1, 2)`度数だけで示唆される以上に追加の補正が行われます。 これを無視すると、有効なペアが過剰にカウントされることになります。 

## アプローチ

 ブルートフォースソリューションは、順序付けられていないすべてのペアを試行します。`(u, v)`そして、すべてのコーダーをスキャンして、選択したペアが交差する数を数えます。`{u, v}`。 各チェックは一定時間であるため、合計の複雑さは最悪の場合の推論で O(n³)、または少なくとも O(n²) ペア×O(n) スキャンになりますが、これは完全に実行不可能です。 

すべてのコーダーをスキャンせずにペアの一致スコアを計算する方法が必要です。 重要な観察は、コーダーの貢献は、`u`または`v`彼らのペアで登場します`(x_i, y_i)`。 これは度を使用して書き換えることができます。 

定義すると`deg[x]`ペアに含まれるコーダの数として`x`、次に候補ペアについて`(u, v)`単純な貢献の合計は`deg[u] + deg[v]`。 ただし、正確に選択したプログラマーは、`(u, v)`合計では 2 回カウントされますが、貢献するのは 1 回だけです。 この超過数は、ペアが正確に一致するコーダーの数を減算することで修正されます。`(u, v)`、私たちはこれを呼んでいます`cnt[u][v]`。 

したがって、実際のスコアは次のようになります。`score(u, v) = deg[u] + deg[v] - cnt[u][v]`。 

この公式が強力なのは、`deg`O(n) で事前計算でき、すべて`(u, v)`実際に入力に現れるペアは、O(1) 補正ルックアップ用のハッシュ マップに保存できます。 

残りの課題は、満たすペアの数を数えることです。`score(u, v) ≥ p`すべての O(n²) 個の可能性を列挙せずに調べます。 問題を分割しました。 まず、修正を無視して、次のすべてのペアを数えます。`deg[u] + deg[v] ≥ p`。 次数は頂点のみに依存するため、頂点を次数でソートし、2 つのポインター スイープを使用して O(n) 内の有効なペアをカウントできます。 

次数のしきい値を通過した一部のペアは減算後に失敗する可能性があるため、これによりオーバーカウントが発生します。`cnt[u][v]`。 これらの問題のあるケースは、実際に入力に現れるペアに対してのみ発生します。これは、それらのペアのみがゼロ以外の補正を行うためです。 そこで、入力ペアをもう一度繰り返して、それらのペアを減算します。`deg[u] + deg[v] ≥ p`しかし`deg[u] + deg[v] - cnt[u][v] < p`。 

これにより、補正フェーズが O(n) に減少し、ソートによりソリューション全体が線形に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · n) | O(n) | 遅すぎる |
 | 度数+補正分解 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`deg[i]`すべてのコーダーインデックスに対して`i`すべての入力ペアを 1 回スキャンすることによって。 これは、すべてのステートメントにわたって各ノードが何回言及されたかを捕捉します。 
2. 周波数マップを構築する`cnt`ペア以上`(x_i, y_i)`、治療`(a, b)`そして`(b, a)`常にソートされたエンドポイントを保存することで、同じキーとして保存されます。 これにより、何人のコーダーが特定のペアを正確に選択したかを高速に調べることができます。 
3. 次数の値でソートされたすべてのノードの配列を作成します。 この順序付けにより、各ペアを明示的に検査することなく、十分な大きさの次数合計を持つペアがいくつあるかを数えることができます。 
4. ペアの数を数えます`(u, v)`満足する`deg[u] + deg[v] ≥ p`2 ポインタ スキャンを使用します。 この考え方は、一方のエンドポイントの次数が増加すると、もう一方のエンドポイントに必要な最小次数が単調に減少するというものです。 
5. 各入力ペアを反復処理します。`(u, v)`を使用して正確なスコアを計算します`deg[u] + deg[v] - cnt[u][v]`。 
6. このペアが以前に学位のみのステップで有効であるとカウントされていたが、その修正スコアが以下の場合`p`、答えからそれを引きます。 これにより、過剰カウントにより誤って含まれたペアのみが削除されます。 

### なぜ効果があるのか

 合意に対するすべてのペアの寄与は、2 つの部分に明確に分割されます。1 つはエンドポイントからの独立した寄与で、もう 1 つは同一ペアの衝突のみに依存する修正です。 次数ベースのカウントでは、すべてのエンドポイントベースの寄与がグローバルに正しく説明されますが、補正項は入力に明示的に存在するペアにのみ影響します。 他のペアはゼロ以外の補正を持つことができないため、次数ベースのセットから無効なペアを削除すると、有効な構成を欠落したり二重にカウントしたりすることなく、正確な最終カウントが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())

pairs = []
deg = [0] * (n + 1)
cnt = {}

for _ in range(n):
    x, y = map(int, input().split())
    pairs.append((x, y))
    deg[x] += 1
    deg[y] += 1
    if x > y:
        x, y = y, x
    cnt[(x, y)] = cnt.get((x, y), 0) + 1

nodes = list(range(1, n + 1))
nodes.sort(key=lambda x: deg[x])

ans = 0
j = n - 1

for i in range(n):
    while j >= 0 and deg[nodes[i]] + deg[nodes[j]] >= p:
        j -= 1
    ans += (n - 1 - j)

for x, y in pairs:
    u, v = (x, y) if x < y else (y, x)
    s = deg[x] + deg[y]
    c = cnt[(u, v)]
    if s >= p and s - c < p:
        ans -= 1

print(ans)
```コードはまず、すべてのコーダーの意見を次数とペアの頻度に圧縮します。 ソート ステップにより、次数のみに基づいて緩和条件を満たすペアの数をカウントする 2 ポインター スイープが有効になります。 2 番目のループでは、衝突が問題となる入力定義のペアのみをチェックしてオーバーカウントを修復します。 

微妙な実装の詳細は維持されています`j`スキャン中は単調に`i`。 これは、`i`移動の程度は小さくなるため、しきい値条件は厳しくなるだけで、ポインタをリセットする代わりに再利用できるようになります。

 ## 特殊なケース

 例外的なケースの 1 つは、すべてのコーダーが同じペアに名前を付ける場合に発生します。 その状況では、両方のノードの次数が非常に大きくなり、次数ベースのカウントが大幅に過大評価されます。 しかし、`cnt[u][v]`はオーバーカウントと正確に一致し、修正ステップでは無効な余分な包含が正確に削除されるため、真の寄与だけが残ります。 

もう一つのケースは次のような場合です。`p = 0`。 コーダーの意見に関係なく、すべてのペアは有効です。 次数ベースのカウントでも値は正しく計算されますが、たとえ補正が誤って処理されたとしても、しきい値は空虚に満たされるため、どのペアも除外する必要はありません。 

最後のエッジケースは、すべてのペアが異なる場合に現れます。 それから`cnt[u][v]`既存のペアの場合は常に 1、それ以外の場合は 0 です。これは、修正によってスコアがわずかに調整されるだけであることを意味します。 補正は既存のエッジにのみ影響し、O(n²) 個の非エッジ ペアの大部分には影響を与えないため、アルゴリズムは引き続き機能します。
