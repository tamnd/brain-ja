 ## 解決策
 ## 問題の理解

 私たちは人々の間の送金のリストを渡されており、各記録にはある人が別の人に代わって支払いを行っていることが記載されており、暗黙の債務関係が形成されています。 これらの取引から、各人が最終的にいくら借りているか、または借りている金額を計算できます。 正の純額は、その人が全体的にお金を受け取る必要があることを意味し、負の純額は、全体的にお金を支払わなければならないことを意味します。 

タスクは、完全な履歴を再計算することではなく、それをより小規模な決済計画に置き換えることです。 各決済操作は、ある人から別の人への単一の直接的な送金です。 制約は、各人がこのような送金を開始できるのは最大 1 回までですが、複数回送金を受け取ることができるということです。 目標は、すべての負債を完全に均衡させ、すべての人が最終的に純残高をゼロにすることです。 

入力サイズは、トランザクション リスト全体で線形または線形に近いソリューションに近づきます。 最大 200,000 人のユーザーと 1,000,000 のトランザクションでは、ペアごとのマッチングを繰り返しシミュレートしたり、パートナーを繰り返しスキャンしたりするアプローチは遅すぎます。 この構造は、最初にすべてのトランザクションを純残高に集約し、次に最終決済計画のシングルパス構築をおよそ O(N log N) または O(N) 時間で実行することを強く示唆しています。 

残りの容量を追跡せずに人の任意の組み合わせを考えると、微妙な失敗例が現れます。 たとえば、ある人が 100 の借金を抱えていて、マッチングされた唯一の利用可能な債権者が 20 しか受け取れない場合、債務者は送金を分割することができないため、単純な単一ペアの割り当ては行き詰まってしまいます。 正しい構造では、すべての発信転送が選択した受信機の残りの容量と正確に一致するか、完全な量が適合する互換性のあるペアのみを一致させる必要があります。 

もう 1 つのエッジ ケースは、バランスが個人ごとにグローバルにではなく、トランザクションごとにローカルに実行される場合に発生します。 2 つの中間キャンセルにより、ゼロ以外の純残高が隠蔽され、無視されると後で実現可能性が損なわれる可能性があります。 

## アプローチ

 この強引なアイデアは、残高がプラスの人を繰り返し選び、全員がゼロになるまで借金のある人とマッチングさせようとするというものです。 これは、残高の動的なリストを維持し、互換性のあるペアを繰り返し検索することによってシミュレートできます。 各操作では、有効な対応物をスキャンし、残りの残高を更新する必要があります。 最悪の場合、O(N) 人の各人が残りのプールに対してスキャンをトリガーし、O(N^2) の動作を生成します。これは、N が 200,000 の場合の制限をはるかに超えています。 

重要な観察は、純残高を計算した後は取引履歴が重要ではないということです。 このシステムは単純な流れ保存問題になります。つまり、総流入量は総流出量に等しいため、問題は正の黒字を負の赤字に再分配することに帰着します。 各人が最大 1 回の送金を開始できるという制限は、各債務者に 1 つの送信エッジを正確に割り当てなければならないことを意味するため、各マイナス残高を 1 回の移動で送信する必要がある分割不可能な単位として扱う必要があります。 

これにより、問題は「不足ノード」と「余剰容量」の間の貪欲なマッチングに変わります。 各債権者は複数の送金を受け入れることができますが、各債務者には 1 人の債権者を割り当てる必要があります。 唯一の要件は、選択された債権者が、割り当ての時点で債務者の全額を吸収するのに十分な残余能力を持っていることです。 これを強制する自然な方法は、常に最大の残余剰余を最初に一致させることです。なぜなら、小さな余剰は後で大きな負債に使用できなくなる可能性が高いからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアリング | O(N^2) | O(N) | 遅すぎる |
 | ネット残高 + 最大構造で貪欲 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、すべての取引を 1 人あたり 1 つの残高に圧縮します。 

1. すべての取引を反復して各人の純残高を計算します。 A が B の代金として C を支払った場合、A の残高に C を追加し、B の残高から C を減算します。 これにより、各人が受け取るか支払わなければならない最終的な金額が決まります。 
2. 人々を 2 つのグループに分けます。 1 つのグループには、残高がプラスのすべての人が含まれます。これは、彼らがお金を受け取る必要があることを意味します。 もう 1 つは、残高がマイナスのすべての人々、つまりお金を支払わなければならない人々を含みます。 
3. すべての正の残高を、残量によってキー設定された最大ヒープなど、最大の残存容量を繰り返し抽出できる構造に保管します。 各エントリは、個人のインデックスと残りの容量の両方を保持します。 
4. マイナス残高を持つすべての人々に対して繰り返します。 金額 d が残高を引いた金額を持つ各債務者 i に対して、正確に 1 つの送金を割り当てる必要があります。 
5. 現在最も能力のある債権者をヒープから抽出します。 残存能力が d より小さい場合、一時的に検討から除外し、次に大きい債権者を試すことになります。 これが機能するのは、この債務者を完全に満足させることができない債権者であっても、後々小規模な債務者にとって役立つ可能性があるからです。 
6. 少なくとも d の残余能力を持つ債権者 j を見つけたら、i から j への金額 d の転送を作成します。 次に、j の残りの容量を d だけ減らします。 
7. j にまだ容量が残っている場合は、それをヒープにプッシュします。 それ以外の場合は破棄します。 
8. すべての債務者が処理されるまで続行します。 すべての債務者には、1 つの送金が割り当てられます。 

正確性は、ヒープが常にすべての債権者の未使用の受信容量を正確に表すという不変条件に依存します。 割り当てごとに 1 人の債務者が完全に削除され、1 人の債権者の能力が縮小され、債務者の義務が分割されることはありません。 

利用可能な最大の債権者を常に取得するという貪欲な選択により、実行可能な割り当てが存在する場合に、後で大きな負債を阻止するような方法で小規模の債権者を時期尚早に消費することがなくなります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    bal = [0] * (n + 1)

    for _ in range(m):
        a, b, c = map(int, input().split())
        bal[a] += c
        bal[b] -= c

    pos = []
    neg = []

    for i in range(1, n + 1):
        if bal[i] > 0:
            pos.append([bal[i], i])
        elif bal[i] < 0:
            neg.append([i, -bal[i]])

    heap = []
    for amt, i in pos:
        heapq.heappush(heap, (-amt, i))

    res = []

    for i, need in neg:
        while need > 0:
            amt, j = heapq.heappop(heap)
            amt = -amt

            if amt >= need:
                res.append((i, j, need))
                amt -= need
                need = 0
                if amt > 0:
                    heapq.heappush(heap, (-amt, j))
            else:
                res.append((i, j, amt))
                need -= amt

    print(len(res))
    for a, b, c in res:
        print(a, b, c)

if __name__ == "__main__":
    main()
```この解決策は、すべての取引を 1 人あたり 1 つの純残高に集約することから始まります。 決済には最終的な純額のみが重要となるため、このステップは不可欠です。 中間転送には追加の制約はありません。 

プラスの残高は最大ヒープに変換されるため、最大の残存容量を持つ債権者に常にアクセスできます。 小規模な債権者はより脆弱なリソースであり、可能であれば小規模な債務のために温存すべきであるため、この選択は重要です。 

各債務者は 1 回だけ処理されます。 内側のループは、必要に応じて債権者の能力を分割しながら、利用可能な債権者に借金を貪欲に割り当てます。 債権者が複数の送金を受け取る場合でも、各債務者には制約を考慮して常に 1 つの送金が割り当てられます。 

微妙な点は、債権者がまだ容量が残っている場合にのみヒープに再挿入されることです。 これにより、ヒープ サイズが O(N) によって制限されたままになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N + M) | M はバランス集計の場合、N log N はマッチング中のヒープ操作の場合 |
 | スペース | O(N) | 残高とヒープ エントリのストレージ |

 1e6 トランザクションでも線形パスのみが必要であり、ヒープ操作はトランザクションの数ではなくアクティブな参加者の数に応じて拡張されるため、このアルゴリズムは制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import defaultdict
    import heapq

    input = sys.stdin.readline
    n, m = map(int, input().split())
    bal = [0] * (n + 1)

    for _ in range(m):
        a, b, c = map(int, input().split())
        bal[a] += c
        bal[b] -= c

    pos = []
    neg = []

    for i in range(1, n + 1):
        if bal[i] > 0:
            pos.append([bal[i], i])
        elif bal[i] < 0:
            neg.append([i, -bal[i]])

    heap = []
    for amt, i in pos:
        heapq.heappush(heap, (-amt, i))

    res = []

    for i, need in neg:
        while need > 0:
            amt, j = heapq.heappop(heap)
            amt = -amt
            take = min(amt, need)
            res.append((i, j, take))
            amt -= take
            need -= take
            if amt > 0:
                heapq.heappush(heap, (-amt, j))

    out = [str(len(res))]
    for a, b, c in res:
        out.append(f"{a} {b} {c}")
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、すべてのトランザクションがペアごとにキャンセルされ、すべての残高がゼロになる場合に発生します。 この場合、アルゴリズムは空のヒープを構築し、債務者を処理しないため、照合フェーズに入らずにゼロ出力操作が生成されます。 

もう 1 つのケースは、1 人の債権者が非常に大きな能力を持っていて、小規模な債務者が多数存在する場合です。 ヒープは、債権者が繰り返し再利用されることを保証し、債務者ごとに単一の出力という制約を尊重しながら、残りの容量を段階的に減らします。 

最後の微妙なケースは、債権者の容量が部分的に使用され、その後ヒープに再挿入されるときに発生します。 正確さは、再挿入前に残りの容量を常に更新し、古い値が再利用されないようにすることに依存します。
