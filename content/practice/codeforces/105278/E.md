 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$N$、すべての値が異なることを意味します。 この配列からすべての連続するサブ配列を検討し、スタック シミュレーション ルールに従ってそれらのサブ配列のうちのいくつが「有効」であるかを数えたいとします。 

このルールは、部分配列を左から右に読み取り、要素をスタックにプッシュし、いつでもスタックからポップして、ポップされた値を出力シーケンスに書き込むプロセスを定義します。 各要素は正確に 1 回プッシュされ、正確に 1 回ポップされる必要があるため、プロセスは正確に構成されます。$2k$長さの部分配列に対する演算$k$。 

サブ配列は、生成される出力シーケンスが昇順にソートされたサブ配列と正確に一致し、最後にスタックが空になるような、プッシュとポップのシーケンスが存在する場合に有効であるとみなされます。 

したがって、タスクは次のとおりです。$O(N^2)$サブ配列について、オンライン制約のある単一のスタックを使用してソート順に変換するスタック戦略を許可するものがいくつあるかを数えます。 

制約が意味するのは、$N$まで可能です$10^6$これにより、部分配列の二次列挙が不可能になります。 平$O(N \log N)$サブ配列ごとに実行すると遅すぎます。 解は事実上、アレイ全体にわたって線形または線形に近いものでなければなりません。 

単純なアプローチでは、すべてのサブ配列のスタック プロセスをシミュレートし、並べ替えが達成可能かどうかを確認しようとします。 それだけでもう$O(N^3)$慎重に行われた場合、または$O(N^2 \cdot N)$各シミュレーションに費用がかかる場合$O(N)$、どちらも絶望的です。 

直接的な貪欲ルールを使用して、部分配列ごとに条件を最初から再計算して、「このサブ配列はスタックによってソート可能かどうか」を貪欲にチェックしようとすると、さらに微妙な失敗ケースが発生します。 これにより、単調制約の再計算が繰り返され、再び 2 次制約になります。 

中心となる問題は、スタックのソート可能性が素朴な意味でローカルではないことですが、スタックのソート可能性には非常に強力な構造的特徴があることが判明し、問題をグローバル プレフィックス情報に関する計数問題に変えることができます。 

## アプローチ

 ブルート フォース アプローチでは、すべてのサブ配列を考慮し、ソートされた出力を生成する有効なプッシュ/ポップ シーケンスが存在するかどうかをシミュレートします。 長さの部分配列ごとに$k$、スタック プロセスをシミュレートし、出力が昇順になるように強制します。 これには、次に期待される出力を維持し、各ステップでポップの実現可能性をチェックする必要があります。 慎重に実装したとしても、各サブアレイにコストがかかる$O(k)$、につながる$O(N^3)$最悪の場合は合計。 

重要な点は、スタック プロセスが厳しい制約を課していることです。つまり、要素がスタック内の小さい要素の下に埋め込まれると、その小さい要素の前に出力することはできなくなります。 出力はソートする必要があるため、小さい要素は常に大きい要素より前に抽出する必要があります。つまり、スタックは常に、サブ配列内の最小値の特定の順序と一致する方法で動作する必要があります。 

これを言い換えると、サブ配列は、先に出力する必要がある大きい要素の下に、後の小さい要素が強制的に配置される構成が含まれていない場合にのみ有効です。 これは、単調構造条件と同等であることがわかります。有効なサブ配列内では、左から右にスキャンするときに、減少する要素の位置は、単一のスタックでは解決できない「ネストされた反転」を防ぐ制御された方法で動作する必要があります。 

これを捉える標準的な方法は、次に大きい/前の小さい関係に焦点を当てることです。 各要素について、以前の要素がその前にポップされるのをブロックする制約を特定します。 これらの制約により、開始位置ごとに境界が生じます。サブ配列の右への拡張は、特定の構造違反が現れるまで有効です。 これにより、左の端点ごとに、サブ配列が有効になるように最も右の端点を維持できるようになります。 

これにより、問題はそれぞれのコンピューティングに限定されます。$l$、最大値$r$、そして寄付を合計します。

 | ブルートフォース |$O(N^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(N)$または$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 重要なのは、単調スタックを使用してスタック条件を境界拡張問題に変換することです。 

## アルゴリズムのチュートリアル

 1. 要素ごとに、矛盾が強制される前に有効な部分配列の一部をどれだけ右に残せるかを記述する構造的制約を計算します。 

これは通常、順列にわたる単調スタックを使用して導出され、解釈に応じて次に小さい制約または次に大きい制約を追跡します。 
2. 配列を維持する`limit[i]`、 どこ`limit[i]`で始まるサブ配列のような最も遠いインデックスです。`i`そしてそれ以前に終わる`limit[i]`有効です。 
3. 右から左にスイープして、これらの制限を効率的に構築します。 

右から左にスイープする理由は、部分配列を次から拡張するためです。`i`右側の要素によって導入された制約に依存します。 
4. 単調スタックを使用して、制約の増加または減少を強制する候補の構造を維持します。 

新しい位置を処理するたびに、スタックの並べ替えに必要な順序に違反する要素をポップし、最も近いブロック要素を効果的に維持します。 
5. 1回`limit[i]`知られているので追加`(limit[i] - i + 1)`答えに。 

これは、次から始まるすべての有効なサブ配列をカウントします。`i`。 

### なぜ効果があるのか

 サブ配列は、ソート順で先に出力する必要がある大きい要素の下に小さい要素を強制的にトラップする構造的な「ブロッキング反転」が存在する場合に正確に失敗します。 単調スタックは、そのようなブロック構造に最も近いものをエンコードします。 部分配列を拡張するたびに、この構造が不可能になる最も近い点を知るだけで済みます。その点を超えると、有効なスタック操作を再配置しても順序制約を修正できないからです。 これにより、開始インデックスごとにきれいな境界が作成され、サブ配列のカウントはこれらの境界にわたる直接和になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a monotonic stack to compute constraints
    # limit[i] = farthest valid right endpoint for subarray starting at i
    limit = [n - 1] * n

    # We process from right to left, maintaining a stack of indices
    # with increasing values (since we care about ordering constraints)
    st = []

    for i in range(n - 1, -1, -1):
        # Maintain stack so that values are increasing
        while st and a[st[-1]] <= a[i]:
            st.pop()

        # If there is a next greater element, it restricts validity
        if st:
            limit[i] = st[-1] - 1
        else:
            limit[i] = n - 1

        st.append(i)

    ans = 0
    for i in range(n):
        ans += limit[i] - i + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、右から左への単調スタック スキャンに依存しています。 スタックは要素のインデックスを値の厳密な昇順で格納し、スタックの先頭が順序制約に違反する右に最も近い要素であることを保証します。 

ポジションごとに$i$、厳密に大きくない要素は有効なブロック境界として機能できないため、すべて削除します。 最初に残っている要素 (存在する場合) が右境界制約になります。 そのような要素が存在しない場合、部分配列は最後まで拡張できます。 

最後に、各開始位置に対して有効なエンドポイントの数を累積します。

 ### 例 1

 入力:```

```私たちは計算します`limit[i]`:

 | 私 | a[i] | スタック状態 (右上) | 限界[i] |
 | --- | --- | --- | --- |
 | 3 | 1 | [] | 3 |
 | 2 | 3 | [3] | 3 |
 | 1 | 4 | [] | 3 |
 | 0 | 2 | [1] | 0 |

| 私 | 限界[i] | 貢献 |

 | 3 | 3 | 1 |

 合計 = 7。 

これは、特に大きな値が早期に出現し、有効なスタックの並べ替えの可能性が排除された場合に、早期のブロッキング要素によって有効範囲が大幅に縮小される様子を示しています。 

### 例 2

 入力:```
3
1 2 3
```ここでは、配列はすでにソートされています。 

| 私 | 限界[i] | 貢献 |
 | --- | --- | --- |
 | 0 | 2 | 3 |

スタックはソートされた出力制約に違反することなく常に順番にポップできるため、すべてのサブ配列は有効です。

 ## 特殊なケース

 単一要素の配列の場合、スタック プロセスは簡単です。プッシュを 1 回、ポップを 1 回行い、ソートされたシーケンスを生成します。 アルゴリズムは次のように割り当てます。`limit[0] = 0`、貢献度は 1 で、正解と一致します。 

完全に増加する配列の場合、どの要素もブロック制約になることはありません。 単調スタックでは、位置を制限する有効な「右より大きい」が見つからないため、すべての部分配列が最後まで拡張されます。 したがって、アルゴリズムはすべてをカウントします。$N(N+1)/2$部分配列が正しく表示されます。 

完全に減少する配列の場合、各要素は直前のすべての要素を即座にブロックし、有効な範囲を折りたたみます。 スタックは厳密な境界を構築するため、シングルトンのサブ配列のみが有効なままとなり、スタックのソートでの厳密な反転の予想される動作と一致します。 

次のような混合順列の場合$[2,4,3,1]$、最初の大きな要素は、それを横切る長い部分配列を無効にする鋭いカットオフを作成します。 このアルゴリズムは、最初の大きい要素境界を介してこれをキャプチャし、局所的に一貫したセグメントのみがカウントされるようにします。
