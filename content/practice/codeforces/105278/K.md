 ## 問題の理解

 整数の行が与えられます。 1 回の移動で、2 つの隣接するポジションを選択し、それらの間で任意の量の値を転送します。整数を追加します。$k$片側に移動して同じ値を引きます$k$反対側から。 これにより、配列の合計が保存されますが、隣接する位置にわたる質量の任意の再配分が可能になります。 

タスクは、すべてのポジションが負の値にならないように、必要なそのような動きの最小数を決定することです。 それが不可能な場合には、その旨を報告しなければなりません。 

制約$N \le 10^5$実際の転送をシミュレートしたり、状態を検索しようとするソリューションは直ちに除外されます。これは、ステップごとの操作数が線形であっても遅すぎるためです。 操作の構造は、規模を最適化しているのではなく、「再分配アクション」をどこで実行する必要があるかを決定していることを示唆しています。 

この操作について考えると便利なのは、隣接する 2 つの間の境界を越えて任意の量を移動できるが、選択した境界使用量ごとにコスト 1 を支払うということです。 同じペア上の複数のアプリケーションは、それらの効果が合計によって 1 つの操作にマージされる可能性があるため、決して役に立ちません。$k$。 これは、真の決定は、転送の大きさではなく、どの隣接ペアをアクティブにするかであることを意味します。 

切り分ける価値のあるエッジの状況がいくつかあります。 

すべての値がすでに負でない場合、再分配は必要ないため、答えは明らかにゼロです。 

配列の合計が負の場合、一連の移動によって配列を修正することはできません。これは、すべての最終値が少なくとも 0 である必要がある一方で、合計は決して変化しないためであり、合計が負でないことが強制されます。 

より微妙な状況は、合計が負ではないが、配列の初期に深い負の谷がある場合です。 「局所的なマイナスをすぐに修正」しようとする素朴な貪欲さは失敗する可能性があります。これは、右側から借用するには複数の隣接するエッジを調整して使用する必要がある可能性があり、境界のアクティブ化ごとではなく値の単位ごとに演算を誤ってカウントすると、誤った答えが得られるためです。 

## アプローチ

 ブルートフォースの観点は、再配布を明示的にシミュレートすることです。 繰り返しマイナスのポジションを見つけて、隣接するポジションの 1 つからそこに価値を押し込み、隣のポジションを順番に調整することを想像することもできます。 このような各調整はアレイ全体に伝播することができ、各伝播ステップは 1 つの操作に対応します。 原理的には正しいですが、このアプローチは遅すぎます。これは、単一の不適切な構成により、長いチェーンにわたって大量の値を移動する必要があり、各移動の決定がカスケードして二次関数またはさらに悪い動作につながる可能性があるためです。 

重要な観察は、どれだけの値が移動されるかは気にせず、境界が使用されるかどうかだけを気にするということです。 各操作は単一エッジ全体で無制限の容量を持つため、同じ隣接ペアにわたるすべての転送は 1 つの操作にまとめられます。 問題は、すべてのマイナスの赤字を解消するために、いくつの明確な「必要な境界」を使用する必要があるかを数えることになります。 

これにより、問題は、左から右にスイープするときに、負のプレフィックスの不均衡をどこまで修復する必要があるかを追跡することに変わります。 現在のプレフィックスの合計がゼロを下回ると、配列の左側の部分に不足分が蓄積されており、少なくとも 1 つの境界を越えて右側から値を送信することで補う必要があります。 以前の補償でカバーできる範囲を超えたこのような新たな赤字に遭遇するたびに、私たちは新たな活動を開始することを余儀なくされ、これらの活動はまさに私たちがカウントするものです。

 ## アルゴリズムのチュートリアル

 現在の位置までに現在利用可能な合計値を表す実行中のプレフィックス合計を維持しながら、配列を左から右に処理します。 

1. 変数を初期化する`prefix`ゼロとカウンターへ`ops`ゼロに。 
2. 配列を最初の要素から最後の要素まで繰り返し、各値を`prefix`。 
3. いつでも`prefix`マイナスになると、左側のセグメントの赤字が黒字よりも多くなることを意味します。 この不足は右側から値を取得することによって補う必要があり、そのためには必然的に残りのサフィックスに交差する少なくとも 1 つの境界操作をアクティブにする必要があります。 インクリメントします`ops`1つずつ概念的にリセットされます`prefix`この境界レベルでの不足を中和するために 1 つの操作が使用されると想定しているため、ゼロに戻ります。 
4. アレイのスキャンを続行し、新しいセグメントごとにこのプロセスを繰り返します。 累計が再びゼロを下回るたびに、操作に対する新しい独立した要件が発生することを表します。 
5. 配列全体を処理した後、すべての要素の合計が負の場合、再配分ではグローバル不足を修正できないため、-1 が出力されます。 それ以外の場合は出力`ops`。 

主な理由は、新しい負のプレフィックス領域に到達するたびに、以前の操作はもう役に立たないということです。これは、値をローカルに移動するだけであり、追加の境界使用を導入せずに複数の分離された不足イベントを同時に解決できないためです。 

### なぜ効果があるのか

 プレフィックスの合計は、処理されたプレフィックスの正味利用可能な質量を表します。 負のプレフィックス合計は、一部のサフィックスが少なくとも 1 つの隣接する境界を介してこのプレフィックスに値を提供する必要があることを示します。 その赤字を解消するために概念的に業務を割り当てたら、実質的には将来のセグメントから「借りる」ことになります。 

この時点以降のゼロ未満のさらなる低下は、回線全体のフローの複雑さを増加させずに同じ境界アクティブ化を再利用することによっては満たせない、新しい独立した借入要件に対応します。 したがって、プレフィックス合計がすでに補償されているものを超えて新しい不足状態に達するたびに、新しい操作が強制され、これらの強制イベントよりも少ない操作を使用するソリューションはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if sum(a) < 0:
        print(-1)
        return
    
    prefix = 0
    ops = 0
    
    for x in a:
        prefix += x
        if prefix < 0:
            ops += 1
            prefix = 0
    
    print(ops)

if __name__ == "__main__":
    solve()
```実装は上記のスイープに従います。 最初の合計チェックでは不可能条件が処理されます。操作では合計が保持されるため、合計がマイナスになるとターゲットに到達できなくなります。 

の`prefix`変数は、スキャン中に利用可能な余剰量を追跡します。 ゼロを下回るたびに、サフィックスから不足分を相殺するのに十分な値を引き出す強制操作として解釈し、その操作が現在の違反を完全に補うとみなされるため、リセットします。 

リセット ステップは微妙な部分です。正確な転送をシミュレートしているわけではありませんが、現在の不足境界条件を除去するには 1 回の操作で十分であることを表しています。

 ## 特殊なケース

 単一要素配列の場合、近傍がなければ再分配は不可能であるため、アルゴリズムは、それが負でない場合は直ちに 0 を出力し、それ以外の場合は -1 を出力します。 

総和が負の配列の場合、一連の操作によって総質量が増加する可能性がないため、初期チェックではスキャンの前にそのケースが正しく拒否されます。 

小さな負の値が正の値と交互に繰り返される配列の場合、接頭辞のスイープは複数の不足リセットを正しくトリガーし、接尾辞から外部値を取り込む必要性が繰り返し必要であることを反映します。
