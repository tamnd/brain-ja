 ## 解決策
 ## 問題の理解

 Codeforces ユーザーは評価履歴を通じて追跡され、評価が生徒、スペシャリスト、エキスパートなどの固定しきい値を超えると「ステータス層」が変化します。 各層は連続する評価間隔に対応し、初めてより高い間隔に移動するとエンブレム賞がトリガーされます。 

ユーザーごとに、ハンドル名、最新のコンテスト後の現在の評価、このコンテスト前の過去の最大評価、および最新のコンテストでの評価の変更が与えられます。 これらの値から、最新のアップデートにより、これまでに到達したよりも高いレベルに到達したかどうかを判断する必要があります。 「はい」の場合、その新しい層の名前を出力します。 それ以外の場合は、動機付けのメッセージを出力します。 

入力には格付けデルタが含まれていますが、決定は「以前の最もよく知られた格付け」と「現在の格付け」を固定階層の境界と比較することによってのみ決まります。 唯一意味のある履歴状態は、現在の更新前の最大評価です。これは、ユーザーがすでにロックを解除しているランクをエンコードしているためです。 

制約の規模は大きいですが、構造の複雑さは些細なものです。 すべてはテスト ケースごとに定数時間であるため、解は O(1) でなければならず、評価履歴に対するシミュレーションや反復を避ける必要があります。 

主な微妙な点は、「初めて新しいランクに到達する」が何を意味するのかを理解することです。 単純な解釈では、現在の評価をしきい値とのみ比較するか、ユーザーが以前にすでに同じ層にいた可能性があることを無視する可能性があります。 

いくつかの危険な状況を考えてみると、これがより明確になります。 

ユーザーが以前に 2100 (マスター) に到達していたが、2050 まで低下し、その後 2100 に戻った場合、マスター エンブレムを再度受け取ることはできません。 最大評価にはすでにその層が含まれているため、新しい層に到達することはありません。 

ユーザーが以前は 1890 (エキスパート) でピークに達し、現在は 1900 に達している場合、ユーザーは初めて候補マスターに入っているため、出力はその移行を反映する必要があります。 

ユーザーの評価が上昇しても同じ段階間隔内に留まっている場合、評価が変わっても何も授与されません。 

## アプローチ

 直接シミュレーションでは、評価履歴全体が再構築されます。つまり、デルタを適用し、段階的に評価を更新し、すべての中間最大値を追跡します。 層の変更は、たどったパスではなく、評価がしきい値境界を越えるかどうかのみに依存するため、これは不要です。 最悪の場合、多くの更新にわたる遷移をシミュレートする単純なアプローチでは、コンテストの数が線形になる可能性があります。これはここには示されていませんが、そのような方法の過剰な性質を示しています。 

重要な観察は、層が整数行の固定パーティションを形成していることです。 各評価は、決定的に 1 つの階層にマッピングされます。 したがって、このパーティションでは、前の最大定格と現在の定格の 2 点を比較するだけで済みます。 両方が同じ Tier にマッピングされている場合、新しいエンブレムは獲得されません。 それらが異なる層にマップされ、現在の層が順序付きリストの上位にある場合、ユーザーは新しい層のロックを初めて解除したことになります。 

これにより、問題は少数の間隔ルックアップと 1 回の比較の計算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース履歴シミュレーション | ユーザー履歴あたり O(T) | お(1) | 不要 |
 | 最適な階層の比較 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての評価層を、最低から最高までの順序付き間隔としてエンコードします。 各区間は 1 つのエンブレム名に対応します。

1. 下限と名前を含む階層の順序付きリストを作成します。 ランクを直接評価値によって比較するのではなく、このリスト内の位置によって比較するため、順序は重要です。 
2. これらの間隔をスキャンし、下限が満たされ、上限を超えていない最初の間隔のインデックスまたは名前を返すことによって、任意の評価をその層にマップする関数を定義します。 マッピングは決定論的であり、履歴から独立しています。 
3. 前回の最高評価を計算します。これは M として直接与えられます。これは、現在のコンテストの前にユーザーがこれまでに得た最高評価を表します。 
4. 最新のコンテスト結果を適用した後の評価を表す現在の評価 C を計算します。 
5. M と C の両方を対応する階層インデックスにマッピングします。 prev_rank を M の階層インデックス、new_rank を C の階層インデックスとします。 
6. new_rank が prev_rank より大きい場合、新しい層の名前を出力します。 それ以外の場合は、動機付けのメッセージを出力します。 

階層は互いに素であり、評価範囲ごとに完全に順序付けされているため、比較は厳密に順序的です。 

### なぜ効果があるのか

 最大評価 M は、層に対するユーザーの過去のエクスポージャーを完全に把握します。 以前に達成された層は、すでに M に反映されています。したがって、「初回」層は、C を含むが M を含まない層に対応する必要があります。層は連続していて順序付けされているため、これは、C の層インデックスが M の層インデックスよりも厳密に大きいかどうかを確認することと同じです。中間状態またはデルタ D がこの結論を変えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

tiers = [
    ("newbie", -10**18, 1199),
    ("pupil", 1200, 1399),
    ("specialist", 1400, 1599),
    ("expert", 1600, 1899),
    ("candidate master", 1900, 2099),
    ("master", 2100, 2399),
    ("grandmaster", 2400, 10**18),
]

def get_rank(x):
    for i, (name, lo, hi) in enumerate(tiers):
        if lo <= x <= hi:
            return i
    return 0

def solve():
    data = input().split()
    if not data:
        return
    s = data[0]
    C = int(data[1])
    M = int(data[2])
    D = int(data[3])

    prev_rank = get_rank(M)
    new_rank = get_rank(C)

    if new_rank > prev_rank:
        print(tiers[new_rank][0])
    else:
        print("Think about it, you can do it!")

if __name__ == "__main__":
    solve()
```この実装では、評価間隔を明示的にエンコードし、7 層の固定配列に対して定数時間の検索を実行します。 機能`get_rank`間隔の数が一定で小さいため、意図的に単純化されています。 

主要な実装の詳細は、C ～ D で​​はなく M を使用することです。デルタが提供されていますが、この問題ではすでに過去の最大値が直接与えられており、これは過去の成果を完全に表しています。 これにより、タイムラインの再構築が回避されます。 

境界比較は両端を含み、ランク定義と正確に一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 定数配列に対する固定間隔のルックアップは 2 つだけ |
 | スペース | お(1) | 7 層の固定リストのみが保存されます。 

制約により任意の評価値が許可されますが、層の構造により一定時間の分類が保証され、ソリューションを制限内に容易に収めることができます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    tiers = [
        ("newbie", -10**18, 1199),
        ("pupil", 1200, 1399),
        ("specialist", 1400, 1599),
        ("expert", 1600, 1899),
        ("candidate master", 1900, 2099),
        ("master", 2100, 2399),
        ("grandmaster", 2400, 10**18),
    ]

    def get_rank(x):
        for i, (name, lo, hi) in enumerate(tiers):
            if lo <= x <= hi:
                return i
        return 0

    data = sys.stdin.readline().split()
    s = data[0]
    C = int(data[1])
    M = int(data[2])
    D = int(data[3])

    if get_rank(C) > get_rank(M):
        return tiers[get_rank(C)][0]
    return "Think about it, you can do it!"

assert run("aprohACk 2098 2098 10\n") == "Think about it, you can do it!"
assert run("ahoraSoyPeor 2237 2288 -69\n") == "Think about it, you can do it!"
assert run("demianOneTwoThree 725 725 721\n") == "specialist"

# custom cases
assert run("x 1199 1199 1\n") == "pupil"  # newbie -> pupil boundary crossing
assert run("x 1399 1399 1\n") == "specialist"  # pupil -> specialist
assert run("x 2500 2000 500\n") == "grandmaster"  # jumps to top tier
assert run("x 1500 1600 0\n") == "Think about it, you can do it!"  # no new tier
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1199 → 1200 | 生徒 | 低層での境界越え |
 | 1399 → 1400 | スペシャリスト | 中間層の移行 |
 | 2500 | グランドマスター | 最上位層の処理 |
 | 1500 層は変更なし | メッセージ | 変更なしの場合 |

 ## 特殊なケース

 よくある間違いは、最大評価がすでに歴史的な成果をコード化していることを無視することです。 たとえば、ユーザーの現在の評価が以前の最大評価よりも高い場合、それは新しいティアの可能性を意味しますが、両方がまだ同じ間隔内にある場合は、エンブレムは授与されません。 このアルゴリズムは、生の評価ではなく階層インデックスを明示的に比較することでこれを処理します。 

もう 1 つの微妙なケースは、格付けの下方変更です。 ユーザーが高い階層から低い階層に落ちた場合でも、現在の順位ではなく過去の最大評価に基づいて決定されるため、以前に獲得したエンブレムは失われません。 M を使用した比較により、層のロックが解除されると、その層は永久に「訪問」されたままになることが保証されます。 

最後に、ちょうど 1200 や 2100 などの境界が等しい場合は、間隔チェックが包括的であるため正しく処理され、層の境界で off-by-one エラーは発生しません。
