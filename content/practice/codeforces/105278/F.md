 ## 解決策
 ## 問題の理解

 グリッドは、2 人のエージェント (パックマンとゴースト) が離散時間ステップ上を移動する迷路を表しています。 パックマンは固定セルから開始し、上、下、左、右のコマンドで構成される所定の一連の動きに従います。 パックマンがグリッドの外側に水平に移動しようとすると、同じ行の反対側に回り込みますが、これは移動先のセルが壁でない場合に限られます。 垂直方向の移動は、迷路のルールで明示的に許可されていない限り、同じ方法でラップすることはありません。 水平境界線のみが周期的に動作します。 パックマンが壁の中に移動しようとすると、その場に留まります。 

ゴーストは独自の位置から開始し、ステップごとにグリッド内の最短パスを使用してパックマンに向かって移動します。 複数の最短経路の移動が存在する場合、ゴーストはそれらのいずれかを選択できますが、その目標は常に、そのタイム ステップでのパックマンまでの距離を最小限に抑えることです。 パックマンとは異なり、ゴーストは国境を越えてテレポートできないため、その動きはグリッドによって完全に制限されます。 

問題は、両方が同時に動き、ゴーストが常に最適に追跡することを前提として、ゴーストが同じ位置、同じタイムステップでパックマンに到達できるかどうかです。 

制約は大きく、グリッドは最大 5000 x 5000、つまり最大 2,500 万個のセルにすることができます。 ステップごとの最短パスを完全に再計算すると、時間がかかりすぎます。 パックマンのパスの長さはグリッドの周囲の約 3 倍であるため、およそ O(R + C) で制限されており、これによりシミュレーションの範囲は管理可能に保たれますが、各ステップでは依然として効率的な距離推論が必要です。 

単純なアプローチでは、各ステップでパックマンの位置から BFS を再計算して、ゴーストの動きを決定します。 これには、ステップごとに O(RC) のコストがかかり、最大 O(R + C) ステップを掛けますが、これはあまりにも大きすぎます。 

微妙なエッジケースはラッピングから生まれます。 パックマンは同じ行の左端から右端まで「ジャンプ」しているように見えますが、ゴーストはこのラップに直接従うことはできません。 これにより、パックマンとゴーストがラップされたジオメトリ内では隣接しているが、実際のグリッド距離では遠く離れているという状況が作成されます。 この区別を無視したソリューションは失敗します。 

もう 1 つの注意が必要なケースは、パックマンがラップした後に境界の壁に進入しようとする場合です。 たとえば、右端の列が壁の場合、そこを囲む移動はパックマンを左側に移動させるのではなく、その場に残す必要があります。 

## アプローチ

 重要な問題は、ゴーストが最短経路距離によって定義され、パックマンの移動に応じて変化することです。 各 BFS は O(RC) であり、O(R + C) 個が必要になる可能性があるため、移動するたびに最短パスを最初から再計算することは明らかに実行不可能です。 

重要な観察は、ゴーストの動作は静的なグリッド内の距離のみに依存し、パックマンの動的な決定には依存しないということです。 特定のタイム ステップでのすべてのセルからパックマンの位置までの最短距離がわかっている場合、ゴーストの次の動きは、その距離を短縮する隣接セルを選択するだけです。 

完全な BFS を繰り返し再計算する代わりに、単一の BFS を使用してパックマンの現在位置からの距離を維持できます。 ただし、ステップごとに BFS を再計算するのは依然としてコストが高すぎます。 

改良点は、パックマンを段階的にシミュレートしながら、時間の経過とともに最短パスを効果的に追跡するマルチソース伝播のアイデアを使用して、ゴースト距離を段階的に維持することです。 パックマンは短いパスに沿って決定論的に移動し、ゴーストの動きは局所的な距離の勾配にのみ依存するため、グリッド全体を毎回再計算することなく、BFS レイヤ化ロジックを使用してゴーストの動きを直接シミュレートできます。

より現実的な解釈は、完全な距離は必要なく、ゴーストが各タイム ステップの時点またはその前にパックマンに到達できるかどうかだけが必要であるということです。 これは、時間拡張された状態にわたる到達可能性になります。各状態は (ゴースト位置、時間) であり、遷移は有効な動きですが、パックマンの位置は毎回決定論的に知られています。 

これにより、問題は、ノードがパックマンのパス インデックスに沿った時間パリティで注釈が付けられたグリッド位置である状態グラフ上の BFS に帰着します。 ただし、時間は最大 O(R + C) になる可能性があるため、代わりに順方向にシミュレートし、パックマンの位置が移動している間、単位時間あたり 1 ステップを拡張する BFS ウェーブとしてゴースト フロンティアを維持します。 

重要な単純化は、ゴーストが常に静的グリッドで BFS 拡張を実行しているため、開始時から単一の BFS を維持できますが、壁を通って拡張するのを阻止し、パックマンがターゲットを移動しているという事実を尊重する必要があることです。 各タイム ステップで、パックマンの現在のセルが時間に等しい深さでゴーストの到達可能な BFS 層内にすでにあるかどうかを比較します。 

これは二重 BFS 解釈につながります。ゴーストからの最短距離を 1 回計算し、次にパックマンの経路をシミュレートし、パックマンがそこに到着するタイム ステップ以下の距離のセルにパックマンが進入するかどうかを確認します。その一方で、パックマンの動きがラッピングによりグリッド距離において均一ではないという事実を考慮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステップごとに BFS を再計算する | O((R+C)・RC) | O(RC) | 遅すぎる |
 | 単一 BFS + 時間シミュレーション | O(RC + R + C) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 ゴーストの動きを、その初期位置から始まる最短経路の伝播として扱います。 これにより、迷路内のすべてのセルに固定距離値が与えられ、BFS を使用して 1 回計算されます。 これらの距離は、ターゲットが静止している場合にゴーストが任意のセルに到達するために必要な最小ステップ数を表します。 

次に、指定されたコマンド文字列に沿ってパックマンの動きが段階的にシミュレートされ、説明どおりに壁のブロックと水平方向のラッピングが適用されます。 

1. パックマンを無視して、グリッド上のゴーストの開始位置から BFS を計算します。 各セルには、ゴーストがそこに到達するために必要な最小歩数が保存されます。 これが機能するのは、ゴーストの移動がターゲットの場所を除いてパックマンの決定から独立しており、後で時間のしきい値に対して到達可能性を評価するためです。 
2. パックマンを最初のセルからシミュレートします。 移動文字列内の文字ごとに、目的の次のセルを計算します。 
3. 移動が水平方向で範囲外になった場合は、同じ行の反対側にラップします。 これは、目的地が壁でない場合にのみ適用されます。 それ以外の場合は、パックマンはその場に残ります。 
4. 対象のセルが壁の場合、パックマンは移動しません。 それ以外の場合、Pacman はそのセルを更新します。 
5. パックマンが移動した後の各時間ステップ t で、パックマンの現在位置と事前に計算されたゴースト距離を比較します。 そのセルまでのゴーストの距離が t 以下の場合、ゴーストは同じタイム ステップまたはそれ以前にそのセルを占有する可能性があり、キャプチャが可能であることを意味します。 
6. いずれかの時点でこの条件が満たされた場合は、すぐに「Yes」を出力します。 シミュレーションが一致せずに終了した場合は、「いいえ」を出力します。 

### なぜ効果があるのか

 ゴーストからの BFS は、変化しないグラフ内の正確な最短パス距離を計算します。 パックマンが移動しても、ゴーストが d ステップで固定セルに到達する能力は、パックマンの軌道とは無関係です。 2 つのプロセス間の唯一の結合は、Pacman が各セルを占有する時間インデックスです。 ゴーストが最大でも同じ歩数で到達できるセルにパックマンが足を踏み入れた場合、ゴーストは最短経路を同期させてその時刻またはその前にそこに到着し、確実に捕らえることができます。 BFS 距離は、考えられるすべてのゴースト パスにわたって最小であるため、距離マップにまだキャプチャされていない高速ルートは存在しません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    grid = [list(input().strip()) for _ in range(R)]
    S = input().strip()

    # locate Pacman and Ghost
    pr = pc = gr = gc = -1
    for i in range(R):
        for j in range(C):
            if grid[i][j] == 'P':
                pr, pc = i, j
            elif grid[i][j] == 'G':
                gr, gc = i, j

    INF = 10**18
    dist = [[INF] * C for _ in range(R)]
    q = deque()
    dist[gr][gc] = 0
    q.append((gr, gc))

    dirs = [(-1,0),(1,0),(0,-1),(0,1)]

    # BFS from ghost
    while q:
        r, c = q.popleft()
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] != '#' and dist[nr][nc] == INF:
                dist[nr][nc] = dist[r][c] + 1
                q.append((nr, nc))

    # simulate Pacman
    t = 0

    def move(r, c, ch):
        nr, nc = r, c
        if ch == 'L':
            nc -= 1
            if nc < 0:
                nc = C - 1
            if grid[nr][nc] == '#':
                nc = c
        elif ch == 'R':
            nc += 1
            if nc >= C:
                nc = 0
            if grid[nr][nc] == '#':
                nc = c
        elif ch == 'U':
            nr -= 1
            if nr >= 0 and grid[nr][nc] == '#':
                nr = r
            if nr < 0:
                nr = r
        elif ch == 'D':
            nr += 1
            if nr < R and grid[nr][nc] == '#':
                nr = r
            if nr >= R:
                nr = r
        return nr, nc

    r, c = pr, pc

    for ch in S:
        r, c = move(r, c, ch)
        t += 1
        if dist[r][c] <= t:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```BFS ブロックは、ゴーストの完全な最短経路ランドスケープを構築します。これは、後のすべての推論がパックマンの到着時刻とこれらの距離の比較に依存するため、不可欠です。 

移動機能は水平方向のみのラップアラウンドをエンコードし、ラップアラウンド後に壁が動きを妨げた場合でも位置を慎重に保持します。 微妙な点は、垂直方向の移動は折り返されないため、境界外チェックは明示的に元の位置に戻す必要があることです。 

タイムカウンターはパックマンの移動ごとに 1 回増加し、各パックマンの位置をゴーストがそれに一致するために必要なステップ数に合わせます。

 ## 特殊なケース

 重要なエッジケースは、マンハッタンという意味では技術的にはゴーストから遠いが、最短パスという意味では非常に近いセルにパックマンがラップする場合です。 BFS 距離の計算ではすでに迷路の形状が考慮されているため、このようなケースは自然に処理されます。 シミュレーションでは距離のしきい値のみがチェックされるため、ラッピングには正しい動作ロジック以外の特別な処理は必要ありません。 

もう 1 つのケースは、パックマンがラップした直後に壁に移動しようとする場合です。 その状況では、移動機能は明示的に元の位置に戻り、パックマンがブロックされたセルに不法に侵入しないようにします。 

最後のケースは、パックマンとゴーストが同じセルで起動する場合です。 ゴーストの開始セルでの BFS 距離は 0 であるため、解釈に応じて時間 0 または 1 で条件 dist <= t が直ちに満たされ、シミュレーション ステップなしで正しくキャプチャが生成されます。
