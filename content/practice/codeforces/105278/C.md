 ## 解決策
 ## 問題の理解

 一連の建物の高さはすべて個別に与えられています。 インデックスからの任意の間隔$i$に$j$、建物に沿って順番に歩くことを想像します。 各ステップでは、連続する 2 つの高さを比較します。高い建物に移動した場合は上昇、そうでない場合は下降となります。 これにより、セグメントに沿って浮き沈みのパターンが生成されます。 

ここで、同じセグメントを逆方向に横断した場合を考えてみましょう。 これにより、すべての比較の方向が反転し、上りは下りになり、下りは上りになります。 

セグメント$[i, j]$順方向の上昇回数が逆方向の上昇回数と等しい場合は、公正であると呼ばれます。 逆にすると上下が入れ替わるので、この条件は順方向の上昇回数が順方向の下降回数と等しいと言うのと同じです。 

したがって、タスクは、連続する要素間で増加と減少の数が等しいサブ配列がいくつあるかを数えることに帰着します。 

入力サイズは次のように大きくできます。$10^6$したがって、二次方程式のアプローチ全体としては、$(i, j)$ペアはすぐには不可能です。 平$O(n \log n)$許容されますが、セグメントごとに情報を再計算しようとするとタイムアウトになります。$5 \times 10^{11}$最悪の場合はサブアレイ。 

微妙な点は、移動がないため、単一要素セグメントは常に公平であるということです。 もう 1 つの特殊なケースは、モノトーン配列です。 シーケンスが厳密に増加または減少している場合、長いセグメントはすべてアンバランスであるため、単一要素セグメントのみが有効です。 

主な課題は、セグメントごとの単純なカウントでは各サブアレイのスキャンが必要となり、時間がかかりすぎることです。 

## アプローチ

 総当たり攻撃を試みる場合は、すべてのペアをチェックします$(i, j)$サブ配列内でカウントが増減します。 プレフィックス前処理を使用しても、セグメントごとに両方のカウントを維持するには依然としてコストがかかります$O(1)$クエリごとに異なりますが、$O(n^2)$クエリなので、これでも二次関数になります。 

重要な観察は、隣接する各比較が次のいずれかに寄与するということです。$+1$(増加) または$-1$（減少）。 セグメント全体にわたるこれらの値の合計がゼロである場合、そのセグメントは正確に公平です。 そこで、この問題を、次の配列内の合計がゼロになる部分配列を数える問題に変換します。$+1/-1$。 

させて$a_k = 1$もし$h_k < h_{k+1}$、 さもないと$a_k = -1$。 次にセグメント$[i, j]$であれば公平です$$a_i + a_{i+1} + \dots + a_{j-1} = 0.$$これは古典的なプレフィックス合計の問題です。プレフィックス合計を定義します。$p[0]=0$、$p[k]=a_1 + \dots + a_k$。 次に、セグメントの合計がゼロになるのは、次の場合です。$p[j-1] = p[i-1]$。 したがって、プレフィックスの合計の等しいペアをカウントする必要があります。 

これにより、問題は 1 回のパスでのプレフィックス合計値の頻度のカウントに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | プレフィックス合計頻度 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、高さの配列を、各位置が次の建物が高いか低いかをエンコードする差分配列に変換します。 

次に、この変換された配列に対して実行中のプレフィックスの合計を維持します。 同じプレフィックス合計値が再び表示されるたびに、2 つの出現の間のセグメントの上昇と下降の数が同じであることを意味します。 

### ステップ

 1. 高さの配列を読み取り、連続する要素間の比較のみが必要であるという事実を直ちに処理します。 

これにより、問題の次元が建物からトランジションまで縮小されます。 
2. 隣接するペアごとに値を計算します。$+1$それが増加である場合と、$-1$減少であれば。 

このエンコーディングが選択されるのは、上昇と下降のバランスがゼロサム条件になるためです。 
3. 要素が処理される前に、ゼロから始まる実行中のプレフィックス合計を維持します。 
4. 辞書 (ハッシュ マップ) を使用して、各プレフィックス合計値がこれまでに出現した回数を保存します。 
5. 空のプレフィックスを表すプレフィックス サム ゼロが 1 回発生するマップを初期化します。 
6. 各値を処理するときに、プレフィックスの合計を更新します。 プレフィックス合計値が再び現れるたびに、その前の頻度を答えに加算します。 

これが機能するのは、プレフィックスの合計が等しいと、それらの位置間のゼロサム セグメントが定義されるためです。 
7. すべての要素を処理した後、累積カウントを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、増加と減少の数が等しいすべてのサブ配列が、プレフィックスの合計が等しいインデックスのペアに一意に対応するという不変式に依存しています。 等しいプレフィックス合計の各ペアは、2 番目の出現が処理されるときに 1 回だけカウントされます。 これにより、有効なセグメントとカウントされたペア間の全単射が保証されるため、セグメントが欠落したり、二重にカウントされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    n = data[0]
    h = data[1:]
    
    if n <= 1:
        print(n)
        return
    
    from collections import defaultdict
    
    freq = defaultdict(int)
    freq[0] = 1
    
    pref = 0
    ans = 0
    
    for i in range(n - 1):
        if h[i + 1] > h[i]:
            pref += 1
        else:
            pref -= 1
        
        ans += freq[pref]
        freq[pref] += 1
    
    print(ans + n)

if __name__ == "__main__":
    solve()
```実装は入力全体を 1 回で読み取り、それを次のように分割します。$n$そして高さの配列。 これにより、大きな入力に対する繰り返しの I/O オーバーヘッドが回避されます。 

変換ステップは隣接する要素に対するループ内で暗黙的に行われ、比較に応じてプレフィックスの合計を +1 または -1 で更新します。 辞書`freq`各プレフィックスの合計が出現する頻度を保存し、すべての一致がすぐに答えに寄与します。 

決勝戦`ans + n`プレフィックス合計ロジックは、少なくとも 1 つのエッジ以上の長さのセグメントのみをカウントするため、つまり、少なくとも 1 つの比較を伴うため、すべての単一要素サブ配列が考慮されます。 

微妙な実装の詳細が初期化されています`freq[0] = 1`。 これがないと、インデックス 0 で始まるセグメントは、プレフィックスの合計が最初の空のプレフィックスと一致するため、正しくカウントされません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 各高さは 1 回処理され、ハッシュ マップ操作は一定時間で償却されます。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    data = list(map(int, sys.stdin.read().split()))

    from collections import defaultdict

    ans = 0

    for i in range(n - 1):

            pref += 1
        else:

        ans += freq[pref]

 ## 特殊なケース

 単一の建物入力は、比較が存在しない基本条件を示します。 アルゴリズムは正しく 1 を返します。`ans`ゼロのままで追加します`n`。 

厳密に増加するシーケンスでは、常に増加するプレフィックス合計が生成されるため、値の繰り返しは発生しません。 ハッシュ マップは余分な寄与を蓄積することはなく、結果は単一要素セグメントのみに分解されます。 

厳密に減少するシーケンスは対称的に動作し、ステップごとにプレフィックスの合計が減少します。 ここでも、プレフィックスの衝突は発生せず、些細なセグメントのみがカウントされることが確認されます。 

増加と減少を繰り返すなどの交互のシーケンスにより、複数のプレフィックス合計の繰り返しが作成され、アルゴリズムは繰り返しのハッシュ ヒットを通じてバランスのとれたすべてのサブ配列を正しくキャプチャし、プレフィックスと合計の等価性が正しいことを確認します。
