 ## 解決策
 ## 問題の理解

 すべて同じ長さのいくつかの数字列が与えられます。 数字の位置の順列を 1 つ選択し、それをすべての文字列に適用できます。 その共有順列に従って数字を並べ替えた後、各文字列は新しい整数になり、場合によっては先頭にゼロが付きます。 

私たちの目標は、結果の最大値と結果の最小値の差をできるだけ小さくすることです。 

たとえば、次のものがあるとします。```
123
908
```順列を選択すると`(2, 1, 3)`、 それから：```
123 -> 213
908 -> 098
```結果の値は次のとおりです。`213`そして`98`、したがって、違いは次のとおりです`115`。 

重要な制限は、すべての数値で同じ位置の並べ替えを使用する必要があることです。 各番号を個別に並べ替えることはできません。 

制約は非常に小さいです。 両方`n`そして`k`せいぜい`8`。 興味深い境界は、`k ≤ 8`の順列の数があるため、`k`ポジションは`k!`。 

最悪の場合:```
8! = 40320
```順列ごとに、再構築します`n`それぞれの数字`k`数字。 総作業量はおおよそ次のとおりです。```
40320 × 8 × 8 ≈ 2.5 million operations
```これは、Python の 1 秒制限内に快適に収まります。 

の小さな値`k`問題の性質が完全に変わります。 すべての順列に対するブルートフォースは不可能です。`k`適度に大きかったが、`k ≤ 8`、徹底的な検索が目的のソリューションになります。 

一般に、誤った実装を破壊するいくつかの特殊なケースがあります。 

先頭にゼロがある数値を考慮します。```
2 3
001
100
```1 番目と 3 番目の位置を交換すると、次のようになります。```
100
001
```値は次のとおりです。`100`そして`1`、 ない`100`そして`001`文字列として。 文字列を整数に変換するのではなく辞書順に比較するソリューションでは、誤った答えが暗黙的に生成される可能性があります。 

別の微妙なケースは、何らかの置換の下ですべての数値が等しくなる場合に現れます。```
3 2
12
12
12
```正しい答えは次のとおりです。```
0
```答えを誤って初期化するか、順列ごとの最小値と最大値の更新を忘れる不注意な実装では、これを見逃す可能性があります。 

可能な限り最小の入力を伴う境界ケースもあります。```
1 1
7
```数値は 1 つだけ存在するため、最大値と最小値は同じになります。 答えは次のとおりです。`0`順列の選択に関係なく。 

## アプローチ

 最も直接的なアイデアは、数字の位置のあらゆる可能な順序を試してみることです。 

仮定する`k = 4`。 次のような順列`(2, 0, 3, 1)`手段：```
abcd -> cadb
```この並べ替えをすべての入力数値に適用し、結果を整数に変換して、次のように計算します。```
max_value - min_value
```すべての順列の中で、最小の差を維持します。 

すべての有効な変換は位置の 1 つの並べ替えに正確に対応するため、この強引な方法は正しいです。 この問題では可能な限り最良の共有再配置が求められるため、すべての順列をチェックすることで、最終的には最適なものを調べることが保証されます。 

当然の懸念はパフォーマンスです。 順列の数は階乗的に増加します。```
k!
```もし`k`だった`15`、これはまったく不可能です。 でもここで`k ≤ 8`、したがって、最悪の場合は、`40320`順列。 各順列について最大で処理するのは`8`一定の長さの文字列`8`。 

これにより、徹底的な検索が十分に高速になります。 

重要な観察は、検索空間は次のもののみに依存するということです。`k`、数値そのものではありません。 なぜなら`k`は小さいため、高度なプルーニングや最適化は必要ありません。 意図されたソリューションは、完全な列挙の単純な実装です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての順列に対するブルートフォース | O(k! × n × k) | O(k) | 承認済み |
 | さらに複雑な最適化 | 不要 | 不要 | やりすぎ |

 ## アルゴリズムのチュートリアル

 1. 入力されたすべての数値を文字列として読み取ります。 

それらを文字列として保持すると、数字の並べ替えが簡単になります。 ここでは算術数字の抽出は必要ありません。 
2. インデックスのすべての順列を生成する`0 ... k-1`。 

各順列は、すべての数値に適用される 1 つのグローバル再配置ルールを表します。 
3. 現在の順列について、すべての番号を再構築します。 

元の文字列ごとに、順列で指定された順序で文字を取得して新しい文字列を構築します。 

例：```
s = "5237"
perm = (2, 0, 3, 1)

result = "3572"
```4. 再構築された各文字列を整数に変換します。 

これにより、先行ゼロが自動的に正しく処理されます。 
5. この順列によって生成される最小値と最大値を追跡します。 

それらの違いは、この再配置ルールによって作成されるスプレッドです。 
6. これまでに確認された最小の差で全体的な回答を更新します。 
7. すべての順列が処理されたら、答えを出力します。 

### なぜ効果があるのか

 問題内のすべての正当な演算は、まさにすべての数値に均一に適用される桁の位置の並べ替えです。 このアルゴリズムは、そのようなすべての順列を省略や重複なく列挙します。 

順列ごとに、結果として得られる正確な最大値と最小値が計算されるため、その構成の差は正確になります。 

アルゴリズムは考えられるすべての構成をチェックし、それらの間の差異を最小限に抑えるため、最終的な答えは最適なものでなければなりません。 

## Python ソリューション```python
import sys
from itertools import permutations

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    nums = [input().strip() for _ in range(n)]

    ans = float('inf')

    for perm in permutations(range(k)):
        mn = float('inf')
        mx = -1

        for s in nums:
            val = int(''.join(s[i] for i in perm))

            mn = min(mn, val)
            mx = max(mx, val)

        ans = min(ans, mx - mn)

    print(ans)

solve()
```ソリューションはアルゴリズムに直接に従います。`permutations(range(k))`あらゆる可能な位置の再配置を生成します。 以来`k ≤ 8`、これでも十分に効率的です。 

文字のインデックス付けは、数学的に数字を繰り返し抽出するよりも簡単でエラーが発生しにくいため、入力数値は文字列として保存されます。 

順列ごとに、以下を使用して数値を再構築します。```
''.join(s[i] for i in perm)
```これにより、再配置後の数字シーケンスが構築されます。 

で変換`int(...)`重要です。 先頭のゼロは許可されており、整数変換では次のようなケースが自然に処理されます。`"001"`なる`1`。 

最小値と最大値は、順列ごとに個別に再計算されます。 順列ループ内でそれらをリセットするのを忘れるのはよくあるバグです。 

入力文字列といくつかの一時的な値のみを保存するため、メモリ使用量はわずかにとどまります。

```アルゴリズムは再配置された文字列を次のように変換するため、これを正しく処理します。`int(...)`。 辞書編集的な比較では、正しく処理されません。`"001"`違う。

| 値 | 最小 | 最大 | 違い |
