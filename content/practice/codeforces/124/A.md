 ## 解決策
 ## 問題の理解

 ペトルは次のような列のどこかに立っている。`n`人々。 ポジションには次から番号が付けられます`1`前に`n`後ろに。 

彼は自分の立場について 2 つのことを知っています。 少なくとも`a`人々は彼の前に立っていて、せいぜい`b`人々が彼の後ろに立っている。 両方の条件を満たす異なる位置がいくつあるかを数えなければなりません。 

ペトルがその位置に立っている場合`p`、それではまさに`p - 1`人々は彼の前にいます、そしてまさに`n - p`彼の後ろには人々がいます。 タスクは整数の個数を見つけることになります`p`両方の不等式を満たす：

 -`p - 1 >= a`-`n - p <= b`制約は非常に小さいので、`n <= 100`。 すべての位置に対するブルートフォースループでも十分に高速です。 高度な最適化、データ構造、動的プログラミングは必要ありません。 主な課題は、1 つずつ間違いを犯すことなく、文言を正しい不等式に変換することです。 

最も一般的な間違いは、「以上」というフレーズを誤解することです。`a`前にいる人」という意味です。`at least a`、正確にはそうではありません`a`。 

次の例を考えてみましょう。```
5 2 1
```有効な位置は次のとおりです`3`そして`4`。 

位置`5`があるため無効です`0`ペトルの後ろに人がいることは許可されていますが、`4`前に人がいる場合も許可されます。 実際の位置`5`も有効です。 正確に想定した不注意な実装`a`前の人は誤って 1 つの位置だけを返します。 

別の微妙なエッジケースが現れるのは、`b = 0`。 

例：```
4 1 0
```ペトルは誰も彼の後ろに立つことができないため、一番後ろに立つ必要があります。 唯一の有効な位置は、`4`。 などの間違った解釈`behind < b`の代わりに`behind <= b`正しい答えを拒否することになります。 

ポジションとカウントの間で変換する際には、簡単なオフバイワントラップもあります。 

例：```
3 0 2
```すべての位置が有効です。 位置`1`もっている`0`前にいる人たちと`2`後ろに。 位置`3`もっている`2`前と`0`後ろに。 位置の番号付けが次から始まることを忘れています。`1`多くの場合、これらの境界ケースを破ります。 

## アプローチ

 ブルートフォースアプローチは、あらゆる可能な位置を直接テストします。`1`に`n`。 

ポジションごとに`p`、次のように計算します。 

- 前にいる人たち =`p - 1`- 後ろの人たち =`n - p`両方の条件が当てはまる場合、答えをインクリメントします。 

制約が非常に小さいため、これが機能します。 最悪の場合はチェックします`100`これは事実上瞬時に行われます。 

興味深いのは、反復せずに数学的に答えを導き出せることを認識していることです。 

から：```
p - 1 >= a
```得られるもの:```
p >= a + 1
```から：```
n - p <= b
```得られるもの:```
p >= n - b
```したがって、ペトルの位置は両方の下限を同時に満たす必要があります。```
p >= max(a + 1, n - b)
```可能な最大の位置は常に`n`したがって、すべての有効な位置は次のとおりです。```
[max(a + 1, n - b), n]
```この間隔内の整数の数は次のとおりです。```
n - max(a + 1, n - b) + 1
```これは、よく知られているコンパクトな式に単純化されます。```
min(n - a, b + 1)
```ここではどちらの方法も完全に受け入れられます。 この式はよりクリーンで定数時間ですが、ブルートフォースの方が最初に導き出すのが簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、`a`、 そして`b`。 
2. Petr は少なくとも次のものを持っている必要があります`a`彼の前にいる人々。 

以来の地位`p`もっている`p - 1`前に人がいる場合、有効な最小位置は`a + 1`。 
3. ペトルが持っているのは最大でも`b`彼の後ろにいる人たち。 

以来の地位`p`もっている`n - p`後ろにいる人たち、私たちは次のことを解決します。```
n - p <= b
```これは次のようになります:```
p >= n - b
```4. これら 2 つの下限のうち、より厳密な方が最初の有効な位置を決定します。```
start = max(a + 1, n - b)
```5. あらゆるポジションから`start`を通して`n`有効です。 

間隔の長さを使用してそれらをカウントします。```
answer = n - start + 1
```6. 答えを印刷します。 

### なぜ効果があるのか

 ポジションは、両方の制約を同時に満たす場合にのみ有効です。 

最初の条件は、前方に近すぎる位置を除外します。 2 つ目では、ペトルの後ろに多くの人が残る可能性があるため、前方に寄りすぎるポジションも除外します。 

両方のステートメントを不等式に変換した後、`p`、すべての有効な位置は、次で終わる 1 つの連続した間隔を形成します。`n`。 その間隔内の整数をカウントすると、欠落も追加もせずに、正当な位置の数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, a, b = map(int, input().split())

start = max(a + 1, n - b)
answer = n - start + 1

print(answer)
```プログラムは、ウォークスルーからの数学的導出に直接従います。 

表現`a + 1`少なくとも次の条件を持つ最初のポジションです`a`前にいる人たち。 これは、1 つ違いの間違いが起こりやすい場所です。 位置`a`しかないでしょう`a - 1`前にいる人たち。 

表現`n - b`ペトルの後ろにいる人々の状況を再整理することから来ています。 もう 1 つのよくある間違いは、次のように書くことです。`n - b + 1`、間隔が誤ってシフトされます。 

ついに、`n - start + 1`包含区間のサイズを計算します。 の`+1`両方のエンドポイントが有効な位置としてカウントされるため、これは重要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n, a, b = map(int, input().split())

    start = max(a + 1, n - b)
    answer = n - start + 1

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 1 1\n") == "2\n", "sample 1"

# custom cases
assert run("1 0 0\n") == "1\n", "single person line"
assert run("4 1 0\n") == "1\n", "must stand last"
assert run("5 0 4\n") == "5\n", "all positions valid"
assert run("100 99 99\n") == "1\n", "maximum boundary"
assert run("6 2 2\n") == "3\n", "middle interval"

 次の入力を考えてみましょう。```

```アルゴリズムは以下を計算します。```

n - b = 4
start = 4
answer = 1
```ポジションのみ`4`ペトルの後ろに誰も置くことができないので、機能します。 アルゴリズムは包含条件を正しく処理します`<= b`。 

次に、次のことを考えてみましょう。```

```得られるものは次のとおりです。```
a + 1 = 1
n - b = 1
start = 1
answer = 5
```どの位置も有効です。 これにより、式がフルレンジの場合を正しく処理していることが確認されます。 

最後に、次のことを考慮してください。```

```計算は次のようになります。```

n - b = 1

```3 つのポジションすべてがカウントされます。 このケースでは、位置と前にいる人の数の間の変換がオフバイワンエラーなしで処理されることを検証します。
