 ## 解決策
 ## 問題の理解

 このタスクでは、次の方程式を満たす 10 億未満のすべての正の整数を見つけるように求められます。$$x = b \cdot s(x) \cdot a + c$$どこ$a$、$b$、 そして$c$定数が与えられ、$s(x)$の桁の合計です$x$。 入力は 3 つの整数で構成されます$a$、$b$、 そして$c$、出力には有効なソリューションの数がリストされ、その後にソリューションが昇順にリストされる必要があります。 

最初の観察は、問題は次のような制約を受けているということです。$x < 10^9$。 以来$x$が制限されている場合、すべての解はこのしきい値を下回る必要があります。 機能$s(x)$最大でも次の桁の合計です$999,999,999$、これは 9 掛ける 9 で、81 に相当します。したがって、桁の合計は、以下に比べて非常に狭い範囲に制限されます。$x$。 これは、効率的な解決策を可能にする重要な観察です。 

以下のすべての整数をテストする素朴なアプローチ$10^9$遅すぎるでしょう。 まで繰り返しても$10^8$数億回の操作が必要となり、1 秒の制限時間内では実行不可能です。 

明白ではないエッジケースには、計算後の否定的な結果が含まれます$b \cdot s(x) \cdot a + c$、の値$x$まさに上限で、そして$x$桁の合計が得られる値$s(x)$ゼロまたは小さいです。 たとえば、次の場合$c$負で大きさが大きいため、減少する可能性があります$x$単純にすべての桁の合計を試行すると、範囲制限を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのことを繰り返すことになります。$x$1から$10^9$、桁の合計を計算します$s(x)$、 評価する$b \cdot s(x) \cdot a + c$と等しいかどうかを確認します$x$。 これは、文字通りすべての候補について方程式をテストするため正しいですが、最大 10 億回のチェックを実行するため、非現実的です。 

重要な洞察は、この方程式が桁の合計に関して書き換えられるということです。$s$の代わりに$x$:$$x = a \cdot b \cdot s + c$$ここ、$s$は、1 ～ 81 の範囲の整数である必要があります。これは、以下の数値の桁の合計の最大値が制限されるためです。$10^9$は 9 の 9 倍です。この観察により、検索スペースが大幅に減少します。 10 億の整数を反復する代わりに、最大 81 桁の可能な合計を反復するだけです。 各候補の合計について$s$、計算します$x = a \cdot b \cdot s + c$、次に、次の桁の合計かどうかを確認します。$x$等しい$s$そしてもし$x$がプラス以下である$10^9$。 これは効率的であり、正確性が保証されます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$a$、$b$、 そして$c$。 これらは方程式の定数です。 
2. 有効なソリューションを保存するために空のリストを初期化します。 
3. 考えられるすべての数字の合計を反復します。$s$1 から 81 まで。これは、以下の数値の実行可能な合計をすべてカバーします。$10^9$。 
4. それぞれについて$s$、候補解を計算します$x = a \cdot b \cdot s + c$。 これは方程式を整理すると直接得られます。 
5.次のことを確認します$x$は正であり、未満です$10^9$。 この範囲外の値はすべて破棄します。 
6. 次の桁の合計を計算します。$x$そしてそれを比較してください$s$。 一致する場合は追加します$x$解決策のリストへ。 
7. 考えられるすべての合計を確認した後、リストを昇順に並べ替えます。 
8. 解の数を出力し、その後に解そのものを出力します。 

なぜそれが機能するのか: ここで不変なのは、有効な解決策が存在することです。$x$は、方程式と桁の合計の定義の両方を満たさなければなりません。 以来$s(x)$いずれの場合も 81 を超えることはできません$x < 10^9$、考えられるすべての合計を反復処理することで、有効な解が失われないことが保証されます。 チェック中$s(x) = s$候補者が誤検知されないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(n):
    return sum(int(d) for d in str(n))

a, b, c = map(int, input().split())
solutions = []

for s in range(1, 82):
    x = a * b * s + c
    if 0 < x < 10**9 and digit_sum(x) == s:
        solutions.append(x)

solutions.sort()
print(len(solutions))
print(*solutions)
```機能`digit_sum`整数を文字列に変換し、その桁を合計します。 これは小さい数値の場合に効率的であり、手動での桁抽出を回避します。 実行可能なすべての桁の合計を反復し、候補を計算し、正数と桁の合計でフィルター処理し、最後に並べ替えて昇順に出力します。 を繰り返すためソートが必要です$s$順序を保証するものではありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    
    def digit_sum(n):
        return sum(int(d) for d in str(n))
    
    a, b, c = map(int, input().split())
    solutions = []
    
    for s in range(1, 82):
        x = a * b * s + c
        if 0 < x < 10**9 and digit_sum(x) == s:
            solutions.append(x)
    
    solutions.sort()
    return f"{len(solutions)}\n{' '.join(map(str, solutions))}"

assert run("1 1 0\n") == "9\n1 2 3 4 5 6 7 8 9", "all single digits"
assert run("2 3 5\n") == "3\n11 17 23", "small a, b, c"

 ## 特殊なケース

 このアルゴリズムは、x = a_b_s + c を計算することで c < 0 を処理します。 s = 1 の場合、x <= 0 の場合、それは破棄されます。 たとえば、入力の場合`1 1 -1`、s = 1 の x = 0 は無効であるため、s = 2 のみが x = 1 になります。桁の合計チェックにより、誤検知が確実に拒否されます。 

たとえば、x が上限に近づいている場合、`a=5, b=100000, c=0`, x = 5_100000_81 = 40500000 < 10^9 であるため、有効な解が含まれています。 並べ替えると、 がソリューションを生成する順序に関係なく、出力が昇順になります。
