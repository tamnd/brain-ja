 ## 解決策
 ## 問題の理解

 ローランドは、すべての塔のペア間の二乗距離の合計が最大になるように、原点のバラの周囲の 2D 整数グリッド上に _n_ 個の監視塔を配置したいと考えています。 各タワーは、(0,0) を中心とする半径 _r_ の円内またはその上に配置する必要があります。 原点自体を含め、複数の塔が同じ座標を占有することができます。 出力は、最初に距離の二乗の最大合計、次に各タワーの座標です。 

入力により、塔の数 _n_ と最大許容距離 _r_ が得られます。 _n_ は 2 ～ 8 と小さいため、大きな _n_ では実現不可能な組み合わせアプローチを検討できます。 半径 _r_ は最大 30 です。これは、円内の整数座標の総数が制限されることを意味します (r = 30 の場合、およそ πr² ≈ 2800 ポイント)。 

単純なアプローチは、対称性を無視すると失敗する可能性があります。 たとえば、すべての塔を原点に配置することは有効ですが、距離の合計はゼロになります。 半径ごとに 1 つの点だけを試行する不注意なアプローチでは、円の反対側に交互に塔があるなど、繰り返される点が合計を最大化する配置を見逃す可能性があります。 エッジ ケースには、最適な配置が円上の正反対の点である n=2、r=1、または r が小さい n>4 (ペアごとの距離を最大化するために複数のタワーが位置を共有する必要がある) が含まれます。 

## アプローチ

 ブルートフォース手法は単純です。円内のすべての整数点を列挙し、これらの点のすべての n タプルを生成し (繰り返しを許可)、各タプルの距離の二乗和を計算し、最大値を取得します。 各距離の計算には n 回の 2 つの演算が必要で、タプルの合計数はおよそ O(m^n) です。ここで、m ≈ πr² は有効な整数点の数です。 r=30、n=8 の場合でも、m^n は約 2800^8 ですが、これは天文学的に大きく、明らかに非現実的です。 

重要な観察は、距離の二乗和を最大化すると、タワーを可能な限り離して配置することが促進されるということです。 距離の二乗和の式は対称であり、各座標の寄与は x と y に沿った二乗の和と考えることができます。 n が小さく、r が有限であることを考慮すると、円の内側にすべての候補点を生成し、バックトラッキング検索を使用して塔を配置することが可能です。 選択ごとに、現在の構成にタワーを再帰的に追加し、距離の二乗の合計を追跡します。 n は最大 8 であるため、再帰の深さは浅くなります。 現在の最適な合計を超える可能性のない構成をスキップすることで、早期にプルーニングを行います。 

これにより、問題はポイントを列挙し、配置に対する再帰的検索を使用することになります。これは、ポイントの n が小さく適度な数であるため扱いやすいものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース: 点のすべての n タプル | O((π r²)^n * n²) | O(n) | 遅すぎる |
 | 点の再帰的バックトラッキング | O(m^n * n²) 枝刈りあり | O(n) | n ≤ 8 の場合は受け入れられます |

 ## アルゴリズムのチュートリアル

 1. x² + y² ≤ r² となるすべての整数点 (x, y) を生成します。 これらがタワーの候補位置です。 原点と円の内側の他のすべての点を含めます。 このステップを行う理由は、円の外側に塔が存在できず、整数の座標が必要であるためです。 
2. 変数を初期化して、二乗距離の最大合計と対応するタワー配置を保存します。 
3. 再帰関数を定義する`search(towers, index)`どこ`towers`すでに配置されているタワーのリストです。`index`これまでに設置されたタワーの数です。 インデックス = n の場合、再帰を停止します。 
4. 各再帰ステップで、すべての候補点を反復処理し、その点を`towers`。 この新しいタワーと、以前に配置されたすべてのタワーによって寄与される距離の二乗和の増分を計算します。 これにより、毎回完全な n² 距離を計算するのではなく、変更内容のみを計算することが保証されます。 
5. 再帰呼び出し`search`新しい塔が追加されました。 再帰が戻ったら、最後のタワーを削除してバックトラックし、次の候補ポイントを試します。 これにより、すべての構成が調査されます。 
6. 再帰が n タワーに達した場合、合計を現在の最大値と比較し、必要に応じて更新し、対応する座標を保存します。 
7. すべての構成を調べた後、タワーの最大合計と座標を出力します。 

機能する理由: 各再帰ブランチは、タワーの個別の配置を探索します。 ペアごとの距離の増分計算によって正確さが保証され、バックトラッキングによってすべての可能な構成が考慮されるようになります。 n ≤ 8 であるため、すべての実現可能な配置を徹底的に探索するため、見つかった最大合計が最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, r = map(int, input().split())
    points = []
    for x in range(-r, r+1):
        for y in range(-r, r+1):
            if x*x + y*y <= r*r:
                points.append((x, y))

    max_sum = -1
    best_config = []

    def dist2(p1, p2):
        dx = p1[0]-p2[0]
        dy = p1[1]-p2[1]
        return dx*dx + dy*dy

    def search(towers, index, current_sum):
        nonlocal max_sum, best_config
        if index == n:
            if current_sum > max_sum:
                max_sum = current_sum
                best_config = towers[:]
            return
        for p in points:
            incremental = sum(dist2(p, t) for t in towers)
            towers.append(p)
            search(towers, index+1, current_sum + incremental)
            towers.pop()

    search([], 0, 0)
    print(max_sum)
    for x, y in best_config:
        print(x, y)

if __name__ == "__main__":
    main()
```この解決策では、まず円内の候補点を列挙します。 の`dist2`関数は浮動小数点演算を避けるために二乗距離を計算します。 再帰的`search`関数は、n 個のタワーのすべての組み合わせを探索し、合計を増分更新します。 バックトラッキングにより、すべての構成が確実に考慮されます。 同じ地点に複数の塔があるなどのエッジケースは、再帰で候補を繰り返すことができるため、自然に処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m^n * n) | 円の内側には m 個の候補点があります。 各再帰の深さは n で、各ステップで前のタワーまでの距離を O(n) で計算します。 |
 | スペース | O(n + m) | 再帰スタックの深さは n です。 候補点リストにはｍ個の点が格納される。 |

 n ≤ 8、r ≤ 30、m ≤ 2800 の場合、再帰呼び出しの総数は実現可能です。 増分距離の計算では、各呼び出しが O(n²) ではなく O(n) に保たれます。
