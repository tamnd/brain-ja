 ## 解決策
 ## 問題の理解

 限られた日数の水やりの後、花の最低高さを最大にするように求められます。 それぞれの花には初期の高さがあり、いつでも、正確に _w_ 個の花の連続したセグメントに水をやり、それぞれを 1 つずつ増やすことができます。 このような水やりには _m_ 日かかります。花は一定の列に配置されているため、水やりセグメントは順序を尊重する必要があります。 

入力により、花の数 _n_、日数 _m_、水やりの幅 _w_ が与えられ、その後に花の初期の高さが続きます。 出力は単一の整数です。_m_ 日間最適に水やりを行った後の最小の花の可能な最大の高さです。 

制約により、_n_ は最大 10^5、_m_ も最大 10^5、花の高さは最大 10^9 であることがわかります。 これにより、可能性の数は指数関数的なため、考えられるすべての水やりシーケンスを試みる単純なシミュレーションは除外されます。 どのソリューションも、テスト ケースごとにおよそ O(n log X) または O(n) で動作する必要があります。ここで、X は達成可能な最大高さによって制限されます。 

重要なエッジ ケースは、最小の花が他の花と比較して既に高い場合、または _w_ = 1 の場合に発生します。たとえば、_n_ = 3、_m_ = 1、_w_ = 1 で、初期の高さが`[1, 2, 3]`、最大最小高さは`2`なぜなら、1つの花を1単位ずつしか増分できないからです。 残りの水やりを考慮せずに、左から右へ貪欲に水を与えようとする不注意なアプローチは、達成可能な最小値を過大評価することになります。 

## アプローチ

 ブルートフォースソリューションでは、毎日の水やりのすべてのシーケンスを試行し、毎回配列を更新して最小値をチェックします。 任意の散水シーケンスをシミュレートできるため、これは正しいですが、最悪のケースでは O(n * m * n) の操作が必要となり、n、m ≤ 10^5 の場合には遅すぎます。 

重要な洞察は、この問題が「最大 m 回の散水で最小高さ H を達成できるか?」という意思決定問題として再構成できることです。 この質問に効率的に答えることができれば、H に対して二分探索を適用できます。これが機能するのは、H の増加が単調であるためです。H が達成可能であれば、より小さい H も達成可能です。 H が達成できない場合、それ以上の H は不可能です。 

高さ H が達成可能かどうかの確認は、差分配列を使用して貪欲に実行し、O(n) での水やりの増分効果をシミュレートできます。 花ごとに、以前の水やりの最終的な効果を追跡し、高さ H を満たすために新しい水やりセグメントを適用するかどうかを決定します。これにより、毎回完全な配列を更新することが回避され、複雑さが線形に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * n) | O(n) | 遅すぎる |
 | 最適 (二分探索 + 貪欲 + 差分配列) | O(n log(最大高さ)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`low`花の高さを最小限に抑え、`high`に`max(a) + m`、最小の花にすべての水やりを適用した後の最小高さの理論上の上限。 
2. その間`low < high`、 選ぶ`mid = (low + high + 1) // 2`。 これは、テストしたい最小高さ H の候補です。 
3. H が達成可能かどうかをテストするには、差分配列を初期化します。`add`サイズは n+1 から 0 までです。 この配列は、水やりの回数が各花に効率的に影響を与えるかを追跡します。 
4. トラック`current_add = 0`、左から右に繰り返すと、前回の水やりからの純成長が表示されます。 
5. 0 から n-1 までの花 i ごとに、次の計算を行います。`current_height = a[i] + current_add`。 もし`current_height < H`、i から水をやる必要があります。 必要な水やりの回数は、`delta = H - current_height`。 
6. インクリメント`current_add`デルタによる更新`add[i + w] -= delta`もし`i + w < n`この散水の効果が位置 i + w - 1 の後に終了することを示します。これまでに使用された散水の合計を追跡します。 
7. 総散水量が m を超える場合、H は達成できません。 それ以外の場合はそのとおりです。 
8. H が達成可能な場合は、設定します。`low = mid`; それ以外の場合は、設定します`high = mid - 1`。 
9. 二分探索が終了したら、`low`is the maximum achievable minimum height.

 機能する理由: 差分配列により、各水やり増分が正確に w 個の連続する花に影響を及ぼし、O(1) 内の任意の花に対する正味の影響を計算できることが保証されます。 二分探索は、決定関数の単調性を利用します。 それぞれの花を貪欲に選択することで、H に達しない水不足や、何日も無駄にする水のやりすぎは決してありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_achieve(H, n, m, w, a):
    add = [0] * (n + 1)
    current_add = 0
    used = 0
    for i in range(n):
        current_add += add[i]
        if a[i] + current_add < H:
            delta = H - (a[i] + current_add)
            used += delta
            if used > m:
                return False
            current_add += delta
            if i + w < n:
                add[i + w] -= delta
    return True

def solve():
    n, m, w = map(int, input().split())
    a = list(map(int, input().split()))
    low, high = min(a), max(a) + m
    while low < high:
        mid = (low + high + 1) // 2
        if can_achieve(mid, n, m, w, a):
            low = mid
        else:
            high = mid - 1
    print(low)

if __name__ == "__main__":
    solve()
```このソリューションでは、二分探索と実現可能性チェックが分離されます。`can_achieve`は差分配列を使用するため、散水ごとに 2 つの位置のみが更新され、時間計算量は O(n) に保たれます。 Off-by-One エラーは、位置 i からの水やりの効果が i + w - 1 まで続くことに注意して、差分配列のインデックスを注意深く作成することによって回避されます。 

## 実用的な例

 **サンプル 1**:

 入力:`n=6, m=2, w=3, a=[2,2,2,2,1,1]`二分探索テスト H = 3:

 | 私 | a[i] | 現在の追加 | デルタ | 中古 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 1 | 1 |
 | 1 | 2 | 1 | 0 | 1 |
 | 2 | 2 | 1 | 0 | 1 |
 | 3 | 2 | 1 | 1 | 2 |
 | 4 | 1 | 1 | 1 | 3 → m=2 を超える → False |

 したがって、H=3 は失敗し、H=2 は成功します。 出力は2です。 

**カスタム例**:

 入力:`n=5, m=5, w=2, a=[1,1,1,1,1]`二分探索テスト H=3:

 | 私 | a[i] | 現在の追加 | デルタ | 中古 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 2 | 2 |
 | 1 | 1 | 2 | 0 | 2 |
 | 2 | 1 | 2 | 1 | 3 |
 | 3 | 1 | 1 | 2 | 5 |
 | 4 | 1 | 0 | 3 | 8 → m=5 を超える → False |

 Ｈ＝２が達成可能である。 出力2。 

これは、差分配列がどのように散水を効率的に伝播するかを示しています。
