 ## 解決策
 ## 問題の理解

 Kevin ではいくつかの種類のタコスを用意しています。 各種類には通常の購入価格があり、タコスの種類間の一方的な交換もあります。 交換では、追加料金を支払うことで、ある種類のタコスを別の種類のタコスに変えることができます。 各交換は何度でも実行できます。 

入力には、タコスの種類の数、各種類のタコスを 1 つ購入する直接価格、すべての可能な交換、そして最後に Kevin が希望する各種類のタコスの数が記述されます。 目標は、要求されたタコスの配布を正確に完了するために必要な最小限の金額を見つけることです。 

中心的な問題は、タコスを購入した後に交換をどのように実行するかではありません。 代わりに、最終的なタコスの種類をどれだけ安く生産できるかが重要です。 タイプのタコス`i`直接購入することも、別のタイプを購入して一連の交換を行うことで入手することもできます。 すべての種類の製造にかかる最も安いコストがわかれば、要求されたタコスを個別に処理できるようになります。 

この制約は、グラフによる解決策を強く示唆しています。 最大 10,000 のタコスの種類と 100,000 の交換が可能です。 すべての目的地について考えられるすべての開始タコスをチェックするアプローチでは、グラフの処理だけでも約 10^8 以上の操作が必要となり、パスを繰り返し探索するのは非常に遅すぎます。 疎なグラフを効率的に処理する最短パス アルゴリズムが必要です。 エッジの重みは負ではないため、ダイクストラのアルゴリズムが適しています。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 1 つ目は、タコスを複数の交換でしか入手できない場合です。 例えば：```

もう 1 つの注意が必要なケースは、ソース タコスを直接購入するよりも交換の方が安いにもかかわらず、交換パスが異なる種類から始まる場合です。 例えば：```

最後のよくある間違いは、多くのタコスの種類が同じ最も安価なソースを共有している可能性があることを無視することです。 例えば：```

## アプローチ

 強引なアプローチでは、すべてのタコス タイプを開始点として考慮し、そのタイプから最短パス検索を実行して、他のどのタコス タイプを生成できるかを決定します。 その後、最初のタコスを購入し、それを目的地ごとの現在のベストアンサーと換算したコストを比較できます。 

この方法は、考えられるすべてのソース タコスが考慮されているため、正しいです。 タコスタイプを作成する最も安価な方法がタコスを購入することから始まる場合`s`、から実行されます`s`対応する交換パスを検出します。 

問題は繰り返し作業の量です。 ディクストラを一度実行するとコストがかかります`O((t + e) log t)`。 あらゆる種類のタコスを実行するとコストがかかる`O(t(t + e) log t)`。 タコスの種類が 10,000 種類、交換回数が 100,000 回と、これは制限時間をはるかに超えています。 

重要な観察は、すべての種類のタコスが同じ質問をしているということです。「私に届く最も安い販売店は何ですか?」 すべてのソースからの最短パスを個別に実行する代わりに、視点を逆転させることができます。 すべてのタコス タイプまでの距離がゼロの仮想ソースを作成することを想像してください。ただし、ダイクストラを実行する前に、すべてのタコス タイプの距離を直接購入コストで初期化します。 マルチソースのダイクストラは、これらの初期コストを為替グラフを通じて分散します。 

ディクストラがタイプからの交換を緩和したとき`i`入力する`j`を取得しているかどうかを確認します。`i`現在の入手方法よりも安く交換手数料を払った方がお得です`j`。 考えられるすべての開始購入が初期距離にすでに存在しているため、これは元の問題と正確に一致します。

 | ブルートフォース | O(t(t + e) log t) | O(t + e) | 遅すぎる |
 | 最適 | O((t + e) log t) | O(t + e) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. タコスの種類、直接購入価格、交換先、必要数量を確認します。 交換からの型であるため、各交換を有向グラフ エッジとして保存します。`i`入力する`j`逆交換が存在することを意味するものではありません。 
2. 各タコス タイプの最短距離を直接購入価格で初期化します。 これは、取引所を使用せずにそのタコスをすぐに購入できる可能性を表します。 
3. すべてのタコス タイプを現在の距離で優先キューに挿入します。 これにより、考えられるすべてのソースから同時にダイクストラが開始されます。 
4. 既知の最小コストのタコス タイプを繰り返し削除します。 送信するすべての交換について、まず現在のタコスの種類を取得し、次に交換手数料を支払うことで、宛先に到達するコストを計算します。 この値が小さい場合は、宛先を更新し、新しい値を優先キューにプッシュします。 
5. 最短パスのプロセスが完了したら、各タコス タイプの最も安いコストに、そのタイプに要求されたタコスの数を掛けます。 これらの値を合計して、最小合計価格を取得します。 

これが機能する理由は、タコスを入手する有効なすべての方法が、購入する最初のタコスを選択し、交換の経路をたどることで構成されているためです。 初期距離はすべての可能な開始購入を表し、すべての緩和はそれらのパスの 1 つを延長することを表します。 すべての交換コストは負ではないため、ダイクストラは常に各ノードへの既知の最も安価なパスを維持します。 アルゴリズムが終了すると、すべてのタコス タイプの距離が、そのタイプの 1 つのタコスを作成するための最も安価なコストになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t, e = map(int, input().split())

    dist = []
    for _ in range(t):
        dist.append(int(input()))

    graph = [[] for _ in range(t)]

    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = []
    for _ in range(t):
        need.append(int(input()))

    pq = []
    for i, cost in enumerate(dist):
        heapq.heappush(pq, (cost, i))

    while pq:
        cost, node = heapq.heappop(pq)

        if cost != dist[node]:
            continue

        for nxt, price in graph[node]:
            new_cost = cost + price
            if new_cost < dist[nxt]:
                dist[nxt] = new_cost
                heapq.heappush(pq, (new_cost, nxt))

    answer = 0
    for i in range(t):
        answer += dist[i] * need[i]

    print(answer)

if __name__ == "__main__":
    solve()
```の`dist`配列は無限ではなく直接タコス価格から始まります。 これは、通常のダイクストラをマルチソース ダイクストラに変える主な実装の詳細です。 

優先キューには、最初にすべてのタコス タイプが含まれます。 より安価なパスが見つかった場合、古いキュー エントリは削除されません。 代わりに、新しいエントリが挿入され、`if cost != dist[node]`check は古いエントリをスキップします。 これは、Python でダイクストラを効率的に実装する標準的な方法です。 

交換は指定された方向にのみ機能するため、グラフには方向性があります。 これを無向として扱うと、誤って不可能な変換が許可されてしまいます。 

タコスの種類と値の数が Python の整数に適切に収まるため、最後の乗算は安全です。 Python の整数はオーバーフローしないため、コードは大きな合計に対して特別な処理を必要としません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((t + e) log t) | 各タコス タイプは優先キューに複数回入ることができ、ダイクストラ中は各交換が緩和されます。 |

 タコスの種類が 10,000 種類、交換が 100,000 種類あるため、この複雑さは簡単に限界に達します。 このアルゴリズムは、考えられるすべての開始タコスから最短パスの計算を繰り返すのではなく、1 つのグラフ走査を実行します。 

## テストケース```python
import sys
import io
import heapq

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    input = sys.stdin.readline

    t, e = map(int, input().split())
    dist = [int(input()) for _ in range(t)]

    graph = [[] for _ in range(t)]
    for _ in range(e):
        i, j, p = map(int, input().split())
        graph[i].append((j, p))

    need = [int(input()) for _ in range(t)]

    pq = [(dist[i], i) for i in range(t)]
    heapq.heapify(pq)

    while pq:
        cost, node = heapq.heappop(pq)
        if cost != dist[node]:
            continue
        for nxt, price in graph[node]:
            if cost + price < dist[nxt]:
                dist[nxt] = cost + price
                heapq.heappush(pq, (dist[nxt], nxt))

    ans = sum(dist[i] * need[i] for i in range(t))
    print(ans)

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

 ## 特殊なケース

 複数回の交換を経ないとタコスに到達できない場合、アルゴリズムは緩和を繰り返すことで自然に処理します。 価格 10、100、100 と取引所の例では`0 -> 1`コスト3と`1 -> 2`コスト4、ディクストラは距離からスタート`[10, 100, 100]`。 まずタイプ 1 を 13 に改善し、次にタイプ 2 を 17 に改善します。最も安価なパスには両方の交換が含まれるため、最終的な答えでは 17 が使用されます。 

タコスがすでに可能な限り安価なソースである場合、アルゴリズムは最初の距離を保ちます。 価格 100 と 5 の入力とタイプ 1 からタイプ 0 への交換の場合、初期距離は次のようになります。`[100, 5]`。 タイプ 1 の処理では、タイプ 0 を 7 に改善しようとしますが、影響を受けるのはタイプ 0 のみです。要求されたタイプ 1 のタコスのコストは依然として 1 つあたり 5 です。 

多くのタコス タイプが同じ最も安価なソースを共有する場合、すべての宛先は独自の最短パス値を受け取ります。 タイプ 0 からの交換チェーンの場合、距離値は一度に 1 つのエッジずつ外側に広がります。 要求されたカウントを最終的に乗算すると、これらの独立した最小コストが正しく結合されます。
