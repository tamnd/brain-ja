 ## 解決策
 ## 問題の理解

 ケビンは、彼自身の 1 つの反応でミーム反応の連鎖を開始します。 毎晩、現在の反応数は自動的に 2 倍になります。 また、いつでも自分でリアクションを追加することもでき、それらの手動リアクションはすぐに行われます。 目標は正確に達成することです`n`チェーンを開始する最初の反応をカウントし、可能な限り最小限の手動反応を実行しながら反応を実行します。 

入力は単一の整数です`n`、必要な最終反応数を表します。 出力は、Kevin が行う必要がある手動反応の最小数です。 

制限により許可されるのは、`n`と同じくらい大きくなる`10^9`。 これにより、日数や考えられる多くのスケジュールを試すことに依存するシミュレーションが除外されます。 ソリューションは定数時間か、最大でも対数時間で機能する必要があります。`10^9`2進数は約30桁しかありません。 

重要な点は、手動の反応が必ずしも最終的なカウントに 1 つの反応だけを反映するとは限らないことを認識することです。 ケビンが早く反応すると、その反応は何倍にもなります。 彼が反応するのが遅ければ、回数は 2 倍少なくなります。 手動による各反応は、最終的な合計に寄与する 2 のべき乗 1 つを選択するものとみなすことができます。 

いくつかの特殊なケースでは、実装における間違いが明らかになります。 

のために`n = 1`、答えは`1`。 ケビンは最初の反応を行う必要があり、それを行わずに最初の反応を得る方法はありません。 

入力の場合:```
8
```正しい出力は次のとおりです。```
1
```不注意なアプローチでは、数が数日にわたって増加するため、ケビンにはいくつかの反応が必要であると思われるかもしれませんが、最初の反応だけでも`2`、`4`、 その後`8`。 

入力の場合:```
5
```正しい出力は次のとおりです。```
2
```1 つの反応が次のように成長する可能性があります`4`、その後、もう 1 つの手動反応が作成されます`5`。 手動ではなく日数を数えようとすると、間違った数量が表示されてしまいます。 

## アプローチ

 直接的な総当たりアプローチはプロセスをシミュレートします。 1 つの反応から始めて、毎日繰り返しカウントを 2 倍にし、到達するまでさまざまな時点で反応を追加してみることができます。`n`。 これが機能するのは、各手動反応がいつ発生するかを決定することによって、考えられるすべてのスケジュールを記述することができるからです。 

問題は、これにより多数の可能なスケジュールが検討されることです。 多くのビットが設定されている数値の場合、リアクションを追加するタイミングについては多くの選択肢があります。 検索スペースは指数関数的に拡大しますが、`n`それ自体は約 30 ビットしかありません。 2 倍化プロセスは単純な数学的構造を持っているため、これは不要です。 

有益な観察は、すべての手動反応が最終的な答えの 2 乗に寄与するということです。 最初に行われた反応が貢献します`2^k`後`k`夜。 1日後に行われた反応が寄与する`2^(k-1)`、 等々。 最終的な数値は、ケビンが反応する瞬間に対応する 2 の累乗の合計です。 

数値の 2 進数表現は、数値を 2 のべき乗の合計として記述する独自の方法です。 各設定ビットは 1 つの必要な手動反応を意味するため、答えは単純にその数です。`1`のバイナリ表現のビット`n`。 

すべてのスケジュールが 2 の累乗の有効な合計に対応するため、ブルート フォースは機能しますが、バイナリ表現で既に直接記述されているスケジュールを検索するため失敗します。 セットされたビットをカウントすると、検索全体が削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 可能な反応時間の数は指数関数的 | お(1) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 目標の反応数を読み取る`n`。 

の値`n`反応のタイミングは 2 のべき乗が加算されるかどうかのみに影響するため、必要な情報がすべて含まれています。 
2. のバイナリ表現を見てください。`n`。 

各 2 進数は、最終的な合計に特定の 2 の累乗が必要かどうかを表します。 以下に等しい数字`1`つまり、ケビンはその貢献として生き残る手動の反応を 1 つ必要としているということです。 
3. 等しい 2 進数の数を数えます。`1`。 

バイナリ表現では数値を作成するために使用する 2 のべき乗が最小限であるため、このカウントは手動反応の最小数です。 
4. カウントを出力します。 

最下位のバイナリ ビットは 2 倍になる前に行われた反応に対応するため、カウントには最初の反応が含まれます。 

なぜ効果があるのか:

 すべての手動反応は、正確に 2 の 1 乗の最終寄与を持ちます。 ケビンがある時点で反応し、`k`残りの夜、その反応が貢献する`2^k`終わりの反応。 したがって、有効な戦略はすべて 2 のべき乗の集合であり、その合計は次のようになります。`n`。 バイナリ表現により、次のような独自の分解が得られます。`n`を 2 のべき乗に変換し、設定された各ビットを 1 回使用すると項の数が最小限に抑えられます。 設定ビット数はまさに手動反応の最小数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    print(n.bit_count())

if __name__ == "__main__":
    solve()
```このソリューションでは Python の組み込み機能を使用します`bit_count()`整数表現で設定されたビット数をカウントするメソッド。 これは、アルゴリズムからの数学的観察と直接一致します。 

入力には整数が 1 つだけ含まれるため、パフォーマンスのために高速入力は必要ありませんが、標準の競技プログラミング入力スタイルが使用されます。 出力は、必要な手動反応の数です。 

境界の問題がないので、`bit_count()`すべての正の整数を直接処理します。 最小の入力でも、`1`、1 つのセットビットを生成します。 許可される最大の入力、`10^9`、それでも Python の整数型に簡単に適合し、ビット数もわずかです。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    return str(n.bit_count()) + "\n"

# provided samples
assert solve("5\n") == "2\n", "sample 1"
assert solve("8\n") == "1\n", "sample 2"

# custom cases
assert solve("1\n") == "1\n", "minimum value"
assert solve("3\n") == "2\n", "two consecutive bits"
assert solve("1023\n") == "10\n", "all bits set"
assert solve("1000000000\n") == "13\n", "large boundary value"
