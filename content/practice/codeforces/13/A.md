 ## 解決策
 ## 問題の理解

 2 から _A_ - 1 までのすべての基数で表される数値 _A_ の桁の平均合計を計算するように求められています。入力は、3 ～ 1000 の単一の整数 _A_ です。出力は、すべての桁の合計を考慮した基数で割ったものを表す既約分数 (基数 10 で書かれたもの) でなければなりません。 

制約は小さいです。 _A_ ≤ 1000 の場合、2 から _A_ - 1 までのすべての基数を反復処理することが可能です。 各基数について、その基数の _A_ の桁の合計を計算する必要があります。 演算の最大数は、_A_ = 1000 の場合に発生し、998 塩基になります。 各基数について、その基数の _A_ の桁数は最大でもおおよそ log₂A で、10 未満です。したがって、桁和の計算の総数は 10,000 未満になります。 これは 1 秒の制限時間内に簡単に収まります。 

明らかではないエッジ ケースには、桁数が大きくなる可能性がある 2 や 3 のような小さい基数や、_A_ が基数で正確に除算される状況が含まれます。 たとえば、_A_ = 4 の場合、底 2 で計算すると合計 1 で 100 が得られ、底 3 で計算すると合計 2 で 11 が得られます。単純な実装で除算や剰余の計算を誤ると、間違った合計が生成されたり、最高の底 _A_ - 1 を含め忘れたりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 2 から _A_ - 1 までの各基数 _b_ について、商が 0 になるまで _A_ を _b_ で割って余りを合計します。 次に、これらの合計を合計し、塩基の数で割って平均を求めます。 基底変換が明確に定義されており、演算の数が少ないため、これは正しく機能します。 最悪の場合、桁の計算数は log₍b₎A のすべての底の合計、つまり O(A log A) になります。 _A_ ≤ 1000 の場合、これは 10,000 回未満の操作であるため、ブルート フォース手法ですでに十分です。 

最適なアプローチは基本的に同じですが、出力形式に注意する必要があります。 既約形式の塩基数に対する合計の分数が必要です。 これを行うには、分子と分母の最大公約数を計算し、印刷前に両方をそれで割ります。 問題の構造により、各塩基を個別に調べる必要があるため、これ以上漸近的に改善することはできません。

 ## アルゴリズムのチュートリアル

 1. 入力から整数 _A_ を読み取ります。 これは、さまざまな基数に変換する数値です。 
2. 変数を初期化する`total_sum`ゼロに。 これにより、すべての基数の桁の合計が累積されます。 
3. ベースを反復処理する`b`2 から _A_ - 1 まで。 各塩基について、桁の合計を計算します。 
4. ループ内で初期化します`n`_A_ と`digit_sum`ゼロに。`n`現在の基数で繰り返し除算されます。 
5. ながら`n`ゼロより大きい場合は追加します`n % b`に`digit_sum`次に整数の除算を実行します`n //= b`。 これにより、数値が基数に変換され、桁が合計されます。 
6.追加`digit_sum`に`total_sum`。 
7. ループが終了した後、考慮される塩基の数は次のようになります。`A - 2`。 
8. 既約分数を求めるには、最大公約数を計算します。`g`の`total_sum`そして`A - 2`。 分子と分母の両方を次の値で割ります。`g`。 
9. 分数を次のように出力します。`X/Y`。 

機能する理由: 各反復では、除算と剰余を繰り返し使用して、base-_b_ 桁の合計が正しく計算されます。 すべてのベースを合計することで、すべての貢献が確実にカウントされます。 分数を減らすと、出力が既約形式になります。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

A = int(input())
total_sum = 0

for b in range(2, A):
    n = A
    digit_sum = 0
    while n > 0:
        digit_sum += n % b
        n //= b
    total_sum += digit_sum

denominator = A - 2
g = math.gcd(total_sum, denominator)
print(f"{total_sum // g}/{denominator // g}")
```コードは最初に数値 _A_ を読み取ります。 外側のループは 2 から _A_ - 1 までのすべての基数を反復し、内部では _A_ を現在の基数に変換し、モジュロと整数除算を使用して桁の合計を計算します。 すべての桁の合計を合計します。`total_sum`。 ループの後、次の最大公約数を計算します。`total_sum`分数を切り捨てて出力するための分母`X/Y`形式。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    A = int(input())
    total_sum = 0
    for b in range(2, A):
        n = A
        digit_sum = 0
        while n > 0:
            digit_sum += n % b
            n //= b
        total_sum += digit_sum
    denominator = A - 2
    g = math.gcd(total_sum, denominator)
    return f"{total_sum // g}/{denominator // g}"

# provided samples

 ## 特殊なケース

 _A_ = 3 の場合、考慮すべき基数は 1 つだけで、基数 2 です。変換すると、合計が 2 の 11 が得られます。分母 = 1。分数 = 2/1、2/1 に減算されます。 アルゴリズムは最小数の塩基を正しく処理します。 

_A_ = 4 の場合、基数 2 と 3 が考慮されます。 基数 2: 100 合計 1; 基数 3: 11 合計 2; 合計 = 3; 分母 = 2; 分数 = 3/2。 このアルゴリズムは桁の合計を正しく計算し、端数を削減します。 

_A_ = 1000 の場合、アルゴリズムは 998 基数を反復し、整数演算を使用して桁の合計を効率的に合計し、gcd を使用して端数を削減します。 これにより、最大の入力でも妥当な時間内に実行され、正しい既約分数が生成されることが確認されます。
