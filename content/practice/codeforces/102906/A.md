 ## 解決策
 ## 問題の理解

 入力をグラフとして再解釈できます。 各頂点はクラス内の項目を表し、各エッジは 2 つの項目に互換性があることを表します。 有効な答えは、頂点間のすべてのペアがエッジで接続されるように 3 つの頂点を選択することに相当します。これは、グラフ内で三角形を探していることを意味します。 

このような三角形を単に見つけるだけでなく、その三角形に対するコスト関数、通常は頂点に割り当てられた重みの合計 (または同様の集計) を最適化することも求められます。 したがって、問題は単に「三角形が存在するかどうか」ではなく、「最小コストの三角形を見つけること」です。 

入力サイズは通常、最大約$n \le 10^5$または同様の、最大で$m$エッジ。 これにより、すべての頂点のトリプルのチェックが直ちに除外されます。$O(n^3)$、これは 2 秒で処理できる範囲をはるかに超えています。 すべてのペアを列挙し、隣接性を盲目的にチェックするだけでも、慎重に構造化されていない限り、時間がかかりすぎます。 

素朴なアプローチは、すべてのトリプルを試すことです$(i, j, k)$、3 つのエッジがすべて存在するかどうかを確認し、コストを計算します。 トリプルの数が次のように増加するため、これは失敗します。$\binom{n}{3}$、さえも実行不可能になります。$n = 5000$、それはすでに次のオーダーで生産されているため、$10^{10}$小切手。 

2 番目の単純な改善は、エッジを修正することです$(u, v)$そして 3 番目の頂点を見つけようとします$w$両方に接続されています。 これにより検索スペースは削減されますが、隣接リストを繰り返しスキャンするという非効率的な作業は依然として発生します。$O(nm)$密集した場合の動作。 

重要な観察は、エッジを反復処理し、隣接セットの交差をチェックすることで三角形を効率的に検出できるということです。 これにより、エッジの 2 つの端点間の共通の近傍を見つけるという問題が軽減されます。これは、ハッシュまたは並べ替えられた隣接リストを使用して実行できます。 

## アプローチ

 ブルート フォース ソリューションでは、頂点のトリプルをすべて列挙します。 各トリプルについて、3 つのエッジがすべて存在するかどうかを確認し、有効な場合はコストを計算します。 これは三角形の定義を直接検証するため正しいですが、その複雑さは頂点の数が 3 次であるため、大規模な入力では不可能になります。 

この改善は、視点を「頂点を 3 つ選択する」から「エッジを 1 つ選択して三角形に完成させる」に変更することで生じます。 エッジを修正したら$(u, v)$、それを含む三角形には 3 番目の頂点が必要です。$w$両方とも$(u, w)$そして$(v, w)$存在する。 したがって、すべてのトリプルを列挙する代わりに、次の隣接セットを交差させます。$u$そして$v$。 これにより、すべてのトリプルからエッジと隣接交差の積までの検索スペースが削減されます。 

隣接関係セットがハッシュ セットとして保存されている場合、共通の隣接関係のチェックを効率的に行うことができます。 次に、検出された各三角形のコストを計算し、最小値を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのトリプル) |$O(n^3)$|$O(1)$| 遅すぎる |
 | エッジ + 隣接交差 |$O(m \cdot d)$平均、$O(nm)$最悪 |$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接構造を構築します。通常、メンバーシップ チェックが一定時間になるように各頂点のセットを構築します。 これが必要なのは、三角形の検出が高速なエッジ存在クエリに依存しているためです。 
2. 各エッジを反復処理します。$(u, v)$。 すべての三角形には少なくとも 1 つのエッジが含まれている必要があるため、これによりすべての三角形が少なくとも 1 回考慮されることが保証されます。 
3. 現在のエッジの場合$(u, v)$、すべての近傍を反復処理します$w$の$u$。 そういったものごとに$w$、どうかを確認してください$w$の隣人でもあります$v$。 この条件は次のことを保証します。$(u, v, w)$三角形を形成します。 
4. 有効な三角形が見つかるたびに、頂点値を使用してそのコストを計算し、グローバル最小値を更新します。 
5. すべてのエッジを処理した後、三角形が見つからなかった場合は戻ります。$-1$それ以外の場合は、記録された最小コストを返します。 

### なぜ効果があるのか

 無向グラフ内のすべての三角形には正確に 3 つのエッジがあるため、これらのエッジのいずれかを「ベース エッジ」として処理するときに検出されます。 交差チェックにより、3 番目の頂点が両方の端点に接続されていることを確認します。これはまさに三角形の定義です。 すべての三角形が少なくとも 1 回カウントされ、すべての有効な三角形が評価されるため、すべての有効な三角形の最小値が正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    adj = [set() for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        edges.append((u, v))

    INF = 10**18
    ans = INF

    for u, v in edges:
        if len(adj[u]) > len(adj[v]):
            u, v = v, u

        for w in adj[u]:
            if w in adj[v]:
                cost = a[u] + a[v] + a[w]
                if cost < ans:
                    ans = cost

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```隣接リストはセットとして保存されるため、3 番目の頂点のメンバーシップ チェックは定数時間で行われます。 間の小規模から大規模のスワップ$u$そして$v$各エッジ反復では、常に小さい隣接リストを反復処理することで近隣チェックの数が削減され、密なグラフでのパフォーマンスが向上します。 

最終的な最小値は無限大に初期化され、有効な三角形が見つかった場合にのみ更新されます。これにより、解が存在しない場合も適切に処理されます。

 ## 特殊なケース

 重要なエッジ ケースは、グラフが密であるにもかかわらず、問題定義に基づく有効なトリプルの接続要件を満たす三角形構造が含まれていない場合です。 たとえば、長さ 4 の単純なサイクルでは多くのエッジが作成されますが、三角形は作成されません。 アルゴリズムは各エッジを正しく処理しますが、隣接セットの交差部分は常に空であるため、更新は行われず、最終結果は次のようになります。$-1$。 

複数の三角形が存在する完全なグラフでは、別のエッジ ケースが発生します。 このアルゴリズムにより、各三角形が異なるベース エッジを介して複数回検出されることが保証されますが、すべての有効な三角形が一貫して評価されるため、最小コストは依然として正しく追跡されます。
