 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられます。 タスクは、指定された文字列の部分列として取得できない最短の文字列を構築することです。 

ここでのサブシーケンスとは、残りの文字の順序を変更せずに、元の文字列から文字を削除できることを意味します。 目標は、この特性を満たさない同じアルファベット上の文字列を見つけることであり、そのような文字列すべての中で可能な限り最小限の長さが必要です。 

より具体的に言うと、元の文字列が位置を伴う一連の文字であると想像してください。 元の文字列を左から右に進み、一致する文字を選択できる場合、候補の応答文字列は有効です。 このプロセスが不可能な文字列を見つけるように求められており、そのような文字列の中で最も短い文字列が必要です。 

制約構造では通常、最大約 10^5 の文字列長が許可されるため、考えられるすべての候補文字列を列挙しようとするソリューションは除外されます。 サブシーケンスの有効性をチェックするだけでも O(n) なので、長さ k のすべての文字列をブルート フォースすると、候補数は 26^k 個に爆発します。 これは、文字列を構築するのではなく、文字列内の位置を動的または貪欲な方法で推論する必要があることを直ちに示唆しています。 

アルファベットのすべての文字が文字列に出現する場合、微妙なエッジ ケースが発生します。 たとえば、文字列が次の場合、`"abcabc"`の場合、すべての文字はサブシーケンスですが、次のような長い文字列も含まれます。`"aa"`または`"zzz"`繰り返しと順序に応じて、サブシーケンスである場合もあれば、そうでない場合もあります。 もう 1 つのエッジ ケースは、ある文字がまったく表示されない場合です。たとえば、`"abac"`、 どこ`"z"`は直ちに長さ 1 の有効な答えになります。常に複数の文字が必要であると想定する不注意なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 長さ 1 のすべての文字列を構築し、次に長さ 2 というように構築を試み、候補ごとに、それが指定された文字列の部分列であるかどうかを確認します。 部分シーケンスのチェックは文字列の長さに対して線形であるため、各候補に対して O(n) を支払います。 候補の数は長さに応じて指数関数的に増加するため、最悪の場合、答えを見つけるまでに最大 26^k 個の可能性を探索します。 これは、小さな k の場合でもすぐに実行不可能になります。 

重要な点は、候補文字列を明示的に構築する必要がないということです。 代わりに、文字列内の任意の位置から、そこから始まる一致に失敗する可能性がある最も短い文字列は何か、という補足的な質問をすることができます。 すべてのサフィックスについて、不可能な最短のサブシーケンスがわかっていれば、動的プログラミングによって文字列全体の答えを構築できます。 

これを機能させる構造は、部分シーケンスのマッチングの単調な進行です。 最初の文字を修正すると、残る問題は一致後の文字列の接尾辞に限定されます。 これにより、重複するサブ問題が発生します。異なるパスが同じサフィックス位置に到達することがよくあります。 これは、ポジションに対する DP を示唆しており、状態はインデックス i から開始して実行できる最善の状態を表します。 

dp[i] が位置 i で始まるサフィックスの部分列ではない最短の文字列の長さである DP を定義します。 位置 i から、ある文字 c がサフィックスにまったく現れない場合、文字列 "c" はすでに即時に失敗するため、答えは単純に 1 になります。 それ以外の場合は、すべての文字がサフィックスのどこかで使用できるため、任意の 1 文字の文字列が有効になり、より長い構造を考慮する必要があります。 すべての文字を試し、次の文字にジャンプして、ステップを 1 つ追加します。 

標準の next 配列を使用して、次の出現位置を事前計算できます。これにより、O(1) での遷移が可能になります。 これにより、問題は O(n * 26) に縮小されます。

 ## アルゴリズムのチュートリアル

 各文字が次にどこに現れるかについての遷移情報を維持しながら、文字列を右から左に処理します。 

1. 次に出現するテーブル next[i][c] を構築します。このテーブルには、文字 c が出現する i 以降の最初の位置、または出現しない場合はセンチネル値が格納されます。 これにより、毎回文字列をスキャンすることなく、部分シーケンスの一致をシミュレートできます。 これが必要な理由は、サブシーケンスの遷移が中間文字ではなく、次の有効な位置のみに依存するためです。 
2. dp[i] を、位置 i から始まる部分列として形成できない最短の文字列の長さとして定義します。 直感的には、dp[i] は、i で始まるサフィックスを「エスケープ」するのがどれくらい難しいかを測定します。 
3. 位置 i にいて、next[i][c] が無効となるような文字 c が存在する場合、dp[i] は 1 になります。これは、すぐに c を選択して、最初のステップでサブシーケンスの一致に失敗する可能性があるためです。 
4. それ以外の場合、すべての文字がサフィックスのどこかに存在します。 その場合、文字 c ごとに next[i][c] + 1 に移動し、答えに 1 を加えます。 すべての文字の最小値を取得します。 これは、最初の文字を選択し、次の状態から最適に続行することで、不可能な最短の文字列を構築しようとすることを反映しています。 
5. 必要なときにすべての遷移がすでにわかっているように、文字列の末尾から dp を逆方向に計算します。 答えは dp[0] です。 

### なぜ効果があるのか

DP は、dp[i] がサフィックス i から始まるサブシーケンスとして一致しない文字列の最小長を正しく表すという不変式に依存します。 すべての遷移は、候補文字列の次の文字を固定し、次の実行可能な一致位置に進むことに正確に対応します。 部分シーケンスのマッチングは本質的に貪欲であり、常に可能な限り早い一致を取得するため、次のテーブルはすべての有効な継続を完全にキャプチャします。 これにより、dp[i] より短い候補は次の遷移までの有効なパスに対応し、dp[i] の定義に矛盾するため、より短い無効な文字列が見逃されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    alphabet = 26
    A = ord('a')

    next_pos = [[n] * alphabet for _ in range(n + 1)]

    last = [n] * alphabet

    for i in range(n - 1, -1, -1):
        last[ord(s[i]) - A] = i
        for c in range(alphabet):
            next_pos[i][c] = last[c]

    dp = [0] * (n + 1)
    dp[n] = 1

    for i in range(n - 1, -1, -1):
        best = float('inf')
        for c in range(alphabet):
            j = next_pos[i][c]
            if j == n:
                best = 1
                break
            best = min(best, 1 + dp[j + 1])
        dp[i] = best

    print(dp[0])

if __name__ == "__main__":
    solve()
```この実装では、各文字遷移が一定時間内に応答できるように、まず次出現テーブルが構築されます。 これにより、後続の実行可能性をチェックする際にスキャンを繰り返す必要がなくなります。 

dp 配列は逆方向に計算されるため、状態 i を評価するときに、すべての状態 j > i がすでにわかっています。 重要な点は、サフィックスに文字が欠落している場合の処理​​です。 この場合、単一文字の文字列はすでに失敗しているため、すぐに 1 を返します。 

もう 1 つの詳細は、「見つからない」ことを表すセンチネル値 n です。 私たちは一貫して j = n を故障状態として扱うため、境界処理が簡素化されます。
