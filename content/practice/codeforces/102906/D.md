 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、対応する 2 つの値の積に二乗素因数が含まれないように位置のペアを何組選択できるかを数えたいとします。 

条件を表現する別の方法は、素因数分解を調べることです。 少なくとも 2 の指数を伴う素数が現れない場合、その数値は「クリーン」です。 数値のペアについては、組み合わされた因数分解もクリーンな状態を維持する必要があります。これは、両方の数値にわたって合計で 2 回以上使用される素数がないことを意味します。 

したがって、有効なペアは 2 つの条件を同時に満たす必要があります。 まず、個々の数値はすでに二乗されていない必要があります。そうでない場合、その因数分解にはすでに二乗素数が含まれており、積は自動的に失敗します。 次に、2 つの数値は素因数を共有してはなりません。素数を共有すると、積内でその素数の指数が少なくとも 2 になるからです。 

入力は単なる整数のリストです。 出力は、上記のプロパティを持つインデックス ペアの数です。 

このタイプの問題に典型的な制約構造は、すべてのペアに対する二次チェックが遅すぎることを意味します。 配列サイズが 10^5 に達すると、すべてのペアに対する単純な O(n^2) スキャンには約 10^10 のチェックが必要になりますが、これは 2 秒の制限で処理できる範囲をはるかに超えています。 これにより、各数値の表現を圧縮し、互換性のあるペアを効率的にカウントする必要があります。 

数値に二乗因数が含まれる場合、微妙なエッジケースが発生します。 たとえば、4 と 9 のような値を考えてみましょう。両方とも個別に無効であるため、それらを含むペアは除外する必要があります。 もう 1 つのケースは、6 と 10 のように、2 乗を含まないが素数を共有する 2 つの数値で、どちらも素数 2 を含む場合です。その積には 2 の 2 乗が含まれるため、それぞれの数値が単独では許容できるように見えても、そのペアは無効になります。 

## アプローチ

 直接的なアプローチは、すべてのペアをチェックし、素因数分解を再計算するか、乗算と因数分解を行うことによって、その積が平方フリーであるかどうかをテストすることです。 これは条件を正確に適用するため論理的に機能しますが、その場で考慮すると、最悪の場合、各チェックのコストはおよそ O(sqrt A) になります。 n 要素の場合、これは約 O(n^2 sqrt A) となり、中程度の入力サイズでも使用できません。 

重要な観察は、条件が各数値に存在する素数のセットにのみ依存し、それらのセットが重複しているか内部に重複が含まれている場合にのみ依存するということです。 これは、各数値を正規表現、つまり素数が複数回出現しない限り、因数分解で 1 回だけ出現する素数のセットに圧縮することを示唆しています。 

すべての数値がそのようなマスクに変換されると、2 つの数値の間の条件は純粋に組み合わせになります。 必要なのは、マスクが互いに素であり、両方が有効であることを確認することだけです。 これにより、問題は交差のないサブセットのペアを数えることに変換されます。 

これに対処する標準的な方法は、同一のマスクをグループ化し、頻度をカウントすることです。 次に、有効なマスクごとに、競合しない以前に確認されたマスクとのみペアリングしたいと考えます。 これは、含まれる個別の素数の数が少ない場合はビットマスクの頻度マップを使用するか、マスクが素数のソートされたタプルとして保存されている場合はハッシュ マップを使用して実行できます。 

この問題群の典型的な制約では、10^6 または 10^7 程度までの数値には、数値ごとに管理可能な素数のセットのみが含まれるように値が制限されます。 最小の素因数のふるいを使用して各数値を 1 回因数分解し、重複する素因数を含む数値を破棄し、その縮小素因数集合を構築します。 次に、以前に確認された表現を反復処理し、交差をチェックすることによって、互換性のあるペアをカウントします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 √A) | お(1) | 遅すぎる |
 | 最適化 (因数分解 + ハッシュ) | O(n log A + K^2) 最悪の場合、通常は O(n log A) に近い | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、すべての数値を削減して、状態に関連する情報を正確に取得する構造にします。 

1. 配列内の最大値までの最小の素因数を事前計算します。 これにより、各数値を要素ごとに対数時間で高速に因数分解できます。 
2. 各数値について、最小の素因数表を使用して因数分解します。 因数分解中に、素数が複数回出現するかどうかを追跡します。 その場合、その数値は無効としてマークされ、後のカウントでは完全に無視されます。 
3. 数値が有効な場合、その個別の素数で構成される表現を構築します。 素数のセットのみが重要であるため、この表現は有効なペアに参加できるかどうかを一意に決定します。 
4. これらの表現から、すでに見た回数までの頻度マップを維持します。 
5. 新しい有効な数値表現ごとに、以前に保存された表現を繰り返し、2 つの素数のセットが交差するかどうかを確認します。 それらが交差しない場合は、それらの周波数の積を答えに追加します。 
6. 以前のグループとの互換性を処理した後、現在の表現の頻度を増やします。 

以前に確認されたグループに対してのみチェックを行う理由は、各ペアが正確に 1 回カウントされるようにするためです。 逆の順序でペアを再検討することはありません。 

### なぜ効果があるのか

 すべてのステップで、各数値は、因数分解で指数 1 とともに表示される素数の正確なセットに置き換えられるか、平方フリーでない場合は破棄されます。 2 つの数値は、それらの素数セットが互いに素である場合に限り、有効なペアを形成します。 このアルゴリズムは、そのようなセットのすべてのペアを 1 回だけ正確に列挙し、素性が維持される場合にのみカウントに追加します。そのため、有効なペアが見逃されることも、無効なペアが含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_spf(n):
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def factorize(x, spf):
    primes = []
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
            if cnt > 1:
                return None
        primes.append(p)
    return tuple(primes)

def disjoint(a, b):
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            return False
        if a[i] < b[j]:
            i += 1
        else:
            j += 1
    return True

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    mx = max(arr) if arr else 0

    spf = build_spf(mx)

    freq = {}
    ans = 0

    for v in arr:
        rep = factorize(v, spf)
        if rep is None:
            continue
        rep = tuple(sorted(rep))

        for k, cnt in freq.items():
            if disjoint(rep, k):
                ans += cnt

        freq[rep] = freq.get(rep, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数を構築するため、試行除算を行わずに各数値を迅速に分解できます。 因数分解ステップでは、素数を繰り返す数値を明示的に拒否するため、ソースで二乗自由性が強制されます。 

各表現はソートされた素数のタプルとして格納されるため、素数のチェックでは 2 ポインター スキャンが使用されます。 これにより、値ごとの素数の比較が線形に保たれますが、実際にはその数は少なくなります。 

頻度マップにより、ペアを再度検討することなく効率的に組み合わせをカウントできるようになります。 

## 実用的な例

 数値が含まれる入力を考えてみましょう。`[6, 10, 15]`。 彼らの因数分解は、`6 = {2,3}`、`10 = {2,5}`、`15 = {3,5}`。 

| ステップ | 現在 | 代表 | 周波数マップ | 追加されたペア |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | {2,3} | {} | 0 |
 | 2 | 10 | {2,5} | {6:1} | どれも素ではない |
 | 3 | 15 | {3,5} | {6:1、10:1} | (15,10)、(15,6) 部分的にフィルタリング |

 各ペアが共有素数を回避するため、(6,15) と (10,15) のみが有効です。 

このトレースは、アルゴリズムが純粋に交差構造に基づいてフィルタリングする方法を示しています。 

ここで考えてみましょう`[4, 3, 5, 6]`。 ここで 4 はすぐに破棄されます。 

| ステップ | 値 | 有効 | アクション | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | いいえ | スキップ | 0 |
 | 2 | 3 | はい | 周波数追加 | 0 |
 | 3 | 5 | はい | 3 とペア | 1 |
 | 4 | 6 | はい | 3 のみとペア | 2 |

 これは、二乗因数がどのようにして候補者を早期に排除するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、8 = 2^3 などの素数の繰り返しを含む数値です。 アルゴリズムはこれらを因数分解中に即座に拒否するため、周波数マップには決して入りません。 入力用`[8, 3, 5]`、有効な表現は次のとおりです。`{3}`そして`{5}`、アルゴリズムはそれらの間の 1 つのペアを正確にカウントします。 

もう 1 つの特殊なケースは、正方形のない同じ数字が繰り返されることです。 入力用`[6, 6]`、両方ともマップされます`{2,3}`。 それらの共通部分はそれ自体と空ではないため、アルゴリズムはペアのカウントを正しく回避します。これは、同一のインデックスは異なる出現間でのみペアにされるだけですが、依然として素条件を満たさないためです。
