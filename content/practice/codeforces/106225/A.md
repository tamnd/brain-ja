 ## 解決策
 ## 問題の理解

 私たちは、一連のドローンに割り当てられた一連のエネルギーレベルを与えられています。 各ドローンは整数値を保持しており、その値はさまざまな位置で繰り返すことができます。 しきい値 k もあり、安定した構成で同じエネルギー レベルを共有できるドローンの数を制限します。 

あるエネルギー値があまりにも多く出現する場合、具体的には k 回を超えて出現する場合、システムは全体的な調整ステップを実行します。 そのステップでは、配列内でその現在のエネルギー値が最初に出現したものではないすべてのドローンが識別され、そのようなすべてのドローンはエネルギーを正確に 1 増加させます。 「最初の出現」の概念は、各操作の後に常に現在の順序に基づいて計算されます。 

このプロセスは、エネルギー値が k 回を超えるまで繰り返されます。 必要な出力は、そのようなグローバル調整の数です。 

入力サイズにより、繰り返される全配列変換について慎重に考える必要があります。 すべてのテスト ケースで n が最大 2 · 10^5 であるため、各操作を素朴にシミュレートし、頻度と最初の出現を最初から再計算するソリューションは、操作の数が多いと困難になります。 各操作は n 個の要素すべてに触れる可能性があるため、テスト ケースあたり数千の操作でも、すでに TLE のリスクがあります。 

重要な微妙な点は、「以前に出現した場合にマークされる」が、頻度ベースではなく位置ベースであることです。 固定値 x の場合、現在の配列内で最初に出現する x のみが操作中に変更されず、その後出現するたびに増加します。 これにより、複製はチェーンのように動作し、1 回の操作内で左端のコピーのみが安定します。 

よくある間違いは、条件を「頻度 > k の場合、その値のすべての出現をインクリメントする」ものとして扱うことです。 最初以外の出現のみが影響を受け、この順序依存性がダイナミクスを駆動するものであるため、これは不正確です。 

別の障害モードは、部分的な更新後に「最初の発生」が正しく再計算されないことに起因します。 すべての増分はマーク付け後に同時に発生するため、順次インプレース更新を使用すると、最初の発生としてカウントされる内容が誤って変更されてしまいます。 

## アプローチ

 直接のシミュレーションは文字通りこのステートメントに従います。 操作ごとに、配列をスキャンし、確認された値のセットを維持し、最初以外のすべての出現をマークして、それらを増分します。 更新後、周波数を再計算するか、少なくとも値が k を超えているかどうかを確認します。 各操作のコストは O(n) であり、最悪の場合、操作の数も必要な最大値シフトに比例して増加する可能性があります。 たとえば、すべての要素が等しく開始される場合、各ステップでは要素が n − 1 個だけ増加するため、構造はゆっくりと上向きに「伸張」します。 これにより、大規模な更新チェーンが発生する可能性があり、単純なシミュレーションが 2 次またはさらに悪化する可能性があります。 

重要な観察は、システムが完全に重複によって駆動されており、重複は、最初に出現したものではない位置をすでにインクリメントした回数によって制御されるということです。 値の最初の出現は、特定のステップでその値に対して移動しないアンカーとして機能し、他のすべてのコピーは伝播に寄与します。 

すべての操作後に正確な配列の状態を追跡する代わりに、各値が最初に出現した後、重複として何回「アクティブ化」されたかを追跡できます。 各操作により、質量が複製位置から 1 レベル上に効果的にシフトされます。 重要なのは個々の位置ではなく、現在の値が最初に出現しない要素の数です。 

各値 x は出現の連鎖があるものとして再解釈できます。 最初の出現は安定しており、残りの出現は、操作ごとに 1 レベル上に移動する「過剰トークン」のプールとして動作します。 最初の出現を含む合計 k 個を超えるトークンがどのレベルにも蓄積されない場合、プロセスは停止します。

これにより、各値レベルで現在「アクティブな重複」になっている要素の数と、それらがどのように上方に伝播するかを追跡する問題が軽減されます。 操作の合計数は、合計数が k を超えるレベルがまだ残っている回数と正確に一致し、各操作により超過が制御された方法で削減されます。 

これを効率的に実装する実際的な方法は、値によって圧縮し、カウント構造を使用してレベル間の周波数の変化のみをシミュレートすることです。 値は 2n で制限され、各操作は重複を +1 ずつ上方に移動するだけであるため、カウントをレベルごとに処理し、k を超えて余剰を蓄積して前に進めることができます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 このアイデアは、現在各エネルギー レベルに存在するドローンの数を維持し、k を超える余剰分を繰り返し押し上げることです。 

1. すべてのエネルギー値の初期周波数を数えます。 これにより、現在各レベルを占有しているドローンの数がわかります。 
2. 各エネルギー レベル x について、このレベルに存在する「過剰なドローン」の数を計算し、max(0, freq[x] − k) として定義します。 これらはまさに、このレベルがアクティブな最初の作戦でマークされるドローンです。 
3. 過剰分の上方への伝播をシミュレーションします。 以前の増分によりレベル x に到着する追加のドローンの数を表す配列またはマップ add[x] を維持します。 レベル x における有効周波数は、freq[x] + add[x] です。 
4. レベルは昇順に処理されます。 各レベル x で、実効周波数を再計算します。 k を超える場合は、余剰 s = 有効 − k を決定します。 その余剰分は、この作戦で増加するドローンに相当します。 
5. すべての s の余剰ドローンは、add[x + 1] を s ずつ増やすことによってレベル x + 1 に移動します。 また、少なくとも 1 つのレベルでバランシング操作がトリガーされたため、操作カウンターも 1 回インクリメントします。 
6. 値は増加するだけなので、影響を受ける可能性のある最大レベル (2n + 操作数で制限される) に達するまで続行します。 
7. 最終的な答えは、この伝播プロセス中に実行された操作の合計数です。 

重要なのは、配列全体を決してシミュレートしないということです。 余剰質量が整数レベル全体でどのように流れるかをシミュレーションするだけです。 

### なぜ効果があるのか

 いつでも、操作が発生する唯一の理由は、あるレベルに k 個を超えるアクティブな代表者がいるということです。 操作は、どの特定のドローンが関与しているかには依存せず、最初以外のドローンがどれだけ存在するかによってのみ決まります。 インクリメントでは常に最初に出現した順序が保持され、重複のみが上方にシフトされるため、システムは余剰カウントの流れとして決定論的に進化します。 各操作により、特定のレベルの過剰が削減され、厳密に上方に押し上げられるため、後方への影響は生じません。 これにより、このプロセスは、値の昇順で過剰なビンを繰り返し解決することと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        maxv = 2 * n + 5
        freq = [0] * (maxv + 1)
        for x in a:
            freq[x] += 1

        add = [0] * (maxv + 1)
        ops = 0

        for x in range(1, maxv):
            cur = freq[x] + add[x]
            if cur > k:
                surplus = cur - k
                add[x + 1] += surplus
                ops += 1

        print(ops)

if __name__ == "__main__":
    solve()
```この解決策は、考えられるすべてのエネルギー レベルにわたる周波数配列を構築することから始まります。 上限は 2n にバッファを加えたものとして安全に選択されます。これは、各操作によって値がステップごとに最大 1 レベルだけ上に押し上げられることがあり、意味のある遷移が最大で O(n) であるためです。 

加算配列には、下位レベルから伝播された余剰が格納されます。 レベルを処理するとき、元の周波数と入ってくる余剰を組み合わせて、真の占有率を取得します。 k を超える場合は、どれだけの要素を上に押し上げる必要があるかを計算し、それらを次のレベルに蓄積します。 

操作カウンタは、プッシュをトリガーするレベルごとに 1 回増加します。 これは、プロセスにおける 1 つのグローバル バランシング ステップに相当します。 

微妙な点は、以前のレベルに戻る必要がないということです。 一度上に押し上げられた余剰は下に戻ることはないため、左から右へのスイープを 1 回行うだけで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import sys
    input = sys.stdin.readline
    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []
    for _ in range(t):
        n, k = map(int, (data[idx], data[idx+1]))
        idx += 2
        a = list(map(int, data[idx:idx+n]))
        idx += n

        maxv = 2 * n + 5
        freq = [0] * (maxv + 1)
        for x in a:
            freq[x] += 1

        add = [0] * (maxv + 1)
        ops = 0

        for x in range(1, maxv):
            cur = freq[x] + add[x]
            if cur > k:
                surplus = cur - k
                add[x + 1] += surplus
                ops += 1

        out.append(str(ops))

    return "\n".join(out) + "\n"

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が異なる場合です。 その状況では、k = 1 であっても値が k を超えることはないため、アルゴリズムによって余剰がトリガーされることはありません。 スイープではどこでも有効周波数 1 が検出され、更新は実行されず、操作は生成されません。 

もう 1 つのケースは、すべての要素が同一で、k が小さい場合です。 k = 1 の入力 [1,1,1,1] の場合、最初のレベルで余剰 3 が生成され、レベル 2 にプッシュされます。レベル 2 では、同じ余剰が再度処理されて別の操作が作成され、余剰チェーンが完全に分散するまでこれが繰り返されます。 このアルゴリズムは、オーバーフローが存在するレベルごとに 1 つの操作を自然にカウントし、予想される繰り返しのバランス動作に一致します。 

最後の微妙なケースは、k がすべての重複を吸収するのに十分な大きさである場合です。 たとえ値がクラスター化していても、レベルが k を超えない限り、加算伝播がアクティブになることはなく、システムは初期スキャンの直後に安定します。
