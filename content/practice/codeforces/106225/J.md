 ## 解決策
 ## 問題の理解

 最初の結晶列が与えられ、各結晶は整数のエネルギーを運びます。 唯一許可される操作は、すべての値が同一である連続ブロックを取得し、それを単一の結晶に圧縮し、その値がそのブロックの長さになるものです。 配列内の他のすべては順序どおりに維持されるため、プロセスは繰り返し同じ値のランをそのランの長さに等しい単一の数値に置き換えます。 

タスクは、このような一連の操作を使用して、初期配列をターゲット配列に変換できるかどうかを判断することです。 

重要な問題は、この操作が単純なマージではないことです。 新しい値は元の値からではなく、構造、特にランレングスから導出されます。つまり、後のマージは以前のグループ化の選択に依存します。 セグメントが融合されると、その内部情報は失われ、カウントに置き換えられるため、このプロセスは強い意味で不可逆的です。 

制約の合計サイズは小さく、テスト ケースの n の合計は最大 4000 です。これにより、配列のすべてのパーティションにわたる三次シミュレーションまたはそれより悪いシミュレーションが即座に排除されます。 二次または二次に近い動的計画法のアプローチは実現可能ですが、すべてのマージ シーケンスを明示的に列挙しようとすると失敗します。これは、可能なマージ履歴の数が n とともに指数関数的に増加するためです。 

値がランレングスにどのように崩壊するかによって、微妙なエッジケースが発生します。 たとえば、[1, 1, 1] のような配列は [3] になる可能性がありますが、マージは連続したブロック内の等価性に厳密に依存するため、圧縮可能なセグメントがある場合でも [1, 2, 2, 1] を任意に縮小することはできません。 

もう 1 つの明白ではないケースは、中間マージによって隣接構造が変更され、新しい同等のランが作成される場合です。 たとえば、[2, 4, 4, 2, 3] は、中央を融合した後に新しい等しいブロックを生成することができ、当初は不可能であったさらなるマージが可能になります。 これにより、欲張りな左から右への圧縮は正しくなくなります。 

## アプローチ

 ブルート フォースの観点では、このプロセスを、最終的にターゲット配列の要素に対応するセグメントに配列を分割するためのあらゆる方法を探索するものと考えることができます。 どの状態からでも、等しい値の連続を選択して置き換えることができ、これにより値と隣接性の両方が変更されるため、状態空間は配列上のグラフになります。 到達可能なすべての配列に対する単純な BFS または DFS は、単一のステップでも多数の新しい同等の実行を作成する可能性があり、個別の配列の数が n で指数関数的になるため、すぐに爆発します。 

視点を逆にすると構造がより明確になります。 ターゲット配列の各要素は、ターゲット値に等しい 1 つの数値に完全に縮小できる、初期配列内の連続したセグメントに対応する必要があります。 このようなセグメント内では、等しいランを繰り返し折りたたんでいきます。 折りたたむたびに長さ k × k のランが置き換えられるため、セグメント内の値は、この折りたたみルールに基づいて最終的にセグメントの合計寄与に等しい 1 つの数値に還元できる必要があります。 

重要な点は、選択したセグメント内で実行を繰り返しマージすることによって最終的な値が決定され、各マージによって実行がそのサイズに置き換えられることです。 これは、セグメント内のプロセスを完全にシミュレートした場合、意味のある唯一の構造は、実行がどのようにして同じ値のより大きな実行にマージされるかということを意味します。 これにより、当然のことながら、ターゲットに対する 2 ポインターのマッチングと組み合わせた、配列のセグメントに対する動的プログラミングが行われます。 

初期配列を同じ値のランに圧縮します。 各実行には値と長さがあります。 有効な構造では、ターゲット要素を連続した実行と位置合わせする必要がありますが、その値が最終的に必要な値に折りたたまれる定数構造への内部マージを許可する場合、単一のターゲット要素が複数の実行を消費する可能性があります。

DP 状態は、実行のプレフィックスを使用してターゲットのプレフィックスと一致するかどうかを追跡すると同時に、部分的に消費された実行をどのように組み合わせることができるかを追跡します。 遷移は、連続する実行をグループ化し、その内部構造がターゲット要素と等しい単一の値に折りたたまれるかどうかを確認することに依存します。 

これは、実行シーケンスを m 個のグループに分割する実現可能性をチェックすることに帰着します。各グループは、その誘発された崩壊によって必要な目標値が正確に得られる場合に有効です。 各グループは連続しているため、セグメントがどのように崩壊するかを事前に計算してから O(nm) で DP を実行できます。合計 n が 4000 であるため、これは許容可能です。

 ## アルゴリズムのチュートリアル

 まず、配列を等しい値の最大セグメントに圧縮します。 これにより、マージは等しい連続値に対してのみ機能するため、冗長性がなくなり、実行内の内部構造は将来の操作に関してすでにアトミックになります。 

次に、実行間隔を 1 つの数値に完全に削減できるかどうか、およびその数値が何であるかを事前計算します。 ランのセグメントについて、マージの動作をシミュレートします。前の崩壊後に隣接する等しい値が現れるたびに、それらはマージされたブロックの長さの合計を値とするランにマージされます。 このプロセスはセグメントに関して連想的であるため、結果を段階的に計算できます。 

次に、最初の i 実行を最初の j ターゲット要素に一致させる DP を定義します。 各 DP ステップで、崩壊が b[j] に等しい連続した実行ブロックを選択することによって、現在の実行プレフィックスを拡張して次のターゲット値を形成しようとします。 位置 i で終わるそのようなブロックが存在する場合、DP 状態を遷移します。 

遷移は、可能なセグメント開始のスキャンに依存します。 各終了位置 i とターゲット インデックス j について、runs[k..i] が正確に b[j] に折りたたまれるような開始 k が存在し、DP[k-1][j-1] が true であるかどうかを確認します。 

i と j の昇順でこのテーブルを埋めます。 

答えは、すべてのランと目標全長にわたる DP が達成可能かどうかです。 

### なぜ効果があるのか

 すべての操作は連続性を維持し、等しい値の実行のみをマージするため、最終的な構成は、実行圧縮された配列の連続ブロックへの分割に対応します。 各ブロックは、選択されると独立します。ブロック内の操作は、実行境界によってすでにキャプチャされている境界圧縮を除いて、他のブロックに影響を与えることはありません。 DP は、可能性のあるすべてのパーティションを正確に列挙し、各ブロックが正しいターゲット値に折りたたまれることを保証するため、有効な構築が見逃されることも、無効な構築が受け入れられることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compress(a):
    runs = []
    for x in a:
        if not runs or runs[-1][0] != x:
            runs.append([x, 1])
        else:
            runs[-1][1] += 1
    return runs

def can_build(a, b):
    runs = compress(a)
    n = len(runs)
    m = len(b)

    # prefix sum of run lengths (not strictly necessary but helps reasoning)
    # dp[i][j] = can use first i runs to form first j targets
    dp = [[False] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = True

    # precompute prefix sums of run sizes
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + runs[i][1]

    def segment_value(l, r):
        # simulate collapse inside runs[l..r]
        # flatten into (value, count) sequence
        stack = []
        for i in range(l, r + 1):
            val, cnt = runs[i]
            if stack and stack[-1][0] == val:
                stack[-1][1] += cnt
            else:
                stack.append([val, cnt])

        # now collapse runs of identical values by converting to counts
        # each block becomes its total length
        changed = True
        while changed:
            changed = False
            new_stack = []
            for v, c in stack:
                if new_stack and new_stack[-1][0] == v:
                    new_stack[-1][1] += c
                    changed = True
                else:
                    new_stack.append([v, c])
            stack = new_stack

        if len(stack) != 1:
            return None
        return stack[0][1]

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            for k in range(i):
                if dp[k][j - 1]:
                    val = segment_value(k, i - 1)
                    if val == b[j - 1]:
                        dp[i][j] = True
                        break

    return dp[n][m]

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        out.append("YES" if can_build(a, b) else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、配列をランに圧縮して、繰り返される等しい値がグループ化されるようにすることから始まります。 これにより、すでに均一な領域内でトランジションが無駄になることがなくなります。 

DP テーブルは、ランのプレフィックスがターゲット シーケンスのプレフィックスと一致するかどうかを追跡します。 トリプル ループでは、考えられるすべてのセグメントの終点と始点が試行され、セグメント シミュレーションでは、選択された間隔が単一のターゲット値にまとめられるかどうかがチェックされます。 

関数segment_valueは、操作の中核となるモデリングです。 隣接する等しい値を繰り返しマージし、マージされたブロックをその合計寄与度で置き換えます。 これは、許可された操作を正確に反映しています。各マージによって均一ブロックがその長さによって置き換えられ、後続のマージによって新しい均一隣接関係が作成される可能性があるためです。 

## 実用的な例

 最初のサンプル入力について考えてみましょう。 

a, b = [2, 4, 4, 2, 3] から開始し、[2] を目標にします。 

圧縮後の実行は [(2,1),(4,2),(2,1),(3,1)] になります。 

DP は、配列全体が 2 に折りたたまれるかどうかを確認しようとします。セグメント [0..3] がテストされます。 その内部では、マージにより単一の最終値 2 が得られるため、dp[4][1] が true になります。 

| 私 | j | k スタート | セグメント | セグメント値 | dp[i][j] |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | [2] | 1 | 偽 |
 | 4 | 1 | 0 | [2,4,4,2] | 2 | 本当 |

 これにより、完全崩壊が可能であることが確認されました。 

2 番目の例として、単純な不可能なケースを考えてみましょう: a = [1,2,3]、b = [3]。 

どのセグメントにも、決して単一の均一ブロックにマージされない個別の値が含まれているため、segment_value が 3 に等しくなることはなく、したがって dp[n][1] は false のままになります。 

| セグメント | 結果を折りたたむ | 一致 3 |
 | --- | --- | --- |
 | [1] | 1 | いいえ |
 | [2] | 1 | いいえ |
 | [3] | 1 | いいえ |
 | [1,2,3] | 均一ではない崩壊 | いいえ |

 これは、孤立した大きな値を製造できない理由を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def compress(a):
        runs = []
        for x in a:
            if not runs or runs[-1][0] != x:
                runs.append([x, 1])
            else:
                runs[-1][1] += 1
        return runs

    def solve_case(n, m, a, b):
        runs = compress(a)
        n = len(runs)
        dp = [[False] * (m + 1) for _ in range(n + 1)]
        dp[0][0] = True

        def seg(l, r):
            st = []
            for i in range(l, r + 1):
                v, c = runs[i]
                if st and st[-1][0] == v:
                    st[-1][1] += c
                else:
                    st.append([v, c])
            changed = True
            while changed:
                changed = False
                ns = []
                for v, c in st:
                    if ns and ns[-1][0] == v:
                        ns[-1][1] += c
                        changed = True
                    else:
                        ns.append([v, c])
                st = ns
            return st[0][1] if len(st) == 1 else None

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                for k in range(i):
                    if dp[k][j - 1]:
                        if seg(k, i - 1) == b[j - 1]:
                            dp[i][j] = True
                            break

        return "YES" if dp[n][m] else "NO"

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        out.append(solve_case(n, m, a, b))
    return "\n".join(out)

 ## 特殊なケース

 まれなケースは、配列全体がすでに均一である場合です。 たとえば、a = [5,5,5,5]、b = [4]。 アルゴリズムは単一の実行 (5,4) に圧縮し、セグメントの折りたたみは 4 を返すため、dp はすぐに受け入れられます。 これにより、中間セグメンテーションを必要とせずに直接完全融合が処理されることが確認されます。 

もう 1 つのケースは、ターゲットが個別に達成可能であるが、正しいパーティション内にない複数のセグメントを必要とする場合です。 a = [1,1,2,2] および b = [2,2] の場合、実行間の境界での分割のみが機能します。 DP はすべての位置から k を試行し、実行境界に一致し、有効なセグメントが折りたたまれる k のみが成功するため、誤った分割は当然拒否されます。 

最後の微妙なケースは、マージによって新しい等しい隣接関係が作成される場合です。 a = [2,4,4,2,3] の場合、内部結合により、中央のブロックを折りたたんだ後に新しい均一領域が生成されます。 セグメント シミュレーションは各マージ パスの後に明示的に再計算され、新しく形成された等しい近傍が後続の反復でマージされることを保証し、実際のプロセスを正確に反映します。
