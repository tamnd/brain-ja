 ## 解決策
 ## 問題の理解

 ゲーム レベル内の一連の敵の種類を表す長い文字列が与えられます。 各クエリはこの文字列の連続したセグメントを選択します。そのセグメントについて、その内部の部分文字列がどの程度反復されるかを測定する必要があります。 

固定文字列の場合、考えられるすべての部分文字列がその中に何度か出現します。 まず、すべての部分文字列の中で発生する可能性のある最大数を特定します。 次に、この最大頻度を達成する部分文字列のみに注目し、その中で最大長を取得します。 この値は、問題で LFS 値と呼ばれるものです。 

クエリ セグメントごとに、誘導された部分文字列でこの値を再計算します。 

主な問題点は、定義の両方の部分がプレフィックスやサフィックスだけでなく、すべての部分文字列に対してグローバルであることです。 この関数は部分文字列の完全な内部構造に依存しており、同じサイズの文字列に対する最大 50 万件のクエリに応答する必要があります。 

単純なアプローチでは、各クエリ セグメントのすべての部分文字列を列挙して出現回数をカウントしますが、長さ n の単一セグメントにはすでに O(n²) 個の部分文字列があり、その頻度をカウントするのはさらに高価であるため、これは直ちに不可能です。 

2 番目の単純な考えは、最も頻繁に出現する部分文字列が常に 1 文字であると仮定することですが、これは誤りです。 たとえば、「abab」では「a」と「ab」の両方が 2 回出現するため、最良の答えはより長い構造化された部分文字列によって決まります。 

繰り返しが周期的ではあるが均一ではない場合、より微妙な失敗のケースが発生します。 「abcabcab」では、最も頻繁に使用される部分文字列は、単一の文字ではなく、繰り返されるパターン「abc」に由来します。 問題を文字の頻度のみに限定する解決策では、これらのケースは見逃されます。 

したがって、主な課題は、ダイナミック レンジをサポートしながら、繰り返される部分文字列を効率的に推論する必要があることです。 

この制約は、小さなアルファベットで償却されるクエリごとにおよそ O((n + q) log n) または線形に近い値が必要であること、および部分文字列の列挙に対する二次的な動作を避ける必要があることを示唆しています。 

## アプローチ

 ブルート フォース手法では、各クエリ セグメントのすべての部分文字列を構築し、ハッシュまたは直接比較を使用して出現回数をカウントします。 部分文字列の比較が O(1) の場合でも、長さ m のクエリ セグメントごとに Θ(m²) 個の部分文字列があり、最大 5·10⁵ のクエリが存在するため、これは完全に実行不可能になります。 

重要な点は、文字列内の部分文字列の最大頻度は常に、単一の文字の出現に合わせて整列された部分文字列によって達成されるということです。 これにより、問題の構造が大幅に軽減されます。すべての部分文字列を検索する代わりに、固定文字の出現に部分文字列がどのように伝播するかを推論するだけで済みます。 

文字を修正する c. クエリセグメント内で c が出現するすべての位置を調べるとします。 c が出現するたびに部分文字列が 1 回出現する場合、その頻度は正確に c の出現数になります。 さらに、この最大頻度を達成するサブストリングは、これらの出現すべてにわたって一貫して整列する必要があります。 

これにより、問題は、同じ文字が連続して出現する間のセグメントを研究することに変わります。 文字 c を取得し、クエリ セグメント内のその出現位置をリストすると、各出現はその位置から始まり、次の出現の直前 (またはクエリ セグメントの終わり) で終わるセグメントを定義します。 部分文字列が正確に f 回 (f は c の頻度) 出現するには、その部分文字列がこれらすべてのセグメントの共通の接頭辞として出現する必要があります。 

したがって、各文字について、候補となる答えは、これらすべての出現セグメントの中で最も長い共通プレフィックスになります。 クエリの最終的な答えは、クエリ セグメント内のすべての文字の最大値です。

任意のサフィックス セグメント間の最長の共通プレフィックスを効率的に計算するために、LCP RMQ 構造を持つサフィックス配列を使用します。 これにより、前処理後に O(1) 内の任意の 2 つのサフィックスの LCP をクエリできるようになります。 

残りの課題は、範囲内の各文字の出現を迅速に抽出し、それらのセグメント制約を効率的に結合することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(クエリごとの n²) | O(n²) | 遅すぎる |
 | サフィックス配列 + クエリごとの文字スイープ | O(26 · k log n) 最悪の場合 | O(n) | 実際に受け入れられる |

 ## アルゴリズムのチュートリアル

 文字列全体のサフィックス配列とその LCP 配列に対する RMQ 構造を構築して、任意の 2 つのサフィックス間の LCP を定数時間で計算できるようにします。 

また、文字ごとに、その出現位置のソートされたリストも保存します。 

各クエリ セグメント [l, r] について、各文字を個別に処理します。 

1. 文字 c の場合、位置リストの二分探索を使用して、[l, r] 内の c のすべての位置を抽出します。 これらの位置を p₁ < p₂ < … < p_k とします。 この文字の周波数 f は k です。 
2. k が 0 または 1 の場合、この文字は繰り返し構造を生成できないため、スキップします。 
3. これらの位置について、k 個のセグメントを定義します。各セグメントは p_i で開始し、p_{i+1} − 1 (i < k) で終了し、最後のセグメントは r で終了します。 
4. これらすべてのセグメントに共通する最長のプレフィックスを取得して、候補の長さを計算します。 最初のセグメントを使用して、この文字の答えを初期化します。 
5. 後続のセグメントごとに、サフィックス配列 LCP クエリを使用して、p_i で始まるサフィックスと p_1 で始まる最初のセグメントの間の LCP を計算します。 また、有効な境界を超えないように、この値をセグメントの長さによってクランプします。 すべてのセグメントにわたって最小限を維持します。 
6. 結果の最小値が、この文字の最適な長さになります。 
7. すべての文字の最大値を取得して出力します。 

### なぜ効果があるのか

 固定クエリ セグメント内では、正確に f 回現れる部分文字列は、頻度が f である文字 c のすべての出現と一致する必要があります。 このような部分文字列は c が出現するたびに開始する必要があります。そうしないと、少なくとも 1 つの出現が欠落し、その頻度が f を下回ります。 

アライメントが修正されると、部分文字列は出現ベースのすべてのセグメントにわたって同一である必要があり、これにより、条件がそれらのセグメントにわたる最長の共通プレフィックス制約に減ります。 サフィックス配列の LCP 構造は、任意の 2 つの位置間の等価性とプレフィックスの比較が定数時間内に正しく計算できることを保証するため、計算された最小プレフィックス長は、すべての出現箇所で繰り返される最長の部分文字列を正確に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# ---------- Suffix Array (doubling) ----------
def build_sa(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = list(map(ord, s))
    tmp = [0] * n

    while True:
        sa.sort(key=lambda x: (rank[x], rank[x + k] if x + k < n else -1))

        tmp[sa[0]] = 0
        for i in range(1, n):
            prev = sa[i - 1]
            cur = sa[i]
            tmp[cur] = tmp[prev] + (
                (rank[cur], rank[cur + k] if cur + k < n else -1)
                != (rank[prev], rank[prev + k] if prev + k < n else -1)
            )

        rank, tmp = tmp, rank
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa, rank

def build_lcp(s, sa, rank):
    n = len(s)
    k = 0
    lcp = [0] * (n - 1)

    for i in range(n):
        if rank[i] == 0:
            continue
        j = sa[rank[i] - 1]
        while i + k < n and j + k < n and s[i + k] == s[j + k]:
            k += 1
        lcp[rank[i] - 1] = k
        if k:
            k -= 1

    # RMQ sparse table
    import math
    LOG = (n - 1).bit_length()
    st = [lcp[:]]
    for j in range(1, LOG):
        prev = st[-1]
        cur = [0] * (n - 1 - (1 << j) + 1)
        for i in range(len(cur)):
            cur[i] = min(prev[i], prev[i + (1 << (j - 1))])
        st.append(cur)

    log = [0] * (n)
    for i in range(2, n):
        log[i] = log[i // 2] + 1

    return sa, rank, lcp, st, log

def get_lcp(x, y, sa, rank, st, log):
    if x == y:
        return float('inf')
    n = len(sa)
    rx, ry = rank[x], rank[y]
    if rx > ry:
        rx, ry = ry, rx
    rx += 1
    length = ry - rx
    j = log[length]
    return min(st[j][rx], st[j][ry - (1 << j)])

# ---------- Solve ----------
n, q = map(int, input().split())
s = input().strip()

sa, rank, lcp, st, log = build_lcp(s, *build_sa(s))

pos = [[] for _ in range(26)]
for i, c in enumerate(s):
    pos[ord(c) - 97].append(i)

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1

    ans = 1

    for c in range(26):
        arr = pos[c]
        # find range of occurrences in [l, r]
        import bisect
        i = bisect.bisect_left(arr, l)
        j = bisect.bisect_right(arr, r)
        if j - i <= 1:
            continue

        base = arr[i]
        best = r - base + 1

        for t in range(i + 1, j):
            cur = arr[t]
            best = min(best, get_lcp(base, cur, sa, rank, st, log))
            if best == 0:
                break

        ans = max(ans, best)

    print(ans)
```サフィックス配列を構築した後、プログラムは任意の 2 つのサフィックス間の高速 LCP クエリをサポートします。 次に、各クエリはセグメント内の各文字の位置に注目を限定し、それらの位置を使用して共通のプレフィックス長を制限します。 

内側のループは、候補プレフィックスがゼロになるとそれ以上の改善は不可能であるため、早期に停止するように慎重に構造化されています。 

## 実用的な例

 ### 例 1

 入力セグメントは`ababa`、クエリ付き`[1, 5]`。 

| キャラクター | 出来事 | 周波数 | 候補セグメント | 結果 |
 | --- | --- | --- | --- | --- |
 | | 1,3,5 | 3 | 「アバ」、「アバ」、「ア」 | 1 |
 | b | 2,4 | 2 | 「バブ」、「バ」 | 1 |

 最大頻度はキャラクターから 3 です`a`。 セグメント全体で共通のプレフィックスは次のとおりです。`"a"`, したがって、答えは 1 です。 

これにより、たとえより長い繰り返しパターンが局所的に存在しても、すべての出現にわたる位置合わせによって使用可能な長さが制限されることが確認されます。 

### 例 2

 入力文字列は`aaaaaaaaaa`。 

| キャラクター | 出来事 | 周波数 | 候補セグメント | 結果 |
 | --- | --- | --- | --- | --- |
 | | 1..10 | 10 | すべてのセグメントが同一 | 10 |

 で始まるすべてのセグメント`a`は同一であるため、共通のプレフィックスは完全なサフィックスに及びます。 答えは10です。 

これは、最大繰り返しが完全な均一性と一致する場合を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | スペース | O(n log n) | サフィックス配列構造と RMQ テーブル |

 ## 特殊なケース

 単一文字の文字列は最も単純なケースです。唯一の部分文字列は文字自体であるため、頻度は 1 で、LFS は 1 です。アルゴリズムはこれを処理します。これは、各文字ループで正確に 1 つの出現が検出されるため、その文字列はスキップされ、デフォルトの応答は 1 のままです。 

次のような完全に均一な文字列`aaaaaa`が出現するたびに同一のセグメントを生成します。`a`。 すべての LCP 比較では残りの完全な長さが返されるため、最小値は最大値のままとなり、最終的な答えはセグメント全体の長さに等しくなります。 

のように高度に交互に配置される文字列`abababab`複数のキャラクターが頻度を競うことを保証します。 アルゴリズムは両方の文字を正しく評価し、それらのセグメント制約を個別に比較して、最適な有効な繰り返し構造を選択します。
