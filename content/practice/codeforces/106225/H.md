 ## 解決策
 ## 問題の理解

 ゲームはボスの健康状態から始まります。`n`。 2 人のプレイヤーが交互に攻撃し、あなたが先に動きます。 すべての攻撃は、次の間隔で一定の整数ダメージを与えます。`1`そして`m`。 唯一の制限は、プレイヤーが直前のターンに対戦相手が使用した金額を繰り返すことはできないことです。 健康状態をプラスにしない人がすぐに勝ちます。 

各テスト ケースについて、2 番目のプレーヤーが常に最適に応答すると仮定して、最初のプレーヤーが勝利を保証する戦略を持っているかどうかを判断する必要があります。 

両方の値`n`そして`m`到達できる`10^6`、まであるかもしれません`10^4`テストケース。 これらの値の合計には制限がないため、次の値に比例した処理を実行するアルゴリズムはすべて`n`または`m`どのケースも高額になりすぎるからです。 一定時間の決定ルールが必要です。 

誤って対処しやすい状況がいくつかあります。 

1つ目は、ボスがすでにすぐに倒せる場合です。```
n = 6, m = 9
```答えは`YES`、最初のプレイヤーは単純にダメージを与える可能性があるため`6`、`7`、`8`、 または`9`。 

2 番目の微妙なケースは次の場合に発生します。`m = 2`。```
n = 69, m = 2
```答えは`NO`。 1人のプレイヤーが使用すると、`1`、もう一方は使用する必要があります`2`、その場合、最初のものは使用する必要があります`1`またまた、など。 一連の動きは完全に強制的になります。 多くの選択肢が常に利用可能であると仮定する素朴なアプローチは、ここでは失敗します。 

もう 1 つの注意が必要なケースは次のような場合です。`n`は正確に割り切れます`2m`。```
n = 20, m = 10
```答えは`YES`、 ない`NO`。 それでも`20`の倍数です`20`、最初のプレイヤーは次の方法で攻撃できます。`10`、健康を離れる`10`、ボブの移動後、最初のプレイヤーは再び使用できるようになります。`10`なぜなら、ボブの以前の攻撃だけが禁止されているからです。 

最後の手を覚えておらずに、ゲームを通常の引き算としてモデル化しようとする不注意な試みは、不正確な結果を生み出すでしょう。 

## アプローチ

 最も直接的なアプローチは、残りの体力と前のターンに使用したダメージによって状態を記述することです。 このような状態から、すべての法定ダメージ値を試し、現在のプレイヤーが勝ち手を持っているかどうかをマークできます。 この再帰はゲーム ツリー全体を探索するため、正しいです。 

残念ながら、約`n × m`州。 両方の値が等しい場合`10^6`、これはおおよそになります`10^12`完全に不可能な状態です。 

ゲームの構造を見ると、さらに強力なパターンが明らかになります。 ターン間で保持される唯一の記憶は、対戦相手が以前に受けたダメージです。 プレイヤーが使用した場合`x`、次のターンではその正確な値はブロックされますが、他のすべての値は利用可能なままになります。 

連続する 2 つのターンを考えてみましょう。 1人のプレイヤーが取引をすると仮定します`a`そしてその他の取引`b`、 と`a ≠ b`。 次のターンでは、`a`再び合法になるのは、`b`は禁止されています。 したがって、2 つの移動ごとに正確に削除されます`a+b`同じペアが無限に繰り返される可能性があります。 

2 回の移動で除去できる最大量は次のとおりです。```
m + (m - 1) = 2m - 1
```なぜなら、2つの損害は異なるはずだからです。 

2 回の移動で除去できる最小量は次のとおりです。```
1 + 2 = 3
```いつ`m = 2`、より一般的には、別個の数値の任意のペア。 

小さな例を調べると、周期構造がすぐに明らかになります。 あらゆる長さのブロック`2m`同じように動作します。 負けているポジションはまさに以下のポジションです。```
n mod (2m) = 1
```いつ`m > 2`。 

ケース`m = 2`は特別です。 移動シーケンスは強制的に交互に実行されます。`1`そして`2`したがって、3 つのヘルス ポイントごとに 1 つの完全なサイクルが対応します。 この場合、損失ポジションは正確に次のとおりです。```
n mod 3 = 0
```ブルート フォースは、勝ち負けの状態を明示的に計算するため機能しますが、状態の数が多すぎるため失敗します。 ゲームが最終的には単純なモジュール パターンで繰り返されるという観察により、状態グラフ全体を定数時間の式に置き換えることができます。

 | ブルートフォース | O(nm) | O(nm) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. もし`m = 2`、どうかを確認してください`n`で割り切れます`3`。 
3. いつ`n % 3 == 0`、出力`NO`、交互のシーケンスなので、`1,2,1,2,...`が強制され、2 番目のプレーヤーが最後の動きをします。 
4. それ以外の場合は出力`YES`。 
5. もし`m > 2`、計算する`n % (2m)`。 
6. 余りが等しい場合`1`、出力`NO`。 
7. 残りを 1 つおきに出力します。`YES`。 

ステップ 6 の背後にある理由は、ブロックが完了するたびに、`2m`ヘルスポイントが減少すると、同じ状況が再現されます。 残りの`1`プレイヤーがヘルスと同じタイプの位置に面して移動することを意味します`1`、対戦相手はいつでもその構造をミラーリングし、最終的に最後の攻撃を得ることができます。 

### なぜ効果があるのか

 のために`m > 2`、位置をピリオドで繰り返します`2m`。 完全な 1 つの期間のうち、正確に残りがある状態`1`負けています。 このような状態からのすべての合法的な手は勝利状態に達しますが、他のすべての状態には残りにつながる少なくとも 1 つの手があります。`1`。 

のために`m = 2`、相手の以前の攻撃を繰り返すことが禁止されているため、ダメージの順序は交互に行われます。`1`そして`2`。 体力が 3 ポイントごとに 1 サイクルが消費されるため、3 の倍数では最初のプレイヤーが負けることになります。 

すべてのポジションが正しく分類され、ゲームでは体力が常に減少するため、アルゴリズムは常に正しい答えを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n, m = map(int, input().split())

    if m == 2:
        if n % 3 == 0:
            ans.append("NO")
        else:
            ans.append("YES")
    else:
        if n % (2 * m) == 1:
            ans.append("NO")
        else:
            ans.append("YES")

print("\n".join(ans))
```プログラムは各テスト ケースを独立して処理します。 

特別な場合`m = 2`が最初に来るのは、その動作が一般的なパターンとは完全に異なるためです。 交互に繰り返される攻撃の期間は 3 つだけです。 

より大きな値の場合、`m`、答えは剰余モジュロにのみ依存します。`2m`。 配列や再帰は必要ありません。 

よくある間違いは、剰余を使用することです`0`残りの代わりに`1`。 たとえば、`n = 20`そして`m = 10`、剰余モジュロ`20`は`0`、ポジションは勝ちです。 間違った剰余を使用すると、このケースが誤って分類される可能性があります。 

もう 1 つの簡単な間違いは、次のことを忘れることです`2 * m`係数を取得する前に計算する必要があります。 Python の整数には制限がないため、オーバーフローが問題になることはありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())

        if m == 2:
            ans.append("NO" if n % 3 == 0 else "YES")
        else:
            ans.append("NO" if n % (2 * m) == 1 else "YES")

    return "\n".join(ans)
