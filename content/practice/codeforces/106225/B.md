### なぜ効果があるのか

 各オファーは、ブレークポイントを 1 つだけ持つ関数を定義します。$a_i$、合計スコアはこれらの点でのみ傾きが変化する区分線形関数になります。 連続する 2 つのブレークポイント間では、関数は線形であるため、ある間隔での最小値はその間隔の終点で発生する必要があります。 すべての傾きの変化は、$a_i$、世界最小値を超える$[l, r]$ソートされた臨界点の 1 つになければなりません。 プレフィックスとサフィックスの合計を事前に計算することで、各候補点で関数を一定時間で評価し、正確性を維持しながら列挙の重複を回避できます。$p$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        total = pref[n]

        def eval_x(x):
            import bisect
            k = bisect.bisect_right(a, x)

            left_sum = pref[k]
            right_sum = total - left_sum

            left_cnt = k
            right_cnt = n - k

            left_part = x * left_cnt - left_sum
            right_part = right_sum - x * right_cnt

            return left_part + right_part

        candidates = set([l, r])
        for v in a:
            if l <= v <= r:
                candidates.add(v)

        ans = 0
        for x in candidates:
            ans = max(ans, eval_x(x))

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、どの候補者にとっても適切なようにオファーが並べ替えられます。$x$、二分探索を使用して配列を分割できます。 接頭辞の合計を使用すると、次からの絶対偏差の合計を計算できます。$x$で$O(1)$、これはまさに関数です`eval_x`計算します。 

候補セットにより、関数の傾きが変化する可能性のある点のみが評価されることが保証されます。 このようなすべてのポイントを評価し、それらの最小寄与度の最大値を取得すると、最終的に保証されたスコアが得られます。 

微妙な点は、関数内のすべての変更は整数のブレークポイントで発生するため、必要なのは整数の候補だけであることです。$a_i$、$l$、 そして$r$。 これにより、継続的な最適化の必要がなくなります。

 主なエッジケースは、すべてのオファーが間隔の片側にある場合です。 仮定する$a_i \gg r$。 それから、どんな場合でも$p \in [l, r]$、すべてのオファーは同じサイン構造で均一に動作し、最適な戦略は一貫した方向性になります。 アルゴリズムはこれを正しく処理します。$a_i$すべての候補の評価で右側になり、接頭辞の合計が空になり、接尾辞の合計が優勢になります。
