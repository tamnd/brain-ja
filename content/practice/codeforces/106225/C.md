 ## 解決策
 ## 問題の理解

 それぞれ長さが m の n 個のシーケンスのコレクションが与えられ、各シーケンスは隠れた構築プロセスによって生成されたブロックに対応します。 隠されたプロセスは、長さ nm/2 の並べ替えから始まり、それをそれ自体と連結して長さ nm の配列を取得し、次にこの 2 倍になった配列を長さ m の n 個の連続するブロックに分割し、最後にこれらのブロックを公開する前に任意に並べ替えます。 

私たちのタスクは、複製とシャッフル後に特定のブロックのマルチセットを生成した可能性がある長さ nm/2 の順列を再構築することです。 

重要な構造的事実は、最終的な構造のすべての値が、全長 nm 配列で正確に 2 回、順列の各コピーで 1 回出現するということです。 ブロックに分割すると、分割によって重複した構造が破壊されないため、各数値はちょうど 2 つのブロックに表示されます。 

制約 n、m ≤ 70 は、テスト ケースごとに nm ≤ 4900 を意味するため、合計データ サイズは O(nm log nm) または O(nm²) の推論に十分小さいです。 これは、ブロックの順列に対する組み合わせ再構成ではなく、グローバルな周波数構造を活用すべきであるという強力なヒントです。 

ブロック境界の位置合わせから微妙な問題が発生します。 ブロックへの分割は倍増配列に固定されていますが、どのブロックが元の順列のどのセグメントに対応するかはわかりません。 ブロックが別個であることが保証されていないため、同一のブロックをペアにしたり、ブロックの同等性に基づいて再構築したりする単純な試みは失敗します。 たとえば、2 つの同一のブロックは、必ずしも重複した構造のアライメントからではなく、順列の異なる位置から取得される可能性があります。 

本当の課題は、ブロックの順序を再構築していないことです。 私たちは、その重複によって長さ m のチャンクのマルチセットが生成される、基礎となる置換を再構築しています。 

## アプローチ

 ブルートフォース解釈では、ブロックが 2 倍化された配列内の位置にどのように配置されるかを推測することによって、順列を再構築しようとします。 各ブロックを前半または後半のいずれかに割り当て、オーバーラップ全体で一貫性を確保することを想像することもできます。 これはすぐに組み合わせになります。n ブロック、それぞれのサイズが m の場合、nm/2 の位置への割り当てと位置合わせが指数関数的に多くなり、n、m が約 70 の場合でも実行不可能になります。 

重要な点は、実際にはブロック間の位置合わせを回復する必要がないということです。 元の順列で値の複数セットを復元することだけが必要です。 最終的な配列は順列の 2 つの連結されたコピーであるため、隠れた順列の各値は全長 nm 配列内で正確に 2 回出現し、したがって結合されたすべてのブロックにわたって正確に 2 回出現します。 

したがって、構造を無視して純粋に周波数に焦点を当てるだけで、順列値を再構成できます。 1 から nm/2 までの各整数は、nm 値の入力マルチセットに正確に 2 回現れます。 これは、すべての数値を単純に収集し、頻度を数え、各数値を 1 回だけ取得できることを意味します。 

残る唯一の微妙な点は、長さ nm/2 の有効な順列を確実に出力することです。 入力によって解の存在が保証されるため、1 から nm/2 までのすべての数値が nm エントリにわたって正確に 2 回出現する必要があります。

 ## アルゴリズムのチュートリアル

 この問題をすべてのエントリにわたる周波数の回復に帰着させます。

1. n 個のブロックをすべて読み取り、それらを nm 個の数値の単一のリストに平坦化します。 これが有効なのは、ブロックが 2 倍の配列のセグメントの単なる並べ替えであるため、平坦化によって値の完全なマルチセットが保存されるためです。 
2. ハッシュ マップまたは配列を使用して、各数値の出現をカウントします。 値は 1 ～ nm/2 の範囲にあるため、サイズ nm/2 + 1 の配列を直接インデックス付けに使用できます。 
3. 1 から nm/2 までのすべての値を反復処理し、各値を 1 回だけ追加することにより、答えを作成します。 正確さは、2 倍の順列で各値が正確に 2 回出現するという事実から得られるため、頻度は正確に 2 でなければなりません。 
4. 結果のリストを出力します。 

重要な推論ステップは、ブロック構造がグローバル周波数に決して影響を及ぼさないということです。 分割によって同じ値の一部が異なるブロックに配置される場合でも、全体で各値が出現する回数は変わりません。 

### なぜ効果があるのか

 長さ L = nm/2 の隠れた順列 P には、1 から L までの各整数が 1 回だけ含まれます。 構築された配列は P と P を連結したものであるため、すべての整数が完全な配列内で正確に 2 回出現します。 ブロックに分割したり、ブロックを並べ替えたりしても、値のマルチセットは変更されません。 したがって、すべてのブロックの頻度をカウントすると、すべての有効な値が正確に 2 回出現するマルチセットが復元されます。 各値を一度選択すると、プロセスと一致する有効な順列 P が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    total = n * m
    arr = []
    
    for _ in range(n):
        arr.extend(map(int, input().split()))
    
    # values are in [1, total//2]
    L = total // 2
    freq = [0] * (L + 1)
    
    for x in arr:
        freq[x] += 1
    
    res = []
    for i in range(1, L + 1):
        if freq[i] >= 1:
            res.append(i)
    
    print(*res)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```ブロックの順序付けは周波数推論には無関係であるため、コードはすべての入力ブロックを単一の配列に平坦化することから始まります。 次に、各整数の出現回数をカウントします。 最後に、各値を 1 回選択して順列を構築します。 

実装の微妙な詳細は、値の範囲が正確に 1 ～ nm/2 であることを前提としています。 これは、その長さの順列の定義と複製ステップから得られます。 この問題は解決可能であることが保証されているため、周波数が正確に 2 に等しいことを検証する必要はありません。 

## 実用的な例

 入力:

 n = 2、m = 2

 ブロック:

 [1、2]

 | 読んだ後 | 1:1、2:1、3:1、4:1 | - |

 これは L = 4 に対応するため、復元される順列は単純にすべての値 1 ～ 4 になります。 

これは、順列が値空間で連続している場合、周波数の存在から即座に再構成が行われることを確認します。 

### 例 2

 入力:

 n = 3、m = 2

 ブロック:

 [5、6]

 [1、2]

 [3、4]

 平坦化された配列: [5、6、1、2、3、4]

 | ステップ | 周波数状態 | 出力構造 |
 | --- | --- | --- |
 | 読んだ後 | すべての値は 1 回出現します | - |

 ブロックの順序は任意ですが、すべての値が 1 回だけ含まれている限り、どの順序でも機能するため、再構成された順列は依然として有効です。 

これは、ブロックの置換が基礎となるマルチセットの再構成可能性に影響を与えないことを示しています。

 ## 特殊なケース

 例外的なケースの 1 つは、ブロックが同一のシーケンスを繰り返す場合です。 このような場合、単純な再構成では、セグメントのペアのコピーとして同一のブロックを照合しようとする可能性がありますが、それは不要です。 このアルゴリズムは出現回数をグローバルにカウントするだけなので、ブロック レベルでの重複は影響しません。 

もう 1 つのケースは、元の置換セグメントに似ているブロックがないように、値がブロック間でインターリーブされる場合です。 その場合でも、平坦化により周波数が保存され、多重度のみが重要となるため、再構成は正しいままになります。 

最後のケースは m = 1 の場合で、各ブロックは単一の数値です。 平坦化によって完全なマルチセットが得られ、各数値を一度選択するとすぐに順列が再構築されるため、この解決策は依然として機能します。
