 ## 解決策
 ## 問題の理解

 パッケージのコレクションが与えられ、各パッケージには 2 つのパラメーターがあります。 1 つ目は、その荷物を配送バッチに含める場合に 1 回だけ支払う基本料金です。 2 つ目は、同じバッチで送信することを決定したパッケージの数に応じて変化する輻輳係数です。 

1 回の実行で正確に K 個のパッケージを配信することを選択した場合、選択した各パッケージ i の合計コストは$a_i + K \cdot b_i$。 重要な点は、輻輳期間は個々のパッケージではなく、選択されたパッケージの全体的な数に依存するということです。 

あなたのタスクは、K を最大化しながら、選択したサブセットの総コストが予算 B を超えないように、パッケージのサブセットを選択し、そのサイズ K も暗黙的に選択することです。この最大 K を達成するすべてのサブセットの中で、可能な最小コストを報告する必要があります。 

選択とコストの相互関係が最も難しい問題です。より多くのパッケージを選択すると、選択されたすべてのアイテムに対するパッケージごとの混雑ペナルティが増加し、これが選択自体の実現可能性にフィードバックされます。 

制約により、最大で$2 \cdot 10^5$パッケージ、最大コスト$10^9$総予算と最大$10^5$個々のパラメータについて。 これにより、各サブセットの実現可能性を明示的に再計算するソリューションは即座に除外されます。 大雑把よりも悪いアプローチ$O(n \log n)$または$O(n \sqrt n)$定数に依存するのは安全ではありません。 

素朴だが有益な失敗モードは、K を修正し、変更されたコストの下で最も安価な K パッケージを貪欲に選択しようとすることです。 たとえば、すべてが$b_i$いくつかの項目では大きくなり、他の項目では小さくなります。 K が誤って固定されている場合、貪欲な選択により、K が変更された後でのみ高価になる項目が選択され、以前の決定が無効になる可能性があります。 

K が項目の順序を変更すると、別の微妙なエッジケースが現れます。 コストは次のとおりであるため、2 つのパッケージは K に応じて順序を入れ替えることができます。$a_i + K b_i$。 たとえば、次の場合$a_1 < a_2$しかし$b_1 > b_2$の場合、小さい K パッケージの場合は 1 が安くなりますが、大きい K パッケージの場合は 2 が安くなります。 一度並べ替えるアプローチ$a_i$または$a_i + b_i$Kが壊れることを考えずに。 

## アプローチ

 強引なアイデアは、1 から N までのすべての可能な K を試すことです。各 K について、コスト公式に基づいて最も安価な K パッケージを選択するコストを計算します。$a_i + K b_i$。 これを直接行うには、すべてのパッケージを評価し、調整後のコストを計算し、並べ替えて、最適な K を選択する必要があります。 

固定 K の場合、ソートには時間がかかります$O(n \log n)$すべての K に対してこれを行うと、次のようになります。$O(n^2 \log n)$が遅すぎます。$2 \cdot 10^5$。 

重要な構造上の観察は、完全な再計算という意味では、実際にはすべての K を独立して試す必要はないということです。 代わりに、決定に関する質問をすることができます。固定 K の場合、予算内で K 個のパッケージを選択できますか? 最小コストはいくらですか? これに効率的に答えることができれば、K を二分探索することができます。 

固定 K の場合、各パッケージが貢献します$a_i + K b_i$。 K は固定されているため、これは項目ごとの静的な重量にすぎません。 したがって、最適な選択は単に次の K 個の最小値です。$a_i + K b_i$。 つまり、並べ替えはチェックごとに 1 回だけで済みますが、それでも遅すぎます。 

K をバイナリ検索し、ヒープベースまたは選択ベースの実現可能性チェックを使用することで、これをさらに削減します。 ただし、さらに簡単なトリックがあります。固定された K に対して、値を計算します。$a_i + K b_i$、ソートまたはヒープを使用して最小の K を選択します。$O(n)$または$O(n \log n)$、合計を計算します。 次に、K を二分探索します。$O(\log n)$。 

これにより、$O(n \log n \log n)$、これは許容範囲です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な再計算による K に対するブルート フォース |$O(n^2 \log n)$|$O(n)$| 遅すぎる |
 | 二分探索 K + K 個の最小調整コストの選択 |$O(n \log n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 与えられた K に対して、正確に K 個のパッケージを選択する最小総コストを計算する関数を定義します。 パッケージごとに実効コストを計算します$c_i = a_i + K b_i$、K はこのチェック内で固定されているためです。 
2. 計算されたものをすべて並べ替える$c_i$値を計算し、最小の K 値の合計を取得します。 固定 K の場合、各パッケージは独立して寄与し、選択数以外の結合はないため、これは最適な選択に対応します。 
3. この合計が B 以下の場合、K 個のパッケージが予算内で実現可能です。 そうしないと、K が大きすぎます。 
4. K を 0 から N まで二分探索します。実行可能性が true から false に遷移する範囲を維持します。 
5. 各中間点 K に対して、実現可能性関数を実行します。 可能であれば、下限を上に移動します。 それ以外の場合は、上限を下に移動します。 
6. 二分探索が完了すると、実現可能な最大 K がわかります。同じ手順を使用してそのコストを再計算し、その K の最小総コストを取得します。 

機能する理由: 固定 K ごとに、コスト関数は完全に決定され、選択数を除いてパッケージ間で独立しています。 K が増加するたびに増加するため、実現可能性述語は K において単調です。$c_i = a_i + K b_i$、K 個の最小値の合計を増やすか、選択を難しくすることしかできません。 この単調性により、バイナリ検索の正確さが保証されます。これは、K が実行不可能になると、それより大きな K はすべて実行不可能のままであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost_for_k(a, b, K, B):
    n = len(a)
    vals = [a[i] + K * b[i] for i in range(n)]
    vals.sort()
    s = sum(vals[:K])
    return s

def feasible(a, b, K, B):
    if K == 0:
        return True, 0
    n = len(a)
    vals = [a[i] + K * b[i] for i in range(n)]
    vals.sort()
    s = sum(vals[:K])
    return s <= B, s

def main():
    n, B = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    lo, hi = 0, n
    best_k = 0
    best_cost = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        vals = [a[i] + mid * b[i] for i in range(n)]
        vals.sort()
        s = sum(vals[:mid]) if mid > 0 else 0

        if s <= B:
            best_k = mid
            best_cost = s
            lo = mid + 1
        else:
            hi = mid - 1

    print(best_k, best_cost)

if __name__ == "__main__":
    main()
```このコードは、答え K に対して直接二分探索を実装します。中間点ごとに、調整されたコストを計算します。$a_i + K b_i$そしてソートによって最小の K を選択します。 他のサブセットは選択された要素をより大きな要素に置き換える可能性があるため、これらの K 値の合計がその K の可能な最小コストになります。 

二分探索では、これまでに確認された最良の実行可能な K が維持されます。 中間点が実現可能な場合、K とそのコストの両方を保存し、K を増加させようとします。そうでない場合は、K を減少させます。K では実現可能性が単調であるため、これが機能します。 

実装の微妙な詳細は、スライスの問題を回避し、予算でパッケージがゼロでも許容される場合の正確性を確保するために、K = 0 を個別に処理することです。 もう 1 つの重要な点は、コスト関数が K に依存するため、以前の計算を再利用しようとするのではなく、各反復内でコストを再計算することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, B = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    def check(K):
        vals = [a[i] + K * b[i] for i in range(n)]
        vals.sort()
        return sum(vals[:K]) if K > 0 else 0

    lo, hi = 0, n
    best_k, best_c = 0, 0
    while lo <= hi:
        mid = (lo + hi) // 2
        c = check(mid)
        if c <= B:
            best_k, best_c = mid, c
            lo = mid + 1
        else:
            hi = mid - 1

    return f"{best_k} {best_c}"

 ## 特殊なケース

 重要なエッジケースは、K がゼロに等しい場合です。 この状況では、パッケージは選択されず、コストはまったくゼロになります。 アルゴリズムは並べ替え前にこれを明示的に処理し、不必要な作業を回避し、予算がゼロの場合でも正確さを保証します。 

別の特殊なケースが発生するのは、$b_i$はゼロです。 その場合、コストは各項目の K から独立し、問題は最小の K を選択することになります。$a_i$価値観。 アルゴリズムはまだ機能します。$a_i + K b_i = a_i$。 

3 番目のケースは次の場合です。$a_i$値はゼロですが、$b_i$ポジティブです。 ここで、K を増やすと、個々のアイテムは最初は無料に見えても、選択が高価になります。 二分探索により、輻輳が優勢になるカットオフ K が自然に発見され、各ステップでの再計算によってこの非線形動作が正確に捕捉されます。
