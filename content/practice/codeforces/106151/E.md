 ## 解決策
 ## 問題の理解

 一連の目標が与えられ、各目標には基本エネルギーコストと疲労係数という 2 つのパラメータがあります。 アスリートはこれらのターゲットの任意のサブセットを選択し、それらを攻撃する順序を決定できます。 ターゲットが j 番目の成功したヒットとして命中した場合、そのコストは、その基本コストに、j から 1 を引いた値に比例する追加のペナルティを加え、その疲労係数によってスケールされます。 目標は、総エネルギーが予算を超えずに達成できるターゲットの数を最大化することであり、その最大数を達成するためのあらゆる方法の中で、使用される最小限のエネルギーも報告します。 

難しいのは、ポジションが上がるにつれて疲労期間が大きくなるため、順序が非常に重要になることです。 疲労係数が大きいターゲットは、後で配置すると大幅に高価になるため、順序の選択はサブセットの選択とは独立していません。 問題は本質的に、コストが選択されたシーケンス内のランクに依存する場合、項目をいくつ選択できるか、およびその最大カーディナリティで達成可能な最小コストはいくらかということです。 

この制約は、単純な階乗またはサブセット列挙アプローチが不可能であることを示唆しています。 N が最大 10^4 の場合、サブセット サイズごとに O(N^2) 以上の構築は遅すぎます。 O(N log N) または O(N sqrt N) に近いものが必要です。 

いくつかのエッジの動作は強調する価値があります。 

すべての疲労係数がゼロの場合、順序は問題ではなく、予算を超えるまで最小の基本コストを選択するだけです。 貪欲な並べ替えソリューションは簡単に機能します。 

すべての基本コストがゼロの場合、後のピックではより多くのペナルティが蓄積されるため、問題は純粋に疲労による順序付けに関するものになります。 疲労度の低いアイテムを早い段階で選択するのが最適であり、b で分類することを提案します。 

より微妙な失敗例は、貪欲な戦略が基礎と疲労の間の相互作用を無視した場合に発生します。 たとえば、最小の ai を最初に選択することは、必ずしも最適であるとは限りません。これは、bi がはるかに小さいわずかに大きい ai は、早期に選択すると全体的に安くなる可能性があるためです。 

例:

 N = 3、B = 10

 a = [5, 4, 4]

 b = [10, 1, 1]

 AI の昇順で選択すると、4 (0)、4 (1)、5 (2) のコストは 4、5、25 となり、合計は 34 となり、無効になります。 ただし、最初に高い基本コストを選択すると、後のペナルティが軽減される可能性があります。 

これは、a だけによる並べ替えは間違っており、b だけによる並べ替えも不十分であることを示しています。 プレフィックスのサイズと傾きの相互作用が重要な問題です。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべてのサブセット サイズ k を試し、最適な順序付けの下で可能な限り最小のコストで k 個のターゲットを選択できるかどうかを確認することです。 固定 k の場合、k 個の項目を選択し、ai + (位置 - 1) * bi の合計を最小化する最適な順列を見つける必要があります。 最適な順序付けは選択したサブセットに依存するため、これはすでに自明ではありません。 

サブセットを修正する場合、乗数を減らすために疲労度の高い項目を先に配置する必要があるため、最適な順序は bi で降順に並べ替えることです。 固定サブセットのコストは O(k log k) で計算できます。 ただし、サイズ k のすべてのサブセットを列挙することは組み合わせによるものであり、不可能です。 

重要な観察は、視点を逆転させることです。 k を固定してサブセットを検索する代わりに、段階的にソリューションを構築しようとします。k 個の項目を選択するとします。 すべての項目を双降順で並べ替えると、k 個の項目を選択するときに、どの項目が疲労ペナルティが小さい順序で最初に表示されるかを効果的に決定することになります。 

選択したセットのコストを b 順にソートして再構成できます。 項目を降順で処理する場合、項目を選択するときの位置は、すでに選択した項目の数によって決まります。 したがって、bi の寄与はその選択時間に関係します。

これは、最小限のコストでサイズ k の候補セットを維持しようとする貪欲な選択プロセスを示唆しています。 この構造は、加重増分ペナルティを付けて k 項目を選択することに似たものになります。これにより、自然に bi によるソートが行われ、選択された項目の数を追跡する構造が維持されます。 

より直接的で標準的な変換は、限界費用の観点から考えることです。 順序を修正する場合、最後に新しいアイテムを追加すると、現在のサイズ k に対して ai に k * bi を加えた分だけコストが増加します。 これは、各アイテムのコストが、すでに選択したアイテムの数に直線的に依存することを意味します。 貪欲な決定を有効にするには、k を増加させても有益な項目を常に選択する構造が必要です。 

正しいアプローチは、双降順による並べ替えと、誘発されたコスト構造の下で常に最良の k 品目を確実に維持する選択戦略を使用することになります。 これは、優先順位構造と組み合わせた k に対する貪欲検索または二分探索を使用して、k を増やすための実行可能性を反復および維持することによって実装できます。 

答え k を二分探索します。 固定 k の場合、最小総コスト ≤ B の k 項目を選択できるかどうかを確認します。実現可能性を評価するために、項目を双降順で並べ替え、ヒープを使用して、位置 1 から k が割り当てられたときに最小の実効増分コストを持つ k 項目を選択します。 これにより、その k の最適な配置が得られます。 

実行可能性チェックが機能するのは、順序が bi によって固定されると、残る選択肢はどの k 項目を取るかだけであり、より高い bi に早い位置を割り当てることで全体の疲労の寄与が最小限に抑えられるためです。

 | --- | --- | --- | --- |
 | ブルート フォースのサブセットと順列 | O(2^N · N log N) | O(N) | 遅すぎる |
 | 二分探索 + ヒープによる貪欲な実現可能性 | O(N log N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. すべてのターゲットを bi の降順に並べ替えます。 これにより、2 つのアイテムが異なる位置で使用されている場合、疲労係数が大きい方が先に考慮され、線形ペナルティ項の最小化と一致します。 
2. 予算 B 内で k 個のアイテムを選択できるように最大 k を二分探索します。k 個のアイテムが実行可能であれば、任意のより少ない数のアイテムも実行可能であるため、単調性が成り立ちます。 
3. 二分探索中の固定 k について、k 個の項目を最適に選択できるかどうかを計算します。 位置 1 から k を順番に割り当てることをシミュレートし、並べ替えられたリストから k 個の項目の最良の選択を維持します。 
4. 最大ヒープを使用して、増分コストの寄与に基づいて選択したアイテムを追跡します。 各項目 i をソート順に検討する場合、現在の位置 j に配置された場合のその寄与 (ai + j * bi) を計算します。 それをヒープに追加し、ヒープ サイズが k を超える場合は、最悪の項目を削除します。 
5. 現在ヒープ内にあるアイテムの合計コストを累積します。 すべての項目を処理した後、ヒープ合計が ≤ B であれば、k は実行可能です。 
6. 二分探索によって実現可能な最大の k が見つかった後、同じ選択手順を再実行して、対応する最小コストを計算します。 

なぜ効果があるのか:

 重要な不変条件は、項目が降順で処理される場合、最初に早い位置を割り当てても最適性が損なわれないということです。 より高い bi 項目を早期に交換すると、全体の疲労寄与が低減または維持されるため、コストを増加させることなく、最適なソリューションをこの次数を考慮したものに変換できます。 ヒープにより、強制された位置構造の下で最小の調整コストで k 個のアイテムが常に保持されることが保証されます。 これにより、サイズ k のサブセットがバジェット内に存在する場合、アルゴリズムが実行可能なサブセットを見つけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(items, k, B):
    if k == 0:
        return True, 0

    # items are (a, b) already sorted by b desc
    import heapq

    heap = []  # max heap via negative values
    total = 0

    for i, (a, b) in enumerate(items[:], start=1):
        # cost if placed at position i in selection order
        cost = a + (i - 1) * b

        heapq.heappush(heap, -(cost))
        total += cost

        if len(heap) > k:
            removed = -heapq.heappop(heap)
            total -= removed

    if len(heap) < k:
        return False, 0

    return total <= B, total

def solve():
    N, B = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    items = list(zip(a, b))
    items.sort(key=lambda x: -x[1])

    lo, hi = 0, N
    best_cost = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        ok, cost = feasible(items, mid, B)

        if ok:
            best_cost = cost
            lo = mid + 1
        else:
            hi = mid - 1

    # recompute final cost for best k
    ok, cost = feasible(items, hi, B)
    print(hi, cost)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に疲労係数によって並べ替えられるため、その後の位置依存コストに関する推論が安定します。 実現可能性関数は、最小の調整コストを維持するヒープを使用して、この順序の下で可能な限り最適なサイズ k のセットの構築をシミュレートします。 二分探索では、k に関する実現可能性の単調な性質を利用します。 微妙な点は、中間の二分探索状態が最終的ではない k 値のコストを保存する可能性があるため、k を固定した後に最終コストを再計算することです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, B = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    items = list(zip(a, b))
    items.sort(key=lambda x: -x[1])

    import heapq

    def feasible(k):
        heap = []
        total = 0
        for i, (ai, bi) in enumerate(items, start=1):
            cost = ai + (i - 1) * bi
            heapq.heappush(heap, -cost)
            total += cost
            if len(heap) > k:
                total -= -heapq.heappop(heap)
        return len(heap) == k and total <= B

    lo, hi = 0, N
    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            ans_k = mid
            lo = mid + 1
        else:
            hi = mid - 1

    # recompute cost
    heap = []
    total = 0
    for i, (ai, bi) in enumerate(items, start=1):
        cost = ai + (i - 1) * bi
        heapq.heappush(heap, -cost)
        total += cost
        if len(heap) > ans_k:
            total -= -heapq.heappop(heap)

    def solve(inp: str) -> str:
        return f"{ans_k} {total}"

    return solve(inp)

 ## 特殊なケース

 予算がゼロの場合、アルゴリズムは実行可能な k = 0 で二分探索を開始し、ヒープ合計がすぐに正になるため、k ≥ 1 はすぐに拒否されます。 項目が選択されていない限り、実現可能性関数は正しく false を返します。 

単一項目入力の場合、並べ替えは簡単であり、ヒープには要素が 1 つだけ含まれます。 二分探索では、コスト a1 ≤ B である場合にのみ k = 1 が実現可能であると特定され、直接解釈と一致します。 

すべてゼロのコストの場合、すべての実現可能性チェックはすべての k に対して true を返すため、二分探索は正しく N に収束し、ヒープ合計は全体を通してゼロのままとなり、bi = 0 の場合には疲労が寄与しないことが確認されます。
