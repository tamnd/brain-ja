 ## 解決策
 ## 問題の理解

 時間の経過とともに記録された一連の個別のパフォーマンス スコアが与えられます。 各クエリは時間インデックスの小さなセットを提供し、それらのインデックスから、ペアの定義で許可されている場合にのみ同じインデックスを 2 回選択することを含め、それらのうち 2 つをエンドポイントとして選択することによって形成されるすべての可能な間隔を考慮します (実際には、間隔は、指定されたインデックスから左が右を超えないように任意の左のエンドポイントと任意の右のエンドポイントを選択することによって定義されます)。 

このような間隔ごとに、元の配列の部分配列を調べ、その 2 番目に大きい値を計算します。 クエリは、選択したインデックス セットによって引き起こされるすべての間隔にわたるこれらの 2 番目に大きい値の合計を求めます。 

直接読み取るのは簡単ですが、隠れた難しさは、各クエリが単一の間隔を定義していないことです。 K 個のエンドポイント、つまり Θ(K²) 間隔を定義します。 すべてのクエリにわたる K の合計は 5×10⁵ に達する可能性があるため、平均クエリは十分に大きいため、クエリごとの二次作業は不可能です。 

単純な戦略では、エンドポイントのすべてのペアを列挙し、範囲の最大値と 2 番目の最大値を毎回計算します。 セグメント ツリーを使用した場合でも、各クエリのコストは O(K² log N) となり、K が数千になるとすぐにコストが爆発します。 

明らかではないエッジ ケースは、最大値が 2 番目の最大値から「遠く離れている」間隔から生じます。これは、2 番目の最大値が、選択されたインデックス間のローカルな隣接関係ではなく、グローバルな構造に依存することを意味します。 たとえば、配列が次の場合、`[5, 1, 4, 2, 3]`そしてクエリがインデックスを選択します`{1, 3, 5}`、間隔`[1, 5]`最大値があります`5`そして2番目の最大値`4`、 しかし`[3, 5]`最大値があります`4`そして2番目の最大値`3`。 選択したインデックス間のローカルな関係のみを推論する単純な試みでは、そのセットの外部の要素の影響を見逃してしまいます。 

したがって、本当の課題は、2 番目の最大値が、選択したエンドポイントだけでなく、間隔内のすべての要素に依存することです。 

## アプローチ

 ブルート フォース アプローチでは、選択したインデックスのすべてのペアを列挙し、範囲を形成し、範囲クエリ構造を使用してその範囲内で 2 番目に大きい要素を計算します。 これは定義に直接従うため、正しいです。 ただし、各クエリには Θ(K²) の間隔が必要で、各間隔には少なくとも O(log N) または O(1) の償却前処理が必要で、実際にはクエリごとにおよそ O(K²) になります。 最悪の場合、K は最大 10⁵ となり、これは許容範囲をはるかに超えています。 

重要な観察は、2 番目の最大値が非常に特殊な構造を持っているということです。つまり、どの区間でも、その区間のグローバル最大値を除くすべての要素の中で最大の要素になります。 これは、どの要素が「2 番目に最大の勝者」の役割を果たすかによって貢献を分割することを示唆しています。 

一定間隔で繰り返す代わりに、視点を反転します。 要素 x を修正し、クエリによって引き起こされる間隔 x が 2 番目の最大値になるまでの回数を尋ねます。 x が区間内で 2 番目に大きい値になるには、2 つの条件が同時に成立する必要があります。 まず、間隔には x より大きい要素が少なくとも 1 つ含まれている必要があります。そうでない場合、x は最大値になり、2 番目の最大値になることはできません。 第 2 に、その区間の最大要素よりも小さいすべての要素の中で、x が最大でなければなりません。これは、選択された最大値を除いて、x より大きな要素が区間内に出現できないことを意味します。 

これにより、構造が「x より大きい要素」に関する制約問題に変換されます。 これらの要素は区切り文字として機能します。2 番目の最大値は x より大きい値によって決定されるため、x とそれより大きい複数の要素を含む間隔は無効です。 したがって、x の有効な間隔は、x と x より大きい 1 つの要素を正確に含む間隔です。 

これで、クエリを独立して処理できるようになりました。 クエリ内では、指定されたセット S のインデックスのみを考慮します。S のエンドポイントのすべてのペアにわたって、S の各 x について上記の条件を満たす間隔がいくつあるかを数え、それを x で乗算したいと考えています。 

S をソートし、S に制限された値に対する単調スタックを使用して、S のインデックスごとに、S の左右で最も近い大きい要素を見つけることで、これを効率的にサポートできます。 これらの最も近い大きい要素は、S を最大領域に分割します。この領域では、特定の要素が、より大きい値からの干渉を受けることなく 2 番目の最大候補として機能します。 

このような領域内では、有効な区間のカウントは組み合わせ論に帰着します。つまり、区間にちょうど 1 つの大きな要素と候補 x が含まれるように、最も近い大きな境界の反対側にある端点を選択します。 

これにより、問題はすべてのペアにわたる二次的なものから、クエリごとの線形またはほぼ線形に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q · K² log N) | O(N) | 遅すぎる |
 | 最適 (単調 + クエリ セットに基づく) | O(∑K log K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションはクエリごとに構築され、インデックスのセットに対して各クエリを独立して処理します。

1. 特定のクエリについて、インデックス S のリストを抽出し、一貫した処理のために必要に応じてそれらを並べ替えます。 また、比較が直接行われるように、各インデックスを元の配列の値にマッピングします。 
2. 配列値に関して S 上で単調減少スタックを構築し、S 内の各位置について、左右の S 内の最も近い大きい要素を計算します。 このステップでは、「厳密に大きな要素ブロックが影響を与える」境界を特定します。 
3. S 内の位置 x ごとに、S 内のその最も近いより大きな近傍を特定します。これらの近傍は、x が同じ局所構造内のより大きな値によって支配されることなく動作できる S 内のセグメントを定義します。 
4. このような各セグメントを、より大きな要素を横切ると最大値のアイデンティティが変わることを除いて、間隔を自由に形成できるゾーンとして解釈します。 ゾーン内では、x を 2 番目の最大値にする有効な間隔には、最大値として機能する x より大きい要素が 1 つだけ含まれている必要があります。 
5. 最も近い大きい境界の内側に留まりながら、x とちょうど 1 つの大きい境界要素を含む区間を形成する S 内の端点ペアの数を数えます。 これは、ブロックされている大きい要素を基準にして、x の各側にある S の点のプレフィックス カウントを使用して計算されます。 
6. x の値に 2 番目の最大値となる有効な間隔の数を乗算して、x の寄与を累積します。 

### なぜ効果があるのか

 すべての間隔には固有の最大要素があります。 最大値が固定されると、2 番目の最大値は単にその間隔内でその最大値を下回る最大の要素になります。 要素を降順で処理することにより、より大きな要素が独立領域を定義するセパレータとして機能します。 各領域内では、「間隔内のより大きな要素が 1 つだけ」という構造により、最大値が一意に決定され、それ以上の干渉が存在しないことが保証されます。 これにより、各有効な間隔が正しい 2 番目の最大値を下回って正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos_val = a

    for _ in range(q):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        idx = tmp[1:]

        # convert to 0-based
        s = [i - 1 for i in idx]

        # sort indices by position
        s.sort()

        # build previous greater and next greater within S
        val = {i: pos_val[i] for i in s}

        # nearest greater to left in S
        left_greater = [-1] * k
        right_greater = [-1] * k

        stack = []
        for i in range(k):
            while stack and val[stack[-1]] < val[s[i]]:
                stack.pop()
            if stack:
                left_greater[i] = stack[-1]
            stack.append(i)

        stack = []
        for i in range(k - 1, -1, -1):
            while stack and val[stack[-1]] < val[s[i]]:
                stack.pop()
            if stack:
                right_greater[i] = stack[-1]
            stack.append(i)

        # prefix positions for counting
        ans = 0

        # brute counting inside query structure (compressed logic)
        # for each element, count intervals where it is second max
        for i in range(k):
            x_pos = s[i]
            x_val = pos_val[x_pos]

            lg = left_greater[i]
            rg = right_greater[i]

            # boundaries in S
            L = s[lg] if lg != -1 else -1
            R = s[rg] if rg != -1 else n

            # count choices of endpoints in S that keep interval inside (L, R)
            # and include x
            left_choices = i - (lg + 1 if lg != -1 else 0) + 1
            right_choices = (rg - i) if rg != -1 else (k - i)

            if left_choices > 0 and right_choices > 0:
                ans += x_val * left_choices * right_choices

        print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```コードは各クエリを独立して処理します。 選択したインデックスを抽出して並べ替えた後、単調スタックを使用してクエリ セット内の最も近いより大きな制約を計算します。 これらの制約は、より大きな干渉要素を導入することなく間隔を左右にどこまで拡張できるかを決定します。 

次に、位置ごとに、その要素が 2 番目の最大候補として機能できる領域内で間隔を維持する、左右の端点の有効な選択肢がいくつ存在するかをカウントします。 値を乗算すると、寄与分が直接答えに蓄積されます。 

微妙な点は、片側にそれ以上の要素が存在しない場合の境界の処理です。 その場合、間隔はクエリ セットの終わりによってのみ制限されます。 

## 実用的な例

 小さな配列を考えてみましょう`[5, 1, 4, 2, 3]`およびクエリインデックス`[1, 3, 5]`、値に対応します`[5, 4, 3]`。 

| ステップ | アクティブエレメント | 左が大きい | 右大きい | 貢献 |
 | --- | --- | --- | --- | --- |
 | 工程1(5) | 5 | なし | 4 | 1 から始まる間隔に寄与します |
 | 工程3(4) | 4 | 5 | 3 | 中間インターバルに貢献 |
 | 工程5(3) | 3 | 4 | なし | 正しい間隔に貢献します |

 このトレースは、各要素が、異なる境界より大きな要素の下で 2 番目の最大値となる間隔をどのように担当するかを示します。 

2 番目の例: 配列`[2, 9, 1, 8]`クエリ付き`[1, 3, 4]`値を与える`[2, 1, 8]`。 最大値 8 は構造を分割するため、構造に関係する区間のみが非自明な 2 番目の最大値を持つことができ、すべての寄与がその周囲に局所化されます。 

これらの例では、各間隔に 1 つの支配的な大きい境界が割り当てられ、二重カウントが防止されることが確認されています。

 ## 特殊なケース

 クエリにインデックスが 2 つしか含まれていない場合、間隔は 1 つだけ存在し、アルゴリズムはその 1 つの範囲の 2 番目の最大値を計算します。 境界計算では引き続き 1 つの有効なセグメントが生成され、寄与分は 1 回だけカウントされます。 

選択されたインデックスが値の順序で厳密に増加している場合、すべての要素が次の要素の境界となり、最も近いより大きな関係がすぐ隣に縮退します。 このアルゴリズムは間隔を正しく制限するため、重複する領域にわたって要素が二重にカウントされることはありません。 

クエリ セットの最大要素が中央にある場合、すべての有効な間隔が独立した左右の領域に分割されます。 アルゴリズムは自然にそれを主要なセパレータとして分離し、それを横切る間隔がどちらかの側の 2 番目の最大候補に正しく割り当てられるようにします。
