 ## 解決策
 ## 問題の理解

 一連の整数が与えられます。 1 回の操作で、任意の 1 つの要素を選択し、正確にプラス 2 またはマイナス 2 だけ変更します。 少なくとも 1 つの要素が正確にゼロになるまで、このプロセスを繰り返します。 目標は、その状態に到達するまでに必要な手の数を最小限に抑えるか、不可能であると報告することです。 

重要なのは、配列全体を特定のものに変換しようとしているわけではないということです。 1 つのポジションをできるだけ早くゼロにすることだけを考慮しており、各ステップでどのインデックスを変更するかを自由に選択できます。 

制約は非常に大きく、最大 10^6 の数値と最大 10^9 の値が含まれます。 これにより、すべての中間値を追跡したり、一連の動きを調べたりしようとするシミュレーションは直ちに除外されます。 どのような解決策でも、問題を線形時間での要素ごとの計算または集約された計算に削減する必要があります。 

微妙な点はパリティです。 すべての操作で数値が 2 ずつ変更されるため、各要素のパリティは決して変わりません。 奇数で始まる数値は常に奇数のままであり、偶数で始まる数値は常に偶数のままです。 ゼロは偶数であるため、どれだけ多くの演算を適用しても、奇数がゼロになることはありません。 これにより、すでに不可能なケースが大量に作成されます。 

2 番目の特殊なケースは、負の数から発生します。 問題のステートメントでは負の値が許可されており、負の値からゼロに到達する場合は、同じパリティとステップ サイズの制限に従います。 すべての数値がゼロまでの正の距離であると仮定する素朴なアプローチは、符号は重要ではなく、絶対距離とパリティだけを無視する場合には失敗します。 

たとえば、単一要素の配列があるとします。`[5]`5 → 3 → 1 → -1 → -3 ... ゼロに到達することはないので、正解は -1 です。 を使用する不用意な解決策`abs(a[i]) // 2`2手でゼロに到達できると誤って主張します。 

別の例は`[4, 3]`。 4は2手でゼロまで到達できますが、3は奇数なので不可能なので、答えは-1となります。 

## アプローチ

 単一の要素に焦点を当てると、プロセスは簡単になります。サイズ 2 のステップを使用してゼロに到達しようとします。 つまり、事実上、整数直線上をストライド 2 で歩いていることになります。 

価値のために`x`と同じパリティを持つ数値のみに到達できます。`x`。 したがって、ゼロに到達できる唯一の候補は偶数です。 このうち、必要な手数は、ゼロになるまでに 2 を何回引くか足す必要があるかということになります。`|x| / 2`。 

各ステップで任意のインデックスを操作できるため、要素間の相互作用について心配する必要はありません。 各移動は 1 つの要素に費やされるため、最適な戦略は、ゼロに到達するために必要な移動が最も少ない要素を選択することです。 ただし、この問題では、すべての要素の合計ではなく、少なくとも 1 つの要素がゼロになるまでに必要な最小移動数が求められます。 これは、すべての変換が完了しているわけではなく、最初に成功したヒットのみが完了していることを意味します。 

したがって、このプロセスは、要素ごとに、ゼロに到達できるかどうか、および何手目でゼロに到達できるかを計算し、すべての有効な候補の最小値を取得することになります。 

ブルートフォースのアイデアでは、すべての一連の操作をシミュレートし、各ステップですべての選択肢を試します。 各ステップには N 個の選択肢があり、最大 O(max |a_i|) ステップが必要になる可能性がありますが、これはまったく実行不可能です。 分岐要素により、時間の経過とともにこれが指数関数的に増加します。 

重要な観察は、各要素が独立して進化し、ゼロに達するかどうかはパリティと距離のみに依存するということです。 これにより、問題は単純な要素ごとの計算に分解されます。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、変数を初期化します。`answer`すべての有効な要素間で必要な移動の最小数が必要なため、無限大を使用します。 
2. 各要素について`x`, まず偶数かどうかを確認します。 もし`x`は奇数です。±2 移動以内ではゼロに到達できないため、すぐにスキップします。 
3. もし`x`が偶数の場合、ゼロに達するまでに必要な手数を計算します。`|x| // 2`。 これは、その大きさをゼロに下げるために必要な ±2 ステップの正確な数を表します。 
4.アップデート`answer = min(answer, |x| // 2)`。 
5. すべての要素を処理した後、偶数が見つからなかった場合は、`answer`まだ無限です、戻ってください`-1`。 それ以外の場合は戻ります`answer`。 

### なぜ効果があるのか

 各要素は固定ステップ サイズ 2 の下で独立して進化するため、ゼロへの到達可能性は、ゼロが到達可能な剰余クラス モジュロ 2 にあるかどうかによってのみ決まります。演算下ではパリティが不変であるため、奇数はゼロから永久に切り離されます。 偶数の場合、すべての演算により絶対距離が 0 まで正確に 2 だけ減少しますが、この距離の展開を変更できる分岐構造はありません。 したがって、ゼロに到達する最小時間は要素ごとに完全に決定され、グローバルな答えは、個別に到達可能なすべての候補の中で単純に最良になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    INF = 10**18
    ans = INF
    
    for x in arr:
        if x % 2 != 0:
            continue
        ans = min(ans, abs(x) // 2)
    
    if ans == INF:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、パリティが唯一のブロック条件であるという観察に直接従っています。 このループは、偶数の値についてのみ答えの候補を計算します。 絶対値を使用すると、ゼロまでの距離が両側で対称になるため、負の数を正しく処理できます。 

センチネル値`INF`有効な要素が存在しない場合を検出するために使用されます。 これが必要なのは、ゼロまたはデフォルト値を返すと誤って成功を示唆してしまうためです。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が奇数である場合です。 この状況では、パリティは決して変化しないため、どの演算シーケンスもゼロを生成することはできません。 アルゴリズムはこれを自然に処理します。`ans`無限のままで、私たちは戻ります`-1`。 

もう 1 つの特殊なケースは、単一要素の配列です。 値が偶数の場合、答えは単純に次のようになります。`|x|/2`奇数の場合、結果は次のようになります。`-1`。 両方の動作がパリティ チェックですでにエンコードされているため、アルゴリズムでは特別なケースは必要ありません。 

±2 の演算ごとに数値がゼロを中心に対称的にシフトされるため、負の値は正の値と同様に動作します。 アルゴリズムは絶対値を正しく使用するため、`-8`そして`8`同じ結果、つまり 4 回の移動が生成されます。
