 ## 解決策
 ## 問題の理解

 各頂点が邸宅の部屋を表し、各有向エッジが部屋間の一方通行のドアを表す有向グラフが与えられます。 すべてのドアのコストは、すでにロックが解除されているか、通過するためにバッジの使用が必要かに応じて 0 または 1 になります。 バッジを効果的に使用すると、施錠されたドアを通過できることになりますが、総移動時間に常に 1 のコストが追加されます。 

タスクは、部屋 1 から部屋 N に移動するための最小の総コストを見つけるか、方向指定された経路がなければ不可能であると判断することです。 

この制約では、最大 100,000 の部屋と 100,000 のドアが許可されており、エッジごとに最短パスを最初から再計算しようとしたり、単純な O(NM) 緩和アプローチを使用したりするソリューションは即座に除外されます。 線形時間または線形算術時間に近いものが必要です。 

一般的な失敗例は、グラフを重み付けされていないものとして扱う場合に発生します。 たとえば、重みを無視して標準的な BFS を実行すると、すべてのエッジのコストが等しいと誤って仮定してしまいます。 

小さなケースを考えてみましょう。 

入力:

 1 2 1

 1 3 0

 3 2 0

 1 から 2 への最適なパスは 1 → 3 → 2 でコスト 0 ですが、直接エッジ 1 → 2 のコストは 1 です。プレーン BFS は隣接順序に応じて直接エッジを誤って優先し、より安価なパスを見逃す可能性があります。 

もう 1 つの微妙な問題は、バイナリ ヒープでダイクストラを使用するが重みを一般的な整数として扱うことから発生します。 それは正しいのですが、重みが 0 または 1 しかないため、これは少しやりすぎであり、さらに改善できる可能性があります。 

## アプローチ

 この強引なアイデアは、ダイクストラのような標準的な最短経路アルゴリズムを使用することです。 エッジを緩和するたびに、更新された距離を優先キューにプッシュします。 これは正しいです。すべてのエッジの重みが負ではないため、ダイクストラは最適性を保証します。 

ただし、複雑さは O(M log N) となり、ここでは許容範囲ですが、問題の構造が無視されます。つまり、重みは 0 または 1 のみです。この構造により、対数因数を完全に回避できます。 

重要な観察は、どの緩和によっても距離が最大 1 増加するだけであるということです。これは、完全な優先キューの順序付けが必要ないことを意味します。 「同じコスト」と「コスト + 1」を区別するだけで済みます。 これにより、当然、コスト 0 のエッジが前面に配置され、コスト 1 のエッジが背面に配置される、デックベースの BFS バリアントが生成されます。 

これにより、問題は 0-1 の重み付きグラフの最短経路に変換され、0-1 BFS を使用して O(N + M) で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ヒープのあるディクストラ | O(M log N) | O(N + M) | 承認済み |
 | 0-1 BFS | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 両端キューを使用してグラフを処理し、前方に近いノードほど現在の距離が常に小さいという不変条件を維持します。 

1. 各エッジが宛先と重みを格納する隣接リストを作成します。 
2. 0 に設定されているノード 1 を除くすべてのノードに対して、距離配列を無限大で初期化します。これは、コストが発生せずに部屋 1 から開始することを表します。 
3. ノード 1 を両端キューにプッシュします。 デクは、ヒープを使用せずに安価な状態が最初に拡張される優先構造のように機能します。 
4. デキューが空ではない間に、先頭からノードをポップします。 これにより、現在知られている最も安価な状態を常に拡張することができます。 
5. 現在のノードからの出力エッジごとに、現在の距離にエッジの重みを加えたものとして候補距離を計算します。 この値が近隣の保存された距離より小さい場合は、値を更新します。 
6. エッジの重みが 0 の場合、隣接エッジをデキューの前にプッシュします。 エッジの重みが 1 の場合は、後ろに押します。 この順序により、すべてのコスト 0 の遷移が、同じ探索レベルでのコスト 1 の遷移より前に処理されることが保証されます。 
7. デキューが空になるまで続行します。 
8. 答えはノード N までの距離、または無限大のままの場合は -1 です。 

### なぜ効果があるのか

このアルゴリズムは、ノードが距離の減少しない順序で処理されるという特性を維持します。 重み 0 のエッジを緩和してもコストは増加しないため、結果の状態はできるだけ早く処理する必要があるため、前面に押し出されます。 重み 1 のエッジはコストを増加させるため、現在のすべてのゼロコスト拡張の​​後に待機する必要があります。 

すべてのエッジの重みは 0 または 1 のみであるため、最短パスは、この deque 規律によって遷移が正しく順序付けられたシーケンスに分解できます。 これにより、ノードが最初にファイナライズされる (ポップされる) ときに、その距離がすでに最小になっており、後で改善されることはないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, t = map(int, input().split())
    g[u].append((v, t))

INF = 10**18
dist = [INF] * (n + 1)
dist[1] = 0

dq = deque([1])

while dq:
    u = dq.popleft()
    for v, w in g[u]:
        nd = dist[u] + w
        if nd < dist[v]:
            dist[v] = nd
            if w == 0:
                dq.appendleft(v)
            else:
                dq.append(v)

print(-1 if dist[n] == INF else dist[n])
```隣接リストには、方向性を維持しながら、指定されたとおりに有向エッジが格納されます。 距離配列は、0 または 1 を繰り返し加算する際のオーバーフローの問題を回避するのに十分な大きさに初期化されます。 

デキュー操作は重要な実装の詳細です。appendleft は即時伝播を保証するために重み 0 のエッジにのみ使用されますが、append は処理を適切に遅らせるために重み 1 のエッジに使用されます。

 | --- | --- | --- |
 | 時間 | O(N + M) | 各ノードは緩和が成功するたびに最大 1 回両端キューにプッシュされ、各エッジは 1 回処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    n, m = map(int, sys.stdin.readline().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, t = map(int, sys.stdin.readline().split())
        g[u].append((v, t))

    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0

    dq = deque([1])
    while dq:
        u = dq.popleft()
        for v, w in g[u]:
            nd = dist[u] + w
            if nd < dist[v]:
                dist[v] = nd
                if w == 0:
                    dq.appendleft(v)
                else:
                    dq.append(v)

    return str(-1 if dist[n] == INF else dist[n])

 ## 特殊なケース

 エッジ ケースの 1 つは、コストが混在した複数のパスが存在し、単純な BFS がより悪い初期ルートを誤ってロックしてしまう場合です。 例えば：```
4 4
1 2 1
2 4 1
1 3 0
3 4 0
```正しいパスは、コスト 0 の 1 → 3 → 4 です。アルゴリズムは、エッジの重み 0 により、最初にノード 3 を前面に押し出すため、高コストのパスを拡張する前にゼロコスト チェーンを完全に伝播します。 ノード 2 からの 1 コストのルートが確定する前に、ノード 4 に距離 0 で到達します。 

もう 1 つのエッジ ケースは、完全な切断です。 ノード N に到達しない場合、その距離は無限大のままとなり、最終比較以降の明示的な到達可能性チェックを必要とせずに、アルゴリズムは正しく -1 を出力します。
