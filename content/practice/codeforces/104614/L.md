 ## 解決策
 ## 問題の理解

 私たちには、交通費とともに、指示された道路で結ばれた一連の倉庫が与えられます。 各倉庫は、最初はいくつかの種類の製品を数量保管します。 目標は、製品タイプごとに 1 つの倉庫が選択され、その製品のすべてのユニットが道路網内の最短ルートに沿って選択された倉庫に移動されるように、保管を「統合」することです。 総コストは、すべての製品の輸送量と、その製品のすべての輸送元倉庫から選択された輸送先倉庫までの最短経路距離の合計です。 

入力では 2 つのことが説明されます。 1 つ目は、行 i と列 j のエントリが現在倉庫 j に保管されている製品 i の数を示す行列です。 2 つ目は、倉庫上の重み付き有向グラフです。エッジの重みが欠落している可能性があります。つまり、直接の道路はありませんが、何らかのパスを介して接続が保証されています。 距離は対称ではないため、有向最短経路問題として扱う必要があります。 

出力は、各製品を個別の倉庫に割り当てた後の可能な最小総輸送コストです。 

n ≤ 1000 という制約により、O(n^2) または O(n^2 log n) の前処理の観点から考える必要が生じます。 製品ごとまたは割り当てごとに最短パスを繰り返し実行しようとするソリューションは、m が n と同じくらい大きくなる可能性があるため、遅すぎます。 

微妙な点は、コストは直接のエッジではなく、倉庫間の最短経路の距離のみに依存することです。 もう 1 つは、複数の製品が個別の倉庫をめぐって競合するため、製品 i を倉庫 j に割り当てるコストが事前に計算できる重み付き割り当て問題になります。 

素朴な読み方の間違いは、各製品を個別に最適な倉庫に貪欲に割り当てることができると想定することです。 2 つの製品が同じウェアハウスを優先する可能性があるため、これは失敗します。 

2 番目の間違いは、総当りの割り当てを試みることです。m 個の倉庫のすべての選択肢と製品のすべての並べ替えを試します。 最短経路を無視したとしても、これは組み合わせ爆発です。n から m を選択するとすでに C(n, m) が得られ、順列を追加すると m! が追加されますが、これは n = 30 の場合でも不可能です。 

## アプローチ

 重要な分離は、移動コストの計算と割り当ての最適化です。 

まず、製品 i の候補倉庫 j を決定します。 製品 i を j に割り当てるコストは、すべての倉庫 k の合計に amount[i][k] とshortest_path(k, j) を掛けたものになります。 これにより、ウェアハウス グラフ上のすべてのペアの最短パスを計算するという問題が軽減されます。 

n ≤ 1000 で、おそらく負の -1 エッジがあるが負のサイクルがない場合、Floyd-Warshall は実行可能ではありません (O(n^3) = 10^9 の演算は不可能の境界線です)。 代わりに、各ノードからダイクストラを実行し、疎なグラフまたは適度に密なグラフで許容される O(n (n log n + m)) を与えます。 

完全な距離行列 dist[k][j] が得られたら、上で定義したコスト [i][j] を使用して、左側に m 個の製品、右側に n 個の倉庫という 2 部構成の割り当てを構築します。 総コストを最小限に抑えるために製品ごとに個別の倉庫を選択する必要があります。これは、不等辺を持つ完全な 2 部グラフでの古典的な最小コストのマッチングです。 

m ≤ n であるため、実装のバリエーションに応じて、m x n のコスト行列で O(m^2 n) または O(n^3) のハンガリー アルゴリズムを実行できます。 n ≤ 1000 の場合、許容できる標準的な O(n^2 m) 形式に依存します。 

構造は次のとおりです。すべてのペアの最短パスを計算し、製品から倉庫までのコスト マトリックスを計算し、割り当てを解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース割り当て + 再計算 | 指数関数 | O(n^2) | 遅すぎる |
 | フロイド-ウォーシャル + 割り当て | O(n^3 + n^3) | O(n^2) | 遅すぎる |
 | 各ノードのダイクストラ + ハンガリー語 | O(n (E log n) + n^2 m) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、道路ネットワークを完全な最短経路距離行列に変換します。 各倉庫は一度ソースとして扱われ、ダイクストラを使用して他のすべての倉庫への最小移動コストが計算されます。 これをノードごとに行う理由は、保管商品の元の倉庫から可能な宛先の倉庫までの正確なコストが必要になるためです。 

次に、製品と倉庫間のコスト表を構築します。 固定製品 i と倉庫 j の場合、すべての倉庫 k を反復処理し、amount[i][k] に dist[k][j] を掛けた値を累積することで、合計送料を計算します。 これが機能するのは、k に保管されているすべてのユニットが独立して移動する必要があり、最短パスによって各ユニットの最適なルーティングが確保されるためです。 

この 2 部構成のコスト マトリックスを構築した後、割り当ての問題を解決します。各製品は個別の倉庫に一致する必要があり、各倉庫は最大 1 回しか使用できません。 これはまさに、完全な 2 部グラフにおける最小コストのマッチング問題です。 

ハンガリーアルゴリズムを適用します。 左側と右側の可能性を維持し、コストを削減したエッジで拡張パスを見つけることでマッチングを段階的に改善します。 各反復では、以前の割り当ての実現可能性を維持しながら、さらに 1 つの製品を倉庫に最適に固定します。 

### なぜ効果があるのか

 正しさは 2 つの分離に依存します。 まず、最短パスは移動コストをユニットごとに個別に分解するため、dist の事前計算によってすべてのルーティング決定が完全に取り込まれます。 第 2 に、コストが固定されると、残る問題は線形加算構造による純粋な組み合わせ割り当てになります。 最適なソリューションは、製品と倉庫の完全なマッチングに対応する必要があり、ハンガリーのアルゴリズムは、拡張全体を通じて二重の実現可能性と補完的な緩みを維持することにより、グローバルな最適性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**30

def dijkstra(src, n, graph):
    dist = [INF] * n
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def hungarian(cost):
    n = len(cost)
    m = len(cost[0])
    u = [0] * (n + 1)
    v = [0] * (m + 1)
    p = [0] * (m + 1)
    way = [0] * (m + 1)

    for i in range(1, n + 1):
        p[0] = i
        minv = [INF] * (m + 1)
        used = [False] * (m + 1)
        j0 = 0

        while True:
            used[j0] = True
            i0 = p[j0]
            delta = INF
            j1 = 0

            for j in range(1, m + 1):
                if not used[j]:
                    cur = cost[i0 - 1][j - 1] - u[i0] - v[j]
                    if cur < minv[j]:
                        minv[j] = cur
                        way[j] = j0
                    if minv[j] < delta:
                        delta = minv[j]
                        j1 = j

            for j in range(m + 1):
                if used[j]:
                    u[p[j]] += delta
                    v[j] -= delta
                else:
                    minv[j] -= delta

            j0 = j1
            if p[j0] == 0:
                break

        while True:
            j1 = way[j0]
            p[j0] = p[j1]
            j0 = j1
            if j0 == 0:
                break

    ans = -v[0]
    return ans

def main():
    n, m = map(int, input().split())

    amount = []
    for _ in range(m):
        amount.append(list(map(int, input().split())))

    graph = [[] for _ in range(n)]
    for i in range(n):
        row = list(map(int, input().split()))
        for j, w in enumerate(row):
            if w != -1 and i != j:
                graph[j].append((i, w))

    dist = [dijkstra(i, n, graph) for i in range(n)]

    cost = [[0] * n for _ in range(m)]
    for i in range(m):
        for j in range(n):
            s = 0
            dij = dist[j]
            for k in range(n):
                if amount[i][k]:
                    s += amount[i][k] * dij[k]
            cost[i][j] = s

    print(hungarian(cost))

if __name__ == "__main__":
    main()
```最初のブロックは積分布行列と有向グラフを読み取り、欠落しているエッジを隣接リスト形式に注意深く変換します。 サンプル形式では列がソースとしてインデックス付けされるため、グラフは入力で指定されたとおりに逆向きで保存されます。 

ダイクストラ関数は、各ウェアハウスからの最短パスを計算します。 すべてのコストがすべてのペアごとの距離に依存するため、これが必要になります。 

コスト マトリクスの構築は変換ステップの中核です。各製品行はすべてのソース倉庫にわたって集約され、保管数量に最短経路距離を掛け合わせます。 

最後に、ハンガリーの実装では最小コストの割り当てが実行されます。 標識規約により、配送コストの合計を最小限に抑えることができます。

 ## 特殊なケース

 主なエッジケースは、倉庫にすべての製品の在庫がゼロの場合です。 アルゴリズムには依然として潜在的な目的地としてそれが含まれていますが、距離がゼロの場合にのみ、すべての製品のコスト列がゼロになります。これは、自明なセルフエッジでない限り起こりません。 割り当てステップでは、グローバル コストが改善されない限り、そのようなノードは当然回避されます。 

もう 1 つのエッジ ケースは、直接エッジは切断されているが、間接パスは接続されている場合です。 ダイクストラ フェーズでは、到達不能な直接エッジがマルチホップの最短パスに置き換えられるため、これらが正しく処理されることが保証されます。 

最後に、複数の倉庫が製品の最適な仕向け先である場合、最小コストのマッチングが有効であるため、ハンガリーのアルゴリズムは最適性に影響を与えることなく二重調整を通じて一貫して関係を解決します。
