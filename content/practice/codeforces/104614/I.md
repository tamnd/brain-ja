 ## 解決策
 ## 問題の理解

 都市は無向の重み付きグラフとしてモデル化されています。 各交差点は頂点であり、各道路はその長さを重みとするエッジです。 市長はいつも交差点から移動します`a`交差点まで`b`、パットは、これら 2 つの場所間の少なくとも 1 つの最短パスに属する道路のみを舗装したいと考えています。 

課題は、最短経路を 1 つ見つけることではありません。 道路を使用する最短経路が存在する場合、その道路は舗装される必要があります。 残りの道路はすべて不要なので、それらの長さの合計を出力する必要があります。 

グラフには最大 100 個の頂点が含まれますが、ステートメントでは道路の数に制限はありませんが、単純な無向グラフのエッジの数を超えることはできません。`n(n-1)/2`。 最も密度の高いグラフでもエッジは 5000 未満です。 これらの制限は十分に小さいため、ダイクストラのアルゴリズムを数回実行することは完全に実用的です。 より複雑な最短経路データ構造は必要ありません。 

主な問題は、異なる最短ルートが複数存在する可能性があることです。 最短パスを 1 つだけ再構築するソリューションでは、別の同様に短いルートに属する道路を見逃してしまいます。 

次のグラフを考えてみましょう。```
4 4 1 4
1 2 1
2 4 1
1 3 1
3 4 1
```正しい出力は次のとおりです```
0
```両方のルートから`1`に`4`長さがある`2`したがって、すべての道路は何らかの最短経路に属します。 ダイクストラ中に 1 つの親のみを保存するソリューションでは、1 つのルートのみが誤ってマークされ、出力されます。`2`。 

もう 1 つの微妙なケースは、直接エッジがより長い代替エッジと一緒に存在する場合です。```
3 3 1 3
1 2 2
2 3 2
1 3 4
```正しい出力は次のとおりです```
0
```どちらのパスにも全長があります`4`, そのため、すべての端を舗装する必要があります。 厳密に短い代替手段のみを探すと、直接道路が誤って除外されてしまいます。 

最後のエッジケースは、道路がどの最短経路にも現れない可能性がある場合に発生します。```
3 3 1 3
1 2 1
2 3 1
1 3 5
```正しい出力は次のとおりです```
5
```長い直接エッジは決して役に立たないため、その長さが答えに貢献します。 

## アプローチ

 簡単なアイデアは、すべての道路を個別にテストすることです。 道路を削除し、最短パスを計算してから、道路をパスに強制的に挿入し、結果の距離が全体的な最適値と等しいかどうかを確認します。 これは、すべてのエッジが個別に検査されるため機能しますが、すべての道路に対して最短パス アルゴリズムを実行する必要があります。 およそ 5000 のエッジと各ダイクストラが取られる`O(m log n)`、合計作業量は次のようになります。`O(m² log n)`、これらの制約があっても不要です。 

重要な観察は、エッジが最短パスに属するかどうかは 2 つの端点からの距離のみに依存するということです。 

エッジが接続されていると仮定します`u`そして`v`重さで`w`。 ～からの最短距離がすでにわかっている場合`a`すべての頂点へ、そしてすべての頂点から`b`そうすると、考えられる両方の方向をすぐにテストできます。 

次のいずれかの場合、エッジは最短パス上に表示されます。`distA[u] + w + distB[v] == distA[b]`または`distA[v] + w + distB[u] == distA[b]`。 

最初の方程式は到達に対応します。`u`、エッジを横切って、`v`、続いて`b`。 2 番目の関数は、グラフの方向が決まっていないため、反対の方向を処理します。 

これにより、問題は 2 回のダイクストラ実行と、それに続くエッジ リストの 1 回のスキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(m² log n)`|`O(n + m)`| 遅すぎる |
 | 最適 |`O(m log n)`|`O(n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 無向重み付きグラフの隣接リストを構築し、同時にすべてのエッジを別個のリストに保存します。 隣接リストはダイクストラによって使用されますが、エッジ リストは最終スキャンに必要です。 
2. 市長の家からディクストラを走らせる`a`。 ～からの最短距離を記録する`a`配列内のすべての頂点に`distA`。 
3.市長室から再びディクストラを実行します。`b`。 ～からの最短距離を記録する`b`配列内のすべての頂点に`distB`。 
4. しましょう`best = distA[b]`、これは 2 つの場所間のすべての最短ルートの長さです。 
5. すべての道路を調べる`(u, v, w)`一度。 どちらかを確認してください`distA[u] + w + distB[v]`または`distA[v] + w + distB[u]`等しい`best`。 
6. どちらの等式も当てはまらない場合、この道路を含む最短経路は存在しないため、その長さを答えに加算します。 
7. 累積合計を出力します。 

### なぜ効果があるのか

 最初のダイクストラは、最初からすべての頂点に到達するための最小コストを計算します。 2 つ目は、すべての頂点から目的地までの可能な最小残りコストを計算します。 

エッジが最短パスに属しているとします。 そのパスを横断すると、1 つの終点に最適に到達し、エッジを越えて、目的地に最適に到達します。 そうしないと、パスが短縮される可能性があります。 したがって、2 つの等式のうちの 1 つが成り立つ必要があります。 

逆に、いずれかの等式が成り立つ場合、最初の端点までの最短パス、エッジ自体、および 2 番目の端点からの最短パスを連結すると、全長が全体的な最適値に等しいパスが生成されます。 したがって、エッジは少なくとも 1 つの最短パス上にあります。 

このテストは必要かつ十分であるため、すべての道路が正しく分類されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def dijkstra(start, graph, n):
    INF = 10 ** 18
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    n, m, a, b = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        graph[u].append((v, w))
        graph[v].append((u, w))
        edges.append((u, v, w))

    distA = dijkstra(a, graph, n)
    distB = dijkstra(b, graph, n)

    shortest = distA[b]
    ans = 0

    for u, v, w in edges:
        if (distA[u] + w + distB[v] == shortest or
                distA[v] + w + distB[u] == shortest):
            continue
        ans += w

    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションはアルゴリズムに直接に従います。 グラフは 2 回保存されます。1 回目は効率的な最短経路計算のための隣接リストとして、もう 1 回はプレーン エッジ リストとして保存されるため、すべての道路を 1 回だけチェックできます。 

ダイクストラ実装では、標準の遅延優先キュー技術が使用されます。 古いエントリがヒープから削除されると、そのエントリの距離と現在の最良の値が比較され、そのエントリは無視されます。 

最終スキャンでは、すべての無向エッジに対して 2 つの等価性テストが実行されます。 最短パスはどちらの方向でもエッジを横切る可能性があるため、両方の方向を確認することが重要です。 Python の整数には任意の精度があるため、複数の距離を合計する場合でもオーバーフローの危険はありません。

## テストケース```python
import sys
import io
import heapq

def solve():
    input = sys.stdin.readline

    n, m, a, b = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        graph[u].append((v, w))
        graph[v].append((u, w))
        edges.append((u, v, w))

    def dijkstra(s):
        INF = 10 ** 18
        dist = [INF] * (n + 1)
        dist[s] = 0
        pq = [(0, s)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in graph[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    da = dijkstra(a)
    db = dijkstra(b)
    best = da[b]

    ans = 0
    for u, v, w in edges:
        if da[u] + w + db[v] == best or da[v] + w + db[u] == best:
            continue
        ans += w
    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 最初の自明ではないケースは、複数の最短パスです。```
4 4 1 4
1 2 1
2 4 1
1 3 1
3 4 1
```最短距離は`2`。 各エッジについて、2 つの等価性チェックのうち 1 つが成功するため、すべてのエッジは最短パスに属するものとして分類されます。 アルゴリズムの出力`0`一方、親ベースの再構成ではエッジの半分が誤って破棄されてしまいます。 

2 番目のケースは、2 つのまったく異なるルートの全長が同じである場合です。```
3 3 1 3
1 2 2
2 3 2
1 3 4
```最短距離は`4`。 直接エッジと 2 エッジ ルートの両方が等価性テストを満たしているため、3 つの道路はすべて舗装されており、答えは次のようになります。`0`。 

最後のケースには、他のすべての選択肢よりも厳密に悪い道路が含まれています。```
3 3 1 3
1 2 1
2 3 1
1 3 5
```最短距離は`2`。 ロングエッジが生み出す`0 + 5 + 0 = 5`、これは最適値よりも大きいため、どちらの等式も成り立ちません。 その長さが答えに追加され、正しい出力が生成されます。`5`。
