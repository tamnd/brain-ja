 ## 解決策
 ## 問題の理解

 2 枚の同一の CD の固定容量と曲の長さのリストが与えられます。 各 CD には最大でも収納できます`c`数分間の音楽で、すべての曲を最大 1 枚の CD に入れることも、完全にスキップすることもできます。 目標は、曲のサブセットを選択し、それらを 2 つのグループに分割して、どちらのグループも次の値を超えないようにすることです。`c`、両方の CD で選択した曲の再生時間の合計を最大化します。 

出力は単なる合計ではなく、2 枚の CD の実際に達成されたフィル レベルです。 両方の値を大きい方から出力する必要があります。複数の割り当てで合計が同じになる場合には、2 つの CD フィルの差ができるだけ小さい方を優先します。 

制約は次のことを示しています`c ≤ 1000`そして`n ≤ 1000`これは、擬似多項式動的プログラミング ソリューションが実行可能であることを直ちに示唆しています。 最大 1000 の容量と最大 1000 のアイテムを含む状態空間は、約 10^6 の状態になります。これは、遷移が適切に構造化されていれば、Python で快適に実現可能です。 

微妙な問題は、単一のナップザックを最適化しているのではなく、同じアイテム セットを共有する 2 つのナップザックを最適化していることです。 単純なアプローチでは、独立したパッキングを誤って想定する可能性がありますが、各曲は世界で 1 回しか使用できないため、2 枚の CD 間のカップリングは不可欠です。 

すべての曲が次のサイズよりも大きい場合、例外的なケースが 1 つ発生します。`c`、この場合、答えは次のようになります。`0 0`。 もう 1 つは、多くの組み合わせの合計が同じであるが分割が異なる場合に発生し、任意の分割ではなく差を最小限に抑えて正しいタイブレークを必要とする場合です。 

## アプローチ

 ブルートフォース手法では、曲のすべてのサブセットが考慮され、各曲を CD1、CD2 のいずれかに割り当てるか、破棄します。 のために`n`これにより、3^n 通りの可能性が生成され、n = 1000 と天文学的に大きくなります。枝刈りを行っても、各決定が構造を持たずに 3 つの独立した選択肢に分岐するため、状態空間は指数関数的なままになります。 

重要な観察は、CD2 のフィルは、選択された合計から CD1 のフィルを差し引いたものから推測できるため、唯一の関連する状態は、曲の一部のプレフィックスを処理した後の CD1 のフル状態であるということです。 これにより、問題は 2 つの独立したビンの追跡から 1 つのビンとグローバル合計制約の追跡に軽減されます。 

動的プログラミング テーブルを定義できます。`dp[a]`CD1 が正確に満たされている場合に達成可能な最大合計値を格納します。`a`。 すべての曲はスキップするか、CD1 (収まる場合) に入れるか、CD2 に入れることができます。 CD2に入れても直接変化しない`a`, ただし総和が大きくなるため、遷移を通じて間接的に補填能力を考慮して対応する。 

これにより、問題は階層化されたナップザックに変わり、境界のある 2 つのコンテナ間の合計の分布を追跡し、状態を注意深く解釈して 2 次元のパッキングを 1 次元の DP に分解します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 最適なDP | O(n·c²) | O(c) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、2 つの容量のナップザックにアイテムを分配するものとして再解釈します。`c`それぞれ。 私たちは DP テーブルを維持します。`dp[i][a]`最初に考慮した後に達成可能な最大総重量です。`i`曲、CD1保持付き`a`分。 CD2 の使用法は暗黙的です: 合計が`S`、その後 CD2 が保持されます`S - a`、これは ≤ である必要があります`c`。 

容量を超えてスペースを 2D 配列に最適化します。 

### ステップ

 1. DP 配列を初期化する`dp[a][b] = -inf`、CD1 = の使用を表します。`a`および CD2 =`b`。 セット`dp[0][0] = 0`。 

これは、最初は曲が取り込まれておらず、両方の CD が空であることをエンコードします。 
2. 曲の長さごとに`x`、次のように初期化された新しい DP レイヤーを作成します。`-inf`。 
3. 到達可能なすべての状態について`(a, b)`:

 - 曲をスキップ: そのまま`(a, b)`変わらない。 
- CD1 に曲を入れる場合`a + x ≤ c`、に移行します`(a + x, b)`合計が増加しました。 
- CD2 に曲を入れる場合`b + x ≤ c`、に移行します`(a, b + x)`。 

各移行では、容量制約の実現可能性が維持されます。 
4.すべての曲を処理した後、すべての状態をスキャンします`(a, b)`そして次に従って最適なペアを計算します。 

- 最大化`a + b`- 同点の場合は最小化します`|a - b|`5. 選択した値の大きいペアを最初に出力します。 

### なぜ効果があるのか

 DP の不変条件は、曲の各プレフィックスを処理した後、`dp[a][b]`正確にそれらの塗りつぶしを使用して、達成可能な最大合計を正確に表します。 すべての曲は 1 回だけとみなされ、CD へのすべての有効な曲の割り当ては、DP トランジションを通る 1 つのパスに正確に対応します。 トランジションでは曲ごとに 3 つの選択肢がすべて列挙されるため、有効な設定が失われることはなく、無効な設定は容量チェックによって除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    c, n = map(int, input().split())
    songs = list(map(int, input().split()))

    NEG = -10**9

    dp = [[NEG] * (c + 1) for _ in range(c + 1)]
    dp[0][0] = 0

    for x in songs:
        ndp = [row[:] for row in dp]
        for a in range(c + 1):
            for b in range(c + 1):
                if dp[a][b] < 0:
                    continue

                val = dp[a][b] + x

                if a + x <= c:
                    if val > ndp[a + x][b]:
                        ndp[a + x][b] = val

                if b + x <= c:
                    if val > ndp[a][b + x]:
                        ndp[a][b + x] = val

        dp = ndp

    best_sum = 0
    best_a, best_b = 0, 0

    for a in range(c + 1):
        for b in range(c + 1):
            if dp[a][b] < 0:
                continue
            total = dp[a][b]
            if total > best_sum or (total == best_sum and abs(a - b) < abs(best_a - best_b)):
                best_sum = total
                best_a, best_b = a, b

    if best_a < best_b:
        best_a, best_b = best_b, best_a

    print(best_a, best_b)

if __name__ == "__main__":
    solve()
```両方の CD が均等に制限され、小さいため、この実装では完全な 2D DP テーブルが保持されます。 コピー先`ndp`更新は同じ反復に影響を与えないため、各曲が 1 回だけ使用されるようになります。 大きなネガティブ センチネルを使用すると、到達不可能な状態と有効な状態が明確に分離されます。 

最後の選択ステップでは、合計使用量を最大化した後、必要なタイブレークを明示的に強制します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    c, n = map(int, inp.splitlines()[0].split())
    arr = list(map(int, inp.splitlines()[1].split()))

    NEG = -10**9
    dp = [[NEG] * (c + 1) for _ in range(c + 1)]
    dp[0][0] = 0

    for x in arr:
        ndp = [row[:] for row in dp]
        for a in range(c + 1):
            for b in range(c + 1):
                if dp[a][b] < 0:
                    continue
                val = dp[a][b] + x
                if a + x <= c:
                    ndp[a + x][b] = max(ndp[a + x][b], val)
                if b + x <= c:
                    ndp[a][b + x] = max(ndp[a][b + x], val)
        dp = ndp

    best_sum = 0
    best = (0, 0)
    for a in range(c + 1):
        for b in range(c + 1):
            if dp[a][b] < 0:
                continue
            if dp[a][b] > best_sum or (dp[a][b] == best_sum and abs(a - b) < abs(best[0] - best[1])):
                best_sum = dp[a][b]
                best = (a, b)

    a, b = best
    if a < b:
        a, b = b, a
    return f"{a} {b}"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、どの CD にも適合する曲の組み合わせがない場合です。 その場合、すべての DP 状態は無効のままになります。`(0,0)`、アルゴリズムは正しく出力します`0 0`。 最終スキャンでは、これより良い合計は見つかりません。 

もう 1 つのケースは、多くの曲が個別には適合するものの、どの組み合わせでも 1 枚の CD を超え、もう 1 枚の CD は十分に使用されないままになる場合です。 DP はこれを自然に処理します。これは、各曲が両方の CD で個別にテストされ、オーバーフィルが防止されるためです。 

最後の微妙なケースはタイブレークです。 2 つの構成が同じ合計を達成するが、分布が異なると仮定します。`(100,80)`そして`(95,85)`。 両方合計すると180になりますが、`(95,85)`差が小さいため選択されます。 最終スキャンでは、DP の完了後にこのルールが明示的に適用され、DP 自体はバランス設定ではなく合計のみを追跡しますが、正確性が保証されます。
