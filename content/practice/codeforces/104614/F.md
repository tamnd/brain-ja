 ## 解決策
 ## 問題の理解

 私たちは、年の長さが現地の日数の正確な整数ではない架空の惑星のために、簡略化された「うるう年システム」を設計するように求められています。 

物理学から、入力により、惑星が星の周りを 1 周するのにかかる時間を計算するのに十分な情報が得られます。 軌道は円形であると想定されているため、総移動距離は円周に比例し、軌道速度で割ると公転周期が時間で求められます。 これを現地の日数に変換すると (1 日は時間で表されるため)、実数値が得られます。これは、「惑星日数」で測定される真の熱帯の年と考えることができます。 

タスクは、グレゴリオ暦に似た暦規則を使用して、この実数を近似することです。 まず、熱帯の年を最も近い整数に四捨五入し、同数を切り上げて、基本整数の年間日数を選択します。 次に、3 つの整数 n1、n2、n3 で定義される周期補正システムを導入します。ここで、n1 は n2 を除算し、n2 は n3 を除算し、n3 は最大 1000 になります。これらの規則は、長さ n3 年のサイクル内で閏年の繰り返しパターンを作成します。ここで、特定の年は、割り算に応じて余分な 1 日を加算または減算します。 

目標は、結果として得られる平均暦年の長さが真の熱帯年にできるだけ近くなるように、n1、n2、n3 を選択することです。 

n3 の上限が 1000 であるため、組み合わせ部分の制約は小さくなります。これは重要な構造制約であり、候補サイクル構造を列挙することができます。 大きな値は熱帯年の物理計算にのみ現れますが、その部分は O(1) です。 

素朴な解釈では、連続最適化または数論反転を示唆するかもしれませんが、n3 の離散境界により、除数チェーンの検索が強制されます。 

微妙なエッジケースは丸めのステップにあります。 熱帯年がちょうど x.5 の場合は、切り上げなければなりません。 ここでの間違いにより d が 1 変化し、すべての補正項の方向が反転し、まったく異なる最適な構造が得られます。 もう 1 つの落とし穴は、閏年のルールでは、基本の四捨五入が切り捨てられるか切り上げられるかによって、1 日を加算または減算するかどうかが変わることを忘れていることです。 

## アプローチ

 この強引なアイデアは、熱帯年 T を計算し、有効なトリプル (n1、n2、n3) をすべて試行することです。 各トリプルについて、長さ n3 の全サイクルにわたってカレンダー ルールをシミュレートし、余分な日または欠落した日が何日挿入されるかを計算し、平均年の長さを導き出します。 

サイクル内で毎年検査するため、各候補についてこのシミュレーションには O(n3) 時間がかかります。 n3 は最大 1000 であり、すべての除数チェーンを試す可能性があるため、これはすぐに遅くなりすぎます。 最悪の場合、n1 には約 1000、n2 には約 1000、n3 には約 1000 の選択肢があり、最大 10^9 の状態が得られ、それぞれのコストは O(1000) であり、制限をはるかに超えています。 

重要な観察は、カレンダー ルールの構造により、平均がシミュレーションではなく割り算カウントによって完全に決定されるということです。 長さ n3 の全サイクルにわたって、n1、n2、および n3 で割り切れる年数は、フロア除算を使用して直接計算できます。 ネストされた可分性制約により、包含-排他は単純な閉じた形式に折りたたまれます。 これにより、各候補の評価が O(1) に減り、列挙が可能になります。 

そこで、年をシミュレートする代わりに、サイクルごとに予想される修正を分析的に計算し、それを実際の熱帯年と比較します。

 ## アルゴリズムのチュートリアル

 ### 1. 軌道周期を計算する

 円運動を使用して熱帯年を時間単位で計算します。 軌道の長さは半径に比例するので、次のようにします。$2\pi r$円周の近似値として、速度 s で割って 1 周あたりの時間を取得し、h で割って現地の日数に変換します。 これにより実数 T が得られます。 

### 2. 暦基準年に変換する

 T を最も近い整数に丸め、0.5 を切り上げて d を計算します。 これにより、ベースラインの年の長さが定義されます。 

これが重要な理由は、すべての修正ロジックがこの整数アンカーに関連しているためです。 

### 3. 修正方向の決定

 T が切り捨てられた場合、閏年には +1 日が加算されます。 T を切り上げた場合、閏年から 1 日が減算されます。 

この選択により、補正項の符号が決まります。 

### 4. 除数チェーンを列挙する

 最大 1000 までの有効な n1 をすべて繰り返します。n1 ごとに、すべての倍数 n2 を繰り返します。 各 n2 について、1000 までのすべての倍数 n3 を繰り返します。 

この構造は制約 n1 | を尊重します。 n2 | n3.

 ### 5. 計算サイクルの修正

 長さ n3 のサイクルの場合:

 整数の除算を使用して、各制約で何年で割り切れるかを計算します。 

以下を定義します。 

- count(n1) = n3 // n1
 - count(n2) = n3 // n2
 - count(n3) = n3 // n3 = 1

 入れ子になっているため、実際のうるう年の数は次のようになります。 

カウント(n1) - カウント(n2) + カウント(n3)

 このような各年は、丸めの方向に応じて +1 または -1 のいずれかに寄与します。 

したがって、サイクル全体の修正の合計は次のようになります。 

補正 = 符号 × (カウント(n1) - カウント(n2) + カウント(n3)) / n3

 ### 6. 目標と比較する

 候補年の長さを計算します。 

cand = d + 補正

 絶対誤差 |cand − T| を最小化します。 

### なぜ効果があるのか

 不変条件は、すべての有効なカレンダーが周期 n3 で周期的であり、その周期内では閏規則の寄与が可算数のみに依存するということです。 ルールは構造 (n1 | n2 | n3) によってネストされているため、包含と除外は正確であり、重複の曖昧さは存在しません。 したがって、年間の平均補正は、n1、n2、n3 の単純な算術によって完全に決定され、列挙はすべての可能性をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, s, h = map(int, input().split())

    # tropical year in days
    # orbital period (hours) = 2πr / s
    # convert to planet days: divide by h
    T = (2.0 * 3.141592653589793 * r) / (s * h)

    # rounding with .5 up
    d = int(T + 0.5)

    # direction of leap adjustment
    # if rounded down => add leap days
    # if rounded up   => subtract leap days
    if T >= d:
        sign = 1.0   # rounded down or exact integer
    else:
        sign = -1.0  # rounded up

    best = float("inf")
    ans = (1, 2, 3)

    for n1 in range(2, 1001):
        for n2 in range(n1 * 2, 1001, n1):
            for n3 in range(n2 * 2, 1001, n2):
                cnt1 = n3 // n1
                cnt2 = n3 // n2
                cnt3 = 1

                leaps = cnt1 - cnt2 + cnt3

                avg = d + sign * (leaps / n3)

                err = abs(avg - T)

                if err < best:
                    best = err
                    ans = (n1, n2, n3)

    print(ans[0], ans[1], ans[2])

if __name__ == "__main__":
    solve()
```T の計算により、軌道モデルが直接エンコードされます。 丸めステップは、次を使用して上方丸めに偏りながら慎重に実装されます。`+0.5`。 符号処理は、閏年によって日数が加算または減算される 2 つの体制を分離します。これは、最適化の方向を反転させるため重要です。 

トリプル ループは、n2 を n1 の倍数で、n3 を n2 の倍数でステップ実行することにより、自然に割り算の制約を強制します。 これにより、明示的な gcd チェックが回避され、すべての候補の有効性が保証されます。 

補正式は、年間挙動のシミュレーションを閉じた形式のカウントに置き換えます。これにより、ソリューションが十分に高速になります。

 ## 特殊なケース

 特殊なケースの 1 つは、熱帯年が整数プラス 0.5 に非常に近い場合です。 この状況では、丸め動作が不安定になります。 比較 T >= d で一貫して符号が定義され、修正方向が丸め規則と一致することが保証されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、n1 = 2 が最適で、n2、n3 が大きな倍数として増加する場合です。 n2 と n3 は密度の制限なしで倍数として生成されるため、列挙ではこれもカバーされます。 

最後のケースは、T が正確に整数の場合です。 この場合、d は T に等しく、符号ブランチはそれを非負として扱い、最適な構造は自然に補正の大きさを最小化する方向に崩壊し、列挙はそれを正しく捕捉します。
