 ## 解決策
 ## 問題の理解

 長方形の迷路と、初期方向を持つ異なるセルに配置された 2 台のロボットが与えられます。 迷路は、特定のセルの南側の境界にある 1 つの出口を除いて、内壁と外側の境界によって移動がブロックされている格子です。 

両方のロボットがまったく同じコマンドを同時に受信します。 各コマンドは前進または回転のいずれかであり、回転のコストは無料です。 前進コマンドが発行されると、両方のロボットは現在の方向に 1 歩移動しようとします。 ロボットが壁に面している場合、ロボットは動かず、代わりに衝突を認識します。 南を向いたまま指定された出口セルを通ってグリッドの外に移動すると、迷路を出て、以降のコマンドの影響を受けなくなります。 

目標は、最終的に両方のロボットを脱出させる一連の順方向コマンドを送信することです。 まず順方向コマンドの数を最小限に抑え、すべての最適解の中でバンプの総数を最小限に抑えます。 重要な制限は、ロボットがどちらかが退出する前のどの時点でも同じセルを占有することができないことです。 

グリッドは最大 50 x 50 なので、セルの数は最大 2500 個になります。 2 台のロボットを使用すると、単純な関節位置空間はすでに約 600 万状態に達し、方向を含めるとさらに大きくなります。 これにより、コマンド シーケンスに対する指数関数的なシミュレーションが即座に排除されます。 

微妙な特殊なケースは、共有された移動ルールから生じます。 両方のロボットが順方向コマンドによって同じセルに押し込まれた場合、たとえ異なる方向から到着したとしても、その状態は無効になるため、回避する必要があります。 もう 1 つのエッジ ケースは、出口動作です。ロボットは、指定された出口セルにいて南に移動する場合にのみ出口になります。 出口のセルに立っているだけでは十分ではありません。 

## アプローチ

 直接シミュレーションでは、コマンドのシーケンスを検索しようとします。 各状態にはロボットの位置と方向の両方が含まれ、各ステップは 3 つの可能なコマンドに分岐します。 順方向コマンドは重要な方法 (ブロック、バンピング、および終了の可能性) で相互作用するため、これはすぐに大規模な分岐プロセスになります。 指示を無視しても、答えに至るまでの長さのすべてのシーケンスを探索すると、指数関数的な爆発が起こります。 

重要な簡素化は、回転コマンドが無料であるという事実から来ています。 両方のロボットが常に一緒に回転するため、特定の方向に永続的に「コミット」することを強制されることはありません。 前進コマンドを実行する前に、ゼロコストでシステムを任意に回転させることができます。つまり、各前進ステップは 4 つのコンパスの方向から方向を選択し、それを即座に適用するものとして解釈できます。 

これにより、方向履歴を追跡する必要がなくなります。 代わりに、各状態は各ロボットが現在どこにいるか (またはすでに終了したかどうか) を記憶するだけで済みます。 どの状態からでも、可能な 4 つの順方向をすべて試すことができます。 

これにより、問題は最短経路探索に変換され、各状態遷移には前方コマンドごとに 1 のコストがかかり、その移動によって発生するバンプの数に等しい 2 次コストがかかります。 すべてのエッジには非負の重みがあり、辞書編集上の最小距離が必要であるため、結合状態空間に対するダイクストラのアルゴリズムが適切です。 

状態空間は位置のペアで構成され、ロボットごとに追加の「アウト」マーカーが含まれます。 これにより、最大で約 (2501 × 2501) 個の状態が生成されます。これは大きいですが、プルーニングと効率的なハッシュまたはインデックス付けにより実現可能です。 各状態には最大 4 つの発信遷移があります。

 ## アルゴリズムのチュートリアル

私たちは迷路を、動きのクエリにすぐに答えられる構造に変換します。すべてのセルと方向について、動きが壁や境界によって妨げられているかどうかがわかります。 

次に、組み合わせたロボット構成に対して最短経路アルゴリズムを実行します。 

### ステップ

 1. 各ロボットの状態をグリッド セルまたは「終了」マーカーとして表します。 完全な状態はこれらのペアです。 これにより、システムに関するすべての関連情報がいつでも圧縮されます。 
2. 壁ルックアップ テーブルを構築して、どのセルからでも北、南、東、西への移動がブロックされているかどうかを確認できるようにします。 出口側は特別に扱われます。出口セルの南端はそのセルに対してのみ開いています。 
3. ダイクストラアルゴリズムの優先キューを初期化します。 初期状態は、両方のロボットの所定の開始位置であり、前進コマンドもバンプもありません。 
4. ポップされた状態ごとに、可能な 4 つの順方向すべてを試みます。 各方向について、両方のロボットを同時にシミュレートします。 

ロボットがすでにアウトになっている場合、そのロボットはアウトのままになります。 

ロボットが迷路内にあり、その方向に移動できる場合、ロボットは移動します。 

壁のせいで動けない場合は、その場に留まり、衝突とみなされます。 

出口セルにいて南に移動しようとすると、留まらずに出ていきます。 
5. 移動後に両方のロボットが同じセルを占有し、どちらも外に出ていない場合は、この遷移を破棄します。 これにより、不正な重複構成が防止されます。 
6. 有効な結果の状態ごとに、そのコストのペアを更新します。 主キーは転送コマンドの数、副キーは合計バンプです。 この状態が最もよく知られているペアを改善する場合は、優先キューにプッシュします。 
7. ダイクストラが最適性を保証しているため、両方のロボットがアウトしている状態に初めて到達したときに停止します。 

### なぜ効果があるのか

 どの時点でも、アルゴリズムは、優先キューが辞書編集上の昇順 (前方コマンド、バンプ) で状態を探索するという不変条件を維持します。 すべての遷移は、両方のロボットに一貫して適用される 1 つのグローバルな前方コマンドに正確に対応します。 回転は自由であるため、方向履歴を無視することによって有効な動作が除外されることはありません。 初めて両方のロボットがアウトとしてマークされると、全体的に最適なシーケンスが見つかりました。これは、その後の発見には少なくとも同量の前進ステップが必要であり、タイはバンプによってすでに最小化されているためです。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

# directions: N, E, S, W
dx = [0, 1, 0, -1]
dy = [1, 0, -1, 0]

def solve():
    c, r, e = map(int, input().split())

    c1, r1, d1, c2, r2, d2 = input().split()
    c1, r1 = int(c1)-1, int(r1)-1
    c2, r2 = int(c2)-1, int(r2)-1

    dir_map = {'N':0,'E':1,'S':2,'W':3}

    # walls
    horiz = [[False]*r for _ in range(c)]   # between (x,y) and (x,y+1)
    vert = [[False]*r for _ in range(c)]    # between (x,y) and (x+1,y)

    parts = list(map(int, input().split()))
    n = parts[0]
    idx = 1
    for _ in range(n):
        x = parts[idx]-1
        y = parts[idx+1]-1
        idx += 2
        horiz[x][y] = True

    parts = list(map(int, input().split()))
    n = parts[0]
    idx = 1
    for _ in range(n):
        x = parts[idx]-1
        y = parts[idx+1]-1
        idx += 2
        vert[x][y] = True

    exit_x = e - 1
    exit_y = 0  # row 1

    def move(x, y, d):
        if x == -1:
            return (-1, 0, 0)  # already out

        nx, ny = x + dx[d], y + dy[d]

        # exiting condition
        if x == exit_x and y == exit_y and d == 2:
            return (-1, 0, 0)

        bump = 0

        # boundary / wall checks
        if nx < 0 or nx >= c or ny < 0 or ny >= r:
            return (x, y, 1)

        # horizontal walls
        if d == 0 and horiz[x][y]:
            return (x, y, 1)
        if d == 2 and horiz[x][y-1]:
            return (x, y, 1)

        # vertical walls
        if d == 1 and vert[x][y]:
            return (x, y, 1)
        if d == 3 and vert[x-1][y]:
            return (x, y, 1)

        return (nx, ny, 0)

    def encode(x1, y1, x2, y2):
        return ((x1+1)*(r+1)+y1) * ((c+1)*(r+1)) + (x2+1)*(r+1)+y2

    INF = (10**18, 10**18)
    dist = {}

    start = (c1, r1, c2, r2)
    pq = [(0, 0, c1, r1, c2, r2)]
    dist[start] = (0, 0)

    while pq:
        f, b, x1, y1, x2, y2 = heapq.heappop(pq)

        if dist.get((x1,y1,x2,y2), INF) != (f, b):
            continue

        if x1 == -1 and x2 == -1:
            print(f, b)
            return

        for d in range(4):
            nx1, ny1, b1 = move(x1, y1, d)
            nx2, ny2, b2 = move(x2, y2, d)

            if nx1 != -1 and nx2 != -1 and nx1 == nx2 and ny1 == ny2:
                continue

            nf = f + 1
            nb = b + b1 + b2

            state = (nx1, ny1, nx2, ny2)
            if dist.get(state, INF) > (nf, nb):
                dist[state] = (nf, nb)
                heapq.heappush(pq, (nf, nb, nx1, ny1, nx2, ny2))

solve()
```実装の中核となるのは、`move`1 つのグローバル転送コマンドを 1 つのロボットに適用する関数。 脱出する、壁や境界にぶつかる、移動が成功するという 3 つのケースを注意深く区別します。 出口セルから南に進むとロボットが完全に取り外されるため、通常の移動の前に出口ケースを確認する必要があります。 

ダイクストラ ループは、ロボットの位置の各ペアをノードとして扱います。 各エッジは、4 つの方向から 1 つを選択し、それを同時に適用することに対応します。 優先キュー内の辞書編集的な順序により、別個の緩和構造を必要とせずに、順方向コマンドが最初に最小化され、次にバンプが最小化されることが保証されます。 

移動後の衝突チェックにより、明示的に禁止されている両方のロボットが同じセルを占有する違法な中間状態が防止されます。

 ## 特殊なケース

 1 つのエッジ ケースは、両方のロボットが出口セルに隣接しているが、一方のロボットだけが他方をブロックせずに退出できる場合に発生します。 終了は他のロボットの位置とは独立した状態遷移として扱われるため、アルゴリズムはこれを処理します。 

別のエッジケースでは、ループ状に壁にぶつかることが繰り返されます。 各状態は位置と累積コストの両方によってキー設定されるため、より悪いコストで同じ構成を再訪することは無視され、無限循環を防ぎます。 

最後の微妙なケースは、ロボットがまだ中にいるのに、ロボットが外に出る場合です。 終了したロボットは終了状態に変換され、衝突や移動に参加しなくなります。これは、固定された「アウト」マーカーとして扱うことで自然に処理されます。
