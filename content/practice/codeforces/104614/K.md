 ## 解決策
 ## 問題の理解

 ルート階層構造についての 2 つのテキスト説明が与えられています。 各構造は整数でラベル付けされた部門を定義し、すべての部門が複数の直接のサブ部門を持つことができます。 形式は再帰的です。単一の数字はリーフ部門を表し、数字の後に括弧で囲まれたいくつかのグループが続く部門は複数の子を持つ部門を表し、それぞれの子自体が完全な階層になります。 

このタスクは、子の順序を無視して、指定された 2 つの階層が同じルートのツリー構造を表しているかどうかを判断することです。 ルート ツリー構造が順序付けされていない子の下で同型である場合、2 つの部門は 2 つのチャート間で同一とみなされ、部門ラベルは対応するノードで正確に一致する必要があります。 

主な困難は、子は任意の順序で出現でき、間隔も任意であるため、同じ構造をさまざまな方法で記述できるという事実にあります。 さらに、入力サイズは最大 100,000 ノードと非常に大きくなる可能性があるため、単純な方法でサブツリーを繰り返し解析または比較するアプローチは失敗します。 

この制約は、線形または線形に近い解決策が必要であることを意味します。 文字列連結を使用してノードごとに繰り返し実行されるサブツリー ハッシュを伴うものはすべて、深い入れ子 (深さは最大 1000) と大きな分岐により、最悪の場合二次動作に低下します。 

いくつかのエッジの状況は微妙です。 

問題の 1 つは注文です。 たとえば、次の 2 つの表現は、

 11(10)(12(13)(17)(28))

 11 (12 (17) (28) (13)) (10)

 子には順序がないため、同一であると見なす必要があります。 

2 番目の問題は、空白スペースの柔軟性です。 のような入力

 11 ( 10 ) ( 12 )

 11(10(12))

 フォーマットの違いにもかかわらず、同じように解析する必要があります。 

3 番目の問題は、ラベルが局所的に一致する場合でも構造的な不一致です。 たとえば

 11 (10) (12)

 11 (10) (13)

 最上位構造は同一であっても、1 つのサブツリー ルートが異なる (12 と 13) ため、異なります。 

単純な間違いは、括弧の並べ替えでは字句の等価性が維持されないため、文字列の正規化を行ってから直接比較を試みることです。 

## アプローチ

 直接的な強引なアイデアは、各階層を完全に解析してツリー構造にし、2 つのツリーを比較して同型性があるかどうかを確認することです。 単純な比較では、すべての順列を試して各ノードの子を再帰的に相互に照合します。 これにより、ノードに多くの子がある場合、最悪の場合、ノードごとの階乗計算量が直ちに増加します。 各ノードに最大 100 個の子があるという制約があっても、直接実装した場合、サブツリー間でマッチングを繰り返すと依然として指数関数的な動作が発生します。 

もう 1 つの素朴なアイデアは、子の表現を再帰的に並べ替えて連結することによって、各サブツリーを正規の文字列表現に変換することです。 これは論理的には正しいですが、文字列の連結を繰り返して実装すると、処理が遅くなりすぎます。これは、深い再帰で文字列を構築するとコピーが繰り返され、全体の複雑さが合計入力サイズで 2 次まで低下する可能性があるためです。 

重要な洞察は、大きな文字列を明示的に構築したり並べ替えたりする必要がないということです。 子の順序に関係なく、同一のサブツリーが同一の識別子を生成するように、各サブツリーに安定した識別子が必要なだけです。 これは、構造ハッシュをボトムアップで計算することを示唆しています。 

式をツリーに解析し、そのラベルとその子ハッシュのマルチセットから計算された正規ハッシュを各サブツリーに割り当てます。 子には順序がないため、順序に依存しない方法でハッシュを結合する必要があります。 子ハッシュのソートは許容されます。これは、ノードあたりの子の総数が少なく (最大 100)、全体の複雑さが分岐では線形のままですが、ノード全体では線形であるためです。 

各サブツリーにハッシュがあると、2 つのチャートの比較はルート ハッシュの比較になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースツリーマッチング | 指数関数 | O(n) | 遅すぎる |
 | サブツリーのハッシュ (標準形式) | O(n log k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各入力行を単一のルート ツリー式として扱い、スタックベースのパーサーを使用してそれをノードに解析します。 

1. 文字列を左から右にスキャンし、整数を部門ラベルとして抽出し、括弧を構造区切り文字として解釈します。 数値を読み取るたびに、ノードが作成されます。 右括弧が表示されたら、現在のサブツリー コンテキストを終了し、その親にアタッチします。 このステップでは、ツリーを明示的に構築します。 
2. 解析中に、ツリー内の現在のアクティブなパスを表すノードのスタックを維持します。 新しい番号の後に開き括弧または子構造が続く場合、それを現在のノードとしてプッシュします。 サブツリーを終了すると、その親に戻ります。 これにより、正確な階層を再構築できます。 
3. ツリーを構築した後、ポストオーダー トラバーサルを使用して各ノードのハッシュを計算します。 リーフ ノードの場合、ハッシュはそのラベルにのみ依存します。 内部ノードの場合、最初にすべての子のハッシュを計算し、次に子のハッシュのリストを並べ替えます。 問題定義では子に順序がないため、並べ替えが必要です。 
4. ノードラベルとソートされた子ハッシュを単一の複合表現に結合します。 実際には、辞書を使用して、それぞれの異なる組み合わせを一意の整数 ID にマッピングします。 これにより、コストのかかる文字列の連結が回避され、比較が一定時間に保たれます。 
5. 両方の入力行に対して同じプロセスを実行し、2 つのルート識別子を生成します。 
6. 2 つのルート識別子を比較します。 一致する場合は「Yes」を出力し、一致しない場合は「No」を出力します。 

ここでソートだけで十分である理由は、サブツリーのアイデンティティが子の順序ではなく子のマルチセット構造のみに依存するためです。 子を安定した識別子のソートされたシーケンスに変換することで、正規形式を強制します。 

### なぜ効果があるのか

 不変条件は、すべてのサブツリーには、その記述方法や子の順序ではなく、その構造とラベルのみに依存する一意の識別子が割り当てられることです。 2 つのサブツリーは、計算された識別子が等しい場合にのみ同等です。 識別子はボトムアップで割り当てられるため、任意の深さでの構造の違いが上に伝播し、ルート識別子が変更されます。 これにより、ルート識別子の同等性が 2 つの入力階層の構造的同等性と同等であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def parse_tree(s):
    n = len(s)
    i = 0

    stack = []

    # Each element: (node_label, children list)
    nodes = []

    def new_node(val):
        return [val, []]

    root = None

    while i < n:
        if s[i].isspace():
            i += 1
            continue

        if s[i].isdigit():
            val = 0
            while i < n and s[i].isdigit():
                val = val * 10 + (ord(s[i]) - 48)
                i += 1
            node = new_node(val)
            nodes.append(node)
            if stack:
                stack[-1][1].append(node)
            stack.append(node)

        elif s[i] == '(':
            i += 1

        elif s[i] == ')':
            stack.pop()
            i += 1
        else:
            i += 1

    root = nodes[0]
    return root

def canonical_hash(root):
    from collections import defaultdict

    sys.setrecursionlimit(10**7)

    memo = {}
    counter = 1

    def dfs(node):
        nonlocal counter
        label, children = node

        child_ids = []
        for ch in children:
            child_ids.append(dfs(ch))

        child_ids.sort()

        key = (label, tuple(child_ids))
        if key not in memo:
            memo[key] = counter
            counter += 1
        return memo[key]

    return dfs(root)

def solve_one(line):
    root = parse_tree(line)
    return canonical_hash(root)

def main():
    s1 = input().strip()
    s2 = input().strip()

    id1 = solve_one(s1)
    id2 = solve_one(s2)

    print("Yes" if id1 == id2 else "No")

if __name__ == "__main__":
    main()
```解析関数は整数を読み取り、ノードを段階的に構築します。 各ノードはその子のリストを保持します。 スタックにより、括弧で定義されたネストが直接親子関係に変換されることが保証されます。 

ハッシュ関数は DFS を実行します。 各ノードは、子のハッシュを収集して並べ替え、辞書を使用してコンパクトな正規 ID を割り当てます。 メモ化により、同一のサブツリー構造が複数回出現した場合でも、同じ識別子を共有することが保証されます。 

微妙な点は、並べ替えが構造文字列ではなく整数 ID で行われるため、比較が高速に行われることです。 もう 1 つは、親ハッシュを計算する前にすべての子が完全に解決されるように、ポストオーダー トラバーサルに依存していることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log k) | 各ノードは、すべてのノードにわたって最大 k 個の子 (k ≤ 100) をソートします。分岐の合計は線形です。 
| スペース | O(n) | 各ノードは一度保存され、さらにサブツリー署名のメモ テーブルも保存されます。 

この制約では最大 100,000 ノードが許可されるため、ほぼ線形のソリューションが必要です。 境界次数の子をソートすると、総オーバーヘッドが小さく抑えられ、ハッシュ化により構造比較の繰り返しが回避されます。

 ## 特殊なケース

 一般的なエッジ ケースは単一ノード ツリーです。 パーサーは、括弧のない単独の数値を完全なツリーとして正しく処理する必要があります。 アルゴリズムはラベルのみに基づいてリーフ ハッシュを割り当てるため、2 つの同一の単一ノードは同等と比較されます。 

もう 1 つのエッジ ケースは、1 つのノードに 100 近くの子がある重度の分岐です。 正確さは子ハッシュのソートに依存しますが、ソートはそのノード レベルでのみ適用されるため、アルゴリズムは引き続き機能します。 のような入力の場合```
1 (2) (3) (4) ... (100)
1 (100) (99) ... (2)
```両方の側で子ハッシュの同一のマルチセットが生成されるため、ルート ハッシュは一致します。 

DFS の深さはツリーの深さと同じであり、Python の再帰制限が増加しているため、深さ 1000 までの深いネストは安全に処理されます。 各ノードは 1 回だけ訪問されるため、次のような最悪のチェーンも発生します。```
1(2(3(4(...))))
```引き続き線形作業を計算し、再計算やバックトラッキングのオーバーヘッドなしで一連のハッシュ計算を生成します。
