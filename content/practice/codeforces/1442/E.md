 ## 解決策
 ## 問題の理解

 各ノードが白、黒、または灰色に着色されたツリーが与えられます。 目標は、最小限の操作ですべてのノードを削除することです。各操作では、削除するノードの接続コンポーネントを選択します。 唯一の制限は、1 回の操作で白ノードと黒ノードを同時に削除できないことです。 グレーのノードはニュートラルで、どちらの色とも調和します。 ノードを削除した後、ツリーは複数の接続されたコンポーネントに分割される場合があり、その後の削除は各コンポーネントで独立して実行できます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、頂点の数、各頂点の色、およびエッジのリストによってツリーを記述します。 出力は、すべてのノードを削除するために必要な削除操作の最小数です。 

主な制約は、すべてのテスト ケースにわたるノードの合計数が最大 200,000 であり、個々のツリーのノード数も最大 200,000 であることです。 これは、最悪の場合、約 200,000 平方の演算が必要になるため、ノード数が 2 次であるソリューションは実行不可能であることを意味します。 線形または線形に近い解 (O(n) または O(n log n)) は許容されます。 また、1 つの色だけを持つツリー、グレーのノードのみを持つツリー、または 1 つのノードを削除するとツリーの残りの部分が予期しない方法で切断されるツリーなど、エッジ ケースの処理にも注意する必要があります。 

微妙なエッジ ケースの 1 つは、木が完全に 1 色 (すべて白またはすべて黒など) である場合です。 不注意なアプローチでは、すべての白いノードを個別に削除する必要があると想定する可能性がありますが、実際には、接続されている同じ色のすべてのノードを 1 回の操作で削除できます。 もう 1 つの注意が必要なケースは、灰色のノードが黒と白のサブツリー間のブリッジを形成する場合です。 同じ操作で白と黒のノードを誤って削除しようとしないようにする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての削除シーケンスをシミュレートしようとします。 各操作では、白と黒が混在していないノードの接続されたコンポーネントをすべて列挙し、それらを削除し、残りのツリーを再帰的に処理します。 このアプローチは原理的には正しいですが、考慮すべき接続されたサブセットが指数関数的に多く、したがって最大 200,000 の n に対しては完全に実行不可能であるため、最悪のケースでは指数関数的になります。 

重要な洞察は、すべてのサブセットを考慮する必要がないという観察から得られます。 この制約は純粋に、同じ操作で黒と白の混合を避けることに関するものです。 各サブツリーについて白、黒、またはその両方が含まれているかどうかを計算すると、必要な操作の数を再帰的に決定できます。 灰色のノードは柔軟性があるため、どちらのグループにも参加できます。 より正式には、深さ優先検索を実行し、各ノードをルートとするサブツリーを削除するために必要な最小限の操作数を追跡できます。 サブツリーの操作は、その子に必要な操作の最大値と、サブツリーに白ノードと黒ノードの両方が含まれる場合の潜在的な追加削除によって決まります。 これにより、問題はツリー上の線形パスに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | DFS + サブツリーの色付け | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、各テスト ケースのツリーの隣接リスト表現を構築します。 各ノードの色を保存します。 
2. 再帰関数を定義する`dfs(node, parent)`タプルを返す`(has_white, has_black, operations)`、サブツリーのルートが次であるかどうかを表します。`node`白いノード、黒いノード、およびサブツリーをクリアするために必要な最小限の削除操作が含まれます。 
3.初期化`has_white`そして`has_black`現在のノードの色に基づきます。 灰色のノードはどちらも true に設定しません。 
4. 現在のノードの親ではない子ごとに、再帰的に呼び出します。`dfs(child, node)`そして子供の情報を収集します。 
5. 子サブツリーに白と黒の両方のノードが含まれる場合は、1 回の操作で両方の色を削除できないため、操作カウントを 1 つ増やします。 それ以外の場合は、子の`has_white`そして`has_black`flags を現在のノードのフラグに置き換えます。 
6. すべての子を処理した後、結合されたフラグと合計操作を返します。 合計操作には、子に蓄積されたすべての操作に加えて、現在のサブツリーに白ノードと黒ノードの両方が含まれており、まだカウントされていない場合はさらに 1 つが含まれます。 
7. DFS が完了すると、ツリーの削除の合計数は次のようになります。`operations`ルートに対して返される値。 

正確性は、サブツリーに白と黒の両方のノードが含まれているかどうか、および黒と白を一緒に削除することなくサブツリー内のすべてのノードを削除するための最小操作数を DFS が正確に計算するという不変条件から得られます。 子情報を上方にマージすることにより、ルートは必要な操作の総数を蓄積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        colors = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        def dfs(node, parent):
            has_white = colors[node] == 1
            has_black = colors[node] == 2
            ops = 0
            for child in adj[node]:
                if child == parent:
                    continue
                c_white, c_black, c_ops = dfs(child, node)
                ops += c_ops
                if c_white and c_black:
                    ops += 1
                else:
                    has_white |= c_white
                    has_black |= c_black
            return has_white, has_black, ops

        _, _, total_ops = dfs(0, -1)
        if _ and _:
            total_ops += 1
        print(total_ops)

if __name__ == "__main__":
    solve()
```このソリューションは、ツリーとカラーを読み取り、隣接リストを構築し、DFS を実行します。 DFSでは、`has_white`そして`has_black`上向きに伝播して、サブツリーにそれらの色が含まれているかどうかを示します。 子サブツリーに白と黒の両方が含まれる場合は、必ず別の操作で削除する必要があります。`ops`増加します。 最後に、ルートがチェックされ、そのサブツリーに白と黒の両方が含まれているかどうかが確認され、最後の操作が 1 つ追加される可能性があります。

 | 4 | 偽 | 本当 | 0 |

 | ルート 1 | 本当 | 本当 | 1+? |

 最初のケースでは、両方のノードが白であるため、1 つの削除で十分です。 2 番目のケースでは、DFS はノード 3 と 4 (両方の色が表示される) を含むサブツリーに対して 1 つの操作をカウントし、残りの操作を組み合わせて合計 3 つの操作を取得します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | DFS では各ノードが 1 回訪問され、各エッジが 2 回横断されます。 |
 | スペース | O(n) | 隣接リストと再帰スタックは O(n) メモリを使用します。 |

 解はツリーのサイズにおいて線形です。 すべてのテスト ケースのノードの合計数は 200,000 であるため、これは 2 秒の制限時間内に簡単に収まります。 メモリ使用量も 512 MB の制約内に十分収まります。
