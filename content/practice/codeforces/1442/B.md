 ## 解決策
 ## 問題の理解

 行に格納された順列から始めます。 各ステップで、現在の行から 1 つの要素を削除し、削除した場所に応じて、そのすぐ隣の要素 (左または右、その時点で存在する方) の 1 つを 2 番目のシーケンスに強制的に追加します。 これを正確に k 回実行した後、追加された近傍値によって形成された最終シーケンス b が与えられ、正確にこのシーケンス b を生成するために削除位置を選択できる方法が何通りあるかを数えるよう求められます。 

重要な点は、配列が時間の経過とともに縮小するため、「隣接」とは常に、元の静的順列ではなく、以前の削除後の現在の隣接を参照することです。 各操作は配列の進化する構造に依存するため、すべての選択を直接シミュレーションするとコストが高くなります。 

この制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 すべてのテスト ケースの合計 n は最大 200000 であるため、O(n log n) よりも悪いソリューションは全体的に TLE の危険性があります。 各ステップで複数の有効な削除位置が存在する可能性があるため、考えられるすべての削除シーケンスを単純にバックトラッキングすると、大きく分岐することになります。 これはすぐに指数関数的に変化します。 

b が隣接制約と矛盾する場合、微妙なエッジ ケースが発生します。 たとえば、b の 2 つの連続する要素が、考えられる中間状態で決して隣接しない場合、答えは 0 でなければなりません。 別の障害モードは、複数のシーケンスがローカルでは有効だがグローバルでは互換性がない場合に発生します。この場合、構造的制約を追跡せずに貪欲にカウントするとオーバーカウントされてしまいます。 

## アプローチ

 ブルートフォース解釈では、可能なすべての削除インデックス t₁、t₂、…、tₖ のシーケンスが試行されます。 削除するたびに配列を更新し、選択した近傍が b の次の要素と一致するかどうかを確認します。 これはプロセスを正しくシミュレートしますが、各ステップは最大 O(n) 個の選択肢に分岐する可能性があり、これを k 回実行するため、指数関数的な動作が発生します。 

重要な観察は、実際には完全な配列構造を気にすることはなく、 b の要素を一部の欠失の近傍として「生成」できるかどうか、およびプレフィックスの決定と一貫性を保つ有効な構造構成がいくつあるかだけを気にするだけであるということです。 

b の固定値 x の観点からプロセスを見ると、元の近傍の 1 つが削除されたときに x が生成されます。 つまり、b のすべての要素は、現在の順列で「隣接関係」を消費することに対応します。 重要な制約は、x が生成された時点で、元の置換構造内にまだ存在する少なくとも 1 つの近傍にまだ隣接していなければならないということです。 

これにより、問題は、ローカルな制約のみが重要となる動的隣接システムの追跡に変換されます。 削除をシミュレートする代わりに、「生きている」セグメントにわたって DSU のような構造を維持し、次に必要な b 要素の隣接関係を維持する削除の選択肢がいくつあるかを数えます。 

各ステップでは、ターゲット要素のどちらの側がまだ有効な貢献者である場合に、どちらの側を最初に削除するかのみが自由になります。 これにより、問題は間隔構造の維持と有効な境界決定のカウントに軽減されます。

 ## アルゴリズムのチュートリアル

 どの要素がまだ「生きている」のか、そしてそれらがどのように接続されているのかを表す構造を維持しながら、順列を処理します。 また、隣接関係はインデックス空間で推論するのが最も簡単であるため、各値を初期順列の位置にマッピングします。

私たちはインデックスに対して DSU を維持しており、各セットは現在有効な要素の連続したブロックを表します。 各ブロックについて、その左端と右端のアクティブな要素を効率的にクエリできます。 

また、現在照合しようとしている b の要素をマークする配列も維持します。 

### ステップ

 1. 元の順列の各値のインデックスを指定する位置配列 pos[x] を構築します。 これにより、値空間ではなくインデックス空間で作業できるようになります。 
2. インデックス 1 ～ n に対して DSU を初期化します。最初は各インデックスを独自のセットに含めます。 また、インデックスが現在削除されているかどうかを追跡する 2 つの配列またはマップも維持します。 
3. まだ削除されていないすべての要素をアクティブとしてマークします。 最初は、すべての要素がアクティブになっています。 
4. b の値を順番に処理します。 各 b[i] について、その位置 pos[b[i]] を考慮し、DSU 構造内の現在隣接するアクティブな要素を調べます。 
5. b[i] に現在 1 つまたは 2 つの有効な隣接アクティブ隣接要素があるかどうかを判断します。 何もない場合、それは決して生成できないため、答えは即座にゼロになります。 
6. 両方の隣接セグメントが存在する場合、このステップでの操作で有効な選択肢の数は、隣接セグメントの左側から削除するか右側から削除することで将来の制約との整合性が保たれるかによって異なります。 有効な対称構成ごとに、有効なシーケンスの数が 2 倍になります。 
7. 答えに、このステップで有効な方向の数を掛けます。 
8. b[i] を処理した後、それを生成する要素の削除をシミュレートし、配列の縮小を反映して DSU 内の隣接するセグメントをマージします。 

### なぜ効果があるのか

 どのステップにおいても、唯一意味のある決定は、現在のターゲット要素のどちら側を使用して要素を生成するかということです。 その選択が決定されると、配列の残りの構造は、連続したセグメントの新しい構成に決定論的に崩壊します。 DSU はこれらのセグメントを正確に維持し、将来のすべての隣接関係が正しい縮小構造に基づいて計算されることを保証します。 各操作はローカル接続にのみ影響するため、グローバルな再計算は必要なく、すべての有効なシーケンスはローカル方向の選択シーケンスに一意に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.parent[b] = a
        self.sz[a] += self.sz[b]

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(a):
            pos[x] = i

        alive = [True] * n
        dsu = DSU(n)

        # helper arrays for neighbors
        left = list(range(-1, n))
        right = list(range(1, n + 1))
        left[0] = -1
        right[n - 1] = -1

        def get_left(i):
            j = i - 1
            while j >= 0 and not alive[j]:
                j -= 1
            return j

        def get_right(i):
            j = i + 1
            while j < n and not alive[j]:
                j += 1
            return j

        ans = 1

        for x in b:
            i = pos[x]
            l = get_left(i)
            r = get_right(i)

            if l == -1 and r == -1:
                ans = 0
                break

            options = 0
            if l != -1:
                options += 1
            if r != -1:
                options += 1

            ans = (ans * options) % MOD

            alive[i] = False

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、進化する「生きた」配列と直接連携します。 b の各要素について、まだアクティブなインデックスが見つかるまで左右にスキャンして、現在の隣接要素を見つけます。 これらの近傍は、このステップで現在の値を生成した可能性のある唯一のソースを表します。 続行する有効な方法の数は、この要素が生成された有効な側面の数と正確に一致します。 

DSU クラスは構造的なプレースホルダーとして表示されますが、実際の実装は明確にするために直接近隣スキャンに依存しています。 完全に最適化されたバージョンでは、DSU またはリンク リスト後継構造がこれらのスキャンを置き換えて、O(1) の償却近隣クエリを保証します。 

答えに現在有効な隣接方向の数のみを乗算し、b の要素に有効な隣接方向が存在しない場合は直ちにプロセスを無効にするように注意する必要があります。

 ## 特殊なケース

 1 つの重大なエッジ ケースは、b の要素が以前の削除後に孤立した場合に発生します。 たとえば、以前の要素を削除すると、将来のターゲットの両方の隣接要素が破壊される場合、左も右も生成できないため、アルゴリズムは直ちにゼロを正しく返します。 

もう 1 つのエッジ ケースは、b が順列の終点で開始または終了する場合です。 この状況では、隣接する要素が 1 つだけ存在するため、それらのステップで乗算係数が 1 に強制され、単純な 2 倍ロジックでは誤ってオーバーカウントされてしまいます。
