 ## 解決策
 ## 問題の理解

 この問題は、エイプリル フール コンテストでの発言で実際のタスクが意図的に隠されていることが原因です。 

2 つの非負の整数が与えられます。 必要な操作は次のとおりです。 

1. 2 番目の数値の小数表現を反転します。 
2. 結果を最初の数値に加算します。 
3. 合計を出力します。 

たとえば、入力が次の場合`3 14`、の逆`14`は`41`、そして答えは`3 + 41 = 44`。 これはサンプル出力と一致します。 

数字は最大でも$10^9$, したがって、それぞれに最大 10 桁の数字が含まれます。 実際には、数値の桁に対する演算には一定の時間がかかります。 高度なアルゴリズム、データ構造、最適化は必要ありません。 単純な桁の反転とそれに続く 1 つの加算は、簡単に制限内に収まります。 

間違いの主な原因は、反転後の先頭のゼロの処理です。 

次の入力を考えてみましょう。```
100 200
```逆転する`"200"`与える`"002"`、整数を表します`2`。 答えは次のとおりです。```
100 + 2 = 102
```先頭のゼロを数字として保持する不注意な実装により、反転された値が誤って次のように扱われる可能性があります。`200`。 

もう 1 つのエッジ ケースは、2 番目の数値がゼロの場合です。```
5 0
```の逆`0`まだです`0`、したがって、答えは次のようになります。```
5
```一部の文字列ベースの実装では、ゼロを削除するときに誤って空の文字列が生成されます。 

3 番目のエッジ ケースは、反転する前に反転した数値がゼロで終わる場合です。```
27 12
```の逆`12`は`21`、与える：```
27 + 21 = 48
```このサンプルは、操作が桁の並べ替えや並べ替えではなく、真の桁反転であることを確認します。 

## アプローチ

 ブルートフォース手法では、2 番目の数値のすべての桁を調べ、その反転形式を構築し、それを整数に戻してから、それを最初の数値に加算します。 

2 番目の数値には最大 10 桁が含まれるため、これはすでに定数時間で実行されます。 たとえ何百万ものテスト ケースを処理したとしても、ケースあたりの作業量はわずかなものにとどまります。 

重要な観察は、単に隠れた操作を理解することです。 答えが次のようになることを認識すると、$$a_1 + \text{reverse}(a_2)$$実装は簡単になります。 

数値を反転するには 2 つの一般的な方法があります。 1 つは算術で、最後の桁を繰り返し取得して新しい数値に追加します。 もう 1 つは、数値を文字列に変換し、文字を反転することです。 入力サイズが非常に小さいため、どちらのアプローチも受け入れられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース桁反転 | O(d) | お(1) | 承認済み |
 | 最適 | O(d) | お(1) | 承認済み |

 ここ$d$2 番目の数値の桁数であり、最大 10 です。 

## アルゴリズムのチュートリアル

 1. 整数を読み取る`a1`そして`a2`。 
2. 小数点以下の桁を反転します。`a2`。 

最も簡単な方法は、最後の桁を繰り返し抽出することです。`% 10`そしてそれを新しい番号に追加します。 
3. 反転した値を`a1`。 
4. 結果を出力します。 

### なぜ効果があるのか

 この問題の隠されたルールは、最初の数値を反転した 2 番目の数値に加算することです。 反転手順は、10 進表現が逆の順序で書かれた整数を再構築します。 のすべての桁`a2`は 1 回表示され、正しい反転位置に表示されるため、構築された値は正確に計算されます。`reverse(a2)`。 この値を追加すると、`a1`必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a1, a2 = map(int, input().split())

rev = 0
if a2 == 0:
    rev = 0
else:
    while a2 > 0:
        rev = rev * 10 + (a2 % 10)
        a2 //= 10

print(a1 + rev)
```最初の部分は 2 つの整数を読み取ります。 

変数`rev`2 番目の数値の反転形式を格納します。 各反復中に、現在の最後の桁が末尾に追加されます。`rev`。 たとえば、次の場合`a2 = 123`、シーケンスは次のようになります。```
rev = 3
rev = 32
rev = 321
```特別な場合`a2 = 0`明示的に処理されます。 これがなければループは決して実行されず、答えは正しいままですが、意図はより明確になります。 

最後に、コードは次のように追加します`a1`と反転した数値を計算し、結果を出力します。 

Python の整数には任意の精度があるため、オーバーフローの危険はありません。 固定幅の 64 ビット整数を使用する言語であっても、可能な最大の答えは制限に比べて非常に小さくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    a1, a2 = map(int, input().split())

    rev = 0
    if a2 == 0:
        rev = 0
    else:
        while a2 > 0:
            rev = rev * 10 + (a2 % 10)
            a2 //= 10

    print(a1 + rev)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided samples
assert run("3 14\n") == "44\n", "sample 1"
assert run("27 12\n") == "48\n", "sample 2"
assert run("100 200\n") == "102\n", "sample 3"

# custom cases
assert run("0 0\n") == "0\n", "both zero"
assert run("5 0\n") == "5\n", "reverse of zero"
assert run("0 1200\n") == "21\n", "leading zeros after reversal"
assert run("1000000000 1000000000\n") == "1000000001\n", "maximum values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 0`|`0`| 可能な最小値 |
 |`5 0`|`5`| ゼロの反転 |
 |`0 1200`|`21`| 反転後、先頭のゼロが消えます。 
|`1000000000 1000000000`|`1000000001`| 最大の投入量 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
100 200
```アルゴリズムは数字を抽出します`0`、`0`、 そして`2`。 反転した値は次のようになります`2`、 ない`002`別のオブジェクトとして。 最終的な答えは次のとおりです。```
100 + 2 = 102
```これは予想される動作と一致し、先行ゼロに関連する間違いを回避します。 

考慮する：```
5 0
```2 番目の数値はすでにゼロに等しくなります。 反転した値もゼロになります。 アルゴリズムは次のように出力します。```
5
```特別なフォーマットの問題は発生しません。 

考慮する：```
0 1200
```数字の抽出シーケンスは次のとおりです。```
0 -> 0
0 -> 0
2 -> 2
1 -> 21
```反転した値は、`21`、最終的な答えは次のとおりです。```
21
```これにより、元の数値の末尾のゼロが反転後に先頭のゼロになり、整数として表されるときに自動的に破棄されることが確認されます。
