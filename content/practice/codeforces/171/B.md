 ## 解決策
 ## 問題の理解

 この問題では、レイヤーの数を指定して、グリッド上に描かれた星形のパターン内のセルの総数を計算するように求められます。 入力は単一の整数です`a`、星の中の同心円状の層の数を表します。 出力は単一の整数で、すべて描画した場合に色付けされるセルの総数です。`a`星の層。 

星の各層は対称的にサイズが増加するため、セルの数は単純な組み合わせ公式に従って増加します。 最初の層は中央の単一セルです。 2 番目の層はその周囲にセルを追加して十字のようなパターンと角を形成し、後続の各層は同じ対称構造に従ってさらに多くのセルを追加します。 

制約は次のことを教えてくれます`a`出力が最大 2·10⁹ に達する可能性があることを考えると、これは、グリッドをレイヤーごとに塗りつぶす単純なシミュレーションでは時間がかかりすぎ、メモリを大量に消費することを意味します。 最大入力を効率的に処理するには、セル数を表す閉じた形式の式が必要です。 

エッジケースは次のような場合です`a = 1`。 中央のセルのみが存在するため、正しい出力は 1 です。 少なくとも 2 つの層を想定したり、最初の層を明示的に処理せずに数式を使用したりする不注意なアプローチでは、誤った結果が生成されます。 

## アプローチ

 ブルートフォースアプローチでは、追加された各セルを数えながら、星の各層を明示的に描画するシミュレーションを試みます。 最初のレイヤーは 1 を加算し、2 番目のレイヤーは 12 を加算し、3 番目のレイヤーは 24 を加算します。 これは概念的には正しいですが、各レイヤーとレイヤー内の各セルを反復処理する必要があります。 と`a = 18257`、セルの総数はおおよそ次のように増加します。`6*a^2 + 6*a + 1`、最大の場合は約 2·10⁹ の操作に相当します。`a`。 これでは遅すぎて、グリッドを保存しようとするとメモリ制限を超えてしまいます。 

重要な洞察は、細胞数のパターンを認識することです。 セルの総数の数列は 2 次数列です。最初の層は 1、2 番目の層は 13、3 番目の層は 37 というようになります。 レイヤー間の違いを調べると、新しいレイヤーがそれぞれ追加されていることがわかります。`12 * (layer - 1)`細胞。 これにより、セルの総数を表す閉じた式が得られます。`a`レイヤー:`1 + 6*a*(a-1)`。 

ブルートフォースアプローチは小規模な場合に機能します`a`各層を安全にシミュレートできますが、全体的には失敗するためです。`a`二次成長のため。 シーケンスが 2 次であるという観察により、反復を行わずに定数時間で結果を直接計算できます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`a`入力から。 これは星の中の層の数を表します。 
2. 閉じた数式を使用してセルの総数を計算します。`1 + 6*a*(a-1)`。 この公式は、各層が`i`（どこ`i ≥ 2`) を追加します`12*(i-1)`これらを合計すると二次式が得られます。 
3. 計算された合計を印刷します。 

これが機能する理由は、数式がセルの加算パターンを正確に捉えているためです。 最初の層は 1 を与えます。後続の層ごとに、前の層の合計よりも 12 個多くのセルが追加され、一連の差分 12、24、36 などが生成され、合計が 2 次公式になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input())
result = 1 + 6 * a * (a - 1)
print(result)
```ソリューションは単一の整数を読み取ります`a`、派生した数式を使用してセルの合計数を計算し、出力します。 この式では整数演算のみが使用されるため、浮動小数点の問題は発生しません。 私たちは掛け算をします`6*a*(a-1)`1 つ目は、Python が大きな整数を自動的に処理するため、整数のオーバーフローを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a = int(sys.stdin.readline())
    return str(1 + 6 * a * (a - 1))

# provided sample
assert run("2\n") == "13", "sample 1"
# custom cases
assert run("1\n") == "1", "minimum input"
assert run("3\n") == "37", "three layers"
assert run("18257\n") == str(1 + 6*18257*18256), "maximum input"
assert run("10\n") == "541", "ten layers"

 ## 特殊なケース

 のために`a = 1`、式は次のように評価されます。`1 + 6*1*(1-1) = 1`。 アルゴリズムは特別な処理を行わなくても 1 を正しく出力します。 次のような大規模な入力の場合`a = 18257`、式は次のように計算します`1 + 6*18257*18256`直接的に行うことで、反復やメモリを大量に使用するシミュレーションを回避します。 すべての中間積は Python の整数の範囲内に収まります。 これにより、入力範囲全体で正しい結果が保証されます。
