 ## 解決策
 ## 問題の理解

 入力には 2 つの数値が含まれています。 最初の数字は、`a`、再帰的に構築されるポリラインの順序を決定します。 2番目の数字は、`b`、はそのポリラインに沿ったインデックスです。 

声明文にある写真が鍵となる。 これは古典的なヒルベルト曲線であり、オブジェクトのすべてのセルを訪れる空間充填曲線です。`2^a × 2^a`グリッドを 1 回だけ実行します。 セルには、曲線がセルを通過する順序で番号が付けられます。 順序を考えると`a`そしてポジション`b`曲線上で、対応するグリッド セルの座標を回復する必要があります。 

制約`a ≤ 10`非常に小さいです。 グリッドの辺の長さは最大で`2^10 = 1024`したがって、セルの総数は最大で`2^20 = 1,048,576`。 再帰的またはビットごとの構築も、制限内であれば簡単です。 

主な問題は効率ではありません。 課題は、画像によってエンコードされた構造を認識し、ヒルベルト曲線の各再帰象限内で発生する回転と反射を正しく処理することです。 

よくある間違いは、番号付けを単純な行優先順序またはモートン順序として扱うことです。 たとえば:

 入力```
2 15
```答えは```
3 0
```行優先の解釈では、次のようになります。`(3,3)`これは、ヒルベルト曲線が象限間で方向を変えるため、不正確です。 

もう 1 つの間違いが起こりやすいのは、再帰的な向きの処理です。 たとえば:

 入力```
4 160
```答えは```
12 12
```正しい象限に入ったが、必要な回転を忘れた解は、たとえ上位レベルの決定がすべて正しかったとしても、間違ったセルに到達します。 

## アプローチ

 ブルートフォースアプローチでは、次数のヒルベルト曲線全体が明示的に生成されます。`a`、訪問したすべての座標を保存し、出力します。`b`- 番目のもの。 

これは、最大の曲線には約 100 万個のセルしか含まれていないため、機能します。 それらをすべて生成することは可能です。 この方法を正当化するのも簡単です。文字通り、訪問順に曲線を作成すると、答えは次のようになります。`b`- 番目に生成されたポイント。 

弱点は、オブジェクト全体を構築することで直接インデックス付けの問題を解決していることです。 必要なセルは 1 つだけですが、すべてのセルが生成されます。 

ヒルベルト曲線の再帰的構造により、よりクリーンなソリューションが得られます。 次数のヒルベルト曲線`a`4 つの次数のヒルベルト曲線で構成されます`a-1`、それぞれが 1 つの象限を占めます。 インデックス`b`どの象限に答えが含まれているかがすぐにわかります。 象限を特定した後、以前のすべての象限の寄与を削除し、選択した象限内で再帰的に続行します。 

唯一の問題は、各象限が親に対して回転または反射される可能性があることです。 これらの変換が正しく処理されると、すべての再帰レベルでインデックスからのビットの 1 ペアが正確に処理されます。 

これは、標準的なヒルベルト指数から座標への変換アルゴリズムにつながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースの生成 | O(4^a) | O(4^a) | 受け入れられるが不要 |
 | 最適なヒルベルト復号 | O(a) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`n = 2^a`。 セル番号の座標が欲しい`b`の中で`n × n`グリッド。 
2. ヒルベルト指数を最も低い再帰レベルから上に向かって処理します。 
3. 正方形サイズのレベルで`s × s`、次の 2 つのビットを決定します。`rx`そして`ry`。 

これらのビットは、どのサブ象限にターゲット セルが含まれているかを識別します。 
4. 選択した象限に移動する前に、ヒルベルト方向ルールを適用します。 

もし`ry = 0`、現在の正方形を回転する必要があります。 追加でしたら`rx = 1`、回転前の座標が反映されます。 
5. 変換後、象限オフセットを追加します。`x += s * rx`そして`y += s * ry`。 
6. 4 で割ることにより、インデックスから 2 つの処理されたビットを削除します。 
7. ダブル`s`すべての再帰レベルが処理されるまで続行します。 
8. 最終出力`(x, y)`。 

### なぜ効果があるのか

 ヒルベルト曲線は再帰的に定義されます。 すべての次数で、正方形は 4 つの等しい象限に分割されます。 これらの象限の横断順序は固定されていますが、各象限には小さいヒルベルト曲線の回転バージョンが含まれています。 

このアルゴリズムは、レベルを処理した後、次の不変条件を維持します。`(x, y)`は、曲線のすでに再構築された部分内の正しい位置です。 回転と反射のルールは、ヒルベルト曲線が 4 つの子曲線を接続する方法と正確に一致します。 各反復は 1 つの再帰レベルをデコードし、この不変式を保持するため、結局のところ、`a`レベルが処理され、結果の座標がインデックスで訪問したセルと正確に一致します。`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b = map(int, input().split())

n = 1 << a

x = 0
y = 0
t = b
s = 1

while s < n:
    rx = (t // 2) & 1
    ry = (t ^ rx) & 1

    if ry == 0:
        if rx == 1:
            x = s - 1 - x
            y = s - 1 - y
        x, y = y, x

    x += s * rx
    y += s * ry

    t //= 4
    s <<= 1

print(x, y)
```変数`t`まだデコードされていないヒルベルト索引の残りの部分を保管します。 すべての再帰レベルが 4 つの象限の 1 つを選択するため、各反復では 2 ビットが消費されます。 

価値観`rx`そして`ry`選択した象限を識別します。 向きの補正は、象限オフセットを追加する前に行う必要があります。 この順序を逆にすると、回転が現在の正方形のローカル座標系内で定義されるため、不正確な座標が生成されます。 

リフレクションステップでは以下を使用します。`s - 1 - x`そして`s - 1 - y`。 の`-1`が不可欠です。 それを忘れると、すべての座標が 1 セルずつシフトされ、再帰が中断されます。 

座標が次を超えることはないため、オーバーフローの懸念はありません。`1023`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    a, b = map(int, input().split())

    n = 1 << a
    x = y = 0
    t = b
    s = 1

    while s < n:
        rx = (t // 2) & 1
        ry = (t ^ rx) & 1

        if ry == 0:
            if rx == 1:
                x = s - 1 - x
                y = s - 1 - y
            x, y = y, x

        x += s * rx
        y += s * ry

        t //= 4
        s <<= 1

    print(x, y)

def run(inp: str) -> str:
    global input
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old
    return out.getvalue().strip()

# provided samples
assert run("1 0\n") == "0 0", "sample 1"
assert run("2 15\n") == "3 0", "sample 2"
assert run("4 160\n") == "12 12", "sample 3"

# custom cases
assert run("1 1\n") == "0 1", "second cell of order 1"
assert run("1 3\n") == "1 0", "last cell of order 1"
assert run("10 0\n") == "0 0", "minimum index at maximum order"
assert run("10 1048575\n") == "1023 0", "last index of largest grid"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`0 1`| 正しい最初の回転 |
 |`1 3`|`1 0`| 最小の非自明な曲線の終わり |

 ## 特殊なケース

 次のことを考慮してください。```
1 0
```ループは 1 レベルだけ実行されます。 両方の象限ビットがゼロで、オフセットは追加されず、結果はそのままになります。`(0,0)`。 これにより、可能な限り最小のインデックスが正しく処理されることが確認されます。 

考慮する：```
2 15
```どちらの再帰レベルでも、ヒルベルトの第 4 象限に入ります。 アルゴリズムは、オフセットを追加する前に、必要な反射と回転を実行します。 その変換をスキップすると、誤って次の時点で終了します。`(3,3)`。 正しい出力は次のとおりです`(3,0)`。 

考慮する：```
10 1048575
```これは最大の有効なインデックスです。 すべての再帰レベルによって最後の象限が選択されます。 アルゴリズムは依然として 10 回の反復のみを実行して戻り値を返します。`(1023,0)`、実装が特別なケースを使用せずに上限を処理していることを示しています。
