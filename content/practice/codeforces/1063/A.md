 ## 解決策
 ## 問題の理解

 複数の小文字のセットが与えられています。 これらの文字を任意の順序に並べ替えて、同じ長さの新しい文字列を形成することができます。 

結果の文字列については、すべての連続する部分文字列を調べて、それが回文であるかどうかを確認します。 各部分文字列は多重度を考慮してカウントされます。これは、同じ文字シーケンスが異なる位置に出現する場合、複数回寄与することを意味します。 

タスクは、回文部分文字列の総数ができるだけ多くなるように文字を並べ替えることです。 

n が 100000 までの制約は、どのソリューションも線形または線形に近い時間で実行する必要があることを意味します。 O(n²) 個の部分文字列が存在するため、すべての部分文字列を明示的にチェックすることを伴うものは不可能であり、部分文字列ごとに回文性をチェックしたとしても、最悪の場合 O(n³) まで押し上げられてしまいます。 Manacher のようなさらに効率的な部分文字列回文手法は、固定文字列の評価に役立つだけであり、すべての置換を最適化するわけではないため、重要な問題は計算上のものではなく構造上のものです。 

単純なアプローチでは、回文構造を改善するために、すべての順列または貪欲なローカル スワップを試行します。 順列の数は階乗であり、局所的な最適化では回文密度の全体的な構造が捕捉されないため、どちらも失敗します。 

文字列に多くの異なる文字が含まれる場合、微妙なエッジ ケースが発生します。 たとえば、すべての文字が異なる場合、回文となるのは単一の文字だけであるため、すべての配列には正確に n 個の回文部分文字列が含まれます。 「対称性の構築」を試みるアプローチでは、この場合の答えは改善されず、対称性に誤って偏ると、混合分布の柔軟性が低下する可能性さえあります。 

もう 1 つの特殊なケースは、すべての文字が同一である場合です。 この場合、すべての部分文字列は回文であり、あらゆる置換が最適になります。 正しい解決策は、このケースを複雑にしすぎてはならず、それでも有効な再配置を生み出す必要があります。 

## アプローチ

 重要な観察は、回文部分文字列が繰り返し構造に大きく依存しているということです。 部分文字列の端点が一致し、内部も対称である場合、その部分文字列は回文です。 回文部分文字列の数は、文字列に同一の文字が長く続き、対称中心が多数存在する繰り返しパターンが含まれる場合に増加します。 

ブルートフォースのアイデアは、マルチセットのすべての順列を試し、各配置の回文部分文字列の数を計算することです。 固定文字列の場合は、Manacher のアルゴリズムなどの線形時間回文カウント方法を使用できます。 ただし、順列は最大 n! 個あるため、すべての順列を生成することは不可能です。 これは、n = 20 の場合でも天文学的に大きくなります。 

代わりに、どのような構造が回文部分文字列を最大化するかを推論する必要があります。 重要な単純化は、同一文字のブロック内の部分文字列全体が常に回文であり、二次関数的に寄与することです。長さ k のブロックは、それ自体で k(k+1)/2 個の回文部分文字列を寄与します。 構造が高度に対称的でない限り、境界を越えた部分文字列を回文にするのは非常に難しく、任意のマルチセットで強制するのは困難です。 

これは、同一文字の長く連続したブロックを最大化することが有益であることを示唆しています。 合計の寄与を最大化するには、同一の文字を可能な限り一緒に配置し、理想的には文字タイプごとに 1 つの大きなブロックを形成する必要があります。 自由に並べ替えることができるので、できる限り同じ文字をすべてグループ化することです。 

したがって、最適な構成は、同じ文字が連続する任意の順序で文字を配置することです。 これらのブロックのどの順序でも、ブロックごとに同じ内部回文寄与が得られ、クロスブロック回文はブロック サイズの最大化によるゲインを上回ることはありません。

したがって、各文字のすべての出現をグループ化して出力するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | O(n! · n²) | O(n) | 遅すぎる |
 | 最適 (周波数ごとにグループ化) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列内の各文字の頻度をカウントします。 最終的な配置は元の順序ではなく多重度のみに依存するため、これが必要になります。 
2. アルファベット順に文字を繰り返し、その頻度で繰り返される各文字を追加することにより、結果の文字列を構築します。 これにより、各文字が単一の連続したブロックを形成するようになります。 
3. 構築された文字列を出力します。 

### なぜ効果があるのか

 重要な特性は、同一文字の連続ブロック内の回文部分文字列の寄与は、そのブロックができるだけ大きいときに最大化されることです。 k(k+1)/2 は k 内で厳密に凸であるため、同一の文字を複数の位置に分割すると、内部回文部分文字列の数が二次関数的に減少します。 同一の文字を複数のブロックに再分配すると、これらの寄与の合計が減少します。 

クロスキャラクタ回文では、異なる文字間での厳密な対称性制約が必要であり、任意の頻度分布の下ではグローバルに最適化できないため、一般的なマルチセットでのこの損失を補償することはできません。 したがって、同一の文字を集中させると、ローカルな最大の寄与がすべて保存され、最適なグローバル構成が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    res = []
    for i in range(26):
        if freq[i]:
            res.append(chr(i + 97) * freq[i])

    print("".join(res))

if __name__ == "__main__":
    solve()
```コードは最初にすべての小文字の頻度テーブルを計算します。 次に、各文字をその数に応じて繰り返されるソート順に連結して答えを構築します。 文字の順序は最適解の中で任意であるため、決定論のために辞書編集順序が使用されます。 

n ≥ 1 では少なくとも 1 つの文字が存在することが保証されるため、入力を注意深く読み取る以外に境界処理は必要ありません。

import sys, io

def run(inp: str) -> str:

    out = io.StringIO()

    sys.stdout = out

    sys.stdout = old

 ## 特殊なケース

 「a」のような単一文字列の場合、アルゴリズムは頻度 {a:1} をカウントし、「a」を直接出力します。 回文部分文字列の数は 1 ですが、これは最適であり、避けられません。 

「aaaa」のような文字列の場合、周波数グループ化により「aaaa」が生成されます。 すべての部分文字列は回文であり、グループ化によってこの最大構造が維持されます。 このアルゴリズムは、同じ文字列を変更せずに出力します。 

「abc」のような文字列の場合、すべての配置により、文字ごとに 1 つずつ、ちょうど 3 つの回文部分文字列が生成されます。 アルゴリズムは「abc」を出力します。これは有効で、最適値と一致します。 

「aabccc」のような大文字と小文字が混在する場合、グループ化すると「aabccc」が生成されます。 どの順列でも回文単一文字部分文字列の総数は同じであり、グループ化しても利用可能なすべての構造を維持しながらこの数は減りません。
