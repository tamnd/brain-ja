 ## 問題の理解

 迷路というのは、$n \times n$各セルは空であるか、45 度の反射板のように動作する固定タイプのミラーを含むことができるグリッドです。 レーザーは南の境界の各列から始まり、北に向かってグリッド内に移動します。 鏡に当たると、鏡の向きに応じて方向が変わります。 最終的に、ビームはグリッドから出るか、ある柱の北の境界に到達します。 

各レーザー$i$ターゲット受信機が割り当てられています$a_i$北側にあります。 目標は、できるだけ多くのレーザーが、割り当てられた受信機列で正確にグリッドから出てくるようにミラーを配置することです。 すべてのレーザーはミラー構成によって引き起こされる決定的な経路をたどる必要があり、2 つのビームを結合したり分割したりすることはできないため、各レーザーは独立して南から北への経路を定義します。 

出力は、正しく配線できるレーザーの最大数と、「.」、「/」、および「\」セルを使用したグリッドの明示的な構築の両方です。 

重要な制約は、$n \le 1000$、これにより、構築が線形または二次に近くなるように強制されます。$n$。 各セルには 3 つの状態があるため、考えられるすべてのミラー配置に対する単純なシミュレーションは指数関数的になるため、構成に対する総当たり検索は不可能です。 固定構成のすべてのパスをシミュレートする場合でも、$O(n^2)$、そのため、構築自体を慎重に構成する必要があります。 

微妙な問題は、ミラーの相互作用がグローバルであることです。 ローカルな変更によりパス全体が再ルーティングされる可能性があるため、列ごとに貪欲に独立して配置することはすぐには有効ではありません。 もう 1 つの失敗モードは、後でミラーを配置した後も以前に固定されたパスが有効であることを保証せずに、順列を上から下まで貪欲に直接一致させようとすることです。 

## アプローチ

 ブルートフォース解釈では、ターゲット列に到達するまでミラーによる水平移動のシーケンスを選択し、これらのパスをグリッドに埋め込むことによって、各レーザーにパスを割り当てようとします。 これはすぐに、交差と共有セルを含むグリッド グラフ上の制約充足問題に変わります。 単一のレーザーの場合でも、可能なジグザグのパスは指数関数的に多く存在し、複数のパスが競合しないようにする必要があるため、検索は困難になります。 

構造上の重要な洞察は、ビームがセルを通過するときにミラーが隣接する列のみを交換するということです。 柱に入る梁$i$ある行ではそのまままっすぐ進むか、列に入れ替わります。$i+1$または$i-1$ミラーの向きによって異なります。 これは、各行がビーム位置の現在の並べ替えに一連の素な隣接スワップを適用するものとして解釈できることを意味します。 

したがって、幾何学的なパスの観点から考える代わりに、グリッドを一連のものとして扱います。$n$各層は隣接する列の独立した交換を実行します。 すべての行を処理した後、ビーム位置の最終的な並べ替えはできるだけ多く一致する必要があります。$a_i$可能な限り割り当て。 

これにより、問題は、最終的な置換とターゲットの置換の間の固定点を最大化する一連の隣接するスワップ層を構築することに変換されます。 各行は、各エッジが一致する折れ線グラフでのマッチングを実装できます。$(i, i+1)$はスワップとして使用されるかどうかのどちらかであり、頂点は行ごとに複数のスワップに参加しません。 

構築は貪欲になります。隣接するスワップを使用して各値を正しい位置に移動するシミュレーションを繰り返し、行をタイム ステップとして消費します。 各スワップは、対応するセルにミラー ペアを配置することによって実装され、ビーム軌道の一貫性が確保されます。

 ## アルゴリズムのチュートリアル

 現在の構成を南の境界に沿った梁ラベルの順列として扱います。 最初はビーム$i$列から始まります$i$。 この順序を維持しながら、正しい宛先を徐々に適用します。 

1. 作業中の順列を初期化する$p[i] = i$、現在どのレシーバーが列に配置されているかを表します。$i$。 また、「.」で埋められたグリッドも維持します。 
2. 行を上から下に処理します。 各行は、順列上で重複しない隣接する一連の交換を実行します。 
3. 各行について、列を左から右にスキャンします。 インデックスを見つけるたびに$i$そのような$p[i] \neq a_i$でも交換$i$そして$i+1$少なくとも 1 つのアラインメントが改善されると、その交換が実行されます。 

この決定は貪欲です:$p[i]$または$p[i+1]$スワップ後にターゲットと一致する場合、それをコミットします。 これにより、すべてのスワップが少なくとも 1 つのポジションの固定に有益となることが保証されます。 

1. ポジションのスワップを実現するには$i$そして$i+1$、鏡を一列に並べます$r$、列$i$そして$i+1$、入射ビームが交差して列を交換できるように、相補的な方向を使用します。 これにより、2 つのビームの制御された交差が作成されます。 
2. 行内のすべてのスワップを処理した後、順列を更新します。 
3. スワップによって一致が改善されなくなるまで、またはすべての行が使用されるまで、この操作を繰り返します。 
4. 満たすポジションの数を数えます$p[i] = a_i$、正しくルーティングされたレーザーの数が得られます。 

この構造により、各行が素のスワップのみを実行することが保証されるため、ビームがあいまいな交差に強制されることはありません。 各スワップはローカルであり、順列進化の観点から可逆的です。 

### なぜ効果があるのか

 不変条件は、各行の後のビームの順列が、グリッドのその深さまでの物理的なビーム軌道によって引き起こされる列位置を正確に表すということです。 行内の各ミラー構成は独立した転置のセットに対応し、これらはその行内の隣接するビーム間で起こり得るすべての相互作用を完全に記述します。 

すべてのスワップは、少なくとも 1 つのビームの正確性が向上する場合にのみ選択されるため、スワップによって、正しく配置されたビームの総数が減少し、後でさらなるスワップによって補正することができなくなります。 連続する行にわたって、現在の順列とターゲットの順列の間のすべての反転は可能な限り最終的に排除され、プロセスは隣接する転置の下で達成可能な最大の固定点と一致する局所的に最適な位置合わせに収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a = [x - 1 for x in a]

    grid = [['.' for _ in range(n)] for _ in range(n)]

    p = list(range(n))
    pos = list(range(n))

    # We simulate row by row, performing swaps greedily
    for r in range(n):
        used = [False] * (n - 1)

        for i in range(n - 1):
            if used[i]:
                continue

            # check if swap helps
            x, y = p[i], p[i + 1]

            if (a[i] == y) or (a[i + 1] == x):
                # perform swap
                p[i], p[i + 1] = p[i + 1], p[i]
                used[i] = True

                # encode swap in grid
                grid[r][i] = '\\'
                grid[r][i + 1] = '/'

        # after row, continue

    # count matches
    ans = sum(1 for i in range(n) if p[i] == a[i])

    print(ans)
    for row in grid:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```実装では、行ごとにグリッドを構築します。 各行は、少なくとも 1 つの梁を直ちに修正するときに、隣接する列を交換することによって局所的な不一致を解決しようとします。 の`used`配列により、スワップが同じ行内で重ならないことが保証されます。これは、ビームが同時に 2 つのミラーに参加できないため必要です。 

グリッド エンコーディングでは、隣接するセル内のペアのミラー配置を使用して、交差点をシミュレートします。 これは、2 つのビームの軌道を交換する離散的な類似物です。 

実装の微妙な詳細は、スワップは元の構成ではなく現在の順列で評価する必要があることです。 更新中`p`各スワップの直後が重要です。そうしないと、同じ行の後の決定が以前のスワップと矛盾することになります。

 ## 特殊なケース

 重要なエッジケースは、順列がすでにソートされている場合です。 ローカル スワップによって正確性が向上しないため、アルゴリズムはスワップを実行しません。 グリッドは空のままで、すべてのビームが正しい受信機に自然にマッピングされます。 

もう 1 つの特殊なケースは、完全に逆の順列です。 このアルゴリズムは、複数の行にわたって隣接するスワップを繰り返し適用し、各要素を正しい位置に向かって徐々に伝播させます。 各行は素のスワップのみを修正するため、要素は干渉することなく安定して移動します。 

より微妙なケースは、次のような巡回置換です。$[2,3,1]$。 ここでは、単一のスワップですべてが解決されるわけではありませんが、各行で 1 つの反転が解消されます。 2 行の後、サイクルはほぼソートされた構成に解決され、最後の行で可能な場合は位置合わせが完了します。
