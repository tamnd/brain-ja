 ## 解決策
 ## 問題の理解

 エッジが都市間の一方向の移動を表す有向グラフが与えられます。 これらのエッジに沿って移動することに加えて、選択した頂点に特別な「ポータル」を配置することができます。 複数の頂点にポータルが含まれている場合、相互に直接到達可能になります。つまり、任意のポータル頂点から他のポータル頂点に瞬時にジャンプできます。 

目標は、ポータルを配置するために選択する頂点をできるだけ少なくし、これらのテレポート接続を追加した後、元の有向エッジとポータル ジャンプの組み合わせを使用して、すべての頂点が他のすべての頂点に到達できるようにすることです。 

言い換えれば、選択したポータル頂点上の完全な有向クリークによって強化された、結果として得られる有向グラフが強く接続されるようにしたいのです。 

制約により、最大で$2 \cdot 10^5$したがって、どのような解も基本的に線形または線形演算的である必要があります。 頂点やエッジを越える 2 次アプローチは生き残れません。 これは、個々の頂点を推論するのではなく、グラフの構造的圧縮が必要であることを直ちに示唆しています。 

重要なエッジ ケースは、グラフがすでに強く接続されている場合に現れます。 この状況では、すべての頂点がすでに有向パスを介して他のすべての頂点に到達しているため、ポータルはまったく必要ありません。 もう 1 つの重要な状況は、到達可能性の点でグラフが完全に切断されている場合です (たとえば、多数のコンポーネントを含む DAG)。 その場合、それらを接続する唯一の方法はポータルであり、答えは元のグラフではなく凝縮構造に完全に依存します。 

## アプローチ

 元のグラフで直接推論しようとすると、すぐに問題に遭遇します。有向エッジの下では到達可能性が推移的で厄介で、ポータルを追加すると、選択した頂点のサブセットに依存する追加の「ショートカット エッジ」が作成されます。 すべてのサブセットを試すと指数関数的になります。 

より直接的な総当たりのアイデアは、一連の頂点を選択し、拡張グラフ上で BFS/DFS による到達可能性をシミュレートし、グラフが強く接続されるかどうかを確認することです。 候補セットを修正したとしても、接続コストを検証する$O(n + m)$、サブセットの数は$2^n$、それは不可能です。 

有向グラフの構造は、標準的な圧縮、つまり強く接続されたコンポーネントを示唆しています。 強く接続されたコンポーネント内では、すべての頂点がすでに他の頂点に到達できるため、同じコンポーネント内のポータルは冗長です。 本当の問題はコンポーネント間で発生します。 

強く接続された各コンポーネントを単一のノードに縮小すると、結果として得られるグラフは有向非巡回グラフになります。 この DAG 内で移動する唯一の方法は、コンポーネント間のエッジに沿って移動することです。 ポータル操作は、複数のコンポーネントを選択した場合、それらの間を両方向に自由に移動して、それらを単一の「スーパーコンポーネント」に効果的にマージできることを意味します。 

したがって、タスクは次のようになります。相互に到達可能にすることで DAG 全体が強力に接続されるように、圧縮 DAG 内のノードの最小数を選択します。 

DAG では、強力な接続を妨げる根本的な障害は、他のソースからソースに到達できず、他のシンクにも到達できないことです。 コンポーネントに入力エッジがない場合、それはソースです。 出力エッジがない場合、それはシンクです。 

重要な点は、すべてのソース コンポーネントがポータルを含むか、ポータル コンポーネントに到達できる必要があり、対称的にすべてのシンクがポータル コンポーネントから到達可能である必要があるということです。 最適な戦略は、これらの境界コンポーネントをカバーすることになります。 

グラフがすでに強く接続されており、両方のカウントがゼロである縮退の場合を除いて、答えは単に凝縮グラフ内のソース コンポーネントの数とシンク コンポーネントの数の最大値であることがわかります。 

直感的には、各ポータルは凝縮 DAG 内の 1 つの「入口ポイント」と 1 つの「出口ポイント」に対応できますが、ソースとシンクには独立した要件が課されます。 それらを最適に一致させると、2 つのカウントが最大になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポータル サブセットに対するブルート フォース |$O(2^n (n+m))$|$O(n+m)$| 遅すぎる |
 | SCC 凝縮 + ソース/シンクのカウント |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、Kosaraju のアルゴリズムまたは Tarjan のアルゴリズムを使用して、グラフを強接続コンポーネントに圧縮します。 各頂点にはコンポーネント ID が割り当てられ、異なるコンポーネント間のエッジによって圧縮されたグラフが定義されます。 

次に、圧縮されたグラフの各成分の入次数と出次数を計算します。 

1. グラフ上で強連結成分分解を実行します。 これにより、相互到達可能性が保たれる最大セットに頂点がグループ化されます。 このような各セット内では、内部接続にポータルは不要です。 
2. 元のグラフのすべてのエッジを反復処理し、エンドポイントが異なるコンポーネントに属している場合は常にコンポーネント ID の間にエッジを追加することによって、凝縮グラフを構築します。 重複したエッジは関係ありません。 
3. 各コンポーネントについて、別のコンポーネントからの入力エッジがあるかどうかを計算します。 そうでない場合、それはソースコンポーネントです。 同様に、別のコンポーネントへの発信エッジがあるかどうかを計算します。 そうでない場合、それはシンク コンポーネントです。 
4. 凝縮グラフ内のソース コンポーネントとシンク コンポーネントの数を数えます。 
5. 全体的に強く接続されたコンポーネントが 1 つだけの場合、グラフはすでに完全に相互に到達可能であるため、0 を返します。 
6. それ以外の場合は、ソースとシンクの最大数を返します。 

これが機能する理由は、DAG では、ポータルを追加した後、すべてのコンポーネントが他のコンポーネントに到達できる必要があるためです。 コンポーネントにポータルを配置すると、選択したすべてのコンポーネント間の双方向の移動が効果的に可能になるため、入口と出口の両方のハブとして機能できます。 ただし、すべてのソースには少なくとも 1 つの入力方法が必要で、すべてのシンクには少なくとも 1 つの出力方法が必要であり、単一のポータル コンポーネントはペアリング構造ごとにこれらの役割の 1 つしか満たせません。 したがって、厳密な境界は、大きい方の側によって支配されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, adj, radj):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in adj[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in radj[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]

    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        radj[b].append(a)
        edges.append((a, b))

    comp, k = kosaraju(n, adj, radj)

    if k == 1:
        print(0)
        return

    indeg = [0] * k
    outdeg = [0] * k

    for a, b in edges:
        ca, cb = comp[a], comp[b]
        if ca != cb:
            outdeg[ca] += 1
            indeg[cb] += 1

    sources = sum(1 for i in range(k) if indeg[i] == 0)
    sinks = sum(1 for i in range(k) if outdeg[i] == 0)

    print(max(sources, sinks))

if __name__ == "__main__":
    solve()
```この解決策は、グラフを読み取り、Kosaraju の 2 パス SCC 分解に必要な両方の隣接リストを構築することから始まります。 最初の DFS は終了順序を生成し、反転グラフ上の 2 番目の DFS はコンポーネント ID を割り当てます。 

SCC 圧縮後、コンポーネントが 1 つだけであるかどうかを明示的にチェックします。 これは、すでに強く接続されているグラフに正確に対応するため、ポータルは必要ありません。 

次に、元のエッジを反復処理して凝縮グラフを暗黙的に構築し、各成分の入次数と出次数を計算します。 これは、すべての圧縮されたエッジを明示的に保存しなくても、ソースとシンクを分類するには十分です。 

最後に、ゼロの入次数を持つコンポーネントの数と、ゼロの出次数を持つコンポーネントの数を数え、それらの最大値を返します。 

微妙な点は、複数のエッジと自己ループは無害であるということです。 自己ループは SCC 構造に影響を与えず、コンポーネントに少なくとも 1 つの入力エッジまたは出力エッジがあるかどうかのみを考慮するため、重複エッジは入次数/出力次数の分類を変更しません。 

## 実用的な例

 グラフがすでに強く結びついている最初のサンプルを考えてみましょう。 すべての頂点は 1 つの SCC に分類されます。 

| ステップ | SCC 数 | 情報源 | シンク | 答え |
 | --- | --- | --- | --- | --- |
 | SCC 分解 | 1 | - | - | 0 |

 これは早期終了条件を示しています。 すべての頂点はすでに相互に到達可能であるため、ポータルを追加する必要はありません。 

ここで、小さな DAG のような構造、つまり 1 → 2 → 3、および 4 が分離されたものを考えてみましょう。 

SCC 圧縮後、各頂点は独自のコンポーネントになります。 

| コンポーネント | 度 | 出次数 |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 2 | 1 | 1 |
 | 3 | 1 | 0 |
 | 4 | 0 | 0 |

 ソースは {1, 4}、シンクは {3, 4} です。 答えは max(2, 2) = 2 です。 

これは、分離されたコンポーネントがソースとシンクの両方として同時に動作し、両方のカウントに影響を与える様子を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、すでに強く結びついているグラフです。 アルゴリズムはそれを 1 つの SCC に圧縮し、すぐに 0 を返します。これにより、コンポーネント レベルで存在しない人為的なソースまたはシンクを誤ってカウントすることが回避されます。 

もう 1 つのケースは、すべての頂点が分離されたグラフです。 各頂点は独自の SCC になり、エッジがないため、すべてのコンポーネントはソースとシンクの両方になります。 このアルゴリズムは、ソースとシンクの両方が n に等しい数をカウントし、n を返します。これは、それらを接続するために頂点ごとに少なくとも 1 つのポータルを選択する必要性に一致します。 

3 番目のケースはチェーン状の DAG です。 圧縮後、最初のノードだけが入次数 0 を持ち、最後のノードだけが次数 0 を持つので、答えは 1 になります。アルゴリズムは、ポータルの双方向移動が導入されると、チェーン内の任意の場所に配置された 1 つのポータルがすべてのコンポーネントを接続するハブとして機能できることを正確に識別します。
