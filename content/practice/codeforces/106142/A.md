 ## 解決策
 ## 問題の理解

 1 から n までのすべての整数が与えられ、それぞれが 1 枚のカードに書かれており、これらのカードは固定された構築ルールを使用して単一のシーケンスに配置されます。 この構造では、まずすべての偶数を取得して昇順に配置し、次にすべての奇数を降順で追加します。 タスクは、この最終シーケンスの k 位置にどの数字が現れるかを決定することです。 

したがって、シーケンスは任意ではなく、動的にクエリされません。 これは、範囲 [1, n] を偶数と奇数の 2 つのグループに分割し、各グループを異なる順序で並べ、それらを連結することによって完全に決定されます。 

n が 100 万までという制約は、位置を直接計算できる場合には、大規模な中間構造を不必要に明示的に構築または保存する余裕がないことを意味します。 ただし、Python では n にわたる線形構築でも 1 秒で実行可能ですが、意図したソリューションでは完全な構築を回避し、代わりに O(1) または O(log n) ロジックで答えを計算します。 

偶数と奇数の境界がどのように決定されるかによって、微妙なエッジケースが発生します。 偶数の数はfloor(n/2)で、それ以降は逆順に奇数になります。 素朴な間違いは、奇数も昇順に現れると仮定したり、偶数がいくつ存在するかを誤って計算したりすることです。これにより、分割点が移動します。 

たとえば、n = 7 の場合、偶数は [2, 4, 6]、オッズは [7, 5, 3, 1] となります。 境界は位置 3 にあります。k = 4 の場合、すでに奇数セグメント内にあるため、そのセグメント内でインデックス付けを逆にする必要があります。 偶数を数える際に 1 つずれたエラーが発生すると、すぐに間違った答えが生成されます。 

## アプローチ

 ブルート フォース ソリューションは、1 から n まで反復し、偶数と奇数を 2 つの配列に分離し、奇数の配列を反転して、それらを連結することによってシーケンスを直接構築します。 これは構築ルールに正確に一致します。 コストは O(n) 時間と O(n) メモリです。 

O(n) は、厳密な言語では 10^6 までの n に対して許容されますが、Python のオーバーヘッドと繰り返しのリスト操作により、エレガントさが失われ、環境の制約によっては限界に達する可能性があります。 さらに重要なのは、シーケンスの構造により、完全な配列を構築しなくても直接インデックス付けが可能になることです。 

重要な観察は、シーケンスの最初の部分が完全に決定されており、すべての偶数が昇順であるということです。 このような数値は正確に n // 2 個あり、それらの k 番目の位置は単純に k 番目の偶数、つまり 2k になります。 k がこの数を超えると、奇数セグメントに入ります。 奇数セグメントは降順のすべての奇数で構成されているため、k を奇数ブロック内の位置にマップし、対応する奇数値を直接計算できます。 

これにより、配列を構築する必要がなくなり、問題が単純な算術演算に軽減されます。

 ## アルゴリズムのチュートリアル

 位置 k を偶数ブロックにあるか奇数ブロックにあるかに分割して答えを計算します。

1. まず、1 と n の間に偶数がいくつ存在するかを計算します。 これは n // 2 です。これは、最終シーケンスの最初のセグメントの長さを示します。 
2. k が n // 2 以下の場合、答えは偶数セグメントにあります。 偶数は 2、4、6 などとしてリストされるため、k 番目の要素は単純に 2 * k になります。 これが機能するのは、シーケンスがまさに偶数のソートされたリストであるためです。 
3. それ以外の場合、答えは奇数セグメントにあります。 k - n // 2 を計算することにより、k を奇数ブロック内のインデックスに変換します。これにより、奇数セグメント内にどれだけ入っているかがわかります。 
4. 奇数の昇順は 1、3、5、... になりますが、シーケンスではそれらを逆の順序で使用します。 したがって、奇数ブロック内の位置 t を t 番目に大きい奇数にマップする必要があります。 
5. 奇数要素の総数は n - n // 2 です。降順の t 番目の要素は、昇順で (total_odds - t + 1) 番目の奇数に対応します。 これを算術に変換すると、正しい値が直接得られます。 

なぜ効果があるのか

 このシーケンスは、独立してソートされた 2 つのサブシーケンス (偶数が昇順、オッズが降順) を連結したものです。 各サブシーケンスには、k 番目の要素に対する閉じた形式の式があります。 それらの間の境界は、配置の詳細とは関係なく、パリティ数によって固定されます。 インターリーブが発生しないため、すべてのインデックスは正確に 1 つの等差数列に一意にマッピングされ、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())

even_count = n // 2

if k <= even_count:
    print(2 * k)
else:
    t = k - even_count
    odd_count = n - even_count
    # t-th largest odd number
    # largest odd is (2*odd_count - 1)
    print((2 * odd_count - 1) - 2 * (t - 1))
```コードはまず、偶数がいくつ存在するかを計算し、それによってシーケンス内の分割ポイントが決定されます。 k が偶数プレフィックス内にある場合、偶数は 2 から始まる昇順に配置されるため、2k を直接返します。 

k が奇数のサフィックスにある場合、k を奇数ブロック内のインデックスに変換します。 最大の奇数は 2 * od_count - 1 であり、後方ステップごとに 2 ずつ減少するため、正しい要素に到達するには 2 * (t - 1) を減算します。 

よくある落とし穴は、奇数が逆の順序で配置されていることを忘れることで、最大値から逆にせずに 2t - 1 を誤って使用してしまいます。 

## 実用的な例

 n = 7、k = 4 を考えてみましょう。 

Even_count = 3 なので、偶数は 1 ～ 3 の位置を占めます: [2, 4, 6]。 k = 4 なので、奇数セグメントにいます。 

| ステップ | k | 偶数カウント | t | 奇数数 | 計算 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 4 | 3 | - | 4 | k > 偶数 |
 | 地図 | - | - | 1 | 4 | t = 4 - 3 |
 | 結果 | - | - | 1 | 4 | 最大の奇数 = 7、答え = 7 |

 したがって、出力は 7 になります。 

ここで、n = 12、k = 8 について考えてみましょう。 

Even_count = 6、偶数は [2、4、6、8、10、12] です。 k = 8 はオッズにあります。 

| ステップ | k | 偶数カウント | t | 奇数数 | 計算 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 8 | 6 | - | 6 | k > 偶数 |
 | 地図 | - | - | 2 | 6 | t = 8 - 6 |
 | 結果 | - | - | 2 | 6 | 最大の奇数 = 11、答え = 11 - 2 = 9 |

 これにより、逆奇数順序への正しいマッピングが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    k = int(input())

    even_count = n // 2

    if k <= even_count:
        return str(2 * k)
    else:
        t = k - even_count
        odd_count = n - even_count
        return str((2 * odd_count - 1) - 2 * (t - 1))

# provided samples
assert run("7\n3\n") == "5"
assert run("12\n8\n") == "9"
assert run("4\n1\n") == "2"

# custom cases
assert run("2\n1\n") == "2", "smallest even-first structure"
assert run("3\n3\n") == "1", "single odd at end"
assert run("1\n1\n") == "1", "degenerate odd-only"
assert run("10\n5\n") == "9", "boundary transition check"

 ## 特殊なケース

 n = 1 の場合、シーケンスは [1] のみで構成されます。 偶数カウントはゼロであるため、すべての k は奇数ブランチに分類されます。 計算により、odd_count = 1 および最大奇数 = 1 が得られるため、答えは 1 となり、シーケンスと一致します。 

n = 2 の場合、シーケンスは [2, 1] です。 Even_count = 1。k = 1 の場合、2 を返します。k = 2 の場合、奇数分岐に入り、t = 1、odd_count = 1、最大奇数 = 1 となり、1 が得られます。これにより、最小の非自明な分割が正しく処理されることが確認されます。 

n = 7、k = 3 (偶数セグメントの境界)、even_count = 3 の場合、2 * 3 = 6 が返され、構築されたシーケンス [2, 4, 6, 7, 5, 3, 1] と一致します。
