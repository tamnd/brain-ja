 ## 問題の理解

 長さの隠された順列が与えられています$n$。 重要な特別な要素は 2 つだけです: 最小値の位置$1$が座っており、最大値が存在する位置$n$座ります。 あらゆるポジションについて$i$の位置からどのくらい離れているかを計測します。$n$の位置からどのくらい離れているか$1$そして、すべての位置にわたるこれらすべての距離を合計します。 その合計が価値です$m$。 

タスクは逆になります。順列から始める代わりに、次のことが与えられます。$n$そして$m$、そして、正確にこの合計を生成できる任意の順列を構築するか、そのような順列が存在しないと判断する必要があります。 

ステートメントでは完全な順列について言及していますが、値に影響を与える唯一の要素は、$1$そして$n$。 それらの位置が固定されると、他のすべての数値は、計算値に影響を与えることなく任意に配置できます。 

制約は十分小さいので、$n$すべてのテスト ケースの合計は 6000 に達する可能性があります。 これは、位置のすべてのペアにわたる二次スキャンが許容されることを意味します。 のようなもの$O(n^3)$または、テスト ケースごとに再計算を繰り返しても、グローバル バウンドにより合格しますが、その必要はありません。 

ポジションを「貪欲に」選択しようとすると、微妙なエッジケースが現れます。$1$そして$n$地元の貢献に基づいています。 たとえば、距離の合計を最大化または最小化するために極値を選択することは失敗します。これは、完全な式をチェックせずに貪欲な構築をサポートする方法で位置のペアと合計の関係が単調ではないためです。 もう 1 つの問題は、中心の周りの対称性が常に機能すると仮定していることです。 たとえば$n=5$、配置$1$そして$5$対称位置では一意に決定されない$m$したがって、正確な合計を計算せずに推測すると、不正確な値が得られます。 

## アプローチ

 単純な考えは、順列全体を再構築し、距離を直接計算することです。 置いてみるのもいいかもしれません$1$そして$n$すべての可能な位置に配置し、残りを任意に埋めて、結果を計算します。$m$毎回。 これには試してみる必要があります$O(n^2)$配置と完全な再計算$O(n)$毎回合計して与える$O(n^3)$テストケースごとに。 と$n$テスト全体で合計 6000 に達すると、速度が遅すぎます。 

重要な観察は、順列へのすべての依存関係が 2 つのインデックスのみに集約されることです。$1$、呼んでください$L$、および位置$n$、呼んでください$R$。 これらが固定されると、他のすべての値は、これら 2 点までの距離によってのみ影響されます。 

関数を事前計算できます$g(i)$、位置からの距離の合計$i$すべてのインデックスに:$$g(i) = \sum_{j=1}^n |i - j|$$この場合、必要な値は次のようになります。$$m = g(L) + g(R)$$これにより、問題は 2 つの異なるインデックスを見つけることになります。$L$そして$R$事前に計算された値の合計が次のようになります$m$。 これは、サイズの配列に対する古典的な 2 つの合計です。$n$、で解決可能$O(n^2)$テストケースごと、またはハッシュを使用した場合でも。 

一度$L$そして$R$が既知である場合、次のようにして有効な順列を構築します。$1$で$L$、$n$で$R$、残りの位置を未使用の番号で任意に埋めます。

 ## アルゴリズムのチュートリアル

 この問題を位置ペアの観点から完全に書き直します。 

1. 配列を事前計算する$g$、各位置はどこですか$i$から合計距離を計算します。$i$すべてのポジションに$1$を通して$n$。 これは次の方法で実行できます$O(n)$直接合計するのではなく、プレフィックス推論を使用してインデックスごとに計算します。 式は次のとおりです。$$g(i) = \frac{i(i-1)}{2} + \frac{(n-i)(n-i+1)}{2}$$これにより、左側と右側からの寄与が分離されます。$i$。 
2. 次に、2 つの異なるインデックスを見つける必要があります。$L$そして$R$次のような:$$g(L) + g(R) = m$$すべてを繰り返します$L$、それぞれに対して必要な補数を計算します。$m - g(L)$。 
3. の値を保存します。$g(i)$値をインデックスにマッピングする辞書内。 補数の一致が見つかった場合、インデックスが異なることを確認します。 
4. そのようなペアが存在しない場合、答えは不可能であり、0 を出力します。 
5. 完了したら$L$そして$R$を配置して順列を構築します。$1$位置にある$L$、$n$位置にある$R$、残りの位置を 2 から 2 までの数字で埋めます。$n-1$任意の順序で。 

構築ステップは、合計の正確さとは無関係です。 すべての正しさは次の選択によって保証されます$L$そして$R$。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な順列が値に関して一意に決定されることです。$m$、その最小要素と最大要素の位置によって決まります。 他のすべての要素は両方の距離の合計に対称的に寄与しますが、それらの同一性は式にまったく影響しません。 これにより、状態空間が順列からインデックスの順序付きペアに折りたたまれます。 すべての実行可能なソリューションは 1 つのペアに正確に対応するため、$(L, R)$、すべてのペアを検索することが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        g = [0] * (n + 1)
        for i in range(1, n + 1):
            left = i * (i - 1) // 2
            right = (n - i) * (n - i + 1) // 2
            g[i] = left + right

        pos = {}
        L = R = -1

        for i in range(1, n + 1):
            need = m - g[i]
            if need in pos:
                L = pos[need]
                R = i
                break
            if g[i] not in pos:
                pos[g[i]] = i

        if L == -1:
            out.append("0")
            continue

        perm = [0] * n
        perm[L - 1] = 1
        perm[R - 1] = n

        cur = 2
        for i in range(n):
            if perm[i] == 0:
                perm[i] = cur
                cur += 1

        out.append(" ".join(map(str, perm)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、2 和への削減を反映しています。 配列$g$は閉じた形式の式から直接計算され、インデックスごとの合計ループが回避されます。 ディクショナリには、以前に確認された値が保存されます。$g(i)$、各ステップで補体が存在するかどうかがチェックされます。 

よくある落とし穴は、同じ値であることを忘れることです。$g(i)$他の問題では原理的に複数の指数で出現する可能性がありますが、ここでは$g(i)$は厳密に凸型であり、位置を一意に識別するため、最初に出現したもののみを保存するのが安全です。 

置換構造は固定を超えて任意です$1$そして$n$したがって、残りのスロットを昇順に埋めるだけです。

 ## 特殊なケース

 非常に小さい場合$n=3$、関数$g$には異なる値が 2 つだけあり、有効なペアのみが強制されます。 ハッシュ マップは補数ペアを即座に検出または拒否するため、アルゴリズムはこれを正しく処理します。 

たとえば入力$n=3, m=2$、計算します$g = [3,2,3]$。 で$i=2$、補数は$0$、マップには決して存在しないため、アルゴリズムは構成に応じて 0 または有効なペアを正しく返します。 

次のような対称分布の場合$n=5, m=20$、複数の有効なペアが存在します。 アルゴリズムは、最初に見つかった有効な一致を選択します。 有効なペアはどれも正しい配置に対応するため、$1$そして$n$の場合、ソリューションが一意でない場合でも、出力は有効なままになります。
