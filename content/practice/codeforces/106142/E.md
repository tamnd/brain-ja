 ## 問題の理解

 整数の配列としきい値が与えられます。$d$。 オプションで、配列から連続するセグメントを 1 つだけ削除した後、残りの要素は、最大値から最小値を引いた値が最大であるシーケンスを形成する必要があります。$d$。 目標は、最終的な配列自体を最適化することではなく、単一の連続した削除で削除される要素の数を最小限に抑えることです。 

操作を再構成する便利な方法は、保持するプレフィックスとサフィックスを選択し、その間にあるものはすべて破棄することです。 最終的な配列は常に次の形式になります。$a[1..l]$と組み合わせた$a[r..n]$, ここで、削除されたセグメントは$a[l+1..r-1]$。 課題は選択することです$l$そして$r$最小限に抑える$r-l-1$、残りの要素が満たされるという条件に従う$\max - \min \le d$。 

制約により許可されるのは、$n$最大 200,000 であるため、すべての削除間隔またはすべてのサブ配列にわたる二次アプローチは遅すぎます。 解決策は線形か、最悪でも線形に近いものでなければなりません$O(n \log n)$。 これは、範囲の最大値と最小値について事前に計算された構造と組み合わせた 2 ポインターまたはスライディング ウィンドウ構造を強く示唆しています。 

微妙な点は、削除されたセグメントが空であってもよいということです。これは、配列全体を保持できることを意味します。 これにより、ゼロという自然なベースライン応答が作成されます。 もう 1 つのエッジ ケースは、配列がすでに全体的に条件に違反しているが、完全なサフィックスまたはプレフィックスだけでは制約を満たさない場合でも、中央の 1 つのセグメントを削除することで問題を修正できる場合です。 

削除された可能性のあるすべての間隔をチェックする単純なアプローチは、次の理由で失敗します。$O(n^2)$それぞれの候補は、2 つの互いに素なセグメントにわたる最小値と最大値の再計算を必要とします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのインデックスのペアを試します$(l, r)$、それらの間のセグメントを削除すると解釈し、残りの要素の最小値と最大値を計算します。 条件が当てはまる場合は、削除されたセグメントのサイズで答えを更新します。 これは、有効な操作をすべて列挙しているため、正しいです。 

ただし、各ペアの残りの要素の最小値と最大値を再計算するにはコストがかかります。 プレフィックスとサフィックスの最小値と最大値を事前に計算したとしても、それらを組み合わせて任意の削除を行うには依然として一定の時間が必要ですが、$O(n^2)$の選択肢$(l, r)$、約につながる$2 \cdot 10^{10}$限界をはるかに超えた最悪の場合にチェックします。 

重要な観察は、何を取り除くかについて考える代わりに、何を残しておくかについて考えることができるということです。 残りの要素は 2 つの互いに素なセグメントに由来しており、それらの結合の範囲は狭い必要があります。 この条件は、保持される要素のグローバル最小値と最大値にのみ依存します。 これは、位置ではなく順序の観点から値を並べ替えるか、少なくとも推論することを示唆しています。 

たとえば、何らかのインデックスに固定することによって、保持されたセットの最小値を固定する場合$i$の場合、最大許容値は、内のすべての要素として決定されます。$[a[i], a[i] + d]$。 残りのタスクは、大きな中間ギャップを含める必要がないことを確認しながら、この値の間隔をどの程度維持できるかを選択することになります。 これは、値の制約内に留まりながら、保持された要素の左右の境界として機能できる最適な位置のペアを見つけることに変換されます。 

有効な値ウィンドウ内に留まりながら、左右にどこまで拡張できるかを位置ごとに事前計算できます。 この場合、最適な保持セットは、値の有効なウィンドウの保持サイズを最大化することに対応し、答えは次のようになります。$n$保持されている最大サイズを差し引いたものです。 これは、値の間隔によって制約された、並べ替えられた、または暗黙的に順序付けされたインデックスの構造に対する 2 つのポインターを使用して解決できます。

 ## アルゴリズムのチュートリアル

 この問題を、1 つの連続したブロックを削除した後、プレフィックスとサフィックスで構成される保持されるサブセットのサイズを最大化することとして再解釈します。 

1. インデックスを暗黙的にソートまたは維持しますが、削除はインデックス内で連続する必要があるため、元の順序を維持します。 代わりに、値でソートされた構造に対して 2 ポインター手法を使用して値の制約を強制しながら、インデックス上でウィンドウをスライドさせることに焦点を当てます。 
2. 値が最大で異なる要素の有効なウィンドウを維持できる構造を構築します。$d$。 現在保持されている構造内の最小値と最大値を維持しながら、配列上で右ポインタを展開します。 維持される構造は連続していないため、左側と右側の部分の間で可能な限り最適な分割を追跡します。 
3. 左側に保持されているセグメントの可能な右端点ごとに、両方のセグメントのすべての値が制約を満たすように、右側に保持されているセグメントの最も遠い左端点を見つけます。 これは、配列上のポインタを維持し、極値の差が最大でも異なるかどうかをチェックすることになります。$d$。 
4. インデックス上に 2 ポインタ ウィンドウを維持しますが、中間セグメントのスキップは許可します。 固定された左境界ごとに$l$、右の境界を移動します$r$ギャップの外側の値の結合が有効なままになるように、できるだけ右に移動します。 候補の削除を次のように計算します。$r - l - 1$。 
5. このようなすべての構成にわたって最小値を追跡します。 

重要な考え方は、有効性は保持される要素の最小値と最大値のみに依存し、ポインタの移動を使用してそれらの値を段階的に維持できるということです。 

### なぜ効果があるのか

 アルゴリズムは常に、削除されたセグメントの周囲で配列を保持するプレフィックスと保持するサフィックスに分割するあらゆる方法を考慮します。 このような分割ごとに、条件は$\max - \min \le d$は、保持された 2 つの部分の結合に適用されます。 ポインタの移動は候補領域を単調に拡大するだけであり、除去中の有効性は単調であるため、すべての最適な構成はスキャン中に何らかの境界ペアとして表示されます。 これにより、有効な構成がスキップされず、実行可能なすべての分割の中から最小限の削除されたセグメントが見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    # We maintain best answer by trying all splits:
    # keep prefix [0..i] and suffix [j..n-1], remove (i+1..j-1)
    # We need max-min over kept elements <= d.

    ans = n  # worst case remove everything

    # Precompute prefix min/max and suffix min/max
    pref_min = [0] * n
    pref_max = [0] * n
    suff_min = [0] * n
    suff_max = [0] * n

    pref_min[0] = pref_max[0] = a[0]
    for i in range(1, n):
        pref_min[i] = min(pref_min[i-1], a[i])
        pref_max[i] = max(pref_max[i-1], a[i])

    suff_min[-1] = suff_max[-1] = a[-1]
    for i in range(n-2, -1, -1):
        suff_min[i] = min(suff_min[i+1], a[i])
        suff_max[i] = max(suff_max[i+1], a[i])

    j = 0

    for i in range(n + 1):
        if i > 0:
            left_min = pref_min[i-1]
            left_max = pref_max[i-1]
        else:
            left_min = float('inf')
            left_max = -float('inf')

        while j < n:
            right_min = suff_min[j]
            right_max = suff_max[j]

            if i <= j:
                cur_min = min(left_min, right_min)
                cur_max = max(left_max, right_max)
            else:
                # overlap not possible; just break
                break

            if cur_max - cur_min <= d:
                break
            j += 1

        if i <= j:
            ans = min(ans, j - i)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックスとサフィックスの極値配列を構築し、左側に保持されたセグメントと右側に保持されたセグメントへの分割を一定時間で評価できるようにします。 次に、削除されたセグメントの考えられるすべての境界を反復処理します。 左側の境界ごとに、残りの要素が制約を満たすまで、右側の境界を貪欲に前方に移動します。 答えは、これら 2 つの境界間の最小ギャップです。 

実装の微妙な点は、ポインタが単調である必要があることです。 左側の境界を拡張しても右側の制約が緩和されるだけであるため、右ポインタが特定の左側に対して前方に移動すると、後方に移動する必要はありません。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列がすでに条件をグローバルに満たしている場合です。 その状況では、正しい答えはゼロであり、アルゴリズムはそれを処理します。$i = 0, j = 0$ポインタを移動しなくても、すでに有効な構成が生成されています。 

もう 1 つのケースは、小さな中間セグメントを除くすべての要素が有効な場合です。 たとえば、次のような配列では、$[1, 100, 101, 2]$小さいもので$d$、最適な削除は中央のブロックです。 ポインターベースの拡張により、自然にプッシュされます。$j$違反が解決され、ギャップが最小になるまで前進します$j - i$その削除をキャプチャします。 

最後のケースは、両端に極値がある場合です。$[1, 100, 2, 99]$。 正しい解決策には、互換性のない極端な部分を切断する中央セグメントを削除する必要がある場合があります。 アルゴリズムは、保持された部分が有効な極値の組み合わせを形成するすべてのプレフィックスとサフィックスの分割を体系的に考慮するため、この構成を引き続き評価します。
