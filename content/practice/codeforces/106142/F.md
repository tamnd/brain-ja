 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、ポジションごとに、そのポジションの値に関する別の最適化の質問に答える必要があります。 インデックス i の要素は固定参照要素として扱われます。 配列から他の要素を削除することができ、削除後に残りのシーケンスを確認します。 インデックス i の目標は、その値が、同点を許可された残りのすべての要素の最大値になるようにすることです。 これを達成するために必要な削除数は最小限に抑えたいと考えています。 

タスクを表示するもう 1 つの方法は、要素 a[i] ごとに、a[i] を含む配列のサブセットを保持することです。そのサブセットには、厳密に a[i] より大きい要素があってはなりません。 a[i] より大きいものはすべて削除する必要があります。 a[i] 以下の要素では、自由に保持または削除できますが、削除にはコストがかかるため、削除する要素は少ない方が常に良いです。 

制約は n = 200000 までなので、すべての i にわたる二次関数の動作を伴う解は直ちに不可能になります。 配列をスキャンして削除を数えることによって各 i の答えを再計算する単純なアプローチでは、O(n^2) となり、大きすぎます。 このため、最初から再計算するのではなく、配列のグローバル構造を再利用するソリューションを選択する必要があります。 

値が繰り返される場合、微妙なケースが発生します。 値が何度も出現する場合、1 つの出現を「最大代表」として選択することは、他の同等の要素を保持できることを意味します。 たとえば、[5, 1, 5] のような配列では、中央の要素 1 については、すべての 5 を削除する必要があるため、答えは 2 になります。5 の場合、すべての 5 を保持できるため、削除は必要ありません。 

もう 1 つの重要なエッジ ケースは、要素がすでにグローバルに最大値である場合です。 この場合、すでに条件を満たしているため、削除する必要はありません。 誤って等しい要素を削除としてカウントするアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各インデックス i について、値 x = a[i] を固定します。 次に、厳密に x より大きい要素がいくつあるかを計算します。 そのような要素はすべて削除する必要があります。 それらを削除した後、残りの配列は x が最大値であることを自動的に満たします。 したがって、i の答えは単に a[i] より大きい要素の数です。 これは正しいです。有効なサブセットには、より大きな要素を含めることはできないからです。 

単純な実装では、i ごとに配列全体をスキャンし、a[i] より大きい値をカウントします。 これにはクエリごとに O(n) のコストがかかり、合計操作数は O(n^2) になります。 n が最大 200000 であるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、答えは値 a[i] のみに依存し、その位置には依存しないということです。 2 つの位置が同じ値を持つ場合、それらの答えは同じになります。 したがって、インデックスごとに再計算する代わりに、すべての個別の値 x について、配列内の x より大きい要素の数を知る必要があるだけです。 

これは、ソートまたは頻度の蓄積を直ちに示唆します。 配列値を並べ替える場合、周波数にわたる接尾語の合計を使用して、各値 x について厳密に x より大きい要素の数を計算できます。 考えられるすべての値についてこれがわかったら、事前計算された結果をすべての位置に割り当てます。 

問題の構造は、グローバル ランク付けの質問に要約されます。各要素の答えは、元の配列内の位置ではなく、値の順序付けにおけるランクによって決まります。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. それぞれの個別の値が配列内に出現する回数を数えます。 同じ値は最終的な答えでは同じように動作するため、これにより問題が位置から値に圧縮されます。 
2. 個別の値を昇順に並べ替えます。 これにより、最小値から最大値への明確な順序が確立され、指定された値よりも大きい要素の数を推論できるようになります。 
3. これまでに見つかった要素の数の累計を維持しながら、並べ替えられた値を最大値から最小値までたどります。 この累計は、現在の値より厳密に大きい要素の数を表します。 
4. 各値 x に対して、x の度数を加算する前に、現在の合計に等しい回答 [x] を降順に割り当てます。 これが機能するのは、その時点で厳密に x より大きいすべての値がすでに考慮されているためです。 
5. x の度数を累計に加算すると、より小さい値でもカウントに含まれるすべてのより大きな値が正しく表示されます。 
6. 最後に、度数表または辞書検索を使用して、これらの事前計算された回答を元の各インデックス i にマッピングします。 

これが機能する理由: 固定値 x の場合、有効なサブセット内で x より大きいすべての要素を削除する必要があります。 x 以下の要素は、x が依然として最大値であるため、正確性を理由に削除する必要はありません。 したがって、最小の削除は正確に x より大きい要素の数であり、並べ替えられた値に対するサフィックスの累積により、この数量が個別の値ごとに 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1

    vals = sorted(freq.keys())
    
    greater_count = 0
    ans_value = {}

    for v in reversed(vals):
        ans_value[v] = greater_count
        greater_count += freq[v]

    out = []
    for v in a:
        out.append(str(ans_value[v]))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```実装は、すべての値の周波数マップを構築することから始まります。 アルゴリズムは位置ではなく値クラスに基づいて動作するため、これは不可欠です。 ソートされたキーのリストは、より大きな要素のカウントを蓄積する順序を定義します。 

逆走査により、ans_value[v] を代入するときに、変数 great_count に厳密に v よりも大きいすべての要素がすでに含まれていることが保証されます。更新ステップは代入後に発生します。これは、現在の値自体を誤ってカウントすることを避けるために重要です。 

最後に、直接辞書検索を使用して回答を各位置にマッピングし、最終的な再構築を線形に保ちます。

 ## 特殊なケース

 すべての要素が等しい場合、逆走査では厳密にそれより大きい要素は検出されないため、アルゴリズムはすべての値に 0 を割り当てます。 入力用`[10, 10, 10]`、頻度マップには単一のキーがあり、greater_count は 0 から始まるため、すべてのインデックスは 0 を受け取ります。 これは、選択した要素がすでに最大であるという要件に一致します。 

配列が厳密に増加している場合、最後の要素を除くすべての要素は、より大きな接尾辞要素をすべて削除する必要があります。 のために`[1, 2, 3, 4]`の場合、サフィックス累積は正しい減少する答えを割り当てます。これは、各値が値の順序でその右側の要素を正確に参照し、厳密にそれより大きいすべての値に対応するためです。
