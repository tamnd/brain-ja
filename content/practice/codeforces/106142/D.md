 ## 問題の理解

 複数の独立したクエリを処理するように求められます。 各クエリには間隔が与えられます$[a, b]$そして目標数値$k$。 すべての整数に対して$x$その間隔で変換します$x$先行ゼロのないバイナリに変換し、1 に等しいビットがいくつあるかを数えます。タスクは、区間内で正確に一致する数値がいくつあるかを数えることです。$k$バイナリ表現のもの。 

入力制約は非常に厳しいため、クエリごとにすべての数値を直接チェックすることが直ちに除外されます。 以来$b$まで行くことができます$10^9$、バイナリ表現は最大 30 ビットです。 ビット長の小さな上限が重要な構造特性です。問題は基本的に長さが最大 30 のビットマスクの分布に関するものです。 

単純なクエリごとのスキャン$a$に$b$までの費用がかかります$10^9$最悪の場合、クエリが 1000 件許可される範囲をはるかに超えて操作が可能になります。 平均して間隔が狭い場合でも、競技プログラミングでは最悪の場合の動作が重要になります。 

先頭にゼロを付けずにバイナリ表現をカウントしているという事実から、微妙なエッジ ケースが発生します。 私たちは固定幅のビット文字列を扱っていないので、これは重要です。 最上位ビットの位置は数値自体によって異なります。 例えば、$7 = 111_2$3 つありますが、$8 = 1000_2$パディングされている場合は両方とも 4 ビット表現ですが、 には 1 が 1 つあります。 

もう 1 つのエッジケースは次のような場合です$k$間隔内の数値のビット長を超えています。 たとえば、次の場合$a = 1, b = 3$、1 の最大数は 2 であるため、次のクエリはすべて$k \ge 3$ゼロを返さなければなりません。 正しいソリューションでは、特別なケースを使用せずにこれを自然に処理する必要があります。 

## アプローチ

 ブルートフォース手法では、すべての数値を直接反復処理します。$x \in [a, b]$、それをバイナリに変換し、設定されたビットをカウントし、それが等しいかどうかを確認します$k$。 これは問題の定義に正確に従っているため、正しいです。 番号あたりのコストは、$O(\log x)$ビットをカウントするにはバイナリ表現をスキャンする必要があるためです。 一定の間隔で、これは次のようになります$O((b-a+1)\log b)$クエリごとに。 最悪の場合、$a=1$そして$b=10^9$、これについてです$10^9 \cdot 30$クエリごとの操作ですが、これはまったく実行不可能です。 

重要な観察は、条件がバイナリ表現と最大の数値にのみ依存するということです。$10^9$30ビット以内に収まります。 値を反復処理する代わりに、バイナリ表現での数値動的プログラミングを使用して、指定された境界までに有効なビット パターンがいくつ存在するかをカウントします。 関数を計算できるようになると、$F(x)$の数を数えます。$[0, x]$まさに$k$1 の場合、各クエリは減算になります$F(b) - F(a-1)$。 

これにより、問題は値の反復から、30 で制限されるビット位置の反復に変換されます。状態空間は範囲サイズに関係なく、小さく固定されます。

 ## アルゴリズムのチュートリアル

 関数を定義します$F(x)$それは整数が何個あるかを数えます$[0, x]$まさに持っています$k$バイナリ表現のもの。 

1.変換$x$最上位から最下位までのビットの配列としてバイナリ表現に変換されます。 これにより、トラバースするための固定長の構造が得られます。これは、数字 DP に不可欠です。 
2. バイナリ文字列内の位置に対して DP 状態を定義します。 各位置に 0 を配置するか 1 を配置するかを決定しますが、超えてはいけないという制約を尊重する必要があります。$x$。 これは、これまでのプレフィックスが次のプレフィックスと正確に等しいかどうかを示すタイト フラグを使用して処理されます。$x$。 
3. すでに配置したものの数も追跡します。 最終的な答えはそれに依存するため、このカウントは状態の一部です。 
4. 遷移では、現在のビットの両方の選択が考慮されます。 1 を配置すると、1 の数が増加します。 0 を置くと、カウントは変化しません。 を超えない移行のみが許可されます。$k$を超えるパスがあるため、$k$早い段階で破棄できるもの。 
5. ビット文字列の終わりに達したら、1 の数が等しいかどうかを確認します。$k$。 そうであれば、これは有効な数値です。 
6. 各クエリについて、計算します。$F(b) - F(a-1)$。 減算により間隔が正しく分離されます。 

重要な設計上の選択は、数値を反復する代わりに、ビット位置を反復して有効な数値を増分的に構築し、上限を決して違反しないようにすることです。 

### なぜ効果があるのか

 内のすべての整数$[0, x]$これは、長さが最大 ​​30 の 1 つのバイナリ文字列に相当します (概念的には先頭にゼロが埋め込まれます)。 DP は、そのような文字列をすべて、反復せずに構造化された方法で列挙します。 厳しい制約により、次の値を超える数値は決して生成されません。$x$、1 カウント ディメンションにより、有効な構成のみが蓄積されることが保証されます。 すべての有効な数値は 1 回だけ形成され、無効な数値はカウントされないため、DP の結果は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def count_upto(x, k):
    bits = list(map(int, bin(x)[2:]))
    n = len(bits)

    @lru_cache(None)
    def dp(i, tight, ones):
        if ones > k:
            return 0
        if i == n:
            return 1 if ones == k else 0

        limit = bits[i] if tight else 1
        res = 0

        for b in (0, 1):
            if b > limit:
                continue
            res += dp(i + 1, tight and (b == limit), ones + b)

        return res

    return dp(0, True, 0)

t = int(input())
for _ in range(t):
    a, b, k = map(int, input().split())
    print(count_upto(b, k) - count_upto(a - 1, k))
```この解決策は、上限のバイナリ表現に対して再帰的な数字 DP を構築します。 機能`count_upto`有効な数値を次まで数えます`x`まさに`k`もの。 メモ化により、各状態が 1 回計算されることが保証されます。 

の`tight`flag はプレフィックス制約を強制します。これが true の場合、現在のビットは、対応するビットを超えることはできません。`x`。 より小さなビットを配置すると、自由状態に切り替わります。 

の`ones`パラメータは、これまでに配置されたものの数を追跡します。 早めの剪定の場合`ones > k`無効なブランチの探索を回避します。

 ## 特殊なケース

 次のような単一値間隔の場合$a=b=2^{30}$、バイナリ表現は、単一の 1 の後にゼロが続きます。 DP は完全なビット パターンに等しい厳しい制約で開始され、有効なパスが 1 つだけ許可されます。 1 のカウンタはちょうど 1 に達するため、次の場合には正しく 1 を返します。$k=1$それ以外の場合は 0。 

場合の場合$k=0$、 のような$a=1, b=10$、すべての正の数値には少なくとも 1 つの設定ビットがあるため、正の整数は適格ではありません。 DP は、区間内にない数値 0 を除き、先頭のゼロのみの数値を除外する表現規則を尊重しながらすべてゼロを配置することは不可能であるため、すべてのパスを正しく拒否します。
