 ## 解決策
 ## 問題の理解

 入力は、交差点が頂点、道路がエッジである重み付き無向グラフを記述します。 各道路には長さがあり、通常は両方向に使用できます。 特定の道路ごとに、この特定の道路が通行止めになっていると想像し、残りの道路を使用してその端点間の最短の代替ルートを計算することが求められます。 

言い換えれば、2 つの頂点を接続する各エッジについて、そのエッジを一時的に削除し、変更されたグラフ内の同じ 2 つの頂点間の最短パスを求めます。 そのエッジのないパスが存在しない場合は、-1 を出力します。 

頂点の点での制約は小さく、ノード数は最大 300 です。 これは、N を超える 3 次またはわずかに悪い動作を持つアルゴリズムが許容されることを直ちに示唆しています。 ただし、エッジの数は小さくないため、エッジごとに完全な最短パスの計算を繰り返すものは、最悪の場合、非常に遅くなります。 ダイクストラを 1 回実行するのは問題ありませんが、それを M 回実行すると、エッジ セットあたり数千万回の操作が必要となり、5 秒未満では安全ではありません。 

微妙な問題は、直接エッジ自体がそのエンドポイント間の固有の最短ルートである可能性があるという事実から生じます。 その場合、それを削除すると経路が大幅に迂回することになり、答えは本来の最短距離とは関係なくなります。 構造を慎重に再利用せずに単に最短パスを再計算する単純なアプローチでは、速度が遅すぎるか、元のエッジ ルートと代替ルートを正しく区別できなくなります。 

同様に短いパスが複数存在する場合、別の失敗ケースが発生します。 そのうちの 1 つが削除されたエッジを使用し、もう 1 つが使用しない場合、直接のエッジが削除されても、答えは元の最短パスと同じままになるはずです。 エッジが削除されると最短パスが常に消えると仮定する解決策は、答えを誤って過大評価することになります。 

## アプローチ

 直接的な解決策は、各エッジを個別に処理することです。 各エッジ (u、v) について、グラフからエッジを削除し、u と v の間の最短パス アルゴリズムを実行します。頂点が 300 個までの場合、ダイクストラは実行ごとに高速ですが、エッジごとに 1 回実行すると M 回の実行が発生し、M が大きい場合はコストが高くなりすぎます。 

重要な観察は、実際にはすべてのエッジに対してグラフ全体を再計算する必要はないということです。 必要なのは、頂点のペアごとに、全長の観点から考えられる最良のルートと 2 番目に最適なルートだけです。 これら 2 つの値がわかったら、特定のエッジを削除することは、そのエッジが最適パスが存在する唯一の理由である場合にのみ問題になります。 

これにより、問題は「エッジごとの最短パスを再計算する」から「頂点のペアごとに 2 つの最適な距離を計算する」に変わります。 

フロイド-ウォーシャルを自然な方法で拡張します。 すべてのペア間の最短距離のみを保存するのではなく、2 つの最小の個別の距離、つまり最適なパス長と 2 番目に最適なパス長を保存します。 中間の頂点 k までリラックスしながら、i から k、k から j までのすべての最善の組み合わせと次善の組み合わせをすべて組み合わせてみて、最も小さい 2 つの結果のみを保持します。 

これが機能するのは、k を介して構築される i から j へのパスは、i から k へのパスと k から j へのパスで構成されるためです。 両方のサブセグメントに対して最適な 2 つのオプションを維持する場合、それらの組み合わせの中から全体的に最適なパスまたは 2 番目に最適なパスが出現する必要があります。 

これら 2 つの値がすべてのペアに対して計算されると、各エッジに答えるのは簡単になります。 u と v の間の最短パスがそのエッジに依存しない場合、それを削除しても何も変わらないため、最短の値が使用されます。 最短パスがまさに直接エッジである場合 (または、直接エッジが含まれている場合)、答えは 2 番目に最適な値になります。 2 番目に良いものさえ存在しない場合、答えは -1 になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジごとにダイクストラを再実行する | O(M・E log N) | O(N + E) | 遅すぎる |
 | フロイド・ウォーシャルのベスト2 | O(N3) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの行列を維持します。 dist1[i][j] は i と j の間の最短パス距離であり、dist2[i][j] は 2 番目に短い個別パス距離です。 

dist1 を直接エッジと他の場所で無限大で初期化し、dist2 をどこでも無限大で初期化します。 各エッジ (u、v、w) について、このエッジが既知の最良の値を改善する場合は dist1[u][v] と dist1[v][u] を更新し、古い最良の値が置き換えられた場合は 2 番目に良い値の候補として扱います。 

次に、すべての中間ノード k に対して修正された Floyd-Warshall を実行します。 

1. 各中間頂点 k について、頂点 i と j のすべてのペアを考慮します。 
2. i から k および k から j の 2 つの最適なオプションを組み合わせて、候補パス長を生成します。 これは、両方のセグメントの dist1 と dist2 をペアにして、最大 4 つの候補を生成することを意味します。 
3. 最小の 2 つの異なる値を維持しながら、これらの候補を既存の (dist1[i][j]、dist2[i][j]) ペアにマージします。 
4. これをすべての k に対して繰り返し、パスが徐々に多くの中間頂点を使用できるようにします。 

これが完了すると、dist1[i][j] がグローバル最短パスとなり、dist2[i][j] が最短パスより厳密に劣る最良の代替ルートになります。 

最後に、各エッジ (u、v、w) について、w を dist1[u][v] と比較します。 最短パスが正確にこの直接エッジではない場合は、そのエッジを削除しても最適なルートに影響を与えないため、dist1[u][v] を出力します。 それ以外の場合は、元の最適ルートが無効になるため、dist2[u][v] を出力します。 

### なぜ効果があるのか

 重要な不変条件は、k までのすべての中間頂点を処理した後、dist1 と dist2 が、{1, …, k} の中間頂点のみを使用して、任意のペア間の可能な 2 つの最小のパス長を正しく表すことです。 すべての候補パスは中間頂点で分割することによって形成され、すべての最適パスまたは 2 番目に最適なパスにはそのような分割が必要です。 2 つの最適なサブパスのすべての組み合わせを明示的に試行するため、有効な候補パスが見逃されることはありません。 2 つの最小の個別の値のみを保持すると、エッジ除去クエリに必要な情報が正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def add_candidate(a, b, c):
    # helper: returns sorted best two distinct values
    vals = []
    for x in (a, b, c):
        if x < INF:
            vals.append(x)
    vals.sort()
    best = INF
    second = INF
    for x in vals:
        if x < best:
            second = best
            best = x
        elif x > best and x < second:
            second = x
    return best, second

def merge_two(best_pair, candidates):
    best, second = best_pair
    vals = [best, second] + candidates
    vals = [x for x in vals if x < INF]
    vals.sort()
    new_best = INF
    new_second = INF
    for x in vals:
        if x < new_best:
            new_second = new_best
            new_best = x
        elif x > new_best and x < new_second:
            new_second = x
    return new_best, new_second

def main():
    n, m = map(int, input().split())
    dist1 = [[INF] * n for _ in range(n)]
    dist2 = [[INF] * n for _ in range(n)]

    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))

        # initialize best distances
        if w < dist1[u][v]:
            dist2[u][v] = dist1[u][v]
            dist1[u][v] = w
        elif w > dist1[u][v] and w < dist2[u][v]:
            dist2[u][v] = w

        if w < dist1[v][u]:
            dist2[v][u] = dist1[v][u]
            dist1[v][u] = w
        elif w > dist1[v][u] and w < dist2[v][u]:
            dist2[v][u] = w

    for i in range(n):
        dist1[i][i] = 0
        dist2[i][i] = INF

    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist1[i][k] == INF or dist1[k][j] == INF:
                    continue

                candidates = [
                    dist1[i][k] + dist1[k][j],
                    dist1[i][k] + dist2[k][j],
                    dist2[i][k] + dist1[k][j]
                ]

                best, second = dist1[i][j], dist2[i][j]
                vals = candidates + [best, second]
                vals = [x for x in vals if x < INF]
                vals.sort()

                nb = INF
                ns = INF
                for x in vals:
                    if x < nb:
                        ns = nb
                        nb = x
                    elif x > nb and x < ns:
                        ns = x

                dist1[i][j], dist2[i][j] = nb, ns

    out = []
    for u, v, w in edges:
        if dist1[u][v] != w:
            out.append(str(dist1[u][v]))
        else:
            out.append(str(dist2[u][v] if dist2[u][v] < INF else -1))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```コア実装は、1 つではなく 2 つの距離レイヤーを維持します。 初期化ステップでは、同じノードのペア間の最小の直接接続と 2 番目に小さい直接接続の両方を維持することにより、平行エッジが正しく考慮されます。 フロイド ステップは、すべての中間頂点が最短の組み合わせだけでなく、次善の組み合わせにも貢献できるように拡張されています。これは、「エッジを 1 つ削除する」要件を処理するために不可欠です。 

エッジごとの最終決定は意図的に単純化されています。 最短パスがエッジの重みと等しいかどうかのみをチェックします。その場合にのみ、直接エッジが少なくとも 1 つの最適解の一部であると確信できるからです。 それ以外の場合、元の最短パスは削除後も有効のままです。 

## 実用的な例

 ### サンプル 1

 私たちは少数の関連するペアのみを追跡します。 

| ステップ | 距離1[1][2] | 距離2[1][2] | 距離1[1][3] | 距離1[3][2] |
 | --- | --- | --- | --- | --- |
 | エッジの初期化 | 4 | インフ | 8 | 4 |
 | 経由 3 | 4 | 9 | 8 | 4 |

 パス 1 → 3 → 2 では 12 が生成され、1 → 4 → 3 → 2 では 9 が生成され、これが (1,2) にとって 2 番目に最適になります。 

エッジ (1,2) の場合、最短パスは 4 で直接エッジを使用するため、2 番目に良い値 9 を出力します。他のエッジの場合、直接エッジが唯一の最短パスではないため、元の最短距離が有効なままになります。 

これは、マルチホップの組み合わせを考慮した後でのみ代替ルートがどのように現れるかを示しています。 

### サンプル 2

 1 と 2 の間にはエッジが 1 つだけあります。 

| ステップ | 距離1[1][2] | 距離2[1][2] |
 | --- | --- | --- |
 | 初期化 | 1 | インフ |

 代替パスが存在しないため、dist2 は無限のままになります。 エッジが削除されると、頂点間にルートが存在しないため、出力は -1 になります。 

これにより、次善の構造が切り離されたケースを正しく捕捉していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、グラフの同じ頂点ペアの間に複数のエッジが含まれる場合です。 この状況では、別のエッジが最適なパスを保持している可能性があるため、1 つのエッジを削除しても最短接続が削除されるとは限りません。 最小の直接エッジと 2 番目に小さい直接エッジの両方を維持する初期化ステップにより、これが正しく処理されることが保証されます。 

もう 1 つのエッジ ケースは、エッジのみを削除するとエンドポイントが切断されるグラフです。 2 番目に短い距離は無限のままであり、-1 が生成されるため、これは自然に処理されます。 

最後の微妙なケースは、最短パスが直接のエッジそのものではないが、削除されたエッジと同じ端点を依然として持つ場合に発生します。 このアルゴリズムは、dist1 に対してのみ等価性をチェックするため、削除されたエッジに依存しない最短パスが正しく保存されます。
