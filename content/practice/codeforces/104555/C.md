 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするツリーが与えられます。各ノードには値があり、ルートからツリー内の固有の単純なパスに沿って任意のノード i まで歩きます。 歩いている間、オプションでいくつかの訪問ノードを「記録」することもできますが、記録されたシーケンスは厳密に増加する値を持つ必要があります。 すべての宛先ノード i について、1 から i までのパスに沿って可能な記録されたノードの最大数が必要です。 

したがって、ルート化されたツリー内の各プレフィックス パスについて、厳密に増加する最長部分列問題を解決しますが、その列はルートからノードへのパスに沿って配置されるように制約されます。 

制約が十分に大きいため、ノードごとに二次関数を適用することは不可能です。 最大 10^5 ノードの場合、ノードごとに LIS を個別に再計算するアプローチやフルパスを再計算するアプローチはすべて TLE になります。 ツリーに沿って計算を再利用する必要がありますが、さらに重要なことに、トラバース中に LIS 情報を段階的に維持できる構造が必要です。 

重要なエッジケースは、ツリーに沿って値が単調でない場合です。 パスに沿った素朴な貪欲な「最後に取得した値よりも大きい場合に取得」は失敗します。これは、大きな値を早期にスキップすると、後でより長いサブシーケンスが可能になる可能性があるためです。 もう 1 つの注意が必要なケースは、複数のブランチが後で高い値をマージする場合で、パスローカルの決定ではなくグローバル構造を維持する必要があります。 

## アプローチ

 ブルート フォース ソリューションは簡単です。各ノード i について、1 から i までのパスを取得し、値のシーケンスを抽出し、そのパス上で LIS を計算します。 これは定義に直接従っているため、正しいです。 ただし、LIS の各計算には O(長さ log length) のコストがかかり、すべてのノードにわたる合計作業量は、歪んだツリーでは O(n^2 log n) になり、これは n が 10^5 までの場合には遅すぎます。 

重要な点は、これが静的配列上の LIS だけではなく、ツリー内の動的ルートからノードへのパス上の LIS であるということです。 この構造は、DFS の実行中に LIS の「忍耐によるソート」表現を維持することを示唆しています。 親から子に移動するとき、子の値をグローバル順序構造に挿入することで LIS 構造を更新し、バックトラック時にそれを復元できます。 

重要な洞察は、tails[k] が長さ k の増加するサブシーケンスの可能な最小終了値であるベクトルを使用して LIS を維持できるということです。 この構造は、バイナリ検索を使用してノードごとに O(log n) で更新できます。また、ツリー上にあるため、ロールバックを伴う DFS を適用してブランチ全体で正確さを維持できます。 

したがって、ノードごとに LIS を再計算するのではなく、DFS パスに沿ってグローバル状態を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス LIS の再計算 | O(n^2 log n) | O(n) | 遅すぎる |
 | DFS + LIS テールメンテナンス | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、現在のルートからノードへのパスの LIS テールを表す構造を維持しながら、深さ優先トラバーサルを実行します。 

1. 配列 tails を維持します。tails[k] は、現在の DFS パスに沿った長さ k の増加するサブシーケンスの可能な最小の最後の値です。 この構造は、いつでも必要なすべての LIS 情報をエンコードします。 
2. 訪問する各ノードについて、二分探索を使用してその値が末尾のどこに収まるかを計算します。 これにより、このノードを含めることを選択した場合、このノードで終わる最長の増加サブシーケンスの長さが得られます。 
3. バックトラックするときにそれを復元できるように、更新する位置にテールの前の値を保存します。 ツリーの異なるブランチが互いに干渉してはならないため、これは不可欠です。 
4. ノードの挿入後に tails[k] が有効になるように、現在のノードの答えを最大長 k として更新します。 
5. 更新された末尾の状態を前方に運びながら、子に再帰します。 
6. すべての子を処理した後、親に戻る前に末尾を以前の状態に復元します。

微妙な点は、サブシーケンスを明示的に保存しているのではなく、その最適な代表だけを保存しているということです。 LIS は実際の要素ではなく最小の終了値のみに依存するため、この圧縮表現で十分です。 

### なぜ効果があるのか

 tails 配列は、現在のパスに沿って増加するすべてのサブシーケンスの正規表現です。 どの時点でも、tails[k] は長さ k のすべてのサブシーケンスの中で可能な最小の終了値であり、将来の拡張がこのフロンティアのみに依存することが保証されます。 DFS では、現在のルートからノードへのパスのみを拡張し、バックトラッキング時に状態を完全に復元することが保証されるため、各パスは共有計算を使用して個別に処理されたかのように正確に評価されます。 これにより、再計算をしなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    parent = list(map(int, input().split()))
    val = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for i, p in enumerate(parent, start=1):
        g[p - 1].append(i)

    tails = []
    ans = [0] * n

    from bisect import bisect_left

    def dfs(u):
        x = val[u]

        idx = bisect_left(tails, x)
        old = None
        replaced = False

        if idx == len(tails):
            tails.append(x)
            replaced = False
        else:
            old = tails[idx]
            tails[idx] = x
            replaced = True

        ans[u] = idx + 1

        for v in g[u]:
            dfs(v)

        if replaced:
            tails[idx] = old
        else:
            tails.pop()

    dfs(0)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```DFS は、現在のルートからノードへのパスに沿ってグローバル LIS 構造を維持します。 各ノードについて、二分探索を使用してその値を tails 配列に挿入し、そこで終わる LIS の長さを計算してから再帰します。 再帰の後、兄弟サブツリーが干渉しないように、以前の状態が復元されます。 

よくある間違いは、テールを適切に復元することを忘れることです。 ロールバックを行わないと、LIS 構造が他のブランチによって汚染され、不正確な結果が生成されます。 もう 1 つの微妙な問題は、bisect_left の代わりに bisect_right を使用することです。これにより、等しい値が増加するサブシーケンスを拡張することが誤って許可されてしまいます。 

## 実用的な例

 次のサンプルを考えてみましょう。```
5
1 1 3 3
5 7 7 6 8
```1 をルートとするツリーを構築します。 

ノード 1 では、尾 = [5]、答え = 1。 

ノード 2 に 7 を挿入し、尾 = [5, 7]、答え = 2 となります。 

ノード 3 では、値 7 が位置 1 の末尾を置き換えますが、長さは増加しないため、答え = 2 となります。 

ノード 4 では、値 6 が tails[1] を置き換え、将来の可能性が高くなりますが、それでも答え = 2 になります。 

ノード 5 では、値 8 は尾部を [5, 7, 8]、答え = 3 まで延長します。 

これは、グローバルな一貫性を維持しながら、LIS 構造がどのようにローカルに進化するかを示しています。 

ここで、歪んだケースを考えてみましょう。```
3
1 2
3 2 5
```ノード 1: [3] は 1 を返します

 ノード 2: [3,2] は [2] になりますが、答えは 1 のままです。 

ノード 3: [2,5] は長さ 2 を与えます

 これは、置換が重要である理由を示しています。2 は以前の増加パターンを破ったとしても、将来のサブシーケンスを改善します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードは 1 つの二分探索更新を実行します。 
| スペース | O(n) | 隣接リスト、テール、再帰スタック |

 各ノードが 1 回処理され、現在の LIS サイズでは各更新が対数であるため、このソリューションは n から 10^5 まで快適に拡張できます。
