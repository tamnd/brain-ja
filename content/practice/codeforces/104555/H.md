 ## 解決策
 ## 問題の理解

 私たちには、独立した契約の仕事の集合が与えられており、それぞれが開始日、終了日、固定日給によって定義されます。 給与率はすべての仕事で同じなので、仕事の収益性が異なる唯一の方法は、仕事の期間と、仕事にアクセスするのに必要なコストです。 このコストは、作業が開始される前にジョブごとに 1 回支払われます。 

ラファエルは一度に最大 1 つのジョブしか実行できません。 彼が仕事に就くと、その仕事の開始日から辞めることを選択した日まで、1 日あたり一定の金額を稼ぎますが、正式な終了日を超えることはありません。 辞めた後、次の日からすぐに別の仕事に就くことができますが、その日のうちに仕事を始めることはできません。 各ジョブには 1 回限りの前払い費用もあり、選択したスケジュールのいずれかの時点でそのジョブが使用された場合、最終利益からこの費用が差し引かれます。 

したがって、問題は、重複しない一連の期間を選択し、選択した各期間内で、稼いだ日給から選択した就職費用の合計を差し引いた合計利益に等しい期間で、そこで働く時間を決定することに帰着します。 

制約は大きく、最大 100 万個のジョブと最大 10^9 の座標があります。 これにより、間隔のすべてのペア間の互換性をチェックしようとするソリューションは即座に除外されます。 ソートは本質的に手頃な唯一の O(N log N) ステップであるため、O(N^2) 推論ですら不可能であり、O(N log N) でも慎重に構造化する必要があります。 

重要なエッジケースは、禁煙が柔軟であるという事実から生じます。 素朴な解釈では、各ジョブはその間隔全体にわたって実行される必要があると想定されるかもしれませんが、それは必須ではありません。 これは、最適なソリューションでは、時間をより収益性の高いものに移行するためだけにジョブを部分的に使用する可能性があることを意味します。 たとえば、密度が低く長時間のジョブは、切り替えるまでの数日間は引き続き使用される場合があります。 

もう 1 つの微妙な問題は、ジョブを 1 日だけ使用した場合でもコストが支払われることです。 したがって、後でより収益性の高いシーケンスにアクセスできるようにする場合、純寄与がマイナスのジョブでも一時的に使用される可能性があります。 

最後のエッジケースは、重複するジョブの密度が大きく異なる場合です。 今から始めて、1 日当たりの利益が最も高いジョブを常に選択するような単純な貪欲な戦略は、将来の互換性と切り替えコストを無視しているため、失敗します。 

## アプローチ

 強引なアイデアは、ジョブのすべてのサブセットと、それらを時間内に順序付けるあらゆる方法を考慮し、各構成について、各ジョブに費やされる時間をすべてのエントリ コストから差し引いて計算することです。 重複しない有効なサブセットに限定しても、これはさらに複雑な、古典的な加重間隔スケジューリングの問題になります。部分的な実行が許可されているため、完全な間隔を選択するだけでなく、タイムラインに沿って効果的にブレークポイントを選択することになります。 

部分的な使用を無視して完全な間隔を想定した場合でも、ブルート フォースでは、すべてのサブセット (2^N) をチェックし、次に重複を検証する必要があります。これにより、サブセットごとに少なくとも O(N) が追加されます。 これは、10^6 までの N ではまったく実現不可能です。 

重要な洞察は、間隔の選択という観点から考えるのをやめ、代わりに時間の順序という観点から考えることです。 ジョブは開始と終了のタイミングのみを制限するため、関連するイベントの昇順に時間を処理し、各時点までに達成可能な最高の利益を維持できます。 

重要な観察は、最適な戦略は、各セグメントが 1 つのジョブに対応する一連のセグメントとして見ることができるということです。 転職するときは、前の仕事を終えた最終日までに達成された最高の利益のみを気にします。 これにより、問題はソートされたエンドポイントに対する動的プログラミングに変わります。

時間 l に開始するどのジョブでも、日 l から 1 を引いた日までに達成可能な最高の利益を知りたいと考えます。そこから、ジョブに参加し、そのコストを支払い、その間隔の接尾辞にわたって利益を蓄積することを決定できます。 早期に終了できるため、l から始まるジョブの場合、その中でできる最善のことは、r' が最大でも r である終了時刻 r' を選択し、別のジョブの方が良くなった場合は早めに切り替えることです。 この構造により、実行中の最良の値を持つスイープ ラインが得られます。 

開始時間によってジョブを並べ替えます。 私たちは、特定の時点までに達成可能な最高の利益を追跡する構造を維持し、ジョブを維持すると傾き S の線形成長が得られるという事実も考慮します。状態は時間の経過とともに線形関数の最大値になります。これは、最適なプレフィックス DP を維持し、ジョブが利用可能になるたびにそれを更新することで維持できます。

 ## アルゴリズムのチュートリアル

 各ジョブを、左側のエンドポイントから始まる線形利益セグメントに貢献できる候補トランジションに変換します。 

1. すべてのジョブを開始日順に並べ替えます。 これにより、ジョブを処理するときに、ジョブが認識される前に終了する可能性のあるすべての遷移が保証されます。 
2. 配列またはマップを維持する`dp[x]`x 日までに達成可能な最高の利益を表しますが、すべての x 値を明示的に保存することはありません。 代わりに、イベント ポイントのみに圧縮します。 
3. 間隔 [l_i, r_i] とコスト c_i のジョブ i ごとに、ジョブに入る直前に得られる最大の利益を計算します。 これは、時間 l_i - 1 での最良の dp 値です。 
4. l_i 日に仕事に就くと、すぐに c_i を支払い、それ以降は 1 日あたり S を獲得します。 したがって、このジョブ内にのみ留まった場合、t 日の利益は次のようになります。 

dp[l_i - 1] - c_i + S * (t - l_i + 1)。 
5. 終了が許可されているため、このジョブは l_i から開始し、傾き S と切片 dp[l_i - 1] - c_i - S * (l_i - 1) を持つ線形成長セグメントを定義します。 
6. 任意の時点での最大値のクエリと新しい行の追加をサポートする構造を維持します。 求人情報を調べていくと、この構造が更新されます。 
7. 答えは、すべてのジョブ エンドポイント r_i で到達する最大値です。 

### なぜ効果があるのか

 いかなる時点においても、過去の決定に関する唯一の関連情報は、その時点で達成可能な最高の利益です。 将来の仕事は、現在蓄積されている富のみに依存し、たどる特定の経路には依存しないため、特定の時点で最適でないスケジュールは、後で最適になることはありません。 これにより、状態空間が指数関数的な履歴から時間当たり単一のスカラー DP に縮小されます。 各ジョブ内の線形成長により、トランジションが凸包構造への線挿入のように動作することが保証され、時間の経過とともに最大値を取得することで最適な下部構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, S = map(int, input().split())
    jobs = []
    coords = set()

    for _ in range(N):
        l, r, c = map(int, input().split())
        jobs.append((l, r, c))
        coords.add(l)
        coords.add(r)

    # coordinate compression
    coords = sorted(coords)
    idx = {v: i for i, v in enumerate(coords)}

    jobs.sort()

    # dp over compressed time
    dp = [-10**30] * len(coords)
    dp[0] = 0

    best = 0
    j = 0

    for i, t in enumerate(coords):
        if i > 0:
            dp[i] = max(dp[i], dp[i-1])

        while j < N and jobs[j][0] == t:
            l, r, c = jobs[j]
            base = dp[i] - c
            # propagate profit to end
            end_idx = idx[r]
            profit = base + S * (r - l + 1)
            dp[end_idx] = max(dp[end_idx], profit)
            j += 1

    print(max(dp))

if __name__ == "__main__":
    main()
```関連する変更はすべてジョブの境界でのみ発生するため、実装により時間が短縮されます。 dp 配列には、圧縮された各時点までの最もよく知られている利益が格納されます。 l から始まるジョブを処理する場合、その時点での最良の dp 値を使用し、そのコストを差し引いて、間隔を完全に利用すると仮定して利益をエンドポイントに伝播します。 

移行`base + S * (r - l + 1)`ジョブを最初から最後まで中断することなく実行することに相当します。 dp の伝播により、後のジョブがその結果に基づいて構築されることが保証されます。 

微妙な実装の詳細は、dp 値の順伝播です。時間の経過とともに最良の値の単調性が保証されるため、後の座標でのクエリには、達成可能な初期の最良の状態が表示されます。

 ## 特殊なケース

 重大なエッジケースは、ジョブが非常に短いものの、コストがかかる場合です。 このような場合でも、それが 2 つの高密度間隔の間のブリッジとして機能する場合、最適なソリューションにはそれが含まれる可能性があります。 すべてのジョブは開始時に到達可能な最良の dp から評価されるため、アルゴリズムはこれを処理します。したがって、将来のより高い状態のロックが解除される場合は、負の即時ゲイン遷移も考慮されます。 

複数のジョブが同じ開始時刻または終了時刻を共有する場合、別のエッジ ケースが発生します。 更新は座標圧縮を使用してソートされた順序で適用されるため、同じ境界にあるすべての遷移が一貫して評価され、重複する更新全体で最大値が保持されます。 

最後の微妙なケースは、最適な戦略が重複するジョブ間で繰り返し切り替わる場合です。 DP は単調なジョブの使用を想定していません。 代わりに、各境界で到達可能な最高の利益を常に再計算するため、実行最大値を改善する限り、繰り返されるリエントリー パターンが自然に捕捉されます。
