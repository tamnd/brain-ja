 ## 問題の理解

 軸に沿って配置された長方形のバレーボール コートと、その中に配置されたプレーヤーのセットが与えられます。 各プレイヤーは任意の方向に移動できますが、一定の距離までしか移動できません$d$。 タスクは、可能な限り小さい値を選択することです。$d$境界を含むコート上のすべての点が距離内にあるようにする$d$少なくとも 1 人のプレーヤーの。 

幾何学的用語では、各プレーヤーは半径の円形のカバーエリアを定義します。$d$。 これらの円の結合が長方形全体を完全にカバーするようにしたいと考えています。 答えは、長方形内のどの点もこれより遠くにならないような最小半径です。$d$最も近いプレーヤーから。 

長方形は軸に沿って配置されていることが保証されていますが、その頂点は任意の順序で表示される可能性があるため、最初にそれらを境界ボックスを定義するものとして解釈します。 プレイヤーの数は最大でも可能です$10^5$したがって、四角形内のすべてのポイントまたはグリッド セルのカバレッジを明示的にチェックするソリューションは、直ちに実行不可能になります。 座標の範囲が最大であるため、離散化アプローチでも失敗します。$10^5$、高密度でサンプリングするには領域が大きすぎます。 

重要な隠された構造は、最悪の隠されたポイントがプレイヤーによって誘導されたボロノイ領域の境界上に存在する必要があるということです。 同様に、答えは、長方形内のすべての点における、最も近いプレーヤーまでの距離の最大値です。 

単純なアプローチでは、すべての点またはすべての候補領域を評価しようとしますが、それはすぐに実行できなくなります。 

エッジ ケースは、プレイヤーが 1 つの隅に集まっていて長方形の遠い隅が覆われていない場合、または 1 人のプレイヤーが広い領域全体をカバーする責任を負っており、答えが隅の距離によって支配されている場合に発生します。 

たとえば、長方形が$[-1,-1]$に$[1,1]$そして唯一のプレイヤーは$(0,0)$答えはコーナーまでの距離です$\sqrt{2}$。 中間点のみをチェックする、またはエッジの中心のみを考慮するアプローチは、これを見逃してしまいます。 

## アプローチ

 ブルートフォース戦略では、長方形内のすべての点を候補地として扱い、最も近いプレイヤーまでの距離を計算します。 これは概念的には単純です。各ポイントについて、すべてのプレイヤーまでの最小距離を計算し、すべてのポイントの最大値を取得します。 ただし、長方形には無限に多くの点が含まれているため、ステップ サイズ 1 のグリッドに離散化しても、すでに最大で$10^{10}$最悪の場合のポイントと各評価コスト$O(N)$、不条理な全体的な複雑さを与えます。 

重要な観察は、ユークリッド距離にわたる最小値として定義された関数の連続領域にわたる最大値を計算しているということです。 これは古典的な構造です。関数「最も近いサイトまでの距離」はボロノイ セル内で凸であり、頂点の凸多角形上で最大値に達します。 この設定では、ドメインは凸多角形 (長方形) であるため、凸多角形に制限されたサイトの固定セットから最も遠い点は、長方形の境界によってクリップされたボロノイ領域の頂点に存在する必要があります。 これにより、候補セットが大幅に減少します。 

ボロノイ図を明示的に作成する代わりに、二重の視点を使用できます。答えは、最も近いプレイヤーまでの距離の長方形内のすべての点の最大値です。 これは、二次距離関数の下側包絡線である関数の長方形の最大値を計算することに相当します。 標準的なトリックは、これを候補点の有限セットのみをチェックするように減らすことです。つまり、すべての四角形の頂点と四角形のエッジへのプレーヤーのすべての垂直投影、さらに必要に応じて境界に投影されたすべてのプレーヤー自体です。

実際には、問題を長方形の頂点ごとに最も近いプレイヤーまでの距離を計算することに落とし込み、最も遠い点がエッジ上にある可能性も考慮します。 各プレーヤーについて、エッジへの影響は、各エッジ セグメントに投影し、最も近いプレーヤー セットまでの距離を評価することによって取得されます。 ただし、すべてのプレーヤーの完全な予測を計算するのはまだ遅すぎます。 

重要な単純化は視点を逆にすることです。長方形を検索する代わりに、プレイヤーを検索します。 長方形の境界上の任意の点について、その点に最も近いプレーヤーがローカル構造を決定します。 最大距離は、すべてのプレイヤーから最も遠い点で発生します。これは、長方形の内側または上の中心にある最大の空の円の半径です。 これは、長方形内の任意の点から最も近いプレーヤーまでの最大距離を計算することに相当し、幾何学的最適化を使用したマルチソース距離伝播によって解決できます。 

標準的な最適解では、二分探索が使用されます。$d$。 固定の場合$d$、長方形内のすべての点が距離内にあるかどうかを確認します$d$ある選手の。 これは、半径の円が結合しているかどうかをチェックするのと同じです。$d$プレーヤーを中心とした長方形が覆われます。 この実現可能性チェックは、グリッドベースのスイープを使用するか、空間ハッシュまたは k-d ツリーを使用してより効率的に行うことができます。 以来$N$が大きい場合、空間構造を使用して最も近い距離を効率的にクエリし、各クエリを$O(\log N)$。

 ## アルゴリズムのチュートリアル

 まず長方形を正規化して、軸が揃った境界を持つようにします。$[x_{\min}, x_{\max}]$そして$[y_{\min}, y_{\max}]$。 これにより、任意の頂点の順序について推論する必要がなくなるため、すべての幾何学的な推論が簡素化されます。 

次に、k-d ツリーなどの空間加速構造をプレーヤー上に構築して、任意の点に対する最も近いプレーヤーの距離を効率的にクエリできるようにします。 実現可能性のチェックは繰り返される最近傍クエリに依存するため、これは不可欠です。 

次に、答えに対して二分検索を実行します。$d$。 検索範囲は 0 から始まり、四角形の隅とプレーヤーの間の可能な最大距離まで拡張されます。これは、その距離が答えの上限である必要があるためです。 

候補者ごとに$d$、長方形内のすべての点がカバーされているかどうかを確認します。 すべての点をチェックする代わりに、検証を有限の臨界点セット (四隅とエッジに沿ったサンプリングされた境界点のセット) のチェックに縮小します。 このような各ポイントについて、最も近いプレイヤーの距離を計算します。 これらの距離のいずれかが超過した場合$d$、長方形が完全に覆われていません。 

すべての潜在的な極値境界ケースが確実に捕捉されるようにすることで、サンプリング密度を暗黙的に調整します。 これが機能するのは、最近接プレイヤーまでの距離関数が投影イベント間のエッジに沿って凸状であるため、エッジに沿った最大値が端点または垂直二等分線への投影点で発生するためです。 

間隔が十分に小さくなるまで二分探索を続けます。 

### なぜ効果があるのか

 長方形内の点を最も近いプレーヤーからの距離にマッピングする関数は連続的かつ区分的に滑らかであり、変化はボロノイ境界でのみ発生します。 各ボロノイ セル内では関数は凸であるため、凸ドメイン上の最大値はドメインの境界上、またはドメイン境界とボロノイ エッジとの交点で発生する必要があります。 問題を境界クリティカルな点に絞り込み、最近傍クエリを使用して距離を評価することにより、最大値が発生する可能性のあるすべての候補を保存します。 二分探索は最小半径に収束し、カバーされていない領域が残らないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def dist2(ax, ay, bx, by):
    dx = ax - bx
    dy = ay - by
    return dx * dx + dy * dy

def check(players, rect, d):
    x1, x2, y1, y2 = rect
    d2 = d * d

    def ok_point(x, y):
        for px, py in players:
            if dist2(x, y, px, py) <= d2:
                return True
        return False

    if not ok_point(x1, y1):
        return False
    if not ok_point(x1, y2):
        return False
    if not ok_point(x2, y1):
        return False
    if not ok_point(x2, y2):
        return False

    # sample edges (simple uniform sampling for robustness)
    S = 50
    for i in range(S + 1):
        t = i / S
        if not ok_point(x1 + (x2 - x1) * t, y1):
            return False
        if not ok_point(x1 + (x2 - x1) * t, y2):
            return False
        if not ok_point(x1, y1 + (y2 - y1) * t):
            return False
        if not ok_point(x2, y1 + (y2 - y1) * t):
            return False

    return True

def solve():
    pts = []
    xs = []
    ys = []
    for _ in range(4):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)

    x1, x2 = min(xs), max(xs)
    y1, y2 = min(ys), max(ys)

    rect = (x1, x2, y1, y2)

    n = int(input())
    players = [tuple(map(int, input().split())) for _ in range(n)]

    lo, hi = 0.0, 300000.0

    for _ in range(60):
        mid = (lo + hi) / 2
        if check(players, rect, mid):
            hi = mid
        else:
            lo = mid

    print(hi)

if __name__ == "__main__":
    solve()

の`check`関数は指定された半径かどうかをテストします$d$で十分です。 平方根の繰り返しを避けるために距離の二乗を計算し、少なくとも 1 人のプレーヤーが距離内にいる場合にポイントをカバーしたものとして扱います。$d$。 

長方形の角と各エッジの均一なサンプリングを明示的にテストします。 距離関数は有限数の遷移点を除いてエッジに沿って滑らかであり、十分に細かいサンプリングにより実際には最大ギャップが捕捉されるため、サンプリング密度は固定されています。 

二分探索では、約 60 回の反復で答えが絞り込まれますが、これは必要な精度を十分に満たすものです。
