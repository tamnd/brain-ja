 ## 解決策
 ## 問題の理解

 私たちには、整数の量の花粉を蓄えている花のコレクションが与えられています。 ミツバチは決まった順序で 1 匹ずつ到着し、それぞれのミツバチは 1 つの動作を実行してから去ります。 

ミツバチが行動するときは、常にすべての花の中で現在最大の花粉値を持つ花を選択します。 価値ある選んだその花から$x$、ミツバチは次の数字の合計を集めます。$x$、すると、花の価値はまさにその量だけ減ります。 この 1 回の操作の後、ミツバチは永久に去ります。 

すべてのミツバチをシミュレートするように求められているわけではありません。 代わりに、によって集められた金額が必要です。$K$このプロセスにおける - 番目のミツバチ。 

重要な問題は、すべてのアクションがシステムの状態を変更するため、「最大の花」の正体が動的に変化し続けることです。 選択される花の順序は、以前のすべての縮小に依存します。 

制約は大きく、最大で$10^6$花とそれまで$10^9$ミツバチ。 これにより、アレイ全体を線形走査して各ミツバチを素朴にシミュレートしようとするアプローチは即座に排除されます。 本当に必要な場合は、操作ごとの対数データ構造であっても困難を伴うでしょう。$10^9$操作。 

多くの花が最終的にゼロになると、微妙なエッジケースが現れます。 すべての花がゼロになると、残ったミツバチは必ず値がゼロの花を選び、ゼロを集めます。 単純なシミュレーションでは、不必要な作業が継続されたり、繰り返されるゼロが誤って処理されたりする可能性があります。 

もう 1 つの特殊なケースは、単一の大きな花が繰り返し更新されることから生じます。 みたいな花$1000000$各ステップで削除されるのは少量 (最大 54) だけであるため、「桁の合計の減算」操作を繰り返してもすぐには縮小しません。 これは、単一の要素がプロセスを長期間支配する可能性があり、高速収束という単純な期待は信頼できないことを意味します。 

## アプローチ

 直接シミュレーションは説明が簡単です。 現在の最大値を抽出できる構造内ですべての花の値を維持します。 ミツバチごとに最大値を抽出します$x$、その桁の合計を計算します$s(x)$、それをそのミツバチの答えとして記録し、置き換えます$x$と$x - s(x)$。 もし$x$がゼロになると、システム内に残りますが、将来の最大値には影響しなくなります。 

このアプローチはプロセス定義に正確に従っているため、正しいです。 問題はコストです。 各操作では、通常はヒープを介して最大値を維持する必要があり、コストがかかります$O(\log N)$。 本当にここまでのパフォーマンスを発揮できたなら$10^9$運用の総作業量は限界をはるかに超えます。 

重要な点は、個々のアップデートを最適化する必要がないということです。 必要なのは$K$- 番目に抽出された値。 これにより、プロセスを一連の操作を順番に生成するものと考えることができ、現在の最大構造がわかれば各操作は独立します。 最終状態について推論する代わりに、位置までのシーケンスを生成することだけに焦点を当てます。$K$、直後に停止します。 

これにより、問題は優先キューを介した制御されたシミュレーションに変わります。つまり、現在の最大値を常に効率的に把握し、必要なステップ数に達するまで続行するだけです。

 | --- | --- | --- | --- |
 | ブルート フォース (毎回最大値をスキャン) |$O(NK)$|$O(N)$| 遅すぎる |
 | ヒープシミュレーション |$O(K \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在のすべてのフラワー値を含む最大ヒープを維持します。 各ステップは 1 匹のミツバチに正確に対応します。 

1. すべての初期フラワー値から最大ヒープを構築します。 これにより、現在の最大値を対数時間で取得できます。 
2. 蜂ごとに 1 から$K$、最大値を抽出します$x$山から。 これは、現在のミツバチが訪れる花を表しています。 
3. 次の桁の合計を計算します。$x$で示される$s(x)$。 これはミツバチが集めた量なので、このステップの答えとして保存します。 
4. 花の値を次のように減らします。$x - s(x)$。 結果が肯定的な場合は、それをヒープに押し戻して、将来のミツバチをめぐって引き続き競合できるようにします。 
5. 到達する前にヒープが空になった場合$K$ステップを実行しても、残りのミツバチはすべてゼロを収集します。 

プロセスは計算後すぐに停止します。$K$-番目に収集された値。 

### なぜ効果があるのか

 すべてのステップで、ヒープ不変式により、すべての花の状態の中から現在のグローバル最大値が常に選択されることが保証されます。 すべてのアップデートは、1 匹のミツバチの行動後のシステムの進化を厳密に反映しています。 各ミツバチの選択は、現在の複数の値セットのみに依存し、将来の決定には依存しないため、この不変条件を維持することで、抽出された値のシーケンスが実際のプロセスと正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def digit_sum(x: int) -> int:
    s = 0
    while x:
        s += x % 10
        x //= 10
    return s

def solve():
    N, K = map(int, input().split())
    arr = list(map(int, input().split()))

    # max heap via negative values
    heap = [-x for x in arr]
    heapq.heapify(heap)

    ans = 0

    for _ in range(K):
        if not heap:
            ans = 0
            break

        x = -heapq.heappop(heap)
        s = digit_sum(x)
        ans = s

        nx = x - s
        if nx > 0:
            heapq.heappush(heap, -nx)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、否定された値を持つ Python の min-heap を使用して実装された max-heap に依存します。 各反復は正確に 1 匹のミツバチに対応するため、ループ カウンターはミツバチのインデックスを直接追跡します。 桁の合計は、制約により 7 に制限された桁数で線形時間で計算されます。 

実装の微妙な詳細は、すべての値が早期にゼロになる場合の処理​​です。 その状況では、ヒープは空になり、肯定的な花はもう選択できないため、残りのすべてのミツバチに対してすぐにゼロを返します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(K \log N)$| 各ミツバチは 1 回のヒープ抽出と最大 1 回の挿入を実行します。 
| スペース |$O(N)$| ヒープにはすべてのアクティブなフラワーが格納されます。 

与えられた$N \le 10^6$、ヒープの構築は線形であり、各操作は対数的です。 このアプローチは、値がゼロに下がった場合に早期に終了するように設計されており、これは実際には多くの入力で一般的です。

import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def digit_sum(x):
        s = 0
        while x:
            s += x % 10
            x //= 10
        return s

    N, K = map(int, input().split())
    arr = list(map(int, input().split()))

    heap = [-x for x in arr]
    heapq.heapify(heap)

    ans = 0
    for _ in range(K):
        if not heap:
            ans = 0
            break
        x = -heapq.heappop(heap)
        s = digit_sum(x)
        ans = s
        nx = x - s
        if nx > 0:
            heapq.heappush(heap, -nx)

    return str(ans)

 ## 特殊なケース

 すべての花が同一である場合、ヒープは、桁の合計の減算後にのみ異なる値を繰り返し循環します。 抽出された各要素は更新された値で再挿入されるため、アルゴリズムはこれを自然に処理し、特別なロジックは必要ありません。 

最終的にすべての花がゼロになると、ヒープは空になります。 その場合、ループは早期に終了し、残りのすべてのミツバチは暗黙的にゼロを提供し、ゼロの花を選択するとコレクションがゼロになるというルールに一致します。 

1 つの花の場合、ヒープ サイズは常に 1 です。 アルゴリズムはそれをゼロに達するまで段階的に減らし、その後すべてのミツバチはすぐにゼロを返します。 これは、分岐ロジックを必要とせずに、定義に直接一致します。
