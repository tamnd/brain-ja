 ## 問題の理解

 次の長さの完全なパスワードを再構築するように求められます。$k$小文字の英字の上に。 パスワードは任意ではありません。辞書順で減少しない必要があります。つまり、各文字がアルファベット順で少なくとも前の文字と同じ大きさであることを意味します。 

記憶されたサブシーケンスも与えられます$s$、最終的なパスワードに順番に出現する必要がありますが、必ずしも連続している必要はありません。 言い換えれば、埋め込む必要があります$s$長さに合わせて$k$減少しない文字列。 

もう 1 つグローバル制約があります。それは各文字です。$a \ldots z$最終的なパスワードに出現する回数には上限があります。 これらの制限は、サブシーケンスだけでなく、構築された文字列全体に適用されます。 

タスクは、すべての制約を満たし、次の内容を含む有効な完全な文字列がいくつ存在するかを数えることです。$s$サブシーケンスとして、またはレポートは不可能です。 

重要な点は、グローバルな容量制限と強制的なサブシーケンス位置を持つ単調文字列をカウントしていることです。 

制約$n, k \le 10^3$そして 26 文字は、位置や文字よりも動的プログラミング ソリューションを強く示唆しています。 すべての非減少文字列に対するブルート フォースは、サブシーケンスとキャップを強制する前であっても、すでに天文学的な規模になります。 

素朴に対処すると、いくつかの失敗例がすぐに現れます。 

まず、部分列自体が非減少順序に違反している場合、カウントを考慮する前に、解は存在しません。 たとえば、次の場合$s = "ba"$、非減少文字列には決して出現できません。 

第二に、欲張って配置しようとすると、$s$次に、遷移を追跡せずに文字ごとに独立して残りのスロットを埋めます。フィラー文字の配置は最後に使用された文字によって制限されるため、オーバーカウントします。 

第三に、文字制限が構築中ではなく最後にグローバルにのみチェックされる場合、DP 状態が爆発するか、無効なパスがカウントされます。 

## アプローチ

 ブルート フォース ビューでは、長さが減少しないすべての文字列を生成します。$k$そして、それが含まれているかどうかを確認します$s$サブシーケンスとして、周波数制限を尊重します。 長さが減少しない文字列の数$k$26文字以上は$\binom{k+25}{25}$、すでにそこら中にある$10^{25}$スケール$k=1000$, したがって列挙は不可能です。 構造が依然として指数関数的であるため、部分シーケンス一致による枝刈りでも意味のある効果はありません。 

重要な観察は、非減少文字列は、各文字が出現する回数によって完全に記述されるということです。これは、カウントが固定されると、順序付けが強制されるためです (すべて a 、次にすべて b というように)。 これにより、問題は分散に変わります。$k$上限を持つ 26 個のバケット間での位置を決定し、同時にサブシーケンスが$s$順序を尊重して埋め込むことができます。 

ただし、サブシーケンスの埋め込みにより、この固定されたグローバル順序付けの内部に位置制約が導入されます。 重要なアイデアはマッチングをシミュレートすることです$s$文字のマルチセットを昇順に構築しながら、何文字かを追跡します$s$文字を「割り当てる」ときに、すでに一致しています。 

これにより、DP の文字数と文字数が決まります。$s$残りのポジションの境界付きナップサックスタイルの割り当てと組み合わせて、これまでのところ一致しています。 

この構造では、「a」から「z」までの文字が処理されます。 各文字で、その制限と残りの容量を考慮して、最終文字列でそれを何回使用するかを決定します。 そうすることで、次の文字数を更新します。$s$この同一の文字のブロックは、シーケンス順に消費できます。 

これは、カウント用の境界付きナップザックとオートマトン スタイルのサブシーケンス マッチングという 2 つの古典的なアイデアを結合します。

 ## アルゴリズムのチュートリアル

 処理された文字に対する DP 状態と、一致したサブシーケンスの文字数を定義します。 

させて$dp[i][j]$最初の処理後のウェイの数を表します$i$文字 (「a」から$i$-番目の文字)、一致した$j$の登場人物$s$、残りの容量を通じて暗黙的に全長の制約を尊重します。 

全長が固定されているため、$k$、各段階で残りのスロットを残りの文字に効果的に分配していますが、DP は正確な割り当てを強制します。 

また、単一文字のブロックの消費が部分列のマッチングにどのような影響を与えるかを記述する遷移関数も事前計算します。 

### 1. サブシーケンスの実現可能性を早期に検証する

 まず次のことを確認します。$s$減っていない。 そうでない場合は、解決策が存在しないことがすぐにわかります。 

これが必要なのは、有効な最終文字列が非減少であるため、すべてのサブシーケンスも非減少でなければならないためです。 

### 2. 文字の上にサブシーケンス オートマトンを構築する

 マッチングを扱います$s$正しい次の文字を配置するたびに進むポインターとして。 

現在の位置にいる場合$j$で$s$、文字を追加します$c$、次に進みます$j$もし$s[j] = c$。 

これにより、最終的な文字列を構築しながらサブシーケンスの進行状況を更新できるようになります。 

### 3. 文字と一致するプレフィックス上の DP

 「a」から「z」までの文字を処理します。 ステップで$i$を割り当てるためのあらゆる方法を検討します。$x$手紙の出現$i$、 どこ$0 \le x \le a_i$、合計残り容量がそれを許可します。 

考えられる現在の DP 状態ごとに$dp[i][j]$を追加してみます$x$手紙のコピー$i$、何文字かをシミュレートします。$s$このブロック中に一致します。 

なぜなら、これらすべてが$x$文字は同一であり、マッチングは決定論的に動作します。繰り返しマッチングを試みます。$s[j]$この書簡に反対し、可能な限り前進してください。 

### 4. 容量制約の適用

 すべての文字に配置される文字の合計数が次になるようにします。$k$。 残りの容量を超える遷移は破棄されます。 

### 5. 最終的な回答の抽出

 26 文字すべてを処理した後、正確に次の状態がどのような状態であるかを調べます。$k$文字が使用されており、すべての後続の制約が満たされています。 すべての有効な最終サブシーケンス位置の合計が答えになります。 

### なぜ効果があるのか

 不変条件は、最初の処理後の$i$文字、すべての DP 状態は文字のみを使用した部分構造に正確に対応します$a \ldots i$、構成による単調性を尊重します。 文字はソートされた順序で処理されるため、今後、非降順順序に違反する可能性はありません。 

DP は文字が追加される順序で照合を明示的にシミュレートするため、後続の正確性が維持されます。 サブシーケンスの進行状況や文字の使用法が異なる 2 つの構造をマージする状態は存在しないため、カウントは正確なままになります。 

文字ごとに制限された選択肢により、すべての有効な文字の分布が 1 回だけ考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    limits = list(map(int, input().split()))
    s = input().strip()

    # check subsequence validity in non-decreasing sense
    for i in range(len(s) - 1):
        if s[i] > s[i + 1]:
            print("NO SOLUTION!")
            return

    # dp[pos in s][used length]
    dp = [[0] * (k + 1) for _ in range(len(s) + 1)]
    dp[0][0] = 1

    for c in range(26):
        ndp = [[0] * (k + 1) for _ in range(len(s) + 1)]
        lim = limits[c]

        for j in range(len(s) + 1):
            for used in range(k + 1):
                if dp[j][used] == 0:
                    continue

                cur = dp[j][used]

                # try using x copies of this letter
                # but we can compress by iterating x
                for x in range(lim + 1):
                    if used + x > k:
                        break

                    nj = j
                    for _ in range(x):
                        if nj < len(s) and s[nj] == chr(ord('a') + c):
                            nj += 1

                    ndp[nj][used + x] = (ndp[nj][used + x] + cur) % MOD

        dp = ndp

    ans = 0
    for j in range(len(s) + 1):
        ans = (ans + dp[j][k]) % MOD

    if ans == 0:
        print("NO SOLUTION!")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、一致したサブシーケンスの文字数と、これまでに配置された合計文字数の両方を追跡します。 文字に対する外側のループにより、以前の文字を再度参照することがないため、自動的に単調性が保証されます。 各文字の可能なカウントに対する内部ループにより、頻度制限が適用されます。 

トランジションは、同一の文字のブロックを追加することでサブシーケンス ポインターがどのように進むか、または進まないかをシミュレートします。 文字は昇順に処理されるため、部分シーケンスの一致は常に一貫しています。 

最終的な集計では、正確に使用された状態のみが受け入れられます。$k$文字。
