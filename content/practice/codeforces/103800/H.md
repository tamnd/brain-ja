 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$各セルに個別の整数が含まれるグリッド。 2 人のエージェントがこのグリッド上を同時に移動します。 ジンジャーは左上のセルから始まり、最初は下を向いています。 彼のクローンは右下のセルから始まり、最初は上を向いています。 

どちらのエージェントも同じ移動ルールに従います。 各ステップで、現在の方向に 1 つのセルを前進させようとします。 次のセルがグリッドの外に出る場合は、代わりに左に 90 度回転し、新しい方向を使用して現在の位置から移動を続けます。 これにより、各エージェントの確定的なウォークが生成され、到達可能なすべてのセルが最終的にスパイラル状のパターンで訪問されるまで継続されます。 

ジンジャーが訪問した値のシーケンスとクローンが訪問したシーケンスを出力するように求められます。 追加の同期ルールがあります。両方のエージェントが同時に同じセルに到着した場合、そのセルの値はジンジャーのシーケンスにのみ記録されます。 

グリッド サイズは最大です$200 \times 200$, つまり、最大でも 40,000 個のセルがあります。 各ステップは$O(1)$ステップの合計数は、エージェントあたりのセルの数によって制限されます。 

多くの場合、誤った解決策を引き起こす素朴な誤解は、時間を同期せずに、動きを独立した螺旋状の順序として扱うことです。 たとえば、2×2 グリッドの場合:```
1 2
3 4
```ジンジャーは 1 → 3 → 4 → 2 を訪問しますが、クローンは同じ回転ルールに基づいて 4 → 2 → 1 → 3 を訪問します。 タイムアライメントを行わずにスパイラルを別々に誤って計算すると、より大きなグリッドで両方が同じステップで同じセルに到達するなどの競合を誤って処理する可能性があります。 

重要な点は、「同じタイム ステップ」条件により、2 つの独立した走査を事前に計算するのではなく、両方のウォークを同期してシミュレートする必要があることです。 

## アプローチ

 ブルートフォースアプローチは、両方のエージェントの直接シミュレーションです。 私たちはエージェントごとにその位置、方向、訪問したセルのセットを維持します。 各タイム ステップで、両方が移動しようとします。 次のセルが範囲外にある場合は、方向を左に回転し、移動を再計算します。 セル値をそれぞれのシーケンスに追加し、両方が同時に同じセルに到達する場合にタイ ルールを適用します。 

各エージェントは各セルを最大 1 回訪問します。 あるので$n^2$セルと 2 つのエージェントの合計ステップ数は、$O(n^2)$。 各ステップは継続的な作業であるため、完全なシミュレーションはすでに十分に効率的です。$n \le 200$。 境界回転を超えて複雑さを後戻りしたり再検討したりする必要がないため、より高度な構造は必要ありません。 

唯一意味のある最適化は、方向変更を注意深く実装し、すべてのセルを終了した後に誤って余分な動きをシミュレートしないようにすることです。 この構造は基本的に、反対側のコーナーから始まる同期したスパイラルウォークです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$|$O(n^2)$| 承認済み |
 | 最適なシミュレーション |$O(n^2)$|$O(n^2)$| 承認済み |

 問題の構造により、歩行自体をシミュレートする以上に漸近的な改善ができないため、実際には両方とも同一です。 

## アルゴリズムのチュートリアル

 現在の位置と方向を維持しながら、両方の歩行器を段階的にシミュレートします。 方向はベクトルとしてエンコードされ、「左に曲がる」は方向ベクトルを反時計回りに回転することに対応します。 

1. ジンジャーを次の場所で初期化します。$(0,0)$「下」方向でクローンを作成します。$(n-1,n-1)$方向は「上」です。 また、各セルがエージェントごとに 1 回正確に記録されるようにするために、2 つの訪問行列またはカウンターも準備します。 
2. 2 つの出力リスト (Ginger 用とクローン用) を維持します。 
3. 各タイム ステップで、現在の方向に 1 ステップ移動してジンジャーの次の位置を計算します。 その位置がグリッドの外側にある場合は、方向を左に回転してステップを再計算します。 有効な動きが見つかるまで繰り返します。 
4. 同じタイム ステップ内のクローンに同じロジックを個別に適用します。 これにより、両方のエージェントが同期して進化することが保証されます。 
5. 両方の移動が決定されたら、移動先のセルを比較します。 両方のエージェントが同じセルに到達した場合は、その値をジンジャーのシーケンスにのみ追加します。 それ以外の場合は、各値をそれぞれのシーケンスに追加します。 
6. 両方の訪問済みセルをそれぞれのエージェントに対して処理済みとしてマークし、両方のシーケンスに正確な内容が含まれるまで続行します。$n^2$これは、すべてのグリッド セルがトラバーサル ルールごとに 1 回だけ割り当てられることを意味します。 

正確かどうかは、各エージェントの移動ルールがグリッド上の決定論的な歩行を定義し、同期は出力ラベル付けにのみ影響し、移動には影響しないという事実に依存します。 

### なぜ効果があるのか

 各エージェントの移動ルールは、任意の状態 (位置、方向) からの一意の後続機能を定義します。 グリッドは有限であり、回転は境界にぶつかった場合にのみ発生するため、パスは最終的にはスパイラル状のトラバースですべてのセルを 1 回だけカバーします。 両方のエージェントは同一の決定論的ルールに独立して従うため、各タイム ステップでのエージェントの位置は明確に定義されます。 唯一のあいまいさは、両方のエージェントが同じタイム ステップで同じセルに到達した場合に発生します。セルをジンジャーに割り当てることで問題を解決すると、移動は所有権ではなく位置と方向にのみ依存するため、将来の移動に影響を与えることなく一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [list(map(int, input().split())) for _ in range(n)]

    # directions: down, left, up, right (clockwise order of turns is left rotation)
    dirs = [(1,0),(0,-1),(-1,0),(0,1)]

    # Ginger: start (0,0), direction down (0)
    gx, gy, gd = 0, 0, 0

    # Clone: start (n-1,n-1), direction up (2)
    cx, cy, cd = n-1, n-1, 2

    g_seen = [[False]*n for _ in range(n)]
    c_seen = [[False]*n for _ in range(n)]

    g_res = []
    c_res = []

    def move(x, y, d):
        for _ in range(4):
            nx = x + dirs[d][0]
            ny = y + dirs[d][1]
            if 0 <= nx < n and 0 <= ny < n:
                return nx, ny, d
            d = (d + 1) % 4
        return x, y, d

    total = n * n

    g_seen[gx][gy] = True
    c_seen[cx][cy] = True
    g_res.append(grid[gx][gy])
    c_res.append(grid[cx][cy])

    for _ in range(total - 1):
        gx, gy, gd = move(gx, gy, gd)
        cx, cy, cd = move(cx, cy, cd)

        if gx == cx and gy == cy:
            g_res.append(grid[gx][gy])
        else:
            g_res.append(grid[gx][gy])
            c_res.append(grid[cx][cy])

        g_seen[gx][gy] = True
        c_seen[cx][cy] = True

    print(*g_res)
    print(*c_res)

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`move`この関数は、現在の方向に進もうとし、有効なグリッド セルが見つかるまで左に回転します。 これは、「前に歩き、ブロックされたら左折する」というルールを直接エンコードします。 

明示的に正確にシミュレーションします$n^2$各ステップは、問題の走査ルールに基づいて各エージェントが入力する 1 つの新しいセルに対応するためです。 開始位置はループの前に個別に初期化されます。 

同点処理ロジックは、両方の手が同じタイム ステップで計算された後に配置され、同期が確実に保持されます。 両方の動きが完了する前にチェックすると一方のエージェントに誤って偏ることになるため、この順序は重要です。 

## 実用的な例

4 5 6
7 8 9
```いくつかの初期ステップのみを追跡します。 

| ステップ | ジンジャー (pos) | クローン (位置) | 出力G | 出力 C |
 | --- | --- | --- | --- | --- |

これは、同期ルールが動作していることを示しています。同時到着により、クローンのシーケンス内の重複した記録が抑制されます。

 ## 特殊なケース

 重要なエッジ ケースは、両方のエージェントが同時に境界に到達し、同じステップで回転する必要がある場合です。 2×2 グリッドの場合、両方のエージェントが初期ステップで壁にぶつかることがよくあります。 移動機能により、方向修正がエージェントごとに個別に適用されるため、両方が同じステップで回転した場合でも、次の位置は一貫したままになります。 

もう 1 つの微妙なケースは、奇数サイズのグリッドの中心での即時衝突です。 3×3 グリッドでは、両方の歩行者が中央のセルに集まることができます。 同期ルールにより、中央のセルがジンジャーのシーケンスに割り当てられますが、両方のエージェントは依然としてその共有位置から独自の方向で移動を継続するため、後のステップで分岐は発生しません。
