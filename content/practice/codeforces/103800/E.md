 ## 解決策
 ## 問題の理解

 1 から n までの数字の順列が与えられます。 これは、すべてのノードが正確に 1 つの他のノードを指す有向グラフと考えることができます。また、これは順列であるため、すべてのノードにも正確に 1 つの入力エッジがあります。 この構造は、互いに素な有向サイクルに分割されます。 

1 から n までの各数字は、黒または白のいずれかで色付けする必要があります。 この制限は、すべての位置 i を値 p[i] に結び付けます。つまり、i の色は p[i] の色と異なっていなければなりません。 言い換えれば、すべての有向エッジ i → p[i] は、両方の端点が同じ色を共有することを禁止します。 

タスクは、この制約 (モジュロ 998244353) の下で有効なカラーリングがいくつ存在するかをカウントすることです。 

n ≤ 100000 という制約により、n の指数関数的な値は排除されます。 2^100000 は実行可能な計算をはるかに超えているため、すべての 2^n 色を試す単純なアプローチは直ちに不可能です。 強力な枝刈りを行わずにノードごとに分岐する方法であっても失敗します。 順列の構造は、線形時間でのサイクル分解を利用する必要があることを示唆しています。 

ノードがそれ自体を指す場合、微妙なエッジ ケースが発生します。 p[i] = i の場合、条件により color(i) ≠ color(i) が強制されますが、これは不可能です。 したがって、固定点はすぐに答えをゼロにします。 より一般的には、奇数のサイクルは不可能であることが判明します。 

たとえば、n = 1 および p = [1] の場合、唯一のノードがそれ自体と異なる必要がありますが、それは不可能であるため、答えは 0 になります。 

n = 2 および p = [2, 1] の場合、長さ 2 の単一サイクルが得られ、これは有効であり、2 つの色付けが得られます。 

n = 3 および p = [2, 3, 1] の場合、サイクルの長さは 3 となり、最初に戻ると一貫性が失われ、答えは 0 になります。 

## アプローチ

 強引なアイデアは、n 個の要素のそれぞれに黒または白を割り当ててから、すべての制約をチェックすることです。 これは 2^n の割り当てを列挙し、各チェックですべての位置をスキャンして color[i] が color[p[i]] と異なることを確認します。 コストは O(n · 2^n) ですが、すでに 10 億回の操作を超えるため、n = 30 の場合でもあまりにも大きすぎます。 

重要な観察は、順列の構造から得られます。つまり、すべての要素が正確に 1 つのサイクルに属します。 サイクル v1 → v2 → ... → vk → v1 内では、この制約により、このサイクル内の隣接する要素の色が交互になることが強制されます。 これにより、各サイクルがパリティの一貫性の問題に変わります。 

v1 に色を割り当てようとすると、サイクルの残りの部分が強制的に実行されます。つまり、v2 は v1 と異なっていなければならず、v3 は v2 とは異なっていなければなりません。 vk に戻るときは、それが v1 と異なることも確認する必要があります。 これは、ステップ数が偶数のときに交互が正確に開始色に戻るため、サイクル長が偶数の場合にのみ機能します。 奇数サイクルの場合、矛盾が生じます。 

偶数長のサイクルごとに、有効な割り当てが 2 つあります。開始ノードを黒または白として選択でき、残りは強制されます。 異なるサイクルは独立しているため、奇数サイクルがまったくない場合、着色の総数は 2 の偶数サイクル数です。

 ## アルゴリズムのチュートリアル

 順列をサイクルに分解し、各サイクルを個別に分析することで問題を解決します。 

### ステップ

 1. すべてのノードを未訪問としてマークし、サイクルのカウンターと、回答がすでに無効であるかどうかを示すフラグを準備します。 
2. 各ノード i を 1 から n まで繰り返します。 i がすでに訪問されている場合は、以前に検出されたサイクルに属しているため、スキップします。 
3. i が未訪問の場合、訪問済みノードに戻るまで、順列エッジ i → p[i] に沿って繰り返し歩き始めます。 このウォーク中に訪問したすべてのノードをマークし、このサイクルに含まれるノードの数を数えます。

これが機能する理由は、順列により各ノードが正確に 1 つのサイクルに属することが保証され、この走査で 1 つの連結成分が正確に回復されるためです。 
4. サイクルを抽出したら、その長さを確認します。 長さが奇数の場合は、ただちに答えをゼロとしてマークし、他のサイクルについてのさらなる推論を停止します。これは、単一の矛盾が色付け全体を無効にするためです。 
5. サイクル長が偶数の場合、有効なサイクル数をインクリメントします。 
6. すべてのノードを処理した後、最終的な答えを 2^(偶数サイクル数) モジュロ 998244353 として計算します。 

### なぜ効果があるのか

 各サイクル内では、制約 c[i] ≠ c[p[i]] により、サイクルのエッジに沿って色の厳密な交互が強制されます。 これは、単一のノードの色が選択されると、サイクル内の他のすべてのノードが一意に決定されることを意味します。 開始ノードに戻ると、サイクル長のパリティのみに依存する一貫性要件が課せられます。 偶数サイクルでは一貫性が維持されますが、奇数サイクルでは矛盾します。 サイクルは互いに素であるため、それらの選択肢は独立して増加し、偶数サイクルごとに 2 つの選択肢の積が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
p = [0] + list(map(int, input().split()))

visited = [False] * (n + 1)
even_cycles = 0

for i in range(1, n + 1):
    if visited[i]:
        continue

    cur = i
    cycle_len = 0

    while not visited[cur]:
        visited[cur] = True
        cycle_len += 1
        cur = p[cur]

    if cycle_len % 2 == 1:
        print(0)
        sys.exit(0)

    even_cycles += 1

print(pow(2, even_cycles, MOD))
```走査では、順列によって引き起こされる関数グラフ上で標準的なサイクルウォークを使用します。 各ノードは最初に出現したときに訪問済みとしてマークされるため、すべてのサイクルが 1 回だけ処理されます。 

サイクル長のパリティ チェックは重要なステップです。奇数のサイクルがあると、出力 0 で即座に終了します。 それ以外の場合、各偶数サイクルは乗算係数 2 に寄与します。 

最後のべき乗は、対数時間で実行され、係数の下で安全な Python の組み込みモジュラー機能を使用します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードはサイクルの形成中に 1 回だけ訪問され、べき乗剰余は O(log n) | になります。 
| スペース | O(n) | 配列と順列ストレージを訪問 |

 線形トラバーサルは制約 n ≤ 100000 内に快適に適合し、アルゴリズムは単純なポインター追跡と 1 つのべき乗のみを十分に制限内で実行します。 

## テストケース```python
import sys, io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    p = [0] + list(map(int, input().split()))

    visited = [False] * (n + 1)
    even_cycles = 0

    for i in range(1, n + 1):
        if visited[i]:
            continue
        cur = i
        cycle_len = 0
        while not visited[cur]:
            visited[cur] = True
            cycle_len += 1
            cur = p[cur]
        if cycle_len % 2 == 1:
            return "0"
        even_cycles += 1

    return str(pow(2, even_cycles, MOD))

# sample-like tests
assert solve("2\n2 1\n") == "2"
assert solve("3\n2 3 1\n") == "0"

# minimum size
assert solve("1\n1\n") == "0"

# all fixed points
assert solve("4\n1 2 3 4\n") == "0"

# two disjoint even cycles
assert solve("4\n2 1 4 3\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2サイクルスワップ | 2 | 単一の偶数サイクル |
 | 3サイクル | 0 | 奇数サイクルが無効 |
 | n=1 自己ループ | 0 | 最小のエッジケース |
 | 恒等置換 | 0 | 複数の奇数サイクル |
 | 2 つの 2 サイクル | 4 | サイクルの独立性 |

 ## 特殊なケース

 p[i] = i のような固定小数点は、長さ 1 のサイクルを直ちに作成します。トラバーサル中に、アルゴリズムはサイクル長 1 を検出し、ゼロで終了します。 たとえば、入力`1 1`サイクル長 1 が生成され、拒否されます。 

完全に自己マップまたは奇数サイクルで構成される順列は、最初に検出された奇数サイクルが即時終了をトリガーするため、早期に崩壊します。 これにより、単一の無効なサイクルによって構成全体が不可能になるため、正確性を維持しながら、グラフの残りの部分の不必要な走査が防止されます。 

等周期が複数ある場合`2 1 4 3`、長さ 2 の 2 つの独立したサイクルが生成されます。それぞれが係数 2 に寄与し、アルゴリズムはそれらを正しく乗算して 4 を取得し、サイクルごとの独立したバイナリの選択を反映します。
