 ## 解決策
 ## 問題の理解

 それぞれの側が最大で保持できる 2 つのパンのバランスが与えられています。`n`同じアイテムを一度に。 がある`m`合計でアイテムがあり、そのうちの 1 つだけが「不良」です。つまり、他のすべてのアイテムと重さが異なりますが、それが重いか軽いかはわかりません。 残り`m - 1`アイテムは区別できず、同じ重さです。 

各計量は、どちらの側も容量を超えないという制約のもとで、一部の品目を左側の皿に置き、一部を右側の皿に置くことで構成されます。`n`。 天秤は、左側が重いか、軽いか、または等しいかを示します。 課題は、最悪の場合に必要な計量の最小数を決定し、複数の計量品の中から不良品を確実に特定できるようにすることです。`m`候補者たち。 

重要な構造は、各計量で 3 つの結果が得られるが、容量の制約があるということです。`n`一度に意味のある比較ができる項目の数は制限されています。 これにより、計量ごとに得られる情報と含めることができるアイテムの数との間に緊張が生じます。 

制約`m ≤ 10^6`すべての構成にわたるシミュレーションやインタラクティブな検索を即座に除外します。 平`O(m log m)`各ステップが高価な場合、サブセットを明示的にシミュレートする構築は大きすぎます。 この問題では明らかに、どのくらいの数の項目を区別できるかについての数学的特徴付けが必要です。`k`秤量。 

次の場合、微妙なエッジケースが発生します。`m = 1`。 この場合、不良品はすでに特定されているため、計量の必要はありません。 もう 1 つの例外的なケースは次のような場合です。`n = 1`ここで、各重み付けでは 1 つの項目だけを他の 1 つの項目と比較することができ、問題を非常に限られた分岐係数を使用した線形検索に効果的に軽減します。 各重み付けが探索空間を均等に分割するという単純な仮定は、この領域では失敗します。これは、容量制約により、識別可能なケースでの指数関数的な増加が妨げられるためです。 

## アプローチ

 この問題を考える強引な方法は、アイテムを天秤に乗せて結果を追跡するために考えられるすべての戦略をシミュレートすることです。 それぞれの計量には 3 つの結果があるため、考えられるすべての計量シーケンスにわたって 3 値決定木を探索することを想像するかもしれません。 ただし、各計量は天びんに載せることができる項目の数によって制限されるため、分岐係数を自由に使用することはできません。 

計量ごとに項目の左、右、または未使用へのすべての可能な割り当てをシミュレートしようとすると、状態空間は両方の組み合わせになります。`m`そして計量回数。 中程度の場合でも`m`、これは実行可能な計算をはるかに超えて爆発します。 

重要な観察は、視点を反転することです。 戦略を構築する代わりに、私たちは能力について質問します。`k`計量では、常にいくつのアイテムを区別できるでしょうか? それぞれのアイテムには 2 つの可能性があり、悪いものである可能性と、より重いまたはより軽い可能性があります。 つまり、各項目は 2 つの状態に対応するため、以下を区別します。`2m`可能性。 

各計量は最大で 1 つまで配置できます`n`アイテムは両側にあるため、最大でも`2n`アイテムは計量ごとに参加します。 それぞれの重み付けから 3 つの結果が得られるため、`k`計量で区別できるのはせいぜい`3^k`結果シーケンス。 したがって、区別可能な仮説の数が可能な結果パターンの数を超えてはいけないという制約がありますが、各項目が計量ごとに容量を消費することも考慮する必要があります。 

このタイプのバランス問題の標準換算は対数関係につながります。つまり、最小のものが必要です。`k`総識別可能な容量が`k`計量はカバーするのに十分です`m`各計量値は、同時にテストできる項目の数によって決定される乗算係数に寄与します。 計量あたりの有効成長は次のとおりです。`2n + 1`項目グループ構造ごとに状態を区別できるため、古典的な境界が得られます。 

私たちは最低限のものを求めます`k`そのような`(2n + 1)^k ≥ m`。 

したがって、答えは単に対数の底です`(2n + 1)`の`m`、切り上げます。

 ## アルゴリズムのチュートリアル

 1. 有効分岐係数を計算します。`b = 2n + 1`。 これは、天びんの両側が完全に利用されている場合に、計量ごとにいくつの異なる結果または品目の状態を解決できるかを表します。 用語`2n`置くことから来る`n`側面ごとの項目、および`+1`計量設計における「未使用または中立」の寄与に相当します。 
2. もし`m = 1`、 戻る`0`比較する必要がないため、すぐに実行されます。 これにより、些細な場合の対数を計算することが回避されます。 
3. カウンタを初期化する`k = 0`そして容量アキュムレータ`cap = 1`、その後の区別可能な状態の数を表します。`k`秤量。 
4. ながら`cap < m`、増分`k`そして掛け算する`cap`による`b`。 各乗算は、追加の重み付けを 1 つ実行し、識別可能な空間を乗算的に拡張することに対応します。 
5. 1回`cap ≥ m`、 戻る`k`必要な計量の最小数として。 

この反復乗算が有効である理由は、両方のパンを完全に飽和させる最適な戦略の下で、各重み付けが固定乗算係数によって検索空間を絞り込むためです。 

### なぜ効果があるのか

 核となる不変条件は次のとおりです。`k`最適な戦略で区別できるのは、最大でも`(2n + 1)^k`どのアイテムが悪いのかについてのさまざまな仮説。 それぞれの計量は、可能性のセットを最大でいくつかに分割します。`2n + 1`各アイテムはバランスの結果全体で最大 3 つの役割に貢献できますが、パンの容量によって制限されるため、一貫した結果クラスになります。 したがって、いかなる戦略も指数関数的な成長を超えることはできません。`k`ベース付き`2n + 1`、そして計量全体で項目をバランスよく割り当てることによって、この限界を漸近的に達成する構造が存在します。 最小限の`k`したがって、この容量を満たすか超える最小の整数になります。`m`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if m == 1:
    print(0)
    sys.exit()

b = 2 * n + 1

cap = 1
k = 0

while cap < m:
    cap *= b
    k += 1

print(k)
```この実装は、指数関数的な容量増加の議論を直接反映しています。 変数`b`計量ごとの拡張係数をエンコードします。 ループは、計量を追加するたびに、どれだけのアイテムを識別できるかを繰り返しシミュレーションします。 停止条件により最小値に到達することが保証されます。`k`蓄積された識別力がすべての人にとって十分であるように`m`アイテム。 

ここでよくある落とし穴は、`m = 1`誤って返されるケース`1`の代わりに`0`対数またはループを介して処理される場合。 もう 1 つの微妙な問題は、整数サイズが固定されている言語での整数オーバーフローですが、Python はこれを自動的に回避します。

 ## 特殊なケース

 いつ`m = 1`、アルゴリズムはすぐに戻ります`0`、計量する必要がないため。 容量から開始するループベースのソリューション`1`インクリメントは誤って返されます`1`少なくとも 1 つの乗算ステップを実行するためです。 

のために`n = 1`そして大きい`m`、成長因子は`3`、したがってループは正確に実行されます`ceil(log_3(m))`回。 たとえば、`m = 10`、容量を取得します`1 → 3 → 9 → 27`、したがって、答えは次のとおりです`3`。 このケースでは、アルゴリズムがオーバーフローや精度の問題を発生させることなく、可能な限り遅い成長率を正しく処理していることを検証します。
