 ## 解決策
 ## 問題の理解

 独立した因子の積として構築された多項式が与えられます。 各因子は、考えられる少数の累乗に寄与します。$x$、すべての因子を掛け合わせると、最終的な拡張多項式が得られます。 タスクは、特定のべき乗の係数を求める多くのクエリに答えることです。$x^a$この完全に拡張された製品では。 

各因子は、定数項、2 で割った値の下限に応じた指数をもつ項、元の値に等しい指数をもつ項の 3 つの項を構成する形式をとります。 具体的には、各因子がいくつかの非ゼロの単項式を含む小さな多項式のように動作し、最終的な式が全体の積になるという構造です。$n$要因。 

入力サイズの制約$n \le 11$が中心的なヒントです。 たとえ指数であっても、$f_i$まで大きくすることができます$10^6$、因数の数はわずかです。 クエリの数は最大で大きくなる可能性があります。$10^4$したがって、関連するすべての係数を一度事前計算し、定数時間で各クエリに答える必要があります。 

素朴な解釈では積を直接拡張しようとしますが、次数と項の数の両方ですぐに巨大な中間多項式に遭遇します。 指数はすべての和に達する可能性があるため、剪定なしで多項式を明示的に表すことさえ不可能です。$f_i$、係数は多くの組み合わせから生じる可能性があります。 

複数の組み合わせが同じ指数を生成する場合、微妙なエッジケースが発生します。 同じべき乗を結合せずに項を列挙する不注意なアプローチでは、集計された係数ではなく重複したエントリが生成されます。 もう 1 つの落とし穴は、指数が小さいと仮定することです。$n$は小さいですが、これは false です。$f_i$大きくなる可能性があり、合計次数は最大約$11 \cdot 10^6$。 

本当の難しさは、サブセットの組み合わせの爆発です。各要素は複数の選択肢に寄与するため、すべての組み合わせを効率的に考慮する必要があります。 

## アプローチ

 この強引なアイデアは、多項式の乗算を段階的にシミュレートすることです。 1 に等しい多項式から開始し、因子ごとに現在の多項式に 3 項の多項式を乗算します。 各乗算では既存の項をすべて取得し、それを 3 つの新しい項に拡張し、指数をシフトして係数を加算します。 

現在の多項式が$M$つまり、1 回の乗算の後、おおよそ次のようになります。$3M$、その後$n$になるステップ$3^n$重複をマージする前に最悪の場合の条件を変更します。 と$n = 11$、これは生の用語約 177,000 であり、境界線にありますが、マージが非常に効率的である場合にのみ管理可能です。 ただし、実際には指数が頻繁に衝突するため、慎重にグループ化しないと実装が遅くなったり、不正確になったりします。 

重要な観察は次のとおりです$n$は、反復多項式畳み込みではなく、インデックスに対する中間一致スタイルのサブセット動的プログラミングには十分小さいです。 各因子は独立して 3 つの選択肢のうちの 1 つに寄与するため、最終的な各単項式はインデックスごとに 1 つの選択肢を選択することに対応します。 これは、すべての係数をすべて列挙することによって決定されることを意味します。$3^n$選択肢の組み合わせですが、$3^{11}$はわずか約 177,000 であり、一度に計算することが可能です。 

すべてのサブセットの組み合わせを事前計算し、その結果得られる指数と係数を累積し、指数によってインデックス付けされた辞書または配列にカウントを保存できます。 この前処理の後、クエリへの応答は直接検索になります。

 ## アルゴリズムのチュートリアル

 各要素は、構築プロセスにおける 3 つの可能な「動き」に寄与すると解釈します。つまり、定数項の選択、中間の指数の選択、または完全な指数の選択です。 すべての因子にわたるそれぞれの完全な選択により、最終展開で 1 つの単項式が生成されます。 

次に、インデックスに対する再帰的または反復的な走査を使用して、そのような選択をすべて明示的に列挙します。 

1. 空の選択を表す単一の状態から開始します。現在の指数は 0、係数は 1 です。これは、まだ因数が存在しない定数項を選択することを表します。 
2. 要素を 1 つずつ処理します。 それぞれの要因について$i$、既存のすべての部分状態を取得し、それを因子の 3 つの項に対応する 3 つの方法で拡張します。 これにより、指数が適切に増加する新しい状態が作成されます。 
3. 状態を拡張するときは、0、$f_i // 2$、 または$f_i$。 係数には、対応する項の係数が乗算されます。 この問題では、係数は実質的に次のようになります。$-1$非定数項の場合、非定数選択が行われた数に応じて、各選択の符号が反転する可能性があります。 
4. すべての因子を処理した後、指数値を最終係数にマッピングする寄与のコレクションを取得します。 多くの異なるパスが同じ指数を生成する可能性があるため、寄与を辞書に蓄積します。 
5. 前処理が完了したら、保存されている指数の係数を返すことで各クエリに答えます。$a$存在しない場合はデフォルトで 0 になります。 

これが機能する理由は、最終的な多項式のすべての単項式が、各因子からの項の 1 つの選択に一意に対応するためです。 この構築では、そのような選択をすべて 1 回だけ列挙し、累積ステップで同一の指数をマージして、正しい係数の合計を保持します。 これにより、拡張多項式の選択状態と項の間に 1 対 1 のマッピングが確立され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, q = map(int, input().split())
    f = list(map(int, input().split()))

    # dp will store (exponent -> coefficient)
    dp = defaultdict(int)
    dp[0] = 1

    for fi in f:
        ndp = defaultdict(int)
        a = fi // 2
        b = fi

        for exp, coeff in dp.items():
            # choose constant term (1)
            ndp[exp] += coeff

            # choose -x^(fi//2)
            ndp[exp + a] += -coeff

            # choose -x^(fi)
            ndp[exp + b] += -coeff

        dp = ndp

    for _ in range(q):
        a = int(input())
        print(dp.get(a, 0))

if __name__ == "__main__":
    solve()
```このソリューションは、指数から係数へのマッピングの辞書を維持します。 各反復では、現在の多項式状態が新しく構築された多項式状態に置き換えられます。 重要な実装の詳細は、辞書を適切に更新してはいけないということです。そうしないと、同じ要素からの寄与が互いに干渉してしまいます。 代わりに、要素ごとに新しいマップを構築します。 

もう 1 つの微妙な点は、クエリ中に欠落している指数を処理することです。 すべての指数が最終展開に現れるわけではないため、キーがない場合は 0 を返します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の組み合わせが反対の符号を持つ同じ指数を生成し、キャンセルにつながる場合です。 たとえば、慎重に選ばれたものでは、$f_i$、異なるパスは同じ指数を生成できますが、+1 と -1 が寄与し、結果はゼロになります。 すべての更新では上書きではなく辞書内の追加の蓄積が使用されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、すべての要因が定数項のみに寄与する場合です。 この状況では、多項式は 1 のままで、指数 0 のみが存在します。 このアルゴリズムは dp[0] = 1 を初期化し、すべての要素が一定の選択パスを保持するため、この状態が失われることはありません。 

最後の微妙なケースは、指数が大きいことです。 値は数百万に達する可能性がありますが、アルゴリズムは指数範囲を反復することはなく、到達可能な状態のみを反復します。 各状態遷移は明示的に新しい指数を構築するため、スパース性は自然に維持され、サイズの配列は必要ありません。$10^6$が必要です。
