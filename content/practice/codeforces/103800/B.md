 ## 問題の理解

 モンスターの健康値の配列が与えられます。 何かを開始する前に、各値を個別に減らすことはできますが、元の値を超えて増やすことはできません。 準備が完了したら、開始位置を選択します$i$。 その位置からインデックス 1 までずっと左に移動します。このセグメントに沿った値は非増加シーケンスを形成する必要があります。 得られる報酬は、この選択したセグメントの最終調整値の合計です。 

したがって、プロセスには 2 つの決定があります。 まず、上限を尊重して配列を下向きに整形します。 次に、次のような接頭辞を選択します。$i$ただし、そのプレフィックスは制限された方法で再配置する必要があります。左に移動するにつれて、値が上がることはありません。 

の制約$n$まで$2 \cdot 10^5$開始位置ごとに最適な調整を個別に再計算する二次関数の試みは直ちに除外されます。 プレフィックス プロセスを再構築またはシミュレートするソリューション$i$遅すぎるでしょう。 

値がすでに減少している場合、微妙なエッジケースが発生します。 その状況では、削減は必要なく、答えは単純に最良のプレフィックス合計になります。 反対に、値が次のように変動する場合、$1, 100, 2, 99, 3$、単純なローカル調整は局所的に最適に見える可能性がありますが、左に拡張するとグローバルな単調要件を破ります。 

## アプローチ

具体的に直すと、$i$、最終値を次のように設定します。$i$に$a_i$。 次に左に移動し、各位置$j$になる$\min(a_j, b_{j+1})$。 すべての制約はローカルであり、次の位置にのみ依存するため、これにより、そのエンドポイントに対して実行可能な最大のシーケンスが生成されます。 

強引なアイデアは、すべてのオブジェクトに対してこの構築を繰り返すことです。$i$。 毎回、最小値を右から左に伝播することによってプレフィックス全体を再計算します。 これには費用がかかります$O(n)$あたり$i$、につながる$O(n^2)$、これは限界をはるかに超えています$2 \cdot 10^5$。 

重要な観察は、この貪欲な構造が実際に何を計算しているのかを再解釈することです。 固定の場合$i$、位置の値$j$区間の最小値になります$[j, i]$。 したがって、エンドポイントの合計スコアは$i$で終わるすべての部分配列の最小値の合計になります。$i$。 

問題がこの形式で表示されると、古典的な「各インデックスで終わる部分配列の最小値の合計」問題になります。 最初から再計算する代わりに、以前の小さな要素がどこにあるかを追跡する単調スタックを使用して、貢献を段階的に維持できます。 これにより、インデックスごとの償却一定時間で合計寄与度を更新できます。

 ## アルゴリズムのチュートリアル

 単調増加するインデックスのスタックを維持しながら、配列を左から右に処理します。スタックの奥深くに行くにつれて値が増加します。 これに加えて、動的な値を計算します。$dp[i]$、位置で正確に終了するすべての部分配列の合計寄与として定義されます。$i$、各部分配列はその最小要素を提供します。 

1. 対応する値が下から上に厳密に増加するようにインデックスのスタックを維持します。 この構造により、所定の位置にあるときに、$i$、スタックは前の小さな要素がどこにあるかをエンコードします。 
2. インデックスごとに$i$、先頭が厳密に小さい値になるまでスタックからポップします。$a[i]$。 この処理の後、スタックの先頭が前のインデックスになります$p[i]$どこ$a[p[i]] < a[i]$、存在しない場合はゼロ。 
3. 重要な移行は計算することです$dp[i]$すべてのサブ配列が次で終わるという事実を利用します。$i$に対する開始位置によってグループ化できます。$p[i]$。 以降に始まるサブ配列$p[i]$持っている$a[i]$それらの間には何もないので、最小限として$i$よりも小さいです$a[i]$。 以降で始まるサブ配列$p[i]$で終わるものとまったく同じように動作します$p[i]$。 
4. これにより、計算が 2 つの部分に分割されます。$dp[p[i]]$に加えて、次の寄稿による新しい貢献の長方形のブロックが含まれています。$a[i]$。 この新しい最小値を取得する開始の数は次のとおりです。$i - p[i]$、したがって、追加された貢献は$a[i] \cdot (i - p[i])$。 
5. の最大値を追跡します。$dp[i]$すべてのポジションにわたって$i$、どのエンドポイントも有効な選択であるためです。 

### なぜ効果があるのか

 スタックはそれを保証します$p[i]$値が厳密に以下の左に最も近い位置です。$a[i]$。 これにより、次で終わるすべてのサブ配列が分割されます。$i$そこに$a[i]$は最小値とそうでないものです。 2 番目のグループは、次で終わる部分配列とまったく同じです。$p[i]$、以前は何でもあったので、$p[i]$すでにそれ以下の制限値が設定されています。 この不変式により、すべてのサブ配列が次で終わることが保証されます。$i$は正確に 1 回カウントされ、その正しい最小値に起因します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    dp = [0] * n

    for i in range(n):
        while stack and a[stack[-1]] >= a[i]:
            stack.pop()

        p = stack[-1] if stack else -1
        left_count = i - p

        prev = dp[p] if p != -1 else 0
        dp[i] = prev + a[i] * left_count

        stack.append(i)

    print(max(dp))

if __name__ == "__main__":
    solve()
```このソリューションは、各要素が以前の厳密に小さい値を認識できるように単調スタックを構築します。 変数`p`はまさに、サブ配列が次のものを持たなくなる境界です。`a[i]`それらの最小限として。 掛け算`a[i] * (i - p)`で終わるすべての新しいサブ配列を考慮します。`i`新たに採用したもの`a[i]`それらの最小限として。 

の再発`dp[i]`これがソリューションを線形にするものです。 すべての部分配列の最小値を再計算する代わりに、`dp[p]`、これには以前の構造からのすべての貢献がすでに含まれており、それを によって作成された新しいブロックで拡張します。`a[i]`。

def solve_output(inp: str) -> str:

    from io import StringIO
    sys.stdin = StringIO(inp)

    stack = []
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

        p = stack[-1] if stack else -1

        dp[i] = prev + a[i] * (i - p)
        ans = max(ans, dp[i])
        stack.append(i)

    return str(ans)

 ## 特殊なケース

 単一要素入力は、以前の構造が存在しない基本的なケースを示しています。 スタックは空なので、$p = -1$、そして答えは単純に要素自体であり、そこで終わる部分配列がちょうど 1 つあるという考えと一致します。 

すべての要素が等しい場合、スタックは空になるまでポップし続けるため、すべての新しいインデックスが以前のすべてのインデックスの境界になります。 それぞれ$dp[i]$は三角形の累積になりますが、この式では依然として各部分配列が 1 回だけ正確にカウントされます。 

厳密に増加する配列では、各要素が新しい最大値となり、以前のすべてのサブ配列を拡張します。 スタックは決してポップしないので、$p[i]$は常に前のインデックスであり、寄与分はリセットせずに成長するセグメント全体にわたって直線的に蓄積されます。
