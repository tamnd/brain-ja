 ## 解決策
 ## 問題の理解

 入力は基本的に、長いエンコードされた整数のリストであり、各整数は垂直バーで囲まれ、順番に表示されます。 書式設定を削除すると、武器の攻撃値の配列が得られ、それぞれが元の文字列内の位置に関連付けられます。 タスクは、これらの武器を正確に k 個選択して、それらの値の積ができるだけ大きくなるようにすることです。 それらを選択した後、元のインデックスを昇順で出力する必要があります。 複数の選択で同じ最大積が得られる場合は、インデックス シーケンスが辞書編集的に最小のものを返さなければなりません。 

主な困難は、最大積を計算することだけではなく、符号とネクタイを扱うことです。 値は負の値になる可能性があるため、選択される負の数の数を注意深く制御することで積が最大化されます。 複雑さの 2 番目の層は、入力が最大長 2 × 10^6 の単一の大きな文字列であるため、解析は線形である必要があるという事実から生じます。 武器の数も十分に多いため、解析後の解はおよそ O(n log n) 以上でなければなりません。 

単純なアプローチでは、k 個の要素のすべての組み合わせを試し、その積を計算し、最良のものを選択します。 オーバーフローを無視しても、n が O(n selected k) に応じて増加するため、n が数十万までは完全に失敗します。 k 個の最大値を選択する貪欲な試みでも、負の数が含まれる場合は失敗します。 たとえば、値によって最大の k 数値を選択することは次善の策となる可能性があります。 

配列が [−10, −9, 2, 3] で k = 3 の場合、[2, 3, −9] を選択すると積 −54 が得られますが、[−10, −9, 3] を選択すると積 270 が得られ、これははるかに優れています。 

もう 1 つの微妙な失敗例は、選択された負の値の数が奇数である場合に発生します。 絶対値の最大値を選んでも積がマイナスになってしまうため、要素を入れ替えて調整する必要があります。 

## アプローチ

 この強引なアイデアは、サイズ k のすべてのサブセットを列挙し、それらの積を計算し、最適なものを追跡することです。 これは目的関数を直接評価するため正しいですが、O(n selected k) 回の演算が必要となり、n が 40 付近の場合でも実行不可能になります。 

重要な観察は、値の大きさだけが寄与の強さを決定し、符号はパリティに影響を与えるということです。 積を最大化するには、絶対値が最大の要素を選択する必要があります。これは、より小さい絶対値をより大きな絶対値に置き換えることで常に積の大きさが改善または維持されるためです。 これにより、絶対値によって k 要素を選択し、符号パリティを修正するという問題が軽減されます。 

絶対値でソートした後、上位 k 個の要素を候補セットとして取得します。 これにより、可能な限り最高の大きさが得られます。 残る唯一の問題は、積が可能な限り負でないこと、つまり負の値が偶数であることを保証することです。 

選択したセットに偶数のネガがある場合、そのセットはすでに最適です。 負の数が奇数の場合は、1 回のスワップを実行する必要があります。 意味のある交換方向は 2 つあります。選択したセットから負を削除するか、選択したセットから正を削除して、大きな大きさを維持しながら符号バランスを改善する未選択の要素に置き換えます。 どのスワップが最良の製品を生み出すかを評価します。

 | --- | --- | --- | --- |

 | 絶対ソートの貪欲な調整 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず入力文字列を解析し、すべての整数を 1 から始まるインデックスとともに抽出します。 各数値はペア (値、インデックス) として保存されます。

1. すべてのペアを絶対値の降順で並べ替えます。 2 つの値の絶対的な大きさが同じである場合、インデックスが小さい方が最初になります。 このタイブレークは、複数の最適解が存在する場合に、辞書編集的に小さい答えを維持するのに役立ちます。 
2. このソートされたリストから最初の k 要素を初期候補セットとして取得します。 選択した要素をより小さい絶対値に置き換えても積を改善できないため、これにより可能な最大の積の大きさが保証されます。 
3. 選択したセットに負の数がいくつあるかを数えます。 このカウントが偶数であれば、最適な大きさと符号の一貫性のレベルで完了です。 
4. 負の数が奇数の場合、符号を修正する必要があります。 考えられる是正措置は 2 つ考えられます。 1 つは、選択した絶対値が最小のネガティブを削除し、セットの外で利用可能な最良のポジティブに置き換えることです。 もう 1 つは、絶対値が最小の選択された正を削除し、セットの外で利用可能な最良の負で置き換えることです。 可能な場合は両方の候補を計算します。 
5. マイナスを均等に回復しながら、積の規模に有効な改善をもたらすスワップを選択します。 スワップが 1 つだけ可能な場合は、それを適用します。 
6. 最後に、選択したインデックスを昇順に並べ替えて出力します。 

このプロセス全体を通して重要な不変点は、ステップ 2 の後、選択されたセットには常にすべての要素の中で最大 k 個の絶対値が含まれていることです。 ステップ 4 での変更はカーディナリティを維持し、絶対積の損失を最小限に抑えながら最適な符号パリティを復元します。 置換により小さい絶対値が削除され、残りの候補の中から大きい絶対値が優先されるため、パリティを修正するために必要な以上に最適性を下げることはありません。

input = sys.stdin.readline

def parse():
    s = sys.stdin.readline().strip()
    nums = []
    i = 0
    n = len(s)
    idx = 1
    while i < n:
        if s[i] == '|':
            i += 1
            if i >= n:
                break
            sign = 1
            if s[i] == '-':
                sign = -1
                i += 1
            val = 0
            while i < n and s[i] != '|':
                val = val * 10 + (ord(s[i]) - 48)
                i += 1
            nums.append((sign * val, idx))
            idx += 1
        else:
            i += 1
    return nums

def solve():

    k = int(sys.stdin.readline())

    rest = nums[k:]

        ans.sort()
        print(*ans)

    chosen_neg = [x for x in chosen if x[0] < 0]
    chosen_pos = [x for x in chosen if x[0] > 0]
    rest_neg = [x for x in rest if x[0] < 0]
    rest_pos = [x for x in rest if x[0] > 0]
    
    best = None
    
    # option 1: remove smallest abs negative, add best positive

```解析ループは文字列を 1 回調べて、増加するインデックスを割り当てながら縦棒の間の符号付き整数を抽出します。 ソートのステップでは、最初に絶対値によって順序付けされ、最初の k の選択によって積の大きさが最大化されることが保証されます。 スワップ ロジックは、負のパリティが間違っている場合にのみトリガーされ、絶対値をできるだけ大きく保ちながら 1 つの要素を交換することで正確さを復元しようとします。 

微妙な点は、完全な積を再計算することは決してないということです。 このアルゴリズムは絶対値による順序付けに完全に依存しており、log(product) は対数の合計であるため、乗算構造を暗黙的にエンコードし、各項を個別に最大化することで最適性が維持されます。 

## 実用的な例

 値 [−10, −9, 2, 3] および k = 3 の入力を考えてみましょう。 

まず絶対値でソートし、[−10, −9, 3, 2] を与えます。 最初の選択は [-10, -9, 3] です。 負の数は 2 で偶数であるため、ソートされたこれらの要素のインデックスを直接出力します。 

ここで、k = 3 の [−10, −3, −2, 5, 6] を考えてみましょう。 

| ステップ | 選択されたセット | ネガカウント | アクション |
 | --- | --- | --- | --- |
 | イニシャル | −10、6、5 | 1 | パリティ修正が必要 |
 | スワップ試行 | -10 を削除し、-3 を追加 | 1→1 | 符号バランスを改善します |

 スワップ後、[−3, 6, 5] が得られますが、これには 2 つの正と 1 つの負があり、まだ修正されていないため、代わりにパリティを適切に復元する最適な有効なスワップを選択します。 

このトレースは、アルゴリズムが、制御された置換を通じて符号パリティを修正しながら、大きな大きさを維持することに重点を置いていることを示しています。 

## 複雑さの分析

 ## 特殊なケース

 1 つのエッジ ケースは、すべての数値が負で、k が奇数の場合に発生します。 この場合、正の積を得ることができないため、最善の戦略は、すべての負の値の中から k 個の最小の絶対値を選択することです。 絶対値による並べ替えにより、最もダメージの少ないネガティブな結果が最初に選択されるため、アルゴリズムはこれを自然に処理します。 

別のケースは、k が n に等しい場合です。 その場合、交換は不可能になり、答えはすべての要素として固定されます。 初期選択にはすでにすべてが含まれており、置換ステップ トリガーがないため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、ゼロがある場合です。 ゼロは積を無効にするためパリティ リセットとして機能しますが、問題はインデックスの選択のみを必要とするため、大きさの順序付けではゼロは他の値と同様に扱われます。 絶対値による並べ替えにより、より強い寄与を置き換えることなく、必要な場合にのみゼロが選択されることが保証されます。
