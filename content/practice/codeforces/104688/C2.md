 ## 解決策
 ## 問題の理解

 私たちは未知の開始値が存在するシステムを与えられていますが、「ハッキングされた」バージョンでは実際にはそれを知っています。 それに加えて、変換したい目標値もあります。 許可される唯一のツールは、現在の値に適用される算術のような演算の小さなセットです。数値を加算したり、数値で乗算したり、数値で正確に除算したり、数値を桁の合計で置き換えたりすることができます。 各操作は順番に適用され、最終値がターゲットと正確に一致することを保証するような操作の短いシーケンスを生成する必要があります。 

インタラクションの説明は隠された値に対するゲームのように見えますが、ハッキングされたバージョンでは不確実性が取り除かれているため、タスクは建設的になります。2 つの整数が与えられた場合、初期値をターゲット値に変換する許可された一連の短い操作を明示的に記述する必要があります。 

一般的な問題とは異なる意味で制約が厳しいです。 制限は計算時間ではなく、最大 4 回の演算数にあります。 これにより、ある数値から別の数値に徐々に「移動」したり、桁ごとの構築をシミュレートしたりするアプローチは即座に排除されます。 値間の差を線形にすることは不可能です。単純に行うと、差が 1 であっても、すでに許容予算を超える量が必要になるからです。 

単純な算術戦略では微妙な問題が発生します。 たとえば、差の 1 回の加算を直接実行することは魅力的に見えますが、中間値が有効なままでなければならない、または非表示の値が存在する場合、この問題の他の変形では制約に違反する可能性があります。 もう 1 つの危険なアイデアは、差を因数分解して乗算と除算を使用しようとすることです。 数値の構造が恣意的であり、割り切れる可能性が保証されていないため、これは破綻します。 

主な困難は、任意の値を「構造化された」ものに迅速に圧縮し、一定のステップ数内で制御された方法でターゲットを再構築しなければならないことです。 

## アプローチ

 ブルートフォースの考え方では、小さな増分または係数ベースの調整を使用して、初期値からターゲットに向かう変換をシミュレートしようとします。 値の加算や減算を繰り返したり、gcd のような操作で数値を整列させたりすることを想像することもできます。 演算は任意の整数に達するほど表現力豊かであるため、これは原理的には正しいですが、演算が 4 つという厳密な上限の下では完全に実行不可能です。 最悪の場合、大きな目標差に到達するには、線形または対数的に多くのステップが必要となり、すぐに制限を超えます。 

重要な観察は、数字の合計演算が圧縮ツールとして非常に強力であるということです。 これを繰り返し適用すると、10^9 までの任意の数値が非常に小さな範囲に折りたたまれます。 1 つのアプリケーションでは数値が最大 81 に減り、2 つ目のアプリケーションではさらに 1 から 9 までの 1 桁に減ります。値が制限された範囲内に収まれば、1 つの乗算と 1 つの加算を使用して任意のターゲットを「再構築」できるため、これは非常に重要です。 

これにより、問題は 2 つのフェーズに分割されます。 まず、桁の合計を使用して未知の値を正規の小さな代表値に積極的に削減します。 次に、1 つのスケーリング ステップと 1 つのオフセット補正を使用して、その代表からターゲットを構築します。

 ## アルゴリズムのチュートリアル

 初期値はわかっていると仮定します`x`そしてターゲット`n`。 

1. 桁合計演算を 1 回適用します。 これは置き換えます`x`桁の合計によって、値が最大 81 になることが保証されます。桁の合計では正の整数に対して 0 が生成されないため、このステップは安全です。そのため、使用可能な正の状態が常に保持されます。 
2. 再度桁和演算を適用します。 値は最大 81 であるため、結果は最大 9 になります。このステップの後、現在の値は 1 から 9 までの 1 桁になります。このステップは重要です。境界のある 1 桁の基数を使用すると、最大 2 つの演算を使用してターゲットを正確に再構築できるためです。 
3. ターゲットに近づくためにこの小さな値をスケーリングする方法を計算します。 現在の値を次のようにします`c`。 私たちは計算します`q = n // c`。 乗算`q`の最大倍数に合わせます`c`を超えないもの`n`。 これは、乗算が許可され、値が範囲内に保たれるため有効です。 
4. 次の乗算演算を適用します。`q`、値を次のように更新します`c * q`。 
5. 残りの差を計算します`r = n - c * q`。 この余りは以下であることが保証されています`c`、したがって小さいです。 次に、次の加算演算を 1 つ適用します。`r`、これは値を正確にもたらします`n`。 

微妙な点は、すべての演算が整数で行われることです。`c`は決してゼロにはならないため、計算時に除算は常に有効です。`q`。 

### なぜ効果があるのか

 正確さは、2 つの桁の合計演算後の現在の値が範囲内のゼロ以外の整数であるという不変条件に基づいています。`[1, 9]`。 ここから、すべての整数`n`一意に分解できます`n = c * q + r`と`0 ≤ r < c`。 乗算ステップで基本倍数を設定し、加算ステップで剰余を正確に補正します。 どちらの操作も制約の下では常に有効であるため、最終的な値は等しくなければなりません。`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(x):
    return sum(map(int, str(x)))

def solve():
    t = int(input())
    for _ in range(t):
        # in hacked version: we read n and x
        n, x = map(int, input().split())
        
        ops = []
        
        # step 1: digit
        x = digit_sum(x)
        ops.append(("digit",))
        
        # step 2: digit again
        x = digit_sum(x)
        ops.append(("digit",))
        
        # now x is in [1, 9]
        c = x
        
        q = n // c
        r = n - c * q
        
        # step 3: multiply
        x = x * q
        ops.append(("mul", q))
        
        # step 4: add remainder
        x = x + r
        ops.append(("add", r))
        
        # output operations
        for op in ops:
            if op[0] == "digit":
                print("digit")
            else:
                print(op[0], op[1])

        # final check command (not needed in hack, but conceptually)
        print("!")

if __name__ == "__main__":
    solve()
```最初の 2 つの操作は、初期値を 1 桁の代表値に圧縮します。 乗算ステップでは、この代表値をターゲットに向かって 1 回で拡張し、最後の加算で正確なオフセットを修正します。 乗算の前に加算を実行すると、基数と剰余へのきれいな分解が無効になるため、順序は重要です。 

よくある間違いは、1 桁の合計のみを使用しようとすることです。 これにより、値は最大 81 の範囲内に残り、残りが 1 つの補正ステップで許容される境界を超える可能性があるため、再構成の安定性が低下します。 2 番目の桁の合計は、厳密な 1 から 9 の範囲を保証し、分解を常に安全にします。 

## 実用的な例

 次の例を考えてみましょう`n = 100`そして`x = 987`。 

最初の桁の合計の後、値は 9 + 8 + 7 = 24 になります。 

2 桁目の合計の後は、2 + 4 = 6 になります。`c = 6`。 

私たちは計算します`q = 100 // 6 = 16`そして`r = 100 - 96 = 4`。 

乗算すると値は 96 になり、加算すると 100 になります。 

トレース:

 これは、桁圧縮によって正確な再構築が可能となる安定したベースがどのように作成されるかを示しています。 

次に、次の 2 番目の例を考えてみましょう。`n = 37`そして`x = 12345`。 

桁の合計は 15、2 番目の桁の合計は 6 になります。`c = 6`。 

私たちは計算します`q = 6`、`r = 37 - 36 = 1`。 

乗算すると 36 が得られ、加算すると 37 が得られます。
