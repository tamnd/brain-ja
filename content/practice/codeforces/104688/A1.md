 ## 問題の理解

 通常の 10 進数形式で書かれた非負の整数のシーケンスが与えられます。 それらを左から右に処理します。私たちの仕事は、シーケンスが厳密に増加するように変換することです。 許可される唯一の操作は、数値を取得し、その右側に 10 進数を追加することです。 追加された各桁は 1 回の操作としてカウントされるため、数値を 3 桁拡張するには 3 回の操作が必要になります。 

目標は、必要な追加桁の合計数を最小限に抑え、最終的な形式ですべての数値が前の数値よりも厳密に大きくなるようにすることです。 

重要な点は、先に進んだ後に以前の数値を変更できないことです。 数値を拡張する方法を決定すると、その後の比較のためにその数値が固定されます。 これにより、プロセスが本質的に貪欲になります。 

制約が十分に大きいため、文字列を繰り返し再構築したり、桁ごとの増分をシミュレートしたりする 2 次または比較ごとの構築が遅すぎる可能性があります。 意図したソリューションでは、各数値を 1 回処理し、以前に変換された数値に対してローカルで推論し、総桁数に比例した時間内で処理する必要があります。 

一般的な失敗例は、プレフィックス関係の処理が間違っていることに起因します。 順番を考えてみる`[12, 121]`。 単純に比較すると、121 は 12 より大きいため、変更は必要ありません。 しかし、12 が以前のステップで拡張された可能性があること、または変換された値には厳密な昇順が適用される必要があることを考慮すると、追加操作を考慮せずに単純な数値比較を行うと不変式が破られることがわかります。 

もう一つの問題となるケースは、`[100, 1]`。 単純に数字を比較すると、ゼロを追加できることがわかります。`1`取得するため`10`、`100`などですが、長さを盲目的に一致させる場合は、減少しないことを保証するのではなく、厳密に増加することを保証しないと失敗する可能性があります。 

これらのケースでは、追加時に数字がどのように動作するか、および数値が前の数値より厳密に大きくなるように数値を最小限に拡張する方法について慎重に推論する必要があります。 

## アプローチ

 ブルートフォース戦略では、シーケンスが厳密に増加するまで、各数値に数字を追加するあらゆる可能な方法が試行されます。 位置ごとに、最大桁数まで追加し、サフィックスが有効なままであることを再帰的に確認することを試みる場合があります。 各数値はさまざまな方法で増加する可能性があるため、分岐係数は位置の数で指数関数的に増加し、中程度の入力サイズでも扱いにくくなります。 

重要な観察は、一度貪欲に修正すれば、以前の数値について複数の候補形式を探索する必要がなくなるということです。 各ステップでは、完全な履歴ではなく、以前に変換された数値のみが問題になります。 問題は次のようになります。以前の結果の数値が文字列として与えられた場合、現在の数値が厳密に大きくなるように最小限に拡張します。 

効率を可能にする構造は、桁拡張の下での辞書編集的な比較です。 数値を整数として扱う代わりに、数値を文字列として扱い、追加する数字が順序にどのような影響を与えるかを推論します。 

最適な方法では、現在の文字列と前の文字列を比較し、ゼロを追加するか、プレフィックスと一致するか、プレフィックス境界をわずかに超えるかを決定します。

 ## アルゴリズムのチュートリアル

 We maintain a variable`prev`、前の数値の最終形式を文字列として保存します。 

新しい番号ごとに`cur`、厳密に次より大きい可能な最小の文字列を構築しようとします。`prev`数字の追加のみを使用します。 

1.変換`cur`そして`prev`文字列に。 させて`s = cur`、`t = prev`。 
2. もし`len(s) > len(t)`、 それから`s`すでに十分な長さになる可能性があります。 もし`s > t`、変更せずにそのままにしておきます。 それ以外の場合は、単一の`'0'`に`s`。 これにより、長さが増加すると、以前の固定長の数値と比較して常に大きさが増加するため、値が大きくなることが保証されます。 
3. もし`len(s) == len(t)`、それらを直接比較します。 もし`s > t`、承ります。 それ以外の場合は、1 つ追加します`'0'`長さを強制的に増加させます。これにより、厳密な増加が保証されます。 
4. もし`len(s) < len(t)`、私たちは位置合わせを試みます`s`と`t`接頭辞推論を使用して。 させて`k = len(s)`。 

プレフィックスを検査します`t[:k]`。 

もし`s < t[:k]`そうすると、どんなに伸ばしても、最終的には長さに到達しなければなりません`len(t)`超える`t`。 したがって、正確に追加します`len(t) - k`ゼロ。 

もし`s > t[:k]`、再度追加します`len(t) - k`ゼロ。一致する長さでそれよりも大きくするのに十分であるため、`t`。 

デリケートなケースは次のような場合です`s == t[:k]`。 ここで真似してみます`t`さらに追加することで`t[k:]`。 この拡張機能が依然として次の値を超える数値を生成する場合は、`t`、終わりました。 一致するか、末尾の 9 または完全に等しいために超えられない場合は、代わりに長さを超えてもう 1 桁追加します。`len(t)`、厳格な増加を保証します。 
5. 新規構築後`s`、追加された数字の数を数え、それを答えに追加してから設定します`prev = s`。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。`i`、`prev`変換後の文字列表現の最小値です。`a[i]`これは、以前のすべての要素で厳密な増加を満たします。 各ステップで、それを超えるために必要な最小限の拡張のみを考慮します。`prev`、短い拡張子は順序に違反し、長い拡張子はコストを不必要に増加させます。 比較は接頭辞の優位性と基数 10 表現の長さの影響に基づいているため、貪欲な選択は局所的に最適であり、全体的に最適なままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().split()

    prev = a[0]
    ans = 0

    for i in range(1, n):
        s = a[i]
        t = prev

        if len(s) > len(t):
            if s > t:
                prev = s
            else:
                ans += 1
                prev = s + "0"
            continue

        if len(s) == len(t):
            if s > t:
                prev = s
            else:
                ans += 1
                prev = s + "0"
            continue

        k = len(s)
        if t[:k] != s:
            if s < t[:k]:
                add = len(t) - k
                ans += add
                prev = s + "0" * add
            else:
                add = len(t) - k
                ans += add
                prev = s + "0" * add
        else:
            tail = t[k:]
            candidate = s + tail
            if candidate > t:
                ans += len(t) - k
                prev = candidate
            else:
                add = len(t) - k + 1
                ans += add
                prev = s + "0" * add

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、整数のオーバーフローを回避し、桁レベルの推論を明示するために、すべてを文字列として保持します。 実行される演算は比較、スライス、連結のみであり、桁数はすべて線形です。 

微妙な実装の詳細は、接頭辞が正確に一致するたびに、接尾辞の再利用を試みることです。`prev`。 これは、次の長さに直接ジャンプすることなく、厳密に大きな最小限の数値を生成できるため、余分な桁の追加を避けることができる唯一の状況です。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、現在の番号が前の番号のプレフィックスと正確に一致する場合に発生します。 例えば、`prev = 12345`そして`cur = 123`。 アルゴリズムはプレフィックス マッチング ブランチに入り、サフィックスの再利用を試みます。`"45"`。 もし`12345`この拡張子に比べてすでに大きすぎる場合、正しい修正は、長さ 5 を超えて 1 桁を追加することです。 これにより、次の場所に確実に移動できます。`1230000`、より大きいことが保証されています`12345`操作を最小限に抑えながら。 

別のケースは、すべての桁が`prev`接頭辞の後には 0 または 9 が続きます。 このような状況では、サフィックスを再利用しようとすると、等しいか超えられない可能性があり、アルゴリズムがフォールバックに強制的に移行し、追加の数字が追加されます。 10 進数の比較では長さを増やすだけで常に同順位を破るのに十分であるため、構造は依然として正確さを保証します。
