 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、それをいくつかの連続した部分に分割することを想像します。 各部分は、通常の左から右の意味を使用して 2 進数として解釈されます。これは、部分の左端の文字が 2 の最大累乗に寄与することを意味します。 

固定数の部分について、文字列を k 個のセグメントに分割すると、各セグメント化で k 個の整数が生成されます。 そのパーティションの値は、それらの k 整数のビット単位の XOR です。 1 から n までの考えられるすべての k について、k セグメントに分割するすべての方法で達成可能な最大の XOR 値と、その最大値を達成するための異なる分割の数 (固定定数を法とする) の 2 つのことが必要です。 

最後に、すべての結果を直接出力する代わりに、それらをすべての k にわたる 4 つの XOR ベースの要約に集約します。 

したがって、中心となる計算タスクは、1 つのパーティショニングを評価するだけではなく、カット数を変更するときに最適な XOR 動作がどのように進化するかを理解することです。 

文字列の長さが非常に大きくなり、パーティションを列挙することが不可能になる場合があります。 単一の k であっても、パーティションの数は指数関数的であるため、非常に小さな入力を超えると総当たり探索は直ちに不可能になります。 許容可能な解決策では、明示的に分割を列挙することを避け、代わりにバイナリ部分文字列の構造特性に依存する必要があります。 

重要な点は、セグメントが 1 位置移動すると部分文字列の値が重なり合うことです。 位置 i で終了する部分文字列の値は、i+1 に拡張するときに再利用できます。これは、エンドポイントまたは接頭辞の関係に対する動的プログラミングが、組み合わせ列挙よりも関連性があることを示唆しています。 

エッジケースは、文字列が均一であるか、極端に歪んでいる場合に発生します。 たとえば、文字列がすべてゼロの場合、k に関係なくすべてのパーティションで XOR ゼロが生成されるため、すべての最大値が崩れ、カウントが組み合わせ的に大きくなります。 文字列がすべて 1 の場合、すべての部分文字列値はその長さだけに依存し、異なるパーティションが非自明な方法で同一の XOR 結果を生成する可能性があります。 

別のエッジ ケースは、k が n に等しい場合に発生します。この場合、すべてのセグメントが単一の文字になります。 この場合、XOR 値は個々のビットの XOR として固定されるため、選択の余地はありませんが、カウントは依然として些細なパーティションの一意性に依存します。 

## アプローチ

 単純なアプローチでは、固定 k についてすべてのパーティションを直接評価しようとします。 n-1 個のギャップの中から k-1 個のカット位置を選択するたびに、セグメント値を計算し、XOR します。 単一のパーティション値を計算するには、最初から計算すると最悪の場合でも O(n) のコストがかかり、全体で O(2^n) 個のパーティションが存在します。 固定 k に制限しても、まだ O(n が k を選択) の可能性があり、これは中程度の n であっても大きすぎます。 

わずかに改良されたバージョンでは、プレフィックス ハッシュまたはプレフィックス 2 のべき乗を使用して、すべての部分文字列のバイナリ値が事前計算されます。 これにより、セグメント値の計算が O(1) に削減されますが、パーティションの組み合わせ爆発は解決されません。 支配的なコストは依然としてカット セットの列挙です。 

重要な観察点は、各パーティションがプレフィックス エンドポイントのグループを定義し、XOR 演算が分割に関して線形に相互作用することです。 セグメントの観点から考える代わりに、各ビット位置がカットされるか、隣接するビットとマージされるかに応じて、最終的な XOR にどのように寄与するかを考えることができます。 これにより、問題は組み合わせセグメンテーションから、すべての k にわたる個々の位置の寄与の追跡へと移行します。 

このように再定式化すると、構造はプレフィックスの長さとセグメント数に関する動的プログラミングに適したものになり、遷移は現在のセグメントを拡張するか新しいセグメントを開始するかによってのみ決まります。 バイナリの性質により、シフトと XOR を使用してセグメント値を増分更新できるため、再計算が回避されます。

これにより、問題は n 個の位置と k 個のセグメント数にわたる DP に縮小され、各状態が達成可能な最良の XOR とそれを達成するための方法の数を取得します。 トランジションは、位置 i にカットを配置するかどうかに基づいてローカルに行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パーティションに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | DP over プレフィックスとセグメント数 | 遷移に応じて O(n^2) または最適化された O(n log n) | O(n^2) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[i][k] が、k セグメントに分割された最初の i 文字を使用して可能な最良の XOR 値を表す DP テーブルを維持しながら、文字列を左から右に処理します。また、それを達成するための方法の数も記載されています。 

1. 空のプレフィックスには有効な分解が 1 つだけあるため、dp[0][0] を XOR 値 0 とカウント 1 のニュートラル状態として初期化します。 
2. 1 から n までの各位置 i について、i より小さいすべての可能な以前のカット位置 j を考慮します。 これはセグメント s[j+1:i] を定義します。 部分文字列を再スキャンしないように、事前に計算されたプレフィックス累乗を使用してバイナリ値を計算します。 
3. dp[j][k-1] からの有効な遷移ごとに、前の XOR と s[j+1:i] の値を組み合わせて候補 XOR を計算します。 この候補を dp[i][k] と比較します。 
4. 候補 XOR が dp[i][k] の現在の最適値よりも大きい場合、それを上書きしてカウントをリセットします。 等しい場合は、dp[j][k-1]からウェイの数を加算します。 
5. これを n までのすべての i と k に対して繰り返し、すべてのセグメント数がカバーされるようにします。 
6. テーブルに記入した後、dp[n][k] は各 k に対する答えを返します。 次に、すべての k に対して必要な集約 XOR 式 A、B、C、D を計算します。 

これが機能する理由は、dp[i][k] が i までのプレフィックスをカバーする正確に k 個の連続セグメントを使用して達成可能な最適な XOR を常に格納するという不変条件に基づいています。 すべての有効なパーティションは最後のカット j で終了する必要があり、トランジションはその最後のカットを正確に列挙します。 XOR は結合的であり、セグメント値が固定されると独立するため、計算値を超えるセグメント間の相互作用が失われることはありません。 DP は、最後のカット分解を通じてすべてのパーティションが正確に 1 回表現されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve(s):
    n = len(s)

    # prefix binary value: pref[i] = value of s[0:i]
    pref = [0] * (n + 1)
    for i, ch in enumerate(s, 1):
        pref[i] = (pref[i - 1] << 1) | (ch == '1')

    # dp[k][i] = (best_xor, count)
    dp = [[(-1, 0) for _ in range(n + 1)] for _ in range(n + 1)]
    dp[0][0] = (0, 1)

    def get_val(l, r):
        return pref[r] ^ (pref[l - 1] << (r - l + 1))

    for i in range(1, n + 1):
        for k in range(1, i + 1):
            best = -1
            cnt = 0
            for j in range(k - 1, i):
                prev_xor, ways = dp[k - 1][j]
                if ways == 0:
                    continue
                val = get_val(j + 1, i)
                cand = prev_xor ^ val
                if cand > best:
                    best = cand
                    cnt = ways
                elif cand == best:
                    cnt = (cnt + ways) % MOD
            dp[k][i] = (best, cnt)

    A = B = C = D = 0
    for k in range(1, n + 1):
        p, q = dp[k][n]
        p %= MOD
        q %= MOD
        A ^= p
        B ^= q
        C ^= (p * k)
        D ^= (q * k)

    print(A, B, C, D)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        s = input().strip()
        solve(s)
```プレフィックス配列にはすべてのプレフィックスの整数値が格納されるため、ビット シフトと XOR を使用して任意の部分文字列値を O(1) で再構築できます。 これにより、バイナリ変換を繰り返し再計算する必要がなくなります。 

DP テーブルは、セグメント数とプレフィックス長によってインデックスが付けられます。 以前のカット位置にわたる内側のループは重要な遷移であり、考えられる最後のセグメントがそれぞれテストされます。 実装では、有効な状態 dp[k-1][j] のみが寄与することが慎重に保証されます。 

よくある落とし穴は、バイナリ値を計算するときに部分文字列のインデックス付けを混同することです。 シフト量は正確なセグメント長と一致する必要があります。そうでない場合、異なるセグメントによって一貫性のない値が生成されます。 もう 1 つの微妙な問題は、最後の XOR 集計がモジュール式ではない一方で、カウントは 998244353 を法として取得する必要があることを忘れていることです。 

## 実用的な例

 短い文字列を考えてみましょう`110`。 

k = 1 の場合、セグメントは 1 つだけです。`110`これは 6 と評価されます。k = 2 の場合、次のように分割できます。`1 | 10`または`11 | 0`。 k = 3 の場合、単一文字の分割のみが存在します。 

dp[k][i] を概念的に追跡します。 

| 私 | k | ラストカットj | セグメント | これまでの XOR | 最高 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | 1 | 1 |
 | 2 | 1 | 0 | 11 | 3 | 3 |
 | 2 | 2 | 1 | 1 | 1 | 0 |
 | 3 | 2 | 1 | 1 | 10 | 2 |
 | 3 | 2 | 2 | 11 | 0 | 3 |

 このトレースは、異なるカット位置によって競合する XOR 値がどのように生成されるか、および dp がどのように最大値のみを保持するかを示します。 

k = 3 の場合、パーティションのみ`1|1|0`が存在し、XOR = 1 ^ 1 ^ 0 = 0 となります。有効な分解が 1 つだけ存在するため、DP はこの一意性を反映しています。 

これは、各状態がラストカット分解によって完全に決定され、誤って二重にカウントされるパーティションがないことを示しています。

## 特殊なケース

 次のようなすべてゼロの文字列の場合`000`、セグメンテーションに関係なく、すべての部分文字列は 0 と評価されます。 DP はゼロより大きい候補 XOR を決して観察しないため、すべての dp[k][n] はゼロで安定し、カウントはすべての有効なカット構造にわたって蓄積されます。 これにより、アルゴリズムが縮退値空間を正しく処理していることが確認されます。 

次のような完全に交互の文字列の場合`1010`、部分文字列の値は境界によって大きく異なります。 DP は各カット位置を明示的に評価するため、ローカル セグメントが 1 ビット異なる場合でも、XOR 遷移によってそれらの違いが正しく伝播されます。 これにより、セグメント間の隠れた依存関係が見逃されることがなくなります。
