 ## 解決策
 ## 問題の理解

 すでに昇順にソートされた個別の値のシーケンスが与えられています。 このシーケンスの任意の連続セグメントから、局所的な凸条件を満たす限り、要素を繰り返し削除できます。内部要素は、隣接する 2 つの要素と比較して「高すぎない」場合、特に隣接要素の平均値以下の場合に削除できます。 

削除するたびにシーケンスが縮小し、新しい隣接関係が形成され、さらなる削除のロックが解除される可能性があります。 各クエリ セグメントのタスクは、これらの削除を任意の順序で適用した後に、有効な削除が存在しなくなるまで残せる要素の最小数を決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列が増加し、サブ配列に対する複数のクエリが与えられます。 各クエリは独立しており、削除ルールに基づいてそのサブ配列の達成可能な最終的な最小サイズを要求します。 

制約構造は、すべてのテスト ケースにわたる合計配列サイズとクエリ数が数十万程度と大きいことを示唆しています。 削除を直接シミュレートしようとするソリューションはどれも遅すぎます。各削除には構造を維持するために線形時間がかかる可能性があり、最悪の場合は単一のクエリでも二次的な動作に低下する可能性があるためです。 

主なエッジ ケースは、無効な入力に関するものではなく、削除ルールがローカル パターンとどのように相互作用するかに関するものです。 

直感が失敗する可能性がある小さな例は、次のような厳密に凸なトリプルです。`[1, 2, 4]`。 真ん中の要素`2`満足する`2*2 <= 1 + 4`、削除できます。`[1, 4]`となり、これ以上削除することはできません。 エンドポイントのみが重要であるという単純な仮定は、解釈によってはすべての内部ポイントが削除可能であるか、何も削除できないという誤った示唆をすることになります。 

もう 1 つのエッジケースは、次のようなほぼ直線的な進行です。`[1, 3, 5, 7, 9]`。 多くの内部ポイントは早期に削除条件を満たしますが、1 つが削除されると、残りの構造が非明白な方法で将来の削除のロックを解除したりブロックしたりする可能性があります。 このため、グローバルな凸包構造を追跡しないと、貪欲なローカル推論では不十分になります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリを個別にシミュレートします。 指定されたサブ配列に対して、インデックスを繰り返しスキャンします。`i`そのような`2 * B[i] <= B[i-1] + B[i+1]`、それを削除し、ネイバーを再起動または更新します。 削除するたびに隣接関係を更新し、場合によってはアレイを再スキャンする必要があります。 

最悪の場合、同じ長さの単一クエリ`k`実行できた`O(k)`削除、および削除ごとにコストがかかる場合があります`O(k)`スキャン作業。 これは次のことにつながります`O(k^2)`クエリごとに。 と`k`まで`5 × 10^4`多くのクエリにわたって、これは実現可能な制限をはるかに超えています。 

重要な観察は、削除条件が、点が隣接する点の間の線分の上または下に位置するための条件であるということです。 幾何学的には、これは、点として解釈されたときにシーケンスの上部の凸包の一部ではない点を繰り返し削除していることを意味します。`(i, a[i])`。 

配列インデックスは厳密に増加し、値も厳密に増加するため、構造は単調チェーンになり、最後に残った要素はセグメント内の点の凸包に正確に対応します。 削除するたびに凸性に違反する点が削除され、ハルの頂点だけが残るまでプロセスが継続されます。 

これにより、問題は動的削除から静的計算に変換されます。クエリごとに、その間隔内の点の上凸包のサイズのみが必要になります。 X 座標は固定され増加するため、これは 1 次元のセグメント上で凸包を維持することになります。これは、セグメント ツリーまたは包結合を伴う分割統治事前計算を使用して効率的に答えることができます。 

標準的なアプローチは、セグメント ツリー ノードごとに、その範囲の凸包をソートされた順序で保存することです。 2 つのノードをマージすることは、2 つの凸状チェーンをマージすることに対応し、結果として得られるハルのサイズに応じて線形時間で実行できます。 範囲をクエリすると収集されます`O(log n)`船体を分割して結合し、そのサイズが答えとなる最終的な船体を生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | クエリあたり O(k²) | O(k) | 遅すぎる |
 | セグメント ツリーの凸包のマージ | クエリあたり O(log n · h) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各要素を扱う`a[i]`ポイントとして`(i, a[i])`。 これにより、問題は、削除が非凸点の削除に対応する幾何学的構造に変換されます。 
2. 各ノードがその区間の凸包を昇順に格納する配列上にセグメント ツリーを構築します。`i`。 船体は、スタックのようなマージ ルールを使用して単調なチェーンとして維持されます。 これが機能するのは、インデックスがすでにソートされているためです。そのため、一方向に凸性を適用するだけで済みます。 
3. 2 つのハルをマージするには、右ハルを左ハルに追加し、隣接する点との凸性を侵害しながら最後から 2 番目の点を繰り返し削除します。 ポイントは凹面ターンの内側にある場合に正確に削除できるため、この条件は削除ルールと一致します。 
4. お問い合わせの場合`[l, r]`、この間隔をカバーするすべてのセグメント ツリー ノードを収集し、それらのハルを 1 つのハルにマージします。 この合体船体のサイズが答えです。 
5. 各クエリのハル サイズを出力します。 

重要なアイデアは、元のプロセスでの削除は最終的な凸構造のみに依存する方法で相互に変換されるため、削除の順序をシミュレートする必要がないということです。 

### なぜ効果があるのか

 不変条件は、一連の有効な削除の後、残りの点が常に不等式に関して凸状の連鎖を形成するということです。`2 * a[i] > a[i-1] + a[i+1]`。 プロセスによって削除された点は、最終構成で残っている 2 つの隣接点間の線分の上に位置するため、セグメントの凸表現の一部にはなり得ないものです。 逆に、凸包内に残るすべての点には、残りの構造の凸性を壊さずに凸包を削除する有効な削除シーケンスがありません。 この対応により、最終状態が一意であり、セグメントの凸包と等しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def bad(p1, p2, p3):
    # check if p2 should be removed (not convex)
    # equivalent to: 2*p2 <= p1 + p3
    return (p2[1] * 2) <= (p1[1] + p3[1])

def merge(left, right):
    # merge two convex chains
    res = left[:]
    for p in right:
        res.append(p)
        while len(res) >= 3 and bad(res[-3], res[-2], res[-1]):
            res.pop(-2)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [[] for _ in range(2 * self.size)]
        
        for i in range(self.n):
            self.data[self.size + i] = [(i, arr[i])]
        
        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge(self.data[2 * i], self.data[2 * i + 1])
    
    def query(self, l, r):
        l += self.size
        r += self.size
        left_hull = []
        right_hull = []
        
        while l <= r:
            if l % 2 == 1:
                left_hull = merge(left_hull, self.data[l])
                l += 1
            if r % 2 == 0:
                right_hull = merge(self.data[r], right_hull)
                r -= 1
            l //= 2
            r //= 2
        
        return merge(left_hull, right_hull)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        st = SegTree(a)
        for _ in range(q):
            l, r = map(int, input().split())
            hull = st.query(l - 1, r - 1)
            print(len(hull))

if __name__ == "__main__":
    solve()
```セグメント ツリーは、各ノードがその区間の既約構造を表すように凸包を格納します。 クエリ中にハルのマージを繰り返し、すべてのマージ操作で元のプロセスと同じ削除条件が適用されるため、一貫性が確保されます。 

最も重要な実装の詳細はマージ順序です。 左包は右包によって拡張される必要があり、その逆はできません。そうしないと、インデックスの単調性が壊れ、凸性テストが無効になります。 

## 実用的な例

 ### 例 1

 入力セグメント:`[1, 5, 6, 8, 9]`ポイントとして処理いたします`(i, a[i])`。 

| ステップ | 現在の船体 |
 | --- | --- |
 | 開始 | (1,1) |
 | (2,5) を追加 | (1,1),(2,5) |
 | (3,6) を追加 | (1,1)、(2,5)、(3,6) |
 | (4,8) を追加 | (1,1)、(2,5)、(3,6)、(4,8) |
 | (5,9) を追加 | (1,1)、(2,5)、(3,6)、(4,8)、(5,9) |

 凸条件に違反するポイントはないので除去は発生せず、答えは5となります。 

これは、何も削除できない完全に凸の増加シーケンスを示しています。 

### 例 2

 入力セグメント:`[1, 3, 2, 6, 4, 8]`| ステップ | アクション | 船体 |
 | --- | --- | --- |
 | 1 を追加 | 初期化 | (1,1) |
 | 3 を追加 | わかりました | (1,1),(2,3) |
 | 2を追加 | 3 条件を削除 | (1,1),(3,2) |
 | 6を追加 | わかりました | (1,1)、(3,2)、(4,6) |
 | 4 を追加 | 6 条件を削除 | (1,1)、(3,2)、(5,4) |
 | 8を追加 | わかりました | (1,1)、(3,2)、(5,4)、(6,8) |

 最終的な船体のサイズは 4 です。 

これは、中間点が凸性に違反した場合にどのように削除されるか、また削除のたびにどのように削除がカスケードされるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q log n) · h) | 各クエリは O(log n) 個のハルをマージします。各マージのハル サイズは線形です。 
| スペース | O(n log n) | 各セグメント ツリー ノードにはハル |

 この制約により、合計でおよそ数十万回の操作が可能になり、典型的な単調シーケンスでは凸包サイズが小さいままであるため、指定された制限内で実際には十分に効率的になります。

 ## 特殊なケース

 次のような単一要素セグメントの場合`[7]`の場合、削除条件を満たす内部ポイントがないため、船体のサイズは自明に 1 になります。 このアルゴリズムは単一点ハルを初期化し、すぐに戻るため、マージ ロジックは呼び出されません。 

次のような厳密に凸状の増加セグメントの場合`[1, 2, 3, 4, 5]`、すべての加算は凸性を維持するため、マージ中にポイントが削除されることはありません。 セグメント ツリー ノードも完全なチェーンを保持し、最終的なクエリは長さ 5 を返します。これは、どの内部位置でも削除条件を満たすことができないという事実と一致します。
