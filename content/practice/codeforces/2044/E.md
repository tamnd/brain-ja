 ## 解決策
 ## 問題の理解

 整数のペアの数を数えるように求められます$(x, y)$2 つの間隔制約と幾何学的関係を満たします。 具体的には、$x$間隔内になければなりません$[l_1, r_1]$、$y$に横たわらなければなりません$[l_2, r_2]$、 そして$y / x$の整数乗でなければなりません$k$。 ここ、$k$は少なくとも 2 であるため、繰り返し乗算によって増加を処理します。 各テスト ケースは独立しており、最大で$10^4$テストケース。 間隔と$k$と同じ大きさにすることができます$10^9$したがって、すべてのペアを単純に列挙することは明らかに非実用的です。 

明らかではない部分は、指数関数的な成長条件です。 単純な解決策では、あらゆることを試してしまう可能性があります。$x$で$[l_1, r_1]$そしてすべての$y$で$[l_2, r_2]$かどうかを確認してください$y / x$の力です$k$。 これは次の順序で実行されます$10^{18}$最悪の場合の操作ですが、これはまったく実行不可能です。 別の微妙な問題が発生する場合、$k$が大きいか、間隔が非常に狭いです。 たとえば、$k = 10^9$そして$x = 1$、$y = 10^9$は有効ですが、すべての中間累乗を列挙する必要はありません。 

小さな例から落とし穴が明らかになります。 もし$l_1 = r_1 = 1$そして$l_2 = r_2 = 1$、唯一の有効なペアは$(1,1)$。 不注意なアプローチでは、複数のペアが存在すると想定される可能性があります。 もし$k$が非常に大きい場合、唯一の有効な指数は 0 である可能性があり、アルゴリズムが区間内に複数の累乗が収まると仮定している場合、これを簡単に見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチはすべての攻撃に対して繰り返されます。$x$で$[l_1, r_1]$そして次の力を生成します$k$から始まる$x$結果がそれを超えるまで$r_2$。 For each power, we check if it falls in$[l_2, r_2]$そしてそれを数えます。 これは正しく動作しますが、遅すぎます。$x$値は最大です$10^9$それぞれが最大で生成する可能性があります$\log_k r_2$権力。 これはおおよそ次のことにつながります$10^9 \cdot 30 \approx 3 \cdot 10^{10}$実行可能性をはるかに超えた操作。 

重要な洞察は、次のような関係です。$y = x \cdot k^n$修正できるようになります$n$の代わりに$x$。 それぞれについて$n \ge 0$、可能性のある$x$満足する$l_1 \le x \le r_1$そして$l_2 / k^n \le x \le r_2 / k^n$。 これは、間隔内の整数をカウントすることになります。$[\max(l_1, \lceil l_2 / k^n \rceil), \min(r_1, \lfloor r_2 / k^n \rfloor)]$。 繰り返しをやめることができます$n$いつ$x_{\text{min}} > x_{\text{max}}$より大きな力は増大するだけだから$x_{\text{min}}$。 このアプローチにより、複雑さ、つまり指数の数が大幅に軽減されます。$n$せいぜい$\log_k r_2 \le 60$、これは多くのテストケースでも実現可能です。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$k$、$l_1$、$r_1$、$l_2$、$r_2$。 
2. カウンタの初期化`ans = 0`。 これにより、有効なペアの合計数が保存されます。 
3.セット`power = 1`そして`n = 0`。 これは、$k^n$。 から始める$k^0 = 1$。 
4. ながら`power <= r_2`、次の操作を行います。 

ａ． コンピューティング`x_min = max(l_1, (l_2 + power - 1) // power)`。 これにより、$x \cdot k^n \ge l_2$。 

b. コンピューティング`x_max = min(r_1, r_2 // power)`。 これにより、$x \cdot k^n \le r_2$。 

c. もし`x_min <= x_max`、増分`ans`による`x_max - x_min + 1`。 

d. もし`power > r_2 // k`、 壊す。 乗算$k$また溢れてしまうだろう$r_2$。 

e. それ以外の場合は乗算します`power *= k`そして増加します`n`。 
5. 印刷`ans`各テストケースの終了後。 

それが機能する理由: 不変条件は、次の各べき乗に対して次のとおりです。$k$、すべて数えます$x$間隔の交差点で$[l_1, r_1]$そしてスケーリングされた間隔$[l_2 / k^n, r_2 / k^n]$。 可能な限りあらゆることを体系的に反復します$k^n$を生み出すことができます$y$で$[l_2, r_2]$。 それぞれのペアが重複してカウントされることはありません。$n$は明確であり、その間隔は実現可能なすべてを正確に捕捉します$x$そのために$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k, l1, r1, l2, r2 = map(int, input().split())
        ans = 0
        power = 1
        while power <= r2:
            x_min = max(l1, (l2 + power - 1) // power)
            x_max = min(r1, r2 // power)
            if x_min <= x_max:
                ans += x_max - x_min + 1
            if power > r2 // k:
                break
            power *= k
        print(ans)

if __name__ == "__main__":
    solve()
```初期化する`power = 1`表す$k^0$。 の計算`x_min`整数の上限除算を使用して下限を保証します。`x_max`上限内に収まるようにフロア分割を使用します。 ブレーク条件はオーバーフローを回避します。これは次の場合に非常に重要です。`k`とても大きいです。 ブレークの前に乗算すると、問題の制約で許可される最大整数を超える危険があります。
