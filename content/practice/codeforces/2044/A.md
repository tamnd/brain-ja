 ## 解決策
 ## 問題の理解

 正の整数の順序ペアを数えるように求められます$(a, b)$そのような$a + b = n$、複数のテスト ケースの場合。 各テスト ケースは単一の整数を与えます$n$、そしてペアの合計数を出力する必要があります$(a, b)$that satisfy the equation. 重要なのは、両方とも$a$そして$b$厳密に正である必要があります。 

制約は小さいです。$2 \le n \le 100$最大 99 個のテスト ケース。 なぜなら$n$が最大 100 の場合、テスト ケースごとに線形時間で実行されるソリューションは完全に許容されます。 単純なアプローチでも十分に高速ですが、それでも閉じた形式の公式について推論することができます。 

可能な限り最小の$n$は 2 です。その場合、ペアは 2 つだけです。$(1,1)$。 解が正の要件を無視し、ゼロまたは負の数を数える場合、不正確な答えが生成されます。 同様に、アルゴリズムが対称ペアを二重にカウントしたり、境界値を誤ってカウントした場合、$n=2$または$n=100$、それは間違いでしょう。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての値を反復処理します。$a$1から$n-1$そしてペアを数えます。$b = n - a$はポジティブです。 これが機能する理由は、$b$によって一意に決定されます$a$、 そして$a$決して到達できない$n$それ以来$b$ゼロになります。 ブルートフォースの解決策は正しいですが、このような小さな問題に対しては不必要に冗長になります。 

重要な洞察は、与えられた条件に対して、$n$、すべてのペアは次の形式になります。$(1, n-1), (2, n-2), ..., (n-1, 1)$。 それぞれ$a$1から$n-1$有効な結果を生成します$b$したがって、ペアの数は単純に次のようになります。$n-1$。 これは閉じた形式のソリューションであり、ループを完全に排除します。これは最も単純で直接的なアプローチです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n) | お(1) | n | が小さいため受け入れられました。 
| クローズドフォーム | テスト ケースごとに O(1) | お(1) | 受け入れられており、最も単純です |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 これにより、計算を繰り返す回数が決まります。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 これは、2 つの正の整数に分割したい合計です。 
3. 有効なペアの数を次のように計算します。$n-1$。 これは、ペアが正確に一致するため機能します。$(1, n-1), (2, n-2), ..., (n-1, 1)$、そして、あります$n-1$条項。 
4. 結果をすぐに印刷するか、すべてのテスト ケースの後に印刷するためにリストに保存します。 

なぜ機能するのか: 不変条件はすべての整数に対して$a$1 ～ の範囲で$n-1$、$b = n - a$自動的にプラスになります。 値がスキップされたり二重にカウントされたりすることはなく、考えられるすべてのペアが考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(n - 1)
```このソリューションは、まずテスト ケースの数を読み取ります。 各テスト ケースについて、次のようになります。$n$そしてプリント$n-1$。 使用する`sys.stdin.readline`入力サイズが小さい場合でも、高速な入力処理が保証されます。 追加のデータ構造は必要ありません。 減算は有効なものをすべて処理します$n \ge 2$自動的にオフバイワンエラーを回避します。 

## 実用的な例

 トレースサンプル 1 入力`3\n2\n4\n6\n`:

 | テストケース | n | 計算 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 - 1 | 1 |
 | 2 | 4 | 4-1 | 3 |
 | 3 | 6 | 6 - 1 | 5 |

 表は、それぞれについて、$n$、1 を減算すると、すべての有効なペアが正しくカウントされます。 のために$n=2$、 のみ$(1,1)$存在します。 のために$n=4$、ペア$(1,3),(2,2),(3,1)$合計は 4 になり、3 つのペアが得られます。

 与えられた$t \le 99$そして$n \le 100$、この解決策は最新のハードウェアで瞬時に実行され、メモリ制限内で十分に有効です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        output.append(str(n-1))
    return "\n".join(output)

# Provided samples
assert run("3\n2\n4\n6\n") == "1\n3\n5", "sample 1"

# Custom cases
assert run("1\n2\n") == "1", "minimum n"
assert run("1\n100\n") == "99", "maximum n"
assert run("2\n3\n5\n") == "2\n4", "small n, odd and even"
assert run("1\n50\n") == "49", "mid-range n"
assert run("1\n99\n") == "98", "odd n near max"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n2\n | 1 | n の最小値 |
 | 1\n100\n | 99 | n の最大値 |
 | 2\n3\n5\n | 2\n4 | 小さい n、奇数と偶数の混合 |
 | 1\n50\n | 49 | ミッドレンジ n |

 ## 特殊なケース

 エッジケースには、$n=2$正しく処理されます。 アルゴリズムは計算します$2-1=1$、単一のペアを与える$(1,1)$。 最大のエッジケース$n=100$生成する$99$、これは正確に次の数です。$(1,99),(2,98),...,(99,1)$。 ループは必要ないため、このソリューションでは off-by-one エラーが完全に回避されます。 積極性の要件は自然に強制されます。$a$1から始まり、最大まで$n-1$。
