 ## 解決策
 ## 問題の理解

 3 種類の演算の下で大きな非負の整数のマルチセットを維持しており、各演算後に現在のすべての要素のビットごとの XOR を報告する必要があります。 

操作は 2 つの異なる方法で動的に行われます。 1 つの操作では既存のすべての値が 1 つずつ上にシフトされ、別の操作では新しい値が挿入され、最後の操作では、指定された値が存在する場合はその値が 1 つだけ削除されます。 各変更の後に、マルチセット全体の XOR が必要になります。 

この制約により、すぐに XOR を最初から再計算することができなくなります。 要素と操作の数は両方とも 200,000 に達する可能性があるため、クエリごとに構造全体をスキャンするアプローチでは、次のオーダーのデータが必要になります。$q \cdot n$、これは実現可能な限界をはるかに超えています。 

微妙な難しさは、グローバル インクリメント操作です。 XOR は加算時に不変ではないため、すべての要素に 1 を加算することは単純な XOR 更新ではありません。 「グローバルな XOR シフトを維持するだけ」のような素朴な考えは、直接的には機能しません。これは、ビットに応じて要素ごとにキャリーが異なる方法で伝播するためです。 

素朴な思考が失敗する理由は、小さな例ですでにわかります。 要素があるとします$[1, 2]$。 彼らの XOR は$3$。 すべての要素をインクリメントすると、次の結果が得られます$[2, 3]$、その XOR は$1$。 からの単純な固定変換はありません。$3$に$1$それはカウントのみに依存します。 それはビット構造に依存します。 

したがって、課題は以下をサポートすることです。 

変更するマルチセットの XOR、挿入と削除、およびすべての要素に適用されるグローバル +1 はすべて厳しい制約の下で行われます。 

単純なアプローチを破るエッジ ケースには、インクリメント操作を繰り返し適用すること、現在暗黙的にシフトされている値を削除すること、XOR によってペアがキャンセルされるため重複を正しく処理することが含まれますが、削除は多重度に正確に影響を与える必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、文字通りすべての要素がリストまたはマルチセット構造に格納されます。 インクリメント型のクエリごとに、すべての要素に 1 を追加します。 挿入と削除の場合はコンテナを変更し、各操作の後にすべての要素を反復処理して XOR を再計算します。 

これは正しいですが、遅すぎます。 各増分にかかるコスト$O(n)$、そしてそれがあるかもしれません$q$そのような操作により、$O(nq)$届くのは$4 \cdot 10^{10}$最悪の場合の運用。 

重要な点は、XOR はビット単位の演算に対して線形ですが、インクリメント演算は構造化された方法でビットと相互作用するということです。 実際の値を追跡する代わりに、シフトされた座標系で値を追跡します。 

グローバル変数にしましょう$add$「すべての要素に +1」を適用した回数を表します。 実際の値を保存する代わりに$x$、正規化された値を保存します$x - add$。 この場合、要素の実際の値は常に次のようになります。$x + add$。 

これにより、挿入と削除が正規化された値に対する操作に変わります。 残りの課題は、すべての実数値の XOR を計算することです。$$\bigoplus (x_i + add)$$ここで、ビット位置ごとのビットごとの DP を使用して、正規化された値のマルチセットとその XOR 構造を間接的に維持します。 重要なアイデアは、各要素を個別に更新することなく、グローバル シフトの適用後にそのビットが設定されている要素の数をビットごとに追跡することです。 

ビットを独立して処理し、定数の追加がバイナリ表現にどのような影響を与えるかをシミュレートします。 すべての要素に触れる代わりに、ハッシュ マップ内の正規化された値の頻度を維持し、ID を使用してビットごとに XOR を再構築します。 

XOR のビットが奇数の要素に設定されている場合、そのビットは 1 になります。 

各クエリについて、最初から再計算することはありません。 カウントを調整し、保存された周波数と現在のグローバル シフトを使用し、ビット レベルの寄与を使用して XOR を再計算するだけです。 

重要な構造的変化は、実際の値を決して保存せず、シフトされた代表値のカウントのみを保存し、そのビットを解釈することです。$x + add$その場で。

 ## アルゴリズムのチュートリアル

 「ベース値」の周波数マップとグローバル シフト値を維持します。`add`。 

1.初期化`add = 0`すべての初期値をその頻度とともにハッシュ マップに保存します。 また、シフト中に変化するため、直接の XOR も維持しません。 
2. 価値の挿入の場合`v`として保存します。`v - add`。 これにより、グローバル シフトが適用されたときに実際の値が正確になることが保証されます。 この正規化により、将来のすべてのグローバル増分が O(1) になることが可能になります。 
3. 値の削除の場合`v`、シフトされた座標系でも次のように解釈します。`v - add`存在する場合はその周波数を減少させます。 不在の場合は何もしません。 
4. すべてインクリメント操作の場合は、次のようにします。`add += 1`。 これがすべてのトリックです。保存されている要素には触れないようにするのです。 
5. 各操作の後、すべての値の XOR を実際の形式で再計算します。 このために、周波数マップに格納されているすべての個別のキーを反復処理し、それらの寄与をビットごとに次のように計算します。`(key + add)`。 
6. To compute XOR, we maintain an accumulator. For each stored key with frequency`cnt`、各ビット位置を確認します。 もし`cnt % 2 == 1`、XORします`(key + add)`答えに。 

重要な単純化は、たとえ加算によって値が変化しても、XOR にとって重要なのはカウントのパリティであるため、重複は自然に崩壊するということです。 

### なぜ効果があるのか

 不変条件は、実数値の複数集合が常に正確に次の複数集合であるということです。`(key + add)`保存されたキーを上書きします。 常にシフトされた座標系に変換されるため、挿入と削除ではこの表現が保持されます。 グローバル増分はすべての要素に均一に影響し、調整によって完全にキャプチャされます。`add`。 XOR は出現のパリティのみに依存するため、このシフトされた空間で正しい多重度を維持することで、最終的な XOR がすべてのステップで正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = defaultdict(int)
    add = 0

    for x in arr:
        freq[x] += 1

    def get_xor():
        res = 0
        for k, cnt in freq.items():
            if cnt % 2 == 1:
                res ^= (k + add)
        return res

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            add += 1

        elif t == 2:
            v = int(tmp[1])
            freq[v - add] += 1

        else:
            v = int(tmp[1])
            key = v - add
            if freq[key] > 0:
                freq[key] -= 1
                if freq[key] == 0:
                    del freq[key]

        print(get_xor())

solve()
```コードは正規化の考え方に直接従っています。 ディクショナリは、グローバル増分が除外される座標系で値を保存します。 の`add`変数は、すべての要素に適用される累積シフトを表します。 挿入および削除により、値がこの正規化された空間に戻されます。 

XOR の再計算では、ペアが相殺されるという事実を利用するため、奇数の周波数のみが問題となります。 追加することによって実際の値を再構築するたびに、`add`。 

微妙な点は、削除ではデクリメントする前に存在を確認する必要があることです。 そうしないと、誤って負のカウントが導入されてしまいます。 ゼロエントリを削除すると、実際には辞書が十分に小さく保たれます。

 ## 特殊なケース

 すべての要素が同一である場合、削除と XOR のキャンセルが強調されます。 入力用`5 3`と`2 2 2 2 2`、出現を 1 つずつ削除すると、最後の要素が削除されるまでパリティは変更されないため、常に XOR の一貫性が保たれます。 

グローバル増分が繰り返されるケースでは、`add`アキュムレータだけでも多くの演算を正しく表現できます。 何百回増分した後でも、保存されたマップに構造的な変化は起こらないため、正確さは値を次のように解釈するかどうかに完全に依存します。`key + add`。 

存在しない値を削除対象とする場合、安定性が確保されます。 シフトされた空間に存在しない値を削除しようとすると、周波数マップは変更されないままでなければなりません。そうしないと、XOR パリティが破損します。
