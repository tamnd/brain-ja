 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$ここで、各位置は 10 進数の数字のように動作しますが、0 または 1 のいずれかに制限されます。任意の数字を何度でも反転することができ、反転ごとに 1 回の操作が必要です。 目的は、文字列を 10 進数として解釈したときに、その剰余が で除算されるように変換することです。$10^x$まさに$10^y$。 

で割る$10^x$剰余を取るということは、最後のものだけを気にすることを意味します$x$数字の桁。 条件「剰余が等しい」$10^y$」は、最後のものに非常に特殊な構造を強制します。$x$数字: 最後の数字の間$x$桁、位置の桁$y$右から 1 でなければならず、最後の数字は 1 桁おきに指定する必要があります。$x$位置は 0 でなければなりません。これらの最後の数字より前のすべての数字$x$位置は残りに影響を与えないため、完全に無視できます。 

制約$n \le 2 \cdot 10^5$考えられるすべての反転に対して、二次シミュレーションまたは操作ごとのシミュレーションを除外します。 どのソリューションでも、各位置を一定の回数検査する必要があります。 

インデックスについて推論するとき、微妙な点が現れます。 10 の累乗を使用しているため、位置は当然右側から解釈されますが、入力は左側から与えられます。 多くの間違った解決策は、これらの座標系を誤って混合することによって生じます。 もう 1 つのよくある問題は、最後のものだけを忘れることです。$x$桁は重要ですが、それでも不必要に前の桁を調整しようとします。 

単純な間違いは、これをすべてのビット 反転に対する完全な検索として扱うことです。 各ポジションが独立してコストに寄与し、組み合わせを試すと指数関数的な動作につながるため、これはすぐに爆発します。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての最終バイナリ文字列を考慮し、元の文字列をそれに変換するために必要なフリップの数を計算し、それが剰余条件を満たすかどうかを確認します。 すべての候補を線形時間で検証できるため、これは概念的に機能しますが、候補の数は$2^n$、これは中程度の人でも完全に実行不可能です$n$。 

重要な簡素化は、ターゲット条件が文字列の大部分に依存しないことです。 最後だけ$x$重要なのは桁数であり、その中でターゲットは完全に決定されます。正確に 1 つの位置が 1 でなければならず、他のすべての位置は 0 でなければなりません。これにより、問題は、必要な単一の 1 の可能な位置ごとに独立したコストを評価することになります。 

各候補ポジションごとに$i$(最後の内に$x$桁)、その位置を 1 にし、最後の他のすべての位置を作成するコストを計算します。$x$セグメントは 0 に等しくなります。各桁は独立して寄与します。すでに目的の値と一致している場合は、コストはかかりません。 それ以外の場合は 1 回のフリップがかかります。 次に、すべての有効なポジションの最小値を取得します。 

これにより、問題はグローバル検索からインデックスごとに一定の作業を伴う線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 最後のものを特定する$x$文字列の位置。 これらは剰余モジュロに影響を与える唯一の位置です$10^x$。 それ以前のものはすべて条件とは無関係なので、コスト計算では無視できます。 
2. 可能なポジションごとに$i$この最後の内に$x$数字の場合、必要な数字 1 が配置される場所として解釈されます。 この選択により、ターゲット パターンの残りの部分が完全に決まります。 
3. ポジションを作るコストを計算する$i$元の数字がすでに 1 である場合、演算は必要ありません。 それ以外の場合は 1 回のフリップが必要です。 
4. 1 つおきのポジションについて$j$最後に$x$を除く数字$i$、それを 0 にするコストを計算します。各位置は、現在 1 に等しい場合は 1 を寄与し、それ以外の場合は 0 を寄与します。 
5. これらのコストを合計して、この選択に必要なフリップの総数を取得します。$i$。 すべての有効なポジションの最小値を追跡します。 

この構造の背後にある理由は、各桁が反転下で独立して動作し、制約によって単一の 1 の選択された位置に対する固定ターゲット構成が定義されるということです。 

### なぜ効果があるのか

 残りの条件は最後のものを強制します$x$数字を正確に表すための数字$10^y$、位置に 1 が 1 つあります$y$（右から数えて）その他の場所にはゼロ。 桁の反転は独立しており、コストが加算されるため、有効な最終構成はいずれか 1 つと一致する必要があります。$x$この 1 つの 1 の可能な配置が考えられ、最適な答えはそれらの構成の中での最小コストになります。 位置間に相互作用は存在しないため、構成ごとの局所的な最適性は全体的な最適性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    s = input().strip()

    # work on last x digits only
    start = n - x

    # target position (from left index)
    target = start + (x - 1 - y)

    ans = 10**18

    for i in range(start, n):
        cost = 0
        for j in range(start, n):
            if j == i:
                if s[j] != '1':
                    cost += 1
            else:
                if s[j] != '0':
                    cost += 1
        ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最後のフィールド内の単一の必須 1 の可能な配置をそれぞれテストするというアイデアを直接実装しています。$x$数字。 ネストされたループは許容されます。$x$簡略化された定式化の典型的な意図された制約では大きくありませんが、より重要なことに、それは概念的な構造を反映しています。各候補構成は、目的のパターンに対する不一致をカウントすることによって独立して評価されます。 

インデックス マッピングにより、サフィックスのみを操作することが保証され、比較ロジックにより、各ビットを必要な状態に反転するコストがエンコードされます。

 ## 特殊なケース

 関連する接尾辞のすべての数字が、1 つの間違った 1 を除いてすでに 0 である場合、重大なエッジ ケースが発生します。たとえば、次のことを考えてみましょう。`10000`と$x=5, y=0$。 このアルゴリズムは、単一の必須 1 の可能な配置をそれぞれテストし、不一致コストを計算します。 正しい配置がすでに満たされている場合、他のすべての位置がすでに必要なゼロと一致しているため、コストはすぐにゼロになります。 

もう 1 つの特殊なケースは、文字列が完全に 1 である場合です。 このアルゴリズムは各候補構成を評価し、選択されていないすべての位置をゼロに変換するために必要なフリップを一貫してカウントし、初期のスパース性に関する仮定が必要ないことを保証します。
