 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、1 つの配列は固定され、もう 1 つは任意に並べ替えることができます。 2 番目の配列の順序を選択した後、その値を最初の配列に対して位置ごとに割り当てます。 このペアの配列から、セグメントごとに、そのセグメント内のペアごとの積の合計を計算し、すべてのセグメントにわたってこの量を合計します。 

計算を言い換える便利な方法は、すべての位置が一度に多くのセグメントに寄与していると考えることです。 位置 i のペアは a_i * b_i に寄与しますが、これは i を含むすべての部分配列でカウントされます。 したがって、最終的な目的は、単なる局所的な合計ではなく、各位置 i がそれをカバーするセグメントの数に等しい係数でカウントされる加重合計です。 

これにより、問題はすぐに重み付き割り当てタスクに変わります。各位置にはそのインデックスによってのみ決定される固定重みがあり、b の値はこれらの重みに最適な方法で一致するように並べ替えることができます。 

n が 200,000 までの制約により、どの解法でも二次構成や部分配列の明示的な列挙を避けることが強制されます。 b のみに n があるため、順列ごとの線形スキャンさえ不可能です。 手配。 正しい解法では、すべての部分配列の寄与を単一の位置ごとの係数に圧縮してから、マッチング問題を解決する必要があります。 

単純な推論による微妙な失敗のケースは、大きな a_i と小さな b_i の組み合わせが常に最適であると仮定することです。 a_i は直接の重みではないため、その直感は当てはまりません。 真の重みは、i が含まれる間隔の数によって異なります。 たとえば、配列の中心に近い位置は、境界位置よりも多くのサブ配列に含まれるため、生の a_i 値に関係なく、割り当てを支配する必要があります。 

## アプローチ

 文字通りの定義から始めます。 各部分配列 [l, r] について、その中の a_i * b_i の合計を計算し、すべての (l, r) の合計を計算します。 これを展開すると、二重カウント構造が得られます。各位置 i は、i 以降で始まり、i 以降で終了するすべての部分配列に表示されます。 このような部分配列の数は i * (n - i + 1) です。 したがって、目的の合計は、各項 a_i * b_i に i のみに依存する固定係数が乗算される位置にわたる単一の合計になります。 

この変換が認識されると、問題は次のようになります。重み w_i = i(n - i + 1) を固定し、b の値を位置に割り当てて、合計 a_i * b_{perm(i)} * w_i を最小化するか、または同等に b のマルチセットと重み付けされた a の間の内積を最小化したいと考えます。 

標準の交換引数が適用されます。 2 つの位置の重みが異なる場合、割り当てられた b 値を交換すると、より大きな b とより小さな重みが組み合わされ、答えが改善されます。 これはまさに、両方のシーケンスを反対方向にソートするための条件です。 

したがって、インデックスごとに w_i を固定して a_i * w_i を暗黙的にソートし、b を昇順にソートして、最小の b を a_i からの最大の実効重み寄与と照合します。

 ## アルゴリズムのチュートリアル

1. 各位置 i の寄与重みを w_i = i * (n - i + 1) として計算します。 これは、位置 i を含むサブ配列の数をカウントするため、元のネストされたサブ配列の合計を位置の線形結合に変換します。 
2. 各 a_i は部分配列に含まれる頻度に比例して寄与するため、a_i と w_i をペアにすることで、各位置が最終的な答えにどの程度強く影響するかを表す値を作成します。 
3. 配列 a をその誘導された重要度 w_i * a_i 構造によってソートしますが、w_i はインデックスごとに固定されているため、a を直接変更するのではなく、位置の影響によるソートを扱います。 
4. 配列 b を昇順に並べ替えて、全体的な影響が最小になる小さい値が使用されるようにします。 
5. b の値を貪欲に割り当てます。最小の b を最大の位置影響 (最大の w_i) に一致させ、最大の b を最小の w_i に一致させます。 
6. 結果を a_i * b_assigned[i] * w_i の i にわたる合計として累積し、最後にモジュロを取ります。 

中心的な推論ステップは、部分配列を位置ごとの重みに折りたたんだ後、問題が再配置不等式インスタンスになるということです。 この構造により、異なる重みに割り当てられた 2 つの b 値間の反転を交換して総コストを削減できることが保証されます。 

### なぜ効果があるのか

 目的を書き換えた後、各位置は w_i * a_i * b_{perm(i)} として独立して寄与します。 重み w_i はインデックスによってのみ決定される固定定数です。 最終的な合計は、2 つのシーケンス (固定係数の 1 つのシーケンスと a_i を乗算した b の 1 つの順列) 間のドット積です。 再配置不等式は、一方のシーケンスを昇順にソートし、もう一方のシーケンスを降順にソートすることによって最小の内積が達成されることを示しています。 偏差があると、コストを削減または維持するために交換できる反転が作成されるため、ソートされたペアリングは全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

# compute positional weights
w = [0] * n
for i in range(n):
    w[i] = (i + 1) * (n - i)

# pair a with weights
pairs = [(w[i] * a[i], i) for i in range(n)]
pairs.sort(reverse=True)

b.sort()

res = 0
for i in range(n):
    val, idx = pairs[i]
    res = (res + val * b[i]) % MOD

print(res)
```コードにおける重要な変換は、最初に位置の重みを構築することです。 因数 (i+1)(n-i) は、インデックス i を含むサブ配列の数をエンコードします。 これが完了すると、ネストされたサブ配列構造は完全に消え、線形配列のみを操作できるようになります。 

重み付けされた a_i を減少させることによってペアを並べ替えると、アライメント後に最大の寄与が最小の b 値を取得することが保証されます。これは再配置不等式の最適な方向です。 

よくある実装上の間違いは、重みの式で 1 ​​から始まるインデックス付けを忘れることです。 (i+1)(n-i) の代わりに i * (n - i) を使用すると、すべての重みが誤ってシフトされ、部分配列の組み合わせカウントが壊れます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    MOD = 998244353

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    w = [(i + 1) * (n - i) for i in range(n)]
    pairs = sorted([(w[i] * a[i], i) for i in range(n)], reverse=True)
    b.sort()

    ans = 0
    for i in range(n):
        ans = (ans + pairs[i][0] * b[i]) % MOD
    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 重要なエッジケースは、b の値がすべて等しい場合です。 その状況では、どの順列でも同じ結果が生成されるため、アルゴリズムは偶発的な順序付けの安定性に依存してはなりません。 重み付けステップだけで答えが決まり、並べ替えによって正しさが変わることはありません。 

a が厳密に増加し、b が厳密に減少する場合、別のエッジ ケースが発生します。 素朴なアプローチではそれらを直接一致させようとするかもしれませんが、正しい動作は生の大きさではなく位置の重みに完全に依存します。 重み付けされた寄与によるソートが a の生の順序付けを支配するため、アルゴリズムはこれを処理します。 

3 番目のケースは n = 1 で、部分配列構造が崩壊し、答えは 1 つの乗算に減ります。 (1)(1) はその要素を含む 1 つの部分配列を正しくカウントするため、重みの公式は引き続き機能します。
