 ## 問題の理解

 禰豆子は、特定の健康ポイントを持つ数直線上の位置 0 から開始し、その位置に到達したいと考えています。`d`。 各ターンで、彼女は休んで 1 ヘルス ポイントを獲得するか、1 ずつ前進することができます。 連続移動中の各連続移動により、その連続移動の長さだけ彼女の健康状態が減少します。 つまり、彼女が一度移動すると、体力が 1 失われます。 2 回連続して移動すると、2 回目の移動で 2 を失います。以下同様です。 体力がゼロ以下になる場合、彼女は行動を起こすことができません。 タスクは、位置に到達するために必要な休憩を含む最小合計ターン数を決定することです。`d`。 

制約は重要です。 健康も両方`h`そして距離`d`は最大 10^9 まで、テスト ケースは最大 10^4 まで可能です。 それぞれの動きを段階的に追跡する単純なシミュレーションでは、次のオーダーの処理が必要になる可能性があるため、非常に遅すぎます。`d`テスト ケースごとの操作。最悪の場合、10^13 の操作になる可能性があります。 

禰豆子の初期体力が距離に比べて低い場合、微妙なエッジケースが発生します。 たとえば、次の場合`h = 1`そして`d = 4`、彼女は連続して複数のステップを移動することはできません。 彼女は移動中に休憩を挟む必要があり、最適な戦略は、単に可能な限り移動することではなく、合計ターンを最小限に抑えるために連続する移動の長さを計画することです。 別のエッジケースが発生するのは次の場合です。`h >= d`。 その場合、彼女は正確に目的地に到着できるかもしれません`d`休むことなく動きますが、`h`体が若干小さい場合でも、しっかりとした方法で休む必要があります。 

## アプローチ

 ブルートフォースのアプローチは簡単です。各ターンをシミュレートし、連続する移動の連続を追跡し、体力を適切に減らし、移動によって体力が 1 未満になるたびに休憩を挿入します。これは正しく機能しますが、長距離には遅すぎます。 たとえば、`d = 10^9`、単一のテスト ケースでも、数十億の動きをシミュレートする必要があります。 

重要な洞察は、一連の連続した健康コストの合計が、`k`移動は最初の合計です`k`整数、`k * (k + 1) / 2`。 禰豆子が連勝を始めたら`k`移動すると、連勝を乗り切るには少なくともそれくらいの健康が必要です。 そう考えると、問題は最適な連続移動数を見つけることになります。`k`彼女は休む前にそれらの筋の合計が距離をカバーできるようにすることができます`d`最小限のターン数で。 最適なシーケンスは、一般に、1 つのストリークでできるだけ多く移動し、次に休憩し、それを繰り返すことを交互に繰り返します。 

なぜなら、健康コスト関数は`k*(k+1)/2`が凸である場合、ストリークの長さの関数としての総ターン数は単峰性であるため、可能な値に対して三分探索を適用できます。`k`考えられるすべての戦略をシミュレーションするのではなく。 これにより、時間の複雑さが大幅に軽減されます。

 | ブルートフォースシミュレーション | テスト ケースごとの O(d) | お(1) | 10^9 までの d には遅すぎます |
 | 最適なストリーク プランニング + 3 値検索 | テスト ケースごとの O(log d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 特定のテスト ケースについて、初期状態が正常かどうかを確認します。`h`距離以上です`d`。 もしそうなら、禰豆子は一直線に動くことができます`d`休まずに動きます。 合計ターン数は次のとおりです`d`。 これにより、単純なエッジケースが処理されます。 
2. もし`h < d`、禰豆子が連続した長さの連続で移動する場合に必要な合計ターン数を計算する関数を定義します。`k`。 各ストリークは消費します`k*(k+1)/2`健康状態が良くなり、各連続記録の後、禰豆子は次の連続記録に十分な健康状態が得られるまで休むことができます。 この関数は、ストリークの長さを指定して、移動と休憩の組み合わせとして合計ターンをモデル化します。 
3. 総回転数とストリークの長さの関数であるため、`k`単峰性であるため、三項検索を適用して最適な値を見つけます`k`それは総ターン数を最小限に抑えます。 三項探索は繰り返して区間を狭めます。`k`現在の間隔内の 2 つの時点での関数値を比較することによって。 
4. 最適なストリーク長になったら`k`が見つかったら、その合計ターン数を計算します`k`同じ関数を使用して、移動と必要な休符を合計します。 
5. 最適なターン数の合計を返します。`k`。 

正確さを保証する不変条件は、休憩には 1 ターンを消費するため、実行可能な最大のストリークで移動する方が、小さなストリークを取るよりも常に優れているということです。 三分探索により、すべての有効なストリーク長にわたって最小合計ターン数が確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_turns(h, d):
    if h >= d:
        return d

    # Function to calculate total turns for a given streak length k
    def turns_for_k(k):
        # health needed for one full streak
        cost = k * (k + 1) // 2
        # number of full streaks
        full_streaks = (d + k - 1) // k
        # total health needed
        total_health_needed = full_streaks * cost
        # extra rests needed
        extra_rests = max(0, total_health_needed - h)
        return d + extra_rests

    # Ternary search on k
    low, high = 1, d
    while high - low > 3:
        m1 = low + (high - low) // 3
        m2 = high - (high - low) // 3
        if turns_for_k(m1) < turns_for_k(m2):
            high = m2
        else:
            low = m1

    res = min(turns_for_k(k) for k in range(low, high + 1))
    return res

t = int(input())
for _ in range(t):
    h, d = map(int, input().split())
    print(min_turns(h, d))
```機能`turns_for_k`ストリークの長さの合計ターンをモデル化します。`k`。 三分探索では、候補ストリーク長の間隔を繰り返し縮小します。 探索後、残った小さな範囲の最小値が答えになります。 慎重な取り扱い`h >= d`不必要な計算を回避し、最も単純なケースを正しく処理します。
