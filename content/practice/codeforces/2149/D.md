 ## 解決策
 ## 問題の理解

 2 つのシンボルのみからなるバイナリ文字列が与えられています。`a`そして`b`。 隣接する文字を交換することが許可されているため、基本的にどの操作も、隣接する 2 つの文字をバブル ソートする 1 つのステップで実行できます。 

目標は、文字列を完全にソートすることではなく、より弱い構造状態に到達することです。いくつかの交換の後、文字の 1 つを選択できる必要があります。`a`または`b`、選択した文字のすべての出現が、最終的な文字列内で 1 つの連続したセグメントを形成するようにします。 もう 1 つの文字は、この選択したブロックの左側と右側の 2 つのセグメントに分割することができます。 

したがって、完全な単調順序を強制するわけではありません。 私たちは、1 つのタイプが複数の別々のグループに出現しないことを強制しているだけです。 

各スワップのコストは 1 であり、スワップの数は最小限にする必要があります。 

制約は大きく、すべてのテスト ケースの合計長は最大 200,000 です。 これにより、すべての中間状態を交換またはチェックする二次シミュレーションが即座に除外されます。 スワップを繰り返しシミュレートしたり、考えられるすべてのターゲット構成を単純に試行したりすると、タイムアウトになります。 

微妙な失敗例は、弦が激しく交互する場合に現れます。`ababababa`。 このような場合、「最も近い不一致を修正する」貪欲なローカル スワップは合理的であるように見えますが、文字タイプを 1 つのブロックにマージするために必要な交差の数を全体的に最小限に抑えることはできません。 コストは、ローカルの隣接関係ではなく、選択した文字の出現間のグローバルな反転に依存します。 

## アプローチ

 直接的なアプローチでは、両方の可能性を個別に試します。`a`文字を 1 つの連続したブロックに入れるか、すべての文字を強制します`b`文字を 1 つの連続したブロックにまとめます。 ターゲットごとに、有効性に達するまで交換をシミュレートし、おそらく、間違って配置された文字を貪欲に内側に移動します。 

隣接するスワップによって任意に再配置できるため、これは正確性という意味では機能しますが、問題はコストです。 最悪の場合、各スワップにより無秩序は 1 つの反転だけ減少し、これを長期間にわたって明示的にシミュレートします。`n`二次的な動作につながります。 

重要な洞察は、オペレーションの観点から考えるのをやめ、代わりに交差点の観点から考えることです。 キャラクターを選ぶとき、こう言います。`a`、私たちは事実上、すべてのことを決定しています。`a`文字はグループ化する必要があります。 毎`a`それは「分離」されています`b`キャラクターはその数に等しいコストを貢献します`b`最後のブロックに結合するために通過する必要がある文字。 各交換では、異なる文字間の反転が 1 つだけ削除されるため、答えは、選択した文字と最適な配置の下での他の文字の間の反転の数になります。 

次に構造の単純化です。 それを全部直したら`a`1 つのブロックを形成し、その後すべてのブロックを形成する必要があります`b`このブロックの完全に左側になるか、完全に右側になるかのどちらかです。 これは、文字列内の分割点を選択していることを意味します。残っているものはすべて`b`、次にブロック`a`、その後残ります`b`。 この構造から逸脱すると、側に到達するために境界を越えなければならないキャラクターの数に等しいコストが発生します。 

したがって、固定された分割位置の場合、次の数を計算できます。`a`が左にずれているのはいくつですか`b`が右にずれています。 それがその分割にかかるコストになります。 考えられるすべての分割に対してこれを行い、最小値を取得します。 同じロジック交換の役割を繰り返します。`a`そして`b`。 

最適な答えは、これら 2 つの対称的なケースの最小値です。

 ## アルゴリズムのチュートリアル

 と判断した場合に必要な最小スワップを計算するプロセスについて説明します。`a`単一の連続したブロックを形成します。 

1. 合計数を数える`a`文字列内の文字。 これにより、最終的な長さがわかります`a`ブロック。 
2. プレフィックスの合計を事前に計算します。`a`各インデックスまで文字が表示されます。 これにより、その数についての定数時間のクエリが可能になります。`a`はカットの左側にあります。 
3. 可能なすべての間隔で、`a`ブロックが座っている場合、文字列が左側、中央の 3 つの部分に分割されると想像します。`a`ブロック、右側。 
4. 開始位置を固定する場合`l`ブロックの数を計算します`a`文字は現在ブロックの外にあります。 これらは内側に進まなければならないものです。 
5. ブロックを配置するコスト`l`に`l + total_a - 1`プレフィックスの合計を使用して計算できます。 

左側にはのみを含める必要があります`b`、それですべて`a`左は間違っています、

 右側にものみが含まれている必要があります`b`、それですべて`a`右は間違っています。 
6. ブロックのすべての有効な位置の最小値を取得します。 
7. 役割を交換して同じ計算を繰り返します (`b`が対象ブロック文字となります）。 
8. 両方の結果の最小値を返します。 

### なぜ効果があるのか

 すべてのスワップは、スワップ間の反転を 1 つだけ解決します。`a`そして`b`。 ターゲット構成を修正する場合、必要なスワップの数は、最終面に交差する必要がある文字間の反転の数と等しくなります。 可能なブロック位置のスライディング ウィンドウは、構造的に有効な最終構成をすべて列挙し、プレフィックスの合計により、反転ごとに配置ミスの文字を正確に 1 回カウントすることが保証されます。 これにより、文字列を有効な単一ブロック配置に変換するために必要な隣接スワップの真の最小数を計算していることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost(s, ch):
    n = len(s)
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == ch)
    
    total = pref[n]
    if total == 0:
        return 0
    
    best = float('inf')
    
    for l in range(n - total + 1):
        r = l + total
        
        left_bad = pref[l]
        right_bad = pref[n] - pref[r]
        
        best = min(best, left_bad + right_bad)
    
    return best

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ans = min(cost(s, 'a'), cost(s, 'b'))
        print(ans)

if __name__ == "__main__":
    solve()
```機能`cost`1 つの文字を単一の連続セグメントに強制的に入れる場合の最適なコストを評価します。 プレフィックス配列は、その文字が各位置までに何回出現するかをカウントするため、選択したウィンドウの外側に出現する文字の数を迅速に計算できます。 

ループオーバー`l`は、連続ブロックの可能なすべての配置を表します。 各配置では、ブロックの外側にある選択された文字の要素が境界を越える必要があり、そのような誤って配置された各文字は、最適な再配置で必要な 1 つの交換に正確に対応します。 

両方の文字の選択を独立して計算します。`a`または`b`最後の単一ブロックを形成するものである可能性があります。 

## 実用的な例

 ### 例 1:`abab`作りを評価する`a`単一のブロック。 

| l | r | left_bad (左に a) | right_bad (右にある) | 合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 1 | 1 |
 | 1 | 3 | 1 | 0 | 1 |

 最小値は 1 です。 

ただいま製作中`b`単一のブロックでも同じ構造が得られ、結果も 1 になります。 

したがって、答えは 1 です。 

これは、小さな交互パターンであってもすでに少なくとも 1 つの反転の解決が強制されており、最適な解決策は 1 つの貪欲なスワップの選択に結び付けられていないことを示しています。 

### 例 2:`bababa`合計`a`カウントは3です。 

長さ 3 のウィンドウをテストします。 

| l | r | 左が悪い | 右_悪い | 合計 |

これは、文字列が対称的であっても、コストはローカルの隣接関係ではなく、選択した境界を越えなければならない出現の数によって決定されることを示しています。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    
    def cost(s, ch):
        n = len(s)
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + (s[i] == ch)
        total = pref[n]
        if total == 0:
            return 0
        best = 10**18
        for l in range(n - total + 1):
            r = l + total
            left_bad = pref[l]
            right_bad = pref[n] - pref[r]
            best = min(best, left_bad + right_bad)
        return best

    for _ in range(t):
        n = int(input())
        s = input().strip()
        print(min(cost(s, 'a'), cost(s, 'b')))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

 ## 特殊なケース

 次のような単一文字列`a`または`b`ブロック配置用の空のループ範囲を生成します。 その文字の合計数が 0 または 1 であるため、コスト関数はすぐに 0 を返し、移動は必要ありません。 

次のような完全に均一な文字列`aaaaa`合計数は次と等しい`n`したがって、唯一の有効なウィンドウは文字列全体そのものです。 左右の不一致は両方ともゼロであり、アルゴリズムは意味のある代替をスキャンせずに正しく 0 を返します。
