 ## 解決策
 ## 問題の理解

 _n_ 個のノードを含むツリーが与えられます。各エッジは正の長さを持ちます。 ツリーは、任意の 2 つのノード間に単純なパスが 1 つだけ存在することを保証します。 このタスクは、エッジの長さとその 2 つの端点のラベルの合計の積のすべてのエッジにわたる合計を最大化する方法で、順列を形成してノードに 1 から _n_ までの数値を割り当てることです。 形式的には、ノード _u_ と _v_ を重み _w_ で接続するエッジの場合、$$\sum_{\text{edges }(u,v)} w \cdot (p_u + p_v)$$どこ$p_u$そして$p_v$割り当てられたラベルです。 

出力には、可能な最大合計とそれを達成する順列の 2 つのことが必要です。 複数の順列が同じ合計に達する場合、辞書編集的に最小のものを選択します。 

入力サイズは最大です$10^5$ノード。 2秒の制限時間で実行されるアルゴリズム$O(n \log n)$または$O(n)$許容されますが、$O(n^2)$それ以上だと遅すぎます。 エッジの重みは最大で$10^5$, これは適度であるため、Python での整数演算は安全です。 すべての順列を考慮する素朴なアプローチは不可能です。$n!$中程度の _n_ であっても天文学的に大きくなります。 

明らかではないエッジ ケースの 1 つは、ノードが 2 つしかないツリーです。 この場合、最適な合計は、2 つのノードに割り当てられた 2 つのラベルにエッジの重みを乗算したものを単純に使用します。 不注意なアプローチではラベルをノード インデックスまたは次数で並べ替える可能性があり、合計を最大化できない可能性があります。 もう 1 つのエッジ ケースは、1 つの中央ノードが他のすべてのノードに接続する星型ツリーです。これは、どのくらいの大きさのラベルを配布する必要があるかに影響します。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$n!$ラベルの順列を計算し、それぞれの合計を計算し、最大値を返します。 これは明らかに実行不可能です。 のために$n = 10^5$、単一の順列を評価する場合でも、すでに$O(n)$操作と$n!$これは完全に範囲外です。 

重要な観察は、合計に対する各エッジの寄与が、そのエンドポイントのラベルの合計とエッジの重みの積に比例するということです。 全体の合計を最大化するには、エッジの重みの点でより「中心」にあるノードに、より大きなラベルを割り当てる必要があります。 具体的には、各ノードは、それに付随するエッジの重みの合計に比例するラベルを受け取る必要があります。 このインシデントの重みの合計 (ノードの「重要度」) でノードを並べ替え、昇順にラベルを割り当てると、最大のラベルが最も重み付けされたノードに割り当てられ、合計が最大化されます。 この方法で並べ替えると、複数のノードの「重要度」が等しい場合に、ノード インデックスとの関係を解消することで辞書編集的に最小の順列を選択することもできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノードの数 _n_ とエッジとその重みを読み取ります。 ツリーを表す隣接リストを作成します。 
2. 各ノードについて、それに付随するすべてのエッジの重みの合計を計算します。 この値をノード インデックスとともに保存します。 これにより、合計に対する各ノードの寄与の可能性の尺度が得られます。 
3. インシデントの重みの合計によってノードを昇順に並べ替えます。 2 つのノードの合計が等しい場合は、辞書編集上の最小性を確保するためにノード インデックスで並べ替えます。 
4. このソート順に従って、1 から _n_ までのラベルを割り当てます。 合計が最小のノードにはラベル 1 が付けられ、次に合計が最小のノードにはラベル 2 が付けられます。 これにより、より重いエッジを介して最も貢献しているノードに最大のラベルが割り当てられることが保証されます。 
5. すべてのエッジを反復処理し、エッジの重みにそのエンドポイントに割り当てられたラベルの合計を乗算して合計を計算します。 
6. ノードに割り当てられたラベルの合計と順列を出力します。 

正確さは、合計がノード ラベル内で線形であるという事実に依存します。 ノードの寄与度によって並べ替えると、加重合計が最大になる方法でラベルが確実に分散されます。 ソートはノードインデックスに関して安定しているため、辞書編集上の最小性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
edges = []
deg_weight = [0] * n

for _ in range(n-1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    edges.append((u, v, w))
    deg_weight[u] += w
    deg_weight[v] += w

nodes = [(deg_weight[i], i) for i in range(n)]
nodes.sort()  # sort by total incident weight, then by node index

perm = [0] * n
for label, (_, node) in enumerate(nodes, 1):
    perm[node] = label

total = 0
for u, v, w in edges:
    total += w * (perm[u] + perm[v])

print(total)
print(' '.join(map(str, perm)))
```このソリューションでは、最初に、入射エッジの重みを合計することによってノードの「重要度」を計算します。 ソートにより、タイが辞書編集的に最小限になることが保証されます。 ソートされたノードに昇順でラベルを割り当てると、より重いエッジで接続されたノードに最大のラベルが割り当てられることが保証されます。 最後に、各エッジの重みにその端点のラベルの合計を乗算して、エッジの合計が計算されます。 

## 実用的な例

 ### サンプル 1

 入力:```

```| ノード | 入射重量の合計 | 並べ替え順 | 割り当てられたラベル |

 | 1 | 3 | 0 | 1 |
 | 2 | 3 | 1 | 2 |

 合計額:$3 \cdot (1+2) = 9$順列：`1 2`。 ただし、辞書編集的に最小の最大値が必要なので、ラベルを交換して取得します。`2 1`。

 入力:```

```ノードの重みの合計: 1→6、2→1、3→2、4→3

 合計で並べ替え: 2、3、4、1

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # call solution code
    n = int(input())
    edges = []
    deg_weight = [0] * n
    for _ in range(n-1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))
        deg_weight[u] += w
        deg_weight[v] += w

    nodes = [(deg_weight[i], i) for i in range(n)]
    nodes.sort()
    perm = [0] * n
    for label, (_, node) in enumerate(nodes, 1):
        perm[node] = label

    total = sum(w * (perm[u] + perm[v]) for u, v, w in edges)
    print(total)
    print(' '.join(map(str, perm)))
    return output.getvalue().strip()
