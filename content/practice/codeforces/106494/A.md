 ## アルゴリズムのチュートリアル

 の値の増加をシミュレートします。$k$、プレフィックスセグメントとサフィックスセグメント間の可能な限り有効な分離を追跡しながら。

### なぜ効果があるのか

 どの段階でも$k$、プレフィックスには最初のものが正確に含まれます$k$インデックス、サフィックスには正確に最後のものが含まれます。$k$インデックス。 条件`pref_max < suf_min`プレフィックスで選択されたすべての要素がサフィックスで選択されたすべての要素よりも前に厳密に存在することを保証します。 プレフィックス最大値は減少しないため、$k$と接尾辞の最小値は増加せず、一度不等式が崩れると再び真になることはありません。 この単調性により、最初の失敗で停​​止すると、有効な最大値が得られます。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    i = list(map(int, input().split()))

    pref_max = -10**18
    suf_min = 10**18

    ans = 0

    for k in range(n):
        pref_max = max(pref_max, i[k])
        suf_min = min(suf_min, i[n - 1 - k])

        if pref_max < suf_min:
            ans = k + 1
        else:
            break

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、前述した両面展開を反映しています。 ループインデックス`k`それぞれの側からどれだけの要素を取り出したかを表します。 プレフィックスの最大値は左側を使用して更新され、サフィックスの最小値は対称右側を使用して更新されます。 答えは次のように保存されます`k + 1`なぜなら`k`ループ内ではゼロベースになります。 

よくある落とし穴は、off-by-one の処理です。ループ インデックスは 0 から始まりますが、問題は$k$当然 1 から始まります。 もう 1 つの微妙な問題は初期化です`pref_max`そして`suf_min`正しく; インデックスが負または大きい場合、制約に応じて 0 または無制限の値を使用すると、正確性が損なわれる可能性があります。

 ## 特殊なケース

 エッジケースの 1 つは、最初の比較がすでに失敗している場合です。 のような入力の場合`2 / 2 1`、k=1 のプレフィックスは次のとおりです。`[2]`そしてサフィックスは`[1]`、 それで`pref_max < suf_min`になる`2 < 1`、これは誤りです。 アルゴリズムセット`ans = 0`有効な分割が存在しない場合を正しく処理して、ただちに終了します。
