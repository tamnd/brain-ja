 ## 解決策
 ## 問題の理解

 数値の配列が与えられ、それをいくつかの素なグループに分割することができます。 各グループについて、その中央値を計算し、パーティションのスコアはこれらの中央値の合計になります。 タスクは、この合計スコアを最大化する配列のパーティションを選択することです。 

主な困難は、中央値が各グループの内部順序に依存する一方、分割の決定がどの要素が相互作用するかに影響を与えることです。 したがって、問題は単に並べ替えることではなく、グループ化によって全体的に最適な方法で中央値がどのように変更されるかを理解することです。 

配列サイズが約 200000 までの場合、すべてのパーティションを試行する解決策は直ちに不可能になります。 サブセットの列挙やグループ化の決定でも、指数関数的に増加します。 これにより、問題を最適なグループがどのようなものであるかの構造的特徴付けに還元し、その後、ソート後に線形または線形計算を行うという解決策に向かうことになります。 

小さなグループについて考えると、微妙な特殊なケースが発生します。 たとえば、サイズ 2 または 3 のグループを貪欲に形成しようとすると、罠にはまる可能性があります。 

入力:

 n = 4

 a = [1、2、3、4]

 [1,2] と [3,4] としてグループ化すると、中央値は 1 と 3 になり、合計は 4 になります。 

ただし、[1,2,3] および [4] としてグループ化すると、中央値は 2 と 4 となり、合計は 6 になります。 

隣接する要素をペアにする単純なローカル戦略では、1 つのより大きな構造化されたグループを作成することによる全体的な改善が失われます。 

中心的な問題は、中央値の値がグループ化に関して非常に非線形であるため、ローカルなヒューリスティックではなくグローバルな構造が必要であるということです。 

## アプローチ

 ブルートフォース手法では、配列のすべてのパーティションをグループに分けて試行し、各グループの中央値を計算します。 ソートされた配列を修正し、連続する分割のみを考慮したとしても、n 個の要素を分割する方法の数は依然として指数関数的です。 n = 40 では、これはすでに実行不可能になり、n = 200000 では完全に不可能になります。 

重要な観察は、最適解の構造が非常に制限されているということです。 配列を並べ替えた後、要素が中央値にどのように影響するかに基づいて、要素をグループ間でどのように分散できるかを推論できます。 提供された分析により、3 つの重要な構造的事実が導き出されます。 

まず、中央値の合計を減らさずにそのような 2 つのグループをマージできるため、最大 1 つのグループが負の中央値を持つ可能性があります。 第 2 に、正の中央値を持つグループの中で、複数の要素を含むことができるのは 1 つのグループだけです。 他のすべての要素は事実上、中央値として独自の値を提供するシングルトンになります。 第三に、そのような特別なグループが存在すると、その要素はソートされた配列内でプレフィックスを形成する必要があります。これは、一貫した方法で常に小さい正と大きい負を優先する場合にのみ、要素を外部要素と交換しても合計を改善または保持できるためです。 

これらの構造的制約により、問題は単純な決定に集約されます。ソートされた配列の接頭辞を選択して 1 つの特別なグループを形成し、残りの要素をすべて単一要素グループとして扱うというものです。 プレフィックスの選択ごとに、プレフィックス情報を使用して O(1) で結果のスコアを計算できるため、すべての分割ポイントをスキャンすることで最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 ### 段階的なプロセス

 1. 配列を降順でない順に並べ替えます。 

すべての構造引数は要素をグローバルに比較することに依存しており、中央値はソートされた順序でのみ予測どおりに動作するため、ソートが必要です。 
2. ソートされた配列のプレフィックス合計を事前計算します。

これにより、候補パーティションを評価する際に、任意のプレフィックスとサフィックスの合計を高速に計算できます。 
3. 各位置 i を、最初の i 要素が特別なグループを形成し、残りの要素がシングルトンである境界とみなします。 

これは、重要なグループが 1 つだけ必要であり、それが接頭辞である必要があるという構造的な結果から導き出されます。 
4. 固定 i について、プレフィックス グループの寄与を計算します。 

プレフィックスの中央値は、ソートされた中央の要素にのみ依存します。 
5. 残りの要素からの寄与を追加します。各要素は、中央値が要素自体であるシングルトン グループとして機能します。 
6. 考えられるすべての分割点にわたって最大スコアを追跡します。 

### なぜ効果があるのか

 正しさは、中央値の合計を減少させることなく、最適な分割を標準形式に変換できるという事実から得られます。 その正規形式には、自明ではないグループが 1 つだけあり、このグループはソートされた順序で連続する接頭辞で構成されます。 他のすべての要素は、独自のシングルトン グループを形成します。 すべての有効な最適なソリューションは 1 つのプレフィックス分割に正確に対応するため、すべてのプレフィックスを列挙することで、最適な構成を考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def median(l, r):
        length = r - l
        return a[l + (length - 1) // 2]

    ans = -10**18

    for i in range(n + 1):
        if i == 0:
            ans = max(ans, pref[n])
            continue

        med = median(0, i)
        rest_sum = pref[n] - pref[i]
        ans = max(ans, med + rest_sum)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、すべての中央値推論が位置的になるように、まず配列がソートされます。 プレフィックス合計配列を使用すると、特別なグループの外側の要素からの寄与を定数時間で評価できます。これは、それらがすべてシングルトンとして動作するためです。 

各分割ポイントについて、プレフィックス グループの中央値は、プレフィックスの中央インデックスを使用して計算されます。 残りの要素は独自の値として直接寄与するため、それらの合計はプレフィックス合計の差から直接取得されます。 

一般的な微妙な点は、i = 0 の場合の処理​​です。これは特別なグループがないことに対応し、すべての要素がシングルトンであることを意味するため、答えは単純にすべての要素の合計になります。

 ## 特殊なケース

 ### すべての要素が否定的

 入力:

 n = 3

 a = [-5、-2、-1]

 ソートは[-5、-2、-1]です。 アルゴリズムではすべてのプレフィックスが考慮されます。 最良の結果は、i = 0 で合計が -8 になるか、i = 1 で -7 が得られます。 最大値は -7 です。 

トレース:

 i = 0 は -8 を与えます

 i = 1 の場合、中央値 -5 + 残り -3 = -8 になります。 

i = 2 の場合、中央値 -5 + 残り -1 = -6 になります。 

i = 3 は中央値 -2 を与えます

 アルゴリズムには常にシングルトン オプションが含まれており、結果を悪化させる強制的なグループ化を防ぐため、このアルゴリズムはこれを正しく処理します。 

### 単一の大きなポジティブと多数の小さなネガティブ

 入力:

 n = 4

 a = [-10、-9、-8、100]

 ソート済み: [-10、-9、-8、100]

 最適なのは、100 を分離し、どのプレフィックス グループでも希釈しないようにすることです。 スキャンには i = 0 が含まれており、合計は 73 になりますが、プレフィックス グループの寄与は 100 から減少します。 

プレフィックス スキャンにより、アルゴリズムが有益な外れ値を次善のグループに強制的に含めることがなくなります。
