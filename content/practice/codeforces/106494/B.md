 ## 解決策
 ## 問題の理解

 いくつかの独立した間隔が与えられ、各間隔から単一の値を選択する必要があります。 間隔ごとに 1 つの値を選択した後、それらの値をベクトルの大きさとして扱います。 重要な問題は、ベクトルの合計が正確にゼロになるように、これらのベクトルに方向を割り当てることができるかどうかです。 

問題の背後にある幾何学は、すべてを数値に関する単一の条件に還元します。 選択した 1 つの値が他のすべての値の合計と比較して大きすぎる場合、方向をどのように設定しても、その最大のベクトルを残りのベクトルで完全にキャンセルすることはできません。 そのような不均衡が存在しない場合、ある時点でシステムのバランスを保つために方向を常に継続的に調整できるため、有効な方向が常に 1 次元に存在します。 

各間隔は柔軟性に貢献しますが、それはその範囲内でのみです。 実際の決定は、選択された値の複数セットがバランス条件を満たすことができるように、各間隔から 1 つの値を選択する方法です。 

この制約は、テスト ケースごとに最悪でも O(n) または O(n log n) の解が必要であることを意味します。 インターバルからのピックの組み合わせを探索しようとするアプローチは、縮小された形式であっても、n が数十を超えるとすぐに指数関数的になり、使用できなくなります。 

最大間隔が最大エンドポイントで固定されていない場合、微妙な失敗例が発生します。 たとえば、間隔 [5, 10]、[1, 2]、[1, 2] を考えてみましょう。 単純なアプローチでは、すべての最大値を選択することが常に最適であると想定する可能性がありますが、最大値が不必要に大きくなり、実現可能な構成が誤って拒否される可能性があります。 正しい推論では、実現可能性を考慮しながら最大間隔を下方に調整することを考慮する必要があります。 

別のエッジ ケースは、複数の間隔が最大の下限で一致する場合、または最大の要素を減らすときにどの間隔が支配的になるかが変化する場合に発生します。 左辺値ではなく右辺値で最大値を固定する不用意な実装は、ここで失敗します。 

## アプローチ

 ブルートフォース解釈では、間隔ごとに 1 つの値のすべての選択肢を試し、それぞれの選択に対して、合計をゼロにする符号を割り当てることができるかどうかを確認します。 固定選択をチェックすると、要素が合計の半分 (線形) を超えているかどうかを確認することになります。 ただし、選択の数は間隔の長さの積であり、n で指数関数的になるため、非常に小さい入力を超えるとこれは不可能になります。 

重要な点は、実際には選択肢を列挙する必要がないということです。 私たちが気にするのは、「支配的な要素」が他のすべての要素の合計を超えることを回避する選択が存在するかどうかだけです。 これにより、問題は、選択された値の有効なマルチセットを構築することに変わります。 

この間隔は縮小するのが最も難しいため、最大の下限を持つ間隔を特定します。 そこから候補値を暫定的に固定し、バランス条件に違反することなく他のすべての選択された値がその値をサポートできることを確認します。 

臨界区間から値 x を選択すると、他のすべての区間は最大でも選択した範囲内で値に寄与し、他の区間の合計が少なくとも x になるようにします。 これにより、問題は、制約の下で残りの区間で x をサポートできるかどうかを確認することに変換されます。 貪欲な戦略は、x を超えずに他の間隔からの寄与を最大化することです。x を超えると条件のバランスがさらに整わないためです。 

これは直接的な構築につながります。アンカーとして最大下限 l_i を持つ区間を選択し、その値を l_i に設定し、他の区間ごとに min(r_j, l_i) を選択します。 これにより、間隔境界との一貫性を維持しながら、アンカーのサポートに対する貢献が最大化されます。

 ## アルゴリズムのチュートリアル

私たちは検索ではなく、実現可能な選択を構築することに重点を置いています。 

### 1. 重要な間隔を特定する

 左端が最大となる間隔を見つけます。 この間隔は、有効なソリューションに少なくともその大きさをサポートする可能性を強制するため、最も制限的です。 

### 2. 選択した値を暫定的に修正します

 この間隔に選択した値を下限に設定します。 値を大きくするとバランスが難しくなるだけなので、これより大きな値は試行しません。 

### 3. 他のすべての間隔に貪欲に値を割り当てます

 1 つおきの間隔については、臨界値を超えない最大値を選択します。 具体的には、min(r_j, l_max)を選びます。 これにより、実現可能性を損なうことなく、すべての間隔が重要な値のサポートに可能な限り貢献することが保証されます。 

### 4. 合計の比較による実現可能性の確認

 選択したすべての値の合計を計算します。 この合計が選択した臨界値の少なくとも 2 倍である場合、残りの値でバランスをとることができ、ゼロ ベクトル構成が可能であることを意味します。 

合計が小さい場合、有効な構造は存在しません。 

### なぜ効果があるのか

 正確かどうかは、ベクトルのキャンセル条件を単一の優勢制約に変換するかどうかに依存します。 値を選択した後、他の要素の合計を超える要素がない場合に限り、構成は実行可能です。 最大の下限区間を固定し、そのアンカーまでの他のすべての寄与を最大化することにより、その区間に対して可能な限り最良のサポート環境を構築します。 この最大限のサポートさえも失敗した場合、他の選択肢はサポートをさらに減らすだけであり、実現可能性は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seg = [tuple(map(int, input().split())) for _ in range(n)]

    # find interval with maximum left endpoint
    i_max = 0
    for i in range(1, n):
        if seg[i][0] > seg[i_max][0]:
            i_max = i

    x = seg[i_max][0]

    total = 0
    for i, (l, r) in enumerate(seg):
        if i == i_max:
            total += x
        else:
            if r < x:
                total += r
            else:
                total += x

    # feasibility condition
    print("YES" if total >= 2 * x else "NO")

if __name__ == "__main__":
    solve()
```このコードは、満たすのが最も難しい制約を決定するため、最初に最大の下限を持つ区間を特定します。 次に、選択した値をその下限に固定します。 1 つおきの間隔では、このアンカーのサポートに可能な限り貢献しますが、それを超えることはありません。 

最後のチェックでは、合計寄与度をアンカーの 2 倍と比較し、残りのベクトルがアンカーを完全に相殺できるかどうかをエンコードします。 

微妙な点は、「他のものの合計」を個別に明示的に計算することは決してないということです。 代わりに、合計にアンカーを含めて 2x と比較します。 これにより、オフバイワンの間違いが回避され、実装が線形に保たれます。 

## 実用的な例

 ### 例 1

 間隔を考慮してください。 

[3、5]、[1、2]、[2、4]

 左端の最大値は 3 なので、x = 3 となります。 

| 間隔 | 選択された値 | 貢献 |
 | --- | --- | --- |
 | [3,5] | 3 | 3 |
 | [1,2] | 2 | 2 |
 | [2,4] | 3 | 3 |

 合計 = 8、2x = 6 なので、条件が成り立ちます。 

これは、一部の間隔が 3 に達しない場合でも、それらの最大寄与がアンカーのバランスをとるのに十分であることを示しています。 

### 例 2

 間隔を考慮してください。 

[10、10]、[1、2]、[1、2]

 ここで x = 10 です。 

| 間隔 | 選択された値 | 貢献 |
 | --- | --- | --- |
 | [10,10] | 10 | 10 |
 | [1,2] | 2 | 2 |
 | [1,2] | 2 | 2 |

 合計 = 14、2x = 20 であるため、条件は失敗します。 

これは、最大のサポートの下でも、1 つの間隔が他のすべての間隔に比べて大きすぎる故障モードを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sysio

    out = sysio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    seg = [tuple(map(int, input().split())) for _ in range(n)]

    i_max = 0
    for i in range(1, n):
        if seg[i][0] > seg[i_max][0]:
            i_max = i

    x = seg[i_max][0]

    total = 0
    for i, (l, r) in enumerate(seg):
        total += x if (i == i_max and l <= x <= r) else min(r, x)

    print("YES" if total >= 2 * x else "NO")

assert run("3\n10 10\n1 2\n1 2\n") == "NO"

# minimum case
assert run("1\n0 5\n") == "YES"

# tight boundary case
assert run("2\n5 5\n5 5\n") == "YES"

# impossible spread
assert run("2\n10 10\n1 1\n") == "NO"

 ## 特殊なケース

 単一間隔のケースが最も単純です。 入力 [0, 5] の場合、他の制約がないため、アルゴリズムは x = 0 を選択し、すぐに条件を満たします。 計算された合計はゼロに等しく、2x もゼロであるため、答えは YES です。 

[5,5]、[5,5] などの厳密に制約された等間隔のケースでは、x = 5 が設定されます。両方の間隔が 5 に寄与し、合計 10 が 2x になり、YES となります。 これにより、等価性の処理が正しく、厳密な不等号が必要ないことが確認されます。 

[10,10]、[1,1] のような非常に不均衡なケースでは、x = 10 が設定されます。2 番目の区間は 1 のみを寄与し、合計は 11 となり、20 をはるかに下回るため、アルゴリズムは正しくこれを拒否します。 これは、たとえ小さな間隔を最大化しても、大きすぎるアンカー間隔を補償できないことを示しています。
