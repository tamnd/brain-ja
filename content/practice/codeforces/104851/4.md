 ## 解決策
 ## 問題の理解

 合計数のケーキを一定数の児童に配布いたします。 すべての子供は正確に同じ量を受け取らなければなりませんが、調理人はケーキを半分に切ることが許可されています。つまり、各ケーキは1単位全体または2半分の単位のいずれかを提供できます。 配布後は、たとえ半分であっても未使用のままにすることはできません。 

したがって、この状況は、いくつかのホールケーキを選択し、場合によってはいくつかのケーキを半分に分割することと同等であり、ケーキ片の総量を D 個の子に余らず均等に分割できます。 各子供は同じ分け前を受け取り、ケーキの合計量は少なくとも A でなければなりません。 

出力は、分割を最適に使用すると仮定した場合、最初に購入する必要があるホール ケーキの最小数です。 

重要な制約は、各ケーキが分割されているかどうかに応じて 1 または 2 のハーフユニットを提供するということです。 これにより、パリティのような柔軟性が導入されます。合計量は D の任意の整数または半整数倍にすることができますが、すべてが残り物なく完全に分配されなければならないため、合計の「ケーキの質量」は、半分で表した場合に D/2 の正確な整数倍でなければなりません。 

入力サイズは最大 10^9 であるため、考えられるケーキ数の反復に依存する解決策は不可能です。 直接的な算術構造が必要であり、これにはおそらく割り算と上限ロジックが含まれます。 

微妙なエッジ ケースは、A がすでに D で割り切れる場合、または A が D の倍数をわずかに下回る場合に現れます。もう 1 つは、A が D に比べて小さい場合であり、分数共有により切り上げが行われます。 また、D が 1 に等しい場合は、分布制約が存在しないため、動作が異なります。 

## アプローチ

 直接的な総当たりアプローチでは、ケーキの数を 0 から上に増やして、分割を使用して少なくとも A 個のケーキ ユニットを D 個の子に分配できるかどうかをシミュレートします。 ケーキ C の候補数ごとに、D/2 で割り切れる C と 2C の間の合計量 (半分の単位) を表現できるかどうかを確認します。 これには、分割の可能な分布をスキャンし、カットされるケーキの数を効果的に反復する必要があります。 

C 自体は最大 10^9 になる可能性があり、C ごとに複数の分割構成について推論する必要があるため、これはすぐに実行不可能になります。 C 上の線形スキャンでさえ、すでに大きすぎます。 

重要な観察は、ケーキを半分にカットすることで、各ケーキが半分につき 2 ハーフユニットまたは 1 ハーフユニットのいずれかに寄与するスケール単位システムで作業できることです。 つまり、ケーキで考えるのではなく、半分のケーキで考えるのです。 必要な合計量を半単位の整数 M とします。ここで、M は M ≥ 2A を満たさなければならず、M は D で割り切れます。 

M が固定されているとすると、必要なケーキの数は、使用できるフル ケーキの数と半分に形成する必要があるケーキの数によって決まります。 各ケーキは最大 2 つのハーフユニットを提供できるため、特定の M に必要なケーキの最小数は ceil(M / 2) です。 ただし、離散分布で M が達成可能であることも確認する必要がありますが、半分は自由に許可されるため、十分なフル ケーキとスプリット ケーキを使用して任意の整数 M ≥ 0 を表現できます。 

したがって、問題は、M ≥ 2A および M % D = 0 となる最小の M を見つけて、それを ceil(M / 2) としてケーキに変換し直すことに帰着します。 

このような最小の M は、2A 以上の D の最小倍数です。

 ## アルゴリズムのチュートリアル

 ## 最適な構造

1. 要件 A を 2A に 2 倍にして、問題を半単位に変換します。 これにより、分数の半分を明示的に処理することが回避され、すべてのケーキが一貫した整数系の 1 または 2 単位に変換されます。 
2. 少なくとも 2A である D の最小倍数を計算します。 この値は、D 個の子に残り物なく均等に分割できる分配可能な合計金額を表します。 
3. 2A がすでに D で割り切れる場合は、M = 2A とします。 それ以外の場合は、M = ((2A + D - 1) // D) * D を計算します。これにより、M が両方の制約を満たす最初の実行可能な合計になります。 
4. ceil(M / 2) を計算することにより、合計ハーフユニットをケーキに変換し直します。 各ケーキは最大 2 ハーフユニットに寄与するため、これにより M に達するのに十分な最小のケーキ数が得られます。 
5. この値を出力します。 

### なぜ効果があるのか

 ハーフユニットへの変換により、小数部分のあいまいさがすべて取り除かれ、実行可能なすべての分布が整数の合計 M に対応します。すべての子は等しいシェアを受け取る必要があるため、M は D で割り切れなければなりません。2A 未満の M は最小要件を満たすことができないため、検索スペースは 2A から始まる D の倍数に減少します。 これらのうち、ケーキの数を最小化することは M を最小化することと同等であり、各ケーキは最大 2 ハーフユニットに寄与するため、ceil(M/2) ケーキの使用が最適であり、フル ケーキとスプリット ケーキを混合することで常に達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    D = int(input())
    A = int(input())

    need = 2 * A

    M = ((need + D - 1) // D) * D

    # each cake contributes up to 2 half-units
    ans = (M + 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず要件を半分の単位にスケールします。 次に、標準的な上限除算トリックを使用して、D の有効な最小倍数を計算します。 最後に、各ケーキが最大 2 つのハーフユニットに寄与するため、天井で 2 で割ることによって逆変換されます。 

微妙な点は、整数の除算は慎重に行う必要があるということです。`(M + 1) // 2`奇数 M の正確性を保証します。これは、半分の単位が部分的に使用されたケーキから取得されなければならない状況に対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    D = int(sys.stdin.readline())
    A = int(sys.stdin.readline())

    need = 2 * A
    M = ((need + D - 1) // D) * D
    ans = (M + 1) // 2
    return str(ans)

# D = 1, trivial
assert run("1\n0\n") == "0"

# no need for rounding
assert run("3\n6\n") == "3"

# needs upward rounding
assert run("5\n2\n") == "3"

# large values
assert run("1000000000\n1000000000\n") == str((2*10**9 + 10**9 - 1)//10**9 * 10**9 // 2 + ((2*10**9 + 10**9 - 1)//10**9 * 10**9 % 2 != 0))

# small uneven case
assert run("2\n1\n") == "1"

 ## 特殊なケース

 D = 1 の場合、均等配分の制約は自明となり、答えは必要に応じて半分を使用して最小要件 A を満たすだけになります。 次の 1 の倍数が常にその値そのものであるため、アルゴリズムはこれを処理します。つまり、M = 2A となり、結果は正確に A ケーキになります。 

A = 0 の場合、厳密にはケーキは必要ありません。 アルゴリズムは need = 0 を計算するため、M = 0 となり、答えは 0 になり、購入の必要がないことが正しく反映されます。 

2A がすでに D の倍数である場合、天井ステップは何も行いません。 この場合、M = 2A であり、解は ceil(2A / 2) = A ケーキに単純化されます。これは、各ケーキを無駄なく完全に利用できるという直感と一致します。
