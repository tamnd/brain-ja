 ## 解決策
 ## 問題の理解

 私たちには一連の旅行計画が与えられており、それぞれにヴァシリーが特定の都市に滞在しなければならない日数が記載されています。 すべての旅行は、開始日から終了日までの全日でアクティブになります。 重要な問題は、ヴァシリーが同じ日に 2 つの異なる場所に滞在することはできないため、異なる都市への旅行が重なると衝突が生じることです。 タスクは、そのような競合が発生した最も早い日を特定するか、競合がまったく発生していないことを報告することです。 

入力はすでに開始日によってソートされており、以前のセグメントを再度訪問することなく、重複を単一の前方パスで処理する必要があることを強く示唆しています。 各間隔は将来の複数の間隔と重なる可能性があるため、維持する構造は現在アクティブなすべての旅行を表す必要があります。 

この制約により、私たちは線形または線形に近い動作をするようになります。 最大 100,000 の間隔と 1e9 までの日数では、毎日のアクティビティをシミュレートするアプローチは不可能です。 範囲が膨大になる可能性があるため、間隔内で一日中スキャンしても大きすぎます。 ソリューションはタイムラインを暗黙的に圧縮し、間隔の境界でのみ反応する必要があります。 

いくつかの特殊なケースは注目に値します。 まず、同一の都市は、間隔が完全に重なっていても競合を引き起こしません。 たとえば、ある旅行が都市 5 の [1, 10] であり、別の旅行が同じく都市 5 の [3, 7] である場合、矛盾はありません。 第 2 に、複数の重複する間隔は、最初の重複ではなく、後で競合する可能性があるため、ペアごとの交差を個別にチェックするのではなく、アクティブ セットを継続的に追跡する必要があります。 第三に、最初の競合は開始日ではなく長い間隔の途中で発生する可能性があるため、単にエンドポイントを比較することはできません。 

## アプローチ

 直接的なアプローチは、すべての間隔のペアを比較し、それらが重複していて異なる都市に属しているかどうかを確認することです。 2 つの間隔が重なっている場合は、交差部分が計算され、その範囲内に競合が存在すると直ちに推定されます。 すべてのペアにわたる最も早い交差により答えが得られます。 これは正しいです。なぜなら、あらゆる競合は、異なる都市で重複する間隔のペアから発生するはずだからです。 

問題は効率です。 N 間隔の場合、O(N²) 個のペアが存在します。 各オーバーラップ チェックは一定時間ですが、最悪の場合、N が 100,000 の場合に約 5e9 回の操作が発生し、これは制限をはるかに超えています。 

重要な点は、間隔が開始日によってソートされていることです。 これにより、それらを昇順に処理し、現在アクティブな間隔のみを維持することができます。 間隔がまだ終了していない場合、間隔はアクティブになります。 先に進むと、終了日が現在の開始日よりも小さい間隔を削除できます。 すべてのアクティブな間隔のうち、それらがどの都市に属しているかを知る必要があるだけです。 競合は、新しい間隔が別の都市のアクティブな間隔と重なるときに発生します。 

すべてのアクティブな間隔を個別に追跡する代わりに、どの都市が現在アクティブであるか、および最新の終了日を記録するデータ構造を維持します。 都市がすでにアクティブな場合は、そのアクティブ範囲を拡張するだけです。 新しい間隔と交差する時間に別の都市が活動している場合、正確な重複ポイントを計算して、最も早い紛争日を特定できます。 

これにより、問題は、ペアごとの比較ではなく、小さなアクティブ状態から始まる間隔にわたるスイープ ラインに縮小されます。

 ## アルゴリズムのチュートリアル

1. 現在アクティブなすべての間隔を表す構造を維持しながら、開始日の昇順に間隔を処理します。 これが機能するのは、開始日を過ぎると、終了時刻を除いてそれ以前の間隔は影響を受けないためです。 
2. 各都市をそのアクティブな間隔の最大終了日までマッピングする辞書を保持します。 同じ都市からの複数の間隔が重複する場合、競合が発生しないため、それらの間隔は 1 つのアクティブな範囲にマージされます。 
3. 他の都市からのすべてのアクティブな間隔の中で最も早い終了を迅速に判断できる構造を維持します。 最初の競合は最も早いオーバーラップ境界で発生するため、これが必要です。 
4. 都市 c の新しい間隔 [l, r] ごとに、最初に、終了が厳密に l より前にあるアクティブな間隔を削除または期限切れにします。 これらの間隔は、現在の間隔と重複することはできません。 
5. c とは異なる現在アクティブな都市をすべてチェックします。 このような都市にアクティブな間隔があり、その終了が少なくとも l である場合、重複が存在します。 別の都市がまだ活動している間に新しい間隔が始まるため、最も早い紛争日はそれ自体です。 
6. 開始時に競合が見つからない場合は、アクティブな終了を max(current_end, r) に更新することにより、都市 c の間隔を挿入またはマージします。 
7. すべての間隔が処理されるまで続行します。 競合が見つからなかった場合は 0 を出力します。 

### なぜ効果があるのか

 どの時点でも、アクティブ セットには、現在のスイープ位置を時間的にカバーする間隔が正確に含まれます。 間隔は開始日の昇順に処理されるため、現在の間隔と競合する可能性のある間隔は、すでに開始されており、まだ終了していない必要があります。 競合が発生する唯一の方法は、ある日、2 つの異なる都市が重複するアクティブ カバレッジを持っている場合であり、これは、重複を引き起こす後の間隔を処理するときにすぐに検出されます。 新しい間隔を挿入する前に常に最初の重複を検出するため、最初に報告される日は全体的に最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    active = {}  # city -> current end day
    
    earliest_conflict = None
    
    for _ in range(n):
        l, r, c = map(int, input().split())
        
        # expire outdated intervals
        to_remove = []
        for city, end in active.items():
            if end < l:
                to_remove.append(city)
        for city in to_remove:
            del active[city]
        
        # check conflict with other cities
        for city, end in active.items():
            if city != c and end >= l:
                if earliest_conflict is None:
                    earliest_conflict = l
                else:
                    earliest_conflict = min(earliest_conflict, l)
                break
        
        # merge current interval
        if c in active:
            active[c] = max(active[c], r)
        else:
            active[c] = r
    
    print(earliest_conflict if earliest_conflict is not None else 0)

if __name__ == "__main__":
    solve()
```この実装では、現在アクティブな都市の辞書が維持されます。 各ステップでは、まず、現在の開始より前に終了する古い間隔を削除します。これは、将来の間隔と重複できないためです。 次に、競合チェックは残りのアクティブなエントリをスキャンし、現在の開始日に別の都市がまだアクティブであるかどうかを検出します。 

マージ ステップにより、同じ都市内の複数の重複する間隔が別々に蓄積されなくなります。そうでない場合、アクティブ セットが不必要に膨張します。 

最も古い競合は、最初に検出された重複ポイントで記録されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    data = inp.strip().split()
    n = int(data[0])

    active = {}
    ans = None

    for _ in range(n):
        l = int(data[idx]); r = int(data[idx+1]); c = int(data[idx+2])

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つの間隔が時間的に重複しているが、同じ都市に属している場合です。 入力用`[1, 10, 1]`そして`[2, 5, 1]`、アクティブな構造は単一のエントリを保持します`{1: 10}`合併後。 2 番目の間隔を処理するときは、別の都市が存在しないため、競合は発生しません。 これにより、同じ都市の合併によって誤検知が防止されることが確認されます。 

もう 1 つの特殊なケースは、次のインターバルが始まる前にインターバルが終了する場合です。 のために`[1, 2, 1]`に続く`[3, 4, 2]`の場合、クリーンアップ ステップでは、都市 1 の終了が次の開始よりも短いため、2 番目の間隔を処理する前に都市 1 が削除されます。 アクティブ セットは空になり、競合は検出されません。 

最後の微妙なケースは、複数の都市がカスケード状に重なっている場合です。 間隔がある場合`[1, 10, 1]`、`[2, 9, 2]`、`[3, 8, 3]`の場合、都市 1 がまだアクティブであるため、競合は 2 番目の間隔が開始する 2 日目に検出されます。 アルゴリズムは、新しい間隔がアクティブなタイムラインに入るたびに重複をチェックするため、常にそのような最も早い境界を検出します。
