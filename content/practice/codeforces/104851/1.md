 ## 解決策
 ## 問題の理解

 私たちは、すべてのセルに自然数が含まれ、中央のセルの周囲に広がる菱形のレイヤーに配置された無限グリッドを使用しています。 中央のセルには値 1 が含まれています。そこから、外側に向かってレイヤーごとに数字が埋められ、各レイヤーが前のレイヤーの周囲にダイヤモンド (ひし形) の境界を形成します。 各レイヤー内では、そのレイヤーの最上位のセルから塗りつぶしが開始され、レイヤーが完了するまで時計回りに進みます。 

グリッドが与えられる代わりに、中心を基準とした座標が与えられます。 中央のセルは座標 (0, 0) として扱われます。 クエリ (x, y) は、セルに書かれた数値 (x は右に、y は中央から上に 1 つずつ) を要求します。 この値は、(12345, 54321) などの非常に大きな座標ペアを含む 4 つの特定の座標ペアに対して直接計算する必要があるため、グリッド上のシミュレーションは完全に不可能になります。 

この問題にはクエリが 4 つしかありませんが、座標が大きくなる可能性があるため、レイヤーを明示的に構築しようとする試みは即座に排除されます。 半径 50,000 までのレイヤーを構築する場合でも、すでに数十億のセルが必要となり、時間とメモリの両方の制限を超えます。 どのソリューションでも、少量の算術推論の後、クエリごとに一定時間で答えを計算する必要があります。 

よくある落とし穴は、単純なマンハッタン距離マッピングのように対称性を仮定したり、正方形のグリッドに似た螺旋状の公式を試みたりすることです。 ここでは、菱形の成長により層境界の構造が変化するため、これは失敗します。各層は |x| によって定義されます。 max(x, y) ではなく、+ |y| です。 もう 1 つの微妙な問題は、番号付けの方向です。これは、位置を直接再構築しようとすると、上隅から時計回りに移動するとオフセットが発生し、カウントを間違えやすいためです。 

## アプローチ

 ブルートフォース解釈では、レイヤーの構築を明示的にシミュレートします。 中心から開始してレイヤーごとに拡張し、各菱形の境界を時計回りに移動しながら番号を割り当てます。 点 (x, y) の場合、半径が |x| に達するまですべてのレイヤーを構築します。 + |y| を実行し、走査順序を追跡してそのレイヤーにインデックスを付けます。 

このアプローチは、定義を正確に反映しているため、正しいです。 ただし、コストはクエリされた点の半径に応じて二次関数的に増加します。 (12345, 54321) のような座標の場合、レイヤー サイズは 70000 に比例し、各レイヤーには O(r) 個の境界要素が含まれているため、複数のレイヤーにわたって単純に実行すると、全体で O(r²) 個の構築になります。 これは実現可能な限界をはるかに超えています。 

重要な洞察は、グリッドは任意ではなく、マンハッタン距離による決定論的な階層化であるということです。 すべての点は、d = |x| によって決定される固有の菱形境界上にあります。 + |y|。 各層には、予測可能な周囲長と予測可能な開始インデックスがあります。 ポイントが菱形境界のどちら側に位置するかを特定したら、シミュレーションの代わりに線形演算を使用して、その境界に沿ったオフセットを直接計算できます。 

ブルートフォースから最適解への移行は、各層がサイズが線形に増加するサイクルであることを認識することであり、すべての座標は、菱形のどの端に位置するかという単純なケース分析を使用して、そのサイクル上の位置にマッピングできます。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。

1. 層インデックス d = |x| を計算します。 + |y|。 これにより、点がどの菱形の境界上にあるかが識別されます。 これが機能する理由は、同じマンハッタン距離にあるすべての点が同じ菱形レイヤーに属しているためです。 
2. 層 d の開始番号を計算します。 各層には 8d 個のセルがあり (d > 0 の場合)、層 d より前の要素の総数は三角形の累積を形成します。 これは、1 + sum_{k=1}^{d-1} 8k = 1 + 4(d-1)d として導出されます。 これにより、層 d の境界上の最初の番号が得られます。 
3. 菱形の境界の 4 つの辺のどの辺に点が位置するかを特定します。 ひし形には 4 つの方向のエッジがあり、各エッジは (x, y) 空間の線形セグメントに対応します。 

- 右上の辺、y = d、x が 0 から d に移動します。 
- 右下の辺、x = d、y が 0 から -d に移動します。 
- 左下辺、y = -d、x は d から -d に移動します。 
- 左上辺、x = -d、y は -d から d に移動します。 
4. (x, y) を、対応する辺に沿ったオフセットに変換します。 コーナーを除く各辺は 2D ステップに寄与し、その辺の開始頂点からの変位を計算します。 
5. このオフセットをレイヤー d の開始値に加算して、最終的な答えを取得します。 

### なぜ効果があるのか

 この構造により、各層が固定線形順序を備えた単純な閉ループであることが保証されます。 すべての座標は正確に 1 つのレイヤーとそのレイヤーの 1 つのエッジに属するため、(x, y) からサイクルに沿った位置へのマッピングは単射的です。 プレフィックスの合計式により、サイクルの正確な開始ラベルが確実にわかり、エッジ分解により決定論的なオフセットが保証されます。 各境界セグメントは端点を除いて互いに素であり、端点は走査順序によって一貫して割り当てられるため、2 つの異なる座標が同じ位置にマップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(x, y):
    d = abs(x) + abs(y)
    
    if d == 0:
        return 1
    
    start = 1 + 4 * (d - 1) * d
    
    if y == d:
        offset = x
    elif x == d:
        offset = d + (d - y)
    elif y == -d:
        offset = 3 * d + (d - x)
    else:
        offset = 4 * d + (y + d)
    
    return start + offset

# fixed queries from statement
queries = [
    (3, 2),
    (0, 10),
    (12, 0),
    (12345, 54321)
]

out = []
for x, y in queries:
    out.append(str(solve(x, y)))

print(" ".join(out))
```この実装では、まずマンハッタン半径によってクエリを分類し、ひし形層を決定します。 基本値の計算では、境界サイズの等差数列の閉じた形式が使用され、シミュレーションが回避されます。 

条件付き構造は、ひし形の 4 つのエッジを直接エンコードしたものです。 各ブランチは、上部の頂点から時計回りにダイヤモンドの片側に沿って歩くことに対応します。 よくある実装ミスは、各エッジでのトラバース方向を混同することです。これにより、サイド全体で一貫したオフバイ 1 シフトが発生します。 もう 1 つのよくある間違いは、コーナーが概念的には 2 つのエッジに属しているが、走査順序では 1 つのセグメントにのみ割り当てられていることを忘れていることです。

### 例 1: (x, y) = (0, 10)

 d = |0| を計算します。 + |10| = 10。これにより、ポイントがレイヤー 10 に配置されます。このレイヤーの開始値は次のとおりです。 

| ステップ | 値 |
 | --- | --- |
 | d | 10 |
 | 開始 | 1 + 4・9・10 = 361 |

 x = 0 および y = d であるため、点は上端にあります。 オフセットは x = 0 です。 

最終的な答えは 361 です。 

これにより、各レイヤーの最上位点が正確にそのレイヤーの開始点であることが確認されます。 

### 例 2: (x, y) = (12, 0)

 d = 12 を計算します。開始値は次のとおりです。 

| ステップ | 値 |
 | --- | --- |
 | d | 12 |
 | 開始 | 1 + 4・11・12 = 529 |

 ここでは y = 0 なので、符号に応じて右下または左下の境界にいます。 x = d であるため、これは右下のエッジです。 

オフセット = d + (d - y) = 12 + 12 = 24。 

最終的な答えは 529 + 24 = 553 です。 

これは、垂直方向のトラバースが開始される前に、水平エッジによってセグメント全体のシフトがどのように導入されるかを示しています。

 ## 特殊なケース

 中央のセル (0, 0) の場合、アルゴリズムはエッジ ロジックを入力せずに 1 を正しく返します。 これにより、d が 0 になり個別に処理されるため、層の計算における未定義の動作が回避されます。 

(d, 0) や (0, d) など、軸の境界上に正確に点がある場合でも、分類ではそれらを単一のエッジに決定的に割り当てます。 たとえば、(5, 0) では、d = 5 および x = d が得られるため、点は右下の端に配置されます。 オフセット式では、走査順序によってコーナーが 1 つのセグメントに正確に割り当てられるため、共有コーナーでのあいまいさがなくなります。 

(12345, 54321) のような大きな座標の場合、中間ステップでは最大約 10^9 までの整数の乗算のみを使用するため、Python の安全な整数範囲内に収まり、計算は安定します。
