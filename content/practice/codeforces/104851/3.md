 ## 解決策
 ## 問題の理解

 たった 3 文字を使用して、有効な文字列をいくつ形成できるかを数えるよう求められます。`a`、`o`、 そして`c`、2 つの制約があります。 各文字列は固定長でなければなりません`N`、およびそれ以上のキャラクターは出現できません。`K`単一の文字列内で何度も実行されます。 

したがって、無制限の文字列の代わりに、頻度が高い文字列のみをカウントします。`a`、`o`、 そして`c`制限内にとどまる`K`、文字の合計数は正確に`N`。 

出力について考えるのに役立つ方法は、配布するすべての方法を数えることです。`N positions`3 つの文字に対応する 3 つのビンの間で、各分布が生成する異なる順列の数を数えます。 分布は、どのビンもサイズを超えていない場合にのみ有効です。`K`。 

の値`N`そして`K`この問題のクエリは非常に小さく、4 つのクエリに固定されています。最大のケースは次のとおりです。`N = 20`。 これにより、広い範囲にわたって漸近的に最適化されたデータ構造または DP の必要性が即座に排除されます。 有効な周波数 3 倍体の状態空間が小さいため、直接組み合わせ列挙が可能です。 

すべての文字列を生成して有効性をチェックする単純な試みは、概念的には機能しますが、すでに不必要に重くなっています。`N = 20`探索することになるから`3^20`必要なものをはるかに超えた可能性。 

ここでよく見られる実装上の間違いは、制約がグローバルではなく文字ごとであることを忘れていることです。 たとえば、`N = 4, K = 3`のような文字列`aaaa`文字が 1 文字だけであっても、制限を超えているため無効です。`a`、文字列は次のようになります`aaao`有効です。 

もう 1 つの微妙な問題は、周波数 3 倍を固定せずに順列を列挙しようとすると二重にカウントされることです。これは、異なる順列が同じマルチセット構成に対応し、個別にカウントする必要があるためです。 

## アプローチ

 ブルートフォース手法では、考えられるすべての長さの文字列が構築されます。`N`3 文字にわたって、それぞれの文字が頻度制約を遵守しているかどうかをチェックします。 これは各文字列が独立して検証されるため機能しますが、次のように展開されます。`3^N`候補者たち。 のために`N = 20`、これは約 34 億の文字列であり、検証を考慮する前でも大きすぎます。 

重要な観察は、同じ頻度カウントを持つ文字列は均等に寄与し、グループ化できるということです。 文字列を明示的に構築する代わりに、各文字が出現する回数を選択するだけで済みます。 もし`a`表示されます`i`回、`o`表示されます`j`回、そして`c`表示されます`k`回の場合は、次のようにする必要があります`i + j + k = N`せいぜいそれぞれの人と`K`。 有効なトリプルごとに、文字列の数が多項係数になります。`N! / (i! j! k!)`。 

これにより、問題はすべての有効な整数のトリプルを反復処理することになります。`(i, j, k)`制限された範囲内で組み合わせ値を合計します。 以来`N ≤ 20`、そのようなトリプルの数は最大でも約 231 の組み合わせであり、これはわずかです。

 | 文字列に対するブルートフォース | O(3^N) | O(N) | 遅すぎる |
 | 周波数の列挙 | O(K^2) (N で区切られる) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 有効な周波数割り当てを列挙することで答えを計算します。 

1. 値を固定する`i`の数に対して`a`からのキャラクター`0`に`K`有効な解決策は文字ごとの上限を超えることができないためです。 これにより、検索空間の 1 つの次元が制限されます。 
2. 値を固定する`j`の数に対して`o`キャラクター、再びから`0`に`K`。 この時点で、残りのカウントが強制されます。 
3. コンピューティング`k = N - i - j`、それは何個かを表します`c`文字列を完成するには文字が必要です。 これにより 3 番目のループが回避され、全長の制約が常に遵守されるようになります。 
4. かどうかを確認します。`k`中にある`[0, K]`。 そうでない場合、この周波数トリプルは無効であり、何も寄与しません。 
5. 有効なトリプルごとに`(i, j, k)`、多項係数を計算します`N! / (i! j! k!)`、これらの周波数を持つマルチセットの個別の順列の数をカウントします。 
6. これらの値を累積して累計し、それが最終的な答えとなります。 

### なぜ効果があるのか

 すべての有効な文字列は、正確に 1 つの周波数トリプルに対応します。`(i, j, k)`。 各トリプルは、そのマルチセットの個別の順列の数に正確に寄与します。 この列挙は、実行可能なすべてのトリプルを重複なくカバーするため、有効な文字列はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import factorial

def solve():
    N, K = map(int, input().split())
    ans = 0

    for i in range(K + 1):
        for j in range(K + 1):
            k = N - i - j
            if 0 <= k <= K:
                ans += factorial(N) // (factorial(i) * factorial(j) * factorial(k))

    print(ans)

solve()
```実装は組み合わせ解釈に直接続きます。 ネストされたループは列挙します`i`そして`j`、 その間`k`不要な反復を避けるために導出されます。 階乗ベースの多項計算は安全です。`N`は最大 20 であるため、すべての値は小さいままであり、整数演算は正確です。 

よくある間違いは反復することです`k`これは、冗長なチェックを導入し、ループの複雑さを増大させますが、メリットはありません。 もう 1 つの潜在的な落とし穴は、ループ内で階乗を繰り返し再計算することです。 ここでは小さな制約があるため許容されますが、問題のより大きなバージョンでは事前計算が必要になります。 

## 実用的な例

 2 つの代表的なケースのロジックを追跡します。 

### 例 1: N = 3、K = 1

 各キャラクターに最大 1 回のみ許可されます。 

| 私 | j | k = 3 - i - j | 有効 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 3 | いいえ | - |
 | 0 | 1 | 2 | いいえ | - |
 | 0 | 2 | 1 | いいえ | - |
 | 0 | 3 | 0 | いいえ | - |
 | 1 | 0 | 2 | いいえ | - |

 のみ`(1,1,1)`有効です、生成します`6`順列、すべての順列に一致する`a`、`o`、`c`。 

### 例 2: N = 4、K = 3

 文字が 4 回出現する場合のみを除外します。 

有効な構成には、合計が 4 になるすべてのトリプルが含まれます。`(4,0,0)`、`(0,4,0)`、`(0,0,4)`。 

合計は`3^4 = 81`3 つの無効な均一文字列を引くと、次のようになります。`78`。 

これは、制約によって、組み合わせ空間の大部分がそのまま残されたまま、極端な構成のみがどのように削除されるかを示しています。

## テストケース```python
import sys, io
from math import factorial

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    N, K = map(int, input().split())
    ans = 0

    for i in range(K + 1):
        for j in range(K + 1):
            k = N - i - j
            if 0 <= k <= K:
                ans += factorial(N) // (factorial(i) * factorial(j) * factorial(k))

    return str(ans)

# provided samples (interpreted)
assert run("3 1") == "6"
assert run("3 3") == "27"

# custom cases
assert run("4 3") == "78", "N=4 excludes only uniform strings"
assert run("2 1") == "6", "all distinct permutations only"
assert run("1 1") == "3", "single letters"
assert run("20 10") == "3093092574", "largest case"

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`K >= N`。 この状況では、どの文字も超過できないため、制約は無関係になります。`N`とにかく出来事。 すべてのトリプルの合計は次のようになるため、アルゴリズムはこれを自然に処理します。`N`が受け入れられ、多項和は次のように崩壊します。`3^N`。 

たとえば、`N = 3, K = 3`、トリプルごとに`(i, j, k)`合計は 3 になります。 アルゴリズムはそれらをすべて列挙し、`27`、3 文字のアルファベット上の文字列の完全なセットと一致します。 

別のエッジケースが発生するのは次の場合です。`K = 0`。 ここでは空の代入のみが有効になりますが、`N > 0`、トリプルでは満足できません`i + j + k = N`、したがって、答えは次のようになります`0`。 このシナリオでは、列挙によって有効な構成が正しく生成されません。
