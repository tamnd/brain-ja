 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノード。 ノードは単なる構造物ではなく、道路で結ばれた観光地を表しており、どの道路も 1 歩のコストは同じです。 グラフはツリーであるため、任意の 2 つの場所の間には単純なパスが 1 つだけあり、そのパスの長さはその上のエッジの数になります。 

ここで、ラベルのランダムな並べ替えを割り当てると想像してください。$1$を通して$n$ノードに。 ラベルを付けた後は、ラベルの昇順でノードを訪問する必要があります。最初に 1 というラベルが付けられたノード、次に 2 というラベルが付けられるノードが最後まで続きます。$n$。 合計トリップ長は、このラベル順序での連続する訪問ノード間の最短パス距離の合計です。 

タスクは、すべての距離にわたるこの合計距離の期待値を計算することです。$n!$ラベルの順列。 

制約は次のとおりです$n = 2 \cdot 10^5$、二次関数や偶数関数は即座に除外されます。$O(n \log n)$順列ごとに。 答えはすべてのノードのペアとすべての順列に依存するため、問題をエッジごとの寄与のカウントに減らす構造的な期待引数が必要です。 

微妙なエッジケースは次のような場合です$n = 1$。 エッジも動きもないので、答えはゼロでなければなりません。 もう 1 つの例外的なケースは、多くの最短パスが中心を共有する星形のツリーです。 パスの独立性を前提とした単純なアプローチでは、そのような構造では寄与を大きく誤ってカウントすることになります。 

## アプローチ

 このプロセスについて考える直接的な方法は、順列を修正してシミュレーションすることです。 与えられた順序に対して、ツリー最短パスを毎回実行することにより、連続するノード間の距離を計算します。$O(n)$単純に実行した場合はクエリごと、または$O(n \log n)$前処理を行った場合でも、順列ごとの全体的な結果が得られます。 あるので$n!$順列、これは非常に小さい場合でも不可能です$n$。 

ポイントは視点を逆転させることです。 フルパスを追跡する代わりに、特定のエッジがどれくらいの頻度で答えに寄与するかを尋ねます。 2 つのノード間のすべてのパスは一意に決定されるため、各エッジは、順列内の連続する要素間のパス上にあるときに正確に寄与します。 

エッジを修正する$e$。 これを削除すると、ツリーがサイズの 2 つのコンポーネントに分割されます。$a$そして$b = n - a$。 次に、ランダムな置換を考えてみましょう。 エッジは、順列内の 2 つの隣接する位置がこのカットの異なる側に属している場合に限り、2 つの連続する要素間の距離に寄与します。 したがって、問題は、ランダムな並べ替えで予想される隣接するクロスコンポーネントのペアをカウントすることに帰着します。 

ランダムな置換では、個別のノードの順序付きペアはすべて、どちらの順序でも連続して出現する可能性が等しくなります。 2 つの特定のノードが存在する確率$u$そして$v$順列で隣接して現れるのは$\frac{2}{n} \cdot \frac{1}{n-1} = \frac{2}{n(n-1)}$ただし、順序付きペアを直接数えることによってエッジ上の線形性を使用する方がよりクリーンです。 

エッジ用$e$、 がある$a \cdot b$ペア$(u,v)$そのような$u$1 つのコンポーネント内にあり、$v$もう一方にあります。 このような順序ペアにはそれぞれ確率があります$\frac{1}{n(n-1)}$順列順序付けプロセスでその方向に連続しているように見えること。 両方の方向が寄与し、それぞれがこのエッジを横切る距離 1 に寄与するため、エッジの期待される寄与は$e$は：$$\frac{2ab}{n(n-1)}.$$すべてのエッジを合計すると、最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. ツリーを読み取り、隣接リストを保存します。 これは、一度走査してサブツリーのサイズを計算できるようにするために必要です。 
2. 任意のノード (通常はノード 1) でツリーをルート化し、DFS を実行してサブツリーのサイズを計算します。 すべてのノードについて、そのサブツリー内にノードがいくつあるかを計算します。 
3. DFS ツリー内のノードとその親の間のエッジを処理する際、カットの一方の側のサイズを子のサブツリー サイズとして決定し、もう一方の側のサイズを次のように決定します。$n - \text{subtree}$。 
4. 各エッジについて、次の式を使用してその寄与を計算します。$$\frac{2 \cdot a \cdot b}{n(n-1)}.$$5. すべての寄与を合計し、結果を浮動小数点数として出力します。 

DFS 構造により、子と親の関係を処理するときにすべてのエッジが 1 回だけ考慮されるため、二重カウントが回避されます。 

### なぜ効果があるのか

 各エッジは、順列内の 2 つの連続するノード間のパス上にある場合は常に、正確に 1 の距離に寄与します。 順列は均一であるため、隣接構造により、連続して出現するノードの順序付きペアに対して均一な確率が生じます。 ツリー構造により、各エッジがクリーンな 2 分割に対応することが保証され、サブツリーのサイズによってそのエッジによって分離されるペアの数が完全に決まります。 期待値の線形性により、相互作用を気にせずにエッジ全体で独立して寄与を合計できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())
        g = [[] for _ in range(n + 1)]
        edges = []

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)
            edges.append((u, v))

        if n == 1:
            out.append("0.000000")
            continue

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                parent[v] = u
                stack.append(v)

        sz = [1] * (n + 1)

        for u in reversed(order):
            for v in g[u]:
                if v == parent[u]:
                    continue
                sz[u] += sz[v]

        denom = n * (n - 1)
        ans = 0.0

        for u in range(2, n + 1):
            p = parent[u]
            a = sz[u]
            b = n - a
            ans += 2.0 * a * b / denom

        out.append(f"{ans:.7f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、明示的な DFS 順序を構築することで再帰の深さの問題を回避します。 サブツリーのサイズは逆の順序で計算されるため、子は親よりも前に処理されます。 ルートを除く各ノードは、その親への 1 つのエッジに正確に対応するため、2 から$n$寄付金を合計するには十分です。 

必要な精度が次のとおりであるため、浮動小数点除算が直接使用されます。$10^{-6}$、式には最大の値が含まれます。$O(n^2)$なので、倍精度で十分です。

 ## 特殊なケース

 のために$n = 1$の場合、DFS はエッジを生成しないため、答えはゼロでなければなりません。 アルゴリズムはこれを明示的にチェックし、式内でのゼロ除算を回避してすぐに戻ります。 

チェーン形状のツリーの場合、各エッジによってツリーがプレフィックスとサフィックスに分割されるため、サブツリーのサイズは体系的に変化します。 DFS ベースの計算はこれらのサイズを正確に取得し、各エッジは分割の不均衡に比例して寄与します。 

スターの場合、すべてのエッジの片側のサイズは 1 です。ルートを除く各ノードのサブツリー サイズが 1 であり、寄与がすべての葉にわたって均一になり、予想される順列の対称性と一致するため、アルゴリズムはこれをきれいに処理します。
