 ## 問題の理解

 大きな整数が与えられます$N$そして別の整数を構築する必要があります$X$それは厳密に以下よりも小さいです$N$ですが、2 による除算の繰り返しに関連する非常に特殊な構造特性も満たします。 

制約とは単に奇妙であるということだけではありません。 繰り返し分割する場合にもそれが必要です$X$1 に達するまで 2 ずつ増加する場合、すべての中間値は奇数のままでなければなりません。 つまり、次のバイナリ表現は、$X$唯一許可される停止点である 1 に到達する瞬間を除いて、半減プロセス中に偶数を生成してはなりません。 

これは、ここでは 2 のべき乗が特別であることをすぐに示唆しています。 2 の因数を持つ数値は最終的に 1 に達する前に偶数まで減少するため、条件に違反します。 2 による除算を繰り返しても偶数にならずに生き残る唯一の数は、除算の各段階ですでに奇数であるため、次の形式になります。$2^k - 1$つまり、完全に 1 で構成される 2 進数です。 

したがって、タスクはフォームの最大数を見つけることになります。$2^k - 1$それは厳密に以下です$N$。 

入力サイズにより総当たり攻撃は不可能になります。 と$T$まで$2 \cdot 10^5$そして$N$まで$10^{18}$、候補に対するテストごとの反復またはビットレベルのシミュレーションは遅すぎます。 クエリごとに直接ビット操作または数学的構築が必要です。 

よくある失敗例は、条件の誤解から生じます。 たとえば、次の場合$N = 10$単純なアプローチでは、10 未満の最大の奇数である 9 を選択する可能性があります。しかし、9 → 4 → 2 → 1 には偶数値が含まれており、ルールに違反するため、9 は無効です。 正解は7です。 

もう 1 つの微妙な間違いは、すべての奇数が機能すると考えることです。 2 進形式がすべて 1 である数値のみが有効です。 それははるかに小さいセットです。 

## アプローチ

 直接的な総当りのソリューションでは、以下から減少させようとします。$N-1$各チェックでは、1 に達するまで除算を繰り返し、すべての中間値が奇数のままであることを確認する必要があります。 最悪の場合、これには時間がかかります$O(\log N)$番号ごとに最大でスキャンできます$O(N)$候補者にとっては完全に不可能です$10^{18}$。 

重要な観察は、妥当性条件によって厳格なバイナリ構造が強制されるということです。 半減を繰り返しても決して均等にならない数値は、中間ステップごとに 2 の因数を避ける必要があります。 このプロパティを維持する唯一の数値は、バイナリ形式ですべてのビットが 1 である数値です。 つまり、有効な数値は正確に次のとおりです。$1, 3, 7, 15, 31, \dots$。 

したがって、整数を検索する代わりに、ビット長を検索します。 どれについても$N$、フォームの最大値を見つけます。$2^k - 1$それでも厳密には以下です$N$。 これは、次のビット長を取得することで導出できます。$N$そしてそのすぐ下に候補を構築します。

 ## アルゴリズムのチュートリアル

 1.変換$N$バイナリ表現に変換するか、最高の設定ビットを決定します。 これは、以下を超えない最大の 2 の累乗を特定します。$N$。 このステップでは、回答のスケールを設定します。 
2. コンピューティング$k$、のビット数$N$。 これはつまり$2^{k-1} \le N < 2^k$。 これを使用して、より少ないビットですべて 1 を持つ最大の候補を構築します。 
3. 候補を作成する$C = 2^{k-1} - 1$。 これは、以下の 2 の最大乗を厳密に下回る最大のオール 1 の数です。$N$。 1 を減算する理由は、先頭の 1 とその後にゼロが続く 1 つをすべて 1 に変えるためです。 
4. もし$C < N$、 戻る$C$。 それ以外の場合は、ビット長を 1 つ減らして構築します。$C = 2^{k-2} - 1$、それからそれを返します。 これは次のような場合に対処します。$N$それ自体は 2 の累乗境界のすぐ上にあります。 

### なぜ効果があるのか

 有効な数値は次の形式でなければなりません$2^k - 1$2 による除算を繰り返すと、すべて 1 の数値についてのみ末尾の 2 進構造がきれいに削除されるためです。 これらはまさに、バイナリ表現が中間の半分のステップでゼロを導入しない数値です。 したがって、答えは以下の最大の数値でなければなりません$N$。 これらの数値は指数関数的に増加するため、ビット長境界付近で最大 1 つまたは 2 つの隣接する候補をチェックするだけで十分であり、常に正しい最大値に到達することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input().strip())

        # find highest power of two <= n
        k = n.bit_length()

        # candidate with k-1 bits all ones
        cand = (1 << (k - 1)) - 1

        if cand < n:
            print(cand)
        else:
            cand = (1 << (k - 2)) - 1
            print(cand)

if __name__ == "__main__":
    solve()
```解決策は完全にビット長に依存します。 表現`n.bit_length()`最小のものを与える$k$そのような$n < 2^k$。 これから、以下の最大のオール 1 の数を構築します。$2^{k-1}$、これはすぐ下の自然な候補です$N$。 その候補が厳密に以下より小さい場合は、$N$、1つ下のレベルに進みます。 

減算パターン`(1 << x) - 1`は核となる変換です。これは、単一のセット ビットを一連の 1 に変換します。これは、問題の状態から導き出される構造要件と正確に一致します。 

注意が必要な場合$k = 1$、しかしそれ以来$N \ge 2$、これにより 2 番目のブランチで無効なシフトが発生することはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input().strip())
        k = n.bit_length()
        cand = (1 << (k - 1)) - 1
        if cand < n:
            out.append(str(cand))
        else:
            out.append(str((1 << (k - 2)) - 1))
    return "\n".join(out)

# provided samples (illustrative)

assert run("1\n1\n") == "0"

 ## 特殊なケース

 のために$N = 2$、ビット長は 2 です。候補は次のようになります。$2^{1} - 1 = 1$、これは有効であり、厳密に小さいです。 

のために$N = 3$、第一候補は$1$これは有効で 3 未満であるため、フォールバックは必要ありません。 

のために$N = 8$の場合、最初の候補は 7 であり、厳密な不等式を満たさないため、強制的に 3 にフォールバックされます。アルゴリズムはビット長を正しく 1 つ減らします。 

非常に大きな値の場合、$10^{18}$、ビット長のみが重要です。 Python はオーバーフローせずに 64 ビットのビット演算を直接処理するため、構造は安定しています。
