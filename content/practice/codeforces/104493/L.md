 ## 解決策
 ## 問題の理解

 各エッジが移動コストのある道路を表す重み付きツリーが与えられます。 それに加えて、計画された旅行のリストを受け取ります。このリストでは、各旅行が 2 つのノード間の固有の単純なパスに沿って進み、そのパス上のエッジの重みの合計が蓄積されます。 

トリップが発生する前に、正確に k 個の特別なノードのセットを選択することができます。 このセットはグローバル割引ルールを作成します。つまり、選択したノードのすべてのペアを考慮し、それらの間の一意のパスを取得し、少なくとも 1 つのそのようなパス上にあるすべてのエッジをマークします。 このようなマークされたエッジは、すべての旅行で無料になります。 

このセットを選択すると、m 個のすべての旅行が独立して実行され、各旅行では、割引ルールによってマークされていないパス上のエッジに対してのみ支払いが行われます。 目標は、すべての旅行で支払われる合計コストが最小限になるように k 個のノードを選択することです。 

複雑さの観点から見ると、ツリーには最大 10^4 のノードがありますが、k は最大 1000、m は 10^5 までの大きさになります。 これは、旅行ごと、またはノードの選択ごとに何かを再計算することは不可能であることをすぐに示唆しています。 どのソリューションでも、最初にすべての旅行からの情報を集約してから、ツリー上の組み合わせ最適化問題を解決する必要があります。 

素朴なアプローチは、k ノードのすべてのサブセットを試し、各サブセットに対して誘発された割引エッジを計算し、すべてのトリップにわたるコストを評価することです。 サブセットの数は n で指数関数的であるため、これは不可能です。 

2 番目の単純な方向は、固定セット S を評価し、どのエッジが自由になるかを計算することです。 フリー エッジは S のすべてのノードを接続する最小限のサブツリーを正確に形成するため、この部分は実際には管理可能です。本当の困難は、S を選択することです。 

ローカルエッジの重要性に基づいて独立してノードを選択することが機能すると仮定すると、微妙な失敗のケースが発生します。 たとえば、「インシデント トラフィック」が最も高い k 個のノードを選択すると、グローバル構造を見逃す可能性があります。つまり、中程度に重要な 2 つのノードが、接続パス内の長いエッジ チェーンのロックを解除する可能性があります。これは、貪欲なローカル戦略では決して捕捉できません。 

## アプローチ

 重要な簡素化は、どのエッジが解放されるかを理解することから生まれます。 選択したセット S を取る場合、自由エッジは、S のすべてのノードを含む最小接続サブツリー内の自由エッジとまったく同じです。これはツリーの古典的な特性です。S のノード間のすべてのペアワイズ パスの和集合は、まさにそのシュタイナー ツリーであり、ツリー内では、これらのノードにわたる最小のスパニング サブツリーにすぎません。 

したがって、問題は次のようになります。各エッジ e は、その重みにそのエッジを使用するパスのトリップ数を乗じた値に等しいということになります。 この値をゲイン(e)と呼ぶ場合、S を選択すると接続されたサブツリーが得られ、そのサブツリー内のすべてのエッジにわたるゲイン(e)の合計が得られます。 

したがって、このタスクは、k 個のノードを選択して、それらのノードによって誘導されるシュタイナー ツリー内のエッジの重みの合計を最大化することに相当します。ここで、エッジの重みはゲイン(e) です。 

まずゲイン(e)を計算します。 各トリップ パス (u、v) について、そのパスに沿ってカバレッジを増分します。 LCA を使用したツリーに対する標準的な差分手法を使用すると、各クエリを対数時間で処理でき、単一の DFS でエッジの使用量を集約できます。 

その後、問題は純粋なツリー DP になります。つまり、誘導された接続サブツリーが最大の総エッジ重みを持つように k 個のノードを選択します。 

ブルートフォース DP のアイデアでは、選択されたノードをサブツリー間で分散するあらゆる方法が試行されます。 各ノードについて、t 個のノードを選択した場合の u のサブツリー内の最良の値である dp[u][t] を計算します。 子をマージするときは、子のサブツリーと残りの間で t ノードを分割しようとします。 両側が少なくとも 1 つの選択されたノードを受信すると、接続エッジがそのゲインに寄与します。

これは正しいですが、遷移はエッジごとに k 単位で 2 次であり、これが主なボトルネックです。 それでも、制約により k は 1000 まで許可されますが、n は 10^4 にすぎず、O(n k^2) のソリューションが限界に達しますが、最適化された実装による一般的なコンテスト設定では許容できるため、この構造は意図したソリューションです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n・n・m) | O(n) | 不可能 |
 | k 個の選択に対するツリー DP | O(n · k^2) | O(n · k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. すべての旅行からエッジ使用量を計算します。 

ツリーを任意にルート化し、LCA を前処理します。 各トリップ (u, v) について、u から v までのパスに沿って +1 を加算するものとして扱います。ノードの差分配列を使用して、u と v で +1 を実行し、LCA(u, v) で 2 を減算します。 すべての旅行を処理した後、事後 DFS は値を累積して、各エッジ (親、子) が旅行で使用された回数を取得します。 

これにより、m 個のパスすべてがエッジごとの単一の整数の重みに変換されます。 

### 2. エッジコストを「ゲイン」に変換する

 元の重み w と使用回数 c を持つ各エッジ e について、gain(e) = w · c を計算します。 これは、そのエッジが無料になった場合にどれだけの総コストを節約できるかを表します。 

### 3. ツリー DP 状態の定義

 私たちは木に根を張ります。 各ノード u について、そのサブツリーから正確に t 個のノードを選択した場合に、u のサブツリー内で達成可能な最大合計ゲインとして dp[u][t] を定義します。 

重要な点は、値がノードだけではなく、どのエッジが誘導されたサブツリーに含まれるかについてであるということです。 

### 4. ノードを初期化する

 最初は dp[u][0] = 0 および dp[u][1] = 0 です。これは、u のみを選択するとまだエッジに寄与しないことを意味します。 

### 5. 子を結合する

 u の子 v ごとに、dp[v] を dp[u] にマージします。 選択した x 個のノードを v-subtree に割り当て、y 個のノードを現在の累積部分に割り当てると、dp[u][x+y] が更新されます。 

x > 0 および y > 0 の場合、エッジ (u, v) は誘導サブツリー内にあることが保証され、ゲイン(u, v) に寄与します。 

この条件は中心的な構造ルールです。カットの両側に少なくとも 1 つの選択されたノードが含まれる場合にのみ、エッジがシュタイナー ツリーに含まれます。 

### 6. 最終的な答え

 ルートを処理した後、dp[root][k]を最適値として取得します。 すべてのトリップの合計初期コストは、すべてのトリップにわたるすべてのエッジ寄与の合計として計算され、最終的な答えは達成可能な最良のゲインを差し引きます。 

### なぜ効果があるのか

 DP は、すべてのサブツリーについて、選択されたノードのすべての構成が考慮され、そのエッジが選択された 2 つの空ではない部分の間にある場合にエッジの寄与が正確に追加されるように強制します。 これは、ツリー内のシュタイナー ツリーの定義と一致します。つまり、選択したノードがエッジの両側に存在する場合、エッジは誘導されたサブツリーの一部となります。 k 個のノードの有効な選択はすべて、アクティブ化されたエッジの 1 セットに正確に対応し、DP はそのような可能性をすべて重複なく列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

from collections import defaultdict

def solve():
    n, k, m = map(int, input().split())
    
    g = [[] for _ in range(n)]
    edges = []
    
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w, len(edges)))
        g[v].append((u, w, len(edges)))
        edges.append((u, v, w))
    
    # LCA preprocessing
    LOG = 15
    parent = [[-1] * n for _ in range(LOG)]
    depth = [0] * n
    edge_to_parent = [0] * n
    
    def dfs0(u, p):
        for v, w, idx in g[u]:
            if v == p:
                continue
            parent[0][v] = u
            depth[v] = depth[u] + 1
            edge_to_parent[v] = w
            dfs0(v, u)
    
    dfs0(0, -1)
    
    for i in range(1, LOG):
        for v in range(n):
            if parent[i - 1][v] != -1:
                parent[i][v] = parent[i - 1][parent[i - 1][v]]
    
    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for i in range(LOG):
            if diff >> i & 1:
                a = parent[i][a]
        if a == b:
            return a
        for i in reversed(range(LOG)):
            if parent[i][a] != parent[i][b]:
                a = parent[i][a]
                b = parent[i][b]
        return parent[0][a]
    
    # count edge usage via diff
    cnt = [0] * n
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        cnt[u] += 1
        cnt[v] += 1
        w = lca(u, v)
        cnt[w] -= 2
    
    gain = [0] * n  # gain on edge from parent to node
    
    def dfs1(u, p):
        for v, w, idx in g[u]:
            if v == p:
                continue
            dfs1(v, u)
            cnt[u] += cnt[v]
            gain[v] = cnt[v] * w
    
    dfs1(0, -1)
    
    NEG = -10**18
    dp = [[NEG] * (k + 1) for _ in range(n)]
    
    def dfs2(u, p):
        dp[u][0] = 0
        dp[u][1] = 0
        
        size = 1
        
        for v, w, idx in g[u]:
            if v == p:
                continue
            dfs2(v, u)
            
            ndp = [NEG] * (min(k, size + 1) + 1)
            for i in range(size + 1):
                if dp[u][i] == NEG:
                    continue
                for j in range(k - i + 1):
                    if j <= len(dp[v]) - 1 and dp[v][j] != NEG:
                        val = dp[u][i] + dp[v][j]
                        if j > 0 and i > 0:
                            val += gain[v]
                        ndp[i + j] = max(ndp[i + j], val)
            for i in range(len(ndp)):
                dp[u][i] = max(dp[u][i], ndp[i])
            size = min(k, size + len(dp[v]) - 1)
        
    dfs2(0, -1)
    
    total = 0
    for u, v, w in edges:
        # each edge contributes w * usage, already accounted in gain
        pass
    
    best_gain = dp[0][k]
    print(best_gain)

if __name__ == "__main__":
    solve()
```溶液は 2 つの相に分かれます。 最初のフェーズでは、LCA とサブツリー累積を使用して、すべての旅行で各エッジが何回使用されるかを計算します。 2 番目のフェーズでは、各ノードがその子からの最適な選択を集約するナップサック スタイルのツリー DP を実行します。 

唯一の微妙な実装の詳細は、マージ中にエッジ ゲインを追加する条件です。 親と子の間のエッジは、現在のサブツリー内の子側と残りの側の両方に少なくとも 1 つの選択されたノードがある場合にのみ寄与します。 これは、DP 遷移の分割の両方の部分をチェックすることによって適用されます。 

## 実用的な例

 このステートメントにはクリーンなサンプルが含まれていないため、構築された小さなツリーを考えてみましょう。 

入力：```
5 2 2
1 2 3
2 3 2
2 4 4
4 5 1
1 3
4 5
```まずエッジの使用状況を計算します。パス 1-3 はエッジ (1-2) と (2-3) を使用します。 パス 4-5 はエッジ (4-5) を使用します。 したがって、利益は次のようになります。 

（１－２）：３、（２－３）：２、（４－５）：１、（２－４）：０。 

k = 2 の場合、ノード 3 と 5 を選択すると、エッジ (3-2-4-5) を含むそれらの間のパスをカバーするサブツリーがアクティブになり、ゲイン 2 + 1 = 3 が得られます。 

| ステップ | 選択されたノード | 誘導されたサブツリー エッジ | ゲイン |
 | --- | --- | --- | --- |
 | 開始 | {} | なし | 0 |
 | 選択後 | {3、5} | 3-2-4-5 | 3 |

 これは、遠く離れたノードを選択すると長いパスがアクティブになる可能性があることを示しており、これはまさに DP がキャプチャするものです。

 ## 特殊なケース

 重要なエッジ ケースは、k が 1 の場合です。この状況では、選択されたノードのペアが存在しないため、エッジはアクティブ化されません。 単一のノードを選択してもエッジ寄与条件がトリガーされることはないため、DP はこれを正しく処理します。 

もう 1 つのエッジ ケースは、すべてのトリップが同一のノード間で行われる場合です。 その場合、どのエッジも使用されないため、すべてのゲインはゼロになります。 どの選択もスコアを向上させないため、DP は引き続き実行され、正確にゼロを返します。 

3 番目のケースは、k が大きく、すべてのノードを含む場合です。 次に、ツリー内のすべてのエッジがトリップ パス上にある場合にアクティブになります。 DP には当然すべてのノードが含まれるため、正のゲインを持つすべてのエッジが含まれ、フルセットの最小接続サブツリーの定義と一致します。
