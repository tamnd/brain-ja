 ## 解決策
 ## 問題の理解

 n 個のセクションに分割された直線的な川が与えられています。 各セクションには最初、ある程度の数の魚が含まれています。 各セクションには閉じてスタートするネットもあります。 

操作は、これまでに選択されていないセクション i を選択し、そのネットを開くことで構成されます。 これが起こると、セクション i に現在座っているすべての魚が右に進みます。 彼らは網がまだ閉じられている最初のセクションに到達するまで移動し、そこで止まり、そのセクションの魚数に加わります。 一度ネットが開かれると、ネットは永続的に開いたままになるため、セクションは徐々にバリアとして機能しなくなります。 

各作業の後、川のどのセクションでも魚の最大数を報告する必要があります。 

重要な点は、魚が恣意的に再分配されないことです。 これらは常に次のまだ閉じているセクションに移動するため、構造は残りの閉じた位置によって定義されるセグメント上で動的結合システムのように動作します。 

制約はテスト全体で n と Q の合計が 10^5 に達するため、魚ごとまたは操作ごとの動きをシミュレートするソリューションは遅すぎます。 O(nQ) でさえ、最悪の場合 10^10 に達するため、直ちに実行不可能になります。 

微妙なエッジケースは、すでに開いているセクションを繰り返しジャンプすることで発生します。 セクションが開くと、魚を直接受け取ることはなくなりますが、ランディング前に複数のオープンセクションをスキップする移動の開始点として機能する可能性があります。 

たとえば、次のことを考えてみましょう。 

n = 5

 a = [1、2、3、4、5]

 セクション 2 を開く

 セクション 2 のすべての魚はセクション 3 に移動します (右側にある最初の魚であるため)。 ここでセクション 3 を開くと、3 の魚は 4 にジャンプしますが、以前に 3 に到着していた魚も移動します。 集約された状態を維持しない単純なシミュレーションでは、そのカスケード的な蓄積が見逃されます。 

主な困難は、値と最大値を動的に追跡しながら、「次のクローズ ポジション」構造を効率的に維持することです。 

## アプローチ

 ブルート フォース シミュレーションでは、魚数の配列と開いた網または閉じた網のブール配列を明示的に維持します。 インデックス i での各操作について、最初の閉じたセクション j が見つかるまで右にスキャンし、すべての魚を i から j に移動します。 最後に、すべてのセクションの最大値を再計算します。 

これは論理的に機能しますが、最悪の場合、各操作で O(n) 個の位置をスキャンする必要があり、最大値の再計算にも O(n) のコストがかかります。 Q が 10^5 までの場合、これは O(nQ) となり、遅すぎます。 

重要な観察は、どのセクションも最大で 1 回しかオープンされず、セクションがオープンされると、そのセクションは着地点として永久に消滅するということです。 これは、「次に利用可能なクローズドポジション」をめぐる素のセット構造を示唆しています。 

各位置がその右側のまだ閉じている次のセクションを指すユニオン検索 (DSU) を維持すると、セクション i が開いたときに、検索操作を使用してその魚がどこに着水するかをすぐに見つけることができます。 i を処理した後、i+1 にマージすることで、i を有効な着陸位置ではなくなったとマークします。 これにより、i を介して次の閉じられたセクションに直接渡される今後のすべてのクエリが圧縮されます。 

DSU と並行して、私たちは現在の一連の魚数と世界最大数を維持しています。 各操作では 2 つの DSU 検索と 1 つの更新のみを行うため、アレイ全体をスキャンすることは避けられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nQ) | O(n) | 遅すぎる |
 | DSU / ネクスト ポインタ圧縮 | O((n + Q) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`fish`初期値で。 これは各セクションの現在の魚を表します。 
2. 各インデックス i が最初にそれ自体を指す DSU 構造を構築します。また、概念的には n+1 を「有効な閉じられたセクションがない」ことを表すセンチネルとして扱います。 
3. 配列を維持する`parent`どこ`parent[i]`は、i から始まる次の閉区間候補を表します。 初期状態では、すべてのポジションは自身の親です。 
4. セクション i の各操作について、まず i がすでに開いているかどうかを確認します。 すでに開いている場合でも、指定されたとおりに操作を処理しますが、この問題では明確な選択肢が保証されているため、これは主に安全性のためです。 
5. を使用します。`find(i)`最初の閉じたセクション j を i または i の右側に配置する操作。 i からのすべての魚がここに移動されます。 
6.追加`fish[i]`に`fish[j]`、リセットします`fish[i]`魚が完全に移送されたため、ゼロになります。 
7. 新しい値を使用してグローバル最大値を更新します。`fish[j]`。 
8. i+1 と結合して i をオープン済みとしてマークします。これは、今後の検索で i が完全にスキップされることを意味します。 

これらのステップの後、システムは各操作後に常に正しい魚の蓄積を反映し、最大値が直接追跡されます。 

### なぜ効果があるのか

 DSU は常に、次の不変条件を維持します。`find(x)`ネットがまだ閉じている最小のインデックス ≥ x を返します。 セクションが開かれると、そのセクションは後続セクションにリンクされることにより、有効な代表者のセットから削除されます。 これにより、すべての魚の移送が常に正しい次の閉じた位置に着水することが保証されます。 

各セクションは正確に 1 回削除され、前方にリダイレクトされるだけなので、魚が「消えたり」したり、有効な着地点をスキップしたりすることはありません。 このプロセスは、ライン外でオープン インデックスを繰り返し縮小するのと同等であり、DSU はこれらの縮小を効率的に圧縮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    fish = a[:]
    max_fish = max(fish)

    for _ in range(q):
        i = int(input())

        j = find(i)

        fish[j] += fish[i]
        fish[i] = 0

        max_fish = max(max_fish, fish[j])

        parent[i] = find(i + 1)

        print(max_fish)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```DSUの構造`parent`は、次に利用可能な閉じたセクションに直接ジャンプするために使用されます。 の`find`この関数はパス圧縮を使用するため、ジャンプの繰り返しはほぼ一定の時間になります。 

Fish 配列はセクションごとに現在の負荷を保存します。 i から Fish を移動するときは、DSU によって解決された宛先 j にそれを追加します。 リセットする`fish[i]`一度処理されるとそれ以上貢献しないので安全です。 

グローバル最大値は、最初から再計算するのではなく、段階的に更新されます。これは効率のために不可欠です。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
a = [1, 3, 2, 4]
operations: open 2, open 1
```DSU の親ポインターとフィッシュ値を追跡します。 

| ステップ | 操作 | 見つける(i) | 魚の配列 | マックスフィッシュ |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | - | [1,3,2,4] | 4 |
 | 1 | 2を開く | 2 | [1,3,5,4] | 5 |
 | 2 | 1 | 開く 1 | [0,4,5,4] | 5 |

 2 を開いた後、2 の魚は 2 に移動します (まだ右に開いていません)。したがって、それは残りますが、概念的には処理されます。 1 を開いた後、1 の魚は DSU の状態に応じて 2 または次に利用可能なものに移動し、セクション 2 が増加します。 

これは、すでに更新された位置に蓄積がどのように発生するかを示しています。

 入力:```

 ## 特殊なケース

 特殊なケースの 1 つは、繰り返しオープンされると、スキップされたインデックスの長いチェーンが発生する場合です。 たとえば、連続したセクションを開くと、DSU は長いセグメントを迅速に圧縮します。 開かれたインデックスはすべて次の代表に即座にリンクされるため、アルゴリズムはこれを処理します。`find`呼び出しは、償却された一定時間でチェーン全体をバイパスします。 

もう 1 つのケースは、すべての大きな値が早期に 1 つのセクションに移動する場合です。 最大値を増分的に維持するため、配列全体にわたって再計算することはなく、支配的なセクションの位置が複数回変更された場合でも、ピークは正しいままです。
