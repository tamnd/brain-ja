 ## 解決策
 ## 問題の理解

 10 進数で構成される文字列が与えられます。 この文字列から、その位置のいくつかを選択し、選択した文字を並べ替えることによって、新しい文字列を構築できます。 並べ替え後のすべての個別の結果は異なるオブジェクトとみなされ、それを「TBN」と呼びます。 

ソートでは位置情報が削除されるため、各 TBN は 0 から 9 までの各数字が何回使用されるかによってのみ完全に決定されます。 したがって、TBN は、数字の周波数ベクトルを選択することと同じであり、選択された数字 d の出現回数は、元の文字列に d が出現する回数を超えることはできません。 

各 TBN の長さは選択された文字の合計数であり、そのコストは含まれる数字から計算されます。 各桁 d は、d を指定の a で累乗し、その桁が TBN で使用される回数を乗算したものに等しい固定値に寄与します。 TBN の総コストは、すべての桁にわたる寄与の合計です。 

各クエリは範囲 [L, R] を与え、長さがこの範囲内にあるすべての個別の TBN のコストの合計を計算する必要があります。 重要なのは、元の文字列内のサブシーケンスの数に関係なく、すべての有効な周波数ベクトルが 1 回だけ寄与することです。 

制約が非常に厳しいため、すべてのサブセットまたはすべてのサブシーケンスを列挙するソリューションは不可能です。 文字列の長さは最大 4 × 10^4 で、最大 10^5 のクエリが存在する可能性があるため、すべての情報を一度に構築し、各クエリに対数時間または定数時間で応答する前処理アプローチが必要です。 

微妙な落とし穴は、サブシーケンスと個別の TBN の区別です。 同じマルチセットを生成する 2 つの異なるサブシーケンスは、1 回だけカウントする必要があります。 もう 1 つの注意が必要な点は、コストは位置ではなく桁の頻度に関係するため、各桁のコピーがどこから来たのかではなく、選択された各桁のコピーの数にのみ依存することです。 

## アプローチ

 直接的なアプローチでは、すべてのサブシーケンスを列挙し、それぞれを並べ替えて、長さ別にコストを累積しようとします。 これは、サブシーケンスの数が n で最大 2^n まで指数関数的であり、周波数ベクトルを格納することすら不可能であるため、すぐに失敗します。 

より構造化されたビューは、視点を反転することです。 ポジションを選択する代わりに、各桁のコピーを何枚取るかを選択します。 freq[d] を文字列内の数字 d の出現数とします。 各桁について、0 から freq[d] までのカウントを個別に選択します。 最終的な TBN は、すべての桁にわたってこれらの選択肢を組み合わせて決定されます。 

これにより、問題は 10 個のアイテム タイプ (数字 0 ～ 9) にわたる制限されたナップザックに変わります。 各桁 d は、c 個のコピーを取得できる方法の数を表す多項式係数に寄与し、重み w[d] = d^a でコストにも線形に寄与します。 

考えられる全長 k ごとに 2 つの並列量が必要です。つまり、長さ k の TBN を形成する方法は何通りあるのか、およびそのようなすべての TBN の合計コストはいくらになるのかということです。 主な難点は、各桁が構造 (ウェイ数) と値 (コスト) の両方に寄与するため、有界たたみ込みを実行する際に dp 配列とコスト配列の両方を維持することです。 

ブルート フォースは、集計を行わずに各桁の選択を独立して処理するため、遅くなりすぎます。 重要な観察は、各桁が 1 つの有界範囲のみに寄与するため、スライディング ウィンドウ プレフィックス合計を使用して DP を段階的に更新し、n での 2 次から線形への各桁の遷移を減らすことができるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブシーケンスを列挙する | O(2^n) | O(n) | 遅すぎる |
 | 単純な畳み込みを使用した桁ごとの有界 DP | O(10・n^2) | O(n) | 遅すぎる |
 | 桁上のスライディング ウィンドウ DP | O(10・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[k] を、いくつかの数字のプレフィックスを処理した後の長さ k の TBN の総数とする。 コスト[k]をそのようなすべてのTBNのコストの合計とします。

0 から 9 までの数字を処理し、各数字を個別に処理して DP を更新します。 

### 1. 桁の重みを事前計算する

 w[d] = d^a modulo m を計算します。 これは、数字 d の出現ごとに寄与する値です。 

### 2. DP の初期化

 dp[0] = 1 およびcost[0] = 0 から始めます。これは空の選択を表します。 

### 3. 各桁を個別に処理する

 周波数 f の固定数字 d の場合、0 ≤ c ≤ f である c 個のコピーを取得できるようにすることで、dp とコストを更新したいとします。 

考えられる合計長 k ごとに、新しい dp はすべての有効な分割の合計になります。 

dp_new[k] = [0, f] の c にわたる dp_old[k - c] の合計

 これは、dp_old に対するスライディング ウィンドウを使用して計算できる、古典的な境界付きナップザック遷移です。 

各 dp_new[k] が O(1) の償却時間で計算されるように、実行ウィンドウの合計を維持します。 

### 4. 同時にコストを維持する

 コストについては、数字 d の c 個のコピーを取得するたびに、その構成の合計コスト寄与に c · w[d] を加算します。 

したがって、cost_new[k] には 2 つの部分があります。 まず、以前のコストを継承します。 

新しいコスト[k] += 古いコストの合計[k - c]

 次に、数字 d の c 個のコピーを選択することによる寄与を追加します。 

cost_new[k] += w[d] * 合計 (c · dp_old[k - c])

 したがって、dp と並行して、スライディング ウィンドウ内のインデックスと dp 値の合計に対する追加のローリング構造を維持します。 これにより、c を明示的に反復することなく、重み付けされた寄与を計算できます。 

### 5. プレフィックス合計を使用してクエリに答える

 すべての桁が処理されると、dp[k] とcost[k] が最終的になります。 両方の配列の k にわたるプレフィックスの合計を構築するので、各クエリ [L, R] は減算によって O(1) で答えることができます。 

### なぜ効果があるのか

 核となる不変条件は、最初の i 桁を処理した後、dp[k] が 0 から i までの桁のみを使用して桁マルチセットを選択するすべての方法を正しくカウントし、cost[k] がそれらのマルチセットにわたる正確な合計コストを累積することです。 異なる数字の選択肢が増えるという意味で、各数字は独立しているため、畳み込みを使用して順番に処理することで正確さが保たれます。 スライディング ウィンドウの定式化は、すべての有効なカウント c に対して同じ制限された合計を計算するためのより高速な方法にすぎないため、基礎となる組み合わせの意味は変わりません。

数字ごとに、境界付きウィンドウ [k - f, k] にわたる遷移を再計算します。これにより、その数字の利用可能な出現数を超えて使用することが強制されます。 プレフィックスの合計により、構成の数と、桁ごとの線形時間のコストに必要なインデックス加重合計の両方を計算できます。

 ## 特殊なケース

 主なエッジケースは、数字がまったく表示されない場合です。 その場合、境界付きナップザック ウィンドウはゼロに折りたたまれ、DP は変更されないままでなければなりません。 f = 0 は空の範囲にわたって遷移の合計を作成し、変更されていない状態のみを寄与するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、L = 1 の場合です。DP には空のセットの長さ 0 が含まれるため、クエリでは dp[0] の寄与を慎重に除外する必要があります。 これは、クエリに応答するときに、1 から始まる k にわたるプレフィックスの合計によって処理されます。 

最後に、a = 0 の場合、すべての桁の重みが 1 になり、コストはすべてのマルチセットにわたる長さの合計を数えることに減ります。 w[d] は一貫して d^a mod m として計算され、1 が得られるため、DP は引き続き正しく動作します。
