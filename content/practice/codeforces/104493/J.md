 ## 解決策
 ## 問題の理解

 各テスト ケースには整数配列が与えられ、追加の整数値を 1 つだけ挿入できます。$X$配列内の任意の場所にあります。 この挿入後、配列サイズは 1 つ増加し、算術平均と中央値の両方が新しい配列で再計算されます。 

課題は選択することです$X$更新された配列の平均がその中央値と等しくなるようにします。 すべての有効な選択肢の中から、$X$、可能な限り最小のものを出力する必要があります。 

平均は要素の合計によって完全に決定されるため、次のように挿入します。$X$平均は線形に変化します。 ただし、中央値はソートされた順序と新しい長さのパリティに依存するため、単一の挿入値がソートされた配列の中心位置をどのようにシフトするかという根本的な問題が生じます。 

制約の合計サイズは大きく、最大で$10^6$テストケース全体の全体的な数値。 これにより、あらゆる可能な位置で挿入を繰り返しシミュレートしたり、候補を単純に試したりするソリューションは即座に除外されます。 候補の挿入ごとに中央値をスキャンまたは再計算することに依存するアプローチは、テスト ケースごとに 1 回の並べ替えに減らさない限り、遅すぎます。 

単純な推論による微妙な失敗のケースは、中央値が挿入後に元の中央値に近いままであると仮定することです。 たとえば、配列が大きく歪んでいる場合は、慎重に選択した配列を挿入します。$X$中央値の位置を、ソート順の完全に異なる領域にシフトすることができます。 中央値の局所的な安定性を前提としたアプローチは、そのような分布では失敗します。 

別の罠が想定されています$X$最終中央値または元の中央値と等しくなければなりません。 それは必ずしも真実ではありません。$X$平均と中央値の両方を同時に変更するため、バランス ポイントが元の構造の外側にある可能性があります。 

## アプローチ

 強引なアイデアは定義から始まります。 可能なすべての整数を試すことができます$X$を挿入し、平均と中央値を再計算して、等しいことを確認します。 制限しても$X$配列要素の周囲の値に対しては、候補ごとに中央値を挿入して再計算する必要があり、コストがかかるため、これはまだ実現不可能です。$O(n)$並べ替えた後、または$O(n \log n)$試行ごとに。 まで$10^6$要素の合計、これは限界をはるかに超えています。 

重要な観察は、配列がソートされると、挿入後の中央値は、挿入された位置にのみ依存するということです。$X$が配置され、平均条件は次の点で直接的な一次方程式を与えます。$X$。 だから推測する代わりに$X$、逆に考えることができます。挿入後の中央値の位置を想定し、何を導き出すかです。$X$それが成立するためには必要だ。 

1 つの要素を挿入した後の新しいサイズは次のようになります。$n+1$、中央位置は に固定されます。$\lfloor (n+2)/2 \rfloor$。 ソートされた最終配列内のその位置が、元の配列の一部の要素、または場合によっては挿入された要素に対応するようにします。 どこを直したら$X$ソートされた順序で配置されると、両方の制約を代数的に表現し、結果として得られる候補値を計算できます。$X$。 中央位置はわかっているので、その周囲の一定数の構造ケースを考慮するだけで済みます。$X$ソートされた配列を基準にして着陸する可能性があります。 

配列を一度ソートすると、プレフィックスの合計により平均値を迅速に計算できるようになり、各候補の配置を定数時間で評価できます。

 ## アルゴリズムのチュートリアル

 配列をソートし、プレフィックスの合計を事前計算して、セグメントの合計を一定時間で計算できるようにします。 させて$m = n+1$挿入後の最終サイズになります$X$。 最終的にソートされた配列の中央位置は次のとおりです。$k = (m+1)//2$。 

次に、どこにあるのかを考えます。$X$ソート順に表示できます。 仮に挿入すると$X$ポジション間$i-1$そして$i$ソートされた配列の最初の$i-1$要素は変更されず、すべての要素は$i$以降は 1 位置ずつ右にシフトします。 

挿入位置ごとに$i$、中央値要素が何になるかを決定します。 もし$i > k$の場合、中央値は挿入の影響を受けず、元の要素の位置に残ります。$k$。 もし$i \le k$、中央値は右に 1 ステップ移動し、その位置で元の要素になります。$k-1$。 

目標の中央値がわかったら$M$、平均が中央値に等しいという条件を強制します。 新しい配列の合計は次のようになります。$S + X$したがって、方程式は次のようになります。$$\frac{S + X}{n+1} = M$$これは次のようになります:$$X = (n+1)\cdot M - S$$この候補を計算します$X$関連する両方の中央値の可能性について、想定された位置への挿入がソートされた順序の制約と一致するかどうかを確認します (正しい間隔に収まる必要があります)。$a_{i-1}$そして$a_i$）。 すべての有効な候補者のうち、最小値を採用します。 

これが機能する理由は、1 回の挿入後の中央構造が挿入位置に関して区分的に一定であるためです。 各領域は、元の並べ替えられた配列内の固定中央値インデックスに対応します。 各領域内で、平均条件が一意に決定されます。$X$、そのため、解空間は継続的な検索ではなく、小さな有限の候補セットに折りたたまれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    total = pref[n]
    m = n + 1
    k = (m + 1) // 2

    ans = None

    def try_median(mid_idx):
        nonlocal ans
        x = m * a[mid_idx] - total
        ans = x if ans is None else min(ans, x)

    if k - 1 >= 0:
        try_median(k - 1)
    if k < n:
        try_median(k)

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```中央値ロジックは純粋に並べ替えられた順序で定義されているため、この解決策は各テスト ケースを並べ替えることに依存しています。 プレフィックス合計は、元の合計を効率的に計算するために使用されます。これは、次の結果を導き出すために必要です。$X$合計を繰り返し再計算することなく、平均方程式から計算します。 

機能`try_median`は、挿入によって中央位置がシフトされるかどうかという 2 つの構造的なケースをエンコードします。 各ケースは、元の配列からの固定候補中央値要素に対応します。 中央値が固定されると、$X$は一意に決まります。 

最終的な答えは有効な候補の中の最小値であり、実行可能な最小値を出力するという要件と一致します。$X$。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 その状況では、等価性を維持する挿入によって、同じ中央値と平均値が生成されるはずです。 このアルゴリズムは中央値から導出された両方の候補を評価しますが、合計は同一の要素で線形にスケールされるため、両方とも同じ値に集約されます。 

もう 1 つのエッジ ケースは、配列が厳密に減少または増加している場合です。 中央値の候補は依然として中央の 2 つの位置からのみ選ばれており、計算された$X$は自然に正しい挿入間隔に収まるため、並べ替え以外の追加の検証は必要ありません。 

最後に、いつ$n$非常に小さい、特に$n=1$または$n=2$、中央値インデックスのロジックは 2 つのケース間で変わります。$k-1$そして$k$。 アルゴリズムは両方の可能性を正しく評価し、特別な分岐を行わずに、有効な候補の最小値が必要な出力と一致します。
