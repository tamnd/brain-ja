 ## 解決策
 ## 問題の理解

 各出場者は最終的に同じ長さの単一の文字列を取得します。`m`。 この文字列はすでに非降順でソートされているため、同一文字の連続で構成されています。`'a'`、その後、いくつかの`'b'`、などまで`'z'`。 

仕事は多くの質問に答えることです。 各クエリでは 2 人の出場者が得られ、順位がいくつあるかを数えなければなりません`i`両方の文字列に同じ文字が含まれています。 言い換えれば、2 つのソートされた文字列間のハミング類似度、つまり正確に一致するインデックスの数を計算します。 

構造的に重要な意味で制約は厳しいです。 合計入力サイズは次の条件を満たします`n · m ≤ 5 × 10^5`したがって、すべての文字列のすべての文字に対してほぼ線形の前処理を行うことができます。 ただし、クエリの数は次のように大きくなる可能性があります。`10^6`これにより、クエリごとに完全な文字列をスキャンするソリューションは直ちに除外されます。 平`O(m)`クエリごとに実行すると遅すぎます。 

重要な隠れた構造は、すべての文字列がソートされていることです。 つまり、各文字列は各文字の数によって完全に決定され、さらに重要なことに、各文字は文字列内の単一の連続セグメントを占めます。 これにより、問題は、任意の配列の位置に関する比較から、間隔にわたる重複クエリに変わります。 

単純な間違いは、クエリごとに文字列を 1 文字ずつ比較することです。 これは論理的には機能しますが、最大で次のことが必要になります。`10^6 × 5×10^5`最悪の場合は操作が不可能になります。 

もう 1 つの微妙な落とし穴は、文字の頻度のみを比較することです。 周波数の等しいことは位置の等しいことを意味しないため、これでは十分ではありません。 例えば、`"aabbcc"`そして`"abcabc"`カウントは同じですが、はるかに少ないインデックスで一致します。 

重要なのは、ソートされた順序によって引き起こされる位置構造を保持することです。 

## アプローチ

 ブルート フォース ソリューションは簡単です。クエリごとに、すべてのクエリを反復処理します。`m`位置とカウントの一致。 定義を直接比較するので、これは正しいです。 ただし、最大で`10^6`潜在的に長いクエリと文字列`5×10^5 / n`、これは最悪の場合の回避策につながります`O(Q · m)`、これは許容範囲をはるかに超えています。 

重要な観察は、並べ替えられたプロパティから得られます。 各文字列は減少しないため、すべての文字が連続したブロックを形成します。 たとえば、文字列は次のようになります。`aaaabbbbcc`。 

個々のポジションの観点から考えるのではなく、各キャラクターの間隔の観点から考えることができます。 すべての文字列とすべての文字について`c`、インデックスのセグメントを計算できます。`c`が表示されます。 次に、2 つの文字列を比較するときに、両方の文字列がその位置で同じ文字ブロック内にある場合にのみ、その位置が答えに寄与します。 これにより、問題は対応する文字間隔の重複を合計することになります。 

文字ごとに、そのブロックが 2 つの文字列間でどの程度重複しているかを計算します。 各文字は文字列ごとに 1 つの連続した間隔で出現するため、その文字の寄与は定数時間で計算できます。 26 文字の場合、各クエリは次のようになります。`O(26)`。 

これにより、文字列全体のスキャンから一定数の間隔の比較までの問題全体が軽減されます。

 ## アルゴリズムのチュートリアル

 1. 各文字列について、各文字が何回出現するかを計算します。 文字列はソートされているため、これらのカウントは、次の順序で連続したセグメントに対応します。`'a'`に`'z'`。 
2. 各文字列を位置にわたる 26 の間隔に変換します。 文字を順番にスキャンしながら、各文字ブロックに開始インデックスと終了インデックスを割り当てます。 これにより配列が生成されます`L[i][c]`そして`R[i][c]`、文字がどこにあるかを表します`c`文字列に住んでいます`i`。 
3. クエリごとに文字列を比較する`s`そして`t`、26 文字すべてを繰り返します。 
4. 文字ごとに`c`、2 つの区間の重なりを計算します。 

重なり合いは`max(0, min(Rs[c], Rt[c]) - max(Ls[c], Lt[c]) + 1)`。 
5. すべての文字にわたるこれらの重複を合計して、一致する位置の数を取得します。 
6. 各クエリの結果を出力します。 

ステップ 4 の背後にある理由は、両方の文字列がその位置に同じ文字を割り当てている場合にのみ、その位置が答えに寄与するということです。 各文字は両方の文字列の 1 つの連続ブロックを正確に占有するため、これらのブロックの交差部分が一致するインデックスを正確にカウントします。 

### なぜ効果があるのか

 各文字列はインデックス範囲を分割します。`[1, m]`26 の素な間隔に、文字ごとに 1 つずつ (空の場合もあります)。 どの位置でも`i`、各文字列から正確に 1 つの間隔が含まれます。`i`、その間隔はその位置の文字を一意に決定します。 

ポジションでの試合`i`両方の文字列が同じ間隔ラベルを選択したときに正確に発生します。`i`。 したがって、等しい位置をカウントすると、対応する文字間隔のペアごとの交差を合計することになります。 文字列内では異なる文字の間隔がバラバラであるため、位置を 2 回カウントすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_intervals(s):
    m = len(s)
    L = [0] * 26
    R = [0] * 26

    i = 0
    pos = 1
    while i < m:
        c = ord(s[i]) - 97
        start = pos
        while i < m and ord(s[i]) - 97 == c:
            i += 1
            pos += 1
        end = pos - 1
        L[c] = start
        R[c] = end

    return L, R

n, m = map(int, input().split())
strings = [None] * n
intervals = [None] * n

for i in range(n):
    s = input().strip()
    strings[i] = s
    intervals[i] = build_intervals(s)

q = int(input())
out = []

for _ in range(q):
    a, b = map(int, input().split())
    a -= 1
    b -= 1

    La, Ra = intervals[a]
    Lb, Rb = intervals[b]

    ans = 0
    for c in range(26):
        left = max(La[c], Lb[c])
        right = min(Ra[c], Rb[c])
        if left <= right:
            ans += right - left + 1

    out.append(str(ans))

print("\n".join(out))
```前処理ステップでは、ソートされた各文字列を 1 回のスキャンで 26 文字間隔に変換します。 ソート順により 1 文字につき 1 つの連続ブロックが保証されるため、これは安全です。したがって、どの文字も複数のセグメントを必要としません。 

各クエリは、文字ごとに一定の作業のみを使用します。 オーバーラップ式は標準区間交差であり、`+1`包括的なインデックス作成を考慮します。 

よくある実装上の間違いは、文字列内にまったく出現しない文字があることを忘れることです。 その場合、それらの間隔は長さゼロのままであり、オーバーラップ式は当然ゼロに寄与します。`left > right`。 

## 実用的な例

 2 つの文字列を考えてみましょう。`s = "aaabbc"`

`t = "aabbbc"`間隔を計算します。 

のために`s`:

 | 手紙 | 間隔 |
 | --- | --- |
 | | [1,3] |
 | b | [4,5] |
 | c | [6,6] |

 のために`t`:

 | 手紙 | 間隔 |
 | --- | --- |
 | | [1,2] |
 | b | [3,5] |
 | c | [6,6] |

 次にオーバーラップを計算します。 

| 手紙 | 重なる |
 | --- | --- |
 | | [1,2] → 2 |
 | b | [4,5] ∩ [3,5] = [4,5] → 2 |
 | c | [6,6] → 1 |

 合計の答えは、`2 + 2 + 1 = 5`。 

これは、内部配置が異なっていても、一致する位置が純粋に区間交差によって捕捉されることを示しています。 

ここで次のことを考えてみましょう。`s = "aaaa"`

`t = "bbbb"`間隔:`s: a[1,4]`

`t: b[1,4]`すべての重なり部分は空であるため、答えは次のようになります。`0`、同じ文字を共有する位置がないため、これは直感と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · m + 26 · Q) | 各文字列は間隔を構築するために 1 回処理され、各クエリは 26 文字をチェックします。 
| スペース | O(n · 26) | 各文字列には、サイズ 26 | 2 の配列が 2 つ格納されます。 

前処理は合計入力サイズにおいて線形であり、最大でも`5 × 10^5`。 各クエリは継続的な作業であるため、`10^6`クエリを実行すると、ソリューションの効率性が維持されます。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build(s):
        m = len(s)
        L = [0]*26
        R = [0]*26
        i = 0
        pos = 1
        while i < m:
            c = ord(s[i]) - 97
            start = pos
            while i < m and ord(s[i]) - 97 == c:
                i += 1
                pos += 1
            L[c] = start
            R[c] = pos - 1
        return L, R

    n, m = map(int, input().split())
    inter = []
    for _ in range(n):
        inter.append(build(input().strip()))

    q = int(input())
    res = []
    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1; b -= 1
        La, Ra = inter[a]
        Lb, Rb = inter[b]
        ans = 0
        for c in range(26):
            l = max(La[c], Lb[c])
            r = min(Ra[c], Rb[c])
            if l <= r:
                ans += r - l + 1
        res.append(str(ans))
    return "\n".join(res)

 ## 特殊なケース

 微妙なエッジ ケースは、文字列の 1 つに文字が出現しない場合です。 その場合、その間隔は設定されないままになります。 アルゴリズムはまだ機能します。`L[c]`そして`R[c]`デフォルトで`0`、無効な間隔が生成され、交差条件が発生します。`left <= right`失敗し、貢献度はゼロになります。 

もう 1 つのケースは、文字列に 1 文字だけが含まれる場合です。たとえば、`"aaaaa"`。 この場合、1 つの間隔だけが空ではなく、他のすべての文字は非アクティブのままになります。 このような文字列に対するクエリは引き続き正しく機能します。これは、一致するすべての寄与がその 1 つの間隔に集中しており、他のすべての文字は空の重複によって自然に何も寄与しないためです。
