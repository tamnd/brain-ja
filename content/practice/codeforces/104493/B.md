 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 グローバル プロセスは繰り返し実行されます。各ステップで現在の配列を確認し、その最大値を選択し (複数の位置が同点の場合は、一番左の値を選択します)、その値を最大の素因数で割ってその値を置き換えます。 この操作は、配列内のすべての要素が 1 になるまで繰り返されます。 

私たちにとって重要なのは、プロセス全体をシミュレーションすることではなく、時間に関する質問に答えることです。 各クエリは部分配列を与えます`[l, r]`, そして、その部分配列内のすべての要素がすでに 1 になっているときに、グローバル プロセスの最も早いステップ番号を決定する必要があります。 

主な難点は、操作がグローバルかつ動的であることです。各ステップは配列全体の現在の最大値に依存するため、配列の異なる部分にある要素は、「残りの最大値」のグローバルな順序付けを通じて互いに干渉します。 

制約は、両方のことを示唆しています。`n`そして`q`最大約200万にもなる可能性があります。 これにより、クエリごとのプロセス全体のシミュレーションや、クエリごとの再計算さえも直ちに除外されます。 どのソリューションも、展開全体をほぼ線形時間で前処理し、各クエリに対数時間または定数時間で答える必要があります。 

単純なアプローチでは、すべての操作を明示的にシミュレートし、各位置が 1 になった時点を記録し、クエリごとに範囲の最大値を取得します。 ただし、配列には多くのステップが必要になる可能性があり、さらに重要なのは、各ステップで最大値を抽出して因数分解する必要があり、複雑さが限界をはるかに超えてしまうため、シミュレーションですら問題があります。 

値が繰り返され、タイブレークが問題になる場合、微妙なエッジケースが発生します。 たとえば、最大値が複数回出現する場合、常に左端の出現を選択すると、どの位置が最初に削減されるかが影響を受け、それによって将来の最大値の順序が変更されます。 この構造を注意深く維持しない単純なシミュレーションでは、各要素が終了するタイミングが不正確になる可能性があります。 

もう 1 つのエッジ ケースは、値がすでに 1 である場合です。値は時間 0 で終了し、更新には関与しないと見なされます。 扱いを誤ると、クエリの回答が誤って遅れてしまう可能性があります。 

## アプローチ

 直接シミュレーションでは、配列値に対する優先順位構造を維持し、最大値を繰り返し抽出し、それを最大の素因数で除算し、再挿入します。 各操作には、ヒープのメンテナンスと因数分解に対数時間がかかります。 それぞれの数字なので、`ai`は 1 になるまで何度も減らすことができ、すべての数値にわたる素因数ステップの合計が大きくなる可能性があるため、最悪の場合の演算数はすべての要素にわたる素因数除去の合計数に比例します。 値が 2e6 までの場合、それでも数千万回の操作が発生する可能性があり、これは境界線ですが、本当のボトルネックはクエリ処理です。依然として完了の位置ごとのタイムスタンプが必要ですが、これには注意深い追跡が必要であり、依然としてグローバルな依存関係に効率的に対処できません。 

重要な洞察は、視点を逆転させることです。プロセスを段階的にシミュレートする代わりに、必要な「削減」の数に関して各数値が独立して変化することを観察しますが、削減の「順序」は現在の値によってグローバルに決定されます。 すべての数字`x`正確に必要です`cnt(x)`それ自体に対する操作、ここで`cnt(x)`は 1 になるまで最大の素因数で割ることができる回数です。 

したがって、各要素が減少すると、一連の「活性化時間」に寄与します。 グローバル プロセスは、常に現在最大の「残りの値」を繰り返し選択することに相当しますが、これにより、すべての「削減イベント」を現在の実効値で並べ替えることと一致する削減のグローバルな順序付けが行われます。 

これにより、ポジションごとに、ポジションが減少する正確な時間、そしてより重要なことに、ポジションが 1 に達する時間を事前に計算することができます。最終的な完了時間がわかったら、`t[i]`インデックスごとに、すべてのクエリが最大クエリの範囲に縮小されます。`t[i]`。 

したがって、問題は次のようになります。`t[i]`グローバル スケジューリング プロセスの下にあるすべてのインデックスに対して、範囲最大クエリに答えます。 

プライオリティ キューを使用してプロセスを効率的にシミュレートできますが、「現在の値」のみを対象にし、残りの削減数のカウントダウンをインデックスごとに保存します。 インデックスが選択されるたびに、その値をデクリメントし、それでも 1 より大きい場合は押し戻します。合計の演算数は、すべての数値の削減ステップの合計によって制限されますが、各ステップで少なくとも 1 つの素因数が削減されるため、この値は小さくなり、最小の素因数を事前に計算することで、各数値が O(log ai) ステップに寄与することが保証されます。 

最後に、完了時間を計算した後、高速範囲最大クエリ用のセグメント ツリーまたはスパース テーブルを構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション | O(nq + 重因数分解) | O(n) | 遅すぎる |
 | イベントシミュレーション + 前処理 + RMQ | O(∑ log ai + n log n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下の値までのすべての数値の最小素因数 (SPF) を事前計算します。`max(ai)`。 これにより、小さい素因数をすべて除算し、最後に残った素因数を取得することで、最大の素因数を迅速に抽出することができます。 これにより、トライアルの分割が繰り返されることが回避されます。 
2. 配列要素ごとに、1 になるまでに必要な演算の数を計算します。各演算は数値を最大の素因数で除算するため、1 に達するまで SPF ベースの分解を使用して数値を繰り返し削減します。これにより、各要素の「寿命」が得られます。 
3. 各インデックスを、削減数に等しい残りの「ワークロード」があるものとしてモデル化します。 すべてのインデックスを、現在の値をキーとする最大ヒープに配置します。インデックスによるタイブレーク (左端が勝ち) になります。 これは元のプロセスを正確に反映しています。 
4. 現在の最大要素を繰り返し抽出し、1 つのリダクション ステップ (最大の素因数で割る) を適用し、要素がまだ 1 でない場合は、それをヒープに戻します。 要素が 1 になるたびにグローバル ステップ番号を記録します。 これが完了時間です。 
5. すべての要素が完了すると、配列が完成します`t[i]`位置の時刻を保存する`i`1になります。 
6. 範囲最大構造を構築する`t`。 各クエリ`[l, r]`返品`max(t[l..r])`これは、部分配列内のすべての要素が 1 になった初めてのことです。 

正確さは、ヒープが常に正確なルールをシミュレートするという事実にかかっています。各ステップで、最小のインデックスで同点を破り、グローバル最大の現在値を選択します。 各リダクションはアトミックかつ決定論的であるため、シミュレートされたシーケンスは実際のプロセスと正確に一致します。 

重要な不変条件は、どのステップでもヒープにはすべてのインデックスの現在の状態が含まれており、抽出された要素は問題定義で選択される要素とまったく同じであるということです。 したがって、記録された完了時間は、元のプロセスにおける実際の時間です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def build_spf(n):
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            step = i
            for j in range(i * i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i
    return spf

def largest_prime_factor(x, spf):
    while x > 1:
        p = spf[x]
        if x // p == 1:
            return x
        while x % p == 0:
            x //= p
    return x

def reduce_once(x, spf):
    lp = largest_prime_factor(x, spf)
    return x // lp

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    maxa = max(a)

    spf = build_spf(maxa)

    heap = []
    for i, v in enumerate(a):
        heapq.heappush(heap, (-v, i))

    t = [0] * n
    step = 0

    while heap:
        val, i = heapq.heappop(heap)
        val = -val
        step += 1

        val = reduce_once(val, spf)

        if val == 1:
            t[i] = step
        else:
            heapq.heappush(heap, (-val, i))

    # build RMQ (sparse table)
    LOG = (n).bit_length()
    st = [t[:]]
    j = 1
    while (1 << j) <= n:
        prev = st[j - 1]
        cur = []
        length = len(prev)
        for i in range(length - (1 << (j - 1))):
            cur.append(max(prev[i], prev[i + (1 << (j - 1))]))
        st.append(cur)
        j += 1

    def query(l, r):
        l -= 1
        r -= 1
        length = r - l + 1
        k = length.bit_length() - 1
        return max(st[k][l], st[k][r - (1 << k) + 1])

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        out.append(str(query(l, r)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、最小素因数ふるいを構築することから始まります。これは、操作ごとに一定時間内に最大の素因数を抽出するために必要です。 ヒープには負の値が格納され、Python の最小ヒープで最大ヒープをシミュレートします。 

シミュレーション ループはプロセスを直接エンコードしたものです。各ポップは 1 つのグローバル操作に対応します。 要素は一度縮小され、再挿入されるか、終了としてマークされます。 

スパース テーブルは完了時間にわたって構築されるため、各クエリは一定範囲にわたる一定時間の最大クエリになります。 

微妙な詳細は、終了条件がヒープの空に依存していることです。これは、すべての要素が 1 に達し、正確に 1 回記録されることを意味します。

 ## 特殊なケース

 重要なエッジケースは、複数の要素が同じ最大値を共有する場合です。 例えば、`[5, 5, 5]`。 アルゴリズムは常に最初にインデックス 0 を選択する必要があります。 タイブレークが無視されると、インデックス 1 と 2 が早期に削減され、完了時間が変更され、次のような範囲にわたってクエリの回答が分割される可能性があります。`[2,3]`。 

もう 1 つのエッジ ケースは、すでに 1 が含まれている配列です。 入力用`[1, x, 1]`、値 1 のインデックスは、すぐに完了時刻 0 を持つ必要があります。ヒープベースのシミュレーションでは、当然のことながら、初期化後にインデックスをさらにプッシュすることは避けられます。 

最後のエッジ ケースは、2e6 のような高度に合成された数であり、最大素因数の除去を繰り返すと、単純な因子の除去とは異なる動作をする可能性があります。 SPF を使用すると、数値に素因数が繰り返されている場合でも、各リダクション ステップが正しいことが保証されます。
