 ## 問題の理解

 完全な二分木が与えられます。$k$レベルなので、頂点の数は$2^k - 1$。 各内部ノードにはちょうど 2 つの子があり、リーフは最下位レベルにあります。 すべてのノードには、ルービック キューブの面に対応する 6 色のいずれかを割り当てる必要があります。 

制限はローカルです。すべてのエッジは 2 つのノードを接続し、その色は立方体上の隣接する面でなければなりません。 反対側の顔は禁じられたペアです。 具体的には、各色は他の 2 つの色を厳密に禁止し、許可されるすべてのペアは対称的になります。 

タスクは、ツリー全体に有効な色の割り当てがいくつ存在するかを数えることです。 

制約$k \le 60$ノードを列挙するアプローチや、ノードごとの再計算を使用してボトムアップ ツリー DP で明示的にノードごとの状態を伝播しようとするアプローチは直ちに除外されます。 ツリーのサイズは指数関数的です$k$したがって、レベルごとまたは構造的対称ごとに機能するソリューションのみが実行可能です。 

微妙な点は、リーフと内部ノードの制約に違いはなく、隣接性はノードの深さではなく色のみに依存することです。 もう 1 つの重要な観察は、ツリーが完全にバランスが取れており、すべてのサブツリーで同一であるため、どの DP も各ノードを個別に扱うのではなく、同一の部分問題を折りたたむ必要があることです。 

よくある落とし穴は、親が固定されればノードの 2 つの子を独立して処理できると想定していることです。 両方の子が親との制約を満たす必要があり、サブツリーの繰り返しを通じて構造的に相互作用する必要があるため、これは無効です。 もう 1 つの間違いは、サブツリー制約がどのように上方に伝播するかをエンコードせずに、レベルごとに色を割り当てようとすることです。 

## アプローチ

 ブルートフォースソリューションでは、すべてのノードに色を割り当て、すべてのエッジをチェックします。 それは次のことにつながります$6^{2^k - 1}$これは、たとえ$k = 5$。 ローカル妥当性チェックを使用した枝刈りでも、制約は各エッジの割り当ての一定部分を削除するだけである一方、探索空間は依然としてノード数に応じて指数関数的に増大するため、意味のある助けにはなりません。 

重要な観察は、ツリーが同種であるということです。つまり、特定の高さのすべてのサブツリーは同じように動作します。 これにより、サブツリーの高さのみに基づいて問題を再帰的に圧縮することができます。 

完全な色を追跡する代わりに、ルートが特定の色に固定されているサブツリーに有効な色がいくつ存在するかを追跡します。 高さ間の移行は、親の色と子の色の互換性のみに依存します。 

ノードが色に固定されている場合$c$、各子は互換性のある任意の色にすることができます。$c$。 親の色が固定されると子は独立するため、サブツリーの方法の数は、許可された子の色を合計した、1 つの子サブツリーを着色する方法の数の 2 乗になります。 

これにより、問題は 6 色および最大 60 の高さにわたる小規模な状態の DP に軽減されます。

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します$dp[h][c]$、 どこ$h$はサブツリーの高さであり、$c$根元の色です。 値には、高さの有効な色の数が格納されます。$h$カラーをルートとするサブツリー$c$。 

1. リーフの基本ケースを初期化します。 葉は高さ 1 のサブツリーなので、$dp[1][c] = 1$すべての色に$c$なぜなら、ルートが固定されると、それ以上の選択肢を制約する子が存在しないからです。 
2. 色間の互換性を事前に計算します。 色ごとに、隣接するノードに許可される色をリストします。 これは単に立方体の隣接規則です。各面には 4 つの隣接面があります。 
3. 高さからトランジションを構築する$h-1$に$h$。 高さにあるノードを考慮します$h$色付き$c$。 その左の子は任意の色を取ることができます$x$と互換性があります$c$、右側の子供についても同様です。 
4. 許可される子の色ごとに$x$、左と右のサブツリーは両方とも独立しており、それぞれが寄与します$dp[h-1][x]$。 したがって、両方の子を色に修正すると、$x$、貢献度は$dp[h-1][x]^2$。 
5. ルートカラーの方法の数を取得するために、許可されているすべての子カラーを合計します。$c$:$$dp[h][c] = \sum_{x \in adj(c)} dp[h-1][x]^2$$6.高さまで充填後$k$、最終的な答えは、考えられるすべての根色の合計です。$$\sum_{c=1}^{6} dp[k][c]$$### なぜ効果があるのか

 不変条件とは、$dp[h][c]$高さの完全なバイナリ サブツリーの有効な色の数を正確にカウントします。$h$色に根ざした$c$、以下の構造とは独立しています。 これは、同じ高さのすべてのサブツリーが同形であり、制約が直接のエッジにのみ依存するため当てはまります。 ルート カラーが固定されると、2 つのサブツリーは同一形式の独立したサブ問題に分割されるため、有効な子カラーの乗算と合計により、ケースを過剰にカウントしたり欠落したりすることなく、すべての有効な構成が正確に列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# adjacency of cube faces (0..5)
# 0-1 opposite, 2-3 opposite, 4-5 opposite (one standard labeling)
adj = [
    [2, 3, 4, 5],
    [2, 3, 4, 5],
    [0, 1, 4, 5],
    [0, 1, 4, 5],
    [0, 1, 2, 3],
    [0, 1, 2, 3],
]

k = int(input())

if k == 1:
    print(6)
    sys.exit()

dp_prev = [1] * 6

for _ in range(2, k + 1):
    dp_cur = [0] * 6
    for c in range(6):
        total = 0
        for x in adj[c]:
            total = (total + dp_prev[x] * dp_prev[x]) % MOD
        dp_cur[c] = total
    dp_prev = dp_cur

print(sum(dp_prev) % MOD)
```各層は前の層にのみ依存するため、コードは DP の 1 層のみを維持します。 隣接リストは、禁止されている反対側の面を各リストから除外することでエンコードします。 二乗$dp_prev[x]$独立した左右のサブツリーを説明します。 

基本ケースは、子エッジが存在しないリーフに対応するため、すべての色が 1 回だけ有効になります。 反復ごとにサブツリーの高さが 1 ずつ増加し、効果的にツリーがボトムアップで構築されます。 

よくある実装上の間違いは、サブツリーの寄与を二乗するのを忘れることです。これにより、両方の子が独立したブランチではなく単一の共有状態として扱われるため、構成が過小評価されます。

 ## 特殊なケース

 のために$k = 1$、ツリーには単一のノードがあります。 アルゴリズムが初期化されます$dp_prev = [1,1,1,1,1,1]$、それらの合計である 6 を直接出力します。これは、制約を課すエッジがないという事実と一致します。 

のために$k = 2$、根には2枚の葉があります。 各リーフは、ルートと互換性のある有効な色を独立して提供します。 DP 遷移は、ルート カラーごとに、その 4 つの近傍の基本ケースの 2 乗の合計を計算し、4 を生成します。最終結果は、隣接性制約の下で両方の子の独立した選択と一致します。 

大型の場合$k$、反復二乗構造により、すべての色にわたって対称性を維持しながら急速な成長が保証され、DP 層の更新により、サブツリー間の依存関係が見逃されないことが保証されます。
