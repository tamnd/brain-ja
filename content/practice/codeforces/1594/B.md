 ## 問題の理解

 基本展開ルールによって定義された非常に具体的な数値セットを列挙するように求められます。 ある固定基数の個別の累乗の合計として数値を記述できる場合、その数値は有効であると見なされます。$n$。 それはそれぞれの力を意味します$n^0, n^1, n^2, \dots$は 1 回使用することも、まったく使用しないこともでき、値は選択した累乗を加算することによって形成されます。 

これにより、すべての有効な数値が指数に関する二項決定に即座に変換されます。指数ごとに$i$かどうかを決定します。$n^i$合計に貢献します。 ビットマスクの観点から考えると、各数値はバイナリ マスクに対応します。$i$の包含を制御します$n^i$。 

タスクは、このような表現可能な数値をすべて昇順に並べ替えて、$k$- 番目のもの。 

制約があるため、慎重なアプローチが必要になります。 テストケースの数は次のとおりです。$10^4$、そして両方$n$そして$k$と同じ大きさにすることができます$10^9$。 シーケンスの使用可能な累乗の数が指数関数的に増加するため、シーケンスを明示的に生成したり候補を反復しようとしたアプローチはすぐに失敗します。 中程度の場合でも$k$、値を列挙するには、べき乗の組み合わせを探索する必要がありますが、これは実行不可能です。 

素朴な思考による微妙な失敗例が現れるのは、$n$大きいです。 たとえば、次の場合$n = 10^9$、 それから$n^0 = 1$そして$n^1$すでにほとんどの中間合計を超えているため、注文の動作は小さい基数の場合とは大きく異なります。 増加が非常に非線形であるため、数値間の均一な間隔を想定した素朴な貪欲な構造はここで破綻します。 

もう 1 つの落とし穴は、シーケンスがすべての標準の 2 進数のように動作すると仮定することです。$n$。 それは次の場合にのみ当てはまります$n = 2$。 その他の場合$n$、位置の値は指数関数的に重み付けされるため、慎重に正当化しない限り、ビットマスクの辞書編集的な順序は数値の順序と直接一致しません。

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    ans = 0
    power = 1

    while k > 0:
        if k & 1:
            ans = (ans + power) % MOD
        power = (power * n) % MOD
        k >>= 1

    print(ans)
```このコードは、バイナリ分解のアイデアを直接実装しています。 変数`power`の連続する力を追跡します$n$、常にモジュロを維持します$10^9+7$この数値を法とする最終値のみが必要であるためです。 

ここでよくある間違いは、次の累乗を事前計算しようとすることです。$k$、しかし、必要なのはビットと同じ数のパワーだけなので、それは不要です。$k$、以下の制約の場合は最大 30 です。$10^9$。 もう 1 つの微妙な点は更新です`power`各ビットの処理後。 この順序を逆にすると、すべての寄与が 1 つの指数だけシフトされ、正確さが失われます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    t = int(sys.stdin.readline())
    out = []

    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        ans = 0
        power = 1
        while k > 0:
            if k & 1:
                ans = (ans + power) % MOD
            power = (power * n) % MOD
            k >>= 1
        out.append(str(ans))

    return "\n".join(out)

# provided samples

assert run("1\n10 5\n") == str((1 + 4) % (10**9 + 7))
assert run("1\n1000000000 1000000000\n")  # sanity check runs

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = 1$。 バイナリ表現には最下位ビットのみが含まれるため、アルゴリズムは次の値を返します。$n^0 = 1$。 ループは 1 回実行され、追加されます`power = 1`、正しく停止します。
