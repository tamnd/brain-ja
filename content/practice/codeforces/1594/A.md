 ## 問題の理解

 与えられた正の整数を表すように求められます$n$一定の間隔にわたる連続した整数の合計として$[l, r]$、両方のエンドポイントが整数であり、$l < r$。 間隔は負の数まで拡張できるため、正の数列に制限されません。 タスクは、連続合計が次の値に等しいような間隔を構築することです。$n$。 

要件をより構造的な方法で書き直すと、等差数列が で始まるような無限整数線のセグメントを見つける必要があります。$l$そして終わる$r$正確に合計すると$n$。 セグメントの長さは固定されておらず、異なるテスト ケースでは完全に異なるセグメント長が必要になる場合があります。 

重要な制約は、$n$と同じ大きさにすることができます$10^{18}$、まであります$10^4$テストケース。 これにより、間隔を超えて検索したり、合計を増分的にシミュレートしようとするアプローチは即座に除外されます。 どのソリューションでも計算する必要があります$l$そして$r$テスト ケースごとに一定時間で直接実行します。 

素朴なアプローチでは修正しようとするでしょう$l$、その後延長します$r$合計を追跡しながら。 そのためには、最大で反復処理が必要になる可能性があります。$O(\sqrt{n})$戦略によってはテスト ケースごとにさらに悪化することもありますが、この規模では実現不可能です。 

さらに微妙な問題は、間隔がゼロを横切り、負の数が含まれる可能性があることです。 たとえば、2 のような小さな正の数を表すには、次の使用が必要になる場合があります。$[-1, 2]$。 これにより、セグメントが正であるか、ゼロを中心とする必要があるという直感が打ち破られます。 

隠れた主な課題は、制限された表現や一意の表現が求められていないことを認識することです。 有効な連続間隔であれば機能します。これは、検索ではなく構築的な公式があることを示唆しています。 

## アプローチ

 強引なアイデアは、可能なすべての出発点を試すことです$l$妥当な範囲内で、一致するか超えるまで部分和を計算します。$n$。 それぞれについて$l$、増分します$r$そして合計を計算します$l + (l+1) + \dots + r$。 たとえ検索に賢く制限をかけたとしても、候補の数は$l$の順序です$O(\sqrt{n})$、それぞれに対して別の線形スキャンを実行する場合があります。 これにより、最悪の場合の複雑さが許容範囲をはるかに超えてしまう可能性があります。$n$到達する$10^{18}$。 

重要な観察は、連続するセグメントの合計が代数的に表現できるということです。 からの合計$l$に$r$は等差数列です:$$S = \frac{(l + r)(r - l + 1)}{2}$$セグメントの長さは自由に選択できます。 その自由により、常に機能する構造を強制することができます。 

標準的なトリックは、都合の良い長さを固定して開始点を解決することです。 セグメントの長さを選択すると$k = r - l + 1$、 それから：$$n = \frac{k(2l + k - 1)}{2}$$並べ替え:$$2n = k(2l + k - 1)$$直したら$k$を解決できます$l$:$$l = \frac{2n/k - k + 1}{2}$$目標は、$k$これにより、ソリューションの完全性と存在が保証されます。 

より単純な建設的なパスは、割り算の推論を完全に回避します。$k$2 を割る最大のべき乗として$2n$。 これにより、2 のすべての因数を除算した後、残りの式で次の整数を回復できることが保証されます。$l$。 これは、すべての有効な表現ではなく 1 つの有効な表現のみが必要なため、機能します。 

一度$k$が選択された場合、直接計算します$l$、 その後$r = l + k - 1$。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、指定された値から開始します。$n$概念的にはそれを 2 倍にして使用することを検討します$2n$。 これは、等差数列の和の公式では 2 による除算が自然に導入され、これを事前にクリアしておくことで後での分数推論を回避できるため便利です。 
2. コンピューティング$k$、除算する 2 の最大のべき乗$2n$。 このステップでは、後で 2 で除算するときに整数を維持する最大の「きれいな」セグメント長を分離します。 2 のべき乗を選択する理由は、2 のべき乗がバイナリ構造の分母の動作を完全に制御するためであり、これは整数の 2 で割り切れる動作と一致します。 
3. 1回$k$が決定されたら、開始点を計算します$l$再配置された等差数列公式を使用すると、次のようになります。$$l = \frac{2n/k - k + 1}{2}$$これにより、構築されたセグメントに必要な合計が正確に含まれることが保証されます。 
4. エンドポイントを次のように計算します。$r = l + k - 1$。 これにより、セグメントの長さが正確であることが保証されます。$k$。 
5. 出力$l$そして$r$このテストケースの答えとして。 

### なぜ効果があるのか

 正確さは、すべての算術セグメントの合計が次のように記述できるかどうかにかかっています。$k(2l + k - 1)/2$。 選択することで$k$2 のすべての因数を吸収する$2n$、残りの式を保証します$2l + k - 1$は整数になります。 これにより、次のことが保証されます$l$式から計算される値は整数です。 明示的に構築するので、$r$から$l$、セグメントは有効であり、合計の式に再度代入すると正確に再構成されます。$n$。 このアルゴリズムは推測には依存せず、制御された因数分解と和の公式の代数的逆変換のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = 2 * n
        
        k = 1
        while x % 2 == 0:
            x //= 2
            k *= 2
        
        # now x is odd part of 2n, k is highest power of 2
        # reconstruct l using derived formula
        # original 2n = k * x
        l = (x - k + 1) // 2
        r = l + k - 1
        
        print(l, r)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理し、完全に整数演算で動作します。 2 のべき乗を抽出するループは最大値を計算します。$k$分割する$2n$。 その後、式は直接再構築されます。$l$、 そして$r$固定長から続きます。 

微妙な点は、すべての算術演算が 64 ビットの安全な範囲内に留まるということです。$10^{18}$、2 の乗算と 2 の累乗による除算は範囲内に収まります。 除算ステップは構造上正確であるため、浮動小数点のリスクはありません。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 重要なエッジケースの 1 つは、$n = 1$。 アルゴリズムが生成するのは、$2n = 2$、 それで$k = 2$、 そして$l = (1 - 2 + 1)/2 = 0$、$r = 1$。 セグメント$[0, 1]$合計は正しく 1 になり、最小の入力でも数式は壊れません。 

もう一つのケースは次のような場合です。$n$は 2 の大きなべき乗です。 例えば$n = 2^{30}$。 それから$2n$2 のべき乗係数が大きいため、$k$非常に大きい。 計算された$l$がゼロになり、間隔は 0 から$k-1$、正しく合計すると、$n$算術構造がバイナリ スケーリングと完全に一致しているためです。 

3 番目のケースは次の場合です。$n$奇数です。 ここ$2n$2 の因数は 1 つだけなので、$k = 2$。 これにより、ソリューションは常に長さ 2 のセグメント (通常は対称) を返すように強制されます。$n/2$、分解さえ存在しなくなった場合でも正確性を保証します。
