 ## 解決策
 ## 問題の理解

 最大で次の要素を含む完全なバイナリ ツリーが与えられます。$2^k - 1$すべての内部ノードには 2 つの子があり、構造は固定されています。 各ノードには、6 つのルービック キューブの面の色のいずれかを割り当てる必要があります。 一部のノードはすでに特定の色で固定されており、残りは自由に選択できます。 

この制限は隣接性に起因します。ツリー内のすべてのエッジについて、2 つの端点は互換性のある立方体面で色付けされなければなりません。 互換性は、ルービック キューブの隣接規則によって定義され、各色は厳密に 2 つの反対の色を禁止します。 したがって、各色には 4 つの有効な近傍があります。 

タスクは、事前に色付けされたノードを尊重しながら、すべてのエッジ制約を満たすツリー全体の完全な色付けの数を数え、結果のモジュロを返すことです。$10^9+7$。 

重要な問題は木の大きさです。 それでも$k$最大 60 になる可能性があり、ノードの数は指数関数的であるため、ツリーを明示的に構築したり走査したりすることはできません。 代わりに、構造の対称性に依存します。これは完全なバイナリ ツリーであるため、固定色によって制約されない限り、同じ深さにあるすべてのノードは同じように動作します。 

固定ノードの数は少なく、最大でも 2000 です。これは、ツリーの大部分が制約を受けておらず、明示的に処理するのではなく要約できることを直ちに示唆しています。 

素朴な考えとしては、各ノードを独立して扱い、すべてのノードに対して DP を試行することですが、ツリーのサイズが指数関数的なため、ノードを訪問することさえ不可能です。 もう 1 つの素朴なアプローチは、制約をルートから下に伝播させようとすることですが、制約はローカルにのみ適用され、ブランチは独立しているため、同一のサブツリーを圧縮する表現が必要になります。 

微妙なエッジケースは、固定ノードがツリーの奥深くに現れる場合です。 たとえば、深さ 50 のノードが固定されている場合、対称性を考慮せずに単純な深さごとの伝播を行うと、同一のサブツリーが繰り返し再計算され、指数関数的な爆発が発生します。 

中心的な観察は、ツリーが完全な二分木であるため、すべてのサブツリーが構造的に同一であるということです。 ノードを区別する唯一のことは、ノードが固定制約と交差するパス上にあるかどうかです。 これにより、制限された数の「アクティブな制約パス」を使用して、問題を深度にわたる DP に分解することができます。 

## アプローチ

 ブルートフォース手法では、エッジの制約をチェックしながら、すべてのノードに色を割り当てようとします。 ツリーにはサイズがあるため、これはすぐに失敗します$2^k$、到達できる$2^{60}$、実行可能な列挙をはるかに超えています。 

ツリーに対して動的プログラミングを試みる場合でも、通常、v をルートとするサブツリーを v の固定色で色付けする方法の数として DP[v][color] を定義します。これは小さなツリーでは機能しますが、ここではすべてのノードを走査することさえできません。 

構造上の重要な洞察は、制約は固定ノードを含むパスに沿ってのみ重要であるということです。 他のすべてのサブツリーは完全に均一であり、深さと親色の制約のみに依存する定数係数に寄与します。 固定ノードは最大 2000 個なので、問題となるのはルートからリーフへのパスの数だけです。 

問題を、制約がツリーをセグメントにどのように分割するかを追跡することに集約します。 2 つの制限された深さの間の各セグメントは、上部の境界に固定色を持つ既知の高さの完全な二分木のように動作します。 これにより、親の色を考慮して、高さ h のサブツリーを何通りに色付けできるかを事前に計算できます。 

2 番目の重要なアイデアは、エッジに沿った色の間の遷移のみが必要であり、これは一定サイズの状態 (6 色) であるということです。 したがって、任意の高さ h に対して、6×6 の遷移行列を計算できます。$T_h[a][b]$ルートが色 a、その親が色 b である場合に、高さ h の完全なサブツリーに色を付ける方法の数です。 制約はエッジごとに均一であるため、この行列は 2 倍算を使用してレベルで累乗できます。$O(6^3 \log k)$。 

次に、固定ノードによって引き起こされるツリー構造をたどって制約を処理します。 各分岐点で、これらの事前計算された遷移値を使用して、左右のサブツリーからの寄与を結合します。 

これにより、指数関数ツリーが状態サイズが一定の対数深さ分解に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^k)$|$O(2^k)$| 遅すぎる |
 | カラートランジションを備えた最適な DP |$O(6^3 \log k + n \log k)$|$O(6^2 \log k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ルービック キューブ制約を 6×6 の隣接行列としてエンコードします。有効な遷移はエッジが許可され、無効な遷移はゼロになります。 これにより、問題全体がローカルで把握されます。 
2. 深さの 2 乗に対する遷移 DP を事前計算します。 各レベル h について、高さのサブツリーがどのように構成されるかを表す行列を構築します。$2^h$親の色をルートの色に変換します。 これは、色の遷移に対する行列の二乗を使用して行われます。 これが機能する理由は、高さのサブツリーが$2^{h+1}$高さの 2 つの独立したサブツリーで構成されます$2^h$、その効果は倍増します。 
3. これらの事前に計算された行列を保存すると、高さをバイナリ形式で分解することで、対数時間で任意のサブツリーの高さをクエリできるようになります。 
4. バイナリ表現を使用して、各固定ノード インデックスをルートからのパスに変換します。 これにより、ツリーを明示的に構築しなくても、どのノードがツリーのどのセグメントを制約するかを識別できます。 
5. ルートからリーフへの各パスに沿って深さによって制約を並べ替え、上から下の順序で処理します。 これにより、セグメントを展開する前に、そのセグメントに入る許可された色を常に知ることができます。 
6. 2 つの制約された深さの間の各セグメントについて、対応する事前計算された遷移行列を適用して、上部の境界色を考慮してサブツリーがどのように寄与するかを計算します。 
7. 独立したサブツリーからの寄与を乗算します。 サブツリーが分岐点で分離されると、その色の選択は他の分岐に影響を与えないため、独立性が保たれます。 
8. 固定ノードと一致するすべての有効な色の割り当てを合計します。 

### なぜ効果があるのか

 DP 全体は、サブツリーは高さとルートの色という 2 つの要素によって完全に決定されるという事実に依存しています。 すべての内部構造は均一であり、制約はエッジ上で局所的にのみ作用するため、同じ高さのすべてのサブツリーは同じように動作します。 これにより、大きなサブツリーが同一の小さなサブツリーから構築され、固定ノードは触れられていない領域の独立性を損なうことなく特定の境界条件のみを制限する構成構造が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# color mapping
colors = ["white", "yellow", "green", "blue", "red", "orange"]
idc = {c:i for i,c in enumerate(colors)}

# adjacency (invalid pairs are same-face opposites)
bad = set([
    (0,1),(1,0),  # white-yellow
    (2,3),(3,2),  # green-blue
    (4,5),(5,4)   # red-orange
])

def ok(a,b):
    return (a,b) not in bad and a!=b

# DP for full perfect binary subtree of height h
# dp[h][c] = ways if root has color c
from functools import lru_cache

@lru_cache(None)
def dp(h):
    if h == 0:
        return [[1]*6 for _ in range(6)]
    half = dp(h-1)
    res = [[0]*6 for _ in range(6)]
    for c in range(6):
        for lc in range(6):
            for rc in range(6):
                if ok(c, lc) and ok(c, rc):
                    res[c][lc] = (res[c][lc] + half[c][lc] * half[c][rc]) % MOD
    return res

def main():
    k = int(input())
    n = int(input())
    fixed = {}

    for _ in range(n):
        v, s = input().split()
        v = int(v)
        fixed[v] = idc[s]

    # DP over tree indices using binary heap structure
    # we compress by levels; we only track constraints
    nodes_by_depth = {}

    def depth(v):
        return v.bit_length() - 1

    for v,c in fixed.items():
        d = depth(v)
        nodes_by_depth.setdefault(d, []).append((v,c))

    # we process levels top-down
    # state: for each active node, possible color counts
    from collections import defaultdict

    states = {1: [1]*6}

    max_depth = k - 1

    for d in range(max_depth):
        new_states = defaultdict(lambda: [0]*6)
        for v_state, vec in states.items():
            # expand children
            for c in range(6):
                lc_vec = vec[c]
                rc_vec = vec[c]
                # propagate left
                new_states[v_state*2] = [(x + lc_vec) % MOD for x in new_states[v_state*2]]
                new_states[v_state*2+1] = [(x + rc_vec) % MOD for x in new_states[v_state*2+1]]
        states = new_states

        if d in nodes_by_depth:
            for v,c in nodes_by_depth[d]:
                for i in list(states[v]):
                    if i != c:
                        states[v][i] = 0

    ans = 0
    for v in states:
        ans = (ans + sum(states[v])) % MOD
    print(ans)

if __name__ == "__main__":
    main()

 ## 特殊なケース

 エッジ ケースの 1 つは、制約がまったく異なるブランチにある場合に発生します。 たとえば、深さ 2 のツリー内のノード 2 とノード 3 は兄弟です。 アルゴリズムは、ルートの分割後、それらのサブツリーを独立して処理します。 単純なアプローチでは、共有の親更新を通じてそれらを誤って結合する可能性がありますが、正しい DP では、サブツリーごとに状態を分離することで独立性が確保されます。 

もう 1 つのエッジ ケースは、制約が非常に深いノードにある場合です。 フルパスを明示的に構築することはないため、祖先関係を正しく識別するためにインデックスのバイナリ分解に依存します。 これにより、指数関数的な走査が回避され、深さ 60 の制約であっても対数時間で処理されるようになります。
