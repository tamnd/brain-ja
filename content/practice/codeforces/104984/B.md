 ## 問題の理解

 ソース文字列が与えられます`s`そしてターゲット文字列`t`。 から始まる`s`、文字を繰り返し削除することができますが、その文字が現在文字列内の偶数の位置にある場合に限ります。 削除するたびに文字列が縮小し、位置が 1 から再度番号付けされます。 

問題は、この操作を何回か適用して、`s`まさになる`t`。 

制約は大きく、どちらの文字列も最大 50 万文字まで可能です。 削除を明示的にシミュレートしようとするソリューションは遅すぎます。各削除には線形の時間がかかる可能性があり、削除の数も線形に多くなる可能性があるためです。 これは、ソリューションが実際に文字列を繰り返し変更することを避け、代わりにどのような変換が可能であるかを推論する必要があることを直ちに示唆しています。 

このプロセスの微妙な点は、削除のたびに位置が常に再計算されることです。 これは、文字のパリティが時間の経過とともに変化する可能性があることを意味するため、元のインデックスを追跡するだけでは十分ではありません。 

最初の文字について考えるときに、重要なエッジケースが現れます。 最初の位置は常に奇数であるため、削除することはできません。 たとえば、次の場合`s = "abc"`そして`t = "bc"`、その答えは明らかに不可能です。`a`は削除できないため、最終文字列に含める必要があります。 この不変条件を無視したアプローチは、そのような場合には直ちに失敗します。 

もう 1 つの失敗モードは、追加の構造のないサブシーケンスに制限されていると仮定することです。 たとえば、任意の文字を削除できると誤って仮定した場合、削除はパリティの進化に依存するという制限により、実際には構成できないケースを受け入れてしまう可能性があります。 

## アプローチ

 直接シミュレーションでは、文字列を維持し、削除可能な偶数位置の文字を繰り返しスキャンし、そのたびに削除します。 削除するたびに文字列をシフトする必要があり、最大で$5 \cdot 10^5$文字の場合、これは最悪のケースにつながります。$O(n^2)$操作。 これは実現可能な限界をはるかに超えています。 

重要な観察は、何が実際に削除を制限しているのかを理解することから得られます。 永続的に保護される唯一の文字は、現在の文字列の最初の文字です。これは、常に位置 1 にあり、偶数になることはありません。 構造が進化するにつれて、適切な偶数位置の要素を繰り返し削除することで、他のすべてを最終的に削除できます。 

これは、最初の文字を修正すると、残りの文字列がプールのように動作し、順序を維持しながら不要な文字を破棄できることを意味します。 テール部の複雑な動的パリティ システムに実際に制約されるわけではありません。 前面に触れない限り、余分な文字はいつでも削除できます。 

これにより、問題ははるかに単純な構造に縮小されます。 の最初の文字`s`最終文字列の最初の文字はそのままにしておく必要があります。 その後、残りがあるかどうかを確認するだけです。`t`の部分列として取得できます`s`2文字目から。

 ## アルゴリズムのチュートリアル

 次に、観察を具体的な手順に変換します。 

1. の最初の文字が`s`の最初の文字と一致します`t`。 そうでない場合は、すぐに建設は不可能であると判断してください。 の最初の文字`s`削除することはできないため、最後の文字列を固定する必要があります。 
2. 2 つのポインタ、1 つのスキャンを初期化します。`s`インデックス 1 以降と 1 回のスキャン`t`インデックス 1 以降。 インデックス 0 は最初のステップですでに修正されているため、意図的にスキップします。 
3. 通過する`s`左から右へ。 現在のキャラクターが`s`現在必要な文字と一致します`t`、ポインタを中に進めます`t`。 それ以外の場合は、文字を無視してスキャンを続行します。 
4. すべての処理が完了したら`s`、ポインタが`t`終わりに達しました。 「はい」の場合、次のすべての文字`t`は順番に見つかりました。つまり、`s`還元不可能な最初の文字を尊重しながら。 そうしないと施工が出来ません。 

重要な考え方は、ステップ 3 の不一致はすべて、何らかの有効な操作シーケンスでその文字を削除することに対応するということです。 削除は常に先頭以外の文字を対象にすることができるため、不要な文字のスキップがブロックされることはありません。 

### なぜ効果があるのか

 不変条件は、現在の文字列の最初の文字がプロセス全体を通じて決して変更されず、他のすべての文字は将来の削除の実現可能性に影響を与えることなく削除できることです。 これにより、サフィックスは自由なサブシーケンス リザーバーのように動作します。 

したがって、この操作によって課される唯一の制約は、順序の保存と最初の文字の保存です。 両方の制約を満たす任意の文字列を実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_build(s, t):
    if not s or not t:
        return False

    if s[0] != t[0]:
        return False

    j = 1
    n, m = len(s), len(t)

    for i in range(1, n):
        if j < m and s[i] == t[j]:
            j += 1

    return j == m

def main():
    s = input().strip()
    t = input().strip()
    print("YES" if can_build(s, t) else "NO")

if __name__ == "__main__":
    main()
```この実装では、2 ポインターのアイデアが直接エンコードされます。 最初の文字のチェックは、照合ステップではなく構造上の制約を表すため、分離されています。 ループは両方の文字列のインデックス 1 から開始します。これは、インデックス 0 が固定されており、削除ロジックに関与しないことを反映しています。 

ここでよくある間違いは、削除をシミュレートしたり、パリティの変更を追跡しようとしたりすることです。 最初の要素のみが保護されていることがわかれば、それらは必要ありません。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    t = input().strip()

    if s and t and s[0] != t[0]:
        return "NO"

    j = 1
    m = len(t)

    for i in range(1, len(s)):
        if j < m and s[i] == t[j]:
            j += 1

    return "YES" if j == m else "NO"

 ## 特殊なケース

 最も重要なエッジケースは、最初の文字が異なる場合です。 例えば、`s = "xbc"`そして`t = "abc"`すぐに失敗してしまうので、`x`削除することはできません。 アルゴリズムは、スキャンが開始される前に一定時間内にこれを処理します。 

もう一つの微妙なケースは次のような場合です。`t`文字が存在しても順番にマッチングできる長さを超えています。 例えば、`s = "abac"`そして`t = "aaaaa"`マッチング後に利用可能になるため失敗します`a`オカレンス、ポインタ`t`最後まで到達することはありません。 貪欲スキャンは、後で必要になる可能性のある一致をスキップしないため、これを正確にキャプチャします。 

最後のエッジケースは次のような場合です`s`単一の文字で構成されます。 その場合、唯一有効なのは、`t`と同一であるか`s`それ以上だと無理。 ループは決して先に進まないため、2 ポインター ロジックはこれを自然に処理します。`t`最初のミスマッチを超えて。
