 ## 解決策
 ## 問題の理解

 長さのシーケンスが何個あるかを数えるように求められます$n$からの数字を使用して形成できます$1$に$k$ただし、3 つの同時構造規則が生き残るシーケンスのみです。 

シーケンスは固定の奇数長であるため、一意の中間位置を持ちます。 中間要素は強制的に正確に$k$、シーケンス内の他のどこにもありません$k$登場することが許される。 したがって、値は$k$中心を固定し、他の場所での繰り返しを禁止する特別なマーカーのように動作します。 

中心から離れると、シーケンスは自由ではなくなります。位置は倍加制約によって結合されます。 中心の左側または右側の位置を見ると、距離にある任意の位置$d$中心からの距離が離れた位置と一致する必要があります$2d$。 これにより、インデックスに沿って等しい値のチェーンが作成されます。$d, 2d, 4d, \dots$。 したがって、シーケンスはもはや自由配列ではありません。 オフセットを繰り返し 2 倍することによって形成される等価クラスに分解されます。 

さらに、隣接するペアには制限があります。 私たちはあきらめています$m \le 16$順序付きペア$(x_i, y_i)$。 このような各有向ペアは、シーケンス全体で最大 1 回、連続する部分文字列として出現できます。 たとえ異なる場所にあったとしても、ペアが 2 回出現した場合、その順序は無効になります。 

制約は非常に特殊な点で小さいです。$k \le 10$そして$n \le 53$。 これは、すべてのシーケンスに対するブルート フォースは不可能であることを即座に示唆していますが、禁止されたペアに対するビットマスクを使用した状態空間動的プログラミング アプローチが妥当であることも示唆しています。 

明らかではない難しさは、2 倍の等価制約です。 ポジションに対する単純な DP では、遠く離れていても強制的に平等にされるポジション間の一貫性を確保する必要があります。 これを無視すると、ポジションが独立したものとして誤ってカウントされることになります。 

典型的な失敗例は、ポジションが早期に割り当てられ、同じダブリング チェーンに属する後のポジションが競合する値を受け取る場合に発生します。 たとえば、位置が$d$に設定されています$1$、次に位置を決めます$2d$もあるはずです$1$しかし、単純な DP はそれを独立して割り当て、無効なシーケンスをカウントする可能性があります。 

もう 1 つの微妙な障害は、隣接関係の追跡に起因します。 各禁止ペアはグローバルに最大 1 回しか出現しないため、貪欲なローカル チェックでは不十分です。 シーケンス全体にわたってグローバルな使用状況を追跡する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。長さのすべてのシーケンスを列挙します。$n$、中心条件が成立するかどうかを確認し、すべての 2 倍の等式を検証し、禁止されたペアの発生を追跡しながらすべての隣接するペアをスキャンします。 各条件は簡単に検証できるため、これは概念的に機能します。$O(n)$したがって、全体の複雑さは次のようになります。$O(k^n \cdot n)$。 と$k \le 10$そして$n \le 53$、これは天文学的に大きく、すぐには不可能です。 

重要な点は、倍加制約によって任意の依存関係が導入されないことです。 2 を繰り返し乗算することで定義されるチェーンに沿って等価性を強制するだけです。 各位置は、そのようなチェーンの 1 つに正確に属します。これは、シーケンスが任意ではなく、それぞれが位置の等価クラス全体を表す少数の「変数」で構成されていることを意味します。 

これにより、左から右への位置に対する動的プログラミングの解釈が可能になります。 以前に確認された同等の位置によって値がすでに決定されている位置に遭遇した場合は、分岐しません。 新しい同値クラス代表に遭遇したとき、私たちはその値を選択します。 なぜなら$k$が小さい場合、この分岐は管理可能なままです。 

禁止されたペアを処理するには、使用されているペアのビットマスクを使用して DP 状態を拡張します。 2 つの隣接する値を配置するたびに、(禁止されていない場合) それを無視するか、対応するペアを使用済みとしてマークします。 ペアが 2 回使用された場合、その分岐は拒否されます。 

「等価クラスのオンデマンド割り当て」と「禁止された遷移に対するビットマスク DP」の組み合わせが、このソリューションを実現可能にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(k^n \cdot n)$|$O(n)$| 遅すぎる |
 | 等価性 + ビットマスクを使用した DP |$O(n \cdot k \cdot 2^m)$|$O(n \cdot 2^m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 シーケンスを左から右に処理し、各位置に到達したときに処理します。 

1.まず中心位置を固定します$c$そしてそれに値を割り当てます$k$。 この値は二度と変更されることはなく、他のポジションがこの値を取ることは許可されません。 これにより、センターに関係するすべての隣接性チェックが直ちに固定されます。 
2. ルールによって引き起こされる倍加等価構造を事前計算します。$a_{c+d} = a_{c+2d}$。 オフセットごとに$d$、範囲内に留まりながら 2 を繰り返し乗算し、これらすべての位置を 1 つのコンポーネントに結合します。 このステップの後、すべての位置は、値が一貫している必要がある 1 つのコンポーネントにのみ属します。 
3. のポジションに対して DP を実行します。$1$に$n$。 各ステップで、DP 状態には、現在の位置インデックス、最後に配置された値 (隣接性チェックに必要)、どの禁止ペアがすでに使用されているかを表すビットマスク、およびこれまでに発生したコンポーネントの割り当てを格納する構造が含まれます。 
4. ポジションを処理する場合$i$、まずそれがどのコンポーネントに属しているかを決定します。 このコンポーネントにすでに値が割り当てられている場合は、それを使用することが強制されます。 割り当てられていない場合は、次の値をすべて試します。$1$に$k-1$を割り当てて続行します。 
5.positionの値を決めたら$i$、隣接関係を処理します。 もし$i > 1$、ペアを見てみましょう$(a_{i-1}, a_i)$。 このペアが禁止されたペアの 1 つである場合は、以前に使用されたことがあるかどうかを確認します。 すでに一度出現している場合、この遷移は無効となります。 それ以外の場合は、中古としてマークされます。 
6.位置まで続ける$n$。 すべてのコンポーネントを一貫して正常に割り当て、禁止されたペアのルールに違反しないシーケンスのみが、答えに寄与します。 

### なぜ効果があるのか

 正しさは、倍加制約がインデックスを素のコンポーネントに分割し、各コンポーネントがシーケンス全体で 1 つの値を保持する必要があるという事実に基づいています。 DP は、各コンポーネントが 1 回だけ割り当てられ、矛盾した再割り当てが行われないことを保証します。 同時に、ビットマスクはすべての禁止されたペアが構造全体にわたってグローバルに追跡されることを保証するため、ローカルな決定によって不正な繰り返しがすり抜けることはありません。 すべての有効なシーケンスはこの DP を通る 1 つのパスに正確に対応し、すべての DP パスはすべての制約を尊重するため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())
    bad = {}
    bad_list = []
    for i in range(m):
        x, y = map(int, input().split())
        bad[(x, y)] = i
        bad_list.append((x, y))

    c = (n + 1) // 2

    comp = [-1] * (n + 1)
    cid = 0

    for i in range(1, n + 1):
        if comp[i] != -1:
            continue
        j = i
        while j <= n:
            comp[j] = cid
            j *= 2
        cid += 1

    # DP state: position, last value, mask, assignments
    from functools import lru_cache

    @lru_cache(None)
    def dp(i, last, mask, assign):
        if i == n + 1:
            return 1

        comp_vals = list(assign)
        c_id = comp[i]
        cur_val = comp_vals[c_id]

        res = 0

        if i == c:
            if 1:  # must be k
                if last != -1:
                    if (last, k) in bad:
                        idx = bad[(last, k)]
                        if mask >> idx & 1:
                            return 0
                        new_mask = mask | (1 << idx)
                    else:
                        new_mask = mask
                    res += dp(i + 1, k, new_mask, tuple(comp_vals))
                else:
                    res += dp(i + 1, k, mask, tuple(comp_vals))
            return res % MOD

        if cur_val != 0:
            v = cur_val
            if last != -1:
                if (last, v) in bad:
                    idx = bad[(last, v)]
                    if mask >> idx & 1:
                        return 0
                    new_mask = mask | (1 << idx)
                else:
                    new_mask = mask
            else:
                new_mask = mask

            res += dp(i + 1, v, new_mask, assign)
        else:
            for v in range(1, k + 1):
                if v == k:
                    continue
                comp_vals[c_id] = v
                if last != -1:
                    if (last, v) in bad:
                        idx = bad[(last, v)]
                        if mask >> idx & 1:
                            continue
                        new_mask = mask | (1 << idx)
                    else:
                        new_mask = mask
                else:
                    new_mask = mask

                res += dp(i + 1, v, new_mask, tuple(comp_vals))
                res %= MOD
            comp_vals[c_id] = 0
            return res

        return res % MOD

    init_assign = tuple([0] * cid)
    print(dp(1, -1, 0, init_assign) % MOD)

if __name__ == "__main__":
    solve()
```このコードは、まず 2 倍化制約を連結成分に圧縮します。 各インデックスは範囲を超えるまで繰り返し 2 倍になり、同等のグループが生成されます。 

次に、DP がポジションを順番に確認します。 タプル`assign`各コンポーネントの現在の値を格納します。ゼロは割り当てられていないことを意味します。 コンポーネントが初めて表示されると、DP は禁止された中心値を除くすべての可能な値に分岐します。$k$。 

の`mask`禁止された有向ペアがすでに使用されているトラック。 隣接するペアが形成されるたびに、対応するビットを設定するか、すでに使用されている場合は遷移を拒否します。 

センター位置は固定のため特別扱いとなります。$k$、また、両側の隣接制約とも相互作用します。 

微妙な点は、代入タプルが分岐ステップごとにコピーされることです。 これが必要なのは、異なるブランチがコンポーネントの割り当てを共有してはいけないためです。

| ステップ | ポジション | 値 | ペア | マスク |

 ## 特殊なケース

 主なエッジ ケースは、コンポーネントが複数の位置にまたがるが、DP の後半でのみ発生する場合です。 その状況では、アルゴリズムは最初の遭遇まで割り当てを正しく遅らせ、時期尚早なコミットメントが行われないようにします。 

もう 1 つの特殊なケースは、中央隣接です。 中心が固定されているので、$k$、以下を含む禁止されたペア$k$正確に追跡する必要があります。 それ以外の場合は、繰り返されるシーケンス$(x, k)$または$(k, y)$間違ってカウントされてしまいます。 

最後に、長い倍増チェーンを形成するコンポーネントは、すべての出現において一貫性を保つ必要があります。 DP は割り当てを共有状態に保存することでこれを強制するため、コンポーネントを再訪問しても競合するブランチが作成されることはありません。
