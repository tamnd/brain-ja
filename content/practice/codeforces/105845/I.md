 ## 解決策
 ## 問題の理解

 英語の小文字に等しい長さの 2 つの文字列が与えられます。 文字列の間隔に作用する非常に特殊な操作を繰り返し実行することができます。 1 回の操作で、2 つの位置を選択し、それらの位置で文字を交換し、各文字をアルファベットの「鏡」に置き換えることによって、すべての文字をそれらの間で厳密に独立して変換します。`a`になる`z`、`b`になる`y`、 等々。 

タスクは、初期文字列をターゲット文字列に変換するために必要なそのような操作の最小数を決定するか、または変換がまったく不可能であると判断することです。 

この操作の重要な部分は、順列効果 (スワップ) と一定の間隔での決定論的なグローバル変換 (アルファベットの反転) を組み合わせていることです。 スワップは 2 つのポジションにローカルですが、フリップは構造化された方法ですべての中間ポジションに影響します。 エンドポイントを交換するとどの文字が反転されるかが変わるため、この結合が問題を自明ではないものにしています。 

制約により、文字列の長さは約$10^5$これにより、一連の操作をシミュレートしたり、状態を明示的に検索しようとしたりするソリューションは除外されます。 有効なアプローチでは、問題を線形または線形に近いパス、または少数の貪欲な決定に減らす必要があります。 

最初の単純なアイデアは、各操作を状態遷移として扱い、1 つの操作で到達可能なすべての文字列に対して BFS を試みることです。 それはすぐに爆発します。なぜなら、各州には$O(n^2)$可能な操作と状態空間のサイズ$26^n$。 非常に小さな文字列の場合でも、これは扱いにくくなります。 

貪欲に左から右に位置を修正しようとすると、より微妙な失敗モードが表示されます。 すべての操作はパリティのような方法でセグメント全体を変更するため、1 つの位置を修正すると、すでに正しい位置が破損する可能性があります。 たとえば、最初の文字を所定の位置に交換して一致させようとするとします。 スワップ距離に応じて、すべての中間文字が反転され、以前に一致したプレフィックスが無効になる可能性があります。 この相互依存性は、ローカルの貪欲な修正が安定していないことを意味します。 

最大の難点は、この操作ではインターバルにわたってグローバルなパリティ構造が導入されるため、正確かどうかは、操作の正確な順序ではなく、モジュロ 2 で各位置が何回影響を受けるかを追跡することに依存することです。 

## アプローチ

 ブルート フォース ビューは、各操作を文字列構成全体の変換として扱います。 指定された文字列から、任意のインデックスのペアを選択し、それらを交換し、セグメント全体を反転することができます。 これにより、膨大な分岐係数が得られ、枝刈りを行ったとしても、2 つの任意の文字列を整列させるのに必要な深さは線形になる可能性があります。$n$、実際には検索が指数関数的に行われます。 

重要な観察は、交換部分は文字を並べ替えるだけであるのに対し、反転部分は文字を可逆的に切り替えるだけであるということです。 アルファベットの反転はインボリューションであり、2 回適用すると元の文字が復元されます。 これは、演算の効果がパリティを使用してモデル化できることを意味します。つまり、各位置が何回か反転され、その回数が奇数であるか偶数であるかのみが問題となります。 

視点を「一連の演算」から「区間に対する最終的なパリティの割り当てと文字の順列」に切り替えると、構造は単純化されます。 各操作は、セグメントの反転と 2 つの要素の転置に影響します。 スワップは文字が配置される場所を再配置するだけですが、フリップは各位置が補数を受け取るかどうかを決定します。 

重要な洞察は、2 つの層を分離することです。 まず、次の文字間のマッチングを決定します。$S$そして$T$、スワップをあらゆる順列を許可するものとして扱います。 次に、誘発された不一致パターンが間隔反転によって解決できるかどうかを確認します。 間隔反転は差分配列を切り替えるように動作するため、実現可能性は範囲 XOR 更新を使用して派生バイナリ シーケンスの一貫性を保つことができるかどうかにかかっています。 

この問題は、部分配列を切り替える操作を使用してバイナリ不一致配列をすべて 0 に変換できるかどうかを確認することと同等になり、各スワップはどの不一致がペアになっているかを再配置するのに役立つだけです。 これにより、インターバル操作下でパリティの一貫性を維持するという問題が軽減され、実行中の不均衡をスキャンして維持することで貪欲に解決できます。

 ## アルゴリズムのチュートリアル

 1. の各位置を比較することにより、問題を不一致表現に変換します。$S$そして$T$。 文字を直接追跡する代わりに、各位置が既に正しいか、または変換が必要かを表します。これは、交換は位置を再配置するだけであり、複数の文字セットを変更しないためです。 
2. スワップを、位置の任意の並べ替えを許可するものとして扱います。 これは、次の文字を自由に一致させることができることを意味します。$S$の位置に$T$したがって、実際の制約は、次のマルチセット構造が成立するかどうかになります。$S$に変換できます$T$許可されたフリップの下で。 
3. 各文字を 0 ～ 25 の整数としてエンコードし、その反転バージョンを次のように定義します。$25 - x$。 これにより、量子反転操作が固定アルファベット空間に対するビットごとのインボリューションとなり、文字変換が固定マッピングを法とする算術変換に変わります。 
4. 位置ごとに、反転が必要かどうかという観点から、現在のキャラクターとターゲット キャラクターの差を計算します。 これにより、位置ごとにバイナリ インジケータが生成されます。つまり、文字がすでに一致しているか、その位置をカバーする間隔に奇数の反転を適用する必要があるかのいずれかです。 
5. 問題を、各位置が必要なパリティで終わるような一連の間隔操作が存在するかどうかを判断することに帰着します。 各操作は範囲の切り替えに寄与するため、システムは古典的な間隔パリティ構築問題になります。 
6. フリップの現在の累積パリティを維持しながら、左から右にスイープします。 各位置で、現在のパリティ状態と必要な状態を比較します。 それらが異なる場合は、この不一致を修正し、一貫して前方に伝播する新しい操作を開始する必要があります。 
7. 操作が必要な場合にのみ導入され、常に最も早い未解決の位置を修正するように選択されるようにします。修正を遅らせても、柔軟性は改善されずに競合する間隔の数が増えるだけであるためです。 

### なぜ効果があるのか

 重要な不変条件は、文字列のすべてのプレフィックスで、以前に固定されたすべての位置と一致するフリップ パリティの一貫した割り当てをアルゴリズムが維持することです。 各操作は連続したセグメントに影響を与えるため、最初の不一致位置に導入された修正は、以前の決定を無効にすることなく右に拡張できます。 これにより、グローバルな問題が一連の強制的なローカル修正に変わり、スワップによって文字の配置に関する位置の制約がなくなるため、パリティが修正されると、切り離されたセグメント間に隠れた依存関係が残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    T = input().strip()
    n = len(S)

    # mismatch parity: 1 if S[i] needs an odd number of flips to become T[i]
    need = [0] * n

    def f(c):
        return ord(c) - ord('a')

    for i in range(n):
        a = f(S[i])
        b = f(T[i])
        # if we flip once, a becomes 25-a
        # so check if we need an odd number of flips
        need[i] = 1 if a != b else 0

    ops = 0
    i = 0
    cur = 0  # current parity of active interval flips

    while i < n:
        if (cur & 1) != need[i]:
            ops += 1
            cur ^= 1
        i += 1

    print(ops)

if __name__ == "__main__":
    solve()
```このコードは、不一致配列に対するパリティ ウォークへの変換を削減します。 変数`cur`現在位置に影響を与えるアクティブなインターバル フリップの数を追跡します (モジュロ 2)。現在のパリティが位置で必要なパリティと一致しない場合は常に、新しい操作が導入され、パリティ状態を反転させます。 

微妙な点は、明示的に間隔を構築したり、スワップを実行したりしないことです。 スワップの自由度はポジションごとの実現可能性への削減に吸収されるため、実装ではパリティの一貫性を確保するだけで済みます。

これは、アルゴリズムがプレフィックスの不一致にのみ反応し、過去の決定を再検討しないことを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての文字がすでに一致している場合です。 この場合、操作を行うと不要な反転が発生するため、操作は必要ありません。 不一致配列はすべて 0 であり、パリティ修正はトリガーされないため、アルゴリズムはこれを自然に処理します。 

すべての文字を反転する必要がある場合、別の特殊なケースが発生します。 この状況では、最初の不一致によって 1 つの操作がトリガーされ、パリティが文字列全体に一貫して伝播され、追加の修正が回避されます。 

3 番目のケースは、次のような交互の不一致です。`abab`に`baba`、構造化されたパターンではすべての位置が一致しません。 このアルゴリズムは、パリティが発散する点に正確に操作を導入し、次の不一致が現れる前に各修正で最大のプレフィックスを修正することを保証します。
