 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、隣接するすべての部分配列を調べます。 サブ配列は、非常に具体的な等式が成立する場合に有効であるとみなされます。つまり、サブ配列内の最大値は、同じサブ配列内のすべての値のビット単位の OR と正確に等しくなければなりません。 

言い換えれば、任意のセグメントを取得し、その最大要素を計算し、さらにその中のすべての要素のビット単位の OR を計算する場合、これら 2 つの値が同一である場合にのみそのセグメントをカウントします。 

タスクは、複数のテスト ケースにわたってこの条件を満たすサブ配列の数をカウントすることです。 

すべてのテスト ケースの合計の長さは次のとおりであるという制約$2 \cdot 10^5$これは、テスト ケースごとのおおよその線形演算より悪いアプローチは失敗することを意味します。 すべてのサブ配列に対する 2 次スキャンは大きすぎます。単一の配列でもサイズが異なるためです。$2 \cdot 10^5$すでに約について暗示しています$2 \cdot 10^{10}$サブアレイ。 

重要な構造上の制約は、平等そのものの中に隠されています。 セグメントの OR は、新しい要素が追加された場合にのみ増加しますが、最大値は 1 つの要素によって決まります。 この不一致により、有効なサブ配列がどのようなものになるかについて強い制限が課されます。 

要素が繰り返される場合、または大きな要素が新しいビットを導入しない小さな要素で囲まれている場合、微妙なエッジ ケースが発生します。 たとえば、配列では$[1, 2, 3]$、サブ配列$[1,2,3]$最大値があります$3$または$1 ,|, 2 ,|, 3 = 3$, したがって、それは有効です。 ただし、次のような部分配列$[2,3,2]$も機能しますが、$[1,2]$max であるため失敗します。$2$しかしORは$3$。 これは、有効性が最大値だけでなく、他のすべての要素がそのビット パターンに「含まれている」かどうかにも依存することを示しています。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての部分配列を列挙し、その最大値とビットごとの OR を計算し、それらを比較します。 両方の値をゼロから計算するコスト$O(n)$サブ配列ごとに与える$O(n^3)$全体的に、または$O(n^2)$ローリング値を維持する場合。 平$O(n^2)$には遅すぎる$2 \cdot 10^5$全長。 

重要な観察は、条件によって何が強制されるのかを理解することから生まれます。 セグメントの場合$[l,r]$最大値で$M$、他のすべての要素は、すでに存在しないビットを導入してはなりません。$M$、そうでない場合、OR は次の値を超えます。$M$。 これは、セグメント内のすべての要素が次のサブマスクでなければならないことを意味します。$M$。 同時に、それ以来、$M$がセグメント内に存在する場合、OR は少なくとも$M$。 これらを組み合わせると、OR は正確に次のようになります。$M$すべての要素が満たされる場合にのみ$a_i ,|, M = M$。 

これにより、問題は、最大値として機能する各位置の周りの制約された展開に変換されます。 インデックスを修正すると$i$サブ配列内の最大要素の位置として、実行中の OR を維持しながらサブ配列を外側に拡張できます。 OR を超えるとすぐに$a_i$、決して回復できないので、その方向はブロックされます。 これにより、OR 制約が壊れるまで各中心が拡張される 2 ポインター スタイルの拡張が行われます。 

より効率的なビューは、OR を維持しながら、左側のエンドポイントを修正し、右側のエンドポイントを貪欲に拡張することです。 OR はビットのみを獲得するため、各ビットはセグメント拡張ごとに 1 回だけ OR 状態に入ることができるため、遷移の総数は要素ごとに 30 ビットに制限されます。 これにより、有効なウィンドウを段階的に維持できるようになります。 

最後の最適化は、開始位置ごとに、OR を現在の最大候補内に維持しながらどこまで延長できるかを維持することです。 新しい要素が現在の最大値を超えると、最大値が変化するためウィンドウがリセットされます。

 ## アルゴリズムのチュートリアル

 1. 左側のエンドポイントを修正します$l$そして、右側のエンドポイントを拡張する間、セグメントの現在のビット単位の OR とセグメント内で見られる最大値の 2 つの値を維持します。 これにより、最初から再計算することなく、各ステップでの状態を確認できるようになります。 
2. 延長を開始する$r$から$l$に$n$を含めて、OR と最大値を更新します。$a_r$。 OR はすべてのビット寄与を取得し、最大値は OR と一致する必要がある候補値を追跡します。 
3. 延長するたびに、現在の OR が現在の最大値と等しいかどうかを確認します。 それらが一致する場合、サブ配列は$[l,r]$は有効であり、答えに 1 つ貢献します。 
4. どこかの時点で OR が厳密に最大値を超えたとしても、すぐには停止しません。 代わりに、後の要素によって OR に再度一致するように最大値が増加する可能性があるため、続行します。 これは重要です。最大値は左側のエンドポイントによって固定されません。 
5. 重要な不変条件は、現在のセグメントに対する不変条件です。$[l,r]$、正確な OR と正確にそのセグメントの最大値を維持するため、有効性チェックは常に正確です。 

正確さは、OR がビットを蓄積するだけであるのに対し、最大値は 1 つの主要な値を追跡するという事実に基づいています。 OR に最大値に存在しないビットが含まれている場合、その最大値は将来、それに一致するように増加する必要があります。そうでない場合、セグメントは決して有効になりません。 したがって、すべての有効なセグメントは、正しいエンドポイントに到達したときに 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for l in range(n):
            cur_or = 0
            cur_max = 0
            
            for r in range(l, n):
                cur_or |= a[r]
                if a[r] > cur_max:
                    cur_max = a[r]
                
                if cur_or == cur_max:
                    ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、左固定拡張のアイデアを直接実装しています。 左側のエンドポイントごとに、一定時間の更新で OR と最大値を維持しながら、一度に 1 ステップずつ右側のエンドポイントを拡張します。 平等性チェック`cur_or == cur_max`有効なセグメントを定義する正確な条件です。 

よくある間違いは、OR が現在の最大値を超えたときにウィンドウをリセットしようとすることです。 後の要素が新しい最大値になり、等価性が復元される可能性があるため、これは不正確です。 このアルゴリズムは、完全なセグメント状態を常に維持することで、早期リセットを回避します。 

もう 1 つの微妙な点は、OR または最大値を最初から再計算することは決してないことです。 再計算によりテスト ケースごとの複雑さが 2 次式に戻されるため、これは不可欠です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose
    import sys

    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = 0
        for l in range(n):
            cur_or = 0
            cur_max = 0
            for r in range(l, n):
                cur_or |= a[r]
                cur_max = max(cur_max, a[r])
                if cur_or == cur_max:
                    ans += 1
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 単一要素配列の場合、OR と最大値は両方とも要素自体であるため、条件は常に当てはまります。 このアルゴリズムは、各インデックスを長さ 1 の有効な部分配列として正しくカウントします。 

すべての要素が同一である配列の場合、拡張を通じて OR と最大値の両方がその値に等しいままであるため、すべての部分配列が有効になります。 

厳密に増加する 2 の累乗を持つ配列の場合、有効性は、右のエンドポイントが、すべての下位ビットが既に最大要素に累積されている点 (拡張によって自然にキャプチャされる) に達した場合にのみ現れます。 

次のような混合ビットパターンの場合$[1,3,5,7]$の場合、OR はすぐに飽和し、最大値にすべての寄与ビットがすでに含まれているセグメントにのみ有効性が現れます。これは、実行中のチェックによって正しいエンドポイントで正確に検出されます。
