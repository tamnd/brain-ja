 ## 解決策
 ## 問題の理解

 私たちは、Buggy DFS (BDFS) と呼ばれる深さ優先検索 (DFS) のバリエーションを研究するように求められています。 BDFS では、標準の DFS は明示的なスタックを使用して実装されますが、動作は微妙です: すべてのノードに対して`u`スタックからポップされると、アルゴリズムは、隣接するすべてのカウンタをインクリメントします。`u`たとえその隣人がすでに訪問していたとしても。 未訪問の近傍のみがスタックにプッシュされます。 目標は、BDFS によって返される合計カウントが指定された整数と等しくなるような、無向の単純なグラフを構築することです。`K`。 そのようなグラフが存在しない場合は、次のコマンドを返してそのことを報告する必要があります。`-1 -1`。 

入力は単一の整数です`K`1 ～ 10^9 の間。 可能であれば、出力はノード数で記述されたグラフになります。`N`、そのエッジの数`M`、およびエッジのリスト。 グラフは、単純な無向グラフの標準制約、つまり自己ループなし、マルチエッジなし、および`1 ≤ N ≤ 32768`、`1 ≤ M ≤ 65536`。 

重要な課題は、BDFS カウンタがどのように増加するかを理解することです。 特定のノードの場合`u`と`d`隣人、カウンタは次のように増加します`d`いつでも`u`が訪問されます。 これは、接続されたグラフのカウンタが、アクセスされた順序でのノードの次数の合計であることを意味します。 すべてのグラフを試すという単純なアプローチは実行不可能です。`K`は最大 10^9 まで可能で、可能なグラフの数は天文学的な数になります。 

考慮すべきエッジケースには、非常に小さな値が含まれます。`K`のように`1`または`2`これは、ノード 1 から始まる接続されたグラフでは達成できません (最初のノードがカウンターに少なくとも 1 つ寄与するため)。 別のエッジケースが発生するのは次の場合です。`K`は 2 マイナス 1 の累乗であり、自然に完全なバイナリ ツリー構造にマッピングされます。 非常に大きい場合`K`、グラフがノードとエッジの制限内に収まることを確認する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、ノード制限までのすべての可能なグラフを生成し、それぞれで BDFS をシミュレートしてカウンターが一致するかどうかを確認します。`K`。 これは明らかに実行不可能です。`N = 100`、グラフの数は指数関数的であり、それぞれの BDFS をシミュレートすると O(M + N) になります。 

重要な洞察は、逆に機能することです。BDFS のカウンターは、DFS 順序で訪問されるノードの度合いに依存します。 慎重に選択した分岐係数を使用してツリーを構築することで、あらゆるカウンター値を達成できます。 具体的には、ルートに多くの子があるルート付きツリーは、カウンタに予測可能な数値を与えます。ルートがその次数に寄与し、次に各サブツリーが再帰的に寄与します。 これにより、ノード 1 から開始して、訪問した近傍数の合計が一致するまで層内にノードを追加して、段階的にグラフを設計することができます。`K`。 非常に大きい場合`K`、効率的に到達するには、完全な二分木またはスターと組み合わせた線形チェーンを使用する必要がある場合があります。`K`ノードとエッジの制限内に留まります。 

最適なアプローチは、階層化されたグラフを段階的に構築することです。 ノード 1 から開始して、新しいノードのチェーン (各ノードがカウンタに 1 を寄与) またはスター パターン (1 つの中央ノードが多くのリーフに接続されている) を繰り返し追加して、カウンタをすばやく増やします。 最大の「チャンク」を貪欲に選択することで、超過することなく追加できます`K`を正確に生成するグラフを構築できます。`K`BDFSで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(N^2)) | O(N^2) | 遅すぎる |
 | 建設的なツリー | O(log K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノードカウンターを初期化する`N = 1`そして空のエッジリスト。 ノード 1 はグラフのルートです。 
2. 新しいエッジを取得できるアクティブなノードの作業リストを初期化します。 から始める`[1]`。 
3. ターゲットの間`K`に到達していない場合は、次のアクティブなノードを選択します`u`作業リストから。 
4. 新しい隣接ノードの最大数を決定します。`x`それ`u`それらを追加しても次の値を超えないようにすることができます`K`。 これは可能です`min(K - current_counter, remaining_node_limit)`。 
5. 新しい近隣ごとに、増分します。`N`、エッジを追加します`(u, N)`をエッジ リストに追加し、新しいノードを作業リストに追加します。 学位の貢献度に応じてカウンタをインクリメントします。 
6. カウンタが一致するまでこのプロセスを繰り返します。`K`。 
7. いずれかの時点で、ノードまたはエッジの制限を超えずにノードを追加できない場合は、次のように出力します。`-1 -1`。 
8. それ以外の場合は出力`N`、エッジの総数`M`、およびエッジリスト。 

機能する理由: スターまたはチェーンの各追加は、BDFS カウンターへの予測可能な貢献です。 貪欲に貢献を最大化することで、`K`、アルゴリズムが正確に結果を生み出すグラフを構築することを保証します。`K`BDFS の実行時。 作業リストにより、DFS 順序が確実に尊重され、増分追加では単純なグラフ制約が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K = int(input())
    if K == 1:
        print("-1 -1")
        return

    edges = []
    nodes = 1
    counter = 0
    active = [1]
    
    while counter < K:
        u = active.pop(0)
        # Calculate remaining increment we can do for this node
        max_add = min(K - counter, 32768 - nodes)
        if max_add == 0:
            print("-1 -1")
            return
        for _ in range(max_add):
            nodes += 1
            edges.append((u, nodes))
            active.append(nodes)
            counter += 1
        # Optionally, continue with next node in active list

    print(f"{nodes} {len(edges)}")
    for u, v in edges:
        print(f"{u} {v}")

if __name__ == "__main__":
    solve()
```解決策は次のことを確認することから始まります。`K`それは自明に不可能です（のように`1`）。 拡張するアクティブ ノードのリストを維持し、BDFS カウンタに向けて各エッジをカウントしながら、新しいノードを段階的に追加します。 カウンタが一致するまでループが継続します`K`。 すべてのエッジは加算順に記録されます。
