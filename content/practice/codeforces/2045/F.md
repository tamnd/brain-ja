 ## 問題の理解

 次のサイズの三角形グリッドが与えられます。$N$, ここで行$r$もっている$r$細胞。 特定の細胞には最初は石がいくつか含まれています。 アンダとカムの 2 人のプレイヤーがアンダから順番に交互にターンします。 ターンでは、プレイヤーは少なくとも 1 つの石があるセルを選択し、その間の石を削除します。$1$そして$K$石を配布することができます。$K$すぐ下の列の特定のセルに石を入れます。 グリッド上に石がなくなるとゲームは終了します。 動けなくなったプレイヤーが負けます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースはグリッド サイズを指定します$N$、空でないセルの数$M$、および手ごとの最大石$K$。 空ではない各セルの位置がわかります。$(R_i, C_i)$そして石の数$A_i$。 両方が最適に実行されると仮定すると、出力が勝者となります。 

いくつかの次元では制約が極端になります。$N$まで可能です$10^9$これにより、グリッド全体を反復するアプローチは除外されます。$M$せいぜい$2 \cdot 10^5$すべてのテスト ケースにわたって、空でないセルを反復処理する余裕ができます。$K$大きくすることもできますが、次の制限があります$2 \cdot 10^5$これは、セルごとの移動を個別に推論するのに十分な大きさです。 

ゲームをセルごとにシミュレートしようとする単純なアプローチは、膨大な量のデータが存在するため実行不可能です。$N$。 不用意に実装すると、石は以下の限られた数の行にしか影響を及ぼせないことを見落とす可能性があります (最大でも$K$行)、変換された座標系で各セルを独立して処理できることを確認します。 これを説明するための小さな例:```
N = 2, M = 1, K = 1
Cell: (1,1) with 1 stone
```アンダは石を 1 つ削除し、石 1 つを (2,1) に分配できます。 カムが移動し、(2,1) から石を 1 つ取り除き、勝ちます。 制限された分布や三角座標を無視したシミュレーションでは、この問題が生じる可能性があります。 

## アプローチ

 ブルート フォース シミュレーションでは、三角形グリッドの状態を維持し、考えられる各動きを繰り返し処理し、すべての結果を再帰的にチェックしようとします。 単一セルの場合$A_i$石、それぞれの動きには$K$オプションがあり、各石の追加により最大で$O(K^2)$下の行の新しい位置。 と$M$セルの状態空間は大まかに爆発します$O((K^2)^M)$、たとえ小規模であっても完全に実行不可能です。$M$。 

重要な観察は、三角形のグリッド内の石の分布パターンが、数値計算に変換できるパターンを形成しているということです。 具体的には、このゲームのルールは古典的な Nim ゲームの一般化に適合しています。各セルは山のように機能しますが、1 つの山から移動すると、予測可能な線形パターンで石が他の山に「移動」する可能性があります。 以下に関してモジュラー演算の特性を活用できます。$K + 1$。 

各セルの座標をマッピングすることで$(r, c)$変換された座標に$d = r - c$、セル内の結石が同じであることを観察します。$d \bmod (K + 1)$ゲームルールに基づいて相互に対話します。 異なる細胞$d \bmod (K + 1)$独立しています。 したがって、各等価クラスのモジュロに対して$K + 1$、すべての石の数の XOR を計算します。 すべてのクラスの累積 XOR がゼロ以外の場合、最初のプレーヤーが勝ちます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$T$。 
2. 各テスト ケースについて、次の内容を読んでください。$N$、$M$、$K$。 
3. 配列を初期化する`xor_classes`サイズの$K + 1` to zero. This array stores cumulative XOR for each equivalence class modulo $K+1$。 
4. 空ではない各セルについて$(R_i, C_i, A_i)$:

 - コンピューティング`d = (R_i - C_i) % (K + 1)`。 
- アップデート`xor_classes[d] ^= A_i`。 これにより、独立したサブゲームの数が累積されます。 
5. すべてのエントリの XOR を計算します。`xor_classes`。 
6. XOR の合計が 0 の場合は「Kamu」を出力し、それ以外の場合は「Anda」を出力します。 

なぜ機能するのか: 座標を変換する`d = r - c`モジュロ`K + 1`三角グリッドを独立した Nim パイルに分割します。 移動は同じモジュロ クラス内のセルにのみ影響するため、標準の Sprague-Grundy 定理が適用されます。 すべてのクラスの XOR によって勝者が決定され、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    T = int(input())
    for _ in range(T):
        N, M, K = map(int, input().split())
        xor_classes = [0] * (K + 1)
        for _ in range(M):
            R, C, A = map(int, input().split())
            d = (R - C) % (K + 1)
            xor_classes[d] ^= A
        total_xor = 0
        for x in xor_classes:
            total_xor ^= x
        print("Anda" if total_xor else "Kamu")

if __name__ == "__main__":
    main()
```実装では、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 各セルについて、等価クラスのモジュロを慎重に計算します。`K + 1`。 XOR の蓄積は次のように行われます。`xor_classes`これにより、巨大な三角形グリッドの反復処理が回避されます。
