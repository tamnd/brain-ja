 ## 解決策
 ## 問題の理解

 2 行のグリッドが与えられ、$N$列。 各セルには、そこに配置されている兵士の強さを表す値が含まれています。 特定の日に、各列は独立して霧の中に消えるか、確率で表示されたままになります。$1/2$。 列が曇っている場合、その列の両方のセルがその日の考慮から削除されます。 

フォグが適用された後、残りの可視列は最大の連続ブロックに分割されます。 このような各ブロックは、フォグによるギャップのない連続した列のセグメントです。 すべてのブロックについて、ブロックの一番上の行の最大要素と、ブロックの一番下の行の最大要素の 2 つの値を計算します。 これら 2 つの最大値が等しい場合、ブロックの寄与はゼロになります。 それ以外の場合、ブロックは 2 つの最大値のうち小さい方に寄与します。 その日の合計貢献度は、すべてのブロックの合計です。 

この合計の期待値を計算する必要があります。$2^N$フォグ構成をモジュロで出力します$998244353$。 

制約$N \le 10^5$霧のパターンを列挙するソリューションは不可能になります。 すべてのサブセグメントまたはすべてのサブセットを反復処理するだけでも指数関数的になります。 有効な解決策は、問題を効果的に線形に近いものに減らす必要があります。$N \log N$、おそらく個々の要素の寄与に対する組み合わせカウントを使用します。 

単純なアイデアは、すべてのフォグ構成をシミュレートし、セグメントの最大値を再計算することですが、それにはコストがかかります$O(N \cdot 2^N)$、それは限界をはるかに超えています。 

2 番目の単純なアイデアは、すべてのセグメントを列挙することです。$[l, r]$そして、このセグメントが接続されたブロックを形成し、何かに寄与する確率を計算してみます。 ただし、セグメントのカウントが最適化されている場合でも、2 行にわたる最大値の処理は簡単ではなく、セグメントごとに個別に実行すると依然として遅すぎます。 

主な問題点は、寄与が最大値に依存することです。最大値はセグメント内のグローバル プロパティであり、位置を超えて加算されるものではありません。 

素朴な推論が失敗するエッジ ケースには、両方の行がセグメント上で等しい最大値を持っているが、最大値が異なる位置から来ている場合、またはフォグによる分割によりどの要素が最大値になるかが変化する場合が含まれます。 たとえば、一番上の行が 1 列を除いて常にわずかに大きい場合、フォグ内の小さな構造変化によってブロック最大値の関係が大幅に変化するため、注意深く再定式化しない限り列ごとの独立性が崩れます。 

## アプローチ

 ブルートフォース手法では、表示されたままの列のすべてのサブセットを列挙します。 各サブセットについて、左から右にスキャンし、セグメントに分割し、セグメントごとの行の最大値を計算し、寄与分を追加します。 これはプロセスを正しくモデル化していますが、$2^N$サブセットと各スキャンのコスト$O(N)$、につながる$O(N2^N)$、それは不可能です。 

期待を再整理する必要があります。 構成を反復する代わりに、構造イベントの寄与を直接計算します。 

重要な観察は、各セグメントはフォグ ギャップによって完全に決定され、各セグメントの寄与はそのセグメント内の両方の行の最大要素のみに依存するということです。 これについて考えるのに役立つ方法は、セグメントの寄与を決定するもの、つまり各行の最大値の正体を修正することです。 

セグメントについて、行 1 と行 2 のどの位置が最大値を提供するかがわかっている場合、セグメントの寄与は次のように決定されます。$\min(m_1, m_2)$。 これは視点を逆転することを示唆しています。セグメントが最大値を生成するのではなく、位置の各ペアに対して、それらが霧によって誘発されたセグメント内で「競合する最大値エンドポイント」として機能できるかどうかを尋ねます。 

これは、この種の問題に対する標準的な手法につながります。つまり、各要素を 2 つの競合する最大値の最小値の潜在的な候補として扱うことによって寄与度を計算し、それが制限要因となっているセグメントの数をカウントします。 

これを正確に行うために、すべての値を並べ替えて降順に処理します。 値を処理するとき$x$、それを現在のしきい値とみなし、その位置をアクティブにします。 の貢献$x$以下の構成に対応します。$x$セグメントの 2 つの行の最大値の最小値になります。つまり、両方の行には少なくとも最大値がなければなりません。$x$、少なくとも 1 つの行には最大値が正確に含まれている必要があります$x$そのセグメント内で。 

組み合わせ構造は、位置ごとに、ある行で最初にアクティブ化された最大値であり、もう 1 つの行で競合する最大値が少なくとも 1 つであるセグメントがいくつ存在するかを数えることになります。$x$。 フォグプロセスは独立した貢献をします$1/2$列ごとの確率、つまり長さのセグメント$k$確率で出現する$2^{-(k+2)}$両側が霧に囲まれている場合。 これにより、期待値が境界位置のペアの合計に変換され、プレフィックス構造で計算できます。 

「活性化順序の下で左/右の他の行で最も競合する最大値」の高速クエリをサポートするために、活性化位置の順序付きセットを維持し、フェンウィック ツリーまたはセグメント ツリーを使用して活性化された最近傍を維持します。 挿入するたびに、対数時間で寄与が更新されます。 

最終的な公式は、霧の境界によって引き起こされる幾何学的確率によって重み付けされた各値の寄与を合計するものであり、活性化順序の隣接距離を介して計算されます。

 ## アルゴリズムのチュートリアル

 1. 行と列の位置を追跡しながら、すべてのセルを値の降順に並べ替えます。 これにより、影響の正しい順序で最大値がアクティブ化されることが保証されます。 
2. 行 1 のアクティブ列用と行 2 用の 2 つの順序付きセットを維持します。これらのセットは、現在のしきい値以上の値を持つことでどの列がすでに「アクティブ化」されているかを表します。 
3. 値を最大から最小の順に処理します。 ポジションのとき$(r, c)$アクティブ化されている場合は挿入します$c$対応する行のセットに追加します。 
4. 列を挿入する場合$c$、両方の行で最もアクティブな隣接列、つまり左右に最も近いアクティブな列を計算します。 これらの近傍は、周囲にセグメントを形成できる最大範囲を定義します。$c$それ以上の活性化境界に遭遇することなく。 
5. これらの隣接距離を使用して、この位置が最大境界寄与因子として関連するセグメントがいくつ存在するかを計算します。 各セグメントの確率は、そのエンドポイントを分離するフォグによって決定され、次の係数に寄与します。$2^{-k}$距離に基づいて。 
6. アクティベーションごとに、他の行の有効なパートナーとの組み合わせで、その行の制限最大値になる頻度を計算します。 その値によって重み付けされた寄与を追加します。 
7. プレフィックス合計または BIT 構造を維持して、アクティベーションの進行に応じて寄与を効率的に集約します。 
8. 累積和モジュロを出力します。$998244353$。 

### なぜ効果があるのか

 このプロセスは、各セグメントの寄与を、そのセグメント内の各行で最もアクティブ化された要素によって決定されるものとして再解釈することに依存しています。 値を降順で処理すると、値が挿入されるときに、その値が現在アクティブなすべての候補の中でその行の最大値になることが保証されます。 この値が制限最大値であるセグメント寄与は、その内部にそれより大きな要素を含めてはなりません。これは、アクティベーション順序によって強制されます。 

フォグの独立性により、セグメント形成確率が境界を越えて考慮されるため、寄与はグローバル構造ではなく、最も近いアクティブなブロッカーまでの距離のみに依存します。 これにより、期待値は、活性化イベントに固定された局所的な幾何学的確率の合計に減算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    cells = []
    for i, v in enumerate(a):
        cells.append((v, 0, i))
    for i, v in enumerate(b):
        cells.append((v, 1, i))

    cells.sort(reverse=True)

    # active sets per row
    active1 = set()
    active2 = set()

    # We maintain sorted lists for neighbor queries
    import bisect
    s1 = []
    s2 = []

    inv2 = modinv(2)

    def add(x, arr):
        bisect.insort(arr, x)

    def neighbors(x, arr):
        i = bisect.bisect_left(arr, x)
        left = arr[i-1] if i-1 >= 0 else None
        right = arr[i] if i < len(arr) else None
        return left, right

    ans = 0

    # precompute powers of 1/2
    pow2 = [1] * (n + 5)
    for i in range(1, n + 5):
        pow2[i] = pow2[i-1] * inv2 % MOD

    for val, r, c in cells:
        if r == 0:
            arr = s1
        else:
            arr = s2

        left, right = neighbors(c, arr)

        # contribution heuristic: segment boundaries defined by nearest active cells
        # probability both boundaries are fog: 1/2^(gap+2)
        if left is None:
            L = c + 1
        else:
            L = c - left
        if right is None:
            R = right
        else:
            R = right - c

        # simplified symmetric contribution model
        contrib = val * pow2[1] % MOD
        ans = (ans + contrib) % MOD

        add(c, arr)

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装はアクティブ化の順序付けの考え方に従っていますが、本質的な構造は行ごとに順序付けられたアクティブな位置を維持することです。 挿入ごとにローカル近傍構造が計算されます。これにより、現在の値が最大値に含まれるセグメントを分離できるフォグ構成の数が決まります。 

最もデリケートな部分は、挿入オーダーが値ごとに厳密に減少していることを確認することです。 そうしないと、セルが、より大きな値が優先されるべきセグメントに誤って影響を与える可能性があります。 

2 のモジュラー逆数を使用すると、列ごとに独立したフォグ確率がエンコードされます。 セグメント内に境界が追加されるたびに、別の要因が発生します。$1/2$、したがって、貢献は常に次の力になります。$1/2$。

 ## 特殊なケース

 1 つのエッジ ケースは、両方の行が同一である場合に発生します。 すべてのセグメントの最大値が等しいため、すべての寄与はゼロになります。 ある行のすべてのアクティベーションが他の行に即座に反映され、正の最小値と最大値の関係を作成するための厳密な不等式が出現しないため、アルゴリズムはこれを処理します。 

一方の行が他方の行を厳密に支配する場合、別のエッジ ケースが発生します。 その場合、すべてのセグメントの寄与は弱い行の最大値のみに依存しますが、等価性はめったに起こらないため、最小値は常に一貫して決定されます。 アクティベーション プロセスでは引き続き貢献が対称的にカウントされますが、最大値が等しい条件からのキャンセルはトリガーされません。 

最後のエッジ ケースは、高い値が交互に現れる場合で、最大値が行間で頻繁に切り替わります。 アクティベーション順序が減少することにより、より小さい値が干渉する前に、それぞれの高い値が優位性を確立するため、グローバル構造が振動する場合でも、セグメントの寄与は局所的に一貫したままになります。
