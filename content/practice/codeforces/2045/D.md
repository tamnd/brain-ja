 ## 解決策
 ## 問題の理解

 私たちは、スタミナが水泳と飛行という 2 つの特別な動きを可能にするドラゴンを運びながら、島 1 から始まり島 N で終わる、1 から N までの番号が付けられた島の列をナビゲートするように求められます。 ドラゴンはスタミナゼロからスタートし、初めて島を訪れると一定量P_iだけスタミナが増加します。 

3つの方法で移動できます。 一人で歩くと時間 T_w がかかり、隣接する島の間には 1 回しか使用できないトンネルが使用されます。 水泳にはスタミナ D が必要で、T_s 秒を消費します。 飛行にはゼロ以外のスタミナが必要で、スタミナをゼロに設定し、T_f 秒かかります。 水泳や飛行ではトンネルを消費しません。 目標は、ドラゴンとともに最短時間で N 島に到達することです。 

制約は大きく、N は最大 200,000、各アクションのコストとスタミナの増加は最大 200,000 です。 これにより、O(N log N) よりも複雑な解は除外されます。 歩行、水泳、飛行のすべてのシーケンスを試みる単純なアプローチは、指数関数的に複雑になるため、不可能です。 

微妙な点は、神社からのスタミナの蓄積は永続的ですが、最初に島を訪れたときにのみトリガーされることです。 これにより、飛行するだけでなく泳ぐのに十分なスタミナを得るために一時的に後戻りする賢い戦略が可能になります。 バックトラッキングやトンネルの使用を無視した不用意な解決策は、時間を過小評価する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての状態をトリプル (位置、ドラゴンのスタミナ、トンネルの使用状況) としてモデル化し、すべての動きを再帰的に試行し、合計時間を計算します。 これは、すべてのアクションに決定的なコストと効果があるため機能しますが、遅すぎます。スタミナ状態の数はすべての P_i の合計に応じて増加し、最悪の場合は 4e10 に達する可能性があります。 D と P_i が 2e5 に達しているため、スタミナを離散化することさえ現実的ではありません。 

重要な洞察は、ドラゴンのスタミナと歩行トンネルが構造化された方法で相互作用しているということです。移動するのは隣接する島のみで、スタミナは最初の訪問時に単調に増加し、トンネルは後戻りにのみ関係します。 この線形構造により、特定のスタミナ状態で各島に到達するまでの最小時間を保存する動的プログラミング アプローチが可能になります。 各アイランドの個別の有効なスタミナ状態の数が最大 2 つ (スタミナ >= D またはスタミナ < D) に削減できることを観察すると、DP は O(N) 状態に簡素化されます。 

さらに、歩くよりも速い場合は常に飛行が優先され、スタミナが十分であり、T_s が T_f より小さい場合は飛行よりも水泳が優先されることに注意してください。 これにより、島に沿った効率的な前方シミュレーションが可能になり、泳ぐのに十分なスタミナの有無にかかわらず、最小限の到着時間を追跡できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N * 合計 P_i) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの状態を持つ現在のアイランドに到達するまでの最短時間を表す 2 つの変数を初期化します。`time_no_stamina`ドラゴンのスタミナが泳ぐのに不十分な場合 (スタミナ < D)、および`time_can_swim`スタミナ >= D の場合。 
2. 島 1 で開始条件を設定します。神社の P_1 を収集します。 P_1 >= D の場合、初期化します`time_can_swim`0に、そして`time_no_stamina`0まで; それ以外の場合のみ`time_no_stamina`意味があります。 
3. 1 から N-1 までの各島について、両方の州で次の島に到達するまでの最短時間を計算します。 

ａ． 一人で歩くことを検討してください。現在時刻に T_w を追加します。 

b. スタミナ > 0 の場合は飛行を検討します: スタミナを 0 にリセットし、T_f を追加します。 

c. スタミナ >= D の場合は水泳を検討してください。スタミナを D 減らし、T_s を追加します。 結果のスタミナがまだ >= D の場合は、`time_can_swim`州; それ以外の場合は、に移動します`time_no_stamina`。 

d. 初めて次の島に到達すると、スタミナに P_i が追加されます。 
4. 2 つの状態変数を更新して、新しい島の各状態の最小時間を反映します。 各状態で可能なすべての遷移のうち小さい方を使用します。 
5. すべてのアイランドを処理した後、アイランド N に到達するまでの最小時間は、2 つの状態変数の小さい方になります。 

不変条件は、各島で、`time_no_stamina`そして`time_can_swim`島に到達するために達成可能な最小時間を常にそのスタミナ カテゴリに保存します。 各移動は決定的であり、DP はすべての有効な遷移の中から常に最小値を選択するため、より高速なシーケンスが省略されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, D, Ts, Tf, Tw = map(int, input().split())
    P = list(map(int, input().split()))
    
    stamina = P[0]
    time_no_stamina = 0
    time_can_swim = 0 if stamina >= D else float('inf')
    
    for i in range(1, N):
        stamina += P[i]
        # next state times
        next_no_stamina = min(time_no_stamina + Tw, time_can_swim + Tw, time_can_swim + Tf)
        next_can_swim = float('inf')
        if stamina >= D:
            if time_no_stamina + Ts < next_can_swim:
                next_can_swim = time_no_stamina + Ts
            if time_can_swim + Ts < next_can_swim:
                next_can_swim = time_can_swim + Ts
        time_no_stamina = next_no_stamina
        time_can_swim = next_can_swim
        
    print(min(time_no_stamina, time_can_swim))

if __name__ == "__main__":
    main()
```このソリューションは、DP テーブル全体ではなく、2 つの最小時間を維持します。 歩くと常に Tw だけ時間が増えます。 飛行はスタミナ > 0 の場合にのみ考慮されます。水泳にはスタミナ >= D が必要です。初回神社ボーナスは島に入るときに追加され、その後の動きに影響します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各島は 1 回処理され、島ごとの州の数は一定であると考えられます。 |
 | スペース | お(1) | アイランドごとに 2 つの変数のみが維持されます。 DP テーブルは必要ありません。 |

 N ≤ 2e5 の場合、O(N) は 3 秒の制限時間内で十分に高速であり、メモリ使用量はわずかです。

 ## 特殊なケース

 最初の島の祠でスタミナがちょうどDになった件。 のために`N=2, D=3, Ts=2, Tf=9, Tw=1`そして`P=[3,1]`、すぐに水泳が可能です。 アルゴリズムは正しく識別します`time_can_swim`最初は 0 として、飛行や歩行ではなく泳ぐことを選択し、合計時間は 2 になります。これにより、DP が境界スタミナ値を正しく処理していることが確認されます。
