 ## 解決策
 ## 問題の理解

 レーザービームがセル間のグリッド線に沿って移動すると考えてください。 ビームが一方の側からセルに入るときは常に、そのセルの内容によってどちら側から出ていくかが決まります。 

空のセルは方向を変えません。 あ`/`ミラーはビームを一方向に 90 度回転させ、`\`ミラーはそれを反対方向に90度回転させます。 

レーザーは、グリッドの外側の境界開口部の 1 つに配置されます。 ビームはグリッドに入った後、最終的に再びグリッドから出るまで決定的な経路をたどります。 

ビームがグリッド内のすべてのミラー セルに少なくとも 1 回当たるすべての境界開口部を見つけなければなりません。 

グリッドの寸法は最大 200 × 200 です。`2(R + C)`可能なレーザー位置は最大 800 です。すべての境界からの簡単なシミュレーションは可能ですが、シミュレーションごとに実行される作業量に注意する必要があります。 

微妙な部分は、「すべてのミラーに当たる」の意味を理解することです。 ビームがそのセルに入り、そのミラーで反射するたびに、ミラーが衝突します。 何回叩かれても構いません。 

よくある間違いは、各境界から独立してシミュレーションし、訪問されたミラーをカウントすることです。 これは機能しますが、迷路のより強力な構造特性が無視されます。 

もう 1 つの簡単な間違いは、異なる入口から無関係なパスが生成されると想定することです。 実際、すべてのビーム経路は、グリッドによって完全に決定される固定グラフの一部です。 グラフが構築されると、ほぼ即座にすべての答えを抽出できます。 

次の小さな例を考えてみましょう。```
1 1
/
```唯一の鏡には 4 つの可能な入口すべてが接触しているため、答えには 4 つの境界位置すべてが含まれます。 

ビーム状態ではなくセルのみを追跡するソリューションは失敗する可能性があります。異なる方向から同じセルに入ると異なる継続が生じる可能性があるためです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての境界入口について、ビームがグリッドから出るまでシミュレーションします。 シミュレーション中に、接触したすべてのミラーにマークを付けます。 すべての鏡に触れた場合は、その入り口を記録します。 

ビームは最大で訪問できます`O(RC)`状態はセルと方向によって決まるためです。 がある`O(R + C)`入り口。 全体の複雑さは次のようになります。`O((R + C)RC)`。 

と`R = C = 200`、これはおおよそです```
800 × 40000 = 32,000,000
```状態遷移。 

これはばかげて大きいわけではありませんが、より明確な観察結果があります。 

ビームの動きは完全に決定的です。 すべてのセルのすべての側面は、正確にもう 1 つの側面に接続されています。 これは、迷路全体が実際には接続されたパス コンポーネントの集合であることを意味します。 

すべてのレーザーを個別にトレースする代わりに、これらのコンポーネントを一度に構築できます。 

すべてのセルの側面をノードとして表します。 

セル内では、コンテンツによってどの辺が接続されているかが決まります。 

空のセルの場合:```
N <-> S
W <-> E
```のために`/`:```
N <-> W
S <-> E
```のために`\`:```
N <-> E
S <-> W
```隣接するセルも共通の境界線を介して接続されます。 

すべての接続が追加された後、すべてのノードは何らかの DSU コンポーネントに属します。 

ここでミラーセルを考えてみましょう。 

ビームは、その経路がミラーを通過する 2 つの構成分岐のいずれかに入ると、そのミラーに当たります。 コンポーネントごとに、そのコンポーネントから到達可能なミラーの数を数えることができます。 

境界開口部がすべてのミラーに到達できるコンポーネントに属している場合、その開口部は有効な答えになります。 

これにより、問題全体が 1 つの DSU 構築とカウント パスに短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((R+C)RC) | O(RC) | 概念的に遅すぎる、不要 |
 | 最適 | O(RC α(RC)) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセルのすべての側に DSU ノードを作成します。 
2. セルの内容に従ってセルの側面を接続します。 

空のセルの場合は、北と南、西と東を接続します。 

のために`/`鏡のように、北と西、南と東を結びます。 

のために`\`鏡のように、北と東、南と西を結びます。 
3. 2 つの隣接するセルが同じ境界ノードを自動的に共有する番号付けスキームを使用します。 

これは、後で余分なエッジを追加することなく、セル境界を越える動きをモデル化します。 
4. すべての結合が実行された後、すべての DSU コンポーネントは 1 つの最大ビーム軌道コンポーネントを表します。 
5. しましょう`tot`ミラーの総数になります。 
6. すべてのミラー セルについて、そのミラーの 2 つの側面に対応する 2 つの DSU コンポーネントを決定します。 

のために`/`、ミラーが分離します`(N,W)`から`(S,E)`。 

のために`\`、ミラーが分離します`(N,E)`から`(S,W)`。 

どちらかの側に属するビームがそのミラーに当たる可能性があります。 
7. ミラーごとに、関連する両方の DSU コンポーネントに 1 つのカウントを追加します。 

両側が同じコンポーネントに属している場合は、一度だけ追加します。 
8. すべての境界開口部について、その DSU コンポーネントを見つけます。 
9. そのコンポーネントの数が次の場合`tot`の場合、その入り口からすべてのミラーにアクセスできるため、対応する応答文字列を記録します。 

### なぜ効果があるのか

 DSU コンポーネントは、決定論的な移動ルールによって関連付けられたすべてのビーム状態を表します。 

特定のミラーでは、ビームがそのミラーに接触する 2 つの軌道コンポーネントのいずれかに属している場合にのみ、ビームがそれに当たることができます。 カウントのステップ中に、正確にそれらのコンポーネントのミラーを登録します。 

全てのミラーを加工したら、`cnt[component]`は、そのコンポーネント内の任意のビーム状態が当たる可能性がある個別のミラーの数に等しくなります。 

境界入口は、正確に 1 つのコンポーネントに属します。 そのコンポーネントがすべてのミラーに関連付けられている場合、そのビームはすべてのミラーに当たる可能性があります。 まさにその条件です```
cnt[component] = total number of mirrors.
```したがって、報告されたすべての入り口は有効であり、すべての有効な入り口も報告されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

R, C = map(int, input().split())
grid = [input().strip() for _ in range(R)]

MAXN = 100000

parent = list(range(MAXN))
cnt = [0] * MAXN

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra = find(a)
    rb = find(b)
    if ra != rb:
        parent[ra] = rb

# directions:
# 1 = N, 2 = S, 3 = W, 4 = E
def node(i, j, d):
    if d == 1:
        return (i - 1) * C + j
    if d == 2:
        return i * C + j
    return (R + 1) * C + (i - 1) * (C + 1) + j + (1 if d == 4 else 0)

for i in range(1, R + 1):
    for j in range(1, C + 1):
        ch = grid[i - 1][j - 1]

        if ch == '.':
            union(node(i, j, 1), node(i, j, 2))
            union(node(i, j, 3), node(i, j, 4))
        elif ch == '/':
            union(node(i, j, 1), node(i, j, 3))
            union(node(i, j, 2), node(i, j, 4))
        else:  # '\'
            union(node(i, j, 1), node(i, j, 4))
            union(node(i, j, 2), node(i, j, 3))

total_mirrors = 0

for i in range(1, R + 1):
    for j in range(1, C + 1):
        ch = grid[i - 1][j - 1]

        if ch == '.':
            continue

        total_mirrors += 1

        if ch == '/':
            a = find(node(i, j, 1))
            b = find(node(i, j, 2))
        else:
            a = find(node(i, j, 1))
            b = find(node(i, j, 3))

        cnt[a] += 1
        if a != b:
            cnt[b] += 1

ans = []

for r in range(1, R + 1):
    if cnt[find(node(r, 1, 3))] == total_mirrors:
        ans.append(f"W{r}")

for r in range(1, R + 1):
    if cnt[find(node(r, C, 4))] == total_mirrors:
        ans.append(f"E{r}")

for c in range(1, C + 1):
    if cnt[find(node(1, c, 1))] == total_mirrors:
        ans.append(f"N{c}")

for c in range(1, C + 1):
    if cnt[find(node(R, c, 2))] == total_mirrors:
        ans.append(f"S{c}")

print(len(ans))
if ans:
    print(*ans)
```番号付け関数は重要な実装の詳細です。 セル側ごとに個別のノードを作成し、隣接するセルを明示的に接続する代わりに、番号付けスキームにより、共有境界の両側に同じ ID が割り当てられます。 これにより、隣接するセル間の移動が自動的にモデル化されます。 

カウントフェーズも微妙です。 ミラーは 2 つの軌道コンポーネントに寄与します。 両方の側がたまたま同じ DSU コンポーネントに属している場合、そのコンポーネントに対してミラーを 1 回だけカウントする必要があります。 

境界開口部は外側の境界セグメントに直接対応します。 最後の 4 つのループは、単にそれらの境界ノードをテストします。

 ## 特殊なケース

 検討してください```
1 1
/
```ミラーの 2 つの側面は、異なる DSU コンポーネントに属します。 アルゴリズムは両方のコンポーネント カウンタをインクリメントします。 すべての境界開口部はこれら 2 つのコンポーネントのいずれかに属するため、4 つの入り口すべてが報告されます。 

考慮する```
1 1
\
```ミラー パーティションは変更されますが、カウント ロジックは同じです。 このアルゴリズムは幾何学的なシミュレーションには依存せず、コンポーネントの構造のみに依存するため、両方のミラーの方向が均一に処理されます。 

考慮する```
2 2
..
./
```いくつかの境界開口部は、ミラーに触れることのないコンポーネントに属しています。 それらのコンポーネントのカウントは 0 のままですが、ミラーに接触しているコンポーネントのカウントは 1 になります。 ミラーの総数に対する最終的な等価性テストでは、ミラーが自動的に除外されます。 

最も微妙なケースは、ミラーの両側が同じ DSU コンポーネントに属している場合です。 実装チェック`if a != b`2 番目のカウントを追加する前に。 この条件がないと、ミラーは 2 回カウントされ、一部の有効な入り口が拒否されます。
