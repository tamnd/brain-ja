 ## 解決策
 ## 問題の理解

 位置 1 から n に関連付けられた複数の強さのセットが与えられ、これらの位置の順列を出力することができます。 順列を修正した後、独立したプロセスが、長さ k の連続セグメントの値を増やす操作を使用して、各位置の必要な値を満たすことを試みます。 

各操作では、現在の順列で長さ k のウィンドウが選択され、そのウィンドウ内のすべての要素が 1 ずつ増分されます。 固定順列のコストは、位置 i がすべての i に対して少なくとも a[i] に達するために必要なそのような操作の最小数です。 私たちの仕事は、特定の順列に対してこのコストを計算することではなく、このコストを可能な限り大きくする順列を構築することです。 

主な問題点は、コストが、サイズ k の重複するウィンドウ内にどれだけ大きな要件がグループ化されるかによって決まることです。 各操作で多くの値をまとめてカバーできるように大きな値を配置すると、合計の操作数が減少します。 窓口が需要の高いポジションを繰り返し「逃す」ことを強いられるような方法で拡散すると、コストが増加します。 

この制約により、n は 2×10^5 まで許可され、すべての順列を試行したり、多数の候補のプロセスをシミュレートしたりするアプローチは除外されます。 順列ごとの O(n²) 推論でも遅すぎるため、ソリューションは単一パスまたはほぼ線形の時間で順列を構築する必要があります。 

k = 1 の場合、微妙なエッジケースが現れます。各操作は 1 つの要素にのみ影響するため、コストは順序に関係なく、すべての a[i] の合計になります。 この場合、あらゆる順列が最適であるため、グループ化動作に依存せずに構成が依然として有効である必要があります。 

k = n の場合、別のエッジケースが発生します。 すべての操作はすべての位置に同時に影響を与えるため、コストは max(a[i]) になります。 繰り返しますが、任意の順列は機能し、構築では局所性の問題を想定すべきではありません。 

本当に難しいのは中間の k です。ここでは、ウィンドウの重なりがスライド式の「カバレッジ容量」効果を生み出し、順序によって大きな需要をどれだけ効率的に償却できるかが決まります。 

## アプローチ

 直接的なアプローチでは、特定の順列のコストを評価しようとします。 固定配置の場合、必要なセグメント操作の数を貪欲にシミュレートできます。 一般的なアイデアは、左から右に処理し、ある位置がまだターゲットを下回るたびに操作を繰り返し適用することです。 ただし、各増分は 1 単位の進行のみに寄与し、a[i] は 10^9 に達する可能性があるため、このシミュレーションでは最悪の場合でもすでに O(n・max(a)) のコストがかかります。 さらに重要なことに、多くの順列をテストする必要があるため、これは完全に不可能になります。 

構造的な洞察は視点を逆転させることで生まれます。 「順列を与えた場合、どのようなコストが得られるか」を考えるのではなく、「どのような配置でスライディング ウィンドウの効率が最も低くなるか」を考えます。 各操作は、隣接する位置に分散された k 個の増分に寄与します。 大きな要求がクラスター化されている場合、1 つの操作で多くの大きな値を一度に支援できます。 コストを最大化するには、このようなクラスタリングを防止し、高い値が互いのカバレッジにできるだけ干渉しないようにしたいと考えています。 

これは、サイズ k のウィンドウによって引き起こされる間隔に関する古典的な貪欲な順序付けの問題になります。 各位置は k 個の連続するウィンドウに参加していると考えることができるため、大きな値を遠く離れて配置すると、それらを満たすために必要な操作の数が増加する傾向があります。これは、単一のウィンドウが多くの大きな要求に繰り返し恩恵をもたらすことはないためです。

重要な観察は、最悪の配置は、順列レイアウトで k を法とする剰余クラス全体に大きな値を均等に分散することによって達成されるということです。 これにより、長さ k のウィンドウが交差するのは各クラスの非常に大きな値が 1 つだけになり、共有カバレッジが制限されます。 実際には、これはインデックスを値でソートし、循環的に k 個のバケットに割り当て、バケットを連結することによって実現されます。 

この構造により、大きな a[i] 値が可能な限り少なくとも k 個の位置で区切られるようになり、グループ化された場合よりもプロセスに操作を何度も「再適用」することが強制されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルート フォース シミュレーション | O(n! · n · max(a)) | O(n) | 遅すぎる |
 | 貪欲な循環分布 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス 1 から n の順列を構築します。 

1. すべてのインデックスを必要な値 a[i] で降順に並べ替えます。 

これにより、強制されるオペレーションの数がこれらのポジションによって支配されるため、最も「高価な」ポジションが最初に配置されるようになります。 
2. k 個の空のバケットを作成します。 

これらのバケットは最終的な配置における残差クラスを表し、高い値の間の分離を保証します。 
3. ソートされたインデックスを反復処理し、ラウンドロビン順で 1 つずつバケットに割り当てます。 

最初に大きいものはバケット 0 に、その次はバケット 1 に、というように循環的に配置されます。 

これにより、最終的な連結において、連続する大きな値が少なくとも k 個の位置で分離されることが保証されます。 
4. すべてのバケットをバケット 0 からバケット k-1 まで順番に連結して、最終的な順列を形成します。 

これにより、各バケットが間隔をあけたサブシーケンスを形成するレイアウトが生成され、それらを結合すると分離特性が維持されます。 

これが機能する理由は、長さ k の各ウィンドウが、大きな値の「密な」領域内の各バケットから最大 1 つの要素と交差できるためです。 大きな値はバケット全体に分散されるため、単一のウィンドウで多くの高需要インデックスを繰り返しカバーすることはできません。 これにより、複数の高い a[i] 位置にわたってカバレッジを効率的に再利用できないため、最小操作数が増加することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

idx = list(range(n))
idx.sort(key=lambda i: a[i], reverse=True)

buckets = [[] for _ in range(k)]

for t, i in enumerate(idx):
    buckets[t % k].append(i + 1)

ans = []
for b in buckets:
    ans.extend(b)

print(*ans)
```実装は構築の後に直接続きます。 a[i] を減らすことによってインデックスを並べ替えます。これにより、最も要求の厳しい位置が最初に処理されるようになります。 ラウンドロビン割り当てにより、k 個のバケットに均等に分散されます。これがクラスタリングを防ぐ中心的なメカニズムです。 

最後の連結は重要です。これは、各バケット内の内部順序を維持しながら、異なるバケットの要素がおよそ k の距離でインターリーブされることを保証します。 この問題では 1 から n までのラベルが付けられた位置が想定されるため、出力で 1 から始まるインデックスを使用する必要があります。 

## 実用的な例

 n = 5、k = 3、値が [7、77、2、22、222] である入力を考えてみましょう。 

インデックスを値でソートした後、値に対応するインデックスを取得します。 

222 (インデックス 5)、77 (インデックス 2)、22 (インデックス 4)、7 (インデックス 1)、2 (インデックス 3)

 k = 3 個のバケットに周期的に分配します。 

| ステップ | インデックス | 値 | バケットの割り当て |
 | --- | --- | --- | --- |
 | 1 | 5 | 222 | バケット0 |
 | 2 | 2 | 77 | バケット 1 |
 | 3 | 4 | 22 | バケツ2 |
 | 4 | 1 | 7 | バケット0 |
 | 5 | 3 | 2 | バケット 1 |

 バケットは次のようになります。 

バケット 0: [5, 1]

 バケット 1: [2, 3]

 バケット 2: [4]

 連結すると: [5, 1, 2, 3, 4]

 これは、大きな値 (5 と 2) を分散させる順列と一致し、サイズ 3 のウィンドウが両方を繰り返し効率的にカバーできないことが保証されます。 

2 番目の例: n = 6、k = 2、値 [1、100、2、99、3、98]

 ソートされたインデックス: 2、4、6、3、5、1

 バケット:

 バケット 0: [2, 6, 5]

 バケット 1: [4, 3, 1]

 最終的な順列: [2, 6, 5, 4, 3, 1]

 この変更により、長さ 2 のウィンドウでは、すべての高い値をグループ化するのではなく、高い値と中間の値が強制的に混合されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートインデックスが優先され、バケットの割り当ては線形です。 
| スペース | O(n) | バケットとインデックス リストの保存 |

 この制約では最大 2×10^5 要素が許可されるため、O(n log n) の構築は十分に制限内に収まります。 メモリ使用量は直線的で安定しています。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    idx = list(range(n))
    idx.sort(key=lambda i: a[i], reverse=True)

    buckets = [[] for _ in range(k)]
    for t, i in enumerate(idx):
        buckets[t % k].append(i + 1)

    ans = []
    for b in buckets:
        ans.extend(b)

    return " ".join(map(str, ans))

# provided sample
assert run("5 3\n7 77 2 22 222\n") == "5 1 2 3 4", "sample 1"

# all equal values
out = run("4 2\n5 5 5 5\n")
assert sorted(out.split()) == ["1","2","3","4"]

# k = 1
out = run("4 1\n1 100 2 99\n")
assert sorted(out.split()) == ["1","2","3","4"]

# k = n
out = run("3 3\n10 20 30\n")
assert sorted(out.split()) == ["1","2","3"]

# descending already
out = run("5 2\n5 4 3 2 1\n")
assert sorted(out.split()) == ["1","2","3","4","5"]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | k=1の場合 | 任意の順列 | 無関係なエッジケースの順序付け |
 | k=n の場合 | 任意の順列 | フルカバレッジの縮退 |
 | 等しい値 | 任意の順列 | 対称性と安定性 |
 | ソートされた入力 | 有効な置換 | 最初の順序に依存しない |

 ## 特殊なケース

 k = 1 の場合、すべての操作は単一の位置にのみ影響するため、インデックス間に相互作用は存在しません。 このアルゴリズムは引き続きソートして 1 つのバケットに分散し、すべてのインデックスの単純な並べ替えを生成します。 バケットは 1 つしかないため、構造は正しく縮退されます。 

k = n の場合、すべての操作は配列全体に影響を与えるため、相対的な順序付けは実現可能性に影響しません。 この構築では、局所性の問題を想定せずにインデックスを再配置するだけであるため、依然として有効な順列が出力されます。 

すべての a[i] が等しい場合、位置間に意味のある区別はありません。 ラウンドロビン分布は単純に任意の順序を生成します。これは、対称要件の下ではすべての置換が同じコストを生み出すという事実と一致します。
