 ## 解決策
 ## 問題の理解

 3 人分の料理の割り当てのタイムラインが与えられ、各文字が A、B、C のいずれかである文字列としてエンコードされています。各位置は 1 日を表し、その日にちょうど 1 人が料理をします。 

目標は、既存のスケジュールを再調整することではなく、結果として得られるタイムラインのどこかに、合計で 3 人全員が少なくとも 1 回含まれる連続 3 日のブロックが存在するように、さらに何日追加する必要があるかを決定することです。 言い換えれば、A、B、C を含む長さ 3 のウィンドウが必要です。 

タスクは、この条件を達成できるようにするために、現在のシーケンスの最後に追加する必要がある余分な日数の最小値を見つけることです。 

n が 2×10^5 までという制約は、線形または線形に近い解が必要であることを意味します。 追加される可能性のあるすべてのシーケンスを明示的に試行するアプローチでは、追加される各日に 3 つの選択肢があるため、組み合わせが爆発的に増加します。 長さ k のすべての拡張をチェックしても 3^k 個の可能性が生じますが、これは小さな k の場合でも実行不可能です。 

微妙な点は、元の文字列内のウィンドウだけを完全にチェックする必要はないということです。 有効なウィンドウは、元のスケジュールと追加された日の間の境界をまたぐ場合があります。 これはまさに、素朴な推論が失敗しやすいところです。有効なトリプルを求めて元の文字列をスキャンするだけで失敗と結論付け、境界で揃えられたトリプルを考慮せずに拡張について誤って推論することが簡単に起こります。 

もう 1 つのエッジ ケースは、元の文字列にすでに条件が含まれている場合です。 たとえば、ACBA には、長さ 3 のウィンドウに 3 文字すべてを含む CBA または AC B のような部分文字列がすでに存在するため、答えはゼロになります。 個別のカウントをグローバルにチェックするだけの単純なアプローチでは、すべての文字がどこかに出現するため、連続する 1 つのトリプル内に文字が出現しない場合でも、答えはゼロであると誤って結論付けることになります。 

## アプローチ

 この問題を考える強引な方法は、追加日を 1 つずつシミュレートし、各拡張の後に長さ 3 のウィンドウに A、B、および C が含まれるかどうかをチェックすることです。固定された候補シーケンスの場合、スライディング ウィンドウを使用して妥当性をチェックするコストは O(n) で、長さ k の可能なシーケンスの数は 3^k です。 たとえ小さな k までのすべてのシーケンスを試しただけでも、検索空間は指数関数的に増加します。 これはすぐに実行不可能になります。 

より構造化された観察は、有効なウィンドウの存在を実際に妨げているものに焦点を当てることで得られます。 有効なウィンドウには、3 つのシンボルすべてをまとめて含む 3 つの連続した位置が必要です。 長さ 3 のセグメントを調べた場合、失敗する唯一の方法は、そのセグメントに含まれる異なる文字が 2 つ以下の場合です。 したがって、問題は、そのような多様なトリプルを現在の文字列の末尾またはその後に強制的に出現させることができるかどうかということになります。 

ここでの重要な簡略化は、境界を越える将来の長さ 3 のウィンドウの形成には、元の文字列の最後の 2 文字だけが重要であるということです。 文字列内に完全に含まれる有効なトリプルは、k = 0 ですでに問題を解決しています。それ以外の場合は、文字列の接尾辞と追加された文字を使用して有効なトリプルを形成することを試みるのが最善です。 

したがって、現在の文字列内の長さ 3 のすべての部分文字列を調べます。 いずれかにすでに A、B、C が含まれている場合は完了です。 そうでない場合、文字列には、連続するトリプルごとに少なくとも 1 文字が欠けているという特性があります。 その場合、最悪の状況は、文字列全体にすでに存在する個別の文字の数と、それらの文字が末尾近くでどのように分散されているかによって決まります。

これを確認するより簡単な方法は、長さ 2 のサフィックスを分類することです。位置 n + k で終了する今後の有効なトリプルには、これらのサフィックス文字が少なくとも 1 つ含まれている必要があります。そうでない場合は、以前にすでに存在していたか、左にシフトされる可能性があります。 したがって、不足している文字セットを完全な {A, B, C} トリプルに完成させるために、必要な追加文字の最小数を決定しようとします。 

接尾辞がすでに内部ウィンドウの 3 文字すべてを含んでいる場合、答えは 0 です。そうでない場合は、欠落している文字を事実上「補完」する必要があります。 追加される各日は、ちょうど 1 つの新しい文字を提供するため、サイズ 3 のウィンドウが ABC の順列になるようにするために必要な文字の数を解決しています。 答えは、文字列境界で終わる最適な重複ウィンドウにすでに存在する個別の文字がいくつあるかによって決まります。 

これにより、最後に追加される可能性のある文字と組み合わせた最大 2 のサイズのすべてのウィンドウが直接チェックされ、不足している文字がいくつ供給される必要があるか計算されます。

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンし、長さ 3 の連続するすべての部分文字列をチェックします。そのような部分文字列に A、B、C の 3 文字すべてが含まれている場合、答えは直ちに 0 になります。これは、必要な条件が何も追加せずにすでに存在しているためです。 
2. そのような部分文字列が存在しない場合は、文字列の最後の 2 文字を調べます。 これら 2 つの文字は、追加された文字を使用して新しい有効なトリプルを形成するための唯一の有用な境界コンテキストです。 
3. 拡張後の最終位置で終了する長さ 3 のウィンドウを形成する可能性をすべて考慮します。 このようなウィンドウは、元の文字列の接尾辞 (長さ 1 または 2) と新しく追加された文字で構成されます。 
4. {1, 2} 内の考えられる接尾辞の長さ t ごとに、どの文字がその接尾辞にすでに存在しているかを計算します。 A、B、C のどれが欠落しているかを判断します。 
5. 追加に必要な日数は、そのウィンドウ内の 3 つの異なる文字のセットを完成させるために必要な欠落文字の数です。 
6. 元の文字列に対して最終的な有効なウィンドウがどこから始まるかを自由に決定できるため、すべての有効なサフィックスの選択肢の最小値を取得します。 

### なぜ効果があるのか

 有効な長さ 3 のウィンドウは、いずれかの位置で終了する必要があり、変更後に最も早く終了できるのは、元の文字列と追加された文字の末尾です。 このようなウィンドウは、長さが 3 に固定されているため、元の接尾辞と最大 2 文字だけ重複する可能性があります。したがって、考えられるすべての解決策は、長さ 1 または 2 の接尾辞を選択し、それを A、B、C の完全な順列に完成させることによって完全に特徴付けられます。追加される各日は、ちょうど 1 つの新しい文字に寄与するため、コストは正確に欠落している個別の文字の数となり、過剰な接尾辞の選択を最小限に抑えることで最適な構築が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    def ok3(x):
        return set(x) == {"A", "B", "C"}

    for i in range(n - 2):
        if ok3(s[i:i+3]):
            print(0)
            return

    best = 3

    for t in [1, 2]:
        if t <= n:
            suffix = s[-t:]
            missing = 3 - len(set(suffix))
            best = min(best, missing)

    print(best)

if __name__ == "__main__":
    solve()
```この解決策は、長さ 3 の既存のウィンドウがすでに要件を満たしているかどうかを確認することから始まります。 ヘルパーの条件`set(x) == {"A","B","C"}`トリプルにすべての個別の参加者が含まれているかどうかをキャプチャします。 

そのようなウィンドウが存在しない場合は、文字列の終わりについて推論するだけで済みます。 ループオーバー`t in [1, 2]`将来の有効なウィンドウが既存の文字列と持つ可能性のある 2 つの重複のみを明示的にモデル化します。 長さ 3 のウィンドウは、境界で終了するときに元の文字列と 1 つまたは 2 つの位置で重なることがあります。 

接尾辞ごとに、すでに存在する異なる文字の数を計算します。 有効なトリプルには 3 文字すべてが必要であるため、欠落している文字の数は、追加で必要な日数に直接変換されます。

 ## 特殊なケース

 文字列に AAA のように繰り返される文字が 1 つだけ含まれている場合、長さ 3 のウィンドウはすべて均一であるため、有効なトリプルは存在しません。 接尾辞分析では、異なる文字が 1 つだけ検出されます。つまり、欠落している 2 つの文字を追加する必要があります。この場合、拡張後に長さ 3 のウィンドウが完全に形成される必要があるため、正しく 2 が得られます。 

文字列にすでに ABC が連続して含まれている場合、初期スキャンはそれをすぐに検出し、0 を返します。このチェックがなければ、接尾辞推論は引き続き機能しますが、拡張子を不必要に考慮することになります。 

AABCA のように、文字列の終わり近くではなく途中で有効性が発生する場合、スライディング ウィンドウ チェックは ACB を早期に検出します。 これは、境界ベースのロジックだけでは内部ソリューションを見逃す可能性があるため、拡張について推論する前にすべての内部ウィンドウをチェックする必要がある理由を示しています。
