 ## 解決策
 ## 問題の理解

 私たちは次のことに取り組んでいます$r \times c$一部のセルに兵士が含まれるグリッド。 目標は正確に配置することです$m$そのため、特定の「破壊ゲーム」には非常に正確な難易度が設定されています。 

このゲームでの 1 つの移動は、行または列のいずれかを選択し、その行全体のすべての兵士を削除することで構成されます。 この操作を繰り返すことができます。 構成の回復力は、すべての兵士を除去するために必要なそのような動きの最小数です。 

したがって、タスクは何かを動的に最小化または最大化することではなく、それをクリアするための最適な戦略が正確に使用されるようなグリッドを構築することです。$k$移動するか、そのような取り決めが存在しないと報告する。 

入力サイズの寸法が小さい ($r, c \le 25$)、ただし、の値は$k$まで大きくすることができます$10^9$。 これは、問題のほとんどが総当り検索ではなく組み合わせによるものであることを直ちに示唆しています。 行または列のサブセットの探索や戦略のシミュレーションに依存するソリューションは、それが独立している場合にのみ問題ありません。$k$、 以来$k$それ自体はグリッドの寸法よりもはるかに大きい場合があります。 

微妙なエッジケースとしては、$k$両方を超えることができる$r$そして$c$。 1 回の移動で少なくとも 1 つの完全な行または列が削除され、残りの行または列のみが削除されるため、これを実現することは不可能です。$r + c$合計すると意味のある明確な選択肢が得られます。 実際、復元力の真の上限は、行と列の間のカバレッジの構造によって厳密に制約されます。$m$。 

もう 1 つのエッジケースは次のような場合です$m$非常に小さいか非常に大きいです。 もし$m = 0$、答えは当然ゼロ手になりますが、ここでは$m \ge 1$。 もし$m = rc$、すべてのセルが埋められ、復元力は配置の柔軟性ではなく、グリッドの寸法のみに依存します。 

最大の困難は、占有セルのセットに「複雑さをカバーする行と列」を正確にエンコードする必要があることです。 

## アプローチ

 総当たりの観点から考えると、可能な限りの配置を試みることになります。$m$ソルダーを抽出し、それらをカバーするために必要な行/列の最小削除数を計算します。 各構成において、これは基本的に行と列に関するヒッティングセットの問題です。 固定グリッドの場合でも、正確な最小移動数を評価するには、各ステップで行または列を削除した方が安いかどうかを推論する必要があり、これはすでにサブセットにわたる検索を示唆しています。 

可能な構成の数は次のとおりです。$\binom{rc}{m}$でさえ天文学的な大きさです。$r, c \le 25$。 したがって、ブルートフォースは直ちに不可能です。 

重要な点は、運用構造が非常に厳格であることです。 移動するたびに、行全体または列全体が削除されます。 これは、どの戦略も、結合がすべての兵士セルをカバーする行と列のセットを選択することに対応することを意味します。 移動の数は、そのような最小選択のサイズです。 

したがって、問題は次のようになります。この 2 部グラフの最小頂点カバー サイズが等しくなるように、行と列の間に 2 部の発生構造を構築します。$k$、配置するエッジ (兵士) の数も制御します。 

ここで、小さなグリッド サイズが重要になります。 最大で 25 行と 25 列があるため、「独立制約」の最大可能数は各辺で 25 に制限されます。 それを超える構築は、強制的な縮退または不可能な条件に依存する必要があります。 

これについて考える標準的な方法は、行と列を 2 部グラフの 2 つのパーティションとして解釈することです。 の兵士$(i, j)$行間のエッジです$i$そしてコラム$j$。 移動すると頂点が削除され、すべてのエッジをカバーするということは、頂点カバーを選択することを意味します。 ケーニッヒの定理によれば、二部グラフでは、頂点カバーの最小値は一致の最大値と等しくなります。 したがって、復元力は、この 2 部グラフの最大一致のサイズと正確に一致します。 

これは問題を完全に再構成します。つまり、正確に 2 部グラフを構築するように求められます。$m$一致する最大サイズが正確になるようなエッジ$k$。 

これで構造がより明確になりました。 一致するサイズは以下を超えることはできません$\min(r, c)$、その場合はすぐに$k > \min(r, c)$、答えは不可能です。 

一方で、少なくとも次のものがあることを確認する必要があります。$k$行と列のペアが互いに素であるため、より大きな一致を形成することはできません。 

クリーンな構築のアイデアは、$k \times k$対角線上の一致、少なくとも一致するサイズを確保する$k$、残りを慎重に加えます$m-k$マッチングサイズを増やさない方法でエッジを調整します。 標準的なトリックは、余分なエッジをすべて 2 部グラフのすでに「飽和」した部分の内側に配置して、新しい拡張パスが導入されないようにすることです。 

最も単純な安全な構造は次のとおりです。 

私たちが選ぶ$k$行と$k$列間で完全な一致を形成し、必要に応じてこれらの列内にのみ追加のセルを入力します。$k$行と$k$列。 余分なエッジはすでに完全にアクティブなサブグラフ内に制限されるため、最大マッチングをこれ以上増やすことはできません。$k$。 

これにより、実行可能性が低下し、内部での単純なカウントが行われます。$k \times k$サブグリッド。 

また、次のことも保証する必要があります。$m$少なくとも$k$、少なくとも$k$サイズの一致をサポートするにはエッジが必要です$k$、そしてせいぜい$k^2$制限領域内にエッジが存在します。

 ## アルゴリズムのチュートリアル

 このタスクを、行と列の間の 2 部グラフを構築するものとして再定式化します。 

1. まず次のことを確認します。$k > \min(r, c)$。 その場合はサイズが合わない$k$存在する以上の行と列をペアにすることはできないため、これが可能です。 
2. 次に、次のことを確認します。$m < k$。 サイズのマッチング$k$少なくとも必要です$k$エッジなので、これはすぐには不可能です。 
3. 次に、$k \times k$元のグリッド内のアクティブなサブグリッド。 最初のものを選択します$k$行と最初$k$列。 
4. 場所$k$対角セルの兵士$(i, i)$のために$0 \le i < k$。 これにより、少なくともサイズの一致が保証されます$k$、各行と列のペアは独立しているためです。 
5. ここで、まだ配置する必要があります$m - k$追加の兵士。 内部にそれらを任意に埋めます。$k \times k$ブロック、行ごとにスキャンし、必要に応じて対角線をスキップして、正確に到達するまで$m$総兵士数。 
6. 構築されたグリッドを出力します。 

これが機能する理由は、すべてのエッジが同じサイズの 2 部グラフ内に完全に含まれているためです。$k \times k$、したがって、可能な最大の一致は最大で$k$。 明示的に作成したため、$k$互いに素なエッジ、一致は正確です$k$。 

### なぜ効果があるのか

 グリッドは、行と列が 2 つのパーティションであり、兵士がエッジである 2 部グラフを生成します。 復元力は最小頂点カバーのサイズに等しく、これは 2 部グラフの最大一致サイズに等しくなります。 

私たちの構造は 2 つの特性を同時に実現します。 まず、明示的にビルドします$k$対角線を使用して互いに素なエッジを作成し、少なくともサイズの一致を保証します$k$。 次に、すべてのエッジを次の範囲に制限します。$k \times k$サブグラフ。一致する条件の上限を指定します。$k$。 両方の境界が一致するため、一致するサイズは正確に一致します。$k$。 同じサブグラフ内にエッジを追加しても、一致度を高めることはできません。$k$行と$k$使用可能な列があるため、そのカーディナリティーを超える一致はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        r, c, m, k = map(int, input().split())

        if k > min(r, c) or m < k:
            print("NO")
            continue

        grid = [['.' for _ in range(c)] for _ in range(r)]

        # build k diagonal matching in top-left k x k
        placed = 0
        for i in range(k):
            grid[i][i] = '#'
            placed += 1

        # fill remaining edges inside k x k
        for i in range(k):
            for j in range(k):
                if placed == m:
                    break
                if grid[i][j] == '.':
                    grid[i][j] = '#'
                    placed += 1
            if placed == m:
                break

        print("YES")
        for row in grid:
            print("".join(row))

if __name__ == "__main__":
    solve()
```解決策は、不可能なケースを拒否することから始まります。$k$利用可能な行または列の数を超えている場合、または兵士をサポートするのに十分な兵士さえいない場合。$k$-サイズのマッチング。 

グリッドは空に初期化され、次に強制構造を配置します。$k$左上のブロックにいる兵士。 これにより、強制的に$k$独立した行と列のペア。 

次に、同じ内部にのみ残りの兵士を慎重に追加します。$k \times k$地域。 この領域の外側に拡張すると、新しい行または列が使用可能になった場合に追加の一致の可能性が生じる可能性があるため、この詳細は重要です。 すべてを制限したままにすると、一致する上限が固定されたままになります。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k = \min(r, c)$。 例えば：```
3 5 m 3
```ここでの構築では、利用可能なすべての行または列を完全に使用する必要があります。 対角線は依然として機能しますが、2 部構造に緩みはありません。 アルゴリズムは依然として$3 \times 3$ブロックし、その範囲内のみを塗りつぶします。 残りのグリッドが未使用であっても、マッチングは飽和しているので問題ありません。 

もう一つのケースは次のような場合です。$m = k$。 この状況では、対角線のみを配置し、すぐに停止します。 さらに構造を追加しようとすると、総兵士数の制約に違反することになります。 マッチングは正確に残ります$k$、すべてのエッジがすでに構築に不可欠であるためです。 

最後に、いつ$m = k^2$、全体$k \times k$ブロックが埋まってます。 この極端な密度でも、マッチングは以下を超えません。$k$使用可能な行と列の数を超えて追加の独立した行と列のペアを形成できないためです。
