 ## 解決策
 ## 問題の理解

 変換は、文字、スペース、句読点、および大文字と小文字が混在する乱雑なフレーズから始まり、それを一連の子音のみに縮小します。 すべての母音は破棄され、残りのすべての子音は大文字に変換され、これらの保持された文字の順序は保持されます。 重要な組み合わせの自由度はその後に現れます。子音の固定シーケンスを取得したら、2 つのスペースが接触せず、文字列の先頭または末尾がスペースでない限り、子音の間にスペースを挿入することができます。 

したがって、実際のオブジェクトは元の文ではなく、クリーンアップされた長さの文字列です。$k$、そしてそれを連続したグループに分割するあらゆる可能な方法を検討するように求められます。各グループは単一のスペースで区切られたブロックになります。 有効な各出力は、連続する子音間のカット位置の選択に正確に対応します。 

クリーン化された子音シーケンスに長さがある場合$k$、それから、$k-1$ギャップがあり、各ギャップはスペースを配置するかどうかを独立して決定します。 それはすぐに示唆します$2^{k-1}$可能な出力ですが、スペース文字がどの文字よりも小さい場合は辞書順に並べられます。 この順序により、より早いスペースの配置が辞書編集的に優先されます。 

入力サイズは最大です$2 \cdot 10^5$したがって、すべての出力を明示的に生成することは不可能です。 平$k=30$すでに列挙が不可能になります。 インデックス$i$と同じ大きさにすることができます$10^{18}$これにより、反復生成ではなく、組み合わせインデックスのアプローチが強制されます。 

微妙なエッジケースは、単語内の句読点と小文字の母音から生じます。 子音のみが残るため、2 つの異なる元の文字列が同一の子音シーケンスに崩壊する可能性があり、問題はフォーマット ノイズとは完全に独立したものになります。 もう 1 つのエッジ ケースは、子音が 1 つしかない場合です。その場合、ギャップは存在しないため、有効な出力が 1 つだけ存在し、すべての出力が存在します。$i > 1$直ちに「範囲外」を返さなければなりません。 

## アプローチ

 ブルートフォース手法では、子音文字列を構築し、各ギャップにスペースを挿入するかどうかを再帰的に試行します。 これによりすべてが生成されます$2^{k-1}$文字列を取得し、並べ替えて、$i$- 番目。 概念的には正しいですが、分岐はギャップごとに 2 倍になります。$k = 50$これは計算上不可能になり、$k = 200000$それはまったく手の届かないところにあります。 

重要な点は、辞書編集上の順序は、スペースが現れるか現れないかの最も早い位置によって完全に決定されるということです。 スペースはどの文字よりも小さいため、前にスペースを入れると文字列が辞書編集的に小さくなります。 これは、カットの選択をギャップ上のバイナリ文字列として解釈し、1 が「スペースを入れる」ことを意味する場合、辞書編集的な順序は、このバイナリ ベクトルの左から右への辞書編集的な順序に正確に対応することを意味します。 

これにより、問題は次の生成に変わります。$i$-番目の長さのバイナリ文字列$k-1$辞書順に変換し、子音の上に間隔をあけた文字列に戻します。 重要な改善点は、すべての可能性を列挙するのではなく、少しずつ答えを直接構築することです。 各ポジションで、そこにスペースを設定することで残りのランク予算内に収まるかどうかを決定します。 それぞれの決定により可能性の残りのスペースが半分になるため、必要なのはギャップに対する線形スキャンのみです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^k \cdot k \log 2^k)$|$O(2^k)$| 遅すぎる |
 | 最適 |$O(k)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列からすべての文字を抽出し、子音のみを保持し、保持されたすべての文字を大文字として扱います。 これによりシーケンスが生成されます$c_1, c_2, \dots, c_k$。 すべての有効な出力の構造は、このシーケンスのみに依存します。 
2. もし$k = 1$、スペースの選択肢が存在せず、代替文字列を形成できないため、ただちに 1 文字を返します。 
3. 有効な各出力を長さのバイナリ ベクトルとして解釈します。$k-1$、どこの位置$j$の間にスペースがあるかどうかを示します$c_j$そして$c_{j+1}$。 1 はスペースの挿入を意味し、0 は連結を意味します。 
4. 辞書編集上の順序を決定するには、前の位置が優先されることに注意してください。位置 1 にスペースを置くと、文字列はスペースで始まります。これは、文字で始まるよりも常に小さくなります。 したがって、位置 1 にスペースがあるすべての文字列は、スペースがないすべての文字列よりも前に配置され、後の位置についても同様に、前の選択に基づいて条件付けされます。 
5. 任意のサフィックスに対して使用可能な文字列の数を事前に計算します。 位置で$j$、決定を修正した場合、長さの残りの接尾辞$r$貢献する$2^{r}$可能性。 これにより、所定の位置にスペースを配置するかどうかを判断できます。$j$残りのランク内に留まります$i$、またはその構成ブロック全体をスキップする必要があるかどうか。 
6. ギャップを左から右に繰り返します。 それぞれのギャップで比較してください$i$そこにスペースを置くことから始まる構成の数を示します。 もし$i$の方が大きい場合は、そのカウントを減算し、スペースなしで続行します。 それ以外の場合は、スペースを入れて次に進みます。 
7. すべての決定が完了したら、子音と選択したスペースをインターリーブして最終的な文字列を再構築します。 

### なぜ効果があるのか

 このアルゴリズムは、ギャップごとの解空間を 2 つの連続する辞書編集ブロック (その位置にスペースがあるブロックとないブロック) に分割することに依存しています。 固定プレフィックスのすべての補完は辞書編集順に連続したブロックを形成するため、列挙ではなくカウントを使用してブロック全体を安全にスキップできます。 これにより、各ステップが次の不変条件を保持することが保証されます。$i$常に、残りの接尾辞スペース内のランクを参照します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_consonant(ch):
    ch = ch.lower()
    return ch.isalpha() and ch not in "aeiou"

s = input().rstrip("\n")
i = int(input())

letters = []
for ch in s:
    if is_consonant(ch):
        letters.append(ch.upper())

n = len(letters)

if n == 1:
    if i == 1:
        print(letters[0])
    else:
        print("out of bounds")
    sys.exit()

# There are n-1 gaps, total configurations = 2^(n-1)
# We do not explicitly compute full powers; just track remaining i.

# Precompute powers of 2 up to n-1, but cap since i can be large
max_gap = n - 1
pow2 = [1] * (max_gap + 1)
for j in range(1, max_gap + 1):
    pow2[j] = pow2[j - 1] * 2

total = pow2[max_gap]
if i > total:
    print("out of bounds")
    sys.exit()

# Build answer
res = []
remaining_gaps = n - 1

for idx in range(n):
    res.append(letters[idx])
    if idx == n - 1:
        break

    # if we put a space here, we still have 2^(remaining_gaps-1) completions
    cnt_with_space = pow2[remaining_gaps - 1]

    if i > cnt_with_space:
        i -= cnt_with_space
    else:
        res.append(" ")

    remaining_gaps -= 1

print("".join(res))
```前処理ステップでは子音を分離し、大文字小文字を正規化して、問題をきれいな組み合わせ構造にまとめます。 パワーテーブルは、任意の接尾辞の長さに対してどれだけの補完が存在するかをエンコードします。これにより、現在のランクを比較できるようになります。$i$辞書編集ブロックのサイズに対して。 

再構成ループは各ギャップを独立して処理します。 各位置で、スペースを挿入するかどうかの決定は、スペースを挿入するかどうかを選択することと同じです。$i$残りの構成スペースの前半または後半にあります。 これが引き算の理由です`cnt_with_space`ランクを「スペースなし」ブランチに正しくシフトします。 

最後の結合では、必要な書式設定の制約を維持しながら、実際の文字列が再構築されます。 

## 実用的な例

 ### 例 1

 入力:```

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k)$| 各子音とギャップは 1 回処理されます。 
| スペース |$O(k)$| フィルタリングされた子音シーケンスと出力を保存します。 

入力サイズの制約$2 \cdot 10^5$すべての操作が線形であり、単純な算術演算と文字列構造のみを使用するため、快適に処理できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def is_consonant(ch):
        ch = ch.lower()
        return ch.isalpha() and ch not in "aeiou"

    s = input().rstrip("\n")
    i = int(input())

    letters = []
    for ch in s:
        if is_consonant(ch):
            letters.append(ch.upper())

    n = len(letters)
    if n == 1:
        return letters[0] if i == 1 else "out of bounds"

    pow2 = [1] * (n)
    for j in range(1, n):
        pow2[j] = pow2[j - 1] * 2

    if i > pow2[n - 1]:
        return "out of bounds"

    res = []
    rem = n - 1

    for idx in range(n):
        res.append(letters[idx])
        if idx == n - 1:
            break
        cnt = pow2[rem - 1]
        if i > cnt:
            i -= cnt
        else:
            res.append(" ")
        rem -= 1

    return "".join(res)

# provided samples
assert run("NOI.PH\n3\n") == "NP H"
assert run("Alice, Bob, and Cindy\n344\n") == "LC BB ND CNDY"

# custom cases
assert run("abc\n1\n") == "B C"   # simple spacing variations
assert run("abc\n8\n") == "out of bounds"
assert run("a!e!i!o!u\n1\n") == "out of bounds"
assert run("B\n1\n") == "B"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`abc`|`B C`| 最小限のマルチギャップ動作 |
 |`abc, i large`|`out of bounds`| 超えて溢れる$2^{k-1}$|

 ## 特殊なケース

 次のような単一子音入力`"b!!!"`ちょうどに減少します`B`。 ギャップがないため、有効な出力は文字自体だけです。 アルゴリズムはチェックすることでこれを即座に処理します。$k = 1$これにより、存在しないギャップに対する配列のインデックス付けが防止されます。 

次のような母音のみの文字列`"aeiou!!!"`空の子音シーケンスに崩壊します。 この問題は少なくとも 1 つの子音を保証するため、有効なテストには現れませんが、堅牢な実装では、空のリストに対してべき乗やインデックス付けを試行しないようにする必要があります。 

構成の総数を超える大きなインデックスは、構築前に比較することで処理されます。$i$に対して$2^{k-1}$。 このチェックがないと、アルゴリズムは誤って解釈しようとします。$i$有効なランクとして認識し、「範囲外」をレポートする代わりに無効な文字列を生成します。
