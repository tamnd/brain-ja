 ## 問題の理解

 私たちには、平面内の開始点と、固定された一連の動作が与えられています。 各移動には 2 つの情報があります: 最大長$K_i$そして、方向の種類 (水平または垂直) の制約。 水平方向に移動するには、東または西に移動する必要があり、1 から 2 までの整数のステップ長を選択できます。$K_i$。 垂直方向の移動の場合も同様に、長さが 1 から 1 までの間の北または南を選択します。$K_i$。 

課題は、すべての動作を順番に実行した後、正確に原点で終了するように、方向とステップの長さの両方を選択できるかどうかを決定することです。 可能であれば、有効な選択肢のシーケンスを 1 つ構築する必要もあります。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースにわたって移動するため、ソリューションはテスト ケースごとに線形またはほぼ線形の時間で実行する必要があります。 方向や長さの割り当てを個別に列挙しようとするアプローチは、それぞれの動きに 2 つの方向の選択肢があり、最大で 2 つの方向の選択肢があるため、指数関数的に爆発的に増加します。$K_i$長さの選択。 

微妙な問題は、明示的に方向の自由度を使用しない限り、動きがゼロの周りで対称にならないことです。 各移動は、固定軸に沿って正または負の整数に寄与します。 つまり、すべての動きは、2 つの区間の和集合内に収まるように制約された整数変数です。$[-K_i, -1]$または$[1, K_i]$。 主な困難は、合計が固定目標に一致するようにこれらの選択肢を調整することです。 

よくある失敗例は、貪欲なメソッドが方向を修正するのが早すぎる場合に発生します。 たとえば、常に可能な限り最大のステップで残り距離を縮めようとすると、範囲の柔軟性が不十分で残りの手で補えない状況が発生する可能性があります。 もう一つの失敗は、たとえ大きな調整があったとしても、一部の動きは小さな調整として「無駄にする」必要があるかもしれないということを無視したことから起こります。$K_i$。 

## アプローチ

 ブルートフォース解釈では、各移動を符号と長さを個別に選択するものとして扱い、結果の合計が必要な変位に等しいかどうかをチェックします。 これにより、およそのサイズの検索スペースが得られます。$\prod (2K_i)$、それはたとえ小さくても実行不可能です$n$。 長さを固定値に制限しても、$2^n$符号構成は依然として指数関数的です。 

重要な観察は、水平成分と垂直成分が独立しているということです。 合計の水平変位は水平方向の移動のみに依存し、垂直方向の変位は垂直方向の移動のみに依存します。 これにより、問題が 2 つの別個の 1 次元構造に分割されます。 

ここで問題は次のようになります: 与えられた値$K_i$、各変数を代入します$x_i$どちらかの整数$[1, K_i]$または$[-K_i, -1]$、それらの合計が目標に等しくなるように$S$。 この構造は、変数ごとに禁止されたゼロを含む制限された区間です。 重要な単純化は、実現可能性が、組み合わせパリティやサブセット構造ではなく、達成可能な合計の範囲によってのみ左右されるということです。 各変数はゼロを除く連続区間のすべての整数を取ることができるため、グローバルな実現可能性の限界を維持する限り、いつでもローカルに調整できます。 

任意のプレフィックスの実行可能な合計範囲は次のとおりです。$[-\sum K_i, \sum K_i]$。 これは必要な条件を与えます。 主な課題は、残りのサフィックスの実現可能性を維持しながら、オンラインで値を構築することです。 

標準的な建設的なアイデアは、残りの必要な合計を維持しながら、順番に手を処理することです。 各ステップで、残りの容量を使用して残余要件を達成できるように、現在の移動の値を選択します。

 ## アルゴリズムのチュートリアル

 水平軸と垂直軸を独立して解決します。 各辺は同一であるため、目標合計を使用して単一シーケンスのプロセスを説明します。$S$。 

1. 水平方向か垂直方向かに応じて、移動を 2 つの配列に分割します。 各グループについて、その軸に沿った目標合計のみを考慮します。これは次のようになります。$-x$または$-y$。 
2. サフィックスの合計を計算します。$K_i$。 させて$rem[i]$移動による残りの最大貢献度の合計になります。$i$これからも。 この値は、位置の後に加算または減算できる最大の大きさを表します。$i$。 
3. 実行中の変数を維持する$R$、最初は目標合計に等しい$S$。 これは、将来の選択によってどの程度の変位を達成する必要があるかを表します。 
4. プロセスは左から右に進みます。 移動中$i$、選ばなければなりません$x_i \in [-K_i, -1] \cup [1, K_i]$。 条件を維持する値を割り当てようとします$|R - x_i| \le rem[i+1]$true の場合、サフィックスが引き続き補正できることを保証します。 
5. もし$R$が正の場合、正の値を選択してそれを減らそうとします。$x_i$。 から始めます$x_i = \min(K_i, R)$これは残りの要件に最もよく一致するためです。 この選択が実現可能性を損なう場合は、大きさを減らすか、符号を反転して反対の方向を試みます。 
6. もし$R$が負の場合、負の値を使用して対称的に上に移動しようとします。$x_i$から始まる$x_i = -\min(K_i, -R)$、再度実現可能性を確認し、必要に応じて調整します。 
7. 固定後$x_i$、 アップデート$R := R - x_i$そして続けます。 

これが機能する理由は、すべてのステップで、残りの必要な合計がサフィックスの達成可能な間隔内にあるという不変条件を維持するためです。 各サフィックスは連続対称範囲内の任意の値に寄与する可能性があるため、この不変条件を維持することで、境界を破らない限り、残りに対して有効な割り当てが存在することが保証されます。 

必須値としてゼロを通過する必要がないため、禁止されたゼロは干渉しません。 必要なのは、個々の割り当てが対称的な非ゼロ間隔内に収まるようにすることだけです。この間隔には、実現可能性と一致する少なくとも 1 つの有効な整数が常に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_group(items, target):
    n = len(items)
    suffix = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix[i] = suffix[i + 1] + items[i][0]

    res = [0] * n
    R = target

    for i in range(n):
        k = items[i][0]

        # try positive first
        for sign in (1, -1):
            lo = 1
            hi = k
            if sign == -1:
                lo, hi = -k, -1

            # choose closest to R in that signed interval
            if sign == 1:
                x = min(hi, max(lo, R))
            else:
                x = max(lo, min(hi, R))

            if abs(R - x) <= suffix[i + 1]:
                res[i] = x
                R -= x
                break

    return res

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, x, y = map(int, input().split())

        H = []
        V = []

        for _ in range(n):
            k, d = input().split()
            k = int(k)
            if d == 'H':
                H.append([k, 'H'])
            else:
                V.append([k, 'V'])

        hx = solve_group([[k, d] for k, d in H], -x)
        vy = solve_group([[k, d] for k, d in V], -y)

        if hx is None or vy is None:
            out.append("NO")
            continue

        out.append("YES")

        hi = vi = 0
        for k, d in H + V:
            if d == 'H':
                if hx:
                    val = hx.pop(0)
                    if val > 0:
                        out.append(f"{val} E")
                    else:
                        out.append(f"{-val} W")
            else:
                if vy:
                    val = vy.pop(0)
                    if val > 0:
                        out.append(f"{val} N")
                    else:
                        out.append(f"{-val} S")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核はサフィックス実行可能性配列であり、貪欲な決定によって構築が罠にはまるのを防ぎます。 各ステップでは、残りの必要な合計が残りの合計容量に適合するかどうかを明示的にチェックすることにより、局所的には妥当でありながら全体的には安全な値を選択します。 

よくある実装の落とし穴は、軸の分解と再構成の順序を混合することです。 出力は元の順序に従う必要があるため、印刷時に水平ソリューションと垂直ソリューションを慎重にインターリーブする必要があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        input = sys.stdin.readline
        t = int(input())
        ans = []

            n, x, y = map(int, input().split())

                    ans.append(f"{k} N")
        return "\n".join(ans)

    return solve()

 ## 特殊なケース

 重要なエッジケースは、ターゲットがまさに実現可能性の境界上にある場合であり、これはすべての合計を意味します。$K_i$絶対的な目標に等しい。 その状況では、すべての動きは一貫した方向に最大の大きさを取ることを強制されます。 実行可能性チェックにより、アルゴリズムはこれを自然に処理します。$|R - x_i| \le rem[i]$各ステップで有効な継続は 1 つだけ許可されます。 

もう 1 つのケースは、初期の手は大きくても、後の手はすべて小さい場合です。 単純に欲張りな選択をすると、最初に消費しすぎて、調整能力が不十分になる可能性があります。 接尾辞ベースの制約は、残りの要件が接尾辞が生成できるものを超えるような割り当てを拒否することで、これを防ぎます。
