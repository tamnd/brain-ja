 ## 問題の理解

 すべての整数に対して$n$、約数を探すように求められます$d$通常よりも強力な特性を備えています。$d$分ける$n$、 しかし$d^k$も分けなければなりません$n$。 このようなすべての約数の中で、それぞれの最大のものを採用します。$n$。 次のすべての数値に対してこの値を計算した後、$1$まで$N$、それらを合計します。 

したがって、このタスクは約数を直接リストすることではなく、各数値について、その最大の整数を抽出することです。$k$-乗はまだその数字に収まります。 その「最大の有効な約数」は、次の素因数がどのように計算されるかによって決まります。$n$除数を累乗すると素因数分解で指数が乗算されるため、分散されます。 

制約により許可されるのは、$N$あたりまで$5 \times 10^7$、試行除算を使用して各数値を個別に因数分解しようとするものはすべて除外されます。 平$O(N \sqrt{N})$または$O(N \log N)$重い定数を使用すると遅すぎます。 唯一の実行可能な方向は、すべての数値の算術構造をほぼ線形な時間で事前計算し、それを再利用することです。 

微妙なエッジケースが現れるのは、$k$大きいです。 もし$k$のすべての素指数を超えます$n$の場合、制約を乗り越えた素数は存在しません。$k \cdot \text{exp}(d,p) \le \text{exp}(n,p)$したがって、有効な除数は次のとおりです。$1$。 たとえば、次の場合$k=10$、その後、$n=72=2^3\cdot 3^2$、各指数を次の値で割ったもの$10$はゼロになるので、答えは$1$。 数値的に「根を近似」しようとする単純なアプローチでは、指数のこの離散的な崩壊を自然に捉えることはできません。 

## アプローチ

 ブルートフォース解釈は簡単です。 それぞれについて$n$、すべての約数を列挙します$d$、どうかを確認してください$d^k$分割する$n$、最大値を追跡します。 これは正しいですが、約数の生成にはすでにおおよそのコストがかかります$O(\sqrt{n})$数値ごとに異なり、条件を検証すると因数分解の作業がさらに追加されます。 全体$n \le N$、これは許容範囲をはるかに超えます。 

重要な観察点は、次の条件です。$d^k \mid n$は純粋に素数指数の乗算です。 もし$$n = \prod p^{a_p}, \quad d = \prod p^{b_p},$$それから$$d^k = \prod p^{k b_p}.$$したがって、制約は次のようになります$k b_p \le a_p$、 意味$b_p \le \left\lfloor \frac{a_p}{k} \right\rfloor$。 これにより、すべての組み合わせ検索が削除されます。$d$の各指数を縮小することによって一意に決定されます。$n$の係数で$k$。 

したがって、問題はコンピューティングに帰着します。$n \le N$、番号$$f(n) = \prod p^{\lfloor v_p(n)/k \rfloor}.$$それから合計します$f(n)$全体$n$。 

この構造はふるいアプローチと互換性があります。 最小の素因数を事前に計算すると、すべての数値を対数またはほぼ定数時間で因数分解して計算できます。$f(n)$段階的に。

 ## アルゴリズムのチュートリアル

 この計算は、すべての整数を迅速に因数分解する方法に依存しており、これは各数値の最小の素因数を事前に計算することによって実現されます。 

1. アレイを構築する`spf`どこ`spf[x]`最小の素数除算を保存します$x$。 これはふるい式のプロセスを使用して行われます。 このステップにより、後で最小の素因数を繰り返し取り除くことによって、すべての数値を因数分解できるようになります。 
2. 配列を初期化する`f`サイズの$N$、 どこ`f[n]`最大のものを保存します$k$-楽しい約数$n$。 因数分解を使用して各エントリを個別に計算します。 
3. 各整数について$n$から$1$に$N$を使用して因数分解します。`spf`配列。 素因数を抽出する際、指数カウントの辞書または一時的なリストを維持します。$n$。 各部門がすぐに数を減らすため、このステップは効率的です。 
4. 各素数について$p$指数付き$a$で$n$、計算する$a // k$。 これは次の指数です$p$結果として得られる除数。 
5. 再構築$f(n)$乗算して$p^{a // k}$因数分解におけるすべての素数にわたって。 これにより、一意の最大除数が得られます。$k$-乗除算$n$。 
6.追加$f(n)$現在のグローバル合計に変換します。 
7. すべての数値を処理した後の最終合計を出力します。 

これが機能する主な理由は、次の制約があるためです。$d^k \mid n$素数にわたって完全に分解され、最大化は素数ごとに独立して行われます。 指数が個別に固定されると、有効な最大除数が 1 つだけ存在するため、重複の問題がなく、数値ごとの合計で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_spf(n):
    spf = list(range(n + 1))
    for i in range(2, int(n ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def solve():
    N, k = map(int, input().split())

    if k > 60:
        print(N)
        return

    spf = build_spf(N)

    total = 0

    for x in range(1, N + 1):
        n = x
        res = 1

        while n > 1:
            p = spf[n]
            cnt = 0
            while n % p == 0:
                n //= p
                cnt += 1

            exp = cnt // k
            if exp:
                res *= p ** exp

        total += res

    print(total)

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数を構築するため、繰り返し除算することで各整数を因数分解できます。`spf[n]`。 因数分解中、素数ごとの指数カウントを集計し、それを次の値で割ってすぐに減らします。$k$。 この縮小を生き残った素数だけが再構築された約数に寄与します。 

ショートカット`if k > 60: print(N)`以下の整数がないことを反映しています$10^{18}$- 一般的な制約では、スケール範囲の素数指数が 60 を超えます。 この問題のコンテキストでは、安全な最適化として機能します。$2^{60}$すでに指数削減の動作上の上限を超えており、すべての寄与が崩壊します。$1$。 より厳密な実装では、これを常に完全なロジックを実行することで置き換えることができます。

 ## 特殊なケース

 いつ$k$非常に大きく、すべての指数を次の値で割ったもの$k$ゼロになります。 たとえば、入力の場合$n=18, k=10$、 我々は持っています$18 = 2^1 \cdot 3^2$、両方の指数がゼロになるため、結果は次のようになります。$1$。 整数の除算であるため、アルゴリズムはこれを自然に処理します。`cnt // k`すべての素数に対してゼロが生成され、再構築に寄与しません。 

いつ$n$のような純粋なプライムパワーです$n = p^{100}$、行動が可視化されます。 もし$k=3$、指数は次のように減ります。$33$、そしてアルゴリズムは再構築します$p^{33}$。 ふるい因数分解では、指数が正確に 1 回カウントされるため、重複や過剰カウントは発生しません。
