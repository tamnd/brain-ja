 ## 解決策
 ## 問題の理解

 からの各値`1`に`n`両方の順列で 1 回だけ出現します。 

価値のために`v`、 させて：

-`posP[v]`最初の順列における位置になります。 
-`posQ[v]`は 2 番目の置換における位置になります。 

クエリは、最初の順列の位置が内側にある値の数を尋ねます。`[l1, r1]`2 番目の順列での位置は内側にあります`[l2, r2]`。 

データをグリッド上の点として視覚化する便利な方法です。 あらゆる価値観`v`1点貢献する$$(posP[v],\; posQ[v])$$そしてクエリは、軸に沿った長方形の中にいくつの点があるかを尋ねます。 

両方の配列は順列であるため、正確には次のようになります。`n`同じ x 座標または y 座標を共有する 2 つの点はありません。 

この制約により、クエリごとのスキャンが完全に除外されます。 と`n = 10^6`そして`m = 2 \cdot 10^5`、たとえ`O(n)`クエリには大まかに必要になります`2 \cdot 10^{11}`操作。 

クエリごとに対数に近い時間が必要です。 

クエリ パラメーターも、前の回答を使用してエンコードされます。 これにより、Mo のアルゴリズムなどのオフライン並べ替え手法が妨げられます。 質問はオンラインで指定された順序で回答する必要があります。 

よくある間違いの原因は、長方形の境界線が包括的であることを忘れることです。 

例えば：```
p = [1,2,3]
q = [1,2,3]
```クエリ```
[1,2] × [2,3]
```値のみが含まれます`2`、したがって、答えは次のとおりです`1`。 

中途半端な解釈では、誤って次のような結果が得られます。`0`。 

もう 1 つの微妙なケースは、オンライン変革から生じます。 仮定する`n = 5`そして前の答えは`2`。 それから`x = 3`、 そして$$f(5)=((5-1+3)\bmod 5)+1=3.$$モジュロ ラップアラウンドはクエリ生成の一部であり、最小値と最大値を取得する前に適用する必要があります。 

## アプローチ

 最も直接的な解決策は、各クエリを個別に処理することです。 

あらゆる価値観に対して`v`かどうかを確認します。$$l_1 \le posP[v] \le r_1$$そして$$l_2 \le posQ[v] \le r_2.$$これはクエリの定義を文字通り実装しているため、これは正しいです。 残念ながら、それは必要です`O(n)`クエリごとに作業します。 と`10^6`価値観と`2 \cdot 10^5`クエリ、最悪の場合は超過`10^{11}`小切手。 

重要な観察は、2 番目の順列の位置がわかると、問題は 1 次元の範囲カウントの問題になるということです。 

配列を構築する$$A[i] = posQ[p_i].$$位置`i`この配列は x 座標に対応します`i`、保存された値は同じ点の y 座標に対応します。 

クエリ四角形ができました$$[l_1,r_1] \times [l_2,r_2]$$は次のようになります:

 > 部分配列内`A[l1..r1]`、いくつの値が属するかを数えます`[l2,r2]`。 

これは古典的な静的範囲カウントの問題です。 

なぜなら`A`の順列です`1..n`、ウェーブレット ツリーは自然に適合します。 以下をサポートします。$$\text{count values } \le k$$任意のサブ配列内`O(log n)`時間。 

それから$$count([l_2,r_2]) = count(\le r_2) - count(\le l_2-1).$$構造は一度構築されると、すべてのクエリは対数時間でオンラインで回答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | ウェーブレット ツリー | O(n log n + m log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の順列を読み取ります。 
2. コンピューティング`posQ[v]`あらゆる価値観に対して`v`。 

これにより、2 番目の順列のどこに値が出現するかをすぐに見つけることができます。 
3. アレイを構築する$$A[i] = posQ[p_i].$$それぞれの値がポイントになります`(i, A[i])`。 
4. ウェーブレット ツリーを構築する`A`。 

レベルごとに、左側の子に渡された要素の数を示すプレフィックス数を保存します。 これらのプレフィックス数によって、ツリーを下降する際のクエリ間隔を制限できるようになります。 
5. メンテナンス`last_answer`。 

ステートメントは次のように定義します$$x = last\_answer + 1$$最初のクエリを除いて、`x = 0`。 
6. 指定された関数を使用して 4 つのクエリ パラメータをデコードします。$$f(z)=((z-1+x)\bmod n)+1.$$7. コンピューティング$$l_1=\min(f(a),f(b)), \quad r_1=\max(f(a),f(b)),$$2 番目の間隔についても同様です。 
8. ウェーブレット ツリーに値の数を問い合わせます。`A[l1..r1]`に属する`[l2,r2]`。 

これは等しい$$count_{\le r_2} - count_{\le l_2-1}.$$9. 答えを出力し、次のように保存します。`last_answer`。 

### なぜ効果があるのか

 配列`A`x 座標が配列インデックスである点の y 座標が正確に含まれます。 

ポジションの選択`l1..r1`で`A`これは、点を長方形の x 範囲に制限することと同じです。 の値をカウントする`A`内部`[l2,r2]`これは、点を長方形の y 範囲に制限することと同じです。 

両方の条件が同時に成立する場合にのみ、点は長方形に属します。 ウェーブレット ツリーは、要求された x 範囲のみを考慮しながら、要求された y 範囲内の値を正確にカウントします。 有効なポイントはすべて 1 回カウントされ、無効なポイントはカウントされません。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

class WaveletTree:
    def __init__(self, data):
        self.pref = []
        self.lo = []
        self.hi = []

        cur = array('I', data)
        segments = [(cur, 1, len(cur))]

        while segments:
            next_segments = []

            for arr, lo, hi in segments:
                self.lo.append(lo)
                self.hi.append(hi)

                if lo == hi:
                    self.pref.append(None)
                    continue

                mid = (lo + hi) >> 1

                pref = array('I', [0])
                left = array('I')
                right = array('I')

                cnt = 0
                for x in arr:
                    if x <= mid:
                        cnt += 1
                        left.append(x)
                    else:
                        right.append(x)
                    pref.append(cnt)

                self.pref.append(pref)

                next_segments.append((left, lo, mid))
                next_segments.append((right, mid + 1, hi))

            segments = next_segments

    def count_leq(self, l, r, k):
        if l > r or k <= 0:
            return 0

        ans = 0
        stack = [(0, l, r)]

        while stack:
            idx, l, r = stack.pop()

            lo = self.lo[idx]
            hi = self.hi[idx]

            if l > r or k < lo:
                continue

            if hi <= k:
                ans += r - l + 1
                continue

            if lo == hi:
                continue

            pref = self.pref[idx]

            left_l = pref[l - 1]
            left_r = pref[r]

            left_count = left_r - left_l

            left_idx = idx * 2 + 1
            right_idx = idx * 2 + 2

            stack.append((
                right_idx,
                l - left_l,
                r - left_r
            ))

            stack.append((
                left_idx,
                left_l + 1,
                left_r
            ))

        return ans

    def range_count(self, l, r, low, high):
        return self.count_leq(l, r, high) - self.count_leq(l, r, low - 1)

def main():
    n = int(input())

    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    pos_q = [0] * (n + 1)
    for i, v in enumerate(q, 1):
        pos_q[v] = i

    arr = [pos_q[v] for v in p]

    wt = WaveletTree(arr)

    m = int(input())

    last = 0
    out = []

    for qi in range(m):
        a, b, c, d = map(int, input().split())

        x = 0 if qi == 0 else last + 1

        def f(z):
            return ((z - 1 + x) % n) + 1

        fa = f(a)
        fb = f(b)
        fc = f(c)
        fd = f(d)

        l1 = min(fa, fb)
        r1 = max(fa, fb)

        l2 = min(fc, fd)
        r2 = max(fc, fd)

        last = wt.range_count(l1, r1, l2, r2)

        out.append(str(last))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```最初のステージでは、次の逆順列を計算します。`q`。 これにより、すべての値が 2 番目の順列の位置に変換されます。 

配列`arr`問題の幾何学的表現です。 索引`i`は x 座標であり、`arr[i]`は対応する y 座標です。 

ウェーブレット ツリーは、内部ノードごとに、各プレフィックスの要素の数が左側の子に移動されたことを示すプレフィックス配列を格納します。 クエリ中に、これらのプレフィックス カウントは、親ノードからのサブ配列間隔を、子の内部の対応する間隔に変換します。 

クエリ ルーチンは最大でも値のカウントを計算します。`k`。 範囲カウントは減算によって取得されます。 これにより、個別の四角形カウント操作の実装が回避されます。 

簡単な間違いの 1 つはインデックス作成です。 ウェーブレット ツリー クエリ式は 1 ベースの間隔を想定しているため、すべてのクエリ間隔は実装全体を通じて 1 ベースに保たれます。 

もう 1 つの微妙な点は、オンライン デコードです。 値`x`現在の回答ではなく、前の回答に 1 を加えたものを使用します。 最初のクエリは唯一の例外です。`x = 0`。

 可能な最小の入力を考えてみましょう。```

```長方形は、x 座標に点があるかどうかを尋ねます。`2`y 座標を持っています`1`。 以来`A[2] = 1`、答えは`1`。 実装ではあらゆる場所で包含境界が使用されるため、クエリ間隔は有効なままです。

l1 = 1, r1 = n

```すべての点がクエリを満たします。 ウェーブレット ツリーの計算$$count(\le n)-count(\le 0)=n-0=n,$$それはまさに正しい答えです。
