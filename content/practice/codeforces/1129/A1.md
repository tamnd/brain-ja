 ## 解決策
 ## 問題の理解

 私たちは持っています`n`有向サイクルで配置されたステーション。 駅から`i`、電車はいつも次へ進みます`i + 1`、駅から`n`折り返して駅に戻ります`1`。 隣接するステーション間の移動にはちょうど 1 秒かかります。 

各キャンディーはあるステーションから始まります`a`そして最終的には駅に到着しなければなりません`b`。 列車は一度にいくつのキャンディーを運ぶことができますが、制限が 1 つあります。列車が駅を訪れるたびに、出発前にその駅から最大 1 つのキャンディーを積み込むことができます。 

考えられるすべての出発駅について、すべてのキャンディーが目的地に到着するまでに必要な最小時間を計算する必要があります。 

重要な問題は輸送力ではない。 ボトルネックは読み込み中です。 ステーションに多くのキャンディーが含まれている場合、最初の訪問時にすべてをロードすることはできません。 列車は周回を繰り返して何度も戻ってきて、1 回の訪問につき 1 つのキャンディーを積み込まなければなりません。 

制約は小さいです。 ステーションは最大 100 個、キャンディーは 200 個あります。 たとえ$O(n^2)$または$O(n^3)$解決策は完全に受け入れられます。 重要なのは、プロセスの正しいモデルを発見することです。 

よくある間違いは、個々のキャンディーに焦点を当てて、読み込みの決定をシミュレーションすることです。 列車は無限に多くのキャンディーを運ぶことができるため、キャンディーが積み込まれると、その配達は目的地までの循環距離によって完全に決まります。 本当の課題は、ステーションからどのキャンディーを最初にロードするかを決定することです。 

別の微妙なケースは、複数のキャンディーが同じステーションから発信される場合に発生します。 

例：```
n = 4

1 -> 2
1 -> 3
1 -> 4
```駅にはキャンディーが3つあります。 列車は、最初の訪問中に 1 つだけ、2 番目のサイクル中に 1 つ、3 番目のサイクル中に 1 つだけ積み込むことができます。 3 つすべてがすぐにロードできることを前提としたソリューションは、答えを過小評価することになります。 

2 番目の見落としやすいケースは、周回距離です。 

例えば：```
n = 5
5 -> 2
```距離はそうではありません`2 - 5 = -3`。 サイクルに沿って:```
5 -> 1 -> 2
```したがって、距離は等しい`2`。 

循環距離を間違えると、計算全体が中断されます。 

## アプローチ

 強引なアイデアは、最適な積載量を選択しながら、すべての始発駅で列車の動きをシミュレートすることです。 ステーションには複数のキャンディーが含まれている可能性があり、列車は何度もステーションを再訪問するため、状態空間は乱雑になります。 制限が小さい場合でも、正しさを推論するのは難しくなります。 

画期的な発見は、単一のステーションを独立して観察することから始まります。 

駅を仮定します`u`含まれています`k`キャンディー。 

電車が来るたびに`u`、そのうちの 1 つだけをロードする場合があります。 訪問は全サイクルごとに発生するため、読み込み時間は次のようになります。```
0, n, 2n, ..., (k-1)n
```そのステーションの最初の訪問と比較して。 

発祥のお菓子の中には、`u`、 定義する```
dist(u, v)
```からの時計回りの距離として`u`に`v`。 

すべてのキャンディーが欲しい場合は、`u`できるだけ早く配達するには、配達距離が最も短いキャンディーを最初に積み込み、次に小さいキャンディーを 2 番目に積み込む、というようになります。 

からのキャンディー間の最小距離を仮定します。`u`は：```
best[u]
```キャンディーの数は次のとおりです。```
cnt[u]
```駅から積み込まれた最後のキャンディー`u`後に去る```
(cnt[u] - 1) * n
```余分な秒数。 

効率を最大化するには、最後にロードされたキャンディーが、目的地までの距離が最小のものである必要があります。 次に駅の完成時間寄与度`u`になる```
(cnt[u] - 1) * n + best[u]
```電車が最初に駅に到着した瞬間から測定される`u`。 

次に始発駅を考えてみましょう`s`。 

駅前`u`キャンディーの処理を開始できるようにするには、列車が最初に到着する必要があります`u`。 

させて```
reach(s, u)
```～から時計回りの距離になる`s`に`u`。 

それから駅`u`全体の終了時間を強制的に延長することができます```
reach(s, u) + (cnt[u] - 1) * n + best[u]
```最も遅いステーションが終了するとプロセス全体が終了するため、開始ステーションの答えは`s`は、単にキャンディーを含むすべてのステーションにおけるこの数量の最大値です。 

これにより、シミュレーションの必要性が完全になくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | きれいに綴じるのは非常に難しい | 大規模な状態の追跡 | 不要 |
 | 観察に基づく最適なソリューション | O(n² + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ステーションごとに、そこから発生するキャンディーの数を数えます。 
2. キャンディーごとに`(a, b)`、時計回りの距離を計算します。```
dist = (b - a + n) % n
```以来`a != b`、この距離は常に正です。 
3. 各駅ごと`a`、そこから始まるすべてのキャンディーの中での最小の目的地距離を保存します。 電話してください`best[a]`。 
4. 始発駅ごと`s`、答えをゼロに初期化します。 
5. すべてのステーションを反復処理します。`u`。 
6. もし`u`キャンディーは含まれていないため、何も貢献せず、スキップできます。 
7. 駅までの所要時間を計算する`u`:```
reach = (u - s + n) % n

finish =
    reach
    + (cnt[u] - 1) * n
    + best[u]
```8. 最大限のものを取る`finish`キャンディーを含むすべてのステーション上で。 
9. すべての開始ステーションに対してこの最大値を出力します。 

### なぜ効果があるのか

 ある駅`k`キャンディーは訪問ごとに 1 つのキャンディーのみをリリースでき、連続する訪問は正確に区切られています。`n`秒。 どのような戦略も遅延を避けることはできません`(k - 1) * n`そのステーションからの最後のキャンディーが積み込まれる前に。 

同じ駅にあるすべてのキャンディーの中で、目的地までの距離が最も短いものが、最後に配達される最適な候補となります。 それ以外の選択をすると、そのステーションの終了時間が長くなります。 したがって、ステーションの可能な最小完了時間は`u`最初の訪問から測定すると、正確に```
(cnt[u] - 1) * n + best[u].
```電車は駅に到着します`u`後`reach(s,u)`数秒なので、すべてのキャンディーが揃う最も早い瞬間`u`配達されています```
reach(s,u) + (cnt[u]-1)n + best[u].
```各駅は、最初の訪問時刻が決まると独立して運行します。 全体のプロセスは、最も遅いステーションが終了したときにのみ終了します。そのため、すべてのステーションの最大値を取ると最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())

    cnt = [0] * n
    best = [10**9] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        cnt[a] += 1

        dist = (b - a + n) % n
        best[a] = min(best[a], dist)

    ans = []

    for s in range(n):
        cur = 0

        for u in range(n):
            if cnt[u] == 0:
                continue

            reach = (u - s + n) % n
            finish = reach + (cnt[u] - 1) * n + best[u]
            cur = max(cur, finish)

        ans.append(str(cur))

    print(" ".join(ans))

if __name__ == "__main__":
    main()
```配列`cnt`各ステーションで発生するキャンディーの数を保存します。 配列`best`それらのキャンディーの中で時計回りの最小の目的地距離を保存します。 

表現```
(b - a + n) % n
```サイクル上の時計回りの距離を計算します。 追加`n`係数を取得する前に、宛先インデックスがソースより数値的に小さい場合に負の値を回避します。 

各始発駅ごとに`s`、すべてのステーションを評価します`u`独立して。 数量```
(cnt[u] - 1) * n + best[u]
```で生成されるすべてのキャンディーの最小完了時間です。`u`、最初の訪問から測定`u`。 

追加```
(u - s + n) % n
```到着までに必要な時間を考慮する`u`選択した始発駅から出発します。 

プロセス全体が完了する前にすべてのステーションのワークロードが完了する必要があるため、最終的な答えはそのような最大値になります。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    cnt = [0] * n
    best = [10**9] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        cnt[a] += 1
        best[a] = min(best[a], (b - a + n) % n)

    ans = []

    for s in range(n):
        cur = 0

        for u in range(n):
            if cnt[u]:
                cur = max(
                    cur,
                    (u - s + n) % n +
                    (cnt[u] - 1) * n +
                    best[u]
                )

        ans.append(str(cur))

    print(" ".join(ans))

    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

 ## 特殊なケース

 ### 1 つのステーションに複数のキャンディー

 入力:```
4 3
1 2
1 3
1 4
```目的地までの距離は、`1`、`2`、 そして`3`。 ステーションには 3 つのキャンディーが含まれているため、最後のキャンディーは 2 サイクル後までロードできません。 

駅の寄付金は、```
(3 - 1) * 4 + 1 = 9
```すべてのキャンディーをすぐにロードできると仮定したシミュレーションでは、誤った結果が返されます。`3`。 

アルゴリズムストア`cnt[1] = 3`そして`best[1] = 1`、正しい結果が得られます。 

### ラップアラウンド先

 入力:```
5 1
5 2
```本当の時計回りのルートは次のとおりです。```
5 -> 1 -> 2
```したがって、距離は等しい`2`。 

アルゴリズムは以下を計算します。```
(2 - 5 + 5) % 5 = 2
```実際の走行距離と一致します。 

通常の減算を使用する実装では、次のようになります。`-3`そしてナンセンスを生み出します。 

### キャンディーのない駅

 入力:```
4 1
2 4
```駅`1`、`3`、 そして`4`キャンディーは含まれていません。 

アルゴリズムはそれらを完全にスキップします。```
if cnt[u] == 0:
    continue
```キャンディーのないステーションには期限がなく、最大値に影響を与えることはありません。 このようなステーションを無視すると、計算が正確かつ単純に保たれます。
