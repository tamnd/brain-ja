 ## 解決策
 ## 問題の理解

 各セグメント内で 1 回だけ出現する整数の数が指定のしきい値を超えないように、指定された整数の配列を連続した空ではないセグメントに分割する方法が何通りあるかを数えるよう求められます。$k$。 概念的には、各セグメントは最大でも許容できるという意味で「分離」されています。$k$ユニークなシングルトン。 たとえば、配列では`[1,1,2]`と$k=1$、セグメント`[1,1,2]`は有効です。`2`1 回表示され、制限内ですが、セグメントは`[1,2]`どちらも無効であるため、`1`そして`2`ちょうど 1 回出現し、$k$。 

入力は配列サイズを提供します$n$、しきい値$k$、および配列要素自体。 出力は単一の数値、つまり有効なセグメンテーションの総数を法的に表したものです。$998244353$。 

与えられた$n$と同じ大きさにすることができます$10^5$、おおよそを超える解決策$O(n \log n)$または$O(n \sqrt n)$遅すぎる可能性があります。 考えられるすべてのセグメンテーションを試みる単純なアプローチですが、そのセグメンテーションの数は指数関数的に多くなります ($2^{n-1}$）、明らかに実行不可能です。 クリティカルなエッジ ケースには、すべての要素が同じである (条件を簡単に満たす) 配列、または多数の異なる要素が 1 回しか出現しない (有効なセグメントが非常に短い可能性がある) 配列が含まれます。 たとえば、入力`[1,2,3]`と$k=1$各要素の後で分割することを強制し、結果だけを生成します。`[1],[2],[3]`有効なセグメントとして。 不用意に実装すると、シングルトン数をチェックせずに要素を誤って結合する可能性があります。 

## アプローチ

 ブルートフォース手法では、配列を連続セグメントに分割するために考えられるすべての方法が試行されます。 各セグメント化について、各セグメントに 1 回だけ出現する整数を数え、それらが次の値を超えているかどうかを確認します。$k$。 このアプローチは正しいですが、セグメンテーションの数は次のように指数関数的に増加します。$n$- について$2^{n-1}$可能性 - それは完全に不可能です$n$まで$10^5$。 

重要な観察は、セグメントの有効性はその内容、具体的には一度だけ出現する要素の数のみに依存するということです。 これは動的プログラミングのアプローチに役立ちます。`dp[i]`長さのプレフィックスの有効なセグメント化の数として$i$。 それからそれぞれについて`i`、考えられるすべての以前の分割点を考慮します。`j`セグメントかどうかを確認します`a[j..i-1]`有効です。 シングルトン制約を満たす最後のセグメントのスライディング ウィンドウを維持することで、これを最適化できます。 2 つのポインターと頻度マップを使用すると、一度だけ出現する要素の数を動的に更新できます。 これにより、内部ループが要素ごとに償却される O(1) 操作に削減され、O(n) のソリューションが得られます。 

ブルートフォースアプローチと最適アプローチは次のように比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | スライディングウィンドウ + DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. を初期化します。`dp`サイズの配列`n+1`どこ`dp[i]`インデックスで終わるプレフィックスの有効なセグメンテーションの数を格納します`i-1`。 セット`dp[0] = 1`空のプレフィックスには簡単なセグメンテーションが 1 つあるためです。 
2. 頻度辞書を使用して、現在のスライディング ウィンドウ内で各整数が何回出現するかを追跡します。 1 回だけ出現する整数の数を維持します。 
3. 左ポインタを維持します`l`現在の位置で終了する有効なセグメントの最も早い開始を示します`r`。 動く`l`セグメント内のシングルトンの数の間、前方に進みます`[l..r]`を超える`k`。 
4. それぞれについて`r`0 から n-1 まで、次のように周波数マップを更新します。`a[r]`。 周波数が 1 になったら、シングルトン数をインクリメントします。 2になった場合はシングルトン数をデクリメントします。 
5.調整後`l`シングルトン制約を満たすために、現在のセグメント`[l..r]`有効です。 追加`dp[l]`に`dp[r+1]`で終わるすべてのセグメンテーションをカウントするには`r`。 
6. 最後に、`dp[n]`有効なセグメンテーションの合計数を 998244353 で割ったものを与えます。 

なぜ機能するのか: DP の不変条件は次のとおりです。`dp[i]`常に、長さのプレフィックスのすべての有効なセグメンテーションをカウントします。`i`。 スライディング ウィンドウにより、以下のセグメントが決して含まれないことが保証されます。`k`シングルトンなので、更新されるたびに`dp[r+1]`以前の有効なセグメンテーションを正しく拡張します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    dp = [0] * (n + 1)
    dp[0] = 1
    
    freq = {}
    singletons = 0
    l = 0
    
    for r in range(n):
        val = a[r]
        freq[val] = freq.get(val, 0) + 1
        if freq[val] == 1:
            singletons += 1
        elif freq[val] == 2:
            singletons -= 1
        
        while singletons > k:
            left_val = a[l]
            freq[left_val] -= 1
            if freq[left_val] == 1:
                singletons += 1
            elif freq[left_val] == 0:
                singletons -= 1
                del freq[left_val]
            l += 1
        
        dp[r + 1] = (dp[r + 1] + dp[l]) % MOD
        if r > 0:
            dp[r + 1] = (dp[r + 1] + dp[r]) % MOD

    print(dp[n] % MOD)

if __name__ == "__main__":
    main()
```頻度マップの更新では、一度だけ出現する整数の数が追跡され、スライディング ウィンドウで左ポインタが移動します。`l`現在のセグメントが有効になるまで。 の`dp`配列は、以前の有効なプレフィックスを拡張することによって有効なセグメンテーションを蓄積します。 モジュロを使用すると、オーバーフローが発生しません。 

## 実用的な例

 ### サンプル 1

 入力:`3 1`配列あり`[1, 1, 2]`。 

| r | l | 周波数 | シングルトン | DP |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | {1:1} | 1 | dp[1]=1 |
 | 1 | 0 | {1:2} | 0 | dp[2]=2 |
 | 2 | 0 | {1:2,2:1} | 1 | dp[3]=3 |

 トレースは、シングルトン数が 1 を超えないことを示しています。`dp`有効な分割を累積します`[1],[1],[2]`、`[1,1],[2]`、 そして`[1,1,2]`。 

### カスタム例

 入力:`4 2`配列あり`[1,2,3,2]`。 

| r | l | 周波数 | シングルトン | DP |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | {1:1} | 1 | dp[1]=1 |
 | 1 | 0 | {1:1,2:1} | 2 | dp[2]=2 |
 | 2 | 0 | {1:1、2:1、3:1} | 3 -> l は 1 に移動、freq={2:1,3:1}、singletons=2 | dp[3]=dp[1]=1 |
 | 3 | 1 | {2:2,3:1} | 1 | dp[4]=dp[1]+dp[3]=1+1=2 |

 これはスライディング ウィンドウの調整を示しています。`l`シングルトン数が超過した場合`k`。
