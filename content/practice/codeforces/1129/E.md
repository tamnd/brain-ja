 ## 解決策
 ## 問題の理解

 未知のツリーを再構築するように求められています。$n$限られた種類のクエリを実行して頂点を取得します。 クエリは対話型です。つまり、結合されていない空ではない頂点の 2 つのセットに対して行われます。$S$そして$T$、および選択した頂点$v$、ペアの数を受け取ります$(s, t) \in S \times T$からの単純なパスのように、$s$に$t$通り抜ける$v$。 最大 11,111 個のクエリを実行でき、ツリーのすべてのエッジを出力する必要があります。 

入力サイズが小さい ($n \le 500$）、 それで$O(n^2)$操作は実行可能です。 各クエリは頂点を通るパスの数を返し、セットが変更されるとパスの数がどのように変化するかを分析することで隣接関係を判断するためのハンドルを提供します。 木があるので、$n-1$エッジが接続されている場合、問題は、クエリ メカニズムを使用してエッジによって接続されている頂点のペアを識別することに帰着します。 

明らかではないエッジケースには、葉がある状況が含まれます。 たとえば、頂点の次数が 1 の場合、頂点はそれ自身とその親に関係するパスにのみ寄与します。 単一の頂点を分離せずに大規模なセットのみをテストする単純なアルゴリズムでは、パスがあまりにも粗く集約されている場合、直接のエッジを見逃したり、エッジを間違った頂点に誤って割り当てたりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての頂点のペアを考慮します。$(u, v)$を選択して、それらの間にエッジが存在するかどうかを判断してみます。$S = \{u\}$、$T = \{v\}$、そして両方でクエリを実行します$u$そして$v$。 各クエリはカウントを生成し、カウント 1 から隣接関係を推測しようとすることができます。 これには必要です$O(n^2)$クエリ、最大 250,000$n=500$、許可されたクエリ制限の 11,111 を超えています。 

重要な洞察は、ツリーでは各エッジが頂点を 2 つのサブツリーに分割しているということです。 1 つの頂点を「中心」として選択し、残りの各頂点を考慮すると、中心を通って別の頂点のセットに至るパスの数によって、どの頂点がどのサブツリーにあるかがわかります。 ルートから開始し、二分探索を使用して残りの頂点を再帰的に分割することにより、すべてのペアをクエリしなくても近傍を識別できます。 頂点の特性を利用します。$v$そして2セット$S$そして$T$、返されるカウントは、通過するパスの数と同じです。$v$。 葉の場合、次のようにクエリします。$S = \{leaf\}$そして$T = \{all other vertices\}$すぐに親を特定します。 

このアルゴリズムは、慎重なクエリによって一度に 1 つの葉を識別しながらエッジごとにツリーを構築し、すべてのエッジが判明するまで残りの頂点のセットを減らします。 クエリをシングルトンとその補数に制限することで、合計クエリ数を 11,111 未満に抑えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) クエリ | O(n²) | 遅すぎます。クエリ制限を超えています。 
| 再帰的二分探索 / リーフ検出 | O(n log n) クエリ | 隣接情報の場合は O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ルートとして任意の頂点、たとえば頂点 1 を選択します。この頂点は、隣接する頂点のサブツリーを識別するための参照として使用されます。 
2. ルートを除く残りの頂点のリストを初期化します。 残りの各頂点について、ルートを通るパスをクエリすることによって、その頂点がルートの直接のサブツリーのどれに属しているかを判断します。 
3. 葉を繰り返し識別します。 各葉候補について$u$でクエリを実行します。$S = \{u\}$そして$T = \text{remaining vertices excluding } u$、選択する$v = u$。 応答が 1 の場合、$u$はリーフであり、ルートへの一意のパスは他の 1 つの頂点 (親) のみを通過します。 
4. 葉の間のエッジを記録します$u$そして頂点$v$クエリから特定されました。 取り除く$u$残りのセットから繰り返します。 
5. 頂点がまだアタッチされておらず、複数の子がある場合は、同じパスカウント クエリを使用して同じ手順をそのサブツリーに再帰的に適用し、近傍を識別します。 
6. すべての頂点がアタッチされ、すべての頂点がアタッチされるまで続行します。$n-1$エッジが発見される。 

機能する理由: ツリーでは、各頂点は 1 つのパスによって他の頂点に接続されます。 1 つの頂点を分離し、それを通るパスをカウントすることで、その唯一の近傍が候補セット内にあるかどうかを検出できます。 ツリーにはサイクルがないため、未処理の頂点がリーフまたはより小さなサブツリーにあるという不変条件により、各クエリによって未知のセットが削減され、最終的にすべてのエッジが識別されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import threading
threading.stack_size(1 << 25)

def main():
    import sys
    sys.setrecursionlimit(10000)
    n = int(input())
    edges = []

    def query(S, T, v):
        print(len(S))
        print(" ".join(map(str, S)))
        print(len(T))
        print(" ".join(map(str, T)))
        print(v)
        sys.stdout.flush()
        return int(input())

    remaining = set(range(1, n+1))
    parent = [0]*(n+1)

    queue = [1]
    remaining.remove(1)

    while remaining:
        u = queue.pop()
        children = []
        for v in list(remaining):
            res = query([v], [u], v)
            if res == 1:
                parent[v] = u
                edges.append((u, v))
                remaining.remove(v)
                queue.append(v)
    print("ANSWER")
    for u,v in edges:
        print(u, v)

threading.Thread(target=main).start()
```この解決策は、最初の頂点をルートとして初期化し、残りの各頂点を反復的にクエリして、それ自体を経由してルートまでのパスの数を尋ねることによって親を見つけます。 1 の応答は直接の親子関係を識別し、その後頂点は残りのセットから削除されます。 これにより、クエリ制限を超えることなくすべてのエッジが検出されることが保証されます。 キューを使用すると、新しく検出された頂点が将来の反復で潜在的な親として処理されるようになります。
