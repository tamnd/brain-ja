 ## 解決策
 ## 問題の理解

 私たちには、一次元の数直線に沿って配置された一連のテレポーターが与えられています。 ブタは位置 0 から開始し、位置 m に到達したいと考えています。 各テレポーターはある座標 ai に配置されており、ピッグがその座標に到着すると、ai から bi までの範囲内で任意の目的地を選択できます。 

テレポートは、リストの下に移動しても開始位置が減少しない順序で表示されます。 この順序は、以前の構造を再考することなく左から右に処理できるため重要です。 

タスクは、0 から始まり最終的に m に達する一連のテレポート使用が存在するかどうかを判断することです。 

制約は小さいです。 最大 100 個のテレポートでは、O(n²) シミュレーションでも簡単に合格しますが、構造は、より単純な線形スキャンで十分であることを示唆しています。 主な困難は計算時間ではなく、新しいテレポートが利用可能になるにつれて到達可能性がどのように進化するかを理解することです。 

各テレポートを独立して扱うことから、素朴な誤解が生じることがよくあります。 たとえば、AI でテレポートにすぐに到達できるということは、テレポートを使用する必要があることを意味すると仮定したり、テレポートは可用性ではなく厳密な使用順序でのみ使用できると仮定したりします。 もう 1 つの微妙な間違いは、テレポートがその位置を超えて到達範囲を拡張し、後のテレポートが使用可能になる可能性があることを無視していることです。 

具体的な失敗例はこんな感じです。 

入力:```
2 5
0 1
2 5
```不注意なアプローチは、厳密に連鎖しようとして、1 までしか到達しないと 2 番目のテレポートにアクセスできないことを認識できない可能性があるため、答えは NO です。 しかし、正しいリーチ追跡アプローチでは、最初のテレポートの上限が 1 に達することがわかり、これでは不十分であるため、進行が停止します。 

別の特殊なケース:

 入力:```
2 5
0 3
1 2
```2 番目のテレポートの有用性は「後退」しているように見えますが、最初のテレポートですでにさらに遠くに到達しているかどうかは関係ありません。 正しいロジックでは、最後に遭遇したテレポートではなく、到達可能な最大の拡張子を常に優先する必要があります。 

## アプローチ

 この強引なアイデアは、これを到達可能性の問題として扱い、現在の位置から使用可能なすべてのテレポートを試し、許容される間隔内で考えられるすべての目的地を再帰的に探索するというものです。 これにより、各間隔の各点がノードとなるグラフが効果的に構築され、テレポートによって密な有向接続が作成されます。 概念的には正しいですが、各テレポートが到達可能なポイントの連続体を生成する可能性があり、たとえ離散化されていたとしても状態を繰り返し再訪する可能性があるため、これは爆発的です。 最悪の場合、テレポートの使用法をすべて組み合わせて調査すると、指数関数的な動作が発生します。 

重要な観察は、到達可能なすべての位置を追跡する必要はなく、Pig が現在到達できる最も遠い地点のみを追跡する必要があるということです。 ai に到達できる場合、そのテレポートを最大限に利用して bi に到達できるようにすることです。 すべての動きは位置に関して単調であるため (後退する必要はまったくありません)、問題は貪欲にフロンティアを拡大することになります。 

aiの昇順にテレポートを処理します。 テレポートの開始点が現在の到達可能な範囲内にある場合は、それを使用してその範囲を拡張できます。 現在到達可能な範囲を超えてテレポートが開始される場合、まだそれを使用することはできません。また、将来のテレポートは (順序により) さらに右から開始されるため、そのようなギャップに達した場合は、それ以上の拡張子のチェックを停止します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース (状態検索) | 指数 | 高 | 遅すぎる |
 | 貪欲なリーチ拡張 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 Pig が現在到達できる最も遠い位置を表す単一の値を維持します。 

1. Pig はそこから開始するため、到達可能な位置を 0 として初期化します。 
2. 指定された順序で各テレポートを繰り返します。 
3. テレポートの開始点 ai が現在の到達可能な位置より大きい場合、それ以降のテレポートの処理を停止します。 これが機能するのは、後のテレポートはさらに右から始まるため、到達できないためです。 
4. ai が到達可能範囲内にある場合、到達可能位置を max(current range, bi) に更新します。 これは、テレポートを最適に使用して、可能な限り右に拡張することを反映しています。 
5. 使用可能なテレポートをすべて処理した後、到達可能な位置が m 以上であるかどうかを確認します。 「はい」の場合、Pig は友人に連絡を取ることができます。 そうでなければ彼はできない。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、到達可能な位置が、処理されたプレフィックスからの一連のテレポートを使用して Pig が到達できる最大の右端の点であるという不変条件を維持します。 テレポートは AI によって分類されるため、開始点が現在の到達範囲外にあるテレポートに遭遇すると、それ以降テレポートを起動することはできません。 すべての使用可能なテレポートの中で、bi を貪欲に取るのが最適です。[ai, bi] 内の中間選択は、将来の到達範囲を減らすか同等にするだけで、改善することは決してないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    reach = 0
    
    for _ in range(n):
        a, b = map(int, input().split())
        
        if a > reach:
            break
        
        if a <= reach:
            if b > reach:
                reach = b
    
    print("YES" if reach >= m else "NO")

if __name__ == "__main__":
    solve()
```この実装は、貪欲なアイデアを直接反映しています。 変数`reach`これまでに到達可能な最も遠い位置を保存します。 早めの休憩が重要です。テレポートが手の届かなくなると、ソートされた AI のせいで、後のテレポートは役に立ちません。 最大アップデートにより、常に可能な限りリーチが拡大されます。 

よくある間違いは、ブレークを削除してスキャンを続けることです。これはまだ正しいですが、大規模なバリエーションでは速度が遅くなります。 もう 1 つの間違いは、bi ではなく ai でリーチを更新することです。これは、各テレポートの拡張機能を無視することになります。

 ## 特殊なケース

 エッジ ケースの 1 つは、最初のテレポートが 0 から始まらない場合です。たとえば、最初の AI が 1 の場合、Pig はまったく動くことができないため、答えは即座に NO になります。 リーチは 0 から始まり、最初のチェックで > リーチが終了するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、複数のテレポートが重なり合う場合です。 たとえ後のテレポートの間隔が短くても、リーチは最大更新によってのみ増加するため、問題にはなりません。 このアルゴリズムはリーチを決して減少させないため、無用な回帰を安全に無視します。
