 ## 解決策
 ## 問題の理解

 このタスクは、指定された長さの最大のマジックナンバーを要求します。 3 桁目以降のすべての数字が前の 2 桁の合計とまったく同じになると、数字は魔法になります。 入力は通常のテスト ケース形式ではありません。 4 から 8 までの 5 つの必要な長さが指定されており、送信では対応する 5 つの最大数値を出力する必要があります。 

実際の変数は最初の 2 桁のみです。 それらが選択されると、以降のすべての数字が繰り返しによって強制されます。 数値には先頭にゼロがない必要があるため、最初の桁は少なくとも 1 になります。生成される桁は 10 進数のままである必要があるため、必要な合計はすべて 9 以下でなければなりません。 

長さは非常に小さいため、最初の 2 桁の可能性のある総当たり検索でもすでに十分であることを意味します。 最初の桁の選択肢は 9 つだけ、2 桁目の選択肢は 10 つだけです。 ただし、より貴重な観察は、再発が急速に成長するため、長さが長くなると、可能な開始ペアが大幅に制限されるということです。 

不注意な実装は依然としていくつかの境界で失敗する可能性があります。 最初の桁にゼロを許可すると、より長くても無効な数値が作成される可能性があります。 たとえば、長さが 4 の場合、ペアは`(0, 9)`作成します`0999`ですが、正しい最大 4 桁のマジックナンバーは次のとおりです。`7769`、最初の桁はゼロ以外でなければならないためです。 

もう 1 つのよくある間違いは、2 番目の桁がゼロである可能性があることを忘れることです。 長さ 8 の場合、最適な数は次のようになります。`10`、与える`10112358`。 正の 2 桁のみを考慮する解決策では、正の 2 桁ごとにフィボナッチの増加が桁制限を超えるため、答えが得られません。 

3 番目の問題は、生成された数値を辞書順ではなく長さで比較することです。 すべての候補の長さは同じであるため、最大の整数は単に辞書編集上最大の数字列になります。 

## アプローチ

 直接的なアプローチは、考えられるすべての開始桁のペアを試してみることです。 各ペアについて、必要な長さに達するまで、前の 2 桁の合計を繰り返し追加します。 生成された数字が 9 より大きい場合、そのペアは無効です。 それ以外の場合は、生成された数値を現在の最良の回答と比較します。 

最初の 2 桁が一意にシーケンス全体を決定するため、この強引な方法は完全に正しいです。 2 桁目以降に隠れた選択肢はありません。 この問題では、探索空間が 90 個の可能な開始ペアに固定されているため、すでに十分に高速です。 

数学的な観察により、さらに単純な視点が得られます。 最初の 2 つの後の数字はフィボナッチ係数に従います。 

開始桁について`a`そして`b`、後の数字は`a + b`、`a + 2b`、`2a + 3b`、`3a + 5b`、 等々。 長さが増加するにつれて、最後の桁によって最も強力な制限が課されます。`a`そして`b`。 たとえば、8 桁の数字には次の情報が必要です。`8a + 13b <= 9`、これだけが残ります`a = 1, b = 0`。 

状態空間が小さいため総当り攻撃は機能しますが、反復の洞察により、なぜ答えが非常に制限されるのかが説明されます。 どちらのアプローチも問題に適合し、ブルート フォース バージョンの方がエラーが発生しにくく、同時に瞬間的です。

 | ブルートフォース | O(90×8) | お(8) | 承認済み |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 要求された 5 つの長さ (4、5、6、7、および 8) を保存します。ある長さの最大値を別の長さから導出する必要がないため、各長さは独立して解決されます。 
2. 1 から 9 までの最初の数字をすべて試し、2 番目の数字を 0 から 9 まですべて試してみます。シーケンス内で自由に選択できるのはこれらだけです。 
3. 次の桁が前の 2 桁の合計に等しいというルールを使用して、残りの桁を生成します。 生成された数字が 9 より大きい場合は、有効なマジック ナンバーを形成できないため、この開始ペアは破棄されます。 
4. 生成されたすべての有効な数値を、これまでに見つかった最良の数値と比較します。 すべての候補の長さが等しいため、通常の文字列比較ではより大きな数値が得られます。 
5. 5 つの最大値を必要な順序で出力します。 

これが機能する理由: すべてのマジックナンバーは最初の 2 桁によって完全に決定されます。 アルゴリズムは、これらの数字に対して考えられるすべての有効な選択肢を検査するため、生成された候補の中に最大の有効なシーケンスが出現する必要があります。 比較では最大の候補が保持されるため、最終的に保存された数値がまさに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_length(n):
    best = ""

    for first in range(1, 10):
        for second in range(10):
            digits = [first, second]
            ok = True

            while len(digits) < n:
                nxt = digits[-1] + digits[-2]
                if nxt > 9:
                    ok = False
                    break
                digits.append(nxt)

            if ok:
                cur = ''.join(map(str, digits))
                if cur > best:
                    best = cur

    return best

def main():
    ans = []
    for n in range(4, 9):
        ans.append(solve_length(n))

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```機能`solve_length`必要な 1 つの桁数を処理します。 2 つのネストされたループは、考えられるすべての 1 番目と 2 番目の桁を列挙します。 複数桁の数値はゼロから始めることができないため、最初のループは 1 から始まります。 

生成ループはマジック ナンバーの定義を反映しています。 現在のリストの最後の 2 桁は次の桁を計算するのに十分であるため、追加の状態は必要ありません。 9 に対するチェックにより、無効な 10 進数が受け入れられなくなります。 

比較では、整数ではなく文字列が使用されます。 これにより、整数のサイズへの依存が回避され、同じ長さの数値を比較する方法と直接一致します。 生成された桁数が要求された長さに達するとループが正確に停止するため、1 つずつずれることはありません。 

## 実用的な例

 長さ 4 の場合、最適な開始ペアは次のとおりです。`7,7`。 

| ステップ | 数字 | 次の桁 |
 | --- | --- | --- |
 | 開始 | 7、7 | 14 |
 | 無効 | 7、7 | 合計が 9 を超えます |

 そのペアは失敗するため、最大の有効なペアが必要です。 ペア`7,6`与える:

 | ステップ | 数字 | 次の桁 |
 | --- | --- | --- |
 | 開始 | 7、6 | 13 |
 | 無効 | 7、6 | 合計が 9 を超えます |

 検索を続けると、`3,0`与える`3033`、 その間`2,3`与える`2358`。 最大有効な 4 桁の回答は、完全な列挙によって次のように見つかります。`7769`3 桁目はすでに 14 であるため、これは不可能です。実際の最大値は次のとおりです。 

| ステップ | 数字 | 次の桁 |
 | --- | --- | --- |
 | 開始 | 5、4 | 9 |
 | 3 桁目を追加 | 5、4、9 | 13 |
 | 無効 | | |

 列挙では有効なシーケンスのみが保持され、最大のシーケンスが返されます。 

長さが 8 の場合、制限はさらに強くなります。 

| ステップ | 数字 | 次の桁 |
 | --- | --- | --- |
 | 開始 | 1、0 | 1 |
 | 3 桁目を追加 | 1、0、1 | 1 |
 | 4 桁目を追加 | 1、0、1、1 | 2 |
 | 5 桁目を追加 | 1、0、1、1、2 | 3 |
 | 6 桁目を追加 | 1、0、1、1、2、3 | 5 |
 | 7 桁目を追加 | 1、0、1、1、2、3、5 | 8 |
 | 8 桁目を加算 | 1、0、1、1、2、3、5、8 | 完了 |

 これは、2 番目の桁としてゼロが必要な理由を示しています。 2 番目の桁が大きくなると、最後の桁が 9 を超えます。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    def solve_length(n):
        best = ""
        for first in range(1, 10):
            for second in range(10):
                digits = [first, second]
                while len(digits) < n:
                    nxt = digits[-1] + digits[-2]
                    if nxt > 9:

                    digits.append(nxt)
                if len(digits) == n:

                    if cur > best:
                        best = cur
        return best

    return "\n".join(solve_length(n) for n in range(4, 9))

 ## 特殊なケース

 最初の桁のループは 1 から始まるため、先頭のゼロのケースが処理されます。このアルゴリズムでは、次のような無効な数値が作成されることはありません。`0999`。 

ゼロ秒の数字の場合は、2 番目のループによって自然に処理されます。 長さ 8 の場合、ゼロより大きい 2 番目の桁の値を試行すると、すぐに 9 より大きい桁が作成されます。`10`正常に続行され、生成されます`10112358`。 

桁オーバーフローの場合は生成中に処理されます。 開始桁のような候補`7,7`は 3 桁目の 14 を生成するため、アルゴリズムは無効な文字シーケンスを保存する代わりに、それを即座に拒否します。 

すべての候補が要求された桁数を正確に持っているため、比較境界も安全です。 この状況では、文字列比較は数値比較と同じであるため、最大の候補が正しく選択されます。
