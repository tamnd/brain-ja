 ## 問題の理解

 平面上に配置されたハエのセットが与えられ、それぞれに座標と正の「アクティビティ」値が与えられます。 半径が固定された円形のハエたたきもあります。 中心点を選択すると、たたきの 1 回の打撃が適用されます。 その半径内のすべてのハエが影響を受けますが、影響を受けるのはまだアクティブなハエだけです。 

k 個のアクティブなハエのグループに攻撃が当たると、それらのハエはそれぞれのアクティビティの正確に 1/k を失います。 ハエの活動がゼロまたはマイナスになるとすぐに、そのハエは排除されたとみなされ、今後の攻撃には参加しなくなります。 目標は、できるだけ少ない攻撃ですべてのハエを排除することです。 

重要な点は、攻撃でヒットした現在アクティブなすべてのハエにダメージが均等に分配されるため、同じ攻撃が多くのターゲットに当たるとハエごとに弱くなりますが、同時にすべてのハエも減少します。 

モデリングの観点から見ると、各ストライクはフライごとに独立していません。 代わりに、選択した幾何学的ディスク内のすべてのハエを結合します。含めるハエの数が増えるほど、そのストライクでの個々のハエの除去に向けた進行は遅くなりますが、それでもすべてのハエを一度に進めることができます。 

この制約は、最大約 1 万個のハエを意味します。 すべてのハエに対する多数の攻撃の単純なシミュレーションでは、どのハエがまだアクティブであるかを再計算し、ジオメトリを繰り返しテストしますが、約 n の 2 乗または n 3 乗より悪いものを試みると、遅すぎます。 最悪の場合でも n の 2 乗または n log n に近い解決策が期待されるはずで、おそらくは貪欲なまたは構造的な削減が行われるでしょう。 

微妙なエッジケースは、すべてのハエが集中しているため、あらゆる最適な攻撃が一度に多くのハエに当たる場合です。 このような場合、単純に貪欲な「最初に最も弱いものを削除する」アプローチは失敗する可能性があります。サブセットを早期に削除すると、後の攻撃の k が変更され、残りのすべてのダメージ値が変更されるためです。 

別の特殊なケースは、ハエが分離され、それぞれの最適なストライクが 1 つのハエのみをカバーする場合に発生します。 その後、プロセスは独立した排除に堕落し、グループ化が常に有益であると仮定するソリューションは効率を過大評価することになります。 

## アプローチ

 直接総当たりアプローチでは、考えられるすべての攻撃中心を考慮し、プロセスをシミュレートします。 攻撃中心は平面内のどこにでも配置でき、各攻撃はどのハエがまだアクティブであるかによって決まるため、これは組み合わせ的に巨大になります。 センターをフライングポジションに離散化したとしても、ストライクごとに n 人の候補者が存在し、場合によっては n 個のストライクが存在し、およそ n3 個のインタラクションが発生します。 これは限界をはるかに超えています。 

重要な観察は、ストライクに関して重要なのは、それがヒットしたハエのサブセットだけであるということです。 ジオメトリは、無限平面を候補サブセットの有限セットに縮小します。任意の最適なストライクは中心にあると仮定できるため、半径内のハエのセットはある点で最大になります。つまり、基準として、またはペアごとの境界によって各フライによって定義されたディスクを考慮するだけで済みます。 

各攻撃がハエのサブセットの選択に対応することを受け入れると、問題は次のようになります。サブセットを繰り返し選択すると、選択されたすべての要素がそのサブセット内の要素ごとに等しい減少を受けます。 各ハエを除去するには、最初の活動と同じ減少量の合計が必要です。 

これは、サブセットにわたるスケジューリングの問題として再構成できます。各サブセットは、使用ごとにその各メンバーに 1/k を寄与するため、サブセット S が t 回使用された後、S の各要素は t/|S| を受け取ります。 そのサブセットからの総削減。

重要な洞察は、攻撃ごとの効率を最大化したいということであり、たたきの中にできるだけ多くのまだアクティブなハエを含めると効率が高くなります。 ハエが除去されると、その後の攻撃は残りのクラスターに対してより効率的になります。 これにより、最大半径のクラスターを繰り返しターゲットにして、可能な限り最大のアクティブ セットを常にカバーするようになります。 

したがって、このプロセスは、「最も制約された」クラスターを繰り返し削除するものとしてモデル化できます。つまり、現在のアクティブ セットと交差する領域 (半径 r のディスク) を選択し、1 回のストライクを適用し、残りのアクティビティを更新し、これを繰り返します。 ジオメトリにより、一部のフライがゼロに達した場合にのみアクティブ セットが変更されることが保証されるため、各ストライクを一連のウェイトを均一に減らす個別のイベントとして扱うことができます。 

最適な戦略は、半径グラフによって引き起こされる接続された幾何学的コンポーネントに対して貪欲になります。つまり、互いに距離 r 以内にあるハエは、一緒に処理する必要があるクラスターを形成します。 接続された各コンポーネント内で、すべてのハエが使い果たされるまで繰り返し攻撃します。必要な攻撃の数は、そのコンポーネントに分散される合計「負荷」によって異なります。

 ## アルゴリズムのチュートリアル

 1. 2 つのハエのユークリッド距離が最大 2r である場合に接続されるグラフを作成します。 これは、単一のたたき位置が両方を同時にヒットできるかどうかを表します。 このステップでは、ジオメトリを接続コンポーネント上の組み合わせ論に還元します。 
2. DFS または DSU を使用して、このグラフのすべての接続コンポーネントを計算します。 どのストライクも異なるコンポーネント内のハエに同時に影響を与えることができないため、各コンポーネントは独立しています。 
3. コンポーネントごとに、ハエのリストとその現在のアクティビティを維持します。 重要な観察は、このコンポーネントに対するすべてのストライクは、まだアクティブな各フライを 1/k ずつ減らすものとして解釈できるということです。ここで、k は、選択したストライク領域で現在アクティブなフライの数です。 
4. すべてのアクティビティが非ポジティブになるまで、コンポーネント内で繰り返しストライクを実行します。 各ストライクは事実上、選択されたアクティブなサブセットに対する均一な減少です。 
5. コンポーネント内のストライクの数を最小限にするには、常に k を最大化するストライクを選択します。これは、そのコンポーネント内で現在アクティブなすべてのフライをカバーすることを意味します。 
6. コンポーネント全体に 1 回のストライキを適用し、それに応じてすべての活動を減らし、活動がゼロ以下になったハエをすべて除去します。 
7. コンポーネントが空になるまで繰り返し、すべてのコンポーネントの結果を合計します。 

ハエが消えるにつれて k は時間の経過とともに変化するため、実装の重要な詳細は、各削減後にアクティブ カウントを正しく維持することです。 

### なぜ効果があるのか

 正確さは効率の単調性特性から来ます。 任意のサブセット S について、ストライクごとの合計削減額は |S| 間で均等に分割されます。 要素。 連結コンポーネント内で最大ではないサブセットを選択した場合でも、要素あたりのコストを増加させたり、実現可能性を低下させたりすることなく、サブセットを拡張できます。 したがって、ストライクの最適なシーケンスは、すべてのストライクがそのコンポーネント内の最大のアクティブなサブセットを使用するものに変換できます。 この変換によってストライクの数が増加することはありません。そのため、貪欲な戦略が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, r = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y, a = map(int, input().split())
        pts.append((x, y, a))

    r2 = r * r

    adj = [[] for _ in range(n)]
    for i in range(n):
        x1, y1, _ = pts[i]
        for j in range(i + 1, n):
            x2, y2, _ = pts[j]
            dx = x1 - x2
            dy = y1 - y2
            if dx * dx + dy * dy <= r2 * 4:
                adj[i].append(j)
                adj[j].append(i)

    vis = [False] * n
    answer = 0

    for i in range(n):
        if vis[i]:
            continue

        comp = []
        q = deque([i])
        vis[i] = True

        while q:
            u = q.popleft()
            comp.append(u)
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    q.append(v)

        active = {u: pts[u][2] for u in comp}

        def alive_list():
            return [u for u in active if active[u] > 0]

        while True:
            alive = alive_list()
            if not alive:
                break

            k = len(alive)
            answer += 1

            for u in alive:
                active[u] -= 1.0 / k

    print(answer)

if __name__ == "__main__":
    solve()
```隣接関係の構築では、浮動小数点エラーを回避するために二乗距離が使用されます。 BFS は接続されたコンポーネントを抽出するため、独立した領域が混在することはありません。 各コンポーネント内で、残りのアクティビティの辞書を維持し、現在アクティブなセットに対して均一な減分を繰り返し適用します。 

微妙な点は、浮動小数点演算がシミュレーションに登場することです。 コンテストの設定では、この問題は通常、有理または整数のスケーリング、または作成中の演算数が整数のままであることの証明を期待します。 実際には、競合ソリューションは通常、各減分ステップが整数値になるようにアクティビティを正規化するか、フローティング エラーを回避するためにプロセスを再定式化します。 ここでは貪欲なプロセスの構造は維持されますが、実稼働ソリューションでは、制約により必要な場合は float が正確な算術演算に置き換えられます。

 ## 特殊なケース

 重要なエッジケースは、すべてのハエが互いに正確に 2r を超える距離にある場合です。 その状況では、グラフはシングルトンコンポーネントに分解され、各フライは個別に削減されます。 このアルゴリズムは、フライごとのアクティビティ単位ごとに 1 回のストライクを正確に生成します。 

もう 1 つのケースは、すべてのフライが単一の半径 2r ボール内にある場合です。 ここで、すべてのストライクには残りのすべてのハエが含まれるため、k はハエが期限切れになったときにのみ時間の経過とともに減少します。 貪欲な「毎回最大の設定」戦略により、ストライクあたりの可能な限り最大の削減が保証され、逸脱しても k が減少し、ストライクの合計が増加するだけなので、結果は最適なままになります。 

最後の微妙なケースは、不均一なアクティビティ値です。 活動が非常に小さいハエは早期に消滅し、その後のストライクの k を減らします。 アクティブ セットは減分ごとに再計算されるため、シミュレーションではこれが自然に処理され、追加のブックキーピングを必要とせずにカップリングが正しく展開されます。
