 ## 問題の理解

 私たちに与えられたリストは、$n$ポジションとそれぞれのポジション$i$単一の値に固定されず、範囲内の任意の整数を許可します$[l_i, r_i]$。 したがって、各有効な配列は、各間隔内の 1 つの値を独立して選択することによって形成されます。 

完全に選択された配列については、少なくとも 2 つの長さの連続したセグメントを選択し、そのセグメント内のすべての要素をそのセグメントの中央値で置き換えるという操作を繰り返し実行できます。 このプロセスはすべての要素が等しくなるまで続き、最終的な定数値がその配列の結果と呼ばれます。 考えられるすべての操作シーケンスの中で、結果は実際には明確に定義されています。つまり、すべての有効なシーケンスは固定配列の同じ最終値に収束します。 配列の値をこの最後の定数として定義します。 

タスクは、指定された間隔から形成されるすべての可能な配列にわたってこの値を合計することです。 

制約の長さは短く、$n \le 150$ただし、間隔内の値は次のように大きくすることができます。$10^9$。 これは、値を直接反復することに依存する解決策は不可能であることをすぐに示します。 この構造は位置に関する純粋な組み合わせであるため、解は値ではなくインデックスに対する引数のカウントと動的プログラミングに依存する必要があります。 

素朴なアプローチでは、考えられるすべての配列を列挙し、中央値置換プロセスをシミュレートし、その最終値を計算します。 配列の数が次のとおりであるため、これはすぐに失敗します。$\prod (r_i - l_i + 1)$, これは中程度の範囲であっても天文学的に大きくなります。 

さらに微妙な失敗例は、各アレイで個別に「プロセスを貪欲にシミュレート」しようとした場合に発生します。 たとえ 1 つの配列に対して最終値を迅速に計算する方法があったとしても、すべての配列に対してそれを行うことは依然として不可能です。 

主な難点は、中央値置換演算ではグローバル不変式が隠蔽されるため、演算をシミュレートするのではなく、最終値が実際にどのような値に依存するかを理解する必要があることです。 

## アプローチ

 ブルートフォースの観点は単純です。つまり、あらゆる選択肢を生成します。$a_i \in [l_i, r_i]$、次に、収束するまで部分配列の中央値演算を繰り返し適用し、最終的な定数を記録します。 これは正しいですが、有効な配列をカウントするだけでも指数関数的になるため、絶望的に遅いです。$n$範囲が自明ではない場合。 

重要な点は、この操作では新しい順序情報が作成されないことです。 中央値の置換は相対的な順序にのみ依存し、操作を繰り返すことで、マルチセットの単一順序統計に向けて全体的な安定化が強制されます。 実際、固定配列の場合、プロセスは常に同じ値に収束し、それが配列全体の中央値のような平衡になることがわかります。 

これは、最終的な値が操作の選択方法ではなく、マルチセットの順序構造のみに依存することを意味します。 したがって、変換をシミュレートする代わりに、考えられる結果の値ごとに決定するだけで済みます。$x$、最終的な中央値平衡が以下に等しいアレイの数$x$、および合計$x$そのカウントによって重み付けされます。 

これを行うには、候補値を固定します。$x$そして、何個のアレイが「安定」するかを数えます。$x$。 中央値条件は、以下の要素の数、以下の要素の数、および以上の要素の数によって純粋に表現できます。$x$。 これにより、問題は位置に関する有界の組み合わせ DP に変換されます。 

タスク全体を圧縮して、すべての意味のある候補値を反復処理します。$x$、これは間隔の終点にすぎず、選択された要素の数がそれを下回る、等しい、または上回るかを追跡する DP を実行します。$x$。

## アルゴリズムのチュートリアル

 値を固定します$x$最終値を正確に持つ配列の数を計算します$x$。 

1. すべての候補値を収集する$x$。 これらはすべて、いずれかの数字です。$l_i$または$r_i$、答えは次の場合にのみ変わるためです。$x$区間の境界を越えます。 
2. 固定の場合$x$、各ポジションを分類$i$間隔に基づいて 3 つの貢献タイプに分類される$[l_i, r_i]$。 間隔が完全に下にある場合$x$、すべての選択肢は「未満」です。$x$完全に上にある場合$x$、すべての選択は「より大きい」です。$x$”。それが交差するなら$x$の場合、次の 3 つのグループに分割されます。$x$、に等しい$x$、およびそれ以上$x$、それぞれが異なる数の選択肢に寄与します。 
3. 処理されたインデックスに対する動的プログラミング状態を定義します。 DP は 2 つの量を追跡します。つまり、選択された要素の数が厳密に以下であるかどうかです。$x$と等しいのはいくつありますか$x$。 残りの要素は暗黙的に次よりも大きくなります$x$。 
4. ポジションごとに、その 3 つのカテゴリに従って遷移を分配することで DP を更新します。 以下の値が選択された場合$x$、「少ない数」が 1 つ増えます。 等しい場合$x$、等価数が増加します。 そうでなければ何も変わりません。 
5. すべての位置を処理した後、結果の構成が中央値の収束に有効であるかどうかを確認します。$x$。 これは 2 つの制約として表現されます。十分な要素が必要です。$\le x$、そして十分でなければなりません$\ge x$。 これらは、DP カウントに対する線形制約に変換されます。 
6. これらの制約を満たすすべての DP 状態を合計して、最終値が次の配列の数を取得します。$x$、乗算します$x$、そして答えに蓄積されます。 

重要な不変条件は、DP がすべてのステップで、以下の固定数の要素を含む部分配列を構築するすべての方法を完全にキャプチャすることです。$x$。 最終条件はこれらのカウントのみに依存するため、順序付け情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        L = []
        R = []
        vals = set()

        for _ in range(n):
            l, r = map(int, input().split())
            L.append(l)
            R.append(r)
            vals.add(l)
            vals.add(r)

        vals = sorted(vals)
        ans = 0

        for x in vals:
            # dp[lt][eq] = number of ways
            dp = [[0] * (n + 1) for _ in range(n + 1)]
            dp[0][0] = 1

            for i in range(n):
                ndp = [[0] * (n + 1) for _ in range(n + 1)]

                l, r = L[i], R[i]

                # compute counts of choices
                # values < x
                a = max(0, min(r, x - 1) - l + 1)
                # values == x
                b = 1 if l <= x <= r else 0
                # values > x
                c = max(0, r - max(l, x + 1) + 1)

                for lt in range(n + 1):
                    row = dp[lt]
                    for eq in range(n + 1 - lt):
                        cur = row[eq]
                        if not cur:
                            continue

                        # choose < x
                        if a:
                            ndp[lt + 1][eq] = (ndp[lt + 1][eq] + cur * a) % MOD
                        # choose = x
                        if b:
                            ndp[lt][eq + 1] = (ndp[lt][eq + 1] + cur * b) % MOD
                        # choose > x
                        if c:
                            ndp[lt][eq] = (ndp[lt][eq] + cur * c) % MOD

                dp = ndp

            total = 0
            for lt in range(n + 1):
                for eq in range(n + 1 - lt):
                    ways = dp[lt][eq]
                    if not ways:
                        continue

                    ge = n - lt  # greater or equal count complement logic
                    le = lt + eq

                    m = n // 2
                    if lt <= m and le >= n - m:
                        total = (total + ways) % MOD

            ans = (ans + x * total) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```コードは各候補値を独立して処理します。 それぞれについて$x$、DP テーブルを構築します。`lt`厳密に以下の要素をカウントします$x$、 そして`eq`以下に等しい要素をカウントします$x$。 各区間は、その区間内の整数が各カテゴリに該当する数に応じて乗算分岐係数に寄与します。 

最終的なフィルタリング条件は、相対的なカウントに関して中央値の実現可能性制約を強制します。$x$。 それぞれの有効な DP 状態が寄与します$x$実現の数が乗算されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての間隔が同一の単一点である場合です。 この状況では、可能な配列は 1 つだけあり、DP は 1 つの候補値に集約される必要があります。 等価性を < と > の両方として誤って扱う実装では、状態が過剰にカウントされますが、厳密で等しいカテゴリに分離することで、カウントは正しいままになります。
