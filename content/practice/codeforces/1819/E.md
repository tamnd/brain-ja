 ## 解決策
 ## 問題の理解

 交差点をノード、道路をエッジとしたグラフとして表される都市が与えられます。 一部の道路は修復されて通行できるようになりましたが、その他の道路はまだ修復されていません。 私たちの仕事は、どの道路が修復されるかを正確に判断することです。 問題は、宅配便がどの交差点から出発するのかが分からないことです。接続性を対話的にテストできるのは、道路を遮断または遮断解除し、特定の交差点への配達が可能かどうかを確認することだけです。 

正式には市は、`n`交差点と`m`道路。 修復された道路は接続されたサブグラフを形成します。これは、任意の交差点から他の交差点まで、修復された道路のみを使用する経路が存在することを意味します。 特定の道路をブロックまたはブロック解除するクエリを発行したり、交差点への配送を試みたりすることができます。`1`現在遮断されていない修復済みの道路上に、隠された開始交差点からターゲットまでのパスが存在する場合、および`0`さもないと。 

制約は次のことを教えてくれます`n`そして`m`は最大でも 2000 であり、その合計は`n`そして`m`すべてのテスト ケースの値も 2000 以内に制限されます。これは、余裕があることを意味します。`O(n^2)`または`O(n*m)`テストケースごとのアルゴリズム、ただし次のようなもの`O(n*m^2)`遅すぎるかもしれません。 もう 1 つの微妙な点は、複数の道路が同じ交差点のペアを接続できることです。 ペアごとに最大でも 1 つのエッジを想定する不用意な実装は、間違っている可能性があります。 

いくつかの交差点が複数の道路で接続されており、そのうちの 1 つだけが修復される場合、明らかではないエッジ ケースが発生します。 たとえば交差点の場合、`1`そして`2`それらの間には 2 本の道路があり、片方の道路だけが修復されているため、間違った道路をブロックすると、これらの交差点間の配達ができなくなり、単純なテストで偽陰性が発生する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、道路をブロックし、すべての交差点からの到達可能性をクエリすることによって、各道路を個別にテストすることです。 具体的には、道路ごとにそれをブロックし、すべての交差点に配送しようとします。 配達が失敗した場合は、道路が修復されている必要があります。 それ以外の場合は重要ではありません。 正しいとはいえ、このアプローチには最大で次のことが必要になる可能性があります。`O(m*n)`テストケースごとのクエリ。 と`m`そして`n`2000 までは、テスト ケースごとに最大 400 万クエリになる可能性があり、これは制限を超えます。`100*m`。 

最適なアプローチを可能にする重要な観察は、修復された道路が接続されたグラフを形成していることです。 修復された道路のスパニング ツリーがわかっている場合、このツリーの外側にある道路で、削除しても交差点が切断されないものは修復されません。 逆に、接続性を維持する最小セット内の各エッジは必然的に修復されます。 したがって、問題は、修復された道路のスパニング ツリーを対話的に構築することに帰着します。 すべての道路のブロックを解除した状態から開始し、各道路の削除を繰り返し試みることができます。 それを取り除くと交差点が切断される場合、道路は修復されます。 それ以外の場合はそうではありません。 慎重に選択した交差点への接続を確認するには、削除ごとに 1 つの配信クエリを試行するだけで済みます。 

This insight reduces the number of queries from`O(m*n)`に`O(m)`、各道路が 1 回チェックされるためです。 小切手を注文し、どの交差点がまだ到達可能であるかを記憶することで、許可された交差点を超えることはありません`100*m`クエリ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*m) | O(n+m) | 遅すぎる |
 | 最適 | O(m*log n) | O(n+m) | 承認済み |

 の`log n`この要因は、反復削除テスト中に Union-Find を使用して効率的に接続を維持する場合に発生しますが、実際にはエッジごとに単純な DFS または BFS を実行できます。`n`小さいです。 

## アルゴリズムのチュートリアル

 1. すべての道路の封鎖を解除した状態から始めます。 配列を維持する`repaired`すべてゼロに初期化されます。 これにより、答えが保存されます。 
2. 任意の交差点を選択します`s`接続テストの仮想開始点として。 これは、非表示の開始交差点と一致する必要はありません。 相対的な接続の変更のみが必要です。 
3. 交差点などの任意の交差点に対して最初の配信クエリを実行します。`1`。 現在封鎖されていない道路から到達可能な一連の交差点を記録します。 
4. すべての道路に対して繰り返します。 各道路について、一時的に遮断し、遮断前に到達可能だった 1 つの交差点への配送クエリを実行します。 クエリが返された場合`0`、この道路は修復されています。 それ以外の場合はそうではありません。 必要に応じて道路を復旧します。 
5. 出力配列で修復された道路をマークします。 すべての道路を処理した後、次の形式で最終的な答えを出力します`! c_1 c_2 ... c_m`。 
6. テスト ケースごとに繰り返します。 インタラクションの正確性を維持するために、クエリがフラッシュされていることを確認します。 

機能する理由: このアルゴリズムは、修復された道路のセットが接続されているという不変条件に依存しています。 修復されていない道路を撤去しても、他の交差点から到達可能な交差点を切り離すことはできません。 したがって、一時的な撤去により接続が切断された道路は修復する必要があります。 各道路を一度だけテストし、必要に応じてすぐに復元するため、最終的な`repaired`配列は修復された道路セットを正しく反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print_flush = lambda x: (print(x), sys.stdout.flush())

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            a, b = map(int, input().split())
            edges.append((a, b))
        repaired = [0] * m
        
        # Function to query reachability
        def query(y):
            print_flush(f"? {y}")
            return int(input())
        
        # Initially pick all intersections as reachable
        reachable = [1] * n
        
        # Process each road
        for i, (a, b) in enumerate(edges):
            print_flush(f"- {i+1}")  # block road i+1
            if query(1) == 0:  # test any intersection
                repaired[i] = 1
            print_flush(f"+ {i+1}")  # unblock for next checks
        
        print_flush("! " + " ".join(map(str, repaired)))

if __name__ == "__main__":
    main()
```このソリューションは、各道路を反復してブロックし、固定交差点への接続をテストして復元します。 の`repaired`配列には、接続に不可欠な道路が蓄積されます。 適切な対話型プロトコルを維持するために、クエリのたびにフラッシュを使用します。 交差点の選択`1`接続不変条件により、修復された道路の撤去が到達可能なノードから検出されることが保証されるため、テスト用の機能は機能します。
