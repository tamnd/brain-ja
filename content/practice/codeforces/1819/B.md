 ## 解決策
 ## 問題の理解

 軸に揃えられた複数の長方形のセットが与えられます。 各長方形は、最初の未知の長方形を整数のグリッド線に沿って繰り返し切断した結果です。 カットごとに、1 つの長方形が縦または横に整数辺の長さの 2 つの小さな長方形に分割され、指定された数のピースが正確に得られるまでこのプロセスが続きます。 

つまり、ストーリーは次のとおりです。元のサイズの長方形が存在します。$h \times w$。 まさにその後$n-1$カット、最終的には$n$長方形。 これらの長方形はシャッフルされ、考えられるすべての元の寸法を復元するように求められます。$(h, w)$それはまさにこのマルチセットを生成した可能性があります。 

重要な制約は、長方形はカット中に回転されないが、出力時には回転されないことです。$(h, w)$そして$(w, h)$は異なる答えとみなされます。 

入力サイズが大きい: すべてのテスト ケースにわたって、四角形の合計数は最大です。$2 \cdot 10^5$。 これにより、あらゆる可能なペアリングを試したり、カット履歴を明示的にシミュレートしたりするアプローチは除外されます。 どのソリューションも基本的に、テスト ケースごとにほぼ線形または線形演算時間で各四角形を処理する必要があります。 

微妙な点は、切断プロセスの最終的な長方形が明示的に指定されていないことです。 他のすべての部分と混合されているため、どの長方形が「ルート」であるかわかりません。 これが中心的な困難です。それを推測しなければなりません。 

単純な間違いは、最大面積の長方形がオリジナルであるに違いないと仮定することです。 最初の長方形が早い段階で 2 つの大きな部分に切り取られ、両方とも大きいままになる場合、これは失敗します。 たとえば、長方形について考えてみましょう$(4,5)$に分割する$(4,2)$そして$(4,3)$。 オリジナルは必ずしもマルチセット内の最大面積の部分であるとは限りません。 

もう 1 つのよくある間違った考えは、切り取った木を再構築しようとすることです。 有効なカット シーケンスが指数関数的に多く存在するため、制約内ではこれは不可能です。 

正しい観点は、すべてのカットで合計領域が維持され、すべてのカットで 1 つの既存の長方形が削除されながら、1 つの新しい長方形が導入されるということです。 したがって、面積の合計は不変であり、次と等しくなります。$h \cdot w$, しかし、これだけでは判断できません。$(h,w)$。 また、すべての中間カットで、最終的なマルチセットと一致するように長方形を 2 つの有効な整数セグメントに分割するように強制する必要があります。 

## アプローチ

 強引なアイデアは、マルチセット内のすべての四角形を潜在的な最終残り部分として試し、それを元のルートの候補として扱うことです。 ルート長方形の候補を選択するとします。$(h, w)$。 次に、分割を繰り返して他のすべての長方形を生成できるかどうかをシミュレーションしてみます。$(h, w)$。 これには、利用可能な長方形を追跡し、各分割を一致させる何らかの構造を構築する必要があります。 最悪の場合、各シミュレーションで四角形の検索と分割が繰り返し行われるため、少なくとも$O(n^2)$候補者ごとの行動、$n$候補者たち。 これはすぐに実行不可能になります$n = 2 \cdot 10^5$。 

重要な洞察は、プロセスを逆にすることです。 前方に分割するという観点から考えるのではなく、後方に四角形を結合することを考えます。 カットごとに、2 つの長方形がマージされて、高さまたは幅のいずれかを維持した 1 つの大きな長方形に戻ります。 

すべてのカットを反転すると、元の形状が復元されるまで長方形が結合されます。$h \times w$。 各マージでは、辺全体の長さを共有する 2 つの長方形を結合する必要があります。 これは、有効な長方形が非常に構造化された方法で共有次元に沿って整列する必要があることを示唆しています。 

重要な点は、有効な構成において、元の四角形は、すべての四角形の境界ボックスの合計が正確に一致するように配置できるようなものでなければならないということです。$(h, w)$、すべての長方形は、このボックスを重複なく分割するサブブロックに対応します。 カットは軸に沿って整列され、整数の境界が保持されるため、マルチセットは効率的にグリッドのパーティションを表します。 

したがって、考えられるすべての候補を試すことができます。$h$そして$w$入力自体から派生します。 重要な制約は、すべての長方形が内側に収まらなければならないということです。$(h, w)$、合計面積が一致する必要があります$h \cdot w = \sum a_i b_i$。 しかし、エリアだけでもまだ多くの候補者が存在します。 

より鋭い洞察は境界構造から得られます。 有効な分解では、少なくとも 1 つの長方形が、高さ全体または幅全体に沿って元の長方形の境界線に接している必要があります。 これは、次のいずれかを意味します$h$いくつかとして現れるはずです$a_i$またはいくつか$b_i$、同様に$w$。 したがって、既存の長方形の辺から派生した候補をテストするだけで済みます。 

候補者ごとに$h$、計算します$w = \frac{\text{total area}}{h}$を実行し、すべての長方形を一貫して配置できるかどうかを確認します。 検証は、長方形を高さに合わせてストリップに分割できるかどうかをチェックすることに要約されます。$h$これは、各高さレイヤーの幅の頻度カウントを使用して検証できます。 

これにより、問題は管理可能な候補の高さのセットをチェックし、それぞれを線形時間で検証することに軽減されます。

 ## アルゴリズムのチュートリアル

 元の高さの有効な値をすべて見つけるようにタスクを再構成します。$h$、幅は総面積によって一意に決定されるためです。 

1. 総面積を計算する$S = \sum a_i b_i$。 これは等しい必要があります$h \cdot w$したがって、すべての候補者の身長を割る必要があります$S$。 これにより、あらゆる可能性が強く制限されます。 
2. 入力長方形からすべての一意の辺の長さを収集します。$h$何らかの長方形の高さまたは幅と等しくなければなりません。 その理由は、一部の長方形が元の長方形の境界と同じ高さに配置され、高さ全体が露出する必要があるためです。 
3. 候補者の身長ごとに$h$、どうかを確認してください$S \bmod h = 0$。 そうでない場合は、整数幅が存在しないため、すぐに破棄します。 
4.セット$w = S / h$。 ここで、すべての四角形を埋め込むことができるかどうかを検証します。$h \times w$矛盾のないグリッド。 検証は、長方形の高さと幅が境界ボックスをタイル表示する方法の一貫性を確保することによって行われます。 
5. 効率的に検証するには、長方形を高さでグループ化し、列パーティションの再構築を試みます。$h$、各長方形は水平セグメントに寄与し、幅の合計がサイズの列全体に正しく収まるかどうかをチェックします。$w$。 不一致が発生した場合は、候補を破棄します。 
6. 有効なものをすべて集める$(h, w)$。 対称的に繰り返して、交換された寸法も含めます$(w, h)$それらが異なるとき。 

### なぜ効果があるのか

 このアルゴリズムは構造的不変式に依存しています。つまり、有効な分解では、元の四角形は、高さ全体または幅全体にわたる少なくとも 1 つの四角形と位置合わせする必要があります。 これにより、元の長方形の少なくとも 1 つの辺が入力長方形の寸法の中に表示されます。 その辺を修正すると、残りの次元は領域保存によって一意に決定され、タイル制約はパーティション間の一貫性の問題としてチェック可能になります。 カットでは長方形が回転されることはないため、すべての長方形は元のフレームに対する軸の位置合わせを維持し、タイリング チェックが必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        rects = []
        total = 0
        
        heights = set()
        widths = set()

        for _ in range(n):
            a, b = map(int, input().split())
            rects.append((a, b))
            total += a * b
            heights.add(a)
            widths.add(b)

        candidates = set()
        for h in heights:
            if total % h == 0:
                candidates.add(h)
        for w in widths:
            if total % w == 0:
                candidates.add(w)

        res = []

        # helper check: try treating h as fixed height
        def check(h):
            w = total // h
            if w <= 0:
                return False

            # we simulate horizontal strips:
            # we count how many full-width contributions we can form per height row
            from collections import defaultdict

            rows = defaultdict(int)
            for a, b in rects:
                if a > h:
                    return False
                rows[a] += b

            # now we try to see if each row can be partitioned into multiples of w
            for a, sumw in rows.items():
                if sumw % w != 0:
                    return False
            return True

        for h in candidates:
            if check(h):
                w = total // h
                res.append((h, w))

        print(len(res))
        for h, w in res:
            print(h, w)

if __name__ == "__main__":
    solve()
```ソリューションは最初に総面積を集計します。これにより積が修正されるからです。$h \cdot w$。 次に、入力に含まれる辺の長さに候補を制限します。これは枝刈りにとって重要です。 検証ステップでは、高さによるグループ化が使用されます。固定された候補の高さの場合、すべての長方形がその中に収まる必要があり、その幅が全幅のサイズのセグメントに結合される必要があります。$w$。 候補の高さを超える長方形は直ちに無効になります。 

実装の微妙な詳細は、行を高さと集計幅によって独立して処理することです。 これにより、コストがかかり、エラーが発生しやすい幾何学的配置の明示的なシミュレーションが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての長方形が同一の小さな正方形である場合です。 その場合、有効な元の長方形は、辺がピースの数に等しい長いストリップだけです。 候補となる高さのセットには 1 のみが含まれており、幅は面積によって強制されるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、1 つの非常に高い長方形と多数の小さな長方形など、長方形が非常に偏った分布を形成する場合です。 単純なアプローチでは、最も高い長方形が元の高さであると誤って想定されますが、すべての幅が全幅パーティションに整列しない限り、検証ステップでそれが拒否されます。 

3 番目のケースは、次元を交換してセットが対称である場合など、複数の有効な元の長方形が存在する場合です。 アルゴリズムには当然両方が含まれます$(h, w)$そして$(w, h)$候補生成には両方の側が表示され、完全性が保証されるためです。
