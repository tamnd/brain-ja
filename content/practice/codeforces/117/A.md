 ## 解決策
 ## 問題の理解

 エレベーターは完全に決定的なサイクルに従います。 

床から始まります`1`時に`0`、床に到達するまで 1 秒ごとに 1 階を登ります`m`、すぐに方向を変えて床に戻ります`1`、再び 1 秒あたり 1 フロア移動します。 階に到達後`1`、同じパターンが永遠に繰り返されます。 

各参加者について、私たちは 3 つのことを知っています。 私たちは、彼らが出発する階、到達したい階、そして出発階に到着する瞬間を知っています。 エレベーターが現在その階に停止している場合、参加者は即座に入場します。 タスクは、目的階への可能な限り最も早い到着時間を計算することです。 

重要な点は、エレベーターの方向が重要であるということです。 上に行く人は、エレベーターが自分の階に到着するたびにそのまま乗り込むことはできません。 上り通行中に乗車する必要があります。 下方向への移動も同様です。 

この制約によりシミュレーションは完全に除外されます。 まであります`10^5`クエリ、およびフロアと時間の両方を次のように大きくすることができます。`10^8`。 1 秒ごとのシミュレーションでは、1 つのクエリでも最大 10 億回の操作が必要になります。 必要なのは`O(1)`参加者ごとの式。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すでに目的階に誰かが立っているとします。 

入力：```
1 10
5 5 100
```出力：```
100
```ここではエレベーターは関係ありません。 不用意に実装すると、待ち時間や移動が計算されてしまう可能性があります。 

エレベーターが時間通りに階に到着する場合、別のトリッキーなケースが発生します。`t`。 

入力：```
1 4
1 2 0
```出力：```
1
```時間に`0`、エレベーターはすでにその階にあります`1`, そのため、参加者はすぐに入場します。 誤って厳密に遅い到着を要求すると、誤って次のサイクルを待つことになります。 

方向の不一致もバグの原因となります。 

入力：```
1 4
2 4 3
```出力：```
9
```時間に`3`、エレベーターは確かにその階にあります`2`ですが、順序が次のとおりであるため、下に移動しています。`1 -> 2 -> 3 -> 4 -> 3 -> 2 -> 1`。 

参加者は上に行きたいので時間通りに乗車`3`役に立たない。 彼らは次の上昇訪問まで待たなければなりません`7`。 

1 階と最終階ではエレベーターの方向が逆になるため、動作が異なります。 

入力：```
1 5
5 1 4
```出力：```
8
```時間に`4`、エレベーターはちょうどその階にあります`5`そしてすぐに下降を開始するので、参加者はすぐに乗り込むことができます。 ターニングポイントの扱いを誤ると、1 つずつ違う間違いが発生することがよくあります。 

## アプローチ

 ブルートフォースソリューションは文字通り、時間の経過に伴うエレベーターの動きをシミュレートします。 私たちはエレベーターの階と方向を毎秒追跡し、参加者全員に対して、エレベーターが必要な方向に移動しながら正しい階に到着するまで待ちます。 

エレベータの経路は決定的であるため、これは論理的に機能します。 最終的には、すべての有効な搭乗瞬間がシミュレーション中に表示されます。 

問題は規模だ。 エレベーターのサイクル長は、`2 * (m - 1)`、ほぼ到達する可能性があります`2 * 10^8`。 すべての参加者に対して 1 つの完全なサイクルをシミュレートするだけでも、遅すぎます。 と`10^5`参加者にとって、操作数は完全に不可能になります。 

重要な観察は、エレベーターの動きが周期的であるということです。 

床用`x`:

 エレベーターが上昇していれば階に到達します`x`時々：```
x - 1 + k * cycle
```エレベーターが下に移動すると階に到達します`x`時々：```
(m - x) + (m - 1) + k * cycle
```どこ：```
cycle = 2 * (m - 1)
```必要な方向がわかれば、最初の有効な搭乗時刻以上の時刻を直接計算できます。`t`。 

参加者が上に行きたいと考えているとします。 次に、最初の時間が必要になります。```
x - 1 + k * cycle >= t
```計算できる`k`シミュレーションの代わりに単純な算術を使用します。 

乗車後の所要時間は次の通りです。```
abs(f - s)
```問題全体は、クエリごとの定数時間演算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エレベーターのサイクル長を計算します。```
cycle = 2 * (m - 1)
```この数秒後、エレベーターは階に戻ります`1`同じ状態です。 
2. 各参加者について、まず次のことを確認します。`s == f`。 

参加者がすでに目的地から出発している場合、答えは単純です。`t`。 
3. 必要な移動方向を決定します。 

もし`f > s`、参加者は上りパス中に乗車する必要があります。 

それ以外の場合は、下りパス中に乗車する必要があります。 
4. エレベーターが最初の階に到着する時間を計算します`s`必要な方向に。 

上向きの動きの場合、1 サイクル内の基本訪問時間は次のとおりです。```
base = s - 1
```下向きの動きの場合:```
base = (m - 1) + (m - s)
```5. 最小の非負の整数を見つける`k`次のような:```
base + k * cycle >= t
```これは天井分割です:```
k = max(0, (t - base + cycle - 1) // cycle)
```6. 搭乗時間は次のようになります。```
board = base + k * cycle
```7. 移動距離を追加します。```
answer = board + abs(f - s)
```### なぜ効果があるのか

 エレベーターの軌道は毎回完璧に繰り返されます`2 * (m - 1)`秒。 各フロアと方向のペアごとに、各サイクル内に訪問時間が 1 つだけ存在します。 アルゴリズムは標準的な訪問時間を計算し、エレベーターがそれより早く到着しない最初のサイクルに直接ジャンプします。`t`。 

エレベーターは 1 秒間に 1 階を途切れることなく移動するため、`s`に`f`搭乗後は常に正確です`abs(f - s)`。 常に最も早い有効な搭乗時刻を選択するため、結果として到着時間は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    cycle = 2 * (m - 1)

    ans = []

    for _ in range(n):
        s, f, t = map(int, input().split())

        if s == f:
            ans.append(str(t))
            continue

        if f > s:
            base = s - 1
        else:
            base = (m - 1) + (m - s)

        if t <= base:
            board = base
        else:
            k = (t - base + cycle - 1) // cycle
            board = base + k * cycle

        arrival = board + abs(f - s)
        ans.append(str(arrival))

    print("\n".join(ans))

solve()
```最初の部分ではサイクル長を計算します。 からのエレベーター通路`1`まで`m`そして戻って`1`正確にかかります`2 * (m - 1)`秒。 

各クエリの特殊なケース`s == f`すぐに処理されます。 一般的な搭乗ロジックでは、参加者が実際にエレベーターに乗らなければならないと想定されているため、このケースを忘れると誤った答えが生成されることがよくあります。 

変数`base`エレベーターがフロアに到達するサイクル内の最初の瞬間を表します`s`必要な方向に。 

上向き移動の場合:```
base = s - 1
```エレベーターはその階から始まるので`1`時に`0`そして1秒間に1階ずつ登っていきます。 

下向き移動の場合:```
base = (m - 1) + (m - s)
```エレベーターは最初に費やします`m - 1`数秒で最上階に到着し、その後さらに`m - s`床に降りるまでの秒数`s`。 

天井分割ステップは、算術トリックの核心です。```
(t - base + cycle - 1) // cycle
```これにより、訪問時間が少なくとも`t`。 

実装は慎重に処理します`t <= base`別に。 その分岐がないと、除算式に負の値が現れる可能性があります。 

Python の整数は、答えがはるかに下回っているため、ここでは最大値を簡単に処理できます。`10^9`。

 ## 特殊なケース

 参加者がすでにターゲットフロアからスタートしている場合を考えてみましょう。 

入力：```
1 10
5 5 100
```アルゴリズムは即座に検出します`s == f`そして戻ってきます`100`。 搭乗ロジックはまったく実行されません。 これにより、参加者が誤って不必要にエレベーターに乗らされることが回避されます。 

ここで、エレベーターの正確な到着時間を考えてみましょう。 

入力：```
1 4
1 2 0
```上向きの動きの場合:```
base = 1 - 1 = 0
```以来：```
t = 0
```アルゴリズムは即座にボードされます。```
board = 0
arrival = 0 + 1 = 1
```等しい場合が重要です。 厳密な比較を使用すると、誤って搭乗が 1 サイクル全体遅れてしまいます。 

方向の不一致も微妙な状況です。 

入力：```
1 4
2 4 3
```サイクルの長さは次のとおりです。```
6
```フロアへの上向きの訪問`2`発生場所:```
1, 7, 13, ...
```下向きの訪問は次の場所で発生します。```
5, 11, ...
```参加者は時間通りに到着します`3`、そのため、近くの訪問も機能しません。 アルゴリズムは、次の上向き訪問を適切に選択します。`7`、生産:```
7 + 2 = 9
```最後に、最上階の転換点について考えてみましょう。 

入力：```
1 5
5 1 4
```下向きの動きの場合:```
base = (5 - 1) + (5 - 5) = 4
```以来`t == base`, 搭乗は下降フェーズ中に最上階ですぐに行われます。 移動時間は`4`ですので到着時間は`8`。 

これにより、反転動作がオフバイワンエラーなしで正しく処理されることが確認されます。
