 ## 問題の理解

 9 桁の文字列で表される数字を含む 2 人用ゲームをシミュレートするように求められます。 最初のプレイヤーが文字列を選択します`s1`指定された値を超えない数値を表す`a`。 2 番目のプレーヤーは文字列で応答します`s2`以下の数値を表す`b`。 どちらの文字列も正確に 9 桁の長さで、先頭にゼロが付いている可能性があります。 を連結した場合、2 番目のプレーヤーが勝ちます。`s1`そして`s2`単一の数値は指定された値で割り切れるので、`mod`。 それ以外の場合は、最初のプレイヤーが勝ちます。 最初のプレイヤーが勝利を保証できる場合は、辞書編集上の最小の文字列も決定する必要があります。`s1`それがこれを達成します。 

境界は次のとおりです`10^9`のために`a`そして`b`、そして最大`10^7`のために`mod`。 9 桁の文字列は、考えられるすべての選択肢を明示的に列挙することが不可能な空間で作業していることを意味します。`10^9`ブルートフォース列挙するにはすでに大きすぎます。 代わりに、この問題には注意深い数論的推論とモジュラー算術が必要です。 エッジケースには、次のような状況が含まれます。`a`または`b`よりも小さいです`10^9`、9 桁の文字列表現の先頭にゼロを強制します。 もう 1 つのエッジケースは次のような場合です`mod`は非常に小さいため、多くの割り算パターンが可能になるか、`a`または`b`がゼロとなり、動きが大幅に制限されます。 

## アプローチ

 単純なブルートフォースアプローチでは、可能な限りあらゆるものを生成しようとします。`s1`からの文字列`0`に`a`、それぞれについて`s1`可能な限りすべてをチェックする`s2`から`0`に`b`、連結された数値の割り切れ性を次のようにテストします。`mod`。 以来`s1`そして`s2`それぞれ最大でかかることができます`10^9`価値観、これは次のことにつながります`10^18`制限時間内に実行できない最悪の場合のチェックを行います。 メモリ効率の高い枝刈りアプローチでも、すべての可能性を直接列挙することはできません。 

重要な洞察は、割り算は剰余モジュロのみに依存するということです。`mod`。 可能なすべての剰余を事前計算できます`s2`剰余数`mod`、そして各候補者について`s1`が存在するかどうかを確認するだけで済みます。`s2`そのような`(s1 * 10^9 + s2) % mod == 0`。 モジュラー算術を使用すると、これは次のことをチェックすることと同じです。`(s1 * 10^9) % mod`一部に一致します`mod - s2 % mod`。 以来`s2`までの範囲`b`、すべての剰余を計算するだけで済みます。`s2 % mod`効率よくセットで保管できます。 これにより、1 回あたりのチェックが削減されます`s1`O(1) セット ルックアップに変換します。 繰り返すことで`s1`昇順で、辞書編集上最小の勝利文字列が存在する場合、それが自動的に検索されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | O(mod + a') | O(mod) | 承認済み |

 ここ`a'`は候補者の数です`s1`文字列、最大`a + 1`しかし実質的には`10^9`。 の`mod`この用語は、すべての剰余を事前計算することから来ています。`s2`価値観。 

## アルゴリズムのチュートリアル

 1.正規化`a`そして`b`必要に応じて先頭にゼロを埋め込み、正確に 9 桁の文字列に変換します。 これにより、辞書編集上の比較が正しく機能し、すべての数値が正確に 9 桁になることが保証されます。 
2. コンピューティング`power = 10^9 % mod`。 これは、次の貢献を表します。`s1`連結された数値の剰余`mod`。 これを利用して、`(s1 * 10^9 + s2) % mod`になる`(s1 * power + s2) % mod`。 
3. 可能な限りすべてを事前計算する`s2`剰余モジュロ`mod`からの数字の場合`0`に`b`。 これらをセットに保存すると、高速に検索できます。 
4. すべての候補番号を反復処理します。`s1`から`0`に`a`昇順で。 For each candidate, compute`(s1 * power) % mod`が存在するかどうかを確認します`s2`セット内の残りは次のようになります`(s1 * power + s2) % mod == 0`。 そうでない場合`s2`存在する場合、最初のプレイヤーはこれで勝利を保証できます`s1`。 
5. 勝利1回`s1`見つかった、出力`1`および 9 桁の文字列表現`s1`。 もしすべてなら`s1`値により、2 番目のプレーヤーが最適に応答して勝つことができます。出力`2`。 

不変条件は、それぞれの`s1`、のセット`s2`残りは、2 番目のプレーヤーが実行できるすべての可能な手を表します。 どちらもキャンセルしない場合`(s1 * power) % mod`、最初のプレイヤーが勝ちます。 2 番目のプレイヤーの考えられるすべてのカウンターの動きを明示的にチェックするため、これにより正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    a, b, mod = map(int, input().split())
    power = pow(10, 9, mod)
    s2_rems = set(i % mod for i in range(b + 1))
    
    for s1_num in range(a + 1):
        s1_rem = (s1_num * power) % mod
        # check if there exists s2 that makes total divisible
        found = any((s1_rem + s2_rem) % mod == 0 for s2_rem in s2_rems)
        if not found:
            print(1)
            print(f"{s1_num:09d}")
            return
    print(2)

if __name__ == "__main__":
    main()
```私たちは計算します`power`9 桁の乗数を直接処理することを避けるために、べき乗モジュラーを使用します。 のセット`s2`剰余により、すべての候補に対して O(1) の検索が可能になります`s1`。 辞書編集上の最小値を保証するために昇順で反復します。`s1`。 使用する`f"{s1_num:09d}"`先頭にゼロを付けた 9 桁の出力が保証されます。
