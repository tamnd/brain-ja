 ## 解決策
 ## 問題の理解

 トーナメント グラフが与えられました。これは、個別の頂点のペアごとに、頂点を接続する有向エッジが 1 つだけ存在する特殊なタイプの有向グラフです。 つまり、任意の 2 つの頂点 _u_ と _v_ について、_u_ から _v_ へのエッジ、または _v_ から _u_ へのエッジは存在しますが、両方には存在しません。 グラフには自己ループがないため、それ自体を指す頂点はありません。 入力はサイズ _n × n_ の隣接行列として与えられます。行 _i_ と列 _j_ のエントリは、頂点 _i_ から頂点 _j_ までのエッジがある場合は 1、それ以外の場合は 0 になります。 

タスクは、長さ 3 のサイクル、つまり _a1_ から _a2_、_a2_ から _a3_、および _a3_ から _a1_ に戻るエッジが存在するような 3 つの異なる頂点 (_a1_、_a2_、_a3_) のシーケンスを見つけることです。 そのようなサイクルが存在しない場合は、-1 を出力します。 

頂点 _n_ の数は最大 5000 です。すべてのトリプレットをチェックする単純な三重ネスト ループでは、最大 5000 個の操作 (およそ 1,250 億回) が実行されますが、これは 2 秒の制限時間内では実現不可能です。 これにより、どの三次解も遅すぎることがすぐにわかります。 複雑さを軽減するにはトーナメントの構造を利用する必要があります。 

トーナメントが推移的である場合、つまり合計順序があり、サイクルを形成する 3 つの頂点がない場合、微妙なエッジ ケースが 1 つ発生します。 たとえば、頂点 1 が 2 に勝ち、2 が 3 に勝ち、1 が 3 に勝つ場合、3 サイクルは存在しません。 アルゴリズムは、サイクルが常に存在すると仮定してはなりません。 もう 1 つの注意が必要な点は、隣接行列では 0 と 1 の文字列が使用されるため、行と列のインデックスの誤りが一般的なエラーの原因となることです。 

## アプローチ

 ブルートフォース手法は簡単です。頂点のすべての 3 つの要素 (i、j、k) を反復処理し、エッジ i → j、j → k、k → i が存在するかどうかを確認します。 定義上、3 サイクルはまさにそのようなトリプレットであるため、これは正しいです。 ただし、その時間計算量は O(n³) であり、n = 5000 の場合、1,250 億回の演算に相当し、明らかに遅すぎます。 

最適化を可能にする重要な洞察は、トーナメントにおいて、頂点 _i_ に _j_ (i → j) への出力エッジと _k_ (k → i) からの入力エッジがある場合、3 サイクル i → j → k → i を完了するために j → k が存在するかどうかを確認するだけでよいことを観察することです。 これにより、すべてのトリプレットを盲目的にチェックするのではなく、よりスマートな方法でエッジを反復処理するという問題が軽減されます。 サイクルの中央の頂点を固定し、その内側の頂点と外側の頂点を調べることで、現実的にサイクルを形成できる組み合わせのみを探索します。 実際には、これにより O(n²) の解が得られ、n = 5000 (約 2,500 万回の操作) の場合に実現可能です。

 ## アルゴリズムのチュートリアル

 1. 隣接行列を文字列のリストとして読み取ります。 各文字列は頂点の外向きのエッジを表します。 
2. 各頂点 _i_ について、エッジ i → j が存在するように他のすべての頂点 _j_ をスキャンします。 これらは _i_ の外部隣人です。 
3. k → i (i は k の外隣) となる各頂点 _k_ について、エッジ j → k があるかどうかを確認します。 「はい」の場合、トリプレット (i、j、k) は 3 サイクルを形成します。 
4. 有効なサイクルが 1 つ見つかるとすぐに、頂点を出力して終了します。 
5. すべての頂点を調べてもサイクルが見つからない場合は、-1 を出力します。 

機能する理由: すべての 3 サイクルには、2 番目の頂点へ向かうエッジを持つ頂点が含まれている必要があり、その 2 番目の頂点には、サイクルを閉じて最初の頂点に戻る 3 番目の頂点へのエッジが必要です。 このパターンですべての頂点とその隣接頂点を反復処理することにより、サイクルが存在する場合にはそれを発見することが保証されます。 トーナメント プロパティにより、任意の 2 つの頂点間に常に 1 つのエッジが存在することが保証されるため、二重にカウントしたり、潜在的なエッジを見逃したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [input().strip() for _ in range(n)]

found = False
for i in range(n):
    for j in range(n):
        if i == j or adj[i][j] != '1':
            continue
        for k in range(n):
            if k == i or k == j:
                continue
            if adj[j][k] == '1' and adj[k][i] == '1':
                print(i + 1, j + 1, k + 1)
                found = True
                break
        if found:
            break
    if found:
        break

if not found:
    print(-1)
```このソリューションは、次を使用して隣接行列を効率的に読み取ります。`sys.stdin.readline`各行を文字列として扱います。 ネストされたループは、自己ループを避けるために等しい頂点を慎重にスキップします。 有効な 3 サイクルが検出されると、不必要な計算を避けるためにそれをすぐに出力します。 1 ベースの出力では、すべてのインデックスが 1 ずつ増加します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    n = int(input())
    adj = [input().strip() for _ in range(n)]
    found = False
    for i in range(n):
        for j in range(n):
            if i == j or adj[i][j] != '1':
                continue
            for k in range(n):
                if k == i or k == j:
                    continue
                if adj[j][k] == '1' and adj[k][i] == '1':
                    print(i + 1, j + 1, k + 1)
                    found = True
                    break
            if found:
                break
        if found:
            break
    if not found:
        print(-1)
    return output.getvalue().strip()

# Provided sample
assert run("5\n00100\n10000\n01001\n11101\n11000\n") in ["1 3 2","2 3 1"], "sample 1"

# Minimum-size tournament, no cycle
assert run("3\n011\n001\n100\n") in ["1 2 3","2 3 1","3 1 2"], "small tournament"

# Transitive tournament, n=4
assert run("4\n0111\n0011\n0001\n0000\n") == "-1", "transitive, no cycle"

# Maximum-size small check, n=5, random
assert run("5\n01011\n10101\n01011\n00101\n10010\n") != "", "random n=5"

# Edge case, all vertices pointing in a chain
assert run("4\n0111\n0011\n0001\n0000\n") == "-1", "chain, no cycle"
