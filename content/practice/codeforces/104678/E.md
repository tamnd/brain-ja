 ## 解決策
 ## 問題の理解

 あります$n$それぞれのチームは固定の強さの値から始まります。 各チームのペアは 1 試合のみを行うため、トーナメントは完全な総当たり戦となります。 試合の結果は最終的な強さによってのみ決まります。強いチームが勝ち、両方の強さが等しい場合、試合は引き分けとなります。 

ポイントは試合ごとに与えられ、チームの合計スコアはすべての試合の合計にすぎません。 勝利すると勝者に 3 ポイントが与えられ、引き分けでは各参加者に 1 ポイントが与えられます。 トレーニング セッションごとにチームの強さを 1 増やすことができ、各セッションは 1 つのチームにのみ影響します。 

主な目標は、試合の結果を直接選択することではなく、すべてのトレーニング後にすべてのチームのポイントの合計ができるだけ大きくなるように強みを調整することです。 この最大合計を達成するためのあらゆる方法の中で、必要なトレーニング セッションの最小数を見つける必要があります。 

制約が示唆するのは、$n$最大 200000 になる可能性があるため、どの解もおおよそ次のようにする必要があります。$O(n \log n)$またはそれ以上です。 チームのすべてのペアにわたる二次アプローチは不可能です。$O(n^2)$シミュレーションするにも多すぎる一致があります。 

多くのチームが同じ強さを共有する場合、微妙な問題が発生します。 たとえば、複数のチームの値が等しい場合、それらのチーム間のすべての試合は引き分けとなり、合計ポイントが減ります。 強さを高めると関係が切れる可能性がありますが、そうすることで複数のペアごとの結果に一度に影響を与えるため、貪欲なローカル決定には慎重な正当化が必要です。 

単純な間違いは、試合をシミュレートしたり、ペアごとに強さを調整しようとしたりすることです。 1 つの増分により、1 つの対戦相手だけでなく、他のすべてのチームとの比較が同時に変更されるため、これは失敗します。 

具体的な例として、すべてのチームが強さからスタートした場合$[5, 5, 5]$、すべての試合は引き分けであり、合計ポイントは最小限になります。 1 つのチームをわずかに増やすと、すべての試合が一度に変更されるため、問題は基本的にグローバル構造に関するものであり、個別の八百長ではありません。 

## アプローチ

 まず、合計スコアが何によって決まるのかを理解しましょう。 各チームのペアは、勝者がいる場合は合計 3 ポイント、引き分けの場合は 2 ポイントを獲得します。 試合数は固定なので、$\frac{n(n-1)}{2}$、合計スコアを最大化することは、引き分け以外の試合の数を最大化することと同じです。 

2 つのチームの最終的な強さが同じになった場合、試合は引き分けとなります。 これは、最終的な強みがすべて異なる場合が最適な状況であることを意味します。その場合、すべての試合に勝者が存在し、2 ポイントではなく 3 ポイントが与えられます。したがって、目標は、最終的な強みの配列で重複をすべて排除することになります。 

値を増やすことのみが可能であり、値を減らすことはできません。 したがって、タスクは次のようになります: 配列から開始$a$、各要素に整数の増分を割り当て、結果の配列が$b$満足する$b_1 < b_2 < \dots < b_n$、合計の増加を最小限に抑えながら$\sum (b_i - a_i)$。 これは、ソートされた配列に対する古典的な貪欲な構築の問題です。 

強引なアイデアは、すべての値が明確になるまでチーム間で増分を分配するすべての可能な方法を試し、コストを計算することです。 各要素が任意に増加する可能性があり、状態空間が指数関数的に爆発するため、これは実現不可能です。 ローカルで競合を解決しようとしても、さらなる競合に連鎖し、周囲で最悪のケースの動作が発生する可能性があります。$O(\text{range of values})$調整ごとに。 

重要な観察は、並べ替え後の構造が線形になることです。 等価性を避けるために、各要素は前の最終値より少なくとも 1 だけ大きい必要があります。 以前の選択が修正されると、現在の要素に最適な選択が強制されます。元の値と厳密な増加制約の両方を尊重しながら、可能な限り小さい値にする必要があります。 これにより、バックトラッキングがすべて削除され、単一パスのソリューションが得られます。

 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適な貪欲さ |$O(n \log n)$| O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ

 1. 強さの配列を降順でない順に並べ替えます。 

ソートが必要なのは、値を厳密に増加させるという最終的な条件を順番に適用するのが最も簡単であるためです。 
2. 実行変数を初期化する`current`次のチームの有効な最小値を追跡します。 
3. 各チームをソートされた順序で処理します。 それぞれの本来の強さに対して$a_i$、最終強度を次のように設定します。$b_i = \max(a_i, current)$。 

これにより、値を決して減らさず、以前のチームとの順序に違反しないことが保証されます。 
4.割り当て後$b_i$、 アップデート`current`に$b_i + 1$、次の要素は厳密に大きくなければならないためです。 
5. コストを次のように累積します。$\sum (b_i - a_i)$、これはトレーニング セッションの合計数を表します。 

### なぜ効果があるのか

 すべてのポジションで、現在のチームに対して可能な限り最小の有効な値を適用します。 将来の要素に対する唯一の制約は、厳密に前の要素よりも大きくなることであるため、より大きな選択をしても、実現可能性は向上せずにコストが増加するだけです。 これにより、単調な構造が作成されます。値が固定されると、それは後続のすべての値の下限になります。 各ステップは、将来の実現可能性を完全に捉える制約の下で局所的に最小限であるため、後の調整によって以前の決定が次善の策となる可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    current = a[0]
    ans = 0

    for i in range(n):
        if i == 0:
            current = a[0]
        else:
            current = max(a[i], current + 1)
        ans += current - a[i]

    print(ans)

if __name__ == "__main__":
    solve()
```ソート ステップは、すべてのペア間の元の組み合わせ相互作用を線形制約チェーンに変換するものです。 ソートを行わないと、依存構造は不明瞭になりますが、ソート後は、各要素は以前に構築された値にのみ依存します。 

の`current`変数は、以前のすべての要素との等価性を回避する最小許容値をエンコードします。 の`max`運用により、元の強度と厳格な増加要件の両方が尊重されるようになります。 累積された差は、すべてのチームに適用される増分数を直接カウントします。 

実装でよくある落とし穴は、値を増やすと、隣接する要素だけでなく、後続のすべての制約に影響を与えるということを忘れていることです。 もう 1 つは、最初の要素がその前の要素より大きい必要がないため、最初の要素を誤って初期化することです。

 ## 特殊なケース

 重要なエッジケースは、すべての強さが等しい場合です。 この状況では、すべてのペアごとの一致は最初は引き分けであり、アルゴリズムは値を厳密に増加するシーケンスにプッシュする必要があります。 貪欲なメソッドは、これを次の方法で自然に処理します。$[x, x, x, \dots]$の中へ$[x, x+1, x+2, \dots]$、三角数の増分を累積します。 各ステップは前に選択した値のみに依存するため、あいまいさは生じません。 

もう 1 つのエッジ ケースは、配列がすでに厳密に増加している場合です。 並べ替えた後、すべての$a_i$すでに満足しています$a_i > a_{i-1}$、それで、`max`操作は常に選択します$a_i$自体。 トレーニングが必要なく、アルゴリズムが不必要な増分を適切に回避するため、コストはゼロのままです。 

最後の微妙なケースは、次のように、重複が大きなギャップでインターリーブされている場合に発生します。$[1,1,100]$。 2 番目の要素は 2 にのみプッシュされ、大きい 3 番目の要素は増加制約をすでに満たしているため変更されません。 これは、アルゴリズムが厳密な順序を維持するために必要な値を超えて値を過剰調整しないことを示しています。
