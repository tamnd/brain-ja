 ## 問題の理解

 2人の観測者が対極に立って、それぞれの位置から見える星を数えます。 各星は、両方の極ではなく、正確に 1 つの極から見えます。これは、2 つの観測結果が星のセット全体を 2 つの素なグループに分割していることを意味します。 1 人の観測者はカウント A を報告し、もう 1 人はカウント B を報告します。タスクは、星の総数を回復することです。これは、単にこれら 2 つの素なセットの和集合のサイズです。 

入力 A と B は整数として指定されますが、それぞれ最大 100,000 桁に達する非常に大きな値になる可能性があります。 128 ビット演算でも小さすぎるため、標準の固定幅整数型に依存するアプローチは即座に除外されます。 時間制限により、桁数の線形時間処理が許可されるため、各桁を一定の回数スキャンする操作は許容されますが、桁数が 2 次の演算は遅すぎます。 

言語の制限を考慮せずに、組み込みの整数解析がすべての環境で安全であると仮定すると、微妙な失敗のケースが発生します。 一部の言語や単純な実装では、これらの数値をネイティブ型に変換すると、警告なしにオーバーフローするか、完全に失敗します。 A と B は必ずしも同じ桁数を持っているわけではないため、異なる長さを適切に処理せずに連結または桁ごとの操作を試みると、別の問題が発生します。 

具体的なエッジ シナリオは、A と B のサイズが大きく異なる場合です。 たとえば、A は 1 桁の数値、B は 100,000 桁の長さになる可能性があります。 アライメントベースの算術演算では、短い方の数値の先頭の欠落した桁を正しく処理する必要があります。 もう 1 つのケースは、両方の数値が大きく、その合計により桁の長さが 1 つ増加する追加のキャリーが生成される場合です (999...999 プラス 1 など)。 

## アプローチ

 この問題を直接解釈すると、単に 2 つの互いに素なカウントを組み合わせているだけであることがわかり、答えは A + B になります。単純なアプローチは、両方の数値を整数に解析し、組み込みの算術演算を使用して加算することです。 Python やその他の言語は任意精度の整数をサポートしているため、これは概念的には機能しますが、より厳密な環境や C++ などの言語では、オーバーフローが原因で失敗します。 

Python でも、整数の直接加算は正しいですが、問題は型に盲目的に依存するのではなく、大数の算術の理解を重視するように設計されています。 大きな整数を持たない言語を想定すると、総当たり戦略は両方の文字列を反転した後、数字ごとに加算することになります。 これにより、各桁が最下位から最上位に処理され、オーバーフローが手動で処理されます。 

ブルートフォース数字シミュレーションは、桁数にわたって線形時間で実行されます。これは、すべての数字を少なくとも 1 回読み取る必要があることを考慮すると最適です。 数値を基数 10 の表現として扱い、列ごとに合計する以外に活用できる構造はありません。 

重要な観察は、スター セットが互いに素であるため、包含/除外の複雑さ、重複の修正、および隠れた制約がないことです。 タスク全体は任意精度の加算に帰着します。

 ## アルゴリズムのチュートリアル

 2 つの入力文字列を 10 進数として扱い、標準的な加算を右から左に実行します。

1. 文字列 A と B の両方を読み取ります。これらは、最大 100,000 桁の長さの 10 進数を表します。 
2. 各文字列の最後の桁で 2 つのポインタを初期化し、キ​​ャリー値を 0 に設定します。 ポインタは、各数値で処理されている現在の桁位置を表します。 
3. A と B の対応する数字をキャリーとともに繰り返し加算します。 1 つの文字列が完全に消費されている場合は、その数字をゼロとして扱います。 これにより、両方の数値が最下位側から正しく配置されるようになります。 
4. 結果の数字を 10 を法とした剰余として計算し、キャリーを 10 による整数の除算として更新します。結果の数字を一時バッファに追加します。 
5. 両方の数値のすべての桁が処理され、キャリーが残らなくなるまで続行します。 
6. バッファを反転して、正しい順序で最終的な合計を取得します。 

この手順が有効である理由は、位置 10 進数表現により独立した列方向の加算が可能になり、キャリーが次の上位の桁にのみ伝播されるためです。 すべてのステップで、部分結果は 2 つの数値のサフィックスと受信キャリーの合計を正しく表します。そのため、アルゴリズムが維持する不変条件は、処理されたすべての下位桁が完全に解決され、将来の操作の影響を受けないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()
    
    i, j = len(a) - 1, len(b) - 1
    carry = 0
    res = []
    
    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - 48 if i >= 0 else 0
        y = ord(b[j]) - 48 if j >= 0 else 0
        
        s = x + y + carry
        res.append(chr((s % 10) + 48))
        carry = s // 10
        
        i -= 1
        j -= 1
    
    res.reverse()
    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```この実装では、文字列から整数への変換によるオーバーヘッドを回避するために、ASCII 算術を使用して手動で数字抽出を実行します。 ループは両方のインデックスが使い果たされ、桁上げが残らなくなるまで継続します。これにより、最終的な合計の桁数が 1 つ増えた場合でも正確さが保証されます。 数字は最下位から最上位の順序で追加されるため、最後に反転する必要があります。 

よくある間違いは、両方のポインターがゼロに達したときにループを停止し、999 + 1 などの残りのキャリーを無視することです。これにより、先頭の桁が誤って削除されます。

 ## 特殊なケース

 重要なエッジ ケースは、一方または両方の入力がゼロの場合です。 インデックスが範囲外になると数字抽出でゼロが返されるため、アルゴリズムはこれを自然に処理し、特別な分岐は必要ありません。 

もう 1 つのケースは、最後の桁上げによって新しい最上位桁が作成される場合です。 999 + 1 のような状況では、両方のインデックスが使い果たされた後もループが続行され、キャリーが破棄されるのではなく新しい桁として追加されることが保証されます。 最後の反転により、正しく前面に配置されます。 

アルゴリズムでは位置が揃っているとは決して想定されないため、長さが等しくない入力は均一に処理されます。 1 つのポインターが負になると、対応する数字の寄与はゼロとして扱われるため、前処理やパディングを行わずに正確さが保たれます。
