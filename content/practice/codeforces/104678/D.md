 ## 解決策
 ## 問題の理解

 開き括弧と閉じ括弧のみで構成される文字列が与えられます。 タスクは、括弧以外のすべてを取り除いた後、このシーケンスが有効な算術式から生じるかどうかを判断することです。 

重要な観察は、数値と演算子が削除されると、算術式では括弧で囲まれた構造だけが残るということです。 この構造は、すべての閉じ括弧が以前に開かれた括弧と一致する場合に正確に有効であり、どの接頭辞も開かれた括弧よりも多くの括弧を閉じることはありません。 

したがって、入力は単に括弧構造の候補であり、出力は、この構造が正しく形成された式に対応するかどうかの二者決定です。 

n が 200000 までの制約により、二次シミュレーションや繰り返しの再スキャンが即座に除外されます。 文字列を検索したり、繰り返し変更したりしてペアを一致させようとするソリューションは、遅すぎます。 リニア スキャンが唯一の現実的な選択肢です。 

いくつかの危険な状況では、よくある間違いが露呈します。 

input のように文字列が右括弧で始まる場合`")("`、一致する左括弧を提供できる以前のコンテキストがないため、これを有効な式からのものとして解釈することは不可能です。 正しい出力は次のとおりです`NO`。 

文字列の合計数は正しいが、順序が無効である場合、次のようになります。`"())("`、オープンの合計数はクローズと等しくなりますが、あるプレフィックスではシーケンスが無効になります。 正しい出力はまだです`NO`, これは、バランスだけでは不十分であることを示しています。 

弦のバランスが完璧に整っていれば、`"(())()"`、順序とカウントの両方が一致しており、答えは次のようになります。`YES`。 

## アプローチ

 構造を検証する強引な方法は、隣接する一致するペアを繰り返し検索することです。`"()"`削除できなくなるまで削除します。 文字列が空になった場合は有効です。 

これが機能するのは、すべての有効なブラケットのペアが最終的に一致して削除される必要があるためです。 ただし、削除するたびに文字列が移動し、再スキャンが強制される可能性があります。 最悪の場合、例えば、`"((((....))))"`を削除するたびに、文字列のほぼ全体が再度スキャンされます。 n が 200000 までの場合、これはおよそ O(n^2) の演算を必要とし、非常に遅すぎます。 

重要な構造的洞察は、有効性は、左から右に読んだときに利用可能な開始括弧よりも多くの閉じ括弧に遭遇するかどうかによってのみ決まるということです。 除去をシミュレートする代わりに、各ステップで一致しない開始括弧がいくつ存在するかを表すカウンターを維持します。 

私たちが見るたびに`'('`、カウンターを増やします。 私たちが見るたびに`')'`、少なくとも 1 つの一致しないものが必要です`'('`利用可能; それ以外の場合、シーケンスは直ちに無効になります。 最後に、シーケンスは、一致しない開口部が残っていない場合にのみ有効です。 

これにより、問題は 1 つのパスに変換され、キャラクターごとに一定の作業が行われます。

 ## アルゴリズムのチュートリアル

 現在開いているが一致しない括弧の数を表す単一の整数を追跡しながら、文字列を左から右にスキャンします。 

1. カウンタを初期化する`balance = 0`。 これは何個かを表します`'('`がまだ一致していないことが確認されています。`')'`。 
2. 文字列内の各文字を繰り返し処理します。 
3. キャラクターが`'('`、増分`balance`1つずつ。 これは、新しい比類のない開始ブラケットの導入を反映しています。 
4. キャラクターが`')'`、デクリメント`balance`1つずつ。 デクリメントの前後に、次のことを確認する必要があります。`balance`はまだゼロではありません。これは、存在しない括弧を閉じようとしていることを意味するためです。 これが発生した場合、シーケンスは有効な式に対応できなくなります。 
5. いつでも`balance`負になると、直ちにシーケンスが無効であると結論付けられます。 
6. 文字列全体を処理した後、次のことを確認します。`balance`ゼロに等しい。 一致する場合、すべての左括弧が一致します。 それ以外の場合、一部は一致しないままとなり、シーケンスは無効になります。 

正確かどうかは、どの接頭辞であっても、有効な式内の閉じ括弧の数が開き括弧の数を超えてはいけないという事実にかかっています。 

### なぜ効果があるのか

 アルゴリズムは不変式を維持します。つまり、各プレフィックスを処理した後、`balance`プレフィックスがこれまで有効であると仮定した場合、そのプレフィックス内で一致しない左括弧の数に等しくなります。 それぞれ`'('`新しい比類のない要件が導入され、それぞれの`')'`このような要件を 1 つだけ削除します。 要件が存在しないときに閉じ括弧が出現すると、整形式括弧の基本的なペア制約に違反し、有効な式からシーケンス全体を導出することができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    balance = 0

    for ch in s:
        if ch == '(':
            balance += 1
        else:
            balance -= 1
            if balance < 0:
                print("NO")
                return

    print("YES" if balance == 0 else "NO")

if __name__ == "__main__":
    solve()
```この実装は、前述のリニア スキャンを反映しています。 早期退場時`balance`これ以上続行すると、すでに無効になっているプレフィックスを修復できないため、負になることが重要です。 最終的な等価性チェックにより、一致しない左括弧が残っていないことが確認されます。 

微妙な点は、括弧の位置を明示的に保存したり、ペアリングを試みたりする必要がないことです。 カウンタは必要な構造を完全にエンコードします。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シーケンスが閉じ括弧で始まる場合です。 入力用`")("`、アルゴリズムは最初の文字で残高をすぐにゼロ未満に減らします。 開き括弧が表示されていないため、これは不可能な構造を反映しており、出力は正しくなります。`NO`。 

もう 1 つのケースは、左括弧と右括弧の合計数が等しいが、順序が無効である場合です。`"())("`。 残高は途中でゼロに戻りますが、その後ゼロを下回ります。 このアルゴリズムは、最終的なカウントに依存するのではなく、違反が発生した正確な時点で違反を検出します。 

3 番目のケースは、次のような左括弧のみの長いシーケンスです。`"((((("`。 残高がマイナスになることはありませんが、最後までプラスのままです。 これは、有効性にはプレフィックスの正確さと完全な一致の両方が必要であり、最後のゼロチェックがこの要件を満たしていることを示しています。
