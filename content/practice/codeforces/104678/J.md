 ## 解決策
 ## 問題の理解

 小文字で構成される 1 つの文字列が与えられ、結果として得られる 3 文字の部分列が単語「cat」と「ほぼ」同じになるように、昇順に 3 つの位置を選択できるかどうかを知りたいと考えています。 ここでの「ほぼ」とは、選択した 3 つの文字を「猫」と比較した場合、最大で 1 つの位置が異なっていてもよいことを意味します。 

したがって、「cat」と正確に一致する必要はありません。 必要なのは、2 つの位置がターゲット文字と一致し、3 番目の位置は何でもよい、長さ 3 のサブシーケンスだけです。 

出力は、有効なインデックスのトリプルか、そのようなトリプルが存在しない場合は -1 になります。 

文字列の長さは最大 200,000 であるため、トリプルの 3 次または 2 次の探索は即座に除外されます。 すべてを直接チェック$i < j < k$約必要になる$O(n^3)$実現可能な限界をはるかに超えた組み合わせです。 平$O(n^2)$このアプローチは、重い内部ロジックを使用して実装すると危険になるため、解決策は本質的に問題を線形または線形に近いスキャンに減らす必要があります。 

微妙な問題は、不一致が許可されていることです。 これにより、制約が大幅に弱められます。つまり、サブシーケンスとして「cat」を検索するのではなく、そのハミング距離 1 以内にあるサブシーケンスを検索します。 つまり、3 つの位置のいずれかが間違っている可能性はありますが、多くても 1 つだけであるということです。 

エッジケースは、文字列が非常に短い場合、または「c」、「a」、または「t」に似た文字がほとんど含まれない場合に発生します。 たとえば、「bbbbbb」のような文字列は明らかに有効なトリプルを生成できません。1 つの不一致を許容しても、構造化された方法で整列するには少なくとも 2 つの位置が必要ですが、多様性がなければ不可能だからです。 もう 1 つの微妙なケースは、文字が表示されるものの順序が正しくない場合です。 たとえば、「tac」にはすべての文字が逆順で含まれており、複数の文字セットが一致しても、増加するインデックス トリプルが条件を満たすことはできません。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルを列挙します。$i < j < k$間のハミング距離を計算します。$s[i]s[j]s[k]$そして「猫」。 トリプルの距離が最大 1 の場合、それを返します。 これは、考えられるすべての候補を明示的にチェックするため、正しいです。 問題はトリプルの数です。これは次のとおりです。$n^3 / 6$。 と$n = 2 \cdot 10^5$、これは天文学的に大きくなり、実行が間に合わなくなります。 

重要な観察は、実際には 3 つの立場すべてを同時に考慮する必要はないということです。 不一致が許容される位置は最大でも 1 つであるため、少なくとも 2 つの位置がターゲット文字と正確に一致する必要があります。 「猫」という単語には 3 文字しかないため、どの位置の誤りが許容されるかに応じて、有効な構造はいくつかの決定的なパターンに減ります。 

どのキャラクターが「無料」であるかを固定するという観点から考えることができます。 

1. 中央の文字が間違っている可能性があるため、次の形式の部分列が必要です。 t.
 2. 最初の文字が間違っている可能性があるため、? が必要です。 で。 
3. 最後の文字は間違っている可能性があるため、c a ? が必要です。 

それぞれの場合において、問題は、任意の間隔で順番に 2 つの固定文字を見つけることに帰着します。 これは古典的な 2 ポインターまたは次の発生の問題です。位置を事前に計算するか、貪欲にスキャンして、必要な文字の有効なインデックスを見つけます。 

すべてのトリプルを検索する代わりに、これら 3 つの構造パターンを試みます。 いずれかが成功した場合は、すぐに出力します。

 ## アルゴリズムのチュートリアル

 考えられる 3 つの「1 つ不一致の配置」をテストして、有効なトリプルを構築しようとします。 

1. 文字列を左から右にスキャンし、必要な各文字の候補インデックスを収集します。 

「c」、「a」、「t」の位置に注意します。 これにより、再スキャンせずに有効なインデックスにすばやくジャンプできます。 
2. パターン「c ? t」を試します。 

任意のインデックスを検索$i$どこ$s[i] = 'c'$、次に任意のインデックスを見つけます$k > i$どこ$s[k] = 't'$。 

両方が存在する場合は、いずれかのインデックスを選択してください$j$それらの間で厳密に (または任意の位置を再利用します。1 つの不一致は許容されるため、必要ありません)$s[j] = 'a'$）。 

これが機能する理由は、1 つの位置のみが逸脱できるためであり、ここでは正しいエンドポイントを強制しているためです。 
3. パターン「? a t」を試します。 

どれかを見つけてください$j$どこ$s[j] = 'a'$、次に見つけます$k > j$どこ$s[k] = 't'$、いずれかを選択します$i < j$。 
4. パターン「c a ?」を試してください。 

探す$i$「c」を付けると、$j > i$「a」を付けて、いずれかを選択します$k > j$。 
5. これらのパターンのいずれも形成できない場合は、-1 を出力します。 

それぞれの構築は貪欲です。実現可能性と簡素性を確保するために、私たちは常に可能な限り最も早い有効な立場を採用します。 

### なぜ効果があるのか

 有効な解決策は、最大でも 1 つの位置で「cat」と異なる必要があるため、少なくとも 2 つの位置が正確に一致する必要があります。 これにより、どの位置が一致していないかに応じて、解決策は上記の 3 つの構造ケースのいずれかに強制的に当てはまります。 このアルゴリズムは、不一致の位置についてあらゆる可能性を網羅し、それぞれの場合において、必要な順序付きサブシーケンスが存在するかどうかを貪欲にチェックします。 存在するだけで十分であり、構築によって秩序が保たれるため、有効な構成は少なくとも 1 つのケースで見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos_c = []
    pos_a = []
    pos_t = []

    for i, ch in enumerate(s):
        if ch == 'c':
            pos_c.append(i)
        elif ch == 'a':
            pos_a.append(i)
        elif ch == 't':
            pos_t.append(i)

    # case 1: c ? t
    if pos_c and pos_t:
        i = pos_c[0]
        k = None
        for x in pos_t:
            if x > i:
                k = x
                break
        if k is not None:
            # pick any j != i, k; must satisfy i < j < k if possible
            if k - i >= 2:
                j = i + 1
            else:
                j = i
            if j == i or j == k:
                # fallback: just choose any middle position
                for mid in range(i + 1, k):
                    j = mid
                    break
            print(i + 1, j + 1, k + 1)
            return

    # case 2: ? a t
    if pos_a and pos_t:
        j = pos_a[0]
        k = None
        for x in pos_t:
            if x > j:
                k = x
                break
        if k is not None:
            for i in range(0, j):
                print(i + 1, j + 1, k + 1)
                return

    # case 3: c a ?
    if pos_c and pos_a:
        i = pos_c[0]
        j = None
        for x in pos_a:
            if x > i:
                j = x
                break
        if j is not None:
            for k in range(j + 1, n):
                print(i + 1, j + 1, k + 1)
                return

    print(-1)

if __name__ == "__main__":
    solve()
```この実装では、関連する 3 つの文字の出現が分離されるため、繰り返しのスキャンが回避されます。 3 つの構造的な試みはそれぞれ独立して処理されます。 主な微妙な点は、インデックスの順序が確実に保持されるようにすることです。 私たちが次のようなペアを選ぶときはいつも$i, k$、明示的に保証します$i < k$次に、その範囲内で有効な中間インデックスを検索します。 

フォールバック ループは、制約によって最大 200,000 文字が保証されており、各ループはすべての場合において全体として線形時間でのみ実行されるため、安全です。

 ## 特殊なケース

 のような文字列`cat`は最小の陽性ケースです。 このアルゴリズムは、1 で c、2 で a、3 で t を即座に検出し、直接一致を生成します。 これにより、最小の有効な入力に対して特別な処理が必要ないことが確認されます。 

のような文字列`bbbbbbbb`故障モードを実行します。 必要な文字が存在しないため、3 つの構造化の試みはすべて即座に失敗し、アルゴリズムは -1 を出力します。 

みたいな逆転構造`tac`すべての文字が含まれていますが、順序が間違っています。 スキャンでは c、a、t が見つかりますが、順序制約に違反するものだけが出現するため、インデックスを強制的に増加させようとする試みはすべて失敗します。 アルゴリズムはそれを正しく拒否し、位置構造がなければマルチセットの存在が不十分であることを示しています。
