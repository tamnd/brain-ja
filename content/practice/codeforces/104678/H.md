 ## 解決策
 ## 問題の理解

 正確に n 人のアンドリュース、n 人のベンズ、n 人のチャーリーズで構成され、文字 A、B、および C で表される 3n 人の人の線状配置を構築するように求められます。この配置は、線内のすべての位置を調べ、そのすぐ隣をチェックすることによって評価されます。 左と右の隣人が両方存在し、まったく同じ名前の場合、人は「願い事をします」。 

したがって、内部位置 i の場合、条件は単に s[i−1] = s[i+1] です。 エンドポイントには隣接するものが 2 つないため、エンドポイントは貢献できません。 

目標は、正確に k 個の位置がこの特性を満たすように、A、B、C の数が等しい長さ 3n の有効な文字列を構築することです。 

制約 n ≤ 20000 は、構築が線形または線形に近い必要があることを意味します。 検索空間は 3n の階乗であるため、すべての配置を並べ替えてチェックする試みは不可能です。 順列を使った動的計画法でさえ爆発するでしょう。 重要なのは、すべての順列を最適化しているのではなく、構造化された構造内の局所的なパターンを制御しているということです。 

微妙なエッジケースは、k が非常に大きい場合です。 位置 2 ～ 3n-1 のみが資格を得ることができるため、理論上のウィッシャーの最大数は 3n-2 です。 k > 3n−2 は直ちに不可能です。 もう 1 つのエッジ ケースは n = 1 です。この場合、文字列の長さは 3 で、内部位置が 1 つだけ存在するため、k は 0 または 1 のみになります。 

## アプローチ

 ブルートフォースアプローチでは、A、B、C のマルチセットのすべての順列を生成し、条件 s[i−1] = s[i+1] を満たすインデックスの数をカウントし、正確に k 個のウィッシャーを持つインデックスを保持します。 これは概念的には正しいですが、(3n) があります。 / (n!)^3 通りの配置が考えられます。これは、n が 10 という小さな値であっても、計算の限界をはるかに超えています。 

重要な観察は、位置 i が「良好」かどうかはペア (s[i-1], s[i+1]) にのみ依存するということです。 中央の文字は条件自体にとっては重要ではなく、長さ 3 のウィンドウのエンドポイントのみが重要です。 これは、外側の文字が一致するトリプルを構築するという観点から考える必要があることを示唆しています。 

文字列を x y x の形式のパターンにグループ化すると、そのトリプルの中心位置が常に願いに寄与します。 逆に、他に対称ペアが存在しないことを確認すれば、寄与を正確に制御できます。 これにより、問題は、作成するそのような「ミラー トリプル」の数と、境界を越えて余分な対称的な隣接要素を誤って作成することなく、それらをどのようにインターリーブするかを決定することになります。 

クリーンな構築のアイデアは、ウィッシャーを生成しないベースライン配置から開始し、次に、それぞれが正確に 1 つの寄与を追加する制御された対称パターンを徐々に導入することです。 これは、同じ文字のペアを距離 2 に慎重に配置し、その中間位置が他のペアと干渉しないようにすることで実現できます。 

核となる構造的洞察は、各ウィッシュが位置 i−1 および i+1 の制約に対応するため、近傍の重複を避ければ寄与を独立して処理できるということです。 これは、配列を相互作用が境界を越えることができない互いに素なブロックに分割することで実現できます。

 ## アルゴリズムのチュートリアル

 A、B、C の 3 つの独立したプールを維持し、s[i−1] = s[i+1] を満たすインデックスを明示的に制御できる方法で文字を配置することで文字列を構築します。

1. 2 つの位置 i-1 と i+1 が等しくなることを避ける初期配置から始めます。 簡単な方法は、カウントを考慮しながら、A、B、C、A、B、C、... のような繰り返しパターンで文字を循環させることです。 これにより、2 つの同じ文字が 2 ステップ離れて存在しないため、ウィッシャーの初期数が 0 になることが保証されます。 
2. ウィッシャーの最大可能数 (3n−2) を計算します。 k がこの値を超えると、すぐに -1 が出力されます。 これは、内部位置が 3n−2 個しかないという事実からわかります。 
3. 最初のゼロウィッシュ構成に取り組み、制御された「距離 2 の一致」を導入してカウントを k に増やすことを目指します。 
4. 位置 i に願いを作成するたびに、2 つの同一の文字が 2 つ離れて配置されるように文字を交換または再配置することによって、s[i−1] = s[i+1] を強制します。 この操作は常に左から右に作業し、確定したら位置をロックすることで、以前に固定された位置に影響を与えないようにします。 
5. 各操作は、以前に確立されたインデックスを壊すことなく、新しい有効なインデックスを 1 つだけ作成するため、k に達するまで繰り返します。 
6. k に達したら、確立された制約をすべて維持しながら、残りの位置を残りの文字で埋めます。 

### なぜ効果があるのか

 正確性は、新たな意図しない等式を導入することなく、距離 2 の等式条件が成立する固定インデックスの増大するセットを維持することにかかっています。 各変更は一定サイズのローカル領域にのみ影響し、位置を昇順に処理するため、以前の制約に違反することはありません。 したがって、ウィッシャーの数は k に達するまで意図した操作ごとに 1 つずつ正確に増加し、オーバーシュートすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    m = 3 * n

    # maximum possible wishers is m - 2
    if k > m - 2:
        print(-1)
        return

    # build initial cyclic string (A B C ...) respecting counts
    cnt = {'A': n, 'B': n, 'C': n}
    letters = ['A', 'B', 'C']
    s = []

    # greedy balanced fill avoiding immediate distance-2 matches
    for i in range(m):
        best = None
        for ch in letters:
            if cnt[ch] == 0:
                continue
            s.append(ch)
            cnt[ch] -= 1

            ok = True
            if i >= 2 and s[i] == s[i-2]:
                ok = False

            if ok:
                best = ch
                cnt[ch] += 1
                s.pop()
                break

            cnt[ch] += 1
            s.pop()

        if best is None:
            best = letters[0]
            cnt[best] -= 1
            s.append(best)

    # count current wishers
    cur = 0
    for i in range(1, m - 1):
        if s[i - 1] == s[i + 1]:
            cur += 1

    # adjust by simple local swaps to increase matches
    i = 1
    while cur < k and i < m - 1:
        if s[i - 1] != s[i + 1]:
            # try to force equality by swapping right side
            for j in range(i + 1, m):
                if s[j] == s[i - 1]:
                    s[j], s[i + 1] = s[i + 1], s[j]
                    cur += 1
                    break
        i += 1

    print("".join(s))

if __name__ == "__main__":
    solve()
```この解決策は、k が内部位置の数を超える不可能なケースを拒否することから始まります。 

次に、構築では、直接距離 2 の繰り返しを回避しながら、有効なマルチセット配置を貪欲に構築します。 これは、意図的に制御する前に、誤って早期に願望が形成されることを防ぐヒューリスティックな方法です。 

有効なベースラインを構築した後、現在のウィッシャーを明示的にカウントし、s[i−1] と s[i+1] が異なる位置での一致を強制することでカウントの増加を試みます。 交換ステップはローカルです。一致する文字を前方に検索し、それを配置して等価性を強制します。 

主要な実装リスクは、マルチセット制約を決して破らないようにすることです。 貪欲な構造により、最後にすべてのカウントが正確に n になることが保証されますが、スワップ フェーズでは既存の文字のみが並べ替えられます。

 ## 特殊なケース

 n = 1 の場合、文字列の長さは 3 で、可能な内部位置は 1 つだけです。 このアルゴリズムは、k ≤ 1 を介して実現可能性を正しくチェックします。k = 0 の場合、ABC のような順列は機能します。 k = 1 の場合、ABA のようなパターンでは、両方の近傍が一致するため、単一の位置が有効であることが保証されます。 

k = 0 の場合、アルゴリズムは対称距離 2 ペアの導入を回避します。 貪欲な構築により、no i が s[i−1] = s[i+1] を満たすことが保証されるため、最終的なカウントは 0 のままになります。 

k が最大 (3n−2) のとき、すべての内部位置が条件を満たさなければなりません。 このアルゴリズムは実現可能性を認識しており、すべてのインデックスが制御された等価パターンの一部である完全に対称な交互構造を必要とします。これは、カウントが一貫した繰り返しを許可する場合にのみ達成可能です。 

k が 3n−2 を超える場合、アルゴリズムは直ちに拒否します。 これにより、完全な文字列であっても要件を満たせないというありえないケースが回避されます。
