 ## 解決策
 ## 問題の理解

 段階的に成長するツリーが与えられます。ツリーは頂点 1 から始まり、後続の各頂点がツリー内の既存の頂点に接続されます。 挿入ごとに、ツリーに **正確に 2 つの重心**を持たせるために頂点をいくつ追加する必要があるかを尋ねられます。 重心とは、頂点を削除すると、合計ノードの半分を超える接続コンポーネントが残らない頂点です。 

入力は、新しい頂点ごとに一連の親ポインターを提供し、出力は、各挿入後に 2 重心プロパティに到達するために必要な追加頂点の最小数です。 

主な制約は、ノード数が 500,000 に達する可能性があること、および最大 10,000 のテスト ケースが存在できることです。 これは、二次演算は実行可能な時間制限を超えるため、どのアプローチもほぼ **総ノード数で線形**でなければならないことを意味します。 ツリーは動的であるため、挿入のたびにサブツリーのサイズを最初から再計算する単純なアプローチでは遅すぎます。 

単純な実装でつまずく可能性のあるエッジ ケースには、すでに中央に配置されているツリー (たとえば、長さ 2 または 3 のチェーン) や、一方の側が他方よりもはるかに速く成長するツリーが含まれます。 このような場合、サブツリーのサイズを効率的に追跡しなければ、必要な追加ノードの数は明らかではありません。 

たとえば、最初の 3 つのノードがチェーンを形成している場合、`1 - 2 - 3`、ノード 3 を挿入すると、重心はすでに`2`ただし、ノード 4 がノード 3 に接続されている場合は、`1 - 2 - 3 - 4`次に、2 つの重心を取得するには、ツリーのバランスをとるために 1 つのノードを追加する必要があります。 「最も重いパス」を追跡しない単純なアルゴリズムでは、これが誤って計算されてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、挿入のたびに各サブツリーのサイズが再計算され、重心がチェックされます。 の木のために`n`ノードでは、DFS 経由でサブツリー サイズを計算します。`O(n)`クエリごとに、`O(n^2)`最悪の場合の合計時間。 と`n = 5e5`、これでは遅すぎます。 

重要な洞察は、**ツリーには最大 2 つの重心**があり、重心構造は現在の重心を接続するパスに沿って安定しているということです。 各クエリについて、重心の位置に影響を与える可能性があるツリーの唯一の部分は、新しいノードから既存の重心までのパスです。 したがって、すべてを再計算する必要はありません。必要なのは、**端点を接続する直径のようなパス**を追跡し、そのパスに沿った 2 つの重心を維持することだけです。 ノードを追加すると、最長の分岐が効果的に延長され、操作の数はツリーの 2 つの部分の間の不均衡によって決まります。 

重心候補から最も遠いノードとその深さを追跡することで、ツリーに正確に 2 つの重心を持たせるために必要な最小加算数を計算できます。 これにより、複雑さが軽減されます。`O(1)`深さ情報を維持した後、クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点を使用してツリーを初期化します。 1. 配列を維持します。`depth`頂点 1 からの各ノードの深さ、および`max_depth`現在の「直径端」を追跡します。 
2. 新しい頂点ごとに、入力からその親を記録し、その深さを次のように設定します。`depth[parent] + 1`。 
3. 2 つの特別なノードを維持します。`a`そして`b`、これは重心または直径パスの終点の現在の候補です。 当初は、`a = b = 1`。 
4. 新しいノードが追加された場合:

 - 新しいノードからノードまでの距離を計算します。`a`そして`b`深さを利用して。 
- 新しいノードがノードからの距離を増加させた場合`a`または`b`、 アップデート`a`または`b`それに応じて。 これにより、ツリー内の「最長パス」が維持されます。 
5. 2 つの重心を達成するための最小加算数は次のとおりです。`max(0, (dist(a, b) - 1) // 2 - 1)`。 この公式は、パスの長さが次のとおりであるという事実から来ています。`L`には中央に 2 つの重心があり、2 より長いパスにはバランスを取るために追加のノードを挿入する必要があります。 
6. この結果を各クエリの出力に追加します。 

**機能する理由**: ツリーの重心は常に、最も遠い 2 つのノード間の最長パス上にあります。 直径の端を追跡することにより、潜在的な重心を暗黙的に追跡します。 更新中`a`そして`b`これにより、ツリー内の最大の不均衡が常にわかり、これによって 2 番目の重心を導入するために必要な追加のノードの数が決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        depth = [0] * (n + 1)
        a = b = 1  # current ends of the diameter
        res = []

        for i in range(n - 1):
            u = i + 2
            parent = p[i]
            depth[u] = depth[parent] + 1

            da = depth[u] - depth[a]
            db = depth[u] - depth[b]

            if da > db:
                if da > depth[b] - depth[a]:
                    b = u
            else:
                if db > depth[a] - depth[b]:
                    a = u

            dist = depth[a] + depth[b] - 2 * depth[1]
            ops = max(0, (dist - 1) // 2)
            res.append(ops)

        print(' '.join(map(str, res)))

if __name__ == "__main__":
    solve()
```コードは各ノードの深さを追跡して、現在の直径を効率的に維持します。 への更新`a`そして`b`アンバランスを定義する四肢を維持します。 直径の長さから操作の数を計算すると、2 つの重心に必要な挿入の最小数が常にわかります。 

微妙な点としては、1 からのインデックス付け、慎重な深さの計算、新しいノードがパスを延長する場合にのみ直径の端を正しく更新することが挙げられます。
