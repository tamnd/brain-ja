 ## 問題の理解

 テストケースごとに配列を構築するように求められます。配列の長さは指定された整数に固定されています。$n$。 各ポジション$i$配列には、次の倍数の値が含まれている必要があります。$i$、すべての値は 1000 までの小さな固定範囲内に収まる必要があります。追加のグローバル条件が 1 つあります。すべての要素を合計する場合、その合計は次で割り切れる必要があります。$n$。 

したがって、構造はインデックスごとのローカルな可分性と、合計に対するグローバルな可分性の制約を加えたものになります。 

制約は小さいです。$n \le 200$最大 200 のテスト ケース。 これにより、線形または線形に近い構築を超えて、テスト ケースごとにコストがかかるものは直ちに除外されます。 位置ごとに最大 1000 の値を検索またはバックトラックしようとするアプローチは、最悪の場合のサイズでも合格しますが、建設的なパターンが存在するため、その必要はありません。 

それぞれを独立して設定しようとすると、素朴な考えによる微妙な失敗例が現れます。$a_i = i$。 これは割り算条件を満たしますが、合計は次のようになります。$\frac{n(n+1)}{2}$、常に割り切れるわけではありません$n$。 たとえば、次のようなとき$n = 3$、合計は 6 で機能しますが、$n = 4$、合計は 10 ですが、10 は 4 で割り切れないため失敗します。これは、ローカルな正確性がグローバルな正確性を保証しないことを示しています。 

もう 1 つの潜在的な落とし穴は、合計を修正するために最後に 1 つの要素だけを調整することです。 割り切りを修正するために 1 つの位置を変更すると、そのインデックスによって必要な割り切りが崩れることがよくあります。 

## アプローチ

 ブルートフォース戦略は、それぞれに割り当てを行うことです。$a_i$の倍数として$i$範囲内で$[i, 1000]$、合計が で割り切れるまで組み合わせを試します。$n$。 それぞれを制限しても$a_i$単一の複数のようなものに$i \cdot k$の場合、検索空間は指数関数的に増加します。$n$、各位置は独立して変化する可能性があるためです。 それでも$n \le 200$、最大 1000/i の分岐係数により、これは実行不可能になります。 

重要な観察は、実際には立場ごとの独立した自由は必要ないということです。 総和モジュロの制御のみが必要です$n$。 つまり、基本的な有効な配列を構築し、制御された方法で合計を変更しながら、インデックスごとの割り算を維持する方法で値を調整する必要があります。 

シンプルなベース構造を設定するのは、$a_i = i$みんなのために$i$。 これにより、割り算の制約が保証されますが、合計は固定されます。 唯一欠けている要件は、合計を次で割り切れるようにすることです。$n$。 

ここで、1 つの値を置き換えると、$a_n$、それでも割り切れる必要があります$n$、したがって、それは次の形式でなければなりません$n \cdot k$。 これは変化することを意味します$a_n$合計を次の倍数でシフトできます$n$、これは総和モジュロの割り算には影響しません。$n$。 したがって、別のピボットが必要です。1 つの位置だけを固定するのではなく、すべての位置にわたって対称的な調整を構築し、それぞれが有効なままになるようにします。 

より堅牢な構造は、すべての$a_i$の倍数として$i$それは、具体的には共有乗数に依存します$a_i = i \cdot k_i$、私たちが選択する場所$k_i$和を割り切れるようにする$n$。 それぞれなので$a_i \le 1000$、$k_i$小さいです。 

この問題に対する標準的な方法はさらに簡単です。すべてを設定します。$a_i = i \cdot n$。 これは次のような割り算を自明に満たします。$i$、合計は次のようになります。$$\sum a_i = n \sum_{i=1}^{n} i = n \cdot \frac{n(n+1)}{2}$$これは明確に割り切れます$n$。 

したがって、両方の制約は調整なしですぐに満たされます。

 ## アルゴリズムのチュートリアル

 固定の式を使用して、テスト ケースごとに配列を直接構築します。 

1. の値を読み取ります。$n$。 これにより、配列の長さと構築に使用されるスケーリング係数の両方が決まります。 
2. インデックスごとに$i$1から$n$、計算する$a_i = i \cdot n$。 これにより、$a_i$で割り切れます$i$なぜなら$a_i / i = n$、整数。

 重要な不変条件は、すべての要素が次のように構築されるということです。$a_i = i \cdot n$、これにより、ローカルの可算性が保証されます。$i$。 合計は次のようになります$n \cdot \sum i$を因数分解します$n$完全に、グローバルな可分性を確保します。 両方の制約は検索ではなく代数構造によって決定論的に満たされるため、無効な中間状態やエッジ ケースが正確さを破るリスクはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

    n = int(input())
    res = []

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        res = [str(i * n) for i in range(1, n + 1)]
        out.append(" ".join(res))
    return "\n".join(out)
