 ## 解決策
 ## 問題の理解

 特定の整数の配列のすべての部分配列について「美しさ」の尺度を計算するように求められます。 配列は最大 300,000 要素まで大きくすることができ、すべてのテスト ケースの合計は同じ数で制限されます。 各サブ配列の利点は、特定の操作を使用して並べ替えるのに必要な時間が最小限であることです。連続した範囲を選択して並べ替える場合、操作にかかる時間は範囲の長さから 1 を引いた長さに比例します。 単一要素の部分配列はすでにソートされているため、その美しさはゼロです。 

制約を考慮すると、すべての部分配列をブルートフォースでソートすることは不可能です。 潜在的にあります$O(n^2)$サブ配列があり、それぞれのソートには直線的な時間がかかる可能性があり、$O(n^3)$合計で。 と$n$3·10^5 までは、これでは遅すぎます。 美しさを効率的に計算するには、配列のプロパティと並べ替え操作を利用する必要があります。 

重要な観察は、問題は要素間の相対的な位置にのみ依存するということです。 配列には個別の整数が含まれるため、増加するシーケンスや反転を追跡できます。 エッジ ケースには、厳密に増加している配列、厳密に減少している配列、または単一の反転がある配列が含まれます。厳密に増加している部分配列では、美しさは常に 0 です。 長さ 2 の厳密に減少する部分配列では、美しさは 1 です。 サブ配列のソートには常にその長さから 1 を引いたコストがかかると想定する不用意なアプローチは、大幅にオーバーカウントすることになります。 

## アプローチ

 素朴なアプローチは、すべての部分配列を生成し、それぞれを並べ替えて、その美しさを直接計算することです。 長さの部分配列ごとに$k$、必要になります$O(k)$最適な範囲ソート操作を見つけるのに時間がかかります。これは完全にソートするのと同じです。 と$O(n^2)$部分配列、これはおおよそ次のようになります$O(n^3)$最悪の場合の運用。 これは大規模な場合はすぐに失敗します$n$。 

この画期的な進歩は、範囲ソート操作を明示的に実行する必要がないことに気づいたことから生まれました。 最小の美しさは、各部分配列内の最大要素と最小要素の位置によって決まります。 具体的には、長さが 1 より大きい部分配列の場合、美しさは厳密に増加していない場合にのみゼロ以外になります。 各要素に対して次に大きい要素と前の大きい要素を事前計算することにより、すべての位置について増加シーケンスがどこまで伸びるかを決定できます。 モノトーン スタックを使用すると、要素ごとに、その要素が属する連続した「未ソート」セグメントの長さを追跡できます。 次に、すべてのセグメントからの寄与をカウントすることは、配列全体の線形パスになります。 

効果的に、最適なアプローチにより、問題は局所反転の追跡とサブ配列全体にわたるその寄与の計算に軽減されます。$O(n)$モノトーンスタックとプレフィックス合計を使用したテストケースごと。 部分配列を明示的に生成することは避けます。

 ## アルゴリズムのチュートリアル

 1. 配列がソートされている場合は、配列の各要素をそのランクにマップします。 このステップでは、任意の整数を連続した範囲に変換し、比較を簡素化します。 
2. 2 つの配列を初期化します。`next_greater`そして`prev_greater`、長さの$n$。 インデックスごとに$i$、`next_greater[i]`より大きな値を持つ右側に最も近いインデックスを格納し、`prev_greater[i]`より大きな値を持つ左に最も近いインデックスを格納します。 両方の配列にモノトーン スタックを使用して、線形時間で埋めるようにします。 これにより、要素が範囲ソートに効率的に参加できる境界が特定されます。 
3. 位置の各要素について$i$、計算によって「最初の反転」となる部分配列の数を決定します。$(i - prev_greater[i]) \cdot (next_greater[i] - i)$。 これは、要素がゼロ以外の美しさに寄与するすべてのサブ配列をカウントします。 
4. すべての要素の寄与を合計します。 最も近い大きい要素によって識別されるセグメントには範囲ソート操作が 1 回だけ必要になるため、各ユニットの寄与はその部分配列の最小コストに対応します。 
5. テスト ケースの合計を返します。 

機能する理由: ランクにマッピングすると、すべての比較が整数比較になります。 モノトーン スタックにより、要素ごとに、要素の存在によりサブ配列がゼロ以外の美しさを必要とする境界を効率的に見つけることができます。 次に大きい要素と前の大きい要素までの距離を乗算すると、すべての部分配列が 1 回だけカウントされます。 各サブ配列の最小ソート時間はその最大の反転によって正確に計算されるため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # Map values to ranks
        sorted_a = sorted(a)
        rank = {val: i for i, val in enumerate(sorted_a)}
        a = [rank[val] for val in a]
        
        # Compute prev_greater
        prev_greater = [-1] * n
        stack = []
        for i in range(n):
            while stack and a[stack[-1]] < a[i]:
                stack.pop()
            prev_greater[i] = stack[-1] if stack else -1
            stack.append(i)
        
        # Compute next_greater
        next_greater = [n] * n
        stack = []
        for i in range(n-1, -1, -1):
            while stack and a[stack[-1]] < a[i]:
                stack.pop()
            next_greater[i] = stack[-1] if stack else n
            stack.append(i)
        
        # Compute beauty sum
        total = 0
        for i in range(n):
            left = i - prev_greater[i]
            right = next_greater[i] - i
            total += left * right - 1
        print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、比較を簡素化するために、まず要素を並べ替えられたランクに変換します。 モノトーン スタックでは、左右に最も近い大きな要素が識別されます。 これにより、要素がソート操作を必要とするサブ配列に寄与する境界が提供されます。 式`(i - prev_greater[i]) * (next_greater[i] - i) - 1`Beauty が 0 以外の要素を含むすべての部分配列をカウントします。 1 を減算すると、単一要素のサブ配列がカウントされなくなります。
