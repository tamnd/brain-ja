 ## 解決策
 ## 問題の理解

 すべてのノードにすでに色が設定されているツリーと、各ノードに必要な最終色が与えられます。 1 から N までの範囲の任意の数でノードを再描画することができ、各再描画は 1 回の操作としてカウントされます。 目標は、最初の色をターゲットの色に変換することです。 

中間状態を含め、常に適用されるグローバル制限があります。ツリー内の隣接するノードは決して同じ色を共有してはなりません。 この制約は、最終構成だけでなく、単一の再描画操作の後にも適用されます。 

タスクは、このルールを尊重しながら目標のカラーリングに到達できるかどうかを判断し、可能であれば、再描画操作の数を最小限に抑えて 1 つの有効なシーケンスを出力することです。 

最大 100000 までの制約 N により、線形または線形に近い解が強制されます。 バックトラッキングを使用して再カラー状態をシミュレートしようとしたり、ノード順序のすべての順列を考慮したりする戦略は、N 個の要素の順列を並べ替えることさえ実行不可能であるため、すぐに失敗します。 

微妙な問題は、ノードの最終的な色が最初の色と異なる場合でも、再描画が早すぎると、初期の色を保持している隣接ノードと一時的に競合が発生する可能性があることです。 同様に、再ペイントするのが遅すぎると、すでに最終色に切り替わった隣の色と競合する可能性があります。 したがって、操作の順序が中心的な問題になります。 

小さな失敗例は、2 つの隣接するノードが色を交換したい場合に発生します。 

入力：```
2
1 2
2 1
1 2
```最初にノード 1 を再ペイントすると、ノード 1 は 2 になりますが、ノード 2 は 2 のままで、隣接関係に違反します。 最初にノード 2 を再ペイントすると、対称の競合が発生します。 正解は不可能です。 

これは、問題は変更するノードの選択ではなく、変更間の一貫した依存関係の順序を見つけることであることを示しています。 

## アプローチ

 ブルート フォース ビューでは、これを、初期色がターゲット色と異なるノードの色を変更する可能な順序をすべて試行するものとして扱います。 各順列について、ノードの色変更をシミュレートし、各ステップの後にエッジが単色にならないことを確認します。 これは制約を直接強制するため概念的には機能しますが、k! までのチェックが必要です。 ここで、k は変更するノードの数ですが、k が 20 付近であっても実行不可能になります。 

重要な点は、各ノードが近隣ノードとのみ対話し、各ノードが 1 回だけ再描画されることです。 これにより、問題は有効な依存関係の順序付けの構築に変わります。 ノード u をペイントできるかどうかは、近傍ノードが現在 u が受け取ろうとしている色と同じ色を持っているかどうかによってのみ決まります。 各隣接ノードはまだ初期状態にあるか、すでに最終状態にあるため、すべての競合は 2 つのノード間の方向の制約に帰着します。 

これにより、グローバル シーケンス検索を、色を変更する必要があるノード上の有向グラフに置き換えることができます。 エッジは、潜在的な色の衝突から派生した優先順位制約をエンコードします。 この有向グラフにサイクルが含まれている場合、有効な順序付けは存在しません。

 | ブルートフォース順列シミュレーション | O(k!・N) | O(N) | 遅すぎる |
 | 依存関係グラフ + トポロジカルソート | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 すでにターゲットと一致しているノードには触れる必要がないため、初期色がターゲット色と異なるノードのみに焦点を当てます。 

1. C[u] != T[u] であるノードの集合 S を特定します。 実際に再ペイントするノードはこれらのみです。 S の外側のノードは色 C[u] で永久に固定されたままになります。 
2. すべてのエッジ (u、v) について、プロセス中に保持される可能性のある色に応じて、1 つの端点の再描画が他の端点とどのように競合する可能性があるかを分析します。 次の 2 種類の競合が発生します。 

v の色が変更されず、C[v] が T[u] に等しい場合、v が変更されないまま u をペイントすることはできません。 v は決して変化しないため、問題全体が即座に不可能になります。 

v の色が変更される場合、最初の色または最後の色が T[u] または T[v] に一致するかどうかに応じて、v が u の前に来るか後ろに来る必要があるかを決定する必要があります。 
3. 次のルールを使用して、S のノード上に有向グラフを構築します。 

C[v] == T[u] の場合、v は u の前にペイントされなければなりません。そうしないと、v がすでに競合していると見られてしまうからです。 

T[v] == T[u] の場合、u は v の前にペイントされなければなりません。そうしないと、後で v がすでに T[u] を持っている u と競合することになります。 
4. すべての制約を構築した後、この有向グラフにサイクルがあるかどうかを確認します。 そうなった場合、有効な順序は存在しません。 
5. 非巡回の場合、S 内のノードの位相順序を計算します。 
6. ノードをその位相順序で再描画し、各ノードをそのターゲット カラー T[u] に直接設定することによって操作を出力します。 

それが機能する理由は、実行中の状態に関する不変式に依存します。 どの時点でも、未処理のノードはすべて初期の色のままであり、処理されたすべてのノードはすでに最終的な色になっています。 すべての有向エッジは、隣接するエッジが割り当てられている色と一致しないようにするために必要な条件を正確にエンコードします。 トポロジー的順序により、ノードが処理されるたびに、競合する可能性のあるすべての隣接ノードがすでに必要な状態 (すでに修正されているか、まだ変更されていない状態) にあることが保証され、プロセス中にエッジが無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    C = [0] + list(map(int, input().split()))
    T = [0] + list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    need = [False] * (n + 1)
    for i in range(1, n + 1):
        if C[i] != T[i]:
            need[i] = True

    # build directed constraints
    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for u in range(1, n + 1):
        for v in adj[u]:
            if not need[u] and not need[v]:
                continue
            # if v is fixed (not changed)
            if not need[v]:
                if C[v] == T[u] and need[u]:
                    print(-1)
                    return
                continue

            # v is in S
            if need[u]:
                if C[v] == T[u]:
                    g[v].append(u)
                    indeg[u] += 1
                if T[v] == T[u]:
                    g[u].append(v)
                    indeg[v] += 1

    # topo sort over nodes in need
    from collections import deque
    q = deque([i for i in range(1, n + 1) if need[i] and indeg[i] == 0])

    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    S = [i for i in range(1, n + 1) if need[i]]
    if len(order) != len(S):
        print(-1)
        return

    print(len(order), 1)
    for u in order:
        print(u, T[u])

if __name__ == "__main__":
    solve()
```他のすべては永続的な制約ソースとして機能するため、実装では最初に変更が必要なノードを分離します。 次に、各エッジをスキャンし、局所的な色の競合を指示された順序付けの制約に変換します。 各制約はグラフのエッジとしてエンコードされ、indegrees は各ノードが持つ前提条件の数を追跡します。 

トポロジカルソートは標準のカーンアルゴリズムです。 重要な点は、変更セットに含まれていないノードは決してグラフの一部ではないにもかかわらず、制約の検証に参加していることです。 早期に不可能性をチェックすることが重要です。そうしないと、固定された隣接色が既に競合する色を保持しているために決して満たされないものをスケジュールしようとすることになるからです。 

各出力操作では、ノードをそのターゲット カラーに直接設定します。これは、順序付けにより、その時点でそのカラーに等しい隣接ノードが存在しないことが保証されるため安全です。 

## 実用的な例

 中心ノードを中心としたツリー形状で複数の再カラーが必要な最初のサンプル構造を考えてみましょう。 このアルゴリズムはまず、初期色がターゲットと異なるすべてのノードをマークし、次にエッジに沿った制約を導き出します。 結果として得られる有向グラフは、固有の有効なシーケンスを強制します。 

簡略化されたトレース:

 | ステップ | 選択されたノード | 度数条件 | アクション |
 | --- | --- | --- | --- |
 | 1 | 任意の次数 0 ノード | 安全 | ターゲットに再ペイント |
 | 2 | 次に利用可能 | 安全 | 塗り直す |
 | 3 | 続ける | すべての制約が満たされています | 塗り直す |

 この実行からの重要な観察は、隣接ノードが競合状態にある間はノードが描画されないということです。そのような状況では、この順序付けを妨げる有向エッジが作成されるためです。 

不可能な場合:

 入力:```
2
1 2
2 1
1 2
```ここでは両方のノードが変更セット内にあります。 エッジは両方の制約を同時に引き起こします。各ノードは、他のノードがその前にあることを必要とします。 これにより、長さ 2 のサイクルが形成されます。 

| ノード | 制約 1 | 制約 2 |
 | --- | --- | --- |
 | 1 | 2 | より前でなければなりません 2 | 以降でなければなりません
 | 2 | 1 | より前でなければなりません 1 | より後でなければなりません

 トポロジー的な順序付けが存在しないため、アルゴリズムは正しく -1 を出力します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各エッジは最大 2 つの有向制約チェックに寄与し、トポロジカル ソートは各ノードとエッジを 1 回処理します。 
| スペース | O(N) | 隣接リストと度数配列は線形サイズの構造を格納します。 

制約により最大 100,000 ノードが許可されるため、線形の複雑さが必要になります。 グラフの構築とカーンのアルゴリズムはどちらも制限内で快適に実行されます。

 ## 特殊なケース

 2 ノードの直接スワップは、最もクリーンな障害モードです。 各ノードは、他のノードを同時に早めたり遅らせたりすることでサイクルを生成し、アルゴリズムは次数の不均衡を通じてこれを即座に検出します。 

もう 1 つの微妙なケースは、ノードが固定されている (C[u] = T[u]) がブロッカーとして機能する場合に発生します。 このようなノードはスケジュールされることはありませんが、それでも隣接ノードが特定の色を使用することを禁止できます。 早期の不可能性チェックにより、固定ノードがすでに隣接ノードのターゲットと一致する色を持っている場合、その固定色を邪魔にならないように移動することができないため、解決策が不可能であることが保証されます。 

大きなツリーでは、複数の依存関係チェーンが連動する可能性があります。 トポロジカルソートはこれを自然に処理し、どのようなサイクルでも、その規模や間接性に関係なく、処理後に非ゼロの次数をもつノードとして現れ、これが正しく不可能性をトリガーします。
