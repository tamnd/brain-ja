 ## 解決策
 ## 問題の理解

 各都市がノード、各道路が有向エッジである有向非巡回グラフが与えられます。 道路に沿って移動するにはコストがかかりますが、標準的な最短経路の問題とは異なり、各道路のコストは固定されていません。 代わりに、すべての道路には基本コストとマイナス 1、ゼロ、またはプラス 1 の日次変化率があります。 d 日に旅行した場合、エッジのコストは初期コストに料金を d 倍したものになります。 

旅行者は常に都市 1 から出発し、各クエリは、指定された間隔内の任意の日に目的地の都市 X に到着するかどうかを尋ねます。 移動は 1 日以内に完了する必要があり、パスのコストは、そのパスに沿った時間依存のエッジ コストの合計です。 都市 1 から目的地に到達する方法がない場合、答えは不可能です。 

したがって、各クエリは、ノード 1 から X までのすべてのパス、および範囲内のすべての日にわたって、cost(path, d) 形式の線形関数の最小可能値は何かを尋ねます。 

制約があるため、構造が重要になります。 グラフには最大 4000 個のノードと 4000 個のエッジがあるため、DAG 上のノードごとの動的プログラミングが実現できるほど十分に疎です。 ただし、クエリの数は最大 500,000 になる可能性があるため、クエリごとに最短パスを再計算するソリューションは直ちに不可能になります。 日数が 1e9 に達するため、1 日あたりの再計算さえ不可能です。 

重要な隠れた構造は、グラフが DAG であるということです。 これによりサイクルが削除され、すべてのパスが有限になり、ノードをトポロジカルな順序で処理できるようになります。 もう 1 つの重要な観察は、固定パスの場合、コストは日変数の一次関数であるということです。 この難しさは、指数関数的に多くのパスにわたって最小値をとらなければならないという事実から生じており、これは多くの線形関数にわたって最小値になります。 

単純な間違いは、最短パスが毎日またはクエリごとに個別に計算できると想定することです。 たとえば、クエリが 1 つだけで範囲が狭い場合、毎日最短パスを実行しようとするかもしれませんが、範囲が 1e9 までであることを考えるとこれは不可能です。 

もう 1 つの微妙な問題は、正当な理由なしにエンドポイントのみを評価することによって、ある区間の最小値が見つかると想定していることです。 これは、関数が適切な構造を備えた凹型または区分線形であることを最初に証明した場合にのみ機能しますが、DP 表現を導出しない限り、すぐには機能しません。 

## アプローチ

 強引な解釈は簡単です。 各クエリについて、間隔内の考えられるすべての日 d を考慮し、ノード 1 から X までの最短パスを実行し、その日を使用してエッジの重みが計算されます。 グラフは DAG であるため、トポロジー順序に対して動的プログラミングを使用して O(N + M) の最短パスを計算できます。 ただし、間隔の長さは最大 1e9 であるため、一日中繰り返すことは不可能です。 サンプリングを試みたとしても、最適パスにおける単調性の保証はありません。 

もう 1 つの強引な方法は、1 から X までのすべてのパスを列挙することです。各パスは d の線形関数を生成するため、クエリごとにすべての関数を評価します。 最悪の場合の DAG ではパスの数が指数関数的に増加するため、これは失敗します。 

重要な構造上の観察は、各パスが A・d + B の形式の一次関数に対応していることです。ここで、A はエッジ レートの合計、B はベース コストの合計です。 したがって、ノードの答えは一連のラインにわたる最小値になります。 これにより、問題は各ノードの線形関数のより低いエンベロープを維持することに変わります。 

グラフは DAG であるため、トポロジ順にノードを処理できます。 各ノードは、その先行ノードからラインを収集し、入力エッジに従ってそれらをシフトし、それらを独自のセットにマージします。 残りのタスクは、これらのライン セットを効率的に維持し、特定の x で最小限のクエリに答えることです。

ノードごとに少数のラインを最低限必要とするだけなので、凸包トリック構造が機能します。 各ノードは、傾きによってソートされたラインの下側の凸包を維持します。 日 d にクエリを実行すると、対数時間での最小値が得られます。 さらに、ノードが 4000 個しかないため、以前のノードからハルを明示的にマージする余裕があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 数日または経路にわたる総当たり攻撃 | 指数 | 指数 | 遅すぎる |
 | ノードごとの DAG DP + 凸包 | O((N + M) log M + Q log M) | O(NM) 最悪の場合の行 | 承認済み |

 ## アルゴリズムのチュートリアル

 DAG 構造を利用し、すべてのノードを、d 日をノード 1 からそのノードまでの最小移動コストにマップする関数を格納するものとして扱います。 

このような各関数は、さまざまなパスによってもたらされる線形関数の下限包絡線です。 

### ステップ

 1. ノードのトポロジー的順序を計算します。 これが必要なのは、すべてのエッジがこの順序で前進するため、ノードを処理するときに、そのすべての先行エッジがすでに終了しているためです。 
2. ノード 1 に設定された関数を、傾き 0、切片 0 の単一の直線として初期化します。これは、日付に関係なく、開始都市でのコストがゼロに相当します。 
3. 他のすべてのノードについて、候補行のセットを空として初期化します。 
4. トポロジ順にノードを移動します。 各ノード u について、基本コスト T と傾き r を持つすべての出力エッジ u → v を考慮します。 
5. A・d + B として表される u の包皮内の各行について、v の新しい行を (A + r)・d + (B + T) として作成します。 これは、エッジ u → v を通るパスの延長を表します。 
6. 生成されたこれらすべての行を v の一時リストに挿入します。複数の先行処理が多くの行に寄与する可能性があるため、v は候補行のマルチセットを収集します。 
7. v への貢献がすべて集まったら、凸包を最初から再構築します。 傾きによってラインを並べ替えてから、単調スタックを使用して下のエンベロープを構築し、決して最適ではないラインを削除します。 
8. すべてのノードを処理した後、各ノードは、終日にわたる最小コスト関数を表す凸包を格納します。 
9. 各クエリ (L、R、X) について、L と R で船体を評価し、最小値を取得します。 ノード X に行がない場合は出力できません。 

### なぜ効果があるのか

 ノード 1 からノード X までのすべてのパスは、d の一意の線形関数に対応します。 DAG 上の DP では、エッジに沿って短いパスを延長することで、このような関数がすべて 1 回だけ生成されることが保証されます。 各ノードでのハル構築では、支配的なラインが削除されますが、凸包構築では下部エンベロープが保存されるため、ある d に対して最適である可能性のあるラインは決して削除されません。 

したがって、各ノードの最終関数は、すべてのパス関数の正確な最小値になります。 この関数は線形関数の最小値であるため、区分的に線形で下に凹型であるため、どの区間でもその最小値は端点の 1 つで発生する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hull(lines):
    if not lines:
        return []
    lines.sort(key=lambda x: (x[0], x[1]))

    hull = []

    def bad(l1, l2, l3):
        # returns True if l2 is unnecessary
        a1, b1 = l1
        a2, b2 = l2
        a3, b3 = l3
        return (b3 - b1) * (a1 - a2) <= (b2 - b1) * (a1 - a3)

    for a, b in lines:
        hull.append((a, b))
        while len(hull) >= 3 and bad(hull[-3], hull[-2], hull[-1]):
            hull.pop(-2)

    return hull

def query(hull, x):
    if not hull:
        return None

    l, r = 0, len(hull) - 1
    best = float("inf")

    while l <= r:
        m = (l + r) // 2
        a, b = hull[m]
        best = min(best, a * x + b)

        # move toward better slope region
        if m + 1 < len(hull):
            a2, b2 = hull[m + 1]
            if a2 * x + b2 < a * x + b:
                l = m + 1
            else:
                r = m - 1
        else:
            r = m - 1

    return best

def main():
    N, M, Q = map(int, input().split())

    g = [[] for _ in range(N)]
    indeg = [0] * N

    for _ in range(M):
        u, v, t, r = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, t, r))
        indeg[v] += 1

    from collections import deque
    q = deque(i for i in range(N) if indeg[i] == 0)

    topo = []
    while q:
        u = q.popleft()
        topo.append(u)
        for v, t, r in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    hulls = [[] for _ in range(N)]
    hulls[0] = [(0, 0)]

    for u in topo:
        if not hulls[u]:
            continue
        for v, t, r in g[u]:
            tmp = []
            for a, b in hulls[u]:
                tmp.append((a + r, b + t))
            hulls[v].extend(tmp)

        for v, _, _ in g[u]:
            if hulls[v]:
                hulls[v] = build_hull(hulls[v])

    out = []
    for _ in range(Q):
        l, r, x = map(int, input().split())
        x -= 1
        h = hulls[x]
        if not h:
            out.append("sorry")
            continue
        out.append(str(min(query(h, l), query(h, r))))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は、トポロジー順序を構築することから始まります。これは、ノードを処理するときに、以前のノードを介してそのノードに到達するすべての方法がすでに考慮されていることを確認するために不可欠です。 

各ノードは、そこに到達する可能性のあるすべてのパスを表す線形関数のリストを維持します。 エッジをトラバースするとき、エッジの傾きと切片の寄与を追加することによって、ソース ノードからすべてのラインをシフトします。 これにより、すべてのパス コストが正しく伝播されます。 

船体の構築ステップが必要なのは、合流後は多くの路線が占有され、いつの日も最適な状態にならないためです。 単調スタックはこれらを効率的に削除します。 

最後に、各クエリは 2 つの境界日で船体を評価し、最小値を取ることによって回答されます。 

## 実用的な例

 ### 例 1

 ノード 3 が回線を受信するときにそれを追跡します。 

| ステップ | ノード | アクション | 保存された行 |
 | --- | --- | --- | --- |
 | 1 | 1 | 初期化 | (0,0) |
 | 2 | 1→2 | 伝播する | ノード 2 の行がシフトされる |
 | 3 | 2 | 船体を構築する | 最高のラインを維持します |
 | 4 | 2→4 | 伝播する | ノード 4 は行を取得します |
 | 5 | 3 | クエリ | エンドポイントを評価する |

 トレースは、線形関数がパスに沿ってどのように蓄積され、伝播後にのみフィルタリングされるかを示します。 

### 例 2

 ここでは、同じノード間に複数の平行エッジが存在します。 

| ステップ | ノード | アクション | 保存された行 |
 | --- | --- | --- | --- |
 | 1 | 1 | 初期化 | 複数の平行線 |
 | 2 | マージ | シフトを組み合わせる | 候補行多数 |
 | 3 | 船体 | 支配的なものを削除する | コンパクトな船体 |
 | 4 | クエリ | 評価 | ベストラインからの回答 |

 これは、重複したエッジは単に候補ラインを追加するだけであり、ハルの構築により冗長性が除去されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + M)・K + Q log K) | 各エッジはラインを伝播し、各ハル クエリは対数 |
 | スペース | O(N・K) | 各ノードは線形関数の凸包を格納します。 

ここで、K はドミナンス プルーニング後のノードあたりの有効ライン数を表します。これは、凸包圧縮と DAG 制約により実際には小さくなります。 N と M は最大 4000 であるため、これは制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    N, M, Q = map(int, sys.stdin.readline().split())
    g = [[] for _ in range(N)]
    indeg = [0] * N

    for _ in range(M):
        u, v, t, r = map(int, sys.stdin.readline().split())
        u -= 1
        v -= 1
        g[u].append((v, t, r))
        indeg[v] += 1

    q = deque(i for i in range(N) if indeg[i] == 0)
    topo = []
    while q:
        u = q.popleft()
        topo.append(u)
        for v, t, r in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    def build_hull(lines):
        if not lines:
            return []
        lines.sort(key=lambda x: (x[0], x[1]))
        hull = []
        def bad(l1, l2, l3):
            a1, b1 = l1
            a2, b2 = l2
            a3, b3 = l3
            return (b3 - b1) * (a1 - a2) <= (b2 - b1) * (a1 - a3)

        for a, b in lines:
            hull.append((a, b))
            while len(hull) >= 3 and bad(hull[-3], hull[-2], hull[-1]):
                hull.pop(-2)
        return hull

    def query(hull, x):
        if not hull:
            return None
        best = float("inf")
        for a, b in hull:
            best = min(best, a * x + b)
        return best

    hulls = [[] for _ in range(N)]
    hulls[0] = [(0, 0)]

    for u in topo:
        for v, t, r in g[u]:
            for a, b in hulls[u]:
                hulls[v].append((a + r, b + t))
        for v, _, _ in g[u]:
            if hulls[v]:
                hulls[v] = build_hull(hulls[v])

    def solve():
        out = []
        for line in inp.strip().splitlines()[1 + M + 1:]:
            L, R, X = map(int, line.split())
            X -= 1
            h = hulls[X]
            if not h:
                out.append("sorry")
            else:
                out.append(str(min(query(h, L), query(h, R))))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 到達不能な宛先は、伝播全体を通じてその船体が空のままであるため、自然に処理されます。 この場合、パスから導出された行はノードに到達しないため、クエリは正しく「不可能」を返します。 

平行なエッジは、複数の同一または類似の線を作成します。 ハルの構造により冗長なものが削除され、クエリ時間が膨らまないことが保証されます。 

負の傾きにより時間の経過とともにコストが減少する可能性がありますが、各パスが完全な線形関数として扱われ、そのようなすべての関数の最小値がハル内で正しく表現されるため、これは正しく処理されます。
