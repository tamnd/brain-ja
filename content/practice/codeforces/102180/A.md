 ## 解決策
 ## 問題の理解

 カティアは T シャツとジーンズの 2 種類の服を持っています。 彼女は荷物をまとめます`n`Tシャツや`m`彼女は旅行中にすでに 1 枚の T シャツと 1 枚の追加のジーンズを着用しています。 こうして彼女はトレーニングキャンプ中に、`n + 1`色々なTシャツと`m + 1`さまざまなジーンズをご用意しております。 

彼女は毎日、T シャツ 1 枚とジーンズ 1 本を選ばなければなりません。 同じ完全な衣装を 2 つの異なる日に登場させることはできません。 T シャツを別のジーンズに合わせて再利用することは許可されており、ジーンズに別の T シャツを合わせて再利用することも許可されています。 

入力には以下が含まれます`k`、キャンプ日数、続いて`n`そして`m`, スーツケースに詰め込まれたTシャツとジーンズの数。 印刷する必要があります`Yes`毎日違う完全な服を選ぶことができれば、そして`No`さもないと。 

重要な制約は、`k`と同じ大きさにすることができます`10^9`、 その間`n`そして`m`せいぜい`1000`。 これは、日数のシミュレーションが望ましくないことをすぐに示唆します。 1 日に一定の作業のみを実行するアルゴリズムであっても、最大 10 億回の反復が必要になる可能性があります。 一方、衣服の種類の数は十分に少ないため、個別の組み合わせの総数を直接計算できます。 

スーツケースに詰められた衣類のみをカウントするソリューションを欺くことができる境界例がいくつかあります。 例えば、`1 0 0`生産しなければならない`Yes`, なぜなら、カティアがすでに着ている服はキャンプ当日のみ利用できるからです。 のみを使用した解決策`n * m`誤って、可能性のある衣装がゼロになる可能性があります。 

入力`2 0 0`生産しなければならない`No`。 カティアは合計で T シャツ 1 枚とジーンズ 1 本しか持っていないため、完全な衣装は 1 つしかありません。 2日目も必ず同じことを繰り返すことになります。 

もう 1 つの有用な境界ケースは次のとおりです。`2 1 0`。 合計 2 枚の T シャツと 1 本のジーンズがあり、正確に 2 つの異なる服装が得られます。したがって、答えは次のとおりです。`Yes`。 間の区別`n`そして`n + 1`、との間`m`そして`m + 1`、必須です。 

## アプローチ

 直接的な総当たりソリューションでは、それぞれの服装を明示的に生成できます。`k`日を経過し、どのペアがすでに使用されているかを追跡します。 これは正しいです。生成されたすべてのペアは前の選択と比較してチェックでき、未使用のペアがなくなるとプロセスは正確に失敗します。 ただし、最悪の場合、最大の処理が必要になります。`10^9`日々。 平均的な一定時間の挿入と検索を行うハッシュ セットを使用したとしても、それは 1 秒のコンテスト制限に収まる量をはるかに超えています。 すべての新しい衣装を以前のすべての衣装と比較するバージョンはさらに悪く、`O(k^2)`比較。 

問題の構造により、衣装をまったく構築する必要がなくなります。 カティアがそうしたら`n + 1`Tシャツや`m + 1`ジーンズ、あらゆる T シャツをあらゆるジーンズと組み合わせることができます。 乗算原理は正確に次のことを与えます`(n + 1) * (m + 1)`独特の完全な衣装。 

要件は単に少なくとも`k`のためのさまざまな衣装`k`日々。 利用可能な組み合わせの数が少なくとも`k`、どれでも選択できます`k`異なるペア。 それより小さい場合は、そもそも明確な衣装が不足しているため、スケジュールは機能しません。 

ブルートフォースアプローチは、利用可能な組み合わせを明示的に探索するため機能しますが、日数が膨大になる可能性があるため失敗します。 考えられるペアの総数のみが重要であるという観察により、問題全体が 1 つの乗算と 1 つの比較に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) とセット、または O(k²) と直接比較 | O(k) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`k`、`n`、 そして`m`。 2 つの衣類カテゴリにはすでに着用されているアイテムが含まれるため、利用可能な数は次のとおりです。`n + 1`Tシャツや`m + 1`ジーンズ。 
2. コンピューティング`(n + 1) * (m + 1)`。 各 T シャツは各ジーンズと個別に組み合わせることができるため、これは個別の完全な衣装の数です。 
3. この数値を次と比較します。`k`。 少なくともそれであれば`k`、印刷`Yes`、選べるから`k`さまざまな組み合わせ。 それ以外の場合は、印刷します`No`、いくつかの衣装を繰り返す必要があるためです。 

乗算の背後にある推論は、ソリューションの中心的な不変条件です。特定の T シャツと特定のジーンズで構成されるすべてのペアは、まさに 1 つの完全な服装を表し、考えられるすべての完全な服装は、まさに 1 つのそのようなペアによって表されます。 

### なぜ効果があるのか

 あります`n + 1`可能なTシャツと`m + 1`可能なジーンズ。 各固定 T シャツには、正確に`m + 1`ジーンズの選択肢もあるので、`(n + 1) * (m + 1)`独特の完全な衣装。 有効なスケジュールが必要です`k`個別の衣装があり、そのようなスケジュールは、利用可能な衣装の数が少なくとも`k`。 アルゴリズムはこの条件を正確にチェックするため、次の値を返します。`Yes`まさに実現可能なケースに当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k, n, m = map(int, input().split())

outfits = (n + 1) * (m + 1)

print("Yes" if outfits >= k else "No")
```入力は 1 行で構成されているため、1 回の呼び出しで`input()`で十分です。 両方に 1 つ追加します`n`そして`m`なぜなら、カティアが旅行中に着ているTシャツとジーンズはキャンプでも利用できるからです。 

乗算は比較の前に実行されます。 Python の整数の精度は任意ですが、ここでの実際の積は最大でも`1001 * 1001`したがって、固定幅の整数型を使用する言語でも整数オーバーフローは問題になりません。 

比較には、`>=`、 ない`>`。 キャンプの日とまったく同じ数の異なる服装がある場合、毎日ユニークな服装を受け取ることができるため、答えは次のようになります。`Yes`。 

## 実用的な例

 最初のサンプルの入力は次のとおりです。`1 0 0`。 キャンプ 1 日は 1 日で、T シャツの梱包数は 0、ジーンズの梱包数は 0 です。 

|`k`|`n`|`m`| トータルTシャツ | トータルジーンズ | 個性的な衣装 | 決定 |

 | 1 | 0 | 0 | 1 | 1 | 1 |`1 >= 1`、はい |

 単一の衣装は、カティアがすでに持っている T シャツとジーンズで構成されています。 1日しかないので、衣装を繰り返す必要はありません。 

2 番目のサンプルの入力は次のとおりです。`2 0 0`。 

|`k`|`n`|`m`| トータルTシャツ | トータルジーンズ | 個性的な衣装 | 決定 |

 可能な完全な衣装は 1 つだけですが、2 日間では 2 つの異なる衣装が必要です。 2 日目は必然的に 1 日目の組み合わせを繰り返すことになります。 

3 番目のサンプルについては、`5 1 2`, カティアはTシャツを2枚、ジーンズを合計3本持っています。 

|`k`|`n`|`m`| トータルTシャツ | トータルジーンズ | 個性的な衣装 | 決定 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 5 | 1 | 2 | 2 | 3 | 6 |`6 >= 5`、はい |

 組み合わせは 6 通りあり、5 つの異なる衣装を選択できます。 1 つの組み合わせは未使用のままにすることができます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    k, n, m = map(int, input().split())
    return "Yes" if (n + 1) * (m + 1) >= k else "No"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("1 0 0\n") == "Yes", "sample 1"
assert run("2 0 0\n") == "No", "sample 2"
assert run("5 1 2\n") == "Yes", "sample 3"

# Minimum-size input
assert run("1 0 0\n") == "Yes", "one day, no packed clothes"

# Exact boundary: exactly enough combinations
assert run("4 1 1\n") == "Yes", "exactly four outfits are available"

# Just beyond the boundary
assert run("5 1 1\n") == "No", "only four outfits are available"

# Maximum values
assert run("1000000000 1000 1000\n") == "No", "maximum k exceeds all possible outfits"

# Maximum possible number of outfits
assert run("1002001 1000 1000\n") == "Yes", "exact maximum number of outfits"

# One clothing category has no packed items
assert run("3 2 0\n") == "Yes", "three shirts and one pair of jeans give three outfits"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 0 0`|`Yes`| 最小限の入力とすでに着用している衣装の貢献 |
 |`4 1 1`|`Yes`| 実現可能境界における完全な等価性 |
 |`5 1 1`|`No`| いつか境界線を越えて捕まえる`>`対`>=`間違い |
 |`1000000000 1000 1000`|`No`| 非常に大きい`k`日数をシミュレーションせずに |
 |`1002001 1000 1000`|`Yes`| 可能な組み合わせの最大数 |
 |`3 2 0`|`Yes`| 履き古したジーンズをそのまま利用できる、詰め込みゼロのジーンズ |

 ## 特殊なケース

 最初の非自明なケースは、`1 0 0`。 計算すると、`(0 + 1) * (0 + 1) = 1`、これは 1 日分で十分なので、アルゴリズムは次のように出力します。`Yes`。 梱包された衣服のみをカウントするソリューションでは、衣服が存在しないと誤って結論付けられてしまいます。 

2番目のケースは、`2 0 0`。 計算では、利用可能な衣装は 1 つだけ得られますが、2 つの異なる衣装が必要です。 以来`1 < 2`、アルゴリズムは出力します`No`。 衣装のどちらかの部分を変更する方法はありません。 

等価境界は次のように表されます。`4 1 1`。 T シャツ 2 枚とジーンズ 2 本があり、組み合わせは正確に 4 つあります。 比較は`4 >= 4`、したがって、答えは次のとおりです`Yes`。 これにより、厳密に数日よりも多くの衣装を誤って必要とする実装が捕捉されます。 

すぐには無理なケース`5 1 1`同じ 4 つの組み合わせが得られますが、5 日かかります。 比較は次のようになります`4 >= 5`これは false なので、アルゴリズムは次のように出力します。`No`。 これは、前のテストの自然な 1 つ違いのコンパニオンです。 

最後に考えてみましょう`1002001 1000 1000`。 がある`1001 * 1001 = 1002001`可能な服装、日数に正確に一致します。 アルゴリズムは一定時間でケースを受け入れ、個々の衣服の組み合わせを構築または保存する必要がない理由を示します。
