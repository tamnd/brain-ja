 ## 解決策
 ## 問題の理解

 カティアは、(n) 枚の T シャツを一定の順序で調べます。 各 T シャツにはモデル識別子 (a_i) が付いています。 初めて識別子を見たとき、彼女はその T シャツを購入します。 同じ識別子を持つそれ以降の T シャツはすべてスキップされます。 タスクは、(n) 個のバイナリ値の配列を生成することです。ここで、位置 (i) の T シャツがその識別子の最初の出現であるとき、位置 (i) には正確に (1) が含まれます。 

入力には、T シャツの数と、表示順序でのその識別子が含まれます。 識別子は (10^9) まで大きくなる可能性があるため、追加の仮定がなければ小さな配列インデックスとして扱うことはできません。 T シャツの数は最大 (5000) であり、これは一部の言語で二次関数の解を実現できるほど十分に小さいですが、意図した解は線形であり、同様に単純です。 

単純な実装では、各識別子を以前のすべての識別子と比較できます。 (n=5000) の場合、最悪の場合、およそ (n(n-1)/2 = 12{,}497{,}500) の比較が必要になる可能性があります。 その量は膨大ではありませんが、不必要であり、ハッシュ セットは直接的な一定平均時間のメンバーシップ テストを提供します。 

最初のエッジ ケースは、T シャツ 1 枚だけを含むシーケンスです。 入力用`1`に続く`7`、答えは`1`、これに一致する以前の出来事がないためです。 すべての答えをゼロに初期化し、重複を検出した後でのみ値をマークする実装では、誤ってゼロが生成されます。 

もう 1 つの特殊なケースは、識別子がすぐ隣り合って繰り返される場合です。 入力用`4`識別子付き`9 9 9 9`、正しい出力は次のとおりです。`1 0 0 0`。 最初`9`購入されると、その後のすべての`9`すでに遭遇しています。 前の要素とのみ比較する不用意な実装はここで機能する可能性がありますが、その推論は連続しない重複には不十分です。 

たとえば、入力の場合`5`と識別子`1 2 1 3 2`、正しい出力は次のとおりです。`1 1 0 1 0`。 3 番目の要素は最初の要素を繰り返し、5 番目の要素は 2 番目の要素を繰り返します。 直前の識別子のみをチェックするアプローチでは、3 番目と 5 番目の位置が誤って新規としてマークされてしまいます。 

識別子の値自体にも注意が必要です。 次のような入力`3`識別子付き`1 1000000000 1`生成する`1 1 0`。 値 (10^9) は完全に有効ですが、通常の整数として保存する必要があり、巨大な配列のインデックスとして使用しないでください。 

## アプローチ

 直接的なブルート フォース ソリューションは、文字通り定義に従います。 各 T シャツについて、その前のすべての位置をスキャンし、その識別子がすでに表示されているかどうかを確認します。 等しい識別子が見つからない場合は、出力します。`1`; それ以外の場合は出力`0`。 これは正しいです。識別子は、前の位置に等しい識別子がない場合にのみ新しいものであるためです。 

このアプローチの問題は、検索が繰り返されることです。 最後の T シャツについては、(n-1) 個の以前の位置をすべて検査し、前の位置については (n-2) までなどと検査します。 最悪の場合、比較の総数は次のようになります。 

[
 0+1+2+\dots+(n-1)=\frac{n(n-1)}2.
 ]

 (n=5000) の場合、これは (12{,}497{,}500) の比較になります。 寛大な実装と時間制限の下ではまだ許容可能ですが、二次関数であり、意図した方法と同じ堅牢性で拡張できません。 

重要な観察は、過去から必要な唯一の情報は、どの識別子がすでに出現したかであるということです。 前回の発生がどこであったか、何回発生したかは気にしません。 セットはまさにこの情報を表します。 (a_i) を処理するとき、セットのメンバーシップは「このモデルを以前に見たことがありますか?」という質問に答えます。 一定の平均時間で。 答えが「いいえ」の場合は、次のように出力します。`1`そしてすぐに識別子をセットに挿入します。 答えが「はい」の場合、次のように出力します。`0`。 

ブルートフォース手法が機能するのは、処理されたプレフィックス全体を検索して、これまでに確認された識別子のセットを再構築するためです。 このセットがプレフィックスの唯一の関連部分であるという観察により、それを明示的に維持し、スキャン全体を 1 つのハッシュ テーブル ルックアップに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(1)) おまけ | これらの制約は受け入れられますが、不必要に遅くなります。 
| 最適 | (O(n)) 平均 | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. という空のセットを作成します。`seen`。 現在の位置より前に検出されたすべてのモデル識別子が含まれます。 
2. 空の結果配列を作成します。 元の順序を維持したまま、各 T シャツに 1 つの値を正確に追加します。 
3. 識別子を左から右に処理します。 現在の識別子の場合`x`、まず次のことを確認してください。`x`すでに入っています`seen`。 このセットは、Katya が以前に遭遇した識別子を正確に表しているため、このメンバーシップ テストは、彼女が現在の T シャツを購入すべきかどうかに直接答えます。 
4. もし`x`入っていない`seen`、追加`1`結果に挿入してください`x`セットに。 その後同じモデルが出現すると重複として認識される必要があるため、挿入は直ちに行われる必要があります。 
5. もし`x`すでに入っています`seen`、追加`0`結果を反映し、セットを変更しないままにします。 同じモデルをもう一度見ても、新しい情報は得られません。 
6. すべて (n) 個の識別子が処理された後、結果をスペースで区切って出力します。 

### なぜ効果があるのか

 入力の接頭辞を処理した後、不変条件は次のとおりです。`seen`には、そのプレフィックス内に存在する個別の識別子が正確に含まれます。 最初はプレフィックスは空であるため、不変式が成り立ちます。 新しい識別子が処理されるとき、その識別子は存在しません。`seen`したがって、アルゴリズムは次のように出力します。`1`そして不変式を維持しながらそれを挿入します。 繰り返される識別子が処理されるとき、それはすでに存在しているため、アルゴリズムは次のように出力します。`0`セットを変更しないままにし、不変条件も保持します。 

その結果、すべての位置でアルゴリズムは次の出力を行います。`1`正確に、現在の識別子が以前に発生していないときです。 それはまさに必要な購入ルールです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set()
    answer = []

    for x in a:
        if x in seen:
            answer.append(0)
        else:
            answer.append(1)
            seen.add(x)

    print(*answer)

if __name__ == "__main__":
    solve()
```最初の 2 行は、`solve`T シャツの数と完全な識別子のシーケンスを読み取ります。 このステートメントでは、2 行目にすべて (n) 個の識別子が含まれることが保証されているため、単一の`split()`で十分です。 

の`seen`set はウォークスルーのステップ 1 に直接対応します。 ループ中に、挿入前にメンバーシップがチェックされます。 この順序が重要です。 コードが挿入された場合`x`メンバーシップを確認する前に、すべての識別子はすでに表示されているように見え、すべての答えは次のようになります。`0`。 

最初の出現は、`else`ブランチ、応答を受け取ります`1`、に追加されます`seen`。 その後の発生は`if`分岐して受け取る`0`。 アルゴリズムにはインデックス演算がないため、管理すべきオフバイ 1 境界はありません。 

Python の整数は (10^9) までの値を直接処理するため、最大識別子には特別な処理は必要ありません。 セットには最大 (n) 個の個別の整数が格納され、出力には正確に (n) 個の値が含まれます。 

この問題にはテスト ケースが 1 つしかないため、外側のテスト ケース ループはありません。`sys.stdin.readline`要求に応じて使用されますが、`print(*answer)`必要なスペース区切りの出力を生成します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) 平均 | 各識別子がチェックされ、最初に出現したものはハッシュ セットに挿入されます。 
| スペース | (O(n)) | セットには最大 (n) 個の個別の識別子を含めることができ、出力には (n) 個の値も含まれます。 

(n\le 5000) を使用すると、線形解では数千回のハッシュ テーブル操作のみが実行されます。 メモリ使用量も 256 MB の制限に比べて小さいです。 (10^9) の識別子の境界は複雑さに影響しません。これは、Python が各識別子を整数値でインデックス付けされた配列を割り当てるのではなく、整数値として格納するためです。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    seen = set()
    answer = []

    for x in a:
        if x in seen:
            answer.append(0)
        else:
            answer.append(1)
            seen.add(x)

    print(*answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run("3\n1 2 3\n") == "1 1 1", "sample 1"

# Provided sample 2
assert run("5\n1 2 1 2 3\n") == "1 1 0 0 1", "sample 2"

# Provided sample 3
assert run("4\n9 9 9 9\n") == "1 0 0 0", "sample 3"

# Minimum-size input
assert run("1\n42\n") == "1", "single T-shirt"

# Maximum-size input, all identifiers distinct
n = 5000
maximum_distinct = list(range(1, n + 1))
expected = " ".join(["1"] * n)
assert run(f"{n}\n{' '.join(map(str, maximum_distinct))}\n") == expected, \
    "maximum-size distinct input"

# Maximum identifier value and non-consecutive duplicates
assert run("6\n1000000000 1 2 1000000000 2 1\n") == "1 1 1 0 0 0", \
    "identifier boundary"

# Duplicates separated by other identifiers
assert run("7\n5 8 5 9 8 10 5\n") == "1 1 0 1 0 1 0", \
    "non-consecutive duplicates"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 42`|`1`| 最小サイズの入力と最初の出現の処理 |
 |`5000 / 1 2 ... 5000`| 5000 個 | 最大値 (n) とすべての識別子は区別されます |
 |`6 / 1000000000 1 2 1000000000 2 1`|`1 1 1 0 0 0`| 識別子の最大値と反復モデル |
 |`7 / 5 8 5 9 8 10 5`|`1 1 0 1 0 1 0`| 他のいくつかの識別子で区切られた重複 |
