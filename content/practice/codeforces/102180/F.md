 ## 解決策
 ## 問題の理解

 (n) 個の島があり、最初はすべての島に住民がいます。 いくつかの報告では、2 つの島の間に方向のない橋が追加されています。 他の報告では、島 (u) で洪水が発生し、その後、現在 (u) に住んでいるすべての住民が島 (v) に移住すると説明しています。 島 (u) 自体は削除されないため、島に付随する橋は引き続き使用できます。 

報告が出るたびに、現在人が住んでいるすべての島に陸路で相互に到達できるようにするために、最小限の数の新しい橋が必要です。 既存の橋を再利用したり、任意の島間に新たな橋を架けたりすることができます。 

すべてのブリッジによって形成されるグラフを考えてみましょう。 正確に (c) 接続コンポーネントに少なくとも 1 人の住民が含まれていると仮定します。 追加のブリッジを 1 つ追加すると、そのような 2 つのコンポーネントをマージでき、(c-1) ブリッジは常にそれらすべてを接続するのに十分です。 したがって、問題全体は、現在少なくとも 1 人の住民を含む接続コンポーネントの数を維持することに帰着します。 

この制約が、グラフの直接走査が不適切な主な理由です。 最大 (3\cdot10^5) 個のアイランドと (3\cdot10^5) 個のレポートを使用すると、すべての操作後に接続コンポーネントを再計算するには (O(nq)) 作業、最悪の場合はおよそ (9\cdot10^{10}) 個の頂点操作が必要になる可能性があります。 レポートごとの 1 回の走査でも、1 秒の制限がサポートできる範囲をはるかに超えています。 各レポートはほぼ一定の償却時間内で処理される必要があります。 

最初の微妙なケースは、島がグラフから消えることなく空になる可能性があることです。 例えば、```
2 1
2 1 2
```報告後の有人島は島 2 だけなので、答えは次のようになります。`0`。 グラフから島 1 を物理的に削除する解決策は、島 1 に再び人が住む可能性があるため、後の橋の操作が面倒になったり、不正確になったりする可能性があります。 

2 番目の微妙なケースは、同じ接続コンポーネントに既に属している 2 つの島間で住民を移動させる場合です。 例えば、```
3 2
1 1 2
2 1 2
```最初のレポートの後、アイランド 1 と 2 は 1 つのコンポーネントを形成し、アイランド 3 は分離されます。 洪水の後、島 1 の住民はすべて島 2 に移動しますが、コンポーネント構成は変わりません。 人が住んでいるコンポーネントはまだ残っています`{1,2}`そして`{3}`、したがって、答えは次のとおりです`1 1`。 すべての洪水を 1 つの居住コンポーネントを削除するものとして扱う不注意な実装では、誤って生成される可能性があります。`1 0`。 

3 番目のケースは、洪水の前に島に人がいない場合に発生します。 例えば、```
3 2
2 1 2
2 1 3
```最初のレポートの後、島 1 には何もなく、島 2 には住民がいます。 2回目の洪水では何も動かないので、状態は変わりません。 正しい答えは次のとおりです`1 1`。 実装では、コンポーネントの数をやみくもに変更するのではなく、ソースの住民の数を検査する必要があります。 

4 番目のケースは、ブリッジが 2 つのコンポーネントを結合し、そのうちの 1 つが空である場合に発生します。 例えば、```
3 2
2 1 2
1 1 3
```洪水の後、人が住んでいるのは島 2 だけです。 アイランド 1 と 3 の間のブリッジは 2 つの空の頂点を結合しますが、居住するコンポーネントの数には影響しません。 答えは次のとおりです。`1 1`。 住民を含むコンポーネントだけをカウントするのではなく、すべてのグラフ コンポーネントをカウントするソリューションは、ここでは失敗します。 

## アプローチ

 簡単な解決策は、グラフを明示的に維持し、レポートごとに、現在居住しているすべての島から DFS または BFS を実行して、接続されたコンポーネントの数に居住者が含まれているかを判断します。 グラフ トラバーサルでは重要な接続性が直接計算されるため、これは正しいです。 

問題は繰り返し作業です。 (n) 個の頂点と最大 (q) 個の追加エッジを持つグラフには、(O(n+q)) 個の保存されたエッジを持つことができます。 (q) 個の各レポートの後に完全な走査を実行すると、(O(q(n+q)))、つまり (O(q^2+nq)) かかることがあります。 (n) と (q) が両方とも (3\cdot10^5) に等しい場合、これは (9\cdot10^{10}) 回の演算か、それよりも悪い演算のオーダーになります。 

ブルート フォース ソリューションは、正確なグラフの状態を最初から再計算するため機能します。 ブリッジは追加されるだけで削除されないため、失敗します。 この単調な構造は、ブリッジ レポートのたびに接続を再検出する必要がないことを意味します。 

Disjoint Set Union 構造はまさにこの状況に適しています。 (u) と (v) の間のすべてのブリッジは、単純に 2 つの DSU セットをマージします。 DSU は、ほぼ一定の償却時間で、どのアイランドの接続コンポーネントも提供します。 

私たちは依然として洪水への対応が必要です。 重要な観察は、住民がグラフの接続性に影響を与えないということです。 洪水は、どの頂点に住民がいるかを変えるだけです。 DSU コンポーネントごとに、現在その内部にある住民の総数を保存できます。 次に、(u) から (v) へのフラッドにより、(u) のコンポーネントの人口が削除され、それが (v) のコンポーネントに追加されます。 ソースコンポーネントが空になると、常駐コンポーネントの数が減少します。 宛先コンポーネントが空で住民を受け入れる場合、その数は増加します。 

これによりグローバルカウンターが得られます`active`、正の母集団を持つ DSU コンポーネントの数に等しい。 2 つの異なるコンポーネントを接続するブリッジにより、`active`両方のコンポーネントが存在するときにちょうど 1 つずつ増えます。 洪水が変化する`active`人口が異なるコンポーネント間で交差し、2 つのコンポーネントのいずれかが空と空でない間で変化する場合のみ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(q(n+q))) | (O(n+q)) | 遅すぎる |
 | 最適 | (O((n+q)\alpha(n))) | (O(n+q)) | 承認済み |

 ここで (\alpha(n)) は逆アッカーマン関数であり、これらの制約に実際に関連する定数を下回ります。 

## アルゴリズムのチュートリアル

 1. 最初はすべての島に住民が含まれているため、すべての島が居住者の DSU コンポーネントになります。 セット`population[i] = 1`島ごとに初期化する`active = n`。 したがって、レポート前の答えは (n-1) になります。 
2. ブリッジレポートの場合`1 u v`、の DSU ルートを見つけます。`u`そして`v`。 それらがすでに等しい場合、ブリッジは何も変更しません。 異なる場合は、2 つのコンポーネントをマージし、それらの母集団の合計を加算します。 両方のコンポーネントの人口が正の場合、2 つの居住コンポーネントは 1 つになるため、減少します。`active`1つずつ。 
3. 洪水レポートの場合`2 u v`、 読む`x = population[u]`。 もし`x`はゼロであり、誰も動かず、更新するものは何もありません。 このケースは、コンポーネントの合計を変更する前に処理する必要があります。 
4. もし`u`住民がいます。現在の DSU のルートを見つけます`ru`そして`rv`。 セット`population[u]`ゼロにして加算する`x`に`population[v]`。 
5. いつ`ru`そして`rv`異なる、差し引く`x`の人口合計から`ru`。 その合計がゼロになると、ソース コンポーネントには存在しなくなるため、値を減らします。`active`。 受信前に宛先コンポーネントの人口がゼロだった場合`x`、 増加`active`。 いつ`ru == rv`両方の操作は同じ常駐コンポーネント内で行われるため、`active`変わりません。 
6. レポートの処理後、印刷します。`active - 1`。 あれば`active`少なくとも接続されたコンポーネントが存在する`active - 1`それらを接続するには新しいブリッジが必要ですが、ツリー内のコンポーネントを結合することで多くのブリッジで十分です。 

中心的な不変条件は次のとおりです`population[root]`次のように表される DSU コンポーネント全体の住民の総数を格納します。`root`、 そして`active`母集団が正であるルートを正確にカウントします。 ブリッジ操作では、母集団の合計をマージすることでこの不変条件が維持されます。 フラッド操作では、適切なコンポーネント合計の間でソース人口を移動することにより、人口を維持します。 (c) 空でないコンポーネントに必要な追加ブリッジの最小数は正確に (c-1) であるため、`active - 1`は常に必須の答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    parent = list(range(n))
    size = [1] * n
    population = [1] * n

    active = n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    out = []

    for _ in range(q):
        t, u, v = map(int, input().split())
        u -= 1
        v -= 1

        if t == 1:
            ru = find(u)
            rv = find(v)

            if ru != rv:
                if size[ru] < size[rv]:
                    ru, rv = rv, ru

                if population[ru] > 0 and population[rv] > 0:
                    active -= 1

                parent[rv] = ru
                size[ru] += size[rv]
                population[ru] += population[rv]

        else:
            x = population[u]

            if x > 0:
                ru = find(u)
                rv = find(v)

                population[u] = 0

                if ru != rv:
                    population[ru] -= x

                    if population[ru] == 0:
                        active -= 1

                    if population[rv] == 0:
                        active += 1

                    population[rv] += x
                else:
                    population[ru] -= x
                    population[rv] += x

        out.append(str(active - 1))

    sys.stdout.write(" ".join(out))

if __name__ == "__main__":
    solve()
```の`parent`そして`size`配列は、パス圧縮とサイズによる結合を備えた DSU を実装します。 これらを組み合わせることで、接続されたコンポーネントの検索とマージにかかるほぼ一定の償却時間が保証されます。 

の`population`配列は、コンポーネントの合計を表すたびに、DSU ルートによってインデックスが付けられます。 結合後、古い子ルートはコンポーネントの代表として使用されなくなるため、その母集団の値が意味のあるままである必要はありません。 新しいルートは、両方のコンポーネント母集団の合計を受け取ります。 

洪水に対しては、`population[u]`現在物理的な島に存在する人口として意図的に解釈されます`u`、 その間`population[root]`コンポーネントの総人口を表します。 この区別は、実装の中で最もデリケートな部分です。 人口を移動させる前に、`x = population[u]`島の人口を捕らえます。 設定後`population[u] = 0`、コンポーネントの合計は個別に調整されます。 

いつ`ru == rv`、同じコンポーネントに同じ量を減算および加算しても、合計は変わりません。 明示的な分岐は、母集団が接続されたコンポーネントから離れることがない場合に、アクティブ コンポーネント カウンタが変更されるのを防ぐため便利です。 

入力頂点は、1 ベースのインデックス付けから 0 ベースのインデックス付けに即座に変換されます。 この問題にはテスト ケースが 1 つしかないため、入力ループは正確に処理します。`q`報告します。 Python の整数には任意の精度があるため、母集団の合計に対するオーバーフローの心配はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((n+q)\alpha(n))) | 各レポートは一定数の DSU 操作を実行し、DSU 操作の償却時間はほぼ一定です。 |
 | スペース | (O(n)) | 親配列、サイズ配列、および人口配列にはそれぞれ (n) 個の値が含まれ、出力には (q) 個の値が含まれます。 |
