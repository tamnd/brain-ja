### なぜ効果があるのか

 初期サイズのカボチャを考えます`x`に達する成功したシーケンス`m`。 上で説明した変換を使用して、すべての加算をシーケンスの最後に移動します。 これにより最終的なサイズが維持されるため、何らかの数値を含む成功したシーケンスも存在します。`t`乗算の後に加算のみが行われます。 

これらの乗算の後、カボチャのサイズが決まります`x * k^t`。 残りの操作は追加します`p`繰り返し実行されるため、最終的な値は次の形式になります。`x * k^t + q * p`。 したがって、成功したシーケンスは、次のようなときに存在します。`t`、`x * k^t <= m`そして`m - x * k^t`で割り切れます`p`。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k, m = map(int, input().split())
    a = list(map(int, input().split()))

    ans = []

    for x in a:
        cur = x
        possible = False

        while cur <= m:
            if (m - cur) % p == 0:
                possible = True
                break

            if cur > m // k:
                break

            cur *= k

        ans.append(1 if possible else 0)

    print(*ans)

if __name__ == "__main__":
    solve()
```外側のループは、各初期カボチャを 1 回処理します。 そのカボチャには、`cur`は常に、一定回数の乗算後、最終加算前のサイズになります。 したがって、最初のチェックは、次の 1 つの候補値に正確に対応します。`t`。 

表現`(m - cur) % p == 0`の後にのみ使用されます`cur <= m`。 境界チェックがなければ、カボチャが絶対に まで減少できないにもかかわらず、負の差が誤って可算性を満たす可能性があります。`m`。 

条件`cur > m // k`次の乗算が次の値を超えることを判断する安全な方法です。`m`。 書き込み`cur * k <= m`Python の整数はオーバーフローしないため、Python でもこれは正しいですが、`m // k`大きすぎることがすでにわかっている値を構築することを回避します。 また、境界条件も明確になります。 

現在の値は乗算の前にチェックされます。 これは両方を処理します`x == m`また、正しい乗算回数が現在の反復回数とまったく同じである場合もあります。 現在の値を確認する前に停止すると、そのようなカボチャが誤って拒否されてしまいます。 

このソリューションでは、必要な追加を明示的にカウントする必要はありません。 一度`m - cur`は負でない倍数です`p`、多くの追加に達するパフォーマンス`m`その通り。
