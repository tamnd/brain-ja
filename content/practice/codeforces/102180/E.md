 ## 解決策
 ## 問題の理解

 あります`n`店舗。 店`i`高価なノートブックがあります`a_i`それぞれのコイン、最大でも`b_i`ノートはそこで買えます。 どの世界にもまったく同じ店舗と在庫がありますが、金額は異なります`k`世界ごとに異なります。 それぞれについて、`m`予算の都合上、購入できるノートブックの数をできるだけ多くする必要があります。 

すべてのノートブックは答えに 1 つだけ貢献するため、ノートブックのアイデンティティはその価格によってのみ重要になります。 ノートブックの数を最大化したい場合、最適な戦略は、入手可能な最も安価なノートブックを最初に使用することです。 したがって、この問題は、利用可能なすべてのノートブックを価格でソートし、予算ごとに、このソートされたシーケンスのプレフィックスがどれだけ長く与えられるかを尋ねることに相当します。 

この制約により、直接シミュレーションが不可能になります。 あり得る`10^5`店舗と`10^5`世界が異なるため、世界ごとにすべてのストアを個別に処理すると実行できる`10^10`操作。 価格は到達する可能性があります`10^9`予算は達成できます`10^18`したがって、64 ビット整数演算が必要です。 Python の整数はすでにこれらの値を安全に処理します。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 まず、予算は店舗の在庫の途中で終了する可能性があります。 例えば、```
1 1
10
6 2
```答えは`1`1 つのノートブックのコストは 6、2 つのノートブックのコストは 12 であるためです。完全なストアのみを考慮する実装では、誤った値が返されます。`0`。 

2 番目に、予算はノートブック数台のコストとまったく同じにすることができます。```
2 1
15
5 2
5 1
```3 冊のノートブックのコストはすべて 5 なので、答えは次のようになります。`3`。 厳密な条件を使用した二分探索`< budget`状態が誤って返される`2`。 

第三に、非常に大きな予算ですべてのノートブックを購入することができます。```
2 1
100
3 2
7 4
```答えは`6`。 アルゴリズムでは、購入したプレフィックスの後に常に手頃な価格の商品が存在すると仮定するのではなく、在庫の合計に到達する検索を可能にする必要があります。 

最後に、複数の店舗で同じ価格が設定される場合があります。 例えば、```
3 2
5 10
2 1
2 3
7 1
```予算に応じて`5`、各 2 ドルのノートブック 4 冊がすべて手頃な価格であるわけではないため、答えは次のとおりです。`2`。 同じ価格のストアは交換可能として扱う必要があり、別々に並べ替えても正しい結果が得られます。 

## アプローチ

 最も直接的な解決策は、店舗を価格で並べ替え、すべての世界について、最も安いものから最も高価なものまでスキャンすることです。 各店舗では、残りの予算が許す限り多くのノートブックを購入しますが、場合によっては在庫の一部のみを購入することもあります。 これは正しいです。購入した高価なノートブックを入手可能な安価なノートブックに置き換えても、購入できるノートブックの数は決して減らないからです。 

問題はスキャンの繰り返しです。 最悪の場合、`n = 10^5`そして`m = 10^5`したがって、予算ごとにすべての店舗をスキャンするには、最大で`10^10`店舗訪問。 これは、1 秒のコンテスト ソリューションで処理できる範囲をはるかに超えています。 

重要な観察点は、ストアはすべてのワールドで同一であるということです。 予算ごとに同じ作業を繰り返すのではなく、共通の価格構造を一度前処理する必要があります。 

ストアを価格で並べ替えた後、最初のいくつかの最も安いストアのすべてのノートブックを含むプレフィックスを定義します。 このようなプレフィックスごとに、ノートブックの総数と総コストを保存します。 予算がプレフィックス全体を購入できるほど大きい場合は、すぐに後のプレフィックスに移行できます。 全在庫を購入できない最初の店舗が見つかったら、その店舗まで答えは決まっているので、そこから一部を購入すればよいことになります。 

これは、総コストが予算を超える最初のプレフィックスを二分検索することで各クエリに答えることができることを意味します。 直前のプレフィックスは完全に手頃な価格です。 残ったお金で買える`remaining // price`次の店舗からのノートブックは、その店舗の在庫が上限となります。 

価格の高い順に店舗を選択すると最適な購入が得られるため、強引な方法が機能します。 すべての世界に対して同じ走査を繰り返すため、失敗します。 すべての世界が同じソート済みストアを共有しているという観察により、繰り返される作業をプレフィックス配列に圧縮し、1 回の二分探索で各予算を個別に回答できるようになります。

 ## アルゴリズムのチュートリアル

 1. すべてのストアを読み取り、並べ替えます。`a_i`、ノートの価格。 安価なノートブックがまだ入手可能なうちに、より高価なノートブックを購入しても、ノートブックの購入数を増やすことはできないため、常に最も安価なノートブックを最初に検討する必要があります。 
2. 2 つのプレフィックス配列を構築します。 させて`cnt[i]`最初のノートブックの合計数になります`i`店舗を分類して、`cost[i]`これらすべてのノートブックを購入した場合の合計金額になります。 価格のある店の場合`a`そして在庫`b`、総コストに占める割合は次のとおりです。`a * b`。 
3. 予算のあるワールドごとに`k`、最大のプレフィックスを二分探索します。`i`満足のいく`cost[i] <= k`。 これにより、利用可能な資金で使い果たされる完全なストアの数が正確にわかります。 
4. しましょう`spent = cost[i]`。 もし`i`が店舗の数に等しい場合、どのノートも手頃な価格なので、答えは単純です。`cnt[i]`。 
5. それ以外の場合はストアを検討してください`i`、在庫全体が高すぎて買えない最初の店です。 まだあります`k - spent`利用可能なお金。 この店のノートはどれも同じ価格なので`a_i`、購入できます`(k - spent) // a_i`彼らのうち。 在庫を超えることはできないため、この商の小さい方の数値が採用されます。`b_i`。 
6. 部分的に購入したノートブックを`cnt[i]`現在の世界の結果を出力します。 

これが機能する理由は、次の不変条件によって捉えられます。`cnt[i]`そして`cost[i]`可能な限り最も安く購入する方法を正確に説明する`cnt[i]`利用可能な在庫からノートブックを選択します。 すべてのプレフィックスは入手可能な最も安価なノートブックで構成されているため、それ以上のものを含むソリューションはすべて`cnt[i]`ノートブックは、次のプレフィックスに到達するのに少なくとも十分なお金を費やす必要があります。 一度`cost[i] <= k < cost[i+1]`、最初のすべて`i`店舗を使い果たしても、次の店舗全体を購入することはできません。 次の店舗にあるノートブックはすべて同じ価格なので、残りの予算が許す限り多くのノートブックを購入すると、可能な限り最大の答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    budgets = list(map(int, input().split()))

    stores = [tuple(map(int, input().split())) for _ in range(n)]
    stores.sort()

    prefix_count = [0] * (n + 1)
    prefix_cost = [0] * (n + 1)

    for i, (price, stock) in enumerate(stores, 1):
        prefix_count[i] = prefix_count[i - 1] + stock
        prefix_cost[i] = prefix_cost[i - 1] + price * stock

    answers = []

    for budget in budgets:
        lo = 0
        hi = n

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if prefix_cost[mid] <= budget:
                lo = mid
            else:
                hi = mid - 1

        i = lo
        answer = prefix_count[i]

        if i < n:
            remaining = budget - prefix_cost[i]
            price, stock = stores[i]
            answer += min(stock, remaining // price)

        answers.append(str(answer))

    sys.stdout.write(" ".join(answers))

if __name__ == "__main__":
    solve()
```店舗はまず次の基準でソートされます。`(price, stock)`ただし、重要なのは価格順だけです。 プレフィックス配列には長さがあります`n + 1`、インデックス付き`0`空のプレフィックスを表します。 これにより、完全な店舗が手頃な価格で手に入らないという境界ケースが自然に生じます。`prefix_cost[0]`はゼロです。 

すべての予算について、二分検索ではすべてのプレフィックスが以下であるという条件が維持されます。`lo`手頃な価格です。 上限は`n`, 全店舗購入が可能かもしれないからです。 表現`(lo + hi + 1) // 2`中間点を上向きにバイアスします。これにより、次の場合に無限ループが発生するのを防ぎます。`lo`そして`hi`一つ違います。 

検索後、`i`予算内に収まるコンプリートストアの最大数です。 もし`i == n`、次に検査する店舗がありません。 さもないと、`remaining`は非負であるため、`prefix_cost[i] <= budget`。 それを次の店の価格で割ると、そこで購入できる追加のノートブックの最大数が求められます。 

掛け算`price * stock`と同じ大きさにすることができます`4 * 10^13`1 つの店舗の場合、総コストはさらに大きくなる可能性があります。 Python の任意精度の整数は、オーバーフローすることなく必要な値を処理します。 

操作の順序も重要です。 まず、完全に購入したすべての安価なストアのコストを取り除き、次に残りのお金を次の価格レベルでのみ使用します。 安価なノートブックをスキップして、より高価なノートブックを選択する理由はありません。

 予算が最も安いノートブックよりも小さい場合、二分検索はプレフィックスを返します。`0`。 例えば、```
1 1
4
5 3
```両方`prefix_cost[0] = 0`そして最初の完全なプレフィックスコスト計算`15`が考慮されます。 手頃な価格の最大のプレフィックスは次のとおりです。`0`、 それで`remaining = 4`、 そして`4 // 5 = 0`。 答えは正解です`0`。 

完全なプレフィックスを作成するのに十分な予算がある場合、`<=`比較することが不可欠です。 のために```

10
5 2
8 1
```最初のプレフィックスは正確にコストがかかります`10`, したがって、二分検索は次の結果を返します`i = 1`。 答えは`2`。 使用する`<`の代わりに`<=`手頃なプレフィックスを誤って破棄してしまう可能性があります。

3 2
7 4
```総費用は`34`したがって、手頃な最大のプレフィックスは配列全体です。 アルゴリズムは戻ります`prefix_count[2] = 6`次のストアがないため、部分ストアの計算をスキップします。
