 ## 解決策
 ## 問題の理解

 少なくとも必要です`n`ジャガイモのキログラム。 お店は2日間別々に営業しております。 

初日は1kgごとに料金がかかります`a`、そしてプロモーションがあります: 支払うたびに`m`キログラムの場合は、さらに 1 キログラムを無料で受け取ります。 の購入`m`支払われたキログラムはあなたに与えます`m + 1`合計でキログラム。 

2日目は1kgごとに料金がかかります`b`そして昇進もありません。 

どちらの日でも、負でない整数のキログラムを購入できます。 目標は少なくとも取得することです`n`可能な限り少ない数のコインを消費しながらキログラム。 

制約は、各テスト ケースを一定時間内に解決する必要があることを直ちに示唆します。 到達できる値は、`10^9`, そのため、購入可能額を繰り返すことは不可能です。 まで`10^4`テストケースでも、`O(n)`テストケースごとのソリューションは遅すぎます。 

主な困難は、プロモーションが実際にいつ役立つかを判断することです。 よくある間違いは、初日プロモーションを常に可能な限り使用する必要があると想定することです。 買うときは嘘だ`m`初日にキログラムを購入すると、単に購入するよりも費用がかかります`m + 1`2日目はキログラム。 

考慮する：```
a = 10, b = 1, m = 2, n = 3
```プロモーション ブロック 1 つで、コスト 20 で 3 キログラムが提供されます。2 日目に 3 キログラムすべてを購入しても、コストはわずか 3 です。ここでプロモーションを使用すると、悲惨な結果になります。 

もう 1 つの簡単な間違いは、最後の不完全なブロックの処理を誤ることです。 

考慮する：```
a = 5, b = 4, m = 2, n = 4
```完全なプロモーション ブロック 1 つでは、コスト 10 で 3 キログラムが得られます。それでも 1 キログラムが必要です。 2 日目にそのキログラムを購入すると 4、合計 14 のコストがかかります。2 日目に 4 キログラムすべてを購入すると 16 のコストがかかります。残りは個別に処理する必要があります。 

3 番目のエッジケースは次の場合に発生します。`n < m + 1`。 

考慮する：```
a = 5, b = 4, m = 100, n = 2
```昇格ブロックを 1 つも形成することはできません。 答えは単純です`2 * min(a, b)`。 

## アプローチ

 ブルートフォース ソリューションでは、初日に購入できるすべてのキログラム数を試し、ギフト後に何キログラムが得られるかを計算し、2 日目に残りのキログラムを購入します。 これは、実行可能なすべての戦略を検討するため、正しいです。 

問題は、可能性の数が次の値に比例することです。`n`、 そして`n`多分`10^9`。 1 つのテスト ケースでもこの方法で処理することは不可能です。 

重要な観察は、プロモーションが固定サイズのブロックで動作するということです。 支払い中`m`初日の収穫量はキログラム`m + 1`キログラム。 

したがって、プロモーションブロックにはコストがかかります$$m \cdot a$$そして生産します$$m+1$$キログラム。 

入手する場合`m+1`2日目の費用はすべてキログラム$$(m+1)\cdot b,$$次に、これら 2 つの値を比較する必要があります。 

もし$$m a \ge (m+1)b,$$プロモーションブロックは、2日目に同じ量を購入するよりも優れていることはありません。 そのような状況では、プロモーションを完全に無視して、より安い毎日の価格ですべてのキログラムを購入する必要があります。 

もし$$m a < (m+1)b,$$すべての完全なプロモーション ブロックは有益です。 次に、できるだけ多くの完全なブロックを使用し、残りのキログラムを個別に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 つのプロモーション ブロックのコストを計算します。$$\text{promo} = m \cdot a.$$プロモーションブロックは正確に与えます`m + 1`キログラム。 

1. 2 日目に同じ量のキログラムを完全に取得するコストを計算します。$$\text{normal} = (m+1)\cdot b.$$1. もし$$m a \ge (m+1)b,$$プロモーションを無視します。 1 キログラムごとに、より安い日価で購入する必要があります。$$n \cdot \min(a,b).$$1. それ以外の場合、プロモーションには価値があります。 させて$$q = \left\lfloor \frac{n}{m+1} \right\rfloor$$完全なプロモーション ブロックの数になります。 

1. これらのブロックは貢献します$$q \cdot m \cdot a$$コイン。 

1. しましょう$$r = n \bmod (m+1).$$これらのキログラムは、別の完全な昇格ブロックを形成するには十分ではありません。 

1. 残りについて`r`キログラムの場合、1 日あたりの 2 つの価格のうち安い方を使用して各キログラムを購入します。$$r \cdot \min(a,b).$$1. 両方の寄与を追加し、結果を出力します。 

### なぜ効果があるのか

 いつでも$$m a < (m+1)b,$$完全なプロモーションブロックは、2日目に同じキログラム数を取得するよりも厳密に安価です。 完全なブロックを他の方法で置き換えても、答えを改善することはできません。 

いつでも$$m a \ge (m+1)b,$$プロモーションブロックは決して有利ではありません。 このようなブロックを含む溶液は、2 日目に同じキログラムを購入すれば、追加費用なしで交換できます。 

収益性の高い完全なブロックをすべて取得した後、残りの数量は`m+1`。 別のプロモーションブロックを形成すると、必然的に余分な不必要なキログラムを購入することになります。 残りのキログラムについては、各単位を原価で個別に購入できます。`min(a,b)`、これが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        a, b = map(int, input().split())
        n, m = map(int, input().split())

        if m * a >= (m + 1) * b:
            print(n * min(a, b))
        else:
            blocks = n // (m + 1)
            rem = n % (m + 1)

            ans = blocks * m * a
            ans += rem * min(a, b)

            print(ans)

solve()
```最初の支店は、プロモーションが通常の購入と競合しない場合を処理します。 そのような状況では、すべてのキログラムを、入手可能なより安価な単価で購入する必要があります。 

2 番目のブランチでは、収益性の高いプロモーション ブロックをできるだけ多く使用します。 整数除算は、完全なグループがいくつあるかを計算します。`m + 1`キログラムは目標量に収まります。 残りは独立して処理されます。 

Python の整数は任意の精度を持っているため、乗算の順序は読みやすさのみを目的としています。 固定幅の整数を使用する言語では、値がおおよその値に達する可能性があるため、64 ビット演算が必要になります。`10^18`。 

よくある off-by-one エラーは、次のような除算です。`m`の代わりに`m + 1`。 プロモーションが生み出すのは、`m + 1`キログラムなので、完全なブロックはそのサイズを使用してカウントする必要があります。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        a, b = map(int, input().split())
        n, m = map(int, input().split())

        if m * a >= (m + 1) * b:
            out.append(str(n * min(a, b)))
        else:
            blocks = n // (m + 1)
            rem = n % (m + 1)
            ans = blocks * m * a + rem * min(a, b)
            out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 次のことを考慮してください。```
a = 10
b = 1
n = 3
m = 2
```完全なプロモーション ブロックの価格は 20 で、収穫量は 3 キログラムです。 2 日目に 3 キログラムを購入しても、コストはわずか 3 です。$$20 \ge 3,$$アルゴリズムは最初の分岐に入り、戻ります。$$3 \cdot 1 = 3.$$これにより、昇格が正しく回避されます。 

考慮する：```
a = 5
b = 4
n = 2
m = 100
```1 つのブロックで 101 キログラムが生成されるため、昇格ブロックを完了することはできません。 アルゴリズムはゼロ完全ブロックを計算し、残りの 2 キログラムを原価で購入します。`min(5,4)=4`、8を与えます。 

次のことを考慮してください。```
a = 3
b = 10
n = 9
m = 2
```各プロモーション ブロックの価格は 6 で、収穫量は 3 キログラムです。 3 つの完全なブロックで必要な量が正確に供給されます。 余りはゼロなので、答えは単純に$$3 \cdot 6 = 18.$$これにより、不必要なキログラムを購入せずに正確な割り算が処理されることが検証されます。
