 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられます。 私たちのタスクは、最初と最後の要素がそのサブセグメントの最小値でも最大値でもない、連続したサブセグメントを見つけることです。 そのようなサブセグメントが存在しない場合は、-1 を出力する必要があります。 

順列には 1 から n までのすべての整数が 1 回だけ含まれるため、重要です。 これにより、グローバル最小値が 1 であり、グローバル最大値が n であることがすぐに分かります。 どちらの端も局所極値でない場合、長さが 3 以上のサブセグメントは条件を満たす可能性があります。 ただし、厳密に増加または減少するシーケンスでは、最後の要素は常にそのサブセグメントの最小値または最大値になるため、このプロパティを満たすサブセグメントはありません。 

制約は厳しく、n は最大 2×10^5、テスト ケースは最大 10^4 まで可能です。 これは、すべての O(n^2) サブセグメントをチェックする総当り的なアプローチは、およそ 10^10 の操作が必要になる可能性があるため、実行不可能であることを意味します。 テスト ケースごとに O(n) または O(n log n) のソリューションが必要です。 エッジ ケースには、サブセグメントが存在できない非常に小さな配列 (n ≤ 2) や、局所的な山と谷が端にあるシーケンスが含まれます。 

## アプローチ

 単純なアプローチは、すべてのサブセグメントを反復処理し、最初と最後の要素がそのセグメントの内部 (最小値でも最大値でもない) かどうかを確認することです。 これは論理的には正しいですが、すべてのサブセグメントをチェックする必要があるため、複雑さは O(n^2) になり、n = 2×10^5 の場合は失敗します。 

重要な点は、有効なサブセグメントの最小長が 3 であることです。長さが 3 のサブセグメントの場合、中央の要素は 2 つの端に対して自動的に内部になります。 中央の要素が他の 2 つの要素の間にある、連続する要素の 3 つの要素を見つける必要があるだけです。 より具体的には、連続する 3 つの要素 a[i]、a[i+1]、a[i+2] が与えられた場合、a[i] < a[i+1] < a[i+2] または a[i] > a[i+1] > a[i+2] が成立しない場合、a[i+1] は最小値でも最大値でもありません。 同様に、a[i+1] が厳密に a[i] と a[i+2] の間にあるかどうかを確認するだけです。 これにより、問題は O(n) 時間でアレイ全体を 1 回スキャンするだけになります。 

有効なトリプレットはすでに有効なサブセグメントを形成しており、問題の要件を満たしているため、長いサブセグメントをチェックする必要はありません。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | トリプレットスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、順列長 n と配列 a を読み取ります。 
2. n < 3 の場合、長さ 3 のサブセグメントが存在しないため、すぐに -1 を出力します。 
3. i = 0 から n - 3 まで反復します (ゼロベースのインデックス付け)。 連続する各トリプレット a[i]、a[i+1]、a[i+2] について、中央の要素 a[i+1] が他の 2 つの要素の間に厳密に存在するかどうかを確認します。 具体的に確認すると、`(a[i] < a[i+1] < a[i+2]) or (a[i] > a[i+1] > a[i+2])`は成立しません。 そうでない場合、a[i+1] は内部のものです。 
4. そのようなトリプレットが見つかった場合は、1 から始まるインデックスを出力します。`i+1`そして`i+3`サブセグメントの左端と右端として。 
5. 配列全体をスキャンした後に有効なトリプレットが見つからない場合は、-1 を出力します。 

これが機能する理由: 不変条件は、長さ 3 のサブセグメントの中間要素が最大値も最小値も持たない場合、両端が問題の条件を自動的に満たすことです。 有効なサブセグメントが 1 つだけ必要なため、連続するトリプレットをスキャンするだけで十分であり、アルゴリズムによりトリプレットがスキップされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    found = False
    for i in range(n - 2):
        if (a[i] < a[i+1] < a[i+2]) or (a[i] > a[i+1] > a[i+2]):
            continue
        print(i+1, i+3)
        found = True
        break
    if not found:
        print(-1)
```コードはすべてのテスト ケースを効率的に読み取ります。 このループは、連続するトリプレットをそれぞれチェックし、Codeforces で一般的な 1 から始まる形式でインデックスを出力します。 私たちが使用するのは`found`有効なセグメントが検出されたかどうかを追跡します。 の`continue`ステートメントは条件を満たさないため、トリプレットの厳密な増加または減少をスキップします。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # solution
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        found = False
        for i in range(n - 2):
            if (a[i] < a[i+1] < a[i+2]) or (a[i] > a[i+1] > a[i+2]):
                continue
            print(i+1, i+3)
            found = True
            break
        if not found:
            print(-1)
    return output.getvalue().strip()

## 特殊なケース

 n<3 の場合、アルゴリズムは直ちに -1 を出力し、最小サイズの配列を正しく処理します。 厳密に増加または減少するシーケンスの場合、すべてのトリプレットはスキップされます。`continue`条件を設定し、-1 が返されるようにします。 複数の有効なサブセグメントが存在する配列の場合、アルゴリズムは常に最初の有効なトリプレットを出力します。問題では有効な答えが許容されるため、これは許容されます。
