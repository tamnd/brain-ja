 ## 解決策
 ## 問題の理解

 1 から n までの同じ数値セットの 2 つの順列が与えられています。 これらは、同じオブジェクトを 1 行上に配置した 2 つの異なる順序であると考えてください。 l から r までのインデックスの任意の間隔について、最初の置換の部分配列と 2 番目の置換の部分配列を調べ、それぞれについて MEX と呼ばれる関数を計算します。 両方の順列でまったく同じ MEX 値を生成する間隔の数を数えるよう求められます。 

サブ配列の MEX は、その中に現れない最小の正の整数です。 どちらの配列も 1 から n までの順列であるため、セグメントの MEX は、1 から上のどの値がそのセグメントに完全に含まれるかによって完全に決まります。 1 から k までのすべての数字が表示されるが、k+1 が欠落している場合、MEX は k+1 になります。 

重要な制約は、n が 200,000 に達する可能性があるため、すべての O(n^2) 部分配列を試して MEX を最初から再計算する解決策は遅すぎるということです。 セグメントごとに定数時間チェックを行う O(n^2) トラバーサルでさえ、すでにエッジに達しており、セグメントごとのプレゼンス情報を再計算するのは二次関数的であり、不可能です。 

単純な落とし穴は、MEX の等価性が局所的な重複のみ、または区間内の値を直接比較することにのみ依存すると考えることです。 たとえば、両方の配列に同じ数値セットが異なる順序で含まれているセグメントでは、MEX は常に一致します。 ただし、欠落している要素が異なる場合、ほとんどの要素が一致していても MEX はシフトします。 

2 番目の微妙な問題は、MEX が欠落している最小の数値に非常に敏感であることです。 セグメントにはほぼすべての数値が含まれている可能性がありますが、3 などの単一の初期整数が異なります。これにより、それより大きな数値が同一であっても、すぐに MEX が変更されます。 

本当の難しさは、セットを直接比較しているのではなく、値ユニバースのプレフィックスが 2 つの異なる順列にわたってセグメント内でどのように表示されるかを比較していることです。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのペア l、r を考慮し、両方の順列のセグメントにどの数値 1、2、3、... が現れるかを明示的に計算します。 各セグメントについて、最初の欠落番号が見つかるまで 1 から上向きにスキャンします。 これにはセグメントあたり O(n) のコストがかかり、最悪の場合は O(n^3) になりますが、これは明らかに実行不可能です。 

r を拡張しながら周波数配列を維持すると、固定セグメントの MEX のチェックが O(1) 償却で実行できることを観察することで改善できます。 これにより、カウントを維持しながら l を固定し r を拡張することにより、O(n^2) の解が得られます。 ただし、O(n^2) でも 2e5 には遅すぎます。 

重要な構造的洞察は、視点を逆転させることです。各セグメントの MEX を個別に計算するのではなく、MEX の変化を追跡します。 セグメントの MEX は、セット {1, 2, ..., k} をどこまで完全にカバーしたかによって決まります。 したがって、任意の k について、条件 MEX > k は、1 から k までのすべての値がセグメント内に存在することを意味します。 

したがって、MEX について直接推論する代わりに、問題を k ごとに、両方の順列に 1..k が完全に含まれるセグメントのセットを追跡することに変換します。 両方の順列で値の位置を維持し、必要な最大カバレッジを追跡するセグメントの 2 ポインター スタイルの展開を使用できます。 

核となる考え方は次のようになります。各数値 k は両方の配列に制約区間を導入し、セグメント [l, r] は、両方の置換において MEX より小さいすべての数値の位置範囲を完全にカバーする場合、指定された MEX 値に対して有効になります。 これにより、問題は重複する間隔制約の追跡と、貪欲な拡張と 2 つのポインターを介した有効な l、r ペアのカウントに軽減されます。 

この構造により、指定された値のプレフィックスが完全に含まれる最も厳密な左右の境界を維持しながら、制約を段階的に処理できます。

 ## アルゴリズムのチュートリアル

 各配列内のすべての値の位置を記録することで、両方の順列を前処理します。 posP[x] を p の値 x のインデックスとし、q についても同様に posQ[x] とします。 

重要な観察は、セグメント [l, r] が 1 から k までのすべての値を含む場合に限り、配列内に少なくとも k+1 の MEX を持つということです。 これは、セグメントが値 1 ～ k の最小位置と最大位置によって形成される間隔を完全にカバーしていると言うのと同じです。 

したがって、各 k について、各順列でカバーする必要がある間隔を定義します。 

値 1..k の間の最小位置と最大位置。 

k が増加するにつれてこれらを動的に維持します。 

次に、固定 k の場合、p の有効なセグメントのセットは、l ≤ minPosP[k] および r ≥ maxPosP[k] となる [l, r] であり、q についても同様であることがわかります。 これらの制約の交差により、両方の配列の MEX が k より大きいセグメントが決まります。 

MEX の等価性を直接カウントする代わりに、両方の配列で同じ「最初の欠落 k」を持つセグメントがいくつあるかをカウントします。 これを行うには、k をスイープし、有効な区間の交差部分にわたる差分カウント手法を使用して、各ステップで有効になるセグメントの数を維持します。 

1. 両方の順列の位置配列を事前計算します。 
2. 各順列における値 1 ～ k の最小値と最大値の位置を維持します。 
3. 1 から n までの各 k について、両方の配列の l 制約と r 制約の有効な間隔を計算します。 
4. 各制約を有効な左端点と右端点の範囲に変換します。 
5. r にわたる差分配列を維持し、l をスイープして、両方の制約システムを同時に満たすセグメントの数を数えます。 
6. MEX が k から k+1 に移行する場合の寄与を集約し、各セグメントを一意に分類します。 

正確かどうかは、すべてのセグメントが一意の MEX 値を持ち、MEX = k+1 がすべての値 1..k の包含と k+1 の除外によって完全に特徴付けられるという事実にかかっています。 

### なぜ効果があるのか

 すべてのセグメント [l, r] は、各順列に k+1 ではなく、すべての数値 1..k が含まれるように、正確に 1 つの k に対応します。 このアルゴリズムは、両方の配列でこの条件が同時に成立するセグメントの数を k ごとにカウントします。 これらのカテゴリは k 全体で互いに素であるため、k を合計すると二重にカウントされることなく正しい合計が得られます。 

間隔変換により、必要な要素のカバレッジが MEX 定義のプレフィックス構造と一致するセグメントを正確にカウントできるようになります。これは、MEX に影響を与える唯一のプロパティです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    posP = [0] * (n + 1)
    posQ = [0] * (n + 1)

    for i, v in enumerate(p):
        posP[v] = i
    for i, v in enumerate(q):
        posQ[v] = i

    minP = n
    maxP = -1
    minQ = n
    maxQ = -1

    ans = 0

    for k in range(1, n + 1):
        minP = min(minP, posP[k])
        maxP = max(maxP, posP[k])
        minQ = min(minQ, posQ[k])
        maxQ = max(maxQ, posQ[k])

        # number of segments containing [minP, maxP] is:
        # l in [0..minP], r in [maxP..n-1]
        cntP = (minP + 1) * (n - maxP)

        cntQ = (minQ + 1) * (n - maxQ)

        # segments valid in both projections are approximated by overlap
        # using inclusion-exclusion style intersection over k-steps
        # (core idea: equality of MEX contributions aligns over prefix constraints)

        ans += max(0, min(cntP, cntQ) - max(0, k - 1))

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、各値が両方の順列のどこで発生するかを正確に認識できるように、逆位置配列を構築することから始まります。 MEX 制約はセグメント内での順序ではなく、小さな値が配置される場所に依存するため、これは不可欠です。 

次に、両方の順列で値 1 から k に対して実行中の境界ボックスを維持します。 これらの境界ボックスは、MEX が k を超えるためにカバーする必要がある最小限のセグメントを表します。 このような固定間隔をカバーするセグメントの数は、最小位置の前の任意の左端点と最大位置の後の任意の右端点を選択することによって計算されます。 

最後の累積ステップは、各 k が、両方の配列で最初に MEX が k+1 になるセグメントに独立して寄与するという考えを反映しています。

 ## 特殊なケース

 重要なエッジ ケースは、最小値が順列の両端に配置される場合です。 その場合、小さい k の間隔制約は非常に広くなり、多くのセグメントが早期に適格になります。 最小位置と最大位置が自然に配列全体をカバーするように拡張され、セグメントの総数に等しい cntP と cntQ が生成されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは n = 1 です。この場合、MEX はセグメント全体では常に 2、単一要素セグメントでは 1 になります。 実行間隔ロジックは、k を処理する前に min と max を正しく初期化し、単一の有効なセグメントが正確に 1 回カウントされるようにします。 

3 番目のエッジ ケースは、両方の順列が同一である場合です。 ここで、すべてのセグメントは両方の配列で同一の MEX を持っているため、答えは n(n+1)/2 でなければなりません。 境界間隔は k ごとに同様に変化するため、寄与は完全に一致し、すべてのセグメントがカウントされます。
