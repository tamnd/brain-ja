[CF 1139E - Mex の最大化](https://codeforces.com/problemset/problem/1139/E)

 **評価:** 2400
 **タグ:** フロー、グラフ マッチング、グラフ
 **解決時間:** 1 分 48 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 各生徒は 1 つのクラブに所属しており、潜在的な価値を持っています。 特定の日に、一部の学生はすでにクラブを永久に退会しています。 残りの生徒の中から、各クラブから最大 1 人の生徒を選ぶことができます。 選ばれた生徒がコンテストチームを結成します。 

チームの強みは選ばれた可能性の集合体です。 私たちは達成可能な最大のメックスを望んでいます。 

少なくともメキシコ人`k`あらゆる値を意味します`0, 1, ..., k-1`選択した生徒の中に が表示されます。 各クラブから生徒を 1 人だけ受け入れることができるため、本当の問題はもはや個々の生徒に関するものではありません。 それは価値観かどうかについてです`0, 1, ..., k-1`個別のクラブに割り当てることができます。 

入力は最初の生徒を記述し、その後、一連の削除を記述します。 最初の削除の後は 1 日目の答えが必要になり、2 回目の削除の後は 2 日目の答えが必要になります。 

制約は重要な観察事項です。 生徒数は最大でも 5,000 人で、クラブ数も最大でも 5,000 です。可能性は厳密に 5,000 未満です。削除のたびにすべてを最初から再計算するソリューションでは、サイズ 5,000 のグラフに対して約 5,000 回の独立した計算が必要になりますが、これは制限をはるかに超えています。 日の間に作業を再利用する必要があります。 

微妙なケースの 1 つは、複数のクラブが同じ価値を提供できる場合です。```
Club 1: potential 0
Club 2: potential 0
Club 3: potential 1
```値 0 はクラブ 1 またはクラブ 2 から取得され、値 1 はクラブ 3 から取得されるため、mex は 2 になります。最初に使用可能なクラブを貪欲に選択すると、再割り当てが許可されない場合、窮地に陥る可能性があります。 

もう 1 つの簡単な間違いは、クラブではなく学生をマッチング対象として扱うことです。```
Club 1: potentials {0,1}
Club 2: potentials {1}
```値 0 と 1 の両方をクラブ 1 から取得することはできません。正しいモデルでは、各クラブが選択した生徒を最大 1 人だけ寄付することを強制する必要があります。 

3 番目の明らかではない状況は、削除された生徒が後で逆のプロセスで再び出現したときに発生します。 基礎となる一致するグラフに新しいエッジが現れるため、最大 mex が増加する可能性があります。 毎回マッチング全体を再計算する必要はありませんが、アルゴリズムは以前の割り当てを再配置する拡張パスを見つけることができなければなりません。 

## アプローチ

 直接的なアプローチは、毎日を独立して処理することです。 その日の削除を適用した後、値が次のとおりであるグラフを構築します。`x`現在潜在的な可能性のある生徒が所属するすべてのクラブに接続されています。`x`。 次に、2 部マッチングを使用して mex が 1 以上、2 以上、3 以上であるかどうかをテストします。 

これは正しいです。なぜなら、少なくとも mex だからです。`k`価値観を意味する`0..k-1`すべてを個別のクラブに割り当てることができます。 一致する定式化はその状態を正確に捉えます。 

問題はコストです。 最大5000日まであります。 毎日の再構築と再マッチングにより、数千万または数億のマッチング操作が行われます。 

重要な点は、削除は永続的であるということです。 オフライン処理により時間を巻き戻すことができます。 

生徒を 1 人ずつ削除するのではなく、すべての削除が完了した最終状態から開始します。 次に、逆の順序で生徒を追加し直します。 

学生を追加すると、グラフにエッジが 1 つだけ追加されます。```
value p_i  --->  club c_i
```エッジが削除されることはありません。 

次に、現在の mex を証明するマッチングについて考えてみましょう。 その値がすでにわかっていると仮定します`0..cur-1`異なるクラブに合わせることができます。 新しいエッジが追加されると、mex は増加するだけです。 古い価値観を再確認する必要はありません。 

二部グラフでのマッチングを維持します。```
values  <->  clubs
```不変条件とは、次の値です。`0..cur-1`一致しています。 mex がなれるかどうかをテストするには`cur+1`、値の一致を試みるだけで済みます`cur`。 拡張パスが存在する場合は、マッチングを拡張して増分します。`cur`。 次の値が一致しなくなるまでこれを繰り返します。 

これにより、プロセス全体が増分マッチング問題に変わります。 各値の照合が成功するのは最大 1 回であるため、作業量の合計は管理可能な範囲に留まります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(d・V・E) | お(え) | 遅すぎる |
 | 最適 | O(E · V) 償却、ここでは O(n · 5000) | お(え) | 承認済み |`V`値の頂点の数を示し、最大 5001、および`E ≤ n`。 

## アルゴリズムのチュートリアル

 1. すべての生徒とすべての削除クエリを読みます。 
2. 最終的に削除されるすべての生徒にマークを付けます。 
3. すべての削除が行われた後の状態に対応するグラフを作成します。 すべてを生き残るすべての生徒のために`d`潜在的な価値からクラブにエッジを加えます。 
4. クラブと価値観の標準的な Kuhn マッチングを維持します。`match[club]`現在そのクラブを使用している値を保存します。 
5. しましょう`cur = 0`。 値から始まる拡張パスの検索を繰り返し試みます`cur`。 
6. DFS が成功した場合、値`cur`マッチング可能になります。 増加`cur`次の値を試してください。 
7. DFS に障害が発生すると、`cur`は正確に現在の最大 mex です。 すべて削除した後の状態の答えとして保存します。 
8. 逆の順序で削除を処理します。 学生時代`k_i`復元され、エッジを追加します`(p[k_i], c[k_i])`グラフに。 
9. 新しいエッジを追加した後は、mex は増加するだけです。 現在から同じループを継続します`cur`、値の一致を繰り返し試行します`cur`。 
10. この新しい状態の結果として得られる mex を保存します。 
11. すべての逆加算が処理された後、すべての中間状態の mex がわかります。 日数に応じた回答を出力します`1..d`。 

### なぜ効果があるのか

 あらゆる値に対して`x`、エッジ`(x, club)`クラブには現在、潜在的な可能性を秘めた現役学生が少なくとも 1 人いることを意味します。`x`。 

少なくともメキシコ人`k`あらゆる値が必要です`0..k-1`選択したチームに表示されます。 各クラブが貢献する生徒は最大 1 人であるため、これらの値は個別のクラブに割り当てる必要があります。 これはまさに一致するカバー値です`0..k-1`。 

維持される一致は常に以下のすべての値をカバーします`cur`。 DFS が値に対して成功した場合`cur`、パスを増強すると、一致するカバーが作成されます。`0..cur`。 DFS が失敗すると、値に関してホールの条件が違反されます。`cur`、したがってマッチングではカバーできません`0..cur`。 したがって、達成可能な最大 mex は正確に次のようになります。`cur`。 

逆処理はエッジを追加するだけなので、以前に一致した値が無効になることはありません。 mexは増えるだけなので今のマッチングを継続すれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    p = list(map(int, input().split()))
    c = list(map(int, input().split()))

    d = int(input())
    rem = [int(input()) - 1 for _ in range(d)]

    removed = [False] * n
    for x in rem:
        removed[x] = True

    MAXV = 5001
    g = [[] for _ in range(MAXV)]

    for i in range(n):
        if not removed[i]:
            g[p[i]].append(c[i])

    match = [-1] * (m + 1)

    sys.setrecursionlimit(20000)

    def dfs(v):
        if vis[v]:
            return False
        vis[v] = True

        for club in g[v]:
            if match[club] == -1 or dfs(match[club]):
                match[club] = v
                return True
        return False

    cur = 0

    while cur < MAXV:
        vis = [False] * MAXV
        if dfs(cur):
            cur += 1
        else:
            break

    ans = [0] * (d + 1)
    ans[d] = cur

    for idx in range(d - 1, -1, -1):
        student = rem[idx]
        g[p[student]].append(c[student])

        while cur < MAXV:
            vis = [False] * MAXV
            if dfs(cur):
                cur += 1
            else:
                break

        ans[idx] = cur

    print("\n".join(str(ans[i]) for i in range(1, d + 1)))

if __name__ == "__main__":
    solve()
```グラフは潜在的な値によってインデックス化されます。`g[v]`現在価値を提供できるすべてのクラブが含まれています`v`。 

マッチングはクラブから値まで保存されます。 これは標準的な Kuhn 表現です。 DFS 中に、クラブが別の値によってすでに占有されている場合、再帰的にその値を別の場所に移動しようとします。 

変数`cur`は常に、一致可能かどうかがまだわかっていない最初の値を表します。 増強に成功すると、ちょうど 1 だけ増加します。 

よくある実装上の間違いは、生徒を復元するたびにマッチングを再構築することです。 オフライン アプローチの重要な点は、エッジは追加されるだけで削除されないため、現在のマッチングが有効なままであるということです。 

もう 1 つの微妙な詳細は、回答のインデックス付けです。 逆処理では状態の答えを計算します。```
after all deletions
after restoring last deletion
after restoring last two deletions
...
```必要な出力は、1 日目、2 日目、...、d 日目以降の状態に対応しており、これらは次の場所に保存されます。`ans[1] ... ans[d]`。

 ## 特殊なケース

 次のことを考慮してください。```
2 1
0 1
1 1
1
2
```クラブは一つしか存在しない。 値 0 と 1 は両方とも使用可能ですが、選択したチームに両方を表示することはできません。 グラフにはエッジが含まれています。```
0 -> club 1
1 -> club 1
```値 0 は照合できますが、値 1 を同時に照合することはできません。 値 1 を増やそうとするとアルゴリズムが失敗するため、mex は 1 として正しく報告されます。 

次に、次のことを考えてみましょう。```
3 2
0 0 1
1 2 2
1
3
```唯一の値 1 を削除すると、残りのグラフは次のようになります。```
0 -> club 1
0 -> club 2
```値 0 は一致しますが、値 1 は一致しません。 アルゴリズムは mex 1 を返します。欠落している下位の値も存在しない限り、同じ値の複数のコピーは役に立ちません。 

ついに：```
3 3
1 2 3
1 2 3
1
1
```値 0 を持つアクティブな学生はいません。値 0 の DFS はすぐに失敗します。 アルゴリズムは、それより大きな値を考慮せずに mex 0 を返します。これはまさに mex の定義です。
