 ## 解決策
 ## 問題の理解

 1 から 9 までの数字の文字列が与えられます。私たちの仕事は、連続するインデックス範囲で定義された偶数を表す部分文字列がいくつあるかを数えるということです。 数値のパリティは完全に最後の桁によって決まるため、部分文字列は最後の桁が偶数であっても偶数です。 

入力サイズは最大 65,000 桁です。 部分文字列の総数はおおよそ次のとおりであるため、すべての部分文字列を明示的に構築するソリューションは除外されます。$n(n+1)/2$、これは20億を超えます$n = 65,000$。 すべての部分文字列を反復して整数に変換しようとするアルゴリズムは、非常に遅すぎます。 

微妙なエッジ ケースは、奇数桁だけで構成される文字列です。 たとえば、「1357」は偶数桁で終わる部分文字列がないため、出力は 0 になります。 もう 1 つのエッジ ケースは、「246」のように、すべての桁が偶数の場合であり、すべての部分文字列がカウントされます。 これらを正しく処理できるかどうかは、完全な部分文字列に対して算術演算を試みるのではなく、最後の桁に基づいて部分文字列をカウントすることに依存します。 

## アプローチ

 ブルートフォース手法では、部分文字列の可能なすべての開始インデックスと終了インデックスを反復処理し、部分文字列を数値に変換し、それが 2 で割り切れるかどうかを確認します。これは正しいですが、必要な処理が必要なため遅すぎます。$O(n^2)$部分文字列の抽出と整数の変換。 と$n = 65,000$、これはおおよそです$2 \times 10^9$0 秒の時間制約の妥当な制限を超える操作。 

重要な洞察は、数値のパリティは最後の桁のみに依存するということです。 位置で終わる部分文字列$i$たとえ$s[i]$は 2、4、6、または 8 のいずれかです。この位置で終わるすべての部分文字列は直接数えることができます。$i$インデックスで終わる部分文字列$i$。 したがって、部分文字列を生成する代わりに、単純に文字列を反復処理し、偶数の数字が表示されるたびに、その位置 (1 から始まるインデックス) を累計に追加します。 これにより、時間の複雑さが軽減されます。$O(n)$不要な文字列や整数の操作を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列とその長さを読み取ります。 1 から始まるインデックスを使用して、文字列を左から右に反復処理します。 
2. カウンタをゼロに初期化します。 このカウンタは、偶数部分文字列の合計数を累積します。 
3. インデックスの各文字について$i$、パリティをチェックするために整数に変換します。 
4. 桁が偶数 (2、4、6、8) の場合、カウンタを 1 つずつインクリメントします。$i$。 これは、この位置で終わるすべての部分文字列が 1 から 1 までの開始インデックスによって一意に識別されるため、機能します。$i$。 
5. 文字列の終わりまで続けて、カウンターを出力します。 

なぜ機能するのか: 各インデックスの不変条件は次のとおりです$i$、で終わる部分文字列の総数$i$まさに$i$、偶数桁で終わる各部分文字列が答えに寄与します。 すべてのインデックスを 1 回だけ訪問し、偶数桁で終わるすべての部分文字列をカウントするため、有効な部分文字列が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

count = 0
for i, c in enumerate(s, start=1):
    if int(c) % 2 == 0:
        count += i

print(count)
```このソリューションは入力文字列を読み取り、1 から始まるインデックスを使用して列挙します。 各文字について、それが偶数であるかどうかを確認し、偶数である場合は、そのインデックスを合計数に追加します。 部分文字列を保存したり、複数の文字を数値に変換したりする必要がないため、メモリと計算の両方が低く抑えられます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()
    count = 0
    for i, c in enumerate(s, start=1):
        if int(c) % 2 == 0:
            count += i
    return str(count)

# Provided samples
assert run("4\n1234\n") == "6", "sample 1"
assert run("3\n246\n") == "6", "sample 2"

# Custom cases
assert run("1\n1\n") == "0", "single odd digit"
assert run("1\n2\n") == "1", "single even digit"
assert run("5\n11111\n") == "0", "all odd digits"
assert run("5\n22222\n") == "15", "all even digits"
assert run("6\n135792\n") == "6", "mixed digits, only last even matters"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 0 | 単一の奇数桁、カウントはゼロ |
 | 2 | 1 | 単一の偶数桁、ゼロ以外の最小カウント |
 | 11111 | 0 | すべての奇数桁、部分文字列はカウントされません |
 | 22222 | 15 | すべての偶数桁、インデックスの合計 1+2+3+4+5 |
 | 135792 | 6 | 混合数字、最後の偶数桁は正しくカウントされます。 

## 特殊なケース

 1 桁の文字列「1」の場合、唯一の部分文字列が奇数の数字で終わるため、アルゴリズムは正しく 0 を出力します。 「22222」のようなすべて偶数の文字列の場合、各インデックスは 1 から始まる位置を合計に寄与し、1+2+3+4+5 = 15 となります。「135792」のような交互パリティの場合、偶数の数字のみが位置 2 と 6 にあり、合計に 2+6=8 が寄与し、アルゴリズムが部分文字列を見逃したり二重にカウントしたりしないことが確認されます。
