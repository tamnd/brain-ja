 ## 解決策
 ## 問題の理解

 端が赤く着色された木があります (`0`) または黒 (`1`）。 長さのシーケンスが何個あるかを数えなければなりません`k`木の頂点で構成されるものは「良好」です。 

シーケンスの場合`[a₁, a₂, ..., aₖ]`、私たちは木の中の一意の最短経路に沿って繰り返し移動します。`a₁`に`a₂`、その後から`a₂`に`a₃`、 等々。 この全行程中に少なくとも 1 つの黒いエッジがどこかを横切った場合、シーケンスは良好であると見なされます。 

木には最大で`10^5`頂点、一方`k`せいぜい`100`。 可能なシーケンスの総数は次のとおりです。`n^k`、それは天文学的な大きさです。 すべてのシーケンスを反復処理することさえ不可能です。 ツリー自体に含まれているため、`10^5`頂点間のパスを繰り返し計算するソリューションも失敗します。 直線に近いものが必要です`n`。 

重要な問題は、シーケンスによって誘導されるパスの集合上に少なくとも 1 つの黒いエッジが存在するかどうかによって良さが定義されることです。 すべてのシーケンスを直接チェックすることは絶望的であるため、間接的にカウントする必要があります。 

すべてのエッジが黒の場合、微妙なエッジ ケースが発生します。```
4 2
1 2 1
2 3 1
3 4 1
```良くない唯一のシーケンスは、`[1,1]`、`[2,2]`、`[3,3]`、 そして`[4,4]`。 個別の頂点間の移動には、少なくとも 1 つの黒いエッジが使用されます。 黒いエッジの接続されたコンポーネントのみを調べるソリューションでは、構造が完全に見落とされてしまいます。 

もう 1 つの重要なケースは、すべてのエッジが赤である場合です。```
4 3
1 2 0
2 3 0
3 4 0
```黒いエッジを含むパスはないので、答えは次のようになります。`0`。 複数の頂点に接触するシーケンスをカウントする不注意な実装では、誤って肯定的な応答が報告されてしまいます。 

より微妙な例は次のとおりです。```
5 2
1 2 0
2 3 0
3 4 1
4 5 0
```頂点`{1,2,3}`赤のみの連結成分を形成します。 次のようなシーケンス`[1,3]`これらのパスは完全に赤いエッジの内側に留まるため、適切ではありません。 同じことが当てはまります`[5,5]`。 答えは、個々の頂点ではなく、赤のみのコンポーネントのサイズによって決まります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 長さのすべてのシーケンスを生成します`k`、ウォークをシミュレートし、少なくとも 1 つの通過エッジが黒かどうかを判断します。 

がある`n^k`シーケンス。 と`n = 10^5`そして`k = 100`, この数字は考えられる計算を超えています。 たとえ小さな値であっても、ツリー内のパスを繰り返し計算すると、すでにコストが高くなります。 ブルートフォース手法は定義を直接適用するため正しいですが、すぐに使用できなくなります。 

何かをより早く見つけるには、逆の質問について考えると役立ちます。 

良好なシーケンスを数える代わりに、**良くない** シーケンスをカウントします。 

すべての通過パスが完全に赤いエッジで構成されている場合、シーケンスは適切ではありません。 

ツリーから黒いエッジをすべて削除することを検討してください。 残りのグラフは、赤いエッジのみで形成される連結成分の集合です。 

シーケンス内のすべての頂点が同じ赤いコンポーネントに属していると仮定します。 この場合、連続する頂点間のすべての最短パスは完全にそのコンポーネントの内側に位置するため、通過したすべてのエッジは赤になります。 順番が良くない。 

シーケンスに 2 つの異なる赤色コンポーネントの頂点が含まれているとします。 これらのコンポーネント間のパスは、少なくとも 1 つの削除されたエッジ、つまり少なくとも 1 つの黒いエッジを横切る必要があります。 それからシーケンスは良いです。 

これは不良シーケンスを完全に特徴づけます。 

シーケンスは、そのすべての頂点が赤いエッジによって形成されるグラフの同じ連結コンポーネントに属している場合にのみ不良です。 

赤いコンポーネントにサイズがある場合`s`、その後、貢献します`s^k`シーケンス内のすべての位置がそのコンポーネントから任意の頂点を独立して選択する可能性があるため、シーケンスは不良になります。 

シーケンスの総数は`n^k`。 

したがって、次のようになります。`answer = n^k - Σ s^k`ここで、合計は赤色のすべての連結成分に及びます。 

これらのコンポーネント サイズは、黒いエッジを無視した DFS、BFS、または DSU を使用すると簡単に見つけられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k · n) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n + log k · コンポーネントの数) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 赤いエッジのみを使用してグラフを作成します (`x = 0`）。 

黒のエッジは、不良シーケンスを決定する赤のみの領域を区切るため、無視されます。 
2. DFS または BFS を使用して、この赤色のみのグラフのすべての接続コンポーネントを検索します。 

すべてのコンポーネントは、黒いエッジを使用せずに接続された頂点の最大セットを表します。 
3. コンピューティング`total = n^k mod M`、 どこ`M = 10^9 + 7`。 

これは、可能なすべてのシーケンスの数です。 
4. サイズの赤の各コンポーネントについて`s`、計算する`s^k mod M`そしてそれをから引きます`total`。 

すべての頂点がこのコンポーネント内にあるシーケンスはすべて不良です。 
5. すべての算術モジュロを実行します`10^9 + 7`。 
6. 最終結果を出力します。 

### なぜ効果があるのか

 黒いエッジを削除した後、頂点は赤い接続されたコンポーネントに分割されます。 

シーケンスのすべての頂点が同じコンポーネントに属している場合、連続する頂点間のすべてのパスは完全にそのコンポーネント内に留まり、赤いエッジのみが使用されます。 こういう順序はダメだ。 

シーケンスに異なるコンポーネントの頂点が含まれている場合、個別の赤いコンポーネントは黒いエッジなしで切断されるため、連続して選択された頂点間のパスの一部は黒いエッジを横切る必要があります。 こういう一連の流れは良いですね。 

不良シーケンスは、すべての頂点が存在するコンポーネントによって分割されます。 サイズの構成要素`s`まさに貢献する`s^k`悪いシーケンス。 すべてのコンポーネントを合計すると、すべての不良シーケンスが 1 回だけカウントされます。 

シーケンスの総数から不良シーケンスの数を引くと、正確に良好なシーケンスの数が残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, k = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, x = map(int, input().split())
        u -= 1
        v -= 1

        if x == 0:
            g[u].append(v)
            g[v].append(u)

    visited = [False] * n

    ans = pow(n, k, MOD)

    for start in range(n):
        if visited[start]:
            continue

        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in g[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        ans = (ans - pow(size, k, MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```グラフには赤いエッジのみが保存されます。 これがソリューションの中心的な観察です。 黒いエッジは不良シーケンスを生成する領域を分離するだけであるため、黒いエッジを横切ることに興味はありません。 

DFS は、赤色のすべての連結コンポーネントのサイズを計算します。 元のグラフはツリーであるため、赤のみのグラフには最大でも`n - 1`エッジなので、トラバースしても直線のままです。 

変数`ans`として始まります`n^k`、すべてのシーケンスの数。 各コンポーネントが貢献します`size^k`不正なシーケンスはすぐに減算されます。 

Python の組み込みを使用する`pow(base, exp, mod)`重要です。 価値観`n^k`そして`size^k`べき乗剰余を使用しないと巨大になります。 

減算はモジュロで実行されます`MOD`。 書き込み```
(ans - value) % MOD
```負の中間値を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + c log k) | DFS は各頂点を 1 回訪問し、各コンポーネントは 1 つの累乗剰余演算に寄与します。 
| スペース | O(n) | 隣接リスト、訪問済みアレイ、DFS スタック |

 ここ`c`赤色の接続コンポーネントの数です。最大で`n`。 以来`k ≤ 100`、べき乗剰余は事実上定数時間です。 このアルゴリズムはツリーのサイズが線形であり、制限内に簡単に適合します。`n = 10^5`。

## 特殊なケース

 全体が黒いエッジで構成されている木について考えてみましょう。```
4 2
1 2 1
2 3 1
3 4 1
```黒いエッジを削除すると、4 つの孤立した頂点が残ります。 コンポーネントのサイズは、`1,1,1,1`。 

アルゴリズムは以下を計算します。```
4² - 1² - 1² - 1² - 1²
= 16 - 4
= 12
```悪いシーケンスは次のとおりです。`[1,1]`、`[2,2]`、`[3,3]`、 そして`[4,4]`。 1 つおきのシーケンスは、少なくとも 1 つの黒いエッジを通過します。 

ここで、全体が赤いエッジで構成される木について考えてみましょう。```
4 2
1 2 0
2 3 0
3 4 0
```黒いエッジを削除しても何も変わりません。 サイズの要素は 1 つだけです`4`。 

アルゴリズムは以下を計算します。```
4² - 4² = 0
```すべてのパスは赤のみであるため、どの順序でも適切ではありません。 

最後に、混合色について考えてみましょう。```
5 2
1 2 0
2 3 0
3 4 1
4 5 0
```赤いコンポーネントにはサイズがあります`3`そして`2`。 

アルゴリズムは以下を計算します。```
5² - 3² - 2²
= 25 - 9 - 4
= 12
```不正なシーケンスとは、2 つの頂点の両方が属するシーケンスです。`{1,2,3}`または両方に属します`{4,5}`。 2 つのコンポーネントを接続するシーケンスはすべて黒いエッジを横切る必要があります`(3,4)`、それは良いことです。 これはまさにソリューションで重要な特性です。
