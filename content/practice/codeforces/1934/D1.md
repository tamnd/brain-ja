 ## アルゴリズムのチュートリアル

 現在の価値を維持します`x`から始まる`n`、一連の状態を構築します。 

1. もし`x == m`、すでに目標に到達しているため、すぐに停止します。 
2. 最上位ビットを見つけます。`x`そして`m`異なる。 このビットはそのままにしておきます`p`。 
3. 値を構築する`y`それは厳密に以下です`x`に設定されているビットのみを使用します`x`ただし、制約に違反する位置ではありません。 目標は作ることです`x XOR y`結果を以下に保ちながら、最も異なるビットを厳密に削減します。`x`。 
4. 操作を実行します`x = x XOR y`。 これが選択されるのは、XOR がキャリーのような増加を引き起こすことなく、選択されたビットをきれいに削除するためです。 
5. 新しいものを追加します`x`シーケンスに。 
6. まで繰り返します。`x == m`あるいは63歩に到達します。 

ステップ 3 内の重要な構成は、次のことを選択することです。`y`のサブマスクとして`x`の最高アクティブビットをターゲットとする`x`合法性を保ちながら。 これにより、`x XOR y`よりも厳密に小さいです`x`の最上位 1 ビットを削除するため、`x`新しい上位ビットを導入することなく。 

### なぜ効果があるのか

 不変条件は、すべてのステップで現在の設定の最高ビットを厳密に減らすことです。`x`、または、共有されていないすべてのビットの最終的な削除を保証する制御された方法でビット数を減らしながらそれを保存します。`m`。 XOR はビットを反転するだけであり、上位ビットが導入されないことを常に保証するため、シーケンスは辞書編集上のビット重要度において厳密に減少します。 整数は 60 ビット表現によって制限されるため、最大 63 回のリダクション内で終了する必要があります。 

さらに、選択するだけなので、各ステップは到達可能性を維持します。`y`両方とも`y < x`そして`x XOR y < x`、操作定義の正当性が保証されます。 この構造により、既存のセットビットのみを操作することでこれらの制約に違反することがなくなります。`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def highest_bit(x):
    return x.bit_length() - 1

def solve_one(n, m):
    if n == m:
        return [n]

    path = [n]
    x = n

    for _ in range(63):
        if x == m:
            break

        # find highest bit where x differs from m
        diff = x ^ m
        p = diff.bit_length() - 1

        # try to construct a y that clears this bit in x safely
        # take lowest set bit under constraint: use a single bit in x
        # at position p if possible, otherwise fallback to lowest set bit
        if (x >> p) & 1:
            y = 1 << p
        else:
            y = x & -x

        # ensure y < x
        if y == x:
            y = x & (x - 1)

        nx = x ^ y

        # safety adjustment: ensure valid transition
        if not (0 < y < x and 0 < nx < x):
            # fallback: remove lowest set bit
            y = x & -x
            nx = x ^ y

        path.append(nx)
        x = nx

    if x != m:
        return None
    return path

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        res = solve_one(n, m)
        if res is None:
            out.append("-1")
        else:
            out.append(str(len(res) - 1))
            out.append(" ".join(map(str, res)))
    print("\n".join(out))

if __name__ == "__main__":
    main()

フォールバック ロジックが必要なのは、厳密な制約の下では、最も異なるビットを直接選択することが必ずしも安全であるとは限らないためです。 最下位の設定ビットにフォールバックすると、有効性を維持しながら進行することが保証されます。

 ## 特殊なケース

 最も重要なエッジケースは次のような場合です`x`は 2 の累乗です。 その状況では、有効な`y`そのビットまたはそれより小さい数値に等しい必要があり、ほとんどの選択肢は違反します`x XOR y < x`。 最も低い設定ビットへのフォールバックにより、依然として削減できることが保証されます。`x`増加させたり制約を破ったりすることなく、安全に。

最後に、いつ`x`多くのビットが設定されているため、積極的な XOR を選択すると、誤ってより大きな中間値が生成される可能性があります。`x`。 シングルビット除去への不変式ベースのフォールバックは、そのようなエスカレーションを防ぎ、確実に単調降下します。`m`。
