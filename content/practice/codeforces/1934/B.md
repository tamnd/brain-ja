 ## 解決策
 ## 問題の理解

 コインの種類は 1、3、6、10、15 の固定セットが与えられています。クエリごとに、使用するコインの数を最小限に抑えることを目的として、任意の数のこれらのコインを使用して正確な合計値 n を構築する必要があります。 

ここでの重要な構造は、コインの種類は固定されており、その数は非常に少ないですが、n は最大 10 億と非常に大きくなる可能性があるということです。 これは、組み合わせを列挙したり、n を超える状態ベースの動的プログラミングを実行したりすることは不可能であることを即座に示唆しています。 ソリューションは、テスト ケースごとに一定の償却時間または非常に短い償却時間で答えを計算する必要があります。 

単純に解釈すると、これが最短経路またはナップザック形式の最小化問題に似ていると思われるかもしれません。 ただし、コインの価値とその特定の構造に対する制約は、貪欲または制限された分解アプローチを強く示唆しています。 

微妙なエッジ ケースの 1 つは、コイン システムが正規でない場合、純粋に最大コインに基づく貪欲な戦略が失敗する可能性があることです。 たとえば、1、3、4 のようなコインの場合、貪欲は 6 で失敗します (4+1+1 対 3+3)。 したがって、正当な理由なしに貪欲が機能すると仮定することはできません。 三角数の特殊な構造に依存する必要があります。 

もう 1 つのエッジ ケースは、n の値が小さく、最適な組み合わせが 1 つの大きなコインではなく、多くの小さなコインを混合する可能性がある場合です。 たとえば、n = 2 では 1 より大きいコインを使用できないため、2 つの 1 コインにフォールバックする必要があります。 どの戦略でも、より高額な額面の利用が可能であることを前提とすることなく、これらの低い値を正しく処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、これを古典的な無制限のナップザックとして扱います。各 n について、合計 x を形成するために必要なコインの最小数として dp[x] を計算します。 これには、5 種類のコインにわたる遷移が必要であり、テスト ケースごとに O(n) が与えられます。 n が最大 1e9 および最大 1e4 のテスト ケースでは、これは時間的にもメモリ的にも完全に不可能です。 

別の視点が必要です。 重要な観察は、コインセットが非常に小さく、構造化されているということです。 最大のコインは 15 で、すべてのコインは非常に狭い範囲の倍数または組み合わせです。 これは、n が大きい場合、解はできるだけ多くの 15 コインを使用することによって支配され、最適に処理できる残りはわずかであることを示唆しています。 

これは、有界残基戦略につながります。 最適なソリューションは次のように記述できます。 

n = 15k + r、r < 15

 重要な考え方は、使用する 15 コインの数を決めれば、残る問題はわずかな剰余 r だけであり、総当たりまたは事前計算によって最適に解決できるということです。 ただし、単純にフロア(n / 15) を取得することが常に最適であるとは限りません。15 コインを 1 枚減らすと、より小さなコインをより適切に組み合わせて合計コイン数を減らすことができる場合があるためです。 

したがって、k を正確に固定する代わりに、n // 15 付近の小さなウィンドウ (通常は k、k-1、k-2) を試します。最適な解決策は、コインの粒度によってわずかに異なるだけであるためです。 各候補 k について、剰余を計算し、小さな値に対して最適に解決します。 残りの部分は制限されているため (調整範囲に応じて、実際には 30 または 45 未満)、小さな DP を介して事前計算できます。 

したがって、問題は、テスト ケースごとに一定数の可能性を試行し、それぞれが O(1) で評価されることになります。

 | 貪欲に修正なし | お(1) | お(1) | 不正解 |

 ## アルゴリズムのチュートリアル

 5 つの金種の標準的な無制限コイン DP を使用して、固定制限 (たとえば 30 または 45) までのすべての値について小さな DP テーブルを事前計算します。 これにより、残りが少ない場合の正確な最小コイン数が得られます。 

各テスト ケースについて:

 1. k = n // 15 を計算します。これは、最大のコインのベースライン数です。

これが選択されるのは、15 が最大額面であり、多額の金額を効率的に支配するためです。 
2. k の候補値については、負の値をスキップして、k、k-1、および k-2 を検討します。 

その理由は、15 コインを 1 枚交換すると残りが 15 増えるためであり、場合によっては、これにより小さいコインの分解が大幅に改善されるからです。 
3. 各候補 k について、r = n - 15 * k を計算します。 

これにより、問題は小さな固定値インスタンスの解決に限定されます。 
4. r が事前計算された DP 範囲内にある場合、dp[r] をコストとして受け取ります。 

これにより、コイン 1、3、6、10、15 を使用して残りを形成する最適な方法が得られます。 
5. すべての候補にわたって k + dp[r] の最小値を追跡します。 

これにより、大量のコインの使用と最適な剰余分解が組み合わされます。 
6. 見つかった最小値を出力します。 

### なぜ効果があるのか

 最適な解決策は、使用する 15 コインの数と、それより小さいコインで構成される残りの数の選択として見ることができます。 15 コインを使いすぎると、修正に費用がかかるわずかな残りが残ります。 使用量が少なすぎると、広い範囲をカバーする際に効率が無駄になります。 最適解は、n // 15 の貪欲な選択に近いものでなければなりません。これは、k を小さな定数以上に変更すると、少なくとも 15 単位の値がシフトすることになり、そのようなシフトは、制限された範囲を超えた小型コイン システムの改善によって補償することができないためです。 

したがって、k を貪欲な選択の周りの一定の近傍に制限すると、問題を事前計算された有限状態空間にわたる定数時間の検索に軽減しながら、最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

coins = [1, 3, 6, 10, 15]

MAX_R = 45
INF = 10**9

dp = [INF] * (MAX_R + 1)
dp[0] = 0

for i in range(1, MAX_R + 1):
    for c in coins:
        if i >= c:
            dp[i] = min(dp[i], dp[i - c] + 1)

def solve():
    n = int(input())
    k = n // 15
    ans = INF

    for dk in [0, -1, -2]:
        kk = k + dk
        if kk < 0:
            continue
        r = n - 15 * kk
        if 0 <= r <= MAX_R:
            ans = min(ans, kk + dp[r])

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```DP テーブル`dp`はすべての小さな剰余に対して 1 回計算されます。 これは、複数のテスト ケースにわたる再計算を回避するため、非常に重要です。 

内部`solve`、15 コインという貪欲な数を中心にソリューションを固定します。 コイン システムは厳密には正規ではなく、局所的な調整によりコインの総数を改善できるため、近くの値を明示的にテストします。 

MAX_R = 45 を選択すると、k を最大 2 まで減らした後でも、残りは DP が有効な範囲内に留まることが保証されます。 この定数境界により、テスト ケースごとに O(1) が保証されます。 

## 実用的な例

 ### 例 1

 入力:

 n = 16

 k = 1 を計算します。 

| k | 剰余 r = n - 15k | dp[r] | 合計 k + dp[r] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 2 |
 | 0 | 16 | dp[16] = 2 | 2 |
 | -1 | 無効 | - | - |

 最小値は 2 で、15 + 1 または 10 + 6 として実現されます。 

これは、「大きいコイン 1 枚 + 小さい残り」と「中程度のコイン 2 枚」の両方が同様に最適であり、アルゴリズムが両方を正しく捕捉していることを示しています。 

### 例 2

 入力:

 n = 20

 k = 1

 | k | 剰余 r | dp[r] | 合計 |
 | --- | --- | --- | --- |
 | 1 | 5 | 3 | 4 |
 | 0 | 20 | dp[20] = 2 | 2 |

 最適な解決策は、15 コインをまったく使用しないことです。 代わりに、20 = 10 + 10 では 2 枚のコインのみが使用されます。 

これは、k-1 または k-2 調整を考慮する必要がある理由を示しています。 純粋に欲張って 15 を使用するのは次善の策です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | スペース | お(1) | DP テーブルは固定サイズ (≤ 45) |

 各クエリは定数演算と少数の配列検索のみを実行するため、このソリューションは 10^4 のテスト ケースを快適に処理します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    coins = [1, 3, 6, 10, 15]
    MAX_R = 45
    INF = 10**9

    dp = [INF] * (MAX_R + 1)
    dp[0] = 0

    for i in range(1, MAX_R + 1):
        for c in coins:
            if i >= c:
                dp[i] = min(dp[i], dp[i - c] + 1)

    def solve_case(n):
        k = n // 15
        ans = INF
        for dk in [0, -1, -2]:
            kk = k + dk
            if kk < 0:
                continue
            r = n - 15 * kk
            if 0 <= r <= MAX_R:
                ans = min(ans, kk + dp[r])
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve_case(n)))
    return "\n".join(out)

## 特殊なケース

 n = 2 の場合、1 より大きいコインは使用できません。 アルゴリズムは k = 0、r = 2 を評価し、dp[2] = 2 を使用して、2 つの 1 コインを正しく返します。 

n = 15 の場合、k = 1 は r = 0 となるため、答えは 1 になります。k を減らそうとすると、より小さいコインの数が増加し、より悪い結果が生じます。 

n = 20 の場合、アルゴリズムは k = 1 および k = 0 を明示的にテストします。2 番目の選択により、最適な dp[20] = 2 が得られます。 これは、正確さのために k の周囲の近傍検索が必要な理由を示しています。
