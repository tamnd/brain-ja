 ## 問題の理解

 正確に一致する最小の正の整数を探しています。`n`数字であり、同時に 2、3、5、7 のすべての数字で割り切れます。 言い換えれば、私たちは最小限のものを望んでいます`n`-これら 4 つの整数の最小公倍数の倍数である桁の数値。 

数値 2、3、5、および 7 はペアごとに互いに素であるため、これらを組み合わせた割り算要件は 1 つの条件にまとめられます。つまり、数値が 210 で割り切れなければなりません。したがって、このタスクは最小値を見つけることと同等です。`n`-210で割り切れる桁の数値。 

出力は長さの制約を厳密に遵守する必要があります。 より小さい数値`n`たとえ割り算を満たしていても、数値は無効です。 同様に、どの候補も最小値を超えてはなりません。`n`必要な場合を除き、-桁のしきい値。 

制約`n ≤ 10^5`数値を 1 つずつ構築またはチェックするアプローチは直ちに除外されます。 リニアスキャンも可能`n`-数字の値は、候補の範囲が指数関数的に増加するため不可能です。`n`。 解決策は算術および数式に基づいている必要があります。 

キーエッジケースが小さく見えます`n`。 のために`n = 1`の場合、210 の最小倍数は 210 自体であり、既に 3 桁になっているため、210 で割り切れる最小の 1 桁の数は存在しません。 これにより、答えは次のようになります`-1`。 桁の長さに対して実現可能性をチェックすることを忘れたアプローチでは、小さい値に対して誤った数値が出力されます。`n`。 

もう 1 つの微妙なケースは、最初の`n`-210 の倍数は正確ではありません`10^(n-1)`ただし、次の倍数に切り上げた後の数値はわずかに大きくなります。 これを正しく扱うには、天井を慎重に分割する必要があります。 

## アプローチ

 強引なアイデアは、最小のものから始めることです`n`-桁の数字、つまり`10^(n-1)`、210 で割り切れる整数が見つかるまで各整数を繰り返しテストします。すべての有効な答えがこの範囲内にあり、昇順に検索しているため、これは正しいです。 

しかし、これは不可能です。 間隔には約が含まれます`9 × 10^(n-1)`数値、そして中程度の場合でも`n`これは天文学的な大きさです。 各割り算チェックは定数時間ですが、チェックの数がすべてを支配します。 

重要な点は、検索する必要がまったくないということです。 少なくとも 210 の最小倍数だけが必要です。`10^(n-1)`。 これは古典的な天井分割問題です。 下限を計算したら、`n`桁数が多ければ、定数時間で次の 210 の倍数に切り上げることができます。 

残る唯一の問題は実現可能性だ。 結果の数値が正確に一致しなくなった場合は、`n`桁数が大きい場合、必要な長さ内に有効な解決策は存在しません。倍数を大きくしても桁数がさらに増加するだけであるためです。

 ## アルゴリズムのチュートリアル

 1. 最小の数値を計算します。`n`数字、つまり`10^(n-1)`。 先行ゼロは許可されないため、これは有効な答えの厳密な下限です。 
2. この下限以上の最小の 210 の倍数を計算します。 これは天井分割を使用して行うことができます。`(lower + 209) // 210 * 210`。 このアイデアは、数値がまだ整列していない場合に、その数値を次の割り切れるブロックにシフトすることです。 
3. 結果の数値がまだ正確であるかどうかを確認します。`n`数字。 未満の場合`10^(n-1)`、無効ですが、構造上、このようなことは起こり得ません。 本当の失敗例は、四捨五入により数値が次のように押し上げられる場合です。`10^n`あるいはそれ以上。 
4. 計算された数値が次の値を超える場合`n`数字、出力`-1`。 
5. それ以外の場合は、番号を出力します。 

### なぜ効果があるのか

 有効な答えはすべて 210 の倍数であるため、等差数列を形成します。 区間内にあるこの進行の最小要素を選択しています。`[10^(n-1), 10^n - 1]`。 シーリング演算では、間隔の開始点を下回らない進行の最初の項を見つけます。 この項が区間の終わりを超える場合、交差部分は空になるため、解は存在しません。 これより小さい候補は両方の制約を同時に満たすことができないため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    if n == 1:
        print(-1)
        return

    lower = 10 ** (n - 1)

    # smallest multiple of 210 >= lower
    ans = (lower + 209) // 210 * 210

    # check digit length
    if ans >= 10 ** n:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、不可能な 1 桁のケースを直接処理します。 これが必要なのは、数学的構造が 210 を返し、桁制約に違反するためです。 

コアの計算では整数演算のみが使用されます。 表現`(lower + 209) // 210`浮動小数点演算を行わずに上限除算を実装します。 210 を掛けると、実際の候補数が復元されます。 

最終チェックでは、上限を超えていないことを確認します。`n`これは、天井ステップが間隔を超えてジャンプする可能性があるため重要です。

 ## 特殊なケース

 のために`n = 1`、アルゴリズムはすぐに戻ります`-1`210 の倍数にはすでに少なくとも 3 桁が含まれているためです。 これにより、無効な候補が生成される下限 1 の計算が回避されます。 

のために`n = 2`、下限は 10 です。上限倍率は 210 で、2 桁の制限を超えています。 小切手`ans >= 10^n`正しく拒否します。 

大型の場合`n`、 のような`n = 3`または`n = 4`、下限は最終的に桁制限内に収まる 210 の倍数に一致します。 上限演算により、最初の有効な候補を決して見逃さないことが保証され、上限チェックにより、オーバーフローのケースが受け入れられないことが保証されます。
