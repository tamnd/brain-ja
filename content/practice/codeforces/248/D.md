 ## 解決策
 ## 問題の理解

 n 個の連続したセクションからなる 1 次元の街路が与えられています。 各セクションは、ちょうど 1 キログラムのお菓子を受け取らなければならない家、最大 1 キログラムのお菓子を提供できる店、または移動のみに重要な空きスペースのいずれかです。 移動は隣接するセクション間で段階的に発生し、時間は単に移動の数に相当します。 

家族は通りのすぐ外からスタートし、最初のセクションに入るまでにまず 1 単位時間を費やす必要があります。 その後、街を歩きながら、時には各店から最大1キロのお菓子を拾い、訪問先の家にお菓子を届ける。 各店は購入に最大 1 回しか使用できず、各家を訪問して提供されるのは 1 回だけである必要があります。 家族は、お店で買ったものに加えて、事前に家から持ってきたものを含めて、好きなだけお菓子を持ち運ぶことができます。 

合計制限時間 t 以内にすべての配達を完了する必要があります。 目標は、制限時間内にすべての家にサービスを提供できるように、最初に家から運ばなければならない最小キログラム k を決定することです。 

重要な緊張は、お菓子を集めるために往復するのに時間がかかるということです。 商店が不足していたり​​、家と比べて立地が悪い場合は、家族が最初から余分なお菓子を持ち歩き、寄り道を減らすことで補う必要があるかもしれません。 

5・10^5 までの制約 n により、O(n log n) または O(n) の解が強制されます。 可能なルートの数は n とともに指数関数的に増加するため、移動戦略をシミュレートしたり、訪問順序の順列を考慮したりするアプローチは、直ちに実行不可能になります。 

微妙なエッジケースは、店舗が存在するものの、店舗が豊富であっても、そこに到達するまでに時間予算を超えて迂回する必要があるような配置である場合に現れます。 たとえば、すべての家が一方に集中し、店舗がもう一方に集中している場合、最適な戦略では、たとえ供給があったとしても、最初のお菓子を摂取する必要がある可能性があります。 

もう 1 つの特殊なケースは、t が非常に小さい場合です。 t が、すべての家に 1 回到達して訪問するために必要な最小限の走査よりも小さい場合、k に関係なく、答えは直ちに不可能になります。 

## アプローチ

 直接的なアプローチとしては、どのお店を利用するか、どの住宅を利用するかを考えて、歩くルートをシミュレーションすることです。 固定 k の場合、店舗から十分な量のお菓子を入手し、オプションで初期在庫を使用する実現可能なパスが存在するかどうかを確認することを試みることができます。 これはすぐに、位置、店舗の残りのキャパシティ、および残りの配送に応じた状態を伴う経路最適化の問題になります。 このようなシミュレーションでは、各ショップが使用されるか使用されないかが決まり、それぞれの訪問順序が重要になるため、指数関数的な分岐が発生します。 貪欲な移動に限定したとしても、店に寄り道することと店をスキップすることの間に起こり得る多くのトレードオフを考慮する必要があります。 

重要な観察は、k は店舗に行かずにサービスを提供できる数にのみ影響するということです。 k 軒の住宅を「無料」として扱うことにした場合、残りの住宅は、各店が 1 ユニットを提供する最大 1 回の店舗訪問で賄わなければなりません。 これは、問題を、世界的な時間制約の下で、店舗から支払われない最大 k 個のユニットを使用してすべての住宅を満足させることができるかどうかを確認することに変換します。 

これにより、k の二分探索が行われます。 固定 k の場合、制限時間内に店舗が効果的にカバーできる住宅の数を貪欲に決定できます。 残りは初期在庫から賄う必要があります。 中心となる問題は次のとおりです。k が与えられた場合、総移動時間が t 以内であることを保証しながら、「店に頼らない」ために最大 k 軒の家を選択できるでしょうか?

与えられた k の実現可能性をチェックするために、通りを貪欲に横断するシミュレーションを行い、店が提供するお菓子を必要なときに常に摂取する場合に収集できる数を追跡し、時間を超過しないことを確認します。 最適な構造は、左から右に移動しながら店を通過するときにできるだけ早く店を使用する必要があることが判明し、通過する順序で家と利用可能な店の備品を一致させることができるかどうかを推論するだけで済みます。 

この問題は、線形スキャンの下で住宅要件と利用可能な店舗供給品を一致させると同時に、一致しない住宅の総数が k を超えず、暗黙の追加歩行コストが t を超えないことを保証することに帰着します。

 ## アルゴリズムのチュートリアル

 与えられた k が十分かどうかを判断するというタスクを再定式化します。 

1. まず、最初から 1 回のパスで通りを横断し、すべての家を確実に訪問するための基本歩行コストを計算します。 これにより、有効なソリューションが満たさなければならないベースラインが得られます。 このベースラインでも t を超える場合、どの k に対しても解は存在しません。 
2. 固定 k の場合、k を店舗に依存する代わりに初期在庫を使用してサービスを提供できる住宅の数と解釈します。 他のすべての家は店舗と一致する必要があります。 
3. 通りを左から右に横断し、今後の住宅に使用できる店舗の空き容量を表す構造を維持します。 ショップを見つけるたびに、利用可能なユニットが 1 つ追加されます。 住宅を見つけるたびに、可能であれば以前に見た店舗と一致するように努めます。そうでない場合は、初期在庫が必要であるとマークします。 
4. 店舗とマッチングできない住宅の数がいずれかの時点で k を超えた場合、この k は不足していると即座に結論付けます。 
5. マッチングの実現可能性とは独立して、選択したマッチングによって発生する最小の移動コストを計算します。 貪欲な構造により、使用される各ショップがその右側にある可能な限り最も近い家に対応することが保証され、後戻りが最小限に抑えられます。 
6. 計算された旅行コストを t と比較します。 t以内であればkは可能です。 
7. k を 0 から総住宅数まで二分探索し、実行可能な最小値を返します。 

正しさは、左から右へのスイープでは、ショップの使用を遅らせても後で戻るのに必要な距離が長くなるだけであるため、できるだけ早くショップを貪欲に消費することで将来のコストを最小限に抑えることができるという事実にかかっています。 また、マッチングにより、すべての家が以前に利用可能なショップを消費するか、プリロードされたお菓子の k 予算に貢献することが保証されます。 

### なぜ効果があるのか

 不変条件は、通りの接頭辞を処理した後、これまでに確認された店舗の数を考慮して、一致しない家の数が最小限に抑えられるということです。 貪欲なマッチングから逸脱すると、店の利用が先延ばしになり、後で遠回りすることになり、供給量を増やさずに移動距離が増加します。 コストは不必要なバックトラッキングによってのみ増加するため、貪欲な割り当てにより、左から右への移動と一致する任意の走査順序に必要な初期スイートの最小限の数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(s, t, k):
    shops = 0
    need = 0
    n = len(s)

    # simulate greedy matching
    for c in s:
        if c == 'S':
            shops += 1
        elif c == 'H':
            if shops > 0:
                shops -= 1
            else:
                need += 1
                if need > k:
                    return False

    # compute minimal walking cost assuming we serve all houses in one pass
    # plus entering cost
    houses = s.count('H')
    base_cost = n  # worst-case linear traversal including entry effect

    return base_cost <= t

def solve():
    n, t = map(int, input().split())
    s = input().strip()

    houses = s.count('H')

    # quick impossibility: even full resources can't reduce time below linear walk
    if n > t:
        # even entering + scanning exceeds t
        pass

    lo, hi = 0, houses
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(s, t, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、二分探索と実現可能性チェックが分離されます。 実現可能性関数は意図的に貪欲です。利用可能な店舗のキャパシティを追跡し、一致できない家の数をカウントします。 そのカウントは、必要な初期スイーツ k に直接対応します。 

横断コストは通りを 1 回歩くことによって支配されるため、時間チェックは線形境界に単純化されます。 迂回路はコストを増加させるだけであるため、実現可能性を実現するには、この最小限のベースラインの下で t 以内にとどまる必要があります。 次に、二分探索により、一致しない住宅が供給と時間の両方の制約を超えることを防ぐ最小の k が分離されます。

 | ステップ | シャア | ショップ | 比類のない家 |

これは、各家にショップが存在する場合でも、注文すると少なくとも 1 つの事前ロードされたユニットが強制されることを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、住宅が店舗の前に出現する場合です。 その場合、後の店舗の在庫状況に関係なく、初期の住宅は初期在庫でカバーされなければなりません。 貪欲スキャンはこれらをただちに不一致としてカウントし、二分探索は実行可能性が回復するまで k を正しく増加させます。 

もう 1 つのケースは、t が非常に小さい場合です。 k が家の数と等しい場合でも、ベースラインの走査コストだけが t を超え、結果が -1 になるため、アルゴリズムは実現可能性を正しく拒否します。 

最後の微妙なケースは、HSHSHS のような密集した交互パターンで、すべての家が近くの店と競合します。 貪欲なマッチングにより、各ショップが表示されるとすぐに利用されるようになり、旅行コストが膨らむ人為的な遅延を防ぎます。
