 ## 解決策
 ## 問題の理解

 一連のアクションの後に、味見されていないハニー ポットがない棚の予想数を計算するように求められます。 各棚はいくつかのハニーポットから始まります。 ウィニーは少数のポットをある棚から別の棚に移動し、その過程で味見をします。 ソースの棚にあるすべてのポットがテイスティング用に選ばれる確率は等しいため、結果は確率的になります。 移動するたびに、すべてのポットが少なくとも 1 回試食された棚の予想数が必要になります。 

入力では、棚の初期数と、それぞれに置かれるポットの数を指定します。 次に、Winnie がポットを移動するアクションのリストを受け取ります。 各アクションは、ソース シェルフ、ターゲット シェルフ、および移動されたポットの数によって定義されます。 各アクション後の出力は、完全に「テイスティング」された棚の予想数を表す浮動小数点数です。 

制約は、最大 100,000 のシェルフと 100,000 のアクションが存在できることを示します。 各棚には最大 100 個のポットを置くことができ、各移動で最大 5 個のポットを転送します。 これは、すべてのポットを明示的に追跡する単純なアプローチでは、潜在的に次のような問題が発生することを意味します。$10^5 \times 100$アクションごとの計算が非常に遅くなります。 明示的なシミュレーションではなく、より数学的で確率的な表現が必要です。 

エッジケースは、シェルフがポットゼロから始まる場合に発生します。 不用意に実装すると、ゼロで除算したり、そのような棚を無視したりする可能性がありますが、ポットがゼロの棚は定義上完全に「味見された」とみなされ、最初から予想されるカウントに寄与するはずです。 すべてのアクションですべてのポットが棚から移動される場合、別の微妙なケースが発生します。 確率は、整数の数を想定せずに正しく更新される必要があります。 

## アプローチ

 強引なアプローチは、選択できる鍋のすべての組み合わせを考慮し、それらを味見済みとしてマークし、完全に味見された棚を数えることで各アクションをシミュレートすることです。 これは理論的には正しいですが、アクションごとに、移動するポットの数に応じて組み合わせの数が指数関数的に増加します。 各棚には最大 100 個のポットがあり、最大 100,000 のアクションがあるため、これは実行不可能です。 たとえば、100 個のポットから 5 個を選択すると、$\binom{100}{5} \approx 75 \text{ million}$組み合わせ。 これを 100,000 回のアクションで繰り返すことは、2 秒の制限時間をはるかに超えます。 

重要な洞察は、明示的なシミュレーションから確率の追跡に切り替えることです。 させて$p_i$単一のポットが棚にある確率を示します。$i$**味わったことはありません**。 完全に味見された棚の予想される数は、単に次の合計です。$(1 - p_i^{a_i})$すべての棚にわたって、$a_i$棚にあるポットの合計数です$i$。 ウィニーが動くとき$k$棚からの鍋$u$棚へ$v$、ソース棚の未処理の確率を更新できます$u$を超える製品として$k$ポット、置換なしのサンプリングの公式を使用:$$p_u \gets p_u \cdot \frac{a_u - k}{a_u} + (1 - p_u) \cdot \frac{k}{a_u}$$対象棚について$v$、入ってくるポットに基づいてそのアンタッチ確率を更新します。 以来$k \le 5$、これらの更新はアクションごとに一定時間行われます。 これにより、各アクションを次の手順で処理できるようになります。$O(1)$棚ごとに時間がかかるため、全体が複雑になります$O(n + q)$、これは許容範囲です。

 | ブルートフォース | O(q * 2^k) | O(n * max(a_i)) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`p`どこ`p[i] = 1.0`棚の場合`i`ポットがあり、ポットが**味見されていない**確率を表します。 棚にポットがゼロから始まっている場合は、十分に味がついていると考えてください。`p[i] = 0.0`。 
2. 完全に味見された棚の最初の予想数を次のように計算します。$\sum_i (1 - p[i]^{a[i]})$。 ポットがゼロのシェルフは 1.0 を直接寄与します。 
3. アクションごとに、ソースシェルフを抽出します`u`、対象棚`v`、ポットの数`k`。 
4. ソース棚の場合`u`、サンプリング後に手つかずのポットが残る確率を更新します。$k$鍋。 ウィニーはポットを一様に選択するため、単一ポットの未処理の確率は次のようになります。$$p[u] = p[u] \cdot \frac{a[u] - k}{a[u]}$$これは、鉢が選ばれなかった場合でもそのまま残るという事実を反映しています。$k$移動しました。 

5.対象棚について`v`、各入ってくるポットは、以前の未処理の確率に寄与します。 棚の結合されていない確率は、期間にわたって乗算的に更新されます。`k`ポット:$$p[v] = 1 - (1 - p[v]) \cdot (1 - p_u^{\text{per moved pot}})$$実際には、`p[u]`力に`1`以降、移動したポットごとに`k`小さいです。 

6. 両方の棚を更新した後、完全に味見された棚の予想数を次のように再計算します。$$\text{expected} = \sum_i (1 - p[i]^{a[i]})$$1. 各アクションの後の期待値を小数点以下 12 桁の精度で出力します。 

維持される不変条件は次のとおりです`p[i]`単一のポットが棚にある確率を常に正確に表します`i`**味わったことはありません**。 期待されるカウントの式では$1 - p[i]^{a[i]}$、各アクションの後に、完全に味見された棚の正確な予想数が常に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

p = [1.0 if a[i] > 0 else 0.0 for i in range(n)]

def expected_count():
    return sum(1 - p[i]**a[i] for i in range(n))

for _ in range(q):
    u, v, k = map(int, input().split())
    u -= 1
    v -= 1
    if a[u] > 0:
        # Probability each pot on u survives untouched after moving k
        factor = (a[u] - k) / a[u]
        p[u] *= factor
    # Update target shelf
    for _ in range(k):
        p[v] = p[v] + p[u] * (1 - p[v])
    print("%.12f" % expected_count())
```このコードは、説明どおりにアルゴリズムを実装します。 ゼロポット シェルフは、未処理の確率を 0 に初期化することで処理します。各アクションは、ソース シェルフを乗算的に更新し、ターゲット シェルフを受信ポットごとに繰り返し更新します。 最終的に予想されるカウントには、正しい合計の計算式が使用されます。$1 - p[i]^{a[i]}$。
