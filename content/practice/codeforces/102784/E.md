 ## 解決策
 # 問題の理解

 フランシーヌは個人の数字のコレクションを持っており、それらのいくつかを、バスターが不気味だと考える最大の数字に配置したいと考えています。 不気味な数字は、2、3、5 で割り切れる非負の整数で、30 で割り切れるのと同じです。アーサーが不要な数字を追加したため、いくつかの数字を破棄することはできますが、残りの数字は可能な限り最大の値を形成する必要があり、不必要な先行ゼロを含めることはできません。 

入力により、使用可能な桁数が与えられ、次に桁そのものが与えられます。 出力は、これらの数字から作成できる 30 で割り切れる最大の整数です。そのような数値が存在しない場合は、次のように出力されます。`-1`。 

この制約では、最大 100,000 桁が許可されます。 候補の数が指数関数的に増加するため、さまざまな配置を試したり、多くの可能なサブセットをチェックしたりするアプローチは不可能です。 桁の大部分のすべての順列を試しても、すぐに使用可能な時間を超えてしまいます。 このソリューションでは、数字を一定回数処理する必要があります。これは、O(n) または O(n log n) メソッドを指します。 

不用意に実装すると失敗するケースがいくつかあります。 ゼロはゼロ以外のすべての約数で割り切れるため、単一のゼロが有効な答えとなります。 たとえば、入力```
1
0
```生産しなければならない```
0
```先頭にゼロ以外の数字を必要とするソリューションは、それを誤って拒否します。 

もう 1 つの罠は、30 で割り切れるには最後にゼロが必要であることを忘れていることです。 例えば、```
4
3 3 6 6
```桁の和は 18 で、3 で割り切れ、偶数桁が含まれていますが、ゼロはありません。 正しい出力は次のとおりです```
-1
```5で割り切れる配列はないからです。 

最後によくある間違いは、桁の合計を修正するときに間違った桁を削除することです。 考慮する```
5
1 1 1 2 0
```合計は 5 なので、合計を 3 で割り切れるようにするには 1 桁削除する必要があります。`2`最大の答えが得られます。```
1110
```を削除する`1`与える`2100`、これは小さいです。 削除プロセスでは、可能な限り最大の残りの数を保持する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、利用可能な数字の可能なサブセットを生成し、選択した各サブセットを降順に並べ、結果の数値が 30 で割り切れるかどうかを確認することです。これは正しいです。考えられるすべての有効な答えが候補の中から表示され、後で最大のものを選択できるからです。 

問題は、最大 100,000 桁があることです。 サブセットの数は 2^n であり、そのごく一部を保存したりチェックしたりすることさえ不可能です。 この強引なアプローチは、何が重要かを正確に説明する割り算ルールを使用するのではなく、数字を独立した選択肢として扱うため、失敗します。 

重要な観察は、30 で割り切れる構造は非常に単純であるということです。 30 で割り切れる数値は 10 で割り切れる必要があるため、末尾にゼロを含める必要があります。 また、3 で割り切れる必要があります。これは、その桁の合計にのみ依存します。 他の数字の正確な順序は、3 で割り切れる可能性には影響しません。 

問題は、どの桁を削除するかを選択することです。 可能な限り大きな数値が必要なので、できるだけ多くの桁を保持する必要があります。 桁の合計がすでに 3 で割り切れる場合は、使用可能なすべての桁を降順に並べ替えるだけで済みます。 それ以外の場合は、合計が 3 で割り切れる最小の桁数を削除します。その後、残りの桁を並べ替えることで、最大の配置が得られます。 

削除に重要な桁は、3 を法とした剰余のみです。合計を 3 を法として 1 減らすには、剰余 1 を持つ最小の桁を削除します。3 を法として 2 減らすには、剰余 2 を持つ最小の桁を削除します。1 桁が使用できない場合は、反対側の剰余の 2 桁を削除すると、同じ効果が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての桁を数え、その合計を計算します。 合計は 3 を法とする現在の剰余を示します。これは、3 で割り切るために必要な唯一の情報です。 
2. 少なくとも 1 つのゼロがあるかどうかを確認します。 ゼロが存在しない場合、その数は 10 で割り切れないため、不気味な数は存在できません。 
3. 桁の合計が 3 で割り切れない場合は、余りを確定する可能な最小の桁または桁のペアを削除します。 削除された値が小さいほど、最終的な数値は大きくなります。 
4. 残りの数字を降順に並べ替えます。 同じ桁の数値は、最上位の桁が最初に表示されたときに最大になります。 
5. 結果の数字を出力します。 残りの表現がゼロのみの場合は、先行する複数のゼロの代わりに単一のゼロを出力します。 

機能する理由: このアルゴリズムは、3 の割り算ルールで必要な場合にのみ桁を削除します。削除する桁数が少なくても、常に桁数が多い数値が保持されます。これは、同じコレクションから作成された桁数が少ない数値よりも大きくなります。 削除が必要な場合、削除可能な最小の数字を選択すると、最大の残りの数字のマルチセットが残ります。 最後に、降順で並べ替えると、そのマルチセットから最大数が生成されます。 ゼロの存在は 10 で割り切れることを保証し、修正された桁の合計は 3 で割り切れることを保証するため、結果は常に 30 で割り切れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    digits = list(map(int, input().split()))

    if 0 not in digits:
        print(-1)
        return

    total = sum(digits)
    rem = total % 3

    if rem != 0:
        removed = False

        for i, d in enumerate(digits):
            if d % 3 == rem:
                digits.pop(i)
                removed = True
                break

        if not removed:
            need = (3 - rem) % 3
            to_remove = []
            for i, d in enumerate(digits):
                if d % 3 == need:
                    to_remove.append(i)
                    if len(to_remove) == 2:
                        break

            if len(to_remove) < 2:
                print(-1)
                return

            for i in reversed(to_remove):
                digits.pop(i)

    digits.sort(reverse=True)

    if digits[0] == 0:
        print(0)
    else:
        print("".join(map(str, digits)))

if __name__ == "__main__":
    solve()
```この解決策は、いくら並べ替えてもゼロで終わる数値を作成できないため、最初にゼロのないケースを拒否します。 これにより、不必要な作業が回避され、10 で割り切れる要件が直接処理されます。 

桁の合計は、削除が必要かどうかを決定するために使用されます。 1 桁を削除すると、削除された桁が小さいほど大きな答えが保持されるため、コードは必要な剰余を持つ最小の桁を検索します。 1 桁では不十分な場合は、同じ結合剰余効果で 2 桁が削除されます。 

最後の降順ソートは、選択した数字を可能な限り最大の整数に変換するものです。 特別なチェックは、`digits[0] == 0`残りのすべての桁がゼロである場合を処理し、次のような出力を防ぎます。`0000`。 

アルゴリズムは決して数値を数値的に構築しないため、Python の整数はここではオーバーフローしません。 回答を数字の文字列として構築します。回答には 100,000 桁が含まれる可能性があるため、これが必要になります。

 ## 特殊なケース

 ゼロのみの場合:```
1
0
```このアルゴリズムはゼロを見つけ、ゼロの桁合計の残りを計算し、削除をスキップし、リストを並べ替えて、最初の桁がゼロであることを確認します。 ゼロを 1 つ出力します。 これにより、先頭にゼロ以外の数字がないためにゼロを無効な数値として扱うというよくある間違いを防ぐことができます。 

ゼロが欠落している場合:```
4
3 3 6 6
```ゼロが存在しないため、アルゴリズムはすぐに 10 で割り切れる要件を満たしません。 出力します`-1`数字の削除を試みる前に。 有効な不気味な数字はすべてゼロで終わる必要があるため、数字を削除しても役に立ちません。 

桁の合計を修正する必要がある場合:```
5
1 1 1 2 0
```合計は 5 で、3 を法とした余り 2 が残ります。アルゴリズムは余り 2 の数字を検索し、その数字を削除します。`2`。 残りの数字の合計は 3 で、ゼロが含まれており、次のように分類されます。`1110`。 何かを削除する`1`代わりに、より小さい数値が残ります。 

複数のゼロの場合:```
3
0 0 0
```考えられるすべての配置はゼロを表します。 並べ替え後、アルゴリズムは最初の桁がゼロであることを検出し、1 桁だけを出力します。 これにより、数学的値を維持しながら表現の問題が処理されます。
