 ## 解決策
 ## 問題の理解

 タスクは、2 つのカボチャの図面が同じトポロジを持つかどうかを判断することです。 彫刻領域の実際の形状は重要ではありません。 重要なのは、接続されたカボチャの果肉部分と接続された穴の間の入れ子関係です。 浮いているカボチャの部分の中に穴があるか、穴の中に浮いているカボチャの部分は、この階層に別のレベルを作成します。 この問題は、2 つの図面がコンポーネントの同じルート階層を記述しているかどうかを尋ねます。 

各図面は長方形のグリッドです。 あ`.`細胞はカボチャの果肉に属しており、`#`セルはホールに属します。 4 方向の移動によって接続された同じ種類のセルが 1 つのコンポーネントを形成します。 すべてのコンポーネントには、ルートである外側のカボチャの果肉コンポーネントを除き、反対のタイプの親コンポーネントが 1 つだけあります。 

寸法は最大 150 x 150 であるため、グリッドには最大 22500 個のセルが含まれます。 グリッドを一定回数探索するソリューションは、十分に高速です。 ただし、考えられるコンポーネントのすべてのペアを比較したり、形状を直接一致させようとすると、不必要な作業が発生し、階層のみが重要であるという事実が無視されます。 

厄介なケースは、ジオメトリとトポロジを混同することによって引き起こされます。 2 つの領域の外観は完全に異なっていても、同じ入れ子構造を持つことができます。 たとえば、肉で囲まれた 1 つの穴は、穴の形状に関係なく、外側の肉の内側に 1 つの穴がある他の図面と一致する必要があります。```
Input

.....
.###.
.....

.....
.###
.....

Output
YES
```座標や正確なアウトラインを比較する不注意な実装では、トポロジが同一であっても、これらが拒否されます。 

もう 1 つのよくある間違いは、繰り返される子構造を無視することです。 外側の肉の内側にある 2 つの穴は視覚的に交換できますが、子は順序付けされていないため、答えは同じままです。```
Input

YES
```BFS によって検出された順序で子を格納するソリューションでは、同じトポロジに対して異なる記述が生成される場合があります。 

最後のエッジ ケースは、数レベルの深さでネストされたコンポーネントを含むコンポーネントです。```

```外側のカボチャの内側の穴を直接カウントするだけの浅い比較では、より深いネストが見逃されてしまいます。 

## アプローチ

 簡単なアプローチは、各セルをグラフの一部として扱い、完全なグリッド構造を比較することです。 これは正しいです。グリッドにはコンポーネントに関するすべての情報が含まれていますが、問題に無関係であると明示的に示されている情報も保持されているからです。 2 つの等しいトポロジは、異なる寸法、位置、形状を持つ可能性があるため、直接比較しても実際の問題は解決されません。 

より洗練された総当たりアプローチでは、接続されているすべてのコンポーネントを見つけて、一方のカボチャのコンポーネントをもう一方のカボチャのコンポーネントと照合しようとします。 コンポーネントが多い場合、一致する子を繰り返し検索するとコストが高くなります。 最悪の場合、考えられるすべてのコンポーネントのペアを比較するには、約 O(K²) 回の比較が必要になります。ここで、K はコンポーネントの数です。 150 x 150 のグリッドでは、K は 22500 に近づく可能性があるため、このアプローチは遅すぎます。 

重要な観察は、すべてのコンポーネントはその下の構造によってのみ表現できるということです。 コンポーネントのアイデンティティはそのセルに依存しません。 それは、それに含まれる子コンポーネントのコレクションによって異なります。 子には順序がないため、すべての子を再帰的に表現し、それらの表現を並べ替えることによって正規表現を作成できます。 

この場合、問題はツリー比較問題になります。 まず、カボチャの果肉と穴が交互に配置された根付きツリーを構築し、次に各ツリーのルートの標準形式を計算します。 正規形が等しいということは、トポロジーが等しいことを意味します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(K² + RC) | O(K) | 遅すぎる |
 | 最適 | O(RCログ(RC)) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド内のすべての接続コンポーネントに塗りつぶしのラベルを付けます。 各コンポーネントには、そのキャラクター タイプ (肉体またはホール) が格納されます。 フラッド フィルは、1 つのトポロジ単位に属するセルを正確にグループ化します。 
2. すべてのコンポーネントの隣接するセルをチェックして、コンポーネント ツリーを構築します。 コンポーネントが反対のタイプのコンポーネントにタッチすると、タッチされたコンポーネントは階層内の子になります。 外側の肉の部分が根になります。 
3. すべてのコンポーネントの正規記述を計算します。 コンポーネントは、そのタイプとその子の正規の説明のソートされたリストによって表されます。 トポロジを変更せずに 2 つの子を任意の視覚的順序で表示できるため、並べ替えが必要です。 
4. 両方のカボチャのルート コンポーネントの正規記述を生成し、それらを比較します。 同一の場合は印刷します`YES`; それ以外の場合は印刷します`NO`。 

機能する理由: ツリー内のすべてのコンポーネントは、ツリー内に直接ネストされているコンポーネントによって決まります。 正規の記述は、この関係を正確に再帰的に記録します。 ソート手順により、描画順序への依存が排除されます。 帰納法により、リーフ コンポーネントは、それらが同じ型である場合に正確に同じ表現を受け取り、すべてのより大きなコンポーネントは、そのすべての子が順序付けされていないコレクションとして一致する場合に正確に同じ表現を受け取ります。 ルートはカボチャ全体を表すため、ルートが等しい表現はトポロジーが等しいことを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

def build_tree(grid):
    r = len(grid)
    c = len(grid[0])

    comp = [[-1] * c for _ in range(r)]
    types = []
    cells = []

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    cid = 0
    for i in range(r):
        for j in range(c):
            if comp[i][j] == -1:
                ch = grid[i][j]
                stack = [(i, j)]
                comp[i][j] = cid
                current = []

                while stack:
                    x, y = stack.pop()
                    current.append((x, y))
                    for dx, dy in dirs:
                        nx, ny = x + dx, y + dy
                        if 0 <= nx < r and 0 <= ny < c:
                            if comp[nx][ny] == -1 and grid[nx][ny] == ch:
                                comp[nx][ny] = cid
                                stack.append((nx, ny))

                types.append(ch)
                cells.append(current)
                cid += 1

    children = [[] for _ in range(cid)]

    for idx, current in enumerate(cells):
        seen = set()
        for x, y in current:
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < r and 0 <= ny < c:
                    other = comp[nx][ny]
                    if other != idx and other not in seen:
                        seen.add(other)
                        children[idx].append(other)

    root = -1
    for i, ch in enumerate(types):
        if ch == '.':
            parent_is_hole = False
            if not any(types[x] == '#' for x in children[i]):
                pass
            if i == comp[0][0]:
                root = i
                break

    memo = {}

    def canonical(v):
        if v in memo:
            return memo[v]
        child_forms = [canonical(u) for u in children[v]]
        child_forms.sort()
        result = types[v] + "(" + "".join(child_forms) + ")"
        memo[v] = result
        return result

    return canonical(root)

def solve():
    data = sys.stdin.read().splitlines()
    if not data:
        return

    r, c = map(int, data[0].split())
    pos = 1

    first = []
    while len(first) < r:
        first.append(data[pos])
        pos += 1

    while pos < len(data) and data[pos] == "":
        pos += 1

    second = data[pos:pos + r]

    a = build_tree(first)
    b = build_tree(second)

    print("YES" if a == b else "NO")

if __name__ == "__main__":
    solve()
```フラッド フィル セクションは、生のグリッド セルを意味のあるトポロジー コンポーネントに変換します。 コンポーネント ID マトリックスにより、後で関係を構築するときに繰り返し検索を実行することが回避されます。 

コンポーネント ツリーは、異なるセル タイプ間の隣接関係から構築されます。 入力によって適切な包含が保証されるため、隣接する反対色のコンポーネントは常にトポロジ内の直接の親子関係を表します。 

正規関数は、サブツリー全体を文字列に再帰的に圧縮します。 トポロジは順序付けされていないツリーであるため、子の表現の並べ替えは重要な詳細です。 2 つの同じ目を持つカボチャは、それらの目が異なる位置にある別のカボチャと一致する必要があります。 

ルートは保証された外境界条件から見つけられます。 境界線は常にカボチャの果肉であるため、左上のセルを含むコンポーネントは外側のカボチャ部分です。 これにより、内部のフローティング カボチャ コンポーネントを誤って選択することがなくなります。

| ステップ | コンポーネント | 子どもたち | 正規形 |

.###.
.....
```階層はさらに深いです。 

| ステップ | コンポーネント | 子どもたち | 正規形 |
 | --- | --- | --- | --- |

 ## 特殊なケース

 最初のエッジ ケースは、異なる形状で描画された 2 つの同一の階層です。 アルゴリズム フラッドは両方の図面をコンポーネントに埋め込み、コンポーネントの作成後にセル ジオメトリを破棄します。 正規表現ではネスト関係のみが保持されるため、両方の描画で同じルート表現が生成されます。 

2 番目の特殊なケースは、順序付けられていない子です。 外側のカボチャに 2 つの穴があり、1 つは島があり、もう 1 つは空だとします。 これらのホールが別の場所に表示される場合、子の走査順序は変わります。 このアルゴリズムは、子表現を結合する前にソートするため、同じ子のコレクションからは常に同じ正規形式が生成されます。 

3 番目のエッジ ケースは、深いネストです。 穴にはカボチャの破片を含めることができ、さらに多くの穴を含めることもできます。 再帰標準関数はリーフ コンポーネントに到達するまで継続し、その後、答えを上方に構築します。 すべてのネスト レベルが最終的な表現に寄与するため、内部レイヤーが欠落していても、誤って同等として渡されることはありません。
