 ## 解決策
 # 問題の理解

 私たちには、`N`巣穴。 各頂点には 1 つのタランチュラが含まれており、すべてのタランチュラは次のいずれかに属します。`K`亜種。 トンネルは接続されたツリーを形成するため、2 つの巣穴の間には 1 本の経路が存在します。 すべての亜種について、その亜種を持つ 2 つの頂点間の最大距離が必要です。 亜種が 1 回だけ出現する場合、その範囲はゼロです。 

入力サイズが到達しました`N = 200000`、したがって、タランチュラのすべてのペアを検査する解決策は不可能です。 すべての頂点を持つ単一の亜種は、すでに約`N^2 / 2`これは数秒で実行できる速度をはるかに超えています。 線形または`N log N`なぜなら、それによって操作数が数百万程度に抑えられるからです。 

難しいのは、1 つの亜種の頂点が必ずしも接続されているわけではないということです。 通常の木の直径アルゴリズムは、木全体が 1 つのセットである場合に機能しますが、ここでは同時に多くの直径 (色ごとに 1 つ) が必要です。 

単純な考えを壊すいくつかのケースを考えてみましょう。 すべてのタランチュラに異なる亜種がある場合、すべての答えはゼロでなければなりません。 例えば：```
Input:
5 5
1 2 3 4 5
1 2
2 3
3 4
4 5

Output:
0
0
0
0
0
```すべての色に少なくとも 2 つの頂点があると仮定したソリューションでは、欠落しているエンドポイントにアクセスすることになります。 

2 番目の罠は、ある亜種の頂点が他の亜種によって分離される可能性があることです。 例えば：```
Input:
5 2
1 2 1 2 1
1 2
2 3
3 4
4 5

Output:
4
2
```亜種 1 の 3 つの頂点は、パスの両端と中央にあります。 隣接する同じ色だけを見ると、実際の直径を見逃してしまいます。 

3 番目の問題は、重心が正しく使用されていない場合に発生します。 重心の同じ子サブツリー内の 2 つの頂点には、その重心を通過するパスがありません。 重心を通る距離を組み合わせると、実際の距離が過大評価されてしまいます。 

## アプローチ

 簡単なアプローチは、各亜種の頂点を収集し、その直径を個別に計算することです。 1 つの色については、任意の頂点を選択し、ツリー トラバーサルを実行して最も遠い頂点を見つけ、その頂点から別のトラバーサルを実行できます。 これは、標準的な 2 BFS または DFS 直径方法です。 ツリーの端点から最も遠い頂点には直径の端点が含まれるため、これは正しいです。 

問題は繰り返し作業です。 1 つの亜種にすべてが含まれる場合`N`頂点、単一直径の計算にはすでにコストがかかります`O(N)`。 多くの亜種に対してそれを繰り返すと、`O(NK)`、色の分布が悪い場合、これは次のようになります。`O(N^2)`。 

重要な点は、グラフがツリーであるため、重心分解によって作業が分割される可能性があるということです。 重心はツリーをより小さなコンポーネントに分割します。 すべての重心について、その重心をパスが通過する有効な頂点のペアはすべて、重心からの距離を調べることで評価できます。 分解により、頂点のすべてのペアが、パスが分割される正確に 1 つの重心で考慮されることが保証されます。 

1 つの重心について、その子コンポーネントを 1 つずつ処理します。 すべての亜種について、以前のコンポーネントで確認された最大距離を記憶します。 現在のコンポーネントに同じ亜種の頂点が見つかった場合、それを前の最大値と組み合わせると、パスが重心を横切る最適なペアが得られます。 すべての子コンポーネントが処理された後、残りの各コンポーネントを再帰的に解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 重心分解 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを構築し、各亜種に属する頂点のリストを保存します。 頂点が 2 つ未満の色にはすでに正しい答えがあるため、答えの配列は 0 から始まります。 
2. 現在のツリー コンポーネントの重心を見つけます。 重心とは、削除しても現在のコンポーネントの半分以下のコンポーネントが残る頂点です。 
3. 重心を、それを通過するパスの 1 つの可能な終点として扱います。 独自の亜種の距離ゼロを保存します。 
4. 重心のすべての隣接コンポーネントについて、DFS を実行して、そのコンポーネント内のすべての頂点と重心からの距離を収集します。 収集中に、各頂点を、以前に処理されたコンポーネントで見つかった同じ亜種の最適距離と比較します。 これが機能するのは、これら 2 つの頂点間のパスが重心を通過する必要があるためです。 
5. 収集した距離を、この重心に対して保存されている最適な距離にマージします。 重心を通る最後のペアには 2 つの最大距離のみが必要であるため、亜種ごとの最大距離のみを維持するだけで十分です。 
6. 重心を削除済みとしてマークし、残りのすべてのコンポーネントに同じプロセスを再帰的に適用します。 

これが機能する理由: 同じ亜種の 2 つの頂点について、2 つの頂点が異なる残りのコンポーネントになるか、またはそれらの 1 つが重心になる分解の最初の重心を考慮します。 彼らの道はその重心を横切ります。 アルゴリズムはその時点でこのペアを正確に検査し、それらの 2 つの距離を正しく組み合わせます。 考えられるすべてのペアがその分離重心で考慮されるため、見つかった最大値がその亜種の真の直径になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

def solve():
    n, k = map(int, input().split())
    color = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    removed = [False] * n
    size = [0] * n
    ans = [0] * k
    best = [None] * n

    def calc_size(u, p):
        size[u] = 1
        for v in g[u]:
            if v != p and not removed[v]:
                size[u] += calc_size(v, u)
        return size[u]

    def find_centroid(u, p, total):
        for v in g[u]:
            if v != p and not removed[v] and size[v] > total // 2:
                return find_centroid(v, u, total)
        return u

    def collect(u, p, d, arr):
        arr.append((color[u], d))
        for v in g[u]:
            if v != p and not removed[v]:
                collect(v, u, d + 1, arr)

    def decompose(u):
        total = calc_size(u, -1)
        c = find_centroid(u, -1, total)

        current = {}
        current[color[c]] = 0

        for v in g[c]:
            if removed[v]:
                continue
            nodes = []
            collect(v, c, 1, nodes)

            for col, dist in nodes:
                if col in current:
                    ans[col] = max(ans[col], current[col] + dist)

            for col, dist in nodes:
                if col not in current or dist > current[col]:
                    current[col] = dist

        removed[c] = True
        for v in g[c]:
            if not removed[v]:
                decompose(v)

    decompose(0)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```の`calc_size`関数は、既に削除された重心を無視して、現在のコンポーネントのサイズを測定します。 の`find_centroid`関数は、有効な重心に到達するまで、大きすぎる唯一のサブツリーに入ります。 

の`collect`DFS が収集します`(color, distance)`重心の 1 つの子コンポーネントからのペア。 子コンポーネントを個別に処理することが不可欠です。 同じ子コンポーネント内の 2 つの頂点からの距離を重心を介して結合することはできません。 

の`current`辞書には、すでに処理されたブランチの中で、この重心から各色までの最大の距離が格納されます。 新しい枝がスキャンされると、その頂点と`current`重心を横切るすべてのパスをチェックします。 回答の更新では距離の加算のみを使用するため、Python の整数はオーバーフローの問題を回避します。 

ツリー DFS とセントロイド再帰の両方が、大きな入力に対して Python のデフォルトの再帰深さを超える可能性があるため、再帰制限が増加します。

 ## 特殊なケース

 亜種が 1 回しか出現しない場合、重心プロセスではその色に何度も遭遇する可能性がありますが、辞書では 2 番目に一致する頂点が見つかりません。 ペアが存在しないため、答えはゼロのままです。 

入力の場合:```
5 5
1 2 3 4 5
1 2
2 3
3 4
4 5
```各重心ステップでは、色ごとに 1 つの距離だけが記録されます。 加算は行われないため、すべての答えはゼロのままです。 

同じ色が他の色で区切られている場合、アルゴリズムは亜種の接続性に依存しません。 のために：```
5 2
1 2 1 2 1
1 2
2 3
3 4
4 5
```外側の2色`1`頂点は最終的に、そのパスがさまざまなブランチに分割される重心で考慮されます。 それらの距離を加算すると 4 になります。これが正しい範囲です。 

多くの頂点が同じ色を共有する場合、辞書は各重心から見える最大距離のみを保持します。 その重心を通るペアは常に同じ中心からの 2 つの距離で構成され、最適なペアは利用可能な 2 つの最大の値を使用する必要があるため、これで十分です。 再帰的分解では、現在の重心を通過しないペアが処理されます。
