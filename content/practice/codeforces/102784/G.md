 ## 問題の理解

 この問題は、パッケージに正確な内容が含まれているかどうかを尋ねます。`x`Felix のハイパーキューブ パッケージのコレクションを使用して、チョコレート キューブのバランスを調整できます。 利用可能なパッケージにはサイズがあります`1, w, w², ..., w¹⁰⁰`、 どこ`w`は各超立方体の辺の長さです。 フェリックスは、任意のパッケージを天秤のどちらかの側に置くことができます。`w`最終的な差異にプラスにもマイナスにも寄与することも、まったく寄与しないこともあります。 課題は、`x`は、次の係数を使用したこれらのべき乗の合計として表すことができます。`{-1, 0, 1}`。 

入力にはチェック対象のパッケージ重量が最大 20 個含まれており、すべての重量は最大 20 個です。`10^9`。 ベース`w`は 2 ～ 10 です。必要な最大の指数は小さいため、`10^10`すでに超えています`10^9`、ベースで桁ごとに機能するソリューション`w`簡単に十分に高速です。 101 個の可能な立方体を選択して総当たり検索を行うと、最大で`3^101`これは完全に不可能であるため、解決策は権力の数学的構造を利用する必要があります。 

間違いの主な原因は、通常のベースを前提としていることです。`w`表現だけで十分です。 通常の数字は 1 より大きくなる可能性があるのに対し、次の各累乗は可能であるため、そうではありません。`w`1回のみ使用できます。 キャリーにより、数字を次の位置に移動して有効にすることができます。 

例えば：```
Input:
4 5
25
```出力は次のとおりです。```
YES
```値`25`のみを使用した通常の基数 5 桁の合計として表されません。`0`そして`1`それはそうだから`100_5`、しかし、それを取ることによって作成することができます`5²`立方体なので、答えは「はい」です。 

もう 1 つの注意が必要なケースは、数字を直接表現できず桁上げが必要な場合です。```
Input:
4 5
29
```出力は次のとおりです。```
YES
```なぜなら`29 = 25 + 5 - 1`。 すべての基数 5 の数字が最大でも 1 桁であるかどうかのみをチェックする貪欲な実装では、これが誤って拒否されます。 

## アプローチ

 簡単なアプローチは、すべてのハイパーキューブに対して可能なすべての選択肢を試すことです。 それぞれの力`w`には 3 つの状態があります。フェリックスの側に置く、母親の側に置く、または無視します。 このアプローチは、天秤上のあらゆる可能な配置を列挙しているので、正しいです。 ただし、可能性の数は増えるにつれて、`3^101`, これは処理できる範囲をはるかに超えています。 

有益な観察は、`w`基地内の位置とまったく同じように動作します`w`番号システム。 残高制限は、各ポジションが 1 桁の数字を必要とすることを意味します。`-1`、`0`、 または`1`。 どのキューブを使用するかを決定する代わりに、最も低いベースを繰り返し検査できます。`w`の桁`x`。 その数字が`0`または`1`、直接使用できます。 それが大きい場合は、この位置で負の立方体を使用してその数字のコピーを 1 つ減算し、1 つを次の位置に繰り上げることができます。 これは、数値を符号付き数字表現に変換するのと同じ考え方です。 

たとえば、基数 5 では、数値 29 には桁が含まれます。`104_5`。 最後の数字は 4 ですが、これは許可されません。 これを次のように置き換えます。`-1`そして 1 つを次の位置に運びます。```
104_5
= 110_5 - 1
= 1 * 5² + 1 * 5 - 1
```ブルート フォースはすべての配置を考慮するため機能しますが、配置が多すぎるため失敗します。 すべての決定は基数変換を通じてローカルに処理できるという観察により、問題は短い桁の処理ループに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 現在値を基数に変換します`w`繰り返し取得して一度に 1 桁ずつ`x % w`。 
2. 現在の桁が`0`または`1`、整数除算を実行して数値からそれを削除します。`w`。 これらの数字は、許可されている係数とすでに一致しています。 
3. 現在の桁が より大きい場合`1`、この位置にマイナスの立方体を置きます。 数学的には、これは数字を置き換えることを意味します`d`と`d - w`そして次のポジションに 1 のキャリーを追加します。 以来`w`最大 10、以下のすべての可能な桁です`2`に`9`このように修正できます。 
4. 残量がゼロになるまで続けます。 すべての数字が処理された場合、その数値は有効な符号付き表現になります。 

変換が常に機能する理由は、すべての整数が固有の剰余剰余を持っているためです。`w`。 余りが 1 より大きい場合は、`-1`この位置では次の倍数が残ります`w`、次の桁に繰り越すことができます。 このプロセスは残りの数値を減らし続けるため、最終的には終了します。 

なぜ効果があるのか:

 すべてのステップで、アルゴリズムは同じ不変条件を維持します。つまり、選択した立方体によってすでに表されている量と残りの値を足したものが元のターゲットに等しいということです。`x`。 の桁を選択する`0`または`1`まさにその量を消費します。 選択する`-1`消費する`-1`現在の電力の超過分を移動します`w`キャリーを通じてユニットを次のポジションに移動します。 値が残っていない場合は、数値全体が係数のみで表現されています`-1`、`0`、 そして`1`、これは有効なバランス調整に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(x, w):
    while x:
        digit = x % w
        if digit <= 1:
            x //= w
        else:
            x = (x // w) + 1
    return True

def solve():
    n, w = map(int, input().split())
    ans = []
    for _ in range(n):
        x = int(input())
        ans.append("YES" if possible(x, w) else "NO")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`possible`関数は符号付き基数変換を実行します。 剰余演算は現在の基数を抽出します。`w`桁。 数字が`0`または`1`、通常の除算ではその数字が削除されます。 桁が大きい場合、式は`(x // w) + 1`次の位置へのキャリーを実行します。 

問題は有効な選択肢が存在するかどうかだけであるため、負の数字を明示的に追跡する必要はありません。 1 より大きいすべての数字は、キャリーを使用して常に負の 1 に置き換えることができます。 また、ループ条件では、指定された制約について少数の反復を行うだけで値がゼロになるため、固定指数制限も回避されます。

 ## 特殊なケース

 まさに次のべき乗の値`w`は最も単純なケースです。 例えば：```
Input:
1 5
25
```数字は`100_5`。 このアルゴリズムはゼロの桁を削除し、最後の 1 桁を受け入れ、正方形のハイパーキューブの使用に一致します。 

次の桁の値`w - 1`キャリーが必要です。 例えば：```
Input:
1 5
26
```番号は`101_5`。 それは次のように表すことができます`25 + 1`、したがってアルゴリズムは数字だけを認識します`1`、`0`、 そして`1`そしてそれを受け入れます。 

どちらでもない数字を含む値`0`、`1`、 または`w - 1`失敗しなければならない。 例えば：```
Input:
1 5
27
```基数 5 の表現には数字が含まれます`2`。 これには、同じ立方体のコピーを 2 つ使用するか、同等の無効な係数を使用する必要があるため、アルゴリズムは直ちに拒否します。 

これらのケースは、問題の主な失敗モード、つまり、通常の基本表現と、天秤に必要な制限された符号付き表現との混同をカバーします。
