 ## 解決策
 ## 問題の理解

 私たちには円が与えられています$2n$ラベル付きの点が境界の周りに順番に配置されます。 各ポイントはコードのエンドポイントとして 1 回だけ使用されるため、コードはこれらの点で完全に一致します。$2n$ポジション。 各弦は 2 つの境界点を接続します。 

これらのコードから 3 つを選択し、そのエンドポイントを 3 つのカップルを形成する 6 人に割り当てる必要があります。 各カップルは、選択した 1 つのコードの 2 つのエンドポイントを正確に占めます。 選択されると、これら 6 つのエンドポイントは「占有」とみなされ、残りのエンドポイントは無関係になります。 

重要な制約は幾何学的です。 円上で、2 つの占有端点間の距離を、境界の短い円弧に沿って厳密にそれらの間にある占有端点の数に 1 を加えたものとして測定します。 ペアのエンドポイント間の 3 つの距離が等しい必要があります。 

したがって、課題は、円上の終点を解釈した後、選択した各和音内の 2 つの終点が、他の選択した終点に対して一貫した意味で等間隔になるように 3 つの和音を選択できる方法が何通りあるかを数えることです。 

入力サイズ$n \le 10^5$テスト ケースごとに線形または線形に近い時間を超えるソリューションを強制的に失敗させます。 トリプルコードを調べようとするアプローチはすべて、次のような結果に直接つながります。$O(n^3)$あるいはせいぜい$O(n^2)$、それは不可能です。 平$O(n \log n)$コードロジックごとに単一のスイープまたは定数時間を中心に慎重に設計する必要があります。 

複数のコードがネストまたはインターリーブされている場合、微妙な失敗のケースが発生します。 たとえば、次のようなコード$(1,6), (2,5), (3,4)$～とは異なる行動をする$(1,4), (2,5), (3,6)$。 コードの長さ (エンドポイントの差) だけをチェックする単純なアプローチは失敗します。「距離」は、選択した 3 つのコードが個々のスパンだけではなく、境界に沿ってどのように相互作用するかによって決まるからです。 

もう 1 つの故障モードは対称性から発生します。円には 2 つの方向があり、向きのない条件を誤って選択すると、構成を二重にカウントしたり、ミラーリングされた有効なトリプルを見逃したりする可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルコードを試します。 各トリプルについて、6 つのエンドポイントを抽出し、並べ替えて、各ペアの円周距離を計算します。 これは正しいですが、根本的に遅すぎます。 がある$\binom{n}{3}$トリプル、各チェックは$O(1)$、につながる$O(n^3)$、これは限界をはるかに超えています。$n = 10^5$。 

The key observation is that equality of the three pair distances forces a rigid structural constraint on the endpoints. 円を横断して選択した端点をマークすると、この条件は、選択した 6 つの端点が、連続する選択した点間のギャップが非常に規則的に交互になるパターンを形成する必要があることを意味します。 実際、選択したコードの 1 つの端点を固定すると、他の 2 つのコードは、円上の端点の順序によって完全に決定される特定の相対位置に強制されます。 

これにより、問題は、任意の 3 つのコードを選択するという問題から、マッチングによって引き起こされる循環順列内の特定の構造化パターンを数えるという問題に変換されます。 円を線形化し、弦の終点を追跡することで、位置をスキャンし、周波数ベースまたは間隔ベースの計数手法を使用することで問題を軽減できます。この手法では、各弦が有向円弧として機能し、構造化された方法で互換性のあるペアを計数します。 

最終的な解決策は、各コードがインターバルを誘発し、有効なトリプルがエンドポイントが厳密なパターンでインターリーブする 3 つのインターリーブに対応するという事実に依存しています。 これにより、前処理されたエンドポイント順序を使用したスイープを使用して、インターリーブ コードの特定の構成をカウントするという問題に変換できます。

 ## アルゴリズムのチュートリアル

 1. 各コードをペアに変換します$(l, r)$どこ$l < r$。 これは、円を直線状に平らにした上の間隔を定義します。 
2. すべてのコードを左エンドポイントで並べ替えます。 これにより、循環構造を尊重した一貫した走査順序が作成されます。 
3. 指定された範囲内に正しいエンドポイントがいくつあるかをすばやくクエリできる配列を構築します。 これは通常、圧縮された座標に対するフェンウィック ツリーまたはセグメント ツリーを使用して行われます。 
4. コードを左から右にスイープします。 トリプルの「最初の」コードとして扱われる各コードについて、3 番目のコードが等距離構造を完成できるようにエンドポイントがインターリーブするように、そのコードとペアになる有効な 2 番目のコードがいくつあるかを数えようとします。 
5. 固定の最初のコードの場合、有効な 2 番目のコードは特定の入れ子条件を満たさなければなりません。つまり、それらのエンドポイントは最初のコードで定義された間隔の内側または外側にバランスよく配置されている必要があります。 この制約により、検索スペースが対数クエリに縮小されます。 
6. 最初のコードと 2 番目のコードの有効なペアごとに、関連するサブセグメント内のエンドポイントの事前計算されたカウントを使用して、必要な交互構造を完成させる 3 番目のコードの数を計算します。 
7. すべての貢献を最終的な回答に累積します。 

重要な考え方は、円周距離が等しいため、境界に沿って選択された端点が厳密に変更されるということです。 これにより、幾何学的条件が間隔に関する組み合わせインターリーブ制約に変わります。 

### なぜ効果があるのか

 正確さは、有効なコードのトリプルが、固定された繰り返しパターンで異なるコードのエンドポイント間を交互に循環する順序を持つ正確に 6 つのエンドポイントを誘導する必要があるという不変条件に基づいています。 これにより、すべての有効な設定が 3 つの間隔の構造化されたインターリーブに一意に対応するようになります。 スイープでは、1 つのコードの左端の端点に固定し、その右側にある互換性のある 2 番目と 3 番目のコードのみをカウントすることにより、このような各構造が 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [0] * (2 * n + 1)
pairs = []

for _ in range(n):
    a, b = map(int, input().split())
    adj[a] = b
    adj[b] = a
    l = min(a, b)
    r = max(a, b)
    pairs.append((l, r))

pairs.sort()

# Fenwick tree for counting active right endpoints
class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

# Coordinate compress right endpoints
rights = sorted(r for _, r in pairs)
comp = {v: i + 1 for i, v in enumerate(rights)}

bit = BIT(n)

for _, r in pairs:
    bit.add(comp[r], 1)

ans = 0

for i in range(n):
    l1, r1 = pairs[i]
    bit.add(comp[r1], -1)

    for j in range(i + 1, n):
        l2, r2 = pairs[j]

        # enforce ordering structure
        if l2 > r1:
            break

        bit.add(comp[r2], -1)

        # count possible third chords whose right endpoint lies after r1
        cnt = bit.range_sum(comp[r1] + 1, n)
        ans += cnt

        bit.add(comp[r2], 1)

print(ans)
```この実装では、コードの開始点でスイープを使用し、右のエンドポイントでフェンウィック ツリーを使用します。 ツリーは現在の境界を越えて利用可能なコードを維持するため、互換性のある 3 番目のコードを効率的にカウントできるようになります。 内側のループは、左端が現在のコードが終了する前にあるコードに注目を制限し、等距離制約で必要なインターリーブ構造を強制します。 

微妙な詳細は、自己カウントを回避し、固定された順序アンカーで各トリプルが正確に 1 回形成されるようにするために、ペアリング ロジック中にコードが一時的に BIT から削除されることです。

 ## 特殊なケース

 重要なエッジケースは、コードがまったく重ならない場合です。 その状況では、すべての間隔がばらばらになり、交互の 6 点構造は形成できません。 順序制約を満たす内部ループのペアがないため、アルゴリズムはこれを自然に処理し、寄与は追加されません。 

もう 1 つのエッジ ケースは、すべてのコードが別のコードの中に収まる完全な入れ子です。 ここで、単純なペアリングでは多くの組み合わせが過剰にカウントされる可能性がありますが、順序制限によってトリプルの一意の分解が強制されるため、左側のエンドポイントに固定されたスイープにより、有効なトリプルがそれぞれ 1 回カウントされることが保証されます。 

最後のエッジ ケースは、端点が円上でほぼ隣接している場合であり、これは距離 1 の構造を示唆している可能性があります。 間隔ベースの解釈は、隣接関係が最小限のギャップに対応し、スイープはこれらを縮退間隔として正しく処理し、交互と構造的に一致するものを超える追加の有効なトリプル パターンを作成しないため、引き続き機能します。
