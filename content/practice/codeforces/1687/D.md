 ## 解決策
 ## 問題の理解

 すべての整数について、その整数を囲む 2 つの連続する完全な正方形に注目してください。 

もし$$m^2 \le x < (m+1)^2,$$それから$g(x)=m^2$そして$f(x)=(m+1)^2$。 数字が上の正方形よりも下の正方形に厳密に近い場合、その数字はかわいいと呼ばれます。 

簡単に計算すると、$$x-m^2 < (m+1)^2-x$$これは以下と同等です$$x \le m^2+m.$$2 つの連続する正方形の間のブロック内で、かわいい数字が連続した間隔を形成します。$$[m^2,\;m^2+m].$$例えば：$$[1,2],\quad [4,6],\quad [9,12],\quad [16,20],\ldots$$ソートされた配列が与えられます$a$。 最小の非負のシフトを見つけなければなりません$k$すべての値が$a_i+k$それらのかわいい区間の1つに属します。 

制約が問題を難しくしているのです。 配列の長さが次の値に達しました$10^6$, したがって、すべての要素を何度も検査することは不可能です。 値自体は最大でも$2\cdot10^6$よりもはるかに小さい$n$、重複する値を圧縮して除去する必要があることを示唆しています。 時間制限があるため、シフトを 1 つずつ確認することもできません。 

多くの配列要素が等しい場合、微妙なエッジ ケースが発生します。 考慮する```
3
5 5 5
```3 つの値はすべて、シフト後は常に同じように動作します。 重複を個別に処理すると、膨大な作業が無駄になります。 重複を削除しても、実現可能性は何も変わりません。 

もう 1 つの簡単な間違いは、中点の処理を間違っていることです。 たとえば、$9$そして$16$、かわいい間隔は$[9,12]$。 値$13$すでに近づいています$16$するよりも$9$、だから可愛くない。 非厳密な不等式を使用すると、中点に隣接する値が誤って分類されます。 

3 番目の罠は、シフトされたすべての数値が同じかわいい間隔に収まるはずだと仮定することです。 のために```
2
1 100
```最適なシフトにより、2 つの値がまったく異なるかわいい間隔に配置されます。 単一のターゲット間隔の選択に基づくソリューションは、すぐに失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 試す$k=0,1,2,\ldots$すべてかどうかを確認します$a_i+k$かわいいです。 整数の平方根を使用すると、1 つの数字がかわいいかどうかを簡単に判断できます。 

問題は検索スペースです。 答えは何百万にもなる可能性があり、各チェックは次の点に達します。$10^6$要素。 最悪のケースは簡単に超えてしまう$10^{12}$操作。 

重要な観察は、かわいい数字のセットが恣意的ではないということです。 かわいい領域とかわいくない領域が交互に配置され、各領域は連続した間隔になります。 

かわいい間隔は、$$[1,2], [4,6], [9,12], [16,20], \ldots$$そしてそれらの間のかわいくない間隔は$$[3,3], [7,8], [13,15], \ldots$$それらの長さは単純なパターンに従います。$$1,1,2,2,3,3,4,4,\ldots$$シフトを直接検索する代わりに、シフト後のどのかわいい区間に最小の配列値が含まれるかを列挙します。 

仮定する$a_0+k$特別なかわいい隙間の中にあります。 それはすぐに可能な範囲を与えます$k$。 次に、数直線上の交互のセグメントをすべて調べて、どの配列値がそのセグメント内に配置されるかを決定します。 

セグメントがかわいい場合、その中の値は問題ありませんが、正しい境界を越えてはなりません。 これにより上限が決まります$k$。 

セグメントが可愛くない場合、そこに値が留まらない可能性があります。 増えてからは$k$すべてを右に移動すると、最も左にある問題のある値を強制的にセグメントから外すことができます。 これにより下限が与えられます$k$。 

すべての制約は間隔更新になります。$k$。 結果として得られる実行可能範囲が空でない場合、その左端点は、選択されたキュートな間隔に対する最小の有効な答えになります。 実行可能な範囲をもたらす最初のかわいい間隔は、全体的な最適値を与えます。 これが意図した解決策です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\text{answer}\cdot n)$|$O(1)$| 遅すぎる |
 | 最適 |$O(M\log U)$|$O(U)$| 承認済み |

 ここ$U$は値の範囲であり、$M$は、検査する必要がある交互セグメントの数です。 

## アルゴリズムのチュートリアル

 1. 配列から重複する値を削除します。 

同じ値は常に一緒に移動するため、異なる値のみが重要です。 
2. かわいいセグメントとそうでないセグメントの境界を交互に生成します。 

それらの長さは$$1,1,2,2,3,3,\ldots$$これにより、すべてのセグメント境界を線形時間で生成できます。 
3. かわいいセグメントをすべて列挙します$i$。 

仮定する$a_0+k$はこのセグメント内にあります。 
4. その仮定に基づいて、最初の実行可能範囲を計算します。$$[lo,hi].$$これはまさに、次のような一連のシフトです。$a_0+k$セグメント内$i$。 
5. 後続のセグメントをスキャンします$j$。 

個別の配列値に対して二分検索を使用して、セグメント内にあるすべての値を見つけます。$j$現在のシフトレンジの場合。 
6. セグメントの場合$j$かわいいので上限を更新します。 

現在そのセグメント内にある値は、その右側の境界を越えてはなりません。 
7. セグメントの場合$j$はかわいくないので、下限を更新します。 

すべての違反値は、値を増やすことによってそのセグメントから押し出される必要があります。$k$。 
8. いつでも$lo>hi$、現在の開始セグメントは有効な答えを生成できません。 
9. 実行可能な間隔が空でない最初のかわいいセグメントが答えを生成します。$lo$。 

### なぜ効果があるのか

 を含む固定のかわいいセグメントの場合$a_0+k$、すべての配列値は次のように単調に移動します。$k$が増加します。 任意のセグメント内で、そのセグメントを現在占有している値のセットはバイナリ検索で見つけることができます。 

かわいいセグメントには上限のみが課せられます。右に移動しすぎると、一部の値がセグメントから外れるからです。 かわいくないセグメントには下限のみが課せられます。$k$最終的には、問題のある値をすべてそこから追い出します。 

現在の開始セグメントのすべての有効なシフトは、維持された間隔内にあります$[lo,hi]$、および内部のすべてのシフト$[lo,hi]$処理された制約をすべて満たします。 間隔が空になると、その開始セグメントに実行可能なシフトは存在しません。 関連するすべてのセグメントを処理した後も空でない場合、その左端点は、その仮定の下での最小の有効なシフトになります。 かわいいセグメントは昇順に考慮されるため、最初に成功したセグメントが全体的に最小の答えを返します。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a = sorted(set(a))
    m = len(a)

    V = []
    cur = 0

    LIM = 4020200

    for i in range(1, LIM + 1):
        V.append(cur)
        cur += i
        V.append(cur)
        cur += i - 1

    for i in range(2, LIM, 2):
        lo = max(0, V[i] - a[0])
        hi = V[i + 1] - 1 - a[0]

        add = lo

        j = i
        while j <= LIM and lo <= hi:
            if V[j] - V[i] > 15505000:
                break

            x = bisect_left(a, V[j] - add)
            y = bisect_left(a, V[j + 1] - add, x)

            if x < y:
                if j % 2 == 0:
                    hi = min(hi, V[j + 1] - a[y - 1] - 1)
                else:
                    lo = max(lo, V[j + 1] - a[x])

            j += 1

        if lo <= hi:
            print(lo)
            return

```最初のステップでは重複を圧縮します。 これは非常に重要です。$n$値の範囲はわずか 200 万ですが、100 万に達する可能性があります。 

配列`V`交互のセグメント境界を保存します。 連続するペアは、かわいい領域とそうでない領域を定義します。 生成ルールは長さのパターンを反映します$1,1,2,2,3,3,\ldots$。 

かわいいセグメントの候補ごとに、`lo`そして`hi`そのセグメント内の最小の配列値を維持するすべてのシフトを記述します。 

バイナリ検索では、シフトされた位置が特定のセグメント内にあるすべての個別の値が検索されます。 配列はソートされているため、ブロック全体を識別するには下限のペアで十分です。 

アップデート```
hi = min(hi, ...)
```かわいいセグメントから来ています。 右側の境界を越えると、一部の値が別の領域に入ります。 

アップデート```
lo = max(lo, ...)
```かわいくないセグメントから来ています。 すべての違反値をその領域から強制的に排除するのに十分なだけシフトを大きくする必要があります。 

オフバイワンの詳細は、実装の中で最もデリケートな部分です。 セグメントの境界は半開区間として扱われるため、式では次のものが使用されます。`-1`まさに、適切なエンドポイントを含める必要がある場所です。
