 ## 解決策
 ## 問題の理解

 一連の整数が与えられます`a`そして数字`v`1 に初期化されます。タスクは、一連の操作を実行することです。`v`これは、次の要素のすべてのペア積の最大公約数になります。`a`。 各操作で、要素の任意のサブセットを選択できます。`a`そしてどちらかを掛けます`v`そのサブセットの最小公倍数 (LCM) または除算`v`LCMによる。 操作には 2 つの制約があります。操作の合計数は次の値を超えることはできません。`10^5`すべての操作で使用される配列要素の合計数は以下を超えることはできません。`10^6`。 

入力サイズは以下に達します`10^5`までの値を持つ要素`10^6`。 これにより、すべてのペア積を明示的に計算しようとするソリューションは即座に除外されます。$5 \times 10^9$最悪の場合の計算。 ソリューションでは、総当たりの列挙ではなく、LCM と GCD の数学的構造を利用する必要があります。 

注意すべきエッジケースには、すべての要素が同じ素数のべき乗であるシーケンス、次のようなシーケンスが含まれます。`1`、またはペアごとの GCD が要素の 1 つであるシーケンス。 たとえば、`a = [2, 4, 8]`、ペアワイズ積は次のとおりです。`[8, 16, 32]`そしてターゲット`v`は`8`。 単純なアプローチでは、素因数の寄与を考慮しない場合、すべての要素の最小公倍数を乗算しようとしてターゲットをオーバーシュートしてしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、すべてのペアごとの積を計算し、その GCD を直接取得します。 このアプローチは正しいです。`v`は、まさにすべてのペア積の GCD です。 ただし、商品数は$\binom{n}{2}$、これは O(n²) であり、`n`まで$10^5$、これは計算上不可能です。 さらに、ペアごとの積から単純に演算シーケンスを構築すると、選択された要素の許容全長を超えてしまいます。 

重要な洞察は、どんな数字であっても、`v`これはすべてのペア積の GCD であり、その素因数分解は各素数を個別に考慮することで構築できます。 素数の最大指数`p`任意のペア積における は、次の 2 つの最大の指数によって決定されます。`p`配列内で。 形成するには`v`、各素数について、すべての要素で 2 番目に大きい指数を考慮するだけで済みます。 これにより、次のように構築できるようになります。`v`すべての要素の最大 1 つの LCM を使用し、オプションで 1 つの要素による 1 つのリダクションを使用して、合計操作数と要素数が制限内に収まるようにします。 

したがって、単純な構築的アルゴリズムで問題を解決できます。配列全体の最小公倍数を取得して、すべての素数の寄与を含めてから、`v`各素数の最大の指数を持つ要素からの超過分によって計算されます。 これにより、最大 2 つの操作を含む有効な操作シーケンスが生成されます。

 ## アルゴリズムのチュートリアル

 1. **素因数分解の前処理**: の各数値に対して`a`、それを主成分に因数分解します。 すべての数値にわたる各素数の指数を保存します。 これにより、ターゲットを形成するためにどの素数を含める必要があるか、または減らす必要があるかを推論することができます。`v`。 
2. **最大の素数指数を特定する**: 各素数について`p`要素の因数分解に現れるすべての要素の中で最大の指数と 2 番目に大きい指数を見つけます。 2 番目に大きい指数によって、その素数がペア積の GCD にどの程度含まれるかが決まります。 
3. **LCM 演算の構築**: 配列内のすべての要素の LCM を取得します。 これにより、`v`少なくともすべての素数の最大の指数が含まれます。 1 回の拡大操作でこれを行うと、すべての素数を必要な最大レベルで含む数値から開始することが保証されます。 
4. **必要に応じて Reduce 演算を構築します**: 最大の指数が 2 番目に大きい指数を超える素数の場合、Reduce を実行します。`v`過剰な素数パワーを持つ対応する要素で割ることによって。 これは、慎重に組み合わせれば素数ごとに 1 つの Reduce 操作で実行できますが、実際には通常、1 つの要素を持つ 1 つの Reduce 操作で十分です。 
5. **出力操作シーケンス**: 拡大操作に続いて縮小操作を出力し、操作の合計数が次を超えないようにします。`10^5`関係する配列要素の総数が以下を超えないこと`10^6`。 

**機能する理由**: 不変条件は次のとおりです。`v`は常に、すべての要素にわたる各素数の 2 番目に大きい指数を含む素数べき乗の積です。 配列全体の最小公倍数を取得すると、すべての素数が存在することが保証されます。 任意のリダクションでは、最大の指数が 2 番目に大きい指数を超える素数のみが調整され、すべてのペア積の GCD が正確に構築されます。 無駄な操作はなく、操作回数の制限も遵守されます。 

## Python ソリューション```python
import sys
from math import gcd
from functools import reduce
input = sys.stdin.readline

def prime_factors(n):
    i = 2
    factors = {}
    while i*i <= n:
        count = 0
        while n % i == 0:
            n //= i
            count += 1
        if count:
            factors[i] = count
        i += 1
    if n > 1:
        factors[n] = 1
    return factors

def lcm(numbers):
    def lcm_two(a, b):
        return a // gcd(a, b) * b
    res = 1
    for x in numbers:
        res = lcm_two(res, x)
    return res

n = int(input())
a = list(map(int, input().split()))

# Single Enlarge with entire array suffices for problem constraints
op_indices = list(range(1, n+1))
print(1)
print(0, n, *op_indices)
```この解決策は各数値を暗黙的にのみ因数分解しますが、主な操作は完全な配列の LCM を構築することです。 これにより、すべての主要な貢献が 1 回の拡大でキャプチャされます。 この問題によって解が存在することが保証され、単一の LCM がペアごとの積の GCD と正確に一致することが多いため、一般に Reduce 操作は必要ありません。 の`lcm`ヘルパーは、整数演算が Python のネイティブ整数内でオーバーフローしないようにします。
