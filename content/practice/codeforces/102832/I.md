 ## 問題の理解

 私たちにはコミュニティのツリーがあります。 1つのコミュニティ`k`配送センターです。 他のすべてのコミュニティについては、配達員がそこから開始し、隣接する道路の 1 つを均等にランダムに選択して、到達するまで繰り返します。`k`。 宅配業者は中心から歩いて戻ってくる可能性があるため、ランダムな移動距離は単なる木の距離ではありません。 

コミュニティを始めるために`i`、ランダムな距離を次のようにします。`D`。 予想される疲労度は次のとおりです。`i * E[D * x^D]`どこ`x = px / qx`。 この値を法で計算する必要があります`10^9 + 7`すべてのコミュニティとすべての結果の XOR を実行します。 

ツリーには以下を含めることができます`100000`コミュニティ。 単一のランダム ウォークですら固定長がないため、ノードごとにランダム ウォークを個別に調査するソリューションは不可能です。 ツリー上の二次解はすでに次のように実行されます。`10^10`最悪の場合、1 秒の制限をはるかに超えた操作が行われます。 線形または線形に近いツリー動的プログラミング ソリューションが必要です。 

厄介なケースは、ツリー構造ではなくランダム ウォークによって引き起こされます。 中心ノードの距離は 0、確率は 1 であるため、その寄与は常に 0 です。 例えば：```
2 1 1 2
1 2
```ノードの回答貢献度`1`は`0`、すでに中心にあるからです。 ルート以外の繰り返しをルートに適用するソリューションでは、誤ってゼロ以外の値が作成される可能性があります。 

もう一つのエッジケースは、`x = 1`。 例えば：```
3 1 1 1
1 2
1 3
```期待される距離は依然として有限ですが、母関数の式は素数を法として評価する必要があります。 べき乗を通常の整数距離に置き換えたり、ウォーク長をツリーの深さと仮定したりすると、誤った結果が得られます。 

## アプローチ

 直接的なアプローチでは、ランダム ウォーク シミュレーションを開始するか、各ノードの可能なすべての距離の確率を導き出します。 これは正しいです。なぜなら、期待値は、考えられるすべての歩行距離にわたる加重合計であるからです。 ただし、運び屋は繰り返しサブツリーに移動して戻ることができるため、可能なウォークの数は無限です。 妥当な距離までの確率を​​保存することさえ機能せず、これをすべてのノードに対して行うと非常に遅くなります。 

有用な観察は、ツリー上のランダム ウォークが単純な再帰構造を持つということです。 ツリーをルート化する`k`。 ノードの場合`v`、最初の移動は、その親に直接移動するか、その子のサブツリーの 1 つに入るかのいずれかです。 ウォークが子サブツリーに入ると、最初に子サブツリーに戻る必要があります。`v`最終的に親に向かって移動する前に。 この独立性により、母関数を使用して分布全体を表現できるようになります。 

定義する：`Fv = E[x^D]`からの距離のために`v`根を張った木の親側に。 もし`Sv`の合計です`Fu`すべての子供たちの上に`u`の`v`、 それから：`Fv = x / (deg(v) - x * Sv)`答えは必要です`E[D*x^D]`、これは母関数を微分することで得られます。`E[D*x^D] = x * Fv'(x)`導関数は子の値と子の導関数のみに依存するため、ボトムアップで計算することもできます。 ツリー構造により、必要な順序が正確に与えられます。最初に子を処理し、次に親を計算します。

 ## アルゴリズムのチュートリアル

 1. ツリーを次の場所にルートします。`k`すべてのノードの親と子を保存します。 DFS オーダーではポストオーダー シーケンスが与えられるため、すべての子はその親の前に処理されます。 
2. 非ルート ノードごとに DFS の逆順で計算します。`Fv = E[x^D]`。 させて`S`すでに計算された子の値の合計になります。 再発は次のとおりです。`Fv = x / (deg(v) - x*S)`分母は、子サブツリーへのトリップの可能性によって生じる確率生成関数の修正です。 
3. 一緒に`Fv`、計算する`Hv = x*Fv'(x)`。 もし`T`子の合計です`H`値を微分すると、次のようになります。`Hv = x * (deg(v) + x^2*T) / (deg(v) - x*S)^2`これにより、確率分布全体を再構築することなく、必要な期待値が直接得られます。 
4. すべてのノードについて`i`、乗算する`Hi`による`i`そして結果をXORします。 ルートの距離は常にゼロであるため、ルートはゼロに寄与します。 

なぜ機能するのか: 不変条件は、ノードを処理した後、`Fv`は、子孫への任意のエクスカーションを含む、そのノードから親側へのすべての可能なウォークの完全な生成関数を表します。 再帰では、ウォークによって取得された最初のエッジが列挙され、乗算を通じて独立した子エクスカーションが結合されます。 この正確な生成関数を微分すると、問題に必要な重み付けされた期待値が得られるため、すべての計算値が数学的定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n, k, px, qx = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    x = px * pow(qx, MOD - 2, MOD) % MOD

    parent = [-1] * n
    order = [k - 1]
    parent[k - 1] = -2

    for v in order:
        for u in g[v]:
            if parent[u] == -1:
                parent[u] = v
                order.append(u)

    f = [0] * n
    h = [0] * n

    for v in reversed(order):
        if v == k - 1:
            continue

        s = 0
        t = 0
        for u in g[v]:
            if parent[u] == v:
                s += f[u]
                if s >= MOD:
                    s -= MOD
                t += h[u]
                if t >= MOD:
                    t -= MOD

        den = (len(g[v]) - x * s) % MOD
        inv = pow(den, MOD - 2, MOD)

        f[v] = x * inv % MOD
        h[v] = x * ((len(g[v]) + x * x % MOD * t) % MOD) % MOD
        h[v] = h[v] * inv % MOD * inv % MOD

    ans = 0
    for i in range(n):
        ans ^= (i + 1) * h[i] % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```最初の DFS は、再帰なしでツリーのルート表現を構築し、チェーン形状のツリーでの Python 再帰の深さの問題を回避します。 の`order`配列はルートから外側への位相順序であるため、これを逆にすると、すべての子の生成関数がすでに計算されていることが保証されます。 

配列`f`そして`h`漸化式に必要な 2 つの量を格納します。 合計`s`そして`t`親の方向はサブツリーからの最終的な出口を表すため、親ではなく子に対してのみ適用されます。 このステートメントは最終分母が次の数で割り切れないことを保証しているため、モジュラー逆行列は有効です。`10^9+7`。 

の乗算`h[v]`モジュロで行われます`MOD`すべての操作の後。 Python の整数はオーバーフローしませんが、値を減らしたままにすることで不必要な増大を回避し、モジュラー式に直接に従います。

 ## 特殊なケース

 開始ノードが中心の場合、アルゴリズムは反復をスキップし、その応答の寄与をゼロのままにします。 のために：```
2 1 1 2
1 2
```ノード`1`はルートなので、その距離は常にゼロです。 アルゴリズムが子式を適用することはありません。 

いつ`x = 1`、力`x`長い散歩の影響を軽減できなくなりました。 この公式は、有限確率の合計ではなく、生成関数自体から導出されるため、依然として機能します。 のために：```
4 2 1 1
1 2
2 3
3 4
```同じボトムアップ計算が適用されます。`x`なる`1`モジュロ`MOD`。 

ノードに多くの子がある場合、合計から親エッジを除外する必要があります。 中心に根を張ったスターの場合、根を張ったツリーの各葉には子がありません。 実装チェック`parent[u] == v`したがって、中心に向かって戻るエッジが誤って含まれ、円形の繰り返しが作成されることはありません。
