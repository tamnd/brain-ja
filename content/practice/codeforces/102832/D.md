 # 問題の理解

 シーケンスは、ビットごとの AND を含む反復によって定義されます。 位置の項`n`の少なくとも 1 つの設定ビットをクリアすることによってインデックスが形成されるすべての以前の位置を調べることによって取得されます。`n`、それらの項の最大値を取得し、それに乗算します。`c`。 タスクは、インデックスからすべての項の合計を計算することです。`0`指定されたインデックスを介して`n`、モジュロ`10^9+7`。 元の問題ステートメントと制約は Codeforces Gym 102832D からのものです。 

入力インデックス`n`は通常の 10 進整数としては与えられません。 これはバイナリ文字列として提供され、最大 3000 ビットを含めることができます。 これにより、すべての値を反復処理することに依存するものはすぐに除外されます。`0`に`n`、 なぜなら`n`それ自体が天文学的な大きさになる可能性があります。 2 進数 3000 桁の数値は約`2^3000`したがって、値ごとに 1 つの操作を実行するアルゴリズムですら不可能です。 解はビット数に依存する必要があります。`n`の数値サイズではありません`n`。 

パラメータ`c`と同じ大きさにすることができます`10^9`ただし、すべての計算はモジュロで実行されます。`10^9+7`。 これは、モジュラー乗算とべき乗だけが必要であり、実際のシーケンス値を保存する必要がないことを意味します。 

最初の課題は、再発が実際に何を生み出すかを理解することです。 直接実装すると、以前のすべての値を維持しようとしますが、インデックスの範囲により、そのアプローチは使用できなくなります。 有用なエッジケースは、隠されたパターンを明らかにするものです。 

入力用`0 5`、唯一の用語は`a_0 = 1`、したがって、答えは次のとおりです`1`。 バイナリ文字列を通常の整数として扱い、最初に設定されたビットからビット DP を開始しようとするソリューションでは、誤ってゼロのケースを見逃す可能性があります。 

入力用`1 0`、条件は`a_0 = 1`そして`a_1 = 0`、したがって、答えは次のとおりです`1`。 を使用した不用意な数式`0^0`または、すべての項が次のべき乗によって生成されると仮定します。`c`インデックス 0 を区切らないと、不正な結果が生じる可能性があります。 

入力用`10 2`、インデックスは`0, 1, 2`、その値は`1, 2, 2`、したがって、答えは次のとおりです`5`。 よくある間違いは、設定されたビットのみを処理することです。`n`そして、バイナリ分解で現れるすべての小さな数値の寄与を忘れます。 

# アプローチ

 ブルートフォースソリューションでは、一度に 1 項ずつシーケンスを生成します。 インデックスごとに`x`、それはすべての小さなインデックスを検査します`i`、計算する`x & i`、すでに計算された最大値を使用します。 これは正しいです。なぜなら、これは再発を直接追跡するからです。 ただし、以下までの取り扱いが必要です。`n`条件、および`n`に近いかもしれない`2^{3000}`。 最大値を求める内部検索を無視したとしても、すべてのインデックスを単純に訪問することは不可能です。 

問題を変える最初の観察は、`n & i`は常に次のサブマスクです`n`。 からアクセス可能なすべてのインデックス`n`AND 演算によるものは単なるバージョンです`n`一部のセットビットが削除されています。 もし`n`もっている`k`セット ビットを使用する場合、以前の最良の値は、少なくとも 1 つのセット ビットを削除しながら、できるだけ多くのセット ビットを維持することによって得られます。 これにより、次の関係が得られます。`a_n = c^(number of set bits in n)`。 

ベースケースもフィットするので、`a_0 = 1 = c^0`。 

これで、タスクはもはや奇妙な繰り返しに関するものではなくなりました。 必要なのは以下だけです:`sum(c^popcount(i))`あらゆる二進数に対して`i`から`0`に`n`。 

残りの課題は、数値を列挙せずにこの合計を計算することです。 ビットを処理します`n`最も重要な側面から。 ちょっとしたとき`n`は`1`、現在のビットが に設定されているすべての数値`0`残りの任意の下位ビットは以下より小さい`n`。 彼らの貢献は完全なブロックとして数えられます。 あれば`k`残りの空き位置では、そのブロックにはそれらのビットの可能な選択肢がすべて含まれるため、その合計寄与率は単純な反復に従います。 

させて`f(k)`の合計になる`c^popcount(x)`全体`k`-ビット番号。 各ビットは次のいずれかです`0`または`1`。 選択する`0`を選択しながら、貢献度は変更されません。`1`それを乗算します`c`、 それで：`f(k) = f(k-1) * (1 + c)`と`f(0) = 1`。 

スキャン中`n`、私たちはどれくらいの数を維持しますか`1`ビットはすでに登場しています。 私たちが何かに遭遇するたびに、`1`、前のすべてのビットに一致する数値の寄与を追加します。`0`ここで、残りのビットを使用します。 これらの数値には、以前に設定されたビットからの固定寄与乗数と、残りの位置からの完全なサフィックス寄与が含まれます。

 # アルゴリズムのチュートリアル

 1. のバイナリ表現を読み取ります。`n`との値`c`。 考えられるすべてのサフィックス長の寄与を事前計算します。 接尾辞の場合`k`ビット、合計を格納します`c^popcount`これらのビットによって形成できるすべての数値にわたって。 再発というのは、`dp[k] = dp[k-1] * (1+c)`。 
2. ケースを処理する`n = 0`別に。 単一の用語しかありません`a_0`、その値は`1`。 
3. のビットをスキャンします。`n`左から右へ。 保つ`ones`、すでに処理されたセットビットの数、および`ans`、すべての小さなプレフィックスからの累積された答え。 
4. When the current bit is`0`、スキャンを続けます。 このプレフィックスを持つすべての有効な番号には、次のものも必要です。`0`ここ。 
5. 現在のビットが`1`を使用するすべての数字を数えます。`0`この位置で。 それらはすでに以下よりも小さくなっています`n`、残りのビットは何でも構いません。 寄与率は、以前の設定ビットを選択する方法の数に、事前に計算されたサフィックスの合計を乗算したものです。 
6. そのブロックを追加した後、次の内容を含めます`n`現在のビットを次のように扱うことにより、それ自体が`1`、これまでに見られたセットビットの数が増加します。 
7. すべてのビットが処理された後、次の寄与を追加します。`n`それ自体をモジュロとして結果を出力します`10^9+7`。 

機能する理由: 反復により、インデックス内の設定されたビット数のみに応じて値が作成されます。 バイナリ スキャンでは、次のすべての数値が分割されます。`0`に`n`より小さくなる最初の位置に基づいて素グループに分割します。`n`。 すべての数値はそのようなグループの 1 つだけに表示され、各グループの寄与は残りのビットの独立した選択から計算されます。 以前の維持されたカウント`1`ビットは固定プレフィックスの寄与を正確に考慮しているため、最終的な合計には必要なすべての用語が 1 回だけ含まれます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n, c = input().split()
    c = int(c) % MOD

    if n == "0":
        print(1)
        return

    m = len(n)

    suf = [1] * (m + 1)
    mul = (1 + c) % MOD
    for i in range(1, m + 1):
        suf[i] = suf[i - 1] * mul % MOD

    ans = 0
    ones = 0

    for idx, ch in enumerate(n):
        if ch == '1':
            rem = m - idx - 1
            ans += pow(c, ones, MOD) * suf[rem] % MOD
            ans %= MOD
            ones += 1

    ans += pow(c, ones, MOD)
    ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```事前計算配列`suf`すべてのサフィックスの完全な寄与を保存します。 サフィックスにもう 1 ビットある場合、古い可能性はすべて 2 回表示されます。1 回目はそのビットが 0 で、もう 1 回はそのビットが 1 です。 2 番目のコピーは次の係数を取得します。`c`、乗数が得られます。`1 + c`。 

メインループは、上で説明したバイナリ分解を実装します。 変数`ones`は、すでに固定されているプレフィックスに設定されているビット数を表します。 現在のビットが`1`に変更します`0`数値が小さくなり、下位ビットは無制限になります。 用語`pow(c, ones, MOD)`固定プレフィックスを処理しますが、`suf[rem]`フリーサフィックスを処理します。 

スキャンでは、あるビットで小さくなる数値のみがカウントされるため、最後の加算が必要です。 元の番号`n`それ自体は最後まで含まれません。 

Python の整数はオーバーフローしませんが、すべての積は剰余化されます。`10^9+7`値を小さく保つためです。 バイナリの長さは 3000 であるため、べき乗剰余演算の使用も安全です。

def solve_data(data):

# エッジケース

 のために`0 5`、アルゴリズムはすぐに戻ります`1`。 これにより、空のビット セットを通常の遷移として扱うことが回避され、次の特別な定義が正しく保存されます。`a_0`。 

のために`1 0`、式は次のようになります`a_0 = 1`そして`a_1 = 0^1 = 0`。 スキャン中に、より小さいブロックが寄与します`1`、最終項が貢献します`0`、正しい答えを与える`1`。 

のために`10 2`、スキャンでは最初のビットが設定されていることがわかります。 そのビットがクリアされた数値をカウントします。`0`そして`1`、与える`1 + 2 = 3`。 最終的な値`a_2 = 2`が追加されます。 パーティションはすべてのインデックスを 1 回だけカバーし、`5`。 

3000 個のバイナリ文字列など、非常に大きなバイナリ文字列の場合、アルゴリズムはシーケンスを生成しようとしません。 ビットごとに固定量の作業のみを実行するため、同じ方法が引き続き適用されます。
