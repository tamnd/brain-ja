 ## 解決策
 ## 問題の理解

 根のない木のフォレストがあり、すべてのノードが単に接続されたコンポーネントに属しています。 各ノードは整数値を格納します。 変更が行われるたびに、同じツリー内の順序のないノードのペアが特別な算術条件 (値の最大公約数が値のビットごとの XOR に等しい) を満たすかどうかを報告する必要があります。 

操作は動的です。 新しい孤立したノードが出現したり、2 つの既存のツリーがマージされたり、ノード値が変更されたりする可能性があります。 答えは操作のたびに保持する必要があります。 

制限が非常に大きいため、すべてのペアをチェックすることは不可能です。 まで$10^5$初期ノードと$2\cdot10^5$演算の場合、二次法はおよそに到達します。$10^{10}$数秒で収まるレベルをはるかに超えたペアチェック。 線形または$O((n+m)\log n)$。 

難しい部分は、値の変更とコンポーネントの変更の間の相互作用です。 よくある間違いは、答えがコンポーネント内の値に依存するため、各コンポーネントにノードの数だけを保存することです。 もう 1 つの間違いは、マージまたは更新のたびにコンポーネント全体を再計算することです。 

再計算が失敗する理由を簡単な例で示します。```
3 1
1 2 3
2 1 2
```最初の操作では、ノード 1 と 2 をマージします。それらの値は 1 と 2 です。XOR は 3、gcd は 1 であるため、これらは悪いペアではありません。 答えは次のとおりです。```
0
```異なる値のすべてのペアが有効であると想定するソリューションでは、誤って 1 が出力されます。 

もう 1 つのエッジ ケースは、大規模なコンポーネント内の値の更新です。```
2 2
2 2
2 1 2
3 1 3
```マージ後、2 つのノードの値は同じになります。 それらの XOR は 0 であるため、ペアは無効であり、答えは 0 です。1 つの値を 3 に変更すると、値は 3 と 2 になります。XOR は 1 で、gcd は 1 であるため、答えは 1 になります。以前の寄与を削除せずに、変更された値をローカルで更新するだけのアプローチでは、不正確な答えが残る可能性があります。 

## アプローチ

 直接的な解決策では、すべてのコンポーネントをノードのリストとして維持します。 クエリが到着すると、すべてのコンポーネント内のすべてのペアを反復処理して、gcd と XOR 条件をテストできます。 これは正しいですが、次のコンポーネントが含まれています。$10^5$ノードはすでに約を作成しています$5\cdot10^9$ペアなので機能しません。 

重要な観察は、算術条件から得られます。 2 つの値があるとします$x$そして$y$満足する$$\gcd(x,y)=x\oplus y=d$$それから$d$両方を分割します$x$そして$y$。 逆に、もし$d=x\oplus y$そして$d$両方の数値を除算すると、gcd は XOR も除算する必要があります。$d$それ自体は両方の数値を除算します。gcd は正確に$d$。 

これは、考えられるすべての値について、他のどの値が有効なペアを形成できるかを知る必要があるだけであることを意味します。 最大値はあくまで$200000$したがって、すべての互換性のある値のペアを事前に計算できます。 

考えられるすべての XOR 値について$d$のすべての倍数を検査します。$d$。 もし$x$の倍数です$d$、計算します$y=x\oplus d$。 もし$y$も倍数です$d$、ペア$(x,y)$有効です。 総作業量は、$$200000(1+\frac12+\frac13+\dots+\frac1{200000})$$それは約です$2.5$百万回の反復。 

この前処理の後、各コンポーネントに必要なのは、値の頻度表とその現在の答えだけです。 値のノードを 1 つ追加する$v$値が一致する既存のノードとまったく同じ数の新しい不良ペアを作成します。$v$。 値を削除すると、この操作が逆になります。 

残りの問題はコンポーネントのマージです。 小規模から大規模へのマージを使用します。 2 つのコンポーネントが結合する場合、小さい方の周波数マップを反復処理し、その値を大きい方の周波数マップに挿入します。 各ノードはマップ間のみを移動します$O(\log n)$回。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$操作ごと |$O(n)$| 遅すぎる |
 | 最適 |$O(V\log V+(n+m)\log n\cdot C)$|$O(V+n)$| 承認済み |

 ここ$V=200000$、 そして$C$1 つの値に対する互換性のある値の平均数です。 

## アルゴリズムのチュートリアル

 1. 条件を満たすすべての値のペアを事前計算します。 考えられるすべての XOR 結果に対して$d$、の倍数にわたって反復します。$d$、 テスト$x\oplus d$、有効な場合は関係を保存します。 これにより、後の操作が単純な周波数ルックアップに変わります。 
2. ノードの素セット共用体構造を構築します。 各コンポーネントは、周波数に値をマッピングする辞書と、そのコンポーネント内の不良ペアの数を含むカウンターを保存します。 
3. コンポーネントに値を挿入する場合は、挿入された値の事前に計算された互換性のある値を調べます。 現在の頻度の合計が、作成された新しい不良ペアの数になります。 次に、周波数を上げます。 
4. 値を削除する場合は、頻度を下げる前に同じ検索を実行します。 得られた数はまさに消滅したペアの数となります。 
5. マージ操作の場合は、両方のルートを見つけます。 すでに等しい場合は、何も変わりません。 それ以外の場合は、小さい周波数辞書を持つコンポーネントを選択し、それを大きい辞書にマージします。 各値を小さい方から挿入する前に、現在の大きいコンポーネントとの交差コンポーネントのペアを数えます。 
6. すべての操作の後、影響を受けるコンポーネントの寄与のみをグローバル回答に追加または削除します。 データ構造には、すべてのコンポーネントの回答の合計が常に保存されます。 

なぜ効果があるのか:

 不変条件は、すべてのコンポーネント ディクショナリにそのコンポーネント内の現在のノードの値が正確に含まれており、格納されたコンポーネントの回答がそれらのノード間の有効なペアの数に等しいということです。 1 回の挿入または削除では、そのノードに関係するペアのみが変更され、それらは互換性リストを通じて直接カウントされます。 マージでは、2 つの古いコンポーネント間に新しいペアのみが作成され、辞書を結合するときにカウントされます。 他のペアは影響を受けないため、すべての操作の後でもグローバルな答えは正しいままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 200000

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    compat = [[] for _ in range(MAXV + 1)]
    for d in range(1, MAXV + 1):
        for x in range(d, MAXV + 1, d):
            y = x ^ d
            if y > x and y <= MAXV and y % d == 0:
                compat[x].append(y)
                compat[y].append(x)

    parent = list(range(n + m + 5))
    bags = [None] * (n + m + 5)
    bad = [0] * (n + m + 5)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def add_value(root, v):
        s = 0
        for u in compat[v]:
            s += bags[root].get(u, 0)
        bad[root] += s
        bags[root][v] = bags[root].get(v, 0) + 1

    def remove_value(root, v):
        s = 0
        for u in compat[v]:
            s += bags[root].get(u, 0)
        bad[root] -= s
        bags[root][v] -= 1
        if bags[root][v] == 0:
            del bags[root][v]

    for i in range(1, n + 1):
        bags[i] = {}
        add_value(i, a[i])

    total = 0
    for i in range(1, n + 1):
        total += bad[i]

    out = []
    cur = n

    for _ in range(m):
        op = list(map(int, input().split()))
        t = op[0]

        if t == 1:
            cur += 1
            x, v = op[1], op[2]
            parent[x] = x
            bags[x] = {}
            add_value(x, v)
            a[x] = v

        elif t == 2:
            x, y = op[1], op[2]
            rx, ry = find(x), find(y)
            if rx != ry:
                total -= bad[rx] + bad[ry]
                if len(bags[rx]) < len(bags[ry]):
                    rx, ry = ry, rx
                parent[ry] = rx
                bad[rx] += bad[ry]
                for v, c in bags[ry].items():
                    for u in compat[v]:
                        total_pairs = bags[rx].get(u, 0)
                        bad[rx] += c * total_pairs
                    bags[rx][v] = bags[rx].get(v, 0) + c
                bad[ry] = 0
                bags[ry] = {}
                total += bad[rx]

        else:
            x, v = op[1], op[2]
            r = find(x)
            total -= bad[r]
            remove_value(r, a[x])
            add_value(r, v)
            a[x] = v
            total += bad[r]

        out.append(str(total))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```前処理により、互換性グラフが一度構築されます。 XOR 値は両方の数値を除算する必要があるため、条件チェックは割り算に限定されます。 

素のセット構造は、変化するフォレストに対応します。 すべての操作は接続されたコンポーネント全体に影響を与えるため、ディクショナリは個々のノードではなくコンポーネント ルートに接続されます。 

挿入ヘルパーと削除ヘルパーは対称的です。 周波数を変更する前に影響を受けるペアをカウントするため、複数のノードが同じ値を共有する場合の間違いが回避されます。 

マージ中、小さい辞書は常に大きい辞書に移動されます。 これにより、ノードごとの辞書移動の合計数が対数に保たれます。 グローバル応答は、コンポーネントの変更の前後で調整されるため、変更されたコンポーネントのみが再計算されます。

 ## 特殊なケース

 2 つの等しい正の整数の XOR がゼロであり、gcd が正であるため、値が等しい場合が処理されます。 互換性の前処理では自己ペアが作成されないため、等しい値を挿入しても誤って無効なペアが追加されることはありません。 

すでに接続されているノードを繰り返しマージしても無害です。 例えば：```
3 2
1 2 3
2 1 2
2 1 2
```最初のマージではコンポーネントが結合されます。 2 番目のマージでは、同一の DSU ルートが検索され、何も行われず、答えは変更されません。 

大きなコンポーネント内の値の更新は、最初に古い値の寄与を削除し、次に新しい値を追加することによって処理されます。 のために：```
2 2
2 2
2 1 2
3 1 3
```マージでは有効なペアが作成されません。 更新により古い値 2 が削除され、新しい値 3 が残りの値 2 と照合され、有効なペアが 1 つ見つかります。 アルゴリズムは影響を受けるペアのみを変更するため、保存されたコンポーネント数は正しいままになります。
