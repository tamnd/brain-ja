 ## 解決策
 ## 問題の理解

 削除する必要がある量を値が表す配列が与えられます。 操作は 1 つの隣接するペアに作用します。 

過ごしたら$t$ギリギリの秒数$(i,i+1)$、減算してもよい$(x t, y t)$ペアから、または$(y t, x t)$ペアから。 

任意のサブ配列に対して$a=[b_l,\dots,b_r]$、 定義する$f(a)$すべての要素が非正になるまでに必要な最小合計時間として。 

配列はオンラインで更新され、タイプ 2 の各クエリの後にレポートする必要があります。$f$要求されたセグメントの場合。 

問題はアップデートではありません。 本当の課題は、その量を理解することです$f(a)$実際にそうです。 

配列の長さは最大です$2\cdot 10^5$、まであります$2\cdot 10^5$更新と範囲クエリ。 セグメントの答えを最初から再計算するソリューションは直ちに除外されます。 平$O(\text{length})$クエリごとに約$4\cdot 10^{10}$最悪の場合の運用。 

答えも実数であり、これは通常、最適化問題を線形プログラムまたは同等の組み合わせ構造に変換する必要があることを示します。 

下限を生成する引数内で、ある位置が他のすべての位置から分離されている場合、微妙なエッジ ケースが発生します。 

たとえば、$x=1,y=2$と配列$[100,1,100]$、位置 1 と位置 3 が同じ操作に属することはありません。 合計のみに基づいた単純な議論では、次のようになります。$$\frac{201}{3}=67.$$ただし、位置 1 と位置 3 を合わせると、少なくとも$$\frac{100+100}{2}=100$$秒。各操作でレートが減少できるのは最大でも 1 つだけであるためです。$2$。 正しい答えは、より強い制約によって決まります。 

もう 1 つの簡単な間違いは、すべてのポジションが独立して貢献していると仮定することです。 

のために$[100,100]$、$$f=\frac{200}{x+y},$$ない$$\frac{100}{y}+\frac{100}{y}.$$両方の位置の間の 1 つのエッジを操作することで、両方の位置を同時に処理できます。 

全体的な解決策は、同時に達成可能な下限を正確に理解することから生まれます。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての操作に変数を導入します。 させて$p_i$エッジで費やした時間になる$i$向きを使用する$(x,y)$、 そして$q_i$オリエンテーションの使用に費やした時間$(y,x)$。 

すべての配列位置は、隣接するエッジから寄与を受け取ります。 合計時間を最小限に抑えたい$$\sum_i (p_i+q_i)$$すべての要素がゼロに削減されることを条件とします。 

これは線形プログラムです。 それは正しいですが、含まれているのは、$O(n)$単一のクエリでも変数を使用できます。 直接解決するのは絶望的です。 

重要な観察は、双対線形プログラムが予想外に単純な構造をしているということです。 想定した上で$x\le y$、二重変数は重みとして解釈できます。$d_i$ポジションに割り当てられます。 

二重制約は、すべての$d_i$のいずれかである必要があります$$0,\quad \frac1{x+y},\quad \frac1y,$$そしていつでも$d_i=\frac1y$、両方の近傍がゼロでなければなりません。 つまり、係数を使用した位置$1/y$パスの独立したセット内で選択された頂点のように動作します。 係数を使用した位置$1/(x+y)$他のものとの相互作用はありません。 

LP 双対性によって証明された重要な事実は、実行可能なすべての双対解には下限が与えられるということです。$f(a)$、そのような最良の下限は正確に次のとおりです。$f(a)$。 

したがって、元の最適化問題は次のようになります。$$f(a)= \max \sum_i a_i d_i,$$それぞれどこで$d_i$から選ばれます$$0,\frac1{x+y},\frac1y,$$と位置を使用して$1/y$隣接することはできません。 

さて、問題は純粋に組み合わせの問題です。 各位置には 3 つの可能な状態があります。 

状態 0 が貢献$0$。 

状態 1 が寄与する$a_i/(x+y)$。 

状態 2 が寄与する$a_i/y$。 

唯一の制限は、連続する 2 つの位置が両方とも状態 2 にならないことです。 

これはパス DP です。 クエリは更新を含む任意のサブセグメントを要求するため、DP 遷移を max-plus マトリックスとして保存し、セグメント ツリーでマトリックスの積を維持します。 これはまさに、受け入れられているソリューションで使用されている構造です。

 ## アルゴリズムのチュートリアル

 仮定する$x \le y$。 そうでない場合は、交換してください。 

1つのポジションに対して$i$、3 つの状態を定義します。 

状態 0 は係数を意味します$0$。 

状態 1 は係数を意味します$1/(x+y)$。 

状態 2 は係数を意味します$1/y$。 

ポジションごとの貢献価値$i$は：$$0,\quad \frac{a_i}{x+y},\quad \frac{a_i}{y}$$それぞれ。 

1. を構築します。$3\times3$すべての位置の max-plus マトリックス。 

行列には対角値のみが含まれます。 

状態 0 が貢献$0$。 

状態 1 が寄与する$a_i/(x+y)$。 

状態 2 が寄与する$a_i/y$。 
2. 隣接する位置間の遷移行列を作成します。 

状態を除くすべての遷移が許可されます$2 \to 2$。 

これは、係数を使用して位置を決定するルールをエンコードします。$1/y$隣接することはできません。 
3. max-plus 行列の乗算を使用して、隣接するセグメントを結合します。 

マトリックスの場合$A$は左側のセグメントを表し、$B$右側のセグメント、次に$$A \cdot T \cdot B$$はそれらの連結を表します。$T$は遷移行列です。 
4. これらの行列をセグメント ツリーに保存します。 

各ノードは、その間隔を表す行列を格納します。 
5. 更新するには、リーフ行列を再構築し、ルートへのパス上の行列を再計算します。 
6. 範囲クエリの場合$[l,r]$、その間隔を正確に表す行列を取得します。 
7. 答えは、結果として得られる行列の最大エントリです。 

これは、境界状態の最適な選択、つまり最適な双対値に対応します。 

### なぜ効果があるのか

 二重の特徴付けでは、実行可能なすべての解決策は状態のシーケンスであると述べています。$0,1,2$、ここで状態 2 は隣接する位置に現れることはできません。 目標値はまさに州の拠出金の合計です。 

セグメント行列には、境界状態のペアごとに達成可能な最良の値が格納されます。 マックスプラス乗算は、隣接する状態の互換性を確保しながら DP 間隔を連結する標準的な方法です。 

行列の乗算はパス DP の反復を正確に再現するため、すべてのセグメント ツリー ノードにはその間隔の最適値が格納されます。 クエリされた行列の最大エントリは、すべての可能な境界選択に対する最適値であり、双対最適値に等しくなります。 LP 二重性は、二重最適値が元の最小時間と等しいことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 1e100

def mat_mul(A, B):
    C = [[-INF] * 3 for _ in range(3)]
    for i in range(3):
        ai = A[i]
        for k in range(3):
            if ai[k] <= -INF / 2:
                continue
            v = ai[k]
            bk = B[k]
            for j in range(3):
                nv = v + bk[j]
                if nv > C[i][j]:
                    C[i][j] = nv
    return C

class SegTree:
    def __init__(self, arr, x, y):
        self.n = len(arr)
        self.x = x
        self.y = y

        self.trans = [[-INF] * 3 for _ in range(3)]
        for i in range(3):
            for j in range(3):
                if ((i != 2 and j != 2) or i == 0 or j == 0):
                    self.trans[i][j] = 0.0

        self.seg = [None] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def leaf(self, val):
        M = [[-INF] * 3 for _ in range(3)]
        M[0][0] = 0.0
        M[1][1] = val / (self.x + self.y)
        M[2][2] = val / self.y
        return M

    def merge(self, A, B):
        return mat_mul(mat_mul(A, self.trans), B)

    def build(self, p, l, r, arr):
        if l == r:
            self.seg[p] = self.leaf(arr[l])
            return

        m = (l + r) // 2
        self.build(p * 2, l, m, arr)
        self.build(p * 2 + 1, m + 1, r, arr)
        self.seg[p] = self.merge(self.seg[p * 2], self.seg[p * 2 + 1])

    def update(self, p, l, r, idx, val):
        if l == r:
            self.seg[p] = self.leaf(val)
            return

        m = (l + r) // 2
        if idx <= m:
            self.update(p * 2, l, m, idx, val)
        else:
            self.update(p * 2 + 1, m + 1, r, idx, val)

        self.seg[p] = self.merge(self.seg[p * 2], self.seg[p * 2 + 1])

    def modify(self, idx, val):
        self.update(1, 0, self.n - 1, idx, val)

    def query(self, p, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.seg[p]

        m = (l + r) // 2
        if qr <= m:
            return self.query(p * 2, l, m, ql, qr)
        if ql > m:
            return self.query(p * 2 + 1, m + 1, r, ql, qr)

        left = self.query(p * 2, l, m, ql, qr)
        right = self.query(p * 2 + 1, m + 1, r, ql, qr)
        return self.merge(left, right)

    def range_answer(self, l, r):
        M = self.query(1, 0, self.n - 1, l, r)
        ans = -INF
        for i in range(3):
            for j in range(3):
                ans = max(ans, M[i][j])
        return ans

def solve():
    n, q = map(int, input().split())
    x, y = map(int, input().split())

    if x > y:
        x, y = y, x

    b = list(map(int, input().split()))

    seg = SegTree(b, x, y)

    out = []

    for _ in range(q):
        op, a, c = map(int, input().split())

        if op == 1:
            seg.modify(a - 1, c)
        else:
            out.append(f"{seg.range_answer(a - 1, c - 1):.15f}")

    sys.stdout.write("\n".join(out))

solve()
```リーフ行列は、単一の位置の 3 つの可能な状態を表します。 長さ 1 のセグメントは同じ状態で開始および終了するため、対角エントリのみが有効です。 

遷移行列には、許可された状態のペアにはゼロが含まれ、禁止された状態のペアには負の無限大が含まれます。 唯一の禁止された隣接関係は、状態 2 の隣の状態 2 です。 

マージ操作が実行される$$A \cdot T \cdot B$$マックスプラス代数で。 これは、2 つの間隔を連結するための DP 反復です。 

クエリの結果は、セグメント全体を記述する行列です。 最大のエントリを取得すると、境界状態の制限がなくなり、最適な値が得られます。

 ## 特殊なケース

 検討してください$x=1,y=2$と配列$[100,1,100]$。 

総和の下限は、次のことのみを与えます。$$201/3=67.$$私たちの DP は、位置 1 と 3 で状態 2 を選択できます。 

| ポジション | 状態 | 貢献 |
 | --- | --- | --- |
 | 1 | 2 | 50 |
 | 2 | 0 | 0 |
 | 3 | 2 | 50 |

 答えは少なくとも次のようになります$100$、これが本当のボトルネックです。 独立集合構造はこれを自動的に捕捉します。 

考慮する$[100,100]$。 

両方の位置で状態 2 を選択することは禁止されています。 最良の解決策は次のとおりです。 

| ポジション | 状態 | 貢献 |
 | --- | --- | --- |
 | 1 | 1 | 100/(x+y) |
 | 2 | 1 | 100/(x+y) |

 合計：$$\frac{200}{x+y}.$$これは、唯一のエッジ上の 1 つの操作で両方の要素を同時に処理できるという事実と一致します。 

次のような、配列の境界における長さ 2 の範囲クエリを考えてみましょう。$[1,2]$。 

セグメント ツリー クエリは、その間隔の行列を正確に返します。 境界状態は行列自体の内部でエンコードされるため、特別な処理は必要ありません。 最大エントリを取得すると、すべての有効な開始状態と終了状態が自動的に考慮されます。
