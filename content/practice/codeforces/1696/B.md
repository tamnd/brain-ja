 ## 解決策
 ## 問題の理解

 「宇宙」を表す配列が与えられます。各要素は負でない整数です。 主人公である NIT は、任意の連続したサブ配列に対して特定の操作を実行できます。`mex`その部分配列のすべての要素をそれに設定します`mex`。 タスクは、配列全体をゼロに変えるために必要なそのような操作の最小数を見つけることです。 

入力には複数のテスト ケースが含まれており、それぞれの長さは最大 100,000 の配列であり、すべてのテスト ケースにわたる要素の合計数は 200,000 を超えません。 これは、テスト ケースあたりの時間計算量が O(n) を大幅に超えるアルゴリズムは制限時間を超える可能性があることを意味します。 たとえば、繰り返し計算を行う単純な総当たりアプローチ`mex`任意の部分配列上では O(n²) 以上になるため、これは受け入れられません。 基本的にアレイを 1 回または 2 回スキャンするソリューションが必要です。 

明らかではないエッジ ケースには、既に完全にゼロで構成されている配列、ゼロから始まる完全なシーケンスである配列、間にギャップのある非常に大きな数値を含む配列が含まれます。 たとえば、配列`[0,1,2,3,4]`1回の操作で解決できますが、`[0,2,3,0,1,2,0]`2 つ必要です。 最大要素のみを考慮したり、連続番号を想定したりする不注意なアプローチでは、必要な演算を誤って計算する可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、一部のサブ配列を繰り返し選択し、そのサブ配列を計算します。`mex`、すべての要素がゼロになるまで操作を適用します。 これが機能するのは、最終的には 1 つ以上の操作を使用して、ゼロ以外の要素をゼロにできるためです。 ただし、それぞれの計算は、`mex`は O(n) を必要とする可能性があり、そのような操作が複数あると、最悪のシナリオでは複雑さが簡単に O(n²) に達する可能性があり、10^5 までの n には遅すぎます。 

重要な洞察は、必要な操作の数は、存在する最小値と最大値、およびゼロが含まれるかどうかのみに依存するということです。 配列に既にゼロのみが含まれている場合は、操作は必要ありません。 配列にゼロが欠落している場合は、配列全体に対して単一の操作を実行してゼロを導入できます。 ゼロが存在するが、削除する必要があるゼロより大きい要素がある場合、最大 2 つの操作が必要になる可能性があります。 具体的には、1 つの操作で連続したブロックをそのブロックに縮小できます。`mex`、ゼロが欠落している場所にゼロが導入される可能性があり、2 番目の操作で残りの非ゼロ要素全体にゼロが伝播される可能性があります。 

問題は、配列内の最小値、最大値、およびゼロを基準にして最大値が発生する最初と最後の位置をチェックすることになります。 これにより、操作が 0 回、1 回、または 2 回のいずれで十分であるかを判断できます。 最適なソリューションでは、操作を直接シミュレートする必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列が既に完全にゼロで構成されているかどうかを確認します。 その場合、操作は必要ないため、0 を返します。 
2. 配列の最小要素を計算します。 最小値がゼロより大きい場合は、配列全体に対して単一の操作を実行してゼロを導入し、1 を返します。これにより、配列内の最小値がゼロになることが保証されます。 
3. 配列内の最大要素とその最初と最後の出現位置を特定します。 配列にゼロが含まれており、すべての要素が最大値以下であるが、ゼロから始まる連続ブロックに出現する場合、残りの非ゼロ要素をゼロに変換するには 1 回の操作で十分です。 
4. 一般に、ゼロが存在するが、ゼロで区切られた非ゼロ要素を含む部分配列が存在する場合、2 つの操作が必要になる場合があります。 最初の操作では、ブロックを次のように縮小します。`mex`、必要に応じてゼロを導入します。 2 番目の操作では、残りの非ゼロ要素にゼロを拡散します。 
5. 上記のチェックで決定された操作の数を返します。すべて 0 の場合は 0、ゼロがない場合または 1 つの操作で十分な場合は 1、それ以外の場合は 2 を返します。 

機能する理由: このアルゴリズムが機能する理由は、`mex`この操作により、連続する部分配列を最小の欠損値に減らすことができます。 大域的な最小値と最大値、およびそれらの位置のみを検査することで、すべてのサブ配列演算をシミュレートせずに、1 つまたは 2 つの演算で十分であるかどうかを判断するために必要な条件を取得します。 これにより、O(n) 時間以内の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if all(x == 0 for x in a):
            print(0)
            continue
        mn = min(a)
        mx = max(a)
        if mn > 0:
            print(1)
            continue
        first = None
        last = None
        for i, x in enumerate(a):
            if x == mx:
                if first is None:
                    first = i
                last = i
        # check if all elements between first and last are mx
        if all(a[i] == mx for i in range(first, last + 1)):
            print(1)
        else:
            print(2)

if __name__ == "__main__":
    solve()
```この解決策は、まず、すでにゼロで構成されている配列の最も単純なケースを処理します。 そうでない場合は、最小値がゼロより大きいかどうかがチェックされます。これは、1 回の操作でゼロを導入できることを意味します。 それ以外の場合は、最大要素を見つけて、それが連続したブロック内に出現するかどうかを確認します。 そうであれば、1 回の操作で十分です。 ギャップがある場合は、2 つの操作が必要です。 このアプローチにより、不必要なシミュレーションが回避され、最小限の操作数が保証されます。 

## 実用的な例

 **例 1:**`[0, 0, 0, 0]`| ステップ | ん | MX | 最初 | 最後 | 操作数 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 0 | 0 | - | - | 0 |

 すべてゼロなので、出力は 0 になります。 

**例 2:**`[0, 2, 3, 0, 1, 2, 0]`| ステップ | ん | MX | 最初 | 最後 | 連続チェック | 操作数 |
 | --- | --- | --- | --- | --- | --- | --- |
 | イニシャル | 0 | 3 | 2 | 3 | 偽 | 2 |

 最大値は 3 ですが、その出現は連続していません。 したがって、2 つの操作が必要になります。 

これらのトレースは、最小値、最大値、および位置を特定するだけで答えを決定するのに十分であることを示しています。

 ## 特殊なケース

 のために`[0,1,0]`、最小値は 0、最大値は 1 です。最大値は非連続部分配列 (位置 2) で発生するため、アルゴリズムは正しく 2 を返します。`[5,5,5,5,5]`, min > 0 であるため、配列全体に対する 1 回の操作でゼロが導入されます。 のために`[0,0,0,0]`、すべてゼロであるため、操作は必要ありません。 これらの例は、アルゴリズムが重大なエッジ ケースを正しく処理することを確認します。
