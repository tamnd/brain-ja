 ## 解決策
 ## 問題の理解

 各ゲームでは、ライン上に時間指定された一連のターゲットが記述されます。 すべてのターゲットは、時刻とライン上の位置で構成されるペアです。 時間ゼロから開始して、Awa は任意の初期位置を選択し、固定最大速度でラインに沿って移動できます。 ターゲットが現れたとき、その時点でその位置に正確にいた場合にのみ、ゴールを決めることができます。 

タスクは、制限速度を決して超えずに、時間ゼロの任意の位置から開始して時間の増加順にターゲットを移動する何らかの方法が存在するように、これらのターゲットの可能な限り最大のサブセットを選択することです。 

重要な問題は、実現可能性がローカルではないことです。 目標に到達できるかどうかは、どの以前の目標から来たのかによって決まります。各選択によって、以前にどこにいたのかが決まるからです。 

この制約は、テスト ケースごとにすべてのターゲット間の単純なペアごとのチェックが不可能であることを意味します。 すべてのテストの合計ポイントが最大 5e5 であるため、二次アプローチでは最悪の場合でも 10^11 程度のチェックが必要になりますが、これは 1 秒の制限をはるかに超えています。 

最もデリケートなエッジ ケースは、時間的には近いが空間的には遠いターゲットから発生します。またはその逆の場合、貪欲な選択により、ローカルで到達可能なポイントが選択され、後ではるかに大きなチェーンへのアクセスがブロックされる可能性があります。 

たとえば、次の 2 つの点を考慮してください。 

時間と位置のペア (0, 0)、(1, 1000000000) を低速で実行します。 2 つ目は 1 つ目からは到達不可能であるため、順序や位置のみに基づいて到達可能性を想定したソリューションはすぐに失敗します。 逆に、時間的には遠くに見えるが空間的には近い点でも、中間の移動が可能であれば連鎖させることができます。 

本当の課題は、到達可能性がポイント上の部分的な順序を定義しており、その構造内で最長のチェーンが必要であることです。 

## アプローチ

 ブルートフォースを試みる場合は、各ポイントをノードとして考え、以前のすべてのポイントをチェックして、そのノードで終わる最適なチェーンを計算しようとします。 時間的に i が早い点 i と j のペアについて、Awa が利用可能な時間差内で j から i に移動できるかどうかを確認します。 これにより、自然な動的プログラミング遷移が生成されます。 

正確さは簡単です。すべての有効なルートは最終点で終了し、前のステップですべての可能性を試します。 

ネックとなるのは移行コストだ。 n 点の場合、すべてのペアをチェックする必要があり、テスト ケースごとに O(n^2) の遷移が生成されます。 合計ポイントが 5e5 であるため、これは実行できません。 

重要な観察は、変換後に到達可能性条件を幾何学的支配制約に書き換えることができるということです。 各点 (t、x) は、この点に到達するまでにアワが左右にどれくらい離れているかをエンコードする 2 つの派生値にマッピングできます。 この変換の下では、点 j が i に対して特定の優勢領域にある場合、点 j は正確に点 i に到達できます。 

これにより、問題は 2D 半順序の下で最長のチェーンを見つけることに変換されます。 このように見ると、この構造は圧縮を調整しやすくなり、範囲全体で最大 DP 値を維持するデータ構造になります。 

最終的な解決策は、慎重に選択した順序でポイントを処理し、フェンウィック ツリー (または同様の構造) を使用して、一方の座標で最良の DP 値を維持しながら他方の座標で反復することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアに対するブルート フォース DP | O(n²) | O(n) | 遅すぎる |
 | 座標変換 + BIT DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての点について、速度に対する到達可能な空間の制約をエンコードする、その時間と位置から 2 つの導出値を計算します。 これらの値は、有効な移動セグメントを通じてポイントがどこまで左右に接続できるかをキャプチャします。 
2. すべてのポイントを左リーチ値の降順に並べ替えます。 これにより、ポイントを処理するときに、(1 つの制約に関して) チェーン内でそのポイントに合法的に先行する可能性のあるすべての候補がすでに考慮されることが保証されます。 
3. 右リーチ座標上にフェンウィック ツリーを維持します。 ツリーには、指定された圧縮座標を持つ任意の点で達成された最大 DP 値が格納されます。 
4. ソートされた順序でポイントを処理します。 各ポイントについて、2 番目の制約 (右リーチ優勢) を満たすすべてのポイントの中で最良の DP 値をフェンウィック ツリーにクエリします。 これにより、この時点で終了する最良の有効な先行チェーンが得られます。 
5. dp[i] をそのクエリされた値に 1 を加えた値に設定し、現在のポイントの右リーチ座標でフェンウィック ツリーを dp[i] で更新します。 
6. テスト ケースの答えは、すべてのポイントの最大 dp 値です。 

この順序付けが機能する理由は、最初に変換された座標による並べ替えにより、実現可能性条件の前半を満たさない限り、その点を先行点として使用しようとしないことが保証されるためです。 フェンウィックの木が効率的に後半を進めます。 

### なぜ効果があるのか

 2 点間の有効な遷移は、速度制約から導出される 2 つの不等式に依存します。 変換後、これらの不等式は 2 次元での支配関係になります。 したがって、有効なチェーンはすべて、これらの支配ルールによって定義された部分的に順序付けられたセット内のチェーンです。 

ソートにより、この順序の 1 つの軸がグローバルに尊重され、フェンウィック ツリーがもう 1 つの軸をローカルに適用することが保証されます。 dp[i] を計算するたびに、実行可能なすべての先行処理がすでに処理されており、クエリ可能になります。 これにより、dp[i] が常に i で終わる最適な有効なチェーンを反映することが保証され、少なくとも 1 つの優先制約に違反するため、無効な先行操作を含めることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, v = map(int, input().split())
        pts = []

        for _ in range(n):
            t, x = map(int, input().split())
            A = x - v * t
            B = x + v * t
            pts.append((A, B))

        # compress B
        vals = sorted({b for _, b in pts})
        idx = {v: i + 1 for i, v in enumerate(vals)}

        pts.sort(reverse=True)  # sort by A descending

        bit = BIT(len(vals))
        ans = 0

        for A, B in pts:
            bi = idx[B]
            best = bit.query(bi)
            dp = best + 1
            if dp > ans:
                ans = dp
            bit.update(bi, dp)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、2 番目に変換された座標を圧縮して、フェンウィック ツリーで使用できるようにします。 各ポイントは最初に変換された座標の降順で処理され、ツリーは実行可能な先行ポイントに対して最適なチェーン長を維持します。 

微妙な点は、DP 状態では時間を明示的に追跡する必要がないということです。 変換では、導出された座標に時間がすでにエンコードされているため、実現可能性は支配関係によって完全に把握されます。 

## 実用的な例

 3 つの点がある小さなケースを考えてみましょう。 

入力点 (t, x):

 (0, 0)、(2, 2)、(4, 1) (v = 1)

 変換された値を計算します。 

| ポイント | A = x - vt | B = x + vt |
 | --- | --- | --- |
 | (0,0) | 0 | 0 |
 | (2,2) | 0 | 4 |
 | (4,1) | -3 | 5 |

 降順で並べ替えると次のようになります。 

(0,0)、(2,2)、(4,1)

 私たちは以下を処理します:

 | ステップ | ポイント | ビットクエリ(B) | DP | ビットアップデート |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | 0 | 1 | B=0 ～ 1 に設定 |
 | 2 | (2,2) | 1 | 2 | B=4 を 2 に更新 |
 | 3 | (4,1) | 2 | 3 | B=5 を 3 に更新 |

 最終的な答えは 3 で、速度制約の下ですべてのポイントがチェーン可能であることを示しています。 

このトレースは、両方の優勢条件が満たされた場合に、ソート順序内の以前のポイントが、後のポイントの潜在的な先行ポイントとしてどのように正しく機能するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートとフェンウィック ツリーの更新とクエリ |
 | スペース | O(n) | 変換されたポイントと BIT のストレージ |

 すべてのテスト ケースにわたって、ポイントの合計数は 5e5 で制限されるため、ソリューションは制限内で快適に実行されます。 座標圧縮と BIT 演算による対数係数により、総作業量がしきい値を十分に下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def update(self, i, v):
            while i <= self.n:
                self.bit[i] = max(self.bit[i], v)
                i += i & -i

        def query(self, i):
            res = 0
            while i > 0:
                res = max(res, self.bit[i])
                i -= i & -i
            return res

    T = int(input())
    out = []

    for _ in range(T):
        n, v = map(int, input().split())
        pts = []
        for _ in range(n):
            t, x = map(int, input().split())
            pts.append((x - v * t, x + v * t))

        vals = sorted({b for _, b in pts})
        idx = {v: i + 1 for i, v in enumerate(vals)}

        pts.sort(reverse=True)

        bit = BIT(len(vals))
        ans = 0

        for a, b in pts:
            bi = idx[b]
            dp = bit.query(bi) + 1
            bit.update(bi, dp)
            ans = max(ans, dp)

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、複数のポイントが同様の変換された座標を共有しているものの、時間の経過とともに大きく異なる場合です。 変換は時間をエンコードするため、そのような点が同一の A または B 値を持つ可能性があり、座標圧縮中に崩壊する可能性があります。 フェンウィック ツリーは、同一の座標が同等の状態として扱われ、DP 値が自然に達成可能な最良のチェーンを蓄積するため、これを安全に処理します。 

もう 1 つの微妙なケースは、点が空間順序では降順で表示されるが、時間順序では昇順で表示される場合に発生します。 素朴な貪欲なアプローチでは、時間順序のみに従おうとしますが、空間距離が速度制限を超えるため、実現可能性が損なわれる可能性があります。 変換された表現では、そのようなケースは少なくとも 1 つの次元で比較できなくなり、無効な遷移が考慮されなくなります。 

最後に、すべてのポイントが実行可能な狭いコリドー上にある場合、すべてのポイントが以前のすべてのポイントから到達できる最大のチェーンが生成されます。 この状況では、BIT は増加する DP 値を継続的に伝播し、事実上、変換された座標に対する最長の増加サブシーケンスの計算に縮退します。
