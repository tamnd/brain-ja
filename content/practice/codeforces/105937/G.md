 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、$N$3 次元整数空間内の点。 各ポイントは 3 つの属性を持つパートナーを表します$(S, F, E)$。 目標は、すべてのポイントが同一になるように操作を適用することです。つまり、すべてのパートナーがまったく同じトリプルで終了することになります。 

操作は、選択した 1 つのパートナーに適用されます。 そのパートナーについては、3 つの座標の空でないサブセットを選択し、選択したすべての座標を 1 だけインクリメントするか、選択したすべての座標を 1 だけデクリメントします。そのような操作ごとに 1 ユニットのコストがかかります。 

タスクは、すべての点を等しくするために必要な操作の合計数を最小限に抑えることです。 

制約により、最大で次のことが許可されます。$10^5$値が最大のポイント$10^5$したがって、すべてのターゲット構成を試したり、候補ターゲットごとに変換をシミュレートしたりするソリューションは、線形またはほぼ線形である必要があります。$N$。 ターゲットに対する 3 次または 2 次の検索は直ちに不可能です。$O(N \log N)$候補空間が大きい場合、候補ターゲットごとの処理は遅すぎます。 

この問題の微妙な点は、操作が座標を結合することです。 私たちは調整していません$S, F, E$独立して: 1 つ、2 つ、または 3 つすべてを同時に変更できるため、次元間の相互作用が生じ、これが標準の 3D 中央値問題とは異なります。 

単純な間違いは、中央値を使用して各座標を個別に最適化できると想定することです。 もう 1 つの間違いは、すべてのポイントが共有ターゲットに収束する必要があることを認識せずに、各ポイントを独立して扱うことです。 

単純な座標の独立性が明らかに正当化されない小さな例は、点が次のような場合です。$$(0,0,10), (10,0,0)$$座標ごとにターゲットを個別に選択すると、$(5,0,5)$ただし、実際のコスト構造は、ジョイント アップデートによって座標間の移動コストがどのように削減されるかによって異なります。 不注意なソルバーはカップリングを無視し、実現可能性について誤った推論を行う可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。最終的な目標点を推測します。$(X, Y, Z)$、次に、すべてのポイントをこのターゲットに変換するために必要な操作の数を計算します。 固定小数点の場合、差分ベクトルを計算し、許可された演算を使用してそれを表現しようとします。 すべてのポイントを合計すると、そのターゲットのコストが求められます。 

これは正しいですが、ターゲット領域が大きいため使用できません。 各座標の範囲は次のとおりです。$10^5$なので、考えられるものをすべて列挙すると、$(X, Y, Z)$必要になるだろう$10^{15}$候補者たち。 観測された座標に限定しても、依然として問題は残ります$O(N^3)$可能性。 

重要な観察は、ターゲットが固定されるとコストが点ごとにきれいに分解され、総コストが絶対座標の差に対する同一の構造化関数の合計になるということです。 各点には 3 つの座標にわたって結合されたコストがありますが、結合によってクロスポイント相互作用は発生しません。 これにより、最適化を、対称絶対偏差式の合計を最小化する単一の最適なターゲットの選択に分けることができます。 

許可された操作セットを使用すると、1 つ、2 つ、または 3 つの座標をまとめて変更できます。これは、実質的に、移動が L1 距離とグループ化された更新圧縮の組み合わせである 3D 基準のように動作することを意味します。 この構造は、コストが絶対偏差にのみ依存し、各次元で凸であるため、最適なターゲットが各座標で中央値のように動作することを意味します。 

これを認識した後、問題は、最適なターゲットを座標方向の中央値として計算し、総コストを評価することに帰着します。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 この問題を、コストの合計を最小化する単一のターゲット ポイントを選択するという問題に変換します。ここで、各コストは座標ごとの絶対差にのみ依存します。 

### ステップ

 1. すべての値を抽出します。$S$、$F$、 そして$E$別々の配列に分割します。 

これが行われるのは、コスト関数が選択したターゲットとの絶対的な差にのみ依存するためであり、ポイントごとのコストが結合されている場合でも、各座標は集計において独立して寄与します。 
2. 3 つの配列をそれぞれソートします。 
3. 各配列の中央値をターゲット座標の候補として選択します。$X$すべての中央値です$S_i$、$Y$すべての中央値です$F_i$、 そして$Z$すべての中央値です$E_i$。 

この選択は、絶対偏差の合計を最小化することが中央値で達成されるという事実によって動機付けられています。 
4. 各ポイントについて$i$、次を計算します。$$dx = |S_i - X|,\quad dy = |F_i - Y|,\quad dz = |E_i - Z|$$5. 以下を使用して、この点のコスト寄与を計算します。$$cost_i = \max(\max(dx, dy, dz), \lceil (dx + dy + dz)/3 \rceil)$$最初の項は、操作ごとに 1 つより速く座標を減らすことができないことを強制します。 2 番目の項では、各操作が座標全体の合計偏差の最大 3 単位に影響を与える可能性があることを強制します。 
6. すべてを合計する$cost_i$そして結果を出力します。 

### なぜ効果があるのか

 各ポイントは、ターゲットに到達するために独立して最小数の操作を必要とし、2 つの独立した下限によって制限されます。つまり、単一座標の最大偏差と、一度に最大 3 つの座標に影響を与える操作で償却された L1 偏差の合計です。 この式は両方の制約を厳密に捉えています。 

ターゲットが固定されると、総コストは絶対偏差の凸関数の合計になります。 ターゲットを左または右にシフトすると絶対偏差の合計が増加するため、各座標が独立して中央値に配置される場合、このような合計は最小化されます。 各点内の結合は、異なる点の座標間に相互作用項を作成しないため、クロスポイントの最適化には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost(dx, dy, dz):
    s = dx + dy + dz
    return max(max(dx, dy, dz), (s + 2) // 3)

n = int(input())
S = []
F = []
E = []

pts = []
for _ in range(n):
    s, f, e = map(int, input().split())
    S.append(s)
    F.append(f)
    E.append(e)
    pts.append((s, f, e))

S.sort()
F.sort()
E.sort()

mx = S[n // 2]
my = F[n // 2]
mz = E[n // 2]

ans = 0
for s, f, e in pts:
    dx = abs(s - mx)
    dy = abs(f - my)
    dz = abs(e - mz)
    ans += cost(dx, dy, dz)

print(ans)
```実装では、ターゲットの選択とコストの評価が分離されます。 並べ替えは中央値を効率的に取得するために使用され、中央値は絶対偏差の合計を最小化するため、中央の要素が直接取得されます。 

コスト関数はポイントごとに一定時間で計算されます。 丸め$(s + 2) // 3$合計偏差の 3 分の 1 の上限を正しく実装します。 

## 実用的な例

 ### 例 1

 入力:$$(2,2,2), (2,2,2), (1,2,3)$$| ステップ | ターゲット | (dx,dy,dz) | 費用 |
 | --- | --- | --- | --- |
 | 選択された中央値 | (2,2,2) | - | - |
 | ポイント1 | (2,2,2) | (0,0,0) | 0 |
 | ポイント2 | (2,2,2) | (0,0,0) | 0 |
 | ポイント3 | (1,2,3) | (1,0,1) | 最大(1, ceil(2/3)=1) = 1 |

 合計 = 1。 

これは、結合偏差のある点が、座標の不均衡と全体の不均衡のうち最悪の場合にのみコストが発生することを示しています。 

### 例 2

 入力:$$(2,3,1), (3,5,3), (3,2,1)$$座標ごとの中央値は次のとおりです。$$(3,3,1)$$| ポイント | dx,dy,dz | 合計 | 最大 | 費用 |
 | --- | --- | --- | --- | --- |
 | (2,3,1) | (1,0,0) | 1 | 1 | 1 |

 | (3,2,1) | (0,1,0) | 1 | 1 | 1 |

これは、1 回の操作で 2 つの座標をペアにすることで、独立した 1D 移動と比較してコストがどのように削減されるかを示しています。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def cost(dx, dy, dz):
        s = dx + dy + dz
        return max(max(dx, dy, dz), (s + 2) // 3)

    n = int(input())
    pts = []
    S, F, E = [], [], []

    for _ in range(n):
        s, f, e = map(int, input().split())
        pts.append((s, f, e))
        S.append(s); F.append(f); E.append(e)

    S.sort(); F.sort(); E.sort()
    mx, my, mz = S[n//2], F[n//2], E[n//2]

    ans = 0
    for s, f, e in pts:
        dx, dy, dz = abs(s-mx), abs(f-my), abs(e-mz)
        ans += cost(dx, dy, dz)

    return str(ans)

 ## 特殊なケース

 すべての座標中央値が点自体に等しいため、1 つのパートナーによる最小構成が直接処理され、偏差もコストもゼロになります。 差分は計算されないため、アルゴリズムは当然ゼロを返します。 

すべてのポイントが同一の場合、並べ替えにより同一の中央値が生成され、すべての偏差がゼロになるため、コスト関数はポイントごとにゼロと評価されます。 これにより、整数の除算や丸めによる偶発的なオーバーカウントが回避されます。 

1 つの座標が大きく、他の座標が小さいなど、座標が大きく偏っている場合、コストの最大項により、単一の座標を減らすために必要な演算の過小評価が正しく防止され、中央値の選択により、ターゲット選択における体系的な偏りが防止されます。 

次のようなケースです。$$(0,0,100), (100,0,0), (0,100,0)$$各座標の中央値は順序に応じて 0 または 100 であり、偏差は対称的に分布しているため、他の座標を犠牲にして誤って過剰最適化される座標がないことが保証されるため、依然として正しく動作します。
