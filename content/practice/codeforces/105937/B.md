 ## 解決策
 ## 問題の理解

 チームごとに 1 つずつ、複数のログイン パスワードが与えられます。各パスワードは、数字、大文字と小文字、アンダースコア、ハイフンなどの印刷可能な文字で構成される単なる文字列です。 システムは、ログイン時に人間にとって 4 つの文字は混乱しすぎると判断しました。`1`、 小文字`i`、大文字`I`、および小文字`l`。 すべてのパスワードについて、これら 4 つの文字をすべて削除し、他のすべての文字を元の順序のままにして、クリーンなバージョンを作成する必要があります。 

入力サイズの制約は、ここで重要な構造の詳細です。 すべての文字列で合計最大 50,000 文字が存在するため、各文字を一定の回数だけ処理するソリューションであれば問題ありません。 ただし、バッファリングを行わずにループ内で繰り返し連結するなど、非効率的に文字列を繰り返し再構築するものは、文字列の不変性により Python で二次的な動作を行う危険性があります。 

エッジケースは単純ですが、それでも明示的に説明する価値があります。 

パスワードはすべて削除可能な文字で構成されている場合があります。 たとえば、入力`1iIl`出力として空の行が生成されるはずです。 ここでの単純な間違いは、空の行を出力することをまったく忘れていることであり、出力の配置がずれてしまいます。 

もう 1 つの特殊なケースは、文字が削除されない場合です。`abcXYZ_9-`。 出力は正確に一致する必要があります。 

3 番目の微妙なケースは、削除された文字が散在する大きな入力です。`1a1b1c1d1e`、文字のみを保存する必要があります。 

## アプローチ

 ブルートフォースの考え方は簡単です。文字列ごとに 1 文字ずつスキャンし、許可された文字のみを追加して新しい文字列を構築します。 文字列ごとのリスト バッファーを使用して正しく実装されている場合、これはすでに最適化されています。 唯一の危険は、次のような文字列連結を繰り返すことです。`res += c`これにより、それぞれに O (現在の結果の長さ) が追加され、最悪の場合、文字列ごとに 2 次時間が発生します。 全長が 5 × 10^4 の場合、それでも合格しますが、ギリギリのレベルであり、より厳しい制限の下で Python でパフォーマンスの問題を引き起こす危険を冒す必要はありません。 

重要な点は、この操作は純粋に文字に対するフィルターであり、位置間に依存関係がないということです。 各文字は独立して保持または破棄されます。 これは、ストリームを 1 回処理し、結果をリストに蓄積し、文字列ごとに 1 回結合できることを意味します。 

したがって、最適な解決策は、小さな禁止セットに対する定数時間のメンバーシップ チェックを伴う単純な線形スキャンです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (文字列連結) | 文字列ごとの O(n²) ワーストケース | O(n) | 危険/境界線 |
 | 最適 (リスト フィルタリング) | O(n) 合計 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パスワードの数を読み取り、各文字列を個別に処理します。 テスト ケース間に相互作用がないため、各文字列を分離して処理できます。 
2. 禁止セットを定義する`{ '1', 'i', 'I', 'l' }`。 メンバーシップのチェックに平均 O(1) 時間がかかるため、セットを使用します。 
3. 文字列ごとに、残すべき文字を収集するための空のリストを作成します。 繰り返しの再割り当てコストを防ぐために、文字列を直接構築することは避けます。 
4. 文字列の各文字を繰り返し処理します。 各文字について、禁止されたセットに属しているかどうかを確認します。 そうでない場合は、リストに追加します。 
5. 文字列全体を処理した後、リストを 1 つの文字列に結合して出力します。 リストが空の場合、結合により自然に空の文字列が生成されるため、やはり改行が出力されます。 

### なぜ効果があるのか

 文字列内の各位置は 1 回だけ処理され、その位置での決定は、その文字が禁止されたセットに含まれるかどうかによってのみ決まります。 隣接する文字や将来のコンテキストに依存する変換はありません。 これにより、アルゴリズムはシーケンスに射影関数を適用するのと同等になり、出力シーケンスは順序を保持しますが、要素は個別にフィルターされます。 すべての文字は 1 回だけ考慮され、すぐに保存または破棄されるため、最終的に構築される文字列は、元の文字列からすべての禁止記号を除いたものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    banned = {'1', 'i', 'I', 'l'}

    out_lines = []

    for _ in range(n):
        s = input().strip()
        buf = []

        for ch in s:
            if ch not in banned:
                buf.append(ch)

        out_lines.append(''.join(buf))

    sys.stdout.write('\n'.join(out_lines))

if __name__ == "__main__":
    main()
```このソリューションは入力を 1 行ずつ読み取り、各パスワードを個別に処理します。 の`banned`set は 1 回事前計算されるため、メンバーシップ チェックは一定時間行われます。 各文字は文字列を直接連結するのではなくリストに追加されるため、中間文字列の繰り返しコピーが回避されます。 

最終出力は単一のコンポーネントを使用して組み立てられます。`join`すべての処理ラインにわたって、多数のテスト ケースが存在する場合でも効率的な出力構築を保証します。 

微妙な点は、入力時に改行文字を削除することです。 パスワードにはスペースは含まれませんが、その他の記号が含まれる可能性があるため、`strip()`有効なコンテンツに影響を与えることなく、末尾の改行文字のみを安全に削除します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(すべての文字列の合計の長さ) | 各文字は定数セットに対して 1 回チェックされます。 
| スペース | O(出力の全長) | 結合する前にフィルタリングされた文字を保存します。 

合計入力サイズは最大 5 × 10^4 文字であるため、すべてのデータに対する単一の線形パスは容易に制限内に収まります。 メモリ使用量は出力サイズにも比例しますが、いずれにしても出力を構築する必要があるため、これは避けられません。

 ## 特殊なケース

 次のような完全に禁止された文字列の場合`1iIl`、アルゴリズムは各文字を反復処理し、すべてが禁止されたセット内にあることを検出し、何も追加しません。 バッファーは空のままで、結合すると空の文字列が生成されますが、空行として正しく出力されます。 

禁止文字を含まない文字列の場合`abcXYZ`、すべてのメンバーシップ チェックが失敗するため、すべての文字が追加されます。 出力バッファは入力と正確に一致し、順序を変更せずに保持します。 

次のような交互パターンの場合`1a1b1c`、各文字は個別にチェックされます。 文字が追加される間、禁止された数字はスキップされます。 結果として得られるバッファーは有効な文字に対してのみ増加し、アルゴリズムが位置やグループ化に依存しないことが確認されます。 

大規模な反復入力の場合でも、各文字は 1 回処理され、定数時間セットのメンバーシップにより、合計実行時間が入力サイズに比例して増加します。
