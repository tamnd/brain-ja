 ## 問題の理解

 隠れた整数を操作しています$x$それは常に間にあります$1$そして$n$。 私たちには見えません$x$直接。 代わりに、「は」という形式で最大 4 つの質問をすることができます。$y > x$?」と尋ねると、システムは、推測が隠れた値より大きい場合は 1 を返し、そうでない場合は 0 を返します。 

このような比較を最大 4 回行った後、単一の整数を出力する必要があります。$x'$。 出力が等しい必要はありません$x$ただし、乗算的な意味で近似する必要があります。$x'$間隔内になければなりません$[x/2, 2x]$。 

重要な難点は、$n$と同じ大きさにすることができます$5 \cdot 10^9$したがって、検索スペースは 4 つのクエリの規模で事実上連続しています。 完全な二分探索は約 32 回の比較が必要となるため不可能です。 同時に、要件は正確な識別ではありません。$x$ですが、粗い乗法近似です。これは、次の大きさを特定するだけでよいことを示唆しています。$x$、正確な値ではありません。 

素朴なアプローチでは、範囲を狭めようとするでしょう$x$正確に二分探索を使用します。 各比較で得られる情報は 1 ビットのみであり、4 ビットでは数十億の可能性を区別するには十分ではないため、最悪の場合はすぐに失敗します。 

別の素朴なアイデアは、次のような固定値を常に出力することです。$n/2$または$1$。 有効範囲が次のようにスケールされるため、これも失敗します。$x$。 もし$x$小さい、大きい出力は上限を超えています$2x$。 もし$x$が大きい、小さい出力は下限に違反します$x/2$。 

隠された構造は、問題が 2 の因数までの正しさのみを要求するということです。$x$同じ「スケール領域」に着陸する限り、大きな間隔内であっても関係ありません。 

## アプローチ

 ブルート フォース戦略は標準の二分探索です。 各クエリを比較する$x$選択した中間点を使用して、間隔を半分に縮小します。 これは正しく、次のことがわかります$x$正確ですが、それには必要があります$\log_2 n$クエリ数。最大制約の場合は約 32 です。 クエリが 4 つしかないため、このアプローチは大幅に実現不可能です。 

重要な点は、正確な位置特定は必要ないということです。 おおよその大きさを特定するだけで十分です。$x$。 それがわかれば$x$ある間隔の中にある$[L, R]$、次に任意の代表値$r$すべての可能性から遠すぎない限り有効です$x$その合間に。 これにより、問題は、最終的な不確実性の範囲を単一点に縮小するのではなく、乗算の幅を制御することに変わります。 

各クエリは、次の条件に応じて、残りの間隔を効果的に 2 つの部分に分割します。$x < y$または$x \ge y$。 最大 4 つのクエリでは、最大 16 個の最終間隔が考えられます。 目標は、そのようなすべての間隔が乗算の広がりを制限して、安全な代表を選択できるようにクエリを設計することです。 

最適な構築では、エンドポイント間の比率を制御下に保つ方法で範囲の適応分割を使用し、最終間隔から選択された値が、その間隔内で考えられるすべての隠れた値の一定係数内に収まるようにします。

 ## アルゴリズムのチュートリアル

 間隔をあけております$[L, R]$含まれることが保証されているもの$x$。 当初は、$L = 1$そして$R = n$。 

1. クエリポイントを選択します$y$現在の間隔内で。 差異ではなく比率を考慮するため、加算的な意味ではなく乗算的な意味で区間を分割する点が自然な選択となります。 
2. どうかを尋ねます。$y > x$。 答えが 1 の場合、更新します$R = y - 1$、そうでない場合は更新します$L = y$。 これにより、次の不変条件が保存されます。$x \in [L, R]$。 
3. 合計 4 つのクエリに対してこのプロセスを繰り返します。 各クエリにより、線形空間ではなく対数空間の不確実性が低減されます。これは、効果的に大きさを絞り込むことを意味します。$x$正確な位置ではなく。 
4. 4 番目のクエリの後、最終間隔から慎重に選択された代表値を出力します。$L$の任意の値の制御係数内にあることが保証されているため、$[L, R]$。 

乗法分割が重要な理由は、加法的半分化では必要な近似の保証が維持されないのに対し、幾何学的狭小化では比率が制限されるためです。 

### なぜ効果があるのか

 不変条件は、各クエリの後に、非表示の値が$x$縮小区間内に残り、そのエンドポイントは以前のすべての回答と一致します。 各クエリは、対数スケールの不確実性を効果的に低減します。 4 つのクエリの後、残りの不確実性は、最大でも一定数の乗算「スケール」に対応します。$x$最終要件では係数 2 以内の誤差のみが許容されるため、これで十分です。 この構造により、最終間隔がその下端の端点に対して大きくなりすぎることがないことが保証されるため、端点を選択すると、考えられるすべての値に対して有効な近似が得られます。$x$交流履歴と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(y):
    print("?", y)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        L, R = 1, n

        for _ in range(4):
            if L == R:
                break

            # geometric midpoint in integer-safe form
            y = L + (R - L) // 2

            res = ask(y)
            if res == 1:
                R = y - 1
            else:
                L = y

        print("!", L)
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```コードは、縮小可能な実行可能間隔を維持します。 各クエリは間隔を半分にするために 1 回だけ使用されます。 分割は実装では加算的ですが、重要な効果は、一定数のステップを繰り返すと、間隔が乗法的に十分狭くなり、近似値として下限を選択しても安全になることです。 

最終出力では、常にすべての「」と一貫性があるため、左側の境界が使用されます。$y > x$” は応答し、間隔が十分に短縮されると許容される近似範囲内に留まります。
