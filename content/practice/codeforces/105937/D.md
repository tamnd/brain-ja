 ## 解決策
 ## 問題の理解

 のサイズの長方形のボードが与えられます$N \times M$。 各セルはすでに黒または白になっています。 追加の白いセルを黒にペイントすることは許可されていますが、黒いセルを白に再ペイントすることは決して許可されません。 

最終的な構成は、2 つの独立した条件を同時に満たす必要があります。 まず、黒セルはグリッド隣接グラフの下で独立したセットを形成する必要があります。これは、2 つの黒セルが 1 つの辺を共有できないことを意味します。 第 2 に、最終パターンには少なくとも 1 つの対称軸が必要です。つまり、水平正中線または垂直正中線に関して対称です。 

タスクは、隣接制約と少なくとも 1 つの対称性の両方を維持しながら、黒セルを追加するだけで初期の黒の構成を有効な最終構成に拡張できるかどうかを判断することです。 

制約$N, M \le 100$までを暗示$10^4$細胞。 これは十分に小さいため、高度なデータ構造を必要とせずに、各セルとその対称セルについて直接推論することができます。 セルごとの一定の作業量をチェックするソリューションで十分です。 

微妙な点は、対称性はセルごとに個別にオプションではないということです。 対称軸をグローバルに選択すると、すべてのセルが 1 つのミラー位置と強制的にペアになるため、決定はグリッド全体にわたって結合されます。 もう 1 つの隠れた問題は、既存の黒セルがすでに実現可能性を 2 回制約していることです。隣接関係を侵害してはならず、また、選択した対称性と互換性がなければなりません。 

典型的な落とし穴は、ミラー位置がすでに黒である可能性や、対称性を強制することで隣接する 2 つの黒セルが強制的に表示される可能性があることを考慮せずに、さらに黒セルを追加して貪欲に違反を「修正」しようとすることです。 

## アプローチ

 ブルートフォースアプローチでは、水平対称を強制するか、垂直対称を強制するかの両方の可能性を個別に試行します。 選択ごとに、有効な最終グリッドの構築を試みます。 

対称性を修正するということは、すべてのセルが$(i, j)$特定のパートナーセルに関連付けられています。 左右対称の場合は、$(N-1-i, j)$。 垂直対称の場合は、$(i, M-1-j)$。 いずれの場合も、1 つのセルが黒であれば、そのミラーも黒でなければなりません。 

単純な構築戦略では、すべてのセルを反復処理して対称性を強制することによって進められます。つまり、黒いセルが表示されるたびに、そのミラーを黒く塗りつぶします。 その後、隣接制約に違反していないかどうかを確認します。 違反がなければ承認します。 

このアプローチは原理的には正しいですが、伝播効果を無視しているため失敗します。対称性を強制すると、新しい黒と黒の隣接関係が作成される可能性があり、これらはセルを削除しても解決できません。 黒セルは一度存在すると永久に固定されます。 

重要な観察は、問題は任意の構成の構築に関するものではなく、対称性によって引き起こされる強制同値クラスの一貫性のチェックに関するものであるということです。 各対称性の選択により、セルがサイズ 1 または 2 の軌道に分割されます。各軌道内では、両方のセルが同じ色の決定を共有する必要がありますが、黒いセルには、隣接する軌道ペアが同時に黒にならないという厳しい制約も課されます。 これにより、問題は、最初の黒のセルによって課された制約の下で軌道値の一貫した割り当てが存在するかどうかをチェックすることになります。 

両方の対称タイプを個別にテストするだけです。 それぞれについて、2 つのレイヤーの一貫性を検証します。1 つ目は、強制された対称性が既存の黒セルと競合しないこと、2 つ目は、対称性の閉鎖を強制した後に隣接制約に違反していないことです。

 ## アルゴリズムのチュートリアル

 水平対称性と垂直対称性を別々にテストします。 それぞれのケースについて、既存のすべての黒セルを尊重しながら対称性を強制した場合に、最終的なグリッドがどのようになるかをシミュレーションします。 

1. 選択した対称性の作業グリッドに初期グリッドをコピーします。 
2. すべてのセルについて$(i, j)$、黒の場合は、ミラー セルも黒に設定して対称性を強制します。 黒セルを破壊することはできず、対称性には平等性が必要であるため、これは必須です。 
3. すべての強制割り当てが完了したら、グリッドを再度スキャンし、隣接する 2 つのセルが両方とも黒かどうかを確認します。 
4. 隣接関係違反が存在しない場合、この対称構成は有効です。 
5. 他の対称方向に対しても同じ手順を繰り返します。 
6. 少なくとも 1 つの方向が有効な場合は、Yes を出力します。 それ以外の場合は番号を出力します。 

重要な点は、隣接性をチェックする前にステップ 2 をグローバルに適用する必要があるということです。 対称性の伝播中にローカルでチェックすると、1 つのペアを強制すると別の場所で別の違反が発生するカスケード効果を見逃す可能性があります。 

これが機能する理由は、対称制約の下での閉包に基づいています。 各黒セルはそのミラーも強制的に黒にするため、有効な解には最初の黒セットのすべての対称クロージャが含まれている必要があります。 この閉包が修正されると、残る唯一の条件は、この強制セットがすでに独立セット制約に違反しているかどうかです。 そうでない場合は、すべての白いセルを自由に白のままにしておくことができます。黒いセルをさらに追加することは、新たな隣接競合が発生する危険性があるだけであり、実現可能性にとっては不要だからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid(grid, n, m, horizontal):
    g = [list(row) for row in grid]

    # enforce symmetry closure
    for i in range(n):
        for j in range(m):
            if g[i][j] == 'B':
                if horizontal:
                    ni, nj = n - 1 - i, j
                else:
                    ni, nj = i, m - 1 - j
                g[ni][nj] = 'B'

    # check adjacency constraint
    for i in range(n):
        for j in range(m):
            if g[i][j] == 'B':
                if i + 1 < n and g[i + 1][j] == 'B':
                    return False
                if j + 1 < m and g[i][j + 1] == 'B':
                    return False

    return True

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    if valid(grid, n, m, True) or valid(grid, n, m, False):
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```このソリューションは、対称タイプごとにグリッドの新しいコピーを構築し、すべての黒いセルをスキャンすることでミラー制約を強制します。 すべての競合は 1 回だけ検出されるため、右と下の隣接関係チェックのみを使用するだけで十分です。 水平対称と垂直対称のケースは明確に分離され、2 つのチェック間に相互作用が発生しないことが保証されます。 

よくある間違いは、隣接関係をチェックしながらグリッドを変更しようとすることです。これにより、同じ伝播パスで後で発生する違反の欠落が発生します。 ここでは、最初に対称クロージャを完全に構築し、次に検証します。 

## 実用的な例

 対称が水平である場合を考えてみましょう。 

入力：```
4 4
WWWW
WBWW
WWWW
WWWW
```強制伝播を追跡します。 

| ステップ | アクション | グリッド変更 |
 | --- | --- | --- |
 | 1 | (1,1) の最初の黒 | (1,1) に 1 つの B |
 | 2 | (2,1) へのミラー | (2,1) に B を追加 |
 | 3 | 隣接性を確認する | 隣接する黒がない |

 この構成は水平対称の下で有効であるため、答えは「はい」です。 

次に、失敗したケースを考えてみましょう。```
2 2
BB
WW
```| ステップ | アクション | グリッド変更 |
 | --- | --- | --- |
 | 1 | (0,0),(0,1) の初期黒 | 上の行すべて B |
 | 2 | 水平対称性を強制する | 一番下の行は B B | になります。 
| 3 | 隣接性チェック | 垂直方向の隣接要素がすべて競合します。 

ここでは、すべての列が黒いセルの垂直ペアになり、隣接ルールに直ちに違反するため、答えは「いいえ」になります。 

これらの例は、初期構成がまばらに見える場合でも、対称性の伝播だけで避けられない競合が発生する可能性があることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、対称性によって既に占有されている黒セルへの伝播が強制される場合であり、対称軸を横切る隣接関係の競合が静かに発生する可能性があります。 例えば：```
2 3
BWB
WWW
```水平対称では、各黒セルが他の行にマッピングされ、黒のペアが完全に垂直に配置されます。 伝播後、各列には垂直に積み重なった 2 つの黒いセルが含まれており、これは直ちに隣接関係を侵害します。 このアルゴリズムは、隣接関係をチェックする前に常に完全な対称性の閉鎖を完了するため、これを処理し、これらの誘発された競合が検出されます。 

もう 1 つのケースは、グリッドがすでに有効であり、変更する必要がない場合です。 アルゴリズムは常に元のグリッドをチェックに含めるため、当然そのようなケースも変更せずに受け入れます。
