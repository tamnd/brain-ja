 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられます。これは、この範囲内のすべての整数が 1 回だけ出現し、線に沿って何らかの順序で配置されることを意味します。 各操作により、この行のセグメント [l, r] が得られます。 このセグメントから、その中に表示される数値の中でどの値が欠落しているかを調べ、欠落している最小の正の整数を取得し、それを x と呼びます。 

x を計算した後、x が n 以上の場合は、単に「平和」という単語を出力し、順列には何もしません。 それ以外の場合は、x を出力し、現在の値 x と x + 1 の位置を交換することによって順列を変更します。 

したがって、各クエリは、動的置換に対する範囲存在クエリと、値ドメイン内の 2 つの連続する値をわずかに再シャッフルするローカル構造更新の両方です。 

制約は大きく、n は最大 5 × 10^5、k は最大 10^5 です。 すべてのクエリの間隔をスキャンするソリューションでは、最悪の場合コストが O(nk) になるため、遅すぎます。これは許容範囲をはるかに超えています。 クエリあたり O(n log n) でも大きすぎます。 非常に高速な更新と範囲チェックを備えた、クエリごとの対数に近いものが必要です。 

難しいのは、順列が動的であることです。 すべてのクエリの後、x と x+1 を交換すると位置が変更され、その後のすべての範囲クエリに影響します。 これにより、値に対する静的な前処理が排除されます。 

微妙なエッジ ケースは、欠損数が n 以上の場合です。 順列には 1 から n までしか含まれないため、x は常に最大でも n+1 になります。 x が n+1 に等しい場合、または事実上、セグメント内にすべての 1..n が出現する場合、「peace」を出力します。 この場合、単純な実装では誤ってスワップを試行する可能性がありますが、スワップは x < n の場合にのみ発生する必要があります。 

## アプローチ

 直接的なアプローチは、セグメント [l, r] をスキャンして、出現する値をマークし、1 から順にチェックして欠落している最小の整数を見つけることによって各クエリを処理することです。 これは正しいですが、遅すぎます。 ブックキーピング配列をリセットすると、最悪の場合、各クエリのコストは O(r - l + 1 + n) となり、最大 10^5 のクエリではこれは実行不可能になります。 

主な困難は、範囲内の値の mex を繰り返し要求することです。値は、値空間内の隣接する値の交換によって変化する順列からのものです。 これは、「値 v が [l, r] に存在するか」を迅速に回答でき、2 つの値の位置を移動する更新をサポートできる構造が必要であることを示唆しています。 

重要な点は、セグメント内のすべての値を実際に調べる必要がないということです。 v が [l, r] に現れないような最小値 v を見つける必要があるだけです。 これは、値に対するプレフィックス スタイルの検索に変えることができます。候補 v を昇順にテストし、各 v について、それがセグメント内に存在するかどうかを確認します。 存在しない最初の v が答えです。 

したがって、コア操作は動的な「ポイント位置」構造になります。各値 v について、その現在位置 pos[v] を維持します。 次に、v が [l, r] に現れるかどうかをチェックすることは、pos[v] がその区間内にあるかどうかをチェックするだけです。 これにより、範囲クエリが値候補ごとの O(1) チェックのシーケンスに減ります。 

残りの課題は、欠落している最小の v を迅速に見つけることです。 値ドメイン [1..n] にわたるセグメント ツリーを維持し、各セグメントの位置が現在のクエリ範囲内にあるという意味で、そのセグメント内のすべての値が完全に「カバーされている」かどうかを格納できます。 ただし、各クエリには異なる [l, r] があるため、これを事前計算することはできません。 

代わりに、視点を逆転させます。 固定クエリ [l, r] の場合、pos[v] が [l, r] に含まれないような最小の v が必要です。 これは、pos[v] < l または pos[v] > r の場合に最初の v を見つけることと同じです。 これは、値の範囲内の値の最小位置と最大位置を格納するセグメント ツリー ノードを使用して慎重に定義すると、v に対する単調な述語になります。

値の範囲 [L, R] については、minPos と maxPos を維持できます。 minPos と maxPos の両方が [l, r] 内にある場合、その範囲内のすべての値はセグメント内にあります。 それ以外の場合、その範囲には欠損値が少なくとも 1 つ存在します。 これにより、セグメント ツリーを使用して最小の v をバイナリ検索し、位置が [l, r] から外れる最初の値が見つかるまで下降することができます。 

更新は簡単です。x と x+1 を入れ替えると、pos[] 内の位置が入れ替わるだけです。 

これにより、セグメント ツリー降下を介して mex を見つけるための O(log n) クエリと、スワップごとに O(1) の更新が行われ、全体として O((n + k) log n) のソリューションが得られます。

 ## アルゴリズムのチュートリアル

 1 から n までの値ドメインにわたってセグメント ツリーを構築します。 各ノードは値の連続範囲を表し、現在の順列における値の最小位置と値の最大位置の 2 つの情報を格納します。 

また、順列における値 v の現在のインデックスを示す配列 pos[v] も維持します。 

各クエリ [l, r] について、pos[v] が [l, r] に含まれないような最小の v が必要です。 

1. 初期順列を使用してセグメント ツリーを構築します。 各値 v について、pos[v] をそのインデックスに設定し、リーフ ノードは (pos[v], pos[v]) を格納します。 内部ノードは子から最小値と最大値を計算します。 
2. クエリ [l, r] に答えるために、ルートから開始してセグメント ツリーを下降し、常に昇順で位置が [l, r] の外側にある値を見つけようとします。 各ノードで、セグメント全体が完全に [l, r] 内にあるかどうか、つまり minPos ≥ l および maxPos ≤ r であるかどうかを確認します。 これが true の場合、このノードのすべての値はセグメント内にあるため、スキップします。 
3. ノードが完全に含まれていない場合は、位置が [l, r] の外側にある値が少なくとも 1 つ存在することを意味します。 次に、その子に進みます。可能な限り小さい値が必要なため、常に左の子が最初に優先されます。 
4. 値 v に対応するリーフ ノードに到達したら、pos[v] が [l, r] 内にあるかどうかを確認します。 外側にある場合は、v を mex として返します。 それ以外の場合、この分岐は無効です。 
5. x を取得した後、x が n に等しい場合、「peace」を出力し、それ以上何もしません。 
6. x が n より小さい場合、x を出力し、x と x+1 の位置を交換します。 pos[x] と pos[x+1] を更新し、両方の値のセグメント ツリーの葉を更新し、変更を上方に伝播します。 

これが機能する理由は構造的不変条件に基づいています。つまり、すべてのノードが常にその値の範囲の正しい最小値と最大値の位置を表します。 これにより、ノードが [l, r] に完全に含まれる場合、サブツリー内の値がセグメントから欠落する可能性がないため、サブツリー全体を安全に破棄できることが保証されます。 逆に、ノードが完全に含まれていない場合は、その範囲内の少なくとも 1 つの値が間隔条件に違反していることが保証されるため、答えはそのサブツリーのどこかにあるはずです。 ツリー トラバーサルでは、常に右より前に左を探索することで順序が維持され、最小の有効な値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, pos):
        self.n = len(pos) - 1
        self.minv = [0] * (4 * self.n)
        self.maxv = [0] * (4 * self.n)
        self.build(1, 1, self.n, pos)

    def build(self, idx, l, r, pos):
        if l == r:
            self.minv[idx] = self.maxv[idx] = pos[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, pos)
        self.build(idx * 2 + 1, mid + 1, r, pos)
        self.pull(idx)

    def pull(self, idx):
        self.minv[idx] = min(self.minv[idx * 2], self.minv[idx * 2 + 1])
        self.maxv[idx] = max(self.maxv[idx * 2], self.maxv[idx * 2 + 1])

    def update(self, idx, l, r, pos_idx, val):
        if l == r:
            self.minv[idx] = self.maxv[idx] = val
            return
        mid = (l + r) // 2
        if pos_idx <= mid:
            self.update(idx * 2, l, mid, pos_idx, val)
        else:
            self.update(idx * 2 + 1, mid + 1, r, pos_idx, val)
        self.pull(idx)

    def find_mex(self, idx, l, r, ql, qr):
        if self.minv[idx] >= l and self.maxv[idx] <= r:
            return -1
        if l == r:
            return l if not (ql <= self.minv[idx] <= qr) else -1
        mid = (l + r) // 2
        res = self.find_mex(idx * 2, l, mid, ql, qr)
        if res != -1:
            return res
        return self.find_mex(idx * 2 + 1, mid + 1, r, ql, qr)

n = int(input())
a = list(map(int, input().split()))
k = int(input())

pos = [0] * (n + 1)
for i, v in enumerate(a, 1):
    pos[v] = i

st = SegTree(pos)

for _ in range(k):
    l, r = map(int, input().split())
    x = st.find_mex(1, 1, n, l, r)

    if x == -1 or x == n:
        print("peace")
        continue

    print(x)
    px, py = pos[x], pos[x + 1]
    pos[x], pos[x + 1] = py, px

    st.update(1, 1, n, x, pos[x])
    st.update(1, 1, n, x + 1, pos[x + 1])
```セグメント ツリーは、位置ではなく値に基づいて構築されます。 各リーフは値 v に対応し、順列における現在の位置を格納します。 この反転により、値に対する範囲クエリが意味のあるものになります。 

mex 検索は、位置に関して値が完全に [l, r] 内にあるセグメント全体をプルーニングすることによって機能します。 ノードの値範囲全体がクエリ セグメント内にある場合、回答を含めることはできないため、直ちにスキップされます。 

スワップ ステップでは、スワップされた値の pos 配列とセグメント ツリー リーフの両方を注意深く更新します。 どちらかの更新が欠けていると、構造の同期が解除され、将来的には不正なクエリが生成されます。 

## 実用的な例

 小さな例を追跡して、構造がどのように進化するかを観察します。 

クエリ [2, 4] による順列 [4, 3, 1, 2, 5] を考えてみましょう。 

| ステップ | クエリ [l, r] | x が見つかりました | アクション | 順列 |
 | --- | --- | --- | --- | --- |
 | 1 | [2,4] | 4 | 4と5を入れ替える | [5、3、1、2、4] |
 | 2 | [2,5] | 5 | 平和 | [5、3、1、2、4] |
 | 3 | [1,3] | 2 | 2と3を入れ替える | [5、2、1、3、4] |
 | 4 | [1,3] | 3 | 3と4を入れ替える | [5、2、1、4、3] |
 | 5 | [1,5] | 6 | 平和 | [5、2、1、4、3] |

 各ステップは、クエリされた間隔内にすべての小さな値が存在すると、mex がドメインを出るまで上方にシフトし、「平和」を生み出すことを示しています。 

次に、より小さな焦点を当てたケース、つまり順列 [1, 2, 3, 4]、クエリ [2, 3] を考えてみましょう。 

| v チェック済み | pos[v] | [2,3]で? |
 | --- | --- | --- |
 | 1 | 1 | いいえ |
 | 2 | 2 | はい |
 | 3 | 3 | はい |
 | 4 | 4 | いいえ |

 最小の欠損値は 1 で、これにより 1 と 2 の間の交換が即座にトリガーされ、ローカル値の調整が今後のクエリにどのように伝播されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n + k) log n) | 各クエリは値のセグメント ツリーを下降し、各スワップは 2 つの葉を更新します。

 ## 特殊なケース

 クエリされたセグメントに 1 から n までのすべての値がすでに含まれている場合、重大なエッジ ケースが発生します。 この場合、すべての値 v は [l, r] 内の pos[v] を満たすため、mex は n+1 となり、「平和」が出力されます。 各ノードの最小位置と最大位置がクエリ間隔内に収まるため、セグメント ツリーはすべてのノードを正しくプルーニングし、完全なカバレッジが発生し、候補リーフが見つからなくなります。 

もう 1 つの微妙なケースは、位置を前後に移動する隣接する値を含む繰り返しスワップです。 各スワップは 2 つの値のみに触れ、両方のリーフ ノードを即座に更新するため、pos[v] が常に正しいという不変条件が保持されます。 多くの操作を行った後でも、すべての更新がローカライズされ、ツリーを通じて伝播されるため、構造の一貫性が保たれます。 

最後の特殊なケースは、x が n の場合です。 これが有効な最大値であっても、x+1 が存在しないため、x+1 とのスワップは無効になります。 このコードは、x == n を停止条件として明示的に処理し、範囲外の更新が発生しないようにします。
