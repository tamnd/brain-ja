 ## 問題の理解

 バス停でのイベントのタイムラインを処理します。 

イベントには2種類あります。 あ`P x`イベントの意味`x`一般の乗客が到着し、待ち始めます。 あ`B x`イベントはバスが到着することを意味します`x`自由席。 

バスが到着すると、一般の乗客は必ずモノカープより先に乗車します。 座席よりも待っている乗客が多い場合は、できるだけ多くの乗客だけが乗車し、残りの乗客は列に残ります。 待っている乗客が全員揃うと、全員が停留所から降ります。 

モノカープは特別で、一般の乗客が全員乗車した後、まだ空席があるバスに乗るかどうかを選択できるからです。 彼はそのようなバスをスキップして、後のバスを待ち続けることができます。 

すべてのバス イベントについて、Monocarp がその特定のバスに乗車できる一連の選択が存在するかどうかを判断する必要があります。 

イベントの数は最大でも 1000 と非常に少ないです。 たとえ$O(n^2)$ソリューションは最大で約 100 万回の操作を実行します。 つまり、高度なデータ構造や高度な最適化は必要ありません。 課題は、実際にどのような情報が重要なのかを理解することです。 

微妙な点は、Monocarp の決定が影響するのは 1 つのことだけです。それは、将来のバスが到着するときに彼がまだ待っているかどうかです。 一般の乗客は決定論的に行動します。 Monocarp の選択に関係なく、彼らのキューは同じように進化します。 

よくある間違いは、常に最初に利用可能なバスに乗るなど、Monocarp を貪欲にシミュレートすることです。 考慮する：```
P 2
B 3
B 1
```正しい答えは次のとおりです。```
YES
YES
```モノカープは2名乗車後、1席が空いているので先頭のバスに乗車できます。 バスをスキップして 2 番目のバスに乗車することもできます。 彼を最初のバスに永続的にコミットするシミュレーションでは、誤って出力されます。`NO`2台目のバスへ。 

もう 1 つの簡単な間違いは、乗りきれない乗客が待ち続けることを忘れることです。```
P 10
B 3
B 8
```正しい答えは次のとおりです。```
NO
YES
```始発のバスが出てもまだ7人の乗客が待っている。 2 番目のバスが到着すると、7 人全員が乗車し、Monocarp 用の空席が 1 つ残ります。 

3 番目のエッジケースは、待っている一般乗客がいない場合に発生します。```
B 1
```答えは次のとおりです。```
YES
```バスはすぐに空席が出たので、モノカープも乗車してみよう。 

## アプローチ

 ブルートフォースビューは、すべてのバスを独立して考慮することです。 特定のバスについては、以前のすべてのイベントを再生し、待っている乗客の数を追跡し、バスに乗車した後にそのバスに予備の座席があるかどうかを確認できます。 空席状況を決定する唯一の要素は一般乗客であるため、これは正しいです。 バスに少なくとも 1 つの空き座席がある場合、Monocarp は前のバスに乗らず、代わりにこのバスに乗るという選択をすることができます。 

と$m$バスと$n$イベントの合計、バスコストごとの履歴の再生$O(nm)$となり、$O(n^2)$最悪の場合。 と$n \le 1000$、これはすでに十分に高速です。 

重要な観察は、履歴を再計算する必要すらないということです。 一般乗客の列は Monocarp とは独立して進化します。 現在の待機乗客数を維持しながら、イベントを 1 回処理できます。 

バスが到着したとします`b`席があり、そこにあります`wait`現在停車中の乗客。 

もし`b > wait`, その後、一般乗客が全員乗車した後、少なくとも1つの座席が残ります。 Monocarp は今まで待ち続けるだけでこのバスに乗ることができます。 答えは`YES`。 

もし`b <= wait`、すべての座席は一般乗客によって消費されます。 Monocarp はこのバスに乗る機会がないので、答えは次のとおりです。`NO`。 

応答後、通常のキューを更新する必要があります。 バスは撤去します`min(wait, b)`乗客、出発`max(0, wait - b)`。 

このシングルパス シミュレーションでは、すべてのバスの結果が即座に得られます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`wait = 0`、現在待機している一般乗客の数。 
2. イベントを時系列に処理します。 
3. イベントが`P x`、設定してこれらの乗客をキューに追加します`wait += x`。 
4. イベントが発生した場合`B x`、バス容量と現在のキュー サイズを比較します。 
5. もし`x > wait`, 一般乗客が全員乗車した後、座席が残ります。 出力`YES`。 

Monocarp はいつでも、以前の機会をすべて無視して、このバスに存在し続けることを選択できます。 
6. それ以外の場合は出力`NO`。 

どの席も一般乗客で占められているため、モノカープは入る機会がありません。 
7. 設定により、バス出発後に乗客の列を更新します。`wait = max(0, wait - x)`。 

これにより、なんとか搭乗できた乗客が正確に削除されます。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`wait`は常に、現在停留所で待っている一般乗客の数と等しくなります。 

Monocarp は、一般の乗客が彼の前に乗車し、彼の決定によって一般の乗客の到着または出発の数が変更されないため、この数量に影響を与えることはありません。 

バスの場合`b`座席、一般乗客がぴったり着席`min(wait, b)`席。 Monocarp に自由席が存在するのは、まさにこのときです$$b - \min(wait, b) > 0$$これは以下と同等です`b > wait`。 

もし`b > wait`, このバスにはモノカープが乗車する可能性があります。 もし`b <= wait`、彼の順番が来る前にすべての席が消費されます。 アルゴリズムは正しい乗客数を維持しながら、すべてのバスのこの条件を正確にチェックするため、すべての答えが正解になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    wait = 0
    ans = []

    for _ in range(n):
        typ, val = input().split()
        val = int(val)

        if typ == 'P':
            wait += val
        else:
            if val > wait:
                ans.append("YES")
            else:
                ans.append("NO")

            wait = max(0, wait - val)

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`wait`現在待っている一般乗客の正確な数を保存します。 

乗客イベントの場合は、この数を単純に加算します。 

バス イベントの場合は、まず現在のキュー サイズを使用してクエリに答えます。 順序が重要です。 決定は、誰かが到着するバスに乗り込む前に何人の乗客が待っているかによって決まります。 

答えを生成した後、キューを更新します。 バスに十分な座席がある場合、待っている乗客は全員降車し、`wait`ゼロになります。 それ以外の場合は、正確に`val`乗客が乗り込み、`wait`によって減少します`val`。 

すべての算術は Python の整数に簡単に適合します。 たとえ 1 つのイベントが積み重なっても、$10^6$乗客の合計は依然として Python の制限をはるかに下回っています。

 ## 特殊なケース

 等しい場合を考えてみましょう。```
2
P 5
B 5
```バスが到着する前に、`wait = 5`。 バスにはちょうど5席あります。 5席すべてが一般乗客で占められており、座席はゼロとなっている。 アルゴリズムチェック`5 > 5`これは false であり、次のように出力されます。```
NO
```これにより、よくある使用上の間違いを回避できます。`>=`の代わりに`>`。 

部分的に処理されたキューを考えてみましょう。```
3
P 10
B 3
B 8
```最初は`wait = 10`。 最初のバスの後、アルゴリズムは次のように出力します。`NO`そしてアップデート`wait`に`7`。 2台目のバスの場合は、`8 > 7`、つまり出力されます`YES`。 最初のバスの残りの乗客は正しく保存されます。 

複数の利用可能なバスを考慮します。```
3
P 2
B 3
B 1
```始発のバスで、`3 > 2`、したがって、答えは次のとおりです`YES`。 バスが出発すると列は空になります。 2台目のバスで、`1 > 0`、したがって、答えも次のようになります`YES`。 

これは、Monocarp による単一の固定決定をシミュレートしているわけではないことを裏付けています。 各バスは、「Monocarp はこのバスを利用することを選択できますか?」という質問の下で独立して評価されます。これはまさに問題が尋ねていることです。
