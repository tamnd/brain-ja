 ## 解決策
 ## 問題の理解

 固定長 3 の非常に短い式が与えられています。 最初と最後の文字は数字で、中央の文字は比較演算子 (「未満」、「等しい」、「より大きい」) です。 私たちの仕事は、できるだけ少ない文字を変更しながら、この式を正しい数学的記述に修正することです。 

正しいステートメントとは、2 つの数字間の関係が演算子と一致する必要があることを意味します。 左の桁が右の桁より小さい場合、演算子は「<」でなければなりません。 それらが等しい場合、演算子は「=」である必要があります。 左の数字が大きい場合、演算子は「>」でなければなりません。 

各テスト ケースは独立しており、各テスト ケースに対して有効な修正済みの式が出力され、文字編集の数が最小限に抑えられます。 

各文字列のサイズは一定であるため、制約は非常に小さくなります。 各桁の選択肢が 10 個しかなく、演算子の選択肢が 3 つしかないため、数字と演算子のすべての可能性を試す強引なアプローチでも十分に高速です。 これにより、テスト ケースごとに 300 の組み合わせ、最大でも 300 のテスト ケースの固定検索スペースが得られますが、これは簡単です。 

この問題の唯一の微妙な点は、数字または演算子の変更が両方とも 1 文字につき 1 回の変更として等しくカウントされることです。 これは、有効な式へのハミング距離を最小限に抑えていることを意味します。 

単純な間違いは、数字を変更せずに演算子だけを修正すること、またはその逆になることです。 演算子の代わりに 1 桁を変更すると、合計の変更が少なくなる場合には、これは失敗します。 たとえば、回転する`5<3`の中へ`5>3`1 文字 (演算子) を変更しますが、それを次のように変換します。`0<3`また、変更は 1 回 (数字のみ) かかるため、両方を考慮してグローバルに比較する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての有効な式を試し、入力と異なる位置の数を測定します。 各テスト ケースについて、0 から 9 までのすべての数字のペアと 3 つの比較演算子をすべて列挙します。 各候補式について、それが論理的に有効であるかどうかを確認し、不一致の文字を数えることによって入力文字列からの距離を計算します。 最良の候補者が選ばれます。 

これが機能するのは、検索空間全体が小さく、入力サイズから完全に切り離されているためです。 ただし、問題の構造により直接推論が可能であるため、これさえも不要です。 

重要な観察は、有効性は 2 桁の相対的な順序にのみ依存するということです。 これにより、すべての有効な式が 3 つのグループ (左より小さい、等しい、または大きい) に分割されます。 各グループについて、元のエンドポイントへの変更を最小限に抑える数字を選択し、それらを正しい演算子と組み合わせることで、最適な代表値を計算できます。 

すべての可能性を検索するのではなく、3 つの論理的な結果を評価し、編集が最も少ないものを選択します。 数字は独立しているため、各カテゴリ内での最良の選択は、意図的に調整する必要がない限り、単純に元の数字を保持することですが、数字の調整が役立つのは、演算子を修正するよりも安価に別の比較カテゴリに一致させることができる場合のみです。 

実際には、文字列の長さは 3 であるため、ケースごとに最適な数字のペアを選択することで、3 つのケースそれぞれのコストを直接計算できます。

 ## アルゴリズムのチュートリアル

 各テストケースを独立して扱います。 

1. 左の数字、演算子、右の数字を解析します。 比較しやすいように、それらを整数として保持します。 これにより、ベースライン式とその現在の正確さがわかります。 
2. 式が「<」を満たすためのコストを計算します。 これを行うには、左の数字が右の数字より厳密に小さい数字のペアが必要です。 最も安価な方法は、可能であれば数字を変更しないことですが、有効なペアのみが許可されます。 そこで、a < b となるすべての数字のペア (a, b) を考慮し、元のエンドポイントを (a, b) に変換し、演算子を「<」に変換するために必要な変更の数を計算します。 このようなすべてのペアの最小値は、正しい「<」式を強制するコストです。 
3. a = b であるペアのみを考慮し、演算子を強制的に「=」にして、「=」の同じコストを計算します。 
4. a > b のペアを考慮し、演算子を適用して、「>」の同じコストを計算します。 

各候補コストは、そのカテゴリで有効な式に到達するために変更する必要がある位置の数を測定します。 

1. コストが最小のカテゴリを選択します。 複数同点の場合はどれでも構いません。 
2. どの候補が最小コストを生成したかを記憶することにより、実際の最良の式を再構築します。 

### なぜ効果があるのか

 このアルゴリズムは、比較関係に基づいて、すべての有効な式を 3 つの素のセットに分割します。 各セット内で、考えられるすべての数字のペアを明示的に評価するため、構成を見逃すことはありません。 すべての有効な式はこれらのセットの 1 つに正確に属するため、グローバル最小値は計算された候補の 1 つに現れる必要があります。 コスト関数は正確に文字置換の数であるため、すべての有効な式を最小化することは、これら 3 つの包括的なカテゴリを最小化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    a0 = int(s[0])
    op0 = s[1]
    b0 = int(s[2])

    best_cost = 10
    best_expr = s

    ops = ['<', '=', '>']

    for op in ops:
        for a in range(10):
            for b in range(10):
                if op == '<' and not (a < b):
                    continue
                if op == '=' and not (a == b):
                    continue
                if op == '>' and not (a > b):
                    continue

                cost = 0
                if a != a0:
                    cost += 1
                if b != b0:
                    cost += 1
                if op != op0:
                    cost += 1

                if cost < best_cost:
                    best_cost = cost
                    best_expr = str(a) + op + str(b)

    return best_expr

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、前述の網羅的だが限定された検索を直接実装します。 ネストされたループは、すべての数字のペアとすべての演算子を反復します。 各候補について、まず無効な組み合わせをフィルタリングして、論理的に正しい式のみを考慮します。 次に、入力文字列に対する編集距離を位置ごとに計算します。 最適な候補は保存され、より低コストの構成が見つかるたびに更新されます。 

検索スペースはテスト ケースごとに一定であるため、制限内で快適に実行されます。 

## 実用的な例

 候補者がどのように評価されるかを確認するために、2 つのケースを追跡します。 

最初の例は`3<7`。 

| | オプ | b | 有効 | コストと投入量 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | < | 7 | はい | 0 | 最高 |
 | 3 | > | 7 | いいえ | - | スキップ |
 | 3 | = | 3 | はい | 2 | もっと悪い |

 元の式はすでに有効であるため、最小コストはゼロで、出力は変更されません。 これは、アルゴリズムが不必要な編集を強制することなく最適性を維持していることを示しています。 

2番目の例は`5<3`。 

| | オプ | b | 有効 | コストと投入量 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 5 | < | 6 | はい | 1 | 最高 |
 | 4 | > | 3 | はい | 1 | ネクタイ |
 | 5 | > | 3 | はい | 1 | ネクタイ |

 ここでは、複数の有効な式が同じ最小コストを達成します。 アルゴリズムはそれらのいずれも正しく受け入れ、タイの処理が正確さに影響を与えないことを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        s = input().strip()
        a0, op0, b0 = int(s[0]), s[1], int(s[2])

        best = 10
        ans = s

        for op in "<=>":
            for a in range(10):
                for b in range(10):
                    if op == "<" and not (a < b):
                        continue
                    if op == "=" and not (a == b):
                        continue
                    if op == ">" and not (a > b):
                        continue

                    cost = (a != a0) + (b != b0) + (op != op0)
                    if cost < best:
                        best = cost
                        ans = f"{a}{op}{b}"

        return ans

    t = int(input())
    return "\n".join(solve() for _ in range(t))

 ## 特殊なケース

 最も重要なエッジケースは、式がすでに正しい場合です。 のような入力の場合`0=0`の場合、アルゴリズムはすべての等号候補間でそれを評価し、ゼロコストの解をすぐに見つけるため、元の文字列を変更せずに返します。 

別のエッジ ケースは、両方の数字が等しいが、演算子が等しくない場合に発生します。`4<4`。 アルゴリズムはすべての有効な等価ペアを考慮し、演算子のみを変更する方がいずれかの数字を変更するよりもコストが低いことを発見し、次のようになります。`4=4`。 

3 番目のケースは、次のように、数字と演算子の両方が完全に一致しない場合です。`7<3`。 ここでの最適解は、コストに応じて演算子を反転するか、1 桁調整する可能性があります。 列挙により両方が考慮されることが保証されるため、次のような最小限の編集による修正が常に選択されます。`3<7`または`7>3`、どちらも有効であり、同様に最適です。
