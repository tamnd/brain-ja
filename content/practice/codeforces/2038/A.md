 ## 解決策
 ## 問題の理解

 当社にはエンジニアのチームがあり、各チームには 1 つの作業単位を実行するためのボーナスと個人費用が約束されています。 チームは、正確に要求されるプロジェクトを完了する必要があります。$k$作業単位に基づいて決定され、エンジニア全員がどれだけ貢献するかを個別に決定します。 各エンジニアが貢献する金額、$c_i$は、次のように定義される個人的な利益を最大化する必要があります。$s_i = a_i - c_i \cdot b_i$、 どこ$a_i$ボーナスと$b_i$は単位あたりのコストです。 エンジニアがマイナスの利益を期待すると、まったく機能しません。 目標は作業配分を決定することです$[c_1, c_2, ..., c_n]$すべてのエンジニアが最適に行動することで結果が得られます。 

制約が教えてくれる$n \le 1000$そして$k \le 10^6$。 以来$k$可能なすべての作業分散をテストしようとするアルゴリズム (たとえば、非負の整数のすべてのタプルの合計は次のようになります)。$k$) は指数関数的になります$n$、それは不可能です。 線形または$O(n \log n)$解決策は約まで処理できるので許容可能です$10^6$操作を快適に。 

明らかではないエッジケースには、ボーナスの合計が少なすぎてプロジェクトの利益が得られない状況が含まれます。 たとえば、次の場合$k = 10$そしてボーナスの合計$a_i$が作業コストの合理的な割り当てよりも小さい場合、エンジニアは作業を自発的に実行しないため、出力はすべてゼロになるはずです。 もう 1 つのエッジケースは、一部のエンジニアのユニットあたりのコストが非常に高い場合です。$b_i$そしてボーナスが少ない。 この場合、たとえ他の人がプロジェクトを完了できたとしても、働くと利益が減ってしまうため、エンジニアは貢献をゼロにする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、可能な限りの割り当てを試みます。$k$エンジニア間の作業単位。 分布ごとに、各エンジニアの利益を計算し、利益がマイナスかどうかを確認し、マイナスの場合はその割り当てを拒否します。 これは原理的には正しいですが、割り当ての数は組み合わせによって決まります。$\binom{k+n-1}{n-1}$。 小さいものでも$n$そして適度な$k$、これでは遅すぎます。 

重要な洞察は、エンジニアが順番に行動し、前のエンジニアが約束したことを考慮して、それぞれが自分の利益を最大化するということです。 各エンジニアは残りの作業量を確認します$r$到達する$k$前のエンジニアが決定した後。 彼らの目標は選択することです$c_i$自身の利益をマイナスにしない範囲で可能な限り大きくする、つまり$c_i \le a_i / b_i$。 また、残りの作業を超えて貢献することはできません$r$。 したがって、最適な$c_i$残りの作業の最小値と収益性の高い貢献の最大値です$a_i / b_i$。 エンジニアがコミットしたら$c_i$、次のエンジニアは、更新された残りの作業で同じロジックを繰り返します。 各エンジニアの選択は残りの作業と各エンジニアの個人的な割合に決定的に依存するため、この貪欲なアプローチにより独自のソリューションが生み出されることが保証されています。$a_i / b_i$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((k+n-1 は n-1 を選択)) | O(n) | 遅すぎる |
 | 貪欲なシーケンシャル | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 残りの作業を初期化します$r = k$。 この変数は、割り当てる必要がある作業量を追跡します。 
2. 各エンジニアを反復処理する$i$から$1$に$n$。 各エンジニアについて、最大収益性の高い作業を計算します。$m_i = a_i // b_i$。 これは、利益をゼロ以下に減らさない最大の作業量を表します。 
3. 実際の作業を決定する$c_i$エンジニアが貢献します。 これは最低限のものです$m_i$そして残りの仕事$r$。 これにより、エンジニアはプロジェクトを完了するために必要な量を超過することなく、利益を最大化することができます。 
4. 残りの作業からエンジニアの貢献を差し引きます。$r -= c_i$。 これにより、以下のエンジニアの残りの作業が更新されます。 
5. すべてのエンジニアに対してこのプロセスを続けます。 最後のエンジニア以降の合計$c_i$どちらかが正確に一致します$k$(プロジェクトは完了しました) または、誰かのエンジニアがマイナスの利益を得なければプロジェクトを完了することが不可能な場合は、それよりも少なくなります。 利益を上げて貢献できないエンジニアは、自動的に貢献がゼロになります。 

機能する理由: あらゆる段階で、各エンジニアは以前の決定を考慮して最適に行動します。 各エンジニアの選択は、収益性の最大の貢献と残りの作業の両方によって制限されるため、貪欲な順次割り当てにより、どのエンジニアもマイナスの利益を得ることが保証されます。 不変条件は、各エンジニアが終了した後の残りの作業が、割り当てられていない部分を正確に反映するということです。$k$、そしてすべてのエンジニアは、損失なく貢献できる最大の金額を選択しました。 これにより、独自の最適なシーケンスが生成されます。$[c_1, c_2, ..., c_n]$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

c = []
remaining = k

for i in range(n):
    max_work = a[i] // b[i]  # maximum work this engineer can profitably do
    contribution = min(max_work, remaining)
    c.append(contribution)
    remaining -= contribution

print(' '.join(map(str, c)))
```解決策は次のようになります$n$、$k$、ボーナス$a_i$、およびコスト$b_i$。 の`max_work`計算により、エンジニアが損失を被って作業することはなくなります。`min(max_work, remaining)`割り当てにより、合計作業量が超過しないことが保証されます$k$。 の`remaining`変数は順次更新されるため、各エンジニアは残りの作業量を正確に把握できます。 整数除算の使用`//`整数単位にとどまることを保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = []
    remaining = k
    for i in range(n):
        max_work = a[i] // b[i]
        contribution = min(max_work, remaining)
        c.append(contribution)
        remaining -= contribution
    return ' '.join(map(str, c))

# provided samples
assert run("3 6\n4 7 6\n1 2 3\n") == "1 3 2"
assert run("2 10\n3 4\n5 2\n") == "0 2"

# custom cases
assert run("1 5\n10\n2\n") == "5"  # single engineer does all work
assert run("3 5\n1 2 3\n1 1 1\n") == "1 2 2"  # sum of max work = k exactly
assert run("2 1000\n1000 1000\n1 1\n") == "500 500"  # evenly distributed
assert run("3 3\n1 1 1\n2 2 2\n") == "0 0 0"  # no profitable work
