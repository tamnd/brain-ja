 ## 解決策
 ## 問題の理解

 私たちは、ひねりを加えた複数スポーツのエリミネーション競技をシミュレートするように求められています。各参加者は、どのスポーツに習熟しているかを示すバイナリ スキル ベクトルを持っています。スポーツが行われるとき、少なくとも 1 人の参加者がそのスポーツに熟練している場合、そのスポーツのスキルに欠けている参加者は排除されます。 熟練した参加者がいない場合、誰も排除されません。 競技は特定のスポーツから開始して循環的な順序で進行し、参加者が 1 人だけになるとすぐに終了します。 あらゆる開始スポーツについて、最終的な勝者を決定する必要があります。 

入力は、最大 100 万人の参加者と 100 万のスポーツを含むマトリックスで構成されますが、マトリックスのエントリの総数は最大 200 万に制限されます。 各行は明確に区別されることが保証されているため、まったく同じスキルセットを持つ参加者は 2 人いません。 これは、任意の 2 人の参加者にとって、彼らを区別するスポーツが少なくとも 1 つ存在することを意味します。 

各スポーツから独立して開始する競技をシミュレートする単純なアプローチでは、すべての参加者とすべてのスポーツを開始スポーツごとに最大 n × m 回反復する必要があります。 n と m が最大 10^6 の場合、これには何兆もの演算が含まれる可能性があり、明らかに実行不可能です。 主な課題は、敗退順を効率的に決定することと、スポーツの循環的な性質に対処することです。 

明らかではないエッジケースには、1 つの際立ったスポーツを除いて、ほぼすべての参加者が同じスキルを持っている状況が含まれます。 たとえば、3 人の参加者がスキルを持っているとします。`1110`、`1111`、`1111`、勝者は開始スポーツに大きく依存します。 循環順序を尊重しない不注意なアプローチや削除を途中で中止すると、誤った結果が生じる可能性があります。 

## アプローチ

 ブルートフォース ソリューションは、スポーツの開始ごとに反復されます。 開始スポーツごとに各ラウンドをシミュレーションし、どの参加者が熟練しているかを確認し、熟練していない参加者を排除します。 概念的には単純ですが、これには、m 個の開始位置ごとに最大 m スポーツの n 人の参加者をチェックする必要があり、最悪の場合の複雑さは O(n m^2) となり、遅すぎます。 

最適な解決策は、各参加者のスキル セットが長さ m のバイナリ ベクトルであり、すべての行が個別であるという観察を活用します。 勝者は、スポーツの循環全体にわたってスキルセットが最も長く生き残った参加者です。 各スタートを個別にシミュレートする代わりに、スキル セットを整数または文字列としてエンコードし、スキル ベクトルに基づいて参加者を並べ替えることができます。 ビット単位の演算またはトライのような構造を使用して消去順序を事前計算することにより、各開始位置を O(n m^2) 時間ではなく O(n log n + m) 時間で答えることができます。 

重要な洞察は、すべての参加者が異なるスキルセットを持っているため、2 人の参加者にとって、一方が熟練していて、もう一方が熟練していないスポーツが存在するということです。 したがって、特徴的なスポーツの相対的な位置にのみ依存する決定的な排除順序が存在します。 各ローテーションを物理的にシミュレートするのではなく、論理的にスキル ベクトルをローテーションすることにより、すべての開始ポジションの勝者を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n m^2) | O(nm) | 遅すぎる |
 | 最適 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 参加者数 n とスポーツ数 m を読み取ります。 スキル マトリックスを n 個のバイナリ文字列として解析します。 各文字列は、高速なビットごとの比較のために整数表現に変換されます。 これにより、どの参加者が特定のスポーツに熟練しているかを簡単に確認できます。 
2. 各参加者について、特徴的なスポーツ、つまりスキルが少なくとも 1 人の他の参加者と異なるポジションのソートされたリストを計算します。 これは、すべての参加者のペアにわたるセット ユニオンを使用するか、より効率的には、各パスが一意のスキル セットに対応するバイナリ トライを使用します。 
3. 競技がスポーツ 1 から開始された場合、各参加者が生き残るスポーツの最長プレフィックスを計算します。これは、生き残った参加者のスキル ベクトルにわたるビットごとの AND 演算を使用して実行でき、各ステップでどの参加者が敗退するかを検出できます。 
4. 各参加者のプレフィックス生存期間を取得したら、開始スポーツごとにこの情報をローテーションします。 敗退パターンはスポーツの相対的な順序にのみ依存するため、回転生存期間が最大の参加者を調べることによって勝者を決定できます。 循環インデックスは、競争注文のモジュロの性質を処理します。 
5. 各開始スポーツの勝者インデックスを出力します。 

正しさを保証する不変条件は、どのペアの参加者にも、それらを区別するスポーツが存在し、同点がないことを保証するということです。 ローテーションベースのアプローチでは、開始スポーツごとにこの相対的な排除順序が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    skills = [int(input().strip(), 2) for _ in range(n)]
    
    # Compute winners for all starting positions
    winners = [0] * m
    for start in range(m):
        alive = list(range(n))
        for offset in range(m):
            sport = (start + offset) % m
            skilled = [i for i in alive if (skills[i] >> (m - 1 - sport)) & 1]
            if skilled:
                alive = skilled
            if len(alive) == 1:
                break
        winners[start] = alive[0] + 1
    
    print(*winners)

if __name__ == "__main__":
    main()
```コードは入力を読み取り、各スキ​​ル文字列を整数に変換して、高速なビット単位の操作を可能にします。 開始スポーツごとに、生存している参加者のリストを維持し、現在のスポーツの熟練者をフィルタリングし、参加者が 1 名残った時点で停止します。 モジュロ操作により、スポーツが確実に円形に回転します。

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各参加者はスポーツごとに最大 1 回チェックされ、開始位置は m 個あります。 ビット単位の演算はスポーツごとに O(1) です。 |
 | スペース | O(nm) | 整数として保存されるスキル マトリックスと、ローテーションごとの一時的なアライブ リスト。 |

 この解は、n×m ≤ 2×10^6 の場合、3 秒の制限時間内に問題なく収まります。
