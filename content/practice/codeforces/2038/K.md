 ## 解決策
 ## 問題の理解

 通過するように求められています$n \times n$グリッドを左上隅から右下隅まで移動し、右または下にステップするだけです。 あらゆる細胞$(i, j)$最大公約数による行インデックスと列インデックスのみに依存するコストに寄与します。$\gcd(i, a) + \gcd(j, b)$。 パスの総コストは、両方のエンドポイントを含む、訪問したすべてのセルの合計です。 

移動構造は単調なパス問題です。 有効なルートは、どこに右に行き、どこに下るかを選択することによって完全に決定され、そのようなすべてのパスは正確に訪問します。$2n-1$細胞。 問題は、コストが行と列全体で均一ではなく、算術構造が次の約数に関連付けられていることです。$a$そして$b$。 

制約により許可されるのは、$n$まで$10^6$これにより、グリッド上のセルごとの動的プログラミングが即座に除外されます。 率直な$O(n^2)$グリッドの横断は時間的にもメモリ的にも不可能です。 平$O(n \log n)$セルごとの推論は、すべてのセルに適用すると大きすぎます。 

微妙な点は、コストが行コンポーネントと列コンポーネントに明確に分離されていることです。 パスの貢献度は$$\sum \gcd(i, a) \;+\; \sum \gcd(j, b)$$しかし、インデックス$i$そして$j$各行と列が何回訪問されるかはパスによって選択されるため、独立していません。 主な困難は、各行と列が単調パス全体に何回寄与しているかを理解することです。 

単純なアプローチでは、DAG 内の最短パスを計算しようとします。$n^2$ノードがありますが、それはすぐには不可能です。 もう 1 つの間違ったショートカットは、行と列の寄与を個別に最小化できると仮定することですが、パス構造が行と列のトラバース方法を結合しているため、これは失敗します。 

## アプローチ

 ブルート フォース ビューは、各セルが 2 つの出力エッジを持つ有向非巡回グラフとしてグリッドを扱います。 すべてのセルに対して DP を実行すると、次のように計算されます。$$dp[i][j] = c(i, j) + \min(dp[i+1][j], dp[i][j+1])$$これは原理的には正しいですが、次のことが必要です。$O(n^2)$状態、それは不可能です$n = 10^6$。 グリッドを保存するだけでもメモリを大量に消費します。 

重要な構造的観察は、コスト関数が行依存部分と列依存部分に加法的に分割されることです。 これにより、問題を 2 つの独立した 1D 問題に分離できますが、それは各行と列が何回アクセスされるかを理解した後でのみです。 

どんな単調な道でも$(1,1)$に$(n,n)$、各行$i$は 1 回だけ入力され、パス コストに 1 回だけ寄与します。これは、行に入った瞬間であるためです。$i$、最終的にはそこから離れなければならず、二度と戻ることはできません。 各列についても同様です。 したがって、すべてのパスには、各行インデックスが 1 回だけ発生し、各列インデックスが 1 回だけ発生します。 

これにより、問題はコンピューティングに限定されます。$$\sum_{i=1}^{n} \gcd(i, a) \;+\; \sum_{j=1}^{n} \gcd(j, b)$$ただし、これではまだ十分ではありません。$(1,1)$行部分と列部分の両方を同時に提供するため、誤って二重にカウントしないようにする必要があります。 注意して分解すると、総コストは正確に次のようになります。$$\left(\sum_{i=1}^{n} \gcd(i, a)\right) + \left(\sum_{j=1}^{n} \gcd(j, b)\right)$$これは選択されたパスとは独立しています。つまり、有効なパスはすべて同じコストになります。 次に、問題は 2 つの約数和のような関数を効率的に計算することに帰着します。 

計算するには$\sum_{i=1}^{n} \gcd(i, a)$では、インデックスを gcd 値によってグループ化します。 各約数について$d$の$a$にある整数の数を数えます。$[1, n]$正確に gcd を持っています$d$と$a$。 標準的な整数理論を使用すると、これは次のようになります。$$\sum_{d \mid a} d \cdot \varphi\left(\frac{a}{d}\right) \cdot \left\lfloor \frac{n}{d} \right\rfloor$$より直接的で簡単な方法は、約数を反復処理し、オイラーの合計寄与を介して包含/除外を使用するか、または除数ごとの gcd 寄与を事前計算することです。$a$そして$b$。 以来$a, b \le 10^6$、約数を列挙できます$O(\sqrt{a})$で貢献を集約し、$O(\sqrt{a} + \sqrt{b})$。

 ## アルゴリズムのチュートリアル

 1. コストが独立した行と列の寄与に分割されることを観察します。 これは有効です。$\gcd(i,a)$のみに依存する$i$、 そして$\gcd(j,b)$のみに依存する$j$したがって、パスを選択しても、それらを非加算的な方法で結合することはできません。 
2. コンピューティング$S_a = \sum_{i=1}^{n} \gcd(i, a)$。 すべてを繰り返すのではなく$i$、約数を列挙する$d$の$a$。 各約数は、次の倍数の潜在的な gcd 値構造を表します。$d$。 約数の寄与は、次の倍数がどのくらいの頻度で発生するかによって決まります。$d$に登場する$[1,n]$。 
3. 各約数について$d$の$a$、内の数値がいくつあるかを計算します。$[1,n]$で割り切れます$d$、つまり$\lfloor n/d \rfloor$。 これらは、約数に対する包含と排除を通じて寄与します。$a$、正確な gcd 層を分離します。 
4. 同じ計算を繰り返します。$S_b = \sum_{j=1}^{n} \gcd(j, b)$。 
5. 戻る$S_a + S_b$。 

### なぜ効果があるのか

 正確さは、右方向と下方向の移動がどのように配置されているかに関係なく、グリッド パス構造が行インデックスごとに 1 つの訪問を強制し、列インデックスごとに 1 つの訪問を強制するという事実に基づいています。 これにより、インターリーブの選択への依存が排除されます。 これが確立されると、コストは独立したインデックス セットに対する純粋な加算算術関数になり、グリッドをシミュレートせずに評価できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sum_gcd(n, x):
    # compute sum_{i=1..n} gcd(i, x)
    res = 0
    d = 1
    while d * d <= x:
        if x % d == 0:
            d1 = d
            d2 = x // d

            # for divisor d1
            cnt = n // d1
            if cnt:
                res += d1 * cnt

            # for divisor d2
            if d2 != d1:
                cnt = n // d2
                if cnt:
                    res += d2 * cnt
        d += 1
    return res

def main():
    n, a, b = map(int, input().split())
    print(sum_gcd(n, a) + sum_gcd(n, b))

if __name__ == "__main__":
    main()
```実装は、約数の列挙に依存しています。$a$そして$b$。 各約数について$d$、インデックスの数によってスケールされたその寄与度を最大まで累積します。$n$で割り切れます$d$。 重要な実装の詳細は、グリッド上でのセルごとの反復を回避することですが、これは実行不可能です。 

ループ構造により、各除数が 1 回処理されることが保証され、平方根境界により、最大入力サイズでも計算の効率が維持されます。

 ## 特殊なケース

 次のような最小限のグリッド$n = 2$実装が両方のエンドポイントを正しくカウントしているかどうかを明らかにします。 その場合、すべてのパスが強制されるため、不一致があると、開始または終了のコントリビューションの処理が正しくないことを直ちに示します。 

いつ$a = 1$または$b = 1$、すべての gcd 項は 1 に崩壊し、結果は純粋に構造的になります。 すべての約数の列挙には自明な約数 1 のみが含まれており、合計は正確に計算されるため、アルゴリズムは正しく削減されます。$n$次元ごとに。 

大きな素数値$a$または$b$除数ループが 2 回だけ実行されるようにします。 これは、アルゴリズムが密な除数構造に依存しておらず、最悪の算術シナリオでも安定していることが確認されています。
