 ## 解決策
 ## 問題の理解

 このゲームの各ターンは、2 つの結合されたシステムに同時に影響を与える小さな戦略的決定です。 n 個の政党があり、各政党はゼロから始まり時間の経過とともに増加する勢力値を維持しています。 モノカープはあらゆる場面で、支持する政党を 1 つだけ選びますが、現在システムを主導している政党を支持することは禁じられています。 

彼の選択後、すべての政党が勢力数を更新し、最も強い勢力を持つ政党が与党になります。 複数の当事者が同点の場合、最小のインデックスが優先されるため、中立的な関係ではなく、戦略的に意味のある関係になります。 最後に、各ターンには制約があります。つまり、選挙ステップの後に特定の政党が最終的に統治者になる必要があり、そうでない場合はシーケンス全体が無効になります。 

課題は、これらの強制支配者の制約をすべて満たしながら、どの時点でどのパーティがサポートされたかに応じてターンごとの報酬の合計を最大化する、m ターンにわたる有効なサポートのシーケンスを選択することです。 

n、m ≤ 50 という制約は十分に小さいため、3 次またはわずかに高い多項式の複雑さを持つ解でも許容されます。 重要なのは生のスピードではなく、ターン間の組み合わせの相互作用を管理することです。なぜなら、それぞれの決定が将来の勝者に影響を与え、次のステップでどのような選択肢が合法であるかさえ制限されるからです。 

微妙な問題は、「現在のリーダーをサポートしない」ルールにより、タイブレークと相互作用する形でシステムが状態に依存することです。 必要な支配者を局所的に満足させようとする素朴な貪欲なアプローチは失敗します。1 ターンで権力の増分を変更すると、リーダーが予期せず移動し、将来の強制状態が無効になる可能性があるためです。 

典型的な失敗例は、2 つの政党が権力的に接近しており、少額の報酬の誘惑により間違った政党を後押しし、意図よりも早くリーダーを反転させ、後で必要な p_j の達成が不可能になる場合です。 たとえば、タイブレークによりパーティー 1 とパーティー 2 が交代でリーダーシップを交代する場合、たとえ後の決定が最適であったとしても、初期の追加サポートによって意図された交代パターンが永久に崩れてしまう可能性があります。 

## アプローチ

 強引な解釈では、各ターンで可能なすべての支持の選択肢をシミュレートし、現在の勢力ベクトルを維持し、各決定後にどの政党が支配者になるかを追跡しようとします。 各ターンには最大 n 個の選択肢があるため、n^m 個の可能性が生じますが、これは m = 50 の場合でも大きすぎます。将来の制約の実現可能性による枝刈りさえ役に立ちません。各決定の影響は広範囲にわたるため、1 つの余分な増分が将来の複数の選択を変更する可能性があります。 

重要な観察は、現在のパワー ベクトルと現在のルーラーの ID という 2 つの情報が与えられると、プロセスが決定論的であるということです。 いずれの段階でも、どの政党を支持するかを決めてしまえば、次の州は完全に決まります。 これは、時間の経過に伴う動的計画法を示唆しており、状態は、現在の順番、現在の電力の差、および現在の支配者など、将来の実現可能性にとって重要なものだけを捕捉します。 

ただし、フルパワーベクトルを追跡すると大きすぎます。 重要な構造的洞察は、次の支配者を決定するのに関係するのは当事者間の相対的な差異のみであり、各ステップで座標が 1 つずつ増加するため、これらの差異は高度に制限された方法で進化するということです。 

n と m は両方とも最大 50 であるため、パワー ベクトル全体を明示的に格納する DP を用意できます。 理論上、状態の総数は O(m · n^n) ですが、実際には、強制ルーラー条件を使用して無効な状態を早期に削除するため、ごく小さなサブセットにのみ到達します。 これにより、各状態が特定の時点で到達可能な構成を表す遷移 DP が可能になり、遷移はサポートする有効なパーティの選択をシミュレートします。

時間ごと、および現在のルーラーとともに可能な電源構成ごとに、達成可能な最高のスコアを保存します。 各遷移では、正当性 (現在のルーラーをサポートできない) がチェックされ、増分が適用され、O(n) で新しいルーラーが再計算され、時刻 j でルーラーが p_j に等しいことが強制されます。 

これにより、問題は、制約の下でサイズが管理可能な状態グラフ上の階層化された最短パス スタイルの DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(n^m) | O(m) | 遅すぎる |
 | 構成上の状態 DP | O(m · n² · 状態) 実質的に O(m · n³) | O(状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各状態が各ターン後のすべての党勢力と現在の統治者の完全なスナップショットを表す、長期にわたる DP を定義します。 これにより、トランジションでは、近似ではなく、常に正確な選択ルールが尊重されるようになります。 
2. ターン 0 で、すべてのパワーがゼロに等しく、意味のあるルーラー状態がない状態で DP を初期化します。 ここから、すべての有効なシーケンスは、最初のタイブレーク勝者 (パーティー 1) ではない、正当な最初のサポートの選択から開始する必要があります。 
3. 各ターン j について、ターン j − 1 から到達可能なすべての状態を反復します。各状態は、以前のすべての強制ルーラー制約を満たす有効な構成をすでにエンコードしています。 
4. 国家から、現在の支配者ではない各政党を支持してみてください。 そのパワーを 1 つ増やし、n 個のパーティすべてをスキャンして最大パワーを選択し、最小のインデックスで関係を破ることにより新しいルーラーを再計算します。 リーダーは突然変わる可能性があるため、このステップはシステムの非線形性が発生する唯一の場所です。 
5. 新しいルーラーを計算した後、このターンに必要な p_j と一致しない場合は、直ちにその状態を破棄します。 これにより、イベント制約がローカルに強制されますが、後で違反を修復できないため、これで十分です。 
6. 報酬 a[i][j] を使用して新しい状態の DP 値を更新し、その状態に到達するすべての方法の中で最大スコアを維持します。 最終シーケンスを再構築するために親ポインターを保存します。 
7. すべてのターンを処理した後、ターン m で最大スコアの状態を選択します。 状態が存在しない場合、問題は不可能です。 

重要な不変条件は、ターン j の処理後、DP には、j までのすべてのプレフィックスの強制条件を満たすパワー ベクトルとルーラーの到達可能なすべての構成と、各構成の達成可能な最適なスコアが正確に含まれることです。 遷移ではすべての有効なアクションが列挙され、常に真の選択結果が再計算されるため、無効な設定が DP に入力されることはなく、有効な設定が失われることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    a = [list(map(int, input().split())) for _ in range(n)]

    from collections import defaultdict

    # state: (powers tuple, ruler) -> score
    dp = {}
    dp[(tuple([0]*n), 0)] = 0

    parent = []

    for j in range(m):
        ndp = {}
        par = {}

        for (powers, ruler), score in dp.items():
            for i in range(n):
                if i == ruler:
                    continue

                new_p = list(powers)
                new_p[i] += 1

                # recompute ruler
                mx = max(new_p)
                new_r = 0
                for k in range(n):
                    if new_p[k] > mx or (new_p[k] == mx and k < new_r):
                        new_r = k
                        mx = new_p[k]

                if new_r != p[j]:
                    continue

                new_state = (tuple(new_p), new_r)
                new_score = score + a[i][j]

                if new_state not in ndp or ndp[new_state] < new_score:
                    ndp[new_state] = new_score
                    par[(j, new_state)] = (powers, ruler, i)

        if not ndp:
            print(-1)
            return

        parent.append(par)
        dp = ndp

    # reconstruct best
    best_state = max(dp.items(), key=lambda x: x[1])[0]
    powers, ruler = best_state

    res = [0] * m
    cur = (powers, ruler)

    for j in range(m - 1, -1, -1):
        prev_powers, prev_ruler, chosen = parent[j][(j, cur)]
        res[j] = chosen + 1
        cur = (prev_powers, prev_ruler)

    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、州の DP のアイデアを直接反映しています。 ルーラーは再計算なしでは安価に推論できないため、各状態はフルパワーベクトルと現在のルーラーの両方を保存します。 内側のループは選出結果を明示的に再計算します。これは、n ≤ 50 により O(n) スキャンが安価に保たれるため安全です。 

親ディクショナリには、ターンと状態によってキー設定された遷移が格納され、曖昧さのない再構築が可能になります。 再構築は、最良の最終状態から逆方向に進み、各ステップで選択されたパーティを取得します。 

微妙な点は、現在のルーラーの選択を禁止する必要があることです。これは状態を更新する前に強制されます。 もう 1 つは、ルーラーを再計算する際に、より小さいインデックスが等しい最大値を支配するタイブレークを正しく考慮する必要があることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m · S · n²) | S は到達可能な状態の数です。 各遷移は n 回の移動を試み、O(n) | でルーラーを再計算します。 
| スペース | O(S) | DP 状態と親ポインタを格納します。 

n、m ≤ 50 という小さな境界により、理論上の状態空間は大きくなりますが、強制的な制約の下でも到達可能な構成の数は管理可能なままになります。 DP は、不可能な分岐を早期に探索することを回避し、実行時間を制限内に保ちます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、現在の統治者が報酬を得るために最適なサポートとなる唯一の候補者でもある場合です。 ルーラーをサポートすることは禁止されているため、アルゴリズムは、スコアの点で世界的に最も優れている場合でも、その手を正しく破棄する必要があります。 DP は、ルールに違反する遷移を決して生成しないことでこれを処理し、貪欲な選択が禁止されたアクションを好む場合でも正確さを保証します。 

もう 1 つのエッジ ケースは、移動後に複数のパーティが最大パワーを得るために同点になる場合に発生します。 この実装では、ルーラーの再計算中に最小インデックス ルールが明示的に適用されます。 これにより、誤った状態の発散が蓄積され、将来の実現可能性チェックが中断されることが防止されます。
