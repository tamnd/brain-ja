 ## 解決策
 ## 問題の理解

 固定された順序で配置された一連の問題スコアが与えられます。 各位置には正の値があり、問題を解決するとその数のポイントが得られます。 すべての問題の合計がしきい値を定義します。参加者は、ディプロマを取得するには、この合計の少なくとも半分を集める必要があります。 

Alexey は任意のサブセットを自由に選択しません。 彼は開始インデックスを選択し、次に厳密に右に進みます。 先に進む間、選択したセグメント全体で最大 1 つの問題をスキップすることもできます。 そのセグメント内の他のすべての訪問済み問題が解決され、そのスコアが収集されます。 目標は、合計スコアの少なくとも半分に到達しながら、実際に解決する問題の数を最小限に抑えることです。 

重要な制約は、$n \le 10^5$これにより、すべての開始位置とセグメントの選択の二次探索が除外されます。 すべての開始位置とすべてのスキップ位置を直接シミュレートしようとするソリューションは、次のように動作します。$O(n^2)$、これは 1 秒の制限には遅すぎます。 

微妙な点は、最適なセグメントが必ずしも最長であるか、または合計密度が最大であるとは限らないということです。 スキップは 1 回だけ許可されるため、解決される問題の数を減らすために価値の高い要素を犠牲にすることができるため、最適な答えは、削除された 1 つの要素がセグメントをどの程度圧縮できるかによって決まります。 

エッジ ケースは、最適解がほとんど値の小さい領域内で非常に大きな値をスキップする必要がある場合、またはスキップがまったく役に立たない場合に発生します。 たとえば、すべての値が同一の場合、カウントがわずかに短くなる以外はスキップしても最適性は変わりません。問題は、半和に達する最短のプレフィックスを見つけることになります。 

もう 1 つのエッジ ケースは、単一の非常に大きな要素が配列を支配する場合です。 その場合、その位置から開始し、何もスキップしないことが最適です。これは、セグメントが長くても、解決される問題の数が増えるだけであり、効率は向上しません。 

## アプローチ

 直接的なアプローチでは、すべての開始インデックスを試行します。$k$、次に、ポイントを蓄積しながら右への拡張をシミュレートし、オプションでセグメント内のすべての可能な位置で 1 つの要素をスキップします。 開始ごとに、合計の半分に達するために必要な解決された要素の最小数を追跡します。 これには、開始ごとに、潜在的に最後までスキャンしてスキップ位置をテストする必要があり、大まかに$O(n^2)$行動。 と$10^5$要素、これは不可能です。 

主な観察は、セグメント内の最大 1 つの要素をスキップすることは、「で始まるすべてのセグメントの中で」と言うのと同等であるということです。$k$、セグメントの合計から 1 つの要素を削除することができ、調整された合計がしきい値に達する最も早いポイントが必要です。 これは、セグメントの長さを最小限に抑えながら、1 つの要素をスキップする利点を最大化したいことを示唆しています。 

開始点を修正して拡張する代わりに、視点を反転します。考えられる正しいエンドポイントごとに、最大 1 つの削除でしきい値に達する、そこで終了する最良のセグメントを知りたいと考えます。 これは当然、2 ポインターまたはスライディング ウィンドウ構造につながります。これは、右側の境界を移動すると、合計と妥当性条件の両方が単調に進化するためです。 

窓口を整備しております$[l, r]$そしてその合計を追跡します。 また、ウィンドウ内の最大の要素も追跡します。1 つの要素をスキップできる場合、最適な選択は常に現在のウィンドウ内の最大の要素をスキップすることになるためです。 これにより、問題は次のことを確認するだけになります。$$\text{sum}(l, r) - \max(l, r) \ge \text{half}$$または、スキップが必要ない場合は、$$\text{sum}(l, r) \ge \text{half}.$$スライドします$r$左から右に、ウィンドウ内の最大のデータ構造を維持して縮小します。$l$条件を満たしながら可能な限り。 最良の答えは、有効なウィンドウ内の要素の最小数です。

 ## アルゴリズムのチュートリアル

 まずすべての値の合計を計算し、その半分としてターゲットを定義します。つまり、少なくとも必要な値は$\lceil \frac{\text{sum}}{2} \rceil$。 

次に、ウィンドウの現在の合計と、ウィンドウ内の最大要素をクエリできる構造という 2 つの情報を維持しながら、配列に対してスライディング ウィンドウを使用します。 

1. 2 つのポインターを初期化します$l = 0$、$r = 0$、現在のウィンドウ合計をゼロに設定します。 また、最大値の候補を維持するために両端キューを初期化します。 この両端キューにはインデックスが値の降順で格納されるため、先頭は常に最大値になります。 
2. 右ポインタを展開します$r$、追加$a[r]$ウィンドウ合計を計算し、以下の要素をすべて削除して両端キューを更新します。$a[r]$後ろから押して$r$。 これにより、常に一定時間内に最大値にアクセスできるようになります。 
3. 展開するたびに、現在のウィンドウが有効かどうかを確認します。 このウィンドウは、合計がすでにターゲットに達しているか、合計から最大要素を差し引いた値がターゲットに達している場合に有効です。 2 番目の条件は、可能な限り最良の要素に対して単一の許可されたスキップを使用することに対応します。 
4. ウィンドウが有効な場合は、左側から縮小しようとします。 引っ越し前に$l$、合計からそれを削除し、一致する場合はデックのフロントからもポップします。 可能な限り小さなウィンドウが必要なため、有効性が保たれている間は縮小を続けます。 
5. 各調整の後、現在のウィンドウ サイズで答えを更新します。 
6. まで繰り返します$r$配列の最後に到達します。 

このアルゴリズムが機能するのは、すべてのステップで、各右境界に対して可能な最小の左境界が維持され、最大 1 回の削除でしきい値に到達できるためです。 

### なぜ効果があるのか

 固定ウィンドウの場合、スキップするのに最適な要素は常にその中の最大要素です。これより小さい要素を削除しても、スキップするメリットが減るだけであるためです。 したがって、どこをスキップするかの決定は、ウィンドウ外の将来の要素には依存しません。 

スライディング ウィンドウにより、各右エンドポイントについて、実現可能性を満たす最小限の左エンドポイントが常に維持されるようになります。 同じ右エンドポイントに対してより小さなウィンドウが可能であれば、妥当性が保たれている間に縮小が貪欲に行われるため、それが見つかるはずです。 これにより、開始点を明示的に列挙することなく、すべての候補最適セグメントが暗黙的に探索されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    target = (total + 1) // 2
    
    dq = deque()
    l = 0
    curr_sum = 0
    ans = n
    
    for r in range(n):
        curr_sum += a[r]
        
        while dq and a[dq[-1]] <= a[r]:
            dq.pop()
        dq.append(r)
        
        while dq and dq[0] < l:
            dq.popleft()
        
        def valid():
            if curr_sum >= target:
                return True
            if dq:
                return curr_sum - a[dq[0]] >= target
            return False
        
        while l <= r and valid():
            ans = min(ans, r - l + 1)
            if dq and dq[0] == l:
                dq.popleft()
            curr_sum -= a[l]
            l += 1
            while dq and dq[0] < l:
                dq.popleft()
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、現在のウィンドウ内の値に対する単調減少構造を表すインデックスのデキューが保持されます。 これにより、最大要素を一定時間で取得できるようになります。これは、オプションのスキップが効果的に適用できるかどうかを評価するために不可欠です。 

明確にするために、有効性チェックは関数として明示的に記述されていますが、実際には、deque 構造により定数時間になります。 縮小フェーズにより、各正しい境界の最小ウィンドウが常に維持されるようになります。 

左ポインタを削除するときは注意が必要です。出力要素が現在最大の候補である場合は、両端キューからポップする必要があります。 最も一般的なエラーの原因は、両端キューとウィンドウ境界の同期に失敗することです。

この例は、しきい値を満たしながら、不必要な低値のプレフィックスを回避するためにウィンドウがどのようにシフトするかを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、最適なソリューションが単一の非常に大きな要素である場合です。 たとえば、`[100, 1, 1, 1]`の場合、しきい値は最初の位置ですぐに満たされ、スキップ ロジックを必要とせずに全合計条件がトリガーされるため、アルゴリズムはサイズ 1 のウィンドウを正しく識別します。 

もう 1 つのケースは、スキップが不可欠な場合です。 で`[1, 100, 1, 1]`、最適なウィンドウには大きな中央の要素が含まれていますが、それをスキップされた要素として使用し、残りの小さな要素が最小長のソリューションを形成できるようにします。 デキューにより、この最大値が常にスキップ候補として考慮されるようになります。 

3 番目のケースは、すべての要素が等しい場合です。 のために`[2, 2, 2, 2]`スキップしてもしきい値への到達可能性は有意に改善されませんが、縮小しても合計の半分を超える最短のセグメントが検索され、長いウィンドウよりもコンパクトなウィンドウが正しく優先されます。
