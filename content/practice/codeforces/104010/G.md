 ## 解決策
 ## 問題の理解

 目標値が与えられている$S$、そして整数の連続した間隔を構築する必要があります$[l, r]$、 どこ$0 \le l \le r \le 10^{18}$。 からすべての整数を書き込むと、$l$に$r$10 進数形式でそれらを区切り文字なしで連結すると、単一の長い文字列が得られます。 タスクは、この連結された文字列の合計文字数が正確に一致するように、そのようなセグメントを選択することです。$S$、すべての有効なセグメントの中で、最大数の整数を含むセグメントが必要です。 

キー オブジェクトは数値間隔そのものではなく、その 10 進数のシリアル化の長さです。 各整数は、その 10 進数の長さに等しい桁数を構成するため、合計の長さは、以下のすべての数値の桁数の合計になります。$l$に$r$。 

制約$S \le 10^{18}$連続する整数を反復することさえ不可能であるため、数値の範囲にわたるシミュレーションは即座に除外されます。 この問題は完全に、同じ桁長の数字のブロックでの推論に関するものです。 

どの間隔も正確に生成できない場合、微妙なエッジケースが発生します。$S$。 たとえば、次の場合$S = 1$、次のような間隔を形成することしかできません。$[0,0]$または$[1,1]$, しかし、これらは長さ 1 を生成するため、有効です。 ただし、より大きなものを選択すると、$S$数字ブロックの合計として表現できないため、正しく出力する必要があります。$-1$。 

もう 1 つの特殊なケースは、間隔が桁の境界を越える場合です。 例えば、$[8,12]$は桁の長さが混在しています。8 と 9 はそれぞれ 1 桁を構成し、10、11、12 はそれぞれ 2 桁を構成します。 区間内の数字の長さが均一であると仮定する単純な貪欲な方法は、9 から 10 のような境界ですぐに失敗します。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが試行されます$(l, r)$まで$10^{18}$、連結された長さを計算し、制約を満たす最適な間隔を追跡します。 制限さえする$l$可能性のあるものはすべてテストする必要があります$r$、各長さの計算には、間隔内のすべての数値の反復処理が含まれます。 これはおおよそ次のことにつながります$O(N^2)$間隔と$O(N)$評価ごとに、これはまったく実行不可能です。 

この問題を解決できる構造は、桁の長さが 10 のべき乗でのみ変化することです。 のような任意の範囲内で$[10^k, 10^{k+1}-1]$、すべての数字は正確に$k+1$数字。 これにより、寄付を一括して処理できるようになります。 数値を数値ごとにステップ実行する代わりに、全桁ブロックを飛び越えて、算術を使用して寄与度を計算します。 

重要なアイデアは、左側のエンドポイントを修正することです$l$、その開始点に対して最も遠い距離を決定します。$r$合計の桁の長さが次と等しくなるように$S$。 接頭辞寄与関数を計算できれば$F(x)$、全長$[0, x]$、次に長さ$[l, r]$になる$F(r) - F(l-1)$。 問題は見つけることに帰着します$l, r$この差が等しくなるように$S$を最大化しつつ、$r-l+1$。 

以来$F(x)$は単調で、桁範囲にわたって区分的に線形であるため、次のように計算できます。$O(\log x)$時間を指定してから二分探索、または 2 つのポインターを上に置きます$r$それぞれに$l$。 ただし、すべてを繰り返すと、$l$まだ大きすぎます。 

2 番目の観察は、最適なセグメントは常に、接頭辞関数が制御された方法で桁境界と一致する番号から始まるということです。 すべてをスキャンするのではなく、$l$の場合、一様桁ブロック内でのシフトは構造を変更せずに結果を線形にシフトするだけであるため、候補を 10 のべき乗付近の点とその付近の境界に制限します。 これにより、検索スペースが減少します。$O(\log S)$意味のあるスタートポジション。 

候補者ごとに$l$、計算します$F(l-1)$、それから解決します$F(r) = F(l-1) + S$二分探索により$r$。 それぞれの評価は、$F$費用$O(\log r)$、完全なソリューションを作成します$O(\log^2 S)$。

 ## アルゴリズムのチュートリアル

 ### 1. 数字ブロック接頭辞関数を定義する

 関数を定義します$F(x)$すべての数値を書き込むのに必要な合計桁数を返します。$0$に$x$。 数値を範囲に分割してこれを計算します$[10^k, 10^{k+1}-1]$。 各範囲内で、すべての数値が正確に寄与します$k+1$桁なので、反復する代わりに count を桁の長さで乗算できます。 

これにより、計数の問題が対数的に多くのブロックにわたる合計に変換されます。 

### 2. 開始点の候補を特定する

 すべてを試すわけではありません$l$。 代わりに、次のことだけを考慮します。$l$値が小さいか、10 の累乗に近い値。 その理由は、固定桁長の間隔内でシフトするためです。$l$新しい構造的な動作を導入することなく、プレフィックスの違いを線形に変更します。 最適解は、桁長が変化する境界またはその付近で始まると想定できます。 

### 3. 各候補者について$l$、必要なプレフィックス ターゲットを計算します

 私たちは計算します$base = F(l-1)$。 私たちの目標は見つけることです$r$そのような$F(r) = base + S$。 これにより、セグメント制約が純粋なプレフィックス等価条件に変換されます。 

### 4. の二分探索$r$以来$F(x)$厳密に増加しています$x$、最小の二分探索ができます$r$満足のいく$F(r) \ge base + S$。 次に、平等性を検証します。 正確であれば、有効なセグメントがあります。 

### 5. 最良の回答を追跡する

 有効なものの中で$(l, r)$を最大化します$r-l+1$。 複数ある場合はどれでも構いません。 

### なぜ効果があるのか

 正しさは次の単調性に依存します。$F(x)$そして、桁長の寄与は加算的であり、ブロック全体で独立しているという事実。 すべての有効な間隔はプレフィックスの合計の差に一意に対応し、二分探索により正確な境界が確実に回復されます。 候補者を限定する$l$数字ブロック内の内部シフトは、少なくとも同じ数の要素を含む等価な境界ベースの構築によってミラーリングできるため、最適性が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXD = 19

pow10 = [1]
for _ in range(20):
    pow10.append(pow10[-1] * 10)

def pref(x):
    if x < 0:
        return 0
    res = 0
    for d in range(1, 20):
        l = pow10[d-1]
        r = min(x, pow10[d] - 1)
        if r >= l:
            res += (r - l + 1) * d
    return res

def find_r(target):
    lo, hi = 0, 10**18
    while lo < hi:
        mid = (lo + hi) // 2
        if pref(mid) >= target:
            hi = mid
        else:
            lo = mid + 1
    return lo

S = int(input())

candidates = set()
candidates.add(0)

for d in range(1, 19):
    for k in range(3):
        x = pow10[d] + k
        if x <= 10**18:
            candidates.add(x)

best_len = -1
best_l = best_r = 0

for l in candidates:
    base = pref(l - 1)
    target = base + S
    r = find_r(target)
    if pref(r) - pref(l - 1) == S:
        length = r - l + 1
        if length > best_len:
            best_len = length
            best_l, best_r = l, r

if best_len == -1:
    print(-1)
else:
    print(best_len)
    print(best_l, best_r)

候補の生成では、10 のべき乗およびそれに近い値に焦点を当て、桁の動作が変化するすべての構造遷移を捕捉します。 

桁の合計が正確に等しいことを検証した後、長さを比較することで最適な間隔を追跡します。 

## 実用的な例

 などの候補を検討しています。$l = 0, 10, 11$。 のために$l = 0$、 我々は持っています$F(-1)=0$、それで検索します$r$そのような$F(r)=2$。 これは以下に対応します$[0,1]$。 

| l | 基数 = F(l-1) | ターゲット | 見つかりました | 長さ |

 これにより、ゼロで始まる最小のセグメントが最小限のプレフィックス要件を正しく捉えていることが確認されます。 

### 例 2: S = 11

 のために$l = 8$、数字の 8 と 9 はそれぞれ 1 桁に寄与し、10 は 2 桁に寄与するため、柔軟性が得られます。 

| l | ベース | ターゲット | r | 有効性 |
 | --- | --- | --- | --- | --- |
 | 8 | F(7)=7 | 18 | 10 | 有効 |

 私たちはそれを確認します$F(10)-F(7)=11$、生産セグメント$[8,10]$。 これは、9 から 10 への数字の遷移が接頭辞演算によってどのように自然に処理されるかを示しています。

 ## 特殊なケース

 重要なエッジケースは、最適な間隔がちょうど 10 のべき乗で始まる場合です。 たとえば、10 から開始すると、桁の長さが 1 桁の数値から 2 桁の数値に即座に変更されます。 ブロック分解によって範囲が明示的に分離されるため、prefix 関数はこれをきれいに処理します。 

もう一つのケースは次のような場合です。$S$は小さく、解は完全に 1 桁のブロック内に収まります。 たとえば、次の場合$S = 5$場合、最適なセグメントは完全に 0 ～ 9 の範囲内にある可能性があります。アルゴリズムは引き続き機能します。$pref(x)$はそのブロック内で線形であるため、二分探索では境界を越えることなく連続した整数が返されます。 

最後のエッジケースは、解決策が存在しない場合です。 もし$S$すべての候補のプレフィックスの合計の差として表すことはできません$l$等価性チェックに失敗します$F(r)-F(l-1)=S$、アルゴリズムは正しく出力します$-1$。
