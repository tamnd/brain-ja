 ## 解決策
 ## 問題の理解

 私たちは無限数直線上のゼロの位置に立っていて、ある目標座標に到達したいと考えています。$x$、正、負、またはゼロにすることができます。 1 回の操作で、負でない整数を選択します$k$、そして右または左に正確にジャンプします$2^k$。 したがって、利用可能な移動の長さは 2 の累乗であり、それぞれの移動を独立して方向を選択できます。 

タスクは、正確に着地するために必要なそのようなジャンプの最小数を計算することです。$x$。 各テスト ケースは独立しており、最大 100,000 個のクエリを実行できます。$x$と同じ大きさにすることができます$10^{18}$規模的には。 

の制約$t$各クエリにほぼ一定時間または対数時間で答える必要があります。 パスをシミュレートしたり、状態を検索しようとしたりするソリューションは、たとえ中程度の分岐要素であっても指数関数的に爆発的に増加するため、直ちに実行不可能になります。 の大きさ$x$バイナリ表現構造を示唆しています。$10^{18}$約60ビット以内に収まります。 

次の場合、微妙なエッジケースが発生します。$x = 0$。 その場合、手は必要ありませんが、バイナリ表現に基づく単純な推論では、常に 2 のべき乗に分解しようとする場合、少なくとも 1 つの手を誤って割り当てる可能性があります。 

もう 1 つの特殊なケースはマイナスです$x$。 私たちはそれぞれの動きの方向を自由に選択できるため、対称性は次のことだけを示唆しています。$|x|$重要ですが、これは想定されるものではなく、操作の構造によって正当化される必要があります。 

## アプローチ

 ブルートフォース解釈では、各状態を直線上の座標として扱い、各動きを 2 つの新しい状態 (加算または減算) に分岐するものとして扱います。$2^k$誰にとっても$k \ge 0$。 ゼロからの最短経路探索$x$すべての移動には 1 ステップのコストがかかるため、概念的には正しいです。 ただし、状態空間は無限で高度に接続されており、座標も制限されます。$[-10^{18}, 10^{18}]$あまりにも多くの州を残します。 各状態には、任意の理由により、無限に多くの送信遷移があります。$k$, したがって、遷移を列挙することさえ不可能です。 分岐係数に制限がなく、最適解の深さが約 60 に達する可能性があるため、このアプローチはすぐに失敗します。 

重要な観察は、すべての移動が、座標のバイナリ表現における 1 つのビット位置の切り替えに対応しているということです。$2^k$ほんの少しだけ影響する$k$。 ただし、標準の 2 進加算とは異なり、移動ごとに独立して符号を選択​​することができます。これは、通常の方法で伝播を行うことに制限されないことを意味します。 代わりに、問題は次のことを表現することと同等になります。$x$2 の符号付き累乗の合計として、項の数を最小限に抑えます。 

これはまさに、整数の非隣接形式 (NAF) 表現の古典的な概念です。数値を基数 2 に書き換えますが、数字は許容されます。$-1, 0, 1$、ゼロ以外の桁の数を最小限に抑えます。 ゼロ以外の各桁は 1 つのジャンプに対応し、ジャンプを最小限に抑えることは、この符号付きバイナリ展開でゼロ以外の桁を最小限に抑えることと同じです。 

NAF の貪欲な構築は少しずつ機能し、$\pm 1$現在のビットで、またはパリティによって強制される場合は次のビットに繰り上げます。 これにより、単純なバイナリ分解で非効率性が生じる原因となる、バイナリ表現における 1 の長い連鎖が排除されます。

 ## アルゴリズムのチュートリアル

 符号は無関係であるため、各数値を個別に処理し、絶対値に換算します。 

1. もし$x = 0$、すぐに 0 を返します。 すでに原点に到達しているため、ジャンプする必要はありません。 
2. 交換する$x$による$|x|$。 これが機能するのは、すべての動きで方向を選択できるため、どの一連の動きでも到達できるからです。$x$ミラーリングして到達できる$-x$同じ長さで。 
3. 操作用のカウンタをゼロに初期化します。 これは、最終的に使用するゼロ以外の符号付きビットの数を表します。 
4. ながら$x > 0$かどうかを調べます。$x$奇数か偶数です。 もし$x$が偶数の場合、2 で割って次のビットに進みます。 これは、現在の位置の符号付きバイナリ表現のゼロ桁に対応します。 
5. もし$x$が奇数の場合、このビットで 1 を加算するか減算するかを決定します。 バイナリ NAF 構築では、$x \bmod 4 = 1$、数字を使用します$+1$、そうでない場合は$x \bmod 4 = 3$、数字を使用します$-1$。 選択後、操作カウンタをインクリメントして更新します$x = (x - d)/2$、 どこ$d \in \{+1, -1\}$。 
6. すべてのビットが処理されるまで繰り返します。 

ステップ 5 の重要な考え方は、次のことを選択することです。$\pm 1$表現内で連続した非ゼロ ビットが生成されることを確実に回避します。そうしないと、必要なジャンプの数が増加します。 

### なぜ効果があるのか

 各ステップで、次の表現を構築しています。$x$基数 2 に数字が入ったもの$\{-1, 0, 1\}$。 1 の各減算または加算は、サイズのジャンプへのコミットに対応します。$2^k$。 貪欲な選択により、ビットが不利な方法 (標準バイナリで 2 つの隣接するゼロ以外の数字を作成する) で設定されるたびに、それを符号付き数字に反転してキャリー フォワードを推進することによって即座に解決されます。 これにより、隣接する 2 つのゼロ以外の数字が残らないことが保証されます。これは、最小長の符号付きバイナリ表現の特徴です。 ゼロ以外の各桁は 1 つの移動に正確に対応するため、それらを最小化するとジャンプの数が直接最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(x):
    if x == 0:
        return 0
    x = abs(x)
    ops = 0

    while x > 0:
        if x & 1 == 0:
            x >>= 1
        else:
            if x == 1:
                ops += 1
                break
            if x & 3 == 1:
                x -= 1
            else:
                x += 1
            ops += 1
            x >>= 1

    return ops

t = int(input())
for _ in range(t):
    x = int(input())
    print(solve_one(x))
```この実装は、署名付きバイナリ構造を直接反映しています。 ループは数値を最下位側からビットごとに処理します。 現在のビットがゼロの場合は、単純にシフトします。 1 の場合、コード化された次のビット コンテキストに基づいて 1 を減算するか加算するかを決定します。$x \bmod 4$これにより、将来的にゼロ以外の数字が隣接することがなくなります。 

特別な場合$x = 1$最後の操作を 1 つカウントする以上はキャリー調整が必要ないため、明示的に処理されます。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        x = int(input())
        if x == 0:
            print(0)
            continue
        x = abs(x)
        ops = 0
        while x > 0:
            if x & 1 == 0:
                x >>= 1
            else:
                if x == 1:
                    ops += 1
                    break
                if x & 3 == 1:
                    x -= 1
                else:
                    x += 1
                ops += 1
                x >>= 1
        print(ops)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 のために$x = 0$を使用すると、アルゴリズムはループに入る前にすぐに 0 を返し、バイナリ処理ループからのファントム操作が誤ってカウントされるのを防ぎます。 

のために$x = 1$、上位ビットが残っていないため、ループは 1 回の操作で終了し、それ以上シフトすることはありません。 これにより、存在しない上位ビットにアクセスしようとする余分な不必要な調整ステップが回避されます。 

次のような 2 の大きな累乗の場合、$x = 2^{60}$の場合、アルゴリズムは最後のビットまでシフトのみを実行し、操作を 1 つだけ生成します。これは、そのサイズの 1 つのジャンプで十分であるという直感と一致します。
