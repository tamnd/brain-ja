 いつでも固定$k$、長さの接頭辞によって単語をグループ化します。$k$同値関係を定義します。 各ペアはクラス内に留まらなければならないため、すべての同値クラスが偶数のカーディナリティーを持っている場合に限り、ペアリングが可能です。 ソートにより、これらの等価クラスが連続したセグメントになることが保証されるため、ハッシュ化や追加のデータ構造を使用せずに、スキャンでこれらのクラスが正しく識別されます。 実行可能性は次のように低下​​するだけであるため、二分探索は有効です。$k$が増えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, words):
    n = len(words)
    i = 0
    while i < n:
        j = i + 1
        pref = words[i][:k]
        while j < n and words[j][:k] == pref:
            j += 1
        if (j - i) % 2 == 1:
            return False
        i = j
    return True

def solve():
    n = int(input().strip())
    words = [input().strip() for _ in range(n)]
    words.sort()

    lo, hi = 0, len(words[0])

    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid, words):
            lo = mid
        else:
            hi = mid - 1

    print(lo)

if __name__ == "__main__":
    solve()
```ソートのステップは、プレフィックスのグループ化を線形スキャン問題に変換するため、非常に重要です。 の`can`関数は、固定の実現可能性チェックを実装します。$k$同一のプレフィックスの連続したブロックをたどることによって。 二分探索は次のように上向きにバイアスされます。`(lo + hi + 1) // 2`上限を狭めるときに無限ループを避けるため。 

主な微妙な点は、プレフィックス比較の一貫性を確保することです。`words[j][:k]`すべての文字列の長さが同じであり、同じ固定値までしか比較しないため、安全です。$k$。

 重要なエッジ ケースは、リファイン後にプレフィックス グループが奇数になる場合です。 たとえば:

 入力:```

```で$k = 1$を並べ替えると、最初の文字ごとにグループ化され、有効な 4 つのブロックが 1 つ生成されます。 で$k = 2$、最初の 2 文字でグループ化すると、サイズ 2 の 2 つのグループに分割されますが、これは引き続き有効です。 で$k = 3$、それぞれがシングルトン グループになり、ペアリングができなくなります。 アルゴリズムは次の時点で障害を正しく検出します。$k=3$なぜなら、スキャン中、各ブロックの長さは 1 であり、これは奇数であり、候補を即座に拒否するためです。
