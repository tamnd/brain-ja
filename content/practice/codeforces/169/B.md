 ## 解決策
 ## 問題の理解

 文字列として 10 進数が与えられ、置換に使用できる追加の数字を含む別の文字列が与えられます。 2 番目の文字列の各数字は最大 1 回使用できます。 選択した各桁について、元の数値の任意の 1 つの位置を置き換えることができます。 

目標は、最終的な数値を最大化することです。 

重要な点は、置換文字列内の桁の順序は重要ではないということです。 置換する数字を自由に選択して、番号の任意の位置に配置できます。 より重要な位置の大きな桁ほど最終値に大きく寄与するため、これはすぐに左端の位置を中心とした貪欲な戦略を示唆します。 

入力サイズが到達しました$10^5$両方の文字列の数字。 文字列を繰り返し再構築したり、置換の組み合わせを多数試行したりするソリューションは失敗します。 二次アルゴリズムは次のように実行します。$10^{10}$限界をはるかに超えた最悪の場合の動作。 直線的または直線に近いアプローチが必要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次の入力を考えてみましょう。```
999
123
```答えは残るはずです:```
999
```不用意に実装すると、すべての置換数字の使用が強制され、誤って数値が減少する可能性があります。 

別の微妙なケースは次のとおりです。```
1000
999
```最良の答えは次のとおりです。```
9991
```数字`9`より前の桁の方が重要性が高いため、最初の位置から最初に使用する必要があります。 最初に最後の数字を置き換えると、さらに悪い結果が得られます。 

重複も重要です:```
1234
3321
```正しい答えは次のとおりです。```
3334
```置換桁を降順にソートした後、毎回、最大の有用な桁を貪欲に消費する必要があります。 あまりにも早い段階で小さい数字を使用すると、機会が無駄になります。 

最後の注意が必要なシナリオは、置換桁が現在の桁と等しい場合です。```
555
555
```答えは変わりません。```
555
```等しい数字に置き換えても何も変わらないため、無害ですが不要です。 貪欲なアルゴリズムは、当然そのような操作をスキップする必要があります。 

## アプローチ

 ブルートフォースソリューションでは、置換数字を位置に割り当てるためにあらゆる方法が試行されます。 置換セット内のすべての桁について、それを使用することも無視することもでき、使用する場合は元の数値の任意の位置に配置することができます。 可能性の数は爆発的に増加します。 長さが 20 であっても、探索空間は膨大になります。 

位置の価値に焦点を当てることで思考を簡素化できます。 左端の数字がその右側のすべての数字よりも優先されます。 最初の桁を 1 増やすことは、後の桁を 9 増やすよりも常に優れています。 

この観察によって問題は完全に変わります。 組み合わせを探索する代わりに、利用可能な最大の置換桁を使用して、可能な限り最も早い位置を改善するように常に努めるべきです。 

すべての置換数字を降順に並べ替えるとします。 次に、元の番号を左から右にスキャンします。 各位置で、現在の最大の未使用の置換桁が現在の桁より大きい場合は、それを置き換えます。 それ以外の場合は、ポジションをスキップします。 

なぜこれが最適なのでしょうか? なぜなら、数字によって何らかの順位を改善できる場合、後で使用するよりも早めに使用する方が常に良いからです。 また、残っている最大の桁で現在の順位を改善できない場合、残りの小さい桁でも現在の順位を改善することはできません。 

これにより、ソート後の問題は単純な貪欲パスに変わります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適な貪欲さ | O(n + m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の数値を文字のリストとして読み取り、その場で数字を変更できるようにします。 
2. 置換された数字を読み取り、降順に並べ替えます。 
3. ポインタを維持する`j`現在の最大の未使用の置換桁に変換されます。 
4. 元の番号を左から右にスキャンします。 
5. 各ポジションについて:

 1. すべての置換数字がすでに使用されている場合は、停止します。 
2. 現在の桁を未使用の最大の置換桁と比較します。 
3. 置換する数字の方が大きい場合は、現在の数字を置き換えて移動します。`j`フォワード。 
4. それ以外の場合は、現在の桁を変更しないでください。 
6. 変更した番号を出力します。 

重要な考え方は、早い段階のポジションが後のポジションを支配するということです。 順位を改善できるときは、その改善を遅らせることは役に立ちません。 残りの最大桁をすぐに使用することが常に最適です。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、処理されたプレフィックスがすでに可能な限り大きいという不変条件を維持します。 

位置を調べているとします`i`。 未使用の置換桁の最大値が現在の桁より大きい場合、最適な解決策では、この位置に何らかの改良桁を配置する必要があります。 前の位置にある大きな数字は常に、そこにある小さな数字の配置よりも優れているため、最大のものを使用することが最適です。 

未使用の置換桁の最大値が現在の桁より大きくない場合、残りの桁でこの位置を改善することはできません。 スキップは強制です。 

すべての決定は局所的に最適であり、将来のポジションを損なうことはできないため、貪欲な戦略はグローバルに最大の数を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = list(input().strip())
s = sorted(input().strip(), reverse=True)

j = 0

for i in range(len(a)):
    if j == len(s):
        break

    if s[j] > a[i]:
        a[i] = s[j]
        j += 1

print("".join(a))
```Python 文字列は不変であるため、元の数値はリストに変換されます。 リスト内の文字を直接更新すると効率的であり、文字列を繰り返し再構築する必要がなくなります。 

置換桁は降順でソートされるため、利用可能な最大桁に常に簡単にアクセスできます。 これは、貪欲な準備の中核となるステップです。 

ポインタ`j`現在使用されていない置換桁を追跡します。 各置換桁は 1 回しか使用できないため、ポインタは置換が実際に発生した場合にのみ進みます。 

前の位置の方が価値があるため、ループは左から右に数字を処理します。 現在の置換桁が現在の数字の桁より厳密に大きくない場合、置換しても結果は改善されません。 残りの置換桁はすべてさらに小さいため、この位置をさらに置換しようとする理由はありません。 

新しい数字が既存の数字より大きい場合にのみ置換が行われるため、アルゴリズムでは先頭のゼロは作成されません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m log m) | 置換桁のソートには O(m log m) のコストがかかり、スキャンは線形です。 
| スペース | O(m) | ソートされた置換数字配列には m 個の文字が格納されます。 

と$n, m \le 10^5$、ソートが実行時間を支配します。 その周り$10^5 \log 10^5$操作は制限時間内に簡単に収まり、メモリ使用量も 256 MB の制限に比べてわずかです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a = list(input().strip())
    s = sorted(input().strip(), reverse=True)

    j = 0

    for i in range(len(a)):
        if j == len(s):
            break

        if s[j] > a[i]:
            a[i] = s[j]
            j += 1

    print("".join(a))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue()

# provided sample
assert run("1024\n010\n") == "1124\n", "sample 1"

# minimum size
assert run("1\n9\n") == "9\n", "single digit replacement"

# no replacement helps
assert run("999\n123\n") == "999\n", "all replacements smaller"

# repeated digits
assert run("1234\n3321\n") == "3334\n", "duplicate replacement digits"

# leading digit improvement
assert run("1000\n9999\n") == "9999\n", "replace earliest positions first"

# equal digits should not waste replacements
assert run("555\n555\n") == "555\n", "equal digits skipped"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 9`|`9`| 最小入力サイズ |
 |`999 / 123`|`999`| 価値を下げる置換は無視されます。 
|`1234 / 3321`|`3334`| 重複した置換数字が正しく処理されました。 
|`1000 / 9999`|`9999`| 以前のポジションが優先される |
 |`555 / 555`|`555`| 等しい数字はスキップされます。 

## 特殊なケース

 すべての置換数字が元の数字より小さい場合を考えてみましょう。```
987
111
```ソートされた置換数字はそのままです`111`。 どの位置においても、現在の置換桁は既存の桁より大きくないため、アルゴリズムは置換を実行しません。 出力はそのまま残ります。```

```これは、貪欲ルールによって数値が決して減少しないことを確認します。 

ここで、多くの置換数字が繰り返されることを考えてみましょう。```
1111
999
```アルゴリズムは位置を左から右に処理します。 

| ポジション | 現在 | 交換 | 結果 |
 | --- | --- | --- | --- |
 | 0 | 1 | 9 | 9111 |
 | 1 | 1 | 9 | 9911 |
 | 2 | 1 | 9 | 9991 |

 最終的な答えは次のとおりです。```
9991
```トレースは、各置換桁が 1 回だけ消費され、常に最も価値のある残りの位置に適用されることを示しています。 

最後に、等しい桁を調べます。```
4444
4444
```どの位置でも、置換桁は現在の桁と等しくなります。 条件`s[j] > a[i]`毎回失敗するため、数値は変わりません。```
4444
```これにより、答えが改善されない操作での無駄な置換が回避されます。
