 ## 問題の理解

 私たちは料理のコレクションを与えられており、各料理には 2 つの独立した値があります。 最初の値は通常のコストを表し、2 番目の値は追加の「イベント追加料金」を表します。これは料理ごとではなく、選択ごとに 1 回だけ支払われ、選択されたすべての料理の最大追加料金に相当します。

だけを貪欲に考えると、微妙な問題が発生します。$a_i$。 たとえば、最小のものを選択すると、$a_i$値が常に最適であるとは限りません。$a_i$はるかに小さいものが付属する可能性があります$b_i$、最終的な最大追加料金が大幅に削減されます。

### なぜ効果があるのか

 一部の最適な選択を修正$k$。 させて$x$最大値を持つアイテムであること$b$その選択の中で。 定義上、他のすべての選択されたアイテムは、次のアイテムのセットから取得されなければなりません。$b_i \le b_x$、これはソート順のプレフィックスに正確に対応します。 そのプレフィックスの中から残りのプレフィックスを選択する最良の方法$k-1$項目は独立してそれらの合計を最小化します$a_i$、追加料金はすでに次のように固定されているため、$b_x$。 アルゴリズムは、可能なすべての選択肢を列挙します。$x$、それぞれについて最適なコンパニオン セットが考慮されるため、最適なソリューションが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    items = []
    for _ in range(n):
        a, b = map(int, input().split())
        items.append((b, a))

    items.sort()

    INF = 10**30
    dp = [INF] * (n + 1)
    dp[0] = 0

    ans = [INF] * (n + 1)

    for b, a in items:
        for k in range(n, 0, -1):
            if dp[k - 1] + a < dp[k]:
                dp[k] = dp[k - 1] + a

        for k in range(1, n + 1):
            if dp[k - 1] < INF:
                ans[k] = min(ans[k], dp[k - 1] + a + b)

    for k in range(1, n + 1):
        print(ans[k])

if __name__ == "__main__":
    main()
```このプログラムは、イベントのコストに応じて料理を分類することから始まります。これは、最大限の運営を管理可能にする構造の変革です。 DP アレイ`dp[k]`正確に選択した場合の基本価格の最小可能額を表します`k`現在のプレフィックスの項目。 

逆ループオーバー`k`これは、0 ～ 1 の選択プロパティを維持しながら、1 回の反復で同じ項目が複数回再利用されるのを防ぐために必要です。 更新ごとに、現在の料理の内容を含めることが考慮されます。`a`値をさまざまなサイズのサブセットに分割します。 

2 番目のループでは、現在のアイテムが最大値として扱われる寄与度を計算します。$b$。 私たちはそれを組み合わせます$a + b$最適なサイズのサブセットでのコスト$k-1$すでに達成可能です`dp`。 

最終的な答えの配列には、最大要素のすべての選択肢にわたる最良の値が格納されます。

 ## 特殊なケース

 重要なエッジケースとは、最小のアイテムが存在する場合です。$b_i$非常に大きい$a_i$。 このような場合、小規模なソリューションの最適なソリューション$k$完全に避けてください。ただし、より大きな場合には関連する可能性があります。$k$選択肢が限られているため。
