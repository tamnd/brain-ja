 ## 解決策
 ## 問題の理解

 ロボットは無限整数グリッドの原点から開始し、固定された一連の移動コマンドを実行します。 各コマンドは、ロボットを 4 つの基本方向のいずれかに 1 単位ずつ移動させようとします。 問題は、一部のグリッド セルが障害物によってブロックされているにもかかわらず、障害物の位置が不明であることです。 ロボットがブロックされたセルに入ろうとするたびに、ロボットは動きませんが、コマンドは消費されたとみなされ、実行は続行されます。 

私たちに与えられるのはコマンド文字列だけであり、障害物の構成やロボットの最終的な軌道さえも与えられません。 未知の障害物の配置の下ですべてのコマンドが処理された後、ロボットは最終位置で終了します。 このタスクは、グリッド上の任意の場所にある一連の障害物 (常に自由である原点を除く) を選択することによって達成できる可能性のあるすべての最終位置を決定することです。 

n ≤ 20 という制約が重要な構造上のヒントです。 このようにステップ数が少ない場合、経路と障害物との間で考えられる相互作用パターンの総数は十分に少ないため、指数関数的な推論が許容されます。 状態空間には境界がないため、無限グリッド上で考えられるすべての障害物構成を直接モデル化しようとするアプローチは、すぐに失敗します。 代わりに、パスに沿ってどの決定を「強制」または「ブロック」できるかを個別に推論する必要があります。 

微妙な点は、障害物は任意に配置でき、最初から存在する必要がないことです。 以前の選択によってまだ除外されていない障害物をターゲットセルに置くことによって失敗が説明可能である限り、各ステップでその動きが成功するか失敗するかを事実上決定することができます。 

主なエッジケースは、動きをブロックするとロボットの位置が変化し、それによって将来のすべての動きの結果が変化するという事実から来ています。 たとえば、「RU」のようなコマンド シーケンスは、最初の動きが成功するかブロックされるかによって動作が異なります。 「R」がブロックされている場合、ロボットは (0,0) に留まるため、「U」は (0,0) から (0,1) に移動します。 「R」が成功しても「U」がブロックされた場合は、(1,0) で終了します。 どちらもブロックされない場合は、(1,1) で終了します。 両方の動きがブロックされた場合、(0,0) に留まります。 これらの依存関係は、問題が基本的に分岐プロセスで到達可能な状態を列挙することにあることを意味します。 

## アプローチ

 ブルートフォース解釈では、考えられるあらゆる障害物の構成についてロボットをシミュレートしようとします。 各グリッドセルはブロックされているかブロックされていない可能性があるため、これは小さなグリッドであっても不可能です。 ただし、実際には任意の障害セットを考慮する必要はありません。 実行中に宛先として試行されるセルのみが問題となります。 このような試みは最大でも n 回あるため、n 個のポジションだけが「クリティカル」ブロッカーになることができます。 

より構造化されたブルート フォースは、すべてのコマンドを決定として扱います。つまり、移動が成功するかブロックされるかのどちらかです。 成功した場合は、位置を更新します。 それが失敗した場合、私たちはその場に留まります。 これは、状態 (i, x, y) によるタイム ステップの再帰を示唆していますが、それだけでは十分ではありません。移動をブロックするには、ターゲット セルに障害物があるものとしてマークする必要があり、セルが障害物として使用されると、同じ座標への今後のすべての訪問が一貫してブロックされるはずです。 これにより、シーケンス全体にわたるグローバルな一貫性制約が導入されます。

重要な洞察は、任意の障害物セットを明示的に追跡する必要がないということです。 代わりに、以前の決定によってどのセルが「障害物としてアクティブ化」されたかを知ることだけが必要です。 n は最大 20 であるため、ロボットは任意の実行パスに沿って最大 20 個の異なるターゲット位置を試行できます。 有効な障害物の構成は、これらの試行された位置のサブセットによって完全に決定されます。 したがって、完全に成功した歩行に沿って試行された一連の座標を事前計算し、それらの座標のどのサブセットがブロックされたものとして扱われるかを調べることができます。 

これはシミュレーションの観点につながります。まず、すべての移動が成功したと仮定して名目上のパスを計算し、すべての中間ターゲット セルを記録します。 次に、これらのセルのサブセットに対して深さ優先検索を実行し、各ステップで移動がブロックされているかどうかを判断し、現在のターゲットがブランチの早い段階でブロックされていると宣言されているかどうかをチェックすることで一貫性を確保します。 

これにより、問題は最大 2^n のサイズの状態空間を探索することになり、n ≤ 20 の場合に実現可能になります。

 | --- | --- | --- | --- |
 | 障害物を乗り越えるブルートフォース | 不可能 | 不可能 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ロボットの現在位置を維持しながら、コマンド文字列を左から右に処理します。 各ステップで、移動が実行される場合の次のターゲット セルを考慮します。 

1. 現在のステップ インデックス、現在位置、およびこれまでに選択されたブロックされた座標のセットを表す再帰関数を定義します。 この状態は、次のターゲット セルがブロックされているかどうかによってのみ不確実性が生じるため、将来のすべての動作を完全に決定します。 
2. ステップ i では、i 番目のコマンドを使用して、現在位置から目的の次の位置 (nx, ny) を計算します。 
3. この座標が現在の状態でまだ強制的にブロックされていない場合にのみ、2 つのケースに分岐します。 最初のケースでは、移動が成功したと仮定しているため、(nx, ny) からステップ i+1 に進みます。 
4. 2 番目のケースは、移動がブロックされていると想定しています。これは、(nx, ny) を障害物としてマークすることにした場合にのみ有効です。 この場合、位置は変更されず、後のステップでの一貫性のためにこの座標が現在ブロックされていることを記録しながら、ステップ i+1 に進みます。 
5. ステップ n に到達したら、考えられる結果の 1 つとして最終位置を記録します。 

重要な最適化の 1 つは、ブロックされたセルの完全なセットを複雑な構造に明示的に格納する必要がないことです。 n が小さいため、各ステップがその分岐内の最大 1 つの候補ブロック座標に対応するため、ブロックされた決定をステップ インデックスのビットマスクとしてエンコードできます。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、移動に関して物理的に意味のある 2 つの可能性のみを正確にモデル化します。つまり、ロボットがターゲット セルに正常に進入するか、セルがブロックされているために進入できないかのどちらかです。 有効な障害物構成は、ステップごとに、どのターゲットをブロックしようとするかを選択することに対応します。 障害物は、目的地と一致する場合にのみ問題となるため、グリッドに関する他の情報は結果に影響を与えません。 これにより、DFS 内の一貫した決定パターンと、障害物の配置下でのロボットの有効な実行との間に 1 対 1 の対応関係が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

dirs = {
    'L': (-1, 0),
    'R': (1, 0),
    'D': (0, -1),
    'U': (0, 1)
}

def solve():
    n = int(input().strip())
    s = input().strip()

    targets = []

    def dfs(i, x, y, blocked):
        if i == n:
            return {(x, y)}

        dx, dy = dirs[s[i]]
        nx, ny = x + dx, y + dy

        res = set()

        if (nx, ny) not in blocked:
            res |= dfs(i + 1, nx, ny, blocked)

        new_blocked = set(blocked)
        new_blocked.add((nx, ny))
        res |= dfs(i + 1, x, y, new_blocked)

        return res

    ans = dfs(0, 0, 0, set())

    ans = sorted(ans)
    print(len(ans))
    for x, y in ans:
        print(x, y)

if __name__ == "__main__":
    solve()
```コードは、前述の再帰構造に直接続きます。 関数 dfs はコマンド シーケンスの部分的な実行を表し、現在のブランチで障害物であると判断されたすべての座標をブロックで保存します。 各ステップで、次の目的の座標を計算し、その座標がフリーとして扱われるかブロックされるかに応じて分岐します。 

重要な点は、ブロッキングがブランチ内で不可逆であるということです。そのため、コピーされたセットを再帰呼び出しに渡します。 これにより一貫性が保証されます。座標がブロックされていると宣言されると、その後のすべてのステップでその座標が尊重されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、同じパス内ですでに以前に訪問した座標を移動の対象とする場合です。 たとえば、「LR」では、2 番目のコマンドは (0,0) に戻ろうとします。 そのセルが適切なタイミングで障害物として選択されると、ロボットはその場で立ち往生し、単純なキャンセルの直観が示唆するものとは異なる最終的な分布が生成される可能性があります。 DFS は、以前に訪問したかどうかに関係なく、試行された各座標を独立して処理するため、これを正しく処理します。 

もう 1 つの微妙なケースは、異なるステップで同じ座標を繰り返しターゲットにすることです。 ブロックされたセットは再帰分岐全体で持続するため、座標がブロックされているとマークされると、それ以降のすべての試行が一貫してブロックされ、「R L R L」のようなサイクルによって誤って一貫性のない部分ブロックが許可されることがなくなります。
