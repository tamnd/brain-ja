 ## 解決策
 ## 問題の理解

 私たちはアイテムのコレクションを増やし続けています。 各アイテムは島に属しており、種類と価格があります。 このシステムは 2 つの操作をサポートしています。新しいアイテムを挿入することと、特定のアイランドと特定のタイプという 2 つの禁止されたカテゴリを同時に回避する最も高価なアイテムを求めるクエリに答えることです。 

クエリにより島が得られます`x`そしてタイプ`y`、島が存在しないすべての保管アイテムの中から最高価格を見つけなければなりません。`x`そしてそのタイプがそうではない`y`。 そのような項目が存在しない場合、答えはゼロです。 主な問題点は、両方のディメンションが同時に除外されるため、どちらかの制約に一致する項目は無効になることです。 

制約は極端です。最大 100 万回の操作、最大 10^9 の値があり、すべての値は前の回答と XOR 暗号化されます。 これにより、操作ごとに一定または対数の償却作業を行う厳密なオンライン ソリューションが強制されます。 クエリごとにデータベース全体をスキャンするソリューションは、最大 10^12 のチェックが必要となるため、直ちに不可能になります。 

素朴なアプローチでは、すべての項目をリストに保存し、クエリごとにすべてをスキャンして最適な有効な候補を見つけます。 これは、各クエリに挿入される項目の数に比例した時間がかかるため、失敗します。 

グローバル最大値を維持し、それが現在のクエリに対して無効な場合にのみ破棄しようとすると、より微妙な障害モードが表示されます。 有効性はクエリに依存するため、この考えは崩れます。 あるクエリでは無効な項目が次のクエリでは有効である可能性があるため、スキャン中に候補を完全に削除することはできません。 

もう 1 つの間違った方向は、アイランドごとまたはタイプごとの最大値を独立して維持することです。 これらの構造は 1 つの除外ディメンションのみを解決しますが、クエリでは両方を同時に除外する必要があり、それらを正しく組み合わせることが中心的な課題です。 

## アプローチ

 ブルート フォース ソリューションは、すべての項目を保存し、クエリごとにそれらをスキャンして、両方の制約をチェックします。 これは、回答の定義を直接評価するため正しいですが、クエリごとに最大 O(q) の作業を実行するため、合計操作数は O(q^2) となり、100 万イベントの実行可能な制限をはるかに超えています。 

改善するには、最初の有益な観察は、すべてのクエリが 2 つの「禁止クラス」を含むセット全体の最大値を要求していることです。 これは、候補者が禁止された行または列内にある場合を除き、答えは通常、世界的に競争力のある少数の候補者の中にあることを示唆しています。 

すべての項目を値で並べ替える場合、グローバル最大値が最初の候補になります。 どちらの制約にも違反しない場合、それがすぐに答えになります。 違反している場合、その答えは、それと競合するアイテム、通常は島またはタイプが異なるアイテムの中にあるはずです。 これにより、「アイランドごとのベスト」と「タイプごとのベスト」への迅速なアクセスを維持することができるようになり、禁止されたカテゴリからすぐに逃れることができます。 

ソリューションを機能させるための重要な構造は、すべてのアイランドとすべてのタイプについて、そのグループ内で利用可能な最良の項目を迅速に返すことができる構造と、現在のクエリの 2 番目の制限で最上位の候補が無効な場合のフォールバックを維持することです。 挿入のみで削除はしないため、すべての項目をグループごとに保存し、必要に応じて最大値を遅延抽出して、候補を再チェックするコストを償却できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q²) | O(q) | 遅すぎる |
 | グループごとに最適化された遅延最大値 | O(q) 償却 | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの主要なハッシュ マップを維持しています。1 つはアイランドからそのすべての項目を含む構造へ、もう 1 つはタイプから同様の構造へです。 各構造は値による最大項目の取得をサポートしていますが、無効な候補は遅延してスキップされるため、繰り返しチェックすることができます。 

また、古典的な意味での削除は行わないと主張します。 代わりに、挿入された各アイテムは一度保存され、ヒープのクリーンアップ中に一定の回数だけ再アクセスできるという事実に依存します。 

アルゴリズムは次のように進行します。 

1. すべての入力が暗号化されているため、XOR による前の回答を使用して各操作をデコードします。 これにより、真のアイランド、タイプ、値を確実に再構築できます。 
2. 挿入の場合、グローバル コンテナ、そのアイランドのアイランド バケット、およびそのタイプのタイプ バケットの 3 つの場所にアイテムを保存します。 各バケットには項目が値ごとに並べられているため、最大値をすぐに取得できます。 
3. お問い合わせの場合`(x, y)`、最初に世界最高のアイテムを取得しようとします。 有効な場合、その島は無効であることを意味します`x`そしてそのタイプは`y`、それはすぐに答えです。 
4. If the global best is invalid, it belongs to either island`x`、 タイプ`y`、またはその両方。 このクエリでは一時的にそれを破棄し、代替手段を探します。 
5. 次に、を除くすべてのアイランドから候補最大値をクエリします。`x`。 そのような島ごとに、私たちはその島で最高のアイテムを入手しようとします。 そのアイテムがタイプに違反している場合`y`、同じ島内で次善の候補にフォールバックします。 このフォールバックは、有効な型が見つかるまでアイランドの構造内の次の要素をチェックすることによって遅延計算されます。 
6. 同じアイデアをタイプ バケットに対して対称的に繰り返し、以下を除くすべてのタイプから最良の候補を収集します。`y`、島の制約を確保しながら`x`尊敬されている。 
7. 答えは、ステップ 5 と 6 で収集されたすべての有効な候補の最大値です。 

重要な不変点は、バケットから候補を破棄するたびに、その候補が現在のクエリに対して無効であるためであり、グローバルに無効ではないということです。 各バケットは、必要なときに先頭からポップすることによってのみ候補を削除し、各要素はバケットごとに 1 回だけポップできるため、すべての操作にわたるポップの合計数は線形のままです。 

## なぜ機能するのか

 すべての有効な回答は、他の島に属している必要があります。`x`そしてそれ以外のいくつかのタイプ`y`。 つまり、少なくとも 1 つのアイランド バケット内に出現する必要があります。`x`そうでないタイプのバケットが少なくとも 1 つあります。`y`。 これらの構造化された最大値をスキャンすることにより、最適である可能性のある候補が、ある時点でバケットの最大値として到達可能であることが保証されます。 遅延削除により、有効な候補が永久に失われないことが保証され、ヒープの単調な性質により、より優れた候補が明らかになると、以前にスキップされたすべての無効な候補が優先されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq
from collections import defaultdict

def add_to_heap(h, item):
    # item is (-value, type, island)
    heapq.heappush(h, item)

def get_valid_top(heap, forbidden_island, forbidden_type):
    while heap:
        val, t, x = heap[0]
        if x != forbidden_island and t != forbidden_type:
            return -val, t, x
        heapq.heappop(heap)
    return None

def solve():
    q = int(input())
    last = 0

    global_heap = []
    island_heap = defaultdict(list)
    type_heap = defaultdict(list)

    for _ in range(q):
        parts = list(map(int, input().split()))
        tp = parts[0]

        if tp == 1:
            x = parts[1] ^ last
            y = parts[2] ^ last
            w = parts[3] ^ last

            item = (-w, y, x)

            heapq.heappush(global_heap, item)
            heapq.heappush(island_heap[x], item)
            heapq.heappush(type_heap[y], item)

        else:
            x = parts[1] ^ last
            y = parts[2] ^ last

            best = None

            # try global heap first
            while global_heap:
                w, ty, isl = global_heap[0]
                if isl != x and ty != y:
                    best = (-w, ty, isl)
                    break
                heapq.heappop(global_heap)

            # fallback from islands
            for isl, h in island_heap.items():
                if isl == x:
                    continue
                while h:
                    w, ty, _ = h[0]
                    if ty != y:
                        cand = (-w, ty, isl)
                        if best is None or cand[0] > best[0]:
                            best = cand
                        break
                    heapq.heappop(h)

            # fallback from types
            for ty, h in type_heap.items():
                if ty == y:
                    continue
                while h:
                    w, ty2, isl = h[0]
                    if isl != x:
                        cand = (-w, ty, isl)
                        if best is None or cand[0] > best[0]:
                            best = cand
                        break
                    heapq.heappop(h)

            ans = 0 if best is None else best[0]
            print(ans)
            last = ans

solve()
```コードは 3 層のヒープを維持します。 グローバル ヒープは、全体の最大値への高速アクセスをサポートします。 アイランド ヒープとタイプ ヒープは、局所的な最大値をサポートします。 遅延ポップにより、データセット全体を繰り返しスキャンすることなく、無効な項目が最終的に考慮から削除されます。 各アイテムは 1 回挿入され、ポップできる回数は限られているため、償却された複雑さは線形のままです。 

微妙な点は、ヒープが構造間で明示的に同期されないことです。 項目は物理的に削除されることはなく、ヒープの先頭になってクエリ制約に失敗した場合にのみ無視されるため、これは許容されます。

 ## 特殊なケース

 すべてのアイテムが禁断の島に属する場合、島ベースのスキャンのすべての候補はすぐに消えます。 禁止された島ではアイランド ヒープが完全にスキップされ、そこから有効な候補が抽出されないため、アルゴリズムはこれを処理します。 

すべての項目が禁止された型を共有すると、型ヒープはそのクエリには役に立たなくなります。 アイランド ヒープのフォールバック メカニズムにより、他の型も正しくチェックされ、正確さに影響を与えることなくヒープが遅延して枯渇することが保証されます。 

グローバル最大値が無効な場合、有効な候補または枯渇するまでポップが繰り返し発生します。 ポップされた各項目はそのヒープから永久に破棄されるため、今後のクエリで再処理されることはなく、敵対的な場合でも線形償却動作が保証されます。
