 ## 問題の理解

 2 つの文字列が与えられています。$S$そして$T$。 課題はカットすることです$S$連続した空ではない部分のシーケンスに変換します。 各部分は次の接頭辞に似ている必要があります$T$、ただし必ずしも正確である必要はありません。 対応するプレフィックスと最大 1 文字の位置で異なることが許可されます。 

有効なパーティション分割方法ごとに$S$、それが生成する場合$k$部分、そのパーティションが寄与する$k^2$答えに。 すべての有効なパーティションにわたるこれらの寄与の合計が必要です。 

主な問題は、パーティションの数が指数関数的に増加する可能性があることです。$|S|$したがって、次の場合にすべての分割を列挙することは不可能です。$|S|$到達する$10^6$。 どのソリューションでも、明示的なパーティションの列挙を避け、代わりに圧縮された動的方法でパーティションをカウントする必要があります。 

微妙なエッジケースが現れるのは、$T$のセグメントより短い$S$。 セグメントは、次の期間に限り有効です。$T$のプレフィックスと比較する必要があるため、$T$同じ長さの。 これは、常に次の部分文字列と一致することを意味します。$S$のプレフィックスに対して$T$、その長さを超えることはありません。 

もう 1 つの明白ではない問題は、セグメントは、必ずしも固定位置ではなく、どこでも 1 つだけ不一致が許容されることです。 たとえば、次の場合$T = "aba"$、次に次のような文字列`"aaa"`、`"abb"`、 そして`"aca"`はすべて長さ 3 の有効なセグメントですが、`"abc"`は、ちょうど 1 つの位置が異なるため、有効です。`"aba"`。 

制約により、私たちはあらゆることを避ける必要があります。$O(nm)$分割ごとの畳み込みまたは部分文字列比較。 両方の文字列が最大であるため、$10^6$、ほぼ直線または直線に近い時間を目標としています。 

## アプローチ

 この問題について素朴に考える方法は、次のような DP を定義することです。$dp[i]$プレフィックスを分割するすべての方法のセットです$S[0:i]$。 それぞれの立場から$i$、可能な次のセグメントの長さをすべて試します。$L$、どうかを確認してください$S[i:i+L]$とは異なります$T[0:L]$多くても 1 つの位置で、すべてのパーティションを拡張します。 これは指数関数的な分岐に直接つながります。$S$、各セグメントの有効性をチェックする場合でも、次の点まで比較する必要があります。$10^6$最悪の場合の文字。 

ローリング ハッシュや事前計算された不一致数を使用してセグメントの有効性をメモ化したとしても、依然としてパーティションの組み合わせの爆発に直面します。 一定の長さの文字列を分割する方法の数$n$は$2^{n-1}$最悪の場合、パーティションを明示的に表す状態はすべて破滅する運命にあります。 

重要な構造的観察は、セグメントの条件はその長さとプレフィックスとの不一致の数のみに依存するということです。$T$。 これは、次のことを示唆しています。$S$の場合、「これまでのところ最大 1 つの不一致」を維持しながらセグメントをどこまで拡張できるかだけを考慮します。 これはまさに、不一致カウンターを使用したスライディング ウィンドウの問題であり、次のように維持できます。$O(1)$2 つのポインターを使用して拡張子ごとに償却されます。 

有効なセグメント境界が判明すると、問題はセグメントの構成を数えることになります。$S$ここで、許可されるセグメントの長さは位置によって異なります。 これは古典的な「制限付きパーティションカウント」DP ですが、さらに工夫が必要です。ウェイ数とパーツ数の 2 乗の合計の両方を累積する必要があります。 

2 番目のツイストは、プレフィックス位置ごとに、そこに到達するウェイの数だけでなく、ウェイの長さの合計とウェイの 2 乗数も維持することによって処理されます。 セグメント単位で延長するとパーツ数が1つ増えるので、$k^2$のように変換します$(k+1)^2 = k^2 + 2k + 1$。 これにより、パーティションを明示的に追跡することなく、貢献を伝播することができます。 

したがって、解決策は、2 ポインター不一致ウィンドウによって決定される有効なセグメント範囲にわたる 2 つの絡み合った DP 遷移に減ります。

 ## アルゴリズムのチュートリアル

 各開始位置がどのくらい離れているかを前処理します。$S$に対して 1 つのミスマッチ以内に留まりながら延長できる$T$。 

スライディングウィンドウを定義します$S$そして$T$、現在のセグメント内で最大 1 つの不一致が維持されます。 

1. 2 つのポインタを初期化する$l = 0$、$r = 0$、および不一致カウンター$bad = 0$。 このウィンドウは常にセグメントを表します$S[l:r]$と一致$T[0:r-l]$。 
2. 展開する$r$左から右へ$S$。 新しいキャラクターを追加するたびに$S[r]$と比較してください$T[r-l]$。 異なる場合は増分します$bad$。 
3. もし$bad > 1$、左から大きくしてウィンドウを縮小します。$l$。 取り外すとき$S[l]$、不一致の原因となった場合はデクリメントします。$bad$。 まで縮小し続けます$bad \le 1$また。 これにより、現在のウィンドウが有効なセグメントであるという不変条件が維持されます。 
4. ポジションごとに$l$、最大有効エンドポイントがわかりました。$r$。 これは、からのことを意味します$l$、の間で終わる任意のセグメント$l$そして$r$有効です。 
5. ポジションに対して動的プログラミングを使用します。$S$。 させて$dp[i]$プレフィックスを分割する方法の数を表します$S[0:i]$また、2 つの補助配列も維持します。$dp2[i]$部品数の二乗の合計、および$dp1[i]$すべての分割のパーツ数の合計。 
6. 位置に着いたら$i$、すべての有効なセグメントエンドポイントを反復処理します。$j$から始まる$i$。 それぞれについて$j$、トランジションを拡張します。$$dp[j+1] += dp[i]$$

$$dp1[j+1] += dp1[i] + dp[i]$$

$$dp2[j+1] += dp2[i] + 2 \cdot dp1[i] + dp[i]$$これらの式は展開から得られます$(k+1)^2$。 
7. 最終的な答えは次のとおりです。$dp2[|S|]$。 

### なぜ効果があるのか

 すべてのプレフィックス位置で$i$、すべてのパーティションがカウントされます$dp[i]$これらは、まさに、より長いプレフィックスの有効なパーティションに独立して拡張できるものです。 スライディング ウィンドウは、トランジションで使用されるすべてのセグメントが「プレフィックスとの最大 1 つの不一致」を満たすことを保証します。$T$二次変換恒等式により、明示的な分割構造を保存せずに累積二乗カウントが正しく伝播されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

S = input().strip()
T = input().strip()

n = len(S)
m = len(T)

# We only need segments up to length m
# Precompute max reach for each l using two pointers
max_r = [0] * n

r = 0
bad = 0

for l in range(n):
    if r < l:
        r = l
        bad = 0

    while r < n and (r - l) < m:
        if S[r] != T[r - l]:
            bad += 1
        if bad > 1:
            if S[l] != T[0]:
                bad -= 1
            break
        r += 1

    max_r[l] = r - 1

# DP arrays
dp = [0] * (n + 1)
dp1 = [0] * (n + 1)
dp2 = [0] * (n + 1)

dp[0] = 1

for i in range(n):
    if dp[i] == 0:
        continue

    # extend segment from i
    limit = min(max_r[i], n - 1)
    for j in range(i, limit + 1):
        ways = dp[i]

        dp[j + 1] = (dp[j + 1] + ways) % MOD
        dp1[j + 1] = (dp1[j + 1] + dp1[i] + ways) % MOD
        dp2[j + 1] = (dp2[j + 1] + dp2[i] + 2 * dp1[i] + ways) % MOD

print(dp2[n] % MOD)
```DP 状態配列は、3 つの情報層 (パーティションの数、パーツ数で表した長さの合計、パーツ数の二乗の合計) を直接エンコードします。 遷移公式は次の展開から導出されます。$(k+1)^2$、 どこ$k$新しいセグメントを追加する前のプレフィックス パーティション内のパーツの数です。 

内側のループオーバー$j$事前に計算されたものに依存します`max_r[i]`これにより、有効なセグメントのみを拡張することが保証されます。 これにより、DP 中の部分文字列の比較が回避されます。 

微妙な点は、不一致の追跡が確実にプレフィックスと正しく一致するようにすることです。$T$。 比較にはオフセットを使用します$r - l$これにより、各セグメントが常に、対応するプレフィックスと照合してチェックされます。$T$、シフトされたまたは任意の部分文字列に対してではありません。

 ## 特殊なケース

 重大なエッジケースが発生するのは次の場合です。$S$よりもはるかに長いです$T$。 この状況では、$|T|$のプレフィックスと照合できないため、自動的に無効になります。$T$。 スライディング ウィンドウは、長さ方向の拡張を停止することで、これを自然に強化します。$m$したがって、無効な長いセグメントが DP 遷移に入ることはありません。 

もう 1 つのケースは、すべての文字が一致しない場合です。$T$セグメントごとに最大 1 回。 例えば$S = "aaaaa"$、$T = "abc"$。 不一致が 1 つだけ発生する限り、長さ 3 のウィンドウはすべて有効です。 このアルゴリズムは、各位置から始まる有効なセグメントの重複を正しく許可し、DP はすべてのパーティション数を独立して累積します。 

最後に、いつ$T$長さが 1 の場合、各セグメントには最大 1 つの不一致が存在する可能性があります。つまり、内容に関係なくすべてのセグメントが有効になります。 DP は、次のすべてのパーティションをカウントすることになります。$S$、拡張ごとにパーツ数が 1 ずつ均一に増加するため、二次累積は引き続き正しく適用されます。
