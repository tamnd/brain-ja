 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに、小さな整数が一列に並んだ配列があります。 各数字は材料を表し、カクテルはこの配列の連続したセグメントを選択することによって形成されます。 カクテルの「味」は、選択したセグメント内のすべての値のビット単位の XOR として定義されます。 このタスクは、すべての可能な連続サブ配列にわたって、個別の XOR 結果をいくつ取得できるかをカウントすることです。 

重要な構造は、すべてのテスト ケースが、異なるプレフィックス XOR の違いの数を要求していると見なすことができるということです。 プレフィックス XOR を配列の先頭から位置までの XOR として定義すると、サブ配列 XOR は 2 つのプレフィックス値の XOR になります。 

制約は全体として厳しいです。すべてのテスト ケースの合計の長さは最大 10^4 ですが、各値は 2^10 未満です。つまり、すべての数値が 10 ビットに収まります。 これは、テスト ケースあたり O(n^2) のアプローチは最小のケースでのみ存続する可能性がありますが、より大きな制限がある場合には意図したソリューション構造ではないことを強く示唆しています。 それでも、合計 10^4 要素に対する O(n^2) であっても境界線にはなりますが、許容できるため、より構造化された組み合わせまたは線形代数の観点を期待する必要があります。 

すべてのサブ配列を列挙して XOR を直接計算する単純なアプローチでは、重複するプレフィックスが繰り返し再計算され、不必要な繰り返し作業が発生します。 プレフィックス XOR で最適化したとしても、テスト ケースごとに O(n^2) 個の異なるサブ配列に直面することになります。 

いくつかの微妙な状況に注目する価値があります。 

1 つはすべての要素がゼロの場合です。 この場合、すべての部分配列の XOR は 0 に等しいため、答えは n(n+1)/2 ではなく 1 になります。 

もう 1 つは、値がランダムな小さなビットである場合など、すべてのプレフィックス XOR が異なる場合です。 この場合、個別のサブ配列 XOR の数は大きくなる可能性がありますが、それでもプレフィックス値間の個別のペアごとの XOR 差異の数によって制限されます。 

最後に、重複が重要です。異なるサブ配列が同じ XOR 値を生成する可能性があり、それらを複数回カウントしてはなりません。 

問題は本質的に、セット {prefix[r] XOR prefix[l] | のサイズを求めることです。 0 ≤ l < r ≤ n}。これは、古典的な「プレフィックスの違いに対する XOR ベース」形式の問題です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 プレフィックス XOR を計算し、l < r であるすべてのペア (l, r) を列挙し、prefix[r] XOR prefix[l] を計算し、セットに挿入します。 すべてのサブ配列 XOR がそのようなペアに一意に対応するため、これは正しいです。 問題はパフォーマンスです。n 個の要素の場合、約 n(n+1)/2 個の部分配列があるため、単一のテスト ケースで n = 10^4 の場合、約 5×10^7 回の演算が行われ、複数のテストにわたって繰り返される場合はさらに悪化します。 場合によっては Python がわずかに合格する可能性がありますが、これは意図した構造的な解決策ではありません。 

重要な観察は、GF(2) 上の 10 ビット ベクトル空間で作業していることです。 各プレフィックス XOR は、10 次元のバイナリ空間内のベクトルです。 このような空間内の点間の差分の個別の XOR の数は、これらのプレフィックス ベクトルの線形スパンによって決まります。 

すべてのペアを明示的に列挙する代わりに、プレフィックス XOR を段階的に処理し、GF(2) に対する線形基礎を維持します。 新しいプレフィックス値はそれぞれ、以前のプレフィックスとの新しい XOR 結果を生成できますが、それは制御された方法でのみ生成されます。基底にベクトルを挿入すると、その次元が増加するか増加しないかのいずれかになり、増加するたびに、到達可能な XOR 値の数が 2 倍になることに対応します。 

したがって、プレフィックス XOR の基礎を維持します。 新しいプレフィックス XOR を挿入するたびに、基底が更新されます。 個別のサブアレイ XOR の数は、独立した基底ベクトルの寄与の合計に等しく、増分的に追跡できます。 実際には、値は最大でも 2^10 であるため、基底サイズは最大でも 10 となり、システムは非常に小さくなります。

結果は、基底を維持し、各プレフィックスが導入する新しい独立状態の数をカウントすることになり、個別のサブ配列 XOR 値の合計数が得られます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. ゼロに等しいプレフィックス 0 から始めて、配列を左から右にスキャンしながらプレフィックス XOR 値を計算します。 これにより、すべてのサブ配列の XOR が 2 つのプレフィックス状態の差になることが保証されます。 
2. 10 ビット整数に対して線形基準を維持します。 基底では、ベクトルが他のベクトルの XOR として表現できないようにベクトルが格納され、GF(2) の独立性が維持されます。 
3. 新しいプレフィックス XOR 値ごとに、それを基底に挿入しようとします。 既存の基底ベクトルを使用して最上位ビットから最下位ビットまで削減します。 ゼロになると、それはすでに表現可能であり、新しい情報は追加されません。 
4. 削減された値がゼロ以外の場合、その値を基底の最も高い設定ビット位置に挿入し、それに応じて基底を更新します。 
5. 新しい独立ベクトルの挿入に成功した回数を追跡します。 挿入が成功するたびに、プレフィックスの違いによって形成される到達可能な XOR 状態の数が 2 倍になるため、それに応じて寄与が蓄積されます。 
6. 最終的な答えは、基底ベクトルの数と、基底ベクトルが到達可能なプレフィックス差分の XOR 空間をどのように拡張するかによって導き出されます。 

これが機能する理由: すべてのサブ配列 XOR は 2 つのプレフィックス XOR の差です。 すべてのプレフィックス XOR のセットは、10 次元のバイナリ空間内のベクトルのセットを形成します。 セットによって生成される個別のペアごとの XOR の数は、そのセットのスパンによって完全に決まります。 線形基底は冗長性を持たずに正確にこのスパンを捉え、すべての独立したベクトルが XOR の組み合わせを形成する際に新たな次元の自由に貢献します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(arr):
    basis = [0] * 10
    cnt = 0
    pref = 0
    seen = set()
    seen.add(0)
    ans = 0

    for x in arr:
        pref ^= x

        if pref not in seen:
            seen.add(pref)
            ans += 1

        v = pref
        for b in range(9, -1, -1):
            if (v >> b) & 1:
                if basis[b]:
                    v ^= basis[b]
                else:
                    basis[b] = v
                    cnt += 1
                    break

    return len(seen) + (1 << cnt) - 1 - (len(seen) - cnt)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        out.append(str(solve_case(arr)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、プレフィックス XOR 構造とコンパクトな 10 ビット線形ベースに依存しています。 基底配列には、各ビット位置の代表ベクトルが格納されます。 プレフィックス XOR を挿入するときは、すでに保存されている基底ベクトルを使用して上位ビットを削除します。 新しい独立ベクトルを配置できた場合は、基底サイズを増加します。 

微妙な点は、インデックス 0 で始まるサブ配列がそれに依存するため、暗黙的にプレフィックス 0 を含める必要があることです。 これは、プレフィックス セットをゼロで初期化することで処理されます。

 ## 特殊なケース

 のような入力の場合`1 0 0 0 0`、接頭辞 XOR は、最初の要素の後に変更されることはありません。 このアルゴリズムは独立した基底ベクトルを 1 つだけ挿入するため、到達可能な XOR 空間は非常に小さいままです。 すべての部分配列の XOR は長さのパリティに応じて 0 または 1 のいずれかになり、基底はこれを 1 次元のスパンとして正しくキャプチャします。 

のような入力の場合`1 2 4 8`、各値は新しい独立したビットを導入します。 基底は完全な次元 4 まで拡大し、個別のサブ配列 XOR の数はそのセグメント上で最大になります。 前のベクトルによってどれも削減できないため、アルゴリズムは各ベクトルを追加し、スパンを段階的に正しく拡張します。
