 ## 解決策
 ## 問題の理解

 単語に分割された短いメッセージが与えられており、送信エラー後に特別なキーワード「codecup」がそのメッセージのどこかに出現する可能性があるかどうかを判断したいと考えています。 

重要な詳細はエラー モデルです。 送信される各単語は送信中に最大 1 文字を失う可能性がありますが、文字が変更されることはなく、単語間で他のことは何も起こりません。 したがって、観察されるすべての単語は、元の単語とまったく同じか、元の単語のどこかで 1 文字が削除されたものになります。 置換や複数の削除は許可されません。 

タスクは、観察された単語のいずれかが、このルールに基づいて意図された単語「codecup」に対応する可能性があるかどうかを確認することです。 少なくとも 1 つの単語が「codecup」の破損したバージョンである可能性がある場合、答えは肯定的です。 

入力サイズは小さく、最大 100 ワード、各ワードの長さは 25 までです。これにより、重い前処理や高度なデータ構造に対するプレッシャーが軽減されます。 各チェックには長さ 7 の固定パターンのみが含まれるため、単語ごとの直接チェックで十分です。 

微妙な点は、文字を変更して単語を「修正」することはできないということです。 受信した単語を取得するために、元の「コードカップ」から最大 1 文字だけを削除します。 この非対称性は、一般的な編集距離との混同を防ぐため重要です。 

主なエッジケースは、単語がほぼ正しいものの、2 つの位置が異なる場合です。 たとえば、「codecap」は置換によって異なりますが無効であり、「cdecp」は 2 つの削除に対応しますがこれも無効です。 どちらも正しく失敗するはずです。 

## アプローチ

 強引な解釈では、各メッセージ ワードを「codecup」から文字を削除するすべての考えられる方法と一致させようとします。 「codecup」の長さは 7 であるため、可能性は 8 つだけです。何も削除しないか、7 つの位置のうち 1 つだけを削除するかです。 単語ごとに、これら 8 つの候補を生成し、比較することができます。 

これはすでに制限内で機能しますが、わずかに間接的です。 もっと明確な観察は、変更されたパターンを生成する必要がまったくないということです。 代わりに、2 つのポインターを使用して「codecup」に対して単語をスキャンし、パターン内の最大 1 文字をスキップすることができます。 これは、「オリジナルから最大 1 つの削除」という制約を直接エンコードします。 

パターン空間が小さいため、強引なアプローチは機能しますが、一般化すると概念的に混乱してしまいます。 2 ポインタの定式化により、すべてが単語ごとに 1 回のリニア スキャンに削減され、正しさの推論が容易になります。

 ## アルゴリズムのチュートリアル

 「codecup」を長さ 7 の固定参照文字列として扱い、各単語を個別にテストします。 

1. メッセージ内の各単語について、単語用とパターン用の 2 つのポインターを使用して、「codecup」との照合を試みます。 

目標は、パターン内で最大 1 文字をスキップできるようにしながら、パターンを進めながら単語全体を消費することです。 
2. 単語用とパターン用の 2 つのインデックスと、スキップするパターン文字の数を表すカウンターを初期化します。 

スキップ カウンタは、破損する前の元の単語内で許可された 1 つの削除を表します。 
3. 両方のポインタが範囲内にあるときに、文字を比較します。 一致する場合は、両方のポインタを進めます。 

これは送信を生き残った文字に対応します。 
4. 一致しない場合は、パターン内の 1 文字をスキップして、スキップ カウンタを増やし、パターン ポインタだけを進めようとします。

これは、このパターン文字が送信前に削除されたものである可能性があるという考えをモデル化しています。 
5. すでにスキップを使用した後に再び不一致が発生した場合、この単語に対する一致の試行は失敗します。 
6. ループの後、単語全体が消費され、パターン内で最大 1 回のスキップを使用した場合にのみ一致が有効になります。パターン内の残りの文字は、許可された単一の削除シナリオに対応する場合にのみ安全に無視できます。 
7. いずれかの単語が成功すると、すぐに「はい」を返します。 それ以外の場合は、すべての単語をチェックした後、「いいえ」を返します。 

### なぜ効果があるのか

 中心となる制約は、観察された各単語は、最大 1 文字を削除することによって元の単語から派生するということです。 つまり、単語と「codecup」の間の位置合わせは、パターン内の 1 つの文字が欠落しているという、まさに 1 つの構造的な方法で失敗する可能性があります。 2 ポインター プロセスでは、観察された単語内のすべての文字がパターンの順序を保持するサブシーケンスに対応する必要があることが強制されますが、スキップ カウンタでは、複数の欠落位置が想定されないことが強制されます。 これは、すべての有効な破損結果を正確に特徴付けており、置換や複数の削除は除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

TARGET = "codecup"

def matches(word):
    i = j = 0
    skipped = 0

    while i < len(word) and j < len(TARGET):
        if word[i] == TARGET[j]:
            i += 1
            j += 1
        else:
            if skipped == 1:
                return False
            skipped += 1
            j += 1

    if i != len(word):
        return False

    return True

def solve():
    n = int(input())
    words = input().split()

    for w in words:
        if matches(w):
            return "Yes"
    return "No"

print(solve())
```このソリューションでは、マッチング ロジックをヘルパー関数に分離して、各単語が個別にチェックされるようにします。 2 ポインター ループにより、固定パターン上での線形スキャンが保証されます。 重要な点は、単語全体が読み取られているかどうかを最終的にチェックすることです。 そうしないと、単語内に余分な文字が残っていると、部分一致が誤って合格する可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    global input
    input = _sys.stdin.readline

    TARGET = "codecup"

    def matches(word):
        i = j = 0
        skipped = 0
        while i < len(word) and j < len(TARGET):
            if word[i] == TARGET[j]:
                i += 1
                j += 1
            else:
                if skipped == 1:
                    return False
                skipped += 1
                j += 1
        return i == len(word)

    n = int(input())
    words = input().split()
    return "Yes" if any(matches(w) for w in words) else "No"

# provided samples
assert run("""4
codeforsquares codecup coming soon
""") == "Yes"

assert run("""3

""") == "Yes"

assert run("""5

""") == "No"

# custom cases
assert run("""1

""") == "Yes"

assert run("""1
codecap
""") == "No"

assert run("""1
cdecp
""") == "No"

""") == "Yes"

 ## 特殊なケース

 有用な失敗例は、「コードキャップ」のような単語です。これは、単一の位置がターゲットと異なりますが、削除ではなく置換によって異なります。 このアルゴリズムでは文字の置換は一切許可されず、パターン内でスキップするだけなので、不一致の文字を位置合わせすることができず、正しく拒否されます。 

もう 1 つの特殊なケースは、「cdecp」のような単語で、元の「codecup」から複数の文字を削除する必要があります。 スキップ カウンタはパターン内の複数の不一致を防ぐため、2 番目の構造ギャップが必要になると、一致は直ちに失敗します。 

最後に、6 文字より短い単語は、最大 1 つの削除がある 7 文字のソースの有効な破損を表すことはできません。 パターン内でスキップする必要がある文字が多すぎて、許容される 1 つの削除を超えているため、ポインター ロジックは当然失敗します。
