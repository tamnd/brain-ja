 ## 解決策
 ## 問題の理解

 トレーニングの開始から分単位で測定されたタスク完了時間のソートされたリストが与えられます。 それぞれの時間は、単一のタスクが解決された時間に対応します。 これらのタイムスタンプは、1440 分ごとを 1 日のバケットにグループ化することで暦日に変換できます。 

少なくとも 3 つのタスクが 1440 分の間隔内に収まれば、その日は「成功」となります。 問題は、日の境界が選択したタイムゾーンによって異なることです。 タイムゾーンを整数の時間分シフトすることは、すべてのタイムスタンプに 60 分の固定倍数を追加することと同等であり、タスクを日の境界を越えて移動できます。 

目標は、成功した日の最長連続ブロックを最大化する 1 時間ごとのシフトを選択することです。 

入力サイズは最大 200,000 タイムスタンプになります。 これにより、シフトごとの動作をシフトごとに線形以上の時間または線形に近い時間で再計算するソリューションは即座に除外されます。 数日間にわたる単純な 2 次アプローチやタスクのペアごとのグループ化は遅すぎますが、24 回程度の線形スキャンであれば完全に実現可能です。 

タスクが日の境界付近にある場合、微妙な問題が発生します。 小さなシフトにより、タスクの密集したクラスターを別の日に分割したり、まばらな日を密な日に統合したりできます。 たとえば、シフトにより 1 つのタスクが前日または翌日に押し込まれると、ちょうど 3 つのタスクがある日が無効になる可能性があります。 

もう 1 つのエッジ ケースは、どのシフトにも少なくとも 3 つのタスクがある日が発生しない場合です。 この場合、連続セグメントを形成するのに成功した日はないため、答えはゼロになります。 

## アプローチ

 直接的なアイデアは、考えられるすべての時間ごとのシフトをシミュレートし、タスクの配分を日ごとに再計算することです。 シフトは整数時間に制限されているため、1440 分を法とする異なるオフセットは 24 個のみです。 

シフトごとに、シフトを適用した後、整数除算を使用してすべてのタスク時間を日インデックスに割り当てます。 次に、毎日到着するタスクの数を数えます。 最後に、結果の日数をスキャンして、毎日少なくとも 3 つのタスクがある連続した日のインデックスの最長実行を見つけます。 

強引な構造では、シフトごとに終日の割り当てを再計算し、日の範囲ごとにウィンドウを繰り返しチェックします。 非効率的に実行すると、繰り返しスキャンまたは範囲の再計算が行われるようになり、最悪の場合、およそ O(24 · n ·number_of_days) の動作が発生しますが、これは不必要です。 

重要な観察は、シフト スペースが小さく、固定されていることです。 シフト全体で最適化する必要はありません。 各シフト評価を n で線形にするだけで済みます。 これにより、問題全体が O(24n) に減ります。 日のグループ化自体はハッシュ マップで処理でき、実際に成功したと思われる日のみを並べ替えることで連続セグメントを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースの再計算とスキャンが非効率的 | O(24・n・D) | O(D) | 遅すぎる |
 | シフトごとにハッシュを使用してすべてのシフトを試す | O(24 · n log n) | O(n) | 承認済み |
 | ハッシュマップ + ソート キーを使用してすべてのシフトを試す | O(24 · n + 24 · k log k) | O(n) | 承認済み |

 ここで、k はシフト内の個別の日数であり、最大でも n です。 

## アルゴリズムのチュートリアル

 ### 1. シフトの検索スペースを制限する

 k の範囲が 0 ～ 23 の場合、k 時間だけシフトすることを考慮します。24 時間を追加すると、すべてのタイムスタンプがちょうど 1440 分シフトされ、日の割り当てが保持されるため、これで十分です。 

### 2. シフトを適用し、日のインデックスを計算します。 

各シフト値について、すべてのタイムスタンプ t を t + シフト · 60 に変換し、その日のインデックスを (t + シフト · 60) // 1440 として計算します。これにより、各タスクがそのタイムゾーンの暦日に割り当てられます。

このステップは、タスク時間に関連して境界がどのように移動するかをシミュレートするため、変換の中核となります。 

### 3. 1 日あたりのタスクを数える

 私たちは、日のインデックスをタスクの数にマッピングする辞書を維持します。 変換されたタイムスタンプごとに、その日のカウントが増加します。 

この集計により、潜在的に大きな時間範囲が管理可能な個別の日数に圧縮されます。 

### 4. 成功した日を特定する

 カウントが少なくとも 3 であれば、その日は成功です。 このような日のインデックスをすべて別の構造に収集します。 最終的な答えを決めるには、この日だけが重要です。 

### 5. 成功した連続日数の最長期間を見つける

 成功した日のインデックスを並べ替え、線形にスキャンします。 連続するインデックスがちょうど 1 だけ異なる場合は、現在の連続値を延長します。 それ以外の場合はリセットします。 

すべてのシフトにわたる最大ストリーク長が記録されます。 

### なぜ効果があるのか

 各シフトは、タイムスタンプの日バケットへの決定的なパーティションを定義します。 成功はカウントのしきい値のみに依存するため、バケットごとのタスクをカウントすることで、その日が成功したかどうかを完全に把握できます。 日インデックス空間内の連続する整数が同じシフト内の連続する日に正確に対応するため、成功した日を並べ替えて隣接性をチェックすると、カレンダー構造が正しく再構築されます。 すべての有効な構成が 24 シフトの間でテストされるため、可能な限り最良の連続ブロックが評価されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))
    
    best = 0
    
    for shift in range(24):
        offset = shift * 60
        cnt = {}
        
        for x in t:
            d = (x + offset) // 1440
            cnt[d] = cnt.get(d, 0) + 1
        
        good_days = []
        for d, c in cnt.items():
            if c >= 3:
                good_days.append(d)
        
        if not good_days:
            continue
        
        good_days.sort()
        
        cur = 1
        best_local = 1
        
        for i in range(1, len(good_days)):
            if good_days[i] == good_days[i - 1] + 1:
                cur += 1
            else:
                cur = 1
            if cur > best_local:
                best_local = cur
        
        if best_local > best:
            best = best_local
    
    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、24 の可能な時間シフトすべてをループします。 シフトごとに日の割り当てを再計算し、辞書にカウントを集計します。 少なくとも 3 つのタスクがある日のみが、さらなる処理のために保持されます。 

連続日の計算は、有効な日のみを並べ替えた後に実行されるため、大きな空の範囲の日をスキャンする必要がなくなります。 比較は純粋に整数の隣接性に基づいて行われるため、整数の違いを超えるカレンダー算術は必要ありません。 

よくある間違いは、シフトが時間に制限されていることを忘れ、不必要な分単位のシフト全体を最適化しようとすることです。 もう 1 つは、シフト全体でグローバルなスライディング構造を維持しようとすることですが、これでは漸近的なパフォーマンスは改善されずに正確性が複雑になります。

## Complexity Analysis

 | 測定 | 複雑さ | Explanation |
 | --- | --- | --- |
 | Time | O(24 · n log n) | 各シフトでは、n 個のタイムスタンプすべてが処理され、さらに最大 n 日分のキーがソートされます。 
| スペース | O(n) | シフトごとのカウントのストレージ |

 ## 特殊なケース

 タスクが 3 つ未満の最小入力では、シフトに関係なく成功条件を満たす日はないため、常にゼロが生成されます。 どのシフトでもしきい値に達する日がないため、アルゴリズムはこれを自然に処理します。 

1440 の倍数付近にクラスター化されたタイムスタンプなど、境界の多い構成では、シフトによって隣接する日にタスクが正しく再分散されるかどうかをテストします。 このような場合、正確さはシフト後の整数の除算に依存しますが、これは実装で一貫して処理されます。 

完全に 1 日内にある均一なクラスターは、すべてのタスクが 1 つの 1440 分のウィンドウ内に留まっている場合、どれだけシフトしても成功日数を 1 日を超えて増やすことができないことを示しています。
