 ## 解決策
 ## 問題の理解

 長さが不明な文字列が与えられました$n \le 5000$、最大 26 文字のアルファベットから構築されます。 文字列を直接見ることはできません。 代わりに、任意のセグメントに対してクエリを実行できます。$[l, r]$、インタラクターは、その部分文字列に出現する個別の文字の数を返します。 

このようなクエリを一定数まで尋ねた後、グローバルな組み合わせ値、つまり隠し文字列の個別の部分文字列の数を計算する必要があります。 

部分文字列は開始インデックスと終了インデックスによって決定されるため、次のようになります。$O(n^2)$最悪の場合は候補も含まれますが、それらの多くは文字列として同一です。 課題は、ユニークなものを数えるということです。 

主な難点は、私たちは文字を直接観察することはなく、間隔内にいくつの異なる記号が現れるかについての情報しか得られないことです。 つまり、部分文字列の一意性を推論するには、文字列の十分な構造を再構築する必要があります。 

制約は、$O(n^2)$あるいは$O(n^2 \log n)$最終的な計算は再構築後に許容されますが、対話フェーズはおおよその範囲内にとどまる必要があります。$3 \cdot 10^4$クエリ。 位置ごとに 26 個の候補に対して線形スキャンを使用し、候補ごとに複数のクエリを実行する戦略は制限を超える危険があるため、各位置が非常に少ないクエリで分類されるように再構成を構成する必要があります。 

「新しい個別カウントは新しい文字を意味する」と欲張って仮定しようとすると、微妙な失敗例が現れます。 たとえば比較してみると$[1,i]$そして$[1,i-1]$、個別のカウントが等しい場合、その位置で前のどの文字が繰り返されるかはわかりません。$i$、いくつかの繰り返しが存在するというだけです。 正確に一致する文字を特定せずにその事実のみに依存するソリューションでは、文字列を再構築できません。 

## アプローチ

 ブルート フォースの観点では、以前に確認されたすべての文字と比較することによって、各文字を直接決定しようとします。 ポジションについて$i$、すべての既知の文字 ID を試し、間隔クエリを使用して新しい位置がそれらの 1 つと一致するかどうかを確認します。 これにより、それぞれが最後に出現したことがわかっている最大 26 の「アクティブ キャラクター」を維持し、各候補を個別にテストすることになります。 各テストでは、一定数のクエリ (通常は 2 つ) を使用して、間隔を延長することで個別のシンボルの数が増加するかどうかを検証します。 

これは正しいです。なぜなら、distinct-count クエリに対する答えは、間隔内に新しい文字が出現するかどうかに正確に依存するからです。 ただし、障害点はクエリ数です。最悪の場合、それぞれの$n$ポジションによっては、最大 26 個の候補者をスキャンする必要がある場合があり、その結果、$2 \cdot 26 \cdot n$クエリは大きすぎて、厳密な対話制限には対応しません。 

重要な観察は、文字の同一性が確立されると、その最後の出現が安定した参照点となり、候補文字との同等性のチェックが、事前に計算されたベースライン値との 1 回の比較に削減できるということです。 これにより、各候補チェックを 2 つではなく 1 つのクエリで実行できるようになり、実際には、ほとんどの位置が既存の文字とすぐに一致するため、アクティブなチェックの数は少なくなります。 

文字列を再構築した後、2 番目の部分は標準的な組み合わせ問題、つまり既知の文字列の個別の部分文字列を数える問題になります。 これは、LCP を備えた接尾辞配列または接尾辞オートマトンを使用して実行できます。 最も直接的な決定論的なアプローチは、サフィックス配列と LCP を組み合わせたもので、制限内で快適に実行されます。$n \le 5000$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート再構築 + 候補全体のスキャン |$O(26n)$クエリ +$O(n^2)$処理 |$O(n)$| クエリが多すぎます |
 | 最適化された再構成 + サフィックス配列 |$O(n \log n)$+ ポジションあたりのクエリ数が少ない |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 復興フェーズ

 1. 発見された文字のリストを維持し、各文字を最後に知られた位置に関連付けます。 最初はこのリストは空です。 
2. 位置を左から右に処理します。 位置で$i$、ここでどのキャラクターが登場するかを決定したいと思います。 
3. 既知の文字ごとに$c$、位置で最後に出現する$p_c$、間隔でクエリを発行します。$[p_c, i]$。 その答えを保存されている値と比較します。$[p_c, i-1]$。 両方の値が等しい場合、位置を追加します$i$その間隔内で個別の文字の数は増加しませんでした。これは、$s[i] = c$。 
4. 既存の文字が一致しない場合は、位置を扱います$i$新しいキャラクターとして追加し、新しいアイデンティティを割り当てます。 
5. 識別された文字の最後に出現した文字を次のように更新します。$i$。 
6. 文字列全体が再構築されるまで繰り返します。 

重要な考え方は、最後に出現した文字が「署名アンカー」として機能するということです。 現在の文字がその候補と等しい場合、最後に出現した文字から拡張しても、新しい個別の記号は導入されません。 不一致があると、必然的に個別カウントが増加します。 

### 個別の部分文字列を数える

 文字列が明示的にわかったら、サフィックス配列と LCP 配列を使用して個別の部分文字列の数を計算します。 接尾辞を辞書順に並べ替えた後の部分文字列の総数は、すべての接尾辞の残りの長さから前の接尾辞の LCP を引いた合計になります。 

### なぜ効果があるのか

 再構成の各ステップで、各キャラクターのアイデンティティは固定された最終出現インデックスに関連付けられます。 正確に一致するには、そのインデックスから間隔を延長します。$i$個別の文字の数は増加しません。 一致が正しくない場合、最後に出現した文字がテストされたセグメント内にないため、新しい文字によってその区間に少なくとも 1 つの追加の別個の記号が導入されます。 これにより、識別された文字の一意性が保証される厳密な分離条件が作成されます。 

各位置にはすべての間隔応答と一致する 1 つの ID が割り当てられるため、再構成された文字列はすべてのクエリ応答と一致し、したがって有効になります。 文字列が固定されると、部分文字列のカウントはその文字列の決定的な関数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# -------- interactive helper --------
def ask(l, r):
    print(f"? {l} {r}")
    sys.stdout.flush()
    return int(input())

# -------- suffix array (doubling) --------
def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = [ord(c) for c in s]
    tmp = [0] * n

    while True:
        sa.sort(key=lambda i: (rank[i], rank[i + k] if i + k < n else -1))

        tmp[sa[0]] = 0
        for i in range(1, n):
            prev = sa[i - 1]
            cur = sa[i]
            tmp[cur] = tmp[prev] + (
                (rank[cur], rank[cur + k] if cur + k < n else -1)
                != (rank[prev], rank[prev + k] if prev + k < n else -1)
            )

        rank = tmp[:]
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa

def build_lcp(s, sa):
    n = len(s)
    rank = [0] * n
    for i, v in enumerate(sa):
        rank[v] = i

    h = 0
    lcp = [0] * n

    for i in range(n):
        if rank[i] == 0:
            continue
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h:
            h -= 1
    return lcp

# -------- reconstruction --------
def solve():
    n = int(input().strip())

    # store discovered characters: (char_id -> last position)
    last_pos = []
    res = [''] * n

    # we also cache previous answers for (p, i-1)
    cache = {}

    def get(p, r):
        if (p, r) in cache:
            return cache[(p, r)]
        cache[(p, r)] = ask(p + 1, r + 1)
        return cache[(p, r)]

    for i in range(n):
        found = -1

        for c in range(len(last_pos)):
            p = last_pos[c]

            # compare distinct([p, i]) vs distinct([p, i-1])
            if i > 0:
                a = get(p, i)
                b = get(p, i - 1)
                if a == b:
                    found = c
                    break

        if found == -1:
            last_pos.append(i)
            res[i] = chr(ord('a') + len(last_pos) - 1)
        else:
            res[i] = chr(ord('a') + found)
            last_pos[found] = i

    s = ''.join(res)

    sa = build_suffix_array(s)
    lcp = build_lcp(s, sa)

    ans = 0
    n = len(s)
    for i in range(n):
        ans += n - sa[i]
        if i:
            ans -= lcp[i]

    print(f"! {ans}")

if __name__ == "__main__":
    solve()
```再構築ループはソリューションの中核です。 これは、既知の文字の小さなセットを維持し、それぞれが最後に出現した文字によって追跡されます。 位置ごとに、最後の位置に固定された間隔個別カウント クエリを使用して、現在の文字をこれらの既知の ID と照合しようとします。 一致するものが見つかると、その ID が再利用されます。 それ以外の場合は、新しいものが作成されます。 

同じペアであるため、クエリ結果をキャッシュすることが重要です。$(p, i)$複数の候補チェックにわたって再利用できます。 

接尾辞配列部分は標準です。再構築された文字列を辞書順に並べた接尾辞に変換し、LCP を使用して重複部分を減算し、一意の部分文字列だけを残します。

 ## 特殊なケース

 単一文字の文字列の場合、再構成により直ちに新しい ID が割り当てられ、サフィックス構造によって 1 つの部分文字列が得られます。 

次のような完全に均一な文字列の場合`aaaaa`、アンカー テストを通じてすべての位置が最初の文字と一致するため、新しい ID は作成されず、サフィックス配列は正しく生成されます。$n(n+1)/2$最大の重複によって部分文字列が削減されます。 

次のような交互パターンの場合`ababab`、アルゴリズムは 2 つの ID を繰り返し交互に実行し、文字がギャップの後に再び現れる場合でも、アンカーベースの等価性チェックで十分であることを示しています。
