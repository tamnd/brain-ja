 ## 解決策
 ## 問題の理解

 次のような整数のグリッドが与えられます。$n$行と$m$列。 各セルには負ではない整数が含まれています。 左上隅から開始して、右または下にのみ移動して右下隅に到達したいと考えています。 開始する前に、各行に対して任意の数の左循環シフトを実行できます。 各シフトにかかるコスト$k$、パスの合計は、訪問したすべてのセルの合計です。 総コストはシフト コストとパスの合計の合計であり、これを最小限に抑える必要があります。 

入力により次のことが保証されます。$n\cdot m$すべてのテストケースで次を超えない$5 \cdot 10^4$、そしてそれぞれ$n, m$最大 200 まで可能です。これにより、$O(n \cdot m^2)$テスト ケース アルゴリズムごとに、$200 \cdot 200^2 = 8 \cdot 10^6$2 秒の制限時間内に快適に収まる操作です。 可能なすべての組み合わせを直接ブルートフォースでシフトします ($m^n$）は不可能でしょう。 

明らかではないエッジケースが発生するのは次の場合です。$k=0$。 その後、コストをかけずに何度でも行をシフトでき、パスの合計を最小限に抑えるためにすべての行の最適な位置合わせを選択する必要があります。 もう 1 つの微妙なケースは、水平方向または垂直方向の移動のみが存在する単一行または単一列です。 単純なコードでは、シフトが誤って適用されたり、パスの合計が過大にカウントされたりする可能性があります。 また、$k$シフトを妨げる可能性があるため、行をシフトしないままにしておくことが最適な場合があります。 

たとえば、次のサイズのグリッド$1 \times 3$価値観を持って$[10, 0, 5]$そして$k=100$移行に伴うコストがいかなる利益をも上回るため、移行すべきではありません。 逆に、もし$k=0$、行を 2 回シフトして、ゼロを開始位置に移動できます。 

## アプローチ

 ブルート フォース アプローチでは、行シフトの考えられるすべての組み合わせを試し、それぞれの最小パス合計を計算します。 一定の長さの列の場合$m$、 がある$m$可能なシフトと$n$これにより生じる行$m^n$組み合わせ。 のために$m = 200$そして$n = 200$、これは天文学的な数字です。 このアプローチは、考えられるすべての前処理ステップを評価するため正しいですが、組み合わせ爆発により失敗します。 

重要な洞察は、行をシフトするとその行の列位置にのみ影響があり、他の行には影響しないということです。 したがって、グリッドの各列について、各行のどのシフト バージョンがその列に対象のセルを配置するかを検討できます。 つまり、各行について考慮する必要があるのは、$m$シフトされたバージョンを取得し、動的プログラミングを使用して最小パス合計を計算します。 

具体的には、動的プログラミング状態は、各行に特定のシフトを選択したと仮定した場合、各セルに到達するための最小合計です。 単一行の場合、セルを特定の列に揃えるための最小コストは、セルの値にセルの値を加えたものです。$k \cdot$必要なシフト数。 複数の行の場合、行ごとに移動する DP を使用してこれを伝播します。 各行には$m$可能なシフトと$n$行が存在する場合、これは次のようになります$O(n \cdot m^2)$時間の複雑さ、制約の下で許容可能。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n) | O(n \cdot m) | 遅すぎる |
 | 最適 | O(n \cdot m^2) | O(n \cdot m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各行について$i$、列ごとに計算します$j$その列に最小のセルを配置するための最小コスト。 これは元のセル値にプラスしたものです$k$その値を列に移すのに必要なシフト数の倍$j$。 あるから$m$行ごとのセル、サイズの配列を事前計算します。$m \times m$行のコストを表す$i$その列になるようにシフト$j$特定のオリジナルセルを持っています。 
2. DP テーブルの初期化`dp[i][j]`行に到達するための最小コストを表す$i$、 カラム$j$。 セット`dp[0][*]`行 1 のシフトされたコストに。 
3. 後続の各行について$i$、 アップデート`dp[i][j]`以前のすべての列位置の最小値として`l`で`dp[i-1][l]`プラス行を移動するコスト$i$現在の列が$j$整列します。 私たちは取る`min(dp[i][j], dp[i-1][l] + cost_of_shift[i][j])`。 
4. すべての行を処理した後、`dp[n-1][m-1]`には最小限の総コストが含まれます。 

これが機能するのは、各行のシフトが列にどのように影響するかが独立しており、動的プログラミングによりすべての列の配置を効率的に調査できるためです。 不変条件というのは、`dp[i][j]`行に到達するまでの最小総コストが常に含まれます$i$、 カラム$j$最適なシフトを行 (i`.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        INF = 10**18
        dp = [ [INF]*m for _ in range(n) ]
        
        # first row
        for shift in range(m):
            for j in range(m):
                val = grid[0][(j - shift) % m] + shift * k
                dp[0][j] = min(dp[0][j], val)
        
        # subsequent rows
        for i in range(1, n):
            ndp = [INF]*m
            for shift in range(m):
                row_shift_cost = [grid[i][(j - shift) % m] + shift * k for j in range(m)]
                for j in range(m):
                    for l in range(m):
                        ndp[j] = min(ndp[j], dp[i-1][l] + row_shift_cost[j])
            dp[i] = ndp
        
        print(min(dp[n-1]))

if __name__ == "__main__":
    solve()
```最初の DP 初期化では、すべての可能なシフトの下で最初の行の各列のコストが計算されます。 後続の行については、`ndp[j]`前の行からの最小パス合計に、現在の行をシフトするコストを加えたものを累積します。 モジュロはラップアラウンドを正しく処理します。 この実装では、`INF`適切な最小比較を確保するため。
