 ## 解決策
 ## 問題の理解

 隠れた整数を決定するように求められます$k$インタラクティブな設定では、$k$長さの隠しバイナリ配列に対する範囲クエリに応答するデバイスの動作を制御します$n$。 配列には 1 が 1 つだけ含まれており、他のすべての要素は 0 です。$k$の場合、デバイスはその範囲内の配列の実際の合計を返します。 少なくともある範囲の長さについては$k$、合計の補数を返します。 

課題は、単一の 1 の位置と配列の長さがわからないことです。$n$非常に大きくなる可能性があり、最大で$2^{30}$。 ただし、クエリは 33 に制限されているため、線形にスキャンすることはできません。 これは、各要素をクエリしたり、すべての可能な範囲を試したりする総当り的なアプローチは実行不可能であることを意味します。 主な洞察は、通信距離が交差するときにデバイスが応答を反転するということです。$k$、これにより次のことが推測できます。$k$賢く選択された範囲クエリを使用して間接的に実行されます。 

明らかではないエッジ ケースは、単一の 1 が配列の先頭または末尾に非常に近い場合、または次の場合に発生します。$k$境界 2 に近い、または$n-1$。 最初のゼロ以外の応答が 1 に対応すると仮定する単純なアプローチは、デバイスが広い範囲に対して応答を反転するため、失敗する可能性があります。 たとえば、次の場合$n=8$、$k=6$、1 が 6 の位置にある場合、[1,8] をクエリすると 1 ではなく 0 が返されます。これを誤解すると、$k$。 

## アプローチ

 ブルートフォースソリューションでは、あらゆる可能な手段が試行されます。$k$範囲をクエリして、デバイスが反転するタイミングを確認します。 これは正解です。反転動作によって一意に識別されるためです。$k$、ただし、最大で必要です$O(n)$クエリ。大規模なクエリでは不可能です$n$。 

最適な解決策の重要な観察は、最初の要素から始まる長さ 1 の範囲をクエリすると、単一要素の範囲はすべて 0 または 1 よりも小さいため、デバイスは正しい 0 または 1 を返すということです。$k$。 次に、次の事実を利用して、同じ点から開始して 2 の累乗になるように長さを増加させながら範囲をクエリできます。$n$は 2 の累乗です。デバイスが応答を反転するタイミングをチェックすることで、しきい値の長さが超過または到達していることを検出できます。$k$。 

反転が発生する範囲がわかったら、次の二分探索を実行できます。$k$その範囲内で。 このアプローチにより、次のことが保証されます。$k$せいぜい$O(\log n)$クエリ。 以来$n\le 2^{30}$、これは 33 クエリ制限内に十分収まります。

 ## アルゴリズムのチュートリアル

 1.初期化$l=1$そして$r=n$。 まず、開始点に対する 1 の位置を決定し、候補範囲を見つけます。$k$。 
2. 最初の要素をクエリする$a[1]$。 1 を返した場合、その 1 はインデックス 1 にあります。 それ以外の場合は、さらに進みます。 
3. デバイスの応答が予想される合計に対して反転するまで、1 から開始して範囲の長さを 2 倍にする一連のクエリ (つまり、1、2、4、8...) を使用します。 この反転は、クエリされた範囲の長さが少なくとも$k$。 
4. 反転の原因となる範囲長が特定されたら、以前の範囲長 (安全) と現在の範囲長 (反転) の間で二分探索を実行して、正確な範囲長を特定します。$k$。 各クエリは、デバイスが真の和を返すかその補数を返すかをテストします。 
5. 見つかった結果を出力する$k$。 

なぜ機能するのか: 不変条件は、範囲が以下よりも短いということです。$k$常に真の合計と少なくとも任意の長さの範囲を返します。$k$常に反転した合計を返します。 最初から範囲を体系的に拡大し、応答がいつ変化するかを観察することで、境界の長さを把握します。$k$。 二分探索により、効率的に反転を引き起こす最小の長さが見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    def query(l, r):
        print(f"? {l} {r}")
        sys.stdout.flush()
        resp = int(input())
        if resp == -1:
            sys.exit(0)
        return resp

    # Find a position where the 1 is located
    pos = 1
    if query(1,1) == 1:
        pos = 1
    else:
        step = 1
        while step < n:
            resp = query(1, step)
            expected = 0  # sum in the range [1, step] if 1 not in range
            if step >= 2 and resp != expected:
                break
            step *= 2
        pos = step

    # Binary search for k
    low, high = 2, n
    while low < high:
        mid = (low + high) // 2
        resp = query(1, mid)
        expected = 0 if mid < pos else 1
        if mid >= 2 and resp != expected:
            high = mid
        else:
            low = mid + 1
    print(f"! {low}")
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```このソリューションでは、まず小さな範囲をクエリすることで 1 の候補位置を特定し、反転が発生したかどうかを確実に把握します。 次に、二分探索を適用して、反転が始まる最小範囲長を効率的に見つけます。これは正確に$k$。 主な微妙な点には、出力のフラッシュと、`-1`裁判官からの打ち切り。

## 特殊なケース
