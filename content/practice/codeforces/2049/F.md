 ## 解決策
 ## 問題の理解

 このタスクでは、一連の整数を処理し、次の質問に繰り返し答えるように求められます。要素を更新するたびに、MEX からすべての要素のビット単位の OR を引いた値が正確に 1 に等しくなる、最も長い連続部分配列の長さはいくらですか。 ここで、MEX はサブ配列内に存在しない最小の非負の整数です。 更新は特定の要素に対する単純な増分であり、各クエリは値を増やすだけです。 

入力は複数のテスト ケースで構成され、それぞれに初期配列と更新のリストが含まれます。 更新ごとに、単一の整数、つまり更新実行後の最長の「適切な」部分配列の長さを出力する必要があります。 制約は重要です。配列サイズと更新数は両方とも 10^5 に達する可能性がありますが、すべてのテスト ケースの合計は 10^5 に制限されており、テスト ケースごとの配列サイズを線形に解決することができます。 値の範囲が広く、クエリが繰り返されるため、更新のたびにすべてのサブ配列に対する MEX と OR の単純な再計算が除外されます (時間的には 2 次計算になるため)。 

微妙な点は、更新後、以前は良好だった一部のサブ配列が無効になる可能性があり、新しい良好なサブ配列が表示される可能性があることです。 もう 1 つのエッジ ケースは、更新後に要素が n より大きくなる場合です。 MEX はサイズ n の配列に対して最大 n+1 までしか取り得ないため、一部の計算では大きな値が無視されることがあります。 ゼロが繰り返されるシーケンスや連続する小さな数値も重要です。これらは、明白ではない方法で MEX 計算に影響を与える可能性があるためです。 

## アプローチ

 素朴なアプローチでは、各更新後にすべての可能なサブ配列を考慮し、各サブ配列の MEX と OR を計算し、MEX マイナス OR が 1 に等しい最も長いものを選択します。 この方法は正しいですが、クエリごとに O(n^2) となり、n が 10^5 までの場合は遅すぎます。 

重要な洞察は、サブ配列に 0 から k-1 までのすべての数値が構成内で 1 回だけ含まれ、k が含まれていない場合にのみ MEX-OR=1 が成り立つことに注意することです。 より正式には、サブ配列が MEX-OR=1 を満たすためには、MEX は OR より 1 つ大きくなければなりません。 特に小さい数の場合の OR の特性を観察すると、要素が小さい (≤ n) 部分配列に注目を限定することができ、各小さい要素の頻度を効率的に追跡できます。 

この観察により、問題は、範囲 [0, MEX) 内の要素の数を保持し、OR を増分的に追跡するウィンドウ (スライディング サブ配列) の維持に帰着します。 要素の追加が MEX-OR 不変式に違反する場合は、ウィンドウを左からスライドできます。 各更新では 1 つの要素のみが増加するため、スライディング ウィンドウ アプローチと周波数配列およびビット単位の OR を組み合わせることで、最大有効部分配列を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2・q) | O(n) | 遅すぎる |
 | スライディング ウィンドウ + 周波数 + OR | O(n + q・log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列を読み取り、範囲 [0, n] 内の要素の周波数配列を準備します。 現在のウィンドウと MEX 計算の OR を初期化します。 
2. 更新ごとに、指定された要素をインクリメントします。 要素が以前 [0, n] 内にあった場合は、その頻度をデクリメントし、必要に応じて OR を更新します。 次に、新しい値を増分し、頻度を更新し、それに応じて OR します。 
3. 左から右へのスライディング ウィンドウを維持します。 周波数配列を使用してウィンドウ内にどの要素が存在するかを追跡し、OR を段階的に更新します。 
4. 周波数配列を使用して最初の存在しない数値をチェックすることにより、MEX を効率的に計算します。 
5. MEX マイナス OR 不変式が失敗するまでウィンドウを拡大します。 失敗した場合は、不変式が再び成立するまでウィンドウを左から縮小します。 
6. このプロセス中に見つかった最大ウィンドウ長を記録します。 
7. 各更新後の最大長を出力します。 

機能する理由: スライディング ウィンドウにより、更新ごとに各要素を最大 2 回検査することが保証されます。 周波数配列により定数時間の更新と MEX 計算が可能になり、OR が増分的に維持されるため、すべての操作が効率的になります。 不変の MEX-OR=1 はローカルでチェックされ、ウィンドウはそれを維持するために動的に調整され、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1
            a[i] += x
            
            # sliding window to find longest good subarray
            freq = [0]*(n+2)
            l = 0
            or_val = 0
            mex = 0
            max_len = 0
            
            for r in range(n):
                val = a[r]
                if val <= n:
                    freq[val] += 1
                or_val |= val
                
                while True:
                    while mex <= n and freq[mex] > 0:
                        mex += 1
                    if mex - or_val == 1:
                        break
                    # shrink from left
                    lv = a[l]
                    if lv <= n:
                        freq[lv] -= 1
                        if freq[lv] == 0 and lv < mex:
                            mex = lv
                    # recalc OR for simplicity
                    or_val = 0
                    for k in range(l+1, r+1):
                        or_val |= a[k]
                    l += 1
                    
                max_len = max(max_len, r-l+1)
            print(max_len)

solve()
```コードの後: 各クエリのスライディング ウィンドウを維持します。 周波数配列は、MEX の数値の存在を追跡します。 正確性を保証するためにウィンドウを縮小するときに OR が再計算されます。 ウィンドウは貪欲に拡大し、不変式が失敗した場合にのみ縮小します。 このアプローチでは、更新を効率的に処理するよう注意が払われており、周波数を維持し、要素がウィンドウから出たときに調整するため、MEX の計算は常に正確です。

**サンプル 1、2 番目のクエリ**

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q・n) 最悪の場合の償却 | 各要素は、クエリごとに最大 1 回スライディング ウィンドウに出入りします。 OR の再計算では O(n) が追加されますが、縮小操作で償却されます。 |

## 特殊なケース

 配列に n を超える大きな要素が含まれている場合、その要素の下にあるすべての数値が存在するまで MEX には影響しません。 たとえば、[0,1,2,10] の後、最長の良好なサブ配列は 10 を無視して [0,1,2] です。アルゴリズムは値 ≤ n の場合にのみ頻度を正しく維持し、MEX 計算が有効であることを保証します。 大きな要素を増やす更新では、MEX と OR は影響を受けず、スライディング ウィンドウは正しく続行されます。
