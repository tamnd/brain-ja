 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、配列内の 1 つの要素から後の要素に 2 のべき乗を移動する演算を実行できます。 具体的には、要素が偶数の場合、それを 2 で割って、後の要素を 2 で乗算できます。 目標は、このような操作を任意の数適用した後に配列の合計を最大化することです。 ここでの工夫は、単一の配列に対してこれを計算するだけでなく、指定された配列のすべてのプレフィックス、つまり最初の要素、次に最初の 2 つの要素などを配列全体に至るまで計算する必要があることです。 各出力はモジュロである必要があります$10^9+7$。 

重要な制約は配列の長さであり、最大長は次のとおりです。$2 \cdot 10^5$単一のテスト ケースの場合、すべてのテスト ケースの長さの合計は最大で$2 \cdot 10^5$。 これは、最悪の場合の複雑さを持つアルゴリズムはすべて、$O(n^2)$遅すぎるでしょう。 線形または線形算術的なアプローチが必要です。 配列要素の値は次の値に達します$10^9$したがって、モジュラー演算を行わずに単純に演算を実装する場合は、整数オーバーフローに注意する必要があります。 

単純な間違いは、除算と乗算のために任意の偶数要素を選択して、各プレフィックスに対するすべての演算をシミュレートしようとすることです。 たとえば、プレフィックスの場合、$[2, 3]$不注意なアルゴリズムでは、2 を繰り返し分割して複数の中間配列を生成する可能性がありますが、最適な解決策は、すべての分割可能な要素を最大の要素に統合して合計を最大化することです。 これは、総当たりシミュレーションが非効率的であり、不必要であることを示しています。 

## アプローチ

 ブルート フォース アプローチでは、許可された操作のすべてのシーケンスが試行されます。 各操作により 1 つの要素が減少し、別の要素が増加し、組み合わせ爆発が起こります。 長さのプレフィックスの場合$k$、最大まであり得る$k^2$各ステップでの潜在的な操作。 たとえ$k \sim 10^5$、操作シーケンスの数が指数関数的に増加するため、これは手に負えません。 

重要な洞察は、各数値を奇数部分と 2 の累乗係数に分けることです。 任意の整数$x$次のように書くことができます$x = 2^p \cdot o$、 どこ$o$奇数です。 この操作により、2 のべき乗を前の要素から後の要素に移動できます。 したがって、最適な戦略は常に、2 の累乗をすべて、より小さな要素から最も乗算効果を吸収できる単一の要素に移動することです。 2 のべき乗による乗算は、最大の数値に適用すると合計に最大の影響を与えるため、(奇数部分を抽出した後) 最大の要素を累積されたすべての 2 の累乗の受信者として選択することが最適です。 

この観察により、問題は奇数部分の合計を追跡し、2 のべき乗を累積することに帰着します。 各プレフィックスについて、最大の奇数部分を持つ要素を特定し、それに乗算することができます。$2^{\text{total accumulated powers}}$。 合計は、すべての奇数部分とこの調整された最大の要素の合計になります。 これにより、問題は組み合わせシミュレーションからプレフィックスごとの線形時間計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$プレフィックスごと |$O(n)$| 遅すぎる |
 | 最適 |$O(n \log a_{\max})$|$O(1)$プレフィックスごと | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのアキュムレータを初期化します。1 つはこれまでに確認された要素の奇数部分の総和用で、もう 1 つはすべての要素から抽出された 2 の累乗の合計カウント用です。 最大の奇数部分を持つ要素のインデックスを維持します。 
2. 配列を要素ごとに繰り返します。 各要素について、次のように因数分解します。$x = 2^p \cdot o$、 どこ$o$奇妙であり、$p \ge 0$。 奇数部分の合計を増分します。$o$、累乗の合計数を増分します。$p$。 
3. これまでに確認された最大の奇数部分を追跡します。 これは 2 の累乗をすべて吸収する候補です。 現在の要素の奇数部分が以前の最大値を超えている場合は、候補インデックスを更新します。 
4. 現在のプレフィックスの最大合計を計算するには、奇数部分の合計から候補要素の元の奇数部分を削除します。 それを掛ける$2^{\text{total powers}}$、残りの奇数部分の合計を加算し直します。 モジュロを適用する$10^9+7$。 
5. この合計を現在のプレフィックスの結果に追加します。 
6. プレフィックスの各要素に対してこの手順を繰り返します。 新しいテスト ケースごとにアキュムレータをリセットします。 

機能する理由: すべてのステップで、利用可能なすべての 2 のべき乗を最大の基本値 (奇数部分) を持つ要素に統合することによって合計が最大化されます。 より小さい要素に再分配すると、乗算は数値が大きいほど効果的になるため、合計への寄与は小さくなります。 不変条件は、任意のプレフィックスを処理した後、この方法で計算された合計が、許可された一連の操作を通じて取得できる最大合計に等しいということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def process_case(a):
    prefix_sums = []
    max_odd = 0
    sum_odds = 0
    powers_total = 0
    candidate_odd = 0
    
    for x in a:
        p = 0
        while x % 2 == 0:
            x //= 2
            p += 1
        o = x
        sum_odds += o
        powers_total += p
        if o > candidate_odd:
            candidate_odd = o
        max_sum = (candidate_odd * pow(2, powers_total, MOD) - candidate_odd + sum_odds) % MOD
        prefix_sums.append(max_sum)
    
    return prefix_sums

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    result = process_case(a)
    print(*result)
```コードは、各数値を奇数部分と 2 の累乗成分に分解します。 奇数部分の合計と 2 の合計累乗を累積し、より大きな奇数部分が見つかった場合は候補要素を更新します。 現在のプレフィックスの最大合計は、2 のすべての累乗を最大の奇数部分に適用し、奇数部分の残りの合計を加算し、モジュロ演算を適用することによって計算されます。 これにより正確性が保証され、オーバーフローが回避されます。
