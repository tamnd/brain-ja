 ## 問題の理解

 次のような長方形のグリッドが与えられます。$n$行と$m$列。 各セルには 1 人の人物が含まれており、これらの人物には 1 から 2 までの番号が付けられます。$nm$行優先の順序です。つまり、番号付けは行内で左から右に進み、次の行に続きます。 

所定の位置に 1 人が配置されている$(r, c)$葉。 この削除により、元々より大きなラベルを持っていたすべての人は、番号付けの位置が 1 つ前に移動します。 言い換えれば、人のシーケンスはサイズのフラットな配列として扱われます。$nm$そしてそこから 1 つの要素を削除します。 インデックス 1 つ分左にシフトした後のすべて。 

このシフトの後、影響を受ける各人は、元のグリッド位置から前のラベルのグリッド位置に移動します。 移動したすべての人々が移動したマンハッタンの合計距離を計算するように求められます。 

ラベル空間内でのシフトであっても、移動は 2D 座標で測定されるため、グリッド構造は重要です。 インデックスを持つ人$j$元の位置に移動します$j-1$を計算し、結果として得られるすべてのマンハッタン距離を合計します。 

制約は大きく、最大で$10^4$テストケース、$n, m$それぞれ最大$10^6$。 これにより、すべてのシミュレーションが即座に除外されます。$nm$テスト ケースごとのセル。$10^{12}$最悪の場合、合計の操作が行われます。 テストごとにすべての位置をリニアスキャンすることさえ不可能です。 

重要なエッジ ケースは、削除されたセルが行優先の順序で最後のセルである場合です。$i = nm$。 その場合、誰も移動せず、答えは 0 です。もう 1 つの微妙な境界は、削除が最初のセルで発生するときです。この場合、他のすべての人がフラット化された順序で 1 位置ずつシフトします。 動きは最大限に構造化され、多くの行と列にまたがります。 

単純な間違いは、フラット配列でインデックスのシフトをシミュレートし、すべての要素の座標を再計算することです。 これは概念的には機能しますが、制約に対して遅すぎます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 グリッドを一定のサイズの配列に平坦化します$nm$、インデックスの要素を削除します$i$、その後のすべてをシフトし、移動されたすべての要素について古い座標と新しい座標を計算し、マンハッタン距離を合計します。 それぞれの座標変換は、$O(1)$、でも私たちはまだ触れています$O(nm)$テスト ケースごとに要素が増えるため、全体的に複雑になります。$O(nm)$クエリごとに。 最悪の場合の値では、これは完全に不可能になります。 

重要な観察は、動きのパターンが個人のアイデンティティではなく、平坦化された順序付けの相対的なシフトにのみ依存するということです。 各要素$j > i$以前に占められていた位置に移動します$j-1$したがって、2D グリッドに埋め込まれた 1D 配列のサフィックスを効果的にシフトすることになります。 したがって、各要素の動きは、マッピングがどのように行われるかによって決まります。$j \mapsto j-1$行と列の変更に変換されます。 

それぞれの動きをシミュレートするのではなく、構造ごとに動きを分類します。 インデックスの差をグリッド座標に変換する場合、ほとんどの移動はローカルです。同じ行内または境界で隣接する行にまたがります。 合計コストは、行全体の遷移が何回発生するか、および削除された位置の近くで部分的な行調整が何回発生するかをカウントすることで導き出すことができます。 

これにより、問題は、サフィックス要素がいくつ存在するか、およびそれらの行インデックスと列インデックスが集合的にどのように変化するかを計算することに軽減されます。 動きをインデックスの差の関数として表現すると、合計は行と列にわたる等差級数に分解されます。

 ## アルゴリズムのチュートリアル

 削除された位置に 1D インデックスとして番号を付けます。$$i = (r-1)m + c$$インデックス付きの要素のみ$j > i$移動すると、そのような各要素が所定の位置から移動します$j$位置を決める$j-1$。 

アイデアは、すべてを反復せずに、このシフトによって生じるマンハッタンの合計距離を計算することです。$j$。 

1. 影響を受ける要素の数を計算します。$$k = nm - i$$これらは、まさに削除された位置の後の要素です。 
2. 移動された各要素が、平坦化された配列内で 1 ステップ後方へのシフトに対応することを確認します。 そこで、連続するインデックスのグリッド位置を比較します。$j$そして$j-1$みんなのために$j > i$。 
3. インデックスの差をグリッド構造に変換します。 からの移動$j$に$j-1$変更:

 - 列の -1 の場合$j$列 1 にありません
 - 行は -1 単位、列は -1 単位$m-1$もし$j$列 1 にあります

 したがって、行間の境界遷移のみが垂直方向の動きに寄与します。 
4. サフィックスの行境界を何回越えたかを数えます。 これはまさにインデックスの数です$j$そのような$j \bmod m = 1$そして$j > i$。 

このような各交差は、行インデックスの垂直距離 1 と水平ラップの 1 に寄与します。$m-1$。 
5. 列内の他のすべての移動では、それぞれの水平距離が 1 になります。 
6. 以下を計算します。 

- 総シフト数 =$k$- 行境界のシフト = の倍数のカウント$m$接尾辞の構造
 - 残りのシフトは行内での移動です
 7. 行内ステップと行境界ステップからの寄与を合計します。 

### なぜ効果があるのか

 変革$j \to j-1$グリッド セルの線形順序に関する固定隣接関係を定義します。 マンハッタン距離は行軸と列軸に沿って分解され、グリッド番号付けにより、すべての変化が周期的に確実に行われます。$m$。 この周期性のため、すべての動きは、同じ行内に留まるか、行の境界を越えるという 2 つのカテゴリのいずれかに正確に属します。 これら 2 つのケースはすべての距離寄与を完全に特徴づけているため、合計コストを正確に再構築するには、それらの頻度をカウントするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, r, c = map(int, input().split())

        i = (r - 1) * m + c
        total = n * m

        k = total - i
        if k <= 0:
            print(0)
            continue

        full_steps = k

        first_after = i + 1

        def next_multiple(x):
            return (x + m - 1) // m * m

        first_row_end = (i // m + 1) * m
        if i % m == 0:
            first_row_end = i

        if first_after > total:
            cross = 0
        else:
            first_cross = ((first_after + m - 1) // m) * m + 1
            if first_cross > total:
                cross = 0
            else:
                last_cross = (total // m) * m + 1
                if last_cross < first_cross:
                    cross = 0
                else:
                    cross = ((last_cross - first_cross) // m) + 1

        within = k - cross

        ans = within + cross * m

        print(ans)

if __name__ == "__main__":
    solve()

そのカウントが計算されると、行内の各シフトはマンハッタンの距離に 1 を与え、各境界シフトはマンハッタンの距離に 1 を与えます。$m$垂直方向の動きに加えて水平方向の大きなラップが含まれるためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, r, c = map(int, input().split())
        i = (r - 1) * m + c
        total = n * m
        k = total - i
        if k <= 0:
            out.append("0")
            continue

        cross = 0
        first = i + 1
        last = total

        start = ((first + m - 1) // m) * m + 1
        if start <= last:
            cross = ((last - start) // m) + 1

        within = k - cross
        ans = within + cross * m
        out.append(str(ans))

    return "\n".join(out) + "\n"

 ## 特殊なケース

 削除された要素が行優先の順序で最後にある場合、サフィックスは空になり、要素は移動されません。 アルゴリズムはこれを次のように処理します。$k = nm - i = 0$、すぐに 0 を返します。 

最初のセルで削除が行われる場合、1 つおきの要素が移動し、サフィックスには最初のセルを除くすべてのインデックスが含まれます。 交差行数が最大になり、数式はすべての行境界を 1 回だけカウントし、反復を必要とせずに大きな構造化された合計を生成します。 

削除された要素が行境界にある場合、最初に影響を受けるシフトは次の行で直ちに開始され、内部の位置と比較して行間カウントが 1 つ増加します。 最初の交差インデックスの算術構造により、特別なケースを使用せずにこのシフトが正しくカウントされることが保証されます。
