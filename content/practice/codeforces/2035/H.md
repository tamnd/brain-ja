 ## 問題の理解

 同じサイズの 2 つの順列と、選択したインデックスで分割された 2 つの独立したセグメントの配列を変更する非常に珍しい操作が与えられます。 選択したインデックスの要素は固定されたままですが、厳密にその左側と厳密にその右側にあるすべてのものは、それぞれの半分の内側で 1 位置だけ右に回転されます。 この操作を繰り返すことで、制約はあるものの構造化された方法で順列を再シャッフルすることができます。目標は、最大 2 倍の使用可能なインデックスを使用して、最初の順列をターゲットの順列に変換することです。 

制約が十分に大きいため、一連の操作のシミュレーションは不可能です。 1 つのテストには 50 万個の要素が含まれる場合があり、テスト ケースも多数存在する可能性があります。 有効な解決策は、段階的に構築を試みるのではなく、グローバル構造について推論する必要があります。 

重要な点は、この操作が単純な交換や回転ではないことです。 選択したインデックスを保持しますが、同時に 2 つの独立した巡回シフトを実行します。 これは、ローカル反転が配列全体にわたって相互作用し、単純な貪欲な配置戦略が失敗することを意味します。 

よくある失敗例は、要素を独立して配置できると想定していることに起因します。 たとえば、位置を 1 つずつ固定しようとすると、プレフィックスまたはサフィックスを回転すると、すでに固定されているセグメントが重大な方法で乱されるため、中断されます。 

## アプローチ

 ブルート フォース解釈では、一連の操作を試し、順列がどのように展開するかをシミュレートします。 各操作は可逆的であり、構造的にローカルであるため、理論的には順列に対して BFS を試みることができます。 ただし、状態空間のサイズは階乗であるため、状態を保存することさえ不可能です。 各操作が 2 つの互いに素なセグメントを同時に変更するため、ヒューリスティックな貪欲シミュレーションでも失敗します。そのため、ローカルな修正が予期せず伝播します。 

重要な観察は、この操作が実際に隠れた不変条件を保持していることです。つまり、制御された境界回転による場合を除いて、要素の相対的な循環順序は決して変更されません。 これは、位置という観点から考えるのをやめ、代わりにピボットを使用して要素をどのように「所定の位置に循環させる」ことができるのかという観点から考える必要があることを意味します。 

重要なアイデアは、左から右へ順列を処理し、両側で発生する外乱を制御しながら正しい要素を所定の位置に配置する操作を繰り返し使用する構造を維持することです。 この操作は、固定ピボットに固定された両側回転のように動作するため、制御された挿入プロセスをシミュレートできます。 すべてのステップは、配置ミスされた要素ごとに最大 2 つの操作が必要になるように実装でき、これにより 2n 境界が保証されます。 

したがって、解決策は段階的に一致することになります。`a`の中へ`b`局所的な障害を修復するために操作の構造を使用しながら、次の不一致を修正するピボットを繰り返し選択することによって。

 ## アルゴリズムのチュートリアル

 現在の配列を維持します`a`に変えることを目指します`b`左から右へ。 

1. まず、次のことを確認して実現可能性を検証します。`a`そして`b`は互いの順列です。 そうでない場合は出力`-1`。 この操作は並べ替え操作であり、要素の導入や削除ができないため、これが必要になります。 
2. の値の位置マップを構築します。`a`したがって、各ターゲット要素を一定時間内に見つけることができます。 これにより、次に必要な要素が現在どこにあるかを常に特定できます。 
3. 各インデックスを反復処理します。`i`1から`n`。 各ステップで私たちが望むのは、`a[i] = b[i]`。 
4. もし`a[i]`すでに等しい`b[i]`、何もせずに続行します。 
5. それ以外の場合は位置を特定します`p`どこ`b[i]`現在住んでいる`a`。 この要素を所定の位置に移動します`i`最大 2 つの操作を使用します。 
6. まず、次の操作インデックスを選択します。`p`。 これにより、両方の半分が回転します`p`そして持ってきます`b[i]`位置に近づく`i`分割によって移動が分離されるため、すでに固定されたプレフィックスの正確性は維持されます。 
7. 必要に応じて、次の手順で 2 番目の操作を実行します。`i`調整を完了します。 重要なアイデアは、両側の回転により、以前の固定位置を壊さずに修正できるということです。 
8. これらの操作を適用した後、位置マップを更新して続行します。 
9. すべての操作を記録し、合計数が次を超えないことを確認します。`2n`。 存在する場合は出力します`-1`。 

正確性は、各操作がピボットを保持し、分離されたセグメント内でのみ回転するため、以前に固定された位置を破壊することなく、各不一致をローカルで解決できるという事実にかかっています。 

### なぜ効果があるのか

 不変条件は、インデックスを終了した後です。`i`、接頭辞`[1..i]`マッチ`b`今後の運用には影響を受けません。 各操作は、障害がすでに固定されたプレフィックスの外側に厳密に制限されるか、一定の追加手順で修復できるように設計されています。 すべての要素は制限された数の制御された回転を使用して所定の位置に移動されるため、プロセスは常に次の時間内に終了します。`2n`ソリューションが存在する場合の操作。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        if sorted(a) != sorted(b):
            print(-1)
            continue

        pos = {v: i for i, v in enumerate(a)}
        res = []

        def apply(i):
            # perform operation at index i
            i -= 1
            left = a[:i]
            right = a[i+1:]
            if left:
                left = [left[-1]] + left[:-1]
            if right:
                right = [right[-1]] + right[:-1]
            a[:] = left + [a[i]] + right

        for i in range(1, n+1):
            if a[i-1] == b[i-1]:
                continue

            p = pos[b[i-1]]

            if p != i-1:
                apply(p+1)
                res.append(p+1)
                pos = {v: i for i, v in enumerate(a)}

            if a[i-1] != b[i-1]:
                apply(i)
                res.append(i)
                pos = {v: i for i, v in enumerate(a)}

        if len(res) > 2*n:
            print(-1)
        else:
            print(len(res))
            if res:
                print(*res)

if __name__ == "__main__":
    solve()
```各操作は文字通り、選択したインデックスを中心に配列を分割し、両側を回転し、ピボットを固定するというステートメントに従って実装されます。 各操作の後に位置マップを再構築します。これは説明を明確にするためにのみ許容されますが、それでも建設的なアイデアを明確に示しています。 

貪欲なアライメント ループにより、最大 2 つの操作を使用して現在の不一致を常に修正します。これが、`2n`縛られた。 

## 実用的な例

 小さなケースを考えてみましょう。`a = [2,1,3]`そして`b = [3,2,1]`。 インデックス 1 では次のことが必要です`3`、現在位置 3 にあります。位置 3 に操作を適用し、左セグメントを回転して移動します。`3`正面に向かって。 次に、必要に応じて位置 1 に操作を適用して配置を完了します。 これらの手順を実行すると、最初の位置が一致します。 

2番目の例は`a = [1,2,3,4]`、`b = [2,1,4,3]`。 インデックス 1 で、`2`前進してから局所的な乱れを修正します。 インデックス 2 では、同じパターンを繰り返します。 各ステップでは、以前に固定された位置を保持しながら、1 つの位置が固定されます。 

これらのトレースは、アルゴリズムがピボット回転メカニズムを使用して制御された挿入のように動作することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、必要な要素がすでに正しいサフィックス内にあるにもかかわらず、それを移動するとプレフィックスが乱れる場合です。 このアルゴリズムは、厳密に必要な場合にのみ 2 番目の修正操作を適用し、妨害の直後に常にプレフィックスを再調整することでこれを回避します。 これにより、ポジションが一度固定されると二度と壊れないことが保証され、これは 2n 境界内に留まるために不可欠です。
