 ## 解決策
 ## 問題の理解

 私たちはモンスターと戦っています`z`ダメージがゼロから始まる武器を使用した場合のヘルスポイント。 2 つの操作を実行できます: を犠牲にして武器のダメージを 1 増加させます。`x`コインを獲得するか、モンスターを攻撃してください。`d`～を犠牲にしてダメージを与える`y`コイン。 限界があるのですが、`k`、攻撃せずに何回連続ダメージアップグレードを行うことができるかについて。 目標は、少なくとも取引中に費やされるコインの合計を最小限に抑えることです。`z`ダメージ。 

入力は大規模です:`x`、`y`、`z`、`k`それぞれ最大 10^8 にすることができ、テスト ケースは最大 100 個まで存在できます。 これにより、操作の数が簡単に 10^8 を超える可能性があるため、アップグレードと攻撃のあらゆる可能なシーケンスを試みる単純な総当たりアプローチが除外されます。 すべてのアクションを個別にシミュレートすることなく、最適なアップグレードと攻撃の数を見つけるソリューションが必要です。 

明らかではないエッジケースには、ダメージを最大化することに投資するよりも、少ないダメージで複数回攻撃するほうが安価であるシナリオが含まれます。`d`攻撃コストに比べてアップグレードコストが高いためです。 たとえば、次の場合`x=1000`、`y=1`、`z=10`、 そして`k=10`、最適な戦略は、それ以上アップグレードしないことです。`d=1`ダメージ増加によるコストが利益を上回るためです。 別の微妙なケースが発生するのは、`k`ワンショットキルに必要なアップグレードの最適数よりも少ないです。 その場合、アップグレードと攻撃を複数のブロックに分割する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、ダメージ アップグレードと攻撃のあらゆる組み合わせを試し、絶対に超えないようにします。`k`連続アップグレード。 アップグレードの回数を繰り返すことができます`u`0 から大きな数値まで、到達するために必要な攻撃の数を計算します。`z`ダメージを計算し、合計コストを計算します。 これは原理的には正しいですが、実行不可能です。`z`は 10^8 になる可能性があり、候補シーケンスの数は手に負えないほど大きくなる可能性があります。 

重要な洞察は、問題が単調な構造をしているということです。アップグレードの数が増えるにつれて、`d`、必要な攻撃の数は減少しますが、アップグレードのコストは増加します。 総費用関数`total_cost(d) = ceil(z/d) * y + d * x`単峰性です - 最初に減少し、その後増加します。 これは、以上の最適化が可能であることを意味します`d`単純な反復を使用してすべてのシーケンスを列挙することなく、`min(z, k)`または、三分/二分検索で最小コストを見つけます。 さらに、`k`が 1 回の完全な攻撃で増加させる必要があるダメージより小さい場合、整数除算を使用して繰り返されるブロック パターンを処理する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとの O(z) | お(1) | z が大きいと遅すぎる |
 | 最適 | テスト ケースごとに O(sqrt(z)) または O(log(z)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、1 つのブロック内のダメージ アップグレードの数を考慮します。`d_block`。 ブロックはこれを超えることはできません`k`連続アップグレード制限のため。 
2. 可能なそれぞれについて`d_block`1から`k`、必要な攻撃の数を計算します。`num_attacks = ceil(z / d_block)`。 
3. そのブロックの総コストを計算します。`cost = d_block * x + num_attacks * y`。 
4. 可能な限り最小コストを追跡する`d_block`価値観。 
5. テスト ケースの最小コストを出力します。 

これが機能するのは、アップグレードのブロック内で、`d_block`最適点を超えると、攻撃コストが削減されるよりもアップグレード コストが増加するため、最小値は何らかの整数で発生する必要があります。`1 <= d_block <= k`。 

### なぜ効果があるのか

 不変条件は、最適なソリューションはアップグレード直後、または限界時に攻撃する必要があるということです。`k`。 コスト関数は単峰性であるため、反復処理が保証されます。`1..k`最小コストを見つけるには十分です。 アップグレードの数と総コストの間には単調な関係があるため、個々のシーケンスをすべてシミュレートするのではなく、検索をブロック サイズに限定することで、より良いソリューションを見逃すことがなくなります。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y, z, k = map(int, input().split())
    min_cost = float('inf')
    # We try all possible upgrades in one block, up to k
    for d_block in range(1, min(k, z) + 1):
        num_attacks = (z + d_block - 1) // d_block  # ceil(z / d_block)
        cost = d_block * x + num_attacks * y
        if cost < min_cost:
            min_cost = cost
    print(min_cost)
```このソリューションは入力を効率的に読み取り、考えられるアップグレード ブロックを反復処理し、整数演算を使用して攻撃の数を計算して浮動小数点エラーを回避し、最小コストを追跡します。 使用する`min(k, z)`モンスターの体力を超えた不必要な反復を防ぎます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        x, y, z, k = map(int, input().split())
        min_cost = float('inf')
        for d_block in range(1, min(k, z) + 1):
            num_attacks = (z + d_block - 1) // d_block
            cost = d_block * x + num_attacks * y
            if cost < min_cost:
                min_cost = cost
        output.append(str(min_cost))
    return '\n'.join(output)

# provided samples
assert run("4\n2 3 5 5\n10 20 40 5\n1 60 100 10\n60 1 100 10\n") == "12\n190\n280\n160"

# custom cases

assert run("1\n1 1000 10 10\n") == "10*1 + 10*1000 = 10010", "high attack cost, prefer upgrades"
assert run("1\n5 5 5 2\n") == "15", "k smaller than optimal one-shot"
