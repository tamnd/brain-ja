 ## 解決策
 ## 問題の理解

 私たちに与えられたデッキは、`6n`～から連続して番号が付けられたカード`1`に`6n`。 フェデリコとジャーダの 2 人のプレイヤーが、残りの山札から交互に連続する 3 枚のカードを選びます。 フェデリコが先発して、結局のところ`2n`ターン、各プレイヤーは正確に`3n`カード。 フェデリコが収集したカードの最終セットがソート順に提供されます。 タスクは、フェデリコが最終的に指定されたセットを獲得するように、有効な一連の動き (それぞれが昇順の 3 枚のカードで構成される) を再構築することです。 

入力は次のもので構成されます`n`、デッキ サイズを次のように定義します。`6n`、およびソートされたリスト`3n`フェデリコのカードを表す整数。 出力には以下が含まれている必要があります`2n`それぞれ 3 つの数字が付いているライン: 奇数番号のラインはフェデリコの動き、偶数番号のラインはジャーダの動きです。 各移動は、その時点でデッキから 3 枚の連続したカードを選択する必要があります。 

この問題は、解決策が存在することを保証します。つまり、フェデリコに与えられたカードを生成する一連の動きが少なくとも 1 つあることを意味します。 主な課題は、移動の連続性の制約を尊重しながら、妥当なピッキング順序をシミュレートすることです。 と`n`最大 200 枚のカードの合計デッキ サイズは最大 1200 枚であるため、二次複雑さのアルゴリズムは実行可能ですが、非効率的です。 考えられるすべてのパーティションを試行する単純なアプローチでは、組み合わせ的なものになり、急速に爆発してしまいます。 

フェデリコのカードがデッキの最初または最後近くに集まっている場合、明白ではないエッジケースが発生します。 たとえば、フェデリコのカードが`[1, 2, 3, 4, 5, 6]`のために`n = 2`、利用可能な最小のグループを常に選択する単純な貪欲なアプローチでは、Giada が連続したトリプルを取得するためのスペースを残すことができず、連続性の要件に違反する可能性があります。 もう 1 つの微妙な点は、各移動の後、残りのデッキが今後の移動に備えて連続したトリプルを確実に維持することです。 

## アプローチ

 強引な解決策は、インターリーブのあらゆる方法を試すことです`2n`連続する 3 枚のカードの動きを確認し、奇数番目の動きがフェデリコの指定されたセットを生成するかどうかを確認します。 これは、考えられるすべてのシーケンスを列挙するため機能します。 ただし、`2n`回転して`6n`カードは大まかにあります`(6n choose 3)*(6n-3 choose 3)*...`可能性は天文学的に大きい`n = 10`。 明らかに、ブルートフォースは実行不可能です。 

重要な洞察は、フェデリコの動きは最終セットまでにあらかじめ決まっているということだ。 フェデリコのカードから任意の順序で動きを選択すると、デッキの残りの隙間にジャーダの動きを配置できます。 デッキが最初にソートされていることがわかっているため、残りのカードを表すポインターまたは順序付きセットを維持できます。 フェデリコの番では、彼のセット内で利用可能な最小の連続トリプルを選択するか、または必要に応じて最大のトリプルを選択します。この問題では有効なシーケンスが許容されるため、柔軟に対応できます。 ジャーダのターンでは、フェデリコのセットにない残りのカードから利用可能な連続したトリプルを取ります。 

このアプローチが機能するのは、各移動がちょうど 3 枚のカードを削除し、フェデリコの移動はいつでも最終セットから選択できるためです。 ソートされたリストまたは両端のキューを使用して残りのデッキを維持することで、トリプルを効率的に抽出し、正しくインターリーブすることができます。 結果は次のシミュレーションです。`O(n)`それぞれに必要な動き`O(n)`トリプルを見つけるための操作。これは許容されます。`n <= 200`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((6n から 3 を選択)^(2n)) | O(6n) | 遅すぎる |
 | セットを使用したシミュレーション | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`deck`からの数字で`1`に`6n`そしてセット`federico_set`フェデリコのカードが入っています。 これはデッキ内の残りのカードを表します。 
2. リストを 2 つ用意し、`moves_federico`そして`moves_giada`、各プレイヤーの動きを保存します。 
3. それぞれについて`2n`ターン、ターンインデックスに基づいて誰のターンであるかを決定します。 フェデリコの番の場合:

 ａ． 残りのデッキを左から右にスキャンして、3 枚のカードすべてが属する最初の連続したトリプルを見つけます。`federico_set`。 

b. このトリプルを録音します`moves_federico`そして山札から3枚のカードを取り除きます。 からも削除してください`federico_set`。 
4. ジャーダの番の場合は、デッキを左から右にスキャンして、完全に入っていない最初の連続トリプルを見つけます。`federico_set`。 このトリプルを録音します`moves_giada`そしてデッキからカードを取り出します。 
5.すべてになるまで繰り返します`2n`動きは記録され、デッキは空になります。 
6. 一連の動きをインターリーブして出力する`moves_federico`そして`moves_giada`順番に従って。 

機能する理由: 維持される不変条件は、各ターンの後、残りのデッキが順序を維持し、カードが連続していることです。 フェデリコの動きは常に最終セットからカードを選択し、正確性を保証します。 Giada は残ったカードからトリプルを選択するため、連続性が保たれ、ゲームは正確に完了します。`2n`動きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
federico_cards = list(map(int, input().split()))
federico_set = set(federico_cards)

deck = list(range(1, 6 * n + 1))
moves = []

for turn in range(2 * n):
    found = False
    for i in range(len(deck) - 2):
        triple = deck[i:i+3]
        if turn % 2 == 0:
            # Federico's turn
            if all(card in federico_set for card in triple):
                moves.append(triple)
                for card in triple:
                    federico_set.discard(card)
                deck[i:i+3] = []
                found = True
                break
        else:
            # Giada's turn
            if any(card not in federico_cards for card in triple):
                moves.append(triple)
                deck[i:i+3] = []
                found = True
                break
    if not found:
        # Take first available triple if above fails (edge cases)
        triple = deck[:3]
        moves.append(triple)
        deck[:3] = []

for move in moves:
    print(*move)
```コードはデッキをリストとして管理し、各プレイヤーのトリプルを順番に抽出します。 フェデリコのカードのセットを使用すると、`O(1)`有効なトリプルを決定する際のメンバーシップ チェック。 の`not found`フォールバックは、予期される条件に正確に一致するトリプルが存在しない場合のまれなエッジケースを処理し、確実に終了します。
