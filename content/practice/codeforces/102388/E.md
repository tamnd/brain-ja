 ## 解決策
 ## 問題の理解

 最大 50 都市を含む無向グラフがあります。 道路を使用すると、馬は 2 つの終点間を 1 ステップで移動できます。また、道路は自己ループになる場合もあります。 固定都市 v の場合、v から始まり、正確に k 個の道路を使用し、v で終わるウォークが存在するかどうかを判断する必要があります。答えは、そのような閉じたウォークが存在する都市の数です。 

入力には最大 20 個の独立したグラフが含まれます。 グラフは頂点の点では小さく、n≤50 ですが、k は 10 9 まで大きくなる可能性があります。この組み合わせが重要な難しさです。 1 日に 1 つの操作を実行するアルゴリズムや、ステップごとに 1 つのグラフ走査を実行するアルゴリズムは、10 億ステップに耐えることはできません。 一方、n=50 は十分小さいので、k のビットごとにおよそ n 2 の作業を伴うアルゴリズムを実行できます。 10 9 には 2 進数が約 30 個しかないため、対数べき乗は自然な目標になります。 

実装を簡単に破壊する可能性のあるいくつかの特殊なケースがあります。 k=0 の場合、空のウォークは既に同じ都市で開始および終了するため、すべての都市が適格となります。 例えば、```
13 0 0
```出力があります```
3
```少なくとも 1 つの道路を必要とするソリューションでは、誤ってゼロが返されます。 

自己ループは、k=1 の場合に特に重要です。 のために```
12 1 10 0
```答えは`1`というのは、都市 0 は一度自己ループを実行して自分自身に戻ることができるのに対し、都市 1 は孤立しているからです。 対角要素を保持せずにグラフを単純なグラフとして扱うソリューションでは、都市 0 が欠落します。 

平行する道路には特別な処理は必要ありません。 2 本の道路が同じ都市のペアを接続している場合、それらは散歩の存在に追加の可能性を提供しません。 少なくとも 1 つの遷移が存在するかどうかのみを考慮します。 例えば、```
12 3 20 10 10 1
```出力があります`2`。 どちらの都市も他の都市に行ってすぐに戻ることができます。 

最後に、パリティは欺瞞的なものになる可能性があります。 2 部グラフでは、すべての閉じたウォークの長さは偶数ですが、奇数サイクルの存在により状況が変化します。 例えば、```
13 3 30 11 22 0
```出力があります`3`, すべての都市が三角形の上にあるためです。 グラフの二部性のみを使用して問題を解決しようとすると、奇数サイクルに接続された頂点などの特殊なケース (十分に長い奇数の閉じたウォークが存在する可能性があるが、短いものは存在しない可能性がある) も見逃されます。 マトリックスの定式化により、これらすべてのケースを手動で特徴付ける必要がなくなります。 

## アプローチ

 最も直接的なアプローチは、各ステップの後に可能な位置をシミュレートすることです。 開始都市 s を固定し、正確に t ステップ後に到達可能な都市のセットを維持し、グラフを通じてそのセットを繰り返し拡張します。 k ラウンド後、s に到達可能かどうかを確認します。 これは正しいです。ラウンド t 後のセットは、s から始まる長さ t の歩​​行の終点を正確に表すからです。 

問題はKさんです。 最悪の場合、1 ラウンドですべての道路を検査する可能性があるため、1 つの開始都市を処理するには O(km) かかります。 n 個の開始都市すべてに対してこれを繰り返すと、O(knm) が得られます。 最大の制約では、これはおおよそ次のとおりです

 10 9 ⋅50⋅2500=1.25×10 14

 制限時間を大幅に超える路上試験。 

グラフは、段階的なシミュレーションを行列のべき乗に置き換えるのに十分なほど小さいです。 ブール隣接行列 A を定義します。ここで、A[i][j] は、道路が i から j への移動を許可する場合に正確に true になります。 ブール行列乗算では、エントリ (A t )[i][j] は、i から j まで正確に t ステップのウォークが存在するかどうかを示します。 したがって、都市 i は、対角要素 (A k )[i][i] が true の場合にのみ有効になります。 

2 進累乗により、行列の乗算の数が k から O(logk) に減ります。 従来の行列の乗算では O(n 3 ) のコストがかかり、n=50 の場合にはすでに妥当な値ですが、Python では行列の各行を単一の整数ビットセットとして表すことで、さらに優れた処理を行うことができます。 行には到達可能な頂点のセットがビットとして含まれ、2 つのブール行列の乗算は一連のビット単位の OR 演算になります。 

左行列の行 i の場合、設定されたすべてのビット j は、i が j に到達できることを意味します。 右行列の対応する行 B[j] には、j から到達可能なすべての頂点が含まれます。 したがって、結果として得られる行は、行 i のすべての設定ビット j に対する B[j] の単純な OR です。 これにより、実際の乗算は O(n 2 ) 行の演算に削減され、各演算では Python の高度に最適化された任意精度の整数が使用されます。 

この総当たり法は、一度に 1 歩ずつ歩くことを明示的に追跡するため機能しますが、k が巨大であるため失敗します。 k のバイナリ表現のみが重要であるという観察により、一度に指数関数的に多くのステップを通過できるようになります。

 ## アルゴリズムのチュートリアル

 1. すべての都市のビットセットとして隣接関係を構築します。 行 i のビット j は、i と j の間に道路が存在する場合に設定されます。 グラフは無向であるため、入力エッジ (x,y) は x→y と y→x の両方を設定します。 自己ループの場合、これにより自然に対角ビットが設定されます。 
2. 単位行列をビットセットとして表します。 単位行列は同じ都市にある長さ 0 の歩行を表すため、その行 i にはビット i のみが含まれます。 
3. 2 つのブール行列を維持します。`result`そして`base`。 当初は、`result`は恒等行列であり、`base`は隣接行列です。 不変条件とは、`result`は、k の処理済みビットからすでに選択されている元の隣接行列のべき乗の積を表します。`base`は電流電力 A 2 p を表します。 
4. k のバイナリ表現を最下位ビットから検査します。 現在のビットが 1 の場合、乗算します`result`による`base`。 これは、対応するパワー A 2 p を答えに組み込みます。 
5. スクエア`base`次の 2 の累乗を求めます。 ここでは、ウォークがいくつ存在するかではなく、少なくとも 1 つのウォークが存在するかどうかを考慮するため、ブール行列の乗算が使用されます。 
6. k を 1 ビット右にシフトし、すべてのビットが処理されるまで続けます。 k≤10 9 であるため、最大 30 ビットが必要です。 
7. べき乗後、次の対角線を調べます。`result`。 ビット i が行 i に設定されている場合、都市 i から都市 i に戻るにはちょうど k ステップの歩行が必要になります。 そのような都市をすべて数えてください。 

### なぜ効果があるのか

 中心的な不変条件は、k のバイナリ表現のプレフィックスを処理した後、`result`は、処理された 1 ビットに対応するべき乗のブール積に等しくなります。 ブール行列の乗算はウォークの存在を構成するため、長さ t のウォークが i と j を接続する場合、A t [i][j] は正確に true になります。 二進累乗は最終的に A k を構築するため、その対角線には長さ k の閉じた歩行を許可する都市が正確に含まれます。 ビットセットの実装は、ブール乗算の計算方法のみを変更し、それが表す数学的結果は変更しません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def multiply(A, B, n):    """    Boolean matrix multiplication.
    Each row is a bitset. For every set bit j in A[i],    row B[j] contributes all vertices reachable after the    second part of the walk.    """    C = [0] * n
    for i in range(n):        mask = A[i]        row = 0
        while mask:            bit = mask & -mask            j = bit.bit_length() - 1            row |= B[j]            mask ^= bit
        C[i] = row
    return C

def solve():    T = int(input())    answers = []
    for _ in range(T):        n, m, k = map(int, input().split())
        adj = [0] * n
        for _ in range(m):            x, y = map(int, input().split())            adj[x] |= 1 << y            adj[y] |= 1 << x
        # A^0 = I.        result = [1 << i for i in range(n)]
        # A^(2^p), starting with A^1.        base = adj
        while k:            if k & 1:                result = multiply(result, base, n)
            k >>= 1
            if k:                base = multiply(base, base, n)
        answer = 0        for i in range(n):            if result[i] & (1 << i):                answer += 1
        answers.append(str(answer))
    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":    solve()
```隣接構築では都市ごとに 1 つの整数を使用します。 少し`j`都市を表す`j`ので、設定`1 << j`その都市への遷移の存在を記録します。 両方の方向を設定すると方向のない道路が処理され、平行エッジに対して同じ操作を 2 回実行しても効果はありません。これはまさに私たちが望んでいることです。`result = [1 << i for i in range(n)]`単位行列を作成します。 A 0 =I であり、恒等式の対角線にはすべての都市が含まれるため、k=0 の場合でもこれが必要です。 の`while k`したがって、loop は特別な分岐を行わずに k=0 を処理します。 

乗算ルーチンは最も注目に値します。 ビット j が設定されているとします。`A[i]`。 つまり、i から j までの最初のステップのセグメントが存在します。 すべてのビットが設定されています`B[j]`は、j からある宛先までの 2 番目のセグメントを表します。 そのようなすべてに対して OR を実行する`B[j]`したがって、連結されたウォークを通じて到達可能な目的地を正確に示します。 

表現`mask & -mask`設定された最下位ビットを抽出します。`bit.bit_length() - 1`そのビットを頂点インデックスに変換します。 で削除すると、`mask ^= bit`到達可能なすべての中間頂点が 1 回処理されることが保証されます。 

整数オーバーフローの問題はありません。 Python の整数は自動的に増加し、最大のビットセットには意味のあるビットが 50 個しかありません。 k の値も Python 整数として直接処理されるため、10 9 の境界には特別な算術演算は必要ありません。 

べき乗ループ内の演算の順序も意図的です。 k の現在のビットが 1 の場合、現在の電力を次のように乗算する必要があります。`result`。 その後、現在の累乗を二乗して次の 2 進数を準備します。 の`if k`ガードは不必要な最後のスクエアリングを 1 回回避します。
