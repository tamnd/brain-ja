 ## 解決策
 ## 問題の理解

 最大 50 の都市と最大 2500 の道路を含む無向グラフがあります。 道路は 2 つの異なる都市を接続したり、都市とそれ自体を接続したりできるため、ループが許可されます。 ある都市から出発して、正確に (k) 本の道路をたどって、同じ都市で終了しなければなりません。 このような長さちょうど (k) の閉じた歩道が存在する場合、都市は有効です。 

タスクは、有効な開始都市をすべて個別にカウントすることです。 都市が異なれば、まったく異なる散歩道を使用することもでき、散歩では都市と道路の両方を繰り返すことができます。 

(n) の小さな値が主な手がかりです。 頂点が 50 個しかない場合、コンパイル言語では (O(n^3)) または (O(n^3 \log k)) メソッドが妥当ですが、値が大きい (k \le 10^9) ため、毎日直接処理するものは除外されます。 (k) に比例する仕事をすることを避ける必要があります。 道路の数が最大 2500 であるという事実は、グラフの走査と小規模な動的プログラムが低コストであることも意味します。 

パリティのみに基づいてソリューションを欺瞞できるエッジケースがいくつかあります。 

まず、(k=0) は馬が動かないことを意味するため、すべての都市はすでに元の状態に戻っています。 例えば、```
1
1 0 0
```出力があります```
1
```少なくとも 1 つの道路横断を必要とするソリューションでは、誤ってゼロが返されます。 

第 2 に、孤立した頂点は正の長さのウォークを行うことができません。 例えば、```
1
2 0 2
```出力があります```
0
```どちらの都市にも道路がないため、2 が偶数であっても、通常の「すべての正の偶数の長さが機能する」という議論は当てはまりません。 

3 番目に、ループは長さ 1 の閉じたウォークを作成します。 例えば、```
1
1 1 1
0 0
```出力があります```
1
```グラフを単純なグラフとして扱い、ループを無視する二部チェックでは、このコンポーネントが誤って二部として分類されてしまいます。 

第 4 に、非 2 部構成要素であることだけでは、小さな奇数 (k) には十分ではありません。 考慮する```
1
3 3 1
0 1
1 2
2 0
```三角形は非 2 部構成ですが、ループがないため 1 ステップのクローズド ウォークはありません。 正しい出力は次のとおりです```
0
```これが、アルゴリズムが最終パリティ プロパティを使用する前に小さい (k) を正確に処理する理由です。 

## アプローチ

 直接的なアプローチは、動的プログラミングによって歩行をシミュレートすることです。 開始都市ごとに、正確に (t) ステップ後に到達可能な都市のセットを維持します。 最初は (s) のみが到達可能です。 ステップごとに、現在到達可能なすべての都市から発生するすべての道路をたどります。 (k) のステップの後、(s) 自体が到達可能かどうかを確認します。 

(t) ステップ後の状態には、長さ (t) のすべての歩行の可能な終点が正確に含まれているため、これは正しいです。 問題は(k)の値です。 最悪の場合、動的プログラムは開始都市ごとに実行されると、(O(k n m)) 個の隣接処理を実行します。 (k=10^9)、(n=50)、(m=2500) の場合、これは (1.25 \cdot 10^{14}) 個のグラフ遷移になります。 (k) が大きいため、これは不可能です。 

重要な観察は、無向グラフにはクローズドウォークの非常に単純な長期パターンがあるということです。 すべての正の偶数の長さは、すべての非分離頂点で可能です。これは、任意の入射エッジをトラバースし、すぐにそれをトラバースして戻すことができるためです。 この 2 段階の歩行を繰り返すと、すべての正の偶数の長さが得られます。 

奇数の長さの場合は動作が異なります。 連結成分は、奇数のサイクルが含まれていない場合、正確に 2 部になります。 2 部コンポーネントでは、すべての閉じたウォークの長さが偶数であるため、(k) の奇数は機能しません。 非二部構成要素では、すべての頂点は最終的に両方のパリティの閉じたウォークを持ちます。 より具体的には、すべての頂点には最大 (2n-1) の長さの奇数の閉じたウォークがあります。 奇数の閉じたウォークが 1 つ存在すると、任意の数の 2 ステップ バックトラックを追加できるため、十分に大きな奇数の長さもすべて存在します。 

これにより、きれいな分割が得られます。 (k) が最大 (2n) の場合、小さなビットセットの動的プログラムを使用して単純に正確に答えを計算します。 (k) が (2n) より大きい場合、正確なウォーク構造は必要なくなります。 偶数 (k) の場合、分離されていないすべての頂点が機能します。 奇数 (k) の場合、非 2 部コンポーネントに属する頂点が正確に機能します。 

ビットセット表現により、正確な部分が特に安価になります。 到達可能な都市のセットは 1 つの Python 整数で表され、都市 (j) が到達可能な場合はビット (j) が設定されます。 一歩進めるために、到達可能な都市 (v) ごとに、その隣接ビットセットの OR を新しい到達可能なセットに演算します。 (n\le50) なので、これらはすべて、いくつかのマシンサイズの Python 整数内に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての (k) ステップのブルート フォース DP | (O(k n m)) | (O(n^2)) | 遅すぎる |
 | (2n) までの正確なビットセット DP、その後パリティ/コンポーネント分析 | (O(n^2 \min(k,n) + n+m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストと隣接ビットセットの両方を作成します。 隣接リストは、接続されたコンポーネントと二部構成を決定するために使用されます。 ビットセットを使用すると、正確な動的プログラムで、高速な整数 OR 演算を使用して、考えられるすべてのエンドポイントを更新できます。 
2. (k=0) の場合、(n) を返します。 空の散歩は、グラフに関係なく、同じ都市で始まり、同じ都市で終わります。 
3. (k\le2n) の場合、答えを正確に計算します。 各都市 (i) について、最初の到達可能なセットはちょうど ({i}) であり、整数 (1\ll i) で表されます。 1 つのステップの後、現在到達可能なすべての都市の隣接セットの和集合によって到達可能なセットを置き換えます。 これを正確に (k) 回繰り返します。

(t) 回目の反復の後、元の都市 (i) から都市 (j) までの長さ (t) の歩行が存在するときに、位置 (j) のビットが正確に設定されます。 したがって、(k) 回の反復後の対角ビットは、どの都市に長さ (k) の閉じた歩道があるかを正確に示します。 
4. (k>2n) の場合、各頂点に 2 値カラーを割り当てながら、すべての連結コンポーネントに対して BFS または DFS を実行します。 2 部グラフでは、すべての通常のエッジに沿って、その端点が反対の色を持つ必要があります。 エッジが同じ色の 2 つの頂点を結合する場合、コンポーネントには奇数のサイクルが含まれており、2 部構成ではありません。 ループの 2 つの端点が同じ頂点であるため、ループではすぐにこのような競合が発生します。 
5. 大きい偶数 (k) の場合、次数が正であるすべての頂点をカウントします。 このような頂点から 1 つの入射エッジを選択し、それを前後にトラバースします。 この 2 段階の歩行を繰り返すと、正の偶数の長さが得られます。 
6. 大きな奇数 (k) の場合、そのコンポーネントが 2 部構成でないことが判明したすべての頂点をカウントします。 非 2 部構成要素には奇数サイクルが含まれます。 任意の頂点からそのサイクルまで歩き、サイクルを 1 回横断し、同じパスに沿って戻ります。 これにより、奇妙なクローズドウォークが得られます。 この構造の長さは最大 (2n-1) であり、(k>2n) であるため、(k) とその奇数の長さの差は正の偶数になります。 2 段階の後戻りを繰り返すことで、その差を埋めることができます。 

### なぜ効果があるのか

 正確な部分に関しては、(t) 回の反復の後、不変条件は次のようになります。`reach[i]`正確に (t) 個のエッジのウォークによって (i) から到達可能な頂点が正確に含まれます。 更新は、現在到達可能なすべての頂点を取得し、もう 1 つのエッジをたどるため、可能なウォークを見逃すことも、不可能なエンドポイントが導入されることもありません。 したがって、(k) 回の反復後のビット (i) は、(i) で長さ (k) の閉じたウォークがある場合に正確に設定されます。 

大きい (k) 場合は、最初に偶数の長さを検討します。 孤立していない頂点には、入射エッジを両方向に横断することによって得られる 2 エッジの閉じたウォークがあります。 これを繰り返すと、すべての正の偶数の長さが得られます。 孤立した頂点には正のウォークがまったくありません。 

奇数の長さの場合、エッジごとに二部の側が変更されるため、二部コンポーネントに奇数の閉じたウォークを含めることはできません。そのため、奇数のエッジの後はウォークが反対側になければなりません。 非 2 部構成要素には奇数サイクルが含まれます。 頂点 (v) については、(v) からそのサイクルまでの長さ (d) の最短経路をとり、奇数サイクルの長さを (l) とします。 パスとサイクルは、(d+l\le n) のように、終点でのみ交わるように選択できます。 結果として得られる閉じたウォークの長さは (2d+l) で、最大でも (d+n\le2n-1) になります。 任意の数の 2 エッジ バックトラックを追加すると、より大きな奇数の長さが得られます。 アルゴリズムは (k>2n) の場合にのみこの引数を使用するため、必要な大きな奇数長には常に到達可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, k, edges):
    graph = [[] for _ in range(n)]
    adj_bits = [0] * n
    degree = [0] * n

    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)

        adj_bits[u] |= 1 << v
        adj_bits[v] |= 1 << u

        degree[u] += 1
        degree[v] += 1

    if k == 0:
        return n

    # Small k: compute the exact set of endpoints after k steps.
    if k <= 2 * n:
        reach = [1 << i for i in range(n)]

        for _ in range(k):
            new_reach = [0] * n

            for start in range(n):
                bits = reach[start]
                result = 0

                while bits:
                    low = bits & -bits
                    v = low.bit_length() - 1
                    result |= adj_bits[v]
                    bits -= low

                new_reach[start] = result

            reach = new_reach

        answer = 0
        for i in range(n):
            if (reach[i] >> i) & 1:
                answer += 1

        return answer

    # Large k: only the parity structure of each component matters.
    color = [-1] * n
    component = [-1] * n
    component_bad = []

    for start in range(n):
        if color[start] != -1:
            continue

        cid = len(component_bad)
        component_bad.append(False)

        color[start] = 0
        component[start] = cid
        stack = [start]

        while stack:
            u = stack.pop()

            for v in graph[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    component[v] = cid
                    stack.append(v)
                elif color[v] == color[u]:
                    component_bad[cid] = True

    if k % 2 == 0:
        return sum(degree[i] > 0 for i in range(n))

    return sum(component_bad[component[i]] for i in range(n))

def solve():
    t = int(input())

    for _ in range(t):
        n, m, k = map(int, input().split())
        edges = [tuple(map(int, input().split())) for _ in range(m)]

        print(solve_case(n, m, k, edges))

if __name__ == "__main__":
    solve()
```の最初の部分`solve_case`2 つのグラフ表現を構築します。`graph`後のコンポーネントと二部性トラバースのエッジを保存します。`adj_bits[u]`は、(u) のすべての近傍を 1 つの整数に格納するため、もう 1 つのグラフ ステップを実行すると、一連の整数 OR 演算になります。 

正確な動的プログラムは次のように始まります。`1 << i`都市 (i) の場合、エッジを取得する前に到達可能な唯一の都市は (i) 自体であるためです。 到達可能な頂点ごとに`v`、`adj_bits[v]`追加の手順を 1 つ行った後の、考えられるすべての宛先が含まれています。 これらすべてのマスクを OR 演算すると、次に到達可能なセットが正確に得られます。 

ループは以下に制限されます`k <= 2 * n`。 この境界は意図的に設けられたものです。 コンポーネントの構造によって答えが完全に決まるため、(2n) を超える正確な歩行長を知る必要はありません。 

2 部走査で色を割り当てる`0`そして`1`。 ループが出現します`graph[u]`からのエッジとして`u`それ自体に、だから`color[v] == color[u]`すぐにコンポーネントを非二部構成としてマークします。 同じ隣接性チェックを繰り返しても結果は変わらないため、平行エッジは問題ありません。 

たとえ大きい (k) の場合でも、`degree[i] > 0`完全な状態です。 奇数大 (k) の場合、コンポーネント識別子は各頂点をその 2 部ステータスにマップします。`component_bad[component[i]]`都市 (i) が非 2 部構成要素に属しているかどうかを直接示します。 

Python では整数オーバーフローの問題はありません。 最大のビットセットには関連するビットが 50 個しかなく、(k) は通常の Python 整数として格納されます。

 ## 特殊なケース

 (k=0) の場合、次のように考えます。```
1
1 0 0
```アルゴリズムはすぐに次のように戻ります。`n`これは 1 です。長さゼロの歩行には道路が必要ないため、隣接情報は必要ありません。 これにより、開始都市にプラスの学位が必要になるというよくある間違いを回避できます。 

正の偶数 (k) を持つ孤立した頂点の場合、次のことを考慮します。```
1
2 0 2
```(2\le2n) のため、large-(k) ショートカットは使用されないため、正確な DP は次で始まります。`{0}`そして`{1}`。 1 つのステップの後、入射エッジがないため両方のセットが空になり、空のままになります。 どちらの対角ビットも存在しないため、0 が与えられます。同じケースにはるかに大きな偶数 (k) がある場合、large-(k) 分岐は明示的にチェックします。`degree[i] > 0`、孤立した都市の受け入れを妨げます。 

ループの場合は、次のように考えます。```
1
1 1 1
0 0
```正確な DP はビット 0 が設定された状態で始まります。 1 つのステップの後、ループによりビット 0 を含む頂点 0 の隣接マスクの OR が計算されます。 対角ビットは設定されたままなので、答えは 1 です。ラージ (k) 分岐では、同じループにより 2 部トラバーサルで端点が同じ色のエッジに遭遇し、コンポーネントが非 2 部であることがマークされます。 

奇数 (k) が小さい非 2 部グラフの場合、三角形を考慮します。```
1
3 3 1
0 1
1 2
2 0
```グラフには奇数のサイクルが含まれていますが、ループはありません。 (k=1) では、1 つのエッジ内で頂点がそれ自体に戻ることはできません。 (1\le2n) なので、正確な DP が使用され、正しく 0 が返されます。これが、ラージ (k) パリティ分類をすべての奇数 (k) に単純に適用できない理由です。 

最後に、非常に大きな奇数 (k) を持つ 2 部グラフを考えてみましょう。```
1
3 2 1000000001
0 1
1 2
```ここでは (k>2n) なので、アルゴリズムは 10 億回繰り返す代わりに 2 部チェックを実行します。 このコンポーネントは 2 つの部分から構成されているため、`component_bad`は誤りです。 (k) は奇数であるため、都市はカウントされず、答えは 0 になります。結果は、2 部グラフ内のすべての閉じたウォークの長さが偶数であるという事実から得られます。
