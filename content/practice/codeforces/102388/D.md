 ## 解決策
 ## 問題の理解

 テストケースごとに、英語の文字のみを含む空ではない文字列を 1 つ受け取ります。 必要なエンコードでは、問題で説明されている順序で 3 つの変換を適用します。つまり、すべての文字を反対の大文字に変更し、文字列全体を反転し、文字の大文字と小文字を保持したまま ROT13 を適用します。 出力は、結果として得られるエンコードされた文字列です。 

たとえば、次のように始めます。`HelloWorld`、大文字と小文字を変更すると、`hELLOwORLD`。 逆にすると`DLROwOLLEh`、ROT13 が生成する`QYEBjBYYRu`。 

テストケースは最大 100 個あり、各文字列には最大 100 文字が含まれます。 したがって、入力の総量はごくわずかであるため、すべての文字列を複数回完全にパスするだけでも、1 秒の制限を十分に満たす速度になります。 さらに重要なのは、変換自体は文字列の長さに対して線形であるため、直接シミュレーションよりも複雑なものを使用する理由はありません。 二次時間を要する解法もこれらの特定の制約を通過しますが、必要以上に難しい問題を解くことになります。 

最初のエッジ ケースは 1 文字の文字列です。 入力用`A`、ケースを交換すると、`a`、反転しても何も変化せず、ROT13 は次のようになります。`n`したがって、正しい出力は次のようになります。`N`指定された構成で変換を適用した後。 反転を少なくとも 2 文字必要なものとして扱う不注意な実装では、このケースを誤ってスキップしたり誤って処理したりする可能性があります。 

2 番目のエッジ ケースは、アルファベットの終わりに近い文字です。 入力用`Z`、ROT13 はからラップアラウンドする必要があります。`Z`に`M`、アルファベットの外に移動するのではなく。 正しい出力は次のとおりです`M`。 小文字でも同じ問題が発生します`z`となり、`m`。 ラップせずに単に ASCII 値に 13 を加算する実装では、無効な文字が生成されます。 

3 番目のエッジ ケースは、ケースとアルファベットの境界が混在したものです。 入力用`AaZz`、最初に逆転すると、`zZ aA`スペースなし、つまり`zZaA`。 ケースを交換するとこうなります`ZzAa`、ROT13 は次のようになります。`MmNn`。 大文字と小文字を変更する前に ROT13 を適用し、その後間違った大文字と小文字の情報を使用する不注意な解決策では、誤った大文字化が容易に発生する可能性があります。 

## アプローチ

 簡単なアプローチは、3 つの操作を個別にシミュレートすることです。 文字列全体をスキャンしてすべての文字の大文字と小文字を交換し、反転を実行してから、文字列全体を再度スキャンして ROT13 を見つけることができます。 これはエンコード定義を直接反映するため、正確さがすぐにわかります。 長さの文字列で`n`、3 つのパスが実行されます`n`ケースの変更、`floor(n / 2)`リバーサルスワップ、そして`n`ROT13 変換。 この直接実装では、つまり、`2n + floor(n / 2)`キャラクターレベルの操作。 と`n <= 100`、最悪の場合でも、テストケースごとにそのような操作が 250 件しかないため、このアプローチが遅くなりすぎるということはありません。 明らかに強引なベースラインはすでに受け入れられています。 

大文字と小文字の交換と ROT13 の両方が文字単位の変換であることを観察することで、実装をよりクリーンにすることができます。 どちらの操作もキャラクターの位置に依存しないため、どちらも反転で通います。 最初に中間文字列を作成してからそれを逆にする代わりに、元の文字列を右から左にたどって、答えを生成しながら 2 つの文字変換を適用できます。 各入力文字は 1 回だけ処理されます。 

重要な点は、3 つの操作には複雑な対話が必要ないということです。 反転は文字が表示される順序を決定しますが、大文字と小文字の入れ替えと ROT13 は個々の文字を変更するだけです。 したがって、元の文字を最後の位置から最初の位置に移動すると、すでに暗黙的に反転が実行されています。 訪問した各キャラクターを変換するだけで済みます。 

これにより、実装が文字列の 1 回の走査に減ります。 漸近的な複雑さは残る`O(n)`、出力を決定するためにすべての文字を少なくとも 1 回検査する必要があるため、これは最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 個別のシミュレーション パス | O(n) | O(n) | 承認済み |
 | 後方移動中のワンパス変換 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります`s`。 文字は英字であることが保証されているため、大文字か小文字かを確認することですべての文字を扱うことができます。 
2.トラバース`s`最後の文字から最初の文字まで。 この方向に読み取ると、反転コピーを明示的に構築せずに、必要な反転が実行されます。 
3. 現在の文字の大文字と小文字を入れ替えます。 大文字は小文字になり、小文字は大文字になります。 
4. 現在の大文字と小文字を保持したまま、ROT13 を文字に適用します。 大文字の場合は減算します`A`、13 モジュロ 26 を追加し、さらに追加します。`A`戻る。 小文字の場合も、次を使用して同じことを行います`a`。 
5. 変換された文字を答えに追加します。 文字は逆の入力順序で処理されるため、結果として得られる答えはすでに必要な逆の配置になっています。 
6. テストケースの完成した回答を印刷します。 

### なぜ効果があるのか

 オリジナルキャラクターを検討してください`s[i]`。 最終的にエンコードされた文字列には、この文字の変換されたバージョンが次の位置に含まれている必要があります。`n - 1 - i`、反転により位置が移動するため`i`その位置に。 からの入力をトラバースすることで、`n - 1`まで`0`、アルゴリズムは、文字を左から右の順序で最終位置に正確に配置します。 大文字と小文字の入れ替えと ROT13 操作はキャラクターの位置とは独立しているため、キャラクターを訪問している間にこれらの操作を適用すると、反転の前後にこれらの操作を適用した結果とまったく同じ文字が生成されます。 したがって、すべての出力位置には正しいエンコードされた文字が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def transform(s):
    ans = []

    for c in reversed(s):
        if 'A' <= c <= 'Z':
            c = c.lower()
        else:
            c = c.upper()

        if 'A' <= c <= 'Z':
            c = chr((ord(c) - ord('A') + 13) % 26 + ord('A'))
        else:
            c = chr((ord(c) - ord('a') + 13) % 26 + ord('a'))

        ans.append(c)

    return ''.join(ans)

def main():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        print(transform(s))

if __name__ == "__main__":
    main()
```の`transform`関数はアルゴリズムのウォークスルーに直接対応します。`reversed(s)`は、反転操作の後に必要な順序で文字を正確に与えるため、個別の反転操作は必要ありません。 

最初の条件は文字の大文字と小文字を変更します。 2 番目の条件は、文字がどのアルファベットに属するかを決定し、モジュラー演算を使用して ROT13 を実行します。 表現`(ord(c) - ord('A') + 13) % 26`文字を 0 から始まるアルファベットの位置に変換し、13 位置ずつ回転し、必要に応じて折り返します。 

モジュロ演算はアルファベットの境界をきれいに処理します。 例えば、`Z`ゼロベースの位置は 25 なので、`(25 + 13) % 26`12 が与えられます。これは次のようになります。`M`。 小文字のブランチは以下と同様に動作します。`a`そのベースとして。 

インデックスの計算はありません。`len(s) - 1 - i`したがって、この実装により、最も一般的な反転オフバイワンエラーが回避されます。 また、すべての演算は 0 ～ 25 の値に対して実行されるため、整数オーバーフローの心配もありません。 

文字列を繰り返し連結すると不要な中間文字列が作成される可能性があるため、答えはリストに保存されます。 最後にリストを 1 回結合すると、最終結果が効率的に構築されます。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    input = io.StringIO(inp).readline
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()
        ans = []

        for c in reversed(s):
            if 'A' <= c <= 'Z':
                c = c.lower()
            else:
                c = c.upper()

            if 'A' <= c <= 'Z':
                c = chr((ord(c) - ord('A') + 13) % 26 + ord('A'))
            else:
                c = chr((ord(c) - ord('a') + 13) % 26 + ord('a'))

            ans.append(c)

        out.append(''.join(ans))

    return '\n'.join(out) + '\n'

def run(inp: str) -> str:
    return solve(inp)

# Provided sample
assert run(

QYEBjBYYRu

"""
) == """QYEBjBYYRu

""", "sample 1"

# All characters equal, maximum length
assert run("1\n" + "A" * 100 + "\n") == "N" * 100 + "\n", "maximum-size equal string"

# Lowercase boundary characters
assert run("1\naz\n") == "MZ\n", "lowercase alphabet boundaries"

# Multiple testcases with different lengths

AbCd

""", "mixed lengths and cases"

 ## 特殊なケース

 1文字入力の場合`A`、トラバースにはその文字のみが含まれます。 大文字と小文字の交換の変更`A`に`a`、ROT13 の変更`a`に`n`。 反転中はキャラクターは他に移動する場所がないため、最終的な出力は次のようになります。`N`。 このアルゴリズムでは、長さ 1 について特別なケースは必要ありません。 

アルファベット境界入力の場合`Z`、キャラクターは最初に次のようになります`z`ケース交換の為。 ROT13 が計算します`(25 + 13) % 26 = 12`、生産`m`したがって、出力は次のようになります`M`。 モジュロ演算により、計算がアルファベットから外れることがなくなります。 

混合境界入力の場合`AaZz`、逆走査訪問`z`、`Z`、`a`、`A`。 大文字と小文字の交換と ROT13 の後、これらは次のようになります。`M`、`m`、`N`、`n`、 それぞれ。 出力は`MmNn`これにより、アルゴリズムが大文字と小文字の両方の回り込みを処理する際に正しい大文字と小文字が保持されることが確認されます。 

100 個のコピーで構成される最大サイズのすべて等しい入力の場合、`A`、反転しても文字列は目に見えて変わりませんが、すべての文字は大文字と小文字の交換と ROT13 変換を受けます。 それぞれ`A`になる`N`、したがって、結果には 100 個のコピーが含まれます。`N`。 このアルゴリズムはちょうど 100 文字を処理し、繰り返される値に対する特別な処理を必要としません。
