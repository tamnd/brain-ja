 ## 解決策
 ## 問題の理解

 黄金比の累乗を使用して、正の整数 (n) の一意の正規表現を出力する必要があります。 

[
 \phi=\frac{1+\sqrt5}{2}。 
]

 各位置には (0) または (1) が含まれており、隣接する 2 つの位置の両方に (1) が含まれることはありません。 通常の位置システムとは異なり、有用な位置には負の指数が含まれる可能性があるため、出力には小数部分が含まれる場合があります。 たとえば、

 [
 2=\phi^1+\phi^{-2}、
 ]

 これは次のように書かれています`10.01`。 

入力には、(n\le 100000) ごとに最大 10 個の独立した整数が含まれます。 (n) で 2 次の解は、1 つのテスト ケースに対して最大 (10^{10}) 個の演算をすでに実行しており、1 秒の制限をはるかに超えています。 指数関数的に多くの数字列を調査するアプローチでさえ、完全に実行不可能です。 基底 (\phi) の位置の数に応じて仕事が大きくなるアルゴリズムが必要ですが、これは (n) でのみ対数になります。 

誤って対処しやすい特殊なケースがいくつかあります。 最小の入力は (n=1) で、その答えは単純に次のようになります。`1`。 常に基数点を出力するフォーマッタは、誤って生成する可能性があります。`1.`。 

負の累乗が必要な最初の数値は (n=2) です。 その答えは、```
2
10.01
```(2) は必要な正のべき乗の合計ではないため、べき乗 (\phi^0,\phi^1,\phi^2,\ldots) のみを検索するメソッドは決して完了できません。 

浮動小数点演算も危険なケースです。 (n=2) の場合、正確な恒等式は (\phi+\phi^{-2}=2) ですが、通常の浮動小数点を使用して 2 つの項を評価すると、正確にゼロではなく小さな残差が残る可能性があります。 残差がゼロになるまで負のべき乗を生成し続けるループでは、誤った余分な桁が生成される可能性があります。 以下の解決策は、(\phi) を数値的に評価することはありません。 

最後に、隣接するものは禁止されなければなりません。 たとえば、(4) は次のように表されます。`101.01`近隣勢力の恣意的な組み合わせによるものではありません。 貪欲なプロセスは、アイデンティティのために必要な分離を自動的に作成します。 

[
 \phi^{k+1}-\phi^k=\phi^{k-1}。 
]

 ここで使用される貪欲な特徴付けは、標準の正規表現、つまりバーグマンの基底 (\phi) 表現です。 

## アプローチ

 直接的なブルートフォース ソリューションでは、指数の範囲を選択し、可能なすべての 2 進数文字列を列挙し、隣接する文字列を含む文字列を拒否し、残りのどの文字列が (n) と評価されるかをチェックします。 必要な表現は有限かつ一意であるため、これは原理的には正しいですが、検索空間は指数関数的に増大します。 49 桁の範囲の場合、隣接するバイナリ文字列がない (F_{51}=20,365,011,074) 個のバイナリ文字列が存在するため、1 つの候補を定数時間でテストすることさえ、最大の入力に対してはすでに絶望的になります。 

より自然ではありますが、依然として不適切なアプローチは、記号式を維持しながら (\phi) のべき乗を繰り返し加算または減算することです。 すべての文字列を列挙することは避けられますが、貪欲な観察がなければ、次にどのべき乗を選択すべきかを知る理由がないため、アルゴリズムは依然として代替案を探索する必要があります。 

重要な観察は、正規表現が貪欲に構築できるということです。 すべての点で、(r) をまだ表現すべき正の剰余とします。 を満たす最大のべき乗 (\phi^k) を選択してください

 [
 \phi^k\le r.
 ]

 (k) の位置に (1) を置き、(r) を (r-\phi^k) に置き換えます。 これを繰り返すと最終的にゼロに達し、正規表現が生成されます。 これはまさに最小の基数 (\phi) 表現の貪欲な特徴付けです。 

2 番目の問題があります。(\phi) を含む比較では、通常の浮動小数点を安全に使用することができません。 有益な代数的事実は、(\phi) のすべてのべき乗は正確に次のように記述できるということです。 

[
 a+b\ファイ
 ]

 整数 (a,b) の場合。 以来

 [
 \phi^2=\phi+1、
 ]

 このようなペアに (\phi) を掛けると、

 [
 (a+b\ファイ)\ファイ=b+(a+b)\ファイ。 
]

 同様に、(1/\phi=\phi-1) なので、(\phi) で割ると次のようになります。 

[
 (a+b\phi)/\phi=(b-a)+a\phi。 
]

 したがって、整数演算だけを使用して必要な電力をすべて生成できます。 

比較自体も正確にすることができます。 のために

 [
 x=a+b\ファイ、
 ]

 書く

 [
 x=\frac{(2a+b)+b\sqrt5}{2}。 
]

 この式の符号は、整数の乗算と比較のみを使用して決定できます。 アルゴリズムのどこにも数値近似はありません。 

したがって、有効な数字列の数が指数関数的であるため、総当たりアプローチは失敗しますが、正規表現が貪欲であるという観察により、問題は累乗を 1 回スキャンするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(F_L))、ここで (L) は位置の数 | (O(L)) | 遅すぎる |
 | 正確な代数演算に貪欲 | (O(L)) | (O(L)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての代数数を ((a,b)) の形式で表し、(a+b\phi) を意味します。 入力整数 (n) は ((n,0)) として始まり、現在の剰余は同じ形式で格納されます。 
2. (\phi^k\le n) の最大の指数 (k) を見つけます。 (\phi^0=1) から始めて、(n) を超えない範囲で現在の累乗を (\phi) 倍することを繰り返します。 (\phi>1) であるため、プロセスは (O(\log n)) 回の反復後に停止します。 
3. この最大の指数から開始して、プロセス電力は降順に増加します。 指数 (k) で、現在の剰余を (\phi^k) と比較します。 べき乗が一致する場合は、この位置に数字 (1) を置き、余りからべき乗を引きます。 それ以外の場合は、数字 (0) を入力します。 
4. 各位置の後で、正確なペア変換 ((a,b)\mapsto(b-a,a)) を使用して、現在のパワーを (\phi) で除算します。 これは、指数 (k) から指数 (k-1) に移動します。 
5. 余りが正確に ((0,0)) になったらすぐに停止します。 有限表現特性により、貪欲なプロセスがゼロに到達することが保証されます。 
6. 数字は、最大の指数から最小の指数まで収集されています。 指数（0）の直後で分割し、整数部の不要な先頭ゼロと小数部の末尾のゼロを削除し、小数点以下の桁が残った場合のみ小数点を挿入します。 

隣接するものが決して表示されない理由は、貪欲な選択から直接導き出されます。 (\phi^k) が選択されているとします。 (k) が可能な最大の指数であったため、選択する前は、剰余は (\phi^{k+1}) より小さくなっています。 したがって、減算後の新しい剰余は以下より小さくなります。 

[
 \phi^{k+1}-\phi^k=\phi^{k-1}。 
]

 したがって、次の位置（ｋ－１）は選択できない可能性がある。 貪欲なプロセスは、隣接しないルールを自動的に満たします。 

**これが機能する理由** すべての反復で、剰余 (r) は、まだ選択されていないすべての桁で表される値とまったく同じです。 このアルゴリズムは、(r) を超えない最大のパワーを選択します。これはまさに標準的な貪欲表現の決定的な選択です。 そのべき乗を減算すると不変式が保存され、恒等式 (\phi^{k+1}-\phi^k=\phi^{k-1}) は、2 つの連続した選択位置が不可能であることを証明します。 剰余がゼロに達すると、選択されたべき乗の和は元の値 (n) と正確に一致し、正規表現の一意性は、結果として得られる数字シーケンスが必要な答えであることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mul_phi(p):
    a, b = p
    return (b, a + b)

def div_phi(p):
    a, b = p
    return (b - a, a)

def nonnegative(a, b):
    """
    Return whether a + b*phi >= 0 exactly.

    a + b*phi = (2*a + b + b*sqrt(5)) / 2.
    """
    c = 2 * a + b

    if c == 0:
        return b >= 0

    if b > 0 and c > 0:
        return True

    if b < 0 and c < 0:
        return False

    if c > 0:
        return c * c >= 5 * b * b

    return 5 * b * b >= c * c

def geq(x, y):
    """
    Return whether x >= y for two numbers represented as
    (a, b) = a + b*phi.
    """
    a = x[0] - y[0]
    b = x[1] - y[1]
    return nonnegative(a, b)

def solve_one(n):
    # Find the largest non-negative exponent whose power does not exceed n.
    power = (1, 0)  # phi^0
    k = 0

    while True:
        nxt = mul_phi(power)
        if not geq((n, 0), nxt):
            break
        power = nxt
        k += 1

    max_k = k
    remainder = (n, 0)
    digits = []

    # Greedily process phi^k, phi^(k-1), ...
    while remainder != (0, 0):
        if geq(remainder, power):
            digits.append('1')
            remainder = (
                remainder[0] - power[0],
                remainder[1] - power[1]
            )
        else:
            digits.append('0')

        power = div_phi(power)
        k -= 1

    s = ''.join(digits)

    # The digit corresponding to phi^0 is at index max_k.
    split = max_k + 1
    left = s[:split].lstrip('0')
    right = s[split:].rstrip('0')

    if not left:
        left = '0'

    if right:
        return left + '.' + right

    return left

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        out.append(solve_one(n))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    main()
```の`mul_phi`関数の実装

 [
 (a+b\phi)\phi=b+(a+b)\phi、
 ]

 したがって、指数を 1 つ右に移動します。 の`div_phi`関数は (\phi^{-1}=\phi-1) による乗算を実装し、指数を 1 つ左に移動します。 

の`nonnegative`関数は重要な精度の詳細です。 (\phi) を浮動小数点数に変換することはありません。 (a+b\phi) の場合、(2) を掛けると (2a+b+b\sqrt5) が得られます。 2 つの無理数成分の符号が同じであれば、答えはすぐにわかります。 符号が異なる場合、2 つの正の量を二乗すると、(c^2) と (5b^2) が正確に比較されます。 

最初のループでは、使用可能な最大の非負の指数を見つけます。 次に、2 番目のループは、その指数から下方向に貪欲な構築を実行します。 ループは負の指数に渡すことができます。(2) や (123) などの整数には小数点位置が必要なため、これが必要です。 

出力フォーマットには次のものを使用します。`max_k + 1`指数 (0) の桁がまさに整数部の最後の桁であるため、分割位置として使用されます。 最上位 (1) の前の先頭のゼロと、最下位 (1) の後の後続のゼロが削除されます。 小数点は、空でない小数部がある場合にのみ出力されます。 

Python の整数には任意の精度があるため、累乗係数がフィボナッチ数のように増加しても、整数のオーバーフローの問題は発生しません。 

## 実用的な例

 サンプル値 (n=2) の場合、(2) を超えない最大のべき乗は (\phi^1) です。 その後、貪欲なプロセスにより正確な表現 (\phi+\phi^{-2}) に到達します。 

| 指数 (k) | 現在の電力 | ステップ前の剰余 | アクション | ステップ後の残り |
 | --- | --- | --- | --- | --- |
 | (1) | (\ファイ) | (2) | (1)を選択 | (2-\ファイ) |
 | (0) | (1) | (2-\ファイ) | (0)を選択 | (2-\ファイ) |
 | (-1) | (\phi^{-1}) | (2-\ファイ) | (0)を選択 | (2-\ファイ) |
 | (-2) | (\phi^{-2}) | (2-\ファイ) | (1)を選択 | (0) |

 (\phi^{-2}=2-\phi) なので、最後の桁は次のようになります。`10.01`。 このトレースは、小数部分を単に通常の小数のように扱うことができない理由も示しています。 

構築された 2 番目の例 (n=5) の場合、使用可能な最大電力は (\phi^3) です。 正確な剰余は徐々に小さくなり、最終的な補正は負の累乗で行われます。 

| 指数 (k) | 現在の電力 | ステップ前の剰余 | アクション | ステップ後の残り |
 | --- | --- | --- | --- | --- |
 | (3) | (1+2\ファイ) | (5) | (1)を選択 | (4-2\ファイ) |
 | (2) | (1+\ファイ) | (4-2\ファイ) | (0)を選択 | (4-2\ファイ) |
 | (1) | (\ファイ) | (4-2\ファイ) | (0)を選択 | (4-2\ファイ) |
 | (0) | (1) | (4-2\ファイ) | (0)を選択 | (4-2\ファイ) |
 | (-1) | (-1+\ファイ) | (4-2\ファイ) | (1)を選択 | (5-3\ファイ) |
 | (-2) | (2-\ファイ) | (5-3\ファイ) | (0)を選択 | (5-3\ファイ) |
 | (-3) | (-3+2\ファイ) | (5-3\ファイ) | (0)を選択 | (5-3\ファイ) |
 | (-4) | (5-3\ファイ) | (5-3\ファイ) | (1)を選択 | (0) |

 結果として得られる表現は、`1000.1001`。 正確なペア表現により、最終的な減算は単にゼロに近づくのではなく、ゼロに等しくなります。

 ## 特殊なケース

 For (n=1), the largest usable power is (\phi^0=1). The first greedy step subtracts exactly (1), leaving the pair ((0,0)). 数字シーケンスには次のものだけが含まれます`1`、フォーマッタは次のように出力します。`1`小数点なし。 

(n=2) の場合、アルゴリズムは最初に (\phi^1) を選択し、(2-\phi) を残します。 次の 2 つのべき乗 (1) と (\phi^{-1}) は両方とも大きすぎます。 指数 (-2) では、べき乗はちょうど (2-\phi) なので、余りはゼロになります。 出力は`10.01`。 このケースは、負の指数が重要である理由を示しています。 

(n=3) の場合、最初に選択されるべき乗は (\phi^2=1+\phi) です。 余りは ​​(2-\phi=\phi^{-2}) なので、出力は次のようになります。`100.01`。 貪欲な選択は、指数 (2) を選択すると指数 (1) が不可能になるため、隣接不変性も示します。 

(n=5) の場合、選択される指数は (3,-1,-4) です。 対応する値は

 [
 \phi^3+\phi^{-1}+\phi^{-4}=5、
 ]

 したがって、出力は`1000.1001`。 選択された 2 つの負の位置は 2 つのゼロで区切られており、隣接 1 なしルールが整数側と同様に基数点全体に適用されることを示しています。 

(n=123) の場合、答えは次のようになります。`10000000000.0000000001`。 これはつまり、

 [
 123=\ファイ^{10}+\ファイ^{-10}。 
]

 2 つの代数項はそれぞれ無理数ですが、それらの (\phi) 係数は正確に相殺されます。 整数ペア表現は、浮動小数点の精度に依存することなく、このキャンセルを処理します。 

(n=100000) の場合、アルゴリズムはわずか数十の位置に対して同じプロセスを継続し、正確にゼロに到達します。 長い答えは高価なアルゴリズムの兆候ではありません。作業は数値 (100000) ではなく桁数に比例するからです。
