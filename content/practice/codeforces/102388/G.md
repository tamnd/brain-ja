 ## 解決策
 ## 問題の理解

 深層から始まるカタツムリを追跡します`n`、深さ`0`地面に到達したことを意味します。 毎日、それは登っていきます`a`メートル。 その登りが地面に達するか通過すると、カタツムリはすぐに逃げてプロセスは終了します。 そうしないと夜が来てカタツムリが落ちる`b`メートルなので、その深さは によって増加します`b`。 

各テスト ケースのタスクは、カタツムリが地面に到達する最初の日を決定することです。 カタツムリが決して逃げられない場合は、次のように出力します。`-1`。 

制約は小さく、テスト ケースは最大 10 個です。`n`、`a`、 そして`b`したがって、直接シミュレーションでは、エスケープが可能な場合、1 つのテスト ケースに対して最大約 1000 日のサイクルが実行されますが、これは 1 秒の制限内に簡単に収まります。 それでも、プロセスの構造により O(1) 式が得られます。これはよりクリーンで、境界が大幅に増加した場合でも効率が維持されます。 

難しいのは、カタツムリが最後の登攀を試みても落ちないという事実です。 たとえば、`n = 5, a = 5, b = 100`、答えは`1`、カタツムリは初日に地面に到達するためです。 カタツムリが逃げたかどうかを確認する前に常に夜の秋を適用する不注意な実装では、カタツムリが井戸内に残っていると誤って報告する可能性があります。 

もう 1 つのエッジケースは、登りと下りが同じくらい大きい場合です。 のために`n = 10, a = 5, b = 5`、カタツムリは深さ 10 から 5 に登り、10 に戻り、これを永遠に繰り返します。 正しい出力は次のとおりです`-1`。 かどうかのみを確認します`a`ゼロ以外の場合、この状況は見逃されます。 

ケース`a < b`カタツムリが初日に地面に到達しない限り、これも不可能です。 例えば、`n = 6, a = 3, b = 4`与える`-1`。 失敗した日が続くと、実際にはカタツムリは以前よりも深くなり、回復することはできません。 

ついに、`a = 0`自然に処理する必要があります。 例えば、`n = 1, a = 0, b = 0`生成する`-1`、カタツムリはまったく動かないからです。 

## アプローチ

 最も直接的な解決策は、毎日シミュレーションを行うことです。 現在の深さを維持し、差し引きます`a`日中は水深がゼロになったかどうかをすぐに確認してください。 そうでない場合は、追加します`b`一晩かけて続けます。 これは物理的なプロセスに正確に従うため、シミュレーションがエスケープで終了するたびに、報告される日は正確になります。 

シミュレーションでは不可能なプロセスも検出する必要があります。 失敗に終わった昼と夜を経て深さは変わる`a - b`上方向に。 もし`a <= b`、カタツムリは一昼夜を終えても決して地面に近づくことはありません。 初日に逃げられなかったとしても、決して逃げられないでしょう。 

与えられた制約の下では、ブルート フォースはすでに十分に高速です。 いつ`a > b`したがって、シミュレーションが成功するには、テスト ケースごとに最大で約 1000 回の反復、またはすべてのテスト ケースで約 10000 回の反復が必要です。 実際の制限に関してこのアプローチを拒否する必要はありません。 

より有益な観察は、毎日失敗するたびに、カタツムリの深さが正確に減少するということです。`a - b`。 カタツムリが初日に逃げなかったと仮定します。 最終日の前に、すでにいくつかの完全な昼夜サイクルを完了しており、それぞれの純進行状況は同じです。 このようなサイクルが何回必要になるかを、シミュレーションする代わりに直接計算できます。 

カタツムリの一日が深海で始まるとしたら`d`、その日まさにその時に逃げます。`d <= a`。 初日に関しては、これは、`n <= a`と即座に答えます。`1`。 それ以外の場合、完全に失敗した日が続くと、深さは次のように減少します。`a - b`。 もし`a <= b`、前向きな進歩がないため、脱出は不可能です。 もし`a > b`、必要な追加サイクルの数を決定するには、天井分割のみが必要です。 

各反復が実際の 1 日を表すため、ブルート フォース手法が機能します。 こうなると魅力が減ります`n`実行時間は日数に比例するため、増加します。 失敗した日ごとに同じ固定量だけ深さが変化するという観察により、これらの繰り返される操作をすべて 1 つの算術計算に置き換えることができます。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず次のことを確認します。`n <= a`。 カタツムリは最初の昼間の登山中に地面に到達するので、答えはすぐにわかります`1`。 プロセスは地面に到達するとすぐに停止するため、夜間の落下は関係ありません。 
2. 初日が脱出できない場合は、次のことを確認してください。`a <= b`。 その後、完全な昼夜のサイクルが完了しても、上向きに進歩することはなく、カタツムリはさらに下に押し込まれます。 初日はすでに失敗したので、カタツムリは決して逃げることができないので、戻ります`-1`。 
3. これでわかりました`a > b`したがって、1 日が失敗するたびに、深さは次のように減少します。`a - b`。 させて`k`カタツムリが逃げ出すまでの日数です。 後`k - 1`完全な昼夜のサイクル、その深さは`n - (k - 1)(a - b)`。 

当日`k`、登ります`a`メートルなので、逃げる必要があります`n - (k - 1)(a - b) <= a`。 

並べ替えると`n - a <= (k - 1)(a - b)`。 

したがって、必要な完全に失敗したサイクルの数は次のようになります。`ceil((n - a) / (a - b))`。 

最終登山日はさらに 1 日追加されるため、答えは次のようになります。`ceil((n - a) / (a - b)) + 1`。 
4. 整数演算を使用して上限除算を計算します。`(x + y - 1) // y`ポジティブな`x`そして`y`、 どこ`x = n - a`そして`y = a - b`。 これにより、浮動小数点演算が回避され、正確な整数の答えが得られます。 

**なぜそれが機能するのか** 最終日の前に、完了した昼夜のサイクルごとにカタツムリの深さが正確に変化します`a - b`。 いつ`a <= b`、その変更ではカタツムリを上に移動させることはできないため、失敗した後は初日の脱出は不可能です。 いつ`a > b`、任意の数の完全なサイクル後の深さは、同じ固定減少によって正確に決定されます。 この式は、次の日中の上昇で地面に到達できる完全なサイクルの最小数を見つけます。 計算ではそのような最小値が使用されるため、正確に最初の脱出日が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, a, b = map(int, input().split())

        if n <= a:
            print(1)
            continue

        if a <= b:
            print(-1)
            continue

        net = a - b
        remaining = n - a

        days = (remaining + net - 1) // net + 1
        print(days)

if __name__ == "__main__":
    solve()
```プログラムはまず、初日の逃亡事件を次のように処理します。`n <= a`。 カタツムリは次のような場合でも逃げる可能性があるため、このチェックは不可能条件の前に行う必要があります。`a <= b`。 例えば、`n = 5, a = 5, b = 100`答えがあります`1`。 

その後、`a <= b`これは、すべてのサイクルを完了してもカタツムリの深さを改善できないことを意味します。 カタツムリは初日は逃げなかったので、答えは次のようになります。`-1`。 

残りのケースについては、`net = a - b`厳密にポジティブです。 変数`remaining = n - a`日中の登山で脱出を完了するまでに、どれだけの追加の進歩が必要かを表します。 天井区分は、最後の上昇までに何回の昼夜サイクルが必要かを計算します。 

決勝戦`+ 1`脱出の日そのものを表しています。 これは、問題の中で最も一般的な 1 つずれのポイントです。 登攀の成功ではなく、登攀に成功するまでの完全なサイクルをカウントします。 

Python の整数はこれらの制約に対してオーバーフローせず、すべての計算で整数演算が使用されるため、精度の問題はありません。 

## 実用的な例

 ### サンプル 1、最初のテスト ケース

 のために`n = 10, a = 5, b = 2`、カタツムリは深さ 10 から深さ 5 まで上昇するため、1 日目は逃げることができません。夜になると深さ 7 に戻ります。同じプロセスが 3 日目まで繰り返されます。 

| 日 | 開始時の深さ | 登山後 | 逃げる？ | 夜の深さ |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 5 | いいえ | 7 |
 | 2 | 7 | 2 | いいえ | 4 |
 | 3 | 4 | -1 | はい | 適用されません |

 失敗した各サイクルの最終的な進行状況は次のとおりです。`5 - 2 = 3`。 式は次のようになります`ceil((10 - 5) / 3) + 1 = ceil(5 / 3) + 1 = 2 + 1 = 3`。 

3日目は成功し、カタツムリがすでに逃げてしまったため夜間落下は行われません。

 のために`n = 10, a = 5, b = 5`、最初の登りでカタツムリは深さ 5 に戻り、夜になると深さ 10 に戻ります。この状態が永遠に繰り返されます。 

| 日 | 開始時の深さ | 登山後 | 逃げる？ | 夜の深さ |

 | 2 | 10 | 5 | いいえ | 10 |

 ここ`a <= b`、したがってアルゴリズムはすぐに戻ります`-1`。 このトレースは、ネットの進行状況をチェックするだけで無限プロセスを検出できる理由を示しています。 

### サンプル 1、3 番目のテスト ケース

 のために`n = 5, a = 5, b = 6`、カタツムリは最初の上昇中に地面に到達します。 

| 日 | 開始時の深さ | 登山後 | 逃げる？ | 夜の深さ |

import io

def solve():
    input = sys.stdin.readline
    t = int(input())

    for _ in range(t):

            print(1)

            print(-1)
        else:

            remaining = n - a

    old_stdout = sys.stdout

    sys.stdout = io.StringIO()

    output = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

 ## 特殊なケース

 カタツムリが初日に逃げられるとき、答えは常に`1`、夜の秋とは関係なく。 入力用`5 5 100`、アルゴリズムは最初にチェックします`5 <= 5`そして戻ってきます`1`。 をチェックするソリューション`a <= b`1 つ目は、カタツムリが夜に到達しないにもかかわらず、プロセスが不可能であると誤って宣言することになります。 

いつ`a = b`そして初日が失敗しても、カタツムリは毎晩まったく同じ深さに戻ります。 のために`10 5 5`、最初の登りで深さが 10 から 5 に変更され、その後夜になると深さが 10 に戻ります。アルゴリズムは次のようになります。`n > a`そして`a <= b`、したがって、それは返されます`-1`無限のシミュレーションを試みることなく。 

いつ`a < b`、最初の失敗した日の後、状況はさらに悪化します。 のために`6 3 4`、最初の登りは深さを 6 から 3 に変更し、その後夜に深さを 7 に変更します。後続のすべてのサイクルは、前のサイクルよりも深く始まります。 最初の上昇が不十分だったため、アルゴリズムは戻ります。`-1`。 

いつ`a = 0`、カタツムリはまったく登ることができません。 のために`1 0 0`、初日の状態`1 <= 0`は誤りであり、かつ`a <= b`それは本当なので、答えは`-1`。 もし`b`がプラスの場合、カタツムリは下方向にしか移動しないため、この状況も不可能です。 

正確な境界ケースは、必要なサイクル数が正味の進行状況を完全に分割する場合に発生します。 のために`n = 7, a = 3, b = 1`、最初の日は深さ 4 で終わり、最初の夜は深さ 5 になります。2 日目は深さ 2 で終わり、2 日目の夜は深さ 3 になります。3 回目の上昇で地上に到達します。 式は次のようになります`ceil((7 - 3) / 2) + 1 = 2 + 1 = 3`, したがって、上限計算によって追加の日が導入されることはありません。 

最終日の境界は、式で次の値が使用される理由でもあります。`n - a`、単にではなく`n`。 カタツムリは、日中に登って仕事を完了できるほど十分に近づく必要があります。 登攀に成功した後の夜をカウントすると、誤った追加サイクルが追加されてしまいます。
