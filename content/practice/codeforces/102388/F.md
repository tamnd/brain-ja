 ## 問題の理解

## アプローチ

 直接的な総当たりアプローチは、各宗派の使用枚数を選択し、その結果の合計が以下であるかどうかをテストすることです。`m`。 宗派別`c_i`、そのカウントの範囲は 0 から`floor(m / c_i)`、したがって、調べられる組み合わせの数は`product(floor(m / c_i) + 1)`。 

これは正しいです。なぜなら、コインの考えられるすべてのマルチセットは、それらの枚数の 1 つの選択に正確に対応するからです。 問題はその検索スペースのサイズです。 最悪の場合、すべての宗派が`1`、理論的にはあります`10001^100`元の声明では重複した額面は許可されていませんが、カウントの選択は可能です。 明確に小さな宗派がある場合でも、検索スペースは膨大になります。 したがって、再帰的列挙は、到達するずっと前に失敗します。`n = 100`そして`m = 10000`。 

より巧妙なブルートフォース戦略では、合計が以下の順序でコインのシーケンスが生成されます。`m`、その後、正確に到達するシーケンスのみを保持します`m`。 同じ組み合わせが多くの順列で出現するため、これはさらに悪いことです。 例えば、`2 + 3 + 5`6 つの異なる順序で生成できます。 実際の問題ではその組み合わせに対する 1 つの答えが求められるため、順序を調べると問題に必要のない作業が作成されます。 

重要な観察は、目標金額が次の制限を受けているということです。`10,000`, そのため、これまでに選択されたコインのコレクション全体を記憶する必要はありません。 それぞれの小さな量が何通りの方法で形成されるかを知る必要があるだけです。 金種が固定された順序で処理されると、すでにカウントされている組み合わせに現在の金種を追加するかどうかを決定できます。 

させて`dp[x]`金額を形成する方法の数になります`x`これまでに処理された額面を使用します。 価値のあるコインを処理するとき`c`、形成するためのあらゆる方法`x - c`1つ延長可能`c`形成するコイン`x`。 したがって、追加します`dp[x - c]`に`dp[x]`。

ブルートフォースは、すべてのコインの可能な多重度をすべて明示的に考慮するため機能しますが、そのような選択肢が多すぎる場合は失敗します。 同じ電流量を持つ 2 つの部分解が同じ将来の可能性を持っているという観察により、それらを 1 つの DP 状態にマージできます。 これにより問題は次のように縮小されます`O(nm)`トランジション。

### なぜ効果があるのか

 不変条件は、最初の処理後の`k`宗派、`dp[x]`正確に形成される組み合わせの数に等しい`x`それらだけを使用して`k`宗派。 新しい金種を処理する場合`c`、すべての古い組み合わせが形成されます`x`引き続き利用可能であり、少なくとも 1 つを使用するすべての組み合わせ`c`1 つを削除することで一意に取得できます`c`でカウントされた組み合わせを残します。`dp[x - c]`。 したがって、アップデートでは、によって導入された新しい組み合わせが正確に追加されます。`c`。 

金種は固定された順序で処理されるため、組み合わせには、最大のインデックス付き金種が導入される独自のポイントがあります。 同じコインを別の順に並べて再度数えることはできません。 金額は少額から大額まで処理されるため、現在の額面は繰り返し使用される可能性があるため、すべての有効な多重度が含まれます。 したがって、不変式はどの宗派でも成り立ちます。`dp[m]`は必須の答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        coins = list(map(int, input().split()))

        # The original statement has distinct denominations.
        # Deduplication also makes the implementation robust to repeated values.
        coins = sorted(set(c for c in coins if c <= m))

        dp = [0] * (m + 1)
        dp[0] = 1

        for coin in coins:
            for amount in range(coin, m + 1):
                dp[amount] += dp[amount - coin]
                if dp[amount] >= MOD:
                    dp[amount] -= MOD

        out.append(str(dp[m]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力はテスト ケースごとに 1 回読み取られ、DP が開始される前に額面がフィルタリングされ、重複が排除されます。 正確さを保つためにソートは必要ありませんが、コイン セットに決定的な順序が与えられ、額面を一貫して処理することが容易になります。 

DP 配列にはインデックスがあります`0`を通して`m`、そのサイズは正確です`m + 1`。`dp[0] = 1`は一意の空の組み合わせを表します。 他の初期状態をゼロ以外の値に設定しないでください。 

コインごとに、内側のループは次のように始まります。`coin`, コインの価値を下回る金額ではその額面を使用できないためです。 で終了します`m`目標を超える金額は貢献できないため、`dp[m]`。 

内側のループが上に移動します。 これは最も重要な実装の詳細です。 現在のコインが`2`。 計算後`dp[2]`、後のアップデート`dp[4]`更新された値を読み取るため、次の 2 つのコピーが作成されます。`2`許可されています。 ループが下方向に移動すると、同じ反復では現在のコインが表示されなくなり、繰り返しが 0 または 1 の使用量の遷移に変わります。 

Python の整数はオーバーフローしませんが、すべての更新モジュロを取得します。`MOD`格納される値を小さく保ち、必要なモジュラー演算を直接実装します。 両方のオペランドがすでに以下であるため、`MOD`、結果を範囲内に保つには、加算後に 1 回の減算で十分です。`[0, MOD)`。
