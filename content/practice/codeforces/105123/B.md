 ## 解決策
 ## 問題の理解

 各層に特定の数のノードが含まれる階層構造が与えられています。 連続する層の各ペアの間で、左層のすべてのノードが右層のすべてのノードに接続されます。 つまり、1 つのレイヤーに`x`ノードと次のノードは`y`ノード間のエッジの数は正確に`x × y`。 

タスクは、すべての隣接するレイヤー ペアにわたるエッジの合計数を計算し、その合計を出力することです。 

入力サイズは小さく、レイヤーは最大 1000 個で、各レイヤーには最大 1000 個のノードがあります。 これにより、O(n²) 解でも安全であることがすぐにわかりますが、問題の構造から、それに近いものは必要ないことがわかります。 隣接するペアとのみ対話するため、単一の線形パスで十分です。 

ここでの単純な間違いは、グラフの構築または列挙という観点から考えることです。 たとえば、両方の層のすべてのノードを反復処理するなどしてエッジを明示的にシミュレートしようとすると、効果的には正しい計算が実行されますが、概念的なオーバーヘッドが不要になります。 もう 1 つの間違ったアプローチは、構造を誤解し、隣接するペアごとではなくグローバルにエッジをカウントしようとすることです。これは、連続したレイヤーのみが重要であることを見逃してしまいます。 

エッジケースは単純ですが、それでも健全性をチェックする価値があります。 層が 1 つしかない場合、隣接するペアは存在しないため、答えはゼロになります。 たとえば、入力`1 / 5`生産すべき`0`。 レイヤーに次のようなものが含まれている場合、`1 1 1 1`、各ペアはちょうど 1 つのエッジに寄与するため、答えは遷移の数になります。`n - 1`。 

## アプローチ

 ブルートフォース解釈では、隣接する層の各ペアを明示的に考慮し、ノードを反復して積を計算します。 2層サイズの場合`x`そして`y`、それはループすることを意味します`x`回と`y`すべての接続をカウントする回数。 すべての隣接するペアにわたって、これはネストされた反復によって計算された積の合計に比例しますが、乗算によってすでに結果が直接得られるため、これは不要です。 

非効率性は、各エッジを個別に列挙するものとして扱うことから生じます。 2 つの隣接するレイヤー間の考えられるノードのペアはすべて 1 つのエッジに寄与するため、接続のシミュレーションからは何も得られません。 

重要な観察は、この構造がすでに遷移ごとの正確な式を与えているということです。`i`、貢献は単純に`a[i] × a[i+1]`。 異なるレイヤーのペア間には依存関係がないため、単一パスで結果を蓄積できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ノード ペアをシミュレート) | O(∑ a[i]・a[i+1]) | お(1) | 遅すぎる |
 | 最適 (隣接乗算) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レイヤー数を読み取る`n`そしてリスト`a`各層のノードの数を表します。 これにより、これから辿る構造が確立されます。 
2. アキュムレータを初期化する`ans = 0`エッジの総数を保存します。 これにより計算が増分的に行われるため、追加のストレージは必要ありません。 
3. インデックスからレイヤーを反復処理します。`0`に`n - 2`。 各インデックスは、2 つの連続するレイヤー間の境界を表します。 
4. 各インデックスについて`i`、計算する`a[i] * a[i + 1]`そしてそれを追加します`ans`。 最初のレイヤーのすべてのノードが 2 番目のレイヤーのすべてのノードに接続しているため、これは 2 つのレイヤー間のすべてのエッジを直接カウントします。 
5. すべての隣接するペアを処理した後、出力します。`ans`。 

### なぜ効果があるのか

 ネットワーク内の各エッジは、連続する 2 つの層の間にのみ存在し、そのようなすべてのエッジは、これら 2 つの層から選択されたノードのペアによって一意に識別されます。 固定のレイヤーのペアの場合`i`そして`i+1`、可能なノードのペアの数は正確にデカルト積です。`a[i] × a[i+1]`。 すべての隣接するレイヤー ペアにわたるこれらの独立した寄与を合計すると、レイヤーのペア間で重複することなく、すべてのエッジが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n - 1):
        ans += a[i] * a[i + 1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、ネットワークの構造を読み取ることから始まります。 次に、ループはレイヤー間の各境界を通過して、隣接する値のみを乗算するようにします。 アキュムレータ`ans`可能な最大値は Python の整数容量の範囲内であるため、単一の整数として保持されます。 

微妙な点は、中間エッジ構造を決して保存しようとしないことです。 これにより、メモリのオーバーヘッドと不必要な複雑さの両方が回避されます。 ループの境界`n - 1`各乗算には有効なペアが必要であるため、これは重要です`(i, i+1)`。

 ## 特殊なケース

 次のような単一レイヤー入力の場合`1 / 5`、ループ`for i in range(n - 1)`決して実行されない理由`n - 1 = 0`。 アキュムレータは残ります`0`これは、隣接するレイヤーのペアがないため、エッジがないという事実と一致します。 

次のような最小限の隣接の場合`2 / 3 4`、ループは 1 回実行されます`i = 0`。 計算は`3 × 4 = 12`、それはすぐに返されます。 隠れた状態や反復間の引き継ぎがないため、各境界は完全に独立しており、個別に安全に処理されます。
