 ## 解決策
 ## 問題の理解

 文字 A、T、C、G のみで構成される同じ長さの 2 つの DNA 文字列が与えられます。各位置はヌクレオチドを表し、相補的な塩基を交換する突然変異のみを使用して 2 番目の文字列を最初の文字列から取得できるかどうかを判断するように求められます。 

生物学的法則は、A は T と対になり、C は G と対になるというものです。ここで意図されている解釈は、すべての位置で、突然変異が起こった場合、ヌクレオチドをその相補的パートナーに変換することしかできず、それ以外は何も変換できないということです。 したがって、A は T になるか A のままになることができ、T は A になるか T のままになることができ、C は G になるか C のままになることができ、G は C になるか G のままになることができます。重要なのは、A から C または G から T のようなクロスペア遷移は許可されていないことです。 

文字列を再配置したり、グローバル操作を実行したりすることはありません。 すべての位置は独立して進化し、最初の文字列の各文字が 2 番目の文字列の対応する文字に合法的に変換できるかどうかを検証しているだけです。 

n が 10^5 までという制約は、線形スキャン ソリューションが必要であることを意味します。 組み合わせを探索したり、位置ごとに複数ステップの突然変異パスをシミュレートしようとするアプローチは、文字ごとに O(1) に留まる場合にのみ問題ありません。 二次関数や繰り返しスキャンを伴うものはすべて、2 秒の制限の下では失敗します。 

微妙な失敗のケースは、文字が異なる補完ペアに由来する場合に発生します。 たとえば、X に A があり、Y に同じ位置に C がある場合、両方の文字が有効な DNA 塩基であっても、これは無効です。 単純な間違いは、「両方の文字が有効である限り、どのような変更も問題ない」と想定することであり、そのようなケースを誤って受け入れてしまいます。 

もう 1 つのエッジ ケースは、文字列が同一である場合です。これは、変更が必要ないため、常に有効である必要があります。 また、単一文字の文字列は、特別な分岐を行わずに正しく処理される必要があります。 

## アプローチ

 ブルートフォースの観点は、位置ごとに許容される突然変異をシミュレートすることです。 各インデックス i について、X[i] が Y[i] になれるかどうかを確認します。 突然変異を「相補的な塩基に留まるか切り替えることができる」としてモデル化する場合、各文字について、その許可されたペアのメンバーシップを明示的にテストします。 

これは、有効な遷移のマッピングを事前定義することで実装できます。 X の各文字について、Y[i] がそれ自身またはその補数のいずれかに等しいかどうかを確認します。 これはすでに O(n) ですが、より素朴な解釈では、文字間の突然変異シーケンスまたはグラフ遷移を生成しようとする可能性がありますが、これは不必要であり、複数ステップの変換として誤ってモデル化された場合、オーバーヘッドまたは指数関数的推論が導入される可能性があります。 

重要な観察は、突然変異ルールが純粋に局所的で対称的であるということです。つまり、各文字は固定ペア {A, T} または {C, G} に属し、突然変異がペア間で交差することはありません。 したがって、必要な唯一の条件は、X[i] と Y[i] が同じペアに属していることです。 

これにより、問題は単純な同値クラス チェックに帰着します。A と T は 1 つのクラスを形成し、C と G は別のクラスを形成します。 X[i] と Y[i] が異なるクラスにある場合、答えは直ちに NO になります。 それ以外の場合は、すべての位置がこの条件を満たさなければなりません。

 ## アルゴリズムのチュートリアル

 各文字を補グループに分類し、位置ごとに一貫性をチェックすることで問題を解決します。

1. 相補的なグループを 2 つのセットとして定義します。1 つは A と T を含み、もう 1 つは C と G を含みます。この構造は、クエリを高速に行う方法で突然変異ルールをエンコードします。 
2. 0 から n−1 までのすべてのインデックス i を繰り返し、X[i] と Y[i] を比較します。 
3. 各位置について、X[i] がどのグループに属するかを決定します。 
4. Y[i] が同じグループに属しているかどうかを確認します。 
5. いずれかのポジションがこの条件に違反する場合は、仮説が間違っていると直ちに結論付け、停止します。 
6. スキャンが違反なく完了した場合は、すべての突然変異がルールに従っていると結論付けます。 

即時に終了する理由は、単一の無効な位置によって仮説全体が無効になるため、続行しても計算が無駄になるだけであるためです。 

### なぜ効果があるのか

 各文字は、相補性によって引き起こされる 2 つの等価クラスのうちの 1 つに正確に属します。 突然変異ルールは、同じクラス内でのみ遷移を許可します。 したがって、有効な変換では、すべてのインデックスでクラスのメンバーシップを保持する必要があります。 アルゴリズムは、クラスの等価性を位置ごとにチェックすることにより、この不変条件を直接適用し、正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def same_group(a, b):
    # A <-> T, C <-> G
    if a in "AT":
        return b in "AT"
    else:
        return b in "CG"

n = int(input().strip())
x = input().strip()
y = input().strip()

for i in range(n):
    if not same_group(x[i], y[i]):
        print("NO")
        sys.exit(0)

print("YES")
```このソリューションは、入力文字列を読み取り、2 つの補数グループをエンコードするヘルパー関数を定義します。 ループは各位置を個別にチェックし、失敗すると早期に終了します。 直接メンバーシップ チェックを使用すると、明示的なマッピング テーブルや複数ステップのロジックが不要になり、実装が最小限に抑えられ、文字あたりの定数時間が維持されます。 

よくある実装の間違いは、x が 2 ステップで y に到達できるかどうかをチェックするなど、補数の連鎖を試みることです。これは、突然変異ルールが同値クラスから離れることをまったく許可していないため、不要です。

 インデックス 9 では、A は AT グループに属し、C は CG に属し、突然変異制約が破られます。 アルゴリズムは直ちに停止し、NO を返します。 これは、グループ間の不一致が 1 つでもあると、完全な文字列が無効になることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

線形スキャンは最大 10^5 の n の制約内に快適に適合し、文字ごとの定数時間演算により、制限時間内でソリューションが効率的に実行されることが保証されます。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input().strip())
    x = input().strip()
    y = input().strip()

    def same_group(a, b):
        if a in "AT":
            return b in "AT"
        else:
            return b in "CG"

    for i in range(n):
        if not same_group(x[i], y[i]):
            print("NO")
            return
    print("YES")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided samples
assert run("8\nGCAAGCCT\nCCATCCCT") == "YES", "sample 1"
assert run("10\nCGTATGGACA\nATACTCACCA") == "NO", "sample 2"

# custom cases
assert run("1\nA\nT") == "YES", "single valid flip"
assert run("1\nA\nC") == "NO", "cross group invalid"
assert run("5\nATCGA\nTACGC") == "YES", "mixed valid pairs"
assert run("5\nAAAAA\nCCCCC") == "NO", "all invalid cross group"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1AT | はい | 最小の有効な補数 |
 | 1AC | いいえ | グループ間拒否 |
 | ATCGA / TACGC | はい | 混合有効遷移 |
 | ああああ / CCCCC | いいえ | 均一な無効なマッピング |

 ## 特殊なケース

 X = "A" や Y = "T" などの単一文字入力の場合、アルゴリズムはグループ チェックを 1 回だけ実行します。 A は AT クラスに属し、T も AT に属しているため、ループは失敗を引き起こすことなく終了し、YES を出力します。 

X = "A" および Y = "C" などの失敗したクラス間の例では、同じチェックにより、A が AT にあり、C が CG にあることが特定されます。 この条件はインデックス 0 ですぐに失敗し、アルゴリズムは追加の処理を必要とせずに NO を出力します。 

X = "CGTAC" と Y = "CGTAC" のような同一の文字列の場合、すべてのインデックスでグループ メンバーシップが保持されるため、アルゴリズムはスキャン全体にわたって有効性を確認し、YES を返します。
