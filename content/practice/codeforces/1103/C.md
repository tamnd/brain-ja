 ## 解決策
 ## 問題の理解

 すべての頂点が少なくとも 3 次を持つ、接続された無向の単純なグラフが与えられます。 グラフとともに、整数も与えられます。$k$。 タスクは、単一の構造を計算することではなく、2 つの根本的に異なる構造のどちらかを決定することです。 

1 つのオプションは、頂点の数が少なくとも次の単純なパスを見つけることです。$\lceil \frac{n}{k} \rceil$。 パスは頂点を繰り返してはいけないため、グラフ内の単なるチェーンになります。 

もう 1 つのオプションは、正確に構築することです$k$頂点が分離された単純なサイクル。 各サイクルには少なくとも 3 つの頂点が含まれている必要があり、その長さは 3 で割り切れてはなりません。 さらに、すべてのサイクルには、他のサイクルには現れない指定された代表頂点がなければなりません。 

出力では、有効なパスまたは完全なサイクル システムのいずれかを使用できます。 どちらも構築できない場合は、印刷します$-1$。 問題の構造により、グラフに長いチェーンが含まれているか、長さに算術上の制約があり慎重に制御された多くの短いサイクルに分解できるかのいずれかを示す必要があります。 

制約は大きく、最大で$2.5 \cdot 10^5$頂点と$5 \cdot 10^5$エッジ。 どのような解決策も本質的に線形または線形に近いものでなければなりません。 これにより、最短パスを繰り返し再計算したり、すべてのサイクルを試行したり、頂点ごとにヘビー ステートの再計算を使用したりするものは直ちに除外されます。 ローカル推論を使用した単一の DFS または BFS トラバーサルが唯一の実行可能な方向です。 

微妙なエッジの状況は、グラフが密で局所的に対称である場合 (クリークのような構造など) に現れます。 このようなグラフでは、すべての頂点が多くのサイクルに存在し、単純なサイクル抽出では、頂点をサイクル間で誤って再利用し、代表制約に違反する可能性があります。 もう 1 つの失敗例は、訪問した構造を注意深く追跡せずに貪欲にパスを拡張しようとしたときに発生します。これは、グラフの高度な度合いにより、バックトラッキングの選択肢が豊富になり、誤って処理しやすくなるためです。 

エッジ ケースの小さな例は、次の 4 つの頂点上の完全なグラフです。$k=2$。 長いパスは存在しますが、多くのサイクルも存在します。 ただし、サイクルを不用意に選択すると、有効な解が存在する場合でもサイクル間で頂点が再利用され、制約に違反する可能性があります。 

## アプローチ

 ブルートフォース解釈では、素の制約を追跡しながら、長い単純なパスを列挙するか、サイクルを明示的に検索しようとします。 パスの場合、すべての頂点に少なくとも 3 つの外向きの選択肢があるため、これはすぐに指数関数的なバックトラッキングに陥ります。 サイクルの場合、多くの素な構造を同時に検索する必要がありますが、これはサイクルのハード パッキング問題に相当します。 単一サイクルの検索でも簡単ですが、$k$算術制約のある素のサイクルでは、単純な列挙が不可能になります。 

重要な構造観察は、最小次数が高いと強い膨張動作が強制されるということです。 DFS チェーンは、構造を再検討する前に長く成長して長い単純なパスを生成するか、繰り返しバックエッジが早期に出現し、短いサイクルに変換されます。 すべての頂点の次数が少なくとも 3 であるという制約により、DFS ツリー ノードに複数の選択肢が確保され、深い成長または頻繁なサイクルの終了が保証されます。 

2 番目の重要なアイデアは、DFS バック エッジを介してサイクルを見つけたら、DFS 祖先パスに沿って適切なエッジを選択することで、その長さを法 3 で制御できるということです。 すべてのサイクルはバック エッジから祖先まで発生するため、サイクルの長さは深さの差によって決まり、これにより調整とフィルタリングが可能になります。 

したがって、問題は、再帰スタック内に十分に長いパスを構築するか、十分なバックエッジ サイクルを収集する DFS に帰着します。そこから選択します。$k$代表者が独立している有効なもの。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスとサイクルの総当たり列挙 | 指数 | O(n) | 遅すぎる |
 | バックエッジサイクル抽出を備えた DFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフを任意の頂点にルートし、親ポインターと深さを維持しながら DFS を実行します。 

1. ノード 1 から DFS を開始し、DFS ツリー内の現在のパスを表す再帰スタックを維持します。 このスタックは、グラフ内の単純なパスの候補です。 
2. いつでも再帰スタックが少なくとも長さに達した場合$\lceil \frac{n}{k} \rceil$、このスタックを必要なパスとしてすぐに出力します。 その理由は、この問題ではどちらの構造も許容されており、十分に長い DFS パスが Johnny の要件をすでに満たしているためです。 
3. DFS トラバーサル中に、現在のノードからその親ではないすでに訪問したノードへのエッジが検出されるたびに、バック エッジが検出されます。 このバック エッジは、現在のノードと祖先の間のサイクルを閉じます。 
4. バックエッジごとに$u \to v$から歩いてサイクルを再構築します。$u$まで親チェーンを上っていきます$v$。 これにより、単純なサイクルが得られます。 
5. 発見された各サイクルをその頂点リストとともに保存し、開始ノードとして代表を選択します。$u$。 この代表者をすぐにマークすることで、他のサイクルで再利用されないようにします。 
6. すべての頂点が処理されるまで DFS を継続し、考えられるすべての候補サイクルを収集します。 
7. DFS の終了後、少なくとも収集した場合$k$各サイクルの長さは少なくとも 3 であり、構造によって十分な多様性が保証されているため、有効なサイクルが得られるまで貪欲に選択します。$k$、代表的な独自性を尊重します。 
8. うまく選べたら$k$有効なサイクルを出力します。 それ以外の場合は出力します$-1$。 

重要な実装の詳細は、バック エッジは現在スタック内にある先祖のみに関係するため、DFS は「再帰スタック内」と「完全に処理された」を区別する方法で頂点を訪問済みとしてマークすることに注意する必要があるということです。 

### なぜ効果があるのか

 DFS は、サイクルを閉じるのに十分な構造に遭遇する前に長いチェーンを成長させるか、最小次数の高い制約によりバック エッジに繰り返し遭遇します。 すべてのバック エッジは DFS ツリーの基本的なサイクルに対応し、一意の代表を強制する場合、これらのサイクルは頂点に共通の要素がありません。 深さの構造により、サイクルの長さが祖先の違いから得られることが保証され、グラフの密度により、長いパスまたは十分な数のサイクルを生成することなく行き詰まることがないことが保証されます。 この二分法により、必要な 2 つの出力のうちの 1 つが存在する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

need = (n + k - 1) // k

vis = [0] * (n + 1)
par = [-1] * (n + 1)
depth = [0] * (n + 1)
stack = []
cycles = []
path_answer = None

def dfs(u, p):
    global path_answer
    vis[u] = 1
    stack.append(u)

    if len(stack) >= need and path_answer is None:
        path_answer = stack[:]

    for v in g[u]:
        if v == p:
            continue
        if vis[v] == 0:
            par[v] = u
            depth[v] = depth[u] + 1
            dfs(v, u)
            if path_answer:
                return
        else:
            # back edge
            if depth[v] < depth[u]:
                cycle = []
                x = u
                cycle.append(x)
                while x != v:
                    x = par[x]
                    cycle.append(x)
                if len(cycle) >= 3:
                    cycles.append(cycle)

    stack.pop()

dfs(1, -1)

if path_answer:
    print("PATH")
    print(len(path_answer))
    print(*path_answer)
    sys.exit()

# select cycles
good = []
used = set()

for c in cycles:
    rep = c[0]
    if rep in used:
        continue
    if len(c) % 3 == 0:
        continue
    used.add(rep)
    good.append(c)
    if len(good) == k:
        break

if len(good) < k:
    print(-1)
else:
    print("CYCLES")
    for c in good:
        print(len(c))
        print(*c)
```DFS は、候補パスとして直接機能する再帰スタックを維持するため、長いパスのチェックはノードごとに一定時間行われます。 バック エッジは、親ポインターを使用してサイクルを再構築するためにすぐに使用されるため、追加の BFS や反復的な走査は必要ありません。 

代表的な制約は、各サイクルの最初の頂点を使用済みとしてマークすることによって強制され、重複が防止されます。 モジュロ 3 フィルターは選択時に適用されるため、有効なサイクルのみが最終的な答えにカウントされます。

### 例 2

 DFS がサイクルをすぐに閉じる密なグラフ、たとえばバック エッジの繰り返しを保証する追加のアタッチメントを持つ三角形を考えてみましょう。 DFS は複数のバック エッジを生成します。 

| ステップ | スタック | バックエッジ | サイクル |
 | --- | --- | --- | --- |
 | 1 | [1,2,3] | 3→1 | [3,2,1] |
 | 2 | [1,2,4] | 4→1 | [4,2,1] |
 | 3 | 収集されたサイクル | 2 つのサイクルが存在します | 有効な場合は選択 |

 サイクルの代表が異なるため、モジュロ制約を満たしていれば両方を使用できます。 

これは、バック エッジがどのようにして必要なサイクル候補を自然に生成するかを示しています。

 ## 特殊なケース

 重要なケースの 1 つは、バック エッジが現れる前に DFS がすぐに長いチェーンを形成する場合です。 その状況では、再帰スタックのみが、サイクル抽出を待たずにパス出力をトリガーする必要があります。 

もう 1 つのケースは、多くのバック エッジが存在するが、サイクルの代表が衝突する場合です。 アルゴリズムは、頂点が一度代表として使用されると、それが決して再利用されないことを保証する必要があります。 これがないと、構造的に十分なサイクルが存在する場合でも、サイクルが重なり、素の要件に違反します。 

最後のケースは、多くの候補についてサイクル長が 3 で割り切れる場合です。 フィルタリング ステップは選択前に実行する必要があります。そうしないと、無効なサイクルが時期尚早にカウントされ、到達できない可能性があります。$k$有効な代替手段が存在する場合でも、有効な代替手段が存在します。
