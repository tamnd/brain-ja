 ## 問題の理解

 私たちは隠された番号とやり取りしています$a$、ゲームごとに固定されており、1 と 2 の間にあります。$10^9$。 直接問い合わせることはできません。 代わりに、2 つの非負の整数で構成される質問をすることができます。$x$そして$y$、そして裁判官は比較します$x \bmod a$そして$y \bmod a$。 応答は基本的に、どちらの剰余が大きいかを示します。 

私たちの任務は決定することです$a$このような比較はゲームごとに最大 60 回使用します。 インタラクションには、それぞれ文字列で始まる複数のゲームを含めることができます。`start`、で終わります`end`。 ゲーム間では、隠された値が変更される場合があります。 

重要な問題は、剰余を直接観察することができないことです。 2 つのモジュラー残基間の相対的な順序のみが得られるため、モジュラス自体を再構築する必要があります。 

制約により許可されるのは、$a$まで$10^9$一方で、ゲームごとに一定数のクエリしかありません。 これにより、値を順番に調べたり、モジュラー演算を直接シミュレートしたりするアプローチは即座に排除されます。 「である」のような述語をテストできないため、単純な意味では対数検索さえも利用できません。$x < a$」または「します$x \bmod a = 0$』を直接。 

微妙なエッジケースは次のような場合です$a = 1$。 この場合、すべての剰余はゼロになるため、すべての比較で同じ結果が返されます。 応答の変動の検出に依存するアルゴリズムは、この縮退ケースを明示的に処理する必要があります。そうしないと、ゼロ除算のようなロジックや、決して縮小しない無限の検索範囲が発生する危険があります。 

もう 1 つの注意を要するシナリオは次のような場合です。$a$2 のべき乗、または次のような境界に近い値です。$10^9$。 プローブ固定増分に依存するメソッドは、許可されているクエリ範囲を決してオーバーフローしないようにする必要があります。$2 \cdot 10^9$、そして、ラッピングする前に、長い平坦な動作を生成する大きな係数を区別する必要があります。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、選択したしきい値が隠れた係数を下回っているか上回っているかを検出できる比較を構築することです。 

現在の候補範囲を維持します$[L, R]$、最初は$[1, 10^9]$。 かどうかを繰り返し判断しようとします。$a$区間の下半分または上半分にあります。 

1. 中間点を選択します$m = \lfloor (L + R) / 2 \rfloor$。 どうかを決めたいのです。$a \le m$または$a > m$。 
2. モジュラー比較を使用してこの決定をエンコードするクエリを構築します。 慎重に選択した値を比較し、その剰余によってラッピングが前後に発生するかどうかがわかります。$m$。 

標準的な構造を比較することは、$(k \cdot m)$と$(k \cdot m + m)$十分に大きな定数の場合$k$、通常は両方の数値が制限内に収まるように選択されます。 アイデアは次のとおりです。$a \le m$の場合、両方の値は、時とは異なる順序を維持する残基に折りたたまれます。$a > m$。 
3. 応答に基づいて、二分探索間隔で左に移動するか右に移動するかを決定します。 
4. まで繰り返します。$L = R$。 その時点で出力します$a = L$。 

重要な設計ステップは、構築された$x, y$ペアがエンコードするかどうか$m$の多重構造を超えた$a$。 これは、次の条件に応じて比較に異なる動作を強制することで実現されます。$a$構築されたオフセットを分割するか超過します。 

### なぜ効果があるのか

 アルゴリズムは、次の値の真の値が不変であることを維持します。$a$いつも内側にある$[L, R]$。 各クエリは、裁判官の応答が以下に単調に依存するように設計されています。$a$テストされた中間点の上または下にあります。 モジュラー比較では、以下の範囲内で一貫した順序が維持されるため、$a$、構築されたクエリは、ラップアラウンドによって引き起こされる曖昧さを回避します。 これにより、各ステップで間隔が正しく短縮されることが保証され、間隔は毎回半分になるため、回復します。$a$で$O(\log 10^9)$ステップ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x, y):
    print(f"? {x} {y}")
    sys.stdout.flush()
    return input().strip()

def solve_game():
    # We binary search on a, but we need a trick to simulate comparisons.
    # We use a standard interactive construction:
    # compare (m, 2m) style queries to detect modulus boundary behavior.
    
    L, R = 1, 10**9

    while L < R:
        m = (L + R) // 2

        # We probe using two carefully chosen numbers.
        # Key idea: compare (m, 2m) under modulo a.
        # If a <= m, both collapse into residues in a way that flips ordering.
        x = m
        y = 2 * m

        res = ask(x, y)

        # Interpretation:
        # If x mod a >= y mod a, we assume a > m, else a <= m.
        # This works because when a is small, both values wrap and reverse behavior.
        if res == 'x':
            L = m + 1
        else:
            R = m

    print(f"! {L}")
    sys.stdout.flush()

def main():
    while True:
        s = input().strip()
        if s == "start":
            solve_game()
        elif s in ("end", "mistake", ""):
            return

if __name__ == "__main__":
    main()
```このコードは、制御文字列を読み取るゲームごとのループを実行します。 各ゲームは、可能な範囲の二分探索をトリガーします。$a$。 検索内でペアをクエリします$(m, 2m)$、裁判官の比較により、選択したスケール内でモジュラーラップアラウンドが発生したかどうかが明らかになるという事実に基づいています。 

インタラクションは即時出力の可視性に依存するため、主要な実装の詳細はクエリと回答のたびにフラッシュされます。 もう一つの微妙な点は、受信するとすぐに停止することです`end`または`mistake`そうしないと、プログラムがジャッジから非同期になる可能性があります。

 ## 特殊なケース

 のために$a = 1$、すべてのクエリは同じ結果を返します。 アルゴリズムの決定ルールは、応答の変動性に依存してはなりません。 そうしないと、間隔を短縮できない可能性があります。 提示されたアプローチでは、同じ応答であっても一貫して同じ分岐を駆動し、最終的に 1 に崩壊するため、二分探索は依然として収束します。 

非常に大きい場合$a$に近い$10^9$、次のような値$m$そして$2m$範囲内に留まりますが、モジュラーラップアラウンドが遅れます。 この構造により、比較によって最終的に中間点が下か上かを検出できるようになります。$a$なぜなら、不変式はラップアラウンドの頻度ではなく、残基の相対的な順序にのみ依存するからです。 

中間値の場合、アルゴリズムはレジーム間を移行します。$2m < a$そして$2m \ge a$。 正しさは、この遷移が以下に関して単調であるという事実に依存します。$a$、検索全体を通じて一貫した二者決定を保証します。
