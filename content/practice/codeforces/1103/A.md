 ## 解決策
 ## 問題の理解

 私たちは空から始まる固定の 4 × 4 ボードに取り組んでいます。 ドミノの流れは 1 つずつ到着し、各ドミノは到着したらすぐに配置する必要があります。 

各ドミノは、同じ列の 2 つのセルをカバーする垂直方向、または同じ行の 2 つのセルをカバーする水平方向のいずれかです。 ボードが配置されると、ボードが変更される場合があります。いずれかの行が完全に埋まると、その行全体が同時に消去されます。 同様に、いずれかの列が完全に埋まると、その列も消去されます。 これらの削除は各配置後に発生し、複数の行または列を一度にクリアする可能性があります。 

タスクは、入ってくるすべてのドミノを現在空いているセルに常に収まるように配置する場所を決定することであり、すべての配置の位置を出力する必要があります。 出力位置は、そのドミノがタッチした最小の行と列で、垂直ドミノの左上のセル、または水平ドミノの左端のセルに対応します。 

重要な制約は、ボードが非常に小さく、わずか 16 セルであるのに対し、ドミノの数は最大 1000 まで大きくなる可能性があるということです。これにより、複雑なグローバル最適化を長期にわたって維持しようとする戦略は即座に排除されます。 各ステップが 4 × 4 グリッドにわたる小規模な固定検索によって制限されている限り、定数係数の非効率なシミュレーションでも問題ありません。 

微妙な難しさは削除ルールにあります。 行や列のクリアをシミュレートせずに単に「セルを貪欲に埋める」という単純なアプローチは、最終的には機能しません。以前にブロックされていたスペースが削除後に突然再び現れる可能性があるためです。 もう 1 つの失敗例は、固定パターンの配置を想定していることです。 削除により状態が動的になり、過去の配置に依存します。 

最後のエッジケースは、複数の行または列が同時にいっぱいになる場合です。 これらはすべて同時にクリアする必要があります。そうしないと、後の配置でセルがまだ占有されていると誤って認識される可能性があります。 

## アプローチ

 ブルートフォース解釈では、各ステップで各ドミノの可能な配置をすべてシミュレートしようとします。 受信するピースごとに、すべての有効な位置をスキャンし、将来の配置を再帰的に試行します。 4 × 4 のボード上でも各ステップには最大数十の配置の選択肢があり、1,000 のステップが存在する可能性があるため、これはすぐに指数関数的になります。 剪定を行ったとしても、分岐要因によりこれは実行不可能になります。 

重要な点は、ボードが非常に小さいため、前を見る必要がないということです。 代わりに、常に有効な構成を維持しながら、貪欲にシミュレーションを行うことができます。 削除によりボードの一部が継続的にリセットされるため、最終的なパックされた構成に向けて構築するのではなく、ほぼ新しいボード上で小さなパッキングの問題を繰り返し解決します。 

これにより、建設的な戦略が可能になります。ドミノごとに、現在のボードの状態に適合する最初の有効な配置を検索するだけです。 配置後、すぐにボードを更新し、完全な行または列をクリアします。 グリッドのサイズは一定であるため、すべての可能性をチェックするには一定の時間がかかり、完全なシミュレーションは入力の長さにおいて線形です。 

これが機能する理由は、ローカルで有効な配置で十分だからです。 削除により、ボードに不可逆的な制約が蓄積されないことが保証されます。 代わりに、スペースを継続的に解放し、行き止まりを防ぎます。

 ## アルゴリズムのチュートリアル

 占有セルを表す 4 × 4 のブール グリッドを維持します。 

1. 入ってくるドミノごとに、有効な配置を見つけるために一定の順序でグリッドをスキャンします。 

水平ドミノの場合、(r, c) と (r, c+1) の両方が空になる行 r と列 c を探します。 垂直ドミノの場合、空の (r, c) と (r+1, c) を探します。

スキャン順序が固定されているため、決定性が保証され、曖昧さが回避されます。 
2. 有効な配置が見つかったら、2 つのセルを占有済みとしてマークし、出力座標を 1 ベースのインデックスで (r, c) として記録します。 
3. 配置後、すべての行をチェックします。 行の 4 つのセルがすべて占有されている場合は、セルを空に設定してクリアします。 
4. 次に、すべての列をチェックします。 列の 4 つのセルすべてが占有されている場合は、同様にその列をクリアします。 
5. 行をクリアすると列がいっぱいになる可能性があり、その逆も同様であるため、行または列が完全に埋められなくなるまでこのクリア ステップを繰り返します。 

繰り返しクリアする理由は、1 つの配置が一連の削除を引き起こす可能性があるためです。 

### なぜ効果があるのか

 すべてのステップで、グリッドはすべての削除が適用された後のアクティブ セルの現在のセットを正確に表します。 ボードには最大 16 個のセルがあり、削除によって永久的な飽和が防止されるため、スキャンでは常に配置が検出されます。 ドミノを 2 つの空のセルに配置するだけなので、重複制約に違反することはありません。 クリア ルールにより、行または列がいっぱいになるとすぐに削除され、容量が復元され、デッドロックが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def clear(board):
    changed = True
    while changed:
        changed = False

        # check rows
        for r in range(4):
            if all(board[r][c] for c in range(4)):
                for c in range(4):
                    board[r][c] = 0
                changed = True

        # check cols
        for c in range(4):
            if all(board[r][c] for r in range(4)):
                for r in range(4):
                    board[r][c] = 0
                changed = True

def solve():
    s = input().strip()
    board = [[0] * 4 for _ in range(4)]
    out = []

    for ch in s:
        placed = False

        if ch == '1':  # horizontal
            for r in range(4):
                for c in range(3):
                    if board[r][c] == 0 and board[r][c + 1] == 0:
                        board[r][c] = board[r][c + 1] = 1
                        out.append((r + 1, c + 1))
                        placed = True
                        break
                if placed:
                    break

        else:  # vertical
            for r in range(3):
                for c in range(4):
                    if board[r][c] == 0 and board[r + 1][c] == 0:
                        board[r][c] = board[r + 1][c] = 1
                        out.append((r + 1, c + 1))
                        placed = True
                        break
                if placed:
                    break

        clear(board)

    print("\n".join(f"{r} {c}" for r, c in out))

if __name__ == "__main__":
    solve()
```このソリューションでは、文字通り 4 × 4 の占有グリッドが維持され、複雑なデータ構造が回避されます。 配置ロジックは決定論的なスキャンであり、常に最初に利用可能なフィットを選択します。グリッドが小さく、最適なパッキングを必要としないため、これは安全です。 

行と列の削除は連鎖する可能性があり、安定するまで削除を適用し続ける必要があるため、クリア関数は分離されています。 

よくある間違いは、繰り返し消去を忘れることです。同じステップで列を削除した後に新しく完成した行が形成された場合、その行が削除されないままになる可能性があります。

 ## 特殊なケース

 微妙なケースの 1 つは、単一の明らかな埋め込みではなく、時間の経過とともにドミノ配置パターンの後半が原因で行がいっぱいになる場合です。 すべての配置後にクリアが適用され、古い完全な行が状態に残らないようにするため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、行と列の同時完了です。 繰り返しのクリア ループにより、一方が間接的に他方をトリガーした場合でも両方が確実に削除され、一貫性のない中間状態が防止され、ボードが次の配置に対して有効なままであることが保証されます。
