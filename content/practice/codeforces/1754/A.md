 ## 解決策
 ## 問題の理解

 私たちに与えられる一連のチャット メッセージは、クライアントの質問とサポートの回答の 2 種類のみで構成されます。 会話は時間順に書かれており、最初のメッセージは常に質問です。 

私たちが気にする唯一の構造的ルールは、すべての質問はその後に続く答えによって「説明」されなければならないということです。 それぞれの回答は、以前に尋ねられた質問に応答することになっており、回答を遅らせたり、インターリーブしたりすることはできますが、事前に一致しない質問がなければ回答は存在できません。 言い換えれば、対話のどの時点においても、それまでに出てきた質問を超える答えが出てはならず、最終的にはすべての質問が答えと一致していなければなりません。 

タスクは、テスト ケースごとに、そのようなシーケンスがこれらのルールの下で有効であるかどうかを判断することです。 

制約は小さく、テスト ケースは最大 500 個で、各文字列の長さは最大 100 です。これは、テスト ケースごとのソリューションが O(n²) または O(n) であっても、わずかに高速であることを意味します。 テストごとに小さな実行状態を追跡するだけで済みます。 

素朴な間違いは、すべての質問の直後に 1 つの回答が必ず続くと想定することです。 たとえば、文字列「QQAA」は、2 番目の回答が遅れても有効です。これは、回答をグループ化でき、対応する質問に直接従う必要がないためです。 

もう 1 つの微妙な失敗例は、十分な質問が存在する前に答えが現れる場合です。 たとえば、「QAQ」は無効です。「QA」を消費した後、次の「Q」によって保留中の質問が増加しますが、前の回答が一貫した構造で適切にペアになっていることが保証されず、一致しない質問が最後に残ります。 

重要な隠れた制約はプレフィックスの有効性です。どのプレフィックスでも、回答が質問を超えてはならず、最後のカウントは等しくなければなりません。 

## アプローチ

 ブルートフォース解釈では、おそらくスタックを使用するか、ペアを明示的に追跡して、各回答を以前の不一致の質問と明示的に一致させようとします。 回答ごとに、利用可能な質問を逆方向に検索し、使用済みとしてマークして、続行します。 これは正しいですが、文字ごとに繰り返しスキャンまたはブックキーピングを行う必要があるため、不必要に重くなり、リストまたは繰り返し検索で適切に実装されていない場合、O(n²) 動作が発生する可能性があります。 

すべてを単純化する観察は、各回答がどの特定の質問に属するかは気にしないということです。 唯一の要件は、回答がどのプレフィックスでも利用可能な質問を超えないことです。 これにより、問題全体が 1 つのカウンター (現在未回答の質問の数) を維持することに集約されます。 

「Q」ごとにカウンターをインクリメントします。 「A」ごとに、それをデクリメントします。 どこかの時点でそれが否定的になる場合は、まだ存在しない質問に答えようとしたことを意味し、無効です。 最終的に、ネガティブにならなければ、この構造は有効です。 

これは事実上、括弧の検証に似たバランス条件であり、「Q」は開始括弧のように動作し、「A」は閉じ括弧のように動作しますが、終了を任意に遅らせることができるという工夫が施されています。

 | --- | --- | --- | --- |
 | ブルートフォースマッチング | O(n²) | O(n) | 受け入れられるが不要 |
 | カウンタートラッキング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`pending = 0`まだ回答されていない質問の数を表します。 
2. メッセージ文字列を左から右に繰り返します。 
3. 現在の文字が「Q」の場合、インクリメントします。`pending`答えのない新たな疑問が現れるからです。 
4. 文字が「A」の場合、デクリメントします。`pending`なぜなら、回答には以前に尋ねられた質問が 1 つ消費されるからです。 
5. いつでも`pending`否定的な場合は、対応する以前の質問なしで回答が表示されたため、対話は無効であると直ちに結論付けます。 
6. 文字列全体を処理した後、次の場合は「Yes」を出力します。`pending == 0`それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 文字列の任意の接頭辞で、`pending`は、今後も回答が必要な質問の数を正確に表しています。 回答が以前の質問に対応している必要があるというルールは、このカウントが決してゼロを下回らないようにすることを要求するのと同じです。 ゼロを下回った場合、回答によっては添付できる質問がありません。 否定的ではないまま肯定的に終わる場合は、一部の質問が回答されなかったことを意味し、これも要件に違反します。 

この不変条件により正確さが保証されます。すべての有効なシーケンスは全体を通して非負のバランスを維持し、そのバランスの違反は無効な対話構造に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    pending = 0
    ok = True
    
    for ch in s:
        if ch == 'Q':
            pending += 1
        else:
            pending -= 1
            if pending < 0:
                ok = False
                break
    
    print("Yes" if ok and pending == 0 else "No")
```実装はカウンタ ロジックに直接に従います。 無効なプレフィックスが検出されると、それ以降の処理では有効性を復元できないため、早期の中断が重要です。 最終チェックでは、未回答の質問がないことを確認します。 

ここでよくあるオフバイワンスタイルの間違いは、最終残高がゼロであることを確認するのを忘れることです。 シーケンスは全体を通して有効性を維持できますが、依然として質問が残されて終了するため、その質問は拒否する必要があります。

 ## 特殊なケース

 特殊なケースの 1 つは、単一の質問です。 「Q」を入力すると保持されます`pending = 1`そして決して減らさないので、最終チェックは失敗し、正しく拒否されます。 

もう 1 つは、質問の多い接頭辞の後に最初に表示される回答です。 入力「QQAQA」の場合、カウンタは最後のプレフィックスまで有効のままですが、それでも正で終了し、正しく無効とマークされます。 

より微妙なケースは、「QAQAQA」のようなインターリーブです。 カウンタは 1 と 0 を繰り返しますが、負になることはなく、0 で終了するため、有効です。 これは、アルゴリズムが回答のグループ化を必要とせず、バランスの維持のみを必要とすることを確認します。
