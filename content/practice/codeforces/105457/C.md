 ## 解決策
 ## 問題の理解

 授業スケジュールのリストが与えられます。各クラスのスケジュールは、1 つの円形の日の開始時刻と終了時刻で表されます。`m`離散的な時間。 各クラスは、開始時間から終了時間までの半開時間間隔を占めます。タスクは、選択した 2 つのクラスが時間的に重ならないように、できるだけ多くのクラスを選択することです。 

時間はから直線的です`0`に`m`, したがって、解釈は「1 日の時間」ですが、ラップアラウンドはありません。 唯一の制約は、選択した間隔がペアごとに素である必要があり、クラスが時刻で終了するため、エンドポイントでのタッチが許可されることです。`t`で始まるものとは重なりません`t`。 

入力には複数の独立したテスト ケースが含まれる場合があり、それぞれに最大`5 · 10^5`最も難しいバージョンのインターバル。 このスケールでは、間隔のペアを比較したり、サブセットを調査したりするソリューションは直ちに除外されます。 二次関数または偶数`O(n log n)`テストケースごとのソリューションはまだ問題ありませんが、これより悪いものはありません`O(n log n)`繰り返しソートが実行時間を支配するため、全体的には失敗します。 

複数の間隔が同じ開始時刻または終了時刻を共有する場合、微妙なエッジ ケースが発生します。 たとえば、次のように考えてみましょう`m = 2`間隔あり`[0, 2]`、`[0, 1]`、`[1, 2]`。 最適な答えは`2`ただし、常に最も早い開始間隔を選択する単純な戦略では、`[0, 2]`そして他のすべてをブロックします。 間隔がネストされている場合、別の落とし穴が発生します。`[0, 10]`、`[1, 2]`、`[2, 3]`, ここで、正解は 1 ではなく 2 です。 

これらのケースは、開始時間のみに基づいたローカルの貪欲な決定では不十分であることを示しています。 

## アプローチ

 ブルートフォースアプローチでは、間隔のすべてのサブセットを試し、選択したサブセットに重複がないかどうかを確認し、最大サイズを追跡します。 1 つのサブセットのコストの妥当性をチェックする`O(n)`単純に並べ替えやスキャンを行った場合、`2^n`サブセットであるため、これは`n = 30`。 もう 1 つのもう少し良いアイデアは、枝刈りによるバックトラックです。ただし、早期の枝刈りを避けるために間隔を調整できるため、最悪の場合の動作は依然として指数関数的な時間にまで縮退します。 

重要な観察は、間隔を終了時間で並べ替えると、問題には最適な部分構造と貪欲な選択特性があるということです。 利用可能な選択肢の中で最も早く終了する間隔を選択すると、将来の間隔のために残りの空き領域が最大化されます。 後で終了する代替選択は、適合できる間隔の数を増やすことなく、将来の選択を制限または遅延させることしかできません。 

これにより、問題は古典的な間隔スケジューリングの最大化問題に変換されます。 終了時間で並べ替えることにより、すべてのステップで局所的に最適な選択が行われ、最大限の柔軟性が確保されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 (貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての間隔を読み取り、ペアとして保存します`(a, b)`。 これらは、重複せずに選択する必要がある固定時間ブロックを表します。 
2. すべての間隔を終了時刻で並べ替えます`b`。 この順序の理由は、より早い終了間隔を選択すると、将来の可用性が最大限に保たれるためです。 
3. 変数を初期化する`current_time = 0`、次の間隔をスケジュールできる最も早い時間を追跡します。 
4. ソートされた順序で間隔を繰り返します。 
5. インターバルごとに`(a, b)`、 もし`a >= current_time`を選択して設定します`current_time = b`。 これにより、重複することがなくなり、常に最も早い終了互換間隔が適用されることが保証されます。 
6. 選択した間隔の数をカウントし、この値を出力します。 

### なぜ効果があるのか

 すべてのステップで、次の不変条件を維持します。`current_time`は最後に選択した間隔の終わりであり、選択したすべての間隔は互いに素であり、並べ替え順序を考慮するとできるだけ早く終了します。 残りのすべての候補の中で最も早く終了する間隔を考慮すると、その間隔と重複するが後で終了する代替間隔は、互換性のある間隔の数を増やすことなく、将来のスケジューリング領域を減らすだけです。 この交換引数は、最適解の最初の異なる選択を貪欲な選択に置き換えても区間の総数が減らないことを保証するため、繰り返し適用することで最適解が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    it = iter(sys.stdin.read().strip().split())
    out = []
    
    while True:
        try:
            n = int(next(it))
        except StopIteration:
            break
        m = int(next(it))  # unused, but part of format
        
        intervals = []
        for _ in range(n):
            a = int(next(it))
            b = int(next(it))
            intervals.append((b, a))  # sort by end time
        
        intervals.sort()
        
        current = 0
        ans = 0
        
        for b, a in intervals:
            if a >= current:
                ans += 1
                current = b
        
        out.append(str(ans))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、繰り返しの I/O 呼び出しによるオーバーヘッドを回避するために、すべての入力を一度に読み取ります。これは、合計サイズが数十万の間隔に達する可能性があることを考えると重要です。 

間隔は次のように保存されます。`(end, start)`具体的には、Python のデフォルトのタプル ソートで、追加のコンパレータ ロジックを使用せずに最初に終了時刻で並べ替えられるようにします。 これは、タイトなループでカスタム ソート キーを使用するよりも簡単かつ高速です。 

貪欲なスイープは維持します`current`、最後に選択した間隔の終わりを表します。 条件`a >= current`問題の定義と一致する連続したスケジュールを許可しながら、非重複を強制します。

 ## 特殊なケース

 最初の特殊なケースは、間隔が完全にネストされている場合です。 入力を考慮してください:```
3 10
0 10
1 9
2 8
```アルゴリズムは終了時間で並べ替えて選択します`(2,8)`初め？ いいえ、実際には選択されます`(8,2)`選択した間隔が終了する前にすべてが開始されるため、他のものは最も早い終了として拒否されます。 最終的な答えは、`1`この構成では重複せずに 1 つの間隔のみを選択できるため、最適な動作と一致します。 

もう 1 つのエッジ ケースは、連続した間隔が緊密に連鎖している場合です。```
3 10
0 2
2 4
4 6
```ここで、各間隔は、前の間隔が終了したときに正確に開始されます。 貪欲な状態`a >= current`それらをすべて選択できます。 アルゴリズムは終了時刻の昇順に処理し、更新します。`current`ステップバイステップと出力`3`、これが最適です。 

3 番目のケースでは、終了時間が同じになります。```
3 10
0 5
1 5
2 5
```並べ替えると、すべての間隔が同じ終わりを共有します。 貪欲なプロセスは、最初に遭遇した開始が有効なものを選択し、残りを拒否します。`current`になる`5`。 結果は`1`すべての間隔が時間 5 までの期間全体で重複しているため、これは正しいです。
