 ## 解決策
 ## 問題の理解

 私たちには、次のように分割された土地が与えられています。$n$それぞれの高さが固定された連続したセグメント。 時間の経過とともに、海面は段階的に上昇します。上昇するたびに、つながった乾燥地のグループがいくつ残っているかを判断する必要があります。 

セグメントの高さが現在の海面しきい値条件を厳密に超えている場合、そのセグメントは乾燥していると見なされます。$a_i > m$、そうでない場合は水没します。 元のラインで隣接するドライ セグメントは 1 つのアイランドを形成するため、アイランドは単純に、高さが現在の海面よりも高いインデックスの最大連続ブロックです。 

毎年、海面が上昇するにつれて一部の地域が恒久的に浸水し、既存の島々がより小さな島に分割されるか、完全に消滅することしかありません。 

入力は複数の独立したケースで構成されます。 それぞれのケースで、高さの配列と厳密に増加する海面の順序が得られます。 海面ごとに、接続された乾燥コンポーネントの数を出力する必要があります。 

制約により構造が明確になります。$n$そして$k$到達できる$10^5$そのため、クエリのたびにアイランドを最初から再計算すると、時間がかかりすぎます。 クエリごとに配列を繰り返しスキャンするソリューションにはコストがかかります$O(nk)$に達する$10^{10}$最悪の場合、操作が不可能になり、実行できなくなります。 

素朴なアプローチの微妙な失敗例は、前の状態を記憶しないで再計算することです。 たとえば、高さを考えてみましょう$[5, 1, 5]$そして海面$1$それから$5$。 レベルで$1$2 つの島があります。位置 0 と 2 はドライです。 レベルで$5$、すべてが水没しているため、答えは次のとおりです。$0$。 ここでもクエリごとの単純なスキャンは機能しますが、多くの誤った最適化では、中間のフラッディングが分離イベントを逆推論で正しくマージすることを追跡せずに「ローカルでカウントを更新」しようとします。これにより、複数のポイントが同時にフラッディングすると一貫性が失われます。 

もう 1 つの重要なエッジ ケースは、高さが等しいことです。 洪水はいつ起こるので$a_i \le m_i$、セグメントは高さのしきい値で正確に消え、等価性を正しく処理できないと、島の数が 1 つずつずれてしまいます。 

## アプローチ

 直接的なアプローチでは、アレイ全体をスキャンし、乾燥セグメントが開始される回数をカウントすることにより、各海面後に島の数を再計算します。 これが機能するのは、すべての島が乾電池の連続した実行であるため、いつでも新しい島を検出できるためです。$a_i > m$そしてどちらか$i = 0$または$a_{i-1} \le m$。 正確さは簡単ですが、すべてのクエリに対してこれを実行すると、同じ完全な走査が繰り返されます。$k$回。 

ボトルネックは明らかです: 各クエリにコストがかかります$O(n)$したがって、全体の複雑さは次のようになります。$O(nk)$。 どちらも最大で$10^5$、これは実際的な限界をはるかに超えています。 

重要な観察は、フラッディングが単調であるということです。 一度水没したセグメントは二度と戻りません。 プロセスを前方にシミュレートする代わりに、視点を逆にします。最初にすべての土地が浸水していると想像し、海面の降順にセグメントを「洪水から解放」するか、または高さを増加させることと同等にセグメントを処理します。 

セグメントを高さで並べ替える場合、セグメントを「アクティブ化」するたびに（海面がその下を通過するにつれて乾燥することを意味します）、そのセグメントは新しい島を形成するか、隣接する島がすでにアクティブである場合は 2 つの既存の島を結合します。 これは回線上の古典的な動的接続プロセスであり、素セット構造で維持できます。 

これをクエリと結びつけるために、アクティベーションを高さの昇順に処理すると同時に、クエリを海面の昇順に処理します。 クエリしきい値ごとに、そのしきい値を超える高さのすべてのセグメントをアクティブ化し、接続されたコンポーネントを維持します。 

アクティブ化するたびに、隣接する島がアクティブかどうかに応じて、島の数が 1 つ増加するか減少します。 行上のユニオン検索により、各マージが確実に行われます。$O(\alpha(n))$、ほぼ線形の解決策が得られます。

 ## アルゴリズムのチュートリアル

 私たちは問題を逆活性化プロセスに変換し、土地が最も高いものから最も低いものへと徐々に現れるようにします。 

1. 各セグメントのインデックスとその高さをペアにし、これらのペアを高さの降順に並べ替えます。 これにより、土地を最も高いものから最も低いものへとアクティブにすることができ、セグメントがアクティブになったときに、より高いすべてのセグメントがすでにアクティブであることが保証されます。 島の構造は絶対的な高さではなく、隣接する島がアクティブかどうかのみに依存するため、この順序付けは非常に重要です。 
2. 元のインデックスを維持しながら、クエリを海面の降順で並べ替えます。 各クエリはしきい値を表します。 回答する前に、そのしきい値を厳密に超えてすべてのセグメントをアクティブにします。 
3. ブール配列を維持する`active[i]`セグメントかどうかを示す$i$現在乾燥中です。 また、アクティブなセグメント間の接続されたコンポーネントを追跡するために、インデックス上で素セットの共用体構造を維持します。 
4. カウンターを維持する`islands`ゼロに初期化されます。 新しいセグメントがアクティブになるたびに、それを暫定的に新しい島として扱います。 
5.ポジション発動時$i$、その左隣をチェックしてください$i-1$そして右隣$i+1$。 近隣がアクティブな場合、セットを結合します。 以前は別々だった 2 つのコンポーネントが結合されるたびに、アイランド数が 1 つずつ減ります。 これにより、カウントが接続されたアクティブ コンポーネントの数と常に一致するようになります。 
6. クエリを降順に処理します。 各クエリ値について$m$、高さより大きいすべてのセグメントをアクティブにします。$m$。 このようなすべてのアクティベーションを処理した後、現在の`islands`その質問に対する答えとして。 
7. 回答を元のクエリ順序に戻します。 

重要な不変条件は、いつでも DSU コンポーネントがアクティブなインデックスの連続ブロックに正確に対応するということです。 許可される接続は隣接のみであるため、各コンポーネントは 1 つのアイランドを表します。 新しいセルをアクティブ化すると、新しい孤立したコンポーネントが作成されるか、最大 2 つの隣接コンポーネントとマージされ、アイランド数が正しく更新されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve_case(n, k, a, m):
    segs = sorted([(a[i], i) for i in range(n)], reverse=True)
    queries = sorted([(m[i], i) for i in range(k)], reverse=True)

    dsu = DSU(n)
    active = [False] * n

    ans = [0] * k
    ptr = 0
    islands = 0

    for qval, qi in queries:
        while ptr < n and segs[ptr][0] > qval:
            h, i = segs[ptr]
            active[i] = True
            islands += 1

            if i > 0 and active[i - 1]:
                if dsu.union(i, i - 1):
                    islands -= 1
            if i + 1 < n and active[i + 1]:
                if dsu.union(i, i + 1):
                    islands -= 1

            ptr += 1

        ans[qi] = islands

    return ans

def main():
    data = sys.stdin.read().strip().split()
    idx = 0
    out = []

    while idx < len(data):
        n = int(data[idx]); k = int(data[idx + 1])
        idx += 2
        a = list(map(int, data[idx:idx + n]))
        idx += n
        m = list(map(int, data[idx:idx + k]))
        idx += k

        res = solve_case(n, k, a, m)
        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```DSU は、現在アクティブなセグメント間の接続を追跡します。 の`active`配列により、すでに浸水していない土地のみが結合されることが保証されます。 各結合は 2 つのアイランドの結合に対応するため、カウンタをデクリメントすると正確さが保たれます。 

実装の微妙な詳細は厳密な比較です`a[i] > m`。 これが、アクティベーションを使用する理由です。`> qval`。 間違って使ってしまったら`>=`、正確に水位にあるセグメントは正しく処理されず、アクティブな状態が長すぎるため、島の数が膨らみます。 

ポインタ`ptr`すべてのクエリにわたって各セグメントが 1 回アクティブ化されることを保証し、並べ替え後のスイープを線形にします。

 ## 特殊なケース

 重要なエッジ ケースは、複数の隣接するセグメントが同じクエリ ウィンドウ内でアクティブになり、すぐにマージされる場合です。 インプットを考慮する`a = [3, 2, 1]`クエリしきい値あり`0`。 すべてのセグメントは順次アクティブ化されますが、アイランド数は 3 ではなく 1 で終了する必要があります。アルゴリズムは、アクティブ化時にアイランドをインクリメントし、すぐに隣接するものとマージし、結合が成功するたびに減分することでこれを処理し、最終的にマージされた構造が正しいことを確認します。 

もう 1 つのケースは、クエリに対してアクティブ化されたセグメントがない場合です。 海面がすでにすべての高さを超えている場合、ポインタは動かず、答えは前の状態のままであり、新しい陸地が現れないことを正確に反映しています。 

3 番目の微妙なケースは、高さが同じで、しきい値が正確に一致する場合です。 アクティベーションでは厳密な比較が使用されるため、`>`、海面と同じ高さのセグメントは水没したままとなり、早期の島の形成が防止され、カウントが洪水の定義と一致します。
