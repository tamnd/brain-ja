 ## 解決策
 ## 問題の理解

 配列の隣接する要素間のローカル比較をエンコードする文字列が与えられます。 各文字は、次の要素が現在の要素より大きくなければならないか小さくなければならないかを示します。 タスクは、有効な配列を構築することではなく、これらすべての比較を尊重しながら、可能な限り異なる値を使用しない配列を構築することです。 

この問題を考えるのに役立つ方法は、線に沿った位置に高さを割り当てようとしており、各ステップで強制的に上昇または下降することです。 値を再利用することは許可されていますが、それが厳格な不等号要件を破らない場合に限ります。 

出力は、指定された一連の上昇と下降に従うそのような「ウォーク」を実現するために必要な個別の整数の最小数です。 

n は最大 100、t は最大 500 であるため、制約は十分に小さいため、テスト ケースごとに O(n²) 個のアイデアがすでに快適に通過します。これは、線形または二次スキャンを超えて漸近的に最適化することは期待されていないことを強く示唆しています。 本当の課題は、どのような構造が個別の値の最小数を決定するかを理解することです。 

単純な試みでは、可能な限り数値を再利用しながら、配列を明示的に構築したり、値を左から右に貪欲に割り当てたりしようとする可能性があります。 ローカルでの再利用の決定により、予測が困難な方法で将来の再利用が妨げられる可能性があるため、これはすぐに脆弱になります。 

2 番目の単純なアイデアは、狭い範囲の整数をバックトラックして、可能なすべての代入を試みることです。 位置が 100 個しかない場合でも、分岐因子には事実上制限がなく、不等式の制約があるため、ラベル付けの大きな組み合わせ空間を探索することになります。 

「<><><><」のように文字列が交互に現れる場合、より微妙な失敗例が現れます。 貪欲なアプローチでは、2 つの値を繰り返し再利用しようとする可能性がありますが、不適切に割り当てた場合、予想よりも多くの個別の値を導入する必要がある振動が発生することが判明しました。 正しい答えは、ローカルな決定ではなく、グローバル構造に依存します。 

## アプローチ

 重要な観察は、問題は実際には絶対値に関するものではなく、相対的な順序制約に関するものであるということです。 連続する要素が上に行くか下に行くかだけを考慮します。つまり、実際の数値は、上または下に移動するパスに割り当てられたラベルと考えることができます。 

個別の値の最小数は、シーケンス全体を一貫して実現するために必要な「レベル」の最小数に対応します。 上昇するたびに、必要に応じてより高い未使用レベルに移動できることを確認する必要があり、下降するたびに、その制約を逆方向に反映します。 

重要な構造的洞察は、値が歩行時の高さに対応するように、有効な割り当てをシフトおよび圧縮できることです。 コストは、訪問した個別の高さの数になります。 これにより、問題はプレフィックス合計のような構造の極値範囲の分析に縮小されます。 

「<」を +1、「>」を -1 として解釈し、実行残高を追跡する場合、この実行合計の最高値と最低値の間の最大の広がりによって、必要な個別の値の数が決まります。 直観的には、歩行が開始点から k ステップ下に進み、また何らかのシフトされた形式で k ステップ上に進む場合、それに対応するには k+1 の別個のレベルが必要です。 

これをより正確に見る方法は、各位置が累積的な動きによって決定される整数直線上の点に対応すると考えることです。 個別の値の最小数は、最適な圧縮表現における個別の高さの数であり、これはまさに到達可能なプレフィックスの極値の範囲です。 

値を明示的に割り当てるという強引なアイデアは、相対的なランクのみが重要であるということを捉えていないため、失敗します。 プレフィックス極値の追跡に切り替えると、ソリューションはテスト ケースごとに線形になります。

 ## アルゴリズムのチュートリアル

 1. 比較文字列を一連の方向ステップに変換し、各文字をランニング ポジションに影響を与える動きの制約として扱います。 
2. 実行中のカウンタをゼロに初期化します。これは、仮想構造における現在の「高さ」を表します。 
3. 文字列を左から右にトラバースします。 「<」に遭遇した場合は、カウンターを 1 つ増やします。「>」に遭遇した場合、カウンターを 1 つ減らします。これにより、配列の 1 つの有効な圧縮表現がシミュレートされます。 

これが機能する理由は、まだ実際の値を割り当てておらず、あらゆる制約を尊重する相対的な順序構造を構築しているためです。 
4. 実行中のカウンタを更新している間、トラバース中に到達した最小値と最大値の両方を追跡します。 
5. 答えは、この歩行がカバーする範囲のサイズであり、次のように計算されます。`max_value - min_value + 1`。 

この範囲は、各高さが一意の値に対応するように構造を最適に圧縮する場合に必要な個別の整数ラベルの数を表します。 

### なぜ効果があるのか

 有効な配列は、符号と一致する隣接する差分を繰り返し割り当てることによって、整数のウォークにマッピングできる一連の相対比較を引き起こします。 最小値がゼロになるようにウォークをシフトして圧縮すると、有効性は変わりませんが、個別の値の数が最小限に抑えられます。 個別の値の数は、正確に訪問される整数レベルの数であり、最小プレフィックス変位と最大プレフィックス変位の間の範囲に等しくなります。 値を再利用しようとすると、文字列の少なくとも 1 つのセグメントで厳密な順序に違反することになるため、代替の代入によってこの範囲を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        cur = 0
        mn = 0
        mx = 0

        for ch in s:
            if ch == '<':
                cur += 1
            else:
                cur -= 1
            mn = min(mn, cur)
            mx = max(mx, cur)

        print(mx - mn + 1)

if __name__ == "__main__":
    solve()
```コードは単一の走行位置を維持し、各比較に従ってそれを更新します。 この横断中に観察された最小値と最大値は、誘導された構造の範囲を定義します。 最終的な答えは、このスパンのサイズとして計算されます。 配列は比較が適用される前に開始されるため、実装ではカウンタをゼロに初期化するように注意してください。

 | 測定 | 複雑さ | 説明 |

アルゴリズムはケースごとに 1 つの線形スキャンを実行するため、最大入力サイズであっても、すべてのテスト ケースにわたる合計作業量は小さいままです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n = int(sys.stdin.readline())
        s = sys.stdin.readline().strip()

        mn = 0
        mx = 0

            if ch == '<':
                cur += 1
            else:
                cur -= 1
            mn = min(mn, cur)
            mx = max(mx, cur)

        out.append(str(mx - mn + 1))

    return "\n".join(out)

 ## 特殊なケース

 単一文字の文字列は、アルゴリズムが基本初期化を正しく処理するかどうかを明らかにします。 「<」の場合、実行値は 1 になるため、範囲は [0,1] となり、答えは 2 になります。「>」の場合、実行値は -1 になるため、範囲は [-1,0] となり、再び 2 になります。極値はゼロで初期化されるため、アルゴリズムは特別なケースを使用せずに両方を自然に処理します。 

「>>>>>>」のような完全に減少する文字列は、実行中の値を継続的に押し下げます。 最小値は減少し続けますが、最大値はゼロのままであるため、範囲は直線的に増加します。 各ステップで新たな最小値が導入され、最終的な答えは到達した合計の深さを反映します。 

「<><><><」などの交互の文字列は、2 つの隣接するレベル間で変動する実行値を維持します。 最小値と最大値は 0 と 1 ですぐに安定するため、結果は 2 のままです。これは、ウォークがその範囲を拡張することがないため、発振によって必要な個別の値が 2 を超えて増加しないことを確認します。
