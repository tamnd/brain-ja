 ## 解決策
 ## 問題の理解

 初期値がランダムである単一のカウントダウン タイマーを保持するシステムをシミュレートしています。 時間ゼロでは、タイマーは 1 から T までの間で均一に選択された整数に設定されます。その後、時間は離散秒単位で進みます。 1 秒ごとにタイマーが 1 ずつ減ります。 ゼロになった瞬間にプロセスは終了し、経過時間がペナルティとして記録されます。 

工夫としては、各デクリメント ステップの後、タイマーがゼロに達していない限り、通常どおり続行することも、現在の値を破棄して「更新」することもできます。これにより、同じ範囲内の新しい独立した均一な値に置き換えられます。 また、決定が行われる前にデクリメント ステップがすでに行われているため、各更新には丸 1 秒の時間がかかります。 

タスクは、この期待を最小限に抑える最適な戦略に従うと仮定して、タイマーがゼロに達するまでの予想合計時間を計算することです。 

入力には最大 100 万個の独立した T 値が含まれており、それぞれがこの確率過程の別のバージョンを記述します。 T は 10^9 まで大きくなる可能性があるため、どのような解でも、数学的な導出の後、定数時間で各ケースを評価する必要があります。 テスト ケースごとの線形シミュレーションや対数シミュレーションも実現できません。 

単純なアプローチでは、意思決定プロセスをシミュレートしたり、タイマー状態に対する動的プログラミングによって期待値を計算したりすることもあります。 状態空間は最大 10^9 であり、各状態はリフレッシュ操作を通じて他のすべての状態に依存するため、T が大きい場合はこれがすぐに破綻します。 

貪欲なシミュレーションでは、より微妙な問題が発生します。最適性を証明せずに固定しきい値戦略を仮定すると、T が小さい場合に一貫性のない結果が得られやすくなります。 たとえば、T = 1 の場合、タイマーは常に 1 ですぐに終了するため、答えは自明に 1 になります。 T = 2 の場合、動作はすでにリフレッシュが価値があるかどうかに依存しており、単純なヒューリスティックでは、リフレッシュによって現在の軌道が改善されるのではなく、ディストリビューション全体が再起動されることを無視するため、予想時間を誤って予測する可能性があります。 

## アプローチ

 ブルートフォース公式では、現在のタイマー値が x である場合の予想残り時間として関数 f(x) を定義します。 状態 x からはデクリメントにより必ず 1 秒が経過します。 その後、タイマーがゼロになった場合は停止します。 それ以外の場合は、減らされた値を使用し続けるか、それを破棄して新しい一様なランダム値から再開するかの二者択一の決定に直面します。 

これにより、各状態が一様分布の期待値を通じて他のすべての状態に依存する再帰的な構造が生じます。 直接計算するには、[1, T] の全範囲にわたって期待値を繰り返し再計算する必要があり、たとえメモ化されたとしても、すべての状態にわたって密な依存関係グラフが形成されます。 遷移の数はテストごとに事実上 O(T) ですが、これは不可能です。 

重要な点は、更新アクションが現在の値に細かく依存していないことです。 再起動の期待値のみに依存します。 これにより、すべてのランダム性が単一の一定量、つまり新たなスタートの期待値に集約されます。 この定数が判明すると、すべての状態がその決定論的な継続を同じベンチマークと比較します。 

この構造の単純化は、最適な政策が州間で恣意的に変動することができないことを意味します。 代わりに、残り時間が減少するたびに、「リフレッシュ」から「キープ」に 1 回だけ切り替える必要があります。 そのため、問題は、再起動した方が有益な状態と継続した方が良い状態を区別する単一のしきい値を見つけることになります。 このしきい値が特定されると、期待値全体が閉じた形式で計算可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 州に対するブルートフォース DP | テストごとの O(T) | O(T) | 遅すぎる |
 | しきい値 + 閉じた形式 | テストごとに O(1) | お(1) | 承認済み |

## アルゴリズムのチュートリアル

 現在のタイマー値が 1 秒の開始時点で x である場合に、予想される残りのペナルティとして f(x) を定義します。 

1. 必須のデクリメント ステップにより、すべての状態ですぐに 1 秒が消費されるため、すべての遷移は追加コスト 1 で始まります。 
2. x が 1 に等しい場合、タイマーはデクリメント後にゼロになるため、f(1) は正確に 1 になります。 
3. x が 1 より大きい場合、最初の 2 番目の支払い後、システムは状態 x-1 に移行します。 この時点で、f(x−1) を継続するか、新しい均一値で再開するかを選択します。 
4. y が 1 から T まで均一に描画されるときの f(y) の期待値を A で表します。これは、リフレッシュを選択する場合の期待コストを表します。これは、リフレッシュによって新しい均一な状態が生成され、プロセスがそこから続行されるためです。 
5. x > 1 の場合、反復は f(x) = 1 + min(f(x−1), A) になります。比較は完全に決定論的継続と一定のベンチマーク A の間で行われます。 
6. f(x) は x 内で単調増加するため、すべての x ≤ m については決してリフレッシュされず、すべての x > m については常にリフレッシュされるようなしきい値 m が存在します。 
7. 非リフレッシュ領域では、プロセスは純粋に決定論的であるため、x ≤ m の場合、f(x) = x となります。 
8. リフレッシュ領域では、すべての状態が同じように動作し、常にリフレッシュを選択するため、x > m の場合、f(x) = 1 + A になります。 
9. この構造をすべての状態にわたる f の平均として A の定義に代入し、m と T に関して A を解き、A = (2T + m(m−1)) / (2m) を取得します。 
10. しきい値条件は、2 つの領域間の境界によって決まります。x = m + 1 では、f(m) ≤ A および f(m+1) > A でなければならず、これにより、不等式 m^2 + m > 2T が生じます。 この不等式を満たす最小の整数 m が正しい分割を定義します。 
11. m が計算されると、初期状態は [1, T] のすべての値に均一に分布するため、期待される答えは A そのものになります。 

### なぜ効果があるのか

 このアルゴリズムは、決定プロセスを、単一のグローバル定数 A に対して可能なすべての継続を比較することに縮小します。これにより、適応ポリシーが単調な構造に崩壊します。つまり、ある状態 x でリフレッシュが最適である場合、将来のコストと継続コストの両方が x とともに増加するため、より大きなすべての状態でも最適である必要があります。 この単調性により、最適な戦略を完全に特徴付ける単一のカットオフ ポイント m の存在が強制されます。 状態空間がこのように分割されると、すべての期待値は 2 つの区間にわたる線形和になり、再帰的な依存関係のサイクルが排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = []
    for _ in range(n):
        T = int(input())
        
        # compute m = smallest integer with m*(m+1) > 2T
        lo, hi = 1, 2 * T
        while lo < hi:
            mid = (lo + hi) // 2
            if mid * (mid + 1) > 2 * T:
                hi = mid
            else:
                lo = mid + 1
        m = lo
        
        num = 2 * T + m * (m - 1)
        den = 2 * m
        
        g = gcd(num, den)
        num //= g
        den //= g
        
        out.append(f"{num} {den}")
    
    print("\n".join(out))

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

if __name__ == "__main__":
    solve()
```この実装では、まず、不等式 m(m+1) > 2T に対する二分探索を使用して、しきい値 m を導出します。 これにより、テストごとの時間を一定に保ちながら、平方根による浮動小数点精度の問題が回避されます。 

m を取得した後、閉じた形式の式 (2T + m(m−1)) / (2m) を使用して期待値が直接計算されます。 最後のステップでは、標準の gcd ルーチンを使用して端数を削減し、必要な出力形式に一致させます。 

すべての乗算が Python 整数内に安全に収まるように注意する必要があります。 値は 1e9 に達する可能性がありますが、m^2 のような中間積は約 1e18 に制限されており、Python の任意精度演算では安全です。

 システムは常に 1 から開始され、1 秒後にすぐに 0 に達します。更新を行っても何も改善されません。 期待は決定論的な動作と一致します。

 ## 特殊なケース

 T = 1 の場合、しきい値の計算により m = 1 が得られ、すべての状態が決定領域内に配置されます。 アルゴリズムは A = 1 を計算し、タイマーが常に即時に終了するという事実と一致します。 

T = 2 の場合、しきい値は m = 2 になり、状態 1 と状態 2 の両方がリフレッシュなしで処理されることを意味します。 計算された期待値は 2 となり、これは、システムがこのような小さな範囲で再起動してもほとんどメリットがないという直接的な推論と一致します。 

非常に大きな T の場合、しきい値は約 sqrt(T) までしか増加しませんが、アルゴリズムが T まで明示的に反復することはありません。二分探索公式により、状態を列挙することなくカットオフが確実に見つかり、最終的な公式は m と T を含む算術のみに依存するため、10^9 スケールでも計算が安定します。
