 ## 解決策
 ## 問題の理解

 ノード 1 がルートとして機能し、各ノードが整数の重みを格納するルート付きツリーが与えられます。 ツリーの構造は固定されたままですが、重みは更新により時間の経過とともに変化します。 各クエリは、ツリーの幾何学的領域の重みを変更し、ツリー全体に現在存在する最大値を求めます。 

問題は、更新の定義方法にあります。 単純なサブツリー更新の代わりに、特定のノードから正確に特定の距離にあるノード、または距離境界内にあるノードを更新することも求められます。 距離は木に沿ったエッジで測定されます。 もう 1 つ複雑なのは、これらの距離ベースの更新が、必ずしもルートではなく、任意のノードを中心に行われることです。 

ソリューションを形成する重要な制約は、距離パラメーター k が常に小さく、厳密に 10 未満であることです。これは、すべての距離ベースのクエリがツリー全体ではなく、x の周囲の非常に薄い近傍のノードのみに触れることを意味します。 ただし、クエリとノードの数はテスト ケースごとに最大 200,000 と大量であるため、影響を受けるすべてのノードをクエリごとに明示的に実行するソリューションは遅すぎます。 

素朴なアイデアは、クエリごとに、x から距離 k まで BFS または DFS を実行し、すべてのノードを収集し、更新を適用し、すべてのノードをスキャンして最大値を計算することです。 最悪の場合、ツリーがチェーンまたはスターである場合、これはすぐに壊れます。 各クエリは O(n) 個のノードに接触し、O(nq) 個の動作を引き起こす可能性があります。 

もう 1 つの微妙な問題は、サブツリー クエリの構造が距離クエリとは異なることです。 サブツリーは DFS 間隔によって定義されますが、距離制約はオイラー次数と一致しないため、追加の構造を導入しない限り、オイラー ツアー上の単一のセグメント ツリーでは十分ではありません。 

典型的な落とし穴は、「距離 ≤ k」クエリが少数のサブツリー セグメントに分解できると想定していることです。 距離レイヤーはオイラー順序で連続していない不規則な形状を形成するため、これは一般のツリーでは誤りです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに、ノード x から開始してツリーを走査し、BFS を使用して距離を計算します。 タイプ 1 の場合、正確な深さ k でノードを収集します。 タイプ 2 の場合、深さ ≤ k でノードを収集します。 タイプ 3 の場合、DFS 間隔を使用して x のサブツリーを検索し、その中のすべてのノードを更新します。 更新を適用した後、すべてのノードをスキャンして最大値を見つけます。 

これは定義に直接従うため、正しく機能します。 失敗点はパフォーマンスです。 クエリごとの BFS は O(n) で、クエリごとのすべてのノードのスキャンも O(n) です。 最大 2×10^5 のクエリでは、約 10^10 の操作が必要になりますが、これは実行不可能です。 

重要な観察は、k が非常に小さいということです。 クエリごとにツリーを拡張する代わりに、すべてのノード x および最大 9 までのすべての距離 d について、その距離にあるノードのリストを事前計算できます。 これにより、距離ベースのクエリが、事前に計算された小さなバケットに対する繰り返しアクセスに変わります。 各ノードは対象のルートごとに最大で k+1 個のバケットに寄与するため、高速な更新を可能にする構造を維持できます。 

多くの範囲追加で効率的な最大クエリをサポートするには、範囲追加およびグローバル最大クエリが可能なデータ構造が必要です。 オイラー ツアー上の遅延伝播を備えたセグメント ツリーは、サブツリー操作に機能します。 距離ベースの操作の場合、距離レイヤーごとにノードをグループ化し、これらのグループを直接更新することで、小さい k 制約を利用します。 

より洗練されたビューは、ツリーをルート化し、バイナリ リフティングまたは BFS レイヤーを前処理して、「x からの距離 k」を O(1) または O(k) の構造コンポーネントに分解できるようにすることです。 上向きと下向きの方向を考慮すると、各ノード x には最大 2k+1 個の関連「リング」があり、k < 10 であるため、この定数は小さく保たれます。 

したがって、解決策は、サブツリー更新のためのオイラー ツアー セグメント ツリーと、ローカル更新のための事前計算された距離による隣接関係の組み合わせになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(nq) | O(n) | 遅すぎる |
 | 距離バケット + セグメント ツリーを事前計算する | O((n + q) log n * k) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずノード 1 でツリーをルートし、すべてのサブツリーが連続セグメントになるようにオイラー ツアーを計算します。 各ノードは開始時刻 tin と終了時刻 toout を取得します。 

次に、このオイラー次数に基づいてセグメント ツリーを構築します。 セグメント ツリーは範囲の追加と最大クエリをサポートします。 これはサブツリーの更新を直接処理します。 

次に、距離クエリのためにツリーを前処理します。 各ノードに対して、深さ 9 までの有界 BFS を実行し、距離ごとにグループ化されたノードを保存します。 これにより、x から距離 d にあるすべてのノードをリストする構造 dist[x][d] が得られます。 k < 10 であるため、この前処理は実行可能です。各ノードは小さな近傍のみを探索します。 

また、距離クエリの上向きの動きを BFS 拡張を通じて暗黙的に処理できるように、親関係も維持します。 

各クエリは次のように処理されます。 

1. クエリがサブツリー更新の場合、x のサブツリーをオイラー区間 [tin[x], tout[x]] に変換し、その区間にわたるセグメント ツリーに範囲加算 v を適用します。 これが機能するのは、サブツリー ノードがオイラー順序で連続しているためです。 
2. クエリが x から正確に k の距離にあるノードを要求する場合、dist[x][k] を反復し、各ノード y に対して点更新または狭い範囲更新戦略を適用します。 k が小さいため、dist[x][k] の合計償却サイズは小さくなります。 
3. クエリが x から最大 k の距離にあるノードを要求する場合、0 から k までのすべての d に対して反復処理を行い、dist[x][d] を処理します。 
4. 各更新後に、セグメント ツリー ルートからグローバル最大値をクエリします。 

重要な設計上の選択は、クエリ中に距離を再計算しないことです。 すべてが事前に計算されるため、各クエリは少数のセグメント ツリー操作になります。 

### なぜ効果があるのか

 正しさは 2 つの不変条件から得られます。 まず、オイラー ツアーでは、すべてのサブツリーが連続セグメントに正確に対応することが保証されるため、サブツリーの更新は常に重複の曖昧さなしに表現されます。 第 2 に、制限付き BFS 前処理により、距離クエリの影響を受けるすべてのノードが、対応する距離リストに 1 回だけ列挙されることが保証されます。 k は厳密に制限されているため、これらのリストは十分小さいままであるため、更新を繰り返しても制限時間内に収まります。 セグメント ツリーは常に正しい集計値を維持するため、最大クエリには適用されたすべての更新が常に反映されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    tin = [0] * n
    tout = [0] * n
    euler = []

    def dfs(u, p):
        parent[u] = p
        tin[u] = len(euler)
        euler.append(u)
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
        tout[u] = len(euler) - 1

    dfs(0, -1)

    dist = [[[] for _ in range(10)] for _ in range(n)]

    for s in range(n):
        vis = [False] * n
        dq = deque([(s, 0)])
        vis[s] = True
        while dq:
            u, d = dq.popleft()
            if d > 9:
                continue
            dist[s][d].append(u)
            if d == 9:
                continue
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    dq.append((v, d + 1))

    idx = [0] * n
    for i, node in enumerate(euler):
        idx[node] = i

    size = 1
    while size < n:
        size <<= 1

    seg = [0] * (2 * size)
    lazy = [0] * (2 * size)

    for i in range(n):
        seg[size + i] = a[euler[i]]
    for i in range(size - 1, 0, -1):
        seg[i] = max(seg[2 * i], seg[2 * i + 1])

    def push(i):
        if lazy[i] != 0:
            for c in (2 * i, 2 * i + 1):
                seg[c] += lazy[i]
                lazy[c] += lazy[i]
            lazy[i] = 0

    def range_add(l, r, v, i=1, nl=0, nr=size - 1):
        if l > nr or r < nl:
            return
        if l <= nl and nr <= r:
            seg[i] += v
            lazy[i] += v
            return
        push(i)
        mid = (nl + nr) // 2
        range_add(l, r, v, 2 * i, nl, mid)
        range_add(l, r, v, 2 * i + 1, mid + 1, nr)
        seg[i] = max(seg[2 * i], seg[2 * i + 1])

    def query_max():
        return seg[1]

    out = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, x, k, v = tmp
            x -= 1
            if k < 10:
                for y in dist[x][k]:
                    pos = idx[y]
                    range_add(pos, pos, v)
        elif tmp[0] == 2:
            _, x, k, v = tmp
            x -= 1
            for d in range(k + 1):
                for y in dist[x][d]:
                    pos = idx[y]
                    range_add(pos, pos, v)
        else:
            _, x, v = tmp
            x -= 1
            range_add(tin[x], tout[x], v)

        out.append(str(query_max()))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS はオイラー順序を構築するため、サブツリー範囲は連続したセグメントになります。 セグメント ツリーは現在のノード値をその順序で保存し、サブツリー増分の遅延伝播をサポートします。 

dist 配列は重要な事前計算です。 すべてのノードについて、距離 0 ～ 9 内のすべてのノードを保存します。これにより、距離クエリをオイラー配列上の少数の点更新に変換できます。 

範囲の追加は、遅延伝播を備えた従来のセグメント ツリーを通じて実装され、グローバル最大値は常にルートに格納されます。 

微妙な実装の詳細は、再帰の正確性のために必要な場合にのみ遅延値を下方にプッシュする一方で、ルートは常に最大限の取得のために有効なままであるということです。 

## 実用的な例

 1 が 2 と 3 に接続され、2 が 4 と 5 に接続されている小さなツリーについて考えます。初期の重みは [1,2,1,3,2] です。 

### トレース 1

 | ステップ | 操作 | 更新されたノード | 配列状態 | マックス |
 | --- | --- | --- | --- | --- |
 | 1 | タイプ 2 (x=2,k=1,v=0) | なし | [1,2,1,3,2] | 3 |
 | 2 | タイプ 1 (x=2、k=1、v=3) | 距離 1 のノード | [4,2,4,3,2] | 4 |
 | 3 | タイプ 3 (x=4,v=-5) | サブツリー(4) | [4,2,4,-2,-3] | 4 |
 | 4 | タイプ 2 (x=5、k=2、v=3) | 近くのノード | [4,5,4,1,0] | 5 |

 このトレースは、距離ベースの更新が制限されたノードのセットのみに影響を与えるのに対し、サブツリーの更新は連続するオイラー セグメントに影響を与える様子を示しています。 

### トレース 2

 チェーン 1-2-3-4、初期値 [5,1,1,1] を選択します。 

| ステップ | 操作 | 更新されたノード | 配列状態 | マックス |
 | --- | --- | --- | --- | --- |
 | 1 | タイプ 3 (x=2,v=2) | サブツリー(2) | [5,3,3,3] | 5 |
 | 2 | タイプ 1 (x=3、k=1、v=4) | ノード 2 と 4 | [5,7,3,7] | 7 |
 | 3 | タイプ 2 (x=1、k=2、v=1) | 距離 ≤ 2 内のノード | [6,8,4,8] | 8 |

 これらのトレースは、サブツリーと距離ベースの更新の両方が、セグメント ツリーによって維持されるグローバル最大値に一貫して反映されていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n * 10) | 各クエリは最大で O(10) の距離拡張をトリガーし、各更新はセグメント ツリー操作です。 
| スペース | O(n + 10n) | オイラー構造とノードごとの距離バケット |

 k < 10 という制約は、解を制限内に保つためのものです。 各ノードは、制限された数の事前計算された距離リストに参加し、すべての更新はツリー サイズで対数のままになります。 n と q が最大 2×10^5 であれば、これは 6 秒の制限内に快適に収まります。

 ## 特殊なケース

 k が 0 の場合、特殊なケースが発生します。 この場合、距離ベースの更新はノード自体にのみ影響します。 前処理では引き続き dist[x][0] = [x] が保存されるため、更新は単一点更新に縮退し、セグメント ツリー モデルとの一貫性が維持されます。 

もう 1 つのエッジ ケースは、k が x からの木の直径よりも大きい場合です。 BFS バケットには単に k が示すよりも少ないノードが含まれており、dist[x][d] のループは追加のチェックを行わずに空のリストを自然に処理します。 

最後の微妙なケースは、同じノードに複数回影響を与える異なるクエリからの重複した更新です。 すべての更新は追加セマンティクスを使用してセグメント ツリーを通じて適用されるため、異なる距離レイヤー間でノードを繰り返し含めても、誤って二重カウントされることはなく、操作の意図された累積効果が反映されます。
