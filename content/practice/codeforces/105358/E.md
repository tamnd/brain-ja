 ## 解決策
 ## 問題の理解

 私たちには、部屋と通路の無方向に接続されたグラフが与えられます。 スニーカーは部屋 1 から開始し、できるだけ少ない通路を使用して部屋 n に到達したいと考えています。 このグラフは、同じ部屋のペア間に自己ループや複数のエッジがないという意味で単純です。 

この問題は、いくつかの部屋に配置された k 台のロボットによって引き起こされます。 スニーカーがエッジに沿って一歩を踏み出すたびに、すべてのロボットも同時に一歩を踏み出し、それぞれが隣接するエッジを選択します。 彼らの動きは固定された経路として敵対的に指定されていませんが、ランダム性が私たちに役立つと仮定するのも安全ではありません。 重要な制約は構造的なものです。ロボットは、連続したバックトラッキングによって以前の動作がキャンセルされるスタックのように動作する歩行履歴を維持します。 ロボットの記録された履歴の長さが d を超えると、新しい部屋に入るとすぐに自爆します。 スニーカーは、現在自爆しているロボットやすでに破壊されているロボットを「認識」しません。 

唯一の致命的な出来事は、同じ部屋で同時にロボットに遭遇することです。具体的には、ロボットと同時に部屋 n に到着することも致命的です。 

タスクは、この動作モデルの下でスニーカーがロボットに遭遇しないことを保証する 1 から n までの可能な最短パスを出力することです。 そのようなパスが存在しない場合は、-1 を出力する必要があります。 

この制約により、グラフ サイズ全体にわたって線形または線形に近いアルゴリズムが求められます。 ノード数が最大 2×10^5、エッジが合計 2×10^6 であるため、マルチソース最短パスや BFS バリアントなどは許容されますが、ロボットの動作をシミュレートしたり、ロボットの位置に関係する状態を探索したりするものは不可能です。 また、最大 10^5 のテスト ケースが存在するため、テストごとの大量の前処理を回避する必要があります。 

微妙なエッジ ケースは、破壊しきい値 d との相互作用です。 ロボットは経路履歴が d を超えると自滅するため、「キャンセルせずに歩きすぎた」ロボットは消滅します。 ただし、キャンセル メカニズムは、ロボットがサイクルを探索しながら効果的に生き続けることもできることを意味するため、グラフ内の距離だけを推論するだけでは十分ではありません。 

もう 1 つの重要なエッジ ケースは、スニーカーが、まったく同じタイム ステップで目的地に到着するロボットと同時に目的地に到着する場合です。 たとえ侵入直後にロボットが破壊されたとしても、同時到着はエンカウントとしてカウントされます。 時刻同期を無視する単純な最短パスのアプローチは、ここでは失敗します。 

2 番目の微妙なケースは、ロボットが最後のエッジを即座に反転することによってのみ履歴を消去できるため、ロボットの有効な状態が減少した歩行に似ていることです。 キャンセル動作を考慮せずにロボットを単純な BFS 波面として扱うアプローチでは、到達可能な領域が誤って分類されます。 

## アプローチ

 ブルートフォース解釈では、スニーカーの動きと考えられるすべてのロボットの動きを段階的にシミュレートします。 各タイム ステップで、現在の部屋や履歴スタックを含む、すべてのロボットの完全な状態を追跡します。 スニーカーは考えられるすべての経路を試し、ロボットの動作がどのような構成であっても彼に対応できるかどうかを確認します。 各ロボットは現在のノードの段階ごとに分岐し、履歴スタックに追加の状態が導入されるため、これはすぐに組み合わせ的に爆発します。 積極的な枝刈りを行ったとしても、状態空間はロボットの数とグラフ サイズの両方で指数関数的に増大し、小さな入力を超えると実行不可能になります。 

重要な観察は、ロボットの動作は、複雑に見えるにもかかわらず、制限された量、つまり履歴の長さによってのみ重要であるということです。 この長さが d を超えると、ロボットは消滅し、システムへの影響を停止します。 したがって、各ロボットは、キャンセル限界の長さ d を超えない歩行によって定義される半径のような領域内でのみ、効果的に制約に寄与します。

これにより、問題はグラフ回避問題に変換されます。ロボットが自己破壊する前に、ロボットの影響を受けるすべての「危険な」ノードまたは領域を回避する 1 から n までのパスを見つける必要があります。 すべてのロボットは同時に開始し、Sneaker と同じ速度で移動するため、これをロボットの開始位置からのマルチソース拡張として解釈できますが、工夫が必要です。ロボットの「リーチ」は、最大許容有効歩行長 d によって制限されます。 

この有界歩行制約の下でロボットが各ノードを占有することができる最も早い時間 (または最小ステップ) を事前に計算すると、スニーカーの問題は、ロボットの到着時間以上の時間にノードに決して到着しない 1 から n までの最短経路を見つけることに帰着します。 これは、禁止時間制約の下での古典的な最短パスであり、すべてのエッジが重み付けされていない場合は BFS で解決できます。 

したがって、ソリューションは 2 つの BFS のようなプロセスに分解されます。1 つはすべてのロボット ソースから危険時間を計算するプロセスで、もう 1 つはノード 1 から最も早く安全に到着するパスを見つけるプロセスです。

 | フルステートシミュレーション | 指数 | 指数 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 まず、ロボットの深さ d までの拡張をシミュレートすることで、各ノードがどの程度危険かを計算します。 

1. すべてのロボットの初期位置から開始してマルチソース BFS を同時に実行します。 各ノードには、ロボットがノードに到達するために必要な最小歩数が保存されます。 

これにより、ロボットがキャンセル効果なしで単に歩いた場合の基準となる「最も早い到着時間」が得られます。 
2. この BFS の上限を深さ d に設定します。これは、d より長いロボット パスは自己破壊につながるためです。つまり、その深さを超えるノードは問題になりません。 

このステップにより、除外する前にロボットの影響のみを考慮することが保証されます。 
3. この結果を配列に保存します`danger[t]`、 どこ`danger[v]`ロボットがノード v を占有することができる最も早い時間です。 
4. 次に、Sneaker のノード 1 から BFS を実行します。ここで、パス再構築のために距離と親ポインターの両方を維持します。 
5. BFS 中に、t+1 が厳密に次の値より小さい場合にのみ、時刻 t+1 でノード v に移動します。`danger[v]`つまり、スニーカーは、ロボットが占拠したり重なったりする前に到着します。 
6. さらに、ノード n への到達は、同じタイム ステップでロボットがそこに到達する前にスニーカーが厳密に到着した場合にのみ有効であることを確認します。 
7. BFS がノード n に到達すると、親ポインタを使用してパスを再構築します。 
8. ノード n に到達しない場合は、-1 を出力します。 

微妙な部分は、ロボット BFS が過剰近似であるということです。BFS は、ロボットをキャンセル制約なしで自由に探索しているものとして扱います。 実際のロボットの動作はせいぜい単純な BFS 到達可能性と同じくらい制限されているため、これは安全です。したがって、ノードが d ステップ以内に BFS に到達できない場合、実際のシステムでも安全です。 

### なぜ効果があるのか

 正確さは過剰近似の原則に基づいています。 キャンセル効果を無視し、ロボットの動きを深さ d までの標準 BFS として扱うことにより、自己破壊前にロボットが占有する可能性のあるすべてのノードのスーパーセットを計算します。 これにより、安全ではないとマークされたノードは、ロボットの有効な動作の下では本当に安全ではないことが保証されますが、安全とマークされたノードは過度に保守的である可能性がありますが、決して不正確ではありません。 スニーカーの BFS は、安全でない可能性のあるすべてのノードを回避する最短パスを見つけます。BFS は距離が増加する順序で探索するため、最初に n に到達するのが最適です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, d = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        tmp = list(map(int, input().split()))
        k = tmp[0]
        robots = tmp[1:]

        INF = 10**18
        danger = [INF] * (n + 1)

        q = deque()
        for s in robots:
            danger[s] = 0
            q.append(s)

        while q:
            v = q.popleft()
            if danger[v] == d:
                continue
            for to in g[v]:
                if danger[to] > danger[v] + 1:
                    danger[to] = danger[v] + 1
                    q.append(to)

        # Sneaker BFS
        dist = [-1] * (n + 1)
        parent = [-1] * (n + 1)

        if danger[1] == 0:
            print(-1)
            continue

        dq = deque([1])
        dist[1] = 0

        while dq:
            v = dq.popleft()
            if v == n:
                break
            for to in g[v]:
                nd = dist[v] + 1
                if dist[to] == -1 and nd < danger[to] and (to != n or nd < danger[to]):
                    dist[to] = nd
                    parent[to] = v
                    dq.append(to)

        if dist[n] == -1:
            print(-1)
            continue

        path = []
        cur = n
        while cur != -1:
            path.append(cur)
            cur = parent[cur]
        path.reverse()

        print(len(path) - 1)
        print(*path)

if __name__ == "__main__":
    solve()
```この解決策は、グラフの隣接リストを構築することから始まります。 次に計算します`danger[v]`これは、任意のロボットがノード v に到達できる最初の BFS 層を表します。深さ d で上限が設定されているため、ロボットが自己破壊すると、より深い伝播は無視されます。 

その後、標準の BFS がノード 1 から実行されます。唯一の変更点は、スニーカーが到着時間が記録されたロボットの到着時間よりも厳密に短い場合にのみノードに入ることができるという制約です。`danger`。 これにより、Sneaker が同じタイム ステップでどのロボットともノードを共有することがなくなります。 

親配列は、ノード n に到達すると、有効な最短パスを再構築するために使用されます。 すべてのエッジの重みが等しいため、BFS は最小限のエッジ数を保証します。 

実装の微妙な詳細は、ノード n の処理です。スニーカーがロボットと同時に n に到着しないことを明示的に保証します。これは、たとえロボットが直後に消えたとしても、遭遇したとみなされるためです。 

## 実用的な例

 ### 例 1

 スニーカーが直接安全なルートを持っている小さなグラフを考えてみましょう。 

| ステップ | キュー | ノード | 距離 | 危険チェック |
 | --- | --- | --- | --- | --- |
 | 1 | [1] | 1 | 0 | 開始 |
 | 2 | [2] | 2 | 1 | 安全 |
 | 3 | [3] | 3 | 2 | 安全 |
 | 4 | [7] | 7 | 3 | 安全 |

 BFS は最初に 7 に到達し、パス 1 → 2 → 3 → 7 を再構築します。これにより、ルートに沿って干渉するロボットがない場合、最短の安全なパスが見つかることが確認されます。 

### 例 2

 ロボットの接近によってノード n が安全でなくなるのが早すぎる場合:

 | ノード | 危険 |
 | --- | --- |
 | 1 | INF |
 | 2 | 0 |
 | 3 | 1 |
 | 7 | 2 |

 スニーカーはタイム 3 でのみ 7 に達する可能性がありますが、危険 [7] = 2 が進入をブロックします。 BFS はノード 7 をキューに入れることはなく、出力は -1 です。 これは、構造パスが存在する場合でもアルゴリズムがどのように遅延到着を防止するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | グラフ上の 2 つの BFS 走査 |
 | スペース | O(n + m) | 隣接リストと距離の配列 |

 この制約により、最大 2×10^6 のエッジが許可され、各エッジは BFS 実行全体で最大 2 回処理されます。 これは、高速 I/O を備えた Python の時間とメモリの制限内に快適に収まります。

def run(inp: str) -> str:

    import sys
    from collections import deque

    input = sys.stdin.readline

    T = 1
    n, m, d = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    tmp = list(map(int, input().split()))

    robots = tmp[1:]

    INF = 10**18
    danger = [INF] * (n + 1)
    q = deque(robots)
    for s in robots:
        danger[s] = 0

    while q:
        v = q.popleft()
        if danger[v] == d:
            continue
        for to in g[v]:
            if danger[to] > danger[v] + 1:
                danger[to] = danger[v] + 1
                q.append(to)

    dist = [-1] * (n + 1)
    parent = [-1] * (n + 1)

    if danger[1] == 0:
        return "-1\n"

    dist[1] = 0

    while dq:

    cur = n

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ロボットがノード 1 から開始する場合です。この場合、`danger[1] = 0`、スニーカーは安全に動き始めることさえできません。 アルゴリズムはこれを直ちに検出し、-1 を返します。 これにより、開始ノードですでに制約に違反している BFS を探索することが回避されます。 

もう 1 つのエッジ ケースは、スニーカーが到着した少し後に危険になるノードを介してのみノード n に到達できる場合です。 BFS 条件`nd < danger[to]`このタイミング ギャップを正しく処理し、Sneaker が同時にノードにステップインすることがないようにします。 

最後のエッジ ケースは、多数の代替最短パスが存在する密なグラフです。 BFS は、すべての最小長のルートを均一に探索し、危険制約は安全なブランチ間の最適性に影響を与えることなく、安全でないブランチのみをプルーニングするため、正確性を保証します。
