 ## 解決策
 ## 問題の理解

 負ではない整数が与えられ、それを 2 のべき乗の合計として表現するように求められますが、標準の 2 進数の代わりに、各ビット位置は値 −1、0、または 1 を取ることができます。位置 i の寄与は ai · 2^i であり、合計は指定された数値に等しくなければなりません。 

制限はこれだけではありません。 この表現は、2 つの隣接する位置が両方とも 0 になることができないように制約されます。 言い換えれば、32 ビット配列内のどこにおいても、ai と ai+1 が両方とも 0 であるパターンを持つことは禁止されています。 

テスト ケースごとに、そのような表現が存在するかどうかを判断する必要があります。 存在しない場合はNOを出力します。 存在する場合は、YES を出力し、固定長 32 の係数シーケンスを出力します。 

入力サイズでは最大 10^4 のテスト ケースが可能で、各数値は 2^30 未満です。 これは、ケースごとの解が O(log n) であっても、合計で約 3 · 10^5 の操作にすぎず、安全であるため、各テスト ケースを一定時間またはほぼ一定時間で処理する必要があることを直ちに示唆しています。 ビット長の 2 次のものはすべて不必要なオーバーヘッドになります。 

微妙な問題は、「符号付きバイナリ」の自由とゼロの隣接制限との間の相互作用です。 非隣接形式のような標準の符号付きバイナリ表現では、すでに数字 -1、0、1 が許可されていますが、特に、連続するゼロではなく、連続する非ゼロ数字は避けられます。 ここでは制限が逆になっているため、既知の正規表現の単純な再利用は直接適用されません。 

素朴な貪欲な思考を打ち破る主なエッジケースは、強制ゼロの伝播です。 あるポジションでゼロをコミットし、次のポジションもゼロに強制されると、直ちにルールに違反します。 たとえば、数値が 4 で割り切れる場合、単純な最下位ビットの貪欲分解では a0 = 0 および a1 = 0 が強制されますが、これは上位ビットを考慮する前でさえすでに無効です。 

## アプローチ

 強引な解釈では、係数の 3^32 の割り当てをすべて試し、値が n と一致し、隣接ルールが成立するかどうかを確認します。 これには約 10^15 の可能性が含まれるため、明らかに不可能です。 

より構造化されたブルート フォースでは、ビット位置に対して深さ優先の検索が試行され、残りの値が運ばれます。 各位置で、パリティと一致する場合は、-1、0、または 1 を選択します。 これでも最悪の場合には大きく分岐しますが、より重要なのは、同等の状態を繰り返し再訪するため、実際には指数関数的になるということです。 

重要な観察は、表現が本質的に冗長性のある基数 2 の数字システムであるため、実行剰余を維持しながら最下位ビットから貪欲に数字を構築できることです。 各ステップで、ai を選択すると、剰余は (n − ai) / 2 になります。これにより、ai は強制的に現在の剰余のパリティと一致するため、ほとんどの選択肢が決定されるか、小さな定数セットに削減されます。 

唯一の問題は、ゼロに対する隣接関係の制限です。 貪欲な構造では、現在の剰余が連続する複数のステップで偶数である場合に、連続した強制ゼロを簡単に生成できます。 修正は、後で強制ゼロを引き起こすゼロの「ロックイン」を避けることです。 ゼロが違反を引き起こす場合は常に、ユニットを次の位置にプッシュすることで表現をローカルに調整します。これによりパリティが反転され、強制ゼロの連鎖が切断されます。 

これにより、問題はビット全体の線形スキャンになり、時折局所的な修正が行われます。

 ## アルゴリズムのチュートリアル

最初は n に等しい現在の剰余値 x を維持しながら、0 から 31 までのビットを処理します。 

各ビット位置 i での目標は、ai を減算して 2 で割った後の剰余が整数のままになり、最終的に正しく減少するように ai を選択することです。 

1. x のパリティを計算します。 x が偶数の場合、−1 と 1 は 2 で割り切れないため、ai は 0 でなければなりません。x が奇数の場合、ai は−1 または 1 でなければならず、両方とも有効な選択です。 
2. x が奇数の場合、可能な限り x の絶対値を減らすために ai を選択します。 これは、x が正の場合は ai = 1 を選択し、x が負の場合は ai = −1 を選択することによって行われます。 これにより、剰余が小さく保たれ、将来の大きな修正が防止されます。 
3. x を (x − ai) / 2 に更新します。 
4. ai を割り当てた後、禁止パターン ai−1 = 0 および ai = 0 を作成したかどうかを確認します。これが発生した場合は、2 つのうちの少なくとも 1 つが非ゼロになるように、現在または前の決定を変更して状況を修復します。 最も簡単な修復は、ゼロが出現するたびに次のゼロ以外のステップが直ちに強制的に実行されるようにすることで、強制ゼロの長い連鎖を回避することです。これは、両方が有効である場合であっても、あいまいな状況では ±1 を優先することで実現されます。 
5. i = 31 まで続行し、残りが完全に消費されたことを確認します。 

修復手順は唯一重要な部分です。 概念的には、2 つのゼロが連続して出現すると、制約が永続的に違反されるため、アルゴリズムがパリティによって複数の連続するゼロを強制される状態になるのを防ぎます。 

### なぜ効果があるのか

 この構築では、各ステップで、構築された係数を使用した部分和が n モジュロ 2^{i+1} に一致するという不変条件が維持されます。 これにより、後続の桁に関係なく、数値表現の正確さが保証されます。 

貪欲な選択により、選択肢が存在する場合、常に可能な限り早く剰余の大きさが減らされることが保証され、剰余が 2 の大きなべき乗で繰り返し割り切れるという病的なケースが防止されます。 ローカル修復により、ゼロが個別に制約されないため、制約に違反する唯一の構造的な方法である 2 つの連続した強制ゼロをコミットすることがなくなります。 

すべてのステップはパリティと一定サイズの修正にのみ依存するため、複数の位置をバックトラックする必要はなく、プロセスは常に有効な割り当てが存在する場合はそこに到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n):
    # special case: 0 cannot be represented without violating adjacency rule
    if n == 0:
        return None

    a = [0] * 32
    x = n

    for i in range(32):
        if x & 1 == 0:
            ai = 0
        else:
            # choose sign to reduce magnitude
            if x > 0:
                ai = 1
            else:
                ai = -1

        a[i] = ai
        x = (x - ai) // 2

    # final check
    if x != 0:
        return None

    # repair pass: avoid consecutive zeros
    for i in range(31):
        if a[i] == 0 and a[i + 1] == 0:
            # force correction by flipping a later non-zero if possible
            j = i + 1
            while j < 32 and a[j] == 0:
                j += 1
            if j == 32:
                return None
            # shift a unit from j to j-1 chain to break zero pattern
            if a[j] == 1:
                a[j] = 0
                a[j - 1] = 1
            else:
                a[j] = 0
                a[j - 1] = -1

    for i in range(31):
        if a[i] == 0 and a[i + 1] == 0:
            return None

    return a

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        res = solve_one(n)
        if res is None:
            out.append("NO")
        else:
            out.append("YES")
            for i in range(0, 32, 8):
                out.append(" ".join(map(str, res[i:i + 8])))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、表現のビットごとの構築に従います。 重要なアイデアは、残りが更新されるということです。`(x - ai) // 2`基数 2 の重み付けとの一貫性が強制されるため、明示的な再構築は必要ありません。 

貪欲なパリティ処理だけではゼロが長く続く可能性があるため、修復フェーズが必要です。 このような違反が検出されると、後続のゼロ以外の数字を見つけて、その寄与を 1 つ左にシフトします。これにより、禁止パターンを局所的に破りながら合計値が保持されます。 

グローバルな再計算を繰り返すと線形の複雑さが失われるため、違反ごとに 1 つの調整のみが実行されるように常に注意する必要があります。 

## 実用的な例

 n = 5 と考えます。 

| 私 | | 前に x あい | | 後の x コメント |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 1 | 2 | 奇数、正 |
 | 1 | 2 | 0 | 1 | 偶数はゼロを強制します |
 | 2 | 1 | 1 | 0 | 奇数 |
 | 3-31 | 0 | 0 | 0 | 残り |

 これにより有効な数値表現が生成されますが、隣接性を確認する必要があります。 位置 1 と 3 に連続する 0 のペアがありますか? いいえ、位置 1 と 2 は 0 と 1 なので有効です。 

これにより、孤立したゼロが許容され、制約を破らないことが確認されます。 

ここで、n = 2 について考えてみましょう。 

| 私 | | 前に x あい | | 後の x
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 1 |
 | 1 | 1 | 1 | 0 |
 | 2-31 | 0 | 0 | 0 |

 ここで、サフィックスには多くのゼロが含まれていますが、注意深く検査するまで、構築された配列内でそれらは互いに隣接していません。 このアルゴリズムは、ゼロの長いサフィックスが形成されると、隣接関係違反が発生し、修正がトリガーされる可能性があることを検出します。 この例は、修復を行わない素朴な貪欲なアプローチが失敗する理由を示しています。

 ## 特殊なケース

 n = 0 の場合、ゼロのみを含む有効な 32 長の配列は隣接制限に違反するため、アルゴリズムは直ちに NO を返します。 これは、与えられたルールの下では表現が構造的に不可能である唯一のケースです。 

n = 2^k など、2 のべき乗が大きい数値の場合、貪欲な構築により強制ゼロの長い接尾辞が生成される傾向があります。 修復メカニズムは、単一のユニットをより高いビット位置から再分配することで、これらのサフィックスが無効な連続ゼロペアを形成するのを防ぎます。 

交互のパリティ番号の場合、アルゴリズムは強制ゼロと ±1 の選択を交互に行います。これにより、パリティ駆動の構築がバックトラックを必要とせずにバイナリ展開を正しく追跡することが確認されます。
