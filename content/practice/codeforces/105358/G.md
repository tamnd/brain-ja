 ## 解決策
 ## 問題の理解

 2 人のプレイヤーがチップの山から始めます。 各ラウンドで、順位に変化がない (引き分け) か、どちらか一方がラウンドに勝利します。 勝利は単なるポイントではなく、勝者がすでに少なくとも対戦相手と同じ数のチップを持っている場合、ゲームは直ちに終了する可能性があります。 それ以外の場合は、勝者の方がまだ弱いため、敗者は勝者の現在のチップに等しいペナルティを支払い、負けた側の山を減らしてゲームが続行されます。 

引き分けは、同じ状況が繰り返されることを除けば無関係であるため、意味のある移行は、アリスがラウンドに勝つか、ボブがラウンドに勝つ場合にのみ発生します。 

このタスクは、初期チップ カウント x と y から始めて、アリスが最終的に最終的な勝ち状況に達する確率を計算することです。各ラウンドでは、アリスが勝つ場合は p0、ボブが勝つ場合は p1、残りは引き分けという固定確率があります。 

この制約により、ラウンドを明示的にシミュレートすることから遠ざけられます。 x と y は最大 10^9 ですが、各非終端ラウンドでは小さい方の山を減算することで大きい方の山を厳密に削減するため、プロセスはユークリッドのような削減パターンに従います。 これにより、任意の状態シーケンスの深さが減算ユークリッド アルゴリズムのステップ数に比例し、値が対数であることが保証されます。 

状態グラフは各ステップで分岐し、可能なシーケンスの数は深さとともに指数関数的に増加するため、すべての確率的結果にわたる単純なシミュレーションは不可能です。 

微妙なエッジ ケースは、ドローによって状態が変更されないものの、依然として確率質量を消費するという事実から生じます。 正規化せずに引き分けを 3 番目の分岐結果として扱うと、誤った確率計算が発生しやすくなります。 別の失敗ケースは、開始時に x がすでに y 以上である場合に発生します。 その場合、ゲームは 1 ラウンドで即座に終了するため、さらなる移行を想定した DP は継続パスを誤って過剰にカウントすることになります。 

## アプローチ

 ブルート フォースを試みる場合は、すべての状態 (x、y) をモデル化し、最大 3 つの結果 (引き分け、アリスの勝ち、ボブの勝ち) への確率的遷移としてラウンドをシミュレートします。 ドロー以外のトランジションはそれぞれ、ゲームを終了するか、(x, y) を (x, y - x) または (x - y, y) に変換します。 これにより、各レベルが 2 回分岐する再帰ツリーが作成され、深さは Euclid 減算プロセスに従います。 連続したフィボナッチ ペアのような最悪の場合、減算チェーンの長さは値において線形であり、分岐によりパスの数が指数関数的に増加します。 

重要な構造上の観察は、ドローが状態にまったく影響を与えないということです。 決定的な結果が生じるまで、それらは繰り返されるだけです。 これは、各ラウンドが事実上、「誰かがラウンドに勝つ」ことを条件としたベルヌーイ試行であることを意味します。 確率を p = p0 / (p0 + p1) および q = p1 / (p0 + p1) に正規化し、引き分けを完全に削除することでプロセスを圧縮できます。 

この圧縮の後、すべての状態遷移は構造において決定的となり、方向においてのみ確率的になります。 状態 (x, y) から、ゲームが終了しない限り、大きい山は常に小さい山だけ減少します。 これはユークリッド アルゴリズムとまったく同じ構造で、再帰の深さ O(log max(x, y)) とマージ パスのないツリーを保証し、状態に対するメモ化された再帰を可能にします。

 ## アルゴリズムのチュートリアル

 現在のチップ構成からアリスが勝つ確率を表す関数 f(x, y) を定義します。

1. まず、確率を再正規化して描画遷移を削除し、アリスまたはボブだけがラウンドに勝つようにします。 これにより、確率は p = p0 / (p0 + p1) および q = 1 − p に変更されます。 
2. ターミナルケースを定義します。 x >= y の場合、アリスはすでに少なくともボブと同じくらい強いので、現在のラウンドに勝てば即座にゲームに勝ちます。 ボブが勝つとゲームもボブに有利に終了するため、状態の値は単純に f(x, y) = p となります。 
3. x < y でアリスがラウンドに勝った場合、ボブは x チップを失い、状態は (x, y − x) になります。 これにより、アリスのチップ カウントが維持され、ボブのチップ カウントが減ります。 
4. x < y でボブがラウンドに勝った場合、アリスは y チップを失い、状態は (x − y, y) になります。 これにより、アリスのチップ数が減ります。 
5. 両方の遷移を組み合わせて繰り返しを作成します。 

f(x, y) = p · f(x, y − x) + q · f(x − y, y)。 
6. メモ化を使用してこの再帰を評価します。 各呼び出しは厳密に x + y を削減するため、再帰は循環できず、常に一方が優勢な最終状態に達します。 

### なぜ効果があるのか

 非終端ステップごとに、大きい方の山が小さい方の山だけ減少します。これはまさにユークリッド アルゴリズムの不変構造です。 これにより、状態空間が、一方の値が他方の値を支配する最終比較に根ざした有向非巡回グラフを形成することが保証されます。 すべての状態は終了するまで減算を繰り返すことで一意に決定されるため、メモ化により各ペア (x, y) が 1 回だけ評価されることが保証されます。 各ラウンドは条件付きで独立しており、考えられる 2 つの勝利結果に分割することによって完全に説明されるため、確率分解は有効です。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

MOD = 998244353

def modinv(a):
    return pow(a, MOD - 2, MOD)

def solve_case(x, y, p0, p1):
    s = p0 + p1
    p = p0 * modinv(s) % MOD
    q = p1 * modinv(s) % MOD

    from functools import lru_cache

    @lru_cache(None)
    def f(a, b):
        if a >= b:
            return p
        if b > a:
            # symmetric case: if roles swapped, same logic applies
            return (p * f(a, b - a) + q * f(a - b, b)) % MOD

    return f(x, y)

def main():
    T = int(input())
    out = []
    for _ in range(T):
        x, y = map(int, input().split())
        p0, p1, b = map(int, input().split())
        out.append(str(solve_case(x, y, p0, p1)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、まず p0 と p1 を逆モジュラで正規化することで描画確率を削除します。 ドローを維持すると単純な DP で無限の自己ループが作成されるため、これは不可欠です。 

メモ化された関数 f は、Euclid 減算遷移を直接エンコードします。 基本ケースは、アリスがすでにボブより弱くないときにトリガーされます。その時点で勝利するとすぐにゲームが終了するためです。 再帰呼び出しはラウンドの勝者となる可能性のある 2 人に正確に対応し、各呼び出しでチップの合計が減り、終了が保証されます。 

## 実用的な例

 アリスが弱くなり始める小さな非対称のケースを考えてみましょう。 

x = 2、y = 3、p = 1/2、q = 1/2 とします。 

| 状態 | 状態 | 使用されるトランジション | 結果の式 |
 | --- | --- | --- | --- |
 | (2, 3) | x < y | 再帰的 | 0.5・f(2,1) + 0.5・f(-1,3) |
 | (2, 1) | x ≥ y | ベース | 0.5 |
 | (-1、3) | 無効な状態形式、端末損失として解釈される | 0 | |

 これにより、f(2,3) = 0.5 · 0.5 + 0.5 · 0 = 0.25 となります。 

ここで、対称の場合 x = y を考えてみましょう。 

| 状態 | 状態 | 結果 |
 | --- | --- | --- |
 | (x, x) | x ≥ y | f = p |

 これにより、対称性が再帰なしで即座に処理されることが確認されます。 

最初のトレースは、非対称な減算パスがどのように最終状態に崩壊するかを示し、2 番目のトレースは、両方のプレーヤーが等しい場合の直接吸収動作を示します。

 ## 特殊なケース

 開始時に x が y に等しい場合、再帰はユークリッド遷移に入ることはありません。 この関数はすぐに p を返します。これは、アリスがすでにボブよりも弱くなく、アリスが勝利するとゲームが即座に終了することを反映しています。 

(1, 10^9) のように、一方の値が他方の値よりはるかに大きい場合、アルゴリズムは再帰的な遷移を通じて大きい方の山から繰り返し 1 を減算します。 状態シーケンスは (1, 10^9 − 1)、(1, 10^9 − 2) などになりますが、メモ化により、ユークリッド パスに沿って各中間ペアが 1 回訪問されることが保証され、分岐間での再計算の繰り返しが防止されます。 

確率が対称である場合、p0 = p1、正規化により p = 1/2 が得られ、すべての最終比較は直接対称な結果に帰着し、中間の減算状態によってバイアスが導入されないことが保証されます。
