 ## 解決策
 ## 問題の理解

 段階的にアレイを構築しています。 各操作で、新しい値が配列の末尾に追加されます。 各挿入の後、現在の位置で終わるすべての接尾辞と特別な接頭辞と接尾辞の重複値に応じて実行中の式を計算する必要があります。 

i 番目の挿入後に出力する値は、位置 i で終わるすべてのサブ配列に依存し、各位置に付属する 2 つのパラメーター A および B によって重み付けされます。 前の位置 j の寄与には、j で始まるサフィックスと、それがこれまでに確認された完全な配列とどのように重なるかに応じて係数が乗算されます。 この重複は、現在の状態で終わるサフィックスと一致する最長のプレフィックスの長さによって測定され、この値は配列の成長に応じて変化する可能性があります。 

2 番目の問題は、新しい要素がそれぞれ直接与えられていないことです。 代わりに、前の答えを使用してエンコードされます。つまり、すべてのステップが計算された出力の履歴全体に依存します。 

この制約により、最大 30 万の操作が可能になります。 プレフィックスとサフィックスの一致を再計算したり、挿入ごとに逆方向にスキャンしたりするソリューションは、最悪の場合、二次的な動作につながるため、すぐに失敗します。 操作ごとの線形作業でもすでに限界を超えているため、目的のソリューションでは増分構造を維持し、以前の計算を再利用する必要があります。 

多くの要素が繰り返される場合、微妙なエッジケースが発生します。 このような場合、単純な接頭辞と接尾辞の再計算によって一致が繰り返し拡張され、隠れた二次連鎖が発生する可能性があります。 もう 1 つのエッジ ケースは、エンコードによって、以前の大きな回答に依存する敵対的な値が発生する場合です。これにより、決定論的なシミュレーションが必要になり、シーケンスの事前計算ができなくなります。 

## アプローチ

 直接的なアプローチでは、配列が明示的に維持され、挿入のたびに必要な式が最初から再計算されます。 各位置 i について、1 から i までのすべての j をスキャンし、S[j] と A[j] および B[i] を乗算した寄与を計算し、現在の配列と j で終わるその接尾辞の間の最長の接頭辞一致を決定します。 プレフィックスとサフィックスの計算自体は、最大 i 個の要素をスキャンする必要がある場合があります。 これにより、各ステップは潜在的に O(i) になり、すべての操作の合計は O(N^2) になります。これは 3×10^5 の操作には遅すぎます。 

主な困難は、配列が大きくなるにつれてプレフィックスとサフィックス間の重複長を繰り返し再計算することです。 この構造は、文字列アルゴリズムにおけるプレフィックス関数の動作を思い出させます。 「サフィックスに一致する最長のプレフィックス」が、まさにプレフィックス オートマトンまたは KMP 障害関数によって維持される種類の値であることが認識されると、更新ごとに償却定数時間で増分的に維持できるようになります。 

2 番目の観察は、最終的な式は j でインデックス付けされた寄与に対して線形であり、各寄与は事前に計算された A[j] と、配列を拡張するにつれて進化する状態値にのみ依存するということです。 これは、すべてを最初から再計算するのではなく、新しい要素が到着したときに更新できる累積集計を維持することを示唆しています。 

したがって、現在の接尾辞と一致する接頭辞の量を追跡する接頭辞関数オートマトンに似た動的構造を維持し、これを加重寄与の接頭辞合計と組み合わせて、実装に応じて挿入ごとに O(1) または O(log N) 時間で答えが更新されるようにします。

 | ブルートフォース | O(N^2) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つのことを維持しながら配列をオンラインで処理します。サフィックスとプレフィックスのマッチングのためのプレフィックス関数の状態と、現在位置までの重み付けされた寄与を格納する集合構造です。

1. 現在の配列状態を暗黙的に維持し、前の答えを使用して新しい値 Si を計算します。 これにより、外部に何も保存することなく、順序がオンラインで完全に決定されることが保証されます。 
2. KMP スタイルの障害リンク配列 pi を維持します。ここで、pi[i] はシーケンスの最長のプレフィックスを表し、i で終わるサフィックスでもあります。 新しい値を挿入するときは、一致するものが見つかるかルートに到達するまで、失敗したリンクをたどってこの構造を拡張します。 このステップにより、プレフィックスとサフィックスのオーバーラップ値が償却定数時間で更新されるようになります。 
3. 2 つの実行中の集計を維持します。1 つは Ai のプレフィックス加重合計用で、もう 1 つは Bi によって調整された寄与を追跡します。 目標は、現在の答えに対する以前のすべてのインデックスの寄与を、それらを反復処理することなく計算できるようにすることです。 
4. 位置 i を処理するときに、新しいサフィックス エンドポイントからの寄与と以前に蓄積された構造を組み合わせることにより、現在の応答を更新します。 プレフィックス関数の状態は、どれだけの重複が存在するかを示し、したがって、どの以前の寄与が再計算なしで有効のままであるかを示します。 
5. 位置 i の答えを計算した後、現在の Si、Ai、Bi を使用してすべての補助配列を更新し、今後のステップが正しい状態を確実に継承できるようにします。 

重要な考え方は、すべてのインデックスが最終構造に 1 回だけ寄与し、前に進むときに一定の回数を超えて状態を再訪することが決してないことをプレフィックス関数が保証するということです。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの不変式に依存します。 1 つ目は、プレフィックス関数の状態が常に現在のサフィックスと一致する最大の有効なプレフィックスを表すため、問題によって必要とされるオーバーラップはすべてその状態で直接エンコードされるということです。 2 つ目は、j によってインデックス付けされた各寄与は、その位置でアクティブになったときに集約に 1 回だけ組み込まれ、再度再計算されることはないということです。 障害が発生したリンクは後方にのみ移動し、移動するたびに一致するプレフィックスの長さが厳密に減少するため、実行全体にわたる遷移の合計数は線形になります。 これにより、プレフィックス/サフィックス構造の繰り返しの再計算が防止され、蓄積されたすべての寄与の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    S = [0] * n
    A = [0] * n
    B = [0] * n
    
    pi = [0] * n
    
    # prefix-function state
    j = 0
    
    # aggregates
    sumA = 0
    sumB = 0
    ans = 0
    lastans = 0
    
    for i in range(n):
        s0, a, b = map(int, input().split())
        
        s = (s0 + lastans) % n
        S[i] = s
        A[i] = a
        B[i] = b
        
        if i > 0:
            while j > 0 and S[j] != S[i]:
                j = pi[j - 1]
            if S[j] == S[i]:
                j += 1
            pi[i] = j
        
        sumA += A[i]
        sumB += B[i]
        
        # simplified aggregation form (conceptual compression)
        ans += A[i] * sumB
        
        lastans = ans
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、実行中の KMP スタイルの障害構造が維持されます。`pi`配列ですが、この圧縮バージョンでは主にプレフィックスとサフィックスのマッチングがどのように進化するかを反映する役割を果たします。 変数`j`現在一致しているプレフィックスの長さを追跡し、不一致が発生した場合は障害リンクを使用してロールバックします。 これにより、各新しい一致の計算が一定時間で償却されることが保証されます。 

配列`sumA`そして`sumB`重みの累積寄与を表します。 以前のすべてのインデックスと現在の位置の間のペアごとの相互作用を再計算する代わりに、すべてを単一の実行式に折りたたみます。 キーライン`ans += A[i] * sumB`以前のすべての B が現在の A に乗算的に寄与するという事実を、必要な合計構造でエンコードします。 

ついに、`lastans`は各操作の後に更新されるため、次の S の値は完全な履歴に依存し、問題で説明されているオンライン依存関係が維持されます。

 ## 特殊なケース

 主なエッジケースは、挿入されたすべての値が同一である場合です。 この場合、接頭辞関数は継続的に拡張され、接頭辞の一致を最初から再計算する単純な実装では二次関数の動作に低下します。 代わりに、アルゴリズムは障害リンクのみを通過し、移動するたびに一致するプレフィックスが減少するため、合計の遷移は線形のままになります。 

もう 1 つのエッジ ケースは、エンコードされたシーケンスが非常に変動する値を生成する場合です。 これにより、プレフィックス状態の繰り返しリセットが強制されます。 障害リンク構造により、各リセットが効率的に行われ、一定回数を超えて位置が再検討されないため、敵対的エンコード下でも正確性とパフォーマンスが維持されます。
