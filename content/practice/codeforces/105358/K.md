 ## 問題の理解

 2 つのサイズ グループを持つ完全な 2 部構成のセットアップが与えられています。$n$、によってインデックス付けされた左頂点と考えることができます。$i$と右の頂点のインデックスは$j$。 間のエッジ$i$そして$j$値の XOR をとった場合にのみ存在します。$a_i \oplus b_j$、少なくとも$k$。 したがって、入力配列はグラフを直接記述しません。 どのペアが許可されるかを決定するしきい値ルールを定義します。 

タスクは、一致する最大値や単一の値を見つけることではありません。 代わりに、すべての$x$から$1$に$n$、正確に選択できる方法が何通りあるかを数えなければなりません$x$2 つのエッジが左右の頂点を共有しないような、互いに素なエッジ。 

これは、サイズの部分一致をすべてカウントするのと同じです。$x$隣接行列がビットごとの条件によって暗黙的に定義される 2 部グラフ内。 

制約$n \le 200$十分に小さいので、$O(n^3)$または$O(n^4)$動的計画法は現実的です。 右側のサブセットに関係するものはすべて、明示的に爆発してしまいます。$2^{200}$、それは完全に不可能です。 数字自体は次のようになります$2^{60}$ただし、XOR 比較のみが重要であるため、エッジの存在チェックでのみ使用される不透明な 60 ビット整数として扱うことができます。 

単純なアプローチでは、一致するものを直接列挙しようとします。$x$左側のノード、選択$x$正しいノードを見つけて、それらの間の完全な一致を数えます。 これにはすでに重大な問題が隠されています。 両方のサブセットを修正したとしても、完全一致のカウントは永続的な計算となり、指数関数的になります。$x$。 のために$n=200$、このアプローチはすぐに失敗します。 

より微妙な失敗例は、貪欲な組み合わせのアイデアから生じます。 左側の各ノードを独立して有効な右側のノードと照合しようとすると、右側の衝突が無視されるため、カウントが大幅にオーバーカウントされます。 たとえば、2 つの左側のノードが両方とも同じ小さな右側のノードのセットに接続している場合、有効なマッチングでは別個の右側の頂点を割り当てる必要がある場合でも、欲張りカウントではそれらを独立して扱います。 

## アプローチ

 実際に必要な構造は、標準的な組み合わせオブジェクト、つまり 2 部マッチング多項式です。 私たちが望むのは、それぞれ$x$、サイズの一致の数$x$。 重要な問題は、選択が共有された正しい頂点を通じて相互作用し、それが独立性を破壊することです。 

ブルートフォース手法では、左頂点と右頂点のすべてのサブセットを列挙し、それらの間に完全な一致が存在するかどうかを計算し、順列をカウントします。 固定サイズのペアの場合$x$、すべてのマッチングコストを確認する$O(x!)$、そして、あります$\binom{n}{x}^2$そのようなペアなので、中程度の場合でも$n$これは天文学的に大きくなり、おおよそ次のオーダーになります。$200!$- 最悪の場合のスケール動作。 

重要な点は、実際には明示的にマッチングを構築する必要がないということです。 必要なのはカウントだけです。 これにより、頂点を一度に片側ずつ処理し、指定された数の既に使用されている正しい頂点との部分一致がいくつ存在するかを維持することができます。 

左側の頂点を順番に処理します。 左の頂点ごとに、それをスキップするか、エッジを持つ未使用の右の頂点と一致させます。 難しいのは、どの右側の頂点がすでに使用されているかを追跡することですが、使用されたセットを明示的に保存する代わりに、一致の数にわたって動的プログラミング テーブルを維持し、右側の頂点にわたる構造化された遷移を通じて暗黙的に一意性を強制します。 

なぜなら$n$たったの200です、余裕です$O(n^2)$または$O(n^3)$隣接リストを慎重に事前計算すると、遷移が起こります。 左の各頂点は、XOR しきい値によって決定される右の頂点のサブセットに接続し、隣接性のチェックは一定時間行われます。 

これにより、問題は古典的な 2 部マッチングのカウント DP に還元されます。左側の頂点を処理し、サイズのマッチングを形成できる方法が何通りあるかを維持するというものです。$j$最初のことを考慮した後$i$左側のノード。利用可能なエッジを通過して選択肢を蓄積するだけで、右側のノードが再利用されないようにします。

 ## アルゴリズムのチュートリアル

 1. 隣接行列を事前計算する$g[i][j]$、 どこ$g[i][j] = 1$もし$a_i \oplus b_j \ge k$。 このステップでは、ビットごとの条件を標準のグラフ表現に変換し、後の遷移が純粋に組み合わせになるようにします。 
2. DP テーブルを定義します。$dp[i][j]$サイズの一致を形成する方法の数を表します$j$最初のものだけを使用して$i$左側の頂点。 右側の頂点は、選択された各エッジが 1 つの右側の頂点を確実に消費することによって暗黙的に制約されます。 
3.初期化$dp[0][0] = 1$。 左側の頂点がない場合、空のマッチングを形成する方法は 1 つだけです。 
4. 左側の頂点を 1 つずつ処理します。 固定左頂点の場合$i$、最初にすべての以前の状態を引き継ぎます。つまり、いつでも終了することを選択できます。$i$比類のない。 これにより、これまでに形成されたすべてのマッチングが保存されます。 
5. 州ごとに$dp[i-1][j]$、左の頂点を一致させようとします$i$すべての右の頂点に$t$そのような$g[i][t] = 1$。 それぞれの有効な$t$でカウントされた一致を拡張できます。$dp[i-1][j]$サイズを合わせて$j+1$、 提供された$t$建設初期には使用されていません。 
6. ステップ 5 が正しいかどうかは、各トランジションによってマッチング サイズが 1 つだけ増加し、エッジごとに一意の右頂点が割り当てられるため、左頂点の異なる順序によって 2 つのブランチが同じマッチングを作成できないという事実に依存しています。 
7. 左側の頂点をすべて処理した後、サイズの答えが得られます。$x$は$dp[n][x]$それぞれに$x$。 

### なぜ効果があるのか

 DP は、すべての州が次のことを行うという不変条件を維持します。$dp[i][j]$最初の一致のみを使用する一致をカウントします。$i$左の頂点と正確に$j$明確な右側の頂点。 各トランジションは、現在の構造を保存する (頂点をスキップする) か、左の頂点と以前に使用されていなかった右の頂点をペアにすることによって構造を拡張します。 各拡張では新しい右頂点が導入されるため、異なる選択シーケンスによってマッチングが 2 回形成されることはなく、すべての有効なマッチングには左頂点の処理と一致する固有の順序が付けられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    g = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if (a[i] ^ b[j]) >= k:
                g[i][j] = 1

    dp = [[0] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(1, n + 1):
        dp[i] = dp[i - 1][:]

        for j in range(i):
            if dp[i - 1][j] == 0:
                continue
            for t in range(n):
                if g[i - 1][t]:
                    dp[i][j + 1] = (dp[i][j + 1] + dp[i - 1][j]) % 998244353

    print(*dp[n][1:])

if __name__ == "__main__":
    solve()
```DP テーブルは行ごとにコピーされるため、左頂点の「スキップ」は前の行の継承によって自動的に処理されます。 トリプル ループ構造は概念的な遷移を反映しています。すでに一致する数を選択し、有効なエッジでそれらを拡張しようとします。 

右側の頂点上の内側のループは安全です。$n \le 200$、全体的な複雑さは残ります$O(n^3)$。 中間カウントでのオーバーフローを防ぐために、モジュロはすぐに適用されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、XOR 条件を満たすペアがない場合です。 この状況では、隣接行列はすべて 0 になります。 DP は拡張トランジションを実行しないため、すべての値が$dp[n][x]$のために$x \ge 1$ゼロのままで、$dp[n][0]=1$これは、一致するのは空のものだけであるという事実と一致します。 

もう 1 つのケースは、グラフが完全な 2 部構成である場合です。 すべての左の頂点がすべての右の頂点に接続されるため、DP は最大に拡張されます。 のために$n=2$、各拡張機能が可能なすべての順序で個別の正しい頂点を選択するため、ペアリングのすべての順序が寄与し、DP は一致のすべての順列を折りたたむのではなく正確にカウントします。
