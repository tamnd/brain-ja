 ## アルゴリズムのチュートリアル

 私たちは、各長方形がその中のすべての重みの gcd によって要約できること、およびこの gcd が到達可能な残基を決定するという事実に依存しています。 

1. ポイントを昇順にソートまたは処理します。$x$。 これにより、2D プレフィックス条件を変換できます。$x \le a$成長するアクティブセットへ。 
2. フェンウィックの木を維持します。$y$-座標。各ノードには、そのセグメントで現在アクティブな重みの gcd が格納されます。$y$。 各ポイント挿入が更新されます$O(\log n)$ノード、gcd 値を上向きにマージします。 
3. すべてのポイントを挿入した後、$x \le a$で任意のプレフィックスをクエリできます。$y$入手する$g(a,b)$、長方形内のすべての重みの gcd$(a,b)$。 This query costs$O(\log^2 n)$Fenwick トラバーサルとセグメント gcd マージを組み合わせることによって。 
4. gcd を使用した固定長方形の場合$g$、到達可能な残基のセットを決定します。 これらは正確に次の倍数です$g$モジュロ$n$。 そのようなすべての残基を反復処理します$c$、合計$a \cdot b \cdot c$答えに。 
5.全体的に貢献を蓄積する$(a,b)$。 以来$a$そして$b$サブセット構造とは独立した乗法重みとしてのみ表示されますが、再計算するのではなく、トラバース中に四角形カウントと一緒に累積することができます。 

重要な考え方は、サブセットを明示的に列挙しないということです。 サブセット構造を四角形ごとに 1 つの不変式に置き換えます。 

### なぜ効果があるのか

 アルゴリズムは、すべてのプレフィックス長方形について、サブセットの和を法とする不変式に依存します。$n$重みによって生成されたサブグループのみに依存し、その重みは gcd スタイルの不変式によってキャプチャされます。$g(a,b)$。 ランダムな入力の仮定の下では、各プレフィックス内のサブセット合計スペースがこのサブグループを飽和させる可能性が圧倒的に高いため、$c$で割り切れるのと同じです$g(a,b)$。 Fenwick 構造のマージでは gcd が正しく保存されるため、すべてのクエリで正しい不変式が取得され、したがって、応答に追加されるすべての寄与が真の条件と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

class FenwickGCD:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, val):
        while i <= self.n:
            self.bit[i] = gcd(self.bit[i], val)
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            res = gcd(res, self.bit[i])
            i -= i & -i
        return res

def main():
    n = int(input())
    pts = []
    for _ in range(n):
        x, y, w = map(int, input().split())
        pts.append((x, y, w))

    pts.sort()

    # compress y
    ys = sorted({y for _, y, _ in pts})
    yid = {y: i + 1 for i, y in enumerate(ys)}

    fw = FenwickGCD(len(ys))

    ans = 0
    MOD = 2**64

    i = 0
    for a in range(1, n + 1):
        while i < n and pts[i][0] <= a:
            x, y, w = pts[i]
            fw.update(yid[y], w)
            i += 1

        for b in range(1, n + 1):
            # compress b via ys
            # find rightmost y <= b
            l, r = 0, len(ys)
            while l < r:
                m = (l + r) // 2
                if ys[m] <= b:
                    l = m + 1
                else:
                    r = m
            g = fw.query(l)

            if g == 0:
                continue

            for c in range(g, n + 1, g):
                ans = (ans + a * b * c) & (MOD - 1)

    print(ans)

if __name__ == "__main__":
    main()

微妙な点は、モジュロ演算を避け、代わりにビットごとの AND を介して 64 ビット マスクを使用していることです。 これは問題の要件に一致し、オーバーフローのオーバーヘッドを防ぎます。

 ## 特殊なケース

 すべての点が同じ位置を共有する場合、問題全体は 1 つのサブセット合計インスタンスに縮小されます。 このアルゴリズムはすべての更新を 1 つのフェンウィック バケットにまとめ、gcd 不変式は結合された重み構造を正しく反映します。 

すべての重みが等しい場合、すべてのプレフィックス長方形はその重みに等しい同じ gcd を生成します。 したがって、アルゴリズムはすべてのシステムにわたって一貫した剰余セットを生成します。$(a,b)$、寄与度の集計は振動することなく安定したままです。 

点が非常にまばらな場合、各プレフィックス長方形に含まれる点は非常に少ないため、gcd は個々の重みによって支配されます。 Fenwick の更新ではこれらのシングルトン値が正しく伝播され、不連続なセグメント上の gcd が直接計算と一貫性を保っているため、誤ったマージは発生しません。
