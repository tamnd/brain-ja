 ## 解決策
 ## 問題の理解

 ボールは原点から選択した方向に沿って投げられ、その光線に沿って等間隔の点に繰り返し現れます。最初は遠くからです。$d$、その後、$2d$、 それから$3d$、 等々。 方向は一度選択すると固定されますが、平面内の任意の実際の方向にすることができます。 

飛行機の中には、$n$サークル。 これらの離散的な着地点の 1 つが円の内側または上にあるたびに、その円は 1 ポイントを与えます。 着地点が複数の円の内側にある場合、すべての円が同時に寄与します。 課題は、すべての円とすべての着地点にわたるそのような「ヒット」の総数が最大化されるように光線の方向を選択することです。 

キー オブジェクトは連続的な軌道ではなく、離散的な無限の点のシーケンスです。$P_k = k \cdot d \cdot u$、 どこ$u$は単位ベクトルです。 スコアは、これらのポイントのうちのいくつが指定されたディスクに当てはまるかによって完全に決定されます。 

制約は非常に具体的な意味で重要です。 まで$2 \cdot 10^4$円の場合、すべての方向または円のすべてのペアを直接チェックするアプローチは、すでに大きすぎます。 さらに重要なことは、すべての光線をシミュレートしたり、角度を細かく離散化しすぎたりするソリューションは失敗します。これは、答えが有限の候補セットではなく方向の連続的な選択に依存するためです。 

各円の半径は比較的小さく (最大 50)、間隔は$d$も小さいです (最大 10)。 これは、固定円の場合、インデックスの数が少数であることを強く示唆しています。$k$ヒット作を生み出す可能性があります。$k d$が円の​​中心から原点までの距離から遠い場合、円にはその点を含めることはできません。 

各円が最大 1 つのヒットに寄与すると仮定すると、微妙な失敗例が現れます。 円は、異なる倍数で複数回交差することができます。$d$。 たとえば、円の中心が原点付近にあるが十分に大きい場合、両方の$k=2$そして$k=3$同じ方向に対して有効なヒットが生成される可能性があります。 

もう 1 つの落とし穴は、各円が 1 つの角度制約のみを課すかのように問題を扱うことです。 制約は実際に依存します$k$、そして異なる$k$同じ円の値によって異なる角度間隔が生成されます。 

## アプローチ

 この問題を考える直接的な方法は、方向を固定して光線をシミュレートすることです。 円ごと、整数ごとに$k$、ポイントかどうかを確認します$k d u$円の中にあります。 すべてのサークルとすべてにわたって$k$、一致をカウントします。 これは正しいですが、方向の候補の数は無限であり、1 つの方向を評価する場合でも、すべての円と関連するすべての円をチェックする必要があるため、絶望的に遅いです。$k$。 

重要な構造観察は視点を逆転させることです。 方向を固定して円を確認する代わりに、円を固定してどの方向とどのインデックスを尋ねます。$k$対応する点はその中にあります。 

中心のある円を固定する$C$。 固定の場合$k$、という条件。$k d u$円の内側にあるのは方向に対する幾何学的制約です$u$。 ポイント$k d u$は原点から一定の距離にあるため、原点を中心とする半径の円という 2 つのオブジェクトを交差させます。$k d$、およびを中心とする指定された円$C$。 この交点は、原点がその半径距離で円を「見る」ことができる角度のセットに対応します。 

それぞれの有効な$k$、方向のセット$u$連続した角度間隔を形成します。 その間隔は次の方向を中心としています。$C$、その半値幅は余弦の法則によって決まります。 

残りの問題は何人かです$k$円ごとの値を考慮する必要があります。 原点からの距離$k d u$は固定されているため、距離を中心とする円の場合$|C|$、の値のみ$k$そのような$k d$以内にあります$r$の$|C|$おそらく機能する可能性があります。 これにより、整数の範囲が狭くなります。$$\frac{|C| - r}{d} \le k \le \frac{|C| + r}{d}.$$なぜなら$r \le 50$そして$d \ge 5$、この範囲には、円ごとに最大約 20 個の整数が含まれます。 

これにより、問題は、それぞれの重みが 1 である角度間隔の集合を生成し、円上でそれらの間の最大の重なりを見つけることになります。

 ## アルゴリズムのチュートリアル

 1. 各円について、その距離を計算します。$R$原点と方向角から$\theta$原点から中心まで。 これにより、その円のすべての可能なヒットの中心ジオメトリが修正されます。 
2. の整数範囲を決定します。$k$円が原点を中心とする円と半径で交差できるようにする$k d$。 これはから得られます$|R - r| \le k d \le R + r$、整数の範囲に変換されます。 このステップでは、無関係な倍数をすべて除外します。 
3. 各整数について$k$この範囲では、問題を 2 つの円の間の角度の可視性の問題として扱います。1 つは原点を中心に半径を持つ円です。$k d$、および指定された円。 
4. 角度の半値幅を計算します。$\alpha$コサインの法則を使用すると、次のようになります。$$\cos \alpha = \frac{(k d)^2 + R^2 - r^2}{2 k d R}.$$値がわずかに外側になるように数値の問題をクランプします。$[-1,1]$アーコスを壊さないでください。 
5. 間隔を追加する$[\theta - \alpha, \theta + \alpha]$。 それを越えると、$-\pi, \pi$境界を 2 つの区間に分割します。 
6. すべての円とすべての有効な円を処理した後$k$、すべての間隔のエンドポイントを並べ替え、角度をスイープして、アクティブな間隔の累計を維持します。 
7. この累計の最大値が答えであり、サークルヒットイベントの最大数と交差する方向に対応します。 

### なぜ効果があるのか

 各ペア$(\text{circle}, k)$独立してスコアに貢献します。固定方向の場合、カウントされるかカウントされません。 ジオメトリは、固定の場合を示しています$k$、条件を満たす方向のセットは、ちょうど 1 つの角度間隔です。 したがって、すべての有効なイベントは単位円上の間隔として表すことができ、方向の最終スコアはその角度をカバーする間隔の数とまったく同じになります。 スコアを最大化することは、円上の最大オーバーラップの問題となり、スイープ ラインはすべてのオーバーラップを正確に捕捉します。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def norm_angle(a):
    while a <= -math.pi:
        a += 2 * math.pi
    while a > math.pi:
        a -= 2 * math.pi
    return a

def add_interval(events, l, r):
    if l <= r:
        events.append((l, 1))
        events.append((r, -1))
    else:
        events.append((-math.pi, 1))
        events.append((r, -1))
        events.append((l, 1))
        events.append((math.pi, -1))

n, d = map(int, input().split())

events = []

for _ in range(n):
    x, y, r = map(int, input().split())
    R = math.hypot(x, y)
    if R == 0:
        continue

    base_angle = math.atan2(y, x)

    k_min = int(math.ceil((R - r) / d))
    k_max = int(math.floor((R + r) / d))

    if k_max < 1:
        continue
    k_min = max(k_min, 1)

    for k in range(k_min, k_max + 1):
        rk = k * d

        val = (rk * rk + R * R - r * r) / (2 * rk * R)
        val = max(-1.0, min(1.0, val))

        ang = math.acos(val)

        l = base_angle - ang
        rgt = base_angle + ang

        l = norm_angle(l)
        rgt = norm_angle(rgt)

        add_interval(events, l, rgt)

events.sort()

ans = 0
cur = 0
for a, t in events:
    cur += t
    ans = max(ans, cur)

print(ans)
```コードは、各円を、実現可能なすべての有効な視線方向の角度記述に変換することから始まります。$k$。 の`k_min`そして`k_max`計算は、不要なインデックスの反復を防ぐための重要な枝刈りステップです。 

各間隔は、ラップアラウンドを処理するために慎重に正規化されます。$\pm \pi$角度スイープには線形順序付けが必要なためです。 スイープ自体は、並べ替えられたイベントに対する標準的な差分配列です。 

微妙な詳細は、呼び出し前にコサイン引数をクランプすることです。`acos`接線に近い浮動小数点演算では、有効な領域からわずかに外れる値が生成される可能性があるためです。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    input = sys.stdin.readline

    n, d = map(int, input().split())
    events = []

    def norm(a):
        while a <= -math.pi:
            a += 2 * math.pi
        while a > math.pi:
            a -= 2 * math.pi
        return a

    def add(l, r):
        if l <= r:
            events.append((l, 1))
            events.append((r, -1))
        else:
            events.append((-math.pi, 1))
            events.append((r, -1))
            events.append((l, 1))
            events.append((math.pi, -1))

    for _ in range(n):
        x, y, r = map(int, input().split())
        R = math.hypot(x, y)
        if R == 0:
            continue
        ang0 = math.atan2(y, x)

        kmin = int(math.ceil((R - r) / d))
        kmax = int(math.floor((R + r) / d))
        kmin = max(kmin, 1)
        if kmax < kmin:
            continue

        for k in range(kmin, kmax + 1):
            rk = k * d
            val = (rk*rk + R*R - r*r) / (2*rk*R)
            val = max(-1.0, min(1.0, val))
            ang = math.acos(val)
            add(norm(ang0-ang), norm(ang0+ang))

    events.sort()
    cur = ans = 0
    for _, t in events:
        cur += t
        ans = max(ans, cur)
    return str(ans)

# circle hits twice
assert run("1 5\n10 0 6\n") == "2"

# far circle, no hit
assert run("1 5\n100 0 1\n") == "0"

# symmetric case
assert run("2 5\n10 0 6\n-10 0 6\n") == "2"

 ## 特殊なケース

 原点から遠く離れた半径の小さい円は空の円を生成します。$k$-range であり、アルゴリズムは自然にそれをスキップします。$k_{\max} < k_{\min}$。 これにより、無効な間隔の生成が防止され、不必要な浮動小数点計算が回避されます。 

円が複数の半径と交​​差するほど大きい場合$k d$の場合、アルゴリズムは同じ円に対して複数の間隔を生成します。 各間隔は独立しており、スイープ ラインはそれらを個別の寄与として正しくカウントします。 これは、最適な方向が同じ幾何学的領域を異なる距離で通過する場合に非常に重要です。 

間隔をまたぐとき$-\pi$境界線では 2 つに分割され、スイープ ラインの順序が一貫していることが保証されます。 これがないと、角張った構造が壊れ、枝のカット付近の重なりが誤って数えられる可能性があります。
