 ## 解決策
 ## 問題の理解

 私たちには一連のカップが与えられ、各カップには 1 から n までの固有のラベルが付いています。 これらのラベルの最初の左から右の順序は不明です。 私たちが知っているのは、この行で実行される m 個の操作の正確なシーケンスです。 

各操作では、特定のラベル付きカップを選択し、それを行の一番前に移動し、他のすべてを右に移動します。 面白いのは、操作がライン内の現在の位置ではなく、カップのラベルとマジシャンのシャッフル プロセス中に観察された位置によって記述されることです。 

私たちのタスクは、ラベルの少なくとも 1 つの初期順序を再構築し、そこから開始して m 個の操作をすべて順番に再生した場合に、記述された位置が各ステップで有効なままになるようにすることです。 そのような初期順列が存在しない場合は、不可能であることを報告する必要があります。 有効な初期順列が複数存在する場合は、辞書編集的に最小のものを出力する必要があります。 

主な困難は、動的再配置によって引き起こされる制約から逆算して推論していることです。 各操作は、要素の相対的な順序を制限し、以前の選択に応じて構造を進化させます。 

10^6 までの n、m の制約により、シフトを伴う配列またはリストの操作を単純にシミュレートするソリューションは直ちに除外されます。 操作ごとに線形作業を実行するアプローチでは、時間がかかりすぎます。 線形または線形に近い合計複雑度、理想的には O(n + m) または O((n + m) log n) が必要です。 

初期の操作が後の位置要件と暗黙的に矛盾する場合、微妙な失敗のケースが発生します。 たとえば、操作で特定のラベルが位置 y にあると主張しているが、最初の順序に関係なく、以前の移動によりそれが不可能になった場合、入力は一貫性がありません。 もう 1 つの失敗モードは、要素を前方に移動すると他のすべてのインデックスがシフトし、位置制約が時間依存になることを無視することです。 

## アプローチ

 直接順方向シミュレーションでは、カップの配列を維持し、各操作で位置 y にある要素を見つけてそれを前方に移動しようとします。 これは概念的には簡単ですが、y 番目の要素を見つけて単純なリストで削除と挿入を繰り返し実行すると、最悪の場合、制限をはるかに超える O(nm) の動作が発生します。 

これを改善するには、効率的な k 番目の要素へのアクセスとカット アンド ペースト操作による動的な順序維持をサポートする構造が必要です。 平衡二分探索ツリーまたは暗黙的トレプは、これらの操作を O(log n) で自然に処理しますが、それを使用した場合でも、問題をさらに単純化するより深い観察があります。 

重要な洞察は、未知の順列から進むプロセスを実際にシミュレートする必要がないということです。 代わりに、最終的な構成を構築してから、制約を逆方向にリバース エンジニアリングすることができます。 「x を位置 y から前に移動する」という各操作は、移動の直前に、要素 x が現在のシーケンス内の位置 y に正確になければならないことを意味します。 これにより、最終状態からの貪欲な配置問題として解釈できる、強制的な相対順序制約のシーケンスが作成されます。 

すべての中間状態を明示的に再構築する代わりに、操作を逆に処理し、最終的な順序を段階的に構築できます。 すでに決定されている位置を表す構造を維持し、必要な位置制約を維持しながら操作の逆の順序で要素を挿入します。 辞書編集的に最小限の出力を達成するために、新しい要素に複数の位置が可能な場合は、常に制約に従って利用可能な最小の位置を選択します。

これにより、各要素を引き続き有効な位置に配置できるようにしながら、空のスロットの動的なセットを維持し、要素を逆の順序で割り当てるという問題が軽減されます。 フェンウィック ツリーまたは順序付きセット オーバー ポジションを使用すると、k 番目の空きスロットを効率的に見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nm) | O(n) | 遅すぎる |
 | 順序統計構造 (Fenwick / BIT) | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 操作を逆の順序で処理します。これは、各順方向操作が移動前に要素が存在していたはずの場所を特定し、逆にするとこれらの制約が配置に変換されるためです。 

1. 1 から n までのすべての位置が空の状態で開始します。 逆のプロセスで右から左に埋めていきますが、操作によって引き起こされる制約は尊重されます。 スロットがまだ空いているかどうかを示す位置に対してフェンウィック ツリーを維持します。 
2. 配列を維持する`pos[x]`値 x に割り当てられる最終位置を表します。 最初はすべて未設定です。 
3. m から 1 まで演算を処理します。演算 (x, y) については、次のように解釈します。逆処理でこの演算の直前に到達したとき、要素 x は、その配置が決定される前に、現在の構造内で正確に y 個の空き位置が考慮されるように配置されなければなりません。 これは、y 番目の利用可能なスロットを選択することになります。 
4. x を配置するには、部分的に埋められている現在の配列内の y 番目の空き位置をフェンウィック ツリーに問い合わせます。 y が空き位置の数より大きい場合、構築は不可能であり、終了します。 
5. その位置に x を割り当て、フェンウィック ツリー内で塗りつぶされたものとしてマークします。 
6. すべての操作が処理された後、残りの未割り当ての位置が、位置の昇順で残りのラベルで埋められ、その中で、辞書編集上最小限の配置が確保されるようにラベルの順序が昇順になります。 

### なぜ効果があるのか

 各操作は、要素が後の操作でまだ固定されていないすべての要素に対して相対的である必要がある場所を制約します。 逆の処理により、要素を配置するときに、後の操作から要素に影響を与えるすべての制約がすでに解決されていることが保証されます。 フェンウィック ツリーでは、常に残りのスロットの数と一致する位置を選択するように強制され、フォワード プロセスの正確な位置セマンティクスが維持されます。 不変条件は、すべてのステップで、部分的に構築された配列を、処理されたすべての制約と一致する完全に有効な初期順列に拡張できることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)
    
    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i
    
    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s
    
    def find_kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n, m = map(int, input().split())
    ops = []
    for _ in range(m):
        x, y = map(int, input().split())
        ops.append((x, y))
    
    fw = Fenwick(n)
    for i in range(1, n + 1):
        fw.add(i, 1)
    
    pos = [0] * (n + 1)
    used = [False] * (n + 1)
    
    for x, y in reversed(ops):
        if fw.sum(n) < y:
            print(-1)
            return
        p = fw.find_kth(y)
        if pos[x] == 0:
            pos[x] = p
            fw.add(p, -1)
    
    remaining = []
    for i in range(1, n + 1):
        if not any(pos[j] == i for j in range(1, n + 1)):
            remaining.append(i)
    
    # fill remaining labels
    unused = [i for i in range(1, n + 1) if pos[i] == 0]
    ptr = 0
    for i in range(1, n + 1):
        if pos[i] == 0:
            pos[i] = remaining[ptr]
            ptr += 1
    
    ans = [0] * n
    for v in range(1, n + 1):
        ans[pos[v] - 1] = v
    
    print(*ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、どのポジションがまだ割り当て可能であるかを維持するために使用されます。 の`find_kth`関数は、y 番目の自由位置を効率的に見つけます。これは、逆の制約を尊重するために必要な核となる操作です。 

の`pos`配列は、再構築された初期順列で各ラベルがどこになるかを記録します。 すべての制約された割り当てを処理した後、辞書編集上の最小性を確保するために、残りのギャップを昇順に埋めます。 

微妙な問題は、ラベルに位置を 1 回だけ割り当てるようにすることです。 小切手なし`if pos[x] == 0`、繰り返し出現すると構造が破損します。 

## 実用的な例

 ### 例 1

 入力:```
2 1
2 1
```ポジション {1,2} が空いている状態から開始します。 

| ステップ | 操作 | フリーポジション | y 番目の無料 | 割り当て |
 | --- | --- | --- | --- | --- |
 | 1 (逆) | (2,1) | {1,2} | 1→1 | pos[2]=1 |

 処理後、ラベル 1 は割り当てられていないため、残りの位置 2 が使用されます。 

最終的な配列は次のようになります`[1, 2]`ですが、ラベル 2 は位置 1 に固定されているため、出力します。`[2, 1]`。 

これは、逆配置によって最初に相対構造が固定され、残りのラベルが辞書編集的に埋められるようにされる様子を示しています。 

### 例 2

 次のことを考慮してください。```
3 2
1 1
2 1
```(2,1) を処理してから (1,1) を処理します。 

| ステップ | 操作 | 無料 | 割り当て |
 | --- | --- | --- | --- |
 | 1 | (2,1) | {1,2,3} | pos[2]=1 |
 | 2 | (1,1) | {2,3} | pos[1]=2 |

 残りのラベル 3 が位置 3 になります。 

最終的な置換は`[2,1,3]`。 

これは、以前の操作が逆処理における以前の位置を制約することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各操作にはフェンウィック ツリーのクエリと更新が必要です。 
| スペース | O(n + m) | ツリー、操作、および位置マッピングのストレージ |

 ## 特殊なケース

 1 つのエッジ ケースは、複数の操作が同じラベルをターゲットとする場合に発生します。 その状況では、逆の順序で最初の有効な割り当てのみを使用できます。 それ以降の試みはすでに固定された位置と競合するため、アルゴリズムはそれを正しく無視します。 

もう 1 つのケースは、y が残りの空きポジションの数を超える場合です。 たとえば、スロットが 2 つだけ残っており、操作で 3 番目の空きスロットが要求された場合、フェンウィック ツリーはこれを即座に検出し、不可能を返します。 

最後の微妙なケースは、すべての制約が処理された後、多くのラベルが割り当てられていないままである場合です。 これらは任意ではありません。操作によって決して制約されない要素に対応します。 位置の昇順でそれらを埋めることは、それらの配置を制限する操作がないため、制約に違反せずに辞書編集上の最小性を維持します。
