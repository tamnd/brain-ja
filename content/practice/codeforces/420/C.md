 ## 解決策
 ## 問題の理解

 社内会議の参加者はそれぞれ他の2人を指さし、犯人はその2人のうちの1人であると主張します。 これから、入力を長さの配列として考えることができます。$n$、各インデックスは$i$順序付けられていないペアを保存します$(x_i, y_i)$。 このペアは、$i$-番目の人が暗示します。 

会社のトップは、容疑者として 2 人の異なる人物を選ばなければなりません。 参加者は、2 人の容疑者のうち少なくとも 1 人が、彼らが述べたペアに現れる場合、この選択を「支持」します。 言い換えれば、各入力ペアは、少なくとも 1 つのエンドポイントを共有する場合は常に、選択したエンドポイントのペアに「投票」するエッジのように機能します。 

タスクは、順序付けられていない個別の人々のペアが何組あるかを数えることです。$(a, b)$少なくとも次からの支援を受けるだろう$p$参加者。 

制約が十分に大きいため、すべての候補の疑わしいペアを明示的に反復するアプローチは不可能です。 と$n$まで$3 \cdot 10^5$、ペアの二次列挙は次のことを意味します$10^{10}$これは実行可能な限界をはるかに超えています。 解決策でも$O(n \sqrt{n})$慎重に最適化しない限り、動作が厳しくなる危険性があります。 

微妙な複雑さは、同じ順序のないペアであることです。$(a, b)$入力ステートメント内で複数回出現する可能性があります。 両方のエンドポイントが容疑者として選択された場合、このような繰り返しステートメントの影響が異なるため、これはカウントに影響します。 

いくつかの特殊なケースは分離する価値があります。 いつ$p = 0$、異なる人々のすべてのペアが有効であるため、答えは次のようになります。$\binom{n}{2}$。 いつ$p = n$、すべてのステートメントが一致する必要がありますが、これはすべての入力ペアと交差するペアでのみ発生し、通常は非常に小さなセットまたはゼロにまで減少します。 もう 1 つの重要な状況は、多くの人が同じペアについて繰り返し言及する場合です。$(a, b)$なぜなら、これらの繰り返しは、修正されなければ素朴な学位に基づく推論を壊す形で合意数に影響を与えるからです。 

## アプローチ

 直接的なアプローチは、すべての順序付けされていない容疑者のペアを反復処理することです。$(a, b)$そして、ペアごとにすべてをスキャンします$n$ステートメントのうち、少なくとも 1 つが含まれるステートメントの数を数えます。$a$または$b$。 これは正しいですがコストがかかります$O(n^3)$合計すると、$O(n^2)$候補ペアと各チェックは$O(n)$。 

問題の構造により、よりコンパクトなビューが可能になります。 固定候補ペアの場合$(a, b)$、ステートメントは、いずれかのエンドポイントに触れた場合に寄与します。 させたら$\text{deg}[v]$すべてのステートメントにわたってその人が何回登場するか、次に該当するステートメントの合計数になります。$a$または$b$は$\text{deg}[a] + \text{deg}[b]$。 これにより、両方を明示的に言及するステートメントのみが二重にカウントされます。$a$そして$b$, したがって、それらの多重度を減算します。 もし$\text{cnt}[a][b]$は正確なペアの回数です$(a, b)$が入力に含まれている場合、一致するステートメントの真の数は次のようになります。$$\text{deg}[a] + \text{deg}[b] - \text{cnt}[a][b].$$これにより、問題は、次数に対して非ゼロのみの小さな補正項を使用して、次数を含むしきい値条件を満たすペアの数を数えるという問題に変換されます。$n$入力ペア自体。 

主な課題は依然として、候補ペアを効率的に列挙することです。 頂点を次数で並べ替えると、2 ポインター スイープで条件を満たすペアの数をカウントできるようになります。$\text{deg}[a] + \text{deg}[b] \ge p$、修正は無視します。 これにより、有効なペアの楽観的なスーパーセットが得られます。 この後、入力ペアのみをチェックしてオーバーカウントを修正します。入力ペアのみが非ゼロを持つことができるためです。$\text{cnt}[a][b]$。 このようなペアごとに、修正によって無効になるかどうかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのペアに対するブルート フォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | ソート + 2 つのポインター + 修正 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各人について、すべてのステートメントにわたってその人が何回出現するかを計算します。 

これにより次の度配列が得られます。$\text{deg}[v]$ステートメント グラフ内でノードがどの程度「人気」があるかを測定します。 
2. すべての人々を学位の昇順に並べ替えます。 

この順序により、2 つのポインターを使用してペアの合計を効率的に推論できるようになります。 
3. 2 つのポインターを使用して、順序付けされていないすべてのペアをカウントします。$(a, b)$そのような$\text{deg}[a] + \text{deg}[b] \ge p$。 

左側の端点ごとに$i$、条件が満たされている間、右ポインタをできるだけ左に移動し、以下を含むすべての有効なペアを追加します。$i$。 

正確さはソートされた次数の単調性から生まれます。つまり、1 つのエンドポイントを増加しても合計が増加するだけです。 
4. 周波数マップを構築する$\text{cnt}$入力からの順序のないペアに対して。 

各入力ステートメントは、ちょうど 1 つの順序なしペアに 1 つの出現をもたらします。 
5. すべての入力ペアを反復処理します。$(x_i, y_i)$そしてそれらを修正候補として扱います。 

このようなペアごとに、それが塩基カウントに含まれているかどうか、また含まれるべきではないかどうかを確認します。 

もし$\text{deg}[x_i] + \text{deg}[y_i] \ge p$しかし$\text{deg}[x_i] + \text{deg}[y_i] - \text{cnt}[x_i][y_i] < p$の場合、このペアは誤ってカウントされたため、一度削除する必要があります。 
6. 修正後の合計を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、問題を構造的な上限と局所的な修正に分離します。 2 ポインター フェーズでは、純粋に度数合計によってペアを分類し、少なくとも 1 つのエンドポイントに接触するステートメントの数を集計して取得します。 この推定値からの逸脱は、両方のエンドポイントを同時に含むステートメントによってのみ引き起こされ、それらはまさに入力ペアそのものです。 他のペアはゼロ以外の補正項に寄与しないため、元のペアのみをチェックします。$n$すべてを再検討することなく、超過数を完全に調整するにはペアで十分です。$O(n^2)$可能性。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())

pairs = []
deg = [0] * (n + 1)
cnt = {}

for _ in range(n):
    x, y = map(int, input().split())
    pairs.append((x, y))
    deg[x] += 1
    deg[y] += 1

    a, b = (x, y) if x < y else (y, x)
    cnt[(a, b)] = cnt.get((a, b), 0) + 1

order = list(range(1, n + 1))
order.sort(key=lambda x: deg[x])

ans = 0
r = n - 1

for l in range(n):
    while r >= 0 and deg[order[l]] + deg[order[r]] >= p:
        r -= 1
    ans += (n - 1 - r)

# subtract overcounted invalid pairs
for x, y in pairs:
    if x > y:
        x, y = y, x
    if deg[x] + deg[y] >= p:
        if deg[x] + deg[y] - cnt[(x, y)] < p:
            ans -= 1

print(ans)
```次数配列は入力から直接構築され、各ステートメントを 2 つの寄与として扱います。 ペアの頻度マップは、エンドポイントを並べ替えることによって正規化されます。$(a, b)$そして$(b, a)$は同一です。 

2 ポインター セクションは、両方のエンドポイントがソートされた次数の順序で反復されるという事実に依存しています。 ポインタ`r`左にのみ移動するため、ソート後の全体的な複雑さは線形に保たれます。 

補正ループは、$n$input ステートメント。二次関数の動作を回避します。

### 2 ポインタカウントフェーズ

 次数の和が少なくとも 2 であるペアを数えます。 

| l | ノード l | r 開始 | 有効なペアが追加されました |
 | --- | --- | --- | --- |

 これにより、塩基数は 6 ペアになります。 

### 修正フェーズ

 入力ペアを調べます。 

| ペア | 度和 | CNT | 調整済み合計 | アクション |
 | --- | --- | --- | --- | --- |

このトレースは、2 ポインタ フェーズが意図的に安全にオーバーカウントしていること、および修正は繰り返しのステートメントによって合意が膨らむ場合にのみ適用されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 並べ替えが優先されます。 2 ポインター掃引は線形であり、補正は入力ペアに対するシングル パスを使用します。 
| スペース |$O(n)$| 入力ペアの次数配列、順序配列、および周波数マップ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    data = inp.strip().split()
    n = int(data[0]); p = int(data[1])
    idx = 2
    pairs = []
    deg = [0] * (n + 1)
    cnt = {}

    for _ in range(n):
        x = int(data[idx]); y = int(data[idx+1]); idx += 2
        pairs.append((x, y))
        deg[x] += 1
        deg[y] += 1
        a, b = (x, y) if x < y else (y, x)
        cnt[(a, b)] = cnt.get((a, b), 0) + 1

    order = list(range(1, n + 1))
    order.sort(key=lambda x: deg[x])

    ans = 0
    r = n - 1
    for l in range(n):
        while r >= 0 and deg[order[l]] + deg[order[r]] >= p:
            r -= 1
        ans += (n - 1 - r)

    for x, y in pairs:
        if x > y:
            x, y = y, x
        if deg[x] + deg[y] >= p:
            if deg[x] + deg[y] - cnt[(x, y)] < p:
                ans -= 1

    return str(ans).strip()

 ## 特殊なケース

 いつ$p = 0$、ステートメントに関係なく、個別のノードの順序のないペアはすべて有効です。 アルゴリズムは最初のフェーズでもすべての次数と和のペアをカウントしますが、補正フェーズでは何も削除されないため、出力は正しく次のようになります。$\binom{n}{2}$。 

すべてのステートメントが同一の場合、すべてのコーダーの名前を言います$(1, 2)$、次数は 2 つのノードに集中します。 唯一の潜在的な問題は、高頻度によるオーバーカウントですが、修正ステップでは正確なペア頻度をチェックすることでこれを明示的に処理し、最終的なカウントが真の一致条件を反映していることを確認します。 

必要な閾値に達したとき$p$が非常に大きい場合、次数の合計がしきい値に到達できないため、ほとんどのペアは 2 ポインター フェーズ中にフィルターで除外されます。 アルゴリズムはそれらをさらに探索することはなく、最初のフィルターで生き残る候補ペアがないため、修正チェックは無関係になります。
