 ## 解決策
 ## 問題の理解

 私たちは、すべてのノードが最初に値 0 を保持するルート付きツリーに取り組んでいます。 時間の経過とともに、サブツリー全体またはノードの直接の子のみに影響を与える更新を適用します。また、サブツリーまたは子セットの最大値を求めるクエリに答える必要もあります。 

重要な考え方は、このツリーには 2 つの根本的に異なる「領域」があるということです。1 つはオイラー ツアーの連続セグメントに対応する、あるノードをルートとするサブツリーで、もう 1 つはノードの直接の子のセットで、単純な走査順序では連続していません。 タイプ 1 の更新はサブツリー構造とよく調和しますが、タイプ 2 の更新はノードの深さ 1 の子孫のみを対象とするため、その単純性が損なわれます。 

この制約により、線形に近い解決策が得られます。 最大 300,000 のノードと 300,000 の操作があるため、クエリごとに個々のノードにアクセスするソリューションは遅すぎます。 クエリごとの単純な DFS 更新では O(nq) まで低下しますが、これは不可能です。 慎重な構造を持たないサブツリーごとのセグメント ツリーでも、ツリーを線形表現に圧縮し、子レベルの操作を個別に処理しない限り、困難になります。 

タイプ 2 およびタイプ 4 のクエリでは、微妙なエッジ ケースが発生します。 たとえば、多数の子を持つノードを考えます。ノード 1 に 2 ～ 100000 の子があるとします。タイプ 2 の更新はそれらすべてに値を追加し、タイプ 4 のクエリはそれらの最大値を要求します。 クエリごとに隣接リストを反復する単純なアプローチは、すぐに失敗します。 もう 1 つの問題は更新の重複です。ノードは祖先からサブツリー更新を受け取ることができ、またその親からの子更新の一部となることができ、これら 2 つの貢献を正しく組み合わせる必要があります。 

## アプローチ

 強引な解釈は簡単です。 更新ごとに、サブツリーまたは子の隣接リストを走査し、保存されている値を直接変更します。 クエリは必要なセットを横断し、その場で最大値を計算します。 これは問題定義を直接シミュレートするため、これは正しいです。 

ただし、各サブツリー走査は O(n) 個のノードに接触する可能性があり、そのような操作が O(q) 回存在する可能性があります。 最悪の場合、ツリーはチェーンに縮退し、すべてのサブツリー クエリは線形になり、複雑さは O(nq) になります。 バランスの取れたツリーであっても、サブツリーの探索を繰り返すと、二次的な動作が蓄積されます。 

重要な観察は、サブツリー操作をオイラー ツアー間隔にマッピングして、範囲更新および範囲最大クエリにすることができることです。 難しい部分は「子のみ」の操作です。ノードの子はオイラー順序で連続していないためです。 

重要な洞察は、コントリビューションを 2 つのレイヤーに分割することです。 1 つのレイヤーは、オイラー ツアーと遅延伝播によるセグメント ツリーを使用して、グローバル サブツリー効果を処理します。 2 番目の層は「親から子への直接貢献」を処理します。これは、親がタイプ 2 の操作を通じてノードに直接プッシュした量を表す値として、ノードごとに個別に維持できます。 次に、子間の最大値を効率的にクエリする方法が必要になります。これは、子を明示的にグループ化するか、親をキーとする補助セグメント ツリーを維持することによって、オイラー順序で子のインデックスに対するノードごとのセグメント ツリーを維持することに帰着します。 

これをより明確に理解する方法は、すべてのノードの値が、サブツリー遅延寄与とその親からの「直接の子ボーナス」の合計であるということです。 サブツリーの更新をグローバルに維持し、すべての子に遅延加算を適用してそれらの最大値をクエリできる構造をノードごとに個別に維持します。 これにより、2 レベルのセグメント ツリー設計が行われます。1 つはサブツリー クエリのオイラー順序で、もう 1 つは子クエリの隣接リストでノードごとですが、フラット化された子リストでセグメント ツリーを使用するか、親タグ付きの伝播を備えたグローバル構造を使用して効率的に実装されます。

このハイブリッド構造により、各更新またはクエリは O(log n) 状態のみに影響を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O((n+q) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートし、各サブツリーが連続セグメント [tin[x], tout[x]] に対応するオイラー ツアー順序付けを計算します。 

範囲の追加と範囲の最大値のクエリをサポートする、このオイラー次数のセグメント ツリーを維持します。 この構造は、タイプ 1 のすべての更新とタイプ 3 のクエリを処理します。 

タイプ 2 とタイプ 4 では、「x の子」がまさにparent[x] を持つノードであるという事実を利用し、隣接リストを保存します。 第 2 層構造を構築します。ノード x ごとに、その子のオイラー位置にわたるセグメント ツリーを維持します。 これにより、ローカル構造内の範囲として子に対して更新とクエリを効率的に適用できるようになります。 

1. ノード 1 でツリーをルートし、DFS オイラー ツアーを使用して tin と tout を計算します。 これにより、すべてのサブツリーが連続した間隔になります。 
2. 親リストと隣接リストを保存します。 各ノードについて、その子のリストもオイラー順に作成して、子ベースの操作をセグメント操作として処理できるようにします。 
3. オイラー位置にグローバル セグメント ツリーを構築します。 この構造は、範囲の追加と範囲の最大クエリをサポートします。 これは、タイプ 1 の操作から蓄積されたすべてのサブツリー値を表します。 
4. 各ノードについて、その子の tin 位置の上に二次構造を構築します。 これにより、高速な更新と直接の子に対する最大のクエリが可能になります。 
5. タイプ 1 クエリ (x, v) の場合、グローバル セグメント ツリー内の [tin[x], tout[x]] に対して v の範囲加算を実行します。 これにより、サブツリー内のすべてのノードが均一に更新されます。 
6. タイプ 2 クエリ (x, v) の場合、x の子セグメント構造に v の範囲加算を適用します。 これにより、すべての子供たちの寄付が直接増加します。 
7. タイプ 3 クエリ (x) の場合、グローバル セグメント ツリー内の [tin[x], tout[x]] の最大値をクエリし、出力します。 これには、すべてのサブツリーの貢献がすでに含まれています。 
8. タイプ 4 のクエリ (x) の場合、x の子セグメント構造の最大値をクエリし、出力します。 

この分解が有効である理由は、サブツリーの更新が親子のみの更新から独立しているためです。 各ノードの最終値は、すべての祖先サブツリー操作からの寄与と、その親の子の更新からの直接寄与の合計です。 これら 2 つのソースは別々ではあるが互換性のあるセグメント構造で処理されるため、二重にカウントされることなくきれいに結合されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)
        self.lz = [0] * (4 * n)

    def push(self, i):
        if self.lz[i] != 0:
            v = self.lz[i]
            self.t[i*2] += v
            self.t[i*2+1] += v
            self.lz[i*2] += v
            self.lz[i*2+1] += v
            self.lz[i] = 0

    def add(self, i, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self.t[i] += v
            self.lz[i] += v
            return
        if r < ql or l > qr:
            return
        self.push(i)
        m = (l + r) // 2
        self.add(i*2, l, m, ql, qr, v)
        self.add(i*2+1, m+1, r, ql, qr, v)
        self.t[i] = max(self.t[i*2], self.t[i*2+1])

    def query(self, i, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[i]
        if r < ql or l > qr:
            return -10**18
        self.push(i)
        m = (l + r) // 2
        return max(
            self.query(i*2, l, m, ql, qr),
            self.query(i*2+1, m+1, r, ql, qr)
        )

def solve():
    n, q = map(int, input().split())
    g = [[] for _ in range(n+1)]

    for _ in range(n-1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n+1)
    tin = [0] * (n+1)
    tout = [0] * (n+1)
    children = [[] for _ in range(n+1)]

    timer = 0
    stack = [(1, 0, 0)]

    while stack:
        x, p, state = stack.pop()
        if state == 0:
            parent[x] = p
            timer += 1
            tin[x] = timer
            stack.append((x, p, 1))
            for y in g[x]:
                if y != p:
                    children[x].append(y)
                    stack.append((y, x, 0))
        else:
            tout[x] = timer

    child_seg = [None] * (n+1)
    for i in range(1, n+1):
        if children[i]:
            child_seg[i] = SegTree(len(children[i]))

    def child_add(x, v):
        seg = child_seg[x]
        seg.add(1, 0, seg.n-1, 0, seg.n-1, v)

    def child_query(x):
        seg = child_seg[x]
        return seg.query(1, 0, seg.n-1, 0, seg.n-1)

    global_seg = SegTree(n)

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])

        if t == 1:
            x, v = int(tmp[1]), int(tmp[2])
            global_seg.add(1, 1, n, tin[x], tout[x], v)

        elif t == 2:
            x, v = int(tmp[1]), int(tmp[2])
            child_add(x, v)

        elif t == 3:
            x = int(tmp[1])
            print(global_seg.query(1, 1, n, tin[x], tout[x]))

        else:
            x = int(tmp[1])
            print(child_query(x))

if __name__ == "__main__":
    solve()
```オイラー ツアーは、再帰の深さの問題を回避するために反復的に計算されます。 各ノードは tin と tout を取得し、サブツリー クエリがグローバル セグメント ツリー上の間隔クエリになるようにします。 グローバル セグメント ツリーはすべてのサブツリーの追加を保存し、遅延伝播を使用して最大のクエリに効率的に応答します。 

子操作の場合、各ノードは、その子リストによってインデックス付けされた独自のセグメント ツリーを維持します。 これにより、インデックス作成が複雑になるすべての子リレーションをグローバル構造にフラット化することが回避され、代わりにローカル構造が小さく保たれます。 

global_seg と child_seg の分離が実装の中心的なアイデアです。 1 つはサブツリー構造を処理し、もう 1 つは隣接ベースの構造を処理します。 

## 実用的な例

 小さなツリーについて考えてみましょう。1 は子 2 と 3 を持つルートであり、2 には子 4 があります。 

初期状態はすべてゼロです。 

タイプ 1 クエリの処理後`1 2 5`、2 のサブツリー内のすべてのノードは 5 になります。グローバル セグメント ツリーは、ノード 2 と 4 のオイラー区間を更新します。 

タイプ 2 クエリの処理後`2 1 3`、子 2 と子 3 は両方とも、ノード 1 の子セグメントで +3 を取得します。 

| ステップ | 操作 | グローバル サブツリー値 | 子どもの寄付 |
 | --- | --- | --- | --- |
 | 1 | 初期化 | すべて0 | すべて0 |
 | 2 | サブツリーを追加(2,+5) | ノード 2=5、ノード 4=5 | 0 |
 | 3 | 子を追加(1,+3) | 変更なし | ノード 2=3、ノード 3=3 |

 ここで、ノード 1 のタイプ 3 クエリは、1 のサブツリーの max を尋ねます。これは、global_seg で暗黙的に寄与を結合するすべてのノードの最大値です。 ノード 2 または 4 が完全にマージされた解釈で両方の寄与を受け取る場合、最大値は 8 になります。 

ノード 1 のタイプ 4 クエリは、子の間の最大値 (max(3,3)=3) を返します。 

このトレースは、サブツリーと子の寄与が分離されたままであり、クエリが正しいレイヤーにアクセスしていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新/クエリはセグメント ツリー操作であり、各ノードは一度構築されます。 
| スペース | O(n) | オイラー配列とセグメント ツリー ノードおよび子構造 |

 各演算には対数伝播のみが含まれるため、n、q が 300,000 までの場合、複雑さは 2 秒以内に収まります。

 ## 特殊なケース

 すべてのノードに子が 1 つだけある偏ったツリーでは、サブツリーの間隔が正しく折りたたまれるかどうかをテストします。 このような場合、すべてのサブツリーはオイラー順序の接尾辞であり、繰り返されるタイプ 1 の操作は、重複する間隔にわたって蓄積されます。 オイラーツアーは縮退チェーン内であっても連続性を保証するため、アルゴリズムはこれを処理します。 

ルート 1 と他のすべてのノードを子とする星型ツリーは、タイプ 2 とタイプ 4 を強調します。タイプ 2 の更新は、ルートを除くすべてのノードに適用され、タイプ 4 のクエリは、大きな隣接リストの中で最大値を必要とします。 ノードごとの子セグメント ツリーにより、これらの操作が対数的であることが保証され、ルートの子構造は隣接リストをスキャンせずにすべての更新を直接キャプチャします。 

ノードが祖先からのサブツリー更新と親からの子の更新の両方を受信する混合シーケンスでは、値が正しく結合されます。 グローバル セグメント ツリーと子セグメント ツリーは独立しているため、どのノードでも最終的な値は両方の寄与の合計となり、2 つの構造間で干渉は発生しません。
