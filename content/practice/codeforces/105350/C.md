 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$テストケースごとに、2 つの異なる数値を選択したいと考えています$a$そして$b$範囲内で$[1, n]$。 制約は、次のバイナリ表現であることです。$a$そして$b$両方が 1 を持つ位置 (ビット単位の AND が 0 であることを意味します) を共有してはなりません。 このようなすべての有効なペアの中で、可能な限り最大の値が必要です。$\gcd(a, b)$。 

したがって、タスクはペアを出力することではなく、2 つの互いに素なビット数のどの構造が依然として大きな公約数を共有できるかを推論することです。 

制約$n \le 10^9$これにより、ペアの列挙から遠ざけられます。 考えられるすべての候補を反復処理しても、$a$または$b$不可能です。 のバイナリ構造のみに依存する構築が必要です。$n$、理想的にはビット数が線形です。 

の値が小さい場合、微妙なエッジケースが発生します。$n$大型のものとは挙動が異なります。 たとえば、次のようなとき$n = 3$、有効なペアは次のとおりです。$(1,2)$、そして答えは$1$。 素朴な直観は、数値が増加するにつれてより高い gcd が可能になると示唆するかもしれませんが、バイナリのオーバーラップによる制約がそれを妨げます。 

もう 1 つの重要な失敗ケースは、次のような単純な構造のペアを使用すると仮定することです。$(g, 2g)$gcd を最大化するために常に機能します。 これは魅力的です。$\gcd(g, 2g) = g$、ただし、ビット単位の条件は、キャリーまたはバイナリ シフトの重複により失敗することがよくあります。 

## アプローチ

 総当り攻撃を試みる場合は、すべてのペアに対して反復処理を行うことになります。$(a,b)$、どうかを確認してください$a \& b = 0$、gcd を計算し、最大値を追跡します。 これはすぐに実行不可能になります。$O(n^2)$テストケースごとのペア、および$n$到達できる$10^9$。 一つに限定しても$n$まで列挙すると、$10^9$価値観は不可能です。 

重要な構造の簡素化は、構造を再構築することによって実現されます。 候補 gcd を修正するとします。$g$。 その場合、両方の数値は次の倍数でなければなりません$g$、と書くことができます。$a = g x$、$b = g y$。 条件はこうなります$(g x) \& (g y) = 0$。 このようなすべてのペアについて直接推論する代わりに、有効な場合に常に最適な gcd 構造を実現する特に単純なペアを探します。 

最も使いやすい構造は次のとおりです。$a = g$、$b = 2g$。 自動的に保証されるので魅力的です$\gcd(a,b)=g$、そしてビット単位の条件を以下のチェックに縮小します。$g$そして$2g$バイナリでオーバーラップします。 1 ビットのシフトによりオーバーラップが発生しないのは、次の場合のみです。$g$隣接する 2 つのセット ビットはありません。 もし$g$連続したものが含まれている場合、シフトすると衝突が発生します。 

これにより、問題は最大の整数を選択することになります。$g \le \lfloor n/2 \rfloor$そのバイナリ表現には隣接する 1 が含まれません。 これを認識すると、問題は標準的な貪欲なバイナリ構築問題になります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを単一の数値の構築に縮小します。$m = \lfloor n/2 \rfloor$。 タスクは、以下を超えない最大の整数を見つけることになります。$m$そのバイナリ表現には連続する 1 が含まれません。 

1. コンピューティング$m = n // 2$。 これは可能な最大値です$g$、 以来$b = 2g \le n$が必要です。 
2. 最上位ビットから最下位ビットまで少しずつ答えを構築します。 各ビット位置で、1 を配置するかどうかを決定しようとします。 
3. ビットを 1 に設定することを検討する場合、2 つの条件が満たされていることを確認する必要があります。 まず、超えないこと$m$。 第二に、この 1 が別の 1 の隣にあるような状況は作成しません。これは、$g, 2g$工事。 
4. ビットの設定が安全な場合は、ビットを配置します。 それ以外の場合は 0 のままにします。上位ビットが値を支配するため、決定は貪欲であり、以前の有効な配置は、実現可能性を損なうことなく後で改善することはできません。 
5. 構築された値をテスト ケースの答えとして返します。 

### なぜ効果があるのか

 あらゆる最適解は次の形式のペアに変換できます。$(g, 2g)$gcdを下げることなく。 条件$g \& (2g) = 0$これは、隣接する 2 ビットが存在しないことを要求することと同じです。$g$1 位置だけ左にシフトすると、隣接するビット位置間で正確に重複する可能性が生じるため、両方とも 1 になります。 したがって、すべての有効な gcd 候補は、連続するものがないバイナリ文字列に対応し、gcd を最大化することは、境界の下でそのような最大の数値を選択することと同じです。$n/2$。 貪欲な構築は、バイナリの重みが位置的であり、最初に上位ビットを固定することで最適性が維持されるため機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(m: int) -> int:
    bits = []
    for i in range(31, -1, -1):
        bits.append(i)

    res = 0
    prev = 0  # whether previous bit was set

    for i in range(31, -1, -1):
        if m & (1 << i):
            # try setting bit i
            if prev == 0:
                # check feasibility: setting this bit must not exceed m in prefix sense
                # we tentatively set it and verify by greedy completion assumption
                res_candidate = res | (1 << i)
                if res_candidate <= m:
                    res = res_candidate
                    prev = 1
                else:
                    prev = 0
            else:
                prev = 0
        else:
            prev = 0

    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        m = n // 2
        print(build(m))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理します。 機能`build(m)`以下を超えない最大の数を構築します$m$これにより、連続したビットの設定が回避されます。 変数`prev`前のビットが 1 として選択されたかどうかを追跡し、隣接性を防ぎます。 各ステップでは、ビットを上位から下位に設定しようと貪欲に試み、結果の値が次の範囲内に留まるようにします。$m$。 

微妙な点は、制約チェックが`res_candidate <= m`最上位ビットから下方向に構築しているため、上限の違反は最上位の異なるビットで直ちに発生するため、これで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def build(m: int) -> int:
        res = 0
        prev = 0
        for i in range(31, -1, -1):
            if m & (1 << i):
                if prev == 0:
                    cand = res | (1 << i)
                    if cand <= m:
                        res = cand
                        prev = 1
                    else:
                        prev = 0
                else:
                    prev = 0
            else:
                prev = 0
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(build(n // 2)))
    return "\n".join(out)

 ## 特殊なケース

 いつ$n = 2$、可能なペアは 1 つだけです$(1,2)$、gcd は 1 です。アルゴリズムは次のように計算します。$m = 1$、1 を超えない最大の有効な数は 1 そのものであり、正しい答えが得られます。 

いつ$n$は 2 のべき乗のすぐ下にあります。たとえば、$n = 7$、中間境界$m = 3$建設を制限します。 3 は数値的には大きいですが、そのバイナリ形式は$11$は隣接するものがあるため無効であり、アルゴリズムが 2 に低下することを強制します。これは、バイナリ制約が数値の大きさではなく最終値にどのように直接影響するかを示しています。 

いつ$n$は 2 のべき乗であり、次のようになります。$n = 8$、アルゴリズムは次のように動作します。$m = 4$、4 はすでに隣接するものがないきれいな 2 進数です。 この構築では、それを変更せずに通過させ、競合が存在しない場合、貪欲なプロセスが最適な値を保持することを確認します。
