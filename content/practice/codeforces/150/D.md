 ## 解決策
 ## 問題の理解

 長さの文字列から始めます`l`。 1 回の操作で、回文であり、その長さの連続する部分文字列を選択できます。`k`許可されています、つまり`a[k] != -1`。 削除すると、残りの文字が連結されます。 この移動で得られるスコアは、`a[k]`。 

このプロセスは、取り外し可能な回文がなくなるまで続けられます。 残りのすべての手が最終スコアを減らすことになる場合は、より早く停止する可能性があります。 タスクは、取得可能な最大合計スコアを計算することです。 

厄介な点は、削除によって隣接関係が変化することです。 元の文字列内で遠く離れていた 2 つの文字が、中間の削除後に隣接する文字になり、新しい回文が作成されることがあります。 現在表示されている回文のみに基づいた貪欲な戦略は大失敗します。 

長さの制限は 150 のみであり、これは区間動的計画法を示唆しています。 3 次アルゴリズムや 4 次アルゴリズムも使用できます。 周りに何か`O(n^4)`または`O(n^5)`通常は大丈夫です`n = 150`一方で、削除命令に対する指数関数的な検索は不可能です。 

より大きな回文の削除が禁止されている場合、微妙なエッジケースが発生しますが、より小さな部分を削除するとより良い結果が得られます。 

例：```
2
-1 5
aa
```文字列全体`"aa"`5点で削除可能です。 最初にすべてを 1 つの文字に分解するよう DP に誤って強制した場合、長さ 1 の削除は禁止されているため、答えが 0 であると誤って結論付けることになります。 

もう 1 つの重要なケースは、何も削除しないことが最適な場合です。 

例：```
3
-5 -5 -5
aba
```合法的な削除はすべてポイントを失います。 移動の実行が強制されることはないため、正解は 0 です。 

より微妙な状況は、部分文字列が最初は回文ではなく、その中間部分を削除した後に削除可能になる場合です。 

例：```
4
1 10 -1 -1
abba
```まず削除するかもしれません`"bb"`10ポイントで退場`"aa"`、削除します`"aa"`合計スコアは 20 です。元の間隔自体が回文であるかどうかのみをチェックする DP では、これを完全に見逃してしまいます。 

問題全体は、内部欠失の後にどの区間が最終的に回文に崩壊する可能性があるかを理解することを中心に展開します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのステップで、現在削除可能なすべての回文部分文字列を列挙し、それぞれを削除してみて、より小さい文字列を再帰的に解決して、最大スコアを取得します。 

これは正しいです。すべての有効な動きのシーケンスが再帰ツリーの 1 つの分岐に対応するからです。 問題は州の数です。 中程度の文字列であっても、個別の削除命令の数は指数関数的に増加します。 のような文字列`"aaaaaa..."`すべての段階で膨大な数の削除可能な部分文字列があります。 

重要な観察は、間隔内の相対的な位置のみが重要であるということです。 内部削除が十分に行われた後、間隔の終わりの文字が隣接する可能性があります。 これはまさに、DP が適切に処理するタイプの構造間隔です。 

中心的な質問は次のようになります。 

缶間隔`[l, r]`完全に回文に還元され、その外側の文字が残っているのは`s[l]`そして`s[r]`?

 それに答えることができれば、スコアリングは管理可能になります。 

間隔を完全に消去できるかどうかを表す DP と、達成可能な最高のスコアを表す別の DP を定義します。 この遷移は、古典的な区間結合問題に似ています。 

2 人の同等の人物がその間のすべてが消滅しても生き残ることができた場合、それらは一緒になってより大きな回文を形成します。 

これにより、削除順序に対する指数関数的な検索が多項式の間隔遷移に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適な間隔 DP | O(n^4) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### コア DP の意味

 2 つの DP 構造を使用します。`can[l][r][k]`意味:

 間隔`s[l..r]`長さの回文に変換できます`k`それらを削除せずに`k`生き残ったキャラクター。`best[l][r]`意味:

 インターバルから得られる最大スコア`s[l..r]`。 

最終的な答えは、`best[0][n-1]`。 

＃＃＃ 建物`can`1. 単一文字を初期化します。 

すべての文字はすでに長さ 1 の回文になっています。```
can[i][i][1] = True
```1. 小さな回文から大きな回文を作成します。 

仮定する`s[l] == s[r]`。 

中間区間の場合`s[l+1..r-1]`回文の長さに縮小できる`k`、両端を保持すると、長さの回文が得られます。`k+2`。 

これによりトランジションが作成されます。```
can[l][r][k+2] = True
```1. サブインターバルの完全な削除を許可します。 

間隔がすでに長さの回文になる可能性がある場合`k`、その長さは削除可能であり、その回文を削除すると、間隔全体が消えます。 

消失を長さ 0 として表します。```
can[l][r][0] = True
```1. 消去可能な区間を連結します。 

もし`[l, m]`そして`[m+1, r]`両方が完全に消える場合は、間隔全体が消える場合があります。 

これは次のように伝播します。```
can[l][r][0] = True
```完全な消去は複数回の削除によって行われることが多いため、この手順は不可欠です。 

### スコアの計算

 1. コンピューティング`best[l][r]`間隔の長さが長くなると、

 常に分割を許可します。```
best[l][r] = max(best[l][m] + best[m+1][r])
```1. インターバル全体を一度に削除してみます。 

もし`can[l][r][k]`それは真実であり、`a[k] != -1`、次に間隔`[l, r]`最終的には取り外し可能な長さの回文になる可能性があります`k`。 

それを削除すると、次のようになります。```
a[k]
```1. 削除と残りの部分を結合します。 

場合によっては、外側のセクションが残ったまま、中央のセクションだけが取り外し可能になる場合があります。 

すべての削除シーケンスが間隔を再帰的に分割するため、分割遷移はすでにこれを自然に処理しています。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。`can[l][r][k]`間隔の場合に正確に真になります`[l, r]`からなる回文に変換できます。`k`いくつかの有効な内部削除後に生き残った文字。 

この不変式が保持されるのは、より大きな回文を作成する唯一の方法が、両端の文字を同等に保ち、それらの間にある十分な内容を完全に削除することであるためです。`best[l][r]`これは正しいです。有効な削除シーケンスはすべて、ある間隔内で最後の操作が実行されるからです。 区間が独立した部分に分割されるか、区間全体が最終的に 1 つの取り外し可能な回文になります。 DP は両方の可能性を網羅的に列挙しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -(10**18)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = input().strip()

    # can[l][r][k]
    # interval l..r can become a palindrome of length k
    can = [[[False] * (n + 1) for _ in range(n)] for __ in range(n)]

    for i in range(n):
        can[i][i][1] = True
        if a[0] != -1:
            can[i][i][0] = True

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            # merge two erasable intervals
            for m in range(l, r):
                if can[l][m][0] and can[m + 1][r][0]:
                    can[l][r][0] = True
                    break

            # extend palindrome by matching ends
            if s[l] == s[r]:
                if length == 2:
                    can[l][r][2] = True
                else:
                    for k in range(n - 1):
                        if can[l + 1][r - 1][k]:
                            can[l][r][k + 2] = True

            # if some palindrome length is removable,
            # whole interval can disappear
            for k in range(1, length + 1):
                if can[l][r][k] and a[k - 1] != -1:
                    can[l][r][0] = True

    best = [[0] * n for _ in range(n)]

    for length in range(1, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            ans = 0

            # split interval
            for m in range(l, r):
                ans = max(ans, best[l][m] + best[m + 1][r])

            # delete whole interval as one palindrome
            for k in range(1, length + 1):
                if can[l][r][k] and a[k - 1] != -1:
                    ans = max(ans, a[k - 1])

            # delete some middle part first
            for m1 in range(l, r + 1):
                for m2 in range(m1, r + 1):
                    cur = 0

                    if m1 > l:
                        cur += best[l][m1 - 1]

                    if m2 < r:
                        cur += best[m2 + 1][r]

                    for k in range(1, m2 - m1 + 2):
                        if can[m1][m2][k] and a[k - 1] != -1:
                            ans = max(ans, cur + a[k - 1])

            best[l][r] = ans

    print(best[0][n - 1])

solve()
```の`can`DP はソリューションの中心です。 スコアは保存されません。 それは、どの間隔が最終的にさまざまな長さの回文に崩壊するかについての構造的な質問に答えるだけです。 

等しいエンドポイントを使用した移行は、重要な洞察です。 内側が回文の長さまで縮むことができれば`k`、その後、等しい外側の文字が長さまで拡張されます`k + 2`。 

完全な欠失を回文の長さ 0 として表すと、再発が大幅に単純化されます。 2 つの完全に消去可能なインターバルを連結すると、すぐに別の完全に消去可能なインターバルが生成されます。 

スコアリング DP は構造 DP からきれいに分離されています。 この分離により、ロジックが管理しやすくなり、実現可能性と最適化が混在することが回避されます。 

実装の微妙な詳細の 1 つは、スコア配列のインデックス付けです。 入力では 1 から始まる長さが使用されますが、Python リストのインデックスは 0 から始まります。 長さ`k`に対応する`a[k - 1]`。 

もう 1 つの簡単な間違いは、最適な戦略が早期に停止する可能性があることを忘れていることです。 マイナスの削除を強制することはないため、スコアを 0 で初期化すると、これが自動的に処理されます。
