 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ジャンクションと`n - 1`道路。 すべての道路には整数の美しさの値があります。 間のパスに次のものが含まれるように 2 つのジャンクションを選択する必要があります。`l`そして`r`エッジも含みます。 

このようなすべてのパスの中で、中央エッジの美しさができるだけ大きいパスが必要です。 

中央値の定義は、偶数の長さでは少し特殊です。 パスに`k`エッジを調べてエッジの美しさを並べ替えます。答えはインデックスの要素です`⌊k / 2⌋`ゼロベースのインデックスを使用します。 たとえば:

 - 長さ`3`2 番目に小さい値を使用します
 - 長さ`4`3 番目に小さい値を使用します

 つまり、中央値が実際には上部中央値であるということです。 

入力は重み付きツリーであり、一般的なグラフではありません。 任意の 2 つのジャンクション間には、単純なパスが 1 つだけ存在します。 出力では、エンドポイントの最適なペアのみが要求されます。 

制約は解決策の方向性を完全に決定します。 まであります`10^5`ノードがあるため、パスの数は 2 次になります。 すべてのペアを列挙するにはすでにコストがかかります`10^10`限界をはるかに超えた操作。 たとえ`O(n^2)`小さな定数を含むアルゴリズムは失敗します。 

エッジの重みは次のように大きくなります。`10^9`これは通常、値を直接 DP すべきではないことを示唆しています。 代わりに、答えを二分探索する必要があります。 

制限時間は7秒と余裕がありますが、それでも3000点の木の問題です。 現実的には、周りに何かが必要です`O(n log^2 n)`または`O(n log n)`。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

偶数の長さのパスを考えてみましょう。```
1 -2- 2 -100- 3
```と`l = r = 2`。 

選別された美女たちは、`[2, 100]`。 必要な中央値は`100`、 ない`2`。 より低い中央値を使用して不注意に実装すると、正しい答えが拒否されます。 

もう 1 つの危険なケースは、有効なパスが重心境界を通過する必要がある場合です。```
1 -10- 2 -1- 3 -10- 4
```と`l = r = 3`。 

最適なパスは`1 -> 4`。 各サブツリー内を個別に検索するだけで、重心を介してそれらを結合しない場合、答えを完全に見逃してしまいます。 

3 番目の微妙なケースは、すべてのエッジ値が等しい場合です。```
1 -5- 2 -5- 3 -5- 4
```すべての有効なパスは同じ中央値を持ちます。 アルゴリズムは、一意性を仮定するのではなく、いくつかの有効なエンドポイントを返す必要があります。 

最後に、正確に境界にあるパスが重要です。```
1 -7- 2 -1- 3 -9- 4
```と`l = 2`、`r = 3`。 

誤って長さだけをチェックしてしまう解決策`< r`の代わりに`<= r`長さのパスを拒否します`3`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 グラフはツリーであるため、頂点のすべてのペアが 1 つのパスを正確に定義します。 すべて列挙できます`O(n^2)`ペアを作成し、パス上のエッジの重みを回復し、それらを並べ替え、中央値を計算し、最も有効な値を保持します。 

これは文字通りすべての候補者をチェックするため、正しいです。 残念ながら絶望的に遅いです。 くらいあります`5 * 10^9`ペアのとき`n = 10^5`。 単一のパスを計算するだけでもコストがかかるため、このアプローチは決して遠くありません。 

中央値条件の構造を利用する必要があります。 

何らかの値を推測するとします`x`そして尋ねてください：

 「中央値が少なくとも次の有効なパスは存在しますか?`x`？」

 これにより問題は完全に変わります。 

すべてのエッジの重みを置き換えます。 

-`+1`もし`w >= x`-`-1`それ以外の場合

 次に、長さのパスを考えます`k`。 

上部中央値が少なくとも`x`、上に丸められたエッジの少なくとも半分は次の条件を満たす必要があります。`w >= x`。 同様に:```
count(good) >= count(bad)
```変換後のパスの合計は次のようになります。```
count(good) - count(bad)
```したがって、条件は単純に次のようになります。```
path sum >= 0
```ここで問題は次のようになります。 

「長さのある道はありますか？」`[l, r]`変換された合計が負でないのは誰ですか?」

 これは、より標準的な最適化問題です。 

ツリー構造は重心分解を示唆しています。 どのパスも 1 つのサブツリー内に完全に存在するか、重心を通過します。 重心の処理中に、重心からすべての下向きのパスを収集し、長さの制約を尊重しながら、さまざまなサブツリーからのパスを結合します。 

残りの課題は、2 つのパスを結合して非負の合計が得られるかどうかを効率的にチェックすることです。 長さを処理し、これまでに発生したすべての深さに対して最適なパスの合計を維持します。 

これにより、次のような決定手順が得られます。`O(n log n)`1つ固定の`x`。 

真の答えはエッジの重みの 1 つであるため、明確なエッジの美しさに対して二分探索を行います。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n log² n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 中央値の二分探索。 

させて`x`現在の候補中央値になります。 中央値が少なくとも以下である有効なパスが存在するかどうかを判断したいと考えています。`x`。 
2. エッジの重みを次のように変換します。`+1`そして`-1`。 

すべてのエッジについて:```
+1 if weight >= x
-1 otherwise
```パスには少なくとも中央値があります`x`まさに、パスに沿った変換された合計が負でないときです。 
3. ツリーに対して重心分解を使用します。 

ツリー内のすべてのパスは次のいずれかです。 

- 現在の重心を通過します
 - 1 つの子サブツリー内に完全に存在します

 再帰的分解により、すべてのパスが一度考慮されることが保証されます。 
4. 現在の重心について、各子サブツリーへの下向きのパスをすべて列挙します。 

重心から到達可能なすべてのノードについて、以下を記録します。 

- 深さ
 - 変換されたパスの合計
 - エンドポイントの頂点

 これらは、重心から始まり 1 つのサブツリー内で終わるすべてのパスを表します。 
5. 異なるサブツリーからのパスを結合します。 

1 つのパスに次のものがあるとします。```
depth = d1
sum = s1
```そしてもう1つは次のようになります。```
depth = d2
sum = s2
```重心を通る結合パスは次のようになります。```
length = d1 + d2
total sum = s1 + s2
```必要なものは次のとおりです。```
l <= d1 + d2 <= r
s1 + s2 >= 0
```6. すべての深さに対して、以前に処理された最適なパスを維持します。 

サブツリーを 1 つずつ反復処理しながら、以前のサブツリーからの各深さの最大合計を保存します。 

これにより、同じサブツリーからの 2 つのパスを結合すると、重心を通過しない無効なパスが生成されることが防止されます。 
7. セグメント ツリーを使用して、深さの範囲内で利用可能な最大合計をクエリします。 

現在の深さのパスの場合`d`、パートナーの深さは次の場所にある必要があります。```
[l - d, r - d]
```その範囲内で保存されている最大合計をクエリします。 もし：```
best + current_sum >= 0
```有効なパスが存在します。 
8. エンドポイントを合計とともに保存します。 

成功した組み合わせが見つかったら、2 つのエンドポイント頂点を保存します。 二分探索が成功した場合、これらが最終的な答えになります。 
9. 子サブツリーに再帰します。 

概念的に重心を削除し、すべてのコンポーネント内で同じ手順を繰り返します。 
10. すべての個別のエッジの重みに対する二分探索。 

候補者であれば`x`実現可能な場合は、上位を検索してください。 それ以外の場合は、下位を検索します。 

### なぜ効果があるのか

 重要な不変条件は、変換されたパス合計の解釈です。 

任意のパスについて、次のように定義します。```
sum = (#edges with weight >= x) - (#edges with weight < x)
```上部中央値は少なくとも`x`まさにこの量が負でないときです。 

重心分解により、すべてのツリー パスが、パスが異なる重心サブツリー間を交差するか、または重心自体に接触する正確に 1 つの重心で処理されることが保証されます。 処理中、データ構造には常に、すでに処理されたサブツリーのみからの最良のパスの合計が格納されるため、結合されたすべてのペアが有効な単純なパスを表します。 

セグメント ツリーにより、全長が内側にある深さのみを結合することが保証されます。`[l, r]`。 

二分探索ではすべての候補の実現可能性が正確にチェックされるため、`x`、実現可能な最高値が最適中央値です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

INF = 10**18

n, L, R = map(int, input().split())

g = [[] for _ in range(n)]

weights = []

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))
    weights.append(w)

vals = sorted(set(weights))

dead = [False] * n
sz = [0] * n

best_u = 0
best_v = 0

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n + 5:
            self.n <<= 1
        self.seg = [(-INF, -1)] * (2 * self.n)

    def clear(self):
        for i in range(2 * self.n):
            self.seg[i] = (-INF, -1)

    def update(self, pos, val):
        pos += self.n
        if val[0] > self.seg[pos][0]:
            self.seg[pos] = val
        pos >>= 1
        while pos:
            self.seg[pos] = max(self.seg[pos << 1], self.seg[pos << 1 | 1])
            pos >>= 1

    def query(self, l, r):
        if l > r:
            return (-INF, -1)

        l += self.n
        r += self.n

        res = (-INF, -1)

        while l <= r:
            if l & 1:
                res = max(res, self.seg[l])
                l += 1
            if not (r & 1):
                res = max(res, self.seg[r])
                r -= 1
            l >>= 1
            r >>= 1

        return res

seg = SegTree(n + 5)

def calc_size(u, p):
    sz[u] = 1
    for v, _ in g[u]:
        if v == p or dead[v]:
            continue
        calc_size(v, u)
        sz[u] += sz[v]

def find_centroid(u, p, total):
    for v, _ in g[u]:
        if v == p or dead[v]:
            continue
        if sz[v] > total // 2:
            return find_centroid(v, u, total)
    return u

def collect(u, p, depth, s, vec, target):
    if depth > R:
        return

    vec.append((depth, s, u))

    for v, w in g[u]:
        if v == p or dead[v]:
            continue

        ns = s + (1 if w >= target else -1)
        collect(v, u, depth + 1, ns, vec, target)

found = False

def solve_centroid(entry, target):
    global found, best_u, best_v

    calc_size(entry, -1)
    c = find_centroid(entry, -1, sz[entry])

    dead[c] = True

    seg.clear()
    seg.update(0, (0, c))

    for v, w in g[c]:
        if dead[v]:
            continue

        vec = []

        start = 1 if w >= target else -1
        collect(v, c, 1, start, vec, target)

        for depth, s, node in vec:
            left = max(0, L - depth)
            right = R - depth

            if left > right:
                continue

            best = seg.query(left, right)

            if best[0] + s >= 0:
                found = True
                best_u = node
                best_v = best[1]
                return

        for depth, s, node in vec:
            cur = seg.query(depth, depth)
            if s > cur[0]:
                seg.update(depth, (s, node))

    for v, _ in g[c]:
        if dead[v]:
            continue
        solve_centroid(v, target)
        if found:
            return

def check(target):
    global found

    found = False

    for i in range(n):
        dead[i] = False

    solve_centroid(0, target)

    return found

lo = 0
hi = len(vals) - 1
ans = vals[0]

while lo <= hi:
    mid = (lo + hi) // 2

    if check(vals[mid]):
        ans = vals[mid]
        lo = mid + 1
    else:
        hi = mid - 1

check(ans)

print(best_u + 1, best_v + 1)
```ソリューションには 3 つの主要な層があります。 

外側の層は、答えに対する二分探索です。 最適な中央値はツリーにすでに存在するエッジの美しさに等しい必要があるため、個別の重みをソートしてそれらを検索します。 

中間層は実現可能性のチェックです。 エッジを次のように変換した後、`+1`そして`-1`、有効なパスの合計が負でないかどうかを知る必要があるだけです。 

内層は重心分解です。 

微妙な部分は中央値の解釈です。 この問題では上部中央値が使用されるため、条件は次のようになります。```
good edges >= bad edges
```厳密にはそれより大きいわけではありません。 

もう 1 つの簡単な間違いは、重心処理中に同じサブツリーからのパスを結合することです。 これにより、実際には重心を通過しないパスが作成されます。 実装では、サブツリーごとに最初にクエリを実行し、その後に挿入することでこれを回避します。 

セグメント ツリーには次のペアが格納されます。```
(maximum sum, endpoint vertex)
```そのため、存在を確認するだけでなく、実際の回答パスを再構築できます。 

の`collect`深さが超えると DFS が停止します`R`。 この剪定はパフォーマンスにとって非常に重要です。 

最後に、分解再帰により重心が死んだものとしてマークされ、再びアクセスされることはありません。 これにより通常の動作が保証されます`O(n log n)`重心分解の合計複雑さ。

この例では、すべての重みが等しい場合、変換時にすべてのパスが同じように動作することを確認します。

 次のことを考慮してください。```
6 2 4
1 2 1
2 3 1
3 4 5
4 5 5
5 6 5
```試す`x = 5`。 

重みは次のようになります。```
-1 -1 +1 +1 +1
```次に、有効なパスを調べます。 

| パス | 長さ | 変換された合計 | 有効 |
 | --- | --- | --- | --- |
 | 3→6 | 3 | 3 | はい |
 | 2→6 | 4 | 2 | はい |
 | 1→4 | 3 | -1 | いいえ |

 重心分解では、正の重みのサフィックスを結合し、非負のパスを発見します。 

このトレースはコアの減少を示しています。 変換後に直接中央値を計算することはありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log² n) | 値に対する二分探索。各チェックは重心分解を使用します。 
| スペース | O(n log n) | ツリーストレージ、再帰、重心構造 |

 個別のエッジの重みの数は最大で`n - 1`したがって、二分探索は`log n`要素。 各実現可能性チェックでは、セントロイド分解を通じてすべてのノードが処理され、次のようになります。`O(n log n)`仕事。 

と`n = 10^5`、これは最適化された Python の制限内に問題なく収まります。

 ## 特殊なケース

 偶数長の中央値の問題を考えてみましょう。```
3 2 2
1 2 2
2 3 100
```唯一の有効なパス上でソートされた美しいものは次のとおりです。```
[2, 100]
```上部中央値は`100`。 

のために`x = 100`、変換された値は次のようになります。```
-1, +1
```合計金額は`0`, したがって、パスは受け入れられます。 まさにこれが実現可能条件の理由です。`>= 0`それよりも`> 0`。 

ここで、重心を横切る必要があるパスを考えてみましょう。```
4 3 3
1 2 10
2 3 1
3 4 10
```のために`x = 10`、変換された値は次のとおりです。```
+1, -1, +1
```からの合計パス合計`1`に`4`は`1`。 

どちらの側のサブツリーにも、単独では有効なパスが含まれていません。 解は、2 つのサブツリー パスが重心を介して結合される場合にのみ表示されます。 分解ロジックはこのケースを明示的に処理します。 

最後に、すべての重みが等しいことを考慮します。```
5 2 3
1 2 7
2 3 7
3 4 7
4 5 7
```のために`x = 7`、すべてのエッジは`+1`。 すべての有効なパスには正の合計があるため、最初に検出された有効なペアがすぐに返されます。 このアルゴリズムは最適値の一意性に決して依存しません。
