 ## 解決策
 ## 問題の理解

 停留所座標が固定された直線のバス ルートがあります。 乗客は通常、乗車停留所と降車停留所の間の全距離を支払います。 車掌は、その旅行の連続する区間を最大 1 つまで切符から「隠す」ことができます。 乗客が停車地から出発する場合`a`止める`b`、指揮者はある程度の間隔を選択できます`[C, D]`その旅行期間中は、からの距離のチケットを販売しないでください。`C`に`D`。 

節約された切符のお金は、乗客と車掌で均等に分割されます。 つまり、隠れセグメントの長さが`x[D] - x[C]`、車掌はその金額の半分をすぐに稼ぎます。 

リスクは検査からもたらされます。 連続するストップ間のすべてのエッジには独立した検査確率があります。 乗客が検査が行われる区間の有効な切符を持っていない場合、車掌は罰金を支払います`c`その区間のその乗客のために。 

課題は、すべての乗客に対して個別に期待利益を最大化することです。 各乗客は異なる不正行為計画を受け取る場合があります。 

制約によってソリューションが完全に形作られます。 まであります`150000`停止して`300000`乗客。 停車地を越える二次解法は不可能であり、ルート上の線形スキャンですべての乗客を処理する場合でも、約`3 * 10^5 * 1.5 * 10^5`、それは限界をはるかに超えています。 周りに何かが必要です`O((n + m) log n)`または`O(n + m)`。 

難しいのは、期待値には 2 つの異なる量が混在していることです。 

1. チケットの一部を売らなくてもすぐに利益が得られる。 
2. 検査により将来予想される損失。 

2 番目の量はセグメント全体の確率に依存するため、不注意な実装では期待値が誤って計算されることがよくあります。 

簡単な間違いの 1 つは、さまざまなセグメントの検査が期待値に直線的に寄与するということを忘れていることです。 仮定する：```
3 1 10
0 10 20
50 50
1 3
```旅行全体を隠しておけば節約できる`20`, それで車掌は儲かります`10`。 予想される罰金は次のとおりです。`10 * 0.5 + 10 * 0.5 = 10`期待利益は`0`、負ではなく、次のような組み合わせた確率を使用して計算されません。`1 - (1-0.5)^2`。 

もう 1 つの微妙なケースは、ルートの一部のみを不正行為することが最適な場合です。```
4 1 100
0 10 20 100
0 100 0
1 4
```中端は検査が保証されているので、旅行全体を隠すのはひどいです。 最適な選択はセグメントのみを非表示にすることです`3 -> 4`、検査リスクはありません。 「ポジティブな距離ですべてを隠す」という貪欲な考えは、ここでは失敗します。 

不正行為が決して利益にならないケースもあります。```
2 1 1000
0 10
100
1 2
```指揮者が得するのは`5`、しかし期待される罰金は`1000`、したがって、最良の答えは次のとおりです`0`。 空ではない非表示間隔を常に選択する実装では、誤った結果が得られます。 

## アプローチ

 ブルートフォースビューから始めます。 停車地からお越しのお客様へ`a`止める`b`、すべてのペアを試すことができます`(C, D)`と`a <= C < D <= b`。 隠れた距離は次のとおりです。```
x[D] - x[C]
```車掌はその半分を受け取ります。 予想される罰金は、内側のすべての覆われていないエッジに対する検査確率の合計に等しくなります。`[C, D)`乗算`c`。 

したがって、期待利益は次のようになります。```
(x[D] - x[C]) / 2 - c * sum(probabilities on hidden edges)
```座標と確率のプレフィックス和を事前に計算すると、各候補区間は次のように評価できます。`O(1)`。 残念ながら、あります`O(length^2)`乗客ごとの間隔。 最悪の場合、一人の乗客が全員にまたがってしまう`150000`停止します。これはすでに約を与えています`10^10`間隔。 

すべての乗客が独立しているため、強引な方法が機能します。 この失敗は、本質的に同じ式を多くの間隔で再計算することで発生します。 

ここで、隠蔽区間の利益計算式を注意深く見てください。`[C, D]`。 

させて：```
w[i] = (x[i+1] - x[i]) / 2 - c * p[i] / 100
```これは隠れエッジの期待される貢献です`i`。 

いくつかの連続したエッジを非表示にした場合、期待される利益の合計は単にそれらのエッジの合計になります。`w[i]`。 

それは問題を完全に変えます。 乗客用`(a, b)`、エッジ内の最大部分配列合計のみが必要です`[a, b-1]`。 

すべてのエッジが独立して寄与する場合、最適な隠れ区間はまさに最大合計の連続セグメントになります。 

したがって、問題全体は、静的配列に対する多くの最大サブ配列クエリに答えることに帰着します。 

これは古典的なセグメント ツリーの問題です。 すべてのノードについて、以下を保存します。 

1. 合計。 
2. 最適なプレフィックス合計。 
3. 最良のサフィックス合計。 
4. 最適な部分配列の合計。 

すると、各乗客のクエリは次のようになります。`O(log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(mn²) | O(n) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 検査確率を 10 進数に変換します。 

エッジ用`i`停留所間`i`そして`i+1`、期待される素晴らしい貢献は次のとおりです。```
c * p[i] / 100
```2. アレイを構築する`w`サイズの`n-1`。 

各エッジは以下に貢献します。```
w[i] = (x[i+1] - x[i]) / 2 - c * p[i] / 100
```これは、まさにそのエッジを隠すことによって得られる期待利益です。 
3. 複数の連続するエッジを非表示にすると、それらの寄与が追加されることを観察します。 

エッジを非表示にする場合`L`に`R`、期待利益は次のとおりです。```
sum(w[L:R+1])
```なぜなら期待は直線的だからです。 
4. すべての乗客に対して`(a, b)`、エッジの内側に最適な連続セグメントが必要です`[a, b-1]`。 

これはまさに、次の最大部分配列合計クエリです。```
w[a-1 : b-1]
```5. セグメントツリーを構築する`w`。 

各ノードには以下が保存されます。```
total sum
maximum prefix sum
maximum suffix sum
maximum subarray sum
```6. 2 つの子ノードをマージします。 

左の子が`A`そして右の子は`B`。 

それから：```
total = A.total + B.total
prefix = max(A.prefix, A.total + B.prefix)
suffix = max(B.suffix, B.total + A.suffix)
best = max(A.best, B.best, A.suffix + B.prefix)
```最後のケースでは、中点を横切る部分配列を処理します。 
7. 各乗客範囲のセグメント ツリーをクエリします。 

返されたノードには、その間隔内の最大サブ配列合計が含まれます。 
8. プラスの利益のみを答えに追加します。 

最適な部分配列の合計が負の場合、車掌は単にその乗客の不正行為を回避します。 

### なぜ効果があるのか

 それぞれの隠れたエッジは独立して期待される利益に貢献します。 寄与は、隣接するエッジではなく、そのエッジの長さと検査確率にのみ依存します。 

期待は加算的なものであるため、連続区間を非表示にすることで期待される利益は、その区間内のエッジ寄与の合計に等しくなります。 

したがって、乗客ごとに最適な戦略は、合計重量が最大になる連続した区間を選択することです。 セグメント ツリーは、標準の最大部分配列マージ不変式を使用してその数量を正確に計算します。 

すべてのクエリは、その乗客にとって可能な限り最善の不正行為計画を返します。また、乗客は独立しているため、これらの最適値を合計すると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("total", "pref", "suff", "best")

    def __init__(self, total=0.0, pref=0.0, suff=0.0, best=0.0):
        self.total = total
        self.pref = pref
        self.suff = suff
        self.best = best

def merge(a, b):
    res = Node()
    res.total = a.total + b.total
    res.pref = max(a.pref, a.total + b.pref)
    res.suff = max(b.suff, b.total + a.suff)
    res.best = max(a.best, b.best, a.suff + b.pref)
    return res

n, m, c = map(int, input().split())

x = list(map(int, input().split()))
p = list(map(int, input().split()))

w = []
for i in range(n - 1):
    dist = x[i + 1] - x[i]
    val = dist / 2.0 - c * p[i] / 100.0
    w.append(val)

size = 1
while size < n - 1:
    size <<= 1

seg = [Node() for _ in range(2 * size)]

for i in range(n - 1):
    v = w[i]
    seg[size + i] = Node(v, v, v, v)

for i in range(size - 1, 0, -1):
    seg[i] = merge(seg[i << 1], seg[i << 1 | 1])

def query(l, r):
    left_res = None
    right_res = None

    l += size
    r += size

    while l <= r:
        if l & 1:
            if left_res is None:
                left_res = seg[l]
            else:
                left_res = merge(left_res, seg[l])
            l += 1

        if not (r & 1):
            if right_res is None:
                right_res = seg[r]
            else:
                right_res = merge(seg[r], right_res)
            r -= 1

        l >>= 1
        r >>= 1

    if left_res is None:
        return right_res

    if right_res is None:
        return left_res

    return merge(left_res, right_res)

ans = 0.0

for _ in range(m):
    a, b = map(int, input().split())

    res = query(a - 1, b - 2)

    if res.best > 0:
        ans += res.best

print(f"{ans:.9f}")
```最初の変換は重要な実装ステップです。 チケットと検査について直接推論する代わりに、コードはエッジ上の重み配列を構築します。 すべてのエッジは、非表示の場合、期待される寄与を保存します。 

最大サブ配列クエリには単なる合計以上のものが必要であるため、セグメント ツリーにはノードごとに 4 つの値が格納されます。 交差の場合は、左の子からの最適なサフィックスと、右の子からの最適なプレフィックスが必要です。 

細かい点の 1 つはインデックスです。 停留所には次からの番号が付けられています`1`ただし、エッジは自然にインデックス付けされます。`0`。 

乗客`(a, b)`エッジを隠すことができます:```
[a-1, b-2]
```エッジだから`i`接続停止`i+1`止める`i+2`。 

もう 1 つの重要な詳細は、中立要素です。 マージ中に空のサブ配列が誤って許可されてしまうため、反復クエリ中に偽のゼロ ノードは使用しません。 代わりに、実装では次を使用します。`None`そして遅延初期化します。 

木は向こうに去っていく`n-1`値はゼロのままです。 すべての範囲が実際のエッジ配列内に留まるため、それらはクエリされることはありません。 

すべての演算はおおよそ次の値で囲まれた加算と最大値であるため、ここでは浮動小数点精度が安全です。`1e9`。

import sys
import io

def run(inp: str) -> str:
    input_data = io.StringIO(inp)
    output_data = io.StringIO()

    input = input_data.readline

    class Node:
        __slots__ = ("total", "pref", "suff", "best")

        def __init__(self, total=0.0, pref=0.0, suff=0.0, best=0.0):
            self.total = total
            self.pref = pref
            self.suff = suff
            self.best = best

        res = Node()
        res.total = a.total + b.total
        res.pref = max(a.pref, a.total + b.pref)
        res.suff = max(b.suff, b.total + a.suff)
        res.best = max(a.best, b.best, a.suff + b.pref)
        return res

    n, m, c = map(int, input().split())

    x = list(map(int, input().split()))
    p = list(map(int, input().split()))

    w = []
    for i in range(n - 1):
        w.append((x[i + 1] - x[i]) / 2.0 - c * p[i] / 100.0)

    size = 1

        size <<= 1

    for i, v in enumerate(w):
        seg[size + i] = Node(v, v, v, v)

    for i in range(size - 1, 0, -1):
        seg[i] = merge(seg[i << 1], seg[i << 1 | 1])

    def query(l, r):
        left_res = None
        right_res = None

        l += size
        r += size

        while l <= r:
            if l & 1:
                left_res = seg[l] if left_res is None else merge(left_res, seg[l])
                l += 1

            if not (r & 1):
                right_res = seg[r] if right_res is None else merge(seg[r], right_res)
                r -= 1

            l >>= 1
            r >>= 1

        if left_res is None:
            return right_res
        if right_res is None:
            return left_res

        return merge(left_res, right_res)

    ans = 0.0

    for _ in range(m):
        a, b = map(int, input().split())
        ans += max(0.0, query(a - 1, b - 2).best)

    output_data.write(f"{ans:.9f}\n")
    return output_data.getvalue()
