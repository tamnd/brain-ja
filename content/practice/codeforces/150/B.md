 ## 解決策
 ## 問題の理解

 一定の長さの文字列をカウントしたい`n`サイズのアルファベットから作られています`m`、次の 1 つの強力な制限があります: 長さのすべての部分文字列`k`回文でなければなりません。 

長さの部分文字列`k`位置から開始`i`文字が含まれています$$s_i, s_{i+1}, \dots, s_{i+k-1}$$そして回文であるということは、$$s_i = s_{i+k-1}, \quad s_{i+1} = s_{i+k-2}, \dots$$タスクは、そのようなすべての制約を同時に満たす完全な文字列の数をカウントすることです。 数値は膨大になる可能性があるため、答えを剰余として出力します。$10^9 + 7$。 

この制限は、グラフの構築やポジションにわたる DFS を可能にするのに十分小さいものです。 と`n, k ≤ 2000`、$O(n^2)$アルゴリズムは完全に安全です。 特に Python では、3 次ソリューションは危険になり始めます。 すべての文字列を列挙することは不可能です。$m^n$候補者、さらには`n = 50`その数はすでに天文学的な数字です。 

厄介な点は、重複する部分文字列からの回文条件が相互作用することです。 局所的な条件により、等値が大きく離れてしまうこともあります。 

次の例を考えてみましょう。```
n = 5, k = 3
```部分文字列は次のとおりです。```
s[0..2], s[1..3], s[2..4]
```最初の回文から次のことが得られます。```
s0 = s2
```2番目から:```
s1 = s3
```3番目から:```
s2 = s4
```それらを組み合わせると次のようになります。```
s0 = s2 = s4
s1 = s3
```したがって、文字列全体は 2 つの独立した文字グループのみによって決定されます。 

よくある間違いは、各部分文字列を独立して扱い、可能性を増やすことです。 同じ位置が多くの部分文字列に出現するため、この値は過大にカウントされます。 

もう一つの微妙なエッジケースは、`k = 1`。 長さのすべての部分文字列`1`は自動的に回文になるため、等価性の制約はまったくありません。 

例：```
n = 4, m = 3, k = 1
```すべての文字列は機能するため、答えは次のようになります。```
3^4 = 81
```ウィンドウ内の位置を常にマージする不注意な実装では、制約が存在しない場合でも、誤って制約を追加する可能性があります。 

その反対の極端は、`k = n`。 その場合、文字列全体自体が回文である必要があります。 

例：```
n = 5, m = 2, k = 5
```必要なものは次のとおりです。```
s0 = s4
s1 = s3
```独立しているのは 3 つの位置だけなので、答えは次のようになります。```
2^3 = 8
```問題が実際にはインデックス間の等価関係に関するものであることを理解することが重要な観察です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 一定の長さのすべての文字列を生成します`n`、次に長さのすべての部分文字列かどうかを確認します。`k`回文です。 

がある$m^n$文字列。 各文字列について大まかに検査します`n`部分文字列、各回文チェックのコストは最大で`k`。 

それは次のようになります:$$O(m^n \cdot n \cdot k)$$これは、中程度の値であっても絶望的です。 

ブルート フォースが概念的に機能する理由は、条件をローカルで検証するのが簡単だからです。 問題は、候補文字列の数が指数関数的に増加することです。 

重要な観察は、回文制約は一部の位置を強制的に等しくするだけであるということです。 実際に使用される文字を制限することはありません。 

長さの部分文字列を想定します`k`から始まります`i`。 次に、オフセットごとに`j`:$$s_{i+j} = s_{i+k-1-j}$$したがって、立場は対等な関係で結ばれます。 

2 つの位置が等しいことが判明すると、それらは 1 つの変数として動作します。 すべての部分文字列を処理した後、文字列は同じ位置の接続されたコンポーネントに分割されます。 

あれば`c`独立したコンポーネントの場合、各コンポーネントはいずれかを選択できます。`m`独立して文字を書く。 

したがって、答えは次のようになります。$$m^c$$モジュロ$10^9+7$。 

これにより、問題は文字列の構築からグラフ内の連結成分のカウントへと変換されます。 

ポジションをモデル化できます`0 ... n-1`グラフの頂点として。 回文条件で 2 つの位置が一致する必要があると示されている場合は、それらを接続します。 次に、接続されたコンポーネントがいくつ残っているかを計算します。 

DFS、BFS、または DSU はすべて機能します。 制約が小さいため、単純な DFS ソリューションで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m^n \cdot n \cdot k)$|$O(n)$| 遅すぎる |
 | 最適 |$O(nk)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを作成します。`n`頂点、文字列の位置ごとに 1 つ。 
2. 長さのすべての部分文字列について`k`、回文条件によって暗示される等価エッジを追加します。 

部分文字列が次で始まる場合`i`、 それから：$$s_{i+j} = s_{i+k-1-j}$$すべて有効な`j`。 

そこで、グラフ内でこれら 2 つのインデックスを接続します。 
3. すべての部分文字列を処理した後、パスを介して接続されている位置には同じ文字が含まれている必要があります。 

これが機能するのは、等価性が推移的であるためです。 もし`a = b`そして`b = c`、 それから`a = c`。 
4. グラフに対して DFS を実行して、接続成分をカウントします。 

すべての連結コンポーネントは、1 つの独立した文字の選択肢に対応します。 
5. 以下を計算します。$$m^{\text{components}} \bmod (10^9+7)$$高速べき乗剰余演算を使用します。 

### なぜ効果があるのか

 すべての回文制約は、位置のペア間の等式の集合として記述することができます。 グラフにはこれらの等式が正確に保存されます。 

2 つの位置が同じ連結成分に属している場合、それらを接続する一連の等価関係が存在するため、それらの位置には同じ文字が含まれている必要があります。 

2 つの位置が異なるコンポーネント内にある場合、拘束はそれらをリンクしないため、それらは独立して選択できます。 

したがって、各接続コンポーネントは、次のような 1 つの自由変数のように動作します。`m`選択肢。 すべての成分を乗算すると、次のようになります。$$m^c$$どこ`c`接続成分の数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m, k = map(int, input().split())

    graph = [[] for _ in range(n)]

    # Add palindrome equality constraints
    for start in range(n - k + 1):
        l = start
        r = start + k - 1

        while l < r:
            graph[l].append(r)
            graph[r].append(l)
            l += 1
            r -= 1

    visited = [False] * n

    def dfs(node):
        stack = [node]
        visited[node] = True

        while stack:
            u = stack.pop()

            for v in graph[u]:
                if not visited[v]:
                    visited[v] = True
                    stack.append(v)

    components = 0

    for i in range(n):
        if not visited[i]:
            components += 1
            dfs(i)

    print(pow(m, components, MOD))

if __name__ == "__main__":
    main()
```グラフには、位置間の平等制約が保存されます。 長さのすべての部分文字列に対して`k`では、それらの位置が回文内で一致する必要があるため、ミラーリングされたインデックスを接続します。 

ループ:```
while l < r:
```重要です。 ミラーリングされたペアを接続するのは 1 回だけです。 いつ`k`が奇数の場合、中央の文字はそれ自体をミラーリングしているため、制約は作成されません。 

DFS は連結成分を計算します。 未訪問のノードごとに、1 つの独立した文字グループを表す新しいコンポーネントが開始されます。 

反復 DFS を使用すると、再帰の深さの問題が回避されますが、再帰もこれらの制限内に収まります。 

最終的な答えは、Python の組み込みのべき乗剰余演算を使用します。```
pow(m, components, MOD)
```対数時間で実行されます。 

実装の微妙な詳細はインデックス作成です。 問題のステートメントは当然 1 から始まりますが、コードでは全体で 0 から始まるインデックスが使用されます。 部分文字列`[start, start + k - 1]`偶然の間違いを避けるために、慎重に扱う必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(nk)$| 各部分文字列は最大で寄与します`k/2`等価エッジ |
 | スペース |$O(n^2)$| グラフには次のものを含めることができます$O(nk)$最悪の場合のエッジ |

 と`n ≤ 2000`、グラフは快適に小さいままです。 最も密度の高いケースでも、総作業量はわずか数百万回の操作であり、十分に制限内です。

 ## 特殊なケース

 次のことを考慮してください。```
4 3 1
```長さのすべての部分文字列`1`は自動的に回文になります。 グラフにはエッジがまったくありません。 

DFS では、次の 4 つの個別のコンポーネントが認識されます。```
{0}, {1}, {2}, {3}
```したがって、答えは次のとおりです。$$3^4 = 81$$これにより、アルゴリズムが誤って制約を導入しないことが確認されます。`k = 1`。 

ここで次のことを考えてみましょう。```
5 2 5
```文字列全体が回文である必要があります。 

アルゴリズムは以下を追加します。```
0 = 4
1 = 3
```位置`2`一人でいる。 

接続されたコンポーネントは次のようになります。```
{0,4}, {1,3}, {2}
```したがって、次の 3 つの独立した選択肢があります。$$2^3 = 8$$これにより、回文が文字列全体にまたがる場合に正しく処理されることが検証されます。 

最後に、等式が推移的に伝播するケースを考えてみましょう。```
4 10 2
```長さのすべての部分文字列`2`は回文でなければなりません。つまり、隣接する文字が一致する必要があります。 

グラフの端は次のとおりです。```
0-1
1-2
2-3
```DFS はすべてを 1 つのコンポーネントにマージします。```
{0,1,2,3}
```残るキャラクターの選択肢は 1 つだけなので、答えは次のようになります。$$10^1 = 10$$これにより、接続コンポーネントが推移的等価性を正しく捉えていることが確認されます。
