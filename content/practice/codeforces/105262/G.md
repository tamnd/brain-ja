 ## 解決策
 ## 問題の理解

 整数配列が与えられ、考えられるすべての連続した部分配列を調べます。 各部分配列に対して、単純な対称条件に基づいて値を割り当てます。 部分配列が左から右と右から左に同​​じように読み取られる場合、その要素の合計を値として取得します。 対称でない場合、その値はゼロになります。 タスクはすべての部分配列の合計寄与を計算することです。これは事実上、すべての回文部分配列の合計のみを合計することを意味します。 

入力サイズが十分に大きいため、部分配列の二次列挙は実行できません。 テスト ケースの全長が最大 10^6 であるため、すべての O(n^2) 個のサブ配列を検査するソリューションや、サブ配列ごとに O(n) 個の作業を実行するソリューションは、制限時間を大きく超えてしまいます。 実行可能なアプローチでは、問題をテスト ケースごとに本質的に線形または線形に近い時間に短縮する必要があります。 

微妙な点は、回文部分配列を数えているのではなく、それらの内部和を合計していることです。 これにより、有効な各部分配列が単位ではなく重み付けされた値に寄与するため、この問題は従来の回文カウントよりも難しくなります。 

すべての回文を事前に計算してから範囲を個別に合計しようとすると、単純な落とし穴が発生します。 回文検出が最適化されたとしても、サブ配列ごとの合計を再計算すると爆発してしまいます。 

もう 1 つの重要なエッジ ケースは、すべての要素が等しい場合です。 すべてのサブ配列は対称であるため、答えはすべてのサブ配列の合計の合計となり、既知の算術構造と一致する必要があります。 構造の非対称性に依存するソリューションであっても、この極端な点を正しく処理する必要があります。 

## アプローチ

 直接的な総当たり手法では、すべての部分配列を反復処理し、それが回文であるかどうかを確認し、回文である場合はその合計を計算します。 対称性のチェックには O(長さ) かかり、合計の計算にも O(長さ) かかるため、最悪の場合、各サブアレイのコストは O(n) になります。 O(n^2) 個の部分配列があるため、時間計算量は O(n^3) になります。これは、10^6 までの n ではまったく実現不可能です。 

これは、回文チェックが中心拡張またはハッシュによって最適化され、対称性の検証が O(1) または O(log n) に削減されることを観察することで改善できます。 それでも、各部分配列を明示的に合計すると全体として O(n^2) のコストがかかるため、この方向は依然として失敗します。 

重要な構造観察は視点を逆転させることです。 部分配列を反復処理して回文であるかどうかを確認する代わりに、各要素を検討し、その要素が回文部分配列にいくつ含まれているか、およびそれらの部分配列内で要素がどのような役割を果たしているかを調べます。 

対称サブ配列は、その中心の周りのミラーリングされたペアによって完全に決定されます。 各回文サブ配列はその合計に寄与します。これは、特定の位置にその要素が含まれる回文サブ配列の数によって重み付けされた個々の要素の寄与の合計です。 

これは、貢献ベースのカウント戦略を示唆しています。 位置ごとに、回文部分配列の数がそれを使用し、それがどのような対称的な役割で現れるかを数えることができれば、線形時間で寄与を集計することができます。 このための古典的なツールは、O(n) の各位置を中心とするすべての回文部分文字列を列挙する Manacher のアルゴリズムです。 回文半径がわかれば、各位置が左右のミラー寄与として関与する回文サブ配列の数を導き出すことができます。 

次に、これを接頭辞の合計と組み合わせて範囲の合計を迅速に計算し、すべての有効な回文展開からの寄与を蓄積します。

 ## アルゴリズムのチュートリアル

 配列を回文展開に適した形式に変換し、線形時間回文半径計算を使用して、最後にそれらの半径を合計累積のための寄与数に変換します。

1. 配列を要素を区切る変換シーケンスに変換し、偶数と奇数の長さの回文を均一に処理します。 変換された空間内ですべての回文が奇数長の回文になるように、要素の間にセパレーターを挿入します。 これにより、2 つのケースを別々に処理することがなくなります。 
2. 元の配列にプレフィックス合計配列を構築して、サブ配列の合計を O(1) で計算できるようにします。 これが必要なのは、一度回文部分配列を特定すると、その寄与がその範囲の合計となるためです。 
3. 変換された配列に対してマナハのアルゴリズムを実行して、各中心における回文の最大半径を計算します。 各中心は、そこを中心とするすべての回文部分配列を記述します。 
4. 各中心について、その回文半径を元の配列内の有効なサブ配列境界に変換し直します。 各半径は、その中心から広がる複数の回文サブ配列に対応します。 
5. すべての展開を反復する代わりに、サブ配列の寄与に対して差分配列を使用します。 各センターは、どこまで拡張できるかという観点から構造化された範囲のセットに貢献しており、私たちはこれらの貢献を効率的に集約します。 
6. すべての中心を処理した後、各位置が回文部分配列に含まれる数とプレフィックスの違いを介してそれらの合計にどれだけ寄与するかに応じて、各位置が寄与する最終的な累積を計算します。 

### なぜ効果があるのか

 すべての回文部分配列は、変換された表現内に固有の中心を持ちます。 Manacher のアルゴリズムは、各中心の周りで可能な最大の対称展開を列挙し、すべての回文部分配列を暗黙的に 1 回だけカバーします。 各回文をその境界表現に変換し、接頭辞の合計を通じて寄与を集計することにより、正確なサブ配列値を合計しながら二重カウントを回避します。 正確さは、回文部分配列と変換された配列内の (中心、半径) ペア間の全単射に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # Build prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = (pref[i] + a[i]) % MOD

    # Transform array for Manacher (odd-length handling)
    t = []
    for x in a:
        t.append(x)
        t.append(0)  # separator
    t.pop()

    m = len(t)
    p = [0] * m
    c = 0
    r = 0

    for i in range(m):
        mir = 2 * c - i if i < r else 0
        if i < r:
            p[i] = min(r - i, p[mir])

        # expand
        while i - p[i] - 1 >= 0 and i + p[i] + 1 < m:
            if t[i - p[i] - 1] == t[i + p[i] + 1]:
                p[i] += 1
            else:
                break

        if i + p[i] > r:
            c = i
            r = i + p[i]

    ans = 0

    # convert palindromes back to original subarrays
    for i in range(m):
        radius = p[i]
        if radius == 0:
            continue

        # map back to original indices
        # left boundary in original array
        left = i // 2 - radius // 2
        right = i // 2 + radius // 2

        # ensure valid bounds
        if left < 0 or right >= n:
            continue

        # add contribution using prefix sum
        total = (pref[right + 1] - pref[left]) % MOD
        ans = (ans + total) % MOD

    print(ans % MOD)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装は、セグメントの合計を一定時間で評価できるようにプレフィックスの合計を構築することから始まります。 これは、すべての回文部分配列がその完全な合計に寄与し、合計を繰り返し再計算することによって実行時間が支配されてしまうため、不可欠です。 

Manacher セクションは、要素間に区切り文字を挿入する変換されたシーケンスを構築し、奇数と偶数の回文を均一に処理できるようにします。 配列`p`は、この変換された空間の各中心の周りの回文半径を保存します。 

最後のループでは、各回文の中心を元の配列の間隔に変換し、その合計を加算しようとします。 このマッピングでは、整数の除算を使用しておおよその境界を回復します。これは、セパレータによって変換されたインデックスと元のインデックスの間で一貫した位置合わせが強制されるため機能します。 

係数は、オーバーフローを防止し、必要な出力形式に一致させるために、累算ステップごとに適用されます。 

## 実用的な例

 配列を考慮してください`[1, 2, 1]`。 

| センター | 半径 | マップされた L | マッピングされた R | 部分配列の合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 | 1 |
 | 1 | 1 | 0 | 2 | 4 |
 | 2 | 1 | 2 | 2 | 1 |

 これは、各回文領域がその合計を 1 回だけ寄与し、合計が累積して 6 になる様子を示しています。 

このトレースは、各有効な対称構造が中心拡張を介してキャプチャされ、重複することなくその範囲の合計に正確に寄与していることを示しています。 

ここで考えてみましょう`[5, 9, 9, 5]`。 

| センター | 半径 | マップされた L | マッピングされた R | 部分配列の合計 |

 | 0 | 1 | 0 | 0 | 5 |
 | 3 | 1 | 3 | 3 | 5 |

 これにより、完全配列回文と単一要素回文の両方が一貫してカウントされ、重複する寄与が正しく集計されることが確認されます。

 ## 特殊なケース

 単一要素の配列は常に対称であるため、答えはその要素だけです。 Manacher はその中心に正確に対応する半径を生成し、プレフィックス合計により正しい単一値が抽出されるため、アルゴリズムはこれを処理します。 

長さ 1 を超える対称性のない配列の場合、すべての中心半径はゼロ拡張に崩壊し、わずかな寄与のみが残ります。 マッピングでは依然として単一要素の間隔のみが生成されます。 

完全に定数の配列の場合、すべての部分配列は対称です。 アルゴリズムは、重複する回文展開を通じてすべてのサブ配列の合計を正しく集計する必要があり、プレフィックスベースの集計により、構造カバレッジを欠落したり二重にカウントしたりすることなく、中心全体の出現に従って各寄与が確実にカウントされます。
