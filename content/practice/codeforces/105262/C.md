 ## 解決策
 ## 問題の理解

 グリッドは都市を表しており、各セルにはその種類を表す文字ラベルが付いています。 都市内の移動は独特の方法で制限されており、任意のセル間を直接移動することはできません。 代わりに、動きは常に 2 つのフェーズに分割されます。 まず、現在のセルから、現在のセルと同じ文字を持つ他のセルに何も支払うことなく「テレポート」できます。 このテレポートの後、オプションでグリッド内の任意のセルまで地下鉄に乗車し、その乗車の出発地と目的地の間のマンハッタン距離を支払うことができます。 

トリップは、文字列で指定された一連の必要なタイプを訪問することで構成されます。 i 日目には、プランの i 番目の文字とタイプが一致するセルで終了する必要があります。 どのセルで終了するかを選択することができ、有料の移動の前にテレポートを利用することもできます。 

重要な難点は、テレポーテーションにより、地下鉄の移動料金を支払う前に、接続された「タイプ クラス」内で自分の位置を任意に変更できることです。 これは、旅行者の有効な状態が単一のセルではなく文字タイプであり、連続する 2 日間のコストが、対応するタイプの代表セルの最適なペアに依存することを意味します。 

制約は非常に大きく、グリッドにはテスト ケースごとに最大 100 万セルを含めることができ、計画も最大 100 万ステップ、最大 10,000 のテスト ケースを含めることができます。 すべての文字の出現の間の遷移を直接考慮したり、グリッド上のステップごとの動きをシミュレートしたりする解決策は不可能です。 唯一実行可能なアプローチは、各文字を小さな要約構造に縮小する必要があります。 

文字がグリッド上に何度も散在して表示される場合、微妙な特殊なケースが発生します。 単純なアプローチでは、最初の出現など、文字ごとに代表的な位置が 1 つだけ必要であると想定するかもしれません。 2 つの文字間の最適な移動は、両方のセットにわたる出現の最適なペアの選択に依存するため、これは失敗します。 もう 1 つの失敗例は、同じ文字が遠く離れた複数のクラスターに出現する場合です。 単一の代表者を選択すると、距離を大幅に過大評価する可能性があります。 

## アプローチ

 テレポートを無視すると、問題は 1 ステップごとに 1 つのグリッド セルを選択し、連続する選択の間にマンハッタン距離を支払うことになります。 各ステップでは潜在的に n・m 個の候補の中から選択する必要があるため、これはすでにコストがかかります。 

ブルートフォース解釈では、必要な文字の連続するペアごとに、最初の文字の出現と 2 番目の文字の出現の間の最小マンハッタン距離を計算しようとします。 これは原則として正しいです。なぜなら、テレポーテーションによって、現在の文字が出現するたびに毎日を終了できるからです。 ただし、2 つの文字のすべての位置間のペアごとの距離を計算するのは遅すぎます。文字が O(nm) 回出現する場合、それを別の頻繁に出現する文字と比較すると、ペアごとに 2 次の動作が発生し、最大 26 個の文字が存在する可能性がありますが、それでも位置が多すぎます。 

重要な観察は、各文字のすべての位置を分離すると、問題はマンハッタン距離下のグリッド内の点のセット間の一連の遷移になるということです。 マンハッタン距離の構造により、古典的な短縮が可能になります。つまり、2 セットの点間の最小距離は、マンハッタン距離を極値のみが必要な形式に変換する座標変換を使用して計算できます。

2 点 (x1, y1) と (x2, y2) の場合、マンハッタン距離は |x1 − x2| となります。 + |y1 − y2|。 絶対値を拡張すると、(x + y)、(x − y)、(−x + y)、(−x − y) の 4 つの線形形式が得られます。 セット A と B の固定ペアの場合、最小マンハッタン距離は、これらの変換された座標での極値投影を一致させることによって達成されます。 したがって、文字ごとに、その出現するすべての x+y および x−y の最小値と最大値を事前計算するだけで十分です。 これら 4 つの数字は、距離クエリの目的でその文字の形状を完全に記述します。 

各文字が 4 つの極値に圧縮されると、文字間の遷移コストの計算は O(1) になります。 最終的な答えは、プラン内の連続するキャラクター間のコストの合計です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての出現に対するブルート フォースのペアワイズ距離 | O(k · (nm)^2) | O(nm) | 遅すぎる |
 | 文字ごとの極値投影を事前計算する | O(nm + k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを 1 回スキャンし、各文字のすべての座標を収集します。 テレポーテーションでは文字が出現するたびに開始点または終了点と同等になるため、この段階では完全な位置マップを構築しています。 
2. すべての文字について、4 つの値を計算します。x + y の最小値と最大値、およびそのすべての出現における x − y の最小値と最大値です。 これらは、マンハッタン距離分解に関連する唯一の方向である両対角方向の文字の広がりを要約しています。 
3. 任意の 2 つの文字 a と b の間のコスト関数を事前計算します。 変換された 4 つのメトリクスのそれぞれについて、極端な値を組み合わせて、a と b の間の最悪の場合の組み合わせを検討します。 最適なマンハッタン距離は、極値から導出されるこれら 4 つの候補の差の最小値です。 
4. 計画文字列をスキャンし、連続する文字間のコストを合計します。 各遷移は、前の文字の最適な出現で 1 日を終了し、次の文字の最適な開始点を選択することを表します。 

これが機能する理由は、テレポーテーションによって、移動料金を支払う前にどの文字の上に立っているかという制約がなくなるからです。 したがって、各文字は実質的に点のセットであり、2 つのセット間のマンハッタンの最小距離のみが問題となります。 極値変換により、すべてのペアの最小値が列挙されずに取得されることが保証されます。 

維持される不変条件は、計画内の各文字を処理した後、位置を明示的に追跡しない場合でも、概念的には将来の移行コストを最小限に抑えるその文字の最適な出現で終了するということです。 すべての可能な位置は、極値投影を通じて暗黙的に表されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        
        INF = 10**30
        min_xp = {}
        max_xp = {}
        min_xm = {}
        max_xm = {}
        
        for i in range(n):
            row = input().strip()
            for j, ch in enumerate(row):
                x, y = i, j
                xp = x + y
                xm = x - y
                
                if ch not in min_xp:
                    min_xp[ch] = INF
                    max_xp[ch] = -INF
                    min_xm[ch] = INF
                    max_xm[ch] = -INF
                
                min_xp[ch] = min(min_xp[ch], xp)
                max_xp[ch] = max(max_xp[ch], xp)
                min_xm[ch] = min(min_xm[ch], xm)
                max_xm[ch] = max(max_xm[ch], xm)
        
        P = input().strip()
        
        def dist(a, b):
            # compute min Manhattan distance between any occurrence of a and b
            candidates = []
            
            # using x+y projection
            candidates.append(max(abs(min_xp[a] - max_xp[b]), abs(max_xp[a] - min_xp[b])))
            # using x-y projection
            candidates.append(max(abs(min_xm[a] - max_xm[b]), abs(max_xm[a] - min_xm[b])))
            
            return min(candidates)
        
        ans = 0
        for i in range(1, k):
            ans += dist(P[i-1], P[i])
        
        print(ans)

if __name__ == "__main__":
    solve()
```グリッド スキャンは、文字をキーとする 4 つの極値辞書を構築します。 これにより、集計に必要な範囲を超えてすべての位置を明示的に保存することが回避されます。 各更新はセルごとに一定時間です。 

トランジション機能`dist`重要な幾何学的縮小を実装します。 極値投影を使用して 2 つの文字を比較します。 セット全体にわたる最小値と最大値のペアを考慮すると、4 つのマンハッタン変換が対称的に折りたたまれるため、必要な候補式は 2 つだけです。 

最後のループでは、プラン内の連続する文字全体のコストが累積されます。 文字が圧縮されると各ステップは独立するため、前の文字を超える状態は必要ありません。 

## 実用的な例

 さまざまな文字を選択することが重要になるように、文字が散在する小さなグリッドを考えてみましょう。 

入力：```

2 3 3
aba
cdc
abc
```極値を計算します。 

| 手紙 | 最小(x+y) | 最大(x+y) | 分(x-y) | 最大(x-y) |
 | --- | --- | --- | --- | --- |
 | | ... | ... | ... | ... |
 | b | ... | ... | ... | ... |
 | c | ... | ... | ... | ... |

 ここで、プラン「abc」の遷移を評価します。 

| ステップ | から | へ | 貢献 |

 | 2 | b | c | dist(b,c) |

 この表は、文字が圧縮されると、グリッド構造自体が計算に明示的に表示されなくなることを示しています。 

これは、アルゴリズムが実際のパスではなく、幾何学的要約のみに依存していることを確認します。 

2 番目の例として、すべてのセルが同一の文字である縮退グリッドを考えてみましょう。 その後、すべての極値が一致し、すべての距離がゼロになります。 このアルゴリズムは、すべての遷移をコスト 0 に正しく折りたたんで、テレポートだけで十分であるという直観と一致します。

 ## 特殊なケース

 離れた 2 つの領域に文字が表示されるグリッドが主なストレス テストです。 手紙だと仮定して、`a`(0,0) と (100,100) に表示されますが、`b`(0,100) と (100,0) に表示されます。 代表的な選択を単純に行うと、間違った組み合わせが選択され、距離が過大評価される可能性があります。 極値法は、x+y および x−y を介して両方の対角方向をキャプチャし、最小ペアが常に表現されることを保証します。 

「aba」のようなプランでは、アルゴリズムは最初に dist(a,b) を計算し、次に dist(b,a) を計算します。 極値定式化では対称性が維持されるため、両方の遷移は一貫しており、どちらの出現が暗黙的に選択されるかには依存しません。 

最後のコーナーケースは、単一キャラクターのプランです。 トランジション上のループは決して実行されないため、答えはゼロのままで、地下鉄の移動が必要ないという事実と一致します。
