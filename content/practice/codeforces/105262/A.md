 ## 解決策
 ## 問題の理解

 各出場者は最大 12 個の問題からなる小さなセットに直面し、制限時間が決められています。 彼らはランダム化された方法で問題と対話します。つまり、事前に順序を選択する代わりに、残っている未使用の問題の中から均一に繰り返し選択します。 問題を選択した後、問題の難易度に比べて評価が十分に高いかどうかに応じて、問題を解決するか失敗します。 いずれにせよ、時間が消費され、競技者は問題を再検討することはありません。 

したがって、ランダム プロセスは問題を一様にランダムに並べたものですが、各ステップの時間コストは問題と、問題が解決されるか失敗するかの両方に依存するというツイストがあります。 時間がなくなるとプロセスは直ちに停止し、問題は制限時間内に完全に完了した場合にのみ解答に貢献します。 

各出場者にとっての課題は、このランダムなプロセスの下で予想される解決される問題の数を計算し、それを大きな素数の法で出力することです。 

制約は重要な構造上のヒントです。 問題の数は少なく、最大 12 個であるため、サブセットにわたる指数関数的な状態が可能になります。 出場者の数は最大 10 万人と多数であるため、出場者ごとに動的プログラムを再計算するソリューションはすぐに遅すぎます。 時間は小さく、最大でも 300 です。これは、時間をかけて 2 番目の DP 次元が実現可能であることを示唆しています。 したがって、サブセットの状態と時間の間の相互作用は、一度事前に計算し、すべての出場者に対して再利用する必要があります。 

微妙なエッジ ケースは、「残っている問題の中から均一にランダムに選択する」ルールから生じます。 これは、独立した選択ではなく、完全なランダムな並べ替えを意味します。 もう 1 つの重要な詳細は、出場者に選択した問題のコストを完了するのに十分な残り時間がない場合、選択がすでに行われていたとしても、それ以上の試行を行わずにプロセスが直ちに停止することです。 

単純な間違いは、各問題を独立して扱い、確率を乗算することです。 順序が固定されておらず、時間の切り捨てがすべてのイベントを結合するため、これは失敗します。 もう 1 つのよくある失敗は、出場者ごとの DP の再計算であり、100,000 クエリまで拡張できません。 

## アプローチ

 ブルート フォース シミュレーションでは、問題のすべての順列が生成され、各順列のプロセスがシミュレーションされ、結果が平均化されます。 これは概念的には簡単です。n 個の階乗次数をすべて列挙し、それぞれの時間発展をシミュレートし、平均を計算します。 ただし、n が 12 であっても、順列の数はすでに 4 億 7,900 万であり、各シミュレーションは最大 12 ステップを処理します。 これは実現可能な限界をはるかに超えています。 

重要な観察は、プロセスが 2 つの要素、つまり残りの問題と残り時間によって完全に決定されるということです。 実際の順序は、プロセスをサブセットにわたるマルコフ連鎖に変換する一様なランダムな選択を通じてのみ重要です。 これにより、問題のサブセットと時間予算を超えた動的プログラミングが可能になります。 

それを受け入れると、問題は関数 dp[S][t] を計算することになります。これは、残り t 分の残りの集合 S から開始して、予想される解決済みの問題の数を表します。 各遷移は S から要素を均一に選択し、参加者にとって解決可能かどうかに応じて適切なコストを適用し、より小さなサブセットに移動します。 

唯一の複雑な問題は、各出場者がどの問題を解決できるかを定義していることですが、これはレーティングと難易度の比較によってのみ決まります。 つまり、各出場者は「良い」問題のサブセットに対応しており、DP はそのようなサブセットごとに事前計算できるということです。 n は最大 12 であるため、サブセットの数はわずか 4096 であり、完全な事前計算が可能になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な順列シミュレーション | O(n! · n) | O(n) | 遅すぎる |
 | 時間ディメンションを持つサブセット DP | O(2^n · 2^n · t · n) 事前計算、クエリごとに O(1) | O(2^n・t) | 承認済み |

 ## アルゴリズムのチュートリアル

 出場者が解決できる可能性のある問題のすべてのサブセットに対する答えを事前に計算し、その結果をすべての出場者に対して再利用します。 

1. 出場者ごとにビットマスクを作成します`good_mask`ここで、出場者の評価が問題 i の難易度以上の場合、ビット i は 1 になります。 これにより、問題がその出場者にとって解決可能なカテゴリと解決不可能なカテゴリに分類されます。 
2. DP テーブルを定義する`dp[mask][time]`、 どこ`mask`残りの未使用の問題のセットを表し、`time`残り分です。 この値には、その状態から予想される解決された問題の数が格納されます。 
3. 小さいマスクへの遷移が常にすでに計算されるように、サイズの大きい順にマスクを処理します。 この順序により、状態を計算するときに、次のすべての状態が確実に利用可能になります。 
4. 州ごとに`(mask, time)`、すべての問題を反復して合計寄与度を計算します。`i`で`mask`。 各問題は確率で選択されます`1 / |mask|`。 
5. 問題がある場合`i`このマスク タイプでは解決できません。`tf[i]`時間が許せば、時間がかかり、解決された問題はゼロになります。 それ以外の場合、プロセスは停止します。 
6. 問題がある場合`i`解決可能、消費する`ts[i]`完全に完了した場合は、時間をかけて解決した問題を 1 つ提供します。 それ以外の場合はゼロを提供して停止します。 
7. コストを差し引いた残り時間が負の場合、その分岐は直ちに終了し、寄与はゼロになります。 
8. それ以外の場合は、次へ移行します。`dp[mask without i][new_time]`、解決が成功した場合は 1 を追加します。 
9. 累積合計を次の値で割ります。`|mask|`モジュラー逆関数を使用して均一なランダム選択を考慮します。 

### なぜ効果があるのか

 このプロセスはマルコフ決定システムであり、次の状態は現在の残りセットと残り時間のみに依存します。 すべての有効な実行パスは、選択された問題の 1 つのシーケンスに正確に対応し、そのようなシーケンスのそれぞれは、各ステップでの均一な選択の積に等しい確率を持ちます。 DP は、最初の選択肢を条件付けし、すべての可能性を合計することによって期待値を計算します。これにより、期待値の線形性が維持されます。 すべての状態がより小さなサブセットに分解され、すべての遷移によってマスク サイズが厳密に縮小されるため、サイクルは存在せず、DP は十分に根拠があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m, t = map(int, input().split())
    d = list(map(int, input().split()))
    ts = list(map(int, input().split()))
    tf = list(map(int, input().split()))
    ratings = list(map(int, input().split()))

    # dp[mask][time]
    size = 1 << n
    inv = [1] * (n + 1)
    for i in range(1, n + 1):
        inv[i] = pow(i, MOD - 2, MOD)

    # precompute dp for every possible "good mask"
    # dp_good[good_mask][mask][time] is too big,
    # instead we compute dp per good_mask

    # store results
    res = {}

    # iterate all good masks
    for good in range(size):
        dp = [[0] * (t + 1) for _ in range(size)]
        # process by increasing mask size
        for mask in range(size):
            for tm in range(t + 1):
                if mask == 0:
                    continue
                total = 0
                cnt = bin(mask).count("1")

                for i in range(n):
                    if not (mask >> i) & 1:
                        continue

                    if good >> i & 1:
                        cost = ts[i]
                        if tm < cost:
                            val = 0
                        else:
                            val = 1 + dp[mask ^ (1 << i)][tm - cost]
                    else:
                        cost = tf[i]
                        if tm < cost:
                            val = 0
                        else:
                            val = dp[mask ^ (1 << i)][tm - cost]

                    total += val

                dp[mask][tm] = total * inv[cnt] % MOD

        res[good] = dp[(1 << n) - 1][t]

    out = []
    for r in ratings:
        good = 0
        for i in range(n):
            if r >= d[i]:
                good |= (1 << i)
        out.append(str(res[good]))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```DP テーブル`dp[mask][tm]`は、特定の残りセットと残り時間からの予想スコアを表します。 マスクと時間に対するネストされたループは、計算時に次のように順序付けされます。`dp[mask][tm]`、小さいマスクはすべてすでに計算されています。 遷移では、次に選択された問題が明示的に列挙され、現在の良好マスク分類で解決可能かどうかに応じて正しい時間コストが適用されます。 

最後のマッピング ステップでは、各出場者を解決可能な問題のビットマスクに変換し、事前に計算された回答を直接取得します。

 ## 特殊なケース

 主なエッジケースは、選択した問題が残り時間内に完了できない場合です。 このような状況では、プロセスは即座に停止し、部分的な貢献は行われません。 たとえば、残り時間が 5 で、問題のコストが 10 の場合、DP ブランチは直接寄与ゼロとなり、それ以上遷移しません。 

もう 1 つの微妙なケースは、時間がコストと正確に一致する場合に発生します。 この場合、問題は解決されたものとしてカウントされ、その後プロセスは終了します。 DP は、次の場合に遷移を許可することでこれを処理します。`tm >= cost`そして、正確にその量を消費し、時間をゼロにしておきますが、終了する前にソルブをカウントします。 

最後のエッジケースは、残りのセットが空になる場合です。 それ以上の問題は選択できず、それ以上の貢献もできないため、DP は残り時間に関係なく正しくゼロを返します。
