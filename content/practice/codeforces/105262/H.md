 ## 解決策
 ## 問題の理解

 n × m 個のブロックに分割された都市を表すグリッドが与えられます。 各ブロックには、カプチーノ、ホット チョコレート、両方のドリンクを提供するコーヒー ショップ、または何も提供しないコーヒー ショップが含まれている場合があります。 2 人がこのグリッドの反対側の角から開始します。1 人は左上のセル (1, 1) から開始し、もう 1 人は右下のセル (n, m) から開始します。 

どちらも 4 つの基本的な方向に一度に 1 歩ずつ移動できます。 通常、移動には 1 単位の労力がかかりますが、現在のセル上のコーヒーショップの種類に応じて、このコストを削減できる特別なルールがあります。 人が好みの飲み物を提供するセルに立っている場合、その移動に労力を費やすことなく、隣接するセルに移動できます。 それ以外の場合は、移動費用が 1 かかります。 

最初の人はホットチョコレートを好むため、タイプ 2 または 3 を含む細胞は彼らにとって「自由移動源」として機能します。 2 番目の人はカプチーノを好むため、タイプ 1 またはタイプ 3 を含むセルは彼らにとって自由に移動できるソースになります。 

目標は、両方の人がグリッド内のどこかの同じセルに到達できるようにするために費やさなければならない最小の合計労力を計算することです。 

すべてのテスト ケースにわたる制約 n · m ≤ 10^6 は、すべての入力にわたるグリッド セルの総数が線形サイズであることを意味するため、どの解も O(nm) または O(nm log nm) に近くなければなりません。 (nm)^2 以下のスケールになる、両方の人を同時にペアワイズ状態探索するようなことは、制限内では不可能です。 

素朴だが魅力的なアイデアは、両方の動きを一緒にシミュレートして、両方の人の位置を追跡することです。 これにより、nm × nm のサイズの状態空間が得られますが、これは実現不可能です。 

幾何学的に「最も近い」セルで貪欲に一致させようとすると、さらに微妙な失敗のケースが発生します。 たとえば、近くに自由移動ゾーンがないために 2 つのセルのうちの 1 つに安価に到達できない場合、中心近くのセルは最適ではない可能性があります。 最適な集合場所は、マンハッタンの距離ではなく、最短経路の構造によって決まります。 

## アプローチ

 この問題を強引に解釈すると、この問題は 2 エージェントの最短経路問題として扱われます。 状態 (x1、y1、x2、y2) を追跡し、各ステップで同期ルールに応じてどちらかまたは両方のプレーヤーを動かします。 独立したパスへの移動を単純化したとしても、すべての合流点を試すには、両方の始点からすべてのセルまでの最短パスを計算する必要があります。 最適化を行わない場合、各 BFS またはダイクストラ展開がグリッドの大部分を再訪することになるため、セルごとまたはペアごとに最短パス検索を実行すると、最悪の場合、およそ O((nm)^2) の動作が発生します。 

重要な観察は、2 人が最終的な会合ポイントまで対話しないことです。 それらのパスは独立しており、コスト構造の形式は両方とも同一であり、どのセルがゼロコスト遷移を提供するかだけが異なります。 これは、各開始点からすべてのセルに到達するための最小コストを個別に事前計算できることを意味します。 これら 2 つの距離グリッドが得られたら、答えは単にそれらの合計のすべてのセルの最小値になります。 

コスト関数の構造は非常に重要です。 セルの種類に応じて、セルからの移動は無料または 1 コストかかります。 これはまさに、エッジの重みが {0, 1} であるグリッド グラフ上の最短経路問題であり、0 ～ 1 BFS を使用して効率的に解くことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 共同状態検索 | O((nm)^2) | O((nm)^2) | 遅すぎる |
 | 2 つの独立した 0-1 BFS 実行 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、各人に 1 つずつ、2 つの別々の距離グリッドを計算することで解決します。

1. (1, 1) から始まる最初の人物の距離グリッドを構築します。 すべての距離を大きな値に初期化し、開始セルを 0 に設定します。 
2. (1, 1) から 0-1 BFS を実行します。 セルから拡張する場合、隣接セルへの移動コストが 0 か 1 かを決定します。コストは、現在のセルにホット チョコレート (タイプ 2 または 3) が含まれているかどうかによってのみ決まります。 「はい」の場合、すべての発信移動は無料です。 それ以外の場合はコスト 1 です。両端キューを使用して距離を更新します。コスト 0 のエッジの場合は前にプッシュし、コスト 1 のエッジの場合は後ろにプッシュします。 
3. (n, m) から始まる 2 人目の人に対して同じプロセスを繰り返しますが、自由移動条件はカプチーノの空き状況 (タイプ 1 または 3) に依存します。 
4. 両方の距離グリッドが計算されたら、グリッド内のすべてのセルを反復処理して、distA[i][j] + distB[i][j] を計算します。 最小合計を追跡します。 
5. この最小値を答えとして返します。 

唯一の微妙な点は、「自由移動」条件が、入力するセルではなく、出力するセルに適用されることです。 これにより、グラフのエッジがソース ノードのみに依存するようになります。これにより、まさに 0-1 BFS がきれいに動作できるようになります。 

### なぜ効果があるのか

 BFS の各状態は、特定のセルに到達するための最小コストが既知であることを表します。 エッジの重みは 0 または 1 のみであり、現在のセル タイプにのみ依存するため、最短パスのプロパティは標準の 0-1 BFS 順序で保持されます。 デキューにより、コスト 0 で到達した状態はすべて、コスト 1 で到達した状態が処理される前に処理され、減少しない正しい探索順序が維持されます。 両方のエージェントがすべてのセルへの真の最短パス コストを独立して計算するため、どのミーティング ポイントでも 2 つの最適な独立したパスが結合され、すべてのセルにわたって最小値を取ることで全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def bfs(grid, n, m, sx, sy, good_set):
    dist = [[INF] * m for _ in range(n)]
    dq = deque()
    dist[sx][sy] = 0
    dq.append((sx, sy))

    while dq:
        x, y = dq.popleft()
        d = dist[x][y]

        # determine cost of moving out of (x, y)
        w = 0 if grid[x][y] in good_set else 1

        for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                nd = d + w
                if nd < dist[nx][ny]:
                    dist[nx][ny] = nd
                    if w == 0:
                        dq.appendleft((nx, ny))
                    else:
                        dq.append((nx, ny))
    return dist

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]

        dist1 = bfs(grid, n, m, 0, 0, {2, 3})
        dist2 = bfs(grid, n, m, n - 1, m - 1, {1, 3})

        ans = INF
        for i in range(n):
            row1 = dist1[i]
            row2 = dist2[i]
            for j in range(m):
                ans = min(ans, row1[j] + row2[j])

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は 2 人の旅行者を完全に分離し、問題を 2 つの最短経路の計算に削減します。 各 BFS は両端キューを使用して 0 ～ 1 の BFS 順序を維持し、グリッド エッジの数における線形の複雑さを保証します。 

よくある実装の落とし穴は、ドリンク条件をソース セルではなく宛先セルに誤って適用することです。 これにより、グラフ モデルが変更され、0-1 BFS の正確さが失われます。これは、エッジの重みが出力状態ごとに一貫しなくなるためです。 

もう 1 つの微妙な点はメモリ レイアウトです。両方の距離の完全なグリッドを保存する必要がありますが、テスト全体のセルの総数が 10^6 で制限されているため、それでも安全です。 

## 実用的な例

 1 つまたは 2 つのセルが自由に移動できる小さなグリッドを考えてみましょう。 

### 例 1

 グリッド:```
2 0
0 1
```ここで、最初の人はホット チョコレート セル (2 または 3) から恩恵を受け、2 人目はカプチーノ セル (1 または 3) から恩恵を受けます。 

両方の距離マップを計算します。 

| ステップ | セル | Dist1 (1,1 から) | Dist2 (2,2 から) |
 | --- | --- | --- | --- |
 | 初期化 | (1,1) / (2,2) | 0/INF | INF / 0 |
 | BFS1 | (1,1) | を展開します。 隣人が更新されました | |
 | BFS2 | (2,2) を展開 | | 隣人が更新されました |

 両方の BFS を実行した後、すべてのセルをチェックし、dist1 + dist2 の最小合計を選択します。 待ち合わせ場所は、必ずしも幾何学的中心ではなく、両者が安価に到着できるセルとして自然に出現します。 

これは、独立した最短パスで十分であり、同期ロジックが必要ないことを示しています。 

### 例 2

 グリッド:```
3 3 3
0 0 0
1 0 2
```一番上の行では、最終的には両方の旅行者が自由に移動できるようになり (3 が両方に役立つため)、コストゼロの移行の回廊が作成されます。 

各コーナーからの BFS は、コストゼロの拡張でその回廊に沿って急速に伝播し、いったん良好なセルに到達すると、グリッドの大部分の横断が事実上低コストになることが確認されています。 

最終的な最小値は、重複する低コスト領域を通じて到達可能なセルで発生します。

 ## 特殊なケース

 単一セルのグリッドは、最もきれいな境界ケースです。 両方の人が同じセルで開始し終了するため、セルの種類に関係なく、答えはゼロになる必要があります。 BFS は開始セルを正しく初期化するため、両方の距離配列のその位置にはゼロが含まれ、最小合計はゼロになります。 

特別なセルがない (すべてゼロ) グリッドでは、問題は均一コスト エッジを使用した 2 つの独立した最短パス計算に帰着します。 BFS は標準的なマルチステップの最短パスに縮退し、両方の距離に障害物に応じたマンハッタンのような移動コストが反映され、自由な遷移に依存することなく正確性が保証されます。 

タイプ 3 のセルで満たされたグリッドにより、最大限の自由が生まれます。 すべてのセルでコスト 0 の移動が許可されるため、両方の BFS 実行でコスト 0 の開始セルがグリッド全体に伝播されます。 すべてのセルは総コストがゼロの有効なミーティング ポイントとなり、アルゴリズムは考えられるすべてのミーティング セルを評価して正しくゼロを返します。
