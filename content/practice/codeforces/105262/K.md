 ## 問題の理解

 いくつかの独立した実験が与えられました。 各実験には、固定の正の整数のしきい値があります。$w$これは不明ですが、同じテスト ケースのすべての実験で一貫しています。 各実験では、左から右に配置されたトマトの重みを表す正の整数の配列が提供されます。 最初のトマトから始めて、順番に食べることをシミュレートします。食べた重量の現在の合計を保持し、次のトマトの追加が超えない限り続行します。$w$。 次のトマトが合計を厳密に大きくするとすぐに、$w$、その実験のために永久に停止します。 実験の結果は、食べられずに残ったトマトの数です。 

したがって、各実験はプレフィックス合計の制約を記述します。$k$トマトは$\le w$、食べられます。 それ以外の場合、プロセスはプレフィックスが超過する最初の位置で停止します。$w$。 

複数の実験にわたって同じ$w$観察されたすべての「残りのカウント」を説明する必要があります。 タスクは、そのような最小のものを決定することです$w$、または、次の値は存在しないと結論付けます。$w$あらゆる実験を満足させることができます。 

制約は大きく、すべての実験にわたる配列の合計長は最大です。$10^6$、まであります$10^4$テストケース。 これにより、すべての候補値を試行するソリューションは除外されます。$w$または、推測ごとに繰り返しシミュレーションします。 有効なソリューションでは、各実験を線形時間で処理し、実験ごとに基本的に一定時間または対数時間で制約を結合する必要があります。 

素朴な再構成アプローチは、次の候補値を試すことです。$w$、すべての実験をシミュレートし、結果の残りの数が指定された値と一致するかどうかを確認します。$m$。 重量が上がるので、$10^9$プレフィックスの合計は次の値に達します$10^{15}$またはそれ以上の検索スペース$w$は巨大で、それぞれのシミュレーションは$O(n)$、これを実行不可能にします。

## アプローチ

 重要な観察は、それぞれの実験が説明していないことです。$w$直接的にですが、プレフィックスの合計が交差する前にどこまで移動できるかを示します$w$。 させて$k$実験で食べたトマトの数になります。 それから$k = n - m$。 このプロセスが意味するのは、最初の$k$トマトは完全に消費されており、$k = n$または$(k+1)$-番目のトマトは最初に取れません。 

これは、次の 2 種類の制約に変換されます。 

もし$k = n$、すべてのトマトが食べられた場合、配列の合計は最大で$w$。 

もし$k < n$、それから私たちは最初のものを正確に食べることができました$k$トマトなので、接頭辞の合計$S_k$満たさなければなりません$S_k \le w$、そして次のトマトの重さ$a_{k+1}$続行できなくなりますので、$S_k + a_{k+1} > w$。 これにより、厳密な上限が決まります。$w < S_k + a_{k+1}$。 

したがって、すべての実験では下限のいずれかが生成されます。$w \ge S_k$または制約区間$S_k \le w < S_k + a_{k+1}$プロセスが早期に終了したか、すべてを消費したかに応じて異なります。 

したがって、すべての実験は単一の整数変数に対する交差制約に帰着します。$w$。 最終的な答えは、すべての有効な間隔の交差部分の最小の整数です。 交差点が空いている場合は実行できません$w$。 

強引なアプローチでは、考えられるすべての手段が列挙されます。$w$最大プレフィックス合計までテストして各実験をテストし、コストを計算します$O(U \cdot n)$、 どこ$U$まで可能です$10^{15}$、それは不可能です。 

代わりに、グローバルな実行可能な間隔のみを維持します。$[L, R)$。 各実験では、線形時間で計算されたプレフィックス合計を使用して、この間隔を狭めます。

 ## アルゴリズムのチュートリアル

 私たちは各実験を独立して処理し、グローバルな実現可能な範囲を継続的に改良します。$w$。 

1. 実行可能範囲を次のように初期化します。$L = 0$、$R = 10^{18} + 1$。 この範囲は、可能なすべての値を表します。$w$これまでに処理された実験と一致しています。 
2. 実験ごとに、計算します。$k = n - m$、食べたトマトの数。 
3. 位置まで配列をスキャンしながらプレフィックスの合計を構築します。$k+1$制約に関してはこの境界のみが重要であるためです。 
4. もし$k = n$、その後トマトはすべて食べられます。 これは合計額を意味します$S_n$満たさなければなりません$w \ge S_n$。 アップデート$L = \max(L, S_n)$。 理由は、これより小さいと、$w$早めにやめておけばよかった。 
5. もし$k < n$、計算する$S_k$そして次の要素を確認してください$a_{k+1}$。 正確に停止するための条件$k$は$S_k \le w < S_k + a_{k+1}$。 以下を交差させて実行可能な間隔を更新します。$L = \max(L, S_k)$、$R = \min(R, S_k + a_{k+1})$。 これは、「k 個のアイテムを食べるのに十分な容量」と「次のアイテムを食べるのに十分ではない」の両方を捉えます。 
6. すべての実験を処理した後、次のことを確認します。$L \ge R$。 その場合、整数はありません$w$はすべての制約を満たしているため、「偽仮説」を出力します。 
7. それ以外の場合は出力$L$、これは実行可能な間隔の最小の整数です。 

なぜそれが機能するのかというと、すべての実験で凸型制約が定義されているからです。$w$、半線または境界のある間隔のいずれかです。 食べるというプロセスは単調です$w$: 増加$w$食べるトマトの数を増やすか保存することしかできません。 したがって、各実験は有効な連続したセットに変換されます。$w$価値観。 これらのセットを交差させると正確さが保たれ、交差部分の最小値が実現可能な最小値となります。$w$すべての実験にわたって。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        e = int(input())
        L, R = 0, 10**18 + 1

        for _ in range(e):
            n, m = map(int, input().split())
            a = list(map(int, input().split()))

            k = n - m

            if k == 0:
                # nothing eaten, so w < a[0]
                R = min(R, a[0])
                continue

            if k == n:
                # all eaten: w >= total sum
                s = 0
                for x in a:
                    s += x
                L = max(L, s)
                continue

            s = 0
            for i in range(k):
                s += a[i]
            next_w = a[k]

            L = max(L, s)
            R = min(R, s + next_w)

        if L >= R:
            print("False Hypothesis")
        else:
            print(L)

if __name__ == "__main__":
    solve()
```コードはグローバルな実行可能な間隔を維持し、実験ごとに調整します。 プレフィックスの合計は停止境界までのみ計算されます。$k$これにより、制約が必要ない場合に完全な配列に対する不必要な作業が回避されます。 

微妙な点は扱い方$k = 0$つまり、トマトを一切食べることができませんでした。 その場合、$w$最初の要素より厳密に小さくする必要があり、これが制約になります$w < a_1$、として実装されます$R = \min(R, a_1)$。 

合計が次の値に達する可能性があるため、整数の安全性は重要です。$10^{15}$, しかし、Python の整数はこれを自然に処理します。 上限$10^{18}$最終的な回答範囲が安全であることを保証します。
