 ## 問題の理解

 与えられた整数を表す数値基数を選択して、その表現に数字 4 が少なくとも 1 回含まれるようにしようとしています。 指定された範囲内のすべての塩基の中で、最大の塩基が必要です。 

具体的には、テストケースごとに番号を受け取ります。$n$。 私たちは書くことを想像します$n$基地内で$b$、 どこ$b$少なくとも 2、最大でも 2 でなければなりません$2 \cdot 10^{12}$。 その表現で、その数字をスキャンします。 少なくとも 1 つの数字が 4 に等しい場合、この基数は有効であるとみなされます。 私たちの仕事は、最大の有効な塩基を見つけるか、存在しないことを報告することです。 

制約$n \le 10^{12}$の桁数を意味します$n$適切な基数では小さく、基数 2 では最大でも約 40 ですが、より大きな基数ではさらに小さくなります。 これにより、どのような表現でも存在できる桁位置の数が制限されます。 テスト ケースの数は最大 10 なので、アルゴリズムはおよそ$O(n^{1/2})$または$O(n^{1/3})$ケースごとでもまだ大丈夫です。 

単純な試みではすべての拠点を試すことになるでしょう$b$2から$2 \cdot 10^{12}$、 変換する$n$基地に$b$、数字が 4 に等しいかどうかを確認します。単一の底をテストしても対数であるため、このアプローチはすぐに失敗します。$n$、したがって、作業の合計は制限をはるかに超えます。 

もう 1 つのよくある失敗例は、人々が単に次のことを確認している場合に発生します。$n \% b = 4$。 これは最後の桁のみを検証し、上位の桁の位置をすべて見逃します。 例えば、$n = 24$進数5は$44_5$、4 ですが満足しません。$24 \% 5 = 4$すべての有効な塩基の十分条件として単独で使用します。 

本当に難しいのは、数字の 4 がどの位置にも出現する可能性があり、各位置で異なる代数的制約が課されることです。$b$。 

## アプローチ

 ブルートフォースの構造はシンプルです。 すべての候補拠点について$b$、分割を繰り返します$n$による$b$基数変換は除算を正確に繰り返すので、これは正しいことです。 問題は、その範囲が$b$は膨大であり、それすべてを反復処理すると、おおよその結果が得られます$2 \cdot 10^{12}$候補者、それぞれの費用$O(\log n)$、それは完全に不可能です。 

重要な観察は、数字の条件が代数的に表現できることです。 数字 4 が位置に表示される場合$i$、次にベースで$b$数字は次のように書くことができます$$n = x \cdot b^{i+1} + 4 \cdot b^i + y$$と$0 \le y < b^i$。 これにより、問題は基底をシミュレートするのではなく、この方程式の整数解を求めることに変わります。 

数字 4 の位置によってケースを分けます。 4 が最下位桁にある場合、方程式は次のように単純化されます。$n = q b + 4$、 それで$b \mid (n - 4)$。 つまり、この場合の有効な基数はすべて次の約数になります。$n - 4$、効率的に列挙できます。 

4 が高い位置にある場合は、次のように言います。$i \ge 1$、 用語$b^{i+1}$早く成長します。 これにより直ちに制限がかかります$b$なぜなら$b^{i+1} \le n$。 したがって、各固定位置について、可能な塩基は次のように制限されます。$n^{1/(i+1)}$、次のように非常に小さくなります$i$が増加します。 これにより、各位置のすべての候補塩基を個別に試し、塩基表現を再構築することで妥当性を検証することができます。

 ## アルゴリズムのチュートリアル

 数字 4 が基本表現のどこに現れるかに基づいて検索を分割します。 

1. まず、数字 4 が単位の位置にある場合を処理します。 その場合に必要となるのは、$n = q b + 4$。 並べ替えると$n - 4 = q b$したがって、すべての有効な基数は除算する必要があります$n - 4$。 すべての約数を列挙します$n - 4$、基数が少なくとも 2 であることを確認し、変換されていることを確認します。$n$この基数には実際に数字 4 が含まれています。割り算だけでは上位の数字も制約に違反しないことが保証されないため、この手順が必要です。 
2. 次に、数字 4 が位置にある場合を考えます。$i \ge 1$。 数値を次のように書き換えます$n = a b^{i+1} + 4 b^i + r$、 どこ$r < b^i$。 これにより、その位置に数字が確実に配置されます。$i$は正確に 4 であり、キャリーやオーバーフローは発生しません。 
3. 固定位置の場合$i$という事実を利用します。$b^{i+1} \le n$。 これにより上限が決まります$b$、 具体的には$b \le n^{1/(i+1)}$。 このようなすべての候補塩基を繰り返します。 
4. 候補塩基ごとに、次の桁を明示的に構築します。$n$候補セットが小さいため、この検証は安全です。 
5. 当社は、すべてのポジションにわたるすべての有効な候補者の最大ベースを追跡します。 

正しさは、すべての有効な塩基のどこかの位置に数字の 4 がなければならないという事実から生まれます。$i$。 考えられるすべての位置を列挙し、それぞれについて、オーバーフローせずにその桁の位置をサポートできる可能性のある基底のみを考慮します。 すべての有効な解決策はこれらのケースの 1 つでのみ表示されるため、候補が見逃されることはありません。

import sys
input = sys.stdin.readline

def has_four(n, b):
    while n > 0:
        if n % b == 4:
            return True
        n //= b
    return False

def divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:

        i += 1
    return res

 ## 特殊なケース

 微妙なケースが 1 つ発生します。$n = 4$。 ここ$n - 4 = 0$そのため、除数ロジックは誤ってゼロの約数を列挙しようとします。 正しい動作は、4 の基数表現に有効な方法で数字 4 が含まれていないため、即座に拒否されます (表現は単なる「4」ですが、基数は厳密に 4 より大きくなければならず、基数制約では数字が無効になります)。 

別のケースは、最適な塩基が正確に$n - 4$。 のために$n = 20$、私たちは得ます$n - 4 = 16$、および基数 16 は表現を生成します$14_{16}$1 桁の 4 が含まれています。除数の列挙にはこの候補が正しく含まれており、検証によってそれが受け入れられることが確認されます。
