 ## 解決策
 ## 問題の理解

 各章に 2 つの属性 (一意のタイトルと一意の開始ページ番号) がある本が与えられています。 正しい本では、章は開始ページ番号の昇順に並べられます。これは、実際の読み上げ順序を表すためです。 

ただし、提供される目次はシャッフルされます。 重要な点は、章自体は何も破損していないということです。 各章は依然として正しい開始ページを指しており、すべての章が 1 回だけ存在します。 リスト内の順序が間違っているだけです。 

クエリごとに、エダードが読み終えたばかりの章のタイトルが示されます。 どの章がその直後に来るのか、開始ページごとに正しい順序で決定する必要があります。 終了した章が読む順序で最後の章である場合は、次の章がないことを出力します。 

入力サイズは大きく、全体で最大 10^5 章、テスト ケースごとに最大 10^5 クエリです。 これにより、クエリごとにすべての章をスキャンするソリューションは即座に除外されます。 最悪の場合、O(nq) でも 10^10 回の演算に達しますが、これは 1 秒の制限をはるかに超えています。 各クエリに一定時間内に応答できるようにする前処理が必要です。 

完了した章が最大の開始ページを持つ章である場合、微妙なエッジケースが発生します。 この場合、有効な後継者は存在しないため、特別なメッセージを出力する必要があります。 もう 1 つのエッジ ケースは、章が完全に任意の順序で指定されている場合です。これは、入力からの部分的な順序を想定できないことを意味します。 

## アプローチ

 直接的なアプローチは、すべてのクエリの正しい読み取り順序を再構築することです。 各クエリについて、すべての章をスキャンし、その章のページを見つけてから、再度スキャンして次の大きなページを見つけることができます。 次の章は現在のページより厳密に大きい最小のページであるだけなので、これは論理的に機能します。 ただし、各クエリのコストは O(n) となり、合計時間は O(nq) になります。n と q が両方とも 10^5 の場合、これでは遅すぎます。 

重要な観察は、構造が決して変わらないということです。 正しい順序は、章を開始ページでソートすることによって完全に決定されます。 一度並べ替えると、各章には決まった後続の章が存在します。 これにより、問題はマッピングの問題に変換されます。章のタイトルごとに、ソートされたリスト内の次のタイトルが知りたいとなります。 

章のタイトルからソートされた配列内の位置まで辞書を事前計算できます。 その後、クエリへの応答は定数時間の検索になり、その後に近隣チェックが行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 (ソート + ハッシュ マップ) | O(n log n + n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての章をペアのリスト (ページ、タイトル、またはタイトル、ページ) に読み込みます。 並べ替えはページごとに行う必要があるため、両方を保存しますが、クエリはタイトルごとに行われます。 タイトルは意味のある順序ではないため、この分離は不可欠です。 
2. 章のリストを開始ページで昇順に並べ替えます。 ページは順序を厳密に定義し、一意であるため、これにより本の実際の読書順序が再構築されます。 
3. 各章のタイトルをソートされたリストのインデックスにマッピングする辞書を作成します。 これにより、クエリ文字列から順序付けされたシーケンス内の位置に直接ジャンプできます。 
4. クエリ タイトルごとに、辞書を使用して O(1) 内のインデックスを取得します。 
5. インデックスがソートされたリストの最後の位置ではない場合は、インデックス + 1 の位置にタイトルを出力します。それ以外の場合は、「No More Chapters」を出力します。 

重要な考え方は、順序がグローバルに固定されると、各クエリは検索問題ではなくローカル近傍検索になるということです。 

### なぜ効果があるのか

ページ番号は個別であり、厳密な合計順序を定義するため、ページ番号で並べ替えると、章の固有の正しい合計順序が生成されます。 辞書では、すべての章タイトルがこの順序で 1 つの位置に正確に関連付けられることが保証されます。 ソートされた配列の後続関係は明確に定義されており、安定しているため、各クエリに対する答えは、この固定シーケンスの次の要素となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        chapters = []

        for _ in range(n):
            s, p = input().split()
            p = int(p)
            chapters.append((p, s))

        chapters.sort()  # sort by page

        pos = {}
        for i, (p, s) in enumerate(chapters):
            pos[s] = i

        for _ in range(q):
            c = input().strip()
            i = pos[c]
            if i == n - 1:
                out.append("No More Chapters")
            else:
                out.append(chapters[i + 1][1])

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず開始ページで章を並べ替えることにより、正しい順序を再構築します。 辞書`pos`これにより、クエリ中にスキャンを繰り返す必要がなくなるため、これは非常に重要です。 各クエリは直接インデックス検索になります。 

よくある実装上の間違いは、クエリの入力文字列を削除するのを忘れることです。これにより、辞書キーの不一致が発生する可能性があります。 もう 1 つは、タプルの順序付けの混乱により、誤ってページではなくタイトルでソートしてしまうことです。 タプルが確実に`(page, title)`これを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q) | 並べ替えが優先され、各クエリは O(1) |
 | スペース | O(n) | チャプターリストとポジションマップの保管 |

 この制約により、合計で最大 10^5 の章が許可されるため、O(n log n) の前処理ステップは問題なく制限内に収まります。 クエリ処理は全体的に q において線形であり、最適です。

 ## 特殊なケース

 特殊なケースの 1 つは、章が 1 つしかない場合です。 並べ替えると、その章は最初と最後になります。 辞書は依然としてインデックス 0 にマップします。`n - 1 == 0`を実行すると、すべてのクエリが「No More Chapters」を正しく返します。 

もう 1 つのエッジ ケースは、入力順序がページごとに逆ソートされる場合です。 ページ番号によって厳密な合計順序が定義されるため、並べ替えても正しい順序が復元されます。 後続者は常にソートされた配列内のインデックス + 1 であるため、隣接ロジックは有効なままです。 

最後のエッジケースは、同じ章に対してクエリが繰り返されることです。 状態を変更しないため、各クエリは同じ辞書検索を介して個別に解決され、繰り返しに関係なく一貫した出力が保証されます。
