 ## アルゴリズムのチュートリアル

 1. 便宜上、ツリーを任意にルート化します。$1$。 DFS を使用してサブツリーのサイズを計算します。 これにより、各ノードについて、ルート化されたツリーの「下」のコンポーネントのサイズがわかります。 
2. 各頂点について$u$、次の場合に残る最大の連結成分のサイズを計算します。$u$が削除されます。 これは、次の各子サブツリーで構成されます。$u$、サイズのある「親側」を加えたもの$n - \text{subtree}(u)$。 
3. すべての頂点にわたるこの最大コンポーネント サイズの可能な最小値を特定します。 この最小値を達成する頂点が重心です。 
4. 複数の頂点が同じ最小値を達成する場合は、最小のインデックスを持つ頂点を選択します。 

これが機能する理由は、敵の最適な戦略が効果的にツリーの 1 つのコンポーネントに質量を集中させるためです。$u$。 最悪のコンポーネント サイズによって、ツリーのどの程度を「キャプチャ」できるかが決まります。$u$したがって、その最大コンポーネント サイズを最小化すると、最初のプレイヤーが保証する有利な頂点のシェアが直接最大化されます。 

### なぜ効果があるのか

 固定の場合$u$、いずれかの選択肢を検討してください。$v$。 優先する頂点$v$のコンポーネント全体を常に含む領域を形成します。$v$木が割れたとき$u$ただし、間のパスの境界近くの頂点は除きます。$u$そして$v$。 この境界効果は、1 つのコンポーネント全体が次の方向に偏っているという事実を上回ることはできません。$v$。

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            g[b].append(a)

        parent = [-1] * n
        order = []
        stack = [0]
        parent[0] = -2

        while stack:
            v = stack.pop()
            order.append(v)
            for to in g[v]:
                if to == parent[v]:
                    continue
                parent[to] = v
                stack.append(to)

        sz = [1] * n
        for v in reversed(order):
            for to in g[v]:
                if to == parent[v]:
                    continue
                sz[v] += sz[to]

        best = n + 1
        ans = 0

        for v in range(n):
            mx = n - sz[v]
            for to in g[v]:
                if to == parent[v]:
                    continue
                mx = max(mx, sz[to])
            if mx < best or (mx == best and v < ans):
                best = mx
                ans = v

        print(ans + 1)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずツリーを構築し、DFS スタイルのトラバーサルを実行して親関係を確立し、サブツリーのサイズを計算します。 長いチェーンでの再帰の深さの問題を回避するために、再帰の代わりに反復スタックが使用されます。 

その後、各頂点が潜在的な重心候補として評価されます。 値$n - \text{subtree}(v)$上のコンポーネントのサイズを表します$v$、一方、各子サブツリーは、次の場合に潜在的なコンポーネントに寄与します。$v$が削除されます。 これらの最大値が計算されて最小化されます。 

よくある実装上の間違いは、親側コンポーネントを忘れることです。これにより、実際の最大コンポーネント サイズが過小評価され、大きなブランチの奥深くにあるノードが誤って選択されてしまいます。

 ## 特殊なケース

 キー エッジ ケースは、重心が一意ではない長いチェーンです。 均等な長さのパスの場合、中央の 2 つの頂点の両方がコンポーネントの最大サイズを最小化します。 アルゴリズムは、それらの中で最小のインデックスを選択することにより、これを正しく処理します。 

もう 1 つのケースは、インデックスの順序を除いてすべてのリーフが対称的に見えるスター グラフです。 計算により、すべてのリーフには大きな最大値コンポーネントがあり、中心には最小値が含まれることが保証されるため、インデックス付けに関係なく中心が常に選択されます。 

最後に、密なサブツリーに接続された 1 つの深いチェーンを持つ歪んだツリーは、依然として正しく動作します。これは、親側のコンポーネント サイズが重いブランチの全重みを捉え、誤って選択された深いノードが選択されるのを防ぐためです。
