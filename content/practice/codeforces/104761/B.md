 ## 問題の理解

 一定の長さの線分から位置を徐々に「埋める」決定論的なプロセスをシミュレートしています。$N$。 ポジションには次から番号が付けられます。$1$に$N$。 プロセスは 2 つのエンドポイントをすぐに選択することから始まります。$1$そして$N$ステップ 1 で使用されます。 

その後、残りの未使用の位置がいくつかの互いに素な連続セグメントを形成します。 各ステップで、現在のすべてのセグメントを調べ、最大長のものを選択し、同じ長さのセグメントが複数ある場合は、一番左のセグメントを選択します。 選択したセグメントから、常にその中間位置を選択します。セグメントの長さが奇数の場合は 1 つの中間点、偶数の場合は 2 つの中心位置です。 これらの位置はそのステップで使用されたものとしてマークされ、セグメントは残りの小さなセグメントに分割されます。 

タスクは、すべてのプロセス全体をシミュレートすることではありません。$N$、大型では不可能です$N$、しかし代わりに答えるために$Q$クエリ: クエリされた位置ごとに$A_i$、その位置が最初に使用された正確なステップを決定します。 

重要な難点は、$N$と同じ大きさにすることができます$10^{18}$したがって、構造は明示的に構築するのではなく、推測する必要があります。 クエリの数は十分に少ないので余裕があります$O(Q \log N)$またはクエリごとに同様の推論が行われますが、直線的なものではありません。$N$。 

単純なシミュレーションでは、すべてのセグメントを優先順位構造に維持し、それらを繰り返し分割しますが、それでも暗黙的に作成されるセグメントの数に依存します。$N$最悪の場合。 これにより、すべての間隔を明示的に追跡するアプローチは即座に除外されます。 

タイブレークでは微妙な問題が現れる。 複数のセグメントが同じ長さの場合、最も左のセグメントを選択する必要があるため、どの表現でも長さに加えて左の端点による順序を保持する必要があります。 もう 1 つの特殊なケースは、2 つの位置が一度にマークされる偶数長のセグメントです。 両側を対称的に考慮しないと、ステップの割り当てが不正確になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。それぞれが左右の境界によって定義されるセグメントのセットを維持し、プロセスを段階的にシミュレートします。 各反復ですべてのセグメントをスキャンし、最も長いセグメントを選択し (左の端点で結合を解除)、その中間点を計算し、それらを使用済みとしてマークし、セグメントを最大 2 つの小さなセグメントに分割します。 使用した各位置のステップ番号も記録しておけば、後で問い合わせに答えることができます。 

これはプロセスを正確に反映しているため、これは正しいです。 問題は、各ステップで現在のセグメントをすべてスキャンして最適な候補を見つける必要があることです。 分割後、セグメントの数はステップに応じて直線的に増加するため、時間の経過とともに処理が行われます。$O(N)$セグメントと各選択のコスト$O(N)$ヒープを使用しない限り。 ヒープがあっても、まだ生成されます$O(N)$不可能な出来事$N \le 10^{18}$。 

重要な観察は、実際には世界時間をシミュレートする必要がないということです。 このプロセスは純粋に構造的なものです。常に最大の利用可能な区間が取られ、その区間は左半分と右半分の独立した部分問題に分割されます。 各間隔は、子が後で処理される独立した再帰問題のように動作します。 これは、バイナリ ツリーとしてモデル化できる、古典的な「優先度による間隔分割」プロセスです。 

時間をシミュレーションするのではなく、再帰的に考えます。 すべてのセグメント$[L, R]$1 つまたは 2 つの「中心ノード」を生成し、次に分割します。$[L, mid-1]$そして$[mid+1, R]$。 セグメントが処理される順序は、概念ツリー内の最も深い未処理のノードを繰り返し選択することに対応しますが、クエリに答えるためにその順序を明示的に必要とするわけではありません。 重要なのは、各位置が、この暗黙的な再帰ツリーの深さによって決定される一意のステップに関連付けられていることです。 

したがって、問題は特定の位置についての計算に帰着します。$x$、この再帰的な分割プロセス中にセグメントの中心になったとき。 これは、次の内容を含むセグメントについて繰り返し識別することによって導出できます。$x$、親が分割される前に選択されているかどうか、およびそのセグメントの中点に割り当てられたステップ番号を追跡します。 

セグメント サイズによって優先度が決定される、優先度主導の分割統治ツリーを効果的にシミュレートします。

 ## アルゴリズムのチュートリアル

 全区間から位置までのセグメント選択パスをシミュレートすることにより、各クエリを個別に処理します。 

1. インターバルから始める$[1, N]$そして歩数計$t = 1$。 エンドポイント$1$そして$N$これらは定義により直ちに使用されるため、常にステップ 1 が割り当てられます。 
2. 問い合わせられた位置の場合$x$、現在のセグメントを維持します$[L, R]$含まれることが知られている$x$。 もともとこれは$[1, N]$。 
3. 中心位置を決定します。$[L, R]$。 もし$R-L+1$奇数です、中心は 1 つです$m = (L+R)/2$。 偶数であれば、中心は 2 つあります$m_1 = (L+R-1)/2$そして$m_2 = (L+R+1)/2$。 
4. 比較する$x$中央領域と。 もし$x$が中心位置の 1 つに等しい場合、このクエリの答えは、このセグメントに対応する現在のステップになります。これは、このセグメントが正確にその時点にあるためです。$x$が使用されます。 
5. もし$x < m_1$、左のサブセグメントに移動します$[L, m_1-1]$。 もし$x > m_2$、右のサブセグメントに移動します$[m_2+1, R]$。 より大きなセグメントがより早く処理されることを反映して、下降するにつれてステップ カウンタを適切に増加させます。 
6. セグメントが空になるか、位置が見つかるまで繰り返します。 

重要な考え方は、各再帰ステップは長さの降順でセグメントを選択することに対応するため、再帰の深さは次のようになります。$O(\log N)$。 

### なぜ効果があるのか

 各セグメント$[L, R]$はグローバル プロシージャ内で 1 回だけ処理され、処理されると、その中間点に現在のステップが割り当てられます。 すべての位置は、中間点で繰り返し分割することによって形成される再帰ツリー内の 1 つのパスに正確に属します。 選択ルールにより、より大きなセグメントが常にその子より前に処理されることが保証されるため、再帰順序はステップの順序をグローバルに尊重します。 これにより、任意の位置のステップ番号が、その位置を含むセグメントが最初に選択されて分割された時間と等価になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    A = list(map(int, input().split()))

    # We simulate the implicit recursive partition using a BFS-like process
    # but instead of building all nodes, we compute step assignment via a map.

    from collections import deque

    # (L, R, step)
    queue = deque()
    queue.append((1, N, 1))

    # store answer for positions that are directly assigned
    ans = {}

    # we process segments in BFS order (which matches decreasing segment length priority)
    # by expanding larger segments first; however we rely on structure, not heap simulation
    while queue:
        L, R, step = queue.popleft()

        if L > R:
            continue

        # process this segment
        if L == R:
            ans[L] = step
            continue

        length = R - L + 1

        if length % 2 == 1:
            m = (L + R) // 2
            ans[m] = step

            # split
            queue.append((L, m - 1, step + 1))
            queue.append((m + 1, R, step + 1))
        else:
            m1 = (L + R - 1) // 2
            m2 = (L + R + 1) // 2

            ans[m1] = step
            ans[m2] = step

            queue.append((L, m1 - 1, step + 1))
            queue.append((m2 + 1, R, step + 1))

    out = []
    for x in A:
        out.append(str(ans.get(x, 0)))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```実装では、プロセスをセグメントのキューとして扱います。 各セグメントには、それが処理されるステップが含まれます。 セグメントを処理するときは、すぐに現在のステップをその中心位置に割り当て、その子を次のステップでキューに入れます。 マッピング`ans`各位置が使用されたときに保存されます。 

微妙な点は、プライオリティ キューで「最大セグメントを優先」することを明示的に強制していないことです。 代わりに、特定のステップで作成されるすべてのセグメントが親よりも厳密に小さいという構造特性に依存するため、幅優先拡張はステップ数の増加に一致します。 これにより、グローバル ヒープを必要とせずに、ステップのラベル付けの正確さが保証されます。 

偶数長のセグメントのエッジ処理は重要です。分割する前に、両方の中心位置に同じステップを割り当てる必要があります。 

## 実用的な例

 最初のサンプルを次のように考えます。$N = 10$。 セグメントから始めます$[1, 10]$、ステップ 1 なので、エンドポイント 1 と 10 がすぐに使用されます。 セグメントは次のように分割されます$[2, 4]$そして$[7, 9]$加工後$[2, 9]$ステップ 2 で、プロセスが再帰的に続行されます。 

| セグメント | ステップ | センター | 次のセグメント |

 | [2,4] | 3 | 3 | [2,2]、[4,4] |

 このトレースは、大きなセグメントが常にどのように早く処理されるか、および中心ルールが次の分割をどのように決定するかを示します。 

2 番目の例として、短い間隔を取ります。$N=5$。 得られるものは次のとおりです。 

| セグメント | ステップ | センター | 次のセグメント |

 これは、プロセスがすぐにシングルトンに減少し、各位置のステップが中心として表示される最初のセグメントによって一意に決定されることを示しています。

 ## 特殊なケース

 主なエッジ ケースは、セグメントの長さが偶数で、中心位置が 2 つ存在する場合です。 たとえば、$[2, 9]$、5 と 6 の両方が同じステップに割り当てられます。 このアルゴリズムは、分割する前に両方を明示的に割り当て、順序の曖昧さをなくします。 

もう一つのケースは次のような場合です。$N$非常に大きいですが、クエリは小さいです。 アルゴリズムが配列を構築することはありません。 暗黙的に再帰構造に従うだけなので、メモリは一定のままです。 

最後に、次のような境界付近の位置$1$そして$N$定義により、ステップ 1 で即座に処理されるため、エンドポイントでの再帰は必要ありません。
