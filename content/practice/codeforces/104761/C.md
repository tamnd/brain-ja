 ## 解決策
 ## 問題の理解

 2 つの異なる数字が与えられているので、それらを呼び出します$A$そして$B$それぞれ 0 から 9 までの数字です。他の数字を使用しない限り、これら 2 つの数字だけから、任意の順序および任意の長さでそれらを連結することによって、任意の正の整数を構築することができます。 タスクは、2023 で割り切れる数値を出力することです。また、最大 100 桁であること、ゼロで始まってはいけないというサイズ制約も満たさなければなりません。 

中心的な難しさは、数字から数字を構築することではなく、非常に大きな検索スペースの下で特定の割り算条件に一致する数字を見つけることです。 長さを固定しても、$2^n$したがって、非常に短い長さを超えると、すべての文字列に対するブルート フォースは不可能になります。 

重要な構造上の制約は、ターゲットの係数が固定されており、2023 という小さい値であるということです。これは、2023 + 1 桁より長い数値は最終的に剰余パターンを繰り返す必要があるため、2023 を法とする剰余の観点から考える必要があることを直ちに示唆しています。 

実装を誤解させやすい単純なエッジ ケースは、数字の 1 つが 0 である場合です。たとえば、次のような場合です。$A = 0$そして$B = 7$不注意な構築では 0 から始めようとし、0077... のような無効な先行ゼロが生成される可能性があります。これは、数値的には有効であっても許可されません。 もう 1 つの微妙なケースは、1 つの数字が 0 で、もう 1 つの数字が小さい場合です。 ゼロ以外の数字を繰り返すような貪欲な構成では、有効な混合パターンが存在する場合でも、2023 の倍数に到達しない可能性があります。 

## アプローチ

 強引なアイデアは、アルファベット上のすべての文字列を生成することです$\{A, B\}$生成された文字列ごとに、2023 を法とする値を計算し、それがゼロかどうかを確認します。 すべての候補者を使い果たすので、これは正しいです。 

ただし、候補の数は長さに応じて指数関数的に増加します。 長さ 50 の場合、すでに$2^{50}$実現可能な計算をはるかに超えた可能性があります。 すべての文字列を列挙する場合、モジュロを段階的に計算しても役に立ちません。 

重要な観察は、実際の数値は気にせず、2023 を法とした剰余だけを気にするということです。数字を追加するたびに、新しい剰余は前の剰余と追加された数字にのみ依存します。 これにより、問題は状態に関するグラフ問題に変換されます。$0 \ldots 2022$、各状態は剰余を表し、遷移はいずれかの数字の追加に対応します。$A$または数字$B$。 

これにより、それぞれが 2 つの出力エッジを持つ、最大 2023 個のノードを含む有向グラフが得られます。 有効な最初の数字 (先頭のゼロ以外の数字) から始まり、剰余 0 に達するパスを見つけたいと考えています。グラフは有限であるため、BFS は、解を見つけるか、すべての状態を使い果たすことを保証します。 ソリューションは意図した構築スペースに存在することが保証されているため、BFS は効率的にソリューションを見つけます。

 ## アルゴリズムのチュートリアル

 各状態を、2023 を法とする剰余とこれまでに構築された文字列から構成されるペアとしてモデル化します。 すべての状態の完全な文字列を保存する代わりに、親ポインタを保存して、最後に答えを再構築します。 

1. すべての有効な開始桁を使用して BFS キューを初期化します。 数字がゼロの場合、その数字は最初の文字として使用できないため、ゼロ以外の数字からのみ開始します。 各開始桁は、その桁の 2023 を法とする剰余に等しい初期剰余を提供します。これにより、無効な先行ゼロが生成されることがなくなります。 
2. キュー内の各状態に対して、数字の追加を検討します。$A$と数字$B$。 現在の残りが$r$、数字を追加した後の新しい剰余$d$は$(10r + d) \bmod 2023$。 この繰り返しにより、10 進数がどのように増加するかが正確に把握されます。 
3. どこかの時点で剰余 0 に達した場合は、すぐに停止します。 開始状態からこの状態までのパスは、2023 で割り切れる有効な数値を定義します。 
4. 数値を再構築するには、格納されている親ポインタを 0 の状態から開始点に到達するまで逆方向にたどります。 次に、数字の順序を逆にします。 
5. 再構築された文字列を出力します。 

重要な設計上の選択は、完全な文字列ではなく先行文字のみを保存することです。これにより、メモリの制限が維持され、効率的な再構築が可能になります。 

### なぜ効果があるのか

 各 BFS 状態は、特定の数字シーケンスを持つ 1 つの到達可能な剰余を正確に表します。 10 進数の連結は次のように忠実にモデル化されているため、すべての拡張ステップで剰余計算の正確さが維持されます。$10r + d$。 BFS は桁数を増やしながら状態を探索するため、最初に剰余 0 に到達した時点が有効な構造に相当します。 可能な剰余は 2023 個しかないため、許可された数字アルファベット内に解が存在する場合、BFS は指数長の文字列を明示的に探索する必要なく、その解に遭遇します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

MOD = 2023

def solve():
    A, B = map(int, input().split())
    digits = [A, B]

    # store visited remainders
    prev = [-1] * MOD
    prev_digit = [-1] * MOD
    visited = [False] * MOD

    q = deque()

    # initialize with valid starting digits (no leading zero)
    for d in digits:
        if d == 0:
            continue
        r = d % MOD
        if not visited[r]:
            visited[r] = True
            prev[r] = -2  # start marker
            prev_digit[r] = d
            q.append(r)

    # BFS over remainder states
    while q:
        r = q.popleft()

        if r == 0:
            break

        for d in digits:
            nr = (r * 10 + d) % MOD
            if not visited[nr]:
                visited[nr] = True
                prev[nr] = r
                prev_digit[nr] = d
                q.append(nr)

    if not visited[0]:
        return ""

    # reconstruct answer
    res = []
    cur = 0
    while prev[cur] != -2:
        res.append(str(prev_digit[cur]))
        cur = prev[cur]

    res.append(str(prev_digit[cur]))
    return "".join(reversed(res))

if __name__ == "__main__":
    print(solve())
```BFS は純粋に剰余に基づいて実装されるため、状態空間が小さく保たれます。 配列`prev`そして`prev_digit`完全な文字列を保存せずに再構築を可能にします。 マーカー`-2`ルート状態と中間状態を区別します。
