 ## 解決策
 ## 問題の理解

 時間制限があります`T`ある週末と順序付けられた配列`N`イベントの期間。 各イベントは 1 回だけ承認されることも拒否されることもできます。 受け入れられるイベントの合計期間は最大でも長くなければなりません`T`そして主な目的は、その合計をできるだけ大きくすることです。 同様に、未使用のホール時間を最小限に抑えたいと考えています。 

いくつかの異なるサブセットの最大合計期間が同じである場合、予約順序は同点を破ります。 前のイベントが優先されるため、2 つの有効な選択肢が異なる最初の位置では、前のイベントを含む選択肢が優先されます。 

入力には、いくつかの独立したテスト ケースが含まれています。 それぞれはから始まります`T`そして`N`、続いて`N`期間。 を含む行`0`入力を終了します。 公式声明によると、最大 50 件の予約が可能で、256 MB のメモリで 2 秒の時間制限が与えられます。 レンダリングされたステートメントでは、個別の数値の上限は提供されません。`T`、 それでも`T`動的プログラムの容量ディメンションとして機能するのに十分なほど小さいことを意図していることは明らかです。 

重要な結果は、アルゴリズムが指数関数的に増加することです。`N`は適切ではありません。 と`N = 50`、すでにあります`2^50`、 について`1.13 * 10^15`、可能なサブセット。 2 番目の次元が次のような動的プログラム`T`目標は利用可能な時間によって制限される合計であるため、これは自然な選択です。 

正しく見える実装が失敗する可能性のあるエッジケースがいくつかあります。 

考慮する`5 3 6 7 8`。 どのイベントも利用可能な 5 ユニットよりも長いため、何も選択できません。 正しい出力は次のとおりです`0`。 不注意な再構築ルーチンは、少なくとも 1 つのイベントが選択されたと想定し、無効な継続時間を出力する可能性があります。 

考慮する`10 4 6 4 5 5`。 両方`6 4`そして`5 5`容量を正確に満たします。 正しい出力は次のとおりです`6 4 10`、期間のあるイベントであるため、`6`期間のあるイベントの前に表示されます`5`。 合計を最大化し、最初に見つかったサブセットを保持するだけの実装では、間違った同点決定の選択肢が返される可能性があります。 

考慮する`5 3 1 4 5`。 最良のサブセットは`1 4`、その合計は正確に`5`したがって、出力は次のようになります`1 4 5`。 決勝戦`5`合計です。別の選択されたイベントではありません。 出力されるすべての数値を選択された期間として扱うパーサーまたは再構築ルーチンは、必要な出力形式を誤って解釈する可能性があります。 

## アプローチ

 直接的なアプローチは、`N`イベントの継続時間を計算し、継続時間が超過した場合は拒否します`T`、最大の有効な合計を持つサブセットを保持します。 これは正しいです。考えられるすべての選択が正確に 1 つのサブセットに対応するため、徹底的な検索では最適なものを見逃すことはありません。 サブセットの生成中に合計が段階的に累積される場合、作業は次のようになります。`O(2^N)`サブセット。 と`N = 50`、それは約です`1.13 * 10^15`これは、2 秒のコンテスト プログラムが処理できる範囲をはるかに超えています。 すべてのサブセットもすべてスキャンする場合`N`イベントで合計を計算すると、境界は次のようになります。`O(N * 2^N)`、 だいたい`5.6 * 10^16`最悪の場合の基本的なイベントチェック。 

部分選択に関する意味のある情報は現在の合計期間だけであるため、総当り攻撃が機能します。 同じ残りの容量には多くの異なるサブセットが到達する可能性があり、その容量に対する最適な結果がわかったら、それらの等価な部分状態のすべてを繰り返し探索する必要はありません。 

まさに0/1ナップザックの構造です。 容量ごとに`j`、残っているイベントから達成可能な最長の合計期間を知る必要があるだけです。 イベント用`i`期間付き`a[i]`、可能性は 2 つだけです。スキップして、容量の既存の値を指定します。`j`、またはそれを取る、与える`a[i]`さらに容量の最適な値を実現`j - a[i]`。 

タイブレーク ルールは、この繰り返しに自然に適合します。 予約リストの末尾から先頭に向かってイベントを処理します。 現在のイベントとそれをスキップしても同じ最適な合計が得られる場合は、現在のイベントを選択します。 現在のイベントは、DP 状態によってすでに表されているすべてのイベントよりも早いため、これを含めると、必要な優先度が正確に与えられます。 

数値 DP を 1 次元に保持してメモリを削減しながら、イベントごとに 1 バイトと、そのイベントが選択されたかどうかを記憶する容量を保存できます。 DP はイベントを通じて逆方向に処理され、また容量を通じて逆方向に処理されるため、同じイベントが複数回使用されることが防止されます。

 ## アルゴリズムのチュートリアル

 1. 利用可能時間を読む`T`、イベントの数`N`、および期間配列`a`。 

選択したすべてのイベントはその期間を正確に消費するため、関連する容量値は次のとおりです。`0`を通して`T`。 
2.作成`dp[j]`、最初はゼロ、ここで`dp[j]`容量で達成可能な最適な合計期間を表します`j`これまでに処理されたイベントを使用します。 

イベントを右から左に処理します。 イベント処理前`i`、`dp`その後のイベントのみを説明します`i`これにより、誤って 2 回使用することなく、現在のイベントを追加するかどうかを決定できます。 
3. 作成する`take[i]`容量によってインデックス付けされたバイト配列として。`take[i][j] = 1`つまり、イベントを考慮した後、`i`、容量の最適なソリューション`j`イベントを選択します`i`。 

この情報が必要なのは、最適な合計を知るだけでは、どのイベントがその合計を生成したかを再構築するのに十分ではないためです。 
4. プロセス`i`から`N - 1`まで`0`。 現在の期間については`w = a[i]`、プロセス能力`j`から`T`まで`w`。 

現在のイベントを受けて得られる候補は`dp[j - w] + w`。 代替案は現在です`dp[j]`, これはイベントのスキップに相当します。 
5. 候補者が少なくとも同等の能力を持っている場合`dp[j]`、 交換する`dp[j]`候補者とマーク付き`take[i][j] = 1`。 

の使用`>=`それよりも`>`タイブレークルールの鍵となります。 両方の選択肢が同じ合計を生成する場合、現在のイベントは、元の配列内ですでに表されているすべてのイベントより前にあります。`dp`, したがって、それを選択することが優先されます。 
6. 再構築中に元のイベント配列を順方向に反復処理します。`remaining = T`。 

もし`take[i][remaining]`設定されている、出力される`a[i]`そしてそれをから引きます`remaining`。 それ以外の場合は、イベントをスキップします。 再構築は、DP の構築中に記録された決定に正確に従います。 
7. 最後にアウトプット`dp[T]`選択した合計期間として。 

選択した期間は、再構築中に元の順序ですでに表示されているため、並べ替えや反転は必要ありません。 

### なぜ効果があるのか

 不変条件はイベントを処理する前の条件です`i`、`dp[j]`イベントから取得できる最大合計期間です。`i + 1`を通して`N - 1`せいぜい使用`j`時間。 イベント用`i`、すべての最適解はそれを除外します。これは古いもので表されます。`dp[j]`、またはそれを含み、次のように表されます。`a[i] + dp[j-a[i]]`。 より大きな値を取ると、不変条件が維持されます。 2 つの値が同点の場合、イベントを選択します`i`は正しいです。これは最も古い未解決のイベントであるため、これを含むすべてのソリューションは、それを除外する他の同等のソリューションよりも高い優先順位を持ちます。 降下容量ループにより、次のことが保証されます。`dp[j-a[i]]`依然として後のイベントのみを説明しているため、イベントが 2 回使用されることはありません。 再構築は記録された最適な決定に従い、最大合計と必要な最優先サブセットの両方が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    out = []

    while True:
        line = input().split()
        if not line:
            break

        T = int(line[0])
        if T == 0:
            break

        N = int(line[1])
        a = list(map(int, line[2:]))

        # If input lines are ever wrapped, keep reading until all N durations exist.
        while len(a) < N:
            a.extend(map(int, input().split()))

        # dp[j] = maximum total duration achievable with capacity j
        # using the events processed so far from right to left.
        dp = [0] * (T + 1)

        # take[i][j] tells us whether event i is selected in the
        # optimal solution for capacity j after considering event i.
        take = [bytearray(T + 1) for _ in range(N)]

        for i in range(N - 1, -1, -1):
            w = a[i]

            for j in range(T, w - 1, -1):
                candidate = dp[j - w] + w

                # On equality, prefer the current event because it
                # appears earlier than all events represented by dp.
                if candidate >= dp[j]:
                    dp[j] = candidate
                    take[i][j] = 1

        remaining = T
        selected = []

        for i in range(N):
            if take[i][remaining]:
                selected.append(str(a[i]))
                remaining -= a[i]

        selected.append(str(dp[T]))
        out.append(" ".join(selected))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは一度に 1 つのテスト ケースを読み取り、最初の値が 0 になるとすぐに停止します。 通常、期間はすべて同じ行に表示されますが、テスト ケースが入力行にまたがって物理的にラップされている場合でも、その後に続く小さなループによってパーサーが安全になります。 

の`dp`配列には唯一のものがあります`T + 1`州。 イベントを右から左に処理すると、各状態に後のイベントのみを使用するという意味が与えられますが、処理能力は右から左にあります。`T`downward は、同じイベントで既に更新されている状態から現在のイベントが読み取られるのを防ぎます。 

比較には、`candidate >= dp[j]`。 厳格な`>`それでも正しい最大合計は見つかりますが、必要な予約順序の優先順位を必ずしも満たすわけではありません。 平等は現在の出来事に有利でなければなりません。 

の`take`配列の用途`bytearray`、完全な Python 整数オブジェクトの代わりに状態ごとに 1 バイトを保存します。 これにより、直接インデックス付けが可能になりながら、再構成情報がコンパクトに保たれます。 

復興の中で、`remaining`は、まだ検討されていない出来事によって説明されなければならない能力です。 イベントの場合`i`を差し引いて、その容量に対して選択されたものとして記録されました`a[i]`残りのサフィックスの問題を表す状態に正確に移動します。 再構成は左から右にスキャンするため、出力はすでに予約順になっています。 

Python の整数には、C または C++ の固定幅オーバーフローの問題がなく、すべての DP 値は最大でも`T`選択した合計が容量を超えることはできないためです。

## テストケース```python
import sys
import io

def solution():
    input = sys.stdin.readline
    out = []

    while True:
        line = input().split()
        if not line:
            break

        T = int(line[0])
        if T == 0:
            break

        N = int(line[1])
        a = list(map(int, line[2:]))

        while len(a) < N:
            a.extend(map(int, input().split()))

        dp = [0] * (T + 1)
        take = [bytearray(T + 1) for _ in range(N)]

        for i in range(N - 1, -1, -1):
            w = a[i]
            for j in range(T, w - 1, -1):
                candidate = dp[j - w] + w
                if candidate >= dp[j]:
                    dp[j] = candidate
                    take[i][j] = 1

        remaining = T
        selected = []

        for i in range(N):
            if take[i][remaining]:
                selected.append(str(a[i]))
                remaining -= a[i]

        selected.append(str(dp[T]))
        out.append(" ".join(selected))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solution()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 のために`5 3 6 7 8`、すべての期間が容量を超えています。 内部 DP ループは、どのイベントに対しても実行されません。`w > T`、だからすべて`dp[j]`ゼロのまま`take[i][j]`未設定のままです。 したがって、再構築では何も選択されずに追加されます。`dp[5] = 0`、正確に生産`0`。
