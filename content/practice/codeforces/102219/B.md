 ## 解決策
 ## 問題の理解

 各テスト ケースは、幅を使用して直角の 4 辺形状を記述します。`w`そして高さ`h`。 このような形状はすべてすでに長方形であるため、唯一の問題は、それが 2 つの辺の長さが等しい特別な種類の長方形であるかどうかです。 

もし`w == h`、形状は正方形なので、必要な答えは次のとおりです。`YES`。 2つの寸法が異なる場合、その形状は普通の長方形になりますので、答えは次のようになります。`NO`。 

寸法は次の間の正の整数です。`1`そして`1,000,000`。 値自体は Python の整数に無理なく収まるほど小さいため、オーバーフローの心配はありません。 さらに重要なのは、実際の次元の大きさがアルゴリズムにまったく影響を与える必要がないことです。 決定は 1 つの等価比較のみに依存し、テスト ケースごとに一定の作業が行われます。 テスト ケースの数が多い場合でも、ディメンションのすべてのペアを読み取って分類する必要があるため、テスト ケースの線形スキャンが自然な制限になります。 

エッジケースは単純ですが、それでも明示的に処理する価値があります。 可能な最小の正方形は、`1 1`を生成する必要があります。`YES`。 ディメンションが 1 より大きいかどうかをチェックする不注意な実装では、ディメンションが誤って拒否される可能性があります。 

形状は正方形でありながら非常に大きな寸法を持つことができます。 例えば、`1000000 1000000`生成する`YES`。 重要なのは等しいことだけであっても、誤って小さな固定境界を使用したり、最大値を特別に扱ったりする実装は失敗します。 

次元の順序は関係ありません。 例えば、`3 7`そして`7 3`どちらも長方形であり、どちらも生成されます`NO`。 次のような比較`w < h`または`w > h`どちらの順序も可能であるため、形状だけでは正方形かどうかは決まりません。 

最後に、1 つだけ異なる次元も拒否する必要があります。 のために`5 6`、正しい出力は次のとおりです。`NO`。 次のような off-by-one 条件を使用した実装`abs(w - h) <= 1`誤って正方形として分類されてしまいます。 

## アプローチ

 ブルートフォースソリューションでは、長方形を単位セルの集合として想像し、それが正方形であるかどうかを判断する前に全体の形状を検査することができます。 のために`w × h`長方形、つまり調べることを意味します`w * h`細胞。 このアプローチは正しいです。寸法によって長方形のグリッドが完全に決定されるため、すべてのセルを処理した後に結果の幅と高さを比較できるからです。 ただし、両方の寸法が等しい場合、`1,000,000`、これには正確に必要です`1,000,000,000,000`1 つのテスト ケースのセル検査。 これは、1 秒のコンテスト プログラムが実行できる能力をはるかに超えています。 

ブルートフォースは最終的に形状を記述するすべての情報を処理するため機能しますが、その作業のほとんどすべてが無関係であるため失敗します。 正方形の条件は個々のセルには依存しません。 それは 2 つの辺の長さに直接依存します。 長方形の幅と高さが正確に等しい場合、その長方形は正方形であるという観察により、問題全体が 1 つの整数比較に縮小されます。 

すべてのテストケースについて、以下をお読みください。`w`そして`h`、比較して印刷します`YES`それらが等しいとき、そして`NO`さもないと。 次元の反復や幾何学的な構築はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`なぜなら、すべての形状に対して同じ決定を独立して行う必要があるからです。 
2. 各テスト ケースについて、幅を読み取ります。`w`そして高さ`h`。 
3. 比較する`w`そして`h`。 等しいということは、まさに長方形が正方形になるための数学的条件であるため、他の幾何学的計算は必要ありません。 
4. 印刷`YES`もし`w == h`; それ以外の場合は印刷します`NO`。 各テスト ケースは、入力形状と回答の間に必要な対応関係を維持しながら、出力行を 1 つだけ生成します。 

### なぜ効果があるのか

 このアルゴリズムは、正方形の定義特性、つまり幅と高さが等しいことに依存しています。 すべてのテスト ケースについて、アルゴリズムが出力する場合`YES`、 それから`w == h`, したがって、形状は辺の長さが等しく、正方形になります。 印刷される場合`NO`、 それから`w != h`, そのため辺の長さが異なり、正方形にはなりません。 これら 2 つのケースは、正の次元の考えられるすべてのペアをカバーするため、アルゴリズムは有効な入力を誤って分類できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        w, h = map(int, input().split())
        print("YES" if w == h else "NO")

if __name__ == "__main__":
    solve()
```最初の行は次のように読み取られます`t`、処理されるディメンションのペアの数を正確に制御します。 これにより、ファイルの終わりの動作に依存することがなくなり、入力形式と一致します。 

ループ内では、`map(int, input().split())`2 つの次元を直接整数に変換します。 Python の整数は、指定された最大値を安全に処理します。`1,000,000`したがって、特別な数値型やオーバーフロー処理は必要ありません。 

条件式は、アルゴリズムで説明されているのと同じ比較を実行します。 ディメンションにわたるループを伴う境界ケースがないため、管理する必要のあるオフバイワン条件はありません。 等価比較では次のことも処理されます。`1 1`そして`1000000 1000000`特別な場合がなくても正しく。 

使用する`sys.stdin.readline`要求された高速入力パターンに従います。 この特定の問題では、入力解析はほとんどの競技プログラミング タスクに比べてすでに小さいですが、テスト ケースが多数存在する可能性がある場合には、このアプローチは適切です。

 ## 特殊なケース

 最小サイズの形状の場合、入力`1 1`アルゴリズムを比較させます`1 == 1`これは true なので、出力されます。`YES`。 辺の長さが 1 の正方形を除外する幾何学的理由はなく、アルゴリズムは特別な条件なしでそれを正しく受け入れます。 

最大サイズの正方形の場合、入力`1000000 1000000`も生産します`YES`。 比較は、値の数値サイズに関係なく、定数時間の整数演算のままであるため、上限によってパフォーマンスや正確性の問題が発生することはありません。 

1 だけ異なる次元の場合、入力`5 6`与える`5 == 6`これは false なので、出力は次のようになります。`NO`。 このアルゴリズムは、「ほぼ等しい」次元と等しい次元を混同せず、よくある 1 つ違いの間違いを回避します。 

逆次元の場合、`7 3`生成する`NO`なぜなら`7 != 3`、 そして`3 7`も生産します`NO`なぜなら`3 != 7`。 正方形はどちらの方向でも同じ寸法を持つため、次を使用してペアを正規化する理由はありません。`min`そして`max`比較する前に。 

このアルゴリズムは、同じ不変条件を通じてあらゆるエッジ ケースを処理します。`YES`2 つの辺の長さが同じ場合、正確に印刷されます。 追加の幾何学的計算や特殊な場合の分岐は必要ありません。
