 ## 解決策
 ## 問題の理解

 各テスト ケースは、幅を使用して 1 つの 4 辺形状を記述します。`w`と高さ`h`。 すべての角はすでに直角であるため、正方形と通常の長方形を区別する唯一の問題は、2 つの辺の長さが等しいかどうかです。 

特定の形状の場合、必要な出力は次のとおりです。`YES`いつ`w == h`, 幅と高さが等しいと長方形が正方形になるためです。 2 つの値が異なる場合、出力は次のようになります。`NO`。 

寸法は次の間の正の整数です。`1`そして`1,000,000`。 上限は十分小さいため、単一の整数の比較は簡単ですが、幾何学的シミュレーションを実行したり、可能な辺の長さを列挙したりする理由がないこともわかります。 テスト ケースの数は独立して処理されるため、ケースごとに一定の作業を実行し、ケース数に直線的な時間を与えることが有用な目標となります。 たとえテストケースがたくさんあったとしても、`O(T)`ソリューションでは形状ごとに 1 つの比較のみが実行されますが、形状ごとに最大 100 万回の操作を実行するアプローチでは、1 秒の制限の下ではすぐにコストが高くなりすぎる可能性があります。 

最初のエッジ ケースは、可能な最小の正方形です。 入力用`1 1`、正しい出力は次のとおりです。`YES`。 両方の寸法が 1 より大きいかどうかをチェックする不注意な実装では、たとえ正方形の辺の長さが 1 であっても、誤って拒否されてしまいます。 

もう 1 つのエッジ ケースは、寸法が 1 だけ異なる長方形です。 入力用`7 8`、出力は`NO`。 誤って次のような条件を使用するコード`abs(w - h) <= 1`この形状を誤って受け入れてしまいます。 平等は正確でなければなりません。 

形状が正方形であっても、寸法の向きは変わりません。 入力用`3 10`、答えは`NO`、同様のことが当てはまります`10 3`。 幅と高さを比較する以上に異なる方法で扱うソリューションでは、不必要な方向依存性が生じる可能性があります。 

最後に、最大値が正常に機能する必要があります。 入力用`1000000 1000000`、答えは`YES`。 値は Python 整数に快適に収まるため、特別な数値処理は必要ありません。 

## アプローチ

 問題を解決する強引な方法は、可能な限りすべての辺の長さを試してみることです。`1`を通して`max(w, h)`そして、その候補が図形の共通辺の長さになり得るかどうかを尋ねます。 候補が両方の次元に等しい場合、形状は正方形になります。 候補者全員が疲れ果てているかといえば、そうではありません。 

寸法のある正方形なので、この方法は正しいです。`w`そして`h`可能な共通辺の長さは 1 つだけあります。`w = h`。 ただし、最大で実行できます`1,000,000`候補者は単一のテスト ケースをチェックします。 横切って`T`場合によっては、最悪の作業は`1,000,000T`小切手。 答えがすでに 2 つの入力値に直接エンコードされている場合、この問題はそれほど時間を費やす有効な理由にはなりません。 

重要な観察は、再構築する隠れたジオメトリが存在しないことです。 4 つの直角を持つ四角形は、幅と高さが同じであれば正確に正方形です。 ブルートフォース手法は、最終的には間接的に等価性をテストするため機能しますが、等価性自体が完全な条件であるという観察により、最大 100 万回のチェックを 1 回の比較で置き換えることができます。 

結果として得られるアルゴリズムは各ペアを読み取ります`(w, h)`、2 つの整数を比較し、出力します。`YES`それらが等しい場合と`NO`さもないと。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(T * max(w, h))`、 まで`1,000,000T`小切手 |`O(1)`| 遅すぎる |
 | 最適 |`O(T)`|`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`。 各テスト ケースは 1 つの独立した形状を表すため、ケース間で情報を共有する必要はありません。 
2. すべてのテスト ケースについて、次の内容を読んでください。`w`そして`h`。 これらは、長方形が正方形であるかどうかを決定する 2 つの辺の長さです。 
3. 比較する`w`そして`h`。 もし`w == h`、両方の次元は同じ長さを持ち、これはまさにここで長方形が正方形であるために必要な定義条件です。 
4. 印刷`YES`比較が真の場合、および`NO`さもないと。 入力によって形状に 4 つの直角があることがすでに保証されているため、他の幾何学的計算は必要ありません。 

### なぜ効果があるのか

 処理された形状ごとに、アルゴリズムは正方形であるための必要十分条件をチェックします。 もし`w == h`、長方形の幅と高さが等しいため、正方形となり、アルゴリズムは次のように出力します。`YES`。 もし`w != h`、その 2 つの辺の長さが異なるため、正方形にすることはできず、アルゴリズムは次のように出力します。`NO`。 すべてのテスト ケースはこの正確な条件から直接決定されるため、アルゴリズムは誤った分類を生成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        w, h = map(int, input().split())

        if w == h:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```最初の行は次のように読み取られます`t`、処理されるディメンションのペアの数を正確に制御します。 これは入力形式と一致し、プログラムが誤ってテスト ケースを超えて読み込むのを防ぎます。 

ループ内では、`w`そして`h`整数として解析されます。 唯一の決定は平等性テストです`w == h`、アルゴリズムのウォークスルーから正方形の定義プロパティを直接実装します。 

コードには特別な境界条件は必要ありません。`1`または`1,000,000`。 どちらも通常の整数値であり、Python はオーバーフローすることなくそれらを処理します。 また、アルゴリズムはディメンションを反復したり範囲を使用したりしないため、off-by-one の問題も発生しません。 各テスト ケースには、1 つの比較と 1 つの出力が必要です。 

## 実用的な例

 ## 特殊なケース

 最小サイズの正方形は`1 1`。 アルゴリズムは次のように読み取ります`w = 1`そして`h = 1`、評価します`1 == 1`true として出力されます`YES`。 辺の長さが 1 を超える必要はないため、可能な最小の正方形が正しく受け入れられます。 

ほぼ等しい長方形の場合`7 8`、アルゴリズムは次のように評価します`7 == 8`false として出力されます`NO`。 差が小さいことに基づく不注意な解決策は、これを誤って正方形として分類する可能性がありますが、正方形には近似的な等しいではなく、正確な等しいことが必要です。 

などの逆次元の場合`10 3`、アルゴリズムは次のように評価します`10 == 3`false として出力されます`NO`。 同じ結果が次の場合にも発生します`3 10`。 正方形の条件は幅と高さが対称であるため、その順序は分類に影響しません。 

最大正方形の場合`1000000 1000000`、比較は true と評価され、生成されます。`YES`。 のために`1000000 999999`、 false と評価され、生成されます。`NO`。 これらのケースは、オーバーフロー、反復制限、または特殊なケースなしで上限が直接処理されることを確認します。
