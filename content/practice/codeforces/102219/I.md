 ## 解決策
 ## 問題の理解

 道路は 3 × 10 文字のグリッドで表されます。 ロボタクシーはマークされたセルを占有します`=`、現在の行に沿ってまっすぐ進むことしかできません。 残りのセルは空であるか、次のように表されます。`.`、またはによって表される障害物`H`、`T`、 そして`P`。 

タクシーは決して車線変更や方向転換をしないため、厳密に右側のセルのみを走行します。`=`同じ行にあるものは結果に影響を与える可能性があります。 これらのセルの中で、最初に遭遇する障害物は、タクシーが衝突する障害物です。 前方のすべてのセルが空の場合、タクシーはクラッシュすることなく指定されたスナップショットの最後に到達するため、必要な出力は次のようになります。`You shall pass!!!`。 

次元は固定されており、ちょうど 3 行、ちょうど 10 列があります。 すべてのセルを単純にスキャンした場合でも、文字チェックは 30 文字のみ実行されますが、これは 1 秒の時間制限と 256 MB のメモリ制限の下では無視できる程度です。 二次スキャンや線形スキャンでさえ問題となる可能性のある大きな入力パラメータはありません。 ここでの有用な最適化はパフォーマンスのためには必要ありませんが、問題の構造を明確にします。つまり、タクシーの列がわかれば、他の 2 つの列は無関係になります。 

よくあるエッジケースは、タクシーが最初の列にいることです。 例えば：```
=.........
..........
..........
```正しい出力は次のとおりです`You shall pass!!!`。 タクシーを見つけた後、列 0 ではなく列 1 からチェックを開始する不注意な実装では、この特定のケースは正しく処理されますが、タクシーの前に少なくとも 1 つのセルが必要であると想定しているコードでは、簡単に無効なインデックスが導入されたり、スキャンが完全にスキップされたりする可能性があります。 

もう 1 つのエッジケースは、タクシーのすぐ隣にある障害物です。```
..........
=P........
..........
```答えは、`P`。 障害物は次の列からチェックしなければなりません。 2 つ前からスキャンを開始すると、タクシーが通過したと誤って報告されてしまいます。 

同じ車線に複数の障害物が発生する場合、最初の障害物も重要になります。```
..........
=..H..TP..
..........
```正しい出力は次のとおりです`H`。 タクシーは最初の障害物で衝突するので、後で`T`そして`P`セルは決して以前の答えを置き換えてはなりません。 

最後に、他の車線の障害物は無視する必要があります。 例えば：```
..H.......
=.........
.......T..
```答えは、`You shall pass!!!`。 グリッド全体をスキャンして、`H`、`T`、 または`P`最初に検索をタクシーの列に限定しないと、間違った結果が生成されます。 

## アプローチ

 ブルートフォース ソリューションでは、30 個のセルすべてを検査し、セルの位置を見つけることができます。`=`、次にその行の右側にある道路セルを調べます。 その正しさは移動ルールから直接得られます。つまり、タクシーは自分の列のセルのみを訪問でき、左から右にセルを訪問します。 最悪の場合、これにより最大 30 回のチェックが実行され、その後、タクシーの列に沿って最大 10 回のチェックが実行されます。 これは、この固定入力サイズに対して最大 40 回の定数操作に相当するため、すでに十分に高速です。 

道路の寸法は決して大きくならないため、この強引な方法が、指定された問題に対して遅すぎるという現実的な点はありません。 同じアイデアを道路に一般化すると、`n`列の場合、グリッド全体をスキャンするには時間がかかります`O(n)`固定数の列の場合、タクシーの列のみをスキャンする場合も時間がかかります。`O(n)`。 ここでの区別は、パフォーマンス重視ではなく、主に概念的なものです。 

重要な観察は、次の行を含む行がわかれば、タクシーの将来の経路が完全に決定されるということです。`=`。 他の 2 つの列は衝突に影響を与えることができず、タクシーの左側のセルはすでに追い越されています。 見つけることができます`=`次に、その行に沿って前方のみをスキャンします。 中の最初の文字`H`、`T`、 そして`P`すぐに答えが出ます。 

したがって、最も単純に受け入れられている実装は、最も直接的な実装でもあります。つまり、タクシーを見つけて右に歩き、最初の障害物で停止します。

 ## アルゴリズムのチュートリアル

 1. 道路の 3 行を配列に読み取ります。 タクシーの列が事前にわからないため、グリッドを維持します。 
2. 3 行で文字を検索します。`=`そしてその行と列を記録します。 タクシーの位置は 1 つだけなので、これによって重要な経路が一意に決まります。 
3. タクシーの直後の列から始めて、同じ列に留まりながらセルを 1 つずつ検査します。 スキャンは次から始まります`taxi_column + 1`なぜなら、タクシー自身のセルは障害物ではなく、その前のセルは到達できなくなるからです。 
4. 現在のセルが`H`、`T`、 または`P`、その文字を出力して停止します。 スキャンは左から右に移動するため、必然的にこれがタクシーが遭遇する最初の障害物となります。 
5. 障害物が見つからずにスキャンが列 9 に到達した場合は、印刷します。`You shall pass!!!`。 この時点で、スナップショット内の到達可能なセルはすべてチェックされており、空になっています。 

### なぜ効果があるのか

 中心的な不変条件は、列をチェックする前の条件です。`c`、タクシーの元の位置と列の間の到達可能なすべてのセル`c - 1`検査済みで障害物はありません。 タクシーは元の列の右側にのみ移動するため、このシーケンスの外側にある未チェックのセルが早期のクラッシュを引き起こす可能性はありません。 スキャンで障害物が見つかると、不変式によってその前に障害物が発生しないことが証明され、そのキャラクターがファースト クラッシュになります。 スキャンが何も見つからずに終了した場合、タクシーの残りの経路のすべてのセルは空になるため、スナップショット内でタクシーはクラッシュしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    grid = [input().strip() for _ in range(3)]

    taxi_row = -1
    taxi_col = -1

    for r in range(3):
        for c in range(10):
            if grid[r][c] == '=':
                taxi_row = r
                taxi_col = c
                break
        if taxi_row != -1:
            break

    for c in range(taxi_col + 1, 10):
        if grid[taxi_row][c] in "HTP":
            print(grid[taxi_row][c])
            return

    print("You shall pass!!!")

if __name__ == "__main__":
    solve()
```入力セクションは、道路の固定寸法に一致する 3 行を正確に読み取ります。`strip()`意味のある道路文字を変更せずに改行を削除します。 

ネストされた検索で次のことがわかります。`=`そしてその行と列の両方を保存します。 2番目`break`タクシーを見つけると、現在の行だけでなくすべての行の検索が終了するため、これが必要です。 

衝突スキャンは次の時刻に開始されます。`taxi_col + 1`。 この境界は、実装において最も重要なインデックス作成の詳細です。 タクシーの専用セルは`=`, そのため、それをチェックしても障害物が見つかることはありませんが、間違った後の列からスタートすると、タクシーのすぐ前の障害物をスキップする可能性があります。 

会員テストは`in "HTP"`3 つの個別の比較を必要とせずに、考えられる 3 つの障害をすべて認識します。 障害物が見つかるとすぐに、その文字が出力されて関数が戻り、最後の障害物ではなく最初の障害物を報告するという要件が維持されます。 

大きな値を含む整数演算は使用されないため、オーバーフローは発生しません。 グリッド自体には 30 文字しか含まれていないため、メモリ使用量は実質的に一定になります。
