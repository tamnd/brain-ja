 ## 解決策
 ## 問題の理解

 (N \times N) 個の正方形グリッドがあります。 各セルには、空白スペースを表すドット、または 4 つの矢印のいずれかが含まれます。`>`、`<`、`^`、 そして`v`。 回転すると、セルの位置と各矢印が指す方向の両方が変わります。 

入力により、グリッドと一連の左右の回転が与えられます。 指定された順序ですべての回転を適用した後、グリッドを印刷する必要があります。 グリッドは正方形であるため、同じ方向に 4 回転するごとに元の方向に戻ります。 

グリッドには最大 (1000 \times 1000 = 10^6) 個のセルを含めることができます。 グリッドの読み取りまたは書き込みにはすでに (O(N^2)) の作業が必要であるため、(O(N^2)) より大幅に悪いアルゴリズムは望ましくありません。 回転シーケンスの長さは最大 100 です。つまり、回転ごとにグリッド全体を繰り返しスキャンするには、最大 (100 \times 10^6 = 10^8) 個のセル操作が必要になる可能性があります。 これは、特に各操作にインデックス作成と別のグリッドの構築が含まれるため、Python の 1 秒の制限としては大きいです。 

主なエッジケースは、ポジションを回転させるだけでは十分ではないということです。 矢印自体は回転する必要があります。 たとえば、```
1 R

```正しい結果は```

もう 1 つの簡単な間違いは、方向マッピングを逆にしてしまうことです。 右回転の場合、サイクルは次のようになります。`>`に`v`、`v`に`<`、`<`に`^`、 そして`^`に`>`。 左回転の場合、サイクルは反対方向に進みます。 例えば、```

## アプローチ

 最も直接的な解決策は、すべての回転をシミュレートすることです。 現在のグリッド内の各文字について、新しい位置と新しい矢印の方向を計算し、新しい (N \times N) グリッドに配置します。 時計回りに回転すると、行 (r)、列 (c) のセルが行 (c)、列 (N-1-r) にマップされます。 反時計回りに回転すると、行 (N-1-c)、列 (r) にマッピングされます。 対応する矢印も同時に回転します。 

個々の変換は 1 つの物理的な回転と正確に一致するため、この強引な方法は正しいです。 問題は繰り返し作業の量です。 (N=1000) で回転文字列の長さが 100 の場合、100 回の回転ごとに (10^6) 個のセルを処理して、(10^8) 個のセル変換を行うことができます。 グリッドは 100 万セルしかないため、基本的に 100 回の完全なパスを実行する必要はありません。 

有用な観察は、回転が可能な方向を 4 つだけ構成するということです。 右回転は (+1)、左回転は (-1)、モジュロ 4 です。最初に回転文字列全体を処理し、0 ～ 3 の範囲で 1 つの値 (k) を計算します。その値により、最終的なグリッドを変更する必要があるか、右に 1 回回転するか、180 度回転するか、または左に 1 回回転する必要があるかがわかります。 

たとえば、シーケンス`RRL`は正味の回転 (1+1-1=1) を持っているため、単一の右回転と同等です。 シーケンス`LRRLL`は正味回転 (-1+1+1-1-1=-1) なので、1 回の左回転に相当します。 

正味の回転がわかったら、グリッドを 1 回だけスキャンして、最終的な方向を直接構築します。 個々の回転は簡単にシミュレートできるため、ブルート フォースは機能しますが、同じ 100 万個のセルが何度も処理されると失敗します。 正方形の回転の周期性により、シーケンス全体を 4 つの変換の 1 つで置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2 \lvert S\rvert)) | (O(N^2)) | 最悪の場合は遅すぎる |
 | 最適 | (O(N^2 + \lvert S\rvert)) | (O(N^2)) | 承認済み |

 ここで (S) は回転文字列です。 

## アルゴリズムのチュートリアル

 1. (N)、回転文字列、および (N) 個のグリッド行を読み取ります。 最終的な表現では元のすべてのセルが異なる位置に配置される可能性があるため、グリッドを保存する必要があります。 
2. 変数を開始する`turns`ゼロで。 あらゆる人にとって`R`、1 つ追加し、すべての`L`、1を引きます。 結果をモジュロ 4 で削減します。結果の値は、すべての回転が構成された後に重要となる回転シーケンスに関する唯一の情報を表します。 
3. もし`turns == 0`、元のグリッドを出力します。 合計の回転は 360 度の倍数であるため、セルを変換する必要はありません。 
4. もし`turns == 1`、時計回りの回転を直接作成します。 オリジナルのセル`(r, c)`に移動します`(c, N - 1 - r)`。 矢印も時計回りに回した方向に変わります。 
5. もし`turns == 2`、グリッドを 180 度回転します。 オリジナルのセル`(r, c)`に移動します`(N - 1 - r, N - 1 - c)`。 各矢印は反対方向に変わります。 
6. もし`turns == 3`、結果を反時計回りの 1 回転として扱います。 元のセル`(r, c)`に移動します`(N - 1 - c, r)`、矢印が反時計回りに回転します。 
7. 結果の行を印刷します。 すべての元のセルには 1 つの宛先が割り当てられるため、結果のグリッドは (N \times N) のままになります。 

方向変換は小さなルックアップ テーブルで表すことができます。 時計回りの場合は、`>`になる`v`、`v`になる`<`、`<`になる`^`、 そして`^`になる`>`。 ドットはどの回転でも変化しません。 ルックアップ テーブルを使用すると、特殊なケースの長い連鎖が回避され、4 方向の変換が明示的に行われます。 

### なぜ効果があるのか

 不変条件は、回転文字列の接頭辞を処理した後、`turns`元のグリッドに対する現在のグリッドの方向を、4 分の 4 回転を法として正確に表します。 右回転は (+1) に寄与し、左回転は (-1) に寄与するため、これらの値を加算すると、実際に合成された方向が保持されます。 

最終的には 4 つの方向のみが可能です。 これら 4 つの方向のそれぞれについて、アルゴリズムはその回転の正確な座標変換を使用し、一致する方向変換をすべての矢印に適用します。 したがって、すべての元のセルは、要求されたすべての回転後の位置に正確に到達し、その向きも物理的な回転と一致します。 したがって、出力は一度に 1 つずつ回転を実行した場合と同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rotate_char(ch, turns):
    if ch == '.':
        return '.'

    if turns == 1:
        return {
            '>': 'v',
            'v': '<',
            '<': '^',
            '^': '>'
        }[ch]

    if turns == 2:
        return {
            '>': '<',
            '<': '>',
            '^': 'v',
            'v': '^'
        }[ch]

    if turns == 3:
        return {
            '>': '^',
            '^': '<',
            '<': 'v',
            'v': '>'
        }[ch]

    return ch

def solve():
    n, rotations = input().split()
    n = int(n)

    grid = [input().rstrip('\n') for _ in range(n)]

    turns = 0
    for ch in rotations:
        if ch == 'R':
            turns += 1
        else:
            turns -= 1

    turns %= 4

    if turns == 0:
        sys.stdout.write('\n'.join(grid) + '\n')
        return

    ans = [['.'] * n for _ in range(n)]

    for r in range(n):
        for c in range(n):
            ch = grid[r][c]
            ch = rotate_char(ch, turns)

            if turns == 1:
                nr = c
                nc = n - 1 - r
            elif turns == 2:
                nr = n - 1 - r
                nc = n - 1 - c
            else:
                nr = n - 1 - c
                nc = r

            ans[nr][nc] = ch

    sys.stdout.write('\n'.join(''.join(row) for row in ans) + '\n')

if __name__ == "__main__":
    solve()
```入力は次のように読み取られます`readline`、競技プログラミングの入力に必要です。 各行の改行のみが削除されるため、ドットと矢印文字は変更されません。 

の`turns`変数は、完全な回転シーケンスを 4 つの状態に圧縮します。 Python のモジュロ演算は負の値を正しく処理するため、右回転よりも左回転が多いシーケンスでも 0 から 3 の値が生成されます。 

座標式は、正方行列の標準的な変換です。 時計回りの場合は、`(r, c)`になる`(c, n - 1 - r)`。 180 度の場合、両方の座標が反映されます。 反時計回りの場合は、`(r, c)`になる`(n - 1 - c, r)`。 

個々の宛先セルを割り当てる必要があるため、回答はリストの変更可能なリストとして保存されます。 元のグリッドは変更されずに維持されるため、すでに回転したセルが別の変換のソースとして使用されるのを防ぎます。 

唯一の算術演算には 1000 で区切られたインデックスが含まれるため、整数オーバーフローの懸念はありません。境界式`n - 1 - r`それも意図的です。 使用する`n - r`次のインデックスが生成されます`n`いつ`r`はゼロ、つまりグリッドの外側にあります。 

文字変換はセルの位置とは無関係です。 点は点のままですが、各矢印は、どこに表示されるかに関係なく、同じ回転サイクルに従います。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N^2 + \lvert S\rvert)) | 回転文字列が 1 回スキャンされ、すべてのグリッド セルが 1 回変換されます。 |
 | スペース | (O(N^2)) | 入力グリッドと出力グリッドにはそれぞれ (N^2) 個のセルが含まれています。 |

 (N \le 1000) の場合、グリッドには最大 100 万個のセルが含まれます。 100 万セルにわたるシングルパスは 1 秒の制限に適していますが、ブルートフォースの上限である 1 億回の変換は不必要にコストがかかります。 メモリ使用量も、100 万文字のグリッドとその出力表現で 256 MB を快適に下回ります。
