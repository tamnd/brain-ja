 ## 解決策
 ## 問題の理解

 私たちには 2 列 (n 人) の兵士がいます。 マッチングでは、最初の行のすべての兵士に対して 2 番目の行から正確に 1 人の兵士が選択され、すべての 2 行目の兵士が 1 回だけ使用されます。 したがって、答えは、最初の行の兵士 (i) が 2 行目の兵士 (p_i) と一致し (|i-p_i|\le e)、明示的に禁止されているペア ((u_i,v_i)) が使用されないような、(1,\ldots,n) の有効な置換 (p) の数です。 

興味深い制限は、(e) が小さいということだけではありません。 それは、すべての兵士 (i) は短い間隔 ([i-e,i+e]) でのみ 2 列目の位置と対話できると述べています。 (e\le4) なので、第 1 列の兵士には最大で (9) 個の関連する第 2 列の位置が存在します。 第一列の兵士の数は (2000) に達する可能性があるため、多項式アルゴリズムが必要です。 (O(n^2)) アルゴリズムにはすでに約 400 万の基本演算があり、これは妥当ですが、(n) で指数関数的なものは不可能です。 小さな定数 (e) は、サイズが (n) ではなく (e) に​​依存する指数状態空間を維持できるようにする機能です。 

単純な実装は境界で失敗する可能性もあります。 たとえば、```
1 0 0
```一致するものが 1 つだけあるため、答えは (1) になります。 位置 (i-e、\ldots、i+e) がすべて存在すると盲目的に仮定する DP は、存在しない 2 列目の兵士を誤って使用可能として扱う可能性があります。 

もう一つの境界ケースは、```
2 1 0
```答えは(2)です。 (1\to1,2\to2) と (1\to2,2\to1) の両方の一致が可能です。 スライディング ウィンドウを不注意に実装すると、ウィンドウが右端を超えたときにこれらの状態のいずれかが失われる可能性があります。 

禁止されたペアは、対応する最初の列の兵士が処理される場合にのみ適用する必要があります。 例えば、```
2 1 1
1 2
```(1\to1,2\to2) は有効なままですが、(1\to2,2\to1) のマッチングは禁止されているため、答えは (1) です。 禁止されたペアが DP の正しい行に接続されずにグローバルに保存されている場合、間違った遷移を簡単に削除できます。 

(e=0) の場合も構造が異なります。 と```
3 0 0
```答えは (1) です。なぜなら、すべての兵士にはパートナー候補が 1 人だけいるからです。 少なくとも 2 つの候補位置を想定した状態遷移の実装では、無効な遷移が発生したり、1 ビット マスクが誤って処理されたりする可能性があります。 

## アプローチ

 最も直接的な総当りの解決策は、一度に 1 人の一致する最前列兵士を構築します。 兵士 (i) については、(|i-j|\le e) を満たすすべての 2 行目の兵士 (j) を試し、(j) がすでに使用されているかどうかをチェックし、再帰的に続行します。 すべて (n 人) の兵士が処理されると、完全に一致するものが 1 つ見つかります。 

これは正しいです。なぜなら、考えられるすべての一致は、正確に 1 つの選択肢のシーケンスに対応しており、距離制限、禁止されたペア、または 2 列目の兵士がすべて 1 回使用されるという要件に違反する場合に、再帰によって選択肢が拒否されるからです。 

問題は、調査される州の数です。 各兵士の候補者は最大でも (2e+1\le9) 個ですが、再帰的検索には (9^n) という指数関数的な上限があります。 (n=2000) の場合、その限界は (9^{2000})、およそ (10^{1908}) であり、実際の操作数をはるかに超えています。 すべて (n!) 個の順列を生成するさらに単純な総当たりアプローチでは、約 (n\cdot n!) 個のペア チェックが実行され、これはさらに悪いことです。 

兵士の法的パートナーが地元にいるため、総当り攻撃が機能しますが、同じ部分的な状況を繰り返し再計算します。 すでに兵士 (1,\ldots,i-1) を処理しているとします。 将来の兵士のために、どの二列目の兵士が使用されたかという完全な履歴を覚えておく必要はありません。 現在のローカル間隔内のどの位置が占有されているかを知る必要があるだけです。 

重要な観察は、将来の第一列の兵士は、(e) 個以上後ろの第二列の位置を使用することは決してできないということです。 ソルジャー (i) からソルジャー (i+1) に移動すると、現在のウィンドウの左端の位置がウィンドウから永久に外れます。 すでに一致しているはずです。 同時に、新しいポジションが 1 つだけウィンドウに入ります。 

これにより、スライディング ウィンドウ ビットマスク DP が得られます。 ウィンドウには (2e+1) 個の位置があり、最大で (9) 個あります。

 ## アルゴリズムのチュートリアル

 1. 現在の 1 列目の兵士 (i) の周囲に (2e+1) 個の 2 列目の位置のスライディング ウィンドウを定義します。 ビット (b) は位置を表します

 [
 j=i-e+b。 
】

 ビットが (1) に等しい場合は、以前に一致したか、実際の範囲 (1,\ldots,n) の外側にあるために、この位置がすでに使用できないことを意味します。 配列の外側の位置をすでに占有されているものとして扱うと、配列の両端で同じ遷移ロジックが機能するようになります。 

1. 兵士 (1) を処理する前に、ウィンドウの初期マスクを構築します。 

[
 1-e、\ldots、1+e。 
】

 (1) より下のすべての位置は占有済みとしてマークされます。 すべての実際の位置は、すでに問題によって除外されていない限り、最初は自由ですが、禁止されたペアは、最初に占有されている位置としてではなく、移行制限として処理されます。 

1. すべての最前列兵士 (i) に対して、ビットマスクを構築します。`allowed`(1\le j\le n)、(|i-j|\le e)、および ((i,j)) が禁止されていない、現在のウィンドウ内の位置 (j) を含みます。 
2. 到達可能な DP マスクごとに、次のコマンドを使用して空き候補位置を見つけます。 

[
 \text{選択肢}=\text{許可}\ &\ \sim\text{マスク}。 
】

 すべてのセットがビットインします`choices`兵士 (i) のパートナー候補の 1 人を表します。 そのビットを選択することは、現在の状態によって表されるすべての部分一致の可能な拡張を 1 つ作成することに対応します。 

1. パートナーを選択した後、結果のマスクの左端のビットを確認します。 一番左の位置は (i-e) です。 兵士 (i) が一致すると、将来の最前列の兵士はそのポジションを使用できなくなります。 したがって、そのビットがまだ 0 の場合、部分一致は決して完全にはならず、破棄する必要があります。 

これは、スライディング ウィンドウ DP の中心的な妥当性チェックです。 これにより、特定の 2 列目のポジションを合法的に使用できる最後の 1 列目の兵士を超えて試合を延期することができなくなります。 

1. マスクを右に 1 ビットシフトします。 古い位置 (i-e) が消え、残りのすべての位置が左方向に 1 ビット移動し、新しい位置 (i+e+1) が最上位ビットに入ります。 

新しい位置が (n) より大きい場合、実際の 2 行目の外側にあるため、そのビットは (1) として挿入されます。 それ以外の場合は、以前の兵士はこの新しく導入された位置を使用できなかったため、(0) として挿入されます。 

1. 結果のマスクの部分一致の数を次の DP 配列に格納します。 すべての加算はモジュロ (10^9+7) で実行されます。 
2. すべて (n) 個の最初の列の兵士を処理した後、有効な最終状態はすべて 1 のマスクだけになります。 実際の 2 行目の位置はすべて使用されている必要がありますが、(1,\ldots,n) の外側のすべての位置も占有済みとしてマークされます。 この状態の値が必要な答えです。 

### なぜ効果があるのか

 第一列の兵士 (1,\ldots,i) を処理した後の DP 不変式は次のようになります。`dp[mask]`現在のウィンドウ内の使用済みおよび使用不可の 2 行目の位置が次のように記述されている兵士の部分一致を正確にカウントします。`mask`。 すでにウィンドウから出たポジションはもう必要ありません。遷移では、出ていくポジションを破棄する前に占有することが明示的に要求されます。 すべての法的パートナーは 1 つの空き許可ビットで表されるため、すべての有効な部分一致には、重複のない、遷移によって表される可能な継続が正確に含まれます。 最終的に、すべて 1 の状態は、実際の 2 列目の兵士がすべて 1 回だけ一致したことを意味するため、その数は正確に完全に有効な一致の数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, e, k = map(int, input().split())

    # bad[i] is a bitmask of second-row positions forbidden for first-row i.
    bad = [0] * (n + 1)

    for _ in range(k):
        u, v = map(int, input().split())
        # v is relevant only if it can be within e of u.
        d = v - (u - e)
        if 0 <= d <= 2 * e:
            bad[u] |= 1 << d

    width = 2 * e + 1
    states = 1 << width
    top_bit = 1 << (width - 1)
    full = states - 1

    # For every first-row position, build the set of legal real
    # second-row positions in its current window.
    allowed = [0] * (n + 1)

    for i in range(1, n + 1):
        mask = 0
        base = i - e
        for b in range(width):
            j = base + b
            if 1 <= j <= n and not (bad[i] >> b & 1):
                mask |= 1 << b
        allowed[i] = mask

    # Initial window for i = 1 is [1-e, 1+e].
    # Positions <= 0 are outside the array, so mark them occupied.
    start_mask = 0
    base = 1 - e
    for b in range(width):
        j = base + b
        if j < 1 or j > n:
            start_mask |= 1 << b

    dp = [0] * states
    dp[start_mask] = 1

    for i in range(1, n + 1):
        cur_allowed = allowed[i]
        out_of_range = i + e + 1 > n

        ndp = [0] * states

        for mask, ways in enumerate(dp):
            if ways == 0:
                continue

            choices = cur_allowed & ~mask

            while choices:
                bit = choices & -choices
                choices -= bit

                used = mask | bit

                # The position leaving the window must already be used.
                if (used & 1) == 0:
                    continue

                new_mask = used >> 1

                # Introduce position i+e+1.
                if out_of_range:
                    new_mask |= top_bit

                ndp[new_mask] = (ndp[new_mask] + ways) % MOD

        dp = ndp

    print(dp[full] % MOD)

if __name__ == "__main__":
    solve()
```の`bad`配列は、禁止された 2 行目の位置をローカル ビットとして保存します。 禁止されたペア ((u,v)) の場合、行 (u) のウィンドウのビット (0) が (u-e) を表すため、ビット位置は (v-(u-e)) になります。 これにより、禁止エッジのチェックが一定時間行われます。 

の`allowed`配列は事前に計算されるため、メイン DP ループは距離条件を繰り返しテストしたり、禁止されたペア構造を検索したりしません。 各ウィンドウには最大 9 つの位置が含まれるため、これらすべてのマスクを構築するコストは (O(ne)) だけです。 

最初のウィンドウは (1) より小さい位置まで拡張されるため、最初のマスクには特別な処理が必要です。 このような位置は選択できないため、ビットは (1) から始まります。 新しい位置が右から入力される場合も同じ考え方が使用されます。一度 (i+e+1>n) になると、新しいビットが (1) として挿入されます。 

表現`choices = cur_allowed & ~mask`まだ使用されていないすべての法的立場を分離します。 ループ`bit = choices & -choices`9 ビットすべてを再度スキャンすることなく、一度に 1 つの候補を抽出します。 

送信ビットのチェックは、新しく選択したパートナーを追加した後に実行する必要があります。 発信ビットが 0 の場合、現在の兵士は到達不能になりそうな 2 列目の位置と一致できませんでした。 このような状態では完全な一致は得られません。 

Python の整数はオーバーフローしませんが、DP 値は加算のたびにモジュロ (10^9+7) で減算されます。 前の層のみが必要なため、すべて (n) 個の層を保持する代わりに 2 つの配列が使用されます。
