 ## 解決策
 ## 問題の理解

 2 つの兵士の列があり、それぞれに (1) から (n) までの位置が含まれています。 最初の列の位置 (i) の兵士は、2 番目の列のちょうど 1 人の兵士とペアになる必要があります。 通常、(|i-j|\le e) の場合、ペア ((i,j)) が許可されますが、追加のペアの一部は明示的に禁止されています。 

したがって、完全なペアリングは (1,\ldots,n) の順列 (p) であり、最初の行の兵士 (i) が 2 行目の兵士 (p_i) とペアになります。 距離制限とすべての明示的な禁止ペア制限 (モジュロ (10^9+7)) の両方を満たす順列をカウントする必要があります。 

重要な制約は (e\le4) です。 (n) の値は (2000) に達する可能性があるため、(n) に二次関数以上依存する解法は、1 秒の制限の下ではすでに不快ですが、階乗は完全に不可能です。 ただし、(e) の値が小さいということは、各兵士が他の列の最大 (2e+1\le9) 位置とのみ対話できることを意味します。 この制限された相互作用範囲により、小さなビットマスク状態が可能になります。 

不注意な実装により、無効なペアが黙ってカウントされる可能性がある境界ケースがいくつかあります。 (e=0) の場合、すべての兵士にはパートナー候補が 1 人だけ存在することになります。```
1 0 0
```生産しなければならない```
1
```その間```
1 0 1
1 1
```生産しなければならない```
0
```禁止リストを距離制限とは別に扱うソリューションでは、2 番目のケースで ID ペアを誤ってカウントする可能性があります。 

兵士の周囲の通常のウィンドウが範囲 (1,\ldots,n) の外側に広がっているため、行の先頭と末尾も特別です。 例えば、```
2 1 0
```には ((1,1),(2,2)) と ((1,2),(2,1)) という 2 つの有効な組み合わせがあるため、答えは (2) になります。 ウィンドウ内のすべての位置を実際の兵士であると単純に想定するマスク実装では、存在しない位置をパートナー候補として導入できます。 

最後に、禁止されたペアは、単にマスク内の位置と照合するだけでなく、処理される実際の兵士と照合する必要があります。 のために```
2 1 1
1 2
```制限のない答えは (2) ですが、ペアリング (1\to2) は禁止されており、有効なペアは 1 つだけ残ります。 列が未使用かどうかだけをチェックし、禁止された関係を無視する遷移では、(1) ではなく (2) が生成されます。 

## アプローチ

 直接的なアプローチは、2 行目の (n) 人の兵士のすべての順列を生成することです。 各順列について、すべて (n) のペアを検査し、距離条件と禁止ペア条件を検証します。 これは正しいです。2 つの行間の完全な一致はすべて、正確に 1 つの順列に対応するからです。 

問題は順列の数です。 それらは (n!) 個あり、1 つの順列をチェックするには (O(n)) 時間がかかるため、最悪の場合の作業は (O(n\cdot n!)) になります。 (n=2000) では、これは (2000\cdot2000!) 個のペア チェックを意味し、試行できる量をはるかに超えています。 

ブルートフォース手法は、マッチング履歴全体を保持するため機能します。 より小さい状態を可能にする観察は、兵士を左から右に処理する場合、兵士 (i) は (i-e) から (i+e) までの列のみを使用できるということです。 十分に右に移動すると、古い列を再度使用することはできなくなります。 この狭い移動ウィンドウ内のどのポジションがすでに占有されているかを覚えておく必要があるだけです。 

そのウィンドウには (2e+1) 個の位置があり、最大で (9) 個です。 最大 (9) ビットを含むビットマスクで占有状態または空き状態を表現し、最大 (2^9=512) 個の状態を与えることができます。 各最前列の兵士について、ウィンドウ内の各自由位置を試し、禁止されたペアを拒否し、ウィンドウを 1 つ右の位置に移動します。 

この移行により、最終的にはすべての 2 列目の兵士が使用されるように強制する方法も得られます。 ウィンドウが移動すると、その左端の位置が永久に消えます。 その位置が実際の兵士であり、そのビットがまだ 0 である場合、部分一致は決して完全にはならないため、状態を破棄します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\cdot n!)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\cdot 2^{2e+1}\cdot(2e+1)+k)) | (O(2^{2e+1}+k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 列目の兵士 (i) の現在のウィンドウを 2 列目の位置として表現します。 
[
 i-e、\ i-e+1、\ldots、i+e。 
】
 マスクのビット (b) は位置 (i-e+b) に対応します。 ビットが設定されている場合は、その位置がすでに占有されていることを意味し、ビットが設定されていない場合は、その位置がまだ使用可能であることを意味します。

(1,\ldots,n) の外側の位置は、すでに占有されているものとして扱われます。 彼らは本物の兵士ではないため、彼らを選ぶ移行は決して許可されません。 
2. すべての最前線の兵士に対して禁止されたビットマスクを作成します。 ((u,v)) が禁止されており、(v) が (u) のウィンドウ内にある場合は、(v) に対応するビットを設定します。 その後、遷移では 1 ビット操作を使用して、明示的に禁止されたすべての選択を拒否できます。 
3. 兵士を処理する前にマスクを初期化します (1)。 その窓口は、
 [
 1-e、\ldots、1+e。 
】
 (1) より下のすべての位置と (n) より上のすべての位置は、実際の兵士に対応していないため、占領された状態で開始されます。 このマスクの初期 DP の値は (1) です。 
4. 各最前列の兵士 (i) について、到達可能なすべてのマスクを反復処理します。 ゼロ ビット (b) ごとに、兵士 (i) とのペアを検討します。 
[
 j=i-e+b。 
】
 これはまさに (|i-j|\le e) を満たすパートナーのセットであるため、有効なパートナーが失われることはありません。 
5. ビット (b) がすでに占有されている場合、または対応するペア ((i,j)) が禁止されている場合は、遷移を拒否します。 それ以外の場合は、ソルジャー (j) が使用されるため、ビット (b) を設定します。 
6. 次の行に移動する前に、左端のビットを設定する必要があります。 左端のビットは位置 (i-e) を表します。 兵士 (i) を処理した後、この位置は今後のウィンドウに表示されなくなります。 それが未使用の本物の兵士である場合、後でそれを照合する機会はないため、部分的な照合は破棄されなければなりません。 
7. マスクを 1 ビット右にシフトして、(i) の周囲のウィンドウから (i+1) の周囲のウィンドウに移動します。 新しい右端の位置は (i+e+1) です。 (n) より大きい場合は、存在しない位置であるため、すぐにそのビットを設定します。 それ以外の場合は、新品未使用の本物の兵士であるため、未設定のままにしておきます。 
8. 兵士 (n) が処理された後、実際の 2 列目の位置はすべて、占有が確認された後にのみ移動ウィンドウからすでに離れています。 残りのポジションはすべて列の外側にあり、占有済みとしてマークされます。 したがって、すべてのビットが設定された完全なマスクは、完全なマッチングを正確に表します。 そのDP値が答えです。 

### なぜ効果があるのか

 不変条件は、最初の (i) ソルダーを処理してウィンドウをシフトした後、現在のウィンドウの左端点より小さい実際の 2 行目の位置がすべて 1 回だけ使用されている一方で、マスクはウィンドウ内にまだ表示されているどの位置がすでに使用されているかを正確に記録することです。 トランジションは、兵士 (i) に対して未使用の許可されたパートナーを 1 つ選択するため、すべての有効な部分一致を 1 回だけ拡張します。 送信ビットをチェックすることで、未使用の兵士が永久に消えるのを防ぎます。 将来の兵士は距離 (e) 内でしか接続できないため、現在のウィンドウ外の情報は将来の決定に影響を与えることはできません。 したがって、生き残っているすべての DP 状態は有効な部分一致を表し、すべての有効な完全一致は完全なマスクへの遷移の 1 つのシーケンスに正確に従います。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, e, k = map(int, input().split())

    width = 2 * e + 1
    states = 1 << width
    full = states - 1
    top_bit = 1 << (width - 1)

    # banned[i] has a bit set for every forbidden second-row
    # position inside the window of first-row soldier i.
    banned = [0] * (n + 1)

    for _ in range(k):
        u, v = map(int, input().split())

        # Pairs outside the distance window can never be used anyway.
        if abs(u - v) <= e:
            bit = v - (u - e)
            if 0 <= bit < width:
                banned[u] |= 1 << bit

    # Before processing row 1, the window is [1-e, 1+e].
    # Positions outside [1,n] are considered already occupied.
    initial = 0
    for bit in range(width):
        col = 1 - e + bit
        if col < 1 or col > n:
            initial |= 1 << bit

    # For every mask, precompute which free bits can be selected,
    # together with the mask before inserting the new rightmost bit.
    transitions = [[] for _ in range(states)]

    for mask in range(states):
        free = full ^ mask
        while free:
            bit = free & -free
            free -= bit

            new_mask = mask | bit

            # The outgoing position must already be occupied.
            if new_mask & 1:
                transitions[mask].append(
                    (bit, new_mask >> 1)
                )

    dp = [0] * states
    dp[initial] = 1

    for i in range(1, n + 1):
        ndp = [0] * states
        forbidden = banned[i]

        # The new rightmost position after this transition.
        new_col = i + e + 1
        new_col_is_virtual = new_col > n

        for mask, value in enumerate(dp):
            if value == 0:
                continue

            for bit, shifted in transitions[mask]:
                if forbidden & bit:
                    continue

                nxt = shifted
                if new_col_is_virtual:
                    nxt |= top_bit

                x = ndp[nxt] + value
                if x >= MOD:
                    x -= MOD
                ndp[nxt] = x

        dp = ndp

    print(dp[full] % MOD)

if __name__ == "__main__":
    solve()
```入力フェーズは、すべての禁止されたペアを、対応する行のローカル ウィンドウ内のビットに変換します。 すでに距離制限の外にある禁止されたペアは、いずれにしても有効なマッチングに参加できないため、無視できます。 

の`initial`マスクは左側の境界を処理します。 たとえば、(e=2) の場合、最初のウィンドウは ([-1,0,1,2,3]) であるため、最初の 2 つの位置は仮想であり、ビットが設定された状態で始まります。 

事前に計算された`transitions`配列には、すべてのマスク遷移の構造部分が含まれます。 現在の入力行に依存する唯一の条件は、選択されたビットが禁止されているかどうかです。 これら 2 つの部分を分離すると、すべて (n) 行に対して同じマスク遷移を繰り返し再構築することが回避されます。 

小切手`new_mask & 1`が重要な正確性の条件です。 現在の兵士がマッチングされると、一番左の列が消えようとしています。 すでに占領されている必要があります。そうでない場合は、将来の最前線の兵士はそこに到達できません。 

新しい右端のビットは、新しい位置が (n) より大きい場合にのみ設定されます。 このような位置は実際の 2 行目の外側にあり、決して選択してはなりません。そのため、その位置に占有マークを付けることは、考慮から削除することと同じです。 

Python の整数はオーバーフローしませんが、すべての DP 加算は依然として減算法 (10^9+7) です。 この実装では 2 つの 1 次元配列を使用するため、メモリはマスク数の (n) 倍ではなく、マスク数のみに依存します。 

## 実用的な例

 サンプル 1 の場合、```
2 1 0
```有効な完全一致が 2 つあります。 ここでは (e=1)、各マスクには 3 ビットがあります。 最初のウィンドウは ([0,1,2]) で、位置 (0) は仮想です。 

| 最前列の兵士 | 現在のマスク | 選択された列 | シフト後のマスク | 意味 |
 | --- | --- | --- | --- | --- |
 | 1 |`001`| 1 |`101`| 列 1 が使用されます |
 | 1 |`001`| 2 |`110`| 列 2 が使用されます |
 | 2 |`101`| 2 |`111`| 列 1 と 2 が使用されます。 
| 2 |`110`| 1 |`111`| 列 1 と 2 が使用されます。 

2 つの分岐は 2 つの順列に正確に対応します。 どちらもマスクで終了`111`, したがって、答えは(2)です。 このトレースは、仮想位置が占有された状態で開始される必要がある理由と、最終状態が完全なマスクである理由も示しています。 

サンプル 2 の場合、```
2 1 1
1 2
```1 行目の位置 (1) と 2 行目の位置 (2) の組み合わせは禁止されています。 

| 最前列の兵士 | 現在のマスク | 候補者 | 結果 |
 | --- | --- | --- | --- |
 | 1 |`001`| 列 1 | 受け入れられました、次のマスク`101`|
 | 1 |`001`| 列 2 | 禁止されたマスクによって拒否されました |
 | 2 |`101`| 列 2 | 受け入れられた、最終マスク`111`|

 ID の一致のみが存続します。 答えは(1)です。 このトレースは、DP 遷移が追加される前に、禁止ペア マスクが選択されたパートナーに適用されていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
# This test harness assumes solve_data is the same algorithm as the
# solve() function above, but accepts a string and returns the answer.

import io
import sys

MOD = 1_000_000_007

def solve_data(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    e = int(next(it))
    k = int(next(it))

    width = 2 * e + 1
    states = 1 << width
    full = states - 1
    top_bit = 1 << (width - 1)

    banned = [0] * (n + 1)

    for _ in range(k):
        u = int(next(it))
        v = int(next(it))
        if abs(u - v) <= e:
            bit = v - (u - e)
            if 0 <= bit < width:
                banned[u] |= 1 << bit

    initial = 0
    for bit in range(width):
        col = 1 - e + bit
        if col < 1 or col > n:
            initial |= 1 << bit

    transitions = [[] for _ in range(states)]

    for mask in range(states):
        free = full ^ mask
        while free:
            bit = free & -free
            free -= bit
            new_mask = mask | bit
            if new_mask & 1:
                transitions[mask].append((bit, new_mask >> 1))

    dp = [0] * states
    dp[initial] = 1

    for i in range(1, n + 1):
        ndp = [0] * states
        forbidden = banned[i]
        virtual_right = i + e + 1 > n

        for mask, value in enumerate(dp):
            if value == 0:
                continue

            for bit, shifted in transitions[mask]:
                if forbidden & bit:
                    continue

                nxt = shifted
                if virtual_right:
                    nxt |= top_bit

                ndp[nxt] = (ndp[nxt] + value) % MOD

        dp = ndp

    return str(dp[full])

 ## 特殊なケース

 (e=0) の場合、すべての 1 列目の兵士は同じインデックスを持つ 2 列目の兵士のみを使用できます。 のために```
1 0 1
1 1
```初期マスクは`0`。 唯一の候補ビットは列 (1) に対応しますが、禁止マスクにそのビットが含まれているため、遷移はなく、最終的なフルマスク DP 値は (0) になります。 遷移中に禁止マスクをチェックしないと、アルゴリズムは誤って (1) を返します。 

左側の境界では、存在しない位置は占有されているものとして扱う必要があります。 考慮する```
2 1 0
```初期ウィンドウは ([0,1,2]) であるため、その初期マスクは次のようになります。`001`。 最初の兵士は列 (1) または列 (2) を選択できます。 どちらを選択しても、送信仮想列 (0) はすでに占有されているため、状態は安全に右に移動できます。 これにより、存在しない列 (0) が誤って選択されるのを防ぎます。 

右境界では、ウィンドウに入る新しい位置は最終的に (n) より大きくなります。 同じ例では、最初の兵士を処理した後の新しい位置は (3) ですが、これは存在しません。 そのビットはすぐに設定されます。 2 番目の兵士が処理されると、その仮想位置は選択できなくなりますが、残りの実際の列は引き続き選択できます。 その結果、両方の有効な一致が完全なマスクに達します。 

禁止されたペアは、それ以外の場合は有効な状態の 1 つの分岐のみを削除できます。 のために```
