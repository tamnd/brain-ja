 ## 解決策
 ## 問題の理解

 正確に 5 つのプレートがあり、次のように識別されます。`A`、`B`、`C`、`D`、 そして`E`。 5 つの入力行のそれぞれは、2 つのプレート間の 1 つの関係を示します。`A<B`または`D>B`。 この関係により、2 つのプレートのどちらが小さいかがわかります。 

タスクは、与えられたすべての比較を満たす、5 つのプレートすべての順序を最小から最大まで見つけることです。 複数の順序がすべての比較を満たす場合、どれも有効です。 比較が互いに矛盾する場合は、有効な順序が存在しないため、次のように出力されます。`impossible`。 

入力サイズは意図的に小さくなっています。 常に 5 つの頂点と 5 つの比較エッジがあるため、考えられるすべての順序を検査するアルゴリズムであっても、`5! = 120`候補者たち。 つまり、階乗探索は実際の問題に対して完全に安全であるということです。 より興味深いアルゴリズムの解釈は、比較を有向グラフとして表示し、トポロジカルなソートを実行することです。 グラフには 5 つの頂点と 5 つのエッジしかないため、ここでは一定の時間がかかり、問題がより多くのプレートに一般化された場合には、より適切にスケールされます。 

不用意に実装すると、さまざまな点で失敗する可能性があります。 まず、矛盾が循環を形成する可能性があります。 例えば、```
A<B
B<C
C<A
D<E
A<D
```最初の 3 つの関係が必要なため、答えはありません。`A<B<C<A`。 グローバルな一貫性をチェックせずにローカルな比較を記録するだけのメソッドでも、順序付けが出力される可能性があります。 

第 2 に、プレートには、それを指すいくつかの制約を設定できます。 例えば、```
A<B
C<B
D<B
E<B
A<C
```必要`A<C<B`、 その間`D`そして`E`前に現れる可能性があります`B`もう一方の拘束されていないプレートに対してどちらかの位置にあります。 正しいアルゴリズムでは、各比較を個別に処理するのではなく、プレートを配置する前に入力されるすべての制約を考慮する必要があります。 

第三に、冗長な比較によって問題が発生してはなりません。 例えば、```
A<B
B<C
A<C
D<E
A<D
```含まれています`A<C`たとえそれがすでに暗示されているとしても`A<B<C`。 正しいトポロジソートでは、単純に両方のエッジが保持されます。 直接的な制約を他の制約の結果から区別する必要はありません。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべて生成`5! = 120`の順列`A`、`B`、`C`、`D`、 そして`E`。 順列ごとに、すべてのプレートの位置を計算し、5 つの比較をすべてチェックします。 すべての関係を満たす最初の順列が有効な答えです。 120 個の順列がすべて失敗した場合、制約は矛盾しています。 

このアプローチは正しいです。なぜなら、5 つの異なるプレートの考えられる順序はすべて、順列の中で 1 回だけ現れるからです。 有効な順序付けが存在する場合、最終的にはブルート フォースによってそれが検査されます。 どの順列も 5 つの関係すべてを満たさない場合、有効な順序は存在しません。 

この問題に関しては、ブルート フォースはまったく遅くありません。 最悪の場合、最大でもパフォーマンスが向上します`120 * 5 = 600`関係チェックに加えて、順列生成の小さなオーバーヘッドが発生します。 したがって、1 秒という制限時間は非常に寛大です。 そこで止まらない理由は、制約の構造により、より一般的な解決策が得られるからです。 

重要な観察は、すべての比較を有向エッジに変えることができるということです。 もし`A<B`、 それから`A`前に現れる必要があります`B`なので、エッジを追加します`A -> B`。 もし`A>B`代わりに追加します`B -> A`。 ここで、すべてのエッジが前の頂点から後の頂点を指すように頂点を順序付ける必要があります。 これはまさに有向グラフのトポロジカルな順序付けです。 

有向グラフは、有向サイクルがない場合に正確にトポロジカルな順序付けを持ちます。 カーンのアルゴリズムは、必要な部分を両方とも提供します。 これは、度数が 0 の頂点を繰り返し選択し、それを答えの次に配置し、その出ていくエッジを削除します。 5 つの頂点すべてが削除された場合、結果として得られるシーケンスはすべての比較を満たします。 すべての頂点が削除される前にプロセスが停止した場合、残りの頂点はサイクルに属しているか、サイクルに依存しているため、制約は不可能になります。 

可能な配置が 120 しかないため、総当たり法は機能しますが、プレートの数が増えると階乗的になります。 比較により有向非巡回グラフが形成されるという観察により、列挙を線形時間グラフ アルゴリズムに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(5! * 5)`|`O(5)`| この問題は受け入れられました |
 | トポロジカルソート |`O(V + E)`|`O(V + E)`| 承認済み |

 ここ`V=5`そして`E=5`したがって、最適な方法は、指定された入力に対して実質的に一定時間になります。 

## アルゴリズムのチュートリアル

 1. 各プレートに 1 つの頂点を持つ有向グラフを作成します。 比較するたびに、小さいプレートから大きいプレートへエッジの向きを合わせます。 例えば、`D>B`になる`B -> D`。 方向は、すべての有効な回答が尊重する必要がある順序を表します。 
2. すべてのプレートの入次数を計算します。 入次数は、そのプレートの前に現在何枚のプレートが必要であるかを示します。 度数 0 のプレートには未解決の先行プレートがないため、次に安全に配置できます。 
3. すべての角度ゼロのプレートをキューに入れます。 入力によって必ずしも一意の順序が決定されるわけではないため、そのようなプレートが複数存在する場合があります。 それらの中から任意の選択が有効です。 
4. キューからプレートを繰り返し削除し、回答に追加します。 そのプレートから別のプレートへのエッジごとに、宛先の入次数を 1 ずつ減らします。 その度数が 0 になると、宛先をキューに追加します。 出ていくエッジを除去することは、整流板をその位置に固定し、その制約を満たすことを意味します。 
5. キューを処理した後、回答に追加されたプレートの数を確認します。 5 つすべてが処理された場合、答えは有効な並べ替え順序になります。 処理された数が 5 つ未満の場合、グラフには循環が含まれており、比較は矛盾しているため、次のように出力します。`impossible`。 

重要な不変条件は、以前に選択されたすべてのプレートが削除された後、答えに配置されたすべてのプレートが次数 0 になることです。 したがって、そのプレートを指すすべての制約はすでに満たされているため、次にそれを配置しても入力比較に違反することはできません。 アルゴリズムがすべてのプレートを処理する場合、各エッジは、前に選択したプレートから後に選択したプレートに移動します。 すべてのプレートを処理できない場合、サイクルによって少なくとも 1 つの残りのプレートが角度 0 に達することがなくなり、有効な順序が存在しないことが証明されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    graph = [[] for _ in range(5)]
    indegree = [0] * 5

    for _ in range(5):
        s = input().strip()
        a = ord(s[0]) - ord('A')
        b = ord(s[2]) - ord('A')

        if s[1] == '<':
            u, v = a, b
        else:
            u, v = b, a

        graph[u].append(v)
        indegree[v] += 1

    q = deque()

    for v in range(5):
        if indegree[v] == 0:
            q.append(v)

    order = []

    while q:
        u = q.popleft()
        order.append(u)

        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                q.append(v)

    if len(order) != 5:
        print("impossible")
        return

    print(''.join(chr(v + ord('A')) for v in order))

if __name__ == "__main__":
    solve()
```グラフはインデックスを使用しています`0`を通して`4`のために`A`を通して`E`。 文字を整数に変換すると、隣接リストと度数配列が簡単になります。 

各入力リレーションに対して、小さいプレートが割り当てられます。`u`そして大きい方のプレートには`v`、優位性を与える`u -> v`。 次のような関係の場合`A>B`、コードは文字を反転して格納します`B -> A`、 なぜなら`B`サイズが大きくなる場合は、早めに注文する必要があります。 

初期キューには、次数が 0 であるすべての頂点が含まれます。 これらは、現在、別のプレートの後に表示する必要がないプレートです。 その後、アルゴリズムはカーンのトポロジカルソートプロセスに従います。 

最終的な長さのチェックは不可欠です。 キューが空になっても、自動的に回答が完了したことを意味するわけではありません。 サイクルが存在する場合、そのサイクル内のすべての頂点は正の内次数を保持するため、一部のプレートが未処理のままでもキューが空になる可能性があります。 比較する`len(order)`と`5`まさにその状況を捉えています。 

Python では整数オーバーフローの懸念はなく、頂点とエッジの数が固定されているため、意味のある境界の問題もありません。 入力にはちょうど 5 つの比較が含まれているため、制約を読み取るループはちょうど 5 回実行する必要があります。 

## 実用的な例

 サンプル 1 の場合、比較は次の有向エッジになります。`B -> D`、`D -> A`、`E -> C`、`B -> A`、 そして`C -> B`。 

初期の入次数は次のとおりです。`A=2`、`B=1`、`C=1`、`D=1`、 そして`E=0`。 のみ`E`を最初に選択できます。 

| ステップ | 前のキュー 選択済み | 除去後の角度 | 答え |
 | --- | --- | --- | --- |
 |`E`|`E`|`A=2, B=1, C=0, D=1, E=0`|`E`|
 |`C`|`C`|`A=2, B=0, C=0, D=1, E=0`|`EC`|
 |`B`|`B`|`A=1, B=0, C=0, D=0, E=0`|`ECB`|
 |`A,D`|`A`|`D=0`|`ECBA`|
 |`D`|`D`| すべて処理済み |`ECBAD`|

 正確な順序は、ゼロ度頂点がキューに入れられる順序によって異なります。 サンプル出力は次のとおりです`ECBDA`、一方、上記のトレースは次のようになります`ECBAD`、これも有効です。`A`そして`D`適切な時点で利用可能になり、制約が必要とするのは`D<A`。 選択すると`D`前に`A`、サンプルの注文を取得します`ECBDA`。 

サンプル 2 では、最初の 3 つの関係がサイクルを形成します。`B -> E`、`E -> A`、 そして`A -> B`。 

残りの比較は、`C -> B`そして`D -> B`。 

| ステップ | 前のキュー 選択済み | 残りの関連する度数 | 答え |
 | --- | --- | --- | --- |
 |`C, D`|`C`|`B=3`|`C`|
 |`D`|`D`|`B=2`|`CD`|
 | 空 | なし |`A=1, B=2, E=1`|`CD`|

 後`C`そして`D`3つの頂点が削除されます`A`、`B`、 そして`E`まだサイクルを形成しています。 どれも度数 0 に到達できないため、キューは空になり、5 つのプレートのうち 2 つだけが処理されます。 アルゴリズムは出力します`impossible`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(V + E)`| 各プレートは 1 回処理され、各比較エッジが 1 回検査されます。 |
 | スペース |`O(V + E)`| 隣接リスト、indegree 配列、キュー、および回答には、5 つの頂点と 5 つのエッジのみが含まれます。 |

 この問題については、`V=5`そして`E=5`したがって、アルゴリズムは一定数の操作のみを実行します。 これは 1 秒の時間制限をはるかに下回っており、256 MB の制限に比べてメモリの使用量は無視できます。 さらに重要なのは、固定数のプレートがより大きなグラフに置き換えられた場合でも、同じ実装の効率が維持されることです。 

## テストケース

 問題には常に正確に 5 つのプレートと 5 つの比較が含まれるため、意味のある最小入力サイズと最大入力サイズは両方とも同じ固定サイズになります。 以下のカスタム テストは、完全な順序付け、冗長制約、制約のない選択、およびサイクルに焦点を当てています。```python
import sys
import io
from collections import deque

def solve():
    input = sys.stdin.readline

    graph = [[] for _ in range(5)]
    indegree = [0] * 5

    for _ in range(5):
        s = input().strip()
        a = ord(s[0]) - ord('A')
        b = ord(s[2]) - ord('A')

        if s[1] == '<':
            u, v = a, b
        else:
            u, v = b, a

        graph[u].append(v)
        indegree[v] += 1

    q = deque(v for v in range(5) if indegree[v] == 0)
    order = []

    while q:
        u = q.popleft()
        order.append(u)

        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                q.append(v)

    if len(order) != 5:
        return "impossible"

    return ''.join(chr(v + ord('A')) for v in order)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided sample 1.
assert run(
    "D>B\n"
    "A>D\n"
    "E<C\n"
    "A>B\n"
    "B>C\n"
) == "ECBDA"

# Provided sample 2.
assert run(
    "B>E\n"
    "A>B\n"
    "E>A\n"
    "C<B\n"
    "D<B\n"
) == "impossible"

# Fully determines A < B < C < D < E.
assert run(
    "A<B\n"
    "B<C\n"
    "C<D\n"
    "D<E\n"
    "A<E\n"
) == "ABCDE"

# Same ordering information with a redundant edge and reversed syntax.
assert run(
    "E>D\n"
    "D>C\n"
    "C>B\n"
    "B>A\n"
    "E>A\n"
) == "ABCDE"

# Several plates are initially available, but the constraints are consistent.
assert run(
    "A<C\n"
    "B<C\n"
    "D<E\n"

    "C<A\n"

 ## 特殊なケース

 直接の矛盾は、必ずしも反対の関係を持つ 2 つの同一のプレートによって表現されるのではなく、サイクルによって表現されます。 考慮する：```
A<B
B<C
C<A
D<E
A<D
```グラフには次の内容が含まれます`A -> B -> C -> A`。 当初は、`D`おそらく他の頂点も処理できますが、最終的にはサイクル頂点が正の内次数で残ります。 何も選択できないため、回答に入力される頂点は 5 つ未満であり、アルゴリズムは次のように出力します。`impossible`。 個々の比較が有効であるかどうかだけをチェックする方法では、この全体的な矛盾を見逃す可能性があります。 

2 番目のエッジ ケースは、1 つのプレートに多数の先行プレートがある場合に発生します。```
A<B
C<B
D<B
E<B
A<C
```ここ`A`先行する必要があります`C`、両方が前になければなりません`B`。 他の 2 つのプレートも先行する必要があります`B`、ただし、それらの相対位置は完全には制約されていません。 カーンのアルゴリズムは、すべての入力エッジが終了するまで待機します。`B`選択する前に削除されています。 それはまさに入次数が表すものなので、`B`誤って早すぎることはありません。 

冗長な比較も、入力を拒否する理由として扱うのではなく、保存する必要があります。 例えば：```
A<B
B<C
A<C
D<E
A<D
```関係`A<C`すでに暗示されています`A<B<C`, しかし、それでも有効なエッジです。 いつ`A`が処理されると、両方の出力エッジが独立して削除されます。 次数`C`は、両方の入力エッジが考慮された後にのみゼロに達します。 結果として得られる順序は、冗長情報に関係なく有効です。 

最後に、固定入力サイズ自体が境界条件です。 常にちょうど 5 つの頂点とちょうど 5 つの比較があるため、空のグラフや処理すべきワンプレートのケースはありません。 この実装では、正確に 5 行を読み取り、正確に 5 つの頂点をチェックし、不必要な一般的なケースの機構を導入することなく、問題の固定境界と一致させます。
