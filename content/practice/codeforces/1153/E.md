 ## 解決策
 ## 問題の理解

 上に描かれた隠された単純なパスが与えられます。$n \times n$グリッド。 パスはヘビを表します。ヘビは個別のセルを訪問し、連続するペアはそれぞれ 1 つの側面を共有し、パスの両端は頭と尾と呼ばれる特別なセルです。 

私たちは道を直接見ることはできません。 代わりに、軸に揃えられた長方形について質問することができます。 任意の長方形について、システムはヘビが頭から尾まで移動するときに長方形の境界を横切った回数に等しい数値を返します。 

重要な課題は、グローバルな幾何学的信号としてこの「境界通過数」しかないことです。 そこから、最大 2019 クエリ内でパスの 2 つのエンドポイントを回復する必要があります。 

制約$n \le 1000$すべての細胞を直接調査する試みは排除されます。 セルごとに 1 つのクエリでもすでに制限を超えており、インタラクション コストによりリニア スキャンは不可能になります。 これにより、ローカルな検査ではなく、各クエリからグローバル構造を抽出する必要が生じます。 

微妙だが重要な観察は、エンドポイントが内部セルとどのように異なる動作をするかということです。 長方形に端点が 1 つだけ含まれている場合、境界交差数に奇妙な影響が生じますが、パスが出入りするたびに 2 つの境界交差が生成されるため、内部頂点は常に偶数の「ペア」で寄与します。 このパリティ分離は、利用できる構造ハンドル全体です。 

単純なアプローチでは、たとえばセルがヘビに属しているかどうかを検出し、隣接するセルに拡張するなどして、セルごとにパスを再構築しようとします。 これは、セルのメンバーシップをテストできたとしても、最悪の場合、パスの拡張に必要なクエリが多すぎるため、失敗します。 最大で完全な BFS$10^6$隣接チェックのあるセルはすぐに制限を超えます。 

正しいアプローチでは、パス全体の再構築を回避し、2 つのエンドポイントを直接見つけることだけに焦点を当てます。 

## アプローチ

 強引なアイデアは、すべてのセルをチェックし、どのセルがヘビに属しているかを特定し、その中から 2 つのエンドポイントを見つけることです。 メンバーシップは、単一セルのクエリを使用してテストできます。パス上にないセルは 0 を返し、内部セルは 2 を返し、エンドポイントは 1 を返します。この分類は正しいですが、すでにコストがかかります$O(n^2)$クエリは制限をはるかに超えています。 

たとえ何らかの方法ですべてのスネーク セルを見つけることができたとしても、隣接関係を特定する必要があり、エッジごとに追加のクエリが必要になります。 ヘビはグリッドのほぼ全体を占有する可能性があるため、このアプローチはクエリの制約の下では破綻します。 

重要な洞察は、個々のセルの観点から考えるのをやめ、代わりに長方形の答えの同等性を通じてエンドポイントについて推論することです。 

させて$F(R)$長方形の答えになります$R$。 パスの各内部セグメントはペアの交差に寄与しますが、各終点が長方形の内側にある場合、単一の不一致の交差に寄与します。 その結果、次のパリティは$F(R)$内部に存在するエンドポイントの数にのみ依存します$R$。 内部構造はモジュロ 2 を完全に打ち消します。 

これは次のことを意味します:

 - 長方形に端点が含まれていない場合、$F(R)$は均等です。 
- エンドポイントが 1 つだけ含まれている場合、$F(R)$奇数です。 
- 両方のエンドポイントが含まれる場合、$F(R)$またしてもです。 

したがって、端点を見つける問題は、長方形に奇数の点が含まれているかどうかを示すブラック ボックス関数を使用して、グリッド内の 2 つの点を見つけることに帰着します。 

問題をこのように解釈したら、グリッド上で標準的な分割統治検索を使用し、単一のセル内の各エンドポイントを分離するまで長方形を繰り返し分割することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースセル再構築 |$O(n^2 + k)$クエリ |$O(n^2)$| 遅すぎる |
 | パリティベースの分割統治 |$O(\log n \cdot \log n)$クエリ |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは機能に依存しています$F(x_1, y_1, x_2, y_2)$、四角形のクエリ結果。 

1. まず、この値のパリティのみが重要であることがわかります。 を返すヘルパー クエリを定義します。$F(R) \bmod 2$。 このパリティは、長方形に奇数の端点が含まれているかどうかに等しくなります。 
2. 再帰的な四角形分割プロセスを使用して最初のエンドポイントを見つけます。 グリッド全体から始めます。 長方形のパリティが 0 の場合、その長方形には端点がないか、両方の端点が含まれるため、単一の端点を分離するのには役に立ちません。 
3. 現在の長方形を、どちらの寸法が大きいかに応じて、水平または垂直の 2 つの部分に分割します。 両方の半分をクエリし、パリティが 1 である半分を選択します。これが機能するのは、親四角形に奇数のエンドポイントが含まれている場合、その半分にちょうど 1 つのエンドポイントが存在する必要があるためです。 
4. 長方形が 1 つのセルに縮小するまで、この分割を繰り返します。 そのセルはエンドポイントである必要があります。 
5. 最初のエンドポイントを特定した後$A$、同じ検索を繰り返して 2 番目のエンドポイントを見つけますが、パリティ チェックを調整します。 任意の長方形の場合$R$、 もし$R$含まれています$A$の寄与が大きいため、そのパリティを反転します。$A$は既知であり、論理的に減算できます。 これにより、単一の未知のエンドポイントを再度検索するという不変条件が復元されます。 
6. 両方のエンドポイントが見つかったら、それらを任意の順序で出力します。 

### なぜ効果があるのか

 全体の削減は、パスの内部構造がパリティで相殺されるという事実に依存します。 すべての内部頂点は、相互作用する四角形に 2 つの交差をもたらすため、パリティには決して影響しません。 エンドポイントのみが不対効果に寄与します。 これは、インタラクティブなオラクルが、正確に 2 つの隠れた点に対してセット メンバーシップ パリティ オラクルと同様に効果的に動作することを意味します。 分割統治戦略は、ユニオンの下でパリティが保持され、パーティション間できれいに分割できるため有効であり、各ステップで選択した検索領域に 1 つのエンドポイントが確実に残るようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

def ask(x1, y1, x2, y2):
    print("?", x1, y1, x2, y2)
    sys.stdout.flush()
    return int(input().strip())

def parity(x1, y1, x2, y2):
    return ask(x1, y1, x2, y2) & 1

def find_endpoint(exclude=None):
    x1, y1, x2, y2 = 1, 1, n, n

    while x1 < x2 or y1 < y2:
        if x2 - x1 >= y2 - y1:
            mx = (x1 + x2) // 2
            p = parity(x1, y1, mx, y2)
            if exclude is not None:
                ex_x, ex_y = exclude
                if x1 <= ex_x <= mx and y1 <= ex_y <= y2:
                    p ^= 1
            if p:
                x2 = mx
            else:
                x1 = mx + 1
        else:
            my = (y1 + y2) // 2
            p = parity(x1, y1, x2, my)
            if exclude is not None:
                ex_x, ex_y = exclude
                if x1 <= ex_x <= x2 and y1 <= ex_y <= my:
                    p ^= 1
            if p:
                y2 = my
            else:
                y1 = my + 1

    return x1, y1

a = find_endpoint()
b = find_endpoint(exclude=a)

print("!", a[0], a[1], b[0], b[1])
sys.stdout.flush()
```実装はインタラクションを小さな単位でラップします。`ask`すべてのクエリの後に確実にフラッシュする機能。これは対話型の問題では必須です。 

コアロジックは次のとおりです`find_endpoint`、グリッドのバイナリ分割を実行します。 各ステップで半分をクエリし、パリティを使用してどちらの側に奇数のエンドポイントが含まれているかを判断します。 2 番目のエンドポイントを検索している場合は、クエリされた半分の内側にある既知のエンドポイントの寄与を差し引き、これによりパリティ信号の正確さが維持されます。 

ここでよくある間違いは、ポイントを直接カウントしているのではなく、パス クエリのパリティ動作に依存していることを忘れていることです。 すでに見つかったエンドポイントを調整することで、2 番目の検索を独立させます。 

## 実用的な例

 ヘビが反対側の角にある 2 つの端点を占める小さなグリッドを考えてみましょう。 

完全なグリッドから始めます。 

| ステップ | 長方形 | クエリ結果のパリティ | アクション |
 | --- | --- | --- | --- |
 | 1 | グリッド全体 | 0 | 分割グリッド |
 | 2 | 左半分 | 1 | 左を維持 |
 | 3 | 左上半分 | 1 | キープ |
 | 4 | 最終セル | 1 | エンドポイントが見つかりました |

 これは、単一のエンドポイントが残るまでパリティによって検索領域がどのように狭められるかを示しています。 

最初のエンドポイントが次の場所でわかった後で、2 番目のエンドポイントを検索することを検討してください。$(1,1)$。 

| ステップ | 長方形 | (1,1) が含まれていますか? | 生のパリティ | 調整されたパリティ | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | グリッド全体 | はい | 0 | 1 | キープ |
 | 2 | 上半分 | はい | 1 | 0 | 破棄 |
 | 3 | 下半分 | いいえ | 1 | 1 | キープ |

 調整ステップにより、すでに検出されたエンドポイントの影響が確実に除去され、クリーンな検索信号が復元されます。 

これらのトレースは、アルゴリズムが、未知のエンドポイントを 1 つだけ含む領域を分離しているという不変条件を常に保持していることを確認します。

 ## 特殊なケース

 重要なエッジケースは、ヘビが非常に短く、隣接する 2 つのセルだけで構成されている場合です。 この場合、いずれかの端点を含むすべての四角形が奇数パリティを生成し、検索は 2 つのセルのうちの 1 つに直ちに収束します。 2 番目の検索では、最初のエンドポイントを除外した後、他のエンドポイントが自然に分離されます。 

もう 1 つのエッジ ケースは、初期の分割試行中に両方のエンドポイントが同じ最初の半分にある場合に発生します。 既知のエンドポイントを減算すると、そのエンドポイントを含むすべての四角形で正しいパリティ動作が復元されるため、パリティ調整により誤った削除が防止されます。 

最後に、エンドポイントが境界付近にある場合、分割プロセスは幾何学的距離に依存せず、位置の影響を受けない純粋にセット メンバーシップのパリティに依存するため、安定したままになります。
