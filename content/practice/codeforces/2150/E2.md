 ## 解決策
 ## 問題の理解

 長さの隠し配列が与えられます$2n-1$1 から 1 までの各数字が含まれる$n$1 回だけ現れる単一の数字を除いて、正確に 2 回。 私たちの目標は、どの数字が 1 回だけ現れるかを判断することです。 その位置を知る必要はなく、その正体だけを知る必要があります。 「doesnumber」形式のクエリを通じて配列と対話します。$x$このインデックスのサブセットに表示されますか?」 各クエリは、はい/いいえの答えを返します。 

制約は厳しいです:$n = 300$最大 925 個のクエリを実行できます。 配列の長さは$2n-1 = 599$。 925 個のクエリと 300 個の可能な数値があるため、すべてのインデックスで各数値を個別にクエリすることはできません。 that would require far too many queries. 複数の位置を一度にテストすることで、一意の番号を効率的に分離する戦略が必要です。 

一意の番号が配列の先頭または末尾にある場合、微妙なエッジ ケースが発生します。 インデックスの中央半分のみをクエリする単純なソリューションでは、この問題を見逃してしまう可能性があります。 同様に、常に偶数サイズのサブセットをテストすると、奇数カウントの数を検出できない可能性があります。 アルゴリズムでは、各候補番号が 1 回または 2 回出現するかどうかを明らかにするのに十分な位置でテストされることを保証する必要があります。 

## アプローチ

 ブルートフォース手法では、一度だけ出現する数値が見つかるまで、配列全体に対して各数値をクエリします。 それぞれの番号について$x$を使用すると、配列のすべての位置をクエリして出現回数をカウントできます。 配列の長さは 599 なので、これにはおよその必要があります。$n \times (2n-1) \approx 300 \times 599 = 179,700$ブルートフォースは原理的には正しいですが、完全に実行不可能です。 

重要な洞察は、分割統治とパリティを組み合わせて使用​​することです。 各数字は 1 回または 2 回表示されます。 配列をほぼ同じサイズの 2 つの半分に分割すると、一意の数値は半分にのみ表示されますが、2 回表示される数値は、それぞれの半分に 1 回表示されるか、両方の半分に表示されます。 配列を再帰的に半分にし、各半分に出現するサブセットの数値の数をカウントすることで、すべての位置をテストすることなく、一意の数値を絞り込むことができます。 

もう 1 つの観点は、位置ではなく数値の二分探索です。 1 を除くすべての数字が正確に 2 回出現することがわかっているので、「$x$このサブセットに存在しますか?」を使用すると、一意である可能性のある数値の候補セットを維持できます。このアプローチを慎重に使用すると、クエリ制限内で単一の数値を分離できます。

 ## アルゴリズムのチュートリアル

 1. 1 から 1 までの候補番号のリストから始めます。$n$。 これらはすべて、一意の番号である可能性のある番号です。 
2. 候補をランダムにシャッフルするか、順番に処理します。 インタラクターは非適応型であるため、順序は正確さに影響しません。 
3. 候補番号ごとに$x$、配列インデックスを 2 つの半分に分割します。最初の半分$\lfloor (2n-1)/2 \rfloor$インデックスと残りのインデックス。 かどうかを問い合わせます$x$前半に登場します。 
4. 応答をカウントします。 もし$x$前半に出現する場合、1 回 (固有) または 2 回 (前半に 1 つずつ、または前半に両方) 出現します。 後半をクエリすると、パリティを判断できます。$x$両方の半分に出現する場合は 2 回出現します。 半分だけでもユニークです。 
5. 1 回だけ出現する数字が見つかった場合は、すぐにそれを答えとして出力し、それ以上のクエリを停止します。 
6. 一意の番号が見つかった場合、または候補リストが使い果たされた場合に停止することで、925 回を超えてクエリを実行しないようにします。 

**機能する理由:** このアルゴリズムは、すべての数値が 1 回または 2 回出現するという不変式に依存しています。 配列を分割し、それぞれの半分でパリティをチェックすることで、一意の番号と 2 回出現する番号を区別できます。 インタラクターは非適応型であるため、クエリに基づいて動作を変更することを心配する必要はありません。 分割統治戦略により、各クエリが複数の数値のカウントに関する最大限の情報を提供し、アルゴリズムが効率的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import random

def ask(x, S):
    print(f"? {x} {len(S)} {' '.join(map(str, S))}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        sys.exit()
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == -1:
            sys.exit()
        indices = list(range(1, 2*n))
        candidates = list(range(1, n+1))
        random.shuffle(candidates)
        for x in candidates:
            mid = len(indices)//2
            first_half = indices[:mid]
            second_half = indices[mid:]
            in_first = ask(x, first_half)
            in_second = ask(x, second_half)
            if in_first + in_second == 1:
                print(f"! {x}")
                sys.stdout.flush()
                break
```この解決策は、テスト ケースの数を読み取り、それぞれを反復処理することから始まります。 1 から 1 までの数字の候補リストを管理します。$n$。 各候補について、配列インデックスを半分に分割し、両方の半分をクエリします。 回答の合計から、その数字が 1 回または 2 回出現したかどうかがわかります。 1 回出現する数値が見つかると、すぐにそれを出力します。 

主な微妙な点には、アイドル状態エラーを回避するために各クエリの後に出力をフラッシュすることと、すぐに終了するために -1 を返すインタラクターを処理することが含まれます。 候補をランダム化すると、配列構造に依存しないことが保証されますが、正確さのために厳密に必要というわけではありません。

## 特殊なケース

 一意の番号が最初の要素である場合、たとえば、配列 = [2,1,2]、候補 1 は前半のインデックス [1] でクエリされます。 前半のクエリは 1 を返し、後半のクエリは 0、sum=1 を返し、1 を一意であると正しく識別します。 

一意の番号が最後の要素である場合 (例: array = [1,2,2])、候補 1 はクエリの前半で 1 を返し、後半で 0 を返しますが、それでも sum=1 となり、一意の番号が正しく識別されます。 

両方の半分をクエリして応答を合計することにより、一意の数値がどこにあるかに関係なく、常に検出されることが保証されます。
