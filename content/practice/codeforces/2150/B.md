 ## 解決策
 ## 問題の理解

 セルを黒く着色する方法の数を数えるように求められます。$n \times n$リストが与えられたグリッド$a$長さの$n$。 エントリー$a_k$行内に表示される黒セルの数を指定します$k$。 さらに、黒のセルの位置を行および列のインデックスにグローバルな方法で結び付ける制約が 2 つ追加されています。 各整数について$k$から$1$に$n$、行または列が次と等しい黒セルが 1 つだけ存在する必要があります。$k$次の意味で、行と列のインデックスの最大値は次のとおりです。$k$最初の条件の場合、行と「反映された」列の最大値$n + 1 - y$でなければなりません$k$2番目に。 これら 2 つの制約は、グリッドの対角線に沿った特定の黒セルの一意の位置を効果的に決定します。 

入力は複数のテスト ケースで構成され、それぞれが指定します$n$そして配列$a$。 出力は有効なグリッドの数を法とした値になる必要があります。$998\,244\,353$。 すべての合計$n$テストケース全体で次を超えない$2 \cdot 10^5$これは、テスト ケースごとに線形または線形に近いソリューションが必要であることを示唆しています。 

必要な行の合計が異なる場合にエッジケースが発生します。$a_k$対角線によって決まる利用可能なポジションの数を超えます。 たとえば、次の場合$n=2$そして$a=[1,1]$、両方の行に 1 つの黒いセルが必要です。 この制約により、黒いセルが特定の対角位置に強制的に配置され、有効な構成が 1 つだけ残ります。 不注意なアプローチでは、グローバル最大制約を無視して自由に組み合わせをカウントしようとする可能性があり、不正確なカウントが生成されます。 

## アプローチ

 ブルートフォース手法では、次のサイズのグリッド セルのすべてのサブセットが生成されます。$m = \sum a_i$、行数を確認し、2 つの最大条件を検証します。 このアプローチは原理的には正しいですが、次の場合には実行できなくなります。$n$まで$2 \cdot 10^5$サブセットの数が組み合わせ的に増加し、許容範囲をはるかに超えてしまうためです。 

重要な洞察は、主対角線と反対角線からの距離の観点からグリッド制約を表示することです。 各黒いセルは、最大制約によって決定される 2 つの「レイヤー」に関連付けられます。$\max(x_i, y_i)$そしてからの1つ$\max(x_i, n+1-y_i)$。 特定の行について$k$、最初の制約を満たす位置の数は、$\min(k, n - k + 1)$。 黒マスを一列に配置する方法の数$k$は組み合わせ計算になります: を選択してください$a_k$その行内の利用可能なスポットからの位置。 いつでも$a_k$許容位置数を超えると設定できません。 

これにより、問題は行全体にわたる組み合わせ選択の積をモジュロで計算することになります。$998\,244\,353$。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2. 答えを 1 に初期化します。これにより、有効な構成の数が乗算的に累積されます。 
3. 各行を反復処理します。$i$1から$n$。 この行の黒セルの最大許容数を計算します。これは、$\min(i, n - i + 1)$。 これにより、各レイヤーの 2 つの対角線の交差が考慮されます。 
4. もし$a_i$この最大値を超える場合は、答えを 0 に設定してブレークします。 構成が不可能です。 
5. それ以外の場合は、答えに選択方法の数を掛けます。$a_i$利用可能なスポットからの位置、モジュロ$998\,244\,353$。 この特定の問題では、各セルは対角線によって一意に決定されるため、ゼロ以外のエントリに対する有効な選択肢は 1 つになります。つまり、階乗を計算するのではなく、実現可能性をチェックするだけで済みます。 
6. テストケースの答えを出力します。 

これが機能する理由: 両方の対角線に沿った最大制約を体系的に尊重するため、問題の不変条件が保存されます。 行の順序で反復し、交差サイズによって黒セルを制限することにより、各黒セルがグローバル最大条件のいずれにも違反しないことが保証されます。 製品アプローチでは、実行可能な行で考えられるすべての選択肢が考慮され、行の要件が利用可能な位置を超えた瞬間に、正しく不可能とマークされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    ans = 1
    for i in range(1, n + 1):
        max_cells = min(i, n - i + 1)
        if a[i-1] > max_cells:
            ans = 0
            break
    print(ans % MOD)
```このソリューションは入力を効率的に読み取り、各行を反復処理してレイヤー制限を計算します。 小切手`a[i-1] > max_cells`不可能な構成は直ちに破棄されます。 実現可能性が確認されれば、許可される各構成は一意であるため、階乗関数や組み合わせ関数は必要ありません。 問題要件を遵守するために、印刷ステップでモジュラー演算が適用されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 998244353
    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = 1
        for i in range(1, n + 1):
            max_cells = min(i, n - i + 1)
            if a[i-1] > max_cells:
                ans = 0
                break
        res.append(str(ans % MOD))
    return "\n".join(res)

# provided samples

# custom cases
assert run("1\n3\n1 2 1\n") == "0", "row sum exceeds layer limit"
assert run("1\n4\n1 1 1 1\n") == "1", "each row has one black cell, feasible"
assert run("1\n2\n0 0\n") == "1", "empty grid is feasible"
assert run("1\n5\n1 1 1 1 1\n") == "1", "single black cell per row feasible"

 ## 特殊なケース

 最小サイズのグリッドの場合、次のようになります。`n=2`と`a=[0,0]`の場合、ゼロの黒セルがすべての制約を満たすため、アルゴリズムは 1 を出力します。 最大サイズのグリッドの場合、アルゴリズムは組み合わせ爆発を起こさずに行ごとにチェックします。 場合`a[i]`そのレイヤーで可能な最大値に等しい場合は、`min(i, n-i+1)`論理。 次のような明白ではないシナリオの場合`a=[2,2,1,0,0]`、アルゴリズムは、対角制約を交差させることによって、固有の実行可能な構成を正確に識別します。
