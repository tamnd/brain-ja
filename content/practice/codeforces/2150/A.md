 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$10^9$セルはそれぞれ黒または白です。 最初は、特定のセルのセットが黒で、その他のセルはすべて白です。 次に、一連のコマンドが累積的に複数回実行されます。最初のコマンドではセル 1 から開始し、そのコマンドに従い、結果のセルを黒で塗ります。 最初の 2 つのコマンドでは、セル 1 から再度開始し、両方のコマンドを順番に実行し、最後のセルを黒で塗ります。 このプロセスは、すべてのコマンドが累積的に適用されるまで続きます。 

コマンドには次の 2 種類があります。`A`一歩前進し、`B`、次の白いセルに移動します。 出力は、すべての人々が動きを実行した後の最後の黒セルのセットです。 

制約は重要です。 コマンドと最初の黒セルの合計数は次のとおりです。$10^5$すべてのテスト ケースにわたってそれぞれが異なりますが、セル数自体は最大になる可能性があります。$10^9$。 これは、セルの行全体をシミュレートしたり、単純な方法で次の白いセルを繰り返しスキャンしたりすると時間がかかりすぎることを意味します。 各セルに直接触れるか、最大で反復されるソリューション$10^9$制限時間を超えてしまいます。 

複数のコマンドを実行すると、微妙なエッジケースが発生します。`B`が連続して実行され、間にあるセルはすべて黒になります。 一度に 1 つのセルを移動する単純なソリューションでは、速度が遅くなるか、注意しないと次の白いセルをオーバーシュートしてしまう可能性があります。 もう 1 つのエッジ ケースは、コマンドの最終宛先がすでに黒である場合です。 アルゴリズムは、更新を重複したり欠落したりすることなく、黒のままにしておく必要があります。 

## アプローチ

 ブルート フォース アプローチでは、セル 1 から開始してコマンドのプレフィックスを実行する各人をシミュレートします。 それぞれについて`A`、1ずつ増加します。`B`、白いセルが見つかるまで前方にスキャンします。 プレフィックスを実行した後、最後のセルを黒にマークします。 このアプローチは正しいですが、遅すぎます。`B`までのスキャンが必要になる可能性があります$O(10^9)$細胞があり、最大で$10^5$コマンド。 最悪の場合の複雑さは本質的には$O(n \cdot m)$定数が非常に大きいため、これは現実的ではありません。 

より高速なソリューションを実現する重要な観察は、**各プレフィックスの最後に訪問したセル**のみをマークする必要があるということです。 コマンド用`B`、最終的な位置は、コマンドのシーケンスと現在の黒セルのセットにのみ依存します。 重要なのは、接頭辞の最後に黒のセルを追加した後は、後からのみ影響するということです。`B`コマンド。 私たちは黒細胞を整理された構造に維持し、動きを貪欲に処理することができます。 私たちが遭遇するたびに、`B`、既存の黒いセルを使用して、次のマークされていない位置にジャンプします。 

最適なアプローチでは、すべてのセルをスキャンする必要がなくなります。 代わりに、セット内の黒セルを維持します。$O(1)$メンバーシップは、最も遠くにアクセスしたセルをチェックし、追跡します。 それぞれのコマンドについて、`A`は簡単なので、1 ずつ増分するだけです。`B`、黒のセットにないセルに到達するまで、現在の位置を増分します。 各セルは最大 1 回だけ黒になる可能性があるため、これにより、すべてのコマンドにわたる増分の合計数が次の範囲内に収まることが保証されます。$n + m$、つまり$O(10^5)$テストケースごとに。 これでも十分効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * セルスキャン) | O(m) | 遅すぎる |
 | 最適 | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`そして`m`、コマンド文字列、および最初の黒いセル。 
2. O(1) メンバーシップ チェックのために、最初の黒いセルをセットに保存します。 
3. 現在位置を初期化する`pos = 1`。 
4. 各コマンドを順番に繰り返します。 コマンドが`A`、増分`pos`1までに。 
5. コマンドが`B`、繰り返し増加します`pos`それまで`pos`黒セルのセットにありません。 これにより、次の白いセルに効率的にジャンプします。 
6. コマンドの各プレフィックス (文字列の各ステップ) の後に、`pos`黒セルセットに。 
7. すべてのコマンドを処理した後、黒いセルのセットをソートし、そのサイズと要素を出力します。 

不変条件は、どの時点においても、黒いセルのセットには前の接頭辞でマークされたすべてのセルが含まれるということです。 それぞれ`B`コマンドは常に黒いセルを飛び越えて次の白いセルにジャンプし、正確さを保証します。 各セルが白から黒に一度しか遷移できないという事実により、`B`コマンドは合計で最大で`n + m`プレフィックス シーケンス全体にわたってステップを実行します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        black = set(map(int, input().split()))
        pos = 1
        for c in s:
            if c == 'A':
                pos += 1
            else:
                while pos in black:
                    pos += 1
            black.add(pos)
        black_list = sorted(black)
        print(len(black_list))
        print(' '.join(map(str, black_list)))

solve()
```このソリューションでは、まず入力を効率的に読み取ります。 Black cells are stored in a set to allow O(1) membership checks, critical for fast`B`コマンド。 の`while`ループアンダー`B`行全体をスキャンすることなく、次の白いセルが確実に見つかるようにします。 最後に並べ替えると、出力が確実に昇順になります。 セットを使用すると、重複した挿入が回避され、メンバーシップ テストの効率が維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各セルには最大 1 回アクセスします。`B`コマンドを実行し、n 個のコマンドを繰り返します。 |
 | スペース | O(m) | 黒のセルのみがセットに保存されます。 最後のソートでは内部的に O(m log m) が使用されますが、許容されます。 |
