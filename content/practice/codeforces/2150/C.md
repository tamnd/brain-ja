 ## 解決策
 ## 問題の理解

 アリスとボブという 2 人のプレイヤーが順番に店から物を選ぶ状況を分析するように求められています。 各オブジェクトには私たちの視点からの価値があり、各プレイヤーには独自の優先順位があります。 プレイヤーは自分の番が来たときに、まだ利用可能な最も優先度の高いオブジェクトを常に選択します。 最後に、アリスは購入したオブジェクトのサブセットを取得することになります。タスクは、私たちの評価に従って取得できるオブジェクトの価値の最大合計を計算することです。 

入力により複数のテスト ケースが得られます。 各テスト ケースでは、オブジェクトの数、その値、アリスとボブの優先順位を指定します。 各テスト ケースの出力は単一の整数、つまりアリスがすべての有効な購入シーケンスで取得できる最大合計です。 

制約は厳しいです。`n`テスト ケースごとに最大 2×10^5 になる可能性があり、すべてのテスト ケースの合計も 2×10^5 に達します。 これにより、テスト ケースごとにおよそ O(n log n) よりも悪いソリューションは除外されます。 オブジェクトを取得する方法の数は n とともに階乗的に増加するため、アリスとボブの選択のあらゆる可能なインターリーブをシミュレートする素朴な総当りはまったく実行不可能です。 

明らかではないエッジ ケースには、アリスの最上位の好みがすべて低いか負の値であるシーケンス、ボブが彼女をブロックする可能性のあるオブジェクトを選択するシーケンス、またはすべての値が負のシーケンスが含まれます。 たとえば、次の場合`v = [-5, -10, 1]`、`a = [3,1,2]`、`b = [1,2,3]`, アリスは合計を最大化するためにオブジェクト 3 だけを選択する必要があります。 彼女が常に最優先の希望を最初に取得すると仮定する不注意で貪欲なアプローチは、異なる選択をして、より低い金額を与える可能性があります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 テスト ケースごとに、考えられるすべての購入順序を生成し、アリスとボブのターンをシミュレートし、アリスが最終的に手に入れるオブジェクトの値の合計を追跡できます。 これは、すべてのシナリオを忠実にシミュレートするため機能しますが、O(n!) であり、2×10^5 までの n にとっては遅すぎます。 

重要な洞察は、逆の考え方から得られます。 すべてのシーケンスをシミュレートするのではなく、アリスの合計に重要な唯一の決定は、ボブがアイテムを取得する前にアリスが優先アイテムを取得できる瞬間であることに注意してください。 各オブジェクトは、アリスまたはボブが最初に選択したものによって特徴付けることができます。 ボブがアリスより早くアイテムを選んだ場合、アリスはそれを手に入れることができません。 アリスが最初に選んだ場合は、いつでも最終的にそれを取ることができます。 

アリスの優先リスト内のサブセットまたは位置に対する動的プログラミングを使用して、これをモデル化できます。 定義しましょう`dp[i]`アリスが自分のトップだけを考慮した場合に得られる最大額として`i`好みのアイテム。 私たちが彼女を処理するとき`i`- 番目の希望として、ボブが彼女より先にそれを受け取ったかどうかを決定します。 これにより、問題はアリスの優先順に線形スキャンされ、どのオブジェクトが利用可能な状態で残っているかが追跡されます。 配列を使用してボブが最も早く選択したものをマークすると、オブジェクトがアリスにとって安全かどうかを迅速に判断し、それに応じて最大合計を累積することができます。 これにより、複雑さはテスト ケースごとに O(n) にまで削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. オブジェクトごとに、ボブの好みリストにその位置を記録します。 これにより、アリスの選択と比較してボブがいつそれを選択するかを正確に知ることができます。 
2. アリスの設定リストを順番に繰り返します。 各オブジェクトについて、ボブのリスト内の位置を確認します。 
3. ボブがオブジェクトを取得する最も古いインデックスの実行変数を維持します。 ボブのインデックスがアリスのシーケンス内の現在のピックより前にある場合は、ボブがそれを取得するため、このオブジェクトをスキップします。 
4. それ以外の場合は、オブジェクトの値を累積合計に加算します。 
5. 反復の最後に合計を返します。これは、アリスがこのテスト ケースで達成できる最大合計を表します。 

維持される不変条件は、反復のどの時点でも、ボブがブロックする前にアリスが安全に選択できるすべてのオブジェクトを正確に考慮しているということです。 これにより、より高い金額を逃すことがなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        v = list(map(int, input().split()))
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # 0-based indexing
        a = [x-1 for x in a]
        b = [x-1 for x in b]
        
        # Position map: where does Bob pick each object
        pos_bob = [0]*n
        for idx, obj in enumerate(b):
            pos_bob[obj] = idx
        
        # Track the maximum sum Alice can get
        max_sum = 0
        # Current earliest Bob's pick that can block Alice
        min_bob_pos = n
        for obj in reversed(a):
            if pos_bob[obj] < min_bob_pos:
                max_sum += v[obj]
                min_bob_pos = pos_bob[obj]
        
        print(max_sum)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず設定リストを 0 から始まるインデックスに変換します。 ボブの位置マップが作成されるので、ボブがアリスより先にオブジェクトを選択するかどうかをすぐに確認できます。 アリスのリストを逆に繰り返すことで、ボブにブロックされることなくアリスが安全に取得できるオブジェクトを確実に選択します。 更新中`min_bob_pos`アリスが確保できるアイテムの値のみが蓄積されるようにします。
