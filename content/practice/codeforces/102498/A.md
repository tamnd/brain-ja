 ## 解決策
 ## 問題の理解

 出発点、目的地、およびいくつかの可能なレストランが座標平面上に配置されています。 旅行者は 1 秒あたり 1 単位の距離という一定の速度で移動し、目的地に到着するまでに 1 軒だけレストランを訪れる必要があります。 レストランを訪れると、食事には既知の秒数がかかるため、一定の待ち時間が追加されます。 課題は、合計移動時間が最小となるレストランを選択することです。 

レストランの場合`(x_i, y_i)`, 合計時間は、出発地からそのレストランまでの距離に食事の時間を加え、そのレストランから目的地までの距離を加えたものです。 移動速度は 1 なので、ユークリッド距離はそのまま移動時間を表します。 答えは、すべてのレストランにおけるこの値の最小値です。 

座標は絶対値で 1000 で区切られているため、距離は最大でも数千単位です。 レストランの数は 1000 に達する可能性があります。これは十分に小さい入力サイズであるため、すべてのレストランを 1 回チェックすることが簡単に可能です。 どのレストランに行くかだけが唯一の選択肢であるため、すべてのレストランを試してみるというソリューションはすでに不要です。 

よくある間違いは、目的地までの直線距離だけを比較し、食事の時間を無視することです。 待ち時間が短く、遠くにあるレストランが最適な選択となる可能性があります。 

例えば：```
0 0 10 0
2
5 0 100
8 0 1
```最初のレストランでは、`5 + 100 + 5 = 110`、一方、2番目は与えます`8 + 1 + 2 = 11`。 最も近いレストランを選択すると、間違った結果が生じる可能性があります。 

もう 1 つのエッジ ケースは、最高のレストランが出発地と目的地の間にない場合です。 レストランの食事時間が十分に短い場合、ルートは最初に移動する可能性があります。```
0 0 5 0
1
0 5 1
```時間は`sqrt(25) + 1 + sqrt(50) = 8.071067811865476`。 直接セグメント上にあるレストランのみを考慮するソリューションでは、唯一の可能性のあるレストランが誤って拒否されてしまいます。 

精度も重要です。 座標は整数ですが、距離は通常無理数です。 計算で浮動小数点数が使用され、十分な桁数が印刷される限り、通常の浮動小数点形式での印刷で十分です。 

## アプローチ

 簡単なアプローチは、すべてのレストランを個別に調査することです。 それぞれについて、出発地からレストランまでの距離を計算し、レストランの食事時間を加算し、レストランから目的地までの距離を加算します。 すべてのレストランの中で最小の値が答えです。 この方法は正しいです。すべての有効な旅行で 1 つのレストランを選択する必要があるため、考えられるすべての選択肢をチェックすることでソリューション スペース全体がカバーされます。 

レストラン間に隠れた相互作用がないため、総当りアプローチはすでに最適解と同じ構造を持っています。 2 つのレストランを訪れる理由はなく、1 つのレストランを訪れる費用が他のレストランに依存することもありません。 と`n = 1000`、これに必要な距離の計算は 1000 回だけであり、簡単です。 

すべてのレストランを独立して評価できるという観察により、問題を単純な最小限の検索に減らすことができます。 重要なのは、ここには経路探索の問題がないことを認識することです。 都市の座標には障害物や制限が含まれていないため、2 点間の最短経路は常に直線セグメントになります。

 ## アルゴリズムのチュートリアル

 1. 始点と終点を読み取ります。 すべてのレストランの計算には同じ 2 つのエンドポイントが必要であるため、それらを保存します。 
2. 応答を非常に大きな値で初期化します。 これは、レストランをチェックする前にこれまでに見つかった最良のルートを表します。 
3. レストランごとに、ユークリッド距離公式を使用して開始点からレストランまでの距離を計算します。 レストランの食事時間とレストランから目的地までの距離を追加します。 
4. このルートの長さを現在の回答と比較し、このレストランの合計時間が短い場合は回答を置き換えます。 
5. 精度要件を満たすのに十分な小数点以下の桁数を含む最終最小値を出力します。 

これが機能する理由は、問題全体における唯一の決定事項がレストランの選択であるためです。 レストランを選択したら、移動が制限されないため、レストランに到着してからレストランを出るまでの最適な方法は常に直線です。 アルゴリズムは考えられるすべての選択肢を 1 回だけチェックするため、アルゴリズムが保持する最小値が真の最適ルートとなります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    xs, ys, xt, yt = map(int, input().split())
    n = int(input())

    ans = float("inf")

    for _ in range(n):
        x, y, t = map(int, input().split())

        first = math.hypot(xs - x, ys - y)
        second = math.hypot(xt - x, yt - y)

        ans = min(ans, first + t + second)

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```解決策はアルゴリズムに直接従います。`math.hypot`はユークリッド距離の公式を明確に表現し、不要な中間コードを避けるため、手動で平方根を計算する代わりに使用されます。 

答えは無限大として始まるため、最初のレストランが常にそれを置き換えます。 すべてのレストランは個別に処理され、値の計算後にレストラン情報を保存する必要がないため、メモリ使用量が一定に保たれます。 

食べる時間は整数ですが、浮動小数点の距離に加算されます。 Python は、必要な精度を維持しながら、結果を浮動小数点値に自動的に変換します。 座標制限によりすべての二乗距離が非常に小さくなるため、オーバーフローの危険はありません。

## テストケース```python
import sys
import io
import math

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import math
    input = sys.stdin.readline

    xs, ys, xt, yt = map(int, input().split())
    n = int(input())

    ans = float("inf")

    for _ in range(n):
        x, y, t = map(int, input().split())
        ans = min(ans,
                  math.hypot(xs - x, ys - y) +
                  t +
                  math.hypot(xt - x, yt - y))

    result = "{:.15f}".format(ans)
    sys.stdin = old_stdin
    return result

 ## 特殊なケース

 問題の理解からの最初のエッジケースは、近くにあるが遅いレストランの存在です。 のために：```
0 0 10 0
2
5 0 100
8 0 1
```アルゴリズムは両方の選択肢を評価します。 最初のものは与えます`110`、2番目は与えます`11`、したがって、保存された最小値は次のようになります`11`。 食事時間も距離と同じ式に含まれるため、アルゴリズムは最寄りのレストランを選択するという罠にはまりません。 

2 番目のエッジ ケースは、ダイレクト パスの外側にあるレストランです。```
0 0 5 0
1
0 5 1
```アルゴリズムはレストランまでの距離を次のように計算します。`5`、食事時間を追加します。`1`、最終的な距離を加算します`sqrt(50)`。 場所によってレストランをフィルタリングすることはありません。そのため、おおよその情報が正確に返されます。`8.071067811865476`。 

最後のエッジケースは、距離が整数ではない場合です。 たとえば、斜めに動くサンプルには平方根が含まれています。 このアルゴリズムはすべての計算を浮動小数点値として保持し、小数点以下 15 桁を出力します。これは、必要な誤差許容度を十分に満たすのに十分です。
