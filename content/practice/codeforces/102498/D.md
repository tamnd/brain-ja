 ## 問題の理解

 私たちには山を開墾した根の生えた木があります。 クリアリング`1`がルートであり、他のすべての空き地には、山のより高い位置にある親が 1 つだけあります。 移動はノードからその子の 1 つへのみであるため、ヘリコプターがそのサブツリーに配置されたときに、クリアリングは正確にヘリコプターに到達できます。 

課題は、場所を選択することです。`k`ヘリコプターの下に少なくとも 1 つの選択されたノードがある開拓地の数ができるだけ多くなるようにします。 入力により、すべてのノードの親が提供されます。`2`に`n`、出力はヘリコプターが到達できる最大のクリアリング数です。 

制約`n <= 300000`使用できるソリューションの種類が完全に変わります。 多くのサブツリーまたは多くの選択肢に関する情報を保持する動的プログラミング ソリューションは、通常、大きすぎます。 平`O(n log n)`快適でありながら、`O(nk)`または`O(n^2)`ツリーには数十万の頂点が含まれる可能性があるため、これは不可能です。 

いくつかの詳細が素朴な考えを危険にさらします。 最初の罠は、任意の内部頂点を選択することです。 内部頂点に配置されたヘリコプターは、覆われた空き地を失うことなく、いつでもその子孫の葉の 1 つに深く移動できます。これは、古い位置に到達できるすべての祖先も、より深い位置に到達できるためです。 2 番目のトラップは、最も深いところにあると仮定しています。`k`深さによる頂点はそれだけで十分です。 異なるヘリコプターがルートへのパスを共有しているため、スコアは深さの合計ではありません。 たとえば、異なるブランチに配置された 2 台のヘリコプタは、同じ長い経路上の 2 台のヘリコプタよりもはるかに多くのヘリコプタをカバーする可能性があります。 

次の入力を考えてみましょう。```
5 1
1 2 3 4
```ツリーは 5 つのノードのチェーンです。 ヘリコプター1台でノードに配置`5`すべてのクリアリングをカバーするので、答えは次のとおりです。`5`。 カバーされるノードの 1 つとして葉だけを誤ってカウントする方法は、ここでは失敗します。 

もう 1 つの重要なケースはスターです。```
5 2
1 1 1 1
```根元から葉が4枚あります。 2 台のヘリコプターが根と選ばれた 2 枚の葉をカバーし、答えを出します`3`。 選択した 2 つの葉の深さを単純に加算する方法では、`2`ですが、ルートが共有されているため、実際の答えはさらに大きくなります。 

最後のエッジケースは、有用な目的地がヘリコプターよりも少ない場合です。 チェーンでは、1 台のヘリコプターを一番下に配置した後、追加のヘリコプターは何も寄与しません。 アルゴリズムは、すべてのヘリコプターが答えを増加させると仮定するのではなく、追加の寄与をゼロにすることを許可する必要があります。 

## アプローチ

 直接的なアプローチは、ヘリコプターの位置の可能なすべてのセットを試し、カバーされている祖先の数を計算することです。 これは、すべての有効な配置を検査するため、正しいです。 ただし、選んでも、`k`間の位置`n`ノードはすでに巨大な検索スペースを提供します。 ある木については、`300000`頂点、これは調査できる範囲をはるかに超えています。 

より実践的な最初の改善は、ヘリコプターを葉の中に配置する必要があることを観察することです。 ヘリコプタが内部ノードにある場合、ヘリコプタを子孫のリーフに移動すると、カバーされているすべてのノードが保持され、さらに多くのノードがカバーされる可能性があります。 これにより、問題は葉から根までのパスの選択に変わります。 

次に一般的なアイデアは、選択したリーフに対する動的プログラミングです。 小さな木の場合は、どの葉がすでに選択されているか、およびそれらのパスがどの程度重複しているかを保存できます。 問題は、リーフの数も多くなり、状態空間が高価になりすぎることです。 

重要な観察は、現在カバーされていない最も深い頂点を調べることで、次のヘリコプターの最適な位置を常に見つけることができるということです。 最も深い頂点を想像してください。`v`は選択されていません。 からの道をたどります`v`選択したヘリコプターによってすでにカバーされている最初の頂点に到達するまで、ルートに向かって移動します。 選択したヘリコプターを次のものに置き換えます`v`置換はそのミーティングポイントより上の同じ共有パスをカバーし、で終わる追加のサフィックスもカバーするため、答えを減らすことはできません。`v`。 したがって、利用可能な最も深い頂点を含む最適なソリューションが常に存在します。 

その頂点を選択すると、ルートへのパス上のすべての頂点がカバーされ、以降の選択では無視できます。 同じ議論がツリーの残りの覆われていない部分にも再び当てはまります。 このプロセスを繰り返すことで`k`回は最適な貪欲な構築を提供します。 

残りの課題は、このプロセスを効率的に実装することです。 最深部の頂点から根元までを繰り返し歩くとコストがかかる`O(nk)`。 代わりに、深さの降順で頂点を 1 回処理します。 頂点を考慮する場合は、現在マークされていない頂点のみを上に向かって歩き、すぐにマークを付けます。 各頂点は最大 1 回マークされるため、合計の作業は線形になります。

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取りながら、すべての空き地の深さを計算します。 後で頂点からルートに向かって上に移動する必要があるため、すべての頂点の親を保存します。 
2. すべての頂点を深さの降順に並べ替えます。 考慮される最初の頂点は、可能な限り最大の新しいカバレッジを与えることができる頂点です。 次のヘリコプタは常に最も深い残りの頂点に配置される必要があるため、この順序は貪欲な証明と一致します。 
3. 頂点全体で素のセット構造を維持します。`find(v)`からのパス上の最初のマークされていない頂点を返します。`v`上向きに。 頂点が覆われたら、その頂点をその上の次の頂点に直接接続します。 これにより、ツリーのすでにカバーされているセクションをスキップできます。 
4. ソートされた順序で頂点ごとに、マークのない頂点を繰り返し上に移動します。 見つかった頂点の数を数え、それらをカバー済みとしてマークします。 このカウントは、次のヘリコプターをそこに配置した場合に獲得できる追加のクリアリング数です。 
5. 取得したゲインをすべて保持します。 貪欲な議論は、このシミュレーションによってもたらされる利益はまさに最適な選択の寄与であると主張します。 最終的な答えは最大値の合計です`k`利益が得られます。 

なぜ効果があるのか:

 不変条件は、いくつかの貪欲な選択の後、マークされた頂点が、既に配置されているヘリコプターによってカバーされる空き地と正確に一致するということです。 マークされていない最も深い頂点は、常に最適な次の選択肢となります。これを使用しないソリューションでは、既存のカバレッジを失うことなく、パス上で選択した頂点の 1 つをこのより深い頂点に置き換えることができるからです。 したがって、すべての貪欲なステップは、任意の最適解から同じ頂点を選択するものに変換できます。 この交換議論を繰り返すと、アルゴリズムによって生成される一連のゲインが最適であることが証明されます。 素のセット構造は、すでにカバーされている頂点をスキップすることによって実装を変更するだけなので、貪欲な選択には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    parent = [0] * (n + 1)
    children = [[] for _ in range(n + 1)]

    if n > 1:
        p = list(map(int, input().split()))
        for i, x in enumerate(p, start=2):
            parent[i] = x
            children[x].append(i)

    depth = [0] * (n + 1)
    order = [1]
    for v in order:
        for u in children[v]:
            depth[u] = depth[v] + 1
            order.append(u)

    vertices = list(range(1, n + 1))
    vertices.sort(key=lambda x: depth[x], reverse=True)

    dsu = list(range(n + 1))

    def find(x):
        while dsu[x] != x:
            dsu[x] = dsu[dsu[x]]
            x = dsu[x]
        return x

    gains = []

    for v in vertices:
        cur = find(v)
        cnt = 0
        while cur != 0:
            cnt += 1
            dsu[cur] = find(parent[cur])
            cur = find(cur)
        gains.append(cnt)

    gains.sort(reverse=True)
    print(sum(gains[:k]))

if __name__ == "__main__":
    solve()
```深さを計算するにはルートからの走査が必要なため、ツリーは子リストを使用して保存されます。 反復トラバーサルにより、長さのチェーンにおける再帰の深さの問題が回避されます。`300000`。 

ソートのステップでは、欲張り証明で必要とされる順序どおりに頂点を配置します。 交換引数により最も深い残りの頂点を直接選択できるため、どの頂点がリーフであるかを明示的に知る必要はありません。 

素のセット配列の意味は、通常の接続 DSU とは少し異なります。 次に発見された祖先を保存します。 頂点のとき`x`カバーされるように設定します`dsu[x]`親の上にある最初のカバーされていない頂点に移動します。 今後の検索はスキップします`x`すぐに。 

while ループは、実行全体にわたってすべての頂点を 1 回だけカウントします。 すべての頂点のパスをたどることができるように見えますが、反復が成功するたびに、以前にマークされていないクリアがマークされるため、反復の総数は次の制限を受けます。`n`。 

答えは次から得られます。`k`最大の利益。 すべての有用なパスがカバーされた後の追加のヘリコプタは単にゼロを提供するだけです。そのため、ゲインの配列には多くのゼロが含まれる可能性があります。
