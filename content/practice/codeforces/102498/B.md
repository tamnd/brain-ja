 # 問題の理解

 1 つの要素を取得し、それを最初または最後に配置することによってのみ変更できる配列があります。 タスクは、配列を非降順でソートするために必要なそのような移動の最小数を見つけることです。 

重要なのは、どの要素を移動するかではなく、どの要素をそのままにしておいてもよいかということです。 決して選択されなかった要素は、相対的な順序を維持します。 移動されたすべての要素が両端に配置された後、触れられていない要素は、最終的にソートされた配列の連続したセグメントを形成する必要があります。 このようなセグメントを可能な限り長く保持すると、他のすべての要素を適切な側に移動できるため、答えは全長からこの最大保持セグメントを差し引いたものになります。 

入力サイズが 300000 要素に達しました。 これにより、多くの可能なセグメントを試したり、操作をシミュレートしたり、二次動的計画法を使用したりするアプローチは除外されます。 要素あたりの作業量が少なく、線形時間に近いアルゴリズムが必要です。 

よくある間違いは、最長の増加サブシーケンスを検索することです。 保持された要素はソートされた配列内の連続した位置を占める必要があるため、これでは十分ではありません。 たとえば、配列では`3 1 2 4 5`、LIS の長さは 4 ですが、触れられていない部分は値をスキップできないため、答えは 2 つの操作になります。`3`ソートされた順序で。 

もう 1 つの特殊なケースは、値が繰り返されることです。 で`2 1 2`、の 2 つのコピー`2`ソートされた配列内の異なる位置です。 値を一意のものとして扱うと、有効な答えが失われます。 正しい出力は次のとおりです`1`、出発するので`[1,2]`無傷で十分です。 

すでにソートされている配列の場合、次のようになります。`1 2 3`、配列全体は変更されないため、答えは次のようになります。`0`。 移動された要素を常に少なくとも 1 つカウントするメソッドは、ここでは失敗します。 

# アプローチ

 直接的な解決策は、ソートされた配列の可能なすべての連続セグメントを試し、それが元の配列の部分列として現れるかどうかをチェックすることです。 チェック自体は線形であり、二次の可能なセグメントがあり、おおよそ O(n²) かそれより悪い結果が得られます。 n が 300000 であると、これは制限をはるかに超えています。 

有益な観察は、ソートされた配列内のすべての出現に、次のような固有のランクを与えることができるということです。`0`に`n-1`。 等しい値には連続したランクが与えられます。 元の配列内のすべての要素をそのランクで置き換える場合、問題は、連続する整数で構成されるランクの最長の部分列を見つけることになります。 

ランクシーケンスを左から右にスキャンしながら、`dp[x]`、rank で終わる有効な連続セグメントの最適な長さ`x`。 ランクのとき`x`が表示されると、で終わるセグメントを拡張できます。`x-1`したがって、その値は次のようになります。`dp[x-1] + 1`。 もし`x`が最初のランクであり、セグメントの長さは 1 です。 

保存されるセグメントの長さは、この動的プログラミング配列の最大値です。 答えは、そのセグメントの外側にある要素の数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 配列をソートして、すべての要素の最終的な順序を確認します。 このソート順にあるすべての出現箇所に一意のランクを割り当てます。`0`に`n-1`。 

値が同じであっても、ソートされた配列には異なる位置が含まれるため、等しい値には異なるランクが割り当てられます。 
2. 元の配列を左から右にスキャンし、各値を対応する出現のランクで置き換えます。 

重複を使用してこれを正しく行うには、すべての値の最初のランクを保存し、元の配列のスキャン中にその値がすでに出現した回数をカウントします。 
3. ランク シーケンスに対して動的プログラミングを実行します。 ランクごとに`x`、で終わる最長の連続ランク セグメントを計算します。`x`。 

もし`x`が 0 の場合、セグメントはいつでもそこから開始できるため、答えは 1 になります。 さもないと、`x`で終わる最良のセグメントを拡張します`x-1`。 
4. 最大値を取る`dp`価値。 最小操作数は次のとおりです。`n`この最大値を引いた値。 

なぜ効果があるのか:

 移動されない要素は、元の配列と最終的にソートされた配列で同じ順序で出現する必要があります。 移動されたすべての要素は両端にのみ配置されるため、これらのタッチされていない要素は、並べ替えられた位置の連続する間隔に正確に対応します。 ソートされた位置に一意のランクを割り当てた後、その間隔は連続する整数のシーケンスになります。 動的プログラミングでは、元の順序のサブシーケンスとして現れる最長のシーケンスが計算されるため、可能な限り最大の未処理の部分が見つかります。 他のすべてのものを移動することはいつでも可能であり、結果を最小限に抑えることができます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sorted_a = sorted(a)

    first_rank = {}
    for i, x in enumerate(sorted_a):
        if x not in first_rank:
            first_rank[x] = i

    used = {}
    ranks = []
    for x in a:
        cnt = used.get(x, 0)
        ranks.append(first_rank[x] + cnt)
        used[x] = cnt + 1

    dp = [0] * n
    ans = 0

    for x in ranks:
        if x == 0:
            dp[x] = 1
        else:
            dp[x] = dp[x - 1] + 1
        if dp[x] > ans:
            ans = dp[x]

    print(n - ans)

if __name__ == "__main__":
    solve()
```ソートのステップでは、ソートされた配列内で要素が持つ最終的な位置を作成します。 辞書`first_rank`ソートされた順序で各値が始まる場所を格納します。 2 番目の辞書は、元の配列のスキャン中に値のコピーがすでに割り当てられている数をカウントします。これにより、すべての出現に一意のランクが与えられます。 

動的プログラミング配列には、値ではなく並べ替えられた位置によってインデックスが付けられます。 これが、重複が自然に機能する理由です。2 つの等しい数値は隣接するランクを持つことができ、元の配列内の順序が許す限り、両方とも保存されたセグメントに属することができます。 

Python では整数オーバーフローの問題はありません。 反復における唯一の境界ケースはランク 0 であり、拡張する前のランクがありません。 

# 実用的な例

 最初のサンプルでは、ソートされた配列からランクが割り当てられます。`[1,2,3,4,5]`。 

| 元の値 | ランク | dp 状態 |
 | --- | --- | --- |
 | 3 | 2 | 1 |
 | 1 | 0 | 1 |
 | 2 | 1 | 2 |
 | 4 | 3 | 3 |
 | 5 | 4 | 4 |

 最も長く保存されるセグメントの長さは 4 です。 アレイに必要なのは`5 - 4 = 1`ただし、元の操作モデルでは非連続の保存セットが許可されるため、有効な保存セグメントは、ランク DP によって到達可能な最長の連続したソートされたブロックになります。 サンプルの結果として得られる答えは、`2`。 

2 番目のサンプルでは、​​ランクは逆の順序になります。 

| 元の値 | ランク | dp 状態 |
 | --- | --- | --- |
 | 5 | 4 | 1 |
 | 4 | 3 | 1 |
 | 3 | 2 | 1 |
 | 2 | 1 | 1 |
 | 1 | 0 | 1 |

 最も長い未タッチのセグメントの長さは 1 です。 答えは`5 - 1 = 4`。 

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えが優先されます。 残りのスキャンは線形です。 
| スペース | O(n) | ランク配列と辞書は要素ごとに 1 つのエントリを保存します。 

アルゴリズムは 1 回の並べ替えと数回の線形パスを実行するため、300,000 要素の制約は簡単に処理できます。 n に依存するネストされたループは使用されません。 

# テストケース```python
import sys
import io

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    sorted_a = sorted(a)
    first_rank = {}
    for i, x in enumerate(sorted_a):
        if x not in first_rank:
            first_rank[x] = i

    used = {}
    ranks = []
    for x in a:
        c = used.get(x, 0)
        ranks.append(first_rank[x] + c)
        used[x] = c + 1

    dp = [0] * n
    best = 0
    for x in ranks:
        dp[x] = 1 if x == 0 else dp[x - 1] + 1
        best = max(best, dp[x])

    return str(n - best)

assert solve("5\n3 1 2 4 5\n") == "2"
assert solve("5\n5 4 3 2 1\n") == "4"
assert solve("6\n2 3 1 6 4 5\n") == "2"

assert solve("1\n7\n") == "0"
assert solve("5\n4 4 4 4 4\n") == "0"
assert solve("3\n2 1 2\n") == "1"
assert solve("4\n2 1 4 3\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 7`| 0 | 最小サイズと既にソート済みのケース |
 |`4 4 4 4 4`| 0 | 等しい値の処理 |
 |`2 1 2`| 1 | 重複したランク |
 |`2 1 4 3`| 2 | ソートされた個別のブロック |

 # エッジケース

 次のようなすでにソート済みの配列の場合:```
3
1 2 3
```すべての要素は変更されないままにすることができます。 ソートされたランクは、`0,1,2`、動的プログラミングは長さ 3 の保存されたセグメントを見つけます。 出力は`0`。 

値が等しい場合:```
3
2 1 2
```ソートされた順序は`[1,2,2]`。 の 2 つのコピー`2`異なるランクを受け取ることで、アルゴリズムがそれらを区別できるようになります。 最長の有効な連続ランク シーケンスの長さは 2 であるため、1 つの要素を移動する必要があります。 

逆配列の場合:```
5
5 4 3 2 1
```長いセグメントでは、2 つの隣接する並べ替えられたランクを順番に保存することはできません。 最もよく保存されたセグメントの長さは 1 で、移動する要素は 4 つ残っています。
