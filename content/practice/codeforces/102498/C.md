 ## 解決策
 ## 問題の理解

 ボードには、空のセル、固定中心、回転可能なハンドルの 3 種類のセルが含まれています。 すべてのハンドルには 2 つの方向のいずれかを割り当てる必要があります。 垂直ハンドルは、その列に沿って移動すると最終的に中心に到達し、その中心より前のすべてのセルが別の垂直ハンドルである場合にのみ有効です。 水平ハンドルは、その行に沿って同じルールに従います。 

課題は、すべてのハンドルの方向を選択するか、そのような選択肢が存在しないことを証明することです。 すべての行と列の中心が最大 1 つだけであるという制限が、重要な構造特性です。 これにより、水平方向と垂直方向の可視性を個別に推論できます。 

サイズ制限は`n <= 500`, したがって、グリッドには最大 250,000 個のセルが含まれます。 ハンドルの数も約 250,000 になる可能性があるため、すべての可能な方向を試すアルゴリズムは不可能です。`2^250000`可能な状態。 多数のセルのペアを繰り返しチェックするアルゴリズムであっても、速度が非常に遅くなる可能性があります。 セル数が線形に近い解決策が必要です。 

扱いにくいケースは、行または列に中心がないハンドルだけではありません。 ハンドルは可能な両方の方向を個別に持つことができますが、別のハンドルではそれらの方向のいずれかを強制的に不可能にすることができます。 

例えば：```
3
.+.
O++
.O.
```正しい答えは次のとおりです。```
No
```上部中央のハンドルは垂直のみ可能です。 中央の行の右端のハンドルは水平のみであるため、その行の中央のハンドルも強制的に水平になります。 上部ハンドルが下部中央に到達するには、同じ中央ハンドルが垂直である必要があり、矛盾が生じます。 

別のケースは次のとおりです。```
1
+
```答えは次のとおりです。```
No
```どこにも中心がないため、唯一のハンドルには有効な方向がありません。 

各ハンドルを個別にチェックするだけの不注意なソリューションでは、これらの対話を見逃してしまいます。 

## アプローチ

 直接的な総当りのソリューションでは、考えられるすべての割り当てを試みます。`|`そして`-`ハンドルに。 割り当てごとに、中心または無効なセルに到達するまで選択した方向に歩き、すべてのハンドルを検証します。 これは正しいロック状態の定義を正確にチェックするためです。 ただし、ハンドルが最大 250,000 個になると、割り当ての数は指数関数的に増加します。`2^250000`、それは不可能です。 

有益な観察は、各方向の選択が論理的な意味のみを生み出すということです。 ハンドルが水平の場合、そのハンドルと同じ行の中心との間にあるすべてのハンドルも水平でなければなりません。 同様に、ハンドルが垂直の場合、そのハンドルと同じ列の中心との間のすべてのハンドルも垂直でなければなりません。 

中心は行と列内で一意であるため、これらの意味は単純なチェーンを形成します。 たとえば、次のように続けます。```
O + + + .
```右端のハンドルが水平であるということは、前のハンドルが水平であることを意味し、前のハンドルが水平であることを意味します。 すべてのハンドルから他のすべてのハンドルへのエッジは必要ありません。隣接する意味だけが必要です。 

これにより、問題は 2-SAT に変換されます。 各ハンドルはブール変数です。 私たちは解釈できる`true`水平方向と`false`垂直として。 すべての含意は含意グラフに追加され、不可能な方向は強制的な false 値または強制的な true 値として表されます。 満足のいく課題は、必要な指示を与えてくれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^k * n^2)`|`O(n^2)`| 遅すぎる |
 | 最適 |`O(n^2)`|`O(n^2)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ハンドルごとに 1 つのブール変数を作成します。 真の状態は水平方向を意味します。 
2. 含意グラフを構築します。 すべての中心について、その行を両方向にスキャンします。 中心から見える連続したハンドルは、さらに水平なハンドルには前のハンドルも水平である必要があることを意味します。 列と垂直方向についても同様の意味を追加します。 

隣接する含意だけで十分である理由は、含意の連鎖がセグメント全体に自動的に伝播するためです。 
3. すべてのハンドルについて、水平方向が可能かどうか、垂直方向が可能かどうかを確認します。 方向がどの中心にも到達できない場合は、この方向を禁止する暗示を追加します。 
4. 含意グラフの強く接続されたコンポーネントを見つけます。 変数とその否定が同じコンポーネント内にある場合、制約は互いに矛盾し、答えは不可能になります。 
5. それ以外の場合は、コンポーネントの順序から満足のいく割り当てを取得して印刷します。`-`水平ハンドル用と`|`縦ハンドル用。 

なぜ効果があるのか:

 含意グラフには、ロックに必要な条件が正確に含まれています。 その方向の前にあるすべてのハンドルが整列しない限り、ハンドルは中心に到達できないため、有効な配置はすべての意味を満たさなければなりません。 逆に、必要なすべての先行ハンドルが同じ方向を持つように強制されるため、意味が満足できる割り当てであれば、すべてのハンドルの選択された方向が有効になります。 SCC チェックは 2-SAT の標準的な正当性条件です。矛盾は、変数が値とその反対の両方を意味する場合に正確に存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(input().strip()) for _ in range(n)]

    pos = {}
    idx = 0
    for i in range(n):
        for j in range(n):
            if a[i][j] == '+':
                pos[(i, j)] = idx
                idx += 1

    m = idx
    g = [[] for _ in range(2 * m)]
    rg = [[] for _ in range(2 * m)]

    def add_edge(u, v):
        g[u].append(v)
        rg[v].append(u)

    def h(i):
        return 2 * i

    def v(i):
        return 2 * i + 1

    def add_same(x, y, horizontal):
        if horizontal:
            add_edge(h(x), h(y))
            add_edge(v(y), v(x))
        else:
            add_edge(v(x), v(y))
            add_edge(h(y), h(x))

    can_h = [False] * m
    can_v = [False] * m

    for r in range(n):
        c0 = -1
        for c in range(n):
            if a[r][c] == 'O':
                c0 = c
                break
        if c0 != -1:
            last = -1
            for c in range(c0 - 1, -1, -1):
                if a[r][c] == '.':
                    last = -1
                elif a[r][c] == '+':
                    x = pos[(r, c)]
                    can_h[x] = True
                    if last != -1:
                        add_same(x, last, True)
                    last = x
            last = -1
            for c in range(c0 + 1, n):
                if a[r][c] == '.':
                    last = -1
                elif a[r][c] == '+':
                    x = pos[(r, c)]
                    can_h[x] = True
                    if last != -1:
                        add_same(x, last, True)
                    last = x

    for c in range(n):
        r0 = -1
        for r in range(n):
            if a[r][c] == 'O':
                r0 = r
                break
        if r0 != -1:
            last = -1
            for r in range(r0 - 1, -1, -1):
                if a[r][c] == '.':
                    last = -1
                elif a[r][c] == '+':
                    x = pos[(r, c)]
                    can_v[x] = True
                    if last != -1:
                        add_same(x, last, False)
                    last = x
            last = -1
            for r in range(r0 + 1, n):
                if a[r][c] == '.':
                    last = -1
                elif a[r][c] == '+':
                    x = pos[(r, c)]
                    can_v[x] = True
                    if last != -1:
                        add_same(x, last, False)
                    last = x

    for i in range(m):
        if not can_h[i]:
            add_edge(h(i), v(i))
        if not can_v[i]:
            add_edge(v(i), h(i))

    order = []
    seen = [False] * (2 * m)

    sys.setrecursionlimit(1000000)

    def dfs(x):
        seen[x] = True
        for y in g[x]:
            if not seen[y]:
                dfs(y)
        order.append(x)

    for i in range(2 * m):
        if not seen[i]:
            dfs(i)

    comp = [-1] * (2 * m)

    def rdfs(x, c):
        comp[x] = c
        for y in rg[x]:
            if comp[y] == -1:
                rdfs(y, c)

    c = 0
    for x in reversed(order):
        if comp[x] == -1:
            rdfs(x, c)
            c += 1

    ans = [['.' for _ in range(n)] for _ in range(n)]
    for (r, col), x in pos.items():
        if comp[h(x)] == comp[v(x)]:
            print("No")
            return
        if comp[h(x)] > comp[v(x)]:
            ans[r][col] = '-'
        else:
            ans[r][col] = '|'

    for i in range(n):
        for j in range(n):
            if a[i][j] == 'O':
                ans[i][j] = 'O'

    print("Yes")
    for row in ans:
        print(''.join(row))

solve()
```プログラムは、2-SAT グラフがコンパクトな整数ノードを使用できるように、最初にすべてのハンドルにインデックスを割り当てます。 各変数には 2 つのグラフ ノードがあります。1 つは水平方向、もう 1 つは垂直方向です。 

行と列のスキャンにより、含意グラフが構築されます。 変数`last`表示されているチェーンに最も近い前のハンドルを保存します。 隣接するハンドルのみをリンクすると、同じ推移的な情報を維持しながら、2次数のエッジの作成が回避されます。 

不可能な方向は、その方向からその反対方向への含意を追加することによって処理されます。 SCC フェーズは矛盾を検出し、有効な割り当てを再構築するために必要な順序付けも行います。 

この実装では、反復入力処理を使用し、元のボードよりも大きいグリッド派生構造の保存を回避します。 含意グラフには長いチェーンが含まれる可能性があるため、Python の再帰の深さが増加します。

1
