 ## 解決策
 ## 問題の理解

 価値のある一枚の紙幣から始まります$A$そして、最終的には正確に支払うことができるようにしたいと考えています。$B$、 どこ$A > B$。 利用できる唯一のツールは自動販売機です。私たちは商品にある程度のお金を使いますが、自動販売機はおつりを返してくれます。 重要な問題は、変更が常に有効な中国の通貨単位で構成され、常に合計が正確に正しい余りになることを除いて、変更の構造が予測できないことです。 

私たちは、管理された方法で過剰支払いを行うことで、有用なコインのセットを「製造」することが許可されています。 このような一連の操作の後、コインの合計を正確に組み立てることができることを保証したいと考えています。$B$、機械が小銭を有効な額面に分割する方法に関係なく。 

すべての値は中国の通貨単位の標準セットに制限されるため、状態空間は連続的ではありません。 問題は本質的に、「変化が最悪の分解に陥った場合でも、形成に必要なすべての単位を再構築できるように、システムに注入しなければならない「無駄」の最小量は何か」を問うことです。$B$。 

制約は、テスト ケースの観点ではなく、個別の宗派の観点からは小さいため、$O(1)$または、テスト ケースごとに非常に小規模な制限された計算が予想されます。 組み合わせの探索や複数のステップにわたる為替のシミュレーションに依存するアプローチは、宗派や中間状態に応じて拡張する場合には遅すぎますが、ここでは固定通貨システムが貪欲な構造または桁単位の構造を強く示唆しています。 

微妙なエッジケースが現れるのは、$A$よりもわずかに大きいです$B$。 たとえば、次の場合$A = 1$そして$B = 0.99$、任意の変更動作を仮定した場合、最適な戦略は明らかではありません。 素朴な考えでは、コインの分割をシミュレートしたり、決定論的な変化を想定したりするかもしれませんが、変化の分配には敵対的な性質があるため、最悪の場合の分解の観点から推論する必要があります。 

## アプローチ

 強引な解釈では、アイテムを購入する考えられるそれぞれの方法をコインのマルチセットを生成するものとして扱い、そのマルチセットを常に次のように再配置できるかどうかをチェックします。$B$。 それぞれの購入により多くの変更結果が生じる可能性があるため、これはすぐにすべての構成にわたる分岐プロセスに変わります。$A - x$、 どこ$x$選択した購入価格です。 単一のステップであっても、金額の合計を剰余に加える有効な組み合わせが可能なため、有効な小銭分解の数は多くなります。 これを複数の購入に拡張すると、到達可能なすべてのコインのマルチセットを追跡する必要があるため、状態空間が組み合わせ的に爆発します。 これは明らかに実行不可能です。 

重要な観察は、実際には変化の正確な分布は気にしておらず、形成を保証できるかどうかだけを気にしているということです。$B$最悪の場合。 これにより、問題は固定の正規コイン システムの適用範囲の問題に変換されます。 重要な構造は、通貨単位が標準的であり、2 と 5 の因数で入れ子になっているということです。これは、あらゆる金額を貪欲な表現に正規化できることを意味し、お釣りの分布の不確実性は、各単位レベルが十分に「カバー」されているかどうかにまで低減できます。 

私たちは、変化をシミュレートするのではなく、すべての宗派のレベルが代表するために必要とされるものを確保するという観点から考えます。$B$、小銭がどのように分割されたかに関係なく、そのレベルの少なくとも 1 つのコインを強制的に利用可能にすることができます。 これにより、通貨構造によって定義された混合基本システムでの桁ごとの推論が行われます。 

最適な戦略は、どこまで到達するかを分析することに帰着します。$A$からです$B$額面のしきい値の観点から、それらのしきい値を超えたキャリーを保証するために必要な最小限の超過支払額を決定します。

 ## アルゴリズムのチュートリアル

 浮動小数点の問題を回避するために、最初にすべての値を整数 fen 単位に正規化します。 各額面は 1 フェンの整数倍となり、固定セットを形成します。 

1.変換$A$そして$B$整数の fen 値に変換します。 

これにより、精度の問題が解消され、コインの価値を直接計算できるようになります。 
2. ギャップを計算する$D = A - B$。 

これは私たちが持っている余剰の合計を表しており、いかなる戦略もこの余剰の範囲内で機能する必要があります。 
3. 表示が不安定になる最小額面のしきい値を特定します。 

私たちは額面を最大額から最小額までスキャンし、そのギャップが境界線を越えていないかどうかを推論し、小銭が予想外に小さなコインに分割される可能性があります。 
4. 最低過払い額を決定する$x$支払った後のように$x$、最悪の場合の変更でも、少なくとも次の再構築は可能です。$B$。 

直観的には、わずかに払いすぎた場合、レジ係は小銭に高額な額面のコインを含めざるを得なくなります。そうしないと、敵対的な分割で低い額面の合計を正しく合計できなくなるからです。 
5. 最小の値を出力します。$x$。 

構造上の重要なステップは、自動販売機の敵対的な分割が宗派の境界でのみ重要であることを認識することです。 より高い額面へのキャリーを強制するのに十分な「ヘッドルーム」を確保すると、すべてのより小さな額面が再構築可能になります。 

### なぜ効果があるのか

 中国の宗派のシステムは階層的であり、フェン単位で表示すると、あらゆる金額を独自の方法で貪欲に分解できます。 敵対者は、小銭の分割方法にのみ影響を与えることができ、残りを表すために存在する必要がある各額面スケールの合計額には影響を与えません。 購入後の残りの価値は、少なくとも 1 つの高額な額面のコインを強制することなく、純粋に低い額面で表現できないことを保証することで、結果として得られるマルチセットが常に、次のように再配置できる正規表現にまたがることを保証します。$B$。 このアルゴリズムは、釣銭がどのように分割されるかに関係なく、必要なすべての額面レベルが強制的に存在することを効果的に保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DENOMS = [10000, 5000, 2000, 1000, 500, 200, 100, 50, 20, 10, 5, 2, 1]

def to_fen(x):
    # input is decimal like 0.01, 1, 0.1 etc
    return int(round(float(x) * 100))

def solve_case(A, B):
    a = to_fen(A)
    b = to_fen(B)

    if a == b:
        return 0

    # we want minimal x such that after spending x,
    # remaining structure always allows forming b
    # key idea: check smallest "forcing" overpay
    need = a - b

    # try candidate answer from smallest denomination upward
    # (since answer must be a denomination)
    ans = None

    for d in DENOMS[::-1]:
        # try forcing at this denomination scale
        # minimal spend that forces rounding/carry behavior
        if d >= need:
            ans = d - (need % d if need % d != 0 else d)
            break

    return ans if ans is not None else need

def main():
    T = int(input())
    for tc in range(1, T + 1):
        A, B = input().split()
        res = solve_case(A, B)
        print(f"Case #{tc}: {res/100:.2f}")

if __name__ == "__main__":
    main()
```The solution converts all currency values into integer fen units so that denomination reasoning becomes exact. コアの計算は、宗派の境界のみが重要であるという観察に基づいて行われるため、考えられるしきい値を大きいものから小さいものまで繰り返します。 

変数`need`私たちが持っているものと構築できなければならないものの違いを表しています。 ループオーバー`DENOMS`強制キャリーが発生する可能性がある最小単位スケールを見つけようとします。 表現`d - (need % d)`残りが宗派の境界に一致するように支出を調整する必要がある金額を把握します。これにより、最悪の場合の変更でも構成可能性が維持されます。$B$。 

出力は、問題のステートメントと一致するように、10 進数 2 桁の CNY に再フォーマットされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    DENOMS = [10000, 5000, 2000, 1000, 500, 200, 100, 50, 20, 10, 5, 2, 1]

    def to_fen(x):
        return int(round(float(x) * 100))

    def solve_case(A, B):
        a = to_fen(A)
        b = to_fen(B)
        need = a - b
        if need == 0:
            return 0

        ans = None
        for d in DENOMS[::-1]:
            if d >= need:
                if need % d == 0:
                    ans = 0
                else:
                    ans = d - (need % d)
                break
        return ans

    T = int(input())
    out = []
    for i in range(T):
        A, B = input().split()
        res = solve_case(A, B)
        out.append(f"Case #{i+1}: {res/100:.2f}")
    return "\n".join(out)

 ## 特殊なケース

 微妙なエッジケースは、$A$そして$B$はすでにまさに額面金額です。 この場合、敵対的な分割によって形成が妨げられることはないため、アルゴリズムは正しくゼロを返す必要があります。$B$。 

たとえば、入力の場合$A = 1$、$B = 0.5$、 我々は持っています$need = 0.5$。 0.5 は有効な単位であるため、お釣りには直接使用できるコインが含まれている必要があり、追加の出費は必要ありません。 

もう 1 つのエッジケースは次のような場合です$A$そして$B$1フェン程度の非常に小さな量の差です。 ここでは、アルゴリズムにより常に最小額面レベルが考慮され、敵対的な分割によっても必要な金額を再構築する能力が損なわれないことが保証されます。
