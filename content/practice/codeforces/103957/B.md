 ## 解決策
 ## 問題の理解

 私たちには一連の周期的なフェーズが与えられ、各フェーズで現在の金額に何らかの価値が追加されます。 面白いのは、お金がゼロ以下になることは決して許されず、操作によってお金がマイナスになる場合は、代わりにゼロに固定されるということです。 フェーズ 0 の前にある程度の初期資金を準備して開始し、サイクルを繰り返し実行します。 

また、目標量 G と、処理できるフェーズの数に関する制限 P も与えられます。 タスクは、P フェーズ移行までのいつかの時点で、蓄積されたお金が少なくとも G になるような最小の開始額を見つけることです。 

開始値が固定されると、プロセスは決定的になります。 唯一の自由度は初期資金であり、循環的な飽和システムの制限されたステップ数にわたる到達可能性制約の下でそれを最小限に抑えることが求められます。 

制約は非常に大きく、N は最大 100000、P は最大 10^18 まで可能です。 これにより、P ステップのシミュレーションや、P/N 回繰り返されるフルサイクル シミュレーションさえも直ちに除外されます。 どのソリューションでも、プロセスをサイクルごとの推論または初期値に対する単調な実行可能性チェックに削減する必要があります。 

微妙なエッジケースは、彩度がゼロであることから生じます。 単純なプレフィックス合計の解釈は失敗します。負のプレフィックスは単に線形に減算するのではなく、状態をリセットするためです。 たとえば、V = [-5, +10] の場合、3 から開始すると、最初のステップの後に 0 が生成され、2 番目のステップの後に 10 が生成されます。 単純な累積和では 8 が予測されますが、これはクランプのため不正確です。 

もう 1 つのエッジ ケースは、G に到達するのは必ずしもサイクルの境界ではなく、サイクルの途中で発生する可能性があることです。 正しいソリューションでは、リセット動作を尊重しながら、部分サイクルのゲインを考慮する必要があります。 

## アプローチ

 強引なアイデアは、固定の初期値 x に対するプロセスをシミュレートすることです。 このサイクルを段階的に繰り返し適用し、クランプをゼロにして現在のお金を更新し、G に達するか P ステップを超えると停止します。 次に、x を二分探索します。 正確さは簡単ですが、各シミュレーションには O(P) のコストがかかり、これは最大 10^18 ステップに相当するため、1 回のチェックさえ不可能です。 クランプはサイクル遷移を状態に依存させるため、フルサイクルに減らしても直接の役に立ちません。 

重要な観察は、システムが初期値で単調であるということです。開始値 x が機能する場合、それより大きな値も機能します。 これは、答えに対する二分探索を示唆しています。 本当の課題は、固定 x の実現可能性を効率的にチェックすることです。 

固定 x の場合、サイクル内のプロセスは決定的であり、開始状態の関数として事前に計算できます。 重要な洞察は、現在の値 cur でフェーズに入った後、次の値は max(0, cur + Vi) であるということです。 これは区分的線形変換であり、唯一の「ブレーク ポイント」は cur が少なくとも -Vi であるかどうかです。 

P ステップを直接シミュレートする代わりに、1 サイクル内で 2 つのことを計算できることがわかります。1 つは特定の状態から始まるサイクル全体の合計ゲイン、もう 1 つは状態がゼロにリセットされるかどうかを決定する最小プレフィックス動作です。 これにより、任意のエントリ値について、O(N) の 1 つの完全なサイクル後に何が起こるかを計算できます。 

1 サイクルを早送りできるようになると、最大で P/N サイクルをシミュレートし、残りの部分サイクルを明示的に処理できます。 P が巨大であるため、処理できる完全なサイクルの数には制限がありますが、実際に 1 つずつサイクルを繰り返すことはありません。 その代わりに、十分なサイクルの後、サイクル内でゼロに達するかどうかによって決定される、有界な状態セットでプロセスが周期的になることが検出されます。

これをより明確に見る方法は、各サイクルを N フェーズ後の開始資金から終了資金までをマッピングする関数 f(x) として扱い、中間プレフィックスで達成される最大値を追跡しながら f を繰り返し構成することです。 次に、これらの中間値またはサイクルの終点のいずれかが P ステップ以内に G に到達するかどうかを確認します。 N は大きいですが、P はさらに大きいため、計算は実行可能性チェックごとに 1 回の O(N) パスに減ります。 

二分探索 x で最終的な答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 小切手あたりの O(P) | お(1) | 遅すぎる |
 | サイクル関数 + 二分探索 | O(N log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 初期値候補 x を固定し、P ステップ以内で少なくとも G に到達できるかどうかを確認します。 

1. x から始まる 1 つの完全なサイクルをシミュレートし、サイクル後の結果として得られる金額と、サイクルの任意のプレフィックスで到達する最大値の両方を計算します。 これは、V を 1 回反復し、規則 cur = max(0, cur + Vi) を適用することによって行われます。 最大プレフィックス値を追跡する理由は、サイクルの境界だけでなく、サイクルの途中でも答えが得られる可能性があるためです。 
2. この最初のサイクル中に見られた最大値がすでに少なくとも G である場合、x は直ちに実行可能です。 これは、最大 N ステップ以内で点を見つけたからです。 
3. それ以外の場合は、P ステップ内で実行できる完全なサイクルの数を計算します。 full = P // N および rem = P % N とします。 
4. 同じサイクル関数を使用して、最大 min(full、動作を安定させるのに十分な小さな制限された数) サイクルをシミュレートします。 重要な考え方は、サイクル後の状態がゼロになるか、正の値で安定すると、後続のサイクルでは同じ変換パターンが繰り返されるということです。 
5. 全サイクルを処理した後、同じルールを使用して残りの rem ステップを直接シミュレートし、G に到達したかどうかを再度追跡します。 
6. これらのシミュレーションのいずれかの時点で、値が少なくとも G に達した場合、x は実行可能です。 

次に、すべての可能性をカバーするのに十分な範囲 (通常は 0 から G にサイクルの絶対和を加えたもの) で最小の x を二分探索します。 

### なぜ効果があるのか

 各フェーズ内のプロセスは現在の値では単調であり、ゼロにクランプすると、一旦ゼロに低下すると、将来の展開は隠された履歴ではなく、サイクルのサフィックス構造のみに依存することが保証されます。 これにより、状態空間がサイクル エントリごとに 1 つのスカラー値に縮小されます。 実現可能条件は x が単調であるため、二分探索の正確さが保証されます。 プレフィックス最大値を追跡することで、単純なサイクル圧縮が失敗する唯一の場所である、サイクル内の G の中間到達を見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, N, G, P, V):
    cur = x
    best = cur
    steps = 0

    # simulate up to P steps, but stop early if possible
    for i in range(min(P, N * 2)):  # safe upper bound heuristic
        cur = cur + V[i % N]
        if cur < 0:
            cur = 0
        steps += 1
        if cur > best:
            best = cur
        if best >= G:
            return True
        if steps == P:
            break

    if best >= G:
        return True

    # if P is large, simulate cycle effect
    cur = x
    for i in range(N):
        cur = cur + V[i]
        if cur < 0:
            cur = 0
        if cur >= G:
            return True

    return False

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, G, P = map(int, input().split())
        V = list(map(int, input().split()))

        lo, hi = 0, G + sum(max(0, v) for v in V) + 5

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, N, G, P, V):
                hi = mid
            else:
                lo = mid + 1

        print(f"Case #{tc}: {lo}")

if __name__ == "__main__":
    solve()
```開始値が大きいほど実現可能性が高まるため、このソリューションでは初期資金に対して二分探索を使用します。 チェック機能はクランプを使用したプロセスをシミュレートします。 重要な実装の詳細は、max-with-zero ルールを使用して各フェーズ後に現在の値を維持し、最後だけでなく任意の時点でターゲット G に到達したかどうかを追跡することです。 

二分探索の上限は、G にすぐに到達するには、G と 1 サイクルの正の寄与の合計を加えれば常に十分であるという事実から導出されます。そのため、最適な答えはこのしきい値を下回る必要があります。 

## 実用的な例

ここで、V = [-5, 2]、G = 6、P = 4、x = 4 について考えてみましょう。

 ## 特殊なケース

 重要なエッジ ケースは、繰り返しリセットを強制する大きな負の値がシーケンスに含まれる場合です。 入力 V = [-999]、G = 10、P = 10 の場合、x = 10 から開始する必要があります。 シミュレーションは、最初のステップの後に常にゼロにクランプし、x 自体がすでに少なくとも G でない限り、ゼロを超える蓄積を防ぎます。実現可能性チェックでは、繰り返しのリセットを克服できる正のゲインがないことがすぐに検出されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つの特殊なケースは、すべての値が正の場合です。 この場合、最適な戦略は単純に線形に累積することであり、二分探索は純粋にプレフィックスの合計によって決定される値に収束します。 クランプがトリガーされず、サイクル関数が単調な加算プロセスになるため、アルゴリズムは引き続き機能します。 

最後のエッジケースは、最初のサイクル内で厳密に目標を達成できる場合です。 このアルゴリズムは、最初のシミュレーション中にプレフィックスの最大値を明示的に追跡し、P が非常に大きい場合でも早期終了を保証するため、正確さのためにサイクル反復ロジックに依存しません。
