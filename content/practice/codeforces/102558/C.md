 ## 解決策
 ## 問題の理解

 私たちはビーチチェアのコレクションを持っており、各椅子にはその外観の特徴を説明する番号が付けられています。 このタスクは、XOR 値が可能な限り小さい番号を持つ 2 つの異なる椅子を選択することです。 XOR は、2 つの数値がバイナリ形式でどの程度異なっているかを測定するため、目的は最も重要でない点で異なるペアを見つけることです。 

入力には複数のテスト ケースが含まれています。 各テスト ケースの最初の値は椅子の数を示し、その後にそれらの椅子に割り当てられた特徴値が続きます。 各テスト ケースの出力は、任意の 2 つの異なる椅子を比較することによって取得できる最小の XOR 値です。 

すべてのテスト ケースにわたる値の合計数は次のとおりです。\(10^6\)。 これにより、すべてのペアのチェックが直ちに除外されます。\(n^2\)オペレーションは近づきます\(10^{12}\)これは、一般的な競技プログラミングの制限をはるかに超えています。 線形または\(n \log C\)、 どこ\(C\)数値の可能な最大値です。 すべての値は最大であるため、\(10^9\)、約 30 個の 2 進数のみが重要です。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 2 つの椅子の値がまったく同じである場合、XOR は 0 であるため、答えは 0 になります。 たとえば、入力```
1
3
7 7 12
```出力があります```
0
```重複を正しく処理せずに並べ替え後に隣接する値のみをチェックするソリューションでは、これが見逃される可能性があります。 

もう 1 つのケースは、数値的に最も近い 2 つの値によって最小のペアが形成されない場合です。 例えば、```
1
4
1 2 8 16
```出力があります```
3
```最良のペアは 1 と 2 です。それらの数値の差は小さいですが、XOR が実際のメトリックであるため、減算だけで推論するのは十分ではありません。 

3 番目のエッジ ケースは、値が大きく、上位ビットを使用する場合に発生します。 例えば、```
1
2
0 1000000000
```出力があります```
1000000000
```チェックするビットが少なすぎるバイナリ トライの実装は、値が近似するため失敗します。\(10^9\)30ビットが必要です。 

## アプローチ

 直接的な解決策は、考えられるすべての椅子のペアを比較することです。 インデックスのペアごとに\(i\)そして\(j\)、計算します\(a_i \oplus a_j\)そして最小の結果を維持します。 このアプローチは文字通り、考えられるすべての回答候補を調べるため、正しいです。 問題はペアの数です。 と\(n = 10^6\)、比較の数は約\(5 \times 10^{11}\)、時間内に終えるのは不可能です。 

XOR の構造は、より良い方向性を与えてくれます。 固定数値との XOR を最小限に抑えるには、他の数値もできるだけ同じビット (特に最上位ビット) を持つようにします。 上位ビットの差は、下位ビットの差よりも最終的な XOR 値に大きく影響します。 

バイナリ トライでは、数値をビットごとに格納します。 最上位ビットから始めてトライをたどることができ、常に現在の数値と同じビットを含む分岐を優先します。 そのような分岐が存在する場合、そのビットは XOR にゼロを与えます。 一致する分岐が欠落している場合にのみ、反対のビットを取得する必要があり、そのビットの値を答えに追加します。 

ブルートフォース手法は、考えられるすべてのパートナーをチェックするため機能しますが、作業の繰り返しが多すぎるため失敗します。 トライには、各数値に対して最適な選択を行うために必要な情報が個別に保存され、すべてのペアからの検索が約 30 レベルにわたる 1 回の走査に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | バイナリトライ | O(30n) | O(30n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のバイナリ トライを作成します。 各ノードは、挿入された数値のバイナリ表現のプレフィックスを表します。 ノードには最大で 2 つの子があり、1 つはビット 0 で、もう 1 つはビット 1 です。 

2. 最上位ビットから最下位ビットまでビットを処理して、最初の数値をトライに挿入します。 各ビットで、必要な子が存在しない場合は作成します。 

3. 後続のすべての数値について、その数値との最小の XOR を生成する値をトライで検索します。 各ビット位置で、トライに現在の数値と同じビットが含まれているかどうかを確認します。 存在する場合は、現在の XOR ビットが 0 に等しくなるため、その分岐に従います。 それ以外の場合は、反対の分岐に従い、このビットの値を現在の XOR 結果に加算します。 

4. 現在の番号に最適なパートナーを見つけたら、グローバル最小の答えを更新し、現在の番号をトライに挿入します。 

5. すべての数値が処理された後に見つかった最小値を出力します。 

検索で同​​じビットを貪欲に選択できる理由は、2 進数が重要度によって比較されるためです。 上位ビットでの差は、下位ビットでの選択によって補償することはできません。 可能な限り最上位のビットを保持することが常に最善の決定です。 

機能する理由: いくつかの数字が挿入された後、トライには可能なすべての以前のパートナーが含まれます。 クエリ中に、トラバーサルは最上位ビットから最下位ビットまでビットごとに XOR を最小化するパスを選択します。 上位ビットが最終的な数値を支配するため、この貪欲な選択により、すでにトライにある任意の数値と可能な限り最小の XOR が生成されます。 最初の数値を除くすべての数値は、この最適なクエリを通じて以前のすべての数値と比較されるため、考えられるすべてのペアが 1 回検討されます。 これらの最適なペア値の最小値が全体的な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BinaryTrie:
    def __init__(self):
        self.children = [[-1, -1]]

    def insert(self, x):
        node = 0
        for bit in range(30, -1, -1):
            b = (x >> bit) & 1
            nxt = self.children[node][b]
            if nxt == -1:
                nxt = len(self.children)
                self.children[node][b] = nxt
                self.children.append([-1, -1])
            node = nxt

    def query(self, x):
        node = 0
        result = 0
        for bit in range(30, -1, -1):
            b = (x >> bit) & 1
            if self.children[node][b] != -1:
                node = self.children[node][b]
            else:
                result |= 1 << bit
                node = self.children[node][1 - b]
        return result

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        trie = BinaryTrie()
        trie.insert(a[0])

        best = 1 << 31
        for x in a[1:]:
            best = min(best, trie.query(x))
            trie.insert(x)

        ans.append(str(best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`BinaryTrie`クラスは、以前に処理された値のバイナリ表現を格納します。 の`insert`このメソッドは 30 から 0 までのビットをたどります。\(10^9\)よりも小さいです\(2^{30}\)したがって、これらの 31 の位置は、ゼロを含むすべての可能な入力値を表すのに十分です。 

の`query`メソッドはアルゴリズムの貪欲な部分です。 どのレベルでも同じビットを維持しようとします。 その分岐が存在する場合、それを選択すると XOR に寄与する値はゼロになります。 存在しない場合は、反対側の分岐が強制され、対応するビットが応答に追加されます。 

ペアには 2 つの異なる椅子が必要であるため、最初の番号はクエリの前に挿入されます。 空のトライから始めると、最初のクエリが無効になります。 すべてのクエリの後に現在の数値が挿入され、将来の数値がその数値を候補として使用できるようになります。 

Python の整数はオーバーフローしないため、ビット演算は安全です。 の初期値`best`以下の 2 つの数値の最大 XOR であるため、考えられるどの XOR 結果よりも大きくなります。\(2^{30}\)以下です\(2^{31}\)。
