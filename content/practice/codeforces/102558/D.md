 ## 問題の理解

 を取り揃えております。`n`塊。 位置の値`i`現在どのサーバーにチャンクが保存されているかを示します`i`。 クエリは、間隔内のすべてのチャンクを移動するように要求します`[l, r]`サーバーから`a`サーバーへ`b`。 移動は、その間隔内のすべての値が正確に一致する場合にのみ許可されます。`a`手術前。 1 つのチャンクでも別のサーバー上にある場合、リクエスト全体が無視されます。 すべてのリクエストに対して出力する必要があります`1`移動が起こった場合、そして`0`さもないと。 

入力には、すべてのチャンクの初期サーバー割り当てと、範囲移動リクエストの時系列シーケンスが含まれます。 出力には、どのリクエストが整合性チェックを通過したかが示されます。 

制約が大きいため、すべての間隔ですべてのチャンクをチェックすることは不可能です。 と`n`そして`q`どちらも到達`100000`、ソリューションのパフォーマンス`O(n)`あらゆるクエリに対する作業`10^10`最悪の場合の運用。 アルゴリズムは、各リクエストをほぼ対数時間で処理する必要があります。 この操作では間隔全体が一度に変更されるため、間隔を要約し、遅延更新できるデータ構造が必要です。 

いくつかの特殊なケースでは、単純な実装が壊れる可能性があります。 単一のチャンク間隔を引き続きチェックし、正しく更新する必要があります。 例えば：```
Input:

1
1 2 1 1
```出力は次のとおりです。```
1
```この間隔には 1 つのチャンクが含まれており、そのサーバーは要求されたソース サーバーと一致します。 

もう 1 つのよくある間違いは、間隔の最初または最後の要素のみをチェックすることです。 考慮する：```
Input:

1 1 2
1 3 1 1 1
```出力は次のとおりです。```

```最初の 2 つのチャンクはサーバー上にあります`1`、ただし 3 番目はサーバー上にあります`2`。 境界のみのチェックでは、移動が誤って受け入れられてしまいます。 

3 番目のエッジケースは、いくつかの動きが成功した後に現れます。 クエリが成功するかどうかは、初期状態ではなく現在の状態によって決まります。 例えば：```

```出力は次のとおりです。```

0
```最初のクエリの後、配列は次のようになります。`[3, 2]`したがって、2 番目のクエリは両方のチャンクをサーバーから移動することを要求します。`3`失敗します。 

## アプローチ

 簡単なアプローチは、各チャンクの現在のサーバーを配列に保存することです。 クエリごとに間隔をスキャンします。`[l, r]`すべての要素が等しいことを確認します`a`。 チェックに合格した場合は、同じ間隔を再度スキャンし、すべての値を次の値に置き換えます。`b`。 

このアプローチは、有効な動きの定義を直接シミュレートするため、正しいです。 ただし、最悪の場合、クエリですべてをカバーできる可能性があります。`100000`チャンクが存在する可能性があります`100000`そのようなクエリ。 総作業量は約になります`10^10`要素の訪問は、可能性をはるかに超えています。 

重要な点は、クエリの処理中にセグメント内のすべての要素の正確な値が必要ないということです。 セグメント全体に 1 つのサーバー値があるかどうかだけを知る必要があります。 同時に、クエリが成功すると、間隔全体が 1 つの新しい値に置き換えられます。 この組み合わせはまさに遅延セグメント ツリーが適切に処理するものです。 

表現された間隔全体が均一であれば、各セグメント ツリー ノードはサーバー値を格納します。 間隔に複数のサーバー値が含まれる場合、ノードは「混合」を意味する特別なマーカーを格納します。 クエリはツリーに状態を尋ねます。`[l, r]`。 戻り値が`a`、移動が発生する可能性があり、間隔が割り当てられます。`b`。 戻り値が混在しているか、別のサーバー番号である場合、リクエストは拒否されます。 

遅延伝播が必要なのは、大きな間隔を割り当てる場合にすべてのリーフを訪問する必要がないためです。 ノードがフルカバー割り当てを受け取ると、新しい値をそのノードに保存し、後で必要になるまで子の更新を遅らせます。

 ## アルゴリズムのチュートリアル

 1. 初期サーバー割り当てから遅延セグメント ツリーを構築します。 各ノードは、その間隔全体がそのサーバー上にある場合には 1 つのサーバー番号を保存します。`-1`その中に別のサーバーが表示される場合。 
2. 移動リクエストごとに`(a, b, l, r)`、区間の状態についてセグメント ツリーをクエリします。`[l, r]`。 結果は、整合性チェックに必要なすべての情報を表します。 
3. 戻り値が正確である場合`a`、クエリを成功としてマークし、間隔全体を割り当てます。`[l, r]`サーバーへ`b`。 
4. 戻り値がそれ以外の場合、出力`0`ツリーを変更しないでください。 

重要な不変条件は、すべてのセグメント ツリー ノードが常にその区間の現在の状態を正しく記述することです。 ノードは、ノード内のすべてのチャンクが存在するため正確なサーバー番号であるか、少なくとも 2 つの異なるサーバーが存在するために混合されています。 遅延伝播では、親の概要を正確に保ちながら子の更新を遅らせることで、この不変条件が維持されます。 

なぜ効果があるのか:

 各クエリの前に、セグメント ツリーは要求された間隔の正確な均一状態を返します。 その状態であれば`a`、間隔内のすべてのチャンクは必要なソース サーバーに保存されるため、移動は有効であり、間隔全体を次のように置き換えます。`b`実際の動作と一致します。 状態が混合または別のサーバーの場合、少なくとも 1 つのチャンクが要件に違反しているため、クエリを拒否するのは正しいことです。 受け入れられたすべての更新により、新しい配列状態に一致するようにツリー表現が変更されるため、今後のすべてのチェックでは正しい情報が使用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    arr = list(map(int, input().split()))

    size = 1
    while size < n:
        size *= 2

    tree = [-1] * (2 * size)
    lazy = [-1] * (2 * size)

    for i, x in enumerate(arr):
        tree[size + i] = x

    for i in range(size - 1, 0, -1):
        if tree[2 * i] == tree[2 * i + 1]:
            tree[i] = tree[2 * i]
        else:
            tree[i] = -1

    def apply(node, value):
        tree[node] = value
        lazy[node] = value

    def push(node):
        if lazy[node] != -1:
            apply(node * 2, lazy[node])
            apply(node * 2 + 1, lazy[node])
            lazy[node] = -1

    def query(node, left, right, ql, qr):
        if qr < left or right < ql:
            return -2

        if ql <= left and right <= qr:
            return tree[node]

        push(node)
        mid = (left + right) // 2
        a = query(node * 2, left, mid, ql, qr)
        b = query(node * 2 + 1, mid + 1, right, ql, qr)

        if a == -2:
            return b
        if b == -2:
            return a
        if a == b:
            return a
        return -1

    def update(node, left, right, ql, qr, value):
        if qr < left or right < ql:
            return

        if ql <= left and right <= qr:
            apply(node, value)
            return

        push(node)
        mid = (left + right) // 2
        update(node * 2, left, mid, ql, qr, value)
        update(node * 2 + 1, mid + 1, right, ql, qr, value)

        if tree[node * 2] == tree[node * 2 + 1]:
            tree[node] = tree[node * 2]
        else:
            tree[node] = -1

    ans = []
    for _ in range(q):
        a, b, l, r = map(int, input().split())
        l -= 1
        r -= 1

        if query(1, 0, size - 1, l, r) == a:
            ans.append("1")
            update(1, 0, size - 1, l, r, b)
        else:
            ans.append("0")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ツリーは 2 のべき乗のサイズで構築されるため、すべてのノードに未使用のリーフを含む 2 つの子が存在します。 それらの余分なリーフは次のように初期化されます。`-1`ただし、すべてのリクエストは内部に留まるため、実際のクエリには決して含まれません。`[0, n-1]`。 

の`tree`配列には、各セグメントの現在の概要が格納されます。 の`lazy`配列には保留中の割り当てが格納されます。 保留中の値は、セグメント全体がそのサーバー番号をすでに持っているが、その子にはまだ古い情報が含まれている可能性があることを意味します。 子どもたちの中に入る前に、`push`この遅延された割り当てが適用されます。 

クエリ関数は次の値を返します。`-2`完全に無関係なセグメントの場合は、部分的な重複を簡単にマージできるようにします。 返された 2 つの有効なサーバー番号は、それらが等しい場合にのみ 1 つの値に結合されます。 それ以外の場合、結果は次のようになります`-1`、間隔が均一ではないことを意味します。 

更新関数は、現在のノードが完全にカバーされている場合、1 回の操作で間隔全体を割り当てます。 次に、再帰的な更新後に祖先を再構築します。 Python の整数はオーバーフローしないため、格納された値に対して特別な処理は必要ありません。
