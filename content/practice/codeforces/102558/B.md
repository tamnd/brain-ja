 ## 問題の理解

 公開キーは正の整数の秘密ペアから作成されます`(p, q)`。 最初の公開値はペアの最大公約数で、2 番目は最小公倍数です。 公開ペアが与えられました`(x, y)`注文されたプライベートペアの数を数える必要があります`(p, q)`それを生成した可能性があります。 

指定された 2 つの数値は次のように大きくなります。`10^12`。 これにより、可能な値の試行が除外されます。`p`そして`q`、すべての約数を反復しても、`y`gcd と lcm の構造を使用しないと、コストが高くなりすぎます。 解決策を成功させるには、gcd と lcm の間の数学的関係を利用し、タスクを 1 つの数値の因数分解に減らす必要があります。 の平方根なので、`10^12`だけです`10^6`, その制限までの試行分割は Python で実用的です。 

不注意な解決策を破る主なケースは、割り算と数に関連しています。`1`。 もし`x`分けない`y`、秘密キーの可能性はありません。 たとえば、入力`10 11`出力があります`0`lcm は常に gcd の倍数であるため、gcd は次のようになります。`10`lcmを生成できません`11`。 

もう 1 つの特殊なケースは、2 つの公開値が等しい場合です。 入力用`7 7`、可能な秘密キーは次のとおりです。`(7, 7)`、したがって、答えは次のとおりです`1`。 素の割り当てのみをカウントし、残りの積が次の値になる可能性があることを忘れるソリューション`1`この件を誤って処理する可能性があります。 

3 番目のケースは次の場合です。`y / x`繰り返しの素因数が含まれています。 入力用`4 36`、比率は`9`。 有効な正規化ペアは次のとおりです。`(1,9)`そして`(9,1)`、秘密鍵を与える`(4,36)`そして`(36,4)`。 gcd を削除した後は両方の数値が同じ素因数を共有できないため、素数の指数によって追加の選択肢が作成されることはありません。 

## アプローチ

 直接的なアプローチは、考えられる秘密キーを検索することです。 ペアの lcm は次のようにする必要があるため、`y`、両方の数値が約数である必要があります。`y`。 すべての約数のペアを列挙できます`(p, q)`の`y`、どうかを確認してください`gcd(p, q) = x`そして`lcm(p, q) = y`、一致を数えます。 これは正しいです。なぜなら、考えられるすべての秘密キーがその列挙に含まれている必要があるからです。 ただし、近似の数の約数を生成してチェックすると、`10^12`すでに多くの操作が必要になる可能性があり、このメソッドでは gcd と lcm の間の特別な関係は使用されません。 

重要な観察は、gcd を分離することから得られます。 仮定する：`p = x * a`そして`q = x * b`。 

共通部分を除いた残りの値`a`そして`b`は互いに素でなければなりません。 lcm は次のようになります。`lcm(p, q) = x * a * b`。 

したがって：`a * b = y / x`。 

元の問題は、次の順序での素因数分解が何回行われるかを尋ねています。`y / x`もっている。 この数値が素因数分解されている場合:`n = r1^e1 * r2^e2 * ... * rk^ek`次に、それぞれの完全な素数パワー`ri^ei`完全に行かなければなりません`a`または完全に`b`。 素数べき乗を分割すると、2 つの数値がその素数を共有することになり、共素条件に違反します。 それぞれの`k`個別の素数には 2 つの選択肢があるため、答えは次のようになります。`2^k`。 

残っている唯一のタスクは、次の異なる素因数の数を見つけることです。`y / x`。 なぜならその値はせいぜい`10^12`までの約数をチェックします`10^6`十分です。

 ## アルゴリズムのチュートリアル

 1. まず次のことを確認します。`y`で割り切れます`x`。 そうでない場合、どのペアも gcd を持つことができません`x`そしてlcm`y`、だから答えはすぐにわかります`0`。 lcm は常に gcd の倍数でなければなりません。 
2. コンピューティング`n = y / x`。 これは、両方の秘密キー値から gcd を削除した後に残った 2 つの互いに素な部分の積です。 
3. 因数分解`n`考えられる約数を試してみる`2`上向きに。 約数が見つかった場合は、それを 1 つの異なる素因数として数え、そのすべての出現箇所を除外します。`n`。 異なる素数の数だけが答えに影響するため、全累乗を取り除くことが必要です。 
4. 試行分割後の値が より大きい場合`1`残っている場合、それは元の数の平方根よりも大きい素因数になります。 それをもう 1 つの異なる素数として数えます。 
5. 戻る`2`見つかった個別の素因数の数まで累乗されます。 各素数パワーは、互いに素のペアのどちらかの側に独立して割り当てることができます。 

なぜ効果があるのか:

 両方のプライベート数値を gcd で除算した後、残りの部分の gcd は次と等しくなければなりません。`1`。 これらの部分の積は次のように固定されます。`y / x`。 共素因数分解では、積のすべての素因数がちょうど一方の側に属します。 それぞれの異なる素数に対して、正確に 2 つの選択肢があります。その全パワーを最初の数に置くか、2 番目の数に置くかです。 これらの選択肢は独立しているため、選択肢を掛け合わせると次のようになります。`2^k`、 どこ`k`は個別の素因数の数です。 カウントされた割り当てごとに 1 つの有効な秘密キーが作成され、すべての有効な秘密キーが 1 つの割り当てに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    if y % x != 0:
        print(0)
        return

    n = y // x
    cnt = 0

    d = 2
    while d * d <= n:
        if n % d == 0:
            cnt += 1
            while n % d == 0:
                n //= d
        d += 1

    if n > 1:
        cnt += 1

    print(1 << cnt)

if __name__ == "__main__":
    solve()
```最初の条件は、因数分解を行う前に、不可能な公開キーを処理します。 もし`x`分けない`y`、gcd と lcm の関係で必要な比率は整数ではありません。 

変数`n`gcd 寄与を削除した後に残る lcm の部分を格納します。 因数分解ループは、異なる素数のみをカウントします。 除数が見つかると、内側のループはその指数全体を削除します。`2`、`4`、 そして`8`個別の割り当ての選択肢を作成しないでください。 

ループ条件では、`d * d <= n`平方根を計算するのではなく。 これにより、次の値に対する浮動小数点精度の問題が回避されます。`10^12`。 Python の整数はオーバーフローしないため、乗算は安全です。 

最終チェックは、`n > 1`残りの素因数を処理します。 たとえば、小さな要素を取り除いた後、`12`、残りの値は次のようになります。`3`、それでも 1 つの独立した選択肢に貢献します。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    x, y = map(int, input().split())

    if y % x != 0:
        return "0\n"

    n = y // x
    cnt = 0
    d = 2

    while d * d <= n:
        if n % d == 0:
            cnt += 1
            while n % d == 0:
                n //= d
        d += 1

    if n > 1:
        cnt += 1

    return str(1 << cnt) + "\n"

assert solution("10 11\n") == "0\n", "sample 2"
assert solution("527 9486\n") == "4\n", "sample 3"

assert solution("1 1\n") == "1\n", "minimum values"
assert solution("7 7\n") == "1\n", "equal public values"
assert solution("4 36\n") == "2\n", "repeated prime factor"
assert solution("1 1000000000000\n") == "16\n", "large composite value"

 ## 特殊なケース

 入力用`10 11`、アルゴリズムは最初に割り算をチェックします。 以来`11 % 10`ゼロではない場合は返されます`0`すぐに。 ファクタリングのみをベースにした手法`y`誤ってペアの検索を続行し、不可能な場合に時間を無駄にする可能性があります。 

入力用`7 7`、比率は次のようになります`1`。 因数分解ループでは素数が見つからないため、個別の素数数は 0 となり、答えは次のようになります。`2^0 = 1`。 これは単一のペアを正しく表しています`(7,7)`。 

入力用`4 36`、比率は`9`、次のように考慮されます`3^2`。 このアルゴリズムは、異なる素数を 1 つだけカウントします。`2^1 = 2`。 2つの課題は、`(1,9)`そして`(9,1)`、になる`(4,36)`そして`(36,4)`。 次の 2 つの要素を分割することは考慮されません。`3`それは正規化された値が非素数になるからです。
