 ## 問題の理解

 グラフには、重み付けされた無向エッジによって接続された頂点が含まれています。 頂点を 2 つの色で着色し、両方の色を使用して、端点が同じ色を受け取ったエッジを確認する必要があります。 そのエッジの中で、私たちは最小の重量を重視します。 The goal is to make this smallest internal edge as large as possible.

 A useful way to look at the objective is to choose an answer value`x`。 すべてのエッジの重みが以下の場合`x`2 つのグループ間を強制的に移動すると、グループ内に残ったすべてのエッジには少なくとも重みがかかります。`x`。 問題は、サブグラフが重みが以下のエッジだけで構成されているかどうかになります。`x`は 2 つの側面に分けることができます。これはまさに、この部分グラフが 2 部グラフであるかどうかという問題です。 

入力サイズが到達しました`100000`頂点と`100000`エッジ。 考えられるすべてのパーティションを試すことは不可能です。`2^n`着色料。 二次関数の動作を持つアルゴリズムでさえ、これらの制限には遅すぎます。`10^10`運用は現実的なものをはるかに超えています。 に近いアプローチが必要です`O((n+m) log C)`、 どこ`C`可能な回答の範囲です。 

正しく実装されていないと、通知なしに失敗する場合がいくつかあります。 異なる重みを持つ繰り返しエッジは個別に処理する必要があります。 例えば：```

```正しい答えは、`4`。 重量の限界`1`小さなしきい値をチェックする場合には重要ですが、重みの限界`5`最終パーティションの内部エッジになる可能性があります。 2 つの頂点の間にエッジを 1 つだけ保持する解決策では、答えに必要な情報が削除される可能性があります。 

もう 1 つのケースは、グラフ全体がほぼ 2 部構成であるが、1 つの重いエッジだけが原因で不可能になる場合です。```

## アプローチ

 直接的な解決策では、頂点の可能なすべての分割を 2 つの空ではないグループに列挙します。 分割ごとに、すべてのエッジをスキャンし、エンドポイントが同じグループ内にあるエッジを見つけて、そのような最小の重みを維持します。 これは、問題で要求された数量を正確にチェックするため、正しいです。 

問題は可能な分割数です。 と`n`頂点があります`2^n`2 つの色の割り当て、および両方の色が交換される対称的なケースを無視した後でも、作業量は依然として指数関数的です。 のために`n = 100000`、このアプローチは遠隔的には実現可能ではありません。 

重要な点は、最適なパーティションを直接構築する必要がないということです。 別の質問をすることもできます。答えは少なくとも次のとおりです。`x`? そのためには、重みが より小さいすべてのエッジが必要になります。`x`異なるグループの頂点を接続する必要があります。 つまり、重みが より小さいエッジのみを一時的に保持すると、`x`、このグラフは 2 部構成でなければなりません。 

この総当り攻撃は、考えられるすべての色をチェックするため機能しますが、色の数が爆発的に増えると失敗します。 しきい値の観察により、パーティションの検索をエッジの重みの検索に置き換えることができます。 プロパティは単調です: エッジが以下より小さい場合`x`2 部グラフを形成すると、より小さい値よりも小さいエッジも 2 部グラフを形成します。 これにより、二分検索が可能になります`x`。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを保存します。 チェック中に必要な唯一の操作は、エッジの重みが選択したしきい値を下回っているかどうかを判断することです。 
2. 間の答えを二分探索します。`1`そして`100001`。 候補値としては`mid`、重みが以下のすべてのエッジかどうかをテストします。`mid`二部グラフを形成します。 
3. チェック中に、カラー配列を作成します。 色のない頂点には 1 つの色が割り当てられ、BFS はしきい値より小さい重みで反対の色をすべてのエッジに広げます。 
4. しきい値よりも小さい重みを持つエッジが、すでに同じ色を持つ 2 つの頂点を接続する場合、グラフはこのしきい値では 2 部ではありません。 候補の答えが大きすぎるため、下半分で二分探索が続行されます。 
5. チェックが成功すると、候補値が達成可能になります。 二分探索範囲を上に移動して、より大きな可能性のある答えを見つけます。 
6. 成功した最大のしきい値が出力されます。 グラフ全体が 2 部ではないことが保証されているため、検索ではすべてのエッジが 2 つのグループの間に配置される可能性のある値が誤って返されることはありません。 

アルゴリズムの背後にある不変条件は、しきい値です。`x`は、禁止された小さな内部エッジとなる可能性のあるすべてのエッジが 2 色で分離できる場合にのみ有効です。 二部チェックは、そのようなカラーリングが存在するかどうかを証明します。 しきい値を増やすと、チェックされたグラフにエッジが追加されるだけなので、しきい値が失敗すると、それより大きなしきい値もすべて失敗します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((u - 1, v - 1, w))

    def check(limit):
        graph = [[] for _ in range(n)]
        for u, v, w in edges:
            if w < limit:
                graph[u].append(v)
                graph[v].append(u)

        color = [-1] * n

        for start in range(n):
            if color[start] != -1:
                continue
            color[start] = 0
            q = deque([start])

            while q:
                v = q.popleft()
                for to in graph[v]:
                    if color[to] == -1:
                        color[to] = color[v] ^ 1
                        q.append(to)
                    elif color[to] == color[v]:
                        return False
        return True

    left = 1
    right = 100002

    while left + 1 < right:
        mid = (left + right) // 2
        if check(mid):
            left = mid
        else:
            right = mid

    print(left)

if __name__ == "__main__":
    solve()
```各二分探索反復では重みによってエッジをフィルタリングする必要があるため、エッジ リストは元の形式で保持されます。 内部の一時グラフを再構築する`check`ロジックをシンプルに保ち、時代遅れのエッジによる間違いを回避します。 

二分探索では範囲を使用します`[1, 100002)`。 エッジの重みは最大でも次の値であるため、上限は排他的です。`100000`、すべてのエッジよりも大きいしきい値にはグラフ全体が含まれます。 元のグラフが二部グラフではないという保証は、そのようなしきい値が満たされないことを意味します。 

BFS は、接続されたコンポーネントを個別に色付けします。 グラフには複数の切断された部分が含まれている可能性があり、各コンポーネントは個別に色付けできるため、これは重要です。 競合は、すでに色付けされている隣接色が同じ色を必要とする場合にのみ発生します。 

ここでは Python の整数はオーバーフローせず、答えに関係する唯一の算術は二分探索の中点計算です。 の使用`sys.stdin.readline`また、両端キューにより、制約に対して十分な速度で入力とグラフの走査が維持されます。
