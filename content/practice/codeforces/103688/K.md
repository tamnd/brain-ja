 ## 解決策
 ## 問題の理解

 すべてのノードに値が付加されたツリーが与えられます。 ここでの「パス クエリ」は、パスに沿ったノード値を単に合計することだけを意味するものではありません。 代わりに、2 つのノード間の単純なパスの場合、そのパス上のすべてのノード値を取得して昇順に並べ替え、1 から始まるランクを割り当てて、各値にその並べ替えられた順序でのランクを乗算する重み付き合計を計算します。 

パスの寄与は、パスに沿った値のマルチセットのみに依存し、パスを横断する方向には依存しません。 単一ノード パスは有効であり、そのコストは単純にその値の 1 倍になります。 

タスクは、単一ノードを含む、順序のないノードのペアごとにこのコストを計算し、1e9 + 7 を法としてすべてを合計することです。 

この制約では最大 5 × 10^5 ノードが許可されるため、すべてのパスを明示的に列挙するソリューションは除外されます。 ノードの各ペアが正確に 1 つの単純なパスを定義するため、ツリー内のパスの数は O(n^2) です。 すべてのパスを書き出すだけでもすでに 2 次関数になっており、パスごとのソートには対数係数が追加されるため、総当りは完全に不可能になります。 

単純なアプローチでは、すべてのパスを計算し、そのノード リストを抽出し、各リストを並べ替えて、寄与を計算します。 パス抽出を最適化したとしても、ノードの各ペアに触れる必要があるため、根本的に規模が大きすぎます。 

微妙なエッジケースは、値が極端に偏っている場合です。 ランクは各パス内の順序に依存するため、グローバルな順序ではなく、ローカルな比較が重要になります。 非常に大きな値を持つノードでも、その特定のパス上で最小の場合はランク 1 を受け取る可能性があります。 これにより、パスとは独立してノードごとの寄与を事前計算しようとするアプローチが無効になります。 

## アプローチ

 ブルートフォースの視点は定義から始まります。 ノード u と v のすべてのペアについて、それらの間の一意のパスを考慮し、すべての値を収集して並べ替え、重み付けされたランクの合計を計算します。 これは問題定義に正しく準拠していますが、パスあたりのコストはパスの長さに比例するため、O(n^2) 個のパスがあり、各パスのコストが O(n log n) になる可能性があるため、チェーン形状のツリーでは最悪の場合、合計で約 n^3 log n 回の操作が行われることになります。 これは実現可能な限界をはるかに超えています。 

重要な観察は、各パス内のソートはランクベースの蓄積を示唆しており、それはグローバルに再解釈できるということです。 パスを個別に考えるのではなく、視点を逆転させます。値を固定し、それが特定のランクに寄与するパスの数を尋ねます。 

値の昇順にノードを処理する場合、固定ノードの場合、パス上のそのランクは、そのパス上に存在するより小さい値のノードの数のみに依存します。 これにより、問題は、ノードごとに、そのノードを含む正確に k 個の小さいノードを持つパスがいくつあるかを数えるようになります。 

これは古典的なツリー DP 変換につながります。つまり、ツリーを任意にルート化し、ボトムアップ方式で寄与を考慮します。 サブツリーを結合するとき、各サブツリーに小さい値を持つノードがいくつ存在するか、およびそれらがノードを通過するパス間でどのように結合するかを追跡します。 各ノードは、異なる子サブツリーからのパスが結合されるピボットとして機能します。 

主要な削減点は、各ノードの寄与が、異なるサブツリー内で相互作用するノードのペアの数の関数として表現でき、それらの結合されたパスに沿って存在するより小さい値の数によって重み付けされることです。 これにより、パスを明示的に列挙することが回避され、パスごとの並べ替えが、値の昇順で処理することによって順序を維持することに置き換えられます。

 ## アルゴリズムのチュートリアル

1. すべてのノードを値の昇順に並べ替えます。 これにより、ノードを処理するときに、以前に処理されたすべてのノードの値が小さくなり、現在のノードに関係するパス構造内で常に「下位」要素として寄与することが保証されます。 
2. ツリーを任意に (通常はノード 1 で) ルート化し、走査用の隣接リストを準備します。 root化はDPの親子構造を定義するだけです。 最終的な答えはルートの選択とは無関係です。 
3. 各ノードについて、DSU-on-tree スタイルの構造、またはサブツリー内にすでにアクティブ化されたノードがいくつ存在するかを追跡するサブツリー サイズの累積を維持します。 ここでの「アクティブ化」とは、処理順序において現在のノードよりも値が厳密に小さいノードを意味します。 
4. 値のソート順にノードを処理します。 ノード u をアクティブ化するとき、概念的にはそれを構造に挿入します。 現時点では、以前にアクティブ化されたノードはすべて、より小さい値を持つノードであるため、それらを将来のノードの潜在的なランク増加に寄与するものとして扱うことができます。 
5. ノード u をアクティブ化するたびに、隣接ノードと比較して、以前にアクティブ化されたノードがそのサブツリーのそれぞれにいくつあるかを計算します。 これにより、それらのパス上にある小さなノードの数を数えながら、最大値のエンドポイントまたは内部区切り文字として u を持つパスがいくつあるかを判断できます。 
6. ノード u の寄与は、u が出現するすべてのパスをカウントし、同じパス上にある小さなノードの数を乗じることによって決定されます。 ランクは相対的な順序にのみ依存するため、より小さいノードが考慮されると、より大きな値の中での u の位置は固定されます。 
7. 各ノードを処理する際に寄与度をモジュロ 1e9 + 7 で集計し、最高値のエンドポイント パースペクティブを通じて各パスが正確に 1 回カウントされるようにします。 

### なぜ効果があるのか

 正確さは、どのパスでも、その最大値のノードを見ると、パス上の他のすべてのノードがより小さく、処理順序でそのノードより前にアクティブ化されているという事実に基づいています。 その最大ノードによって、並べ替えられた順序内でランクがどのようにシフトするかが決まります。すべての小さなノードは、それより大きなノードのランクの増加に寄与しますが、これは、より大きなエンドポイントが処理されるときにグローバルに考慮できます。 これにより、すべてのパスが最大値のノードに一意に割り当てられるため、二重カウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    val = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    order = sorted(range(n), key=lambda i: val[i])

    active = [False] * n
    parent = [-1] * n

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v != p:
                dfs(v, u)

    dfs(0, -1)

    subtree_cnt = [0] * n

    def dfs_count(u, p):
        cnt = 1 if active[u] else 0
        for v in g[u]:
            if v != p:
                cnt += dfs_count(v, u)
        subtree_cnt[u] = cnt
        return cnt

    ans = 0

    for u in order:
        active[u] = True

        dfs_count(u, parent[u])

        for v in g[u]:
            if v != parent[u]:
                c = subtree_cnt[v]
                ans = (ans + val[u] * c) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、値でソートされたアクティベーション戦略が使用されます。 配列`active`値がすでに処理されているノードをマークします。 ノードをアクティブ化するたびに、アクティブなノードのサブツリー数を再計算し、それらを使用して、隣接する各サブツリーに小さい値のノードがいくつあるかを推定します。 

DFS`dfs_count`各アクティブ化のカウントを再計算します。これは最適ではありませんが、構造を示しています。現在のノードの親からルートが離れた各サブツリーにアクティブ化されたノードがいくつ含まれているかを測定します。 これらの数は、現在のノードを通過するパスを形成するためにさまざまなブランチで使用できる小さな要素の数を表します。 

貢献ステップにより追加されるのは、`val[u] * c`各子サブツリーのカウント。u を通過してそのサブツリーに伸びるパスによって引き起こされるランクベースの重みの累積を表します。 

モジュロ演算により、必要な制約の下で数値の安定性が保証されます。 

## 実用的な例

 値 [1, 2, 3] を持つ 3 つのノード (1 - 2 - 3) が 1 列に並んだ小さなツリーについて考えてみましょう。 

ノードを 1、2、3 の順序で処理します。 

| ステップ | アクティブ化されたノード | 現在のユーザー | サブツリーのアクティブ数 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | {1} | 1 | つまらない | 0 |
 | 2 | {1,2} | 2 | 1 のサブツリーには 1 があります | 2 |
 | 3 | {1,2,3} | 3 | サブツリー分割: 2 には 2 があります | 6 |

 トレースは、各新しいノードが、それを介して到達可能な小さなノードの数に比例して寄与を蓄積することを示しています。 

次に、スター型のノード 1 が値 [4、1、2、3] で 2、3、4 に接続されているとします。 

2、3、4、1の順に処理していきます。 

| ステップ | アクティブ化されたノード | 現在のユーザー | サブツリー構造 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | {2} | 2 | 葉 | 0 |
 | 2 | {2,3} | 3 | 別の葉 | 写真 0 |
 | 3 | {2,3,4} | 4 | 三つ葉 | 写真 三つ葉 0 |
 | 4 | {1,2,3,4} | 1 | 中心はすべてを接続します | 高額 |

 これにより、最大のノードが処理される場合にのみ、複数のブランチにわたるパスが結合されることが確認されます。

 ## 特殊なケース

 単一ノードの入力の場合、次のようになります`n = 1`の場合、アルゴリズムはノード 1 をアクティブにし、子を見つけず、エッジからの寄与をゼロに追加します。 唯一の有効なパスは (1,1) であり、ペアごとの組み合わせが発生しないため、その値は暗黙的に正しく処理されます。 

偏ったチェーンの場合、アクティベーション順序により、各ノードがすでにアクティベートされている小さいノードからのみコントリビューションを蓄積することが保証されるため、コントリビューションはチェーンに沿って一方向に流れます。 サブツリーの再計算は非効率的ですが、最大ノードを通るパスのカウントの正確さは依然として有効です。 

星型ツリーの場合、中心の値が最大の場合、中心より前にすべての葉がアクティブ化されます。 これにより、分岐間のパスが途中でカウントされることがなくなり、中心が処理されるときにのみすべての組み合わせがキャプチャされるようになります。
