 ## 解決策
 ## 問題の理解

 同じ長さの文字列とターゲット文字列が与えられます。 1 回の操作で、2 つの許可されたカット位置の 1 つを選択し、文字列をプレフィックスとサフィックスに分割し、特定の並べ替えシーケンスを実行します。つまり、2 つの部分を交換し、結果全体を逆にします。 

現在の文字列がプレフィックスとして記述されている場合$A$その後に接尾辞が続く$B$、操作は変わります$AB$の中へ$BA$そしてそれを逆転させます。 反転を拡大すると、その効果がブロックの回転や単純な交換ではなく、プレフィックスとサフィックスの両方が順序を維持しながら独立して反転される構造化された変換であることがわかります。 具体的には、オペレーションマップ$AB$の中へ$A^R B^R$、 どこ$A^R$そして$B^R$2 つのセグメントの反転です。 

したがって、各動きはカット位置を選択するように機能します$l$、セグメントを反転します$[1..l]$そして逆転も$[l+1..n]$。 唯一の自由は、カット位置が次のいずれかであることです。$l_1$または$l_2$、操作は何度でも適用できます。 

タスクは、これらの操作のシーケンスを使用して、初期文字列をターゲット文字列に変換できるかどうかを判断することです。 

入力サイズが大きい: テスト ケース全体のすべての文字列の合計長は最大です。$5 \cdot 10^5$。 これにより、変換を段階的にシミュレートしたり、状態を明示的に調査したりするソリューションは除外されます。 各操作は次のとおりであるため、すべての中間文字列を保存することさえ不可能です。$O(n)$そして単純な検索は指数関数的に爆発的に増加するでしょう。 

微妙な難点は、この操作が複雑で高度に構造化されていることです。 多くの誤ったアプローチでは、回転や単純な反転のように動作すると想定していますが、実際には、どの位置で文字を交換できるかについて、より厳密な制約が保持されます。 

よくある落とし穴は、各操作を文字を自由に並べ替えるグローバルな並べ替えとして扱うことです。 たとえば、両方の場合に任意の順列が可能であると仮定します。$l_1$そして$l_2$「存在する」は、誤った「はい」の答えにつながります。これは、操作によってインデックス順列の制限されたサブグループのみが生成されるためです。 

もう 1 つの失敗例は、対称性を無視したことに起因します。 各操作は 2 つのセグメントに独立した反転を適用するため、実際には完全に反転しているにもかかわらず、各セグメント内の相対的な順序が保持されていると誤って考えることがよくあります。 

## アプローチ

 ブルート フォース アプローチでは、文字列を状態としてモデル化し、2 つの操作を使用して到達可能なすべての文字列に BFS を適用しようとします。 各状態には最大 2 つの遷移があるため、状態グラフの次数は 2 になります。 ただし、到達可能な個別の置換の数は、最悪の場合でも階乗になります。$n$、この空間を探索することは完全に不可能です。 各移行コスト$O(n)$そのため、たとえ小さな BFS であっても、ほぼすぐに時間制限を超えてしまいます。 

重要な点は、文字列の進化全体を追跡する必要がないということです。 各操作はインデックスの固定順列です。 文字列をシミュレートする代わりに、インデックスがどのように動くかを研究します。 

カット用$l$、誘導された順列は決定的です。プレフィックス内の位置はプレフィックス内で逆転し、サフィックス内の位置はサフィックス内で逆転します。 したがって、各操作は 2 つの独立した反転から構成される順列になります。 

問題を 2 つのそのような順列によって生成されるグループとして見ると、構造は 1 次元になります。繰り返し適用すると、特定の位置が相互に到達可能になり、同値クラスが形成されます。 各クラス内では、合成演算によって文字を任意に並べ替えることができます。 

したがって、問題は、最初の文字列の複数の文字セットが、すべての到達可能な位置クラス内のターゲット文字列と一致するかどうかをチェックすることに帰着します。 

これらのクラスの構造は、クラス間の距離にのみ依存します。$l_1$そして$l_2$。 システムはライン上の反射のように動作し、生成されたグループは次のステップ サイズに従ってインデックスを分割します。$|l_1 - l_2|$。

 ## アルゴリズムのチュートリアル

 ### 1. 演算をインデックス順列に変換する

 許可されたカットごとに$l$、純粋にインデックス マッピングとして操作を書き換えます: すべての位置$i \le l$に移動します$l - i + 1$、そしてあらゆるポジション$i > l$に移動します$n - (i - l) + 1$。 位置がどのように再配置されるかを理解すれば、文字列の内容は無関係になるため、このステップは重要です。 

### 2. 到達可能な構造はインデックス接続のみに依存することに注意してください。 

順列を適用する代わりに、インデックス上のグラフを想像します。$1 \dots n$、エッジが接続される場所$i$許可された各操作でそのイメージにコピーされます。 重要な事実は、2 つのインデックスが任意の操作シーケンスを通じて接続されている場合、それらの操作によって引き起こされる何らかのスワップ シーケンスを通じてそれらの文字を交換できるということです。 

したがって、タスクは、この暗黙的な変換グラフの接続コンポーネントを特定することになります。 

### 3. 不変ステップ サイズを決定する

 2 つの異なるカットを適用する$l_1$そして$l_2$によるシフトのように動作する合成を生成します。$|l_1 - l_2|$指数に関して（反転対称まで）。 これにより、繰り返し構造が作成されます。インデックスは値の剰余によってグループ化されます。$g = |l_1 - l_2|$。 

これが核となる単純化です。 複雑な順列グループの代わりに、ラインの周期的な分割を取得します。 

### 4. インデックスの同値クラスを構築する

 各インデックス$i$剰余モジュロによって決定されるクラスに属します$g$。 オペレーションにはリバーサルも含まれるため、インデックス$i$さらにミラー位置にもリンクされています$n + 1 - i$。 したがって、各クラスは次のペアによって定義されます。$$(i \bmod g,\ (n+1-i) \bmod g)$$同じペアを持つすべてのインデックスは 1 つのコンポーネントに属します。 

### 5. 各クラス内の文字を比較する

 クラスごとに初期文字列とターゲット文字列から文字を収集します。 すべてのクラスで、マルチセットが正確に一致する必要があります。 すべてのクラスが一致する場合、変換は可能です。 

### なぜ効果があるのか

 各操作は、等価クラス内のインデックスのメンバーシップを保持します。これは、操作が、次の倍数だけ異なるカット ポイントの周囲の反転から構築されているためです。$g$。 一連の操作では、クラス内のインデックスの並べ替えのみが可能であり、インデックスを別のクラスに移動することはできません。 逆に、クラス内では、許可された 2 つの操作を組み合わせることで、文字を任意に再配置するのに十分な柔軟性が得られます。 これにより、マルチセット条件が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        r = input().strip()
        l1, l2 = map(int, input().split())
        n = len(s)

        g = abs(l1 - l2)

        from collections import defaultdict
        cnt_s = defaultdict(list)
        cnt_t = defaultdict(list)

        for i in range(n):
            j = n - 1 - i
            key = (i % g, j % g)
            cnt_s[key].append(s[i])
            cnt_t[key].append(r[i])

        for key in cnt_s:
            if sorted(cnt_s[key]) != sorted(cnt_t[key]):
                print("no")
                break
        else:
            print("yes")

if __name__ == "__main__":
    solve()
```このコードは、次の 2 つの情報を使用して各位置の等価クラスを計算します: そのインデックス モジュロ$g$、およびそのミラーインデックスモジュロ$g$。 両方の文字列の文字がこれらのクラスにグループ化され、比較されます。 

重要な実装の詳細は、明示的に順列を構築したり、操作をシミュレートしたりしないことです。 すべては構造バケットへのインデックスのハッシュに還元されます。

これは、アルゴリズムが操作をシミュレートする必要がないことを示しています。 構造グループ内のローカルな整合性のみをチェックします。

これは、グローバルな再配置がもっともらしい場合でも、単一の壊れたクラスが変換を無効にしてしまうことを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    t = int(input())
    for _ in range(t):
        s = input().strip()
        r = input().strip()
        l1, l2 = map(int, input().split())
        n = len(s)

        g = abs(l1 - l2)

        from collections import defaultdict
        cnt_s = defaultdict(list)
        cnt_t = defaultdict(list)

        for i in range(n):
            j = n - 1 - i
            key = (i % g, j % g)
            cnt_s[key].append(s[i])
            cnt_t[key].append(r[i])

        ok = True
        for key in cnt_s:
            if sorted(cnt_s[key]) != sorted(cnt_t[key]):
                ok = False
                break

        out.append("yes" if ok else "no")

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、文字列の長さが 1 の場合です。この場合、プレフィックスとサフィックスの反転の両方で 1 つの文字が保持されるため、すべての操作は自明に動作します。 このアルゴリズムはインデックスを単一のクラスに配置し、文字を即座に照合します。 

もう 1 つのエッジケースは次のような場合です$l_1$そして$l_2$これにより、可能な限り最小のステップ サイズが作成され、多くのインデックスが 1 つの接続された構造にマージされる傾向があります。 すべてのインデックスには明確に定義された剰余クラスがあるため、モジュロベースのグループ化はこれを正しく処理します。 

最後のケースは、すべての文字が同一である場合です。 構造が多くのクラスに分割された場合でも、マルチセットは同一であるため、各クラスの比較は常に成功します。
