 ## 解決策
 ## 問題の理解

 直立させたときに幅が同じになる 2 種類の本が与えられています。どの本も、棚の幅の 1 単位を正確に占有します。 違いは高さです。 タイプAの本には高さがあります`a`、タイプ B の本は高さが高くなります。`b`、 どこ`a < b`。 最大許容高さの本棚もあります`h`と言われてしまいます。`h`少なくとも`b`, そのため、どちらのタイプも高さ制限に違反することなく直立することができます。 

最初は、すべての本が縦一列に配置されます。`n`最初に本を入力し、次にすべての本を入力します`m`タイプBの本。 この構成では、合計幅は単純に次のようになります。`n + m`。 

ツイストは、右側からいくつかのタイプ B の書籍を取得できることです。具体的には、`k`との本`0 ≤ k ≤ m - 1`、水平方向に回転させます。 これらの回転されたブックは、既存の垂直配置の上に配置され、高さの消費方法が変わりますが、独立した垂直ブックとして水平幅に寄与することはなくなります。 

目標は、高さ制限を守りながら、最終的に必要な棚の幅ができるだけ小さくなるように、回転させるタイプ B の本の数を選択することです。`h`。 

制約は大きく、最大で`10^3`テストケースと値`n`そして`m`まで`10^9`したがって、どのソリューションもテスト ケースごとに一定時間で実行する必要があります。 これにより、書籍に対するシミュレーションや、可能性のある値を反復するアプローチが即座に除外されます。`k`。 

高さと回転する本の数の相互作用について推論するときに、微妙な失敗例が現れます。 たとえば、次の場合`h`よりわずかに大きいだけです`b`の場合、たとえ多数の B 本があったとしても、ローテーションできるのはごく少数の B 本だけです。 逆に、もし`h`大きい場合、制約によってのみ制限されます`k ≤ m - 1`。 

単純な間違いは、おそらく 1 冊を除くすべての B ブックを常に回転して幅を縮小できると想定することです。`n + 1`。 これは、水平方向の本をあまりにも多く積み重ねると高さの制限を超えると失敗します。これが実現可能性を左右する真の制約です。 

## アプローチ

 ブルートフォース戦略ではあらゆる可能性を試すことになる`k`から`0`に`m - 1`、回転しているかどうかを計算します`k`本は高さ制限の下で有効であるため、結果の幅を計算します。`n + m - k`。 問題は、それぞれの実現可能性を確認することです`k`水平に積まれた本がどのように高さを増加させるかをモデル化する必要があります。 たとえ各チェックが O(1) だったとしても、最大で反復処理が行われます。`10^9`の値`k`不可能です。 

重要な洞察は、アレンジメントが完全に単調であるということです。 タイプ B の本をさらに回転させるたびに、棚の同じ領域にまったく同じ種類の高さの圧力が加わります。 これは、一定数の B 本を高さを超えずに回転できることを意味します。`h`、それより小さい数値も有効ですが、それより大きい数値は無効です。 

これにより、問題は実現可能な最大値を見つけることになります。`k`。 高さの相互関係は、既存の最も高い垂直の本 (タイプ B の本) の上に水平の本を積み重ねることによってのみ得られるため、構造はさらに簡素化されます。 各水平ブックは、すでに高さがある領域に追加の高さ単位を与えます。`b`、だから積み重ねる`k`このような本では、その地域での有効高さの要件が増加します。`b + k`。 制約`b + k ≤ h`答えを直接的に制限します。 

また、すべての B 冊をローテーションすることはできないという条件も尊重する必要があります。`k ≤ m - 1`。 

最大値が有効になったら`k`が決定されると、最終的な幅は単純に次のように縮小されます。`k`, 回転する本ごとに縦幅の寄与が 1 つ削除されるためです。

 ## アルゴリズムのチュートリアル

 1. タイプ B のブックを回転すると垂直レイアウトから削除されるため、有効な回転ごとに全体の幅が 1 単位だけ減少することに注目してください。 これにより、回転できる B ブックの最大数を見つけることが問題になります。 
2. B 本を回転させたときに高さがどのように変化するかを確認します。 各水平 B は、既存の B 高さスタックの上に追加の高さ単位を提供します。`k`B ブックを回転すると、強制的に高さが決まります`b + k`被災地域では。 
3. 要求して高さ制限を強制します。`b + k ≤ h`。 これにより上限が得られます`k ≤ h - b`。 
4. すべての B ブックを回転させることはできないという問題の制約を強制します。`k ≤ m - 1`。 
5. 両方の制約を組み合わせて、実現可能な最大回転数を取得します。`k = min(m - 1, h - b)`。 
6. 元の幅から回転した本の数を引いて、最終的な幅を計算します。`w = n + m - k`。 

### なぜ効果があるのか

 問題の構造により、回転するすべての本が同一かつ累積的に高さと相互作用することが保証されます。 追加の水平 B ブックごとに制限高さ領域に一律 +1 が寄与するため、回転を異なる方法で分散する利点はありません。 これにより、実現可能性は、位置ではなく、回転された本の数のみに依存します。 その結果、有効なセットは、`k`ゼロから始まり最大化するプレフィックス間隔を形成します。`k`幅を最小限に抑えるには十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, n, m, h = map(int, input().split())
        
        # maximum number of B books we can rotate
        k = min(m - 1, h - b)
        if k < 0:
            k = 0
        
        # final width after removing k books from vertical layout
        print(n + m - k)

if __name__ == "__main__":
    solve()
```ソリューションは各テスト ケースを読み取り、一定時間内に答えを計算します。 唯一の重要なステップは正しく境界を設定することです`k`。 表現`h - b`棚の高さを超える前に追加の水平層を何段積み重ねられるかを取得します。 クランプも行います`k`少なくともゼロにする`h == b`、横積みはできません。 

よくある間違いは、`m - 1`すべての B ブックを回転できないようにする制約。 もう 1 つは、水平方向の配置が幅に乗算的に影響するものとして誤解していることです。 実際には、高さにのみ影響し、それらの本は縦幅のカウントから削除されます。

 ## 特殊なケース

 いつ`h`等しい`b`, 本を横積みする場合の高さの予算がゼロになります。 その状況では、式は次のようになります。`k = min(m - 1, 0) = 0`なので幅は残ります`n + m`。 これは、たとえ 1 冊の横長の本であっても、積み重ねられた領域で許容される高さをすぐに超えるという物理的解釈と一致します。 

いつ`m = 1`、制約`k ≤ m - 1`力`k = 0`身長に関係なく。 実装ではこれを自然に処理します。`min(0, h - b)`は常にゼロまたは負であるため、それをゼロにクランプします。 

いつ`h`が非常に大きい場合、制限要因は次のようになります。`m - 1`、つまり、ほぼすべての B 本をローテーションできるということです。 最終的な幅は次のようになります。`n + 1`これは、回転されていない B ブックを 1 冊だけ縦方向に配置したままにすることと一致します。
