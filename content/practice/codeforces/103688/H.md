 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた一連の単語と、その横に、開き括弧、閉じ括弧、およびダッシュの 3 つの可能な文字で構成される同じ長さの文字列が与えられます。 

括弧は、正しく一致する構造を形成します。 すべての開き括弧には一意に一致する閉じ括弧があり、すべての接頭辞で開き括弧の数が閉じ括弧の数より少なくなることはありません。 

この文字列は計算を直接説明するものではありません。 代わりに、インデックス 1 から n に対する走査ルールを定義します。 位置 1 から開始して、すべてのインデックスの読み取り順序を生成します。 ルールは再帰的です。各位置 i で、文字に応じて、すぐに i を出力するか、一致する括弧の間隔を使用して構造化された方法で出力を延期します。 

文字がダッシュまたは右括弧の場合は、現在のインデックスを出力して前方に続行します。 それが開き括弧の場合、位置 j で対応する閉じ括弧を見つけます。 その場合、最初に i+1 と j−1 の間のセグメントを再帰的に処理し、次に i 自体を出力し、最後に j+1 から続行します。 これにより、構造が有効な括弧シーケンスによって暗黙的にエンコードされることを除いて、式がツリー形式で評価される方法と同様のネストされたトラバーサルが作成されます。 

出力は 1 から n までのインデックスの順列であり、この再帰的ルールに基づいて位置が訪問される正確な順序を表します。 

n が 100000 までの制約により、あらゆる解が線形または線形に近いものになります。 一致する括弧を繰り返し検索したり、メモ化せずにセグメントを再帰的に再処理したりするシミュレーションでは、二次的な動作が発生する危険があります。 オンデマンドで一致する括弧をスキャンしたり、部分文字列を繰り返しスライスしたりする単純な再帰では、重複する間隔で繰り返し作業を行うため、制限を超えてしまいます。 

素朴なアプローチの微妙な失敗例は、深くネストされた括弧が存在する場合、たとえば「((((-))))...」のような文字列が存在する場合に発生します。 各一致が前方スキャンによって検索される場合、各レベルのコストは O(n) となり、結果として O(n^2) になります。 

もう 1 つの失敗例は、再帰順序の不適切な処理に起因します。 たとえば、すべての文字を均一に扱い、単純にインデックスをスタックにプッシュすると、リニア スキャンに対してローカルな順序を逆転させる '(' の特別な「自分自身の前の内部プロセス」動作が無視されます。

 ## アプローチ

 プロセスをシミュレートする直接的な方法は、定義に文字通り従うことです。 範囲を指定して左から右に反復処理する再帰関数を作成します。 ダッシュまたは右括弧に遭遇した場合は、インデックスを追加します。 開き括弧に遭遇した場合、まず対応する閉じ括弧を見つけて内部セグメントを再帰的に処理し、次に開き括弧を追加して閉じ括弧の後に続行します。 

このアプローチは正しいですが、非効率的です。 ボトルネックは、一致する括弧を繰り返し見つけることです。 O(n) のスタックを使用して一致を事前計算したとしても、再帰自体は依然としてすべてのセグメントにわたって構造化された走査を実行します。 スライスや繰り返しスキャンを使用して不用意に実装すると、隠れた定数が大きくなり、Python の再帰オーバーヘッドが問題になる可能性があります。 

重要な観察は、括弧によって引き起こされる構造がツリーであるということです。 各開き括弧は、その子がその一致区間内の要素であるノードに対応します。 走査ルールは事実上、最初に子を訪問し、次にノード自体を訪問し、次に次の兄弟セグメントに進みます。 これは、ノードが括弧の位置であり、葉がダッシュまたは終了であるツリー上のポストオーダーのような走査です。

これを認識すると、一致する括弧を事前に計算し、スタックを使用して走査を反復的にシミュレートできます。 各スタック フレームは、まだ処理する必要があるセグメントを表しており、ネストされたセグメントを展開する順序を明示的に制御します。

 ## アルゴリズムのチュートリアル

 まず、スタックを使用して、すべての開始ポジションに対応する括弧を事前計算します。 これにより、ネストされたセグメントのエンドポイントに直接 O(1) アクセスできるようになります。 

次に、明示的な間隔のスタックを使用して走査をシミュレートし、通常の左から右へのスキャン モードか特別な括弧拡張の内側かを常に制御します。 

1. 配列の一致を計算します。ここで、i が '(' の場合、match[i] は i に対応する閉じ括弧のインデックスを返します。
 2. 1 から n までの全範囲を表す単一の間隔でスタックを初期化し、それを左から右に処理する必要がある通常のセグメントとしてマークします。 
3. スタックが空でない間に、インターバルをポップします。 左から右にスキャンしていきます。 
4. ルールでは直接読み取りが指定されているため、「-」または「)」に遭遇すると、直ちにそのインデックスを回答シーケンスに追加します。 
5. '(' に遭遇すると、最初にその内部セグメント [i+1, match[i]−1] を再帰的に処理します。これは i を出力する前に行う必要があるため、現在の継続状態をプッシュしてから内部区間をスタックにプッシュします。
 6. 内部セグメントが終了したら、i 自体を出力に追加し、match[i] の後にスキャンを続けます。 

プッシュの順序により、内側のセグメントが常に開始ブラケットの位置自体の前に処理されるようになります。 

### なぜ効果があるのか

 括弧構造は、ルート付き順序付きツリーを定義します。各開き括弧はノードであり、その子は、同じレベルでさらにネストされていないその内部の最大の連続セグメントです。 走査ルールは、まさにこの暗黙的なツリーに対する後順走査です。子は親ノードが出力される前に完全に処理され、兄弟は左から右の順序で処理されます。 

スタック シミュレーションは、'(' セグメントを入力するたびに、'(' インデックスを出力する前にその内部間隔を完全に処理し、その後でのみ外部スキャンを再開することを保証することで、この順序付けを強制します。すべてのインデックスは、各ネスト レベルで 1 つのセグメントに正確に属するため、要素がスキップされたり重複したりすることはありません。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    match = [-1] * n
    st = []

    for i, ch in enumerate(s):
        if ch == '(':
            st.append(i)
        elif ch == ')':
            j = st.pop()
            match[i] = j
            match[j] = i

    res = []
    sys.setrecursionlimit(10**7)

    def dfs(l, r):
        i = l
        while i <= r:
            if s[i] == '(':
                j = match[i]
                dfs(i + 1, j - 1)
                res.append(i + 1)
                i = j + 1
            else:
                res.append(i + 1)
                i += 1

    dfs(0, n - 1)
    print(*res)

if __name__ == "__main__":
    solve()
```この解決策は、線形時間のスタックを使用してかっこをペアにすることから始まります。 各閉じ括弧は、一致しない最新の開き括弧を取得し、入力文字列の有効性により正しい一致を保証します。 

再帰関数`dfs(l, r)`セグメント上の走査を実装します。 間隔内で直線的にスキャンします。 括弧以外の分岐文字を見つけると、すぐに出力します。 左括弧を見つけると、開始インデックス自体を追加する前に、内側の間隔を再帰的に処理します。 この問題ではインデックスが 1 から始まるため、出力で +1 シフトする必要があります。 

重要な実装の詳細は、ポインタが`i`ブラケットが処理されたかどうかに応じて、進み方が異なります。 括弧ブロックを処理した後、内部構造を再度訪問することを避けるために、一致する終了境界に直接ジャンプします。

 ## 特殊なケース

 次のような完全にネストされた構造`(((())))`各レベル内にダッシュをインターリーブすると、マッチングと再帰の順序が強調されます。 このアルゴリズムは、各開始括弧をスタックに 1 回プッシュし、そのセグメントが完了したときに 1 回だけ解決します。 再帰が複数のレベルに下降する場合でも、各インデックスはネスト レベルごとに 1 つの開始操作と 1 つの終了操作にのみ参加するため、スキャンが繰り返されることはありません。 

のようなフラットな構造`-----`は対極です。 ここには括弧がまったくないため、アルゴリズムは単純な線形出力に縮退します。 スキャン ループは各文字を 1 回処理し、インデックスを順番に追加して、括弧のロジックが括弧以外のセグメントに干渉しないことを確認します。 

のような混合交互パターン`(-)-(-)-(-)`再帰的セグメントと線形セグメント間の正しい切り替えを検証します。 括弧で囲まれた各ブロックは一致境界によって分離されるため、1 つのブロックを終了した後、ポインターは内部の文字を再処理することなく次のセグメントで正しく再開されます。
