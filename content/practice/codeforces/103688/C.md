 ## 問題の理解

 私たちに与えられた木は、`n`ノードがあり、各ノードは整数値を保持します。 ノードを修正します`1`特別なルート候補として、すべてのノードを 2 つの素のグループに分割できるかどうかを判断する必要があります。`A`そして`B`ノードから始まるすべての単純なパスに沿って単調制約が適用されるようにする`1`。 

より正確には、任意のノードを考慮します`v`木の中で。 ノードからの一意のパスを確認します`1`に`v`。 要件はグループ内であることです`A`、値は、から離れるときにそのパス順序に沿って厳密に増加する必要があります。`1`、そしてグループ内で`B`、値はそのパス順序に沿って厳密に減少する必要があります。 パーティションはグローバルです。つまり、各ノードは 2 つのグループのうちの 1 つに一度だけ割り当てられます。この割り当てにより、すべてのルートからノードへのパスが、選択された順序付けルールと一致する必要があります。 

出力は単にそのようなパーティションがルートに存在するかどうかです。`1`。 

制約`n ≤ 100000`パーティションを明示的にテストしようとするものは直ちに除外されます。 全部チェックしても`2^n`割り当ては不可能であり、サブセット上のローカル DP でも失敗します。 有効なソリューションはすべて、ツリーのサイズが線形またはほぼ線形である必要があります。通常、`O(n)`または`O(n log n)`。 

各パスを独立して処理できると考えると、微妙な特殊なケースが発生します。 たとえば、星型ツリーの場合、ノードは`1`多くのノードに接続している場合、相対的な値に基づいて各子を貪欲に割り当てたくなる傾向があります。`a[1]`。 これは、条件がエッジに対してローカルであるだけでなく、パス上のすべての祖先の順序に依存するため、サブツリーが祖先制約を通じて間接的に相互作用する場合に問題が発生します。 

別の失敗例は、各ノードをその親とのみ比較することによって、各ノードのメンバーシップを独立して決定できると想定していることです。 これは、より深い制約を無視します。つまり、ノードは親子の順序を満たしますが、同じパスに沿った祖父母に対する相対的な順序に違反する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのノードの割り当てを試みます。`A`そして`B`。 割り当てごとに、すべてのノードをチェックして条件を検証します。`v`からの道を歩いています。`1`に`v`、そしてそれをグループ内で検証する`A`シーケンスは厳密に増加しており、`B`厳密に減少します。 親ポインターを事前計算したとしても、各チェックの深さは線形であるため、割り当てごとの合計検証は次のようになります。`O(n^2)`鎖状の木の中。 と`2^n`割り当てを行うと、これは天文学的に大きくなります。 

グローバル割り当て検索を、これらの単調な制約が実際に強制するものについての構造観察に置き換える必要があります。 重要な考え方は、この条件ではルート パスに沿った値の相対的な順序のみが考慮され、ノードが 2 つの単調チェーンに分割されます。1 つはルートから増加するシーケンスのように動作し、もう 1 つはルートから減少するシーケンスのように動作します。 

ノードを修正すると`t = 1`、この条件は、すべてのノードについて、そのノードが「ルートから増加」構造に属するか、「ルートから減少」構造に属するかを決定していることと同じであり、この決定は祖先チェーンに沿って一貫性を保たなければなりません。 ノードを 2 つのグループのいずれかに配置すると、すべての子孫パスにそのノードが含まれるため、そのすべての子孫を配置する方法が制限されます。 

これは古典的な変換につながります。パスについて考える代わりに、有向の方法でツリーのエッジに沿って制約を適用します。各ノードは、その親と独自に割り当てられた単調タイプの両方と互換性がなければなりません。 問題は、値の比較から得られるローカルでチェック可能なルールをすべてのエッジが尊重するように、2 つのラベルのうちの 1 つを各ノードに割り当てることができるかどうかをチェックすることに帰着します。 

重要な単純化は、ツリーをルート化した後は、ノードとその親の間の比較のみが重要になるということです。`1`。 有効なグローバル パーティションが存在する場合は、各ノードの選択が一意のルート パスに沿った順序制約と一致していることを確認することで構築でき、違反は何らかの親子関係ですでに発生している必要があります。 これにより、グローバル パス制約がエッジ上のローカル整合性チェックに変わります。

 ## アルゴリズムのチュートリアル

 ノードでツリーをルートします`1`そして制約を下方向に伝播します。 

1. ノードでツリーをルート化します`1`BFS または DFS を使用して親子構造を計算します。 

すべての制約はノードから始まるパスに沿って定義されるため、この手順が必要です。`1`、ルート化によりパスが祖先チェーンに変換されます。 
2. 各ノードについて、ルート パスに沿って増加するグループの一部のように動作するか、減少するグループの一部のように動作するかに応じて、2 つの状態のいずれかを割り当てようとします。 

ルートは最初は制約されていませんが、比較の開始参照を定義します。 
3. ルートから BFS または DFS の順序でツリーをたどります。 各エッジについて`(u, v)`、どの割り当てを決定するか`v`すでに選択されている割り当てと互換性があります`u`。 

これは相対値をチェックすることで行われます。`a[u]`そして`a[v]`単調条件により、ルートからノードへのセグメントに沿って一貫した方向が強制されるためです。 
4. ノードが両方の割り当てを矛盾なく行うことができる場合、決定を延期します。 1 つだけで済む場合は修正します。 何も取得できない場合は、ルートが無効であると直ちに結論付けられます。 

このステップにより、ローカルな実現可能性の伝播が強制され、後でパス制約を破る構成にコミットすることがなくなります。 
5. すべてのノードが処理されるまで伝播を続けます。 矛盾が見つからない場合、パーティションは存在します。 

中心的な考え方は、ツリーがルート化され、制約が単調な方向の選択として解釈されると、すべての禁止された構成が何らかの親子エッジ上で直接の不一致として現れるということです。 

### なぜ効果があるのか

 不変条件は、ノードを処理した後の条件です。`u`、そのサブツリー内のすべてのノードには、以下を含むすべてのルートからノードへのパス制約と一致する割り当てがあります。`u`。 ノードからのすべてのパスなので`1`エッジの一意のシーケンスを通過するノードへのパスの場合、厳密な単調性の違反は最初にそのパスに沿った隣接するペアで発生する必要があります。 したがって、すべてのエッジが導出されたローカル制約を満たしている場合、ローカルでまだ検出されていない矛盾をパスに導入することはできなくなります。 これにより、グローバル パス条件がエッジ ローカルの実行可能性チェックのセットに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        g[y].append(x)

    parent = [-1] * n
    parent[0] = 0
    order = [0]
    stack = [0]

    while stack:
        u = stack.pop()
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)
            order.append(v)

    # dp[u][0/1]: whether u can be in group A (0) or B (1)
    dp = [[True, True] for _ in range(n)]

    for u in order[::-1]:
        for v in g[u]:
            if v == parent[u]:
                continue

            # propagate constraints from u to v
            # if we pick same group, check monotonic consistency
            new0 = new1 = False

            # try u in group 0 or 1 with v in group 0 or 1
            for gu in [0, 1]:
                for gv in [0, 1]:
                    if not dp[v][gv]:
                        continue
                    if not dp[u][gu]:
                        continue

                    ok = True
                    if gu == gv:
                        if gu == 0 and not (a[u] < a[v]):
                            ok = False
                        if gu == 1 and not (a[u] > a[v]):
                            ok = False

                    if ok:
                        if gu == 0:
                            new0 = True
                        else:
                            new1 = True

            dp[u][0] = dp[u][0] and new0
            dp[u][1] = dp[u][1] and new1

    # check root has at least one valid state
    print("YES" if (dp[0][0] or dp[0][1]) else "NO")

if __name__ == "__main__":
    solve()
```この実装では、スタックベースの DFS を使用してルート付きツリーを構築し、実行可能性をリーフから上に伝播しようとします。 の`dp[u][t]`配列はノードかどうかを表します`u`グループに割り当てることができます`t`サブツリー制約との一貫性を保ちながら。 ネストされた遷移では、必要な厳密な不平等規則を使用して、親と子の割り当て間の互換性がチェックされます。 

重要な点は、2 つの隣接するノードが同じグループに配置されている場合にのみ、ルート パスのそのセグメントに沿って厳密な順序制約が直接適用されるため、比較が重要になることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、厳密に増加するチェーンまたは厳密に減少するチェーンです。 たとえば、パス内で`1 - 2 - 3 - 4`価値観を持って`[4,3,2,1]`、すべてのエッジが一貫した減少パターンを満たすため、すべてのノードを同じグループに配置できます。`B`。 アルゴリズムはすべてのエッジ遷移を同じグループ ルールの下で互換性があるとマークするため、実現可能性がルートにきれいに伝播し、返されます。`YES`。 

もう 1 つのエッジ ケースは、ノードを中心とするスターです。`1`ここで、子の値は順序付けされていません。 各子はルートに対して相対的にのみ制約されるため、子間の制約は存在しません。 DP では子エッジごとに独立した割り当てが可能であり、制約のサイクルが形成されないため、ルートは有効なままになります。 

3 番目のエッジ ケースは、強制的なグループ割り当て内で単一のエッジが厳密な不等式に違反する場合です。 例えば`1 - 2`と`a[1] = 5`そして`a[2] = 5`両方の同じグループ割り当てを即座に無効にし、ノードに有効な状態を残しません。`1`。 伝播によってこれがリーフ レベルで検出され、ルートが即座に無効になります。これは、違反がローカルで検出され、ツリーのより深くに隠蔽できないことを示しています。
