 ## 解決策
 ## 問題の理解

 n 個の真珠が円形に配置されています。 各パール i は、負でない整数値 ci を持ちます。 このプロセスは、開始パール i を繰り返し選択するという意味で対話的ですが、これは ci が少なくとも 1 で、現在十分な数のパールがまだ存在している場合に限られます。 

パール i を選択すると、i から時計回りの順序で正確に ci のパールの連続したブロックが削除されます。そのブロック内の最初のパールは、その時点でまだ存在している必要があります。 除去後、残りの真珠は閉じて新しい円になり、相対的な秩序が保たれます。 

有効な動きがなくなるまで続行します。 移動は、選択した開始パールがまだ存在し、必要なブロック サイズが現在の残りのパールの数を超えない場合にのみ正当です。 

課題は、除去される真珠の数を最大化することです。 この最大値を達成するすべての方法の中で、順序を無視して、各ステップで使用される開始インデックスのセットによってのみ解が定義される、個別の解がいくつ存在するかを数えます。 

n ≤ 2000 および ci ≤ 2000 という制約は、O(n³) または O(n² log n) の動的プログラミング アプローチが C++ ではかろうじて合格する可能性がありますが、Python では合格しない可能性があることを示唆しています。 O(n²) または O(n² log n) に近い解が必要ですが、シーケンスの数が n とともに指数関数的に増加するため、削除シーケンスを直接列挙することは不可能です。 

微妙な問題は、削除によって円構造が動的に変化することです。 プロセスを段階的にシミュレートしようとする素朴な解釈は、「時計回りに次の真珠」の正体が削除のたびに変わるため、すぐに曖昧になってしまいます。 

重要なエッジケースは、ほとんどの真珠で ci = 0 の場合です。 たとえば、すべての ci = 0 の場合、空のシーケンスが唯一の有効な解であるため、移動は不可能であり、答えは 0 1 になります。 もう 1 つのエッジ ケースは、1 つの ci が大きい場合です (たとえば、n = 5、c1 = 5)。その後、1 で削除するとすべてがすぐに削除されますが、残りのサイズによっては他の位置から開始することが不正になる可能性があるため、解のセット定義が非常に重要になります。 

## アプローチ

 ブルートフォースアプローチでは、有効な削除の考えられるすべてのシーケンスをシミュレートします。 各状態で、有効な開始パールを選択し、再帰的にブロックを削除して、サークル構造を更新します。 

これはプロセスに正確に従っているため、原理的には正しいです。 しかし、国家空間は膨大です。 円を表現する場合でも、どの真珠が残っているかを追跡する必要があり、2ⁿ のサブセットが考えられます。 各遷移は循環隣接にも依存するため、完全な循環構造をエンコードしないと単純なメモ化が困難になります。 

サブセットに対して DP を試みたとしても、各状態には O(n) 個の遷移が必要となり、O(n 2ⁿ) になりますが、これは完全に実行不可能です。 

重要な観察は、円構造はまだ生きている真珠の間隔に関してのみ重要であるということです。 削除の順序を修正すると、各操作は周期シーケンスの連続セグメントを削除します。これは間隔 DP を示唆します。 ただし、真の簡素化は、プロセスを逆に行うことで実現します。 

セグメントを削除することを考える代わりに、固定された初期円内で互いに素な間隔を選択することによって有効な削除シーケンスを構築することを考えます。 各演算は、i から始まる長さ ci のセグメントを消費します。つまり、元の円では、選択された各演算は区間 [i, i+ci−1] (mod n) の選択に対応し、これらの区間は最終的なシーケンス順序で重複してはなりません。 

これにより、問題は円上の加重区間の最大セットを選択することに変換されます。各区間の重みは ci であり、区間が ci ≤ 現在利用可能なセグメント サイズの場合にのみ有効であることも強制されます。 重要な洞察は、最適な戦略が、ブレークポイントを固定した後の円の線形化バージョンで重複しない間隔の集合を選択することに対応しているということです。

可能なすべての開始位置で円を分割し、それを線形配列に変換し、最適な間隔スケジューリング DP を計算します。 各間隔 i は、i+ci−1 で終わるセグメントを定義します。 次に、重みが ci である重み付きインターバル スケジューリングのバリアントを解きます。ただし、ここではすべての重みが目的への寄与でもあります。 

除去された真珠の最大数を固定した後、計数ソリューションは、最適な遷移に対する標準的な DP 計数問題になります。

 ## アルゴリズムのチュートリアル

 1. 円のカット開始点としてインデックスを固定し、ラップアラウンドを処理するために配列を複製します。 これにより、円形構造が長さ 2n の線形アレイに変わります。 
2. 考えられる開始間隔 i ごとに、j = i + ci − 1 で終了する削除間隔を定義します。 j が i + n − 1 を超える場合は、完全なサイクルを複数回ラップすることになるため、それを破棄します。これは線形化後は無効です。 
3. ここで、固定回転ごとにセグメント [0, n−1] に対して DP を実行します。 DP 状態 dp[i] は、線形配列の位置 i から始まる最良の結果を表します。これは、i 以降で達成可能な削除されたパールの最大数を意味します。 
4. 遷移では、位置 i をスキップするか、i から始まる間隔を使用します。 これを使用する場合は、i + ci にジャンプし、スコアに ci を追加します。 
5. 正確性を確保するには、間隔が重ならないようにする必要があります。 間隔を選択した後、その終わりを超えて先に進むため、これは自然に適用されます。 
6. dp と並行して、dp[i] を達成する方法の数である cnt[i] を維持します。 複数のトランジションが同じ dp 値を生成する場合、それらのカウントを 998244353 を法として合計します。 
7. すべての回転の dp を計算した後、すべての回転の最大 dp[0] を取得します。 答えは、この最大値と対応するカウントです。 

重要な不変条件は、dp[i] が常に、選択された線形化における i で始まるサフィックスの最適解を表すということです。 すべての有効な削除シーケンスは、間隔選択の 1 つのチェーンに正確に対応し、すべてのチェーンは、元のサークル内の有効な削除シーケンスに対応します。 すべての回転を考慮するため、有効な循環解が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    c = list(map(int, input().split()))
    
    a = c * 2
    
    best_ans = 0
    best_cnt = 0

    for start in range(n):
        dp = [0] * (2 * n + 1)
        cnt = [0] * (2 * n + 1)
        dp[2*n] = 0
        cnt[2*n] = 1

        for i in range(2 * n - 1, start - 1, -1):
            if i >= start + n:
                dp[i] = 0
                cnt[i] = 1
                continue

            # option 1: skip
            best = dp[i + 1]
            ways = cnt[i + 1]

            # option 2: take interval
            if a[i] > 0:
                j = i + a[i]
                if j <= start + n:
                    val = a[i] + dp[j]
                    if val > best:
                        best = val
                        ways = cnt[j]
                    elif val == best:
                        ways = (ways + cnt[j]) % MOD

            dp[i] = best
            cnt[i] = ways % MOD

        if dp[start] > best_ans:
            best_ans = dp[start]
            best_cnt = cnt[start]
        elif dp[start] == best_ans:
            best_cnt = (best_cnt + cnt[start]) % MOD

    print(best_ans, best_cnt)

if __name__ == "__main__":
    solve()
```コードは回転トリックを明示的に実装します。 配列は 2 倍になるため、循環間隔は線形セグメントになります。 開始位置ごとに、位置をスキップするか、そこから始まる削除間隔を取るサフィックス DP を実行します。 

dp 配列は、指定されたインデックスから除去可能な最大合計を格納し、cnt はその値を達成する方法の数を格納します。 逆方向反復により、状態 i を計算するときに、将来のすべての状態がすでに計算されていることが保証されます。 

境界処理は、間隔が選択した n 個の長さのウィンドウを超えないようにする場合に重要です。 これは、j ≤ start + n をチェックすることによって強制されます。 

円の最初のカットは任意であり、すべての有効な解は 1 つの回転位置合わせで一意の表現を持つため、最終的な答えはすべての回転にわたって集計されます。

 ## 特殊なケース

 すべての ci がゼロの場合、DP は間隔を取りません。 このアルゴリズムは、スキップ遷移のみが存在するように dp 遷移を正しく初期化し、dp[0] = 0 および cnt = 1 を生成します。 

単一の ci が n に等しい場合、その間隔は選択された回転ウィンドウ全体を消費します。 DP では、この間隔を取ると終了境界に直接ジャンプし、n のフルスコアが得られます。 重複する間隔はあり得ないため、その回転ではカウントは正確に 1 のままになります。 

複数の等しい長さの間隔が重複する場合、スキップ対テイク DP は、重複しないチェーンのみが有効なシーケンスに寄与することを保証します。 間隔を取ろうとすると、オーバーラップを防ぐジャンプが強制されるため、状態遷移中に無効な組み合わせが形成されることはありません。
