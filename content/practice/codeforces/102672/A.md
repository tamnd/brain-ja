 ## 解決策
 # 問題の理解

 ロックは頂点が 2 色で塗られた木です。 移動により、1 つの頂点を再ペイントすることも、現在すべての頂点が同じ色になっている接続領域全体を削除することもできます。 タスクは、頂点がなくなるまでに必要な最小移動数を見つけることです。 入力により、頂点の数、初期のバイナリ カラー、およびツリー エッジが与えられます。 出力は可能な限り最小の操作数です。 

重要な点は、ツリー構造が削除のシミュレーションを要求していないことです。 頂点の数は 200,000 に達する可能性があるため、考えられる多くの削除順序を試したり、操作のたびにツリーを維持したりするアプローチは適合しません。 二次アルゴリズムであっても、最大サイズではすでに約 400 億の演算が必要となるため、解は線形時間に近い必要があります。 

自然な戦略は 2 つあります。 最初の単色コンポーネントをすべて個別に削除することも、頂点を再ペイントする操作に時間を費やして、多くのコンポーネントが結合して一緒に消えるようにすることもできます。 課題は、部分的な再描画と部分的な削除を複雑に組み合わせても、これら 2 つのアイデアの最良のものに勝るものはないということを認識することです。 

星のような形をした 4 つの頂点を持つツリーを考えてみましょう。```
4
1000
1 2
1 3
1 4
```最初は単色コンポーネントが 4 つあるため、コンポーネントを 1 つずつ削除すると 4 回の操作が必要になります。 ただし、中心を再ペイントするとツリー全体が白くなり、最後の削除ですべてが削除され、答えは 2 になります。 コンポーネントをカウントするだけのソリューションはここで失敗します。 

もう 1 つの重要なケースは、すべての頂点がすでに同じ色を持っている場合です。 例えば：```
3
000
1 2
2 3
```答えは 1 つです。ツリー全体が既に単一の取り外し可能なコンポーネントになっているからです。 削除する前に常に 1 つの再描画を追加する数式は、誤って 2 を返します。 

反対の極も重要です。 単一の頂点の場合:```
1
1
```答えは一つです。 再ペイントする必要はありませんが、削除操作によって頂点を削除する必要があります。 

# アプローチ

 直接的な総当たりアプローチでは、どのコンポーネントを最初に削除し、どの頂点を再ペイントするかを決定しようとします。 ツリーの考えられるすべての状態に対して、利用可能なすべての操作を試行し、メモ化による再帰を使用できます。 これは、考えられるすべてのシーケンスを探索するため正しいですが、状態の数は頂点の数とともに指数関数的に増加します。 小さな木であっても、作成される可能性のあるカラーリングと残りの頂点セットが多すぎるため、このアプローチは使用できません。 

より単純な強引なアイデアは、現在の単色コンポーネントを繰り返しカウントし、可能な限りの再描画を試みることです。 各再描画後も可能な選択肢の数が多数のままであるため、これでも失敗します。 200,000 個の頂点がある場合、考えられる単一の頂点の再描画をすべてチェックするだけでもすでにコストがかかりすぎます。 

重要な点は、再描画は異なる色のグループの数を減らすことによってのみ役立つということです。 色は 2 つしかないため、ツリー全体を 1 色にすると決めた場合、最も安価な選択は、頻度の低い色のすべての頂点を再描画してから、ツリーを一度削除することです。 これには次の費用がかかります。```
min(number of white vertices, number of black vertices) + 1
```もう 1 つのオプションは、再ペイントをまったく行わないことです。 その場合、初期の単色連結コンポーネントはすべて最終的に削除する必要があるため、コストはそのようなコンポーネントの数に等しくなります。 

驚くべきことに、2 つの戦略を混合しても答えは改善されないということです。 少数色の数よりも少ない頂点を再ペイントすると、両方の色の頂点がいくつか残ります。 残りの異なる色の領域は個別に削除する必要があり、最初のコンポーネントをすべて削除するだけでは合計を達成できません。 1 つの色を完全に削除するのに十分な頂点を再ペイントすると、少なくともツリー全体を単色にするコストをすでに支払っていることになります。 

したがって、解決策は、1 回の走査で 2 つの値 (単色成分の数と各色の頂点の数) をカウントすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 各色を持つ頂点の数を数えます。 これは、ツリーから 1 つの色を消去し、他の色を再ペイントし、最後に 1 回の削除を実行する戦略のコストを示します。 
2. ツリーを 1 回走査し、単色の連結成分を数えます。 すべての未訪問の頂点からトラバースを開始します。 同じ色の到達可能な頂点はすべて同じコンポーネントに属します。 
3. 考えられる 2 つの答えを計算します。 1 つ目は単色成分の数です。 2 番目は、あまり一般的ではない色の頂点の数に、最後の削除操作を 1 回加えたものです。 
4. すべての最適シーケンスがこれら 2 つのケースのいずれかに該当するため、これら 2 つの値のうち小さい方を出力します。 

なぜ効果があるのか:

 すべての削除操作により、現在のツリーの 1 つの単色の接続コンポーネントが削除されます。 色を完全に除去しない場合、残った色の境界により、元のコンポーネントを処理するのと少なくとも同じコストを支払う必要があります。 これらのコンポーネントの境界を回避する唯一の方法は、ツリー全体が 1 つの色になるように十分な頂点を再ペイントすることです。 このような最も安価な変換では、より小さいカラー クラスのすべての頂点が再描画されます。 その後、1 回削除するとすべてが削除されます。 すべての最適なソリューションは両方の色を維持するか、一方の色を完全に削除する必要があるため、これら 2 つのコストの最小値は常に達成可能であり、改善することはできません。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    count0 = s.count('0')
    count1 = n - count0

    components = 0
    visited = [False] * n

    for i in range(n):
        if not visited[i]:
            components += 1
            color = s[i]
            stack = [i]
            visited[i] = True

            while stack:
                v = stack.pop()
                for u in graph[v]:
                    if not visited[u] and s[u] == color:
                        visited[u] = True
                        stack.append(u)

    repaint_strategy = min(count0, count1) + 1
    print(min(components, repaint_strategy))

if __name__ == "__main__":
    solve()
```コードの最初の部分では、隣接リストを使用してツリーを構築します。 木にはまさに`n - 1`したがって、各エッジを 2 回保存すると、メモリ使用量が線形になります。 

色数は、完全な再描画戦略を評価するのに十分です。 各色の頂点の合計数のみが重要であるため、どの特定の頂点が再ペイントされるかを知る必要はありません。 

DFS は単色成分をカウントします。 新しい未訪問の頂点が見つかると、ちょうど 1 つのコンポーネントの走査が開始されます。 DFS は同じ色の頂点までエッジをたどるだけなので、反対色の頂点は自然にツリーを異なるコンポーネントに分割します。 

すべての頂点が正確に 1 回訪問され、各トラバース開始が 1 つのコンポーネントに対応するため、コンポーネント数に 1 つずれの問題はありません。 Python の整数は、オーバーフローを考慮せずに最大数も処理します。

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての頂点とエッジは、走査中に 1 回処理されます。 |
 | スペース | O(n) | 隣接関係リスト、訪問先アレイ、および DFS スタックには線形情報が格納されます。 |

 入力サイズは 200,000 頂点に達する可能性があり、アルゴリズムは頂点とエッジごとに一定量の作業のみを実行します。 必要な範囲内に快適に収まります。 

# テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.readline
    n = int(data())
    s = data().strip()

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, data().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    count0 = s.count("0")
    count1 = n - count0

    visited = [False] * n
    components = 0

    for i in range(n):
        if not visited[i]:
            components += 1
            color = s[i]
            stack = [i]
            visited[i] = True
            while stack:
                v = stack.pop()
                for u in graph[v]:
                    if not visited[u] and s[u] == color:
                        visited[u] = True
                        stack.append(u)

    ans = min(components, min(count0, count1) + 1)

    sys.stdin = old_stdin
    return str(ans) + "\n"

 # エッジケース

 星型ツリーの場合:```
4
1000
1 2
1 3
1 4
```このアルゴリズムは 4 つの単色成分をカウントします。 また、1 つの黒い頂点と 3 つの白い頂点もカウントし、2 つの操作の再描画戦略を生成します。 最小値は 2 で、中心の再描画とツリー全体の削除の順序に一致します。 

完全に単色のツリーの場合:```
3
000
1 2
2 3
```走査により 1 つのコンポーネントが見つかります。 再ペイントする黒い頂点がないため、再ペイント戦略には 4 コストがかかります。式は次のようになります。`0 + 1 = 1`。 ツリーはすぐに削除できるため、答えは 1 つのままです。 

可能な限り最小の入力の場合:```
1
1
```トラバースでは、コンポーネントが 1 つだけ作成されます。 リペイント戦略でも 1 つ与えられるため、最終的な答えは 1 つになります。 最後の頂点を削除するには常に削除が必要であるため、アルゴリズムが誤ってゼロを返すことはありません。
