 ## 解決策
 ## 問題の理解

 負でない整数のオリジナルの配列があります。 配列を直接見る代わりに、連続するすべての長さの合計が与えられます。`K`。 元の配列が`A`、最初に指定された値は次の合計です。`A[1]`を通して`A[K]`、次の値はウィンドウを 1 位置ずらした後の合計、というように続きます。 タスクは、指定された一連のウィンドウ合計を生成できる元の配列の数を数えることです。 

入力は、元の配列の長さ、ウィンドウ サイズ、ウィンドウ合計のシーケンスを記述します。 出力は有効な元の配列の数を法でとったものです。`998244353`。 

有用な制約は、配列の長さがおよそであることです。`2 * 10^5`したがって、要素の可能な値を試したり、配列を列挙したりする解決策は不可能です。 二次処理でもすでに大きすぎます。`4 * 10^10`操作。 重複する合計の代数構造を利用し、問題を線形スキャンと小さな組み合わせ計算に減らす必要があります。 

微妙な点は、最初の`K`最終的なカウントでは要素がすべて独立しているわけではありません。 後の要素は、隣接するウィンドウの合計間の差によって強制されます。 ただし、これらの強制要素は、初期値が十分に大きくないと負になる可能性があります。 最初のウィンドウ合計のみをチェックし、その後の非負性制約を無視するソリューションでは、無効な配列がカウントされます。 

例えば：```
Input:
4 3
1 0

Output:
0
```最初のウィンドウでは、`A1 + A2 + A3 = 1`。 2 番目のウィンドウでは、`A2 + A3 + A4 = 0`、 それで`A4 = A1 - 1`。 すべての要素が負でない必要があるため、`A1`少なくとも`1`。 最初のウィンドウでは小さな値のみが許可され、制約を考慮した結果、有効な選択肢はありません。 

別の特殊なケースは、答えが大きな上限値との組み合わせを必要とする場合に発生します。 例えば：```
Input:
2 2
1000000000

Output:
1755648
```がある`1000000001`非負の数値の可能なペアですが、答えはモジュロで必要です`998244353`。 上限値が 10 億に近いため、上限値までの通常の階乗事前計算は不可能です。 組み合わせ論では、選択された要素の数が少ないという事実を利用する必要があります。 

## アプローチ

 直接的なアプローチは、最初のものを推測することです`K`要素。 これらの値が固定されると、その後のすべての要素が決定されます。 方程式`B[i+1] - B[i] = A[i+K] - A[i]`以前の要素から新しい要素をそれぞれ計算してみましょう。 すべての有効な配列はこれらの違いを満たさなければならないため、この方法は正しいです。 

問題は、最初の`K`要素には膨大な数の割り当てが可能です。 最初のウィンドウ合計が適度に大きいだけであっても、その合計の可能な分布の数は次のようになります。`K`ポジションは組み合わせで増加します。 それらを列挙することは不可能です。 

重要な観察は、差分方程式が配列を同じインデックスモジュロを持つ独立した位置のチェーンに分割することです。`K`。 最初のすべてに対して`K`位置に応じて、そのチェーン内の後のすべての要素は、開始値に既知のオフセットを加えたものにすぎません。 残る唯一の問題は、チェーン全体を非負に保つために、各開始値がどのくらいの大きさでなければならないかということです。 

最初のそれぞれの最小許容値を見つけた後、`K`ポジションの場合、これらの必須金額を差し引きます。 残りの金額は自由に分配できます。`K`開始位置。 これは標準的な星と棒の問題になります。 

残りの金額が`S`、それを分散する方法の数`K`負でない変数は次のとおりです。`C(S + K - 1, K - 1)`唯一の追加の問題は、この組み合わせの頂点がモジュラスを超える可能性があるため、最終的な組み合わせの計算にはルーカスの定理が必要になることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | K の指数 | O(K) | 遅すぎる |
 | 最適 | O(N + K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のそれぞれの最小必要値を計算します。`K`要素。 すべての剰余クラスのモジュロに対して`K`、要素は連続する値が異なるチェーンを形成します。`B[i+1] - B[i]`。 チェーン内を移動している間、累積オフセットを維持し、到達した最小オフセットを記録します。 最小オフセットが負の場合、開始値はその絶対値だけ増加する必要があります。 
2. これらの最小必要な開始値をすべて加算します。 この合計がより大きい場合`B[1]`、最初のウィンドウでは十分な合計値を提供できないため、有効な配列が存在しません。 
3. しましょう`S`必須の最小値をすべて支払った後の最初のウィンドウ合計の未使用部分になります。 残りの値は次のいずれかの場所に配置できます。`K`開始位置。 
4. コンピューティング`C(S + K - 1, K - 1)`モジュロ`998244353`。 組み合わせの下位部分は係数より小さいため、ルーカスの定理により計算が最大 1 つの小さな組み合わせに減ります。 

なぜ効果があるのか:

 隣接するウィンドウの合計の差により、要素間のあらゆる関係が修正されます。`K`離れた位置にあります。 一度最初の`K`要素が選択されると、配列全体が決定されます。 このアルゴリズムは、非負性で必要な各選択肢の下限を正確に見つけます。 これらの下限が削除された後、残りのすべての分布は有効な配列を生成し、すべての有効な配列はそのような分布の 1 つに正確に対応します。 星と棒の式は、ケースを欠落したり重複したりすることなく、それらの分布をカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def comb_small_top(n, r):
    if r < 0 or r > n:
        return 0
    if r == 0:
        return 1
    res = 1
    for i in range(r):
        res = res * (n - i) % MOD
    fact = 1
    for i in range(1, r + 1):
        fact = fact * i % MOD
    return res * pow(fact, MOD - 2, MOD) % MOD

def comb_lucas(n, r):
    if r >= MOD:
        return 0
    low = n % MOD
    if r > low:
        return 0
    return comb_small_top(low, r)

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    low = [0] * k
    offset = [0] * k
    minimum = [0] * k

    for i in range(k):
        minimum[i] = 0

    for i in range(n - k):
        idx = i % k
        offset[idx] += b[i + 1] - b[i]
        if offset[idx] < minimum[idx]:
            minimum[idx] = offset[idx]

    need = 0
    for x in minimum:
        need += -x

    if need > b[0]:
        print(0)
        return

    remaining = b[0] - need
    print(comb_lucas(remaining + k - 1, k - 1))

if __name__ == "__main__":
    solve()
```配列`offset`最初のそれぞれの量を保存します`K`チェーンを前方にたどると位置が変わります。 更新では、隣接するブロック合計間の差分が使用されます。これは、その差分が正確にウィンドウに入る新しい要素からウィンドウから出ていく古い要素を差し引いたものであるためです。 

配列`minimum`各チェーンが到達した最小オフセットを記録します。 チェーンが寄ってきたら`5`開始値から、開始値は少なくとも貢献する必要があります`5`その連鎖を負にしないようにするためだけです。 

変数`need`これらの下限によって強制される合計量です。 最初のウィンドウ合計からそれを除いた後、残りの金額は自由に分配できます。 

注目すべきはその組み合わせ機能だ。 二項係数の分子は次の値を超える可能性があります。`998244353`、ただし、選択されたカウント`K - 1`は常に係数より小さいです。 ルーカスの定理によれば、分子の下の部分が小さすぎる場合、結果はゼロになります。そうでない場合は、素数を法とする単一の通常の組み合わせで十分です。 

## 実用的な例

 最初のサンプルの場合:```
5 4
2 3
```チェーンのオフセットは次のとおりです。 

| ポジション | オフセットの変更 | 最小オフセット | 必須の値 |
 | --- | --- | --- | --- |
 | 1 | +1 | 0 | 0 |
 | 2 | なし | 0 | 0 |
 | 3 | なし | 0 | 0 |
 | 4 | なし | 0 | 0 |

 残りの金額は、`2`。 

配布数は以下の通りです。`C(2 + 4 - 1, 4 - 1) = C(5,3) = 10`トレースにより、将来のすべての要素がオフセットを通じて表現された後は、最初のウィンドウ合計のみが重要であることが確認されます。 

2 番目のサンプルの場合:```
6 1
2 3 0 8 2 5
```ここ`K = 1`, したがって、すべての要素は直接固定されます。 

| ステップ | 現在のオフセット | 最低限必要なもの |
 | --- | --- | --- |
 | A1 | 0 | 0 |
 | A2 | 0 | 0 |
 | A3 | 0 | 0 |
 | A4 | 0 | 0 |
 | A5 | 0 | 0 |
 | A6 | 0 | 0 |

 最初の値によって、可能な唯一の配列がすでに決定されています。 組み合わせは次のとおりです。`C(2 + 1 - 1, 0) = 1`トレースは次のことを実行します。`K = 1`自由がなくなった場合。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + K) | それぞれの差異は 1 回処理され、最終的な組み合わせでは最大でも次の値が使用されます。`K`掛け算。 |
 | スペース | O(K) | 最初のオフセットと最小要件のみ`K`位置が保存されます。 |

 このアルゴリズムは、リニア スキャンを使用して大きな入力サイズを処理します。 組み合わせ計算も次の制限を受けます。`K`、最大でも`2 * 10^5`, そのため、一般的な競技プログラミングの制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        n, k = map(int, input().split())
        b = list(map(int, input().split()))

        MOD = 998244353
        offset = [0] * k
        minimum = [0] * k

        for i in range(n - k):
            j = i % k
            offset[j] += b[i + 1] - b[i]
            minimum[j] = min(minimum[j], offset[j])

        need = sum(-x for x in minimum)
        if need > b[0]:
            print(0)
            return

        r = k - 1
        ncr = b[0] - need + k - 1
        if r > ncr % MOD:
            print(0)
            return

        num = 1
        den = 1
        for i in range(r):
            num = num * (ncr % MOD - i) % MOD
            den = den * (i + 1) % MOD
        print(num * pow(den, MOD - 2, MOD) % MOD)

    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdout = sys.__stdout__
    sys.stdin = old
    return out.getvalue()

assert run("5 4\n2 3\n") == "10\n"
assert run("6 1\n2 3 0 8 2 5\n") == "1\n"

assert run("2 2\n1000000000\n") == "1755648\n"
assert run("3 3\n5\n") == "21\n"
assert run("4 2\n0 0 0\n") == "0\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 2 / 1000000000`|`1755648`| 大きな組み合わせ値とモジュラー処理 |
 |`3 3 / 5`|`21`| シンプルな星とバーのケース |
 |`4 2 / 0 0 0`|`0`| 不可能な非負性制約 |

 ## 特殊なケース

 ゼロ回答の場合:```
4 3
1 0
```ブロックの違いは、`-1`、4 番目の要素が最初の要素より 1 つ小さくなります。 アルゴリズムは、最初のチェーンには最小開始値が必要であることを記録します。`1`。 最初のブロック合計は小さすぎるため、他の非負の値と一緒にこの要件を満たすことができないため、次のように出力されます。`0`。 

大きな値の場合:```
2 2
1000000000
```開始値は 2 つあり、それらの合計のみが制限されています。 アルゴリズムはこれを次のように変換します。`C(1000000001,1)`そしてそれをモジュロで評価します`998244353`最大 10 億までの階乗を構築しようとするのではなく、ルーカスの定理を使用します。 出力は正しいモジュール結果です。 

のために`K = 1`:```
6 1
2 3 0 8 2 5
```すべてのウィンドウには要素が 1 つだけ含まれるため、選択肢はありません。 チェーン加工によりさらなる自由度が生まれ、`K - 1 = 0`正しく返します`1`。
