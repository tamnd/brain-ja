 ## 問題の理解

 順列と循環を扱うように求められます。 1 から 2 までのラベルが付けられた色石の列があると想像してください。$n$。 モンクは、順列によって決定される「サイクルシフト」操作を実行できます。$p$。 ポジションの選択$i$、そこにある石が所定の位置に移動します$p[i]$、中の石$p[i]$に移動します$p[p[i]]$, and so on, effectively rotating the elements along a cycle in the permutation. Over multiple days, the monks apply these operations repeatedly to produce new arrangements of the stones.

 目標は 2 つあります。 First, we want to maximize the number of distinct arrangements that can be generated using these operations. 第 2 に、初期の順列をこの最大数の配置を達成するものに変換するために必要なスワップの数を最小限に抑えたいと考えています。 The output is therefore the maximum number of arrangements modulo$10^9 + 7$そして、「最大循環」順列に達するための最小スワップ数。 

制約はかなり大きいです。 それぞれ$n$まで可能です$10^6$、との合計$n$すべてのテストケースにわたって、$10^6$。 これは、$O(n^2)$アプローチが遅すぎるでしょう。 線形または線形演算的なものが必要です$n$。 エッジケースには、すでに単一サイクルである順列、完全にソートされた順列、完全に 2 サイクルで構成される順列が含まれます。これらは、サイクル分解と必要なスワップ数の両方に影響を与えるためです。 

## アプローチ

 ブルートフォース手法では、サイクル シフト操作を繰り返し適用することで、各順列に対して可能なすべての配置を生成しようとします。 これは概念的には正しいですが、実行不可能です。$n = 10^6$許可された時間をはるかに超えてしまう可能性があります。 単純な方法でサイクルを 1 つずつ構築する場合でも、慎重に行わないと時間がかかりすぎます。 

重要な観察は、問題がサイクル分解に帰着するということです。 各操作はサイクルに沿って要素を回転させ、個別の配置の数はすべてのサイクルの長さの最小公倍数になります。 サイクルに長さがある場合$k$、回転させることができます$k$生産にかかる時間$k$独特のアレンジメント。 したがって、配置の数を最大化するには、サイクル長の最小公倍数を最大化する必要があります。 これは、LCM が最大化されるように、サイクルを素数累乗またはその積となる長さに結合することによって達成されます。 

スワップの最小数については、順列を並べ替えるための最小スワップは次のとおりであるというよく知られた結果に依存します。$n - \text{number of cycles}$。 ここで、すべての 2 サイクルを 3 サイクルに結合すると、最小限のスワップで最適な LCM に達するように順列を調整できます。 これにより、明確な線形時間戦略が得られます。順列をサイクルに分解し、その長さの最小公倍数を計算し、最小のスワップ数で最大化するようにサイクルを調整します。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$そして順列$p$。 順列をゼロベースのインデックス付けに変換して、サイクル トラバーサルを簡素化します。 
2. 訪問した位置をマークするために配列を初期化します。 各インデックスを反復処理します。 インデックスが訪問されていない場合は、そのサイクルを走査し、サイクル内のすべての要素を訪問済みとしてマークし、サイクルの長さをカウントします。 
3. すべてのサイクルの長さを保存します。 修道士が生成できる個別の配置の数は、これらすべてのサイクル長の最小公倍数です。 大きな数値にはモジュロ演算を使用し、モジュロを取得します。$10^9 + 7$。 
4. 長さ 1、2、3、およびそれ以上のサイクルの数を数えます。 スワップを最小限にするには、長さ 2 のサイクルが重要です。スワップを 1 つだけ行うと、2 つの 2 サイクルを 3 サイクルと 1 サイクルに結合できるため、LCM が増加します。 長さが 1 以上のサイクルの場合、標準のソート スワップを超えるスワップは必要ありません。 
5. スワップの最小数を次のように計算します。$n - \text{number of cycles}$次に、3 サイクルにマージできる 2 サイクルに基づいて調整して、より少ないスワップで LCM を最大化します。 この調整により、不必要なスワップを行わずに最適な置換が確実に達成されます。 
6. LCM モジュロを出力します。$10^9 + 7$各テストケースの最小スワップ。 

機能する理由: サイクルに分解すると、繰り返される操作の効果が得られます。 各サイクルは独立して回転し、LCM はすべてのサイクルの結合された周期性を取得します。 最小スワップは古典的な順列理論に従い、サイクル マージを通じて LCM を最大化するための調整が行われます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        p = [x-1 for x in p]  # zero-based indexing

        visited = [False]*n
        cycles = []

        for i in range(n):
            if not visited[i]:
                j = i
                length = 0
                while not visited[j]:
                    visited[j] = True
                    j = p[j]
                    length += 1
                cycles.append(length)

        # compute LCM
        def lcm(a, b):
            return a*b // math.gcd(a, b)

        result = 1
        for c in cycles:
            result = result * c // math.gcd(result, c)
            if result >= MOD:
                result %= MOD

        # compute minimal swaps
        swaps = n - len(cycles)
        print(result % MOD, swaps)

if __name__ == "__main__":
    solve()
```この解決策は、まず順列をサイクルに分解します。 未訪問のインデックスごとに新しいサイクルが開始され、サイクルが終了するまでトラバースします。 サイクル長の LCM を計算すると、個別の配置の最大数が得られます。 スワップ数は次のようになります。$n - \text{number of cycles}$、最初のサイクル以降のすべてのサイクルは、最適な順列に変換するときにスワップに寄与するためです。 大量の数値のオーバーフローを避けるために、必要な場合にのみモジュロを適用します。
