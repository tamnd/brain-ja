## アプローチ

 ブルート フォース ソリューションでは、まず文字列の考えられるすべての接尾辞を識別し、それが完全に次のもので構成されているかどうかを確認します。`)`文字を取得し、その長さを計算します。 文字列の長さは最大でも 100 であるため、このような非効率な方法でも制限内で快適に実行できます。 

問題の構造からは、はるかに簡単な観察が得られます。 最後の連続ブロックのみ`)`重要です。 そのブロックより前のすべての文字は「残りの文字」カウントに属します。 

多くの接尾辞を調べる代わりに、文字列の終わりから始めて、連続する接尾辞の数を数えることができます。`)`の文字が表示されます。 他のキャラクターに遭遇した瞬間、私たちは立ち止まります。 この数は、ステートメントで必要なサフィックスのサイズとまったく同じです。

```ブルートフォース手法は最終的に終了ブロックを見つけるため機能しますが、一度逆方向にスキャンすると同じ情報が直接得られます。

 ## アルゴリズムのチュートリアル

 1.長さを読み取ります`n`そして文字列`s`。 
2. 文字列の最後の文字から開始して左に移動します。 
3. 連続何回かを数えます`)`文字は最後に登場します。 このカウントを次の場所に保存します`cnt`。 
4. 異なる文字が出たらすぐに停止します`)`最後の連続ブロックのみが重要であるため、この問題が発生します。 
5. 残りの文字数を次のように計算します。`n - cnt`。 
6. もし`cnt > n - cnt`、印刷`"Yes"`。 
7. それ以外の場合は、印刷します`"No"`。 

### なぜ効果があるのか

 不正なメッセージの定義は、文字列の末尾にある連続した閉じ括弧のみに依存します。 逆方向にスキャンすることで、その量を正確に計算します。 

この終了ブロックに属さないすべての文字は、文字列の残りの部分の一部になります。 したがって`n - cnt`は、ステートメント内で言及されている残りの文字の正確な数です。 

アルゴリズムは定義から条件を直接チェックするため、その答えは常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        cnt = 0
        i = n - 1

        while i >= 0 and s[i] == ')':
            cnt += 1
            i -= 1

        if cnt > n - cnt:
            print("Yes")
        else:
            print("No")

solve()
```実装はアルゴリズムに正確に従います。 

変数`cnt`連続するサフィックスの長さを格納します。`)`文字。 ループは最後のインデックスから始まり、現在の文字が存在する間左に移動し続けます。`)`。 

別の文字が表示されると、サフィックスは終了するため、スキャンを続ける必要はありません。 残りの文字数は単純に`n - cnt`。 

最終的な比較では、`>`それよりも`>=`。 カウントが同じであってもメッセージが悪くなるわけではないため、この詳細は非常に重要です。 

文字列の長さが非常に短いため、ここでは整数のオーバーフローやメモリの問題は存在しません。
