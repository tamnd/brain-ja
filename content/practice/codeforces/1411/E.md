 ## 解決策
 ## 問題の理解

 私たちは小文字の文字列を与えられ、それを奇妙な「ポマン」数字体系の数字として解釈します。 それぞれの単一文字は 2 のべき乗に対応します。`a`は 2^0 = 1、`b`は 2^1 = 2、`c`は 2^2 = 4 など、以下まで続きます。`z`= 2^25。 長い文字列の場合、値は再帰的に定義されます。文字列を任意の位置で分割し、最初の部分と 2 番目の部分を加算した値の負の値として値を定義できます。 正式には、文字列の長さが 1 より大きい場合、インデックスを選択します。`m`(1 ≤ m < n) として値を計算します。`-f(S[1..m]) + f(S[m+1..n])`。 目標は、最終結果が指定された整数と等しくなるように、すべてのステップで分割を選択できるかどうかを判断することです。`T`。 

入力制約では、最大 10^5 文字と 10^15 までのターゲット値が許可されます。 分割方法の数は文字列の長さに応じて指数関数的に増加するため、考えられるすべての再帰的分割を試行するソリューションは除外されます。 最終的な答えを線形または線形時間で計算するソリューションが必要です。 

この操作ではプレフィックスの合計を否定できるため、明らかではないエッジ ケースが発生します。 たとえば、最初と最後の文字が 2 の大きなべき乗である文字列や、すべての文字が同じである文字列は、単純なアプローチでは誤解を招く可能性があります。 最後の文字はプラスにしか寄与しないという事実を無視すると、特定のマイナスの合計が達成可能であると誤って仮定する可能性があります。 具体的な例は次の文字列です`ba`ターゲット付き`-1`。 最初の手紙`b`= 2 と 2 番目の文字`a`= 1. 正しい分割により得られる結果`-b + a = -2 + 1 = -1`これは達成可能ですが、符号を考慮せずにすべての値を不用意に合計すると失敗します。 

## アプローチ

 強引な解決策は、考えられるすべての分割を再帰的に試し、左右のセグメントの値を計算し、組み合わせによって結果が得られるかどうかを確認することです。`T`。 このアプローチは、すべての操作シーケンスを徹底的に調査するため、正しいです。 ただし、分割の数は文字列の長さに応じて指数関数的に増加します。 ある長さの文字列の場合`n`、 がある`2^(n-1)`分割を挿入する方法が異なるため、このアプローチは n = 10^5 では実行不可能になります。 

重要な観察は、すべての演算が文字に対応する 2 の累乗の加算と減算の組み合わせに帰着するということです。 最後の 2 文字のみが特定の順序で符号に「強制」されるため、すべての文字の累乗の合計を計算し、最後の 2 文字を除くすべての文字の合計の 2 倍を減算して、再帰的アプリケーションでの固定位置を考慮することができます。 これにより、問題は単純な算術チェックに集約されます。すべての文字のべき乗を合計し、最後の 2 つを適切に減算し、その差が一致するかどうかを確認します。`T`。 内部文字をべき乗の降順にソートし、柔軟な加算/減算として扱うことで、単純な合計チェックを使用することができます。

 ## アルゴリズムのチュートリアル

 1. 文字列の各文字を、対応する 2 のべき乗に変換します。 手紙の場合`c`、計算する`2^(ord(c) - ord('a'))`。 これらを配列に格納します`vals`。 これにより、文字列が数値の寄与に変換されます。 
2. 文字列の最後の文字は、最終計算において常にプラスに寄与し、最後から 2 番目の文字は常にマイナスに寄与することに注意してください。 ターゲットを調整する`T`これら 2 つの寄与を考慮するには、次の値から最後の値を引きます。`T`、最後から 2 番目の値を追加します。 これにより、残りの文字をチェックするだけで済みます。 
3. 最後の 2 つを除くすべての値の合計を計算します。 これは、再帰的分割で自由に否定または追加できる数値の合計プールです。 この合計を次のように表します`S`。 
4. 問題は、記号を選択した後の残りの文字の合計が調整後の文字と等しくなるように、残りの文字を分割できるかどうかを確認することになります。`T`。 すべての数値は 2 の累乗であるため、任意の ± 符号を付けた数値の合計は、以下の任意の整数に達します。`-S`に`S`と同じパリティを持つ`S`。 したがって、必要十分条件とは、`S >= |T_adjusted|`そしてそれ`(S - T_adjusted)`は均等です。 
5. これらの条件が当てはまる場合は、「はい」と出力します。 それ以外の場合は、「いいえ」を出力します。 

機能する理由: 再帰的分割操作は、プレフィックスを否定し、残りのサフィックスを追加するだけです。 これは、寄与が固定されている最後の 2 文字を除くすべての文字に ± 記号を選択することと同じです。 2 のべき乗の和には、パリティが揃っていれば負の合計と正の合計の間の任意の整数が得られるという特性があるため、単純な算術チェックで考えられるすべての分割シーケンスが捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, T = map(int, input().split())
S = input().strip()

vals = [1 << (ord(c) - ord('a')) for c in S]

# Adjust target by last two letters
T_adjusted = T - vals[-1] + vals[-2]

# Sum of remaining letters
S_sum = sum(vals[:-2])

# Check if we can reach T_adjusted with ± signs
if S_sum >= abs(T_adjusted) and (S_sum - T_adjusted) % 2 == 0:
    print("Yes")
else:
    print("No")
```最初の行は、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 2 行目は文字を 2 の累乗に変換します。 目標調整は、最後の 2 文字の強制的な寄与を考慮しています。 残りの文字の合計が、自由な記号割り当て用のプールを形成します。 最終チェックでは、大きさとパリティの両方の条件が満たされていることを確認します。 どちらかが失敗すると、ターゲットに到達できないことを意味します。

 ## 特殊なケース

 可能な最小の文字列の場合、`n = 2`、入力`ba`そしてターゲット`-1`、アルゴリズムは次のように計算します。`vals = [2,1]`、ターゲットを次のように調整します`0`、残りの文字の合計は`2`、チェックパスし、Yes と出力されます。 すべての文字が同じ文字列の場合、例:`aaaa`そしてターゲット`0`、内部文字の合計は 2、調整されたターゲットは 0、チェックはパスし、Yes と出力されます。 すべてのレター貢献の合計を超えるターゲットの場合、予想どおりチェックは失敗します。 このアルゴリズムは、最後の 2 文字の固定寄与を一貫して考慮し、残りには ± 符号の柔軟性を使用して、すべてのエッジ ケースを正しく処理します。
