 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$。 許可される操作では 3 つのインデックスが選択されます$i < j < k$の値が$i$の最大値よりちょうど 1 多いです$p_j$そして$p_k$そして最小値より正確に 2 つ多い$p_j$そして$p_k$。 操作の実行が減少します$p_i$2ずつ増加します$p_j$そして$p_k$それぞれ1つずつ。 タスクは、この操作を何度でも実行して、辞書編集的に達成可能な最小の順列を見つけることです。 

最初の重要な観察は、この操作により、非常に制御されたパターンで、より大きな要素からより小さな要素に「重み」が効果的に移動されるということです。 この操作は何度でも実行できるため、辞書編集的に並べ替えを最小限に抑えるために、大きい数値をできるだけ右に、小さい数値を左に移動するように努める必要があります。 

制約は次のことを教えてくれます$n \le 2000$と合計$n^2$すべてのテスト ケースで最大でも$2000^2$。 これは次のことを示唆しています$O(n^2)$テストケースごとのソリューションは許容されます。 有効な演算の数は順列サイズによって制限されるため、すべてのトリプレットを繰り返しチェックする単純なアプローチでも機能します。 

条件が制限されすぎて操作ができない場合、微妙なエッジ ケースが発生します。 たとえば、順列がすでに昇順にソートされている場合、トリプレットは存在しません。$i, j, k$制約を満たしていること。 アルゴリズムはこれを検出し、置換を変更せずに返す必要があります。 

もう 1 つの特殊なケースは、最大数が早期に出現する場合に発生します。 操作を順番に実行して慎重に右に向かって伝播させる必要があります。そうしないと、単純な左から右へのアプローチにより、多数の数値が時期尚早に所定の位置に「ロック」されてしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのトリプルに対して繰り返し反復処理を行うことです。$(i, j, k)$条件が満たされるたびに操作を実行します。 これは正しいです。すべての操作で順列プロパティが保持され、適用できる操作がなくなるとプロセスが収束します。 ただし、最悪の場合の複雑さは次のとおりです。$O(n^3)$テストケースごとに、次のようになります$8 \times 10^9$のための操作$n = 2000$、遅すぎます。 

重要な洞察は、この操作では値がローカルに移動されるだけであるということです。つまり、1 つの要素が減少し、2 つの小さな要素が増加します。 辞書編集的に順列を最小限に抑えるには、余剰部分を後の要素に移動できる操作を左端の要素に適用することが常に有益です。 左から右にスキャンして、見つけたときはいつでも、$p_i$インデックスより少なくとも 2 大きい場合は、貪欲にそれを進めます。 これにより、問題は次のようになります。$O(n^2)$解決策: インデックスごとに、後続のインデックスをスキャンして、それ以上の移動が不可能になるまで有効な操作で超過分を分散します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 貪欲な左から右へ | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左から右へ順列を繰り返します。 各インデックスで$i$、どうかを確認してください$p_i$より大きい$i+1$。 これは、演算を使用して右方向に移動できる超過を表します。 
2. それぞれについて$i$過剰な場合は、後続のインデックスを反復します$j$そして$k$($i < j < k$) かどうかを確認します$p_i = \max(p_j, p_k) + 1$そして$p_i = \min(p_j, p_k) + 2$。 有効なトリプレットが見つかったら、次の操作を実行します。$p_i$2ずつ増加します$p_j$そして$p_k$1までに。 
3. 現在の内部ループを継続します。$i$それまで$p_i$有効な条件を満たさなくなりました$j$そして$k$。 次に、次のインデックスに移動します。 
4. 配列内のすべてのインデックスに対してこの手順を繰り返します。 常に左端の可能なものを処理することで、$p_i$まず、小さい数値が前に移動され、大きい数値が後ろに押し出されるようにして、辞書編集的に最小限の並べ替えを実現します。 

機能する理由: この操作では、値の複数セットが保存されます (ステップごとに 1 つの要素が 2 ずつ減少し、2 つずつ 1 ずつ増加するため)。 可能な限り大きな要素を貪欲に前方に移動しても、残りの大きな要素が残りのペアで演算条件を満たすことができないため、並べ替えをさらに改善することはできません。 左から右への順序付けにより、辞書編集上の最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        for i in range(n - 2):
            while p[i] > 1:
                j = i + 1
                k = i + 2
                # Check if the operation is possible
                if p[i] == max(p[j], p[k]) + 1 and p[i] == min(p[j], p[k]) + 2:
                    p[i] -= 2
                    p[j] += 1
                    p[k] += 1
                else:
                    break
        
        print(' '.join(map(str, p)))

if __name__ == "__main__":
    solve()
```このソリューションはすべてのテスト ケースを読み取り、各順列を個別に処理します。 までだけ繰り返します$n-2$なぜなら、この操作には 3 つの要素が必要だからです。 の`while`ループにより、可能であれば単一のインデックスで複数の操作が実行されるようになります。 両方の動作条件を慎重に確認してから適用します。 印刷は各テスト ケースの最後に行われます。
