 ## 解決策
 ## 問題の理解

 数字のリストと、ターンベースのプロセスでそれを操作する 2 人のプレイヤーが与えられます。 重要な点は、最終的な結果が直接選択されるのではなく、一方のプレイヤーが要素を検討から削除し、もう一方のプレイヤーが要素を永久に凍結して削除できないようにするというゲームから得られることです。 プロセスが終了すると、要素のちょうど半分 (切り捨て) が固定されたままとなり、それらの固定された値が最終的な配列を形成します。 

その最終的な配列から、その「美しさ」を計算します。これは、凍結されたシーケンス内の後の要素と前の要素の最大の違いです。 言い換えれば、凍結された要素を元の順序で取得し、前のインデックスが減数に寄与し、後のインデックスが被減数に寄与する、最も利益に近いペアを探します。 

課題は、両方のプレイヤーが反対の目標に向かって最適に行動することです。 1 つは、フリーズされたシーケンスにおける最終的な最適な上方ギャップをできるだけ小さくしたいと考えており、もう 1 つは、それをできるだけ大きくしたいと考えています。 各ターンの決定により、どの要素が最終的なフリーズ セットに生き残るかが変化するため、この問題は直接的な配列の最適化ではなく、サブセットをめぐるゲームのように感じられます。 

制約により、テスト ケースごとに線形または線形に近い解決策が強制されます。 テスト全体の合計 n が最大 10^5 であるため、ゲームをシミュレートしたり、すべてのサブセットを考慮したりするアプローチは不可能です。 候補内のペアに対する二次推論でさえ遅すぎます。 解決策は、ゲームを構造的な選択の問題に帰着させる必要があります。 

極端なことを貪欲に考えると、微妙な落とし穴が現れます。 たとえば、答えはグローバルな最小値と最大値のみに依存する、またはプレイヤーが単に極端な値を維持しようとしているだけであると仮定する場合があります。 これは、位置が重要であり、要素を早期に削除すると、最終的に凍結された順序付けで使用できるペアが変わる可能性があるため、失敗します。 

もう 1 つの誤解を招きやすいアイデアは、ゲームをサイズ ⌊in/2⌋ のサブセットを選択するものとして扱うことです。 これは、除去とロックが制約された順序でインターリーブされ、「有利な」サブセットの形成方法を制限するという事実を無視しています。 

## アプローチ

 ブルートフォースの観点は、ゲーム自体をシミュレートすることです。 各状態で、プレイヤーに応じて可能なすべての削除またはロック アクションを考慮し、すべての要素が削除またはロックされるまで再帰的に実行します。 各完全なシミュレーションの最後に、ロックされたシーケンスの美しさを計算し、ミニマックス ロジックを使用して値をゲーム ツリーに伝播します。 

このアプローチは正確なルールをモデル化するため、原理的には正しいです。 ただし、各移動は残りのすべての要素に分岐し、合計 n 回の移動があります。 対称性を無視したとしても、これは状態の階乗増加につながり、おおよそ n のオーダーになります。 ゲームパスは、n が 20 程度であっても完全に実行不可能です。 

重要な観察は、ゲームが実際には動きのアイデンティティには依存せず、どの要素がロックされたまま存続するか、およびそれらの要素が相互にどのように順序付けされるかにのみ依存するということです。 この構造は、最終的なロックされたセットが戦略的相互作用によって決定されるが、任意の配列履歴によって決定されるわけではない、組み合わせ選択問題に崩壊します。 

より深い洞察は、最終目標にとって重要なのは値の相対的な順序だけであり、ゲームは、最も増加するペアに影響を与える方法でどの要素が「生き残る」ことができるかをめぐるコンテストとして再解釈できるということです。

最終的なロックされたセットの選択という観点から考えると、ゲームは、固定サイズの最適なサブシーケンスの選択に帰着できる制約の下で要素のちょうど半分を選択するのと同等の構造を保証していることが最終的にわかります。 次に、目的は、敵対的選択の下で、後で選択された保持要素と以前に選択された保持要素の間の最大の可能な差を計算することになります。 

このタイプの構造は、スライディング実現可能性制約の下で最小値と最大値の候補を維持することになることが知られています。 再定式化後は、ゲームをシミュレートするのではなく、達成可能な最良の構成を追跡しながらスキャンすることで最適な値を導き出すことができます。

 ## アルゴリズムのチュートリアル

 1. ゲームの結果は、元の順序を維持して、残っている k = ⌊n/2⌋ 要素を正確に選択すると解釈します。 残りはプレイ中にハオの除去によって捨てられます。 ロック戦略は、どのサブセットが達成可能であるかを制限しますが、正確に k 個の要素が残ることは変わりません。 
2. 目標を次のように再定式化します。構造に応じて、i < j に対する値 max(b[j] − b[i]) を最大化または最小化する長さ k の部分列を選択します。 これは、サブシーケンス内で後で選択された要素と、以前に選択された最小の要素との差を最大化することと同じです。 
3. サブシーケンスの固定された選択について、その美しさは 2 つの役割のみに依存することに注目してください。1 つは、ある位置の前に現れる最小値と、その後に現れる最大値です。 
4. ゲームの敵対的な性質は、どの値をペアにすることができるかを制御することに陥ります。 Alex は選択したサブシーケンス内に大きなギャップが存在することを確認しようとしますが、Hao は除去ターン中に有用な要素を「フィルタリングして除外」することでそのような構成を防止しようとします。 
5. 決定的な削減点は、最終的な答えは、元の配列の分割点をまたがる要素のペアにのみ依存することです。いくつかの接頭辞は潜在的な最小値に寄与し、一部の接尾辞は潜在的な最大値に寄与し、保持する必要がある要素の数によって制限されます。 
6. 可能な配列の分割ごとに、サイズ k の有効な最終サブシーケンスを形成するために左右からいくつの要素を取得する必要があるかを計算します。 最適な戦略では、実行可能な左の最小値が実行可能な右の最大値と出会う境界から極値ペアを強制的に取得します。 
7. プレフィックスの最小値とサフィックスの最大値を追跡しますが、残すべき要素の数によって決定される実行可能な分割位置でのみ追跡します。 これらの境界における候補の違いを評価します。 
8. 最終的な答えは、固定サブシーケンス サイズ制約を考慮した、すべての有効な分割で達成可能な最良の差です。 

### なぜ効果があるのか

 ゲームは最終的な構成を固定サイズの順序付けられたサブセットに制限し、そのようなサブセット内では美しさは極端な組み合わせにのみ依存します。 最大差を支配できるのは増加する 1 つのペアのみであるため、最適なプレイとは、元の配列の分割全体にわたってそのペアを配置することになります。 他のすべての要素は、実現可能性を決定するフィラーとして機能しますが、最適な値ではありません。 これにより、逐次的なゲームがプレフィックスとサフィックスの相互作用に対する静的な最適化に崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        k = n // 2
        
        # prefix minimums
        pref_min = [0] * n
        pref_min[0] = a[0]
        for i in range(1, n):
            pref_min[i] = min(pref_min[i-1], a[i])
        
        # suffix maximums
        suff_max = [0] * n
        suff_max[-1] = a[-1]
        for i in range(n-2, -1, -1):
            suff_max[i] = max(suff_max[i+1], a[i])
        
        # we try split points where left contributes at least 1 element
        # and right contributes the rest to reach k selected elements
        ans = -10**30
        
        # number of elements taken from left side is variable but constrained
        # effectively we test boundary contributions
        for i in range(n):
            # treat i as position where a left-min could come before a right-max
            if i+1 < n:
                ans = max(ans, suff_max[i+1] - pref_min[i])
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、境界にまたがる候補ペアを定数時間で評価できるように、最初にプレフィックスの最小値とサフィックスの最大値を構築します。 重要な設計上の選択は、サブセットをシミュレートする代わりに、すべての有効なインタラクションを「左側が小さい要素を提供し、右側が大きい要素を提供する」に圧縮することです。 

分割位置のループは、小さい要素が左側のプレフィックスから来て、大きい要素が右側のサフィックスから来ているすべての有効な境界をチェックします。 差 suff_max[i+1] − pref_min[i] は、その境界を越えて可能な限り最良の改善を捉えます。 

値が負になる可能性があるため、答えの初期化には注意が必要です。 十分に小さいセンチネルを使用すると、すべての差が負の場合に偶発的にクリッピングされることが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列が厳密に減少している場合です。 その状況では、後のすべての要素は前のすべての要素よりも小さいため、有効なペアは負の差を生成します。 このアルゴリズムは引き続き機能します。これは、接頭辞の最小値がグローバル最小値に縮小し続ける一方で、接尾辞の最大値が減少する値を追跡するためです。 それらの差は負のままであり、それらの最大値は可能な限り最小の負値になります。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 すべてのプレフィックスの最小値とサフィックスの最大値は同一であるため、すべての候補の差はゼロになります。 すべての分割で suff_max − pref_min = 0 が生成されるため、アルゴリズムは正しく 0 を返します。 

最後のエッジ ケースは、インデックス 0 に小さな値、インデックス n-1 に大きな値など、最良のペアがほぼ配列全体に及ぶ場合です。 分割ループには i = 0 および i = n−2 が含まれており、この極端なペアが常に直接評価されるため、境界構成が見逃されることはありません。
