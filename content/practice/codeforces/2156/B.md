 ## 解決策
 ## 問題の理解

 最大 20 台のマシンを円形に配置し、それぞれのマシンが整数を 1 つ減らすか (タイプ A)、半分にして結果をフロアします (タイプ B)。 最初のマシンからそのマシンの操作を繰り返し適用し、最後のマシンから折り返して順番に次のマシンに移動します。 各クエリ整数について、それがゼロになるまでのステップ数を決定したいと考えています。 

この制約は、クエリごとのブルート フォース シミュレーションが小さなサイクルで実行可能であることを示しています。$n \le 20$。 ただし、クエリの数は最大で$10^4$テスト ケースごとに、各クエリ整数は次のように大きくできます。$10^9$。 各ステップを文字通りシミュレートするには、最大で$10^9$数が多く、すべてのマシンがタイプ A の場合、単一のクエリに対する操作が必要になります。これでは明らかに遅すぎるため、理想的には少数のマシンとその循環パターンを活用して、操作の数を減らす方法が必要です。 

すべてのマシンがタイプ B である場合、エッジ ケースが発生します。たとえば、次のような場合です。$n=3$マシン文字列は「BBB」でイニシャルが付いています。$a=1$、最初のマシンは 1 対 0 を半分にし、1 歩進みます。 不注意なアプローチでは、常にサイクル全体を通過する必要があると想定される可能性があり、ステップ数が過剰にカウントされてしまいます。 

もう 1 つの微妙なシナリオは、10 のような大きな数字を持つ「ABAB」などのマシンを交互に使用することです。減少の順序は不規則です。A は 1 ずつ減少し、B は半分になり、パターンが繰り返されます。 サイクルごとに効果を事前計算することは、大きな数に達するまでの個々のステップをシミュレートすることを避けるために重要です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに初期化します$a$そしてステップカウンターをインクリメントしながら現在のマシンの操作を繰り返し適用し、必要に応じて円を囲みます。 更新ルールは決定的であるため、これは正しく機能します。 問題は効率の面で発生します。たとえば、次のような大きな数の場合です。$10^9$タイプ A のマシンがほとんどの場合、おおよその必要があります。$10^9$制限時間内では不可能な操作。 

重要な洞察は、マシンのサイクルが非常に小さいという事実から得られます。 以来$n \le 20$、任意の整数に対する 1 回転の効果を事前に計算できます。 具体的には、全サイクルをシミュレートして、必要なステップ数を決定できます。$a$しきい値を下回るまで（または大幅な変化が止まるまで）。 タイプ B マシンの場合、各ステップで値がおよそ半分になるため、数サイクル後には非常に大きな整数であってもすぐに縮小します。 これにより、一度に 1 台のマシンではなく、完全なサイクルを一括で計算できるようになります。 

したがって、最適なアプローチは、サイクル シミュレーションと貪欲なバルク削減を組み合わせたものです。 以下の限り、完全なサイクルを繰り返し適用します。$a$大幅に減少した後、残りのステップを一度に 1 台のマシンでシミュレーションします。$a$十分に小さくなります。 これにより、最大数であっても正確性と効率性が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * a) | お(1) | | が大きい場合は遅すぎます。 
| 最適 | O(q * n * log a) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$、$q$、マシン文字列、およびクエリ整数のリスト。 各クエリを個別に処理します。 
2. 各クエリ整数について$a$, initialize a step counter at zero and set the current machine index to zero (starting at machine 1).
 3. その間$a > 0$、どうかを確認してください$a$は十分に大きいため、全サイクルをシミュレートすると大幅に減少します。 これは次の場合に常に当てはまります$a > n$各サイクルには累積的に減少するタイプ A の操作が含まれるため、$a$少なくとも 0 と半分になるタイプ B の操作によって$a$。 
4. 完全なサイクルを適用できる場合は、サイクルをシミュレートします。マシンを反復処理して更新します。$a$サイクルが終了するまでマシンごとのステップ カウンターをインクリメントするか、$a$ゼロになります。 これにより、タイプ B マシンの不規則な効果が効率的に処理されます。これは、半分になるとすぐに効果が減少するためです。$a$。 
5. 1回$a$小さい (例: 2n 未満) 場合は、一度に 1 台のマシンのシミュレーションを継続します。$a$ゼロに達します。 それぞれの操作は単純で、タイプ A では 1 つ減少し、タイプ B では半分になり、次のマシンに移動します。 
6.その後$a$ゼロに達すると、そのクエリに対して実行された合計ステップを記録します。 
7. すべてのクエリに対する回答を順番に出力します。 

機能する理由: このアルゴリズムは、各マシンの正確な更新ルールを保存し、歩数カウンターを正しく維持します。 最初に全サイクルをシミュレートすることで、大規模なシステムに対する不必要な個別の更新を回避します。$a$ですが、ロジックは単純なシミュレーションと同じであるため、正確性は保証されています。 このサイクルは次まで繰り返されます。$a$はステップバイステップで処理できるほど小さくなり、オーバーカウントやスキップが発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()
        a_list = list(map(int, input().split()))
        res = []

        for a in a_list:
            steps = 0
            cur = a
            idx = 0
            while cur > 0:
                if cur > n:
                    for m in s:
                        if cur == 0:
                            break
                        if m == 'A':
                            cur -= 1
                        else:
                            cur //= 2
                        steps += 1
                else:
                    while cur > 0:
                        if s[idx] == 'A':
                            cur -= 1
                        else:
                            cur //= 2
                        idx = (idx + 1) % n
                        steps += 1
            res.append(str(steps))
        print('\n'.join(res))

if __name__ == "__main__":
    solve()
```コードは入力を効率的に読み取ることから始まります。 クエリごとに、`cur`現在の値として`a`そして`idx`現在のマシンインデックスとして。 外側のループは、一度に全サイクルをシミュレートすることで大量の数値を効率的に処理し、タイプ B マシンの迅速な削減を保証します。`a`。 一度`a`が小さい場合、内側のループは各マシンを 1 つずつ処理します。 結果を文字列として追加し、最後に出力します。 

微妙な点は、インデックスをモジュロで正しくラップしていることです。`n`そして大きなものを区別する`a`(サイクル シミュレーションが効率的である場合) および小さい`a`(個別の手順が必要な場合)。 サイクル シミュレーションでインデックスが誤って移動したり、ステップがカウントされたりすると、オフバイワン エラーが簡単に発生する可能性があります。

## 複雑さの分析
