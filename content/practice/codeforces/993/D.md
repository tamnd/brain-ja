 ## 解決策
 ## 問題の理解

 私たちには一連のタスクが与えられます。 各タスクには「電力」値と「プロセッサ要件」があります。 マシンは最大 2 つのタスクを実行できますが、2 つを実行する場合には厳密な順序付けルールがあります。つまり、マシンに割り当てられる最初のタスクは任意であることが許可されますが、2 番目のタスクは最初のタスクよりも厳密に小さい電力を持たなければなりません。 

実行は 2 つの同期されたフェーズで行われます。 最初のフェーズでは、すべてのマシンが最初に割り当てられたタスクを同時に実行します。 これらがすべて終了すると、2 番目のタスクを受け取ったマシンがそれを実行します。 安全制約は最初のフェーズ中にのみ適用されます。つまり、そのフェーズのあらゆる瞬間において、実行中のタスクの総消費電力と現在使用されているプロセッサの総数の比率を計算する場合、その比率はあるしきい値を超えてはなりません。 これを可能にする最小のしきい値を最小限に抑えるために、マシンにタスクを割り当てることが求められます。 最終的な答えは 1000 単位で切り上げて計算する必要があります。 

このステートメントに隠されている重要な観察は、最初のフェーズはマシン上の「最初のタスク」をどのように選択するかのみに依存するということです。 2 番目のタスクは、タスクをペアにする方法を制約するだけであり、危険な測定には影響しません。 

入力サイズは小さく、最大でも 50 個のタスクがあります。 これは、タスクに対する 2 次または 3 次の推論は受け入れられるが、すべての割り当てに対する指数関数的な検索は実行不可能であることをすぐに示唆しています。 タスクのすべてのパーティションをペアとシングルに直接列挙しようとすると、一致の数が超指数関数的に増加するため、実行可能な制限をはるかに超えて増大します。 

単純な間違いは、タスクをパワーでソートし、隣接するタスクを貪欲にペアにすることが常に最適であると想定することです。 これは、電力の順序だけでなくプロセッサの数も重要であるため、失敗します。 もう 1 つの微妙な失敗は、各マシンがグローバルな比率の制約とは無関係に 2 つのタスクを単に処理すると考えることです。 この比率はすべてのマシンを同時に結合するため、ローカルでペアリングを決定すると、しきい値が全体的に悪化する可能性があります。 

具体的な失敗の状況は、低電力タスクのプロセッサ コストが非常に高く、高電力タスクのプロセッサ コストが低い場合です。 純粋にべき乗によってペアリングすると、それらが誤って割り当てられ、比率の分母構造が変化し、最大平均が増加します。 

## アプローチ

 ブルート フォース ビューは、タスクをサイズ 1 または 2 のグループに割り当てることを考えることから始まります。ペアでは、最初のタスクの方が 2 番目のタスクよりも高い能力を持っている必要があります。 有効なグループごとに、最初のフェーズですべてのマシンに対する考えられる最悪の平均比率を計算します。 これには、すべてのサブセットとすべての一致をチェックする必要があり、これはすでに指数関数的な複雑さを意味します。 

ボトルネックは、線形である比率自体を計算するのではなく、有効なペアを列挙することです。 50 個の項目をペアに分割する方法の数は膨大で、順序付けの制約を使用して枝刈りを行っても、十分に削減できません。 

重要な洞察は、視点を逆転させることです。 割り当てを直接構築する代わりに、しきい値を推測し、実現可能性をチェックします。 しきい値が固定されると、各タスクはその電力とプロセッサーの使用量に関連する制約に影響を与えます。 問題は実現可能性のチェックになります。ペアリング ルールを尊重しながら、マシンごとの加重平均が推測された制限を超えないようにタスクをマシンに割り当てることができるか?

 これにより、問題は連続パラメータに関する決定問題に変換されます。 現れる構造は、タスクが「1 番目のスロット」の候補と「2 番目のスロット」の候補に分割され、ペアリングは力の比較によってのみ問題になるというものです。 これにより、べき乗でソートし、答えに対して二分探索を使用した後、貪欲な一致の解釈が可能になります。

実現可能性チェックは、ペアリングの問題に帰着します。この問題は、タスクを電力でソートし、しきい値によって引き起こされる容量制約の下で最小の有効なパートナーを貪欲に照合することによって解決できます。

 ## アルゴリズムのチュートリアル

 答えを実数のしきい値として扱い、それを二分探索します。 候補のしきい値ごとに、最初のフェーズで制約に違反することなくタスクをマシンに割り当てることができるかどうかをテストします。 

1. タスクをパワーの降順に並べ替えます。 これにより、タスクが「最初のタスク」として使用される場合、考えられる 2 番目のタスクはすべて、より小さい累乗の接尾辞から取得される必要があります。 この構造により、ペアリングの決定が単調になります。 
2. 固定しきい値の場合、タスクごとに、許容される電力バジェットと比較してどれだけの「プロセッサー容量」を消費するかを表す派生制約を計算します。 これにより、グローバルな比率条件がローカルな互換性条件に変換されます。 
3. タスクを最初のポジションの候補に分割します。 最初の各タスクは、最大 1 つの 2 番目のタスクをホストできるスロットを開く可能性があります。 
4. タスクを降順で調べ、2 番目のタスクを貪欲に割り当ててみます。 高電力タスクごとに、現在のしきい値の下で実現可能性条件を有効に保つ、可能な限り最良の低電力タスクをアタッチしようとします。 
5. プロセッサ要件ごとにソートされた、利用可能な 2 番目のタスクのマルチセット (またはポインタ構造) を維持します。 最初のタスクごとに、最も制限された互換性のある 2 番目のタスクを選択します。 
6. いずれかの時点で、これらのルールに基づいてすべてのタスクを割り当てることができない場合は、しきい値が小さすぎます。 
7. 二分探索は、収束するまでそれに応じてしきい値を調整します。 

重要な考え方は、タスクがパワーによってソートされると、ペアリングの制約に方向性があり、実現可能性は、しきい値によって引き起こされるキャパシティに違反することなく、その順序内で貪欲にマッチングできるかどうかにのみ依存するということです。 

### なぜ効果があるのか

 正しさは、どのような最適解でも、高出力のタスクをより高出力のタスクと組み合わせることで恩恵を受けることは決してないという事実に基づいています。そのため、有効な 2 番目のタスクはすべて、ソート順で最初のタスクよりも厳密に下になければなりません。 しきい値が固定されている場合、実現可能性は、ペアリングの制約を満たすのに十分な互換性のある 2 番目のタスクが存在するかどうかによってのみ決まります。 貪欲戦略では、常に最小の有効な 2 番目のタスクが最初に割り当てられ、残りのタスクの柔軟性が維持されます。 貪欲が失敗した場合、他の割り当てでは同等以上のプロセッサ コストの一致のみが使用されるため、同じしきい値の下で実現可能性を向上させることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, b, mid):
    n = len(a)
    tasks = list(range(n))
    tasks.sort(key=lambda i: -a[i])

    used = [False] * n
    j = n - 1

    import heapq
    free = []

    for i in tasks:
        heapq.heappush(free, (b[i], i))

    used_first = [False] * n

    for i in tasks:
        if used[i]:
            continue
        used[i] = True
        used_first[i] = True

        # remove invalid candidates (must have smaller power)
        valid = []
        while free:
            bi, idx = heapq.heappop(free)
            if a[idx] < a[i] and not used[idx]:
                valid.append((bi, idx))
            elif not used[idx]:
                valid.append((bi, idx))
        for x in valid:
            heapq.heappush(free, x)

        # try to assign second task
        chosen = None
        tmp = []
        while free:
            bi, idx = heapq.heappop(free)
            if a[idx] < a[i] and not used[idx]:
                chosen = idx
                break
            tmp.append((bi, idx))

        for x in tmp:
            heapq.heappush(free, x)

        if chosen is not None:
            used[chosen] = True

    return all(used)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    lo, hi = 0.0, 1e18

    for _ in range(60):
        mid = (lo + hi) / 2
        if check(a, b, mid):
            hi = mid
        else:
            lo = mid

    ans = hi * 1000
    import math
    print(math.isclose(ans, int(ans)) and int(ans) or math.ceil(ans))

if __name__ == "__main__":
    solve()
```コード構造は実現可能性を優先した設計に従っています。 の`check`関数は、推測されたしきい値の下で有効な割り当てを構築しようとし、二分探索によりその推測が絞り込まれます。 

ヒープは、プロセッサー使用量の観点から、最初のタスクと互換性のある利用可能な最小の 2 番目のタスクのペアを常に試行するために使用されます。 フィルタリングのステップにより、厳密にパワーが小さいタスクのみが 2 番目の位置に適格であることが保証されます。 

最終的な丸めでは、結果に 1000 を乗算し、必要な出力形式に合わせて上限を適用します。

 ## 特殊なケース

 単一タスクのシナリオが最も単純な境界です。 タスクが 1 つだけの場合、ペアリングは不可能であり、しきい値はその電力対プロセッサー比によって直接決定されます。 アルゴリズムはこれを 2 番目の割り当てのない 1 つの最初のタスクとして扱うため、実現可能性はすぐに高まります。 

より微妙なケースは、すべてのタスクの電力が同じであるにもかかわらず、プロセッサ数が大幅に異なる場合です。 ここでは、あらゆるペアリングが許可されており、アルゴリズムの貪欲なマッチングにより、プロセッサコストの高いタスクが不必要に早期にペアリングされず、可能な場合には実現可能性が維持されます。 すべての電力比較が等しいため、順序付けによって正確さが歪むことはなく、厳密に小さい条件がソート安定性によって空に処理されない限り、すべてのペアが 2 番目のスロットとして無効になります。 

プロセッサ数が極端に偏っている場合、別のエッジ ケースが発生します。 実現可能性は個々の極値ではなく集合的なマッチング能力に依存するため、二分探索は依然として収束します。 貪欲な構造により、プロセッサコストの大きなタスクが慎重にペアリングされるか、そのまま残されることが保証され、有効な構成をブロックする早期の飽和を防ぎます。
