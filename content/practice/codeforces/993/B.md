 ## 解決策
 ## 問題の理解

 2 人がそれぞれ、1 から 9 までの異なる数字の秘密のペアを受け取ります。2 つの隠されたペアは、単一のプロパティによってリンクされています。つまり、それらは 1 つの共通の数字を共有しています。 非表示のペアが直接与えられるわけではありません。 

代わりに、各人は、その中のどこかに自分の真のペアを含む候補ペアの小さなリストを送信します。 リストされたすべてのペアは、依然として 1 から 9 までの 2 つの異なる数字にすぎません。ユーザーの観点からは、両方のリストは既知ですが、各リストのどのペアが実際のペアであるかはわかりません。 

タスクは、最初のリストから 1 つのペアを選択し、2 番目のリストから 1 つのペアを選択して、選択したペアがちょうど 1 つの数字で重なるように、考えられるすべての方法を推論することです。 すべての一貫した選択において、共有番号が一意に決定されるのか、それとも各参加者がローカルで推測できるとしても一意に知られていないのかを判断する必要があります。 

重要な制約は、各リストが小さく、最大でも 12 ペアであり、数値がセット {1, …, 9} に制限されることです。 これにより、両側からすべての候補の隠れたペアを試すことが可能になります。 すべてのペアの単純な組み合わせ爆発は最大 144 ケースであり、各ケースでは一定数のペアのみを検査するため、単純なシミュレーションでも十分です。 

複数の非表示の割り当てが指定されたリストと一致しているが、異なる共有番号につながる場合、微妙なエッジ ケースが発生します。 このような状況では、答えが 1 桁になることはありません。 もう 1 つの注意が必要なケースは、共有番号がユーザーの観点からはグローバルに一意ではないにもかかわらず、すべての有効な割り当てにおいて、両方の参加者が曖昧さなくその番号を推測できる場合です。 これにより、特別な出力 0 が得られます。 

不注意なアプローチは、両方のリストに共通するペアが答えを示していると仮定したり、どのペアが実際に有効な隠れたペアであるかを考慮せずにリストの交差部分のみをチェックしたりすることにより、失敗することがよくあります。 実際の制約は、セットの重複だけではなく、非表示のペア選択の一貫性によって決まります。 

## アプローチ

 強引なアイデアは、最初のリストのすべてのペアを最初の参加者の隠れたペアの候補として扱い、2 番目のリストのすべてのペアを 2 番目の参加者の候補として扱うことです。 組み合わせごとに、2 つの隠れたペアが正確に 1 つの数値で交差しなければならないというルールと一致しているかどうかを確認します。 一貫性がある場合は、その共有数を計算します。 

これはすでにソリューション空間の完全な説明を提供しています。 各陣営に最大 12 の選択肢があるため、最大 144 個の候補世界が存在します。 サイズ 2 の 2 つのペアを比較するのは簡単なので、各チェックは一定時間です。 

重要な洞察は、特定の隠れたペアの割り当てが修正されると、問題は決定論的になるということです。つまり、両方の参加者が、相手側のリストから矛盾するペアを削除することによって共有番号を推測できる場合とできない場合があります。 これにより、問題は、有効な各ワールドの評価と、すべてのワールドにわたる論理プロパティの集約に変換されます。 

リストから直接答えを導き出そうとする代わりに、一貫した隠れた構成をすべて列挙し、その結果生じる動作を分類します。つまり、共有数が不変かどうか、両方の参加者によって常に局所的に推定可能かどうか、またはどこかに不確実性が残っているかどうかです。

 ## アルゴリズムのチュートリアル

1. 最初のリスト内のすべてのペアを最初の参加者の可能な非表示ペアとして列挙し、2 番目のリスト内のすべてのペアを 2 番目の参加者の可能な非表示ペアとして列挙します。 各ペアは、実際の割り当ての候補として扱われます。 
2. 各候補割り当てについて、選択した 2 つのペアが正確に 1 つの数値を共有しているかどうかを確認します。 そうでない場合は、この割り当てを破棄します。 これは、問題の唯一の構造的制約を強制します。 
3. すべての有効な割り当てについて、両方のペアに存在する一意の要素である共有数 x を計算します。 
4. 最初の参加者は、自分の視点から x を推測できるかどうかを判断します。 これは、最初の参加者が選択したペアと正確に 1 つの数値で交差する、2 番目の参加者のリスト内のすべてのペアをスキャンすることによって行われます。 このような各ペアは、共有される可能性のある数を示唆します。 このようなすべての候補が同じ x を生成した場合、最初の参加者がそれを一意に決定します。 それ以外の場合はできません。 
5. 選択したペアと最初の参加者のリストを使用して、2 番目の参加者に対して対称チェックを実行します。 
6. すべての有効な課題にわたって 3 つの情報を収集します。共有数 x、およびその課題で両方の参加者がそれを推測できるかどうかです。 
7. すべての有効な代入が同じ x を生成する場合、その数値を出力します。 
8. それ以外の場合、すべての有効な割り当てで両方の参加者が共有番号を一意に推定できる場合は、0 を出力します。 
9. それ以外の場合は、-1 を出力します。 

### なぜ効果があるのか

 すべての有効な実行パスは、入力制約と一致する 1 つの可能な現実に正確に対応します。 有効な非表示ペアが提供されたリストに表示される必要があり、すべてのペアの組み合わせがテストされるため、列挙はそのような現実をすべてカバーします。 

各固定現実について、各参加者の推論条件はローカルであり、選択したペアを相手側のリストと比較することによって完全に決定されます。 これはその参加者が入手可能な情報と一致するため、チェックは参加者の推論力を正確にモデル化します。 

最終的な答えは、共有数がすべての有効な現実にわたって不変であるかどうか、または不確実性が持続するかどうかによってのみ決まるため、すべての有効な割り当てを集計することで正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def intersect_one(a, b):
    # returns (True, common_value) if intersection size is exactly 1
    common = 0
    val = -1
    for x in a:
        if x in b:
            common += 1
            val = x
    return common == 1, val

def deducible(my_pair, other_list):
    vals = set()
    for p in other_list:
        ok, v = intersect_one(my_pair, p)
        if ok:
            vals.add(v)
    return len(vals) == 1

n, m = map(int, input().split())

A = []
B = []

for _ in range(n):
    x, y = map(int, input().split())
    A.append((x, y))

for _ in range(m):
    x, y = map(int, input().split())
    B.append((x, y))

valid = []

for a in A:
    for b in B:
        ok, x = intersect_one(a, b)
        if ok:
            valid.append((a, b, x))

all_x = set()
all_both_know = True

for a, b, x in valid:
    all_x.add(x)

    k1 = deducible(a, B)
    k2 = deducible(b, A)

    if not (k1 and k2):
        all_both_know = False

if len(all_x) == 1:
    print(next(iter(all_x)))
elif all_both_know:
    print(0)
else:
    print(-1)
```実装は列挙ロジックに直接続きます。 各ペアはタプルとして保存され、すべての交差組み合わせをテストします。 の`intersect_one`ヘルパーはキー制約 (共有数字 1 つだけ) を分離します。 の`deducible`関数は、相手側からのすべての一貫した選択肢が単一の共有値に崩壊するかどうかをチェックすることによって、参加者が推測できる内容をモデル化します。 

最終的な集計は分類ロジックを反映しています。共有番号の一意性がすべてを支配します。 それ以外の場合は、すべてのシナリオが両方の参加者によってローカルに解決可能かどうかを確認します。 otherwise ambiguity remains.

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys as _sys

    input = _sys.stdin.readline

    def solve():
        def intersect_one(a, b):
            common = 0
            val = -1
            for x in a:
                if x in b:
                    common += 1
                    val = x
            return common == 1, val

        def deducible(my_pair, other_list):
            vals = set()
            for p in other_list:
                ok, v = intersect_one(my_pair, p)
                if ok:
                    vals.add(v)
            return len(vals) == 1

        n, m = map(int, input().split())
        A = [tuple(map(int, input().split())) for _ in range(n)]
        B = [tuple(map(int, input().split())) for _ in range(m)]

        valid = []
        for a in A:
            for b in B:
                ok, x = intersect_one(a, b)
                if ok:
                    valid.append((a, b, x))

            all_x.add(x)

        if len(all_x) == 1:
            print(next(iter(all_x)))
        elif all_both_know:
            print(0)
        else:
            print(-1)

    solve()
    return ""

 ## 特殊なケース

 複数の候補の隠れたペアが存在するが、すべてが同じ共有番号につながる場合、列挙では同じ x 値が収集されます。`all_x`。 その状況では、アルゴリズムはすぐにその数値を出力します。 たとえば、すべての有効な割り当てが桁 1 での重複を強制する場合、すべての`(a, b)`妥当性に寄与するペアは x = 1 を生成し、集合は`all_x`サイズは1になります。 

異なる割り当てによって異なる共有数が生成されるが、どの割り当てでも各参加者が結果を一意に推測できる場合、変数`all_both_know`真実のままです。 これは、不確実性がグローバルではあるがローカルではない状況に対応します。 アルゴリズムは、すべての有効な値に対して次のことを保証することでこれを検出します。`(a, b)`ペア、両方`deducible(a, B)`そして`deducible(b, A)`true と評価されます。 

参加者が結果を推測できない有効な課題が少なくとも 1 つ存在する場合、`all_both_know`偽になります。 これにより、出力が最終的なものに強制されます。`-1`共有番号がグローバルに一意でない場合は常にこの場合です。
