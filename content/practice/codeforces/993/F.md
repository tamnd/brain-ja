 ## 解決策
 ## 問題の理解

 一連のバイナリ入力機能の上の 2 層に構築された固定論理回路が与えられます。 最初の層には少数のゲートが含まれており、各ゲートは 2 つの入力変数を正確に読み取り、AND、OR、NAND、または NOR の 4 つの演算のいずれかを使用してブール出力を生成します。 2 番目の層には別のゲート セットが含まれており、各ゲートは最初の層から 2 つの出力を正確に受け取り、同じ種類の演算を適用します。 最終出力は、すべての第 2 層出力を集約する単一の OR ゲートによって生成されます。 

評価の仕組みにはねじれがあります。 通常の評価では、すべてのゲートが期待どおりに動作します。 「恋に落ちた」状態では、すべてのゲートの意味が反転します。AND は NAND になり、OR は NOR になり、NAND は AND になり、NOR は OR になります。 この反転は、2 番目の層と最後の OR ゲートを含むすべてのゲートに均一に適用されます。 

目標は、可能な限り少ない数の第 2 層ゲートを削除して、回路の最終出力が入力機能のすべての可能な割り当てに対して両方のモードで同一になるようにすることです。 言い換えれば、削除後の回路の出力は、すべてのゲート セマンティクスが正常であるか完全に反転しているかに依存してはなりません。 

制約は小さく、入力フィーチャは最大 50、第 1 層のゲートは 50、第 2 層のゲートは 50 個です。 これにより、すべての入力割り当てを列挙しようとするソリューションは即座に除外されます。$2^{50}$は大きすぎます。 ただし、有効な依存関係を制限できれば、局所的な小さな構造上での動作を明示的にシミュレートすることができます。 

第 2 層ゲートの構造が異なっていても、すべての入力に対して同一に動作する場合、微妙なエッジ ケースが発生します。 たとえば、2 つのゲートが異なるように配線されていても、最初の層の対称性により同じブール関数を計算する場合があります。 それらを別個のオブジェクトとして扱うのは正しくありません。 すべての入力にわたってそれらの誘導関数を比較する必要があります。 

もう 1 つの落とし穴は、第 2 層の出力が独立していると仮定していることです。 それぞれが同じ基礎となる機能の決定論的な関数であるため、これらは任意のブール変数ではありません。 この相関関係により、代入に対する強引な攻撃が実行不可能になり、構造的な推論が必要になります。 

## アプローチ

 直接的な総当たりアプローチでは、第 2 層ゲートのすべてのサブセットが試行されます。 各サブセットについて、すべての条件で回路を評価します。$2^n$入力割り当てを行い、通常モードと反転モードが一致するかどうかを確認します。 指数関数的な入力空間を無視しても、すべてのサブセットを試すにはすでにコストがかかります$2^{50}$、それは不可能です。 

重要な単純化は、「愛の反転」が回路構造にどのような影響を与えるかを理解することです。 すべてのゲート出力は無効化され、すべてのゲート動作もそのデュアルに置き換えられます。 これは、2 つの完全に異なる回路を追跡する代わりに、同じ中間信号に対して 2 つの決定論的なブール式を比較していることを意味します。 

ノーマルモードでの第 2 層ゲートの出力を次のように表すと、$x_i$、反転モードでは次のようになります。$\neg x_i$。 最後のゲートは、通常モードでは OR、反転モードでは NOR になります。 それで:

 通常モードでは、出力は次のようになります。$$\text{OR}(x_1, x_2, \dots)$$反転モードの場合:$$\text{NOR}(\neg x_1, \neg x_2, \dots) = \neg (\text{OR}(\neg x_i)) = \text{AND}(x_i)$$したがって、単純化すると、問題は次のようになります: サブセットを選択する$S$すべての有効な入力に対して、$$\text{OR}_{i \in S}(x_i) = \text{AND}_{i \in S}(x_i)$$この等価性は非常に制限的です。 任意のブール変数の場合、すべての変数が入力空間上で同一の関数である場合にのみ、すべての代入に対して OR が AND と等しくなります。 それ以外の場合、いずれかの入力で 2 つの関数が異なる場合、一方が 1、もう一方が 0 である代入が見つかり、OR と AND の間の等価性が崩れてしまいます。 

したがって、問題は、機能的等価性によって第 2 層ゲートをグループ化することに帰着します。 各グループ内では、すべてのゲートが元の入力フィーチャに対してまったく同じブール関数を計算します。 このようなグループの 1 つからサブセットを選択すると、OR と AND は同じように動作します。 グループを混合すると、一部の入力が異なり、2 つのモードが分岐します。 

したがって、第 2 層ゲートごとに、それが計算するブール関数の正規表現を計算します。 次に、同一の表現の頻度を数え、最大のグループを保持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットと入力に対するブルート フォース |$O(2^k \cdot 2^n)$|$O(1)$| 遅すぎる |
 | 関数の正規化 |$O(k)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのゲートを最大 4 つの入力変数にわたる正規ブール関数に還元し、同一のものをグループ化します。 

1. 各第 1 層ゲートについて、その 2 つの入力フィーチャを特定します。 これは正確に 2 つの変数に依存するため、それらの変数に対するサイズ 4 の真理値表によってその動作を表すことができます。 
2. 各第 2 層ゲートについて、その 2 つの入力第 1 層ゲートで使用される変数の和集合を収集します。 各第 1 層ゲートは最大 2 つの変数に寄与するため、このセットのサイズは最大 4 です。 
3. すべて列挙する$2^s$これらの変数の代入、ここで$s \le 4$。 割り当てごとに、格納されている真理値表を使用して、基礎となる 2 つの第 1 層ゲートの出力を計算します。 
4. これら 2 つの値に第 2 層のゲート演算 (AND、OR、NAND、NOR) を適用して、この割り当ての第 2 層の出力を計算します。 
5. これにより、第 2 層ゲートのサイズが最大 16 の真理値表が生成されます。 順序付き変数リストと一緒に正規の署名として使用します。 
6. 同じ署名を共有する第 2 層ゲートの数を数えます。 
7. 答えは、第 2 層ゲートの総数から最大の署名グループのサイズを引いたものです。 

### なぜ効果があるのか

 第 2 層の各ゲートは、元の入力フィーチャの決定論的なブール関数です。 2 つのゲートは、入力空間全体にわたる真理値表が同一である場合に限り、すべての入力に対して同一の動作をします。 すべてのゲートは最大 4 つの機能に依存するため、それらの機能だけのすべての割り当てを列挙することで機能が完全に決まります。 これにより、署名が完全になり、衝突がなくなります。 したがって、この署名によるグループ化は機能的等価性を正確に捕捉し、最適なサブセットは任意の最大等価性クラスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def eval_op(op, a, b):
    if op == "and":
        return a & b
    if op == "or":
        return a | b
    if op == "nand":
        return 1 - (a & b)
    if op == "nor":
        return 1 - (a | b)

def build_truth(op, vars_idx):
    # vars_idx has size 2, indices into [0,1]
    tt = [0] * 4
    for mask in range(4):
        a = (mask >> 0) & 1
        b = (mask >> 1) & 1
        tt[mask] = eval_op(op, a, b)
    return tt

def main():
    n, m, k = map(int, input().split())

    first_ops = []
    first_vars = []
    first_tt = []

    parts = input().split()
    idx = 0
    for _ in range(m):
        op = parts[idx]
        s = parts[idx + 1]
        idx += 2

        vars_idx = [i for i, c in enumerate(s) if c == 'x']
        first_ops.append(op)
        first_vars.append(vars_idx)
        first_tt.append(build_truth(op, vars_idx))

    second = []
    parts = input().split()
    idx = 0
    for _ in range(k):
        op = parts[idx]
        s = parts[idx + 1]
        idx += 2
        j, l = map(int, s.split())

        second.append((op, j, l))

    def eval_first_gate(g, assignment):
        op = first_ops[g]
        v = first_vars[g]
        a = assignment[v[0]]
        b = assignment[v[1]]
        return eval_op(op, a, b)

    freq = {}

    for op, j, l in second:
        g1 = j - 1
        g2 = l - 1

        vars_set = set(first_vars[g1]) | set(first_vars[g2])
        vars_list = list(vars_set)

        idx_map = {v: i for i, v in enumerate(vars_list)}
        s = len(vars_list)

        tt = []
        for mask in range(1 << s):
            assignment = [0] * n
            for i, v in enumerate(vars_list):
                assignment[v] = (mask >> i) & 1

            x = eval_first_gate(g1, assignment)
            y = eval_first_gate(g2, assignment)
            tt.append(eval_op(op, x, y))

        key = (tuple(vars_list), tuple(tt))
        freq[key] = freq.get(key, 0) + 1

    ans = k - max(freq.values())
    print(ans)

if __name__ == "__main__":
    main()
```実装ではまず、各第 1 層ゲートを小さな真理値表に変換して、列挙中に迅速に評価できるようにします。 第 2 層ゲートごとに、関連する変数の結合を構築し、それらの割り当てのみを列挙し、すべてには触れません。$n$インデックス作成を超えた有意義な方法で変数を活用します。 

よくある間違いは、直接入力を使用して第 2 層ゲートを直接比較しようとすることです。 2 つの異なる第 1 層ゲートが同一の関数を計算できるため、構造比較が不正確になるため、これは失敗します。 もう 1 つの微妙な問題は、変数セットが正規キーの一部である必要があることを忘れていることです。 異なる変数位置に対する同じ真理表は、同じ関数を表しません。

 ## 特殊なケース

 すべての第 2 層ゲートが異なる関数を計算する場合、グループ化ステップではシングルトン クラスのみが生成されます。 アルゴリズムは最大のシングルトンを選択します。これは、ゲートが 1 つだけ残ることを意味します。 異なるブール関数のペアは一部の割り当てに関して一致せず、OR と AND が異なることを強制されるため、これは要件に一致します。 

すべての第 2 層ゲートが構造的に同一であるが、異なる中間第 1 層表現を使用している場合でも、正規化ステップはサポート変数のすべての割り当てにわたって動作を評価するため、正規化ステップによってそれらのゲートが 1 つの署名に折りたたまれます。 これにより、構造の違いによる誤った分割が回避されます。 

2 つのゲートが互いに素な変数セットを使用している場合でも、それらの和集合はゲートごとに最大 4 つの変数内に収まり、列挙はそれらの相互作用を正確にキャプチャします。 構造的に独立しているように見えても、出力動作の違いは真理値表で検出され、正しいグループ化が保証されます。
