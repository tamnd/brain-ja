 ## 解決策
 ## 問題の理解

 2D 平面上に一連の個別の点が与えられます。 このタスクは、1 つの点が他の 2 つによって形成されるセグメントの中点に正確に位置する構成を形成する、順序のない点の 3 つの要素がいくつあるかを数えることです。 

3つのポイントを挙げるなら$A$、$B$、 そして$C$、 それから$B$セグメントの中点です$AC$いつ：$B = \left(\frac{x_A + x_C}{2}, \frac{y_A + y_C}{2}\right)$トリプルには順序がないため、ペアは$(A,B,C)$と同じです$(C,B,A)$。 有効な幾何学的構成をそれぞれ 1 回だけカウントしたいと考えています。 

制約$n \le 3000$が問題の鍵です。 すべてのトリプルを直接チェックする三次解では、約$3000^3 = 27$これは 2 秒の制限時間に収まる量をはるかに超えています。 約 900 万回の演算を伴う 2 次解は、Python では完全に合理的です。 

座標は小さいです。$-1000$そして$1000$, しかし、それだけでは小さなグリッドベースのソリューションを構築するには十分ではありません。 重要な観察は幾何学的なものです。$B$の中間点です$AC$、次に、の座標$A$そして$C$決定する$B$ユニークに。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

次の入力を考えてみましょう。```
3
0 0
1 1
2 2
```答えは次のとおりです。```
1
```ポイント$(1,1)$の中間点です$(0,0)$そして$(2,2)$。 

次に、次のことを考えてみましょう。```
3
0 0
1 0
2 1
```答えは次のとおりです。```
0
```平均が整数であるかどうかをチェックするだけの単純な実装では、これを誤ってカウントする可能性があります。 の中間点$(0,0)$そして$(2,1)$は$(1,0.5)$、点間には存在しません。 

もう 1 つの微妙な問題は、二重カウントです。 次のものがあるとします。```
3
0 0
1 1
2 2
```順序付けされたペアを反復すると$(A,C)$、その後両方$(0,0)\rightarrow(2,2)$そして$(2,2)\rightarrow(0,0)$同じ中間点を生成します。 不注意な解決策を実行すると、1 ではなく 2 が返されます。 

もう 1 つの重要なケースは、中点座標が小数の場合です。```
4
0 0
1 1
1 0
2 1
```の中間点$(0,0)$そして$(1,1)$は$(0.5,0.5)$、これは無効です。 の中間点$(1,0)$そして$(2,1)$は$(1.5,0.5)$、も無効です。 正解は 0 です。浮動小数点演算を使用するアプローチでは、精度の問題や不必要な複雑さのリスクが生じます。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 個別の点のトリプルごとに反復処理を行い、そのうちの 1 つが他の 2 つの点の中点であるかどうかを確認できます。 

トリプルごとに$(A,B,C)$、次のことを確認します。$2x_B = x_A + x_C \quad \text{and} \quad 2y_B = y_A + y_C$これが機能するのは、中間点の座標が端点の正確な平均であるためです。 このアプローチは正しいですが、実行時間は悲惨なものです。 がある$\binom{3000}{3}$トリプル、つまり約 45 億通りの組み合わせになります。 Even a tiny constant factor cannot save this.

 ボトルネックは、トリプルを明示的に選択することにあります。 中間点の条件は、実際には端点のペアにのみ依存します。 一度$A$そして$C$が固定されると、中点がすぐに決定されます。 

この観察によって問題は完全に変わります。 

3 つの点を選択する代わりに、2 つの点だけを選択します$A$そして$C$。 それらの中間点は次のとおりです。$\left(\frac{x_A+x_C}{2}, \frac{y_A+y_C}{2}\right)$指定された点の中にその中間点が存在する場合、有効な 3 つ組が 1 つ見つかりました。 

すべてのポイントをハッシュ セット内に保存できます。$O(1)$会員チェック。 次に、順序付けされていないすべての点のペアを反復処理します。 

各ペアについて:

 1. 合計が正しいかどうかを確認します。$x_A+x_C$そして$y_A+y_C$均等です。 
2. 中点座標を計算します。 
3. その中間点がセット内に存在するかどうかを確認します。 

これにより、複雑さが軽減されます。$O(n^2)$、制約に簡単に適合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを読み取り、リストに保存します。 
2. すべてのポイントをハッシュ セットに挿入します。 

このセットを使用すると、中点が存在するかどうかを確認するときに定数時間の検索が可能になります。 
3. 答えを 0 に初期化します。 
4. 順序付けされていないすべての点のペアを反復処理します。$(i,j)$どこ$i < j$。 

順序のないペアを使用すると、二重カウントが防止されます。 ペア$(A,C)$正確に 1 回処理する必要があります。 
5. 現在のペアについて、次を計算します。$s_x = x_i + x_j, \quad s_y = y_i + y_j$6. どちらかの場合$s_x$または$s_y$奇数なので、このペアをスキップしてください。 

整数座標点には分数座標の中点を含めることはできません。 
7. それ以外の場合は、中点を計算します。$m_x = \frac{s_x}{2}, \quad m_y = \frac{s_y}{2}$8.次のことを確認します。$(m_x,m_y)$点の集合の中に存在します。 

存在する場合は、答えを 1 増やします。 
9. 最終的な答えを印刷します。 

### なぜ効果があるのか

 有効なトリプレットごとに、順序のないエンドポイントのペアが 1 つだけ存在します。$(A,C)$。 それらの中点は一意に決定され、アルゴリズムはその中点が入力に存在するかどうかをチェックします。 

ペアの反復では次を使用するため、すべての有効なトリプレットは 1 回カウントされます。$i < j$。 逆の順序$(C,A)$決して再訪されることはない。 

中間点条件は整数演算を使用して正確にチェックされるため、無効なトリプレットはカウントされません。$2m_x = x_A + x_C, \quad 2m_y = y_A + y_C$中点は、実際の入力点と一致する場合にのみ受け入れられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    points = []
    point_set = set()
    
    for _ in range(n):
        x, y = map(int, input().split())
        points.append((x, y))
        point_set.add((x, y))
    
    ans = 0
    
    for i in range(n):
        x1, y1 = points[i]
        
        for j in range(i + 1, n):
            x2, y2 = points[j]
            
            sx = x1 + x2
            sy = y1 + y2
            
            if sx % 2 != 0 or sy % 2 != 0:
                continue
            
            mx = sx // 2
            my = sy // 2
            
            if (mx, my) in point_set:
                ans += 1
    
    print(ans)

solve()
```最初の部分では、すべてのポイントをリストとセットの両方に読み取ります。 リストは反復順序を保持しますが、セットは高速な中間点の存在チェックを提供します。 

ネストされたループは、順序付けされていないペアをすべて 1 回だけ列挙します。 使用する`j`から`i + 1`重複処理を回避し、正確なカウントを保証します。 

パリティ チェックは重要です。```
if sx % 2 != 0 or sy % 2 != 0:
    continue
```これがないと、整数の除算が黙って切り捨てられ、誤った中間点の一致が作成されてしまいます。 

中間点は整数演算のみを使用して計算されます。 浮動小数点演算は不要であり、回避可能な精度の問題が発生します。 

メンバーシップの最終チェック:```
if (mx, my) in point_set:
```は、ソリューションの幾何学的コアです。 入力点の間に中点が存在する場合、それらの 3 つの点は有効なトリプレットを形成します。

 ## 特殊なケース

 小数点の中点の場合を考えてみましょう。```
3
0 0
1 1
2 1
```アルゴリズムチェックペア$(0,0)$そして$(1,1)$。 それらの座標の合計は、$(1,1)$、どちらも奇妙です。 中間点は次のようになりますので、$(0.5,0.5)$の場合、ペアはすぐにスキップされます。 

次にチェックします$(0,0)$そして$(2,1)$。 合計は$(2,1)$。 y 座標の合計が奇数であるため、このペアもスキップされます。 

最後のペアも分数の中点座標を生成します。 答えは0のままです。 

次に、二重カウントのシナリオを考えてみましょう。```
3
0 0
1 1
2 2
```唯一の有効なトリプレットはエンドポイントを使用します$(0,0)$そして$(2,2)$。 アルゴリズムは、次のインデックスのみを考慮するため、このペアを 1 回処理します。$i < j$。 逆のペアは決して現れないので、答えは 2 ではなく 1 になります。 

最後に、中点座標が整数であるが、中点が欠落している場合を考えてみましょう。```
3
0 0
2 2
5 5
```ペア$(0,0)$そして$(2,2)$中間点を生成します$(1,1)$。 パリティ チェックは合格しますが、セット ルックアップは失敗します。$(1,1)$は入力に入っていません。 アルゴリズムはペアを正しく拒否し、0 を出力します。
