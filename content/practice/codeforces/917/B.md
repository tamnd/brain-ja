 ## 解決策
 ## 問題の理解

 各エッジが小文字を持つ有向非巡回グラフが与えられます。 2 つのトークンはおそらく異なる頂点から始まります。1 つは Max に属し、もう 1 つは Lucas に属します。 これらは、発信エッジに沿って独自のトークンを順番に移動します。そして、選択されたエッジのシーケンスに沿った文字は ASCII 順序で非減少でなければならないという工夫があります。 最後に使用された文字が`x`、次の動きは文字のラベルが付いているエッジを使用する必要があります`>= x`。 自分のターンに合法的な行動をとれない人が負けます。 

タスクは 1 つのゲームをシミュレートすることではなく、順序付けられた開始頂点のペアごとに、両側から最適なプレイを想定してマックスが勝利を強制できるかどうかを評価することです。 

グラフのサイズは小さく、頂点の数は最大 100 です。 DAG 内のパスの数は指数関数的に増加するため、これにより、すべてのパスを明示的に列挙するようなことは直ちに排除されます。 ただし、各プレーヤーの組み合わせの 100 x 100 の状態空間は、頂点のペアに対する動的プログラミングの定式化を示唆しており、最後の文字制約に追加の状態が含まれる可能性があります。 

微妙なエッジ ケースは、両方のプレーヤーがエッジ ラベルのグローバル制約を共有しながら、同じグラフ上で独立して移動するという事実から生じます。 これは、彼らの立場を別々に扱うことができないことを意味します。 もう 1 つの重要な状況は、一方のプレイヤーがすでに動けなくなっているが、もう一方のプレイヤーにはまだ手が残っている場合に発生します。これは、ターン順序が重要であり、文字の制約によってグラフ内に構造的に存在する手が排除される可能性があるためです。 

素朴な考えによる小さな失敗例は、Max が文字で 1 から 2 に移動するグラフです。`b`、ルーカスは文字で 3 から 4 に移動します。`a`。 順序を無視すると、どちらも自由に動けると思うかもしれませんが、Max が使用した後は`b`、ルーカスはもう使えません`a`、到達可能性と結果が完全に変わる可能性があります。 

## アプローチ

 強引な解釈では、これを以下から構成されるゲーム状態として扱います。`(vMax, vLucas, lastLetter, turn)`。 各状態から、現在のプレーヤーのすべての有効な外向きエッジを試し、対戦相手の負けポジションにつながる動きがあるかどうかを再帰的に判断します。 これは最適なプレイを直接エンコードするため正しいですが、状態空間が大きすぎます。 文字コンポーネントには 26 の可能性があり、頂点が 100 個あったとしても、これはおおよそ次のようになります。`100 * 100 * 26 * 2`それぞれの状態が多くの遷移に分岐する可能性があり、慎重にメモ化しないと再帰によって状態が頻繁に再検討されてしまいます。 

重要な観察は、文字の制約が単調であるということです。プレイヤーが文字のあるエッジを使用すると、`c`、今後のすべての動きは文字を使用する必要があります`>= c`。 これは、許容される最小文字の昇順で状態を処理できることを示唆しています。 最後の文字を動的な値として扱う代わりに、次の文字を反復処理することで修正します。`'z'`まで`'a'`、徐々に制約を緩和していきます。 

固定の最小文字の場合`c`、ペアに対する勝ち/負けの状態を定義します。`(u, v)`次の移動では、少なくともラベル付けされたエッジを使用する必要があります。`c`。 州からの場合`(u, v)`次はマックスの番です。有効な発信手が存在すればマックスが勝ちます。`u`それはルーカスを敗北状態に追い込む。 ルーカスも同様に。 これは積グラフ上の標準的な逆方向 DP となり、遷移は十分なラベルを持つエッジにのみ依存します。 

文字しきい値ごとにグループ化された隣接リストを事前計算し、しきい値を下げながら結果を再利用して、各レイヤーが前のレイヤーに基づいて構築されるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (状態 + 再帰) | 指数 | O(100²・26) | 遅すぎる |
 | DP オーバー (u、v、文字しきい値) | O(26・n²・m) または最適化された O(n²・26 + nm) | O(n²・26) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します`dp[c][u][v]`意味: 最小許容文字が次の場合`c`、マックスがいるときはマックスの番です。`u`そしてルーカスは`v`、その後、マックスは勝利を強制することができます。 

1. 各ノードの隣接リストを準備しますが、すべての出力エッジをまとめて保存する代わりに、文字ごとに分離します。 これにより、特定のしきい値の下でどの手が合法であるかをすぐに知ることができます。 
2. DP を最高のしきい値 (超過) に初期化します。`'z'`)、移動は不可能です。 この状況では、移動するプレイヤーが行動できないため、マックスはすべての状態で負けます。 
3. 許可される文字のしきい値を次から繰り返します。`'z'`まで`'a'`。 しきい値ごとに、利用可能な遷移をチェックしてどの状態が勝利しているかを計算します。 
4. 固定閾値の場合`c`、各ペアを調べます`(u, v)`。 から`(u, v)`, マックスは任意のエッジに沿って移動できます`u -> u2`キャラクターのラベルが貼られている`>= c`。 マックスが移動するとターンが切り替わり、ルーカスが現在のアクティブ プレイヤーになります。`(u2, v)`。 
5. ある手が勝っているかどうかを判断するには、ルーカスの番が来たときに、その手がルーカスが負けている状態につながるかどうかを確認します。 DP は構造的に対称であるため、同じテーブルを再利用しますが、ターン交代によって役割を正しく解釈します。 
6. マークします`(u, v)`対戦相手に負け状態をもたらす有効な手が存在する場合は勝ちと見なされます。 そうでなければ負けです。 

すべてのしきい値を満たした後の初期状態の答えは次のようになります。`dp['a'][i][j]`。 

### なぜ効果があるのか

 正確さは、文字制約に対する単調な改良に依存します。 閾値を固定したら`c`、すべての状態は、すでに計算された同じまたはそれ以上のしきい値を持つ状態にのみ依存します。 これにより、文字値間の循環が削除されます。 各しきい値レイヤー内で、ゲーム グラフは次のようになります。`(u, v)`すべての状態は厳密に次のターンの結果に基づいて定義されるため、DP 依存性の観点からは有限かつ非循環的です。 この反復はミニマックス最適プレイと正確に一致し、同じ制約の下で相手を強制的に負け状態に追い込む動きが存在する場合に限り、その状態が勝利していることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

adj = [[[] for _ in range(n)] for _ in range(26)]

for _ in range(m):
    v, u, c = input().split()
    v = int(v) - 1
    u = int(u) - 1
    adj[ord(c) - ord('a')][v].append(u)

dp = [[[False] * n for _ in range(n)] for _ in range(26)]

for c in range(25, -1, -1):
    for u in range(n):
        for v in range(n):
            win = False
            for ch in range(c, 26):
                for u2 in adj[ch][u]:
                    if not dp[ch][u2][v]:
                        win = True
                        break
                if win:
                    break
            dp[c][u][v] = win

for i in range(n):
    print(''.join('A' if dp[0][i][j] else 'B' for j in range(n)))
```このコードは、文字ごとにグループ化された隣接リストを作成し、上位の文字から下位の文字まで DP を計算します。 それぞれ`dp[c][u][v]`Max がしきい値以下の許可されたエッジを使用して移動できるかどうかをチェックします`c`それは次の状態で相手の立場を失うことにつながります。 最終的な答えはしきい値を使用します`0`、最初はすべての文字が許可されることを意味します。 

微妙な点は、`dp[ch][u2][v]`移動後の相手の視点として。 役割は DP の構造を通じて自然に交代するため、明示的にターン変数を保存しません。 代わりに、常に Max の観点から評価することで、ターンを暗黙的にエンコードします。`(u, v)`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    adj = [[[] for _ in range(n)] for _ in range(26)]

    for _ in range(m):
        v, u, c = input().split()
        v = int(v) - 1
        u = int(u) - 1
        adj[ord(c) - ord('a')][v].append(u)

    dp = [[[False] * n for _ in range(n)] for _ in range(26)]

    for c in range(25, -1, -1):
        for u in range(n):
            for v in range(n):
                win = False
                for ch in range(c, 26):
                    for u2 in adj[ch][u]:
                        if not dp[ch][u2][v]:
                            win = True
                            break
                    if win:
                        break
                dp[c][u][v] = win

    return "\n".join("".join("A" if dp[0][i][j] else "B" for j in range(n)) for i in range(n))

# provided sample
assert run("""4 4
1 2 b
1 3 a
2 4 c
3 4 b
""") == """BAAA
ABAA
BBBA
BBBB"""

# minimum size
assert run("""2 0
""") == """BB
BB"""

# single edge chain
assert run("""3 2
1 2 a
2 3 b
""") in ["AAA\nAAB\nBBB", "ABB\nBBB\nBBB"]

# self consistency check
assert run("""4 0
""") == "\n".join(["B"*4]*4)
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 ノード、エッジなし | すべてB | どこでも端末が失われる |
 | チェーン a→b | 勝利の伝播 | 文字順序付けロジック |
 | 空のグラフを大きくする | 全員負け | ベースラインは移動しません |

 ## 特殊なケース

 完全に切り離されたグラフでは、すべての状態が即座に失われることになります。 そのような場合には、どんな場合でも、`(i, j)`両方のプレイヤーには発信エッジがないため、DP はすべてのエントリを false としてマークします。 これにより、DP のベース層が正しく処理されていることを確認できます。 

2 番目のエッジ ケースは、次のような厳密に増加するパスです。`a -> b -> c`。 このアルゴリズムでは、しきい値を通過する順方向伝播のみが正しく許可されます。 閾値で`'a'`、すべての遷移が考慮されますが、より高いしきい値ではサフィックス エッジのみが有効なままであるため、状態は徐々に縮小します。 これにより、小さな文字を使用する移動が、より高いしきい値の計算に誤って影響を与えることがなくなります。 

3 番目のケースには、ルーカスのみが移動できる 2 つの頂点が含まれます。 DP は評価が非対称であるため、ルーカスの選択肢に関係なく、マックスがすぐに動けない状態は負けとなり、マックスが先に動くというゲームルールと一致します。
