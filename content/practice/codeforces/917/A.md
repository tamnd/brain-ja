 ## 解決策
 ## 問題の理解

 可能な 3 つの文字で構成される文字列が与えられます。`'('`、`')'`、 そして`'?'`。 

すべての部分文字列について、それぞれを置き換えることによって空ではない正しい括弧シーケンスに変換できるかどうかを尋ねます。`'?'`どちらとも独立して`'('`または`')'`。 このような部分文字列は _pretty_ と呼ばれます。 

タスクは、きれいな部分文字列がいくつあるかを数えるということです。 

正しい括弧シーケンスには 2 つの定義的なプロパティがあります。 開き括弧と閉じ括弧の合計数は等しく、左から右にスキャンしている間、閉じ括弧の数が開き括弧の数を超えることはありません。 

文字列の長さは最大 5000 です。$$\frac{n(n+1)}{2}$$部分文字列の数は、およそ 1,250 万です。$n=5000$。 すべての部分文字列に対して実質的な作業を実行するアルゴリズムは、直ちにコストが高くなりすぎます。 3 次の解はまったく不可能であり、単純な 2 次の解であっても、非常に小さな定数係数が必要です。 

いくつかの特殊なケースにより、問題は通常の括弧の検証よりも難しくなります。 

次の文字列を考えてみましょう。```
??
```次のように置き換えることができるので、答えは 1 です。`"()"`。 

治療する素朴なチェック`'?'`何かに一致するワイルドカードを使用すると、多くの無効な部分文字列が誤ってカウントされるためです。 

考慮する：```
?)
```答えも 1. 置き換える`'?'`と`'('`与える`"()"`。 

置換を決定する前に現在のプレフィックスのバランスがすでに非負でなければならないと主張するメソッドは、この部分文字列を誤って拒否します。 

考慮する：```
(((
```答えは 0 です。無効な接頭辞がない場合でも、開き括弧と閉じ括弧の合計数が等しくなることはありません。 

別の微妙な例は次のとおりです。```
???
```答えは 1 です。長さ 2 の部分文字列のみが候補となります。 正しい括弧シーケンスはすべて均等な長さであるため、長さ 3 の部分文字列全体がバランスをとることはありません。 

どのアプローチでも、プレフィックス制約と置換を動的に選択する機能を同時に処理する必要があります。 

## アプローチ

 最も直接的な解決策は、すべての部分文字列を列挙し、その疑問符の割り当てによって正しい括弧シーケンスが生成されるかどうかを判断することです。 

ブルート フォース バージョンでは、すべての部分文字列を列挙し、各部分文字列について疑問符の可能なすべての置換を試みます。 疑問符が 20 個ある部分文字列でも、すでに 100 万を超える代入が行われているため、これは完全に不可能です。 

より良い総当たりのアイデアは、すべての部分文字列を列挙し、有効なシーケンスに完成できるかどうかを貪欲にチェックすることです。 がある$O(n^2)$部分文字列と各チェックにかかる時間$O(n)$、につながる$O(n^3)$時間。 と$n=5000$、これは限界をはるかに超えています。 

重要な点は、終了位置ごとに検証を最初からやり直す必要がないということです。 

開始位置を固定する$l$。 次に、右のエンドポイントを拡張します$r$一度に 1 文字ずつ。 

スキャン中は 2 つの量を維持します。 

最初の数量は、貪欲な選択を行った後の現在の残高です。 私たちが見るたびに`'('`、残高が増加します。 私たちが見るたびに`')'`、残高が減ります。 私たちが見るたびに`'?'`、一時的に次のように扱います。`'('`、バランスが増加します。 

2 番目の数量は、疑問符が何個として扱われたかです。`'('`これまでのところ。 これらの選択肢は後から切り替えることができます`')'`、残高が 2 減ります。 

残高がマイナスになるたびに、以前に使用した残高をすぐに変換します`'?'`から`'('`に`')'`。 これにより、残高が 2 減り、利用可能な疑問符変換が 1 つ消費されます。 変換が利用できない場合は、これから始まる長い部分文字列がすべて$l$も失敗するのでやめておきます。 

この貪欲なプロセスにより、残高を可能な限り小さく保ちながら、プレフィックスが無効になることは決してありません。 

現在の部分文字列の長さが偶数で、その結果のバランスが正確にゼロになる場合は常に、きれいな部分文字列が見つかったことになります。 

修正してから$l$そして延長します$r$各ペアに 1 回$(l,r)$は 1 回だけ処理されます。 複雑さは次のようになります$O(n^2)$、これは許容されます$n=5000$。

 | ブルートフォース部分文字列検証 | O(n3) | お(1) | 遅すぎる |
 | あらゆるスタートから貪欲なスキャン | O(n²) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 答えをゼロに初期化します。 
2. 開始位置を選択します$l$。 
3.セット`balance = 0`。 
4.セット`free = 0`、現在疑問符として扱われている疑問符の数を表します。`'('`後で反転することもできます。 
5. 終了位置を延長する$r$から$l$文字列の最後まで。 
6. もし`s[r]`は`'('`、増分`balance`。 
7. もし`s[r]`は`')'`、デクリメント`balance`。 
8. もし`s[r]`は`'?'`、両方を増分します`balance`そして`free`。 

これは一時的に選択することに相当します`'('`。 
9. ながら`balance > 0`そして`free > balance // 2`正しい状態ではありません。 その代わり、いつでも`balance`一時的なものをたくさん蓄積したため、大きくなりすぎました`'('`、まだ何もしていません。 有効性をチェックする場合にのみ反応します。 
10. もし`balance < 0`、以前に使用可能な疑問符を 1 つ反転してみてください。 

反転すると選択した項目が変更されます`'('`の中へ`')'`、残高が 2 減ります。 

実装では、これは次のように行われます。```
balance += 2
free -= 1
```11. 修復を試みた後も残高がまだマイナスの場合は、この開始位置の処理を停止します。 拡張機能ではすでに無効なプレフィックスを修復できなくなりました。 
12. 現在の部分文字列の長さが偶数で、かつ`balance == 0`、答えを増やします。 
13. 開始位置ごとに繰り返します。 

### なぜ効果があるのか

 開始位置が固定されている場合、すべての疑問符は最初は次のように扱われます。`'('`。 これにより、そのような選択は後で次のように変換できるため、将来の柔軟性が最大化されます。`')'`。 

残高がマイナスになる場合は常に、有効な括弧シーケンスでは、この時点の前に追加の開始括弧が必要になります。 これらを取得する唯一の方法は、以前の疑問符を再解釈することです。 この修復を直ちに実行することは必須であり、将来の可能性を損なうことはありません。 

このアルゴリズムは、処理されたすべてのプレフィックスが非負に保たれるように、すべての割り当ての間で実行可能な最小のバランスを常に維持します。 偶数長の位置で残高が 0 に達した場合、プレフィックスがすべて有効で合計残高が 0 である割り当てが存在します。 この割り当てにより、正しいブラケット シーケンスが形成されます。 逆に、そのような状態に到達しない場合は、両方の条件を満たす代入はできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    ans = 0

    for l in range(n):
        balance = 0
        free = 0

        for r in range(l, n):
            if s[r] == '(':
                balance += 1
            elif s[r] == ')':
                balance -= 1
            else:
                balance += 1
                free += 1

            if balance < 0:
                if free == 0:
                    break
                balance += 2
                free -= 1

            if (r - l + 1) % 2 == 0 and balance == 0:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```外側のループは部分文字列の左端を固定します。 

各開始位置について、右端点を 1 回だけスキャンします。 変数`balance`そして`free`現在の部分文字列に関して必要なすべての情報を要約します。 

疑問符は最初は左括弧としてカウントされます。 これにより両方が増加します`balance`そして`free`。 値`free`それらの暫定的な選択肢のうち変換可能なものがいくつ残っているかを記録します。 

閉じ括弧によって残高がマイナスになった場合、可能な唯一の修復は、前の疑問符を閉じ括弧として再解釈することです。 このような変更によりバランスが変更されます。`+2`キャラクターが以前に貢献したため、現在の状態と比較して`+1`そして今では貢献しています`-1`。 

ブレイク条件は重要です。 残高が負で、未使用の疑問符が存在しない場合、現在のプレフィックスは永久に無効になります。 部分文字列を拡張しても、すでに失敗しているプレフィックスを変更することはできないため、それ以上の作業は必要ありません。 

パリティチェックも不可欠です。 正しい括弧シーケンスでは、開始括弧と閉じ括弧の数が同じである必要があり、これは長さが均等であることを意味します。 バランスゼロだけでは十分ではありません。
