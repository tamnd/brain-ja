 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルが白 (「.」) または黒 (「*」) のグリッドです。 Vasya は、このグリッドのいくつかのサブスクエアにフラクタルを描いたと主張しています。 フラクタルは次から再帰的に構築されます。$2 \times 2$基本パターンでは、各ステップで、各白い正方形が 4 つの小さな正方形に再分割され、基本パターンに従って色付けされます。黒い正方形も黒のままですが、同様に再分割されます。 有効なフラクタルは、少なくとも 2 つの再帰ステップで始まります。つまり、最小の有効なフラクタルは少なくとも 1 ステップです。$4 \times 4$四角。 

私たちの目標は、いくつかの関数によって生成された可能性のあるフラクタルに正確に対応するグリッドのサブスクエアがいくつあるかを数えるということです。$2 \times 2$基本パターン。 正方形は、色とサイズの両方においてフラクタルと正確に一致する必要があります。 

制約$2 \le n, m \le 500$任意のサイズのすべての部分正方形を単純に列挙すると遅すぎると考えられます。 完全なブルートフォースアプローチでは、それぞれのチェックを試みます。$k \times k$あらゆる可能なサイズの正方形$k$2 から 500 まで、セルごとに比較し、到達する可能性があります$O(n^3 m^3)$明らかに法外な操作。 

明らかではないエッジ ケースには、すべてのセルが黒または白である均一な色のグリッド、またはフラクタル パターンが繰り返される可能性があるが、開始位置に小さな正方形が含まれていないグリッドが含まれます。 たとえば、$4 \times 4$真っ白なグリッドは、単一のグリッドを表す 1 を返す必要があります。$4 \times 4$しかし、フラクタルに両方の色が含まれている必要があると想定している場合、単純なパターン チェックではそれを見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての左上隅と正方形のサイズを列挙し、サブ正方形を抽出し、それが次の式から導出できるかどうかを再帰的にチェックすることです。$2 \times 2$基本パターン。 フラクタルは同じパターンを繰り返すことによって構築されるため、これは原理的には機能しますが、実際には次のことが必要になります。$O(n^3 m^3)$比較しても制限時間を超えてしまう$n = m = 500$。 

効率的なソリューションを実現するための重要な洞察は、フラクタルは自己相似であり、その再帰的な構造はハッシュ化またはメモ化を使用してキャプチャできるということです。 それぞれにハッシュを定義すると、$1 \times 1$セルの場合、フラクタル規則に従って 4 つの象限のハッシュを結合することで、より大きな正方形のハッシュを計算できます。 小さな正方形のハッシュがわかれば、それらを一定時間で結合して、$2 \times 2$親、次に$4 \times 4$正方形など。 これにより、すべてのセルを個別に比較することなく、繰り返されるパターンを検出できます。 

サイズごとの正方形のハッシュを保存できます$2^k$テーブル内で、少なくとも 1 つの再帰ステップが上にあるものだけをカウントします。$2 \times 2$、つまりサイズの正方形$2^2 = 4$そしてさらに大きい。 最終的なカウントは、有効なフラクタル ハッシュが表示される左上の位置の数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3 m^3)$|$O(n m)$| 遅すぎる |
 | 最適 (DP + ハッシュ) |$O(n m \log \min(n,m))$|$O(n m \log \min(n,m))$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 個々のセルごとにハッシュを初期化し、「.」をマッピングします。 これらは、より大きな正方形ハッシュの基本ケースとして機能します。 これが機能するのは、フラクタルの最小単位が単一セルであるためです。 
2. 象限を結合する際の衝突を避けるために、行と列のハッシュに対する基数の累乗を事前計算します。 これにより、正方形のハッシュが象限の内容と相対位置の両方に依存することが保証されます。 
3. 2 から始まる 2 のべき乗であるすべての可能な正方形サイズを反復します。各サイズについて$2^k$、前のレベルの 4 つの象限のハッシュを組み合わせて、そのサイズのすべての正方形のハッシュを計算します。$2^{k-1}$。 これらのハッシュを、左上の座標でインデックス付けされた DP テーブルに保存します。 
4. レベルで計算された各ハッシュについて$k \ge 2$、この正方形が少なくとも$4 \times 4$(ベースより上の少なくとも 1 つの再帰ステップを確保します)。 有効な場合は、フラクタル カウントをインクリメントします。 
5. 正方形のサイズがいずれかの方向のグリッドの寸法を超えるまで続行します。 合計数を返します。 

重要な不変条件は、任意のレベルの 2 つの正方形が同じハッシュを持つ場合、それらの内容は同一であるということです。 小さい正方形から大きい正方形を再帰的に構築するため、ハッシュの組み合わせにより一意性が維持され、各セルを複数回検査することなく効率的にフラクタルを検出できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    base = 31
    mod = 10**9 + 7
    
    # Precompute hashes for individual cells
    cell_hash = [[1 if c == '*' else 0 for c in row] for row in grid]
    
    # DP table for squares of size 2^k
    max_k = 1
    while (1 << max_k) <= max(n, m):
        max_k += 1
    
    dp = [cell_hash]
    
    count = 0
    
    for k in range(1, max_k):
        size = 1 << k
        prev = dp[-1]
        new = [[0]*(m - size + 1) for _ in range(n - size + 1)]
        
        for i in range(n - size + 1):
            for j in range(m - size + 1):
                h1 = prev[i][j]
                h2 = prev[i][j + size//2]
                h3 = prev[i + size//2][j]
                h4 = prev[i + size//2][j + size//2]
                
                combined = (h1 * base**3 + h2 * base**2 + h3 * base + h4) % mod
                new[i][j] = combined
                
                if size >= 4:
                    count += 1
        
        dp.append(new)
    
    print(count)

if __name__ == "__main__":
    main()
```このコードは、単一セルのハッシュを初期化し、次に 4 つの象限のハッシュを繰り返し結合して、より大きな正方形のハッシュを計算します。 少なくとも次のサイズの正方形のカウントをインクリメントします$4 \times 4$。 の力`base`異なる象限が結合されたハッシュに明確に寄与するようにします。 モジュロはオーバーフローを防ぎます。
