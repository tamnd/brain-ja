 ## 解決策
 ## 問題の理解

 の配列を構築するように求められます。`n`ビット単位の XOR が正確に一致する正の整数`x`そして配列の合計を最小化します。 配列自体を出力する代わりに、要素の合計を返すように求められます。 入力は複数のテスト ケースで構成され、それぞれがペアを与えます。`(n, x)`どこ`n`は必要な配列の長さであり、`x`はターゲット XOR です。 各テスト ケースの出力は単一の整数、つまり可能な最小合計、または`-1`配列が存在しない場合。 

制約は大きくなります。`n`最大 10^9 までの大きさになる可能性があり、`x`最大 10^9、最大 10^4 のテスト ケースを持つことができます。 これにより、明示的に配列を構築したり、あらゆる可能性を反復処理したり、一定の長さの配列を格納したりするようなソリューションは即座に除外されます。`n`。 代わりに、XOR と正の整数のプロパティを使用して合計について数学的に推論する必要があります。 

明らかではないエッジケースには、次のような状況が含まれます。`n = 1`または`x = 0`。 たとえば、次の場合`n = 1`そして`x = 0`、正の整数で条件を満たすことは不可能なので、出力は次のようにする必要があります。`-1`。 もう一つの微妙なケースは次のような場合です。`n = 2`そして`x = 0`。 2 つの等しい数値の XOR はゼロなので、配列は`[1, 1]`動作して合計を返します`2`。 不注意に実装すると、これらの小さな値を見落とす可能性があります。`n`一般的な公式を誤って仮定します。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての組み合わせを生成しようとします。`n`XOR が等しい正の整数`x`そして最小の合計となる組み合わせを選択します。 小型用`n`そして`x`これは機能しますが、複雑さは指数関数的に増大します。`n`そしてすぐに実行不可能になります。 たとえ`n = 20`、 がある`2^20`考慮すべきサブセット。 

重要な洞察は、合計の最小化と組み合わせた XOR 演算を理解することで得られます。 最も単純な正の整数は次のとおりです。`1`s なので、配列に次の値を入力してみるのが直感的です。`1`そして、最後の 1 つまたは 2 つの要素を調整して、目標の XOR を達成します。 もし`n = 1`、唯一の選択肢は`[x]`もし`x > 0`。 もし`n = 2`、配列は次のようにすることができます`[1, 1 ⊕ x]`もし`x != 0`。 のために`n >= 3`、ほとんどの場合、有効な配列を構築することが常に可能です。`1`XOR を実現するために調整された最大 2 つの要素。 

これにより、テスト ケースごとに O(1) の計算が行われます。 配列を構築する代わりに、合計を直接計算します。 

- のために`n = 1`、合計は`x`もし`x > 0`、 さもないと`-1`。 
- のために`n = 2`、合計は`x + 0`もし`x != 0`、 さもないと`2`。 
- のために`n >= 3`、合計は`x + (n-1)`使えるから`(n-3)`XOR に一致するように調整された 1 と 2 の数値。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`x`。 
3. もし`n = 1`、どうかを確認してください`x > 0`。 「はい」の場合、印刷します`x`最小合計として。 それ以外の場合は印刷します`-1`等しい正の数がないため`0`。 
4. もし`n = 2`、どうかを確認してください`x = 0`。 「はい」の場合、最小合計は次のとおりです。`2`使用して`[1, 1]`。 もし`x > 0`、最小合計は`x + 0 = x`使用して`[1, 1 ⊕ x]`。 
5. もし`n >= 3`、 使用`(n-3)`XOR を調整する 1 と 2 の数値`x`。 これにより、最小の合計が保証されます。 合計は`(n-3) + adjusted pair sum`。 最も単純な式は`(n-1) + x`。 
6. 計算された合計を出力します。 

機能する理由: 複数の XOR を 2 つの数値で簡単に調整して、任意のターゲット XOR を達成できます。 1 より大きい正の整数ごとに合計が増加するため、1 を使用すると合計が最小になります。 のために`n = 1`そして`2`、特殊なケースは、肯定的な制約を尊重するために個別に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    if n == 1:
        print(x if x > 0 else -1)
    elif n == 2:
        if x == 0:
            print(2)
        else:
            print(x + 1)
    else:
        print(x + n - 1)
```最初の条件は単一要素の場合を正しく処理し、ゼロを出力しないようにします。 2 つ目は 2 要素の配列を処理し、ベースとして 1 を使用し、XOR で他の要素を調整します。 最後のケースは、より大きな場合に一般化します。`n`任意の XOR は、最大 2 つの調整された要素を上に置くことで達成できるという洞察を利用します。`1`s. これにより、配列を明示的に構築することが回避されます。

 ## 特殊なケース

 のために`n = 1, x = 0`、アルゴリズムは正しく出力します`-1`。 のために`n = 2, x = 0`、それは出力します`2`に相当する`[1, 1]`。 大型用`n`、式`x + n - 1`配列を反復したり構築したりせずに合計を正しく処理します。 のために`n = 2`そして`x > 0`、合計は`x + 1`これにより、肯定的で正しい XOR が保証されます。 重要な不変条件は、XOR は基本の数値以外に最大 2 つの数値を使用して常に調整できるということです。
