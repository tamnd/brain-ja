 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられ、各要素が元の位置からどれだけ離れているかを測定します。 各位置 i について、そこにある値と i 自体の間の絶対差をとり、これを配列全体で合計します。 これにより、その順列に対する単一の整数スコアが生成されます。 

タスクは、単一の順列に対してこの値を計算することではなく、長さ n の考えられるすべての順列を考慮し、異なる合計スコアがいくつ出現できるかを決定することです。 

重要なオブジェクトは順列そのものではなく、距離に似た尺度の達成可能な値のセットです。 各順列は同じ整数の複数セットを再配置するため、合計はグローバルに可能な変位量によって制限されます。 

この制約により、複数のテスト ケースで最大 500 の n が許可されます。 n = 10 の場合でも、置換の数はすでに 3,628,800 であるため、置換を明示的に列挙する解決策は不可能です。 これにより、ブルートフォース生成が完全に排除されます。 解決策は、これらの絶対的な違いがどのように変化するかという構造的特性に依存する必要があります。 

非常に小さい n では、微妙なエッジケースが現れます。 n = 1 の場合、順列は 1 つだけで、値は常に 0 であるため、答えは 0 ではなく 1 でなければなりません。 n = 2 の場合、取り得る値は 0 と 2 の 2 つだけです。これは、関数が必ずしも連続した整数を生成するわけではなく、それでも構造化セットを形成することを示しています。 

## アプローチ

 強引なアイデアは単純です。すべての順列を生成し、絶対差の合計を計算し、結果をセットに挿入し、そのサイズを返します。 これは定義に直接従うため、正しいです。 ただし、n 回繰り返す必要があります。 順列を作成し、それぞれについて O(n) の合計を計算すると、O(n · n!) の演算が行われます。 これは、n = 10 を超えるとすぐに実行不可能になります。 

重要な観察は、順列を個別に研究しているのではなく、可能な総変位値の範囲を研究しているということです。 式 ∑|p_i − i| は、アイデンティティからの総変位またはスピアマン フットルール距離として知られています。 重要な構造的事実は、要素の交換が制御された増分で合計に影響を及ぼし、達成可能な値のセットが最大値までのすべての偶数を形成し、n に応じたパリティ制約があることです。 

より正確には、最小値は 0 (恒等順列) で、最大値は配列を反転することで得られます。 中間値は、予測可能な段階で合計コストを調整するスワップを使用して、逆順列を徐々に修正することで取得できます。 合計のパリティは n が偶数か奇数かによって決まりますが、それに関係なく、個別の値の数は n にのみ依存し、n における単純な 2 次式に従います。 

最終的な閉じた形状は、要素をどこまで対称的に移動できるかを分析することで導き出すことができます。 位置間の各スワップは合計の制御された変化に寄与し、到達可能なセットは 0 から最大値までの特定のパリティ範囲のすべての整数を埋めます。 これらの値をカウントすると、等差数列の長さをカウントすることになり、最終的な式が得られます。 

偶数 n の場合:

 個別の値の数は n² / 4 + 1 です

 奇数 n の場合:

 個別の値の数は (n² + 3) / 4 です。 

これは統一された式に簡略化されます。 

⌊in² / 4⌋ + 1

 したがって、問題はテスト ケースごとの定数時間の計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | お(ん!) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースの n を読み取ります。 これにより、順列サイズが定義され、取り得る値の全体の構造が決まります。 
2. n × n を計算します。 各位置が合計に最大で O(n) を寄与するため、これは総変位容量のスケールを表します。 
3. 整数除算を使用して、この値を 4 で除算します。 これは、達成可能な値の範囲全体に適合する個別の「ステップ」の数を数えることに対応し、恒等順列に関して対称的です。 
4. 1 を追加して、ゼロ変位順列を含めます。 これにより、恒等置換の値が確実にカウントされます。 

各ステップは、順列距離の構造を単一の算術範囲に圧縮することに直接対応します。 唯一の重要なステップは、到達可能な値がパリティ クラス内の連続したセットを形成していることを認識することです。 

### なぜ効果があるのか

 関数 f(p) は、恒等順列からの総変位を測定します。 2 つの要素を交換すると、制御された段階的な方法で合計が変更され、一連の交換を通じて任意の順列を別の順列に変換できます。 主要な構造特性は、これらのスワップにより、固定間隔内で実現可能なすべての総変位を実現できるが、パリティ制約と一致する増分でのみステップ実行できることです。 その結果、達成可能な値のセットは、0 から始まり最大変位で終わり、パリティ クラスを 1 つだけ含む等差数列を形成します。 この数列の要素を数えると、その長さは n だけに依存して計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(n * n // 4 + 1)
```コードは、派生した閉じた形式を直接実装します。 乗算 n * n は、結果が Python の整数内に収まるため、n が 500 までは安全です。 4 による整数除算は、範囲内で達成可能な値の密度を取得します。 +1 はゼロ値の順列を表します。 

この解決策は、いかなる順列構築も回避し、個別の値の数が n のみに依存するという構造的結果に完全に依存します。 

## 実用的な例

 ### 例 1

 入力:

 n = 2

 すべての順列を評価します。 

| 順列 | f(p) |
 | --- | --- |
 | [1、2] | 0 |
 | [2、1] | 2 |

 個別の値は {0, 2} です。 

n = 2 の場合、式は 2² // 4 + 1 = 1 + 1 = 2 となります。 

これにより、自明ではない最小限のサイズであっても、値は連続した整数ではなく、依然として算術構造に従っていることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースは単一の算術計算です。 
| スペース | お(1) | 変数以外の補助構造はありません |

 計算はテスト ケースごとに一定時間であり、最大値 t = 100 であっても容易に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(n * n // 4 + 1))
    return "\n".join(out)

# provided samples
assert run("5\n2\n3\n8\n15\n43\n") == "2\n3\n17\n57\n463"

# minimum size
assert run("1\n1\n") == "1"

# small even/odd comparison
assert run("2\n2\n3\n") == "2\n3"

# larger boundary
assert run("1\n500\n") == str(500 * 500 // 4 + 1)
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n = 1 | 1 | 単一順列のエッジ ケース |
 | n = 2,3 | 2,3 | 最小の自明ではない構造 |
 | n = 500 | 62501 | 最大制約の処理 |

 ## 特殊なケース

 n = 1 の場合、順列は 1 つだけです。 このアルゴリズムは 1 * 1 // 4 + 1 = 1 を計算し、唯一の達成可能な値 0 を正しくカウントします。 

n = 2 の場合、計算では 4 // 4 + 1 = 2 が得られます。2 つの順列により値 0 と 2 が生成され、予測と一致します。 

500 などの大きな n の場合、Python ではオーバーフローの問題が発生することなく、式が直接適用されます。 この構造は列挙や組み合わせ生成に依存しないため、パフォーマンスは一定に保たれます。 

これらのケースは、最小入力と最大入力の両方が同じ算術式によって均一に処理されることを確認します。
