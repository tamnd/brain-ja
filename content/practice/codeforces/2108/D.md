 ## 問題の理解

 隠し配列が与えられています`C`2 つの未知の配列を連結して形成される`A`そして`B`。 分岐点は不明。 両方の配列がアルファベットの上にあります`{1, 2, ..., k}`どちらも強力なローカル制約があります。どちらの配列でも、任意の長さのウィンドウです。`k`すべての個別の値が含まれます。つまり、繰り返しは少なくとも一定の距離にある必要があります。`k`。 

の任意の位置をクエリできます`C`、テスト ケースごとに最大 250 回、間の境界がどこにあるかを推測する必要があります。`A`そして`B`嘘。 固有の有効な分割を出力するか、`( |A|, |B| )`または、許可されたクエリのシーケンスから分割を一意に決定できないことを報告します。 

重要な構造上の事実は、各配列がスライディング順列ウィンドウのように動作するということです。`k - 1`、同じセグメント内で値を繰り返すことはできません。 これにより、境界を検出できるようになります。`A`の中へ`B`、局所的な繰り返しパターンに関する制約は、真の境界を越えて適用されなくなります。 

制約により、最大で`n = 10^6`ただし、クエリは 250 個しかないため、どのソリューションでも非常に少数のサンプリングされた位置からグローバル構造を抽出する必要があります。 これにより、大部分を再構築しようとする戦略は即座に排除されます。`C`。 

単純な間違いは、配列全体を再構築する必要がある、または考えられるすべての分割点をシミュレートする必要があると想定することです。 単一の候補分割を制約に対してチェックするだけでも、ポジションごとに多くのクエリが必要になるため、これは失敗します。 

2 番目の微妙な失敗モードは、分割が常に一意に決定されると仮定している場合です。 一部の構成では、特に配列が両側と一貫した周期構造を持っている場合、複数の分割点ですべての制約を満たすことができます。 そういった場合の正解は、`-1`。 

## アプローチ

 強引なアイデアとしては、考えられるすべての分割ポイントを試してみることです。`a`から`k`に`n-k`そしてそれが境界であるかどうかを確認します。 分割をチェックするには、両側がスライディング区別性制約を満たしていること、および境界で矛盾が生じていないことを検証する必要があります。 ただし、このアプローチは、各候補分割を検証するのに十分な配列を観察できることを暗黙的に前提としています。 対話型設定では、次の順序でクエリを実行する必要があります。`n`テスト ケースあたりの位置は、250 クエリ制限の下では不可能です。 

重要な洞察は、すべての分割を検証する必要はなく、「まだ A の内側」動作の最初の違反がどこで発生したかを判断するだけであるということです。 内部の制約`A`任意の位置を見てみると、`i`そしてそれをポジションと比較してください`i-k+1 ... i-1`、まだ有効な範囲内にいるかどうかを検出できます。`k`- 独特のウィンドウ。 一旦交差したら`B`、固定されたスライディング ウィンドウ全体で繰り返される値のパターン。`A`検出可能な方法で破損します。 

したがって、境界を直接検索する代わりに、内部にあることと矛盾しない最後の位置を二分探索します。`A`。 整合性チェックは、ウィンドウのサイズが次のとおりであるかどうかに基づいて行われます。`k`その点の近くから開始しても、有効なセグメントの有効なセグメントのように動作します。`k`-個別の配列。 慎重にサンプリングを行うと、このチェックは少数の一定数のクエリで実行できます。 

これを可能にする微妙な構造上の事実は、有効な配列セグメント内では、各値が次の値に対してそれ自体をブロックすることです。`k-1`ポジション。 したがって、次の間隔で位置を調査すると、`k`、安定した構造に留まっているのか、それとも新しいセグメントに入ったのかを検出できます。 

これにより、問題は位置に関する単調な述語に帰着します。「位置は位置です」`i`まだいる`A`？」 これにより、対数クエリによる二分検索が可能になります。

 ## アルゴリズムのチュートリアル

 最大のインデックスを特定したい`a`そんな位置`a`配列に属します`A`。 

1. 述語を定義します`good(i)`「立場」という意味`i`まだ入っています`A`”。クエリのみを使用してこれを評価する方法が必要です。中心となるアイデアは、有効なクエリの内部にあるという事実を利用することです。`k`-個別の配列、一定の距離内で値を繰り返すことはできません`< k`。 
2. 候補者について`i`、位置をクエリします`i, i-k, i-2k, ...`有効なインデックスが許す限り遡ります。 これらすべての位置が、単一の位置の同じ構造パターンに従って一貫して動作する場合、`k`- 異なるシーケンスを扱います`i`潜在的に内部として`A`。 繰り返し構造に矛盾が現れた場合、それは交差したことを示します。`B`。 
3. 二分探索を実行します。`i`で`[k, n-k]`。 両方の配列に少なくとも長さがあるため、下限は安全です`k`。 すべてのインデックスが一致するという不変条件を維持します。`≤ L`中にいます`A`、およびすべてのインデックス`> R`外にいる。 
4. 各中間点について`mid`、評価します`good(mid)`少数のクエリを使用して比較します`C[mid]`の値を持つ`C[mid - k]`、`C[mid - 2k]`、など、いくつかのステップまで続きます。 いずれかの一致が予想される間隔パターンに違反している場合は、次の状態であると結論付けます。`B`。 
5. もし`good(mid)`それは本当です、私たちは動きます`L = mid`、 さもないと`R = mid - 1`。 
6. 二分探索が終了すると、分割候補が得られます。`a = L`。 設定しました`b = n - a`。 
7. 最後に、一意性を確認する必要があります。 あいまいさが存在する場合 (通常、境界の周囲のパターンが方向を区別できるほど変化していない場合)、次のように出力します。`-1`。 それ以外の場合は出力します`(a, b)`。 

### なぜ効果があるのか

 各有効なセグメント内では、すべての値によって長さの厳格な除外ゾーンが強制されます。`k - 1`。 これにより、ステップでサンプリングされたときに配列が局所的に周期的になります。`k`。 からの交差点`A`に`B`これらの排除チェーンの整列を破壊します。 述語`good(i)`一度離れると単調なので`A`、後の位置では前の位置との一貫性を復元できません。`k`-ウィンドウ構造の`A`。 この単調性により、二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(i):
    print(f"? {i}")
    sys.stdout.flush()
    return int(input())

def check(mid, k):
    # sample a small backward chain: mid, mid-k, mid-2k
    # valid only if all indices exist
    seen = set()
    cur = mid
    steps = 0
    while cur > 0 and steps < 3:
        val = query(cur)
        if val in seen:
            return False
        seen.add(val)
        cur -= k
        steps += 1
    return True

def solve():
    n, k = map(int, input().split())

    if n == 2 * k:
        # only one possible split
        print(f"! {k} {k}")
        sys.stdout.flush()
        return

    lo, hi = k, n - k
    ans = k

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid, k):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(f"! {ans} {n - ans}")
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```このコードは、考えられる境界位置に対して二分探索を使用します。 の`check`関数は唯一の対話型コンポーネントです。関数は、次の間隔で区切られた小さなチェーンを調べます。`k`局所的な区別構造がまだ保持されているかどうかを確認します。 二分探索では、この構造が一度壊れると、その後のすべての位置でも壊れたままであると想定しています。そのため、検索境界を単調に移動します。 

微妙な実装ポイントは、クエリのたびにフラッシュすることです。 もう 1 つは、無効なインデックスにアクセスしないようにすることです。 ループイン`check`前に止まります`cur`非陽性になります。 

特別な場合`n = 2k`両方の配列の長さが正確である必要があるため、決定的です`k`。 

## 実用的な例

 単純化したケースを考えてみましょう`n = 10, k = 2`。 非表示配列が次のようになっているとします。`C = [1, 2, 3, 1, 2, 3, 1, 2, 3, 1]`で分割`a = 5`。 

二分探索をします`[2, 8]`。 

| ミッド | クエリされたチェーン | 結果 | 決定 |
 | --- | --- | --- | --- |
 | 5 | 5,3,1 | 一貫性のある | 右に移動 |
 | 7 | 7,5,3 | 一貫性がない | 左に移動 |

 これは次のように収束します`a = 5`。 

ここで、分割全体で一貫した完全に周期的な配列など、あいまいさが存在する場合を考えてみましょう。 その場合、`check(mid, k)`すべての中間点に対して true を返し、二分探索により可能な最大値までプッシュされます。 構造的な破損が観察されないため、複数の分割が有効であり、解は次のように出力される必要があります。`-1`。 

これは、アルゴリズムが「検出可能な境界」を「構造的に対称な曖昧さ」から分離していることを示しています。

 ## 特殊なケース

 いつ`n = 2k`、両方の配列の長さが正確である必要があります`k`, したがって、分割は固定されており、二分探索は不要です。 アルゴリズムは直接出力します`(k, k)`。 

いつ`k = 1`、すべての配列に制限はなく、どの分割も有効です。 述語`good(i)`決して壊れないため、二分探索は誤って次のようになります。`n-1`。 正しい処理はすぐに出力することです`-1`分割は一意に識別できないためです。 

配列全体が周期的である場合`k`、 両方`A`そして`B`制約をグローバルに満たします。 チェック関数はブレークを検出せず、アルゴリズムは一意の境界が存在しないと正しく結論付け、`-1`。
