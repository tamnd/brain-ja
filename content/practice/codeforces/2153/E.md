 ## 問題の理解

 任意の基底で階乗の末尾のゼロを処理するように求められます。 具体的には、任意の整数に対して$x\ge 1$そしてベース$k\ge 2$、$v_k(x!)$何回数えますか$k$分割する$x!$。 素数基数の場合、これは簡単です。次の整数の除算を合計します。$x$～の力によって$p$。 複合ベースの場合、係数$k$を素数に分割し、階乗素数累乗の指数による階割りの最小値を取得します。 

次に、2 つの階乗の間の重みを定義します。$(a!, b!)$ベース用に$k$どちらかとして$\min(v_k(a!), v_k(b!))$等しくない場合は任意の大きな数、等しい場合は任意の大きな数。 機能$f_m(a, b)$すべての最小重量です$k$2から$m$。 最後に、次の合計を計算する必要があります。$f_m(x, n)$みんなのために$x < n$。 

制約を考慮すると$2 \le n \le m \le 10^7$最大 100 のテスト ケース、すべてのベースをチェックする単純なアプローチ$k$あらゆる人にとって$x$おおよそ必要になります$10^{14}$最悪の場合は操作が不可能になります。 各階乗ペアのすべての基数の反復を回避する方法が必要です。 

階乗の多くの基底で同じ末尾のゼロが付いている場合、明らかではないエッジ ケースが発生します。 たとえば、連続する階乗は小さな素数の同じ累乗を持つことが多いため、間違った基数を選択すると、誤って大きな素数にヒットしてしまう可能性があります。$10^{100}$重さ。 正しく処理するには、カウントが異なる最初の塩基を特定する必要があります。$n$の素因数で発生します$n$。 

## アプローチ

 ブルートフォース手法では、すべてのプロセスを反復処理します。$x < n$そしてすべての$k \le m$、計算する$v_k(x!)$そして$v_k(n!)$それぞれに$k$、次に、カウントが異なる最小重量を取得します。 これは正しいですが、スケールは次のようになります$O(n \cdot m \cdot \text{log } n)$が遅すぎます。$n, m \sim 10^7$。 対数因数は、標準的な公式を使用して素数の階乗を計算することで得られます。 

重要な洞察は、次のことを観察することによって得られます。$v_k(n!)$モノトーンです$n$あらゆる固定ベースに対応$k$、そしてそれ$w_k(x, n)$場合のみ重要です$v_k(x!) \neq v_k(n!)$。 以来$v_k(x!)$は減少していない$x$、最小重量が発生するのは次の場合です。$v_k(x!)$まず違うのは$v_k(n!)$。 さらに、すべての素因数を考慮すると、$n$を使用すると、どの塩基が最小の重みを生成するかを正確に判断できます。 与えられた素数に対して$p$、$v_p(n!) - v_p(x!)$回数を数えます$p$の間で数値を除算します$x+1$そして$n$。 これにより、抜本的なアプローチが可能になります。素数ごとに、その寄与を、素数からの距離に基づいて累積和に加算します。$n$、複雑さがほぼ線形に軽減されます。$n$さらに素因数分解のオーバーヘッド。

 ## アルゴリズムのチュートリアル

 1. 最大値までのすべての素数を事前計算します。$m$エラトステネスのふるいを使用したテストケース全体。 これにより、任意の数値の因数分解が可能になります。$O(\log n)$素数上の試算除算を使用した時間。 
2. 各テストケースの係数$n$その主な要因に$p_i$指数付き$e_i$。 これらの素数は、他の基数がゼロ以外の寄与を生成できる唯一の基底です$v_k(x!) = v_k(n!) = 0$のために$x < n$。 
3. 配列を初期化する`contrib`サイズの$n$それぞれの最小重量を保存するには$x$未満$n$。 ゼロから始めてください。 
4. 各素因数について$p_i$、から逆方向に反復します$n-1$～1.それぞれについて$x$、何回かを計算します$p_i$の間で数値を除算します$x+1$そして$n$。 この値を追加します`contrib[x]`。 
5. すべての素因数を処理した後、配列は`contrib`含まれています$f_m(x, n)$みんなのために$x < n$。 配列を合計して最終結果を生成します。 
6. 各テスト ケースの合計を出力します。 

効果がある理由: それぞれ$v_k(x!)$素数の割り算のみに依存する$k$。 最初の塩基だけが必要なので、$v_k(x!) \neq v_k(n!)$、素数の割り算のみ$n$ゼロ以外の貢献を生み出す可能性があります。 これらの素数をスイープすることにより、すべての素数の最小重みが正しく累積されます。$x < n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(max_n):
    is_prime = [True]*(max_n+1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(max_n**0.5)+1):
        if is_prime[i]:
            for j in range(i*i, max_n+1, i):
                is_prime[j] = False
    primes = [i for i, val in enumerate(is_prime) if val]
    return primes

primes = sieve(10**7)

def prime_factors(n):
    factors = {}
    x = n
    for p in primes:
        if p*p > x:
            break
        if x % p == 0:
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            factors[p] = cnt
    if x > 1:
        factors[x] = 1
    return factors

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    factors = prime_factors(n)
    contrib = [0]*(n)
    for p, e in factors.items():
        val = 0
        k = p
        while k <= n:
            for i in range(k, n, k):
                contrib[i] += 1
            k *= p
    print(sum(contrib[1:]))

内側のループは、次の式を反映して、素数のべき乗の倍数に対応する位置のみを注意深くインクリメントします。$v_p(n!) - v_p(x!)$。 無関係な拠点への接触を避け、効率を確保します。
