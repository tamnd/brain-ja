 ## 解決策
 ## 問題の理解

 うちには本が３段積まれています。 各スタックには以下が含まれます`n`本を上から下に並べます。 どの本にも負ではない整数が書かれています。 

テンジンは次の知識から始まります`0`。 彼が価値のある本を読むときはいつでも`v`、彼の知識は`knowledge | v`、 どこ`|`はビット単位の OR 演算です。 

この制限はスタック構造に起因します。 Tenzing はスタックの現在の一番上のブックのみを読み取ることができます。 読み終えると、その本は消えて、次の本が手に入るようになります。 彼はいつでもスタックを切り替えることができ、必要に応じていつでも停止することができます。 

目標は、一連の読み取りによって最終的な知識が次の内容とまったく同じになるかどうかを判断することです。`x`。 

入力には複数のテスト ケースが含まれています。 テストケースごとに目標値を受け取ります`x`そして3つのスタック。 アウトプットしなければなりません`"Yes"`有効な読み取りシーケンスが正確に到達した場合`x`、 さもないと`"No"`。 

すべての合計`n`入力全体の値は最大でも`10^5`。 これは、テスト ケースごとに線形または線形に近いソリューションが必要であることを直ちに示唆しています。 多くの異なる読み取り順序を試したり、OR 値の状態を調査したりするアプローチは、すぐに実行不可能になります。 

この問題の最も危険な部分は、ビットごとの OR の不可逆的な性質です。 一度少しになると`1`、決して元に戻ることはできません`0`。 単純な実装では、本に存在しないビットを紹介する書籍が誤って許可されてしまう可能性があります。`x`たとえそのような動きは永久に到達することになりますが、`x`不可能。 

次の例を考えてみましょう。```
n = 1, x = 2

Stack A: 3
Stack B: 0
Stack C: 0
```値`3`ビットが含まれています`11₂`、 その間`x = 2`は`10₂`。 読む`3`に属さない余分なビットを導入します`x`、したがって、答えは次のとおりです`"No"`。 

もう 1 つの微妙なケースは、いつでも停止できるということです。```
n = 1, x = 0

Stack A: 5
Stack B: 7
Stack C: 9
```正しい答えは、`"Yes"`ゼロ本を読むことは許されているからです。 

3 番目のよくある間違いは、アクセス可能な本はすべて読まなければならないと考えることです。```
n = 2, x = 1

Stack A: 1 2
Stack B: 0 0
Stack C: 0 0
```すでに生成されているスタック A の最初のブックのみを読み取る`1`。 さらに読むと価値が生まれます`3`、それは間違いです。 停止は許可されているため、答えは次のようになります。`"Yes"`。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての読み取りシーケンスが試行されます。 すべてのステップで、現在空ではないスタックまたは停止の 1 つを選択できます。 各スタックを独立して進めることができるため、可能なシーケンスの数は指数関数的に増加します。 控えめな値であっても、`n`、可能性の数は膨大になります。 

ブルートフォースのアイデアは、有効な読み取り順序をすべて明示的に調査し、最終的な OR が等しいかどうかをチェックするため、正しいです。`x`。 問題は、`n`まで`10^5`全体として、そのような探査は完全に不可能です。 

重要な観察は、いつ本が安全に読めるかを調べることから得られます。 

現在の知識が`cur`。 本に存在しないビットが本に含まれている場合、`x`、その後、OR 演算を実行すると、そのビットは永久に残ります。 正確に届く`x`不可能になります。 

つまり、私たちがこれまでに読んだすべての本は次の条件を満たしている必要があります。```
(book | x) = x
```同様に、ブックに設定されているすべてのビットはすでに`x`。 

次にスタックを上から下に見てみましょう。 禁じられた部分が含まれている本に出会うと、私たちはその本を決して読むことができなくなります。 その下にあるすべての書籍へのアクセスがブロックされるため、そのスタックの残りの部分全体が使用できなくなります。 

これにより、非常に単純な特徴が得られます。 

各スタックについて、本を上から読みますが、そのビットは次のサブセットです。`x`。 このようなすべての値を OR してグローバルな結果にします。 無効な本を見つけた瞬間に、そのスタックの処理を停止します。 

アクセス可能な有効な書籍すべてに OR を実行するのが安全なのはなぜですか? OR はビットを追加するだけだからです。 アクセス可能なすべての有効な書籍には、以下に属するビットが含まれています。`x`そして、そのような部分をスキップする理由は決してありません。 アクセス可能な有効な本からビットを取得できる場合、それを最後の OR に含めることは、到達するのに役立つだけです`x`。 

3 つのスタックすべてを処理した後、累積された OR を次のようにします。`ans`。 

もし`ans == x`そうすると、アクセス可能な有効な書籍を正確に読み、到達する順序を選択できます。`x`。 それ以外の場合は、少し`x`決して取得できなかったので、答えは`"No"`。

 ## アルゴリズムのチュートリアル

 1.初期化`ans = 0`。 
2. 3 つのスタックのそれぞれを上から下に個別に処理します。 
3. 現在の簿価について`v`、設定されているすべてのビットが以下に属しているかどうかを確認します。`x`。 

これは以下をチェックすることと同じです。```
(v | x) == x
```4. チェックが成功した場合、OR で本を答えに導きます。```
ans |= v
```このような本は、決して禁じられた内容を紹介していないため、安全に読むことができます。 
5. チェックが失敗した場合は、このスタックの処理を直ちに停止します。 

まず上部から本を削除する必要があるため、その下にある本にはアクセスできません。 
6. 3 つのスタックすべてが処理された後、比較します。`ans`と`x`。 
7. 出力`"Yes"`もし`ans == x`、それ以外の場合は出力`"No"`。 

### なぜ効果があるのか

 ちょっとした外のことを書いた本`x`有効な読み取りシーケンスに出現することはできません。 これを読み取ると禁止ビットが永続的に設定され、最終的な値が`x`そのビット位置で。 

したがって、すべてのスタックについて、有効な書籍の最大のプレフィックスのみにアクセスできます。 ブロックしているブックは削除できないため、最初の無効なブック以降のブックにはアクセスできません。 

このアルゴリズムは、有効なシーケンスに参加する可能性のあるすべての本の OR を計算します。 結果の OR が次の場合`x`、その後、すべてのビット`x`が取得可能であり、禁止ビットは表示されません。 それらの本を読むと正確に結果が得られます`x`。 

結果の OR に一部のビットが欠けている場合は、`x`の場合、アクセス可能な本にはその部分が含まれていません。 どのような読書戦略もそれを生み出すことはできません。`x`不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())

        stacks = [
            list(map(int, input().split())),
            list(map(int, input().split())),
            list(map(int, input().split()))
        ]

        ans = 0

        for stack in stacks:
            for v in stack:
                if (v | x) == x:
                    ans |= v
                else:
                    break

        print("Yes" if ans == x else "No")

if __name__ == "__main__":
    solve()
```解決策は証明に直接続きます。 

条件`(v | x) == x`すべてのビットが設定されているかどうかをチェックします`v`にも設定されています`x`。 これは問題に対する批判的な観察です。 他の条件を使用すると、本で禁止されているビットが紹介されているケースを見逃す傾向があります。 

の`break`も同様に重要です。 無効な本が現れると、そのスタックは永久にブロックされます。 以下の本の検査を続けると、それらが到達可能であると誤って想定されてしまいます。 

変数`ans`アクセス可能なすべての有効な書籍の OR を保存します。 OR は結合的かつ可換であるため、最終的な値には正確な読み取り順序は関係ありません。 

Python の整数は、すべての数値が最大値であるため、関係する値を簡単に処理できます。`10^9`。
