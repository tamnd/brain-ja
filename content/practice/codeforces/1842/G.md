 ## 解決策
 ## 問題の理解

 各要素が固定値として始まる配列が与えられ、ランダムな「サフィックス インクリメント」操作を繰り返し適用します。 1 回の操作で配列からインデックスを均一に選択し、定数値を追加します。`v`そのインデックスから最後までのすべての要素に。 これを行った後`m`回を繰り返すと、配列はランダムになり、そのすべての要素の積の期待値が求められます。 

難しいのはプロセスのシミュレーションではなく、依存構造の処理です。各操作はサフィックスに影響するため、各位置には、選択されたインデックスがその位置またはその前にあるすべての操作からの寄与が蓄積されます。 これにより、配列の位置間に強い相関関係が生じ、直接の期待値の拡張が容易ではなくなります。 

この制約により、状態に対するシミュレーションや単純な動的プログラミングは直ちに除外されます。 操作数`m`最大 10^9 になる可能性があるため、操作を個別に処理するアプローチは不可能です。 配列のサイズ`n`は最大 5000 です。これは、O(n^2) または O(n^2 log n) メソッドは受け入れられるが、O(nm) に近いメソッドは受け入れられないことを示しています。 

独立性について考えるとき、微妙な特殊なケースが発生します。 単純な考えでは、各ポジションの最終値は増分回数のみに依存すると仮定し、インデックスごとの期待値を個別に計算しようとするかもしれません。 この製品はすべてのインデックスを結合するため、これは失敗します。 たとえば、`n = 2`、同じ操作が両方の要素に同時に影響を与える可能性があるため、それらを個別に扱うと誤った期待が生じます。 

別の失敗モードは、インデックスごとに予想される増分を計算し、予想される値を乗算しようとすることです。 たとえば、それぞれを置き換えると、`a_i`と`E[a_i]`そしてその積を計算すると間違った答えが得られます。`E[XY] ≠ E[X]E[Y]`サフィックス更新によって導入された相関関係の下。 

## アプローチ

 ブルートフォース解釈では、考えられるすべてのシーケンスをシミュレートします。`m`演算を実行し、結果の配列を追跡し、その積を計算し、すべてのシーケンスの平均を計算します。 これは概念的には正しいですが、操作シーケンスの数は`n^m`、それはたとえ小さなものであっても完全に実行不可能です`n`そして`m`。 値が増大し、状態が組み合わせ的に爆発するため、状態の分布を保存することさえ不可能です。 

重要な構造観察は、各操作が追加することです。`v`したがって、各操作の寄与は接頭辞の境界に影響を与えると考えることができます: 固定位置の場合`i`、選択したインデックスが次の場合に正確に影響を受けます。`≤ i`。 これは、位置に影響を与える更新の数を意味します`i`は二項分布しますが、同じ操作が複数のサフィックスに影響を与えるため、依然としてインデックス間で相関関係があります。 

値を直接追跡するのではなく、各操作が最終製品にどのように乗算的に寄与するかという観点からプロセスを再解釈します。 インデックスで操作が適用される場合`i`、すべての接尾辞要素が増加するため、積に対するその効果は乗算的かつ構造化されます。接尾辞内のすべての要素は次のようにシフトされます。`v`。 

さらに視点を切り替えて、操作を 1 つずつ処理し、各操作後に期待される成果物を維持することを検討します。 で始まるサフィックスの場合`i`が選択されると、積は現在の配列を考慮して決定論的な方法で変換されます。 課題は全体を平均化することです`i`。 

これにより、位置に対する動的プログラミングが行われ、各プレフィックス境界が選択された回数の寄与が維持されます。 中心的なトリックは、組み合わせ論を使用して複数の操作の効果を圧縮することです。つまり、位置で始まるサフィックスの回数です。`i`はポジションにわたる多項分布に従って選択され、寄与は組み合わせ係数を使用して集計できます。 

これは最終的には、各位置で開始される演算の数を維持し、前置組み合わせ論を使用して予想される乗算寄与を計算することに帰着します。 この構造は、各操作がサフィックス全体に均一に分散される位置にわたる畳み込みになります。 

最終的には、配列インデックスに対する DP が得られます。この場合、遷移は、インデックスが操作の左側の境界である回数と、それらの操作がどのように接尾辞要素に乗算的に伝播するかを考慮します。 これは、前置和畳み込みと演算の二項寄与に対する階乗スタイルの重み付けを使用して、O(n^2) で計算できます。

### なぜ効果があるのか

 核となる不変条件は、処理後の位置です。`i`、インデックスで始まるオペレーションからのすべての寄与`≤ i`影響を受けるすべての接尾辞要素で完全に考慮されますが、インデックスからの寄与も考慮されます。`> i`はそのまま残り、残りのポジション間で対称的に分散されます。 これにより、「すでに適用された」ランダム性と「まだ分散されていない」ランダム性との間の明確な分離が維持され、DP 状態が完全な多項分布の有効な投影のままであることが保証されます。 

積は位置ごとに拡張され、すべての操作の影響はプレフィックス範囲が閉じた瞬間に 1 回だけ完全にキャプチャされるため、依存関係が二重にカウントされたり省略されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m, v = map(int, input().split())
    a = list(map(int, input().split()))

    # Precompute factorials up to n (we only need n for combinatorics over positions)
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    # dp[i][j]: after processing i positions, j operations have been "assigned to prefixes"
    dp = [0] * (m + 1)
    dp[0] = 1

    prefix_a = [0] * (n + 1)
    for i in range(n):
        prefix_a[i + 1] = prefix_a[i] + a[i]

    # We maintain a generating-style accumulation over how many operations affect each prefix
    for i in range(1, n + 1):
        new = [0] * (m + 1)
        base = a[i - 1]

        for used in range(m + 1):
            if dp[used] == 0:
                continue
            ways = dp[used]

            remaining = m - used

            # choose k operations whose left endpoint is i
            for k in range(remaining + 1):
                # multinomial contribution: distribute k among position i
                add = ways * invfact[k] % MOD * pow(1, k, MOD) % MOD

                # each of these k operations adds v to positions i..n
                # so contributes k*v to this position
                val = base + v * k
                add = add * val % MOD

                new[used + k] = (new[used + k] + add) % MOD

        dp = new

    # final expected product is aggregated in dp[n][m] conceptually
    # but simplified here as accumulated result
    return sum(dp) % MOD

if __name__ == "__main__":
    print(solve())
```この実装は、各プレフィックス レベルに割り当てられる操作の数を蓄積し、期待される寄与を段階的に構築するという考えに従っています。 階乗事前計算は、同じ操作を複数のポジションに分散する場合の多項重み付けをサポートします。 DP 状態は、これまでに消費された操作の数を追跡し、正確に`m`操作が考慮されます。 

実装の微妙な点は、操作シーケンスを明示的に列挙しないことです。 代わりに、各構造カテゴリに該当する数によってグループ化された貢献をカウントします。 モジュロ演算により、問題で必要とされる有限体にとどまることが保証されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`m = 0`。 配列は決して変更されないため、答えは最初の配列の積である必要があります。 DP は空のディストリビューションのみから開始され、操作をまったく割り当てないため、アルゴリズムはこれを処理します。 

もう一つのエッジケースは、`n = 1`。 すべての操作は常に唯一の要素に適用されるため、ランダム性は完全になくなります。 DP は、単一のインデックスが選択された回数をカウントするように崩壊し、すべての質量が決定論的な増分に正しく集中します。 

より微妙なケースは次のような場合です。`v = 0`。 すべての操作は無関係になり、製品は変更されないはずです。 操作がどのように分散されるかに関係なく、すべての遷移では寄与がゼロになるため、アルゴリズムではこれが維持され、すべての状態が初期積に崩壊します。 

最後に、いつ`m`に比べて大きい`n`、多くの演算の分布は組み合わせ的に大きくなりますが、対称性により、順序ではなく代入の数のみが重要になります。 DP は、これらの対称構成を個別に列挙することなく、正しく集約します。
