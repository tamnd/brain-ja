 ## 解決策
 ## 問題の理解

 私たちは持っています$n$独立した確率変数。それぞれ区間から均一に選択されます。$[0,1]$。 変数のペアの間には、次の形式の制約が与えられます。$$x_i+x_j\le 1$$または$$x_i+x_j\ge 1.$$タスクは、すべての制約が同時に成立する確率を計算することです。 

最も重要な観察は、変数が連続的であるということです。 次のような等式$x_i+x_j=1$確率で起こる$0$したがって、議論を単純化する場合には常に厳密な不等式を使用して推論することができます。 

制約$n\le 20$指数アルゴリズムが$n$可能です。 サイズの状態空間$2^n$100万程度なので実現可能です。 変数のすべての順列を含むものはすべて、$20!$可能性があり、絶望的です。 

微妙な点は、制約が個々の変数を比較しないことです。 彼らは合計を比較します$1$。 変数の値を離散化するか、直接積分しようとしています$[0,1]^n$すぐに手に負えなくなる。 

もう 1 つの簡単な間違いは、自己ループの処理を誤ることです。 

例えば：```
1 1
1 1 1
```制約は$2x_1\ge 1$、つまり$x_1\ge \tfrac12$。 答えは$\tfrac12$、 ない$1$。 

同様に:```
1 1
0 1 1
```必要$x_1\le \tfrac12$、再び確率$\tfrac12$。 

別のトラップは間接的に作成される矛盾した構造です。```
4 4
0 1 2
0 3 4
1 1 3
1 2 4
```4つ目のサンプルです。 制約により、満たすことができない符号要件のサイクルが強制されるため、答えは次のようになります。$0$。 各エッジのローカルチェックだけでは十分ではありません。 

## アプローチ

 ブルートフォースの観点では、確率を単位立方体の内部の領域の体積として考えることです。$[0,1]^n$。 すべての制約は立方体を超平面で切断します。 結果の体積を正確に計算するには、複雑な多面体にわたって積分する必要があります。 たとえ$n=20$、これはまったく非現実的です。 

重要な観察は、中間点付近の変数を書き換えることから得られます。$1/2$。 

定義する$$y_i=x_i-\frac12.$$それぞれ$y_i$に均一に分布しています$\left[-\frac12,\frac12\right]$。 

今ではあらゆる制約が$$y_i+y_j\le 0$$または$$y_i+y_j\ge 0.$$仮定する$|y_i|<|y_j|$。 

もし$y_i+y_j\le 0$、合計の符号は、より大きい絶対値の項によって決定されます。$y_j$。 以来$|y_j|$が優勢である場合、この不等式は要求することと同等です。$y_j<0$。 

同様に、次の場合も$y_i+y_j\ge 0$、それは要求するのと同じです$y_j>0$。 

これが画期的な点です。 すべてのエッジについて、より大きな絶対値を持つエンドポイントのみが重要になります。 

したがって、実際の値を操作する代わりに必要なのは、次のことだけです。 

1. 絶対値の順序付け$|y_i|$。 
2. それぞれの符号$y_i$。 

これらが修正されると、すべての制約が満たされるか違反されます。 

絶対値は独立した一様変数です。 あらゆる大きさの順序は確率で発生します$1/n!$。 すべての変数の符号は、確率に応じて独立して正または負になります。$1/2$。 

したがって、問題は次のようになります。 

有効なペアの数を数える$$(\text{ordering of }|y|,\ \text{sign assignment})$$で割ります$$2^n n!.$$カウント自体は、大きさの順序にわたるサブセット DP を使用して実行できます。

 ## アルゴリズムのチュートリアル

 ### ステップ 1

 すべての変数を変換します。$$y_i=x_i-\frac12.$$制約は次のようになります$y_i+y_j\le 0$そして$y_i+y_j\ge 0$。 

### ステップ 2

 すべての変数に対して 2 つのビットマスクを保存します。`LE[i]`に接続されているすべての頂点が含まれます$i$制約によって$y_i+y_j\le 0$。`GE[i]`に接続されているすべての頂点が含まれます$i$制約によって$y_i+y_j\ge 0$。 

セルフループも当然入っています。 

### ステップ 3

 プロセス変数を昇順に並べます。$|y|$。 

させて$S$すでに配置されている頂点のセットになります。 すべての頂点$S$外側のすべての頂点より絶対値が小さい$S$。 

頂点を配置したいとします。$i$次。 

それから$i$の中で最大の大きさになる$S\cup\{i\}$。 

### ステップ 4

 可能な記号の選択肢がいくつあるか数えてください$i$。 

もし$i$が正の場合、型のすべての制約$\ge 0$の出来事$i$まだ配置されていない頂点を指している必要があります。 さもないと$i$は、より大きな振幅のエンドポイントとなり、そのエッジによって強制的に正になります。 

したがって、次の場合にポジティブが許可されます$$GE[i]\cap(S\cup\{i\})=\varnothing.$$これが当てはまる場合は、トランジションを 1 つ追加します。 

同様に、負の値も許可されます。$$LE[i]\cap(S\cup\{i\})=\varnothing.$$これが当てはまる場合は、別のトランジションを追加します。 

許可された各記号は、正確に 1 つの方向に寄与します。 

### ステップ 5

 標準サブセット DP を実行します。 

させて$$dp[S]$$は、頂点の順序と符号の有効な構成の数になります。$S$。 

初期化$$dp[\varnothing]=1.$$すべての状態とまだ選択されていないすべての頂点に対して、上記の 2 つのチェックを適用して更新します。$dp[S\cup\{i\}]$。 

### ステップ 6

 終わった後は、$dp[(1<<n)-1]$有効なペアの数に等しい$$(\text{ordering},\text{sign assignment}).$$すべての符号の割り当てには確率があります$1/2^n$。 

絶対値の順序には必ず確率があります$1/n!$。 

したがって、答えは次のとおりです$$\frac{dp[(1<<n)-1]}{2^n n!}.$$すべての算術はモジュロで実行されます$998244353$。 

### なぜ効果があるのか

 どのような制約でも、絶対値が大きいエンドポイントのみが合計が正か負かを決定します。 絶対値の順序が固定されると、すべてのエッジは、ちょうど 1 つのエンドポイント、つまりその順序で後のエンドポイントに符号要件を課します。 

DP は、最小の大きさから最大の大きさまでの順序を構築します。 頂点のとき$i$が挿入され、すべての頂点が入ります$S$大きさが小さくなります。 間のエッジ$i$そして頂点$S$すでにどの星座が決まっているのか$i$持っている必要があります。 2 つのビットマスク テストは、陽性または陰性が可能であるかどうかを正確にチェックします。 

有効な順序付けと符号の割り当てはすべて 1 回だけカウントされ、カウントされたすべての構成はすべての制約を満たします。 符号と大きさの順序は一様に分布しているため、次のように割ります。$2^n n!$カウントを希望の確率に変換します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, m = map(int, input().split())

    LE = [0] * n
    GE = [0] * n

    for _ in range(m):
        t, i, j = map(int, input().split())
        i -= 1
        j -= 1

        if t == 0:
            LE[i] |= 1 << j
            LE[j] |= 1 << i
        else:
            GE[i] |= 1 << j
            GE[j] |= 1 << i

    N = 1 << n
    dp = [0] * N
    dp[0] = 1

    for S in range(N):
        cur = dp[S]
        if cur == 0:
            continue

        for i in range(n):
            if (S >> i) & 1:
                continue

            T = S | (1 << i)

            if (GE[i] & T) == 0:
                dp[T] = (dp[T] + cur) % MOD

            if (LE[i] & T) == 0:
                dp[T] = (dp[T] + cur) % MOD

    ans = dp[N - 1]

    inv2 = pow(2, MOD - 2, MOD)
    for k in range(1, n + 1):
        ans = ans * pow(k, MOD - 2, MOD) % MOD
        ans = ans * inv2 % MOD

    print(ans)

if __name__ == "__main__":
    main()
```2つのマスク`LE`そして`GE`制約グラフ全体をエンコードします。 自己ループは自動的に頂点を独自のマスク内に配置します。これはまさに私たちが望んでいることです。 たとえば、制約$x_i+x_i\ge 1$セルフビットインになる`GE[i]`、ネガティブトランジションが不可能になります。 

DP 状態には、すでに処理された頂点のサブセットのみが保存されます。 順序は頂点が挿入された順序から再構築されるため、追加の情報は必要ありません。 

表現`GE[i] & T`禁止されているかどうかを確認します`>=`エッジはすでに小さい大きさの頂点を指しています。 そうである場合、正の符号を選択​​すると制約に違反します。 

最後に、次のモジュラー逆数を乗算します。$2$そして$1,2,\dots,n$で割る$2^n n!$。

 | 状態 | 追加された頂点 | 許可された標識 |

がある$3!\cdot 2^3 = 48$同様に可能性の高い順序/符号のペア。 したがって$$\frac{6}{48}=\frac14.$$モジュロ$998244353$、これは`748683265`。 

この例では、順序付けロジックに影響を与えることなく、自己ループが単一変数の符号を制限する方法を示します。 

### サンプル 2

 入力:```
3 3
0 1 2
0 1 3
0 2 3
```すべてのエッジにはタイプがあります$\le 0$。 

どのペアを検査する場合でも、大きい方の終点は負である必要があります。 

したがって、全体として最大の大きさの変数は負でなければなりません。 残りの 2 つの変数にはどちらの符号も付けることができます。 

| 最大の大きさの頂点 | 必須の記号 |
 | --- | --- |

この例は、より大きな振幅のエンドポイントのみが重要であるという中心的な原則を示しています。

 ## 特殊なケース

 次のことを考慮してください。```
1 1
1 1 1
```セルフループは内部に格納されています`GE[1]`。 DP が負の符号を付けて頂点を配置しようとすると、条件$$GE[1]\cap\{1\}\neq\varnothing$$その移行をブロックします。 プラスの符号だけが残ります。 DP カウントは次のようになります。$1$、で割る$2$確率を生み出す$1/2$。 

次に、次のことを考えてみましょう。```
1 1
0 1 1
```同じ理由が次の場合にも当てはまります`LE`。 負の符号のみが許可され、再び確率が生成されます$1/2$。 

最後に、次のことを考慮してください。```
4 4
0 1 2
0 3 4
1 1 3
1 2 4
```どちらかの頂点$\{1,3\}$大きさが大きい場合は正でなければなりません。 どちらかの頂点$\{1,2\}$大きさが大きい場合は負でなければなりません。 グラフの周りでこれらの要件を追求すると、矛盾が生じます。 DP 中に、すべての部分的な構築が最終的に行き詰まるため、最終的なカウントはゼロとなり、アルゴリズムは次のように出力します。$0$。 これは、DP がローカル チェックに依存するのではなく、グローバルな不整合を自動的に検出することを示しています。
