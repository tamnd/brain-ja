 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは、一列に配置された一連のカラー ボールを表す整数の行から始まります。 移動は 2 つのポジションを選択することで構成されます$i < j$それらの位置のボールが同じ色になるようにし、セグメント全体を削除します。$i$に$j$、両方のエンドポイントを含みます。 削除すると、右側にあるものはすべて左側に移動します。 この操作を何度でも繰り返し、合計で取り除くボールの数を最大化することが目標です。 

これを解釈するのに便利な方法は、すべての操作でエンドポイントが同じ値を共有する連続したブロックを削除し、削除後は配列が短くなり、以前は隣接していなかった新しいマージが可能になる可能性があるということです。 

全体にわたる制約の合計$n$は$2 \cdot 10^5$、だから、$O(n^2)$テストごとの解決策が遅すぎるし、$O(n \sqrt n)$危険です。 テストケースごとに線形または線形に近いアプローチが必要です。 

色が繰り返されていても大きなセグメントで区切られている場合、微妙なエッジケースが表示されます。 たとえば、`[1, 2, 3, 1]`、この2つを考えたくなります。`1`は大きな削除に直接寄与する可能性がありますが、中間の構造は部分的な削除後に何が可能になるかに影響します。 最初の有効なペアを常に削除する単純な貪欲なアプローチは、将来のより良いペアリングをブロックする可能性があるため、失敗する可能性があります。 

もう 1 つの落とし穴は、各色が「最初と最後の出現の間の距離」のようなものに独立して寄与していると想定していることです。 内部構造が複数段階の削除を許可している場合、この問題は解決されません。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのペアを試します。$(i, j)$等しい値を使用して削除をシミュレートし、残りの配列を再帰的に解決します。 これはプロセスを正しくモデル化していますが、削除するたびに配列サイズが変化するため、$O(n^2)$候補者は州ごとに移動します。 再帰は大量に分岐するため、最悪の場合、全体の複雑さは指数関数的に増加します。 

重要な点は、中間配列を明示的にシミュレートする必要がないということです。 代わりに、左から右に処理し、後で一致する色で閉じるセグメントを「開く」かどうかを決定するという観点から考えることができます。 

これは当然、プレフィックスを介した動的プログラミングにつながり、各位置まで最適な答えを追跡します。 主な問題は、その位置でセグメントを閉じるときです。$i$、場合によっては内部の要素をスキップしながら、同じ色の以前の出現をペアにする最良の方法を考慮する必要があります。 

この構造の問題に対する標準的なトリックは、各位置で 2 つの選択肢を検討する DP 配列を維持することです。つまり、現在の要素をスタンドアロンとして扱うか (外部の削除には使用されません)、以前に出現した同じ色のものと一致させ、その間にあるすべてのものを最適に削除します。 

また、各色について、その色が最後に出現した位置での最良の DP 値も維持します。 これにより、繰り返し逆方向にスキャンすることが回避されます。 

結果として得られる解は、テスト ケースごとに線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 | O(n) 再帰 | 遅すぎる |
 | 最後に発生した状態を使用した最適な DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP 配列を定義します。`dp[i]`インデックスまでのプレフィックスを考慮した、削除されたボールの最大数を表します`i`。 

辞書も整備しています`best[color]`これは、現在の位置でセグメントを閉じるという考えを適用した後、この色が表示された位置で見られた最良の DP 値を保存します。 

### ステップ

 1.初期化`dp[0] = 0`そしてすべてを設定します`best[color] = 0`。 

つまり、何かを処理する前は削除できないということです。 
2. 配列を左から右に繰り返します。 

位置で`i`、現在のボールの色を考慮します`c = a[i]`。 
3. まず、以前のベストを繰り越します。`dp[i] = dp[i-1]`。 

これは、その位置で削除を終了しない場合を表します。`i`。 
4. 次に、次で終了するセグメントを閉じることを検討します。`i`。 

前に同じ色を見たなら`c`ある位置で、その以前の出現が削除の左端として機能する可能性があります。 
5. 色について`c`、次を計算します。$$dp[i] = \max(dp[i], best[c] + 1)$$これは、以前に出現した同じ色の有効なペアを形成し、すでにエンコードされている最適な方法でその間にあるものをすべて削除することを表します。`best[c]`。 
6.アップデート`best[c] = \max(best[c], dp[i])`。 

これにより、将来の発生が確実になります。`c`この時点までに達成可能な最良の状態から恩恵を受けることができます。 
7. すべての要素を処理すると、答えは次のようになります。`dp[n]`。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`best[c]`常に、カラーが適用されるすべての位置の中で達成可能な最大 DP 値を保存します。`c`が表示されます。これは、色のセグメントを閉じる前の可能な限り最良の状態を表すことを意味します。`c`"。新しい発生を処理するとき、`c`、それを以前の最良の出現とペアにすることは、ここで終わるセグメントの最適な左境界を選択することと同じです。 内部セグメントはすでに最適に解決されているため、`dp`、以前のすべての発生を単一の最良の状態に集約することで、最適性を失うことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        dp_prev = 0
        best = {}

        for x in a:
            cur = dp_prev

            if x in best:
                cur = max(cur, best[x] + 1)

            if x not in best or cur > best[x]:
                best[x] = cur

            dp_prev = cur

        print(dp_prev)

if __name__ == "__main__":
    solve()
```各ステップで必要なのは前の値のみであるため、コードでは完全な配列の代わりにローリング DP が使用されます。 辞書`best`色ごとのすべての履歴状態を 1 つの値に圧縮し、二次関数の動作を回避します。 

移行`best[x] + 1`同じ色の以前の出現を使用して、現在の位置で終わるセグメントを閉じるというアイデアをエンコードします。 この増分は、1 回の削除操作の実行に対応します。 

アップデートには注意が必要`best[x]`計算後`cur`そうしないと、同じステップ内で状態がそれ自体を再利用することを誤って許可してしまうことになります。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 各要素は O(1) 辞書演算で 1 回処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        dp_prev = 0
        best = {}

        for x in a:
            cur = dp_prev
            if x in best:
                cur = max(cur, best[x] + 1)
            best[x] = max(best.get(x, 0), cur)
            dp_prev = cur

        out.append(str(dp_prev))

    return "\n".join(out)

# provided samples
assert run("""2
5
1 2 2 3 3
4
1 2 1 2
""") == "4\n3"

# all same values
assert run("""1
5
7 7 7 7 7
""") == "4"

# alternating pattern
assert run("""1
6
1 2 1 2 1 2
""") == "3"

# single color pair only
assert run("""1
3
1 2 1
""") == "1"

# no possible useful merges
assert run("""1
4
1 2 3 4
""") == "0"

 ## 特殊なケース

 すべて同じ値を持つ配列の場合、アルゴリズムは継続的に更新されます。`best[color]`、すべての新しい発生が以前の最適なチェーンを拡張できるようにします。 DP は、隣接する出現ペアごとに 1 つの操作を構築します。これは、マージごとにセグメントが少なくとも 1 つの完全な間隔だけ削減されるという事実と一致します。 

次のような厳密に交互のシーケンスの場合`[1,2,1,2,...]`、各色の`best`値は独立して進化し、DP は有効な以前の状態が存在する場合にのみ遷移を許可することでオーバーカウントを正しく回避します。 これにより、互換性のないセグメント間での誤ったチェーンが防止されます。 

繰り返しのない配列の場合、`best`は全体を通して空のままであるため、演算は決して形成されません。 どの削除操作にも有効なエンドポイントが存在しないため、DP は正しくゼロを返します。
