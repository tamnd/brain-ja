 ## 解決策
 ## 問題の理解

 この問題は、以下からなる円形のネックレスを提示します。$n$真珠では、各真珠が紐で隣の真珠と接続され、最後の真珠が最初の真珠に戻ります。 各弦の切断には分単位のコストがかかります。 Tenzing は、どのセグメントにも複数のセグメントが含まれないように、ネックレスを連続したセグメントに分割したいと考えています。$k$真珠。 目標は、そのようなカットを行うのに必要な最小合計時間を決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースはパールの数を提供します$n$、最大セグメント長$k$、およびリスト$n$整数$a_1$を通して$a_n$各弦のカッティング時間を表します。 各テスト ケースの出力は、セグメント サイズの制約を満たすための最小の合計切断時間です。 

与えられた$n$まで可能です$5 \cdot 10^5$すべてのテスト ケースにわたって、制限時間は 2 秒です。これよりも複雑なアルゴリズムはすべて、$O(n)$テストケースごとにタイムアウトになる可能性があります。 可能な組み合わせの数が指数関数的に増加するため、カットのすべてのサブセットを考慮する素朴なアプローチは実行不可能です。 ネックレスの円形の性質を無視したり、常に均等なカットを前提とした不用意な実装は、誤った結果を生み出す可能性があります。 たとえば、次の場合$n = 5$、$k = 2$、カット時間はすべて異なるため、最小限の組み合わせを考慮せずにカットを純粋に順番に選択すると、合計が必要以上に高くなる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのカット セットを列挙し、セグメント長の制約を満たす各組み合わせの合計時間を計算します。 このアプローチは正しいですが、カットのサブセットの数が指数関数的に増加するため、非現実的です。$n$、それはあたりでしょう$2^n$最悪の場合の運用。 小さいものでも$n$、これは実行可能な実行時間をすぐに超えます。 

重要な洞察は、最大セグメント長が固定されているということです。$k$、ネックレスの円形の性質により、問題には周期的な構造があります。 有効な分割は、開始パールを選択し、最大で長さのセグメントを貪欲に取得することで表現できます。$k$。 最適なカット戦略は、以下のサイズの各セグメントでカットする最小コストの文字列を選択することです。$k$。 これにより、問題は、考えられるすべての開始位置の線形スキャンに軽減され、最大でも長さのセグメントに対する最小の累積カット コストが追跡されます。$k$。 

スタートポジションごとに$s$、真珠を繰り返し処理し、毎回の後にカットを検討します。$k$-th パール、これらの位置で利用可能な最小の切削コストを合計します。 ネックレスは円形であるため、ネックレスを 1 回複製することで一連の切断時間を延長し、ウィンドウ化されたセグメントのモジュロ演算を行わずに線形スキャンを可能にします。 

問題はすべてを考慮することになります$k$最初の範囲内で可能な開始オフセット$k$真珠を調整し、そのオフセットを進める際のカットの最小合計を計算します。 最後に、これらの開始オフセットの中から最小の合計を選択します。 このアプローチは次の点で線形です。$n$テスト ケースごとに、指定された制約の下で許容されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$k$、および切断時間のリスト$a$。 伸ばす$a$これをそれ自体に連結することで、モジュロ演算を行わずに循環の性質を処理します。 
2. 変数を初期化する`res`最小の合計切断時間を保存するには、大きな値に設定します。 
3. 可能なすべての開始オフセットを反復処理します。`start`0から$k-1$。 各オフセットは、最初のカット位置の選択を表します。$k$真珠。 
4. オフセットごとに合計を初期化します。`cur_sum`これにより、現在の戦略の削減コストが累積されます。 
5. から始めてパールを繰り返します。`start`のステップで`k`、長さのセグメントで最小の切断コストを選択します$k$。 この最小限のコストを追加すると、`cur_sum`。 
6. この開始オフセットのすべてのパールをスキャンした後、更新します。`res`もし`cur_sum`現在よりも小さいです`res`。 
7. すべての開始オフセットを確認した後、出力します。`res`テストケースの最小合計切断時間として。 

機能する理由: サイズの最初のセグメント内のすべての開始オフセットを反復処理することによって$k$、すべての有効な切断構成が考慮されることを保証します。 各セグメント内の最小コストを貪欲に選択することで、どのセグメントも最小コストを超えることがなくなります。$k$累積コストを最小限に抑えながら真珠を生産します。 配列を拡張すると、円形のラップアラウンドがシームレスに処理されます。 不変条件は、各セグメントが次の値を超えないことです。$k$可能なすべての開始構成が検査され、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a_extended = a + a  # handle circular necklace
        res = float('inf')
        for start in range(k):
            cur_sum = 0
            for i in range(start, start + n, k):
                cur_sum += a_extended[i]
            res = min(res, cur_sum)
        print(res)

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 配列を連結すると、モジュロ演算を行わずに循環構造の処理が簡素化されます。 オフセットを反復処理することで、考えられるすべてのセグメントの位置合わせが確実に考慮されます。 の`cur_sum`指定されたオフセットの最小カットを累積し、全体の最小値を更新します`res`。
