 ## 問題の理解

 最大の長さの配列を数えるように求められます。$n$間の値$1$そして$m$複数の有効な削除シーケンスが存在する場合。 削除シーケンスは、各要素が次のように削除される順序です。$a_i$は、削除された時点の配列内の現在の位置と互いに素です。 

入力は 2 つの整数です。$n$、考慮すべき配列の最大長、および$m$、要素が取り得る最大値。 出力は、あいまいな配列の合計数を法で表したものです。$998244353$。 

境界線を見てみると、$n$まで可能です$3 \cdot 10^5$そして$m$まで$10^{12}$。 長さ 10 の配列をすべて生成する場合でも、$m^{10}$最悪の場合の運用。 どのような解決策でも、個々の配列の反復を避け、代わりに組み合わせまたは数学的に推論する必要があります。 

重要なエッジケースが発生するのは次のような場合です$n = 2$そして$m = 1$。 その場合、唯一の配列は$[1, 1]$、削除シーケンスが複数ある場合はあいまいですが、注意深く調べるとシーケンスが 1 つだけ存在することがわかります。 同様に、すべての要素が 1 である配列は、削除シーケンスが 1 と互いに素な位置によって完全に決定されるため、通常はあいまいではありません。 

## アプローチ

 単純な総当たりアプローチでは、次の長さのすべての配列が生成されます。$n$、各配列に対して考えられるすべての削除シーケンスをシミュレートし、複数のシーケンスが存在するかどうかを確認します。 これが機能するのは、あいまいさの定義が明確であるためです。配列で複数の削除シーケンスが許可されている場合、その配列はカウントされます。 ただし、長さ 20 の配列であっても、$m=10^6$このアプローチは実行不可能になります。 シーケンスの列挙は長さとともに階乗的に増加するため、$O(n!)$配列ごとは不可能です。 

重要な洞察は、曖昧さは、ある数字が削除できる複数の位置に出現する場合にのみ発生するということです。 より正確には、あいまいさは、配列に連続した位置のペアがある場合にのみ発生します。$i$そして$i+1$そのような$\gcd(a_i, i+1) = 1$そして$\gcd(a_{i+1}, i) = 1$。 これにより、まさにあいまいさの条件である共素性の条件に違反することなく、2 つの要素の削除順序を入れ替えることができます。 

これを認識すると、問題は、配列内の任意の場所でこのローカル条件を満たす長さ 2 以上の配列を数えるということになります。 各要素は独立しているため、長さがあいまいな配列の数は$k$少なくとも 1 つのそのような隣接ペアが存在する配列のすべての位置の合計です。 各位置の有効な値の数は、単純に最大の整数の数です。$m$その位置インデックスと互いに素であるもの。 

の整数の数を計算するには$[1, m]$与えられた整数と効率的に互いに素になるようにするには、オイラー十関数を使用します。$\phi(i)$。 この関数を使用すると、配列を列挙することなく、組み合わせ的に配列をカウントできます。$\phi(i)$隣接要素とのあいまいさを生み出す可能性のある要素の選択肢。

 ## アルゴリズムのチュートリアル

 1. オイラーの合計関数を事前計算する$\phi(i)$みんなのために$i \le n+1$ふるいを使って。 これにより、数を数えることができます$[1, m]$各インデックスに素早い対応を求めます。$\phi(i)$内の整数の数です$[1, i]$と互いに素である$i$、そして私たちの目的のために、私たちは次のようにスケールすることができます$\lfloor m / i \rfloor$上記の倍数を考慮する$i$。 
2.長さごとに$k$2から$n$、すべての隣接する位置のペアを考慮します$i$そして$i+1$。 削除順序を入れ替えることができる場合、曖昧さが発生します。 ポジションについて$i$、選択肢の数$a_i$と互いに素である$i+1$は$\phi(i+1)$(上限は$m$もし$m < i+1$）。 のために$a_{i+1}$、と互いに素な数のカウント$i$は$\phi(i)$。 これらのカウントを乗算して、この位置のあいまいなペアの数を取得します。 
3. 配列内の任意の場所にそのようなペアが 1 つだけ存在するだけで曖昧さには十分であるため、すべての位置を合計します。$i$長さの配列で$k$。 より長い配列$k$には追加の位置がありますが、追加の要素によって曖昧さが解消されないため、各カウントは独立しています。 
4. 2 から 2 までのすべての長さの合計数$n$曖昧な配列の総数を取得します。 モジュロを適用する$998244353$オーバーフローを避けるために各ステップで。 

機能する理由: オイラー トーティエントの事前計算により、各位置の潜在的な値の正確なカウントが保証されます。 隣接するペアのみを分析し、要素の独立性を使用することで、少なくとも 1 つのスワップが可能なすべての配列をキャプチャします。 位置の合計により、曖昧な配列をすべて数えることが保証され、モジュロ演算を使用することで、大規模な環境下でも正確さが維持されます。$m$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def compute_totients(limit):
    phi = list(range(limit + 2))
    for i in range(2, limit + 2):
        if phi[i] == i:
            for j in range(i, limit + 2, i):
                phi[j] -= phi[j] // i
    return phi

def main():
    n, m = map(int, input().split())
    phi = compute_totients(n + 1)
    ans = 0
    for i in range(1, n):
        count_i = min(phi[i], m)
        count_ip1 = min(phi[i+1], m)
        ans = (ans + count_i * count_ip1) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```コードはまず、次の位置までのすべての位置のオイラー合計を事前計算します。$n+1$これにより、各インデックスと互いに素な数を効率的に数えることができます。 メイン ループは、隣接する各ペアの互いに素な数のカウントを乗算し、合計モジュロを累積します。$998244353$。 最小$m$許可された最大値を超えて数値がカウントされないようにします。
