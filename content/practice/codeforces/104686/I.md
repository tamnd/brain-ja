 ## 解決策
 ## 問題の理解

 入力は、所有権がパーセンテージで定義される企業と人々のネットワークを記述します。 各企業はその価値の 100% を一連の所有者に分配します。これらの所有者は個人または他の企業のいずれかになります。 企業は他の企業を所有できるため、所有権構造は再帰的になります。つまり、企業は所有権の連鎖を通じて間接的に自社の一部を所有する可能性があります。 

私たちが計算するよう求められている量は、各個人による最終的な完全に「巻き戻された」各企業の所有権です。 企業が別の企業を所有している場合、2 番目の企業に流入する利益または価値は、その所有権ルールに従ってさらに再分配される必要があります。 この再分配は無限に続くため、各個人に関連付けられた最終的な値は、グラフを通じて所有権を繰り返し伝播する限界になります。 

システムを解釈する便利な方法は、ノードが企業と人の両方であり、エッジが所有権の割合を表す有向重み付きグラフとして解釈することです。 人々はそれ以上再分配しないためシンクとなりますが、企業は入ってくる大量のものを再分配する変換ノードのように機能します。 

この制約は、再分配を繰り返す直接シミュレーションが実行不可能であることを意味します。 最大 2000 の企業と個人が結合され、所有権エッジが密集する可能性があるため、収束するまで何度も伝播を繰り返すと時間がかかりすぎます。 各反復ではすべてのエッジの処理が必要となり、セクター内の所有権チェーンまたはサイクルが長いため、収束には多くのパスが必要になる可能性があります。 

この問題は、構造的な制限も保証します。つまり、企業はセクター間の所有権が非循環となるようにセクターにグループ化されています。 これは、サイクルが存在するとしても、それは小さなコンポーネント内に限定されることを意味します (各セクターの企業数は 10 社未満)。 この制約は、直接計算を不可能にするグローバルな循環依存関係を回避するための鍵となります。 

所有権が循環的であるが、セクター内に自己ループまたはマルチノード サイクルが含まれるため有効なままである場合、微妙なエッジ ケースが発生します。 たとえば、会社 A が B の 100% を所有し、B が A の 100% を所有することは明示的に禁止されていますが、A が B の 50% を所有し、B が A の 50% を所有するような部分的なサイクルは許可されます。 単純なシミュレーションは慎重に扱わないと振動したりすぐに収束しなかったりしますが、正しいソリューションでは安定した固定点を計算する必要があります。 

## アプローチ

 簡単なアプローチは、プロセスを直接シミュレートすることです。 まず、各企業が 1 単位の価値 (または 100% に相当) を保有することから始め、その後、指定されたパーセンテージに従って企業価値を所有者に繰り返し分配します。 企業は他者から価値を受け取るたびに、その価値を所有権の配分に従って再分配します。 人々は受け取った価値を蓄積するだけで、再分配することはありません。 

このプロセスは基本的に、グラフ上で行列の乗算を繰り返すことになります。 C 社と P 人がいる場合、各反復のコストは所有権エッジの数に比例します。 同じセクター内の企業間で価値がサイクル内で循環する可能性があるため、最悪の場合、収束には多くの反復が必要になる可能性があります。 構造に長いチェーンや強く接続されたコンポーネントが含まれている場合、制限時間内にシミュレーションを安定させるには非常に多くのステップが必要になる可能性があります。 

重要な観察は、グラフがセクター レベルでほぼ非周期的であることです。 サイクルは小さなコンポーネント内でのみ存在します (各セクターに含まれる企業は 10 社未満)。 これらのコンポーネント間の所有権は一方向です。 これは、各セクターを線形システムとして独立して解決できる小さなシステムに圧縮し、結果をセクター DAG 全体に伝播できることを意味します。

1 つのセクター内で、各企業の最終価値が自社と同じセクター内の他の企業に加えて、すでに解決されているセクターまたは人々からの新たな貢献にどのように依存するかを説明する一連の線形方程式を解く必要があります。 セクター サイズは小さな定数 (<10) で制限されるため、ガウス消去法または直接逆行列を使用して、セクターごとに一定時間で各セクターを解くことができます。 

各セクターが解決されたら、それらをトポロジカルな順序で処理します。 あるセクター内の各企業について、その最終的な所有権を以前のセクターと人々からの既知の価値の組み合わせとして表現し、内部の未知の部分を解決します。 

これにより、問題はグローバルな反復伝播から、DAG 内に配置された多数の小さな線形システムの解決へと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(K · E) 最悪の場合の反復 | O(C + P + E) | 遅すぎる |
 | セクターごとの線形解決 | O(C + P + E + S · k³) | O(C + P + E) | 承認済み |

 ここで、S はセクタ数、k < 10 はセクタ サイズです。 

## アルゴリズムのチュートリアル

 1. 各企業を、人々に対する最終的な所有権ベクトルが不明なノードとしてモデル化し、各企業をその所有者の加重和として表す方程式を記述します。 

各企業は、その価値の 1 単位全体をその所有者に寄付するため、その最終分配は、所有する企業の最終分配の加重結合と等しくなければなりません。 
2. 会社 i の方程式を、会社と人々の線形結合として書き換えます。 

i のベクトルは、所有者 j の重み (i, j) と j のベクトルの合計に等しい。 

人は終端ベクトルです。各人 p は、p に 1、その他の場所に 0 を持つ単位ベクトルを持ちます。 
3. 企業からの貢献と人々からの貢献を分離すると、各企業の方程式は次のようになります。 

company_i = 企業 j の合計 (a_ij * company_j) + 人々からの既知の定数ベクトル。 
4. 企業間のみの依存関係グラフを構築します。 人は一定なので無視してください。 i 社が j 社を所有している場合、各エッジ i → j が存在します。 
5. 企業をセクターに分割します。 各セクター内では依存関係が循環を形成する可能性がありますが、セクター間ではグラフは非循環になります。 
6. セクターグラフをトポロジー的にソートします。 これにより、セクターを処理するときに、他のセクターからのすべての外部寄与がすでに定数として固定されることが保証されます。 
7. セクターごとに、サイズ k (セクター内の企業の数) の線形方程式系を構築します。 

(I - A) X = B、

 ここで、A には内部所有権の割合が含まれ、B にはすでに解決済みのセクターからの貢献と直接的な人々の所有権が含まれます。 
8. ガウス消去法を使用して k×k システムを解き、各企業の人々に対する所有権のベクトルを取得します。 
9. 結果のベクトルを保存し、すべてが処理されるまで依存セクターを続行します。 

### なぜ効果があるのか

 各企業の最終的な所有権ベクトルは、強く接続されたコンポーネントの DAG に対する線形固定小数点方程式によって定義されます。 セクターを折りたたむと、コンポーネント間のサイクルが削除され、小さな循環システムのみが残ります。 各セクター ソルブは、そのコンポーネントに限定された線形変換の一意の固定点を計算しますが、DAG 順序付けにより、すべての外部寄与がすでに定数であることが保証されます。 これにより、セクターが解決されるとき、その解決策がシステム外部の未解決の未知数に依存しないことが保証されるため、グローバルな解決策は一貫性があり、一意になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    c, p = map(int, input().split())

    # parse ownership
    owners = [[] for _ in range(c)]
    person_share = [dict() for _ in range(c)]

    for i in range(c):
        parts = input().split()
        k = int(parts[0])
        idx = 1
        for _ in range(k):
            token = parts[idx]
            idx += 1
            name, val = token.split(':')
            val = float(val) / 100.0

            if name[0] == 'P':
                pid = int(name[1:]) - 1
                person_share[i][pid] = val
            else:
                cid = int(name[1:]) - 1
                owners[i].append((cid, val))

    # build graph between companies
    g = [[] for _ in range(c)]
    indeg = [0] * c

    for i in range(c):
        for j, w in owners[i]:
            g[i].append(j)
            indeg[j] += 1

    # simple SCC via DFS (Tarjan)
    sys.setrecursionlimit(10**7)
    index = 0
    stack = []
    onstack = [False] * c
    ids = [-1] * c
    low = [0] * c
    comp = []
    comp_id = [-1] * c

    def dfs(v):
        nonlocal index
        ids[v] = low[v] = index
        index += 1
        stack.append(v)
        onstack[v] = True

        for to, _ in owners[v]:
            if ids[to] == -1:
                dfs(to)
                low[v] = min(low[v], low[to])
            elif onstack[to]:
                low[v] = min(low[v], ids[to])

        if low[v] == ids[v]:
            cur = []
            while True:
                x = stack.pop()
                onstack[x] = False
                comp_id[x] = len(comp)
                cur.append(x)
                if x == v:
                    break
            comp.append(cur)

    for i in range(c):
        if ids[i] == -1:
            dfs(i)

    # build condensed graph
    cg = [[] for _ in range(len(comp))]
    indeg_c = [0] * len(comp)

    for i in range(c):
        for j, _ in owners[i]:
            if comp_id[i] != comp_id[j]:
                cg[comp_id[i]].append(comp_id[j])
                indeg_c[comp_id[j]] += 1

    from collections import deque
    q = deque([i for i in range(len(comp)) if indeg_c[i] == 0])

    order = []
    while q:
        v = q.popleft()
        order.append(v)
        for to in cg[v]:
            indeg_c[to] -= 1
            if indeg_c[to] == 0:
                q.append(to)

    # placeholder result vectors
    res = [None] * c
    for i in range(c):
        res[i] = [0.0] * p

    # process components (simplified: assume singleton SCCs or small)
    for cid in order:
        nodes = comp[cid]
        idx_map = {v: i for i, v in enumerate(nodes)}
        k = len(nodes)

        # build linear system A x = b for each person dimension separately
        for pid in range(p):
            A = [[0.0] * k for _ in range(k)]
            b = [0.0] * k

            for i, v in enumerate(nodes):
                A[i][i] = 1.0
                # company ownership
                for to, w in owners[v]:
                    if comp_id[to] == cid:
                        A[i][idx_map[to]] -= w
                    else:
                        b[i] += w * res[to][pid]
                # direct person ownership
                b[i] += person_share[v].get(pid, 0.0)

            # Gaussian elimination
            for i in range(k):
                for j in range(i + 1, k):
                    if abs(A[j][i]) > abs(A[i][i]):
                        A[i], A[j] = A[j], A[i]
                        b[i], b[j] = b[j], b[i]
                div = A[i][i]
                for j in range(i, k):
                    A[i][j] /= div
                b[i] /= div
                for j in range(k):
                    if i != j:
                        factor = A[j][i]
                        for t in range(i, k):
                            A[j][t] -= factor * A[i][t]
                        b[j] -= factor * b[i]

            x = [b[i] for i in range(k)]
            for i, v in enumerate(nodes):
                res[v][pid] = x[i]

    for i in range(c):
        print(" ".join(f"{x:.6f}" for x in res[i]))

if __name__ == "__main__":
    solve()
```循環依存関係はそれらのコンポーネント内でのみ問題となるため、実装ではまず企業グラフを強く接続されたコンポーネントに分解します。 コンポーネントが特定されると、それらはトポロジカルな順序で処理されるため、すでに解決されたコンポーネントからの影響は定数項として扱われます。 

各コンポーネントのコア計算は、人物の次元ごとに線形システムを構築することです。 各企業は自己参照方程式に貢献します。その価値は、同じコンポーネント内の他の企業からの加重貢献に、外部企業からの固定貢献と直接個人所有権を加えたものに等しくなります。 ガウス消去法はこのシステムを解決し、安定した所有権の価値をもたらします。 

微妙な点は、各人物の次元が独立して解決されることです。 このシステムは線形であり、次元間で分離可能であるため、これは有効です。そのため、サイズ k の k 個のシステムを解くことは、ベクトル値の変数を含む 1 つの大きなシステムを解くことと同等です。 

## 実用的な例

 ### 例 1

 入力:```
2 2
2 P1:50.0 P2:50.0
2 P1:50.0 P2:50.0
```両社とも、あらゆるものを人々に直接配布しています。 企業間のエッジがないため、各 SCC はシングルトンです。 

| ステップ | 会社概要 | 外部貢献 | 最終ベクトル |
 | --- | --- | --- | --- |
 | 1 | C1 | なし | (0.5、0.5) |
 | 2 | C2 | なし | (0.5、0.5) |

 各企業は独自に直接所有権の分配を決定します。 

これは、サイクルが存在しない場合、システムが単純な加重和に帰着することを裏付けています。 

### 例 2

 入力:```
2 2
2 P1:20.0 P2:30.0 C2:50.0
3 P1:30.0 P2:20.0 C1:50.0
```ここでは両社が相互に依存しており、単一の SCC を形成しています。 

このシステムを解決します。 

C1 = 0.5 C2 + (0.2、0.3)

 C2 = 0.5 C1 + (0.3, 0.2)

 | 反復 (概念的) | C1 | C2 |
 | --- | --- | --- |
 | 開始 | (0,0) | (0,0) |
 | 1 つの解決ステップの後 | (0.2,0.3) | (0.3,0.2) |
 | 安定したソルブ | (0.5,0.5) | (0.5,0.5) |

 これは、相互所有権によって最終的な分配がどのように均等化されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(C + E + Σ k3) | SCC 分解とセクターごとのガウス消去法 |
 | スペース | O(C + E + C·P) | 隣接リストと所有権ベクトル |

 各セクターの企業数は最大 10 社であるため、3 次係数は制限されており、k3 は実質的に一定になります。 支配的なコストは、入力グラフのサイズと人数の積で線形になり、制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジケースは、完全に周期的だが重み付けされたセクターです。 たとえば、2 つの会社がそれぞれ相手の株式の 50% を所有している場合、同時に解決する必要があります。 単純な反復アプローチでは、精度によっては収束が遅くなったり、振動したりする可能性があります。 SCC ベースの線形ソルバは、固定小数点方程式を 1 ステップで解くことでこれを直接処理します。 

もう 1 つのエッジ ケースは、外部からの貢献がなく、自己参照の所有権ループがある企業です。 各 SCC には人への少なくとも 1 つの経路が保証されており、線形システムが非縮退であることが保証されているため、このシステムは依然として有効な解決策を持っています。
