 ## 解決策
 ## 問題の理解

 私たちは、もともと非常に特殊な構造から得られた一連の実数を与えられています。誰かが整数配列から始めて、それをベクトルであるかのように正規化したものです。 各エントリはベクトルのユークリッド長で除算され、結果の数値が単位ベクトルを形成します。 その後、すべての値は小数点以下 12 桁に四捨五入されて保存されます。 

タスクは、指定された正規化された値を生成した可能性のある有効な整数配列を復元することです。 再構築は浮動小数点的に正確である必要はありません。 再構成された整数を再度正規化すると、座標あたり 10^{-6} の絶対誤差以内で、提供されたものに非常に近い単位ベクトルが得られるという意味で一貫性があればよいだけです。 再構築された整数は 1 ～ 10000 の範囲になければならず、gcd は 1 に等しい必要があります。 

入力に隠された重要な構造は、すべての値が同じ未知の整数ベクトルに比例するということです。 元の整数が a_1、a_2、...、a_N で、その長さが d の場合、すべての入力値はおよそ a_i / d になります。 これは、すべての座標が共通の倍率だけ異なることを意味します。 

この制約により、任意の整数ベクトルに対する総当り攻撃が不可能になります。 N は最大 10000 であるため、座標ごとに独立して検索しようとしたり、高精度の浮動小数点演算の組み合わせを再構築しようとしたりするソリューションは遅すぎます。 ペアワイズ比に関する O(N^2) 推論さえも実行不可能です。 

スケール値を個別に丸めることによって a_i を再構築しようとする単純な試みは、スケール係数が不明なため失敗します。 間違ったスケールを推測すると、丸め誤差が蓄積し、正規化後の結果のベクトルが異なる方向になる可能性があります。 

比率が近いものの、浮動丸めのせいで正確ではない場合、微妙な失敗のケースが発生します。 たとえば、2 つの座標がほぼ比例しているが、12 進数表現では同一ではない場合、各座標を個別に単純な整数で丸めると、gcd が 1 でないベクトル、または正規化された方向が許容誤差を超えてドリフトするベクトルが生成される可能性があります。 

## アプローチ

 重要な問題は、欠落しているスケール係数 d がわからないことです。 入力は方向のみを与え、大きさは与えません。 ただし、元のベクトルは整数値であるため、すべての座標は共通の整数解に比例する必要があります。 

ブルートフォースアプローチでは、整数ベクトル全体を直接推測しようとします。 各座標は最大 10000 であり、N 個の座標があるため、これは完全に実行不可能です。 推測されたベクトルのスケーリングに制限したとしても、依然として指数関数的に多くの候補を検索する必要があります。 

重要な観察は、ベクトルが単一のスカラーまで決定されるということです。 再構築された整数ベクトル内の 1 つの座標の値を固定すると、他のすべての座標は比例によって強制されます。 これにより、問題は N 個の未知の整数から単一の未知のスケーリング係数に縮小されます。 

インデックス j を選択し、最大の座標が範囲 [1, 10000] 内の整数値 k に対応すると仮定します。 k が固定されると、1 つおきの整数は次のように決定されます。 

a_i = k * x_i / x_j

 k の推測が正しければ、すべての値が同時に整数に近づきます。 正しくない場合、少なくとも 1 つの座標が整数に失敗するか、境界に違反します。 

これにより、問題は、最大座標として考えられるすべての整数値を試し、一貫性を検証することになります。 最大値は 10000 で制限されているため、検索スペースは十分に小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ベクトル検索 | 指数 | O(N) | 遅すぎる |
 | 最大座標のスケール推測 | O(10000・N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 最大入力値 x_j のインデックス j を特定します。 この座標は、対応する整数値が元の配列の最大整数である可能性が高いため、最も安定した参照となります。 
2. 1 から 10000 までのすべての可能な整数値 k を a_j の候補として試します。 真の再構成が正しければ、最大の整数はこの範囲内にあるはずだという考えです。 
3. 各候補 k について、a_i = k * x_i / x_j を使用して、すべての位置の暫定的な整数を計算します。 これにより、すべての座標が入力方向に比例したままになることが強制されます。 
4. 計算された各 a_i を最も近い整数に丸め、[1, 10000] 以内に収まることを確認します。 値が境界に違反する場合は、この k を直ちに破棄します。 
5. 構築された整数ベクトルのユークリッド ノルムを計算し、正規化します。 結果の正規化ベクトルを入力 x と比較します。 すべての座標の違いが最大 10^{-6} であれば、このベクトルを受け入れます。 
6. 候補がチェックに合格した後、すべての a_i の gcd を計算し、それで割って、最終的なベクトルがプリミティブであることを確認します。 

これが機能する理由は、元のベクトルが R^N の 1 次元光線上に正確に存在するためです。 すべての有効な再構成は、その光線上の整数点です。 1 つの座標を固定すると、この光線に沿った格子点が選択され、正しいスケーリングによってのみ、すべての座標にわたって一貫した整数の格子点が生成されます。 スケーリングが正しくないと、丸め後の比例関係が崩れます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def gcd_list(arr):
    g = 0
    for x in arr:
        g = gcd(g, x)
    return g

def check(xs, cand, j):
    n = len(xs)
    a = [0] * n

    for i in range(n):
        val = cand * xs[i] / xs[j]
        ai = int(val + 0.5)
        if ai < 1 or ai > 10000:
            return None
        a[i] = ai

    # compute norm
    norm = math.sqrt(sum(x * x for x in a))

    for i in range(n):
        if abs(a[i] / norm - xs[i]) > 1e-6:
            return None

    g = gcd_list(a)
    for i in range(n):
        a[i] //= g

    return a

def main():
    n = int(input())
    xs = [float(input().strip()) for _ in range(n)]

    j = max(range(n), key=lambda i: xs[i])

    for cand in range(1, 10001):
        res = check(xs, cand, j)
        if res is not None:
            print("\n".join(map(str, res)))
            return

if __name__ == "__main__":
    main()
```実装はスケーリング仮説を中心に行います。 機能`check`再構成されたすべての整数が入力ベクトルによって定義された単一の光線上に正確に存在する必要があるという構造上の制約を強制します。 浮動小数点除算では小さな数値誤差が発生し、丸めを行わないと正しい候補であっても整数制約に失敗してしまうため、丸めのステップは非常に重要です。 

正規化検証は、境界線の浮動不正確さを防ぐために明示的に行われます。 最後に、gcd リダクションにより、返されたベクトルがプリミティブであるという要件が満たされることが保証されます。 

候補の検索は最大座標に配置されます。これにより、不安定性が最小限に抑えられます。最大の大きさに固定されている場合、スケーリング エラーの影響は最小限になります。 

## 実用的な例

 入力が [2, 3, 6] の正規化バージョンである小さな概念的な例を考えてみましょう。 正規化後、最大の座標は 6 に対応するため、その位置をアンカーとして選択します。 

候補 k = 6 の場合、再構成は完全に一致します。 

| ステップ | 私 | 値の計算 | 丸い愛 |
 | --- | --- | --- | --- |
 | スケール | 0 | 6 * x0 / xj | 2 |
 | スケール | 1 | 6 * x1 / xj | 3 |
 | スケール | 2 | 6 * x2 / xj | 6 |

 正規化されたベクトルは入力方向に正確に再計算されるため、候補は受け入れられます。 

ここで、間違った候補 k = 5 を考えてみましょう。スケーリングされた値は矛盾します。 

| ステップ | 私 | 値の計算 | 丸い愛 |
 | --- | --- | --- | --- |
 | スケール | 0 | 5 * x0 / xj | 1 または 2 |
 | スケール | 1 | 5 * x1 / xj | 2 |
 | スケール | 2 | 5 * x2 / xj | 5 |

 正規化後、誤差が 10^{-6} を超えるほど方向がシフトするため、この候補は拒否されます。 

これらのトレースは、正しいスケーリングのみがグローバルに一貫した整数構造を生成することを示しています。

 ## 特殊なケース

 複数の座標が正規化ベクトルの最大値を共有する場合、微妙な状況が 1 つ発生します。 その場合、それらのいずれかをアンカーとして選択しても、すべてが同じ基礎となる整数最大値の比例表現であるため、機能します。 このアルゴリズムは、最大インデックスの一意性に依存しません。 

もう 1 つのエッジ ケースは、真の整数ベクトルに 10000 に近い値が含まれている場合に発生します。間違った候補がわずかにスケールを超えている場合、丸めにより値が境界外に押し出される可能性があります。 範囲チェックでの即時拒否により、そのような候補が正規化比較にさらに伝播することがなくなります。 

最後の微妙なケースは、再構築中に浮動小数点の丸めにより半整数に非常に近い値が生成される場合です。 明示的な丸めステップによりこれが安定し、一貫した候補が数値ノイズによるドリフトではなく同じ整数ベクトルに確実に収束します。
