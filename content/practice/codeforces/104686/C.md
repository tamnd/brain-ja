 ## 解決策
 ## 問題の理解

 平面内には点のセットが与えられます。各点は、古いものから新しいものへの固定された作成順序を持つ「星」です。 最初は、すべての星が独自の星団を形成します。 クラスターが 1 つだけ残るまで、クラスターのマージを繰り返します。 

各ステップで、現在のクラスターのすべてのペアを調べ、それらの距離を、それらの間の点のすべてのペアにわたるユークリッド距離の二乗の平均として定義します。 一方のクラスターに点 A があり、もう一方のクラスターに点 B がある場合、A のすべての a と B の b の間の距離の二乗の合計を計算し、|A|·|B| で割ります。 

このプロセスでは常に、そのような距離が最小のクラスターのペアがマージされます。 複数のペアが同じ距離を共有する場合、クラスターの「年齢」を使用して同点が解決されます。古いクラスターを含むペアが最初に優先され、依然として同点の場合は、新しいクラスターが同点を破ります。 各マージの後、新しく形成されたクラスターのサイズを出力します。 

The constraints allow up to 2000 stars. 各マージ後にすべてのペアごとのクラスター距離を再計算する単純なアプローチでは、最大 n 回のマージに対して最大 O(n^2) ペアを繰り返しスキャンするため、O(n^3) の動作が発生しますが、このスケールでは遅すぎます。 したがって、定数時間の距離クエリを可能にする表現と、マージのたびに影響を受ける距離のみを更新する方法が必要です。 

微妙な問題は、クラスター距離が重心間の単純な幾何学的距離ではないことです。 それはすべてのペアごとの相互作用に依存するため、閉じた形式を導出しない限り、マージは局所的に加算されない方法で距離を変更します。 

## アプローチ

 ブルート フォース ビューは、すべてのクラスターを明示的な点のセットとして扱います。 次のマージを決定するたびに、クラスター全体のすべての点のペアを反復処理して、クラスターのすべてのペア間の距離を計算します。 n 個のクラスターの場合、マージ ステップごとにすでに O(n^2) のコストがかかり、マージごとにクラスター数が 1 つ減るため、合計作業量は n の 3 次になります。 n が 2000 までになると、これはすぐに実行不可能になります。 

重要な観察は、距離の式を代数的に拡張できるため、各クラスターがいくつかの集計統計によって要約されることです。 距離の 2 乗は、 ||a − b||² = ||a||² + ||b||² − 2a・b のように展開されます。 すべてのクロス ペアを合計すると、A と B の独立した合計に分離されるため、式全体はクラスター サイズ、座標の合計、および二乗ノルムの合計から計算できます。 This reduces each distance computation to O(1).

 距離が短くなると、マージを繰り返しても現在の最小ペアを維持することが問題になります。 これは、古典的な凝集クラスタリングのシナリオです。 We maintain a heap of candidate merges. 2 つのクラスターを結合した後は、新しいクラスターに関係する距離のみを再計算する必要があります。 他のものはすべて有効のままです。 これにより、各マージで O(n) 個の新しい距離計算のみが行われることが保証され、ヒープ操作により全体として O(n² log n) 構造が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 最適 | O(n² log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クラスターのデータ構造を維持し、そのサイズ、x 座標の合計、y 座標の合計、および二乗ノルム x² + y² の合計を保存します。 また、タイブレークを処理するために各クラスターに作成時間を割り当てます。 

閉形式を使用してすべての星のペア間の初期距離を事前計算し、それらを距離順に並べた優先キューに入れ、次にタイブレーク ルールに従って並べます。 

また、古いヒープ エントリを遅延無視できるように、クラスターのアクティブ フラグも維持します。

1. 各星を独自のクラスターとして初期化し、その集計統計を保存し、固有の増加する年齢を割り当てます。 
2. 導出された式を使用してクラスターの各ペア間の距離を計算し、距離とタイブレーク メタデータをキーとした優先キューに各ペアを挿入します。 
3. 優先キューから最小の要素を繰り返し抽出します。 ペアのいずれかのクラスタがすでに別のクラスタにマージされている場合は、このエントリを破棄して続行します。 
4. 有効なペアが見つかったら、2 つのクラスターを新しいクラスターにマージします。その統計は、両方のクラスターの対応するフィールドを合計することによって取得されます。 
5. 新しいクラスターに、以前のすべてのクラスターよりも新しい経過時間を割り当てます。 
6. 新しく作成されたクラスターについて、同じ閉じた形式を使用して残りのすべてのアクティブなクラスターまでの距離を計算し、それらを優先キューにプッシュします。 
7. 新しいクラスターのサイズを出力します。 

正確さは、将来の距離に対するすべてのクラスターの寄与が、その集約された統計によって完全に捕捉されるという事実に依存します。 これらの概要が維持されれば、個々のポイントに関する情報は必要ありません。 優先キューには常にすべてのマージ候補が含まれており、遅延削除により、古いペアが結果に影響を与えないようにします。 マージごとに正しく要約されたクラスターが作成されるため、将来の距離計算は定義との一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def sq(x):
    return x * x

def dist(a, b):
    sa, sb = a["size"], b["size"]
    ax, ay, asq = a["sx"], a["sy"], a["ssq"]
    bx, by, bsq = b["sx"], b["sy"], b["ssq"]

    # sum ||a-b||^2 expanded
    cross = sa * bsq + sb * asq - 2 * (ax * bx + ay * by)
    return cross / (sa * sb)

n = int(input())
pts = []
for _ in range(n):
    x, y = map(int, input().split())
    pts.append((x, y))

clusters = []
alive = [True] * (2 * n)
age = 0

for i, (x, y) in enumerate(pts):
    clusters.append({
        "id": i,
        "size": 1,
        "sx": x,
        "sy": y,
        "ssq": x * x + y * y,
        "age": i
    })

heap = []

def push(i, j):
    d = dist(clusters[i], clusters[j])
    ai, aj = clusters[i]["age"], clusters[j]["age"]
    older = min(ai, aj)
    younger = max(ai, aj)
    heapq.heappush(heap, (d, older, younger, i, j))

for i in range(n):
    for j in range(i + 1, n):
        push(i, j)

next_id = n

for _ in range(n - 1):
    while True:
        d, a1, a2, i, j = heapq.heappop(heap)
        if alive[i] and alive[j]:
            break

    ni = next_id
    next_id += 1

    ci, cj = clusters[i], clusters[j]

    clusters.append({
        "id": ni,
        "size": ci["size"] + cj["size"],
        "sx": ci["sx"] + cj["sx"],
        "sy": ci["sy"] + cj["sy"],
        "ssq": ci["ssq"] + cj["ssq"],
        "age": max(ci["age"], cj["age"]) + 1
    })

    alive.append(True)
    alive[i] = alive[j] = False

    print(clusters[-1]["size"])

    for k in range(len(clusters) - 1):
        if alive[k]:
            push(len(clusters) - 1, k)
```この実装では、各クラスターを一定サイズの要約に圧縮するため、距離クエリはクラスター サイズに依存しません。 ヒープにはすべてのマージ候補が保存され、古いペアはアライブ配列を使用してフィルタリングされます。 age ルールはヒープ キーに直接エンコードされるため、抽出中に追加のロジックを使用せずにタイが解決されます。 

微妙な点は、古いヒープ エントリを積極的に削除することは決してないということです。 代わりに、それらを蓄積し、ポップされた場合にのみ破棄できるようにします。 これにより更新がシンプルになり、償却効率が保証されます。 

## 実用的な例

 単純な三角形を形成する 3 つの点を考えてみましょう。 初期化後、各ペアは計算された距離とともにヒープに挿入されます。 最小のペアが最初にマージされ、サイズ 2 のクラスターが生成されます。このクラスターから残りのシングルトンまでの距離は、個々のポイントを再検討することではなく、集約された統計から計算されます。 

| ステップ | 選択した結合 | クラスターのサイズ | アクション |
 | --- | --- | --- | --- |
 | 1 | 最も近い 2 つの星 | 2、1 | サイズ 2 にマージ |
 | 2 | 新しい星団 + 最後の星 | 3 | 最終マージ |

 このトレースは、表現によってペアごとの点の距離の再計算がどのように回避されるかを示しています。 

ここで、点が遠く離れているが、クラスターのサイズが異なるという縮退ケースを考えてみましょう。 距離はすべてのペアの平均を使用するため、平均二乗距離がサポートしない限り、大きなクラスターが自動的に優勢になることはありません。 すべての候補ペアが同じ正規化された式に基づいて評価されるため、ヒープによって正確さが保証されます。 

| ステップ | クラスターのサイズ | キーの距離の効果 |
 | --- | --- | --- |
 | 1 | 1,1,1,1 | すべてのペアは最初は等しい |
 | 2 | 2,1,1 | マージされたクラスターは加重平均を変更します。 
| 3 | 3,1 | 再計算された平均によって決定される最終的なマージ |

 これにより、完全な 2 番目の瞬間の追跡は有効なままですが、重心のみの推論は失敗することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² log n) | O(n²) 個の候補ペアがそれぞれ 1 回プッシュされ、ヒープ操作により log n のオーバーヘッドが発生します。 
| スペース | O(n²) | ヒープには、すべてのペア候補とクラスターのメタデータが格納されます。 

制限 n = 2000 では、約 400 万のペア評価が制限内で管理可能であり、ヒープ操作が実際的な制約内に留まるため、O(n² log n) が実現可能になります。

 ## 特殊なケース

 2 つの星の最小構成では、初期化後に更新を必要とせずにヒープの初期化と直接マージ ロジックが機能するかどうかをテストします。 アルゴリズムはただちに唯一のペアを選択し、サイズ 2 を計算して出力します。 

すべてのペアごとの距離が等しい対称構成では、タイブレーク ルールが重視されます。 すべての距離が一致するため、アルゴリズムは一貫してマージを選択するために経過時間の順序に依存する必要があります。 ヒープ キーには経過時間が含まれており、特殊な場合のロジックを使用せずに決定的な動作が保証されます。 

1 つのクラスターが大幅に大きくなるクラスター構成では、距離の集約が安定しているかどうかを早期にテストします。 距離は重心だけではなく二乗和と座標和に依存するため、マージされたクラスターは、個々の点を再計算しなくても、残りのクラスターと正しく相互作用し続けます。
