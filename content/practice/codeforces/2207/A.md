 ## 解決策
 ## 問題の理解

 バイナリ文字列と、繰り返し適用できる単一の操作が与えられます。 この操作は、厳密に文字列の内側にある位置にのみ影響し、その位置の両側が 1 で囲まれている場合にのみ影響します。 そのような位置が存在する場合は、0 または 1 で上書きできます。 

このプロセスは何度でも繰り返すことができるため、文字列は一連のローカルな変更を通じて進化しますが、変更が可能な唯一の場所は 2 つの 1 の間に「挟まれた」場所です。 

各テスト ケースでは、一連の有効な動きを適用した後、2 つの極端な値を決定する必要があります。 1 つは、最終的に得られる 1 の最小可能数であり、もう 1 つは、到達できる 1 の最大可能数です。 

制約は小さく、文字列の長さは最大 100、テスト ケースは最大 500 です。 これは、O(n³) または慎重に管理された O(n²) シミュレーションでも合格する可能性があることを意味しますが、操作構造がより単純な組み合わせ結果を示唆しているため、本当の目標はシミュレーションを完全に回避することです。 

単純な解釈では、到達可能なすべての文字列に対するすべての変換または BFS をシミュレートしようとする可能性があります。 n = 100 の場合でも、可能な文字列の数は指数関数的であり、すべての手が自明ではない方法で利用可能な手の構造を変更するため、これはすぐに実行不可能になります。 

孤立しているかまばらな場合、微妙なエッジケースが発生します。 たとえば、次のような文字列では`10101`、すべてのゼロはすでに 1 の間にあるため、複数の位置を編集できます。 単純な貪欲なフリップでは、そのようなポジションはすべて独立して設定できると想定されますが、その後のフリップでは、将来のポジションが有効なままであるかどうかが変更される可能性があります。 

主な難点は、操作が周囲の操作に依存しており、位置を変更すると、編集可能な位置が破壊されたり、さらに作成されたりする可能性があることです。 

## アプローチ

 ブルート フォース アプローチでは、BFS または DFS を使用して、到達可能なすべての文字列を探索しようとします。 各状態はバイナリ文字列であり、各遷移ではすべての有効なインデックスと両方の置換オプションが試行されます。 これによりプロセスが正しくモデル化されますが、指数関数的に増大する可能性のある状態空間が作成されます。 各状態には最大 n 個の遷移がありますが、実際には状態の数に制限がないため、非常に小さい n を超えると使用できなくなります。 

重要な観察点は、この操作では文字列全体に情報が自由に伝播されないということです。 両側のセグメントによってすでに「サポート」されているセグメントのみを変更できます。 これは、周囲の構造が変化しない限り、2 つの 1 の間にない 0 は永久に不活性であることを意味します。 

文字列の構造を見ると、ゼロで囲まれた連続領域の一部であるすべての 1 が、変更の潜在的な「アンカー」のように機能します。 1 が存在するセグメント内では、最大値が必要な場合は境界 1 間のすべての内部ゼロが最終的に 1 に変換され、最小値が必要な場合は選択的に 0 に変換されます。 

これにより、問題は、連続する 1 の実行と、それらの間で 0 がどのように相互作用するかを分析することになります。 このプロセスでは、新しい最も外側のものが作成されることはありません。 既存の境界内の構造を埋めるか破壊するだけです。 

最大のケースでは、1 の間に挟まれたすべての 0 が 1 に変わる可能性があり、一度それが起こると、さらに充填が伝播される可能性があります。 最終的には、影響の端でブロックされているものを除き、1 の接続されたコンポーネントの内部または間にあるすべての位置が充填可能になります。 

最小限のケースでは、操作を可能にする接続を維持するために構造的に必要なものがあることを尊重しながら、できるだけ多くのものを切断したいと考えています。 最適な戦略は、最終的に 1 の各最大セグメントをより小さな代表的な構造に縮小し、事実上、境界制約のみをそのまま残します。 

これを慎重に形式化した後、解決策は 1 の構造セグメントを数え、1 に隣接することによって「アクティブ化」されるゼロの数を決定することに帰着します。

 ## アルゴリズムのチュートリアル

 最大値と最小値は反対の意図から来ているため、最大値と最小値の推論を独立して分離します。 

### 1 の最大数

 1. 変更のために最初に到達可能なすべての位置を特定します。つまり、プロセスのある時点で 2 つの位置の間に位置します。 
2. ゼロが 1 で囲まれると、それを 1 に変えることができ、これにより影響範囲が外側に広がる可能性があることに注目してください。 
3. これは、少なくとも 2 つの 1 を含むセグメントは最終的にそのスパン全体で 1 に完全に変換できることを意味します。 
したがって、最終的な最大値は、最初の影響領域によって形成されたすべての接続された影響領域を拡張し、反復拡張で到達可能になるすべての位置をカウントすることによって取得されます。 

これを計算する実際的な方法は、閉包プロセスをシミュレートすることです。変化が起こらなくなるまで、両側に 1 を持つゼロを繰り返し 1 としてマークします。 nが小さいのですぐに安定します。 

### 1 の最小数

1. できるだけ多くのものを破壊したいという観察から始めます。 
2. 分離されているものは、他の場所での操作をサポートする必要がある場合があるため、常に削除できるわけではありません。 
3. 重要な構造は、ゼロで区切られた 1 の連続です。 このような各実行は減らすことができますが、他の場所で隣接関係を有効にする必要がある場合は完全に削除することはできません。 
4. 最小値は、最終的には、必須の境界値のみを保持し、拡張可能な領域内の冗長な内部境界値を削除することに対応します。 

これをわかりやすく表現する方法は、パターンを見るたびに、`1 0 1`、その中心のゼロを「使用」して、隣接するものの 1 つの冗長性を排除し、制御されたセグメントの折りたたみによって総数を効果的に削減できます。 

最終的な結果は、最初のものを数え、これらのパターンによって引き起こされる削除可能なものの最大数を減算することによって得られます。 

### なぜ効果があるのか

 不変条件は、構造を変更する唯一のメカニズムが、両側に 1 を持つ位置を中心とするローカル トリプルであるということです。 これは、影響力が常に既存のものを介して伝播し、サポートなしにゼロを飛び越えることは決してないことを意味します。 その結果、文字列は最初の 1 つの位置によって制御される独立したセグメントに分解され、各セグメント内でプロセスは飽和するか、部分的に崩壊することしかできません。 これにより、境界領域内でのマージや充填を超えたグローバルな再配置が防止され、結果は操作のシーケンスではなくローカルの隣接構造のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ones = s.count('1')

        # find segments of consecutive 1s
        segments = []
        i = 0
        while i < n:
            if s[i] == '1':
                j = i
                while j < n and s[j] == '1':
                    j += 1
                segments.append((i, j - 1))
                i = j
            else:
                i += 1

        if ones == 0:
            print(0, 0)
            continue

        # minimum: check if there exists a '0' between two 1s
        # such zeros allow merging structure and reducing redundancy
        min_ones = ones

        for i in range(1, n - 1):
            if s[i] == '0' and s[i - 1] == '1' and s[i + 1] == '1':
                min_ones -= 1

        # maximum: fill all zeros that are inside any segment influence
        # effectively, any zero that lies between first and last 1 can become 1
        first = s.find('1')
        last = s.rfind('1')

        max_ones = ones + (last - first + 1 - ones)

        print(min_ones, max_ones)

if __name__ == "__main__":
    solve()
```コードは最初に 1 の合計数を数えます。これは、両方の答えがそこから導出されるからです。 次に、連続するセグメントの構造セグメントを特定します。ただし、これらは最終的な式に厳密には必要ありませんが、概念的に構造を理解するのに役立ちます。 

最小値の場合、1 が直接隣接する 0 から寄与分が減算されます。 これらのポジションは、重複を削減する操作に即座に参加できる唯一のポジションであるため、そのような各パターンは潜在的な削減に貢献します。 

最大値の場合、影響は 1 の最初の出現から最後の出現まで拡大されます。 その間隔内のすべての位置は反復伝播によって到達可能になるため、その範囲内のすべての 0 を 1 に変換でき、単純な間隔の完了につながります。 

エッジ処理は、エッジがまったくない場合に非常に重要です。これは、演算を適用することができず、両方の答えがゼロになるためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ones = s.count('1')

        if ones == 0:
            out.append("0 0")

        last = s.rfind('1')
        max_ones = ones + (last - first + 1 - ones)

        out.append(f"{min_ones} {max_ones}")

    return "\n".join(out)

 ## 特殊なケース

 条件には周囲に 2 つの文字列が必要であるため、1 のない文字列は操作をトリガーしません。 アルゴリズムは、次の値を返すことでこれを直接処理します。`0 0`また、スキャンベースのロジックは無効な間隔の計算を安全に回避します。`find('1')`返品`-1`。

のような文字列`10001`は、最初と最後の間のセグメントのみが最大値として重要であることを示しています。 アルゴリズムはこの間隔全体を拡張し、完全なカバレッジを正しく生成します。 

のような文字列`101010`繰り返される局所パターンを示します。 それぞれ`101`最小値と区間の約定可能性に独立して寄与します。`[first, last]`到達可能なすべての拡張を最大限に正確にカバーします。
