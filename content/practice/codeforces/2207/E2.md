 ## 解決策
 ## 問題の理解

 一連のネストされた MEX 条件を満たす非負の整数の配列を数えるように求められます。 具体的には、配列が与えられます`a`長さの`n`。 ポジションごとに`i`配列内で、`(n-i+1)`プレフィックスの - 番目の MEX`[b_1, ..., b_i]`等しい`a[i]`。 ここで、`k`セットの - 番目の MEX は`k`-番目に小さい非負の整数がセット内に存在しません。 それぞれ`b[i]`満たさなければなりません`0 <= b[i] <= n`。 出力は有効な配列の数を法的に表したものです。$10^9 + 7$。 

この制約により、総当たり的なアプローチは実行不可能になります。 の合計`n`すべてのテストケースにわたって、`2 * 10^5`、だから、`O(n^2)`アルゴリズムは大まかに実行します`4 * 10^{10}`制限時間を超えた操作。 テスト ケースごとに効果的に線形または線形に近いソリューションが必要です。 エッジ ケースには、MEX 値が繰り返されるか減少する配列、または必要な MEX が不可能なシーケンスが含まれます。 例えば、`a = [2, 1, 3]`MEX 制約が競合するため、解決策がありません。 

## アプローチ

 ブルートフォース手法では、考えられるすべての配列を生成しようとします。`b`MEX 条件を確認します。 これは原理的には正しいですが、明らかに遅すぎます。 すべてのシーケンスの構築`b`長さの`n`収量$(n+1)^n$可能性は指数関数的に大きくなります。 各プレフィックスの評価`k`-MEX では、候補配列ごとに次の係数が追加されます。`n`、これを実行不可能にします。 

重要な洞察は、`(n-i+1)`-番目の MEX 制約。 配列の末尾から逆方向に作業することができます`a`、どの値が許可されるかについての推論`b[i]`将来の MEX 条件を満たすため。 各 MEX レベルの「利用可能な数値」のカウントを維持することにより、各ステップで選択肢の数を増やすことができ、列挙ではなく組み合わせカウントを効果的に実行できます。 この問題は、各整数が何回出現できるかを追跡しながら、MEX 順序を維持する整数の有効な配置をカウントすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+1)^n * n) | O(n) | 遅すぎる |
 | 最適な計数 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を反転します`a`プレフィックスの自然な順序と一致するようにします。 させて`a_rev[i] = a[n-i]`。 これにより、次の最初の要素から制約を処理できるようになります。`b`最後までプレフィックスロジックに合わせて調整します。 
2. トラック`count[x]`可能な値ごとに`x`から`0`に`n`。 最初はすべてのカウントがゼロです。 それぞれ`count[x]`まだ何回配置できるかを表します`x`配列内で`b`必要な MEX に違反することなく。 
3. 変数を初期化する`total_ways`この変数は、各選択肢の数の積を累積します。`b[i]`。 
4. 反復処理する`i = 0`に`n-1`以上`a_rev`。 ステップで`i`、MEX 要件`a_rev[i]`すべての整数が以下であることを指示します`a_rev[i]`プレフィックスに少なくとも 1 回出現する必要があります`[b_1, ..., b_i]`。 したがって、利用可能なオプションの数は、`b[i]`は`count[a_rev[i]]`、この値がすでに出現し、再利用できる回数を表します。 
5. 乗算`total_ways`による`count[a_rev[i]]`モジュロ$10^9 + 7$。 配置後`b[i] = a_rev[i]`、増分`count[a_rev[i]]`この値がもう一度使用されたことを反映します。 
6. どこかの段階で`count[a_rev[i]]`がゼロの場合、MEX 要件を満たすことができません。 セット`total_ways`ゼロにして早めにブレイクする。 
7. すべてのポジションを処理した後、`total_ways`配列の総数が含まれます`b`すべての条件を満たしていること。 

不変条件は、各ステップで`i`、`count[x]`値の何倍かを正しく反映します`x`MEX 要件に違反することなく配置できます。 これにより、次の乗算が保証されます。`count[a_rev[i]]`過剰にカウントしたり欠落したりすることなく、すべての有効な構成を累積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b_rev = a[::-1]
        count = [0] * (n + 2)
        total_ways = 1
        for x in b_rev:
            if x > n:
                total_ways = 0
                break
            total_ways = total_ways * max(1, count[x]) % MOD
            count[x] += 1
        print(total_ways)

if __name__ == "__main__":
    solve()
```このソリューションは入力を効率的に読み取り、配列を反転してプレフィックスを自然に処理し、カウント配列を使用して利用可能な配置を追跡します。 の`max(1, count[x])`値が最初に出現したときにも、有効な配置が 1 つだけ考慮されるようにします。 オーバーフローを防ぐために、乗算のたびにモジュロ演算が適用されます。

 ## 特殊なケース

 配列の場合、`a[i]`を超える`n`、アルゴリズムはこれを直ちに検出し、`total_ways`ゼロに。 例えば、`a = [5]`と`n = 3`有効な情報を生成できません`b`サイズ 1 の配列では MEX を 5 にすることはできないためです。 同様に、大きな値が繰り返されるシーケンスは count 配列によって処理され、各ステップで選択肢が正しく乗算されます。 このソリューションは、長さ 1 のシーケンス、値がすべて等しいシーケンス、および特別な場合を除いて厳密に増減する MEX シーケンスを自然に処理します。
