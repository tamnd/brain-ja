 ## 解決策
 ## 問題の理解

 この問題により、Zuko がランクと色の組み合わせごとに 1 枚ずつ、すべてのカードを 1 列に保持する hanabi のようなカード ゲームが得られます。 Iroh にはカードが見えますが、Zuko には見えません。 Iroh のターンでは、特定のランクのすべてのカード、または特定の色のすべてのカードをハイライト表示することでヒントを与えます。 次に、Zuko は左端の強調表示されたカードをプレイします。 ゲームは、すべてのカードが各色のランクごとに正しい順序でプレイされるまで、手がかりとプレイを交互に繰り返します。 ランクのカードをプレイする$r \ge 2$同じ色の前のランクがプレイされる前にプレイすることは違法です。 

目標は、Iroh の手がかりが前のターンから変更される回数を最小限に抑えながら、すべてのカードが合法的にプレイされるように手がかりのシーケンスを設計することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースが提供するのは、$n$ランクと$m$色のリストに続いて、$n \cdot m$Zuko の手札に表示されるカードのランクと色。 出力は、ゲーム全体で手がかりが変更される最小回数です。 

制約により最大で許可されるのは、$2 \cdot 10^5$すべてのテスト ケースの合計カード。 これは、以上のアルゴリズムを意味します。$O(n \cdot m)$複雑さが遅すぎるため、二次アプローチは実行不可能です。 

単純なエッジケースは、単一ランクのすべてのカードが連続して出現する場合です。 たとえば、すべてのランク 1 カードがすでに手札内で連続している場合、それらすべてを順番にプレイするために手がかりを変更する必要はありません。 ターンごとに手がかりを切り替える不注意なアプローチでは、変更が過大評価され、間違った答えが生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームをシミュレートし、すべてのターンで考えられるすべての手がかりを発行し、Zuko のプレイ順序を追跡し、手がかりの変更を数えようとします。 これは原理的には正しいですが、各ターンですべてのカードと潜在的な手がかりを調べる必要があります。 まで$2 \cdot 10^5$カードの数が増えると、操作の数が爆発的に増加します。$O((n \cdot m)^2)$、それは不可能です。 

重要な洞察は、一連のプレイが各色のランクの増加に従う必要があることに気づくことから得られます。 これは、手を色のランクが増加する一連の「ブロック」として扱うことができることを意味します。 色の前のランクがプレイされた最新の位置を追跡すると、Iroh が手がかりを切り替えなければならない最小の手数を決定できます。 具体的には、問題は、手を昇順に移動するときの単調セグメントの最小数を見つけることに帰着します。 各カードに色ごとに「ランク順インデックス」を割り当て、このインデックス シーケンスが何回減少するかを数えることができます。 それぞれの減少は、必要な手がかりの変更に対応します。 これにより、問題は次のように変換されます。$O(n \cdot m)$シーケンス処理タスク。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((n*m)^2) | O(n*m) | 遅すぎる |
 | ランク順 | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$m$そしてハンドはランクと色のリストとして表示されます。 
2. 各色をランクの位置リストにマッピングする辞書を構築します。$1$に$n$。 これにより、色ごとの各ランクのプレイ順序を決定することができます。 
3. 各色について、各カードに「昇順のランク順」インデックスを割り当てます。これは、ランク 1 のカードが 1、ランク 2 のカードが 2 などを意味します。 
4. 手の中の各カードを、色順の対応するインデックスに置き換えます。 これにより、問題は、この新しい配列内の厳密に増加するシーケンスの最小数をカウントすることに変換されます。 
5. 変形した手を左から右に移動します。 各色の最後のインデックス値を維持します。 現在のカードのインデックスが同じ色の最後のカード以下になるたびに、必要な手がかりの変更の数が増加します。 これは、Iroh が Zuko が正しくプレイしていることを確認するために手がかりを切り替える必要があるポイントを捉えています。 
6. テスト ケースの手掛かり変更の合計数を出力します。 

ここで不変なのは、不正なプレイを避けるために、各色内でハンド内のランク インデックスのシーケンスが減少していなければならないということです。 減少をカウントすると、変更を最小限に抑えながら合法性を維持するために必要な手掛かり変更の正確な数がわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        ranks = list(map(int, input().split()))
        colors = list(map(int, input().split()))
        pos_in_color = [[] for _ in range(m + 1)]
        
        for i in range(n * m):
            pos_in_color[colors[i]].append((ranks[i], i))
        
        index_in_color = [0] * (n * m)
        for c in range(1, m + 1):
            # Sort by rank to get correct play order
            pos_in_color[c].sort()
            for order, (_, idx) in enumerate(pos_in_color[c]):
                index_in_color[idx] = order + 1
        
        res = 0
        last = 0
        for i in range(1, n * m):
            if index_in_color[i] < index_in_color[i - 1]:
                res += 1
        print(res)

solve()
```このコードでは、まずランクごとにソートされたカードの色ごとのリストを作成します。 次に、各カードを色の順序に置き換えます。 最後に、ハンドのカウントが順番に減少し、それぞれが必要な手がかりの変化を表します。 

微妙な点としては、ランク順の 1 ベースと 0 ベースのインデックス付け、および手がかりの変更なしで非減少シーケンスが許容されるため、均等ではなく減少を注意深く追跡することが含まれます。
