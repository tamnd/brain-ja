 ## 解決策
 ## 問題の理解

 私たちは、危険管理の観点から、フレディ・ファズベアのピッツェリアでの夜をシミュレートするよう求められました。 各アニマトロニクスは毎秒危険を蓄積し、夜は一定の秒数続きます。 プレイヤーは、あらかじめ決められた時間に限られた数の「懐中電灯アクション」を行うことができ、それぞれのアクションで 1 つのアニマトロニクスの危険性をゼロにリセットできます。 目標は、最小の最大危険レベルを見つけることです`x`アニマトロニクスがどのように攻撃を分散させても、懐中電灯を最適に使用することで最終的な危険レベルを以下に保つことができます。`x`。 

入力には複数のテスト ケースが記述されており、各テスト ケースには懐中電灯の使用回数、アニマトロニクスの数、夜の長さ、懐中電灯が使用できる時間が示されています。 各テスト ケースの出力は単一の整数、つまり最小値です。`x`それは安全を保証します。 

この問題には限界があります。 すべてのテスト ケースにわたる合計秒数とアニマトロニクスの数の積は 2×10^5 に制限されており、各アニマトロニクスの 1 秒ごとを直接シミュレートしようとするソリューションは除外されます。 これにより、単純な秒ごとのシミュレーションが即座に除外されます。 段階的なシミュレーションではなく、カウントまたは間隔に基づいた戦略を使用する必要があります。 

エッジケースには、懐中電灯の動作の数が非常に少ない場合、アニマトロニクスの数よりも少ない可能性がある場合、または夜間の長さが極端に短いまたは極端に長い場合が含まれます。 たとえば、最後に 1 つのアニマトロニクスと 1 つの懐中電灯を使用した場合、最終的な危険は、最後の懐中電灯から何秒後に発生するかによって完全に異なります。 これが考慮されていない場合、単純なアプローチでは、危険があまりにも早くリセットされると誤って想定される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各アニマトロニクスの危険レベルを毎秒追跡し、適切なタイミングで懐中電灯の動作を適用します。 これは原理的には正しいですが、次の場合には遅すぎます。`m * ℓ`2×10^5に達します。 

重要な観察は、私たちが最後に直面する最大の危険は、連続して懐中電灯を使用するまでの秒数と、アニマトロニクスの数によってのみ決まるということです。 懐中電灯は夜をいくつかの間隔に分割すると考えることができます。 各インターバル内で、アニマトロニクスは単一のアニマトロニクスの危険性を貪欲に増大させることを選択できます。 したがって、長いインターバルの後に最後の危険が`t`と`m`アニマトロニクスは天井です`t/m`- 危険の増大を常に可能な限り均等に分散できます。 

したがって、問題は、フラッシュ間の間隔の最大長を計算し、それをアニマトロニクスの数で割って切り上げ、すべての間隔の最大値を取ることに帰着します。 最初の間隔は時間ゼロから始まり、最後の間隔は最後の懐中電灯から夜の終わりまでとなります。 この間隔ベースの貪欲なアプローチにより、1 秒ごとのシミュレーションの必要性がなくなり、テスト ケースごとに O(n) で機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * ℓ) | O(m) | 遅すぎる |
 | インターバル / 貪欲 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`max_interval`フラッシュライトの連続使用間の最大ギャップを保存します。 最初の間隔から開始します`a[0]`（開始から最初のフラッシュまでの秒数）。 
2. フラッシュライトの時間を繰り返します。 連続するペアごとに`(a[i-1], a[i])`、間隔の長さを次のように計算します。`a[i] - a[i-1] - 1`。 アップデート`max_interval`この間隔が大きい場合。 
3. すべてのフラッシュを処理した後、最後のフラッシュライトから夜の終わりまでの最終間隔を処理します。`ℓ - a[-1]`。 アップデート`max_interval`必要に応じて。 
4. 最小限に保証される最大の危険性`x`の天井です`max_interval / m`。 これは、すべてのアニマトロニクス間で危険の増加を可能な限り均等に分散するためです。 Python の整数は上限除算をサポートしているため、`(a + b - 1) // b`, この手順は簡単です。 
5. 計算結果を出力します。`x`。 

機能する理由: このアルゴリズムは、リセット間の最大のギャップが単一のアニマトロニクスの最悪の場合の累積を決定するという不変条件を維持します。 合計間隔の増加を可能な限り均等に分割することで、アニマトロニクスが計算された危険を超えないことを保証します。 天井分割により、間隔を均等に分割できない場合でも、残りの部分は一部のアニマトロニクスにとって追加の危険としてカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, m, l = map(int, input().split())
        a = list(map(int, input().split()))
        max_interval = a[0] - 0
        for i in range(1, n):
            max_interval = max(max_interval, a[i] - a[i-1] - 1)
        max_interval = max(max_interval, l - a[-1])
        result = (max_interval + m - 1) // m
        print(result)

if __name__ == "__main__":
    main()
```コードは最初にテスト ケースの数を読み取ります。 テストケースごとに、フラッシュの数、アニマトロニクスの数、夜間の長さ、懐中電灯の点灯時間を読み取ります。 の`max_interval`計算では、リセットせずに危険が蓄積する可能性がある最大の時間間隔が正確に取得されます。 最終的な危険度は、この間隔をアニマトロニクス全体で分割し、切り上げて求められます。 

微妙なポイントとしては、`a[i] - a[i-1] - 1`連続するフラッシュ間の間隔を正確に計算し、開始間隔と終了間隔を個別に処理します。 

## 実用的な例

 **例 1:**`n=1, m=2, l=10, a=[10]`| 間隔 | 計算 | 最大間隔 |
 | --- | --- | --- |
 | 開始 | 10-0=10 | 10 |
 | 終わり | 10-10=0 | 10 |
 | x = 天井(10/2) | 5 | 5 |

 唯一のフラッシュは最後の 1 秒で発生するため、最初のアニマトロニクスは最大 5 つの危険を蓄積でき、フラッシュによってリセットされ、最終的な危険は 5 になります。 

**例 2:**`n=2, m=3, l=40, a=[13,37]`| 間隔 | 計算 | 最大間隔 |
 | --- | --- | --- |
 | 開始 | 13-0=13 | 13 |
 | フラッシュの間 | 37-13-1=23 | 23 |
 | 終わり | 40-37=3 | 23 |
 | x = 天井(23/3) | 8 | 8 |

 最悪の間隔はフラッシュ 13 と 37 の間です。23 秒を 3 つのアニマトロニクスに分割すると、最小最大危険度である天井 8 が得られます。

 ## 特殊なケース

 すべてのフラッシュが最後に発生する場合、最初の間隔が長くなる可能性があります。 例えば、`n=1, m=2, l=10, a=[10]`結果は max_interval = 10 になります。アニマトロニクスを 2 で割ると 5 となり、これは直感と一致します。 フラッシュが均等に分布しているがアニマトロニクスの数で割り切れない場合、天井分割により、計算された危険を超えるアニマトロニクスが存在しないことが保証されます。 アルゴリズムはこれらの境界条件を正しく処理します。
