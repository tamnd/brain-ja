 ## 解決策
 ## 問題の理解

 配列を構築するように求められます`b`指定された配列から`a`次のように、各プレフィックスに対して、`b`、一般化された MEX 条件が成り立ちます。 具体的には、`(n-i+1)`最初の - 番目の MEX`i`の要素`b`等しい必要があります`a[i]`。 の`k`マルチセットの -MEX は、`k`- 番目に小さい非負の整数が欠落しています。 たとえば、1-MEX は存在しない最小の非負整数、2-MEX は欠落している中で 2 番目に小さいなどです。 

入力は一連のテスト ケースであり、各テスト ケースは配列で構成されます。`a`。 次のいずれかを出力する必要があります`YES`有効な配列`b`、 または`NO`そのような配列が存在しない場合。 配列`b`までの値を含めることができます`10^9`これは、MEX 計算での競合を避けるために非常に大きな整数を使用できるため重要です。 

制約が示すのは、`n`到達できる`2 * 10^5`の合計となります。`n`すべてのテストケースにわたって、以下に限定されます`2 * 10^5`。 これにより、線形より悪いアルゴリズムが排除されます。`n`テストケースごとに。 各プレフィックスに対して単純に MEX を計算すると二次関数となり、タイムアウトになります。 

次の場合には、明らかではないエッジケースが発生します。`a`減少が速すぎるか、使用可能な整数で表現できないギャップが含まれています。 例えば、`a = [2, 1, 3]`最初の要素は要素を 1 つだけ含む 3-MEX を要求しており、すでに矛盾しているため、これは不可能です。 欠落している数値の相対的な順序を無視する不注意な貪欲な割り当てでは、無効な配列が生成されます。 

## アプローチ

 ブルートフォースアプローチは、あらゆる可能性を試すことです`b`配列を調べて、すべてのプレフィックスの MEX 条件を確認します。 これは、長さのすべてのシーケンスを生成できるため、原理的に機能します。`n`各プレフィックスの MEX を確認します。 ただし、シーケンスの数は次のように指数関数的に増加します。`n`、したがって、`n = 20`、それはすでに非現実的です。 最悪の場合の操作数は次のようになります。`O(10^9^n * n^2)`それは完全に不可能です。 

重要な洞察は、次のことを構築できるということです。`b`どの数値が使用されているか、そして MEX 条件を満たすために次にどの数値が出現する必要があるかを維持することで、貪欲に実行できます。 MEX の定義を考えてみましょう。`k`-番目の欠落している数値は、すでに存在する整数の数にのみ依存します。 加工できます`a`最後の要素から最初の要素までです。プレフィックスの MEX 条件は、その前にある数字に依存するためです。 こうすることで、番号を割り当てることができます。`b`バックトラックすることなく MEX 条件を保証する方法で。 

このアルゴリズムは、安全に使用できる整数 (将来の MEX 要件を妨げない整数) の「プール」を維持し、各位置に、MEX が正しいことを保証する数値、または干渉しない大きな数値のいずれかを割り当てます。 いずれかの時点で、必要な数値がすでに誤って使用されている場合、配列は不可能であると宣言されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((max_b)^n * n^2) | O(n) | 遅すぎる |
 | 貪欲な建設 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の配列を初期化する`b`長さの`n`。 カウンターを維持するか、これまでに配列内でどの数値が使用されたかを追跡するように設定します。 
2. の最後の要素から反復します。`a`最初に。 これは、次のプレフィックスを考慮することに対応します。`b`逆に、これは以下に応じて MEX 定義と一致します。`(n-i+1)`。 
3. ポジションごとに`i`、ターゲット MEX 値を計算します`a[i]`。 位置に表示する必要がある数値を決定します`i`を満たすために`(n-i+1)`-で終わるプレフィックスの -th MEX`i`。 MEX 番号が将来の割り当てと競合する方法ですでに使用されている場合、配列は不可能です。 
4. 目的の MEX を達成するために必要な数値、または大きな整数 (次のように) を割り当てます。`10^9`) 将来の MEX 計算に干渉しません。 複数の数値が条件を満たす場合は、そのうちの 1 つが有効です。 
5. すべての位置を埋めた後、プレフィックスのすべての MEX 制約が満たされていることを確認します。 その場合は印刷してください`YES`そして配列`b`; それ以外の場合は、印刷します`NO`。 

このアルゴリズムが機能するのは、割り当てられた各番号がそのプレフィックスの MEX を満たすことに寄与するか、MEX に影響を及ぼさない十分な大きさによって安全に無視されるかのいずれかを保証するためです。 逆に反復することで、前の要素に対する MEX の依存関係が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        used = set()
        b = []
        next_large = 10**9
        possible = True
        
        # We'll process from end to start
        for ai in reversed(a):
            if ai in used:
                b.append(next_large)
                next_large -= 1
            else:
                b.append(ai)
                used.add(ai)
        
        b.reverse()
        # Validate MEX conditions greedily
        current_set = set()
        valid = True
        for i in range(n):
            current_set.add(b[i])
            mex = 0
            missing_count = 0
            while True:
                if mex not in current_set:
                    missing_count += 1
                    if missing_count == n - i:
                        break
                mex += 1
            if mex != a[i]:
                valid = False
                break
        
        if valid:
            print("YES")
            print(" ".join(map(str, b)))
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```コードの最初の部分は、複数のテスト ケースの読み取りを効率的に処理します。 建設ループが満たされます`b`最後から最初まで、各数値が MEX を満たすか、大きなフィラーであることを確認します。 検証ループは、正確さを保証するために各プレフィックスの MEX を再計算します。 の使用`next_large`以前の MEX 要件によってすでに修正されている数値の競合を回避します。 

## 実用的な例

 **例 1:**

 入力`a = [3, 3, 1]`| ステップ | 私 | a[i] | 割り当てられた b[i] | 中古 | これまでのところ |
 | --- | --- | --- | --- | --- | --- |
 | 3 | 2 | 1 | 1 | {1} | [1] |
 | 2 | 1 | 3 | 3 | {1,3} | [3,1] |
 | 1 | 0 | 3 | 10^9 | {1,3} | [10^9,3,1] |

 反転後、`b = [10^9,3,1]`。 MEX 検証により確認されるのは、`[3,3,1]`満足しています。 

**例 2:**

 入力`a = [2,1,3]`を満たすために数値を割り当てるため、逆の処理は失敗します。`a[2]=3`と衝突する`a[1]=1`。 アルゴリズムは正しく出力します`NO`。
