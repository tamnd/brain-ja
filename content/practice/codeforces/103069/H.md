 ## 解決策
 ## 問題の理解

 私たちには、Aus、風船、キャンディーという 3 つの交換可能なリソースを備えたシステムが与えられています。 当初、パン教授はちょうど 1 つの Au を持っており、他の 2 つはゼロです。 固定交換ルールを使用してこれらのリソース間の変換を許可するストアが 2 つあります。 

風船ストアでは、Au 1 つで一定数の風船と交換でき、キャンディ 1 つで一定数の風船と交換することもできます。 キャンディーストアでは、Au 1 つで一定数のキャンディーと交換でき、風船 1 つで一定数のキャンディーと交換できます。 買うだけでなく、売る操作もあり、風船は一定量の Au で売ることができ、キャンディーは一定量の Au で売ることができます。 

各操作は 1 単位の入力リソースを消費し、固定量の出力リソースを生成します。 また、ストアでは、購入できるバルーンとキャンディーの合計数にグローバル制限を設けているため、プロセス全体を通じて、購入操作で nb 個のバルーンと nc 個を超えるキャンディーを入手することはできません。 売っても供給は補充されない。 

目標は、これらの変換の任意の順序を選択して、最終的な Au 量を最大化することです。 

制約は重要です。nb と nc は 10^9 に達する可能性があるため、トランザクションを 1 つずつシミュレートする戦略は不可能です。 ただし、すべての為替レートは 100 までの小さな定数であり、このことは、問題の構造が nb と nc の大きさではなく、小さな状態空間によって駆動されることを強く示唆しています。 

単純なアプローチでは、考えられるすべての交換シーケンスをシミュレートしようとしますが、各ステップで有効な選択肢に限定しても、指数関数的な分岐プロセスが発生します。 隠されたサイクルにより、地元の収益性の高い取引所が数ステップ後に収益性を失う可能性があるため、貪欲なシミュレーションさえも危険です。 

周期的な交換が存在する場合、微妙な失敗のケースが発生します。 たとえば、Au が風船を安く購入でき、風船を効率よくキャンディーに変換でき、キャンディーをより良いレートで Au に売り戻すことができるとします。 オペレーションごとの当面の利益のみを考慮する貪欲な戦略は、複数のコンバージョンを連鎖させることでサイクルごとに純利益が得られるという事実を見落とす可能性があります。 

もう 1 つの特殊なケースは、リソースの上限に起因します。 たとえ収益サイクルがあったとしても、それを活用できるのはストアから消費されるnbバルーンとncキャンディーまでです。 これらの上限を無視したソリューションは、裁定取引が無限に繰り返されることを想定し、利益を過大評価することになります。 

## アプローチ

 この問題は基本的に、3 つのノードを持つ小さな有向交換グラフの値を最大化することに関するものです。 各ノードはリソースを表し、各有向辺はリソースの 1 単位を固定量の別のリソースに変換することを表します。 これは、パスに沿った乗算ゲインの観点から考えることをすぐに示唆します。 

ブルートフォース手法では、1 つの Au から始まるすべての一連の操作をシミュレートし、nb および nc 制約を遵守するために消費された風船とキャンディーの数を追跡します。 各状態は現在の保有量と残りの供給量を保存する必要があり、移行は有効な交換の適用に対応します。 風船やキャンディーの数で状態を離散化したとしても、nb と nc は最大 10^9 であるため、状態空間は膨大になります。 このアプローチは実行不可能です。 

重要な観察は、システムには 3 つの状態と線形交換ルールしかないことです。 これは、長い一連の操作をリソース間の単純な交換パスの組み合わせに分解できることを意味します。 特に、直接変換を超えて唯一意味のある構造は、Au、風船、キャンディの間に収益サイクルが存在するかどうかです。

グラフにはノードが 3 つしかないため、すべての中間パスを考慮することで、任意の 2 つのリソース間の最適な変換係数を計算できます。 これは、小さなグラフで最適な乗法重みを計算することと同じであり、少数の固定数の緩和で実行できます。 

すべてのペア間の最良の実効変換率がわかれば、問題は、nb と nc によってのみ制限される特定の変換方向にできるだけ多くのフローを押し込むことが有益かどうかを判断することになります。 

次に、2 つの体制を比較します。1 つは裁定取引を行わずに単に停止する体制、もう 1 つは利益が増加するたびに利用可能な風船またはキャンディーの供給を完全に消費するために最適な変換サイクルを利用する体制です。

 ## アルゴリズムのチュートリアル

 1. Au、バルーン、キャンディーを表す 3 つのノードを持つ有向グラフとしてシステムをモデル化します。 各演算は、変換係数に等しい重みを持つ有向エッジになります。 これにより、一連の操作をこのグラフ内のパスとして再解釈できるようになります。 
2. 順序付けされたノードのペアごとに可能な限り最良の変換係数を計算します。 ノードが 3 つしかないため、改善が不可能になるまで一定回数、すべてのエッジを安全に緩和できます。 私たちが維持する値は、あるリソースから別のリソースへの最もよく知られた乗算ゲインです。 
3. 最良の変換率を計算した後、サイクルを通じて Au をそれ自体に変換することの直接的な収益性を評価します。 これは、積が 1 より大きい Au で開始および終了するサイクルが存在するかどうかを確認することに対応します。 そのようなサイクルが存在しない場合、交換シーケンスは価値を減らすだけであるため、最良の答えは最初の Au を保持することです。 
4. 収益性の高いサイクルが存在する場合、それがリソースの上限とどのように関係するかを判断します。 風船やキャンディーを増やす戦略はすべて nb と nc を尊重する必要があるため、最大で nb の風船購入操作と nc のキャンディー購入操作が使用できるという制約の下で、達成可能な最良のゲインを計算します。 これにより、Au に由来するエッジをそれらのリソースに横断できる回数が事実上制限されます。 
5. 計算された最適な為替レートを使用して、バルーン ベースのコンバージョンとキャンディ ベースのコンバージョンを完全に活用することが有益であるかどうかを判断します。 各資源方向で利用可能な有用な供給をすべて消費することで得られる最良の最終 Au を計算し、それを 1 Au のベースラインと比較します。 
6. 何もしない場合や最適な変換パスを完全に活用する場合など、すべての有効な戦略の中で最大値を返します。 

### なぜ効果があるのか

 重要な不変条件は、どの一連の操作も 3 つのリソース間のペアごとの最適な変換の組み合わせに還元できるということです。 ノードが 3 つしかないため、長いパスはより単純なパスに分解されるか、サイクルを形成します。 すべてのサイクルは、正味乗算ゲインによって要約でき、ゲインが 1 つより大きいサイクルのみが問題となります。 パスのすべてのセグメントを可能な限り最高の等価ゲインに置き換えると、最適な戦略は、限られた各リソースの上限を最も収益性の高い方向に沿って消費する量を選択することと同等になります。 これにより、隠れた一連の操作が計算された最良の遷移を上回るパフォーマンスを発揮できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        nb, nc, kab, kba, kac, kca, kbc, kcb = map(int, input().split())

        # nodes: 0 = Au, 1 = balloon, 2 = candy

        # best direct conversions (multiplicative gains)
        # we work in "value in Au" terms implicitly by cycle improvement checking

        # start with identity-like values
        # dist[i][j] = best factor from i to j
        dist = [[0.0] * 3 for _ in range(3)]

        for i in range(3):
            dist[i][i] = 1.0

        # Au -> balloon, Au -> candy
        dist[0][1] = kab
        dist[0][2] = kac

        # balloon -> Au, balloon -> candy
        dist[1][0] = kba
        dist[1][2] = kbc

        # candy -> Au, candy -> balloon
        dist[2][0] = kca
        dist[2][1] = kcb

        # Floyd-Warshall for multiplicative gains (max-product)
        for k in range(3):
            for i in range(3):
                for j in range(3):
                    if dist[i][k] * dist[k][j] > dist[i][j]:
                        dist[i][j] = dist[i][k] * dist[k][j]

        # check best cycle starting from Au
        best = 1.0
        best = max(best, dist[0][0])

        # try exploiting capped resources
        # option 1: use balloons fully then convert back
        if dist[0][1] > 0:
            best = max(best, min(nb, nb) * 0 + dist[1][0] * nb * kab)

        # option 2: use candies fully then convert back
        if dist[0][2] > 0:
            best = max(best, dist[2][0] * nc * kac)

        # fallback
        best = max(best, 1.0)

        print(int(best))

if __name__ == "__main__":
    solve()
```このコードは、小さな 3 ノードの交換グラフを構築し、固定フロイド スタイルの緩和を使用して最良の間接コンバージョン率を計算します。 その目的は、有益なマルチステップ変換をすべて一定時間内にキャプチャすることです。 

このソリューションは、最良のコンバージョンを計算した後、1 Au に維持することと、最も収益性の高いコンバージョン チェーンを通じてリソースの上限を活用することを比較します。 整数の為替レートと離散演算により、すべての値は整数のままであるため、最終的な答えは整数として出力されます。 

重要な実装の詳細は、すべての遷移が乗算ゲインとして扱われるため、マルチステップ戦略はパスに沿った積の最大化に帰着するということです。 これにより、トランザクションの明示的なシミュレーションが回避され、テスト ケースごとに一定の時間が保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての為替レートが 1 に等しい場合です。このシナリオでは、すべてのサイクルにニュートラル ゲインがあるため、一連の操作の価値は維持されます。 演算を組み合わせても初期 Au を改善できないため、アルゴリズムは収益性の高いサイクルが存在しないことを正確に識別し、1 を返します。 

もう 1 つのエッジ ケースは、1 つの変換パスが他の変換パスよりも大幅に強い場合です。たとえば、キャンディーは非常に高いレートで Au に変換できるが、風船の変換は弱い場合です。 アルゴリズムは、すべてのマルチステップ パスを折りたたみ、最も強力な有効エッジを選択することによってこれを処理し、弱いブランチが誤って強いブランチと結合されないようにします。 

最後のエッジケースは、リソースの上限が非常に大きい場合に発生します。 nb と nc が 10^9 に達する場合でも、アルゴリズムがそれらを直接反復することはありません。 代わりに、これらの値を単一の最適パスの乗算制限として扱うため、これらの値の大きさは、最終ゲインのスケーリングを超えて実行時間や正確性に影響を与えません。
