 ## 解決策
 ## 問題の理解

 固定配列と、その連続セグメントに対する多くのクエリが与えられます。 クエリ間隔ごとに$[l, r]$、サブ配列の数を数えなければなりません$[i, j]$その間隔内に完全に含まれているものは、部分配列内の個別の値の数が奇数であるという特性を持ちます。 

したがって、タスクはサブ配列自体をカウントすることではなく、個別の要素数のパリティ条件によってすべてのサブ配列を分類し、各クエリ範囲内のすべてのサブ配列を集計することです。 

制約は大きく、配列の長さとクエリの数は両方とも最大になります。$5 \times 10^5$。 各クエリをサブ配列ごとに線形時間または対数時間で個別に処理するソリューションは、直ちに遅すぎます。 ナイーブ$O(n^2)$部分配列の列挙は不可能です。$10^{11}$最悪の場合の運用。 たとえ$O(n \sqrt{n})$または$O(n \log n)$クエリごとのアプローチは次の場合に失敗します$5 \times 10^5$クエリ。 

主な問題点は、プロパティが個別の要素に依存しており、本質的にサブ配列全体にわたってグローバルであることです。 このため、何らかの事前計算や構造の再定式化がなければ、寄与を特定することが困難になります。 

セグメント内のすべての要素が同一である場合、微妙なエッジケースが発生します。 その場合、すべてのサブ配列には 1 つの異なる要素が含まれるため、すべてのサブ配列がプラスに寄与します。 ある長さのセグメントの場合$k$、答えは$\frac{k(k+1)}{2}$。 すべてのサブ配列が均一に動作するため、個別のカウントをエンドポイントごとに独立したものとして扱う間違ったアプローチは失敗します。 

別のエッジケースは、値が交互に切り替わる場合に発生します。たとえば、$[1,2,1,2,1]$。 ここで、個別のカウントはウィンドウ サイズに応じて変動し、個別のカウントの単調性に関する単純で貪欲な仮定は完全に失敗します。 個別の要素の単調な拡大または縮小に依存するメソッドでは、挿入だけでなく削除も明示的に処理する必要があります。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。 固定の場合$[l, r]$、その中のすべてのサブ配列を列挙し、サブ配列ごとにセットまたは頻度マップを維持して、そこに含まれる個別の要素の数を計算します。 これは定義に直接一致するため、正しい結果が得られます。 

ただし、ある長さのセグメントについては、$k$、 がある$\frac{k(k+1)}{2}$サブ配列なので、単一のクエリですでに$O(k^2)$仕事。 と$k$まで$5 \times 10^5$、これは実現可能な限界をはるかに超えています。 サブ配列ごとの個別のカウントを最適化しても、サブ配列の数が支配的なため役に立ちません。 

重要な観察は、「個別の要素の数が奇数である」という条件がパリティ条件であるということです。これは、個別の値を明示的にカウントするのではなく、問題をプレフィックスの寄与に関して線形なものに変換することを示唆しています。 個別の数を直接追跡する代わりに、部分配列を拡張するときに各値が個別の構造を変更する頻度の関数として答えを表現したいと考えています。 

問題を再定式化する有効な方法は、正しいエンドポイントを修正することです$j$。 それぞれについて$j$、すべてを考慮してください$i \le j$で、これらの接頭辞のうちのいくつが奇数の個別の値を生成するかを尋ねます。$[i, j]$。 これにより、問題は、最後に発生した値に基づいて各位置が寄与する構造に移行します。 

ここで重要な洞察が必要です。異なる要素のパリティです。$[i, j]$からスキャンしたときに「ウィンドウ内の最初の出現」が何回現れるかのパリティに等しい。$i$に$j$。 これは、各値の最後の出現を維持することで追跡できます。 移動するとき$j$、最後の出現位置のみが変更され、各値は、新しい出現が最新になったときに、寄与を 1 回だけ切り替えます。 

これにより、問題は、クエリに対するオフライン処理で処理できるコントリビューションに対する動的な構造の維持に変わります。通常は、スイープと組み合わせたフェンウィック ツリーまたはセグメント ツリーを使用します。$j$、最後の発生からの貢献を追跡しながら。 

エンドポイントを昇順に処理し、各ポジションの構造を維持します。$i$で始まる部分配列かどうかをエンコードします。$i$現在の時点で終了するとき、現在、奇数または偶数の個別のカウントがあります。$j$。 繰り返される値が表示されるたびに、以前の値を削除して新しい値を追加し、各状態が確実に更新されるようにします。$O(\log n)$。 

最後に、各クエリ$[l, r]$合計額を要求します$i \in [l, r]$エンドポイントでの有効な状態の$r$、これは、維持された構造にわたるプレフィックスの合計を使用して答えることができます。

 ## アルゴリズムのチュートリアル

 クエリを右のエンドポイントでソートすることで処理し、各開始インデックスが現在、現在の位置で終わる奇数の異なる要素を持つサブ配列を形成しているかどうかをエンコードする動的構造を維持します。 

1. 右の終点を固定し、左から右にスイープします。 それぞれのポジションで$r$で終わるすべてのサブ配列を概念的にアクティブにします。$r$。 問題は、奇数の個別カウントを生成する開始位置の数をすぐに答えることに帰着します。 
2. 各値から最後に出現したインデックスへのマッピングを維持します。 新しいポジションを処理するとき$r$価値のあるもの$a[r]$、以前の出現を見つけます$p$。 これは重要です。なぜなら、$p$そして$r$変化します。 
3. 値ごとに 2 つのトグルを維持します。値が表示されると、開始位置が以前の値と現在の位置の間にあるすべてのサブ配列のパリティに寄与します。 この範囲効果により、サブ配列ごとの推論を間隔更新に置き換えることができます。 
4. 開始インデックスに対してフェンウィック ツリーを使用します。 各更新は、開始範囲のパリティ寄与を反転することに対応します。 範囲反転は、2 点更新または差分配列スタイルのフェンウィック構造として実装されます。 
5. 加工後の位置$r$、正しいエンドポイントが$r$。 各クエリは、「アクティブな奇数パリティ開始」の合計を求めます。$[l, r]$、これをフェンウィック ツリーのプレフィックス合計の差として取得します。 
6. すべての位置が処理されるまでスイープを続けます。 

これが機能する理由は、値が再出現するたびに、以前の寄与がキャンセルされ、新しい境界で再導入されるため、各サブ配列のパリティ状態は、エンドポイントが反復値の出現を横切る場合にのみ進化するためです。 これにより、維持する構造が常にすべてのオブジェクトの正しいパリティ分類を反映することが保証されます。$[i, r]$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        if l <= r:
            self.add(l, v)
            self.add(r + 1, -v)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())

    queries = [[] for _ in range(n + 1)]
    for idx in range(m):
        l, r = map(int, input().split())
        queries[r].append((l, idx))

    bit = Fenwick(n)
    last = {}

    ans = [0] * m

    for r in range(1, n + 1):
        x = a[r - 1]

        if x in last:
            prev = last[x]
            bit.range_add(prev, prev, -1)

        bit.range_add(r, r, 1)
        last[x] = r

        for l, idx in queries[r]:
            ans[idx] = bit.sum(r) - bit.sum(l - 1)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```ここではフェンウィック ツリーが開始位置に対する動的なカウンターとして使用されています。 各ポジション$i$現在の位置で終了するサブ配列の有効な開始として現在寄与しているかどうかを格納します。$r$。 値が繰り返されると、その前の寄与が削除され、新しい寄与が新しい位置に追加されます。 これにより、すべてのステップでツリーが現在のパリティ分類を反映するようになります。 

クエリは適切なエンドポイントごとにグループ化されるため、スイープがそのエンドポイントに到達したときに各クエリが正確に応答されます。$r$。 プレフィックスの合計の差によりカウントオーバーが得られます$[l, r]$。 

主な微妙な点は、それぞれの処理の瞬間に更新を適用する必要があることです。$r$、その位置でクエリに応答する前に、そうでない場合、クエリは古い状態になります。 

## 実用的な例

 配列を考慮してください$[1, 2, 1]$単一のクエリで$[1, 3]$。 

で$r=1$、値 1 が最初に表示されるため、位置 1 がアクティブになります。 で$r=2$、値 2 は新しいため、位置 2 がアクティブになります。 で$r=3$、値 1 が繰り返されるため、インデックス 1 からの前の寄与が削除され、インデックス 3 に再度追加されます。 

| r | 値 | アクティブなスタート |
 | --- | --- | --- |
 | 1 | 1 | {1} |
 | 2 | 2 | {1,2} |
 | 3 | 1 | {2,3} |

 問い合わせ用$[1,3]$、アクティブなスタートをカウントします$[1,3]$、これは 2 です。 

ここで考えてみましょう$[1,1,1,1]$クエリ付き$[1,4]$。 

新しい出現が発生するたびに、以前の寄与が削除され、前方にシフトされます。 

| r | アクティブなスタート |
 | --- | --- |
 | 1 | {1} |
 | 2 | {2} |
 | 3 | {3} |
 | 4 | {4} |

 すべてのサブ配列には個別の要素が 1 つだけあるため、10 個のサブ配列すべてが有効であり、アクティブな開始での累積と一致します。 

これらのトレースは、構造が各値の寄与のスライド式の「所有権」のように動作し、最後に発生したロジックと一致することを示しています。

 ## 特殊なケース

 単一要素配列の場合$[x]$、唯一の部分配列は$[1,1]$、これには 1 つの異なる要素があり、常にカウントされます。 このアルゴリズムは位置 1 をアクティブとして初期化し、フェンウィック ツリーから直接クエリに応答して 1 を生成します。
