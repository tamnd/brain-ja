 ## 問題の理解

 を埋める必要があります`2 x 2`4 つの異なる数字を持つグリッド`1`に`9`。 グリッドは次のようになります。$$\begin{matrix} a & b \\ c & d \end{matrix}$$入力により 6 つの和が得られます。 

最初の行には、次の 2 つの行の必要な合計が含まれています。$$a + b = r_1$$

$$c + d = r_2$$2 行目には、2 つの列の必要な合計が含まれています。$$a + c = c_1$$

$$b + d = c_2$$3 行目には、2 つの対角線の必要な合計が含まれています。$$a + d = d_1$$

$$b + c = d_2$$私たちのタスクは、次の 4 つのペアごとに異なる整数を見つけることです。`1`そして`9`6 つの方程式をすべて満たします。 そのような取り決めが存在しない場合は、印刷します`-1`。 

制約は非常に小さいです。 グリッド内のすべての値は次のものから取得する必要があります`1..9`、したがって、最大で次のものがあります。$$9 \times 8 \times 7 \times 6 = 3024$$順序付きで 4 つの異なる数字を選択する方法。 あらゆる可能性を総当たりで検索しても、2 秒の制限内ではほんのわずかです。 これにより、複雑な最適化が不要であることがすぐにわかります。 

主な困難はパフォーマンスではなく、正確さです。 不用意に実装すると、無効なグリッドが簡単に受け入れられる可能性があります。 

よくある間違いの 1 つは、4 つの数字はすべて異なるものである必要があることを忘れていることです。

## アプローチ

 最も直接的なアイデアはブルートフォースです。 からの 4 つの異なる数字の可能なすべての割り当てを試みます。`1`に`9`をグリッドに入力し、6 つの方程式がすべて成り立つかどうかをテストします。 

検索スペースが小さいため、これが機能します。 あるのは`3024`4 つの異なる数字の順序付けされた選択であり、各候補は数回の算術チェックのみを必要とします。 合計作業時間は事実上一定時間です。 

より単純な総当り攻撃では、すべてを反復処理することになります。`9^4 = 6561`グリッドを作成し、重複を個別に拒否します。 それでも十分速いです。 

興味深い観察は、十分な変数を選択すると、方程式によってグリッドが完全に決定されるということです。 たとえば、私たちが知っているとすれば、`a`、 それから：$$b = r_1 - a$$

これにより、ネストされた 4 つのループから、次の可能な値に対する検索が 1 つのループに減ります。`a`。 

ブルートフォースの解決策はすでに受け入れられていますが、代数的アプローチはよりクリーンで、システムがいかに厳しく制約されているかを示しています。

 ## アルゴリズムのチュートリアル

 1. 必要な 6 つの合計を読み取ります。 
2. 反復する`a`から`1`に`9`。 

左上の値を自由変数として扱います。 
3. 方程式を使用して他の 3 つのセルを導出します。$$b = r_1 - a$$

$$c = c_1 - a$$

$$d = d_1 - a$$これらの式は、行、列、対角の制約から直接得られます。`a`。 

1. 4 つの値がすべて有効範囲内にあることを確認します。`1..9`。 

この範囲外の値は有効な gem を表すことができません。 
2. 4 つの値がすべて異なることを確認します。 

この問題では、ペアごとに異なる数値が明示的に必要です。 
3. 残りのすべての方程式を検証します。$$c + d = r_2$$

$$b + d = c_2$$

$$b + c = d_2$$値がいくつかの方程式から導出されたとしても、他の方程式を確認する必要があります。 

1. すべてのチェックに合格した場合は、グリッドを印刷して終了します。 
2. すべての反復後に機能する候補がない場合は、出力します。`-1`。 

### なぜ効果があるのか

 アルゴリズムは、考えられるすべての値を考慮します。`a`許容範囲内です。 有効な解の場合、その左上の値はこれら 9 つの可能性のいずれかである必要があります。 

一度`a`が固定されている場合、方程式は一意に決定されます`b`、`c`、 そして`d`。 すべてのソリューションは正確に 1 回の反復に対応するため、有効な構成が見逃されることはありません。 

検証フェーズでは正確性が保証されます。 範囲チェックでは許可された数字が強制され、一意性チェックでは個別の gem が強制され、残りの方程式チェックでは問題からのすべての制約が満たされていることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

r1, r2 = map(int, input().split())
c1, c2 = map(int, input().split())
d1, d2 = map(int, input().split())

for a in range(1, 10):
    b = r1 - a
    c = c1 - a
    d = d1 - a

    values = [a, b, c, d]

    if not all(1 <= x <= 9 for x in values):
        continue

    if len(set(values)) != 4:
        continue

    if c + d != r2:
        continue

    if b + d != c2:
        continue

    if b + c != d2:
        continue

    print(a, b)
    print(c, d)
    sys.exit()

print(-1)
```プログラムはまず、行、列、対角線を表す 6 つの合計を読み取ります。 

ループは、左上のセルの可能な値をすべて試します。`a`。 一度`a`が固定されている場合、残りの 3 つの値は方程式から直接計算されます。 これにより、不必要なネストされたループが回避されます。 

範囲チェックは重要です。 派生値は次のようになります。`0`または超える`9`、合計が一致しても両方とも無効です。 

一意性テストではセットを使用します。 設定サイズがこれより小さい場合`4`の場合、少なくとも 2 つのセルに同じ数値が含まれています。 

最後の 3 つの方程式チェックでは、導出中に直接使用されなかったすべての制約が検証されます。 これにより、一貫性のないシステムが検出されます。 

プログラムは、最初の有効なグリッドを印刷した直後に終了します。 このステートメントでは、あらゆる有効な解決策が許可されます。
