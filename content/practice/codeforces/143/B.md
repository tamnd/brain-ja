 ## 解決策
 ## 問題の理解

 数値は文字列として与えられるので、それを銀行スタイルの通貨形式で出力する必要があります。 

書式設定ルールは、いくつかの独立した変換を組み合わせます。 整数部分には、右から数えて 3 桁ごとにカンマを含める必要があります。 小数部には正確に 2 桁の数字が含まれている必要があります。 元の数値の小数部が 2 桁未満の場合は、ゼロが追加されます。 2 桁以上の場合は、四捨五入せずに余分な桁を切り捨てます。 

負の数値は、マイナス記号の代わりに括弧を使用して表示されます。 ドル記号は常に数値の前に表示する必要があり、負の値の場合は括弧内に置く必要があります。 

入力長は最大 100 文字であるため、これは純粋に文字列操作の問題です。 算術演算は必要ありません。また、四捨五入ではなく桁を切り捨てる必要があるため、浮動小数点数を使用すると実際には危険です。 入力が小さいため、文字列を複数回通過してもまったく問題ありません。 線形時間ソリューションはどれも簡単に十分に高速です。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

数値には小数点がまったく含まれない場合があります。 

入力：```
2012
```正しい出力:```
$2,012.00
```盲目的に別れてしまったら`"."`存在するかどうかを確認しないと、クラッシュしたり、空の小数部が誤って生成されたりする可能性があります。 

小数部分は四捨五入ではなく切り捨てる必要があります。 

入力：```
1.999
```正しい出力:```
$1.99
```次のような浮動小数点形式を使用する`"{:.2f}"`生み出すだろう`$2.00`、それは間違いです。 

入力では負のゼロのような値は使用できません。 このステートメントは、ゼロに等しい値にマイナス記号がつかないことを保証します。 符号は切り捨て後の書式設定された値ではなく、元の文字列から決定されるため、これは重要です。 

入力：```
-0.001
```この入力は問題によって禁止されているため、特別な処理は必要ありません。 

もう 1 つの微妙なケースは、整数部分が非常に短い数値です。 

入力：```
12.3
```正しい出力:```
$12.30
```不注意にカンマを作成するループを実行すると、誤って小さな数値の前にカンマが付加される可能性があります。 

数が多い場合も、慎重にグループ化する必要があります。 

入力：```
123456789
```正しい出力:```
$123,456,789.00
```グループ化は、左側からではなく、右側から開始する必要があります。 

## アプローチ

 ブルートフォーススタイルの解決策では、整数部分の最後の 3 桁を繰り返し剥がして、答えを逆から構築します。 入力サイズが小さいため、これはすでに効率的に機能します。 10 進数の書式設定を文字ごとに手動でシミュレートすることもできます。 

主な危険はパフォーマンスではなく、正確さです。 浮動小数点変換がソリューションに入ると、切り捨て動作は信頼できなくなります。 たとえば、変換すると、`"999999999999999999.999"`float に変換すると、すぐに精度が失われます。 次のような小さな値でも、`"1.999"`標準の書式設定関数が使用されている場合、切り捨てではなく丸められます。 

重要な観察は、問題内のすべてのルールがテキスト表現に直接作用するということです。 数値自体が必要になることはありません。 整数部分はカンマでのみ並べ替えられ、小数部分はテキストとして埋められるか切り捨てられ、負数は最初の文字から検出されます。 

つまり、最もクリーンな解決策は純粋な文字列処理であるということです。 

まず、オプションのマイナス記号を削除します。 

次に、残りの文字列を整数部分と小数部分に分割します。 

整数部分を右からカンマグループでフォーマットします。 

小数部を正確に 2 文字に正規化します。 

最後にドル記号とオプションの括弧を追加します。 

アルゴリズム全体は入力長において線形であり、あらゆる精度の問題を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 数値変換によるブルート フォース | O(n) | O(n) | 丸めと精度のため間違っています |
 | 最適な文字列処理ソリューション | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 
2. 最初の文字が次であるかどうかをテストして、数値が負であるかどうかを確認します。`'-'`。 

最終的な形式ではマイナス記号が消えて括弧に置き換えられるため、これを個別に覚えておく必要があります。 
3. 数値が負の場合は、先頭の数字を削除します。`'-'`。 
4. 残りの文字列を整数部分と小数部分に分割します。 

文字列に小数点が含まれる場合は分割します。`"."`。 

それ以外の場合、文字列全体が整数部分になり、小数部分は空から始まります。 
5. 小数部を正確に 2 桁に正規化します。 

文字数が 2 文字未満の場合は、長さが 2 文字になるまでゼロを追加します。 

3 文字以上ある場合は、最初の 2 文字だけを残します。 
6. 整数部分をカンマでフォーマットします。 

数字を 3 文字ごとに右から左にたどります。 収集したチャンクを反転し、カンマで結合します。 

最下位桁がグループ化の境界を決定するため、右からのグループ化が不可欠です。 
7. フォーマットされた通貨文字列を次のように作成します。```
$<formatted_integer>.<fraction>
```8. 元の数値が負の場合は、結果全体を括弧で囲みます。 
9. 最後の文字列を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、各書式設定ルールを個別に直接実装します。 

整数部分の変換では、すべての桁が保持され、右から 3 桁ごとにカンマのみが挿入され、仕様と正確に一致します。 

分数正規化では、余分な文字が切り捨てられるか、欠落しているゼロが追加されるため、常に正確に 2 桁が生成されます。 

元の符号は変更前に保存され、後で括弧に一度だけ変換されるため、符号の処理は正確です。 

すべての変換は決定的であり、文字列の一部に対してローカルであるため、最終出力は、すべての有効な入力に必要な財務形式と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    negative = s[0] == '-'

    if negative:
        s = s[1:]

    if '.' in s:
        integer_part, fractional_part = s.split('.')
    else:
        integer_part = s
        fractional_part = ""

    fractional_part = (fractional_part + "00")[:2]

    groups = []

    i = len(integer_part)
    while i > 0:
        start = max(0, i - 3)
        groups.append(integer_part[start:i])
        i -= 3

    formatted_integer = ",".join(reversed(groups))

    result = f"${formatted_integer}.{fractional_part}"

    if negative:
        result = f"({result})"

    print(result)

solve()
```この解決策は、文字列を変更する前に署名情報を保存することから始まります。 これにより、後でマイナス記号が出力形式から消えたときの混乱を避けることができます。 

整数部分と小数部分の間の分割は、すべて文字列を使用して行われます。 プログラム内のどこでも数値変換は行われないため、オーバーフローと不要な丸め動作の両方が回避されます。 

ライン```
fractional_part = (fractional_part + "00")[:2]
```小数部を正規化するコンパクトな方法です。 追加中`"00"`文字列に少なくとも 2 文字が含まれることを保証し、スライスでは正確に 2 文字が維持されます。 これにより、次の 3 つのケースがすべて正しく処理されます。```
""     -> "00"
"3"    -> "30"
"987"  -> "98"
```コンマ グループは最下位桁を基準にして定義されるため、整数書式設定ループは右から左に桁を処理します。 各反復では、最大 3 桁の 1 つのグループが抽出されます。 

使用する`reversed(groups)`カンマで結合する前に、グループを通常の左から右の順序に戻します。 

括弧は最後にのみ追加されます。 これにより、ステートメントで必要とされるドル記号が内部に留まることが保証されます。

 ## 特殊なケース

 次の入力を考えてみましょう。```
1.999
```アルゴリズムは文字列を整数部分に分割します`"1"`そして小数部`"999"`。 正規化後:```
("999" + "00")[:2]
```生成する`"99"`。 アルゴリズムは値を数値的に解釈しないため、丸めは行われません。 最終的な答えは次のようになります。```
$1.99
```これはステートメントの要件に直接一致します。 

ここで次のことを考えてみましょう。```
12
```小数点がないため、小数部分は空の文字列として始まります。 正規化後:```
("" + "00")[:2]
```になる`"00"`。 整数部分は 4 桁未満であるため、カンマは挿入されません。 出力は次のようになります。```
$12.00
```これにより、アルゴリズムが不足している小数部分を正しく処理していることが確認できます。 

大きなグループ化された数値を考えてみましょう。```
1234567890
```グループ化ループは以下を抽出します。```
890
567
234
1
```逆の順序で。 リストを逆にすると次のようになります。```
1,234,567,890
```これにより、右側から数字が正しくグループ化されます。

-5.2

($5.20)
