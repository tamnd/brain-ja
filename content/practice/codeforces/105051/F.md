 ## 解決策
 ## 問題の理解

 サイズが最大 20 の小さなアルファベットから構築された文字列のコレクションが与えられます。クエリ文字列ごとに、非常に特殊な意味で互換性のある文字列をコレクションから 1 つ選択する必要があります。選択した文字列は、クエリ文字列と文字を共有してはなりません。 このような互換性のある文字列すべての中で、辞書編集的に最小のものを出力する必要があり、複数の文字列が存在する場合は、それらの中で最小のインデックスを取得します。 コレクション内の文字列がクエリのすべての文字を回避しない場合、答えは -1 です。 

重要な構造は、互換性は文字列の順序や多重度ではなく、文字列内に出現する文字のみに依存するということです。 これは、各文字列を最大 20 ビットのビットマスクに圧縮することを直ちに示唆します。 

制約は厳しく、最大 200,000 個の文字列と 200,000 個のクエリ、合計の長さは最大 10^6 です。 各クエリをすべての文字列と個別に比較するソリューションでは、最悪の場合、約 4×10^10 の文字チェックが発生しますが、これは実行可能な制限をはるかに超えています。 すべての文字列に対するクエリごとの線形スキャンさえも除外されます。 

アルファベットの境界は重要なシグナルです。 最大 20 文字の場合、文字のサブセットはサイズ 2^20、つまり約 100 万のスペースを形成します。 これは、すべてのマスクを事前計算するには十分小さいですが、単純なクエリごとのサブセット列挙では 200,000 回繰り返しても遅すぎる可能性があります。 

多くの文字列が同じ文字セットを共有する場合、微妙な特殊なケースが発生します。 たとえば、すべての文字列が 1 文字だけ (たとえば「a」) で構成されており、クエリに「a」が含まれている場合、すべての文字列は無効になります。 正解は -1 です。生の文字列の内容ではなく文字セットでフィルタリングすることを忘れたアプローチでは、一部の文字列が常に利用可能であると誤って想定されてしまいます。 

もう 1 つのケースは、複数の文字列が有効であるが、辞書順のみが異なる場合です。 たとえば、文字列「abc」と「abd」があり、両方の外側の文字のみを含むクエリがある場合、最初に挿入された文字列または最も短い文字列ではなく、「abc」を返さなければなりません。 これにより、マスクごとの任意の選択ではなく、慎重なグローバル順序付けが強制されます。 

## アプローチ

 直接的なアプローチでは、各クエリをすべての文字列に対してチェックします。 各ペアについて、それらの文字セットが交差するかどうかをテストします。 これには、各文字列とクエリのビットマスクを構築し、ビットごとの AND をチェックする必要があります。 チェック自体は一定時間ですが、ペアごとに繰り返すと O(nq) となり、大きすぎます。 

この改善は、同一の文字マスクを持つ文字列をマージできることに気づいたことから来ています。各マスクについて、それを生成する辞書編集上最小の文字列のみを考慮します。 同じマスクを持つ他の文字列は、どのクエリでも決して優れたものではありません。 

この圧縮後も、次の質問に答える必要があります。クエリ マスク q が与えられた場合、m と q が互いに素であるような、すべてのマスク m の中から最適な文字列を見つけます。 ビットマスクの用語では、q の補数のサブセットであるすべての m が必要です。 

これにより、問題は 20 ビット空間にわたる古典的なサブセット集計クエリに変換されます。 クエリごとにすべてのサブセットをチェックする代わりに、マスクごとにそのすべてのサブマスクの中から最良の答えを事前計算します。 その後、各クエリは単一の配列ルックアップになります。 

これはまさに SOS DP (サブセットに対するサブセット ゼータ変換スタイルの動的プログラミング) が提供するものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | マスク圧縮のみ | O(n + q・2^20) | O(2^20) | 境界線 |
 | サブセット上の SOS DP | O(2^20 + n + q) | O(2^20) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字列を 20 文字以上のビットマスクとして扱います。

1. すべての文字列をビットマスクに変換します。ビット i は i 番目の文字の存在を示します。 これを実行している間、マスクごとに、それを生成する辞書編集上の最小の文字列を追跡します。 これにより、各マスクが可能な限り最良の候補を表すことが保証されます。 
2. 配列を作成する`best[mask]`その正確なマスクに最適な文字列で初期化されます。そのマスクを持つ文字列がない場合は空です。 
3. 2 番目のアレイを構築する`dp[mask]`これは、すべてのサブマスクの中で最適な文字列を保存します。`mask`。 
4.初期化`dp[mask] = best[mask]`すべてのマスクに。 
5. 0 ～ 19 のビット位置 i ごとに、すべてのマスクを繰り返します。 ビット i がマスクに設定されている場合は、改善を試みてください`dp[mask]`使用して`dp[mask without bit i]`。 このステップでは、最適な値を小さなサブマスクから大きなマスクに伝播します。 
6. 各クエリ文字列をマスクに変換します。`q`。 コンピューティング`comp = full_mask XOR q`ただし、許可される文字を表す 20 ビットに制限されます。 
7. 答えは次のとおりです。`dp[comp]`存在する場合は -1。 

重要なアイデアは次のとおりです`dp[comp]`に完全に含まれるすべてのマスクの中で最適な文字列がすでに含まれています`comp`これはまさに、クエリと共有文字がないための条件です。 

これが機能する理由は、ビット i を処理した後、すべてのビットが処理されるという不変条件から来ています。`dp[mask]`には、i までのビットに制限されたすべてのサブマスクの中で最良の値がすでに含まれています。 すべてのビットが処理されると、これは 20 ビットすべてに拡張されます。つまり、`dp[mask]`すべてのサブマスクを正しくカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, w = map(int, input().split())
    
    # map letters to bits
    def to_mask(s):
        m = 0
        for c in s.strip():
            m |= 1 << (ord(c) - 97)
        return m
    
    INF = None
    MAXM = 1 << w
    
    best_str = [INF] * MAXM
    best_idx = [-1] * MAXM
    
    for i in range(n):
        s = input().strip()
        m = to_mask(s)
        if best_str[m] is None or s < best_str[m]:
            best_str[m] = s
            best_idx[m] = i + 1
    
    dp_str = best_str[:]
    dp_idx = best_idx[:]
    
    for bit in range(w):
        for mask in range(MAXM):
            if mask & (1 << bit):
                pm = mask ^ (1 << bit)
                if dp_str[pm] is not None:
                    if dp_str[mask] is None or dp_str[pm] < dp_str[mask]:
                        dp_str[mask] = dp_str[pm]
                        dp_idx[mask] = dp_idx[pm]
    
    full = (1 << w) - 1
    
    out = []
    for _ in range(q):
        t = input().strip()
        qm = to_mask(t)
        comp = full ^ qm
        
        if dp_str[comp] is None:
            out.append("-1")
        else:
            out.append(str(dp_idx[comp]))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、2 つの並列配列の維持に依存しています。1 つは辞書編集上の最小の文字列用で、もう 1 つはそのインデックス用です。 DP ステップでは、サブマスクからより良い候補を慎重に上に伝播させます。 伝播の順序により、中間の改善が正しく再利用されることが保証されます。 

よくある落とし穴は、サブマスクの代わりにスーパーセットを使用するなど、間違った方向に伝播しようとすることです。 これにより、禁止された文字を含む文字列が結果に影響を与える可能性があります。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ文字を回避する文字列がない場合です。 たとえば、保存されているすべての文字列にクエリの文字が少なくとも 1 つ含まれている場合、補数マスクは空になるか、エントリを含む有効なサブマスクがありません。 この場合、`dp[comp]`未設定のままであり、伝播によって有効な候補を導入できないため、アルゴリズムは正しく -1 を返します。 

複数の文字列が同じマスクを共有する場合、別の微妙なケースが発生します。 前処理ステップにより、辞書編集的に最小のもののみが保持されることが保証されるため、後の DP 伝播で誤ってより悪い文字列が昇格されることはありません。 

最後に、補数マスクが大きい場合でも、すべてのサブセット情報がすでに事前計算されているため、ソリューションは引き続き機能します。 クエリごとの組み合わせ爆発は発生せず、ルックアップは一定時間のままです。
