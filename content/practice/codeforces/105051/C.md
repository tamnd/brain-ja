 ## 解決策
 ## 問題の理解

 n 行 m 列の長方形グリッドが与えられます。 すべてのセルには 3 つの色のいずれかが割り当てられますが、その色付けは標準のチェス盤のようにパリティに基づいていません。 代わりに、グリッドは左上方向から右下方向に向かう対角線に分解され、これらの対角線にはグリッドの一端から始めて固定の順序で番号が付けられます。 

対角線に番号が付けられると、この対角線のシーケンスに沿って、色が周期 3 で周期的に繰り返されます。 最初の対角線は白、2 番目は黒、3 番目は青、4 番目は再び白、というように色が付けられます。 すべてのセルは、そのセルが配置されている対角線の色を継承します。 

タスクは、n × m 個のセルすべての中で 3 つの色のどれが最も頻繁に現れるかを判断し、その色の名前を出力することです。 複数の色が最大頻度で同点の場合、そのうちのいずれか 1 つを印刷できます。 

この制約により、n と m は 10^9 まで許可され、セルごと、または対角ごとの列挙が即座に除外されます。 セルの総数は 10^18 に達する可能性があるため、解は反復ではなく算術構造のみに依存する必要があります。 

単純な間違いは、対角線を明示的にシミュレートしようとすることから生じます。 たとえば、適度に大きい 10^7 × 10^7 グリッドの場合でも、対角線の反復は時間的にすでに不可能です。 もう 1 つの微妙な落とし穴は、境界線での対角線の番号付けを注意深く考慮せずに、色付けが (i + j) mod 3 のみに依存すると仮定していることです。 その直感は近いですが、各対角クラスに該当するセルの数を正確にカウントする必要があります。 

## アプローチ

 ブルート フォースの観点は単純です。各セルに対角インデックスを割り当て、その色を計算し、白、黒、青のカウンターを増分します。 これは定義に直接従うため、正しいです。 ただし、nm 操作が実行され、最悪の場合は 10^18 更新になります。 各セルは正確に 1 つの対角線に属するため、対角線を明示的に生成する場合でも、比例的な作業が必要になります。 

重要な観察は、定数 i + j の対角線がグリッドの完全な分割を形成し、色付けはこのシーケンス内の対角線のインデックスのみに依存するということです。 したがって、セルを個別に数えるのではなく、各対角線上にあるセルの数を数え、インデックス モジュロ 3 に従って対角をグループ化して寄与を合計します。 

合計 s = i + j の各対角線は、予測可能なセル数に寄与します。1 から min(n, m) まで増加し、その後対称的に減少します。 This forms a triangular profile. すべての対角線の長さがわかったら、インデックスが 0、1、または 2 の法 3 に一致する対角線のカウントを累積するだけで済みます。 

これにより、問題が nm 個の作業から区分的線形シーケンスに関する O(n + m) 推論に削減され、等差数列和を使用した閉形式の計算にさらに簡略化できます。

 ## アルゴリズムのチュートリアル

 まず、行が 1 ～ n、列が 1 ～ m である座標系を固定します。 各対角線は合計 s = i + j によって識別され、s の範囲は 2 ～ n + m です。 

合計 s を持つ対角線上のセルの数は、長方形内で i + j = s を満たすペア (i, j) がいくつあるかによって異なります。 このカウントは直線的に増加し、n ≠ m の場合は横ばいのままで、その後対称的に減少します。 

対角線を 3 つの領域 (増加するプレフィックス、プラトー領域、減少するサフィックス) に分割します。

1. 2 から min(n, m) + 1 までの s の場合、対角線の長さは s − 1 です。これは、対角線がまだ完全に小さい境界の内側にある増加部分です。 
2. min(n, m) + 1 から max(n, m) + 1 までの s の場合、すべての対角線の長さは min(n, m) になります。 短辺が完全にカバーされる安定した中間帯域です。 
3. max(n, m) + 1 から n + m までの s については、対角線の長さは n + m − s + 1 として直線的に減少します。 

これらの長さがわかれば、個々の対角線は必要ありません。 代わりに、各対角インデックス s を 3 を法とする 3 つの剰余クラスのいずれかに分類します。 s ≡ 2, 0, 1 3 を法とする対角によって寄与されるセルの合計数をそれぞれ累積します (インデックス付けが 2 で開始されるか 1 で開始されるかによって異なりますが、マッピングは一度選択されると固定されます)。 

注意すべき点は、最初の対角線が s = 2 に対応するため、色シーケンスは s = 2 から始まり、白、黒、青の順になるということです。 これは、集計前にモジュロ クラスを一貫してシフトする必要があることを意味します。 

各カラー クラスの合計を合計した後、3 つの値を比較し、最大数のカラーを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのセルが s = i + j でインデックス付けされた 1 つの対角線に正確に属し、同じ s を持つすべての対角線が単色であるという不変条件に依存します。 したがって、問題は、対角線のセットの部分にわたる関数の合計に帰着します。 色付けは s mod 3 のみに依存するため、残差によるグループ化により、情報を失うことなく正確な色数が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = int(input())

    # ensure n <= m for simpler piecewise handling
    if n > m:
        n, m = m, n

    white = black = blue = 0

    # diagonal index s = i + j ranges from 2 to n + m
    # we treat s-2 as step index starting from 0

    def add_range(l, r, base_len):
        nonlocal white, black, blue
        if l > r:
            return

        # we compute contributions per residue class mod 3
        # by iterating only over 3 residues, not all values
        for start in range(l, min(l + 3, r + 1)):
            length = base_len(start)
            s = start
            cnt = (r - s) // 3 + 1

            color = (s - 2) % 3
            if color == 0:
                white += sum(base_len(s + 3*k) for k in range(cnt))
            elif color == 1:
                black += sum(base_len(s + 3*k) for k in range(cnt))
            else:
                blue += sum(base_len(s + 3*k) for k in range(cnt))

    def diag_len(s):
        # s from 2..n+m
        if s < 2 or s > n + m:
            return 0
        if s <= n + 1:
            return s - 1
        if s <= m + 1:
            return n
        return n + m - s + 1

    # split by residue class directly
    def total_for_start(start):
        res = 0
        s = start
        while s <= n + m:
            res += diag_len(s)
            s += 3
        return res

    for start in range(2, 5):
        color = (start - 2) % 3
        total = total_for_start(start)
        if color == 0:
            white += total
        elif color == 1:
            black += total
        else:
            blue += total

    if white >= black and white >= blue:
        print("White")
    elif black >= white and black >= blue:
        print("Black")
    else:
        print("Blue")

if __name__ == "__main__":
    solve()
```この実装では、対角長関数を直接エンコードし、ステップ 3 で等差数列を実行して対角を集計します。重要な簡略化は、範囲を別の式で処理する代わりに、同じ対角長関数を再利用し、3 つの剰余クラスのみを合計することです。 

唯一の微妙な点は、一貫した配置です。対角線の番号付けは s = 2 から始まるため、剰余の計算では (s − 2) mod 3 を使用して、白、黒、青に正しくマッピングされます。

 ## 特殊なケース

 エッジ ケースの 1 つは、1 つの次元が 1 の場合です。n = 1、m が大きい場合、すべての対角線の長さは 1 になります。そのため、答えは純粋に [2, m + 1] 内の整数が各モジュロ クラスにいくつ入るかによって決まります。 diag_len(s) は有効な s ごとに 1 に減少するため、アルゴリズムはこれを正しく処理し、累積は連続する整数の単純なモジュラー カウントになります。 

もう 1 つのエッジ ケースは、n と m が等しい場合です。 この状況では、対角線の長さのプロファイルは中心の周りで完全に対称であり、ピーク対角線を誤って 2 倍にカウントする実装は、中間のカラー クラスを過大評価することになります。 関数 diag_len は、増加領域、一定領域、および減少領域を重複せずに明示的に分離するため、これを回避します。 

最後のエッジ ケースは、n + m が小さい場合 (n = 2、m = 2 など) に発生します。対角シーケンスは短く、3 色すべてが少なくとも 1 回表示されます。 範囲ループには 2 から 4 までのすべての s 値が含まれており、それぞれが正確に 1 回だけ正しい剰余クラスに寄与するため、アルゴリズムは引き続き機能します。
