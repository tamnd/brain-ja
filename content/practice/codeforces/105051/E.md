 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$、各セルには 0 または 1 が含まれています。1 はキャンディーのあるセルを表し、0 は空であることを意味します。 プレイヤーは左上のセルから開始し、移動するたびに右に 1 ステップまたは下に 1 ステップしか移動できません。 パスは常に右下のセルで終了するため、すべての有効なパスは正確に訪問する単調なパスになります。$n + m - 1$細胞。 

プレーヤーが 1 を含むセルに着地するたびに、キャンディーを 1 つだけ集めます。 重要な観察は、異なるパスが異なるセルのセットを通過する可能性があるため、収集されるキャンディーの総数はどの単調なパスが選択されるかによって異なるということです。 

そのとき私たちに与えられるのは、$q$クエリ。 各クエリは、訪問したセルの合計が正確に等しい有効な単調パスが少なくとも 1 つ存在するかどうかを尋ねます。$s_i$, ここで、合計はそのパス上の 1 セルの数です。 

制約により、最大で次のことが許可されます。$10^5$合計セルと$10^5$クエリ。 これにより、すべてのパスの列挙が直ちに除外されます。 単調パスの数だけでも指数関数的に増加する可能性があります。$n + m$、組み合わせなので$\binom{n+m-2}{n-1}$したがって、パスを直接シミュレートしようとするアプローチは失敗します。 

微妙な点は、答えは単一の最適なパスではなく、すべての単調なパスにわたって達成可能な合計のセットにのみ依存するということです。 これにより、問題は、DAG のような構造におけるパスの合計に関する到達可能性の問題に変わります。 

エッジケースは、グリッドが極端に歪んでいる場合に発生します。 たとえば、次の場合$n = 1$、パスは 1 つしかないため、すべての答えは一意に決まります。 もう 1 つの特殊なケースは、すべてのセルが 0 またはすべて 1 の場合です。 どちらの場合も、達成可能な合計のセットは 1 つの値に集約されるため、クエリは簡単になります。 縮退構造を処理せずにパス合計の変動を仮定するソリューションは、ここでは失敗します。 

## アプローチ

 ブルートフォース手法では、左上から右下まですべての単調パスを列挙し、各パス上の 1 の数を計算し、達成可能なすべての合計をセットに保存しようとします。 これは定義と直接一致するため、概念的には正しいです。 ただし、パスの数はグリッド サイズに応じて指数関数的に増加するため、計算的には実行不可能です。 たとえ$20 \times 20$グリッドでは、パスの数はすでに膨大です。 

ブルートフォースを超えるために重要な観察は、グリッドが有向非巡回グラフを形成し、各セルがその上と左の隣接セルのみに依存するということです。 私たちは個々のパスに興味があるのではなく、各セルに到達するときに達成できる合計の範囲に興味があります。 

これは、セルごとに 1 つの最良の値を保存する代わりに、そのセルに到達する可能性のあるすべての合計のセットを保存するという動的プログラミングのアイデアを示唆しています。 ただし、各マージが大きくなる可能性があるため、単純なセットの伝播では依然として遅すぎます。 

重要な構造は単調性から生まれます。 セルへのすべてのパスは上または左から来る必要があり、両方の方向で順序が維持されます。 これにより、明示的なセットではなく、各セルに対して達成可能な合計の範囲を維持できるようになります。 グリッド構造の局所的な調整によってパス間を補間できるため、各セルで可能な合計のセットは連続した間隔を形成します。 これにより、セルごとの最小および最大の可能な合計を追跡するという問題が軽減されます。 

右下のセルで達成可能な最小値と最大値の合計がわかれば、O(1) で各クエリに答えることができます。間隔内の値はすべて達成可能ですが、範囲外の値はすべて達成できません。

 ## アルゴリズムのチュートリアル

 私たちは定義します$dp[i][j]$ペアとして$(mn, mx)$、からの単調なパスで収集できるキャンディーの最小数と最大数を表します。$(1,1)$に$(i,j)$。 

1. 開始セルを初期化します。 の値$(1,1)$グリッドに応じて 0 または 1 のいずれかになります。 これがすべての道の基礎となります。 
2. 最初の行と最初の列を入力します。 最初の行の各セルに到達する方法は左から 1 つだけであるため、その範囲は前のセルと現在のグリッド値から継承されます。 同じロジックが最初の列にも適用され、その上のセルにのみ依存します。 
3. 1 つおきのセルについて$(i,j)$、2 つの候補を計算します: 上から来る$(i-1,j)$そして左から来る$(i,j-1)$。 これらのそれぞれは、現在のセルの値によってシフトされた間隔に寄与します。 新しい最小値は、すべての入力可能な最小値の最小値であり、新しい最大値は、すべての入力最大値の最大値です。 
4. DP テーブル全体を入力した後、次の値を読み取ります。$(n,m)$。 これにより間隔が生まれます$[L, R]$有効なパス上で達成可能なすべてのキャンディーの数。 
5. 各クエリについて$s_i$の場合は「YES」を出力します。$L \le s_i \le R$それ以外の場合は「NO」を出力します。 

### なぜ効果があるのか

 セルへのすべてのパスは、上からまたは左からの移動で終了する必要があるため、DP は有効なサブパスの可能なすべての拡張を正しくキャプチャします。 最小値と最大値は、到達可能な範囲を完全に要約します。これは、グリッド内のターンをシフトすることですべての中間パスをローカルに変換でき、中間合計の到達可能性を維持できるためです。 どのパスもセルをスキップしたり、収集される 1 の数の不連続なジャンプを作成したりできないため、達成可能な合計のセットに計算範囲内にギャップが存在することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # dp[i][j] = (min, max)
    dp = [[(0, 0)] * m for _ in range(n)]

    dp[0][0] = (int(grid[0][0]), int(grid[0][0]))

    for j in range(1, m):
        val = int(grid[0][j])
        mn, mx = dp[0][j-1]
        dp[0][j] = (mn + val, mx + val)

    for i in range(1, n):
        val = int(grid[i][0])
        mn, mx = dp[i-1][0]
        dp[i][0] = (mn + val, mx + val)

    for i in range(1, n):
        for j in range(1, m):
            val = int(grid[i][j])

            up_mn, up_mx = dp[i-1][j]
            left_mn, left_mx = dp[i][j-1]

            mn = min(up_mn, left_mn) + val
            mx = max(up_mx, left_mx) + val

            dp[i][j] = (mn, mx)

    L, R = dp[n-1][m-1]

    out = []
    for _ in range(q):
        s = int(input())
        out.append("YES" if L <= s <= R else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各状態が 2 つの先行状態から到達可能な合計を集計する DP テーブルを構築します。 最初の行と列は、入力方向が 1 つしかないため特別であり、無効な遷移を避けるために個別に処理されます。 各遷移では、現在のセル値が間隔の両方のエンドポイントに追加されます。 

右下のセルの最後の間隔は、達成可能なすべての合計を表すため、各クエリは単純な範囲チェックに減ります。

 ## 特殊なケース

 1×1 グリッドは初期化の感度を明らかにします。 DP は隣接セルにアクセスしようとしてはならず、単一セルの値を間隔の両方のエンドポイントとして直接取得する必要があります。 ここでオフバイワンエラーが発生すると、すべてのクエリの回答が即座に破損します。 

単一行グリッドは、実装が誤って両方向からマージを試行するかどうかをテストします。 左の遷移のみが存在するため、間隔は決定論的に進化するはずです。 セルごとに先行処理が 1 つだけ存在するため、提供された DP はこれを処理します。 

すべてゼロのグリッドでは、すべての DP 値がゼロに折りたたまれます。 これは、ソリューションが誤って負の間隔または偽の間隔を許容するかどうかを強調します。 

オールワン グリッドは、可能な最大のパス合計を生成し、アンダーフローや最小値と最大値の誤った混合が発生することなく、伝播によって値が正しく累積されることを保証します。
