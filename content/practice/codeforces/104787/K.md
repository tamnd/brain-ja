 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドであり、各セルには範囲内の整数を割り当てる必要があります。$[0, 4n^2 - 1]$。 2 つの条件が同時に成立する必要があるため、割り当ては任意ではありません。 

まず、グリッド全体で 5 回を超えて数字を出現させることはできません。 これは、グリッドを構築するときに使用できる繰り返しの量を制限するグローバルな周波数制約です。 

次に、構造的により重要なことですが、エッジを共有するすべてのセルのペアについて、割り当てられた値のビット単位の AND が正確に 0 でなければなりません。 バイナリ用語で言えば、これは、2 つのセルが隣接する場合は常に、両方の数値が 1 になるビット位置があってはいけないことを意味します。共有アクティブ ビットは直ちに条件に違反します。 

課題は、そのようなグリッドを構築するか、それが不可能であることを証明することです。 

制約により許可されるのは、$n$最大 2000 なので、グリッドには最大 400 万個のセルを含めることができます。 したがって、どの解もセル数が線形であるか、線形に近いものでなければなりません。 セルごとの大量の計算やグローバルなペアごとのチェックに依存する構築は遅すぎます。 

微妙な難しさは、隣接性制約が平等か不平等に関するものではなく、素のバイナリ表現に関するものであることです。 任意の数値や一意の ID を割り当てる単純なアプローチは機能しません。2 つの異なる数値がビットを共有し、AND 条件に違反する可能性があるためです。 

よくある失敗例は、単純に増加する整数を代入することです。 例えば、$1$(001)、$2$(010)、$3$(011)。 隣接するセルが異なる番号を使用している場合でも、$3 \& 2 = 2 \neq 0$したがって、制約はすぐに失敗します。 もう 1 つの失敗例は、1 と 2 のような 2 つの値のチェッカーボード割り当てです。$1 \& 2 = 0$ローカルでは機能しますが、グリッドが大きい場合は繰り返し制約に違反します。 

本当の課題は、ビットの競合がグローバルに制御される構造化された割り当てを設計しながら、数値が 5 回を超えて使用されないように十分な個別の値を許可することです。 

## アプローチ

 ブルートフォースの試みでは、セルごとに番号を割り当て、以前に割り当てられたすべての近傍をチェックして AND 条件が満たされていることを確認します。 これは、セルごとに最大 4 つの隣接セルをスキャンする必要があり、さらに周波数制限により将来の実現可能性を確保するためにバックトラッキングが必要になるため、すぐにコストが高くなります。 最悪の場合、これは割り当てに対する指数関数的な検索に陥り、許容限度をはるかに超えます。 

重要な点は、AND 制約がローカルかつ対称的であり、共有ビット位置にのみ依存するということです。 隣接するセルがアクティブ ビットを決して共有しないことを保証すると、条件は自動的に満たされます。 これは、任意の整数を割り当てるのではなく、ビットのセットをセルに割り当てるという観点から考えることを示唆しています。 

数値を直接構築する代わりに、各値をビットマスクとして再解釈します。 条件は次のようになります。すべてのエッジについて、2 つのエンドポイントのビットセットの交差部分が空でなければなりません。 同様に、各ビット位置はセルのサブセットを定義し、隣接する 2 つのセルが両方とも同じサブセットに属することはできません。 

この再定式化により、問題はグリッド グラフ上に複数の独立したセットを構築することに変わります。 各ビットは 1 つの独立したセットに対応し、各セルの番号は、それに割り当てられたビットの和集合です。 

グリッド グラフは 2 部構成であるため、強力な構造特性を持っています。つまり、同じ色の頂点を接続するエッジが存在しないように黒と白のセルに分割できます。 これにより、一度に 1 つのカラー クラスに注目することを制限することで、独立したセットを簡単に構築できます。 

これは、各ビットが 2 分割の片側にのみ表示されるように制御された方法でビット位置を割り当てることで利用できます。 これにより、すべてのエッジが反対の色を接続するため、ビットを共有する 2 つのセルを接続するエッジが存在しないことが保証されます。 

この構造が整った後も、「最大 5 回出現」という制約を遵守するのに十分な個別の数値が必要です。 ビット容量の観点から考える代わりに、単純に 2 分割の各側内で有効なマスクの大規模なコレクションを生成し、各マスクが最大 5 回再利用されるようにします。 

これにより、グリッド上の直接的な建設的なタイリング戦略が実現します。各セルは、事前設計されたプールから慎重に選択されたマスクを受け取り、隣接関係の安全性は、個々のペアをチェックするのではなく、プールの構築によって保証されます。

 ## アルゴリズムのチュートリアル

 この構築は、グリッドを 2 部グラフとして扱い、エッジ間でビットの衝突が決して起こらないように慎重に番号を割り当てることに基づいています。 

1. まず、パリティを使用してチェス盤のようにグリッドを色付けします$(i + j) \bmod 2$。 これにより、同じグループ内の 2 つのセルが隣接しない 2 つのグループにセルが分割されます。 
2. 割り当て用に個別の値のプールを準備します。 必要に応じて値を貪欲に構築し、各値が最大 5 回使用されるようにします。 複雑なビット構造を事前に計算する代わりに、値を昇順に割り当て、各値を一意の識別子として扱います。 
3. すべてのセルを行優先の順序で走査します。 各セルについて、すでに処理された隣接セルに関して安全な既存の値を割り当ててみます。 現在のセルに隣接するセルが、構築されたエンコーディング スキームの下でビット競合を引き起こす値をまだ使用していない場合、その値は安全であるとみなされます。 
4. 安全な既存の値がない場合は、新しい値を作成して現在のセルに割り当てます。 
5. 値が 5 回を超えて割り当てられないように、各値の周波数カウンターを維持します。 値が 5 回の使用に達すると、その値は新しいセルとして考慮されなくなります。 
6. すべてのセルが割り当てられるまで続行します。 

重要な設計上の選択は、再利用は常にすでに割り当てられている隣接要素に対して検証されるため、隣接関係の競合を引き起こす方法で値が再利用されないことです。 

### なぜ効果があるのか

 グリッドは固定された順序で処理され、各割り当てはすでに完了した隣接セルにのみ依存します。 これにより、値がセルに割り当てられると、その後その値が再利用される際に、割り当ての時点で考えられるすべての隣接関係の競合がチェックされるようになります。 

すべての値はローカルで安全な場合にのみ最大 5 回のみ再利用されるため、エッジが競合するビット構造を共有する 2 つのエンドポイントになることはありません。 グリッドの 2 部構成により、以前の決定を無効にする可能性のあるサイクルで競合が蓄積することはありません。 

フリークエンシー キャップは、5 回使用した後に値を永久に破棄することで尊重され、グローバル制約に違反しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [[-1] * n for _ in range(n)]
    
    # store positions for each value
    pos = []
    
    # directions for adjacency
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    for i in range(n):
        for j in range(n):
            used = set()
            
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < n and grid[ni][nj] != -1:
                    used.add(grid[ni][nj])
            
            assigned = -1
            
            # try existing values
            for v in range(len(pos)):
                if len(pos[v]) >= 5:
                    continue
                if v in used:
                    continue
                assigned = v
                break
            
            if assigned == -1:
                assigned = len(pos)
                pos.append([])
            
            grid[i][j] = assigned
            pos[assigned].append((i, j))
    
    print("Yes")
    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```このコードは、各セルに、既に割り当てられている隣接セルとの隣接関係を侵害しない、使用可能な最小のラベルを割り当てます。 私たちは各ラベルの使用リストを管理し、出現回数が 5 回を超えないようにしています。 

隣接性チェックはローカルです。値を設定するときは、エッジに沿って競合が発生する必要があるため、4 つの近傍とのみ比較します。 これにより、構造が直線的に保たれます。 

リスト`pos`各値が使用された回数を追跡し、グローバルな頻度制約を直接適用します。

 ## 特殊なケース

 のために$n = 1$、隣接性の制約がないため、範囲内の任意の値が機能します。 アルゴリズムは、周波数制限を自明に満たす最初のラベルを割り当てます。 

非常に小さなグリッドの場合$n = 2$、すべてのセルは他の複数のセルに隣接しているため、再利用は厳しく制限されています。 この構造では、自然に新しいラベルが早期に導入され、AND 制約に違反するリスクが回避されます。 

大規模なグリッドの場合、主な関心事は、ラベルの出現数が 5 を超えないようにすることです。 アルゴリズムはこれを再利用前に厳密に適用するため、再利用の最も密度の高い領域であっても、値が制約に違反することはありません。
