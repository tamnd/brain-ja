 ## 解決策
 ## 問題の理解

 単語のコレクションが与えられていますが、各単語について重要なプロパティはその長さだけです。 毎日、Keyi は勉強する単語をいくつか選びます。特別なルールがあります。それは、彼女が長い単語を勉強すると決めた場合です。$k$、その後、彼女はすべての長さの単語を勉強する必要があります$k$その日。 言い換えれば、長さは分割できないグループのように機能します。 

毎日容量制限があります$W$、その日に学習した単語の総数が超えてはいけないことを意味します$W$。 1 つの長さを選択すると、すべての単語がその長さになるように強制されるため、実際の決定は、合計頻度が超えないことを条件として、どの長さを同じ日にまとめるかということになります。$W$。 

入力により得られるのは、$n$タスクは、これらの長さを有効な日数の最小数に分割することです。ここで、各日は長さグループのサブセットであり、1 日のグループ サイズの合計は次を超えません。$W$。 

出力は、すべての単語をカバーするために必要な最小日数です。 

制約は非常に具体的な意味で重要です。 それでも$n$これは、異なる長さの数に依存する解は小さくて管理しやすいことをすぐに示唆しています。 長さごとのカウントを追跡するソリューションで十分です。 長さのすべてのサブセットを反復処理することは、最大でも$2^{13}$可能性。 

素朴な解釈では、グローバル構造を考慮せずに、単語を 1 つずつ割り当てたり、貪欲に毎日のパッキングをシミュレートしたりする可能性があります。 グループ化の決定は相互に依存しているため、これは簡単に破綻します。早い段階で大きなグループを選択すると、後でより適切なパッキングが妨げられる可能性があります。 

1 つの長さが容量を支配する場合、微妙なエッジケースが発生します。 

入力:

 n = 5、W = 4

 長さ: [1, 1, 1, 1, 1]

 各長さグループは長さ 1 で頻度 5 です。すべてをまとめて取得する必要がありますが、1 日あたり 4 を超えることはできないため、少なくとも 2 日かかります。 グループ制約を無視して「残りの単語を適合させよう」とする貪欲なアプローチでは、誤って分割したり過小評価したりする可能性があります。 

もう 1 つのエッジ ケースは、多くの小さなグループが緊密に結合して、容量をわずかに超えるのではなく日数を正確に満たす場合です。この場合、最適なパッキングは順序付けではなくサブセットの選択に依存します。 

## アプローチ

 重要な抽象化は、個々の単語を忘れて、代わりに入力を長さごとの頻度数に圧縮することです。 長さの範囲は 1 ～ 13 のみなので、最大で 13 個のグループが得られ、それぞれのグループは固定サイズになります。 

さて、問題は次のとおりです。アイテムが最大 13 個あり、それぞれの重みがその頻度に等しいので、すべてのアイテムを最小数の容量のビンに詰めたいとします。$W$、アイテムは分割できないという制約があります。 

これはまさに、アイテム数は非常に少ないものの、潜在的に重量が大きくなる可能性があるビン パッキングの問題です。 この強引なアイデアでは、グループを日にちに割り当てることをシミュレートし、考えられるすべての割り当てを試します。 これにより、おおよそ、プレースメントに対する指数関数的な検索が発生します。$O(k^n)$どこ$k$はビンの数ですが、これは中程度の入力でも実行不可能です。 

ただし、異なるグループは最大 13 個あるため、グループのサブセットに対してビットマスク動的プログラミングを使用できます。 各状態はどのグループがすでにパックされているかを表し、合計サイズが以下の残りのグループのサブセットを選択することで 1 日を埋めようとします。$W$。 有効なサブセットごとに、それらのグループを使用済みとしてマークし、1 日を追加することで移行します。 

これにより、問題はサブセットにわたる最短経路に変換され、各移動は 1 日を最適に埋めることに対応します。 

重要な観察は、残りの未使用のグループを除いて、1 日の荷造りが前日とは独立していることです。 したがって、各 DP 移行は 1 日の作業を完全に表します。

 ## アルゴリズムのチュートリアル

 入力を周波数配列に圧縮します`cnt`サイズ 13 の場合、`cnt[i]`長さの単語の数です$i+1$。 

次に、これら 13 のグループをそれぞれ重みのある項目として扱います。`cnt[i]`。 

各マスクがどの長さグループが既に日に完全に割り当てられているかを表すビットマスク DP を定義します。 

すべてのグループをパックするのに必要な最小日数として DP[マスク] を計算します。`mask`。 

### ステップ

 1. コンピューティング`cnt[0..12]`入力から。 
2. グループのすべての有効なサブセットを事前計算します。 サブセットは、そのカウントの合計が以下の場合に有効です。$W$。 これは 1 日分の梱包を表します。 
3. サイズの DP 配列を初期化します$2^{13}$値が大きい場合は、DP[0] = 0 を設定します。 
4. 0 から 0 までのすべてのマスクを繰り返します。$2^{13}-1$。 
5. 各マスクについて、残りの未使用グループのすべてのサブセットを考慮します。 
6. サブセットが有効で、現在のマスクから切り離されている場合は、1 日を追加して新しいマスクに移行します。 
7. すべての遷移にわたって最小値を取得します。 
8. 答えは DP[(1<<13)-1] です。 

重要な設計上の決定は、DP 内で重みを繰り返しチェックすると実行時間が不必要に増加するため、有効なサブセットを事前計算することです。 13 は小さいため、すべてのサブセットを列挙することが可能です。 

### なぜ効果があるのか

 どの DP 状態でも、マスクはどのグループが残っているかを正確にエンコードします。 トランジションごとに、1 日に収まる残りのグループのセットが選択されます。 グループは分割できず、完全にスケジュールする必要があるため、すべてのグループはすべてのトランジションにわたって 1 回だけ表示されます。 DP は、13 グループのすべての可能なパーティションを容量のビンに調査します。$W$そして、すべての有効なパーティションはサブセット削除のシーケンスに対応するため、DP を超える最小値が最適な日数を捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, W = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = [0] * 13
    for x in a:
        cnt[x - 1] += 1

    # Precompute subset weights
    m = 13
    subset_weight = [0] * (1 << m)
    for mask in range(1 << m):
        s = 0
        for i in range(m):
            if mask & (1 << i):
                s += cnt[i]
        subset_weight[mask] = s

    valid = []
    for mask in range(1 << m):
        if subset_weight[mask] <= W:
            valid.append(mask)

    INF = 10**9
    dp = [INF] * (1 << m)
    dp[0] = 0

    full = (1 << m) - 1

    for mask in range(1 << m):
        if dp[mask] == INF:
            continue
        remaining = full ^ mask
        for sub in valid:
            if (sub & mask) == 0:
                new_mask = mask | sub
                if dp[new_mask] > dp[mask] + 1:
                    dp[new_mask] = dp[mask] + 1

    print(dp[full])

if __name__ == "__main__":
    main()
```実装は、入力を 13 長さの周波数配列に圧縮することから始まります。 このステップは、潜在的に大規模な問題を削減するため、非常に重要です。$n$問題を固定サイズの状態空間に変換します。 

の`subset_weight`計算は中心的な前処理ステップです。 長さのすべてのサブセットを評価し、それらの長さが 1 日に一緒に選択された場合に含まれる単語の数を計算します。 

の`valid`リストには、1 日の制限内に収まるサブセットのみが保存されます$W$。 これにより、DP 移行中に繰り返し容量チェックが行われることがなくなります。 

DP ループはマスクを昇順に繰り返します。 状態ごとに、未使用のグループの有効なサブセットを追加しようとします。 XOR チェックにより、グループが再利用されないことが保証されます。 各移行はちょうど 1 日を消費することに相当します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, W = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = [0] * 13
    for x in a:
        cnt[x - 1] += 1

    m = 13
    subset_weight = [0] * (1 << m)
    for mask in range(1 << m):
        s = 0
        for i in range(m):
            if mask & (1 << i):
                s += cnt[i]
        subset_weight[mask] = s

    valid = [mask for mask in range(1 << m) if subset_weight[mask] <= W]

    INF = 10**9
    dp = [INF] * (1 << m)
    dp[0] = 0

    full = (1 << m) - 1

    for mask in range(1 << m):
        if dp[mask] == INF:
            continue
        for sub in valid:
            if (sub & mask) == 0:
                dp[mask | sub] = min(dp[mask | sub], dp[mask] + 1)

    return str(dp[full])

# sample
assert run("5 4\n1 2 1 2 1\n") == "2"

# all same
assert run("4 4\n1 1 1 1\n") == "1"

# tight split
assert run("6 4\n1 1 1 2 2 2\n") == "2"

# minimal
assert run("1 1\n1\n") == "1"

# each must be separate
assert run("3 1\n1 2 3\n") == "3"

 ## 特殊なケース

 単一の長さのグループが長さの半分を超える場合、重要なエッジ ケースが発生します。$W$、他のほとんどのグループと組み合わせることが不可能になります。 たとえば、1 つのグループのサイズが 5 で、$W = 6$、非常に特殊な組み合わせのみが有効です。 DP はこれを自然に処理します。これは、サブセットの有効性が貪欲な順序付けとは関係なく、純粋に合計制約によってチェックされるためです。 

もう 1 つの特殊なケースは、複数の組み合わせが完全に一致する場合です。$W$。 このような場合、貪欲な戦略により、最初に次善のサブセットが選択され、残りのグループが断片化される可能性があります。 DP は、すべての有効なサブセットを対称的に探索し、到達可能なすべてのマスク状態からの合計日数を常に最小化するため、これを回避します。 

最後の微妙なケースは、すべてのグループが個別には小さいものの、集合的にはさまざまな点で容量を超え、パッキングが非常に組み合わせ的になる場合です。 ここでも、サブセットの列挙により、すべての有効なパッキングが考慮されることが保証され、構築順序ではなく状態の最小化を通じて最適なパーティションが見つけられます。
