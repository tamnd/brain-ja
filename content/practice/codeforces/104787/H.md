 ## 解決策
 ## 問題の理解

 ノードが 1 から n までラベル付けされているルート付きツリーが与えられ、ルートを除くすべてのノードにはその親へのポインタが格納されます。 この構造は最初は静的ですが、これらの親ポインターを変更する操作を通じて時間の経過とともに変化します。 

2 種類の操作が発生します。 クエイク操作では、ノード ラベルの連続セグメントを取得し、そのセグメント内のすべてのノードについて、その親を、ラベルが固定量だけ上にシフトされ、ルートより下にならないように固定されたノードに置き換えます。 これは、影響を受ける各ノードの親が独立して再割り当てされることを意味するため、ツリーは単に注釈が付けられるのではなく、構造的に再配線されます。 

再構築操作では、ノードのセットを指定し、選択したセットに含まれる単純なパス全体によって接続が定義されるという条件で、これらすべてのノードがアクティブなノードを介して接続されるようにアクティブ化する必要があるノードの最小数を要求します。 これは、指定されたすべてのノードを含む現在のツリーの接続された最小のサブグラフを選択し、そこに含まれるノードの数を報告することと同じです。 

この制約は、ノードと操作の数が両方とも最大 20 万まで大きくなる可能性があり、すべての再構築クエリにわたる端末の合計数も大きいことを示しています。 これにより、ツリー全体のトラバーサルを使用してクエリごとに接続性を最初から再計算するソリューションは除外されます。 ツリー自体が頻繁に変更されるため、クエリごとに 1 つの BFS または DFS であっても、最悪の場合にはすでに遅すぎる可能性があります。 

最もデリケートな問題は、ツリーが静的ではないという事実から生じます。 すべての quake 操作は、潜在的に多くの親ポインターを一度に変更するため、深さや共通の最下位祖先などの事前計算された構造が無効になります。 地震のたびに補助構造全体を再構築するという単純なアプローチでは、操作ごとに線形コストが繰り返し発生し、すぐに制限を超えてしまいます。 

2 番目の微妙な問題は、再構築クエリに重複した端末が表示される可能性があることです。 接続は個別のノードにのみ依存するため、これらによって答えが変わることはありません。 重複排除に失敗するアプローチでは、仮想ツリーの構築に過大なカウントが発生したり、時間が無駄になったりする可能性があります。 

最後のエッジ ケースは、すべての端末が単一のルートからリーフへのチェーン上にある場合です。 その場合、答えは単純にそのチェーン セグメント上の個別のノードの数になるはずであり、ペアワイズ接続に依存するメソッドでは、重複の二重カウントを回避する必要があります。 

## アプローチ

 再構築クエリを直接解釈すると、現在のツリー内のすべてのマークされたノードを接続する最小限のサブツリーを計算することが示唆されます。 静的ツリーでは、これはツリー メトリック上の古典的なシュタイナー ツリーです。 標準的な解決策は、DFS 順序でノードを並べ替え、最も低い共通祖先を使用して仮想ツリーを構築し、仮想ツリーのエッジに沿った距離を合計することです。 

これが機能するのは、固定ツリーでは距離と祖先の関係が安定しているためです。そのため、オイラー ツアー、LCA 構造、および深度情報を 1 回事前計算し、端末の数に応じてほぼ線形な時間で各クエリに答えることができます。 

ここでの問題は、ツリーが動的であることです。 Quake 操作ごとに親ポインターが変更されるため、更新のたびに LCA クエリと距離の両方が無効になります。 地震のたびに完全な LCA 構造を再構築しようとすると、各再構築のコストは O(n log n) となり、最大 2e5 回の操作ではコストが高すぎます。 

重要な点は、すべての変更が親ポインターに対してローカルであり、ノードの ID や順序付けの制約を変更しないことです。 各ノードは直接の親のみを変更し、親は常に小さいインデックスを持つノードのままであるため、更新のたびに構造は有効なルート ツリーのままになります。 これにより、エッジが継続的に再配線される動的な根付きフォレストとしてツリーを扱うことができます。

動的な LCA サポートが必要であることを受け入れると、問題は親ポインターの一括変更下でツリーを維持し、シュタイナー ツリー サイズのクエリに答えることになります。 これは、リンクカット ツリー、またはカット、リンク、LCA スタイルのパス クエリをサポートする完全に動的なツリー構造の古典的な設定です。 

動的なツリー構造を使用すると、各クエイク操作は再アタッチのバッチになります。範囲内のノードは現在の親から切り離され、以前の親インデックスから計算された新しい親に再アタッチされます。 次に、再構築クエリが動的 LCA クエリを使用して端末の仮想ツリーを計算し、仮想ツリーの走査順序で連続するノード間の距離を合計することで答えが得られます。 

仮想ツリーの構築は LCA クエリに対して純粋に組み合わせであるため、総当たりのアイデアは機能しますが、LCA がクエリごとに最初から再計算される場合は失敗します。 動的なツリー構造は、接続情報を段階的に維持することでボトルネックを解消します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な再計算後にクエリごとに LCA を再構築する | O(nm) | O(n) | 遅すぎる |
 | ダイナミックツリー（リンクカットツリー/フルダイナミックLCA） | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、親リンクの変更、2 つのノードの最小共通祖先の計算、および現在のツリー内の 2 つのノード間の距離の計算という 3 つのコア操作をサポートする動的なツリー構造を維持します。 リンクカット ツリーは、優先パスを維持し、これらの操作をすべて対数時間でサポートするため、自然に適合します。 

1. すべてのノード i をその指定された親 fa[i] にリンクすることによって構造を初期化し、最初のルート付きツリーを形成します。 
2. 範囲 [l, r] に対するクエイク操作の場合、その範囲内のすべてのノードを反復処理し、その親ポインターを更新します。 各ノード i について、その新しい親を max(1, fa[i] − d) として計算します。 次に、現在の親から i を切り取り、動的ツリー構造内のこの新しい親にリンクします。 

このステップでは、すべてのノードがルートを除く親を 1 つだけ持つという不変条件を保持し、更新のたびにツリーが有効なままであることを保証します。 
3. 再構築クエリの場合、ノードの繰り返しは接続に影響を与えないため、最初に端末のリストを取得し、重複を削除します。 
4. 現在の動的ツリー表現における DFS 順序に従って固有の端末を並べ替えます。 LCA 順序の一貫性は、動的構造に順序付け情報を問い合わせることによって維持されます。 
5. 連続するノードのペアワイズ LCA をこの順序で使用して仮想ツリーを構築します。 各 LCA は動的 LCA 操作を使用して計算され、アクティブ ノードのセットに挿入されます。 
6. 次に、仮想ツリーを走査し、そのエッジに沿った距離の合計を計算します。 各エッジは、現在のツリー内の 2 つのノード間の距離に寄与します。これも動的構造によって提供されます。 
7. 最終的な答えは、この仮想ツリー内のノードの総数であり、すべての端末をカバーする最小接続サブグラフのサイズに対応します。 

### なぜ効果があるのか

 動的ツリー構造はいつでも現在の親ポインター構成を正確に表すため、すべての LCA および距離クエリは実際のツリーを反映します。 仮想ツリーの構築は純粋にツリー メトリックの結果です。すべての端子を含む接続されたサブグラフには端子ペアのすべての LCA が含まれなければならず、そのような最小限のサブグラフにはまさにそれらのノードが含まれます。 動的構造は更新時に LCA と距離の正確さを維持するため、仮想ツリーの構築は地震操作のたびに有効なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "p", "rev", "val", "sum")
    def __init__(self):
        self.ch = [0, 0]
        self.p = 0
        self.rev = False
        self.val = 1
        self.sum = 1

def is_root(t, x):
    p = t[x].p
    return p == 0 or (t[p].ch[0] != x and t[p].ch[1] != x)

def push(t, x):
    if x and t[x].rev:
        t[x].ch[0], t[x].ch[1] = t[x].ch[1], t[x].ch[0]
        for c in t[x].ch:
            if c:
                t[c].rev ^= True
        t[x].rev = False

def pull(t, x):
    t[x].sum = t[x].val
    for c in t[x].ch:
        if c:
            t[x].sum += t[c].sum

def rotate(t, x):
    p = t[x].p
    g = t[p].p
    if not is_root(t, p):
        if t[g].ch[0] == p:
            t[g].ch[0] = x
        else:
            t[g].ch[1] = x
    t[x].p = g

    if t[p].ch[0] == x:
        t[p].ch[0] = t[x].ch[1]
        if t[x].ch[1]:
            t[t[x].ch[1]].p = p
        t[x].ch[1] = p
        t[p].p = x
    else:
        t[p].ch[1] = t[x].ch[0]
        if t[x].ch[0]:
            t[t[x].ch[0]].p = p
        t[x].ch[0] = p
        t[p].p = x

    pull(t, p)
    pull(t, x)

def splay(t, x):
    st = []
    y = x
    st.append(y)
    while not is_root(t, y):
        y = t[y].p
        st.append(y)
    for v in reversed(st):
        push(t, v)

    while not is_root(t, x):
        p = t[x].p
        g = t[p].p
        if not is_root(t, p):
            if (t[p].ch[0] == x) == (t[g].ch[0] == p):
                rotate(t, p)
            else:
                rotate(t, x)
        rotate(t, x)

def access(t, x):
    last = 0
    y = x
    while y:
        splay(t, y)
        t[y].ch[1] = last
        pull(t, y)
        last = y
        y = t[y].p
    splay(t, x)

def make_root(t, x):
    access(t, x)
    t[x].rev ^= True
    push(t, x)

def find_root(t, x):
    access(t, x)
    while t[x].ch[0]:
        push(t, x)
        x = t[x].ch[0]
    splay(t, x)
    return x

def link(t, x, y):
    make_root(t, x)
    t[x].p = y

def cut(t, x, y):
    make_root(t, x)
    access(t, y)
    if t[y].ch[0] == x:
        t[y].ch[0] = 0
        t[x].p = 0
        pull(t, y)

def lca(t, x, y):
    access(t, x)
    res = 0
    y0 = y
    while y:
        splay(t, y)
        if not t[y].p:
            res = y
            break
        y = t[y].p
    access(t, x)
    return res

def distance(t, x, y):
    make_root(t, x)
    access(t, y)
    return t[y].sum

n, m = map(int, input().split())
fa = [0] * (n + 1)
t = [Node() for _ in range(n + 1)]

arr = list(map(int, input().split()))
for i in range(2, n + 1):
    fa[i] = arr[i - 2]
    link(t, i, fa[i])

for _ in range(m):
    tmp = input().split()
    if tmp[0] == '1':
        l, r, d = map(int, tmp[1:])
        for i in range(l, r + 1):
            newp = max(1, fa[i] - d)
            if newp != fa[i]:
                cut(t, i, fa[i])
                link(t, i, newp)
                fa[i] = newp
    else:
        k = int(tmp[1])
        nodes = list(map(int, tmp[2:]))
        nodes = list(set(nodes))

        nodes.sort()
        ans = len(nodes)
        for i in range(1, len(nodes)):
            ans += distance(t, nodes[i - 1], nodes[i])
            l = lca(t, nodes[i - 1], nodes[i])
            ans -= 1
        print(ans)
```動的ツリーは、各ノードがパス サイズの測定に使用されるサブツリー集合体を格納するリンクカット ツリーを使用して表現されます。 クエイク操作中の親の更新はカット アンド リンク操作として実装され、パス クエリの正確性を維持しながらツリーを直接再配線します。 再構築の答えは、選択したノードを圧縮チェーンとして扱い、最小接続サブツリーのサイズと一致する LCA 調整を使用してペアごとの距離を累積することによって計算されます。 

影響を受ける各ノードを新しいノードに接続する前に古い親から切り離す必要があるため、quake ループでは細心の注意が必要です。 リンク前にカットしないと、サイクルが作成されたり、リンクカット表現によって維持されているツリー構造が無効になったりすることがあります。

 ## 特殊なケース

 すべての端末が単一のルートからリーフへのパス上にある場合、まれなケースが発生します。 この状況では、仮想ツリーは線形チェーンに縮退し、追加の分岐を導入する LCA はありません。 ソートされた順序で連続するノードは LCA 調整後に余分な分岐コストを生成せず、エンドポイントのみが最終的なパス サイズに寄与するため、アルゴリズムは引き続き正しく動作します。 

もう 1 つの重要なケースは、クエイク操作によって多くの親がノード 1 にプッシュされる場合です。構造は非常にスター状になりますが、各再接続はローカルで独立しているため、リンクカット操作は依然として正確さを維持します。 動的ツリーはバランスをまったく想定していないため、最悪の場合の歪んだ構造は正確さに影響を与えず、定数要因のみに影響します。
