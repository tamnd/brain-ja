 ## 解決策
 ## 問題の理解

 整数の配列とターゲット値が与えられます。 目標は、配列を同じサイズの部分に繰り返し分割し、配列をそれらの部分の平均で置き換え、配列の要素が 1 つだけになるまで継続することです。 ターゲットと等しい単一要素で終了するような一連の操作が存在するかどうかを判断する必要があります。 

入力には複数のテスト ケースが含まれます。 各テスト ケースは配列の長さを提供します`n`、ターゲット`x`、および配列`a`自体。 配列要素と`x`はすべて正の整数であり、`n`これは、およそ 100 までの時間計算量のアルゴリズムを許容できることを意味します。$O(n^2)$テストケースごとに。 考えられるすべての分割に対してブルートフォースを実行すると、特に分割ごとに平均を計算して再帰する必要があるため、面倒になります。 

配列がすでに単一の要素である場合、またはすべての要素が同一である場合には、明らかではないエッジ ケースが発生します。 たとえば、次の場合`a = [3]`そして`x = 3`、すぐにYESを返すことができます。 もし`a = [5,5,5]`そして`x = 5`、答えもYESですが、正確に合計するサブセットを探す単純なアプローチです。`x`誤って拒否してしまう可能性があります。 ターゲットがターゲットの場合、別の微妙な問題が発生します。`x`は配列の平均に等しくなりますが、個々の要素には等しくありません。 例えば、`a = [1, 2]`そして`x = 1.5`分割では整数長の部分列を生成する必要があり、ここで示しているように、すべての要素が整数の場合にのみ、それらの平均化によって整数が生成されるため、これを達成することはできません。 

## アプローチ

 ブルートフォースアプローチでは、すべてのステップで可能な分割をすべて試し、平均を再帰的に計算します。 これは技術的には正しいです。有効な一連の操作は一連のこのような分割でなければならないからです。 ただし、配列を分割する方法の数は、組み合わせによって増加します。`n`、このアプローチは、`n = 20`。 のために`n = 100`、それは不可能です。 

重要な洞察は、各操作で、配列の新しい要素が現在の配列要素の凸の組み合わせであるということです。 これは、最終的な値が`x`元の配列の最小値と最大値の間になければなりません。 もし`x`要素の 1 つと等しい場合、答えは自明のことながら YES です。 それ以外の場合は、`x`は配列の範囲内にありますが、どの要素とも正確に等しくない場合は、常に次のように平均する分割のシーケンスを構築できます。`x`まず配列全体の平均を取ることによって。 具体的には、常にすべての要素を 1 つの長さのサブシーケンスにマージできます。`n`(配列全体)、平均を算出します。 したがって、条件は次のことを確認することになります。`x`は、任意の要素と等しいか、配列の平均と等しいかのいずれかです。 

この観察により、問題を配列の線形スキャンに帰着させることができます。`x`いる`a`または平均に等しい`a`。 これは高速であり、制約内に快適に収まります。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`x`、および配列`a`。 
2. 配列要素の合計を計算します。 
3. 次のことを確認します。`x`の任意の要素と等しい`a`。 「はい」の場合は、「YES」と出力し、次のテスト ケースに進みます。 これは、単一要素のサブシーケンスをすぐに選択できる自明なシーケンスをカバーします。 
4. それ以外の場合は、次のことを確認してください。`x * n == sum(a)`。 これにより、`x`はまさに配列の平均です。 「はい」の場合は、「YES」と出力します。 その理由は、配列全体を 1 つのグループに分割し、平均を取ると次のようになります。`x`。 
5. どちらの条件も満たされない場合は、「NO」と出力します。 許可された一連の操作では生成できないもの`x`この場合。 

機能する理由: 許可された操作は、配列を同じサイズのサブシーケンスの平均で置き換えます。 結果として得られる平均は既存の要素の凸状の組み合わせであるため、最終要素は元の配列の最小値と最大値の間になければなりません。 ターゲットが要素または全体の平均と一致する場合、それに到達するための明示的な分割シーケンスが存在します。 そうしないと、どのシーケンスでもそれを生成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    if x in a:
        print("YES")
    elif sum(a) == x * n:
        print("YES")
    else:
        print("NO")
```このソリューションは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、配列を読み取り、合計を計算します。 チェック中`x in a`最も単純なケースを即座に処理します。 比較する`sum(a)`に`x * n`平均がターゲットと等しい場合を処理します。 乗算する`x`による`n`浮動小数点精度の問題を回避します。 どちらの条件も当てはまらない場合は、「NO」が出力されます。 このアプローチは単純かつ高速であり、不必要な再帰を回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        if x in a:
            print("YES")
        elif sum(a) == x * n:
            print("YES")
        else:
            print("NO")
    
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

 ## 特殊なケース

 配列に次の要素が 1 つある場合、`x`の場合、アルゴリズムはすぐに「YES」を返します。 のために`a = [3]`そして`x = 3`、小切手`x in a`通ります。 ターゲットが平均と等しいが、それに一致する要素が 1 つもない場合、たとえば`a = [1,9,14,12,10,8]`そして`x = 9`、小切手`sum(a) == x * n`パスすると「YES」が生成されます。 すべての要素が等しい配列は、両方のチェックが成功するため、正しく処理されます。 どちらの条件も当てはまらない配列、たとえば、`a = [1,2]`そして`x = 5`、正しくは「NO」となります。
