 ## 解決策
 ## 問題の理解

 この構造では、各ステージが前の文字列を 2 倍にし、後半のビットを反転する無限のバイナリ文字列を定義します。 これにより、よく知られた Thue-Morse シーケンスが生成されますが、ここで重要な視点はその再帰的な構造ではなく、むしろ各位置の背後にある算術構造です。 

各ポジション`i`文字列内の設定ビット数のパリティによって決定されます。`i`。 書いてみると`popcount(i)`のバイナリ表現における 1 の数として`i`、次に位置の値`i`は`S[i] = popcount(i) mod 2`。 これにより、建設をシミュレーションする必要がなくなります。 

このタスクでは、2 つの長さの間のハミング距離が求められます。`m`部分文字列: 位置から始まる 1 つ`0`、および位置から始まる別の`n`。 つまり、比較してみると、`S[i]`と`S[i + n]`みんなのために`0 ≤ i < m`、不一致をカウントします。 

制約は極端で、`n`そして`m`まで`10^18`。 すべてを反復するソリューション`m`ポジションは無理です。 平`O(m)`テスト ケースごとの数はすでに大きすぎるため、最大 100 個のテスト ケースが存在する可能性があります。 この構造は、ビット単位または数字 DP レベルで利用する必要があります。 

シーケンスを定期的にシミュレートまたは圧縮しようとすると、微妙な失敗のケースが発生します。 Thue-Morse シーケンスは周期的ではないため、2 の累乗などの繰り返しブロックをサイクルとして使用しようとすると、すぐに中断されます。 もう 1 つの障害モードは、インデックスの再帰を単純に使用してシーケンスを計算することで発生します。`i`メモ化を行わないと、各クエリが作成されます。`O(log i)`を掛けてもまだ遅すぎます`m`。 

## アプローチ

 ブルートフォース手法では、Thue-Morse シーケンスの各項を個別に計算します。 それぞれについて`i`で`[0, m)`、評価します`S[i]`そして`S[i + n]`を使用して`popcount`。 それぞれの評価にかかる費用`O(log i)`ビットをカウントするため、合計の複雑さはおおよそ次のようになります。`O(m log n)`テストケースごとに。 と`m`まで`10^18`、これは単一のテストでも実行不可能です。 

重要な洞察は、位置の観点から考えるのをやめ、代わりに比較をビット単位の構造に変換することです。 条件`S[i] ≠ S[i + n]`になる`popcount(i) % 2 ≠ popcount(i + n) % 2`。 これはバイナリ加算に関するパリティ比較の問題です。 

追加`n`に`i`構造化された方法でポップカウントのパリティに影響を与えます。各キャリーはビットを切り替え、パリティの変更は間の相互作用にのみ依存します。`i`そして`n`。 すべてを繰り返すのではなく`i`、プロセスをビット上の数字 DP として扱い、キャリーとパリティ遷移を追跡します。 

最下位から最上位までビットを処理します。 各ビットで、現在のビットがわかります。`i`、の対応するビット`n`、下位ビットからのキャリー。 これにより、結果のビットを決定できるようになります。`i + n`そしてポップカウントのパリティがどのように変化するか。 それから何個数えますか`i`特定の範囲内では不一致状態が生成されます。 

これにより、問題は、位置、桁上げ、およびパリティの差によって定義される状態をもつ有界桁 DP に縮小されます。 以来`n, m ≤ 10^18`、ビット数は最大 60 であるため、この DP は効率的になります。

 ## アルゴリズムのチュートリアル

 この問題を整数を数える問題として再解釈します`i`で`[0, m)`のパリティが成り立つように、`popcount(i)`のパリティとは異なります`popcount(i + n)`。 

1.変換`n`そして`m`バイナリ配列に変換して、少しずつ処理できるようにします。 値は ≤ 10^18 であるため、最大 60 ビットまで処理します。 これにより、固定の有界 DP 深さが保証されます。 
2. DP 状態を次のように定義します。`dp[pos][carry][parity_diff]`、 どこ`pos`は現在のビットインデックス、`carry`下位ビットからこのビットへのキャリーがあるかどうか、そして`parity_diff`のパリティ間の差異を追跡します`popcount(i)`そして`popcount(i + n)`これまでのところ。 パリティを増分的に追跡する理由は、popcount パリティがビットに対して加算されるためです。 
3. 最下位から最上位までビットを繰り返します。 ビットごとに、現在のビットの両方の可能性を試します。`i`(0 または 1) ですが、選択肢を制限して、`i < m`標準のタイトバウンド DP を使用して尊重されます`m`。 
4. ビットの選定にあたって`i`、結果のビットを計算します。`i + n`この位置で使用して`i_bit + n_bit + carry`。 これにより、新しいビットと新しいキャリーが生成されます。 このステップでは、加算によって構造がどのように上位ビットに伝播されるかをエンコードします。 
5. パリティ寄与を更新します: ビットが入っている場合`i`が 1 の場合、パリティを反転します。`popcount(i)`。 同様に、結果のビットが`i + n`が 1 の場合、シフトされた文字列のパリティを反転します。 パリティが異なるかどうかを維持します。 
6. 最終ビット位置で、パリティ差が 1 であるすべての DP 状態を合計します。これらは、次の位置に対応するためです。`S[i] ≠ S[i + n]`。 この合計がテスト ケースの答えになります。 

### なぜ効果があるのか

 正確さは、Thue-Morse 値がポップカウントのパリティと定数による加算のみに依存するという事実から来ています。`n`は、ローカル ビット遷移とキャリー伝播によって完全に決定されます。 DP は可能な限りすべてを列挙します`i`両方のプレフィックス制約を維持しながら、正確に 1 回 (`i < m`) と加算時のパリティの正確な変換。 近似は導入されておらず、すべての有効な`i`正確に 1 つの DP パスに寄与し、最終的なカウントが正確であることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m):
    N = n
    M = m

    # extract bits
    nb = [(N >> i) & 1 for i in range(61)]
    mb = [(M >> i) & 1 for i in range(61)]

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, carry, tight, parity_i, parity_j):
        if pos == 61:
            return 1 if parity_i != parity_j else 0

        limit = mb[pos] if tight else 1

        res = 0
        for bi in range(limit + 1):
            # compute i + n bitwise
            s = bi + nb[pos] + carry
            bj = s & 1
            nc = s >> 1

            ni_tight = tight and (bi == limit)

            # update parities
            n_parity_i = parity_i ^ bi
            n_parity_j = parity_j ^ bj

            res += dp(pos + 1, nc, ni_tight, n_parity_i, n_parity_j)

        return res

    return dp(0, 0, 1, 0, 0)

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    print(solve_case(n, m))
```この実装では、61 ビットにわたって数字 DP を実行し、次の値の変化を追跡します。`i`～までの厳しい制約の下で`m`そしてキャリー動作`i + n`。 2 つのパリティ アキュムレータは、次の Thue-Morse 値を表します。`i`そして`i + n`。 再帰のリーフでの最後の比較では、不一致が正確にカウントされます。 

よくある落とし穴は、両方の文字列がポップカウント パリティに独立して依存していることを忘れることです。 パリティだけであれば、`i`の単純な変換規則を仮定しながら追跡されます。`i + n`、キャリー伝播とビット反転の間の相互作用が失われ、正確性が損なわれます。

import sys, io

def run(inp: str) -> str:

    def solve():
        t = int(input())
        for _ in range(t):
            n, m = map(int, input().split())

            def S(x):
                return bin(x).count("1") & 1

 ## 特殊なケース

 主なエッジケースは次のような場合です`n = 0`。 この場合、両方の部分文字列が同一であるため、答えは常に 0 になります。 DP はこれを自然に処理します。`i + 0`は、すべての位置でポップカウントとパリティの両方を保持するため、すべてのパスは等しいパリティ状態で終了します。 

別のエッジケースが発生するのは次の場合です。`m = 1`。 DP は単一のインデックスの評価に帰着します`i = 0`、唯一の不一致条件は、`S[0]`等しい`S[n]`。 以来`S[0] = 0`、結果は完全にパリティに依存します。`n`、DP はビットレベルでキャリーフリー加算を通じてこれをキャプチャします。 

大型用`n`そして`m`、キャリーの伝播が支配的な効果になります。 DP はすべてのビットでキャリーを明示的に追跡し、次のような長い加算チェーンが確実に行われるようにします。`1111 + 1`複数のビットにわたって正しく伝播し、局所的な近似エラーを防ぎます。
