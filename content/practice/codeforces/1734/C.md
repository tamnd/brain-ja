 ## 問題の理解

 最初のセットが与えられました$n$正の整数、$S = \{1, 2, \dots, n\}$、そして、いくつかの要素を削除して、サブセットのみを削除したいと考えています。$T$残っています。 削除は無料ではありません。番号を選択します$k$の最小倍数を削除します$k$現在いる$S$に等しいコストを支払います$k$。 私たちの使命は達成することです$S = T$最小限の総コストで。 

入力は複数のテスト ケースを提供します。 各テスト ケースが提供するのは、$n$および長さのバイナリ文字列$n$ここで、「1」は要素がそのまま残されることを示します。$T$「0」は削除する必要があることを示します。 出力は、含まれていないすべての要素を削除するための最小コストです。$T$。 

制約が厳しい:$n$到達できる$10^6$、テストケースの合計が以下を超えないものとする。$10^6$。 これは、どのソリューションもおおよそ線形または線形に近い時間で実行する必要があることを意味します。$n$テストケースごとに。 考えられるすべての削除シーケンスを試みる二次的または単純な反復的アプローチでは、時間がかかりすぎます。 

多数の大きな数の倍数である小さな数が保存される場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$T = \{3\}$で$S = \{1,2,3,4\}$、最初に 1 と 2 を削除するには、慎重に選択する必要がある場合があります。$k=1$コスト効率を考えると、$k=2$4. 不用意なアプローチでは、より小さい番号の倍数として実行した場合、後の番号の削除の方がコストが安くなる可能性があることを考慮せずに、番号を順番に削除しようとする可能性があります。$k$。 

## アプローチ

 ブルートフォース手法では、含まれていない数値ごとにプロセスを正確にシミュレートします。$T$、可能な限り反復します$k$値を使用して最小の倍数を削除します。 これは、最終的には削除されるすべての数値がいくつかの倍数として到達可能になるため機能します。$k$。 ただし、各数値を何度も繰り返す必要がある場合があります。$k$、最悪の場合の操作が重要になります$O(n^2)$。 のために$n = 10^6$、これは不可能です。 

最適化のための重要な洞察は、それぞれの数値が$x$削除できるのは 1 回のみで、最も安価な削除方法です$x$常に最小のものを選択することです$k$それは分ける$x$より小さい倍数によってまだブロックされていない$k$保存されている。 これは、数値を順番に反復し、削除する必要がある数値ごとに、ブロックされていない最小の除数コストを追加することと同じです。 これにより、問題がふるいのようなプロセスに変換されます。数値を反復処理し、倍数の場合は、倍数が保持されない限りコストを伝播します。$T$。 

事実上、1 から 2 までの数値を処理します。$n$。 それぞれの番号について$i$、入っていない場合は$T$、追加します$i$総コストに。 次に、すべての倍数について$j = 2i, 3i, \dots, n$の場合、伝播をスキップします。$j$保存されない場合は、削除コストが発生します。$j$後で小さい除数によって処理されます$i$。 これにより、決して過剰にカウントせず、常に利用可能な最小値を使用することが保証されます。$k$。

 ## アルゴリズムのチュートリアル

 1.読む$n$そしてそれを表すバイナリ文字列$T$。 文字列をブール配列に変換します$keep[1..n]$, where True indicates the number must remain.
 2. 変数を初期化する$total\_cost = 0$削除のコストを蓄積するため。 
3. 反復処理$i = 1$に$n$。 それぞれについて$i$：

- もし$keep[i]$は True、スキップします$i$削除してはいけないからです。 
- もし$keep[i]$は偽です、追加します$i$に$total\_cost$。 これが最低限の撤去費用です$i$以来$i$それ自体で割り切れます。 
- 複数の場合$j = 2i, 3i, \dots, n$：

- もし$keep[j]$が True の場合、保存された数値により、より小さい約数によるさらに安価な削除がブロックされるため、この倍数による伝播を停止します。 
- それ以外の場合は続行します。 将来の倍数は次の場合に処理されます。$i$彼らに届きます。 
4. すべての数値を処理した後、出力します$total\_cost$。 

不変条件は、以下に含まれないすべての数値です。$T$可能な限り最小の値を使用して 1 回だけ削除されます$k$それがそれを分けるのです。 の数字$T$伝播をブロックし、不用意に削除しないようにします。 このアルゴリズムでは、各ステップで削除ごとに利用可能な最小の除数が選択されるため、コストが最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        keep = [c == '1' for c in s]
        total_cost = 0
        used = [False] * (n + 1)
        
        for i in range(1, n + 1):
            if keep[i - 1]:
                continue
            j = i
            while j <= n:
                if keep[j - 1]:
                    break
                if not used[j]:
                    total_cost += i
                    used[j] = True
                j += i
        print(total_cost)

if __name__ == "__main__":
    solve()
```の`used`配列では、複数の約数が到達する可能性がある場合でも、各数値が 1 回だけ削除されることが保証されます。 倍数を反復する`j += i`すべての番号が最初に最も安価な削除を受けることを保証します。 保存された番号は伝播を停止し、誤って削除されるのを防ぎます。 アルゴリズムは維持します$O(n \log n)$倍数の調和系列の動作による複雑さ。
