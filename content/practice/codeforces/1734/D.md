 ## 解決策
 ## 問題の理解

 位置から開始します`k`の行に`n`スライム。 各位置にはある程度の健康値を持つスライムが含まれており、まだスライムがいる位置に足を踏み入れると、スライムを吸収してその健康値を自分の健康値に追加します。 負の値は健康を低下させ、正の値は健康を増加させます。 私たちのスライムは、どんな瞬間でもゼロ以下になることは決して許されません。 

目標は、左または左の位置に向かって一歩ずつ移動することです`0`または位置に向かって右`n+1`、スライムは食べられると消えるので、私たちが通過するすべてのものを吸収します。 最初にどの方向に進むかを決定することで、暗黙的に拡張の順序を選択することができますが、ポジションを通過すると、そのポジションは失われます。 

主な難しさは、合計が負でないかどうかを単にチェックしているわけではないことです。 パスのすべてのプレフィックスで、実行状態が決してマイナスにならないようにする必要があり、最初に「より安全な」方向を選択する必要がある場合があります。 

制約は大きく、合計すると`n`最大 200,000 のすべてのテスト ケースにわたって。 これにより、インターバルにわたる二次シミュレーションや、考えられるすべての左右インターリーブの試行が除外されます。 すべてのソリューションはテストごとに線形であるか、全体的に償却が線形である必要があります。 これは、各位置が最大でも一定の回数処理されること、および決定がプレフィックスのような、または貪欲な実行可能性チェックに依存していることを強く示唆しています。 

微妙な落とし穴は、合計額のみが重要であると想定していることです。 たとえば、次のようなセグメントについて考えてみましょう。`[-5, +100, -200, +200]`。 合計は正ですが、吸収の順序を間違えると、大きな正の値に達する前に負の接頭辞に達する可能性があります。 もう 1 つの失敗例は、反対側に触れる前に、片側のすべてのスライムを完全に取らなければならないと仮定した場合です。 実際、最適な戦略には、切り替えても「十分安全」になるまで片側だけを延長することが含まれる場合があります。 

## アプローチ

 素朴な見方は、両方の可能性をシミュレートすることです。つまり、左から先に行くか右から先に行くかを試し、外側に拡張するすべての方法を再帰的に検討します。 各ステップで、左または右に移動することを選択し、健康状態がマイナスでない状態を維持しているかどうかを確認して、続行します。 すべての状態は現在の間隔によって定義されるため、これはすぐに指数関数的になります。`[L, R]`とその内部の位置、および方向の分岐により組み合わせ爆発が作成されます。 

「完全に左に移動してから完全に右に移動する」、またはその逆のような単調な戦略に限定したとしても、中間の実現可能性が重要であるため、これは依然として失敗します。セグメントの合計が正になる可能性がありますが、ゼロ以下の落ち込みを避けるために特定の順序で吸収する必要があります。 

重要な観察は、一度片側を完全に消費すると決定すると、内部の順序が固定されるということです。 したがって、問題は、現在の健全性を考慮してそれぞれの拡張が実行可能であるように、ある順序で左右に拡張できるかどうかを確認することに帰着します。 重要な洞察は、片側への拡張の実現可能性は、現在の健全性から開始してセグメント全体を横断できるかどうかのみに依存するということです。健全性は、外側に向かってスキャンし、最小のプレフィックス合計を維持することで貪欲にチェックできます。 

したがって、すべてのパスをシミュレートするのではなく、開始点から各サイドを完全に消費できるかどうかを事前計算し、現在安全なサイドを貪欲に拡張し、間隔が伸びるにつれて健全性を更新します。

 ## アルゴリズムのチュートリアル

 私たちは推論を開始位置に根付かせます`k`、現在の到達可能な領域を外側に拡張するセグメントとして扱います。 

1. から左に展開できるかどうかを計算します。`k`健康状態がゼロ以下にならないようにしながら、可能な限り距離を保ちます。 一度に 1 歩ずつ左に移動して健康状態を更新し、さらに先に進むことができなくなったときに停止することをシミュレートします。 これにより、到達可能な最大の左境界が得られます。 
2. 同様に、右からどこまで拡張できるかを計算します。`k`同じルールの下で。 これにより、到達可能な最大の右境界が得られます。 
3. どちらかの側が境界線を越えた場合 (`0`または`n+1`）、すぐに逃げられます。 
4. それ以外の場合は、問題を間隔を維持するものとして扱います`[L, R]`最初は`[k, k]`、現在の健康状態は次のとおりです`a[k]`。 
5. 間隔を外側に拡張しようとします。 各段階で、左のいずれかを次のように拡張することを検討します。`L-1`または権利`R+1`ただし、そのサイドセグメント全体が「実行可能」である場合に限ります。つまり、マイナスにならずに現在の健康状態から開始して横断できる場合に限ります。 
6. 実現可能性を効率的にテストするために、セグメントのプレフィックス合計を維持し、内線番号に沿った最小プレフィックス合計が下回らないようにします。`-current_health`。 これにより、吸収中にゼロを越えないことが保証されます。 
7. 現在実現可能な方を貪欲に拡張します。 両方が実現可能な場合は、両方の拡張が非負の健全性を維持するため、どちらの順序でも機能します。 
8. どちらかに到達するまで続けます`0`または`n+1`。 

### なぜ効果があるのか

 どの時点においても、重要な制約は、非負プレフィックス条件に違反せずに完全な連続セグメントを消費できるかどうかだけです。 セグメントが実現可能になったら、それを完全に消費するのが常に最適です。これは、到達可能なポジションを拡大することで柔軟性を高めるだけであり、すでに実現可能性が考慮されている健康状態の変化による場合を除き、将来のオプションを減らすことはありません。 このプロセスは、現在の間隔という不変条件を維持します。`[L, R]`健康上の制約を破ることなく、ある順序で完全に消費可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_cross(a, k):
    n = len(a) - 1
    left = k
    right = k
    health = a[k]

    if health < 0:
        return False

    # Try expanding greedily
    while True:
        moved = False

        # try left
        if left > 1:
            h = health
            ok = True
            for i in range(left - 1, 0, -1):
                h += a[i]
                if h < 0:
                    ok = False
                    break
            if ok:
                for i in range(left - 1, 0, -1):
                    health += a[i]
                left = 1
                moved = True

        # try right
        if right < n:
            h = health
            ok = True
            for i in range(right + 1, n + 1):
                h += a[i]
                if h < 0:
                    ok = False
                    break
            if ok:
                for i in range(right + 1, n + 1):
                    health += a[i]
                right = n
                moved = True

        if not moved:
            break

        if left == 1 or right == n:
            return True

    return left == 1 or right == n

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = [0] + list(map(int, input().split()))
        print("YES" if can_cross(a, k) else "NO")

if __name__ == "__main__":
    solve()
```実装は現在の間隔を維持し、完全なサイド セグメントが安全に吸収できる場合にのみ外側に拡張しようとします。 内部実行可能性チェックは、実行合計を通じて暗黙的に最小ヘルスを追跡しながら、候補側の消費をシミュレートします。 

主な微妙な点は、セグメント全体が安全であることがわかっている場合にのみ拡張をコミットすることです。 部分的な消費は、実行可能性テストと状態の突然変異が混在するため、チェックフェーズでは決して許可されません。 もう 1 つの重要な詳細は、境界条件の保護です。`left == 1`または`right == n`つまり、まだ脱出セルにもう一歩進むことができるということです。 

## 実用的な例

 ### 例 1

 入力:```
7 4
-1 -2 -3 6 -2 -3 -1
```インデックス 4 の健康状態 6 から始めます。 

| ステップ | 左 | 右 | 健康 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 6 | 開始 |
 | 2 | 4 | 7 | 6 → -3 | 右いっぱいに展開 |
 | 3 | 4 | 7 | 6 → -3 → ​​-6 → -7 | 右拡張は早期に無効です |

 まず右側は安全に消耗できないため、代わりに左側の拡張を試します。 

| ステップ | 左 | 右 | 健康 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 4 | 4 | 6 | 開始 |
 | 2 | 1 | 4 | 6 → 5 → 3 → 0 | 左いっぱいに展開 |
 | 3 | 1 | 4 | 0→6→4→1 | 次に、右に展開します |

 無事に両端に到達しました。 

これは、正しい戦略は方向性の偏りではなく、実現可能性に基づいた拡張であることを示しています。
