 ## 解決策
 ## 問題の理解

 2-3-4 検索ツリーへの一連の挿入をシミュレートする必要があります。 値は次の順列です。`1..n`したがって、すべての値は 1 回だけ表示されます。 ノードには 1 つ、2 つ、または 3 つのソートされたキーが含まれる場合があります。 3 つのキーを持つノードはいっぱいです。 完全なノードを下降する前に、ノードを分割し、その中間のキーを親に移動します。 フルノードがルートの場合、中央のキーが新しいルートとなり、ツリーは 1 レベルずつ成長します。 

すべての挿入の後、必要な出力は事前順序のツリー全体です。 訪問したノードごとに、そのすべてのキーを昇順で 1 行に出力します。 

入力には最大 50 個の独立したテスト ケースが含まれており、1 つのケースに最大 5000 個の挿入が含まれます。 2-3-4 ツリーの高さは対数であるため、各挿入がツリー パスに従う場合は、直接シミュレーションで十分です。 と`n = 5000`、たとえ`O(n log n)`実装では、テスト ケースあたり数万回程度のノード操作のみが実行されます。 50 のケースすべてで、挿入された値の合計は 250,000 に達する可能性があるため、`O(n²)`ケースごとの操作は依然として役立ちます。 

最も一般的な正当性の間違いは、分割に関して発生します。 たとえば、`1 2 3 4`与える```
Case #1:
2
1
3 4
```4 番目の挿入は単に追加するだけではありません。`4`根元まで。 降りる前に根元から`[1 2 3]`周りに分かれている`2`、根を生成します`[2]`子供たちと一緒に`[1]`そして`[3]`。 値`4`次に、右側の子に入ります。 

逆の広告掲載オーダーは、反対側から同じ境界を適用します。 のために```
1
4
4 3 2 1
```正しい木は```
Case #1:
3
1 2
4
```間違ったキーをプロモートしたり、間違った順序で子を作成したりする不注意な実装では、通常、表面的​​には有効な検索ツリーが生成されますが、異なる事前順序トラバーサルが生成されます。 

2 番目の微妙なケースは、非ルート ノードがいっぱいの場合に発生します。 ルートがすでに分割されており、後で挿入すると完全な子に到達するとします。 中央のキーは既存の親に挿入する必要があり、残りの 2 つの部分は元の子を置き換えます。 このようなノードをルートであるかのように分割すると、ツリーの高さが誤って増加します。 

最後に、最初の 3 つの挿入では、ルートが単一ノードとして開始されるため、特別に見える動作が行われます。 のために`1 2 3`、ツリーは単なる 1 つのノードです。`1 2 3`。 分割は、完全なノードを作成した直後ではなく、次の挿入を処理するときに実行されます。 

## アプローチ

 最も直接的なブルート フォース シミュレーションでは、ツリーを明示的に維持し、新しい値ごとに、適切な間隔が見つかるまで既存のツリーをスキャンして宛先リーフを検索します。 これは正しいです。すべてのキーが 1 つの子間隔に属し、完全なノードを分割すると検索ツリーの順序が保持されるためです。 ただし、最悪の場合、スキャンにより既存のすべてのノードが検査される可能性があります。 前に`i`-番目の挿入があります`i-1`保存された値、最大でも`i-1`したがって、意図的に徹底的な検索を実行すると、`1 + 2 + ... + (n-1) = n(n-1)/2`ノードの検査。 のために`n = 5000`つまり、1 つのテスト ケースでは 1,249 万 7,500 件の検査が行われ、最大サイズの 50 件のケースでは最大約 6 億 2,500 万件の検査が行われることになります。 Python は、ツリーの無関係な部分を繰り返し走査するのにそれほど多くの時間を費やすべきではありません。 

ブルートフォースアプローチが機能するのは、ツリー自体に次の子の選択に必要な情報がすでに含まれているためです。 重要な観察は、2-3-4 ツリーが構造によってバランスが取れているということです。 すべてのルートからリーフへのパスは同じ長さを持ち、すべての内部ノードには少なくとも 2 つの子があります。 したがって、高さは、`O(log n)`。 無関係なサブツリーを検査する必要はありません。 すべてのノードで、その 1、2、または 3 つのキーが残りの検索スペースを 2、3、または 4 つの間隔に分割するため、1 つの比較シーケンスで 1 つの子が正確に識別されます。 

これにより、標準的なトップダウンの B ツリー挿入戦略が得られます。 検索パスをたどる際、完全なノードを分割してからそのノードに降りてください。 完全なノードには以下が含まれます`[a, b, c]`、 それで`b`上に移動すると、ノードは次の要素を含む 2 つのノードになります。`[a]`そして`[c]`。 ノードに子がある場合、最初の 2 つの子は残ります。`[a]`そして最後の2つは残ります`[c]`。 リーフに到達すると、そのリーフには最大 2 つのキーがあるため、新しい値をそこに挿入するだけで済みます。 

結果として得られる実装は、問題からの挿入手順に正確に従いますが、実際のツリー上のノードのみを保存し、無関係なサブツリーを検索することはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n²)`|`O(n)`| 最悪の場合は遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのノードをソート順に表現します`keys`リストとその`children`リスト。 リーフには子がなく、2 ノードには 1 つのキーがあり、3 ノードには 2 つのキーがあり、4 ノードには 3 つのキーがあります。 内部ノードには、キーの数よりちょうど 1 つ多い子があります。 
2. 挿入するすべての値について、まずルートがいっぱいかどうかを確認します。 3 つのキーが含まれている場合は、それを 2 つの子に分割し、その中間のキーを新しいルートにプロモートします。 これはツリーの高さを増やす唯一の操作です。 
3. ルートから開始して、子を選択する前に現在のノードを処理します。 現在のノードがリーフの場合、ソートされたキー リストに値を挿入して停止します。 フルノードは、そこに降りる前に分割されるため、ノードがすでにフルであることはできません。 
4. 現在のノードが内部ノードである場合は、どの子に新しい値が含まれているかを確認します。 鍵付き`[k0]`, より小さい値`k0`子 0 に進み、より大きな値は子 1 に進みます。 と`[k0, k1]`、間隔は 3 つあります。 と`[k0, k1, k2]`、4つあります。 
5. 選択した子に降りる前に、その子がいっぱいかどうかを確認します。 そうなった場合は、すぐに分割してください。 その中間のキーが現在のノードに移動し、結果として得られる 2 つのノードが元の完全な子を置き換えます。 このため、最終的な子インデックスを選択する前に親を変更する必要があります。 
6. 子を分割した後、値を新しくプロモートされたキーと比較します。 値がプロモートされたキーより大きい場合、正しい宛先は新しい右側の子となるため、子のインデックスをインクリメントします。 それ以外の場合、値は左側の子に属します。 
7. 葉に到達するまで下降を繰り返します。 ソートされた挿入操作を使用して、値をリーフに挿入します。 
8. すべての値を挿入した後、事前順序トラバーサルを実行します。 まず現在のノードを出力し、次にその子を左から右に再帰的にアクセスします。 

重要な不変条件は、下降するたびに、進入するノードが満員ではないことです。 すべての分割では、キーの並べ替え順序と、子の間隔とキー間の対応が保持されます。 すべての挿入は、その間隔に値が含まれる一意のリーフに行われるため、すべての値は検索ツリーの順序に残ります。 すべての完全なノードは降下前に分割されるため、挿入後に 4 つのノードを変更する必要はなく、ツリーはプロセス全体を通じて有効なバランスの取れた 2-3-4 ツリーのままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("keys", "children")

    def __init__(self, keys=None, children=None):
        self.keys = [] if keys is None else keys
        self.children = [] if children is None else children

    def is_leaf(self):
        return not self.children

def split_child(parent, idx):
    """
    parent.children[idx] is a full node with three keys.

    Split:
        [a, b, c]
    into
        [a] and [c]
    and promote b into parent.
    """
    node = parent.children[idx]

    middle = node.keys[1]

    left = Node([node.keys[0]])
    right = Node([node.keys[2]])

    if node.children:
        left.children = node.children[:2]
        right.children = node.children[2:]

    parent.keys.insert(idx, middle)
    parent.children[idx] = left
    parent.children.insert(idx + 1, right)

def insert(root, value):
    # A full root has to be split before we start descending.
    if len(root.keys) == 3:
        new_root = Node([], [root])
        split_child(new_root, 0)
        root = new_root

    cur = root

    while True:
        if cur.is_leaf():
            # The leaf is guaranteed not to be full.
            if not cur.keys:
                cur.keys.append(value)
            elif value < cur.keys[0]:
                cur.keys.insert(0, value)
            elif value > cur.keys[-1]:
                cur.keys.append(value)
            else:
                # Input is a permutation, so this branch is unreachable.
                pos = 0
                while pos < len(cur.keys) and cur.keys[pos] < value:
                    pos += 1
                cur.keys.insert(pos, value)
            return root

        # Find the child interval containing value.
        idx = 0
        while idx < len(cur.keys) and value > cur.keys[idx]:
            idx += 1

        # Split a full child before descending into it.
        if len(cur.children[idx].keys) == 3:
            split_child(cur, idx)

            # The promoted key now sits at cur.keys[idx].
            if value > cur.keys[idx]:
                idx += 1

        cur = cur.children[idx]

def preorder(root, out):
    out.append(" ".join(map(str, root.keys)))
    for child in root.children:
        preorder(child, out)

def solve():
    t = int(input())
    output = []

    for case_id in range(1, t + 1):
        n = int(input())
        a = list(map(int, input().split()))

        root = Node()

        for value in a:
            root = insert(root, value)

        output.append(f"Case #{case_id}:")
        preorder(root, output)

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```の`Node`クラスは表現を意図的に小さく保ちます。 ノードには最大 3 つのキーと最大 4 つの子があるため、ノード内の Python リスト操作は漸近分析では定数時間になります。`split_child`中心的な構造操作を実装します。 フルノードの場合`[a, b, c]`、鍵`b`親に昇格します。 左側のノードは受信します`a`そして右のノードが受信します`c`。 元のノードが内部ノードの場合、最初の 2 つの子は左側のノードに属し、最後の 2 つの子は右側のノードに属します。 スライスインデックス`[:2]`そして`[2:]`これは、検索ツリー間隔で必要な 4 つの子分割とまったく同じです。 

ルートには、中間キーをプロモートできる親がないため、個別に処理されます。 結果として得られる 2 つの子を含む新しいルートを作成することは、ツリーの高さを 1 つ増やすことと同じです。 

非 root 完全な子の場合、`split_child(cur, idx)`プロモートされたキーを正確な位置に挿入します`idx`親に配置し、左半分の直後に右半分を挿入します。 挿入された値がプロモートされたキーよりも大きい場合、子インデックスをインクリメントする必要があります。 古い子インデックスは左半分を参照するようになったため、この調整を忘れることは誤った答えの一般的な原因となります。 

ノードには最大 3 つのキーしかないため、リーフの挿入では Python リストが使用されます。 これらのいくつかの要素を移動しても、意味のある漸近コストは発生しません。 入力は順列であることが保証されているため、重複処理が実際に必要になることはありません。 

最後の走査では、子ノードの前にノードが出力されます。これは正確には事前順序走査です。 子はすでに左から右に格納されているため、リスト順にアクセスすると、追加の並べ替えを行わずに必要な走査が可能になります。 

すべての値が間にあるため、Python 整数オーバーフローはここでは無関係です。`1`そして`n`、ツリーはそれらの値を直接保存します。

 ## 特殊なケース

 最小の有効な入力は次のとおりです。`n = 1`順列で`1`。 ルートは空から始まり、`1`が直接挿入され、事前注文トラバーサルは次の内容を含む 1 行を正確に出力します。`1`。 特別な分割や子の走査は関係ありません。 

のために`n = 4`そして入力`1 2 3 4`、ルートは次のようになります`[1 2 3]`最初の 3 回の挿入後。 加工前`4`、アルゴリズムはルートがいっぱいであることを検出し、プロモートします`2`、子を作成します`[1]`そして`[3]`。 以来`4 > 2`、子のインデックスは右側に残り、`4`に挿入されます`[3]`、生産`[3 4]`。 出力は正確に`2`、`1`、`3 4`予約注文中。 

のために`n = 4`そして入力`4 3 2 1`、完全なルートは次のとおりです。`[2 3 4]`挿入する前に`1`。 真ん中のキー`3`促進され、生産されます`[3]`子供たちと一緒に`[2]`そして`[4]`。 以来`1 < 3`、アルゴリズムは左の子に降りて次を取得します。`[1 2]`。 これにより、中央のキーではなく最初または最後のキーを誤って昇格させる実装が捕捉されます。 

より深い境界ケースは、子が満杯であるのに親が満杯ではない場合に発生します。 を通じてインプットを増やすことを検討してください。`1 2 3 4 5 6 7`。 4 回目の挿入後、ルートは次のようになります。`[2]`子供たちと一緒に`[1]`そして`[3 4]`。 挿入する`5`正しい子供を作る`[3 4 5]`。 挿入する前に`6`、その子は周りに分かれています`4`, したがって、ルートは次のようになります`[2 4]`子供たちと一緒に`[1]`、`[3]`、 そして`[5]`。 値`6`次に 3 番目の子が入ります。 さらに挿入すると、別の子がいっぱいになり、別のローカル分割がトリガーされる可能性があります。 子が分割されただけでルートが新しいレベルを取得するわけではありません。ルート処理を通常の子の処理から分離する必要があるのはまさにこのためです。
