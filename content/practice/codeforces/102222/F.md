 ## 問題の理解

 都市の完全な方向性のない重み付けグラフができました。 市`i`リスク値がある`r[i]`、 そして`d[i][j]`都市間の直線移動距離です`i`そして`j`。 クエリは 2 つのエンドポイントを提供します`u`そして`v`、リスクしきい値とともに`w`。 

そのクエリでは、からの最短ルートが必要です。`u`に`v`1 つの制限の下では、ルート上のすべての中間都市は最大でもリスクを負わなければなりません`w`。 制限は 2 つのエンドポイント以外の都市に適用されるため、エンドポイント自体はリスクに関係なく許可されます。 からの直接エッジ`u`に`v`したがって、次の場合には常に有効な候補になります。`u != v`。 

入力には最大 50 の独立したテスト ケースが含まれます。 各テスト ケースには最大 200 の都市と最大 20,000 のクエリが含まれます。 距離行列によって都市の各ペア間にエッジがすでに与えられているため、グラフは密になっています。 以来`n`わずか 200 です、`O(n^3)`前処理アルゴリズムは実用的です。 クエリ数が多いと、避けるべきことが変わります。すべてのクエリに対して完全な最短パスの計算を個別に実行すると、コストがかかりすぎます。 

ブルート フォース コストを見積もる便利な方法は、最大値を取ることです。`n = 200`そして`q = 20,000`。 フロイド・ウォーシャル計算には約`200^3 = 8,000,000`1 つのクエリに対する緩和の反復。 すべてのクエリに対してこれを繰り返すと、おおよその結果が得られます`1.6 * 10^11`Python のオーバーヘッドを考慮する前に、最悪の場合の反復を行います。 コストのかかるグラフ計算をクエリの数に関係なく実行する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、エンドポイントはしきい値を満たす必要はありません。 たとえば、次のように考えてみましょう```
1
2 1
10 1
0 5
5 0
1 2 1
```中間都市がまったくないため、都市 1 から都市 2 への直接ルートは有効であり、答えは次のようになります。`5`。 リスクが超過するすべての都市を排除するソリューション`w`エンドポイントを含む、ルートが不可能であると誤って宣言されてしまいます。 

2 番目に、エンドポイントは同じ都市にすることができます。 例えば、```
1
1 1
100
0
1 1 1
```答えは`0`。 すでに目的地に到着しており、中間都市は使用されないため、都市はしきい値を満たす必要はありません。 

3 番目に、パスは許可された複数の中間都市を使用できます。 例えば、```
1
3 1
1 1 2
0 10 100
10 0 10
100 10 0
1 3 1
```しきい値あり`1`、都市 2 は中間都市として許可されているため、ルートは`1 -> 2 -> 3`費用`20`、直接コストよりも優れています`100`。 フロイド・ウォーシャル緩和の反復を許可せずに、直接エッジのみ、または 1 つの中間都市のみをチェックするソリューションでは、この改善は見逃されます。 

「他の都市」という表現は、しきい値がパスの頂点セット全体に対するものではなく、中間の頂点に対する制限であることも意味します。 この違いが、ソリューションの背後にある中心的な詳細です。 

## アプローチ

 簡単なアプローチは、すべてのクエリを個別に処理することです。 お問い合わせの場合`(u, v, w)`、元の距離行列から始めて、次の条件を持つ都市のみを許可しながらフロイド-ウォーシャルを実行できます。`r[i] <= w`中間頂点として。 ここでの Floyd-Warshall は正しいです。許可された中間都市のセットを処理した後、`dist[i][j]`からの最短ルートを表します`i`に`j`その内部頂点がそのセットに属します。 

問題は繰り返し作業です。 と`n = 200`、フロイド・ウォーシャルの実行コストは 1 回分です。`O(n^3) = O(8 * 10^6)`。 と`q = 20,000`クエリ、最悪のケースは`O(qn^3)`、 その周り`1.6 * 10^11`リラクゼーション操作。 グラフ自体はクエリ間で変化せず、最大許容リスクのみが変化するため、同じ緩和を再計算するのは無駄です。 

重要な観察は、許容される中間都市のセットが次のように単調に増加するということです。`w`が増加します。 すべての都市をリスク順に分類するとします。 しきい値が小さい場合、おそらく最も安全な都市のみが中間として利用可能です。 しきい値が次の都市を含めるほど大きくなった場合、以前のすべての作業を再計算する必要はありません。 現在の最短パス行列を取得し、新しく有効になった都市を使用してフロイド-ウォーシャル フェーズを 1 つだけ実行できます。 

これはまさにフロイド＝ウォーシャルの構造である。 その`k`- 番目のフェーズで頂点を追加します`k`内部で使用できる頂点のセットに追加します。 ここでは、都市インデックスではなく都市リスクに従って、これらのフェーズの順序を単純に選択します。 

クエリを昇順で処理できます。`w`。 並べ替えられたクエリを処理しながら、リスクが現在のクエリのしきい値以下であるすべての都市を段階的にアクティブ化します。 都市がアクティブになるたびに、フロイド・ウォーシャル緩和フェーズが 1 回実行されます。 結局のところ、すべての都市は`r[i] <= w`がアクティブ化されている場合、マトリックスには、そのクエリで許可されている中間都市を正確に使用した最短パスが含まれています。 

エンドポイントは概念的に特別な考慮が必要ですが、マトリックスに特別な変更を加える必要はありません。 たとえ`u`または`v`～より大きなリスクがある`w`、ダイレクトエッジ`u -> v`は存在したままであり、フロイド-ウォーシャル行列はどちらかのエンドポイントをソースまたは宛先として使用できます。 どの頂点が中間頂点として使用されるかを制御するだけです。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(qn^3)`|`O(n^2)`| 遅すぎる |
 | 最適 |`O(n^3 + q log q)`|`O(n^2 + q)`| 承認済み |

 の`q log q`この用語はクエリを並べ替えることから来ています。 フロイド-ウォーシャル段階が寄与する`O(n^3)`なぜならそれぞれの`n`都市は 1 回だけアクティブ化されます。 

## アルゴリズムのチュートリアル

 1. すべての都市のリスクと完全な距離マトリックスを読み取ります。 行列を現在の最短経路行列として保持し、最初は直接移動距離のみを含みます。 
2. 都市インデックスをリスク値で並べ替えます。 ソートされた順序によって、各都市がいつ中間頂点として利用可能になるかが決まります。 
3. すべてのクエリを読み取り、各クエリを元の位置とともに保存します。 クエリをしきい値で並べ替えます`w`なぜなら、この順序で処理すると、許可される中間都市のセットが増えるだけだからです。 
4. ソートされた都市リストへのポインタを維持します。 現在のクエリしきい値の場合`w`、リスクが最大であるすべての都市を活性化します`w`。 新しく活性化された都市ごとに`k`、フロイド・ウォーシャルのリラクゼーションを実行します。```
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```すべてのペアに`i, j`。 

ここでは順序が重要です。 都市は一度活性化され、リスクのより小さい都市がすべて活性化された後に緩和が実行されます。 これは標準のフロイド・ウォーシャルの不変式と一致し、頂点の数値順序がリスク順序に置き換わります。 
5. 結局のところ、リスクのある都市はせいぜい`w`活性化されていて、`dist[u][v]`がクエリに対する答えです。 最終出力が入力順のままになるように、クエリの元の位置に保存します。 
6. 回答を元のクエリの順序で出力し、その前に必要な文字列を付けます。`Case #x:`ヘッダ。 

### なぜ効果があるのか

 都市の直後の瞬間を考えてみましょう`k`がアクティブ化されました。 以前にアクティブ化された、リスクが小さいか同等のすべての都市は、すでに中間頂点として利用可能です。 加工前`k`、`dist[i][j]`は、中間都市がすでにアクティブ化されたセットに属する最短パスです。 追加後に可能になる新しく改善されたパス`k`形を持っています`i -> ... -> k -> ... -> j`、ここでは双方が以前にアクティブ化された中間都市のみを使用します。 フロイド・ウォーシャル緩和は、その可能性を正確にチェックします。`dist[i][k] + dist[k][j]`。 

最大でもリスクのあるすべての都市を活性化した後、活性化命令を超える誘導によって`w`、`dist[i][j]`中間都市がすべてリスクをほとんど負わない最短経路`w`。 エンドポイントは制限されていないため、これはまさにクエリで許可されるルートのセットです。 したがって`dist[u][v]`は必須の答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    output = []

    for case_id in range(1, t + 1):
        n, q = map(int, input().split())
        risk = list(map(int, input().split()))

        dist = [list(map(int, input().split())) for _ in range(n)]

        cities = sorted(range(n), key=risk.__getitem__)

        queries = []
        for idx in range(q):
            u, v, w = map(int, input().split())
            queries.append((w, u - 1, v - 1, idx))

        queries.sort()

        ans = [0] * q
        city_ptr = 0

        for w, u, v, idx in queries:
            while city_ptr < n and risk[cities[city_ptr]] <= w:
                k = cities[city_ptr]

                dk = dist[k]

                for i in range(n):
                    di = dist[i]
                    dik = di[k]

                    for j in range(n):
                        candidate = dik + dk[j]
                        if candidate < di[j]:
                            di[j] = candidate

                city_ptr += 1

            ans[idx] = dist[u][v]

        output.append(f"Case #{case_id}:")
        output.extend(map(str, ans))

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```実装の最初の主要部分では、行列を直接読み取ります。`dist`。 アルゴリズム全体を通じてこのマトリックスを変更するので、都市が活性化された後、`dist`現在利用可能なすべての中間都市を使用した最適な距離が含まれています。 

の`cities`配列には、リスク値そのものではなく都市のインデックスが格納されます。 並べ替える`risk.__getitem__`頂点を Floyd-Warshall に導入する正確な順序を示します。 

クエリは次のように保存されます`(w, u, v, original_index)`そして並べ替え`w`。 元のインデックスが必要なのは、並べ替えによって答えが計算される順序が変更される一方で、出力は入力の順序に従う必要があるためです。 

の`while`ループは満足するすべての都市を活性化します`risk[city] <= w`。 比較は意図的に行われています`<=`、 ない`<`。 リスクがクエリのしきい値と等しい都市が許可されます。 

活性化された都市ごとに`k`、ネストされたループは 1 つの完全なフロイド-ウォーシャル フェーズを実行します。 変数`dk`、`di`、 そして`dik`Python のインデックス作成のオーバーヘッドを軽減するために使用されるローカル参照です。 C++ では時間制限が比較的寛大ですが、Python では操作あたりのコストが大幅に高いため、行列が最大サイズに達した場合には、こうした小さな最適化が重要になります。 

緩和では Python 整数が使用されるため、整数オーバーフローの懸念はありません。 最短の単純なパスでは、最大でも次の値を使用します。`n - 1`エッジ、および最大でも各エッジで`10^5`とにかく、答えは Python の整数の範囲内に収まります。 

エンドポイントは、リスクに基づいて削除されることはありません。 マトリックスには常にすべての直接エッジが含まれており、アルゴリズムはフロイド-ウォーシャル中間として選択された頂点のみを制限します。 したがって、次のようなクエリは、`u = 1`、`v = 2`、`w = 1`都市 1 にリスクがある場合でも有効です`100`。 

自己クエリの場合も、特別な処理を行わなくても機能します。`dist[u][u]`ゼロから始まり、最短経路緩和を通じて正になることはできません。
