 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられます。最初の文字列は既知の平文で、2 番目の文字列はその Caesar 暗号化バージョンです。 シーザー暗号は、すべての大文字に 1 つの固定循環シフトを適用します。 同じシフトは 3 番目の文字列の暗号化にも使用されており、私たちのタスクは、その 3 番目の文字列の平文を復元することです。 

たとえば、次の場合`A`になる`D`、シフトは`3`、 それで`B`になる`E`、`Y`になる`B`、 そして`Z`になる`C`。 シフトが分かると、別の暗号文を復号するには、すべての文字をその量だけ後方に移動するだけで済みます。 

各テスト ケースが提供するのは、`n`、既知の平文と暗号文の長さ、および`m`、復号化する必要がある暗号文の長さ。 どちらもせいぜい`50`、最大でも`50`テストケース。 これらの制限は非常に小さいです。 全てをチェックするアプローチでも`26`おそらくシーザーのシフトと文字列のスキャンは快適に高速であり、最大でも約`26 * 50 * 50 = 65,000`すべてのテストケースにわたる文字の比較。 対応する 1 つの文字ペアからシフトを即座に回復できるため、直接的な解決策の方が依然として望ましいと言えます。 

主なエッジケースは、アルファベットの周期的な性質から生じます。 シフトをまたぐことができます`Z`に戻る`A`したがって、モジュロ演算を行わない通常の整数減算では、無効な文字コードが生成される可能性があります。 ゼロ シフトも有効です。つまり、平文と暗号文が同一である可能性があります。 ついに、`n`できる`1`したがって、シフトは単一の文字から回復可能でなければなりません。 

たとえば、1 文字のテスト ケースは次のようになります。```
1
1 1
Z
A
A
```既知のペアから、暗号化のシフトは次のようになります。`1`で、最終回`A`に復号化します`Z`。 正しい出力は次のとおりです。```
Case #1: Z
```計算する不注意な実装`ord('A') - 1`モジュロをラップする代わりに直接`26`前にキャラクターを生成できます`A`、これは有効な大文字ではありません。 

ゼロシフトの例は次のとおりです。```
1
1 3
A
A
ABC
```正しい出力は次のとおりです`Case #1: ABC`。 暗号文が平文とは異なる必要があると想定する実装では、非ゼロ シフトが誤って検索されます。 

ラップアラウンド ケースは特に便利です。```
1
2 3
YZ
ZA
ABC
```ここで、既知のペアは次のシフトを使用します。`1`、 なぜなら`Y -> Z`そして`Z -> A`。 復号化中`ABC`与える`ZAB`。 モジュロ演算を忘れると、`A`1 つ後ろに戻すと、無効な結果が生成されます。 

## アプローチ

 簡単なアプローチは、次のすべてを試してみることです。`26`シーザーシフトの可能性。 候補シフトごとに、既知の平文を暗号化し、その結果を既知の暗号文と比較します。 正確に 1 つの候補が一致することが保証されます。 それを見つけたら、3 番目の文字列に逆シフトを適用します。 

すべてのシーザー暗号は次の 1 つの値によって完全に記述されるため、この強引な方法は正しいです。`0`を通して`25`。 考えられるすべての値をチェックしても、実際の暗号化ルールを見逃すことはできません。 1 つのテスト ケースの場合、これには次の時間がかかります`O(26n + 26m)`時間、つまり単純に`O(n + m)`なぜなら`26`は定数です。 最大値で`n = m = 50`、せいぜいあります`2,600`テストケースごとの文字操作、または約`130,000`全体的に`50`ケース。 前述の制約の下では、ブルートフォース手法は実際にはそれほど遅くはありません。 

より直接的なアプローチは、シーザー シフトが対応する文字のいずれか 1 つのペアにすでにエンコードされていることを観察することから得られます。 平文が次で始まると仮定します。`A`そして暗号文は次で始まります`T`。 シフトはすぐに`19`。 より一般的には、アルファベットのインデックスが`p`そして`c`の場合、暗号化シフトは次のようになります。`(c - p) mod 26`。 入力では有効で明確なシーザー変換が保証されているため、このシフトは 3 番目の文字列内のすべての文字を復号化するのに十分です。 

ブルートフォース手法が機能するのは、`26`変換は可能ですが、不必要な検索が実行されます。 1 つの整列された文字ペアがシフトを決定するという観察により、検索を 1 回の減算と、ターゲット暗号文の 1 回の線形スキャンに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(26(n + m)) = O(n + m)`|`O(m)`| 承認済み |
 | シフトを直接導出する |`O(n + m)`|`O(m)`| 承認済み |

 直接的なアプローチは、より優れた定数係数を持ち、問題の構造を明確にします。 

## アルゴリズムのチュートリアル

 1.読む`n`、`m`、既知の平文、既知の暗号文、および復号化する必要がある暗号文。 最初の 2 つの文字列は同じ長さであるため、対応する位置を持ちます。 
2. 平文と暗号文の最初の文字をアルファベットのインデックスに変換します。`0`に`25`。 暗号化シフトを次のように計算します。`(cipher_index - plain_index) % 26`。 シーザー暗号はどこでもまったく同じシフトを使用するため、対応するペアが 1 つあれば十分です。 
3. ターゲット暗号文のすべての文字について、それをアルファベットのインデックスに変換し、復元されたシフトを減算します。 適用する`% 26`その前に移動する`A`に包み込む`Z`。 
4. 結果として得られた各インデックスを大文字に変換し、文字を連結します。 結果の先頭に次の文字を付けます`Case #x:`現在のテスト ケース番号を使用します。 

なぜ機能するのか: 暗号化を移行しましょう`s`。 既知のペアのすべての位置について、暗号文インデックスは平文インデックスに次の値を加えたものと等しくなります。`s`モジュロ`26`。 したがって`(cipher_index - plain_index) % 26`正確に回復します`s`。 暗号化されたインデックスを持つターゲット暗号文文字の場合`c`、その平文インデックスは次のようにする必要があります`(c - s) % 26`したがって、アルゴリズムによって生成されるすべての文字は、暗号文を生成した文字とまったく同じになります。 同じシフトがすべての位置に適用されるため、文字を個別に復号化すると、完全に正しい平文が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())
        plain = input().strip()
        cipher = input().strip()
        target = input().strip()

        plain_index = ord(plain[0]) - ord('A')
        cipher_index = ord(cipher[0]) - ord('A')

        shift = (cipher_index - plain_index) % 26

        decoded = []
        for ch in target:
            value = (ord(ch) - ord('A') - shift) % 26
            decoded.append(chr(value + ord('A')))

        answers.append(f"Case #{case}: {''.join(decoded)}")

    sys.stdout.write('\n'.join(answers))

if __name__ == "__main__":
    solve()
```最初の文字ペアによって決定されます。`shift`。 暗号文インデックスから平文インデックスを減算すると、平文が移動された位置の数が得られます。`% 26`正と負の両方の差を均一に処理します。 

復号化ループは逆の操作を実行します。 暗号化があった場合`plain + shift`、復号化は`cipher - shift`。 Python のモジュロ演算は、次のような負の結果が得られるため、ここでは特に便利です。`-1 % 26`になる`25`、に対応`Z`。 

この問題により、それらが 1 つの一貫したシーザー シフトによって生成されたことが保証されるため、既知の平文と暗号文の残りの文字を検査する必要はありません。 それらをチェックすると、最初のペアによってすでに決定されている情報が繰り返されるだけです。 

結果はリストに蓄積され、文字列を繰り返し連結するのではなく、最後に 1 回結合されます。 これは小さな制約には必要ありませんが、標準的な線形時間構造を提供し、不必要な中間文字列を回避します。 

Python では整数オーバーフローは発生しません。注意が必要な唯一の境界演算はモジュロです。`26`復号化が交差するとき`A`に`Z`。

        return sys.stdout.getvalue()

 ## 特殊なケース

 1 文字の場合は、特別な分岐なしで処理されます。 入力用```

1 1
Z
A
A
```インデックスは`25`そして`0`、つまりシフトは`(0 - 25) % 26 = 1`。 ターゲット`A`インデックスあり`0`、 そして`(0 - 1) % 26 = 25`、与える`Z`。 出力は`Case #1: Z`。 少なくとも 2 つの位置が存在する必要があると仮定したソリューションは、不必要に失敗します。

A
A
ABC
```回復されたシフトは、`(0 - 0) % 26 = 0`。 すべてのターゲット キャラクターは変更されず、`Case #1: ABC`。 また、モジュロ式により、ゼロ シフトが別の条件なしで自然に動作します。

1
2 3
YZ
ZA
ABC
