 ## 解決策
 ## 問題の理解

 都市の重み付けツリーがあります。 工場は元のリーフにのみ配置できます。これは、無向ツリーの次数がちょうど 1 である都市を意味します。 正確に選択しなければなりません`k`個別のリーフを選択し、選択されたリーフの順序付けされていないすべてのペアにわたる最短パス距離の合計を最小化します。 

入力には最大で次のものが含まれます`10^3`テストケース、`n`まで`10^5`1 つのテスト ケースとすべてのテスト ケースの合計`n`によって制限される`10^6`。 工場数`k`せいぜい`100`、これは動的プログラミング ソリューションを可能にするパラメーターです。 公式の制限は 10 秒および 256 MB です。 

大きな値`n`都市の数の二次関数を除外します。 平`O(nk^2)`大体届く`10^9`両方の場合の基本的な遷移`n=10^5`そして`k=100`したがって、実装では、すべてを盲目的に反復するのではなく、実際の状態の範囲を厳密に保つ必要があります。`k`すべてのノードの状態。 リーフの数自体がほぼ次の値になる可能性があるため、可能なファクトリー セットを指数関数的に検索することは完全に不可能です。`10^5`。 

最初のエッジケースは`k=1`。 工場のペアは存在しないため、ツリーに関係なく答えはゼロになります。```
1
2 1
1 2 7
```正しい出力は次のとおりです`Case #1: 0`。 誤って工場からそれ自体への距離を加算したソリューションは、ゼロ以外の値を生成します。 

2 番目のエッジ ケースは、2 つの都市を含む最小のツリーです。 どちらかの都市が実装のルートとして選択される可能性がありますが、両方の都市は葉です。```
1
2 2
1 2 7
```正しい出力は次のとおりです`Case #1: 7`。 ルート付きツリーを不用意に実装すると、子のみが選択可能なリーフとして分類され、有効なファクトリの場所が 1 つ失われる可能性があります。 

3 番目の特殊なケースは、元のリーフのみが資格があるということです。 パスを考えてみましょう。```
1
4 2
1 2 1
2 3 1
3 4 1
```工場として考えられるのは都市だけだ`1`そして`4`、したがって、答えは次のとおりです`3`。 すべての頂点を工場の可能性があるものとして扱うソリューションでは、隣接する都市を誤って選択し、`1`。 

4 番目のエッジ ケースは、すべてのリーフを選択する必要がある場合に発生します。```
1
4 3
1 2 2
1 3 3
1 4 4
```三つ葉は強制です。 それらのペアごとの距離は次のとおりです。`5`、`6`、 そして`7`、与える`18`。 エッジの下にある選択されたリーフの数のみを使用してエッジの寄与を計算し、エッジの外側にある選択されたリーフの数を忘れる DP は、このケースで誤った結果を導きます。 

## アプローチ

 直接的なアプローチは、すべてのセットを列挙することです。`k`葉を作成し、そのセット内の距離の合計を計算し、最小値を維持します。 あれば`L`残します、これは調べます`C(L,k)`可能な工場出荷時のセット。 すべてのペアワイズ リーフ距離が事前に利用可能な場合でも、各候補セットには`C(k,2)`ペアの評価。 許される最悪の形の星は、`L=99999`葉、だから`k=100`ペア評価の数だけでも`C(99999,100) * C(100,2)`、

 これは実際の計算をはるかに超えています。 すべての葉と葉の距離を事前に計算するには、二次メモリも必要になります。 

有益な観察は、ツリーを使用すると、すべてのエッジの寄与を個別にカウントできるということです。 セットを修正する`k`工場から出て重量の端を取り除く`w`。 正確に仮定してください`x`選択した葉はエッジの片側に配置されます。 それではまさに`k-x`選ばれた葉は反対側にあります。 両側の 1 つのリーフで構成されるすべてのペアには、このエッジを含むパスがあるため、エッジは正確に使用されます。`x(k-x)`工場出荷時のペア。 したがって、全体の答えに対するその貢献度は次のようになります。`w * x * (k-x)`。 

これにより、リーフのペアの合計がエッジの合計に変換されます。 同じエッジ寄与定式化が、この問題の標準ソリューションで使用される中心的な観察です。 

次に、木を根付かせます。 すべてのノードについて`u`、そのルートサブツリー内の葉のみを考慮します。 定義する`dp[u][j]`正確にそのサブツリーの内側に完全にあるすべてのエッジの最小寄与として`j`そこで工場が選ばれます。 サブツリーをツリーの残りの部分に接続する唯一のエッジが親エッジであるため、親はどのリーフが選択されたかを知る必要はなく、いくつ選択されたかを知る必要があります。 

仮定する`v`の子供です`u`、そしてエッジ`u-v`重さがある`w`。 私たちが取るなら`x`からの工場`v`のサブツリー、そのエッジが寄与します`w*x*(k-x)`。 すでに処理された部分の場合、`u`含まれています`j-x`工場では、移行は次のようになります`dp[u][j] = min(dp[u][j], dp[u][j-x] + dp[v][x] + w*x*(k-x))`。 

こちらはツリー型のナップサックです。 この遷移は、この問題に対する既存の解​​決策で説明されている標準的な子とサブツリーのマージとまったく同じです。 

このブルートフォース手法は、考えられるすべてのファクトリ セットが明示的に考慮されるため機能しますが、そのようなセットが指数関数的に多く存在するため失敗します。 エッジ寄与の観察により、サブツリーの処理中に選択された葉のアイデンティティを忘れて、その数だけを保持することができます。 以来`k`せいぜい`100`、これにより、問題は制限された動的プログラムに変わります。 

ツリーナップザック再発の標準的な最悪の場合の限界は次のとおりです。`O(nk^2)`。 以下の実装では、到達可能な状態のみを保存し、各遷移を有効な範囲に制限することにより、実際の動作が大幅に改善されます。 特に、分岐サブツリー上の長いチェーンは、不可能な状態を繰り返しスキャンしません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(C(L,k) * k^2)`距離前処理後 |`O(L^2)`すべてのリーフ距離が保存されている場合 | 遅すぎる |
 | 最適なDP |`O(nk^2)`最悪の場合、到達可能な状態を厳密に枝刈りする |`O(nk)`最悪の場合 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 街に木を根付かせる`1`そして、親、子の前の走査順序を構築します。 ツリーは長いパスになる可能性があるため、反復トラバーサルが使用されます。`10^5`これにより、再帰的 Python DFS が再帰の深さの制限に対して脆弱になります。 
2. すべての都市の元の度数を記録します。 都市は、元の学位が次のとおりであるときに、選択可能な工場国家を 1 つ提供します。`1`。 ルートは同じルールで処理されます。これは、両方の頂点が葉である 2 都市ツリーに必要です。 
3. 逆のトラバーサル順序で頂点を処理します。これにより、すべての子は親が処理される前にすでに DP を計算しています。 非リーフ ノードの場合、DP を次のように初期化します。`[0]`、サブツリーから葉を 0 つ選択するという選択を表します。 リーフの場合は初期化します`[0, 0]`、ここでの状態`1`これは、そのリーフを選択することを意味し、サブツリー内のコストはゼロです。 
4. すべての子供たちに`v`の`u`、マージ`dp[v]`の中へ`dp[u]`。 現在の`u`州がサポートするのはせいぜい`a`選択した葉は最大で子供がサポートします`b`。 を含む状態を取得するには`j`工場では、有効な数値をすべて試してください`x`子供から取られたもの。 候補者は`dp[u][j-x] + dp[v][x] + w*x*(k-x)`。 
5. を実行します。`j`逆方向にループします。 現在の DP 配列はその場で更新されるため、降順になります。`j`それを保証します`dp[u][j-x]`は、この子がマージされる前の状態をまだ参照しています。 これは、1 次元の 0/1 ナップザックが容量を逆方向に処理するのと同じ理由です。 
6. 不可能な値を反復しないでください。 現在の部分に次のものが含まれている場合、`a`選択可能な葉、次に状態`j-x`より大きい`a`存在できない。 同じく、`x`子によって表される状態の数を超えることはできません。 この枝刈りは、単純な実装が無限値の状態のテストにほとんどの時間を費やす可能性がある長いチェーンの場合に特に役立ちます。 
7. ルートのすべての子がマージされたら、`dp[root][k]`は、正確に、すべてのエッジの可能な最小寄与です。`k`選ばれた葉っぱ。 その値をテスト ケースの答えとして出力します。 

### なぜ効果があるのか

 ファクトリの固定選択では、各エッジは、その両側にある選択されたリーフの数に応じて独立して寄与します。 DP 状態は、親が必要とする情報、つまりサブツリー内で選択されたリーフの数と、そのサブツリーの下にあるすべてのエッジの最小寄与度を正確に記録します。 子がマージされると、可能なすべての数が`x`その子から選択された葉の数が考慮され、接続エッジがその寄与を正確に受け取ります。`w*x*(k-x)`その選択に迫られる。 したがって、すべての有効なファクトリ セットは一連の DP 遷移に対応し、すべての DP 遷移は、互いに素な子サブツリーからのファクトリ選択の有効な組み合わせを表します。 すべての遷移にわたって最小値を取ると、最適値が得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

INF = 10**18

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, k = map(int, input().split())

        # Compact forward-star adjacency representation.
        head = array('i', [-1]) * n
        to = array('i')
        weight = array('i')
        nxt = array('i')

        degree = array('i', [0]) * n

        for _ in range(n - 1):
            u, v, w = map(int, input().split())
            u -= 1
            v -= 1

            idx = len(to)
            to.append(v)
            weight.append(w)
            nxt.append(head[u])
            head[u] = idx

            idx = len(to)
            to.append(u)
            weight.append(w)
            nxt.append(head[v])
            head[v] = idx

            degree[u] += 1
            degree[v] += 1

        # Root the tree at 0 and construct a preorder.
        parent = array('i', [-2]) * n
        parent[0] = -1
        parent_weight = array('i', [0]) * n
        order = [0]

        for u in order:
            e = head[u]
            while e != -1:
                v = to[e]
                if v != parent[u] and parent[v] == -2:
                    parent[v] = u
                    parent_weight[v] = weight[e]
                    order.append(v)
                e = nxt[e]

        # dp[u] is an array indexed by the number of selected leaves.
        # Only reachable states are stored.
        dp = [None] * n

        for u in reversed(order):
            if degree[u] == 1:
                cur = 1
                du = array('q', [0, 0])
            else:
                cur = 0
                du = array('q', [0])

            e = head[u]

            while e != -1:
                v = to[e]

                if parent[v] == u:
                    dv = dp[v]
                    child_lim = len(dv) - 1

                    new_lim = cur + child_lim
                    if new_lim > k:
                        new_lim = k

                    if new_lim > cur:
                        du.extend([INF] * (new_lim - cur))

                    w = parent_weight[v]

                    # Descending j keeps du[j-x] unchanged during
                    # this child merge.
                    for j in range(new_lim, 0, -1):
                        if j <= cur:
                            best = du[j]
                        else:
                            best = INF

                        lo = j - cur
                        if lo < 1:
                            lo = 1

                        hi = child_lim
                        if hi > j:
                            hi = j

                        for x in range(lo, hi + 1):
                            cand = du[j - x] + dv[x] + w * x * (k - x)
                            if cand < best:
                                best = cand

                        du[j] = best

                    cur = new_lim

                    # The child DP is no longer needed after this merge.
                    dp[v] = None

                e = nxt[e]

            dp[u] = du

        out.append(f"Case #{case_id}: {dp[0][k]}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```隣接構造では、Python タプルやネストされたリストの代わりに、4 つのコンパクトな整数配列が使用されます。 まで`10^5`テスト ケースごとの都市数と 256 MB のメモリ制限を設定すると、Python オブジェクトのオーバーヘッドがかなり大きくなる可能性があるため、これは重要です。 

親の構築は反復的です。`order`には走査順序で頂点が含まれており、それを逆にすると、DP で必要な事後順序が正確に得られます。`parent_weight[v]`エッジ接続の重みを保存します`v`そのため、DP フェーズでその重みを再度検索する必要はありません。 

内部ノードの DP 配列は状態 0 のみから始まります。 リーフは状態 0 と 1 から始まります。 ファクトリの適格性は元の無向ツリーによって定義されるため、区別にはルート化された子の数ではなく、元の次数が使用されます。 

最もデリケートな部分は、インプレース マージです。 古い DP に以下の状態が含まれていると仮定します。`cur`。 配列を拡張した後、上記の状態`cur`は無限大に初期化されます。 目標の状態に向けて`j`、下限`j-cur`の上`x`それを保証します`j-x`古い到達可能な状態です。 反復`j`大から小へ変更すると、既に更新された状態が同じ子マージで再利用されなくなります。 

用語`w * x * (k - x)`グローバルに要求されたファクトリ数を使用します`k`、処理されたサブツリー内で現在選択されている番号ではありません。 行方不明者`k-x`ファクトリは必ず子サブツリーの外側にあるため、まさにこれらのペアが親エッジを越えます。 

すべての演算は、DP 配列の 64 ビット ストレージを使用して実行されます。 考えられる最大の答えは以下の通りです`10^18`、せいぜい`C(100,2)`工場出荷時のペアとすべてのツリーの距離は最大でも`(n-1)*10^5`。

### サンプル 2

 同じ星が使われていますが、今は`k=3`。 選択されたすべてのリーフは、そのエッジの外側にある 2 つのファクトリのそれぞれに 1 回エッジを提供するため、ウェイトのエッジ上のリーフは`w`貢献する`2w`。

 | --- | --- | --- |
 | 時間 |`O(nk^2)`最悪の場合 | 各子マージは、最大でも制限付きのナップザック畳み込みです。`k`状態 |

 | 5 ノードの加重パス、`k=2`|`10`| 元の葉のみを選択できます |
 |`100000`-ノードの単位重量スター、`k=100`|`9900`| 最大`n`、最大`k`、パフォーマンス |

 ## 特殊なケース

 のために`k=1`、入力を考慮します```
1
2 1
1 2 7
```リーフ DP には状態が含まれます`0`そして`1`。 唯一のエッジを介して 1 つの工場を選択するためのトランジションが追加されます。`7*1*(1-1)=0`。 したがって、根は到達します`dp[1]=0`、これが正解です。 

2 都市の場合`k=2`、```
1
2 2
1 2 7
```両方の頂点の次数は 1 です。 街に根ざして`1`都市を作る`1`選択可能なルート リーフと都市`2`選択可能な子リーフ。 子をマージした後、2 ファクトリ状態は`7*1*(2-1)=7`。 結果は`7`、したがって、ルート化された表現はルートの葉を失いません。 

パスの場合、```
1
4 2
1 2 1
2 3 1
3 4 1
```都市`1`そして`4`葉だけです。 民進党は都市を選択できない`2`または`3`元々の次数は 2 であるためです。 両方のエンドポイント リーフを選択する必要があり、それらの距離は次のとおりです。`1+1+1=3`。 エッジ貢献も`1`、`1`、 そして`1`、合計は同じになります。 

すべての葉を選択する必要がある場合、```
1
4 3
1 2 2
1 3 3
1 4 4
```ルートは内部にあり、各子はリーフです。 と`k=3`、各葉の端の下にある選択された数は次のようになります。`1`、したがって、3 つのエッジ寄与は次のようになります。`2*1*2=4`、`3*1*2=6`、 そして`4*1*2=8`。 それらの合計は`18`、直接ペアワイズ距離に一致します`5+6+7`。 これは、DP 全体の背後にある重要な不変条件です。すべての工場出荷時のペアは、そのパス上にあるすべてのエッジで 1 回だけ充電されます。
