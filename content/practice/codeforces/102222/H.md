 ## 解決策
 ## 問題の理解

 各モンスターには健康値があります`HP`そして攻撃値`ATK`。 毎秒、まだ生きているすべてのモンスターが最初にヒーローを攻撃するため、ヒーローは攻撃値の合計を失います。 次に、主人公は生きているモンスターを 1 体だけ選択し、それを攻撃します。 

特定のモンスターに与えられるダメージは、そのモンスターがすでに攻撃された回数によってのみ決まります。 最初に獲得したヒット案件`1`、その 2 番目の取引`2`、その 3 番目の取引`3`、 等々。 したがって、モンスターが必要とする場合は、`k`死ぬほどの攻撃、それらの攻撃は対処しなければなりません

 [
 1+2+\cdots+k=\frac{k(k+1)}2
 】

 合計ダメージ。 問題は、主人公が受けるダメージの合計ができるだけ少なくなるように、攻撃の順序をどのように選択するかです。 

入力には最大で次のものが含まれます`10^3`テスト ケース、最大でも`10^5`モンスターは 1 つのテスト ケースに含まれ、最大でも`10^6`すべてのテストケースにわたるモンスター。 体力と攻撃力の値は最大でも`10^5`。 これらの境界は、モンスターのサブセットまたは順列を含むものを除外します。 たとえ`O(n^2)`この方法ではコストが高すぎる場合`n=10^5`したがって、意図した解決策では、問題を本質的に並べ替えることに減らす必要があります。 

各モンスターの体力が潜在的に大きいにもかかわらず、必要な攻撃の数は非常に少ないです。 と`HP <= 10^5`、`447`攻撃はすでに対処されています`100128`ダメージなので、すべてのモンスターが必要とするのは最大で`447`攻撃します。 独自の制約や出力形式は公式問題ページで確認しています。 

単純な実装が間違っている可能性があるいくつかの特殊なケースがあります。 

単一のモンスターの場合、順序の決定はまったくありません。 例えば、```
1
1
1 1
```答えがあります`1`。 誤って 1 秒余分にモンスターが生きているとカウントする数式は、`2`、モンスターは一度攻撃し、ヒーローの最初の攻撃の直後に死ぬため、これは間違っています。 

ヘルス値が三角形の数値に正確に等しい場合も、正しい処理が必要です。 のために```
1
1
3 2
```モンスターにはちょうど 2 回の攻撃が必要です。`1 + 2 = 3`、したがって、答えは次のとおりです`4`。 厳密な使用法`>`の代わりに`>=`必要な攻撃数を見つけると、誤って 3 回目の攻撃が必要になる場合があります。 

等しい注文率も、もう 1 つの境界ケースです。 モンスターが2体いる場合`(k_1, ATK_1) = (1, 2)`そして`(k_2, ATK_2) = (2, 4)`、両方とも比率を持ちます`k / ATK = 1/2`。 どちらの注文でも合計金額は同じです。 コンパレータは、矛盾した順序を課すのではなく、これを同点として扱う必要があります。 

最後に、答えは 32 ビット整数を超える可能性があります。 のために`100000`モンスターと`HP=1`そして`ATK=1`、完了時間は次のとおりです。`1,2,...,100000`、与える

 [
 \frac{100000\cdot100001}{2}=5000050000。 
】

 32 ビット整数はオーバーフローします。 Python の整数にはこの問題はありませんが、対応する C++ 実装には次の必要があります。`long long`。 

## アプローチ

 直接的な総当たり的なアプローチは、モンスターが完全に殺される可能性のあるすべての順序を試すことです。 1 つの固定された順序に対して、すべてのモンスターが必要とする攻撃の回数を計算し、累積時間をシミュレートできます。 これは正しいです。考えられるすべての順序が考慮されるため、候補の中から最適なものが表示される必要があります。 

問題は候補者の数だ。 と`n`そこにいるモンスター`n!`順列、および 1 つの順列の評価には時間がかかります`O(n)`時間。 したがって、最悪の作業は次のとおりです。`Theta(n * n!)`。 平`20! * 20`についてです`4.87 * 10^19`基本的な注文処理ステップは、実用的な限界をはるかに超えています。 のために`n=10^5`、順列列挙はリモートでは実行できません。 

有益な観察は、モンスターに必要な合計攻撃回数は戦闘が始まる前に固定されているということです。 モンスターが必要なら`k`実際の攻撃は処理時間の仕事と考えることができます。`k`。 その攻撃値`ATK`このモンスターが生き続けるために毎秒支払われるコストです。 

すべてのモンスターの攻撃力の合計があるとします。`S`、必要なモンスターを 1 体考えます。`k`攻撃します。 その後に殺された場合`C`ヒーローの攻撃が発生しました、それはまさに貢献します`ATK * C`主人公の合計ダメージに。 したがって、問題全体がスケジュールの問題になります。すべてのモンスターは処理時間のあるジョブです。`k`そして体重`ATK`、そして重み付けされた完了時間の合計を最小限に抑えたいと考えています。 

最適な順序は、2 つのモンスター交換引数を使用して導き出すことができます。 モンスターについて考えてみましょう`A`そして`B`、必要な攻撃回数付き`k_A`、`k_B`と攻撃値`w_A`、`w_B`。 この 2 匹のモンスターの前のすべてを無視して、現在の時刻をそのままにしておきます。`C`。 

もし`A`が先に殺されると、彼らの貢献度は

 [
 w_A(C+k_A)+w_B(C+k_A+k_B)。 
]

もし`B`が先に殺されると、彼らの貢献度は
 [
 w B(C+k_B)+x_I(S+k_B+x_I)。 
】
 共通規約はキャンセルされます。 パッティング`A`最初は、正確に言うと悪くはありません

 [
 k_A w_B \le k_B w_A.
 】

 同様に、

 [
 \frac{k_A}{w_A}\le\frac{k_B}{w_B}。 
】

 したがって、モンスターは増加する順に分類する必要があります`required_attacks / ATK`。 これは、標準の加重完了時間スケジューリング ルールで使用されるものと同じ交換引数であり、この問題に対する既存のソリューションでも同じ製品間比較が行われます。 

完全な順序付けによってすべてのモンスターの完了時間が完全に決定されるため、総当り攻撃は機能しますが、順序付けが非常に多いため失敗します。 Exchange 引数を使用すると、反転を含むすべての順序を削除し、全体的に最適な 1 つの並べ替え順序を残すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n · n!)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. モンスターごとに最小数を計算します。`k`それを倒すために必要なヒーローの攻撃の数。 最小のものが必要です`k`満足のいく

 [
 \frac{k(k+1)}2\ge HP。 
]

以来`HP <= 10^5`、`k <= 447`, したがって、これらの値は、事前に計算された三角数のテーブルを使用して効率的に見つけることができます。 
2.各モンスターを処理時間のあるジョブとして扱う`k`そして体重`ATK`。 処理時間は、モンスターが死ぬまでにヒーローのターンが何回必要かを意味し、重量は、ヒーローが生きている間に 1 秒ごとにそのモンスターから受けるダメージの量を意味します。 
3. モンスターの増加順に並べ替える`k / ATK`。 比較は分割せずに理解できます: モンスター`A`モンスターの前に属する`B`いつ

 [
 k_A ATK_B \le k_B ATK_A.
 】

 この外積形式は正確な数学的比較であり、除算に関連した順序付けの問題を回避します。 
4. 分類されたモンスターを探索します。 維持する`time`、以前に処理されたすべてのモンスターを倒すために使用されたヒーローの攻撃の合計数。 現在のモンスターの場合、増加します`time`必要な攻撃回数に応じて`k`。 その死はこの新しい時点で発生するため、

 [
 攻撃力の\倍の時間
 】

 答えに損害が生じます。 
5. これらの重み付けされた完了コストを合計し、結果を必要な形式で出力します。`Case #x: answer`形式。 

不変条件は、最初の処理後の`i`モンスターを順番に並べると、`time`まさにそれらのモンスターを倒すために必要なヒーローの攻撃の数です、そして`answer`は、同じモンスターをその順序で完了するすべてのスケジュールの中で可能な最小の加重ダメージ寄与です。 交換の議論は、2 つの隣接するモンスターが比率の順序に違反する場合は常に、それらを交換しても結果が増加しないことを示しています。 すべての反転を繰り返し削除すると、並べ替えられた順序が作成されるため、他のスケジュールの総コストが小さくなることはありません。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

# The largest possible number of attacks is 447 because
# 447 * 448 // 2 = 100128 >= 100000.
MAX_HITS = 447

triangular = [0]
for k in range(1, MAX_HITS + 1):
    triangular.append(triangular[-1] + k)

def solve(inp=input):
    t = int(inp())
    out = []

    for case_id in range(1, t + 1):
        n = int(inp())
        monsters = []

        for _ in range(n):
            hp, atk = map(int, inp().split())

            # Smallest k such that k * (k + 1) / 2 >= hp.
            k = bisect_left(triangular, hp, 1)

            monsters.append((k, atk))

        # Under the given bounds, distinct rational ratios k / atk
        # are separated by at least 1 / 10^10, much more than the
        # floating-point precision around these values.
        monsters.sort(key=lambda x: x[0] / x[1])

        time = 0
        answer = 0

        for hits, atk in monsters:
            time += hits
            answer += time * atk

        out.append(f"Case #{case_id}: {answer}")

    return "\n".join(out)

if __name__ == "__main__":
    sys.stdout.write(solve())
```三角数配列は一度構築されます。 最大の健康は`100000`、必要な攻撃回数は最大で`447`。`bisect_left`モンスターの体力に達する最初の三角形の数字を見つけて、必要な攻撃回数を正確に与えます。 

各モンスターは次のように保存されます。`(hits, atk)`。 並べ替えのキーは比率です`hits / atk`、昇順で。 数学的ルールは正確な相互乗算に基づいていますが、実装では浮動小数点比を安全に使用できます。`hits <= 447`そして`atk <= 100000`。 このような 2 つの異なる分数は、少なくとも次の点で異なります。`1 / 10^10`、一方、倍精度は、からの間隔にわたってはるかに細かい絶対解像度を持ちます。`0`に`447`。 

重要な境界は、`bisect_left`。 ヘルスが正確に三角形の場合、次のようになります。`HP=3`、最初の有効な値は次のとおりである必要があります。`2`、 ない`3`。 下限検索ではまさにそれが得られます。 

最後の横断中に、`time`現在のモンスターの貢献を追加する前に更新されます。 これは戦闘順序と一致します。モンスターは、ヒーローが倒す秒までの毎秒攻撃します。 その結果、モンスターは時間内に完成しました`C`貢献する`ATK * C`。 

答えは数十億以上になる可能性があるため、実装では意図的に Python の任意精度の整数で計算が行われます。

 サンプル 1 のモンスターは次のとおりです。```

サンプル 2 のモンスターは次のとおりです。```

3   1

```必要な攻撃回数は、`2`、`2`、 そして`1`。 

| モンスター | HP | 攻撃力 | 必要な攻撃 | 比率`hits / ATK`| 完了時間 | 貢献 |

 ## 特殊なケース

 最小サイズの場合```
1
1
1 1
```三角数検索で見つかる`k=1`。 ソートされた配列には 1 つのモンスターが含まれているため、`time`になる`1`そして答えは次のようになります`1 * 1 = 1`。 モンスターは一度攻撃してその後死亡するため、死亡後の追加ダメージはありません。 

正確な三角形の境界の場合```
1
1
3 2
```三角数字が始まります`0, 1, 3, 6`。`bisect_left`インデックスを見つける`2`, したがって、モンスターはちょうど 2 回の攻撃を必要とします。 その完了時間は、`2`、与える`2 * 2 = 4`。 これにより、平等を不十分なダメージとして扱うというよくある間違いを回避できます。 

比率順序の場合```
1
2
1 2
2 3
```最初のモンスターに必要なもの`1`攻撃力があり攻撃値がある`2`、比率を与える`1/2`。 2番目に必要なのは`2`攻撃し、攻撃値を持つ`3`、比率を与える`2/3`。 アルゴリズムは一度に最初のモンスターを殺します`1`、貢献`2`、次に2番目を同時に殺します`3`、貢献`9`、合計で`11`。 それらを逆にすると、`6 + 6 = 12`したがって、攻撃値のみ、または必要な攻撃のみで並べ替えると、最適なものが失われます。

1
2
1 2
2 4
```どちらのモンスターにも比率がある`1/2`。 最初のものが最初に処理される場合、コストは次のようになります。`2*1 + 4*3 = 14`。 2 番目が最初に処理される場合、コストは次のようになります。`4*2 + 2*3 = 14`。 交換条件は平等になるので、どちらの順序でも最適です。
