 ## 解決策
 ## 問題の理解

 頂点が反時計回りの順序で与えられる凸多角形と、多角形の内部または境界上にある点 (Q) があります。 最初は、最初のエッジ (P_0P_1) が水平線上にあります。 その後、ポリゴンは滑ることなく回転します。エッジ (P_{i-1}P_i) が地面にある場合、ポリゴンは次のエッジ (P_iP_{i+1}) が地面に到達するまで (P_i) を中心に回転します。 すべての頂点が一度ピボットとして機能した後、元のエッジ (P_0P_1) が再び地面に配置され、プロセスが停止します。 

このような回転中、ポリゴンは固定されており、ピボット頂点は動きません。 その結果、(Q) はそのピボットを中心とする円弧に沿って移動します。 必要な答えは、これらすべての円弧の合計の長さです。 

1 つのポリゴンには最大 50 個の頂点があり、最大 50 個のテスト ケースがあります。 座標は最大 (10^3)​​ の絶対値を持つ整数です。 これらの境界は、(O(n)) 個の幾何学的計算としては小さいため、ポリゴン全体の継続的に変化する位置を維持したり、高価な幾何学的検索を実行したりする理由はありません。 (O(n^2)) でも問題なく適合しますが、ジオメトリは直接 (O(n)) の式を与えます。 

最初の微妙なケースは、(Q) がポリゴンの頂点と一致する場合です。 例えば、```
1
3
0 0
2 0
0 2
0 0
```正しい答えは、`Case #1: 3.142`。 ポリゴンが ((0,0)) を中心に回転する場合、(Q) はまさにピボットとなるため、その軌跡の一部の長さは 0 になります。 すべての半径が正であると仮定する不注意な実装は、このケースを誤って処理する可能性があります。 

別の境界ケースは、(Q) が頂点ではなくエッジ上にある場合に発生します。 例えば、```
1
4
0 0
2 0
2 2
0 2
1 0
```ここで (Q) は最初のエッジにあります。 すべての回転は (Q) から現在のピボットまでの距離によってのみ決定されるため、この式は引き続き機能します。 境界上の点を特別に処理する必要はありません。 

3 番目によくある間違いの原因は、最後のトランジションです。 このプロセスでは、すべてのポリゴン頂点がピボットとして 1 回だけ使用されます。 (P_{n-1}) を中心に回転した後、次のエッジは (P_{n-1}P_0) となり、(P_0) を中心に回転した後、元のエッジ (P_0P_1) が復元されます。 したがって、すべての頂点の循環近傍はモジュロ演算で処理する必要があります。 たとえば、(P_0) で寄与を省略すると、すべての中間回転が正しいように見えても、間違った答えが得られます。 

## アプローチ

 直接シミュレーションでは、多くの小さな角度増分でポリゴンを回転させます。 各増分中に、(Q) の位置を更新し、小さな変位を測定し、それらの変位を蓄積することができます。 (n) 個の回転をすべて (K) 回の増分に分割すると、(O(nK)) 回の操作が必要になります。 (n=50) および偶数 (K=10^6) の場合、テスト ケースごとに 5,000 万回の幾何学的更新になります。 より基本的には、これは単なる近似であり、固定 (K) を選択しても、必要な小数点以下 3 桁が完全に保証されるわけではありません。 

シミュレーションを回避できる理由は、個々のローリング操作には正確な幾何学的記述があるためです。 現在のピボットが (P_i) であるとします。 ポリゴンは (P_i) を中心に厳密に回転するため、この操作中に (P_i) から (Q) までの距離は変化しません。 したがって、(Q) は (P_i) を中心とする半径の円上を移動します。 

[
 r_i=|P_iQ|。 
]

 残りの量は、ポリゴンが回転する角度です。 回転前、エッジ (P_{i-1}P_i) は水平です。 回転後、(P_iP_{i+1}) は水平になります。 多角形は凸面であり、その頂点は反時計回りにリストされているため、回転量はまさに有向エッジ ベクトル間の回転角度になります。 

[
 P_i-P_{i-1}
 ]

 そして

 [
 P_{i+1}-P_i。 
]

 この角度が (\theta_i) である場合、対応する軌道の長さは単純に次のようになります。 

[
 r_i\シータ_i。 
]

 したがって、合計の答えは、

 [
 \箱入り{
 \sum_{i=0}^{n-1}|P_iQ|\theta_i
 }
 ]

 ここでインデックスは循環的に取得されます。 

2 つのベクトル (u) と (v) の場合、それらの間の角度は次のようにロバストに計算できます。 

[
 \theta=\オペレータ名{atan2}(|u\times v|,u\cdot v)。 
]

 使用する`atan2`コンピューティングよりも好ましい`acos(dot / (|u||v|))`。 後者では長さによる除算が必要ですが、浮動小数点エラーによりわずかに外側の値 ([-1,1]) が生成される可能性があります。`atan2`外積とドット積を直接使用し、ゼロまたは (\pi) に近い角度に対して適切に動作します。 

ブルート フォース シミュレーションは、物理的な回転プロセスに正確に従うため機能しますが、連続的な回転を数値的に解決するのに時間がかかります。 各回転が単なる円弧であるという観察により、問題全体が頂点ごとに 1 つの一定量の演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nK)) ピボットごとの (K) 個の角度サンプル | (O(n)) | 遅すぎて大雑把すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) 個のポリゴン頂点と (Q) の座標を読み取ります。 その順序によってローリング ピボットの順序がすでに決定されているため、頂点を指定された反時計回りの順序に保ちます。 
2. すべての頂点 (P_i) について、その 2 つの有向隣接エッジを見つけます。 入ってくるエッジは次のように表されます。 

[
 u=P_i-P_{i-1}、
 ]

 そして出力エッジは

 [
 v=P_{i+1}-P_i。 
]

 インデックスは巡回であるため、(P_{-1}=P_{n-1}) および (P_n=P_0) となります。 
3. 次を使用して (P_i) での回転角度を計算します。 

[
 \theta_i=\オペレーター名{atan2}(|u\times v|,u\cdot v)。 
]

 これらは、ポリゴンの周りを歩いているときに発生する 2 つの連続するエッジの方向とまったく同じです。 凸型の反時計回りの多角形の場合、これは、多角形が (P_i) を中心に回転する量である外部回転角を与えます。 
4. この回転中の (Q) の軌道の半径を計算します。 

[
 r_i=|P_iQ|。 
]

 (P_i) は固定ピボットであるため、半径は回転全体を通じて一定です。 
5. 答えに (r_i\theta_i) を追加します。 これは、ポリゴンが (P_i) を中心に回転するときに (Q) によってトレースされる正確な円弧の長さです。 
6. すべて (n) 個の頂点に対して繰り返します。 ローリング プロセスでは各頂点が 1 回使用されるため、これら (n) の寄与の後、元のサポート エッジに再び到達します。 
7. 累計値を小数点以下 3 桁で出力します。 このステートメントは、10 進数の 4 桁目が正確に 4 または 5 ではないことを保証しているため、必要な丸めには通常の浮動小数点書式設定で十分です。 

### なぜ効果があるのか

 (P_i) を中心とした回転中、多角形のすべての点は (P_i) を中心とする円上を移動します。 特に、(Q) は固定半径 (|P_iQ|) を持ちます。 ポリゴンは、出ていくエッジが地面と一直線になると正確に回転を停止するため、その回転角度は、入ってくる有向エッジと出ていく有向エッジの間の方向の変化になります。 結果として得られる円弧の長さは、半径と角度の積です。 すべてのローリング操作には 1 つのピボットがあり、すべての頂点が 1 回だけピボットになるため、これら (n) の円弧の長さを合計すると、(Q) の完全な軌道の長さが正確に得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

PI = math.pi

def solve_case(points, q):
    n = len(points)
    qx, qy = q
    ans = 0.0

    for i in range(n):
        prev = points[(i - 1) % n]
        cur = points[i]
        nxt = points[(i + 1) % n]

        ux = cur[0] - prev[0]
        uy = cur[1] - prev[1]

        vx = nxt[0] - cur[0]
        vy = nxt[1] - cur[1]

        cross = ux * vy - uy * vx
        dot = ux * vx + uy * vy

        angle = math.atan2(abs(cross), dot)

        dx = qx - cur[0]
        dy = qy - cur[1]
        radius = math.hypot(dx, dy)

        ans += radius * angle

    return ans

def main():
    t = int(input())

    for case_id in range(1, t + 1):
        n = int(input())
        points = [tuple(map(int, input().split())) for _ in range(n)]
        q = tuple(map(int, input().split()))

        ans = solve_case(points, q)
        print(f"Case #{case_id}: {ans:.3f}")

if __name__ == "__main__":
    main()
```メイン ループは、(n) 個のローリング操作に直接対応します。 頂点の場合`i`、`(i - 1) % n`そして`(i + 1) % n`は循環近傍を提供するため、最初と最後の頂点には特別なケースは必要ありません。 

2 つのベクトルは、有向の入力エッジと出力エッジです。 それらの内積により角度が鋭角、直角、鈍角のいずれであるかが決まり、絶対外積により正弦成分が得られます。`math.atan2(abs(cross), dot)`これら 2 つの量をラジアン単位の角度に直接変換します。 

半径は次のように計算されます。`math.hypot`、平方根式を手動で記述せずにユークリッド距離を評価します。 (Q) が現在のピボットと等しい場合、半径はゼロとなり、寄与も当然ゼロになります。 

最後の三角関数計算の前のすべての座標演算では Python 整数が使用されるため、整数オーバーフローの心配はありません。 最終的な答えは浮動小数点値であり、座標は十分小さいため、標準の倍精度で十分です。 

頂点を明示的に回転したり、(Q) の位置の変化を追跡したりする必要はありません。 各寄与は現在のピボット (Q) と 2 つの隣接するエッジの方向のみに依存するため、ローリング中のポリゴンの絶対位置は円弧の長さに影響しません。 

## 実用的な例

 ### サンプル 1

 多角形は正方形です

 [
 (0,0)、(2,0)、(2,2)、(0,2)
 ]

 そして (Q=(1,1))。 すべての頂点は (Q) から (\sqrt 2) の距離にあり、すべての外部回転角は (\pi/2) です。 

| ピボット | 半径 (|P_iQ|) | 回転角度 | アークの貢献 |
 |---|---:|---:|---:|
 | (P_0=(0,0)) | (\sqrt2) | (\pi/2) | (2.22144) |
 | (P_1=(2,0)) | (\sqrt2) | (\pi/2) | (2.22144) |
 | (P_2=(2,2)) | (\sqrt2) | (\pi/2) | (2.22144) |
 | (P_3=(0,2)) | (\sqrt2) | (\pi/2) | (2.22144) |

 合計は

 [
 4\cdot\sqrt2\cdot\frac{\pi}{2}
 =2\sqrt2\pi
 \約8.885765。 
]

 丸め後の出力は次のようになります。`Case #1: 8.886`。 

対称性により、不変条件が特に目立つようになります。すべての回転は同じ半径と同じ角度を持つため、4 つの円弧の長さはすべて同一になります。 

### サンプル 2

 頂点は

 [
 P_0=(0,0)、\quad P_1=(2,1)、\quad P_2=(1,2)
 ]

 そして (Q=(1,1))。 

半径は

 [
 |P_0Q|=\sqrt2,\qquad |P_1Q|=1,\qquad |P_2Q|=1。 
]

 (P_0) での回転角は次のとおりです。 

[
 \演算子名{atan2}(4,-4)=2.498092,
 ]

 一方、(P_1) と (P_2) の角度は両方ともおおよそ

 [
 1.892547。 
]

 | ピボット | 半径 | 回転角度 | アークの貢献 |
 | --- | --- | --- | --- |
 | (P_0) | (1.414214) | (2.498092) | (3.532) |

 凸多角形の周りを 1 回完全に横断する場合と同様に、3 つの回転角の合計は (2\pi) になります。 軌道の全長は約 (7.3176) で、次のようになります。`Case #2: 7.318`。 

この例は、内角を直接使用することがなぜ間違っているのかも示しています。 ローリング量は、有向エッジの方向の変化、つまり外部回転角です。

1

0 0
```ピボット ((0,0)) は何も寄与しません。 ((2,0)) では、回転角度は (\pi/4)、半径は 2 となり、(\pi/2) になります。 ((0,2)) では、同じ寄与が発生します。 合計は (\pi) なので、出力は次のようになります。`Case #1: 3.142`。 この実装では、除算や特別なケースを使用せずに、ゼロ半径を自然に処理します。 

(Q) がエッジにあるとき、軌道式にはまだ不連続性がありません。 のために```
1

```最初の回転はピボット ((0,0)) と半径 1 を持ち、他の 3 つのピボットは半径 (1,\sqrt5,\sqrt5) を持ちます。 各角は、対応する半径に (\pi/2) を乗じたものとなり、中心の正方形の 4 つの半径 (\sqrt2) 構成と同じ合計が得られます。`8.886`。 (Q) が最初に地面に触れているという事実は、半径の公式も回転角度も変更しません。

1

```すべてのピボットは (Q) から (\sqrt2) の距離にあり、すべての回転角は (\pi/2) です。 合計は

 [
 4\sqrt2\frac{\pi}{2}=2\sqrt2\pi\約8.886。

最後に、(P_{n-1}) と (P_0) の間の循環境界は、隣接関係に 2 回含まれる必要があります。1 回は (P_0) の入力エッジとして、もう 1 回は (P_{n-1}) の出力エッジとして含まれます。 表現`(i - 1) % n`そして`(i + 1) % n`このトポロジを正確にエンコードします。 これにより、最初と最後の頂点に対する特別な処理が回避され、ソリューションで最も一般的な off-by-one エラーが防止されます。
