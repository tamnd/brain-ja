 ## 解決策
 ## 問題の理解

 最初は空のスタックがあります。 各テスト ケースには操作が明示的にリストされていません。 代わりに、擬似乱数発生器のパラメータが与えられ、同じシーケンスを再現する必要があります。`PUSH`そして`POP`ジェネレーターとして動作します。 プッシュにより、次の間の値が作成されます。`1`そして`m`一方、ポップは現在のトップ要素が存在する場合はそれを削除します。 すべての操作の後、次を使用して、現在スタックに存在する最大値が必要になります。`0`スタックが空のとき。 The required answer is the bitwise XOR of`i * maximum_i`すべてのオペレーションインデックスにわたって`i`。 公式の制約では、次のような制限が許可されます。`5 * 10^6`1 つのテスト ケースでの操作。最大 50 のテスト ケースと 256 MB のメモリ制限があります。 

大きな値`n`ソリューションの形状を決定します。 すべての要素で繰り返される少量の作業であっても、1 回の操作あたりの時間が一定である場合にのみ許容されます。 すべての操作の後にスタック全体をスキャンするアルゴリズムは、大まかに実行できます`1 + 2 + 3 + ... + n = n(n + 1) / 2`比較。 のために`n = 5 * 10^6`、それは約です`1.25 * 10^13`これは 10 秒の制限が許容できる範囲をはるかに超えています。 目的のソリューションでは、生成されたすべての操作を O(1) 時間で処理する必要があります。 公式の問題ページにも同じことが記載されています`5 * 10^6`制限あり、10秒制限。 

誤って対処しやすい特殊なケースがいくつかあります。 初め、`POP`スタックがすでに空の場合は許可されます。 最初のサンプルでは、​​生成された操作は 2 つのポップで始まります。 最初の操作ではスタックが空のままになるため、その寄与は次のようになります。`1 * 0 = 0`; 2 番目も同じことを行います。 すべてのポップが有効であると想定するソリューションでは、無効なスタック要素にアクセスする可能性があります。```
1
1 1 1 4 23333 66666 233333
```ここで、最初に生成されたオペレーションは、サンプル 1 と同じ最初のオペレーションです。`POP`したがって、正しい出力は次のようになります。`Case #1: 0`。 空であるかどうかをチェックせずに先頭の要素を読み取る不注意な実装は失敗します。 

2 番目のエッジ ケースは、現在の最大値をポップしても新しい最大値がゼロになるわけではないということです。 以前の最大値は、その下に別の要素がまだ存在する場合に再表示される必要があります。 このため、単に 1 つのグローバル最大値を保存するだけでは不十分です。 たとえば、その後`PUSH(3), PUSH(8), POP()`、残りの最大値は`3`、 ない`0`。 正しいデータ構造では、すべてのスタック深さに関連付けられた最大値を記憶する必要があります。 

3 番目のエッジ ケースは、同じ値が繰り返されます。 スタックに次のものが含まれているとします。`7, 7, 7`そして一度ポップします。 最大値はまだです`7`。 最大値が厳密に増加する位置のみを格納する表現では、この多重度を追跡できなくなる可能性があります。 プレフィックスの最大値表現では、すべての深さが独自の最大値を格納するため、この問題が回避されます。 

最後に、ジェネレーター自体は 32 ビットの符号なし演算を使用します。 Python の整数は自然にオーバーフローしないため、すべての状態が更新されます。`SA`、`SB`、 そして`SC`剰余を減算する必要がある`2^32`。 このマスキングを省略すると、生成される操作が変更され、スタック ロジックが完璧であっても、間違った答えが生成される可能性があります。 

## アプローチ

 直接的な解決策は、実際のスタック値をすべて保存することです。 プッシュ時に値を追加します。 ポップでは、最後の値を削除します。 各操作後に最大値を取得するには、スタック全体をスキャンしてその最大値を取得します。 スキャンではスタック内に現在存在する要素が正確に検査されるため、これは正しいです。 

問題はスキャンの繰り返しです。 スタックのサイズが大きくなった場合`n`大きいままの場合、最初のクエリは 1 つの要素を検査し、次の 2 つの要素を検査するというようになります。 最悪の場合、総作業量は O(n²) になります。`1.25 * 10^13`スタック要素の検査`n = 5 * 10^6`。 ジェネレーターは入力自体が巨大にならないように意図的に使用されていますが、それで O(n²) アルゴリズムが実行可能になるわけではありません。 

重要な点は、スタック プレフィックスから必要な情報は最大値だけであるということです。 数回プッシュした後のスタックを考えてみましょう。 深さで`k`、最初の値のうちの最大値を格納します。`k`実際の要素。 新しい価値観が生まれるとき`x`がプッシュされると、新しい最大値は単純に`max(previous_maximum, x)`。 トップがポップされると、最大値は自動的に前の深さで保存された値になります。 

これは、実際にプッシュされた値が不要であることを意味します。 たとえば、実際のスタックが次のようになっているとします。`[4, 2, 9, 3]`。 これを次のように置き換えることができます`[4, 4, 9, 9]`。 最高値`9`現在の最大値です。 1 回ポップすると、表現は次のようになります。`[4, 4, 9]`、その上限は依然として正しい最大値です。 もう一度ポップすると、`[4, 4]`、明らかにする`4`、元のスタックとまったく同じです。 

したがって、この構造はプレフィックス maxima を含む単なる別のスタックです。 すべての操作は一定時間になります。 プッシュ後には実際の値が必要ないため、実装をさらに一歩進めることができます。 スタック深さごとに 1 つの 32 ビット整数で十分です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`p`、`q`、`m`、および 3 つのジェネレーターの状態`SA`、`SB`、 そして`SC`。 これらの値には操作シーケンスが暗黙的に含まれているため、ジェネレーターは正確に再現する必要があります。 
2. プレフィックス最大値のスタックを、次の内容を含む 1 つの追加スロットで割り当てます。`0`。 させて`depth`現在論理スタック内にある要素の数を表します。 深さ 0 のセンチネルは、空のスタックの最大値がすぐに 0 として利用可能であることを意味します。 
3. 操作について`i`、ジェネレーターを 1 回呼び出して、操作がプッシュかポップかを決定します。 条件は`rng61() % (p + q) < p`。 
4. 操作がプッシュの場合は、呼び出します。`rng61()`2 回目の値の生成`v = rng61() % m + 1`。 スタックの深さを増やして格納する`max(stack[depth - 1], v)`新たな深さで。 スタックが以前に空だった場合、以前の最大値はゼロであるため、格納される値は単純に`v`。 
5. 動作がポップの場合は減少させます。`depth`スタックが空でない場合のみ。 すでにゼロの場合は、変更しないでください。 センチネルは、正しい最大値のゼロを返します。 
6. 操作を実行した後、以下を読んでください。`stack[depth]`現在の最大値として。 XOR`i * stack[depth]`答えに。 乗算では、問題で必要とされる 1 から始まる演算インデックスが使用されます。 
7. 結局のところ`n`操作では、必要な値を使用して蓄積された XOR を出力します。`Case #x: y`形式。 

### なぜ効果があるのか

 不変条件とは、`stack[d]`実際のスタックの最初の最大値に等しい`d`要素。 最初は`d = 0`、空の最大値はゼロです。 プッシュ中、新しい実スタックは以前のスタックで構成されます。`d`要素の後に続く`v`したがって、その最大値は正確に`max(stack[d], v)`、これは深層に保存されるものです`d + 1`。 ポップ中に、最後の実際の要素が消えるため、残りのスタックの最大値は、深さにすでに格納されている値とまったく同じになります。`d - 1`。 したがって、不変式はすべての操作で存続し、から読み取られる値は`stack[depth]`は常に必要な最大値です。 すべての寄与は対応する操作の直後に XOR 演算されるため、最終的な答えは正確に必要な XOR になります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MASK = 0xFFFFFFFF

def rng61(sa, sb, sc):
    sa ^= (sa << 16) & MASK
    sa &= MASK

    sa ^= sa >> 5
    sa &= MASK

    sa ^= (sa << 1) & MASK
    sa &= MASK

    t = sa
    sa = sb
    sb = sc
    sc = (sc ^ t ^ sa) & MASK

    return sc, sa, sb, sc

def solve():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, p, q, m, sa, sb, sc = map(int, input().split())

        # stack[d] = maximum of the logical stack when its size is d.
        # stack[0] = 0 represents the empty stack.
        stack = array('I', [0]) * (n + 1)
        depth = 0
        ans = 0
        total = p + q

        for i in range(1, n + 1):
            r, sa, sb, sc = rng61(sa, sb, sc)

            if r % total < p:
                r, sa, sb, sc = rng61(sa, sb, sc)
                value = r % m + 1

                previous_max = stack[depth]
                depth += 1

                if value > previous_max:
                    stack[depth] = value
                else:
                    stack[depth] = previous_max
            else:
                if depth > 0:
                    depth -= 1

            ans ^= i * stack[depth]

        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`rng61`関数は C++ ジェネレーターをミラーリングします。 明示的な`& 0xFFFFFFFF`C++ であるため、操作が必要です。`unsigned int`算術ラップ剰余`2^32`一方で、Python の整数は際限なく増加します。 各 XOR と左シフトの後のマスキングにより、後続のすべての操作が 32 ビットの符号なし値に対する場合と同様に動作します。 

と呼ばれる配列`stack`プッシュされた元の値は含まれません。 インデックス時`d`、最初の最大値が含まれます。`d`要素。 スタックに関してこれまでに行われた唯一のクエリはその最大値であるため、これで十分です。 

配列は事前に割り当てられています`n + 1`符号なし 32 ビット整数。 Python リストには Python 整数オブジェクトへの参照が格納され、最大の深さで 100 MB をはるかに超える容量を消費する可能性があります。 の`array('I')`表現ではエントリごとに 4 バイトが使用されるため、深さが 500 万の場合、スタックに約 20 MB が必要になります。 

の`depth`変数は論理スタック サイズです。 プッシュの書き込み先`stack[depth + 1]`、有効なポップが減少する間、`depth`。 保管`stack[0] = 0`スタックが空になったときに特別な最大値を設定する必要がなくなります。 

ジェネレーターは、操作の決定ごとに 1 回だけ呼び出す必要があります。 プッシュ時には、プッシュされた値に対してもう一度正確に呼び出す必要があります。 別の順序で呼び出すと、後続のジェネレーターの状態全体が変更されます。 答えはスタック操作後に更新されます。`a_i`の後の最大値を指します`i`- 回目の操作。 

Python の整数は、最終的な式にも役立ちます。 最大の製品は最大です`5 * 10^6 * 10^9 = 5 * 10^15`、これは Python の整数表現に快適に適合し、符号付き 64 ビット整数にも適合します。 

## 実用的な例

 サンプル 1 の場合、ジェネレーターは次のように生成します。`POP, POP, PUSH(1), PUSH(4)`。 スタック表現には、各深さの最大値のみが格納されます。 

| 操作 | 生成されたアクション | 深さ | プレフィックス最大スタック | 現在の最大値 | XOR への貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 1 |`POP`| 0 |`[0]`| 0 |`1 * 0 = 0`|
 | 2 |`POP`| 0 |`[0]`| 0 |`2 * 0 = 0`|
 | 3 |`PUSH(1)`| 1 |`[0, 1]`| 1 |`3 * 1 = 3`|
 | 4 |`PUSH(4)`| 2 |`[0, 1, 4]`| 4 |`4 * 4 = 16`|

 最終的な答えは、`0 XOR 0 XOR 3 XOR 16 = 19`、与える`Case #1: 19`。 最初の 2 つの操作では、空のスタックのポップが何も行われないことも確認します。 

サンプル 2 の場合、生成されるオペレーションは次のとおりです。`PUSH(2), POP, PUSH(1), POP`。 

| 操作 | 生成されたアクション | 深さ | プレフィックス最大スタック | 現在の最大値 | XOR への貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 1 |`PUSH(2)`| 1 |`[0, 2]`| 2 |`1 * 2 = 2`|
 | 2 |`POP`| 0 |`[0, 2]`| 0 |`2 * 0 = 0`|
 | 3 |`PUSH(1)`| 1 |`[0, 1]`| 1 |`3 * 1 = 3`|
 | 4 |`POP`| 0 |`[0, 1]`| 0 |`4 * 0 = 0`|

 最終的な XOR は次のとおりです。`2 XOR 0 XOR 3 XOR 0 = 1`。 このトレースは、挿入と空の状態への削除の両方を実行します。

## テストケース

 次のテスト ハーネスは、提出されたプログラムと同じソリューション ロジックを使用します。 大規模なカスタム ケースは、独自に生成された期待値に依存せずにその動作を証明できるように、意図的に選択されています。`SA = SB = SC = 65536`、すべてのジェネレータの状態は均等のままであるため、`p = q = 1`すべての操作はプッシュです。 設定`m = 1`プッシュされたすべての値が次と等しくなります`1`。```python
import sys
import io
from array import array

MASK = 0xFFFFFFFF

def solve_text(inp: str) -> str:
    data = io.StringIO(inp)
    input = data.readline

    t = int(input())
    out = []

    def rng61(sa, sb, sc):
        sa ^= (sa << 16) & MASK
        sa &= MASK
        sa ^= sa >> 5
        sa &= MASK
        sa ^= (sa << 1) & MASK
        sa &= MASK

        tmp = sa
        sa = sb
        sb = sc
        sc = (sc ^ tmp ^ sa) & MASK

        return sc, sa, sb, sc

    for case_id in range(1, t + 1):
        n, p, q, m, sa, sb, sc = map(int, input().split())

        stack = array('I', [0]) * (n + 1)
        depth = 0
        ans = 0
        total = p + q

        for i in range(1, n + 1):
            r, sa, sb, sc = rng61(sa, sb, sc)

            if r % total < p:
                r, sa, sb, sc = rng61(sa, sb, sc)
                value = r % m + 1

                depth += 1
                previous_max = stack[depth - 1]
                stack[depth] = max(previous_max, value)
            else:
                if depth:
                    depth -= 1

            ans ^= i * stack[depth]

        out.append(f"Case #{case_id}: {ans}")

    return "\n".join(out)

# Provided samples
sample = """\
2
4 1 1 4 23333 66666 233333
4 2 1 4 23333 66666 233333
"""

assert solve_text(sample) == """\
Case #1: 19
Case #2: 1
""", "provided samples"

# Minimum-size case. The first generated operation is POP,
# so the empty stack contributes zero.
assert solve_text(
    "1\n1 1 1 4 23333 66666 233333\n"
) == "Case #1: 0", "minimum-size empty pop"

# First three operations of Sample 1:
# POP, POP, PUSH(1), giving contributions 0, 0, 3.
assert solve_text(
    "1\n3 1 1 4 23333 66666 233333\n"
) == "Case #1: 3", "operation-index weighting"

# All generated operations are PUSH because every RNG state is even.
# m = 1 makes every pushed value equal to 1.
# For n = 5, the answer is 1 xor 2 xor 3 xor 4 xor 5 = 1.
assert solve_text(
    "1\n5 1 1 1 65536 65536 65536\n"
) == "Case #1: 1", "all-equal values"

# Maximum-size case.
# Every operation is PUSH(1), so the answer is xor(1..5,000,000).
# Since 5,000,000 is divisible by 4, xor(1..n) = n.
assert solve_text(
    "1\n5000000 1 1 1 65536 65536 65536\n"
) == "Case #1: 5000000", "maximum-size case"

 ## 特殊なケース

 空のスタック ポップの場合は、サンプル 1 の最初の操作を具体的なケースとして使用します。```
1
1 1 1 4 23333 66666 233333
```最初に生成されたランダム値によって選択される`POP`。 論理深さはゼロから始まるため、ポップ条件は次のようになります。`if depth > 0`は false であり、深さはゼロのままです。 番兵`stack[0]`ゼロ、貢献度を与える`1 * 0 = 0`。 出力は`Case #1: 0`。 有効範囲外のスタックアクセスは発生しません。 

等しい値が繰り返される場合は、次の点を考慮してください。```
1
5 1 1 1 65536 65536 65536
```3 つのジェネレーターの状態はすべて均等に始まります。 変換ではシフト、XOR、代入のみが使用されるため、すべての状態は偶数のままになります。 と`p = q = 1`、偶数のランダム値は次の条件を満たします。`value % 2 < 1`, したがって、すべての操作はプッシュです。 なぜなら`m = 1`、生成されるすべての値は`1`。 プレフィックス最大スタックは次のようになります。`[0, 1, 1, 1, 1, 1]`。 貢献内容は、`1, 2, 3, 4, 5`、その XOR は`1`。 繰り返される最大値には特別な処理が必要ありません。 

最大サイズの境界については、次と同じ構造になります。`n = 5 * 10^6`500万プッシュの価値を生成します`1`。 スタックは可能な最大の深さに達しますが、プログラムは最大 500 万の 32 ビット プレフィックス (約 20 MB) しか保存しません。 答えは、次のすべての整数の XOR です。`1`を通して`5,000,000`。 以来`5,000,000 mod 4 = 0`、XOR が等しい`5,000,000`。 これにより、メモリ表現とループ境界の両方が、許容される最大値で正確にテストされます。`n`。 

操作インデックス境界には、サンプル 1 の最初の 3 つの操作を使用します。```

ジェネレーター境界については、同じテストで、プッシュが 2 つの乱数を消費するのに対し、ポップは 1 つだけを消費することも検証します。 サンプル 1 では、最初の 2 つの操作はポップであるため、それぞれに対してジェネレーター呼び出しが 1 つだけ行われます。 3 番目の操作はプッシュであるため、操作選択呼び出しの直後に値生成呼び出しが続きます。 実装がポップの後に値のジェネレーターを呼び出すと、その後のすべての操作がシフトされ、最終的な XOR が正しくなくなります。 Python の実装は、元のジェネレーターの正確な呼び出し順序に従います。
