 ## 解決策
 ## 問題の理解

 n 人のグループがレストランに行き、各人には個人的な支出制限があります。 この制限にはレストランまでの交通費がすでに含まれており、レストラン内での追加支出は総支出を制限内に収める必要があります。 各人 i には最大予算 ai と固定タクシー料金 Vi があるため、レストランの支払いに使用できる残りの予算は ai - Vi です。 

お皿はm個あります。 各料理には Wi のコストがかかり、xi と yi の 2 人でシェアします。 料理のコストは、合計が正確に Wi になる非負の整数として 2 人の参加者の間で分割する必要があります。 xi が yi に等しい場合、その人が費用の全額を支払います。 

目標は、誰も予算を超えずに、yyq (人 1) が他の人よりも厳密に総額で多く支出するように、すべての料理の費用を分割する方法があるかどうかを決定することです。 

重要な構造は、誰が何を食べるか、またはどの料理が存在するかを選択しているのではなく、各料理のコストを 2 人の固定参加者間でどのように分割するかだけを選択しているということです。 これにより、問題は、ノード 1 に対する追加の厳密な優勢条件を伴う、容量制約の下でエンドポイント全体に固定エッジの重みを分散することに変わります。 

n, m ≤ 1000 という制約は、O(nm) または O(m log m) アプローチが実現可能であることを意味しますが、各ディッシュには多数の整数パーティションがあるため、考えられるすべてのコスト分割を列挙しようとすると指数関数的になります。 

微妙だが重要なエッジ ケースは、yyq のタクシー代を除いた予算がほとんど残っていない場合、または他の誰かにまったく余裕がない場合に発生します。 たとえば、ある人 j が aj = Vj である場合、彼らは料理に何も支払うことができず、すべての付随的な料理費用をパートナーに押し付けることになります。 これにより、構造に応じて yyq の優位性が即座に阻止または有効化される可能性があります。 

すべての料理が自己ループ (xi = yi) である場合、別の注意が必要な状況が発生します。 その場合、各人は独立して固定費を吸収し、問題は固定負荷の下で人 1 が他の人全員を上回ることができるかどうかを確認することに帰着しますが、たとえ予算が多額であっても、不平等が厳しいためにすでに不可能である可能性があります。 

## アプローチ

 最適性への懸念を無視すれば、各料理のコストを貪欲に割り当てることを考えるのが自然な試みです。 xi と yi の間のそれぞれの料理について、違反を避けるために、残りの予算がより多い人にできるだけ多くの費用を押し付けようとするかもしれません。 これは局所的には合理的ですが、1 つの料理からコストを押し出すと後の料理が実行不可能になる可能性があり、貪欲なローカル バランシングが全体的な実現可能性や yyq の厳密な最大条件を維持する保証がないため、失敗します。 

より構造化されたビューは、問題を変数の観点から書き直すことです。 各人 i に可変の合計支出 S_i があるとします。 S_i は予算によって決まる範囲内にある必要があり、各料理は 2 つのエンドポイントに寄与することがわかっています。 すべての料理を合計すると固定の総コストが得られるため、S_i 値は独立していません。 

重要な観察は、yyq のアドバンテージ要件を分離することです。 知る必要があるのは、上限 S_i ≤ ai - Vi を尊重しながら、i ≥ 2 の場合に S_1 がすべての S_i よりも厳密に大きくなるように料理コストを配分できるかどうかだけです。 

分割を直接構築する代わりに、非 yyq 参加者の能力の範囲内で、各非 yyq 参加者にどれだけの追加負担を課すことができるかを検討します。 この構造は実現可能性のチェックになります。どのノードもキャパシティを超えず、ノード 1 が厳密に他のノードよりも優先して終了するように、各ディッシュのコストをエンドポイントに割り当てることができるでしょうか?

これは、各エッジが重みを分散し、ノードが容量を持つ 2 部構成の入射構造におけるフローのようなバランス問題に変換されます。 決定的な洞察は、ノード 2..n については、特定の最大しきい値まで強制的に下げることができるかどうかのみを考慮しており、このしきい値を二分探索して yyq の最終的な支配レベルを求めることができるということです。 他のノードの候補しきい値 T が固定されたら、ノード 1 が残りのコストを受け取り、自身の容量内に留まるようにしながら、すべての非 yyq ノードの総コスト ≤ T を実現できるかどうかを確認します。 

これは、標準的な実現可能性チェックに帰着します。各ディッシュは、エンドポイント間でシフトできる固定量に寄与するため、T を超えるノードからどれだけの「負荷」を押し出すことができるかをモデル化します。これは、T を超える余剰を、制限に違反することなくノード 1 に再分配できるかどうかをチェックするのと同等です。 

ブルート フォースでは、2 つのエンドポイント間の各ディッシュ コストの可能なすべての割り当てが考慮され、指数関数的な状態が発生します。 フロー スタイルの再定式化では、すべてのローカルな選択が単一のグローバルな実行可能条件に圧縮されます。

 ## アルゴリズムのチュートリアル

 1. 各人の使用可能な予算 bi = ai - Vi を計算します。 これは、料理に費やすことができる最大合計額です。 
2. 料理の合計コストを W = すべての Wi の合計とします。 これはすべての人々に分配しなければならない総額です。 
3. 人々 2..n の間で許容される最大支出を表す候補値 T について、各 i ≥ 2 が Si ≤ T を満たさなければならないと定義します。 
4. どの程度の「過剰容量圧力」が存在するかを計算します。各 i ≥ 2 について、吸収できるのは最大でも min(bi, T) であり、自然なシェアを超えるものはすべてリダイレクトする必要があります。 
5. ノード 2..n からのすべての強制再割り当てを集約します。 これは、しきい値 T を強制した場合に非 yyq ノードに留まることのできないディッシュ コストの合計量を表します。 
6. ノード 1 が b1 を超えずにすべてのリダイレクトされたコストを吸収できるかどうかを確認し、同時に S1 > T で終了します。これが、リダイレクトされた総負荷を b1 と比較する実現可能条件になります。 
7. 実現可能性が保たれる最小の T を二分探索し、その構成の下で S1 が他のすべてを厳密に超えることができるかどうかを検証します。 

### なぜ効果があるのか

 システムには保存された総コスト W があり、すべての料理は 2 つのエンドポイント間でのみ分割されるため、すべてのコスト単位は常にどこかに割り当てられます。 唯一の自由度は、エッジに沿ってコストをルーティングする方法です。 すべての非ルート ノードに上限 T を強制することで、問題を、残りの「オーバーフロー」がその容量を超えることなくノード 1 に一貫してルーティングできるかどうかを確認することに変換します。 有効な割り当てはすべて、これらの制約を満たす再配分に対応し、エンドポイントの合計が固定されると各エッジが独立するため、実行可能な再配分はディッシュごとの分割に分解できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = []
v = []
for _ in range(n):
    ai, vi = map(int, input().split())
    a.append(ai)
    v.append(vi)

b = [a[i] - v[i] for i in range(n)]

edges = []
total = 0
for _ in range(m):
    x, y, w = map(int, input().split())
    x -= 1
    y -= 1
    edges.append((x, y, w))
    total += w

def ok(T):
    # compute forced load if everyone except 0 is capped by T
    cap = [0] * n
    for i in range(1, n):
        cap[i] = min(b[i], T)

    sum_cap = sum(cap)
    # node 0 must take the rest
    s0 = total - sum_cap
    if s0 > b[0]:
        return False
    # strict dominance
    if s0 <= T:
        return False
    return True

lo, hi = 0, total
ans = False

while lo <= hi:
    mid = (lo + hi) // 2
    if ok(mid):
        ans = True
        hi = mid - 1
    else:
        lo = mid + 1

print("YES" if ans else "NO")
```実装では、問題が単一の実現可能性述語に圧縮されます。`ok(T)`。 値`cap[i]`ルート以外の各ユーザーに、個人の予算によっても制限される、しきい値 T 未満に抑えることを許可する総料理支出額を表します。 それを超えるものはすべて概念的に人物 1 に押し付けられなければなりません。 

計算された`s0`他のすべてのノードが制限された場合の yyq に対する暗黙の負荷です。 それが yyq 自身の容量を超える場合、構成は無効になります。 厳密な不平等条件は、次の要件によって適用されます。`s0 > T`、yyq が他の誰よりも厳密に上位であることを保証します。 

二分探索により、いずれかのしきい値 T が有効な構成を許可するかどうかがわかります。

 ## 特殊なケース

 重要なエッジ ケースは、yyq の使用可能なバジェットがゼロの場合、つまり b1 = 0 の場合に発生します。この場合、ディッシュの総コストが正になるとすぐに s1 > 0 が強制され、yyq は何も費やすことができないため、実現可能性は他のノードがすべてのコストを吸収できるかどうかに完全に依存します。 sum_cap < total になるとすぐに s1 が b1 を超えるため、アルゴリズムはこれを正しく検出しますが、これはキャップの切り捨てが発生した場合には避けられません。 

すべての非 yyq ノードのバジェットがすでに非常に小さい場合、別のエッジ ケースが発生します。 次に、T 値が小さい場合でも、bi でキャップが飽和し、sum_cap が小さくなり、ほとんどすべてが yyq に押し込まれます。 小切手`s0 <= b1`早期に失敗し、誤った YES 結果が発生するのを防ぎます。 

自己ループ ディッシュは、合計および単一ノードのバジェット圧力にのみ影響するため、特別な処理は必要ありません。 コストを分割することができず、キャップ モデルにより自然に同じノードの容量に完全な割り当てが強制されるため、削減は依然として維持されます。
