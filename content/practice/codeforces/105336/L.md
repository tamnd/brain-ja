 ## 問題の理解

 小文字のグリッドが与えられます。$n$行と$m$列。 このグリッドから、任意の 2 つの連続する行と任意の 2 つの連続する列を選択することに興味があります。 このような各選択により、$2 \times 2$部分行列。 目標は、これらが何個あるか数えることです$2 \times 2$ブロックは特定のパターンに一致します。$$\begin{matrix}
c & c \\
p & c
\end{matrix}$$言い換えると、ブロックの一番上の行は 2 つの同一の文字でなければならず、両方とも次の値と等しくなります。`'c'`、一番下の行には`'p'`左側と`'c'`右側に。 

出力は単に位置の数です$(i, j)$行によって形成される部分行列が$i, i+1$とコラム$j, j+1$このパターンを満たします。 

制約$2 \le n, m \le 500$せいぜい暗示する$500 \times 500 = 250000$可能性のある左上隅$2 \times 2$部分行列。 これは十分小さいので、$O(nm)$スキャンで十分です。 ただし、各候補は一定時間内にチェックする必要があるため、グリッド アクセス パターンが重要になります。 

ここで時々起こる素朴な誤解は、行と列のすべてのペアを個別にスキャンし、より複雑な方法で部分行列を再計算することです。 この問題のサイズではそれでも機能しますが、その必要はありません。 

エッジケースは最小限ですが、注目に値します。 グリッドに何も含まれていない場合`'c'`まったく、答えは明らかにゼロです。 すべての細胞が`'c'`、左下は次のとおりである必要があるため、答えはまだゼロです。`'p'`、決して現れません。 もう一つの微妙なケースは次のような場合です。`'p'`表示されますが、有効な位置よりも左下の位置にありません`'c'`ペアの場合、部分的ではあるが無効な一致が生じます。

前処理や高度なデータ構造は必要ありません。 重要な観察は、各候補部分行列が独立しており、検証には直接の文字比較のみが必要であるということです。

 ## アルゴリズムのチュートリアル

 考えられるものをそれぞれチェックするだけで済みます$2 \times 2$部分行列を一度。 

## アルゴリズムのチュートリアル

 1. 可能なすべての左上の位置を反復処理します。$(i, j)$どこ$0 \le i < n-1$そして$0 \le j < m-1$。 これにより、部分行列が境界内に収まるようになります。 
2. 各位置について、4 つのセルを調べます。 

左上$(i, j)$、右上$(i, j+1)$、左下$(i+1, j)$、右下$(i+1, j+1)$。 
3. これらが条件を満たしているかどうかを確認します。 

一番上の行は両方とも`'c'`、左下は次でなければなりません`'p'`、右下は次でなければなりません`'c'`。 
4. 条件が成立する場合、応答カウンタをインクリメントします。 
5. すべての位置をスキャンした後、カウンタを出力します。 

グループ化や前処理を行わずに各候補を直接チェックする理由は、各部分行列が 4 つの文字によって完全に決定されるため、利用する価値のある重複した計算が存在しないためです。 

### なぜ効果があるのか

 すべての有効な回答は、左上隅の 1 つの選択肢に正確に対応します。$(i, j)$。 アルゴリズムは、そのようなすべてのコーナーを省略や重複なく列挙します。 コーナーごとに、必要なパターンに一致する決定的な述語が適用されます。 述語は候補ごとに 1 回だけ評価され、これら 4 つのセルのみに依存するため、有効な構成が見逃されることはなく、無効な構成がカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    ans = 0

    for i in range(n - 1):
        row1 = g[i]
        row2 = g[i + 1]
        for j in range(m - 1):
            if row1[j] == 'c' and row1[j + 1] == 'c' and row2[j] == 'p' and row2[j + 1] == 'c':
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、前に説明した列挙を反映しています。 グリッドは文字列のリストとして保存されるため、文字アクセスは$O(1)$。 インデックスを繰り返し作成することを避けます。`g[i][j]`可能な場合は行参照をキャッシュすることで`row1`そして`row2`これにより、Python のオーバーヘッドが軽減されます。 

ループの境界`n - 1`そして`m - 1`を形成するときに範囲外のインデックスにアクセスしないようにします。$2 \times 2$ブロック。
