 ## 問題の理解

 私たちには、戦闘力値と累積ダメージ値という単一の進化状態を持つターンベースのゲームが与えられます。 強度は最初は固定値です$a_0$、ダメージはゼロから始まります。 がある$n$各ラウンドで、2 つのアクションのうち 1 つを正確に選択する必要があります。 

1 つのアクションが攻撃であり、現在の強さを追加します。$a$合計ダメージに$d$。 もう 1 つのアクションはトレーニング ステップであり、一定量だけ強度が増加します。$a_i$そのラウンドに関連付けられています。 

結局$n$ラウンド、攻撃アクションを使用したと仮定します$x$タイムとトレーニングアクション$y$回。 最終スコアは単なるダメージではなく、重み付けされた製品です。$$\text{score} = d \cdot (x \cdot k_1 + y \cdot k_2),$$ここで、各クエリは異なる定数を提供します$k_1, k_2$。 タスクは、各クエリのこのスコアを最大化するために、アクションのシーケンスと暗黙的にどのトレーニング増分が行われるかを選択することです。 

制約は大きいです:$n$そして$q$までです$10^5$、値は最大で大きくなる可能性があります$10^6$そして$10^9$。 これにより、クエリごとにシーケンスをシミュレートしたり、トレーニング アクションのすべてのサブセットを試行したりするアプローチは除外されます。 平$O(nq)$すぐに遅すぎます。 

重要な点は、時間の経過とともに強度が増加するため、ダメージにはアクションの順序が重要であるということです。 もう 1 つの微妙な点は、クエリが異なると目的関数が完全に変わるため、どのソリューションでも前処理をクエリごとの評価から分離する必要があることです。 

よくある失敗例は、カウント以上に順序は重要ではないと仮定した場合に発生します。 たとえば、順序を無視すると、次のようになります。 

入力:```

a = [100, 1]
```「すべてのトレーニングを最初に行う」と常に想定していると、最初に大きな増分のみを選択すると、構造によっては優先される可能性があることを見落とす可能性があります。 正しい答えは、最適な順序付け構造を推測することではなく、証明することにかかっています。 

別の故障モードの治療中$d$どちらから独立して$a_i$選ばれます。 トレーニングはサブセットの選択と順序付けの両方に影響を与えるため、どちらかを無視すると不正確なスコアリングにつながります。 

## アプローチ

 直接的な総当りのソリューションでは、次のすべてのシーケンスが列挙されます。$n$アクションを選択し、どのラウンドがトレーニングでどのラウンドが攻撃であるかを決定し、どのラウンドのサブセットかを選択します。$a_i$値はトレーニングの増分として使用されます。 たとえカウントを修正したとしても$x$そして$y$、トレーニング ポジションを選択する方法は次のとおりです。$\binom{n}{y}$、および選択された順序$a_i$価値観がさらに可能性を広げます。 これは急速に実現可能性を超え、指数関数的な複雑さに達します。 

最初の構造の単純化は、順序を理解することです。 どれを修正するとしますか$y$私たちが使用するトレーニング増分。 その後、強度は増加するだけであり、攻撃が後で発生する場合、常に高い強度から恩恵を受けます。 トレーニング操作の前に攻撃が発生した場合、それらを交換すると、その攻撃はより高いまたは同等の強度で発生し、将来の強度の増加が減少することはありません。 これは、ダメージを減らすことなく、すべてのトレーニング操作をすべての攻撃の前に移動できることを意味します。 したがって、トレーニング値の固定サブセットの場合、最適な順序は「最初にすべてのトレーニング、次にすべての攻撃」です。 

この構造の下で選択すると、$y$トレーニング値と合計$S_y$となると、攻撃前の強さは$a_0 + S_y$、ダメージは次のようになります。$$d = x \cdot (a_0 + S_y), \quad x = n - y.$$残る唯一の決定は、どちらかです$y$選択する値。 重要なのは合計のみであるため、常に最大値を採用します$y$配列からの値。 

さて、問題は一次元的な選択になります。$y$: それぞれ$y$、決定論的なスコアを計算し、クエリごとに最大化します。 

残りの問題は、クエリによって、次のような非線形結合が導入されることです。$d$、$x$、 そして$y$。 式を展開すると、それぞれのことがわかります。$y$は 2D 空間内の点に対応し、各クエリは次から導出される方向ベクトルとの最良の内積を求めます。$k_1, k_2$。 これにより、問題は静的な凸包の最大内積クエリに変わります。

 ## アルゴリズムのチュートリアル

 ### 1. トレーニングゲインを並べ替えてプレフィックス合計を構築する

 配列をソートします$a_i$降順でプレフィックスの合計を計算します$S_y$、 どこ$S_y$最大のものの合計です$y$トレーニングの価値観。 これにより、固定数のトレーニング操作に対して、常に最適なサブセットが使用されることが保証されます。 

### 2. ダメージを次の関数として表現します。$y$固定の場合$y$、 我々は持っています$x = n - y$、そして強さは$a_0 + S_y$。 すべてのトレーニングは攻撃の前に行われるため、ダメージは次のようになります。$$d_y = (n - y)(a_0 + S_y).$$これにより、順次プロセス全体が 1 つあたり 1 つの値に縮小されます。$y$。 

### 3. スコアを状態ごとに線形形式に書き換えます

 スコアは次のようになります。$$\text{score}(y) = d_y \cdot ((n-y)k_1 + yk_2).$$拡張:$$(n-y)k_1 + yk_2 = nk_1 + y(k_2 - k_1),$$それで：$$\text{score}(y) = nk_1 \cdot d_y + (k_2 - k_1) \cdot (y d_y).$$それぞれ$y$固定ペアを提供します$(d_y, y d_y)$、各クエリはこれらの点の線形最大化です。 

### 4. 凸包の最大内積として解釈します。 

各州$y$点に対応します:$$P_y = (d_y, y d_y).$$各クエリは方向ベクトルを定義します。$$(K_1, K_2) = (nk_1, k_2 - k_1),$$そして私たちは以下を最大化したいと考えています。$$P_y \cdot (K_1, K_2).$$これは古典的な静的凸包問題です。 

### 5. 点の凸包を構築する

 すべての点の上凸包を計算します$P_y$。 線形目標に対する最適な答えは船体の頂点にあり、方向が変わると、最適な頂点は船体に沿って単調に移動します。 

### 6. 二分検索でクエリに答える

 ハルは順序付けされているため、固定方向の内積はそれに沿って単峰性になります。 最適な頂点を二分探索します。$O(\log n)$クエリごとに。 

### なぜ効果があるのか

 オペレーションのすべての再配置は、次の選択肢に集約されます。$y$、それぞれについて$y$、最適な内部順序は固定されています。 これにより、問題は 1 次元インデックスに対する決定論的関数の評価に変わります。 この関数は、線形クエリがサポート超平面に対応する凸幾何学的表現に自然に持ち上げられます。 凸面性により、最大値が常に船体上で発生することが保証されるため、注意を船体の頂点に限定しても最適なソリューションが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_convex_hull(points):
    def cross(o, a, b):
        return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

    hull = []
    for p in points:
        while len(hull) >= 2 and cross(hull[-2], hull[-1], p) <= 0:
            hull.pop()
        hull.append(p)
    return hull

def dot(p, k1, k2):
    return p[0] * k1 + p[1] * k2

def query_hull(hull, k1, k2):
    l, r = 0, len(hull) - 1
    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        if dot(hull[m1], k1, k2) < dot(hull[m2], k1, k2):
            l = m1
        else:
            r = m2
    best = 0
    for i in range(l, r + 1):
        best = max(best, dot(hull[i], k1, k2))
    return best

def solve():
    n, a0 = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort(reverse=True)

    pref = [0]
    for v in a:
        pref.append(pref[-1] + v)

    points = []
    for y in range(n + 1):
        x = n - y
        d = x * (a0 + pref[y])
        points.append((d, d * y))

    hull = build_convex_hull(points)

    q = int(input())
    out = []
    for _ in range(q):
        k1, k2 = map(int, input().split())
        k1n = k1 * n
        k2k1 = k2 - k1
        out.append(str(query_hull(hull, k1n, k2k1)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、トレーニング ゲインを並べ替えることから始まり、任意のプレフィックスが固定数のトレーニング アクションに対する最適な選択に対応するようになります。 プレフィックス合計は、サブセット選択を定数時間ルックアップに変換します。$y$。 

それぞれ$y$次に、ダメージと、それがトレーニング アクションの数に応じてどのようにスケールされるかをエンコードする幾何学的なポイントにマッピングされます。 これは、シーケンス構造への依存を取り除く重要な変換です。 

凸包は、標準の単調スタックを使用して構築されます。 これは、ポイントが増加した順に追加されるため機能します。$y$、そしてその構造は非凸ターンを削除します。 

各クエリは線形目的に変換され、凸多角形の内積はその境界に沿って単峰性であるため、包皮に対して三分探索が使用されます。

 ## 特殊なケース

 すべてのトレーニングゲインがゼロの場合、重大なエッジケースが発生します。 その状況では、順序に関係なく強度が増加することはありません。そのため、最適な戦略は純粋に実行する攻撃の数を選択することになります。 すべてのプレフィックスの合計はゼロのままであり、スコア関数は単純な二次形式に縮退するため、アルゴリズムはこれを正しく処理します。$y$、これは同じ変換を通じて引き続き正しく評価されます。 

次の場合には、別のエッジケースが発生します。$k_1 = k_2$。 ここでは乗数は攻撃とトレーニングの分割とは独立しており、問題はダメージの最大化のみに帰着します。 クエリ方向が固定ベクトルに崩壊し、最良の点が最適なダメージ蓄積に対応するハル頂点のままであるため、凸包は引き続き正しく評価されます。 

最後の微妙なケースは次のような場合です。$n = 1$。 決定は 1 つだけあり、船体には以下に対応する 2 つの点が含まれています。$y=0$そして$y=1$。 このアルゴリズムは自然に両方を評価し、特別なケースを必要とせずに正しい最大値を返します。
