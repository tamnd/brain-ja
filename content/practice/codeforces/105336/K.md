 ## 解決策
 ## 問題の理解

 山積みになっている$n$石と 2 人のプレーヤーが交互にターンし、アリスが最初に動きます。 各移動で、プレイヤーは山から正の数の石を取り除きます。 移動のサイズは 2 つの方法で制限されます。 それを超えることはできません$k$、そして、以前に選択されたすべての動きを分割する必要があるという意味で、以前のすべての動きと互換性がなければなりません。 最初の動きには割り算の制限がないため、アリスは以下の数字を選択するだけで済みます。$1$そして$k$残りの石を超えないこと。 

プレイヤーが最後の石を取り除くとゲームは終了し、そのプレイヤーが勝ちます。 両方のプレイヤーが最適なプレーをします。 

入力により、複数の独立したゲームが提供されます。 各テスト ケースは次のように指定します$n$そして$k$そして、アリスが強制的に勝利するかどうかを判断する必要があります。 

制約は以下に達します$10^9$両方にとって$n$そして$k$、最大で$10^4$したがって、すべての解はテスト ケースごとに一定時間である必要があります。 ゲームツリーのシミュレーションや、考えられる動きの反復を伴うものは、直ちに実行不可能になります。 

微妙なエッジケースが現れるのは、$k = 1$。 その状況では、すべての手が正当である場合には必ず 1 になるように強制され、割り算条件は無関係になりますが、依然として有効です。 もう 1 つの微妙な点は、最初の動きの後、割り算の制約によって動きが大きく制限され始めますが、いつでも手「1」が排除されるわけではないことです。$k \ge 1$、残りのゲームの構造が完全に変わります。 

たとえば、次の場合$n = 5, k = 1$, アリスは1つ取らざるを得なくなり、ゲームは単純に石を1つずつ交互に取り除くことになります。 もし$n = 4, k = 3$, アリスには複数の初手がありますが、その後の構造は非常に制約されたプロセスに崩壊します。 手 1 が常に利用可能であることに気づかずに、ゲームが gcd ダイナミクスのみに依存するという単純な仮定は、誤った結論につながるでしょう。 

## アプローチ

 直接シミュレーションでは、以前のすべての手の gcd とともに残りの石としてゲームの状態をモデル化しようとします。 各ターンでは、その gcd の有効な約数を超えないものをすべて列挙します。$k$、残りの山よりも大きくありません。 これはルールを正しく捉えていますが、原理的には分岐要素がまだ大きすぎるため、ゲーム ツリーは急速に成長します。$n$大きいです。 主な問題はパフォーマンスだけではなく、さまざまな gcd 状態における最適な再生に関する推論が複雑になることでもあります。 

重要な単純化は、最初の動きの後、数字の 1 が常に有効なままであるため、ほとんどの場合、割り算の制限によって選択肢が有意に減少しないことを観察したことに由来します。 1 はすべての整数を除算し、常に制限内に収まるため$k$、最初の動きの後のゲームは強制減算プロセスに変質し、山がなくなるまで両方のプレイヤーが常に 1 を取ることができます。 

これにより、ゲーム全体が先手の選択とそれに続く決定的なパリティ ゲームに変わります。 アリスの決断は最初の行動を選択することになります$a_1$、その後の残りのゲームは純粋なテイクワンゲームになります。$n - a_1$ボブから始まる石。 

ブルート フォースでは最初の手をすべて試してから、残りのゲームをシミュレートします。 最適化されたソリューションは、第 2 フェーズをパリティ チェックに圧縮します。

 ## アルゴリズムのチュートリアル

 ### 1. 些細な勝ち手を扱う

 もし$n \le k$, アリスは最初は割り算の制限がないため、初手ですべての石を取ることができます。 彼女はすぐに勝ちます。 

### 2. 最初の動きの後にゲームを減らす

 アリスが取ると仮定します$a_1$、 どこ$1 \le a_1 \le k$そして$a_1 \le n$。 この移動後、残った山は$r = n - a_1$、そして今後のすべての動きは分割する必要があります$a_1$。 

重要な観察は、値 1 はすべての整数を除算し、常に次を満たすため、常に有効な手であるということです。$1 \le k$。 

### 3. ゲームをテイクワンプロセスに折りたたむ

 この時点から、両プレイヤーは常に正確に 1 つの石を取ることができます。 他の許可された手は、合法性を維持するために決して必要ではなく、1 を取ることが常に可能であるため、最適なプレイには影響しません。 

したがって、ゲームの残りの部分は、各プレーヤーが 1 つの石を取り除く単純な交互のプロセスになります。 

### 4. 残りのゲームの勝者を決定します

 テイクワンゲームでは、最適なプレイの下では常に奇数の石に直面したプレーヤーが勝ちます。 残りのゲームではボブが最初に動くので、次の場合はボブが勝ちます$r$奇数です。 

アリスはボブが偶数の石に直面することを望んでいます。$$n - a_1 \equiv 0 \pmod 2$$これは選択するのと同じです$a_1$と同じパリティを持つ$n$。 

### 5. そのような動きを選択する実現可能性を確認する

 アリスはどれでも選べる$a_1 \le k$。 それで:

 - もし$n$それは奇妙だ、彼女には奇数が必要だ$a_1$、1 は常に利用可能であるため、彼女の勝ちです。 
- もし$n$偶数です、彼女には偶数が必要です$a_1$。 これは次の場合にのみ可能です$k \ge 2$、最小の偶数手は 2 であるため。 

### なぜ効果があるのか

 不変条件は、最初の動きの後、正当な動きのセットには常に 1 が含まれており、残りのゲームで最適なプレイをシミュレートするには 1 で十分であるということです。 残りの手をセットしても、どちらのプレイヤーの結果も改善することはできません。1 を繰り返し取ることから逸脱しても、最終状態のパリティに基づく必然性は変わらないからです。 したがって、ゲームは、最初の動きの後に残っている山のパリティを制御することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())

        if n <= k:
            out.append("Alice")
            continue

        if n % 2 == 1:
            out.append("Alice")
        else:
            if k >= 2:
                out.append("Alice")
            else:
                out.append("Bob")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は削減を直接反映します。 最初の条件は、アリスがすべてを取得できる場合に即時終了を処理します。 2 番目のブランチは、強制「テイク 1」フェーズから得られたパリティ条件をエンコードします。 手 1 が将来のすべての可能性を支配するため、約数や gcd 状態のシミュレーションは必要ありません。 

## 実用的な例

 | 1 | アリス | 1 | 4 |

 アリスは偶数の石を残す手を選択したため勝ち、ボブは平等を失うことを余儀なくされます。 

これは、最初の手が固定されると、ゲームの残りの部分は強制的な交互の連鎖になることを示しています。 

### 例 2:$n = 6, k = 1$アリスには最初の行動に選択肢はありません。 

| ステップ | プレーヤー | 移動 | 残り$n$|

これは、なぜ$n$負けになるとき$k = 1$、アリスは最初の動きと同等を調整できないためです。

＃＃＃ 場合：$k = 1$入力：```

```アリスは 1 つ取らざるを得なくなり、残りの石は 5 つになります。 残りのゲームは、1 を取るという厳密な交互です。アルゴリズムは、これをアリスの負けポジションとして分類します。$n$は偶数であり、パリティを調整することはできません。 

### ケース: 大$k$、 平$n$入力：```

### ケース: 大$n$、 小さい$k$入力：```
