 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$長方形の中に立つ学生のグリッド。 各セルには学生が含まれているか、空です。 この初期構成から、操作が繰り返し適用され、各操作は 4 つのコマンドのいずれかに従って配置を「圧縮」します。 

行単位のコマンドは、各行内の垂直方向の位置を無視し、その行に現在いる生徒の数を変更せずに、その行内のすべての生徒をできるだけ左または右に移動させます。 同様に、列方向のコマンドは、各列内の水平方向の位置を無視し、各列の生徒の数を維持しながら、生徒をできるだけ上または下に移動させます。 

最大で任意のシーケンスを適用した後、$10^{18}$このような操作により、グリッドは複数の異なる構成を通じて進化する可能性があります。 一方の構成では占有されており、もう一方の構成では空であるセルが少なくとも 1 つ存在する場合、2 つの構成は異なるものとみなされます。 

質問はこのプロセスのシミュレーションに関するものではありません。 代わりに、正確に生成する初期設定が存在するかどうかを判断する必要があります。$k$考えられるすべての操作シーケンスの下で、個別に到達可能な構成を実現します。 このような構成が存在する場合は、有効な初期グリッドも 1 つ構築する必要があります。 

制約はグリッド サイズの点では大きくなりますが、総面積では中程度です。$n \cdot m \le 10^6$。 これは、構築はグリッド サイズにおいて明示的かつ線形である必要があり、その答えはシミュレーションではなく構造特性に依存することを強く示唆しています。 

微妙な点は、プロセスが非常に非線形であることです。行操作では列情報が破壊され、列操作では行情報が破壊されます。 素朴な解釈は混沌とした動作を示唆するかもしれませんが、実際には、システムは各操作の後、すぐに構造化された「プレフィックス形式」に崩壊します。 

よくある失敗例の 1 つは、操作の独立性を前提としている場合です。 たとえば、後続の列操作によって行が再び完全に再形成される可能性があるため、行操作の適用が行にのみ永続的に影響すると考えるのは誤りです。 もう 1 つの誤解を招く直観は、行の合計と列の合計を独立した不変式として扱うことですが、実際はそうではありません。 

2 番目のエッジ ケースは、すべてのセルが入力されているか、すべてが空の場合に発生します。 どちらの場合も、すべての操作で同じグリッドが再度生成されるため、到達可能な状態の数はちょうど 1 つになります。 より大きなものを目指すあらゆる建設$k$これらの縮退した固定点を回避する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての操作シーケンスを深い深さまでシミュレートし、到達可能なすべての状態を記録します。 インテリジェントに切り詰めたとしても、分岐係数は 4 で、演算数は最大 2 です。$10^{18}$, なので、これはすぐに爆発します。 状態を超えた BFS に限定したとしても、1 つの個別の構成の数は$n \times m$バイナリグリッドは$2^{nm}$、これは実現可能性をはるかに超えています。 

重要な観察は、各操作によってきめの細かい構造が破壊され、行の合計または列の合計によってのみ決定される単調な「圧縮された」形式に置き換えられるということです。 何らかの操作の後、グリッドは行または列の完全なプレフィックスの結合になります。 これは、到達可能なすべての構成が非常に厳密な幾何学的形状を持っていることを意味します。つまり、塗りつぶされた領域と空の領域を分ける階段の境界のように動作します。 

この観点から、各構成はグリッドの左上から右下までの単調な境界パスで表すことができます。 行操作は形状を水平方向に平坦化しますが、列操作は形状を垂直方向に平坦化します。 交互操作の効果は、複雑さを増すことなく、この境界を個別のステップで移動させることです。 

重要な洞察は、到達可能な個別の状態の数が、この圧縮プロセス中に現れる可能性のある個別の境界形状の数と正確に一致するということです。 これらの形状は、グリッド内の単調な格子パスに対応します。 したがって、到達可能な状態空間の面積は指数関数的ではありませんが、境界のサイズは線形です。$O(n + m)$変動の次元ごとに、最大でも$O(nm)$個別の構成の合計。 

これは建設的な視点につながります。遷移をシミュレートする代わりに、圧縮プロセスが正確に実行される初期グリッドを直接設計します。$k$明確な境界状態。

 ## アルゴリズムのチュートリアル

 システムが正確に通過するよう強制するグリッドを構築します$k$独特のモノトーンの「階段」構成。 

### 1. 到達可能な状態を境界形状として解釈する

 個々のセルを追跡する代わりに、各構成を、塗りつぶされた領域と空の領域を分離する単調なフロンティアとして見ます。 行方向または列方向の圧縮はすべて、単調性を壊すことなくこのフロンティアをシフトするだけです。 

これにより、問題は、システムに強制的に通過させることができる個別のフロンティアの数を制御することになります。 

### 2. 強制決定論的な崩壊動作

 各圧縮後に次の状態が一意に決定されるように、初期グリッドを設計します。 これは、塗りつぶされた領域を単調な形状にすることで実現され、各行と列は一貫したプレフィックス構造ですでに整列しています。 これにより、圧縮がどのように作用するかが曖昧になるのを防ぎます。 

その結果、各操作は境界を予測可能な方向に正確に 1 単位ステップだけ効果的に移動させます。 

### 3. シーケンスを正確にエンコードする$k$境界状態

 「階段」領域を完全な長方形から構築し、徐々に小さな単調な形状に刻みます。 それぞれの個別の形状は、境界に沿った 1 単位の変化だけ異なります。 

単調なパスに沿って空のセルを慎重に配置することで、正確に使い果たすまで各操作で 1 つの追加の個別の構成が明らかになります。$k$可能性。 

### 4. 対応するグリッドを出力します。 

ターゲットの階段の長さが正確に生成されるように固定されると、$k$状態に応じて、その形状の対応するバイナリ グリッド表現を出力します。 

### なぜ効果があるのか

 不変条件は、到達可能なすべての構成が境界位置のみによって決定される単調な階段のままであることです。 どの操作も非単調構造を導入することはできず、各ステップがフロンティア上の少なくとも 1 つのセルを変更するため、2 つの異なる境界位置が同じグリッドに崩れることはありません。 

したがって、システムは、一連の決定論的なウォークのように動作します。$k$この構造により、各状態の到達可能性と一意性の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())

        # If k is larger than total number of cells + 1, impossible in this construction model
        if k > n * m + 1:
            print("No")
            continue

        print("Yes")

        # Build a monotone staircase of k-1 filled cells in row-major order.
        # We place '*' for first k-1 cells, '-' otherwise.
        cnt = k - 1

        for i in range(n):
            row = []
            for j in range(m):
                idx = i * m + j
                if idx < cnt:
                    row.append('*')
                else:
                    row.append('-')
            print("".join(row))

if __name__ == "__main__":
    solve()
```この構造では、セルが行優先の順序で正確に入力されるまで埋められます。$k-1$ポジションは占有されており、残りは空のままになります。 これにより、単一の拡張フロンティアのように動作する単調な領域が作成されます。 

重要な実装の詳細は、次の場合に少なくとも 1 人の生徒が存在することを確認することです。$k \ge 2$、少なくとも 1 つ配置することで保証されます。`'*'`。 のために$k = 1$、単一の安定した構成として解釈を調整することで要件を満たしていることを除いて、グリッドは完全に空です。 

行優先の充填により、一貫した単調構造が保証されるため、圧縮により分岐動作が導入されず、到達可能な状態の数が制御されます。

 ## 特殊なケース

 完全に空のグリッドまたは完全に充填されたグリッドは、ただちに単一の安定した構成に折りたたまれます。 このような場合、すべての操作で同じグリッドが再度生成されるため、到達可能な状態数は 1 つだけになります。 この構築では、次のことを保証することでこれを回避します。$k > 1$、圧縮操作が作用するように、少なくとも 1 つのセルが入力されます。 

いつ$k = 1$、運用中に安定している限り、どのグリッドも有効です。 完全に空のグリッドは、最も単純で有効な構造です。スチューデントが存在しない場合、操作はスチューデントを導入できないからです。 

いつ$k$グリッド内で使用可能な位置の数を超えると、階段構造では必要な各ステップに個別の状態を割り当てることができなくなります。 これは、それらのケースを直接拒否することで処理されます。
