 ## 問題の理解

 文字列が与えられています$S$長さの$n$。 この文字列から、2 番目のはるかに大きな文字列が再帰的に構築されます。 構築は最初の文字から始まり、対称的に外側に向かって拡大していきます。最初の文字はベース文字列で、次の各ステップでは前の文字列が取得され、次の文字が中央に配置され、前の文字列が両側に反映されます。 したがって、すべての文字を処理した後、最終的な文字列は、次のすべての文字が含まれる完全に対称な展開になります。$S$完全なバイナリ展開では内部ノードになります。 

この最終的に展開された文字列を次のように表すと、$S^{(0)}_n$、次に、2番目の文字列が何回あるかを数えるように求められます$T$内部のサブシーケンスとして表示されます$S^{(0)}_n$。 サブシーケンスとは、文字は削除できますが、順序は保持する必要があることを意味します。 

展開された文字列の構造が重要な問題です。 その長さはおおよそ指数関数的に増加します$2^n - 1$, したがって、明示的に構築することはできません。 たとえ$n = 100$、文字列は天文学的な大きさです。 それを実体化したり、サブシーケンスを直接列挙しようとするアプローチは、直ちに不可能になります。 

この構築パターンでは、強力な再帰的重複も作成されます。すべての接頭辞によって、間に 1 文字を挟んで、左側で 1 回、右側で 1 回、計 2 回再利用される構造が生成されます。 この重複は、私たちが利用できる唯一の構造です。 

微妙なエッジケースが現れるのは、$T$長さは 1 です。その場合、答えは単純に最終構造内の文字の合計数になります。$2^n - 1$。 単純なサブシーケンス DP はまだ機能する可能性がありますが、指数構造が早期に認識されない場合、不必要に重くなり、オーバーフローの危険性があります。 

もう 1 つの失敗例は、構造を単純な連結チェーンとして扱うことから発生します。 これは線形連結ではありません。 これはバイナリ ツリーの拡張であるため、両方の側から同時に貢献がもたらされ、左部分と右部分の組み合わせが重要になります。 

## アプローチ

 ブルートフォース解釈では、明示的に文字列が構築されます。$S^{(0)}_n$次に、サブシーケンス DP を実行して、$T$。 サブシーケンスを無視したとしても、文字列の構築にはすでにコストがかかります$O(2^n)$、それは不可能です。 

もう少し素朴なアイデアは、再帰をシミュレートし、次のサブシーケンスの数を維持しようとすることです。$T$弦が伸びるにつれて。 ただし、有効なサブシーケンスは前の構造の左右のコピーに分割できるため、単純な連結ではサブシーケンスは加算されません。 

重要な観察は、構築されたすべての文字列が非常に厳密な形式を持っているということです。各ステップで次の形式の文字列が構築されます。$A + c + A$。 この構造により、パターンに対して動的プログラミング テーブルを使用して各中間文字列を表すことができます。$T$文字列自体を構築することはありません。 

固定パターンの場合$T$、構築された文字列ごとに 2 つの配列を維持します。 1 つの配列は、プレフィックスを一致させる方法が何通りあるのかを追跡します。$T$サブシーケンスとして、もう 1 つは、接尾辞を一致させる方法が何通りあるのかを追跡します。$T$文字列の右側から読む場合。 2 つの構造を連結すると、サブシーケンスが境界を越えて分割される可能性があるため、これら 2 つの方向が必要です。 

これらのプレフィックスとサフィックスの DP 状態が利用可能になると、2 つの文字列を結合することは、$T$。 これにより、指数関数的な爆発が回避されます。$T$長さは最大 100 なので、マージごとにコストがかかります$O(|T|^2)$。

 ## アルゴリズムのチュートリアル

 文字列を処理します$S$左から右に、現在構築されている構造の DP 表現を維持します。 

どの時点でも、現在の文字列は 2 つの配列で表されます。 

しましょう$f[k]$プレフィックスに一致する現在の文字列のサブシーケンスの数になります。$T[0..k-1]$。 

させて$g[k]$接尾辞に一致する現在の文字列(順方向に読み取られた)のサブシーケンスの数になります。$T[k..m-1]$、パターンの残りの部分のサブシーケンスとして解釈されます。 

これら 2 つのビューを使用すると、明示的に構築せずに構造をマージできます。 

の最初の文字で初期化します$S$。 そこから、それぞれの新しいキャラクターが$a_i$現在の構造を変革します$X$の中へ$X + a_i + X$。 

これを 2 つのステップでシミュレーションします。 

1. まず拡張します$X$単一の文字で$a_i$。 これにより両方が更新されます$f$そして$g$なぜなら、単一の文字は既存のサブシーケンスを拡張するために使用することも、スキップすることもできるからです。 
2. 次に、更新された構造をそれ自体と連結します。$Y = X + X$。 サブシーケンスは左側のコピーで開始され、右側のコピーで終了する可能性があるため、これは最も重要な部分です。 スプリットポジションごとに$k$で$T$、プレフィックスを一致させる方法を組み合わせます$k$左側の部分に接尾辞を一致させる方法が記載されています$k$右側の部分です。 

すべての文字を処理した後の最終的な答えは次のとおりです。$f[m]$、完全一致をカウントします$T$。 

正確さは、最初の処理後の不変条件に依存します。$i$の登場人物$S$、配列$f$そして$g$暗黙的に構築された文字列のすべてのサブシーケンス相互作用を完全にエンコードします。$S^{(0)}_i$。 単一文字の挿入と複製の両方の操作が行われるため、新しいステップごとにこの表現が保持されます。$X + X$、完全にプレフィックスとサフィックスの分割遷移の観点から表現できます。$T$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def merge(Af, Ag, Bf, Bg, m):
    # A + B
    f = [0] * (m + 1)
    g = [0] * (m + 1)

    # prefix DP for A+B
    for i in range(m + 1):
        for j in range(i, m + 1):
            f[j] = (f[j] + Af[i] * Bf[j - i]) % MOD

    # suffix DP (mirror idea)
    for i in range(m + 1):
        for j in range(i, m + 1):
            g[i] = (g[i] + Ag[j] * Bg[i + (m - j)]) % MOD

    return f, g

def add_char(f, g, c, T):
    m = len(T)
    nf = f[:]
    ng = g[:]

    # update prefix matches
    for i in range(m - 1, -1, -1):
        if T[i] == c:
            nf[i + 1] = (nf[i + 1] + f[i]) % MOD

    # update suffix matches
    for i in range(m):
        if T[i] == c:
            ng[i] = (ng[i] + g[i + 1]) % MOD

    return nf, ng

def solve():
    S, T = input().split()
    m = len(T)

    f = [0] * (m + 1)
    g = [0] * (m + 1)
    g[m] = 1

    f[0] = 1
    g[m] = 1

    for i in range(len(S)):
        f, g = add_char(f, g, S[i], T)
        f, g = merge(f, g, f, g, m)

    print(f[m] % MOD)

if __name__ == "__main__":
    solve()
```この実装により、DP はコンパクトに保たれます。 の`add_char`関数は、単一の文字をすべてのサブシーケンスに挿入し、線形時間内で接頭辞と接尾辞の一致を更新することをシミュレートします。$T$。 の`merge`関数は、パターンのすべての分割を考慮して 2 つの同一の構造を結合する、重要な複製ステップを実行します。 

操作の順序は重要です。各ステップで構成されているため、挿入は複製の前に行われる必要があります。$X + c + X$。 配列は常にモジュロに保たれます$998244353$オーバーフローを防ぐため。

 ## 特殊なケース

 いつ$T$長さが 1 の場合、最終的に展開された構造内のすべての文字が直接寄与します。 再帰により各新しい文字の周囲の文字列が 2 倍になるため、カウントは構築されたツリーの合計サイズに従います。 挿入ステップごとに利用可能な一致が直線的に増加し、重複により既存の寄与が 2 倍になるため、DP はこれを正しく累積します。 

いつ$S$繰り返しの文字で構成されると、構造は非常に対称的になります。 プレフィックスとサフィックス DP は文字の多様性を想定しておらず、位置の遷移のみを想定しているため、アルゴリズムはこれを処理します。 

いつ$T$に存在しない文字が含まれています$S$、すべての遷移更新が失敗し、空の一致を除いて両方の DP 配列がゼロのままになり、最終的な答えとして正しくゼロが生成されます。
