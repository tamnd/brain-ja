 ## 問題の理解

 数直線上に 2 組の点が与えられています。 1 つのセットは荷物アイテムを表し、それぞれが整数の位置にあります。 もう 1 つのセットは、ベルトコンベアの前に立つ人々を表しており、これも整数の位置にあります。 毎秒、すべての荷物の位置が 1 つずつ増加するため、人々は固定されたまま、すべてが単位速度で右に流れていきます。 

各人は最大でも 1 個の荷物と一致する可能性がありますが、その荷物が左側から始まっている場合に限ります。右側にあるものはすでに事実上「見られ」ており、その人のものではないためです。 有効な設定とは、荷物が複数の人に割り当てられず、誰も複数の荷物を受け取らないように、いくつかの荷物アイテムを一部の人に割り当てる方法です。 

有効な構成ごとに、誰かが最初に荷物に到達した時刻を調べます。 ある人が位置 a から開始してバッグとマッチングされ、その人が位置 b にいる場合、両者は互いに相対的に剛体的に移動するため、バッグは時間 b − a に彼らに到着します。 構成で対象となる値は、すべての一致したペアにおけるこれらの時間の最小値です。 

構成を列挙するように求められることはありません。 代わりに、すべての有効な構成にわたるこの最小時間の合計を、998244353 を法として計算する必要があります。 

座標は最大 500 と小さく、最大でも 500 人の人物と 500 個の荷物があります。 これは、位置がインデックスよりも重要であることをすぐに示唆しています。ジオメトリは密ですが境界があるため、どのような解決策でも、大きな組み合わせ状態を直接反復するのではなく、小さな値範囲でのカウントに問題を軽減する必要があります。 

微妙な点は、構成は時間内に注文することではなく、どの人がどの荷物を受け取るかによってのみ定義されることです。 もう 1 つの重要な制約は、割り当てが両側で単射的であるため、「人の荷物が残っている」条件によって引き起こされる 2 部グラフで部分一致をカウントしていることです。 

素朴な解釈の間違いは、各人が独立して左側の荷物アイテムを選択していると考えることです。 これにより、2 人が同じ荷物を選択した場合の衝突は無視されますが、これは禁止されています。 もう 1 つの簡単な間違いは、一致が存在するかどうかだけを気にしていると考えることです。 代わりに、すべての一致に関する統計を合計しています。 

## アプローチ

 強引なアプローチでは、各人に荷物を割り当てないか、左側の荷物のうち 1 つだけを割り当てる方法をすべて列挙し、2 人が同じ荷物を選ぶ割り当てを除外します。 実現可能性のチェックを無視したとしても、状態空間はすでに巨大です。各人には最大 500 の選択肢があるため、生の製品はおよそ$500^{500}$、計算の範囲をはるかに超えています。 

二部グラフでの割り当てからマッチングに視点を移すと、実際の構造がより明確になります。 構成は単に人と荷物のマッチングであり、荷物が人の左側にある場合にのみエッジが存在するという制約があります。 各マッチングに必要な数量は、選択したエッジの最小値です。$b_j - a_i$。 

マッチングの最小値を直接計算する代わりに、視点を逆転させます。 任意のしきい値時間に対して$t$、少なくとも遅延を伴うすべての選択されたエッジを持つマッチングが何回あるかを尋ねることができます。$t$。 つまり、満足するエッジのみを許可します$b_j - a_i \ge t$。 定義すると$F(t)$そのようなエッジのみを使用するマッチングの数として、すべてのマッチングはすべてに正確に 1 を与えます。$F(t)$のために$t$最小エッジ重量まで。 総括$t$必要な最小値の合計を再構成します。 

したがって、答えは、次のようにパラメータ化された 2 部グラフのファミリーにわたる累積カウントになります。$t$、エッジが次のように消えます。$t$が増加します。 ポジションは 500 で制限されているため、関連するしきい値は 500 のみです。 

固定の場合$t$、グラフは特殊な構造をしています。 荷物の位置を分類すると、各人は荷物の項目の接頭辞に接続されます。$a_i \le b_j - t$モノトーンです$a_i$。 したがって、すべての人には、ソート順の接頭語である許可される荷物の間隔があります。 このような「プレフィックスがネストされた」二部グラフでの一致のカウントは、制約が単調であり、プレフィックスの長さの増加順に処理できるため、扱いやすいです。 

これらのグラフでは、アクセスできる荷物の数によって人々を並べ替えて処理します。 人を処理するとき$k$利用可能な荷物アイテムがあるとします$i-1$人々にはすでに個別の荷物が割り当てられています。 がある$k - (i-1)$未使用の対象手荷物アイテムが残っていること。 人はこれらのいずれかを選択することも、一致しないままにすることもできます。 これにより、実行可能条件が満たされている限り、1 人当たりの単純な乗算寄与が得られます。$k \ge i-1$維持されている。 

これによりそれぞれが変形します$F(t)$プレフィックス サイズから導出された線形項でソートされた人々の積に変換され、それぞれの評価が行われます。$O(m \log m + n \log n)$。 以来$t$値の範囲は最大 500 個を超えますが、全体の複雑さは管理可能なままです。

 ## アルゴリズムのチュートリアル

 最初に荷物の位置を並べ替えて、「左側にあるアイテムの数」をプレフィックス数として推論できるようにします。 各人について、後でその制約を単一の整数に変換します。$k$、指定されたしきい値の下で適格な手荷物品目の数を表します。$t$。 

次に、考えられるすべてのしきい値時間を繰り返します。$t$0から可能な最大距離まで。 それぞれについて$t$、効果的なグラフを構築します。 

固定の場合$t$、各人について、満足できる荷物の数を計算します。$a_i \le b_j - t$。 これにより値が得られます$k_j$、その人のプレフィックス近傍のサイズ。 

次に、増加順に人々を並べ替えます$k_j$。 この順序付けは、人を処理するときに、以前のすべての人がより大きな実行可能なセットを持たないことを保証し、使用済みの荷物を一貫した方法でこれらのプレフィックスから消費するものとして扱うことができるため、非常に重要です。 

現在のインデックスを維持します$i$、処理した人数を表します。 処理するときは、$i$この順序の - 番目の人、以前の割り当てが潜在的に消費された後に残っている選択肢がいくつあるかを確認します$i-1$利用可能なプールからの荷物アイテム。 自由な選択肢の数は、$k_j - (i-1)$。 人はこれらのいずれかを選択するか、一致しないままになる可能性があり、それが要因の要因となります。$k_j - (i-1) + 1$合計数に。 

これらの貢献をすべての人々に掛け合わせて、$F(t)$。 合計する$F(t)$全体$t$最終的な答えを出します。 

### なぜ効果があるのか

 任意の固定しきい値で$t$、すべての有効な割り当ては、各人の隣接リストがソートされた荷物配列のプレフィックスである 2 部グラフでのマッチングです。 プレフィックス サイズでユーザーを並べ替えると、一致の制約が区別できない容量の貪欲な割り当てのように動作します。 重要な不変条件は、処理後の$i$人、せいぜい$i$荷物アイテムは消費することができ、後の人にとって残りの有効な選択肢はすべて、残りのプレフィックス サイズによって完全に決定されます。 これにより、すでに選択されている荷物アイテムの特定の ID への依存が取り除かれ、カウントだけが残るため、製品の公式が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    max_a = max(a)
    min_b = min(b)

    # possible t values are bounded by coordinate range
    max_t = 500

    ans = 0

    for t in range(max_t + 1):
        # compute k_j for each person: number of a_i <= b_j - t
        k = []
        for bj in b:
            limit = bj - t
            # count of a_i <= limit
            # binary search
            l, r = 0, n
            while l < r:
                mid = (l + r) // 2
                if a[mid] <= limit:
                    l = mid + 1
                else:
                    r = mid
            k.append(l)

        k.sort()

        ways = 1
        for i, ki in enumerate(k):
            # number of ways: choose unused or stay unmatched
            choices = ki - i + 1
            if choices <= 0:
                ways = 0
                break
            ways = (ways * choices) % MOD

        ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```コードでは、最初に両方の配列を並べ替えるため、プレフィックスのカウントが意味を持つようになります。 閾値ごとに$t$、ソートされた荷物の位置に対する二分検索を使用して、各人が到達できる荷物の数を計算します。 これらのカウントは、貪欲な処理順序に一致するように並べ替えられます。 

乗算ループは、接頭辞制約の下で一致をカウントするための派生式を直接実装します。 表現`ki - i + 1`は、残りのキャパシティに、その人をマッチングしないままにするオプションを加えたものを表します。 これが正でなくなると、そのしきい値に対する有効な一致が存在しません。 

最後に、しきい値を超えたすべての寄与が最終的な答えに累積されます。

 ## 特殊なケース

 まれなケースは、特定のしきい値に到達できる荷物がない場合に発生します。 たとえば、すべての荷物が厳密に人の右側にある場合、差し引きます。$t$、 それから$k_j = 0$。 その状況では、式は次のようになります$k_j - i + 1 \le 0$、正しく強制します$F(t) = 0$有効な割り当てにはそのしきい値に該当する人を含めることはできないためです。

最終ケースが大きい$t$、すべてのエッジが消えます。 毎$k_j = 0$, したがって、人がいない限り積はすぐにゼロになります。これは、荷物が届かない場合は割り当てが不可能であるという事実と一致します。
