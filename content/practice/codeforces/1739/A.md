 ## 解決策
 ## 問題の理解

 私たちに与えられるのはせいぜい非常に小さなチェス盤です$8 \times 8$。 タスクは複雑な値を計算することではなく、ナイトがボード内に留まる正当な動きを持たないセルを見つけることです。 そのようなセルが存在する場合は、そのうちの 1 つを出力する必要があります。 それ以外の場合は、ボード上の任意の座標を出力できます。 

重要なオブジェクトは標準的なナイトの動きです: セルから$(r, c)$、ナイトはフォームの 8 つの可能なオフセットにジャンプしようとします。$(\pm 2, \pm 1)$そして$(\pm 1, \pm 2)$。 これら 8 つの宛先のいずれもボード内に残っていない場合、そのセルは孤立していると呼ばれます。 

両方の次元が次のように制限されているため、$8$、セルの総数は最大で$64$。 これにより、問題は直ちに、直接シミュレーションで十分であるだけでなく、どのような最適化よりも概念的にクリーンになるという領域に置かれます。 各セルを検査し、最大 8 つの手をチェックするアプローチは、テスト ケースごとに一定時間で実行されます。 

ボードが非常に小さい場合、微妙なエッジ ケースが発生します。 で$1 \times m$または$n \times 1$ボード上では、ナイトが移動するたびにボードから離れるため、すべてのセルが孤立します。 で$2 \times 2$ボードでも同じことが起こります。 ような大きなボードでは、$3 \times 3$、一部の中央セルは孤立しますが、境界セルではジオメトリに応じて少なくとも 1 つの有効な移動が許可されます。 この定義は純粋にローカルであるため、グローバルな制約やパリティの問題を考慮する必要はありません。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのセルを検査し、8 つのナイトの動きをすべて試します。 少なくとも 1 つの手がグリッド内に留まる場合、セルは分離されません。 何もない場合は、すぐに返品します。 せいぜいあるので$64$細胞と$8$セルごとの指示に応じて、テスト ケースごとの作業は数百の操作に制限されますが、これは自明のことながら高速です。 

ボードが非常に小さいため、活用できるより深い構造はありません。 さらに詳しく考える唯一の理由は、この状態が純粋に幾何学的で局所的なものであることを認識することです。隔離は周囲の環境がどうかによってのみ決まります。$3 \times 3$そして$5 \times 5$近隣は境界内に存在します。 これは、前処理や検索が必要ないことを意味します。 

最適なソリューションは総当たりアプローチと同じであり、直接実装されるだけです。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理し、基板をスキャンします。 

1. すべてのセルを反復処理します。$(r, c)$で$n \times m$グリッド。 各細胞は分離の候補となります。 
2. 固定セルの場合は、8 つのナイトの動きをすべてチェックします。 移動するたびにターゲットセルが生成されます$(r + dr, c + dc)$そしてそれがボードの境界内に残っているかどうかを確認します$1 \le r \le n$、$1 \le c \le m$。 
3. 少なくとも 1 つの移動が有効な場合、セルを非分離としてマークし、次の移動に進みます。 これにより、有効なナイト遷移がゼロのセルのみを受け入れることが保証されます。 
4. 8 つの手がどれも有効でないセルが見つかった場合は、直ちにそれを出力し、現在のテスト ケースの処理を停止します。 
5. すべての位置をスキャンした後、孤立セルが見つからない場合は、任意のセルを出力します。$(1, 1)$。 

重要な考え方は、孤立の定義は完全にローカルであり、ナイトの移動によって到達可能な直近の近隣にのみ依存するため、徹底的なチェックでは有効な候補を見逃すことはできないということです。 

### なぜ効果があるのか

 8 つのナイト オフセットすべてがグリッドから離れると、セルは正確に分離されます。 アルゴリズムはこの条件を直接テストします。 すべてのセルが独立してチェックされ、考えられるすべての動きが列挙されるため、定義を満たす場合にのみ、セルが分離されて報告されます。 そのようなセルが存在しない場合、問題により任意の座標を返すことが許可されるため、すべての場合において正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    moves = [(2, 1), (2, -1), (-2, 1), (-2, -1),
             (1, 2), (1, -2), (-1, 2), (-1, -2)]
    
    for _ in range(t):
        n, m = map(int, input().split())
        
        found = False
        for r in range(1, n + 1):
            for c in range(1, m + 1):
                isolated = True
                
                for dr, dc in moves:
                    nr, nc = r + dr, c + dc
                    if 1 <= nr <= n and 1 <= nc <= m:
                        isolated = False
                        break
                
                if isolated:
                    print(r, c)
                    found = True
                    break
            
            if found:
                break
        
        if not found:
            print(1, 1)

if __name__ == "__main__":
    solve()
```実装は文字通りアルゴリズムに従います。 唯一の微妙な点は早期終了です。孤立したセルが見つかると、有効な答えは受け入れられるため、それ以上のスキャンは停止されます。 移動リストは固定されており、網羅的であるため、ケース分析を行わなくても正確性が保証されます。 

## 実用的な例

 考えてみましょう$3 \times 3$ボード。 中央のセルを確認します$(2, 2)$。 そこからナイトが移動するたびにグリッドの外に出るため、すぐに孤立したものとして分類されます。 アルゴリズムは、反復中にこのセルに遭遇するとすぐに停止します。 

| セル | 有効なナイト移動が存在します | 孤立した |
 | --- | --- | --- |
 | (1,1) | はい | いいえ |
 | (1,2) | はい | いいえ |
 | (1,3) | はい | いいえ |
 | (2,2) | いいえ | はい |

 これにより、この場合、アルゴリズムが一意の孤立した位置を正しく識別していることが確認されます。 

ここで考えてみましょう$2 \times 3$ボード。 すべてのセルには少なくとも 1 つのナイト ムーブがグリッド内に留まっているため、孤立したセルは存在しません。 アルゴリズムはすべての位置をスキャンし、孤立した位置を見つけて出力します。$(1,1)$。 

| セル | 有効なナイト移動が存在します | 孤立した |
 | --- | --- | --- |
 | (1,1) | はい | いいえ |
 | (1,2) | はい | いいえ |
 | (1,3) | はい | いいえ |
 | (2,1) | はい | いいえ |
 | (2,2) | はい | いいえ |
 | (2,3) | はい | いいえ |

 これは、分離セットが空の場合のフォールバック動作を示しています。

 ## 特殊なケース

 で$1 \times m$または$n \times 1$ボードでは、すべてのナイトの動きが少なくとも 1 つの座標ですぐに境界を超えるため、すべてのセルが分離されます。 各セルについて 8 つの候補移動がすべて境界チェックに失敗するため、アルゴリズムがこれを処理します。そのため、最初に検出されたセルが孤立として返されます。 

で$2 \times 2$ボードでも同じロジックが適用されますが、より高密度の形式になりました。高さや幅が不十分なため、ナイトの移動はすべてグリッドから外れます。 スキャンは最初のセルを孤立したセルとして分類し、ただちに停止します。 

ような大きなボードでは、$3 \times 3$、中央のセルのみ、グリッド内に有効なナイトの動きがありません。 アルゴリズムは反復中にそれに到達し、すべてのオフセットが範囲外になるため、孤立しているものとして正確に識別します。
