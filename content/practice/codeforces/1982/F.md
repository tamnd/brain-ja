 ## 解決策
 ## 問題の理解

 ポイントの更新を通じて時間の経過とともに変化する配列が与えられます。 変更のたびに、配列に関する構造的な質問に答える必要があります。つまり、そのセグメントのみをソートすると配列全体が非降順でソートされるような、最も短い連続セグメントは何かということです。 

重要な考え方は、配列を完全に並べ替えようとしていないということです。 代わりに、すべての反転を含む最小の「損傷間隔」を特定しようとしています。その間隔だけをソートすることで配列全体が修復されます。 

各クエリは 1 つの位置を変更します。変更するたびに、この最小限のセグメントを最初から効率的に再計算する必要があります。 

制約があるため、慎重な設計が必要になります。 配列の長さと更新数は両方とも合計 5e5 までになります。 クエリごとに直線的な時間で並べ替えやスキャンを再計算するソリューションでは、最悪の場合、約 2.5e11 回の操作が発生しますが、これは実行可能な制限をはるかに超えています。 これにより、クエリごとの並べ替え、反転の完全な再計算、またはネストされたスキャンが即座に除外されます。 

配列がすでにソートされている場合、微妙なエッジケースが発生します。 その場合、答えは -1 -1 でなければなりません。 [1,1] や [l,l] などのセグメントを常に返す単純な間隔検出アプローチは、少なくとも 1 つの位置が「固定」されている必要があると誤って想定しているため、ここでは失敗します。 もう 1 つの注意が必要な状況は、更新がローカルであるにもかかわらず、その影響がグローバルに伝播する場合です。 たとえば、[1,2,3,4,5] のようなほぼソートされた配列では、中央を 0 に変更すると、インデックス 1 まで左境界がシフトされ、将来の答えはローカルな変更ではなくグローバルな順序に依存します。 

## アプローチ

 ブルート フォース ソリューションは、配列をスキャンし、並べ替えられたプロパティに違反している最初と最後の位置を見つけることによって、更新のたびに答えを再計算します。 また、考えられるすべてのサブ配列をソートし、配列が修正されるかどうかをチェックすることをシミュレートすることもできます。 これは概念的に機能します。なぜなら、部分配列をソートするとその内部のすべての反転が削除され、残りの問題は境界の反転が残るかどうかであるからです。 ただし、すべての部分配列を試すことは二次的であり、各クエリのスキャンでも線形であるため、O(nq) となり、遅すぎます。 

重要な観察は、最適なセグメントは配列の反転のグローバル構造によって完全に決定されるということです。 配列のソートされたバージョンを想像すると、最小セグメントは、正しいソート領域に対して「場違い」にあるすべてのインデックスをカバーする必要があります。 より具体的には、l の左側がすべてソート順とすでに一致するような最小の l と、r の右側もすべて一致するような最大の r が必要です。 

これは、順序統計に関するクエリとして再構成できます。配列がソートされた構造と異なる最初と最後の位置を見つける必要がありますが、更新時にこれを動的に維持する必要があります。 

重要な構造的洞察は、答えが 2 つのことによって決まるということです。1 つは l の前に反転が現れないという接頭辞の条件、もう 1 つは r の後に反転が現れないという接尾辞の条件です。 これらは、ローカルな順序付け制約を効率的に維持する順序付けされたデータ構造を使用して追跡できます。 

これを実現する標準的な方法は、値とインデックスをキーとしたバランスのとれた構造ですべてのインデックスを維持し、並べ替え順序に違反している箇所をすぐに見つけられるようにすることです。 境界は、先行関係が壊れる最初の位置と最後のその位置によって決定されます。 

ローカルな順序の一貫性を維持する適切な順序セットまたはセグメント ツリーを使用すると、各更新は比較の小さな近傍にのみ影響しますが、グローバルな極値のクエリは対数時間で実行できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適(順序構造/セグメントツリー) | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列と、順序プロパティ a[i] <= a[i+1] がどこで成立するか失敗するかを追跡する構造を維持します。 

1. a[i] <= a[i+1] の場合は diff[i] = 1、それ以外の場合は 0 となる補助配列 diff を構築します。これは、配列が各境界でローカルにソートされるかどうかをエンコードします。 
2. 単一の位置が変更された場合の diff の更新をサポートするデータ構造を維持します。 a[i] が更新されると、隣接する比較のみが影響を受けるため、変更できるのは diff[i-1] と diff[i] のみです。 これは重要な地域特性です。 
3. クエリに答えるには、l またはその前に違反が存在するような最小の l と、r またはその後に違反が存在するような最大の r が必要です。 同様に、diff[i] = 0 のすべてのインデックス i をカバーする最小間隔が必要です。 
4. diff[i] = 0 のすべてのインデックス i を格納する構造 (ソートされたセットなど) を維持します。 左側の境界はこのセット内の最小のインデックスから導出され、右側の境界は最大のインデックスに 1 を加えたものから導出されます。 
5. セットが空の場合、配列はすでにソートされており、-1 -1 を返します。 
6. 更新ごとに、最大 2 つの diff エントリを調整し、それに応じてセットを更新し、セットの端から答えを再計算します。 

微妙な点は、返すセグメントが直接 diff 間隔ではなく、そこから派生していることです。 最初の違反が i にある場合、並べ替えられたセグメントは i 以降で開始する必要があり、右側についても同様です。 

### なぜ効果があるのか

 すべての反転が完全にその部分配列内にある場合に限り、部分配列を修正した後、配列はソートされます。 あらゆる反転は、diff 内の隣接する違反のペアによって確認されるため、diff 内のすべてのゼロエントリをカバーすることは、すべての反転をカバーすることと同じです。 セグメントを並べ替えると、セグメントに完全に含まれるすべての反転が削除され、外側の要素には影響を与えないため、最小有効セグメントは、すべての違反境界を含む最小の間隔になります。 これにより、ソート後に反転が境界を越えることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    bad = set()

    def add(i):
        if 0 <= i < n - 1:
            if a[i] > a[i + 1]:
                bad.add(i)

    for i in range(n - 1):
        add(i)

    def answer():
        if not bad:
            return "-1 -1"
        l = min(bad) + 1
        r = max(bad) + 1
        return f"{l} {r}"

    out = []
    out.append(answer())

    for _ in range(q):
        pos, val = map(int, input().split())
        pos -= 1

        a[pos] = val

        for i in (pos - 1, pos):
            if 0 <= i < n - 1:
                if i in bad:
                    if not (a[i] > a[i + 1]):
                        bad.remove(i)
                else:
                    if a[i] > a[i + 1]:
                        bad.add(i)

        out.append(answer())

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、局所的な無秩序を定義する隣接する比較のみを維持することに依存しています。 値が変更されると、その 2 つの隣接値のみが新たに無効になったり、再度有効になったりするため、セット内の最大 2 つのエントリを更新します。 

答えは、一連の違反の極値インデックスから直接導出されます。 diff[i] は a[i] および a[i+1] に対応するため、境界インデックス i から配列インデックスへの変換には +1 シフトする必要があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [2,2,3,4,5]
```最初は違反がないため、セットは空です。 

| ステップ | 更新 | 配列 | 悪いセット | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 初期化 | [2,2,3,4,5] | {} | -1 -1 |
 | 1 | a[2]=1 | [2,1,3,4,5] | {1} | 2 2 |
 | 2 | a[4]=1 | [2,1,3,4,1] | {1,3} | 2 4 |

 これは、単一の更新によって複数の素の違反がどのように発生する可能性があるかを示しており、答えは両端をカバーする必要があります。

 入力:```

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新は最大 2 つの隣接関係チェックと設定操作に影響します。 
| スペース | O(n) | 配列と不正な位置のセット |

 最大 5e5 までの各操作は、バランスのとれた構造上で一定の作業のみをトリガーするため、複雑さは制限内に問題なく収まります。

 ## 特殊なケース

 完全にソートされた配列は、更新によって厳密な反転が導入されるまで安定した状態を保ちます。 この場合、無効になるのは隣接する 2 つの比較だけであり、アルゴリズムはそれらのインデックスを正確に不良セットに挿入し、それらをカバーするのに十分な範囲の最小限のセグメントを生成します。 

配列全体で減少する値を繰り返し挿入するなど、複数の更新によって徐々に広範囲の乱れが生じると、不良セットが拡大し、それに応じて返される間隔も長くなります。 各更新ではローカル比較のみが行われますが、反転は少なくとも 1 つの隣接する違反によって目撃される必要があるため、極値インデックスは依然としてグローバルな影響を受ける領域を正確にキャプチャします。
