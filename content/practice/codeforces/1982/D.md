 ## 問題の理解

 山の高さを表す数値のグリッドと、各セルを 2 つのグループのいずれかに分割する 2 番目のグリッドが与えられます。 1 つのグループは雪をかぶったものとしてマークされ、もう 1 つのグループは雪をかぶっていません。 ここでのタスクは、雪のあるグループの値の合計を雪のないグループの値の合計と等しくできるかどうかを判断することです。 

許可される唯一の操作は、いずれかを選択することです$k \times k$部分行列と整数の加算$c$その中のすべての細胞に。 の値$c$は毎回独立して選択され、正または負の値になります。 重要なのは、この操作は部分行列が両方のグループに重なっている場合は両方のグループに同時に影響します。 

したがって、問題は、これらの平方更新を使用して 2 つのグループ間で合計「質量」を再分配できるかどうかを問うことに帰着します。 

制約は大きく、最大で$500 \times 500$テストケースごとに最大$2.5 \cdot 10^5$セルの合計。 これにより、すべての部分行列のシミュレーションや操作ごとの推論が直ちに除外されます。 どのソリューションも、グリッド サイズが線形または線形に近いものでなければなりません。 

微妙な点が現れるのは、$k = 1$。 すべてのセルは独立して調整できるため、いつでも値を自由に設定して両方の合計を等しくすることができます。 これは、両方のグループが些細な方法で構造的に縮退していない限り、答えは常に「YES」である特殊なケースです。 

2 番目の重要なエッジ ケースは、グループの 1 つが空の場合です。 その場合、その合計はゼロとして定義されるため、問題は他のグループの合計を強制的にゼロにできるかどうかになります。 操作の自由度が大きいため、これは、少なくとも 1 つの操作が 1 つのグループにのみ影響を与えることができるかどうか、または構造が結合を強制するかどうかに完全に依存します。 

単純な間違いは、個々のセルを常に独立して調整できると想定することです。 それは次の場合は誤りです$k > 1$更新はブロックベースであり、多くのセルを同時にオーバーラップするため、位置間に制約が作成されます。 

## アプローチ

 ブルートフォースの視点は、それぞれについて考えることから始まります。$k \times k$変数としての操作。 それぞれの操作が貢献します$c \cdot ( \#\text{snowy cells in block} - \#\text{non-snowy cells in block})$2 つの合計の差に換算します。 可能な部分行列ごとに 1 つの変数がある場合、最終的な差がゼロになるように強制する線形システムを解くことを試みることができます。 

この定式化は正しいですが、まったく実用的ではありません。 がある$(n-k+1)(m-k+1)$可能な部分行列、最大$250{,}000$テストごとに。 このようなシステムを構築して解決するには、時間制限をはるかに超えるでしょう。 

重要な観察は、完全な線形システムは必要ないということです。 各操作は隣接するブロックに影響を与え、重複する構造によりキャンセルが可能になります。 個々のセルを追跡する代わりに、グリッドを独立したコンポーネントに分割できるかどうかだけを考慮します。$k \times k$更新情報。 

これを捉える標準的な方法は、グリッドのモジュロを調べることです。$k$両方の次元で。 毎$k \times k$操作は 1 つの剰余クラス パターンにのみ影響し、操作を繰り返すと、同じモジュロ構造を共有するすべてのセルに調整を転送できます。 これにより、問題は 2 つのグループ間の差異がこれらのブロック効果の組み合わせとして表現できるかどうかを確認することになります。 

最終条件は、誘導されたデータの一貫性をチェックすることに単純化されます。$k \times k$-周期構造: 各剰余クラスのモジュロ内$k$、雪のセルと雪のないセルの間の不均衡は、グローバルに調整可能でなければなりません。 すべての剰余クラスが全体としてバランスがとれている場合、全体的な差がなくなるまで値をシフトする演算を構築できます。 それ以外の場合、少なくとも 1 つのクラスが不変の障害を作成します。

 ## アルゴリズムのチュートリアル

 1. 積雪量と非積雪量の初期差を計算します。 この差がすでにゼロである場合、操作は必要ないため、すぐに成功します。 このステップでは、調整が必要かどうかを判断します。 
2. 単一の$k \times k$操作により差が変わります。 選択したブロック内では、すべての雪のセルが貢献します$+c$そして、雪のないすべてのセルが貢献します$-c$。 したがって、各操作が貢献します$c \cdot (\text{snowy count} - \text{non-snowy count})$そのブロックの中にあります。 
3. すべてのブロックについて直接推論する代わりに、座標の剰余によってセルをグループ化します。$k$。 すべてのセルは、正確に 1 つの残基クラス ペアに属します。$(i \bmod k, j \bmod k)$、そしてすべての$k \times k$配置は、構造化された繰り返し方法でこれらのクラスと対話します。 この周期性が中心となる制約構造です。 
4. 各残基クラスについて$(r, c)$、そのクラス内のすべてのセルが寄与する正味の不均衡を計算します。これは、雪の寄与から雪以外の寄与を引いたものとして定義されます。 これにより、グリッドが縮小されます。$k \times k$アンバランスを圧縮して表現。 
5. ブロック係数を選択することで合計を中和できるという意味で、これらすべての剰余クラスの不均衡が互換性があるかどうかを確認します。 この条件は、すべての残基が「内部的に一貫している」ことを単純化します。これは、基本的な残基に対する累積的な不均衡を意味します。$k \times k$パターンは矛盾を強制してはなりません。 
6. この周期構造に矛盾が生じた場合は、どの一連の操作でも差異を解消することはできないと結論付けます。 それ以外の場合は、建設的に各残差の寄与をキャンセルする操作を割り当てることができるため、答えは「YES」です。 

### なぜ効果があるのか

 それぞれ$k \times k$操作はグリッド上で周期的に繰り返される方法で質量をシフトします。$k$。 これにより、到達可能な変換の線形空間が作成され、その基底は剰余クラスの法によって完全に決定されます。$k$。 初期差分ベクトルが消去可能となるには、これらの変換の範囲内に存在する必要があります。 剰余集計ステップでは、問題をこのスパンに投影し、メンバーシップをチェックします。 投影が成功すると、不均衡を解消するための操作を合成できます。 失敗した場合、不均衡は許可された操作の影響を受けずに不変の方向に存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        
        a = [list(map(int, input().split())) for _ in range(n)]
        typ = [input().strip() for _ in range(n)]
        
        diff = 0
        
        for i in range(n):
            row_t = typ[i]
            row_a = a[i]
            for j in range(m):
                if row_t[j] == '0':
                    diff += row_a[j]
                else:
                    diff -= row_a[j]
        
        if diff == 0:
            print("YES")
            continue
        
        if k == 1:
            print("YES")
            continue
        
        # build residue imbalance
        mod_sum = [[0] * k for _ in range(k)]
        
        for i in range(n):
            for j in range(m):
                r = i % k
                c = j % k
                if typ[i][j] == '0':
                    mod_sum[r][c] += a[i][j]
                else:
                    mod_sum[r][c] -= a[i][j]
        
        # key condition: all mod classes must balance globally
        # reduce to checking if all values equal modulo global scaling
        base = mod_sum[0][0]
        ok = True
        for r in range(k):
            for c in range(k):
                if mod_sum[r][c] != base:
                    ok = False
                    break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()

特別な場合$k = 1$すべてのセルが独立して調整可能になり、システムが完全に制御可能になるため、早期に処理されます。 

ソリューションの中核は、$k \times k$配列`mod_sum`、セルの位置モジュロに基づいてセルの符号付き寄与を集計します。$k$。 これにより、グリッドが周期構造に圧縮されます。 

最後に、すべての残余セルが同じように動作するかどうかを確認します。 この等価条件により、ブロック操作を繰り返しても解消できない削減不可能な不均衡が剰余クラスによって引き起こされることがなくなります。
