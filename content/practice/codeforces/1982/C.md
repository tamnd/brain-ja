 ## 解決策
 ## 問題の理解

 私たちは、特定の順序で並べられたカードのデッキを使用してゲームをシミュレートするように求められます。 各カードには正の整数が書かれています。 エゴールは各ラウンドでデッキの一番上からゼロ以外のカードを取り、取り出したカードの合計が所定の範囲内にある場合にラウンドの勝利となります。$[l, r]$。 タスクは勝利ラウンドの総数を最大化することですが、勝利ラウンドが連続して発生する必要はありません。 入力では複数の独立したテスト ケースが提供され、それぞれがカードの数、ターゲット範囲、カード値の順序を指定します。 各テスト ケースの出力は単一の整数、つまり勝利ラウンドの最大数です。 

制約により最大で許可されるのは、$10^5$テストケースごとのカード数と合計$n$すべてのテストケースにわたって$2 \cdot 10^5$。 これは除外します$O(n^2)$各ラウンドですべての可能な連続部分配列を反復処理すると、$10^{10}$操作。 各カードの価値と境界$l, r$まで可能です$10^9$, そのため、小さな数値を前提とした配列インデックス付けのトリックに依存せずに、整数の合計を慎重に処理する必要があります。 

エッジケースには、すべてのカードが大きすぎて収まらないシーケンスが含まれます$[l, r]$個別に、個々のカードがすでに範囲を満たしているシーケンス、および範囲に到達するために複数の小さなカードをグループ化する必要があるシーケンス。 例えばカードの場合`[1, 2, 1]`そして範囲`[3, 3]`、1 枚のカードを取ることはできませんが、最初の 2 枚のカードの合計が 3 になり、勝利ラウンドが得られます。 常に一番上のカードを取り、それが勝つかどうかを確認するという単純な貪欲なアプローチは、小さなカードを組み合わせる機会を逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは、残りのデッキのすべての可能なプレフィックスを調べて、勝ちの範囲内で連続する合計を見つけることです。 これは正しいですが、次のことが必要です。$O(n^2)$最悪の場合、各ステップで考えられるすべてのプレフィックス長をチェックする必要がある可能性があるためです。 と$n$まで$10^5$、これは遅すぎます。 

重要な観察は、問題は、合計が以下に該当するプレフィックスの数を数えることに帰着するということです。$[l, r]$。 プレフィックスの合計配列を考えてみましょう$S$どこ$S_i = a_1 + a_2 + ... + a_i$。 各ラウンドは、合計が以内になるようにプレフィックスの開始インデックスと終了インデックスを選択することに対応します。$[l, r]$。 エゴールは常に上からカードを取得する必要があるため、各ラウンドは最初に残ったカードから始まります。 したがって、各位置について、現在のカードから始まる最短のプレフィックスを見つけるだけで済みます。$[l, r]$。 最初の合計$k$カードは$S_k$したがって、最大のものを見つけることが問題になります。$k$そのような$S_k - S_{prev}$にある$[l, r]$、 どこ$S_{prev}$以前に削除されたすべてのカードの合計です。 プレフィックス合計に 2 ポインター手法を使用すると、これを線形時間で計算できます。 

もう 1 つの洞察は、カードの値が正であるため、より多くのカードを含めるにつれて合計が厳密に増加するということです。 これにより、2 ポインター アプローチでは、より大きなプレフィックスも厳密に大きくなり、順番にチェックできるため、後戻りすることなく常に範囲を満たす最小長のプレフィックスを見つけることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックス合計のツーポインタ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$l$、$r$、およびカード値の配列$a$。 プレフィックス合計配列を初期化する$S$と$S_0 = 0$そして$S_i = S_{i-1} + a_i$。 これにより、任意の上位セグメントの合計を計算できます。$O(1)$として$S[j] - S[i-1]$。 
2. カウンタの初期化`wins = 0`そしてポインタ`start = 0`、デッキに残っている最初のカードの位置を示します。 
3. ポインタを使用する`end`からのプレフィックス合計を反復処理します。`start + 1`まで`n`。 それぞれについて`end`、計算する`sum_segment = S[end] - S[start]`。 
4. もし`sum_segment`を超える`r`、このラウンドではこれ以上カードを受け取ることができないため、増加します`start`それまで`sum_segment <= r`または`start = end`。 すべてのカードの値が正であるため、これは有効です。 さらにカードを追加しても合計は増加するだけです。 
5. もし`sum_segment`少なくとも`l`そしてせいぜい`r`、勝利ラウンドとしてカウントされます。 インクリメント`wins`そして移動します`start`に`end`次のカードで次のラウンドを開始します。 
6. すべてのカードが処理されるまで繰り返します。 出力`wins`このテストケースでは。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`start`常に最初の未収集のカードを指します。`end`単調に成長します。 カードの値が正であるため、次の合計は`start`に`end`と増加します`end`。 2 つのポインターにより、小さすぎるセグメントまたは大きすぎるセグメントを効率的にスキップできます。 各カードは最大 2 回アクセスされます (1 回は`start`そして一度は`end`)、テスト ケースごとの線形時間を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        
        wins = 0
        start = 0
        prefix_sum = [0]*(n+1)
        for i in range(n):
            prefix_sum[i+1] = prefix_sum[i] + a[i]
        
        end = 1
        while start < n:
            while end <= n and prefix_sum[end] - prefix_sum[start] < l:
                end += 1
            if end <= n and prefix_sum[end] - prefix_sum[start] <= r:
                wins += 1
                start = end
                end = start + 1
            else:
                start += 1
                if end <= start:
                    end = start + 1
        print(wins)

if __name__ == "__main__":
    solve()
```このコードは、セグメントの合計を迅速に計算するためにプレフィックスの合計を初期化します。`start`は最初の未収集のカードをマークします。`end`合計が勝利範囲内にある最短セグメントを検索します。 インクリメントします`wins`セグメントが基準に一致して移動したとき`start`に`end`次のラウンドを開始します。 すべての値が正であるため、ネストされたループが後戻りすることはなく、各インデックスは線形に処理されます。
