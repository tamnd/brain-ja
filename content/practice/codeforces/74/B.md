 ## 解決策
 ## 問題の理解

 電車には、`n`ワゴンが並んでいます。 コントローラーは決定的に動きます。1 分ごとに現在の方向に 1 台のワゴンを歩き、どちらかの端に到達すると方向を反転します。 最初のワゴンと方向が分かれば、彼の道は完全に決まります。 

密航者の行動は、列車が走行中か駅に停車中かによって異なります。 

列車の走行中、密航者はその場に留まるか、貨車1台分を左右に移動させる可能性があります。 順序は重要です。密航者が最初に移動し、次に管制官が移動します。 管制官が移動した後、同じワゴンに乗り合わせてしまった場合、密航者は直ちに逮捕されます。 

駅で列車がアイドル状態の場合、密航者は管制官が移動する前に一時的に列車から降りる。 管制官が移動を終了した後、密航者は任意のワゴンに再乗車することができます。 この駅が終着駅の場合、最後の で表されます。`'1'`文字列にある場合、密航者は単に永久に去り、即座に勝ちます。 

入力文字列は、列車の状態を分ごとに記述します。 キャラクター`'0'`電車がその分間動いていることを意味しますが、`'1'`電車が空いていることを意味します。 最後の文字は常に`'1'`つまり、プロセスは常に最終的に終着駅に到達します。 

ターミナル駅に到着する前に管制官が密航者を必然的に捕まえられるかどうかを判断する必要があります。 コントローラーが勝った場合は、最適なプレイでキャプチャが発生した最も早い分も出力する必要があります。 

制約は小さいです。 列車には最大 50 両の貨車があり、タイムラインの長さは最大 200 です。これは、状態ベースの動的プログラミングまたはゲーム シミュレーション ソリューションが完全に実現可能であることを直ちに示唆しています。 たとえ`O(n * m)`または`O(n^2 * m)`状態の総数はわずか数千であるため、アルゴリズムはここでは非常に小さいです。 

難しいのはパフォーマンスではなく、ゲームを正しくモデリングすることです。 

簡単な間違いの 1 つは、アイドル状態の数分間に、密航者が管制官が動いた後に再入国することを忘れることです。 考慮する：```
3 1 2
to tail
1
```コントローラは、アイドル状態の 1 分間にワゴン 2 からワゴン 3 に移動します。 ここはターミナル駅なので、密航者は再入国する前に永久に退場し、すぐに勝ちます。 不用意に実装すると、最後の瞬間に密航者にワゴンの選択を誤って強制し、誤って捕獲を報告する可能性があります。 

もう 1 つの微妙なケースは、移動時間中の移動順序です。 仮定する：```
2 1 2
to head
0
```ワゴン 1 の密航者が最初に移動します。 彼は、ワゴン 2 に留まるか、ワゴン 2 に移動することができます。その後、コントローラーはワゴン 2 からワゴン 1 に移動します。密航者が留まった場合、密航者は生き残ります。 最初に移動するコントローラーを誤ってシミュレートした場合は、即時にキャプチャされると主張することになります。 

3 番目のバグの原因は、コントローラーの方向の反転です。 方向が変わるのはワゴンに入った後だけです`1`またはワゴン`n`。 例えば：```
4 2 3
to tail
0001
```コントローラーのパスは次のとおりです。```
3 -> 4 -> 3 -> 2
```ない```
3 -> 4 -> 4 -> 3
```バウンスのシミュレーションが間違っていると、到達可能な安全なワゴンが完全に変わってしまいます。 

## アプローチ

 ゲームについて考える最も直接的な方法は、完全なミニマックス検索として考えることです。 

毎分のゲーム状態は、現在の分、密航ワゴン、コントローラワゴン、およびコントローラの方向で構成されます。 このような状態から、合法的な密航の動きをすべて再帰的に試し、管制官の動きをシミュレートし、ターミナルステーションまで何らかの戦略が生き残るかどうかを判断できます。 

ゲームの長さは最大 200 分に制限されているため、この総当り再帰は概念的には正しいです。 コントローラーは各ステップで実行できる動きが 1 つだけであるため、唯一の分岐は密航者からのものです。 

それでも、生のゲームツリーは急激に成長します。 移動中の密航者には最大 3 つの選択肢があり、待機中の密航者は次のいずれかを選択できます。`n`ワゴン。 最悪の場合、考えられる履歴の数は天文学的なものになります。 

重要な観察は、コントローラーの軌道が完全に事前に決定されていることです。 最初のワゴンと方向が固定されると、コントローラーが毎分どこに立っているかを正確に事前計算できます。 

これにより、問題は 2 プレイヤーの探索から到達可能性 DP に変わります。 

分に`t`、どの密航者の位置がまだ生存可能であるかを知る必要があるだけです。 コントローラーの位置は固定されています。 タイムラインを逆方向に処理します。 

状態を定義します。```
dp[t][p] = whether the stowaway can survive starting from minute t in wagon p
```遷移はその時の列車の状態に依存します`t`。 

列車が動いている場合、密航者は次の場所に移動する可能性があります。`p-1`、`p`、 または`p+1`。 その後、管制官は次のワゴンに移動します。 コントローラーに着地するいかなる動きも禁止されています。 少なくとも 1 つの法的措置が将来の国家の勝利につながる場合、`dp[t][p]`それは本当です。 

列車がアイドル状態で終点ではない場合、密航者は管制官が動いた後に任意の貨車に再乗車することができます。 自由に選択できるため、次の 1 分間に勝っているコントローラの位置とは異なるワゴンが 1 台でも存在すれば勝利状態となります。 

現在が終着駅であれば、現在どこにいても密航者の勝ちです。 

ゲームは有限であり、一度手が選択されると決定的であるため、ブルート フォース検索は機能しますが、同じ状態を繰り返し再計算するため失敗します。 後進的な DP は多くの歴史を指数関数的に崩壊させ、`O(length * n)`州。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ミニマックス | 指数 | 指数再帰ツリー | 遅すぎる |
 | 後方DP | O(L * n²) | O(L * n) | 承認済み |

 ここ`L`train-state 文字列の長さで、最大 200 です。 

## アルゴリズムのチュートリアル

 1. コントローラーの位置を毎分事前計算します。 

店`ctrl[t]`分の移動完了後はコントローラーワゴンとして`t`。 また、現在の方向を維持し、コントローラーがワゴンに到達するたびに逆にします。`1`またはワゴン`n`。 
2. DP テーブルを作成します。`dp[t][p]`つまり、密航者は数分後からでも捕獲を回避できるということです`t`ワゴンに立ったまま`p`その瞬間の彼の行動の前に。 
3. 終端状態を初期化します。 

分ならば`t`は文字列の最後の文字であり、`'1'`、密航者はそれ以上のやり取りを行う前に列車から永久に降ります。 Every position is winning.
 4. 終わりから始まりに向かって分を逆方向に処理します。 

各状態は将来の状態にのみ依存するため、逆方向処理が機能します。 
5. アイドル時間を処理します。 

アイドル状態の 1 分間、密航者はコントローラーが移動する前に消え、その後任意のワゴンに再侵入する可能性があります。 So after the controller moves to`ctrl[t]`, 密航者はそのワゴン以外のワゴンを選ぶことができます。 

少なくともワゴンが1台あれば`q != ctrl[t]`満足する`dp[t+1][q]`そうすると、現在のワゴンはすべて勝者になります。 
6. 移動中の議事録を処理します。 

ワゴンから`p`、密航者はに移動する可能性があります`p-1`、`p`、 または`p+1`あのワゴンがあったら。 

密航移動後、コントローラーは次の場所に移動します。`ctrl[t]`。 以下に等しい候補ワゴン`ctrl[t]`は即時キャプチャを意味するため、スキップする必要があります。 

合法的な次期ワゴンも満足するなら`dp[t+1][next_pos]`、 それから`dp[t][p] = True`。 
7. テーブルを埋めたら、最初の密航ワゴンを確認します。 

もし`dp[0][m]`それは本当です、印刷します`"Stowaway"`。 
8. それ以外の場合は、独自の最適な再生長さをシミュレートします。 

必然的に管制官が勝つため、密航者は生存時間を最大化する動きを選択します。 同じ遷移を使用して、最新のキャプチャ分を再帰的に計算します。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。```
dp[t][p] is true exactly when the stowaway has a strategy to avoid capture from that state onward.
```逆帰納法により正確さが保証されます。 密航者は永久に出発するため、終着駅では答えは自明の理です。 以前のすべての状態は、すでに正しい将来の状態からのみ評価されます。 

移動中の数分間、密航者は、即時の衝突を回避し、別の生存可能な状態につながる少なくとも 1 つの合法的な動きが存在する場合にのみ生存します。 

アイドル状態の間、密航者はコントローラーの動きを観察した後に任意のワゴンを選択できるため、少なくとも 1 つの安全なワゴンがその後も生存可能であれば、状態は存続可能です。 

考えられるすべてのアクションがゲーム ルールに従って正確に考慮されるため、DP は最適なプレイを正確に特徴付けます。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    direction_line = input().strip()
    s = input().strip()

    L = len(s)

    direction = -1 if direction_line == "to head" else 1

    ctrl = [0] * L

    pos = k
    d = direction

    for i in range(L):
        pos += d

        if pos == 1:
            d = 1
        elif pos == n:
            d = -1

        ctrl[i] = pos

    dp = [[False] * (n + 1) for _ in range(L + 1)]

    for p in range(1, n + 1):
        dp[L][p] = True

    for t in range(L - 1, -1, -1):
        if s[t] == '1':
            if t == L - 1:
                for p in range(1, n + 1):
                    dp[t][p] = True
            else:
                exists = False

                for q in range(1, n + 1):
                    if q != ctrl[t] and dp[t + 1][q]:
                        exists = True
                        break

                for p in range(1, n + 1):
                    dp[t][p] = exists
        else:
            for p in range(1, n + 1):
                ok = False

                for np in (p - 1, p, p + 1):
                    if not (1 <= np <= n):
                        continue

                    if np == ctrl[t]:
                        continue

                    if dp[t + 1][np]:
                        ok = True
                        break

                dp[t][p] = ok

    if dp[0][m]:
        print("Stowaway")
        return

    @lru_cache(None)
    def latest_capture(t, p):
        if s[t] == '1':
            if t == L - 1:
                return float('-inf')

            best = -1

            for q in range(1, n + 1):
                if q == ctrl[t]:
                    continue

                if dp[t + 1][q]:
                    best = max(best, latest_capture(t + 1, q))

            return best

        best = -1

        for np in (p - 1, p, p + 1):
            if not (1 <= np <= n):
                continue

            if np == ctrl[t]:
                best = max(best, t + 1)
                continue

            if dp[t + 1][np]:
                best = max(best, latest_capture(t + 1, np))
            else:
                best = max(best, t + 1)

        return best

    ans = latest_capture(0, m)

    print("Controller", ans)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、コントローラーの軌道を事前計算します。 終点の貨車に入って初めて方向が反転するため、間違いやすいです。 

すべての状態は将来の分のみに依存するため、DP テーブルでは後方評価が使用されます。 余分な行`dp[L]`タイムラインが終了した後、ダミーの正常終了状態として機能します。 

アイドル状態からの移行は微妙です。 密航者はコントローラーが動く前に姿を消すので、以前のワゴンは無関係になります。 だからこそ、すべての`dp[t][p]`アイドル時間中に同じ値を受け取ります。 

移動分の移行では、3 つの可能なアクションすべてがチェックされます。 キャプチャはコントローラーの移動後に行われるため、候補となるワゴンは次のとおりです。`ctrl[t]`すぐに負けてしまいます。 

生存が可能かどうかを判断した後、2 番目の DFS は最適な遅延プレイの下で可能な最新のキャプチャ時間を計算します。 管制官のパスは決定的であるため、密航者は捕獲時間を最大化するだけです。

4 1 3
to tail
0001
```コントローラーのパスは次のようになります。```
3 -> 4 -> 3 -> 2
```反転は貨車 4 に入った直後に起こります。 

前処理ループは、次の時点で方向を正確に更新します。`pos == 1`または`pos == n`、したがって、生成された軌道はルールに正確に一致します。
