 **評価:** 1000
 **タグ:** 実装
 **解決時間:** 1 分 35 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 Codeforces ルームのすべての参加者のスコアボード データが提供されます。 各参加者には、ハンドル、成功したハッキングの数、失敗したハッキングの数、および問題 A ～ E で獲得したポイントが与えられます。 

1 人の参加者の合計スコアは次のように計算されます。 

- the sum of the five problem scores,
 - プラス`100 × successful_hacks`、
 - マイナス`50 × unsuccessful_hacks`。 

私たちのタスクは、どの参加者が最高の最終スコアを持っているかを判断し、そのハンドルを出力することだけです。 

制約は非常に小さいです。 参加者は最大 50 人で、各参加者は一定量の情報しか持っていません。 非効率な解決策であっても、制限時間内に問題なく収まります。 出場者を追い越すだけで十分です。 

実装上の主なリスクはアルゴリズムの複雑さではなく、スコアを正しく計算し、負の合計を適切に処理することです。 

簡単な間違いの 1 つは、ハッキングが失敗するとポイントが減点されることを忘れることです。 

例：```
2
alice 0 0 500 500 500 500 500
bob 0 10 500 500 500 500 500
```アリスは`2500`ポイント。 

ボブは持っています`2500 - 10 × 50 = 2000`。 

正しい出力は次のとおりです。```
alice
```ハッキング ペナルティを無視する不注意な実装では、Bob が同点か同等として誤って選択されてしまいます。 

もう 1 つの微妙なケースは、参加者が何も解決しなかったにもかかわらず、ハッキングの失敗によりマイナスのスコアが残った場合です。 

例：```
2
x 0 5 0 0 0 0 0
y 0 0 0 0 0 0 0
```出場者`x`もっている`-250`、 その間`y`もっている`0`。 

正しい出力は次のとおりです。```
y
```ベストスコアを次のように初期化すると、`0`安全に小さいものではなく、すべてが陰性の場合は失敗する可能性があります。 

3 番目のよくあるバグは、ハンドルが文字列であるのに対し、残りのフィールドは整数であるため、入力が誤って読み取られることです。 

例：```
1
tourist_123 1 0 500 1000 1500 2000 2500
```正しい出力は次のとおりです。```
tourist_123
```パーサーはハンドルを数値から分離しておく必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての参加者について、入力フィールドから最終スコアを計算し、それを他のすべての参加者と比較して、それが最大値であるかどうかを確認します。 

これは出場者の数が少ないため機能します。 あれば`n`参加者にとって、このアプローチのパフォーマンスはおおよそ`n²`比較。 と`n ≤ 50`、それだけです`2500`最悪の場合の比較。 

この方法の問題は、ここでのパフォーマンスではなく、不必要な作業です。 出場者のスコアを計算したら、実際には他の全員と個別に比較する必要はありません。 現在の最大値のみを考慮します。 

その観察が最適なアプローチにつながります。 参加者を 1 人ずつ読み取りながら、すぐにスコアを計算し、2 つの変数を維持します。 

- これまでに確認された最高スコア、
 - 対応するハンドル。 

新しい参加者のスコアが大きい場合は常に、両方の値を更新します。 

これにより、繰り返しの比較による作業が 1 回のリニア スキャンに軽減されます。 問題の構造上、勝者は出場者間のペアの関係ではなく、最大スコアのみに依存するため、これは自然なことです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、出場者の数。 
2. 2 つの変数を初期化します。 

-`best_score`非常に小さい数として、
 -`best_handle`空の文字列として。 

入力の処理中に現在のリーダーを追跡するには、これらの変数が必要です。 
3. 各出場者について:

 - ハンドルを読んで、
 - 成功したハッキングの数を読み取ります。 
- 失敗したハッキングの数を読み取ります。 
- 5 つの問題のスコアを読みます。 
4. 以下を使用して、出場者の合計スコアを計算します。```
total = sum(problem_scores) + 100 × successful_hacks - 50 × unsuccessful_hacks
```5. この合計スコアを次と比較します。`best_score`。 
6. 新しいスコアの方が大きい場合:

 - アップデート`best_score`、
- アップデート`best_handle`。 

これにより、出場者が処理されるたびにリーダー情報が正確に保たれます。 
7. すべての出場者が処理されたら、印刷します。`best_handle`。 

### なぜ効果があるのか

 出場者の接頭辞を処理した後、`best_score`処理されたすべての参加者間の最大スコアを保存し、`best_handle`対応するハンドルを格納します。 

最初は、まだ出場者が処理されていないため、この不変条件は true です。`best_score`可能な実際のスコアよりも小さいです。 

新しい出場者を処理する場合、可能性は 2 つだけです。 

- スコアが現在の最大値を超えていないため、リーダーは変更されません。 
- それらのスコアは大きいため、保存されているリーダーを置き換えると不変条件が true に保たれます。 

最後の出場者の後は、不変条件により、保存されたハンドルがルーム全体で最も高いスコアを持つ参加者に属することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

best_score = -10**18
best_handle = ""

for _ in range(n):
    parts = input().split()

    handle = parts[0]
    plus = int(parts[1])
    minus = int(parts[2])

    scores = list(map(int, parts[3:]))

    total = sum(scores) + plus * 100 - minus * 50

    if total > best_score:
        best_score = total
        best_handle = handle

print(best_handle)
```ソリューションはアルゴリズムに直接に従います。 

最初の重要な詳細は、入力行がどのように解析されるかです。 ハンドルは文字列であるため、別個に保存されますが、残りのフィールドは整数です。 

スコアの計算はコンテストのルールに正確に一致します。 ハッキングが成功すると追加される`100`ポイント、ハッキング失敗による減算`50`、5 つの問題のスコアが通常どおり合計されます。 

変数`best_score`の代わりに非常に小さな値に初期化されます。`0`。 これにより、すべての出場者がマイナスのスコアを持った場合のバグを回避できます。 

このソリューションでは、各参加者のスコアを計算した後すぐにリーダーを更新するため、追加の配列や並べ替えは必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    best_score = -10**18
    best_handle = ""

    for _ in range(n):
        parts = input().split()

        handle = parts[0]
        plus = int(parts[1])
        minus = int(parts[2])

        scores = list(map(int, parts[3:]))

        total = sum(scores) + plus * 100 - minus * 50

        if total > best_score:
            best_score = total
            best_handle = handle

    print(best_handle)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run(
"""5
Petr 3 1 490 920 1000 1200 0
tourist 2 0 490 950 1100 1400 0
Egor 7 0 480 900 950 0 1000
c00lH4x0R 0 10 150 0 0 0 0
some_participant 2 1 450 720 900 0 0
"""
) == "tourist", "sample 1"

# minimum-size input
assert run(
"""1
solo 0 0 0 0 0 0 0
"""
) == "solo", "single contestant"

# negative scores
assert run(
"""2
x 0 5 0 0 0 0 0
y 0 0 0 0 0 0 0
"""
) == "y", "negative totals"

# hack bonus changes winner
assert run(
"""2
alice 0 0 500 500 500 500 500
bob 3 0 500 500 500 500 500
"""
) == "bob", "successful hacks matter"

# boundary-style large values
assert run(
"""2
maxer 50 0 500 1000 1500 2000 2500
other 0 0 500 1000 1500 2000 2500
"""
) == "maxer", "large bonuses"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一の出場者 |`solo`| 最小サイズの入力 |
 | マイナススコアの場合 |`y`| 負の合計の正しい処理 |
 | 問題のスコアは同じですが、ハックは異なります |`bob`| 成功したハックは適切に追加されます。 
| 高額案件 |`maxer`| 上限スタイルの算術 |
