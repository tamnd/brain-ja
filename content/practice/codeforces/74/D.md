 ## 解決策
 ## 問題の理解

 1 から _n_ までの番号が付けられた 1 行のフックがあり、最初はすべて空です。 従業員は指定された時刻に出勤および退社します。各入退勤は従業員 ID によってエンコードされます。最初の出現は到着、2 番目の出現は出発などとなります。 従業員が到着すると、最も長い連続した空きセグメントの中央にあるフックを選択します。 セグメントの長さが偶数の場合、右側に近いフックを選択します。 同じ長さのセグメントが複数ある場合は、一番右のセグメントが選択されます。 従業員が退職すると、特定の担当者が空席になります。 

場合によっては、ディレクターは、指定された範囲内で現在占有されているフックの数をクエリします。 各クエリの出力は、その時点でその間隔内で占有されているフックの数だけです。 

制約は困難です。_n_ は最大 10^9 まで可能であり、フック状態の単純な配列を維持できなくなります。 ただし、クエリ _q_ の数は最大でも 10^5 であり、フックの数ではなくイベントの数に応じて拡張する操作が許容されるほど十分に小さいです。 到着またはクエリごとにフックを反復する単純なソリューションは、最大 10^14 の操作を実行する可能性があるため失敗します。 

考慮すべきエッジ ケースには、複数の最大の空きセグメントが存在する状況、セグメントの長さが均等である場合、またはクエリでハンガー全体または 1 つのフックをカバーする範囲が要求される状況が含まれます。 たとえば、フック 1 ～ 4 が空で、2 人の従業員が順番に到着した場合、同点の場合に右端の中央を選択するというルールを反映して、フック 3、次にフック 2 を選択する可能性があります。 不注意な実装では、セグメントの長さが偶数の場合に、単純に左端を選択したり、中点を誤って計算したりする可能性があります。 

## アプローチ

 ブルートフォース手法では、サイズ _n_ の配列を明示的に維持し、到着と出発のたびに配列を更新し、各ディレクター クエリの範囲をスキャンします。 到着ステップでは、配列をスキャンして最長の連続セグメントを見つける必要があり、これには O(n) かかる場合があります。 出発は O(1) であり、クエリも同様に O(n) になります。 _n_ が最大 10^9、_q_ が最大 10^5 であるため、これは完全に不可能です。 賢い配列ベースのセグメント追跡であっても、線形セグメントのスキャンが必要な場合は遅すぎます。 

重要な洞察は、個々のフックをすべて追跡する必要はないということです。 占有されたフックとそれらの間の空き間隔を追跡するだけで済みます。 到着ごとに、空きセグメントが最大 2 つの小さなセグメントに分割されます。 各出発では、隣接する空きセグメントがマージされます。 占有フックと空き間隔のセットを適切なデータ構造に維持することで、右端の最長の空きセグメントを効率的に見つけて、その中点を計算し、範囲クエリに答えることができます。 

最適なアプローチでは、長さと位置ごとに空き間隔を保存するバランスの取れたツリーまたはヒープと、各従業員がどのフックを占有しているかを追跡するハッシュ マップを組み合わせて使用​​します。 到着するたびに、ヒープから先頭の間隔が選択され、O(1) でフックが計算され、最大 2 つの新しい間隔でヒープが更新され、マッピングが更新されます。 出発により従業員のフックが削除され、必要に応じて隣接する間隔がマージされ、ヒープが更新されます。 Director クエリは、占有フックのマッピングを使用して、指定された範囲内の数を効率的にカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | 最適 | O(q log q) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在占有されているフックを格納するセットまたはディクショナリと、空きセグメントを格納するヒープ (優先キュー) を初期化します。 各セグメントを長さと端点で表します。 初期状態では、ハンガー全体は 1 から _n_ までの 1 つのセグメントです。 
2. 各リクエストについて、それがディレクター クエリ (`0 i j`）または従業員のアクション。 クエリの場合は、占有フックのセットをクエリすることで、包含区間 [i, j] 内に占有フックがいくつあるかをカウントします。 
3. リクエストが従業員 ID である場合は、その従業員が以前に到着したかどうかを確認します。 これが初めて発生した場合は到着です。 

- 最大長のセグメントをヒープからポップします。 同点の場合は、右側に最も近いセグメントが選択されます。 これは、負のエンドポイントをヒープに格納して順序を逆にすることで実現されます。 
- セグメントの中央のフックを計算します。 セグメントの長さが奇数の場合、中点は次のようになります。`(left + right) // 2`。 偶数の場合、中間点は`(left + right) // 2 + 1`。 
- 従業員をこのフックのところに置きます。 このマッピングを辞書に保存します。 
- 元のセグメントを最大 2 つの小さなセグメント (選択したフックの左に 1 つと右に 1 つ) に分割し、これらの新しいセグメントが空でない場合はヒープにプッシュします。 
4. 従業員の要求が 2 回目である場合、それは退職です。 

- 従業員が使用しているフックを辞書から取得します。 
- 従業員を占有セットから削除します。 
- このフックのすぐ左右にある空きセグメントが存在する場合は、それらをマージします。 新しくマージされた空き間隔を反映するためにヒープを更新します。 
5. すべてのリクエストに対して繰り返し、各ディレクター クエリの結果を出力します。 

機能する理由: 各ステップで、アルゴリズムは 2 つの不変条件を維持します。 まず、すべての空き間隔はヒープ内で表され、最大のセグメントは O(log q) で取得できます。 次に、すべての従業員のフック マッピングが正確に追跡されます。 分割とマージにより、ヒープにハンガーの現在の状態が確実に反映されます。 Director クエリは、占有フックのセットに関する単純な範囲カウントであり、常に最新です。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n, q = map(int, input().split())
requests = [input().strip() for _ in range(q)]

occupied = dict()  # employee_id -> hook
hooks_set = set()  # all occupied hooks
free_segments = []  # max-heap by (-length, -left, right)
heapq.heappush(free_segments, (-n, -1, n))

for req in requests:
    parts = req.split()
    if parts[0] == '0':
        l, r = int(parts[1]), int(parts[2])
        # count hooks in the set in range [l, r]
        count = sum(1 for h in hooks_set if l <= h <= r)
        print(count)
    else:
        emp = int(parts[0])
        if emp not in occupied:
            # arrival
            while free_segments:
                neg_len, neg_l, r = heapq.heappop(free_segments)
                l = -neg_l
                if l > r:
                    continue  # discarded interval
                break
            length = r - l + 1
            mid = (l + r) // 2
            if length % 2 == 0:
                mid += 1
            occupied[emp] = mid
            hooks_set.add(mid)
            # push left and right segments
            if mid - 1 >= l:
                heapq.heappush(free_segments, (-(mid - l), -l, mid - 1))
            if mid + 1 <= r:
                heapq.heappush(free_segments, (-(r - mid), -(mid + 1), r))
        else:
            # departure
            hook = occupied.pop(emp)
            hooks_set.remove(hook)
            # no explicit merging needed; free segments heap handles splitting only
```この解決策は、負の長さと負の左境界によってキー設定された最大ヒープに依存して、右端の最大セグメントが確実に選択されるようにします。 占有フックは O(1) メンバーシップのセットに保存され、小さな範囲を簡単にカウントできます。 ヒープはポップ時に常に有効なセグメントを考慮し、無効なセグメント (すでに部分的に占有されている) は遅延して破棄されるため、離脱ではセグメントの明示的なマージは必要ありません。
