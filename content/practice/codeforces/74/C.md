 ## 解決策
 ## 問題の理解

 私たちは、`n × m`チェス盤。 ビリヤードのボールはビショップのように斜めに動きますが、ビショップとは異なり、ボードの境界線に反射します。 垂直の壁にぶつかると、方向の水平成分が反転します。 水平の壁にぶつかると、垂直成分が反転します。 コーナーに当たると両方が反転します。 

2 つのボールは、その無限の反射運動中に、一方が他方の占有している正方形を最終的に通過できた場合、互いに攻撃します。 選択した 2 つの正方形が同じビリヤード軌道上に存在しないように、可能な限り最大の正方形のセットが必要です。 

核心的な質問は、まさにこれです。ボード上には、個別の動作コンポーネントがいくつ存在するのでしょうか? 同じコンポーネント内のすべての正方形は、そのコンポーネント内の他のすべての正方形を攻撃するため、コンポーネントごとに最大 1 つのボールを配置できます。 すべてのコンポーネントには少なくとも 1 つの正方形が含まれるため、答えは正確に接続された軌跡の数になります。 

ボードの寸法は最大です`10^6`。 これにより、すべてのマス目に触れるものは即座に排除されます。 たとえ`O(nm)`トラバースには次までの処理が必要になります`10^12`2秒以内には不可能です。 ソリューションでは算術のみを使用する必要があります。`n`そして`m`、理想的には対数または定数時間です。 

難しいのは、反射が実際に何をするのかを理解することです。 素朴な解釈では、この動きを複雑な跳ね返りとして扱うかもしれませんが、幾何学的には、パスは無限にタイル状に並べられたボード上の直線の対角線のように動作します。 この変換を怠ると、問題が実際よりもはるかに難しく見えるようになります。 

見落としやすいエッジケースがいくつかあります。 

正方形のボードを考えてみましょう。```
4 4
```正しい答えは、`4`、 ない`1`。 不注意な議論では、すべての対角線が最終的には他のすべての対角線に反映されると言われるかもしれませんが、パリティ制限によりそれが妨げられます。 モーションはいくつかの独立したサイクルに分解されます。 

次に、次のことを考えてみましょう。```
2 3
```答えは`1`。 以来`gcd(1, 2) = 1`、すべての正方形は単一の軌道に属します。 通常のビショップ対角線を個別にカウントするアプローチでは、過剰にカウントされてしまいます。 

別の微妙なケースは次のとおりです。```
2 2
```答えは`2`。 ボードには 4 つのセルしかありませんが、軌道は 2 つの切り離されたグループに分割されます。 小さなボードではパリティの間違いがすぐに明らかになります。 

## アプローチ

 ブルートフォースアプローチでは、移動グラフを明示的に構築します。 各正方形には、最大 4 つの出射反射対角方向があります。 すべてのセルから、ビリヤードの可能なすべての動きをシミュレートし、到達可能なセルをマークし、連結成分を計算できます。 

「攻撃できる」という関係はまさにグラフの接続性であるため、これは概念的に機能します。 2 つのセルが同じ連結コンポーネント内にある場合、一方のビリヤードの軌道は他方の軌道に到達します。 

問題は規模だ。 ボードには以下が含まれる場合があります`10^12`正方形。 1 平方あたり 1 ビットを格納することすら不可能です。 セルを横断すると、メモリ制限と時間制限の両方が直ちに満たされなくなります。 

重要な観察は、反射が展開される可能性があるということです。 

境界線で方向を反映するのではなく、ボード自体を反映することを想像してください。 次に、ビリヤードのパスは、無限にミラーリングされたボードのコピーを通る直線の対角線になります。 これはビリヤードの標準的な展開トリックです。 

一度展開すると、あらゆる動きは傾斜線に沿って進みます`+1`または`-1`。 重要な不変量は、特定の周期性を法とした座標の値になります。 反射がどのようにセルを接続するかを分析した後、ボード全体が正確に次のように分割されます。$$\gcd(n-1, m-1) + 1$$独立した軌道。 

その公式がすべての解決策です。 

なぜそうなるのか`n-1`そして`m-1`の代わりに現れる`n`そして`m`? 反射は行と列の境界で発生するためです。 展開された動きの効果的な周期性は、境界間の距離によって決まります。`n-1`垂直方向と`m-1`水平方向に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(nm) | 遅すぎる |
 | 最適 | O(log(min(n,m))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. コンピューティング`g = gcd(n - 1, m - 1)`。 

展開する軌跡は繰り返す`n - 1`垂直ステップと`m - 1`水平ステップ。 それらの相互作用は最大公約数によって決まります。 
3. 出力`g + 1`。 

各剰余クラスは 1 つの独立したビリヤード軌道を形成します。 このようなクラスの数は、gcd よりちょうど 1 つ多いことがわかります。 

### なぜ効果があるのか

 反射されたボードを無限に多くの鏡面コピーに展開します。 ビリヤードの軌道は真っ直ぐな対角線になります。 

2 つのセルは、展開された座標が同じ無限対角線上に揃っている場合、正確に同じ軌跡に属します。 周期構造は毎回繰り返されます`2(n-1)`垂直方向と`2(m-1)`水平方向、および個別の対角サイクルの数は、これらの周期がどのように同期するかによって決まります。 

同期数は`gcd(n-1, m-1)`。 これらのサイクルはボードを次のように分割します。`gcd(n-1, m-1) + 1`等価クラス。 1 つのクラス内のすべてのセルは、そのクラス内の他のすべてのセルを攻撃するため、クラスごとに最大 1 つのボールを配置することができ、クラスごとに 1 つのボールを配置することは常に可能です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

n, m = map(int, input().split())

print(gcd(n - 1, m - 1) + 1)
```すべての重労働は数学的リダクションで行われるため、実装は意図的に小さくなっています。 

gcd を取得する前に、両方の次元から 1 を減算します。 ここは間違いが最も起こりやすい場所です。 ビリヤードの反射は、セル自体の数ではなく、境界間の距離に依存します。 

Pythonの組み込み`math.gcd`ユークリッド アルゴリズムを使用してすでに対数時間で実行されているため、最大の値を簡単に処理できます。`10^6`。 

決勝戦`+1`軌道パーティションの構造に由来します。 それを忘れると、すべての場合において一貫して 1 が小さすぎる答えが生成されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    print(gcd(n - 1, m - 1) + 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 4\n") == "2\n", "sample 1"

# minimum board
assert run("2 2\n") == "2\n", "minimum size"

# coprime dimensions
assert run("2 3\n") == "1\n", "coprime periods"

# square board
assert run("5 5\n") == "5\n", "equal dimensions"

# large values
assert run("1000000 1000000\n") == "1000000\n", "maximum equal values"

# off-by-one trap
assert run("4 7\n") == "1\n", "gcd(3,6)=3 so answer should be 4"

 ## 特殊なケース

 次のことを考慮してください。```
2 2
```アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | n - 1 | 1 |
 | m - 1 | 1 |
 | gcd | 1 |
 | 答え | 2 |

 このような小さな基板では反射が頻繁に発生するため、素朴なアプローチでは、4 つのセルすべてが 1 つの軌道に属していると推測する可能性があります。 実際には 2 つの独立したサイクルに分かれます。 

次に、次のことを調べます。```
2 3
```計算は次のようになります。 

| 数量 | 値 |
 | --- | --- |
 | n - 1 | 1 |
 | m - 1 | 2 |
 | gcd | 1 |
 | 答え | 2 |

 このケースでは、誤って使用する実装が捕捉されます。`gcd(n, m)`の代わりに`gcd(n-1, m-1)`。 間違った式を使用すると、次のような結果が得られます`gcd(2,3)+1 = 2`、ここでは偶然一致しますが、他の場所では失敗します。 

より良い反例は次のとおりです。```
4 7
```正しい計算:

 | 数量 | 値 |
 | --- | --- |
 | n - 1 | 3 |
 | m - 1 | 6 |
 | gcd | 3 |
 | 答え | 4 |

 使用する`gcd(4,7)+1`誤って生成してしまう`2`。 これは、この問題における古典的な落とし穴です。
