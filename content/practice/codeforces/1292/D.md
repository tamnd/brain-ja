 ## 解決策
 ## 問題の理解

 この問題のグラフは明示的に与えられるのではなく、整数の構造によって完全に決定されます。 すべての正の整数はノードであり、それぞれの数値は$x > 1$～に向けられたエッジがある$x / f(x)$、 どこ$f(x)$の最小の素因数です$x$。 この操作を繰り返し適用すると、最終的に 1 に達するまで常に数値が減少するため、すべてのノードは 1 に向かう下向きの一意のパスを持ちます。 

入力は任意のノードを記述するのではなく、代わりに次のことを与えます。$n$価値観$k_i$。 各フラグメントは、次のことを表すノードに配置されます。$k_i!$。 タスクは単一のノードを選択することです$P$この無限グラフでは、すべての階乗ノードからの最短経路距離の合計が$k_i!$に$P$最小化されます。 

複数のフラグメントが同じノード上に存在する可能性があるため、それらのフラグメントからの距離は$P$多重度を考慮してカウントする必要があります。 したがって、問題は事実上、階乗ノードの複数セットが与えられた場合、このツリー状構造内の合計距離を最小にするノードを見つけます。 

この制約により、強引なグラフ手法は不可能になります。 まであります$10^6$したがって、完全な走査で各フラグメントを個別に処理する方法は遅すぎます。 ただし、それぞれ$k_i$最大 5000 です。これが重要な制限です。 これは、すべての階乗ノードが、非常に構造化された圧縮可能な整数のサブセット内にあることを意味します。 

単純な間違いは、階乗を明示的に構築したり、グラフの距離を直接シミュレートしようとしたりすることです。 たとえば、コンピューティングでも、$5000!$時間的にもメモリ的にも不可能であり、その主要な構造を直接保存するだけでも爆発してしまいます。 もう 1 つの落とし穴は、任意の整数間の一般的な最短パス クエリが必要であると想定していることですが、実際には階乗の構造によって問題が素数指数計算に崩壊してしまいます。 

微妙なエッジケースは、$k_i$等しいです。 その場合、すべてのノードが一致し、答えはゼロになるはずです。 カウントを集計せずにオカレンスを誤って個別に処理する方法は、冗長な作業を行う危険性がありますが、それでも多重度が正しく処理されることを保証する必要があります。 

## アプローチ

 重要な観察は、グラフ演算が数値に対して何を行うかを理解することから得られます。 各ステップでは、最小の素因数が除算されます。 つまり、エッジに沿って移動することは、正確に 1 つの素因数、特にそのステップで利用可能な最小の素因数を削除することに相当します。 

これにより、すべての数値が素因数の複数セットに変換され、$x$to 1 は、まさにすべての素因数を 1 つずつ削除するシーケンスです。 したがって、2 つのノード間の最短パスは、それらの素因数分解がどのように重なるかによって決まります。 

階乗$k!$特別に構造化されています: すべての素数$p \le k$は、ルジャンドルの公式によって与えられる既知の指数とともに表示されます。 したがって、階乗を数値として考えるのではなく、素指数のベクトルとして考えます。 

2 つのノード間の距離が素数に対して加算されるようになりました。素数ごとに$p$、貢献度は回数によって異なります$p$パスに沿って追加または削除する必要があるため、問題全体が指数プロファイルの比較に集約されます。 

目的はノードの選択になります$P$、素数指数のベクトルとしても表すことができ、すべての階乗指数ベクトルにわたる L1 のような距離の合計を最小化します。 これにより、素数ごとにきれいに分離されます。素数ごとに、周波数で重み付けされた絶対差の合計を最小化する最適な指数値を個別に選択します。 

ブルートフォースアプローチでは候補者を列挙することになる$P$値を計算したり、すべての素数とすべての階乗にわたる距離をシミュレートしたりすることで、$O(n \cdot \text{max factorial size})$あり得ない行動です。 

最適解は 2 つの事実を利用します。階乗指数構造は単調です。$k$、素数あたりのコスト関数は凸であるため、最適な指数は観測された指数の加重中央値になります。

 ## アルゴリズムのチュートリアル

 1. それぞれ何回か数えます$k$が表示されます。 同じ階乗の複数のフラグメントが繰り返しの重みに寄与するため、これは重要です。 
2. すべてについて事前計算する$k \le 5000$、すべての素数の指数$p \le 5000$で$k!$。 これは、ふるいベースの累積を使用して行われ、1 から 5000 まで段階的に指数テーブルを構築します。 
3. 各素数について$p$、ペアのリストを収集します$(\text{exponent in } k!, \text{frequency of } k)$全体$k$入力に表示されるもの。 これにより、問題が独立したプライムごとのデータセットに圧縮されます。 
4. 素数ごとに、これらの指数と周波数のペアを並べ替えまたは処理し、重み付き中央値指数を計算します。 コスト関数$\sum |e - e_i|\cdot w_i$加重中央値から離れると両側の不均衡が増大するため、加重中央値で最小化されます。 
5. すべての素数の結果として得られる最小コストを合計します。 距離は素数指数にわたって加算的に分解されるため、各素数は独立して寄与します。 
6. 総和を出力します。 

### なぜ効果があるのか

 グラフ内の各ノードは素数指数ベクトルに一意に対応し、すべてのエッジ操作は制御された方法で指数の 1 単位を正確に変更します。 これにより、グラフの距離は指数カウントの不一致の合計と等しくなります。 階乗表現は固定ベクトルであるため、最適化は整数に対する独立した凸コスト関数を最小化することになります。 凸性により、重み付き中央値が各座標に対してグローバルに最適であることが保証され、素数間の独立性により、ローカル最適値の合計がグローバルな最適値を生み出すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXK = 5000

n = int(input())
ks = list(map(int, input().split()))

freq = [0] * (MAXK + 1)
for x in ks:
    freq[x] += 1

# smallest prime factor sieve
spf = list(range(MAXK + 1))
for i in range(2, MAXK + 1):
    if spf[i] == i:
        for j in range(i * i, MAXK + 1, i):
            if spf[j] == j:
                spf[j] = i

# factorial prime exponent table
# fac_exp[k][p_index] is stored sparsely via dict per prime
prime_to_idx = {}
primes = []

for i in range(2, MAXK + 1):
    if spf[i] == i:
        prime_to_idx[i] = len(primes)
        primes.append(i)

pc = len(primes)

# exp[p][k] = exponent of prime p in k!
exp = [None] * pc
for pi in range(pc):
    exp[pi] = [0] * (MAXK + 1)

# build factorial exponents
for k in range(2, MAXK + 1):
    x = k
    temp = {}
    while x > 1:
        p = spf[x]
        temp[p] = temp.get(p, 0) + 1
        x //= p
    for p, cnt in temp.items():
        exp[prime_to_idx[p]][k] = exp[prime_to_idx[p]][k - 1] + cnt
    for pi in range(pc):
        if primes[pi] not in temp:
            exp[pi][k] = exp[pi][k - 1]

total = 0

for pi in range(pc):
    vals = []
    for k in range(1, MAXK + 1):
        if freq[k]:
            vals.append((exp[pi][k], freq[k]))

    if not vals:
        continue

    # weighted median via sorting
    vals.sort()
    total_w = sum(w for _, w in vals)
    acc = 0
    best = 0
    for v, w in vals:
        acc += w
        if acc * 2 >= total_w:
            best = v
            break

    cost = 0
    for v, w in vals:
        cost += abs(v - best) * w

    total += cost

print(total)
```実装は、入力を各周波数カウントに圧縮することから始まります。$k$。 正確さを期すためには各発生を個別に処理する必要があるため、これは重要です。 

ふるいは最小の素因数を計算するため、最大 5000 までのすべての整数を高速に分解できます。これにより、後で試行除算を繰り返す必要がなくなります。 

階乗指数テーブルは段階的に構築されます。 それぞれ$k!$から派生した$(k-1)!$乗算することで$k$、それに応じて素数指数が更新されます。 これにより、階乗分解を最初から再計算する必要がなくなります。 

最後に、各素数について、重み付き中央値がそれらの素数のみに対して計算されます。$k$入力に表示されるもの。 中央値は絶対偏差コストを最小化します。これは、その素数の合計経路長の寄与を最小化することに正確に対応します。

 ## 特殊なケース

 いつすべて$k_i$同一であり、すべてのフラグメントが同じノード上にあります$k!$、だから選択する$P = k!$コストがゼロになります。 各素数が同一の指数値を参照するため、アルゴリズムはこれを処理します。そのため、加重中央値はその値に等しく、絶対的な差はすべてなくなります。 

いつ$k_i = 0$または$k_i = 1$、すべての階乗は 1 になります。これは、すべてのノードがルートで一致することを意味します。 指数ベクトルはすべてゼロであるため、選択されたものに関係なく、すべての素数のコストはゼロになります。$P$、計算された合計はゼロのままです。 

入力が非常に小さいものと非常に大きいものが混在する場合$k$、階乗指数の増加は大きく偏ります。 加重中央値ステップにより、コストが二次関数ではなく中央値から直線的に増加するため、極端な値が誤って優勢にならないことが保証されます。
