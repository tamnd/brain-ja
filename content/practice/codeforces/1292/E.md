 ## 解決策
 ## 問題の理解

 最大 50 の長さの隠し文字列を再構築しようとしています。この文字列では、C、H、O の 3 つの記号のみが使用されることが保証されています。情報を取得する唯一の方法は、部分文字列クエリ メカニズムを使用することです。パターン文字列を送信すると、隠し文字列内でそれが出現するすべての位置が通知されます。 

各クエリには長さの二乗に応じたコストがかかるため、長いクエリは非常に高価ですが、非常に短いクエリは比較的安価です。 利用可能な総予算は固定されており小さいため、クエリごとに最大限の情報を抽出し、冗長な調査を回避する必要があります。 

この対話は決定的で非適応的です。つまり、非表示の文字列はクエリ中に変更されません。 私たちの目標は、慎重に選択された少数の部分文字列クエリを使用して正確に再構築することです。 

重要な制約は、文字列の長さが小さいことですが、クエリのコストにより、すべての部分文字列に対するブルート フォース攻撃や大規模なパターンの繰り返しテストが抑制されます。 本当の難しさは、クエリを最小限に抑えながら、可能なすべての構成を 3 進アルファベットで区別することです。 

単純なアプローチでは、重複を繰り返しクエリしながら、すべての部分文字列をテストするか、文字列を 1 文字ずつ拡大しようとします。 これは、長いクエリを繰り返すとすぐにエネルギー バジェットを超え、中程度の冗長性であっても、多くのテスト ケースにわたって蓄積されると致命的になるため、失敗します。 

グローバルな整合性チェックを行わずに貪欲な拡張機能を使用すると、微妙な失敗のケースが発生します。 たとえば、1 文字を追加して文字列を左から右に構築し、毎回プレフィックス全体をクエリすると、クエリの動作が 2 次またはさらに悪くなる可能性があります。 n が小さい場合でも、この戦略は複数のテスト ケースにわたって厳密なエネルギー制約を超える可能性があります。 

もう 1 つの失敗モードは、単一文字または非常に短い部分文字列のクエリのみに依存している場合です。 安価ではありますが、C、H、O 分布は同一の周波数プロファイルを生成する可能性がありますが、構造が異なるため、順序付けの明確化はできません。 

## アプローチ

 ブルートフォースの考え方は、すべての可能な候補文字列またはすべての可能な拡張子を繰り返しチェックすることによって文字列を再構築することです。 {C, H, O} にわたる長さ n のすべての有効な文字列のセットを維持し、部分文字列クエリを使用してそれらをフィルタリングすることを想像することもできます。 各クエリでは、矛盾する候補が除外されます。 

すべてのクエリは正確な位置制約を与えるため、これは原理的には正しいです。 ただし、状態空間は 3^n であり、n = 50 の場合でも天文学的に大きくなります。枝刈りを積極的に行ったとしても、そのようなセットを維持およびフィルタリングすることは不可能です。 

重要な点は、文字列全体を直接再構築する必要がないということです。 代わりに、クエリからの重複情報を使用してローカル構造を注意深く学習し、これらのローカル部分を一貫してマージすることで、それを再構築できます。 アルファベットが小さく、n が小さいため、戦略的に選択された少数の長いクエリを許容でき、それぞれに強い位置制約が与えられます。 

中心的なアイデアは、慎重に設計されたパターンの重複クエリを利用して隣接関係を推測することです。 すべての候補をグローバルにテストする代わりに、文字間の遷移をエンコードするパターンをクエリし、位置の交差を使用して正確な配置を推定します。 これにより、問題は指数関数的な探索から、オーバーラップ構造によって導かれる小規模な決定論的再構成に軽減されます。 

最適なソリューションでは、部分文字列交差制約を通じて文字の一貫した順序を発見することで文字列を効果的に構築し、各ステップで不確実性を最大限に低減します。

 ## アルゴリズムのチュートリアル

 再構成は、慎重に選択されたパターン間の重複情報を使用して位置を段階的にロックすることに依存します。 

1. まず、単一文字 C、H、O をクエリします。これにより、隠し文字列内の各文字の完全な位置セットが得られます。 すべての位置はこれらのセットの 1 つに正確に属しているため、インデックスが 3 つのグループに分割されていることがわかります。 
2. 各文字グループを位置インデックスでソートします。 この段階では、各文字がどこに現れるかはわかっていますが、最終的な文字列の順序でそれらがどのようにインターリーブされるかはわかっていないため、これだけでは不十分です。 
3. 文字を位置に割り当てて仮の文字列を作成しますが、ペア クエリを使用して隣接性を検証します。 「CH」、「HC」、「CO」、「OC」、「HO」、「OH」などの小さな 2 文字のパターンをクエリします。 各クエリは、これらの遷移が発生する正確な開始インデックスを返します。 
4. これらの遷移位置から、連続するインデックス間の有向隣接制約を構築します。 たとえば、位置 i が「CH」の結果セットにある場合、位置 i が C の場合、位置 i+1 は H でなければならないと推測します。 
5. すべての隣接制約を結合して、インデックスの単一の線形順序付けを行います。 各位置には正確に 1 つの文字があり、制約は一貫しているため、すべての位置を通る一意のパスが形成されます。 
6. 導出された順序を使用して再構築された文字列を入力し、最終結果を出力します。 

微妙なステップは、アルファベットが小さく、すべての位置が曖昧さを避けるのに十分な制約に参加しているため、ペアごとの隣接クエリで順序を完全に決定することです。 

### なぜ効果があるのか

 長さ 2 のパターンに対する各部分文字列クエリは、非表示文字列内の連続する位置間の正確な隣接情報をエンコードします。 すべての位置は正確に 1 つの文字クラスに属し、遷移は 6 つの可能な順序ペアによって完全にカバーされるため、すべての有効な隣接ペアは確認されるか除外されます。 これにより、再構成が n 個のノードと正確に n-1 個のエッジを持つ決定論的グラフに変わります。これは、隠し文字列と一致する単一のハミルトニアン パスを形成する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(s):
    print("? " + s)
    sys.stdout.flush()
    parts = input().split()
    if not parts:
        exit()
    k = int(parts[0])
    if k == -1:
        exit()
    return list(map(int, parts[1:])) if k > 0 else []

def solve_case(n):
    pos = {c: [] for c in "CHO"}

    # Step 1: collect positions of each character
    for c in "CHO":
        res = ask(c)
        pos[c] = res

    # Step 2: build inverse mapping position -> char
    ans = [''] * (n + 1)
    for c in "CHO":
        for i in pos[c]:
            ans[i] = c

    # Step 3: deduce adjacency via pair queries
    nxt = [0] * (n + 1)

    pairs = ["CH", "HC", "CO", "OC", "HO", "OH"]
    for p in pairs:
        res = ask(p)
        a = p[0]
        b = p[1]
        for i in res:
            nxt[i] = i + 1  # position i is followed by i+1 having b

    # Step 4: find start (no incoming edge)
    indeg = [0] * (n + 2)
    for i in range(1, n + 1):
        if nxt[i]:
            indeg[nxt[i]] += 1

    start = 1
    for i in range(1, n + 1):
        if indeg[i] == 0:
            start = i
            break

    # Step 5: reconstruct string
    res = []
    cur = start
    while cur:
        res.append(ans[cur])
        cur = nxt[cur]

    print("! " + "".join(res))
    sys.stdout.flush()
    return

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```実装は、単一文字の出現をクエリしてインデックスを 3 つの文字グループに分割することから始まります。 これにより、キャラクタの位置への完全な割り当てが即座に得られます。これは、安価に入手できる可能な限り最強のグローバル情報です。 

次に、ペア クエリを使用して隣接関係を推測します。 2 文字のパターンが出現するたびに既知の遷移に対応し、位置 i を i+1 に直接接続します。 これが重要な単純化です。任意の長さのオーバーラップについて推論する代わりに、問題を局所的な遷移に分解します。 

最後に、先行ノードのない一意のノードを見つけてチェーンの開始位置を特定し、構築された次のポインターを使用してトラバースします。 最後の位置を除いて、すべての位置に出力エッジが 1 つだけあるため、これにより完全な再構成が得られます。 

最もデリケートな実装の詳細は、遷移の欠落を決して想定しないようにすることです。 ペア クエリは、6 つの順序付けされたペアすべてをカバーする必要があります。そうでないと、隣接情報が不完全になり、トラバーサルが中断される可能性があります。 

## 実用的な例

 小さな非表示文字列 CCHO を考えてみましょう。 単一の文字をクエリし、仮定の構成で C が {1,2}、H が {}、O が {} の位置を受け取ります。 これから、キャラクターを位置に割り当てます。 

次に、CH などのペア クエリが {2} を返し、位置 2 の後に H が続くことを示し、その位置で CH の隣接関係が確認されます。 構築されたネクスト ポインタは、CCHO を一意に再構築するチェーンを形成します。 

| ステップ | クエリ | 応答 | 推論 |
 | --- | --- | --- | --- |
 | 1 | C | {1,2} | 位置 1、2 は C |
 | 2 | H | {3} | 位置 3 は H |
 | 3 | ああ | {4} | 位置 4 は O |
 | 4 | チ | {2} | 2→3 |
 | 5 | ほ | {3} | 3→4 |

 これにより、隣接関係の再構築によって単一の一貫したチェーンが正しく構築されたことが確認されます。 

2 番目の例は CHCO です。 同じプロセスにより、一貫した遷移 CH、HC、CO が生成され、文字が不均一に繰り返される場合でも、あいまいさのない完全な再構築が可能になります。

 ## 特殊なケース

 特殊なケースとしては、CCCCOOOO のように、文字の出現がすべて連続している場合があります。 この状況では、CH や HO などの遷移に対するペア クエリは空のセットを返しますが、同一セグメント内には内部遷移のみが存在するため、隣接関係は引き続き単一の一貫したチェーンを形成します。 

もう 1 つの特殊なケースは、CHCHCH のような交互パターンです。 ここで、すべての位置は前方制約と後方制約の両方に関与しており、各位置にはペアの一致によって決定される有効なサクセサーが 1 つだけあるため、隣接関係の再構築によって依然として一意のハミルトニアン パスが得られます。 

これらのケースは、位置間のマッピングの一意性が維持されるため、遷移がまばらな場合や繰り返しが多い場合でも、隣接関係の構築が有効なままであることを確認します。
