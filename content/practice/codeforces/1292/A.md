 ## 解決策
 ## 問題の理解

 2行が与えられます$n$-迷路を表す柱グリッド。 プレーヤーは左上のセルから開始します$(1,1)$右下のセルに到達したいと考えています$(2,n)$。 移動は直角に隣接するセル間でのみ許可されます。 最初は、すべてのセルが通過可能な地面です。 おもしろいのは、特定の細胞が溶岩になったり、地面に戻ったりする可能性があることです。$q$瞬間。 変更のたびに、溶岩を踏まずに開始から終了までのパスがまだ存在するかどうかを尋ねられます。 

言い換えれば、入力は動的な 2x を記述します。$n$各クエリがセルの状態を反転するグリッド。 出力は、各反転の直後にパスが可能であるかどうかを示す一連の「はい」または「いいえ」です。 

制約が教えてくれる$n$そして$q$と同じ大きさにすることができます$10^5$。 これは、各クエリの後にフルパス検索をシミュレートできないことを意味します。クエリごとの単純な BFS は次のようになります。$O(nq)$、潜在的に$10^{10}$これは 2 秒の制限には遅すぎます。 各クエリを一定時間またはほぼ一定時間で処理するアプローチが必要です。 

列の両方のセルが上から下への交差を完全に防ぐ方法でブロックされている場合、微妙なエッジ ケースが発生します。 たとえば、列 3 の両方のセルに溶岩がある場合、たとえ隣接する列に障害物がなくても、パスは列 3 を通過できません。 もう 1 つのエッジ ケースは、セルを切り替えて、以前は不可能だったパスのブロックを間接的に解除することです。 不注意なアプローチでは、隣接するセルとどのように相互作用するかを確認せずに、新たにブロックされたセルのみを考慮し、誤った答えが生成される可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、グリッドを 2D 配列として表し、そこから BFS を実行します。$(1,1)$各フリップの後。 BFS は、到達可能なすべてのセルを探索し、$(2,n)$に達します。 これは正しいですが、各 BFS が異なるため遅すぎます。$O(n)$そしてそこにあります$q$クエリ、それにつながる$O(nq)$、これは受け入れられません$n,q \sim 10^5$。 

より高速な解決策を実現するための重要な観察は、パスがブロックされる唯一の方法は、ある行の溶岩セルが隣接する列の反対側の行の溶岩セルと整列する場合であることに気づくことです。 言い換えれば、単一の溶岩セルがパスを脅かすのは、他の行に隣接するセルが同じく溶岩である場合のみです。 

パスをシミュレートする代わりに、競合を追跡します。「競合」は、溶岩細胞が次の位置にあるときに発生します。$(r,c)$反対側の列の列に隣接する溶岩がある$c-1$、$c$、 または$c+1$。 競合がある場合、パスはブロックされます。 アクティブな競合の数を維持する必要があるだけです。 各クエリはセルを切り替え、隣接するセルに基づいて競合数を更新します。 パスが可能かどうかを確認するということは、競合カウントがゼロかどうかを確認することになります。 このアプローチは、$O(1)$クエリごとに、時間制限内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの BFS) | O(nq) | O(n) | 遅すぎる |
 | 紛争のカウント | O(q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2x を初期化します。$n$ブール配列`lava`すべてのセルを次のように設定した場合`False`、地面を表します。 整数を初期化する`conflicts`これにより、アクティブなブロック状態の数が追跡されます。 
2. 各クエリを処理して、セルの状態を反転します。$(r,c)$。 切り替える前に、反対側の行にある隣接する 3 つの列を調べます。$c-1$、$c$、 そして$c+1$。 溶岩が含まれている場合、近隣ごとに減少します`conflicts`現在のセルが溶岩である場合 (これから削除しようとしています)、この競合はもう存在しないため、1 つずつ増えます。 
3. セルの状態を切り替えます。セルが地面にある場合は、溶岩としてマークします。 溶岩の場合は地面としてマークします。 
4. 切り替えた後、同じ 3 つの近傍を再度調べます。 反対側の列にある隣接する溶岩ごとに、増加します`conflicts`現在のセルが溶岩になっている場合は、新しい競合が作成されたため、1 ずつ増えます。 
5. もし`conflicts`がゼロの場合は「Yes」を出力し、それ以外の場合は「No」を出力します。 すべてのクエリに対して繰り返します。 

なぜ機能するのか: 不変条件は次のとおりです。`conflicts`ある行の溶岩が反対側の行の溶岩のすぐ隣にある、隣接するペアの数を正確に数えます。 競合は、プレーヤーがそのペアを横切ることができないため、パスがブロックされていることを示します。 移動は隣接するセルのみであるため、他のシナリオではパスを完全にブロックすることはできません。 カウントを増分的に維持することにより、完全なパス検索を行わずに、一定時間で各クエリに答えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
lava = [[False] * n for _ in range(2)]
conflicts = 0

for _ in range(q):
    r, c = map(int, input().split())
    r -= 1
    c -= 1
    delta = 1 if not lava[r][c] else -1
    for dc in [-1, 0, 1]:
        nc = c + dc
        if 0 <= nc < n:
            if lava[1-r][nc]:
                conflicts += delta
    lava[r][c] = not lava[r][c]
    print("Yes" if conflicts == 0 else "No")
```便宜上、0 から始まるインデックス表現を使用します。 変数`delta`セルを切り替えると競合が追加されるか削除されるかを決定します。 反対側の行にある 3 つの隣接する列をループして、`conflicts`カウント。 セルの状態と競合を更新した後、パスがブロックされているかどうかを確認します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q) | 各クエリは最大 3 つの近傍を検査し、セルを切り替えます。 |
 | スペース | O(n) | 2×n グリッドを保存します。 |

 上限について$n,q = 10^5$の場合、アルゴリズムはクエリ セットごとにおよそ 3·10^5 の操作を実行しますが、これは 2 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, q = map(int, input().split())
    lava = [[False] * n for _ in range(2)]
    conflicts = 0
    out = []
    for _ in range(q):
        r, c = map(int, input().split())
        r -= 1
        c -= 1
        delta = 1 if not lava[r][c] else -1
        for dc in [-1,0,1]:
            nc = c + dc
            if 0 <= nc < n:
                if lava[1-r][nc]:
                    conflicts += delta
        lava[r][c] = not lava[r][c]
        out.append("Yes" if conflicts==0 else "No")
    return "\n".join(out)

# provided sample
assert run("5 5\n2 3\n1 4\n2 4\n2 3\n1 4\n") == "Yes\nNo\nNo\nNo\nYes", "sample 1"

# minimum size
assert run("2 1\n1 2\n") == "Yes", "minimum size"

# maximum size, no conflicts
assert run("5 5\n1 2\n2 4\n1 3\n2 5\n1 4\n") == "Yes\nYes\nYes\nYes\nYes", "max size no conflict"

# all toggled once and back
assert run("3 6\n1 2\n2 2\n1 2\n2 2\n1 3\n2 3\n") == "Yes\nNo\nYes\nYes\nYes\nNo", "toggle twice edge"

# adjacent conflicts
assert run("4 4\n1 2\n2 1\n1 3\n2 2\n") == "Yes\nNo\nNo\nNo", "adjacent column conflict"
