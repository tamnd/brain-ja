 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、`n`それぞれが正の整数でラベル付けされた、個別のおもちゃ箱`a_i`。 ROBO は非常に具体的なアクションを複数回実行できます。1 つのボックスのラベルが他の 2 つを分割する場所にある 3 つの異なるボックスを選択し、3 番目のボックスを削除して山に置きます。 目標は、山をできるだけ大きくしたい場合に、ROBO が山に集められる個別の箱のシーケンスの数を決定することです。 いずれかの位置でボックス番号が異なる場合、2 つのシーケンスは区別されます。 

制約は控えめですが、自明ではありません。`n`は最大 60 まで、ボックス ラベルは最大 60 までです。これは、指数関数的なアプローチをすぐに示唆しています。`n`慎重に管理すれば、ほぼ実現可能です。 問題は、除去の順序が重要であるため複雑です。ボックスが山に置かれると、そのボックスはもう利用できなくなり、潜在的なシーケンスの組み合わせ爆発が発生します。 

重要なエッジ ケースは、最小のボックスが大きなボックスのペアを分割できない場合に発生します。 たとえば、入力が次の場合`3 5 7 11`, ROBOはボックスを取り除くことができないため、最大の山は空であり、それを形成する方法はまさに1つです。 常に少なくとも 1 つの有効な手が存在すると仮定する単純なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースアプローチは、すべてのトリプレットを反復して、可能なすべての一連の動きを生成することです。`(i, j, k)`ボックスの削除を再帰的にシミュレートします。 残りのボックスの状態ごとに、有効な手をすべて試してみます。 これは原理的には正しいですが、たとえ`n = 20`を超えるとシーケンスの数が爆発的に増加します。`10^6`三つ子の数は次のように増加するため、`O(n^3)`各ステップで、私たちは補うことができます`n-2`動きます。 のために`n = 60`、これはまったく手に負えません。 

重要な観察は、アクション制約が **分割 DAG** を形成しているということです。ボックスは、ボックスを分割する場合にのみ別のボックスを削除できます。 どのボックスをその後に削除できるかという観点から考えると、この問題を **ビットマスク動的プログラミング問題** としてモデル化できます。この問題では、どのボックスが既に削除されているかが状態によってエンコードされます。 なぜなら`n ≤ 60`、完全に使用することはできません。`2^n`DP ですが、約数と倍数が小さい数であることがわかります (`≤60`)、実際の組み合わせ爆発ははるかに少ないです。 具体的には、各ボックスについて、3 番目のボックスと組み合わせて他のどのボックスを削除できるかを事前に計算できます。 次に、残りのボックスに対してメモ化を使用して、山の最大サイズとそれを達成する方法の数を数えることができます。 DP 再帰は、ビットマスクで表現できる利用可能なボックスのセットで定義されます。 

最終的には、各状態の 2 つの値、つまりその状態から山に追加できるボックスの最大数と、その最大値に達するシーケンスの数を追跡するアルゴリズムが完成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n^3) | O(n) | 遅すぎる |
 | 割り算グラフを使用したビットマスク DP | O(3^n) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのボックスのラベルを前処理します。 各ボックスごとに`i`、他のどのボックスを分割できるかを決定します。 これにより、すべての候補「除数」ボックスの潜在的な除算ペアのリストが得られます。 
2. ビットマスクを使用してゲームの状態を表現します。`mask`長さの`n`、ここで、`1`はボックスがまだ利用可能であることを示します。 最初はすべてのボックスが利用可能です。 
3. 再帰的 DP 関数を定義する`dp(mask)`タプルを返す`(max_pile, ways)`残りのボックスから取得できる最大の山と、それを達成するシーケンスの数を表します。 
4. 三つ子ごとに`(i, j, k)`割り算ルールを満たすボックスの数 (`a_i`分割する`a_j`そして`a_k`)、ボックスを削除してみます`k`そして更新されたマスクを使用して再帰します`mask ^ (1 << k)`。 追加`1`再帰によって返される最大パイル サイズ。 それに応じてシーケンスの数を集計します。再帰によって現在の既知の最大値が返された場合は、カウントを増分します。 
5. それぞれの結果をメモする`mask`同じ部分問題の再計算を避けるため。 これにより、実質的な複雑さが階乗から大まかに減少します。`O(3^n)`それぞれの移動で 1 つのボックスが削除され、各ボックスはシーケンスごとに 1 回だけ削除されるためです。 
6. 最大パイル サイズとシーケンスの総数を法的に返します。`10^9 + 7`。 

なぜ機能するのか: DP の不変条件は次のとおりです。`dp(mask)`常に、残りのボックスに可能な最大の山サイズを返します。`mask`そしてそのサイズに到達するまでの方法の数。 メモ化により、同じ構成が 2 回カウントされることがなくなります。 各ステップでは、割り算の制約に従って有効な手のみが考慮されるため、カウントされるすべてのシーケンスは正当です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    div = [[] for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j and a[j] % a[i] == 0:
                div[i].append(j)
    
    from functools import lru_cache
    
    @lru_cache(None)
    def dp(mask):
        best = 0
        ways = 1
        for i in range(n):
            if not (mask & (1 << i)):
                continue
            for j in div[i]:
                if mask & (1 << j):
                    for k in div[i]:
                        if k != j and mask & (1 << k):
                            new_mask = mask ^ (1 << k)
                            sub_best, sub_ways = dp(new_mask)
                            sub_best += 1
                            if sub_best > best:
                                best = sub_best
                                ways = sub_ways
                            elif sub_best == best:
                                ways = (ways + sub_ways) % MOD
        return best, ways

    full_mask = (1 << n) - 1
    max_pile, num_ways = dp(full_mask)
    print(num_ways % MOD)

if __name__ == "__main__":
    solve()
```最初のループは、各ボックスが分割できるボックスのリストを作成します。 再帰的 DP は、すべての有効なトリプレットを反復し、3 番目のボックスを再帰的に削除します。 メモ化により、各ビットマスクが 1 回だけ計算されるようになります。 シーケンスを追加するときは特別な注意が必要です。新しい最大値が見つかった場合、カウントはリセットされます。 最大値を結ぶと、法を剰余として合計します。`10^9+7`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(3^n) | 各 DP 状態はボックスのサブセットです。 各ボックスはペアのおよそ n 個の選択肢で動きをトリガーできます。 |
 | スペース | O(2^n) | メモ化テーブルには、各サブセット マスクの結果が保存されます。 |

 のために`n ≤ 60`、有効な DP 状態の数は枝刈りによって管理可能です。すべてのボックスが他のボックスの約数になるわけではないため、分岐係数が大幅に減少します。 メモリ使用量は 256 MB 未満です。`2^60`LRU キャッシュとプルーニングのおかげで、マスクが完全に実現されることはありません。
