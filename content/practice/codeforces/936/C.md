 ## 問題の理解

 長さの文字列が与えられます$n$、文字列をサフィックスとプレフィックスに切り取る単一の操作を使用して変換することができます。 サフィックスは反転されて前に移動され、プレフィックスはその後に追加されます。 各操作は接尾辞の長さを選択することで完全に制御されます$x$、したがって、変換は一度決定的になります$x$固定されています。 

目標は、初期文字列を変換することです$s$ターゲット文字列に$t$このような操作を最大 6100 回使用するか、実行できないと判断します。 

主な難点は、各操作が単純な回転ではないことです。 The reversal of the suffix means characters do not preserve relative order in a straightforward cyclic way, so classical “rotation matching” intuition does not directly apply.

 制約は十分小さいので、$n \le 2000$、しかし操作予算は大きく、最大6100手です。 これは、ターゲットを段階的に構築する建設的な方法を強く示唆しており、各段階で文字列の一部を「修正」し、残りの部分には適度に影響を与えるだけであることが保証されています。 

単純なアイデアは、考えられるすべての操作シーケンスをシミュレートするか、文字列に対して BFS を実行することです。 状態空間のサイズが大きいため、これは直ちに実行不可能です。$26^n$、そしてポジション上の制限されたBFSでさえ爆発するでしょう。 

もう 1 つの単純なアイデアは、反転を慎重に制御せずに左から右へ貪欲に配置することです。 これは、文字を固定するためにシフトを適用すると、非ローカルな方法ですでに固定されているプレフィックスを妨害することがよくあるため、失敗します。 

次の場合、微妙なエッジケースが発生します。$s$そして$t$順列のような構造が異なるだけですが、演算のパリティにより特定の配置に到達することができません。 たとえば、サフィックスを逆にしても、任意の順列を作成することはできません。 逆変換に対する一部のパリティ制約は暗黙的です。 

したがって、正しいソリューションでは、正しいサフィックスまたはプレフィックスを徐々に「ロック」する、可逆的なローカル操作の制御されたシーケンスで文字列を構築する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、一連の操作を試して、$t$到達可能です。 各州には、$n+1$したがって、深さ 6100 までの BFS の幅は依然として指数関数的になります。これは、数ステップ後に到達可能な文字列の数がすでに膨大になるためです。 メモリ爆発のため、訪問した状態を保存することさえ不可能です。 

重要な観察は、各操作が構造化されたブロック操作のように動作することです。つまり、文字列を 2 つの部分に分割し、1 つの部分を反転し、順序を入れ替えます。 これにより、選択したサフィックスを反転しながら前面に再配置するための強力なツールが得られます。 

グローバルな再配置という観点から考える代わりに、ターゲット文字列を右から左に構築します。 各ステップで、正しい文字を文字列の末尾に配置し、二度と移動しないように「ロック」します。 反転操作は十分に柔軟であるため、いつでも目的の文字を作業セグメントの境界に持ってきて、それを分離できます。 

重要な洞察は、中間ステップで構造全体を保存する必要はなく、既に修正したサフィックスのみを保存する必要があるということです。 慎重に選択したサフィックスの抽出と再配置を繰り返すことで、制御された挿入プロセスをシミュレートできます。 

これは、要素を繰り返し選択し、それを最終位置まで回転させることによる並べ替えに似ていますが、回転が接尾辞の反転によって置き換えられ、順序も反転される点が異なります。 余分な反転は、補償の動きによって処理されます。

 ## アルゴリズムのチュートリアル

 現在の作業文字列を維持しながら、ターゲット文字列を右から左に照合することで答えを構築します。 

1. 変更可能な文字列を維持する$cur$、最初は次と等しい$s$、および操作の空のリスト。 
2. ポジションについて$i$から$n-1$まで$0$を確保したいと考えています。$cur[i] = t[i]$。 すでに一致している場合は、何もせずに続行します。 
3. 一致しない場合は、位置を特定します。$p$どこ$t[i]$現在登場しているのは$cur[0..i]$。 以前に固定された位置はそのままにしておく必要があるため、この検索は常にプレフィックスに制限されます。 
4. もし$p = i$、このインデックスの作成は完了です。 
5. それ以外の場合は、最大 2 つの操作を実行して、$p$位置を決める$i$:

 1. まず、次のコマンドでシフトを適用します。$x = n - p - 1$。 これにより、サフィックスが次から始まるように移動されます。$p+1$反転後に前に移動すると、キャラクターが効果的に所定の位置に移動します$p$コントロールされたリバースブロックでフロントに迫る。 
2. 次に、次のようにシフトを適用します。$x = n - i$、目的の文字がインデックスに配置されるように文字列を回転します。$i$前のステップで導入した反転を考慮した後。 
6. これらの操作の後、位置を概念的に扱います$i$修正済みとして保存し、二度と変更しないでください。 

各キャラクターの配置には最大でも一定数の操作が必要となるため、合計は制限内に収まります。 

### なぜ効果があるのか

 アルゴリズムは成長不変式に依存します: 反復終了後$i$、接尾辞$cur[i+1..n-1]$マッチ$t[i+1..n-1]$正確に、そして二度と邪魔されることはありません。 すべての操作は、厳密に左にあるインデックスのみを操作するように選択されます。$i$、または、固定サフィックスに対するその効果は、2 番目のシフトの構築によって中和されます。 これにより、アルゴリズムが未固定の接頭辞を完全に制御できる一方で、以前に配置された文字が安定したままになることが保証されます。 

接尾辞の反転と再配置を使用して任意の文字を所定の位置に配置でき、すでに固定された接尾辞の正確性が決して失われることがないため、解が演算範囲内に存在する場合、プロセスは常に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply(s, x):
    n = len(s)
    if x == 0:
        return s
    a = s[:n-x]
    b = s[n-x:]
    return b[::-1] + a

def solve():
    n = int(input())
    s = list(input().strip())
    t = list(input().strip())

    ops = []

    for i in range(n-1, -1, -1):
        if s[i] == t[i]:
            continue

        pos = -1
        for j in range(i+1):
            if s[j] == t[i]:
                pos = j
                break

        if pos == -1:
            print(-1)
            return

        if pos != i:
            x = n - pos - 1
            s = list(apply(s, x))
            ops.append(x)

            x = n - i
            s = list(apply(s, x))
            ops.append(x)

    if len(ops) > 6100:
        print(-1)
        return

    print(len(ops))
    print(*ops)

if __name__ == "__main__":
    solve()
```コードは現在の文字列を明示的に維持し、定義どおりにシフト演算を適用します。 ヘルパー関数は、文字列をプレフィックスとサフィックスに分割し、サフィックスを逆にして連結します。 メインループは右から左に動作するため、キャラクターがその位置に配置されると、$i$、後の反復では再び触れられることはありません。 

最初のシフトは、目的のキャラクタの領域を分離する方法で前面に引き寄せます。 2 番目のシフトにより位置合わせが復元され、文字がインデックスに正確に配置されるようになります。$i$。 操作は順番に追加され、問題に必要な正確な変換シーケンスが維持されます。 

実装の微妙な点は、常にプレフィックスのみを検索することです。$i$。 文字列全体を検索すると、すでに「修正」された文字を使用でき、不変条件が崩れます。

 ## 特殊なケース

 最小の 1 文字の場合は、到達可能性の境界を明らかにします。 もし$s = "a"$そして$t = "b"$、シフト操作は新しい文字を導入する方法で文字列を変更しないため、アルゴリズムは一致する位置が存在しない場合に失敗を正しく検出します。 

すべて等しい文字列は、アルゴリズムが不必要な操作を導入していないことをテストします。 すべての位置がすでに一致しているため、ループはシフトを実行せず、ゼロの演算を返し、既に正しい構造を決して乱さないという不変条件を維持します。 

次のような逆順の文字列$s = "dcba"$、$t = "abcd"$は、サフィックス反転が制御された部分操作を通じてグローバル反転をシミュレートする方法を示しています。 アルゴリズムはプレフィックスから文字を繰り返し選択し、正しいサフィックス境界に配置します。右から左への構築順序により、各配置はその後も安定したままになります。
