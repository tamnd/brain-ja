 ## 解決策
 ## 問題の理解

 各頂点がゲーム トークンの状態を表す有向グラフが与えられます。 トークンは固定された頂点から始まり、2 人のプレイヤーが交互に外側のエッジに沿ってトークンを動かします。 プレイヤーは、外向きのエッジがない頂点から移動すると、即座に負けます。 このゲームにはハードキャップもあります。プレイが非常に長い時間 (最大 10^6 手まで) 継続した場合、ゲームは引き分けと宣言されます。 

面白いのは、1 人のプレイヤーが眠っているため、1 人のプレイヤーがゲームの両側を効果的にコントロールできることです。 これにより、問題は標準的な交互ゲームから、最適なプレイの下で結果を推論しなければならない自己制御のウォークに変わりますが、サイクルによって強制終了が防止され、したがって引き分けが暗示されるという制約が追加されます。 

タスクは、開始頂点を 3 つの結果 (コントローラーの強制勝利、強制敗北、または無期限の終了を回避する能力による引き分け) のいずれかに分類することです。 

制約は大きく、最大 10^5 頂点と 2・10^5 エッジです。 これにより、ゲーム ツリーのシミュレーションが除外されます。 ゲーム状態に対する単純な BFS ですら不可能です。なぜなら、各頂点状態が誰のターンであるかに依存し、事実上状態が 2 倍になり、それでも指数関数的な分岐構造が残るからです。 

重要な困難はサイクルにあります。 行き止まりへのパスを見つけようとするだけの単純な DFS は、それが回避可能か強制可能かを理解せずに、あらゆるサイクルを勝ち負けの可能性があるものとして誤って扱います。 

微妙な失敗例としては、すべてのパスが最終的にサイクルにつながるグラフがあります。 たとえば、すべての頂点が 1 つのサイクルを形成している場合、単純な「行き止まりに到達できない」アプローチでは、終端頂点に到達せずに無限にプレイが継続する可能性があるため、実際には引き分けであるにもかかわらず、通過順序に応じて勝ちまたは負けと誤ってラベル付けされる可能性があります。 

## アプローチ

 強引なアイデアは、各状態をゲームの局面として扱い、可能なすべての動きシーケンスをシミュレートすることです。 頂点からすべての出力エッジを試し、その結果の状態から対戦相手が負けるかどうかを再帰的に判断します。 これは、有向グラフにおける標準のミニマックス再帰です。 

このアプローチは原則として正しいです。なぜなら、すべてのポジションは、負けポジションにつながる手が存在するかどうかに応じて勝ちか負けになるからです。 ただし、状態空間はサイクルによって爆発します。 単純な DFS は状態を無限に再検討するか、手数やパリティをエンコードする状態のメモ化を必要とするため、複雑さが大幅に増加します。 

本当の洞察とは、視点を逆転させることです。 ポジションが勝っているかどうかを尋ねる代わりに、最終状態からの逆推論を使用してポジションを分類します。 出ていくエッジのない頂点は損失状態です。 相手を敗北状態に追い込むことができる頂点はすべて勝利です。 ただし、伝播後に勝敗が証明されていない頂点は、どちらのプレイヤーも強制終了できないサイクル内に存在するか、サイクルにつながる必要があります。 

これにより、残りの発信移動のカウンターを備えた反転エッジ上のマルチソース BFS が実現します。 負けラベルと勝ちラベルを外側に伝播し、完全な伝播後に未分類のものはすべて描画領域の一部になります。 

実際の勝利パスの構築は、BFS 中に親ポインターを保存することによって行われ、終端頂点で終わる有効な強制勝利パスを再構築できるようになります。

 ## アルゴリズムのチュートリアル

 このゲームを有向グラフ上の最短勝利伝播問題として解釈します。

1. すべての終端頂点、つまり出力エッジのない頂点を特定します。 これらは、移動するプレイヤーが行動できないため、すぐにポジションを失います。 それらを負け状態として初期化します。 
2. 各エッジ u → v について、情報を v から u に効率的に伝播できるように、逆隣接リストを構築します。 これが必要なのは、終末状態から逆算して推論するためです。 
3. 配列を維持する`deg[u]`各頂点から出ていくエッジの数を保存します。 これは、各局面で「未解決」のまま残っている手の数を追跡します。 
4. 損失としてマークされたすべての終端頂点で初期化された BFS キューを実行します。 また、各頂点が勝ち、負け、または不明である状態の配列も維持します。 
5. 失われた頂点 v を処理するとき、すべての先行頂点 u を検査します。 u が v に対して有利な場合、負けている位置に移動することで強制的に勝利を得ることができます。 u を勝利としてマークし、v をパス再構築のための後継として保存します。 
6. 勝った頂点 v を処理するとき、デクリメントします。`deg[u]`それぞれの前任者 u に対して。 これは、u の選択肢の 1 つが相手の既知の勝利状態につながることを表します。 u から出るすべての手が相手の勝ち状態につながることが証明された場合 (負け子が見つからずに deg[u] がゼロになることを意味します)、u 自体が負けになります。 
7. 新しい状態が決定できなくなるまで伝播を続けます。 
8. 伝播後、開始頂点を確認します。 勝っている場合は、終端の負け頂点に到達するまで、保存されている親ポインタに従ってパスを再構築します。 
9. 勝っていないが未分類のままの場合、それは両方のプレーヤーが終了を回避できるサイクル領域の一部であるため、結果は引き分けになります。 
10. そうしないと、負けのポジションになります。 

### なぜ効果があるのか

 このアルゴリズムは、強制された結果に基づいて頂点の単調な分類を維持します。 頂点は、確定した負けの頂点に直接移動した場合にのみ勝利となり、強制移動のアドバンテージが保証されます。 頂点が負けになるのは、すべての発信手が相手の勝利がすでに証明されている位置につながった場合のみです。つまり、安全な手が残っていないことを意味します。 

完全な伝播後に分類されていない頂点は、勝ちの伝播も負けの伝播も到達できない領域に存在する必要があります。 このような頂点は必然的にサイクルまたはサイクルにのみフィードする構造に属し、そこでは遊びは最終状態に到達することなく無限に継続することができます。 これは、10^6 移動上限の下でのドローの定義と正確に一致します。 

伝播は常に解決された状態から未解決の状態に移行し、決定を覆すことは決してないため、一度割り当てられた頂点に誤ってラベルが付けられることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())

g = [[] for _ in range(n)]
rg = [[] for _ in range(n)]
deg = [0] * n

for i in range(n):
    parts = list(map(int, input().split()))
    c = parts[0]
    for v in parts[1:]:
        v -= 1
        g[i].append(v)
        rg[v].append(i)
    deg[i] = c

s = int(input()) - 1

# state: 0 unknown, 1 winning, 2 losing
state = [0] * n
parent = [-1] * n

q = deque()

# terminal nodes are losing
for i in range(n):
    if deg[i] == 0:
        state[i] = 2
        q.append(i)

while q:
    v = q.popleft()

    if state[v] == 2:
        for u in rg[v]:
            if state[u] == 0:
                state[u] = 1
                parent[u] = v
                q.append(u)
    else:
        for u in rg[v]:
            if state[u] == 0:
                deg[u] -= 1
                if deg[u] == 0:
                    state[u] = 2
                    q.append(u)

if state[s] != 1:
    if state[s] == 0:
        print("Draw")
    else:
        print("Lose")
else:
    print("Win")
    path = []
    cur = s
    while cur != -1:
        path.append(cur + 1)
        cur = parent[cur]
    print(*path)
```この解決策は、順方向および逆方向の両方の隣接リストを構築することから始まります。 すべての伝播は既知の結果からその前の結果に逆方向に進むため、反転グラフは不可欠です。 

の`deg`配列は、各ノードに対して「安全でない」ままになっている発信エッジの数を追跡します。 ノードは、そのすべての子が勝ちポジションとしてみなされた後にのみ負けになります。 

BFS キューには、ステータスがすでにわかっているノードが含まれています。 負けているノードから、先行ノードをすぐに勝ちのノードに変換します。 勝者ノードからは、先行ノードの送信オプションを 1 つ削除し、場合によっては先行ノードを負けステータスに強制します。 

親配列は、ノードが勝利した場合にのみ書き込まれ、再構築されたパスが常に有効な強制勝利移動シーケンスに従うことが保証されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]
    deg = [0] * n

    for i in range(n):
        parts = list(map(int, input().split()))
        c = parts[0]
        for v in parts[1:]:
            v -= 1
            g[i].append(v)
            rg[v].append(i)
        deg[i] = c

    s = int(input()) - 1

    state = [0] * n
    parent = [-1] * n
    from collections import deque
    q = deque()

    for i in range(n):
        if deg[i] == 0:
            state[i] = 2
            q.append(i)

    while q:
        v = q.popleft()
        if state[v] == 2:
            for u in rg[v]:
                if state[u] == 0:
                    state[u] = 1
                    parent[u] = v
                    q.append(u)
        else:
            for u in rg[v]:
                if state[u] == 0:
                    deg[u] -= 1
                    if deg[u] == 0:
                        state[u] = 2
                        q.append(u)

    if state[s] != 1:
        print("Draw" if state[s] == 0 else "Lose")
    else:
        print("Win")
        path = []
        cur = s
        while cur != -1:
            path.append(cur + 1)
            cur = parent[cur]
        print(*path)

 ## 特殊なケース

 1 → 2 → 3 → 1 などのサイクルのみで構成されるグラフでは、終端ノードは生成されません。 このアルゴリズムでは、BFS の初期化後、すべての頂点が不明な状態のままになります。 状態は最終条件から逆方向に解決できないため、分類は不完全なままとなり、引き分けとして正しく解釈されます。 

複数の発信エッジを持ち、1 つは終端ノードにつながり、他の頂点はサイクルにつながる頂点は、終端近傍を発見するとすぐに勝ちになります。 これは、負けている状態からの逆伝播が十分である理由を示しています。負けている状態への 1 回のエスケープが、他のエッジに関係なく強制的な勝利を定義します。 

シンクで終わる長いチェーンにより、伝播によって完全な勝利パスが正しく構築されます。 各先行処理は 1 回だけ解決され、親ポインターは曖昧さのない有効なシーケンスを再構築します。
