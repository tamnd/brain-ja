 ## 解決策

 ## 問題の理解

 バラのコレクションが与えられ、それぞれのバラが美しさの値と、白、オレンジ、または赤の 3 つの色のいずれかによって説明されます。 全体的な美しさを最大限に高めるには正確に k 個のバラを選択する必要がありますが、その選択は 2 つの制約に従う必要があります。 まず、赤バラと白バラが同時に入った花束を選ぶことはできません。 第二に、選ばれたバラがすべて同じ色の花束を選ぶことはできません。 

したがって、有効な花束はすべて、「オレンジのみ」、または「オレンジと赤で白は含まれない」、または「オレンジと白で赤は含まれない」のいずれかになります。 それ以外の組み合わせは禁止されています。 

タスクは、これらの制約の下で k 個の項目を選択し、それらの値の合計を最大化することです。 

制約は大きく、最大 200,000 本のバラがあります。 サブセットを列挙したり、ケースごとに最適な選択を繰り返し再計算しようとするソリューションは、非常に遅すぎます。 O(nk) や O(グループ選択ごとに n log n を何度も繰り返す) のように見えるアプローチでも、慎重に構造化しない限り危険であるため、貪欲な構造またはソートベースの構造を期待する必要があります。 

重要な構造的観察は、色の制約が固定されると、問題はフィルタリングされたリストから k 個の最大値を選択することになり、これはソートまたはソートされた配列のプレフィックス合計を維持することで自然に解決されるということです。 

切り分ける価値のある微妙なエッジケースがいくつかあります。 

失敗例の 1 つは、k がバラの総数に等しいが、すべてのバラが単一の色を共有する場合です。 たとえば:

 入力:```
3 3
5 4 1
RRR
```すべてのバラを使用する唯一の選択方法ですが、これは「すべて同じ色ではない」ルールに違反するため、答えは -1 でなければなりません。 赤と白の競合のみを強制する単純な解決策では、誤って 10 が返されます。 

別の特殊なケースは、オレンジだけでは k を埋めるのに不十分だが、有効な組み合わせが赤または白のいずれか 1 つだけで存在する場合に発生します。 たとえば、排他性の制約を強制せずに、複数の色で貪欲な選択を混合すると、共有された「全体のトップ K」戦略によって赤と白が誤って結合される可能性があります。 

最後に、最も危険な間違いは、オレンジが柔軟な橋として機能することを無視することです。 多くの不正確な解決策は、オレンジがどちらの側にも割り当てられるかを考慮せずに、許可された各グループから独立して最大の k 個を貪欲に選択するため、次善の組み合わせが生じます。 

## アプローチ

 ブルート フォース アプローチでは、サイズ k のすべての有効なサブセットが試行されます。 各サブセットについて、赤と白が混ざっていないこと、および単色ではないことを確認し、その合計を計算します。 これには、おおよそのチェックが必要です$\binom{n}{k}$n が 200,000 になる可能性があるため、n が小さい場合でもこれは実行不可能です。 

もう 1 つの単純なアイデアは、すべてのバラを美しさによって並べ替え、色の制約に違反しているかどうかを調整しながら、上位 K 個を選択しようとすることです。 これは失敗します。グローバルの上位 k には赤と白の両方が含まれる可能性があり、それを貪欲に (項目を交換することで) 修正しても最適性が保証されないためです。 

重要な観察は、制約が有効なソリューションを 3 つの構造タイプのみに分割していることです。 有効な花束は、赤 + オレンジのみ、白 + オレンジのみ、またはオレンジのみのカテゴリのいずれかに属している必要があります (ただし、「すべて同じ色」が禁止されているため、k が選択したセット全体に等しい場合、他の色がグローバルに存在しない限り、オレンジのみは許可されません)。 型を修正すると、問題はマルチセットから k 個の最大要素を選択することになります。 

オレンジ色のバラの役割は重要です。 これらは両方の有効な混合構成で使用できるため、赤互換プールと白互換プールの両方に候補として含める必要があります。 これは当然、各関連グループ内でバラをソートし、プレフィックス合計またはヒープベースの選択を使用することを示唆しています。 

以下について可能な限り最良の合計を計算します。 

1. 赤とオレンジのみを使用する
 2.白とオレンジのみを使用する

 また、選択された k 個のバラが単一の色に由来する場合も明示的に拒否します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n は k を選択) | O(k) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、バラを色に基づいて 3 つのリストに分け、各リストを美しさの降順に並べ替えます。 

1. 赤、白、オレンジの 3 つのアレイを構築します。 それぞれがその色の美しさの値を保存します。 

これにより、互換性制約をペアごとのチェックではなくセット制約として扱うことができます。 
2. 各配列を降順に並べ替えます。 

ソートにより、プレフィックスの取得が可能な最大の部分選択に対応することが保証されます。 
3. 各配列のプレフィックス合計を事前計算します。 

これにより、任意の色グループからの最良の x 要素の合計を O(1) で計算できます。 
4. 固定 k の場合、次の 2 つの方法で有効な花束を構築しようとします。 

まず、赤とオレンジの組み合わせを考えます。 私たちは、何個の赤 (i 個) を取るかを繰り返し、それから、可能であれば k - i 個のオレンジを取る必要があります。 k - i が利用可能なオレンジを超える場合、この分割はスキップされます。 

i を反復処理する理由は、オレンジが共有リソースであるため、赤色側にどれだけ移動するかを明示的に決定する必要があるためです。 
5. 同様に、白とオレンジについても同じプロセスを繰り返します。 
6. すべての有効な分割にわたる最大合計を追跡します。 1 つの色のみを選択する結果となる分割は破棄されます。 
7. 有効な分割が存在しない場合は、-1 を返します。 

重要なアイデアは、オレンジが唯一の柔軟なコンポーネントであるということです。 赤と白は共存できないため、オレンジを介してのみ交差する 2 つの独立した最適化問題を定義します。 

なぜ効果があるのか:

 最適な解では、赤または白のいずれかが存在しますが、両方が存在することはありません。 赤 (または白) の数を固定することで、使用するオレンジの数が完全に決まります。 各色の中で常に最高の美しさの要素を採用するため、プレフィックスの選択からの逸脱により合計が減少します。 これにより、赤 (または白) の数にわたる分割を列挙することで、構造的に異なるすべての最適な候補が探索されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))
    c = input().strip()

    red = []
    white = []
    orange = []

    for i in range(n):
        if c[i] == 'R':
            red.append(b[i])
        elif c[i] == 'W':
            white.append(b[i])
        else:
            orange.append(b[i])

    red.sort(reverse=True)
    white.sort(reverse=True)
    orange.sort(reverse=True)

    def prefix(arr):
        ps = [0]
        for x in arr:
            ps.append(ps[-1] + x)
        return ps

    pr = prefix(red)
    pw = prefix(white)
    po = prefix(orange)

    INF = -10**18
    ans = INF

    def try_color(main, main_pref, other):
        nonlocal ans
        m = len(main)
        o = len(other)

        for i in range(m + 1):
            j = k - i
            if j < 0 or j > o:
                continue
            if i + j != k:
                continue
            if i == k or j == k:
                continue
            ans = max(ans, main_pref[i] + prefix(other)[j])

    try_color(red, pr, orange)
    try_color(white, pw, orange)

    if ans == INF:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最初にバラを色ごとにグループ化し、最適な選択肢がプレフィックスの選択になるように各グループを並べ替えます。 ヘルパー関数はプレフィックスの合計を構築し、2 つのグループ間の固定分割を高速に計算できるようにします。 

の`try_color`関数は、原色のグループ (赤または白) とオレンジの間で k 個のピックを分配するあらゆる方法を調査します。 これは実現可能性の条件を強制し、すべての k が 1 つの色に由来する退化ケースも拒否します。これは問題の制約に違反するためです。 

最終的な答えは、両方の有効な構成の最大値です。

 ## 特殊なケース

 重大なエッジケースは、すべてのバラが単色の場合です。 アルゴリズムはこれを処理します。`try_color`呼び出しは、両方の色が表示される有効な分割を生成できず、そのままになります。`ans`変更されず、結果は -1 になります。 

k が n に非常に近い場合、別のエッジ ケースが発生します。 オレンジが存在する場合でも、「すべて同じ色ではない」という制約により、少なくとも 1 つのオレンジ以外の色が強制的に表示されます。 の`i == k`そして`j == k`チェックにより、単色の花束の選択が明示的に禁止されます。 

3 番目のエッジケースは、オレンジは豊富にあるが、価値の高いバラはすべて赤または白である場合です。 分割列挙により、より良い色のバラを除外するという犠牲を払ってオレンジを使いすぎないようにすることができます。これは、 i のすべての割り当てで自動的に接頭辞の合計が使用され、そのパーティションの最大の選択が保証されるためです。 

最後に、カラー グループの 1 つが空の場合、アルゴリズムは自然に 1 つの有効な構成に減り、もう一方のブランチが唯一の実行可能なブランチであるため、正確性は維持されます。
