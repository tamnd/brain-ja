 ## 解決策

 ## 問題の理解

 数直線上の閉じた区間の増加を維持しています。 最初は何も塗られていません。 セグメントが 1 つずつ追加され、各挿入後に、これまでに確認されたすべてのセグメントを結合した場合に、結合していない黒い領域がいくつ存在するかを知りたいと考えます。 

2 つのセグメントが重なっている場合、または 1 つの点で接触している場合でも、端点は接続されていると見なされるため、2 つのセグメントは同じ領域に寄与します。 したがって、私たちが追跡している構造は個々のセグメントではなく、重複または隣接する間隔のマージされた結合です。 

素朴なメンタル モデルは、各セグメントを線の上にペイントし、連続する黒い部分が何本存在するかを数えるというものです。 概念的には、挿入するたびに、重なっているペイント領域をマージし、個別のブロックがいくつ残っているかをカウントする必要があります。 

制約は大きく、最大 200,000 セグメント、最大 10^9 の座標です。 これにより、セグメントのセット全体を繰り返しスキャンしたり、座標上で密な配列を維持したりするソリューションは即座に除外されます。 前のすべてのセグメントとの重複をチェックする O(n^2) アプローチでも、1 秒の制限時間内で 200,000 の二乗演算を実行するのは不可能であるため、遅すぎます。 

主な問題点は、間隔が動的であり、既存のコンポーネントが任意の方法でマージされる可能性があることです。 

いくつかのエッジケースは、単純なアプローチが失敗する理由を明らかにします。 

問題の 1 つは、エンドポイントに触れるとコンポーネントがマージされることを忘れていることです。 たとえば、セグメント (1,3) と (3,5) は単一のコンポーネントを形成します。 次のような厳密な重複チェックを使用する単純な実装`l < r`の代わりに`l <= r`2 つの成分を誤ってカウントしてしまう可能性があります。 

もう 1 つの問題は、マージの二重カウントです。 すでにマージされた区間 [1,10] があり、[3,5] を挿入するとします。 単純な重複チェックでは、マージされた間隔を単一のエンティティとして慎重に扱わない限り、複数の保存されたセグメントとの重複が検出され、コンポーネント数が複数回減分される可能性があります。 

3 番目の問題は、順序の感度です。 セグメントは入力順に到着するため、増分要件を失わずにセグメントを並べ替えたり、毎回すべてを再計算したりすることはできません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。マージされた非結合区間の現在のリストを維持します。 新しいセグメントごとに、既存のすべての間隔をスキャンし、交差または接触する間隔をマージし、それらを削除して、結果のマージされた間隔を挿入します。 答えは単純に、保存されている間隔の数です。 

これは、不変条件が明示的であるため、正しいです。常に、結合されていない、完全にマージされた和集合表現を保存します。 ただし、挿入ごとに既存のすべての間隔をスキャンする必要がある場合があり、最悪の場合、各間隔が他の多くの間隔と重なったり、線形スキャンを繰り返したりする必要があります。 新しいセグメントごとに O(n) 個の既存のセグメントに対するマージが必要になる可能性があるため、これにより全体として O(n^2) の動作が行われます。 

重要な観察は、実際には完全なジオメトリを明示的に維持する必要がないということです。 必要なのは接続されたコンポーネントの数だけです。 新しいセグメントはそれぞれ、新しいコンポーネントを作成するか、既存の 1 つのコンポーネントとマージするか、複数のコンポーネントを 1 つにマージします。 これはまさに動的な区間マージの問題であり、構造ではなく接続性のみを考慮します。 

現在の素な間隔のソートされた構造を維持できます。 受信セグメントごとに、挿入される場所を特定し、間隔が重なったり接触したりしながら左右に拡大し、吸収されるコンポーネントの数を数えます。 吸収された間隔ごとにコンポーネントの数が減り、最後にマージされた間隔を挿入します。 

これは、各間隔がプロセス全体で最大 1 回削除されるため、効率的です。 各挿入は複数の間隔をスキャンする可能性がありますが、順序付けされた構造を使用すると、削除の総数は n によって制限されるため、償却された複雑さは O(n log n) になります。 

Python では、インターバルにわたるバランスのとれたツリーが組み込まれていないため、二分探索によるソートされたリストを使用してシミュレートします。`bisect`、除去は依然として線形に償却されるが、単調な結合動作による制約の下では管理可能であることを受け入れます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (順序付けされたマージ) | O(n log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 コンポーネントの実行数とともに、開始座標でソートされた素な間隔のリストを維持します。 

1. 間隔の空のリストを初期化し、コンポーネント数をゼロに設定します。 この時点では回線には何もないので、答えはゼロです。 
2. 受信セグメント [l, r] ごとに、バイナリ検索を使用して、その左端点に基づいてこのセグメントが挿入される位置を見つけます。 これにより、近くにある重複する可能性のある間隔のみを検査することが保証されます。 
3. すぐ左側に、新しいセグメントと重なるか接触する可能性のある間隔があるかどうかを確認します。 その間隔が l 以降に終了する場合は、マージする必要があります。 新しいセグメントを拡張してカバーし、構造から削除して、コンポーネント数を 1 つ減らします。 
4. 挿入位置から順方向の間隔を確認し続けます。 次の間隔が現在のマージされた右エンドポイントまたはその前で始まる限り、それをマージします。 各マージは 1 つの既存のコンポーネントを吸収し、間隔リストを縮小します。 
5. すべての重複または接触する間隔が削除されたら、新しくマージされた間隔を正しい位置に挿入し、コンポーネント数を 1 つ増やします。 これは、現在のセグメントによって作成された最終的なマージされたブロックを表します。 
6. 各セグメントを処理した後の現在のコンポーネント数を出力します。 

各ステップが正しい理由は、構造内の間隔が常に素でソートされているためです。 これにより、すべての重複部分が挿入ポイントの周囲の連続したブロック内に表示されるようになります。 

### なぜ効果があるのか

 あらゆる瞬間において、連結成分を表す結合されていない結合区間への数直線の分割を維持します。 新しい各セグメントは、既存の間隔内に完全に存在するか、複数の隣接する間隔を 1 つにマージするか、または新しい孤立した間隔を形成します。 間隔はソートされ、結合されていない状態に保たれるため、新しいセグメントに重なるまたは接触する間隔はリストの連続領域に存在する必要があり、マージが失われることはありません。 マージのたびに保存される間隔の数が厳密に削減されるため、コンポーネント数は接続されたコンポーネントの実際の数と一致したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import bisect

def solve():
    n = int(input())
    intervals = []
    res = []
    comp = 0

    for _ in range(n):
        l, r = map(int, input().split())

        # find insertion position
        i = bisect.bisect_left(intervals, (l, r))

        nl, nr = l, r

        # check left interval
        j = i - 1
        if j >= 0 and intervals[j][1] >= l - 0:
            nl = min(nl, intervals[j][0])
            nr = max(nr, intervals[j][1])
            intervals.pop(j)
            comp -= 1
            i -= 1

        # merge right side
        while i < len(intervals) and intervals[i][0] <= nr:
            nl = min(nl, intervals[i][0])
            nr = max(nr, intervals[i][1])
            intervals.pop(i)
            comp -= 1

        intervals.insert(i, (nl, nr))
        comp += 1
        res.append(str(comp))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装では、互いに素な間隔のソートされたリストが維持されます。 二分探索によって挿入点の候補が見つかり、次に左右に拡張して重複または接触する間隔をすべて吸収します。 間隔を削除するたびに、2 つのコンポーネントが 1 つになるため、コンポーネント カウンタがデクリメントされます。 最後に、マージされた間隔を挿入すると、マージされたブロック全体に対して 1 つのコンポーネントだけが復元されます。 

微妙な点はコンディションです`intervals[j][1] >= l`。 これは、接触しているエンドポイントは接続されていると見なされるというルールをエンコードしているため、同等性を含める必要があります。 もう 1 つの微妙な点はインデックスの調整です`i`リストがシフトするため、左の間隔をポップした後。

 ## 特殊なケース

 重要なエッジ ケースは、新しいセグメントが既存の間隔に 1 つの点でのみ接触する場合です。 たとえば、[1,5] がすでに存在する場合に [5,7] を挿入すると、それらを 1 つのコンポーネントにマージする必要があります。 左側のチェックでは次のものが使用されるため、アルゴリズムがこれを処理します。`>= l`、エンドポイントの接触がオーバーラップとして扱われるようにします。 

もう 1 つの特殊なケースは、セグメントが 1 回の挿入で複数の互いに素な間隔を埋める場合です。 たとえば、既存の間隔 [1,2] と [4,5] に [2,4] を挿入すると、両方がマージされる必要があります。 右側の拡張ループは、重複がなくなるまでマージを続け、両方が 1 回の操作で確実に吸収されます。 

最後の微妙なケースは、セグメントが既存の間隔に完全に含まれている場合です。 [1,10] に [3,4] を挿入してもコンポーネント数は変わりません。 アルゴリズムはこれを処理します。これは、左側の間隔がセグメントを吸収し、既存の間隔を同一またはより大きい間隔で置き換える以上の新しい挿入は行われず、コンポーネント数は変更されないままになるためです。
