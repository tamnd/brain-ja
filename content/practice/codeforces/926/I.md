 ## 解決策

 ## 問題の理解

 私たちには、24 時間周期で表される、無限に繰り返される 1 日が与えられています。 各アラームは毎日ちょうど 1 分間の時間を占め、これらのアラームの瞬間は固定されており、時計の同じ位置で毎日繰り返されます。 この数分間、ポリカルポスは眠ることができず、アラームが鳴るとすぐにその時間が終了するまで起きています。 

このタスクは、時間の周期的な性質を考慮して、アラームが鳴っていない最長の連続時間を見つけることです。 この間隔は午前 0 時ごろにラップすることができます。つまり、その間隔は 1 日の終わり近くに始まり、次の日の初めまで続く可能性があります。 

この問題を考えるのに役立つ方法は、すべてのアラーム時刻を 1440 分の円周上に配置することです。 各アラームはこの円上の 1 つのポイントをブロックします。時計回りに移動するときに、連続するブロックされたポイント間の最大のギャップが必要です。 

n ≤ 100 という制約は、O(n²) または O(n log n) 個の解を快適に得ることができることを意味します。 ここではソートが最適なものより優先され、ソート後のすべてのペアに対するブルートフォースでさえも依然として簡単です。 

微妙なエッジケースは、その日の循環的な性質から生まれます。 ラップアラウンドを処理せずに、ソートされた連続するアラーム間の差異のみを考慮すると、その日の最後のアラームと翌日の最初のアラームの間のギャップを見逃してしまいます。 たとえば、05:43 にアラームが 1 つだけある場合、単純な差分の計算では、23:59 のギャップ全体が認識されず、誤って 0 が返される可能性があります。 

アラームが互いに非常に接近している場合、別のエッジ ケースが発生します。 たとえば、アラームが 00:00 と 00:01 にある場合、正しい答えは、包括的な分の解釈に応じて 00:58 または 23:58 になります。また、「1 分間の呼び出し間隔」を不注意に 1 つずつずらして処理すると、結果が 1 分ずれる可能性があります。 

## アプローチ

 この強引なアイデアは、すべてのアラーム時刻を午前 0 時以降の分に変換することから始まり、次に、考えられるすべてのアラームのペアについて、円周上でそれらの間の前方ギャップを計算します。 各ペア (i, j) について、アラーム i からアラーム j までの時間を測定し、必要に応じて日の境界を折り返して、最大値を取得します。 

これが機能するのは、最大スリープ間隔は、あるアラームが終了した直後に開始し、別のアラームが開始したときに終了する必要があるため、そのエンドポイントがアラーム境界と一致するためです。 n 個のアラームでは、O(n²) 個の候補ペアがあり、各ギャップの計算は O(1) で、合計作業量は O(n²) になります。これは、n ≤ 100 の場合でも問題ありません。 

この改善は、すべてのペアが必要ではないことに気づいたことから来ています。 時間がソートされると、周期的な順序で連続するアラーム間に最適なギャップが現れるはずです。 複数の中間アラームにまたがるより大きなギャップがある場合、それらの中間アラームは間隔内に位置し、最大値と矛盾します。 これにより、ソートされた円形配列内の隣接する差異をスキャンするという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. 各アラーム時刻を「hh:mm」から 00:00 からの合計分数に変換します。 これにより、円形の 1 日が線形で表現されます。 
2. 変換されたすべての時間を昇順に並べ替えて、連続する要素が時計上の連続するアラーム イベントを表すようにします。 
3. ソートされたリスト内の各隣接ペア間のギャップを計算します。 2 つの連続するアラーム a[i] と a[i+1] の場合、両方のエンドポイントがアラームによって占有されているため、それらの間の空き時間は a[i+1] - a[i] - 1 になります。 
4. 最後のアラームから真夜中をまたぐ最初のアラームまでのラップアラウンド ギャップも計算します。 これは、(1440 - a[last]) + a[0] - 1 です。 
5. 計算されたすべてのギャップの最大値を取得します。 
6. この最大空き時間数を「hh:mm」形式に変換し直します。

各アラームは 1 分間の間隔全体を占有するため、各ギャップで 1 を減算する必要があります。 時刻 t にアラームが発生した場合、分 [t, t+1) はブロックされるため、スリープは t+1 にのみ開始でき、同様に次のアラーム分が始まる前に終了する必要があります。 

### なぜ効果があるのか

 ソート後、最大スリープ間隔は、循環順序で 2 つの連続するアラーム開始時刻の間になければなりません。 間隔が中間のアラームにまたがる場合、そのアラームが占有する分が睡眠の継続を妨げます。 したがって、すべての有効な最大間隔は、円上の連続するアラーム時間間のギャップの 1 つに正確に対応します。 ラップアラウンド境界を含むこのようなギャップをすべてチェックすると、漏れや重複なくすべての候補が網羅されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_minutes(s):
    h, m = map(int, s.split(":"))
    return h * 60 + m

n = int(input())
a = [to_minutes(input().strip()) for _ in range(n)]
a.sort()

best = 0

for i in range(n - 1):
    gap = a[i + 1] - a[i] - 1
    best = max(best, gap)

wrap_gap = (1440 - a[-1]) + a[0] - 1
best = max(best, wrap_gap)

h = best // 60
m = best % 60
print(f"{h:02d}:{m:02d}")
```変換ステップにより、すべての比較が均一な線形スケールで行われることが保証されます。 並べ替えると、アラームが時系列順に配置されるため、隣接する違いが意味を持つようになります。 隣接するペアにわたるループはすべての内部ギャップを捕捉し、ラップアラウンド計算は時間の循環的な性質を処理します。 ギャップの両端点はアラームの分に対応しており、睡眠には使用できないため、1 分の減算が不可欠です。 

最後の書式設定ステップでは、分が [0, 59] 以内に収まり、必要な出力形式と一致することが保証されます。

 ## 特殊なケース

 単一のアラームは循環的な解釈を強調します。 入力あり`05:43`の場合、並べ替えにより 1 つの要素が生成され、アルゴリズムは内部ギャップをスキップします。 ラップの計算では (1440 - 343 - 1) = 1096 分となり、23:59 に正確に対応します。 アルゴリズムは、午前 0 時ごろに 1 日が連続したものとして正しく処理されます。 

2 つの隣接するアラーム`00:00`そして`00:01`off-by-one ロジックをテストします。 変換後、内部ギャップは 0 - 1 = -1 で、max によって 0 にクランプされます。ラップ ギャップは (1440 - 1) + 0 - 1 = 1438 分、つまり 23:58 になります。 これにより、両方のアラーム分の除外が正しく処理され、ラップ計算が線形ギャップと一貫性を保っていることが確認されます。
