 ## 解決策

 ## 問題の理解

 長さのシーケンスとして表される 1 次元の画像が与えられます。$n$、各位置は黒または白です。 解釈は列ごとに行われます。すべての列が均一に色付けされているため、画像全体がバイナリ配列になります。 

タスクは、この配列を、各ブロックが同一の値で構成され、すべてのブロックが同じ長さを持つ連続したブロックに分解できるかどうかを判断することです。 隣接するブロック間で色を交互にする必要があります。 言い換えれば、配列は固定パターン長の繰り返しである必要があります。$k$、各セグメントの長さは$k$は一定であり、連続するセグメントの色が反転します。 

出力は、シーケンス全体を生成できる均一なストライプ幅が存在するかどうかという単純な実現可能性チェックです。 

制約$n \le 100000$これは、あらゆる解が線形または線形に近いものでなければならないことを意味します。 アン$O(n^2)$考えられるすべてのストライプ幅を試してそれを直接検証する試みには、最大のチェックが必要になります。$n$候補者、それぞれの費用$O(n)$、につながる$10^{10}$最悪の場合の運用。 それは許容範囲をはるかに超えています。 たとえ$O(n \log n)$シングルパスで構造を検証できるため、ソリューションは不要です。 

いくつかの特殊なケースは過小評価されがちです。 

たとえば、すべての要素が同一の場合、$[1,1,1,1]$の場合、配列全体を覆う単一のストライプとして見えるため、正解は「YES」です。 少なくとも 2 つの交互セグメントを要求する単純な実装では、このケースが誤って拒否される可能性があります。 

配列の長さが奇数で、次のように 1 より大きい均等なストライプ幅を強制しようとする場合、$[0,0,0,1,1]$一部の実装では、最終ブロックが完了していることを確認せずに、有効なセグメンテーションが存在すると誤って想定する可能性があります。 要件は、ローカルな一貫性ではなく、グローバルな可分性です。 

配列がすべての要素を交互に配置する場合、次のようになります。$[0,1,0,1,0,1]$、ストライプ幅は 1 でなければなりません。ストライプが 1 よりも長くなければならないと仮定するアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォース手法により、可能なすべてのストライプ幅が試行されます。$k$1から$n$。 候補者ごとに$k$、配列を一定の長さの連続したセグメントに分割します。$k$そして 2 つの条件を確認します。各セグメントは均一である必要があり、隣接するセグメントは異なっていなければなりません。 

これが機能するのは、有効なゼブラ パターンの定義を直接反映しているためです。 ただし、コストは法外なものになります。 それぞれについて$k$、配列全体をスキャンして、次の結果が得られます。$O(n)$候補者ごとに作業し、$O(n^2)$最悪の場合、全体的に複雑になります。 と$n = 100000$、これは遅すぎます。 

重要な観察は、配列がそのランレングス エンコーディングによって完全に決定されるということです。 これを同じ値の連続したブロックに圧縮すると、問題はすべてのランレングスが等しいかどうかをチェックすることになります。 

配列が有効な場合、連続する同一の値はすべてストライプ境界と完全に位置合わせする必要があります。 つまり、ランを複数のストライプに分割することはできず、どのストライプも長さの異なる複数のランをマージすることはできません。 したがって、合計でランが 1 つしかない場合を除いて、すべてのランはまったく同じ長さでなければなりません。 

これにより、問題は単純なスキャンに変換され、ランレングスを計算して均一性を検証します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 連続する等しい値を追跡しながら、配列を左から右に走査します。 値が変更されるたびに、終了したばかりのセグメントの長さを記録します。 このステップでは、入力をランレングスに圧縮し、ストライプ形成に関連するすべての構造情報をキャプチャします。 
2. 最初のランレングスを参考値として保存する$k$。 これが候補ストライプ幅を表します。 
3. 後続の実行ごとに、その長さを次と比較します。$k$。 いずれかのランが異なる場合、構造を等幅のストライプに分割することができないため、答えは直ちに無効になります。 
4. 走査が矛盾なく終了した場合は、設定を受け入れます。 

重要な考え方は、有効なゼブラ パターンによりラン境界とストライプ境界の間の厳密な位置合わせが強制されるということです。 2 つの連続するランの長さが異なる場合、ストライプ幅によってランが分割されるか、不一致のランがマージされることになり、どちらも定義に違反します。 

### なぜ効果があるのか

 有効な解決策はいずれも、値が交互に配置される同じ長さのブロックに配列を分割します。 各ブロックは均一であるため、同じ値のすべての実行が単一のブロック内に完全に含まれている必要があります。 すべてのブロックは同じサイズであるため、すべてのランも同じ長さでなければなりません。 これにより、ランとストライプの間に 1 対 1 の対応が強制され、ランの長さが等しいことが必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

runs = []

cur = a[0]
length = 1

for i in range(1, n):
    if a[i] == cur:
        length += 1
    else:
        runs.append(length)
        cur = a[i]
        length = 1

runs.append(length)

ok = True
for i in range(1, len(runs)):
    if runs[i] != runs[0]:
        ok = False
        break

print("YES" if ok else "NO")
```この実装では、単一パスでランレングスを直接構築します。 ループは現在のセグメントを維持し、変更が発生するまで継続する時間をカウントします。 完了した実行はそれぞれリストに追加されます。 

検証ステップは意図的に最小限に抑えられています。ランレングスがわかったら、平等性だけが重要になります。 最初の実行はストライプ幅を定義し、他の実行はすべてその幅と一致する必要があります。 

微妙な点は、実行構築では変更点の定義によってすでに変更が保証されているため、値の変更を明示的にチェックする必要がないことです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    a = list(map(int, input().split()))

    runs = []
    cur = a[0]
    length = 1

    for i in range(1, n):
        if a[i] == cur:
            length += 1
        else:
            runs.append(length)
            cur = a[i]
            length = 1

    runs.append(length)

    ok = all(x == runs[0] for x in runs)
    return "YES" if ok else "NO"

# provided sample
assert run("9\n0 0 0 1 1 1 0 0 0\n") == "YES"

# all equal
assert run("4\n1 1 1 1\n") == "YES"

# alternating
assert run("6\n0 1 0 1 0 1\n") == "YES"

# invalid unequal runs
assert run("7\n0 0 0 1 1 1 1\n") == "NO"

# single element
assert run("1\n0\n") == "YES"
