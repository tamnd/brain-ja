 ## 問題の理解

 閉じた区間内の整数の個数を数えるように求められます$[l, r]$素因数 2 と 3 のみを使用して記述できます。有効な数値は次の形式でなければなりません。$2^x \cdot 3^y$ここで、両方の指数は負ではない整数です。 これには 1 が含まれます。$x = 0, y = 0$生成する$1$。 

このタスクは純粋に、指定された範囲内にそのような「制限因子」の数値がいくつ入るかを数えることです。 間隔の順序や分解などの制約は他にないため、問題全体は、非常にまばらな整数セットに対するメンバーシップ テストに帰着します。 

制約により許可されるのは、$l$そして$r$まで$2 \cdot 10^9$。 このサイズでは、次の値までのすべての数値の生成が即座に除外されます。$r$密な方法で、または間隔内のすべての整数をチェックします。 素朴なスキャン$[l, r]$最悪の場合、最大 20 億回の反復が必要となる可能性があり、これは 1 秒の時間制限内での実行可能な限界をはるかに超えています。 

さらに微妙な問題は、生成試行の重複です。 次のように数値を構築しようとすると、$2^x \cdot 3^y$、特に両方の指数が独立して反復される場合、不注意に列挙すると、同じ値が複数回再利用される可能性があります。 正しいソリューションでは、重複を避けるか、制御された順序で値を生成する必要があります。 

エッジケースは、小さな境界と大きなべき乗の周囲に現れます。 

もし$l = 1$、数字の 1 を含める必要があります。 から累乗を開始する素朴な解決策$x = 1$または$y = 1$誤って除外してしまうことになります。 

もし$r = 1$の場合のみ、答えは 1 になります。$l = 1$、それ以外の場合は 0。 

近くの大きな値$2 \cdot 10^9$次のような力も重要です$2^{30}$または$3^{19}$制限に近い場合、オーバーフローまたは早期停止条件により、有効な値が通知なく削除される可能性があります。 

## アプローチ

 ブルートフォース戦略では、すべての整数を反復処理します。$[l, r]$そして、それが 2 と 3 に完全に織り込まれるかどうかを確認します。 各数値について、割り切れる間は 2 で割り、次に 3 で割り、結果が 1 になるかどうかを確認します。これは定義を直接テストするため、正しく機能します。 

ただし、このアプローチでは範囲内のすべての整数が検査されるため、最悪の場合、$r - l + 1$小切手。 と$r$まで$2 \cdot 10^9$、その範囲のごく一部であっても、1 秒の制限には大きすぎます。 チェックあたりのコストは対数値ですが、支配的な要因は整数の多さです。 

重要な観察は、有効な数値が非常にまばらであるということです。 すべての数値をテストする代わりに、次の形式のすべての数値を生成できます。$2^x \cdot 3^y$まで$r$。 どちらの塩基も指数関数的に増加するため、そのような値の合計数は少なくなります。 のために$2^x$、$x$超えるまでは最大 30$2 \cdot 10^9$。 のために$3^y$、$y$は最大 19 です。これにより、最大で数百の組み合わせが得られます。 

有効な数値をすべて生成したら、$r$、それらを並べ替えて、その間隔内にいくつあるかを数えます$[l, r]$。 これにより、問題は広大な範囲のスキャンから小さな構造化されたセットの列挙に変換されます。

 | 最適 |$O(\log r \cdot \log r)$|$O(N)$、$N \approx 200$| 承認済み |

 ## アルゴリズムのチュートリアル

 フォームのすべての数値を構築します$2^x \cdot 3^y$上限を超えないもの$r$。 

1. 反復して 3 の累乗を修正する$y$0 から開始して 3 を繰り返し乗算します。これにより、3 の指数を見逃すことがなくなり、最初からの再計算も回避されます。 
2. 各固定値について$3^y$、1 から開始して繰り返し 2 を乗算することで 2 の累乗を生成します。これにより完全なセットが構築されます。$2^x \cdot 3^y$すべて有効な$x$。 
3. 値を計算するたびに、それが制限内にあるかどうかを確認します$r$。 超えた場合$r$、これについては 2 の累乗を停止します。$y$、さらに乗算しても大きくなるだけであるためです。 
4. 有効な値をそれぞれコンテナに保存します。 異なる指数ペアが同じ数値を生成する場合、このコレクションには重複が含まれる可能性があるため、セットを使用して重複を排除します。 
5. すべての生成が完了したら、結果のセットを反復処理し、そのセットに含まれる値の数を数えます。$[l, r]$。 

重要な設計上の選択は、直接の指数ループではなくネストされた指数生成です。これにより、再計算能力が回避され、操作が制限されます。 

### なぜ効果があるのか

 すべての有効な数値は次のように一意に表現できる必要があります。$2^x \cdot 3^y$。 生成プロセスでは、考えられるすべてのペアが列挙されます。$(x, y)$～によって暗示される範囲内で$r$, したがって、有効な番号を見逃すことはできません。 小さい値から明示的に乗算するため、構築されたすべての数値は挿入前に制約内に留まり、フィルタリングの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    l, r = map(int, input().split())

    vals = set()

    p3 = 1
    while p3 <= r:
        p2 = p3
        while p2 <= r:
            vals.add(p2)
            p2 *= 2
        p3 *= 3

    ans = 0
    for v in vals:
        if l <= v <= r:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは構築プ​​ロセスを直接反映しています。 外側のループは 3 の累乗を固定し、内側のループは制限を超えるまで 2 を乗算します。 生成された各値は、一意性を保証するためにセットに挿入されます。 最後に、必要な間隔内にいくつ入るかを数えます。 

微妙な点は、両方のシーケンスを 1 から開始することです。これにより、ケースが確実に$1 = 2^0 \cdot 3^0$特別な処理をしなくても自然に含まれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    l, r = map(int, input().split())

    vals = set()

    p3 = 1
    while p3 <= r:
        p2 = p3
        while p2 <= r:
            vals.add(p2)
            p2 *= 2
        p3 *= 3

    return str(sum(1 for v in vals if l <= v <= r))

# provided samples
assert run("1 10") == "7"

# custom cases
assert run("1 1") == "1"
assert run("2 2") == "1"
assert run("10 10") == "0"
assert run("1 1000000000") == run("1 1000000000")  # consistency check

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、間隔が 1 で始まる場合です。両方のループが 1 に初期化された乗数で始まるため、アルゴリズムには自動的に 1 が含まれます。`1 1`、世代が生み出す`{1}`、カウントは正しく 1 を返します。 

もう 1 つのケースは、範囲内に有効な数値が存在しない場合です。`10 10`。 生成されたセットには 8 や 9 などの有効な数値が含まれていますが、範囲内に収まるものがないため、最後のフィルターですべてが削除され、答えは 0 になります。 

次のような大きな境界`1 2000000000`値が制限を超えるとすぐにループが終了するため、安全に処理されます。 指数関数的な増加により、停止するまでに少数の反復のみが発生することが保証されるため、アルゴリズムは最大入力サイズでも効率を維持します。
