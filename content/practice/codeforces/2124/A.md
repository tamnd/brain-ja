 ## 解決策
 ## 問題の理解

 配列が与えられているので、残りの要素の相対的な順序を維持しながら、任意の数の要素を削除できます。 削除後、残りのシーケンスは空であってはなりません。 

シーケンスのコピーを非降順でソートした後、すべての位置の値が変化する場合、そのシーケンスは乱れたと呼ばれます。 つまり、残りの配列が`b`そしてそのソートされたバージョンは`c`、それでは必要です`b[i] != c[i]`すべてのインデックスに対して。 

タスクは、何かを最大化したり最小化したりすることではありません。 元の配列の一部のサブシーケンスが乱れを形成しているかどうかを判断し、乱れている場合はそのようなサブシーケンスを出力するだけで済みます。 

制約は非常に小さいです。 各テスト ケースには最大 100 個の要素があり、テスト ケースの数は最大 100 個です。 二次または三次の複雑さを持つアルゴリズムであっても完全に安全です。 これは、複雑な最適化を心配するのではなく、単純な構造観察を見つけることに集中する必要があることを意味します。 

主な困難は、どのような結果が錯乱になり得るかを理解することです。 

配列を考慮してください`[1, 1, 1]`。 空でないすべてのサブシーケンスは 1 だけで構成されます。 ソート後は変更されないため、乱れはありません。 

考慮する`[2, 1]`。 配列全体は次のようになります`[1, 2]`並べ替え後。 どちらの立場も変化するので、答えは「YES」です。 

微妙なケースとしては、`[2, 2, 3]`。 ソート順はすでに`[2, 2, 3]`。 を削除すると、`3`与える`[2, 2]`、並べ替え後も変化しません。 いずれかを削除すると、`2`が与えます`[2, 3]`、その並べ替え順序も`[2, 3]`。 空でないサブシーケンスはすべて失敗するため、答えは「NO」です。 

不注意なアプローチでは、まだソートされていない配列全体を使用しようとする可能性があります。 次のような入力では失敗します。`[3, 1, 2]`。 ソート後に次の結果が得られるため、配列全体は混乱していません。`[1, 2, 3]`中央の要素は次のようになります`2`、ソートされた位置と一致します。 単に配列がソートされたバージョンと異なるかどうかをチェックするだけではなく、すべての位置を検証する必要があります。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、空でないすべてのサブシーケンスを調べることです。 サブシーケンスごとにコピーをソートし、すべての位置が異なっているかどうかを確認します。 考えられるすべての答えをテストするので、これは明らかに正しいです。 

問題は、長さの配列であることです。`n`もっている`2^n - 1`空ではないサブシーケンス。 たとえ`n = 100`、これはまったく不可能です。 

重要な観察は、最小の要素に注目することから得られます。 

させて`mn`現在のシーケンスの最小値になります。 ソート後、次のすべての出現が`mn`先頭に表示する必要があります。 ポジションにすでに次のものが含まれている場合`mn`ソート後の最初の位置に留まり、その位置がソートされた値と異なることはありません。 

ある部分列のすべての要素を選択して並べ替えるとします。 要素がすでにソート順と同じ位置にある場合、混乱条件は失敗します。 

この問題を考えるためのはるかに簡単な方法は、元の配列を並べ替えて、元の順序と比較することです。 すべてのインデックスが`a[i] != sorted_a[i]`その要素は、ソートされたシーケンスがそこに配置する要素とすでに異なっているため、「良好」です。 

すべてのインデックスが`a[i] == sorted_a[i]`「悪い」のは、その立場を維持するとすぐに錯乱条件に違反するためです。 

これは、元の配列がソートされたバージョンと異なる位置を正確に取得することを示唆しています。 これらの要素でサブシーケンスを形成します`d`。 

保持された位置ごとに、元の値とソートされた値は異なります。 ソートされたマルチセット`d`は、正確に、ソートされた配列から取得された対応する値です。 したがって、あらゆる位置`d`ソートされたバージョンの位置とは異なるため、`d`正当な錯乱。 

そのような位置が存在しない場合、配列はすでにソートされたバージョンと等しくなります。 その場合、すべての要素がソートされた位置と一致し、有効なサブシーケンスを形成できません。

 | ブルートフォース | O(2^n · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る`a`。 
2. ソートされたコピーを作成する`b = sorted(a)`。 
3. すべてのインデックスを検索する`i`そのような`a[i] != b[i]`。 

これらはまさに、ソートされた配置と既に一致していない位置です。 
4. 対応する値を収集します`a[i]`新しい配列に`ans`。 
5. もし`ans`空です、印刷します`NO`。 

これは、元の配列がソートされたバージョンとすでに同一であるため、乱れた部分列が存在しないことを意味します。 
6. それ以外の場合は印刷します`YES`、の長さ`ans`、およびの要素`ans`。 

### なぜ効果があるのか

 しましょう`S`はインデックスのセットになります。`a[i] != b[i]`、 どこ`b`のソートされたバージョンです`a`。 

私たちは建設します`ans`まさにそれらの位置を使用します。 

ソートされたバージョン`ans`要素を取ることで得られます`b[i]`同じインデックスの場合`i ∈ S`。 これは次の事実から導かれます`b`同じマルチセットをグローバルにソートした配置です。 

保持されているポジションごとに、`a[i] != b[i]`建設によって。 したがって、それぞれの位置`ans`ソートされたバージョンの対応する位置とは異なります。 

したがって、`ans`錯乱です。 

もし`S`空の場合`a = b`、配列全体がすでにソートされていることを意味します。 ソートされた配列のすべてのサブシーケンスもソートされるため、一部の位置は常にそのソートされたバージョンと一致します。 錯乱など存在し得ない。 

これにより、正確さと完全性の両方が証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        b = sorted(a)

        ans = []
        for i in range(n):
            if a[i] != b[i]:
                ans.append(a[i])

        if not ans:
            print("NO")
        else:
            print("YES")
            print(len(ans))
            print(*ans)

solve()
```この解決策は、配列をソートすることから始まります。 ソートされたコピーは、混乱状態が測定される対象となる配置を表します。 

このループは、元の値がソートされた配列内の値と異なるインデックスを正確に収集します。 有効な回答に参加できるのはこれらのポジションだけです。 

そのような位置が存在しない場合、配列はすでにソートされており、有効なサブシーケンスは存在しません。 

そうでない場合、収集された要素は有効な混乱を形成します。 実装はそれらを直接出力します。 

最も一般的な間違いは、インデックスを次の場所に保持しようとすることです。`a[i] == b[i]`。 値がすでにソートされた位置と一致しているため、このような位置は直ちに混乱要件に違反します。 

もう 1 つの簡単な間違いは、配列全体がソートされたバージョンと異なるかどうかだけをチェックすることです。 錯乱するには、少なくとも 1 つの位置だけでなく、すべての位置が異なることが必要です。

import io

    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        b = sorted(a)

        ans = [a[i] for i in range(n) if a[i] != b[i]]

    old_stdout = sys.stdout

    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdout = old_stdout

    return out

 ## 特殊なケース

 次のことを考慮してください。```
1
1
1
```ソートされたコピーは同一です。 満たすインデックスがありません`a[i] != b[i]`したがって、応答配列は空であり、アルゴリズムは次のように出力します。`NO`。 使用可能なサブシーケンスは次のとおりであるため、空でない混乱は存在できません。`[1]`。 

考慮する：```
1
5
3 3 3 3 3
```ここでも、ソートされたコピーは同一です。 すべてのサブシーケンスは完全に 3 で構成されており、並べ替えによって何も変更されることはありません。 アルゴリズムは異なる位置を正しく検出し、出力します。`NO`。 

考慮する：```
1
2
2 1
```ソートされたコピーは、`[1,2]`。 両方の位置が異なるため、アルゴリズムは両方の要素を保持します。 結果の配列`[2,1]`ソートされたバージョンがあります`[1,2]`、それぞれの立場が異なります。 アルゴリズムは出力します`YES`。 

考慮する：```
1
3
3 1 2
```ソートされたコピーは、`[1,2,3]`。 3 つの位置はすべて異なるため、配列全体が選択されます。 比較する`[3,1,2]`と`[1,2,3]`、すべての立場が異なるため、それは正当な錯乱となります。 アルゴリズムは配列全体を出力します。
