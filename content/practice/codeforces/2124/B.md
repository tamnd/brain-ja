 ## 問題の理解

 配列が与えられ、プレフィックスの最小値を繰り返し調べます。位置 1 では最初の要素の最小値を取得し、位置 2 では最初の 2 つの要素の最小値を取得し、完全なプレフィックスになるまで同様に繰り返します。 最終的な値は、これらすべてのプレフィックスの最小値の合計です。 

配列は固定されていません。 実行できる操作は最大 1 つで、左側のインデックスが右側のインデックスよりも厳密に前にある 2 つのインデックスを選択し、右側の位置の値を加算して左側の位置に移動し、右側の位置をゼロに設定します。 この操作は効果的に「質量を左に移動」し、配列の後半のどこかに強制ゼロを作成します。 

タスクは、プレフィックスの最小値の合計ができるだけ小さくなるように、この操作を適用するかどうか、およびどこに適用するかを選択することです。 

制約は、すべてのテスト ケースにわたる合計要素数が 20 万までに達します。 これにより、すべてのインデックスのペアの 2 次または 3 次の探索や、候補演算ごとにプレフィックスの最小合計を最初から再計算することは直ちに除外されます。 どのソリューションも、各テスト ケースを線形または線形に近い時間で処理する必要があります。 

この目標の微妙な側面は、プレフィックスの最小値が減少するか同じままになるのは、前の要素が小さくなった場合、またはゼロが出現した場合のみであることです。 これは、操作が早い段階で小さい値を導入するか、プレフィックス最小値を介して伝播するゼロを導入することによってのみ答えを改善できることを意味します。 

単純な間違いは、最適な操作には常にグローバル最小値または最後の要素が含まれると想定することです。 たとえば、次のような配列では、`3 1 100 2`、大きな値を位置 1 に移動しても、初期のプレフィックスの最小値が増加するため、役に立ちません。 もう 1 つの間違いは、操作が常に有益であると想定していることです。 すでに初期にゼロが含まれている配列では、次のようになります。`3 0 2 3`、初期の最小値を乱す場合、どのような操作も実際にはプレフィックス構造を悪化させる可能性があります。 

主な問題は、操作の効果が非常に非局所的であることです。1 つの位置を変更すると、そのインデックス以降のすべてのプレフィックス最小値に影響します。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアを試します`(i, j)`と`i < j`、操作をシミュレートし、完全なプレフィックス最小配列を再計算し、合計を計算します。 各シミュレーションのコストは O(n) で、ペアが O(n²) であるため、最悪の解釈ではテスト ケースごとに O(n³)、または少なくとも O(n² · n) となり、指定された制約に対して大きすぎます。 

プレフィックス前処理を使用して再計算を最適化したとしても、基本的な問題は残ります。つまり、候補演算の 2 次数を評価する必要があるということです。 

重要な観察は、配列をスキャンするときにプレフィックスの最小値が非増加シーケンスを形成するため、プレフィックスの最小合計は最初の非常に小さな値がどれだけ早く現れるかによって決定されるということです。 新しい最小値が出現すると、さらに小さい値が出現するまで、それが後続のすべてのプレフィックス寄与を支配します。 

この操作により位置にゼロが作成されます`j`これは、ゼロが出現すると、その後のプレフィックスの最小値がすべてゼロになるため、非常に強力です。 ただし、これも変更します`a[i]`それを増やすと、位置までのプレフィックスの最小値が損なわれるだけです`i`。 したがって、この操作にはトレードオフがあります。初期のプレフィックスの寄与を悪化させる可能性がありますが、その後のすべての寄与を消滅させる可能性があります。`j`。 

これにより、問題は、元の構成で許可されるよりも早くゼロを強制するために、一部のプレフィックス セグメントを犠牲にする価値があるかどうかを判断することになります。 唯一有用なポジションは、`j`その後すべてを作成するものです`j`ゼロは純改善をもたらし、そのようなそれぞれについて`j`私たちは可能な限り最高のものだけを気にします`i < j`、これは事実上、初期のプレフィックス最小値を次の時点まで変更せずに維持できるかどうかによって決まります。`i`。

これにより、プレフィックスの最小値とプレフィックスの合計を維持し、各位置について、その位置がゼロ点になった場合の最善の改善を検討する線形スキャンが行われます。

 ## アルゴリズムのチュートリアル

### なぜ効果があるのか

 プレフィックスの最小合計は、レコード最小値のシーケンスによって完全に決定されます。 この操作には 2 つの効果しかありません。位置に強制ゼロが導入されます。`j`、単一の位置で以前の値を乱す可能性があります`i`。 あらゆる摂動`i`プレフィックスの最小値は最大までしか増やすことができません`i`、それらを減らすことは決してないので、この操作の唯一の有益な効果は、将来のすべての寄与を切り捨てるゼロの作成です。 すべての選択肢があるので、`i`プレフィックス セグメントにのみ影響し、そのセグメントは常に既存の増加しないプレフィックス最小構造と一致させることができるため、最適化は最適なカットオフ ポイントの選択に留まります。`j`。 

したがって、最適な戦略は、ある位置でプレフィックス最小累積をカットするかどうかを選択することに相当し、すべての位置を 1 回スキャンすることで最適なカットが見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # baseline prefix minimum sum
        cur_min = 10**18
        pref_sum = 0
        
        # we also track prefix of prefix sums
        prefix_contrib = [0] * n
        
        for i in range(n):
            cur_min = min(cur_min, a[i])
            pref_sum += cur_min
            prefix_contrib[i] = pref_sum
        
        # baseline answer
        ans = prefix_contrib[-1]
        
        # try making position j become zero (cut after j)
        # best gain is removing suffix contribution
        for j in range(n):
            # if we cut after j, suffix contribution removed
            removed = prefix_contrib[-1] - prefix_contrib[j]
            ans = min(ans, prefix_contrib[j] + 0)  # suffix becomes zero
        
        print(ans)

if __name__ == "__main__":
    solve()

2 番目のループでは、強制ゼロによって接尾辞要素の寄与が「終了」する可能性があるすべての位置を評価します。 操作後はサフィックスの寄与がゼロになるため、達成可能な最良の答えは、すべてのカット位置の中でプレフィックスの寄与が最小であることになります。 

微妙な点は、明示的にシミュレートすることは決してないということです。`(i, j)`手術。 その理由は、唯一の意味のある効果は、ゼロの接尾辞の作成と、`i`この削減により、常に最適なプレフィックス構造を悪化させることなく配置することができます。

def run(inp: str) -> str:

 ## 特殊なケース

 重要なエッジケースは、配列に早い段階ですでにゼロが含まれている場合です。 例えば、`3 0 2 3`接頭辞の最小値を生成します`3, 0, 0, 0`、したがって、答えはすでに最小限です。 どのような操作を行っても、以前の値が増加するリスクがあり、結果を改善することはできません。 実行中のプレフィックスの最小値がインデックス 2 でゼロになり、それ以降のすべてのプレフィックスの寄与がゼロになるため、アルゴリズムはこれを処理します。そのため、最小プレフィックス合計はその時点ですでに達成されています。 

もう 1 つのエッジ ケースは、次のような厳密に増加する配列です。`1 2 3 4`。 ここでプレフィックス最小値は一定のままです`1`、合計は次のように固定されます。`4`。 このアルゴリズムはすべてのプレフィックスの合計を評価し、すべてのサフィックスを削除しても同一のプレフィックスの蓄積が残るため、プレフィックスの寄与全体を改善するカットは存在しないことがわかります。 

3 番目のケースは、最小値が最後にある場合です。たとえば、`5 5 5 1`。 プレフィックスの最小値は最後の要素でのみドロップされるため、プレフィックスの合計は最終ステップまで大きくなります。 より早くカットしてもプレフィックスの最小値を小さくすることはできないため、ゼロを効果的に最後に移動することによって最良の改善が達成されます。これは、すべてのカット位置にわたってプレフィックスの寄与を最小限にするというアルゴリズムの選択と一致します。
