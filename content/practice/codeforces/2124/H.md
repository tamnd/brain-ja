 ## 解決策
 ## 問題の理解

 配列が与えられています`a`。 サブシーケンスを選択し、それを新しい配列として再解釈したいと考えています。`b`。 目標は、長さを最大化することです。`b`の対象となる`b`_良い_配列であること。 

良さの定義は、順列と範囲の最小値の観点から記述されます。 一見するとサブシーケンスとは無関係に見えますが、実際の作業はどの配列がどの配列であるかを理解することです。`b`その構造から実際に現れることができます。 

値`b_i`で終わるセグメントの左端の位置を表します`i`その最小値は正確な位置で発生します`i`。 順列には個別の値が含まれるため、すべての比較は厳密になります。 定義に隠された構造は、順列そのものよりもはるかに重要であることが判明しました。 

元の配列の長さは最大でも`15000`、との合計`n²`すべてのテストケース全体で最大でも`15000²`。 これは非常に強力なヒントです。 複雑さを伴うソリューション`O(n²)`意図されています。 3次アルゴリズムには大まかに次のものが必要です`3·10¹²`最悪の場合、操作が不可能になり、完全に実行不可能になります。 二次動的計画法ソリューションについて`2.25·10⁸`すべてのテストにわたる単純な操作は、まさにこれらの制約が設計された範囲です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
a = [2,2,2,2]
```等しい値はいつでも連鎖できるという魅力的な考えがあります。 それはできません。 適切な配列には、値がそれ自体のインデックスと等しい位置が含まれている必要があります。 あらゆる値は`2`、空ではない良好なサブシーケンスは存在しません。 正しい答えは、`0`。 

考慮する：```
a = [1]
```単一の要素はすでに必要な構造を満たしています。 答えは`1`。 

考慮する：```
a = [1,1,2]
```シーケンス全体が良くありません。 局所的な不等式のみに基づいた単純なチェックでは、それが誤って受け入れられてしまいます。 最長の良好なサブシーケンスは、`[1,2]`、長さは`2`。 

これらの例は、決定的な困難は位置を選択することではなく、どのシーケンスが実際に優れているかを特徴付けることであることを示しています。 

## アプローチ

 強引なアイデアは単純明快です。 すべてのサブシーケンスを列挙し、それが適切であるかどうかをテストし、最大長を維持します。 

長さの配列の場合`n`、 がある`2^n`後続。 たとえ`n = 60`これはもう絶望的です、そしてここで`n`到達できる`15000`。 強引なアプローチは、概念的な出発点としてのみ機能します。 

本当の進歩は、優れた配列の構造を理解することから生まれます。 

させて`b_i = x`。 範囲最小解釈、位置を見ると、`x`それ自体が有効なブロックの先頭でなければなりません。 定義を解くと、次のような特徴が得られます。 

シーケンス`b`すべてのポジションでその場合にのみ良い`i`と`b_i = x`、次のいずれかが当てはまります。 

1.`x = i`。 
2.`b_x = x`セグメント上のすべての値`[x, i]`少なくとも`x`。 

これにより、問題から順列が完全に削除されます。 インデックスと値についてのみ推論する必要があります。 

今度はあらゆるポジションを考えてみましょう`x`満足のいく`b_x = x`ブロックのルートとして。 その後に発生した値`x`そのブロックに属している必要があり、ブロック内のすべての値は少なくとも`x`。 

これは当然、区間動的計画法につながります。 考えられるブロック ルートを処理し、右側に拡張します。 より大きな値に遭遇すると、ネストされたブロックが開始される可能性があります。 重要な点は、このような入れ子になったブロックの開始位置はできるだけ早く貪欲に選択する必要があるということです。 これにより、すべての遷移を二次時間で実装できるようになります。 

結果の DP は、`Σ n² ≤ 15000²`制約。

 ## アルゴリズムのチュートリアル

 ### 状態の定義

 しましょう`dp[i][j]`間隔内で形成できる適切なサブシーケンスの最大長を表します。`[i, j]`条件の下で：

 - 位置`i`選ばれて、
 - その値はブロックルートとして機能します。 
- 位置`j`は、構築されたサブシーケンス内でそのルート値が最後に出現する場所です。 

編集実装では、まさにこの量が保存されます。 

### 移行工事

 1. プロセスの開始位置`i`右から左へ。 
2. をルートとするブロックを初期化します。`i`。 

最小の有効なサブシーケンスは、次の出現のみで構成されます。`a[i]`。 最初に:```
dp[i][i] = a[i]
```変数`curr`これまでに得られた最高の値を保存します。 
3. 右側のエンドポイントを延長します`j`。 
4. もし`a[j] < a[i]`、要素は現在のブロックに属することはできません。 

特性評価では、ブロック内のすべての値が少なくともルート値である必要があります。 
5. もし`a[j] = a[i]`、この出来事を無料で追加することができます。 

増加`curr`1 つずつ指定して設定します。```
dp[i][j] = curr
```6. もし`a[j] > a[i]`、要素はネストされたブロックのルートになる可能性があります。 

配列を維持する`good[v]`。`good[v]`値が次のような最も古い位置を格納します。`v`DP 値がすでに次のタイプのブロックをサポートするのに十分な大きさである`v`。 
7. このようなネストされたブロックが存在する場合は、それを現在の構造にマージします。```
curr = max(curr, dp[idx][j])
```どこ`idx = good[a[j]]`。 
8. すべてのエンドポイントが処理されるまで続行します。 

### 答えを抽出する

 すべての間隔状態が計算されたら、同じ遷移ロジックを配列全体でもう一度実行します。 

有効なルートが利用可能になったら、対応するルートを使用します。`dp`値を使用してグローバルな回答を更新します。 

最終的な値は、`curr`最長の正常なサブシーケンスの長さです。 

### なぜ効果があるのか

 優れた配列の特徴付けでは、値が出現するたびに、`x`値も同じ位置をルートとするブロックに属している必要があります。`x`。 

このようなブロック内では、すべての値が少なくとも次の値でなければなりません。`x`。 これは、より小さい値は決して追加できず、等しい値は常にブロックを拡張し、より大きな値は、ルートがすでに同じプロパティを再帰的に満たしているネストされたブロックを通じてのみ表示できることを意味します。 

DP 状態には、ブロック ルートの達成可能な最適な長さと固定された最後のオカレンスが正確に保存されます。 すべての有効な適切なサブシーケンスはこれらのネストされたブロックに分解でき、DP によって実行されるすべての遷移は 1 つの正当な分解に対応します。 最も早い実行可能なルートが将来の拡張にとって常に最適であるため、次のような貪欲な選択が使用されます。`good[]`より良いソリューションを失うことはありません。 

したがって、すべての有効な良好なサブシーケンスが考慮され、DP によって生成されたすべてのサブシーケンスが特性評価を満たします。 アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    dp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n, 0, -1):
        good = [-1] * (n + 1)

        curr = a[i]
        dp[i][i] = curr

        for j in range(i + 1, n + 1):
            if a[j] < a[i]:
                continue

            if a[j] == a[i]:
                curr += 1
                dp[i][j] = curr
                continue

            if good[a[j]] == -1 and a[j] <= curr + 1:
                good[a[j]] = j

            if good[a[j]] != -1:
                idx = good[a[j]]
                curr = max(curr, dp[idx][j])

    curr = 0
    good = [-1] * (n + 1)

    for j in range(1, n + 1):
        if good[a[j]] == -1 and a[j] <= curr + 1:
            good[a[j]] = j

        if good[a[j]] != -1:
            idx = good[a[j]]
            curr = max(curr, dp[idx][j])

    print(curr)

t = int(input())
for _ in range(t):
    solve()
```外側のループはすべての間隔の状態を計算します。`dp[i][j]`。 処理`i`右から左へは、将来の遷移で必要となるすべてのネストされたブロックがすでに計算されていることを保証します。 

配列`good`開始位置ごとに再構築されます。 各値の最も古い使用可能なルートが記録されます。 前のルートが後のルートよりも優先されるため、最初のそのような位置のみを保存するだけで十分です。 

微妙な点は次の条件です。```
a[j] <= curr + 1
```value をルートとするブロック`v`少なくとも必要です`v - 1`開始する前にすでに位置が構築されている必要があります。 この条件はまさに実現可能性チェックです。 

もう 1 つの微妙な詳細は、`a[j] < a[i]`完全にスキップされます。 それらを許可すると、特性定理に違反し、無効なブロックが作成されます。

## 特殊なケース

 次のことを考慮してください。```
1
4
2 2 2 2
```グローバルフェーズでは、価値`2`現在達成可能な長さに決して達しないため、有効なルートになることはできません`1`ルートを作成する前に。 どの DP 状態も使用可能になり、答えは残ります`0`。 空ではない良好なシーケンスには何らかの位置が含まれている必要があるため、これは特徴付けと一致します。`i`価値のあるもの`i`。 

考慮する：```
1
1
1
```唯一の位置は、ルートとそのブロックの終わりです。 DP が初期化されます`dp[1][1] = 1`、そしてグローバルフェーズはすぐに答えを回復します`1`。 

考慮する：```
1
3

```最初の 2 つの要素は、value をルートとするブロックを作成します。`1`。 最終値のとき`2`が検査されると、DP は、必要な入れ子構造がシーケンス全体に存在しないことを検出します。 最も有効なサブシーケンスは長さのままです`2`、に対応`[1,2]`。 

これらの例は、2 つの最も一般的な落とし穴を示しています。それは、等しい値が常に連鎖できると仮定することと、すべてのブロックが有効なルートから発生する必要があるという要件を無視することです。
