 ## 問題の理解

 長さの配列を構築しています$n$ですが、要素ごとに構築しているわけではありません。 代わりに、ブロック全体を繰り返し追加することによって配列が形成されます。 各ブロックは順列の循環回転です。$[1, 2, \ldots, s]$選択した長さに対して$s$。 すべての操作は連続したセグメントに寄与し、そのセグメント内のすべての値は次の順列になります。$1$に$s$いくつかの回転順序で。 

最終的な配列は、「位置」という形式の位置制限を満たす必要があります。$i$、 価値$x$タスクは、長さの異なる最終的な配列の数を正確に数えることです。$n$このようなブロック追加操作のシーケンスによって生成できます。 

主な問題は、操作によって構造化配列の巨大なファミリーが定義されることです。 各位置はそれをカバーするブロックの影響を受け、ブロックは時間的にのみ重複できますが、値の割り当てにおいては重複できません。 したがって、最終的なオブジェクトは任意ではありませんが、単純な順列や合成でもありません。 

制約の総和は小さく、$\sum n \le 5000$そして$\sum m \le 5000$、これは、$O(n^2)$または$O(n^2 \log n)$テストごとのソリューションは許容されますが、テストごとに 3 次のものは、単純に実装するとすでに境界線になってしまいます。 

微妙な点は、各制限はローカルなものですが、実現可能性はグローバル構造に依存するということです。 値が共有ブロック構造を通じて相互作用するため、配列を独立して構築したり位置を独立して扱う単純なアプローチは失敗します。 もう 1 つのよくある落とし穴は、各ポジションが独立して割り当てられると想定していることです。$[1,n]$除外を使用すると、ブロック内の値が置換セグメントを形成する必要があることが無視されます。 

たとえば、構造を無視して各位置を独立して扱うと、次のような配列を過剰にカウントすることになります。$[1,1,1]$またはそれを見逃します$[2,2,3]$サイズ 2 または 3 のブロック内では、値には次のすべての数値が含まれなければならないため、ブロック構築規則の下では不可能です。$1$に$s$。

 ## アルゴリズムのチュートリアル

 この問題を、配列を連続ブロックに分割するための有効な方法を数えることに変換します。ここで、各ブロックは順列の巡回シフトです。 

1. 構造を事前計算して、セグメントが適切かどうかを迅速にチェックします。$[l, r]$何らかの回転の下で有効なブロックを形成できます。 各セグメントについて、禁止値の一貫性をチェックすることにより、考えられるすべての回転を暗黙的にテストします。 アイデアは、長さを何回回転させるかを決定することです$len = r-l+1$そのセグメント内のすべての制約を満たします。 
2. セグメントごと$[l, r]$、値を計算します$ways[l][r]$、これは、制限に違反しない有効な循環シフトの数です。 これは、各回転をチェックし、セグメント内のすべての位置を確認することで実行できます。 以来$n \le 5000$合計すると、すべてのセグメントにわたって慎重に最適化されたチェックが可能になります。 
3. DP 配列を定義する$dp[i]$、 どこ$dp[i]$長さのプレフィックスを生成する有効な構造の数です。$i$。 
4.初期化$dp[0] = 1$、空の構造を表します。 
5. 各エンドポイントについて$i$、可能なすべての最後のセグメントの開始を反復します。$j$から$0$に$i-1$。 分割ごとに、ブロックを 1 つカバーすることで構築を拡張します。$[j+1, i]$、貢献$ways[j+1][i] \cdot dp[j]$。 
6. すべての貢献を合計して取得します$dp[i]$。 答えは$dp[n]$。 

これが機能する理由は、有効な構造は最大の追加ブロックへの固有の分解を持っているためです。 各ブロックは、その長さと回転が固定されると独立し、制限は個々のブロックのみを制限し、異なるブロック間の相互作用を制限するものではありません。 したがって、DP は、最後のブロック境界を選択することによって、すべての有効なグローバル構造を 1 回だけ列挙します。 

不変条件とは、$dp[i]$プレフィックス長の有効な構造をすべてカウントします。$i$ここで、すべてのブロックは完全にプレフィックス内にあり、独立して制約を満たします。 すべての遷移では、有効なプレフィックスが 1 つの有効なブロックによって拡張され、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    bad = [[False] * (n + 1) for _ in range(n + 1)]
    
    for _ in range(m):
        i, x = map(int, input().split())
        bad[i][x] = True

    # ways[l][r] = number of valid rotations for segment [l, r]
    ways = [[0] * (n + 1) for _ in range(n + 1)]

    for l in range(1, n + 1):
        for r in range(l, n + 1):
            length = r - l + 1
            cnt = 0
            for shift in range(length):
                ok = True
                for pos in range(length):
                    val = ((pos + shift) % length) + 1
                    if bad[l + pos][val]:
                        ok = False
                        break
                if ok:
                    cnt += 1
            ways[l][r] = cnt

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        total = 0
        for j in range(i):
            total = (total + dp[j] * ways[j + 1][i]) % MOD
        dp[i] = total

    print(dp[n] % MOD)

t = int(input())
for _ in range(t):
    solve()
```実装はセグメント分解上の DP に直接続きます。 の`ways`テーブルは、間隔ごとに、すべての禁止された制約を乗り越えて恒等順列の巡回シフトが何回存続するかをカウントします。 それから`dp[i]`可能なすべての最後のセグメント境界にわたって累積されます。 

回転用のトリプル ループは最も高価な部分ですが、制限内に留まります。$n$テスト全体の値は 5000 によって制限されます。最悪の場合、DP はテストごとに 2 次になりますが、グローバルには許容されます。 

DP では包含境界が使用される一方で、セグメントは 1 からインデックス付けされるため、制限のインデックス付けを正しく行うには注意が必要です。 乗算はモジュロで行われます$998244353$オーバーフローを防ぐために各遷移で。

### 例 2

 入力:```
3 2
1 1
2 1
```Position 1 and 2 both forbid value 1, heavily restricting valid rotations.

 Segment [1,1] cannot place value 1, so it is invalid.

 Segment [1,2] also fails because every rotation of [1,2] places a 1 somewhere in the segment.

 Only segments that avoid placing 1 at forbidden positions survive, which collapses many transitions.

 The DP therefore only allows segments ending at 3 that avoid violating constraints earlier, leading to a much smaller set of valid constructions.

 This trace shows how local constraints prune entire segments rather than individual values.

 ## 特殊なケース

 重大なエッジ ケースは、単一の制限によってセグメントのすべての回転が排除される場合です。 たとえば、長さ 2 のセグメントが両方の位置で値 1 を禁止する場合、どちらの回転も禁止されます。$[1,2]$または$[2,1]$は存続するため、セグメントの寄与はゼロになります。 このようなセグメントは次のような結果をもたらすため、DP はこれを正しく処理します。$ways[l][r] = 0$したがって、プレフィックス拡張には決して寄与しません。 

もう 1 つの微妙なケースは、制限が 1 つの回転にのみ影響し、すべてには影響しない場合です。 アルゴリズムは、残りの回転を正しくカウントする必要があります。 たとえば、長さ 3 のセグメントでは、単一の位置と値のペアを禁止すると、通常は 1 回転だけが削除され、DP はこれを 2 値の有効/無効の決定ではなく、乗算の重みの減少として反映します。 

最後のコーナーケースは、長さ 1 の自明なセグメントを除いて、指定された長さのすべてのセグメントが無効である場合に発生します。DP は自然にシングルトン パーティションのみをカウントするように崩壊し、正しいが最小限の構成セットが生成されます。
