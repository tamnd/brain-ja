 ## 解決策
 ## 問題の理解

 長さの配列を数えるように求められます$n$配列の巡回シフトを繰り返し追加することで構築できます$[1, 2, \dots, s]$誰にとっても$s \ge 1$、形式の一連の制限を尊重しながら$a_i \ne x$。 各操作では、ある番号から始まる連続した数値シーケンスが追加されます。$r$ラップアラウンドして順列を形成します$[1, \dots, s]$。 

事実上、構築できる配列は小さな循環順列の連結ですが、どの配列を作成するかについての明示的な制約はありません。$s$毎回使うために。 最終的な長さは$n$そして$n \le 100$、位置の総数が少ないため、配列の位置全体にわたって DP を考慮できます。 それぞれの制限により、特定のインデックスでの特定の値が禁止されるため、配列を構築するときに実行可能な値を追跡する必要があります。 

明らかではないエッジ ケースには、すべての小さなセグメントに禁止値が含まれる配列が含まれます。 たとえば、次の場合$n = 3$すべての位置が 1 を禁止している場合、どの配列も 1 から始めることはできず、最大 3 のサイズのすべての可能な巡回置換をチェックする必要があります。すべての可能なシーケンスを列挙する単純なアルゴリズムでは、各位置をチェックせずに有効な配列が存在すると誤って想定してしまいます。 同様に、サイズ 2 の巡回シフトごとに値を出現させる必要がある値が制限によって禁止されている場合、カウントが直ちに 0 に減少する可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての長さの配列を生成しようとします。$n$追加された巡回シフトのすべての可能なシーケンスを反復し、制限に違反するものを除外します。 長さの配列の数なので、$n$指数関数的です$n$、このアプローチはすぐに実行不可能になります。$n = 20$、あるように$2^n$or more sequences to consider.

 重要な洞察は、この問題を配列の位置に関する動的プログラミングとして再構成できるということです。 ポジションごとに$i$、ポジションを埋める方法の数を追跡できます。$i$制限が満たされるようにします。 各 DP 状態では、現在の長さと数値の追加に使用される最後のセグメント サイズが考慮され、許可された操作を使用して配列を構築できることが保証されます。 トランジションには、新しいセグメント長の選択が含まれます$s$とその開始値$r$, then checking that appending this segment does not violate any restriction at the positions it occupies. 以来$n \le 100$、位置とセグメントの長さを明示的に反復して、多項式時間の解を与えることができます。

 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、それぞれを繰り返します。 それぞれの場合について読んでください$n$そして$m$、すべての制限事項を読みます。 各位置の禁止値を便利なデータ構造に保存します。たとえば、次のようなセットのリストです。`forbidden[i]`その位置で禁止されているすべての値が含まれています$i$。 
2. DP 配列を初期化する`dp[i]`どこ`dp[i]`有効な長さの配列の数を表します$i$。 セット`dp[0] = 1`基本ケースとして、空の配列を表します。 
3. 1 から 1 までの長さにわたって反復します。$n$。 それぞれについて`i`、 length で終わる配列を拡張しようとします`i - s`長さの循環セグメントを追加することによって`s`。 各候補セグメントの長さについて`s`1から`i`、考えられるすべての出発点を試してください`r`サイクリックシフトの場合。 
4. 特定のセグメント長の場合`s`と開始値`r`、追加された値をシミュレートし、制限に違反するかどうかを確認します。 これには、新しい位置ごとに値を計算することが含まれます。`(r + j - 1) % s + 1`そして、対応する配列位置の禁止セットと照合します。 
5. セグメントが有効な場合は、`dp[i - s]`に`dp[i]`。 すべてのセグメントの長さと開始値が位置に対して試行されるまで続行します。`i`。 
6. 計算後`dp[n]`、出力`dp[n] % 998244353`現在のテストケースの場合。 

このアルゴリズムの正しさは、次の不変条件に依存します。`dp[i]`有効な長さの配列をすべてカウントします`i`ルールに従って建てられています。 すべての有効なセグメントによって配列を拡張することで、可能性が失われることがなくなり、制限をチェックすることで、有効な配列のみがカウントに寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    forbidden = [set() for _ in range(n)]
    for _ in range(m):
        i, x = map(int, input().split())
        forbidden[i-1].add(x)

    dp = [0] * (n+1)
    dp[0] = 1

    for i in range(1, n+1):
        for s in range(1, i+1):
            valid_starts = 0
            for r in range(1, s+1):
                ok = True
                for j in range(s):
                    pos = i - s + j
                    val = (r + j - 1) % s + 1
                    if val in forbidden[pos]:
                        ok = False
                        break
                if ok:
                    valid_starts += 1
            dp[i] = (dp[i] + dp[i - s] * valid_starts) % MOD

    print(dp[n])
```このコードは、まず禁止されたセットを構築し、次に各エントリがその長さの有効な配列をカウントする DP 配列を使用します。 ネストされたループは、すべての可能な巡回シフトを追加し、制限をチェックするロジックを実装します。 モジュロ演算により、値が指定された制限を超えないことが保証されます。 慎重なインデックス作成`(r + j - 1) % s + 1`巡回置換を正しく生成し、off-by-one エラーを回避します。 

## 実用的な例

 最初のサンプルでは、`n=3, m=0`、巡回シフトから構築できる長さ 3 の配列はすべて有効です。 DP テーブル`dp`次のように進化します。 

| 私 | dp[i] |
 | --- | --- |
 | 0 | 1 |
 | 1 | 1 |
 | 2 | 3 |
 | 3 | 7 |

 これにより、合計 7 つの配列が確認されます。 2 番目のサンプルについては、`n=3, m=1`制限付き`1 1`、`dp`は:

 | 私 | dp[i] |
 | --- | --- |
 | 0 | 1 |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 0 |

 部分的に構築できる配列は 1 つだけであり、長さ 3 の配列は位置 1 の制限を満たさないため、出力は 0 になります。
