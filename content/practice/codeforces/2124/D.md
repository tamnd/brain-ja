 ## 解決策
 ## 問題の理解

 配列から始めて、要素を繰り返し削除する場合があります。 削除ルールは特殊です。少なくとも長さの任意の部分配列を選択してください。`k`、それを見つけてください`k`- 番目に小さい値を選択し、選択した部分配列内のその値の出現を 1 つ削除します。 

目標は、操作の数を最小化または最大化することではありません。 回文を残す有効な欠失のシーケンスが存在するかどうかを判断するだけで済みます。 

この制約は、ほぼ線形の解決策が必要であることを直ちに示唆しています。 すべてのテスト ケースにわたって、全長は最大でも`2·10^5`、だから、`O(n log n)`アルゴリズムは快適ですが、二次関数は不可能です。 単一のテストでも、`n = 2·10^5`作るだろう`O(n²)`数百億回を超える操作。 

主な困難は、実際にどの要素を削除できるかを理解することです。 操作は任意の部分配列を通じて定義されるため、削除を直接シミュレートしようとするとすぐに絶望的になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する`k = 1`。```
4 1
1 1 2 1
```答えは`YES`。 長さ 1 の部分配列の最初の最小要素がその要素自体であるため、すべての要素を削除できます。 いくつかの値が残される必要があると仮定したソリューションは、ここでは失敗します。 

考慮する`k = n`。```
3 3
1 2 2
```答えは`NO`。 使用可能なサブ配列は配列全体だけです。 3 番目に小さい要素は、`2`、したがって、`2`削除することができます。 一つ削除したら`2`、配列の長さは次のようになります。`2 < k`, したがって、それ以上の操作はできません。 削除を常に利用可能であるものとして扱う単純なアプローチでは、誤った答えが返されます。`YES`。 

もう 1 つの微妙なケースは、配列に重要な値のコピーが多数含まれている場合に発生します。```
5 4
1 2 1 2 2
```答えは`YES`。 重要な値の一部のコピーは削除される可能性がありますが、他のコピーは残しておく必要があります。 その値のすべてのコピーを永続的に固定されたものとして扱うのは正しくありません。 

## アプローチ

 ブルートフォースアプローチでは、プロセスを直接モデル化しようとします。 すべての状態で、すべての有効なサブ配列を列挙し、それらのサブ配列を決定することができます。`k`- 番目に小さい値を使用して、考えられるすべての削除を生成し、検索を続行します。 これは、あらゆる法的な操作シーケンスを調査するため、理論的には正しいです。 

状態空間はほぼ即座に爆発します。 中程度の場合でも`n`、到達可能な配列の数は膨大になります。 以来`n`到達する`2·10^5`、この方向性は完全に不可能です。 

画期的な点は、削除可能な要素をグローバルに特徴付けることです。 

配列をソートしてみましょう`x`になる`(k-1)`- 1 から始まるインデックスを使用した、配列全体の中で 2 番目に小さい要素。 同様に、`x`インデックスの値です`k-1`並べ替え後。 

重要な事実は、`k-1`グローバルに最小の要素がすべて消えることはありません。 すべての削除では、削除された要素に少なくとも`k-1`選択した部分配列内のそれ以下の要素。 世界最小に属する要素`k-1`ポジションはこれを決して満たすことはできません。 

コンバースは意外と強いです。 世界最小の要素に含まれない要素`k-1`要素はいつでも削除できます。 公式社説は、保護されている限り、`k-1`要素が残っている場合は、ターゲット要素が正確になる適切な間隔を選択できます。`k`- 番目に小さい。 

これにより問題は完全に変わります。 

させて`x`の値になります`(k-1)`- 番目に小さい要素。 

厳密に次より大きいすべての値`x`は自由に削除できるため、そのような値を保持する理由はありません。 

より厳密に小さい値`x`アンタッチャブルです。 

以下に等しい値`x`は柔軟な部分です。 保護されたセットに属するコピーもあれば、属さないコピーもあります。 一部のコピーを削除する場合があります`x`、でも少なくとも出発しなければなりません`k-1`全体的な要素。 

より大きい値をすべて削除した後、`x`、縮小された配列を取得します`b`値だけで構成される`< x`と価値観`= x`。 

ここで、一部のコピーを削除するかどうかを判断する必要があります。`x`作ることができます`b`回文。 

これは貪欲な 2 点問題になります。 

ポインタを両端から移動します。 

値が一致する場合は、両方を保持します。 

それらが異なっていて、どちらの側も等しい場合`x`の場合、両方の値が保護され、削除できなくなります。 答えはすぐに`NO`。 

片方の辺が等しい場合`x`、そのコピーを削除します`x`そして続けます。 

これはそれらのみを貪欲に削除します`x`消えざるをえない価値観。 できるだけ多くの要素を維持したいので、これが最良の戦略です。 

最後に、生き残る要素の数を数えます。 未満の場合`k-1`要素が残っていると、保護された位置を削除しすぎてしまいますが、これは不可能です。 それ以外の場合の答えは、`YES`。

 ## アルゴリズムのチュートリアル

 1. 配列のコピーをソートします。 
2. 探す`x`、位置の値`k-1`ソートされた配列内。 
3. 新しいアレイを構築する`b`要素のみを含む`<= x`。 

より大きいすべての値`x`いつでも削除できるので、保存しておいても役に立ちません。 
4. 2 つのポインタを初期化します。`l = 0`そして`r = len(b)-1`。 
5. カウンターを維持する`kept`、最初は`len(b)`。 
6. ながら`l < r`:

 1. もし`b[l] == b[r]`、両方の要素を保持し、両方のポインターを内側に移動します。 
2. もし`b[l] != b[r]`そして`b[l] == x`の左側のコピーを削除します。`x`、デクリメント`kept`、増加します`l`。 
3. もし`b[l] != b[r]`そして`b[r] == x`の右側のコピーを削除します。`x`、デクリメント`kept`、および減少`r`。 
4. どちらの辺も等しい場合`x`、 戻る`NO`。 

内部にある唯一の取り外し可能な要素`b`のコピーです`x`。 不一致が生じた場合は、取り外し可能な面をすぐに取り外す必要があります。 
7. ループ後、次のことを確認します。`kept >= k-1`。 
8. true の場合は戻ります`YES`; それ以外の場合は戻る`NO`。 

### なぜ効果があるのか

 世界最小`k-1`要素は保護されたコアを形成します。 有効な最終配列にはそれらが含まれている必要があります。 より大きいすべての値`x`は常に削除できるため、そのような値を保持しておくと回文の作成に役立ちません。 

より大きい値をすべて削除した後、`x`、残りの唯一の取り外し可能な要素はコピーです`x`。 2 ポインタ スキャン中に、端が異なり、どちらの端も等しくない場合`x`の場合、2 つの保護された値が一致しません。 どちらも削除できないため、回文は作成できません。 

片側が等しいときはいつでも`x`、そのコピーの削除は強制されます。 保護された要素と互換性のある回文は、最終的には破棄する必要があります。 貪欲スキャンでは、これらのコピーが正確に削除されます。`x`これらは必要であり、他のすべての要素は保持されます。 

このアルゴリズムでは、次の要素に等しい最小数の要素が削除されるため、`x`、この最大サイズの回文候補に含まれる内容が`k-1`要素を含む場合、有効な操作シーケンスは存在できません。 逆に言えば、少なくとも`k-1`要素が残っている場合、必要な削除は上記の特徴付けによって実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k == 1:
            ans.append("YES")
            continue

        s = sorted(a)
        x = s[k - 1]

        b = [v for v in a if v <= x]

        l = 0
        r = len(b) - 1
        kept = len(b)

        ok = True

        while l < r:
            if b[l] == b[r]:
                l += 1
                r -= 1
            elif b[l] == x:
                kept -= 1
                l += 1
            elif b[r] == x:
                kept -= 1
                r -= 1
            else:
                ok = False
                break

        if ok and kept >= k - 1:
            ans.append("YES")
        else:
            ans.append("NO")

    sys.stdout.write("\n".join(ans))

solve()
```最初のステップでは、しきい値を計算します。`x`。 これは、常に削除可能な要素と、残しておく必要がある要素を区別する値です。 

配列`b`より大きいすべての値を削除します`x`。 これらの要素は、成功したソリューションであれば事前に削除できるため、無関係です。 

2 ポインター ループは、貪欲な回文構築を実行します。 両端が一致する場合、それらは明らかに最後の回文に属することができます。 それらが異なる場合、内部の唯一の合法的な削除`b`のコピーです`x`したがって、不一致が含まれる場合は、`x`そのコピーを削除することで解決されます。 

変数`kept`どれだけの要素が生き残るかを追跡します。 これは、後で削除を数えるよりも若干簡単で、多数のコピーがある場合の間違いを避けることができます。`x`が削除されます。 

最終条件`kept >= k - 1`が不可欠です。 保護されたコアには以下が含まれます`k-1`したがって、実行可能な最終配列には少なくともその数の要素が含まれている必要があります。

 次のことを考慮してください。```
1
4 1
1 1 2 1
```以来`k=1`、すべての要素は取り外し可能です。 アルゴリズムはすぐに戻ります`YES`。 任意の配列は、単一の要素または空の配列 (どちらも回文) に縮小できます。 

考慮する：```
1
3 3
1 2 2
```ソートされた配列は`[1,2,2]`、 それで`x=2`。 縮小された配列はそのまま残ります`[1,2,2]`。
