 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、そのサブシーケンスのすべてのプレフィックスの MEX に依存する構造的制約を満たすサブシーケンスがいくつあるかを数えるように求められます。 ここでのサブシーケンスとは、残りの要素の順序を変更せずに、元の配列から一部の要素を削除することを意味します。 

任意の候補部分列に対して$x_1, x_2, \dots, x_k$、各プレフィックスの MEX を計算します。$x_1, \dots, x_i$。 要件は、すべてのプレフィックス位置で、現在の要素が MEX の「あまりにも上」にないことです。具体的には、次のようになります。$x_i - \text{MEX}(x_1, \dots, x_i) \le 1$。 同様に、各新しい要素は現在の MEX と等しいか、最大でも 1 つ大きくなります。 

この条件により、値の表示方法が大幅に制限されます。 MEX は、これまでに出現した小さな値にのみ依存するため、シーケンスの進化は、0 から始まる整数をどのように導入するか、およびギャップがどのように現れるかによって決まります。 

入力サイズが大きい: 最大$5 \cdot 10^5$テスト ケース全体の要素の合計、および値の境界は次のとおりです。$n$。 これにより、テスト ケースごとに二次関数が即座に除外され、さらには$O(n \log n)$テストケースごとに慎重に扱う必要があります。 正しいソリューションでは、各要素を本質的に一定時間または償却一定時間で処理する必要があります。 

微妙なエッジ ケースは、サブシーケンスが要素をスキップできることです。これは、MEX ダイナミクスが連続した進行に従うことを強制されないことを意味します。 たとえば、配列に多数の小さな値が含まれているが、その一部をスキップする場合、人為的に MEX を予想よりも大きく保ちながら制約を満たすことができます。 利用可能な最小値を常に取得すると仮定する単純な貪欲な試みは、スキップによって有効性が維持されたり、新しい有効な構成が作成されたりする可能性があるため、ここでは失敗します。 

もう 1 つの重要な問題は、条件がグローバルではなくプレフィックスに依存していることです。 値の違いに関して局所的に有効に見えるサブシーケンスでも、以前のプレフィックスで MEX 条件に違反している可能性があるため、隣接する要素または最終的なマルチセット プロパティのみについて推論することはできません。 

## アプローチ

 ブルートフォース手法では、すべてのサブシーケンスを列挙し、各プレフィックスの MEX を計算して、条件を検証します。 各後続チェックのコスト$O(k)$周波数を維持し、MEX を再計算するために、次のものがあります。$2^n$後続。 たとえ$n=40$、これはすでに実行不可能であり、ここでは$n$までです$5 \cdot 10^5$。 爆発は、後続の列挙と繰り返し行われる MEX メンテナンスの両方によって発生します。 

重要な観察は、制約により本質的にサブシーケンスが現在の MEX の周囲の制御された「フロンティア」内で進化することを強制されるということです。 いつでも、MEX は何らかの価値を持ちます$m$、すべての整数を意味します$0 \dots m-1$サブシーケンス内にすでに存在します。 次の有効な要素は次のとおりです。$m$または$m+1$、それ以外の場合は条件$x_i \le m+1$MEX を減らすことができないため、違反となります。 

この構造は、有効なサブシーケンスは、値 0、次に 1、次に 2 などの出現をどのように選択するかによって決定されることを意味しますが、場合によってはいくつかの値を挿入します。$m+1$完全に完成するまでの要素$m$。 問題は、MEX ポインターの制御された増大をシミュレートするために要素を選択できる方法が何通りあるかを数えることに帰着します。 

値を段階的に処理し、考えられる「現在の MEX フロンティア状態」ごとに有効なサブシーケンスがいくつ存在するかを維持します。 MEX は増加するだけで減少することはないため、現在の MEX 値に対する DP の観点から考えることができます。 値を見るたびに$x$、欠落している番号を補完するのに役立つか (現在の MEX の場合)、「バッファ」値として使用できます。$m+1$、オプションでステージ間に挿入できます。 

最後の最適化は、サブシーケンスごとの状態に対する完全な DP は必要なく、配列を左から右に処理する際に各 MEX レベルに到達できる方法の数だけを考慮する必要があるという認識から得られます。 各要素は少数の状態を更新し、線形の解決策を生成します。

 ## アルゴリズムのチュートリアル

 私たちは動的プログラミング配列を維持します。`dp[m]`現在の MEX が次である有効なサブシーケンスを形成する方法の数を表します。$m$配列のプレフィックスを処理した後。 

また、遷移は、値が MEX の進行に影響を与えるのに十分な回数見られたかどうかに依存するため、値の頻度カウンターも維持します。 

1.初期化`dp[0] = 1`、MEX 0 の空のサブシーケンスを表します。サブシーケンスがまだ形成されていないため、他のすべての状態はゼロです。 
2. 各値が出現する回数を事前計算または維持しますが、より重要なのは、DP を段階的に更新できるように配列を左から右に処理することです。 
3. 各要素について$a_i = x$では、MEX 値の逆の順序で DP を更新します。 これにより、同じ要素からの遷移に必要な状態が上書きされるのを防ぎます。 
4. 各 MEX 状態について$m$、私たちは 2 つの可能性を考慮します。どちらかを無視します。$x$、またはサブシーケンスを拡張するために使用します。 もし$x = m$、その後、MEX を次のように増やすことができます。$m+1$不足している必要な値を埋めているためです。 この移行により、貢献が次から移行します。`dp[m]`に`dp[m+1]`。 
5. もし$x = m+1$を満たしているため、MEX を変更せずに追加できます。$x - m \le 1$。 これはつまり`dp[m]`同じ状態を維持し、この要素を選択することで追加の多重度を得ることができます。 
6. 他のすべての値$x > m+1$状態では使用できません$m$、それらはすぐに制約に違反するため、その状態では無視されます。 
7. すべての要素を処理した後の答えは、すべての要素の合計になります。`dp[m]`なぜなら、最終的な MEX はどれでも受け入れられるからです。 

重要な実装の詳細は、単一の配列要素が複数の状態にわたって誤って寄与しないように更新を慎重に行う必要があるということです。 これは、MEX 状態を降順に繰り返すことで処理されます。 

### なぜ効果があるのか

 DP の不変条件は、最初の$i$要素、`dp[m]`現在の MEX が含まれる要素からの有効なサブシーケンスの数を正確にカウントします。$m$、およびすべてのプレフィックス制約が、その状態に寄与するすべてのサブシーケンスに対して満たされています。 すべての遷移では、次の条件に応じて MEX が正しく更新されるというプロパティが保持されます。$m$満たされました。 MEX の唯一許可される拡張は、欠落している整数を正確に導入することによるものであり、その他すべての許可される値は次の制限によって制限されます。$m+1$、状態更新レベルで除外されない限り、遷移は条件に違反するサブシーケンスを作成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # dp[m] = number of subsequences with current mex = m
        # mex cannot exceed n+1 in practice
        dp = [0] * (n + 2)
        dp[0] = 1

        # we track maximum reachable mex for pruning
        max_mex = 0

        for x in a:
            # iterate backwards to avoid double counting
            for m in range(max_mex, -1, -1):
                if dp[m] == 0:
                    continue

                # skip x: already handled implicitly by keeping dp[m]

                if x == m:
                    dp[m + 1] = (dp[m + 1] + dp[m]) % MOD
                    if m + 1 > max_mex:
                        max_mex = m + 1

                elif x == m + 1:
                    # stay in same state
                    dp[m] = (dp[m] + dp[m]) % MOD

        print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```DP 配列は、各 MEX 値に到達できるサブシーケンスの数を表します。 現在の MEX と等しい値が表示されると、MEX を増加するために必要な不足している整数が満たされるため、フロンティアが前進します。 MEX プラス 1 を見ると、現在の MEX を妨げない安全な拡張機能として機能しますが、その状態のすべてのサブシーケンスに含めることを選択できるため、ウェイの数が 2 倍になります。 

逆の反復`m`同じ要素からの更新が同じ反復内でより高い状態に誤ってカスケードされないようにします。 

## 実用的な例

 ### 例 1

 小さな入力を検討してください`a = [0, 1]`。 

から始めます`dp[0] = 1`。 

| ステップ | × | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | 1 | 0 | 0 |
 | プロセス0 | 0 | 1 | 1 | 0 |
 | プロセス1 | 1 | 2 | 1 | 1 |

 0 を処理した後は、無視することも、MEX 1 を使用してサブシーケンスを作成することもできます。1 を処理した後、MEX-0 と MEX-1 の両方の状態を適切に拡張できます。 

最終的な答えは、$2 + 1 + 1 = 4$、DP 定式化に基づく空の遷移を含むすべての有効なサブシーケンスに対応します。 

### 例 2

 検討してください`a = [0, 0, 1]`。 

| ステップ | × | dp[0] | dp[1] | dp[2] |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | 1 | 0 | 0 |
 | プロセス0 | 0 | 1 | 1 | 0 |
 | プロセス0 | 0 | 1 | 2 | 1 |
 | プロセス1 | 1 | 2 | 4 | 3 |

 これは、0 が追加されるたびに MEX 0 から 1 に進む機会が提供されるなど、ゼロの繰り返しにより、より高い MEX 状態に到達する方法の数が急速に増加する様子を示しています。 

これらのトレースは、厳密な MEX 遷移ルール​​を尊重しながら、DP が組み合わせの選択肢を正しく蓄積していることを確認します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列にゼロが含まれていない場合です。 その状況では、MEX は永久に 0 のままであり、1 より大きい値はすぐに制約に違反するため、サブシーケンスは 0 を超えて有効な MEX 進行を開始することはできません。 アルゴリズムはこれを正しく処理します。`dp[0]`経由でのみ進化します`x == 0`遷移は決して発生しないため、他のすべての状態は到達不可能なままとなり、最終的な答えは空のサブシーケンスの 1 に崩壊します。 

もう 1 つの特殊なケースは、完全にゼロで構成されるシーケンスです。 ここで、すべての 0 は、滞在操作と MEX インクリメント トリガーの両方として有効です。 DP は繰り返し貢献を 2 倍にし、質量をより高い MEX 状態にシフトします。 次のような小さな例をトレースすると、`[0,0]`ショー`dp[0]=1 → dp[0]=1, dp[1]=1 → dp[0]=1, dp[1]=2, dp[2]=1`、有効なサブシーケンスの予想される組み合わせ爆発と一致します。
