 ## 問題の理解

 長さの順序付けされた配列をすべて見るように求められます。$m$合計が固定されている非負の整数で構成されます。$n$。 このような配列はすべて、そのすべての要素のビットごとの XOR に等しい値を提供します。すべての有効な配列に対するこれらの XOR 値の合計が必要です。 

入力をイメージするのに役立つ方法は、次のようなものを配布していることです。$n$同一のユニットに$m$ラベルが貼られた箱。 各分布は配列を定義します$a_1, a_2, \dots, a_m$。 分布ごとに 2 番目の値を計算します。つまり、すべての分布のバイナリ表現を取得します。$a_i$、それらを XOR して、その結果をグローバル合計に加算します。 

制約があるからこそ面白いのです。 合計$n$と同じ大きさにすることができます$10^{15}$したがって、構成を列挙したり、構成に比例するものを保存したりすることさえできません。$n$。 箱の数$m$は最大でも 500 ですが、これは位置ごとの組み合わせ動的計画法が妥当であるほど十分に小さいです。 すべてのコンポジションを反復処理するか、DP を使用するかに応じたソリューション$n$直接的には実行不可能です。$n$遅すぎるでしょう。 

素朴なアプローチもまた、微妙な方法ですぐに壊れます。 たとえば、次の場合$m = 2$そして$n = 10$、有効なペアはすでに 11 番であり、各ペアは XOR 演算される必要があります。 これをスケーリングすると$n = 10^{15}$ブルート フォースは完全に不可能になりますが、さらに重要なのは、分割によって段階的に状態を生成しようとすることさえも不可能になることです。$n$指数関数的な爆発を引き起こします。 

もう 1 つのよくある失敗例は、ビットを独立して処理しようとすることです。 それぞれのビットを誤って仮定すると、$a_i$ビットごとの合計制約のみに従って独立して割り当てることができるため、ビット間の桁上げ伝播は無視されます。 例えば、$a_i = 1$そして$a_i = 2$どちらも加算構造を通じて複数のビット位置に寄与しますが、ビット レベルでは動作が大きく異なります。 

本当の難しさは、その条件です。$\sum a_i = n$はバイナリキャリーを通じてすべてのビットを結合しますが、XOR は列値のビットごとのパリティのみに依存します。 

## アプローチ

 直接的な総当り戦略では、すべてが生成されます。$m$- 非負の整数のタプルの合計$n$、次にそれらの XOR を計算します。 これは基本的に、以下のすべての弱い組成を列挙することになります。$n$の中へ$m$部品。 このようなタプルの数は$\binom{n+m-1}{m-1}$、それはすでに天文学的な大きさです$n$までです$10^{15}$。 小さいものでも$n$、すべての有効なタプルを反復処理することは現実的ではなく、各タプルには次のものが必要です。$O(m)$XOR を計算する作業。 

重要な構造的観察は、制約が$\sum a_i = n$はバイナリ加算制約です。 各ビット位置は、キャリーを除き、独立して合計に寄与します。 これは、加算時の数字 DP とまったく同じように、下位ビットからのキャリーを維持しながら、数値をビットごとに処理することを示唆しています。 

ただし、有効な割り当てをカウントしているだけではなく、XOR 値も累積しています。 ビット位置での XOR は、$a_i$そのビット、特にそのパリティに 1 があります。 これにより、加算制約を通じてグローバルな妥当性を維持しながら、問題をビットごとの寄与に分割することができます。 

したがって、解決策はバイナリ位置に対する DP になります。各状態は、次の位置への特定のキャリーを持つビットの部分割り当てを形成できる方法が何通りあるかを追跡し、同時に、すでに固定されている下位ビットによって寄与される XOR 寄与の合計を累積します。

 ## アルゴリズムのチュートリアル

 のバイナリ表現を処理します。$n$最下位ビットから最上位ビットまで。 各ビット位置で、$m$数値は、ビットの合計が一致する必要があることを考慮しながらビットを分配します。$n$キャリーも含めて。 

ビットのプレフィックスを処理した後に特定のキャリーに到達できる方法の数と、処理されたビットからすでに蓄積された XOR 寄与の量を追跡する DP 状態を定義します。 

### ステップ

 1. 二項係数を事前計算します$C(m, k)$みんなのために$0 \le k \le m$。 これが必要なのは、各ビットで正確にいくつのビットを選択するためです。$m$数字のその位置には 1 があります。 
2. DP テーブルを初期化します。初期状態ではキャリーと XOR 寄与がゼロであり、処理されたビットがないことを表します。 
3. 各ビット位置について$pos$0 から約 60 まで、現在の DP 状態を取得し、その数について考えられるすべての選択肢を試します。$k$中に現れます$m$このビットの数値。 

選択する$k$組み合わせ要因に寄与する$C(m, k)$、どれを選択しているので、$k$インデックスにはビット 1 があります。 
4. このビットにキャリーされる電流を次のようにします。$c$、そしてさせてください$n_{bit}$になる$pos$-番目のビット$n$。 すべての数値のこの位置にあるビットの合計は次のようになります。$k + c$。 

この合計は、次の 2 進加算制約を満たす必要があります。$$k + c \equiv n_{bit} \pmod{2}$$そして次のキャリーは次のようになります。$$c' = \frac{k + c - n_{bit}}{2}$$5. 有効な遷移ごとに、2 つの数量を更新します。 まず、ウェイの数は次のように乗算されます。$C(m, k)$。 第 2 に、このビットでの XOR 寄与は次のいずれかによって決まります。$k$の XOR なので奇数です$k$1 は 1 であれば$k$奇数です。 1の場合は追加します$2^{pos}$この移行に寄与する方法の数を掛けたものです。 
6. これらの遷移を次の DP 状態に蓄積します。$c'$。 
7. すべてのビットを処理した後の答えは、最終キャリーがゼロのすべての DP 状態にわたる合計 XOR 寄与です。 

### なぜ効果があるのか

 DP は、キャリー付きの 2 進加算と同じように、合計制約の正確性を強制します。 すべての有効なタプルは、ビット選択とキャリーの 1 つのシーケンスに正確に対応します。 組み合わせ係数により、すべての 1 ビットの割り当てが確実にカウントされます。$m$正しく位置決めします。 XOR の累算はビット全体で線形であるため、異なるビット位置からの寄与が干渉することはなく、遷移中に安全に合計できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    max_c = m

    # precompute binomial coefficients
    C = [[0] * (m + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        C[i][0] = 1
        for j in range(1, i + 1):
            C[i][j] = (C[i - 1][j] + C[i - 1][j - 1]) % MOD

    # dp[carry] = (ways, xor_sum)
    dp = [[0, 0] for _ in range(m + 1)]
    dp[0][0] = 1

    for bit in range(61):
        ndp = [[0, 0] for _ in range(m + 1)]
        nb = (n >> bit) & 1

        for carry in range(m + 1):
            ways, xs = dp[carry]
            if ways == 0:
                continue

            for k in range(m + 1):
                comb = C[m][k]
                if comb == 0:
                    continue

                total = k + carry
                if (total & 1) != nb:
                    continue

                nc = (total - nb) // 2
                if nc < 0 or nc > m:
                    continue

                nways = ways * comb % MOD

                # xor contribution from this bit
                if k & 1:
                    add_xor = (nways * ((1 << bit) % MOD)) % MOD
                else:
                    add_xor = 0

                ndp[nc][0] = (ndp[nc][0] + nways) % MOD
                ndp[nc][1] = (ndp[nc][1] + xs * comb % MOD + add_xor) % MOD

        dp = ndp

    print(dp[0][1] % MOD)

if __name__ == "__main__":
    solve()

微妙な点は、`ways`そして`xor_sum`。 XOR の合計は、状態に到達する方法の数に依存するため、すべての遷移は乗算と加算の両方で更新されます。 これらを誤って混合すると、過剰カウントの一般的な原因になります。

 ## 特殊なケース

 のために$n = 0$、すべての配列は強制的にすべてゼロになります。 DP はゼロキャリーから開始され、ただちに 1 つの有効な設定のみを伝播します。 あらゆる点で、ただ$k = 0$は有効であるため、XOR は常に 0 であり、最終出力は 0 のままです。 

のために$m = 1$、変数は 1 つだけです$a_1 = n$。 DP は、キャリーが常に一致する単一のパスを追跡することになります。$n$、XOR が等しい$n$XOR には値が 1 つしかないため、それ自体が存在します。
