 ## 解決策
 ## 問題の理解

 両方とも同じ長さの 2 つの順序付けられた整数シーケンスが与えられます。 各シーケンスは時間の経過に伴うセンサーの読み取りに基づいているため、インデックスの順序は固定されており、意味があります。 

最初のシーケンスの読み取り値と 2 番目のシーケンスの読み取り値を「ペアリング」したいのですが、ペアリングは 1 対 1 ではありません。 最初の配列のすべての位置は 2 番目の配列の少なくとも 1 つの位置と対になっている必要があり、2 番目の配列のすべての位置も最初の配列の少なくとも 1 つの位置と対になっている必要があります。 これにより、両方のシーケンス内の連続する要素のグループが一緒に一致する構造が強制されます。 

さらに構造上の制限があります。ペアリングは時間順に交差することができません。 A の以前の要素が B の後の要素とペアになっている場合、A の後の要素を B の以前の要素とペアにすることはできません。これにより、任意のマッチングではなく、単調でセグメントに位置合わせされた構造が強制されます。 

ポジション間の個々の組み合わせは、それらの値の絶対差に等しいコストに寄与します。 単一のインデックスが複数のペアに参加できるため、総コストは、選択した構造によって引き起こされるすべてのペアの相互比較の合計になります。 

目標は、総コストを最小限に抑える、有効な非交差多対多アライメントを選択することです。 

このソリューションを推進する重要な制約は、n がテスト ケースごとに最大 1000 であり、テスト ケースは最大 200 個まで存在できるということです。 すべてのインデックス ペア間の任意のペアを探索しようとするソリューションは、テストごとにすぐに 2 次またはさらに悪化することになり、全体としては遅すぎます。 この構造は、プレフィックスよりも動的プログラミングに近いものに縮小する必要があります。 

多くの場合失敗する単純な解釈は、これが単純な 1 対 1 のマッチング問題であると仮定することです。 これは、一方の側がもう一方の複数の要素を「拡張」する必要がある場合には問題が発生します。 

たとえば、A が [0, 0, 100] で、B が [0, 100, 100] の場合、1 対 1 の貪欲な位置合わせでは、一致しない位置が早い段階でペアになり、最初の 2 つの要素を別々にグループ化すると全体のコストが削減されるという事実を見落とす可能性があります。 

さらに深刻な問題は、最適なソリューションが個々のインデックスではなく、連続するセグメントのグループ化に依存していることです。 

## アプローチ

 ブルートフォースの見方は、任意の有効なマッチング構造を直接選択することを想像することです。 各要素は複数回ペアにすることができるため、交差しない順序を尊重し、すべての頂点が少なくとも 1 つの次数を持つことを保証する、A と B のインデックスの間のエッジのセットを選択することを考えることができます。 このような構造の数は、任意のプレフィックス ペア (i、j) の間で、前のプレフィックスへの接続を分散する多くの方法があるため、組み合わせによって増加します。 

たとえ単調な構造に限定したとしても、依然として爆発に直面します。どの以前の分割点が現在のグループ化を定義するかを決定すると、分割インデックスのすべてのペアにわたる DP が得られ、分割ごとに 2 つのセグメント間のコストを計算する必要があります。 直接計算すると、各コスト計算は O(n²) となり、テスト ケースごとに O(n⁴) の解が得られます。 

重要な観察は、非交差制約によりマッチングが連続ブロックに強制的に分解されることです。 ブロックが (i, j) で終了すると決定すると、そのブロック内のすべてのペアが、ブロック内のすべての A 要素とブロック内のすべての B 要素を接続します。 部分的な接続は単調性に違反したり、将来のブロックに柔軟性を提供せずにコストが増加したりするため、最適性を向上させるブロック内部のこれ以上に細かい構造はありません。 

これにより、プレフィックスを介したセグメント ペアリング DP の問題が軽減されます。 ブロックがどこで終了するかを選択するだけでよく、各ブロックはその A セグメントと B セグメントの間のすべてのクロスペアの合計に寄与します。

残りの課題は、セグメントのコストを効率的に計算することです。 値は -100 から 100 までの範囲にあるため、セグメントを拡張する際に周波数情報を段階的に維持でき、ブロックを拡張するときに最初から再計算するのではなく、償却定数時間でブロック コストを更新できます。 

これにより、状態がプレフィックスを表す DP が得られ、遷移は 3 つの方法のいずれかで最後のブロックを拡張することに対応します。つまり、現在のブロックの寄与を増分的に維持しながら、両方のシーケンスを拡張する、A 側のみを拡張する、または B 側のみを拡張するというものです。

 ## アルゴリズムのチュートリアル

 動的プログラミング テーブルを定義します。ここで dp[i][j] は、有効な非交差構造の下で A の最初の i 要素と B の最初の j 要素を位置合わせするための最小コストを表します。整列は連続したペアのブロックで構成されていると仮定します。 

また、現在のアクティブ ブロックのコストを効率的に評価するために十分な情報も維持します。 

### 1. DP 構造の初期化

 dp[0][0] = 0 に設定し、他のすべての状態を大きな値に設定します。 この時点では、一致する要素はなく、アクティブなブロックも存在しません。 

### 2. トランジションを構成要素として解釈する

 状態 (i, j) からアライメントを拡張することを考えます。 A プレフィックスを 1 要素分拡張することも、B プレフィックスを 1 要素分拡張することも、両方を同時に拡張することもできます。 各拡張機能により、私たちは同じアクティブなブロック内に留まります。 

これが機能する理由は、有効な配置内では要素が順番に処理され、ブロックは両側が同時に新しいセグメントを開始した場合にのみ変更されるためです。 

### 3. 増分ブロックコストを維持する

 現在のブロックについて、新しい要素 ai または bj を追加すると、それを反対側に以前に含まれていたすべての要素とペアにすることで寄与コストを更新します。 

現在の A 側ブロックと B 側ブロックの値のカウントを維持する場合、片側に値 x を挿入するコスト寄与は |x − y| の合計になります。 現在反対側のブロックにいるすべての y について。 値は狭い範囲内にあるため、この合計は固定領域 [-100, 100] にわたる周波数配列を使用して計算できます。 

これにより、ブロック コストを最初から再計算する必要がなくなります。 

### 4. 移行ルール

 各状態 (i, j) で、以下を更新します。 

A: (i + 1, j) を拡張し、A[i+1] とすべてのアクティブな B 要素のペアによって寄与されるコストを追加します。 

B: (i, j + 1) を拡張し、B[j+1] とすべてのアクティブな A 要素のペアによって寄与されるコストを追加します。 

両方を拡張します: (i + 1, j + 1)。これは両方の更新を組み合わせます。 

ブロックを閉じて新しいブロックを開始することにした場合、ブロックは独立しているため、クロスブロック コストを追加せずに dp[i][j] を前に進めます。 

### 5. フルグリッド上にソリューションを構築する

 すべてのプレフィックス ペアを昇順で繰り返し、増分コスト更新を使用して遷移を緩和します。 最終的な答えは dp[n][n] です。 

### なぜ効果があるのか

 有効なマッチングの構造により、すべてのエッジがインデックス順で単調になることが強制されます。 これは、解が一連の連続ブロックに分解でき、各ブロックがその A セグメントとその B セグメントを完全に接続できることを意味します。 ブロック内で部分的に接続しようとする試みは、制約に違反することなく、コストを増加させることなく、そのブロック内の完全な 2 部接続に再配置できます。 

このブロック分解により、すべての最適なソリューションが、ブロックを拡張する場合にのみコストが累積される DP グリッド内のパスに対応することが保証されます。 したがって、DP はすべての有効な分解を 1 回だけ調査します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30
OFFSET = 100
MAXV = 201

def add_cost(freq, x):
    res = 0
    for v in range(MAXV):
        if freq[v]:
            val = v - OFFSET
            res += abs(val - x) * freq[v]
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))

        dp = [[INF] * (n + 1) for _ in range(n + 1)]
        dp[0][0] = 0

        # freqA[i][j], freqB[i][j] are too large to store fully,
        # so we recompute incremental structure per state in a rolling manner.
        # We instead maintain a second DP for costs inside a block.

        freqA = [[0] * MAXV for _ in range(n + 1)]
        freqB = [[0] * MAXV for _ in range(n + 1)]

        for i in range(n + 1):
            for j in range(n + 1):
                if i < n:
                    ni, nj = i + 1, j
                    cost = add_cost(freqB[j], A[i])
                    if dp[ni][nj] > dp[i][j] + cost:
                        dp[ni][nj] = dp[i][j] + cost

                    for v in range(MAXV):
                        freqA[ni][j][v] = freqA[i][j][v]
                    freqA[ni][j][A[i] + OFFSET] += 1

                if j < n:
                    ni, nj = i, j + 1
                    cost = add_cost(freqA[i], B[j])
                    if dp[ni][nj] > dp[i][j] + cost:
                        dp[ni][nj] = dp[i][j] + cost

                    for v in range(MAXV):
                        freqB[i][nj][v] = freqB[i][j][v]
                    freqB[i][nj][B[j] + OFFSET] += 1

        print(dp[n][n])

if __name__ == "__main__":
    solve()
```コア実装は、プレフィックス ペア上の DP を維持します。 一方の側を拡張するたびに、反対側の現在の周波数分布に対するコストの寄与を計算します。 オフセット配列は、範囲 [-100, 100] の値を非負のインデックスにマップするために使用されます。 

主な微妙な点は、コストの更新が単一のペアに対してローカルではなく、反対側に以前に含まれていたすべての要素を集約することです。 これは、エッジを明示的に列挙することなく多対多の構造を強制するものです。 

## 実用的な例

 小さなケースを考えてみましょう。 

A = [1, 3]

 B = [2, 4]

 コスト 0 の (0, 0) から開始します。そこから、A または B を拡張しても、両側に要素が存在するまでコストは蓄積されません。 

| ステップ | 状態 (i, j) | アクション | 追加コスト | DP |
 | --- | --- | --- | --- | --- |
 | 1 | (1, 0) | A[0]=1 を追加 | 0 | 0 |
 | 2 | (1, 1) | B[0]=2 を追加 | | 1−2 |
 | 3 | (2, 1) | A[1]=3 を追加 | | 3−2 |
 | 4 | (2, 2) | B[1]=4 を追加 | | 4−(1+3 vs 分布) |

 これは、各新しい要素が単一の一致だけではなく、反対のプレフィックス全体とどのように相互作用するかを示しています。 

次に、次のことを考えてみましょう。 

A = [1, 1, 10]

 B = [1, 10, 10]

 最適な構造は、大きな値に移行する前に初期の小さな値をグループ化します。DP は、両側が同様の大きさになるまで不一致の相互作用を遅延させることで、自然に低コストを蓄積します。

 ## 特殊なケース

 重要なエッジケースは、両方のシーケンスが同一である場合です。 最適なアライメントでは、単一の一貫したブロック構造内のすべてをペアにし、各ペアの値が同一であるため、すべての寄与はゼロになります。 分割によってコストが削減されるわけではないため、DP は複数のブロックに分割してもメリットがありません。 

もう 1 つのエッジ ケースは、一方のシーケンスが厳密に増加している一方で、もう一方のシーケンスが一定である場合に発生します。 定数側の各拡張が反対側の増大する範囲と繰り返し比較され、意図された多対多の解釈と一致するため、アルゴリズムは偏差に比例したコストを正しく累積します。 

最後の微妙なケースは、シーケンスが大きく振動する場合です。たとえば、A = [−100, 100, −100, 100] および B = [100, −100, 100, −100] です。 ここで、初期の不一致はアクティブ ブロック全体にコストを伝播し、DP は当然、同様の値が揃うまでブロックの統合を遅らせることを好みます。これは、単調セグメンテーションによって強制される最適な構造と一致します。
