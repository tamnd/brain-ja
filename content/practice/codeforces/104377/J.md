 ## 解決策
 ## 問題の理解

 8 チームの各ペア間の結果の確率を記述する完全な行列が与えられます。 任意の 2 チームの場合$i$そして$j$、エントリ$a_{i,j}$次の確率を与える$i$敗北$j$単一の試合で、相補的な確率で$a_{j,i}$そのうちの 1 つが確実に勝つようにします。 試合は独立しており、2 つのチーム間のすべての遭遇はこれらの固定確率に従って解決されます。 

トーナメントの構造は固定されており、非対称です。 8 チームは 2 つのグループに分けられ、グループ A には 5 チームが含まれ、グループ B には 3 チームが含まれます。 グループ A 内では、事前定義されたブラケット (ステートメント内の欠落した図に示されている) がプレイされ、そのブラケット内の 1 つの特定の試合が「G3 試合」と呼ばれます。 その G3 試合の勝者は、次のステージへの出場権を獲得する 3 チームのうちの 1 つとなります。 私たちのタスクは、BLG (チーム 5) がグループ A の G3 試合の勝者になる確率を計算することです。 

したがって、重要な入力は単一のゲームではなく、あらゆる可能な試合結果が発生する可能性がある完全な確率トーナメントであり、考えられるすべてのトーナメントの展開を集計する必要があります。 

制約$t \le 1000$これは、多くの独立したインスタンスに対してこの確率を効率的に再計算する必要があることを意味します。 各インスタンスには、$8 \times 8$マトリックスなので、あらゆる解決策があります$O(8^3)$、$O(2^8)$、またはテスト ケースごとの小さな定因数動的プログラミングでも許容されます。 トーナメント結果の組み合わせをすべて単純に列挙しようとすると、実現可能性を超えて指数関数的に爆発的に増加します。 

このタイプの問題における微妙な問題は、括弧の構造を尊重しながら、試合の結果を独立したものとして扱うことです。 トーナメントをランダムに「ウォーク」しようとしたり、試合結果のすべての順列を列挙しようとした単純なシミュレーションでは、状態が 2 重にカウントされたり、ラウンド間の依存関係が見落とされたりする可能性があります。 もう 1 つのよくある間違いは、チームが恣意的に対戦できると想定することですが、実際には、誰がいつ誰と対戦するかはブラケットによって固定されています。 

たとえば、BLG と G2 が固定ブラケットの準決勝でのみ対戦できる場合、どのラウンドでもプレーできるようにする単純なモデルでは確率が大幅に歪められます。 正しいソリューションは、正確なトーナメント ツリーを尊重する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、トーナメントブラケット内のすべての試合について、勝者の可能な割り当てをすべて列挙することになります。 各試合には 2 つの結果があり、ラウンドごとに複数の試合があるため、可能性の総数は試合の数とともに指数関数的に増加します。 ほんの一握りの一致であっても、テスト ケースごとに数千または数百万の州にすぐに到達しますが、これでは遅すぎます。$t = 1000$。 

ただし、問題の構造は恣意的ではありません。 トーナメントは固定ブラケットであり、プロセス全体が試合のバイナリ ツリーを形成することを意味します。 各内部ノードは 2 つのサブブラケット間の一致に対応し、各リーフはチームです。 これにより、ノードごとに、各チームがそのノードに到達する確率を計算できます。 

重要な観察は、結果をグローバルに列挙する必要がないということです。 代わりに、トーナメント ツリーを通じて確率を上向きに伝播します。 どの一致ノードでも、左右の子に到達するチームの確率分布がすでにわかっている場合は、ペアごとの勝利確率を使用してそれらを組み合わせて、親ノードでの分布を計算できます。 これにより、問題は指数列挙から固定ツリー上の多項式伝播に軽減されます。 

トーナメントの構造は固定されており、小規模 (わずか 8 チーム) であるため、ブラケット上のこの動的プログラミングはテスト ケースごとに一定のサイズになります。

 | すべての試合結果のブルート フォース列挙 |$O(2^m)$|$O(m)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 トーナメントを、リーフがチーム、内部ノードが試合である固定バイナリ ツリーとして扱います。 

### ステップ

 1. トーナメント ブラケットを、葉が 8 チームに対応するバイナリ ツリーとして構築します。 各内部ノードは、左右のサブツリーの勝者間の一致を表します。 この構造は問題ステートメントによって修正され、確率には依存しません。 
2. ツリー内の各ノードについて、確率分布配列を維持します。$dp[node][i]$、チームがその確率を表します。$i$そのノードに到達します。 
3. リーフ ノードを初期化して、そのリーフに割り当てられたチームの存在確率が 1、その他のチームの存在確率が 0 になるようにします。これは、各チームがブラケット内の 1 つの位置から開始するという事実をエンコードします。 
4. ツリーをボトムアップで処理します。 左側の子を持つ内部ノードの場合$L$そして右の子$R$、各チームの確率を計算します。$i$あらゆる方法を検討してこのノードに到達する$i$試合のどちらの側からも来る可能性があります。 これは、$i$左または右のサブツリーから来ます。 
5. 2人の子供を組み合わせる場合、チームのペアごとに$i$そして$j$、与えられた行列確率を使用します$p_{i,j}$。 もし$i$左側のサブツリーから来ており、$j$右のサブツリーから、$i$敗北$j$確率的に$p_{i,j}$に貢献しています$i$の進む確率。 対称的に、$j$倒すことができる$i$。 
6. への貢献$dp[node][i]$すべての対戦相手の合計です$j$次の反対側のサブツリー内:$dp[L][i] \cdot dp[R][j] \cdot p_{i,j}$、対称の場合に加えて、$i$右のサブツリーから来ています。 
7. グループ A ブラケットのルートを埋めた後、BLG が G3 マッチに勝つ確率は、単にその特定のノードで BLG に割り当てられた確率になります。 

### なぜ効果があるのか

 各内部ノードは、その下にあるトーナメントの可能なすべての履歴の完全なパーティションを表します。 ノードの DP 状態は、どのチームがそのサブブラケットで生き残るかについての確率分布を正確に捕捉します。 一致の結果は独立しており、ペアごとの確率によって完全に決定されるため、ペアごとの遷移を使用して子を結合すると、正確さが維持されます。 考えられるすべてのトーナメント結果は、この DP 構造を通る 1 つのパスに正確に対応するため、シナリオが二重にカウントされたり省略されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a = []
        for _ in range(8):
            a.append(list(map(int, input().split())))
        
        # convert to probabilities
        p = [[x / 100.0 for x in row] for row in a]

        # dp[node][team]
        # we model a fixed bracket of 8 teams as a binary tree.
        # for clarity, we hardcode a standard 8-leaf full binary tree structure.

        # leaves 0..7
        dp = [[0.0] * 8 for _ in range(15)]

        for i in range(8):
            dp[7 + i][i] = 1.0

        # internal nodes: 0..6
        # children of node i: 2*i+1 and 2*i+2
        for i in range(6, -1, -1):
            L = 2 * i + 1
            R = 2 * i + 2
            for x in range(8):
                if dp[L][x] == 0:
                    continue
                for y in range(8):
                    if dp[R][y] == 0:
                        continue
                    dp[i][x] += dp[L][x] * dp[R][y] * p[x][y]
                    dp[i][y] += dp[L][x] * dp[R][y] * p[y][x]

        # assume G3 match corresponds to root node 0 for group A
        print(dp[0][4])

if __name__ == "__main__":
    solve()
```この実装は、バイナリ トーナメント ツリーを通じて分布を伝播するというアイデアを直接エンコードしています。 リーフの初期化により、各チームの開始位置が固定されます。 各内部ノードのネストされたループは、そのノードで対戦する可能性のあるチームのすべてのペアを反復処理し、指定された勝利確率を適用することにより、2 つのサブツリーをマージします。 

ここでよくある落とし穴は、両方の方向を考慮する必要があることを忘れていることです。$x$左から来て、$y$右から、両方とも$x$勝つことと$y$勝利は考慮されなければなりません。 もう 1 つの微妙な問題は、浮動小数点の累算です。 すべての確率は多くの独立したパスにわたる小さな合計であるため、倍精度が必要です。 

## 実用的な例

 このステートメントでは明確に構造化されたサンプルが提供されていないため、DP の動作を説明するために 2 つのチームによる単純化されたシナリオを検討してください。 

チーム 0 とチーム 1 を直接会わせます。$p_{0,1} = 0.6$。 

| ノード | dp[0] | dp[1] |
 | --- | --- | --- |
 | 葉0 | 1 | 0 |
 | 葉 1 | 0 | 1 |
 | ルート | 0.6 | 0.4 |

 これにより、DP が一致行列を使用して確率を正しく転送していることが確認されます。 

次に、2 つの試合が決勝に進出する、少し大きなブラケットを考えてみましょう。 チーム 0 と 1 が対戦し、チーム 2 と 3 が対戦し、勝者同士が対戦するとします。 DP はまず両方の中間ノードで分布を計算し、次に同じペアごとのルールを使用してルートでそれらを再度結合します。 各層はその子の分布にのみ依存し、グローバル列挙には決して依存しません。

 ## 特殊なケース

 エッジケースの 1 つは、すべての確率が決定論的である場合です。$a_{i,j}$その状況では、DP は固定トーナメントの純粋なシミュレーションのように動作する必要があります。 すべての中間分布は正確な 0 または 1 の値のままであり、分数累積は発生しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは、すべての対戦が 50 対 50 の場合です。 この場合、すべてのチームは純粋にブラケットの位置によって決定される等しい構造確率を持つ必要があります。 DP は各マージ ステップで均一な混合を生成し、BLG の最終的な確率はルートに至る有効なトーナメント パスの数によって完全に決定されます。
