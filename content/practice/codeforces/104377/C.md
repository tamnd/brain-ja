 ## 解決策
 ## 問題の理解

 n 行 n 列の行列と一連の演算が与えられます。 各演算では、左上と右下の座標を使用して正方部分行列を選択し、その部分行列に 1 つの幾何学的変換を適用します。 変換は標準的な画像スタイルの操作です。時計回りに 90 度回転、水平反転、垂直反転、および 2 つの対角線を横切る反射です。 

すべての操作を順番に適用した後、最終的な行列を出力する必要があります。 

重要な点は、操作がグリッド全体ではなく部分行列にのみ適用されること、および同じセルが多くの重複する変換に関与する可能性があることです。 出力は、すべての変換の累積効果に依存します。 

この制約により、n は最大 500、最大 100 の操作が許可されます。 したがって、操作ごとに影響を受ける部分行列を再構築する直接シミュレーションが妥当です。これは、操作ごとに可能な最大の作業が 500 x 500 の領域 (約 250,000 セル) 上で行われ、これが最大 100 回繰り返され、約 2,500 万のセルが更新されるためです。 

エッジ ケースは主に、部分行列内で変換がどのように適用されるかによって発生します。 

最初の微妙な問題は、回転の正確さです。 回転中に行列をその場で上書きすると、移動前の値が破損します。 たとえば、一時バッファを使用せずに 3 x 3 ブロックを所定の位置で回転すると、後で回転マッピングで必要になるエントリが上書きされます。 

もう 1 つの問題は、インデックス作成の一貫性です。 入力は 1 ベースであるため、0 ベースのインデックスへの変換に失敗すると、結果が構造化されているように見えても正しくない可能性があるため、検出が困難な off-by-one の破損が発生します。 

最後に、対角反転には慎重な座標マッピングが必要です。 行と列を部分行列内ではなくグローバルに交換する単純な実装では、行列の無関係な部分が破壊されます。 

## アプローチ

 問題ステートメントの直後に総当り解釈が続きます。つまり、操作ごとに、部分行列を抽出し、新しい変換バージョンを構築し、それを書き戻します。 

これが機能するのは、各変換が正方形領域内の座標の固定順列であるためです。 サイズ k の部分行列の場合、O(1) 内の各要素の新しい位置を計算できるため、部分行列の再構築には O(k²) のコストがかかります。 各セルは、そのセルを含む部分行列が処理されるときにのみ書き換えられるため、総作業量は、影響を受ける領域のサイズを 2 乗したすべての操作の合計によって制限されます。 

最悪のケースは、すべての操作が n × n 行列全体に触れる場合に発生します。 この場合、各操作のコストは O(n²) であり、q が 100 までの場合、これは O(100 · 500²) となり、約 2,500 万回の割り当てになります。 これは Python では許容されます。 

重要な点は、グローバル座標追跡や遅延変換合成が必要ないことです。 演算の数が少ないため、直接再計算する方が簡単で安全です。 セルごとのシンボリック変換を維持しようとする試みは不要なオーバーヘッドとなり、この制約条件で漸近的なパフォーマンスを改善することなく実装の複雑性が増大します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサブマトリックス再構築 | O(q · k²) | O(k²) | 承認済み |
 | 最適なダイレクト シミュレーション | O(q · n²) 最悪の場合 | O(n²) | 承認済み |

 この問題では、制約が十分に小さいため、単純なシミュレーションがすでに最適化されているため、両方のアプローチが収束します。 

## アルゴリズムのチュートリアル

 マトリックスを現在の状態に維持し、各操作を直接適用します。

1. マトリックスを読み取り、変更可能な構造に変換します。 これにより、各変換後のインプレース更新が可能になります。 
2. 操作ごとに、座標を 1 から始まるインデックスから 0 から始まるインデックスに変換します。 これにより、以降のすべてのインデックス付けが Python 配列規則に一致し、境界のシフトが防止されます。 
3. 操作によって定義された部分行列を一時バッファーに抽出します。 このステップでは、計算中にまだ必要な値が変換によって上書きされないように領域を分離します。 
4. 部分行列と同じサイズの新しい行列を構築します。 
5. 変換タイプに従って新しい行列を入力します。 回転の場合、部分行列内の位置 (i, j) の各要素は (j, k-1-i) に移動します。 水平反転および垂直反転の場合、インデックスは対応する軸に沿って反転されます。 対角線の反射の場合、行と列のインデックスは、使用される対角線に応じて適切な反転で交換されます。 
6. 変換された部分行列を元の行列の同じ座標に書き込みます。 
7. すべての操作が処理されるまで繰り返します。 

すべての更新が完了したら、最終的な行列を出力します。 

### なぜ効果があるのか

 各操作は、選択した正方形領域のセルに対する全単射であり、すべての要素が正確に 1 つの新しい位置に移動し、すべての位置が正確に 1 つの要素を受け取ります。 各部分行列を書き戻す前に完全に再構築するため、この 1 対 1 マッピングは変換で定義されたとおりに正確に保存されます。 操作は順番に適用され、各ステップでは前のステップで完全に更新された行列が使用されるため、最終状態はすべての変換の構成と順番に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

def apply_op(x0, y0, x1, y1, t):
    x0 -= 1
    y0 -= 1
    x1 -= 1
    y1 -= 1
    k = x1 - x0 + 1

    tmp = [[0] * k for _ in range(k)]

    for i in range(k):
        for j in range(k):
            tmp[i][j] = a[x0 + i][y0 + j]

    res = [[0] * k for _ in range(k)]

    if t == 1:
        for i in range(k):
            for j in range(k):
                res[j][k - 1 - i] = tmp[i][j]

    elif t == 2:
        for i in range(k):
            for j in range(k):
                res[i][k - 1 - j] = tmp[i][j]

    elif t == 3:
        for i in range(k):
            for j in range(k):
                res[k - 1 - i][j] = tmp[i][j]

    elif t == 4:
        for i in range(k):
            for j in range(k):
                res[j][i] = tmp[i][j]

    elif t == 5:
        for i in range(k):
            for j in range(k):
                res[k - 1 - j][k - 1 - i] = tmp[i][j]

    for i in range(k):
        for j in range(k):
            a[x0 + i][y0 + j] = res[i][j]

for _ in range(q):
    x0, y0, x1, y1, t = map(int, input().split())
    apply_op(x0, y0, x1, y1, t)

for row in a:
    print(*row)
```実装は、各操作をヘルパー関数に分離することにより、アルゴリズムに正確に従います。 一時バッファ`tmp`すべての変換は部分行列の元の構成に依存し、インプレース更新により後の割り当てに必要な値が上書きされるため、これが必要です。 

各変換ケースは直接座標マッピングをエンコードします。 たとえば、回転の場合は、(i, j) から (j, k-1-i) へのマッピングを使用します。これは、正方形を時計回りに回転することに対応します。 対角線の場合はインデックスを交換し、メインまたは反対角線を反映します。 

各操作の開始時にすべてのインデックスが一貫して 0 ベースの形式にシフトされ、それが書き戻されることに注意する必要があります。`a`完全に変換されたブロックが計算された後にのみ発生します。 

## 実用的な例

 3 × 3 行列がグリッド全体で完全な回転操作を受ける最初のサンプルを考えてみましょう。 座標マッピングのみを追跡します。 

| ステップ | (i, j) | 値 | 新しいポジション |
 | --- | --- | --- | --- |
 | イニシャル | (0,0) | 1 | (0,2) |
 | イニシャル | (0,1) | 2 | (1,2) |
 | イニシャル | (0,2) | 3 | (2,2) |
 | イニシャル | (1,0) | 4 | (0,1) |
 | イニシャル | (1,1) | 5 | (1,1) |
 | イニシャル | (1,2) | 6 | (2,1) |
 | イニシャル | (2,0) | 7 | (0,0) |
 | イニシャル | (2,1) | 8 | (1,0) |
 | イニシャル | (2,2) | 9 | (2,0) |

 すべての値を新しい位置に配置した後、行列は時計回りに回転します。 

2 番目の例として、同じ行列の水平反転を考えてみましょう。 各行は独立して反転されます。 上の行は反転した値の最下行になりますが、中央の行は反転を除いて構造的に変更されません。 

これにより、変換が選択された部分行列内で厳密に動作し、境界の外側に漏れないことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · k²)、最悪の O(q · n²) | 各操作では k × k の部分行列が再構築され、k は最大 n | になります。 
| スペース | O(n²) | 行列とサイズ k² の一時バッファのストレージ。 

n が最大 500、q が最大 100 の場合、最悪の場合の操作数は約 2,500 万のセル割り当てになります。これは、単純なループ本体と高価な操作がない場合、Python の制限時間内に問題なく収まります。

    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

        x0 -= 1; y0 -= 1; x1 -= 1; y1 -= 1
        k = x1 - x0 + 1

            for j in range(k):
                tmp[i][j] = a[x0+i][y0+j]
        res = [[0]*k for _ in range(k)]

        if t == 1:
            for i in range(k):
                for j in range(k):
                    res[j][k-1-i] = tmp[i][j]
        elif t == 2:
            for i in range(k):
                for j in range(k):
                    res[i][k-1-j] = tmp[i][j]
        elif t == 3:
            for i in range(k):
                for j in range(k):
                    res[k-1-i][j] = tmp[i][j]
        elif t == 4:
            for i in range(k):
                for j in range(k):
                    res[j][i] = tmp[i][j]
        elif t == 5:
            for i in range(k):
                for j in range(k):
                    res[k-1-j][k-1-i] = tmp[i][j]

        for i in range(k):
            for j in range(k):
                a[x0+i][y0+j] = res[i][j]

    for _ in range(q):
        x0, y0, x1, y1, t = map(int, input().split())
        apply_op(x0, y0, x1, y1, t)

    return "\n".join(" ".join(map(str, r)) for r in a)

 ## 特殊なケース

 1 行 1 列の部分行列は、変換によってセルが誤ってセル自体に移動されたり、範囲外のインデックスに移動されたりしていないかどうかをテストします。 すべてのマッピングが (0,0) を (0,0) に送り返すため、アルゴリズムはこれを処理し、行列は変更されないままになります。 

フルグリッド操作を複数回繰り返して蓄積をテストします。 各操作は次の操作の前に行列を完全に再構築するため、意図的な合成を超える変換間の干渉はありません。 

重複する部分行列は、分離の正確さをテストします。 各操作は書き戻す前に一時バッファーにコピーされるため、同じ操作中に以前の更新が部分的に再利用されず、中間値の破損が防止されます。
