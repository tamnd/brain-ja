 ## 解決策
 ## 問題の理解

 私たちは 2D 平面内に立っていて、車を表す隠れた点があります。 半径という重要なパラメーターが 1 つ与えられています。`r`そして、面内の任意の場所に点をインタラクティブに移動し、現在位置が距離内にあるかどうかという二項回答を受け取ることができます。`r`隠された車の有無。 

原点から始めます`(0, 0)`そして、この開始点が検出円の内側にあることが保証されます。 各クエリにより、実際の座標に位置を変更し、未知の車の位置を中心とする円の中にまだいるかどうかを観察できます。 タスクは、最大 300 個のクエリを使用してこの円の中心の正確な座標を決定し、それを十分な精度で出力することです。 

重要な構造的事実は、隠されたオブジェクトが既知の半径のユークリッド円によって完全に決定されるということです。 グリッドやグラフ上で検索しているのではなく、各クエリがディスク内のメンバーシップ テストを行う連続ジオメトリ内で検索しています。 

この制約により、高密度のサンプリングやグリッドの再構築が不可能であることが明らかになります。 たとえば、20000 x 20000 の正方形で 0.01 の解像度で平面を粗く離散化する場合でも、300 クエリをはるかに超える、10^10 程度の評価が必要になります。 唯一の実行可能な方法は、円の幾何学的構造を利用し、問題を一定数の連続 1D 検索に減らすことです。 

単一方向の検索で十分であると仮定すると、微妙な問題が生じます。 円内の開始点から 1 つの光線に沿って移動すると、境界点が特定されるだけですが、無限に多くの円の中心がその境界点に対応する可能性があります。 別の故障モードは、原点の周りで対称性を仮定することですが、これは保証されておらず、不正確な幾何学的再構築につながります。 

## アプローチ

 この強引なアイデアは、平面内の点をサンプリングし、内側と外側の領域を検出して円の「輪郭を描く」ことを試みることです。 グリッドをスキャンしたり、原点から多くの方向に放射状サンプリングを実行したりすることを想像する人もいるかもしれません。 各クエリは安価ですが、角度分解能が中心の位置を特定するのに十分になるまで必要な方向の数は増加します。これは事実上、300 クエリ以内に明確な終了限界がない連続検索問題になります。 これは失敗します。円の境界の解像度が無限であるため、固定角度の離散化では正しい中心位置が失われる可能性があります。 

重要な点は、完全な境界は必要ないということです。 単一の境界点がすでに強力な幾何学的情報をエンコードしています: 点がわかっている場合`P`円と半径上で`r`、その場合、中心は正確な距離にある必要があります`r`から`P`。 これにより、未知のものは 2D の点から 2 つの円の交点に縮小されます。 

残りの課題は、正確な境界点を取得する方法です。 ここで、光線に沿った単調性が役に立ちます。 方向ベクトルを固定して原点から外側に移動すると、原点は円の内側にあり、直線は 1 つのセグメント内の円と交差するため、答えは最初は「内側」で、最終的には 1 回だけ「外側」になります。 これにより、任意の光線に沿って単調な述語が作成され、二分探索が可能になります。 

2 つの独立した方向から 2 つの境界点が見つかると、中心は 2 つの半径円の交点になります。`r`これらの境界点を中心に配置されます。 交点は最大 2 つあり、原点を中心とした円の内側にどの候補があるかをチェックすることで正しい交点が決定されます。

 ## アルゴリズムのチュートリアル

 原点が厳密に円の内側にあるという事実に依存しているため、原点からのすべての光線は境界と正確に 1 回交差します。 

1. 方向ベクトルを修正します。たとえば、`(1, 0)`。 フォームのポイントを考える`(t, 0)`と`t ≥ 0`。 で`t = 0`、私たちは円の中にいます。 として`t`増加すると、固有のしきい値が存在します`t0`ステータスが内側から外側に切り替わる場所。 これは、x 軸方向に沿った境界点です。 
2. 二分検索を実行します。`t`などの十分に大きな間隔で`[0, 20000]`。 各ステップで中点をクエリします`(mid, 0)`反応が内側か外側かに応じて間隔を縮めます。 単調遷移により、二分探索の正確さが保証されます。 
3. 結果の境界点を次のようにします。`P1`。 
4. 同じ手順を独立した方向に繰り返します。`(0, 1)`、2 番目の境界点を取得します。`P2`。 これにより、縮退した単一ラインの再構成に制約されなくなります。 
5. 私たちは今、中心が`C`を満たす:```
|C - P1| = r
|C - P2| = r
```これはつまり`C`を中心とする 2 つの円の交点に位置します。`P1`そして`P2`、両方とも半径付き`r`。 
6. 標準的な幾何学公式を使用して、これらの円の可能な 2 つの交点を計算します。 
7. 各候補中心について、どれが元の条件 (距離内にある) を満たすかを確認します。`r`(原点が円の内側にあることが保証されているため、正しい中心のみが再構築制約の下で一貫性を維持します)。 

### なぜ効果があるのか

 正しさは 2 つの不変条件に基づいています。 まず、円の内側の点から始まる光線に沿って、メンバーシップ述語が内側から外側に 1 回だけ遷移するため、連続領域にわたって二分探索が有効になります。 第 2 に、円の 2 つの異なる境界点は、反射の曖昧さまでその中心を一意に決定し、原点が円の内側にあるという追加の制約により、誤った交差点の候補が排除されます。 これらのプロパティを組み合わせることで、再構成された点が真の中心と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

EPS = 1e-7

def ask(x, y):
    print("?", x, y)
    sys.stdout.flush()
    return int(input().strip())

def binary_search_direction(dx, dy):
    lo, hi = 0.0, 20000.0
    
    # ensure hi is outside
    if ask(hi * dx, hi * dy) == 1:
        # extremely unlikely, but just in case expand
        while ask(hi * dx, hi * dy) == 1:
            hi *= 2
    
    for _ in range(60):
        mid = (lo + hi) / 2
        if ask(mid * dx, mid * dy) == 1:
            lo = mid
        else:
            hi = mid
    
    return lo * dx, lo * dy

def circle_intersections(p1, p2, r):
    x1, y1 = p1
    x2, y2 = p2
    
    dx, dy = x2 - x1, y2 - y1
    d = math.hypot(dx, dy)
    
    if d < 1e-12:
        return []
    
    midx = (x1 + x2) / 2
    midy = (y1 + y2) / 2
    
    h = math.sqrt(max(0.0, r*r - (d/2)**2))
    
    ux, uy = -dy / d, dx / d
    
    c1 = (midx + h * ux, midy + h * uy)
    c2 = (midx - h * ux, midy - h * uy)
    
    return [c1, c2]

def dist(x, y):
    return math.hypot(x, y)

def main():
    r = float(input().strip())
    
    p1 = binary_search_direction(1.0, 0.0)
    p2 = binary_search_direction(0.0, 1.0)
    
    candidates = circle_intersections(p1, p2, r)
    
    for cx, cy in candidates:
        if dist(cx, cy) <= r + 1e-6:
            print("!", cx, cy)
            sys.stdout.flush()
            return

if __name__ == "__main__":
    main()
```この解決策は、半径を読み取ることから始まり、次に直交軸に沿った二分探索を使用して 2 つの境界点を独立して抽出します。 各検索は、光線に沿った円の内側にあるという単調な特性に依存します。 境界上の 2 つの点が固定されると、標準的な円の交差点ジオメトリによって中心候補が復元され、既知の内部点との一貫性を検証することによって正しいものが選択されます。 

微妙な実装の詳細は、すべての幾何学的演算が浮動小数点誤差を許容する必要があることです。 最後の円の交差により結果が絞り込まれるため、二分探索では極端な精度は必要ありません。 60 回の反復は、位置誤差を基準値よりはるかに下回るようにするには十分です。`1e-6`出力条件によって要求される許容誤差。

 ## 特殊なケース

 エッジ ケースの 1 つは、円が検索間隔に比べて非常に大きい場合です。 この場合、二分探索の上限は依然として円の内側にある可能性があるため、実装では間隔を動的に拡張する必要があります。 コードはこれを 2 倍にすることで処理します。`hi`外側の点が見つかるまで、単調セグメントが適切に囲まれていることを確認します。 

別のエッジ ケースは、選択した 2 つの方向がほぼ同一線上の境界点を生成する場合に発生し、円の交点で数値的不安定性を引き起こす可能性があります。 アルゴリズムは直交方向を使用することでこれを回避します。`(1, 0)`そして`(0, 1)`、良好な条件の交差点システムを確保します。 

最後のエッジ ケースは、正しい交差点候補を選択する際の浮動小数点精度です。 どちらの候補も有効な幾何学的解であるため、原点が円の内側にあるという追加の制約のみがそれらを明確にします。 このチェックでは、丸め誤差による拒否を防ぐために小さなイプシロン マージンが使用されます。
