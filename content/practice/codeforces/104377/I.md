 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、そのリスト内で特定の構造特性を満たす最大の値を選択するように求められます。その値のすべての素因数もリスト内のどこかに出現する必要があります。 

より具体的に言い換えると、各数値がそれを分割する一連の素数に寄与すると想像してください。 因数分解に現れるすべての素数が、その素数で割り切れる配列の少なくとも 1 つの要素で「カバーされる」場合、その数値は有効です。 すべての有効な数値の中から最大値を見つけるか、そのような数値が存在しないことを報告するように求められます。 

入力サイズは最大 100,000 個の数値 (それぞれ最大 1,000,000) に達します。 これにより、前処理を行わずに繰り返し除算を使用してすべてのクエリに対して単純に素因数分解を再計算することが直ちに排除されます。 要素ごとの直接因数分解は、ふるいまたは最小の素因数テーブルを注意深く使用すれば、引き続き実行可能です。$10^6$は、SPF を線形または線形に近い時間で前処理するのに十分小さいため、各因数分解の値は対数になります。 

重要な隠れた制約は、因数分解の効率性だけではなく、数値間の依存関係にもあります。 素朴な解釈では各数値を独立して扱う可能性がありますが、有効性はグローバル情報、つまり各素約数が配列内のどこかで表されているかどうかに依存します。 この結合により、データセット全体に対して前処理が強制されます。 

いくつかの特殊なケースでは、よくある間違いが明らかになります。 

すべての数値が同一で複合的な場合、次のようになります。`[6, 6, 6]`、次に素数`{2, 3}`両方とも一部の要素の因数として出現する必要があり、これは当てはまります。そのため、有効な最大数は次のようになります。`6`。 素朴な解決策では、素数自体が因数としてではなく配列内の生の値として現れるかどうかだけをチェックする場合、これを誤って拒否する可能性があります。 

配列が`[4, 9]`の場合、4 は素因数になります`{2}`そして9は`{3}`。 両方の素数が配列全体の因数として現れるため、両方とも有効であり、答えは次のようになります。`9`。 要素としての素数の直接の存在のみをチェックする間違ったアプローチは、ここでは失敗します。 

配列が`[8, 9]`、同じロジックが適用されますが、代わりに`[8]`、次にプライム`2`カバーされているので、`8`有効です。 

微妙な失敗モードは、「素数が要素として現れる」ことと「素数が何らかの要素の約数として現れる」ことを混同することです。 

## アプローチ

 ブルートフォース戦略は、各数値を個別に因数分解し、次に因数分解内のすべての素数が何らかの使用可能な方法で配列内に出現するかどうかを数値ごとにチェックすることから始まります。 これを実装する 1 つの方法は、最初にすべての数値の頻度マップを構築し、次に候補数値ごとにそれを素因数分解し、各素数が配列内の少なくとも 1 つの要素を分割するかどうかを検証することです。 

ボトルネックは、素数性/可分性チェックの繰り返しと組み合わせた因数分解の繰り返しです。 最悪の場合、最大の各数値は、$10^6$で処理される可能性があります$O(\sqrt{a_i})$試験分割、約$10^5 \cdot 10^3 = 10^8$定数が含まれる場合、これは境界線に達し、Python ではさらに悪化します。 さらに重要なことは、同じ値の因数分解を繰り返すと無駄が生じるということです。 

重要な観察は、どの素数が配列内のどこかに因数として現れるかを知る必要があるだけであるということです。 そのセットが判明すると、各数値の検証は素因数分解に対する単純なメンバーシップ チェックになります。 これは、最大の範囲全体にわたって最小の素因数ふるいを使用して前処理することを示唆しています。$10^6$、各要素の素早い因数分解が可能になります。 次に、因数分解に現れるすべての素数のセットを計算します。 最後に、同じ因数分解を使用して各数値を再評価し、そのすべての素数がそのグローバル セットに属していることを確認します。 

これにより、問題は線形前処理と効率的な因子抽出による線形トラバーサルに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \sqrt{A})$|$O(n)$| 遅すぎる |
 | 最適 |$O(A \log \log A + n \log A)$|$O(A)$| 承認済み |

 ここ$A = 10^6$。 

## アルゴリズムのチュートリアル

 1. 最小の素因数配列を構築する`spf`以下のすべての整数に対して$10^6$。 これにより、最小の素因数で繰り返し除算することにより、対数時間で任意の数値を因数分解できます。 
2. 配列内のすべての数値について、次を使用して因数分解します。`spf`。 素数を抽出する際、因数分解に現れるそれぞれの異なる素数をグローバル ブール配列に記録します。`present_prime`。 このステップでは、データセット内で「利用可能な」すべての素数をキャプチャします。 
3. 配列を再度繰り返します。 各数値について、次を使用して再度因数分解します。`spf`そして、その数値のすべての異なる素因数が存在するものとしてマークされているかどうかを確認します。`present_prime`。 
4. 番号がこのチェックに合格した場合、その番号は有効な候補になります。 すべての有効な候補の中から最大値を追跡します。 
5. 有効な候補がない場合は、出力します。`-1`。 

ステップ 2 が正しいかどうかは、素数をグローバル リソースとして扱うかどうかにかかっています。 多重度をカウントしているのではなく、入力内のどこかに素数が因子として少なくとも 1 回出現するかどうかだけをカウントしています。 

### なぜ効果があるのか

 有効性の条件は、数値を分割する各素数が、配列から導出されたグローバル素因数サポート セットに存在するかどうかによってのみ決まります。 すべての数値は、すべての因数分解から構築された同じグローバル セットに対してテストされるため、決定は一貫性があり、要素ごとに独立しています。 ふるいは正しい素数分解を保証し、素数をグローバルに保存することで数値間の依存関係の欠落がないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    primes = set()
    while x > 1:
        p = spf[x]
        primes.add(p)
        while x % p == 0:
            x //= p
    return primes

n = int(input())
a = list(map(int, input().split()))

present_prime = [False] * (MAXV + 1)

fact_cache = []
for x in a:
    ps = factorize(x)
    fact_cache.append(ps)
    for p in ps:
        present_prime[p] = True

ans = -1
for i, x in enumerate(a):
    ok = True
    for p in fact_cache[i]:
        if not present_prime[p]:
            ok = False
            break
    if ok:
        ans = max(ans, x)

print(ans)
```ふるいは一度組み立てるだけで、迅速な分解が可能になります。 この実装では、各数値が 2 回因数分解されます。1 回目はグローバル素数セットの構築、もう 1 回目は候補の検証です。 小規模な最適化では、再計算を避けるために係数セットをキャッシュします。 

の`present_prime`配列は、どこにでも現れるすべての素数のグローバル レジストリとして機能します。 各候補は、それ自体の素数セットに対してのみチェックされます。

このトレースは、すべての素数がグローバルに収集されると、検証が数値ごとに独立したものになることを示しています。 

次に、次のことを考えてみましょう。```
3
8 9 5
```因数分解:

 8 → {2}

 9 → {3}

 5 → {5}

 すべての素数はグローバルに出現するため、すべての数値が有効となり、答えは 9 になります。 

これは、アルゴリズムが素数をスタンドアロン要素として表示する必要はなく、データセット内のどこかの因子としてのみ表示することを必要とすることを裏付けています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    MAXV = 10**6
    spf = list(range(MAXV + 1))
    for i in range(2, int(MAXV ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXV + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factorize(x):
        primes = set()
        while x > 1:
            p = spf[x]
            primes.add(p)
            while x % p == 0:
                x //= p
        return primes

    n = int(input())
    a = list(map(int, input().split()))

    present = [False] * (MAXV + 1)
    facts = []

    for x in a:
        ps = factorize(x)
        facts.append(ps)
        for p in ps:
            present[p] = True

    ans = -1
    for i, x in enumerate(a):
        ok = True
        for p in facts[i]:
            if not present[p]:
                ok = False
                break
        if ok:
            ans = max(ans, x)

    return str(ans)

## 特殊なケース

 特殊なケースの 1 つは、数値自体が素数である場合です。 入力用`[2, 3, 5]`、すべての数値はそれ自体に等しい単一の素因数を持ちます。 これらすべての素数は独自の要素の因数として配列内に現れるため、すべての数値が有効であり、答えは最大の要素になります。 

もう 1 つの特殊なケースは、次のような複合構造が繰り返されることです。`[4, 9, 25]`。 各数値は単一の素因数に依存しますが、有効性を維持するには、これらの各素数が配列内のどこかに出現する必要があります。 アルゴリズムは正しく収集します`{2,3,5}`グローバルに実行され、すべての要素が正常に検証されます。 

より微妙なケースは、次のような依存関係が混在している場合です。`[6, 25]`。 ここで6つの要件があります`{2,3}`そして25の要件`{5}`。 すべての素数は既存の要素の因数分解に現れるため、どちらも有効で、出力は 25 になります。このアルゴリズムは、同じ数内の素数の相互共有を必要とせず、グローバルな存在のみを必要とすることでこれを保証します。
