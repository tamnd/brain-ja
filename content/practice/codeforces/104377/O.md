 ## 問題の理解

 平面内に点のセットが与えられ、各点は正または負の値を持ちます。 漁師は原点に立ち、非常に柔軟な方法で網を展開できます。 ネットは常に原点を境界とする円に対応しており、その円の内側や円上にあるものはすべて収集されます。 合計ゲインは、収集されたすべてのポイントの値の合計です。 

重要な幾何学的自由度は、円の中心や半径を固定しないことです。 原点を通過する限り、任意の円を選択することができます。これには、円が任意に大きくなり、事実上、境界が原点を通る直線に変わり、収集された領域として半平面が残るという縮退ケースが含まれます。 

したがって、タスクは、そのような円によって定義される幾何学的領域を選択して、その内部のすべての点の値の合計を最大化することです。 

制約は十分小さいため、O(n^2) の幾何学的スイープが実行可能です。 n が最大 1000 であれば、各点を基準方向として考慮し、それを基準にして他のすべての点を処理するソリューションでも、制限時間内で問題なく通過できます。 

微妙な点は、最適な領域が必ずしも「正の点のクラスターの周りの小さな円」ではないことです。 原点を強制的に通過させながら円を拡大できるため、原点を通る任意の半平面を効果的に近似できます。 これにより、多くの中程度に正の点が線の片側に位置する構成が、密集した高値の点よりもはるかに重要になります。 

単純な間違いは、近​​くの正の点を捕捉するどこかを中心とする半径を選択する必要があると仮定して、距離だけの観点から考えることです。 これは、円が原点を通過しなければならないという制約を無視しており、基本的にすべての有効な領域を原点に固定された方向に結び付けます。 

もう 1 つのよくある落とし穴は、問題を凸包または境界円の問題の選択として扱うことです。 たとえば、正の点を囲む最小の円を選択しようとする場合がありますが、その円は原点を通過する必要がないため、有効な候補ではありません。 

## アプローチ

 強引な解釈では、原点を通過する可能性のあるすべての円を列挙し、その内側のすべての点をテストして合計を計算します。 平面内の円には 3 つの自由度がありますが、原点を通過するという制約により、中心の自由度は 2 つに減ります。 中心位置を離散化したり、点のペアによって定義される候補円の組み合わせ列挙を試みたりしても、すぐに可能性の爆発に直面します。 各候補の n 点すべてのメンバーシップをチェックすると、3 次またはそれ以上の複雑さが生じますが、幾何学的構造を考慮すると、これは不必要です。 

重要な観察は、原点を通過するすべての円が、「遠い境界の動作」が半平面に相当する平面の分割を引き起こすということです。 円の半径が大きくなるにつれて、その境界は原点の周囲で局所的に平坦になり、その領域は境界線が原点を通る半平面に近づきます。 

より具体的には、あらゆる最適な構成は、すべての点がその線の片側にあるように、原点を通る有向線の選択として表すことができます。 方向を決定すると、事実上、半平面を決定することになり、原点を通る線の片側にある点を正確に含むように、すべての有効な円を引き伸ばすことができます。 

これにより、問題は次のように簡略化されます。線の片側の点の値の合計が最大になるような、原点を通る線を見つけます。

これは古典的な角度スイープ問題です。 各点には原点の周りの極角があります。 任意の半平面は、厳密に π より小さい長さの角度の間隔に対応します。 そこで、点を角度ごとに並べ替え、円形の角度空間上で幅 π のスライディング ウィンドウを使用し、ウィンドウ内の値の合計を維持します。

 ## アルゴリズムのチュートリアル

 幾何学的な問題を角度座標に変換し、重み付けされた点の最適な半円形の範囲を検索します。 

1. 原点に対するすべての点の極角を計算します。 これにより、各点が範囲 [0, 2π) の角度にマップされます。 
2. 各角度に 2π を加算して点のリストを複製し、それを配列に追加します。 これにより、線形スイープを使用して円形のラップアラウンドをシミュレートできるようになります。 
3. すべてのポイントを角度別に並べ替えます。 連続する角度間隔が配列内の連続するセグメントに対応するように、並べ替えが必要です。 
4. 2 ポインターのスライディング ウィンドウを使用します。 左の端点ごとに、角度スパンが π 未満であることを維持しながら、右の端点をできるだけ遠くに進めます。 
5. 有効なウィンドウごとに、その中のポイントの値の合計を計算し、すべてのウィンドウの最大値を追跡します。 

ウィンドウ サイズが π である理由は、原点を通る半平面が長さ π の任意の間隔内にあるすべての方向に正確に対応するためです。 これより大きな間隔には、必ず原点を通る線の両側の点が含まれることになり、半平面構造に違反します。 

### なぜ効果があるのか

 実行可能なすべての解決策は、原点を通る有向線を選択することに対応し、これにより半平面が定義されます。 その半平面は、単位円上の幅 π の連続した角度間隔に対応します。 逆に、そのような間隔は有効な半平面を定義します。 スライディング ウィンドウはそのような間隔をすべて列挙するため、すべての有効な幾何学的構成が 1 回だけ考慮されます。 したがって、最適なウィンドウ合計は、最適な円ベースの選択と等しくなります。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    n = int(input())
    v = list(map(int, input().split()))
    
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        ang = math.atan2(y, x)
        pts.append((ang, v[i]))
    
    pts.sort()
    
    extended = pts + [(ang + 2 * math.pi, val) for ang, val in pts]
    
    m = len(extended)
    
    ans = -10**18
    current_sum = 0
    r = 0
    
    for l in range(n):
        if r < l:
            r = l
            current_sum = 0
        
        while r < m and extended[r][0] - extended[l][0] < math.pi - 1e-12:
            current_sum += extended[r][1]
            r += 1
        
        ans = max(ans, current_sum)
        current_sum -= extended[l][1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、各点を極角形式に変換することから始まります。 の使用`atan2`負の座標を含むすべての象限にわたって正しい処理が保証されます。 

ソート後、角度を 2π ずらして配列を明示的に複製します。 これにより、スライディング ウィンドウは特別なモジュラー演算を行わずに円形の角度空間を線形間隔として扱うことができます。 

2 ポインター スイープでは、現在の角度ウィンドウ内の値の累計が維持されます。 条件`< π`半平面制約を強制します。 左ポインタを移動するときの減算ステップにより、ウィンドウの合計が一貫した状態に保たれます。 

よくある実装上の間違いは、角度の違いを比較するときに浮動小数点の精度の問題を忘れることです。 小さなイプシロンは、点が π しきい値上に正確に位置する場合に境界の不安定性を防ぎます。

 ## 特殊なケース

 重要なエッジ ケースは、点が選択した半平面の境界線上に正確に位置する場合です。 角度用語では、これは π に正確に等しい差に相当します。 このアルゴリズムはウィンドウを厳密に π 未満として扱い、各境界が一貫して片側のみに割り当てられるようにします。 たとえば、角度 0 と π の点が同じウィンドウに一緒に含まれることはありません。これは、原点を通る線が点を反対側に配置するという幾何学的解釈と一致します。 

すべての値が負の場合、別の微妙なケースが発生します。 最適な戦略は、空のセットではなく、負の最小の半平面を選択することです。 スライディング ウィンドウはこれを自然に処理します。これは、最小の大きさの負の合計を含むすべてのウィンドウの合計が計算され、最大値が正しくキャプチャされることが保証されるためです。
