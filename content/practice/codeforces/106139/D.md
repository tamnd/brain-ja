 ## 解決策
 ## 問題の理解

 最初は空です`n × m`グリッド。 操作はどのセルでも実行できます。 

タイプ 1 の操作は、選択した行のすべてのセルと選択した列のすべてのセルを塗りつぶします。 

タイプ 2 の操作は、選択したセルを通過する 2 つの対角線上のすべてのセルを塗りつぶします。 

このタスクは、グリッド全体を埋めるために必要な操作の最小数を決定するだけでなく、その最小値を達成する 1 つの操作シーケンスを出力することも目的としています。 グリッドの寸法が満たされている`1 ≤ n, m ≤ 1000`、すべてのテスト ケースにわたるセルの合計数は最大で`10^6`。 

出力は建設的です。 最適なシーケンスを自由に選択できます。 

重要な観察は、答えはグリッドのより小さい次元にのみ依存するということです。 以来`n`そして`m`せいぜい`1000`を使用したあらゆる建設`O(min(n,m))`操作は簡単に制限内に収まります。 

よくある間違いは、対角操作を悪用することに労力を費やすことです。 これらは強力に見えますが、最適性を証明するには実際には不要です。 最小数が特定されたら、タイプ 1 の演算のみを使用する非常に単純な構成で十分です。 

考えてみましょう`1 × 5`グリッド。 唯一の行に対する 1 つのタイプ 1 操作により、すべてのセルが直ちに埋められます。 正しい答えは、`1`、 ない`5`。 

考えてみましょう`2 × 2`グリッド。 タイプ 1 操作の実行`(1,1)`行 1 と列 1 を埋めて、残ります`(2,2)`発見された。 2回目の手術がまだ必要です。 正しい答えは、`2`。 

これらの例は、最小値がセルの総数ではなく、より小さい次元によって制御されることを示唆しています。 

## アプローチ

 強引な視点は、グリッドをセットカバー問題として考えることです。 可能なすべての操作はセルの一部のサブセットをカバーしており、結合がグリッド全体である操作の最小のコレクションが必要です。 たとえ`1000 × 1000`グリッドには 100 万個の中心が存在する可能性があるため、徹底的な検索は不可能です。 

重要な観察は、タイプ 1 の操作ですでに完全な解決策が得られているということです。 

仮定する`n ≤ m`。 タイプ 1 の操作を行ごとに 1 回実行すると、すべての行が完全に埋められます。 結局`n`行が選択され、グリッド全体が塗りつぶされます。 対称的に、`m < n`、すべての列で 1 つのタイプ 1 操作を実行すると、グリッド全体が埋められます。 

これにより、すぐに次の上限が得られます。`min(n,m)`操作。 

これが最適であることを示すために、次のように仮定します。`n ≤ m`。 すべての操作では、選択した行として最大 1 つの行を直接指定できます。 以下の場合`n`操作では、少なくとも 1 つの行が選択されることはありません。 決して選択されない行は、以下の数で完全に生成することはできません。`n`すべての列と対角線にわたって操作を実行するため、グリッドを完全にカバーすることはできません。 したがって、少なくとも`n`操作が必要です。 対称性により、下限は次のようになります。`min(n,m)`。 

上限と下限が一致するため、最小演算数は正確に`min(n,m)`。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. もし`n ≤ m`、出力`n`操作。 
3. 各行について`i`から`1`に`n`、タイプ 1 演算を出力します。`(i, 1)`。 

行の選択`i`行全体が埋まることが保証されます。 すべての行を処理した後、グリッドのすべてのセルは選択された行に属します。 
4. それ以外の場合は出力`m`操作。 
5. 各列について`j`から`1`に`m`、タイプ 1 演算を出力します。`(1, j)`。 

列の選択`j`列全体が埋まることが保証されます。 すべての列を処理した後、グリッドのすべてのセルは選択した列に属します。 

### なぜ効果があるのか

 もし`n ≤ m`、この構造では、行ごとにタイプ 1 の操作が 1 つだけ実行されます。 すべての行が完全に塗りつぶされるため、グリッドのすべてのセルが塗りつぶされます。 操作数は、`n`。 

もし`m < n`、対称引数は、列ごとに 1 つの操作が正確に使用してグリッド全体を埋めることを示しています。`m`操作。 

下限もまた、`min(n,m)`、したがって構築は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

out = []

for _ in range(t):
    n, m = map(int, input().split())

    if n <= m:
        out.append(str(n))
        for i in range(1, n + 1):
            out.append(f"1 {i} 1")
    else:
        out.append(str(m))
        for j in range(1, m + 1):
            out.append(f"1 1 {j}")

sys.stdout.write("\n".join(out))
```実装は構築の後に直接続きます。 

いつ`n ≤ m`、すべての操作はタイプ 1 であり、別の行に配置されます。 選択された列は常に`1`なぜなら、その正確な値は重要ではないからです。 この操作では、どの列が中心として使用されるかに関係なく、行全体が塗りつぶされます。 

いつ`m < n`、対称構造では列ごとに 1 つの操作が使用され、常に行が選択されます。`1`。 

グリッドシミュレーションは必要ありません。 アウトプット自体が解決策です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        if n <= m:
            out.append(str(n))
            for i in range(1, n + 1):
                out.append(f"1 {i} 1")
        else:
            out.append(str(m))
            for j in range(1, m + 1):
                out.append(f"1 1 {j}")

    return "\n".join(out)

# minimum size
assert run("1\n1 1\n") == "1\n1 1 1"

# single row
assert run("1\n1 5\n") == "1\n1 1 1"

# single column
assert run("1\n5 1\n") == "1\n1 1 1"

# square grid
assert run("1\n2 2\n") == "2\n1 1 1\n1 2 1"

# rectangular grid
assert run("1\n3 4\n") == "3\n1 1 1\n1 2 1\n1 3 1"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`5 1`| ワンオペレーション | 単一列の場合 |

 ## 特殊なケース

 のために`1 × 5`グリッド：```
1
1 5
```アルゴリズムは次を出力します。```
1
1 1 1
```唯一の行に対するタイプ 1 の操作により、すべてのセルが直ちに埋められます。 答えは`1`。 

のために`5 × 1`グリッド：```
1
5 1
```アルゴリズムは次を出力します。```
1
1 1 1
```唯一の列に対するタイプ 1 の操作により、すべてのセルが直ちに埋められます。 

のために`2 × 2`グリッド：```
1
2 2
```アルゴリズムは次を出力します。```
2
1 1 1
1 2 1
```最初の操作は行 1 を埋めます。2 番目の操作は行 2 を埋めます。すべてのセルがカバーされ、操作の数は次のとおりです。`min(2,2)=2`。 

同じ理由がすべての大きなグリッドに当てはまります。 構築では常に正確に使用されます`min(n,m)`操作し、ボード全体を埋めます。
