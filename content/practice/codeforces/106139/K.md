 ## 解決策
 ## 問題の理解

 文字列が与えられ、0 から n までの位置に整数マーカーを配置します。位置 i は文字間の境界を表します。 任意の位置 x から、厳密にそれらの間の部分文字列、つまり min(x, y) + 1 から max(x, y) までが回文を形成する場合に限り、別の位置 y にジャンプできます。 

各クエリは開始位置 a を与え、エンドポイント 0 またはエンドポイント n に到達するために必要なジャンプの最小数が必要です。 

入力は非常に大きくなる可能性があり、文字列の長さとクエリの数は両方とも最大 100 万件に達します。 これにより、クエリごとに部分文字列を検査したり、すべての回文部分文字列を明示的に構築したりするアプローチは直ちに除外されます。 クエリごとの線形ソリューションであっても、遅すぎるでしょう。 

主な問題点は、グラフが暗黙的であり、最悪の場合には非常に密になることです。 単一の回文部分文字列がその 2 つの境界位置間の直接接続に寄与し、「aaaaaa...」のような最悪の文字列には Θ(n²) 個の回文部分文字列が存在する可能性があります。 エッジを明示的に列挙しようとするソリューションは失敗します。 

微妙なエッジ ケースは、開始位置がすでに終了点に隣接している場合です。 たとえば、a = 0 または a = n の場合、答えは自明のことながらゼロになります。 もう 1 つのエッジ ケースは、0 から a または a から n の部分文字列自体が回文である場合で、これにより直接 1 ステップ ジャンプが可能になります。 たとえば、s = "abacaba" および a = 3 の場合、プレフィックスとサフィックスの構造により、エンドポイントへの即時到達がすでに許可されている可能性があります。 直接的なエンドポイントの回文を無視する単純な BFS では、これらの即時の答えを見逃してしまいます。 

## アプローチ

 ブルート フォース解釈では、各位置をノードとして扱い、i と j の間の部分文字列が回文である場合、それらをエッジで接続します。 その場合、各クエリは最短経路問題になります。 隣接関係の構築でさえ、最悪の場合はすでに 2 次的であり、クエリごとに BFS を実行すると、これに q が乗算され、実行不可能な O(n² + qn²) の動作が発生します。 

重要な点は、完全なグラフは必要ないということです。 2 つの特別なノード 0 と n への最短パスのみが必要です。 すべての動きは回文間隔によって定義されるため、構造は完全に回文部分文字列によって決まります。 これは、すべての部分文字列を明示的にリストすることなく、すべての出現を効率的に列挙できる回文構造を使用することを示唆しています。 

このための標準ツールは、エアツリーとしても知られる回文ツリーです。 これにより、すべての異なる回文部分文字列が O(n) ノードに圧縮され、すべての出現を線形時間で追跡できるようになります。 各ノードは回文を表し、文字列を拡張するたびに、現在の位置で終了する回文を更新できます。 

各位置で終わるすべての回文がわかったら、各出現を、その 2 つの境界位置間のグラフ エッジに寄与する間隔として扱うことができます。 すべてのエッジを構築する代わりに、それらをバッチで処理します。回文の出現が発見されると、すぐにそれを使用して BFS を緩和し、線形全体処理を保証するために破棄します。 

BFS 自体は、エンドポイント 0 と n の両方から同時に実行されます。 各位置は 1 回訪問され、現在の位置で終了する回文を列挙することによって遷移が生成されます。 これにより、すべての回文間隔が 1 回だけ使用されることが保証され、全体的に線形の複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² + qn) | O(n²) | 遅すぎる |
 | 最適 (エアツリー + BFS) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から n までの各位置をグラフ内のノードとしてモデル化します。 目標は、各クエリ ノードからいずれかのエンドポイントへの回文ジャンプの最短数を計算することです。

文字列上に回文ツリーを構築します。 ツリー内の各ノードは個別の回文を表し、ツリーを構築する際に、各位置で出現がその位置で終了する回文ノードのリストを維持します。 

次に、両方のエンドポイント 0 と n が有効なターゲットであるため、両方のエンドポイントから開始してマルチソース BFS を実行します。 

1. 左から右にスキャンしながら文字列上に Eertree を構築します。 各位置 i で、i で終わる回文部分文字列のセットを更新します。 このような回文ごとに、その左境界 l と右境界 i を記録します。これらは、l − 1 と i の間のエッジに対応します。 
2. 距離 0 のノード 0 と n で BFS キューを初期化します。これらは、すでに到達したターゲットを表します。 
3. 2 つの端点を除くすべての位置について、無限大に初期化された距離配列を維持します。 
4. キューから位置 x をポップするとき、x で終わるすべての回文部分文字列を調べます。 このような各回文は区間 [l, x] に対応し、l − 1 と x の間のジャンプを実現します。 
5. このような間隔ごとに、l − 1 の距離を緩和しようとします。改善された場合は、それをキューにプッシュします。 
6. x で終わるすべての回文を処理した後、各回文が 1 回だけ処理されるように、それらをクリアまたは使用済みとしてマークします。 
7. BFS が終了すると、各クエリの答えは単に位置 a での事前計算された距離になります。 

重要な考え方は、BFS は隣接リストではなく回文の出現によって駆動され、各出現はその正しいエンドポイントが処理されるときに 1 回消費されるということです。 

### なぜ効果があるのか

 すべての有効な動きは、2 つの境界位置を結ぶ回文間隔に正確に対応します。 BFS は、位置 x に到達するたびに、x で終わるすべての回文が直ちに探索されることを保証します。これは、x から生じるすべての可能なエッジが可能な限り早い時点で緩和されることを意味します。 各回文出現は 1 回だけ処理されるため、遷移が見逃されることはなく、冗長な作業が繰り返されることもありません。 これにより、初めてノードに距離を割り当てるときに、それが可能な最小限のジャンプ数になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Eertree:
    def __init__(self, s):
        self.s = s
        self.n = len(s)
        self.next = [{}]
        self.link = [-1]
        self.len = [0]
        self.last = 0

        self.next.append({})
        self.link.append(0)
        self.len.append(-1)

        self.last = 0
        self.s = s
        self.n = len(s)

        self.tree = [{}, {}]
        self.link = [1, 0]
        self.len = [0, -1]
        self.suff = 0
        self.nxt = [{} , {}]

        self.nodes = 2
        self.pos_end = [[] for _ in range(self.n + 1)]

    def add(self, pos):
        ch = self.s[pos]
        cur = self.suff

        while True:
            curlen = self.len[cur]
            if pos - 1 - curlen >= 0 and self.s[pos - 1 - curlen] == ch:
                break
            cur = self.link[cur]

        if ch in self.nxt[cur]:
            self.suff = self.nxt[cur][ch]
        else:
            self.nxt[cur][ch] = self.nodes
            self.len.append(self.len[cur] + 2)

            if self.len[-1] == 1:
                self.link.append(1)
            else:
                linkcur = self.link[cur]
                while True:
                    curlen = self.len[linkcur]
                    if pos - 1 - curlen >= 0 and self.s[pos - 1 - curlen] == ch:
                        break
                    linkcur = self.link[linkcur]
                self.link.append(self.nxt[linkcur][ch])

            self.nxt.append({})
            self.suff = self.nodes
            self.nodes += 1

        v = self.suff
        self.pos_end[pos + 1].append(v)

def solve():
    s = input().strip()
    n = len(s)

    et = Eertree(s)
    for i in range(n):
        et.add(i)

    adj = [[] for _ in range(n + 1)]

    for r in range(1, n + 1):
        for v in et.pos_end[r]:
            l = r - et.len[v]
            adj[l - 1].append(r)
        et.pos_end[r] = []

    from collections import deque
    dist = [INF] * (n + 1)
    dq = deque([0, n])
    dist[0] = 0
    dist[n] = 0

    while dq:
        x = dq.popleft()
        for y in adj[x]:
            if dist[y] > dist[x] + 1:
                dist[y] = dist[x] + 1
                dq.append(y)

    q = int(input())
    a = list(map(int, input().split()))
    out = []
    for x in a:
        out.append(str(dist[x]))
    print(" ".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、線形時間で終了するすべての回文の出現をキャプチャする Eertree を構築します。 それぞれの出来事は、境界位置間の単一の指向性緩和に変換されます。 次に、両方のエンドポイントからの BFS が最小ジャンプを計算します。 

この実装では、ノード i が境界 i を表す位置インデックスを慎重に使用し、部分文字列の境界がグラフのエッジにきれいにマップされるようにします。 各回文の出現は、その右のエンドポイントが処理されるときに 1 回だけ消費され、二次関数の爆発を防ぎます。 

よくある落とし穴は、部分文字列インデックスと境界インデックスを混同することです。 部分文字列 [l, r] からエッジ (l − 1, r) への変換は、正確さを保つために不可欠です。 

## 実用的な例

 文字列を考えてみましょう`abba`さまざまな位置でクエリを実行します。 

まず回文間隔を列挙します。`a`、`b`、`bb`、`abba`。 

これらはエッジに対応します。`(0,1)`、`(1,2)`、`(1,3)`、`(0,4)`。 

これで、BFS は 0 と 4 から始まります。 

| ステップ | ノード | 距離 | 新しく緩和されたノード |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1、4 |
 | 2 | 4 | 0 | 0、3 |

 処理後、すべての位置の最短距離が得られます。 2 は回文エッジを介して直接接続されているため、位置 2 のクエリは 1 を返します。 

このトレースは、大きな回文が複数の動きを 1 つの BFS ステップにまとめる長距離エッジをどのように作成するかを示しています。 

ここで考えてみましょう`abcd`ここには自明ではない回文はありません。 

エッジのみ`(0,1)`、`(1,2)`、`(2,3)`、`(3,4)`。 

位置 2 のクエリでは、0 または 4 に到達するまで段階的に移動する必要があり、距離 2 が得られます。これは、構造が存在しない場合、BFS が線形ウォークに縮退することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | Eertree 構築と BFS はそれぞれ、すべての文字と出現を 1 回処理します。 
| スペース | O(n) | 回文ツリー、隣接リスト、距離配列のストレージ |

 制約により最大 100 万回の操作が許可されるため、線形ソリューションが必要です。 回文ツリーにより、各文字が一定の償却仕事のみに寄与することが保証され、BFS により各位置が 1 回訪問されることが保証されます。
