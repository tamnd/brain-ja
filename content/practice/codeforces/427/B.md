 ## 解決策
 ## 問題の理解

 一連の囚人がいて、各囚人には犯罪の重大度の値があります。 正確に選択しなければなりません`c`連続移送囚人。 選択したセグメント内のすべての囚人の重症度は最大でも高くなければなりません`t`。 

タスクは単に、長さの連続するセグメントの数を数えるだけです。`c`この制限を満たします。 

入力により、囚人の数、最大許容重症度、および必要なセグメント長が得られます。 次に、重大度の配列を受け取ります。 出力は単一の整数、つまり有効な連続セグメントの数です。 

この制約により、コストのかかるアプローチは即座に除外されます。 到達できる囚人の数`2 * 10^5`、つまり、`O(n^2)`アルゴリズムは大まかに実行します`4 * 10^10`最悪の場合、1 秒の問題の制限をはるかに超えて操作が可能になります。 線形または線形に近いものが必要です。 

値自体は次のように大きくできます。`10^9`、しかし、比較を超えてそれらに対して算術を実行することは決してないので、それはあまり問題ではありません。`t`。 

見落としやすいエッジケースがいくつかあります。 

よくある間違いの 1 つは、セグメントが連続している必要があることを忘れることです。 例えば：```
5 3 2
1 5 2 3 1
```有効なセグメントは次のとおりです。 

-`[2,3]`-`[3,1]`答えは`2`、 ない`4`。 不注意な解決策は、最大でも価値のあるすべての囚人をカウントする可能性があります`3`そしてそれらから組み合わせを形成しようとしますが、これは連続要件を無視します。 

もう 1 つの微妙なケースは、悪意のある囚人が配列を独立した領域に分割した場合に発生します。```
7 2 3
1 2 1 5 1 1 1
```1 つの有効なセグメントからの最初の 3 人の囚人。 最後の3人は別の囚人だった。 を横切る任意のセグメント`5`は無効です。 正しい答えは、`2`。 

有効なブロック長が正確に等しい場合、off-by-one バグが頻繁に発生します。`c`。```
4 3 4
1 2 3 1
```配列全体が有効なので、答えは次のようになります。`1`。 一部の実装では誤って使用されています`length - c`の代わりに`length - c + 1`。 

もう 1 つの重要なエッジケースは、制限を満たす囚人がいない場合です。```
5 1 2
3 4 5 6 7
```どのセグメントも機能しないため、答えは次のようになります。`0`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 連続するすべての長さのセグメントを調べます`c`、その後、そのセグメント内のすべての値が最大かどうかを確認します。`t`。 

がある`n - c + 1`可能なセグメント。 1 つのセグメントのチェックにかかる時間`O(c)`時間がかかるため、全体の複雑さは次のようになります`O((n - c + 1) * c)`。 最悪の場合は両方とも`n`そして`c`約であることができます`2 * 10^5`、大まかに言うと`4 * 10^10`操作。 それは遅すぎます。 

ブルート フォースが機能するのは、セグメントの条件が単純であるためです。セグメント内のすべての要素が制限を満たさなければなりません。 問題は、隣接するセグメントが重なり合っているにもかかわらず、ブルートフォースが同じ要素を繰り返し再チェックすることです。 

重要な観察は、無効な囚人が配列を独立した有効な領域に完全に分離していることです。 配列をスキャンし、すべての値が最大値である連続した区間のみに焦点を当てるとします。`t`。 

例えば：```
1 2 1 5 1 1 1
```値`5`配列を次のように分割します。```
[1 2 1]   and   [1 1 1]
```有効な長さのブロック内`L`、長さのすべての連続する部分配列`c`は自動的に有効になります。 このような部分配列の数は次のとおりです。```
L - c + 1
```提供された`L >= c`。 

これにより、問題は最大有効ブロックの長さをカウントすることに変換されます。 

連続して受け入れ可能な囚人の現在の長さを維持しながら、配列を 1 回スキャンします。 より大きい値に遭遇したとき`t`、現在のブロックが終了し、その寄与を追加します。 

これにより線形が得られます`O(n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × c) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 回答変数を初期化する`ans = 0`。 
2. カウンターを維持する`length`すべての重大度が最大である現在の連続ブロックを表します。`t`。 
3. 配列を左から右に走査します。 
4. 現在の重大度が最大でも`t`、増分`length`有効なブロックが続いているからです。 
5. 現在の重大度が次の値を超えている場合`t`、現在の有効なブロックが終了します。 

もし`length >= c`の場合、このブロックは貢献します`length - c + 1`有効なセグメント。 

この値を答えに追加してリセットします`length = 0`。 
6. トラバース終了後、最後のブロックも処理します。 

配列は有効なブロック内にある間に終了する可能性があるため、この手順が必要です。 
7. 蓄積された回答を印刷します。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`length`常に、受け入れ可能な囚人のみで構成される現在の最大サフィックスのサイズと等しくなります。 

無効な囚人に遭遇すると、有効なセグメントはその位置を横切ることができません。 これは、すべての有効なセグメントが 1 つの有効なブロック内に完全に存在する必要があることを意味します。 一定の長さのブロックの場合`L`、サイズの隣接するすべてのウィンドウ`c`は有効であり、そのようなウィンドウの数は正確に`L - c + 1`。 

アルゴリズムはすべての有効なブロックを 1 回だけ処理し、すべての長さをカウントするため、`c`その内側のウィンドウでは、すべての有効なセグメントが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, t, c = map(int, input().split())
a = list(map(int, input().split()))

ans = 0
length = 0

for x in a:
    if x <= t:
        length += 1
    else:
        if length >= c:
            ans += length - c + 1
        length = 0

if length >= c:
    ans += length - c + 1

print(ans)
```この実装は、ブロックカウントの考え方に直接従っています。 

変数`length`現在の連続有効領域のサイズを格納します。 以下の値を読み取るたびに`t`、領域を 1 つ拡張します。 

値を超えた場合`t`、現在のリージョンが終了したことがわかります。 そのサイズが少なくとも`c`の場合、有効なウィンドウが含まれています。 窓の数は、`length - c + 1`。 

決勝戦`if`ループの後は忘れやすいです。 これがなければ、最後の要素で終わる有効なブロックは決してカウントされません。 

すべての計算は Python 整数内に快適に収まります。 最大のケースであっても、答えはせいぜい`n`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, t, c = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0
    length = 0

    for x in a:
        if x <= t:
            length += 1
        else:
            if length >= c:
                ans += length - c + 1
            length = 0

    if length >= c:
        ans += length - c + 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("4 3 3\n2 3 1 1\n") == "2", "sample 1"

# minimum size
assert run("1 5 1\n3\n") == "1", "single valid prisoner"

# no valid segment
assert run("5 1 2\n3 4 5 6 7\n") == "0", "all prisoners invalid"

# entire array valid
assert run("5 10 3\n1 2 3 4 5\n") == "3", "all windows valid"

# exact block size equals c
assert run("4 3 4\n1 2 3 1\n") == "1", "off-by-one check"

# multiple separated blocks
assert run("7 2 3\n1 2 1 5 1 1 1\n") == "2", "split by invalid prisoner"

 ## 特殊なケース

 悪い囚人が配列を分割した場合を考えてみましょう。```
7 2 3
1 2 1 5 1 1 1
```スキャンにより、有効な長さのブロックが構築されます`3`、その後の出会い`5`。 以来`5 > 2`、アルゴリズムは次を追加します。```
3 - 3 + 1 = 1
```次に、ブロック長をゼロにリセットし、再びカウントを開始します。 最後のブロックにも長さがあります`3`、別の貢献`1`。 合計は次のようになります`2`。 

次に、正確な境界の場合を考えてみましょう。```
4 3 4
1 2 3 1
```配列全体が 1 つの有効な長さのブロックを形成します`4`。 以来`length == c`、式は次のようになります。```
4 - 4 + 1 = 1
```これにより、配列全体から構成される単一の有効なセグメントが正しくカウントされます。 

最後に、完全に無効な配列を考えてみましょう。```
5 1 2
3 4 5 6 7
```すべての値が超過`t`、そのため、アルゴリズムは繰り返しリセットされます`length`ゼロに。 ブロックがサイズに達することはありません`2`、したがって答えは残ります`0`。
