 ## 解決策
 ## 問題の理解

 私たちは都市で時間順に起こる一連の出来事を与えられます。 各イベントは、1 人以上の新しい警察官の到着、または犯罪の発生です。 新兵が到着すると、利用可能な将校の数が増加します。 犯罪が発生すると、現在利用可能な警察官が存在する場合は 1 人だけ消費されます。 そうしないと、その犯罪は処理されません。 

課題は、このプロセスをシミュレートし、発生した瞬間にどの警察官にも割り当てられなかった犯罪の数を数えることです。 

入力サイズは最大 100,000 イベントまで可能です。 これは、ネストされたスキャンや以前のイベントの再訪を実行するソリューションが遅すぎることを直ちに示唆しています。 各イベントは順番に処理される必要があり、決定は現在の状態にのみ依存するため、利用可能な役員の現在の数のみを維持するリニア スキャンで十分かつ必要です。 

各犯罪を可能な限り早い新兵と照合しようとしたり、利用可能な警察官を逆方向に検索したりする強引なアイデアは、多くの犯罪と新兵が混在する最悪の場合、二次的な動作に低下します。 10^5 イベントの場合、O(n^2) は実現可能な限界をはるかに超えます。 

微妙なエッジの事件は、新兵が現れる前の連続犯罪によって引き起こされます。 たとえば、入力が次の場合`-1 -1 1`、最初の2つの犯罪は警察官がいない状態で発生したため、どちらも未処理のままです。 後から採用した人は遡及して役に立ちません。 

もう 1 つのエッジ ケースは、新兵が必要以上に大量に一斉に到着する場合です。`5 5 -1 -1 -1`。 消費される武将は 3 人だけで、残りの武将は後のイベントまで残ります。 間違った貪欲なアプローチでは、グローバル プールを維持する代わりに、イベントごとのカウントを誤って「リセット」する可能性があります。 

## アプローチ

 単純なアプローチでは、警察官を 1 つずつ犯罪に明示的に割り当てようとします。おそらく、以前の事件をスキャンしたり、個々の警察官のリストを維持したりして、犯罪事件ごとに採用可能な新兵を検索します。 論理的には正しいですが、各役員は同一で交換可能であるため、これにより不必要なオーバーヘッドが発生します。 唯一関連する州は、現在何名の警察官が自由であるかということである。 

各警察官を個別にシミュレートすると、各新兵はリストを増やし、犯罪ごとにそのリストから 1 つの要素を削除します。 最悪の場合、シフトまたは検索によりイベントごとに O(n) 回のリスト操作を実行することになり、すべてのイベントが犯罪または新兵の場合は O(n^2) 回の動作が発生します。 

重要な観察は、警官の身元レベルの追跡は決して必要ないということです。 必要なのは、対応可能な役員を表すカウンターだけです。 各新兵イベントによってこのカウンタが追加され、可能であれば各犯罪によってこのカウンタが消費され、そうでない場合は未処理のカウントが増加します。 これにより、問題は一定時間の更新による単一パスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (個人を追跡) | O(n^2) | O(n) | 遅すぎる |
 | 最適（カウンターシミュレーション） | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの整数を維持します。1 つは現在対応可能な警察官用で、もう 1 つは未処理の犯罪用です。 

イベントを順番に処理します。 

1. 変数を初期化する`available`これは、現時点で何名の警察官が空いているかを表します。 
2. 変数を初期化する`untreated`対処できない犯罪を追跡します。 
3. 各イベントを左から右に読んでください。 
4. イベント値が正の場合、増加します。`available`新入社員はすぐに採用できるようになるため、その分だけ増加します。 
5. イベント値が`-1`、私たちは犯罪を処理しています。 
6. もし`available`0より大きい、減少する`available`この犯罪を担当する警察官が 1 人であるため、1 ずつ減点されます。 
7. それ以外の場合は増加します`untreated`現時点では対応可能な役員がいないため、1 によって。 
8. すべてのイベントを処理した後、出力します。`untreated`。 

すべての警察官は同一であり、警察官間で節約したり選択したりするメリットがないため、各犯罪ステップでの決定は局所的に最適です。 

### なぜ効果があるのか

 シーケンスの任意のプレフィックスで、次の値が`available`これは、過去の新入社員がまだ対応できる犯罪の数を正確に表しています。 各警察官が扱える犯罪は最大 1 つで、有効期限や空き状況を超える順序の制約がないため、システムは単純なリソース カウンターのように動作します。 犯罪が発生するたびに、可能であればこのカウンターを 1 ユニット消費することが常に最適であり、そうしないと、不足ごとに 1 回だけ避けられない損失の数が増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
events = list(map(int, input().split()))

available = 0
untreated = 0

for x in events:
    if x == -1:
        if available > 0:
            available -= 1
        else:
            untreated += 1
    else:
        available += x

print(untreated)
```コードはシミュレーション戦略に直接従います。 の`available`変数は加算と減算によってのみ更新されるため、イベントごとに O(1) の作業が保証されます。 チェックの順序は重要です。イベント自体は犯罪または募集のいずれかであるため、そのイベントの他の内容を更新する前に犯罪を処理する必要があります。 

よくある間違いは、新入社員をリストに保存し、そこからポップすることです。 それは不必要であり、非効率の危険があります。 もう一つの間違いはリセットです`available`グローバルに蓄積するのではなく、イベントごとに。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    events = list(map(int, sys.stdin.readline().split()))

    available = 0
    untreated = 0

    for x in events:
        if x == -1:
            if available > 0:
                available -= 1
            else:
                untreated += 1
        else:
            available += x

    return str(untreated)

# provided samples
assert run("3\n-1 -1 1\n") == "2"

# all crimes, no recruits
assert run("4\n-1 -1 -1 -1\n") == "4"

# all recruits, no crimes
assert run("5\n1 2 3 4 5\n") == "0"

# alternating pattern
assert run("6\n1 -1 1 -1 -1 2\n") == "1"

# exact balance
assert run("4\n1 1 -1 -1\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて -1 | 4 | 利用可能な役員はこれまでにいません |
 | すべて肯定的 | 0 | 犯罪は起こらない |
 | 交互 | 1 | インタリーブの正確さ |
 | バランスの取れた | 0 | 新兵の適切な消費 |

 ## 特殊なケース

 重要なエッジケースの 1 つは、新兵が存在する前に犯罪が発生する場合です。 入力用`-1 -1 -1`、アルゴリズムは維持します`available = 0`全体と増分`untreated`あらゆるイベントに。 これは、遡及的な割り当てが不可能であるという要件と一致します。 

もう 1 つのエッジ ケースは、いくつかの犯罪の後に大量の新兵が到着する場合です。 入力用`-1 -1 5`、最初の2つの犯罪が増加します`untreated`2.新兵が5名到着すると、`available`は 5 になりますが、すでにカウントされている失敗は減りません。 犯罪は発生と同時に解決され、過去の失敗は修復できないため、この動作は正しいです。 

最後のエッジケースは、新兵がシーケンスの後半で犯罪と完全に一致する場合です。`2 -1 -1`。 最初のイベントセット`available = 2`。 犯罪ごとに警官が 1 人消費され、カウンターがゼロになり、犯罪が未処理のまま残されることはありません。 これにより、カウンターが 1 対 1 の割り当てを正しくモデル化していることが確認されます。
