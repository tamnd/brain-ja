 ## 解決策
 ## 問題の理解

 すべての犯罪者は X 軸上に立っており、警察署の整数座標を 1 つ選択する必要があります。 パトカーは署から出発し、何人かの犯罪者を訪問し、署に連れ戻し、全員が逮捕されるまで繰り返します。 各旅行で最大でも持ち込めるのは、`m`犯罪者。 

1回の移動距離にかかる費用はシンプルです。 その旅行で訪れた最も遠い犯罪者が遠くにいる場合`d`駅から車は駅からその地点まで行って戻ってくる必要があるため、交通費がかかります`2d`。 

本当の問題は、犯罪者をどのように移動に分割し、総移動距離が最小になるようにステーションをどこに配置するかということです。 

ポジションはすでにソートされています。 まであります`10^6`犯罪者、二次関数は即座に除外されます。 平`O(n log n)`は、この入力サイズに対する Python の実用的な制限にすでに近づいているため、意図した解決策はソート後に基本的に線形になるはずです。入力はすでにソートされているので幸運です。 

よくある間違いは、最適なステーションの位置が常に中央値であると考えることです。 すべての犯罪者が個別に移送される場合にはこれは当てはまりますが、車は 1 回の移動で複数の犯罪者をグループ化できるため、ここでは誤りです。 

考慮する：```
n = 4, m = 2
positions = [0, 1, 100, 101]
```駅を中央分離帯の近くに配置すると、`50`、両側が高価になります。 旅行は各バッチの最も遠い犯罪者によって請求されるため、最適な解決策は実際には 1 つのクラスターの近くにあります。 

犯罪者がステーションの両側に存在する場合、別の簡単なバグが発生します。 左右へのトリップは独立しています。 いずれにせよ、車は再び駅を横切る必要があるため、1 回の旅行で両方向を効率的に組み合わせることはできません。 

例えば：```
n = 3, m = 2
positions = [-10, -9, 100]
```駅が次の場所にある場合`0`、最適な計画は次のとおりです。 

- 1回の旅行`100`、 料金`200`- 1回の旅行`-10`そして`-9`、 料金`20`合計`220`。 

左右の犯罪者を 1 回の移動にまとめようとしても、距離が長くなるだけです。 

犯罪者が立っている場所に駅が建設されている場合、別の微妙な事件が発生します。```
n = 5, m = 2
positions = [1, 1, 1, 10, 10]
```での建物`1`交通費ゼロで犯罪者3名を即座に逮捕。 犯人は二人だけ`10`交通手段が必要です。 

駅にいる犯罪者を交通費に含める不注意な実施は、過大に計上されることになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 駅は整数の座標に配置する必要があるため、すべての候補位置を試し、その駅の最適な輸送コストを計算し、最小値を取得することができます。 

駅が次のように固定されているとします。`x`。 

すべての犯罪者は左側にいる`x`右の犯罪者とは独立して処理できます。 一方で、最適な戦略は貪欲です。つまり、移動コストは到達した最遠距離のみに依存するため、常に最も遠くに残っている犯罪者を 1 回の旅行で一緒に連れて行きます。 

たとえば、片側の距離が次の場合:```
1 3 5 8 10
```そして`m = 2`の場合、最適なグループ化は次のようになります。```
(10, 8), (5, 3), (1)
```費用込み:```
2 * (10 + 5 + 1)
```ない：```
2 * (10 + 8 + 5)
```なぜなら、私たちはすでに遠くに旅​​行してしまったからです。`10`、取る`8`一緒は無料です。 

したがって、固定局の場合、線形時間で貪欲に答えを計算できます。 

問題は候補駅の数である。 座標に到達する可能性があります`10^9`したがって、整数の位置をブルートフォースすることは不可能です。 犯罪座標に限定しても、依然として`O(n^2)`総作業量は遅すぎます`10^6`要素。 

重要な観察は、コスト関数が凸であるということです。 

ステーションをわずかに右に移動すると、右側の距離は減少しますが、左側の距離は増加します。 旅行はソート順に貪欲にグループ化されるため、合計コストは傾きで単調に変化します。 これにより、ステーション座標上に離散凸関数が作成されます。 

凸性は、駅の位置に対して三分探索を使用できることを意味します。 

さらに良いことに、1 つのポジションの評価を次の手順で行うことができます。`O(n / m)`の代わりに`O(n)`グループ化された犯罪者を直接飛び越えた場合。 

結果として生じる複雑さは十分に効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O((n / m) log C) | お(1) | 承認済み |

 ここ`C`はおおよその座標範囲です`2 * 10^9`。 

## アルゴリズムのチュートリアル

 1. 候補駅位置を選択する`x`。 
2. 犯罪者を残された者に分ける`x`そしてそれらの権利`x`。 

まさに犯罪者`x`交通手段も必要ないし、何も貢献しない。 
3. 左側を加工します。 

駅からの距離は以下の通りです。```
x - position
```位置がソートされているため、最も遠い犯罪者が左端になります。 

最適な戦略は、残っている最も遠いものをグループ化することです。`m`犯罪者を一度の旅行に連れて行く。 

左側のインデックスが次の場合:```
l, l+1, ..., r
```次に、次のように追加します。```
2 * (x - positions[i])
```あらゆる人にとって`i`の段階で行われる`m`一番遠い側から。 
4. 右側も同様に加工します。 

最も遠い犯罪者が最も右の犯罪者です。 

再びサイズのグループを受け付けます`m`最も遠い側から次を追加します。```
2 * (positions[i] - x)
```5. 両辺の合計がステーション位置の総コストとなります。`x`。 
6. コスト関数は凸であるため、三分探索を実行します。`x`。 

中間の 2 点でコストを比較し、悪い方を破棄します。 
7. 検索間隔が小さくなったら、その間隔内に残っているすべての整数座標をブルート フォースして最小値を出力します。 

### なぜ効果があるのか

 固定ステーションの場合、1 回の移動コストは訪問した最も遠い犯罪者にのみ依存するため、貪欲なグループ化が最適です。 旅行がすでに距離に達したら`d`、追加の犯罪者をより近くに運ぶ`d`余分な移動距離は追加されません。 したがって、すべての移動には、利用可能な最も遠い犯罪者を最初に含める必要があります。 

ステーションの位置の関数としての総コストは凸状になります。 ステーションを右に移動すると、右側のグループが寄与するコストが減少し、左側のグループが寄与するコストが増加します。 各グループは絶対値線形項に寄与し、凸関数の和は凸のままです。 このような関数では三項検索が有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    def cost(x):
        res = 0

        # left side
        i = 0
        while i < n and a[i] < x:
            i += 1

        j = 0
        while j < i:
            res += 2 * (x - a[j])
            j += m

        # right side
        j = n - 1
        while j >= i and a[j] > x:
            j -= 1

        k = n - 1
        while k > j:
            res += 2 * (a[k] - x)
            k -= m

        return res

    lo = -10**9
    hi = 10**9

    while hi - lo > 5:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3

        if cost(m1) <= cost(m2):
            hi = m2
        else:
            lo = m1

    ans = 10**30

    for x in range(lo, hi + 1):
        ans = min(ans, cost(x))

    print(ans)

solve()
```の`cost(x)`関数は貪欲なバッチ処理ロジックを直接実装します。 

左側では、犯罪者はステーションから最も遠いものから最も近いものまですでにソートされています。 毎`m`- 番目の犯罪者は、そのグループの最も遠いメンバーであるため、1 回の移動コストを決定します。 

仮定する：```
positions = [-10, -8, -3, -1]
x = 0
m = 2
```バッチは次のとおりです。```
(-10, -8)
(-3, -1)
```のみ`-10`そして`-3`移動距離を決定するので、一歩ずつ進みます`m`。 

右側は配列の端から対称的に機能します。 

三分検索では整数座標が使用されます。 離散凸関数には平坦な領域がある可能性があるため、間隔を十分に縮小した後、残りのいくつかの座標を総当たり攻撃します。 

すべての算術演算では Python 整数が使用され、可能な最大の答えが安全に処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n / m) log C) | 各コスト評価はバッチごとに 1 人の犯罪者を処理し、三分探索は対数的に多くの評価を実行します。

def run(inp: str) -> str:

    def solve():

        def cost(x):
            res = 0

            i = 0
            while i < n and a[i] < x:
                i += 1

            j = 0
            while j < i:
                res += 2 * (x - a[j])
                j += m

            j = n - 1
            while j >= i and a[j] > x:
                j -= 1

            k = n - 1
            while k > j:
                res += 2 * (a[k] - x)
                k -= m

 ## 特殊なケース

 すべての犯罪者がすでに同じ座標に立っていると考えてください。```
5 3
10 10 10 10 10
```アルゴリズムはステーションの位置を評価します`10`。 

犯罪者が満たさないため、左右のスキャンが両方とも空になります`< x`または`> x`。 

総コストは残ります`0`全員が即座に逮捕されるため、これは正しいです。 

次に、両側の犯罪者について考えてみましょう。```
4 2
-100 -1 1 100
```駅で`0`、アルゴリズムは次のようになります。 

残ったバッチ:```

```適切なバッチ:```

```合計：```

```両側は独立して処理されますが、駅を越えてもメリットがないため、これが最適です。
