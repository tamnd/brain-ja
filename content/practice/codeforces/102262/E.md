 ## 問題の理解

 各クラスターは、分割できない単一の更新ジョブです。 クラスタ`i`含まれています`x_i`サーバーなので、処理には正確に時間がかかります`x_i`時間の単位。 許可される時間間隔は次から始まります`a_i`そしてで終わります`a_i + x_i`。 許可される間隔は必要な処理時間とまったく同じ長さであるため、実際にはそのクラスターに可能なスケジュールは 1 つだけです。それは間隔全体を占有します。`[a_i, a_i + x_i]`。 

クラスターの任意のサブセットを選択できますが、一度に更新できるクラスターは 1 つだけであるため、間隔が重複してはなりません。 選択した 2 つの間隔がエンドポイントで一致する場合、それは有効です。一度に 1 つの更新を完了できます。`t`そして次は時間通りに始めることができます`t`。 

クラスターを選択する価値`i`は`x_i`、なぜならすべて`x_i`そのクラスター内のサーバーは更新されます。 したがって、タスクは、重複しない間隔の最大重みセットを選択し、その合計重みと、対応するゼロベースのクラスター インデックスの両方を出力することです。 

と`n`まで`10^5`、すべてのサブセットを試すには、最大で`2^100000`可能性はありますが、それは完全に不可能です。 二次アルゴリズムでも次のようなパフォーマンスを発揮します。`10^10`最悪の場合、1 秒の制限をはるかに超えて操作が行われる可能性があります。 必要なのは`O(n log n)`または同様に効率的なソリューション。 

合理的な実装が間違っている可能性がある境界例がいくつかあります。 まず、接触する間隔が互換性があると考えられる必要があります。 例えば、```
21 23 2
```間隔を与える`[1,3]`そして`[3,5]`。 どちらも選択できるので、答えは`4`インデックス付き`0 1`。 を使用した先行検索`< a_i`の代わりに`<= a_i`2 番目のクラスターが誤って拒否されてしまいます。 

第 2 に、最長の個々の間隔が必ずしも最良の答えであるとは限りません。 のために```
31 44 26 3
```間隔は`[1,5]`、`[4,6]`、 そして`[6,9]`。 クラスターの選択`1`そして`2`与える`2 + 3 = 5`、クラスターを選択するよりも優れています`0`価値のあるもの`4`。 したがって、単に利用可能な最長のクラスターを取得するという貪欲な戦略は失敗する可能性があります。 

第三に、多数のクラスターが存在する場合でも、回答には 1 つのクラスターしか含めることはできません。 のために```
31 51 51 5
```3 つの間隔はすべて同一であるため、処理できるのは 1 つだけです。 正しい最大値は`5`、 ない`15`。 

最終的に、すべての時間と回答の値がおおよその値に達する可能性があります。`10^14`合計すると`10^5`クラスター。 Python の整数はこれを自動的に処理しますが、C++ 実装では次のことが必要になります。`long long`。 

## アプローチ

 直接的な総当たりアプローチでは、クラスターのすべてのサブセットが考慮されます。 サブセットごとに、選択した間隔を並べ替えたり検査したり、重複しているかどうかを確認したり、更新されたサーバーの数を計算したりできます。 これは正しいです。クラスターの考えられるすべてのセットが検査されるため、最終的には最適な実行可能なセットが見つかるはずです。 

問題はサブセットの数です。 と`n = 10^5`、 がある`2^100000`サブセット。 これらのサブセットが実現可能かどうかを確認する前でさえ、これは天文学的に大きすぎます。 

より便利なブルートフォース動的プログラミング公式では、間隔を終了時刻で並べ替えます。 すべての間隔について、以前のすべての間隔を調べて、互換性のある最後の間隔を見つけることができます。 これにより、よく知られた加重間隔スケジュールの繰り返しが行われますが、以前のすべての間隔をスキャンして先行のものを見つけるには時間がかかります。`O(n^2)`時間。 で`n = 10^5`、それは約です`5 * 10^9`最悪の場合、先行チェックが行われますが、それでも遅すぎます。 

重要な観察は、右のエンドポイントで間隔を並べ替えた後、前の間隔から必要な情報は、最後の間隔が現在の間隔の開始前に終了する最良の回答だけであるということです。 以前のすべての右エンドポイントがソートされているため、その先行エンドポイントは二分探索で見つけることができます。 

間隔を次のように表すとします。`(start, end, weight, index)`、 どこ`start = a_i`

`end = a_i + x_i`

`weight = x_i`。 

で並べ替えた後、`end`、 定義する`dp[i]`最初の設定を使用して更新できるサーバーの最大数として`i`並べ替えられた間隔。 次の間隔については、正確に 2 つの可能性があります。 それをスキップするか、そのままにしておきます`dp[i]`、またはそれを取得し、その重みとその開始時または開始前に終了する最適なソリューションを組み合わせます。 もし`p`終了点が現在の開始点以下である間隔の数です。繰り返しは次のようになります。`dp[i + 1] = max(dp[i], dp[p] + x_i)`。 

二分探索の結果`p`で`O(log n)`、完全なアルゴリズムを次のように削減します。`O(n log n)`。 

同じ動的プログラミングを使用して、選択したクラスターを再構築することもできます。 現在の間隔を取得した方が厳密に優れた値が得られる場合は常に、この間隔が選択されたことを記憶し、元の間隔に戻ります。`p`。 それ以外の場合は、前の間隔に移動します。

 ## アルゴリズムのチュートリアル

 1. すべてのクラスターを読み取り、その固定更新間隔を構築します。 クラスター用`i`、 店`(a_i, a_i + x_i, x_i, i)`。 出力では入力からのクラスター番号付けを使用する必要があるため、元のインデックスが保持されます。 
2. すべての間隔を終了時刻で並べ替えます。 この順序により、間隔のすべての先行部分がその前に表示され、さらに重要なことに、すべての終了時刻が二分探索で使用できるようになります。 
3. 配列を作成する`ends`ソートされた終了時刻が含まれます。 開始までの現在の間隔について`s`、 使用`bisect_right(ends, s)`それ以前に終了する間隔の数を確認するには`s`。 この番号に電話してください`p`。 の使用`bisect_right`間隔が正確に終了するため、意図的に行われます。`s`現在の間隔と重なりません。 
4. メンテナンス`dp`、 どこ`dp[k]`最初から取得できる更新されたサーバーの最大数です。`k`並べ替えられた間隔。 最初は`dp[0] = 0`何も選択しないとサーバーが更新されないためです。 
5. 間隔を左から右に処理します。 現在の間隔については、スキップすることが 1 つのオプションです。`dp[i]`。 もう一つの選択肢は、それを受け取ることです。`dp[p] + x_i`。 大きい方の値を格納します`dp[i + 1]`。 
6. 一緒に`dp`、各ポジションの決定を保存します。 現在の間隔を使用する方が良い場合は、その間隔が選択されたことを記録し、覚えておいてください。`p`。 スキップしても少なくとも同等の効果がある場合は、現在の間隔がスキップされたことを記録します。 両方の値が等しい場合にスキップを選択すると、最適な答えを維持しながら、単純な決定論的な再構成が得られるため便利です。 
7. 最終的な DP 状態から開始し、選択したクラスターを逆方向に再構築します。 現在の間隔が選択されている場合は、元のインデックスを追加して、次の間隔にジャンプします。`p`。 それ以外の場合は、前の DP 状態に移動します。 収集したインデックスを印刷する前に反転します。 

ソート後の不変条件は次のとおりです。`dp[i]`常に最初の値を正確に使用して最適な答えを表します`i`終了時刻順の間隔。 最適解はいずれも現在の間隔を除外します。その場合、それは次のように表されます。`dp[i]`、またはそれを含みます。この場合、選択された他のすべての間隔はその開始時刻までに終了する必要があり、そのような最適なプレフィックスは正確に次のとおりです。`dp[p]`。 これら 2 つのケースは、実行可能なすべての解をカバーしているため、再帰的に最適解を見逃すことはありません。 

## Python ソリューション```python
Pythonimport sysfrom bisect import bisect_right
input = sys.stdin.readline

def solve():    n = int(input())
    intervals = []    for idx in range(n):        a, x = map(int, input().split())        intervals.append((a, a + x, x, idx))
    intervals.sort(key=lambda item: item[1])
    ends = [item[1] for item in intervals]
    dp = [0] * (n + 1)    take = [False] * n    prev = [0] * n
    for i, (start, end, weight, idx) in enumerate(intervals):        p = bisect_right(ends, start, 0, i)
        skip_value = dp[i]        take_value = dp[p] + weight
        if take_value > skip_value:            dp[i + 1] = take_value            take[i] = True            prev[i] = p        else:            dp[i + 1] = skip_value
    answer = []    pos = n
    while pos > 0:        i = pos - 1        if take[i]:            answer.append(intervals[i][3])            pos = prev[i]        else:            pos -= 1
    answer.reverse()
    print(dp[n])    print(*answer)

if __name__ == "__main__":    solve()

並べ替えた後、`ends[i]`の終了時間です`i`- 番目の間隔。 への呼び出し`bisect_right(ends, start, 0, i)`DP によってすでに処理された間隔の間でのみ検索します。 この制限は、次の理由で役立ちます。`i`間隔の前任者にはできません`i`。 また、等しいエンドポイントも正しく処理されます。 

DP 配列には追加の要素が 1 つあります。`dp[0]`空のプレフィックスからの選択とソートされた位置の間隔を表します`i`状態を生み出す`dp[i + 1]`。 このインデックス作成により、以前のインデックスが作成されます。`p`DPポジションとして直接使用可能。 

再構築アレイは特に注目に値します。`prev[i]`間隔がある場合に意味があります`i`が選択されており、その前にどの DP 状態が使用されていたかを正確に示します。 単純に 1 ずつ減らすのではなく、その状態にジャンプします。 インターバルを飛ばした場合は、`pos`に`pos - 1`。 

厳密な比較`take_value > skip_value`値の正確さには必須ではありませんが、両方の選択肢が同等に優れている場合には、決定的な選択肢が与えられます。 このステートメントでは任意の最適なセットが許可されるため、どちらの選択も有効です。 

再構築はスケジュールを逆にたどるので、最終的なインデックスは逆になります。 出力内での順序は実際には制限がありませんが、順序を逆にすると結果の検査が容易になり、選択した間隔と同じ順序が維持されます。
