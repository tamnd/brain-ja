 ## 問題の理解

 頂点がサーバー、エッジが物理接続である無向グラフがあります。 サーバーは、同じ接続コンポーネントに属する別のサーバーからのみファイルをダウンロードできます。 サーバー識別子は (10^9) までの任意の整数であるため、配列のインデックスとして直接使用することはできません。 

すべてのクエリについて、(X) は宛先サーバーであり、次のリストには、要求されたファイルを現在持っているサーバーが含まれています。 (X) に接続されているサーバー (Y) を正確に保持し、元の順序で出力する必要があります。 順序が重要であるため、クエリ リストを単純にセットに変換することはできません。 

グラフには最大 (10^6) 個のエッジを含めることができます。 したがって、ほぼ (2\cdot10^6) 個の異なるサーバー ID が存在する可能性があります。 使用できる時間がわずか 1.5 秒であるため、クエリごとにグラフ トラバーサルを実行するとコストが高すぎます。 (Q\le 1000) を使用すると、クエリごとにすべての (10^6) エッジを 1 回スキャンするだけでも、(10^9) エッジの検査に到達できます。 (K_i\le100) なのでクエリ リスト自体は小さいため、主なタスクは接続を効率的に前処理することです。 

グラフには、クエリでのみ発生するサーバー識別子も含まれる場合があります。 このようなサーバーは、入力エッジの 1 つによって接続されていない限り、孤立した頂点になります。 エッジに発生する頂点のみを格納する不注意な実装では、(X) と (Y) の両方がグラフに存在しないクエリを誤って処理する可能性があります。 例えば：```
0
1
42 2
42 17
```正しい出力は次のとおりです。```
1 42
```両方のサーバーは分離されていますが、識別子が等しい場合は同じサーバーです。 すべての未知の識別子を何らかの一般的な「未知の」コンポーネントに属するものとして扱うと、誤って受け入れられてしまいます。`17`。 

2 番目のエッジ ケースは、グラフ内で発生するサーバーですが、別の候補は発生しません。 例えば：```
1
1 2
1
1 2
3 2
```正しい出力は次のとおりです。```
1 2
```サーバ`3`孤立した頂点なのでサーバーからダウンロードできません`2`両方の識別子がプログラムに認識されている場合でも。 ソリューションでは、異なる孤立した頂点を区別する必要があります。 

3 番目のエッジ ケースは、入力に重複と順序が含まれている場合、回答では重複と順序を保持する必要があるということです。 例えば：```
0
1
7 3
7 7 8
```出力は次のとおりです。```
2 7 7
```このクエリは、リストされた 3 つのソースと、両方の発生箇所について尋ねます。`7`有効です。 クエリ リストを並べ替えたり重複を排除したりすると、必要な出力が変更されます。 

## アプローチ

 直接的な解決策は、DFS または BFS を使用して、クエリごとに個別に (X) の接続コンポーネントを見つけることです。 コンポーネントが判明したら、最大 100 台の候補サーバーのそれぞれをそのコンポーネントに対してチェックできます。 これは正しいです。接続性はまさにダウンロードが可能かどうかを定義する条件であるためです。 

問題は、グラフの走査が繰り返されることです。 最悪の場合、1 回の走査ですべての (10^6) エッジを検査できる可能性があります。 (1000) クエリでは、追加の頂点作業をカウントする前に、最大 (10^9) 個のエッジ検査になります。 すべての候補 (Y) に対して個別の走査を実行すると、さらに状況が悪化し、(10^{11}) 個ほどの接続チェックが発生する可能性があります。 

グラフ構造により、より強力な観察が得られます。 すべてのクエリは、2 つの頂点が同じ連結コンポーネントに属しているかどうかのみを尋ねます。 それらの間の実際のパスは必要ありません。 これはまさに、素セット共用体構造 (DSU) によってサポートされる操作です。 各エッジ ((A,B)) を読み取りながら、(A) と (B) を含むコンポーネントをマージします。 すべてのエッジが処理された後、DSU 代表が等しい場合に限り、2 つのサーバーが接続されます。 

任意のサーバー識別子は 2 番目の問題を引き起こします。 従来の DSU は、(0,\ldots,V-1) などのコンパクトなインデックスを想定しています。 座標圧縮はこれを解決しますが、64 MB のメモリ制限の下では数百万の Python 整数と大きな辞書を保存することは望ましくありません。 以下の実装では、代わりに、次のようなコンパクトなオープン アドレス指定ハッシュ テーブルを使用します。`array('I')`。 占有されている各ハッシュ テーブル スロットには、サーバー ID とその DSU 親が格納されます。 識別子は正であるため、ゼロは未使用のスロットを表すことができます。 

ブルート フォースは、走査によって接続コンポーネントが 1 つだけ直接検出されるため機能しますが、コストのかかる同じ走査が多数のクエリに対して繰り返されると失敗します。 すべてのクエリはコンポーネントのメンバーシップ テストにすぎないという観察により、グラフの走査をほぼ一定時間の DSU 操作に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Q(N+V))) | (O(N+V)) | 遅すぎて、(10^9) 程度のエッジ検査まで |
 | DSU + コンパクトなハッシュ テーブル | 期待される (O(N\alpha(V)+QK\alpha(V))) | (O(V)) | 承認済み |

 ここで、エッジに現れる頂点の (V\le2N)、(\alpha) は逆アッカーマン関数であり、ハッシュ テーブル操作には (O(1)) 時間が予想されます。 

## アルゴリズムのチュートリアル

 1. グラフのエッジの数 (N) を読み取り、すべての可能なエンドポイントに十分な大きさのコンパクトなハッシュ テーブルを作成します。 異なるエンドポイントは最大 (2N) 個あり、少なくともその 2 倍のスロットが予約されるため、負荷率は 2 分の 1 未満にとどまります。 これにより、予想される短いプローブ配列が得られます。 
2. すべてのエッジ ((A,B)) について、両方のサーバー ID が存在しない場合はハッシュ テーブルに挿入します。 新しく挿入されたサーバーは、独自の DSU ルートとして起動します。 次に、(A) と (B) のルートをマージします。 

DSU は、圧縮された頂点番号によってインデックス付けされた別の親配列を必要としません。 ハッシュ テーブル スロット自体は頂点インデックスとして機能し、別のマッピング配列を保存してメモリ使用量を小さく保ちます。 
3.実装する`find`パス圧縮あり。 サーバーのスロットから開始して、それ自体が親であるルートに到達するまで、親スロットをたどります。 次に、通過したパスを圧縮して、後の操作がより早くルートに到達できるようにします。 
4.実装する`union`両方のルートを見つけて、一方のルートをもう一方のルートに接続します。 この実装では、ルート スロット自体を親値として使用するため、追加のランクやサイズの配列は必要ありません。 
5. グラフの処理後に各クエリを読み取ります。 宛先 (X) については、そのハッシュ テーブル スロットを検索します。 DSU ルートが存在する場合、その DSU ルートは接続されたコンポーネントを表します。 存在しない場合、(X) は分離サーバーです。 
6. (K) 個の候補ソースを元の順序で読みます。 それぞれ (Y) について、まずその識別子がグラフのハッシュ テーブルに存在するかどうかを確認します。 (X) と (Y) の両方が存在しない場合、それらの識別子が等しい場合にのみ接続されます。 ちょうど 1 つが欠けている場合、それらは接続できません。 両方が存在する場合は、それらの DSU ルートを比較します。 
7. 他の候補との相対的な位置を変更せずに、すべての有効な情報源を回答に追加します。 カウントの後に選択した識別子を出力します。 

### なぜ効果があるのか

 すべてのエッジが処理された後、DSU の不変条件は、グラフに表示される 2 つのサーバー間にパスがある場合、正確に同じ代表を持つということです。 すべての入力エッジは 2 つのエンドポイントを結合するため、一連のエッジによって接続されたすべてのペアは最終的に 1 つの DSU セットにマージされます。 逆に、DSU は、入力エッジが 2 つのコンポーネントを接続しない限り、2 つのコンポーネントをマージすることはありません。そのため、2 つの異なるグラフ コンポーネントが同じ代表を受け取ることはできません。 

エッジ リストにないサーバーは次数が 0 であるため、孤立したコンポーネントになります。 このような 2 つのサーバーは、同じ識別子である場合に正確に接続されます。 クエリ ロジックはこのケースを個別に処理するため、すべての候補が宛先の接続コンポーネントに属している場合に正確に受け入れられます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MASK32 = 0xFFFFFFFF
MULT = 2654435761

def solve():
    n_line = input()
    if not n_line:
        return
    n = int(n_line)

    # At most 2*n different server identifiers occur in edges.
    # Keep the load factor below 1/2.
    need = max(2, 4 * n)
    size = 1
    while size < need:
        size <<= 1

    mask = size - 1

    # 0 means an unused slot. Server identifiers are >= 1.
    keys = array('I', [0]) * size
    parent = array('I', [0]) * size

    def locate(x):
        """Return the slot containing x, or 0 if x is absent."""
        p = (x * MULT) & mask
        while True:
            k = keys[p]
            if k == 0:
                return 0
            if k == x:
                return p
            p = (p + 1) & mask

    def get_slot(x):
        """Find x, inserting it as a new DSU root when necessary."""
        p = (x * MULT) & mask
        while True:
            k = keys[p]
            if k == 0:
                keys[p] = x
                parent[p] = p
                return p
            if k == x:
                return p
            p = (p + 1) & mask

    def find(p):
        root = p
        while parent[root] != root:
            root = parent[root]

        while parent[p] != p:
            nxt = parent[p]
            parent[p] = root
            p = nxt

        return root

    def union(a, b):
        ra = find(a)
        rb = find(b)
        if ra != rb:
            parent[rb] = ra

    for _ in range(n):
        a, b = map(int, input().split())
        sa = get_slot(a)
        sb = get_slot(b)
        union(sa, sb)

    q = int(input())
    out = []

    for _ in range(q):
        x, k = map(int, input().split())
        ys = list(map(int, input().split()))

        sx = locate(x)

        if sx == 0:
            # x is an isolated server.
            ans = [y for y in ys if y == x]
        else:
            rx = find(sx)
            ans = []

            for y in ys:
                sy = locate(y)
                if sy != 0 and find(sy) == rx:
                    ans.append(y)

        if ans:
            out.append(str(len(ans)) + " " + " ".join(map(str, ans)))
        else:
            out.append("0")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の最初の部分では、エッジ エンドポイントの最大可能数に従ってハッシュ テーブルを割り当てます。 エッジごとに 4 つのスロットが予約されているため、すべてのエンドポイントが異なる場合でも、テーブルの負荷率は最大でも半分になります。 2 のべき乗のサイズにより、より高価なモジュロ演算の代わりにビット マスクを使用してハッシュ位置を取得できます。`get_slot`すべてのエンドポイントが DSU 頂点になる必要があるため、エッジの処理中に使用されます。`locate`エッジ内で発生しなかったクエリ識別子は、既存のコンポーネントに挿入されるのではなく、孤立した頂点のままでなければならないため、クエリに使用されます。 

親配列には、ハッシュ テーブルのスロット番号が格納されます。 新しく挿入された識別子の場合、`parent[p] = p`、そのスロットを独自のルートにします。 2 つのコンポーネントがマージされると、一方のルートがもう一方のルートを親として保存します。 パス圧縮`find`その後の動作はほぼ一定時間になります。 

Python には整数オーバーフローの問題はありません。 コンパクトなハッシュ テーブルは符号なしの 32 ビット サーバー識別子と 2 のべき乗のテーブル サイズを中心に設計されているため、ハッシュ関数で使用される乗算は明示的に 32 ビットにマスクされます。 

クエリ リストは、グラフの DSU が完了した後にのみ処理されます。 候補が追加されるため、元の順序は維持されます。`ans`読まれたとおりです。 並べ替えや重複排除は実行されません。 

微妙な境界ケースは (N=0) です。 その状況では、ハッシュ テーブルにグラフの頂点がありません。 クエリ対象のすべてのサーバーは分離されているため、宛先 (X) の唯一の有効なソースは、同じ識別子 (X) が再度出現することです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 期待される (O(N\alpha(V)+QK\alpha(V))) | 各エッジは、予期される 2 つの (O(1)) ハッシュ ルックアップと 1 つの DSU マージを実行します。 各クエリは最大 100 個のソースをチェックします。 
| スペース | (O(V)) | コンパクトなハッシュ テーブルと親配列には、最大 (O(2N)) 個の占有サーバー スロットが含まれます。 

ここで (V\le2N) はグラフのエッジに発生する頂点です。 (N=10^6) の場合、実装では最大 (2^{22}) 個のハッシュ スロットが予約され、キーと親の両方が 4 バイトの符号なし整数を使用します。 したがって、2 つのメイン配列は約 32 MB を占有し、意図したメモリ モデルでの入力処理と出力のための余地が残されています。 

クエリの作業は最大でも (1000\cdot100=10^5) 個の候補チェックであり、グラフの前処理に比べれば無視できる程度です。 高価な部分は、クエリごとに 1 回ではなく、1 回処理されます。

            if k == x:
                return p
            p = (p + 1) & mask

    def find(p):
        root = p
        while parent[root] != root:
            root = parent[root]

        while parent[p] != p:
            nxt = parent[p]
            parent[p] = root
            p = nxt

        return root

    def union(a, b):
        a = find(a)
        b = find(b)
        if a != b:
            parent[b] = a

    for _ in range(n):
        a, b = map(int, input().split())
        union(get_slot(a), get_slot(b))

    q = int(input())
    out = []

    for _ in range(q):
        x, k = map(int, input().split())
        ys = list(map(int, input().split()))

        sx = locate(x)

        if sx == 0:
            ans = [y for y in ys if y == x]
        else:
            rx = find(sx)
            ans = []
            for y in ys:
                sy = locate(y)
                if sy != 0 and find(sy) == rx:
                    ans.append(y)

        out.append(
            str(len(ans)) +
            ((" " + " ".join(map(str, ans))) if ans else "")
        )

    sys.stdin = old_stdin
    return "\n".join(out)

## 特殊なケース

 エッジがない場合、すべてのサーバーは分離されます。 入力用```
0
1
42 3
42 17 42
```目的地`42`にはグラフ エントリがないため、クエリ ロジックは分離サーバー ブランチを選択します。 両方の発生を維持します`42`そして拒否します`17`、生産```
2 42 42
```グラフ内に出現するサーバーは、3 番目のクエリされた識別子が存在しないままでも、別のサーバーに接続できます。 のために```
1
1 2
1
1 3
2 3 1
```DSU には 1 つのコンポーネントが含まれています`{1,2}`。 サーバ`3`不在で孤立しているため、`1`宛先のコンポーネントに属します。 結果は```
1 1
```このため、存在しない識別子に特別な共通代表を単純に割り当てることはできません。 存在しないすべての識別子は、それ自体が分離されたコンポーネントです。 

候補が複数回出現する場合、出現ごとに個別に評価する必要があります。 のために```
0
1
7 4
7 7 8 7
```宛先は隔離されたサーバーです`7`、つまり、次の 3 つの出現は`7`はすべて有効です。 出力は```
3 7 7 7
```実装構造`ans`元のリストを反復処理するため、順序や多重度の情報が失われることはありません。 

自己ループでは、別のサーバーへの接続は作成されません。 のために```
1
1000000000 1000000000
1
1000000000 2
1 1000000000
```DSU は、次の内容を含む 1 つのシングルトン コンポーネントを作成します。`1000000000`。 候補者`1`は別の隔離されたサーバーですが、`1000000000`目的地そのものです。 出力は```
1 1000000000
```繰り返されるエッジも同様に動作します。 電話をかける`union`すでに同じ DSU セット内にある 2 つの頂点に接続しても何も変更されないため、重複した接続によってコンポーネントの構造が破損することはありません。 

最後に、サーバー識別子は (10^9) ほど大きくなる可能性がありますが、サーバーの数ははるかに少なくなります。 ハッシュ テーブルは、識別子によってインデックス付けされた配列を割り当てようとするのではなく、識別子を意図的に 32 ビットの符号なし整数として格納します。 この違いにより、メモリ使用量が識別子の最大値ではなく実際のサーバーの数に依存するようになります。
