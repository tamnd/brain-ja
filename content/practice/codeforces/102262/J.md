 ## 解決策
 ## 問題の理解

 有効なメッセージから 1 文字だけを削除して取得された JSON のような文字列が与えられます。 有効なメッセージには意図的に短い文法が含まれています。 メッセージ全体は文字列またはオブジェクトのいずれかです。 文字列は、二重引用符で囲まれた空ではない一連のラテン文字と数字です。 オブジェクトは中かっこで囲まれ、0 個以上のキーと値のペアが含まれます。 すべてのキーは文字列であり、すべての値は文字列または別のオブジェクトであり、これらの部分間の句読点は固定されています。 

私たちの仕事は、元のデータを意味的に再構築することではありません。 結果の文字列がこの文法に従うように、どこかに 1 文字を挿入するだけで済みます。 削除された文字が 1 文字の文字列内にあった場合、その正確な身元を推測することはできないため、次のような許可された英数字を挿入します。`a`、で十分です。 

入力長は (10^5) に達する可能性があります。 1 秒という制限があるため、文字列全体を繰り返しスキャンするアルゴリズムはコストが高すぎます。 線形または線形に近いパーサーが自然なターゲットです。 文法は非常に小さいため、現在のパーサーの状態とネストされたオブジェクトを表すスタックのみを保持できるため、一般的な JSON 解析機構は必要ありません。 

ブレースのみに基づいた単純な修復では、誤った対応をしてしまうケースがいくつかあります。 たとえば、入力`{"key":"value}`値の終了引用符が欠落しているため、答えは次のようになります。`{"key":"value"}`。 左中括弧と右中括弧のみをカウントする戦略では、バランスの取れた中括弧が表示され、実際のエラーが見逃されます。 

もう一つのケースは、`{"key""value"}`。 欠落している文字はキーと値の間のコロンです。`{"key":"value"}`。 すべての引用符と中括弧はすでにバランスが取れているため、一致しない区切り文字のみを検索するパーサーは再び失敗します。 

特に小さなエッジケースは、`{`。 元の JSON は次のようになっている可能性があります`{}`、右中括弧が削除されているため、正しい答えは次のようになります。`{}`。 同様に、`}`に修理することができます`{}`欠落している左中括弧を挿入することによって。 2 番目のケースは、欠落している文字が最初の入力文字の後ではなく前にあるため、重要です。 

最後に考えてみましょう`""`。 通常の JSON 構文では、これは有効な空の文字列ですが、問題により空の文字列は明示的に禁止されています。 元の文字から唯一の文字を削除することで発生する可能性があります`"a"`。 次のように復元する場合があります`"a"`2 つの引用符の間に任意の英数字を挿入します。 

## アプローチ

 直接的な総当たりアプローチは簡単です。 考えられるすべての挿入位置を試し、削除された可能性のあるすべての文字を試し、結果の文字列を構築し、それが有効なメッセージであるかどうかを確認します。 文字セットは 4 つの構造文字で構成されます`{`、`}`、`:`、`,`、二重引用符、および 62 個の文字と数字なので、候補は 67 個あります。 

(n+1) 個の可能な挿入位置があります。 結果の文字列を最初から最後まで解析する必要があるため、1 つの候補をチェックするには (O(n)) 時間がかかります。 したがって、最悪のケースは、約 (67(n+1)n) 文字の操作になります。 (n=10^5) の場合、これはおよそ (6.7\cdot10^{11}) 回の操作となり、制限時間を大幅に超えます。 ブルートフォース手法は、文字通りすべての可能な 1 文字の修復を検査するので正しいのですが、隣接する候補の同じパーサー状態を再検出するのにほぼすべての時間を費やします。 

有益な観察は、有効な文法が決定的であるということです。 有効なメッセージのあらゆる時点で、次にどのような種類のトークンが表示されるかを正確に把握できます。 キー文字列の後にコロンが続きます。 値の後には、コンマまたは現在のオブジェクトの右中括弧が続きます。 文字列内に使用できるのは、英数字または終了引用符のみです。 オブジェクトの先頭で、オブジェクトがすぐに閉じるか、文字列キーが始まります。 

入力は有効なメッセージとは 1 つだけ削除が異なっているため、決定論的パーサーが続行できない最初のポイントで欠落文字が特定されます。 すべての挿入位置を試す必要はありません。 文法が必要とする文字を現在の位置に挿入し、その文字が常に存在していたかのように入力の残りの解析を続けます。 

唯一の特殊なケースは空の文字列です。 文字列が始まり、次の入力文字が既にその終了引用符である場合、入力は構文的には正しく構成されていますが、問題の非空文字列ルールに違反します。 欠落している文字は英数字である必要があり、`a`有効な結果が得られます。 

ネストされたオブジェクトは、パーサーがスタックを必要とすることを意味します。 ネストの深さは (O(n)) にすることができ、深くネストされた入力は Python の再帰制限や C コール スタックに依存すべきではないため、再帰的な関数呼び出しよりも明示的なスタックの方が適しています。

 ## アルゴリズムのチュートリアル

 1. 文法記号を含むスタックから開始します`VALUE`そして`END`。`VALUE`ルートメッセージを解析する必要があることを意味しますが、`END`入力文字が後に残らないことを意味します。 
2. スタックの最上位シンボルを処理します。 のために`VALUE`、現在の入力文字を検査します。 二重引用符は文字列の始まりであり、`{`オブジェクトを開始します。 現在のキャラクターが`}`、唯一可能な 1 文字の修復は欠落です`{`、空のオブジェクトが作成されます。 別の文字の場合、問題保証の中で唯一実行可能な修復は、文字列の開始引用符が欠落していることです。 
3. オブジェクトをシーケンスに展開します`{`、オブジェクト本体、`}`。 オブジェクト本体は空であるか、ペアの後にゼロ個以上のコンマ区切りのペアが続くかのいずれかです。 スタックを使用すると、任意の深いネストに対して同じロジックを機能させることができます。 
4. オブジェクト本体の場合、現在の文字が`}`、本文を空のままにして、右中括弧記号でそれを消費させます。 それ以外の場合は、キーと値のペアの解析を開始します。 
5. ペアを文字列キーとして解析し、続いて`:`、その後に値が続きます。 コロンがない場合、ターミナルは`:`は現在の文字と一致しないため、正確にその位置に挿入を記録し、入力文字を消費せずに続行します。 
6. 値の後に、オブジェクトは次のいずれかで終わることができます。`}`または続行してください`,`そしてもう一組。 どちらの文字も存在しない場合、欠落している文字は同じ終端一致ルールによって決定されます。 
7. 文字列の内容は他の文法とは異なるため、文字列を個別に解析します。 開始引用符を使用し、連続するすべての英数字を使用してから、終了引用符を要求します。 終了引用符が欠落している場合は、現在の位置に終了引用符を挿入します。 
8. 文字列が空の場合、つまり開始引用符の直後に別の引用符が続く場合は、次の文字列を挿入します。`a`彼らの間で。 これにより、既存の入力文字を変更せずに、必要な空でない文字列プロパティが復元されます。 
9. 必要な端子が現在の入力文字と一致しない場合は常に、その端子を現在のインデックスで欠落文字として記録します。 入力文字は意図的に消費されません。欠落文字を挿入した後、既存の文字がまさにパーサーが次に処理する文字となるからです。 
10.その後`END`に達すると、元の入力文字がすべて消費されている必要があります。 次に、記録された挿入位置と文字を使用して、その位置の前に 1 つのスライス、挿入された文字、その後に 1 つのスライスを含む回答が作成されます。 

### なぜ効果があるのか

 欠落文字に到達する前に、入力は元の有効な JSON の正確なプレフィックスであるため、決定論的パーサーは元の文法に従い、すべての文字を正しく消費します。 まず、パーサーが存在しない文字を必要とする場合、現在の入力と元のメッセージの唯一の違いは、まさにその削除された文字です。 文法に必要な文字をその位置に挿入すると、元のパーサーの状態が復元されます。 

挿入後、残りのすべての入力文字は、元の有効なメッセージに表示されたときとまったく同じ状態で処理されます。 スタックはオブジェクトの入れ子構造を保持しますが、文字列パーサーは文字列の内容と JSON 句読点の区別を保持します。 空の文字列の場合は、カスタム文法に違反しながら入力が構造的に解析できる唯一の状況であり、英数字 1 文字を挿入するとその違反が正確に修正されます。 

このステートメントは、1 回の挿入後に何らかの有効なメッセージが存在することを保証するため、この決定論的な解析プロセスによって検出される最初の修復は、削除された文字とその位置であり、無害な選択に至るまでです。`a`削除された文字自体が特定できない場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def repair(s):
    n = len(s)
    i = 0

    stack = ["END", "VALUE"]
    insert_pos = -1
    insert_char = ""

    def add_missing(ch):
        nonlocal insert_pos, insert_char
        if insert_pos == -1:
            insert_pos = i
            insert_char = ch

    def is_alnum(c):
        return (
            "a" <= c <= "z"
            or "A" <= c <= "Z"
            or "0" <= c <= "9"
        )

    while stack:
        symbol = stack.pop()

        if symbol == "END":
            continue

        if symbol == "VALUE":
            if i < n and s[i] == '"':
                stack.append("STRING")
            elif i < n and s[i] == "{":
                stack.append("OBJECT")
            elif i < n and s[i] == "}":
                add_missing("{")
                stack.append("OBJ_END")
                stack.append("OBJ_BODY")
            else:
                add_missing('"')
                stack.append("STRING")

        elif symbol == "OBJECT":
            if i < n and s[i] == "{":
                i += 1
            else:
                add_missing("{")

            stack.append("OBJ_END")
            stack.append("OBJ_BODY")

        elif symbol == "OBJ_END":
            if i < n and s[i] == "}":
                i += 1
            else:
                add_missing("}")

        elif symbol == "OBJ_BODY":
            if i < n and s[i] == "}":
                continue

            stack.append("MORE")
            stack.append("PAIR")

        elif symbol == "MORE":
            if i < n and s[i] == "}":
                continue

            stack.append("MORE")
            stack.append("PAIR")
            stack.append(",")

        elif symbol == "PAIR":
            stack.append("VALUE")
            stack.append(":")
            stack.append("STRING")

        elif symbol == "STRING":
            if i < n and s[i] == '"':
                i += 1
            else:
                add_missing('"')

            if i < n and s[i] == '"':
                add_missing("a")
                i += 1
                continue

            while i < n and is_alnum(s[i]):
                i += 1

            if i < n and s[i] == '"':
                i += 1
            else:
                add_missing('"')

        else:
            if i < n and s[i] == symbol:
                i += 1
            else:
                add_missing(symbol)

    return s[:insert_pos] + insert_char + s[insert_pos:]

def main():
    s = input().strip()
    print(repair(s))

if __name__ == "__main__":
    main()
```の`stack`まだ処理する必要がある文法記号が含まれています。`VALUE`はルートの非終端ですが、`OBJECT`、`OBJ_BODY`、`PAIR`、`MORE`、 そして`STRING`再帰なしで展開できる文法部分を記述します。 

の`VALUE`ブランチは、現在の位置でどの種類の値が始まるかを決定します。 特別な`}`ブランチは、次のようなネストされた空のオブジェクトを含め、左中括弧が削除された場合を処理します。`{"a":}}`。`OBJECT`左中括弧を使用し、オブジェクト本体とそれに続く閉じ中括弧をスケジュールします。 逆の順序`stack.append`スタックは LIFO であるため、呼び出しは意図的です。 たとえば、`OBJ_END`その後`OBJ_BODY`作る`OBJ_BODY`最初に実行します。`PAIR`に拡大します`STRING`、`:`、 そして`VALUE`。 ここでも、シンボルは逆の順序でプッシュされるため、パーサーは最初にキーを認識し、最後に値を認識します。`MORE`はペアが完成した後の繰り返しを表します。 もし`}`がすでに存在する場合、繰り返しは終了します。 それ以外の場合は、欠落しているコンマまたは既存のコンマが処理され、その後に別のペアと別のコンマが処理されます。`MORE`。 

の`STRING`ブランチは、句読点によって長さが決定されない文法の唯一の部分を処理します。 開始引用符を使用し、英数字コンテンツをスキャンして、終了引用符を使用または挿入します。 2 つの引用符が隣接している場合、`a`文字列が空ではなくなります。 

ヘルパーさん`add_missing`最初の挿入のみを記録します。 問題保証の下では、挿入は 1 回だけで十分であるため、その後のすべてのパーサー アクションは修復された文法に対して機能します。 元の文字列自体は解析中に変更されることはありません。 最終的な構築では挿入が 1 回だけ実行されるため、線形時間で実行されます。 

再帰がなく、入力サイズに応じた整数演算もないため、再帰の深さや整数のオーバーフローの問題はありません。 明示的なスタックには、深くネストされた JSON オブジェクトに (O(n)) 個の文法記号を含めることができます。
