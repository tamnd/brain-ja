 ## 解決策
 ## 問題の理解

 バナー値の配列は厳密に減少しています (P_1>P_2>\dots>P_N)。 順序を変更せずに、バナーを正確に (K) 個の空でない連続ブロックに分割する必要があります。 

ブロックについては、位置 (l,\ldots,r) が含まれていると仮定します。 (P) は厳密に減少しているため、ブロック内の最大値は常に (P_l) であり、最小値は (P_r) です。 したがって、その貢献は、

 [
 P_r(r-l+1)-L_sP_l。 
】

 パーティションの値は、すべての (K) ブロックにわたるこれらの寄与の合計です。 可能な最大値が必要です。 

制約 (N\le 50000) は、すべてのブロック番号内の (N) の二次関数を除外します。 (K\le100) の場合、(O(KN^2)) 動的プログラムは、2 秒の制限をはるかに超える最大値でおよそ (1.25\cdot10^{11}) の遷移を実行します。 ターゲットは (O(KN)) またはおそらく (O(KN\log N)) に近い値である必要があります。 

(P) の厳密な減少は、最適化を可能にする構造特性です。 これにより、すべての連続ブロックの最小値と最大値の単純な式と、凸包トリックの単調クエリ値の両方が得られます。 

最初のエッジ ケースは (N=1)、(K=1) です。 のために```
1 1
5
7
```唯一のブロックには値 (5-7\cdot5=-30) があるため、答えは (-30) になります。 応答またはすべての DP 状態をゼロに初期化する実装では、最適な値が負になる可能性があるため、間違った結果が暗黙的に返されます。 

別のエッジケースは (K=1) です。 のために```
3 1
8 5 2
3
```まったく選択肢がありません。 配列全体は 1 つのブロックであり、その値は (2\cdot3-3\cdot8=-18) です。 DP の実装では、誤って余分なカットや空のブロックを許可してはなりません。 

反対側の境界は (K=N) です。 のために```
3 3
9 4 1
0 0 0
```すべてのバナーはシングルトン ブロックであるため、答えは (9+4+1=14) になります。 これにより、最初または最後のカットが省略されるインデックス作成の間違いが見つかります。 

入力は (P_i>P_{i+1}) を保証するため、すべての (P_i) が等しい配列は有効なテスト ケースではありません。 ただし、等しい (L_i) は完全に有効であり、ブロック ペナルティがすべての層で同一であるため、実装のテストに役立ちます。 

## アプローチ

 直接動的プログラムでは、最後のカットの位置が考慮されます。 (dp_s[r]) を、正確に (s) 個のブロックに分割された最初の (r) 個のバナーの最大値とする。 最後のブロックが (l) で始まる場合、前の (s-1) ブロックは位置 (1\ldots l-1) をカバーし、最後のブロックが寄与します。 

[
 P_r(r-l+1)-L_sP_l。 
】

 したがって、

 L_sP_l
 \右）。 
】

 この反復はすでに正しいですが、すべての (r) に対して可能なすべての (l) を評価すると、コスト (O(KN^2)) がかかります。 (N=50000) と (K=100) の場合、これは約 (1.25\cdot10^{11}) 個の候補遷移になります。 

(P_r) を含む用語を展開すると、有益な観察結果が表示されます。

\end{整列}
 】

 固定 (l) の場合、最大値内の式は (x=P_r) で評価される行になります。 

[
 y=(-l)x+\left(dp_{s-1}[l-1]-L_sP_l\right)。 
】

 したがって、考えられるすべての開始位置 (l) は、傾き (-l) と切片 (dp_{s-1}[l-1]-L_sP_l) を持つ直線を作成します。 

(r) が増加すると、(-1,-2,-3,\ldots) が減少するため、勾配は降順で挿入されます。 同時に、元の (P) 配列は厳密に減少しているため、(P_r) は降順でクエリされます。 これはまさに、deque スタイルの凸包トリックが挿入行ごとおよびクエリごとに償却 (O(1)) 作業を与える単調な状況です。 

ブルートフォースの再発が解決策の基礎であることに変わりはありません。 凸包トリックは、以前のすべての開始位置の最大値がどのように維持されるかを変更するだけです。

 ## アルゴリズムのチュートリアル

 1. プレフィックス (P_1,\ldots,P_r) を正確に (s) 個のブロックに分割するための最適な値として (dp_s[r]) を定義します。 前の層だけが必要なので、実装では`prev[r]`そして`cur[r]`。 
2. 固定ブロック番号の場合、遷移を次のように書き換えます。 

P_r(r+1)
 +
 \max_l
 \左(
 (-l)P_r+
 dp_{s-1}[l-1]-L_sP_l
 \右）。 
】

 (l) に依存する部分は、(x=P_r) で評価される行になります。 

1. (r=s,s+1,\ldots,N) を処理する場合、(l=r) に相当する行を挿入します。 その傾きと切片は、

 [
 m=-r、
 \qquad
 b=dp_{s-1}[r-1]-L_sP_r。 
】

 前のブロックが正確に最初の (r-1) 位置を占めているため、この行は有効です。 

1. 挿入されたラインを上部の凸包として維持します。 到着する勾配は厳密に減少するため、新しく挿入されたラインは船体の端近くの一部のラインのみを無関係にすることができます。 連続する3本の直線(A,B,C)において、(A)と(B)の交点が(B)と(C)の交点の右側にない場合、(B)の直線は不要です。 

傾きが減少するライン ((m_1,b_1),(m_2,b_2),(m_3,b_3)) の場合、この条件は浮動小数点を使用せずにチェックできます。 

[
 (b_2-b_1)(m_2-m_3)
 \le
 (b_3-b_2)(m_1-m_2)。 
】

 整数相互乗算により、精度エラーが回避されます。 

1. (x=P_r) でハルをクエリします。 (r) が増加すると (P_r) が減少するため、最適なラインは船体を通って前方にのみ移動します。 2 行目は現在の (x) で少なくとも 1 行目と同じくらい大きな値を示しますが、1 行目は破棄します。 将来のクエリ値はすべてさらに小さくなるため、破棄された行が再び最適になることはありません。 
2. (P_r) での最良のラインの値が (mP_r+b) であるとします。 セット

 [
 dp_s[r]=P_r(r+1)+mP_r+b。 
】

 すべて（r）を処理した後、置き換えます`prev`と`cur`次のブロックに進みます。 

1. 正確に (K) 層を重ねた後、`prev[N]`は、正確に (K) 個のブロックに分割されたすべて (N) 個のバナーの最大値であるため、必須の答えになります。 

不変条件は、各クエリの直前に、アクティブなハルには、現在の最後のブロックのすべての有効な開始位置に対応する行が正確に含まれており、決して最適化できない行はすべてすでに削除されていることです。 傾きとクエリ値の単調性により、どちらかの端からの線の削除が永続的であることが保証されます。 したがって、すべての DP 状態に対して選択されたラインは、すべての有効な以前のカットの中で可能な最良の遷移になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    L = list(map(int, input().split()))

    neg_inf = -(10 ** 30)

    # prev[r] = best value for the first r elements using the
    # already processed number of blocks.
    prev = [neg_inf] * (n + 1)
    prev[0] = 0

    for s in range(1, k + 1):
        cur = [neg_inf] * (n + 1)
        loss = L[s - 1]

        # Hull is stored in two parallel arrays.
        # Lines are kept in decreasing slope order.
        slopes = []
        intercepts = []
        head = 0

        for r in range(s, n + 1):
            # Add the line corresponding to l = r:
            #
            # y = (-l) * x + prev[l - 1] - loss * P_l
            m = -r
            b = prev[r - 1] - loss * p[r - 1]

            while len(slopes) - head >= 2:
                m1 = slopes[-2]
                b1 = intercepts[-2]
                m2 = slopes[-1]
                b2 = intercepts[-1]

                # Remove the middle line if it is redundant.
                if (b2 - b1) * (m2 - m) <= (b - b2) * (m1 - m2):
                    slopes.pop()
                    intercepts.pop()
                else:
                    break

            slopes.append(m)
            intercepts.append(b)

            x = p[r - 1]

            # Queries arrive with decreasing x, so the optimum
            # moves only from the front toward the back.
            while len(slopes) - head >= 2:
                v1 = slopes[head] * x + intercepts[head]
                v2 = slopes[head + 1] * x + intercepts[head + 1]

                if v1 <= v2:
                    head += 1
                else:
                    break

            best_line = slopes[head] * x + intercepts[head]
            cur[r] = x * (r + 1) + best_line

        prev = cur

    print(prev[n])

if __name__ == "__main__":
    main()
```DP の初期化では、`prev[0] = 0`つまり、ブロックを作成する前は、空のプレフィックスの値はゼロです。 不可能な分割は決して最大値に関与してはならないため、他のすべての状態は負の無限大から始まります。 

スタートポジションのライン`r`用途`prev[r - 1]`そして`p[r - 1]`Python ではゼロベースのインデックスが使用されますが、数学的位置 (r) は 1 ベースであるためです。 傾斜は`-r`、 ない`-(r - 1)`代数には 1 から始まる位置 (l) を持つ項 (-lP_r) が含まれているためです。 

船体は勾配を降順に保存します。 冗長性テストでは整数の乗算のみが使用されるため、浮動小数点の交差座標は必要ありません。 これは、関連する値が十分に大きいため、浮動小数点比較では正確な順序が失われる可能性があるため、重要です。 

の`head`インデックスは両端キューの先頭として機能します。 行はクエリによって破棄されるときに物理的に削除されないため、(O(N)) のシフト操作が回避されます。 各行は 1 回追加され、最大 1 回後ろから削除され、最大 1 回クエリ ポインタによって渡されます。 

Python の整数には任意の精度があるため、凸包テストと DP で使用される積がオーバーフローすることはありません。 最大の中間値も Python で快適に管理できます。
