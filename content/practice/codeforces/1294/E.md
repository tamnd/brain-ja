 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$マトリックス。 ターゲット行列は完全に固定されています: 行優先の順序$1$に$n \cdot m$。 最終的にその位置に配置される値$(r,c)$は$$(r-1)\cdot m + c.$$2 種類の操作を実行する場合があります。 1 回の移動で任意の単一セルの値を任意に変更できます。 また、1 回の移動を消費して、列全体を 1 位置ずつ上に循環的にシフトすることもできます。 

目標は、最小の合計移動数を使用して、指定された行列をターゲット行列に変換することです。 

最初の観察は、列シフトによって列間で要素が移動されることはないということです。 すべての値は常に元の列に残ります。 すべての数値のターゲット位置がわかっているため、各列を個別に最適化できます。 合計の答えは、すべての列の最適コストの単純な合計です。 

制約があるため、この分解が必要になります。 両方$n$そして$m$と同じ大きさにすることができます$2 \cdot 10^5$、ただし、彼らの製品にも制限があります$2 \cdot 10^5$。 すべての行のペアを試したり、シフトを繰り返しシミュレートしたりするアルゴリズムは、コストが高くなりすぎます。 セルの数が線形に近いものが必要です。 

見落としやすいエッジケースがいくつかあります。 

考慮する```
2 2
100 100
100 100
```ターゲット行列のどこにも値が属しません。 すべてのセルは最終的には書き換えられなければなりません。 正しい答えは、$4$。 シフトの機会のみを考慮する不注意なソリューションでは、シフトが役立つと誤って考える可能性があります。 

考慮する```
3 1
2
3
1
```対象となる列は、```
1
2
3
```単一の上方巡回シフトにより、ターゲット列が即座に生成されます。 正しい答えは、$1$。 シフト計算における 1 つずつの間違いにより、単一列インスタンスでは頻繁に失敗します。 

考慮する```
3 2
1 2
3 4
5 100
```1 つのセルだけが間違っています。 正しい答えは、$1$、最後の値を書き換えることによって。 一部の値が一致するたびに常にシフトを実行するソリューションでは、誤って余分な操作が費やされる可能性があります。 

最も微妙なケースは、値がターゲット行列の現在の列に属しているが、考慮されたシフト量によってそのターゲット行に到達できない場合です。 このような値は、そのシフトのスコアに寄与すべきではありません。 

例えば：```
3 2
5 2
3 4
1 6
```最初の列の値$5$そこに属しているから$5 \equiv 1 \pmod 2$ですが、そのターゲット行は、特定のシフトに関連する行とは異なります。 数え方を間違えると、答えが過小評価されてしまいます。 

## アプローチ

 この問題を考える強引な方法は、各列を個別に処理し、可能な限りの循環シフトを試行することです。 シフト量を選択すると$s$、シフトされた列をシミュレートし、正しい値がすでに含まれている位置の数を数え、残りを書き直すことができます。 

1 つの列に対して、$n$可能なシフト量。 単純に 1 つのシフトを評価するには、すべてのシフトを調べる必要があります$n$行。 それは与える$O(n^2)$列ごとに作業し、$O(n^2m)$全体。 

以来$n \cdot m$届くかもしれない$2 \cdot 10^5$、二乗因数はあまりにも高価です。 最悪の形で、$n=2\cdot10^5$そして$m=1$、大まかに必要になります$4\cdot10^{10}$操作。 

重要な点は、固定列の場合、各セルが最大 1 つのシフト量しか支援できないということです。 

列を調べているとします。$j$。 値がこの列に属するのは、そのターゲット列も同じである場合のみです。$j$。 ターゲット式を使用すると、$$x=(r-1)m+j$$いくつかのターゲット行に対して$r$。 

値を与える$x$、それが列に属しているかどうかをすぐに判断できます$j$。 そうでない場合は役に立たず、最終的には書き直す必要があります。 

それが属している場合は、そのターゲット行を計算できます。 次に、循環シフトの回数がこの値を正しい行に配置することを正確に決定できます。 このようなシフト量は 1 つだけです。 

すべてのシフトを試してすべてのセルをチェックする代わりに、プロセスを逆にします。 各セルについて、それがサポートする一意のシフトを計算し、そのシフトのカウンターをインクリメントします。 

列のすべての行を処理した後、すべてのシフトがわかります。$s$適用後に正しくなるセルの数は何個ですか$s$シフトします。 

シフトを選択した場合$s$、費用は次のとおりです。$$s + (n - \text{correct}_s).$$最初の項は、実行される列シフトの数です。 2 番目の項は、再書き込みが必要な残りのセルの数です。 

全体的に最小限のものを採用する$s$その列の最適コストが得られます。

 | ブルートフォース |$O(n^2m)$|$O(n)$| 遅すぎる |
 | 最適 |$O(nm)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各列に対して個別に次のようにします。 

1. 配列を作成する`cnt`長さの`n`、ゼロに初期化されます。`cnt[s]`正確に実行した場合に正しくなるセルの数を保存します`s`この列の上向き循環シフト。 
2. 行ごとに`i`、値を検査します`a[i][j]`。 
3. この値が列に属することができるかどうかを確認します`j`ターゲットマトリックス内。 

値は列に属します`j`もし$$(a[i][j]-1)\bmod m = j.$$この条件が満たされない場合は、値を無視してください。 
4. この値のターゲット行を計算します。 

行には内部的にゼロからインデックスが付けられているため、$$target = \frac{a[i][j]-1}{m}.$$5. この値をターゲット行に配置するシフト量を決定します。 

後`s`上にシフト、現在行にある要素`i`に移動します$$(i-s+n)\bmod n.$$この位置を同等にしたい`target`。 

並べ替えると$$s = (i-target+n)\bmod n.$$6. 一部の値は列に属しますが、行列の外のターゲット行に対応します。 

有効なターゲット行は次のとおりです。`0 ... n-1`、計算対象行が少なくとも次の値である値を無視します。`n`。 
7. インクリメント`cnt[s]`。 
8. すべての行が処理された後、すべてのシフト量を評価します`s`。 

選ぶのにかかる費用`s`は$$s + (n-cnt[s]).$$9. すべてのシフトの最小コストを取得し、それをグローバルな答えに追加します。 
10. すべての列に対して繰り返します。 

### なぜ効果があるのか

 固定列の場合、列シフトが他の列と相互作用することはないため、最適化は独立しています。 

それぞれの有効な値にはターゲット行が 1 つだけあります。 固定の現在の行とターゲット行の場合、値を正しい位置に移動する循環シフト量が 1 つだけ存在します。 アルゴリズムはこの寄与を直接カウントします。 

シフト量選択後$s$、すべてのカウント値はすでに最終的な場所を占めており、書き換える必要はありません。 1 行おきにその値を変更して修正する必要があり、行ごとに 1 回の操作が必要になります。 出演以来$s$コストを正確にシフトする$s$移動した場合、その選択にかかる合計コストは$s + (n-cnt[s])$。 

考えられるすべてのシフト量が評価されるため、取得される最小コストがその列にとって最適になります。 異なる列に対する操作が相互に影響を与えることはないため、列の合計は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    ans = 0

    for col in range(m):
        cnt = [0] * n

        for row in range(n):
            x = a[row][col]

            if (x - 1) % m != col:
                continue

            target = (x - 1) // m

            if target >= n:
                continue

            shift = (row - target + n) % n
            cnt[shift] += 1

        best = n

        for shift in range(n):
            cost = shift + (n - cnt[shift])
            if cost < best:
                best = cost

        ans += best

    print(ans)

solve()
```シフトによって列間で要素が移動されることはないため、外側のループは列を独立して処理します。 

条件```
(x - 1) % m != col
```値がターゲット行列の現在の列に属しているかどうかを確認します。 このテストに合格しない値は、シフトを使用して修正することはできず、書き換えによってのみ影響します。 

ターゲット行の計算```
target = (x - 1) // m
```ゼロベースのインデックスを使用します。 よくある間違いは、1 から始まる行番号と 0 から始まる行番号を混合することです。これにより、シフト計算が不正確になります。 

小切手```
if target >= n:
    continue
```は不可欠です。 値は、行列を超えた行に対応していながら、列の条件を満たしている場合があります。 このような値は、有効なターゲット位置を占有することはできません。 

シフト式```
shift = (row - target + n) % n
```は周期運動方程式を解くことから直接得られます。 減算を逆にするとシフト方向が逆になり、多くのテストで間違った答えが生成されます。 

最後に、シフト量ごとに、シフトを実行するコストと、まだ正しくない行をすべて書き直すコストを組み合わせます。

 ## 特殊なケース

 ### 値はターゲット列に属しません

 入力:```
2 2
100 100
100 100
```すべての列について、$$(100-1)\bmod 2 = 1.$$カラムテストに合格するのはカラム 1 だけですが、$$(100-1)/2 = 49$$これは有効な行インデックスの最大値を超えています。 どのエントリもシフト カウントに影響しません。 

全て`cnt[s]`ゼロのままなので、最小コストは次のようになります。$$0 + (2-0)=2$$列ごとに。 合計の答え:`4`。
