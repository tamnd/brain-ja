 ## 問題の理解

 一度に 1 要素ずつ配列を構築しています。 挿入するたびに、特別な操作を使用して値を「再構成」できます。固定数値を加算または減算できます。$x$ゼロを下回らない限り、任意の要素に何度でもアクセスできます。 このような調整を実行した後、配列の最大可能 MEX を知りたいと考えます。 

重要な点は、配列要素が固定値ではなくなったことです。 それぞれの数字$y$挿入するのは単なる値ではなく、可能な値の等差数列全体です。$$y, y + x, y + 2x, \dots$$また、下方向に移動します$x$非負である限り、つまり、$y$正確にすべての数字が一致する$y \bmod x$、ただし、負でない整数に制限されます。 

したがって、各クエリの後で、次のことを知りたいと思います: プレフィックスの大きさ$[0, 1, 2, \dots]$利用可能な数値を使用して完全に「カバー」できます。各数値はその剰余クラスのモジュロの 1 つのスロットに寄与します。$x$。 

制約は次のとおりです$4 \cdot 10^5$したがって、どの解も線形に近いか、$O(n \log n)$。 操作をシミュレートしようとしたり、要素ごとに到達可能な値の完全なセットを維持しようとしたりするものはすべて失敗します。そうしないと、各クエリが配列全体にわたる大規模な再計算をトリガーする可能性があるためです。 

多くの場合、解決策を壊す素朴な誤解は、各要素を独立して扱い、値を任意の非負の整数に自由に変換できると考えることです。 それは誤りです。モジュロによって制約されます。$x$。 たとえば、次の場合$x = 3$、1 のような値は次のようになります。$1, 4, 7, 10, \dots$、決して2や3ではありません。 

複数の要素が同じ剰余クラスをめぐって競合する場合、微妙な失敗のケースが発生します。 たとえば、多くの数値が 0 mod に一致する場合$x$、それらはすべて同じバケット内に「存在」しており、必要なすべての小さな整数に対して独立して使用することはできません。 

## アプローチ

 強引なアイデアは、各クエリの後に、すべての候補 MEX 値について完全な配列を維持することです。$m$、モジュロ制約の下で利用可能な要素を使用して形成できるかどうかを確認します。 これには、ターゲットへの番号の割り当てのシミュレーションが含まれます。$0, 1, 2, \dots$、クエリごとに実現可能性を繰り返し確認します。 最悪の場合こうなります$O(n^2)$さらに悪いことに、クエリごとに多くの値をスキャンし、多くの要素を調整する必要がある可能性があるためです。 

重要な構造的洞察は、各数値がその剰余モジュロを通じてのみ重要であるということです。$x$許可された操作ではその残差クラスが保持されるためです。 したがって、すべての要素は次のいずれかに正確に属します。$x$独立したバケット。 

ここで、MEX を構築することを検討してください。$0$上向きに。 数字を形成するには$m$、バケット内に少なくとも 1 つの未使用の要素が必要です$m \bmod x$。 各要素は 1 回しか使用できないため、各バケットは、残りの番号を格納する利用可能な「スロット」のキューのように動作します。 番号を割り当てると、$0, 1, 2, \dots$、対応する各残余バケットから 1 つの要素を消費します。 

したがって、問題は、各剰余クラスが何回出現したかのカウントを維持することと、欠落している最小の MEX を貪欲にチェックすることに帰着します。 

課題は、クエリが到着したときにこれを動的に維持することです。 以前の MEX 値を形成する際に、そのクラス内の要素の数がすでに使用されているかを示す各残差クラスのポインターを維持します。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの主要な構造を維持します: 各剰余クラスのモジュロの周波数カウンター$x$、および最小の MEX 候補を追跡するグローバル ポインター。 

各残基クラス$r$要素の数を保存します$y \equiv r \pmod{x}$が挿入されています。 

1. 受信値ごとに$y$、計算する$r = y \bmod x$、バケットの数をインクリメントします$r$。 これは、その残余クラスに使用可能な要素を 1 つ追加することを反映しています。 
2. 現在の MEX ポインタを維持する$mex$これは、構築可能であることがまだ確認されていない最小値を表します。 
3. 挿入するたびに、電流が流れているかどうかを繰り返し確認します。$mex$形成できます:

 これにはそのバケットが必要です$mex \bmod x$には、以前の MEX 値でその残差クラスを既に使用した回数よりも厳密に多くの要素が含まれています。 
4. 可能であれば、その残差クラスから 1 つの要素を「消費」し、インクリメントします。$mex$。 これは、この MEX 値を表すために以前に使用されていなかった要素を割り当てるモデルを示します。 
5. 次のタイミングで停止します。$mex$残余バケット内の要素が不十分なため、形成できません。 電流を出力する$mex$。 

私たちが移動するだけの理由$mex$前方へ進むと、ある時点で数値が不可能であることが確認されると、後でさらに多くの要素が到着したときに可能になる可能性がありますが、以前の値が再検討されることはありません。 

### なぜ効果があるのか

 不変条件は、いつでも、あらゆる値に対して$v < mex$、すでにそれを、残差クラスがそれを許可する別個の要素と一致させています。 そういったものごとに$v$、バケットから 1 つの要素だけを使用しました$v \bmod x$。 

まで拡張しようとすると、$mex$、必要な残余クラスに未使用の要素が存在するかどうかを確認しています。 「はい」の場合、それを永久に割り当てます$mex$。 そうでない場合、以前の要素はすでにコミットされているため、以前の要素を今後再割り当てしても、以前の割り当てを破ることなく役に立ちません。 これにより、貪欲な割り当てが最適化され、次のことが保証されます。$mex$常に最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q, x = map(int, input().split())
    cnt = [0] * x
    
    mex = 0
    
    for _ in range(q):
        y = int(input())
        r = y % x
        cnt[r] += 1
        
        # try to extend mex greedily
        while cnt[mex % x] > mex // x:
            mex += 1
        
        print(mex)

if __name__ == "__main__":
    solve()
```このソリューションでは、剰余カウントと単一の増加ポインターのみが維持されます。 条件`cnt[mex % x] > mex // x`現在の MEX 位置に割り当てるのに十分な要素がその残余クラスにあるかどうかを正確に取得します。 

部門`mex // x`MEX シーケンスの初期部分を構築する際に、この剰余クラス内の以前の数値が何個すでに消費されているかを表します。 

ループは前方にのみ進むため、全体の動きは`mex`すべてのクエリにわたって線形です。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのクエリに残基クラスが 1 つだけ現れる場合です。 その状況では、そのクラスを法として一致する数値のみが得られます。$x$が形成される可能性があるため、MEX はすぐに 0 で停止します。 アルゴリズムはこれを処理します。`cnt[mex % x]`ゼロを超えることはありません`mex % x`欠落しているクラスです。 

もう一つのケースは次のような場合です。$x = 1$。 この場合、すべての数値は同じ残基クラスに属し、挿入ごとに利用可能なプールが直接増加します。 条件は純粋なカウント比較に単純化され、MEX は処理された要素の数と等しくなります。これはアルゴリズムによって自然に生成されます。`cnt[0]`常に成長し、`mex`一歩一歩前進します。
