 ## 解決策

 ## 問題の理解

 ロボットはグリッドの原点から開始し、右または上の 2 方向にのみ移動できます。 各パッケージは、負でない整数値を持つ個別のグリッド座標に配置されます。 ロボットは出発地から始めてすべての荷物の場所を訪問する必要があり、訪問順序は自由に選択できます。 移動するたびに、x 座標または y 座標が 1 ずつ増加します。 

このタスクは、ロボットが左や下に移動する必要がなく、その順序ですべての荷物に到達できるように、すべてのポイントを訪問する順序が存在するかどうかを判断することです。 このような順序が存在する場合は、有効な移動の最短パス文字列を構築する必要があります。 すべての有効な最短パスの中で、辞書編集的に最小のものを出力する必要があります。ここで、「R」は「U」より小さいと見なされます。 

この制約により、ソリューションは線形または線形に近い並べ替えロジックに非常に厳密に束縛されます。 すべてのテスト ケースにわたる合計ポイント数は最大 1000 であるため、O(n log n) の並べ替え戦略で十分です。 すべての順序の順列またはバックトラックを伴うものはすべて、組み合わせ論的に爆発するため、非常に小さい n を超えると直ちに実行不可能になります。 

単調なトラバースに関してポイントが「互換性がない」場合、微妙な問題が発生します。 たとえば、点 (1, 2) と (2, 1) がある場合、単調性を損なうことなく x と y の移動の単一の増加シーケンスの両方を訪れる単調パスはありません。 命令を強制しようとすると、最終的には下方向または左方向への移動が必要になりますが、これは禁止されています。 

単純な間違いは、点を x だけまたは y だけで並べ替えようとすることです。 たとえば、x だけでソートすると、連続する点の間で y が減少するシーケンスが生成され、直接の単調な走査が不可能になる可能性があります。 同様に、点を任意に順序付けすると、ロボットが「戻る」必要がある無効な中間状態が発生します。 

## アプローチ

 強引なアイデアは、点のすべての順列を試し、右と上の移動のみを使用して各順序を通過できるかどうかを確認し、有効なパスの中から辞書編集上最適な最小パスを追跡することです。 各順列について、(0,0) から最初の点への移動をシミュレートし、次に連続する点間の移動をシミュレートし、両方の座標が決して減少しないことを確認します。 これは実現可能性を明示的に強制するため機能しますが、n! をチェックする必要があります。 n = 10 の場合でも、これはすでに計算上実行不可能になります。 

重要な構造上の観察は、有効なパスはいずれも x と y が減少しない方法で移動する必要があるということです。 これは、一度大きな x を持つ点を訪問すると約束すると、その後、より小さな x を持つ点を訪問することはできないことを意味します。 連続する点間の相対順序制約の y にも同じことが当てはまります。 

これは、点を x 座標で並べ替えて昇順に処理すると、左に移動する必要がないことが自動的に保証されることを示唆しています。 残る唯一の問題は、等しい x 値内で実現可能性を維持できるかどうかです。 辞書編集的に最小の出力の場合、できるだけ早く「R」を生成する動きを優先したいと考えます。これは、y 遷移の前に小さい x 遷移を優先することと一致します。 

ただし、重要な改良点は、実際にはポイント自体の間で厳密な順序付けを強制する必要がないことです。 代わりに、現在の位置から次のターゲットに移動するときに右と上にのみ移動できることだけを考慮します。つまり、両方の座標が選択されたシーケンスに沿って減少しない必要があります。 したがって、最適な戦略は、x の昇順でポイントを並べ替え、x が等しい場合は y の昇順で並べ替えることです。 これにより、両方の次元で単調増加チェーンが保証され、実現可能性が保証されます。

このチェーンが修正されると、パスの構築は簡単になります。現在の位置から、次の x に到達するまで右に移動し、次の y に到達するまで上に移動します。 x は減少せず、y も減少しないため、これは常に機能します。 

可能な場合には、各ステージで「U」が移動する前に、常に必要な「R」がすべて実行されるため、辞書編集上の最小要件は自然に満たされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 座標順に並べ替える | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソートされたポイントを通る単調な進行を強制することにより、有効なパスを構築します。

 1. テスト ケースのすべてのパッケージ座標を読み取ります。 これらは、ロボットが到達する必要があるターゲット セルを表します。 
2. x 座標を増やしてすべての点を並べ替え、x が等しい場合は y 座標を増やして並べ替えます。 これにより、リスト内を移動するときに両方の座標が減少することがなくなり、後方に移動する必要がなくなります。 
3. 現在位置を (0, 0) に初期化し、結果文字列を空にします。 
4. ソートされたポイントを繰り返し処理します。 各点 (x、y) について、「R」ステップを使用して現在の x から x に水平に移動し、次に「U」ステップを使用して現在の y から y に垂直に移動します。 これらの動きを応答文字列に追加します。 最初に右に移動すると辞書編集上の最小性が維持されるため、この順序は強制されます。 
5. すべての点を処理した後、構築されたパスを出力します。 

なぜ効果があるのか

 ソートされた順序により、訪問ポイントのシーケンスに沿って x と y の両方が減少しないことが保証されます。 これにより、連続するポイント間のすべての移行が右と上の移動のみを使用して達成可能になります。 常に垂直方向の移動の前にすべての水平方向の移動が完了するため、すべての有効な単調パスの中で辞書順に可能な限り最小の文字列が生成されます。これは、「U」を先に挿入しようとすると必要な「R」が遅れ、辞書順に大きな接頭辞が生成されるためです。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    pts.sort()
    
    x, y = 0, 0
    res = []
    ok = True
    
    for nx, ny in pts:
        if nx < x or ny < y:
            ok = False
            break
        
        res.append('R' * (nx - x))
        res.append('U' * (ny - y))
        x, y = nx, ny
    
    if not ok:
        print("NO")
    else:
        print("YES")
        print(''.join(res))
```コードは、ポイントを辞書順に並べ替えることから始まります。これは、x、次に y による並べ替えに相当します。 これにより、実現可能性チェックに必要な単調特性が保証されます。 ロボットの現在位置のポインターを維持し、連続する各ポイントに到達するために必要な右および上への移動の回数を正確に追加することで、パスを段階的に構築します。 

有効性チェックにより、決して後戻りしようとしないことが保証されます。 いずれかの点が前の点と比較して単調性に違反すると、構築は失敗します。 

構築順序は重要です。常に、必要なすべての「R」移動を「U」移動の前に追加します。これにより、有効な単調パス間で辞書編集上の最小性が保証されます。 

## 実用的な例

 ### 例 1

 入力点: (1,3)、(1,2)、(3,3)

 並べ替えると、(1,2)、(1,3)、(3,3) が得られます。 

| ステップ | 現在の (x,y) | ターゲット (x,y) | R が動きます | U が移動します | パス |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (0,0) | (1,2) | R | うう | るう |
 | 2 | (1,2) | (1,3) | | う | るうう |
 | 3 | (1,3) | (3,3) | RR | | ルール |

 このトレースは、ソートによって、一見「ソートされていない」入力が単調なチェーンに解決されることを示しています。 ロボットは座標を減らす必要がなく、実現可能性が確認されています。 

### 例 2

 入力点: (1,0)、(0,1)

 ソート後: (0,1)、(1,0)

 | ステップ | 現在 | ターゲット | 有効な遷移 |
 | --- | --- | --- | --- |
 | 1 | (0,0) | (0,1) | う |
 | 2 | (0,1) | (1,0) | 無効 (y が減少) |

 y を 1 から 0 に減らす必要があるため、これはすぐに失敗します。アルゴリズムは正しく NO を出力します。 

これは、チェックによって強制される単調な実現可能性が成立しない限り、並べ替えだけでは十分ではないことを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        pts = [tuple(map(int, input().split())) for _ in range(n)]
        pts.sort()

        x, y = 0, 0
        res = []
        ok = True

        for nx, ny in pts:
            if nx < x or ny < y:
                ok = False
                break
            res.append('R' * (nx - x))
            res.append('U' * (ny - y))
            x, y = nx, ny

        out.append("NO" if not ok else "YES\n" + ''.join(res))

    return "\n".join(out)

 ## 特殊なケース

 (0,0) にある単一のパッケージは、移動する必要がなく、ソートされたシーケンスが有効なままであるため、きれいに処理されます。 出力は単純に YES で空のパスがあり、ロボットがすでにその場所に存在するという要件と一致します。 

(1,0) や (0,1) など、反対の対角方向に交差する必要がある 2 つの点は、ソートによって座標の減少が必要なステップが生成されるため、すぐに失敗します。 チェックはパスを構築する前にこれを検出し、正確さを保証します。 

(0,0)、(1,0)、(2,0) など、すべての点が単一の増加直線上にある場合は、アルゴリズムが不必要な複雑さなしに純粋な「R」移動のシーケンスに縮退することを示し、構築の最適性が確認されます。
