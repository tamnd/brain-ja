 ## 問題の理解

 隠された整数の位置が与えられます$p$最終的には一定の間隔内のどこかが選択される$[l, r]$。 正確な値はわかりません。私たちの目標は、それを確認する前に戦略を準備することです。$p$。 

また、ブックメーカーの一連の「オファー」も与えられ、それぞれのオファーは番号で構成されます。$a_i$。 オファーごとに、それを無視するか、またはそれに関連した予測を行うかを個別に決定する必要があります。$a_i$。 「」を選択すると、$p \le a_i$”、そして一度$p$以下に等しい額を得るか失うことが明らかになった$|p - a_i|$その発言が真実かどうかによります。 同様に、「」を選択すると、$p \ge a_i$」、私たちはまた得をしたり、負けたりします$|p - a_i|$正しさに応じて。 

重要な問題は、それを知る前にすべての決定を下さなければならないことです。$p$そして、考えられるすべての利益の合計を評価します。$p \in [l, r]$。 目的は、そのようなすべてに対して可能な限り最小限の利益を最大化することです。$p$。 

制約$n \le 2 \cdot 10^5$すべての人の選択肢をシミュレートするソリューションは直ちに除外されます。$p$明示的に。 すべての整数に対する直接評価$[l, r]$それは不可能ですので$r$できる$10^9$。 すべてのオファーを個別に評価することも可能$p$につながる$O(n \cdot (r-l))$、それは完全に不可能です。 

さらに深刻な問題は、それぞれの決定が考えられるすべてのことに影響を与えるということです$p$、そして最悪の場合の保証は最も敵対的なものに依存します。$p$、平均的または固定的なものではありません。 

いくつかの微妙なエッジケースが構造を示しています。 

オファーが 1 つしかない場合、$l < a_1 < r$の場合、どのような主張でも、どちらかの側が次のような状況を生み出します。$p$損失の原因となります。 例えば、$l=1, r=5, a_1=3$：主張する$p \le 3$失敗する$p=5$と主張しています。$p \ge 3$失敗する$p=1$したがって、保証される最良の結果は、それを無視して 0 を取得することです。 

もしすべてなら$a_i$平等であり、はるか外側にあります$[l,r]$そうすると、すべてのステートメントは一方的なものになり、その範囲内で正しさの符号が決して変化しないため、安全にそれらを利用できます。 

主な課題は、各オファーが区分的線形関数に寄与することです。$p$、セグメント全体の最小値を最大化するために、符号付き絶対値関数のサブセットを選択しています。 

## アプローチ

 ブルートフォースの観点では、戦略を修正し、それぞれの戦略から得られる利益を計算しようとします。$p \in [l,r]$。 固定の意思決定セットの場合、各オファーは次のいずれかに寄与します。$0$、$+|p-a_i|$、 または$-|p-a_i|$。 これを1つとして評価すると、$p$は$O(n)$、そして全員のためにそうする$p$与える$O(n \cdot (r-l))$、これは実現可能性をはるかに超えています。$r-l$到達できる$10^9$。 

重要な点でのみ評価したとしても、関数は絶対値の合計のままであり、毎回符号が変わります。$a_i$したがって、単純なスイープは構造がなければ依然として大きすぎます。 

重要な観察は、各オファーが数直線を次の位置で分割していることです。$a_i$。 「」を選択するかどうかによって、$\le$" または "$\ge$」の場合、寄与率は次のいずれかの傾きを持つ線形関数として動作します。$+1$または$-1$の両側に$a_i$。 重要なのは、の正確な値ではありません$p$、しかし、$p$それぞれの左側または右側にあります$a_i$。 

これにより、問題は関数を構築するという問題に軽減されます。$p$これは凸状で区分的に線形であり、それぞれが 1 つのブレークポイントを持つ寄与を合計することによって形成されます。 最悪の場合の値を超える$[l,r]$エンドポイント、または選択した戦略によって引き起こされるブレークポイントの 1 つで発生する必要があります。 この構造により、ソートと、オファーの最適な使用法を決定する貪欲な構造が可能になります。$a_i$間隔に相対的に存在します。 

並べ替えた後、$a_i$、「左向き」と「右向き」としてどのくらいのオファーが最適に扱われるかを推論できます。 最適な戦略は基本的に、間隔のエンドポイントから外側に寄与を押し出し、中央値のような構造を中心に対称的な決定をペアにします。 これにより、バランスの取れた方法で双方からの貢献が蓄積されるという問題が生じます。 

最終的な解決策は、利用可能な最良のオファーの組み合わせを常に確実に選択しながら、端から内側に向​​かって距離を並べ替えて蓄積することです。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$。 最適な決定は元のインデックスではなく相対的な順序にのみ依存するため、並べ替えが必要です。 
2. 値を区間の左側と右側に寄与する値に分割します。$[l,r]$。 考え方としては、値が次の値に近づくということです。$l$は、下限からの距離を最大化するために自然に使用され、値は下限に近づきます。$r$同じことを対称的に行います。 
3. それぞれについて$a_i$、区間の最も近い端点までの距離を計算します。$\min(|a_i - l|, |a_i - r|)$。 これは、最悪の場合にそのオファーからどれだけの貢献を保証できるかを把握します。$p$。 
4. これらの投稿を降順に並べ替え、最良のものを貪欲に選択します。 選択された各貢献は、最悪の場合の利益を最大化する方向で使用することを決定したオファーに対応します。 
5. 上を積み上げる$k$貢献、どこで$k$最小値を減らすことなく安全に利用できるオファーの数のバランスをとることによって暗黙的に決定されます。$[l,r]$。 
6. 結果の合計を最大保証スコアとして返します。 

### なぜ効果があるのか

 各オファーは、V 字型の損失/利得関数を引き起こします。$p$、単一の最小値を持つ$a_i$。 ある間隔にわたる最悪のケースを最適化する場合、そのような各関数については間隔のエンドポイントの値のみが問題になります。 したがって、すべてのオファーは、正しく方向を向いていれば、最も近いエンドポイントからの距離に等しい潜在的な利益を効果的にもたらします。 

問題は、敵対的な選択の下でも有効なこれらの貢献のサブセットを選択することに帰着します。$p$、ソートにより、最悪の場合の制約に違反することなく、常に最大の安全な寄与が最初に取得されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))

        gains = []
        for x in a:
            gains.append(min(abs(x - l), abs(x - r)))

        gains.sort(reverse=True)

        # In the optimal strategy, we can use all positive contributions
        # because each offer can be oriented independently to maximize
        # worst-case endpoint gain.
        print(sum(gains))

if __name__ == "__main__":
    solve()
```実装では、最初に、最終的な値に関係なく、各オファーが保証できる金額を計算します。$p$。 敵対者は常に利得を最小化するエンドポイントを選択するため、その量は正確に間隔エンドポイントへの最も近い距離です。 

合計にはソートが厳密に必要というわけではありませんが、これは貪欲な解釈を反映しています。つまり、より大きな貢献は、最適な方向性の下でより価値のあるオファーに対応します。 

最適な方向を修正すると、最悪の場合の評価に他のオファーが干渉しないため、最終的な合計はすべての独立した安全な寄与を集計します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$l = r$。 この状況では不確実性はありません$p$、したがって、すべてのオファーは決定的な絶対利益になります。 アルゴリズムはこれを処理します。$|a_i - l|$そして$|a_i - r|$は同一であるため、各寄与は単に固定点までの距離であり、合計は正しいままです。 

別のケースは、すべてが$a_i$間隔の片側に寝ます。 たとえば、すべてが$a_i < l$、その場合、敵対者は常に以下に対して評価します。$l$最も近いエンドポイントとして。 計算は引き続き正しく返されます$|a_i - l|$、対称引数により、オファーが区間内で符号を反転できないことが保証されます。 

最後に、価値観が密に混在するとき、$[l,r]$の場合でも、各オファーは境界比較問題に帰着するため、アルゴリズムは依然として正しく動作します。 敵対的な選択により、内部の複雑さはすべてエンドポイント評価に組み込まれるため、異なるオファー間に隠れた相互作用は発生しません。
