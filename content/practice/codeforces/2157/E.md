 ## 解決策
 ## 問題の理解

 私たちは、それぞれ初期エネルギーレベルを持つドローンのフリートを管理しています。 ルールは、エネルギーレベルが次の値を超えてはいけないということです。`k`回。 いずれかのエネルギー レベルがこの制限を超えると、ドローンは一連のバランス操作を実行します。アレイ内で以前に発生したものの複製である各ドローンは、そのエネルギーを 1 つずつ増加させます。 この操作は、すべてのエネルギーレベルが最大で現れるまで続けられます。`k`回。 テスト ケースごとにこれらの操作の合計数を計算する必要があります。 

入力により複数のテスト ケースが提供され、それぞれにドローンの数が含まれます。`n`、許可される最大数`k`、および初期エネルギーの配列。 出力は、実行された操作の数を表すテスト ケースごとに 1 つの整数です。 

制約は重要です。`n`まで可能です`2·10^5`、との合計`n`テストケース全体の限界も次のとおりです`2·10^5`。 これにより、あらゆる操作の単純なシミュレーションが除外されます。`O(n^2)`最悪の場合、重複を繰り返し処理した場合に発生します。 エネルギーレベル自体は最大でも`2n`したがって、周波数配列またはマップを使用することが可能です。 

すべてのエネルギーレベルが等しい場合、微妙なエッジケースが発生します。 たとえば、次の場合`n = 6`そして`k = 3`と`a = [1,1,1,1,1,1]`、操作により配列が徐々に進化し、重複が 1 つずつ増加します。 最後の重複のみをインクリメントしたり、即時のオーバーフローのみをカウントしたりする不用意な貪欲なアプローチは、操作の合計数を誤って計算する可能性があります。 

もう 1 つのエッジケースは次のような場合です`k >= n`。 その後、周波数制限を超えることはないため、操作は必要ありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。配列を反復処理し、以前の要素と重複しているすべての要素にマークを付け、それらをインクリメントし、それ以上の要素が表示されなくなるまで繰り返します。`k`回。 これは正しく機能しますが、最悪の場合、すべてのドローンで何度もインクリメントする必要がある可能性があります。 最大の数が 1 の場合、`k = 1`、操作は大まかに繰り返すことができます`n`ドローン 1 台につき`O(n^2)`が鈍くなるにもほどがあります。`n = 2·10^5`。 

重要な洞察は、ドローンの正確な最終位置は重要ではなく、各エネルギー レベルのカウントのみが重要であるということです。 エネルギーレベルを分類し、圧縮された周波数空間での増分をシミュレートできます。 それを超えるエネルギーレベルごとの重複の数を数えると、`k`、これらの余剰ドローンをワンステップで次のより高いエネルギーレベルに「運ぶ」ことができます。 これにより、プロセスがソートされた固有のエネルギーにわたる線形スイープに短縮され、保留中のドローンのカウンターが増加し、ワンステップで次のレベルに追加できます。 各増分は、元のプロセスの操作に正確に対応します。 これにより、合計の操作を計算できるようになります。`O(n log n)`ソートステップによる時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (周波数 + キャリー) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`そしてエネルギーアレイ`a`。 
2. マップまたは配列を使用して、各エネルギー レベルの頻度を数えます。 これにより、現在各エネルギーにあるドローンの数がわかります。 
3. 変数を初期化する`carry`これにより、各ステップで増加する必要があるドローンの数が保存されます。 
4. エネルギー レベルを昇順に繰り返します。 レベルごとに`x`:

 1. 現在の値を追加します`carry`の周波数に`x`。 これは、前のレベルから増加したすべてのドローンを表します。 
2. の頻度の場合、`x`を超える`k`、計算する`excess = freq[x] - k`。 インクリメント`carry`これによって`excess`。 過剰な各単位は、最終的にはバランス操作になります。 
3. 合計操作カウンタを次のようにインクリメントします。`excess`。 
5. すべてのエネルギー レベルを処理した後、合計操作カウンターにはテスト ケースの答えが含まれます。 

なぜ機能するのか: アルゴリズムは、エネルギーレベルを処理した後、不変条件を維持します。`x`、以下はドローン禁止`x`彼らのことは終わった`k`限界。 過剰分は次のように伝播されます。`carry`元のバランシング操作を模倣して、次のレベルに進みます。 並べ替えにより、増分は常に前に進むことが保証されるため、操作の順序は説明したプロセスと一致します。 

## Python ソリューション```python
import sys
from collections import Counter
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        freq = Counter(a)
        ops = 0
        carry = 0
        
        for x in sorted(freq.keys()):
            freq[x] += carry
            if freq[x] > k:
                excess = freq[x] - k
                carry = excess
                ops += excess
            else:
                carry = 0
        
        print(ops)

solve()
```コードは最初に周波数をカウントし、次にソートされたキーをスイープします。`carry`は余分な重複を前方に伝播し、キャリーの各単位は元の反復プロセスで実行された 1 つの操作を正確に表します。 ドローンが常に正しい順序で次のより高いエネルギー レベルに増加するようにするには、並べ替えが必要です。

 ## 特殊なケース

 いつ`n = k`、ドローンのエネルギーに関係なく操作は行われません。 例えば、`n = 2, k = 2, a = [5,5]`。 5 の頻度は 2 であり、次と同じです。`k`、 それで`carry`ゼロのままで、出力は`0`。 

すべてのエネルギーが同じであるとき、`k = 1`、 のような`n = 6, k = 1, a = [1,1,1,1,1,1]`、各パスは重複を増分し、エネルギーが超過しなくなるまでキャリーを生成します。`k`。 私たちのアルゴリズムはキャリーを使用して超過分を正しく伝播します
