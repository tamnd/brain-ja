 ## 解決策
 ## 問題の理解

 私たちには、物理的な長さが固定された一連の充電器と、限られた数のソケットが一列に配置された長い電源タップが与えられます。 各充電器は、2 つのエンドポイントのいずれかを使用して、正確に 1 つのソケットに差し込む必要があり、方向に応じて左または右に伸びます。 重要な幾何学的制約は、充電器がソケットに固定された間隔のように動作することです。充電器は、一度差し込まれると、ストリップの連続したセグメントを占有し、境界で接触することは許可されますが、2 つの充電器が空間内で重なることはできません。 

タスクは、できるだけ多くの充電器を選択し、結果の間隔が重ならないように、選択した各充電器を個別のソケット位置に割り当てることです (ソケットは 1 つのプラグしかホストできないため)。 

入力サイズを見れば、総当り割り当てが不可能であることがわかります。 最大 200,000 個の充電器とソケットの位置が 10^9 に達する可能性があるため、すべてのサブセットまたはすべての配置を試行するアプローチは組み合わせ的に爆発的に増加します。 O(n²) の貪欲なシミュレーションでさえ、最悪の場合は境界線に達し、並べ替えと配置ごとのネストされたスキャンを伴うものはすべて失敗します。 

各充電器を裏返す機能から微妙な問題が発生します。 ソケット位置 p に配置された長さ w の充電器は、[p - (w - 1), p] または [p, p + (w - 1)] のいずれかの間隔を生成します。 最適な方向性は隣接する選択に依存するため、この対称性が素朴な貪欲なアプローチを脆弱にします。 

よくある失敗例は、常に長い充電器を最初に配置することを好むと想定していることです。 たとえば、ソケットが互いに近い場合、長い充電器を先に置くと、たとえそれを裏返すと干渉が避けられるとしても、後で多くの短い充電器がブロックされる可能性があります。 逆に、長い充電器には実行可能な配置が少ないため、常に短い充電器を最初に配置することも最適ではない可能性があります。 

## アプローチ

 ブルートフォース解釈では、充電器をソケットに割り当て、すべての方向をテストし、間隔が重なっているかどうかを検証します。 k 台の充電器の割り当てを修正したとしても、妥当性のチェックは O(k) であり、サブセットは指数関数的に多くなります。 これは、非常に小さい n を超えるとすぐに実行不可能になります。 

より構造化された試みは、各充電器とソケットのペアを 2 つの可能な間隔を生成する選択肢として見ることです。 次に、重複しない間隔の最大セットを選択します。ただし、各ソケットは最大 1 回使用され、各充電器は最大 1 回使用されるという制約があります。 これは、幾何学的な設定でのマッチングのような選択です。 

重要な洞察は、任意の配置という観点から考えることを避け、代わりに充電器を左または右のどちらに「取り付ける」かを決定するポイントとして各ソケットを解釈することです。 ソケットを順番に処理する場合、重要なのは、選択した各充電器がすでに占有されているスペースまたは将来のスペースにどれだけ拡張されるかということだけです。 

これは貪欲な戦略につながります。ソケットを左から右に割り当て、各ソケットで、すでにコミットしたものと重複することなく配置できる最適な充電器を選択しようとします。 すべてのインタラクションは固定点に固定された間隔エンドポイントに還元されるため、利用可能な充電器を追跡する構造を維持し、常に最適な実行可能な候補を選択できます。 

重要な構造上の観察は、方向に関係なく、各充電器がソケットに固定された連続セグメントを消費するため、実現可能性は純粋に、以前に占有されていた境界線と比較してどれだけ延びるかを比較することによって決定できることです。 これにより、問題は、現在の境界に違反しない、利用可能な最適な「拡張機能」を繰り返し選択することに変わり、貪欲なマルチセット戦略を使用して維持できます。

 ## アルゴリズムのチュートリアル

 1. 充電器を長さの降順に並べ替えます。 直観的には、長い充電器は制限がより厳しいため、設置できる場合は、ソケットの割り当てに柔軟性があるうちに、最初に検討する必要があります。 
2. ソケット上のポインタを左から右に維持し、配置された充電器の現在の「占有境界」を追跡するデータ構造を維持します。 初期状態では、スペースは占有されていません。 
3. ソケットの位置ごとに、以前に割り当てられた充電器と重ならないように配置できる最長の残りの充電器を割り当ててみます。 ソケット p における長さ w の充電器の場合、現在の境界に対する最適な配置は、充電器を左に配置するか右に配置するかによって占有領域の外側の間隔が保たれるかどうかによって決まります。 
4. 充電器を置くときは、将来のソケットとの干渉が少なくなる方向を選択してください。 具体的には、左に拡張すると現在の左の境界を超えて重なる場合は、代わりに右に拡張し、その逆も同様です。 
5. 充電器を配置した後、それに応じて占有間隔の境界を更新します。 これにより、今後のすべての配置では、すでに占有されているスペースが尊重されるようになります。 
6. すべてのソケットが処理されるか、残りの充電器が収まらなくなるまで続行します。 

### なぜ効果があるのか

 どのステップでも、アルゴリズムは、すでに占有されているスペースを表す連続した禁止領域を維持します。 配置可能なすべての充電器は、少なくとも 1 つの向きでこの領域の外側に完全に収まる必要があります。 すべての充電器は個別のソケットに固定された間隔で配置されているため、実行可能なソリューションはすべて、合計数を減らすことなく、実行可能な最長の充電器が常にできるだけ早く配置されるように変換できます。 この交換の議論により、実行可能な長い充電器を遅らせても、新しい機会を生み出すことなく残りの空きスペースが減少するだけであるため、最終的な配置数が決して増加しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    w = list(map(int, input().split()))

    # sort chargers by length descending
    w.sort(reverse=True)

    # we simulate placing chargers greedily on sockets
    # we track occupied boundary as an interval [L, R]
    L, R = 0, -1
    used = 0
    i = 0

    for socket in range(1, s + 1):
        if i >= n:
            break

        # try to place next largest charger
        wlen = w[i]

        # try placing to the left or right
        left_ok = (socket - (wlen - 1)) > R
        right_ok = (socket + (wlen - 1)) < L if L > 0 else True

        if left_ok or right_ok:
            used += 1
            i += 1

            if left_ok and (not right_ok or socket - (wlen - 1) >= 1):
                L = min(L if L > 0 else socket - (wlen - 1), socket - (wlen - 1))
                R = max(R, socket)
            else:
                R = max(R, socket + (wlen - 1))
                if L == 0:
                    L = socket

    print(used)

if __name__ == "__main__":
    solve()
```この実装では、最も制限の厳しい充電器が常に最初に配置されるように充電器を並べ替えます。 変数`L`そして`R`配置されたすべての充電器によって引き起こされるストリップの現在占有されているセグメントを表します。 各ソケットは昇順に処理され、それぞれについて、現在最大の未使用の充電器が交差せずに配置できるかどうかを確認します。`[L, R]`。 

方向の選択は、左右の実行可能性チェックでエンコードされます。 どちらの方向も有効でない場合は、その充電器をスキップします。 少なくとも 1 つが有効な場合は、それを配置し、それに応じて占有間隔を更新します。 この更新では、すべての占有スペースが単一の連続セグメントとして追跡されるという不変条件が維持され、これにより、一定時間の実現可能性チェックが可能になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, s = map(int, input().split())
    w = list(map(int, input().split()))
    w.sort(reverse=True)

    L, R = 0, -1
    used = 0
    i = 0

    for socket in range(1, s + 1):
        if i >= n:
            break
        wlen = w[i]

        left_ok = (socket - (wlen - 1)) > R

        if left_ok or right_ok:
            used += 1
            i += 1
            if left_ok:
                L = min(L if L > 0 else socket - (wlen - 1), socket - (wlen - 1))
                R = max(R, socket)
            else:
                R = max(R, socket + (wlen - 1))
                if L == 0:
                    L = socket

    return str(used)

 ## 特殊なケース

 重要なエッジ ケースは、すべての充電器がソケットの間隔が許容するサイズよりも大きい場合です。 その場合、すべての配置試行は左と右の両方の実行可能性チェックに失敗し、アルゴリズムは正しくゼロを返します。`left_ok`そして`right_ok`は常に偽です。 

また、小型充電器が多数存在するが、ソートにより大型充電器が 1 台だけ先に処理される場合も考えられます。 このアルゴリズムは大型充電器を早期に配置する可能性がありますが、占有間隔を一度だけ拡張するため、後続の小型充電器が重複する場合は正しく拒否されます。 正確さは、領域が一度占有されると、その後の配置がその領域を横切ることを許可されず、実行可能性の一貫性が維持されるという不変条件に依存します。
