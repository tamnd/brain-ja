 ## 解決策
 ## 問題の理解

 複数の整数セットが与えられ、各整数を 1 回だけ使用する単一の算術式を構築できます。 使用できる演算は加算と乗算のみであり、括弧を自由に挿入して評価順序を制御できます。 目標は、有効な式を作成することだけではなく、その数値を最大化することです。 

主な問題は、グループ化の下では乗算と加算が自明ではない方法で相互作用することです。 すべての数値は正であるため、乗算が加算よりも優先される傾向がありますが、加算は、係数を乗算する前に係数を膨らませるのに役立つ場合があります。 

制約は大きく、最大 100,000 個の数値 (それぞれのサイズは 1,000,000 個) です。 これにより、式ツリーやサブセットに対する動的プログラミングを探索しようとするアプローチは即座に排除されます。 平$O(n^2)$推理が遅すぎる。 解決策は効果的に線形または線形に近いものでなければなりません。$O(n \log n)$仕分けステップ。 

1 のような小さな数値が存在する場合、微妙なエッジケースが発生します。 1を掛けると何も起こりませんが、1を加えると掛ける前の値が増加するため、それらの配置が重要になります。 たとえば、入力の場合`1 1 1 1`、単純な貪欲な乗算では 1 が得られますが、それらを次のようにグループ化します。`(1+1)*(1+1)`4 が得られますが、これは厳密には優れています。 

もう 1 つの特殊なケースは、すべての数値が大きい場合です。 その場合、乗算はほとんどの場合有益ですが、それでもグループ化を決定する必要があります。 例えば、`13 37 1`乗算の前に 1 を 13 に加算すると最も効果的です。 

中心的な課題は、すべての可能性を総当たり的に実行することなく、括弧の最適な構造を決定することです。 

## アプローチ

 ブルートフォースソリューションでは、数値に対して可能なすべてのバイナリ式ツリーを試し、各内部ノードに加算または乗算のいずれかを割り当てます。 可換性を無視しても、木の形の数はカタルーニャ数です$C_{n-1}$、各内部ノードには 2 つの操作の選択肢があるため、合計の検索スペースは指数関数的に増加します。 これはすぐに実行不可能になります$n = 20$、ましてや$10^5$。 

重要な観察は、乗算は結合的であり、加算も結合的であるが、これらを混合すると、相互作用が 1 つだけ重要になる構造が作成されるということです。つまり、数値のグループを別の何かに乗算する前に加算を使用して「アップグレード」するかどうかです。 すべての数値が正であるため、係数を増やすと最終積が増加します。そのため、各項が何らかのサブセットの合計である、構築された項のセットの積を最大化したいと考えます。 

これにより、問題は数値をグループに分割し、各グループが合計されてから、すべてのグループの合計が乗算されるようになります。 残りの問題は、これらのグループを最適に形成する方法です。 

最適な戦略は、古典的な不等式スタイルの直観から生まれます。2 つの合計を乗算することは、すべてを 1 つの巨大な合計にマージするよりも有益です。これは、1 が大きな合計の中で無駄になるのではなく、他の数値を膨らませるために使用されることを注意深く確認した場合に限られます。 最良の構造は、1 より大きい数値を個別にグループ化し、乗算の前に 1 を使用してそれらのグループを増やす単一の乗算チェーンを形成することであることが判明しました。 これにより、正準構造が得られます。つまり、1 より大きいすべての数値を取得し、それらの「拡張合計」を乗算し、選択した 1 つの係数にそれらを加算することによって 1 を処理します。 

最大値を達成する式ツリーには常に「乗算バックボーン」があり、各ノードは基数またはいくつかの 1 を吸収する合計のいずれかになります。 この構築は、ソートと貪欲な 1 の付加に集約されます。

 ## アルゴリズムのチュートリアル

 1. 入力数値を 1 と 1 以外の 2 つのグループに分けます。 その理由は、1 は乗算と加算では異なる動作をするためです。これは、1 が乗算には中立ですが、合計をブーストするのに役立つためです。 
2. 1 より大きい数値がない場合は、括弧で囲まれたすべての数値の合計を返します。 この場合、乗算は役に立たず、最適な値は単にそれらの合計になります。 
3. 1 より大きい数値がある場合、それらのそれぞれを乗算構造の基本コンポーネントとして扱います。 
4. 最終的な乗算チェーンのアンカーとして、1 以外の数値の 1 つを選択します。 残りの 1 をすべて加算を使用してこのアンカーに接続します。 これにより、乗算構造を変更せずにこの係数の値が増加します。 
5. 残りの 1 以外の数値については、それぞれを乗算チェーン内の独立した因数として扱います。 
6. 乗算を使用してすべての因子を結合し、評価順序が意図したグループ化を強制するように括弧を挿入します。 
7. すべての 1 が加算グループ内で 1 回だけ使用されるようにし、やむを得ない場合を除き、単独の乗算因数として使用しないようにします。 

### なぜ効果があるのか

 この構築は、最終積のすべての因子が 1 より大きい単一の整数、またはその整数といくつかの 1 の合計のいずれかであるという不変条件に依存します。 乗算は正の整数に対して単調であるため、係数の値を増加させると、厳密には積の合計が増加します。 したがって、分割すると限界ゲインが減少するため、すべての 1 を複数の場所に分割するのではなく、正確に 1 つの係数に割り当てる必要があります。 これが修正されると、残りの構造は独立した最適化された因子に対して純粋に乗算されるため、全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ones = []
    others = []

    for x in a:
        if x == 1:
            ones.append(x)
        else:
            others.append(x)

    # case: all ones
    if not others:
        expr = "(" + "+".join("1" for _ in ones) + ")"
        print(expr)
        return

    # sort to have deterministic structure
    others.sort()

    # attach all ones to the first non-one number
    # build first factor
    first = str(others[0])
    if ones:
        first = "(" + first + "+" + "+".join("1" for _ in ones) + ")"

    # remaining factors
    factors = [first] + [str(x) for x in others[1:]]

    # multiply them all
    expr = factors[0]
    for f in factors[1:]:
        expr = "(" + expr + "*" + f + ")"

    print(expr)

if __name__ == "__main__":
    solve()
```コードは、入力を 1 と 1 以外に分割することから始まります。これは、入力が構築において根本的に異なる役割を果たすためです。 すべてが 1 の場合、唯一の意味のある演算は加算であるため、明示的にかっこを使用して単純に合計します。 

1 より大きい数値が少なくとも 1 つ存在する場合、正確さは順序に依存しませんが、1 以外の値を並べ替えて出力を決定します。 次に、すべての 1 を最初の要素に付加します。 これは、すべての加算的な「無料ブースト」を 1 か所に集中させ、乗算ゲインを最大化する必要があるという貪欲な決定を反映しています。 

最後に、乗算を使用してすべての要素を接続し、評価順序を強制し、演算子の優先順位の曖昧さを避けるために各ステップを注意深く括弧で囲みます。 

## 実用的な例

 ### 例 1

 入力:`1 2 3 4`値を 1 つ = [1]、その他の値 = [2、3、4] に分けます。 

| ステップ | 現在の構造 | アクション |
 | --- | --- | --- |
 | 1 | 2、3、4 | そうでないものを特定する |
 | 2 | 2、3、4 | 最初の要素に 1 を付ける |
 | 3 | (2+1)、3、4 | 最初の要素を構築する |
 | 4 | ((2+1)*3), 4 | 順番に乗算する |
 | 5 | (((2+1)*3)*4) | 最終的な式 |

 これにより、次と同等の式が生成されます。`3*((1+2)*4)`グループ分け後の値。 トレースは、すべての加算的な柔軟性が 1 つの乗法ブランチに集中していることを示しています。 

### 例 2

 入力:`13 37 1`あるもの = [1]、その他 = [13, 37] に分けます。 

| ステップ | 現在の構造 | アクション |
 | --- | --- | --- |
 | 1 | 13、37 | そうでないものを特定する |
 | 2 | (13+1)、37 | 最初に 1 を付けます |
 | 3 | ((13+1)*37) | 乗算する |

 これは、1 をスタンドアロンで使用するのではなく、単一の乗算係数を増加させる必要があるという最適なアイデアと一致します。 

トレースは、1 を他の場所に配布しても製品が改善されないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、すべての数値が 1 である場合です。乗算ではすべてが 1 になるため、アルゴリズムは合計式を生成することでこれを処理します。入力の場合`1 1 1`、建設利回り`(1+1+1)`、これが最適です。 

もう 1 つの特殊なケースは、次のような単一の大きな数値です。`1000000`。 どの操作もその値を改善できないため、アルゴリズムは直ちにその値を返します。 

のような混合ケース`1 1 100`なぜ集中力が重要なのかを示します。 アルゴリズムが生成するのは、`(100+1+1)`、利用可能な乗法成分が 1 つしかないため、複数の因子にわたる 1 の代替分布は積を改善できません。
