 ## 問題の理解

 それぞれ固定長のレンガ タイプのセットが与えられ、各タイプのレンガを無制限に使用できます。 目標は、一定の幅で無限に高い壁を構築することです`w`。 各行は、全長が正確に一致する一連のレンガです。`w`。 

列を無限に積み重ねたときに、連続する 2 つの列の間にレンガ間の垂直の亀裂が入らない場合、壁は安定していると見なされます。 言い換えれば、ある列のレンガの終了位置に注目すると、それらのカット位置は次の列のカット位置と決して一致してはなりません。 

重要な制約により、構築が大幅に簡素化されます。有効な無限の壁が存在する場合、永久に交互する 2 つの異なる行パターンのみを使用して常に構築できます。 したがって、無限に多くの行について推論する代わりに、2 つの行を見つけるだけで済みます。`A`そして`B`次のような:

 内部のカット位置`A`そして`B`重ならないようにしてください。 

入力により提供されるのは、`n`レンガの種類と幅`w`、レンガの長さのリストが続きます。 そのような行のペアが存在するかどうかを判断し、存在する場合は有効なペアを出力する必要があります。 

制約により、最大で次のことが許可されます。`3 · 10^5`価値観。 可能なすべての行パーティションを列挙したり、行の構築を組み合わせてシミュレートしようとするソリューションは、幅の可能なセグメンテーションの数が指数関数的に増加するため、非常に遅くなります。`w`。 これにより、ブルートフォースパーティション生成が即座に排除されます。 

貪欲な構築が最初に行を選択し、どの完了でも問題ないと仮定した場合、微妙な失敗例が発生します。 たとえば、レンガの数を最大化または最小化する行を選択すると、別の組み合わせが存在する場合でも、2 番目の行での位置合わせが避けられない可能性があります。 

本当の課題は、問題が 2 つのパーティションを構築することにあることを理解することです。`w`許可されたレンガ サイズを使用して、カット セットがばらばらになるようにします。 

## アプローチ

 ブルートフォースアプローチでは、幅をタイル化する可能なすべての方法を生成しようとします。`w`指定されたレンガの長さを使用します。 各タイリングは次の構成に対応します。`w`許可されたセットのパーツを使用します。 最悪の場合、サイズ 1 のブリックが存在する場合、可能な行数はフィボナッチのような増加のオーダーであり、ほぼ指数関数的に増加します。`w`。 のために`w = 3 · 10^5`、これはまったく不可能です。 

ただし、重要な構造上の観察は、多くの行は必要なく、2 行だけ必要であるということです。 これにより、問題は 2 つの異なる表現方法を見つけることに変わります。`w`許可された数値の合計として、プレフィックスの合計 (カット位置) が次の場合を除いて一致しないようにする`0`そして`w`。 

完全なパーティションという観点から考えるのではなく、視点を変えます。すべての行が一連のカット位置を誘導します。 内部がバラバラなこのようなセットが 2 つ必要です。 これは、1 つの行を選択した後、その内部境界位置をすべて回避しながら別の行を構築できることを保証するのと同じです。 

これは、貪欲 + 到達可能性の観点を示唆しています。まず、有効なタイリングを 1 つ構築します。`w`。 次に、カット位置を禁止点として扱い、位置に対する最短パスのような動的プログラミングを使用して 2 番目のタイリングを構築しようとします。`0..w`、禁止されたカットポイントに正確に到達するトランジションを禁止します。 

両方の構築が成功した場合、互換性のある行が 2 つあります。 どちらかが失敗した場合、有効なソリューションはそのようなパーティションのペアに対応する必要があり、構築スペースはプレフィックス合計に対する到達可能性によって完全にキャプチャされるため、安定した壁は存在しません。

 ## アルゴリズムのチュートリアル

 私たちはタスクを 2 つの建設的なフェーズに分割しました。 

### 1. 最初の行を作成します

 1. 幅の単純な到達可能なタイリングを計算します。`w`許可されているレンガを使用します。 

標準の DP を使用します。`dp[i]`位置に到達できれば true`i`から`0`。 

再建のために、私たちは最後に使用されたレンガを保管します。 
2. 1回`dp[w]`が true の場合、有効なレンガのシーケンスを 1 つ再構築します。 

再構築中に、すべてのカット位置、つまりレンガが終了するすべてのプレフィックスの合計を記録します。 

この時点で、有効な行が 1 つあります`A`。 

### 2. 位置合わせを避けて 2 行目を作成します

 1. 列の内部のカット位置をすべてマークします。`A`禁じられているように。 これらは厳密に次の間の位置です。`0`そして`w`。 
2. 2 番目の行を構築するために別の DP を実行します。`B`、再びから`0`に`w`ただし、今回はトランジションのみを許可します`i -> i + b`もし：

-`i + b <= w`- そして`i + b`禁止されたカット位置ではありません
 3. たどり着いたら`w`、行を再構築します`B`。 
4. いずれかの DP が失敗した場合、出力`impossible`。 

### この制限で十分な理由

 最初の行は、亀裂が存在するすべての位置を定義します。 有効な 2 行目では、これらの位置のいずれかにレンガの境界を配置しないようにする必要があります。そうしないと、無限の繰り返しにより亀裂が垂直に整列することになります。 すべての列はカット位置によって完全に決定されるため、内部のカット セットを切り離すことで、交互の列の安定性が保証されます。 

これにより、無限壁条件が DAG 上の位置上の 2 パス制約に軽減されます。ここで、ノードは位置であり、エッジはレンガの配置に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_row(w, bricks, forbidden=set()):
    dp = [False] * (w + 1)
    prev = [-1] * (w + 1)
    prev_brick = [-1] * (w + 1)

    dp[0] = True

    for i in range(w + 1):
        if not dp[i]:
            continue
        for b in bricks:
            j = i + b
            if j <= w and (j == w or j not in forbidden):
                if not dp[j]:
                    dp[j] = True
                    prev[j] = i
                    prev_brick[j] = b

    if not dp[w]:
        return None, None

    # reconstruct
    pos = w
    cuts = set()
    row = []

    while pos != 0:
        p = prev[pos]
        b = prev_brick[pos]
        row.append(b)
        if pos != w:
            cuts.add(pos)
        pos = p

    row.reverse()
    return row, cuts

def solve():
    n, w = map(int, input().split())
    bricks = list(map(int, input().split()))

    row1, cuts1 = build_row(w, bricks)
    if row1 is None:
        print("impossible")
        return

    row2, _ = build_row(w, bricks, cuts1)
    if row2 is None:
        print("impossible")
        return

    print("possible")
    print(len(row1), *row1)
    print(len(row2), *row2)

if __name__ == "__main__":
    solve()
```最初の DP は、実行可能な幅のタイリングを構築します。`w`そしてその内部のカット位置を記録します。 2 番目の DP は同じ到達可能性プロセスを繰り返しますが、それらのカット位置を禁止状態として扱います。 特別な条件`j == w`たとえ`w`上部の境界は壁の内側に垂直な亀裂を生じさせないため、禁止されています。 

再構築のステップは、`w`に`0`先行ポインターを使用して、ブリック選択のシーケンスを再構築します。

 ## 特殊なケース

 最初のエッジケースが現れるのは、`w`それ自体は直接レンガの長さになります。 最初の行 DP は 1 つのステップですぐに成功し、内部カットのない行が生成されます。 この場合、禁止されたセットは空であるため、2 番目の行の構築も同様に動作し、成功し、2 つの任意のタイリングが生成されます。 違反する内部制約がないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、すべての有効なタイリングが少なくとも 1 つの内部カット位置を共有する場合です。 このような場合でも、最初の DP は行を生成しますが、禁止されたセットにより 2 番目の DP の代替補完がすべてブロックされます。 2 番目の DP は失敗し、正しく不可能であることを示します。 

最後の微妙なケースは、複数の DP 再構成が可能な場合に発生します。 先行ストレージは最初に見つかった遷移を選択するため、正確な行は一意ではありません。 有効な最初の行は有効な禁止セットを定義し、成功した 2 行目は構造に関係なく十分であるため、これは正確さに影響しません。
