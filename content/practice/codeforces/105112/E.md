 ## 解決策
 ## 問題の理解

 すべて同じ基本値 2023 から始まる変数のコレクションを維持します。2 種類の操作がオンラインで適用されます。 1 つの演算で、1 つの変数を別の変数で累乗することにより置き換えます。 もう 1 つの操作では、2 つの変数を比較し、最初の変数が小さいか等しいか大きいかを報告するように求められます。 

主な問題点は、累乗が繰り返されると値が非常に速く増加することです。 小規模な更新チェーンであっても、組み込みの整数型や合理的な正確な算術表現をはるかに超える、天文学的に大きな数値が生成される可能性があります。 同時に、クエリでは近似ではなく、正確な順序比較が必要です。 

入力サイズは n と m の点で小さく、どちらも最大 1000 です。これにより、重いデータ構造や、演算ごとの線形または線形に近いを超える漸近的な最適化に関する懸念が排除されます。 ただし、真の課題はアルゴリズムのスケールではなく表現です。数値自体を明示的に保存することはできません。 

各更新後に実際に xi^xj を計算する単純なアプローチは、オーバーフローと時間の爆発によりすぐに失敗します。 指数タワーを直接構築したり比較したりすることはすぐに不可能になるため、大きな整数を使用するだけでは不十分です。 

微妙なエッジケースは、異なるべき乗シーケンスが極端に異なる増加率を生成するものの、その基数が同じ 2023 である場合に発生します。たとえば、数回の演算の後、2 つの変数が両方とも巨大である可能性がありますが、1 つは「タワーの高さ 3」、もう 1 つは「タワーの高さ 2」であるため、比較は大きさではなく構造に依存します。 

## アプローチ

 直接シミュレーションでは、各 xi を整数として保存し、べき乗によって更新します。 これは、非常に小さなケースでは概念的には正しいですが、すぐに壊れます。 Python の大きな整数でさえ、精度は任意ですが、数値のサイズが値だけでなくビット長でも指数関数的に増大するため、この種の累乗の繰り返しを処理できません。 

重要な点は、実際には数値が必要ないということです。 次の形式の式を比較するだけで済みます。 

2023^(2023^(...)),

 ここでの構造はべき乗の塔です。 

すべての変数は、同じベース 2023 のパワー タワーとして表すことができます。時間の経過とともに変化するのは、タワーの高さだけです。 

最初は、すべての xi が高さ 1 の塔に対応します。 

ここで、演算 xi = xi^xj を考えてみましょう。 xi が高さ a の塔で、xj が高さ b の塔である場合、べき乗により、指数自体が塔となる塔に変換されます。 これは、単純な算術的な方法ではなく、構造的に乗算的に高さを効果的に増加させます。 ただし、すべての基数が同一であり、すべての成長が同じ開始点から始まるため、実際に比較に重要な情報は指数タワーの高さだけです。 

より正確には、各変数を「タワーの高さ」としてモデル化できますが、それだけでは十分ではありません。 また、タワーが「純粋に 2023 年に対応している」のか、それともすでに反復指数構造を表しているのかを知る必要があります。 正しい抽象化は、各値がテトレーション表記の 2023 ↑↑ h に相当するということです。ここで、h は再帰的に定義された高さです。 重要なのは、このような式間の比較は、数値展開ではなく、その構造のみに依存することです。 

この操作は、各変数が最終的に他の変数に依存する、指数依存関係のフォレストを維持することに帰着します。 n と m が小さいため、有向構造を安全に維持し、メモ化を使用して指数ツリーを再帰的に比較することで比較を評価できます。 

ブルートフォースのアイデアは次のようになります。各変数をノードとして表します。ここで、xi = xi^xj により、i から j への有向依存関係が作成されます。 xi と xj を比較するために、それらの「有効指数高さ」を再帰的に評価し、依存関係を通じて比較を注意深く伝播します。

これは繰り返し再計算すると遅すぎますが、クエリごとまたは状態バージョンごとにメモ化することで実現可能になります。 

重要な洞察は、べき乗によって、指数構造に関して辞書編集的に比較できる単調な順序付けが引き起こされるということです。より高い指数塔がより低い指数塔を支配し、依存構造全体が一致する場合にのみ等価性が発生します。 

したがって、各変数が現在の「式ツリー」へのポインターを格納する表現を維持でき、比較はツリーの再帰的比較になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース数値累乗 | 不可能 (オーバーフロー + 爆発) | お(1) | 間違っています |
 | 式ツリー + 再帰的比較 | O(m · n) 償却 | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各変数を、その指数式を表す有向構造内のノードとしてモデル化します。 

1. 各変数 xi を基本値 2023 を表すリーフ ノードとして初期化します。このノードはすべての変数で同一ですが、概念的にはインデックスごとに異なります。 
2. 各変数について、その現在の式ノードへの参照を維持します。 各ノードは、それが基数であるか合成されたべき乗であるかを格納し、演算によって形成された場合にはその子へのポインタを格納します。 
3. 更新「! i j」を処理するとき、xi を、xi の現在の式を xj の式に累乗したものを表す新しいノードに置き換えます。 これにより、左の子 xi と右の子 xj を持つツリー ノードが作成されます。 構造は一度作成されると不変です。 
4. クエリ「? i j」を処理するとき、xi と xj をルートとする 2 つの式ツリーを比較します。 
5. 2 つのノード A と B を比較するには、再帰的に処理を進めます。 両方がベース ノードである場合、それらは同等です。 一方がベースで、もう一方がコンポジットの場合、コンポジットの方が大きくなります。 両方が複合べき乗ノードである場合、最初にそれらの指数構造を比較します。 それらが異なる場合は、より大きい指数が結果を決定し、等しい場合は、基本構造を比較します。 
6. 同じサブツリーがクエリ間で頻繁に比較されるため、ノード ペアの比較をメモ化します。 
7. 再帰評価に基づく比較結果を出力します。 

再帰は当然、べき乗の優位性を反映します。より高い指数構造は常に、より低いレベルの差を上回るため、比較は常に最初の構造的発散を見つけることによって解決されます。 

### なぜ効果があるのか

 すべての変数はルート付き式ツリーとして表され、その構造はその成長率を一意にエンコードします。 この構造に関しては、べき乗は単調です。サブツリーを厳密に大きなものに置き換えると、厳密に大きな全体の式が生成されます。 したがって、2 つの変数を比較すると、構造的優位性によってそれらのツリーを辞書編集的に比較することになります。 すべての変数は同じ基底に由来するため、隠れた定数因子の違いはなく、構造だけで順序が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("left", "right", "id")
    def __init__(self, left=None, right=None, id=None):
        self.left = left
        self.right = right
        self.id = id

memo_cmp = {}

def cmp(a, b):
    if a is b:
        return 0
    if (id(a), id(b)) in memo_cmp:
        return memo_cmp[(id(a), id(b))]

    # base vs non-base
    if a.left is None and a.right is None:
        if b.left is None and b.right is None:
            res = 0
        else:
            res = -1
    elif b.left is None and b.right is None:
        res = 1
    else:
        # both composite: compare structure
        c1 = cmp(a.left, b.left)
        if c1 != 0:
            res = c1
        else:
            res = cmp(a.right, b.right)

    memo_cmp[(id(a), id(b))] = res
    return res

def main():
    n, m = map(int, input().split())
    nodes = [Node(id=i) for i in range(n + 1)]

    for _ in range(m):
        parts = input().split()
        if parts[0] == '!':
            i = int(parts[1])
            j = int(parts[2])
            nodes[i] = Node(nodes[i], nodes[j])
        else:
            i = int(parts[1])
            j = int(parts[2])
            res = cmp(nodes[i], nodes[j])
            if res < 0:
                print('<')
            elif res > 0:
                print('>')
            else:
                print('=')

if __name__ == "__main__":
    main()
```このソリューションでは、変数ごとに永続的な式ツリーを構築します。 更新のたびに、既存のノードを変更するのではなく、新しいノードが作成されるため、以前の比較が有効なままとなり、メモ化が正しく行われることが保証されます。 

比較機能はコアロジックです。 最初に同一性を処理し、次に基本対複合の優位性を処理し、最後に左と右の部分構造を再帰的に比較します。 メモ化ディクショナリは、サブツリー比較の再計算を回避します。これは、クエリ間で同一のサブツリー ペアが繰り返し現れるため、不可欠です。 

Python オブジェクト ID の使用`id()`構造的に同一のノードが異なるメモリ アドレスに存在する場合でも、安定したメモ化キーが保証されます。

### サンプル 1

 構造形式のみを追跡し、基数 2023 には B、べき乗ノードには (A ^ C) を書き込みます。 

| ステップ | 操作 | x1 | x2 | ×3 | ×4 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 初期化 | B | B | B | B |
 | 1 | ！ 1 4 | (B^B) | B | B | B |
 | 2 | ！ 2 1 | (B^B) | (B ^ (B ^ B)) | B | B |
 | 3 | ！ 4 3 | (B^B) | (B ^ (B ^ B)) | B | (B^B) |
 | 4 | ！ 1 4 | ((B ^ B) ^ (B ^ B)) | ... | B | (B^B) |
 | 5 | ！ 2 3 | ((B ^ B) ^ (B ^ B)) | (B ^ (B ^ B)) ^ B | B | (B^B) |

 クエリは構造の深さを比較します。x3 は常に基数で、x4 はべき乗後に大きくなり、指数構造がより深いため x2 が x1 よりも優位になります。 

このトレースは、数値の大きさが無関係であることを示しています。 構造のみが順序を決定します。 

### サンプル 2

 もう一度構造を追跡します。 

| ステップ | 操作 | x1 | x2 | ×3 | ×4 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 初期化 | B | B | B | B |
 | 1 | ！ 2 4 | B | (B^B) | B | B |
 | 2 | ！ 1 2 | (B ^ (B ^ B)) | (B^B) | B | B |
 | 3 | ? 3 1 | B vs (B ^ (B ^ B)) | | | |
 | 4 | ? 1 2 | (B ^ (B ^ B)) vs (B ^ B) | | | |
 | 5 | ！ 2 3 | ... | ((B ^ B) ^ B) | B | B |
 | 6 | ? 1 2 | より深いツリーを比較する | | | |

 クエリは、ツリー内のどこで構造的分岐が最初に発生するかを純粋に確認することによって解決されます。 

これらの例は、ツリー表現が修正されると、比較が決定論的で更新間でも安定していることを確認します。

 | 時間 | O(m・α) | 更新ごとにノードが作成され、比較ごとにメモ化されたサブツリー ペアが参照されます。

 ## 特殊なケース

 特殊なケースの 1 つは、変数が単独でべき乗されるときに発生します。 たとえば、xi = xi^xi です。 これにより、自己参照的な成長構造が形成されます。 

アルゴリズムは、右の子が左の子と同一であるノードを作成することでこれを処理します。 このようなノードをベース ノードと比較すると、再帰的比較によって複合構造とリーフ構造が即座に検出され、厳密な順序付けが行われます。 異なる時点で作成された 2 つの自己べき乗ノードを比較する場合、メモ化されたサブツリー比較により、たとえそれらが異なるオブジェクトであっても、同一の構造が等しいものとして認識されることが保証されます。 

もう 1 つのエッジ ケースは、x1 = x1^x2 の後に再び x1 = x1^x2 が続くような累乗チェーンが繰り返されることです。 これにより、時間の経過とともに構造的に大きな木が生成されます。 更新のたびに新しいノードが作成されるため、以前の比較は有効なままであり、その後の拡張によって破損することはなく、比較は常に各変数をルートとする現在の構造を反映します。
