 ## 解決策
 ## 問題の理解

 私たちは最大 100 × 100 のサイズの隠された 2D グリッドに配置されています。このグリッド内には最大 10 隻の船があり、各船は常に水平または垂直の正確に 5 つの連続したセルからなる直線セグメントです。 船は決して重なりませんが、互いに接触することはできます。 

船がどこにあるのかわかりません。 代わりに、撮影するセルを繰り返し選択することで審査員と対話します。 各ショットは、セルが空だったのか、船のセグメントが含まれていたのか、船全体が破壊されたのかを返します。 すべての船が沈没すると、対話は直ちに終了します。 

微妙なひねりは、裁判官が適応的であるということです。 応答が有効な最終配置と一致している限り、対話中に船の位置を決定することが許可されます。 これにより、グリッドが事前に固定されているという仮定が取り除かれますが、幾何学的制約は取り除かれません。すべての船は依然として長さ 5 の直線セグメントであり、その数は多くても 10 個です。 

2500 ショットの制限が主なボトルネックです。 グリッドの完全なスキャンは不可能であり、すべてのセルを 2 回プローブするだけでもすでにコストがかかりすぎます。 船の構造、つまり長くて硬い部分が私たちが利用できる唯一の手段です。 

素朴な考えは、ヒットするまでランダムにセルを撃ち、ヒットから拡張しようとすることです。 これは、敵対的な適応設定ではひどく失敗する可能性があります。ジャッジは常に有効なヒットを与えるのを遅らせることができ、ランダム性によりすべての船を見つけることに決定的な制限がありません。 

行ごとまたは列ごとに高密度で検索しようとすると、別の障害モードが表示されます。 たとえば、1 行あたり 100 列をスキャンすると 10000 ショットが得られ、拡張を考慮しなくても制限をはるかに超えます。 

中心的な課題は、予算内に収まる程度にプローブのセットを小さく保ちながら、小規模で決定的なプローブのセットを使用して、船ごとに少なくとも 1 回の命中を保証することです。 

## アプローチ

 ブルートフォースの観点は単純明快です。 すべてのセルを候補として扱い、それを発射し、ヒットをマークし、5 つの部分がすべて見つかるまで、検出された各セグメントを拡張することができます。 これにより船が正確に識別され、拡張にかかるコストは最大でも船ごとに一定数の追加ショットです。 問題は最初の検出フェーズです。100 x 100 ではすでに 10000 個のセルが得られるため、セルあたり 1 ショットでも制限を 4 倍超えます。 

長さ 5 のすべての可能な水平または垂直セグメントに少なくとも 1 つの選択されたプローブ セルが含まれることを保証しながら、検索スペースを削減する方法が必要です。 

これはカバーリングの問題になります。 任意の行または任意の列の 5 つのセルからなる連続するブロックがすべてそのセットと交差するようなグリッド点のセットが必要です。 重要な観察は、両方の次元の周期構造がこの保証を強制できるということです。 

各セルに色を付けると、`(row mod 5, column mod 5)`次に、2 つの残基が一致する単一の対角クラスに焦点を当てます。長さ 5 のすべての行セグメントは必ず 5 つの列残基すべてにまたがり、長さ 5 のすべての列セグメントは 5 つの行残基すべてにまたがります。 これにより、有効な各船舶セグメントに選択したクラスのセルが 1 つだけ含まれることが保証されます。 

これにより、検索セットが 10000 セルから約 10000 / 5 = 2000 セルに減り、制限内に十分収まります。 各船の長さは 5 セルしかないため、ヒットが見つかったら、局所的に拡張して船全体を回復できます。

 ## アルゴリズムのチュートリアル

 1. すべての位置で構成されるターゲット セルのセットを構築します`(i, j)`そのような`i mod 5 == j mod 5`。 これにより、グリッドの約 5 分の 1 が生成されます。 このパターンが選択される理由は、5 つの連続する行または列のシーケンスがすべての剰余 mod 5 を循環するためです。 
2. このセット内のすべてのセルを正確に 1 回射撃します。 応答が「ミス」の場合は無視します。 「衝突」または「沈没」の場合、船に属する少なくとも 1 つのセルが発見されました。 
3. ヒットセルが見つかったら、船全体の再構築を試みます。 すべての船は長さ 5 の直線セグメントであるため、向きを決定し、両方向に延ばすだけで十分です。 
4. 方向を決定するために、4 つの基本方向で隣接するセルをプローブします。 もし`(x+1, y)`または`(x-1, y)`命中すると船は垂直になります。 それ以外の場合は、`(x, y+1)`または`(x, y-1)`命中すると船は水平になります。 一方向のみが追加の船舶セルを生成します。 
5. 方向がわかったら、ラインに沿って歩き、連続するセルを合計 5 つまで調査し、ミスに到達するか、5 つの船のセルを収集した後で停止します。 新しく発見されたセルはそれぞれ記録されるため、同じ船の処理が再開されることはありません。 
6. 5 つのセグメントすべてが確認された後 (命中または最終的な「沈没」のいずれかによる)、その船を完了としてマークし、命中セット内の残りのセルのスキャンを続けます。 

重要な考え方は、発見と再構築は分離されるということです。 ヒット セットにより、シップごとにシード セルが常に見つかることが保証され、再構築フェーズではそのシードが全長 5 のセグメントに決定的に拡張されます。 

### なぜ効果があるのか

 セルのセット`(i, j)`このようなセグメントには各列剰余クラスの代表が 1 つだけ含まれるため、剰余が等しいモジュロ 5 は、可能なすべての長さ 5 の水平セグメントと交差します。 同じ対称性が行残基全体にわたる垂直セグメントにも当てはまります。 これにより、ジャッジの配置や適応性に関係なく、すべての船に少なくとも 1 つのプローブされたセルが含まれている必要があることが保証されます。 

単一の船舶セルが見つかると、船舶は固定長の直線セグメントであるという制約により、構造全体が単一の行または列に沿って配置され、分岐や曖昧さは発生しません。 これにより、ローカル拡張が決定的かつ限定的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = 100

def ask(x, y):
    print(x, y)
    sys.stdout.flush()
    return input().strip()

def expand(x, y, used):
    # try to determine orientation
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    vertical = False
    horizontal = False

    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if (nx, ny) in used:
            if dx != 0:
                vertical = True
            if dy != 0:
                horizontal = True

    # fallback probing if needed
    if not vertical and not horizontal:
        if ask(x+1, y) in ("hit", "sunk"):
            vertical = True
        elif ask(x-1, y) in ("hit", "sunk"):
            vertical = True
        elif ask(x, y+1) in ("hit", "sunk"):
            horizontal = True
        elif ask(x, y-1) in ("hit", "sunk"):
            horizontal = True

    cells = [(x, y)]
    used.add((x, y))

    if vertical:
        for dx in [1, -1]:
            nx, ny = x + dx, y
            while 1 <= nx <= N:
                if (nx, ny) in used:
                    nx += dx
                    continue
                res = ask(nx, ny)
                if res == "miss":
                    break
                used.add((nx, ny))
                cells.append((nx, ny))
                if len(cells) == 5:
                    break
                nx += dx
    else:
        for dy in [1, -1]:
            nx, ny = x, y + dy
            while 1 <= ny <= N:
                if (nx, ny) in used:
                    ny += dy
                    continue
                res = ask(nx, ny)
                if res == "miss":
                    break
                used.add((nx, ny))
                cells.append((nx, ny))
                if len(cells) == 5:
                    break
                ny += dy

    return cells

def main():
    n, k = map(int, input().split())

    used = set()

    for i in range(1, n+1):

            if i % 5 != j % 5:
                continue
            if (i, j) in used:
                continue

            res = ask(i, j)
            if res == "miss":
                continue

            if (i, j) not in used:
                ship = expand(i, j, used)
                # ship fully discovered

    return

```メイン ループはクエリをモジュラー対角クラスに制限し、2000 ショットのバジェットを確保します。 の`used`set により、拡張中の冗長なクエリが防止され、複数の検出にわたるシップ セルの二重カウントが回避されます。 

拡張機能は意図的に保守的です。方向に船の一部が含まれていることを確認した場合のみ、その方向への探査を続行します。 これにより、空いたスペースを探索してショットを無駄にすることがなくなります。

 ## 特殊なケース

 エッジ ケースの 1 つは、船がスキャンの後半まで最初に探査されなかったセル上に完全に横たわっている場合です。 たとえば、次のような船があります。`(1,5)`に`(1,9)`の場合にのみ発見される可能性があります`(1,5)`モジュラーパターンで達成されます。 長さ 5 の各水平セグメントには一致する残差セルが 1 つだけ含まれているため、アルゴリズムは依然として検出を保証します。そのため、これら 5 つの位置のうち少なくとも 1 つをクエリする必要があります。 

もう 1 つのケースは、複数のプローブ セルが同じ船に属している場合の重複した発見の試みです。 たとえば2ヒット`(3,3)`そして`(3,5)`両方とも初期スキャン中にトリガーされる可能性があります。 の`used`このセットにより、船が 1 つのシードから拡張されると、スキャン中に同じ船からの後続のヒットが無視され、二重再構築が防止され、過剰なショットが回避されます。 

3 番目のケースには、次のような境界に隣接する船舶が含まれます。`(1,1)`に`(1,5)`。 グリッドの外側またはシップエンドポイントを超えてミスが発生した場合はプローブが停止するだけであり、固定長により 5 回のヒット成功以内に完了することが保証されるため、拡張は引き続き機能します。
