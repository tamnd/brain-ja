 ## 解決策
 ## 問題の理解

 私たちは 3D 空間に惑星の固定ネットワークを与えられており、特定の惑星のペアが双方向の宇宙ハイウェイで接続されています。 各高速道路は、その端点間のユークリッド距離によって決定される既知の長さの直線セグメントです。 

宇宙船はクエリごとに惑星 1​​ から始まります。 各ミッションには、目標の惑星と制限時間が与えられます。 私たちは 2 つのことを決定する必要があります。高速道路を使用して許容時間内に目標に到達できるかどうか、また、可能である場合、時間制約を満たす有効なすべての方法の中で必要な最小燃料はいくらかということです。 

高速道路に沿った移動は任意の動きではありません。 各航行は、直線セグメントに沿った物理的なスプリントのように動作します。船は静止状態から開始し、加速し、ピーク速度に達する可能性があり、終点で正確に停止する必要があります。 この動きの加速度の大きさは 1 m/s² で一定であり、燃料消費量は時間に比例するため、燃料を最小限に抑えることは移動時間を最小限に抑えることと同じです。 

この物理モデルの重要な結果は、最適なプロファイルは対称的な加速と減速であるため、長さ L の単一エッジの移動には、中間の選択に関係なく常に一定の最小時間がかかることです。 エッジの時間コストは、すべてのエッジで同一となる定数係数までは √L に比例します。 すべてのクエリは移動時間の合計を制限と比較するだけであるため、各エッジの重みを √ distance に比例する決定論的な値として扱うことができます。 

したがって、この問題は重み付きグラフの最短経路問題になりますが、クエリごとに追加のグローバル制約があります。つまり、合計移動時間が t を超えない経路のみを考慮し、その中で可能な最小の移動時間を必要とします。 

制約は、最大 10^5 の n、m、q を配置します。 これにより、クエリごとに最短パスを再計算したり、ゼロからダイクストラを q 回実行したりすることが直ちに排除されます。これは O(q m log n) となり、大きすぎます。 

コンポーネントが切断されていると、微妙なエッジケースが発生します。 1から達成できない目標であれば、制限時間に関係なく「不可能」と答えなければなりません。 もう 1 つの重要なケースは、制限時間が非常に短いにもかかわらずパスが存在する場合です。 すべてのエッジの重みが正であるため、実現可能性は時間的には単調ですが、事前に計算された最短距離に対してチェックする必要があります。 

## アプローチ

 直接的なアプローチは、すべてのクエリに対してノード 1 からダイクストラを実行し、すべてのノードへの最短パス距離を計算し、ターゲットまでの距離を確認して制限時間と比較することで各クエリに答えることです。 これは正しいです。正の加重のもとでは最短パスが総移動時間を最小限に抑えるからです。 ただし、これは計算上不可能です。 各ダイクストラのコストは O(m log n) で、それを q 回実行すると O(q m log n) になります。これは最悪の場合で 10^10 の演算に相当します。 

重要な点は、グラフが静的であり、すべてのクエリが同じソースを共有していることです。 クエリごとの再計算は必要ありません。 ノード 1 からのグローバル最短パスの計算は 1 つだけで十分です。 すべてのノードへの最短移動時間を計算すると、各クエリは定数時間ルックアップになります。dist[c] ≤ t の場合は dist[c] を出力し、それ以外の場合は「不可能」を出力します。 

残りの唯一の重要な部分は、エッジの重みを正しく計算することです。 各高速道路は 3D でのユークリッド長 L を持ちます。 移動時間は√Lに比例します。 すべてのクエリは時間制限と比較し、時間に比例した燃料も出力するため、エッジの重みを直接 √L として保存し、単一のダイクストラを実行できます。 

これにより、問題全体が、大きな疎グラフにおける 1 つの最短パスの計算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにダイクストラを再実行します。 O(q m log n) | O(n + m) | 遅すぎる |
 | ノード 1 からの単一のダイクストラ | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての惑星座標を読み取り、隣接エッジのリストを作成します。 各高速道路について、終点間のユークリッド距離を計算し、平方根を使用して移動時間の重みに変換します。 
2. 各エッジ (u、v) に計算された重みが格納される隣接リスト グラフを構築します。 これにより、どの惑星からでもすべての発信高速道路を効率的に横断できるようになります。 
3. 惑星 1 から開始してダイクストラを実行します。距離配列を無限大で初期化し、dist[1] = 0 に設定します。(0, 1) を優先キューにプッシュします。 
4. 暫定距離が最小となるノードを繰り返し抽出します。 抽出された値が古い場合はスキップします。 それ以外の場合は、すべての出力エッジを緩和します。 
5. 各エッジ (u、v、w) について、dist[u] + w を使用して dist[v] の改善を試みます。 これにより、各惑星への既知の最良の移動時間を常に維持することができます。 
6. Dijkstra が完了したら、各クエリを個別に処理します。 クエリ (c, t) の場合、dist[c] が有限であり、≤ t であるかどうかを確認します。 はいの場合は dist[c] を出力し、そうでない場合は「不可能」を出力します。 

この分離が機能する理由は、最短パス値がクエリ制約に依存しないためです。 計算が完了すると、実現可能性が完全に特徴づけられます。 

### なぜ効果があるのか

 正確さはダイクストラのアルゴリズムの標準特性に依存します。つまり、すべてのエッジの重みが負でない場合、最初にノードが確定されるときに、そのノードまでの可能な最小パス コストが見つかります。 すべての有効な移動ルートは、移動時間に等しい加重重みを持つグラフ内のパスに正確に対応するため、計算された dist 配列は全体的に最適になります。 ノードへの代替パスには同等以上のコストが必要であるため、すべてのクエリの実行可能性を同時に判断するには、制限時間と比較するだけで十分です。 

## Python ソリューション```python
import sys
import math
import heapq

input = sys.stdin.readline

def dist(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    dz = a[2] - b[2]
    return math.sqrt(dx*dx + dy*dy + dz*dz)

def solve():
    n, m, q = map(int, input().split())
    pts = [None] * (n + 1)

    for i in range(1, n + 1):
        x, y, z = map(int, input().split())
        pts[i] = (x, y, z)

    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        w = dist(pts[a], pts[b])
        g[a].append((b, w))
        g[b].append((a, w))

    INF = float('inf')
    dist_arr = [INF] * (n + 1)
    dist_arr[1] = 0.0

    pq = [(0.0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist_arr[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist_arr[v]:
                dist_arr[v] = nd
                heapq.heappush(pq, (nd, v))

    out = []
    for _ in range(q):
        c, t = map(int, input().split())
        if dist_arr[c] <= t:
            out.append(f"{dist_arr[c]:.10f}")
        else:
            out.append("impossible")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは座標からグラフを構築し、ユークリッド エッジの重みを計算します。 ダイクストラ実装は最小ヒープを使用し、現在の最適距離に対する標準の等価性チェックを使用して古い状態をスキップします。 同じノードの複数のエントリがヒープ内に存在する可能性があるため、これが必要です。 

クエリ処理はグラフ ロジックから意図的に分離されています。 前処理後の各クエリは、事前に計算された最短パス距離に対する単純なしきい値の比較になります。 

実装の微妙な詳細は、浮動小数点の安定性です。 座標は 1e3 で制限され、エッジの長さは最大でも約 1e3、パスは最大でも 1e5 エッジを蓄積するため、必要な 1e-6 の精度には倍精度で十分です。 

## 実用的な例

 惑星 1 が惑星 2 に接続し、惑星 2 が惑星 3 に直線で接続する小さなシナリオを考えてみましょう。 

| ステップ | ノードが処理されました | 現在の距離[2] | 現在の距離[3] |
 | --- | --- | --- | --- |
 | 1 | 1 | 5.0 | インフ |
 | 2 | 2 | 5.0 | 9.0 |
 | 3 | 3 | 5.0 | 9.0 |

 これは、最短経路が外側に伝播する標準的な緩和チェーンを示しています。 制限時間 8 で惑星 3 を要求するクエリは失敗しますが、制限時間 10 は成功します。 

ここで、同じノードへの 2 つのルート (1 つは長いがより直接的で、もう 1 つは中間ノードを経由して短い) を持つグラフを考えます。 ダイクストラでは、ヒープ順序付けでは常に既知の最小部分距離が最初に拡張されるため、探索順序に関係なく、より短いルートが選択されることが保証されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n) | 各エッジ緩和は一度ヒープにプッシュされる可能性があり、ヒープ操作が支配的になります。 
| スペース | O(n + m) | 隣接リストと距離配列およびヒープ |

 この複雑さは、10^5 までの n、m と互換性があります。 heapq および隣接リストを使用して実装した場合、Python であっても、単一のダイクストラ パスは制限内に問題なく収まります。

    import math
    import heapq

    input = sys.stdin.readline

    def dist(a, b):
        dx = a[0] - b[0]
        dy = a[1] - b[1]
        dz = a[2] - b[2]
        return math.sqrt(dx*dx + dy*dy + dz*dz)

    def solve():
        n, m, q = map(int, input().split())
        pts = [None] * (n + 1)

        for i in range(1, n + 1):
            x, y, z = map(int, input().split())
            pts[i] = (x, y, z)

        g = [[] for _ in range(n + 1)]

        for _ in range(m):
            a, b = map(int, input().split())
            w = dist(pts[a], pts[b])
            g[a].append((b, w))
            g[b].append((a, w))

        INF = float('inf')
        dist_arr = [INF] * (n + 1)
        dist_arr[1] = 0.0

            if dist_arr[c] <= t:
                res.append("ok")
            else:
                res.append("impossible")
        return "\n".join(res)

    return solve()

 ## 特殊なケース

 主なエッジケースは、グラフが切断された場合です。 惑星 3 が惑星 1 から孤立しているとします。ダイクストラは dist[3] を無限大のままにするため、3 をターゲットとするクエリは時間制限に関係なく「不可能」を返す必要があります。 無限大は常に有限 t を超えるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、複数のパスが存在するが、コストがわずかに異なる場合です。 たとえば、直接のロングエッジとマルチエッジのショートカットです。 ダイクストラは、すべての緩和によって距離が単調に改善され、古いヒープ エントリが破棄されるため、より短い複合パスが選択されるようにします。 

最後の微妙なケースは、パスが長いチェーンになった場合の数値精度です。 各エッジの重みは限界値の平方根であるため、累積誤差は 1e-6 許容範囲内に十分収まり、固定精度で印刷すると正確さが維持されます。
