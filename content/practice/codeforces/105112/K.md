 ## 解決策
 ## 問題の理解

 私たちは左上のタイルに配置されています$n \times n$グリッドを作成し、2 つの異なる「騎士のような」移動ルールを使用してグリッドを横切ることができます。 各移動は L 字型にジャンプします。最初のルールは、固定された距離のペアだけ移動します。$(a,b)$2 つの軸に沿って任意の方向と符号で、2 番目のルールは同じことを行います。$(c,d)$。 一手ごとにもう一方のルールに切り替える必要がありますが、最初のステップとしてどちらのルールを選択しても自由です。 

タスクは単一のパスを見つけることではなく、グリッドを離れることなく、左上隅から始まる有効な交互の一連の移動によって、いくつの個別のグリッド セルを訪問できるかを判断することです。 

制約の重要な構造的意味は次のとおりです。$n \le 500$したがって、グリッドには最大 250,000 個のセルがあります。 可能な移動シーケンスの数は深さとともに指数関数的に増加するため、シーケンスの数に比例して状態を探索する解決策は不可能です。 これは、問題が基本的にパスの列挙ではなく、グラフ内の到達可能性に関係していることを直ちに示唆しています。 

微妙な点は、移動の交代によってシステムにメモリが導入されることです。 セル上にあるだけでは状態を説明するのに十分ではありません。次に許可される移動は、前の移動がタイプ A かタイプ B かによって異なるためです。そのため、2 つの同一のグリッド位置は、次にどの移動タイプが予想されるかに応じて異なる動作をする可能性があります。 

単純な間違いは、これを無視して、グリッド セルのみの標準 BFS として扱うことです。 到達可能性は移動タイプのパリティに依存するため、これは失敗します。 

別の失敗モードは、メモ化を行わずにすべてのシーケンスに対して DFS を試行することです。 などの小さなケースでも、$n=10$すでにステップごとに最大 16 方向の分岐係数を生成できるため、同じ構成を繰り返し探索すると爆発的な影響が発生します。 

## アプローチ

 ブルートフォースのアイデアは、最初のセルから開始して 2 つの移動タイプを交互に実行し、可能なすべての一連の移動をシミュレートすることです。 各位置から、現在の移動タイプの最大 8 つの方向をすべて試し、再帰的に続行します。 これはルールに正確に従っており、有効なダンスをすべて列挙しているため、原則的には正しいです。 

ただし、異なる残りの移動パターンで同じセルが何度も再訪問されるため、このアプローチは失敗します。 さらに悪いことに、分岐因子は各ステップで複合化し、探索されたシーケンスの指数関数的な増加につながります。 最悪の場合は次のように動作します$O(16^k)$シーケンスの長さについて$k$、これは小さなグリッドでも完全に実行不可能です。 

重要な観察は、システムには少量の「メモリ」しかないということです。つまり、現在のセルと次に必要な移動タイプです。 このメモリを明示的に含めると、問題全体は、最大でも次のような有限グラフ上の最短パス形式の到達可能性問題になります。$2n^2$州。 

各状態は、グリッド位置と、次の移動でタイプ A またはタイプ B を使用する必要があるかどうかを示すフラグで構成されるペアです。各状態から、反対のフラグを持つ別の状態への最大 8 つの遷移を生成します。 これにより、問題が標準の BFS/DFS 到達可能性の計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シーケンスに対するブルート フォース再帰 | 指数 | 指数スタック | 遅すぎる |
 | BFS 終了$(x,y,parity)$状態 |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、拡張された状態に対するグラフ検索としてモデル化します。 

### ステップ

 1. 状態を次のように定義します$(x, y, t)$、 どこ$(x,y)$は現在のセルであり、$t$は、次にどの移動タイプを使用する必要があるかを示します。 
2. 2 つの開始状態で BFS キューを初期化します。$(0,0,A)$そして$(0,0,B)$, 最初の動きはどちらのタイプを使用してもよいためです。 
3. すべての状態にわたって訪問済みの配列を維持する$(x,y,t)$すでに処理された構成に再度アクセスすることを避けるため。 
4. 各移動タイプの 8 方向のオフセットを事前計算します。$(a,b)$すべての符号と軸の交換を生成します。$(c,d)$。 
5. キューが空でない間に状態をポップします$(x,y,t)$。 
6. 現在の移動タイプについて$t$、考えられるすべての宛先セルを生成します$(nx,ny)$8 つの変換を使用します。 
7. グリッド内の有効な目的地ごとに、状態が$(nx,ny,1-t)$訪問されていない場合は、訪問済みとしてマークし、キューに追加します。 
8. BFS が完了したら、個別のグリッド セルの数を数えます。$(x,y)$どちらかの州を訪れたことがあります。 

### なぜ効果があるのか

 重要な不変条件は、BFS が移動交互制約の下で到達可能な拡張状態のセットを正確に探索することです。 すべての有効なダンスは、この状態グラフのパスに対応します。これは、各動作が厳密に必要な遷移タイプを交互に行い、許可されるすべての幾何学的動作がエッジとして表されるためです。 逆に、このグラフ内のすべてのパスは、構造上、有効な一連のダンス動作に対応しています。 両方の有効な初動選択から到達可能なすべての状態を探索するため、すべての可能なダンスの結合を捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input().strip())
    a, b = map(int, input().split())
    c, d = map(int, input().split())

    movesA = []
    movesB = []

    for dx, dy in [(a, b), (b, a)]:
        for sx in (-1, 1):
            for sy in (-1, 1):
                movesA.append((sx * dx, sy * dy))

    for dx, dy in [(c, d), (d, c)]:
        for sx in (-1, 1):
            for sy in (-1, 1):
                movesB.append((sx * dx, sy * dy))

    def id_state(x, y, t):
        return (x, y, t)

    vis = [[[False, False] for _ in range(n)] for _ in range(n)]
    q = deque()

    vis[0][0][0] = True
    vis[0][0][1] = True
    q.append((0, 0, 0))
    q.append((0, 0, 1))

    while q:
        x, y, t = q.popleft()

        if t == 0:
            moves = movesA
        else:
            moves = movesB

        for dx, dy in moves:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n:
                nt = 1 - t
                if not vis[nx][ny][nt]:
                    vis[nx][ny][nt] = True
                    q.append((nx, ny, nt))

    seen = set()
    for i in range(n):
        for j in range(n):
            if vis[i][j][0] or vis[i][j][1]:
                seen.add((i, j))

    print(len(seen))

if __name__ == "__main__":
    solve()
```実装では、2 つの移動タイプを事前計算された方向リストに明示的に分離します。 これにより、BFS 中の 8 つの対称変換の再計算が回避されます。 各グリッド セルは、次の移動タイプごとに 1 つずつ、2 つのブール フラグで追跡され、同じセルに到達しても必要な次の移動が異なる状態を混同しないようにします。 

よくある実装上の落とし穴は、両方の移動タイプから BFS を開始するのを忘れることです。 最初の動きは自由に選択できるため、両方の初期状態をキューに入れる必要があります。 そうしないと、到達可能なスペースの半分が失われます。 

## 実用的な例

 小さなグリッドを考えてみましょう。$n = 4$、$a = 1, b = 2$、$c = 2, d = 3$。 BFS はから始まります$(0,0,A)$そして$(0,0,B)$。 

### トレース 1

 | ステップ | 状態 | 使用した技 | 新しい州が追加されました |
 | --- | --- | --- | --- |
 | 0 | (0,0,A)、(0,0,B) | 開始 | イニシャル |
 | 1 | (0,0,A) | A 動き | いくつかの有効な (nx,ny,B) |
 | 2 | (0,0,B) | B ムーブ | いくつかの有効な (nx,ny,A) |

 このトレースは、交互配置によって状態空間が 2 つのインターリーブ層に即座に分割されるが、両方の層が BFS 拡張を通じて同期されたままであることを示しています。 

### トレース 2 (縮退の場合)

 しましょう$n=3$、$a=b=c=d=1$。 すべての動きは標準的な王のようなステップになります。 

| ステップ | 状態 | 到達可能 |
 | --- | --- | --- |
 | 0 | (0,0,A/B) | (0,0) |
 | 1 | 隣人 | 隣接するすべてのセル |
 | 2 | バックプロパゲーション | すでに訪問したセルのみ |

 これは、異なる移動タイプで同じセルを再訪問しても、到達可能なセットが増加しないことを示しており、状態ベースのプルーニングが不可欠であることが確認されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2)$| 各州$(x,y,t)$は 1 回訪問され、一定の 8 つの遷移が行われます。 
| スペース |$O(n^2)$| セルごとに 2 つの状態と BFS キューの訪問済み配列 |

 グリッドには最大 250,000 個のセルがあるため、2 つの移動状態に対してセルを 2 倍にしても、問題なく制限内に収まります。 BFS は各状態が 1 回処理されることを保証し、5 秒の制限を簡単に満たす十分な速度のソリューションを実現します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$a=b$または$c=d$これにより、固有の移動方向の数が減少します。 この実装では引き続き 8 つの署名付きバリアントが生成されますが、一部は重複に崩壊します。 BFS にアクセスすると追加コストなしで重複が確実に無視されるため、これによって正確性が損なわれることはありません。 アルゴリズムは遷移の一意性に依存しないため、引き続き正しく動作します。 

もう 1 つの特殊なケースは、両方の移動タイプが同一である場合です。 その状況では、状態グラフは対称の交互パターンで接続された 2 つの同一のレイヤーになります。 両方のレイヤーから開始することで、到達可能な構成が失われないことが保証されるため、BFS は引き続き正しく探索されます。 

最後に、いつ$n$が小さいため、多くの手がすぐにグリッドの外に落ちます。 境界チェックにより無効な状態の拡張が防止され、理論上のほとんどの動きが使用できない場合でも BFS が迅速に終了します。
