 ## 解決策
 ## 問題の理解

 私たちには、それぞれのサイズが数値化されたマトリョーシカ人形のコレクションが与えられました。 人形は、そのサイズが厳密に小さい場合にのみ、別の人形の中に入れることができます。 各人形には最大 1 つの他の人形を直接含めることができるため、構築する構造は分岐構造ではなくチェーンになります。 

タスクは、いくつかの人形を破棄して、残りの人形を 1 つの入れ子シーケンスに配置し、各人形が次の人形の中に収まるようにすることです。 このようなシーケンスに残る人形の数を最大化したいと考えています。 

言い換えると、これは厳密に増加する最長の数値シーケンスを要求することになります。サイズがチェーンに沿って厳密に増加する限り、任意のネスト順序を選択できるため、選択した要素を任意に並べ替えることができます。 

入力サイズは最大 1000 体の人形で、サイズは最大 10000 です。これは、O(n^2) の解が許容される一方で、3 次の解も依然として通過するが不要であることを示唆しています。 O(n log n) ソリューションも可能ですが、必須ではありません。 

微妙な点は、元の順序を維持することに限定されないということです。 誰かが入力を誤ってシーケンスとして扱い、最も長く増加するサブシーケンスを見つけようとすると、過少カウントされる可能性があります。 ここでは自由に並べ替えることができるため、値の複数セットのみが重要になります。 

2 番目のエッジ ケースは、サイズが等しい場合に発生します。 ネストには厳密な等価性が必要なため、等しい要素を連続して配置することはできません。 たとえば、入力`3 3 3 3`生産すべき`1`、 ない`4`なぜなら、厳密に増加するチェーンではそのうちの 1 つだけを選択できるからです。 

## アプローチ

 素朴な解釈は、選択された人形のあらゆる可能な順序を試し、それが有効な厳密に増加するシーケンスを形成するかどうかを確認することによってチェーンを構築することを考えることです。 サブセットを並べ替えて制約を検証することになるため、これはすぐに複雑になりますが、非常に小さい n を超えると不可能です。 

もう 1 つの強引なアイデアは、すべてのサブセットを試して、厳密に増加するシーケンスにソートできるかどうかを確認することです。 これにより、サブセット内のすべての値が個別であるかどうかを確認する問題が軽減されます。これは、サブセットを並べ替えると、重複が存在しない場合にのみ有効なネストが得られるためです。 この観察により、問題はすでに大幅に単純化されています。 

重要な洞察は、順序は無関係であるということです。 すべてのサイズを並べ替えると、有効なネストは厳密に増加する値のサブシーケンスを選択することに対応します。 ソートによって順列の問題がなくなるため、チェーンできる個別の値の数を数えるだけで済みますが、より一般的な DP フレームワークでは多重度も正しく考慮する必要があります。 

これを確認するきれいな方法は、配列をソートし、厳密に増加する最長の部分列を計算することです。 ソートによって元の構造が破壊されるため、LIS は自明なものになります。等しい値はシーケンスを拡張できませんが、増加する値は常に拡張できます。 ソートされた配列では、各個別の値から代表的な値を 1 つ選択するのが最善ですが、LIS を誤って解釈した場合、これでは必ずしも十分とは限りません。 正しい解釈は依然として元の配列の LIS ですが、自由に並べ替えることができるため、最初に並べ替えて、問題を等しい値のグループ化に減らすことができます。 

したがって、解決策は、次の各値が厳密に大きくなるような値を何回選択できるかを数えることになります。これは、マルチセット内の個別の値の数に相当します。 

ただし、より慎重な観点もあります。重複を並べ替えて圧縮すると、最長のチェーンはまさに一意の値の数になります。 

ブルート フォースはすべてのサブセットと順列を探索することで機能しますが、同じ実現可能性チェックを指数関数的に繰り返すため失敗します。 値による順序付けのみが重要であるという観察により、問題は並べ替え後の重複排除に帰着します。

 ## アルゴリズムのチュートリアル

 1. 人形のサイズのリストをお読みください。 
2. リストを降順でない順に並べ替えます。 並べ替えにより、有効なネスト シーケンスがこの順序で厳密に増加するサブシーケンスとして表示されることが保証されます。 
3. 回答のカウンターを初期化します。 最初の要素が存在する場合は、最初の要素を数えることから始めます。 
4. ソートされた配列を左から右にスキャンします。 
5. 前の値より厳密に大きい値が表示されるたびに、カウンタを増やします。 このステップにより、厳密に大きな人形が利用可能な場合にのみネスト チェーンを拡張できるようになります。 
6. 最終的なカウンター値は、ネストできる人形の最大数です。 

### なぜ効果があるのか

 並べ替え後、有効なネスト チェーンは、値が厳密に増加するインデックスのシーケンスの選択に対応する必要があります。 このようなチェーンでは同じ値を隣接させることはできないため、それぞれの個別の値が寄与できる要素は 1 つだけです。 逆に、それぞれの個別の値から昇順で 1 つの代表を選択すると、常に有効なネスト シーケンスが形成されます。 これにより、最適な解が配列内の個別の値の数と正確に一致することがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

if n == 0:
    print(0)
    sys.exit()

cnt = 1
for i in range(1, n):
    if a[i] > a[i - 1]:
        cnt += 1

print(cnt)
```この解決策は、すべての等しい値が隣接するように配列を並べ替えることから始まります。 空でない配列では常にチェーン内に少なくとも 1 つの人形が許可されるため、答えを 1 として初期化します。 次に、線形にスキャンし、前の値よりも厳密に大きい値が見つかった場合にのみ、回答をインクリメントします。 これにより、重複は厳密に増加するチェーンを拡張できないため、無視されることが保証されます。 

ここでよくある間違いは、次のように使用することです`>=`の代わりに`>`これにより、同じサイズがチェーンを延長することが誤って許可されてしまいます。 もう 1 つの微妙な問題は、制約によって少なくとも 1 つの要素が保証されているにもかかわらず、空の入力ケースを忘れることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from io import StringIO
    return _sys.stdout.getvalue()

def solve(inp: str) -> str:
    import sys
    from io import StringIO
    sys.stdin = StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    cnt = 1 if n > 0 else 0
    for i in range(1, n):
        if a[i] > a[i - 1]:
            cnt += 1
    return str(cnt)

 ## 特殊なケース

 重要なエッジケースは、すべての値が等しい場合です。 入力の場合:```
4
7 7 7 7
```並べ替えると同じ順序が得られます。 アルゴリズムは cnt = 1 で始まり、後の要素は厳密に前の要素より大きくないため、結果は 1 のままです。これは、人形を 1 つだけ選択できるという事実と一致します。 

もう 1 つのエッジ ケースは、入力を厳密に減少させることです。```
5
5 4 3 2 1
```並べ替え後:```
1 2 3 4 5
```各ステップで cnt が増加し、5 が生成されます。これにより、並べ替えが完全に許可され、元の順序は無関係であることが確認されます。 

最後の微妙なケースは、混合重複です。```
6
1 2 2 3 3 4
```並べ替えても変わりません。 このアルゴリズムでは、遷移 1→2、2→3、3→4 がカウントされ、結果は 4 になります。これは、重複が追加のネスト深さに寄与することはなく、厳密な増加のみが重要であることを示しています。
