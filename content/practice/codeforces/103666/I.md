 ## 解決策
 ## 問題の理解

 私たちには、それぞれプラスの価値を持つ魔法のアーティファクトのコレクションが与えられています。$w_i$。 主人公は魔力ゼロからスタート。 各アーティファクトは 1 回だけ使用する必要があり、それぞれ 2 つの方法のいずれかでアクティブ化できます。 

アーティファクトが魔法を使用してアクティブ化された場合、その値は主人公の現在の魔力に追加されます。 力を使って発動した場合、アーティファクトの価値にその時点での主人公の現在の魔力を乗じたものに等しいゴールドが得られます。 発動順序は自由で、アーティファクトごとに魔法を使うか力を使うかの決定も自由です。 

目標は、力のアクティベーションから得られるゴールドの合計を最大化することですが、将来のゴールド獲得に使用される乗数を増加させるのは魔法のアクティベーションのみであることを覚えておいてください。 

入力サイズが小さいため、$n \le 100$と価値観$w_i \le 100$。 これは、二次または三次動的計画法のアプローチは受け入れられるが、すべてのサブセットにわたる指数列挙は信頼できないことをすぐに示唆しています。$2^{100}$は大きすぎます。 

重要な構造的観察は、将来の利益を増やす唯一の方法は、一部のアーティファクトを純粋なパワービルダーとして「消費」し、残りを利益ジェネレーターとして「消費」することだということです。 電力は時間の経過とともに蓄積され、後で選択されたすべての利益貢献を直接倍増するため、順序は重要です。 

微妙なエッジケースは、すべてのアーティファクトが魔法として使用される場合です。 この場合、金はまったく生成されず、答えはゼロになります。 もう 1 つの特殊なケースは、すべてが強度として使用される場合ですが、その場合は乗数が常に 0 になるため、やはり答えは 0 になります。 最適なソリューションでは、両方の役割のバランスを取る必要があります。 

## アプローチ

 ブルートフォースアプローチでは、各アーティファクトを魔法または力として使用するために割り当てるあらゆる可能性を試行し、起動順序のすべての順列も考慮します。 それぞれの配置について、現在の電力を追跡し、ゴールドを蓄積するプロセスをシミュレートします。 順列を無視しても、$2^n$割り当てと各シミュレーションのコスト$O(n)$、与える$O(n \cdot 2^n)$、それは限界をはるかに超えています。 

重要な観察は、順序が正規化できるということです。 どのアーティファクトが魔法に使用されるかを修正する場合、魔法の遅延は将来の乗数を減らすだけであるため、パワーへの寄与を重要視したいときにすべての魔法操作を昇順で最初に適用することが常に最適です。 この分離が理解されると、問題は次のようになります。パワーに寄与するアイテムのサブセットを選択し、増加するプレフィックス合計の下でゲインを最大化する強度アイテムの順序を決定します。 

これは、魔法として使用されるアーティファクトの数と、それらの総力がどのように構築されるかについての動的プログラミングの定式化につながります。 私たちはアーティファクトを分類して、合計の魔力と処理したアイテムの数の可能な状態を維持しながら、それらを 1 つずつ検討します。 各アーティファクトはパワーを増加させるか、現在のパワーによって重み付けされたゴールドに貢献し、その決定は DP の移行によって最適に行われます。 

この構造は本質的にナップザックのような DP であり、状態がアイテムのプレフィックスを処理した後に蓄積されたマジック サムとその合計に対して達成可能な最高のゴールドを追跡します。

 ## アルゴリズムのチュートリアル

 私たちは、このプロセスを 2 つのグループを構築すると解釈します。魔力を増加させるために使用されるアーティファクトと、ゴールドを獲得するために使用されるアーティファクトです。ゴールドは、各強度アーティファクトが使用された瞬間の最終的な蓄積パワーに依存します。 難しいのは、力の活性化が進化するパワーに依存するため、パワーの蓄積を慎重にモデル化する必要があることです。 

### ステップ

 1. 成果物を値で並べ替えます。より正確には、すべての選択肢が対称であるため、任意の順序で処理します。 代わりに、プレフィックス処理を介して暗黙的にサブセット上の DP に焦点を当てます。 
2. 処理されたアーティファクトの数とこれまでに蓄積された合計魔力を追跡する DP 状態を定義し、そのような状態ごとに達成可能な最大のゴールドを保存します。 
3. 処理されたアーティファクト、パワー、およびゴールドがゼロの状態で DP を初期化します。 
4. 価値のある成果物ごとに$w$では、既存のすべての状態からの 2 つの遷移を考慮します。 1 つの移行ではアーティファクトを魔法として扱い、現在のパワーを次のように増加させます。$w$金を産出せずに。 もう 1 つの移行ではそれを強度として扱い、現在のパワーに次の値を乗じたものに等しいゴールドを生成します。$w$、パワーを変えることなく。 
5. 各アーティファクトが 1 回だけ使用されるように DP を慎重に更新し、同じ反復内での再利用を避けるために処理の逆の順序で状態を反復します。 
6. すべてのアーティファクトを処理した後、すべての DP 状態をスキャンし、最大のゴールド値を取得します。 

重要な設計上の選択は、電力を状態変数として保存することです。 これが必要なのは、ゴールドが各決定の乗数に依存し、その乗数がまさにそれまでに蓄積された魔力であるためです。 

### なぜ効果があるのか

 プロセスのどの時点でも、将来の結果に影響を与える情報は、現在の合計魔力とどのアイテムが残っているかだけです。 DP 状態はまさにこの情報をキャプチャします。 同じ処理されたプレフィックスと同じ電力で終わる 2 つのシーケンスは、将来の決定のために交換可能であるため、各状態に最適なゴールドのみを保持することが安全です。 これにより、各アーティファクトの決定は現在のパワーのみに依存し、そのパワーがどのように達成されたかには依存しないため、最適な下部構造が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))

    max_sum = sum(w)

    # dp[i][p] = max gold after processing some prefix, with power p
    dp = [[-1] * (max_sum + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        wi = w[i]
        for j in range(i, -1, -1):
            for p in range(max_sum - wi, -1, -1):
                if dp[j][p] < 0:
                    continue

                # use as magic: increase power
                dp[j + 1][p + wi] = max(dp[j + 1][p + wi], dp[j][p])

                # use as strength: gain gold
                dp[j + 1][p] = max(dp[j + 1][p], dp[j][p] + p * wi)

    ans = 0
    for j in range(n + 1):
        for p in range(max_sum + 1):
            ans = max(ans, dp[j][p])

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、処理されたアイテムの数と現在蓄積されている魔力によってインデックスが付けられた DP テーブルを構築します。 各アーティファクトは、パワーの増加に貢献するか、現在のパワーに基づいてゴールドに貢献します。 

逆の反復`j`そして`p`各アーティファクトが 1 回だけ使用されることを保証し、同じアイテムを誤って複数回再利用するような状態の上書きを防ぎます。 強さを利用するための移行`p * wi`、乗数ルールを直接エンコードします。

 ## 特殊なケース

 1 つのアーティファクトを含む最小限のケース (入力など)`1 / 5`、事前の魔法がなければ、どの強さのアクティベーションでもゴールドがゼロであることをアルゴリズムに認識させます。 DP はパワー 0 から始まるため、両方の遷移で最終的な答えはゼロになります。 

みたいなユニフォームケース`3 / 1 1 1`分割が不可欠であることを示しています。 最適な計画は、魔法にアーティファクトを 1 つ、力にアーティファクトを 2 つ使用し、パワー 1 を与え、次にゴールドを与えることです。$1 + 1 = 2$。 DP はすべての中間電力状態を保持するため、両方の可能性を正確に調査します。 

などの初期値が大きいケース`3 / 10 1 1`は、常に当面のゴールドを最大化しようとすると、貪欲な注文が失敗する理由を示しています。 最適解は、最初に 10 をべき乗に変換し、次にそれを 2 回消費して 20 を生成し、DP は正しい状態伝播を通じてこれを取得します。
