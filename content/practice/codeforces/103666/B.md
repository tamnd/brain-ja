 ## 問題の理解

 最初の 2 つの項が次のように固定されているフィボナッチのような数列が与えられます。$F_1 = 1$そして$F_2 = 2$、後の各項は前の 2 つの項の合計です。 これにより、決定論的な無限の整数列が生成されます。 タスクは、大きな値を直接計算することではなく、インデックスが付けられたこのシーケンスのセグメントに焦点を当てることです。$L$に$R$, そして、それらのインデックス付きフィボナッチ数のうち 3 で割り切れる数がいくつあるかを数えます。 

入力は 2 つの整数を与えます$L$そして$R$、フィボナッチ数列内のインデックスの連続ブロックを記述します。 出力は、そのインデックス範囲内で 3 で割ったときに 0 が残るフィボナッチ数がいくつあるかを表す単一の整数です。 

制約により許可されるのは、$L, R \le 10^5$これは、フィボナッチ値を各クエリ エンドポイントまで単純に再計算するソリューションは、$10^5$フィボナッチ数は簡単です。 ただし、本当の問題はフィボナッチ数自体を計算することではなく、割り算を効率的にチェックし、そのプロパティの構造を認識することです。 

大きなフィボナッチ値を直接計算しようとすると、微妙な落とし穴が発生します。 それでも$n \le 10^5$, フィボナッチ数は指数関数的に増加し、標準の整数の範囲を急速に超えます。 Python では大きな整数を使用した単純な実装も可能ですが、その必要はありません。 さらに重要なのは、3 を法とするシーケンスのみに依存する 3 で割り切れるかどうかだけを考慮しているため、完全な値を再計算するのは無駄な労力であるということです。 

入力の書式設定や範囲からトリッキーなエッジ ケースが発生することはありませんが、概念的なエッジ ケースが存在します。誰かがフィボナッチ値を直接計算して割り算をチェックする場合、Python がそれを安全に処理すると想定する可能性があります。 それは可能ですが、問題の構造により、前処理後にインデックスごとに定数時間の解決が可能であるという事実が隠蔽されます。 

## アプローチ

 直接的なアプローチは、フィボナッチ数を 1 つずつ生成することです。$F_1$まで$F_R$、各値を確認し、範囲内の数を数えます。$[L, R]$は 3 で割り切れます。これは定義に直接従うため、正しいです。 コストは直線的です$R$、各ステップで加算とモジュロチェックが実行されます。 Python ではこれはまだ実現可能です$10^5$条件的には問題ありませんが、不必要な作業を行っています。 

重要な点は、完全なフィボナッチ値は決して必要ないということです。 それらはモジュロ 3 のみが必要です。モジュロ 3 の漸化式を削減すると、小さな状態マシンが得られます。各項は、モジュロ 3 の前の 2 つの剰余のみに依存します。$\{0,1,2\}$、最終的にはプロセス全体を繰り返す必要があります。 実際、このシーケンスは非常に短い周期構造を持っているため、インデックスでは 3 で割り切れるパターンが周期的になります。 

このパターンがわかれば、問題はインデックスの数を数えるということになります。$[L, R]$フィボナッチ剰余がゼロになる位置に落ちます。 これは、最初の期間を事前に計算して算術カウントを使用するか、または最大の周期パターンにわたってプレフィックスの合計を構築することによって答えることができます。$10^5$。 

より簡単で同様に安全なアプローチは、以下の残基シーケンスを事前に計算することです。$R$、位置のプレフィックスの合計を構築します。$F_i \bmod 3 = 0$、一定時間内にクエリに応答します。

 ## アルゴリズムのチュートリアル

 割り算は剰余のみに依存するため、フィボナッチ数列を法 3 のみで構築します。 

1. 配列を計算する`f[i]`保管する$F_i \bmod 3$みんなのために$i \le R$。 各値は反復を使用して計算されます。$f[i] = (f[i-1] + f[i-2]) \bmod 3$。 これにより、数値が小さく保たれ、オーバーフローが完全に回避されます。 
2. プレフィックス合計配列を構築する`pref[i]`どこ`pref[i]`インデックスの数を数えます$1 \le j \le i$満足する$f[j] = 0$。 これにより、問題は範囲のカウントに変換されます。そのため、ここでプレフィックスの合計が役立ちます。 
3. 質問に答える$[L, R]$計算によって`pref[R] - pref[L-1]`。 これが機能するのは、プレフィックスの合計が累積頻度をエンコードしているため、減算によって関心のある範囲が正確に分離されるためです。 

機能する理由: フィボナッチ漸化法 3 は決定的な剰余シーケンスを定義するため、すべてのインデックスは事前に固定値を持ちます。 プレフィックス配列には、任意のインデックスまでの割り算条件を満たす位置の正確な数が格納されます。 シーケンスは近似なしで完全に事前計算されるため、プレフィックス値を減算すると、任意の間隔内の有効な要素の数が正確に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

L = int(input().strip())
R = int(input().strip())

n = R

f = [0] * (n + 1)
pref = [0] * (n + 1)

if n >= 1:
    f[1] = 1 % 3
    pref[1] = 1 if f[1] == 0 else 0

if n >= 2:
    f[2] = 2 % 3
    pref[2] = pref[1] + (1 if f[2] == 0 else 0)

for i in range(3, n + 1):
    f[i] = (f[i - 1] + f[i - 2]) % 3
    pref[i] = pref[i - 1] + (1 if f[i] == 0 else 0)

ans = pref[R] - (pref[L - 1] if L > 1 else 0)
print(ans)
```この実装は再発を直接反映していますが、3 を法とするすべてのフィボナッチ値を即座に減少させ、不必要な増加を防ぎます。 プレフィックス配列は、2 回目のパスを避けるために同じループ内で更新されます。 

微妙なディテールは、$L = 1$、 以来`pref[0]`配列内に存在しません。 これはゼロとして扱うことで明示的に処理されます。
