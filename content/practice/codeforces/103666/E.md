 ## 解決策
 ## 問題の理解

 最大 20 × 20 の小さなグリッドが与えられ、各セルには N、S、E、W の中の方向文字が含まれています。各セルは指示された命令のように動作します。ロボットがそのセルの上に立っていると、指示された方向に 1 歩移動することを強制され、グリッド内の隣接するセルに移動します。 

ロボットはこのグリッド上でタスクを実行しようとしていますが、すべての動きには燃料コストがかかります。 タスクの解釈は、ロボットがどこかから開始し、これらの方向規則に従って繰り返し、グリッド内を決定論的に歩行するというものです。 ただし、セルに入るときは常に、方向を自由に選択できず、そのセル内の矢印に従わなければなりません。 

必要な出力は、ロボットがすべての強制動作と一貫した方法でプロセスを完了できるようにするために必要な燃料の最小量です。 実際、これは、グリッドによって引き起こされる有向グラフに対する最短コストの一貫性の問題になります。 

主要な構造上の制約はグリッド サイズであり、n と m は最大 20 です。これにより、最大 400 ノードが与えられます。 およそ O(n^2 m^2)、または V、E が約 400 の O(VE) までのアルゴリズムは許容されます。 これにより、完全な走査履歴に依存するパスまたは状態に対する指数関数的な列挙が直ちに除外されます。 

サイクルによって微妙な問題が発生します。 すべてのセルには出力方向が 1 つだけあるため、グラフは関数グラフとなり、すべてのコンポーネントにはツリーが入力される有向サイクルが 1 つだけ含まれます。 訪問した状態を追跡せずに矢印をたどり続ける単純なトラバーサルは永久にループすることになるため、正しいソリューションではサイクルを明示的に処理する必要があります。 

もう 1 つのよくある落とし穴は、答えが単一の開始セルに依存すると仮定することです。 実際には、コンポーネントは独立しており、それぞれが独自のサイクル構造を持っているため、コストは単一のウォークに沿ったものだけでなく、すべてのコンポーネントにわたって累積されます。 

## アプローチ

 ブルートフォース解釈は、可能なすべてのセルから開始することをシミュレートし、サイクルに到達して解決されるまで矢印に従って完全な走査を完了するコストの計算を試行することです。 各セルから DFS を実行し、訪問した状態を追跡し、反復までのコストを合計することを想像できます。 ただし、これでは同じ部分問題が何度も繰り返されます。 最悪の場合、400 個のノードのそれぞれがサイズ 400 のトラバースをトリガーし、開始ごとに約 160,000 の操作が行われ、これが 400 回繰り返され、約 6,400 万回の状態訪問が発生し、サイクル検出による追加のオーバーヘッドが発生します。 ボーダーラインではありますが、本当の問題は実行時間だけではなく正確性です。単純な DFS では「サイクルのコスト」が何を意味するかを自然に定義しておらず、繰り返しアクセスするとエッジが二重にカウントされたり、共有構造が無視されたりする可能性があります。 

重要な観察は、各ノードには出力エッジが 1 つだけあるため、グラフ全体が互いに素な機能コンポーネントに分解されるということです。 各コンポーネントには正確に 1 つのサイクルがあります。 サイクルを特定すると、他のすべてはそれらにフィードを与える木になります。 最適な計算は、サイクルを見つけてその寄与をコンポーネントごとに 1 回だけ累積することに帰着します。 これは、各サイクルが一貫した最小限の方法でカウントされることを保証しながら、すべてのノードの寄与を計算することに相当します。これは、状態マーキングを伴うグラフ トラバーサルを使用して処理できます。 

各セルをノードとして扱い、その出力エッジをたどることができます。 未訪問、訪問中、完了の 3 つの状態を持つ DFS を使用すると、サイクルを正確に検出できます。 訪問ノードへのバック エッジを見つけると、サイクルを抽出して 1 回処理します。 すべての非サイクル ノードは最終的に何らかのサイクルに接続され、DFS アンワインドまたは BFS 伝播中に処理できます。

 | サイクル検出を備えた機能グラフ DFS | O(V) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドをサイズ V = n × m のグラフに変換します。ここで、各セルは、その方向によって決定される出力エッジを 1 つだけ持ちます。 これにより、機能的なグラフ構造が作成されます。つまり、各ノードが正確に 1 つの近傍ノードを指すことになります。 
2. 訪問状態と親ポインタを保存する配列を維持します。 訪問状態は、処理されていないノード、現在再帰スタック内にあるノード、および完全に処理されたノードを区別します。 
3. 未訪問のすべてのノードから DFS を実行します。 ノードに入るときは、そのノードを訪問中としてマークし、その発信隣接ノードに移動します。 これにより、グラフの決定論的な構造に常に従うことが保証されます。 
4. DFS 中に、すでに訪問状態にあるノードに到達した場合は、サイクルが検出されています。 次に、開始サイクル ノードに戻るまで出力エッジに沿って歩き、そのサイクル内のすべてのノードを収集することによってサイクルを明示的に横断します。 
5. サイクルが特定されたら、その寄与を 1 回だけ計算します。 各ノードには出力エッジが 1 つだけあるため、グラフ内のすべてのノードは 1 つのサイクルに属するか、サイクルにつながるパス上に位置するため、まずサイクルを処理して正確さを保証します。 
6. ノードまたはサイクルを処理した後、ノードを終了としてマークし、今後の DFS 呼び出しでノードが再度アクセスされないようにします。 これにより、二重カウントが防止され、線形の複雑さが保証されます。 

### なぜ効果があるのか

 グラフは関数グラフであるため、すべての接続コンポーネントには 1 つの有向サイクルが含まれており、他のすべてのノードは最終的にそのサイクルにつながります。 スリーステート マーキングを備えた DFS では、各ノードが再帰スタック内で 1 回だけアクセスされ、完了時に 1 回だけアクセスされることが保証されます。 サイクルが検出されると、最初に遭遇したバックエッジがサイクルを閉じるため、そのサイクル内のすべてのノードが 1 回だけ識別されます。 すべてのノードはサイクルに属するか、サイクルにつながり、各 DFS パスは一意の出力エッジをたどるため、割り当てに曖昧さはなく、複数回カウントされるノードはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

# map direction to delta
dir_map = {
    'N': (-1, 0),
    'S': (1, 0),
    'W': (0, -1),
    'E': (0, 1)
}

def idx(i, j):
    return i * m + j

V = n * m
to = [0] * V

for i in range(n):
    for j in range(m):
        di, dj = dir_map[grid[i][j]]
        ni, nj = i + di, j + dj
        to[idx(i, j)] = idx(ni, nj)

state = [0] * V  # 0 = unvisited, 1 = visiting, 2 = done
parent = [-1] * V
answer = 0

stack = []

def dfs(u):
    global answer
    state[u] = 1
    v = to[u]
    parent[v] = u

    if state[v] == 0:
        dfs(v)
    elif state[v] == 1:
        # found cycle
        cycle = []
        cur = u
        cycle.append(v)
        while cur != v:
            cycle.append(cur)
            cur = parent[cur]
        # process cycle exactly once
        answer += len(cycle)

    state[u] = 2

for i in range(V):
    if state[i] == 0:
        dfs(i)

print(answer)
```コードはまずグリッドをグラフに線形化し、各セルがノード インデックスになります。 方向マッピングは、各文字を近傍インデックスに変換します。 DFS は出力エッジに沿ってのみ探索し、すべての走査が機能構造に従うようにします。 

サイクル検出は、再帰スタック マーカー state[u] == 1 に依存します。このようなノードを再訪問するときは、親ポインターを使用してサイクルを再構築します。 再構築は、サイクルのエントリ ポイントに到達するまで現在のノードから逆方向に進み、サイクル内のすべてのノードを収集します。 これにより、各サイクルを 1 回だけカウントすることが保証されます。 

微妙な点は、再帰が続行される前に親ポインターが割り当てられるため、親ポインターは常に DFS ツリー構造を反映することです。 これにより、検出されたサイクルに沿ったバックトラッキングが有効になります。 もう 1 つの重要な詳細は、木の端ではなく、サイクルが見つかった場合にのみ答えをインクリメントすることで、二重カウントを防止します。

 ## 特殊なケース

 それ自体を指す単一のセルが最も単純なサイクルです。 DFS は即座にノードを訪問中としてマークし、自身のエッジをたどり、自身へのバック エッジを検出して、サイズ 1 のサイクルを生成します。 アルゴリズムは、答えを 1 だけ 1 回だけ増分します。 

2 セルのスワップ サイクルにより、親の再構成の正確性がテストされます。 一方のセルが他方のセルを指す場合、またはその逆の場合、DFS スタックは両方のノードをキャプチャし、再構築はエントリ ノードに到達するまで親ポインタを介して正しく戻り、両方を 1 回だけカウントします。 

サイクルにつながる長いチェーンにより、非サイクル ノードがカウントされなくなります。 サイクル検出のみが応答の増分をトリガーするため、受信チェーン上のノードは結果に寄与せずに終了としてマークされ、正確性が維持されます。
