 ## 問題の理解

 長さのバイナリ スケジュールが与えられます。$n$ここで、各ポジションは、アーセニーが特定の時間に行う予定の内容、つまりトレーニングまたは食事のいずれかを表します。 スケジュールは 2 文字の文字列として固定されており、1 文字はトレーニングを表し、もう 1 文字は食事を表します。 

私たちが強制しなければならない制約は局所的で非常に具体的です。最終スケジュールのどこにも、食後すぐにトレーニングを行うことは許可されていません。 言い換えれば、トレーニング時間が食事時間の直後に続くパターンは、最後の文字列に現れてはなりません。 

スケジュール内の任意の位置を変更することができ、変更するたびにキャラクターが訓練から食事へ、またはその逆に切り替わります。 目標は、結果の文字列が制約を満たすように、可能な限り最小限の変更を行うことです。 

制約$n \le 10^5$いかなる二次戦略も即座に除外します。 考えられるすべての変更を試したり、ネストされたスキャンで修正をシミュレートしたりするアプローチは、遅すぎます。 解は線形または線形に近いものでなければなりません。$n$くらいしか時間がないので、$10^7$操作。 

微妙な点は、1 つの悪い隣接関係を修正することは、注意せずに貪欲に行うと、以前または後の決定の有効性に影響を与える可能性があることです。 たとえば、ローカルで違反を修正するだけの単純な左から右への修正では、次の位置を考慮せずに文字を変更すると、新しい違反が発生する可能性があります。 

弦が頻繁に切り替わる場合には、別の特殊なケースが発生します。`ete...`。 このような場合、単純な貪欲な修正により文字が繰り返し反転され、不必要な変更が生じる可能性がありますが、最適な解決策では文字列が食事とトレーニングの間の単一の境界を持つ安定した形式に再形成される傾向があります。 

## アプローチ

 ブルートフォースアプローチでは、可能な長さの最終文字列をすべて試します。$n$2 つの文字にわたって、制約を満たしながら、元の文字までの編集距離が最小のものを選択します。 このような文字列の数は$2^n$有効性をチェックしてそれぞれの距離を計算するにはコストがかかります$O(n)$、につながる$O(n 2^n)$、それは完全に不可能です。 

より構造化された総当たり攻撃では、有効な文字列が非常に厳密な形式であることがわかります。 トレーニングの後に食事が行われると、それは禁止されます。これは、文字列にパターンを含めることができないことを意味します。`te`。 これはすべてを意味します`e`全員の前に現れなければなりません`t`したがって、有効な最終文字列は次の形式でなければなりません。`eeee...tttt...`いくつかのスプリットポイント付き。 

これが重要な構造的洞察です。 任意に変更するのではなく、境界インデックスを選択するだけで済みます。$k$、ここでの位置は前にあります$k$すべてです`e`そしてからのポジション$k$それ以降はすべてです`t`。 分割ごとに、元の文字列との不一致の数を計算し、最小値を選択できます。 

これにより、問題はすべての文字列にわたる指数関数的な検索から、すべての文字列にわたる線形スキャンに軽減されます。$n+1$分割ポイント。それぞれはプレフィックス カウントを使用して定数時間で評価されます。

 ## アルゴリズムのチュートリアル

 私たちは、有効な最終スケジュールを食事からトレーニングへの単一の移行として解釈します。 タスクは、この遷移がどこで起こるかを選択することになります。 

1. プレフィックス数を事前に計算します。`t`各ポジションまで登場します。 これにより、プレフィックスをすべてに強制した場合に必要な変更の数をすぐに知ることができます。`e`。 
2. 同様に、サフィックスの数を計算します。`e`以降は各ポジションから登場します。 これにより、サフィックスを強制的にすべてにする場合に必要な変更の数を評価できます。`t`。 
3. 考えられる各分割ポイントについて$k$、次のように解釈します: 位置$[0, k-1]$なる`e`、およびポジション$[k, n-1]$なる`t`。 
4. この分割のコストを次の数として計算します。`t`プレフィックスに次の数を加えたもの`e`接尾語に。 これは、文字列を分割フォームに一致させるために必要な反転の数です。 
5. 最小限のコストで分割を追跡します。 複数の分割で同じコストが発生する場合は、どれを分割しても問題ありません。 
6. 最適な分割を見つけたら、その分割から直接最終的な文字列を再構築します。 

これが機能する理由は、すべての有効な文字列の間に境界が 1 つだけ存在するためです。`e`そして`t`。 制約の違反`te`このような境界を強制すると、 は正確に消えるため、有効な候補を見逃すことはありません。 

### なぜ効果があるのか

 有効な最終構成では部分文字列を避ける必要があります。`te`。 このような部分文字列がどこかに存在する場合、それは違反を表します。 このような違反をすべて世界的に排除する唯一の方法は、`t`表示されます、いいえ`e`後で登場します。 これにより、文字列の構造が単調な形式になります。`e`続いてブロック`t`。 すべての有効なソリューションはこのファミリーに属しており、そのファミリー内のすべての可能な境界をテストするため、最適なソリューションがその中にあることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # prefix_t[i]: number of 't' in s[0:i]
    prefix_t = [0] * (n + 1)
    for i in range(n):
        prefix_t[i + 1] = prefix_t[i] + (1 if s[i] == 't' else 0)

    # suffix_e[i]: number of 'e' in s[i:n]
    suffix_e = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_e[i] = suffix_e[i + 1] + (1 if s[i] == 'e' else 0)

    best_cost = n + 1
    best_k = 0

    for k in range(n + 1):
        cost = prefix_t[k] + suffix_e[k]
        if cost < best_cost:
            best_cost = cost
            best_k = k

    res = []
    for i in range(n):
        if i < best_k:
            res.append('e')
        else:
            res.append('t')

    print(best_cost)
    print("".join(res))

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックスとサフィックスのアキュムレータを構築して、各分割を定数時間で評価できるようにします。 分割位置にわたるメイン ループは、最適な境界を選択します。 再構築は選択した構造を直接適用するため、増分編集やシミュレーションの必要がありません。 

よくある間違いは、分割ごとに文字列をスキャンしてコストを再計算することです。これにより、$O(n^2)$。 もう 1 つは、分割ポイントが次のような場合があることを忘れることです。$0$または$n$、すべてに対応`t`またはすべて`e`。

 ## 特殊なケース

 単一文字の文字列は値に関係なく常に制約を満たし、アルゴリズムは両方の境界位置を自然に考慮します。$k = 0$そして$k = 1$、コストがゼロになります。 

次のような完全に交互の文字列`tetete`興味深いのは、局所的な修正が失敗するためです。1 つの違反を反転すると、近くに別の違反が作成される可能性があります。 分割ベースの定式化では、グローバル構造にコミットすることでこれを完全に回避し、プレフィックス/サフィックスのコストは 1 回の評価で必要なすべての変更を正確にキャプチャします。 

完全に均一な文字列には変更が必要なく、コスト関数はすべての分割を正しく評価し、少なくとも 1 つの分割ではコストがゼロになり、元の文字列が保持されます。
