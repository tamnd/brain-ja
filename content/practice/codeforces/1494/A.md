 ## 解決策
 ## 問題の理解

 A、B、C という 3 つの記号にわたる文字列が与えられています。各位置に括弧「(」または「)」を割り当てて、同じ長さの括弧シーケンスを生成する必要があります。 主な制限は、等しい文字は等しい括弧にマップする必要があるということです。そのため、すべての A は同じ括弧で置き換えられ、すべての B は同じ括弧で置き換えられ、すべての C は同じ括弧で置き換えられます。 

したがって、位置ごとに括弧を選択する代わりに、セット {A, B, C} から {“(”, “)”} へのマッピングを選択しています。 可能なマッピングは 8 つだけですが、そのすべてが有効な通常のブラケット シーケンスを生成するわけではありません。 

目的は、これらのマッピングの少なくとも 1 つが正しいブラケット シーケンスを生成するかどうかを判断することです。 

n ≤ 50 という制約は非常に小さいです。 t ≤ 1000 の場合、テスト ケースごとに最大 8 × 50 の操作しか実行しないため、すべてのマッピングに対するブルート フォースとマッピングごとの線形妥当性チェックは十分に高速です。 

グローバル構造を考慮せずに、局所的なバランスや頻度に基づいてブラケットを貪欲に割り当てようとすると、微妙な失敗例が発生します。 たとえば、過半数の文字が「(」になるはずだと仮定すると、バランスは数ではなく順序に依存するため、失敗する可能性があります。

 もう 1 つの落とし穴は、問題を立場ごとに独立したものとして扱うことです。 文字の出現はすべて結合されているため、単一の位置を反転することは不可能であり、ローカル修正が無効になります。 

## アプローチ

 ブルートフォースの見方は簡単です。 A、B、C はそれぞれ独立して「(」または「)」のいずれかにマッピングでき、23 = 8 個の割り当てが可能です。 割り当てごとに、結果として得られるブラケット シーケンスを構築し、左から右にスキャンし、決してマイナスになってはならず、ゼロで終わる必要があるバランス カウンターを維持することによって、それが通常のブラケット シーケンスであるかどうかを確認します。 

これが機能するのは、通常のブラケット シーケンスが O(n) で検証でき、マッピング候補の数が一定であるためです。 したがって、テスト ケースごとの総コストは定数の n 倍になります。 

制約が文字のすべての出現をグローバルに結合するため、位置に基づいて括弧を貪欲に割り当てて賢くしようとしても機能しません。 この構造は非常に小さいため、列挙が最適化の必要性を支配します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (8 マッピング) | O(8n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、文字から括弧までのすべての可能な割り当てをテストすることに集約します。 

1. {A、B、C} から {“(”, “)”} までの 8 つのマッピングをすべて列挙します。 これは 3 ビット マスクを使用して行われ、各ビットが 1 つの文字のブラケット タイプを決定します。 これにより、考えられるすべてのグローバル割り当てを確実にカバーできます。 
2. マッピングごとに、マッピングに従って文字列内の各文字を置き換えることによって括弧シーケンスを構築またはシミュレートします。 文字列を明示的に構築する必要はありません。 残高を直接計算できます。 
3. カウンターを維持しながら文字列を左から右にスキャンします。`bal`。 「(」が表示されると増加し、「)」が表示されると減少します。 
4. いつでも`bal`が負になると、シーケンスは無効になり、このマッピングのチェックを直ちに停止します。 これは、左括弧よりも閉じ括弧が多い接頭辞を後で修正できないため、必要です。 
5. スキャンが終了したら、次のことを確認します。`bal`ゼロに等しい。 「はい」の場合、マッピングにより有効な通常の括弧シーケンスが生成されるため、「YES」を出力できます。 
6. マッピングが機能しない場合は、「NO」を出力します。 

### なぜ効果があるのか

 有効な割り当ては、3 つの文字のそれぞれに括弧の種類を選択することによって完全に記述されます。 隠れた自由度はありません。 括弧シーケンスの接頭辞条件は必要かつ十分です。シーケンスは、その実行残高がゼロを下回らず、ゼロで終了する場合にのみ正規です。 考えられるすべての割り当てを徹底的にテストするため、有効な構成を見逃すことはなく、無効な割り当てはプレフィックス条件に違反する場合に正確に拒否されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_valid(s, mp):
    bal = 0
    for ch in s:
        if mp[ch]:
            bal += 1
        else:
            bal -= 1
        if bal < 0:
            return False
    return bal == 0

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()

        letters = ['A', 'B', 'C']

        ok = False
        for mask in range(8):
            mp = {}
            for i, c in enumerate(letters):
                mp[c] = (mask >> i) & 1  # 1 -> '(', 0 -> ')'

            if is_valid(s, mp):
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、ビットマスクを使用して 8 つのマッピングすべてを反復します。 各ビットは、文字が「(」または「)」のどちらにマップされるかをエンコードします。 ヘルパー関数は、実行バランスを維持し、負になった場合は早期に拒否することにより、線形時間で妥当性をチェックします。 早期終了は重要ですが、小さな制約があるため、厳密に必要というわけではありません。 

マッピング ディクショナリはマスクごとに再構築されますが、キーが 3 つだけ存在するため問題ありません。 代わりに、サイズ 8 × 3 の事前に計算された配列を使用することもできますが、複雑さは変わりません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def is_valid(s, mp):
        bal = 0
        for ch in s:
            bal += 1 if mp[ch] else -1
            if bal < 0:
                return False
        return bal == 0

    def solve():
        t = int(input())
        for _ in range(t):
            s = input().strip()
            letters = ['A', 'B', 'C']

            ok = False
            for mask in range(8):
                mp = {}
                for i, c in enumerate(letters):
                    mp[c] = (mask >> i) & 1
                if is_valid(s, mp):
                    ok = True
                    break
            print("YES" if ok else "NO")

    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("4\nAABBAC\nCACA\nBBBBAC\nABCA\n") == "YES\nYES\nNO\nNO"

# custom cases
assert run("1\nAA") == "NO"
assert run("1\nAB") == "YES"
assert run("1\nABCABC") == "YES"
assert run("1\nAAAAAA") == "NO"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | AA | いいえ | 有効なマッピングがない最小の偶数の場合 |
 | AB | はい | 最も単純で有効な交互構造 |
 | ABCABC | はい | 複数文字の循環有効な代入 |
 | ああああ | いいえ | 均一文字列はバランス制約を満たさない必要があります。 

## 特殊なケース

 重要なエッジケースは、すべての文字が同一である場合です。 例えば`AAAAAA`すべての位置に同じブラケットを強制的に受け入れます。 「(」にマッピングされている場合、シーケンスは決して閉じられません。「)」にマッピングされている場合、シーケンスは直ちに無効になります。 アルゴリズムは両方を正しくテストし、どちらも最終残高がゼロになるため両方を拒否します。 

もう一つのケースは、次のような交互構造です。`ABABAB`。 ここでは、特定のマッピングのみがプレフィックスの安定性を可能にします。 実行中、バランス トレースは、A と B を反対のブラケット タイプに揃える割り当ての場合にのみ非負のままになります。これは列挙型によって自動的にキャプチャされます。 

3 番目のケースは、次のような短い文字列です。`AB`。 カウントのバランスが取れている場合でも、有効なシーケンスを生成するマッピングは 1 つだけです。 スキャンは、プレフィックスが即座に -1 に低下するマッピングを正しく拒否します。これは、考えられる最も早い障害点です。
