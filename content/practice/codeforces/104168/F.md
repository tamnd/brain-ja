 ## 解決策
 ## 問題の理解

 各頂点が正の値を持ち、各エッジが正の重みを持つルート付きツリーが与えられます。 ルートはノード 1 に固定されており、他のすべてのノードには 1 つの親があります。 

ゲームは、任意の開始頂点にトークンを配置し、それをツリー内で下に移動することによってプレイされます。 親への移動は明示的に禁止されているため、ノードからその子のいずれかへの移動のみが許可されます。 これは、すべての有効なプレイがルートから厳密に離れる単純なパスであることを意味します。 

この下向きのパスに沿って歩きながら、2 つの量を蓄積します。 利益は、開始ノードを含むすべての訪問ノードの頂点値の合計です。 コストは、パスに沿って使用される最大エッジの重みとして定義され、エッジが使用されない場合、コストはゼロになります。 

各テスト ケースについて、利益が少なくとも k である有効な下向きパスが少なくとも 1 つ存在するように、可能な限り最小のコストを決定する必要があります。 すべてのエッジが許可されている場合でも、そのようなパスが存在しない場合、答えは -1 になります。 

制約は大きく、テスト ケースあたり最大 10^5 ノード、合計 5×10^5 です。 これにより、ツリー内の下向きのパスの数は最悪の場合でも 2 次になるため、すべてのパスを明示的に試行するソリューションは除外されます。 すべてのパスを保存することさえ不可能であるため、固定コストの実現可能性を線形時間で評価し、コストを探索する方法が必要です。 

出発点について考えると、微妙な問題が生じます。 パスはどこからでも開始できるため、ルートからノードへのパスだけを考慮するだけでは十分ではありません。 どのノードも開始点として機能するため、すべてのサブツリーで下向きのパスを考慮する必要があります。 

もう 1 つの罠は、根から葉へのチェーン全体を取得する必要があると仮定していることです。 パスはいつでも停止する可能性があるため、最適なセグメントが葉に到達する前に終了する場合や、ツリーの奥深くで開始される場合もあります。 

下向きのパスをすべて列挙する単純なアプローチは、すぐに失敗します。 考えられるすべてのコストのパス合計を再利用せずに個別に再計算する動的プログラミングでも、繰り返しチェックすると TLE になります。 

## アプローチ

 ブルートフォースのアイデアは、ツリー内のすべての可能な下向きパスを考慮し、そのノード値の合計を計算し、その最大エッジ重みを記録することです。 次に、パスの和が少なくとも k に達するかどうかを確認し、そのような最大エッジの重みの最小値を取得します。 

これは正しいですが、まったく実行不可能です。 n 個のノードを持つツリーには、チェーン状の構造で Θ(n^2) 個の下向きのパスを持つことができます。 各パスは、その合計と最大エッジの重みを計算するために O(長さ) の作業を必要とし、最悪の場合は 3 次的な動作につながります。 

重要な点は、コストは使用される最大エッジ重みにのみ依存するということです。 しきい値 X を固定し、重みが最大でも X であるエッジのみを許可する場合、問題は実行可能性チェックに集約されます。つまり、許可されたエッジのみを使用して合計が少なくとも k になる下向きのパスが存在するかどうかです。 

X より上のエッジが削除されると、残った構造は根のある森のままであり、単純なツリー DP を使用して最適な下向きパスを計算できます。 各ノードについて、そのノードから始まる下向きのパスの最適な合計を計算します。 

これにより、問題は X の単調決定関数に変わります。X の値が有効なパスを許可する場合、より大きな X も許可されます。 この単調性により、エッジの重みに対して二分探索を適用できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | O(n^2) から O(n^3) | O(n^2) | 遅すぎる |
 | 二分探索 + ツリー DP | テストあたり O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 固定最大エッジ重み X の実現可能性チェック

1. ツリー隣接リストを作成しますが、重みが X を超えるエッジは無視します。これにより、ゲーム グラフから禁止された手が効果的に削除されます。 
2. 子が親の前に処理されるように、ツリーの後順走査を計算します。 これが必要なのは、ノードから始まる最適なパスがその子に依存するためです。 
3. 各ノード u について、エッジ制約の下で u から始まる下向きパスの最大利益である dp[u] を計算します。 
4. 即時停止は常に許可されるため、dp[u] を a[u] として初期化します。 
5. 許可されたエッジによって接続された u の各子 v について、u から v へのパスの拡張を検討します。dp[u] を a[u] にゼロと dp[v] の最大値を加えたものとして更新します。 これは、合計が増加する場合にのみ下降を続けるという考えを表しています。 
6. すべてのノードの最大 dp 値を追跡します。 この最大値が少なくとも k であれば、しきい値 X で十分です。 

### エッジの重みに対する二分探索

 1. すべてのエッジの重みを収集し、それらを並べ替えて検索空間を形成します。 
2. 実行可能性チェックが成功した最小の重み X を二分探索します。 
3. 最大の X でも失敗した場合は、-1 を返します。 

### なぜ効果があるのか

 dp 計算により、固定 X に対して、考えられるすべてのノードから開始する最適な下向きパスの合計が見つかることが保証されます。 すべての有効なプレイは正確に 1 つの下降パスであるため、グローバル最大 dp 値は、その制約の下で可能な最大の利益となります。 

単調性は、X を増加しても使用可能なエッジが追加されるだけで削除されないため、以前に有効だったパスはすべて有効のままであり、新しいパスが表示される可能性があるという事実から来ています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve_case(n, k, a, parent, w):
    children = [[] for _ in range(n)]
    edges = []
    
    for i in range(1, n):
        p = parent[i-1] - 1
        weight = w[i-1]
        children[p].append((i, weight))
        edges.append(weight)

    # postorder using stack
    order = []
    stack = [0]
    parent_idx = [-1] * n
    while stack:
        u = stack.pop()
        order.append(u)
        for v, wt in children[u]:
            parent_idx[v] = u
            stack.append(v)

    order.reverse()

    def check(x):
        dp = [0] * n
        best = 0

        for u in order:
            best_child = 0
            for v, wt in children[u]:
                if wt <= x:
                    if dp[v] > best_child:
                        best_child = dp[v]
            dp[u] = a[u] + best_child
            if dp[u] > best:
                best = dp[u]

        return best >= k

    lo, hi = 0, max(edges) if edges else 0
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        parent = list(map(int, input().split()))
        w = list(map(int, input().split()))
        out.append(str(solve_case(n, k, a, parent, w)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、指定された親配列を使用してルート隣接リストを構築します。 エッジは下向きにのみ使用されるため、各ノードは対応するエッジの重みを持つ子を格納します。 

実現可能性チェック関数は、ボトムアップの走査順序を実行し、1 つのパスで dp 値を計算します。 重要な詳細は、接続エッジの重みが現在のしきい値内にある子のみを考慮するということです。 これにより、フィルタリングされたツリー上で dp が正確に計算されます。 

二分探索は可能な最大エッジ重みを超えて実行され、全体的な最適化の問題が実現可能性チェックの繰り返しに軽減されます。 

## 実用的な例

 小さな木を考えてみましょう。 

入力:```
n = 4, k = 11
a = [2, 5, 6, 10]
parents = [1, 2, 1]
weights = [20, 1, 2]
```X = 2 の実現可能性をテストします。 

| ノード | 許可される最高の子 DP | dp[u] | 理由 |
 | --- | --- | --- | --- |
 | 3 | なし | 6 | 上向きのエッジは許可されません |
 | 4 | 0 (エッジの重み 2 が許可されます) | 10 | 4から始まります |
 | 2 | dp[4]=10 | 15 | 5 + 10 |
 | 1 | dp[2]=15 | 17 | 2 + 15 |

 最大 dp は 17 で、これは ≥ 11 であるため、X = 2 が機能します。 

ここで、より厳しいしきい値 X = 1 を考えてみましょう。 

| ノード | 許可される最高の子 DP | dp[u] |
 | --- | --- | --- |
 | 3 | なし | 6 |
 | 4 | なし (エッジウェイト 2 はブロックされています) | 10 |
 | 2 | なし | 5 |
 | 1 | なし | 2 |

 最高は 10 であるため、このしきい値は失敗します。 

これは、エッジのフィルタリングによって構造がどのように変化するか、および制約の下で dp が最適な下向きセグメントを再計算する方法を示しています。

 ## 特殊なケース

 最適なパスがルート付近ではなく深いノードで始まる場合、特殊なケースが発生します。 たとえば、ルートの値が小さいが、リーフの値が大きい場合でも、正しいソリューションでは、そのリーフから開始して単独でカウントできる必要があります。 dp[u] には子遷移を必要とせずに常に a[u] が含まれるため、dp 定式化はこれを自然に処理します。 

別のケースは、すべてのエッジが重すぎてしきい値を小さくできない場合に発生します。 DP は依然として正しい単一ノード値を返す必要があります。 dp はエッジを使用する必要がないため、分離されたノードを選択するように正常に低下します。 

最後に、k が非常に大きい場合、ツリー全体にさえ十分な合計が含まれない可能性があります。 その場合、最大の X での最大 dp は k に到達しないため、二分探索はすべてのしきい値を使い果たし、正しく -1 を返します。
