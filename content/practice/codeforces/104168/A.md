 ## 解決策
 ## 問題の理解

 正の整数が与えられます$n$、すべての因子ペアを考慮します$(x, y)$そのような$x \cdot y = n$両方とも$x$そして$y$正の整数。 このようなペアごとに、絶対差を計算します。$|x - y|$そして、すべての有効な因子ペアにわたって可能な最大値が必要です。 

入力には最大で次のものが含まれます$2 \cdot 10^5$テスト ケース。各テスト ケースは 1 つの整数を持ちます。$n$まで$10^9$。 これにより、因子のすべてのペアをスキャンして試行するアプローチは即座に除外されます。$n$が鈍くなるにもほどがあります。 テスト ケースごとにすべての約数を列挙するだけでも効率的である必要があるため、どのソリューションも大まかに実行する必要があります。$O(\sqrt{n})$テストごと、またはそれ以上。 

微妙な点は、ペアが$(x, y)$そして$(y, x)$は絶対値であるため等価であるため、次までの約数のみを考慮する必要があります。$\sqrt{n}$。 

素朴な間違いは、体系的に除数をチェックせずに、最大の差が「ランダムな」因子のペアから得られると仮定することです。 たとえば、次の場合$n = 36$、考えられるペアには以下が含まれます$(1,36)$、$(2,18)$、$(3,12)$、$(4,9)$、$(6,6)$。 最大の違いは明らかに次のとおりです$(1,36)$、与える$35$。 連続する約数だけをチェックするか、最も近い因子のペアだけをチェックする不注意なアプローチでは、これを見逃してしまいます。 

もう 1 つのよくある誤解は、最良のペアが常に近くにあると考えていることです$\sqrt{n}$。 これは誤りです。違いではなく、類似性が製品の安定性を最大化するからです。 ここでは反対の目的が必要です。 

## アプローチ

 ブルートフォース手法では、すべての整数をチェックしてすべての因子ペアを生成します。$x$から$1$に$n$かどうかをテストします$x \mid n$、そしてコンピューティング$y = n / x$。 これは、すべての有効なペアを明示的に列挙し、目的を評価するため、正しいです。 ただし、かかります$O(n)$テストケースごとに、次のようになります$2 \cdot 10^5 \times 10^9$最悪の場合、それは不可能です。 

重要な観察は、因子のペアが対称的な形で現れるということです。$\sqrt{n}$。 すべての約数$x \le \sqrt{n}$ユニークなパートナーを定義します$y = n/x$。 したがって、次まで繰り返すだけで済みます。$\sqrt{n}$これにより、検索スペースが大幅に削減されます。 

約数を考えてみると$x$、ペアは固定されており、寄与は$|x - n/x|$。 このようなすべてのペアの最大値を追跡するだけです。 

効率的な除数の列挙以上に必要な、より深い組み合わせ構造はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$テストごと |$O(1)$| 遅すぎる |
 | 除数の列挙 |$O(\sqrt{n})$テストごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 与えられた条件に対して$n$、応答変数をゼロに初期化します。 これにより、すべての因子ペア間で見つかった最良の絶対差が保存されます。 
2. 反復する$i$から$1$に$\lfloor \sqrt{n} \rfloor$。 私たちはただ考慮します$i$候補要因としては。 
3. もし$i \cdot i = n$、 それから$i$は完全な平方根因数のペアです$(i, i)$、差がゼロであるため、答えは改善されません。 
4. もし$i \mid n$、ペアの約数を計算します$j = n / i$。 これで有効な因子ペアが得られました$(i, j)$。 
5. コンピューティング$|i - j|$この値が現在の最大値より大きい場合は、回答を更新します。 
6. ループが終了したら、見つかった最良の値を出力します。 

重要な推論ステップは、次のステップまでのみをチェックすることです。$\sqrt{n}$これにより、すべての約数が 1 回だけ表示されることが保証され、各約数はその相補的なパートナーを一意に決定します。 

### なぜ効果があるのか

 すべての因子ペア$(x, y)$と$x \cdot y = n$を超えない要素が 1 つあります$\sqrt{n}$。 したがって、すべてを繰り返すと、$i \le \sqrt{n}$それを分ける$n$すべての異なるペアを 1 回だけ列挙します。 目的は順序付けではなくペアのみに依存するため、候補が見逃されることはなく、重複が正確さに影響を与えることはありません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        best = 0
        
        r = int(math.isqrt(n))
        for i in range(1, r + 1):
            if n % i == 0:
                j = n // i
                if i != j:
                    diff = j - i
                    if diff > best:
                        best = diff
        
        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、整数の平方根を使用してループを境界付けします。 各約数について$i$、そのパートナーを計算します$j$次の場合にのみ差異を評価します。$i \neq j$。 この条件により、完全正方形の冗長なゼロ更新が回避されますが、それらを含めても正確さに影響はありません。 

微妙な実装の詳細は、`math.isqrt`精度の問題を避けるため、浮動小数点平方根の代わりに使用します。 以来$n \le 10^9$、整数平方根は安全かつ高速です。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        best = 0
        r = math.isqrt(n)
        for i in range(1, r + 1):
            if n % i == 0:
                j = n // i
                if i != j:
                    best = max(best, abs(i - j))
        out.append(str(best))
    return "\n".join(out)

# provided sample-like checks
assert run("3\n36\n20\n1\n") == "35\n19\n0", "basic cases"

# custom cases
assert run("1\n1\n") == "0", "n=1 edge"
assert run("1\n2\n") == "1", "prime small"
assert run("1\n1000000000\n") >= "0", "large stress"
