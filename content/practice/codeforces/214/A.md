 ## 解決策
 ## 問題の理解

 負でない整数のペアが何組あるかを数える必要があります。`(a, b)`2 つの方程式を同時に満たします。 

-`a² + b = n`-`a + b² = m`入力により 2 つのターゲット値が与えられます`n`そして`m`。 私たちの仕事は、可能な値をテストすることです`a`そして`b`そして、両方の方程式が同時に成り立つペアが何組あるかを数えます。 

制約は非常に小さいです。 両方`n`そして`m`せいぜい`1000`これは、ブルートフォースが実行可能であることを即座に示唆しています。 すべてのペアをチェックしても`(a, b)`から`0`に`1000`必要な反復回数は約 100 万回だけですが、これは Python の 2 秒の制限内では簡単です。 

さらに興味深いのは、方程式が検索空間をどれほど厳密に制限しているかを認識することです。 以来`a² ≤ n`、の値`a`決して超えることはできません`√n`。 同様に、`b² ≤ m`、 それで`b`決して超えることはできません`√m`。 この観察により、検索が大幅に減少します。 

見落としやすいエッジケースがいくつかあります。 

微妙なケースの 1 つは、1 つの変数がゼロになる場合です。 例えば：```
9 3
```有効なペアは次のとおりです。`(3, 0)`なぜなら：

-`3² + 0 = 9`-`3 + 0² = 3`からループを開始する不用意な実装`1`の代わりに`0`would incorrectly miss this answer.

 もう 1 つの注意が必要な状況は、ペアがまったく存在しない場合です。 例えば：```
1 1
```あらゆる可能性を試しても有効なペアは得られません。 間違った解決策の中には、各方程式を独立して解き、誤って互換性のない値を組み合わせてしまうものがあります。 

複数の候補値が個別に 1 つの式を満たしているが、両方が一緒には満たされていない場合、別のエッジ ケースが発生します。 例えば：```
10 34
```ペア`(3, 1)`を満たす:

 -`3² + 1 = 10`-`3 + 1² = 4`最初の方程式は機能しますが、2 番目の方程式は機能しません。 アルゴリズムは常に両方の方程式を同時に検証する必要があります。 

## アプローチ

 最も直接的なアプローチは、考えられるすべてのペアを試すことです`(a, b)`両方の式が成り立つかどうかを確認します。 

両方の変数が負ではなく、次の値に制限されているため、`1000`、次を繰り返すことができます。 

-`a`から`0`に`1000`-`b`から`0`に`1000`各ペアについて、次を計算します。 

-`a² + b`-`a + b²`両方が一致する場合`n`そして`m`、答えを増やします。 

この総当り的な解決策は、考えられるすべての候補ペアを明示的にチェックするため、正しいです。 何も見逃すことはできません。 

問題は効率です。 完全な検索は大まかに次のように実行されます。```
1001 × 1001 ≈ 1,000,000
```小切手。 これでも、与えられた制約の下では問題なく通過しますが、少し観察することでさらに改善できる可能性があります。 

最初の方程式から:```
a² + b = n
```以来`b ≥ 0`、私たちは次のことを知っています：```
a² ≤ n
```それで`a`まで上がるだけでいい`√n`。 

同様に、以下から:```
a + b² = m
```得られるもの:```
b² ≤ m
```それで`b`まで上がるだけでいい`√m`。 

これにより、検索は全体ではなく現実的な候補値に対する非常に小さな総当り攻撃に変わります。`[0, 1000]`範囲。 

もう 1 つの有益な観察は、一度`a`が固定されている場合、最初の方程式は一意に決定されます。`b`:```
b = n - a²
```したがって、入れ子になったループも必要ありません。 繰り返すことができます`a`、可能な唯一のものを計算します`b`、2 番目の方程式を検証します。 

これにより、アルゴリズムが線形の複雑さまで軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(1000㎡) | お(1) | 承認済み |
 | 最適 | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`そして`m`。 
2.初期化`answer = 0`。 
3. 反復する`a`から`0`その間`a² ≤ n`。 

より大きな値`a`最初の方程式に直ちに違反します。`b`マイナスにはできません。 
4. 以下を計算します。```
b = n - a²
```これが唯一可能な値です`b`電流の最初の式を満たすことができる`a`。 
5. 2 番目の方程式も成立するかどうかを確認します。```
a + b² == m
```true の場合、インクリメントします`answer`。 
6. ループが終了したら、印刷します。`answer`。 

### なぜ効果があるのか

 負でない整数ごとに`a`と`a² ≤ n`、最初の方程式は、次の候補値を 1 つだけ決定します。`b`。 他にはありません`b`を満たすことができます:```
a² + b = n
```したがって、アルゴリズムは、考えられるすべての有効なペアを 1 回だけ検査します。 2 番目の方程式は、システム全体を満たすペアのみを維持するフィルターとして機能します。 このプロセスでは実行可能なすべてのペアが出現する必要があるため、最終的なカウントは正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

answer = 0

a = 0
while a * a <= n:
    b = n - a * a

    if a + b * b == m:
        answer += 1

    a += 1

print(answer)
```ループは実行可能な値のみを反復します。`a`。 条件`a * a <= n`それを保証します`b = n - a²`非負のままです。 

行:```
b = n - a * a
```最初の方程式を整理すると直接得られます。 これにより、入れ子になったループが完全に回避されます。 

2 番目の方程式:```
a + b * b == m
```候補ペアごとに 1 回だけチェックされます。 

微妙な点の 1 つは、平方根の代わりに乗算を使用していることです。 浮動小数点平方根を使用して境界を計算すると、丸めの問題が発生する可能性があります。 ループ条件`a * a <= n`その問題を完全に回避します。 

もう 1 つの小さな実装詳細は次のとおりです。`b`は常に整数であるため、`n`そして`a²`は整数です。 追加の検証は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())

    answer = 0

    a = 0
    while a * a <= n:
        b = n - a * a

        if a + b * b == m:
            answer += 1

        a += 1

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided samples
assert run("9 3\n") == "1\n", "sample 1"

# custom cases
assert run("1 1\n") == "2\n", "two symmetric solutions"

assert run("2 2\n") == "0\n", "no valid pair"

assert run("0 0\n") == "1\n", "minimum values"

assert run("1000 1000\n") == "0\n", "large boundary case"

assert run("25 5\n") == "1\n", "solution with b = 0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`|`2`| 複数の有効なペア |
 |`2 2`|`0`| 解決策は存在しません |
 |`0 0`|`1`| 最小境界値 |
 |`1000 1000`|`0`| 大きな入力の処理 |
 |`25 5`|`1`| 1 つの変数がゼロの場合 |
