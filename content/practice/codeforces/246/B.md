 ## 解決策
 ## 問題の理解

 整数の配列があり、2 つの異なる要素を選択し、同時に一方を 1 増やし、他方を 1 減らすことができます。この操作は何度でも実行できます。 タスクは、これらの操作のシーケンス後に等しくできる配列要素の最大数を決定することです。 

重要なのは、この操作が何を行うかを解釈することです。 1 つの数値を 1 増やし、別の数値を 1 減らすと相殺されるため、各演算では配列の合計が保持されます。 したがって、合計は不変です。 同時に、この操作により値の「再分配」が可能になります。つまり、大きな数値を減少させ、小さな数値を増加させることができます。 これは、配列がターゲット値の周囲で可能な限りバランスが取れているときに、等しい要素の最大数が発生することを示唆しています。 

配列には最大 100,000 個の要素と、最大 10,000 の大きさの値を含めることができます。 これにより、総当たりの動きのシミュレーションが除外されます。$10^9$操作を繰り返し適用しようとした場合の手順。 

エッジ ケースには、すべての要素が等しい配列、要素が 1 つだけ含まれる配列、または 2 つの要素の違いが 1 より大きい配列が含まれます。たとえば、配列`[2, 1]`それらの合計は 3 であり、整数がないため、完全に等しくすることはできません`x`そのような`2x = 3`両方の要素について。 このようなケースを正しく処理するには、個々の要素を比較するだけでなく、配列と整数の除算プロパティの合計を考慮する必要があります。 

## アプローチ

 単純なアプローチでは、考えられるすべての操作のペアをシミュレートし、それ以上の操作が役に立たなくなるまで要素を等価になるように調整しようとします。 この操作では合計が保持され、値が相互に移動するため、これは原理的には正しいです。 しかし、最悪の場合、各移動は 2 つの要素を 1 ずつ変更するだけです。配列に 10,000 オーダーの値を持つ 100,000 の要素が含まれている場合、これには数十億の操作が必要になる可能性があり、これでは遅すぎます。 

問題を単純化するための洞察は、2 つのことを観察することで得られます。 まず、配列の合計は変化しません。 第二に、もし望むなら`k`要素が何らかの整数と等しくなるようにする`x`、 それから`k * x`合計は合計以下である必要があります。そうでない場合は、分配するのに十分な合計がありません。 このことから、等しい要素の最大数は、配列サイズにわたる合計の最大公約数に密接に関係していることがわかりますが、実際には、合計が次で割り切れるかどうかを確認するだけで済みます。`n`か否か。 和が割り切れる場合`n`、すべての要素を次と等しくすることができます。`sum // n`。 そうでない場合、私たちにできる最善のことは`n - 1`要素は等しい。1 つの要素が残りを吸収する必要があるため。 

ここでの話は、各操作が平等に向かうため総当たり攻撃は機能しますが、操作が多すぎるために失敗するということです。 合計は不変であり、等価性には整数値が必要であるという観察により、これを割り算に基づく単純なチェックに減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての要素の合計を計算します。 これは、再配布できる「リソース」の合計を表します。 
2. 合計が要素数で割り切れるかどうかを確認します。`n`。 そうであれば、すべての要素を次と等しくすることができます。`sum // n`。 これが機能するのは、各演算で合計が保持され、整数除算によって正確なターゲット値が存在することが保証されるためです。 
3. 合計が割り切れない場合`n`の場合、すべての要素を等しくすることは不可能です。 この場合、私たちにできる最善のことは、`n - 1`要素が等しい。 残りの要素は残りを吸収します。 これは鳩の巣原理から導き出されます。`n-1`余分な要素を 1 つ残して、要素のバランスを正確に調整できます。 
4. 可分性チェックに基づいて結果を出力します。 

これが機能する理由: 不変式は配列の合計です。 有効な操作のシーケンスではこの合計が保持されるため、等しい要素のターゲット値は次の条件を満たす必要があります。`k * x <= sum`整数の場合`x`。 割り切れるということは、合計を均等に分割できることを保証します。 それ以外の場合は、1 つの要素が残りを取得する必要があります。 他の構成では、これ以上に増加するため、これ以上等しい要素を生成することはできません。`n - 1`要素が合計制約に違反する可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)

if total % n == 0:
    print(n)
else:
    print(n - 1)
```コードは最初に要素の数と配列を読み取ります。 合計を計算し、次のように割り切れるかどうかを確認します。`n`。 和が均等に除算されるかどうかだけを知る必要があるため、整数除算を直接使用する必要はありません。 の`n - 1`フォールバックは、単一の剰余によって完全な等価性が得られない場合に対処します。 Python は大きな整数を自動的に処理するため、境界の問題はありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    return str(n if total % n == 0 else n - 1)

# Provided sample
assert run("2\n2 1\n") == "1", "sample 1"

# Custom tests
assert run("1\n100\n") == "1", "single element"
assert run("3\n1 1 1\n") == "3", "all equal"
assert run("4\n2 2 2 3\n") == "3", "one remainder"
assert run("5\n5 5 5 5 5\n") == "5", "all equal large n"
assert run("2\n-100 100\n") == "2", "sum divisible with negatives"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n100`| 1 | 単一要素配列 |
 |`3\n1 1 1`| 3 | すでにすべて等しい |
 |`4\n2 2 2 3`| 3 | 1 つの要素が異なります |
 |`5\n5 5 5 5 5`| 5 | すべて等しい、より大きい n |
 |`2\n-100 100`| 2 | 負の値、合計は割り切れる |

 ## 特殊なケース

 配列の要素が 1 つだけの場合、合計は自明に次で割り切れます。`n=1`、アルゴリズムは正しく 1 を出力します。 2 つの要素が 1 だけ異なる配列の場合、次のようになります。`[2, 1]`の場合、合計 3 は 2 で割り切れないため、アルゴリズムは正しい 1 を出力します。 すべての要素が等しい配列の場合、合計は均等に除算されるため、出力は次のようになります。`n`。 合計ロジックは整数に一律に適用されるため、アルゴリズムは負の数とゼロを自然に処理します。
