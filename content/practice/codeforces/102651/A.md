 ## 解決策
 ## 問題の理解

 2 つのチームが不明な数の試合を行います。 勝利すると勝者に3ポイントが与えられ、引き分けは両チームに1ポイントが与えられ、負けた場合はポイントが与えられません。 私たちが知っているのは、第 1 チームと第 2 チームの最終的な得点数だけです。 課題は、このスコアが達成可能かどうかを判断し、達成可能であれば、可能な限り少ない試合数を使用して、試合をファースト チームの勝利、引き分け、セカンド チームの勝利に分割する方法を見つけることです。 

させて`a`最初のチームの最終スコアとなり、`b`2番目のチームの最終スコアになります。 答えには、最初のチームが勝った試合の数、引き分けの試合の数、2 番目のチームが勝った試合の数という 3 つの値が含まれている必要があります。 一連の一致がスコアを生成できない場合は、次のように出力します。`-1`。 

スコアは次のように大きくなります。`10^9`したがって、試合をシミュレートしたり、可能な数の試合を反復しようとしたりすることは不可能です。 サイズのループでも`a`または`b`10 億回の反復が必要になる可能性があります。 ソリューションはスコアリング システムの算術プロパティを使用し、一定時間内に完了する必要があります。 

いくつかの境界状況により、単純な解決策が崩れる可能性があります。 たとえば、入力```
0
1
```答えはありません。 スコアの差は、`-1`, ただし、試合ごとに点差が3の倍数で変化するため、このスコアは表示されません。 

別のケースは次のとおりです。```
2
2
```正しい出力は次のとおりです。```
0 2 0
```不注意なアプローチでは、1 勝につき 3 ポイントが効率的であるため、両方のスコアを勝利で表そうとする可能性がありますが、その試合ではどちらのチームも相手に 0 ポイントを与えずに勝利することはできません。 両チームが勝ち点２を獲得するには２引き分けが唯一の方法だ。 

ケース```
3
0
```以下を生成する必要があります:```
1 0 0
```最初に引き分けだけを検索する方法では、最小の試合数で 1 回の勝利で正確なスコアがすでに得られていることを見逃す可能性があります。 

## アプローチ

 直接総当り方式では、最初のチームの勝利と引き分けを可能な限り試し、残りの試合から 2 番目のチームのスコアを形成できるかどうかを確認します。 スコアは到達できるので、`10^9`、そのような検索には、最悪の場合、最大で数十億回の反復が必要になります。 このアプローチは、考えられる一致の組み合わせを列挙するため、論理的には正しいですが、制限に適合することはできません。 

有益な観察は、スコアの差を見ることから得られます。 させて`x`最初のチームが勝利すること、`y`引き分けになり、`z`セカンドチームの勝利になる。 最終スコアは次の条件を満たします。```
3x + y = a
y + 3z = b
```これらの方程式を減算すると、描画が削除されます。```
3x - 3z = a - b
```それで：```
x - z = (a - b) / 3
```チームのスコアの差は 3 で割り切れる必要があります。 その条件を確認したら、残るは勝敗数の選択です。 

試合の総数を最小限に抑えるには、引き分けに代わる勝利の数を最大化する必要があります。 勝利は 1 つのチームに 3 ポイントを与えますが、引き分けは各チームに 1 ポイントしか与えないため、できるだけ多くの勝利を使用すると試合の数が減ります。 

最初のチームがスコアで有利な場合、最初のチームに必要な追加の勝利を維持し、2 番目のチームの勝利を最大化します。 2番目のチームは最大でも`b // 3`勝ちます。 逆の場合は対称です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(max(a, b)) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スコアの差を計算する`a - b`。 3で割り切れない場合は出力`-1`。 チームのスコアの差は勝利によってのみ生まれ、勝利するたびにその差はちょうど 3 点ずつ変わります。 
2. コンピューティング`k = (a - b) / 3`。 この値は、最初のチームが 2 番目のチームよりも何勝多いかを表します。 正の値は最初のチームが追加の勝利を持っていることを意味し、負の値は 2 番目のチームが追加の勝利を持っていることを意味します。 
3. もし`k`が負でない場合は、2 番目のチームができるだけ多くの試合に勝つようにします。 セット`z = b // 3`, なぜなら、第 2 チームが勝利するたびに、第 2 チームのスコアから 3 ポイントが消費されるからです。 2 番目のチームの残りのポイントは引き分けになります。`y = b - 3z`。 最初のチームが必要とするのは、`x = z + k`必要な差を維持するために勝ちます。 
4. もし`k`が負の場合は、ミラー計算を実行します。 設定により、最初のチームができるだけ多くの試合に勝つようにします。`x = a // 3`。 残りの勝ち点は引き分けとなり、2番目のチームの勝利となります。`z = x - k`。 
5. 出力`x`、`y`、 そして`z`。 

なぜ効果があるのか:

 The score difference equation fixes the difference between the numbers of wins of the two teams. アルゴリズムによってその違いが変わることはありません。 必要なアドバンテージを持たずにチームに可能な最大の勝利数を割り当てた後、残りのポイントは常に 3 未満になるため、引き分けによってのみ獲得できます。 この構造により、有効なスコアが生成されます。 Since every replacement of a draw by a win reduces the number of matches, maximizing wins minimizes the total number of matches.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())

    diff = a - b

    if diff % 3 != 0:
        print(-1)
        return

    k = diff // 3

    if k >= 0:
        z = b // 3
        y = b - 3 * z
        x = z + k
    else:
        x = a // 3
        y = a - 3 * x
        z = x - k

    print(x, y, z)

if __name__ == "__main__":
    solve()
```最初の部分では、唯一の不可能な条件を確認します。 Python の整数はオーバーフローしないため、次の値が得られます。`10^9`計算全体を通じて安全です。 

いつ`k`が正の場合、コードは可能な限り多くのセカンド チームの勝利を得ることから始まります。 必要なスコア差を維持しながら、これらの勝利がいくつかの引き分けを置き換えるため、これは重要な最小化ステップです。 ２軍の残り勝ち点は引き分けの数そのままだ。 

いつ`k`が負の場合、チームを入れ替えて同じ考え方が適用されます。 表現`z = x - k`機能するので`k`は負であるため、2 番目のチームに必要な追加の勝利が追加されます。 

除算には整数フロア除算が使用されます。 勝ちの可能性をすべて取り除いた残りは常に次のようになります。`0`、`1`、 または`2`、これは有効な描画数です。 数式では自然に一致がゼロになるため、スコアがゼロの場合は特別な処理は必要ありません。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        a = int(input())
        b = int(input())

        diff = a - b

        if diff % 3 != 0:
            return "-1"

        k = diff // 3

        if k >= 0:
            z = b // 3
            y = b - 3 * z
            x = z + k
        else:
            x = a // 3
            y = a - 3 * x
            z = x - k

        return f"{x} {y} {z}"

    ans = solve()
    sys.stdin = old_stdin
    return ans

assert solution("2\n1\n") == "-1", "sample 1"
assert solution("3\n0\n") == "1 0 0", "sample 2"
assert solution("0\n0\n") == "0 0 0", "both teams score zero"
assert solution("2\n2\n") == "0 2 0", "only draws"
assert solution("1000000000\n1000000000\n") == "333333333 1 333333333", "large equal scores"
assert solution("1\n4\n") == "0 1 1", "second team advantage"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 / 0`|`0 0 0`| 空のトーナメント結果 |
 |`2 / 2`|`0 2 0`| 引き分けが必要なスコア |
 |`1000000000 / 1000000000`|`333333333 1 333333333`| 大きな値と整数の演算 |

 ## 特殊なケース

 のために`0`そして`1`、アルゴリズムは次のように計算します。`diff = -1`。 以来`-1`3 で割り切れない場合は返されます`-1`すぐに。 これにより、どの勝利の組み合わせでも生み出せない差によって引き起こされる不可能なスコアが処理されます。 

のために`2`そして`2`、差はゼロであるため、チームの勝利数は同じでなければなりません。 アルゴリズムは、すべての可能な勝利を削除します。`a // 3 = 0`そして2点を引き分けとして残す。 出力します`0 2 0`、可能な限り最小限の一致数を使用します。 

のために`3`そして`0`、その差は 3 ですので、`k = 1`。 最初のチームは 2 番目のチームよりもちょうど 1 勝多くなければなりません。 2番目のチームはポイントを獲得せず、`z = 0`そして`y = 0`、結果は次のようになります`x = 1`。 このアルゴリズムは不必要な引き分けの作成を回避し、可能な限り最小のトーナメントを返します。
