 ## 解決策
 ## 問題の理解

 Petya はある程度の積載量のあるトラックを購入できます。 各潜在的な顧客は、いくつかの可能な契約を提示します。 トラックがその契約に必要な重量以上を運ぶことができ、一定の利益が得られる場合にのみ契約が可能です。 Petya は各顧客から最大 1 つの契約を受け入れることができます。 

選択したトラックの容量に対して、すべての顧客は、その容量に適合する最も収益性の高い契約を個別に提供します。 タスクは、1 つの固定容量の利益を見つけることではなく、多くのクエリに答えることです。つまり、希望する利益ごとに、達成可能な利益の合計がその値に達する最小の容量を見つけます。 

入力では顧客を 1 人ずつ説明します。 各顧客ブロックには、その顧客に対して考えられるすべての契約が含まれています。 全顧客の契約数の合計は最大50万件、クエリ数も最大10万件です。 

制限が大きいため、すべての容量をすべての契約に対してチェックすることができなくなります。 すべてのクエリを個別に試行し、すべてのコントラクトをスキャンするソリューションでは、約 500000 * 100000 の操作が必要になります。これは、約 5 * 10^10 の操作に相当し、2 秒の制限をはるかに超えています。 すべての契約をまとめて処理し、予想される利益を簡潔に表現して質問に答える必要があります。 

重要な問題は、同じ顧客からの契約を単純に加算できないことです。 不注意な解決策では、すべてがトラックに適合する場合、1 人の顧客の複数の契約がカウントされる可能性がありますが、選択される契約は 1 つだけになる可能性があります。 もう 1 つの微妙な点は、同じ顧客が同じかそれ以上の利益を持つより安価な契約をすでに結んでいる場合、より大きな必要容量を持つ契約は役に立たない可能性があることです。 

たとえば、ある顧客について考えてみましょう。```

```容量 9 では、顧客は依然として 20 の利益しか得られないため、容量 9 のトラックを購入する必要はありません。 支配的な選択肢を削除せずに、必要な利益に達する最初の契約だけを探すソリューションでは、9 と誤答する可能性があります。 

もう 1 つのエッジケースは、目標利益を達成できない場合です。```
1

5 8
1

```出力は次のとおりです。```

```考えられる最大の利益は 8 であるため、最終的な利益を確認せずに常に最大の利用可能な容量を答えとして採用するアルゴリズムは間違っています。

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。 キャパシティを推測するには、すべての契約を検査し、どの契約が利用可能であるかを判断し、すべての顧客について利用可能な契約の中で最高の利益を維持することができます。 これは正しいです。顧客は独立しており、各顧客は独自の最大有効契約のみを拠出するからです。 

ただし、すべてのクエリに対してこれを実行すると、時間がかかりすぎます。 100,000 件のクエリと 500,000 件の契約がある場合、最悪のケースでは約 500,0000,000 件のチェックが必要になります。 

有益な観察は、答えはトラックの積載量が増加したときに総利益がどのように変化するかによってのみ決まるということです。 1 人の顧客の貢献は減少しない関数です。 契約が利用可能になると、その顧客にとって以前の最良の契約が置き換えられる可能性がありますが、顧客の貢献が減少することはありません。 

お客様ごとに、必要な容量ごとに契約を並べ替えることができます。 それらを昇順に通過しながら、これまでに見られた最高の利益を維持しています。 あるキャパシティで最高の利益が向上すると、そのキャパシティによって合計の答えが増加します。 プレフィックスの最大値を改善しない契約は無視できます。 

すべての顧客を処理した後、イベントのコレクションが得られます。 満員御礼のイベント`w`トラックの積載量が上限に達すると、達成可能な利益の合計がある程度増加すると述べています`w`。 すべてのイベントを容量ごとに並べ替え、プレフィックスの合計を取得すると、完全な関数が得られます。`capacity -> maximum possible total profit`これで、すべてのクエリはこの単調リストに対する二分探索になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * sum(mi)) | O(n) | 遅すぎる |
 | 最適 | O(sum(mi) log sum(mi) + q log sum(mi)) | O(和(ミ)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての顧客について、必要なトラックの積載量ごとにすべての契約を並べ替えます。 複数のコントラクトの容量が同じ場合、すべてが同時に使用可能になるため、順序は重要ではありません。 
2. この顧客にとって最大の利益を維持しながら、この並べ替えられたリストをスキャンします。 この最高の利益が増加するたびに、増加が発生する容量と増加のサイズを含むイベントを追加します。 これにより、1 人の顧客の選択肢が、全体の答えが変わる瞬間のみに変換されます。 
3. すべての顧客イベントを 1 つのリストに結合し、容量ごとにリストを並べ替えます。 同じキャパシティを必要とするすべてのコントラクトが同時に利用可能になるため、同じキャパシティのイベントは一緒に処理する必要があります。 
4. ソートされたイベントを走査し、2 つの配列を構築します。 最初のものは、総利益が変化する容量を保存します。 2 番目には、その容量までのすべての変更を適用した後の合計利益が格納されます。 
5. すべてのクエリについて、格納された利益が要求された値以上である最初の位置を二分探索します。 そのような位置が存在しない場合は、出力します`-1`。 

なぜ効果があるのか:

 ある顧客の場合、契約を容量別に分類した後、プレフィックス最大値がまさにこの顧客が考えられるすべてのトラック容量で選択できる最適な契約になります。 このアルゴリズムは、このプレフィックスの最大値が変化するポイントのみを記録するため、その顧客に関する情報は失われません。 

総利益は、すべての顧客の貢献の合計です。 すべての貢献が減少しないため、総利益も減少しません。 イベント リストはこの関数のすべての増加を再構築するため、二分探索により、必要な利益が達成される最初の容量が見つかります。 最終値がクエリより小さい場合、それを満たす容量はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []

    for _ in range(n):
        m = int(input())
        contracts = []
        for _ in range(m):
            w, c = map(int, input().split())
            contracts.append((w, c))

        contracts.sort()

        best = 0
        i = 0
        while i < m:
            w = contracts[i][0]
            current_best = best

            while i < m and contracts[i][0] == w:
                if contracts[i][1] > current_best:
                    current_best = contracts[i][1]
                i += 1

            if current_best > best:
                events.append((w, current_best - best))
                best = current_best

    events.sort()

    capacities = []
    profits = []

    total = 0
    i = 0
    while i < len(events):
        w = events[i][0]
        while i < len(events) and events[i][0] == w:
            total += events[i][1]
            i += 1
        capacities.append(w)
        profits.append(total)

    q = int(input())
    ans = []

    import bisect

    for _ in range(q):
        x = int(input())
        pos = bisect.bisect_left(profits, x)
        if pos == len(profits):
            ans.append("-1")
        else:
            ans.append(str(capacities[pos]))

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```入力は顧客ごとに処理されるため、プログラムですべての顧客を一度に保存する必要はありません。 顧客ごとに並べ替えることで、契約が利用可能になる順序が明らかになります。 同じ容量で表示される複数の契約が同時に顧客の選択に影響を与えるため、スキャンでは同じ容量がグループ化されます。 

変数`best`現在の顧客の以前の最大利益を保存します。 新しい最大値と古い最大値の差は、まさにこの顧客がそのキャパシティで追加する寄与分です。 この差分のみを保存することで、不要な契約を保持することを回避できます。 

すべての顧客が処理された後、グローバル イベント リストが並べ替えられます。 2 回目のスキャンでは、等しい容量を結合してから保存します。 これが必要なのは、そのキャパシティを要求するクエリは、そのキャパシティでロックが解除されたすべてのコントラクトが考慮された後に利益を受け取る必要があるためです。 

Python の整数は、言語に任意精度の演算機能があるため、可能な利益の合計を安全に処理します。 二分探索では、`bisect_left`なぜなら、利益が目標を下回らない最初の容量が必要だからです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M log M + q log M) | M は総契約数です。 契約書やイベントの仕分けが仕事の大半を占めます。 |
 | スペース | お(お) | イベント リストには容量の変更のみが保存され、契約数を超えることはできません。 |

 契約の総数は最大 500,000 であるため、これだけの要素を並べ替えることは可能です。 クエリ フェーズでは、圧縮利益関数に対してバイナリ検索のみを実行するため、100,000 個のクエリを迅速に処理できます。 

## テストケース```python
import sys
import io
import bisect

def solve_data(data):
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(data)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.getvalue().strip()

def solve():
    input = sys.stdin.readline
    n = int(input())
    events = []

    for _ in range(n):
        m = int(input())
        a = [tuple(map(int, input().split())) for _ in range(m)]
        a.sort()
        best = 0
        i = 0
        while i < m:
            w = a[i][0]
            cur = best
            while i < m and a[i][0] == w:
                cur = max(cur, a[i][1])
                i += 1
            if cur > best:
                events.append((w, cur - best))
                best = cur

    events.sort()
    caps = []
    vals = []
    total = 0
    i = 0
    while i < len(events):
        w = events[i][0]
        while i < len(events) and events[i][0] == w:
            total += events[i][1]
            i += 1
        caps.append(w)
        vals.append(total)

    q = int(input())
    ans = []
    for _ in range(q):
        x = int(input())
        p = bisect.bisect_left(vals, x)
        ans.append(str(caps[p]) if p < len(caps) else "-1")

    print(" ".join(ans))

 顧客が同じ重みを持つ複数の契約を持っている場合、アルゴリズムはイベントを作成する前にそれらをグループ化します。 例えば：```

要求された利益が不可能な場合、最終的なプレフィックス利益はクエリよりも小さくなります。 のために：```
