 ## 解決策
 ## 問題の理解

 の棚があります`n`本。 配列`p`現在の棚を説明します: 現在位置にある本`i`ポジションにいたい`p[i]`棚を整理したところ。 目的地はそれぞれ異なるため、`p`の順列です`1..n`。 

訪問者は 2 つの位置を交換するだけなので、各クエリの後に次の 2 つの要素が必要になります。`p`場所を交換します。 このような変更が行われるたびに、正しい順序を復元するために必要な最小限の操作が必要になります。 1 回の操作で、どこからでも 1 冊の本が削除され、棚の先頭または最後尾に配置されます。 

重要な問題は更新の数です。 両方`n`そして`q`到達できる`200000`したがって、交換のたびに答えを再構築することは不可能です。 アン`O(n)`クエリごとの再計算にはすでに約`4 * 10^10`最悪の場合の運用。 各更新は、維持されている情報のごく一部にのみ影響を与える必要があります。 

見落としがちなエッジケースが 2 つあります。 まず、手つかずのままの本は、現在の棚で隣接する必要はありません。 例えば：```
3 0
2 1 3
```答えは`1`。 不注意な解決策を使用すると、配列の連続したセグメントのみを検索し、長く順序付けされた部分が存在しないと結論付ける可能性があります。 位置にある本`1`そして`3`すでにターゲット位置のサブシーケンスを形成しています`2,3`, したがって、最初の本のみを移動する必要があります。 

もう 1 つのよくある間違いは、最も長く保存されているシーケンスはどこで開始または終了してもよいということを忘れていることです。 例えば：```
5 0
5 1 2 3 4
```答えは`1`。 続いて`1,2,3,4`は、配列の 2 番目の位置から始まっているにもかかわらず、すでに正しい相対順序になっています。 最初の位置にある本を移動するだけで十分です。 

## アプローチ

 直接的なアプローチは、仕分けプロセスをシミュレートするか、手つかずのまま残っている本の可能な限りの選択を試すことです。 最初のオプションは、手の数が多くなり、最適な選択を証明するのが難しいため、魅力的ではありません。 2 番目のオプションはさらに悪く、本のサブセットを選択するのは指数関数的です。 

有益な観察は、私たちが動かさない本について説明することから得られます。 本に触れなければ、その相対的な順序は決して変わりません。 何冊かの本を前に移動し、何冊かの本を後ろに移動するとします。 手つかずの本が最後の棚の真ん中を占めています。 したがって、ターゲット位置は連続した間隔の位置である必要があり、現在のシェルフ内で昇順に表示される必要があります。 

したがって、問題は次の最長の部分列を見つけることになります。`p`それは次のようになります:```
x, x + 1, x + 2, ..., x + k - 1
```答えは`n - k`1 冊おきに本を移動する必要があるためです。 

このサブシーケンスを直接保存する代わりに、隣接するターゲット位置を調べます。 させて`pos[v]`最終目的地が次の本の現在の位置になります。`v`。 シーケンス`v, v+1`次の場合に、有効な保持されたサブシーケンスの一部になる可能性があります。```
pos[v] < pos[v+1]
```バイナリ配列を作成する`good`、 どこ`good[v]`この条件が成立する場合に true になります。 からの真の値の連続実行`v`に`v+k-2`目的地のある本を意味します`v`を通して`v+k-1`すでに正しい順序になっています。 したがって、最も長く保持されるサブシーケンスの長さは、`good`、プラス1。 

2 つの棚の位置を交換すると、2 冊の本の位置だけが変更されます。 したがって、これら 2 つの宛先値が関係する比較のみを変更できます。 これにより、この問題は、ポイント更新を伴うセグメント ツリーの最長実行を維持するセグメント ツリーに適したものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | クエリあたり O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 逆順列を構築する`pos`、 どこ`pos[v]`で終わるはずの本の現在の位置です。`v`。 クエリは現在の棚の位置に基づいて書籍を交換するため、逆形式によりどの宛先の値が影響を受けるかをすぐに知ることができます。 
2. バイナリ配列を構築する`good`。 あらゆる人にとって`v`から`1`に`n-1`、保存するかどうか`pos[v] < pos[v+1]`。 正しく順序付けされた連続する宛先の最長のチェーンは、この配列内の最長の連続するセグメントです。 
3.ストア`good`セグメントツリー内。 各ツリー ノードは、1 の最長プレフィックス、1 の最長サフィックス、1 の最長ラン、およびセグメントの全長を保持します。 これら 4 つの値は、2 つの隣接するセグメントをマージするのに十分です。 
4. クエリを処理する前に、セグメント ツリーのルートから最初の応答を計算します。 最も長く実行されるものがある場合、`best`、保持されたサブシーケンスには長さがあります`best + 1`、したがって、必要な動きは次のとおりです。`n - best - 1`。 
5. 棚の位置を交換するクエリの場合`x`そして`y`、現在それらの位置にある本の 2 つの宛先値を見つけます。 シェルフ配列内のこれら 2 つの値を交換し、それらの位置を更新します。`pos`。 
6. のみ`good[value-1]`そして`good[value]`影響を受ける 2 つの宛先値ごとに変更される可能性があります。 これらの位置を再計算し、対応するセグメント ツリー ポイントの更新を実行します。 
7. 更新後、ルートの最長実行を読み取り、新しい回答を出力します。 

これが機能する理由: 移動されない本は、最後の棚のちょうど中央部分を形成する必要があります。 ターゲットのポジションは連続しており、現在の順序はターゲットの順序とすでに一致している必要があります。 バイナリ配列は、そのような保持されたシーケンス内のすべての可能な隣接ペアを表します。 真の値の連続は、まさに最大の保持されたシーケンスです。 セグメント ツリーには常にそのような最長のランが保存されるため、その長さを次の値から差し引きます。`n`移動された本の最小数を示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.pref = [0] * (4 * self.n)
        self.suff = [0] * (4 * self.n)
        self.best = [0] * (4 * self.n)
        self.length = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, node, l, r, arr):
        self.length[node] = r - l + 1
        if l == r:
            val = arr[l]
            self.pref[node] = val
            self.suff[node] = val
            self.best[node] = val
            return
        m = (l + r) // 2
        self.build(node * 2, l, m, arr)
        self.build(node * 2 + 1, m + 1, r, arr)
        self.pull(node)

    def pull(self, node):
        left = node * 2
        right = node * 2 + 1
        llen = self.length[left]
        rlen = self.length[right]

        self.length[node] = llen + rlen
        self.pref[node] = self.pref[left]
        if self.pref[left] == llen:
            self.pref[node] = llen + self.pref[right]

        self.suff[node] = self.suff[right]
        if self.suff[right] == rlen:
            self.suff[node] = rlen + self.suff[left]

        self.best[node] = max(
            self.best[left],
            self.best[right],
            self.suff[left] + self.pref[right]
        )

    def update(self, node, l, r, idx, val):
        if l == r:
            self.pref[node] = val
            self.suff[node] = val
            self.best[node] = val
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(node * 2, l, m, idx, val)
        else:
            self.update(node * 2 + 1, m + 1, r, idx, val)
        self.pull(node)

    def set(self, idx, val):
        self.update(1, 0, self.n - 1, idx, val)

def solve():
    n, q = map(int, input().split())
    p = [0] + list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i in range(1, n + 1):
        pos[p[i]] = i

    good = [0] * (n - 1)
    for i in range(1, n):
        good[i - 1] = 1 if pos[i] < pos[i + 1] else 0

    seg = SegTree(good)

    ans = [str(n - seg.best[1] - 1)]

    def refresh(v):
        if v <= 0 or v >= n:
            return
        seg.set(v - 1, 1 if pos[v] < pos[v + 1] else 0)

    for _ in range(q):
        x, y = map(int, input().split())

        a = p[x]
        b = p[y]

        affected = {a - 1, a, b - 1, b}

        p[x], p[y] = p[y], p[x]
        pos[a], pos[b] = y, x

        for v in affected:
            refresh(v)

        ans.append(str(n - seg.best[1] - 1))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```逆順列は中心的な実装詳細です。 配列`p`「この棚の位置にはどの目的地が含まれますか?」と答えます。`pos`「この目的地は現在どこにありますか?」という質問に答えます。 保持されたシーケンスを拡張するための条件は、当然次のように表現されます。`pos`, そのため、すべてのクエリをローカルで処理できます。 

セグメント ツリーには、答えを直接保存するのではなく、1 の実行に関する情報が保存されます。 2 つの子がマージされる場合、最良のセグメントは完全に左の子の内側にあるか、完全に右の子の内側にあるか、中央を横切っています。 交差ケースは、まさに左の子の接尾辞と右の子の接頭辞を組み合わせたものです。 

クエリの更新順序は重要です。 スワップ後は古い値が元の位置になくなるため、スワップする前に宛先の値が保存されます。 これら 2 つの値の周囲にある 4 つの隣接する比較のみが変更できるため、さらに多くの位置を更新しても時間の無駄になるだけです。 

## 実用的な例

 サンプルの場合:```

```初期状態は次のとおりです。

 | イニシャル | 5 1 2 4 3 |`1<2`、`2<3`本当です | 2 | 2 |

 保管されている本には行き先があります`1,2,3`, そのため、2 冊の本を移動する必要があります。 

ポジション交換後`4`そして`5`:

 | ステップ |`p`|`pos`比較 | 最長実行 | 答え |
 | --- | --- | --- | --- | --- |
 | クエリ 1 | 5 1 2 3 4 |`1<2<3<4`| 3 | 1 |

 ポジション交換後`1`そして`4`:

 | ステップ |`p`|`pos`比較 | 最長実行 | 答え |
 | --- | --- | --- | --- | --- |

 トレースは、隣接する宛先の比較における局所的な変更によってのみ答えが変化することを示しています。 

2 番目の小さな例:```
4 1
1 3 4 2
2 4
```| ステップ |`p`| 最長ラン`good`| 答え |
 | --- | --- | --- | --- |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | ツリーの構築は線形であり、各クエリは一定数のリーフのみを変更します。 |
 | スペース | O(n) | 順列配列とセグメント ツリーは、位置ごとに一定量の情報を保存します。 |

 操作の総数は次のようになります。`n, q <= 200000`なぜなら、すべての更新では対数セグメント ツリー操作がわずか数回しか実行されないからです。

 ## 特殊なケース

 有効な保持シーケンスが現在のシェルフ内で連続していない場合でも、アルゴリズムは配列間隔を検索しないため、引き続き機能します。 のために：```
3 0
2 1 3
```逆の位置は`pos[1]=2`、`pos[2]=1`、`pos[3]=3`。 唯一の本当の比較は、`pos[2] < pos[3]`、1 つのエッジの最長ランと長さ 2 の維持されたシーケンスが得られます。 答えは次のようになります`3 - 2 = 1`。 

保持されたシーケンスが配列の境界から離れて開始または終了する場合、バイナリ表現はそれを自然に処理します。 のために：```
5 0
5 1 2 3 4
```価値観`1,2,3,4`出現位置が増加するため、真の比較の実行の長さは 3 になります。 答えは`5 - (3 + 1) = 1`、目的地が記載された本のみを意味します`1`移動する必要があります。 

境界近くのスワップは、無効な比較にアクセスしてはなりません。 たとえば、宛先の値が`1`位置を変えるだけ`good[1]`がないので更新できます`good[0]`。 の`refresh`関数は外部の値を無視します`1..n-1`、これらのオフバイワンエラーを防ぎます。
