 ## 解決策
 ## 問題の理解

 花の数の配列 (A_1,\ldots,A_N) があります。 タイプ 1 の操作は、間隔 ([l,r]) を選択し、それに階段を追加します。 位置 (l) は (1) を受け取り、位置 (l+1) は (2) を受け取り、一般に位置 (i) は (i-l+1) を受け取ります。 タイプ 2 の演算は、一定の間隔 ([u,v]) で現在の配列の合計を求めます。 

操作は順番に処理されるため、すべてのクエリで以前に発生したすべての更新を参照する必要があります。 タスクは、タイプ 2 のすべての操作の答えを出力することです。 

最大のテストには、(10^5) 個の位置と (10^5) 個の演算を含めることができ、最大 4 つのテスト ケースが含まれます。 (O(NQ)) ソリューションは、最悪の場合でも約 (10^{10}) 個の基本配列演算を実行できますが、これは 2 秒の制限をはるかに超えています。 ここでは (O(N+Q\sqrt N)) であっても不必要に高価になります。 各操作にはおよそ (O(\log N)) 時間がかかる必要があります。 

一見正しい実装が失敗する可能性がある境界ケースがいくつかあります。 まず、更新には 1 つの位置だけを含めることができます。 例えば、```
1
1
0
2
1 1 1
2 1 1
```生成する```
1
```アップデートで追加されるのは(1)だけだからです。 (l<r) かどうかをチェックせずに、常に (l+1) に 2 番目の差を挿入する式は、状態を破壊する可能性があります。 

更新は配列の最後の位置に到達することもあります。 例えば、```
1
3
0 0 0
2
1 2 3
2 1 3
```生成する```
6
```追加された値は位置 (2,3) に (1,2) であるため、配列 ([0,1,2]) になります。 内部表現では位置 (r+1=4) を使用できますが、その位置は配列に属さず、終端の差としてのみ機能する必要があります。 フェンウィック ツリーの割り当てが狭すぎるか、この境界で不適切にクエリを実行すると、off-by-one エラーが発生する可能性があります。 

クエリは更新の一部のみをカバーする場合があります。 例えば、```
1
5
0 0 0 0 0
2
1 2 5
2 3 4
```生成する```
5
```更新によって ([0,1,2,3,4]) が作成され、位置 (3,4) の合計が (5) になるためです。 階段を一定範囲の加算として扱うと、誤って (2+2=4) が得られます。 

最後に、いくつかの更新が重複する可能性があります。 例えば、```
1
4
0 0 0 0
3
1 1 3
1 2 4
2 2 3
```生成する```
5
```最初の更新では ([1,2,3,0]) が追加され、2 番目の更新では ([0,1,2,3]) が追加されるため、位置 (2,3) には (3,5) が含まれます。 すべての更新は、最終的な合計に独立して貢献する必要があります。 

## アプローチ

 直接的な解決策は、(l) から (r) までのすべての (i) を訪問し、(i-l+1) を (A_i) に加算することによってタイプ 1 の演算を処理することです。 タイプ 2 の操作は、プレフィックスサム構造を使用して、または単に要求された間隔をスキャンすることによって応答できます。 すべての更新は、記述されている位置に正確に適用されるため、これは正しいです。 

問題は、更新によって影響を受けるポジションの数です。 (N=Q=10^5) の場合、配列のほぼ全体をカバーする (10^5) 回の更新が可能になります。 1 回の更新には (10^5) 回の追加が必要になる可能性があり、最悪の場合はおよそ (10^{10}) 回の演算が行われます。 2 秒の制限により、これは排除されます。 

有益な観察は、更新によって追加される値は任意ではないということです。 ([l,r]) では、

 [
 i-l+1=i+(1-l)。 
]

 したがって、更新ごとに位置インデックスの一次関数が追加されます。 具体的には、(i) の位置の加算値を次のように書くと、

 [
 f(i)=ai+b、
 ]

 次に、ここでは (a=1) と (b=1-l) です。 

実際には、影響を受けるすべての値を保存する必要はありません。 代わりに、すべての更新によってもたらされた値の差分配列を考慮してください。 ([l,r]) 上の 1 つの線形更新 (f(i)=ai+b) の場合、その差分配列には 3 つの変更しかありません。 (l) では (f(l)) から始めます。 (l) と (r) の間では、連続する値が (a) ずつ増加するため、(l+1) で (a) を追加します。 (r+1) で (f(r)) を減算し、更新を終了します。 

この特定の問題では、(a=1) および (b=1-l) なので、

 [
 f(l)=1
 ]

 そして

 [
 f(r)=r-l+1。 
]

 したがって、1 つの更新は、差分配列内の一定数の点変化によってのみ表現できます。 

残りの問題は、これらの差の変化から範囲の合計を効率的に回復する方法です。 (D_j) が差分配列の場合、位置 (i) の値は次のようになります。 

[
 X_i=\sum_{j\le i}D_j。 
]

 したがって、(x) を介したプレフィックスの合計は次のようになります。 

\sum_{j=1}^{x}D_j(x-j+1)。 
]

 並べ替えると、

 (x+1)\sum_{j=1}^{x}D_j-\sum_{j=1}^{x}jD_j。 
]

 これは、(\sum D_j) と (\sum jD_j) の 2 つのプレフィックス量だけが必要であることを意味します。 2 つのフェンウィック ツリーは、(O(\log N)) の点変化の下でこれらの量を維持できます。 

元の配列をこれらのフェンウィック ツリーに挿入する必要はありません。 通常のプレフィックスの合計を 1 回事前計算し、クエリに答えるときに、後続のすべての階段更新の寄与を追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(NQ)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N+Q\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期の花数の通常のプレフィックス合計配列を計算します。 (P[x]) を位置 (1) から (x) までの初期値の合計とします。 ([u,v]) に対するクエリは、その初期寄与を (P[v]-P[u-1]) として取得できます。 
2. 2 本のフェンウィックの木を維持します。 1 つ目は点の変更を差分配列 (D) に保存し、2 つ目は同じ変更に位置を掛け合わせたものを保存します。 位置 (p) で (d) の差分変化が発生した場合、(d) を最初のツリーに追加し、(p d) を 2 番目のツリーに追加します。 
3. 更新 ([l,r]) の場合、加算される値は (f(i)=i-l+1) です。 位置 (l) では、差分配列は (f(l)=1) だけ増加する必要があるため、(l) で (+1) を追加します。 (l<r) の場合、連続する値は (1) ずつ増加するため、(l+1) で (+1) を加算します。 (r+1) で、最終値を減算します (f(r)=r-l+1)。 結果として生じる差分の変更は、この更新によって追加された階段を正確に表しています。 
4. プレフィックス ([1,x]) に対するすべての更新の寄与を計算するには、次の式を取得します。 

[
 S_D=\sum_{j\le x}D_j
 ]

 最初のフェンウィックの木から、

 [
 S_{jD}=\sum_{j\le x}jD_j
 ]

 2枚目から。 動的プレフィックスの合計は次のとおりです。 

[
 (x+1)S_D-S_{jD}。 
]

 この式は、各差分値が含まれるプレフィックス位置の数を数えることから直接得られます。 位置 (j) に導入された差は、位置 (j,j+1,\ldots,x)、つまり正確に (x-j+1) の位置に影響します。

1. タイプ 2 クエリ ([u,v]) の場合、(v) を通じて動的プレフィックス合計を計算し、(u-1) を通じて動的プレフィックス合計を減算します。 対応する初期プレフィックス合計の差を加算します。 これにより、([u,v]) の完全な現在の合計が得られます。 
2. すべての操作を入力順に処理します。 更新は 2 つのフェンウィック ツリーを即座に変更しますが、クエリはそれらを読み取るだけなので、すべてのクエリは自動的にその前の更新を正確に認識します。 

### なぜ効果があるのか

 不変条件は、2 つのフェンウィック ツリーが、処理されたタイプ 1 操作によって生じたすべての花の寄与の差分配列を表すということです。 更新ごとに、3 つの差分変更により、([l,r]) 上のシーケンス (1,2,\ldots,r-l+1) とその外側のゼロが再構築されます。 差分配列は線形に加算されるため、重複する更新は差分の変更を加算することによって正しく表現されます。 

(x) で終わる接頭辞の場合、すべての違い (D_j) が (j) から (x) までの位置に寄与し、花の合計は (D_j(x-j+1)) になります。 アイデンティティ

 (x+1)\sum_{j\le x}D_j-\sum_{j\le x}jD_j
 ]

 したがって、正確な動的プレフィックス合計が回復されます。 2 つのプレフィックスを減算すると、正確な動的間隔の合計が得られ、変更されていない初期プレフィックスの合計を加算すると、現在の配列の合計が得られます。 したがって、タイプ 2 のすべての答えは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    __slots__ = ("n", "bit")

    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, value):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += value
            idx += idx & -idx

    def sum(self, idx):
        bit = self.bit
        res = 0
        while idx > 0:
            res += bit[idx]
            idx -= idx & -idx
        return res

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        prefix = [0] * (n + 1)
        for i, value in enumerate(a, 1):
            prefix[i] = prefix[i - 1] + value

        # One tree stores D[j].
        # The other stores j * D[j].
        bit_d = Fenwick(n + 1)
        bit_jd = Fenwick(n + 1)

        def add_difference(pos, delta):
            if pos > n + 1:
                return
            bit_d.add(pos, delta)
            bit_jd.add(pos, pos * delta)

        def dynamic_prefix(x):
            if x <= 0:
                return 0
            sum_d = bit_d.sum(x)
            sum_jd = bit_jd.sum(x)
            return (x + 1) * sum_d - sum_jd

        q = int(input())

        for _ in range(q):
            query = list(map(int, input().split()))
            typ, x, y = query

            if typ == 1:
                l, r = x, y

                # f(i) = i - l + 1
                # At l: start with f(l) = 1.
                add_difference(l, 1)

                # From l+1 through r, consecutive values differ by 1.
                if l < r:
                    add_difference(l + 1, 1)

                # At r+1, terminate the staircase.
                add_difference(r + 1, -(r - l + 1))

            else:
                u, v = x, y

                initial = prefix[v] - prefix[u - 1]
                dynamic = dynamic_prefix(v) - dynamic_prefix(u - 1)

                out.append(str(initial + dynamic))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`prefix`配列は最初の花を個別に処理します。 初期値は決して変更されないため、Fenwick 構造体に初期値を表す理由がないため、これは便利です。`bit_d`(D_j) を表しますが、`bit_jd`(jD_j)を表します。 ヘルパーさん`add_difference`両方の構造を一緒に更新することで、2 つの表現が同期しなくなるのを防ぎます。 

更新 ([l,r]) の場合、最初の変更は常に`+1`で`l`。 ２つ目の変化も、`+1`、しかしそのときだけ`l < r`。 この条件は 1 要素の更新には不可欠です。 最終的な変更は次の場所に配置されます。`r + 1`と等しい`-(r-l+1)`。 フェンウィックの木には大きさがある`n + 1`具体的には、この最終的な差異を保存できるようにするためです。`r = n`。 

の`dynamic_prefix`関数の実装

 [
 (x+1)\sum_{j\le x}D_j-\sum_{j\le x}jD_j。 
]

いつ`x`がゼロの場合、答えはすぐにゼロになります。これにより、位置 (1) から始まるクエリは安全になります。`dynamic_prefix(0)`。 

Python の整数には任意の精度があるため、潜在的に大きな花の数がオーバーフローすることはありません。 可能な最大の合計は、32 ビット整数の範囲を大幅に超える可能性があります。 

各 Fenwick 操作は対数的であり、更新ごとに一定数の操作が実行されます。 クエリは、エンドポイントごとに 1 つずつ、計 2 つのプレフィックス計算を実行します。 結果として得られる実装では、潜在的に膨大な更新間隔自体に触れることが回避されます。

import sys
import io

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, value):
        while idx <= self.n:
            self.bit[idx] += value
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        while idx:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

def solve_io():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        prefix = [0] * (n + 1)
        for i, value in enumerate(a, 1):
            prefix[i] = prefix[i - 1] + value

        bit_d = Fenwick(n + 1)
        bit_jd = Fenwick(n + 1)

        def add_difference(pos, delta):
            bit_d.add(pos, delta)
            bit_jd.add(pos, pos * delta)

        def dynamic_prefix(x):
            if x <= 0:
                return 0
            sd = bit_d.sum(x)
            sjd = bit_jd.sum(x)
            return (x + 1) * sd - sjd

        q = int(input())

        for _ in range(q):
            typ, x, y = map(int, input().split())

            if typ == 1:
                l, r = x, y
                add_difference(l, 1)
                if l < r:
                    add_difference(l + 1, 1)
                add_difference(r + 1, -(r - l + 1))
            else:
                u, v = x, y
                ans = (
                    prefix[v] - prefix[u - 1]
                    + dynamic_prefix(v)
                    - dynamic_prefix(u - 1)
                )
                out.append(str(ans))

    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve_io()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 1 要素の更新については、次のことを考慮してください。```
1
1
0
2
1 1 1
2 1 1
```更新は (f(1)=1) です。 アルゴリズムは追加します`+1`位置 (1) の差分配列に代入し、`-1`(2)の位置にあります。 2 番目の変更はフェンウィック ツリーに保存されますが、クエリされたプレフィックスの外にあります。 したがって、位置 (1) を通る接頭辞は (1) となり、出力は次のようになります。`1`。 (l+1) で中間変化が欠落しているのは、階段には 2 番目の位置がないため、意図的です。 

最終位置で終了する更新については、次のことを考慮してください。```
1
3
0 0 0
2
1 2 3
2 1 3
```更新により (1,2) が位置 (2,3) に追加されます。 その違いの変化は、`+1`(2)では、`+1`(3)で、そして`-2`(4)で。 フェンウィック ツリーのサイズは (N+1) であるため、位置 (4) は終了する差分を保持できます。 (3) までのプレフィックスはその終了を無視して (3) を与えるため、期待される出力は実際には次のようになります。`3`。 

更新の一部のみをカバーするクエリの場合は、次のことを考慮してください。```
1
5
0 0 0 0 0
2

2 3 4
```更新により ([0,1,2,3,4]) が生成されます。 (4) までのプレフィックスは (6) ですが、(2) までのプレフィックスは (1) であるため、要求された合計は (6-1=5) になります。 動的プレフィックス式は、間隔内の個々の値がわからなくても機能します。 

更新が重複する場合は、次の点を考慮してください。```
1
4
0 0 0 0
3
1 1 3
1 2 4
2 2 3
```最初の更新は ([1,2,3,0]) に寄与し、2 番目の更新は ([0,1,2,3]) に寄与します。 それらの合計は ([1,3,5,3]) であるため、位置 (2,3) には (3+5=8) が含まれます。 差分表現では、両方の更新による差分変更が単純に加算され、まったく同じ結合配列が生成されます。 

最大サイズの場合には、別の実際的な境界が適用されます。 (N=Q=10^5) の場合、各更新がすべて (N) 個の位置を訪問する場合、配列全体を繰り返し更新することは不可能になります。 フェンウィック表現は更新ごとに一定数の位置のみを操作するため、操作の数は (O(NQ)) ではなく (O(Q\log N)) として増加します。 Python の任意精度の整数は、(2^{31}-1) よりもはるかに大きくなる可能性がある結果の合計も安全に処理します。
