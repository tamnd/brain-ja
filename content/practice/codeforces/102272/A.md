 ## 解決策
 ## 問題の理解

 長方形のカロムテーブルがあります。その左下隅は`(0, 0)`そして右上隅は`(N, M)`。 ボールは整数の位置から始まります`(x0, y0)`テーブル内を一定速度で移動`(vx, vy)`。 垂直の壁に到達するたびに、`vx`変化します。 水平の壁に到達するたびに、`vy`変化します。 コーナーに到達すると、両方の標識が変わるだけです。 

タスクは、ボールの正確な位置を見つけることです。`S`秒。 整数の場合、位置は整数であることが保証されます`S`ただし、モーションを直接シミュレートするのはコストがかかりすぎます。 

次元、速度、時間はすべて次のように大きくすることができます。`10^9`、最大までありますが、`10^4`テストケース。 1 秒あたり 1 つの操作を実行するシミュレーションでは、`10^9`単一のケースの反復回数および最大`10^13`入力全体にわたる反復。 それは1秒の制限時間に収まりきらない。 実行時間が依存しない式が必要です。`S`。 

2 つの座標も独立しています。 垂直の壁は X 座標のみに影響し、水平の壁は Y 座標のみに影響します。 これにより、1 次元の問題を解決し、それを 2 回適用することができます。 

いくつかの境界ケースにより、単純な実装が間違っている可能性があります。 インプットを考慮する```
1
5 4 2 1 3 0 1
```1 秒後、x 座標は正確に`5`、したがって、答えは次のとおりです`(5, 1)`。 座標が以上になるとすぐに反映する不用意な実装`N`誤ってボールを元に戻す可能性があります`0`またはへ`2`反射がどのようにコーディングされているかに応じて異なります。 壁自体は有効な位置であるため、反射三角波の公式は正確に許容する必要があります。`N`。 

2 番目の問題は負の速度です。 のために```
1
5 4 2 1 -3 0 1
```ボールが届く`x = -1`展開した写真で。 実際の位置は`1`、したがって、答えは次のとおりです`(1, 1)`。 言語`%`負の剰余を保持するには特別な処理が必要ですが、Python のモジュロはすでに非負の剰余を返します。 

両方の座標で同時にコーナーに到達することができます。 例えば、```
1
3 5 2 4 1 1 1
```ボールを～に移動します`(3, 5)`、ちょうど右上隅です。 正しい出力は次のとおりです```
3 5
```境界を検出してすぐに反映する方式では、誤った出力が行われる可能性があります。`(2, 4)`要求された時間のために。 正確な衝突時の位置は依然としてコーナーです。 

最後に、1 つの速度成分がゼロになる可能性があります。 のために```
1
7 6 3 4 0 0 1000000000
```ボールは決して動かないので、答えは簡単です。`(3, 4)`。 速度で除算するか壁衝突のカウントに基づく式はこのケースを明示的に処理する必要がありますが、展開式は特別な数学的処理を行わなくても機能します。 

## アプローチ

 最も直接的な解決策は、一度に 1 秒ずつボールをシミュレートすることです。 毎秒追加します`(vx, vy)`現在の位置に。 X 座標が間隔を離れる場合`[0, N]`、それを反射して反転します`vx`; 同様に、y 座標を反映して反転します。`vy`。 これはテーブルの物理規則に正確に従っているため、これは正しいです。 

問題は反復回数です。 と`S = 10^9`、1 つのテスト ケースで必要となるのは、`10^9`シミュレーションの手順。 と`10^4`テストケース、理論上の最悪のケースは`10^13`ステップ。 各ステップに含まれる整数演算が数個しかないとしても、それは 1 秒の制限をはるかに超えています。 

重要な観察は、バウンス座標は単なる周期的な三角波であるということです。 X 座標のみを考慮してください。 テーブルの幅が`N`、壁を取り除き、ボールを無限に継続できるようにすることを想像してください。 展開後の座標`S`秒は`u = x0 + vx * S`。 

実際のテーブルは、この無限の直線を長さの間隔ごとに折り返すことによって再構築できます。`N`。 パターンは毎回繰り返されます`2N`: 座標の移動元`0`に`N`、から戻ってきます`N`に`0`と繰り返します。 

したがって、必要なのは`r = u mod (2N)`。 

もし`r <= N`、実際の x 座標は次のとおりです。`r`。 もし`r > N`、座標は`2N - r`。 同じ計算により、周期を使用して独立して y 座標が得られます。`2M`。 

これにより、シミュレーションが完全に不要になります。 大きな値`S`と速度は整数演算で処理され、壁衝突の回数をカウントする必要はありません。

 | --- | --- | --- | --- |
 | ブルートフォース |`O(S)`テストケースごと |`O(1)`| 遅すぎる |
 | 最適 |`O(1)`テストケースごと |`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`N`、`M`、初期位置`(x0, y0)`、速度`(vx, vy)`、および要求された時間`S`。 垂直方向の衝突では y コンポーネントが変更されず、水平方向の衝突でも x コンポーネントは決して変更されないため、x モーションと y モーションは独立して処理できます。 
2. x 座標について、展開された位置を計算します。`u = x0 + vx * S`。 これは、垂直の壁がまったくなかった場合にボールがどこにあるかを表します。 
3.減らす`u`モジュロ`2N`、取得`r`。 間隔`[0, 2N]`x 座標の 1 つの完全な前後サイクルを記述します。 剰余の縮小`2N`テーブル内の最終位置を変更せずに、すべての完全なサイクルを削除します。 
4.変換`r`三角波ルールを使用してテーブルに戻ります。 もし`r <= N`、座標は`r`、これはサイクルの前半だからです。 それ以外の場合、座標は`2N - r`、後半はゼロに向かって戻っているからです。 
5. まったく同じ計算を y に適用し、次のように置き換えます。`x0`、`vx`、 そして`N`と`y0`、`vy`、 そして`M`。 
6. 結果を印刷します。`(x, y)`。 両方の座標が同じ絶対時間で計算されるため、`S`、同時コーナー衝突は自然に処理されます。 コーナーでは、両方の三角波がそれぞれの境界に正確に位置します。 

### なぜ効果があるのか

 1 つの座標については、テーブルを展開するとすべての反射が除去されます。 ボールは単純な一次方程式に従います`x0 + vx*S`。 この行を折り返すと、`[0, N]`最初の区間の長さはすべての反射を再現します。`N`は右の壁に向かう動きに対応し、2 番目の間隔は左の壁に向かう反射された動きに対応します。 完全なパターンには期間があります`2N`、つまりモジュロを取る`2N`情報を失いません。 同じ引数が y に独立して適用されます。 その結果、再構築された 2 つの座標は、正確にボールの位置になります。`S`秒。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reflected_position(start, velocity, length, time):
    period = 2 * length
    r = (start + velocity * time) % period

    if r <= length:
        return r
    return period - r

def solve():
    t = int(input())

    for _ in range(t):
        N, M, x0, y0, vx, vy, S = map(int, input().split())

        x = reflected_position(x0, vx, N, S)
        y = reflected_position(y0, vy, M, S)

        print(x, y)

if __name__ == "__main__":
    solve()
```の`reflected_position`関数には 1 次元の解全体が含まれています。`start + velocity * time`は展開された位置を計算し、モジュロ演算によりそれをバウンス モーションの 1 周期に圧縮します。 

期間は`2 * length`、 ない`length`。 座標はかかります`length`ある壁から別の壁、さらに別の壁まで移動するための展開距離の単位`length`ユニットは開始壁に戻ります。 のみを使用する`length`これは、ピリオドが右の壁に向かう途中の点と、戻る途中の対応する点を誤って識別してしまうためです。 

比較`r <= length`も意図的です。 いつ`r == length`、ボールは正確に壁上にあり、それは要求された時点で有効な位置です。 より厳密に大きい値のみ`length`サイクルの反映された半分に属します。 

Python のモジュロ演算は、負の速度の場合に特に便利です。 たとえば、展開された座標が`-1`そしてその期間は`10`、Pythonは評価します`-1 % 10`として`9`、これはまさに現在の期間の同等のポイントです。 

Python では整数オーバーフローの危険はありません。 最大の製品は次のとおりです`10^18`、Python 整数が直接処理します。 固定幅言語では、十分な幅の整数型が必要になります。`velocity * S`。

 ## 特殊なケース

 壁に正確に着地したボールは、要求された位置が報告されるまで反射されてはなりません。 のために```
1
5 4 2 1 3 0 1
```展開された x 座標は`5`、期間は`10`。 以来`5 <= 5`、反映された座標はまだです`5`。 出力は`5 1`。 条件は次のとおりです。`r <= length`、 ない`r < length`。 

負の速度も同じ式で処理されます。 のために```
1
5 4 2 1 -3 0 1
```展開された x 座標は`-1`。 その剰余モジュロ`10`は`9`、そしてなぜなら`9 > 5`、実際の座標は`10 - 9 = 1`。 出力は`1 1`。 左側の壁に向かって移動する別のシミュレーションは必要ありません。 

コーナー衝突は、両方の座標が同時に上限に達することによって自動的に表されます。 のために```
1
3 5 2 4 1 1 1
```展開された座標は`3`そして`5`。 彼らの生理期間は、`6`そして`10`、両方の剰余はそれぞれのテーブルの長さに等しくなります。 結果はまさに`3 5`。 壁に到達した直後に計算が反映されるとすると、要求された位置ではなく、次の瞬間の位置が返されることになります。 

ゼロ速度コンポーネントには、メイン アルゴリズムに特別な分岐は必要ありません。 のために```
1
7 6 3 4 0 0 1000000000
```展開された座標は残ります`3`そして`4`時間に関係なく。 対応するモジュロを取得して折り畳むと、それらは変更されず、次のようになります。`3 4`。 これが、速度で割ろうとする衝突カウント式よりも展開座標式の方が好ましい理由の 1 つです。 

最大値については、算術にも注意が必要です。 速度と時間の両方を考慮して`10^9`、彼らの製品は到達することができます`10^18`。 Python はこれを正確に処理するため、式は`start + velocity * time`安全です。 32 ビット整数を使用する言語では、同じ式がオーバーフローするため、64 ビット整数型が必要になります。
