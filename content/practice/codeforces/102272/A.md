 ## 解決策
 ## 問題の理解

 水平範囲が (x=0) から (x=N) で、垂直範囲が (y=0) から (y=M) である長方形の carom テーブルがあります。 ボールは、厳密に長方形内の整数位置 ((x_0,y_0)) から始まります。 毎秒、現在の速度ベクトル ((v_x,v_y)) だけ移動します。 垂直の壁に到達すると、(v_x) の符号が変わります。 水平な壁に到達すると、(v_y)の符号が変わります。 コーナーにぶつかると両方のサインが変わります。 

タスクは、(S) 秒後のボールの正確な整数位置を見つけることです。 入力には最大 (10^4) 個の独立したシミュレーションが含まれます。 テーブルの寸法、座標、速度、時間はすべて (10^9) までの大きさになる可能性があります。 

(S) の値が大きいと、一度に 1 秒ずつモーションをシミュレートできなくなります。 単一のテスト ケースには (10^9) 個の更新が必要になる可能性があり、(10^4) 個のテスト ケース全体では (10^{13}) 個の更新が必要になります。 シミュレートされた 1 秒あたりの作業量が非常に少ない場合でも、制限時間 1 秒をはるかに超えてしまいます。 コストが (S) に線形的に依存しない計算が必要です。 

最も有益な構造上の事実は、水平方向と垂直方向の動きが独立していることです。 垂直の壁は (v_x) のみ変化し、水平の壁は (v_y) のみ変化します。 ([0,N]) と ([0,M]) 上の 1 次元の動きを個別に解決し、その後 2 つの座標を組み合わせることができます。 

単純な実装では間違いが明らかになる可能性のある境界ケースがいくつかあります。 まず、速度は負の値になる可能性があります。 たとえば、```
1
5 5 2 2 -3 0 1
```正しい位置は```
4 2
```なぜなら、ボールは (x=2) から (x=-1) に移動し、(x=0) で壁に到達し、実際の連続軌道が壁に到達した後でのみ (x=1) に反射するからです。 要求された位置は時間 (1) にあるため、正しい解釈は展開された軌道 (2-3=-1) によって得られ、その反映位置は (1) です。 負の値を正規化せずに通常の剰余を使用する数式は、負の座標を生成する可能性があります。 

2 番目のトラップは、要求された時刻に正確に壁に到達します。 考慮する```
1
2 3 1 1 1 2 1
```時刻 (1) では、ボールはちょうど右上隅にあるので、答えは次のようになります。```
2 3
```衝突後に速度は変化しますが、要求された時間より前にボールがコーナーから離れることはありません。 エンドポイントを見つけるとすぐに反映し、すぐに別の動作を適用する実装では、off-by-one エラーが発生する可能性があります。 

3 番目のケースはコーナー衝突です。 のために```
1
2 3 1 2 1 1 1
```ボールは ((2,3)) に到達するため、出力は次のようになります。```
2 3
```どちらの座標も独自の反射ルールを使用する必要があります。 コーナーを 1 つの壁衝突のみとして扱うと、1 つの速度コンポーネントの方向が間違ったままになり、後のクエリで表示されるようになります。 

最後に、速度ゼロはどちらの座標でも有効です。 例えば、```
1
2 2 1 1 0 1 3
```出力があります```
1 2
```水平座標は決して変化しないのに対し、垂直座標は最初の 1 秒で (2) に達し、その後反映されるためです。 

## アプローチ

 直接シミュレーションは物理的記述に正確に従います。 ((x_0,y_0)) から始めて、1 秒ごとに ((v_x,v_y)) を加算します。 座標が 2 つの境界のいずれかに到達すると、対応する速度成分が反転されます。 ビリヤード モデルとまったく同じトランジションを実行するため、これは正しいです。 

問題は反復回数です。 最悪のケース (S=10^9) では、1 つのテスト ケースに (10^9) 秒のシミュレーションが必要になる可能性があります。 (T=10^4) の場合、理論上の合計反復回数は (10^{13}) 回に達します。 シミュレーションは正しいですが、基本的に制約と互換性がありません。 

重要な観察は、反射された 1 次元の軌道が直線に展開される可能性があるということです。 間隔 ([0,N]) を無限のコピーのシーケンスで置き換えることを想像してください。 

[
 [0,N]、[N,2N]、[2N,3N]、\ldots
 ]

 そしてそれらを交互の向きで続けます。 ボールは壁に反射するのではなく、境界を通って次のコピーに向かってまっすぐに移動し続けます。 その直線軌道を元の間隔に折り返すと、まったく同じ物理位置が得られます。 

(S) 秒後の展開された水平座標は単純に次のようになります。 

[
 p_x=x_0+v_xS。 
]

 実際のテーブル座標は、(p_x) が長さ (2N) の期間内のどこにあるかによってのみ決まります。 定義する

 [
 r_x=p_x\bmod 2N。 
]

 (0\le r_x\le N) の場合、折り畳まれた位置は (r_x) になります。 (N<r_x<2N) の場合、(2N-r_x) となります。 これにより、跳ね返るパーティクルのおなじみの三角波が作成されます。 

垂直座標は(M)と全く同じ形になります。 これにより、シミュレーション全体がいくつかの整数の加算、モジュロ演算、比較に減ります。 Python のモジュロ演算はすでに正の係数の範囲 ([0,2N-1]) の値を返すため、負の速度には特別な物理的なケースは必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(S)) テスト ケースごと | (O(1)) | 遅すぎる |
 | 最適 | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 展開後の水平位置を計算します (p_x=x_0+v_xS)。 展開モデルではボールがすべての壁を直線的に通過し続けるため、ここでは反射を意図的に無視します。 
2. (p_x) モジュロ (2N) を減算し、(r_x=p_x\bmod 2N) を取得します。 一方の壁からもう一方の壁へ、また戻ってくるまでの完全な往復移動の長さは (2N) であるため、(2N) だけ離れた位置は同じ物理座標に折り畳まれます。 
3. (r_x) をテーブルに折り込みます。 (r_x\le N) の場合、物理座標は (r_x) です。 それ以外の場合、軌道は周期の鏡映された半分にあるため、物理座標は (2N-r_x) になります。 
4. (p_y=y_0+v_yS)、周期 (2M)、および折り曲げ境界 (M) を使用して、同じ計算を垂直方向に実行します。 
5. 結果の (x) 座標と (y) 座標を出力します。 2 つの次元は独立しているため、個別に計算された位置がボールの最終的な位置を形成します。 

### なぜ効果があるのか

 水平座標のみを考慮してください。 実際のテーブルでは、(x=0) または (x=N) と衝突するたびに水平速度が逆転します。 展開された表現では、速度を逆転させる代わりに、テーブルの反射コピーに進みます。 これらのコピーを ([0,N]) に折り返すと、実際のボールが壁にぶつかるときとまったく同じときに、見かけの方向が反転します。 反射の 1 つの完全なペアは (2N) の距離に対応するため、展開された座標を (2N) を法としてとると、現在の物理的位置を決定するために必要なすべての情報が保存されます。 同じ引数が (y) に独立して適用されます。 したがって、折り畳まれた 2 つの座標は、(S) 秒後の実際のボールの正確な位置になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def position(start, velocity, length, seconds):
    unfolded = start + velocity * seconds
    period = 2 * length
    r = unfolded % period

    if r <= length:
        return r
    return period - r

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m, x0, y0, vx, vy, s = map(int, input().split())

        x = position(x0, vx, n, s)
        y = position(y0, vy, m, s)

        out.append(f"{x} {y}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`position`関数には、1 次元リフレクション ロジック全体が含まれています。 最初に、(S) 秒後に展開された座標を構築します。 すべての衝突は周期的な折り畳み操作によって表されるため、個々の衝突をシミュレートする必要はありません。 

モジュロ除数はテーブル長そのものではなく、テーブル長の 2 倍です。 (N) を使用すると、到達 (x=0) と到達 (x=N) は軌道の異なる点であるため、2 つの移動方向が誤って識別されます。 

条件`r <= length`正確な壁の位置が含まれます。 要求された時間にボールが正確に壁に当たる可能性があるため、これは重要です。 その瞬間、衝突後に起こる速度の反転に関係なく、その位置は依然として壁の座標です。 

Python の整数には任意の精度があるため、(v_xS) などの積はオーバーフローしません。 固定幅の整数型を使用する言語では、積がおよそ (10^{18}) に達する可能性があるため、64 ビット整数を使用する必要があります。 

負の速度には別の分岐は必要ありません。 たとえば、展開された座標が (-1) で周期が (10) の場合、Python は (-1\bmod 10=9) を計算します。 (9) を折りたたむと、(10-9=1) が得られます。これは、点 (-1) を (x=0) に反映することによって得られる物理位置とまったく同じです。

 ## 特殊なケース

 最初の注意が必要なケースは、負の速度です。 のために```
1
5 5 2 2 -3 0 1
```展開された水平座標は (2-3=-1) です。 期間 (10) の場合、正規化された剰余は (9) になります。 (9>5) なので、折り畳まれた座標は (10-9=1) になります。 (2)では垂直座標は変化しないので、答えは次のようになります。`1 2`。 負の速度に対する特別な分岐は必要ありません。 

2 番目のケースは、要求された時刻にちょうど壁に到達した場合です。 のために```
1
2 3 1 1 1 2 1
```展開された座標は (2) と (3) です。 それらの剰余も (2) と (3) であり、どちらもそれぞれのテーブルの長さに等しいです。 折りたたみ状態を使用しているため、`<=`、結果はまさに`2 3`。 速度の反転は、衝突の瞬間の位置ではなく、その後の動きに影響します。 

3 番目のケースはコーナー衝突です。```
1
2 3 1 2 1 1 1
```展開された両方の座標は同時に最大値に達します。 水平方向の結果は (2)、垂直方向の結果は (3) となり、次のようになります。`2 3`。 各座標は独立して処理されるため、実装に特別なコーナーケースは必要ありません。 両方の速度成分は、それぞれの三角波公式によって暗黙的に反映されます。 

4 番目のケースは速度がゼロです。```
1
2 2 1 1 0 1 3
```(x) の場合、展開された座標は (1) のままであるため、水平方向の結果は常に (1) になります。 (y) の場合、展開された座標は (4)、周期は (4) となり、剰余は (0) になります。 したがって、垂直方向の結果は (0) となるため、正確な出力は次のようになります。`1 0`。 これは、速度ゼロが特別な処理を必要としない理由を示していますが、要求された時点でボールが境界上にある可能性があることも示しています。 

バグの最後の原因は、テーブルの長さと完全な反映期間を混同することです。 幅 (5) のテーブルの場合、1 つの水平サイクル内の位置のシーケンスは次の形式になります。 

[
 0、1、2、3、4、5、4、3、2、1、0。 
]

 サイクル長は (10=2N) です。 実装がモジュロ (N) を削減すると、復路から往路に位置が誤ってマッピングされ、反射によってエンコードされた方向情報が失われます。
