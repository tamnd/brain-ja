 ## 問題の理解

 異なる整数のペアを数えるように求められます$a$そして$b$と$1 \le a < b \le n$、そのペアにはちょうど 2 つの公約数があります。 

両方を割ることが保証されている唯一の数値$a$そして$b$は最大公約数の約数です。 したがって、条件は実際には次の構造に関するものです。$\gcd(a,b)$。 gcd にちょうど 2 つの正の約数がある場合、ペアは有効です。 

数値が素数の場合にのみ、正の約数が 2 つだけ含まれます。 したがって、条件は次のようになります: ペアを数えます$a < b$そのような$\gcd(a,b)$は素数です。 

入力は単一の整数を与えます$n$、範囲内のペアの数を数えなければなりません$[1,n]$この gcd 条件を満たします。 

制約$n \le 10^7$十分に大きいので、これに近い解はどれも$O(n^2)$全く不可能です。 平$O(n \log n)$重い定数を使用することは危険であるため、解は線形または線形に近いものでなければならず、おそらく素数に対するふるいベースの計数方法を使用します。 

単純な実装では、すべてのペアを反復しようとします。$(a,b)$gcdを計算しますが、これは中程度の場合でも失敗します$n$。 のために$n = 10^7$、ペアの数は約$5 \cdot 10^{13}$、それは不可能です。 

2 番目の単純なアイデアは、gcd 値を修正することです。$g$両方の数値が次の倍数であるペアをカウントします$g$、しかしそれを確認するのを忘れていました$g$は正確に gcd です。これは、gcd とのペアが次の倍数に等しいため、オーバーカウントにつながります。$g$が誤って含まれてしまう可能性があります。 

整数は 1 つだけであるため、入力書式設定からトリッキーな特殊ケースは発生しません。 主な困難は、過剰カウントを回避し、線形前処理を実現することです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペアについて$a < b$、計算する$\gcd(a,b)$、素数かどうかを確認して数えます。 これは正しいです。gcd が公約数のセットを完全に決定するからです。 ただし、このアプローチのパフォーマンスは、$O(n^2)$gcd の計算。 各 gcd は$O(\log n)$, したがって、合計は次のとおりです。$10^{14} \log n$、これは実現可能な限界をはるかに超えています。 

重要な観察は、視点を逆転させることです。 ペアをチェックしてその gcd を計算する代わりに、gcd 値を修正します。 

ペアの gcd が素数であると仮定します。$p$。 したがって、両方の数値は次のように書くことができます。$$a = p \cdot x,\quad b = p \cdot y$$と$\gcd(x,y) = 1$、そして両方$x,y \le \lfloor n/p \rfloor$。 

したがって、各素数について$p$、互いに素のペアを数える必要があります。$(x,y)$範囲内で$[1, \lfloor n/p \rfloor]$。 これはまだ自明ではありませんが、カウントを再度変換することができます。 

互いに素のペアを直接カウントする代わりに、「gcd が正確に」という条件が成り立つことを観察します。$p$」は、倍数を減算することと同じです。 

固定素数の場合$p$、 させて$m = \lfloor n/p \rfloor$。 両方の数値が次の倍数であるペアの数$p$は：$$\binom{m}{2}$$これには、gcd が次の倍数であるすべてのペアが含まれます。$p$、正確にだけではありません$p$。 

したがって、割り算可能性の降順で包含を使用します。つまり、大きな倍数から始めて、貢献が二重にカウントされないようにします。 もっときれいな方法は、gcd が正確に素数であるペアを効果的に数えていることを認識することです。これは次と同等です。$$\sum_{p \in \text{primes}} \text{count pairs with gcd divisible by } p - \text{count pairs with gcd divisible by } 2p, 3p, \dots$$ただし、より単純な組み合わせ恒等式が存在します。 

素数ごとに$p$、gcd とのペアの正確な数$p$等しい:$$\sum_{k=1}^{\lfloor n/p \rfloor} \mu(k) \cdot \binom{\lfloor n/(pk) \rfloor}{2}$$しかしメビウスを実装する$10^7$必要以上に重いです。 

はるかに単純な変換は、数値ごとに貢献をカウントすることです。 

各ペア$(a,b)$は 1 回だけカウントされ、その gcd は整数です$g$。 私たちが求めているのは、次のようなペアだけです。$g$プライムです。 したがって、次のように計算します。$$\sum_{g \text{ prime}} \text{number of pairs with gcd } g$$ここでは、標準的なふるいベースのトリックを使用します。 させて：$$f(g) = \text{number of pairs } (a,b) \text{ such that } g \mid a, g \mid b$$それから：$$f(g) = \binom{\lfloor n/g \rfloor}{2}$$ただし、これは gcd が次の倍数であるペアをカウントします。$g$、正確にはそうではありません$g$。 これを修正するには、倍数を大きいものから小さいものまで処理し、寄与分を差し引きます。 

以下を定義します。$$cnt[g] = \binom{\lfloor n/g \rfloor}{2}$$それからそれぞれについて$g$から$n$まで$1$、その倍数の寄与をすべて差し引きます。$$exact[g] = cnt[g] - \sum_{k \ge 2} exact[k g]$$最後に、答えは次のとおりです。$$\sum_{p \text{ prime}} exact[p]$$これは本質的に、可分性に対する包含と排除であり、ふるいのような蓄積によって効率的に実装されます。

 ## アルゴリズムのチュートリアル

 以下までのすべての素数を計算します。$n$最終的な合計では素数のみが重要となるため、ふるいを使用します。 

次に、各インデックスが含まれる配列を計算します。$g$で割り切れる数で形成されるペアの数を格納します$g$。 これは純粋に組み合わせによるものです。$k = \lfloor n/g \rfloor$の倍数$g$、それから、$k(k-1)/2$ペア。 

次に、大きな値から値を伝播します。$g$小さいものまで$g$、倍数の寄与を差し引くので、各値は最終的に gcd が正確に一致するペアを表すことになります。$g$。 

最後に、すべての素数を合計します。 

## アルゴリズムのチュートリアル

 1. 素数をマークするブール配列を構築します。$n$ふるいを使って。 最終的には素数の gcd 値のみが有効になるため、これが必要になります。 
2. すべての整数について$g$1から$n$、内の数値がいくつあるかを計算します。$[1,n]$で割り切れます$g$。 これをそのままにしておきます$k = n // g$。 コンピューティング$cnt[g] = k \cdot (k-1) / 2$。 これは、両方の要素が次の値で割り切れるすべてのペアをカウントします。$g$、正確な gcd に関係なく。 
3. 配列を作成する$exact[g]$として初期化される$cnt[g]$。 これは後で修正され、gcd が次とまったく同じになるように分離されます。$g$。 
4. プロセス$g$から$n$1 まで。それぞれについて$g$、すべての倍数から寄与分を差し引きます。$2g, 3g, \dots$。 これにより、gcd の倍数が大きいペアが削除され、gcd が正確に一致するペアのみが残ります。$g$。 
5. この修正の後、すべての素数に対して反復処理を行います。$p$そして合計$exact[p]$。 これにより、gcd が素数であるペアの数が得られます。 

減算が機能する理由は、すべてのペアがネストされた方法で gcd のすべての約数に寄与するためです。 大きいものから小さいものへと処理することにより、より高い gcd 値がより小さい値から減算される前に完全に解決されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    # sieve for primes
    is_prime = [True] * (n + 1)
    if n >= 0:
        is_prime[0] = False
    if n >= 1:
        is_prime[1] = False

    p = 2
    while p * p <= n:
        if is_prime[p]:
            step = p
            start = p * p
            for j in range(start, n + 1, step):
                is_prime[j] = False
        p += 1

    cnt = [0] * (n + 1)
    for g in range(1, n + 1):
        k = n // g
        cnt[g] = k * (k - 1) // 2

    exact = cnt[:]

    for g in range(n, 0, -1):
        mg = exact[g]
        if mg == 0:
            continue
        for m in range(2 * g, n + 1, g):
            exact[g] -= exact[m]

    ans = 0
    for p in range(2, n + 1):
        if is_prime[p]:
            ans += exact[p]

    print(ans)

if __name__ == "__main__":
    solve()
```ふるいは素数を効率的に分離するので、後で最終的な合計を有効な gcd 値のみに制限できます。 

の`cnt[g]`計算では倍数の直接カウントが使用されるため、ペア全体の反復が回避されます。 各値は単純な算術から導出され、全体として線形コストが保証されます。 

逆除数 DP は重要な構造ステップです。 大きいものから小さいものへと処理することで、倍数を減算するときにその値がすでに確定していることが保証されます。

 ## 特殊なケース

 のために$n = 2$、唯一のペアは (1,2) で、その gcd は 1 であり、素数ではないため、答えは 0 になります。アルゴリズムは次のように計算します。$cnt[1] = 1$、何も減算しません。1 は素数ではないため、何も寄与せず、0 が生成されます。 

小型用$n$ここで、1 より大きい素数はありません。たとえば、$n = 1$、ふるいはすべての候補者を即座に排除します。 特別な処理を行わなくても、素数の最終的な合計はゼロになります。 

多くの倍数が重なり合う値の場合、次のようになります。$n = 10$、除数の伝播により、下位の gcd 層が評価される前に上位の gcd 層が完全に削除されることが保証され、2 と 4 で同時に割り切れるペアのような二重カウントが防止されます。
