 ## 解決策
 ## 問題の理解

 2 つのオブジェクトは数直線上で厳密に右に移動します。 人間はロボットの 1 メートル前からスタートし、一定の速度で移動します`v1`メートル/秒、つまり後`t`人間が正確に進んだ秒数`t · v1`初期オフセットを超えた数メートル。 

ロボットは人間の 1 メートル後方からスタートしますが、その速度は一定ではありません。 最初の 1 秒間は 1 メートル、次の 2 メートルは 2 メートルというように進みますが、1 秒あたりの速度は次のように制限されます。`v2`。 ロボットが速度に達すると`v2`、正確に動き続けます`v2`後続の 1 秒ごとにメートル/秒。 

最小の整数時間を見つけるように求められます`t`その後`t`開始からのロボットの合計距離は、完全に人間の位置よりも厳密に長くなります。 

制約により許可されるのは、`v2`最大 2 · 10^9 であるため、どのソリューションでも秒ごとのシミュレーションを避ける必要があります。 時間の経過に伴う線形スキャンには、最悪の場合、最大で数十億回の反復が必要になりますが、これは実行不可能です。 

微妙な問題は、加速から制限速度への移行です。 上限を無視したり、上限に達した正確な秒数を誤って処理したりする単純なアプローチでは、不正確な答えが生成されます。 もう 1 つのよくある落とし穴は、1 つずれた推論です。この問題では、1 秒間ではなく、整数秒後の厳密な追い越しが明示的に必要です。 

たとえば、個別のステップではなく継続的な平等性チェックを想定している場合、会議時間は十分であると結論付ける可能性があります。 ただし、このステートメントでは整数倍の位置を厳密に大きくする必要があるため、等しいかどうかは考慮されません。 

## アプローチ

 直接シミュレーションでは、両方の位置を秒ごとに追跡します。 ロボットの速度は、衝突するまで毎秒 1 増加します。`v2`、その後は一定のままです。 各ステップで両方の位置が更新され、ロボットが人間を追い越したかどうかが確認されます。 

このアプローチは正しいですが、ロボットが必要とする可能性があるため遅すぎます。`v2`フルスピードに達するまで数秒、そして`v2`それ自体は 2 · 10^9 まで大きくなる可能性があります。 さらに悪いことに、それを超えて追い越しの瞬間までシミュレーションする必要があり、最悪の場合の実行時間を答えに線形にする必要があるかもしれません。 

重要な観察は、ロボットの動きが自然に 2 つの領域に分割されるということです。 最初の領域では、速度が直線的に増加するため、距離は三角形に増加します。 2 番目の領域では、その距離は傾きに応じて直線的に増加します。`v2`。 人間は常に傾きを持って直線的に成長します`v1`。 以来`v2 > v1`、ロボットがフルスピードに達すると、相対ギャップは直線的に変化し、最終的にはゼロをちょうど 1 回横切る必要があります。 

これは、いつでも両方の位置関数を閉じた形式で計算できることを意味します`t`。 次に、最小の整数を見つける必要があります`t`そのような`robot(t) > human(t)`。 述語は時間的には単調です。ロボットが追い越すと、その実効勾配は人間の勾配より決して小さくないため、ロボットは永遠に先を行き続けます。 これにより、時間をかけて二分探索が可能になります。 

残る詳細は、ロボットの距離を効率的に計算することだけです。 時間のために`t`、 もし`t <= v2`、合計を使用します`1 + 2 + ... + t`。 それ以外の場合は、最初の値を合計します`v2`条件を追加してから`(t - v2) · v2`。

 ## アルゴリズムのチュートリアル

 両方の参加者の位置を計算する関数を定義します。`t`秒。 

1. 人間の位置を次のように計算します。`human(t) = 1 + t · v1`。 1 メートルの初期オフセットはモーション全体を通じて維持され、速度のみが成長に寄与します。 
2. ロボットの距離を 2 段階で計算します。 もし`t <= v2`、ロボットはまだ加速しているため、その距離は最初の距離の合計になります。`t`整数、つまり`t · (t + 1) / 2`。 これは、速度が増加する等差級数から直接得られます。 
3. もし`t > v2`、モーションを分割します。 ロボットはまず、次の時点までの完全な三角フェーズを完了します。`v2`、貢献`v2 · (v2 + 1) / 2`。 その後は一定速度で移動します`v2`のために`(t - v2)`秒、貢献`(t - v2) · v2`。 
4. 述語を定義する`f(t)`もしそうならそれは真実です`robot(t) > human(t)`。 私たちは最小のものを望んでいます`t`これは当てはまります。 
5. 次のことに注意してください。`f(t)`モノトーンです。 ロボットが完全に先行すると、その速度の利点により、再び遅れをとることはありません。 
6. 二分探索を実行します。`t`十分に広い範囲、たとえば一定速度でも安定する値まで`v2`追い越しを保証します。 安全な上限は`2 * 10^18`最悪の理論的推論ですが、実際には`2 * v2 + 5`飽和後のギャップは線形であるため、十分です。 
7. 最小値を返します`t`どこ`f(t)`それは本当です。 

### なぜ効果があるのか

 ロボットの位置関数は次までに凸です。`v2`増分が増加するため、その後は直線的に傾きます`v2`。 人間の位置は傾きのある直線です`v1`。 以来`v2 > v1`、ロボットが上限速度に達すると、ロボットと人間の位置の差は正の傾きを持つ一次関数になります。 これにより、非正の差分から正の差分への 1 回の遷移が保証され、述語が時間内に単調になり、二分探索が検証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def robot_pos(t, v2):
    if t <= v2:
        return t * (t + 1) // 2
    tri = v2 * (v2 + 1) // 2
    return tri + (t - v2) * v2

def human_pos(t, v1):
    return 1 + t * v1

def ok(t, v1, v2):
    return robot_pos(t, v2) > human_pos(t, v1)

def solve():
    v1, v2 = map(int, input().split())
    
    lo, hi = 0, 1
    while not ok(hi, v1, v2):
        hi *= 2
    
    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if ok(mid, v1, v2):
            hi = mid
        else:
            lo = mid
    
    print(hi)

if __name__ == "__main__":
    solve()
```この実装では、ロボットの 2 相距離関数と人間の線形関数を直接エンコードします。 の`ok`function は二分探索で使用される単調述語です。 指数関数的な拡大`hi`上限を推測することなく、十分な大きさの検索間隔を常に見つけることができます。 

よくある間違いは、人間の最初のオフセットを忘れることです。これにより、比較がちょうど 1 メートルずれてしまい、初期のエッジ ケースでの最終的な答えに影響を及ぼします。 もう 1 つの微妙な点は、`>=`の代わりに`>`; ロボットは厳密に先行する必要があるため、等しいだけでは明らかに十分ではありません。

 ## 特殊なケース

 重要なエッジケースの 1 つは、最終的な答えが出る前にロボットと人間が同等になる場合です。 最初のサンプルでは、`t = 4`両方の位置が正確に一致しますが、正しい答えは次のとおりです。`t = 5`。 述語では厳密な不等号が使用されているため、アルゴリズムはこれを正しく処理します。そのため、等号が成功を引き起こすことはありません。 

もう 1 つのエッジ ケースは、ロボットが最高速度に達する前に追い越しが発生する場合です。 たとえば、`v1 = 2, v2 = 4`、ロボットは正確に勝ちます`t = 4`、まだ加速しているにもかかわらず。 三角和の公式はこの状況を正確に捉えているため、特別な処理は必要ありません。 

最後のエッジケースは、非常に大きな値です。`v1`そして`v2`。 このソリューションでは算術検索と対数検索のみを使用するため、シミュレーションの深さに依存せず、Python の任意精度の整数により、すべての中間値が 64 ビット整数に安全に収まります。
