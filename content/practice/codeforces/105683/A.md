 ## 解決策
 ## 問題の理解

 直線上に順序付けられたターゲット ポイントの 2 つのコレクションが与えられます。1 つのセットは原点の厳密に右側にあり、もう 1 つは厳密に左側にあります。 ロボットは位置 0 から開始し、両方のセットのすべてのポイントを訪問する必要があります。 

ロボットは単位速度で移動するため、時間は移動距離に等しくなります。 工夫は訪問の構造にあります。ロボットが一方の地点に行くときは常に、反対側の地点に行く前に原点に戻る必要があります。 両側の訪問ポイントの順序は任意であり、左側から開始するか右側から開始するかを選択することも自由です。 

重要な微妙な点は、最後に訪問したポイントの後に原点に戻る必要がないため、最後の移動はどこで終了してもよいことです。 

入力により、長さ n の 2 つの配列 (右側の点のゼロからの距離と左側の点のゼロからの距離) が与えられます。 交互制約の下ですべてのポイントを訪問するのに必要な最小合計時間を見つける必要があります。 

n が最大 100000、距離が最大 10^9 の場合、すべての順列を試行したり、スケジュールの選択を明示的にシミュレートしたりするソリューションは、非常に遅すぎます。 O(n^2)ですら使えなくなり、階乗はすぐにアウトになってしまいます。 

主な問題点は、訪問ポイントの順序が各サイド内で重要ではないことですが、交互制約によりゼロに戻ることを繰り返すことで 2 つのサイドが結合されることです。 

一般的な失敗例は、一方の側に多数の小さな点があり、もう一方の側に非常に大きな点が 1 つある場合に発生します。 常に最も近い次のポイントに向かう貪欲なアプローチは、往復の料金を払いすぎてしまう可能性があります。 

たとえば、右側のポイントが [10] で左側のポイントが [1、2、3] の場合、単純な貪欲な戦略では不十分に交互に繰り返し戻ってくる可能性がありますが、最適なソリューションでは訪問をグループ化して高価な長距離移動を最小限に抑えます。 

もう 1 つの失敗モードは、最後のセグメントだけがゼロに戻る必要がないことを忘れていることです。 多くの誤った解決策では、1 つの余分なリターンが過大に計算されます。 

## アプローチ

 強引な解釈では、連続する訪問では両側を交互に行う必要があることを尊重しながら、左右のポイントを訪問するあらゆる可能な順序を考慮します。 左の点と右の点の順序、および開始側の選択ごとに、移動コストをシミュレートします。点へのすべての移動がその距離に寄与し、辺間の切り替えごとに強制的にゼロに戻り、そのセグメントの移動距離の 2 倍が追加されます。 

すべての有効なスケジュールを明示的に探索するため、これは正しいですが、インターリーブの数は組み合わせ的に増加します。 内部順序を固定しても、各ステップで 2 つの選択肢があり、O(2^n) パターンが得られ、各辺内の順列も考慮すると階乗になります。 これは実現可能な限界をはるかに超えています。 

重要な観察は、どちらの側でも、訪問順序が帰路の回数に影響を与えないということです。 それぞれの側で点を並べ替える場合、唯一意味のある決定は、どの正確な順列を使用するかではなく、何回側を切り替えるかということです。 

片側の点を訪問するたびに、その距離を支払います。 さらに、陣営を切り替えるたびに、訪問した地点の距離に等しいゼロ復帰コストが発生します。 訪問の順序は自由に変更できるため、高価な返品が最小限に抑えられるように順序を構造化したいと考えています。 

これにより、問題は 2 つのソートされたリストに基づいて最適な交互シーケンスを決定することになります。 最適な構造は、ソートされた値に貪欲であることがわかります。距離が長いほど、より少ないスイッチと組み合わせる必要があるため、各サイドが選択された場合、常に各サイド内の距離の降順でポイントを処理します。

最後の単純化は、最適な戦略は、ソートされた 2 つのリストを降順にマージし、サイドが足りなくなったときを注意深く考慮して、交互のウォークをシミュレートすることと同等であるということです。

 ## アルゴリズムのチュートリアル

 1. 両方の配列を降順に並べ替えます。 これにより、常に各側の最も遠い残りのポイントが最初に考慮されるようになり、後で不必要に長い移動を繰り返すことを回避できます。 
2. 各配列に 1 つずつ、その側の次の未訪問の点を表す 2 つのポインターを維持します。 
3. 両方の可能性を暗黙的に評価することによって開始側を決定しますが、シミュレーションを複製する代わりに、両方の結果を計算します。 
4. 貪欲なプロセスをシミュレートします。各ステップで、両側の次に利用可能な点を比較し、より長い距離を選択します。 この選択により、陣営を切り替える前に常に現在の「高価なリーチ」を拡張することができます。 
5. 距離 d の点に移動する場合、総コストに d を加算します。 これが最初の動きではなく、サイドを切り替える場合は、新しい点に到達する前にゼロに戻ることを表すために d を追加します。 
6. 最後の移動でゼロに戻るコストが発生しないことを確認しながら、すべてのポイントを訪問するまで続行します。 
7. 可能な両方の開始側で最小の結果を取得します。 

### なぜ効果があるのか

 コストの構造は、各帰還前に訪問した最大距離の順序のみに依存します。 反対側に大きなポイントが残っている間に小さなポイントを選択すると、後になって遠距離で不必要な追加のリセットが発生する危険があります。 利用可能な最も遠い点を常に優先することで、各リターン トゥ ゼロ イベントが局所的に最大のセグメントに関連付けられるようになります。これは、リターンは不可逆的なコスト イベントであるため、これが最適です。 

これにより、単調な構造が作成されます。一度大きな距離をスキップすると、後でそれより悪いまたは同等の条件でのみ使用できます。 したがって、貪欲な順序付けにより、最小限のリセットで長い手の最適な組み合わせが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_once(R, L):
    R.sort(reverse=True)
    L.sort(reverse=True)

    i = j = 0
    cur_side = None
    ans = 0

    # pick first side based on larger starting point
    if i < len(R) and (j == len(L) or R[i] >= L[j]):
        cur_side = 0
    else:
        cur_side = 1

    first = True

    while i < len(R) or j < len(L):
        if cur_side == 0:
            d = R[i]
            i += 1
        else:
            d = L[j]
            j += 1

        ans += d

        if first:
            first = False
        else:
            ans += d  # return to origin before switching

        # switch side
        if i == len(R):
            cur_side = 1
        elif j == len(L):
            cur_side = 0
        else:
            if R[i] >= L[j]:
                cur_side = 0
            else:
                cur_side = 1

    return ans

def solve():
    n = int(input())
    R = list(map(int, input().split()))
    L = list(map(int, input().split()))

    # try both starting choices
    res1 = solve_once(R, L)
    res2 = solve_once(L, R)

    print(min(res1, res2))

if __name__ == "__main__":
    solve()
```このソリューションは、固定開始側を想定した単一のシミュレーション ルーチンを中心に構築されています。 2 つの配列は、各側の次の候補が常に残りの最大距離になるように降順で並べ替えられます。 

ポインタ ロジックにより、要素を再度訪問することがなくなります。 の`first`フラグは非常に重要です。最初の動きではゼロに戻る必要がないため、最初のセグメントの後にのみラウンドトリップ ペナルティの追加を開始します。 

サイドスイッチング ロジックは、次に利用可能な要素を比較することによって駆動されます。 これは、長い距離がより早く処理され、複数のリターン サイクルが強制されるのを防ぐ貪欲な決定ポイントです。 

最後に、最初に選択した側で返品コストの構造が変わる可能性があるため、シミュレーションを 2 回実行します。 

## 実用的な例

 右の点が [4, 1] で左の点が [3, 2] である単純なケースを考えてみましょう。 

降順にソートされた両方の配列は同じままです。 

### 右から始まるトレース

 | ステップ | 側面 | 選ばれた | d | を追加しました。 返品費用 | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | R | 4 | 4 | 0 | 4 |
 | 2 | Ｌ | 3 | 3 | 3 | 10 |
 | 3 | R | 1 | 1 | 1 | 12 |
 | 4 | Ｌ | 2 | 2 | 2 | 16 |

 このトレースは、各スイッチが最後に訪問した距離に等しいリターンをどのように追加するか、および貪欲な順序付けによって大きな値が早期に処理されるようにする方法を示しています。 

### 左から始まるトレース

 | ステップ | 側面 | 選ばれた | d | を追加しました。 返品費用 | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | Ｌ | 3 | 3 | 0 | 3 |
 | 2 | R | 4 | 4 | 4 | 11 |
 | 3 | Ｌ | 2 | 2 | 2 | 15 |
 | 4 | R | 1 | 1 | 1 | 17 |

 これは、最初のセグメントがリターンを回避するため、開始側が総コストに影響を与えることを示しており、最大の初期セグメントを最初に配置することが有益です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 両方の配列のソートが優先され、シミュレーションは線形になります。 
| スペース | O(1) おまけ | 入力ストレージを超えて使用されるのはポインターといくつかの変数のみです。 

この制約では最大 10^5 ポイントが許可されるため、O(n log n) の並べ替えソリューションは十分に制限内に収まりますが、線形シミュレーションにより並べ替え後にボトルネックが発生しないことが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、各側にポイントが 1 つだけある場合です。 アルゴリズムは 2 つの距離のうち大きい方から開始され、切り替えが 1 つだけ発生する場合と発生しない場合があるため、不必要な戻りコストが正しく回避されます。 

たとえば、右は [5]、左は [10] です。 アルゴリズムは左から始まり、リターンなしで 10 を取得し、次にスイッチ コストの 5 + 5 を加算して 5 に進み、20 を生成します。他の開始側の方が悪く、コードの 2 番目のシミュレーションは両方の選択肢をカバーしています。 

もう 1 つのエッジ ケースは、片側が大幅に大きいものの、小さな点が多数ある場合です。 並べ替えにより、大きなポイントが常に最初に消費されるため、初期の小さな移動によって発生する繰り返しの返品サイクルが強制されることはありません。 

たとえば、右は [100, 1, 1]、左は [2] です。 正しい側から開始すると、大きな 100 が中間の戻り値によって分割されることがなくなり、貪欲な比較により、小さな中断の前に処理されることが保証されます。
