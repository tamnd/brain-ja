 ## 問題の理解

 長さの文字列が与えられます$n$、すでに大文字のラテン文字が埋め込まれているポスターを表します。 タスクは、コスト モデルのバランスをとりながら、部分文字列「NEIMARK」ができるだけ多く出現するようにこの文字列を変更することです。任意の文字を変更すると 1 単位のペナルティがかかり、7 文字の連続ブロックとして部分文字列「NEIMARK」が出現するたびに 5 の報酬が与えられます。 

重要な詳細は、出現回数が長さ 7 の固定部分文字列 (各位置を意味する) にわたってカウントされることです。$i$から$0$に$n-7$候補セグメントを定義します。 そのセグメントを「NEIMARK」に変えることにした場合、5 を獲得しますが、現在の部分文字列と「NEIMARK」の間のハミング距離を支払う必要があります。 

最終的なスコアは、すべての報酬の合計からすべての変更コストを差し引いたものになります。また、キャラクターをグローバルに自由に変更できます。つまり、選択した出現間の重複が共有キャラクターを通じて相互作用します。 これにより、問題は基本的に、長さ 7 の間隔のセットを選択し、正味ゲインを最大化するために一貫して文字を割り当てることが問題になります。 

以来$n \le 2 \cdot 10^5$、部分文字列のサブセットを列挙することを伴う解決策は不可能です。 部分文字列のすべてのペアに対する 2 次アプローチでも時間がかかりすぎます。 この構造は、決定が固定長のローカル セグメントのみに依存するため、動的プログラミングまたは位置に関する最短パスの定式化を強く示唆しています。 

重複するオカレンスが一貫性なく選択された場合、微妙なエッジ ケースが発生します。 たとえば、位置 0 と位置 1 から同時に「NEIMARK」を形成しようとすると、矛盾した文字の割り当てが強制されます。 各ウィンドウを個別に評価する単純な貪欲なアプローチでは、両方の報酬が過大評価され、変更の競合が過小評価されます。 

## アプローチ

 強引なアプローチは、「NEIMARK」を配置するための開始位置のすべてのサブセットを考慮することです。 サブセットごとに、選択されたすべてのセグメントを満たすように文字を割り当て、元の文字列を変換するコストを計算します。 これはすぐに実行不可能になります。$2^{n}$最悪の場合はサブセット。 

すべての部分文字列を個別にチェックするように制限しても失敗します。 計算してみると、ポジションごとに$i$、変換にかかるコスト$s[i:i+7]$を「NEIMARK」に入力し、収益性の高いものをすべて貪欲に選択すると、すぐに矛盾に遭遇します。 重複する 2 つの収益セグメントがキャラクターを共有する場合があり、一方を修正すると他方のコストが増加または減少する可能性があります。 

重要な観察は、ターゲットの単語が固定長 7 であるため、有効な設定はすべて左から右に移動し、各位置で単語を開始するかスキップするかを決定すると見なすことができるということです。 単語を位置で始めると$i$、次に位置$i+1$に$i+6$その決定によって事実上消費されます。 これは当然、インデックスに対する動的プログラミングにつながります。 

それぞれのポジションで$i$、2 つの可能性を比較します: スキップして次へ移動します。$i+1$、または「NEIMARK」を次のように配置します。$i$、不一致のコストを支払って、次の場所にジャンプします。$i+7$。 不一致コストは、開始位置ごとに事前に計算できます。

 ## アルゴリズムのチュートリアル

 動的プログラミング配列を定義します。$dp[i]$位置までのプレフィックスのみを考慮した達成可能な最大スコアです$i$、 どこ$i$はまだ処理されていない最初のインデックスです。 

1. サイズの DP 配列を初期化します。$n+1$非常に小さな値で設定します$dp[0] = 0$。 これは、文字を処理する前にスコアがゼロであることを表します。 
2. すべての開始位置のコスト配列を事前計算します。$i \le n-7$、ここで、両者の間で異なる文字数が何文字あるかを計算します。$s[i:i+7]$そして文字列「NEIMARK」。 これは、で始まる単語を配置することにした場合の修正コストを示します。$i$。 
3. 位置を左から右に繰り返します。 それぞれのポジションで$i$、設定によって現在の文字をスキップするオプションを伝達します。$dp[i+1] = \max(dp[i+1], dp[i])$。 これは、その位置で単語を開始しないという決定をモデル化します。$i$。 
4. もし$i \le n-7$、から始まる「NEIMARK」を配置することを検討してください。$i$。 更新します$dp[i+7] = \max(dp[i+7], dp[i] + 5 - cost[i])$。 この移行では、5 の報酬とキャラクター変更のペナルティの両方が得られます。 
5. すべての位置が処理されるまで続行します。 答えは$dp[n]$、これは文字列全体で達成可能な最高のスコアを反映します。 

重要な点は、すべての遷移がインデックス内で前進するため、サイクルや不整合が生じるような形で状態が再検討されることはないということです。 

### なぜ効果があるのか

 DP は次の不変条件を維持します。$dp[i]$厳密に順位に影響を与える決定のみを使用して達成可能な最高のスコアです。$i$。 「NEIMARK」オカレンスの有効な構造は、ある位置から始まるかスキップされる、互いに素なセグメントに分解できます。 すべての配置は正確に 7 つの連続する文字を消費するため、DP 状態空間で遷移が時間的に重複することはありません。 これにより、グローバルに最適な配置が DP グラフ内の 1 つのパスに正確に対応することが保証され、再帰ではそのようなすべてのパスが重複することなく探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    target = "NEIMARK"

    INF = -10**18
    dp = [INF] * (n + 1)
    dp[0] = 0

    cost = [0] * n

    for i in range(n - 6):
        c = 0
        for j in range(7):
            if s[i + j] != target[j]:
                c += 1
        cost[i] = c

    for i in range(n):
        if dp[i] == INF:
            continue

        if i + 1 <= n:
            dp[i + 1] = max(dp[i + 1], dp[i])

        if i <= n - 7:
            dp[i + 7] = max(dp[i + 7], dp[i] + 5 - cost[i])

    print(dp[n])

if __name__ == "__main__":
    solve()
```実装は DP に直接準拠します。 コスト計算では、考えられるウィンドウごとに不一致文字を明示的にカウントします。 DP ループは、スキップによって 1 つの位置が進み、単語の配置によって 7 つの位置が進み、重複しない構造が維持されることを注意深く確認します。 

実装の微妙な点は、同じ反復内の同じインデックスの決定を上書きしない方法で更新を適用する必要があることです。 順方向 DP 配列を使用すると、各状態が以前のインデックスからのみ書き込まれるため、この問題が回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列の長さがちょうど 7 の場合です。アルゴリズムはセグメント全体を取得するか、セグメントをスキップします。 DP は 0 から 7 への 1 回の遷移を明示的に許可するため、何もしない場合と比べて全コストを正確に評価します。 

もう 1 つのケースは、「NEIMNEIMARK」のような文字列など、潜在的な一致が重複している場合です。 貪欲なアプローチでは位置 0 と 2 の両方から開始しようとする可能性がありますが、0 から始まるセグメントが選択されると、状態はインデックス 7 にジャンプし、競合するオーバーラップをスキップするため、DP はこれを防ぎます。 

最後の微妙なケースは、不一致が非常に高い場合です。 ウィンドウの構造が類似している場合でも、次の場合、DP はそれを正しく回避します。$5 - cost[i]$このような遷移は合計スコアを低下させるため、より大きなグローバル構造で有益でない限り、決して選択されないため、負です。
