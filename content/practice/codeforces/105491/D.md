 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 重要な隠れた構造は、要素を自由に再配置できることですが、制限された方法でのみ可能です。つまり、任意の 2 つの位置を選択して、それらの値を交換できます。 したがって、任意の並べ替えはスワップを通じて実現できるため、配列を任意に並べ替えることができます。 

配置を選択した後、配列がプレフィックス条件を満たすようにします。つまり、すべてのプレフィックスの合計が厳密に正でなければなりません。 言い換えれば、左から右にスキャンしても、どの時点でも累計がゼロ以下になることはありません。 

各テスト ケースのタスクは、配列を「有効なプレフィックス合計 - 正」の順序に再配置するために必要なスワップの最小数を決定することです。 どの再配置もこの特性を達成できない場合は、-1 を出力する必要があります。 

入力制約は、すべてのテスト ケースにわたる要素の合計数が最大約 10^5 と大きいことを意味します。 これにより、すべての順列を試行したり、スワップを明示的にシミュレートしたりするアプローチは除外されます。 最悪の場合、テスト ケースあたり O(n^2) でも遅すぎます。 

重要なエッジケースは、配列に正の値に比べて負の値が多すぎる場合です。 たとえば、配列に 1 よりも -1 が多く含まれている場合、最適な順序であっても、プレフィックスの合計が最終的に非正になることを防ぐことはできません。 

もう 1 つの微妙なケースは、合計がプラスであるものの、かろうじてプラスである場合に発生します。 たとえば、配列が [1, -1, -1, 1] の場合、合計はゼロになるため、最後のプレフィックスの合計を正にすることはできません。 これにより、局所的に配列のバランスが取れているように見えても、即座に答えが不可能になります。 

2 番目のタイプのエッジ ケースは、配置は存在するがスワップをまったく必要としない場合です。 たとえば、[1, 1, -1] はすでに有効であるため、単純に考えて並べ替えを検討しても、答えはゼロになります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。配列のすべての順列を生成し、そのプレフィックスの合計が正のままかどうかを確認します。 順列ごとに、O(n) でプレフィックスの合計を計算し、元の配列からそれに到達するために必要な最小スワップ数を追跡します。 ただし、順列の数は n! であり、スワップのカウントを無視しても、非常に小さい n を超えると、単純に妥当性をチェックすることはすでに不可能になります。 

この問題を考えるためのより有効な方法は、有効な取り決めがそもそもいつ可能になるのかということと、そのような取り決めの構造は何なのかという 2 つの質問を分けて考えることです。 

プレフィックス合計条件は、貪欲な構造を強く示唆しています。 すべてのプレフィックス合計をプラスのままにしたい場合は、できるだけ早く大きなプラスの寄与が必要です。 配列は 1 と -1 のみで構成されているため、実際に自由にできるのはそれらをどのようにインターリーブするかだけです。 

P を 1 の数、N を -1 の数として定義すると、有効な配置はすべてのプレフィックスで P > N を満たす必要があり、特に P はグローバルに N を超える必要があります。 したがって、必要条件は P > N です。 

ここで、有効な順序を構築することを検討してください。 自然な戦略は、可能な限り早い段階で常に 1 を配置し、-1 を遅らせることです。 実際、最初にすべて 1 を配置し、次にすべて -1 を配置する貪欲な順序は、P > N の場合には常に有効です。これは、プレフィックスの合計は最初は厳密に増加し、その後減少しますが、P が十分に大きい場合は非正に達することはないためです。 

妥当性がカウントのみに依存することがわかったら、残りの問題は、元の配列を有効な順序に変換するために何回のスワップが必要かということになります。 

重要な観察は、有効な配置は、制御された方法で十分な -1 が導入される前に、すべての 1 が出現するターゲット シーケンスの選択に対応している必要があるということです。 必要な最小限のスワップは、正規の最適な順序付けと比較して、1 が配置されるべき位置に現在 -1 がいくつ配置されているか、またはその逆を数えることと同等です。

これを形式化するきれいな方法は、ターゲットの配置を最初の P 位置にすべて 1 が配置されていると考えることです。 次に、元の配列をこのターゲットと比較し、不一致をカウントします。 それぞれのスワップで 2 つの間違って配置された要素を修正できるため、実現可能性が保たれていれば、答えは不一致の数のおよそ半分になります。

 ## アルゴリズムのチュートリアル

 1. 配列内に 1 と -1 がいくつあるかを数えます。 これにより、有効な取り決めがそもそも可能かどうかが決まります。 
2. 1 の数が -1 の数より厳密に大きくない場合は、すぐに -1 を返します。 どの順列でも合計は正ではないため、一部のプレフィックスは失敗します。 
3. 最初にすべて 1 を配置し、その後にすべて -1 を配置することで、正規のターゲット配置を修正します。 これは、ステップ 2 の条件が成立する場合に常に有効です。1 の間のすべての接頭語が正の和を持ち、1 が余っているため、-1 を追加した後にゼロに下がらないことが保証されます。 
4. 元の配列をスキャンし、位置ごとにターゲットと比較し、不一致を数えます。 1 が必要な領域に -1 が表示される場合、またはその逆の場合、不一致が発生します。 
5. 誤って配置された 1 を誤って配置された -1 と交換すると、両方の位置が一度に修正されるため、各交換により 2 つの不一致を修正できます。 したがって、不一致を 2 で割った値を計算して答えとします。 
6. その値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、有効な最終構成はすべて -1 に対する 1 の位置によって決定され、prefix-sum 制約により、最適な配置でできるだけ早くすべての 1 が使用されるように強制されることです。 スワップはインデックス上で制限がないため、問題はマルチセットの配置を固定の正規順列に変換することに帰着します。 不一致ペアリング引数により、すべてのスワップによって不正確な配置の数がちょうど 2 つ減少し、これより優れたスワップはないため、貪欲なペアリングが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n = int(input())
    a = list(map(int, input().split()))

    ones = a.count(1)
    negs = n - ones

    if ones <= negs:
        return -1

    # target: all 1s then -1s
    target = [1] * ones + [-1] * negs

    mismatches = 0
    for i in range(n):
        if a[i] != target[i]:
            mismatches += 1

    return mismatches // 2

t = int(input())
for _ in range(t):
    print(solve_case())
```このコードは、最初に単純なカウント条件を使用して実現可能性をチェックします。 これは、存在にとって重要な唯一のグローバル制約です。 

次に、単純なパターンを超える大きなものを明示的に保存せずに、概念的なターゲットの順序付けを構築します。 不一致数は線形時間で計算されます。 

2 による除算が実装の重要な詳細です。すべてのスワップで、1 つの不正な 1-position と 1 つの不正な -1-position が解決されます。 

## 実用的な例

 ### 例 1

 入力:

 n = 5

 a = [1, -1, 1, 1, -1]

 ターゲットは [1, 1, 1, -1, -1] です

 | 私 | a[i] | ターゲット[i] | 不一致 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0 |
 | 2 | -1 | 1 | 1 |
 | 3 | 1 | 1 | 0 |
 | 4 | 1 | -1 | 1 |
 | 5 | -1 | -1 | 0 |

 不一致 = 2 なので、答えは 1 スワップです。 これは、位置 2 と 4 を交換することに対応します。 

### 例 2

 入力:

 n = 4

 a = [-1, -1, 1, 1]

 ターゲットは [1, 1, -1, -1] です

 | 私 | a[i] | ターゲット[i] | 不一致 |
 | --- | --- | --- | --- |
 | 1 | -1 | 1 | 1 |
 | 2 | -1 | 1 | 1 |
 | 3 | 1 | -1 | 1 |
 | 4 | 1 | -1 | 1 |

 不一致 = 4 なので、答えは 2 つのスワップです。 各スワップは、間違って配置された -1 を間違って配置された 1 と交換します。

 すべてのテスト ケースの合計 n が最大 10^5 であるため、ソリューションは制約内に問題なく適合します。そのため、アルゴリズムは全体で約 10^5 の演算を実行します。 

## 特殊なケース

 配列の数値が 1 と -1 である場合、実行可能性チェックは直ちに失敗します。 たとえば、[1, -1] は、最終的な合計がゼロであり、一部のプレフィックスがゼロになる必要があるため、どの順序でも厳密に正のプレフィックス合計を生成することはできません。 

配列がすべて 1 の後にすべて -1 が続くようにすでにソートされている場合、不一致数は 0 となり、答えはゼロ スワップになります。 たとえば、[1, 1, 1, -1] はすでにターゲット構造を満たしています。 

[1, -1, 1, -1, 1, -1, 1] のような値が交互に現れるなど、配列が激しく混合されている場合、不一致数は大きくなりますが、各スワップでは依然として 2 つの誤配置が解決されるため、アルゴリズムはコストを無秩序に線形に増加させるのではなく、自然に小さい整数のスワップ数に圧縮します。
