 ## 問題の理解

 長さの配列を構築するように求められます$n$からの整数を使用して$1$に$k$、強力なローカル制約付き: 長さのすべての連続セグメント$k$からのすべての値を含める必要があります$1$に$k$まさに一度。 

この条件はかなり制限的です。 任意のサイズのウィンドウ$k$すでに持っています$k$したがって、値を繰り返すことはできず、値を見逃すこともありません。 これにより、そのような各ウィンドウが即座に次の順列になるように強制されます。$1 \ldots k$。 課題は、これらのウィンドウが重なり合うため、1 つのセグメントの選択が他のすべてのセグメントを制約することです。 

目標は、有効な配列を構築することだけではなく、すべての有効な構築の中でその要素の合計を最大化することです。 

制約の観点から見ると、$n$テスト ケース全体で大きくなる可能性があります (合計で最大数十万)。 すべてのウィンドウを明示的にシミュレートしたり、すべての部分配列をスキャンして各候補の構成を検証しようとしたソリューションは、最悪の場合は 2 次形式になり、すぐに失敗します。 この構造は、ローカルなチェックではなく、グローバルな周期的な動作を理解する必要があることを示唆しています。 

微妙なエッジケースが現れるのは、$k = 1$。 この場合、サイズ 1 のすべての部分配列には数値 1 が含まれている必要があり、配列全体が強制的に定数になります。 順列構造を前提とする推論は、この場合にも正しく分解される必要があります。 

もう 1 つの重要なエッジケースは小さいです$n$に対して$k$。 もし$n < k$、サイズの有効な部分配列がありません$k$したがって、任意の配列が有効であり、選択することによって各位置を個別に最大化するだけです。$k$どこでも。 正しい解決策では、ウィンドウが存在しないときに誤って完全な置換制約を強制してはなりません。 

## アプローチ

 直接的な試みは、サイズの各ウィンドウを処理することです$k$独立して。 すべてのセグメントについて、すべての値が含まれていることを確認することができます。$1 \ldots k$ただし、ウィンドウが重なるため、選択肢は複雑な形で前方に伝播します。 ブルート フォース ビューでは、位置ごとに値を割り当て、各割り当て後に影響を受けるすべてのウィンドウの妥当性をチェックすることを試みる場合があります。 各割り当ては最大に影響します$k$窓口と各小切手の費用$O(k)$、おおよそにつながります$O(n \cdot k^2)$限界をはるかに超えた行動。 

重要な構造観察は、重なり合う窓から得られます。 すべての長さの場合-$k$セグメントにはすべての値が含まれます$1 \ldots k$次に、2 つの連続するウィンドウを考えます。$$[a_i, \ldots, a_{i+k-1}] \quad \text{and} \quad [a_{i+1}, \ldots, a_{i+k}]$$どちらも同じセットの順列です。 それらの唯一の違いは、一方の要素が去り、別の要素が入ってくることです。 両方のマルチセットが同一である必要があるため、送信要素と受信要素は一致する必要があります。 これにより、$a_i = a_{i+k}$。 

これは重要な単純化です。配列は周期的に周期的である必要があります。$k$。 これが受け入れられると、有効な配列はすべて、次の順列を繰り返したものになります。$1 \ldots k$。 

問題は、次の順列を選択することに帰着します。$1 \ldots k$、配列に沿って繰り返され、次の場合には最後の部分ブロックが切り捨てられます。$n$で割り切れない$k$。 残された唯一の自由は、1 つの期間内で値をどのように割り当てるかです。 

これで、最適化は線形になりました。 最初の各ポジション$k$それに合同なすべての位置をモジュロで決定します$k$。 したがって、各剰余クラスのモジュロ$k$最終的な配列内の固定数の位置に寄与します。 より頻繁に出現する残基クラスには、より大きな番号を割り当てる必要があります。 

したがって、最適な戦略は、単一期間内の各位置が配列全体に出現する回数をカウントし、これらのカウントを並べ替えて、最大値を割り当てることです。$k, k-1, \ldots, 1$最も頻度の高い位置に移動します。

 ## アルゴリズムのチュートリアル

 1. 長さの最初のブロック内の各インデックスの回数を計算します。$k$配列全体に表示されます。 

ポジションのために$i$、これは単に整数の数です。$[1, n]$に一致する$i \bmod k$。 これは、その「スロット」が合計にどのくらいの頻度で寄与するかを捕捉します。 
2. これらの周波数を配列に保存します`cnt`サイズの$k$、 どこ`cnt[i]`位置に対応する$i$最初の期間に。 

このステップでは、長い配列について推論するのではなく、問題を重み付け位置に変換します。 
3. 並べ替え`cnt`降順ではない順に。 

考え方は、最も頻繁に使用される位置と最大値を一致させる準備をすることです。 
4. 以下から値を割り当てます。$k$まで$1$並べ替えられた位置に移動します。 

各割り当ては貪欲です。寄与が線形で位置間で独立しているため、より頻繁な位置に大きな数値を配置すると、合計が最大に増加します。 
5. すべてのインデックスにわたって選択した期間パターンを繰り返して完全な配列を構築します$1 \ldots n$。 

これが機能する主な理由は、周期性が強制されると、合計に対する各ポジションの寄与が他のポジションから独立するためです。 唯一の結合は、最初の$k$要素は順列を形成しますが、個別の値を割り当てているため、$1 \ldots k$、その制約は自然に満たされます。 

### なぜ効果があるのか

 不変条件は、すべての有効な配列がその最初の配列によって完全に決定されるということです。$k$要素であり、それらの要素のそれぞれは、次の倍数で区切られた互いに素な位置のセットに独立して寄与します。$k$。 合計はこれらの選択肢の線形結合であるため、最適性は最大の係数 (周波数) を最大の値と一致させることになります。 周期性制約により、初期の置換要件を超えて異なる剰余クラス間で相互作用が起こらないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        cnt = [0] * k

        for i in range(k):
            # positions are i+1, i+1+k, i+1+2k, ...
            # count how many <= n
            cnt[i] = (n - (i + 1)) // k + 1 if i + 1 <= n else 0

        # sort counts
        cnt.sort()

        # assign values 1..k, largest to largest count
        # we compute contribution directly
        ans = 0
        val = 1
        for c in cnt:
            ans += c * val
            val += 1

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各剰余クラスが配列内に何回出現するかを計算します。 これはシミュレーションの代わりに直接演算を使用し、配列全体に対する反復を回避します。 

カウントをソートすると、頻度の昇順に値を貪欲に割り当てることができます。 より大きな値とより大きな周波数を組み合わせる必要があるため、割り当てられた値を増やしながら最小カウントから最大カウントまで反復します。 

よくある間違いは、最初に順列配列を明示的に構築してから、それを貪欲に埋めようとすることです。 それは機能しますが、不要です。 最終的な配列を具体化することなく、合計を直接計算できます。
