 ## 解決策
 ## 問題の理解

 私たちは、最初に位置 -1 に固定された白いピースと、正の数直線上の異なる整数座標に配置されたいくつかの黒いピースを含む 1 次元のボードを操作しています。 黒のピースが開始時に位置 0 を占めることは決して許可されず、位置によって厳密に順序付けされます。 

このプロセスはプレーヤーとシステムの間で交互に行われます。 プレイヤーの番では、別の駒と衝突しない限り、黒い駒を 1 つだけ左に 1 つ移動します。 このような移動のたびに、システムは白い部分を使用して決定論的に反応します。 現在の位置から開始して、白い駒はすぐ右にある連続する黒い駒のブロックを繰り返し見て、その長さ k を測定し、1 回の移動でブロック全体を飛び越えます。 このような各ジャンプは実行中の XOR スコアに k を与え、ジャンプによって飛び越えた黒い部分はボードから削除されます。 この連鎖反応は、白いピースの右側に直接隣接する連続した黒いセグメントがなくなるまで続きます。 

ゲームはすべての黒のピースが除去されるまで続き、最終的なスコアは、すべての白のピースの反応中に発生したすべてのセグメントの長さの XOR によって決定されます。 問題は、黒の駒の左の動きのシーケンスを最適に選択することによって、最終的な XOR スコアをゼロにできるかどうかです。 

入力サイズでは、すべてのテスト ケースで最大数十万の位置が許可され、位置自体は 10^9 に達する可能性があります。 これにより、個々の動きのシミュレーションや、各操作後のボード状態の繰り返しの再構築が除外されます。 どのようなソリューションでも、プロセスを段階的にシミュレートするのではなく、プロセスの構造的不変条件を抽出する必要があります。 

考えられるすべての動きシーケンスをシミュレートしようとする単純なアプローチは、各動きによってローカルな隣接関係が変化し、非常に非ローカルな方法で将来の連鎖反応に影響を与えるため、すぐに手に負えなくなります。 単一の完全なゲームをシミュレートする場合でも、連続するセグメントを繰り返し識別して位置を更新する必要がありますが、これは操作ごとに線形であり、全体的に遅すぎます。 

スコアが黒のピース間の初期ギャップのみに依存すると仮定すると、微妙な失敗モードが現れます。 これは不正確です。プレイヤーの動きにより、将来の XOR 寄与が変化する形で連続セグメントが結合または分割される可能性があるからです。 もう 1 つの罠は、k 値の貪欲な局所最小化が機能すると仮定することですが、初期の小さな調整により、XOR を支配する大きな後続の連続ブロックが強制される可能性があるため、これは失敗します。 

## アプローチ

 ブルートフォース戦略では、黒トークンの可能な動きのすべてのシーケンスを明示的にシミュレートし、結果の構成ごとに、完了するまで決定論的な白駒の反応を実行し、結果の XOR スコアを計算します。 開始構成を 1 つに限定したとしても、考えられるすべての黒手で分岐すると、指数関数的な数の状態が生成されます。 各シミュレーション ステップでは、隣接セグメントを見つけるために隣接構造をスキャンまたは維持する必要があり、反応ステップごとにおよそ O(n) の作業が必要になります。 総検索空間は n で指数関数的に増加するため、このアプローチは入力が小さい場合でも実行不可能になります。 

重要な構造的観察は、白い部分は黒い部分の最大の連続ブロックとのみ相互作用し、各ブロックの XOR 寄与は、そのブロックが消費された瞬間のサイズと正確に一致するということです。 黒のピースの動きは動的なシステムを作成しているように見えますが、最終的に重要なのは、これらのブロックが時間の経過とともにどのように結合または分割されるかだけです。 プレイヤーが動くたびに 1 つのトークンが事実上シフトされ、システムの反応は絶対的な位置ではなく隣接関係のみに依存します。

この問題は、連続する黒い部分間のギャップがどのように変化するかを制御するものとして再構成できます。 移動によりギャップが減少するか、隣接性が増加します。白い部分は常に、ギャップのないセグメントを現在の長さに等しい単一の XOR 寄与に折りたたみます。 したがって、ゲーム全体は、空間シミュレーションではなく、セグメントのパリティとマージ動作を制御することに帰着します。 

このように再定式化すると、問題はギャップに関する組み合わせゲームになります。 決定的な洞察は、すべての構成は十分に大きなギャップによって分離された独立したセグメントに分解でき、トークンを 1 歩左に移動するプレイヤーの能力は、隣接するセグメントが最終的に結合するかどうかにのみ影響するということです。 セグメント長の XOR は、セグメント内の内部再配置の下では不変であるため、唯一の効果的な制御は、最終的な折りたたみの瞬間に残っているセグメントの数です。 これにより、すべての XOR 寄与がキャンセルされるように初期構造でセグメントのペアリングが許可されるかどうかによって答えが決まるという削減が生じます。

 ## アルゴリズムのチュートリアル

 1. 位置が昇順で与えられるため、入力をソートするか、ソート済みとして扱います。 絶対的な位置は隣接の進化には無関係であるため、連続する黒の部分間のギャップに完全に焦点を当てます。 
2. 連続する黒い部分間の一連のギャップを計算します。 各ギャップは、最適なプレイの下で 2 つの隣接するピースが同じ連続コンポーネントに属するか、分離されたままであるかを決定します。 
3. 連続する位置の連続する各ランを、単一の XOR イベントで最終的に白の部分によって消費される潜在的なブロックとして解釈します。 このブロックのサイズが XOR に寄与します。 
4. 黒い部分を 1 単位だけ左に移動すると、あるギャップから別のギャップに 1 単位の長さが効果的に移動することを観察します。 これにより、黒の部分の総数が維持されますが、隣接構造の再配分が可能になります。 
5. 問題を、ブロックの最終的なサイズの XOR がゼロになるようにブロックをマージできるかどうかを判断することに帰着します。 マージによってブロック境界は変更されますが、合計は保持されるため、唯一の制御可能なパラメータは、サイズがちょうど 1 のギャップによって引き起こされるパリティ構造です。 
6. 1 に等しいギャップがいくつあるかを追跡します。これは、これらのギャップのみが分離を生じずに即座にマージできるためです。 大きなギャップは、セグメントの独立性を維持するハードセパレータとして機能します。 
7. これらの強制的な分離によって引き起こされるセグメント長の XOR を計算します。 この XOR が、ユニット ギャップを介して許可されるマージを再配置することによって無効化できる場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 このプロセスでは常に、連続する黒セグメントがアトミックな XOR 寄与に分解され、プレイヤーの移動は隣接境界が消えるか存続するかにのみ影響します。 したがって、ゲームのすべての状態は、最初にソートされた配列を事実上除去不可能なギャップによって分離されたセグメントに分割したものと同等になります。 内部再配置ではセグメント サイズは変更されず、マージによってのみセグメント数が変更されるため、最終的な XOR はどのギャップを削除できるかによって完全に決まります。 アルゴリズムはこのパーティション構造を正確に計算するため、最適な動きのシーケンスは有効なマージ パターンに対応し、その逆も同様であり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))

        if n == 1:
            print("NO")
            continue

        # compute gaps
        gaps = [x[i] - x[i - 1] for i in range(1, n)]

        # count forced separations (gaps > 1 behave as separators)
        # and track structure parity
        xor_val = 0
        for g in gaps:
            if g == 1:
                continue
            xor_val ^= g

        # decision depends on whether structure can be balanced
        print("YES" if xor_val == 0 else "NO")

if __name__ == "__main__":
    solve()
```コードはまず各テスト ケースを読み取り、隣接する黒トークンの位置の差を計算します。 これらの違いは、トークンが隣接しているか離れているかをエンコードします。 サイズ 1 のギャップは、シフトによって削除できるため、構造的な XOR に寄与しないマージ可能な境界として扱われます。 

残りのギャップは、不変セグメントを定義する独立したセパレータのように動作します。 それらの値は単一のアキュムレータに XOR 演算され、一連の有効な移動によって削除できない強制構造を表します。 この累積された XOR がゼロの場合、セグメンテーションをペアにしてすべての寄与をキャンセルできます。 そうしないと、少なくとも 1 つの不可逆的な不均衡が残ります。 

微妙な点は、実際の動きを決してシミュレートしていないことです。 すべての推論は静的ギャップ分析に押し込まれます。 これが、ソリューションが制約内に収まる唯一の理由です。

 ## 特殊なケース

 n = 1 の場合、構造を変える可能性のある手はないため、スコアは固定され、答えは常に NO になります。 アルゴリズムはギャップを計算する前にこれを明示的に処理します。 

すべての位置が連続している場合、すべてのギャップは 1 であるため、構造的な XOR は累積されず、答えは YES になります。 これは、すべてが 1 つのセグメントに折りたたまれる、完全にマージ可能な構成に対応します。 

すべてのギャップが大きい場合、トークンのすべてのペアは永久に分離されます。 XOR は孤立したシングルトンの寄与の組み合わせとなり、アルゴリズムはギャップによって引き起こされるすべての成分をキャンセルせずに累積することによってこれを反映します。
