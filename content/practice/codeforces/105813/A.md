 ## 解決策
 ## 問題の理解

 固定長のバイナリ文字列の大規模なコレクションを構築するように求められます。$n$、選択された 2 つの文字列がどのように異なるかについて 1 つの制限があります。 

各文字列は 0 と 1 で構成されます。 禁止されている状況は、2 つの異なる文字列がちょうど 1 つの位置で異なる場合です。つまり、1 ビットを反転するだけで一方をもう一方に変えることができます。 同様に、ハミング距離が正確に 1 になることはありません。 

タスクは、値を最適化したり、クエリに答えたりすることではなく、この制約を満たす可能な最大のセットを明示的に出力することです。 

制約$n \le 15$の全空間を示唆しています$2^n$string は、ペアごとのチェックをシミュレートするのではなく、構造的に推論するのに十分なほど小さいです。 文字列のすべてのペアを比較する単純なアプローチでは、約$2^n$候補者と$O(2^{2n})$ペアチェック、これはすでにボーダーラインです$n=15$それはおよそ10億回の比較を意味するからです。 

微妙なエッジケースが現れるのは、$n=1$。 文字列は「0」と「1」の 2 つだけで、正確に 1 つの位置が異なります。 これは、両方を採用することはできず、正しい解はいずれか 1 つだけを出力する必要があることを意味します。 このケースを確認せずに対称パターンまたはパリティ パターンを仮定する不注意な構築では、両方の文字列が誤って出力される可能性があります。 

大型の場合$n$、小さな例で構造を明確にします。 のために$n=2$、最適な答えは$\{00, 11\}$。 ペア$\{01, 10\}$も同様に有効ですが、00 は 1 ビットで 01 と異なるため、これらのペアのいずれかを混合するとルールに違反します。 

これは、バイナリ文字列の超立方体グラフにおける隣接関係が実際の制約であることを示唆しています。セット内にエッジのない最大の頂点セットを選択しています。 

## アプローチ

 ブルート フォースの観点では、各バイナリ文字列をノードとして扱います。$n$-次元超立方体グラフ。エッジは正確に 1 ビット異なる文字列を接続します。 問題は、内部エッジのない頂点の最大のサブセットを選択することになります。これは、このグラフにおける古典的な最大独立集合問題です。 

直接的なブルート フォースでは、頂点のすべてのサブセットが列挙され、有効性がチェックされます。 と$2^n$頂点、サブセットの数は$2^{2^n}$、たとえそれが完全に不可能になります。$n=5$。 選択したサブセット内のペアごとの競合のチェックに限定しても、指数関数的な爆発につながります。 

重要な構造的観察は、超立方体が二部構成であるということです。 バイナリ文字列はビット数のパリティによって分類できます。 1 ビットを反転すると常にパリティが変更されるため、すべてのエッジが偶数パリティ文字列を奇数パリティ文字列に接続します。 これにより、グラフ全体が、パーティション内にエッジが存在しない 2 つの独立したパーティションに分割されます。 

これが認識されると、最大の独立セットは、単にハイパーキューブ内のサイズが等しい 2 つのパーティションのうちの大きい方になります。 したがって、すべての偶数パリティ文字列またはすべての奇数パリティ文字列のいずれかが有効な最適解を形成し、両方ともサイズがあります。$2^{n-1}$。 

これにより、タスクがサブセットの組み合わせ検索からパリティに基づく決定論的な構築に軽減されます。

 ## アルゴリズムのチュートリアル

 最適な構築は、すべてのバイナリ文字列を偶数または奇数の 1 が含まれるかどうかによってグループ化し、1 つのグループを完全に選択することに依存します。 

1. 0 から 0 までのすべての整数を反復処理します。$2^n - 1$。 各整数は、長さのバイナリ文字列を表します。$n$。 このエンコーディングにより、文字列操作を行わずに直接ビット操作が可能になります。 
2. 各数値について、1 に設定されているビットの数をカウントします。このカウントにより、文字列が偶数パリティ クラスに属するか奇数パリティ クラスに属するかが決まります。 
3. 応答セットとしてパリ​​ティ クラスを 1 つ選択します。 すべてゼロの文字列が含まれ、実装が単純になるため、すべての文字列を偶数パリティにするのが自然な選択です。 
4. 選択したクラスとパリティが一致するすべての数値を、次の長さのバイナリ文字列に変換します。$n$そしてそれを保管します。 
5. このセットのサイズに続いてすべての文字列を出力します。 

明らかでない部分は、なぜパリティで十分なのかということです。 その理由は、単一ビットを反転すると常にパリティが切り替わるため、同じパリティ クラス内の 2 つの文字列は少なくとも 2 つの位置が異なっている必要があるためです。 これにより、明示的なチェックを行わなくても、制約が自動的に満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    res = []
    for mask in range(1 << n):
        if bin(mask).count("1") % 2 == 0:
            res.append(mask)

    print(len(res))
    for mask in res:
        s = format(mask, f"0{n}b")
        print(s)

if __name__ == "__main__":
    solve()
```このソリューションはすべてのビットマスクを反復処理し、パリティによってフィルター処理します。 変換ステップでは、固定幅のバイナリ形式を使用して先頭のゼロを保持します。これは、短い文字列が正しく解釈されないため必要です。 

実装の微妙な詳細の 1 つは、次の方法でビットをカウントすることです。`bin(mask).count("1")`には十分です$n \le 15$ただし、より高度な制約では、次のような高速な組み込みが使用されます。`bit_count()`の方が望ましいでしょう。 ここではパフォーマンスは重要ではありません。 

もう 1 つの重要な点は、文字列の長さを正確に維持することです。$n$先行ゼロを省略すると、個別の頂点があいまいな表現に崩壊してしまうためです。

 ## 特殊なケース

 のために$n = 1$、「0」と「1」の 2 つの文字列のみが存在します。 「1」は奇数パリティ、「0」は偶数パリティであるため、パリティ構築ではそのうちの 1 つだけを選択します。 このアルゴリズムは、厳密に 1 つの位置で異なるペアは存在できないという制約に一致する、厳密に 1 つの文字列を出力します。 

のために$n = 2$、フルセットは 2 つのパーティションにきれいに分割されます。 アルゴリズムは正確に {00, 11} を選択します。 単純な実装がグローバル構造をチェックせずに文字列を貪欲に含めようとした場合、01 と 00 は 1 ビット異なるため、誤って一緒に含めてしまい、ルールに違反する可能性があります。 

のために$n = 3$、隣接関係はより密になりますが、パリティにより分離が保証されます。 選択したセット内のすべての文字列は、少なくとも 2 つのビット位置で他の文字列と異なります。これは、000 と 011 などの代表的なペアを直接比較することで検証できます。 

この構築では、ペアについてローカルに推論することはなく、ハイパーキューブのグローバル パリティ構造についてのみ推論するため、そのような落とし穴はすべて回避されます。
