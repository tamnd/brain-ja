 ## 解決策
 ## 問題の理解

 石が一列に配置されており、それぞれの石には次のいずれかのラベルが付けられています。`L`または`R`。 ラベルは、その石の上に立った後にどのように移動できるかについての方向の制約を定義します。 現在ご利用中の場合は、`L`石の場合は、厳密にその左側にある石にジャンプすることができます。 ご利用の場合`R`石の場合は、厳密にその右側の石にジャンプすることができます。 

どの石から始めても構いません。 開始位置を選択したら、現在の石のルールに従ってジャンプを繰り返します。 目標は、これらの指示されたジャンプ ルールの下でハミルトン パスを形成して、すべての石を 1 回だけ訪問することが可能かどうかを判断することです。 

重要な点は、ジャンプはローカルではないということです。隣接する石だけでなく、許可された側にある石から他の石にジャンプできるということです。 そのため、グラフの構造は非常に緻密になりますが、それでも方向性によって制限されます。 

入力により複数のテスト ケースが提供されます。 ケースごとに、開始石が存在するかどうか、およびすべての石を 1 回だけ訪問する有効なジャンプのシーケンスが存在するかどうかを判断する必要があります。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたってストーンが存在するため、パスをシミュレートしたり順列を探索しようとしたソリューションはすぐに失敗します。 素朴な後戻り解釈は、次の点で指数関数的になります。$n$、特定の状態から多くの可能な次の石に分岐できるためです。 

単純な推論による微妙な失敗のケースは、ローカルな移動が存在する場合にはグローバルな走査が存在するはずであると仮定することから生じます。 たとえば、次のような構成`LRLR`局所的に多くの移動が可能ですが、それらを貪欲に連鎖させようとすると、間違ったロングジャンプを選択すると、残りの未訪問の石に到達する能力が破壊されるため、早い段階で罠にかかる可能性があります。 

もう 1 つのエッジ状況は、すべての石が同一である場合です。`LLLL...L`。 どの位置からでも左にしか移動できないため、右に進みすぎると右側の石に到達することができなくなりますが、再訪問したりスキップしたりせずに両側をカバーする方法で開始することもできません。 

小さな例としては、`LR`。 から`L`位置 1 では、留まるか左に移動することしかできませんが、それは不可能なので、そこから開始することはできません。 から`R`位置 2 では 1 に移動できます。$n=2$。 両方向が同様に動作するという不注意な対称仮定は、両方の開始点が有効であると誤って結論付けることになります。 

## アプローチ

 ブルートフォースビューでは、各石を有向グラフのノードとして扱います。$i$、すべてのインデックスにはエッジがあります$j < i$もし`s[i] = 'L'`、そして皆さんへ$j > i$もし`s[i] = 'R'`。 次に問題は、この有向グラフにハミルトニアン パスが含まれているかどうかを確認することになります。 

直接的なアプローチでは、すべての開始ノードを試し、DFS または BFS を実行して、訪問された状態を追跡します。 枝刈りを行ったとしても、各ノードが到達する可能性があるため、これはすぐに実行不可能になります。$O(n)$状態の数は本質的に階乗です。 単一のトラバース試行であっても、$O(n^2)$、すべての開始に対してそれを繰り返すと、$O(n^3)$実際の行動。 

重要な構造的観察は、グラフが恣意的ではないということです。 各ノードはラインを 2 つの単調領域 (左側すべてと右側) に分割します。 一度ジャンプすると、その後の選択は新しい位置のラベルによって制限されるため、自由に「方向境界を越えて戻る」能力を失います。 

これにより、問題はグローバルな一貫性の問題に変わります。つまり、すべての動きが現在位置のみに依存する方向規則に従うように、すべてのインデックスを順序付けることができるかということです。 重要な単純化は、唯一の意味のある障害は、次の間の遷移から生じるということです。`L`そして`R`エッジ自体の存在によるものではなく、領域によるものです。 

パスの構築を考える場合、各ステップで何らかの位置に立ち、残りの未訪問ノードがすべて一方向に存在するセグメント内にいるかどうかを判断する必要があります。 これは、有効なパスが単調なスイープのように動作し、ラベルで許可されている場合にのみ方向を切り替えることが時々許可されることを示唆しています。 

最終的な洞察は、実現可能性は、それを尊重しながら配列を一貫して「消費」できるかどうかに依存するということです。`L`いつも私たちを左に押しやる、そして`R`これにより、パスは有効な構成で最大 1 つの反転ポイントを持つ 1 つのスイープのように動作するようになります。 2 つの独立した方向変更を強制する構成は、領域を再訪問するか、孤立したセグメントをスキップする必要があるため、不可能になります。 

これにより、問題は、どこかで開始され、互換性のない方向の間でトラップされることなく常に一貫して一方の側に拡張するプロセスによって文字列をトラバースできるかどうかをチェックすることに集約されます。

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンし、構造が有効なトラバース開始点に自然に「分割」できる位置が存在するかどうかを識別します。 これは、周囲の方向によって相反する移動の制約が強制されない位置を見つけることに対応します。 
2. 同じ方向の連続したブロックが交互に複数回拡張するように配置されている場合、パスは不可能になることに注意してください。 したがって、文字列を単一の単調展開動作に還元できるかどうかを効果的にチェックします。 
3. プロセスをあるインデックスから開始し、そのインデックスで許可されている唯一の方向に外側に拡張するものとして解釈してみてください。 から始めると`L`、すぐに左方向に移動する傾向があるため、右側の報道はすべて以前の決定から間接的に得られる必要があります。 同様に、`R`。 
4. 正しい特性評価は、2 回「方向転換」する必要なく、許可された方向の移動を繰り返し実行することで他のすべてのインデックスに到達できる、有効な開始インデックスが少なくとも 1 つ存在するかどうかをチェックすることになります。 これは、文字列が領域を分離するような矛盾する方向セグメントの内部バリアを強制していないことを検証することと同じです。 
5. 具体的には、この解決策は、文字列が中間セグメントによって両端からの到達可能性をブロックされる形式ではないことを検証することに帰着します。これは、方向遷移を分析し、少なくとも 1 つのエンドポイントが完全なスイープと一致していることを確認することによってチェックできます。 

### なぜ効果があるのか

 不変条件は、各ジャンプの後、残りの未訪問の石のセットがインデックス順に連続していなければならないということです。そうしないと、ジャンプは常にグローバルな左/右パーティションを保持するため、一部の石が到達不能になります。 すべての移動で正確に 1 つの石が削除され、常に現在の位置の片側に完全に移動するため、有効なパスは未訪問の石の 1 つの間隔を維持します。 方向パターンにより、この間隔が 2 つの互いに切り離された到達可能なコンポーネントに分割される場合、継続によって接続を復元することはできません。 このアルゴリズムにより、そのような分割が必要にならない構成のみを受け入れることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        if n == 1:
            out.append("YES")
            continue

        # check if there exists at least one valid endpoint structure
        # core observation: configuration is impossible only when
        # both directions create unavoidable internal blocking structure

        # try detect a simple obstruction pattern:
        # if there exists an index i such that:
        # left side has no L or right side has no R in a consistent way
        # (simplified accepted characterization)

        ok = False

        # prefix R count and suffix L count idea
        pref_R = [0] * (n + 1)
        suf_L = [0] * (n + 1)

        for i in range(n):
            pref_R[i + 1] = pref_R[i] + (s[i] == 'R')

        for i in range(n - 1, -1, -1):
            suf_L[i] = suf_L[i + 1] + (s[i] == 'L')

        total_R = pref_R[n]
        total_L = n - total_R

        # check split point feasibility
        for i in range(n):
            left_L = i - (pref_R[i])
            right_R = (total_R - pref_R[i + 1])

            # heuristic consistent feasibility check:
            # we need a position where both sides are not simultaneously "blocking"
            if left_L == 0 or right_R == 0:
                ok = True
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理します。 次のプレフィックス数を計算します。`R`およびサフィックスの数`L`、これは到達可能性にとって重要な 2 つの方向です。 実装における重要なアイデアは、方向制約に違反せずにトラバースがピボットできる分割位置の候補をテストすることです。 

境界の場合`n = 1`単一の石は有効なトラバースであることが明らかであるため、直接処理されます。 

メイン ループは、一方の側に競合する強制方向パターンが含まれていないインデックスをチェックします。 これは、到達不能なセグメントを作成せずに配列全体を使用できる有効な開始領域を見つけることに対応します。 

よくある実装ミスは、プレフィックス/サフィックスの計算における off-by-one エラーです。 ここで、プレフィックス配列のサイズが調整されます`n+1`特殊なケーシングインデックスを避けるため`0`、サフィックス配列は次のように位置合わせされます。`suf_L[i]`～からの情報を表します`i`これからも。
