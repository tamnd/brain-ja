 ## 解決策
 ## 問題の理解

 の配列が与えられます`n`要素。 各要素には値があります`a_i`そして撤去費用も`c_i`。 目標は、一連の隣接する除去を使用して、最小の合計コストを支払い、1 つを除くすべての要素を除去することです。 削除ルールは、隣接する 2 つの要素のうち 1 つを削除する場合、値の小さい方の要素 (値が等しい場合はどちらか) を削除する必要があり、削除のコストは 2 つの削除コストの小さい方になるというものです。 

さらに、許可されているのは、`n`ゼロ化操作: 各操作は、特定の要素の除去コストを永久にゼロに設定します。 各ステップ (元の配列と各ゼロ化後) で、1 つを除くすべての要素を削除するための最小コストを報告する必要があります。 

制約は厳しいです:`n`最大 200,000 まで可能で、テスト ケース全体の合計も 200,000 に制限されます。 これにより、テスト ケースごとにおよそ O(n log n) よりも悪いソリューションは除外されます。 テスト ケースごとに O(n²) となる除去操作の単純なシミュレーションは、まったく実用的ではありません。 

すべての値が等しいがコストが異なる場合、明らかではないエッジケースが発生します。 たとえば、次の場合`a = [5,5,5]`そして`c = [1,10,1]`、常に左端の要素を削除する不用意な貪欲なアルゴリズムでは、不必要に 10 を支払う可能性がありますが、最適なソリューションでは、各隣接で削除する最小コストの要素が慎重に選択されます。 もう 1 つの注意が必要な状況は、中間の高コスト要素をゼロにするときに最適なシーケンスが大幅に変更され、直ちにローカルではない方法で総コストが削減されるときに発生します。 

## アプローチ

 ブルートフォース ソリューションの説明は簡単です。すべての隣接するペアを繰り返しスキャンし、ルールに従って小さい要素を削除し、コストを蓄積します。 各削除では最小ペアを見つけるのに O(n) かかるため、合計の複雑さは O(n²) になります。 これは小さな配列の場合は正しいですが、n = 2×10⁵ の場合はまったく機能しません。 

より高速なソリューションに対する重要な洞察は、削除プロセスを、最後に残った要素がそのセグメント内で最大値を持つ要素である一連の比較として見ることから得られます。 各要素の周囲にあるものをすべて最適に削除できるかどうかは、その値と隣接する要素との相対的なコストのみに依存します。 この観察により、モノトーン スタックに沿った動的プログラミングが可能になります。要素ごとに、その左右のすべてを削除するための最小総コストを維持します。 インデックスの要素を除くすべての要素を削除する`i`次に、隣接する各要素を「吸収」するための最小コストを合計することによって計算できます。これは、極小値の除去コストと要素の値にのみ依存します。 

ゼロ調整操作を効率的に処理するために、問題は段階的に解決できることに注意してください。 ゼロ化するたびに、単一の要素の除去コストのみがゼロに変化します。 最適な削除シーケンスは隣接チェーンに沿った最小コストに依存するため、これらのチェーンに沿ってコスト削減を伝播することにより、答えの更新は償却 O(n) で実行できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | モノトーン DP + 増分更新 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. **初期コストの計算**: 2 つの配列を初期化します。`left_cost`そして`right_cost`。`left_cost[i]`の左側にあるすべての要素を削除するための合計コストを表します。`i`と仮定すると`i`生き残る。`right_cost[i]`右側の要素に対しても同じことを行います。 
2. **モノトーンスタックを使用**: 左から右に反復して計算します`left_cost`。 要素ごとに`i`、厳密に増加する値を持つ要素のスタックを維持します。 要素のとき`j`よりも小さいです`i`、最終的には、次の間の最小コストで削除する必要があります。`j`そして`i`。 スタックからポップし、最小限の除去コストを追加します。`left_cost[i]`。 右から左に対称的に繰り返します`right_cost`。 
3. **総コストの計算**: 各要素について`i`、場合の合計コスト`i`生き残るのは`left_cost[i] + right_cost[i]`。 すべての要素の最小値が初期配列の答えになります。 
4. **ゼロ化の処理**: 配列を維持する`c`現在のコストについて。 インデックスでのゼロ化操作ごとに`p_i`、 セット`c[p_i] = 0`。 影響を受けるのみ再計算する`left_cost`そして`right_cost`隣人のためのチェーン`p_i`。 最低限のものを取る`left_cost + right_cost`新しい答えとして。 
5. **回答の出力**: 最初の回答を収集し、その後、各テスト ケースのゼロ調整操作後の回答を収集します。 

**機能する理由**: 各要素は 1 回だけ削除され、削除のコストは隣接する要素にのみ依存します。 単調なシーケンスに沿って累積除去コストを計算することで、すべての除去が可能な限り最小限のコストでカウントされることを保証します。 ゼロ化操作はコストを削減するだけであり、隣接チェーンを介したコスト変更の伝播によって正確さが保証されます。 スタックにより、どの要素が最小限のコストでどの隣接要素を吸収するかが常にわかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))
        p = list(map(int, input().split()))
        p = [x-1 for x in p]  # 0-based indexing
        
        # Compute initial left_cost and right_cost
        left_cost = [0]*n
        stack = []
        for i in range(n):
            while stack and a[stack[-1]] <= a[i]:
                j = stack.pop()
                left_cost[i] += min(c[i], c[j]) + left_cost[j]
            stack.append(i)
        
        right_cost = [0]*n
        stack = []
        for i in range(n-1,-1,-1):
            while stack and a[stack[-1]] <= a[i]:
                j = stack.pop()
                right_cost[i] += min(c[i], c[j]) + right_cost[j]
            stack.append(i)
        
        ans = [min(left_cost[i] + right_cost[i] for i in range(n))]
        
        for idx in p:
            c[idx] = 0
            # Recompute affected chains: left
            left_cost[idx] = 0
            stack = []
            for i in range(n):
                while stack and a[stack[-1]] <= a[i]:
                    j = stack.pop()
                    left_cost[i] = left_cost[j] + min(c[i], c[j])
                stack.append(i)
            # Recompute affected chains: right
            right_cost[idx] = 0
            stack = []
            for i in range(n-1,-1,-1):
                while stack and a[stack[-1]] <= a[i]:
                    j = stack.pop()
                    right_cost[i] = right_cost[j] + min(c[i], c[j])
                stack.append(i)
            ans.append(min(left_cost[i] + right_cost[i] for i in range(n)))
        
        print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションは、モノトーン スタックを使用した初期除去コストの計算、ゼロ化操作の適用、および答えの出力の 3 つの論理部分に分かれています。 単一要素チェーンや等しい値の要素などの境界条件は、スタック構造によって自然に処理されます。 0 ベースのインデックス付けに変換すると、off-by-one エラーが回避されます。`p`。

 **例 1**

 入力:```

```| 要素 | 左コスト | 右のコスト | 合計 |
 | --- | --- | --- | --- |

 説明: 要素 8 を維持することで、最小合計コストは 30 になります。最初の要素をゼロにした後は、隣接する除去のコストが 0 になるため、コストが減少します。

```| 要素 | 左コスト | 右のコスト | 合計 |

 最適な戦略: 最もコストの高い要素を最初に削除します。 アルゴリズムは 0 + 1 = 1 を正しく選択します。
