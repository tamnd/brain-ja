 ## 解決策
 ## 問題の理解

 次から構成されるバイナリ文字列が与えられます。`0`と`1`s、少なくとも 1 つ`1`。 目標は、この文字列をすべての文字列に変換することです。`1`s. これを達成するには、シフトを繰り返し選択できます`d`そして、次のように文字列の循環右シフトを実行します。`d`。 シフトされた文字列内のすべての位置に対して、`1`、元の文字列内の対応する位置は次のように設定されます。`1`。 各操作に正確なコストがかかります`d`文字列全体をコインに変換するために必要な総コストを最小限に抑えたいと考えています。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、文字列と文字列自体の長さを指定します。 テスト ケース全体のすべての文字列の長さの合計は、最大でも`2 × 10^5`。 これにより、二次関数であるアルゴリズムが即座に除外されます。`n`なぜなら、おおよそ最大で`4 × 10^10`最悪の場合は操作が可能になりますが、これは 2 秒の制限時間には大きすぎます。 テスト ケースごとにほぼ直線的またはほぼ直線的な時間で実行されるソリューションが必要です。 

明らかではないエッジ ケースの 1 つは、すでにすべて 1 である文字列です。`111`。 この場合、最小コストはゼロにする必要があります。 もう 1 つは、次のような、孤立したゼロが 1 で囲まれた文字列です。`10101`。 ゼロ間の間隔を考慮せずに単純にシフトを選択すると、必要以上にコストが高くなる可能性があります。 同様に、次のような文字列の場合、`100001`、ゼロの最大ギャップが必要な最小シフトを支配することを認識する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能なシフトを試みることが考慮されます`d`から`1`に`n`、巡回シフトを実行し、元の文字列を更新し、すべての要素が 1 になるまでコストを累積します。 操作定義では、シフトを繰り返し適用するとシフトが伝播されることが保証されているため、これは正しく機能します。 ただし、最悪の場合には、`n`まで`2 × 10^5`、このアプローチには大まかに必要になります`O(n^2)`1 つのテスト ケースの操作では遅すぎます。 

最適な解決策の重要な観察点は、文字列をすべて 1 に変換するコストは、最大の連続するゼロのブロックのみに依存するということです。 ゼロのシーケンスは、シフトによって 1 がゼロの 1 つと整列する場合にのみ 1 に変えることができます。 したがって、問題を、任意の 1 から次の 0 までの最大距離を計算することに減らすことができます (循環ラッピングを考慮)。 最小コストは、最大のゼロ ブロックの長さの半分の上限に等しくなります。 これは、サイズの 1 回の操作だからです`d`1 を伝播できる`d`位置なので、ブロックをカバーします`k`ゼロには少なくとも必要です`ceil(k / 1)`最悪のアライメントでのステップ。 

言い換えれば、ゼロの最長連続セグメントが最小値を決定します。`d`私たちは選択しなければなりません。 このセグメントをカバーすると、他のすべてのものが自動的に伝播されます。 これにより、複雑さが軽減されます。`O(n)`テスト ケースごとに、単純に最長のゼロのブロックをスキャンし、循環ラップを考慮します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、バイナリ文字列を読み取ります。`s`。 
2. ゼロの位置をすべて特定します。 文字列を円形として扱い、終端と始端を接続します。 
3. 最も長く連続するゼロのブロックの長さを見つけます。 これには、文字列の 1 回のスキャンが含まれ、連続するゼロをカウントし、これまでに見つかった最大値と比較します。 循環性を処理するには、文字列がゼロで始まりゼロで終わる場合、それらのカウントを 1 つのブロックとして合計します。 
4. 最大のゼロブロックの長さの半分を上限として最小コストを計算します。 これが機能するのは、1 つのシフトで最大の範囲をカバーできるためです。`d`1 回の操作で位置を調整できます。 
5. 計算された最小コストを出力します。 

機能する理由: このアルゴリズムが機能するのは、すべてのゼロをカバーするために 1 が伝播しなければならない最小距離が最大のゼロ ブロックによって決まるためです。 より小さなブロックは、同じシフトまたはより小さなシフトによって自然にカバーされます。 シーリング演算により、伝播は 1 回のシフトで双方向であるため、奇数長のゼロ ブロックが正しく処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        # Handle case where string is already all ones
        if '0' not in s:
            print(0)
            continue
        
        # Duplicate string to handle cyclic property easily
        doubled = s + s
        max_zeros = 0
        count = 0
        
        for ch in doubled:
            if ch == '0':
                count += 1
                max_zeros = max(max_zeros, count)
            else:
                count = 0
        
        # Since doubled, max_zeros could be up to 2*n, we clamp to n
        max_zeros = min(max_zeros, n)
        print(math.ceil(max_zeros / 2))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、すでにすべて 1 である文字列がないかチェックし、すぐに 0 を返します。 文字列の循環的な性質を処理するために、文字列を複製し、連続するゼロをスキャンして最大数を取得します。 2 倍にすることで、末尾を囲むゼロが 1 つの連続したブロックとして扱われるようになります。 最後に、最小コストをこのブロックの長さの半分として計算し、必要に応じて切り上げます。

 ## 特殊なケース

 ゼロを含む長さ 1 の文字列の場合、次のようになります。`0`、アルゴリズムは文字列を次のように複製します。`00`、連続するゼロを 2 としてカウントし、n=1 にクランプし、ceil(1/2)=1 を計算します。 これはコスト 1 を正しく返します。次のようなゼロが末尾を囲む文字列の場合`1001`、収量の重複`10011001`、二重化された文字列内の最大連続ゼロは 2 で、最小コストは 2 と正しくなります。これは、循環性の処理が正しいことを示しています。
