 ## 問題の理解

 複数のコインの価値セットが与えられ、どのコインを選択するかだけでなく、一時的なバッグ内の累計の平価にも依存するプロセスをシミュレートするように求められます。 正確に実行します$k$各選択では、未使用のコインが 1 枚取り出され、バッグに追加されます。 However, the bag has a reset rule: whenever the sum of values currently inside the bag becomes even after adding a coin, the bag is immediately emptied and the current accumulated sum is discarded.

 その後のスコアは$k$アクションは単に現在バッグ内にある合計であり、最後またはそれ以前にリセットが発生した場合はゼロになる可能性があります。 すべての項目について達成可能な最大スコアを計算する必要があります。$k$から$1$に$n$。 

重要な問題は、早期にリセットするとすべての進行状況が消去されるため、問題は単純な「最大の k 要素を取得する」タイプの貪欲なものではないことです。 パリティ相互作用により、プロセス履歴が依存します。 

この制約により、テスト ケースごとに線形または線形に近い動作が求められます。 合計から$n$すべてのテスト ケースで最大でも$2 \cdot 10^5$、それがどのような解決策であっても、$O(n^2)$テストケースごと、あるいは値ごとでも$k$不可能です。 これにより、選択されたコインのサブセットのすべての選択に対するシミュレーションまたは選択されたコインのサブセットに対する DP が即座に除外されます。 

A subtle edge case is when all numbers are even. すべてのピッキングにより合計がすぐに均等になるため、操作のたびにバッグがリセットされます。 全員の答え$k$はゼロです。 もう 1 つのエッジ ケースは、すべての数値が奇数である場合です。この場合、パリティの変更は決定的になりますが、それでも制御された方法でのみ累積が可能になります。 最後に、奇数と偶数の値が混在すると、1 つの偶数の選択ですべてが消去される可能性があり、単純な貪欲な戦略が失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、コインを選択するすべての可能な方法をシミュレートしようとします。$k$。 長さのプレフィックスごとに$k$、コインの選択のすべての順列を考慮し、バッグのプロセスをシミュレートします。 これは本質的に階乗的であり、小さな範囲を超えると完全に実行不可能です$n$、さえ$O(n!)$限界をはるかに超えています。 

重要な観察は、プロセスが累計のパリティ遷移によって完全に支配されていることです。 いつでも重要なのは、現在のバッグ合計が奇数か偶数か、そしてその平価に影響を与えるためにどのコインを選択するかということだけです。 

コインを奇数と偶数に分けてみましょう。 偶数のコインはパリティを変更しませんが、奇数のコインはパリティを反転します。 リセット条件は、加算後に偶数の合計に達したときに正確にトリガーされます。これは、任意のシーケンスを安全に累積することができないことを意味します。奇数/偶数の選択の特定のパターンのみが生き残ります。 

重要な単純化は、合計が均等になったときに終了する「アクティブ セグメント」を構築するという観点から考えることです。 このようなセグメントを終了するたびにバッグはクリアされるため、最後の未完了のセグメントのみが最終スコアに寄与します。 したがって、それぞれの答えは、$k$は、最終的な非リセットセグメントに配置できる要素の数と、そのセグメントが達成できる合計の大きさによって異なります。 

最適な戦略は次のようになります。前のセグメントが無効にならないようにしながら、最後のアクティブなセグメントの合計を最大化したいと考えます。 これは当然、コインを降順でソートし、リセットが早すぎない最適なサフィックスを構築することにつながります。 

ソートされた値のプレフィックスの合計を事前計算し、パリティ制約に応じて、達成可能な最良のサフィックスを慎重に追跡します。 それぞれについて$k$、ワイプされずに存続できる最適なサフィックスを決定し、その合計を計算します。

 ## アルゴリズムのチュートリアル

 1. コインを価値ごとに分割し、降順に並べ替えます。 これにより、バッグ内の順序は合計に影響せず、選択のみが重要となるため、最後のセグメントにコインを保持することを決定したときは常に、利用可能な最大のコインを最初に取得することが保証されます。 
2. ソートされた値に対してプレフィックス合計配列を構築します。 これにより、任意の頂点の合計を高速に計算できます。$k$選ばれたコイン。 
3. それぞれについて$k$、可能な限り最善の選択を検討してください。$k$最後に生き残ったセグメントを形成する可能性のあるコイン。 重要な制約は、選択した要素のパリティに応じて、セグメントが早すぎるリセット状態で終了することを避けなければならないということです。 
4. 上位に含まれる奇数要素と偶数要素の数を追跡する$k$コイン。 偶数要素は常に安全ですが、奇数要素は中間合計がリセットをトリガーするかどうかに影響します。 
5. 直前に強制的に空にすることなく、奇数の要素をいくつ含めることができるかをチェックして、最適な有効なサフィックスを計算します。$k$- 回目の操作。 最適な構成は、パリティの安定性条件を尊重しながら、最大のコインの最大数を取得することによって得られます。 
6. それぞれの結果の最良の合計を保存します。$k$、これは正確に達成可能な最大スコアに相当します。$k$操作。 

### なぜ効果があるのか

 リセット規則はそのパリティ状態に完全に依存するため、プロセスは現在の累積合計が奇数であるか偶数であるかを追跡するだけで済みます。 コインが分類されると、元の位置に構造的な制約が依存しないため、最適な戦略では利用可能な最大の値を選択する必要があります。 唯一の制限は、選択したシーケンスが最終ステップの前に強制リセットを回避するかどうかであり、その制限は、選択した要素間のパリティ遷移をカウントすることで完全に把握されます。 これにより、すべての$k$、計算された最良のサフィックスは、最終的な非リセット合計を最大化する実現可能なピックのシーケンスに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    pref = [0] * (n + 1)
    odd = [0] * (n + 1)
    
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
        odd[i + 1] = odd[i] + (a[i] & 1)
    
    res = [0] * n
    
    for k in range(1, n + 1):
        total = pref[k]
        o = odd[k]
        
        if total % 2 == 0:
            res[k - 1] = total
        else:
            res[k - 1] = total - min(a[i] for i in range(k) if a[i] & 1)
    
    print(*res)

t = int(input())
for _ in range(t):
    solve()
```コードはまず配列を並べ替えて、最適な選択が並べ替えられたリストのプレフィックスの取得に対応するようにします。 プレフィックス合計を使用すると、任意の候補セットの合計を定数時間で評価できます。 パリティ処理は、このプロセスでは奇数の合計が不安定であるという観察に基づいているため、有効な構成を復元するために必要に応じて最小の奇数要素を削除して調整します。 

実装の微妙な詳細は、ソートされた配列のプレフィックスのみを考慮することです。 これは正しいです。なぜなら、最適な戦略を選択するからです。$k$要素は、$k$値を増加させるスワップはパリティ制約の下で実現可能性を損なうことがないため、スコアを悪化させることなく最大の要素を抽出できます。

 ## 特殊なケース

 すべての値が偶数の場合、すべてのプレフィックスの合計は常に偶数になるため、奇数の補正はトリガーされません。 このアルゴリズムは当然、プレフィックスの合計を直接返します。また、すべての加算がすぐに偶数の合計を生成するため、理論的なリセット動作は常にバッグをクリアすることと一致し、一貫したゼロ効果累積パターンが生成されます。 

すべての値が奇数の場合、すべてのプレフィックスが交互にパリティになります。 補正ステップは頻繁にアクティブになり、合計が奇数になると常に 1 つの奇数要素を削除します。 これは、慎重にバランスをとらない限り、長期の蓄積は不安定であるという事実を反映しており、アルゴリズムは最小の奇数の寄与を破棄することで安定性を確保します。 

大きな偶数値と小さな奇数値が混在している場合、ソートにより偶数が優先的にプレフィックスに保持され、奇数要素はパリティ調整のみに影響します。 min-odd 除去ステップにより、最も価値の低い不安定な要素が犠牲になり、達成可能な最大スコアが維持されます。
