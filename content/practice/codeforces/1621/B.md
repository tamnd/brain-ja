 ## 解決策
 ## 問題の理解

 この問題の各セグメントは、コストと対になった整数直線上の閉区間として考えるのが最も適切です。 Vasya がセグメントのセットを選択すると、少なくとも 1 つの選択された間隔に含まれるすべての整数が自動的に取得され、それらのコストの合計が支払われます。 

この構造を興味深いものにする追加のルールがあります。 セグメントを選択した後、Vasya が最小値と最大値を含む整数を持っている場合、選択したセグメントに属していない場合でも、既に取得された 2 つの値の間に厳密に含まれるすべての整数も無料で与えられます。 これは、選択されたセグメントが左端のカバーされた整数と右端のカバーされた整数を決定すると、Vasya はそれらの間の連続範囲全体を効果的に受け取ることを意味します。 

したがって、セグメントを選択した最終結果は、間隔の和集合ではなく、たとえ選択したセグメントが連続していない場合でも、カバーされる最小点からカバーされる最大点までの単一の連続したセグメントになります。 

目的は、セグメントのプレフィックスごとに、取得される整数の総数が最大化されるように、またこの数を最大化するすべての方法の中で総コストが最小化されるように、利用可能なセグメントのサブセットを選択することです。 

各プレフィックスの出力は、すべての最適な選択肢の中の最小コストにすぎません。 

制約は大きく、合計で最大 2⋅10^5 セグメントです。 これにより、すべてのサブセットを明示的に試行するソリューションは指数関数的となるため除外され、プレフィックスごとに最適なサブセットを最初から再計算するソリューションも少なくとも 2 次関数となるため除外されます。 

主な問題は、新しいセグメントを追加すると、達成可能な最適な間隔のエンドポイントが非ローカルな方法で変更される可能性があり、最適なソリューションを段階的に維持する必要があることです。 

微妙なエッジ ケースは、同一セグメントまたは優勢なセグメントから発生します。 2 つのセグメントの間隔は同じだがコストが異なる場合、最適な構築には最も安価なバージョンのみが重要になります。 もう 1 つのエッジ ケースは、長い間隔は高価であるが、2 つの安価な独立した領域を接続する場合にのみ必要となり、カバレッジとコストの両方が同時に変化する場合です。 

## アプローチ

 直接的なアプローチは、最初の s セグメントのすべてのサブセットを考慮し、結果の連続スパンを計算することです。 選択したサブセットについて、選択したセグメント間の最小 l と最大 r を取得し、答えはそれらのエンドポイントと総コストのみに依存します。 これにより、考えられる左右の境界を決定するすべてのサブセットを試すことになります。 

ただし、サブセットの数は 2^ であり、各サブセットのエンドポイントを計算することすら不可能です。 状態は多くの可能な間隔のエンドポイントを表す必要があるため、セグメントに対する動的プログラミングでも役に立ちません。 

重要な観察は、最終的にカバーされるセグメントは、どちらのセグメントが左側の境界を提供し、どれが右側の境界を提供するかによってのみ依存するということです。 選択した左端のセグメントと右端のセグメントを修正すると、それらの間にあるすべてのセグメントが使用可能になる可能性がありますが、完全なカバレッジを保証する最も安価な組み合わせのみが問題となります。 これにより、時間の経過とともに、間隔のエンドポイントをカバーする最適な方法を維持することが問題になります。 

より有用な再定式化は、候補となる左側の境界と右側の境界の間のすべての整数を確実にカバーするための最小コストを維持する観点から考えることです。 これは、任意のポイントをカバーする最も安価なセグメントを追跡し、セグメントが追加されるにつれてカバー範囲がどのように拡大するかを追跡することに帰着します。 

重要な単純化は、どのプレフィックスでも、最適なソリューションは常に、端点が極端な「有用な」セグメントによって決定される連続間隔のカバレッジを集合的に保証するセグメントを選択することに対応し、コストは必要な最も安価なコンポーネントの合計に分解できることです。

これは貪欲な構造につながります。つまり、どの時点でも、コストとカバレッジへの貢献の両方において他のセグメントより厳密に劣っていないセグメントのみを考慮することになります。 当社は、関連する境界構成ごとに最適な (最小コスト) セグメントを維持し、セグメントがグローバル カバレッジを拡大するときに、新しいエンドポイントに到達するためのコストが削減されるかどうかを確実に考慮します。 

標準ソリューションは、現在の「アンカー」として機能できるこれまでに確認された最も安価なセグメントを維持し、セグメントが現在の境界を超えて拡張する場合、または同じ境界に到達するためのコストを削減する場合の改善を追跡します。 セグメントを順番に処理する際、増分更新を使用して各プレフィックスに対して達成可能な最適な構成を維持します。

 ## アルゴリズムのチュートリアル

 カバーされる整数を最大化し、コストを最小限に抑える最もよく知られた構造を維持しながら、指定された順序でセグメントを処理します。 

1. これまで最適に達成できた最小の左エンドポイントと最大の右エンドポイントという 2 つの実行境界を維持します。 

これらは、当社が保証できる最高の継続的カバレッジのエンドポイントを表します。 
2. また、現在の最良の補償範囲を達成するために必要な最小限のコストも維持します。 
3. 新しいセグメントを処理するとき、それが左側の境界を改善できるかどうかを検討します。 その l が現在の最良の左境界よりも小さい場合、カバレッジが拡張される可能性があります。 その場合、最適なカバレッジの構造が変化するため、境界を更新してコストを再設定します。 
4. 同様に、その r が現在の最良の右境界よりも大きい場合、右側のカバレッジを拡張し、それに応じて境界構造を再度更新します。 
5. セグメントが現在の最適な間隔内に完全に収まる場合、カバレッジは増加しませんが、以前に必要だったセグメントよりも安価であれば、コストが削減される可能性があります。 その場合は料金を更新させていただきます。 
6. 各挿入後のプレフィックスの答えは、単純に現在の最良間隔エンドポイントに関連付けられたコストになります。 

微妙な点は、セグメントの組み合わせを明示的に列挙することは決してないということです。 代わりに、現在達成可能な最良のスパンを維持するための最も安価な方法を継続的に維持し、セグメントが境界またはコストのいずれかを改善した場合にのみ更新します。 

### なぜ効果があるのか

 重要な不変条件は、最初の s セグメントを処理した後、維持される間隔がそれらのセグメントのサブセットを使用して達成可能な最大連続カバレッジを表し、保存されるコストがその最大カバレッジを正確に達成するすべてのサブセットの中での最小コストであるということです。 

どちらの境界にも影響を与えないセグメントはカバレッジを向上させることができないため、コストにのみ影響するため、同じ領域をカバーする以前に使用されたセグメントよりも厳密に安価な場合にのみ関係します。 境界を拡張するセグメントは、その境界に到達しなかった以前の構成を厳密に支配するため、以前の最良の構成を新しい構成で安全に置き換えます。 

この優位性の特性により、後でより良い最終的な答えにつながる可能性のある構成を決して破棄することがなくなります。これは、将来の改善には境界をさらに拡張するか、同じ境界内のコストを削減する必要があり、その両方が追跡されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        INF = 10**30
        
        # current best left/right coverage
        L = 10**30
        R = -10**30
        
        # minimal cost for achieving current best span
        cost = 0
        
        # best cost for a segment achieving current extremal role
        best_left_cost = INF
        best_right_cost = INF
        
        ans = []
        
        for _ in range(n):
            l, r, c = map(int, input().split())
            
            # initialize if first segment
            if L > R:
                L, R = l, r
                cost = c
                best_left_cost = c
                best_right_cost = c
                ans.append(cost)
                continue
            
            # update boundary expansion
            if l < L:
                L = l
                cost = c
                best_left_cost = c
            elif r > R:
                R = r
                cost = c
                best_right_cost = c
            else:
                # inside current interval, may improve cost
                if c < cost:
                    cost = c
            
            ans.append(cost)
        
        print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このコードは、現在達成可能な最良の間隔エンドポイントを維持し、セグメントが範囲を拡張するたびにそれらを更新します。 セグメントが厳密に内側にある場合、それは潜在的なコスト改善としてのみ機能します。 前の間隔がないため、最初のセグメントは構造を初期化します。 

重要な点は、複数の内部セグメントを明示的に結合しようとしないことです。 正確さは、間隔を拡大するためには外側のセグメントのみが重要であり、内側のセグメントは厳密に安価な場合にのみコストに影響するという事実に依存しています。

def run(inp: str) -> str:

    import sys

    for _ in range(t):
        n = int(input())

        R = None

 ## 特殊なケース

 主なエッジケースは、複数のセグメントが重なり合っているものの、コストが異なる場合です。 たとえば、複数の同一の間隔が表示される場合、最小コストのバージョンのみが問題となります。 アルゴリズムは、セグメントが現在の最良の間隔内にある場合は常に、それより小さい場合にのみコストを更新し、境界を乱さないため、これを処理します。 

もう 1 つのエッジ ケースは、セグメントが両方の境界を同時に拡張する場合です。たとえば、単一ステップで新しい最小左と新しい最大右の両方になる場合です (初期化時または単一セグメントでのみ可能)。 この場合、アルゴリズムは両方のエンドポイントを正しくリセットし、そのセグメントを新しい基本構成として使用します。 

3 番目のエッジ ケースには、拡張には役に立たないが、有用なセグメントの前に現れるセグメントが含まれます。 処理は増分であるため、これらは後の境界拡張に干渉せず、現在のスパン内で有益な場合にのみコストに影響します。
