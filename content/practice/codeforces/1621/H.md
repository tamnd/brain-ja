 ## 解決策
 ## 問題の理解

 次のような接続された無向グラフが与えられます。`n`ノード。 各エッジは、2 つの都市間の鉄道または飛行機の接続を表します。 電車の移動コストは 1、飛行機の移動コストは 0 です。目標は、都市ごとに、場合によっては任意の数の飛行機のフライトを使用して、首都 (都市 1) に到達するために必要な電車の最小乗車回数を計算することです。 出力は都市ごとに 1 つの整数、つまり首都に到達するために必要な電車の最小乗車時間です。 

入力により、2 つのリストのエッジが得られます。1 つは電車用、もう 1 つは飛行機用です。 グラフは確実に接続されているため、各都市は飛行機と電車を組み合わせて首都にアクセスできます。 ノード数`n`2×10^5 までの大きさになる可能性があります。 2 秒の時間制限では、最大 4×10^10 の演算が必要になる可能性があるため、O(n^2) アプローチは避けなければなりません。 線形または線形に近い O(n + m) アルゴリズムが実現可能です。 

重要な点は、飛行機にはコストがかからないということです。 すべてのエッジを等しいものとして扱う単純な BFS では、ゼロコスト エッジと単位コスト エッジを区別する必要があるため、電車の乗車回数が過大にカウントされます。 たとえば、不注意に実装すると、飛行機に乗る場合でも首都から開始してすべての近隣の距離が 1 ずつ増加し、誤った結果が生じる可能性があります。 

エッジ ケースには、すべての都市が飛行機で首都に直接接続されているスター グラフが含まれます。正解は、すべての都市に電車がゼロです。 もう 1 つのエッジ ケースは、すべてのエッジが列車であるパスです。つまり、列車の最小数はパスに沿った距離に等しくなります。 コストを混在させることなく、同じ走査で両方のタイプを処理することが重要です。 

## アプローチ

 強引なアプローチでは、各都市から首都までのすべての経路を列挙し、各経路上の列車のエッジの数を数え、最小値を選択します。 これは正しいです。理論的にはグラフが十分に小さいため、徹底的な検索が可能ですが、`n`2×10^5 まではパスの数が指数関数的に増加するため、このアプローチは完全に実行不可能になります。 

重要な洞察は、電車の乗車のコストは 1、飛行機のコストは 0 であるということです。これはまさに、重みが 0 または 1 の重み付きグラフ上の最短経路問題です。古典的なダイクストラのアルゴリズムでも機能しますが、もっと良い方法があります。すべてのエッジの重みが 0 または 1 の場合、0 ～ 1 BFS を使用できます。 0-1 BFS は両端キューを使用し、エッジの重みが 0 の場合は前方に近傍を挿入し、エッジの重みが 1 の場合は後方に近傍を挿入します。これにより、線形 O(n + m) の走査が行われます。 この問題は、エッジの重みが慎重に処理されたグラフ上の単純な BFS に帰着します。 

ブルートフォースはすべてのパスを探索するため機能しますが、都市の数が多い場合は失敗します。 飛行機のエッジのコストがゼロであるという観察により、デックでそれらを異なる方法で扱うことができ、問題を O(n + m) の操作に減らすことができます。これは、`n`最大 2×10^5。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n^2) | 遅すぎる |
 | ディクストラ | O((n + m) log n) | O(n + m) | 承認済み |
 | 0-1 BFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを隣接リストとして表し、各隣接ノードをそのエッジ コスト (飛行機の場合は 0、電車の場合は 1) とともに保存します。 これにより、高速なトラバースと重みを意識した決定が可能になります。 
2. 配列を初期化する`dist`サイズの`n + 1`無限大で。 この配列には、各都市から首都に到達するために必要な電車の最小乗車回数が格納されます。 セット`dist[1] = 0`。 
3.両端キューを初期化し、キ​​ャピタルノードをプッシュします`1`その上に。 デキューでは両端での O(1) 挿入が許可され、0 ～ 1 BFS が有効になります。 
4.両端キューが空ではない間に、ノードをポップします。`u`正面から。 隣人ごとに`v`の`u`エッジウェイトあり`w`：

- もし`dist[v] > dist[u] + w`、 アップデート`dist[v] = dist[u] + w`。 
- もし`w = 0`、 押す`v`両端子の前に。 もし`w = 1`、 押す`v`後ろへ。 これにより、飛行機経由で到達可能なノードが即座に探索されるようになります。 
5. トラバース後、`dist[i]`市内からの電車の最低限の乗車時間が含まれます`i`首都へ。 すべての都市の距離を出力します。`2`に`n`。 

このアルゴリズムが機能するのは、両端キューが距離の増加順にノードを維持するためです。 ゼロコストのエッジは距離を増加させないため、最初に処理します。 各ノードは距離ごとに最大 1 回更新され、正しい最小値が保証されます。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    n, m_train, m_plane = map(int, input().split())
    graph = [[] for _ in range(n + 1)]
    
    for _ in range(m_train):
        u, v = map(int, input().split())
        graph[u].append((v, 1))
        graph[v].append((u, 1))
    
    for _ in range(m_plane):
        u, v = map(int, input().split())
        graph[u].append((v, 0))
        graph[v].append((u, 0))
    
    dist = [float('inf')] * (n + 1)
    dist[1] = 0
    dq = deque([1])
    
    while dq:
        u = dq.popleft()
        for v, w in graph[u]:
            if dist[v] > dist[u] + w:
                dist[v] = dist[u] + w
                if w == 0:
                    dq.appendleft(v)
                else:
                    dq.append(v)
    
    print(' '.join(map(str, dist[2:])))
```隣接リストには、エッジの重みとともに隣接要素が格納されます。 Deque を使用すると、ダイクストラを模倣しながら、ヒープを使用せずにゼロコストのエッジを優先することができます。 距離は、より適切なパスが見つかった場合にのみ更新されます。 よくある落とし穴は、両端キューの使用を忘れ、代わりに標準キューを使用することです。これにより、ゼロコスト エッジの順序が間違ってしまい、不正確な距離が与えられてしまいます。

 | スペース | O(n + m) | グラフ隣接リスト + 距離配列 + デキュー |
