 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、住宅を表す 2D グリッド上に点のセットがあります。 目標は、この点からすべての住宅までのマンハッタン距離の合計ができるだけ小さくなるように、新しい建物の整数座標を選択することです。 必要なのは、位置そのものではなく、この可能な最小合計距離を達成するさまざまな整数グリッド点の数です。 

距離モデルは水平成分と垂直成分に明確に分離されています。 候補点からの総コスト$(x, y)$は、すべてのハウスにわたる x 方向の絶対差の合計と y 方向の絶対差の合計です。 この分離可能性は重要な構造特性です。x の最適な選択は y に依存しませんし、その逆も同様です。 

制約は全体としては小さく、合計すると$n$すべてのテスト ケース全体で最大 1000 件です。これにより、$O(n^2)$または$O(n \log n)$テストケースごとに問題ありません。 ただし、隠れた課題はパフォーマンスではなく推論です。答えは 1 つの点ではなく、すべての最適な点の数です。これには、L1 距離合計の最小化要素の完全なセットを理解する必要があります。 

素朴な誤解は、最適な場所が 1 つだけ、通常は「中心」だけであると考えることです。 これは、座標がクラスターになっている場合や偶数である場合には失敗し、単一の点ではなく最適な解の間隔が生成されます。 

たとえば、すべての家が$(0,0)$、すべてのポイントによって距離が増加するため、$(0,0)$有効です。 しかし、家がグリッド長方形上にある場合、多くの内部点は同じ最小値を共有します。 

もう 1 つのよくある落とし穴は、x と y を独立して扱おうとして、最終的な答えが有効な x の選択と有効な y の選択の積であることを忘れていることです。 これらを混合したり、一緒に再計算したりすると、過大カウントまたは過少カウントが発生します。 

## アプローチ

 ブルートフォース手法では、すべての家を含む境界ボックス内のすべての整数点が試行されます。 候補者ごとに$(x, y)$では、すべてのポイントまでのマンハッタンの合計距離を計算し、最小値を追跡します。 最後に、その最小値に到達するポイントが何点あるかを数えます。 

これは、定義を直接評価するため、正しいです。 問題はスケールです。座標は次のようになります。$10^9$、そのため、境界ボックスが巨大になる可能性があります。 住宅間の最小/最大 x と y に制限したとしても、最大で$10^9 \times 10^9$最悪の場合の候補点。 それは計算上不可能です。 

重要な観察は、マンハッタン距離が独立した 1D 問題に分解されるということです。 総コストは次のようになります。$$\sum |x - x_i| + \sum |y - y_i|$$最小限に抑える$(x, y)$これは、x と y を別々に最小化することと同じです。 最適なソリューションでは、次の値を最小化する X 座標を使用する必要があります。$\sum |x - x_i|$、yについても同様です。 

1 次元では、絶対偏差の最小化関数の構造はよく知られています。 値を並べ替えると、最小値は中央値に達します。 より正確には、点の数が偶数の場合、中央の 2 つの要素間の間隔のすべての値が最適になります。 奇数の場合、中央の要素のみが最適です。 整数の座標のみを考慮しているため、その最適な間隔内に整数がいくつあるかを数えます。 

したがって、問題は、x 座標の中央間隔内の整数 x 値の数を求め、y 座標の中央間隔内の整数 y 値の数を乗算することに帰着します。

 ## アルゴリズムのチュートリアル

 1. すべての X 座標を配列に抽出し、並べ替えます。 絶対偏差の中央値構造を明らかにするには、並べ替えが必要です。 
2. すべての y 座標を別の配列に抽出し、同じ理由で並べ替えます。 
3. X 座標について、最適な間隔を決定します。 

- n が奇数の場合、最適な x は中央の要素に固定されます。 
- n が偶数の場合、中央の 2 つの要素 (両端を含む) 間の任意の x が最適です。 
4. この間隔内の整数の x 値の数を計算します。 これは、中央値の上限と下限の差に 1 を加えたものにすぎません。 
5. y 座標についても同じ計算を繰り返します。 
6. 有効な x 位置の数と有効な y 位置の数を乗算して、最終的な答えを求めます。 

### なぜ効果があるのか

 マンハッタン距離目標は 2 つの独立した凸 1D 問題に分割されます。 絶対偏差の各 1D 合計は、中央間隔で正確に最小化されます。 x と y の間に交互作用項がないため、あらゆる最適な解は、最適な x と最適な y を独立して選択することによって形成されます。 これにより、最適なセットのデカルト積が作成され、それらをカウントするときれいに因数分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_1d_opt(vals):
    vals.sort()
    n = len(vals)
    if n % 2 == 1:
        return 1
    left = vals[n // 2 - 1]
    right = vals[n // 2]
    return right - left + 1

t = int(input())
for _ in range(t):
    n = int(input())
    xs = []
    ys = []
    for _ in range(n):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)
    print(count_1d_opt(xs) * count_1d_opt(ys))
```実装の中核となるのは、`count_1d_opt`関数。 これは、1 次元の最適点のセットが単一の中央値、または 2 つの中間値の間の完全な整数セグメントであるという事実をエンコードします。 

中央値構造に直接アクセスするには、並べ替えが必要です。 偶数の場合の公式`right - left + 1`端点だけでなく、有効な間隔内の整数格子点をカウントします。 

最後の乗算は軸の独立性を反映しており、これが中心的な構造の単純化です。 

## 実用的な例

 2 つの代表的なケースを追跡して、間隔構造がどのように形成されるかを確認します。

 ## 特殊なケース

 エッジケースの 1 つは、すべての家が同じ地点に一致する場合です。 この状況では、両方の座標配列は一定です。 並べ替えると同一の中間要素が得られ、偶数ケースの式は単一の有効な座標に折りたたまれます。 同一の中間値の差がゼロであるため、アルゴリズムは正しく 1 を返します。 

もう 1 つのエッジ ケースは、n が偶数で中央間隔が自明でない場合に発生します。 たとえば、x 値 [0, 10] は、0 から 10 までの有効な範囲を生成します。 アルゴリズムはこれを計算によって捕捉します`right - left + 1`、エンドポイントだけではなく、間隔内のすべての整数の位置を正確にカウントします。
