 ## 問題の理解

 少なくとも長さの指定された配列のすべての連続する部分配列の中から可能な最大の中央値を見つけるように求められます。$k$。 つまり、入力配列から$a$長さの$n$、長さのすべてのセグメントを考慮する必要があります$k$それ以上の場合は、そのセグメントの中央値を計算し、これらの中央値の最大値を返します。 サイズの配列の中央値$m$位置にある要素です$\lfloor (m + 1) / 2 \rfloor$配列がソートされている場合。 

制約が示すのは、$n$と同じ大きさにすることができます$2 \cdot 10^5$。 すべての部分配列を明示的に調べる単純な解決策では、大まかに次のものが必要になります。$O(n^2)$までの操作$4 \cdot 10^{10}$最悪の場合の運用。 これは 2 秒の制限時間をはるかに超えているため、ほぼ直線的または直線的なアプローチが必要です。$O(n \log n)$せいぜい。 配列要素の境界は次のとおりです。$1$に$n$これは、部分配列を繰り返し完全にソートするのではなく、値ベースの処理の可能性を示唆しています。 

明らかではないエッジ ケースには、複数の要素が等しいサブ配列、または最大の中央値が 2 よりも長いサブ配列内に出現する場合が含まれます。$k$。 たとえば、$n = 5$、$k = 3$、 そして$a = [1, 2, 2, 2, 1]$、サブ配列$[2, 2, 2]$中央値が 2 で、次のような長い部分配列があります。$[1, 2, 2, 2]$最初の k 個の長さの部分配列から中央値を選択するだけの不注意なアプローチでは、真の最大値を逃す可能性があります。 

すべての要素が等しい場合には、別の微妙なケースが発生します。 どの部分配列も同じ中央値を持つため、最大中央値は自明のことながらその要素になります。 

## アプローチ

 ブルートフォース方法は、少なくとも長さのすべての部分配列を反復処理することです。$k$、各部分配列をソートし、中央値を取得します。 このアプローチは文字通りすべての部分配列の中央値を計算するため正しいですが、最悪の場合の複雑さは次のとおりです。$O(n^3 \log n)$すべてのサブ配列のサイズとソートを考慮すると、これは実行不可能です。$n$まで$2 \cdot 10^5$。 

効率的なソリューションを実現するための重要な洞察は、候補の中央値が適切かどうかを知るために正確な並べ替え順序は必要ないことを認識することです。$m$可能です。 長さの部分配列の場合$l \ge k$少なくとも中央値を持つこと$m$、その要素の半分以上が$\ge m$。 これは、次の場合に要素を +1 としてマークするのと同じです。$\ge m$それ以外の場合は -1 し、少なくとも次の長さの部分配列が存在するかどうかを確認します。$k$累積和が正になるもの。 これにより、問題は最大部分配列合計問題の変形に変換されます。 

この変換により、候補中央値に対して二分探索を実行できます。 要素は 1 から 1 までの範囲にあるため、$n$、せいぜいあります$n$明確な候補者。 各候補中央値について、接頭辞の合計とスライディング ウィンドウを使用して、少なくとも次の長さの部分配列があるかどうかを効率的にチェックします。$k$中央値を少なくともその候補にするのに十分な大きな要素が存在します。 これにより、全体的な結果が得られます$O(n \log n)$解決。

 ## アルゴリズムのチュートリアル

 1. 1 と 2 の間の候補中央値に対する二分探索を初期化します。$n$。 各候補者$m$はテストしている中央値を表します。 
2. 特定の候補者について$m$、配列を変換します$a$配列に入れる$b$どこ$b[i] = 1$もし$a[i] \ge m$、 そして$-1$さもないと。 これにより、サブ配列に十分な大きな要素があるかどうかを追跡できます。 
3. プレフィックスの合計を計算する$s[i] = b[0] + b[1] + \dots + b[i-1]$。 プレフィックス合計の差$s[r] - s[l]$部分配列内の大きな要素から小さな要素を差し引いた正味の数を返します。$a[l..r-1]$。 
4. 少なくとも次の長さの部分配列があるかどうかを確認するには$k$少なくとも中央値で存在します$m$、繰り返します$r = k$に$n$最小のプレフィックス合計を維持します$min\_prefix = \min(s[0..r-k])$。 もし$s[r] - min\_prefix > 0$、次にで終わる部分配列$r-1$-1 よりも +1 の方が多いため、中央値は少なくとも$m$。 
5. そのような部分配列が存在する場合、候補中央値は実現可能です。 それ以外の場合はそうではありません。 実現可能な最大の中央値が見つかるまで、バイナリ検索の境界を適宜調整します。 

なぜ機能するのか: 維持される不変条件は、要素の半分以上を含むサブ配列であることです。$\ge m$は、変換されたプレフィックス合計の正の差に対応します。 二分探索により、最大値が保証されます。$m$が見つかり、プレフィックス合計チェックにより、少なくとも長さのサブ配列の正確性が保証されます。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_median(n, k, a):
    low, high = 1, n
    ans = 1
    while low <= high:
        mid = (low + high) // 2
        b = [1 if x >= mid else -1 for x in a]
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i+1] = prefix[i] + b[i]
        min_prefix = 0
        found = False
        for r in range(k, n+1):
            min_prefix = min(min_prefix, prefix[r-k])
            if prefix[r] - min_prefix > 0:
                found = True
                break
        if found:
            ans = mid
            low = mid + 1
        else:
            high = mid - 1
    return ans

if __name__ == "__main__":
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(max_median(n, k, a))
```コードはまず、考えられる中央値に対して二分検索を実行します。 候補ごとに、配列を +1/-1 値に変換し、プレフィックスの合計を計算します。 少なくともサイズの引き違い窓$k$有効なサブ配列が存在するかどうかを効率的にチェックできるようになります。 更新中`min_prefix`微妙です。 先頭から最後までの最小プレフィックス合計を常に表す必要があります。`r-k`少なくとも一定の長さのすべての部分配列をキャプチャするには$k$。
