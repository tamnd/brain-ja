 ## 解決策
 ## 問題の理解

 個別の値の非表示の配列が与えられており、クエリを通じてのみそれを操作できます。 各クエリはサブセグメントを要求し、そのサブセグメント内の 2 番目に大きい値の位置を返します (ただし、インデックスは元の配列で報告されます)。 

私たちの目標は、最大 20 個のそのようなクエリを使用してグローバル最大要素の位置を決定することです。 

主な困難は、値を直接観察することがないことです。 すべてのクエリは、範囲内の相対的な順序に関する情報を返しますが、その情報さえもシフトされます。つまり、最大値ではなく 2 番目の最大値が得られます。 

この制約により、配列サイズは最大 100,000 まで許可されますが、クエリ制限は一定です。 これにより、要素を個別に検査したり、検索範囲を線形に縮小したりする戦略は即座に除外されます。 正しい解決策は、対数検索のように動作する必要がありますが、間接的な対話型フィードバックに適応する必要があります。 

単純な試みとしては、単一の要素をクエリするか、範囲をスキャンして最大値を繰り返し絞り込むことになりますが、各クエリではセグメントの 2 番目の最大値のみが明らかになり、最大値がどこにあるかが直接示されないため、これは失敗します。 

グローバル最大値がエンドポイントにある場合、微妙なエッジ ケースが発生します。 たとえば、最大値が位置 1 にある場合、それを含まない範囲に対する多くのクエリは依然として有効な 2 番目の最大値を返しますが、それらはいずれもエンドポイント構造を直接明らかにしません。 もう 1 つの失敗例は、グローバル コンテキストを追跡せずに間隔を縮小すると、真の最大値がまったく考慮されなくなる場合です。 

## アプローチ

 ブルートフォースインタラクティブアプローチでは、候補者をテストすることで最大の順位を推測しようとします。 それぞれの位置について、それを含む範囲または除外する範囲をクエリし、それが最大値であるかどうかを検証することができます。 これは基本的に遅すぎます。単一の候補を検証するのに複数のクエリが必要であり、最悪の場合、O(n) チェックが必要になりますが、厳密なクエリ制限の下ではこれは不可能です。 

重要な観察点は、グローバルに安定した唯一の参照点は、配列全体の 2 番目の最大値の位置であるということです。 範囲全体をクエリすると、配列全体で 2 番目に大きい要素であることが保証されるインデックス s が得られます。 この要素はアンカーとして機能します。 

ここで、配列を 2 つの半分に分割することを考えてみましょう。 唯一不確実なのは、どの半分に最大値が含まれるかということです。 2 番目の最大値 s により、対数ステップでこれを解決するのに十分な構造が得られます。 各ステップで半分をテストし、答えが s に「崩壊」するかどうかを使用して、真の最大値がどこにあるかを決定します。 

これにより、問題は最大値の位置に対する二分探索に帰着し、各ステップでサブセグメントに対する単一のクエリが使用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースチェック候補 | O(n) クエリ | お(1) | 遅すぎる |
 | Second-Max クエリを使用した二分探索 | O(log n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 最大値を含むことが保証されている現在の検索セグメント [l, r] を維持します。

1. まず、全範囲 [1, n] をクエリします。 応答は、配列全体で 2 番目に大きい要素のインデックス s を返します。 この値は、プロセス全体を通じて固定参照として残ります。 
2. ここで、セグメント [1, n] に対して二分探索を実行します。 各ステップで、中間を計算します。 
3. 現在のセグメント [l, r] をクエリし、返されたインデックス x (このセグメント内の 2 番目の最大値) を観察します。 
4. s が左半分 [l, mid] にある場合は、右半分 [mid + 1, r] をクエリします。 s が右半分にある場合は、左半分 [l,mid] をクエリします。 
5. 重要な決定ルールは、返された 2 番目の最大値が s に等しいかどうかに基づいています。 クエリされた半分が s を返す場合、その半分にはグローバル最大値と 2 番目の最大値の両方が含まれます。これは、最大値がその半分にある場合にのみ発生します。 それ以外の場合、最大値は反対側の半分にある必要があります。 
6. それに応じてセグメントを縮小し、l == r まで続行します。 そのインデックスは最大値の位置です。 

### なぜ効果があるのか

 正確さは、グローバル最大値 p とグローバル 2 番目の最大値 s の間の相互作用に依存します。 p と s の両方を含むセグメントは、常に 2 番目の最大値として s を返します。 p を含まないセグメントは、s がそのセグメントの最大値にならない限り s を返すことができません。この場合、p はそのセグメントの外側になければなりません。 この非対称性により、各ステップで少なくとも半分が確実に除外され、真の最大値が常に選択されたセグメント内に残るという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input().strip())

    # find second maximum position in whole array
    s = ask(1, n)

    l, r = 1, n

    while l < r:
        mid = (l + r) // 2

        if s <= mid:
            # second max is in left half
            res = ask(mid + 1, r)
            if res == s:
                l = mid + 1
            else:
                r = mid
        else:
            # second max is in right half
            res = ask(l, mid)
            if res == s:
                r = mid
            else:
                l = mid + 1

    print("!", l)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、単一のアクティブな間隔が維持され、それが繰り返し半分になります。 唯一の微妙な部分は、 s を含む側が異なる方法で処理されることを保証することです。これは、 s が、クエリされたセグメントにグローバル最大値が含まれるかどうかを決定する参照として機能するためです。 

このソリューションは対話型同期に依存しているため、すべてのクエリはすぐにフラッシュされます。 

## 実用的な例

 最大値が左側にあり、2 番目の最大値が右側にある配列を考えてみましょう。 

| ステップ | クエリ | 応答 | 間隔の決定 |
 | --- | --- | --- | --- |
 | 1 | [1、5] | s = 3 | 全範囲が既知 |
 | 2 | ミッド = 3、クエリ [4, 5] | 4 ≠ s | 左半分の最大値 |
 | 3 | 新しい間隔 [1, 3] | 続ける | 左に縮小 |
 | 4 | 最終 | 1 | 答えが見つかりました |

 このトレースは、s との不一致により、最大値を含めることができない半分が直ちに削除される様子を示しています。 

ここで、最大値と 2 番目の最大値の両方が同じ半分にある、逆の構成を考えてみましょう。 

| ステップ | クエリ | 応答 | 間隔の決定 |
 | --- | --- | --- | --- |
 | 1 | [1、5] | s = 3 | 参照が修正されました |
 | 2 | ミッド = 3、クエリ [4, 5] | s | 右半分には両方の上部要素が含まれています。 
| 3 | 右に移動 | [4、5] | 正しく縮小する |
 | 4 | 最終 | 4 | 見つかった最大値 |

 これにより、半分に上部の要素が両方とも含まれる場合、それが保持されることが確認されます。

 ## 特殊なケース

 最大値が配列の境界にある場合、2 番目の最大値は反対側にまだ存在するため、最初の全範囲クエリは正しい参照 s を即座に修正し、二分探索により最大値を含む側がきれいに分離されます。 

2 番目の最大値が最大値に非常に近い場合、初期の分割中に両方が同じ半分に入る可能性があります。 その場合、クエリされた半分は s を返し、アルゴリズムは最終ステップまでその半分を保持し、間隔が最大インデックスに正しく折りたたまれます。 

すべての場合において、現在の間隔に常に真の最大値が含まれるという不変条件により、2 番目に最大のクエリの動作を考慮して最大値を含めることができないことが証明された場合にのみ半分が削除されるため、誤った削除が発生しないことが保証されます。
