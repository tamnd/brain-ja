 ## 解決策
 ## 問題の理解

 すべての文字をモールス表現に置き換え、それらの表現をすべて結合した後、英語の小文字の文字列が回文になるかどうかを判断する必要があります。 元の文字はエンコード前に分離されますが、結果として得られるモールス信号は、ドットとダッシュの連続した 1 つの文字列にすぎません。 この最終シーケンスが両端から同じように読み取られる場合、答えは「YES」、そうでない場合は「NO」です。 

入力長は最大 1000 文字です。 1 文字のモールス信号には最大でも 4 つの記号が含まれるため、エンコードされた文字列でも数千文字の長さしかありません。 これは、線形スキャンは容易に十分に高速ですが、二次動作のアルゴリズムは不要であり、実装がより複雑になるだけであることを意味します。 

間違いの主な原因は、回文の性質が元の文字で確認できると想定していることです。 文字が異なると一致または不一致のドットおよびダッシュ パターンが作成される可能性があるため、エンコードによって構造が完全に変わります。 

たとえば、入力`aarrghh`生産すべき`NO`。 文字が回文を形成しているかどうかのみをチェックする不注意な解決策では、文字が対称であることがわかり、誤って YES が返されます。 代わりにモールス表現をチェックする必要があります。 

もう 1 つの罠は、エンコード後に文字の境界が消えることを忘れていることです。 入力`panne`生産すべき`NO`。 最終的な比較は個々のモールス記号間で行われるため、文字自体を単純にグループとしてミラーリングすることはできません。 

このステートメントでは空でない小文字のシーケンスが保証されているため、空の文字列は入力として使用できません。 次のような 1 文字の入力`a`生成する`.−`、これは回文ではないため、正しい出力は NO です。 

## アプローチ

 直接的なアプローチは、入力文字列全体をモールス信号に変換し、文字の先頭と末尾を比較することです。 これには、エンコードされた文字列を作成し、その最初のシンボルが最後のシンボルと等しいかどうか、2 番目のシンボルが最後から 2 番目のシンボルと等しいかどうかなどをチェックする必要があります。 すべてのミラーリングされた位置に同じ文字が含まれている場合、文字列は回文になるため、この方法は正しいです。 

ブルート フォース実装では、エンコードされた文字列内の位置のすべてのペアを繰り返し比較することもできます。 エンコードされた長さが約 4000 文字の場合、最悪の場合でも約 1600 万件の比較が実行されます。 これは、これらの制約にとってはまだ悲惨なことではありませんが、不必要であり、回文チェックのより単純な構造を無視しています。 

重要な点は、すべてのペアを比較する必要はないということです。 回文では両端から 1 回のパスのみが必要です。 モールス信号を取得すると、2 つのポインターが内側に移動し、異なる記号を見つけるとすぐに答えを拒否することができます。 

ブルートフォースは最適解と同じ情報を調べるため機能しますが、多くの比較が繰り返されます。 中心に向かって移動しながらミラーリングされた位置を確認できることが観察されたため、作業はリニア スキャンに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(m) | 大きなバリアントでは遅すぎる |
 | 最適 | O(m) | O(m) | 承認済み |

 ここ、`m`モールス符号化された文字列の長さです。 

## アルゴリズムのチュートリアル

 1. すべての小文字英語文字のモールス表現を、インデックスが文字位置と一致する配列に格納します。 これにより、入力の処理中にマッピングを再構築することが回避されます。 
2. 元の文字列を読み取り、各文字のモールス信号を 1 つの連続したシーケンスに追加します。 回文チェックは最後のモールス ストリームで行われるため、文字間のスペースは意図的に保存されません。 
3. エンコードされたシーケンスの先頭に 1 つのポインタを設定し、最後に別のポインタを設定します。 それらが指す 2 つのシンボルを比較してください。 
4. 記号が異なる場合、その配列は回文になるはずがないので、答えは即答で NO です。 ミラーリングされた位置の不一致は、失敗を証明するのに十分です。 
5. 両方のポインタを中心に向かって移動し、出会うか交差するまで続けます。 すべてのミラーリングされたペアが一致した場合は、YES を出力します。 

機能する理由: このアルゴリズムは、2 つのポインターによって既に渡された位置のすべてのペアがそのミラーリングされた位置に等しいという不変条件を維持します。 回文はこのプロパティによって正確に定義されます。 不一致が見つからずにアルゴリズムが中間まで到達した場合は、必要なすべてのペアが検証されているため、エンコードされた文字列は回文である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    morse = [
        ".-", "-...", "-.-.", "-..", ".", "..-.", "--.", "....", "..",
        ".---", "-.-", ".-..", "--", "-.", "---", ".--.", "--.-", ".-.",
        "...", "-", "..-", "...-", ".--", "-..-", "-.--", "--.."
    ]

    s = input().strip()

    encoded = []
    for ch in s:
        encoded.append(morse[ord(ch) - ord('a')])

    encoded = "".join(encoded)

    left = 0
    right = len(encoded) - 1

    while left < right:
        if encoded[left] != encoded[right]:
            print("NO")
            return
        left += 1
        right -= 1

    print("YES")

if __name__ == "__main__":
    solve()
```の`morse`配列には変換テーブルが一度格納されます。 インデックスの計算`ord(ch) - ord('a')`小文字をゼロベースの位置に変換するため、辞書検索は必要ありません。 

一部の言語では文字列を繰り返し連結すると不要な一時文字列が作成される可能性があるため、モールス信号の構築中にエンコードされたリストが使用されます。 ループの後に 1 回結合することで、構築が簡単かつ効率的になります。 

2 ポインター ループは次を使用します。`left < right`奇数長の回文の中央の文字はそれ自体と比較する必要がないためです。 比較が成功するたびに、両方のポインタが正確に 1 位置内側に移動し、1 つずれの問題が回避されます。

## 特殊なケース

 入力`aarrghh`は、文字自体が対称的に見えるため、便利な例です。 アルゴリズムは、まずそれをモールス記号に変換し、次にその新しいシーケンスの外側の記号を比較します。 不一致は 2 ポインター スキャン中に発生するため、正しく NO が返されます。 

入力`panne`文字の境界を保持できない理由を示します。 アルゴリズムは決して比較できません`p`と`e`または`a`と`n`文字として。 タスクによって定義された実際のオブジェクトである、結合されたモールス信号内の位置のみを比較します。 

入力`e`モールス信号を生成します`.`。 2 つのポインターは同じ位置から始まるため、ループはスキップされ、アルゴリズムは YES を返します。 これは、1 文字の回文の正しい動作です。 

入力`zzzz`4 つの同一のモールス ブロックを作成します。 それらを結合すると、ミラー化されたシンボルのペアはすべて等しいため、ポインタは交差するまで内側に移動し、答えは YES のままになります。
