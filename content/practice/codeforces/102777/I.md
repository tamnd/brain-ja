 ## 解決策
 # 問題の理解

 HyperLoop ネットワークは、次のような有向グラフとして表示できます。`n`駅。 どのステーションからも、左側のトンネルと右側のトンネルという 2 つの発信エッジが存在します。 左側のトンネルを繰り返し通過することは 1 つの関数を適用することを意味し、右側のトンネルを繰り返し通過することは別の関数を適用することを意味します。 

各クエリは開始駅を示します`x`、左の移動数`a`、いくつかの正しい動き`b`、およびコインの結果`c`。 もし`c = 0`、旅行の内容は、`a`左に移動してから`b`右に動きます。 もし`c = 1`、順序が逆になります。 課題は、2 ブロックの移動後に最終ステーションを見つけることです。 

難しいのは、グラフには次のものしかないことです。`100000`駅まで移動できますが、移動回数は次のとおりです。`10^15`。 1 つのクエリでも 1,000 兆回の遷移が必要になる可能性があるため、移動をシミュレートすることは不可能です。 と`500000`クエリ、それに近いソリューション`O(nq)`あるいは`O(q * min(a,b))`利用可能な時間を大幅に超えています。 各クエリにほぼ対数時間で回答できるように、グラフの前処理が必要です。 

グラフの構造は非常に特殊です。 各トンネル タイプは単独で機能グラフを作成します。つまり、すべてのステーションには、出力左エッジが 1 つと、出力右エッジが 1 つだけあります。 関数グラフには、そこにつながるツリーを含む有向サイクルが含まれており、これはまさにバイナリ リフティングが適切に機能する構造です。 

いくつかの特殊なケースでは、不用意な実装が失敗する可能性があります。 1 つ目は、移動がゼロのクエリです。 例えば：```
n = 1
left: 1
right: 1
query: 1 0 0 0
```答えは次のとおりです。```
1
```常に少なくとも 1 つのジャンプを実行するソリューションでは、ステーションから誤って離脱する可能性があります。 

もう 1 つの注意が必要なケースは、大きな電力が混在する自己ループです。```
n = 2
left: 1 1
right: 2 2
query: 2 1000000000000000 7 0
```答えは次のとおりです。```
1
```最初に左に移動すると、駅は次のようになります。`1`、さらに左に移動するたびにそこに留まります。 サイクル検出に基づく方法では、長さ 1 のサイクルを正しく処理する必要があります。 

2 つの操作の順序も重要です。 例えば：```
n = 3
left: 2 3 3
right: 1 1 2
query: 1 1 1 0
```答えは次のとおりです。```
1
```パスは`1 -> 2`左側のトンネルを使用して、`2 -> 1`右のトンネルを使用します。 順序を逆にすると遷移が異なるため、クエリを 1 つの組み合わせた操作として扱うのは正しくありません。 

## アプローチ

 直接的な解決策は、旅行をシミュレーションすることです。 すべてのクエリについて、次から開始します。`x`、必要なトンネルを進みます`a`何度か進み、もう一方のトンネルを進みます`b`回。 すべての移動は、選択したトンネルによって定義されたエッジに正確に対応するため、これは正しいです。 ただし、最悪の場合は巨大です。 1 つのクエリで必要となるのは、`10^15 + 10^15`移行、および`500000`このようなクエリには次のものが必要になります`10^21`操作。 

重要な観察は、2 つのトンネル システムが独立しているということです。 左右のトンネルを交互に行き来する必要はありません。 すべてのクエリは、左関数の 1 乗と右関数の 1 乗のみを要求します。 「この駅はその後どこへ行くの？」と答えられたら`k`left move?」と入力すると、すぐにクエリ全体が 2 つの独立したジャンプになります。 

バイナリ リフティングはまさにこの操作を提供します。 トンネルの種類ごとに、すべてのステーションが到達する場所を保存します。`2^j`動く。 までの任意の値`10^15`最大 50 のバイナリ ビットを使用して表現できるため、ジャンプは最大 50 個の保存された遷移に分解できます。 

エッジを 1 つずつたどることはプロセスと正確に一致するため、ブルート フォースは機能しますが、移動するエッジの数が多すぎるために失敗します。 各トンネル タイプが関数グラフであるという観察により、長い歩行を事前に計算された対数のジャンプに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. 2 つのバイナリ リフティング テーブルを構築します。1 つは左側のトンネル用、もう 1 つは右側のトンネル用です。 最初のレベルには、1 回の移動後の直接の目的地が保存されます。 次の各レベルでは、前のレベルの 2 倍の移動後に目的地が保存されます。 たとえば、レベル`j`長さのジャンプに答える`2^j`。 
2. クエリごとに、次を使用して操作の順序を決定します。`c`。 もし`c = 0`、最初に長さの左ジャンプを適用します。`a`、次に長さの右ジャンプ`b`。 もし`c = 1`、最初に右ジャンプを実行します。 
3. 長さのジャンプを実行するには`k`、のバイナリ表現を検査します。`k`。 設定されているすべてのビットについて、現在のステーションをそのバイナリ リフティング レベルで格納されている宛先に置き換えます。 設定された各ビットは、ルートの 2 のべき乗の 1 つのセグメントに対応します。 
4. 両方のジャンプが完了した後に到達したステーションを出力します。 

なぜ効果があるのか:

 バイナリリフティングの背後にある不変条件は次のとおりです。`up[j][v]`常に正確に表現します`2^j`から始まる同じトンネル機能のアプリケーション`v`。 基本レベルは構造上真であり、各上位レベルは前のジャンプを 2 回適用することによって形成されるため、このプロパティはすべてのレベルに当てはまります。 バイナリ表現を使用すると、任意の移動カウントを 2 のべき乗に分割できるため、選択したジャンプを組み合わせると、すべての移動を個別に実行した場合とまったく同じ結果が得られます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def build_lift(n, nxt):
    LOG = 50
    lift = [array('i', nxt)]
    for _ in range(1, LOG):
        prev = lift[-1]
        cur = array('i', [0]) * (n + 1)
        for i in range(1, n + 1):
            cur[i] = prev[prev[i]]
        lift.append(cur)
    return lift

def jump(v, k, lift):
    bit = 0
    while k:
        if k & 1:
            v = lift[bit][v]
        k >>= 1
        bit += 1
    return v

def solve():
    n, q = map(int, input().split())
    left = [0] + list(map(int, input().split()))
    right = [0] + list(map(int, input().split()))

    left_lift = build_lift(n, left)
    right_lift = build_lift(n, right)

    ans = []
    for _ in range(q):
        x, a, b, c = map(int, input().split())
        if c == 0:
            x = jump(x, a, left_lift)
            x = jump(x, b, right_lift)
        else:
            x = jump(x, b, right_lift)
            x = jump(x, a, left_lift)
        ans.append(str(x))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`build_lift`関数は、1 つのトンネル方向のテーブルを作成します。 最初の配列は直接エッジであり、その後の配列はすべて、前の配列をそれ自体で構成することによってジャンプの長さを 2 倍にします。 の使用`array('i')`Python リストには参照が保存され、約 1,000 万件の保存された遷移のメモリ制限を超えるため、これは意図的なものです。 

の`jump`関数は移動カウントのビットに従います。 現在のビットが設定されている場合、対応する事前計算されたジャンプが適用されます。 移動カウントは 50 ビット内に収まります。`2^50`よりも大きいです`10^15`。 

クエリ処理では、2 つの独立したジャンプの順序のみが選択されます。 の値`a`そして`b`ゼロにすることもできます。`while k`ループは元のステーションを返すことでこのケースを自然に処理します。 

Python の整数はオーバーフローしないため、移動回数が多くても安全です。 注目すべき唯一のインデックス作成の詳細は、ステーションに番号が付けられていることです。`1`したがって、すべてのリフティング配列には、位置に未使用の要素が含まれます。`0`。

 ## 特殊なケース

 単一ステーションのグラフには、それ自体を指す両方のトンネル関数があります。 昇降テーブルには目的地のみが含まれています`1`あらゆるレベルで。 クエリ`a = 0`そして`b = 0`ジャンプは実行せず、開始ステーションを返します。 巨大な値を含むクエリは依然として返されます`1`すべてのジャンプ レベルで自己ループが維持されるためです。
