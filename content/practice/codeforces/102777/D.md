 ## 解決策
 ## 問題の理解

 シリーズを視聴する最も早い開始時刻を選択する必要があります。 唯一の情報はエピソードの長さ (分単位) です。 有効な開始時刻とは、先頭に示される 4 桁と末尾に示される 4 桁がすべて異なる時刻です。 

時計は通常の 24 時間形式を使用するため、時刻は 2 桁の時間と 2 桁の分で表されます。 エピソードが午前 0 時を超える場合、終了時刻は翌日から継続され、通常の時刻として表示されます。 経過日数ではなく、表示された終了時刻のみが必要です。 

期間は丸 1 日ほどになる場合があります。 これにより、有用な検索スペースが即座に制限されます。1 日に可能な開始時間は 1,440 分のみです。 考えられるすべての開始時刻をチェックして桁を検証するソリューションでは、数千回の操作のみが実行されるため、制限時間内に簡単に収まります。 全体の状態空間が小さいため、より複雑なアルゴリズムは必要ありません。 

主なエッジ ケースは、クロック表現が正しく処理されていないことに起因します。 よくある間違いは、先頭のゼロを忘れることです。 たとえば、最初の桁が表示の一部であるため、時刻 6:39 は 06:39 と見なす必要があります。 入力用`1`、開始時間`00:00`表示されている 4 つの数字がすでに繰り返されているため、機能しません。 

もう 1 つの間違いは、午前 0 時を誤って処理することです。 入力用`60`、で開始`23:30`で終わります`00:30`。 比較には表示された終了時刻を使用する必要があります`00:30`、 ない`24:30`。 

3 番目のエッジ ケースは、丸 1 日にわたる期間です。 入力用`1440`、すべての開始と終了で同じ時刻が表示されるため、8 桁がすべて異なることはできません。 正しい出力は次のとおりです`PASS`。 

## アプローチ

 簡単なアプローチは、可能なすべての開始時間をシミュレートすることです。 1440 個のクロック位置のそれぞれについて、エピソードの継続時間を追加した後、終了位置を計算します。 次に、両方の時刻を 4 桁の文字列に変換し、結合された 8 文字に重複が含まれているかどうかを確認します。 有効な時間が見つかった場合は、最初に見つかった時間が自動的に最も早いものになります。 

この強引な方法は、候補の最大数が固定されているため、すでに十分に高速です。 最悪の場合でも、1440 件の開始をチェックし、各チェックでは 8 桁のみを検査します。 合計作業量は約 11520 桁の比較ですが、これはごくわずかです。 

より複雑な最適化は必要ありません。 この問題は時間をかけて調べる必要があるように見えますが、完全なタイムラインは 24 時間しかありません。 有用な観察は、回答空間の制約が非常に小さいため、直接列挙することが最もクリーンでエラーが発生しにくい解決策であるということです。

 ## アルゴリズムのチュートリアル

 1. 開始時間から可能なすべての分を試してください。`00:00`を通して`23:59`。 その日には可能なポジションが 1440 件しか含まれていないため、すべてをチェックすると最も早い正確な答えが得られます。 
2. 開始分を時と分に変換します。 先頭のゼロを含め、4 桁を別々に保管してください。 
3. エピソードの長さを開始分に追加します。 結果をモジュロ 1440 にすると、エピソード終了後に表示される時刻が得られます。 
4. 終了分を同じ 4 桁の表現に変換します。 
5. 開始 4 桁と終了 4 桁を組み合わせます。 すべての数字が 1 回だけ出現する場合、この開始時間は要件を満たします。 
6. 最初に見つかった有効な開始時刻を出力します。 1440 の可能性がすべて失敗した場合は、印刷します`PASS`。 

機能する理由: アルゴリズムは、可能なすべての開始時刻を時系列でチェックします。 有効な回答は、チェックされた瞬間の 1 つである必要があります。 最初に発生した有効なモーメントは最小のものであるため、アルゴリズムは以前の解をスキップできません。 桁テストは、表示される 8 桁すべてが異なる必要があるという条件に正確に一致するため、印刷されたすべての回答が有効になります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    k = int(input())

    for start in range(1440):
        end = (start + k) % 1440

        sh = start // 60
        sm = start % 60
        eh = end // 60
        em = end % 60

        digits = [
            sh // 10,
            sh % 10,
            sm // 10,
            sm % 10,
            eh // 10,
            eh % 10,
            em // 10,
            em % 10,
        ]

        if len(set(digits)) == 8:
            print(f"{sh:02d}:{sm:02d}")
            return

    print("PASS")

if __name__ == "__main__":
    solve()
```ループオーバー`range(1440)`は、1 日のすべての可能な開始点を表します。 順序は 1 日の始まりから終わりまでであるため、最初に成功したチェックが必須の回答となります。 

時計は午前 0 時を過ぎるとラップするため、終了時刻はモジュロ 1440 で計算されます。 この操作を行わないと、1500 分のような値は無効な時計表現を生成します。 

数字は文字列を手動で構築するのではなく、整数として保存されます。 の`set`サイズ チェックが機能するのは、8 つの一意の数字が正確に 8 つの要素を含むセットを生成する必要があるためです。 書式設定式`:02d`時と分は常に 2 桁でなければならないため、印刷時にのみ使用されます。

 | 1 | 00:01 | 00:20 | 00010020 | いいえ |

一定期間`5`、検索が到達したとします。`06:39`。 

| 開始分 | 開始時間 | 終了時間 | 数字の組み合わせ | 有効 |

 この例は、数字チェックの役割を示しています。 時刻には内部的に 4 つの異なる桁が含まれる可能性がありますが、終了時刻に桁の繰り返しが導入されるため、失敗する可能性があります。

 | スペース | お(1) | 固定数の変数と小さな桁のコンテナのみが保存されます。 |

 ## 特殊なケース

 入力用`1440`、すべての候補開始時刻は、表示されている時刻とまったく同じ時刻に終了します。 例えば、`12:34`になる`12:34`。 桁リストには必然的に重複が含まれるため、アルゴリズムはすべての候補を拒否して出力します。`PASS`。 

入力用`1`、最早候補`00:00`に終了します`00:01`。 いくつかのゼロが表示されるため、数字は一意ではありません。 アルゴリズムは、表示された 8 桁がすべて異なる最初のペアに到達するまで続行されます。 これにより、ゼロの繰り返しを無視する誤った解決策が防止されます。 

入力用`60`、一日の終わりに近い候補者は真夜中を越えることができます。 からのスタート`23:30`生成する`00:30`終了時刻は桁を抽出する前に 1440 を法として短縮されるため、アルゴリズムはこれを正しく処理します。 

どの期間でも、答えは見つからない可能性があります。 決勝戦`PASS`出力は、開始分がすべてチェックされた後にのみ到達するため、有効な時間を逃すことはできません。
