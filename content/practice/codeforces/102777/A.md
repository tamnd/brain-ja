 ## 問題の理解

 入力は、バイナリ文字列として書き込まれた正の整数です。 タスクは最大の指数を見つけることです`b`表現された数値を次のように割ることができます。`2^b`残りなしで。 

2 進数では、2 の累乗で割ることは非常に直接的な意味を持ちます。 2 の因数を 1 つ削除すると、バイナリ表現が 1 つ右にシフトされます。 2進数は次で割り切れます`2`、`4`、`8`など、最後に十分なゼロビットがある場合に続きます。 答えは、バイナリ文字列の末尾にある連続するゼロの数です。 

入力の桁数は 1000 に達する可能性があります。これは文字列全体を直接検査できるほど十分小さいですが、通常の整数型への変換に依存すべきではないことも意味します。 1000 ビットの数値は、ほとんどの言語の組み込み固定幅整数の範囲をはるかに超えています。 リニア スキャンは、約 1,000 文字のチェックのみを実行するため、十分に高速です。 

主なエッジケースは最後の位置から来ています。`1`バイナリ表現で。 数値がすでに奇数である場合、2 の因数は存在しません。 たとえば、入力`1011`は 11 を表し、出力は次のようになります`0`。 間違った側からゼロを数える不注意な解決策を使用すると、誤って正の値が返される可能性があります。 

もう 1 つの境界ケースは、2 の累乗自体です。 入力用`1000`、答えは`3`なぜなら`1000₂ = 8 = 2^3`。 最初の文字以降の文字数をカウントする実装`1`このような場合、末尾のゼロの数ではなく失敗します。 

有効な最小の数値は次のとおりです。`1`。 バイナリ形式には末尾のゼロがないため、正しい出力は次のようになります。`0`。 最後の末尾の後に常に少なくとも 1 つのゼロがあることを前提としたコード`1`無効な位置にアクセスしたり、間違った結果が生成されたりする可能性があります。 

## アプローチ

 簡単なアプローチは、数値が 2 で割り切れる範囲内で繰り返し 2 で割ることです。 除算が成功するたびに、答えは 1 つずつ増えます。 成功した除算の数は、元の値を除算した最大の 2 のべき乗に正確に一致するため、これは数学的に正しいです。 

問題は、数値が最大 1000 桁のバイナリ文字列として与えられるため、繰り返し除算を実装するには、高価な文字列演算か手動のバイナリ算術のいずれかが必要になることです。 各部門は多くの桁に触れる可能性があり、最悪の場合、次のような数値が発生する可能性があります。`1000...000`2 の 999 個の因数が含まれます。 シミュレーションは次のように実行できます。`1000 * 1000`数字の演算は必要ありません。 

重要な観察は、2 進数での 2 による除算は単に最後のビットを削除するだけであるということです。 重要なのは、文字列の末尾から読み取るときに、最後のビットの前にゼロ ビットが何個現れるかだけです。 数値を繰り返し変更する代わりに、その表現を直接検査できます。 

このブルートフォース手法は、すべての除算が 2 のうち 1 つの要素を削除するため機能しますが、バイナリ表現がすでに公開している作業を繰り返すため失敗します。 末尾のゼロカウントは 1 回のパスで同じ情報を提供します。

 ## アルゴリズムのチュートリアル

 1. バイナリ表現を文字列として読み取ります。 入力には最大 1000 ビットを含めることができるため、テキストとして保持すると、整数サイズに関する問題が回避されます。 
2. 最後の文字から開始し、現在の文字が表示されている間に左に移動します。`0`。 後続のゼロは数値が 2 の累乗で割り切れることを意味するため、見つかったすべてのゼロは 2 の因数 1 つを表します。 
3.最初の位置に到達したら停止します`1`。 遭遇したゼロの数が最大の指数になります`b`。 
4. カウンタを印刷します。 

これが機能する理由は、すべての正の 2 進数が、接頭辞で終わる固有の形式を持っているためです。`1`残りのビットはすべてゼロです。 これらの最後のゼロは、正確に削除できる 2 の因数です。 一回`1`に達すると、残りの数は奇数になるため、これ以上 2 で割ることはできません。 

## なぜ機能するのか

 このアルゴリズムは、カウントされる文字が正確に 2 の係数から削除されたものであるという不変条件を維持します。 1 つのゼロで終わる 2 進数は 2 で割り切れます。 2 つのゼロで終わる場合は 4 で割り切れます。以下同様です。 スキャンはそのようなゼロごとにカウントし、別の除算を防ぐ最初のビットで停止します。 奇数の 2 進数は常に次のように終わるため、`1`、停止点は、2 の累乗以上では元の数を割り切れないことを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    ans = 0
    i = len(s) - 1

    while i >= 0 and s[i] == '0':
        ans += 1
        i -= 1

    print(ans)

if __name__ == "__main__":
    solve()
```1000 ビットのバイナリ値を整数に変換する必要がなく、多くの環境では通常の整数の制限を超える可能性があるため、このソリューションでは入力を文字列として保持します。 

変数`i`2 の累乗による割り算は下位ビットのみに依存するため、最後のビットから始まります。 ループは、末尾のゼロが見つかったときに正確に答えをインクリメントし、より重要なビットに向かって移動します。 

ループ条件チェック`i >= 0`アクセスする前に`s[i]`、無効なインデックスを防ぎます。 有効な正の 2 進数の場合、スキャンは最終的に次の値に達します。`1`ですが、境界チェックによってコードも安全になります。 

実際の数値に対する算術演算は実行されないため、オーバーフローの心配はなく、実装はアルゴリズムで使用されるバイナリ プロパティに直接に従います。

これらの例は 2 つの重要な状況を示しています。1 つは 2 の因数を持たない数値、もう 1 つは後続ビットによって直接表される 2 の因数をいくつか持つ数値です。

## テストケース```python
import sys
import io

def solve(data: str) -> str:
    s = data.strip()

    ans = 0
    i = len(s) - 1

    while i >= 0 and s[i] == '0':
        ans += 1
        i -= 1

    return str(ans)

def run(inp: str) -> str:

 ## 特殊なケース

 入力用`1011`、アルゴリズムは最後の文字から始まります。を参照してください。`1`、すぐに止まります。 答えは残っている`0`。 表現された値が奇数であり、2 で割ることができないため、これは正しいです。 

入力用`1000`、スキャンは最初のゼロに到達する前に 3 つのゼロを訪問します。`1`。 カウンターはこうなる`3`、これは次の事実と一致します。`1000₂`は`8`、 そして`8`で割り切れます`2^3`。 

入力用`1`、インデックスは唯一の文字から始まります。 ですので`1`、ループは実行されず、出力は次のようになります。`0`。 これにより、末尾のゼロの存在を想定することがなくなります。 

入力用`1000000000`、スキャンは先頭の後にゼロごとにカウントされます。`1`。 このようなゼロは 9 個あるので、答えは次のようになります。`9`。 このアルゴリズムでは、ゼロ ビットで構成されるサフィックスのみがカウントされるため、文字列の長さと指数を混同しません。
