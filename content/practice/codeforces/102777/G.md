 ## 解決策
 ## 問題の理解

 入力は犯罪者のネットワークを説明します。 各犯罪者は無向グラフの頂点であり、文書化された各接続は 2 つの頂点間のエッジです。 犯罪コミュニティは、犯罪者のつながりのあるグループですが、孤立した 1 人の犯罪者はコミュニティとしてカウントされません。 タスクは、少なくとも 2 つの頂点を含むグラフの接続コンポーネントがいくつあるかを判断することです。 

最初の行は、犯罪者の数と記録された接続の数を示します。 次のペアは、どの犯罪者が直接関係しているかを示しています。 つながりは連鎖を形成する可能性があるため、2 人の犯罪者の間に直接の縁がなくても、他の犯罪者を通る経路がある限り、2 人の犯罪者は同じコミュニティに属します。 出力は、そのような自明ではない連結成分の数です。 

犯罪者の数は最大 100 人で、接続の数は犯罪者の数の 2 乗に達する可能性があります。 これらの制限があるため、単純なグラフ走査メソッドでも十分に高速になります。 時間計算量が O(N + M) 程度のソリューションで十分です。 すべての犯罪者のペア間のすべてのパスを繰り返し検索するようなより高価なアプローチは不必要であり、問​​題の構造が必要とするよりもはるかに多くの作業を実行することになります。 

いくつかのケースでは注意が必要です。 実際のコミュニティを含まないグラフでは、頂点が存在する場合でも、ゼロが生成されるはずです。 

例えば：```
3 0
```答えは次のとおりです。```
0
```すべての頂点をコンポーネントとしてカウントする不注意な実装では、誤って 3 が返されます。 

接続された犯罪者のペアは 1 つのコミュニティとしてカウントされる必要があります。 

例：```
2 1
0 1
```答えは次のとおりです。```
1
```多くのエッジを持つ頂点のみを検索する実装では、各犯罪者が 1 つの接続しか持たないため、これを見逃す可能性があります。 

自己とのつながりは、孤立した犯罪者をコミュニティに変えるものではありません。 

例：```
3 1
1 1
```答えは次のとおりです。```
0
```頂点にはループがありますが、接続されたコンポーネントにはまだ 1 人の犯罪者しか含まれていません。 エッジを含むすべてのコンポーネントをカウントするソリューションでは、間違った結果が生成されます。 

## アプローチ

 直接的な総当たりのアイデアは、すべての犯罪者から開始して、そこから到達可能なすべての犯罪者を検索することです。 到達可能なセットを見つけた後、そのサイズが 1 より大きいかどうかを確認し、それをコミュニティとしてカウントできます。 同じコミュニティを何度もカウントしないようにするには、どの犯罪者がすでに処理されているかを追跡する必要があります。 

この最適化がなければ、同じコンポーネントが繰り返し探索されることになります。 最悪の場合、100 人の犯罪者を含む密集したグラフには約 10,000 の接続が存在する可能性があります。 すべての頂点から完全な走査を実行すると、約 O(N(N + M)) の操作が実行されます。これは、ここでは約 100 万回の操作に相当します。 これらの制約には合格しますが、タスクのより単純な構造は無視されます。 

重要な観察は、コミュニティがまさに無向グラフの接続されたコンポーネントであるということです。 特定の犯罪者ペア間のパスを見つける必要はありません。 すべての接続された領域を 1 回検出して、そのサイズを確認するだけで済みます。 

深さ優先検索や幅優先検索などのグラフ走査は、これを自然に実行します。 訪問されていない犯罪者から始まり、同じコンポーネント内のすべての犯罪者を訪問します。 走査が完了すると、コンポーネントのサイズがわかります。 そのサイズが少なくとも 2 つである場合、星が 1 つ与えられます。 

到達可能性はグラフの走査によって発見できるため、総当り攻撃は機能しますが、同じ作業を繰り返すため概念的には失敗します。 すべての犯罪者が正確に 1 つの接続コンポーネントに属しているという観察により、各頂点とエッジを 1 回だけ処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N(N + M)) | O(N) | ここでは機能しますが、不要です |
 | 最適 | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 グラフは無向であるため、2 人の異なる犯罪者間のすべての接続について、各エンドポイントを相手のリストに保存します。 サイズ 1 のコンポーネントは決して答えに寄与しないため、自己ループは保存することも無視することもできます。 
2. 各犯罪者がすでに訪問されているかどうかを記録する配列を作成します。 最初は、関連コンポーネントが調査されていないため、すべての犯罪者は訪問されていません。 
3. すべての犯罪者を反復処理します。 未訪問の犯罪者が見つかったら、そこから DFS を開始し、到達した頂点の数を数えます。 トラバースでは、この接続されたコンポーネント内のすべての犯罪者がマークされるため、後の反復では同じコミュニティがスキップされます。 
4. DFS が完了したら、検出されたコンポーネントのサイズを確認します。 少なくとも 2 人の犯罪者が含まれている場合は、答えを 1 つ増やします。 単一の訪問頂点は孤立した犯罪者にすぎず、コミュニティではありません。 
5. カウントされたコンポーネントの最終的な数を出力します。 

なぜ効果があるのか:

 アルゴリズム中の不変条件は、完了したすべての DFS トラバーサルが 1 つの接続コンポーネントを正確に表すということです。 DFS は既存のエッジに沿ってのみ移動するため、そのコンポーネントから離れることはできません。 同時に、パスを通じて到達可能なすべての頂点が最終的​​に訪問されるため、コンポーネントのメンバーが見逃されることはありません。 すべての頂点は、それが以前に検出されていない場合にのみ 1 つの DFS を開始するため、すべての接続コンポーネントは 1 回だけカウントされます。 最終的なサイズ チェックでは、犯罪コミュニティの定義に一致する単一頂点コンポーネントが削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        x, y = map(int, input().split())
        if x != y:
            graph[x].append(y)
            graph[y].append(x)

    visited = [False] * n
    answer = 0

    for start in range(n):
        if visited[start]:
            continue

        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in graph[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        if size > 1:
            answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```トラバーサルではどの犯罪者が直接接続されているかを知るだけでよいため、グラフは隣接リストとして保存されます。 完全な隣接行列を保存することも制約に適合しますが、より多くのメモリを使用することになり、ソリューションがグラフ走査のアイデアと直接的に結びつかなくなります。 

反復 DFS では、再帰の代わりにスタックが使用されます。 Python の再帰の深さは、大きなグラフ タスクの長いチェーンでは問題になる可能性があるため、明示的なスタックによりその制限が回避されます。 

変数`size`現在の接続コンポーネントの頂点をカウントします。 アルゴリズムはコミュニティを表すかどうかを決定する前にコンポーネント全体のサイズを知る必要があるため、走査の終了後にのみチェックされます。 

グラフを作成するときに自己ループを無視しても安全です。 自己ループはコンポーネント内に別の頂点を作成することはありません。重要な唯一の問題は、コンポーネントのサイズが 1 を超えるかどうかです。

import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    graph = [[] for _ in range(n)]

    for _ in range(m):
        x, y = map(int, input().split())
        if x != y:
            graph[x].append(y)
            graph[y].append(x)

    visited = [False] * n
    ans = 0

    for i in range(n):
        if not visited[i]:
            stack = [i]
            visited[i] = True
            size = 0

            while stack:
                v = stack.pop()
                size += 1
                for u in graph[v]:
                    if not visited[u]:
                        visited[u] = True
                        stack.append(u)

            if size > 1:
                ans += 1

    return str(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve()
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 孤立した犯罪者のみを含む入力:```
3 0
```各頂点から DFS を開始しますが、各トラバースは 1 つの頂点のみを訪問します。 サイズ チェックでは 3 つのコンポーネントすべてが拒否され、答えは 0 のままになります。接続とコミュニティ サイズは個別にチェックされるため、アルゴリズムはこれを処理します。 

接続されたペア:```
2 1
0 1
```最初の DFS が両方の頂点にアクセスします。 コンポーネントのサイズは 2 になるため、答えは 1 に増加します。このアルゴリズムでは、コンポーネントに多くのエッジが必要ではなく、複数の頂点が必要です。 

自己ループ:```
3 1
1 1
```有効なコミュニティを作成しません。 グラフ表現はループを無視しており、頂点 1 からの DFS のサイズは 1 のままです。単一の犯罪者がコミュニティを形成できないため、答えは 0 のままです。 

いくつかの切断されたグループを含むグラフ:```
6 3
0 1
1 2
4 5
```3つのコンポーネントとして処理されます。 1 つ目はサイズ 3 で星が 1 つあり、2 つ目は孤立していて何も貢献せず、3 つ目はサイズ 2 で星が 1 つ増えます。 最終的な答えは 2 です。これは、トラバーサルが頂点やエッジをカウントするのではなく、コンポーネントを独立してカウントすることを確認します。
