 ## 解決策
 ## 問題の理解

 ボードには、`N`行と`M`列。 そのセルは 7 色で着色されており、対角線に沿って周期的に繰り返されます。 アリスがセルに名前を付けた後`(X, Y)`、そのセルに割り当てられた色番号を決定する必要があります。 

基板の寸法は次のように大きくできます。`10^6 × 10^6`ただし、クエリされるセルは 1 つだけです。 これにより、ボードを明示的に構築するアプローチは即座に除外されます。 色を保存するだけでも、`10^12`セルは、メモリと時間の制限をはるかに超えています。 解では、座標から直接答えを計算する必要があります。 

重要な観察は、同じ対角線上にあるすべてのセルが定数であることです。`X + Y`同じ色をしています。 次の対角線に 1 歩移動すると増加します`X + Y`1 つずつ進むので、7 色のサイクルで色も 1 つずつ進みます。 

よくある間違いは、色に番号が付けられていることを忘れることです。`1`の代わりに`0`。 たとえば、入力の場合```
1 1 1 1
```正しい答えは```
1
```一番最初の対角線は色から始まるので`1`。 使用する`(X + Y) % 7`直接的には誤って生成されます`2`。 

もう 1 つの微妙なケースは、対角インデックスが 7 の倍数である場合です。 例えば、```
5 9 3 6
```もっている`X + Y = 9`。 最初の対角線は次のように対応するため、`X + Y = 2`、オフセットは`7`、これはサイクルをちょうど 1 回ラップします。 正しい色は`1`、 ない`7`。 

## アプローチ

 単純なシミュレーションでは、ボード全体を対角ごとに生成し、繰り返しの順序で色を割り当てます。`1, 2, ..., 7, 1, ...`。 これは、色付けルールに直接従うため、正しいです。 残念ながら、ボードには最大で次の内容が含まれる可能性があります。`10^12`セルが多くなり、実行時間とメモリの両方が完全に非実用的になります。 

重要な観察は、色がクエリされたセルを含む対角線にのみ依存するということです。 最初の対角線には、`X + Y = 2`そして色を受け取ります`1`。 1 つ増えるごとに`X + Y`次の対角線に移動し、色を 1 つ進めます。 7 色があるため、必要なのは対角オフセットのモジュロ 7 のみです。 

対角オフセットは```
(X + Y) - 2
```そしてそれをに変換して戻します`1`-ベースの色番号付けにより、```
((X + Y - 2) % 7) + 1
```これにより、ボードの一部を構築することなく、一定時間で答えが計算されます。

 ## アルゴリズムのチュートリアル

 1. 4 つの整数を読み取ります`N`、`M`、`X`、 そして`Y`。 クエリされた座標は有効であることが保証されているため、基板の寸法は計算には必要ありません。 
2. 対角オフセットを次のように計算します。`X + Y - 2`。 最初の対角線には和があります`2`なので、引き算すると`2`オフセットをゼロに等しくします。 
3.色を計算します。`((X + Y - 2) % 7) + 1`。 モジュロ演算では、7 つの対角線ごとに色がラップされ、1 を加算すると、結果が必要な番号付けに変換されます。`1`に`7`。 
4. 結果の色を印刷します。 

### なぜ効果があるのか

 同じ対角線上のすべてのセルは同じ値を持ちます。`X + Y`、したがって、同じ色を受け取る必要があります。 隣接する対角線は異なります`X + Y`正確に 1 つずつ、7 色の繰り返しシーケンスの 1 つ前に一致します。 最初の対角線は色から始まるので`1`、ずらして`(X + Y - 2)`対角線を計算し、7 を法として剰余をとると、常に固有の正しい色が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, x, y = map(int, input().split())
print((x + y - 2) % 7 + 1)
```プログラムは入力を読み取り、対角オフセットを計算し、モジュロ 7 を適用し、結果を変換して戻します。`1`-ベースの番号付けを行い、それを印刷します。 

ボードの寸法は、クエリされたセルが判明すると色に影響を与えないため、意図的に使用されません。 2 を引いた値がキーオフ 1 の調整です。 これがないと、最初の対角線が誤ってカラーから開始されてしまいます。`3`色の代わりに`1`。 

Python の整数は、可能な最大の座標合計を簡単に処理できるため、オーバーフローの心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline
    n, m, x, y = map(int, input().split())
    print((x + y - 2) % 7 + 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# provided samples
assert run("3 3 3 3\n") == "5\n", "sample 1"
assert run("5 9 3 6\n") == "1\n", "sample 2"

# custom cases

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1 1 1 1
```アルゴリズムは計算します`X + Y - 2 = 0`、 それから`0 % 7 = 0`、最後に 1 つを追加して色を取得します`1`。 これにより、最初の対角線が正しく処理されていることを確認できます。 

ここで、オフセットがちょうど 7 である対角線を考えてみましょう。```
5 9 3 6
```オフセットは`3 + 6 - 2 = 7`。 取る`7 % 7`与える`0`1 を追加すると色が生成されます`1`。 これにより、7 つの対角線ごとに繰り返しシーケンスが正しく再開されます。 

最後に、折り返す前の最後の対角線を考慮します。```
7 7 1 7
```オフセットは`1 + 7 - 2 = 6`。 残りはまだです`6`、色は次のようになります`7`。 次の対角線は色に戻ります`1`、必要な周期パターンと一致します。
