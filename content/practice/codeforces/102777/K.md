 ## 解決策
 ## 問題の理解

 このタスクでは、正の整数をゼロに変えるために必要な最小の手数を見つけるように求められます。 移動すると、現在の値を 1 つ減らすか、数値を 2 つの係数に分割して大きい方を保持することによって得られる小さい係数に置き換えることができます。 たとえば、12 = 2 × 6 であるため、12 からは 6 に移動でき、15 = 3 × 5 であるため、15 からは 5 に移動できます。 

すべてのクエリに対して 1 つの開始番号が与えられ、ゼロに達する可能な限り短いシーケンス長を出力する必要があります。 

クエリの最大値は 10^6 で、最大 1000 個のクエリを含めることができます。 状態の数が多く、約数の数に応じて分岐係数が増加するため、考えられるすべての一連の動きを検討する解決策は不可能です。 すべての値からすべての可能性を試す単純なシミュレーションでも、値の範囲にわたる二次作業に近づきますが、これは 2 秒の制限には多すぎます。 最大のクエリまでのすべての値の答えを計算する前処理メソッドが必要です。 

厄介なケースは、有効なファクターの動きがない数値です。 素数は 1 より大きい 2 つの因数に分割できないため、強制的に 1 つずつ減少します。 たとえば、入力`5`出力を生成する必要があります`5`。 すべての数値に因数遷移があると想定する不注意な実装では、存在しない約数に誤ってアクセスする可能性があります。 

もう 1 つの簡単な間違いは、因子を数値からそれ自体に移動させることです。 この演算では両方の因数が 1 より大きい必要があるため、4 のような数値は 2 に移動できますが、4 に移動することはできません。`4`、正解は`3`:`4 -> 2 -> 1 -> 0`または`4 -> 3 -> 2 -> 1 -> 0`どちらも最適ではありません。 最適なパスの長さは 3 です。 可能な遷移に数値自体を含めると、無効なゼロコスト サイクルが作成されます。 

値`1`も特別です。 係数の移動はなく、デクリメント演算は 1 つだけ可能です。 入力用`1`、答えは`1`。 

## アプローチ

 直接的な解決策は、数値の答えを再帰的に定義することです。 値から`n`、あらゆる手を尽くします。 減少遷移により、次のことが得られます。`dp[n - 1]`, 一方、有効な因数分解はすべて`n = a × b`への移行を与えます`b`。 最適な次の状態を選択し、1 つの手を追加します。 

すべての最初の移動はデクリメントまたは係数置換である必要があるため、この繰り返しは正しいです。そのため、考えられるすべての最初の移動をチェックすることで、すべての最適なパスがカバーされます。 問題は、すべての数値のすべての因数分解を繰り返しチェックするとコストがかかることです。 すべての状態を個別に計算すると、除数チェックの総量が大きくなりすぎます。 

重要な観察は、数値を昇順に処理すると、すべての小さな数値の答えがすでにわかっているということです。 将来の状態を検索する必要はありません。 以下から答えを事前に計算できます`0`動的プログラミングを使用して、クエリ値の最大値まで計算します。 

数値ごとに 1 回因数分解し、約数を生成します。 すべての適切な約数は、乗算分割後のより大きな因数になる可能性があります。 これらの約数の中で、すでに計算されている最小の答えを見つけて、それを可能な遷移として使用します。 デクリメント遷移は常に利用できるため、係数遷移と比較されます。 

状態グラフが大きな数から小さな数に向かって見ると非巡回であるため、総当たりアプローチは機能しますが、同じ小さな状態が繰り返し検出されるため失敗します。 状態を一度処理してその回答を再利用すると、検索が動的なプログラムに変わります。

 ## アルゴリズムのチュートリアル

 1. すべてのクエリを読み取り、要求された最大値を見つけます。 遷移ごとに常に数値が減少するため、動的プログラミング値をこの最大値まで計算するだけで済みます。 
2. ふるいを使って最小の素因数配列を構築します。 これにより、考えられるすべての約数をテストするのではなく、すべての数値をすばやく因数分解できます。 
3.初期化`dp[0] = 0`。 からのプロセス番号`1`昇順で最大値まで。 すべての可能な移動はより小さい値に進むため、以前の状態はすでに確定しています。 
4. 現在の数値に対する答えをデクリメント演算で開始します。 これにより、候補値は次のようになります。`dp[n - 1] + 1`。 
5. 因数分解`n`そしてその素因数分解からすべての約数を生成します。 適切な約数ごとに`d`1 より大きい場合は、次からの移行を検討してください。`n`に`d`。 結果として得られる回答候補は、`dp[d] + 1`。 
6. 最小の候補を次のように保存します。`dp[n]`。 前処理後、すべてのクエリにこの配列から直接応答します。 

なぜそれが機能するのか: すべての有効な最初の動き`n`数値を 1 つ減らすか、適切な約数に変更します。 アルゴリズムは、これらの移動の考えられるすべての目的地をチェックし、すでに計算されているゼロまでの最適距離が最も小さいものを選択します。 すべての遷移は大きい数値から小さい数値に進むため、計算の昇順により、繰り返しで使用されるすべての値がすでに正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    queries = [int(input()) for _ in range(q)]
    limit = max(queries)

    spf = list(range(limit + 1))
    if limit >= 1:
        spf[1] = 1

    for i in range(2, int(limit ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, limit + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def get_divisors(x):
        factors = []
        while x > 1:
            p = spf[x]
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            factors.append((p, cnt))

        divisors = [1]
        for p, cnt in factors:
            current = []
            power = 1
            for _ in range(cnt + 1):
                for d in divisors:
                    current.append(d * power)
                power *= p
            divisors = current
        return divisors

    dp = [0] * (limit + 1)

    for n in range(1, limit + 1):
        best = dp[n - 1]

        for d in get_divisors(n):
            if d != 1 and d != n:
                if dp[d] < best:
                    best = dp[d]

        dp[n] = best + 1

    print("\n".join(str(dp[x]) for x in queries))

if __name__ == "__main__":
    solve()
```ふるいには、すべての数値の最小の素因数が保存されます。 これにより、動的プログラムが新しい値に達したときに試行分割が繰り返されることが回避されます。 

約数ジェネレータは、まず素因数分解を取得し、次に素数べき乗を組み合わせてすべての約数を構築します。 10^6 までの値の約数の数は少ないため、状態ごとに約数を生成するのは十分に高速です。 

動的計画法のループは次のように始まります。`dp[n - 1]`、必須の減少オプションを表します。 因数ループは、異なる約数のみを受け入れます。`1`そして`n`なぜなら、どちらも有効な因子置換を表していないからです。 保存された値はすべて小さいため、Python 整数のオーバーフローは問題になりません。

 ## 特殊なケース

 入力用`1`、アルゴリズムは約数を作成せず、考慮するだけです。`dp[0] + 1`、正しい答えを与える`1`。 

入力用`5`、因数生成では除数のみが返されます。`1`そして`5`。 どちらも因子の移動から除外されるため、アルゴリズムはデクリメントのみを使用して次の値を取得します。`dp[5] = 5`。 

入力用`4`、生成される約数は次のとおりです。`1`、`2`、 そして`4`。 のみ`2`は有効な宛先です。 アルゴリズムはデクリメント パスを次のものと比較します。`dp[2] + 1`、因子遷移の選択と生成`3`。 

入力用`12`、約数には以下が含まれます`2`、`3`、`4`、 そして`6`。 アルゴリズムはすべての有効な目的地をチェックし、その中で既知の最小距離を選択します。 これにより、演算では分割後に大きい因子が保持されるため、最小の因子のみをチェックするというよくある間違いが回避されます。
