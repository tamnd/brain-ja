 ## 解決策
 ## 問題の理解

 私たちは一連の数字を与えられ、その順序の観点からそれが「きれい」からどれだけ離れているかを理解することを中心に作業が行われます。 重要な重要な量は反転カウントです。反転カウントは、自然な順序から外れている要素のペアが何ペアあるかを測定します。つまり、大きな要素が小さな要素の前に現れることを意味します。 

完全な反転構造を直接計算する代わりに、この問題は構造の単純化を示唆しています。つまり、シーケンスの先頭または末尾にすでに正しく配置されている要素は、分離されると反転計算にあまり寄与しません。 中心となるタスクは、アレイのどの程度が「すでに整列している」かを特定し、残りの乱れを判断することになります。 

計算の観点から見ると、これは、シーケンスが大きくなると、すべてのペアを直接検査するソリューションは遅すぎることを直ちに示唆します。 単純なペア チェックには二次時間が必要ですが、配列サイズが約 10^5 要素に達すると、およそ 10^10 の比較が必要となり、実行できなくなります。 このため、ソート構造や、マージベースのカウントやフェンウィック ツリーなどの効率的なカウント手法を活用するアプローチが必要になります。 

配列がすでにソートされているか、中央の小さな領域を除いてほぼソートされている場合、微妙なエッジ ケースが発生します。 たとえば、次のような入力では`[1, 2, 3, 10, 9, 8, 4, 5, 6, 7]`、ほとんどのプレフィックス要素は正しく配置されており、反転の複雑さにはまったく寄与しませんが、中央の反転ブロックが反転数を支配します。 単純な方法では、大きなソート済みセグメントがコントリビューション ロジックで無視できることを認識せずに、すべてのペアをスキャンする可能性があります。 

もう 1 つのエッジ ケースは、配列が厳密に減少している場合です。`[5, 4, 3, 2, 1]`。 ここでは、すべてのペアが反転に寄与しており、完全な反転カウントに正しく還元されない限り、境界からの部分的な順序付けを前提とする最適化は失敗します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのペアをチェックします`(i, j)`と`i < j`そして何回数えるか`a[i] > a[j]`。 これは反転の定義に直接一致し、すべての関係を徹底的に検証するため、正しいことが保証されます。 問題はスケーラビリティです。 のために`n = 100000`、このメソッドは次の順序で実行されます。`n^2 / 2`時間内に実行できる範囲をはるかに超えた比較です。 

重要な観察は、並べ替えられた順序に対して要素がどのように移動するかを追跡できる場合、反転カウントでは明示的なペアの列挙を必要としないことです。 マージ ソート中に配列が分割される場合、反転は、右半分の要素が左半分の残りの要素の前に配置される場合に正確に対応します。 これにより、ソート中に反転をカウントできるようになります。`O(n log n)`時間。 

もう 1 つの同等の観点は、フェンウィック ツリーまたはバイナリ インデックス付きツリーを使用することです。 要素を順番に処理し、要素ごとに、以前に確認された要素が現在の要素よりも大きいものがいくつあるかをクエリします。 これにより、ペアごとのカウントがプレフィックス頻度クエリに変換され、動的に維持するのが効率的になります。 

反転数に影響を与えないプレフィックス要素とサフィックス要素に関するステートメントのヒントは、この構造と一致しています。すでに順序付けされているセグメントは、ソートされた境界のように動作し、相互作用ポイントを超えて相互反転を導入しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | ソート / フェンウィック ツリーをマージ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 反転カウントを実装する最も直接的な方法であるフェンウィック ツリー アプローチについて説明します。 

1. まず、配列の値をより小さい範囲に圧縮します。 これが必要なのは、フェンウィック ツリーが生の値ではなくインデックスに対して動作し、値が大きいと構造が実行不可能になるためです。 圧縮により相対的な順序が維持されるため、反転カウントで重要なのはこれだけです。 
2. プレフィックス合計クエリとポイント更新をサポートするフェンウィック ツリーを初期化します。 ツリーは、各圧縮値がこれまでに何回表示されたかを追跡します。 
3. 配列を左から右に走査します。 各要素において、以前に見た要素がその要素よりも大きいものがいくつあるかを知りたいと考えます。 これは、処理された要素の数から現在の要素以下の要素の数を引いた値をクエリすることに対応します。 
4. 前の要素はそれぞれ現在の要素と反転を形成するため、このカウントを実行中の回答に追加します。 
5. フェンウィック ツリーを更新して現在の要素を表示済みとしてマークし、将来の要素が反転計算でそれを考慮できるようにします。 

重要なアイデアは、動的なプレフィックス頻度構造を継続的に維持し、明示的なペアの列挙を集計されたカウントに置き換えることができるということです。 

### なぜ効果があるのか

 すべてのステップで、フェンウィック ツリーには、現在のインデックスの前に表示される要素のマルチセットが正確に含まれます。 要素を処理するとき`a[i]`、それより大きい以前の要素は反転ペアを形成します`(j, i)`どこ`j < i`。 プレフィックス合計クエリは、より大きい以前の要素を正確に分離します。`a[i]`個別に検査することなく。 すべての反転は、その右エンドポイントが処理されるときに正確に 1 回カウントされるため、ペアが見逃されたり、二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    data = list(map(int, input().split()))
    n = data[0]
    arr = data[1:]

    vals = sorted(set(arr))
    comp = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    inv = 0

    for x in arr:
        cx = comp[x]
        inv += fw.sum(len(vals)) - fw.sum(cx)
        fw.add(cx, 1)

    print(inv)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、ポイント更新とプレフィックス合計を備えた標準的なバイナリ インデックス付きツリーとして実装されています。 の`add`関数は頻度カウントを更新しますが、`sum`指定された圧縮インデックスまでに見つかった要素の数を取得します。 

内部`solve`、座標圧縮により、値が 1 から始まるコンパクトな範囲にマップされるようになります。要素ごとに、合計処理数から現在の値までのプレフィックス数を引くことによって、以前に確認された値が厳密に大きい値の数を計算します。 この差は反転回数に直接影響します。 

よくある落とし穴は、圧縮では順序を保持する必要がありますが、絶対値を保持する必要がないことを忘れていることです。 もう 1 つの微妙な問題は、フェンウィック ツリーのインデックスが 1 つずつずれていることです。これは、圧縮された値を 1 から開始するようにシフトすることで回避されます。

 ## 特殊なケース

 次のようなすでにソートされた配列の場合`[1, 2, 3, 4]`、すべてのクエリのため、フェンウィック ツリーは常にゼロ反転を報告します。`fw.sum(max) - fw.sum(x)`ゼロに評価されます。 この構造は、以前に確認された要素が現在の要素よりも大きいことを正確に反映しており、答えは全体を通じて安定しています。 

次のような完全に減少する配列の場合`[4, 3, 2, 1]`、各ステップは、可能な最大の新しい反転に寄与します。 加工時`1`、ツリーにはすでに大きな要素がすべて含まれているため、クエリは次の値を返します。`3`、3 つのペアが正確に一致します`(4,1), (3,1), (2,1)`。 これらはそれぞれ、正しいエンドポイントが処理された瞬間に 1 回だけカウントされ、正確であることが確認されます。
