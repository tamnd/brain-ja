 ## 解決策
 ## 問題の理解

 私たちには非常に小さな計算タスクが与えられています。整数のペアが分数を表し、その分数が少なくとも 2 分の 1 であるかどうかを判断する必要があります。 

これは、取得された値が「可能な最大値の半分よりも悪くないかどうか」をチェックするものと考えることができます。 入力は分子と分母を記述し、出力は二者決定であり、通常、問題の規則に応じて、はい/いいえ形式の回答または 1/0 として出力されます。 

中心となる操作は、比率と固定しきい値の比較です。 すべてが 1 つの算術条件に帰着するため、構造はテスト ケースごとに定数時間になります。 

タスクは簡単に見えますが、誤った送信には失敗モードがいくつかあります。 最も一般的なのは浮動小数点除算です。 たとえば、比較すると、`a / b >= 0.5`浮動小数点演算を使用すると、次の場合に不正確な結果が生じる可能性があります。`a`そして`b`精度の損失が境界線のケースを反転させる可能性があるため、この値は大きくなります。 

もう 1 つの微妙な問題は、整数の除算です。 誰かが書いたら`a / b >= 1/2`整数の除算が切り捨てられる言語では、式は`a / b`多くの有効な入力に対して 0 になり、正しさが直ちに失われます。 

具体的なエッジケースは、値がちょうど境界上にある場合です。 たとえば、次の場合`a = 5`そして`b = 10`、ちょうど半分なので正解です。 ここでも浮動小数点アプローチは機能する可能性がありますが、不注意な整数除算アプローチは誤った評価を行う可能性があります。`5 / 10`として`0`そしてチェックに失敗します。 

これらすべてを推論する安全な方法は、除算を完全に回避し、不等式を同等の整数比較に変換することです。 

## アプローチ

 ブルートフォース解釈では、分数を直接計算し、半分と比較します。 つまり評価するということです`a / b`浮動小数点数として取得し、それが少なくとも以下であるかどうかを確認する`0.5`。 これは問題の定義と直接一致するため、概念的には機能します。 

ただし、このアプローチは実装すると脆弱になります。 浮動小数点演算の精度には限界があり、`a`そして`b`大きくなると、丸め誤差が発生する可能性があります。 最悪の場合、しきい値に非常に近い値が誤分類される可能性があります。 たとえ時間計算量が一定であっても、一般的な競技プログラミングの制約の下では正確性は保証されません。 

重要な観察は、不等式の両辺を乗算することで除算を完全に排除できるということです。 条件$$\frac{a}{b} \ge \frac{1}{2}$$次のように書き換えることができます$$2a \ge b$$この変換では、整数演算のみを使用しながら正確性が維持されます。 また、決して除算しないため、ゼロ除算の落とし穴も完全に回避できます。 

この形式に縮小すると、問題はテスト ケースごとに 1 つの比較になります。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります`a`そして`b`入力から。 これらは、評価している分数の分子と分母を表します。 
2. 「分数が半分以上」という条件を次のように書き換えて整数不等式に変換します。`2 * a >= b`。 これにより、分割が回避され、すべての操作が正確に保たれます。 
3. 整数演算のみを使用して比較を実行します。 不等式が成り立つ場合、分数は少なくとも 2 分の 1 になります。 
4. 問題に必要な形式に従って、対応する結果を出力します。 

### なぜ効果があるのか

 正しさは、不等式の等価変換から得られます。 比較の両側に正の数を乗算すると順序が維持されるため、次のように乗算します。`2b`(または慎重に掛け算するだけでも) ステートメントの真実は変わりません。 以来`b`有効な分数コンテキストでは正であるとみなされ、符号反転は発生しません。 これにより、すべての有効な入力について、整数条件が元の小数条件と正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    if 2 * a >= b:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```プログラムは単一の整数ペアを読み取り、変換された不等式を直接適用します。 掛け算`2 * a`Python では安全です。Python の整数は実際には制限がないため、オーバーフローは問題になりません。 

決定は一定時間内に行われ、即座に出力されます。

 ## 特殊なケース

 のような境界ケース`1 2`は等価条件を示します。 アルゴリズムは計算します`2 * 1 = 2`そしてそれを比較します`2`、正しい YES 出力が生成されます。 これにより、等価性が適切に処理されることが確認されます。 

分子がゼロの場合のような`0 1`生成する`2 * 0 = 0`、そしてそれ以来`0 >= 1`false の場合、出力は NO になります。 これにより、アルゴリズムがゼロを正のしきい値を通過したものとして誤って扱っていないことが検証されます。 

など、端数が1を超える場合`10 1`、生成します`2 * 10 = 20`、これは条件を自明に満たします。 これは、この方法が一般的な [0,1] 範囲解釈の外でも機能することを示しています。
