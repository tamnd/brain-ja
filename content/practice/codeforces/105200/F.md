 ## 解決策
 ## 問題の理解

 この問題は、少数の基本的な編集操作を使用して、ある文字列を別の文字列に変換することを扱います。 原文が「外国語」のアルファベットで書かれ、訳文が別の「外国語」のアルファベットで書かれていると考えてください。 ソースはターゲットと同一になるまで段階的に変更できますが、各変更にはコストがかかり、編集の種類によってコストも異なる場合があります。 

各ステップで、文字の挿入、文字の削除、またはある文字を別の文字に置き換えることができます。 タスクは、最初の文字列を 2 番目の文字列に変換するために必要な最小の総コストを計算することです。 

入力は 2 つの文字列と、各編集操作に関連するコストの説明で構成されます。 出力は、許可された一連の操作を使用して最初の文字列を 2 番目の文字列に変換する際の最小コストを表す単一の数値です。 

複雑さの観点から見ると、両方の文字列が十分に長くなる可能性があるため、二次または二次に近い構造を慎重に調整する必要があります。 両方の文字列の長さが最大約 2000 である場合、位置ごとに 3 つの操作に分岐するだけでも非常に速く成長するため、すべての編集シーケンスを単純に指数関数的に探索することは不可能です。 これは、重複する部分問題が存在し、再計算する代わりに再利用する必要があることを直ちに示唆します。 

正確さのためには、いくつかの特殊なケースが重要です。 一方の文字列が空で、もう一方の文字列が空ではない場合、答えは単純に、すべての文字を挿入するか、すべての文字を削除するコストになります。 たとえば、変形する`"abc"`の中へ`""`変換中に 3 回の削除が必要になるはずです`""`の中へ`"abc"`挿入には 3 回のコストがかかります。 単純な再帰的ソリューションでは、これらのベース遷移を一貫して考慮することを忘れることが多く、再帰が空のプレフィックスにヒットしたにもかかわらず不一致の文字比較を試行すると、不正確な部分的な結果が得られます。 

文字がすでに一致している場合には、別の微妙なケースが発生します。 たとえば、変形する`"abc"`の中へ`"abc"`コストはゼロになるはずです。 等価性をチェックせずに常に置換または削除操作を適用する不注意な実装では、コストが人為的に膨らむ可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。最初の文字列を 2 番目の文字列に変換する編集の可能なシーケンスをすべて探索するものとして問題を扱います。 プレフィックス間の不一致が発生するたびに、文字の挿入、文字の削除、または現在の文字の置換を試み、結果として生じる部分問題を再帰的に解決し、すべてのパスの中で最小コストを取得します。 

このアプローチは、許可された変換の定義を直接反映しているため、正しいです。 ただし、可能なシーケンスの数は指数関数的に増加します。 文字列に長さがある場合`n`そして`m`、その後、各状態から最大 3 つの新しい状態に分岐し、最悪の場合の複雑さは次のとおりになります。`O(3^(n+m))`。 中程度の入力の場合でも、同じプレフィックス ペアが異なる操作シーケンスを通じて何度も再計算されるため、これは完全に実行不可能になります。 

重要な点は、変換の状態は、各文字列がどれだけ処理されているかによって完全に決定されるということです。 関数を定義すると`dp[i][j]`プレフィックスを変換するための最小コストとして`s[:i]`の中へ`t[:j]`の場合、すべての遷移はより小さいプレフィックスのみに依存します。 これにより、重複するサブ問題が作成されます。`(i, j)`このペアには、さまざまな一連の編集を通じて到達できます。 これが認識されると、問題は自然に、すべてのプレフィックス ペアにわたる動的プログラミング テーブルに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^(n+m)) | O(n+m) | 遅すぎる |
 | 最適なDP | O(n × m) | O(n × m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各エントリが最初の文字列のプレフィックスを 2 番目の文字列のプレフィックスに変換するための最小コストを表す DP テーブルを構築します。 

1. 2D テーブルを定義する`dp`どこ`dp[i][j]`最初の変換にかかる最小コストを表します`i`の登場人物`s`最初に`j`の登場人物`t`。 この定式化は、編集操作が対象となるプレフィックスの最後の文字にのみ影響するため、機能します。 
2.初期化`dp[0][0] = 0`2 つの空の文字列の変換には操作が必要ないためです。 
3. 最初の行を入力します`dp[0][j]`のすべての文字を挿入することで、`t`一つ一つ。 空のソースから空でないターゲットに移動する唯一の方法は挿入を繰り返すことであるため、各ステップのコストは挿入コストだけ増加します。 
4. 最初の列に入力します`dp[i][0]`すべての文字を削除すると、`s`。 空のターゲットに到達するには文字を 1 つずつ削除する必要があるため、各ステップのコストは削除コストだけ増加します。 
5. ペアごとに`(i, j)`両方のプレフィックスが空でない場合は、最後の文字を考慮してください`s[i-1]`そして`t[j-1]`。 それらが等しい場合、最後の文字に対して操作は必要ないため、最適な解決策は次のようになります。`dp[i-1][j-1]`。 
6. 文字が異なる場合は、3 つの可能な操作を検討します。 削除中`s[i-1]`につながる`dp[i-1][j]`プラス削除コスト。 挿入する`t[j-1]`につながる`dp[i][j-1]`プラス挿入コスト。 交換中`s[i-1]`と`t[j-1]`につながる`dp[i-1][j-1]`プラス交換費用。 最適な変換はこれらの操作のいずれかで終了する必要があるため、これらのオプションの最小限を採用します。 
7. 最終的な答えは次のとおりです。`dp[n][m]`、完全なソース文字列を完全なターゲット文字列に変換するコストを表します。 

### なぜ効果があるのか

 DP は、すべてのプレフィックス ペアが一致するという不変条件に依存します。`(i, j)`より大きなプレフィックスを計算するために使用される前に、最適に解決されます。 有効な編集シーケンスの変換`s[:i]`に`t[:j]`次の 3 つの方法のいずれかで終了する必要があります: の最後の文字を削除する`s`の最後の文字を挿入します`t`、または最後の文字を一致/置換します。 すべての小さな部分問題はすでに最適に計算されているため、これらの遷移の中から最小値を選択することで全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    ins_cost, del_cost, rep_cost = map(int, input().split())

    n, m = len(s), len(t)
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        dp[i][0] = i * del_cost

    for j in range(1, m + 1):
        dp[0][j] = j * ins_cost

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s[i - 1] == t[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = min(
                    dp[i - 1][j] + del_cost,
                    dp[i][j - 1] + ins_cost,
                    dp[i - 1][j - 1] + rep_cost
                )

    print(dp[n][m])

if __name__ == "__main__":
    solve()
```このソリューションは文字列と操作コストの両方を読み取り、すべてのプレフィックス ペアに対して動的プログラミング テーブルを構築します。 最初の行と列の初期化は、空のプレフィックスを変換する唯一の可能な方法をエンコードします。 ネストされたループは、プレフィックス サイズの増加に応じて遷移を計算するため、必要なときにすべての依存関係がすでに利用可能になります。 

実装でよくある落とし穴は、等価性のショートカットを忘れることです。 これがないと、アルゴリズムは引き続き機能しますが、速度が低下し、文字がすでに一致している場合に誤って置換コストを追加する可能性があります。 もう 1 つの頻繁な問題は、特にアクセス時のインデックスの不整合です。`s[i-1]`そして`t[j-1]`。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの文字列が空である場合です。 たとえば、変換すると、`""`に`"abcd"`純粋な挿入チェーンを強制します。 DP は累積挿入コストとして最初の行を正しく埋め、置換や削除を使用する遷移はありません。 

別のケースは、次のような同一の文字列です。`"foreign"`→`"foreign"`。 文字が一致するすべての対角セルがコピーされます`dp[i-1][j-1]`、対角線全体にゼロコストを伝播します。 

3 番目のケースは、削除と挿入よりも置換の方が安価な場合です。 のために`"a"`→`"b"`コストは削除 = 5、挿入 = 5、置換 = 3 で、DP は次の方法で置換を直接選択します。`dp[1][1] = 3`、2 段階の選択肢を正しく回避します。
