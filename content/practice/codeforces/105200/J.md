 ## 解決策
 ## 問題の理解

 このタスクにより、競合は 1 つの比較に集約されます。 各参加者には、解決した問題の数の記録があり、各参加者が解決セッションを終了したか、最終的に記録された状態に到達した瞬間も与えられます。 目標は、純粋に解決された問題の数によって測定され、最も早い決定的瞬間に誰がより優れたパフォーマンスを発揮するかを決定することです。 

実際には、2 つのシーケンスのパフォーマンス スナップショットを比較しています。 各シーケンスは、時間の経過に伴う参加者の進歩を表します。 重要な考え方は、1 人の参加者が他の参加者を厳密に上回った最も早い時点のみが重要であるということです。 1 人の参加者が特定の時間インデックスでより高い解決数を獲得すると、その参加者は馬上槍試合に「勝った」とみなされます。 

ステートメントは非常に短いにもかかわらず、暗黙的に時間順構造を想定しています。 入力サイズが n の場合、長さ n の 2 つの配列を効果的にスキャンし、決定的に異なる最初のインデックスに基づいて決定を行っていることを意味します。 

線形複雑性を示唆する制約では、O(n) を超えるものは不要になります。 すべてのプレフィックスを繰り返し比較する 2 次アプローチは、n が 200,000 以上に達すると、最悪の場合で約 4 × 10^10 の比較を意味するため、非常に遅くなります。 

主な微妙な点は、等価プレフィックスは重要ではないということを理解していることです。 両方の参加者がある位置まで同じ解決済みカウントを持っている場合、その領域全体を無視できます。 決定は最初の不一致の場合にのみ表示されます。 

合計または最終値が勝者を決定すると仮定すると、単純な落とし穴が発生します。 それは間違いです。問題は明らかに、誰がより強くフィニッシュするかではなく、誰が最初にリードするかに依存するからです。 

たとえば、次のことを考えてみましょう。 

入力:```
A: 1 3 3
B: 2 2 3
```一見したところ、どちらも 3 で終わりますが、インデックス 1 では B が先行しているため、A が B よりも先行することはありません。 正解は B です。B がすぐに主導権を握るからです。 

もう 1 つの誤った仮定は、辞書編集的に間違った方向で比較したり、値を合計したりすることであり、どちらも時間順の優勢条件を無視しています。 

## アプローチ

 ブルートフォース解釈では、各位置がチェックポイントとして扱われます。 すべてのインデックス i で、開始点から i までをスキャンし、累積的な進行状況をカウントまたは比較することによって、A が B より進んでいるかどうかを再計算します。 n 個の位置ごとに最大 n 個の要素を再チェックする可能性があるため、これには O(n^2) 時間がかかります。 

これは、各瞬間に誰が先にいるかを確認するというアイデアを忠実にシミュレートしているため、論理的に機能しますが、作業が不必要に繰り返されます。 n が大きくなると非効率が著しくなります。 

重要な観察は、重要なのは 2 つのシーケンスの累積的優位性が異なる最初のインデックスだけであるということです。 最初から再計算する代わりに、現在の合計を維持するか、単一パスでプレフィックス値を直接比較します。 厳密な不平等が現れたらすぐに勝者を決めて中止することができます。 

これにより、繰り返しのプレフィックス評価の問題が 1 回の線形スキャンに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各参加者が解決した問題の進行を表す 2 つのシーケンスを読みます。 両方のシーケンスが時間的に整列していると仮定します。つまり、インデックス i は両方の同じ瞬間に対応します。 
2. 最初のインデックスから最後のインデックスまでスキャンして、実行中の比較を初期化します。 各インデックスで値を直接比較するか、入力が増分解決を表す場合は累積差を維持します。 
3. インデックス i で、一方の参加者の値が他方の参加者よりも厳密に大きいかどうかを確認します。 その場合、直ちにその参加者を勝者として返します。 これが機能する理由は、早い段階でリードが確立されると、その後の同点や逆転は「最初の決定的なアドバンテージ」ルールとは無関係であるためです。 
4. 値が等しい場合は、順方向にスキャンを続けます。 平等とは、どちらの参加者もまだ決定的な分離を形成していないことを意味します。 
5. 厳密な不等号が存在せずにスキャンが完了した場合は、どちらの参加者もいかなる時点においてもアドバンテージを得ていないため、結果を引き分けとして宣言します。 

### なぜ効果があるのか

 このアルゴリズムは、最初の不等式のインデックスの前では、意味のあるすべての競合条件において両方のシーケンスが同一であるという不変式に依存しています。 最初のインデックスが異なる場合、その差の符号が結果を完全に決定します。これは、以前のインデックスがそれと矛盾することはなく、後のインデックスが最初の決定的なリードを遡及的に無効にすることができないためです。 これにより、プレフィックス比較で最初の非ゼロの差を見つけるという決定が軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    n = len(a)
    
    for i in range(n):
        if a[i] > b[i]:
            print("A")
            return
        elif a[i] < b[i]:
            print("B")
            return
    
    print("TIE")

if __name__ == "__main__":
    solve()
```コードは両方のシーケンスに対して 1 回のパスを実行します。 比較はインデックスごとに行われ、最初の決定的な利点を検出するというアルゴリズムの考え方と正確に一致します。 厳密な不平等が見つかった瞬間に、不必要な作業を避けて早期に終了します。 

よくある間違いは、最初の違いで停止するのを忘れて、その後の変更を追跡し続けることです。 これでは、後の逆転によって以前の優位性が無効になるという誤った許容が発生し、「最初にさらに多くを解決する」という問題の定義に矛盾します。

a = [1, 3, 3]
b = [2, 2, 3]
```| 私 | a[i] | b[i] | 決定 |

 | 0 | 1 | 2 | B がリード、停止 |

 インデックス 0 では、B の値がすぐに高くなるため、追加の検査を必要とせずに B が勝ちます。 

これは、たとえ後の値が収束したとしても、初期の優位性が決定的であることを示しています。 

### 例 2

 入力:```
a = [2, 2, 5]
b = [2, 2, 3]
```| 私 | a[i] | b[i] | 決定 |
 | --- | --- | --- | --- |
 | 0 | 2 | 2 | 続ける |
 | 1 | 2 | 2 | 続ける |
 | 2 | 5 | 3 | A がリード、停止 |

 等号の接頭語は、同点が決定に影響を与えないことを示します。 最初の厳密な違いはインデックス 2 で発生し、A がリードします。 

これにより、アルゴリズムがニュートラル プレフィックスを正しく無視し、最初の発散にのみ反応することが確認されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのポジションにわたって完全に平等であることです。 たとえば:

 入力:```
a = [4, 4, 4]
b = [4, 4, 4]
```このアルゴリズムは、厳密な不等式を検出することなく、すべてのインデックスをスキャンします。 各ステップで「続行」分岐がトリガーされます。 シーケンスを使い果たした後でのみ TIE が出力されます。これは、参加者がリードを確立したことがないため、これは正しいことです。 

もう 1 つのエッジケースは、最初の要素がすでに結果を決定している場合です。 

入力:```
a = [10, 0, 0]
b = [1, 100, 100]
```インデックス 0 では、A がすでにリードしています。 The scan stops immediately, and later reversals in B’s favor are ignored. This confirms that early termination is essential and correctly enforced by the algorithm’s structure.
