 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そのタスクは、配列を左から右に拡張しながら、古典的な「最大部分配列」量を繰り返し評価することです。 配列のすべてのプレフィックスにおいて、完全にそのプレフィックス内にある連続するサブ配列の可能な限り最良の合計を知りたいと考えます。 出力は、プレフィックスごとに 1 つずつ、これらの最良の値のシーケンスです。 

タスクを読み取るもう 1 つの方法は、配列を一度に 1 要素ずつ明らかにすることをシミュレートすることです。 最初の要素を確認した後、その 1 つの要素の最大サブ配列合計を計算します。 最初の 2 つの要素を確認した後、両方の最大部分配列合計を再計算します。 これは、配列全体が処理されるまで続きます。 

重要な制約の意味は、各プレフィックスを単純に再計算すると時間がかかりすぎるということです。 配列の長さが 100000 などの一般的な競技プログラミングの制限に達している場合、プレフィックスごとに完全な Kadane スキャンを再計算すると O(n²) の動作が発生し、これは許容範囲をはるかに超えています。 新しい要素がそれぞれ一定時間で答えを更新できるように、増分状態を維持する必要があります。 

一般的なエッジケースは、すべての数値が負の場合です。 たとえば、配列が [-5, -2, -8] の場合、各プレフィックスの答えは、ゼロではなく、これまでに確認された最大の単一要素になります。 負の値をゼロにリセットする単純な Kadane 実装では、誤ってゼロが出力されます。空の部分配列が禁止されている場合、これは有効な部分配列の合計ではありません。 

もう 1 つの微妙なケースは、プレフィックスに最適なサブ配列が正確に現在の位置で終了する場合です。 たとえば、[3, -10, 4] では、接頭辞の答えは 3、3、4 と進化します。「ここで終了する最適な」状態を適切に維持せずに、グローバル最良のみを追跡するアプローチは、拡張するよりも現在の要素で再開する方が良い遷移では失敗します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのプレフィックスの最大サブ配列合計が個別に再計算されます。 インデックス i で終わる各プレフィックスについて、i またはそれより前で終わるすべてのサブ配列をスキャンし、それらの合計を計算します。 直接実装では、r ≤ i のすべてのペア (l, r) が試行されるため、プレフィックスごとに O(n²) の作業が発生し、加算によって素朴に実装された場合は全体で O(n³) の作業になります。 プレフィックス合計によって範囲合計クエリが O(1) に減ったとしても、プレフィックスごとに O(n²) 個のサブ配列が存在するため、実行不可能になります。 

これが無駄である理由は、隣接するプレフィックスがほぼすべての構造を共有しているためです。 プレフィックス i からプレフィックス i+1 に移動するとき、新しい要素を 1 つ追加するだけですが、ブルート フォースでは以前の結果を更新するのではなく、すべてが最初から再計算されます。 

重要な観察は、Kadane のアルゴリズムが、このプロセスに必要な 2 つの情報、つまり現在の位置で終了する最良のサブ配列合計と、これまでに確認された最良のサブ配列合計をすでに正確に保持していることです。 最初の値は、前の部分配列を拡張するか、現在の要素から新たに開始するかを決定することによって、O(1) で更新できます。 2 番目の値は、単に経時的な最大値です。 

これら 2 つの状態を繰り返しながら維持することで、再計算を行わずにすべてのプレフィックスに対する答えが自然に生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) または O(n³) | お(1) | 遅すぎる |
 | プレフィックスごとの最適なカダネ | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 2 つの変数を初期化します。1 つは現在のインデックスで終わる最良の部分配列の合計を追跡するためのもので、もう 1 つはこれまでに確認された最良の答えを追跡するためのものです。 空のサブ配列は許可されないため、最初の配列は最初の要素から開始する必要があります。 
2. 配列を左から右に繰り返し、一度に 1 つの要素を処理します。 各ステップで、前のサブ配列を拡張するか、現在の要素で新しいサブ配列を開始するかを決定します。 
3. 「ここでの最良の結末」の値を、現在の要素単独と、以前の最良の結末と現在の要素との間の最大値として更新します。 この選択は、継続が役立つか害があるかを反映します。 
4. グローバル最良値を、現在の値と新しく計算された「ここでの最良の終了値」の間の最大値として更新します。 
5. 各反復後にグローバル最良を出力します。その時点で、それが現在のプレフィックスのサブ配列合計の最大値を表すためです。 

### なぜ効果があるのか

 このアルゴリズムは正確な不変条件を維持します。つまり、インデックス i を処理した後、変数追跡「ここで終わる最適な値」は正確に i で終了する必要があるサブ配列の最大合計に等しく、グローバル ベストはプレフィックス [0, i] に完全に含まれるサブ配列の最大合計に等しくなります。 i で終わるサブ配列は、i-1 で終わるサブ配列を拡張するか、i で新たに開始されるため、遷移はすべての可能性を取り込みます。 すべてのサブ配列には一意の終了位置があるため、すべての候補サブ配列は「ここで終了」状態になるときに 1 回だけ考慮され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    n = int(data[0])
    arr = list(map(int, data[1:]))

    # In case input is split across lines
    if len(arr) < n:
        while len(arr) < n:
            arr.extend(map(int, input().split()))

    best_ending = arr[0]
    best_global = arr[0]

    out = [str(best_global)]

    for i in range(1, n):
        x = arr[i]

        best_ending = max(x, best_ending + x)
        best_global = max(best_global, best_ending)

        out.append(str(best_global))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```解決策は、最初の行にすべての要素が含まれていない可能性がある場合を含め、配列全体を注意深く読み取ることから始まります。 これは、入力にスペースや改行が混在している場合によくある競技プログラミングの落とし穴です。 

変数`best_ending`は、現在の位置で終了する必要がある最適な部分配列の合計に対応します。 アップデート`max(x, best_ending + x)`再開または延長の決定を直接エンコードします。 変数`best_global`これまでのすべてのプレフィックスで最もよく見られたものを追跡し、必要な出力シーケンスを生成するために各更新後に追加されます。 

細かい点は初期化です。 部分配列には少なくとも 1 つの要素が含まれている必要があるため、どちらの変数もゼロではなく最初の要素から始まります。 

## 実用的な例

 配列 [3, -2, 5] について考えてみましょう。 

| 私 | 値 | ベストエンディング | ベストグローバル | 出力 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 3 | 3 | 3 |
 | 1 | -2 | 最大(-2, 3 + -2 = 1) = 1 | 3 | 3 |
 | 2 | 5 | 最大(5, 1 + 5 = 6) = 6 | 6 | 3 3 6 |

 このトレースは、負の値がすべてをリセットするのではなく、延長が依然として有益な場合にのみ終了合計を減らす方法を示しています。 グローバルな答えは、より良いサブ配列が現れるまで安定したままになります。 

次に [-1、-2、-3] を考えてみましょう。 

| 私 | 値 | ベストエンディング | ベストグローバル | 出力 |
 | --- | --- | --- | --- | --- |
 | 0 | -1 | -1 | -1 | -1 |
 | 1 | -2 | 最大(-2, -1 + -2 = -3) = -2 | -1 | -1 |
 | 2 | -3 | 最大(-3, -2 + -3 = -5) = -3 | -1 | -1 |

 これは、アルゴリズムがゼロ初期化を正しく回避し、最大の負の要素を保持していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素は定数時間遷移で 1 回処理されます。 
| スペース | お(1) | 維持される実行変数は 2 つだけです。 

プレフィックスに対する二次再計算は一般的な制限を数桁超えてしまうため、線形時間計算量は大規模な配列を処理するために不可欠です。 一定のスペース使用量により、最大入力サイズでもメモリの安定性が保証されます。

 ## 特殊なケース

 [-5, -1, -3] のような入力の場合、アルゴリズムは -5 で初期化されます。 2 番目の要素の後は、best_ending = max(-1, -5 + -1 = -6) = -1 と評価され、best_global は -1 のままになります。 3 番目の要素の後は、best_ending = max(-3, -1 + -3 = -4) = -3 となり、best_global は -1 のままになります。 出力は各ステップで最適なプレフィックス値を正しく維持し、誤ってゼロが導入されることはありません。 

[4, -10, 6] のような入力の場合、アルゴリズムは最初に best_ending = 4、best_global = 4 を設定します。インデックス 1 では、best_ending は max(-10, -6) = -6 になりますが、best_global は 4 のままです。インデックス 2 では、best_ending は max(6, 0) = 6 になり、best_global を 6 に更新します。これは、3 番目の要素での再起動が、グローバルではなくローカル遷移ルールを通じてどのように正しくキャプチャされるかを示しています。 再計算。
