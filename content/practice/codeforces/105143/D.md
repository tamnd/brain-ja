 ## 解決策
 ## 問題の理解

 私たちは座席の列の上に立っていて、各座席は負ではない値を保持しています。 選択した開始席から、1 秒ごとに左、右に移動するか、その場にとどまることができます。 初めて座席に着くたびに、私たちはその価値を収集します。 後でその席を再訪問しても、何も新しいことはありません。 

すべての開始位置とラインの長さの 2 倍までの時間予算ごとに、収集できる最大合計値が必要です。 これらすべての答えを計算した後、テーブル全体を出力するのではなく、それらをグローバル XOR スタイルの集計と組み合わせるように求められます。 

重要な構造は、移動が隣接するステップに制限されるため、到達可能な訪問済みの座席のセットは、開始位置を含む連続したセグメント内に存在する必要があるということです。 微妙な部分は、時間は単に距離を制限するものではなく、両端に到達するためにセグメント内で振動しながらセグメントを拡張できるコストを制限することです。 

最大 5000 の n と最大 2n の時間という制約は、開始位置ごとの 2 次または 2 次に近いアプローチは許容されるが、すべてのペアにわたる 3 次のものは許容できないことを強く示唆しています。 これにより、シミュレーションや訪問セットの状態に対する最短パスを使用してペアごとに最適なウォークを個別に再計算することは直ちに除外されます。これは爆発的な影響を与えるためです。 

一般的なエッジ ケースは、最適な戦略が最初に 1 つの極端な方向に進み、次に外側に向かってスイープする必要がある場合です。 たとえば、開始点の両側に大きな値が集中している場合、最適パスは一方向の単調ではなく、辺を集めた後に方向が切り替わります。 

もう 1 つの重要な例外ケースは、しばらくの間静止することが最適な場合です。これは、高値の領域に到達するのに十分な時間が確保されるまで、特定の方向へのコミットが遅れる可能性があるためです。 単純な貪欲な拡張は、すぐに外向きに動くことを前提としている場合、ここで失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各開始位置から長さ t の可能なすべての歩行をシミュレートしようとします。 これは、可能なパスの数が t とともに指数関数的に増加し、訪問済みセットによる枝刈りでも依然として多すぎる状態が残るため、すぐに実行不可能になります。 報酬はエンドポイントだけでなく、訪問したノードのセットに依存するため、位置と時間だけを対象とした動的プログラミングでも不十分です。 

重要な観察は、最適な戦略は常に開始位置を含む連続する座席の間隔を訪問し、その間隔内では、訪問要素の順序は間隔を外側に拡張するコストを超えて重要ではないということです。 最終的な間隔 [l, r] を決定すると、s から開始してその間隔をカバーするのに必要な最小時間が完全に決まります。最初に近い端に移動し、次に遠い端までスイープします。 最初の位置決めの後、外側にもう 1 座席だけ間隔を広げるには、方向に関係なく、追加のステップが 1 つだけかかります。 

これにより、固定 s の問題は、s から開始して徐々に外側に間隔を拡張し、拡張するたびに左端または右端の次の未訪問の席が追加されるプロセスに縮小されます。 唯一の問題は、時間予算内で収集された値を最大化するには、左端と右端をどの順序で拡張する必要があるかということです。 

開始点ごとに、2 つの標準戦略をシミュレートします。 1 つは、外側への貪欲な拡張を開始する前に、まず可能な限り左に移動することから始まり、もう 1 つは、最初に右に移動することから始まります。 最初の到達後の各ステップでは、次の未使用の左または右の境界要素が単純に追加され、次に常に大きい方の利用可能な値が取られます。 すべての拡張には同じ追加時間がかかるため、この貪欲な選択は有効です。そのため、一連のゲインに対して単純なプレフィックス最適化を解決しています。 

次に、考えられる時間予算ごとに、この拡張プロセスの最適なプレフィックスを記録します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数 | 高 | 遅すぎる |
 | 開始ごとの 2 方向の貪欲な拡張 | O(n²) | O(n) 余分 | 承認済み |

 ## アルゴリズムのチュートリアル

 開始位置 s を固定し、すべての制限時間に対する答えを個別に計算します。 

1. 最初の 2 つの選択肢を検討します。最初に左の端点に向かって移動するか、最初に右の端点に向かって移動します。 これらは、成長区間に入る初期の「セットアップコスト」を支払う 2 つの根本的に異なる方法に対応します。 
2. 選択した方向について、s から 1 または n まで直接歩いて境界に到達することをシミュレートします。 この最初の移動には移動距離に等しい固定コストがあり、それによって初期間隔の境界が決まります。 
3. 片側に到達したら、常に s を含み、これまでに訪問したすべての位置を表す現在の間隔 [l, r] の維持を開始します。 
4. 初期化後の各ステップで、これらのインデックスが範囲内にある限り、間隔を l − 1 または r + 1 に拡張できます。 各延長には正確に 1 秒の追加料金がかかります。 
5. 利用可能な 2 つの端の間で、a 値がより大きい拡張子を常に選択します。 どちらの選択も同じ時間を消費し、訪問したセットに 1 つの新しい要素を永続的に追加するため、これは安全です。 
6. 拡張の各回数の後の累積合計を記録し、最初の移動コストによって指数をシフトします。 これにより、時間 t からこの拡張戦略の下で達成可能な最良の値までのマッピングが生成されます。 
7. 両方の初期方向についてシミュレーション全体を繰り返し、時間 t ごとに最大の結果を取得します。 
8. これらの結果を固定開始 s の Fi,s,t として保存し、最後に必要に応じてすべての s と t にわたって集計します。 

### なぜ効果があるのか

 ライン上で収集された値を最大化する最適なウォークは、スコアを失ったり時間を増加させたりすることなく、単一の連続した区間を訪れるものに変換できます。 その間隔内では、最小時間トラバーサル構造により、1 つの境界の最初の到達点への分解が強制され、その後に外側への拡張ステップが続きます。 初期化後の各展開は、正確に 1 つの新しい頂点に寄与し、正確に 1 単位時間のコストがかかるため、問題はこれらの単位コストのゲインを順序付けることに帰着します。 より大きな利用可能なエンドポイント値を取得する貪欲な選択は、以前の選択に応じて将来の決定が安くなったり、より高価になったりすることがなく、現在の境界値を超える拡張選択肢の間に結合がないため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_for_start(a, s):
    n = len(a)

    def simulate(first_left):
        l = s
        r = s
        time = 0
        total = a[s]

        used = [False] * n
        used[s] = True

        if first_left:
            # go left until boundary or until we decide to stop expanding
            while l > 0:
                l -= 1
                time += 1
                total += a[l]
                used[l] = True
            r = s
        else:
            while r < n - 1:
                r += 1
                time += 1
                total += a[r]
                used[r] = True
            l = s

        # expand outward greedily
        left_ptr = l
        right_ptr = r

        gains = []
        while left_ptr > 0 or right_ptr < n - 1:
            left_gain = a[left_ptr - 1] if left_ptr > 0 else -1
            right_gain = a[right_ptr + 1] if right_ptr < n - 1 else -1

            if left_gain > right_gain:
                gains.append(left_gain)
                left_ptr -= 1
            else:
                gains.append(right_gain)
                right_ptr += 1

        # prefix best over time
        best = [0] * (2 * n + 1)
        cur = total
        best[time] = cur

        for i, g in enumerate(gains, start=1):
            cur += g
            if time + i <= 2 * n:
                best[time + i] = cur

        # propagate maxima over time
        for i in range(1, 2 * n + 1):
            best[i] = max(best[i], best[i - 1])

        return best

    left_best = simulate(True)
    right_best = simulate(False)

    return [max(left_best[i], right_best[i]) for i in range(2 * n + 1)]

def main():
    n = int(input())
    a = list(map(int, input().split()))

    all_F = [ [0] * (2 * n + 1) for _ in range(n) ]

    for i in range(n):
        all_F[i] = compute_for_start(a, i)

    # required XOR-style aggregation
    result = 0
    for i in range(n):
        for t in range(1, 2 * n + 1):
            result ^= (i + 1) + t * all_F[i][t]

    print(result)

if __name__ == "__main__":
    main()
```実装では、開始位置ごとに計算が分離されます。 シミュレート関数は、最初に左に進むと仮定して、もう一度右に進むと仮定して、その開始から拡張シーケンスを構築します。 初期境界に到達した後は、常に隣接する未使用の大きい値を取得することによって、外側に向かって貪欲に拡張します。 

外側への拡張が始まる前に最初の移動フェーズでステップが消費されるため、タイム カウンタは明示的に追跡されます。 プレフィックス配列により、既知の最良の値を繰り越すことで、最大 2n までの毎回のバジェットに応答できることが保証されます。 

最終的な XOR 集計は、すべての Fi,t 値がわかった後で、必要に応じて正確に計算されます。 

## 実用的な例

 値が非対称である小さな配列 (たとえば、インデックス 2 (値 2) から始まる a = [1, 10, 2, 9]) を考えてみましょう。 1 つの戦略は、最初に左に移動し、すぐに 10 を集め、次に 1 を集め、次に右に拡張して 9 を得るというものです。もう 1 つの戦略は、最初に右に進み、早めに 9 を集めてから左に拡張することです。 シミュレーションは、貪欲な拡張シーケンスがどのように初期方向に依存するが、最終的には同じ間隔をカバーするかを示しています。 

2 番目の例、a = [5, 1, 1, 1, 5] では、中央から開始され、展開では常に末尾の 5 が優先されます。 トレースは、最初の位置決めの後、貪欲シーケンスが内部の低い値を消費する前に両方のエンドポイントを選択することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 各開始では、配列 | に対して線形拡張シミュレーションが実行されます。 
| スペース | 開始ごとに O(n) 追加 | 現在の展開状態とプレフィックス結果のみを保存します。 

n の合計は最大 5000 であるため、O(n²) 個の解で十分です。 各シミュレーションは線形であり、開始位置ごとに 2 回実行されます。

 ## 特殊なケース

 シングルシート配列の場合、アルゴリズムは total をそのシートの値として直ちに初期化し、展開は行いません。 代替の動きがないため、出力はすべての時間予算に対して安定したままになります。 

すべての値が等しい配列の場合、すべての展開選択肢は同等です。 貪欲なタイブレークでも有効な完全な間隔拡張が生成され、プレフィックス値は時間の経過とともに直線的に増加し、最適なパスに一致します。 

開始点が終了点にある場合、意味のある初期方向は 1 つだけです。 シミュレーションは、無駄な初期トラバーサル フェーズを発生させることなく、単一の外向き拡張プロセスに正確に縮小されます。 

1 つの極値が他の極値よりもはるかに大きい、非常に偏った配列の場合、貪欲な拡張では常にその極値が最初に優先され、プレフィックス構造により、できるだけ早くそのエンドポイントに到達することによって早期の時間予算が支配されることが保証されます。
