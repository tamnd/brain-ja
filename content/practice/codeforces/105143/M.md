 ## 解決策
 ## 問題の理解

 兵士を表す正の整数の重みのマルチセットが与えられます。 許可される唯一の操作は、強さがちょうど 1 異なる 2 人の兵士を、その合計の強さを持つ 1 人の兵士と置き換えることです。 選択したペアが差分​​条件を満たす限り、この操作は任意の順序で何度でも繰り返すことができます。 

このような一連のマージを実行すると、最終的にマルチセットが得られます。 この最後のマルチセットは降順でソートされ、対戦相手の結果のマルチセットと辞書順に比較されるため、ゲームの結果を決定します。 Siri の目標は、このソートされたシーケンスが辞書順でできるだけ大きくなるように、マージを使用して最初のマルチセットを変換することです。 

辞書編集の目的は、何が重要であるかを即座に示します。考えられる最大の最初の要素、次に 2 番目の要素、というようになります。 ソートは最後に適用されるため、構築の内部順序は重要ではなく、最後のマルチセットのみが重要になります。 

この制約では最大 200,000 人の兵士が許可され、値は 10^18 までの大きさになります。 すべての要素の中からマージ可能なペアを単純に繰り返し検索しようとするソリューションは、最悪の場合、マージのたびに O(n^2) 個の候補チェックや構造の再スキャンが繰り返される可能性があるため、遅すぎます。 

微妙な問題は、マージが独立していないことです。 新しい値を作成するマージでは、異なる値を持つ新しいマージのロックが解除される可能性があるため、マージを慎重に編成しないと、貪欲なローカル決定は簡単に間違ってしまう可能性があります。 

一般的な失敗モードは、利用可能な連続値のペアを貪欲に繰り返しマージしようとすることです。 たとえば、値 1、2、3、4 がある場合、単純なマージでは最初に 2 と 3 を選択して 5 を形成し、その後 1 + 2 = 3、3 + 4 = 7 などのより大きなチェーンを形成する機会を失う可能性があります。 マージの順序によってどのようなチェーンが可能になるかが変わるため、すべてのマージの可能性を体系的に捉える構造が必要です。 

## アプローチ

 一見すると、プロセスを直接シミュレートできるかもしれません。 配列を繰り返しスキャンし、差が 1 であるペアを探し、それらをマージし、元の値を削除して、新しい値を挿入します。 マージごとに要素の数が 1 つずつ減るため、マージは最大で n 回行われます。 ただし、マージごとに有効なペアを見つけて構造を更新する必要があり、単純なスキャンで実行すると O(n) のコストがかかる可能性があり、ローカル構造の更新では O(log n) のコストがかかる可能性がありますが、それでも n 回繰り返すと O(n^2) 以上のコストがかかります。 これは、2×10^5 までの n に対しては遅すぎます。 

重要な観察は、マージは位置ではなく値のみに依存し、隣接する整数に対する連鎖反応のように動作するということです。 すべての数値が値によってグループ化されていると考えると、マージは連続する整数値のみを接続し、各マージは隣接する 2 つの「値バケット」のそれぞれから 1 ユニットを消費し、より高いバケットで 1 ユニットを生成します。 

これは、ソートされた値に対する貪欲な戦略を示唆しています。つまり、値を昇順に処理し、マージによって「質量」がどのように上方に流れるかをシミュレートします。 任意のペアを繰り返し選択する代わりに、各値のカウントを維持し、可能な限り多くのマージを前方に伝播させようとします。 重要な洞察は、値 x と x+1 の間でマージが何回発生するかを決定すると、結果として得られる x+1 の構造が将来の決定に備えて固定されるということです。 これにより、ソートされた個別の値に対してプロセスが線形になります。 

システムを整数値に沿ったフローとして効果的に扱います。各マージによって隣接する 2 つのカウントが減少し、次のレベルが増加します。 実際には、各要素は最大でも O(log 値) の上向き遷移に参加するため、小さいものから大きいものまで慎重に貪欲に蓄積することで、最適な最終的なマルチセットが得られます。

 ## アルゴリズムのチュートリアル

 まず入力を等しい値の周波数に圧縮します。 これが必要なのは、マージでは位置ではなく多重度だけが重要であるためです。 

次に、以前のマージで作成されたアイテムを含め、各値に存在するアイテムの数のマップを維持しながら、値を昇順に処理します。 

また、可能な限り値 x から x+1 に「超過」をプッシュできる構造も維持します。 中心となるアイデアは、x に少なくとも 1 つの項目があり、x+1 に少なくとも 1 つの項目があるときはいつでも、それらをマージして両方を消費し、x+2 で 1 つを生成できるということです。 

ソートされた順序で値を反復処理し、そのレベルでローカル マージが不可能になるまでこのルールを継続的に適用してから次に進みます。 

最後に、すべての伝播が終了した後、残りの周波数マップからマルチセットを再構成します。 

### なぜ効果があるのか

 すべての値 x において、x を超える前に x および x+1 を含むすべての可能なマージが完了することを保証します。 これにより、安定した境界が作成されます。将来、より大きな値を含む操作を行っても、遡及的に x レベル要素をより適切に使用できるようになります。 各マージは生成される要素の値を厳密に増加させるため、プロセスは値空間では単調であり、マージを遅らせても辞書編集上の結果が改善されることはありません。 これにより、最小値を最初に貪欲に解決することで、全体的に最適な最終的なマルチセットが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = Counter(a)
    keys = sorted(cnt)

    # we will process in increasing order, but may create new keys dynamically
    i = 0
    keys = sorted(cnt.keys())

    for x in keys:
        if cnt[x] == 0:
            continue
        # try to propagate merges forward
        while cnt[x] > 0 and cnt[x + 1] > 0:
            cnt[x] -= 1
            cnt[x + 1] -= 1
            cnt[x + 2] += 1

            # ensure new keys are tracked if needed
            if x + 2 not in cnt:
                cnt[x + 2] = 0

    result = []
    for k in cnt:
        result.extend([k] * cnt[k])

    result.sort(reverse=True)

    print(len(result))
    print(*result)

if __name__ == "__main__":
    solve()
```値が判明すると兵士の身元は無関係となるため、実装は頻度をカウントすることから始まります。 マージ ループは、隣接する値間でローカルに許可された唯一の操作を適用しようとします。 while ループを繰り返すことで、先に進む前に x と x+1 の間のすべての対話を完全に使い切ることができます。 

微妙な点の 1 つは、x+2 で新しく作成された値も後で考慮する必要があるため、それらがディクショナリに存在することを確認することです。 この問題では降順でソートした後に辞書順を評価するため、最後にソートが必要です。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    a = list(map(int, input().split()))
    cnt = Counter(a)

    keys = sorted(cnt.keys())

    for x in keys:
        while cnt[x] > 0 and cnt[x + 1] > 0:
            cnt[x] -= 1
            cnt[x + 1] -= 1
            cnt[x + 2] += 1

    res = []
    for k in cnt:
        res.extend([k] * cnt[k])

    res.sort(reverse=True)

    return str(len(res)) + "\n" + " ".join(map(str, res))

# minimal case
assert run("1\n5\n") == "1\n5"

# provided-like chain
assert run("4\n1 2 3 4\n") == "1\n7"

# no merges
assert run("3\n10 100 1000\n") == "3\n1000 100 10"

# all equal
assert run("5\n7 7 7 7 7\n") == "5\n7 7 7 7 7"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 10 100 1000 | 変更なし | 無効なマージはありません |

 ## 特殊なケース

 重要なエッジ ケースは、値を処理する前にはローカルで表示されなかった新しい機会がマージによって作成される場合です。 たとえば、1、2、3、4 から開始して、最適な結果は、中間結果が後のマージに参加できるように、マージを正しい順序で前方に伝播するかどうかに依存します。 アルゴリズムは、周波数を継続的に更新し、新しく作成された値を後で処理できるようにすることでこれを処理し、チェーンが失われないようにします。 

もう 1 つのエッジ ケースは、大きな値が優勢であるにもかかわらず、小さな値が上方にカスケードする可能性がある場合です。 続行する前に常にローカル マージを実行するため、小さなチェーンはより高い値の決定に干渉する前に完全に解決され、最終的な辞書編集上の最大化の正確さが維持されます。
