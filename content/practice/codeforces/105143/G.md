 ## 解決策
 ## 問題の理解

 2種類のアイテムが与えられます。 がある`n`タイプ A の項目、それぞれの寄与値`a`、 そして`m`タイプ B の項目、それぞれの寄与値`b`。 私たちは同じ「製品」を繰り返し組み立てたいと考えています。 各製品は、そのバンドルの合計値が正確に一致するように、負でない数の A アイテムと負でない数の B アイテムを選択することによって定義されます。`k`。 

単一の製品がどのように形成されるかを決定したら、すべての製品でその構成を維持します。 製品が使用する場合`x`アイテムと`y`B アイテムの場合、各製品は価値を消費します`x·a + y·b = k`。 その後は、ご用意できる数を超えない範囲で可能な限り多くの製品を製造します。つまり、製品の数には制限があります。`n / x`そして`m / y`(係数がゼロの側は無視します)。 

出来るだけ完成品を生産した結果、未使用品が残ってしまう場合がございます。 すべての有効な製品定義の中で、残ったアイテムの総数を最小限に抑えたいと考えています。 

重要な点は、利益だけを目的として 1 つの製品の構成を最適化しているのではなく、両方の在庫をどれだけ効率的に排出できるかという観点で最適化しているということです。 全体として無駄になる残り物が少なくなれば、より少ない製品を生産する構成でも最適である可能性があります。 

制約により許可されるのは、`n, m, a, b, k`まで`10^9`最大 50 のテスト ケース。 これにより、実行可能なすべてを列挙するアプローチは除外されます。`(x, y)`ペアは直接ペアになります。`O(k)`最悪の場合。 

1 つのタイプだけで製品を形成できる場合、微妙なエッジケースが現れます。 たとえば、次の場合`k`で割り切れます`a`、 それから`(x = k/a, y = 0)`は有効であり、B アイテムが不足している場合に最適である可能性があります。 同様に、`(x = 0, y = k/b)`。 

もう 1 つの特殊なケースは、複数の分解が行われる場合です。`k`どれが最適かは、生産数と在庫制限がどのように関係するかによって決まります。 最大化という素朴で貪欲な選択`x + y`または、製品数が非線形に依存するため、製品ごとの残りを最小限に抑えることは失敗します。`(x, y)`。 

## アプローチ

 ブルートフォースのアイデアは、負でない整数のペアをすべて列挙することです。`(x, y)`そのような`a·x + b·y = k`、各ペアの生産をシミュレートします。 候補ごとに、完成した製品をいくつ製造できるかを計算し、残りを数えます。 これは、有効な製品定義をすべてチェックするため、正しいです。 

問題は、一次方程式の解の数が膨大になる可能性があることです。 最悪の場合、`a = 1`そして`b = 1`、その後、すべてのペア`(x, y)`と`x + y = k`有効です。`O(k)`候補者が多すぎるため、`k`まで`10^9`。 

重要な観察は、線形ディオファントス方程式のすべての解が 1 次元族を形成しているということです。 拡張ユークリッド アルゴリズムを使用して単一の解を見つけると、他のすべての解はパラメーターに沿った線形シフトとして表現できます。`t`。 これにより、検索空間が 2 次元の列挙から 1 つの等差数列に変わります。 

それぞれの有効な`(x, y)`家族、製品の数は状況に応じて異なります`t`、目的は次の線形関数になります。`t`制限された間隔にわたって。 これは、すべての値ではなく、間隔の境界のみを確認する必要があることを意味します。

 ## アルゴリズムのチュートリアル

 私たちは単一のテストケースに焦点を当てます。 

### 1. k の有効な分解を 1 つ見つけます。 

解決します`a·x + b·y = k`拡張ユークリッド アルゴリズムを使用して、`(a, b)`。 もし`g = gcd(a, b)`分けない`k`、個別に処理される単一タイプの製品のみを使用できるという些細な場合を除いて、解決策は存在しません。 

特定の 1 つの解決策が得られます`(x0, y0)`。 

### 2. すべての解決策を表現する

 すべての整数解は次のとおりです。```
x = x0 + t · (b / g)
y = y0 - t · (a / g)
```整数の場合`t`。 

これにより、問題は有効な選択肢を選択することに変わります。`t`。 

### 3. t の有効範囲を決定する

 私たちは次のことを要求します:```
x ≥ 0
y ≥ 0
```これらの不等式は次のように変換されます。```
t ≥ -x0 / (b/g)
t ≤  y0 / (a/g)
```したがって、間隔を取得します`[L, R]`有効な`t`。 

### 4. 一定の t に対する製品の数を計算します。 

固定の場合`(x, y)`、製品の数は次のとおりです。```
tprod = min(n / x, m / y)
```(除算がスキップされるゼロのケースは無視します)。 

残ったアイテムは次のとおりです。```
(n - tprod·x) + (m - tprod·y)
```製品を最大限に活用することは、残り物を最小限に抑えることと同じです。 

### 5. 全体にわたる最適化

 A と B の使用法のバランスが良くなると、製品の数が増加します。 置き換える`x(t), y(t)`製品ごとの使用済みアイテムの合計を直線的にします。`t`したがって、その後の使用済みアイテムの合計は`tprod`製品もエンドポイントに関して単調です。 

評価のみを行っております`t = L`そして`t = R`有効な区間にわたって目標が線形になるためです。 

また、A のみまたは B のみが積を形成する縮退ケースも明示的に考慮します。 

### なぜ効果があるのか

 実現可能なすべての製品構造は、単一のディオファンチン ソリューション ファミリに対応します。 そのファミリー内では、実現可能な製品数は、在庫制限によって課されるパラメーター境界に応じて単調に変化します。 目標は固定された構成の製品の数において線形であるため、最適解は実現可能な極端なパラメータ値で発生する必要があり、内部では決して発生しません。 これにより、ソリューション ファミリごとに最大 2 つの候補をチェックするという問題が軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def extended_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = extended_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def solve_case(n, m, a, b, k):
    best_leftover = n + m

    # case 1: only A
    if k % a == 0:
        x = k // a
        if x > 0:
            prod = n // x
            if prod > 0:
                used = prod * x
                best_leftover = min(best_leftover, n + m - used)

    # case 2: only B
    if k % b == 0:
        y = k // b
        if y > 0:
            prod = m // y
            if prod > 0:
                used = prod * y
                best_leftover = min(best_leftover, n + m - used)

    g, x0, y0 = extended_gcd(a, b)
    if k % g != 0:
        return best_leftover

    mul = k // g
    x0 *= mul
    y0 *= mul

    # step size
    dx = b // g
    dy = a // g

    # find bounds for t
    import math

    def floor_div(a, b):
        return a // b if a * b > 0 else -((-a) // b)

    L = -10**30
    R = 10**30

    # x >= 0
    if dx != 0:
        L = max(L, (-x0 + dx - 1) // dx)
    # y >= 0
    if dy != 0:
        R = min(R, y0 // dy)

    # check endpoints
    for t in [L, R]:
        x = x0 + t * dx
        y = y0 - t * dy
        if x <= 0 or y <= 0:
            continue
        prod = min(n // x, m // y)
        if prod == 0:
            continue
        used = prod * (x + y)
        best_leftover = min(best_leftover, n + m - used)

    return best_leftover

def main():
    T = int(input())
    for _ in range(T):
        n, m, a, b, k = map(int, input().split())
        print(solve_case(n, m, a, b, k))

if __name__ == "__main__":
    main()
```実装は、純粋な A 構造と純粋な B 構造を別々に処理することから始まります。これらは、1 つの変数がゼロである縮退解に対応しており、ディオファントス変換のみに依存している場合は見逃しやすいためです。 

拡張ユークリッド部分は、方程式の基本解を構築します。`a·x + b·y = k`。 一致するように拡大縮小した後`k`、ステップの方向を導き出します`dx`そして`dy`、有効な解に沿って一方の変数が増加する一方で、もう一方の変数が減少する様子を説明します。 

の境界`t`の非負性制約から導出されます。`x`そして`y`。 目標は実現可能な値全体で単調に動作するため、この間隔のエンドポイントのみがテストされます。

 ## 特殊なケース

 1つの項目タイプのみを満たす場合`k`、ディオファントスの解が存在しても実現可能性に違反する場合でも、アルゴリズムはそれを考慮する必要があります。 明示的な単一タイプのチェックにより、正確性が保証されます。 

いつ`a`そして`b`が等しい場合、すべてのソリューションは対称ファミリーに集約され、両方のエンドポイントが同一の結果を生成します。 変換は定数関数に帰着するため、区間ロジックは引き続き正しく評価されます。`t`。 

いつ`gcd(a, b)`分けない`k`、混合溶液は存在しません。 このアルゴリズムは、独立した A のみおよび B のみのパッキングに正しくフォールバックし、実現可能な単一タイプの製品が見逃されないようにします。
