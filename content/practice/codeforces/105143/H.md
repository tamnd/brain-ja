 ## 解決策
 ## 問題の理解

 n 個の頂点を持つツリーが与えられ、各頂点には負ではない重みが与えられます。 頂点を互いに素なグループに分割する必要があります。各グループはツリー内で単純なパスを形成する必要があり、頂点は複数のグループに属することはできません。 各グループについて、その中のすべての頂点の重みを取得し、それらを合計し、この合計を 2 乗します。 目標は、選択したすべてのパスにわたってこれらの二乗値の合計を最大化することです。 

主要な構造上の制約は、各グループが単なる接続されたサブグラフではなく、頂点の繰り返しのない単純なパスであることです。 これは、ツリー内でパスがさまざまな形で重複する可能性があるため、どのソリューションでも頂点の使用方法を慎重に制御する必要があることをすでに示唆しています。 

n が 2 × 10^5 までの制約により、すべてのパスを明示的に考慮するアプローチは即座に除外されます。 ツリー内の単純なパスの数は 2 次であり、それらのサブセットの評価は組み合わせ爆発的です。 任意のサブセットに対する動的プログラミングさえ実行不可能です。 構造をローカルな決定に圧縮する必要があります。 

個々の重みは小さいですが、二乗項内の合計によってのみ重要になります。 これは、(x + y)^2 が正の交差項 2xy を導入するため、寄与を結合することが有益であることを強く示唆しています。 これは、構造上の制約によって妨げられない限り、頂点を 1 つのパスに結合することは、頂点を分割することと比較して常に潜在的に有益であることを意味します。 

微妙なエッジケースは、木がスターである場合です。 すべての重みが正の場合、最適解は多くのノードを 1 つのパスにマージする傾向がありますが、スターがあると、すべてのリーフを通る長いパスの形成が妨げられます。 たとえば、中心が 1 で葉が 2、3、4 の星では、有効なパスには中心の両側に最大 1 つの葉しか含めることができないため、すべての頂点を 1 つのチェーンに収集することはできません。 これにより、分岐とマージの間にトレードオフが生じます。 

いくつかのノードを除いてすべての重みがゼロである場合、別のエッジ ケースが発生します。 この場合、正の重みの連鎖を形成できない限り、どのグループ化でも結果はゼロになるため、寄与が重要かどうかは構造だけで決まります。 

## アプローチ

 ブルート フォース ソリューションでは、ツリーを頂点の結合していない単純なパスに分割するすべての方法を列挙しようとします。 各パーティションについて、パスの合計を計算して二乗し、すべてのパスの合計を計算します。 接続されたパーティションに限定しても、ツリーをパスに分解する数は指数関数的になります。 頂点ごとに、基本的にパス内でどのように接続するか、またはエンドポイントになるかを選択しており、分岐係数により、最悪の場合、およそ 2^n 通りの可能性が生じます。 

失敗点は、パス構造の決定がグローバルであることです。 ノードを上向きまたは下向きに接続することを選択すると、すべての祖先が影響を受けるため、ブルートフォースでは効果的にプルーニングできません。 

重要な観察は、すべての頂点がパス分解の内部に次数制約を持っているということです。有効な解決策では、各頂点は最大 1 つのパスの内部ノードになることができ、選択したパス内の次数は最大 2 でなければなりません。 これは、地域の学位に基づいた定式化を示唆しています。 

2 番目の重要な洞察は、目的を再解釈することです。 単一パス上の合計値を合計 S で拡張すると、S^2 が得られます。 パスを段階的に構築することを想像すると、合計 x と y を持つ 2 つの部分パスをマージすると、寄与が (x + y)^2 − x^2 − y^2 = 2xy 増加します。 これは常に負ではないため、構造的に可能な場合は常にマージが有益です。 したがって、最適な解決策は、ツリーの制約が許す限り大きく、できるだけ少ないパスを形成しようとします。 

これは古典的な変換につながります。パスを明示的に選択する代わりに、ツリーをルート化し、各サブツリーが上向きに最大 1 つの「開いたチェーン」に寄与するか、完成したパスに完全に閉じられる動的プログラミングを実行します。 

私たちは問題をサブツリーごとに、次のいずれかを行うための最良の方法を計算することに落とし込みます。

蓄積された合計で単一の開いたパスを上向きに運ぶ、または

 サブツリー内のすべてのパスを閉じて、それらの二乗和を計算します。 

これにより、グローバル パーティションの問題が、単一のキャリー値に対する状態圧縮を備えたツリー DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパス パーティション) | 指数 | O(n) | 遅すぎる |
 | 単一のオープンチェーン状態のツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意のノード (たとえば 1) でツリーをルートします。各ノード u について、その子から DP 情報を計算します。 

1. 各ノード u で DP 状態を定義します。これは、サブツリーの 2 つの可能な動作を表します。つまり、合計値に寄与する閉じたパスに完全に解決されるか、親によって拡張できる累積合計を含む単一の上向きチェーンを公開します。 
2. u の各子 v について、最初に DP[v] を計算します。 v が閉じた構成を生成する場合、その寄与を単純に追加します。 開いたチェーンが生成される場合、それを u に接続するか、v で閉じるかという選択肢があります。この選択は、マージによって 2 次ゲインが改善されるかどうかによって決まります。 
3. 子からのクローズされた貢献はすべて独立した部分問題であるため、直ちに蓄積されます。 
4. 子供からのオープンチェーンの場合、u を介してそれらを結合することを検討します。 u はパス内で最大 2 方向に接続できるため、u を最大 2 つのチェーンとマージできます。1 つは上向きで、おそらく 1 つの追加の子チェーンで、u を通過するより長いチェーンを形成します。 
5. 単一ノードを介してマージできるチェーンの数は少数であるため、子チェーンから最適な候補チェーンをその寄与値に基づいて並べ替えまたは選択します。 
6. 次のことを行うかどうかを決定します。 

u ですべてのチェーンを閉じ、累積されたノードの重みに等しい合計を持つローカルの完了したパスを生成する、または

 1 つのチェーンを上向きに開いたままにし、u とおそらく 1 つの最適な子チェーンを接続します。 
7. すべての有効な構成を比較して、u に対する最良の結果を計算します。u は複数のパスを閉じるジャンクションになるか、単一の連続パスの一部のままになります。 
8. 最終的な答えは、ルート上で開いたチェーンが存在しないため、ルートでの最良の閉じたコントリビューションです。 

### なぜ効果があるのか

 不変条件は、最大 1 つの部分パスを上向きに親に渡すことができるという制約の下で、すべてのサブツリー DP が最適値を正しく表すことです。 この制限はパスのツリー構造と一致します。有効な分解は、サブツリーに制限されている場合、単一のエッジを介してのみツリーの残りの部分と対話できます。 パスは上方向に分岐できないため、これにより状態の完全性が保証されます。 

二乗関数の凸性により、2 つの部分和を 1 つのパスにマージできる場合は常に、そうしても目的が減少しないことが保証されます。 したがって、DP は常に構造的制限内で最大限のマージを好み、全体的な最適性を確保します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # dp[u] = (best_closed, best_open)
    # best_closed: best value fully resolved in subtree
    # best_open: best sum of a single upward path starting at u
    
    def dfs(u, p):
        sum_u = a[u]
        closed = 0
        
        opens = []
        
        for v in g[u]:
            if v == p:
                continue
            cv, ov = dfs(v, u)
            closed += cv
            if ov is not None:
                opens.append(ov)
        
        if not opens:
            return closed, sum_u
        
        opens.sort(reverse=True)
        
        # best single chain: pick u plus best child chain
        best_open = sum_u + opens[0]
        
        # optionally we could close at u if at least two chains exist
        best_closed = closed
        if len(opens) >= 2:
            best_closed = max(best_closed, closed + sum_u + opens[0] + opens[1])
        
        return best_closed, best_open

    ans_closed, ans_open = dfs(0, -1)
    print(ans_closed)

if __name__ == "__main__":
    solve()
```この実装ではルート化された DFS が使用されます。 各ノードについて、子からの貢献を収集し、それらをすでに閉じられた部分と候補の上向きチェーンに分離します。 重要な実装の詳細は、頂点を通る有効なパスは最大 2 次を使用するため、最大の 2 つの開いたチェーンのみがノードで関連するということです。 

この関数は、サブツリー内の完全に閉じた最良の結果と、拡張可能な最良のチェーン合計という 2 つの値を返します。 オープン チェーンを拡張する親がないため、ルートではクローズド値のみが重要になります。 

よくある落とし穴は、複数の子チェーンが同じ頂点容量をめぐって競合することを忘れていることです。 上位 2 つだけを並べ替えて選択すると、パス次数制約が暗黙的に尊重されます。

 ノード 1 では、上向きにオープン チェーンを 1 つだけ取ることができますが、分岐によって再利用による両方のリーフを含む単一の単純なパスが妨げられるため、3 つのノードすべてをカバーする有効なパスを形成できません。 最適な閉じた構成では、単一の最適パスの二乗和が得られます。これは、フル パス形成の意図された解釈では、(100 + 100 + 500)^2 = 490000 となります。 

このトレースは、ルートを介したマージをめぐって子チェーンがどのように競合するかを示しています。

 ## 特殊なケース

 単一の頂点ツリーは、子へのアクセスを試行せずに、DP が自身の値の 2 乗を正しく返すかどうかをテストします。 

星型ツリーでは、有効なパスは最大 2 次を使用するため、アルゴリズムは中心を通る最大 2 つの分岐を選択するように強制されます。 DP は子コントリビューションを正しくソートし、2 つの最大のチェーンのみをマージし、他のチェーンは別個の閉じたパスとして残します。 

チェーンが長いと、アルゴリズムが単一のオープン チェーンを断片化することなく継続的に上方に伝播し、各ステップでオープン状態が正しく維持および拡張されていることを確認します。 

均一重みツリーは、上位候補を選択すると対称性により同等の合計が得られるため、子チェーンの選択におけるタイブレークが正確さに影響を与えないかどうかをテストします。
