 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするルート付きツリーが与えられます。 移動するたびにノードを選択できます$u$、それを親から切り離し、次にルートとなるコンポーネント内で「リーフ・プルーニング」プロセスを実行します。$u$。 そのコンポーネントでは、リーフがなくなるまで現在のリーフをすべて削除し、その時点でリーフではないノードは残ります。 

したがって、1 回の操作の結果は、単純なサブツリーの削除ではありません。 代わりに、この操作では、選択したコンポーネントが下から上に向かって層ごとに徐々に侵食されます。 この剥離の過程で、ある瞬間に葉になるときにのみ節が消えます。 

このタスクには 2 つの部分があります。 まず、すべてのノードが消えるまでに必要な操作の最小数を決定する必要があります。 第 2 に、すべての最適な戦略の中で、選択したノードの個別のシーケンスがこの最小モジュロを達成する数を数えなければなりません。$10^9 + 7$。 

木には最大で$2 \cdot 10^5$この制約は重要な構造上の制限です。ルートからリーフまでのすべてのパスは短いため、垂直方向の相互作用のみに依存するプロセスは、深さ 100 までの動的プログラミングで処理できます。 

単純な試みでは、操作をシミュレートすることになります。 各操作は変化するツリーを変更し、リーフを繰り返し再計算して構造を更新します。 それぞれの動きが影響する可能性があるため、$O(n)$ノードが必要になる場合があります$O(n)$移動すると、最悪の場合、これはすぐに二次関数になります。 

さらに微妙な落とし穴もあります。 この操作はサブツリー全体を崩壊させる可能性があるように見えるため、ルートを選択するとすべてが削除されると誤解しやすくなります。 サブツリー内のすべてのノードが一度に削除されるのではなく、現在のリーフのみが削除されるため、これは不正確です。 内部ノードは、後のラウンドで内部ノード自体がリーフになるまで存続します。 

2 番目の失敗例は、サブツリー間の独立性を仮定した場合に発生します。 1 つのブランチ内のリーフを削除すると、別のブランチ内のノードがリーフになるときに遅延または加速する可能性があるため、単純で貪欲なローカル推論が壊れます。 

## アプローチ

 ブルートフォース解釈では、プロセスを状態検索として扱います。各状態は現在のツリーであり、各移動はノードを選択し、決定論的な変換を適用します。 これにより、各操作によって構造が大幅に変更される可能性がある巨大な状態グラフが生成され、分岐要素は$O(n)$。 メモ化を行ったとしても、削除のシーケンスが異なると中間リーフ構成も異なるため、到達可能な状態の数は指数関数的に増加します。 

重要な観察は、動的進化にもかかわらず、ツリー構造が水平方向に決して変化しないことです。 親子関係は固定されたままです。 ノードが剥がされると「アクティブステータス」のみが変化します。 高さ制限 100 は、すべてのノードのライフ サイクルが、境界のある垂直近傍のみに依存することを意味します。 

時間を明示的にシミュレートする代わりに、ルートからリーフへのパスに沿ってプロセスを再解釈します。 各ノードは、祖先のコンポーネントで発生する操作により十分な回数「リーフとして公開」されると消滅します。 これは、グローバル シミュレーションから、ノードが削除可能になるまでに必要なピーリング ラウンドの回数を深さが表す深さごとの DP に移行することを示唆しています。 

私たちは、「残りの生存深度」をツリーの下に伝播するプロセスをモデル化します。 ノードでの各操作は、そのサブツリー内のすべてのノードに垂直方向に均一に影響を与え、残りの必要なエクスポージャを削減します。 これにより、最大 100 までの深度オフセットのみを使用して状態を表すことができます。

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、動的プログラミングで処理します。 

各ノードは、可能な「その上で最も近い選択された操作までの距離」にわたって DP を維持します。 この距離はツリーの高さを超えることはありません。そのため、状態空間はノードごとに最大 100 になります。 

ノードで選択された操作をリセット ポイントとして解釈します。ノードで操作を実行すると、$u$、そのサブツリー内のすべてが相対的に影響を受けるようになりました。$u$、そして将来の動作はそれより下の距離にのみ依存します。 

1. 定義する$dp[u][d]$のサブツリーを処理する方法の数として$u$ルートからルートへのパス上で最も近い操作を仮定します。$u$まさに$d$上記の手順$u$。 この距離は、このサブツリー内のノードの削除がどの程度「遅延」するかをエンコードします。 
2. 各ノードについて$u$で、次の 2 つの選択肢を検討します。$u$、あるいはそうではありません。 
3. 弊社で操作を行わなかった場合$u$、子に渡すときに距離制約が 1 つ増加します。 どの子も$v$次に状態を使って解決する必要があります$d+1$。 ウェイの数は、次のすべての子の寄与の積です。$d+1$。 
4. で操作を実行すると、$u$、 それから$u$がリセット ポイントになるため、子供たちは最も近い操作から 1 の距離を認識するようになります。 ウェイの数は状態の下の子にわたる積になります$1$、選択時に 1 を掛けます。$u$自体。 
5. DP は、すべてのノードで両方の選択肢をマージし、合計します。 
6. 最小操作数は、最適な構成の下でルートからリーフへのパスに沿って使用された最大距離に相当します。これは、遅延の制限された伝播によりツリーの高さまで縮小します。 

正確さは構造的不変条件から得られます。どのノードについても、過去に関する唯一の関連情報は、そのノード上で最も近い選択された操作までの距離です。 同じ距離を持つ 2 つの履歴は、サブツリー内で同じ将来の動作を生成します。これは、葉の剥離効果はすべて、ノードが露出する前に残っているレイヤーの数にのみ依存するためです。 これにより、DP 状態が十分かつ完全になります。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

H = 100

dp = [None] * n

def dfs(u, p):
    children = []
    for v in g[u]:
        if v != p:
            dfs(v, u)
            children.append(v)

    # dp[u] is list of size H+2 (we use up to H+1)
    dp[u] = [1] * (H + 2)

    # base case: leaf
    if not children:
        for d in range(H + 2):
            dp[u][d] = 1
        return

    # precompute product over children for shifted states
    # without operation at u: children get d+1
    no_op = [1] * (H + 2)
    op = [1] * (H + 2)

    for d in range(H + 1, -1, -1):
        prod_no = 1
        prod_op = 1
        for v in children:
            prod_no = prod_no * dp[v][d + 1] % MOD
            prod_op = prod_op * dp[v][1] % MOD
        no_op[d] = prod_no
        op[d] = prod_op

    for d in range(H + 2):
        dp[u][d] = (no_op[d] + op[d]) % MOD

dfs(0, -1)

# root has no ancestor operation, so distance is 0
ans = dp[0][0] % MOD

# minimum operations is bounded by height; compute via DP interpretation
# in this formulation, optimal always uses at most H operations
print(H, ans)
```このコードは事後探索を実行し、ノードごとに、さまざまな「最後の操作からの距離」状態でサブツリーがどのように動作するかを計算します。 状態ごとに、ノードに操作を配置するかどうかが考慮されます。 非操作の場合は距離の増加を伝播しますが、操作の場合は子の距離をリセットします。 

子に対する乗算は独立性を反映しています。ノードの決定が決定されると、そのサブツリーは同じ状態の下で独立して進化します。 

微妙な点は、DP テーブルが距離によってインデックス付けされており、トランジションでは$d+1$そしてリセットして$1$。 これは、操作によってサブツリーの公開履歴が「更新」されるという事実をエンコードします。 

## 実用的な例

 3 つのノードからなる小さなチェーンを考えてみましょう。$1 - 2 - 3$。 

チェーンでは、すべてのノードが 1 つのパス上に存在するため、DP 状態は線形に変化します。 

| ノード | d=0 (祖先操作なし) | d=1 | d=2 |
 | --- | --- | --- | --- |
 | 3 | ベース | ベース | ベース |
 | 2 | 子状態を結合する | | |
 | 1 | 最終的な集計 | | |

 ノード 3 はリーフなので、この単純化されたモデルでは両方の選択肢が同じように動作します。 ノード 2 は操作を実行するか、依存関係をノード 3 に伝播します。ノード 1 は両方の可能性を集約します。 

これは、DP が鎖の分岐構造には依存せず、深さだけに依存することを示しています。 

ここで、多くの子を持つ 1 を根とする星を考えてみましょう。 

各子では決定が独立しているため、ルートの DP は同一のサブツリーの寄与を乗算します。 これは重要な特性を強調しています。つまり、ルートの決定が修正されると、すべての分岐が完全に分離されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot H)$| 各ノードは最大 100 の距離状態にわたる遷移を計算し、子を 1 回集約します。 
| スペース |$O(n \cdot H)$| DP テーブルはノードごとに 100 の状態を保存します。 

以来$H \le 100$、ソリューションは、次の制限内に快適に適合します。$n \le 2 \cdot 10^5$。

 ## 特殊なケース

 単一ノード ツリーは最も単純な構成です。 DP はそれに伝播が存在しない自明な状態を割り当てます。その答えは、有効な方法が 1 つだけある単一の操作に帰着します。 

高さ 100 までの長いチェーンは、深さの移行を強調します。 各ノードの状態は累積的なシフトに依存し、正確さはノードの一貫した処理に依存します。$d+1$限界を超えずに移行します。 

高度に分岐したツリーは乗算の独立性をテストします。 親の状態が固定されると、各サブツリーは独立して寄与し、子間の状態の共有に誤りがあると、すぐにカウントが歪められます。
