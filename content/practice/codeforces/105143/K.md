 ## 解決策
 ## 問題の理解

 1 から n までの整数を一列に並べたシーケンスが与えられます。 2 人のプレーヤーが最初のプレーヤーから順番に交互に動きます。 プレイヤーのターンで許可される唯一のアクションは、左端または右端の残りの数字を削除することですが、これは残りのすべての数字の XOR がゼロ以外の場合にのみ許可されます。 XOR がゼロになると、現在のプレイヤーには正当な手がなくなり、即座に負けます。 

各ラウンドは独立しています。 与えられた n ごとに、両方のプレーヤーが最適にプレイすると仮定して、最初のプレーヤーが強制的に勝利するかどうかを判断する必要があります。 

T が 100,000 まで、n が 1,000,000 までという制約は、クエリごとに O(1) または償却された O(1) が必要であることを意味します。 ゲームのシミュレーションは、テスト ケースごとに線形または対数であっても、直ちに実行不可能になります。 O(T log n) であってもタイトであり、テストごとに n に依存するものは遅すぎます。 

微妙なエッジ ケースは、配列全体の最初の XOR がすでに 0 である場合です。 この状況では、最初のプレイヤーは有効な手をまったく持っていません。 

たとえば、n = 1 の場合、配列は [1]、XOR は 1 であるため、移動が存在します。 n = 2、配列が [1,2]、XOR が 3 の場合、まだ手は存在します。 n = 3 の場合、XOR は 0 となるため、最初のプレイヤーはすぐに負けます。 これは、答えが 1 ⊕ 2 ⊕ ... ⊕ n がゼロかどうかのみに依存することをすでに示唆しています。 

もう 1 つのエッジ ケースは、要素を削除すると、最終的に相手のターンで XOR が正確にゼロになる可能性がある場合です。 単純なシミュレーションでは、最初のプレイヤーが常にターンごとに少なくとも 1 つの手を持っていると仮定するかもしれませんが、実際には、要素の数よりも到達可能な状態の同等性の方が重要です。 

## アプローチ

 ゲームの直接シミュレーションでは、現在の間隔が維持され、削除のたびに XOR が再計算されます。 プレフィックス XOR を維持する場合、各手のコストは O(1) ですが、ゲームではラウンドごとに O(n) の手が存在する可能性があり、最悪の場合は O(nT) となり、これは制限をはるかに超えています。 

重要な観察は、ゲームが単一の不変条件、つまり残りのセグメントの XOR によって完全に制御されていることです。 プレーヤーがブロックされるのは、この XOR がゼロになるときだけです。 プレイヤーは端から削除するだけなので、残りのセットは常に連続した部分配列になります。 これは、ゲームの状態が現在の間隔 [l, r] とその XOR によって完全に決定されることを意味します。 

ここで、実際に何が重要であるかを考えてみましょう。XOR(l, r) が 0 以外の場合に限り、プレーヤーは移動することができます。 移動後、間隔はどちらかの側で 1 ずつ縮小するため、1 つのエンドポイントを削除することで XOR が更新されます。 これにより、プレイヤーの手番で XOR がゼロになる状態を回避しながら、間隔を繰り返し縮めることと同じになります。 

重要な単純化は、両方のプレイヤーが対称的であり、常に同じ構造に直面していることです。 唯一の負け条件は、自分のターンで XOR がゼロの状態に遭遇することです。 これにより、ゲームは、最初のプレイヤーが自分のターンで相手をゼロ XOR インターバルに強制できるかどうかに集約されます。 

小規模なケースを調べると、パターンが現れます。つまり、結果は XOR(1..n) が 0 かどうかにのみ依存します。 ゼロの場合、最初のプレイヤーは開始時にまったく動くことができません。 ゼロ以外の場合、最初のプレイヤーはいつでも手を打つことができ、その構造により、最終的には対戦相手が最初にゼロ XOR 状態に直面することになります。 

これが機能するのは、すべての手が制約された方法でパリティを反転し、ゲームは間隔を縮める以外に根本的に異なる状態に分岐できないためです。 したがって、ゲーム全体は最初の XOR による単純な分類に分類されます。 

よく知られた周期公式を使用して XOR(1..n) を計算します。 

1. n % 4 == 0 の場合、XOR は n です。 
2. n % 4 == 1 の場合、XOR は 1 です。 
3. n % 4 == 2 の場合、XOR は n + 1 になります。 
4. n % 4 == 3 の場合、XOR は 0 です。 

したがって、最初のプレーヤーは、n % 4 == 3 の時点で負けます。

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、n を読み取ります。 n の値によって初期状態が完全に決定されるため、他の情報は必要ありません。 
2. n mod 4 に基づく周期単位を使用して、シーケンス 1 から n の XOR を計算します。これにより、配列の構築や配列の反復処理が回避されます。 
3. 計算された XOR がゼロの場合、最初のプレーヤーが負けたことを出力します。 これは、ゲーム開始時に正当な手が存在しない局面に相当します。 
4. それ以外の場合は、最初のプレイヤーが勝つことを出力します。 この場合、最初のプレイヤーはいつでも初動を行うことができ、相手のターンでも最終位置以外の位置を維持できます。 

### なぜ効果があるのか

 ゲームの状態は、残りのインターバルの XOR という 1 つの値によって完全に特徴付けられます。 移動するたびに間隔が 1 エンドポイントずつ減少します。唯一の負け条件は、自分のターンで XOR がゼロになることです。 すべての間隔は固定順列の連続するプレフィックス/サフィックスであるため、XOR 構造は間隔の正確な位置ではなく、間隔のサイズのみに依存します。 これにより、決定木全体が n のみの関数に折りたたまれ、すべての中間ゲームの選択が最終的な結果の分類とは無関係になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def xor_1_to_n(n: int) -> int:
    r = n % 4
    if r == 0:
        return n
    if r == 1:
        return 1
    if r == 2:
        return n + 1
    return 0

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        x = xor_1_to_n(n)
        if x == 0:
            out.append("Pinkie Pie")
        else:
            out.append("Fluttershy")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、XOR 計算が定数時間ヘルパーに分離されます。 これにより、n に対する偶発的な反復が防止されます。 各テスト ケースは個別に処理され、繰り返しの I/O オーバーヘッドを回避するためにリストに追加されます。 

決定ステップは理論的な結果を直接反映しています。XOR がゼロの場合は、最初のプレーヤーが即座に負けている状態を意味し、それ以外の場合は最初のプレーヤーが勝ちの手を持っています。

### 例 2

 | ステップ | n | n mod 4 | XOR(1..n) | 結果 |

 初期状態ではすでに XOR が 0 になっているため、最初のプレイヤーには有効な手がありません。 これは、ゲームをターミナル状態で開始できる唯一の方法です。 

これら 2 つの例は、分類の両方のエンドポイントを示しています。XOR が 0 以外の場合は即時勝ち、XOR が 0 の場合は即時損失です。

 ## 特殊なケース

 n = 3 の場合、配列全体の XOR は 0 になります。 アルゴリズムは n % 4 == 3 を計算し、最初のプレイヤーが開始時に有効な手を持っていないという事実と一致して、即座に負け状態として分類します。 

n = 1 の場合、XOR はゼロ以外であり、アルゴリズムは勝利を返します。 ゲームは 1 つの手で終了します。これは、ゼロ以外の XOR によって唯一の要素を削除できるというルールと一致します。 

n = 4 の場合、XOR は 4 であるため、アルゴリズムは勝利を返します。 シーケンスが長くても、分類は XOR パリティのみに依存し、最初のプレイヤーは常に初期状態から少なくとも 1 つの正当な手を持っています。
