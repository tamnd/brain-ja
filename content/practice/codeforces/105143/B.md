 ## 問題の理解

 負ではない整数の配列と、どの要素も負にならない限り、ある位置から別の位置に任意の量の値を移動できる非常に柔軟な操作が与えられます。 各操作では 2 つのインデックスが選択され、一方から他方に任意の非負の量が転送されます。 この操作を実行できるのは最大でも$n$しかし、各操作は大きな値を移動できるため、このプロセスの真の能力は、配列の合計をほぼ任意に再分配できることです。 

これらの再分配の後、最終的に元の配列と同じ総和を持つ新しい配列が得られます。 目標は、配列内のすべての要素のビット単位の OR を最小化する最終的な配置を選択することです。 

キーの量は配列全体の OR であり、少なくとも 1 つの要素にどのビットが出現するかによってのみ決まります。 任意の要素に設定されているビットは、最終的な答えに影響します。 

制約$n \le 2 \cdot 10^5$これは、どのような解も本質的に線形または線形に近いものでなければならないことを意味します。 再配布操作をシミュレートしたり、構成を検索したりすることはできません。 操作の構造は、問題が動きのシミュレーションではなく、合計に対する全体的な推論に関するものであることを強く示唆しています。 

1 つの大きな値を除いてすべての数値がゼロの場合、微妙なエッジ ケースが発生します。 その場合、再分配は必要なく、答えは単にその値です。 もう 1 つのエッジ ケースは、合計が他のものと比較して小さい場合です。$n$、多くの要素がゼロになる可能性があり、制限要因は合計をどれだけ均等に分散できるかであることを示唆しています。 

素朴なアプローチでは、ビットごとの寄与を追跡しながら値を貪欲に再分配しようとするかもしれませんが、すべての配列が同じ合計を共有しているとしても、可能な配列のスペースが膨大であるため、そのようなシミュレーションは失敗します。 

## アプローチ

重要な観察は、この操作により合計の完全な再分配が可能になるため、唯一の不変条件はすべての要素の合計であるということです。 したがって、任意の配列を自由に選択できます。$n$合計が次になる非負の整数$S$、 どこ$S$は初期の合計額です。 

これを理解すると、問題はサイズのマルチセットを選択することになります。$n$合計付き$S$これにより、すべての要素のビット単位の OR が最小化されます。 OR は、選択された数値に現れる最上位のビット パターンによって決定されます。 すべての数値が一定の範囲内にあることを確認できた場合$M$の場合、OR は次を超えることはできません$M$、実際には、構築された値のビットごとの OR になります。これをできるだけ小さくすることを目指しています。 

最適な構造は、合計をできるだけ少ない大きな等しいチャンクに圧縮することです。これは、合計を細かく分散しすぎると、小さい数が必要になりますが、個別のビットに寄与する要素の数が増加するためです。 最も厳しい制約は、全体の合計を分散しながら最大要素をどれだけ小さくできるかということです。$n$ポジション。 

これにより、答えは可能な限り最小の上限によって支配されるという結論が得られます。$M$そのような$S$全体に分散できる$n$それぞれを超えない数$M$、まさに天井です。$S/n$。

 ## アルゴリズムのチュートリアル

 しましょう$S$配列内のすべての要素の合計になります。 

1. 合計を計算する$S = \sum a_i$。 これにより、許可された操作で保存されたすべての情報が取得されます。 
2. 任意の数の操作の後、任意の構成を実現できることに注目してください。$n$合計がまだ負でない非負の整数$S$。 これにより、操作から純粋なパーティショニングに焦点を切り替えることができます。 
3. 構築したい$n$OR ができるだけ小さい数値。 配列の OR は、任意の要素に出現するビットの結合によって決定されるため、個々の要素の大きさを制御すると、OR が直接制御されます。 
4. すべての最終要素が最大でも何らかの値になるように強制することを検討します。$M$。 このような構成を実現できれば、配列の OR は次を超えることはできません。$M$、それを超えるビットを導入する要素はないため$M$。 
5. 与えられた条件の実現可能条件$M$それは？$S$最大で次のように分割できます$n$パーツ、最大でも各パーツ$M$。 この制約の下で合計をパックする最良の方法は、できるだけ多くの値を使用することです。$M$を可能な限り加算し、余りを 1 つ加えます。 これはまさに次の場合に可能です$S \le n \cdot M$。 
6. 最小のもの$M$したがって$M = \left\lceil \frac{S}{n} \right\rceil$。 
7. 建設的に言えば、$\lfloor S/M \rfloor$に等しい要素$M$、1 つの要素が残りと等しく、残りをゼロで埋めます。 これは制約を尊重し、次と等しい OR を実現します。$M$。 

### なぜ効果があるのか

 このアルゴリズムは、唯一のグローバル不変条件が合計であるという事実に基づいています。 候補の最大値を確定したら$M$、への合計の実行可能な分配$n$どの要素も超えないようにパーツを配置できます。$M$。 ビットごとの OR は各要素で単調であるため、可能な最大値を減らすと OR が直接最小化されます。 実現可能な最小のキャップは、まさに最も厳しいパッキング バインドです。$S/n$, したがって、値が小さいと合計を分配できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

S = sum(a)

# minimal possible maximum value per element
ans = (S + n - 1) // n

print(ans)
```コードは、配列を読み取り、その合計を計算することから始まります。 最終的な答えは、再分配後の各要素の最小実現可能な上限に直接対応する天井除算を使用して計算されます。 総和を任意に再配分できる運用モデルであるため、運用のシミュレーションは不要です。 

よくある落とし穴は、元の数値の個々のビットについて推論しようとすることです。 この操作では、合計のみを保持しながらすべての位置構造が破壊されるため、これは不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    S = sum(a)
    return str((S + n - 1) // n)

# provided sample

# evenly divisible sum

# uneven distribution
assert run("3\n2 2 2\n") == "2"

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 1$。 アルゴリズムは戻ります$S$唯一の要素は OR を減らす方法で変更できないためです。 再配布はできないため、これは正しいです。 

もう 1 つのエッジ ケースは、1 つの大きな値を除いてすべての要素がゼロである場合です。 合計はその値に等しく、上限除算は同じ値を返します。これは、再配分によって値を減らすことができないという事実と一致します。 

合計が以下の場合$n$、天井は 1 になります。これは、少なくとも 1 つのユニットが何らかの要素に出現する必要があることを意味します。 これは、合計を多数の 0 と少数の 1 に分散して、常に OR を 1 に等しくできることを正しく反映しています。$S > 0$。
