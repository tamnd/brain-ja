 ## 解決策
 ## 問題の理解

 私たちには隠されたものが与えられています$n \times n$範囲内の正の整数で埋められたグリッド$[1, n^2]$。 グリッドは任意ではありません。値は両方向で単調です。つまり、右または下に移動しても値が減少することはありません。 したがって、すべての行は減少せず、すべての列も減少しません。 

私たちはグリッドを直接見ることはできません。 代わりに、単一のセルをクエリできます。$(i, j)$閾値あり$x$、そして裁判官は、そのセルの隠された値が最大であるかどうかを教えてくれます。$x$。 各クエリでは、選択したしきい値とのブール比較のみが表示されます。 

タスクは、$k$-すべての中で 2 番目に大きい値$n^2$このようなクエリを最大 50,000 個使用するエントリ。 

この制約は、大きな検索スペースを意味します。$n$最大 1,000 まで指定できるため、行列には​​最大 100 万個の値が含まれます。 各セルを直接読み取ることができないため、リニアスキャンは不可能であり、各検査は相互作用によりすでにコストがかかります。 どのようなソリューションでも、プローブの数を大幅に削減し、各クエリを可能な限り再利用する必要があります。 

単純な間違いは、これを各セルを個別にクエリする際の値に対する単純な二分検索として扱うことです。 たとえば、セルごとにすべての値のしきい値をチェックして完全な並べ替えリストを決定しようとすると、次のことが必要になります。$O(n^2 \log n)$クエリは制限をはるかに超えています。 

もう 1 つの微妙な落とし穴は、単調性を無視することによって発生します。 たとえば、構造を利用せずに任意のセルのみをクエリする場合、複数のセルが同じしきい値動作を共有する可能性があるため、同じ値または平坦な領域により不必要な検索が繰り返される可能性があります。 

## アプローチ

 この問題を直接的に考える方法は、すべてのクエリが「この位置は一連の値の中にあるか」という質問に答えていることを理解することです。$\le x$”。直したら$x$、概念的には細胞の数を数えることができます。$\le x$、このカウントを次と比較します。$n^2 - k$かどうかを決定する$x$答えになるのに十分な大きさです。 

ブルートフォースアプローチでは、候補者ごとにこのカウントを個別に評価しようとします。$x$。 そのためには、すべてのセルにクエリを実行して、セルが以下であるかどうかを判断する必要があります。$\le x$、につながる$n^2$値チェックごとのクエリ。 次に、値を二分探索すると、$[1, n^2]$、私たちは得ます$O(n^2 \log n)$クエリ、これは実行不可能です$n = 1000$。 

重要な構造上の観察は、行列が行方向と列方向の両方でソートされていることです。 これは、しきい値を固定すると、$x$、を満たすセルのセット$a_{i,j} \le x$左上の連続領域を形成します。セルが有効であれば、その上と左のすべても有効です。 これにより、カウントは独立したセル チェックではなく、幾何学的横断問題に変わります。 

ある位置のクエリをこの単調領域の境界へのプローブとして扱うことで、これを利用できます。 すべてのセルを個別にテストするのではなく、空間関係を再利用します。領域の動作がしきい値を下回るか上回ることがわかったら、大きなブロックを一度に削除します。 

標準的な削減は、問題を、少なくとも次のような最小値を見つけることに変換することです。$n^2 - k + 1$要素は$\le x$。 これは値に対する二分探索となり、各チェックは単調な述語になります。 課題は、クエリ制限の下で述語を効率的に実装することです。 

述語を評価するには、左下隅からガイド付きトラバーサルを実行します。 行と列はソートされているため、右に移動すると値が増加し、上に移動すると値が減少します。 各クエリは、応答に応じて行セグメント全体または列セグメント全体のいずれかを削除するため、各ステップで少なくとも 1 つの行方向または列方向が破棄され、チェックごとの合計クエリ数が次の範囲内に保たれます。$O(n)$。 

これにより、全体的な複雑さは次のようになります。$O(n \log n)$クエリは 50000 未満に収まります。$n \le 1000$。

 ## アルゴリズムのチュートリアル

 1. 最小値を見つけるタスクとして解釈します。$x$少なくともそうなるように$n^2 - k + 1$細胞は満足する$a_{i,j} \le x$。 これにより、順序統計がカウント述語に変換されます。 
2. 関数を定義する`count_leq(x)`行列内の要素の数を計算します。$\le x$インタラクティブなクエリを使用します。 
3. 計算するには`count_leq(x)`、位置から開始$(n, 1)$、左下隅。 これが選択される理由は、値が右に増加し、下に増加するという決定的な動きを可能にするためです。 
4. 各ステップで、現在位置をクエリします。$(i, j)$しきい値あり$x$。 答えが 1 の場合、値は次のようになります。$\le x$したがって、同じ列にある上記のすべても同様です$\le x$、貢献$i$その列セグメント内の有効な要素。 次に右に移動して、$j + 1$現在の列はこの行プレフィックスに対して完全に解決されているためです。 
5. 答えが 0 の場合、値は超過します$x$したがって、この行の右側にあるすべても無効になります。 上に向かって進みます$i - 1$、現在のセルを破棄し、より小さい値で検索を続行します。 
6. 列セグメントが確認されるたびに寄与を蓄積し、カウントされた領域間で重複がないことを保証します。 
7. 値の範囲に対して二分探索を実行します。$[1, n^2]$、呼び出し中`count_leq(mid)`毎回。 述語は増加するため単調です$x$有効なセルの数のみを増やすことができます。 
8. 最小値を返す$x$そのような`count_leq(x) >= n^2 - k + 1`。 

### なぜ効果があるのか

 正確さは行列の単調幾何学に依存します。 任意の固定しきい値で$x$、有効なセルのセットは、右下の閉じた領域を形成します。 トラバーサルは、この領域の境界ウォークをシミュレートします。各クエリは、列全体の寄与、または領域境界と再び交差できない行セグメントのいずれかを除去します。 各ステップは厳密に左または上/右に移動するため、セルが 2 回処理されることはなく、チェックごとのクエリの総数は線形です。$n$。 二分探索は述語「要素数」なので有効です。$\le x$」は減っていない。$x$、回答範囲を誤ってスキップすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

def count_leq(x):
    i, j = n, 1
    cnt = 0
    while i >= 1 and j <= n:
        print("?", i, j, x)
        sys.stdout.flush()
        res = int(input())
        if res == 1:
            cnt += i
            j += 1
        else:
            i -= 1
    return cnt

lo, hi = 1, n * n
ans = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if count_leq(mid) >= n * n - k + 1:
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print("!", ans)
sys.stdout.flush()
```コア実装は以下を中心に展開します。`count_leq`ルーティンは、裁判官と対話する唯一の部分です。 トラバーサルでは左下の開始点が使用されるため、各クエリは行プレフィックスまたは列のいずれかを決定的に削除します。 蓄積`cnt += i`細胞が$(i, j)$が有効であることが確認されている場合、同じ列内のその上にあるすべてのセルも単調性のもとで有効です。 

二分探索はインデックス空間ではなく値空間で動作するため、行列全体を再構築する必要がなくなります。 off-by-one 境界は、k 番目に大きいランクを k 番目に小さいランクに変換することによって処理されます。$n^2 - k + 1$。

 ## 特殊なケース

 最小限のケース$n=1$単一細胞を持っています。 トラバースはすぐにクエリを実行します$(1,1)$二分探索はその値に収束します。 ポインターの移動によって常に検索スペースが縮小されるため、アルゴリズムは無限ループに入りません。 

すべてのエントリが同一である均一行列では、すべてのクエリが 1 を返します。走査は枯渇するまで右に移動し、すべての列の寄与が正しく累積されます。 すべてのしきい値が同じように動作するため、二分探索はすぐにその 1 つの繰り返し値に崩壊します。 

両方の次元にわたって値が急速に増加する厳密な増加行列では、多くの初期のクエリは 0 を返し、有効な境界が見つかるまで上方への移動を強制します。 比較が失敗した場合でも、行プレフィックスまたは列サフィックス全体が削除され、走査が完全なスキャンに陥るのではなく段階的に線形に保たれます。
