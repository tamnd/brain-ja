 ## 解決策
 ## 問題の理解

 次のような有向グラフが与えられます。$n$ノードと$m$単位長さのエッジ。 私たちも持っています$k$独立した建設チーム。 各チームは独立して、既存のエッジの 1 つを均一にランダムに選択します。$j$、そして追加します$a_i$選択したエッジと同一の追加の平行な有向エッジ。 

すべてのランダムな選択が行われ、すべての新しいエッジが追加された後、ノードからの最短パス距離に関心があります。$1$ノードへ$n$、より具体的には、その最小距離に到達する別の最短パスの数です。 構築はランダムであるため、この量は確率変数になり、タスクはその期待値の法 998244353 を計算することです。 

重要な問題は、ランダム性がパスに直接影響するのではなく、エッジの多重度に影響するため、間接的に最短パスの構造と数が変化することです。 

制約は大きいです:$n, m, k \le 2 \cdot 10^5$。 これにより、ランダムな構築を明示的にシミュレートしたり、シナリオごとに最短パスを再計算しようとするアプローチは即座に除外されます。 最短パスの 1 回の再計算でも、$O(m \log n)$、独立したランダムな選択により指数関数的に多くの構成が存在するため、直接列挙することは不可能です。 

グラフにはサイクルや複数の最短パスが含まれる可能性があり、パス構造がツリー状ではないため、パスに対する単純な動的プログラミングも失敗します。 

複数の建設チームが同じエッジを選択すると、微妙なエッジケースが現れます。 そのエッジは大きな多重度を蓄積できるため、$a_i$まで可能です$10^9$、追加された個々のエッジを列挙することによって寄与を追跡することはできません。 

もう 1 つの明白ではない問題は、最短経路の距離自体がランダムであることです。 素朴なアプローチでは、最初に予想される距離を計算し、次にその距離を条件として予想されるパスの数を計算しようとしますが、これらの量は非線形に結合されます。 

## アプローチ

 ブルートフォースの観点は、ランダム性をシミュレートすることです。 それぞれについて、$k$チーム、私たちは以下から均一にエッジを選択します$m$オプションを選択してから、対応する多重度を追加します。 最終的なマルチグラフを構築した後、ノードから最短パス アルゴリズムを実行します。$1$、ノードへの最短パスの数を数えます$n$、すべての結果の平均。 

これは期待の定義と直接一致するため、概念的に機能します。 ただし、考えられる結果の数は次のとおりであるため、すぐに失敗します。$m^k$、これは大きすぎます。 平$k=20$もう無理でしょう。 

次に自然なアイデアは、各建設チームの貢献に対して線形的に期待値を計算することです。 問題は、最短パスがグラフのグローバル構造に依存するため、単純な加算方法では寄与が独立していないことです。 

重要な構造的観察は、加重 DAG における最短パスのカウントがノードからの距離によって引き起こされることです。$1$距離が固定されると、動的プログラミングによって表現できます。 ランダム性はエッジの多重度にのみ影響するため、最短パス DAG の遷移の重みにのみ影響します。 

完全な構成について推論する代わりに、視点を変えます。各建設チームが独立してエッジを選択するため、各エッジは$e_j$独立した寄与の合計に等しいランダムな重み増加を受け取ります。 固定エッジに対する 1 つのチームの期待される貢献は次のとおりです。$a_i / m$。 ただし、最短パス構造は、エッジが最短パス DAG の一部になるかどうかに依存するため、最短パス DP 構造を通じて期待値を伝播する必要があります。 

これにより、2 層の分解が生じます。 まず、ベース グラフを処理し、ランダム性を無視して最短距離を計算します。 次に、追加されたエッジを、最短パス層上の線形化 DP のパス多重度に影響を与える期待重み摂動として解釈します。 重要な単純化は、ランダム性は多重度にのみ影響し、最短パスは依然として最短距離の階層化を尊重するエッジから来るという意味での到達可能性の構造には影響しないということです。 

したがって、問題は、予想されるエッジの多重度を計算し、その後、誘導された重み付けされたグラフに対して最短パス カウント DP を実行することに帰着します。ここで、元の各エッジは重み 1 を持ち、各エッジは追加の予想される並列寄与を取得します。 

各エッジについて計算します$j$追加される平行エッジの予想数:$$E[\text{add to } j] = \sum_{i=1}^k \frac{a_i}{m} = \frac{S}{m}$$どこ$S = \sum a_i$。 各チームが均一かつ独立して選択するため、この期待はすべてのエッジで同一です。 

したがって、すべてのエッジは事実上、期待される多重度スケーリングを備えた重み付きエッジになります。これは、グラフが、各エッジが期待に比例した重みを与えるマルチグラフになることを意味します。 

次に、これらの有効な重みを使用してノード 1 からの最短距離を計算し、最短パス DAG 上の標準 DP を使用して最短パスをカウントします。 

これにより、ランダムな構造が期待線形性の下で決定論的な重み付きグラフに崩壊します。

 ## アルゴリズムのチュートリアル

 まずランダム性を期待されるエッジ多重度に変換し、次に決定論的な最短パスのカウント問題を解きます。 

1. 合計を計算する$S = \sum_{i=1}^k a_i$。 これは、ランダムな選択によりすべてのエッジに分散された合計「エッジ質量」を表します。 
2. 元の各エッジに寄与すると予想される追加多重度を次のように計算します。$S / m$。 各チームが均一に選択するため、すべてのエッジが同じ予想される負荷を受けます。 
3. 元の各エッジが重み付けされた有向グラフを構築します。$u \to v$には、接続に対する予想される寄与を反映する重みが割り当てられます。 概念的には、各エッジにはベースライン寄与 1 と予想される追加の平行エッジがあり、これによりパスのカウントが調整されます。 
4. ノード 1 からダイクストラを実行して最短距離を計算します。 これが必要なのは、期待される多重度を追加しても到達可能性は変わらないが、最短パスをカウントする際の効果的な遷移構造に影響を与えるためです。 
5. 最短パス DAG を構築します: 各エッジに対して$u \to v$、それが満たされる場合$dist[u] + 1 = dist[v]$、これは最短パス構造の一部です。 
6. 距離が増加する順にノード上で DP を実行し、1 から各ノードまでの最短パスの数を数えます。 各遷移は、エッジの実効多重度に比例した寄与を追加します。 
7. ノードへの最短パスの数を出力$n$、モジュロ 998244353。 

重要なステップは、多重度が最短パス DAG 内のエッジを横断する方法の数に影響するため、DP 遷移ではそれに応じて各エッジに重み付けする必要があることです。 

### なぜ効果があるのか

 このアルゴリズムは、エッジの多重度に適用される期待値の線形性に依存します。 各構築チームは独立して、ランダムな数の平行エッジを正確に 1 つの元のエッジに提供し、期待値はエッジ全体に均一に分布します。 DAG での最短パスのカウントはエッジ多重度に対して線形であるため、DP 結果の期待値を変更せずに、ランダムなマルチグラフをその期待される多重度表現に置き換えることができます。 最短パス構造は基本距離のみによって決定されますが、多重度は有効な遷移の数のみをスケールし、これは線形累積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

from collections import defaultdict
import heapq

def solve():
    n, m, k = map(int, input().split())
    
    edges = []
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))
        g[u].append(v)
    
    a = list(map(int, input().split()))
    
    S = sum(a) % MOD
    
    # expected contribution per edge
    inv_m = pow(m, MOD - 2, MOD)
    add = S * inv_m % MOD
    
    # shortest path distances (unweighted graph)
    dist = [10**18] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]
    
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v in g[u]:
            nd = d + 1
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    # DP on shortest path DAG
    dp = [0] * (n + 1)
    dp[1] = 1
    
    order = sorted(range(1, n + 1), key=lambda x: dist[x])
    
    for u in order:
        for v in g[u]:
            if dist[u] + 1 == dist[v]:
                dp[v] = (dp[v] + dp[u] * (1 + add)) % MOD
    
    return dp[n] % MOD

if __name__ == "__main__":
    print(solve())
```実装ではまずグラフを読み取り、すべてのグラフの合計を計算します。$a_i$、一様ランダム選択により合計のみが重要となるためです。 次に、モジュラー逆関数を計算します。$m$この合計期待値をエッジ全体に分散します。 

ダイクストラは、単位重量グラフの最短距離を計算するために標準形式で使用されます。 元のエッジはすべて長さ 1 であるため、これは不可欠であり、BFS も機能しますが、一般性を考慮してダイクストラは保持されます。 

距離がわかった後、最短パス DAG にわたる DP の正確性を確保するために、ノードは距離の増加順に処理されます。 有効なエッジ遷移ごとに、ウェイの数が次のように乗算されます。$1 + \text{expected added multiplicity}$これは、元のエッジのそれぞれに予期される追加の並列コピーが効果的に存在するという事実を反映しています。

 ## 特殊なケース

 主なエッジ ケースは、複数の建設チームが同じエッジを繰り返し選択する場合です。 その場合、すべてのランダム性が単一のエッジに崩壊し、多重度に大きなスパイクが発生します。 アルゴリズムはすべてを集約するため、これを正しく処理します。$a_i$単一の合計に$S$したがって、繰り返された選択を個別に追跡する必要はありません。 

別のエッジ ケースは、グラフに多数の並列最短パスがある場合に発生します。 DP は距離順に実行されるため、同じレベルのすべてのノードはその先行ノードの後に​​処理され、異なる最短ルートからの寄与が正しく結合されることが保証されます。 

自己ループと冗長エッジは、距離を決して短縮しないため、最短経路の距離に影響を与えず、dist 緩和条件では自然に無視されます。$dist[u] + 1 = dist[v]$。
