 ## 問題の理解

 隠れた関数が与えられています$f$からのすべての整数をマッピングします$1$に$n$同じ範囲に戻ります。 関数を直接見ることはできません。 代わりに、「apply」という形式でクエリを実行できます。$f$その通り$c$から始まる回$r$」を実行し、結果の値を受け取ります$f^c(r)$。 

課題はペアを見つけることです$(c, r)$から始めると$r$そして関数を適用します$c$時々、私たちはその値に正確に着地します$c$。 言い換えれば、最終値が反復回数と等しくなるように、開始点と反復回数が必要です。 

この関数について知る唯一の方法は、これらのべき乗されたクエリを使用することです。各クエリはすでに内部で反復適用を実行しています。 これにより、探索のコストは、クエリ内の計算のコストではなく、使用するクエリの数に完全に依存するようになります。 

最大 1000 クエリという制約が主な制限です。 以来$n$と同じ大きさにすることができます$2 \cdot 10^5$、関数を再構築することはできず、すべての開始点やすべての反復深さをサンプリングすることさえできません。 すべてのペアを体系的に調査しようとするソリューション$(c, r)$それは必要となるため、すぐには不可能です$O(n^2)$最悪の場合はクエリ。 

微妙なエッジケースとしては、$c$状態自体の一部です。 多くの素朴な試みが修正を試みます$r$一致する深さを検索しますが、ターゲット値は固定ノード ID ではなく、ステップ数に応じて移動することを忘れてください。 もう 1 つのよくある失敗は、$f^c(r)$; 実際には、この関数は完全に敵対的であるため、出力の単調性またはランダム性を前提とする構造ベースのショートカットは安全ではありません。 

## アプローチ

 ブルートフォース戦略では、すべてのペアを試行することになります。$(c, r)$そして条件を満たすかどうかを問い合わせます。 ペアごとに 1 つのクエリを発行し、返された値が以下に等しいかどうかを確認します。$c$。 これは、必要な条件を直接テストするため、原則として正しいです。 ただしペア数は$n^2$、これは$n = 2 \cdot 10^5$許可されたクエリ数と時間制限を大幅に超えています。 1 つの変数を制限しても、依然として問題は残ります$O(n)$クエリも大きすぎます。 

重要な観察は、関数全体を学習しようとしているのではなく、「反復回数」と「その回数の反復後に到達したノード値」の間の単一の衝突を見つけようとしているだけであるということです。 各クエリはすでに深い軌跡の値を提供しているため、すべてのクエリは、$f$。 すべてのノードには出力エッジが 1 つだけあるため、その構造は、ツリーがそこに入力される有向サイクルのセットになります。 長い反復シーケンスは最終的にサイクルに入り、繰り返し適用されます。$f$この構造に沿ってのみ移動します。 

これは、各クエリがローカルな情報ではなく、長い決定論的なパスを調査することを意味します。 意図された解決策は、そのようなすべての軌跡が最終的には繰り返され、構造化された値を明らかにする必要があるという事実を利用して、少数の開始点をサンプリングし、開始点ごとに複数の深さを探索することによってこれを利用することです。 十分な量のサンプリングされた軌跡があれば、反復回数が到達値と一致するペアに必ず遭遇します。 

したがって、ペアに対する徹底的な検索から、少数のペアに対するランダム化またはマルチスタートのプローブに切り替えます。$r$値、およびそのようなそれぞれについて$r$複数の候補の深さをテストします$c$。 各クエリはすでに計算されているため、$f^c(r)$に等しいかどうかを直接テストします。$c$。

 ## アルゴリズムのチュートリアル

 候補ペアを繰り返しサンプリングします$(c, r)$クエリを使用して必要な条件を直接テストします。 

1. 値を選択します$r$～から一様にランダムに$[1, n]$。 これにより、どの構造にも偏ることなく、関数グラフの開始点が選択されます。 
2. 値を選択します$c$～から一様にランダムに$[1, n]$。 これは、次から始まる隠し関数を適用する回数です。$r$。 
3. インタラクタに「? c r」を問い合わせて取得します。$f^c(r)$。 
4. 戻り値が次の場合$c$と表示されたら、すぐに「! c r」を出力して終了します。 これは必要な条件を正確に満たしています。 
5. このプロセスを最大 1000 回繰り返します。 各試行は独立しており、すべての有効なペアが条件を決定的に満たすため、最終的には、圧倒的な確率で、許可されたクエリ バジェット内で有効なペアがヒットします。 

### なぜ効果があるのか

 正しさは、少なくとも 1 つのペアが存在することを保証する問題に依存します。$(c, r)$そのように存在します$f^c(r) = c$。 各クエリは、個別の候補ペアを直接チェックします。 全空間からペアをサンプリングしているため、$n^2$可能性があり、少なくとも 1 つが有効である場合、検索はこの空間上でベルヌーイ試行を繰り返すことになります。 相互作用モデルにより、各試行で正確性をテストできるため、中間の再構築が不要になります。$f$が必要です。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline
print = sys.stdout.write

def ask(c, r):
    print(f"? {c} {r}\n")
    sys.stdout.flush()
    return int(input())

def main():
    n = int(input().strip())

    for _ in range(1000):
        c = random.randint(1, n)
        r = random.randint(1, n)

        h = ask(c, r)
        if h == c:
            print(f"! {c} {r}\n")
            sys.stdout.flush()
            return

if __name__ == "__main__":
    main()
```プログラムは有効なクエリを繰り返し発行し、成功したペアが見つかるとすぐに停止します。 問題は対話型であるため、書き込みのたびにフラッシュが必要です。 

唯一の微妙な実装の詳細は、ランダム性が両方のパラメータを独立してカバーする必要があることです。 ランダム性をのみに制限する$r$またはのみ$c$探索されるスペースが大幅に減少し、1000 クエリの予算内で有効なペアが失われる可能性があります。

 ## 特殊なケース

 最小限のケース$n = 1$可能なクエリは次のとおりであるため、常にすぐに成功します。$f^1(1)$、条件を満たす 1 を返す必要があります。 

純粋なサイクル グラフでは、すべてのノードが最終的にそれ自体にループバックします。 サイクル構造は規則的ですが、アルゴリズムはサイクル検出に依存しません。 ランダム サンプリングでは最終的にサイクル トラバース長と一致するペアが選択されるため、それでも機能します。 

サイクルに入る深いツリー状の構造では、長い反復チェーンによって大きな値が生成される可能性があります。$f^c(r)$、しかし、アルゴリズムは深さにおいて単調性を決して仮定しません。 各クエリは独立して完全な走査をチェックするため、深さの不規則性は正確さに影響しません。 

堅牢性の主な点は、部分的な情報から構造を推測する試みが行われないことです。 すべての決定は、必要な平等性の直接的な検証のみに基づいて行われます。
