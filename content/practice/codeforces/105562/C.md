 ## 解決策
 ## 問題の理解

 街区の無限グリッド上に 5 つの特別な交差点が与えられています。 各ブロックは厳密に水平または垂直に走る道路によって接続されており、行または列に沿った隣接する交差点のペアはすべて、同じ長さの 1 つの道路セグメントに対応します。 個々の道路セグメントを「修復」することができ、修復されたセグメントは使用可能になります。 

目標は、指定された 5 つの重要な場所のすべてのペアについて、修復された道路セグメントのみを使用する最短のマンハッタン パスがそれらの間に存在することを保証することです。 ここでの最短パスとは、グリッドの意味で不必要な迂回を一切行わないパスを意味し、グリッド線に沿って x と y に単調に移動するだけです。 

この条件がすべてのペアに当てはまるように、修復する単位道路セグメントの最小数を選択する必要があります。 

重要な問題は、任意の接続を構築しているわけではないことです。 すべてのペア間に最短パス接続を強制しています。これは非常に強力な幾何学的構造を意味します。2 点間のパスは軸に合わせた境界ボックス内に留まり、なおかつ最短である必要があります。 

座標は最大 1000 であるため、すべてのグリッド エッジを直接幾何学的または組み合わせて探索することは原理的には実現可能ですが、グリッドは概念的には無限であるため、すべてのエッジをグローバルに列挙することは避けなければなりません。 問題のサイズは特別なポイントの点で非常に小さく、ちょうど 5 つです。これは、一般的なグラフ検索ではなく、構造主導の解決策を強く示唆しています。 

微妙なエッジ ケースは、5 つの点すべてが 1 つの水平線または垂直線上にある場合です。 その場合、最適な構造は単一のセグメントに崩壊し、修復されたセグメントを共有するのではなく各ペアを独立して扱うため、単純なペアごとの思考は過大評価する傾向があります。 

別の失敗例は、点が長方形のような構成を形成する場合に発生します。 独立したマンハッタン パスを介して各ペアを接続する単純なアプローチでは、多くの共有エッジが二重にカウントされ、大幅な過大評価が生成されます。 

したがって、正しいソリューションでは、すべてのペアの最短パスを同時にサポートする共有構造を特定する必要があります。 

## アプローチ

 この問題を考える強引な方法は、5 つの点すべてを含む境界ボックス内のすべてのグリッド交点をモデル化し、エッジのすべてのサブセットを考慮して、必要な最短パスがすべて存在するかどうかを確認することです。 1000 × 1000 のグリッドでも約 100 万の頂点と 200 万のエッジが含まれており、そのサイズではエッジのサブセットを列挙することは指数関数的であるため、これは直ちに実行不可能です。 

5 点の境界ボックス内のエッジのみに制限したとしても、候補エッジの数は依然として 10^6 のオーダーであり、サブセットを列挙することは不可能です。 

2 番目の素朴なアイデアは、点の各ペアを考慮し、それらの間の最短のマンハッタン パスを 1 つ選択し、そのようなすべてのパスの結合を取るというものです。 これにより、パスの固定選択の正確性が保証されますが、パスの選択が独立していないため失敗します。 同じペア間の 2 つの異なる最短パスは、他のペアのパスと構造を共有する可能性があり、ペアごとに貪欲に選択しても重複は最小限に抑えられません。 

重要な観察は、最適解はパスの任意の結合ではなく、指定された点の間、または慎重に選択されたシュタイナーのような交差点に端点がある軸に沿ったセグメントの結合を形成するということです。 点が 5 つしかないため、最適解の構造は十分に制約されており、すべての最短パスの結合を小さな組み合わせ構造として表すことができます。

重要な再定式化は、水平方向と垂直方向の適用範囲の観点から考えることです。 x の垂直セグメントが使用される場合、x 間隔がその線を通過する必要がある複数の点を提供できます。 水平セグメントについても同様です。 問題は、すべてのペア間で最短のマンハッタン接続を可能にする一連のグリッド ライン (選択した x または y 座標に沿ったセグメント) を選択することになります。 

2 点間のすべての最短パスは、それらによって定義される長方形の内側に完全に存在するため、関連するエッジは、そのようなすべての長方形の和集合の内側にあるエッジだけになります。 これにより、ジオメトリが 5 つの x 座標と 5 つの y 座標によって引き起こされる小さな配置に縮小されます。 

5 つの点の場合、考えられる垂直の「イベント ライン」は 5 つだけ、水平の「イベント ライン」は 5 つだけです。 入力点の座標からセグメントをシフトしてもカバレッジは向上せず、コストが増加または維持されるだけであるため、最適な解決策はすべてこれらの座標上にあると想定できます。 

これにより、問題は最大 25 個の交差ノード候補からなる小さなグリッドにわたる有限の組み合わせ最適化に帰着します。 

次に、連続する x 座標と y 座標の間の各セルを潜在的なエッジの位置として解釈します。 各候補解は、点の各ペアが単調なパスを介してルーティングできるように、選択された長方形を接続する水平および垂直の単位セグメントのサブセットを選択することに対応します。 

この時点で、この問題は、5 つの端子すべてが最短パス制約の下で接続されるように、非常に小さな暗黙的なグリッド グラフの最小コストのサブグラフを選択することと同等になります。 最短経路制約は単調性を強制するため、実現可能な構造は共有の「クロス」構造を通じて x 座標と y 座標間の移動を独立して許可する必要があります。 

最後の単純化は、最適解は常に 5 つの点上で接続された直線シュタイナー ツリーを形成する候補グリッド点のセットを選択することに対応しますが、パスが最短でなければならないという追加の制約があります。 この特殊なケースでは、最短パス制約により、解は基本的に 5 点セット上のマンハッタン シュタイナー ツリーのように動作することになります。エッジは点の投影に沿ってのみ存在します。 

したがって、問題を少数の中央値ベースの構成候補の評価に集約します。これは、指定された x 座標から x を選択し、指定された y 座標から y を選択することによって形成される中心の「ハブ」交差点のすべての選択肢を列挙し、そのハブ構造を介してすべての点を接続するために必要なセグメントの最小合計を計算することによって解決できます。 

これにより、定式化に応じて O(5^2) または O(5^3) スタイルの評価が得られますが、これは自明です。

 ## アルゴリズムのチュートリアル

 この問題を、5 つの点の x 座標と y 座標の小さなセットに対する推論に圧縮します。 点を P0 ～ P4 とします。

1. 5 つの点のすべての x 座標と y 座標を収集します。 これらは、最適なソリューションが構造を変更できるすべての関連する垂直および水平「イベント ライン」を定義します。 最適な解決策は、これらの座標のみを使用すると想定できます。 
2. 任意の x 座標と任意の y 座標を組み合わせて形成されるハブ位置の候補をすべて試します。 これにより、最大 25 個のグリッド交差点の候補が得られます。 直感的には、最適な共有構造では、接続は端末によって定義される主要な垂直線と水平線の交差によって仲介されると考えられます。 
3. 候補ハブごとに、マンハッタン パスを使用してすべてのポイントをそのハブに接続するコストを計算しますが、必要な水平セグメントと垂直セグメントの結合のみが考慮されます。 ポイントからハブへの各接続は、その x 方向および y 方向の投影に沿ったセグメントに寄与します。 
4. 和集合を計算する際、共有セグメントが二重にカウントされないように注意してください。 これは、各水平線および垂直線に沿ったどの単位セグメントが少なくとも 1 回使用されたかを追跡することによって処理されます。 
5. ハブのコストは、この結合で使用される固有のユニット エッジの数です。 これは、並べ替えられた x 座標と y 座標によって引き起こされる離散グリッド上のセグメントをマークすることによって計算されます。 
6. 答えは、すべての候補ハブの最小コストです。 

これが機能する理由は、マンハッタン幾何学における最短経路の構造に関係しています。 2 点間の最短経路は、x と y の独立した移動によって完全に決定されます。 すべてのペアを同時に満たすには、ソリューションは、複数のペア間での再利用を可能にする X 座標と Y 座標に沿った共有コリドーを提供する必要があります。 セグメントをこれらの線から遠ざけると、最短パスの実現可能性を維持しながら再利用を向上させることはできないため、最適な構成はすべて、入力に整列した線の交差点ですべての分岐が発生する構成に変換できます。 これにより、単一の交差点がすべてのルートの組み合わせの合流点として機能する、小さな有限の検索空間が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def segments_between(sorted_coords):
    # returns number of unit segments covered when connecting all consecutive coords fully
    return sorted_coords[-1] - sorted_coords[0]

def solve():
    pts = [tuple(map(int, input().split())) for _ in range(5)]
    
    xs = sorted(set(p[0] for p in pts))
    ys = sorted(set(p[1] for p in pts))

    ans = float('inf')

    for cx in xs:
        for cy in ys:
            used_h = set()
            used_v = set()

            for x, y in pts:
                # horizontal segment from x to cx at row y
                if x != cx:
                    a, b = sorted((x, cx))
                    for xx in range(a, b):
                        used_h.add((y, xx))
                # vertical segment from y to cy at column cx
                if y != cy:
                    a, b = sorted((y, cy))
                    for yy in range(a, b):
                        used_v.add((xx := cx, yy))

            ans = min(ans, len(used_h) + len(used_v))

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、入力点から x と y を選択することによって形成されたすべての交差候補を試行します。 このような中心ごとに、すべての点からその中心までのマンハッタン パスの結合を構築します。 各パスは水平および垂直の単位セグメントに分解され、共有使用が 1 回カウントされるように、これらのセグメントをセットに保存します。 

重要な実装の詳細は、整数座標間の単位ステップとしてのエッジの表現です。 水平セグメントは次のように保存されます。`(y, x)`間のセグメントを表すペア`(x, y)`そして`(x+1, y)`。 垂直セグメントは次のように保存されます。`(cx, y)`間のエッジを表すペア`(cx, y)`そして`(cx, y+1)`。 

必要なのはユニオン内の一意のセグメントのカーディナリティーだけであるため、セットを使用するだけで十分です。

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が同じ x 座標を共有する場合です。 その場合、正しい解は、最小値 y と最大値 y を接続する単一の垂直セグメントになります。 すべての候補ハブが同じ x 座標上にあるため、アルゴリズムはこれを自然に処理します。そのため、すべてのパスは重複することなく垂直結合に折りたたまれます。 

別のエッジ ケースは、ポイントが遠く離れた 2 つの密集したクラスターを形成する場合に発生します。 単純なペアワイズ構築では、クラスタ間のすべてのポイントを接続しようとしますが、ハブベースの構築では、クラスタ間にブリッジング コリドーが 1 つだけ作成され、すべてのクラスタ内パスでローカル セグメントが再利用されます。 

最後の微妙なケースは、最適なハブが視覚的に「中心」ではなく、極端な座標の 1 つに位置合わせされている場合です。 すべての入力 x および y 値の列挙により、このケースが明示的にテストされることが保証されるため、アルゴリズムは対称性に関する幾何学的直観に依存しません。
