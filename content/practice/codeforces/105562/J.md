 ## 解決策
 ## 問題の理解

 各クレーンは平面上の固定点に設置され、垂直なタワー高さを持っています。 各塔の最上部から、回転する水平梁を取り付けます。 ビームの長さは正の整数である必要があり、タワーの高さを超えることはできません。 

梁をある方向と長さに設定すると、その塔の高さで水平面内の直線セグメントになります。 ビームがそのタワーの高さ以下にあるときに、このセグメントが別のタワーの地上位置を通過すると、ビームが他のクレーンの垂直構造と物理的に交差するため、衝突が発生します。 ビームがタワーの境界を正確に通過する場合でも、接触は許可されており、衝突とはみなされません。 

タスクは、すべての可能な回転にわたって、少なくとも 1 つのビームが到達できる合計領域が最大化されるように、各クレーンに長さを割り当てることです。 各クレーンは、選択した長さに等しい半径のディスクをカバーします (ただし、高さの制限までに限ります)。問題は、禁止されたタワーとの交差を許可しない最大の安全な半径を各点で選択することになります。 

重要な幾何学的制限は、クレーンが別のクレーンと競合するのは、そのビームが他のクレーンの位置に到達でき、かつ他のクレーンの高さがビームと交差するのに十分な場合だけであるということです。 すべての高さは異なるため、クレーンの各ペアには明確な優勢関係があります。つまり、クレーン i については、h_i 以上の高さを持つクレーンのみがそれをブロックできます。 ビームがその上を通過するため、より短いタワーは無視しても問題ありません。 

考えられるすべての半径を個別に試行する単純なアプローチは失敗します。特定の方向にある 1 つの遠く離れた背の高いクレーンが許容半径を大幅に制限してしまう可能性があり、この制限は他のクレーンの高さに応じてクレーンごとに異なるためです。 

複数の高いクレーンが低いクレーンをまばらに取り囲んでいる場合、微妙な失敗例が発生します。 たとえば、近くのすべてのポイントが小さい場合でも、遠くにある 1 台の背の高いクレーンが依然として制限要因となる可能性があります。 グリッド内のローカル近傍のみを考慮する戦略や、高さの順序を考慮せずに距離で並べ替える戦略は、許容される半径を過大評価します。 

制約は十分小さいので、$O(n^2)$クレーンごとの幾何学的比較は実現可能ですが、ペアごとの角度スイープや半径ごとの再計算を伴うものは不必要に複雑になるほど大規模になります。 

## アプローチ

 ブルートフォース解釈は各クレーンから独立して開始され、禁止された塔に衝突する前にそのビームがどこまで伸びることができるかを尋ねます。 固定クレーンの場合、クレーンが短いため 1 つおきのクレーンは問題にならないか、ビームが固定クレーンに向かって正確に回転すると衝突の可能性が生じます。 したがって、安全な最大長は、ユークリッド距離で最も近いブロッキング クレーンによって制限されます。 

これにより、単純な計算が行われます。各クレーン i について、少なくとも同じ高さの他のすべてのクレーン j を調べます。 ビームが j の位置に到達すると衝突が発生するため、使用可能な長さは i と j の間の距離よりも厳密に短くする必要があります。 このようなすべての制約の最小値を取ると、i の答えが得られます。 

これはすでに次のことを示唆しています$O(n^2)$しかし、重要な構造上の改善点は、ビームの回転や角度ジオメトリをシミュレーションする必要がまったくないことを認識したことです。 各クレーンの実行可能領域は、ユークリッド距離で最も近い同等以上のタワーによって半径が切り取られた単純な円盤です。 

残りの問題は計算の問題、つまりこれらの制約を効率的に評価する方法です。 以来$n \le 500$、直接ペアごとの比較で十分ですが、クレーンを高さの降順に処理することで計算を整理することもできます。 クレーンを処理する場合、すでに処理されたクレーンはすべて厳密に高くなるため、まさに潜在的なブロッカーのセットを形成します。

 ## アルゴリズムのチュートリアル

 クレーンを最も高いものから最も低いものへと処理するため、クレーンを評価するときに、以前に挿入されたすべてのクレーンの高さが厳密に保証されます。 

### 1. クレーンを高さの降順に並べ替えます

 クレーンに到達したときに、以前に見たすべてのクレーンが有効な潜在的なブロッカーとなるように、クレーンの順序を変更します。 

これにより、高さの条件を繰り返しチェックすることが回避され、フィルタリングが反復順序で構造化されます。 

### 2. 処理済みのクレーンのセットを維持する

 私たちは、現在のクレーンよりも厳密に高いクレーンのリストを保管しています。 これらは、現在のクレーンのビーム長を制限できる唯一のクレーンです。 

### 3. クレーンごとに、最も近い遮断距離を計算します。 

位置 (xi, yi) にある現在のクレーン i について、セット内に既に存在するすべてのクレーン j までの二乗ユークリッド距離を計算します。$$d_{ij}^2 = (x_i - x_j)^2 + (y_i - y_j)^2$$クレーン j が距離 d にある場合、ビームの長さ L ≥ d を選択するとビームは j に到達できますが、j が十分に高い場合は無効です。 したがって、j からの安全限界は、厳密に d より小さい最大の整数です。 

平方根を直接計算する代わりに、これを整数演算に変換します。つまり、次を満たす最大の有効な整数 L$L^2 < d_{ij}^2$は：$$L_{ij} = \lfloor \sqrt{d_{ij}^2 - 1} \rfloor$$すべての背の高いクレーンについてこの値の最小値を採用します。 

### 4. タワーの高さ制限を適用する

 たとえクレーンが幾何学的にそれを妨げなかったとしても、ビームの長さはタワーの高さを超えることはできません。 したがって、最終的な答えは次のようになります。$$L_i = \min(h_i, \text{minimum blocking limit})$$より背の高いクレーンが存在しない場合、答えは単純です。$h_i$。 

### なぜ効果があるのか

 任意のクレーン i について、有効なビーム方向はすべて平面内の点に対応します。 衝突は、その点がビームの高さと交差するのに十分なタワーの高さを持つ別のクレーンの位置と正確に一致したときに発生します。 したがって、そのようなクレーンはそれぞれ独立して、許容半径に厳密な上限を課します。 これらの境界のうち最も制限的なものは、ユークリッド距離で最も近い有効なブロッカーによって決定され、衝突はセグメントに沿って何が起こるかではなく、端点が禁止された座標に到達するかどうかにのみ依存するため、中間ジオメトリはその事実を変更しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def isqrt(x):
    # floor(sqrt(x)) for x >= 0
    if x <= 0:
        return 0
    r = int(x ** 0.5)
    while (r + 1) * (r + 1) <= x:
        r += 1
    while r * r > x:
        r -= 1
    return r

n = int(input())
cranes = []
for _ in range(n):
    x, y, h = map(int, input().split())
    cranes.append((h, x, y))

cranes.sort(reverse=True)  # sort by height descending

processed = []
ans = [0] * n

for i in range(n):
    hi, xi, yi = cranes[i]

    best = hi  # cannot exceed height

    for hj, xj, yj in processed:
        dx = xi - xj
        dy = yi - yj
        d2 = dx * dx + dy * dy

        # largest L such that L^2 < d2
        limit = isqrt(d2 - 1)
        if limit < best:
            best = limit

    processed.append((hi, xi, yi))
    ans[i] = best

print(*ans)
```この実装はクレーンを高さの降順に処理することに依存しているため、リストは次のようになります。`processed`現在のクレーンを制限できるクレーンが常に正確に含まれます。 各ペアごとの距離は 1 回評価され、答えを初期化することで高さの制約が直ちに適用されます。`hi`。 

一般的な実装の落とし穴は、距離制約における厳密な不等式を処理することです。 使用する`floor(sqrt(d2))`ビームが別のクレーンに正確に到達することを誤って許可してしまうため、これは許可されていません。 引き算`d2 - 1`浮動小数点比較を行わずに厳密性を正しく適用します。

 ### 例 1

 小規模な構成を考えてみましょう。 

入力クレーン:

 | クレーン | × | y | h |

 | あ | 0 | 0 | 5 |
 | B | 3 | 0 | 4 |
 | C | 0 | 4 | 2 |

 高さでソートした後、A、次に B、次に C を処理します。 

| ステップ | 処理済みセット | 現在 | これまでで最高 |
 | --- | --- | --- | --- |
 | あ | ∅ | あ | 5 |
 | B | あ | B | min(4, dist(A,B)-1 = 2) = 2 |
 | C | Ａ、Ｂ | C | min(2, dist(C,A)-1 = 3, dist(C,B)-1 = 4) = 2 |

 この結果は、C が A および B に近いにもかかわらず、C 自体の高さが制限要因であることを示しています。

 ## 特殊なケース

 単一クレーンのケースは、障害物が存在しない場合、アルゴリズムが高さ制限を正しくデフォルト設定することを示しています。 処理されたセットは空のままであるため、初期値は変更されずに残ります。 

1 台の非常に近い背の高いクレーンを備えた緊密な 2 台のクレーン構成では、厳密な不等号の処理がテストされます。 距離が 1 の場合、正の長さがあるとすぐに高いタワーと交差するため、下のクレーンの有効な半径は 0 でなければなりません。 

高さが減少する単調な線により、並べ替えロジックの正確さが保証されます。 各クレーンは、それよりも上位のすべてのクレーンをそれより前に認識し、各ステップにより厳格な境界が蓄積され、処理順序だけですべての制約を強制するのに十分であることが確認されます。
