 ## 解決策
 ## 問題の理解

 (n) 個のワードのそれぞれに、空ではない個別のバイナリ コードワードを割り当てる必要があります。 コードワードはバイナリ トライのリーフを形成するため、コードにはプレフィックスを含めないようにする必要があります。 追加の制限が 1 つあります。コードワードには次の内容を含めることはできません。`00`。 コストは、空のプレフィックスを含むすべてのトライ ノードに請求されます。 正確に (k) 個のコードワードがノードを通過する場合、そのノードのコストは

 [
 f(k)=\sum_{j=1}^{k}\left\lfloor 1+\log_2 j\right\rfloor。 
】

 タスクは、総コストが最小になるようにトライの形状を選択することです。 

入力には最大 (50,000) 個の (n) の独立した値が含まれており、単一の (n) は (10^{15}) ほどの大きさになる可能性があります。 これにより、トライの構築が即座に除外され、(O(n)) 動的プログラムであっても大きすぎます。 二次 DP は完全に不可能ですが、(O(n\log n)) でも (10^{15}) に対してあまりにも多くの演算が必要になります。 この解決策は、最適な DP 関数の勾配変化の数が非常に少ないという事実を利用する必要があります。 これは、問題に対する受け入れられている解決策で使用される中心的な観察です。 

よくある間違いを明らかにする小さなケースが 2 つあります。 (n=2) の場合、答えは (5) です。 常に左のサブツリーに余分なコストを追加する不注意な反復では (6) が得られます。これは、左のサブツリーに葉が 1 つしか含まれていない場合、コードワードがその直後に終了する可能性があるためです。`0`。 余分な`1`の後に必要な`0`サブツリーに少なくとも 2 つの葉がある場合にのみ必要です。 

(n=4) の場合、答えは (20) です。 1 つの最適な形状がコードワードに対応`0`、`10`、`110`、 そして`111`。 ルートには 4 つの子孫があり、`0`枝には葉が 1 枚含まれていますが、`1`枝には3枚の葉が含まれています。 2 つのルートの子を対称的に扱うと、サブツリーが`0`すぐに分岐することはできません。分岐すると、`00`角。 

(n=10) の場合、答えは (98) です。 最適な分割のバランスが明白に異なるため、これは再発の境界ケースとしても役立ちます。 最適な分割は、単に同じサイズの 2 つのサブツリーを選択することによってではなく、凸コスト関数によって制御されます。 公式サンプルでは値 (98) が確認されています。 

## アプローチ

 自然な総当たりアプローチは、(D(n)) を (n) 個のリーフを含む有効なトライの最小コストとして定義することです。 ルートの下に (n) 個の葉があると、ルート自体のコストは (f(n)) になります。 左側のサブツリーに (k) 個の葉が含まれ、右側のサブツリーに (n-k) 個の葉が含まれている場合、右側のサブツリーは正常に構築できます。 左側のサブツリーには以下を経由して到達します。`0`したがって、複数の葉が含まれる場合、その次のエッジは次のとおりである必要があります。`1`分岐する前に。 その追加のプレフィックスが (f(k)) に寄与します。 

特殊なケース (k=1) では、左の子自体がリーフになる可能性があるため、そのような追加のノードは必要ありません。 したがって、

 [
 D(1)=f(1)=1
 】

 そして (n>1) の場合、

 [
 D(n)=f(n)+
 \分\左(
 D(n-1)+1,,
 \min_{2\le k<n}
 {D(k)+D(n-k)+f(k)}
 \右）。 
】

 同じ漸化式は通常、(k=1) 項を個別に処理して、すべて (k) にわたる最小値として記述されます。 

(D(1),D(2),\ldots,D(n)) を直接計算すると、各状態は (O(n)) 個の分割を試み、合計作業量は (O(n^2)) になります。 (n=10^{15}) の場合、これはおよそ (10^{30}) 回の分割評価となるため、このアプローチはリモートでは実行できません。 

次の観察は、(f) が離散凸関数であるということです。 (k-1) から (k) までの増分は、まさに (k) のビット長であり、減少することはありません。 最適な DP 関数 (D) も離散凸関数です。 したがって、固定 (n) の場合、式は次のようになります。 

[
 D(k)+f(k)+D(n-k)
 】

 は (k) の関数として凸です。 したがって、その最小値は、考えられるすべての分割をスキャンするのではなく、整数 3 分検索で見つけることができます。 これにより、1 つの新しい (D(n)) の計算がおよそ (O(\log n)) 回の評価に減ります。 凸定式化と三分探索は、この問題に対する標準的な最初の還元です。 

(10^{15}) までのすべての値を計算することは依然として不可能であるため、これでも実際の制約は解決されません。 最後の観察はさらに珍しいものです。(D(n)) は巨大な領域にわたって成長しますが、その離散的な傾きはほんのわずかしか変化しません。 (10^{15}) までは、勾配の変化は約 (1800) 回のみです。 ある公開された実装では、そのようなブレークポイントが 1833 個報告されていますが、別の解決策では、同じ現象がわずか約 1840 個の異なる傾斜領域として説明されています。 

したがって、(n) ごとに (D(n)) を保存する代わりに、すべての線形セグメントの開始、その傾き、およびその値をそこに保存します。 2 つの連続するブレークポイントの間では、

 [
 D(x)=D(p)+s(x-p)。 
】

 次のブレークポイントを見つけるために、現在の線形セグメントを一時的に拡張し、その外挿を、既知の区分線形関数を使用して評価された真の反復と比較します。 2 つが一致する最後の点は、現在のセグメントの終わりです。 等価述語は単調に変化するため、二分探索でその点が見つかります。 反復自体は三分探索によって最小化され、前処理の複雑さ (O(M\log^3 N)) が与えられます。ここで (M) は傾きの変化の数です。 各クエリでは、ブレークポイント間の二分検索のみが必要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | (O(N^2)) | (O(N)) | 遅すぎる |
 | (n) ごとの凸 DP | (O(N\log N)) | (O(N)) | まだ遅すぎる |
 | 区分線形 DP | (O(M\log^3 N+T\log M)) | (O(M)) | 承認済み |

 ここで、(N=10^{15})、(T\le 50,000)、および (M) は必要な範囲の (1833) 付近にすぎません。 

## アルゴリズムのチュートリアル

 1. 定義する

 [
 f(k)=\sum_{j=1}^{k}\演算子名{ビット長}(j)。 
】

 (f(k)) を繰り返し必要とするため、すべての (k) 項を合計するのではなく、最も高い設定ビットから直接計算します。 (b=\演算子名{ビット長}(k)) の場合、

 [
 f(k)=(b-2)2^{b-1}+1+b(k-2^{b-1}+1)。 
】

 これにより、(f(k)) (O(1)) が 1 つ評価されます。 
2. (D(n)) を (n) 個のコードワードを使用した有効なトライの最小コストとして定義します。 基本ケースは (D(1)=1) です。 

(n>1) の場合は、葉を根元で分割します。 もし`0`側面には (k) 個の葉があり、`1`辺は (n-k) であり、根は (f(n)) に寄与します。 の`1`側は (D(n-k)) に寄与します。 (k>1) の場合、`0`側は最初に強制的な措置を講じる必要があります`1`エッジ、寄与 (f(k))、その後に最適な (D(k)) 構造。 (k=1) の場合、その強制エッジは不要です。`0`子供はすでに葉っぱです。 

したがって、

 [
 D(n)=f(n)+
 \分\左(
 D(n-1)+1,,
 \min_{2\le k<n}
 {D(k)+D(n-k)+f(k)}
 \右）。 
】
 3. (D) の現在わかっている部分を区分線形セグメントとして保存します。 させて`P[i]`セグメント (i) の最初の (x) である、`S[i]`その傾きと、`V[i]`値 (D(P[i]))。 それから

 [
 D(x)=V[i]+S[i](x-P[i])
 】

 (P[i]\le x<P[i+1]) の場合はいつでも。 

最初は (P=[1])、(S=[4])、(V=[1]) です。 最初のセグメントには (D(1)=1) と (D(2)=5) が含まれており、その差は (4) です。 
4. 関数を実装する`known(x)`二分探索で (x) を含むセグメントを見つけ、対応する一次式を評価します。 

この関数は、現在知られているブレークポイントよりもはるかに大きな値を評価することが意図的に許可されています。 これは、最後に発見されたセグメントの線形外挿を表します。 
5.実装`next_value(n)`漸化式を使用して、すべての未知数 (D(k)) を次のように置き換えます。`known(k)`。 機能

 [
 D(k)+f(k)+D(n-k)
 】

 は (k) で凸であるため、整数 3 分探索はその最小値を見つけます。 (k=1) の場合は次のように個別に処理されます。`known(n - 1) + 1`。 
6. 現在の線形セグメントが (p) で始まると仮定します。 次の最大値 (x>p) を見つけます。 

[
 既知(x)=next_value(x)。 
】

 外挿された直線が実際の最適関数である限り、2 つの値は一致します。 反復により大きな値が強制される最初の点で、傾きが変わります。 等価条件はこの検索間隔にわたって単調であるため、二分探索により最後の等価点が見つかります。 
7. 検出されたブレークポイントを追加します。 その値は古いセグメントから取得され、新しい傾きは次のようになります。 

[
 D(p+1)-D(p)。 
】

 (D(p+1)) を次から取得します。`next_value(p + 1)`。 このプロセスを繰り返すと、(10^{15}) までのすべての傾斜セグメントが生成されます。 
8. 各入力 (n) に対して、二分探索`P`そのセグメントを見つけて線形式を評価します。 答えはまさに (D(n)) です。 

### なぜ効果があるのか

 木の反復では、木の葉の可能なすべての数 (k) が考慮されます。`0`サイドなので、すべての有効なトライ形状をカバーします。 唯一の特別な構造上の制限は、強制的なものです。`1`葉以外のあと`0`これはまさに漸化式の追加の (f(k)) 項です。 

(f) と (D) が離散凸であるため、最適化は有効です。 したがって、分割コスト関数は凸関数であり、三分探索によってその最小値が見つかります。 区分的表現では、格納されているすべてのセグメントが真の DP 関数と正確に一致するという不変条件が維持されます。 セグメント境界では、再発が現在の線形外挿とまだ一致する最終点を見つけることによって、次のセグメントが見つかります。 その点以降は、繰り返しによって新しい傾きが決定されるため、そのブレークポイントを追加すると不変条件が維持されます。 すべてのクエリは正確なセグメントから評価されるため、返される値は真の最適値になります。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

MAX_N = 10**15
SEARCH_HIGH = 10**16

def f(n):
    """sum(bit_length(j) for j = 1..n), for n >= 1"""
    b = n.bit_length()
    first = 1 << (b - 1)

    # Sum_{j=1}^{first-1} bit_length(j)
    base = (b - 2) * first + 1

    # j = first .. n all have bit length b
    return base + b * (n - first + 1)

def build_segments():
    # P[i] = first x of segment i
    # S[i] = slope on segment i
    # V[i] = D(P[i])
    P = [1]
    S = [4]
    V = [1]

    def known(x):
        i = bisect_right(P, x) - 1
        return V[i] + S[i] * (x - P[i])

    def next_value(n):
        # k = 1 is special: the 0-child can itself be a leaf.
        lo = 1
        hi = n - 1

        while lo + 3 < hi:
            x1 = (2 * lo + hi) // 3
            x2 = (lo + 2 * hi) // 3

            v1 = known(x1) + known(n - x1) + f(x1)
            v2 = known(x2) + known(n - x2) + f(x2)

            if v1 > v2:
                lo = x1
            else:
                hi = x2

        best = known(n - 1) + 1

        for k in range(lo, hi + 1):
            if k == 1:
                cur = known(n - 1) + 1
            else:
                cur = known(k) + known(n - k) + f(k)
            if cur < best:
                best = cur

        return f(n) + best

    while True:
        left = P[-1] + 1
        right = SEARCH_HIGH

        # Find the last point where the current linear extrapolation
        # is still equal to the recurrence.
        while left < right:
            mid = (left + right + 1) // 2
            if known(mid) == next_value(mid):
                left = mid
            else:
                right = mid - 1

        p = left

        if p > MAX_N:
            break

        value_at_p = known(p)

        # The slope after p is D(p+1) - D(p).
        new_slope = next_value(p + 1) - value_at_p

        P.append(p)
        V.append(value_at_p)
        S.append(new_slope)

    return P, S, V

P, S, V = build_segments()

def answer(n):
    i = bisect_right(P, n) - 1
    return V[i] + S[i] * (n - P[i])

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(answer(n)))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```機能`f`Python 実装にとって重要な最初の最適化です。 区間 ([2^{b-1},2^b-1]) 内のすべての (j) はビット長 (b) を持つため、合計はビット長ごとにグループ化できます。 Python 整数を使用すると、C++ 実装で注意が必要となるオーバーフローの問題も解消されます。 

配列`P`、`S`、 そして`V`は DP をコンパクトに表現したものです。`known(x)`用途`bisect_right`ブレークポイントはその新しいセグメントに属しているためです。 この境界規則は不可欠です。 (P=[1,2,\ldots]) の場合、正確に (x=2) をクエリするには、その直前で終了するセグメントではなく、(2) で始まるセグメントを使用する必要があります。`next_value`再発を正確に追跡します。 (k=1) の式は意図的に分離されています。 書き込み`known(1) + known(n - 1) + f(1)`人工ノードを追加し、(n=2) に対してすでに間違った答えを生成します。 

三分検索は、残っている候補が 4 つ未満になると停止し、残りの整数値を明示的にチェックします。 これにより、浮動小数点三項検索に依存することがなくなり、最小値付近でのオフバイワンエラーが防止されます。 

前処理中に、`known`は、DP がその座標ですでにわかっているという約束ではなく、外挿です。 二分探索では、この外挿がどこで再帰を満たすかを尋ねるだけです。 最初の不一致に達すると、新しい勾配が導入されます。 保存されたセグメントのプレフィックスは、プロセス全体を通じて正確なままになります。 

前処理は、次のブレークポイントが (10^{15}) を超えると終了します。 (10^{16}) の検索上限は、次のブレークポイントを見つけるために使用される便利な安全境界にすぎず、クエリがその値に到達できるという主張ではありません。

 ## 特殊なケース

 (n=2) の場合、唯一の分割には 1 つの葉があります。`0`側。 アルゴリズムが使用するのは、`known(n-1)+1`したがって、ルートの前の寄与は (1+1=2)、ルートのコストは (f(2)=3) になります。 結果は(5)です。 (f(1)) を加算する一般的な分割式は、誤って (6) を返します。 

(n=4) の場合、最適な分割は (k=1) です。 このアルゴリズムは、特別な候補 (D(3)+1=12) を通常の候補 (D(2)+D(2)+f(2)=13) および (D(3)+D(1)+f(3)=17) と比較します。 (f(4)=8) を加算すると、答えは (20) になります。 これにより、強制的に`1`葉以外のあと`0`サブツリーは正しくモデル化されています。 

(n=10) の場合、最小値は複数の分割で発生します。 (k=3) と (k=4) の候補は両方とも (98) を生成します。 整数三項探索には一意のミニマイザーは必要ありません。目的が凸であることだけが必要なので、フラット最小値が正しく処理されます。 

(n=10^{15}) の場合、アルゴリズムは (10^{15}) 個の DP 状態を構築しません。 まず、小さな勾配ブレークポイントのセットを構築し、次に 1 つのセグメント ルックアップと 1 つの線形式を使用して要求された値を評価します。 これは、メモリまたは実行時間が (n) とともに増加する DP から目的のソリューションを分離する場合です。
