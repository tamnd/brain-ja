 ## 解決策
 ## 問題の理解

 1 つの手で 1 つのタプルが最大 (2^n-1) 個の新しいタプルに置き換えられ、初期位置にはすでに (n!) 個のタプルが含まれているため、ゲームは巨大に見えます。 これをシミュレーションとして見るのではなく、ポジションがスプレイグ グランディの値を持つ公平なゲームとして見るのが有益です。 

タプル (A=(A_1,\ldots,A_n)) は、すべての座標が正の場合にのみ再生できます。 移動では、(0\le B_i<A_i) を持つ任意のタプル (B) を選択し、(A) を削除し、(A_i) または (B_i) のいずれかを個別に選択して得られたすべてのタプルを各座標に挿入します。ただし、元のタプル (A) 自体は挿入されません。 全体の位置はこれらのタプル ゲームの互いに素な合計であるため、すべてのタプルの Grundy 値は XOR 演算されます。 

入力により、(n\times n) 行列 (M) が得られます。 その列のすべての順列について、個別の列を使用して各行から 1 つのエントリを取得し、1 つの初期タプルを取得します。 したがって、初期位置には、行列からのすべての順列選択に関連付けられた (n!) 個の積が含まれます。 必要な出力は、Grundy 値の XOR がゼロかどうかだけです。 値がゼロの場合は 2 番目のプレーヤーが勝つことを意味し、値がゼロ以外の場合は最初のプレーヤーが勝つことを意味します。 

境界 (n\le150) は、(n!) タプルの明示的な生成を含め、(n) 内のあらゆる指数関数を除外します。 (n=20) の場合でも、(n!) はすでに (2.4\cdot10^{18}) 程度であり、(n=150) の場合は実用的な表現をはるかに超えています。 行列には (n^2\le22500) 個のエントリしかありません。これは、置換の合計を代数的に書き直す必要があることを強く示唆しています。 行列のエントリは (2^{64}) より下にあるため、通常の符号付き 64 ビット演算は安全ではなく、必要な乗算はいずれにしても通常の整数の乗算ではありません。 

ゲームを通常の算術のように扱う実装を簡単に欺いてしまう小さなケースがいくつかあります。 例えば、```
1
0
```出力があります`Second`。 唯一のタプルは ((0)) であるため、正当な動きはありません。 すべてのタプルを正のヒープとして扱う実装では、最初のプレイヤーの勝利が誤って宣言されてしまいます。 

のために```
1
18446744073709551615
```出力は`First`。 1 つの座標では、ゲームはまさにそのサイズの通常の Nim ヒープであるため、すべての正の値が勝ちとなります。 (2^{64}-1) が (2^{63}-1) より大きいため、符号付き 64 ビット パーサーはこの入力ですでに失敗します。 

もう 1 つの微妙なケースは、繰り返し行です。 例えば、```
2
1 1
1 1
```出力があります`Second`。 2 つの同一の置換タプル、つまり ((1,1)) が 2 回あります。 それらの Grundy 値は XOR によってキャンセルされます。 順列合計を通常の整数合計に変換する実装では、この特性 2 のキャンセルが失われます。 

最後に2つ目のサンプルですが、```
2
1 2
2 3
```も与えます`Second`。 行列式に似た式は (1\otimes3\oplus2\otimes2=3\oplus3=0) です。ここで、(\otimes) は数値乗算です。 通常の乗算​​を使用すると (3+4=7) が得られますが、これはゲームのグランディ値とは何の関係もありません。 

## アプローチ

 直接的なアプローチでは、すべての順列を列挙し、そのタプルを構築し、そのタプルの Grundy 値を計算し、それらすべての値の XOR を計算します。 (n!) 個の順列があるため、これはすでに不可能です。 すべてのエントリが (2^{64}-1) に等しい最悪の場合の行列の場合、(n!) 個の初期タプルがあり、そのようなタプルの 1 つから (B) のすべての正当な選択肢を列挙しようとすると、(B) には ((2^{64}-1)^n) 個の選択肢があり、すべての選択肢に対して (2^n-1) 個のタプルが生成されます。 したがって、ゲーム ツリーの最初の層を列挙するだけでも、(n!(2^{64}-1)^n(2^n-1)) 個の組み合わせが必要になります。 ブルート フォースは概念的には正しいですが、実際のゲーム分析が適切になる前に失敗します。 

重要な観察は、タプルのグランディ値が驚くほど代数的な形式をとっているということです。 (a) を含む 1 座標タプルはグランディ値 (a) を持ちます。 いくつかの座標について、この移動により (A) が (A_i) と (B_i) の空でないすべての組み合わせで置き換えられます。 独立コンポーネントの Grundy 値は XOR 演算されるため、生成されたタプルの XOR は特性 2 の積とまったく同じように展開されます。 

これはまさに、数値乗算の再帰的ゲーム解釈です。 タプルが (A=(A_1,\ldots,A_n)) の場合、その Grundy 値は次のようになります。 

[
 g(A)=A_1\otimes A_2\otimes\cdots\otimes A_n。 
]

 その理由は、(A) から選択された (B) への移動により、数値乗算の標準的な再帰定義で使用されるのと同じ 3 隅、4 隅、および高次元の構造が作成されるためです。 すべての空でないサブセットに対する XOR は、対応する積拡張であり、nimber 乗算の mex 特性化により、必要なグランディ再帰が正確に得られます。 これは、Conway の減少長方形ゲームの (n) 次元バージョンです。 

したがって、開始位置は次の XOR になります。 

[
 \bigotimes_{i=1}^{n} M_{i,\sigma(i)}
 ]

 すべての順列 (\sigma) にわたって。 数値の加算は XOR であり、数値の乗算は XOR を介して分配されます。 行列式を標数 2 の体に展開すると、まさにこの順列和が得られます。 標数 2 では (1=-1) なので、通常の決定記号は消えます。 したがって、ゲーム全体がコンピューティングに帰着します。 

[
 \det(M)
 ]

 ここで、すべての加算は XOR であり、すべての乗算は nimber 乗算です。 この削減は、この問題に対する公開された解決策の議論の中心的な観察でもあります。 

残りの課題は、十分な速度で nimber 乗算を実装することです。 以下の値 (2^{64}) は、数値加算と乗算で有限体 (\mathrm{GF}(2^{64})) を形成します。 (O(n^3)) ガウス消去法内では、単純な再帰乗算はコストが高すぎます。 代わりに、64 ビットの数値を 16 ビットの部分に分割し、16 ビットの数値フィールドの対数/指数表現を事前計算します。 64 ビット製品は、一定数の 16 ビット フィールド製品のみを使用してアセンブルできます。 これは、確立された nimber ライブラリで使用されているのと同じ分割統治構造です。

 ## アルゴリズムのチュートリアル

 1. すべての行列エントリを 64 ビット数値として解釈します。 数値の加算は通常のビット単位の XOR ですが、乗算は特殊な数値の積です。 
2. 各初期タプルを独立した公平なゲームとみなします。 タプル (A) のグランディ値は次のとおりです。 

[
 A_1\otimes A_2\otimes\cdots\otimes A_n。 
]

 多次元移動ルールはまさに再帰的構造であり、そのグランディ値はニンバー乗算であるため、タプルの子孫をシミュレートする必要はありません。 

1. すべての置換タプルのグランディ値の XOR を計算します。 分配性により、これは次のようになります

[
 \bigoplus_{\シグマ}
 \左(
 M_{1,\sigma(1)}
 \otimes\cdots\otimes
 M_{n,\sigma(n)}
 \右）。 
]

 これは、64 ビット数値フィールド上の (M) の行列式です。 体には標数 2 があるため、奇数の順列に対する個別の符号はありません。 

1. ガウス消去法を使用してこの行列式を計算します。 列 (k) については、その列にゼロ以外のエントリがある行 (p\ge k) を見つけます。 何も存在しない場合、行列式はゼロとなり、答えはすぐに得られます。`Second`。 
2. 行 (p) と行 (k) を交換します。 通常のフィールドでは、行のスワップによって行列式が否定されますが、特性 2 では値の否定そのものであるため、行列式は変わりません。 
3. 行列式アキュムレータにピボット (A_{k,k}) を掛けます。 次に、その逆乗を計算し、それを使用してピボットより下のエントリを削除します。 行 (i>k) の場合、必要な係数は次のとおりです。 

[
 f=A_{i,k}\otimes A_{k,k}^{-1}。 
]

 すべての (j>k) について、次のように置き換えます。 

[
 A_{i,j}
 \左矢印
 A_{i,j}\oplus(f\otimes A_{k,j})。 
]

 その後、列 (k) のエントリを直接ゼロに設定できます。 

1. フィールド恒等を使用して逆数を計算する

 [
 x^{-1}=x^{2^{64}-2}
 ]

 非ゼロ (x) の場合。 2 進累乗では、ピボットごとに 64 回の乗算のみが必要ですが、これは (O(n^3)) の消去更新と比較すると無視できます。 有限体の逆恒等式は、公開されたソリューションで使用されるものでもあります。 

1. すべての列が処理された後、行列式アキュムレータは開始位置全体の Grundy 値になります。 印刷する`First`ゼロ以外の場合、および`Second`さもないと。 

### なぜ効果があるのか

 不変条件は、現在表現されているすべてのタプル ゲームの Grundy 値の XOR が、個々のゲーム値の nim-sum であるということです。 1 つのタプルの場合、移動ルールはまさに多次元の減少長方形ゲームであり、その Grundy 値はその座標の数値積です。 したがって、初期位置は、すべての順列によって選択された nimber 積の XOR に等しい値を持ちます。 分布性は、その順列 XOR を数値体上の (M) の行列式に変えます。 ガウス消去法は、行列を三角形の形式に縮小しながら行列式を保存し、そのピボットの積が行列式になります。 決定要因が 0 であるということは、Grundy 値が 0 であることを意味します。これはまさに先手プレイヤーにとって負けのポジションです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK16 = 65535
ORDER = 65535
PROOT = 10279
PPOLY = 92191

def build_small_table():
    dp = [[0] * 256 for _ in range(256)]
    dp[1][1] = 1

    for e in range(1, 4):
        p = 1 << e
        q = p >> 1
        ep = 1 << p
        eq = 1 << q
        mask = eq - 1

        for i in range(ep):
            for j in range(i, ep):
                if i < eq and j < eq:
                    continue

                if min(i, j) <= 1:
                    v = i * j
                else:
                    iu = i >> q
                    il = i & mask
                    ju = j >> q
                    jl = j & mask

                    u = dp[iu][ju]
                    l = dp[il][jl]
                    ul = dp[iu ^ il][ju ^ jl]
                    uq = dp[u][eq >> 1]

                    v = ((ul ^ l) << q) ^ uq ^ l

                dp[i][j] = v
                dp[j][i] = v

    return dp

SMALL = build_small_table()

def nim16_direct(a, b):
    if a == 0 or b == 0:
        return 0
    if min(a, b) <= 1:
        return a * b

    iu = a >> 8
    il = a & 255
    ju = b >> 8
    jl = b & 255

    u = SMALL[iu][ju]
    l = SMALL[il][jl]
    ul = SMALL[iu ^ il][ju ^ jl]
    uq = SMALL[u][128]

    return ((ul ^ l) << 8) ^ uq ^ l

def build_field_tables():
    base = [1] * 16
    for i in range(1, 16):
        base[i] = nim16_direct(base[i - 1], PROOT)

    raw_exp = [0] * ORDER
    raw_exp[0] = 1

    for i in range(1, ORDER):
        x = raw_exp[i - 1]
        raw_exp[i] = (x << 1) ^ (PPOLY if x & 32768 else 0)

    pre = [0] * 65536
    for bit in range(16):
        start = 1 << bit
        end = start << 1
        value = base[bit]
        for x in range(start, end):
            pre[x] = pre[x - start] ^ value

    exp = [0] * ORDER
    log = [0] * 65536

    for i in range(ORDER):
        value = pre[raw_exp[i]]
        exp[i] = value
        log[value] = i

    return exp, log

EXP16, LOG16 = build_field_tables()

def mul16(a, b):
    if a == 0 or b == 0:
        return 0
    return EXP16[(LOG16[a] + LOG16[b]) % ORDER]

def h16(a, shift):
    if a == 0:
        return 0
    return EXP16[(LOG16[a] + shift) % ORDER]

def mul32(a, b):
    ah = a >> 16
    al = a & MASK16
    bh = b >> 16
    bl = b & MASK16

    low = mul16(al, bl)
    cross = mul16(ah ^ al, bh ^ bl)
    high = h16(mul16(ah, bh), 3)

    return ((cross ^ low) << 16) ^ high ^ low

def mul64(a, b):
    if a == 0 or b == 0:
        return 0

    ah = a >> 32
    al = a & 0xffffffff
    bh = b >> 32
    bl = b & 0xffffffff

    low = mul32(al, bl)
    cross = mul32(ah ^ al, bh ^ bl)

    high_part = mul32(ah, bh)
    h_high = (
        (h16((high_part >> 16) ^ (high_part & MASK16), 3) << 16)
        ^ h16(high_part >> 16, 6)
    )

    return ((cross ^ low) << 32) ^ h_high ^ low

def nim_pow(a, e):
    result = 1
    while e:
        if e & 1:
            result = mul64(result, a)
        a = mul64(a, a)
        e >>= 1
    return result

def nim_inverse(a):
    return nim_pow(a, (1 << 64) - 2)

def determinant(mat):
    n = len(mat)
    det = 1

    for col in range(n):
        pivot = col
        while pivot < n and mat[pivot][col] == 0:
            pivot += 1

        if pivot == n:
            return 0

        if pivot != col:
            mat[pivot], mat[col] = mat[col], mat[pivot]

        p = mat[col][col]
        det = mul64(det, p)
        inv = nim_inverse(p)

        pivot_row = mat[col]

        for i in range(col + 1, n):
            value = mat[i][col]
            if value == 0:
                continue

            factor = mul64(value, inv)
            row = mat[i]

            row[col] = 0
            for j in range(col + 1, n):
                row[j] ^= mul64(factor, pivot_row[j])

    return det

def solve():
    n = int(input())
    mat = [list(map(int, input().split())) for _ in range(n)]

    ans = determinant(mat)
    print("First" if ans else "Second")

if __name__ == "__main__":
    solve()
```最初の前処理ステージでは、以下のすべての数値 (256) の乗算を構築します。 再帰では、8 ビット値が 2 つの半分に分割され、数値乗算の再帰定義が使用されます。 このテーブルには (256^2) 個のエントリのみが含まれています。 

次のステージでは、65536 個の要素を含むフィールドの表現を構築します。 値`PPOLY = 92191`多項式表現に使用される既約多項式を記述します。`PROOT = 10279`数値表現のプリミティブ要素を提供します。 指数テーブルは、その原始要素の累乗を実際の 16 ビット数値に変換します。`LOG16`逆マッピングを実行します。 この構造は、標準の高速 nimber 実装の 16 ビット バージョンです。 

16 ビットの nimber 積は、2 つのテーブル検索と 1 つのインデックス操作だけで済みます。 32 ビット製品と 64 ビット製品は、nimber フィールドの Karatsuba スタイルのアイデンティティを使用します。 特に、`mul32`3 つの 16 ビット製品が必要であり、`mul64`3 つの 32 ビット製品が必要です。 で表されるシフト`h16`は、16 ビット フィールド分解における (2^{15}) の乗算に対応します。 

行列式ルーチンは、加算を置き換える XOR を使用して通常のガウス消去法を実行します。 フィールドには特性 2 があるため、行の交換によって符号の変更は発生しません。 ピボット自体は次のように乗算されます。`det`行が消去に使用される前に行われるため、消去行が正規化されていなくても、最終値が行列式のままになります。 

逆指数は`(1 << 64) - 2`、これは正確に (2^{64}-2) です。 Python の整数には任意の精度があるため、指数の作成中または入力値の解析中にオーバーフローが発生することはありません。 行列エントリ自体は (2^{64}) 未満のままであり、すべての数値演算で別の 64 ビット フィールド要素が返されます。 

消去中の操作の順序が重要です。 係数は、ピボット行を変更する前に、現在のピボットの逆数を使用して計算する必要があります。 この実装では、ピボット行は正規化されないため、行の更新ごとに元のエントリが利用可能なままになります。 

## 実用的な例

 ### サンプル 1

 マトリックスは```
0 1 2
1 2 3
1 2 1
```除去トレースは次のとおりです。 

| コラム | ピボット行 | ピボット | 行の更新 | 決定要因 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | (R_1\leftrightarrow R_0)、次に (R_2\leftarrow R_2\oplus R_0) | 1 |
 | 1 | 1 | 1 | ピボットの下にゼロ以外のエントリはありません | 1 |
 | 2 | 2 | 2 | 以下に行はありません | 2 |

 最初の交換後の行列は次のようになります。```
1 2 3
0 1 2
1 2 1
```3 行目の因数は (1\otimes1^{-1}=1) なので、3 行目は次のようになります。```
0 0 2
```したがって、三角形のピボットは (1,1,2) となり、行列式は次のようになります。 

[
 1\otimes1\otimes2=2。 
]

 行列式はゼロ以外なので、最初のゲームのグランディ値はゼロ以外であり、答えは次のようになります。`First`。 

このトレースは、通常の乗算​​を行列式に代入してはならない理由も示しています。 同じ行列が数値フィールドで評価されます (たとえば、(2\otimes2=3))。 

### サンプル 2

 マトリックスは```
1 2
2 3
```トレースは次のとおりです。 

| コラム | ピボット | インバース | 行係数 | 更新された行 | 決定要因 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 2 | ([0,,3\oplus(2\otimes2)]=[0,0]) | 1 |
 | 1 | 0 | 利用不可 | なし | なし | 0 |

 (2\otimes2=3) なので、2 番目のエントリは次のようになります。 

[
 3\oplus3=0。 
]

 2 番目のピボットは存在しないため、行列式はゼロとなり、答えは次のようになります。`Second`。 

この例では、数値乗算が通常の整数乗算とは異なるため、行列が特異になる状況を正確に実行します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | (O(n^3+2^{16})) | ガウス消去法では (O(n^3)) 個のフィールド演算が実行されますが、16 ビット テーブルでは (O(2^{16})) 個の前処理が必要です。 
| スペース | (O(n^2+2^{16})) | 行列には (O(n^2)) 個のストレージが必要で、指数/対数テーブルには (O(2^{16})) 個のストレージが必要です。 

(n\le150) の場合、ガウス消去法には行列レベルの演算が数百万回しかなく、各乗算は一定数の 16 ビット テーブル アクセスに減ります。 前処理は (n) とは独立しているため、解は元の順列セットの階乗サイズではなく、意図した多項式の範囲に適合します。

 ## 特殊なケース

 ゼロタプルの場合は、逆算または消去が試行される前に処理されます。 のために```
1
0
```行列式は単一のエントリ (0) であるため、アルゴリズムはゼロを返し、次のように出力します。`Second`。 ゼロを含むタプルは選択できないため、これはゲームに一致します。 

可能な最大値については、```
1
18446744073709551615
```行列式は同じ非ゼロ数値です。 1 次元ゲームは通常の Nim ヒープであるため、その Grundy 値はヒープ サイズそのものです。 アルゴリズムは値を符号付き型に変換することはなく、非ゼロの行列式は次の結果を生成します。`First`。 

繰り返されるタプルは XOR によって自動的に処理されます。 と```
2
1 1
1 1
```どちらの順列もまったく同じタプル ((1,1)) を生成します。 その Grundy 値は (1\otimes1=1) で、2 つのコピーが寄与します (1\oplus1=0)。 2 つの行が等しいため、行列式もゼロになるため、アルゴリズムは次のように出力します。`Second`。 

ゼロ ピボットは、アルゴリズムがその下にあるすべての行を検索するまで、ゼロの決定要因を意味しません。 例えば、```
2
0 1
1 0
```最初のピボット位置はゼロで始まりますが、2 行目はゼロ以外のピボットを提供します。 行を交換した後、ピボットは (1) と (1) となり、行列式 (1) と出力が得られます。`First`。 単純にチェックするだけの実装`matrix[k][k] == 0`別の行を検索しないと誤って返されてしまいます`Second`。 

2 番目のサンプルでは、​​通常の算術演算と数値演算の違いを明らかにします。 のために```
2
1 2
2 3
```消去係数は(2)となり、右下の値は

 [
 3\oplus(2\otimes2)=3\oplus3=0。 
]

 行列式はゼロなので、結果は次のようになります。`Second`。 通常の整数消去では、代わりに (2\cdot2=4) を使用して (3-4=-1) を取得しますが、これはゲームの代数とは無関係です。 

最大次元で、すべてのエントリが (7) である (150\times150) 行列を考えます。 最初のピボットを選択できますが、他の行はすべてそれと同一であるため、削除すると後のピボット列はすべて消えます。 同様に、行列式には 2 つの等しい行があり、ゼロになります。 アルゴリズムは次のように終了します。`Second`(150!) の初期タプルを構築する必要はありません。
