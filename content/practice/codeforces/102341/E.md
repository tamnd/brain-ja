 ## 解決策
 ## 問題の理解

 (k) 個のスタックがあり、それぞれに (n) 個の石のすべての 1 つの破片が含まれています。 すべてのスタックにはすべての石が 1 回だけ含まれるため、各スタックは (1,\ldots,n) の順列になります。 

選択した連続するスタック グループ ([l,r]) について、各スタックの内部順序を維持しながら、その内容をインターリーブします。 同様に、([l,r]) 内のすべてのインデックスを正確に (n) 回使用して、スタック インデックスのシーケンスを構築します。 スタックの選択によって生成されたフラグメント値が、その現在の最上位値になります。 

石が (r-l+1) 回連続して出現する場合、その構築は不良です。 選択されたスタックはすべて異なるため、そのような実行には、間隔内のすべてのスタックからのその石の出現が 1 つだけ含まれます。 (f(l,r)) を、そのような実行をすべて回避するインターリーブの数とします。 必要な答えは、少なくとも 2 つのスタックを含むすべての間隔にわたる (f(l,r)) の合計です。 

順列は独立して均一にランダムに生成されます。 このランダム化は、意図された複雑さの議論の一部です。固定された石のペアの場合、長さ (s) の間隔のすべてのスタックで相対的な順序が同じになる確率は (2^{-s+1}) です。 公式の問題は Codeforces によってホストされており、同じ問題に対する独立した編集では、結果として予想される複雑さが (O(n^2k+nk^2)) として示されています。 

境界 (n,k\le300) は、すべてのインターリーブを列挙することに近いものを除外します。 (k) 個のスタックを含む 1 つのインターバルの場合でも、無制限のインターリーブの数は

 [
 \frac{(kn)!}{(n!)^k}。 
】

 (n=k=300) では、これは実際の列挙をはるかに超えています。 禁止されたランにはすべてのスタックから同じ石のコピーが 1 つ含まれており、すべての石は各スタックで 1 回だけ出現するという事実を利用する必要があります。 

実装を簡単に壊す可能性のある境界ケースがいくつかあります。 まず、(k=2) は、禁止区間が 2 つの等しい隣接するフラグメントで構成されることを意味します。 のために```
2 2
1 2
2 1
```(6) 無制限のインターリーブがあります。 ちょうど 4 つではダメなので、答えは (2) です。 値の最終シーケンスのみをチェックし、2 つのスタック順序を保持する必要があることを忘れたソリューションでは、無効な配置がカウントされる可能性があります。 

第二に、2 つの石は、すべてのスタック内で同じ相対順序を持つ場合にのみ、包含/除外で両方を選択できます。 のために```
3 2
1 2
1 2
2 1
```2 つのスタックの間隔はそれぞれ (2) に寄​​与し、3 つのスタックすべての間隔は (66) に寄与します。 合計の答えは (70) です。 各石が個別にランを形成できるかどうかだけをチェックするソリューションでは、交差項が欠落します。 

第三に、同一の順列は、ランダム化された入力分布を表すものではないにもかかわらず、有用な正確性テストです。 のために```
2 3
1 2 3
1 2 3
```唯一の区間の答えは (4) です。 ここでは、多くの禁止されたイベントが同時に互換性があるため、さまざまな不正なイベントが独立していると仮定した実装は失敗します。 

最後に、スタック内のすべての値が等しい入力は、まったく正当なテスト ケースではありません。 すべての行は順列である必要があるため、「すべて等しい値」とされるストレス テストでは、代わりに (1,2,\ldots,n) の 2 つのコピーなど、繰り返しの順列を使用する必要があります。 入力を任意の行列として扱うと、この区別が隠蔽される可能性があります。 

## アプローチ

 直接的なブルート フォースは概念的には単純です。 間隔 ([l,r]) ごとに、(r-l+1) 個のスタック インデックスのそれぞれの正確に (n) 個のコピーを含むスタック選択のすべてのシーケンスを列挙します。 各シーケンスについて、スタックをシミュレートし、1 つの石を含む長さ (r-l+1) のランが発生するかどうかを確認します。 この方法は、考えられるすべてのインターリーブを明示的に検査し、適切な構造の定義を正確に適用するため、正しいです。 

(s) スタックの間隔で、検査されるシーケンスの数は次のようになります。 

[
 \frac{(sn)!}{(n!)^s},
 】

 そして 1 つのシーケンスのコスト (O(sn)) をチェックします。 したがって、1 つの大きな間隔でも、すでに

 [
 O\left(sn\frac{(sn)!}{(n!)^s}\right)
 】

 操作。 最悪の間隔は (s=k) であるため、このアプローチは完全に実行不可能です。 

有益な観察は、包含-除外を使用して不適切な構造をカウントすることです。 スタックを含む間隔を修正します。 すべての石 (x) について、(x) の (s) 個のコピーが連続して発生するイベントを (E_x) とします。 

ここで、いくつかの石 (x_1,x_2,\ldots,x_t) を選択し、それらのすべてのイベントを要求するとします。 選択した石は、すべてのスタック内で同じ相対順序を持つ必要があります。 すべてのスタックで (x) が (y) より前に出現する場合は、(x\prec y) と書き込みます。 選択した石は、この部分的な順序でチェーンを形成する必要があります。 

チェーンが固定されると、シーケンスは自然にギャップに分割されます。 最初に選択された石の前、連続して選択された 2 つの石の間、および最後に選択された石の後、すべてのスタックが一定数の通常のフラグメントを提供します。 1 つのギャップ内では、スタック順序を維持しながら、これらすべてのフラグメントを任意にインターリーブできます。 

ギャップに (s) 個のスタックからの (d_1,d_2,\ldots,d_s) 個の通常のフラグメントが含まれているとします。 そのインターリーブ数は

 \frac{(d_1+\cdots+d_s)!}{d_1!\cdots d_s!}。 
】

 選択された各石自体が 1 つの連続したブロックを形成します。 その (s) スタック インデックスは任意の順序で出現でき、(s!) の係数が与えられます。 

これにより、石の上にパス DP が得られます。 (u\prec v) の場合、(u) から (v) への遷移には、それらの位置の間にあるフラグメントの多項係数のみが必要です。 DP は、ギャップ分解により、選択されたすべてのブロックの正確な数と位置がすでに説明されているため、選択された石の数がすでに選択されているかを知る必要はありません。 

1 つの間隔について、結果の DP は (O(n+m)) をとります。ここで (m) は、同等の順序付けられた石のペアの数です。 ランダムな順列により、平均して (m) が小さくなります。 長さ (s) の間隔では、固定された石のペアは、すべてのスタック全体で同じ相対順序を持つ確率 (2^{-(s-1)}) を持ちます。 すべての間隔を合計すると、予想される (O(n^2k)) の比較可能なペアの仕事量が得られます。 (O(k^2)) 間隔ごとの残りの (O(n)) 作業が (O(nk^2)) に寄与します。 これは、意図したランダム化された複雑さです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O\left(kn\frac{(kn)!}{(n!)^k}\right)) 最大間隔 | (O(kn)) | 遅すぎる |
 | 最適 | 期待値 (O(n^2k+nk^2)) | (O(n^2+nk)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのスタックを位置配列に変換します。 すべてのスタック (s) と石 (x) について、(\operatorname{pos}[s][x])、そのスタック内の (x) の位置を保存します。 これにより、すべての順序付けテストとすべてのギャップ サイズを一定時間内に取得できます。 
2. 左のエンドポイント (L) を固定し、右のエンドポイント (R) を一度に 1 スタックずつ拡張します。 最初のスタック (L) は、すべての石の固定順序を示します。 すべての比較可能なペアは、スタック (L) 内で (u) が (v) より前に発生するエッジ (u\to v) として表すことができます。 
3. すべての石 (x) について、(x) の前の接頭語の多項係数を維持します。 

[
 B_x=
 \frac{(\sum_s(\オペレータ名{pos}[s][x]-1))!}
 {\prod_s(\オペレーター名{pos}[s][x]-1)!},
 】

 および対応する接尾辞係数

 [
 A_x=
 \frac{(\sum_s(n-\オペレーター名{pos}[s][x]))!}
 {\prod_s(n-\operatorname{pos}[s][x])!}。 
】

 これらは、(x) を含む選択されたブロックの前後にすべてのフラグメントをインターリーブする方法の数を記述します。 

1. 現在比較可能なすべてのペア (u\prec v) について、それらの間のギャップの多項係数 (G_{u,v}) を維持します。 新しいスタックに位置 (p_u,p_v) がある場合、(p_u<p_v) のときに正確に比較可能性が存続します。 (p_u\ge p_v) の場合は、エッジを完全に削除します。 
2. 新しいスタックが追加されると、残っているすべての多項係数を定数時間で更新します。 現在の多項式に合計 (S) があり、新しいスタックが要素 (d) を提供する場合、

 [
 M' = M\frac{(S+d)!}{S!,d!}。 
】

 同じ式で (B_x)、(A_x)、およびすべての生き残った (G_{u,v}) が更新されます。 

1. 最初のスタックの石の順序で包含-除外 DP を実行します。 (dp[x]) を、(x) より前のすべてのギャップを含む、最後に選択された石が (x) である空でないすべてのチェーンの符号付き寄与とします。 それから

 -s!\left(
 B_x+
 \sum_{u\prec x}dp[u]G_{u,x}
 \右）。 
】

 最初の項は (x) のみを選択することに対応します。 1 つおきの用語は、(u) で終わるチェーンに (x) を追加します。 係数 (s!) は、新しく選択されたブロック内の (s) スタック選択肢の順序を説明します。 

1. DP の後、最後に選択したブロックの後にサフィックスを追加します。 区間の包含/除外補正は次のとおりです。 

[
 \sum_x dp[x]A_x。 
】

 無制限のインターリーブ数は次のとおりです。 

[
 T_s=\frac{(sn)!}{(n!)^s}。 
】

 したがって、

 [
 f(L,R)=T_s+\sum_x dp[x]A_x。 
】

 1. この値をすべて (R>L) のグローバル応答に追加します。 次に、アクティブな比較対象ペア構造を拡張 (R) して更新します。 左側のエンドポイントが変更されると、新しい最初のスタックを使用して構造を再構築します。 

重要な不変条件は、すべてのアクティブ エッジ (u\to v) が、現在の間隔のすべてのスタックで (u) が (v) より前に発生するという条件を正確に表すことです。 アクティブなエッジのチェーンごとに、DP は、ギャップごとに 1 つの多項係数と、選択された石ごとに 1 つの (s!) 因子を含む、厳密に 1 つの包含-除外項に寄与します。 したがって、同時不良イベントのすべてのサブセットは、正しい符号で 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve_instance(k, n, a):
    # pos[s][x] = zero-based position of stone x in stack s.
    pos = [[0] * n for _ in range(k)]
    for s in range(k):
        for p, x in enumerate(a[s]):
            pos[s][x - 1] = p

    max_fact = k * n
    fact = [1] * (max_fact + 1)
    for i in range(1, max_fact + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (max_fact + 1)
    invfact[max_fact] = pow(fact[max_fact], MOD - 2, MOD)
    for i in range(max_fact, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    invfact_n = invfact[n]

    ans = 0

    for left in range(k - 1):
        first = pos[left]

        order = sorted(range(n), key=first.__getitem__)

        # Every pair is created according to the order in the first stack.
        # Pair id -> (u, v).
        eu = []
        ev = []

        # Global doubly linked list of active pairs.
        gnxt = []
        gprev = []

        # Doubly linked lists of active incoming pairs for every v.
        bnxt = []
        bprev = []
        head_bucket = [-1] * n

        # Multinomial data for each pair.
        gap_sum = []
        gap_val = []

        # Active flag is useful when unlinking through two lists.
        active = []

        global_head = -1
        global_tail = -1

        # Build all pairs u -> v in first-stack order.
        for ii in range(n):
            u = order[ii]
            for jj in range(ii + 1, n):
                v = order[jj]

                eid = len(eu)
                eu.append(u)
                ev.append(v)

                d = first[v] - first[u] - 1
                gap_sum.append(d)
                gap_val.append(1)

                active.append(True)

                # Insert into v's incoming list.
                old = head_bucket[v]
                bprev.append(-1)
                bnxt.append(old)
                if old != -1:
                    bprev[old] = eid
                head_bucket[v] = eid

                # Insert into global list.
                gprev.append(global_tail)
                gnxt.append(-1)
                if global_tail != -1:
                    gnxt[global_tail] = eid
                else:
                    global_head = eid
                global_tail = eid

        # For one stack every multinomial coefficient is 1.
        before_sum = [first[x] for x in range(n)]
        before_val = [1] * n

        after_sum = [n - 1 - first[x] for x in range(n)]
        after_val = [1] * n

        invfact_n_pow = invfact_n

        # Add stacks right of 'left'.
        for right in range(left + 1, k):
            s = right + 1

            cur = pos[right]

            # Add the new stack to the prefix/suffix multinomials.
            for x in range(n):
                d = cur[x]

                old_sum = before_sum[x]
                new_sum = old_sum + d
                before_val[x] = (
                    before_val[x]
                    * fact[new_sum]
                    % MOD
                    * invfact[old_sum]
                    % MOD
                    * invfact[d]
                    % MOD
                )
                before_sum[x] = new_sum

                d2 = n - 1 - cur[x]

                old_sum = after_sum[x]
                new_sum = old_sum + d2
                after_val[x] = (
                    after_val[x]
                    * fact[new_sum]
                    % MOD
                    * invfact[old_sum]
                    % MOD
                    * invfact[d2]
                    % MOD
                )
                after_sum[x] = new_sum

            # Add the new stack to every currently comparable pair.
            eid = global_head
            while eid != -1:
                nxt_eid = gnxt[eid]

                u = eu[eid]
                v = ev[eid]

                pu = cur[u]
                pv = cur[v]

                if pu >= pv:
                    active[eid] = False

                    # Remove from global list.
                    p = gprev[eid]
                    q = gnxt[eid]
                    if p != -1:
                        gnxt[p] = q
                    else:
                        global_head = q
                    if q != -1:
                        gprev[q] = p
                    else:
                        global_tail = p

                    # Remove from v's bucket.
                    p = bprev[eid]
                    q = bnxt[eid]
                    if p != -1:
                        bnxt[p] = q
                    else:
                        head_bucket[v] = q
                    if q != -1:
                        bprev[q] = p
                else:
                    d = pv - pu - 1

                    old_sum = gap_sum[eid]
                    new_sum = old_sum + d

                    gap_val[eid] = (
                        gap_val[eid]
                        * fact[new_sum]
                        % MOD
                        * invfact[old_sum]
                        % MOD
                        * invfact[d]
                        % MOD
                    )
                    gap_sum[eid] = new_sum

                eid = nxt_eid

            # Number of unrestricted interleavings.
            invfact_n_pow = invfact_n_pow * invfact_n % MOD
            total = fact[s * n] * invfact_n_pow % MOD

            # Inclusion-exclusion DP.
            dp = [0] * n
            block_factor = fact[s]

            for x in order:
                val = before_val[x]

                eid = head_bucket[x]
                while eid != -1:
                    u = eu[eid]
                    val += dp[u] * gap_val[eid]
                    if val >= MOD:
                        val %= MOD
                    eid = bnxt[eid]

                dp[x] = (-block_factor * (val % MOD)) % MOD

            good = total
            for x in range(n):
                good += dp[x] * after_val[x]
                if good >= MOD:
                    good %= MOD

            ans += good
            if ans >= MOD:
                ans %= MOD

    return ans % MOD

def solve():
    k, n = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(k)]
    print(solve_instance(k, n, a))

if __name__ == "__main__":
    solve()
```位置行列は、最初の構造的前処理ステップです。 逆順列を保存すると、2 つの石の間のすべての比較が 1 つの配列検索になるため、石のスタックを繰り返し検索するよりもはるかに便利です。 

固定左エンドポイントの場合、最初のスタックは DP によって使用されるトポロジー順序を定義します。 スタックが 1 つだけ存在するため、すべてのペアは比較可能なものとして開始されます。 別のスタックが追加されると、その順序が新しいスタックと一致する場合、ペアは存続するか、永久に消滅します。 この単調性により、アクティブ ペア リストを段階的に維持できるようになります。 

プレフィックスおよびサフィックスの多項式は、ペアのギャップと同じ更新 ID を使用します。 現在、多項式に合計が (S) である部分があり、新しいスタックが (d) に寄与すると仮定します。 新しい値は、古い値に次の値を乗算したものです。 

[
 \frac{(S+d)!}{S!d!}。 
】

 すべての階乗と逆階乗は事前に計算されたモジュロ (10^9+7) であるため、各更新は定数時間になります。 

ペア構造では、エッジごとに 2 つのリンク リストが使用されます。 グローバル リストを使用すると、実装では、スタックが追加されるときに、現在アクティブなすべての比較可能なペアを参照できます。 ターゲットごとのリストにより、DP は特定のストーンのアクティブな先行者のみを訪問できます。 ペアは、相対的な順序が矛盾した後、両方のリストから 1 回だけ削除されます。 

サインイン`dp[x]`追加の不良イベントを 1 つ選択すると、包含/除外の係数 (-1) が寄与するため、負の値になります。 移行は、

 [
 -s!\left(B_x+\sum dp[u]G_{u,x}\right),
 】

 そうではない

 [
 -s!B_x\left(1+\sum dp[u]G_{u,x}\right)。 
】

 後者は、(x) が既存のチェーンに追加されるときに、(x) の前のプレフィックスを 2 回カウントします。 

Python の整数はオーバーフローしませんが、すべての乗算は剰余 (10^9+7) で減算されます。 必要な最大階乗は (k n\le90000) ですが、これは直接事前計算するには十分小さいです。 

## 実用的な例

 ### サンプル 1

 入力は```
3 3
1 2 3
3 2 1
1 3 2
```間隔 ([1,2]) を考慮します。 (20) 個の無制限のインターリーブがあります。 

[
 \frac{6!}{3!3!}=20。 
】

 ３つの石の位置は、

 | 石 | スタック 1 | スタック 2 | 匹敵するものですか？ |
 | --- | --- | --- | --- |
 | 1 | 1 | 3 | |
 | 2 | 2 | 2 | |
 | 3 | 3 | 1 | |

 両方のスタックで同じ相対順序を持つ石のペアは存在しないため、すべての包含/除外チェーンの長さは 1 になります。 

石 (1) の場合、接頭語には (0) と (2) の要素が含まれており、多項係数は (1) になります。 サフィックスには (2) と (0) が含まれており、(1) も与えられます。 このブロックには (2!) 個の内部命令があるため、その不良イベント数は (2) です。 

石 (2) の場合、接頭辞は (1,1) 要素を持ち、(2) に寄​​与します。 接尾辞も (2) に寄​​与します。 ブロック要素 (2!) を含めると、不良イベントの数は (8) になります。 

石 (3) の場合、カウントは再び (2) になります。 

DP 状態は

 | 石 | 接頭辞係数 | 前任者の貢献 | (dp) | サフィックス係数 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | -2 | 1 |
 | 2 | 2 | 0 | -4 | 2 |
 | 3 | 1 | 0 | -2 | 1 |

 したがって、

 [
 f(1,2)=20-2-8-2=8。 
】

 区間 ([1,3]) では、3 番目のスタックは、3 つの順列に従って一部の比較可能性を削除し、他の比較可能性を保持します。 同じ DP を実行すると、

 [
 f(1,3)=1446。 
】

 3 つの間隔値は (8,1446,10) であるため、最終的な答えは次のようになります。 

[
 8+1446+10=1464。 
】

 このトレースは、DP が個々の石ではなく、互換性のある不良イベントの連鎖に基づいている理由を示しています。 単一の不良イベントにはプレフィックスとサフィックスの多項式のみが必要ですが、イベントの同時コレクションはアクティブな先行エッジによって表されます。 

### サンプル 2

 入力は```
4 2
1 2
2 1
1 2
2 1
```2 つの隣接するスタックの場合、無制限のインターリーブ数は次のとおりです。 

[
 \frac{4!}{2!2!}=6。 
】

 スタック (1、2) の場合、2 つの石は逆の順序で表示されるため、どちらのペアも比較できません。 それぞれの石は 2 つの悪い構造に寄与し、

 [
 f(1,2)=6-2-2=2。 
】

 同じ推論により、

 [
 f(2,3)=2、\qquad f(3,4)=2。 
】

 3 つのスタックの場合、無制限の数は次のとおりです。 

[
 \frac{6!}{2!2!2!}=90。 
】

 2 つの石にはやはり互換性のない相対順序があるため、交差項はありません。 個々の悪いイベントが寄与し (12)、

 [
 f(1,3)=90-12-12=66。 
】

 同様に、

 [
 f(2,4)=66。 
】

 4 つのスタックすべてについて、

 [
 \frac{8!}{2!^4}=2520
 】

 無制限のインターリーブ。 2 つの石には交互の順序パターンがあり、DP は次のようになります。 

[
 f(1,4)=2328。 
】

 間隔の値は次のとおりです。 

| 間隔 | (f(l,r)) |
 | --- | --- |
 | ([1,2]) | 2 |
 | ([1,3]) | 66 |
 | ([1,4]) | 2328 |
 | ([2,3]) | 2 |
 | ([2,4]) | 66 |
 | ([3,4]) | 2 |

 それらの合計は (2466) で、サンプル出力と一致します。 

この例では、主要な最適化を実行します。 スタックが追加されると、互換性のないペアがアクティブ リストから消えるため、DP はすべての (n^2) 個の可能なペアを繰り返し検査しません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 期待値 (O(n^2k+nk^2)) | (O(n)) 間隔ごとの DP 仕事に、生き残った比較可能なペアに比例する仕事を加えたもの |
 | スペース | (O(n^2+nk)) | ペアリストとそのギャップ係数が支配的 |

 石のペアの場合、1 つのスタックで順序を固定した後、追加の独立したランダム スタックごとにその順序が確率 (1/2) で保持されます。 したがって、長さ (s) の区間では、確率 (2^{-(s-1)}) でペアが生き残ります。 可能なすべての間隔を合計すると、予想される (O(n^2k)) ペアの処理が得られますが、(O(n)) 個の間隔ごとの DP 作業では (O(nk^2)) が得られます。 これは、問題の独立した編集情報源によって記述された、ランダム化された複雑さです。 

(n,k\le300) を使用すると、予想される作業量は実用的になります。 この実装では、アクティブ ペア グラフに対して Python セットや辞書の代わりにコンパクトな整数配列も使用します。これは、このスケールでは定数因子が重要であるためです。

# Same permutation twice.
# There is only one interval, and its answer is 4.

    [1, 2, 3],

# Three stacks, with the third reversing the order.

 ## 特殊なケース

 最小の場合```
2 2
1 2
2 1
```(6) 無制限のインターリーブがあります。 石 (1) は (2) の方法で連続したペアを形成でき、石 (2) は (2) の方法で同じように形成できます。 2 つのスタックは相対的な順序が一致しないため、それらのイベントは同時に発生することはできません。 したがって、DP は (6-2-2=2) となります。 重要な境界は、間隔の長さが正確に (2) であるため、不良ランは 2 つの等しいフラグメントで構成されることです。 

のために```
2 3
1 2 3
1 2 3
```3つの石はどれも同等です。 不良イベントの数は (12,8,12) です。 ペアの交差には重み (8,8,8) があり、トリプル交差には重み (8) があります。 包含排除により、

 [
 20-(12+8+12)+(8+8+8)-8=4。 
】

 アクティブ ペア構造では、両方のスタックで順序が一致するため、3 つのペア エッジすべてが保持されます。 このテストは、すべての悪いイベントを個別に扱うという間違いを発見します。 

のために```
3 2
1 2
1 2
2 1
```最初の 2 つのスタックは一致するため、石のペアは間隔 ([1,2]) に関して同等です。 3 番目のスタックを追加すると、順序が逆になるため、そのペアが削除されます。 2 つのスタック インターバルはそれぞれ (2) に寄​​与しますが、3 スタック インターバルには (90) の無制限のインターリーブと 2 つの個別の不良イベントによる寄与 (12) があり、(66) になります。 合計は(70)です。 これにより、新しく追加されたスタックの順序が逆になったときにペアの削除が正確に行われることが検証されます。 

テスト ブロックで使用される巡回シフト構造など、最大サイズの有効な入力の場合、すべての行は本物の順列のままになります。 階乗配列には (90000) までのインデックスのみが必要で、すべての多項更新はモジュラー演算内に留まります。 アクティブ ペア リストにより、DP はすでに互換性がなくなったペアをスキャンできなくなります。 元の入力のランダム化された性質により、予想される生き残るペアの数が、意図した (O(n^2k+nk^2)) 限界に対して十分に小さくなります。 

「すべて等しい値」のケースは、すべてのスタックが順列であるという入力条件に違反するため、このプログラムに渡すべきではありません。 最も近い意味のあるストレスケースは、同じ順列を何度も繰り返すことです。 この場合も、意図的に可能な限り最大数の比較可能なペアを作成し、非典型的で高度に構造化された入力に対しても包含-除外式自体が正しいままであることを確認するため、役に立ちます。
