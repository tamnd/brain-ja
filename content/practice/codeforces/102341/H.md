 ## 解決策
 ## 問題の理解

 最大 200,000 の交差点と 200,000 の道路を含む、接続された無向グラフがあります。 頂点 1 から開始して頂点 n に到達したいと考えています。 道路を横断するのに 1 分かかりますが、どの道路にも 2 種類の Hypno のいずれかが隠されています。 確率 1/2 では、Hypno は私たちにとって無害であり、その場合、すべての横断は成功します。 確率 1/2 では有害であり、この場合、すべての走査は確率 1/2 で独立して成功します。 

道路を使用する前には、道路の種類はわかりません。 横断の失敗は特に貴重な情報であり、その道路が有害であることを証明します。 トラバーサルが成功しても、Hypno が完全に特定されるわけではありませんが、新しい頂点から続行する場合、これまでに得られた情報は適応戦略を有効にするのに十分です。 

このタスクは、頂点 1 から頂点 n までの予想される最小移動時間を計算することです。 必要な絶対誤差または相対誤差は最大 10^-9 です。 

この制約により、グラフの大部分を繰り返し検査するアルゴリズムが除外されます。 頂点が 200,000 個、エッジが 200,000 個ある場合、O(nm) メソッドは最悪の場合でも約 4 * 10^10 の隣接演算を実行できますが、これは 2 秒の制限をはるかに超えています。 基本的に線形または O((n + m) log n) の作業が必要です。 

最初の小さなエッジ ケースは、頂点が 2 つだけあるグラフです。```
2 1
1 2
```答えは1.5です。 すべての道路を予想通過時間 2 があるものとして扱う不用意な解決策では、免疫の 1/2 確率を忘れて 2 が出力されます。 

2 番目のエッジ ケースは、目的地までの直接道路と無関係な代替手段です。```
3 2
1 3
1 2
```答えはやはり 1.5 です。 目的地には最初の道路を使用して到達できるため、頂点 2 に関する情報は無関係です。 最適化ではなく、すべての下り道路を平均するソリューションでは、より悪い値が生成される可能性があります。 

興味深いエッジケースとして、同様に優れた代替案がいくつかあります。 グラフの中で```
4 4
1 2
2 4
1 3
3 4
```各 2 エッジ ルート自体のコストは 3 と予想されますが、最適な答えは 2.875 です。 1 つのルートで最初の試みが失敗した後、すぐに既知の悪路を再試行するよりも、別のルートを試すほうが良い場合があります。 したがって、すべての道路に 1.5 の固定コストを割り当て、通常の最短パスを単純に実行するソリューションでは、中心となる観察が欠けてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、頂点ごとに、すでに検出されているすべての隣接頂点の距離を維持し、別の隣接頂点が利用可能になるたびに最適なローカル戦略を再計算します。 ローカル戦略を評価するには、既知の近傍値を並べ替えて、役立つ可能性のあるプレフィックスを検査します。 これは正しいです。なぜなら、近傍は最適な継続値の昇順に考慮されるからです。 

問題は、更新のたびに完全なスキャンを実行すると、同じ隣接リストを何度も検査する可能性があることです。 次数 d の頂点の場合、これには O(d^2) がかかり、グラフ全体では最悪のケースは O(m^2) になります。 m = 200,000 の場合、およそ 4 * 10^10 の隣接検査に達します。 

重要な観察は、目的地から開始してダイクストラのアルゴリズムを使用してグラフを処理すると、近傍が最適値の昇順で既知になるということです。 頂点の最初の有用な近傍が判明すると、その後のすべての近傍がその距離の減少しない順序で到着します。 プレフィックス全体を再計算する代わりに、期待値を段階的に更新できます。 

最良の近傍が最適な継続値 x を持つ頂点 u を考えてみましょう。 あなたからの新しいk路ですでに失敗したと仮定します。 最初に失敗した道路は最もよく知られているフォールバックであり、現在では有害であることが知られています。 この時点からその道路を横断するにはさらに 2 分かかり、その後継続するには x の費用がかかります。 

継続値 y を持つ別の新しい道路を検討する前に、フォールバックのコストは 2 + x です。 新しい道を試すには、すぐに 1 分かかります。 確率 3/4 で成功し、継続 y が得られます。 確率 1/4 で失敗し、その後のフォールバックには 2 + x のコストがかかります。 したがって、この追加の道路を試行する場合に予想されるコストは次のようになります。 

1 + 3/4 y + 1/4(2 + x)。 

試してみるとこんなときに便利です

 1 + 3/4 y + 1/4(2 + x) < 2 + x、

 これを単純化すると

 y < x + 2/3。 

このしきい値は、距離が大きくなりすぎるとアルゴリズムが近隣の処理を永久に停止できる理由です。 

最初の道路の場合、横断が成功する確率は 3/4 です。これは、私たちが免疫を持っているか、影響を受けやすいかのどちらかであり、ランダムなエンドポイントが反対であるためです。 失敗した場合 (確率 1/4 で発生)、その道路は有害であることがわかります。 

有用な近傍の値が昇順に x1、x2、...、xk を持つ場合、期待される値は次のようになります。 

E_k = Σ (1/4)^(i-1) * (3/4) * (i + x_i) の i=1 から k
 + (1/4)^k * (k + 2 + x_1)。 

重要な部分は、E_k が一定時間で更新できることです。 E_1 = 1.5 + x_1 から始めて、x_k を追加すると、答えは次のように変化します。 

(1/4)^(k-1) * (3/4 * (x_k - x_1) - 1/2)。 

したがって、すべてのエッジは、そのエンドポイントがダイクストラによって最終決定されるときに 1 回だけ処理する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 視点を逆にして、頂点 n からダイクストラを実行します。 頂点に保存された値は、その頂点から n までの予想される最小残り時間を表します。 

グラフには方向性がないため、エッジを物理的に変更する必要はありません。 n を距離ゼロで初期化し、その近傍に情報を伝播するだけです。 

1. すべての頂点 u について、最終的な最小隣接距離を維持します。`first[u]`。 最初の近傍が決定される前に、u には候補となる戦略がありません。 

距離 d の最初の隣接 v が決定されると、現在知られている最良の戦略は、成功するまでその道路を使用することです。 新しい道路には 1.5 分かかると予想されるため、`value[u] = d + 1.5`。 

1. 最初の近傍が処理された後、確率を維持します。`p`それまでの有用な新しい道路がすべて失敗した後、次の新しい道路に到達するまでの時間。 

すべての新しい道路は 1/4 の確率で失敗するため、k 個の有用な道路を処理した後のこの確率は次のようになります。`(1/4)^k`。 

1. 距離 d の別の近傍が決定されたら、それを次のものと比較します。`first[u]`。 

もし`d >= first[u] + 2/3`、戦略を改善することはできません。 その後最終的に決定されたすべての近傍の距離は少なくとも d であるため、距離を改善することもできません。 u の近隣の処理を停止できます。 

もし`d < first[u] + 2/3`、戦略に含めてください。 現在の期待値は次のように変化します`p * (0.75 * (d - first[u]) - 0.5)`。 

次に、次の新しい道路に到達するには別の失敗が必要になるため、p に 1/4 を掛けます。 

1. u の現在の値が改善されるたびに、新しいペアを挿入します。`(value[u], u)`優先キューに入れます。 

同じ頂点に対して複数のエントリが存在する場合があります。 エントリがポップされたときに、そのエントリが現在の最良の値と等しくない場合は、そのエントリを破棄します。 これは、ダイクストラ実装で使用される標準的な遅延削除手法です。 

1. 頂点 1 が確定すると、その値が答えとなります。 

ダイクストラ順序付けは、頂点の有用な近傍が満足するため有効です。`d < first[u] + 2/3`。 

u の現在の値は常に より大きいです`first[u] + 2/3`したがって、u 自体をファイナライズする前に、すべての有用な近傍をファイナライズする必要があります。 したがって、u が優先キューを離れるとき、その応答を改善できるすべての近傍はすでに組み込まれています。 

### なぜ効果があるのか

 固定頂点 u の場合、最適戦略では、最適継続値の非降下順に隣接候補を考慮します。 最初の道路が失敗すると、その道路は予想残り横断時間 2 の既知の有害な代替道路になります。新しい道路は、その継続値が 2 未満の場合にのみ役立ちます。`first[u] + 2/3`, したがって、有用な近傍はダイクストラ次数の接頭辞を形成します。 

維持される値は、そのプレフィックスを試行し、新たな試行がすべて失敗した場合に最初に失敗した道路を繰り返し使用する場合に予想されるコストとまったく同じです。 増分式は完全な期待式と代数的に同等であるため、更新のたびに、現在利用可能なすべての有用な近傍の中で正確な最適値が保存されます。 

潜在的に有用な近傍はすべて u の値よりも短い距離を持っているため、そのような近傍はすべて u より前に確定されます。 したがって、ダイクストラが u を最終化すると、将来の近傍はその値を改善できなくなります。 これにより、通常のダイクストラと同じ正確性の不変性が得られます。未確定の最小値がすでに最適です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    INF = float("inf")

    dist = [INF] * n

    # first[u] is the smallest finalized neighbor distance.
    first = [INF] * n

    # value[u] is the best expected value currently known for u.
    value = [INF] * n

    # prob[u] is the probability of reaching the next fresh edge
    # after all currently useful edges have failed.
    prob = [0.0] * n

    # Whether we have already found the first neighbor.
    seen = [False] * n

    pq = [(0.0, n - 1)]
    dist[n - 1] = 0.0

    while pq:
        cur, u = heapq.heappop(pq)

        if cur != dist[u]:
            continue

        if u == 0:
            print(f"{cur:.12f}")
            return

        du = cur

        for v in graph[u]:
            d = du

            if not seen[v]:
                seen[v] = True
                first[v] = d

                # One fresh edge has expected traversal cost 3/2.
                value[v] = d + 1.5

                # To reach the second fresh edge, the first one
                # must have failed, which happens with probability 1/4.
                prob[v] = 0.25

                if value[v] < dist[v]:
                    dist[v] = value[v]
                    heapq.heappush(pq, (dist[v], v))

            else:
                # Later neighbors are processed in nondecreasing d.
                # Once this threshold fails, no later neighbor can help.
                if d >= first[v] + 2.0 / 3.0:
                    continue

                # Add this neighbor to the useful prefix.
                value[v] += prob[v] * (
                    0.75 * (d - first[v]) - 0.5
                )

                prob[v] *= 0.25

                if value[v] < dist[v]:
                    dist[v] = value[v]
                    heapq.heappush(pq, (dist[v], v))

if __name__ == "__main__":
    solve()
```隣接リストには、通常の方法で無向グラフが格納されます。 すべての道路は双方向であるため、個別の反転グラフを作成する必要はありません。`dist`はダイクストラ値です。`value`インクリメンタルなローカル式を保存します。`first`これまでに処理された近傍の中で最良の継続値を記憶します。`prob`次の未使用の道路に到達する確率を格納します。 

最初のネイバーには特別な処理が必要です。 道路は新しいため、無条件の予想通過時間は 3/2 です。 最初の試行が失敗する確率は 1/4 で、これが 2 番目の新しい道路に到達する確率になります。 

後のすべての隣人について、式は```
prob[v] * (0.75 * (d - first[v]) - 0.5)
```は、まさに、その近隣を有用なプレフィックスに追加することによって生じる期待値の変化です。 

しきい値は以下を使用します`2.0 / 3.0`、 ない`1.0 / 2.0`。 これは、誤った実装が発生しやすい箇所です。 新しい道路への挑戦自体には常に 1 分かかり、その後 3/4 の確率で成功し、1/4 の確率で失敗します。 これら 2 つの戦略を比較すると、2/3 のしきい値が得られます。 

ここでは浮動小数点で十分です。 乗数`prob`有用な近傍が追加されるたびに 4 倍に減少するため、有用な近傍が数十個追加されただけでは、その寄与は必要な 10^-9 精度をはるかに下回ります。 Python の整数は数値の反復に関与しないため、整数のオーバーフローの問題は発生しません。 

優先キューは遅延削除を使用します。 頂点は、最終的に決定される前に、段階的により良い推定値をいくつか受け取ることができます。 現在のエントリと一致するエントリのみ`dist[u]`処理されます。 

## 実用的な例

 ### サンプル 1

 グラフは三角形で、頂点 3 が目的地です。```
3 3
1 2
1 3
2 3
```頂点 3 以降、頂点 1 と頂点 2 は両方とも最初は継続値 0 を持ちます。 

| 完成した頂点 | 隣人が更新されました | 最初の値 | 現在の値 |
 | --- | --- | --- | --- |
 | 3 | 1 | 0 | 1.500000 |
 | 3 | 2 | 0 | 1.500000 |

 頂点 1 は宛先への直接エッジを受け取り、1.5 を与えます。 もう一方のエッジは継続値も 0 であるため改善できませんが、別の有用な更新が重要になる前に頂点はすでに終了しています。 

したがって、答えは 1.500000000000 となります。 

このトレースは、単一の新しい道路のコストが 1.5 と予想される理由を示しています。 最初の試みは 3/4 の確率で成功します。 失敗した場合、その道路は有害であることが判明し、残りの試行の予想回数は 2 回となり、道路が有害であるという条件付きの合計予想時間は 2 になります。 

### サンプル 2

 グラフは```
4 4
1 2
2 4
4 3
3 1
```目的地4で。 

頂点 2 と 3 にはそれぞれ目的地への新しい道路が 1 つあるため、両方とも値 1.5 を取得します。 

| 完成した頂点 | 更新された頂点 | 最初の値 | 隣人を追加 | 新しい価値 |
 | --- | --- | --- | --- | --- |
 | 4 | 2 | 1.500000 | なし | 1.500000 |
 | 4 | 3 | 1.500000 | なし | 1.500000 |
 | 2 | 1 | 1.500000 | なし | 3.000000 |
 | 3 | 1 | 1.500000 | 1.500000 | 2.875000 |

 頂点 1 の場合、頂点 2 のみを使用すると 3 が得られます。ただし、頂点 2 への道路が失敗した後は、頂点 3 を経由する他のルートを試す価値があります。その継続値は最初のルートの値と等しく、その継続値が下回っているためです。`first + 2/3`しきい値。 

2 回目の試行は 1/4 の確率で達成されます。 これを含めると値が 3 から 2.875 に減り、必要なサンプル回答が得られます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | すべての隣接関係は 1 回処理され、有用な値の更新はすべてバイナリ ヒープに挿入されます。 
| スペース | O(n + m) | 隣接リスト、距離配列、および優先キューには線形スペースが必要です。 

グラフには最大 200,000 のエッジが含まれるため、アルゴリズムは O(m) 個のローカル エッジ処理と O(m) 個のヒープ挿入のみを実行します。 結果として得られる O((n + m) log n) の複雑さは、指定された制約に容易に適合しますが、メモリ使用量はグラフ サイズにおいて線形です。

    for _ in range(m):

    return ""

 ## 特殊なケース

 2頂点グラフの場合```
2 1
1 2
```ダイクストラは値 0 の頂点 2 から始まります。 頂点 2 がファイナライズされると、頂点 1 はその最初の近傍を次のように受信します。`first[1] = 0`。 その候補値は次のようになります。`0 + 1.5 = 1.5`。 2 番目の近傍は存在しないため、答えは正確に 1.5 になります。 

直接の宛先エッジを含むグラフの場合、```
3 2
1 3
1 2
```頂点 3 が最初にファイナライズされます。 直接エッジは頂点 1 に 1.5 の値を与えます。 頂点 2 も最終的には処理されることになりますが、その距離では、すでに最終化された直接の宛先エッジよりも優れたルートを提供することはできません。 答えは 1.5 のままです。 

3 つの等しい選択肢を含むグラフの場合、```
5 6
1 2
2 5
1 3
3 5
1 4
4 5
```頂点 2、3、および 4 はすべて、頂点 5 から値 1.5 を受け取ります。最初のそのような近傍は頂点 1 に値 3 を与えます。2 番目の近傍はそれを次のように変更します。`(1/4) * (-1/2) = -1/8`、

 2.875を与えます。 3番目は次のように変更します`(1/16) * (-1/2) = -1/32`、

 2.84375を与えます。 4 番目の同等の代替案では、わずか 1/128 だけ改善されます。以下同様です。 幾何学的確率係数はまさに増分表現を効率的にするものです。 

次の隣接頂点に少なくとも距離がある場合`first + 2/3`、アルゴリズムはそれを無視します。 最もよく知られている近傍の値が x であり、新しい近傍の値が y であるとします。 もし`y >= x + 2/3`、その新しい道路を試すには、既知の有害な道路をすぐに使用するのと少なくとも同じくらいの費用がかかります。 将来のすべての隣接値はさらに大きな最終値を持つため、いずれも役に立ちません。 これは、同じ隣接リストの繰り返しスキャンを防止する停止条件です。 

最大サイズのチェーンの場合、各頂点には宛先に向けて有用な近傍が 1 つだけあります。 代替道路は考慮されないため、すべてのエッジが予想時間に正確に 1.5 寄与します。 199,999 本の道路がある場合、結果は次のようになります。`199999 * 1.5 = 299998.5`。 このアルゴリズムはすべてのエッジを 1 回処理し、O((n + m) log n) 時間以内に処理されます。
