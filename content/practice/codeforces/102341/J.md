 ## 解決策
 ## 問題の理解

 小文字の (n \times m) 個のグリッドがあります。 ルートは左上のセルで開始し、右下のセルで終了し、右と下の移動のみで構成されます。 すべてのルートは正確に (n+m-1) 個のセルを訪問するため、すべてのルートで同じ長さの文字列が生成されます。 

問題は、ある特定の文字列が少なくとも 3 つの異なるルートで生成できるかどうかです。 ルート自体は別々である必要はありません。 長いプレフィックスやサフィックス、あるいはセルの大部分を共有する場合もあります。 重要なのは、訪問した文字のシーケンスは同一であるが、移動のシーケンスは異なるということです。 

境界 (n,m\le 3000) では、最大 900 万のグリッド セルが与えられます。 すべてのセルを一定回数検査するソリューションが適切です。 (O(n^2m^2)) などの 2 次のセル数は大きすぎ、明示的にルートを列挙することは完全に不可能です。 

[
 \binom{n+m-2}{n-1}。 
]

 (n=m=3000) の場合、これはおよそ (10^{1803}) ルートになります。 ルートごとに 1 ビットの情報を書き出すことさえ、すでに実行不可能です。 

表面的に合理的な条件が間違った答えを与える、いくつかの特殊なケースがあります。 まず、1 つの (2\times2) 正方形には、同じ文字列を生成する 2 つのルートを持つことができますが、3 つのルートは存在できません。```
2 2
aa
aa
```正しい答えは、`NO`。 2 つの異なるルートが同じ文字列を持つことができるかどうかだけをチェックする不注意な解決策では、誤って出力されてしまいます。`YES`。 

2 番目のエッジ ケースは、2 つの有用なローカル構成が同じ行に存在するが、複数の列で分離されている場合です。```
2 4
abca
bday
```良好なセルは、1 から始まる座標を使用して、最初の行の列 1 と列 3 にあります。 これらは隣接していないため、3 つの等しいルートは得られません。 答えは、`NO`。 同じ行にある 2 つの正常なセルを十分なものとして扱うのは間違いです。 

2 つの隣接する良好なセルには 3 つのルートが与えられます。 例えば、```
2 3
aba
bab
```3 つの異なるルートがあり、すべて生産されています`abab`、したがって、答えは次のとおりです`YES`。 

同じ現象が垂直方向にも発生します。```
3 2
ab
ba
ab
```ここでも生産ルートは 3 つあります。`abab`、したがって、答えは次のとおりです`YES`。 

## アプローチ

 直接的なアプローチでは、すべての単調ルートを列挙し、その文字列を構築し、各文字列が出現する回数をカウントします。 これは正しいです。すべてのルートが考慮され、同じ文字列を生成するルートがグループ化されるからです。 問題は路線数です。 それらは (\binom{n+m-2}{n-1}) 個あり、各文字列の構築には (O(n+m)) かかります。 

[
 O\left((n+m)\binom{n+m-2}{n-1}\right)
 ]

 時間。 (3000\times3000) グリッドの場合、これは (10^{1807}) 文字の操作に相当するため、このアプローチは単に遅すぎるだけでなく、根本的に使用できません。 

有益な観察は、2 つの単調ルートが局所的に異なるのは、右移動の後に下降移動を行う場合と、下移動の後に右移動を行う場合を交換するだけであるということです。 セル ((r,c)) について考えてみましょう。 ローカルな可能性としては 2 つあります。 

[
 (r,c)\rightarrow(r,c+1)\rightarrow(r+1,c+1)
 ]

 そして

 [
 (r,c)\rightarrow(r+1,c)\rightarrow(r+1,c+1)。 
]

 最初と最後のセルは共有されます。 2 つのルートで同じ部分文字列を生成するには、中央の 2 つのセルに同じ文字が含まれている必要があります。 したがって、セル ((r,c)) を次の場合に良好であると定義します。 

[
 グリッド[r][c+1]=グリッド[r+1][c]。 
]

 良好なセルは、生成された文字列を変更しないローカル スワップを表します。 

驚くべきことに、3 つの等しいルートは、良好なセルの 2 つの特定の配置を通じてのみ存在できるということです。 最初の配置は、2 つの正常なセル ((r_1,c_1)) と ((r_2,c_2)) で構成されます。 

[
 r_1<r_2、\qquad c_1<c_2。 
]

 これらは厳密に互いに南東にあるため、2 つのローカル スワップは独立して実行できます。 両方のマス目を通過するルートから始めて、どちらのスワップも選択しない、最初のマス目のみ、2 番目のみ、または両方を選択できます。 これにより、同じ文字列を持つ少なくとも 3 つの異なるルートが得られます。 

2 番目の配置は、2 つの隣接する正常なセルで構成されます。 それらは水平方向に隣接しているか、

 [
 (r,c),\ (r,c+1),
 ]

 または垂直方向に隣接して、

 [
 (r,c)、\ (r+1,c)。 
]

 2 つの正方形は接触しているため、結合された領域を通る 3 つの可能な方法により、同じ文字列を持つ 3 つの異なるルートがすでに得られます。 

その逆が重要な構造補題です。 3 つのルートが同じ文字列を生成する場合は、グリッドの各対角線で上から下に順序付けします。 共通のプレフィックスとサフィックスを圧縮します。 3 つの異なるルートの選択肢が残る最初の領域には、両方の座標で厳密に分離された 2 つの独立したローカル スワップ、または 1 つのサイドを共有する 2 つのスワップが含まれている必要があります。 3 つのルートすべての対応する位置のラベルが一致するため、必要なローカル スワップはすべて良好なセルになります。 したがって、上記の 2 つの構成のいずれかが発生する必要があります。 公式社説にはまさにこの特徴が述べられています。 

これにより、元のパスの問題が、一連の良好なセルに関する幾何学的な問題に縮小されます。 隣接するペア、または厳密に増加する行と列のペアを検出する必要があります。 

厳密な南東の場合は、行を上から下にスキャンします。 すべての行について、正常なセルが含まれる最小列と最大列を見つけます。 現在の行の列 (c) に良好なセルがあり、前の行の小さい列に良好なセルがあった場合、最初の構成になります。 前の行にあるすべての正常なセルの中で最小の列を覚えておくだけで十分です。 現在の行の最大の良好な列がその最小値よりも大きい場合、必要なペアが存在します。 

残りの課題は、Python でグッドセルの計算を迅速に実行することです。 グリッドには最大 900 万個のセルがあるため、すべての文字に対するネストされた Python ループは、1 秒の制限の下では不必要にコストがかかる可能性があります。 グリッド文字ごとに 1 バイトを使用して、各行を Python 整数にパックできます。 連続する 2 つの行 (A) と (B) の場合、位置 (c) のバイトは

 [
 (A\mathbin{>>}8)\mathbin{\mathsf{XOR}}B
 ]

 (A[c+1]=B[c]) の場合、 は正確にゼロになります。これはまさに良好なセルの定義です。 Python は、最適化されたネイティブ コードでこれらの大きな整数の演算を実行します。 

標準のゼロバイト検出式、

 [
 (x-L)\ &\ \sim x\ &\ H、
 ]

ここで、(L) はすべての位置にバイト値 (1) を含み、(H) はすべての位置にバイト値 (128) を含み、設定バイトが (x) のゼロバイトに対応するビットマスクを与えます。 これにより、1 つの行ペアのすべての正常なセルを一度に見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((n+m)\binom{n+m-2}{n-1})) | グリッド次元の指数 | 遅すぎる |
 | 最適 | (O(nm)) | (O(m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドの最初の行を読み取り、その文字を 1 つの Python 整数にパックします。 良好なセルは連続する 2 つの行によって決定されるため、前の行のみが必要です。 
2. 次の行ごとに、それを整数にパックし、(x=(previous>>8)\mathbin{\mathsf{XOR}}current) を計算します。 (x) のバイト (c) は、前の行の列 (c+1) の文字と現在の行の列 (c) の文字を比較します。 
3. (x) のゼロバイトを抽出します。 このような各バイトは 1 つの正常なセルを表します。 結果のビット マスクから、現在の行ペアの最初と最後の正常な列を取得します。 
4. 現在の良好なマスクが以前の良好なマスクと交差するかどうかを確認します。 存在する場合、垂直方向に隣接する正常なセルが 2 つあり、これが 2 番目の構成であるため、答えは次のようになります。`YES`。 
5. 現在の良好なマスクに 1 列離れた 2 つの位置が含まれているかどうかを確認します。 これは次によって検出されます`good & (good >> 8)`。 このようなペアは水平方向に隣接しており、2 番目の構成も得られます。 
6. 前の行の列に正常なセルが含まれている場合`p`、現在の行には、より大きい列に正常なセルが含まれています。`p`、2 つのセルは厳密に互いに南東にあります。 以前のすべての行で確認された最小の良好な列を保持するため、テストは単純に行われます。`current_max > minimum_previous`。 
7. 現在の行ペアのすべてのチェックが完了したら、グローバル最小良好列を更新し、次の反復のために現在の良好なマスクを記憶します。 完全なスキャン後に構成が見つからなかった場合は、次のように印刷します。`NO`。 

不変条件は、行ペアを処理する前に、`minimum_previous`すでに処理されたすべての正常なセル行内の正常なセルの最小の列です。 したがって、それを現在の行の最大の良好な列と比較することは、厳密な南東のペアが存在するかどうかを尋ねることとまったく同じです。 同時に、`previous_good`は、直前の行の正常なセルを正確に表すため、現在のマスクとの交差により、垂直方向に隣接するすべてのペアが検出されます。 現在のマスク内のシフトされた交差により、水平方向に隣接するすべてのペアが検出されます。 上記の構造的特徴は、これらがまさに 3 つの等しいルートを生成する可能性がある状況であることを示しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    prev = input().strip().encode()
    prev_value = int.from_bytes(prev, 'little')

    # One byte with value 1 in every position.
    low = ((1 << (8 * m)) - 1) // 255

    # One byte with the high bit set in every position.
    high = low << 7

    # We only care about the first m - 1 bytes, corresponding to
    # columns 0 .. m - 2.
    valid = (((1 << (8 * (m - 1))) - 1) // 255) << 7

    previous_good = 0
    minimum_previous = None

    for _ in range(n - 1):
        cur = input().strip().encode()
        cur_value = int.from_bytes(cur, 'little')

        # Byte c compares prev[c + 1] with cur[c].
        x = (prev_value >> 8) ^ cur_value

        # A set bit in byte c means x's byte c is zero, hence
        # prev[c + 1] == cur[c].
        good = (x - low) & ~x & high & valid

        if good:
            # Two vertically adjacent good cells.
            if good & previous_good:
                print("YES")
                return

            # Two horizontally adjacent good cells.
            if good & (good >> 8):
                print("YES")
                return

            # Strict southeast pair.
            first = ((good & -good).bit_length() - 1) >> 3
            last = (good.bit_length() - 1) >> 3

            if minimum_previous is not None and last > minimum_previous:
                print("YES")
                return

            if minimum_previous is None or first < minimum_previous:
                minimum_previous = first

        previous_good = good
        prev_value = cur_value

    print("NO")

if __name__ == "__main__":
    solve()
```入力は一度に 1 行ずつ処理されるため、アルゴリズムがグリッド全体を保存する必要はありません。`prev_value`そして`cur_value`行がパックされたバイト シーケンスとして含まれます。 パイソンの`int.from_bytes`は元の文字値を保持するため、対応するバイトの XOR 演算はまさに文字の等価性テストになります。 

8 ビットによるシフトは、インデックス付けの中心的な詳細です。 後`prev_value >> 8`、バイト 0 には元の列 1 が含まれ、バイト 1 には元の列 2 が含まれます。 これを現在の行と XOR すると整列します`previous[c+1]`と`current[c]`。 

ゼロバイト式には注意が必要です。 による引き算`low`標準のゼロバイト検出 ID がすべてのゼロバイトの上位ビットをマークできるように、独立して実行されます。 の`valid`マスクは最後のバイトを削除します。`m-1`は右側にセルがないため、正常なセルの左側になることはできません。 

最初に設定されたビット`good`は最小の良好な列を与え、最後に設定されたビットは最大の列を与えます。 関連するすべてのビットはバイトの上位ビットであるため、そのビット インデックスを 8 で割ると列インデックスが回復されます。 

水平隣接テストでは、マスクが 1 バイトずつシフトされます。 列 (c) と列 (c+1) の両方が良好な場合、対応するビットの 1 つが交差部分でも残ります。 両方のマスクが正常なセル列を表すため、垂直テストでは前の行のマスクが直接使用されます。 

Python では整数オーバーフローの懸念はありません。 パックされた行は最大 3000 バイトなので、最大の整数は約 24,000 ビットしかありません。 

## 実用的な例

 サンプル 1 では、行 0、列 1 の文字が`e`、行 1、列 0 に一致します。次のペアには、列 1 と 2 に正常なセルが含まれています。現在の最大の列は 2 ですが、前の行の最小の正常な列は 0 であるため、厳密な南東構成がすぐに見つかります。 

| 行ペア | 良いコラム | 以前の最小値 | 前のマスクのオーバーラップ | 結果 |
 | --- | --- | --- | --- | --- |
 | 行 0、1 | 0 | なし | なし | 続ける |
 | 行 1、2 | 1、2 | 0 | なし | (2>0)、はい |

 2 つの良好なセルは、`(0,0)`そして`(1,1)`厳密には互いに南東にあります。 ローカル スワップは独立して選択でき、同じノート シーケンスを持つ複数のルートを提供します。 したがって、アルゴリズムはグリッドの残りの部分をスキャンせずに停止します。 

サンプル 2 では、隣接するすべての行ペアで良好なセルが生成されません。 たとえば、最初の 2 行の間には、`b`と比較されます`f`、`c`と`g`、`d`と`h`、 等々。 同じ不一致パターンが行のすべてのペアで継続します。 

| 行ペア | 良いコラム | 以前の最小値 | 前のマスクのオーバーラップ | 結果 |
 | --- | --- | --- | --- | --- |
 | 行 0、1 | なし | なし | なし | 続ける |
 | 行 1、2 | なし | なし | なし | 続ける |
 | 行 2、3 | なし | なし | なし | 続ける |
 | 行 3、4 | なし | なし | なし | 続ける |

 正常なセルがまったく存在しないため、3 つの検出メカニズムはいずれも成功しません。 最終的な答えは、`NO`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nm)) | 隣接する行のすべてのペアがパックされて 1 回比較され、パックされた操作で (O(m)) ビットが処理されます。 |
 | スペース | (O(m)) | 2 つのパックされた行と一定数のマスクのみが維持されます。 |

 グリッドには最大 900 万文字が含まれます。 このアルゴリズムは、(n-1) 行ペアごとに (O(m)) バイトを含む整数に対して一定数の演算を実行し、標準複雑度モデルでの合計作業量は (O(nm)) になります。 メモリ使用量は行幅に線形であり、512 MB の制限をはるかに下回っています。

## 特殊なケース

 最小 (2\times2) グリッドの場合```
2 2
aa
aa
```正常なセルが 1 つあり、`(0,0)`、右と下のセルは両方とも`a`。 このアルゴリズムは、列 0 を含む 1 つの良好なマスクを作成しますが、同じ行または列に前の良好な行や 2 番目の良好なセルはありません。 印刷します`NO`これは、(2\times2) グリッドに 2 つの単調ルートがあることを正しく反映しています。 

水平方向に隣接する良好なセルの場合、```
2 3
aba
bab
```最初の行のペアには適切な列 0 と 1 があります。そのマスクには 2 つの隣接するセット バイトがあるため、`good & (good >> 8)`ゼロ以外です。 アルゴリズムはすぐに出力します`YES`。 3 つのルートは、最初の列の前、2 つの列の間、またはそれらの後の下への移動に対応しており、すべての結果が生成されます。`abab`。 

垂直に隣接する良好なセルの場合、```
3 2
ab
ba
ab
```最初の行のペアには列 0 に良好なセルがあり、2 番目の行のペアには列 0 に別の良好なセルがあります。それらのマスクは交差しているため、`good & previous_good`2 番目のペアが処理されるときは 0 以外になります。 アルゴリズムは出力します`YES`。 

厳密に南東にある 2 つの良好なセルの場合、```
4 4
xayz
aqrs
tuxb
vwby
```良い細胞は`(0,0)`そして`(2,2)`。 隣接する良好なセルがないため、2 つのローカル隣接テストはトリガーされません。 最初の行ペアの後、`minimum_previous`を含む行ペアが 0 になるとき`(2,2)`が処理され、その最大の良好な列は 2 であり、`2 > 0`、したがって、厳密な南東テストは成功します。 これは、グローバル最小列だけで最初の構成を検出できる理由を示しています。 

同じ行内の隣接していない正常なセルの場合、```
2 4
abca
bday
```適切な列は 0 と 2 です。これらは 1 列で区切られているため、水平隣接性テストは 0 です。 厳密な南東ペアを形成できる良好なセルの前の行はなく、良好なセルを含む行は 1 つだけです。 アルゴリズムは出力します`NO`。 これは、有効なローカル構成と、魅力的ではあるが誤った一般化との間の境界です。 

最大サイズのすべてが等しいグリッドの場合、可能なすべてのセルが適切です。 最初の行のペアにはすべての列に正常なセルが含まれており、2 番目の行のペアにも含まれています。 アルゴリズムは 2 番目のペアを処理するとすぐに厳密な南東構成を検出するため、次の値を返します。`YES`余計な仕事をせずに。
