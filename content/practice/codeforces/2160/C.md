 ## 問題の理解

 ターゲットの整数が与えられます$n$、そして、何らかの正の整数を構築できるかどうかを知りたいのです。$x$特定の変換が適用されるように、$x$XOR と組み合わせると正確に生成されます$n$。 

変革$f(x)$のバイナリ表現を受け取ります$x$、ビット順序を反転し、結果を新しい 2 進数として解釈します。 重要なのは、反転後の先頭のゼロは無視されることです。これは、結果の有効ビット長が、反転された文字列内の最も高い設定ビットに依存することを意味します。 

プロセスは次のとおりです: 番号を選択します$x$、バイナリで書き込み、それらのビットを反転して、新しい整数を形成します$f(x)$、どうかを確認してください。$x \oplus f(x) = n$。 

出力は、各テスト ケースに対する単純な「はい/いいえ」の決定です。 

制約$n < 2^{30}$これは、最大 30 ビットの数値についてのみ推論する必要があることを意味します。 任意の有効な$x$また、反転ビットが無制限の検索空間にオーバーフローしないように、問題は十分に小さいビット幅内に収める必要があります。 以下のすべての整数に対する単純な検索$2^{30}$はすでに大きすぎます。$10^9$最悪のシナリオでのテスト ケースごとの候補数を乗算した場合$t = 10^4$。 

さらに微妙な問題は、$f(x)$補数やシフトのような単純なビット演算ではありません。 反転すると、次の最下位ビットが結合されます。$x$の最上位ビットを使用して$f(x)$、局所性を壊します。 このため、対称性を明示的に利用しない限り、ビットに関する貪欲な推論は信頼性が低くなります。 

エッジケースは次の場合に発生します。$x$単一のセットビットまたは非常にまばらな構造を持っています。 例えば、$x = 1$収量$f(x) = 1$なので、XOR はゼロになります。 これは次のことを示しています$n = 0$いつでも可能です。 一方、次のような小さな値は、$n = 8$ビットを反転すると位置の独立性が維持されず、XOR 制約がビット文字列全体にわたってグローバルに不一致になるため、多くの表現があるにもかかわらず失敗します。 

## アプローチ

 直接総当たりアプローチですべての候補者を試す$x$、計算します$f(x)$、そして次のことをチェックします$x \oplus f(x) = n$。 コンピューティングのコスト$f(x)$のビット長に比例します$x$、それで、それについて$O(\log x)$。 ただし、候補者数は最大$2^{30}$これは完全に不可能になります。 クエリごとにそれらの一部をテストするだけでも、数十億の操作が必要になります。 

重要な構造的観察は、次のようなバイナリ表現であるということです。$x$XOR とその反転によって引き起こされる回文制約の観点から考えると、 は任意ではありません。 それぞれのビット$x$ちょうど 1 つのミラーリングされたビットと対話します$f(x)$。 これは、システムがビット ペアの独立した制約に分解されることを意味しますが、XOR にはキャリーが存在しないため、長さを固定すると各ビット位置を独立して扱うことができます。$x$。 

代わりに、問題をバイナリ文字列の構築として再解釈できます。$s$それを逆にすると、$s^R$、 それから$s \oplus s^R = n$。 これにより、問題は対称ビット ペアの一貫性チェックに変わります。 The only real difficulty is that the length of$s$は不明なので、最大 30 ビットの長さを試します。 各長さについて、両端から内側に向​​かってビットを割り当てようとし、必要な XOR ビットとの一貫性を確保します。$n$。 どの長さでも一貫した割り当てが得られる場合、答えは「YES」です。 

これにより、問題は整数の検索から有限制約システムの実現可能性のチェックまで軽減されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、可能なバイナリの長さを考慮します。$L$1 から 30 まで。アイデアは次のとおりです。$x$30ビット以上は必要ないので、$n$それ自体は有限です。 
2. 固定長の場合$L$、 解釈する$x$として$L$-bit バイナリ文字列$s$。 私たちが欲しいのは$s \oplus reverse(s) = n$、ただし最低のみ$L$のビット$n$案件。 
3. ポジションごとに$i$0から$L-1$、それを位置と組み合わせます$j = L-1-i$。 これら 2 つの位置は、XOR 制約によって相互に決定されます。$$s[i] \oplus s[j] = n[i]$$4. もし$i = j$、つまり奇数長の文字列の中間ビットにいることを意味すると、方程式は次のようになります。$$s[i] \oplus s[i] = 0$$だから私たちは持っている必要があります$n[i] = 0$。 もし$n[i] = 1$、この長さ$L$不可能です。 
5. のために$i < j$、XOR と一致する両方の代入を試します。 

もし$n[i] = 0$、 それから$s[i] = s[j]$、 さもないと$s[i] \neq s[j]$。 割り当てを伝播し、一貫性をチェックします。 
6. すべてのビットを矛盾なく割り当てることに成功し、$x > 0$の場合は、すぐに YES を返します。 
7. 長さが無い場合$L$動作する場合は、「NO」を返します。 

### なぜ効果があるのか

 正確さは、XOR 式をミラーリングされたビット位置に対する独立した制約に縮小することで得られます。 XOR は桁上げ依存関係を削除するため、各ビット方程式はローカルになります。 反転操作はインデックスを並べ替えるだけなので、システム全体が変数のペア間の等価または不等制約のセットになります。 有効な解はすべて、この制約グラフ内の一貫した代入に正確に対応し、すべての一貫した代入は有効な整数を定義します。$x$。 考えられるすべてのビット長がテストされるため、有効な構成が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(n, L):
    bits = [(n >> i) & 1 for i in range(L)]
    s = [-1] * L

    for i in range(L):
        j = L - 1 - i
        if i > j:
            break

        if i == j:
            if bits[i] == 1:
                return False
            if s[i] == -1:
                s[i] = 0
            continue

        if bits[i] == 0:
            # s[i] == s[j]
            for a, b in [(i, j)]:
                if s[a] == -1 and s[b] == -1:
                    s[a], s[b] = 0, 0
                elif s[a] == -1:
                    s[a] = s[b]
                elif s[b] == -1:
                    s[b] = s[a]
                elif s[a] != s[b]:
                    return False
        else:
            # s[i] != s[j]
            if s[i] == -1 and s[j] == -1:
                s[i], s[j] = 0, 1
            elif s[i] == -1:
                s[i] = 1 - s[j]
            elif s[j] == -1:
                s[j] = 1 - s[i]
            elif s[i] == s[j]:
                return False

    if all(v == 0 for v in s):
        return False

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ans = False
        for L in range(1, 31):
            if ok(n, L):
                ans = True
                break
        print("YES" if ans else "NO")

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`ok`固定長の有効なバイナリ文字列を構築しようとする関数$L$。 配列`s`の未知のビットを表します$x$、に初期化されます`-1`未割り当てという意味です。 ミラー化されたペアごとに、対応するビットに応じて等価または不等価のいずれかを強制します。$n$。 ペアの両方のビットが割り当てられていない場合、有効な構成を直接割り当てます。 それ以外の場合は、制約を伝播し、一貫性を検証します。 

中間ビット条件は、次の場合に明示的に処理されます。$i = j$、ビットとそれ自体の XOR は 1 を生成できないためです。最終チェックにより、次のことが保証されます。$x$すべてゼロの代入を拒否することで正になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def ok(n, L):
        bits = [(n >> i) & 1 for i in range(L)]
        s = [-1] * L
        for i in range(L):
            j = L - 1 - i
            if i > j:
                break
            if i == j:
                if bits[i] == 1:
                    return False
                continue
            if bits[i] == 0:
                if s[i] == -1 and s[j] == -1:
                    s[i] = s[j] = 0
                elif s[i] == -1:
                    s[i] = s[j]
                elif s[j] == -1:
                    s[j] = s[i]
                elif s[i] != s[j]:
                    return False
            else:
                if s[i] == -1 and s[j] == -1:
                    s[i], s[j] = 0, 1
                elif s[i] == -1:
                    s[i] = 1 - s[j]
                elif s[j] == -1:
                    s[j] = 1 - s[i]
                elif s[i] == s[j]:

                ok_flag = True

        out.append("YES" if ok_flag else "NO")

 ## 特殊なケース

 のために$n = 0$、任意の回文 2 進数が機能するため、構築は簡単です。 アルゴリズムは次のことを見つけます$L = 1$、割り当てます$s = [0]$と、すぐに承諾します。 

のために$n = 1$、有効な構造が存在します。$x = 1$。 チェックでは、$L = 1$再び単一の中間ビットが生成されます。これは次の場合にのみ有効です。$n[i] = 0$したがって、代わりにアルゴリズムは次のように移行します。$L = 2$そして一貫した非対称割り当てを見つけます。
