 ## 解決策
 ## 問題の理解

 整数のマルチセットが与えられ、元の要素がすべて全体でまったく同じ回数使用されるように、それをいくつかの小さなマルチセットに分割することができます。 言い換えれば、出現する数値をグループに分割しているということです。 

各グループについて、そのグループに欠落している最小の非負の整数である MEX を計算できます。 すべてのグループがまったく同じ MEX 値を持つ場合、パーティションは有効であると呼ばれます。 その共有値がパーティションのスコアになります。 タスクは、このスコアをできるだけ小さくするパーティションを選択することです。 

この問題がわかりにくいのは、1 つのセットを選択してその MEX を直接計算していないことです。 番号のコピーを複数のグループに配布し、すべてのグループが同じ最初の欠落番号で「失敗」するように強制しています。 

制約は小さいです。各テストには最大 100 個の要素があり、値も 100 で制限されます。これにより、分布または分割に対する指数関数的な影響が即座に排除されます。 値の頻度に関する二次推論も安全ですが、パーティションを明示的に列挙するものは不要であり、やりすぎです。 

配列全体またはそれに近いものの MEX を計算すればよいと考えるのは単純な間違いです。 分割によって達成可能なスコアが増減する可能性があるため、これは失敗します。 もう 1 つの間違いは、最善の戦略は常にグループ サイズを最大化することであると考えていることですが、MEX は合計やサイズではなく、0 から始まるすべての数値の存在に依存します。 

具体的なエッジケースは、数値が 1 つだけ存在する場合です。 例えば、`[0, 0, 0]`。 すべてを 1 つのグループに入れると、MEX は 1 になります。しかし、3 つのグループに分割すると、`{0},{0},{0}`、各グループにはまだ MEX 1 があるため、スコアは 1 です。不注意な解決策では、分割によって MEX が予期せず変更されると考えられるかもしれませんが、ここでは構造が保持されます。 

もう 1 つのエッジ ケースは、0 が完全に欠落している場合です。 例えば`[1,2]`。 どのグループも即座に MEX 0 を持つため、分割に関係なく答えは強制的に 0 になります。 MEX がより高い値に依存すると仮定すると、これは見落とされがちです。 

## アプローチ

 ブルート フォース アプローチでは、オカレンスを複数のグループに分散するあらゆる方法を試し、すべてのグループが同じ MEX を共有するかどうかを計算します。 これにはパーティション分割が含まれます`n`要素を任意のサブセットに分割し、指数関数的よりも速く増加します。 たとえ`n = 100`、これはまったく不可能です。 

重要な観察は、スコアはセットの完全なコピーの数によって完全に決定されるということです。`{0, 1, 2, ..., x-1}`グループを超えて結成することもできます。 グループに MEX を持たせたい場合`x`、次に、からのすべての数値`0`に`x-1`そのグループに少なくとも 1 回は出現する必要がありますが、`x`が欠けているはずです。 

すべてのグループが同じ MEX を持つ有効なパーティションを実現するには`x`、各グループは、すべての数値の少なくとも 1 つの出現を消費します。`0..x-1`。 したがって、次のように表すと、`freq[i]`値の周波数として`i`、形成できるそのようなグループの数は、グループ内の最小頻度によって制限されます。`0..x-1`。 

それを最小限にしましょう`k`。 せいぜい形成できます`k`各番号のコピーを 1 つずつ含むグループ`0..x-1`。 残りのすべての要素 (余分なコピーを含む) は、MEX に影響を与えることなくどこにでも配置できます。`x`どのグループにも表示されません。 

有効な構築のためには、少なくとも次のものが必要です。`k`また、次のことを確認する必要があります。`x`すべてのグループに偶然現れることはありません。 重要な制約は、一部のユーザーに対して次のことを保証しなければならないということです。`x`の場合、構造は実行可能であり、そのような値が可能な限り最小になります。 

これは、候補となる MEX ごとにチェックすることになります。`x`、すべての数字かどうか`0..x-1`少なくとも一度は存在します。 どれかが欠けていると、MEX ≥ x の有効なグループを 1 つも形成できません。 したがって、最小の`x`これがどこで失敗するか制約されるかによって、答えが決まります。 

パーティションを構築する代わりに、すべてのグループにわたってより高い MEX を維持することが不可能になる時期について直接推論します。 答えは、頻度が低下しすぎてグループ全体で繰り返しカバレッジをサポートできない最初の指標になります。

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての値の頻度を数えます。 

これにより、各番号のコピーをグループ全体に何部配布できるかにすぐにアクセスできるようになります。 
2. 候補 MEX 値を 0 から順にチェックし始めます。 

私たちは事実上、すべてのグループに少なくとも MEX を持たせることを強制できないか、と尋ねているのです。`x`?
 3.固定の場合`x`、からのすべての数値かどうかを確認します。`0`に`x-1`少なくとも 1 回は表示されます。 

どれかが欠落している場合、どのグループにも必要な要素をすべて含めることができないため、MEX は到達できません。`x`。 
4. 最大のものを追跡する`x`すべての数字が`0..x-1`存在する。 

これは、連続する整数の接頭辞が途切れるポイントです。 
5. 答えは、まさにこの達成可能な最大のプレフィックス長です。 

この点を超えると、すべてのグループにわたって MEX を一貫して増加させることはできません。 

### なぜ効果があるのか

 同じ MEX を持つ各グループには、共有の構造要件が強制されます。すべてのグループには、その MEX より下のすべての番号が含まれている必要があります。 これにより、問題は、数値のセットが 0 から開始してどこまで「プレフィックス完全」であるかをチェックすることになります。数値がグローバルに欠落しているということは、どのグループでも条件を満たすことが不可能であることを意味するため、分割の自由度によってこの要件は変更されません。 したがって、答えは、マルチセット内に存在する 0 から始まる最長の連続プレフィックスのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * 105
        for x in a:
            freq[x] += 1
        
        mex = 0
        while freq[mex] > 0:
            mex += 1
        
        print(mex)

if __name__ == "__main__":
    solve()
```周波数配列は、0 から始まる最初の欠落した整数を検出するためにのみ使用されます。ループはインクリメントします。`mex`ゼロ周波数の値が見つかるまで、これはまさにマルチセットの MEX の定義です。 

重要な実装の詳細は、パーティションのシミュレーションをまったく試みないことです。 この解決策は、分割によって値がマルチセットに存在するかどうかが変わらないため、実現可能性を決定するプレフィックス条件に影響を与えないという観察に完全に依存しています。

## 特殊なケース

 のような入力の場合`[0]`、周波数チェックでは次のようになります。`freq[0] > 0`そしてに移動します`1`、 どこ`freq[1] = 0`。 アルゴリズムの出力`1`これは、どのパーティション (1 つのグループのみも可能) に MEX 1 があるという事実と一致します。 

のような入力の場合`[2,3,4]`、ループは次の時点ですぐに失敗します。`mex = 0`、 以来`0`は不在です。 これにより出力が生成されます`0`また、グループに 0 を含めることはできないため、すべてのパーティションにも MEX 0 が必要です。 

のために`[0,1,1,2,2]`、ループは次のように進みます。`0,1,2`しかし、そこで止まります`3`。 これにより、重複は問題ではなく、各整数が少なくとも 1 回出現するかどうかだけが問題であることが確認されます。
