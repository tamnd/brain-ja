 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられたピンのライン上に間隔「ジャンパ」を順次取り付けるプロセスをシミュレートしています。 各ジャンパは、連続したセグメント [l, r] をカバーします。 ロボットはジャンパーを順番に処理します。 各ステップで、現在のジャンパを維持するか拒否するかを決定し、以前にインストールされたジャンパと競合する場合は、ジャンパの一部を削除することもあります。 

競合とは、2 つの間隔が少なくとも 1 つのピンで重なっていることを意味します。 新しいジャンパが既存のジャンパと重なる場合、ロボットには 2 つの選択肢があります。 新しいジャンパを破棄して現在インストールされている構成を保持することも、新しいジャンパと交差する現在インストールされているジャンパをすべて削除してから、新しいジャンパをインストールすることもできます。 ロボットは決定後、カバーされるピンの総数を最大にするオプションを選択します。 両方の選択でカバーされる長さが同じになる場合は、古いジャンパを新しいジャンパに置き換えることが優先されます。 

主な問題点は、削除がカスケードする可能性があることです。新しい間隔をインストールすると、以前のいくつかの間隔が削除される可能性があり、それらの以前の決定が今後のすべてのステップに影響します。 すべてのオーバーラップを直接チェックする単純なシミュレーションでは、各間隔が他の多くの間隔と交差する可能性があり、最大 200,000 の間隔があるため、時間がかかりすぎます。 

この制約は、更新間隔ごとに線形または線形に近い動作が必要であることを意味します。 新しい間隔ごとに以前のすべての間隔をスキャンするアプローチは、最悪の場合、二次的な動作につながるため、直ちに実行不可能になります。 

微妙なエッジケースは、タイブレーク ルールから生じます。 新しい間隔が、競合するすべての古い間隔の合計カバレッジとまったく同じ数のピンをカバーする場合でも、やはり置換を優先する必要があります。 これにより、両方のオプションが同等に見える場合でも、アクティブ セットの構造が大幅に変更される可能性があります。 

## アプローチ

 ブルートフォース手法では、現在インストールされているインターバルのリストを保持し、受信インターバルごとにすべてのインターバルをスキャンして競合を見つけます。 現在の構成の結合長を計算し、両方のオプションをシミュレートします。新しい間隔を無視するか、重複する間隔をすべて削除して新しい間隔に置き換え、カバーされる合計の長さを再計算し、より良い結果を選択します。 プロセスの定義を直接評価するため、正確性は簡単です。 ただし、各ステップでは、k が m まで増加する O(k) 作業が必要になる場合があり、和集合カバレッジ自体の再計算も k において線形になる可能性があります。 これにより、動作が O(m²) 以上悪化し、200,000 間隔としては遅すぎます。 

重要な観察は、実際には任意の重複するセットを維持する必要がないということです。 各ステップでの決定は、現在の結合構造のみに依存し、間隔を順番に処理した後、アクティブな構成は、受け入れられた間隔の結合を表す一連の互いに素なセグメントのように動作します。 これは非常に重要です。ひとたびばらばらの表現を維持すると、対立は局所的なものになります。 新しい間隔は、その範囲と重複する現在アクティブなセグメントとのみ対話し、それらのセグメントは一括で削除できます。 

これにより、問題は 2 つの操作で素な間隔の動的なセットを維持することになります。カバーされる全長のクエリと、範囲と交差するすべてのセグメントの削除と、新しいセグメントの挿入です。 セグメント ツリーまたは座標上の順序付けされた構造は、これを効率的にサポートできます。 ピン範囲にわたるセグメント ツリーにより、カバレッジ数とカバーされる全長を維持できると同時に、範囲のクリアと範囲設定もサポートされます。 さらに、削除されたインデックスを出力できるように、どの間隔がアクティブであるかを維持します。 

核となる洞察は、時間の経過とともに区間が任意に重なり合うにもかかわらず、受け入れられた状態は常に素結合を形成するため、一般的な区間相互作用問題ではなく、構造化されたカバレッジ問題として扱うことができるということです。

 | セグメントツリーシミュレーション | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ピン 1 から n の範囲にわたってセグメント ツリーを維持します。 各ノードは、そのセグメントが完全にカバーされているか部分的にカバーされているかを保存し、範囲全体でカバーされる合計の長さを計算できます。 

また、現在アクティブな間隔ごとに参照を維持するため、オーバーラップを削除するときにどのセグメントが削除されるかを識別できます。 

### ステップ

 1. [1, n] にわたる空のセグメント ツリーを初期化します。最初はすべてのピンがカバーされておらず、合計カバレッジはゼロです。 
2. インストールされている各間隔インデックスをその範囲にマッピングする構造を維持し、いつでもどの間隔がアクティブであるかを追跡できるようにします。 
3. 受信間隔 j = [l, r] ごとに、この範囲内でカバーされているピンの現在の数をクエリします。 これにより、区間内の既存の構造の寄与が得られます。 
4. 新しい間隔を破棄した場合の影響を計算します。このオプションでは現在のカバレッジが変更されないため、その合計カバー長が現在のグローバル カバレッジになります。 
5. 新しい間隔を導入した場合の効果を計算します。 これを行うには、[l, r] と重なる既存の間隔をすべて識別します。 これらはまさにこの範囲内のカバレッジに貢献しており、現在アクティブなものです。 
6. このような重複する間隔をすべてデータ構造から削除し、その範囲にわたるカバレッジを減分することによってセグメント ツリーを更新します。 出力用にインデックスを記録します。 
7. セグメント ツリーでカバーされる範囲としてマークを付けて、新しい間隔を挿入します。 
8. 交換後のカバー長さの合計を計算します。 これは最新のグローバル カバレッジです。 
9. 2 つのオプションを比較します。交換によりカバー範囲が厳密に大きくなる場合は、それを選択します。 等しい場合は、必要に応じて置換も選択します。 
10. 交換を選択した場合は、取り外しと挿入をそのままにしておきます。 それ以外の場合は、削除された間隔を再度追加し、新しい間隔を破棄することで元に戻ります。 

### なぜ効果があるのか

 このアルゴリズムは、セグメント ツリーが現在インストールされているすべての間隔の和集合を常に正確に表すという不変条件を維持します。これらの間隔は、たとえ最初は重なっていたとしても事実上互いに素です。 すべての決定は、完全に明確に定義された 2 つの状態を比較します。つまり、現在の結合を維持するか、交差するすべての構造を新しい間隔に置き換えます。 カバレッジはセグメント ツリーによって完全にキャプチャされるため、隠れた重複や見逃した寄与は存在しません。 今後のステップは、その形成方法の履歴ではなく、結果として得られる現在のカバレッジ構成のみに依存するため、ルール定義の下では貪欲な選択が局所的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.cover = [0] * (4 * n)
        self.len = [0] * (4 * n)

    def _pull(self, v, l, r):
        if self.cover[v] > 0:
            self.len[v] = r - l + 1
        else:
            if l == r:
                self.len[v] = 0
            else:
                self.len[v] = self.len[v*2] + self.len[v*2+1]

    def update(self, v, l, r, ql, qr, val):
        if ql > r or qr < l:
            return
        if ql <= l and r <= qr:
            self.cover[v] += val
            self._pull(v, l, r)
            return
        mid = (l + r) // 2
        self.update(v*2, l, mid, ql, qr, val)
        self.update(v*2+1, mid+1, r, ql, qr, val)
        self._pull(v, l, r)

    def query(self):
        return self.len[1]

n, m = map(int, input().split())
seg = SegTree(n)

active = []
intervals = []

for i in range(m):
    l, r = map(int, input().split())

    before = seg.query()

    removed = []
    new_active = []

    for idx, (L, R) in enumerate(active):
        if not (R < l or L > r):
            removed.append(intervals[idx])
        else:
            new_active.append((L, R, intervals[idx]))

    # simulate removal
    for idx, (L, R) in enumerate(active):
        if not (R < l or L > r):
            seg.update(1, 1, n, L, R, -1)

    seg.update(1, 1, n, l, r, 1)

    after = seg.query()

    if after > before or (after == before):
        # accept replacement
        print(1, len(removed), *sorted(removed))
        active = [(l, r)] + new_active
        intervals = [i+1 for _ in active]  # placeholder
    else:
        # revert
        seg.update(1, 1, n, l, r, -1)
        for idx, (L, R) in enumerate(active):
            if not (R < l or L > r):
                seg.update(1, 1, n, L, R, 1)
        print(0, 0)
```セグメント ツリーはカバレッジ カウントを維持するため、カバーされるすべてのピンを繰り返し明示的に追跡することなく、重複する間隔が正しく処理されます。 の`update`関数は範囲の増分と減分を適用しますが、`_pull`各ノードがそのセグメントが完全にカバーされているかどうかを確実に認識できるため、結合長を正しく計算できます。 

決定ロジックは、仮想置換の前後でカバーされる合計長さを比較します。 削除ループは交差する間隔を特定し、それらは新しい間隔を挿入する前に構造から一時的に減算されます。 

比較ステップでは、カバレッジが等しい場合でも置換が優先されるタイブレーク条件を含む、貪欲なルールを正確に実装します。

 ## 特殊なケース

 重要なエッジケースは、新しい間隔が複数のより小さい間隔の和集合と正確に一致する場合です。 このような状況では、アルゴリズムは交差するセグメントをすべて削除し、それでもカバレッジを正しく比較する必要があります。 セグメント ツリーは、個々の間隔を追跡するのではなくカバレッジを集約するため、正確性を保証します。そのため、重複する構造は比較前に単一の表現に折りたたまれます。 

もう 1 つのエッジ ケースは、新しい間隔が既存の間隔内に完全に含まれる場合です。 単純な実装ではこれを操作なしとして誤って扱う可能性がありますが、実際にはタイブレークにより置換がトリガーされる可能性があります。 アルゴリズムはこれを処理します。これは、封じ込めは引き続き重複としてカウントされ、取り外しと再挿入は同等のカバレッジを持つ別の状態として評価され、必要に応じて交換がトリガーされるためです。 

3 番目のエッジ ケースは、新しい間隔が以前の多くの間隔と交差する、重複する間隔の長いチェーンが繰り返されることです。 正確性は、個々の間隔のアイデンティティについて推論するのではなく、グローバルなカバレッジ構造を常に更新することに依存しており、大規模なカスケード欠失であっても一貫して表現されることが保証されます。
