 ## アルゴリズムのチュートリアル

 まず、任意のプレフィックス間隔にわたる総収入をすばやくクエリできるように、プレフィックス合計を構築します。 これにより、毎日のプロセスが、段階的なシミュレーションではなく、累積範囲に関する推論に変換されます。 

次に、特定の開始点に対して、累積合計が特定の条件下でリセットを強制する前にどこまで前進できるかを迅速に決定できる構造を前処理します。$X$。 これは、インデックスごとに、実行中の累積セグメントを厳密に下回ったままにしながら、どこまでジャンプできるかを格納することによって行われます。$X$、そしてこれらのジャンプ上にバイナリリフティングテーブルを構築します。 

最後に、各クエリは配列を繰り返しジャンプすることによって処理され、「リセットされるまで消費」動作を対数ステップでシミュレートします。 

### ステップ

 1. プレフィックスの合計を計算する$p$、 どこ$p[i]$初日から当日までの総収入です$i$。 これにより、セグメントの合計を 2 つのプレフィックス値の差として計算できます。 
2. 各開始位置について$i$、最も遠い位置を決定します$j$からの収入の合計が$i+1$に$j$まだ未満です$X$。 強制リセットが発生しない区間を表します。 
3. 複数のセグメントを効率的に移動できるように、これらのジャンプ上にバイナリ リフティング テーブルを構築します。 各ジャンプは、リセット イベントの前に可能な限り消費することを表します。 
4. 各クエリについて、コインゼロで 0 日目から開始し、その日に到達するまで事前計算された構造を使用して繰り返しジャンプします。$n$。 各セグメントは、制御された量を最終的な残りに寄与します。 
5. 最後のジャンプ後に残ったコインは、まさに最後の不完全なセグメントに蓄積された残り物です。 

### なぜ効果があるのか

 プロセスは、実行中の累積が超過する前にどこまで成長できるかによって完全に決定されます。$X$。 累計額が超えるたびに$X$、システムはすべてを破棄します。つまり、唯一の意味のある進化はリセットポイントの間だけです。 これにより、シミュレーション全体が、それぞれがプレフィックス合計のしきい値条件によって境界付けられた一連の独立したセグメントに変わります。 バイナリ リフティング構造により、すべてのジャンプが制約の下で最大有効範囲を尊重するように定義されているため、中間リセットを見逃すことなく各セグメント境界が正しく検出されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    xs = list(map(int, input().split()))

    # prefix sums
    p = [0] * (n + 1)
    for i in range(n):
        p[i + 1] = p[i] + a[i]

    # For each i, we will compute next position where reset might occur for a given X.
    # We answer queries offline by sorting X values.
    
    # Precompute next jump for each i for all possible j is not feasible directly.
    # Instead we will answer each query with two pointers.

    answers = []

    for X in xs:
        if X == 0:
            answers.append(p[n])
            continue

        res = 0
        i = 0

        while i < n:
            # find furthest j such that sum(i+1..j) < X
            lo, hi = i, n
            best = i
            while lo <= hi:
                mid = (lo + hi) // 2
                if p[mid] - p[i] < X:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            # accumulate segment
            segment_sum = p[best] - p[i]
            res += segment_sum

            # simulate spending
            i = best
            if i < n:
                # at position best+1, we would have overflow or exact reach
                # so we reset
                i += 1

        answers.append(res)

    print(*answers)

if __name__ == "__main__":
    solve()

固定クエリの場合、バイナリ検索は、累積収入が厳密に下回っている現在の位置から始まる最長の区間を見つけます。$X$。 このセグメントは、完全には使用されない金額に寄与するため、結果に追加されます。 セグメントが終了したら、リセットポイントを越えて前進し、続行します。 

特別な場合$X = 0$は支出がまったく発生しないため個別に処理され、答えは単純に合計になります。

 ## 特殊なケース

 いつ$X = 0$、このプロセスではコインが削除されることはありません。 この実装は、プレフィックスの合計を明示的に返します。これは、支出によって何も行われず、リセットも発生しないという事実と一致します。 

いつすべて$a_i = 0$、すべてのセグメントは自明であり、バイナリ検索は常に同じインデックスを返します。 ポインタは反復ごとに常に増加するため、アルゴリズムは無限ループを発生せずに配列内を正しく処理します。 

いつ$X$がプレフィックスの合計よりも大きい場合、バイナリ検索は常に最も遠いインデックスまで拡張され、単一のセグメントが生成されます。 アルゴリズムは一度全額を累積して終了します。 

大きな収入と小さな収入が交互に起こるなど、値が大きく変動する場合、二分探索は制約を直接適用するため、毎回正しく最大有効セグメントを分離します。$p[j] - p[i] < X$無効な超過累積がセグメントに含まれないようにします。
