 ## 問題の理解

 バイナリ文字列と、位置ごとに 2 つの代替「モード」が与えられます。 位置を赤に割り当てると、値が得られます$r_i$。 青を割り当てると、次のようになります。$b_i$。 すべての選択を行うと、すべての青い位置が消え、赤い位置だけが元の順序で残ります。 

このフィルタリングされた文字列に対して、残りのシーケンスの反転数に等しいペナルティを支払います。ここで、反転とは位置のペアです$(i, j)$と$i < j$、$i$- 番目の残りの文字は`1`、そして$j$- 番目の残りの文字は`0`。 このようなペアごとに 1 コインのコストがかかります。 

課題は、総利益 (選択したすべての合計) を最大化する色を選択することです。$r_i$そして$b_i$残りの赤のみのシーケンスの反転ペナルティを差し引いた値。 

この制約は、すべてのテスト ケースの合計の長さが最大であることを意味します。$4 \cdot 10^5$したがって、どのような解も線形または線形に近い必要があります。$O(n \log n)$。 すべてのプレフィックスまたはサブセットに対する二次アプローチは、多くの異なる選択の下で反転コストを再計算する必要があるため、直ちに不可能です。 

いくつかの状況は、特に誤って対処しやすいものです。 すべての文字があれば`0`、反転は決して存在しないため、最適な戦略は純粋にローカルです。各ポジションは独立して次のいずれかをとります。$r_i$または$b_i$の方が大きいです。 すべての文字があれば`1`、やはり反転は現れず、問題は位置ごとの独立した選択に帰着します。 困難は両方の場合にのみ表示されます。`1`そして`0`存在するため、`0`選択した数によって異なります`1`がその前に表示されます。 

各ポジションを独立して決定する単純な貪欲な戦略は失敗します。`1`早期に行うと、将来のすべてのコストが増加します`0`それは赤のままです。 

## アプローチ

 この問題を直接考える方法は、赤になる位置のサブセットを修正し、その他すべてを青として扱うことです。 スコアは、選択された赤のゲインとすべての青のゲインの合計から、選択された赤の位置間の反転ペナルティを差し引いたものになります。 

構造を無視する場合は、赤色の位置のすべてのサブセットを列挙しようとする可能性があります。 これは正しいですが、すべての要素には 2 つの状態があるため、指数関数的になります。$2^n$テストケースごとの構成。 

重要な構造は、赤色の位置のみが、一方向にのみ相互作用するということです。つまり、選択された位置のみです。`1`選択した項目の前に表示された場合にのみペナルティに影響します。`0`。 これは、コストが選択された要素の数だけではなく、その順序によって決まることを意味します。 

プロセスを再構成する便利な方法は、文字列を左から右にスキャンし、選択された数を維持することです。`1`はすでに登場しています。 ポジションを赤にすることを決定すると、`1`即座にローカルゲインのみに貢献しますが、`0`ローカルゲインから、以前に選択された赤の数に等しいペナルティを引いたものに寄与します。`1`s.

 これにより、問題は文字列の接頭辞に関する動的なプログラムに変わり、状態はその数を追跡します。`1`これまでに選択されています。 ただし、各遷移では考えられるすべてのカウントを考慮する必要があるため、この状態に対する直接の DP は大きすぎて単純に処理できません。 

重要な観察は、固定プレフィックスの場合、DP 値が選択されたプレフィックスの数の関数であることです。`1`は構造化された方法で動作します。 を処理するとき、`1`、DP は効果的に状態から大衆をシフトします。$k$に$k+1$。 を処理するとき、`0`、各州$k$線形に依存する関数を使用して独立して更新されます$k$しきい値まで。 この構造により、状態インデックス上で凹面のような動作を保存する範囲変換を備えたセグメント ツリーを使用して DP を効率的に維持できます。

 ## アルゴリズムのチュートリアル

 まず、答えの定数部分、つまりすべての合計を分離します。$b_i$。 その後、すべてのポジションが調整に貢献します。$r_i - b_i$選択された場合は赤、それ以外の場合はゼロになりますが、反転ペナルティを通じて相互作用します。 

状態インデックスが含まれるプレフィックス上で DP を維持します。$k$何個かを表します`1`これまでのキャラクターは赤色で選ばれてきました。 保存される値は、プレフィックス内のすべての決定に対する可能な限り最高の追加利益です。 

各位置で、キャラクターが`1`または`0`。 

1. DP を単一の状態で初期化します。`1`が選択され、値はゼロになります。 
2. 文字を加工する場合`1`、赤を選択すると、選択された数が増加します。`1`s. これは、すべての DP 状態を意味します$k$状態への遷移$k+1$ゲインを追加して$r_i - b_i$。 青を選択した場合、DP 状態は何も変わりません。 
3. 文字を加工する場合`0`、赤として選択しても、選択された数は変わりません。`1`ただし、現在選択されている数に等しいペナルティが発生します。`1`s. したがって、各州ごとに$k$、現在の値を維持するか (青にペイントする場合)、次のように改善します。$r_i - b_i - k$（赤く塗った場合）。 
4. のアップデート`0`したがって、すべての状態にわたる点ごとの変換になります。$k$、各状態は次の線形関数に基づいて独立して更新されます。$k$。 
5. インデックスのシフトと範囲ごとの最大更新の効率的な適用をサポートするデータ構造で DP 配列を維持します。これにより、`1`そして、`0`操作ごとに対数時間で適用できます。 

## なぜ機能するのか

 DP 状態は、重要な唯一の依存関係、つまり依存関係の数を完全にキャプチャします。`1`は現在の位置より前に選択されています。 将来のすべてのペナルティは、特定のペナルティではなく、このカウントのみに依存します。`1`が選ばれました。 トランジションでは、`1`このカウントを増加させるだけであり、`0`現在のカウントを変更せずにのみ使用します。 

すべての相互作用はこの単一のスカラー状態を通じて仲介されるため、履歴を表すために追加の構造は必要ありません。 セグメント ツリーの実装は、状態インデックスに依存する線形変換を適用しながら、この状態のすべての可能な値を効率的に維持する単なる方法です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        r = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = sum(b)
        dp = [0] * (n + 1)
        neg_inf = -10**30

        for i in range(n):
            ndp = [neg_inf] * (n + 1)

            if s[i] == '1':
                w = r[i] - b[i]
                for k in range(n):
                    if dp[k] == neg_inf:
                        continue
                    ndp[k + 1] = max(ndp[k + 1], dp[k] + w)
                    ndp[k] = max(ndp[k], dp[k])
            else:
                w = r[i] - b[i]
                for k in range(n + 1):
                    if dp[k] == neg_inf:
                        continue
                    ndp[k] = max(ndp[k], dp[k])
                    ndp[k] = max(ndp[k], dp[k] + w - k)

            dp = ndp

        ans = max(dp)
        print(base + ans)

if __name__ == "__main__":
    solve()

のために`1`、スキップするか取得するかのどちらかであり、取得すると状態インデックスが上にシフトします。 のために`0`、スキップするか取得しますが、取得すると、現在選択されている数だけ値が減少します。`1`s、まさにその通りです`k`。 

すべての状態にわたる外側のループにより、このバージョンは概念的に単純になりますが、DP 定式化から状態ごとの遷移が圧縮される最適化されたセグメント ツリー実装へのブリッジとして意図されています。
