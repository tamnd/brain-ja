 ## 解決策
 ## 問題の理解

 ゲームのコレクションが与えられ、各ゲームにはストレージ コストとレーティングが設定されています。 これらのゲームのサブセットを選択して、合計ストレージ容量が限られているコンピューターにインストールしたいと考えています。 サブセットには少なくとも k 個のゲームが含まれている必要があり、それらのサイズの合計が m を超えてはなりません。 

有効なサブセットをインストールした後、選択したゲームを評価の降順に並べ替えます。 このソートされたリストから、x 番目の要素を取り出し、その評価を「プレイ済み評価」と呼びます。 私たちの目標は、この x 番目に大きい評価ができるだけ大きくなるようにサブセットを選択することです。 

したがって、決定はどのゲームを含めるかだけでなく、選択したセット内のランキングがどのように動作するかによっても決まります。 最小カーディナリティ要件を持つナップザックのような制約の下で、選択された評価の分位数を最大化しようと効果的に試みています。 

制約は大きく、すべてのテスト ケースにわたる合計ゲーム数は最大 2×10^5、テスト ケース数は最大 10^4 です。 これにより、テストごとにすべてのサブセットや二次関数さえも試行するソリューションは即座に除外されます。 テスト ケースごとに O(n log n) を超えるものは、全体として失敗します。 また、非常に大きな m (最大 10^14) があるため、容量を超えて DP に依存することはできません。 

サイズ制限内で k 個のゲームを選択できない場合、重要なエッジ ケースが発生します。 その場合、-1 を出力する必要があります。 たとえば、すべてのゲームのサイズが m より大きい場合、選択は無効になります。 もう 1 つの微妙なケースは、k 個を超えるゲームを選択することが有益である場合です。要件は「少なくとも k」であるため、追加のゲームを追加すると、どの要素が x 番目に大きくなるかが変わり、答えが改善される可能性があります。 

単純な間違いは、常に正確に k 個のゲームを選択する必要がある、または常に k 個の最小サイズを選択する必要があると想定することです。 選択されたセット内の評価順序が実際の目的の要因であるため、どちらも間違っています。 

## アプローチ

 ブルートフォースアプローチでは、ゲームのすべてのサブセットを考慮し、合計サイズが最大でも m、最小でもサイズが k であるものをフィルターし、各サブセットで x 番目に大きい評価を計算して最大値を取得します。 これは正しいですが、実行不可能です。 部分集合は 2^n 個あり、2×10^5 はおろか、n = 40 ですら実際には不可能になります。 

目標を再構築する必要があります。 この難しさは、ナップザック制約の下でサブセット (x 番目に大きい評価) の統計を最適化しているという事実から生じます。 

重要な観察は視点を逆転させることです。サブセットを構築してからその x 番目に大きい評価を計算する代わりに、候補評価値 R を固定し、選択された少なくとも x のゲームが評価 ≥ R を持ち、サブセットが依然としてサイズ ≤ m およびカーディナリティ ≥ k を尊重するような有効なサブセットを構築できるかどうかを尋ねます。 

R を固定すると、すべてのゲームは 2 つのタイプに分かれます。ri ≧ R の場合は「良い」、それ以外の場合は「悪い」です。 R を答えとして実行可能にするには、選択したゲームのうち、少なくとも x が適切であることを確認する必要があります。 これらの x 個の良いゲームだけが、x 番目に大きい条件にとって重要です。なぜなら、少なくとも x 個の良いゲームがあれば、x 番目に大きい評価は少なくとも R であるからです。 

ここで、少なくとも x 個の良いゲームを選択することと、少なくとも k 個の合計ゲームを選択するという 2 つの制約を満たしながら、合計サイズを最小化したいと考えています。 サイズを最小限にするには、常に各カテゴリの中で最小サイズのゲームを選択する必要があります。 これにより、フィルターされたセット内でサイズによる並べ替えが行われます。 

固定 R の場合、すべての良いゲームとすべての悪いゲームを取得し、両方をサイズで並べ替えて、実行可能な組み合わせを選択します。x 個の最小の良いゲームを取得し、両方のプールからの最小の残りのゲームを使用して、残りのスロットを最大 k まで埋めます。 合計サイズが ≤ m の場合、R は達成可能です。 

R では実現可能性が単調であるため、評価を二分探索することができます。

 | 二分探索 + 貪欲な実現可能性 | O(n log n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各テストケースを個別に処理します。 

1. 評価による事前の並べ替えではなく、回答候補に対する二分検索を介して暗黙的に評価値によってすべてのゲームを並べ替えます。 代わりに評価値を抽出し、検索スペースとして使用します。 答えは指定された評価のいずれかである必要があるため、これは有効です。 
2. 固定候補レーティング R の場合、ゲームを 2 つのグループに分けます。レーティングが少なくとも R のグループと R 未満のグループです。最初のグループは、「x 番目に大きい」要件を満たすのに貢献できるゲームを表します。 
3. 両方のグループをサイズの昇順に並べ替えます。 これにより、ゲームを選択する必要があるときは常に、ストレージの面で利用可能な最も安価なオプションを選択することが保証されます。 
4. まず、高評価グループから可能な限り最小の x ゲームを選択します。 これが不可能な場合、つまりそのようなゲームが x 個よりも少ないことを意味し、候補 R は直ちに実行不可能になります。 
5. これら x 個の必須の高評価ゲームを選択した後でも、インストールされているゲームの合計が少なくとも k 個以上に達するには、さらに多くのゲームが必要になる場合があります。 残りの高評価ゲームと低評価ゲームの結合から利用可能な最小のゲームを繰り返し選択することで、残りのスロット (k − x) を埋めます。 
6. この構築されたセットの合計サイズを計算します。 m を超えない場合、R は実行可能ですが、そうでない場合は実行できません。 
7. 実現可能性が成立する最大 R を二分探索します。 

最小サイズを安全に選択できる理由は、制約が同一性ではなく合計合計とカウントのみに依存するためです。 より大きなゲームをより小さなゲームに置き換えるスワップは、レーティングの制約に影響を与えることなく、実現可能性を維持または向上させます。 

### なぜ効果があるのか

 固定しきい値 R の場合、問題は、指定されたセット (良い評価) から少なくとも x 個の項目と、全体で少なくとも k 個の項目を含む最小コストのサブセットを選択することに帰着します。 最小サイズの貪欲な選択は、制約を破ることなく、選択された大きな要素を選択されていない小さな要素と繰り返し交換することによって、実行可能なソリューションを貪欲な解決策に変換できるため、最適です。 これにより、実現可能性チェックが正しく、二分探索の正しさが単調性から導かれることが証明されます。R を増加しても「適切なセット」は小さくなるだけで大​​きくなることはないため、実現可能性は低下するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(ratings, sizes, k, x, m, R):
    good = []
    bad = []

    for s, r in zip(sizes, ratings):
        if r >= R:
            good.append(s)
        else:
            bad.append(s)

    if len(good) < x:
        return False

    good.sort()
    bad.sort()

    # take x smallest good
    total = sum(good[:x])

    if total > m:
        return False

    i = x
    j = 0
    taken = x

    # we may need to reach at least k total items
    while taken < k:
        if i < len(good) and (j >= len(bad) or good[i] <= bad[j]):
            total += good[i]
            i += 1
        else:
            total += bad[j]
            j += 1

        if total > m:
            return False

        taken += 1

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x, m = map(int, input().split())
        sizes = list(map(int, input().split()))
        ratings = list(map(int, input().split()))

        # if even k smallest sizes exceed m, impossible quickly
        pairs = sorted(zip(sizes, ratings))
        if sum(s for s, _ in pairs[:k]) > m:
            print(-1)
            continue

        vals = sorted(set(ratings))

        lo, hi = 0, len(vals) - 1
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(ratings, sizes, k, x, m, vals[mid]):
                ans = vals[mid]
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性のチェックを二分探索から分離します。 の`can`関数は、固定の評価しきい値を強制し、その制約の下で可能な限り安価な有効なサブセットを構築します。 

微妙な点は、k 個の最小サイズを使用した早期の剪定チェックです。 これは正確さのために必須ではありませんが、レーティングを無視しても k 個のゲームに適合できないような実行不可能なケースに時間を浪費することを避けます。 

もう 1 つの重要な実装の詳細は、次の間の 2 ポインターのマージです。`good`そして`bad`サイズごとに並べ替えた後のリスト。 これにより、常に可能な限り安価な方法で現在のセットを拡張できることが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、正確に k ゲームがかろうじて収まるが、追加のゲームを追加すると制約が破られる場合です。 アルゴリズムは常に k を超える最小コストの拡張を構築するため、これを処理します。そのため、高価な項目が不必要に含まれることはありません。 

もう 1 つのケースは、高評価のゲームがちょうど x 個ある場合です。 実現可能性チェックでは、それらすべてが即座に解に強制的に組み込まれ、それらのサイズが m を超える場合、答えは無効な拡張を試行することなくそのしきい値を正しく拒否します。 

最後のケースは、高評価のゲームは非常に大きいが、低評価のゲームは小さい場合です。 貪欲なマージにより、「合計 k 以上」要件を満たすために低レーティングのゲームのみを使用すると同時に、x 個の高レーティングの制約が保証され、しきい値テストの正確性が維持されます。
