 ## 解決策
 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 それぞれに、既存のパスワード文字列と新しいパスワードのターゲット長があります。 新しいパスワードは、小文字、大文字、数字で構成される固定アルファベットで構成され、これらを合わせて 62 個の異なる文字を構成する必要があります。 

タスクは、新しい文字列のすべての文字が一意であり、古いパスワードにはこれらの文字がまったく表示されないように、正確に k 文字の文字列を構築することです。 古いパスワードですでに使用されている個別の文字が多すぎる場合、多くのオプションが削除され、有効な新しいパスワードを作成できなくなる可能性があります。 

中心となる制約は組み合わせです。62 個のシンボルからなる世界から、古いパスワードに含まれるすべてのシンボルを削除し、少なくとも k 個のシンボルが残っているかどうかを確認します。 「はい」の場合、残りのプールから任意の k 個の異なるシンボルを出力できます。 そうでない場合は、不可能であることを報告する必要があります。 

境界は小さく、固定されています。 各パスワードの長さは最大 62 で、テスト ケースは最大 500 です。 これは、すべての操作がケースごとに O(62) であるため、アルファベットをスキャンしてテスト ケースごとにセットを構築するソリューションは、自明のことながら十分に高速であることをすぐに示唆しています。 

古いパスワードに 62 文字すべてが含まれている場合、微妙なエッジ ケースが発生します。 その状況では、k = 1 であっても答えは不可能になります。 もう 1 つのケースは、k = 0 の場合です。これは、k ≥ 1 であるため、ここでは制約によって明示的に許可されていませんが、許可されている場合は、常に空の文字列で自明に満たされます。 最後に、一意性は個別の記号に対してのみ定義されるため、古いパスワード内の文字の繰り返しは問題になりません。 

## アプローチ

 素朴なアプローチは、許可されたアルファベットから長さ k の考えられるすべての文字列を生成し、そのような文字列が古いパスワードの文字を回避しているかどうかを確認することを検討することです。 個別の文字列に限定したとしても、これは最大 62 個のシンボルにわたる順列スタイルの生成になります。 k 個の異なる文字を選択する方法の数は 62Pk のオーダーであり、これは中程度の k であってもすでに膨大です。 このアプローチはまったく実行不可能です。 

重要な観察点は、複雑な方法で注文を検討する必要がまったくないということです。 出力は任意であり、使用可能な文字のセットのみが重要です。 どの文字が禁止されているか (古いパスワードに含まれる文字) を特定したら、問題は残りのプールから k 個の要素を選択することになります。 

したがって、この構造は単純な集合差分問題に分解されます。つまり、許可された文字の集合を計算し、そのサイズを検証し、サイズ k のサブセットを出力します。 これは、一意性以外の配置に制約がないため機能します。

 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(62Pk) | O(62Pk) | 遅すぎる |
 | フィルタリングと選択を設定する | テスト ケースごとに O(62) | お(62) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 小文字、大文字、数字で構成される有効な 62 文字すべての固定リストを作成します。 これは私たちが描く宇宙として機能します。 
2. 各テスト ケースについて、k、n、および古いパスワード文字列 s を読み取ります。 
3. s に出現するすべての文字をマークするブール値またはセット構造を構築します。 個別の文字のみを考慮するため、 の重複は自然に無視されます。 
4. 62 文字のユニバースを反復処理し、s に存在するとマークされていない文字を収集します。 これにより、使用可能な文字のプールが得られます。 
5. このプールのサイズが k 未満の場合は、有効な構造が存在しないため、単一のハイフンを出力します。 
6. それ以外の場合は、このプールから最初の k 文字を任意の順序で出力します。 この問題では任意の有効な答えが許容されるため、それ以上の順序付けロジックは必要ありません。 

### なぜ効果があるのか

すべてのステップで、プールには古いパスワードで禁止されていない文字が正確に含まれているという不変条件が維持されます。 すべての出力文字はこのプールから抽出されるため、古いパスワードに表示されるという制約に違反することはできません。 また、各文字は最大でも 1 回しか取得されないため、一意性の条件は自動的に満たされます。 残りの唯一の要件はカーディナリティであり、プール サイズを直接チェックすることで、有効な選択が存在する場合にのみ続行することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    import sys
    input = sys.stdin.readline

    # Build full alphabet of allowed characters
    alphabet = []
    for i in range(26):
        alphabet.append(chr(ord('a') + i))
    for i in range(26):
        alphabet.append(chr(ord('A') + i))
    for i in range(10):
        alphabet.append(chr(ord('0') + i))

    t = int(input())
    for _ in range(t):
        k = int(input())
        n = int(input())
        s = input().strip()

        used = set(s)

        available = []
        for c in alphabet:
            if c not in used:
                available.append(c)

        if len(available) < k:
            print("-")
        else:
            print("".join(available[:k]))

if __name__ == "__main__":
    solve()
```この解決策は、実行ごとに 1 回、完全な 62 文字のアルファベットを構築することから始まります。 これにより、範囲を繰り返し再計算することが回避され、ロジックが明示的になります。 

テスト ケースごとに、古いパスワードをセットに変換し、重複したパスワードを自動的に圧縮します。 次に、このセットに対してアルファベットをフィルタリングして、許可されたプールを構築します。 決定ステップは単純な長さのチェックであり、出力はフィルタリングされたリストのプレフィックスです。 

よくある落とし穴は、古いパスワードの重複を誤って複数の削除として処理してしまうことです。 削除は個別の文字のみに基づいているため、これは不正確です。

 ## 特殊なケース

 重要なケースの 1 つは、古いパスワードに繰り返しの文字が含まれている場合です。たとえば、`s = "aaAA111"`。 アルゴリズムはこれをセットに変換します`{a, A, 1}`各文字を 1 回だけ削除します。 誤って重複を複数回削除した場合でも、最終的には同じセットが得られますが、セットのメンバーシップではなくカウントに依存する実装では、可用性が実際よりも縮小していると誤って認識する可能性があります。 

もう 1 つのケースは、k が使用可能な文字の正確な数に等しい場合です。 たとえば、 s に 10 個の異なる文字が含まれている場合、ちょうど 52 個が残ります。 アルゴリズムは、順序付けや部分的なチェックを賢く行うべきではなく、単純に残りの文字をすべて取得する必要があります。 これら 52 個の順列はすべて有効です。 

最後に、k が小さい (1 など) が禁止セットが大きい場合、正確さは出力を構築する前に可用性をチェックするかどうかに依存します。 このチェックがスキップされると、実装は、正しい応答が単に "-" であるはずであっても、使用可能な文字の空のリストにインデックスを付けようとしてクラッシュする可能性があります。
