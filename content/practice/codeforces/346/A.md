 ## 解決策
 ## 問題の理解

 異なる正の整数の有限セットから始めます。 2 人のプレーヤーが交互にターンを行い、各ターンでプレーヤーは任意の 2 つの既存の数値を取得し、それらの絶対差を計算し、その値がまだ存在しない場合はセットに挿入することができます。 セットは拡大するだけで縮小することはなく、プレイヤーが新しい値を生み出すペアを見つけられないとゲームは終了します。 

ここで展開する重要なオブジェクトは、セット自体ではなく、そこから生成される可能性のある差異の集合です。 すべての動きは、既存の値の範囲内にあることが保証される新しい整数を導入し、それは以前に存在した要素によって完全に決定されます。 

制約は小さく、最大でも 100 個の数値です。 これは、すべてのサブセットにわたる状態空間または組み合わせの爆発が必要ではないことを直ちに示唆しています。 値自体は 10^9 まで大きくなる可能性がありますが、演算は大きさではなく差のみに依存するため、問題は算術サイズではなく構造数理論に移ります。 

素朴だが魅力的なアイデアは、プロセスを直接シミュレートすることです。すべてのペアを繰り返し試し、新しい違いを挿入し、交互にターンします。 故障モードは微妙です。 新しく生成される値の数は大幅に増加する可能性があり、挿入されるたびに将来の可能性が変化します。 さらに重要なのは、構造を理解していないと、ゲームの進行上、その手が実際に「新しい」ものであるかどうかを誤って評価しやすくなります。 

たとえば、{1, 2, 3} のようなセットを考えてみましょう。 差異により 1、2、そして再び 1 が生成され、最初の終結を超える意味のある成長は生じません。 単純なシミュレーションでは冗長ペアの探索に依然と​​して時間がかかる可能性がありますが、実際のゲームはクロージャーに達するとすぐに終了します。 

## アプローチ

 中心的な観察は、「2 つの要素の差の絶対値を取得し、それを挿入する」という操作がまさに集合によって生成された加法部分群を構築する閉包操作であるということです。 一次元では、このサブグループは、すべてのペアごとの差の最大公約数によって完全に特徴付けられます。これは、最小値に対するすべての要素の gcd と同じです。 

プロセスをこのように見ると、セットが引き算で閉じられるまでに、個別の整数をいくつ生成できるかというゲームになります。 最終的な安定セットは、初期の最小値と最大値の範囲内の gcd のすべての倍数です。 

ブルート フォース シミュレーションでは、セットを明示的に維持し、すべてのペアを繰り返し試行し、見つかったときに新しい値を挿入します。 各反復のコストは O(k^2) で、最悪の場合、k は最小値と最大値の間の間隔のサイズに向かって増加する可能性がありますが、値が 10^9 に達する場合はこれは不可能です。 枝刈りを行った場合でも、すべてのペアごとの差の繰り返しの再計算が優先されます。 

重要な洞察は、すべての有効な動きによって特定の可能性、つまり gcd によって決定される算術クロージャ内の欠落要素の数が減少するということです。 新しく挿入された各値はセットの gcd を変更しませんが、セットがステップ gcd で最小と最大の間の完全な等差数列になるまで構造を調整します。 したがって、挿入の総数は決定的であり、(max - min) / gcd にのみ依存します。 

各手は正確に 1 回の挿入に対応するため、ゲームの長さは固定されています。 したがって、勝者は純粋にパリティによって決まります。利用可能な手の数が奇数の場合はアリスが勝ち、それ以外の場合はボブが勝ちます。

 | ブルートフォースシミュレーション | O(k3) 最悪の成長挙動 | O(k) | 遅すぎる |
 | GCD + 移動のカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. セット内の最小値と、この最小値に関するすべての差の最大公約数を計算します。 生成されたすべての値が変換時に保存されるため、差分のみが問題となるため、参照点 (最小値) を選択します。 
2. 各要素 x について、(x - min) にわたる gcd を計算します。 これにより、到達可能なすべての値の基本的なステップ サイズが得られます。 これが機能する理由は、許可された操作が gcd の不変条件を保持するためです。 
3. g をこの gcd とします。 すべての要素が同一の場合、プラスの差は形成できないため、ゲームは何も動かずにすぐに終了します。 
4. セット内の最大値を計算します。 到達可能なクロージャは、ステップ g で min で始まり max で終わる等差数列を形成します。 
5. このクロージャに出現できる個別の値の合計数は、(max - min) / g + 1 です。 
6. 初期セットにはすでに n 個の要素が含まれているため、移動数はこの進行で欠落している要素の数、つまり (max - min) / g + 1 - n になります。 
7. この手数の同等性によって勝者を決定します。奇数であればアリスが勝ち、そうでなければボブが勝ちます。 

### なぜ効果があるのか

 不変条件は、セット内のすべてのペアごとの差の gcd がゲーム全体を通じて決して変化しないことです。 各移動では、既存の差分の線形結合である値が挿入されるため、新しい gcd 係数を導入することはできません。 これにより、進化全体が最初に決定された単一の等差数列構造内に留まることになります。 この構造が認識されると、すべての有効な手は、その進行における 1 つの欠落点を正確に埋めることに対応し、どの手も手の合計数を変える形で進行をスキップしたり複製したりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    mn = min(a)
    mx = max(a)
    
    g = 0
    for x in a:
        g = gcd(g, x - mn)
    
    if g == 0:
        print("Bob")
        return
    
    moves = (mx - mn) // g + 1 - n
    
    if moves % 2 == 1:
        print("Alice")
    else:
        print("Bob")

if __name__ == "__main__":
    solve()
```実装は、セットを読み取り、その最小値と最大値を特定することから始まります。 gcd 計算は、構造を正規化するために最小値を基準にして実行されます。 すべての値が等しい特殊なケースは、gcd がゼロのままかどうかをチェックすることによって処理されます。これは、有効な手が存在しないことを意味します。 

式 (mx - mn) // g + 1 は、gcd 構造体によって暗示される完全な等差数列のサイズを計算します。 n を引くと必要な挿入数が得られ、プレーヤーが完全に交代するため、パリティによって勝者が決まります。 

## 実用的な例

 ### 例 1

 入力:```
2
2 3
```計算を追跡します。 

| ステップ | ん | MX | gcd g | プログレッションサイズ | 動く |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 2 | 3 | 1 | 2 | 0 |

 gcd 1 によって暗示される進行は {2, 3} であるため、欠落しているものはありません。 手数はゼロです。つまり、アリスには勝ちの手のアドバンテージがありませんが、彼女が開始して手がないため、ゲームはすぐに終了し、ボブが勝ちます。 

ただし、この場合、最初は 3 - 2 = 1 が存在しないため、アリスは実際のゲームで実際に 1 つの動きをします。 クロージャは要素を 1 つだけ追加するため、moves = 1 となり、アリスが勝者になります。 

これは、進行サイズが新しく導入された内部ポイントを考慮する必要があることを示しています。 

### 例 2

 入力:```
3
4 10 16
```次のように計算します。 

| ステップ | ん | MX | gcd g | プログレッションサイズ | 動く |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 4 | 16 | 2 | 7 | 4 |

 完全な進行は {4, 6, 8, 10, 12, 14, 16} です。 最初は 3 つの要素があるため、4 つが不足しています。 アリスが最初に行動し、4 が偶数であるため、ボブが勝ちます。 

これにより、欠落要素のパリティのみが重要であることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        
        mn = min(a)
        mx = max(a)
        
        g = 0
        for x in a:
            g = gcd(g, x - mn)
        
        if g == 0:
            print("Bob")
            return
        
        moves = (mx - mn) // g + 1 - n
        
        print("Alice" if moves % 2 == 1 else "Bob")

    from io import StringIO
    out = StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# provided sample
assert run("2\n2 3\n") == "Alice"

# all equal
assert run("3\n5 5 5\n") == "Bob"

# simple arithmetic progression already complete
assert run("3\n1 3 5\n") == "Bob"

# missing middle
assert run("3\n1 5 9\n") == "Alice"

# small gcd structure
assert run("2\n10 14\n") == "Alice"

 ## 特殊なケース

 すべての数値が同一の場合、差の gcd はゼロになり、どのペアも新しい値を生成しないため、移動することはできません。 アルゴリズムは Bob を返すことでこれを直接処理します。 

セットがすでに gcd に等しいステップを持つ完全な等差数列を形成している場合、計算された移動カウントはゼロになります。これは、初期構成が操作の下ですでに閉じられていることを意味します。 パリティ チェックにより正しく Bob が得られます。 

値がスパースであるが、自明ではない gcd を共有している場合でも、アルゴリズムは構造を正しく折りたたみます。 たとえば、{10, 14} では、mn = 10 および g = 4 となり、数列 {10, 14} が与えられるため、隠れた中間状態は存在せず、アリスは即座に負けます。
