 ## 解決策
 ## 問題の理解

 ロボットが横断できる地図を表す有向グラフが与えられます。 ロボットは頂点 _s_ から開始し、ターゲット頂点 _t_ に到達する必要があります。 これは 3 つの法則に従います。頂点に再度アクセスすると自己破壊し、出力エッジのない頂点に到達すると自己破壊します。複数の出力エッジが存在する場合は、どのエッジを取るかを明示的に指定しない限りランダムに移動します。 mzry1992 は、ロボットがランダムに移動するのを防ぐために、複数の出力エッジを持つ頂点に特別な命令を提供できます。 

入力は、頂点とエッジの数、エッジのリスト、開始頂点とターゲット頂点で構成されます。 出力は、最悪の場合にロボットが安全に _t_ に到達することを保証するために、ロボットのパスに沿って発行する必要がある命令の最小数、またはパスが存在しない場合は -1 です。 

この制約では、最大 10^6 の頂点とエッジが許可されます。 これにより、時間計算量が O(n + m) を超えるアルゴリズムが除外されます。 すべてのパスを明示的に探索する単純な DFS は、特にサイクルや分岐点が多いグラフでは、最悪の場合、指数関数的なパスを試行するため、遅すぎます。 

複数の外向きエッジを持つ頂点がサイクル上にある場合、微妙なエッジ ケースが発生します。 そこで指示を出さないと、ロボットが無限ループして目標に到達しない可能性があります。 たとえば、頂点 2 経由でのみ到達可能なターゲット 3 を持つ 1 → 2 → 1 のようなサイクルでは、ランダム ループを避けるために頂点 1 での命令が必要です。 1 つのパスに沿った分岐点のみをカウントする不注意な DFS は、命令の数を過小評価し、不正確な出力を生成する可能性があります。 

もう 1 つのエッジ ケースは、ターゲット頂点に出力エッジがある場合です。 ロボットはターゲットで停止するため、複数の出力エッジがある場合でも、そこで指示を与える必要はありません。 同様に、ターゲットへのパス上にない行き止まりの頂点は無関係です。 ターゲットに到達できる頂点のみに焦点を当てる必要があります。 

## アプローチ

 ブルートフォース手法では、ロボットがたどる可能性のあるすべてのパスをシミュレートし、ロボットが分岐頂点に到達するたびに命令をカウントします。 これが機能するのは、各分岐頂点には潜在的に命令が必要であるためですが、シミュレーションではサイクルを考慮し、無限再帰を回避する必要があります。 メモ化を行ったとしても、10^6 ノードを持つグラフ内のパスの数は指数関数的に増加する可能性があるため、このアプローチは実行不可能になります。 

重要な洞察は、パスを完全に詳細にシミュレートする必要はないということです。 代わりに、問題をグラフ上の動的計画問題として扱うことができます。 値を定義します`dp[v]`頂点からターゲットに安全に到達するために必要な命令の最小数として`v`。 頂点に外向きのエッジがなく、ターゲットではない場合、ターゲットに到達することは不可能です。`dp[v] = inf`。 出力エッジが 1 つだけある頂点の場合は、命令を追加せずにそのエッジから値を単純に伝播します。 複数の外向きエッジを持つ頂点の場合、ロボットが任意の出向きエッジを取る可能性があるという最悪のシナリオを考慮する必要があります。 したがって、そのような頂点の値は、(命令の) 1 に次の最大値を加えたものになります。`dp`隣人の価値観。 

これにより、問題はコンピューティングに限定されます`dp[v]`逆グラフの事後走査を使用して、ターゲットから到達可能なすべての頂点を対象にします。 ターゲットに接続されていないサイクル内の頂点は無視され、ターゲットから到達可能なサイクル内の頂点は、反転したグラフ エッジに沿って最大値を伝播することによって正しく処理されます。

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストと、ターゲットからのトラバース用の逆隣接リストを作成します。 ターゲットから逆方向に開始して最小限の命令を計算します。 
2. を初期化します。`dp`サイズの配列`n + 1`、設定`dp[t] = 0`ロボットはすでに目標に到達しているため、指示は必要ありません。 他の頂点を、計算されていない値のプレースホルダー (-1 など) に設定します。 
3. 再帰関数を定義する`solve(v)`それは計算します`dp[v]`計算されていない場合。 この関数は最初に頂点かどうかをチェックします。`v`発信エッジはありません。 そうであれば、そして`v`ターゲットではありません、マークしてください`dp[v] = inf`ロボットはここからターゲットに到達できないためです。 
4. 頂点の場合`v`発信エッジが 1 つだけある`u`、 それから`dp[v] = solve(u)`。 ロボットには選択の余地がないため、指示は必要ありません。`v`。 
5. 頂点の場合`v`複数の発信エッジがあり、再帰的に計算します`dp[u]`すべての隣人のために`u`そしてセット`dp[v] = 1 + max(dp[u])`。 の`1`でのランダムな動きを防ぐために必要な命令を説明します。`v`、そして`max`最悪の場合のブランチを確実に処理できるようにします。 
6. 再帰中に頂点を「現在処理中」としてマークすることで、サイクルを安全に処理します。 現在の再帰で頂点を再訪すると、サイクルが検出されたことになります。最大伝播はターゲットから到達可能なすべてのノードを計算した後に最終的に解決されるため、特別なことを行う必要はありません。 
7. 最後に計算します`solve(s)`。 結果が次の場合`inf`、ロボットがターゲットに到達できないため、-1 を出力します。 それ以外の場合は、計算された値を出力します。 

不変条件は、計算後のものです。`dp[v]`、ターゲットに到達するために必要な命令の最小数を表します。`v`最悪の場合、後続のすべての分岐頂点で最適な命令が実行されると仮定します。 最大値を伝播することで、すべてのパスを明示的にシミュレートすることなく、最悪の場合のランダムな動きを考慮できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    adj[u].append(v)

s, t = map(int, input().split())

dp = [-1] * (n + 1)
processing = [False] * (n + 1)

INF = n + 1

def solve(v):
    if dp[v] != -1:
        return dp[v]
    if processing[v]:
        return INF
    processing[v] = True
    if v == t:
        dp[v] = 0
    elif not adj[v]:
        dp[v] = INF
    elif len(adj[v]) == 1:
        dp[v] = solve(adj[v][0])
    else:
        dp[v] = 1 + max(solve(u) for u in adj[v])
    processing[v] = False
    return dp[v]

res = solve(s)
print(-1 if res >= INF else res)
```隣接リストには、高速な近隣反復のためのエッジが保存されます。 の`processing`配列は無限再帰を防ぐためにサイクルを検出します。`INF`到達不能なノードを表します。 再帰的`solve`関数は、概説したとおりに DP を正確に実装します。 命令を追加せずにシングルエッジ ノードを処理することが重要です。 マルチエッジ ノードは命令を追加し、隣接ノードの最大 DP を伝播し、最悪の分岐シナリオをカバーします。
