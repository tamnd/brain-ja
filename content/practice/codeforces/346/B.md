[CF 346B - 幸運な共通サブシーケンス](https://codeforces.com/problemset/problem/346/B)

 **評価:** 2000
 **タグ:** dp、文字列
 **解決時間:** 1 分 5 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 連続パターンとして 3 番目の文字列を避けながら、指定された 2 つの文字列のサブシーケンスとして現れるシーケンスを構築するように求められます。 言い換えれば、選択した文字が同じ文字列を形成するように、インデックスの昇順で両方の入力文字列から文字を選択する必要があります。また、そのような共通のサブシーケンスすべての中で、「ウイルス」文字列がその内部の連続ブロックとして形成されることは絶対に避けなければなりません。 

難しいのは、2 つの文字列内の部分列の選択がグローバルに相互作用するのに対し、禁止条件は構築された回答内のローカル構造に依存することです。 これにより、グローバルな最適性 (最長共通部分シーケンス) とローカルな制約 (パターン回避) の間に緊張が生じます。 

すべての文字列の長さは最大 100 であり、これは接頭辞のペアに対する動的プログラミング ソリューションを即座に示唆します。 入力長に対する 3 次以上の依存性は許容されますが、サブシーケンスにわたる指数関数は許容されません。 長さ 100 の文字列のすべての部分列を単純に列挙すると、すでに 2^100 の可能性が生じますが、これは実行可能な計算をはるかに超えています。 

貪欲 LCS または標準 LCS の微妙な失敗例は、ローカルで最適な一致によって部分的なアライメントが作成され、後で禁止された部分文字列が強制される場合です。 たとえば、文字が一致するたびに共通のサブシーケンスを貪欲に拡張したが、初期の選択により誤ってウイルスのプレフィックスが作成されたとします。 プレフィックスが形成されると、一致する文字を継続するとウイルスが完成し、以前のわずかに短い代替手段で回避できたとしてもシーケンス全体が無効になる可能性があります。 

したがって、重要な課題は、両方の文字列内でどれだけ離れているかを追跡するだけでなく、現在構築されているシーケンスが禁止パターンの形成にどれだけ近づいているかを追跡する必要があることです。 

## アプローチ

 古典的な最長共通部分列問題では、2 つの文字列のプレフィックスに対して 2 次元の DP が使用されます。 ここでは、ウイルスを完成させるリスクがあるかどうかを決定するため、構築されたサブシーケンスの最後の部分に関する追加の状態を記憶する必要があるため、これでは十分ではありません。 

強引なアイデアは、最初の文字列のすべてのサブシーケンスを生成し、それらが 2 番目の文字列に出現するかどうかを確認し、ウイルスを回避するものをフィルタリングすることです。 1 つの候補サブシーケンスをチェックするには O(n) または O(m) がかかり、サブシーケンスの数は n で指数関数的になります。 n = 40 であってもすでに約 1 兆個のサブシーケンスが生成されるため、これはすぐに実行不可能になります。 

重要な観察は、ウイルスが部分文字列として現れるかどうかは、ウイルスのプレフィックスと一致する、現在構築されているシーケンスの最長のサフィックスのみに依存するということです。 これは、文字列オートマトンでパターン マッチングに使用されるのと同じ構造です。 シーケンス全体を記憶するのではなく、部分的な回答の最後でウイルス プレフィックスの何文字が現在一致しているかを追跡するだけです。 

これにより、問題が 3 次元の DP、つまり s1 の位置、s2 の位置、および現在一致するウイルスのプレフィックス長に変換されます。 各 DP 状態には、その制約の下で可能な最適な LCS 長が格納されます。 遷移では、1 つの文字列から文字をスキップするか、一致する文字を取得し、KMP オートマトン ロジックと同様の事前計算された遷移テーブルを使用してウイルス プレフィックスの状態を更新します。 

これにより、指数関数的爆発がサイズ O(n・m・k) の管理可能な状態空間に縮小されます。ここで、k はウイルスの長さです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス | O(2^n · n) | O(n) | 遅すぎる |
 | LCS のみの DP | O(n・m) | O(n・m) | 不正解 (ウイルス制約を無視します) |
 | オートマトン状態の DP | O(n・m・k・26) | O(n・m・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方の文字列のプレフィックスを処理し、サフィックスとしてのウイルスとの一致にどの程度近づいているかを追跡する DP を定義します。

1. ウイルス パターンの遷移関数を事前計算します。 現在一致しているウイルスのプレフィックス文字の数を表すすべての状態、およびすべての文字について、その文字を追加した後に新しく一致したプレフィックスの長さを計算します。 これにより、DP 移行中にウイルスの進行状況を O(1) 時間で更新できるようになります。 
2. プレフィックス s1[0..i)、s2[0..j)] を使用して、有効な共通サブシーケンスの最大長として dp[i][j][k] を定義します。ここで、k は、ウイルスのプレフィックスと一致する現在のサブシーケンスの最長のサフィックスの長さを表します。 
3. dp[0][0][0] = 0 を除くすべての状態を負の無限大に初期化します。空のサブシーケンスは有効であり、ウイルスのどの部分にも一致しません。 
4. 各状態 (i、j、k) に対して、遷移を伝播します。 

1. s1[i] をスキップして、(i+1, j, k) に移動します。 これにより、サブシーケンスは変更されません。 
2. s2[j] をスキップして、(i, j+1, k) に移動します。 
3. s1[i] == s2[j] の場合、この文字を採用します。 k2 = 遷移[k][s1[i]] を計算します。 k2 がウイルスの完全長と等しくない場合は、dp[i+1][j+1][k2] を dp[i][j][k] + 1 で更新します。 

各遷移には選択が反映されます。つまり、1 つの文字列の文字を無視するか、共通のサブシーケンスを拡張するかのいずれかです。 ウイルスの移行により、禁止パターンが完了した状態が決して許されないことが保証されます。 

1. DP を満たした後、すべて (i、j、k) にわたって最大値を持つ状態を見つけます。 これにより、可能な限り最適な長さが得られます。 
2. 答えを再構築するために、各 dp 状態の親ポインターを保存し、どの遷移が使用されたかを記録します。 

正確さは、k が構築されたサブシーケンスとウイルス制約の間の相互作用を完全に要約しているという事実に依存します。 同じ (i, j, k) 状態で終了する 2 つの部分シーケンスは、将来の有効性に関して同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_automaton(p):
    m = len(p)
    nxt = [[0]*26 for _ in range(m+1)]
    for k in range(m+1):
        for c in range(26):
            ch = chr(ord('A') + c)
            if k < m and ch == p[k]:
                nxt[k][c] = k + 1
            else:
                # fallback: longest prefix which is suffix
                s = p[:k] + ch
                while s and not p.startswith(s[-m:]):
                    s = s[1:]
                nxt[k][c] = len(s)
    return nxt

def solve():
    s1 = input().strip()
    s2 = input().strip()
    virus = input().strip()

    n, m, v = len(s1), len(s2), len(virus)

    nxt = build_automaton(virus)

    NEG = -10**9
    dp = [[[NEG]*(v+1) for _ in range(m+1)] for _ in range(n+1)]
    parent = {}

    dp[0][0][0] = 0

    for i in range(n+1):
        for j in range(m+1):
            for k in range(v+1):
                cur = dp[i][j][k]
                if cur < 0:
                    continue

                if i < n:
                    if dp[i+1][j][k] < cur:
                        dp[i+1][j][k] = cur
                        parent[(i+1, j, k)] = (i, j, k, None)

                if j < m:
                    if dp[i][j+1][k] < cur:
                        dp[i][j+1][k] = cur
                        parent[(i, j+1, k)] = (i, j, k, None)

                if i < n and j < m and s1[i] == s2[j]:
                    c = ord(s1[i]) - ord('A')
                    k2 = nxt[k][c]
                    if k2 < v:
                        if dp[i+1][j+1][k2] < cur + 1:
                            dp[i+1][j+1][k2] = cur + 1
                            parent[(i+1, j+1, k2)] = (i, j, k, s1[i])

    best = 0
    state = (0, 0, 0)

    for i in range(n+1):
        for j in range(m+1):
            for k in range(v+1):
                if dp[i][j][k] > best:
                    best = dp[i][j][k]
                    state = (i, j, k)

    if best == 0:
        print(0)
        return

    i, j, k = state
    res = []

    while (i, j, k) != (0, 0, 0):
        pi, pj, pk, ch = parent[(i, j, k)]
        if ch is not None:
            res.append(ch)
        i, j, k = pi, pj, pk

    print("".join(reversed(res)))

if __name__ == "__main__":
    solve()
```DP 配列は、すべてのプレフィックス ペアとウイルスの状態について、達成可能な最適なサブシーケンス長を追跡します。 親ディクショナリには、各状態にどのように到達したかが保存され、「文字を取る」遷移と「スキップ」遷移が区別されます。 実行されたトランジションのみが最終的な再構成に文字を提供します。 

オートマトン関数は、新しい文字が追加されたときにウイルスのプレフィックスの状態がどのように変化するかをエンコードします。これは、DP 中にプレフィックスの一致を繰り返し再計算することを避けるために重要です。 

## 実用的な例

 ### 例 1

 入力:```
s1 = AJKEQSLOBSROFGZ
s2 = OVGURWZLWVLUXTH
virus = OZ
```いくつかの代表的な DP 遷移を追跡します。 

| ステップ | 私 | j | k (ウイルス一致) | アクション | サブシーケンス |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 開始 | "" |
 | 1 | 0 | 1 | 0 | s2 をスキップ | "" |
 | 2 | 1 | 0 | 0 | s1 をスキップ | "" |
 | 3 | 5 | 3 | 0 | 一致 G/U 不一致 | "" |
 | 4 | 10 | 8 | 1 | 部分一致 O | 「お」 |
 | 5 | 12 | 10 | 0 | ウイルス状態をリセット | 「または」 |
 | 6 | 15 | 14 | 1 | Zセーフで終了 | 「オルズ」 |

 このトレースは、DP がウイルスの一時的な部分一致を許可しながら、長い共通部分配列を保持しながら完全な一致を妨げている様子を示しています。 

証明された不変条件は、ウイルス プレフィックスが完全に一致する状態は DP では決して許可されないということです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・m・v・26) | 文字の更新により、すべてのプレフィックス ペアとウイルス状態を遷移します。 
| スペース | O(n・m・v) | DP テーブルと再構築ポインタ |

 n、m、v ≤ 100 の場合、状態空間は最大 10^6 で、遷移は定数因数で制限され、時間とメモリの制限内に快適に収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、最適な LCS がウイルス文字列と自然に等しい場合です。 たとえば、両方の文字列がウイルスと同一の場合、単純な LCS は文字列全体を返します。 DP は、ウイルスの最終的な特徴を完成させる遷移を正しくブロックし、アルゴリズムにわずかに短いサブシーケンスを選択するか、存在しないと結論付けるよう強制します。 

別のケースは、ウイルスの部分一致が最適なサブシーケンス内で繰り返し現れる場合に発生します。 オートマトンの状態により、これらの部分一致が正確に追跡されることが保証されます。 サブシーケンスが複数回リセットされた場合でも、状態は完全な履歴ではなく最長のサフィックス一致のみをキャプチャするため、DP は各プレフィックスを一貫して処理します。
