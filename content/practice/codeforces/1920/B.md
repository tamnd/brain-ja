 ## 解決策
 ## 問題の理解

 正の整数の配列でプレイされる 2 ステップ ゲームをシミュレートするように求められます。 最初のプレイヤーであるアリスは最大で削除できます。$k$要素。 彼女は、配列の最終的な合計をできるだけ大きくしたいと考えています。 2 番目のプレーヤーであるボブは、フリップアップして次のようにすることができます。$x$要素を乗算する$-1$, そして彼はその額をできるだけ少なくしたいと考えています。 私たちの仕事は、両方が最適にプレイすると仮定して最終的な合計を計算することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは配列のサイズを示します。$n$、アリスの限界$k$、ボブの限界$x$、および配列$n$整数。 各テスト ケースの出力は、両方のプレイヤーが最適な手を行った後の最終的な合計です。 

制約が教えてくれる$n$まで可能です$2 \cdot 10^5$テストケースごととすべての合計$n$すべてのテストケースでも超えません$2 \cdot 10^5$。 これは、次の線形の解が必要であることを意味します。$n$、$O(n \log n)$せいぜい、$O(n^2)$アプローチが遅すぎるでしょう。 

明らかではないエッジ ケースには、サイズ 1 の配列が含まれます。この場合、アリスは要素のみを削除して合計を 0 のままにすることができます。$k \ge n$これにより、アリスはすべてを削除できるようになります。 もう 1 つの注意が必要なケースは次のような場合です。$x \ge n$そして、ボブは残りの要素をすべて反転して、大きな合計をマイナスにすることができます。 これらの条件を無視すると、誤った出力が発生する可能性があります。 たとえば、次の入力`1 1 1`配列あり`[1]`生産しなければならない`0`、 ない`1`なぜなら、Alice は要素を最適に削除するからです。 

## アプローチ

 ブルートフォースアプローチでは、以下のサイズのすべてのサブセットが列挙されます。$k$アリスが削除できるものを削除し、結果の配列ごとに、最大サイズのすべてのサブセットを列挙します。$x$ボブがひっくり返るかもしれないと。 組み合わせごとに合計を計算し、各プレイヤーに応じて最大/最小を選択します。 これは原理的には正しいですが、$n \sim 2 \cdot 10^5$、それは関与するため、実行不可能です。$O(2^n)$操作。 

重要な洞察は、両方のプレイヤーが極端な要素に対して貪欲に行動していることに気づくことから得られます。 アリスは、ボブが負に反転する最大値を削除したいと考えています。ボブは常に、合計を最小化するために残りの最大の要素を負に反転します。 これにより、配列をソートして先頭のみを考慮するという問題が軽減されます。$k + x$要素。 実際には、アリスは$k$ボブが反転できる場合は最大の要素を選択し、最終的な合計が最大になる場合は選択する要素を少なくします。 

プレーヤーの動きは完全に順序によって決定されるため、最適なソリューションには複雑な状態追跡や動的プログラミングは必要ありません。 アリスが以下を削除した後の合計を計算できます。$k$最大の要素から合計の 2 倍を減算します。$x$残りの最大の要素 (ボブが反転)、最終的な合計が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n, k, x$そして配列$a$。 
2. 配列をソートする$a$昇順で。 並べ替えると、削除または反転する最大の要素を簡単に選択できます。 
3. アリスのアクションを計算します。 彼女は最大で削除できます$k$要素。 要素の削除は、ボブが反転できる最大の要素の場合にのみ有益です。 合計を最大化するには、$k$最大の要素。 
4. ボブのアクションを計算します。 アリスが連れ去られた後、ボブはひっくり返り、$x$残りの最大の要素に次の値を掛けます。$-1$。 これにより、合計が可能な限り減少します。 
5. 両方のプレイヤーが行動した後に残った配列の合計を計算します。 ボブのフリップの場合は、合計の 2 倍を減算します。$x$要素を反転するため、残りの最大要素$y$合計を変更します$-2y$。 
6. 最終的な合計を出力します。 

機能する理由: アリスは、ボブが反転した場合に合計に最も悪影響を与える要素を常に削除します。 ボブは常に、合計を最小化するために残りの最大の要素を反転します。 並べ替えにより、両方のステップで最大の要素に効率的にアクセスできるようになります。 この貪欲な戦略では、問題が合計に関して線形であり、各要素が順序付けされると独立して動作するため、最適な結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        
        # Alice removes k largest
        if k > 0:
            a = a[:n - k]
        
        # Bob flips x largest remaining
        if x > 0:
            a[-x:] = [-v for v in a[-x:]]
        
        print(sum(a))

if __name__ == "__main__":
    main()
```このソリューションは配列を並べ替えるため、削除および反転する最大の要素を効率的に特定できます。 配列をスライスしてアリスの要素を削除し、最後の要素を反転します。`x`ボブの要素。 Python のネガティブ スライシングは、次のようなケースを処理します。`x`または`k`安全に配列サイズを超えています。

 ## 特殊なケース

 このアルゴリズムは、アリスが単一要素の配列を削除できるようにすることで、単一要素の配列を正しく処理し、合計が 0 になります。ボブのフリップ数が残りの要素の数を超えると、Python のスライス操作はエラーなしで残りのすべての要素を安全に反転します。 繰り返しの要素または最大サイズの要素を含む配列も、操作が極値要素の並べ替えと選択のみに依存するため、正しく処理されます。 これにより、問題で指定されたすべてのエッジ条件にわたって解決策が機能することが確認されます。
