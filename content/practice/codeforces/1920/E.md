 ## 解決策
 ## 問題の理解

 バイナリ文字列の数を数えるよう求められます。そのようなバイナリ文字列の数は、正確に 1 つを含む部分文字列の総数になります。`1`指定された数値に等しい`n`、そのような部分文字列の長さが指定された最大値を超えることはありません。`k`。 部分文字列は、単に文字列の連続した部分です。 異なる位置に出現する部分文字列はそれぞれ個別にカウントされるため、`1010`、部分文字列`10`は 2 回発生し、それぞれが独立してカウントされます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは 2 つの整数が与えられます。`n`そして`k`。 タスクは、テスト ケースごとに、これらの条件を満たすバイナリ文字列の数をモジュロで出力することです。`998244353`。 

この制約により、すべてのテスト ケースの合計を含めて、最大 2500 のテスト ケースが許可されます。`n`すべてのテスト ケースの値も 2500 以下です。これは、`O(n^2)`テストケースごとのソリューションは実現可能です。 長さのバイナリ文字列の数が制限されるため、すべての文字列を生成する単純なアプローチは不可能です。`L`は`2^L`、これは大きすぎます。 

エッジケースが発生するのは次のような場合です`k = 1`。 その場合、それぞれ`1`はゼロで区切って単独で指定する必要があります。 例えば、`101`それはいいけど、`11`は、長さ 2 の部分文字列が 1 つだけ含まれているため、無効です。`1`(`11`2つあります`1`s、これは無効です) - 慎重に数える必要があります。 

## アプローチ

 ブルートフォース手法は説明するのは簡単ですが、実装するのは不可能です。 以下の長さのすべてのバイナリ文字列を反復処理できます。`n`、ちょうど 1 つを含むすべての部分文字列をカウントします。`1`、長さを超えているかどうかを確認します`k`。 長さの文字列ごとに`L`、 がある`O(L^2)`部分文字列、文字列の数は`2^L`。 のために`L ≈ 50`、これは手に負えなくなります。 

重要な観察は、問題は配置に帰着できるということです。`1`s は最大で区切られた位置にあります`k-1`ゼロ。 の位置を表すと`1`とそれらの間のゼロの数から、各構成によって生成される適切な部分文字列の数を計算できます。 

シングル`1`三角形パターンの部分文字列に寄与します: で囲まれている場合`a`左側のゼロと`b`右側のゼロ、これを含む部分文字列の合計`1`は`(a+1)*(b+1)`。 これは、左拡張子 (0 から a) と右拡張子 (0 から b) を選択した場合でも、部分文字列には 1 つだけが含まれるためです。`1`。 

これを考慮すると、動的プログラミング ソリューションを組み立てることができます。`dp[i]`正確に生成する文字列を構築する方法の数になります。`i`良い部分文字列。 新しいものごとに`1`、左側のゼロの数を繰り返します (最大`k-1`) と生成される適切な部分文字列の数を調べ、それに応じて DP テーブルを更新します。 これにより問題は次のように縮小されます`O(n*k)`テストケースごとに。

 ## アルゴリズムのチュートリアル

 1. DP 配列を初期化する`dp`長さの`n+1`どこ`dp[i]`正確に生成するバイナリ文字列の数を格納します`i`良い部分文字列。 セット`dp[0] = 1`空の文字列は適切な部分文字列を提供しないためです。 
2. の数を繰り返します。`1`を配置します。 それぞれ`1`前の値と 0 から区切ることができます。`k-1`ゼロ。 
3. 潜在的なゼロの数ごとに`z`の左側にある`1`、これで適切な部分文字列の数を計算します。`1`貢献してくれるでしょう。 これは 1 から 1 までの整数の合計です。`z+1`、つまり、`(z+1)*(prev_zeros+1)`。 
4. 値が途中で上書きされるのを避けるために、DP 配列を逆に更新します。 それぞれについて`i`から`n`0まで下げる、設定する`dp[i + contribution] += dp[i]`。 モジュロ演算を使用して、`998244353`。 
5. すべての可能な位置を処理した後、`dp[n]`条件を満たすバイナリ文字列の数が含まれます。 

正しさは次の不変条件に依存します。`dp[i]`正確に到達する方法の数を常に数えます`i`適切な部分文字列と、`1`特定の数の前にゼロを付けると、最大部分文字列長の制約と一致するすべての構成が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(t)]
    max_n = max(n for n, k in queries)
    
    results = []
    
    for n, k in queries:
        dp = [0] * (n + 1)
        dp[0] = 1
        
        for ones in range(1, n+1):
            ndp = [0] * (n + 1)
            for prev in range(n + 1):
                if dp[prev] == 0:
                    continue
                for length in range(1, k+1):
                    if prev + length > n:
                        break
                    ndp[prev + length] = (ndp[prev + length] + dp[prev]) % MOD
            dp = ndp
        results.append(dp[n])
    
    print('\n'.join(map(str, results)))

solve()
```この実装では、それぞれに対して DP 配列を繰り返し構築します。`1`追加した。 ネストされたループ`length`(1から`k`) 許容される最大長を尊重しながら、適切な部分文字列が寄与する可能性を考慮します。 

微妙な点は、更新を順方向または逆方向で繰り返すことです。`dp`- ここでは前方に進むのが安全です。`ndp`毎回新たに割り当てられます。 モジュロ演算によりオーバーフローが防止されます。
