 ## 問題の理解

 順列を受け取ります`p[1..n]`～のすべての値を含む`1`に`n`まさに一度。 入力シーケンスは左から右にのみ使用できます。 消費されたすべての値は、使用可能なスタックの 1 つにプッシュされ、後でスタックの最上位の値が回答に追加されるか、別のスタックに移動されます。 最終出力は正確に次のようにする必要があります。`1, 2, ..., n`。 

課題は、これを可能にする最小のスタック数を見つけることです。 

重要な驚きは、答えがこれより大きくなることは決してないということです。`2`。 1 つのスタックでは、一部の順列はすでにソートできますが、1 つのスタックでソートできないすべての順列は 2 つのスタックで処理できます。 したがって、問題全体は、指定された順列が有効な単一スタック出力シーケンスであるかどうかを認識することに帰着します。 

以来`n`到達できる`10^5`、二次動作のアルゴリズムにはすでに約`10^10`最悪の場合、基本的な操作が行われますが、これは 1 秒のコンテスト制限が許容できる範囲をはるかに超えています。 必要なのは`O(n)`または`O(n log n)`解決。 順列プロパティは、すべての値が一意であることも意味するため、等しい要素を本物のケースとして扱う必要はありません。 

不注意なシミュレーションを欺いてしまう可能性のあるエッジケースがいくつかあります。 のために`n = 1`、順列`[1]`必要なスタックは 1 つだけなので、答えは次のようになります。`1`。 少なくとも 1 つの要素がスタック内に残る必要があると想定する単純な実装では、誤った値が返される可能性があります。`2`。 

次のようなすでに増加する順列の場合、`1 2 3`、答えも`1`。 すべての値は消費され、すぐに出力されます。 すべての入力値を最初にプッシュする実装では、不必要にスタック状態が作成されます。`[1, 2, 3]`、そのトップは`3`、スタックが 1 つでは不十分であると誤って結論付ける可能性があります。 

重要な失敗パターンは、`2 3 1`。 最初の 2 つの値は、`1`スタック状態を与えて出力することができます`[2, 3]`。 後`1`生産され、`2`下に閉じ込められている`3`なので、1 つのスタックでは出力できません。`2`次。 正しい答えは、`2`。 順列に減少ペアが含まれているかどうかだけをチェックするか、最も長い減少部分列が特定の長さを持っているかだけをチェックする不注意な実装では、そのようなケースを誤って分類する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、あらゆる数のスタックを試し、合法的な操作を明示的に調査できます。 固定構成の場合、各入力値を異なるスタックに割り当てることができ、最上位の値を出力前にスタック間で移動することもできます。 同じ値をさまざまなスタックを介して多くの順序でルーティングできるため、可能な操作シーケンスの数は指数関数的に増加します。 検索を可能なすべてのスタック割り当てに制限しても、すでに次のようになります。`k^n`～の可能性`n`入力値と`k`スタックする場合、それは絶望的です`n = 10^5`。 

より合理的な単純なアプローチは、標準のスタック ソート プロセスをシミュレートすることによって、1 つのスタックが機能するかどうかをテストすることです。 ターゲット出力は強制されます。次に必要な値は常に`1`、 それから`2`、 それから`3`、 等々。 次の入力値が必要な値であれば、すぐに出力できます。 それ以外の場合は、スタックにプッシュする必要があります。 スタックトップが次に必要な値になるたびに、それをポップします。 

重要な観察は、この貪欲なプロセスにより、1 つのスタックで十分かどうかが完全に決定されるということです。 出力は増加する必要があるため、必要な値をスタックの最上位に残しておくことに利点はありません。 同様に、次の入力値が必要な出力値である場合、それを遅らせても役に立ちません。 

その結果、スタック数に対するブルートフォース検索をさらに減らすことができます。 1 つのスタックと複数のスタックを区別する必要があるだけです。 順列が 1 スタックのシミュレーションに合格した場合、答えは次のようになります。`1`。 それ以外の場合の答えは、`2`なぜなら、すべての順列には 2 つのスタックで十分だからです。 最初のスタックに次に必要な値をブロックする要素が含まれている場合、2 番目のスタックは一時ストレージとして使用できます。 これがまさに、この問題の一見一般的なマルチスタック操作モデルが二項対立の答えに崩壊する理由です。 

1 スタック条件は、古典的なスタックでソート可能な置換パターンを回避することにも相当します。`231`ただし、シミュレーションの実装は、禁止パターンを明示的にチェックするよりも簡単で、エラーが発生しにくくなります。

 ## アルゴリズムのチュートリアル

 1.セット`need = 1`、という意味です`1`は、並べ替えられた出力に表示される必要がある次の値です。 空の補助スタックを作成します。 すべての必要な値が順番に生成できるかどうかのみを考慮するため、出力自体を保存する必要はありません。 
2. 左から右へ順列を処理します。 現在の入力値が等しい場合`need`、消費してすぐに増加します`need`1つずつ。 この値はすでに、最終的な増加シーケンスで必要とされる次の値とまったく同じであるため、これは最適です。 
3. 現在の入力値が正しくない場合`need`、それをスタックにプッシュします。 必要な昇順に違反するため、まだ出力できません。 
4. すべての入力値が処理された後、スタックトップを繰り返しチェックします。 上位は同等ですが、`need`、ポップして増やします`need`。 この貪欲なポップは強制されます。最高値は出力の準備ができており、それをそこに保持しておくと、将来の配置を改善することはできません。 
5. 結局のところ`n`入力値が消費されている場合は、スタックを検査してください。 空の場合、すべての値が必要な順序で出力されているため、スタックは 1 つで十分であり、答えは次のようになります。`1`。 
6. スタックが空でない場合、1 つのスタックは順列をソートできません。 2 つのスタックで十分なので、答えは次のとおりです。`2`。 

### なぜ効果があるのか

 不変条件は、入力の接頭辞を処理した後、すべての値が より小さいことです。`need`スタックに現在格納されているすべての値が順番を待っている間、必要な順序で正確に出力されています。 いつでも`need`がスタックトップにある場合、最終シーケンスは最初にそれより大きなものを出力できないため、それをすぐに出力することが必須です。 現在の入力が等しいときはいつでも`need`、最初にそれをスタックに入れても、すでに利用可能な正しい出力が遅れるだけです。 

したがって、貪欲シミュレーションは、正当な 1 スタックの実行が存在する場合に正確に成功します。 要素が残された場合、それらの要素は 1 つの LIFO 構造内で十分に再配置されず、欠損値を順番に生成することができません。 一般的な 2 スタック構造では、次の上限が得られます。`2`、つまり、失敗した 1 スタックのケースには最小の答えが正確にあります。`2`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        stack = []
        need = 1

        for x in p:
            if x == need:
                need += 1
            else:
                stack.append(x)

            while stack and stack[-1] == need:
                stack.pop()
                need += 1

        ans.append("1" if not stack else "2")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`need`は、最終的な並べ替えシーケンスにまだ配置されていない最小値を表します。 から始まります`1`そして届く`n + 1`処理が成功した後。 

リスト`stack`は、1 スタック テストで使用できる唯一のスタックを表します。 現在の順列値がすぐに使用できない場合は、このリストにプッシュされます。 パイソンの`append`スタックプッシュをモデル化しますが、`pop`一番上の要素を削除します。 

の`while`単一ではなくループが必要です`if`。 新しく消費された値の 1 つが、その下にある別の必要な値を公開する可能性があります。 たとえば、順列を使用すると、`3 2 1`、3 つの値すべてがプッシュされてから、一番上のシーケンスがプッシュされます。`1, 2, 3`連続でポップできる。 この繰り返しのポップを見逃すことは、スタック シミュレーションにおける一般的なオフバイワン エラーです。 

のためのテスト`x == need`押す前に起こる`x`。 受信した値が次に必要な値である場合、スタックに入れる必要はありません。 これにより、次のような増加順列が可能になります。`1 2 3`保存されたものを何も残さずに 1 つのスタックを使用して処理されます。 

すべての値が最大値であるため、整数オーバーフローの問題はありません。`10^5`、そして Python 整数はとにかくカウンターを直接処理します。 保存されたデータの総量は次のように線形です。`n`。
