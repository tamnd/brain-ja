 ## 解決策
 ## 問題の理解

 この場合、サウンド内の各音を 24 ポートの琴対に対応する演奏形式に変換する必要があります。`n`、続いて出てくる`n`各音符は数字で構成されています`1`到`7`基本音阶、数字後ろを示します`+`升高一八度を示す、`-`2 つの記号が継続して出現することは、2 つの平坦度が下がることを示し、2 つの平坦度が変化することを示します。`0`休止を示します。 

私たちが実際に判断する必要があるのは、音符が１つの八度にあるということではなく、対応する口琴の音の配列が、異なる八度にわたって同じ基本的な音の演奏様式に属するかどうかである。`5`、`5-`和`5--`プログラムは、数字部分に基づいて処理されることだけを必要とします。`0`则出`X`。 

24 ポートの琴の音配列は、各階調で一定の規則を持っています。`1`、`3`、`5`吹气であるために、`2`、`4`、`6`、`7`必要な文字に置き換えます。`1 -> E`、`2 -> I`、`3 -> E`、`4 -> I`、`5 -> E`、`6 -> I`、`7 -> I`。`n`最大は 100 だけなので、非常に直接的な処理方法を使用しても 1 には影響しません。 ここでは、入力された文字ごとに数桁の文字を判断する必要があるだけであり、計算全体の量は数百回の基本的な動作レベルに達する必要はない。`O(n)`これはすでに十分であり、さらに入力が必要な量でもあります。 

問題が発生しやすいのは、主に八度シンボルと休止符の処理に集中する場合です。`3 3+ 3-`時，三音符都是音阶 3，应的出应该是`EEE`プログラムがあれば`+`または`-`異なる音符で映り直すと、結果が得られる可能性があります。```
3
3 3+ 3-
```正确出力:```
EEE
```第二边界情况は休止符`0`デジタル音声ではないため、通常のデジタル映写はできません。```
1
0
```正确出力:```
X
```如果程序直接使用類似`mapping[token[0]]`の辑、却下されていない`0`単独で処理すると、問題が発生する可能性があります。 

3 番目の簡単な状況は、低八度が連続して多数の可能性があることです。`-`例：```
3
5-- 7+ 1
```正确出力:```
EIE
```ここ里`5--`然し照音阶 5 判断、`7+`密度情報は、高い音を決定するが、要求される吸気または吹気には影響を与えない。 

## アプローチ

 最も直接的な方法は、各入力音に対して、数字と 8 度記号に基づいて実際に対応する音の高さを決定し、次に 24 個のポートを検査することです。 この方法は、この音が最も高い位置にある孔の位置を追跡し、最終的に、その孔の位置が気体であるか吸気であるかに応じて出力される。 孔口琴の完全な音の図は、それ自体が有限の放射であり、孔は対応する位置に到達するのに限界がある。 

しかし、このような方法が暴力的検索として知られているとしても、実際にはそれは現実的ではない。`n = 100`，每个音符最检查 24 个孔，故に最只有`100 × 24 = 2400`これは、１秒未満の処理量に比べて少ない。 

この問題に真に適した方法は、より具体的な見解から得られたものである。我々は、具体的にどの孔であるかを知る必要はなく、この音が異なるレベルでの吹奏方法が同じであることだけを知っていればよい。`+`和`-`したがって、各入力文字列の最初の文字をただちに検査するだけでよい。 

から`1`到`7`固定マッピングを直接構築できます。`1`、`3`、`5`是吹气、输出`E`；`2`、`4`、`6`、`7`は吸气、输出`I`最初の文字が次の場合`0`、出ます`X`各音声は定期的な操作のみを実行するため、プロセス全体が連続的になります。 

暴力的方法の価値は、対象の口琴音の図を直接表示することができますが、多くは不必要な動作を実行します。 「孔内での聴取音の高さ」が「音を観察する基本的な音の高さ」にまで低下し、これにより理想的な実現が得られる。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(24n) = O(n) | お(1) | 受け入れられますが、不要です |
 | 最適 | O(n) | 出力文字列の場合は O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.读取音符数`n`、再註次来的`n`各音符文字列。各文字列は通常の数字、記号である可能性があります。`+`的音符、带`-`の音符、または`0`。 
2. 各音を段階的に処理します。八度変換シンボルは音の高さを変えるだけで、口琴上のこの基本音の吹奏方法は変更しないため、文字列の最初の文字だけを検査します。 
3. 如果当前音符是`0`、掴む`X`応答案を追加します。`0`これは、口琴孔での聴取が必要なサウンドボタンではなく、休止状態を示します。 
4. 如果当前音符所属`1`、`3`、`5`、掴む`E`この３つの基本音は、対応する２４穴の琴音配列に加えられる。 
5.如果当前音符所属`2`、`4`、`6`、`7`、掴む`I`これらのサウンド ボタンには吸気ガスが使用されています。 
6. すべての音の処理が完了したら、得られた文字を順次接続して出力します。`i`个字符只由第`i`どの入力音も決まっているため、前後の音の間の状態を気にする必要はありません。 

### なぜ効果があるのか

 算法の核心不変量とは：処理から第`i`音符の後、答案文字列の前`i`个字符好描写前`i`入力音の吹奏方式。非休止音の場合、その最初の文字が基本音になります。`1`到`7`，而して`+`、`-`八度の変化を示すだけであり、この基本音の吹き出し方式は変更しないため、固定マッピングは唯一の正しい文字を取得することができます。`0`，算法直出`X`各音は独立して処理されるため、この特性は最初の音から最後の音まで保持され、最終的には正しいものとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    notes = input().split()

    mapping = {
        '1': 'E',
        '2': 'I',
        '3': 'E',
        '4': 'I',
        '5': 'E',
        '6': 'I',
        '7': 'I',
        '0': 'X'
    }

    ans = []
    for note in notes:
        ans.append(mapping[note[0]])

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```程序首先建立`mapping`、基本的な音と出力文字を対にします。`0`同じスクリーンを放った後も、処理は完了し、サイクル内に特別なフラグを追加する必要はありません。 

循環中`note[0]`たとえば、関連付けられたプロトコルです。`5--`の最初の文字は`5`、`7+`の最初の文字は`7`したがって、当然のことながら、各音声が正規の形式で入力されるため、文字列が空であるかどうかを検査する必要はない。 

最後に使用`''.join(ans)`すべての文字が結合されて 1 つの文字列になります。循環中に頻繁に使用される文字列を結合して応答を構成することはできません。`n`100 個だけであれば、重大なパフォーマンスの問題は発生しませんが、リストの収集後の接続はより厳密な文字列構造方式になります。 

题目中的`n`2行目の音数と一対になります。`split()`读取整行、したがって多くの空格も通常の処理が可能であり、受け入れられません`+`、`-`等記号の影響。

## テストケース

import sys
import io

input = sys.stdin.readline

def solve():
    n = int(input())
    notes = input().split()

    mapping = {
        '1': 'E',
        '2': 'I',
        '3': 'E',
        '4': 'I',
        '5': 'E',
        '6': 'I',
        '7': 'I',

    ans = []
    for note in notes:
        ans.append(mapping[note[0]])

    return ''.join(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve()
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 八度記号について、入力`3`、`3+`和`3-`の領域は高音のみであるため、要求されるのは吸気である。```
3
3 3+ 3-
```程順に三字を取り出して、最初の一字符、三字に達する`3`、再び映射によって得られた`E E E`，最終出`EEE`場合は、完全な文字列を字典として使用し、確立されただけです`3`的映射，就会在`3+`または`3-`上は失われています。 

休止符について、入力：```
1
0
```文字列の最初の文字です`0`，而映射表专门将`0`設置場所は`X`、したがって出力されます`X`この処理では処理できません。`0`現在普通の音阶であるため、`0`対応する噴霧または吸気動作はありません。 

複数の八度記号について、入力：```
3
5-- 7+ 1
```最初に取得した最初の文字`5`，映射する`E`；二番目に得たもの`7`，映射する`I`；三番目に得た`1`，映射する`E`最終的な出力`EIE`ここでは説明は必要ありません`+`または`-`の数は、昇圧なしでも 2 つの等高さであるため、両方とも吸気タイプを変更することはありません。 

边界音阶について`1`和`7`，输入：```
2
1 7
```程順に到達`E`和`I`，出：```
EI
```この 2 つのサウンドボタンはそれぞれ基本サウンド スクリーンの両端にあり、フレームが書き取られているかどうかを検出できます。`2`到`6`あるいは、すべての奇数音に空気を吹き込むことが規則的に認められています。`1`、`3`、`5`吹气，而`7`同じく空気に属するため、完全な反射が７つの音域を個別に覆う必要がある。
