 ## 解決策
 ## 問題の理解

 (m) 個の既存のマテリアルがあり、それぞれが小文字の文字列 (s_i) で表されます。 新しいマテリアルは、その文字列の長さが正確に (n) であれば許容されますが、既存の (s_i) の連続した部分文字列として出現してはなりません。 出力する必要があるのはそのような文字列を 1 つだけであり、ステートメントはその文字列が存在することを保証します。 

問題を考察する便利な方法は、化学用語を忘れて純粋な文字列の質問をすることです。長さ (n) のすべての (26^n) 個の小文字文字列の中から、入力文字列の長さ (n) 個のすべての部分文字列のコレクションに存在しない文字列を見つけます。 

しましょう

 [
 S=\sum_i |s_i|。 
]

 (S\le 3\times 10^5) になりますが、(n) は (10^5) まで大きくなる可能性があります。 これにより、(26^n) に依存するアルゴリズムが即座に除外されます。これは、(26^{10}) でさえすでに列挙できるものをはるかに超えているためです。 また、すべての入力文字列に対してすべての候補を直接チェックすることも除外されます。 入力自体の合計は数十万文字にすぎないため、目的のソリューションでは入力をほぼ線形に処理する必要があります。 

特に有用な計数観察があります。 文字列 (s_i) には、長さ (n) 個の部分文字列の異なる開始位置が最大で (|s_i|-n+1) 個含まれるため、個別の禁止文字列の総数は最大で

 [
 \sum_i \max(0, |s_i|-n+1)\le S.
 ]

 したがって、考えられる答えは (26^n) 通りありますが、実際に禁止できるのは最大でも (3\times10^5) 個です。 必要なのは、少数の候補者を列挙し、メンバーシップを迅速にテストする方法だけです。 

エッジ ケースの 1 つは、既存のすべての文字列が (n) より短い場合です。 例えば、```
3 2
a
bc
```長さ 3 の部分文字列はどこにもないので、`aaa`はすでに有効な答えです。 すべての入力文字列が少なくとも 1 つのウィンドウに寄与すると仮定する不注意な実装では、不正確なループ境界または空の候補セットが生成される可能性があります。 

最初の候補は存在するが、次の候補が存在しない場合、別のエッジ ケースが発生します。 例えば、```
3 1
aaaa
```文字列`aaa`発生しますが、`aab`しません。 正しい出力は次のとおりです。`aab`。 などの繰り返し文字候補のみをチェックする実装`aaa`、`bbb`などは有効な回答を見逃してしまいます。

## アプローチ

 直接的な総当たりアプローチは概念的に単純です。 長さ (n) の (26^n) 個の小文字文字列をすべて列挙し、各候補について、それが入力文字列に出現するかどうかを確認します。 単純な部分文字列マッチングを使用すると、1 つの候補をチェックするのに最悪の場合 (O(Sn)) 時間がかかる可能性があります。 

[
 O(26^nSn)。 
]

 完全な検索構造を使用して部分文字列メンバーシップが (O(1)) に削減されたとしても、(26^n) 個の候補を列挙するだけでは、(n) が大きい場合はすでに不可能です。 ブルート フォースは完全な応答空間を検査するので正しいのですが、応答空間は入力よりも指数関数的に大きくなります。 

重要な点は、入力では線形数の長さ (n) の文字列のみを禁止できるということです。 すべての入力文字列にわたって、最大で (S) 長さ - (n) 個のウィンドウが存在します。 したがって、最大 (S+1) 個の個別の候補を検査した後、少なくとも 1 つの候補が欠落している必要があります。 

これにより問題は完全に変わります。 すべての (26^n) 文字列を理解する必要はありません。 辞書編集順に候補を列挙し、禁止された部分文字列のフィンガープリントのセットに属さないフィンガープリントを見つけたらすぐに停止できます。 

ローリング多項式ハッシュを使用すると、各長さ (n) のウィンドウのフィンガープリントをウィンドウごとの (O(1)) の償却時間で計算できます。 これらすべてのフィンガープリントをハッシュ セットに保存します。 次に、次で始まる候補文字列を列挙します。`aaa...a`、 に続く`aaa...b`、 等々。 候補は 26 進数のカウンターとして維持でき、そのハッシュは変化する位置に応じて更新できます。 (K) 個の連続する候補全体で、変更された末尾位置の合計数は (O(K)) であるため、候補の生成も候補の数において線形です。 

ハッシュ化により、通常、衝突の可能性が生じます。 大きな素数係数 (2^{61}-1) を使用し、基数をランダムに選択します。 衝突によって禁止された候補も禁止されたように見える可能性があるため、検索が遅れるだけで、実際に存在する文字列が出力されることはありません。 ランダム化された 61 ビット多項式ハッシュでは、意図した複雑さに影響を与えるほどの衝突の可能性は無視できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(26^nSn)) | (O(n)) | 遅すぎる |
 | ローリング ハッシュ + 候補の列挙 | 期待される (O(S+n)) | (O(S+n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) と既存のすべての文字列を読み取り、ランダムな多項式ハッシュ ベースを選択します。 素数法 (P=2^{61}-1) を使用します。これにより、Python の整数演算を管理しやすくしながら、非常に大きなハッシュ スペースが得られます。 
2. 事前計算 (B^n\bmod P)。 これは、長さ (n) のローリング ウィンドウが 1 つ右に移動するときに最も古い文字を削除するために必要な係数です。 
3. 長さ (n) のローリング ウィンドウを使用してすべての入力文字列をスキャンします。 文字列が (n) より短い場合は、禁止された候補にはなりません。 それ以外の場合は、すべての長さ (n) ウィンドウのハッシュを計算し、それをセットに挿入します。 
4. 候補を次のように初期化します。`a`(n) 回繰り返します。 その多項式ハッシュは、すべての文字が値 (1) を持つという事実から計算されます。 これは、辞書編集上可能な最小の長さ (n) 文字列です。 
5. 候補ハッシュが禁止ハッシュ セットに存在するかどうかを確認します。 存在しない場合は、直ちに候補を出力します。 入力文字列に出現する候補は、保存されているウィンドウの 1 つとまったく同じハッシュを持っている必要があるため、ハッシュが欠落している場合は、候補が存在しないことが証明されます。 
6. 候補が禁止されている場合は、26 進数でインクリメントします。 最後の位置から開始し、後続のすべての位置`z`になる`a`、そして最初の非`z`キャラクターが1つ増えます。 変更された位置ごとに、変更に適切な塩基のべき乗を乗算して、候補ハッシュを更新します。 
7. 欠落しているハッシュが見つかるまで、メンバーシップのチェックと増分を繰り返します。 (S) 個を超える個別の禁止文字列は存在できないため、最大で (S+1) 個の個別の候補の後で、無視できるハッシュ衝突の確率を無視して、有効な答えが表示されなければなりません。 

これが機能する理由: 禁止ハッシュ セットには、既存のすべてのマテリアルの実際の長さ (n) の部分文字列すべてのフィンガープリントが含まれています。 候補の列挙では、辞書編集順に異なる長さ (n) の文字列を参照します。 そのハッシュがセットに存在しない場合は常に、候補は既存の長さ (n) の部分文字列と一致することができないため、有効な新しいマテリアルとなります。 入力には合計で最大 (S) 長さ (n) 個のウィンドウを含めることができるため、(S) 個を超える個別の候補を禁止することはできません。 したがって、最初の (S+1) 個の候補の 1 つが有効でなければなりません。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

MOD = (1 << 61) - 1

def solve():
    n, m = map(int, input().split())

    # Randomized base makes adversarial hash collisions extremely unlikely.
    base = random.randrange(256, MOD - 1)

    pow_n = pow(base, n, MOD)

    forbidden = set()

    for _ in range(m):
        s = input().strip()
        if len(s) < n:
            continue

        h = 0

        # Hash of the first window.
        for i in range(n):
            h = (h * base + (ord(s[i]) - 96)) % MOD
        forbidden.add(h)

        # Roll the window.
        for i in range(n, len(s)):
            old = ord(s[i - n]) - 96
            new = ord(s[i]) - 96
            h = (h * base + new - old * pow_n) % MOD
            forbidden.add(h)

    # Candidate is represented by values 0..25.
    # Its polynomial character values are values + 1.
    candidate = bytearray(b'a' * n)

    # Hash of a^n.
    h = (pow(base, n, MOD) - 1) * pow(base - 1, MOD - 2, MOD) % MOD

    # The formula above is the geometric sum:
    # 1 * base^(n-1) + ... + 1.
    #
    # Handle base == 1, which is astronomically unlikely but easy to avoid.
    if base == 1:
        h = n % MOD

    powers = [1] * n
    for i in range(1, n):
        powers[i] = powers[i - 1] * base % MOD

    while True:
        if h not in forbidden:
            sys.stdout.write(candidate.decode())
            return

        # Increment the base-26 number.
        pos = n - 1

        while pos >= 0 and candidate[pos] == ord('z'):
            # z -> a changes the character value from 26 to 1.
            h = (h - 25 * powers[n - 1 - pos]) % MOD
            candidate[pos] = ord('a')
            pos -= 1

        if pos < 0:
            # The statement guarantees that an answer exists.
            return

        # Increase the first non-z character by one.
        h = (h + powers[n - 1 - pos]) % MOD
        candidate[pos] += 1

if __name__ == "__main__":
    solve()
```入力文字列は一度に 1 つずつ処理されるため、すべてをメモリに保持する必要はありません。 少なくとも (n) の長さの文字列の場合、最初のウィンドウは直接ハッシュされます。 Every subsequent window is obtained from the previous hash by multiplying by the base, adding the new character, and subtracting the old character multiplied by (B^n).

 候補は次のように保存されます。`bytearray`これにより、検索中に Python 文字列を繰り返し構築することがなくなります。 その文字は (1) から (26) までの値として扱われますが、バイト値自体は ASCII コードです。`a`に`z`。 

候補ハッシュは、base-26 カウンタがインクリメントされるときにローカルで更新できます。 ポジションが変更された場合`a`に`b`、そのハッシュ寄与は (B^k) だけ増加します。 から変わる場合`z`に`a`、その寄与は (25B^k) 減少します。 指数 (k=n-1-\text{pos}) は、まさにその右側の位置の数です。 

累乗配列には、この指数によってインデックスが付けられます。 そもそも候補者がスタートするから`a`、その初期ハッシュは幾何学和 (1+B+\cdots+B^{n-1}) です。 特別な`base == 1`ブランチは、幾何学和の公式におけるゼロによる除算を回避しますが、ランダムな選択によりそのイベントは事実上不可能になります。 

整数には任意の精度があるため、Python では整数オーバーフローの問題は発生しません。 モジュラスは各算術更新の後に適用され、保存されたハッシュが (2^{61}) で区切られた状態に保たれます。

import random

MOD = (1 << 61) - 1

def solve_data(inp: str) -> str:
    data = inp.split()
    it = iter(data)

    n = int(next(it))
    m = int(next(it))

    base = random.randrange(256, MOD - 1)
    pow_n = pow(base, n, MOD)

    forbidden = set()

    for _ in range(m):
        s = next(it)

        if len(s) < n:
            continue

        h = 0
        for i in range(n):
            h = (h * base + ord(s[i]) - 96) % MOD
        forbidden.add(h)

        for i in range(n, len(s)):
            old = ord(s[i - n]) - 96
            new = ord(s[i]) - 96
            h = (h * base + new - old * pow_n) % MOD
            forbidden.add(h)

    candidate = bytearray(b'a' * n)

    powers = [1] * n
    for i in range(1, n):
        powers[i] = powers[i - 1] * base % MOD

    if base == 1:
        h = n % MOD
    else:
        h = (pow(base, n, MOD) - 1) * pow(base - 1, MOD - 2, MOD) % MOD

    while True:
        if h not in forbidden:
            return candidate.decode()

        pos = n - 1

        while pos >= 0 and candidate[pos] == ord('z'):
            h = (h - 25 * powers[n - 1 - pos]) % MOD
            candidate[pos] = ord('a')
            pos -= 1

        assert pos >= 0, "The original problem guarantees an answer."

        h = (h + powers[n - 1 - pos]) % MOD
        candidate[pos] += 1

3 1
a
""") == "aaa", "sample 1"

# Provided sample 2.
assert solve_data("""\
3 2
ac
ak
""") == "aaa", "sample 2"

# Minimum n. Every character except z is forbidden.

# Off-by-one case: aaa occurs in aaaa, but aab does not.

```候補者はアルファベットに到達するまで一度に 1 文字ずつ移動します。`z`。 1 文字の文字列の列挙ロジックには特別なケースはありません。
