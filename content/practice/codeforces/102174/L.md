 ## 解決策
 ## 問題の理解

 都市は有向非巡回グラフを形成し、旅は都市 1 から始まります。旅行者は都市に到着すると、決定を下す前に 1 日かけて観光します。 

現在の都市に (d>0) 個の鉄道の発信端があると仮定します。 翌日には、(d+1) 通りの可能性の選択肢があります。(d) の下り列車のいずれかに乗るか、もう 1 日観光に滞在するかです。 宿泊した場合は再度宿泊することはできませんので、翌日は一律(d)下り列車のいずれかを選択しなければなりません。 外部へのエッジのない都市はターミナルシティであり、そこで合計 2 日間を過ごし、旅は終了します。 

入力には、(T) 個の独立したテスト ケースが含まれています。 各テスト ケースでは、(n) 個の都市と (m) 個の有向鉄道エッジが与えられます。 グラフは DAG であることが保証されていますが、都市の番号付けがトポロジカルな順序であることは保証されていません。 モジュロ (998244353) で表される、都市 1 から始まる予想合計日数が必要です。 

境界 (n,m\le 10^5) が主要なアルゴリズム信号です。 二次アルゴリズムは、1 つの大きなテスト ケースに対して約 (10^{10}) 個の演算を実行できますが、これは 1 秒の制限をはるかに超えています。 DAG には指数関数的に多くの個別のパスが含まれる可能性があるため、すべての可能なルートの列挙に依存するアルゴリズムであっても絶望的です。 仕事が基本的にグラフ サイズ、つまり (O(n+m)) に比例する解が必要です。 

不注意な実装が間違っている可能性があるいくつかの特殊なケースがあります。 最小のグラフは```
1
1 0
```発信エッジはありませんが、旅行者は依然として唯一の都市で 2 日間を過ごします。 正しい答えは、`2`。 ゼロ出次数をゼロ将来コストとして扱い、2 番目の観光日を忘れる実装では、次の出力が出力されます。`1`。 

1 つの発信エッジを持つ都市も、確率計算で特別な処理を必要とします。 のために```
1
2 1
1 2
```都市 2 は 2 日を提供します。 都市 1 からは、すぐに電車に乗る確率 (1/2) と、電車に乗る前に 1 日余分に滞在する確率 (1/2) があります。 都市 2 に到着する前に期待される寄与は (1+3/2=5/2) であるため、合計は (9/2) となり、そのモジュラー表現は次のようになります。`499122181`。 滞在確率を (1/(d+1)) ではなく (1/d) に置き換えると、間違った結果が得られます。 

都市番号が位相順序を形成すると仮定することもできません。 例えば、```
1
3 2
1 3
3 2
```都市 2 は都市 3 の前に処理され、都市 3 は都市 1 の前に処理される必要があります。単純に (n) から (1) にループする DP は一部のグラフでは機能しますが、ここでは正確性の保証はありません。 

最後に、到達できない都市は答えに影響しません。 のために```
1
3 0
```旅行者は都市 1 から出発し、2 日後にそこで終了します。 都市2と都市3は関係ありません。 答えでは都市 1 の値のみが使用されるため、すべての都市の DP 値を計算しても問題ありません。 

## アプローチ

 直接的な総当りアプローチでは、あらゆる可能性のある旅をシミュレートすることになります。 (d) 下り端がある都市では、当面の列車の選択と滞在の可能性に分岐し、滞在後に再び下り端を越えて分岐します。 完全なルートごとに、その期間と確率を計算し、寄与を合計することができます。 

これは正しいです。期待値は、考えられるすべての行程にわたる確率で重み付けされた合計であるためです。 問題は走行回数です。 (i<j) のすべてのエッジ (i\to j) を含む DAG には、都市 1 から都市 (n) までの (2^{n-2}) 個の個別のパスがあります。これは、中間都市のすべてのサブセットが昇順に出現する可能性があるためです。 停止の決定により、状態空間に分岐が追加されます。 (n=10^5) の場合、(2^{99998}) でさえ列挙できるものをはるかに超えています。 

各行程を独立して評価できるため、総当り攻撃は機能しますが、多くの異なる行程が同じ都市を繰り返し通過するため、失敗します。 重要な観察は、都市に到着すると、予想される残りの所要時間はその都市にのみ依存し、そこに到達するまでに使用された歴史には依存しないということです。 その期待値を DP 状態として保存できます。 

遷移確率にはもう 1 つ便利な単純化があります。 都市に (d>0) 個の出力エッジがある場合、各直近の列車の選択の確率は (1/(d+1)) になります。 滞在にも確率 (1/(d+1)) があり、滞在後の各出エッジは確率 (1/d) で選択されます。 したがって、最終的に特定の出力エッジを取得する合計確率は次のようになります。 

[
 \frac{1}{d+1}+\frac{1}{d+1}\cdot\frac{1}{d}
 =\frac{1}{d}。 
]

 したがって、追加の観光日の可能性を考慮した後、次の都市は単に外出する近隣都市に均一に配分されます。 

(f_u) を、旅行者が都市 (u) に到着したばかりの時点で、そこを観光するまでの予想残り日数とします。 (d=0) の場合、

 [
 f_u=2。 
]

 (d>0) の場合、最初の観光日は 1 日かかります。 その後、電車に乗ると 1 日かかりますが、最初に滞在する場合は電車までにさらに 1 日かかります。 滞在する確率は(1/(d+1))なので、その時点から次の都市に到着するまでの予想費用は、

 [
 1+\左(1+\frac{1}{d+1}\右)
 =2+\frac{1}{d+1}。 
]

 次の都市は、(d) 発信する近隣都市に均一に分散され、次のようになります。 

2+\frac{1}{d+1}
 +
 \frac{1}{d}\sum_{u\to v}f_v。 
]

 グラフは非巡回であるため、すべての (f_u) は DAG に沿った遠い値のみに依存します。 トポロジカルな順序付けにより、すべての値を逆の順序で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n)) 最悪の場合 | (O(n)) 再帰の深さ | 遅すぎる |
 | 最適 | (O(n+m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 有向グラフを読み取り、すべての都市の発信近隣都市を記録します。 同時に、各都市の入次数を計算します。 indegree 値を使用すると、都市ラベルに依存せずにトポロジカルな順序を取得できます。 
2. カーンのトポロジカルソートアルゴリズムを実行します。 すべての入次数ゼロの都市をキューに入れ、繰り返し 1 つの都市を削除し、その出力する近隣都市の入次数を減らします。 グラフは DAG であることが保証されているため、最終的にはすべての都市が順序付けされることになります。 
3. (n+1) までのすべての整数の逆モジュラーを事前計算します。 出次数 (d) の都市の場合、漸化式には (1/d) と (1/(d+1)) の両方が必要です。 すべての次数は最大 (10^5) であるため、これらの分母はすべて法 (998244353) より小さいため、その逆数が存在します。 
4. トポロジーの順序付けを逆に処理します。 都市 (u) が処理されるとき、すべての発信近隣都市 (v) はすでに処理されているため、すべての (f_v) 値がわかっています。 
5. 都市 (u) に出力エッジがない場合は、(f_u=2) を設定します。 旅行者は 1 日は観光をし、電車がないのでさらに 1 日過ごします。 
6. それ以外の場合、(d) を (u) の出次数とします。 コンピューティング

 [
 f_u=
 2+\frac{1}{d+1}
 +\frac{1}{d}\sum_{u\to v}f_v
 \pmod {998244353}。 
]

 項 (2+1/(d+1)) には、現在の都市で過ごした日と次の都市への移行に費やした毎日が含まれます。 後続の値の平均により、最終的にどの発信列車が使用されるかが考慮されます。 

1. 都市 1 が開始都市であるため、出力 (f_1)。 

不変条件は、都市が逆トポロジー順序で処理される場合、その DP 値は 1 つの発信エッジによって到達可能なすべての都市の正確な値から計算されるということです。 再発自体は、その都市で起こり得るすべての決定に対する完全な期待の法則です。 すべてのエッジはトポロジー順序付けで前方に進むため、最終決定されるまで値は使用されません。 したがって、すべての (f_u)、特に (f_1) は、真の予想残り移動時間に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 100000 + 2

# inv[i] = i^(-1) mod MOD
inv = [0] * (MAXN + 1)
inv[1] = 1
for i in range(2, MAXN + 1):
    inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

def solve():
    T = int(input())
    answers = []

    for _ in range(T):
        n, m = map(int, input().split())

        graph = [[] for _ in range(n)]
        indeg = [0] * n

        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            graph[u].append(v)
            indeg[v] += 1

        # Kahn's algorithm for a topological ordering.
        queue = [u for u in range(n) if indeg[u] == 0]
        head = 0
        topo = []

        while head < len(queue):
            u = queue[head]
            head += 1
            topo.append(u)

            for v in graph[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    queue.append(v)

        dp = [0] * n

        # Every successor appears earlier in reverse topological order.
        for u in reversed(topo):
            d = len(graph[u])

            if d == 0:
                dp[u] = 2
                continue

            s = 0
            for v in graph[u]:
                s += dp[v]
            s %= MOD

            dp[u] = (
                2
                + inv[d + 1]
                + s * inv[d]
            ) % MOD

        answers.append(str(dp[0]))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```隣接リストには、繰り返しに必要な発信鉄道の選択肢が正確に保存されます。 また、トポロジカル ソートと DP の両方が一定の回数だけすべてのエッジを横断できるようになります。 

トポロジカル ソートでは、Python リストの先頭から繰り返し削除するのではなく、リストとヘッド ポインターを使用します。 前方から除去すると、前進中に操作ごとに (O(n)) のコストがかかります。`head`は一定時間です。 

逆配列はすべてのテスト ケースに対して 1 回計算されます。 逆モジュラーの漸化式は次のようになります。 

-\左\lfloor\frac{MOD}{i}\右\r床
 \オペレーター名{inv}(MOD\bmod i)
 \pmod{MOD}。 
]

 これにより、都市ごとにべき乗剰余演算を実行する必要がなくなります。 電話をかける`pow(x, MOD-2, MOD)`最大 (10^5) 度まで個別に指定すると、不必要な対数係数が追加されます。 

ゼロ出次分岐は使用する前に処理する必要があります。`inv[d]`, (1/0) が未定義であるためです。 さらに重要なのは、その期待値が 1 ではなく正確に 2 であることです。 

すべての算術演算は縮約法で行われます (998244353)。 Python の整数はオーバーフローしませんが、近傍合計と最終再帰を減らすと中間値が小さく保たれ、数学的なモジュラー計算と一致します。 

グラフは頂点番号順に並べられるとは想定されていません。 の逆走査`topo`すべてのことを保証するものです`dp[v]`によって使用される`dp[u]`はすでに利用可能です。

## テストケース```python
# The production solution above is organized around solve(), which reads
# from sys.stdin. For isolated tests, this helper temporarily replaces stdin.

import sys
import io
from contextlib import redirect_stdout

MOD = 998244353

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.read().split()
    it = iter(data)

    T = int(next(it))
    out = []

    for _ in range(T):
        n = int(next(it))
        m = int(next(it))

        graph = [[] for _ in range(n)]
        indeg = [0] * n

        for _ in range(m):
            u = int(next(it)) - 1
            v = int(next(it)) - 1
            graph[u].append(v)
            indeg[v] += 1

        queue = [i for i in range(n) if indeg[i] == 0]
        head = 0
        topo = []

        while head < len(queue):
            u = queue[head]
            head += 1
            topo.append(u)

            for v in graph[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    queue.append(v)

        max_degree = max((len(x) for x in graph), default=0)

        inv = [0] * (max_degree + 2)
        if max_degree + 1 >= 1:
            inv[1] = 1

        for i in range(2, max_degree + 2):
            inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

        dp = [0] * n

        for u in reversed(topo):
            d = len(graph[u])

            if d == 0:
                dp[u] = 2
            else:
                s = sum(dp[v] for v in graph[u]) % MOD
                dp[u] = (
                    2 + inv[d + 1] + s * inv[d]
                ) % MOD

        out.append(str(dp[0]))

    sys.stdin = old_stdin
    return "\n".join(out)

 ## 特殊なケース

 都市 1 のみで構成されるグラフの場合、```
1
1 0
```トポロジー順序には都市 1 が含まれており、逆 DP では出次数 0 がすぐにわかります。 割り当てます`dp[0] = 2`したがって、出力は次のようになります`2`。 端子ケースは別個に扱われるため、出次数による分割はありません。 

単一の鉄道エッジの場合、```
1
2 1
1 2
```逆トポロジー順序では、最初に都市 2 が処理され、それに値 2 が割り当てられます。都市 1 は次数 1 を持つため、その反復は次のようになります。 

[
 2+\frac12+\frac{2}{1}=\frac92。 
]

 モジュールの結果は次のとおりです`499122181`。 これは、追加の観光日の可能性を考慮せずに、列車の確率を 1 として扱うというよくある間違いを捉えています。 

ラベルがトポロジー的にソートされていないグラフの場合、```
1
3 2
1 3
3 2
```正しいトポロジー順序は (1,3,2) です。 逆の処理では、都市 2 の値が 2、次に都市 3 の値 (9/2)、次に都市 1 の値 (27/4) が与えられます。 モジュラー出力は次のとおりです。`249561095`。 一般に、都市番号の降順または昇順のみに基づくループでは、必要な依存関係の順序付けが提供されません。 

複数の発信エッジがある都市の場合、```
1
4 3
1 2
1 3
