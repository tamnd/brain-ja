 ## 解決策
 ## 問題の理解

 正確に (n) 文字で構成されるすべての有効な式の値の合計が必要です。 式は数字で始まり数字で終わり、演算子が隣り合うことはなく、演算子は次のとおりです。`+`そして`-`。 先頭のゼロは許可されるため、最大桁ブロックは、ゼロで始まる場合でも、単純に通常の 10 進整数として解釈されます。 必要な答えは、評価されたすべての式のモジュロ (998244353) の合計です。 公式声明とサンプルは Codeforces で入手できます。 

難しいのは、1 つの式を評価しないことです。 長さ (n) の文字列には指数関数的に多くの可能性があり、(n) が (5\times10^5) に達すると、すべての文字列をチェックすることすら絶望的になります。 最大 500 個のテスト ケースが同じ上限を共有する場合、許容可能なソリューションには、最大 (n) での基本的に線形前処理が必要で、その後、テスト ケースごとに一定の作業が続きます。 (O(n^2)) の繰り返しでは、1 秒の制限をはるかに超える、最大入力サイズでの約 (2.5\times10^{11}) の操作がすでに必要になります。 

一見自然に見える再発が問題を引き起こす可能性がある境界例がいくつかあります。 (n=1) の場合、演算子は発生しないため、10 個の式は次のようになります。`0`を通して`9`ゼロまたは (10) ではなく、(45) に貢献します。 (n=2) の場合、演算子は 2 つのエンドポイントのいずれかを占有する必要があるため、依然として発生できません。そのため、答えはすべての 2 桁の文字列の合計 (4950) になります。 すべての式に演算子があると仮定した繰り返しは、どちらの場合も失敗します。 

もう 1 つのよくある間違いは、最初の演算子の後の数字ブロックだけを数えることです。 たとえば、(n=3) の場合、次のような式になります。`1+2`そして`1-2`どちらも存在します。 それらの寄与を合計すると (3+(-1)=2) となるため、接頭辞の値は 2 倍残りますが、接尾辞の値はキャンセルされます。 このキャンセルは、効率的な再発の背後にある重要な観察です。 

先頭のゼロも重要です。 (n=2) の場合、`00`は有効な式であり、寄与はゼロですが、`09`は有効な式であり、9 に寄与します。 数字ブロックを最初の数字がゼロ以外であることを要求するのではなく、通常の文字列として扱うことが必要です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 使用可能な 12 文字にわたる長さ (n) のすべての文字列を生成し、構文規則に違反する文字列を破棄し、残りの式をそれぞれ評価して、その値を加算します。 有効性チェック前の生の文字列は (12^n) 個あるため、(n=5\times10^5) の場合、候補の数は天文学的に多くなります。 有効な式では多くの位置で演算子または数字を選択できるため、すべての有効な式を生成するだけでも指数関数的になります。 このアプローチは、必要な値を持つオブジェクトを直接列挙するので正しいですが、すぐに使用できなくなります。 

より有望なアプローチは、最初の演算子で式を分割することです。 最初の演算子が (i) 文字の後にあると仮定します。 接頭辞 (A) 自体は長さ (i) の有効な式ですが、最初の演算子で分割が行われるため、接尾辞 (B) には数字のみが含まれます。 したがって、サフィックスには正確に (10^{n-i-1}) 個の文字列が存在します。 

すべての固定ペア (A,B) に対して、(A+B) と (A-B) の 2 つの式があります。 彼らの価値観がさらに加わります

 [
 (A+B)+(A-B)=2A。 
]

 接尾語は合計から完全に消えます。 これが中心的な単純化です。最初の演算子が特定の位置にあるすべての式の寄与を計算するには、プレフィックスの合計値と、可能な数字のみのサフィックスの数だけが必要です。 

(F_n) を長さ (n) のすべての有効な式の値の合計とします。 (P_n) をすべて (n) 桁の文字列の合計とします。先頭のゼロは許可されます。 このような文字列は (10^n) 個あり、すべての数字がすべての位置に同じ頻度で出現し、次のようになります。 

[
 P_n=\frac{10^n(10^n-1)}2.
 ]

 演算子のない式は正確に寄与します (P_n)。 最初の演算子が長さ (i) の接頭辞の後に現れる式の場合、`+`そして`-`バージョンは

 [
 2F_i\cdot10^{n-i-1}。 
]

 したがって、

 [
 F_n=P_n+2\sum_{i=1}^{n-2}F_i10^{n-i-1}。 
]

 残りの問題は、この式の畳み込みです。 定義することで削除できます

 [
 S_n=\sum_{i=1}^{n-2}F_i10^{n-i-1}。 
]

 (S_{n-1}) から (S_n) にシフトすると、既存のすべての項に (10) が乗算され、(i=n-2) に対応する新しい項は (10F_{n-2}) になります。 したがって、

 [
 S_n=10S_{n-1}+10F_{n-2}。 
]

 (F_n=P_n+2S_n) なので、(S) を完全に消去できます。 

[
 \begin{整列}
 F_n
 &=P_n+20S_{n-1}+20F_{n-2}\
 &=P_n+10(F_{n-1}-P_{n-1})+20F_{n-2}。 
\end{整列}
 ]

 純粋な数の項はうまく単純化されます。 

[
 P_n-10P_{n-1}=45\cdot10^{2n-2}。 
]

 したがって、最終回帰は次のようになります。 

[
 \boxed{F_n=10F_{n-1}+20F_{n-2}+45\cdot10^{2n-2}}
 ]

 と

 [
 F_1=45、\qquad F_2=4950。 
]

 これにより、元の指数列挙が線形反復に変わります。 要求された最大値 (n) までのすべての回答を 1 回事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(12^n\cdot n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(\max n+T)) | (O(\max n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースを読み取り、要求された最大の長さ (N) を見つけます。 最大 (N) までのみを事前計算することで、より小さい入力に対する不必要な作業の実行を回避します。 
2. (10) モジュロ (998244353) の累乗を事前計算します。 再帰には (10^{2n-2}) が必要なので、(p_n=10^n) を維持して (p_{n-1}^2) を使用するのが便利な選択肢です。 
3. (F_1=45) と (F_2=4950) を設定します。 これらは演算子を使用できない場合であるため、答えは単純に 1 桁と 2 桁の文字列をすべて合計したものになります。 
4. (n\ge3) ごとに、計算します。 

[
 F_n=(10F_{n-1}+20F_{n-2}+45p_{n-1}^2)\bmod998244353。 
]

 (p_{n-1}=10^{n-1}) なので、最後の項は正確に (45\cdot10^{2n-2}) になります。 
5. (F_n) ごとに保存します。 各クエリは、事前に計算された値を直接出力することで答えることができます。 

なぜそれが機能するのかは、第一演算子分解によって要約できます。 演算子を含むすべての式には、最初の演算子が 1 つだけあります。 その前はすべて任意の有効な式 (A)、その後はすべて任意の数字列 (B) です。 最初の演算子の 2 つの選択肢は (A+B) と (A-B) に寄与し、その合計は (2A) になります。 したがって、すべての式は 1 回だけカウントされ、その寄与は反復によって表されます。 畳み込みから 2 次漸化式への代数変換では同じ量が保存されるため、保存されるすべての (F_n) は正確に必要な合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]
    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 1:
        ans[1] = 45

    if mx >= 2:
        ans[2] = 4950

    pow10 = [1] * (mx + 1)
    for i in range(1, mx + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

    for n in range(3, mx + 1):
        # 45 * 10^(2n-2) = 45 * (10^(n-1))^2
        pure_term = 45 * pow10[n - 1] % MOD * pow10[n - 1] % MOD

        ans[n] = (
            10 * ans[n - 1]
            + 20 * ans[n - 2]
            + pure_term
        ) % MOD

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

if __name__ == "__main__":
    solve()
```最初の部分では、動的プログラミングを実行する前にすべてのクエリを読み取ります。 これにより、プログラムは必要な最大長を決定し、1 つの共有事前計算を実行できます。これは、テスト ケースが数百ある可能性があるため、特に便利です。 

配列`pow10`ストア (10^i\bmod MOD)。 位置 (n) における不均一項は (45\cdot10^{2n-2}) であり、次のように計算されます。`45 * pow10[n - 1] * pow10[n - 1]`。 乗算は剰余で縮小されます`MOD`そのため、Python は 10 の膨大な正確な累乗を操作する必要がありません。 

繰り返しで使用するのは`ans[n - 1]`、`ans[n - 2]`、 そして`pow10[n - 1]`。 基底 (F_1) と (F_2) は別々に処理されます。これは、反復では最初の演算子分解後の式が記述され、前の 2 つの長さが必要となるためです。 

Python には整数オーバーフローの問題はなく、各乗算の後に削減することで中間値が小さく保たれます。 固定幅言語では、法を取得する前に、十分に幅の広い整数型を使用して乗算を実行する必要があります。

import io

MOD = 998244353

def solve():
    input = sys.stdin.readline

    t = int(input())
    queries = [int(input()) for _ in range(t)]
    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 1:
        ans[1] = 45
    if mx >= 2:
        ans[2] = 4950

    pow10 = [1] * (mx + 1)
    for i in range(1, mx + 1):

        pure_term = 45 * pow10[n - 1] % MOD * pow10[n - 1] % MOD
        ans[n] = (
            10 * ans[n - 1]
            + 20 * ans[n - 2]
            + pure_term
        ) % MOD

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

def mat_mul(a, b):
    return [
        [
            sum(a[i][k] * b[k][j] for k in range(3)) % MOD
            for j in range(3)
        ]
        for i in range(3)
    ]

def mat_pow(a, e):
    r = [
        [1, 0, 0],
        [0, 1, 0],
        [0, 0, 1],
    ]

    while e:
        if e & 1:
            r = mat_mul(r, a)
        a = mat_mul(a, a)
        e >>= 1

    return r

def max_case_expected(n):
    # State:
    # [F_n, F_(n-1), 10^(2n-2)]
    #
    # F_(n+1) = 10 F_n + 20 F_(n-1) + 45 * 10^(2n)
    #
    # The third component is multiplied by 100.
    trans = [
        [10, 20, 4500],
        [1, 0, 0],
        [0, 0, 100],
    ]

    if n == 1:
        return 45
    if n == 2:
        return 4950

    # At n = 2:
    # state = [F_2, F_1, 10^2]
    p = mat_pow(trans, n - 2)
    state = [4950, 45, 100]

    return sum(p[0][i] * state[i] for i in range(3)) % MOD

 ## 特殊なケース

 (n=1) の場合、有効な文字列は 10 桁の数字だけです。 初期化では (F_1=45)、つまり (0+1+\cdots+9) が設定されます。 反復ステップは試行されないため、より短い式への無効な参照はありません。 

(n=2) の場合、演算子は最初または 2 番目の文字のいずれかを占有する必要がありますが、両方とも禁止されています。 したがって、すべての有効な式は次の 2 桁の文字列になります。`00`を通して`99`。 初期化 (F_2=4950) により正しい結果が得られます。 

(n=3) の場合、まず演算子が可能になります。 純粋な数字列が貢献します

 [
 0+1+\cdots+999=499500。 
]

 演算子を含む式には、1 桁の接頭辞と 1 桁の接尾辞が付きます。 各プレフィックス値 (a) について、ペア`a+b`そして`a-b`貢献します(2a)。 考えられる 10 個の接頭辞と 10 個の接尾辞を合計すると、次のようになります。 

[
 2\cdot45\cdot10=900。 
]

 したがって、

 [
 F_3=499500+900=500400。 
]

 これはまさに、最初のオペレーターのキャンセルが関係する最初のポイントです。 

複数の演算子を含む式の場合、最初の演算子のみが選択されるため、分解は引き続き機能します。 たとえば、次のような表現です。`12-3+45`(A=12) として分割されます。演算子`-`、および (B=3+45) は、概念的には (B) に演算子を含めることが許可されている場合に限りますが、これは分解の対象ではありません。 代わりに、最初の演算子は後になります。`12`したがって、実際の接尾辞は数字ブロックです。`3`、残りは`+45`最初の演算子が後で選択された場合にのみ、異なるプレフィックス分解の構造に属します。 より直接的には、すべての完全な式には一意の最初の演算子が 1 つあり、その位置より前のすべては有効な式ですが、その後のすべてには演算子が含まれません。 この一意性により、二重カウントが防止されます。 

先行ゼロの場合、`00`、`007`、 そして`00042`はすべて正当な数字ブロックです。 (10^k) という用語は、正確に (k) 桁の 10 進数を持つ整数ではなく、すべての (k) 桁の文字列をカウントします。 このため、純粋な文字列の合計は次のようになります。 

[
 P_k=\frac{10^k(10^k-1)}2
 ]

 (10^{k-1}) から (10^k-1) までの整数の合計ではありません。 

(n=500000) の場合、アルゴリズムは式を構築したり、大きな 10 進数を評価したりすることはありません。 同じ繰り返しを長さごとに 1 回実行し、すべての量を法 (998244353) で減らします。 入力サイズが大きいと、線形時間反復の回数のみが変更され、解の数学的構造は変更されません。
