 ## 解決策
 ## 問題の理解

 衣類アイテムが名前によって挿入され、上部から削除され、場合によっては中央からも削除される、積み重ねのようなワードローブをシミュレートしています。 各操作はこのパイルを変更またはクエリします。 

操作は3つあります。 あ`put s`アクションにより、一意の名前が付けられた衣類アイテムが山の最上部にプッシュされます。 あ`get`アクションは、先頭の項目を削除してその名前を出力するか、または出力します。`empty`何も存在しない場合。 アン`iditarod`アクションは、山全体から名前付きの特別なアイテムを検索します。`snowcoat`。 存在する場合は、残りの項目の相対的な順序を乱すことなく、現在存在する場所から削除し、成功メッセージを出力します。 それ以外の場合は、失敗メッセージが出力されます。 

主な制約は、すべての操作をオンラインで処理する必要があり、最大 1000 個の操作があるため、操作ごとのリニア スキャンでも十分に高速であることです。 微妙な要件は、`snowcoat`スタックがその要素を中心に分割されたかのように、他のすべての項目の順序を正確に保持する必要があります。 

単純な間違いは、構造を純粋なスタックとして扱い、それを忘れることから発生します。`iditarod`中削除です。 

エッジケースの 1 つは、山が空で、`get`と呼ばれます。 正しい出力は次のとおりです`empty`。 

もう 1 つのエッジケースは次のような場合です`snowcoat`は存在しません。 その場合、`iditarod`スタックをまったく変更してはなりません。 バグのある実装により、検索中に誤って状態がポップされたり、部分的に変更されたりする可能性があります。 

3 番目のエッジケースは次のような場合です。`snowcoat`スタックの一番上または一番下にあります。 これを削除しても、残りの要素の順序は維持される必要があり、誤って構造を逆にしたり、間違って再構築したりしてはなりません。 

## アプローチ

 最も簡単なアプローチは、山を Python リストとして明示的にモデル化することです。 リストの末尾をスタックの先頭として扱います。 あ`put`操作はプッシュ、`get`操作はポップです。 どちらも O(1) です。 

のために`iditarod`、リストを上から下にスキャンして、`"snowcoat"`。 見つかったら、リスト削除を使用して削除します。 パイル全体をスキャンする可能性があるため、この操作は最悪の場合 O(n) になります。 

合計で最大 1000 の操作がある場合、最悪の場合でも操作ごとの O(n) スキャンでも合計ステップ数は約 10^6 となり、これは問題なく制限内に収まります。 これ以上複雑なデータ構造は必要ありません。 

重要な洞察は、恣意的な削除を効率的にサポートする必要はないということです。 値によって削除する特別なキーは 1 つだけであるため、線形検索で十分です。 バランスのとれたツリーまたはインデックス マップを維持しようとする試みは、この制約サイズにとって不必要なオーバーヘッドになります。

 ## アルゴリズムのチュートリアル

 私たちはリストを管理しています`pile`、最後の要素がスタックの最上位になります。 

1. 操作が次の場合`put s`、追加`s`最後まで`pile`。 これは、新しいアイテムを上に配置することを表します。 
2. 操作が次の場合`get`、どうかを確認してください`pile`は空です。 空の場合は出力`empty`。 それ以外の場合は、最後の要素を削除して出力します。 これはスタックのセマンティクスと直接一致します。 
3. 操作が次の場合`iditarod`、リストの最後から最初に向かってスキャンします。 最初に出現するものを検索します`"snowcoat"`スタックの最上位から見た場合、それは物理的にアクセス可能なインスタンスであるためです。 
4. もし`"snowcoat"`インデックスで見つかります`i`、削除を使用して削除し、成功メッセージを出力します。 
5. スキャンが見つからずに完了した場合は、失敗メッセージを出力します。 

上からスキャンする理由は、杭への自然なアクセス方法と一致するためですが、一致する要素を 1 つだけ削除する限り、どちらの方向からスキャンしても正しいことは変わりません。 

### なぜ効果があるのか

 パイルは常にアイテムの線形順序付けであり、末尾への追加、末尾からの削除、または単一の既知の値の削除の 3 つの変換のみが発生します。 削除では 1 つの要素のみが削除され、他の要素は並べ替えられないため、アルゴリズムでは順序が維持されます。 各操作は、1 つの有効なシーケンスを、問題の定義に正確に一致する別の有効なシーケンスに変換するため、各ステップの後でも構造の一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    pile = []

    for _ in range(T):
        parts = input().strip().split()

        if parts[0] == "put":
            pile.append(parts[1])

        elif parts[0] == "get":
            if not pile:
                print("empty")
            else:
                print(pile.pop())

        else:  # iditarod
            found_idx = -1
            for i in range(len(pile) - 1, -1, -1):
                if pile[i] == "snowcoat":
                    found_idx = i
                    break

            if found_idx == -1:
                print("oopsimcold :(")
            else:
                pile.pop(found_idx)
                print("winner winner chicken dinner :)")

if __name__ == "__main__":
    solve()
```実装はスタック モデルを直接ミラーリングします。 唯一の微妙さは、`iditarod`ここで、スタックの一番上から下に向かって明示的にスキャンします。 これにより、他のバリアントで複数の同一の名前が許可されていた場合でも、正しい出現を確実に削除できますが、ここでは一意性により簡単になります。 

の`pop(found_idx)`この操作は、他の項目の相対的な順序に影響を与えることなく要素を削除します。これはまさに必要な動作です。

 ## 特殊なケース

 いつ`iditarod`空のパイルで呼び出されると、スキャン ループは実行されず、アルゴリズムが直接出力します。`oopsimcold :(`状態を変更せずに。 たとえば、入力`iditarod`即時に失敗出力が発生し、パイルは空のままになります。 

いつ`snowcoat`スタックの最上位にある場合、逆スキャンによりインデックスですぐに検出されます。`len(pile) - 1`、 そして`pop`その要素のみを削除します。 残りの山は相対的な順序に変更はありません。 

いつ`snowcoat`が一番下にある場合、スキャンはリスト全体を走査し、インデックス 0 でそれを見つけて削除します。 残りの要素は下にシフトしますが、元の順序は保持されます。これは、他のものを並べ替えることなく、選択した項目のみが消えるという要件に一致します。
