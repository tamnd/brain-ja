 ## 解決策
 ## 問題の理解

 まっすぐな丘に沿った雪の高さを表す配列が与えられます。 値は負ではなく、シーケンスは左から右に単調非減少です。 各クエリは、要素の合計が指定された値に正確に一致する連続セグメントを要求します。$K$。 すべての有効なセグメントの中で、「最小」のもの、つまり長さが最も短いものを返す必要があります。複数のセグメントが同じ最小長を共有する場合は、配列内で最も早く出現するセグメントが選択されます。 

重要な操作は、配列をカウントしたり変換したりすることではなく、順序付けの制約の下で正確な目標合計を持つ部分配列を見つけることです。 

制約は非常に具体的な意味で重要です。 配列の長さは次のとおりです$10^5$、クエリの数は最大でも$100$。 これにより、クエリごとに 2 次の解が即座に除外されます。$Q \cdot N^2$大きすぎるでしょう。 クエリごとに配列を線形にスキャンするソリューションは許容されますが、クエリごとに線形より悪いものは失敗します。 

配列の単調構造は、主要な手法の正確さに直接必要ではありませんが、すべての値が正であることが保証され、これが私たちが依存する実際の構造特性です。 

素朴な「すべてのサブ配列を試す」アプローチを仮定すると、微妙な失敗例が現れます。 

入力:```
5 1
1 2 3 4 5
5
```ブルートフォースメソッドで見つかるかもしれない`[0,2]`(合計 6) は誤って考慮されるか、実装によっては早期に停止される可能性があります。 正しい答えは、`[1,2]`または`[4,4]`解釈にもよりますが、あくまで`[1,2]`最小長 2 の合計 5 に対して有効であり、`[4,4]`長さ 1 でも機能しますが、実際にはその方が優れているため、正しい答えは次のとおりです。`[4,4]`。 これは、正確さが、最初の一致で停止するのではなく、すべての有効なウィンドウを系統的に探索することに依存する理由を示しています。 

もう 1 つのエッジ ケースは、複数の同一の値が存在し、重複する有効なセグメントが多数生成される場合です。 各左境界の最初の一致のみを記録する不注意な実装では、後で現れる短いセグメントを見逃す可能性があります。 

## アプローチ

 最も直接的なアプローチは、考えられるすべての部分配列を調べ、その合計を計算し、それが以下に等しいかどうかを確認することです。$K$。 すべての候補を列挙しているため、これは正しいです。 ただし、各クエリには次のことが必要になります。$O(N^2)$すべてのサブ配列をチェックする時間があり、最大 100 個のクエリの場合、これは次のようになります。$10^7$サブ配列はそれぞれ一定の作業を必要とし、すでに境界線に達しており、オーバーヘッドを含めると通常は遅すぎます。 

重要な観察は、すべての要素がポジティブであるということです。 これにより、ウィンドウの合計が超過すると、スライディング ウィンドウ手法が可能になります。$K$、さらに拡大しても合計は増加するだけなので、左ポインタを前に移動して安全に減少させることができます。 この単調な動作により、各ポインターが配列内で前方にのみ移動することが保証され、クエリごとに線形の複雑さが得られます。 

すべての部分配列の合計を再計算する代わりに、実行ウィンドウを維持し、それを段階的に調整します。

 | スライディングウィンドウ |$O(N)$クエリごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリ値について$K$、2 つのポインターを使用して配列を個別にスキャンします。 

### ステップ

 1. 2 つのポインタを初期化する$l = 0$そして$r = 0$、および累計$s = 0$。 

窓$[l, r)$は検討中の現在のセグメントを表します。 
2. 移動して右側の境界を拡張します。$r$左から右へ。 各増分後、新しい要素を$s$。 

このステップにより、有効なセグメントの可能な終了位置をすべて探索できるようになります。 
3. いつでも$s > K$、ウィンドウを左から増分して縮小します。$l$そして要素を減算します$s$それまで$s \le K$。 

すべての値が負ではないため、これは有効であり、合計を減らす唯一の方法は縮小することです。 
4. いつ$s == K$、現在の間隔を記録します$[l, r]$答えの候補として。 

このウィンドウは、この修正では最小限です$r$, これ以上縮小すると平等が崩れてしまうためです。 
5. これまでに確認された最良の間隔を記録します。 「ベスト」とは、最初に最小の長さを意味し、同点の場合は最小の開始インデックスを意味します。 
6. 右ポインタが配列の末尾に到達するまで続けます。 

### なぜ効果があるのか

 任意の固定右エンドポイントで$r$、アルゴリズムは、左ポインタが最小のインデックスに配置されることを保証します。$[l, r]$せいぜい$K$。 すべての値は負ではないため、より小さい値は$l$合計が増加するだけです。つまり、次の値を超えることになります。$K$。 したがって、有効なセグメントが次で終わる場合、$r$が存在する場合、アルゴリズムはそれを最小形式で 1 ​​回だけ見つけます。 考えられるすべての適切なエンドポイントが処理されるため、すべての有効な候補が考慮され、その中からグローバルに最適なエンドポイントが選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    for _ in range(q):
        k = int(input())

        l = 0
        s = 0

        best_len = float('inf')
        best_l = -1
        best_r = -1

        for r in range(n):
            s += a[r]

            while l <= r and s > k:
                s -= a[l]
                l += 1

            if s == k:
                length = r - l + 1
                if length < best_len or (length == best_len and l < best_l):
                    best_len = length
                    best_l = l
                    best_r = r

        print(best_l, best_r)

if __name__ == "__main__":
    solve()
```このソリューションは各クエリを個別に処理し、毎回スライディング ウィンドウの状態をリセットします。 内側のループオーバー$r$要素ごとに 1 回ウィンドウを拡張し、内側の縮小ループが移動します$l$必要な場合にのみ転送します。 これにより、クエリごとの線形動作が保証されます。 

タイブレーク ロジックは、間隔の長さと開始インデックスの両方を明示的に追跡し、複数の候補が同じ合計を共有する場合でも、最も早い最小セグメントが選択されるようにします。 

よくある間違いは、初めてのことを想定してしまうことです$s == K$で十分です。 これは、より短い有効なセグメントがより良い左側の境界とともに後で現れる場合には失敗します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    out = []
    for _ in range(q):
        k = int(input())

        l = 0
        s = 0
        best_len = inf
        best_l = best_r = -1

        for r in range(n):
            s += a[r]
            while l <= r and s > k:
                s -= a[l]
                l += 1
            if s == k:
                if r - l + 1 < best_len or (r - l + 1 == best_len and l < best_l):
                    best_len = r - l + 1
                    best_l, best_r = l, r

        out.append(f"{best_l} {best_r}")

    return "\n".join(out)

 ## 特殊なケース

 のような繰り返し値が多数あるケース`1 1 1 1 1`より早く表示されるという理由だけで、アルゴリズムが誤って長いウィンドウを優先するかどうかをテストします。 スライディング ウィンドウは依然として各エンドポイントを個別に評価するため、右ポインターが一致する位置に到達すると、常に最短の有効なセグメントが見つかります。 

場合$K$単一の要素に等しい場合、有効なウィンドウを記録する前にアルゴリズムが不必要に拡張されないようになります。 正しい動作とは、次の場合に即座に認識することです。$s == K$単一のインデックスで。 

場合$K$は大きく、配列の終わり近くでのみ達成可能であるため、各クエリがスキャン全体にわたって最良の候補を追跡し続けるため、初期の部分一致が誤って最終的な答えとして返されないことが確認されます。
