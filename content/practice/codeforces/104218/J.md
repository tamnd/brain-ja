 ## 解決策
 ## 問題の理解

 有向グラフが与えられます$n \le 20$一方通行の道路がすでに存在するラベル付き都市。 目的は、1 から 1 までの順序で都市を訪れる有効な「マーチ マーチ ルート」を確保することです。$n$、つまり、連続するペアごとに$i \to i+1$、からの有向エッジに沿って移動できなければなりません。$i$に$i+1$。 

2種類の変更が可能です。 まず、任意の順序付けされた都市のペアの間に、コストをかけて新しい有向道路を構築できます。$c$。 第二に、都市のラベルを変更することはできますが、再ラベル付けには制約があります。$i$ラベルを付けることができます$j < i$自由ですが、より悪いラベルが付けられる場合、つまりより大きな数になる場合は、コストを支払わなければなりません$d$。 これにより、エッジによるグラフ構造の変更とラベルによる順序の変更の間に緊張が生じます。 

タスクは、(ルールに従って) 都市の再ラベル付けを選択し、最終的なラベル付きグラフが 1 から 2 までのハミルトニアン パスをサポートするように、どのエッジに依存するか構築するかを決定することです。$n$、総コストを最小限に抑えます。 

制約は非常に小さいです$n$これは、指数関数的な状態探索が受け入れられることを直ちに示唆しています。 と$n \le 20$、都市のサブセットまたは順列を列挙するソリューションは、最悪の場合の要因爆発を回避する限り実行可能です。 これは、ビットマスク動的プログラミング定式化またはサブセット DP を強く示しています。 

既存のグラフがすでに完全なチェーンをサポートしているが、ラベルを変更する方が欠落しているエッジを構築するよりも安価である場合、微妙なエッジ ケースが発生します。 もう 1 つは、コストの非対称性により再ラベル付けが実際には許可されず、ソリューションが純粋なグラフ拡張に堕落する場合です。 

素朴な考え方のより具体的な失敗モードは、ラベルの元の順序を保存する必要があると仮定することです。 たとえば、エッジが存在する場合、$1 \to 3$、$3 \to 2$、 そして$2 \to 4$、単純なアプローチではローカル エッジの修復を試みる可能性がありますが、最適な解決策では代わりに都市のラベルを変更してパスを簡単にし、高価なエッジの構築を回避する可能性があります。 

## アプローチ

 強引な解釈では、考えられるすべての都市の最終的なラベル付けを検討し、その結果の順序が既存のエッジとオプションで追加されたエッジを使用して有効なパスにできるかどうかを確認します。 各ラベル付けについて、再ラベル付けのコストと欠落したエッジのコストを計算します。 実現可能性を確認するには、固定長のチェーンに沿った接続を検証する必要があります$n$、つまり$O(n)$ただし、すべての再ラベルを列挙するのは$O(n!)$、でもそれは不可能です$n = 20$。 

重要な観察は、実際には順列について明示的に推論する必要がないということです。 重要なのは、どの都市のサブセットが罰則構造に矛盾なくすでに「良い」ラベルを割り当てられているか、そしてそれらを乗り越える道をどのように構築するかです。 ターゲット構造は単一のチェーンであるため、代わりに左から右に段階的にチェーンを構築し、各ステップでどの都市が次の位置を占めるかを決定するという観点から考えることができます。 

位置で$i$、未使用の都市を選択します$v$。 以前に配置した都市からのエッジがすでに存在する場合$u$に$v$、私たちは何も支払いません。 そうでなければ、私たちは支払わなければなりません$c$それを構築するために。 これとは別に、元の順序制約に違反するラベルを割り当てると、より悪い立場に追い込まれた都市の数に基づいてペナルティが導入されます。 

これは自然に、これまでに配置された都市のサブセットと最後に配置された都市を追跡するビットマスク DP につながります。 移行コストには、エッジ構築コストに加えて、元のインデックスと矛盾する位置に都市を配置することによって引き起こされる再ラベルのペナルティが含まれます。 

なぜなら$n$小さい、$O(n^2 2^n)$DPもあれば十分です。

 ## アルゴリズムのチュートリアル

 私たちは問題を、すべての都市の順序付けされたシーケンスを構築するものとして再解釈します。この場合、都市をインデックスよりも前の位置に配置することは無料ですが、インデックスよりも後に配置することにはコストがかかります。$d$ユニットシフトごと。 

1. DP 状態を次のように定義します。$dp[mask][i]$、 どこ`mask`はすでに最終的な順序に配置されている都市のセットであり、$i$最後に配置された都市です。 この状態は、次で終わる有効なプレフィックスを構築するための最小コストを表します。$i$。 
2. 設定により基本ケースを初期化します。$dp[1 << i][i] = 0$すべての都市にとって$i$。 これは、コストなしで任意の単一都市からシーケンスを開始することに相当します。 
3. 州ごとに$(mask, i)$、都市を選択してシーケンスを拡張してみてください$j$入っていない`mask`。 これにより、次への移行が作成されます。$(mask \cup \{j\}, j)$。 
4. 移行コストを 2 つの部分に分けて計算します。 まず、有向エッジかどうかを確認します$i \to j$すでに存在します。 そうでない場合はコストを追加します$c$それを構築するために。 2 番目に、再ラベルペナルティを計算します: 都市を配置します$j$位置で$|mask| + 1$元のインデックスの順序に違反する可能性があるため、追加します$d \cdot \max(0, (|mask| + 1) - j)$。 
5. 新しい状態ごとに最小コストで DP を更新します。 
6. DPを満たした後、答えはすべての終了都市で最小になります$i$の$dp[(1<<n)-1][i]$。 

重要なアイデアは、マスクが位置の順序を暗黙的にエンコードするということです。 シーケンスを拡張するたびに、都市の最終的なランクを修正し、そのランクが元のラベルよりも悪いかどうかを直接計算できます。 

### なぜ効果があるのか

 DP は、すべての州が明確に定義されたコストを持つ個別の都市の有効な部分順序に対応するという不変条件を維持します。 すべての遷移で未使用の都市が 1 つだけ追加されるため、無効な置換は発生しません。 考えられるすべての完全な順序付けはこれらの状態を通るパスとして表現可能であり、各遷移はエッジ構築と再ラベル付けペナルティの両方を局所的に考慮するため、すべての完全な状態にわたる DP 最小化によってグローバル最小値が達成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c, d = map(int, input().split())

    adj = [[False] * n for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a - 1][b - 1] = True

    INF = 10**18
    size = 1 << n
    dp = [[INF] * n for _ in range(size)]

    for i in range(n):
        dp[1 << i][i] = 0

    for mask in range(size):
        k = mask.bit_count()
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            if not (mask & (1 << i)):
                continue

            for j in range(n):
                if mask & (1 << j):
                    continue

                nmask = mask | (1 << j)

                cost = dp[mask][i]

                if i != j:
                    if not adj[i][j]:
                        cost += c

                pos = k + 1
                if j + 1 < pos:
                    cost += d * (pos - (j + 1))

                if cost < dp[nmask][j]:
                    dp[nmask][j] = cost

    full = size - 1
    ans = min(dp[full])

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルはビットマスクと最後のノードによってインデックス付けされるため、実装ではすべてのプレフィックス状態が 1 回だけ考慮されることが保証されます。 位置は、マスクの現在のポップカウントに 1 を加えたものとして導出されます。遷移ごとにマスク サイズが 1 つずつ増加するため、これは安全です。 

よくある落とし穴は、再ラベル付けのコストがグラフ構造ではなく最終位置に依存することを忘れていることです。 もう 1 つは、エッジがすでに存在している場合でも、エッジ コストを誤って請求することです。 隣接マトリックスによりスキャンの繰り返しが回避され、遷移が維持されます。$O(1)$。

 ## 特殊なケース

 重要なエッジ ケースは、グラフにすでに完全なチェーンが含まれているにもかかわらず、ラベルを変更すると不必要なペナルティが発生する場合です。 たとえば、エッジがすでに形成されている場合、$1 \to 2 \to 3 \to \dots \to n$の場合、各都市は自然な位置に表示されるため、DP は常にエッジ コストと再ラベル コストがゼロのパスを選択します。 

もう 1 つのケースは、元のインデックスが小さいノードが遅れて配置される場合です。 DP は明示的に追加します$d \cdot (pos - index)$したがって、ノード 1 を最後に配置すると、大きなペナルティが発生します。 遷移は引き続き有効ですが、自動的に次善の状態になります。 

3 番目のケースは、エッジが逆の順序で存在する場合です。 欠落したエッジは常にコストをかけてローカルで修復されるため、DP はこれを適切に処理します。$c$、そのため、反転チェーンは無効な状態ではなく、エッジ構築の均一なシーケンスになります。
