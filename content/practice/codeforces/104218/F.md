 ## 解決策
 ## 問題の理解

 それぞれが 2D 平面上の点に位置し、特定の時間に発生する一連のイベントが与えられます。 それぞれのイベントにも価値があります。 プレイヤーは時間ゼロの原点からスタートし、単位速度で平面内を継続的に移動できます。つまり、距離を移動します。$d$正確に必要です$d$時間。 

このタスクは、プレイヤーが選択した各イベントを必要な時間と場所に、起点から開始して何らかの順序で正確に訪問できるように、イベントのサブセットを選択し、それらの値の合計を最大化することです。 

言い換えれば、各イベントはタイムスタンプと重み付けされた報酬を持つノードであり、連続するノード間の移動時間の制約が尊重される実現可能な最良のシーケンスが必要です。 

重要な制約は、$N \le 5000$、これにより、三次またはそれより悪い解は即座に除外されます。 中間チェックを伴う単純な全ペア動的プログラミングでは、イベントのペア間のすべての遷移を考慮する必要があります。$O(N^2)$は自然な目標の上限です。 ただし、たとえ$O(N^2)$各遷移にはユークリッド距離の計算と時間の実現可能性チェックが含まれるため、慎重に実装する必要があります。 

微妙な問題は、イベントが時間順に並べ替えられることが保証されていないことです。 分類するのを忘れると、後のイベントから前のイベントに移行しようとする可能性がありますが、これは物理的に不可能です。 

2 つのイベントのタイムスタンプは同一であるが、空間的には離れている場合、別の特殊なケースが発生します。 実現可能性を厳密に強制しない単純な DP は、それらを誤って連鎖させる可能性があります。 たとえば、イベント A と B が両方とも時間 10 に発生するが、100 単位離れている場合、ゼロ時間では移動が不可能であるため、両方を順番に訪問することはできません。 

最後の微妙なケースは浮動小数点精度です。 距離には平方根が含まれるため、不注意に実装すると浮動小数点値を直接比較し、精度誤差が生じる可能性があります。 堅牢なソリューションでは、距離の二乗を比較することで平方根を完全に回避します。 

## アプローチ

 この強引なアイデアは、各イベントを決定点として扱い、それらのイベントを訪問するすべての可能なサブセットと順列を試すことです。 すべてのシーケンスについて、連続するイベント間で移動時間の制約が満たされているかどうかを確認し、合計値を計算します。 これは正しいですが、まったく実行不可能です。 順列に限定しても、順序数は次のようになります。$N!$、そして注文ごとに 1 回の実現可能性チェックを行うだけでも、天文学的な規模になります。 

より構造化されたブルート フォースは、サブセットに対する動的プログラミングです。ここでは、サブセット マスクを使用して、イベント i で終わる最良の値として DP[mask][i] を定義します。 これは依然として指数関数的です$N$、状態空間だけが$O(2^N N)$、それは限界をはるかに超えています。 

重要な観察は、遷移の実現可能性はイベント間のペアごとの互換性にのみ依存するということです。 時間の経過に伴うイベントの順序を修正する場合、有効なパスはすべてこの順序を尊重する必要があります。 以前のイベントより$i$その後のイベントへ$j$、プレイヤーが物理的にそこから移動できるかどうかを確認するだけで済みます。$i$に$j$時間内に$T_j - T_i$。 これにより、エッジは時間的に前方にのみ進むため、問題は有向非巡回グラフの最長パスに縮小されます。 

時間で並べ替えると、構造はノード間の DP になり、各ノードが以前の到達可能なすべてのノードを拡張しようとします。 これによりきれいになります$O(N^2)$移行DP。

 ## アルゴリズムのチュートリアル

 1. すべてのイベントを時間順に並べ替えます$T_i$。 これにより、有効な遷移はすべて DP 順序でのみ前進することが保証されます。これは、実行可能なパスに沿って厳密に時間が増加するため、必要です。 
2. イベントごとに$i$でパスを終了する場合に、達成可能な最高の値を計算します。$i$。 これを DP 配列に保存します。DP[i] はイベント i で終了する最大報酬を表します。 
3. DP[i] をイベント i 自体の値で初期化します。 これは、原点から i に直接到達する新しいルートを開始することに対応します。 
4. イベントの各ペアについて$i < j$, i から j に移動できるかどうかを確認します。 これには、i から j までの移動時間が最大で$T_j - T_i$。 浮動小数点エラーを回避するために二乗距離を計算し、それを比較します。$(T_j - T_i)^2$。 
5. 遷移が有効な場合、DP[j] を DP[j] = max(DP[j], DP[i] + V_j) として更新します。 これは、i で終わる最適なパスは、到達可能であれば j まで拡張できるという考えを捉えています。 
6. すべてのペアを処理した後、答えは DP 配列の最大値になります。 

原点が暗黙的に処理される理由: 時間 0 で (0,0) からイベント i に到達することは可能であるため、すべてのイベントを最初から到達可能なものとして扱います。$X_i^2 + Y_i^2 \le T_i^2$。 これは、DP[i] の初期化時に明示的にチェックすることも、到達不能な状態は DP 順序付けでは正しく拡張されないため、DP[i] が V_i として開始できるようにすることで一律に処理することもできます。 

### なぜ効果があるのか

 イベントが時間順に並べ替えられると、実行可能なルートは増加するインデックスに従う必要があります。 DP は、DP[i] がイベント i で正確に終了する有効なルートの最良の値であるという不変条件を維持します。 i から j へのすべての遷移では、時間 T_i より前に i に到達するためのすべての有効な方法が考慮され、速度制約に違反することなくその後 j に到達できるかどうかがチェックされます。 すべての有効なパスには一意の最後のイベントがあり、すべての可能な先行パスを時間順に列挙するため、最適なソリューションが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    for _ in range(n):
        x, y, t, v = map(int, input().split())
        events.append((t, x, y, v))
    
    events.sort()
    
    dp = [0] * n
    
    for i in range(n):
        t_i, x_i, y_i, v_i = events[i]
        dp[i] = v_i
        
        # try to reach i from origin implicitly
        if x_i * x_i + y_i * y_i <= t_i * t_i:
            dp[i] = max(dp[i], v_i)
        
        for j in range(i):
            t_j, x_j, y_j, v_j = events[j]
            
            dt = t_i - t_j
            dx = x_i - x_j
            dy = y_i - y_j
            
            if dx * dx + dy * dy <= dt * dt:
                dp[i] = max(dp[i], dp[j] + v_i)
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```中心となる構造は、間隔を超えて時間でソートされた古典的な動的プログラミングです。 ソートにより、無効な時間後方への遷移が試みられることがなくなります。 

DP の初期化では、各イベントをスタンドアロン パスとして設定します。 これは重要です。イベントがオリジンから到達できない場合でも、別のイベントから間接的に到達できる可能性があるため、早期に破棄しないでください。 

ネストされたループは、以前のすべてのイベントをチェックし、二乗ユークリッド距離を使用して実現可能性チェックを実行します。 時間差の 2 乗との比較は、浮動小数点精度の問題を完全に回避できるため、非常に重要です。 

DP を超える最終的な最大値は、最良のルートがどのイベントでも終了する可能性があり、必ずしも時間順で最後のルートであるとは限らないという事実を捉えています。

 DP を段階的に計算します。 

| 私 | イベント | 最高の前任者 | DP[i] |
 | --- | --- | --- | --- |

これは、時間による並べ替えにより、物理的に有効な手のみを連鎖させることができ、無効な逆推論を回避できることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、イベントが同時に発生することです。 移動時間がゼロであるため、同一の座標のみが連鎖を許可します。 DP はこれを正しく処理します。$dx^2 + dy^2 \le dt^2$になる$dx^2 + dy^2 \le 0$、立場の平等を強制します。 

もう 1 つのエッジ ケースは、オリジンから個別に到達可能であるが相互に到達できないイベントです。 各イベントは独自の値で始まり、有効な遷移のみがそれを改善するため、DP は依然として最適な単一イベントまたは組み合わせを正確に選択します。 

最後のエッジケースは、大きな座標値です。 2 乗整数を使用すると、Python の 64 ビット演算に安全に適合し、浮動小数点の問題が完全に回避され、最大の制約でも正確さが保証されます。
