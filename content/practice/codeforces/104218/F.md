 ## 解決策
 ## 問題の理解

 飛行機内では一連のチェックポイントが与えられます。 各チェックポイントには固定の場所、そこに宝が出現する特定の時間、およびその宝に付加された値があります。 競技者は時間 0 に原点からスタートし、任意の方向に継続的に移動しますが、速度は制限されているため、単位時間当たり最大 1 単位の距離を移動できます。 宝物が出現したときにチェックポイントの座標に正確にいた場合にのみ、宝物を収集できます。 

タスクは、移動の制約が尊重され、収集された価値の合計が最大になるように、収集する一連の宝物を選択することです。 

これは基本的に、幾何学的な移動制約によるスケジュールの問題です。 それぞれの宝物は「ジョブ」となり、以前に選択したジョブから時間内にその位置に到達できた場合にのみ就くことができます。 

ここでは、制約 N が最大 5000 であることが重要なシグナルです。 単純な O(N3) または一部の O(N² log N) アプローチは境界線にありますが、定数係数が小さい場合にのみ許容される可能性があります。 ただし、構造を持たずにパスを明示的にシミュレートしたり、到達可能性を繰り返し再計算しようとするソリューションは合格しません。 

いくつかの特殊なケースは注目に値します。 

1 つは、複数の宝物が同じ時間を共有しているが、遠く離れている場合です。 たとえば、時刻 10 の位置 (0,0) と (100,100) で 2 つのチェックポイントが発生した場合、選択できるのは 1 つだけであり、単純なアプローチでは、最初から両方に独立して到達可能であると誤って想定される可能性があります。 

もう 1 つは、時刻 0 または非常に早い時点で宝物が発生した場合です。 チェックポイントが (0,0,0) にある場合、チェックポイントは常にすぐに収集可能ですが、一部の遷移はゼロ時間差分の注意深い処理に依存します。 

3 番目の微妙なケースは、後の宝物が幾何学的には近いものの、時間的に早すぎる場合です。 たとえば、(0,0,10) から (1,1,11) に移動することは、空間的なギャップが小さいにもかかわらず、必要な移動距離が利用可能時間を超えるため不可能です。 

これらの例は、到達可能性を明示的に強制しない限り、時間だけによる順序付けでは十分ではないことを強調しています。 

## アプローチ

 この問題を直接考える方法は、チェックポイントのサブセットに対する動的プログラミングです。 dp[S] を、有効な順序でサブセット S を選択することによって達成できる最良の値として定義します。 遷移ごとに、速度制約を尊重しながら、選択した 1 つのチェックポイントから別のチェックポイントに移動できるかどうかを確認します。 サブセットの数が 2^N であるため、これは直ちに指数関数的な複雑さにつながりますが、N = 5000 ではまったく実現不可能です。 

状態を大幅に単純化できます。 サブセットを追跡する代わりに、有効なルートはすべてチェックポイントのシーケンスであることが観察され、シーケンス内の最後のチェックポイントを修正すると、関連する履歴はその直前にどのチェックポイントが来たかだけになります。 これは、エンドポイント上の DP を示唆しています。dp[i] は、チェックポイント i で終了する有効なルートの最大値です。 

主な困難は、チェックポイント j がチェックポイント i に続くことができるかどうかを判断することです。 ポイント間の移動時間がユークリッド距離をカバーするのに十分であるかどうかを確認する必要があります。 つまり、|Ti - Tj| は少なくとも sqrt((Xi - Xj)² + (Yi - Yj)²) でなければならず、また時間は前進する必要があるため、Ti < Tj となります。 

これが分かると、問題は有向非巡回グラフの最長パスになりますが、エッジは明示的に与えられません。 代わりに、すべてのペアをチェックして遷移を計算します。 N が 5000 であるため、O(N²) DP が許容されます。 

すべての有効な遷移が独立しており、中間状態を必要としないため、ブルート フォース ペア チェックが機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット DP | O(2^N) | O(2^N) | 遅すぎる |
 | エンドポイント上のペアワイズ DP | O(N²) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

有効な遷移は時間の単調性を考慮する必要があるため、チェックポイントを時間の昇順に処理します。 

1. T を増やしてすべてのチェックポイントを並べ替えます。これにより、dp[i] を計算するときに、考えられるすべての先行チェックポイントがすでに処理されることが保証されます。 
2. すべての i に対して dp[i] = V[i] を初期化します。 これは、チェックポイント i 自体でパスを開始する場合の最良の値を表します。 
3. 各チェックポイント i について、左から右に、以前のすべてのチェックポイント j < i を拡張しようとします。 
4. 各ペア (j, i) について、ユークリッド距離の 2 乗と時間差の 2 乗を比較することで、j から i への移動が実現可能かどうかを確認します。 

(Xi - Xj)² + (Yi - Yj)² ≤ (Ti - Tj)²。 
5. 条件が成立する場合、dp[i] = max(dp[i], dp[j] + V[i]) を更新します。 

各更新は、i より前に最後に収集された宝物として j を選択することを表します。 この不等式により、単位速度の旅行者が時間内に j から i に物理的に到達できることが保証されます。 

すべての i を処理した後の答えは、dp の最大値になります。 

### なぜ効果があるのか

 任意のチェックポイント i で、dp[i] は、正確に i で終わるすべての有効なシーケンスの中で達成可能な最良の値を表します。 時間による並べ替えでは、考慮されるすべての先行者 j の時間が厳密に小さいか等しいことが保証されるため、将来の無効な依存関係は存在しません。 遷移条件は物理的な到達可能性を強制するため、DP 内のすべてのエッジが有効な動きに対応します。 すべての有効なルートには最後のチェックポイントがあり、dp は各チェックポイントに対して考えられるすべての先行ルートを考慮するため、最適なパスが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    pts = []
    for _ in range(n):
        x, y, t, v = map(int, input().split())
        pts.append((t, x, y, v))

    pts.sort()
    
    dp = [0] * n
    ans = 0

    for i in range(n):
        ti, xi, yi, vi = pts[i]
        dp[i] = vi
        best = vi

        for j in range(i):
            tj, xj, yj, vj = pts[j]
            dt = ti - tj
            dx = xi - xj
            dy = yi - yj
            if dx * dx + dy * dy <= dt * dt:
                if dp[j] + vi > dp[i]:
                    dp[i] = dp[j] + vi

        ans = max(ans, dp[i])

    print(ans)

if __name__ == "__main__":
    main()
```このコードは、DP 遷移が常に時間内で進むように、最初にチェックポイントを時間で並べ替えます。 dp 配列には、各チェックポイントで達成可能な最高の報酬が格納されます。 チェックポイントのペアごとに、浮動小数点精度の問題を回避するために、二乗距離を使用して到達可能性をチェックします。 

微妙な点は、sqrt の代わりに dt * dt を使用していることです。 これにより、精度エラーが回避され、すべてが整数に保たれます。これは、最大 10^9 の座標値を指定するために必要です。 

最適なパスはどのチェックポイントでも終了する可能性があるため、答えは最大 dp 値として使用されます。 

## 実用的な例

 ### サンプル 1

 入力:```
3
1 1 100 10
2 2 40 8
20 20 25 1000
```時間順に並べ替えると、次の順序になります。 

(20,20,25,1000)、(2,2,40,8)、(1,1,100,10)

 dp を段階的に計算します。 

| 私 | ポイント | dp[i] 初期化 | 有効な先行者 | dp[i] 最終 |
 | --- | --- | --- | --- | --- |
 | 0 | (20,20,25) | 1000 | なし | 1000 |
 | 1 | (2,2,40) | 8 | 0 に到達できません | 8 |
 | 2 | (1,1,100) | 10 | 1 到達可能、0 到達可能 | 10 (ダイレクトベストスタート経由) |

 最良の方法は、到達可能な時間順の最初のイベントのみを取得し、次に最適な独立した値を選択することです。 理論的には、最適な結果は 1000 + 8 + 10 ですが、距離に比べて時間ギャップが不十分であるため、到達可能性によってチェーンがブロックされます。 

これは、貪欲な直観を支配する幾何学的制約の重要性を示しています。

 ## 特殊なケース

 主なエッジケースは、2 つのチェックポイントのタイムスタンプが同じである場合です。 dt がゼロになるため、アルゴリズムではそれらの間の遷移は決して許可されず、座標が同一でない限り距離チェックは失敗します。 たとえば、(0,0,5,10) と (1,1,5,20) は連鎖できません。 DP は両方を独立して処理し、物理的制約に一致する max(10,20) を生成します。 

もう 1 つのケースは、チェックポイントが空間内で非常に近いが、わずかに早すぎる場合です。 (0,0,0) ～ (100,0,1) とします。 距離は 100 ですが、使用できる時間単位は 1 つだけであるため、不等式は成立せず、dp は誤って伝播しません。 

3 番目のケースは、長いチェーンが存在するが中間ノードが必要な場合です。 中間チェックポイントが後のノードに到達するのに最適になると、それはすでに dp に保存されており、後の移行中に再利用されるため、DP によって正確さが保証されます。
