 ## 解決策
 ## 問題の理解

 円上に配置された n 等間隔の点に n 個の犬を配置します。 犬 i は時間 0 の位置 i から開始し、各犬は単位時間ごとに固定ステップ サイズ v_i で時計回りに前進します。 動きは円の周りでモジュール化されているため、位置は常に n を法として取得されます。 

いつでも、各犬は円上で決定的な位置を持ちます。 すべての犬が同時に同じ位置を占めるような最も早い時間 t を見つけるように求められます。 このような時間が許容範囲 (事実上 1000 によって制限される) 内に発生しない場合は、-1 を出力します。 複数の解が存在する場合は、最小の t と、その t に対する共通の位置を返します。 

重要な観察は、それぞれの犬がサイズ n の周期的なグループ上の直線運動に従うということです。したがって、問題は n を法とする等差数列の同期に関するものです。 

n ≤ 1000 および v_i ≤ 100 という制約は、O(n^2) または O(n^2 log n) のアプローチが受け入れられることを示唆しています。 n の 3 次関数や、最大 1000 ステップまでの時間をかけて繰り返し完全なシミュレーションを行うものも境界線に達しますが、慎重に実装すれば許容できる可能性があります。 

ペアごとの衝突をチェックするだけ、または 1 匹の参照犬だけを追跡するだけで十分だと考えると、素朴な落とし穴が生じます。 たとえば、2 匹の犬が以前のある時点で出会う可能性がありますが、すべての犬が同時に一致することは保証されません。 もう 1 つのよくある間違いは、中間状態を注意深くチェックせずに、時刻 t=1000 ですべての犬が一致するまでシミュレーションすることです。これにより、以前の有効な解決策を見逃す可能性があります。 

具体的なエッジ ケースは、モジュラー ラップアラウンドにより、ドッグがゼロ以外の時間でのみ整列する場合です。 たとえば、小さなサイクルでは、同期はすぐにではなく数回転後に行われることが多いため、t=0 または t=1 のみをチェックすると、後で解が存在する場合でも失敗します。 

## アプローチ

 直接的な総当たりシミュレーションでは、0 から 1000 までの各タイム ステップ t が考慮され、n 個の位置がすべて計算されます。 各 t について、すべての位置が同一かどうかを確認します。 位置の計算にはタイム ステップごとに O(n) のコストがかかるため、合計の複雑さは O(1000 · n) になります。 n が 1000 までの場合、これは約 10^6 の演算になります。これは Python では実際には問題ありませんが、正しく実装されている場合に限ります。 ただし、各位置は段階的に更新できるため、これでも冗長な計算が行われます。 

より深い構造は、各犬の位置がモジュラー一次関数であるということです。 

pos_i(t) = (i + t・v_i) mod n。 

これらの式がすべて等しくなるような時刻 t を探します。 毎回すべての位置をチェックする代わりに、選択した参照犬、たとえば犬 0 を基準にして条件を再定式化できます。すべての犬が一致する場合、すべての i について次のようになります。 

(i + t・v_i) ≡ (0 + t・v_0) (mod n)

 これはモジュラー線形合同システムになります。 

t・(v_i − v_0) ≡ −i (mod n)

 各 i は t に制約を与えます。 解決策は、これらすべての合同式の交差点です。 モジュラー線形方程式ソルバー (基本的に拡張 gcd ロジックを介して制約をマージします) を使用して、t の単一の合同式を反復的に維持できます。 n ≤ 1000 であるため、係数は小さく、すべての i に対して繰り返しマージを行うことが可能です。 

主な利点は、時間をかけて検索する代わりに、すべての有効な時間を代数的に直接構築できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n・T) ただし、T ≤ 1000 | お(1) | 受け入れられるが境界線にある |
 | 合同マージ | O(n log n + n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ドッグ 0 を基準点として固定します。 すべての犬が犬 0 の位置に同時に一致するように、t に対する制約を導き出します。 

1. 犬 i が犬 0 と一致する条件をモジュラー方程式として表現します。 

t・(v_i − v_0) ≡ −i (mod n)。

これは、両方の位置がモジュロ n に一致するという要件を捉えています。 
2. t の自明な合同式から始めます。最初はすべての整数が有効です。 
3. 各ドッグ i を 1 から n−1 まで反復し、現在の制約を新しい合同式とマージします。 
4. 各 i について、線形合同式 a・t ≡ b (mod n) を解きます。ここで、a = (v_i − v_0) mod n および b = (−i) mod n。 

a が n を法とする 0 である場合、方程式は b も 0 であるかどうかをチェックすることになります。そうでない場合、解は存在しません。 
5. a がゼロでない場合、gcd(a, n) を計算し、一貫性をチェックします。b は gcd(a, n) で割り切れる必要があります。 そうでない場合、解決策は存在しません。 
6. gcd で除算して方程式を縮小し、拡張 Euclid を使用して a/g モジュロ n/g の逆剰余を計算します。 これにより、n/g を法とする t の基本溶液が得られます。 
7. 2 つの線形合同の標準的な CRT スタイルの組み合わせを使用して、この解を現在のグローバル合同とマージします。 
8. すべての犬を処理した後、単一の合同式 t ≡ x (mod M) が得られるか、解が存在しないと判断されます。 
9. 最終的な答えは、許容範囲内 (≤ 1000) 内の最小の非負の t です。 また、犬の公式を使用して、対応する位置を計算します。 

### なぜ効果があるのか

 すべてのドッグは時間 t においてある位置 p で一致する必要があるため、各ドッグは n を法とする t に線形制約を課します。 これらの制約は、等差数列の交差を定義します。 マージ プロセスでは、現在の合同式がこれまでに処理されたすべてのドッグを常に満たしていることを表す不変式が維持されます。 各マージは以前のシステムとの等価性を維持し、新しい制約を強制するため、最終的な合同式は有効な時間のセットを正確に表します。 交差が空の場合、グローバル同期は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inv(a, m):
    g, x, _ = egcd(a, m)
    if g != 1:
        return None
    return x % m

def merge_congruence(r1, m1, r2, m2):
    # solve: x ≡ r1 (mod m1), x ≡ r2 (mod m2)
    # returns (r, m) or (None, None)
    g, p, q = egcd(m1, m2)
    diff = r2 - r1
    if diff % g != 0:
        return None, None

    lcm = m1 // g * m2

    # adjust solution
    t = (diff // g) * p % (m2 // g)
    x = (r1 + m1 * t) % lcm
    return x, lcm

def solve():
    n = int(input())
    v = list(map(int, input().split()))

    r, m = 0, 1  # t ≡ r (mod m)

    for i in range(n):
        a = (v[i] - v[0]) % n
        b = (-i) % n

        if a == 0:
            if b != 0:
                print(-1)
                return
            continue

        g, _, _ = egcd(a, n)
        if b % g != 0:
            print(-1)
            return

        n_ = n // g
        a_ = a // g
        b_ = b // g

        inv = mod_inv(a_ % n_, n_)
        if inv is None:
            print(-1)
            return

        x = (b_ * inv) % n_

        # merge t ≡ x (mod n_) with current
        r, m = merge_congruence(r, m, x, n_)
        if r is None:
            print(-1)
            return

    # smallest valid t
    ans_t = r
    if ans_t > 1000:
        print(-1)
        return

    pos = (0 + ans_t * v[0]) % n
    print(ans_t, pos)

if __name__ == "__main__":
    solve()
```このコードは、有効な時刻のグローバル合同を構築します。 各ドッグは 1 つのモジュラー線形方程式を提供し、拡張 gcd を使用して解かれ、一般化された CRT マージを使用してマージされます。 最後のステップでは、時間制限をチェックし、最初の犬の軌道を使用して共有位置を計算します。 

微妙な点は、係数が n を法としてゼロになる場合の処理​​です。 その場合、右辺もゼロであることを確認する必要があります。 そうしないと、システムに一貫性がなくなり、時間が機能しなくなります。 

## 実用的な例

 ### 例 1

 入力:```
3
1 2 3
```ドッグ 0 を参照として使用して制約を追跡します。 

| 私 | a = v_i - v_0 | b = -i mod 3 | 制約の結果 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | ベース |
 | 1 | 1 | 2 | t ≡ 2 (mod 3) |
 | 2 | 2 | 1 | 一貫性のあるマージ |

 i=1 を処理した後、t ≡ 2 mod 3 が得られます。i=2 をチェックして、一貫性を検証し、同じ合同性を維持します。 

最終的な答えは t=2、位置は (0 + 2・1) mod 3 = 2 です。 

このトレースは、システムが明示的なシミュレーションではなく単一のモジュール状態にどのように還元されるかを示しています。 

### 例 2

 入力:```
4
1 1 1 1
```すべての犬が同じように動くので、すぐに同期できます。 

| 私 | | b | 制約 |
 | --- | --- | --- | --- |
 | 1 | 0 | 3 | 不可能 |
 | 2 | 0 | 2 | 不可能 |
 | 3 | 0 | 1 | 不可能 |

 a=0 ですが b≠0 なので、解は存在しません。 

これは、縮退方程式の重要な一貫性チェックを示しています。

 ## 特殊なケース

 すべての v_i が等しい場合、1 つの重要なエッジ ケースが発生します。 この場合、位置は永遠に等間隔のままになります。 入力用`n=4, v=[2,2,2,2]`, すべての方程式は 0・t ≡ -i mod 4 になりますが、これはどの i≠0 でも不可能です。 各 i について a がゼロになり、b がゼロ以外になるため、アルゴリズムはこれを正しく検出し、即座に拒否されます。 

もう 1 つのエッジ ケースは、t=0 で同期が発生する場合です。 のために`n=3, v=[0,0,0]`、すべての犬は開始位置に固定されたままであるため、すべての開始位置が等しい場合にのみ一致します。これは、n=1 でない限り false です。 合同系は、i≥1 の場合、すぐに矛盾を示します。 

最後の微妙なケースは、有効な解が存在するが 1000 を超えている場合です。アルゴリズムは依然として解を正しく計算しますが、最後の境界チェックでそれを拒否し、問題の時間制限への準拠を保証します。
