 ## 解決策
 ## 問題の理解

 10 進数が文字列として与えられます。 その桁を個別に 2 回並べ替えて、元の数値とまったく同じ複数の桁セットを含む 2 つの新しい数値を生成することができます。 先頭のゼロは置換後に許可されます。 

私たちの目標は、結果として得られる 2 つの数値の合計ができるだけ多くのゼロで終わるように桁を配置することです。 言い換えれば、それらの合計に可能な限り多くの末尾のゼロが必要です。 

数字の加算により 10 で割り切れる結果が得られ、桁上げ伝播も正しく動作する場合には、末尾のゼロが表示されます。 数値には最大まで含めることができるため、$10^5$数字が大きい場合、解はほぼ線形である必要があります。 順列に直接関係するものはすべて絶望的です。$20!$すでに天文学的な規模になっています。 

小数加算の構造は、正確な数値よりもはるかに重要です。 位置に末尾のゼロ$i$は、その位置の 2 桁に前の位置からのキャリーを加えた合計が 10 の倍数になることを意味します。キャリーは左方向にのみ移動するため、プロセスは必然的に最下位桁から最上位桁まで貪欲になります。 

危険なエッジケースは、局所的に最適なペアリングが将来のキャリーの可能性を破壊するケースです。 

次の入力を考えてみましょう。```
55
```ペアリングしたら$5+5=10$、末尾のゼロを 1 つ取得し、キャリーを生成します。 桁が残っていないため、そのキャリーはそれ以上使用できません。 正しい答えは、末尾のゼロが 1 つです。 

ここで次のことを考えてみましょう。```
5005
```常に数字の合計を 10 にしようとする不用意な戦略は、唯一の有効なキャリーを無駄にする可能性があります。 有効な最適な構成の 1 つは次のとおりです。```
5500
5500
```それらの合計は次のとおりです。```
11000
```末尾に 0 が 3 つあります。 重要な点は、最初のキャリーが現れた後は、入ってくるキャリーが残りの 1 に寄与するため、後続の各桁位置の合計が 9 になるだけでよいということです。 

もう 1 つの微妙なケースは、キャリーをまったく開始できない場合です。 

例：```
111
```数字の合計が 10 以上になることはないため、答えには末尾のゼロが含まれていない必要があります。 結果のすべてのゼロ桁がキャリーに対応すると仮定する貪欲な実装は、ここでは失敗します。 

先頭のゼロも重要です。 例えば：```
1000
```先頭にゼロを自由に配置できます。 先頭のゼロを拒否すると、有効な最適解が誤って削除されてしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 最初の数値のすべての桁の置換と 2 番目の数値のすべての置換を生成し、それらの合計を計算し、後続のゼロの最大数を追跡します。 

検索スペースには有効な答えがすべて含まれているため、これは概念的に機能します。 問題はその大きさです。 番号があれば$n$数字、あります$n!$各数値の順列、おおよその結果$(n!)^2$ペア。 たとえ$n=15$、これはまったく不可能です。 

実際の観察は、10 進数の加算によって末尾のゼロがどのように作成されるかに由来します。 

すでにある桁の位置にキャリーが入っていると仮定します。 次に、末尾のゼロをもう 1 つ生成するには、2 つの数字の合計が 9 になるだけで済みます。$$a+b+1=10$$受信キャリーがない場合は、代わりに次のものが必要です。$$a+b=10$$これにより問題は完全に変わります。 完全な数値はもう気にしません。 形成できる数字のペアの数だけを考慮します。$$10 \quad \text{for the first carry}$$その後：$$9 \quad \text{afterward}$$このプロセスは桁数のマッチング問題になります。 

私たちは最初のキャリーを生み出す可能性のあるすべてのペアを試します。 その開始ペアを修正した後、可能な限り多くの sum-9 ペアを貪欲に作成します。 10 桁の値しかないため、すべての開始ペアを試すのは継続的な作業です。 

貪欲な部分が機能するのは、成功したすべてのペアが末尾のゼロをもう 1 つだけ提供し、キャリー チェーンが開始されると、そのようなペアはすべて同等になるためです。 可能性のある合計 9 のペアを後で使用するために保存しておくことには利点がありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((n!)^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各桁が何回あるかを数えます$0 \dots 9$元の番号に表示されます。 
2. 順序付けられたすべての数字のペアを試します$(a,b)$そのような$a+b=10$。 このペアが最下位桁となり、キャリー チェーンが開始されます。 
3. 開始ペアの候補ごとに、次の 1 つの出現を一時的に削除します。$a$そして1回の発生$b$桁数から。 
4. キャリーが存在した後は、後続のゼロごとに、数字の合計が 9 になるだけで済みます。貪欲に多くのペアを取得します。$(x,9-x)$できるだけ。 
5. この構造によって生成される末尾のゼロの数を記録します。$$1 + \text{number of sum-9 pairs}$$追加の 1 は、最初の合計 10 のペアから得られます。 
6. すべての開始ペアの中で最良の構築を維持します。 
7. もう 1 つの可能性があります。おそらく、キャリーを開始できない可能性があります。 その場合、答えの末尾にゼロはありません。 この場合とも比較してみます。 
8. 選択した数字の組み合わせから 2 つの数字を再構築します。 

ペアの数字は、最下位から最上位に向かって配置されます。 

残りの未使用の数字は任意に追加されます。 
9. 最下位桁から順に構築したため、印刷する前に構築された文字列を逆にします。 

### なぜ効果があるのか

 最初の末尾のゼロは、受信キャリーがまだないため特別です。 最初のゼロを作成する唯一の方法は、合計が 10 になる数字のペアです。 

キャリー チェーンが開始されると、将来のすべてのポジションには、数字の合計が 9 になるだけが必要です。そのような各ペアは、確定的に後続のゼロをもう 1 つ生成し、キャリーを次のポジションに保存します。 

すべての有効な sum-9 ペアが末尾の 0 を 1 つだけ提供し、正確に 2 桁を消費するため、貪欲なマッチングが最適です。 桁の利用可能性を超えて、異なる sum-9 ペア間に相互作用はありません。 利用可能なペアをすぐに選択しても、最終的なカウントを減らすことはできません。 

考えられるすべての初期合計 (10 ペア) を試すことで、最適なキャリー スタートを見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    cnt = [0] * 10
    for ch in s:
        cnt[int(ch)] += 1

    best = -1
    best_pairs = None

    # try all starting pairs with sum = 10
    for a in range(1, 10):
        b = 10 - a

        if cnt[a] == 0 or cnt[b] == 0:
            continue

        cur = cnt[:]
        cur[a] -= 1
        cur[b] -= 1

        pairs = [(a, b)]
        total = 1

        for x in range(10):
            y = 9 - x
            if x > y:
                break

            if x == y:
                take = cur[x] // 2
            else:
                take = min(cur[x], cur[y])

            for _ in range(take):
                pairs.append((x, y))

            cur[x] -= take
            cur[y] -= take
            total += take

        if total > best:
            best = total
            best_pairs = pairs

    # no carry possible
    if best == -1:
        a = []
        b = []

        digits = []
        for d in range(10):
            digits.extend([str(d)] * cnt[d])

        print("".join(digits))
        print("".join(digits))
        return

    used = [0] * 10
    left = []
    right = []

    for x, y in best_pairs:
        left.append(str(x))
        right.append(str(y))
        used[x] += 1
        used[y] += 1

    remain = cnt[:]
    for d in range(10):
        remain[d] -= used[d]

    extra_left = []
    extra_right = []

    leftovers = []
    for d in range(10):
        leftovers.extend([d] * remain[d])

    for i, d in enumerate(leftovers):
        if i % 2 == 0:
            extra_left.append(str(d))
        else:
            extra_right.append(str(d))

    while len(extra_left) < n - len(left):
        extra_left.append('0')

    while len(extra_right) < n - len(right):
        extra_right.append('0')

    left.extend(extra_left)
    right.extend(extra_right)

    left.reverse()
    right.reverse()

    print("".join(left))
    print("".join(right))

solve()
```解決策は、桁の頻度を数えることから始まります。 数字は 0 ～ 9 に制限されているため、数字タイプに対する以降のすべての操作は定数になります。 

外側のループは、合計が 10 になるすべての可能なペアを試行します。最初はキャリーがないため、これが最初の末尾のゼロを作成する唯一の方法です。 

そのペアを修正した後、コードは合計が 9 になるできるだけ多くのペアを貪欲に抽出します。 ループは次の時点までのみ反復されます。`x > y`対称ペアを 2 回処理することを避けるため。 

再建フェーズは少し微妙です。 数字のペアは、最下位の位置から上に向かって収集されます。 つまり、印刷する前に文字列を反転する必要があります。 

もう 1 つの簡単な間違いは、2 つの出力数値にはそれぞれ元の数値のすべての桁が正確に含まれている必要があることを忘れていることです。 このコードは、ペアリングによって消費された桁数を追跡し、残りの桁を任意に分配します。 

フォールバック ケースは、sum-10 ペアが存在しない入力を処理します。 この場合、キャリー チェーンを開始することはできないため、後続のゼロの最大数は 0 になります。

import sys, io

def solve():
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)

    cnt = [0] * 10
    for ch in s:
        cnt[int(ch)] += 1

    best = -1

    for a in range(1, 10):
        b = 10 - a

        if cnt[a] == 0 or cnt[b] == 0:
            continue

        cur = cnt[:]
        cur[a] -= 1
        cur[b] -= 1

        total = 1

        for x in range(10):
            y = 9 - x
            if x > y:
                break

            if x == y:
                take = cur[x] // 2
            else:
                take = min(cur[x], cur[y])

            cur[x] -= take
            cur[y] -= take
            total += take

        best = max(best, total)

    print(best if best != -1 else 0)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

111
```2 桁の合計が 10 になることはないため、アルゴリズムは有効な開始キャリー ペアを見つけることができません。 フォールバック ブランチはすぐにアクティブになり、2 つの同一の順列を出力します。 各桁の加算は最大で$1+1=2$、合計は 1 つのゼロでも終わることはできません。
