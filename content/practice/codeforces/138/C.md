 ## 解決策
 ## 問題の理解

 木を数直線上に配置しました。 それぞれの木は左に倒れたり、右に倒れたり、立ったままになる場合があります。 これら 3 つの結果の確率は、ツリーごとに独立して与えられます。 

倒れた木は、木の位置と高さによって決まる半開きの間隔でキノコを破壊します。 

位置に木がある場合`x`高さのある`h`左に落ちるとキノコが破壊されます`[x - h, x)`。 

正しく落ちると、キノコが破壊されます`(x, x + h]`。 

すべてのキノコには位置とパワー値があります。 キノコは木がそれを破壊しない場合にのみ生き残ります。 生き残っているすべてのキノコの予想される合計パワーが必要です。 

重要な観察は、期待が線形であるということです。 すべてのキノコをまとめて考える代わりに、各キノコの生存確率を個別に計算し、それにキノコのパワーを掛けて、すべてを合計することができます。 

制約はソリューションを強力に形作ります。 あり得る`10^5`したがって、すべての木をすべてのキノコに対してチェックするアルゴリズムは、およそのパフォーマンスを発揮します。`10^9`最悪の場合の操作は、1 秒の制限には遅すぎます。 キノコの数は少ないですが、`10^4`これは、キノコを反復処理して木を効率的に処理することが実現可能であることを示唆しています。 

微妙な点は、間隔の境界です。 左滝使用`[x - h, x)`、右下がりながら使用します`(x, x + h]`。 どちらの場合も、ツリーの位置自体は除外されます。 

次の例を考えてみましょう。```
1 1
5 3 100 0
5 10
```木は確率 1 で左に倒れますが、間隔が 5 であるため、位置 5 のキノコが生き残ります。`[2, 5)`、5自体は除外されます。 を使用した不注意な実装`<=`両側で誤って破壊してしまう可能性があります。 

もう 1 つの簡単な間違いは、複数の木が同じキノコに当たる可能性がある場合に発生します。```
2 1
0 5 50 0
10 5 0 50
5 100
```キノコは、危険な出来事が起こらなかった場合にのみ生き残ります。 正しい生存確率は次のとおりです。```
(1 - 0.5) * (1 - 0.5) = 0.25
```確率を直接加算して計算する`1 - 0.5 - 0.5 = 0`ツリーイベントは独立しているため、これは間違っています。 

3 番目のエッジケースには、ちょうど境界上にキノコが存在します。```
1 2
10 5 100 0
5 1
10 1
```5のキノコは破壊されるので、`5 ∈ [5,10)`。 10 が除外されるため、10 のキノコが生き残ります。 ハーフオープンインターバルを正しく処理することが不可欠です。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのキノコについて、すべての木を反復処理し、この木がキノコを破壊する確率を決定します。 

木が左に倒れてキノコを破壊できる場合、生存確率に次の値を掛けます。`(1 - left_probability)`。 右側も同様に。 

最後にキノコのパワーに生存確率を掛けて答えに加えます。 

これが機能するのは、ツリーの結果が独立しているためです。 キノコがすべての木で生き残る確率は、単に個々の木がキノコを破壊しない確率の積です。 

問題は複雑さです。 と`10^5`木々や`10^4`キノコ、私たちはパフォーマンスします`10^9`間隔チェック。 非常に小さな定数係数であってもタイムアウトになる可能性があります。 

重要な観察は、各ツリーが数直線上の連続区間にのみ影響を与えるということです。 すべての木をすべてのキノコごとに処理する代わりに、ソートされた順序でキノコを処理し、スイープ ライン スタイルのイベントで乗算効果を維持できます。 

木が左に倒れたとします。 次に、すべてのキノコが`[a-h, a)`が乗算されます`(1 - l/100)`その生存確率において。 

同様に、右下がりの場合も影響があります。`(a, a+h]`。 

これらは、キノコの位置に対する範囲の乗算です。 

キノコだけなので、`10^4`、それらを並べ替えて、対数時間の差分配列のアイデアを使用して乗法間隔の更新を適用できます。 すべての間隔について、その乗算寄与がどこで開始され、どこで終了するかをマークします。 

次に、キノコを 1 回スイープするだけで、各キノコに影響を与える合計乗算係数が再構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O((n + m) log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのキノコを読み取り、座標順に並べ替えます。 

ソートにより、ツリー効果をマッシュルーム配列全体の連続したインデックス範囲に変換できます。 
2. 配列を作成する`mul`サイズの`m + 1`、で初期化されます`1.0`。 

この配列には、乗算差分更新が格納されます。 スイープ中の実行積は、アクティブなツリー間隔からの生存確率の寄与を表します。 
3. すべての木について、左下がりの間隔を処理します。 

危険な間隔は`[a-h, a)`。 

ソートされたキノコ座標に対して二分探索を使用します。 

-`L = lower_bound(a-h)`-`R = lower_bound(a)`インデックスのキノコ`[L, R)`影響を受けています。 
4. 左側の間隔に乗算更新を適用します。 

左落ち確率が`p`、区間内のすべてのキノコは次のように乗算する必要があります。`(1-p)`。 

乗法差分更新の使用:

 -`mul[L] *= (1-p)`-`mul[R] /= (1-p)`その後、プレフィックス積によって完全な乗数が再構築されます。 
5. 右下がり区間も同様に処理します。 

危険な間隔は`(a, a+h]`。 

必要なものは次のとおりです。 

-`L = upper_bound(a)`-`R = upper_bound(a+h)`キノコ`[L, R)`影響を受けています。 
6. 係数を使用して同じ乗算範囲更新を適用します。`(1-r)`。 
7. キノコを左から右に掃除します。 

稼働中の製品を保守する`cur`。 

各インデックスで:

 -`cur *= mul[i]`-`cur`はこのキノコの生存確率と等しくなります。 
8.追加`cur * mushroom_power`答えに。 
9. 最終的な期待値を出力します。 

### なぜ効果があるのか

 すべての木は、それぞれのキノコの生存確率に独立して寄与します。 

固定キノコの場合、その生存確率は次のようになります。```
Π(probability this tree does not destroy it)
```このアルゴリズムは、各危険区間がカバーするすべてのキノコにこれらの乗算係数を正確に適用します。 

乗算差分配列技術により、スイープ中に実行中の積に、現在のマッシュルームに影響を与えるすべてのアクティブな間隔係数の積が正確に含まれることが保証されます。 

すべての間隔更新は 1 つのツリー方向イベントに正確に対応し、間隔は正しい半開境界で構築されるため、すべてのキノコは正確に正しい生存確率を受け取ります。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    trees = []
    for _ in range(n):
        a, h, l, r = map(int, input().split())
        trees.append((a, h, l / 100.0, r / 100.0))

    mushrooms = []
    for _ in range(m):
        b, z = map(int, input().split())
        mushrooms.append((b, z))

    mushrooms.sort()

    coords = [x for x, _ in mushrooms]

    mul = [1.0] * (m + 1)

    for a, h, lp, rp in trees:
        # Left interval: [a-h, a)
        L = bisect_left(coords, a - h)
        R = bisect_left(coords, a)

        if L < R and lp > 0:
            factor = 1.0 - lp
            mul[L] *= factor
            mul[R] /= factor

        # Right interval: (a, a+h]
        L = bisect_right(coords, a)
        R = bisect_right(coords, a + h)

        if L < R and rp > 0:
            factor = 1.0 - rp
            mul[L] *= factor
            mul[R] /= factor

    ans = 0.0
    cur = 1.0

    for i in range(m):
        cur *= mul[i]
        ans += cur * mushrooms[i][1]

    print("{:.10f}".format(ans))

if __name__ == "__main__":
    solve()
```最初の重要な実装詳細は、パワー値を付加したままキノコを分類することです。 すべての二分検索は、ソートされた座標配列に対して実行されます。 

範囲の更新では、加算差分ではなく乗算差分が使用されます。 間隔ですべての生存確率を乗算すると、`f`、次のように配置します。```
mul[L] *= f
mul[R] /= f
```スイープ中に、プレフィックス積によりファクターがアクティブになります。`L`そしてその後それを削除します`R-1`。 

境界の処理は最も注意が必要な部分です。 

のために`[a-h, a)`私たちは以下を使用します:```
bisect_left(a-h)
bisect_left(a)
```左側の境界は包含的であり、右側の境界は排他的であるためです。 

のために`(a, a+h]`私たちは以下を使用します:```
bisect_right(a)
bisect_right(a+h)
```左側の境界は排他的であり、右側の境界は包含的であるためです。 

間違った組み合わせを使用すると、`bisect_left`そして`bisect_right`境界ケースを静かに破ります。 

スイープ変数`cur`現在のキノコの合計生存確率乗数を常に保存します。 キノコのパワーを掛けると期待値への寄与が得られます。

 ## 特殊なケース

 境界の問題をもう一度考えてみましょう。```
1 2
10 5 100 0
5 1
10 1
```危険な間隔は`[5,10)`。 

二分検索では次の結果が得られます。```
L = lower_bound(5)
R = lower_bound(10)
```5 のキノコのみがそのインデックス範囲内にあります。 10 のキノコは、右端が開いているため除外されます。 

アルゴリズムは正しく出力します。```
1
```ここで、複数の木が 1 つのキノコに影響を与えると考えてみましょう。```
2 1
0 10 50 0
10 5 0 50
8 100
```キノコは両方の危険な区間にあります。 

更新要因は次のとおりです。```
0.5 and 0.5
```スイープではそれらを乗算します。```
0.5 × 0.5 = 0.25
```期待値:```
25
```これにより、独立確率が正しく処理されることが確認されます。 

最後に、キノコが木の位置に正確に存在することを考えます。```
1 1
0 100 100 100
0 10
```左の間隔は`[-100,0)`、右の間隔は`(0,100]`。 

位置 0 はどちらの区間にも属しません。 

二分検索では空の範囲が生成されるため、乗数は適用されません。 キノコは確率 1 で生き残り、次の答えが得られます。```
10
```ここで、誤って閉じた間隔を使用すると失敗します。
