 ## 解決策
 ## 問題の理解

 私たちは引き出しの中に手袋のコレクションを与えられ、それぞれの手袋に色とタイプ (左または右) が付いています。 それぞれについて、$n$色、手袋が何個残っているか正確にわかります$l_i$そして右の手袋$r_i$存在する。 私たちの目標は、少なくともフォームを形成できることを保証するために、盲目的に選択しなければならないグローブの最小数を決定することです。$k$一致する手袋のペア。各ペアは同じ色の左右の手袋 1 つずつで構成されます。 

入力は複数のテスト ケースで構成され、それぞれが色の数を指定します。$n$、必要な一致するペアの数$k$、および 2 つの配列$l$そして$r$左右のグローブのカウントについて。 各テスト ケースの出力は単一の整数、つまり保証するために選択する手袋の最小数です。$k$一致するペア。 

制約は重要です。$n$まで可能です$2 \cdot 10^5$、 そして$l_i$、$r_i$と同じ大きさにすることができます$10^9$。 これにより、手袋の選択を明示的にシミュレートしようとしたり、各手袋を個別に反復しようとしたりするソリューションは除外されます。そのようなアプローチには以下が含まれる可能性があるためです。$10^9$色ごとの反復回数。 代わりに、最悪の場合の選択と左右の手袋のバランスについて数学的に推論する必要があります。 

エッジケースには、一方が色を支配する状況が含まれます。$100$残された手袋と$1$右の手袋。 単純なアプローチでは、すべてのピックが支配的な側からのものである可能性を考慮せずに、単純に最大のカウントを選択する可能性があり、必要な数のペアを生成できません。 もう 1 つのエッジケースは次のような場合です$k$等しい$n$、色ごとに 1 ペアを強制するため、追加で何個選択する必要があるかを慎重に考慮する必要があります。 

## アプローチ

 強引なアプローチは、手袋を選ぶあらゆる可能な方法をシミュレートし、少なくとも次の条件を満たすかどうかを確認することです。$k$ペア。 これはあらゆる可能性を考慮しているので正しいでしょうが、計算上は不可能です。$10^9$実現不可能です。 

重要な洞察は、過剰な側からできるだけ多くの手袋を選択し、組み合わせの選択肢を最小限にすると、最悪のシナリオが発生するということです。 各色について、大きい方の一致しない手袋の数は次のように計算できます。$|l_i - r_i|$、最小保証ペアは、より小さい数の合計によって制限されます。$\min(l_i, r_i)$。 確実にするために$k$ペアの場合、小さい側のすべての手袋と、手が届く大きな側の余分な部分をカバーするのに十分な手袋を選択する必要があります。$k$。 

具体的には、次のようなアプローチです。 

1. 各色の左右の手袋をすべて合計し、色ごとに保証されるペアを次のように計算します。$\min(l_i, r_i)$。 
2. 各色の余剰手袋を次のように計算します。$|l_i - r_i|$、これは、戦略的に選択した場合に追加される可能性のあるペアを表します。 
3. 保証された手袋を超えて残りのペアを形成するために必要な追加の手袋の数を計算します。 これは、余剰の手袋の半分を使用することに相当します (追加の手袋ごとに、余剰から左右に 1 つずつ必要となるため)。 
4. すべての保証された手袋と追加の手袋を合計して、選択する最小数を見つけます。 

これにより、問題は手袋のピッキングのシミュレーションから色ごとの単純な算術演算に軽減され、結果として次のようになります。$O(n)$テストケースごとの複雑さ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(手袋合計) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`guaranteed_pairs`合計する$\min(l_i, r_i)$すべての色にわたって。 これは、手袋の選び方に関係なく、常に形成できるペアをカウントします。 
2. リストの初期化`surplus`保管する$|l_i - r_i|$色ごとに。 これらは、追加の手袋に貢献する可能性がある追加の手袋を表します。 
3. コンピューティング`remaining_pairs`ask - 保証されたペア`. If `残りのペア <= 0` の場合、保証されたペアはすでに十分です。 
4. 並べ替え`surplus`降順で、手袋が最も多い色を優先します。 
5. カウンタの初期化`extra_picks`ゼロに。 反復処理`surplus`そして、各剰余価値に対して、追加のペアを提供するために必要な数の手袋を用意します。 追加のペアごとに 2 つの手袋 (左 1 つ、右 1 つ) が必要になるため、`(surplus_i // 2)`ペア形成を最大化します。 
6. 満足するまで追加のピックを蓄積する`remaining_pairs`。 
7. 選択する手袋の最小数は、各色の小さい方の左右の手袋をすべて合計したものです (つまり、`guaranteed_pairs * 2`）プラス`2 * remaining_pairs`残りのペアを形成するために必要な追加の手袋を考慮するためです。 

不変条件というのは、`guaranteed_pairs`あらゆるシナリオに存在するペアをカウントし、余剰を戦略的に消費することで、ペアの総数が満たすかそれを超えることを常に保証できます。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        l = list(map(int, input().split()))
        r = list(map(int, input().split()))
        
        guaranteed = 0
        surplus = []
        
        for li, ri in zip(l, r):
            guaranteed += min(li, ri)
            surplus.append(abs(li - ri))
        
        if guaranteed >= k:
            # Need at least one glove from each of the k guaranteed pairs: 2*k
            print(2 * k)
            continue
        
        # Remaining pairs to form after guaranteed
        remaining = k - guaranteed
        surplus.sort(reverse=True)
        extra_picks = 0
        
        for s in surplus:
            take = min(remaining, s // 2)
            extra_picks += take
            remaining -= take
            if remaining == 0:
                break
        
        # Total picks = all guaranteed gloves + 2*remaining unfulfilled
        total_picks = 2 * sum(min(li, ri) for li, ri in zip(l, r)) + 2 * (k - guaranteed - extra_picks) + sum(surplus)
        print(total_picks)

if __name__ == "__main__":
    solve()
```コードはまず、保証されたペアと各色の余剰を計算します。 保証されたペアがすでに要件を満たしている場合は、ペアごとに 2 つの手袋を選択するだけです。 それ以外の場合は、余剰を使用して残りのペアを埋め、追加のピックが何回必要になるかを慎重に数えます。 余剰分を分類することで、最大の寄与分を最初に使い果たし、総ピック数を最小限に抑えることができます。
