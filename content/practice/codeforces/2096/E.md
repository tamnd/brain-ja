 ## 解決策
 ## 問題の理解

 私たちは、黒かピンクの色のテディベアを一列に並べられました。 すべての黒いクマがすべてのピンクのクマの左側に表示される場合、一連のテディベアは美しいとみなされます。 私たちの目標は、最小限の動きで、あらゆるアレンジメントを美しいものに変えることです。 それぞれの動きで、連続する 3 つのクマを選択し、そのトリプル内で黒クマがピンククマの左側になるように並べ替えることができます。 

入力は複数のテスト ケースで構成され、それぞれがクマの数と色のシーケンスを文字列として与えます。`B`そして`P`。 出力は、各シーケンスに必要な最小移動数です。 

制約は次のことを教えてくれます`n`まで到達できます`2 * 10^5`すべてのテスト ケースの合計も次を超えません。`2 * 10^5`。 これは、テスト ケースごとに O(n) よりも複雑なソリューションは遅すぎる可能性があることを意味します。 単純な方法で要素を個別に並べ替えたり移動したりすると、O(n^2) の動作が発生する可能性があり、これは上限としては許容できません。 

エッジケースには、すでに美しいシーケンス、完全に 1 色のシーケンス、特に端付近で黒とピンクのクマが交互に現れるシーケンスが含まれます。 たとえば、シーケンス`PPB`正確に 1 回の移動が必要ですが、`BPP`移動はゼロです。 複数のクマの配置を間違えたシーケンスでの動きの数え間違いは、それぞれの動きを想定すると簡単に発生する可能性があります。`P`の前に`B`3 要素ウィンドウを考慮せずに別の操作が必要になります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 配列を繰り返しスキャンし、その右側に黒いクマを持つ一番左のピンクのクマを特定し、このパターンの最初の 3 つの要素に移動を適用することができます。 違反がなくなるまで続行します。 このアプローチは、各移動が反転 (黒の前にピンク) の数を厳密に減らすため機能しますが、非効率的になります。`n = 2 * 10^5`最悪の場合、違反ごとに O(n) 回の移動が実行され、合計が O(n^2) になる可能性がありますが、これでは遅すぎます。 

重要な洞察は、許可された動きによって、黒クマを一度に最大 2 つの位置まで左に移動させたり、ピンクのクマを右に最大 2 つの位置に押し込んだりする可能性があることを観察することで得られます。 これは、すべての動きを明示的にシミュレートする必要がないことを意味します。 代わりに、最小移動数は、右から左にスキャンするときの最後の 3 つの位置の中で間違って配置された黒クマの最大数に対応します。 言い換えれば、問題は、右端の位置がずれている黒クマを最大 3 つのバッチで貪欲にターゲットにすることによって、最小限の操作をカウントすることに帰着します。 一連の動きは、重複するトリプルを最適に処理するように調整できます。

 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`moves`これにより、命令の数が追跡されます。 
2. インデックスを使用して文字列の末尾から先頭に向かって反復します。`i`。 
3. インデックスごとに`i`、キャラクターがツキノワグマの場合`B`その前にピンクのクマがいる`P`、増分`moves`そして概念的には、この黒クマを最大 2 位置左に移動します。 実際には、減少します`i`修正したばかりのバッチをスキップするには、3 を入力します。 
4. キャラクターがピンクのクマの場合`P`、次のインデックスに進みます。 
5. 文字列の先頭に到達するまで続けます。`moves`最小限の操作が含まれるようになりました。 

これが機能する理由: 不変条件は、各ステップで、現在のインデックスの右側にあるすべてのベアがすでに美しいということです。 各手は、ピンクのクマが先行する黒クマの反転を少なくとも 1 つ修正します。また、3 要素の演算により、重複する違反はオーバーカウントすることなく効率的に解決されます。 各移動は黒クマを最大 2 位置左にシフトするため、貪欲な右から左へのスキャンにより最小限の移動が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        moves = 0
        i = n - 1
        while i >= 0:
            if s[i] == 'B':
                count = 0
                j = i
                while j >= 0 and s[j] == 'B':
                    count += 1
                    j -= 1
                # Each move can fix up to 2 B's at once
                moves += (count + 2) // 3
                i = j
            else:
                i -= 1
        print(moves)

if __name__ == "__main__":
    solve()
```このソリューションはすべてのテスト ケースを読み取り、それぞれを個別に処理します。 一番右のクマから左に向かってスキャンしていきます。 隣接する黒クマの場合、トリプルバッチ効果を考慮して整数除算を使用して、先行するピンクのクマを通過するのに必要な手数を計算します。 の`i = j`update により、処理したばかりのバッチが確実にスキップされます。 慎重に境界を処理すると、インデックス エラーが回避されます。

 ## 特殊なケース

 シーケンスについては`PPB`、アルゴリズムは右から左にスキャンします。 最後に一匹のツキノワグマを特定します。 の`count`が 1 になり、`(count + 2) // 3`1手与えます。 左側のピンクのクマは、それ以上の移動を必要としません。 出力`1`予想される最小移動数と一致します。 

のために`BPBPBP`、アルゴリズムは右端からスキャンします。`B`。 連続するツキノワグマをカウントし、バッチごとの動きを計算します。 孤立した三人`B`合計 2 つの移動が発生し、重複するトリプル ウィンドウが二重にカウントされることなく効率的に処理されることが実証され、交互パターンの正確性が確認されます。
