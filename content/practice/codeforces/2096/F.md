 ## 解決策
 ## 問題の理解

 私たちに与えられたゲームは、`n`視聴者はそれぞれ乗組員または詐欺師のいずれかである可能性があります。 視聴者は、自分自身や他の人について連続した範囲で発言します。 各ステートメントには 2 つの形式のいずれかがあります。視聴者のセグメントに少なくとも 1 人の偽者が含まれていると主張するか、セグメントに偽者が含まれていないと主張します。 

複数の質問があり、それぞれがステートメントの連続したサブセットを指定しており、その範囲内のすべてのステートメントが同時に真であることが可能かどうかを判断する必要があります。 重要なのは、このゲームでは世界中に少なくとも 1 人の詐欺師または少なくとも 1 人の乗組員が存在することを保証していないため、記述の範囲外のことを想定することはできません。 

入力制限は大きく、テスト ケースごとに最大 200,000 のビューア、ステートメント、クエリがあり、すべてのテスト ケースの合計も 200,000 に制限されます。 これは、クエリごとにビューアやステートメントを単純に反復するソリューションは遅すぎることを示しています。 具体的には、すべてのステートメントについてすべての視聴者をチェックするブルートフォース手法では、次のような結果が得られます。`O(m*n)`テストケースごとに、最大で`4*10^10`最悪の場合、2 秒で実行可能な動作をはるかに超えた操作が可能になります。 

たとえば、あるステートメントでは視聴者 1 ～ 3 に少なくとも 1 人の偽者がいると述べ、別のステートメントでは視聴者 2 ～ 3 には偽者がいないと述べているなど、複数のステートメントが重なる場合に微妙なエッジ ケースが発生します。 各ステートメントを個別に単純にチェックすると、範囲の重複によって生じる競合を見逃す可能性があります。 もう 1 つの注意が必要なケースは、ステートメントが同じ範囲を完全にカバーしているものの矛盾している場合です。「1 ～ 5 に少なくとも 1 人の詐欺師が存在する」というステートメントと、「1 ～ 5 に詐欺師は存在しない」というステートメントを一緒にクエリすると、即座に「NO」が返されなければなりません。 重複を効率的に追跡しない不注意なアプローチでは、間違った答えが得られます。 

## アプローチ

 ブルート フォース ソリューションでは、各ステートメントにタイプを割り当ててから、ビューアのロールへのすべての割り当てを試行し、クエリ内のすべてのステートメントの一貫性をチェックします。 考えられるすべてのビューア割り当てをチェックすることで正確さが保証されるため、これは原則として正しいです。 ただし、`n`最大 2 * 10^5、割り当ての数は`2^n`、それは完全に不可能です。 クエリごとに各ステ​​ートメントを個別にチェックするだけだとしても、クエリごとに範囲を明示的に反復すると、次のような結果になります。`O(q * m * n)`動作が遅すぎます。 

重要な点は、役割を完全に割り当てる必要はないということです。 ステートメント間の潜在的な競合を特定するだけで済みます。 タイプ 0 (範囲内に詐欺師がいない) のステートメントは、その範囲内のすべての視聴者を強制的にクルーメイトになります。 タイプ 1 (少なくとも 1 人の偽者) のステートメントでは、その範囲内の少なくとも 1 人の閲覧者が偽者である必要があります。 タイプ 1 ステートメント全体がタイプ 0 ステートメントに含まれている場合、2 つのステートメントは競合します。 したがって、問題は、連続するステートメントのセット内で、タイプ 1 のステートメントが完全にタイプ 0 のステートメント内にあるかどうかを効率的に検出することに帰着します。 各ステートメントの最も古い競合位置を事前に計算し、クエリ範囲がこの最も早い競合を超えているかどうかを確認することで、一定時間内に各クエリに応答できます。 これにより、複雑さが法外な前処理から線形な前処理と定数時間のクエリに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * n * q) | O(n) | 遅すぎる |
 | 最適 | テスト ケースごとに O(m + q) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、視聴者数を読み取ります。`n`そしてステートメントの数`m`。 
2. 変数を初期化する`rightmost_zero`これまでに確認されたタイプ 0 ステートメントの最も遠いエンドポイントを追跡します。 これは、乗組員のみを含める必要がある最大範囲を表します。 
3. 配列を初期化する`earliest_conflict`サイズの`m + 1`競合が発生した最も古い位置を保存します。 
4. 1 から 2 までのすべてのステートメントを繰り返します。`m`。 各ステートメントについて:

 - タイプ 0 の場合は更新します`rightmost_zero`現在の値とこのステートメントのエンドポイントの最大値になります。 これにより、強制執行された乗組員の全範囲を確実に把握できます。 
- タイプ 1 の場合、このタイプ 1 ステートメントが前のタイプ 0 ステートメントと競合する可能性がある最も古いステートメント インデックスを記録します。 具体的には、開始点が以下の場合、`rightmost_zero`、その場合、潜在的に競合する可能性があり、`earliest_conflict[i]`の最大値である必要があります`earliest_conflict[i-1]`そして現在のインデックス。 それ以外の場合は継承`earliest_conflict[i-1]`。 
5. すべてのステートメントを処理した後、各ステートメントについて、前のタイプ 0 ステートメントの完全に内側にある最も古い競合するタイプ 1 が得られます。 
6. 各クエリについて`(l, r)`、どうかを確認してください`earliest_conflict[r] < l`。 true の場合、この範囲には競合がないため、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

これが機能するのは、タイプ 0 ステートメントが厳格な乗組員を強制し、そのような範囲内のタイプ 1 ステートメントはすべてのステートメントが true である可能性を直ちに侵害するためです。 右端のゼロを追跡し、競合を伝播することで、クエリごとの検証を単純な比較に削減します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        statements = []
        for _ in range(m):
            x, a, b = map(int, input().split())
            statements.append((x, a, b))
        earliest_conflict = [0] * (m + 1)
        rightmost_zero = 0
        for i, (x, a, b) in enumerate(statements, start=1):
            if x == 0:
                rightmost_zero = max(rightmost_zero, b)
            if x == 1:
                if a <= rightmost_zero:
                    earliest_conflict[i] = max(earliest_conflict[i-1], i)
                else:
                    earliest_conflict[i] = earliest_conflict[i-1]
            else:
                earliest_conflict[i] = earliest_conflict[i-1]
        q = int(input())
        for _ in range(q):
            l, r = map(int, input().split())
            print("YES" if earliest_conflict[r] < l else "NO")

if __name__ == "__main__":
    solve()
```コードはまず、タイプ 0 ステートメントによって課された乗組員の最も遠い範囲を追跡します。 タイプ 1 ステートメントがこの範囲内で始まる場合、競合する可能性があるため、これを次のように記録します。`earliest_conflict`。 クエリは、クエリ範囲内に競合が存在するかどうかを確認することによって回答されます。 使用する`i-1`伝播によって競合情報が累積されることが保証されるため、以前のタイプ 0 ステートメントを見逃すことはありません。
