 ## 解決策
 ## 問題の理解

 1 から n までの数値に対する順列タスクが与えられます。 各数字はスティックの長さを表し、すべての長さを 1 回だけ使用する必要があります。 目標は、連続する位置間の相対的な制約が満たされるように、これらのスティックをシーケンス内に配置することです。 

制約は、長さ n − 1 の文字列 s から取得されます。各文字は、シーケンス内の次の要素が前のすべての要素とどのように比較されるかを示します。 文字が「<」の場合、次に選択する数値は、すでに配置されているすべての数値よりも厳密に小さくなければなりません。 「>」の場合、次に選択する数値は、すでに配置されているすべての数値よりも厳密に大きくなければなりません。 

したがって、各ステップでは、隣接する要素のみを比較するのではなく、新しい要素をそれまでに構築されたプレフィックスのグローバル最小値または最大値と比較します。 「<」は新しいグローバル最小値を強制し、「>」は新しいグローバル最大値を強制します。 

重要な構造上の意味は、各ステップが現在の範囲を下方または上方に拡張し、決してその範囲内に収まらないということです。 これにより、間隔を繰り返し拡張してシーケンスを構築するようなプロセスになります。 

n ≤ 100 および t ≤ 500 という制約は、テスト ケースごとに O(n²) であっても十分に高速であることを意味します。 ただし、構造が単純なので直線的な施工も可能です。 主な困難は、将来の制約を考慮した有効な数値を常に確保できるようにすることです。 

よくある間違ったアプローチは、現在の文字のみに基づいて、未使用の最小値または最大値を貪欲に選択しようとすることです。 これは、将来の拡張を予測して選択する必要があるため、失敗します。 たとえば、最初に「>」が表示された場合、すぐに最大のものを選択すると、以前のすべての選択肢よりも小さい新しいグローバル最小値を必要とする後の「<」を満たすことができなくなる可能性があります。 

もう 1 つの失敗例は、未使用の値の上限と下限を適切に分離せずに、単純なスタックのような構造で「<」と「>」を対称的に扱うことです。 正確かどうかは、一連の制約の間の一貫したマッピングと、上向きまたは下向きに何回拡張したかに依存します。 

## アプローチ

 ブルート フォース ソリューションでは、1 から n までのすべての順列を試し、各順列が制約定義を満たすかどうかを確認します。 各候補の順列について、左から右にスキャンし、プレフィックスの最小値と最大値を維持し、各ステップが文字に応じて、前のすべての要素よりも厳密に小さいか、または前のすべての要素よりも厳密に大きいかのいずれかを満たしていることを確認します。 あるよ！ 順列であり、各チェックには O(n) が必要で、O(n · n!) 回の操作が必要になりますが、これは n = 100 の場合でも実行不可能です。 

重要な観察は、実際には順列を検索する必要がないということです。 制約は、新しい最小値または新しい最大値を作成する必要がある場合のみを記述します。 これは、極端な観点から考えることを示唆しています。 

構築のどの時点でも、未使用の番号から選択します。 使用可能な値のソートされたリストを維持する場合、「<」ごとに残りの最小の数値を選択することを強制されます。これは、その数値がその前のすべての数値よりも小さくなる必要があるためです。 同様に、すべての「>」は、残りの最大の数値を選択することを強制します。これは、その数値がその前のすべての数値よりも大きくなる必要があるためです。 

ただし、微妙な問題があります。最初の要素には制約がなく、その後の min および max 操作のシーケンスは残りのカウントと一致する必要があります。 これを解決する正しい方法は、シーケンスを逆に解釈することです。単純なカウント引数を使用して、下限と上限から何回取得するかを事前に決定し、1 回のパスで順列を構築します。

より明確な建設的なビューは次のとおりです。最初の要素を修正するとします。 その後、後続のすべてのステップで、新しいグローバル最小値または最大値が挿入されます。 これは、未使用の最小値または最大値を繰り返し取得してシーケンスを構築することと同じです。 制約文字列は、どちら側から取るかを直接示します。 

したがって、ソートされた利用可能な数値セットに対する 2 つのポインターを維持し、左から右へ貪欲に答えを構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 から n までの利用可能な数値のプールと、未使用の最小値と最大値を表す 2 つのポインターを維持することによって、順列を構築します。 

1. 使用可能な数値のリストを範囲 [1, n] として暗黙的に初期化し、下位ポインタを 1 に設定し、上位ポインタを n に設定します。 空の回答配列も用意します。 
2. 最初の要素を現在の値として任意に選択します。 後のステップを制限しないため、残りの最小値を選択するのが便利です。 シーケンスに 1 を配置し、下位ポインタを 2 に移動します。 
3. 文字列 s を左から右に繰り返します。 各文字で、新しいグローバル最小値または新しいグローバル最大値を作成する必要があるかどうかを決定します。 
4. s[i] が「<」の場合、以前に選択した値よりも小さい値を選択する必要があります。 順列を維持しながらこれを保証する唯一の方法は、下位ポインタから現在の最小の未使用値を取得することです。 それを追加して低く増加します。 
5. s[i] が「>」の場合、以前に選択したすべての値よりも大きい値を選択する必要があります。 現在の最大の未使用値を上位ポインターから取得します。 それを追加して高くデクリメントします。 
6. すべてのポジションが埋まるまで続けます。 各ステップは正確に 1 つの数値を消費するため、両方のポインターは正確に 1 回だけ一致します。 

正確さは、各ステップの後、以前に選択されたすべての要素が、使用された値のソート順で連続したセグメントを形成するという不変式に依存します。 ローエンドから取得する場合、使用されているセグメントを下に拡張します。 高い端から取るときは、それを上に伸ばします。 これにより、新しく選択されたすべての値が、対応する文字の要求どおりに、以前のすべての値よりも小さいか、または以前のすべての値よりも大きくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        low, high = 1, n
        ans = []

        ans.append(low)
        low += 1

        for ch in s:
            if ch == '<':
                ans.append(low)
                low += 1
            else:
                ans.append(high)
                high -= 1

        print(*ans)

if __name__ == "__main__":
    solve()
```コードは、未使用の範囲に 2 つのポインターを保持します。 最初の要素は最小値に固定されており、安定した開始点が保証されます。 「<」が表示されるたびに、次に小さい数値を消費してシーケンスを下方向に拡張します。 「>」が表示されるたびに、次に大きい数値を消費して上に拡張します。 各数値は 1 回だけ使用されるため、ポインタは自然に収束します。 

微妙な点は、最初の 1 の選択は任意ですが便利であるということです。 残りの構造が一貫して極端な値を消費する限り、固定の開始値は機能します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        low, high = 1, n
        ans = [low]
        low += 1

        for ch in s:
            if ch == '<':
                ans.append(low)
                low += 1
            else:
                ans.append(high)
                high -= 1

        out.append(" ".join(map(str, ans)))

    return "\n".join(out)

 ## 特殊なケース

 微妙なエッジケースは、文字列が「<」と「>」の間で交互に現れる場合です。 たとえば、n = 5、s = 「<>><」です。 すべてのステップが以前のパターン形状ではなく残りの極値にのみ依存するため、アルゴリズムは引き続き機能します。 低ポインタと高ポインタは常に内側に移動し、可用性が保証されます。 

もう 1 つの特殊なケースは、すべての接頭辞が「<」であることです。 この場合、増加する最小値を継続的に選択し、逆の順序で完全に減少するプレフィックスを効果的に生成します。 新しい値はそれぞれ、以前のすべての値よりも小さいことが保証されているため、アルゴリズムは引き続き有効です。 

最後に、文字列が「<」で終わる場合、最後のステップでは残りの最小値が強制されます。 Low と High は正確に収束するため、最終要素は一意に決定され、置換は曖昧さなく有効なままになります。
