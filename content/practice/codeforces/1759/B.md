 ## 解決策
 ## 問題の理解

 未知の順列に間違いなく属するいくつかの数値が与えられています。 欠損値は失われていますが、すべての欠損値の合計はわかっています。 

問題は、合計が正確に一致する追加の数字を選択できるかどうかです。`s`そのため、指定された数値を組み合わせると、最終的な配列が有効な順列になります。 

長さの順列`n`～からのすべての整数が含まれます`1`を通して`n`まさに一度。 この要件は、単に異なる値を持つことよりもはるかに強力です。 最終的な配列の最大値が`k`、次に、からのすべての数字`1`に`k`必ず現れるはずです。 

制約は非常に小さいです。 テスト ケースは最大 100 個あり、各テスト ケースには最大 50 個の既知の数値が含まれており、すべての値は最大 50 です。多くの候補の置換長を試行するシミュレーションでも、制限時間内で快適に実行できます。 高度なデータ構造や高度なアルゴリズムは必要ありません。 

難しいのは、欠落している数値がどのようなものかを理解することです。 これらは任意の個別の値ではありません。 最後の配列が何らかの最大値で終わる順列である場合`k`の場合、欠落している数値は正確に次の整数になります。`1`に`k`指定された配列にまだ存在しないもの。 

いくつかの特殊なケースを考えてみましょう。 

入力が次のようになっているとします。```
1
1 1
1
```既知の番号はすでに`1`。 数値の合計を加算するには`1`、別のものを追加する必要があります`1`、重複が作成されます。 より大きな数値はすべて少なくとも次の値であるため、これより大きな数値は機能しません。`2`。 答えは`NO`。 

ここで次のことを考えてみましょう。```
1
3 3
1 4 2
```間の唯一の欠損値`1`そして`4`は`3`、その合計は正確に`3`。 それを追加すると生成されます`[1,2,3,4]`、したがって、答えは次のとおりです`YES`。 

別の微妙なケースは次のとおりです。```
1
2 1
4 3
```不注意な解決策を講じると、合計が不足していることに気づく可能性があります。`1`追加できると仮定します`1`。 追加後`1`、配列には以下が含まれます`{1,3,4}`、これは順列ではありません。`2`まだ行方不明です。 正しい答えは、`NO`。 

最大値までのすべての整数が存在する必要があるという要件は、多くの誤った解法を防ぐための重要な観察事項です。 

## アプローチ

 ブルートフォースのアイデアは、合計が`s`、それらを指定された配列に追加し、結果が順列であるかどうかを確認します。 これは、すべての候補の補完を調査するため、正しいです。 問題は、サブセットの数が指数関数的に増加することです。 値が 50 で制限されている場合でも、すべての可能性を列挙する必要はなく、概念的には問題の構造が必要とするよりもはるかに複雑です。 

重要な観察は、順列はその最大値によって完全に決定されるということです。 

最後の順列が最大値を持つと仮定します。`k`。 次に、順列には以下のすべての整数が含まれている必要があります。`1`を通して`k`。 指定された数値はすでに固定されているため、追加する必要がある数値は、まさにこの範囲の欠落している整数です。 

これにより、問題が単純なシミュレーションに変わります。 

合計から始めます`s`。 指定されたセットにまだ存在しない最小の正の整数を繰り返し追加します。 このような数値を追加するたびに、次から減算します。`s`。 

もし`s`ちょうどゼロになると、順列の候補が見つかりました。 次に、結果のセットに次のすべての整数が含まれていることを確認するだけで済みます。`1`最大要素まで。 

もし`s`が負の場合、必要な欠損合計をすでに超えており、解は存在しません。 

すべての値が小さいため、このプロセスは非常に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(M + X) | O(M + X) | 承認済み |

 ここ`X`はシミュレーション中に検査された最大値であり、指定された制約の下では小さくなります。 

## アルゴリズムのチュートリアル

 1. 指定された番号を読み取り、メンバーシップを迅速に確認できるようにセットに保存します。 
2. から始める`1`、正の整数を上方向にスキャンします。 
3. 現在の数値がセット内に存在しない場合は常に、それを欠落した順列値として扱います。 からそれを引きます`s`そしてそれをセットに挿入します。 
4. まで続けます`s`ゼロまたはマイナスになります。 
5. もし`s`ネガになる、プリントする`NO`。 
6. もし`s`がちょうどゼロになる場合は、セット内の最大値を見つけます。 
7. 以下のすべての整数が正しいかどうかを確認します。`1`その最大値がセット内に存在することを介して。 
8. すべて存在する場合は、印刷します。`YES`; それ以外の場合は印刷します`NO`。 

### なぜ効果があるのか

 アルゴリズムは常に、指定された要素を含む有効な順列に出現する必要がある数値のみを追加します。 現在の最大値を含むすべての順列には、より小さな正の整数がすべて含まれている必要があるため、不足している整数を昇順に処理します。 

いつ`s`がゼロに達すると、セットには元の数値と、合計が必要な損失合計に等しい欠損値が正確に含まれます。 結果のセットが以下の完全な範囲を形成する場合、`1`最大の要素まで、それは順列です。 その範囲内の値が欠落している場合、すべての順列にはその欠損値も含まれている必要があるため、有効な順列を形成することはできません。 

このアルゴリズムは、必要な数値をスキップしたり、不要な数値を追加したりすることはないため、有効なケースを正確に受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    m, s = map(int, input().split())
    present = set(map(int, input().split()))

    x = 1

    while s > 0:
        if x not in present:
            s -= x
            present.add(x)
        x += 1

    if s < 0:
        print("NO")
        continue

    mx = max(present)

    ok = True
    for v in range(1, mx + 1):
        if v not in present:
            ok = False
            break

    print("YES" if ok else "NO")
```セット`present`現在知られているすべての番号を保存します。 メンバーシップのチェックは一定時間行われるため、値がすでに順列の一部であるかどうかを簡単に判断できます。 

ループは正の整数を昇順に処理します。 数値が欠落している場合、それは最終的な配列が順列になる場合に必ず出現する必要がある値の 1 つです。 それを差し引きます`s`そしてそれをセットに追加します。 

ループはすぐに停止します`s`はもうポジティブではありません。 負になる場合は、必要な欠損合計を超えており、有効な補完が存在しません。 

いつ`s`がちょうどゼロに達したら、最終検証を実行します。 のようなセット`{1,3,4}`重複はありませんが、順列ではありません。`2`は不在です。 最後の範囲チェックでは、そのようなケースが検出されます。 

すべての数値が小さいため、オーバーフローの懸念はありません。 唯一の微妙な詳細は、`s == 0`それだけでは十分ではありません。 セットが完全な間隔を形成していることをさらに検証する必要があります。`1`最大値まで。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        m, s = map(int, input().split())
        present = set(map(int, input().split()))

        x = 1
        while s > 0:
            if x not in present:
                s -= x
                present.add(x)
            x += 1

        if s < 0:
            ans.append("NO")
            continue

        mx = max(present)
        ok = all(v in present for v in range(1, mx + 1))
        ans.append("YES" if ok else "NO")

    return "\n".join(ans) + "\n"

## 特殊なケース

 次のことを考慮してください。```
1
1 1
1
```アルゴリズムは set から始まります`{1}`。 最初に欠落している正の整数は次のとおりです。`2`なので、それを引くと、`s = -1`。 合計がマイナスになるので、答えは`NO`。 これにより、必要な欠損合計が小さすぎて有効な新しい置換要素を追加できない場合が正しく処理されます。 

考慮する：```
1
2 1
4 3
```アルゴリズムは追加します`1`、作る`s = 0`。 セットはこうなります`{1,3,4}`。 最終検証では数値をチェックします`1,2,3,4`そしてそれを発見します`2`は不在です。 答えは`NO`。 これにより、不完全な範囲を受け入れることができなくなります。 

考慮する：```
1
3 3
1 4 2
```アルゴリズムは欠損値を追加します`3`、作る`s = 0`。 セットはこうなります`{1,2,3,4}`。 からのすべての数字`1`を通して`4`存在するので、答えは`YES`。 これにより、アルゴリズムが完了した順列を正しく認識していることが確認されます。 

考慮する：```
1
5 6
1 2 3 4 5
```次の欠損値は次のとおりです。`6`、 それから`7`、 等々。 追加`6`すぐに作る`s = 0`。 結果のセットは次のとおりです`{1,2,3,4,5,6}`、これは有効な置換です。 答えは`YES`。 このケースは、元の数値がすでに最終的な並べ替えの接頭辞を形成している可能性があることを示しています。
