 ## 解決策
 ## 問題の理解

 初期パワーを備えたヒューマノイドがいます`h`そして力を持った宇宙飛行士の集合体`a[i]`。 

ヒューマノイドは、宇宙飛行士のパワーがヒューマノイドの現在のパワーよりも厳密に小さい場合にのみ、宇宙飛行士を吸収できます。 吸収後、宇宙飛行士は消滅し、人型ロボットが獲得する`floor(a[i] / 2)`力。 

ヒューマノイドは、ちょうど 3 つの消耗品ブーストも所有しています。 緑色の血清を 2 つ使用すると現在の威力が 2 倍になり、青色の血清を 1 つ使用すると現在の威力が 3 倍になります。 各血清は最大 1 回まで使用できます。 

目標は、何人の宇宙飛行士を吸収できるかを最大化することです。 

最初の観察は、宇宙飛行士の順序が重要であるということです。 より弱い宇宙飛行士を早期に吸収すると、後でより強い宇宙飛行士を吸収するのに十分な電力が増加する可能性があります。 吸収が必要なので、`a[i] < h`、小さい宇宙飛行士は常に消費しやすいです。 

制約が主なヒントです。 すべてのテストケースにわたる宇宙飛行士の総数は最大で`2 * 10^5`、だから、`O(n log n)`溶液は完全に安全です。 二次関数は遅すぎるでしょう。`n^2`大体届くかもしれない`4 * 10^10`最悪の場合の運用。 

微妙なエッジケースは、「厳密に」という言葉から来ています。 

入力：```
1
1 5
5
```答えは次のとおりです。```
0
```宇宙飛行士は吸収できないので、`5`厳密には以下ではありません`5`。 を使用した不注意な実装`<=`間違って戻ってきます`1`。 

もう 1 つの簡単な間違いは、血清は常に後で使用するために保存する必要があると想定していることです。 

入力：```
1
3 1
2 4 100
```すぐに美容液を使用しないと何も吸収されません。 最適な戦略は血清から始まります。 「可能な吸収がすべてなくなった場合にのみ血清を使用する」などの貪欲なルールは、最初は吸収が不可能な場合にも正しく処理する必要があります。 

3 番目のエッジケースは、血清の使用順序が重要であるということです。 

入力：```
1
1 2
11
```ブルーセラムを最初に使用するとパワーが得られます`6`、その後、緑色の血清が与えられます`12`、吸収を可能にします。 最初に 2 つの緑色の美容液を使用すると、`8`、不十分です。 単一の血清順序を固定するソリューションでは、最適な順序を逃す可能性があります。 

最後の観察は、血清は合計で 3 つしかないということです。 この小さな数字が問題全体を変えます。 

## アプローチ

 強引な解決策では、宇宙飛行士を分類し、考えられるあらゆる一連の行動を試みます。 それぞれの瞬間に、利用可能な宇宙飛行士を吸収し、宇宙飛行士が残っている場合は緑色の血清を使用し、残っている場合は青色の血清を使用することができます。 

この検索は、あらゆる法的戦略を調査するため、正確です。 問題は州の数です。 ヒューマノイドの力は継続的に変化し、最大で`2 * 10^5`宇宙飛行士。 単純な検索はすぐに実行不可能になります。 

重要な観察は、宇宙飛行士を分類することで複雑さがほとんど解消されるということです。 

宇宙飛行士だと仮定してください`x`宇宙飛行士よりも小さな力を持っています`y`。 吸収できれば`y`、それなら私たちも吸収できます`x`。 小さな宇宙飛行士を早期に吸収することは、決して悪いことではありません。なぜなら、彼らは私たちの力を増加させるだけであり、時間以外のリソースを消費することはありませんが、それはここでは無関係です。 

分類後、あらゆる最適な戦略が左から右へ宇宙飛行士を吸収します。 唯一の本当の決定は、3 つの血清をいつ使用するかです。 

ここで、緑色の血清が 2 つと青色の血清が 1 つあることに注目してください。 使用順序は 1 つだけです`GGB`、`GBG`、 または`BGG`。 

それはただ`3! / 2! = 3`可能性。 

血清の順序が固定されている場合、シミュレーションは簡単になります。 宇宙飛行士をソート順に処理します。 現在の宇宙飛行士が吸収できない場合は、選択した順序から次の血清を消費します。 血清が残っていない場合、シミュレーションは終了します。 

考えられる血清の注文は 3 つだけなので、3 つすべてをシミュレーションして最大の答えを得ることができます。

 ## アルゴリズムのチュートリアル

 1. 宇宙飛行士のパワーを降順でない順に並べ替えます。 

後で吸収できる宇宙飛行士は、弱い宇宙飛行士がすべてすでに吸収された後に吸収することもできるため、並べ替えることで最小から最大の順に処理できます。 
2. 考えられる 3 つの血清オーダーを列挙します。`[(2,2,3), (2,3,2), (3,2,2)]`ここ`2`緑色の血清を表し、`3`青い血清を表します。 
3. 1 つの固定血清オーダーの場合、初期パワーから開始します。`h`、宇宙飛行士インデックス`i = 0`、血清指数`j = 0`。 
4. 宇宙飛行士が残っている間:

 もし`a[i] < current_power`、その宇宙飛行士を吸収し、力を増加させます`a[i] // 2`。 
5. 選択した順序に別の血清が存在する場合は、それを使用します。 

現在のパワーに次の血清乗数を乗算し、血清インデックスを進めます。 
6. そうしないと、宇宙飛行士が吸収されず、血清が残りません。 

シミュレーションを停止します。 
7. 何人の宇宙飛行士が吸収されたかを記録します。 
8. 3 つの血清オーダーすべてについてシミュレーションを繰り返します。 
9. 最大の結果を出力します。 

### なぜ効果があるのか

 選別後、吸収されたすべての宇宙飛行士はヒューマノイドの力を増加させるだけです。 現在吸収可能な宇宙飛行士をスキップして、代わりに大きな宇宙飛行士を吸収する理由は決してありません。なぜなら、小さな宇宙飛行士は少なくとも同じくらい消費しやすく、追加のパワーを提供するからです。 

唯一意味のある決定は、2 つの緑色の血清と 1 つの青色の血清の相対的な位置です。 異なる順序は 3 つしかないため、考えられるすべての血清戦略がシミュレーションの 1 つで表されます。 

血清の順序が固定されている場合、吸収が可能な間は血清の使用を遅らせることが最適です。 最初に吸収すると厳密にパワーが増加し、将来のすべてのオプションが保存されます。 血清は進歩が不可能になった場合にのみ必要です。 

すべての有効な戦略は 3 つの血清オーダーの 1 つに対応し、各シミュレーションはそのオーダーの最適な動作に従うため、3 つのシミュレーションの最大値を取ることで最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(arr, h, order):
    power = h
    serum_idx = 0
    absorbed = 0
    n = len(arr)
    i = 0

    while i < n:
        if arr[i] < power:
            power += arr[i] // 2
            absorbed += 1
            i += 1
        elif serum_idx < 3:
            power *= order[serum_idx]
            serum_idx += 1
        else:
            break

    return absorbed

def solve():
    t = int(input())
    orders = [
        (2, 2, 3),
        (2, 3, 2),
        (3, 2, 2)
    ]

    answers = []

    for _ in range(t):
        n, h = map(int, input().split())
        arr = list(map(int, input().split()))
        arr.sort()

        best = 0
        for order in orders:
            best = max(best, simulate(arr, h, order))

        answers.append(str(best))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```配列は各テスト ケースの開始時に 1 回ソートされます。 その後、各シミュレーションは配列を左から右に 1 回だけスキャンします。 

の`simulate`関数は、現在の電力、処理する次の宇宙飛行士、選択された順序でどの血清を次に使用する必要があるかという 3 つの状態を維持します。 

よくある間違いは、`<=`の代わりに`<`吸収性をチェックするとき。 このステートメントには厳密に小さい電力が必要です。 

もう一つの微妙な点は、美容液の使用です。 次の宇宙飛行士が現在吸収できない場合にのみ、血清を使用します。 最初に吸収することは、限られたリソースを消費せずにパワーを増加させるため、常に少なくとも同等の効果があります。 

Python の整数は、乗算を繰り返した後に発生する可能性のある大きなべき乗を自動的に処理するため、オーバーフローは心配ありません。

## 特殊なケース

 次のことを考慮してください。```
1
1 5
5
```選別した結果、力を持つのは宇宙飛行士だけ`5`。 人型にも力がある`5`。 アルゴリズムチェック`5 < 5`、これは誤りです。 血清を使用する場合もありますが、それがなければ宇宙飛行士は吸収できません。 厳密な比較はステートメントと正確に一致し、一般的な比較を防ぎます。`<=`バグ。 

考慮する：```
1
3 1
2 4 100
```ソートされた配列はすでに`[2, 4, 100]`。 最初の宇宙飛行士は吸収できません。`2 < 1`は誤りです。 シミュレーションは、選択した順序に従って血清の消費を直ちに開始します。 これにより、最初に進行不能な状況が正しく処理されます。 

考慮する：```
1
1 2
11
```3 つの血清注文は個別にテストされます。 注文`(3, 2, 2)`権力に達する`12`2つの血清を摂取した後、宇宙飛行士を吸収します。 注文`(2, 2, 3)`のみに達します`8`ブルーセラムを使用する前とパフォーマンスが異なります。 3 つの可能性をすべて列挙することで、最適な順序が決して見逃されないことが保証されます。 

考慮する：```
1
2 6
6 7
```最初の宇宙飛行士は、出力が厳密に大きくなければならないため、吸収することはできません。 血清を使用するとヒューマノイドのパワーが上昇し、その後、両方の宇宙飛行士が吸収可能になります。 このアルゴリズムは、等価性が十分であるものとして扱うのではなく、吸収が正当になるまで正しく待機します。
