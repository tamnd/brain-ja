 ## 解決策
 ## 問題の理解

 この問題は、ルート化されたツリーのすべての深さレベルに表示される必要がある頂点の数を示します。 最初の数値はツリーの高さを表し、次のシーケンスはルートから正確に 0 エッジ、1 エッジ、2 エッジなどの位置にある頂点の数を示します。 タスクは、この情報によって固有の根付きツリー形状が強制されるかどうか、または 2 つの異なる非同型ツリーが同じ深さカウントを満たすことができるかどうかを判断することです。 ツリーが一意でない場合は、2 つの異なるツリーを表す 2 つの有効な親配列を構築する必要があります。 これは、Codeforces の「ハッシュ ツリー」問題の背後にある古典的な考え方です。 

高さは最大約 100,000 まで大きくすることができ、頂点の総数には制限があります。 これは、解の頂点数が線形に近い必要があることを意味します。 考えられるすべてのツリーを構築したり、考えられる多くの配置を比較したりすると、異なる親の選択肢の数が膨大になる可能性があるため、成長が早すぎます。 曖昧さがいつ現れるかを正確に知らせる構造的特性を見つける必要があります。 

いくつかの特殊なケースは見落とされがちです。 ルート以降の各レベルに頂点が 1 つだけある場合、ツリーは強制的に 1 つのパスになります。 たとえば、入力```
2
1 1 1
```可能なツリーは 1 つだけなので、出力は次のようになります。```
perfect
```あるレベルに複数のノードがあるかどうかだけをチェックする不用意なアプローチは、これを誤って曖昧と呼ぶ可能性があります。 

もう 1 つの重要なケースは、2 つの隣接するレベルの両方に複数の頂点が含まれる場合です。 例えば、```
2
1 2 2
```曖昧です。 最初のレベルには 2 つのノードがあり、次のレベルにも 2 つのノードがあります。 両方のより深いノードを同じ親の下に接続することも、2 つの親間で分割することもできます。 これらにより、さまざまな根を張った木の形状が得られます。 

正しい出力は次で始まります。```
ambiguous
```その後に 2 つの異なる有効なツリーが続きます。 隣接するレベルを考慮せずにシーケンス内で繰り返される値のみを検索するソリューションでは、この状況は見逃されます。 

## アプローチ

 問題を解決する直接的な方法は、レベル数に一致する可能なすべてのツリーを構築してみることです。 1 つのレベルの頂点ごとに、次のレベルから受け取る子の数を選択します。 これは正しいです。なぜなら、このようなツリーを構築する際の自由は、連続したレベルの親間での子の分散だけであるからです。 ただし、多くの頂点を持つ 1 つのレベルでも、膨大な数の分布が作成されます。 最大数十万の頂点があるため、可能性の数は探索できる範囲をはるかに超えています。 

重要な点は、ツリー構造を変更する選択肢があるのは、連続する 2 つのレベルの両方に分岐がある場合だけであるということです。 想定レベル`i`少なくとも 2 つの頂点とレベルが含まれています`i + 1`少なくとも 2 つの頂点も含まれています。 レベルの高い子どもたち`i + 1`1 つの親に集中することも、複数の親に分散することもできます。 これら 2 つの選択により、異なるサブツリー形状が作成されます。 

このプロパティを持つ隣接するレベルのペアがない場合、すべての分岐レベルの後に単一のチェーンが続きます。 レベルに複数の頂点があると、次のレベルはそれ以上分割できないため、子を再配置して別の非同型ツリーを作成する方法はありません。 ツリーは一意に決定されます。 

あいまいさが存在する場合は、まず有効なツリーを構築し、次に連続する分岐レベルの最初のペアでローカルな変更を 1 つ行うことができます。 1 つの子を最初の親から 2 番目の親に移動すると、すべての深さのカウントを維持したまま形状が変更されます。

 ## アルゴリズムのチュートリアル

 1. すべての深さレベルの高さと頂点の数を読み取ります。 頂点の最終的な番号付けにおける各レベルの開始インデックスを追跡します。 ルートは頂点 1 であり、レベル順に頂点が割り当てられます。 
2. 現在のレベルのすべての頂点を前のレベルの最後の頂点に接続して、最初のツリーを構築します。 すべての頂点が必要な深さを正確に受け取るため、これにより常に有効なツリーが作成されます。 
3. 隣接するレベルのすべてのペアをスキャンします。 あるレベルと次のレベルの両方に少なくとも 2 つの頂点が含まれている場合、ツリーは曖昧になります。 その理由は、次のレベルの子を複数の方法で配置できるためです。 
4. そのようなペアが存在しない場合は、次のように出力します。`perfect`なぜなら、すべての有効なツリーは同じ構造を持つ必要があるからです。 
5. レベルに曖昧さが見つかった場合`i`そして`i + 1`、最初に構築されたツリーを最初の答えとして使用します。 2 番目の答えでは、レベル上の 1 つの頂点の親を変更します。`i + 1`レベルの最初の頂点から`i`レベルの 2 番目の頂点まで`i`。 これにより変更されるのは接続パターンのみであり、深さの頂点の数は変更されません。 

なぜ効果があるのか:

 ノードの親は、前のレベルの頂点のみにすることができます。 2 つの連続するレベルの両方に複数の頂点がある場合、子を分散する方法は少なくとも 2 つあり、それらの方法では同じ深さの頂点に対して異なる数の子が生成される可能性があります。 この違いは頂点の名前を変更しても取り除くことができないため、ツリーは同形ではありません。 

すべての隣接するペアに頂点が 1 つだけあるレベルが含まれている場合、すべての分岐の決定が強制されます。 頂点が 1 つあるレベルには可能な親が 1 つだけあり、分岐レベルの後に再配置可能な別の分岐レベルを続けることはできません。 ツリー全体の形状が固定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h = int(input())
    a = list(map(int, input().split()))

    start = [0] * (h + 1)
    cur = 1
    for i in range(h + 1):
        start[i] = cur
        cur += a[i]

    n = cur - 1

    parent1 = [0] * (n + 1)
    parent2 = [0] * (n + 1)

    current = 1
    for level in range(1, h + 1):
        prev_start = start[level - 1]
        prev_vertex = prev_start
        for j in range(a[level]):
            parent1[current] = prev_vertex
            parent2[current] = prev_vertex
            current += 1

        if level > 0 and a[level - 1] > 1 and a[level] > 1:
            pass

    for i in range(h):
        if a[i] > 1 and a[i + 1] > 1:
            child = start[i + 1]
            parent2[child] = start[i] + 1

            print("ambiguous")
            print(*parent1[1:])
            print(*parent2[1:])
            return

    print("perfect")

if __name__ == "__main__":
    solve()
```配列`start`番号付けの各深さレベルが始まる場所を格納します。 これにより、レベルの最初と 2 番目の頂点を一定時間内に識別することが可能になります。 

最初のツリーは貪欲に作成されます。 新しいレベルのすべての頂点は、前のレベルの最初の頂点にアタッチされます。 構築中に重要なのは深さのカウントのみであるため、これにより有効なツリーが生成されます。 

条件は入力シーケンスのみに依存するため、曖昧さのスキャンは構築とは別個に行われます。 隣接する分岐レベルのペアが見つかったら、より深いレベルの最初の頂点の親を変更するだけで 2 番目のツリーを作成できます。 

インデックス作成の詳細は、最も間違いを犯しやすい場所です。 ルートは頂点 0 ではなく 1 なので、`start[i]`は常に実頂点番号を参照します。 出力には、頂点の親が 1 から 1 までの順序で必要です。`n`これが、最後のスライスが未使用のゼロ インデックスをスキップする理由です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各頂点は、ツリーの構築および確認中に一定の回数処理されます。 |

 このアルゴリズムは、頂点の数に対して線形作業のみを実行します。 頂点の総数が主要な要素であるため、これは意図した制約に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    h = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    start = [0] * (h + 1)
    cur = 1
    for i in range(h + 1):
        start[i] = cur
        cur += a[i]

    n = cur - 1
    p1 = [0] * (n + 1)
    p2 = [0] * (n + 1)

    cur = 1
    for level in range(1, h + 1):
        for _ in range(a[level]):
            p1[cur] = start[level - 1]
            p2[cur] = start[level - 1]
            cur += 1

    out = []
    for i in range(h):
        if a[i] > 1 and a[i + 1] > 1:
            p2[start[i + 1]] = start[i] + 1
            out.append("ambiguous")
            out.append(" ".join(map(str, p1[1:])))
            out.append(" ".join(map(str, p2[1:])))
            sys.stdin = old
            return "\n".join(out) + "\n"

    sys.stdin = old
    return "perfect\n"

assert run("2\n1 1 1\n") == "perfect\n", "single path"
assert run("2\n1 2 2\n").splitlines()[0] == "ambiguous", "branching case"
assert run("3\n1 2 1 1\n") == "perfect\n", "branch followed by chain"
assert run("3\n1 2 2 1\n").splitlines()[0] == "ambiguous", "two branching levels"
assert run("1\n1 5\n").splitlines()[0] == "perfect", "star tree"

 ## 特殊なケース

 チェーンケースの場合```
2
1 1 1
```アルゴリズムは親を構築します`0 1 2`。 スキャン中、隣接するレベルではカウントが 1 を超えることはないため、変更はできません。 印刷します`perfect`、これは唯一可能な形状と一致します。 

曖昧な場合については```
2
1 2 2
```アルゴリズムは、レベル 1 と 2 の両方に複数の頂点があることを認識します。 最初のツリーは頂点 4 と 5 を頂点 2 の下に接続します。2 番目のツリーは頂点 4 を頂点 3 の下に移動します。レベル カウントは残ります。`1, 2, 2`ですが、1 つのツリーには 2 つの子を持つノードがあり、もう 1 つはそれらを展開します。 

次のような境界ケースの場合```
3
1 2 1 1
```レベル 1 は分岐しますが、レベル 2 には頂点が 1 つだけ含まれます。 その頂点には親が 1 つだけ存在する必要があるため、代替構造はありません。 アルゴリズムは単一の分岐レベルを正しく無視し、次のように出力します。`perfect`。 

のために```
3
1 2 2 1
```レベル 1 と 2 は両方とも分岐します。 最初の深い頂点は、レベル 1 の 2 つのノードのいずれかに接続できます。アルゴリズムはこの隣接するペアを検出し、2 つの異なる有効なツリーを生成します。
