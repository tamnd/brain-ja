 ## 解決策
 ## 問題の理解

 この問題では、円に少なくとも次の要素が含まれるように、平面上のどこかに配置できる円の最小半径を求めます。`M`のうちの`N`与えられたポイント。 点は固定されていますが、円の中心は完全に自由です。 必要なのは半径だけであり、中心位置は必要ありません。 元の問題は、可能な限り最小の「人口円」を見つける幾何学的バージョンであり、点は人々の位置を表します。 

入力では、整数座標を含む最大 500 個のポイントと、カバーする必要があるターゲット数のポイントが与えられます。 座標は絶対値で 100 万にも達する可能性があるため、ジオメトリでは考えられるすべての中心を列挙することを避ける必要があります。 と`N = 500`、`O(N^3)`解決策はすでに限界に近づいている可能性がありますが、何度も繰り返すと遅くなりすぎます。 正確な浮動小数点の答えが必要なため、最終的なアルゴリズムには管理可能な数の演算と制御された数値誤差の両方が必要です。 

よくある間違いは、中心が既存の点である円のみを考慮することです。 最適な円は、特定の点の中心にある必要はありません。 たとえば、入力の場合```
2 2
0 0
2 0
```正しい出力は`1.0`、円の中心が`(1,0)`半径あり`1`両方の点をカバーします。 点の中心のみを試行するメソッドは、指定された点の 1 つを中心として選択し、半径を取得します。`2`。 

もう 1 つのエッジ ケースは、答えが正確に境界上の点によって決定される場合です。 例えば：```
3 3
0 0
2 0
1 1
```最小半径は約`1.0`。 最適な円には境界上にいくつかの点があるため、厳密な円を使用します。`< r`チェック中に比較すると、実際の答えが誤って拒否される可能性があります。 

3 番目のケースは、多くの点が同一である場合に発生します。```
3 3
5 5
5 5
5 5
```答えは`0`。 すべての点のペアがゼロ以外の直径を形成すると仮定したアプローチは、ここでは失敗します。 

## アプローチ

 簡単なアプローチは、円の中心を推測し、それがカバーする点の数を数えることです。 難しいのは、中心が平面上のどこにでもある可能性があるため、無限に多くの可能性があることです。 当然の制限として、一連の点をカバーする最小の円は通常、境界点によって決定されるため、点のペアによって定義される円を試すことができます。 ペアを列挙し、すべての点をチェックすると、`O(N^3)`方法。 

各ペアについて、考えられる円の半径の中心を計算できます。`R`これら 2 つのポイントを通過するポイントを計算し、各候補者がカバーするポイントの数を数えます。 これが機能するのは、固定半径の場合、最大数の点をカバーする最適な円をその境界が少なくとも 1 つの点に接触するまでシフトでき、有用な中心候補をこれらの角度イベントで表すことができるからです。 問題は、このプロセスを半径全体にわたる二分探索内で実行する必要があることです。`O(N^3 log W)`, 500点としては遅すぎます。 

重要な観察は、半径の実現可能性が単調であるということです。 半径の場合`R`カバーできる`M`ポイント、より大きな半径もすべてカバーできます`M`ポイント。 これにより、答えを二分探索できます。 

固定半径の場合、問題は少なくとも中心が内側にあるかどうかを確認することになります。`M`の`N`半径の円`R`指定された点を中心に配置されます。 飛行機全体を探索する必要はありません。 すべての点について、答えの円の中心が半径の円周上を移動することを想像してください。`R`その点の周りを一周します。 カバーできる他の点は、この円周上に角度間隔を作成します。 ある程度の角度が十分な間隔に含まれている場合、その中心の位置は十分な点をカバーします。 

これが機能する理由は、有効なカバー円が存在する場合、その中心が半径の内側にあるためです。`R`カバーするすべてのポイントのディスク。 カバレッジを失うことなく、これらのディスクの 1 つの境界に中心を移動できます。 したがって、すべての境界円をチェックするだけで十分です。 

境界基準として選択したすべての点について、他の点によって寄与されるすべての有効な角度間隔を計算し、間隔の端点を並べ替え、スイープ ラインを使用して最大の重なりを見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3 log W) | お(1) | 遅すぎる |
 | 最適 | O(N² log N log W) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 半径を二分探索します。 検索範囲は次から始まります`0`答えは連続的であり、実現可能性関数は false から true に 1 回だけ変化するため、十分に大きな値になります。 
2. 候補半径について、実現可能性チェックを実行します。 少なくともカバーするこの半径の円が存在する場合、チェックは true を返します。`M`ポイント。 
3. 各点について、それを候補円の境界上にある点として扱います。 距離にある考えられるすべての中心を正確に考慮する`radius`この時点から。 これらの中心は円を形成し、その上の位置を角度で表します。 
4. 他のすべての点について、中心がその点をカバーするのに十分に近づく角度の範囲を決定します。 2 つの制限角度は、可能な 2 つの半径円から得られます。`radius`両方のポイントを通過します。 
5. 間隔エンドポイントをイベント リストに追加します。 間隔が開始されたら、現在のカバレッジ数を増やします。 終わったら減らします。 スイープ中の最大カウントは、この境界円上の中心によってカバーされる点の最大数を示します。 
6. 最大適用範囲に達した場合`M`任意の基準点に対して、候補半径が可能です。 そうしないと小さすぎます。 

最適な円には境界上に覆われた点が存在する可能性があるため、スイープはすべての点に対して実行されます。 すべてをチェックすることで、最適な境界位置が考慮されることが保証されます。 

機能する理由: 半径を大きくしても中心候補が追加されるだけで、中心が削除されないため、二分探索は正しいです。 すべての有効な解は、中心がカバーされたポイントの半径ディスクの境界に接触する解に変換できるため、実現可能性チェックは正しいです。 角度スイープでは、そのような境界位置をすべて調べて、同時にカバーされる点の最大数を見つけます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

eps = 1e-12
PI = math.pi

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    pts = []
    for _ in range(n):
        x = int(next(it))
        y = int(next(it))
        pts.append((x, y))

    def check(r):
        if r == 0:
            return n >= m

        rr = r * r
        for i in range(n):
            events = []
            x1, y1 = pts[i]
            for j in range(n):
                if i == j:
                    continue
                x2, y2 = pts[j]
                dx = x2 - x1
                dy = y2 - y1
                d2 = dx * dx + dy * dy

                if d2 > 4 * rr + eps:
                    continue

                d = math.sqrt(d2)
                if d < eps:
                    continue

                base = math.atan2(dy, dx)
                half = math.sqrt(max(0.0, rr - d2 / 4.0))
                angle = math.acos(d / (2 * r))

                l = base - angle
                h = base + angle

                while l < 0:
                    l += 2 * PI
                    h += 2 * PI
                while l >= 2 * PI:
                    l -= 2 * PI
                    h -= 2 * PI

                if h <= 2 * PI:
                    events.append((l, 1))
                    events.append((h, -1))
                else:
                    events.append((l, 1))
                    events.append((2 * PI, -1))
                    events.append((0, 1))
                    events.append((h - 2 * PI, -1))

            events.sort(key=lambda x: (x[0], -x[1]))
            cur = 1
            best = 1
            for _, v in events:
                cur += v
                if cur > best:
                    best = cur
            if best >= m:
                return True
        return False

    lo, hi = 0.0, 2e6
    for _ in range(50):
        mid = (lo + hi) / 2
        if check(mid):
            hi = mid
        else:
            lo = mid

    print("{:.15f}".format(hi))

if __name__ == "__main__":
    solve()
```コードは最初にすべてのポイントを読み取り、二分探索で使用される実現可能性テストを定義します。 二分探索では 50 回の反復が使用されますが、必要な精度はおよそ であるため、これで十分です。`1e-4`。 

内部`check`、すべての点が候補円の境界点として使用されます。 別の点がスイープに影響を与えるには、2 つの点の距離が最大でも離れていなければなりません`2r`、それ以外の場合は半径の円はありません`r`両方を含めることができます。 有効な中心位置は角度間隔になります。 

インターバルの処理は最もデリケートな部分です。 角度は次から回り込みます`2π`に戻る`0`, そのため、この境界を越える区間は 2 つの通常の区間に分割されます。 同じ角度でイベントが終了する前に開始イベントを並べ替えると、点が境界上に正確に位置する場合が処理されます。 

初期のカバレッジ数は次のとおりです。`1`選択された境界点は常に候補円で覆われているためです。 スイープでは他のポイントのみがカウントされます。

 ## 特殊なケース

 最適な中心が入力点の 1 つではない場合、```
2 2
0 0
2 0
```二分探索では中心を推測しないため、アルゴリズムがこれを処理します。 半径の実現可能性チェック中`1`、境界基準としていずれかの点を選択すると、中央の中心位置を含む角度間隔が作成されます。 スイープでカバレッジが見つかる`2`。 

重複したポイントについては、```
3 3
5 5
5 5
5 5
```二分探索では非常に小さな半径がテストされます。 半径内`0`の場合、すべての点がすでに同じ位置にあるため、特殊な場合はすぐに true を返します。 これにより、角度計算でのゼロ除算が回避されます。 

点が円の境界上に正確に存在する解の場合、```
3 3
0 0
2 0
1 1
```間隔のエンドポイントはスイープ中に含まれます。 並べ替え順序では、同じ角度で終了イベントの前に開始イベントが処理されるため、境界上の中心が正しくカウントされます。 これにより、精度誤差による真の最小半径の損失が防止されます。
