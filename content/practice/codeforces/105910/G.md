 ## 解決策
 # 問題の理解

 すべてのエッジに方向を割り当てる必要があるツリーがあります。 一部のエッジはすでに固定方向を持っていますが、残りのエッジは選択できます。 すべての頂点について、そこに入るエッジの数は、許可された度数の指定されたセットに属している必要があります。 未知のエッジを指示するすべての有効な方法の中で、未知のエッジの選択を説明する辞書編集上最小の文字列を出力する必要があります。 未知のエッジの場合`(x, y)`、答えの文字は`0`から指示する場合`x`に`y`、 そして`1`さもないと。 

ツリー構造が主要な制限です。 エッジは 2 つのコンポーネントを接続するだけなので、エッジの方向をサブツリーの親に固定した後は、そのサブツリーの残りの部分を独立して解決できます。 これにより、この問題を一般的なグラフの向きの問題として扱うことが除外されます。 

すべてのテスト ケースにわたる頂点の合計数は数十万に達する可能性があるため、アルゴリズムは線形に近い必要があります。 すべてのノードに対して可能なすべての次数カウントを試行する二次動的計画法ソリューションは遅すぎます。 すべてのエッジを一定の回数だけ処理する必要があります。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 リーフには入射エッジが 1 つだけあるため、その入次数は次のとおりです。`0`または`1`。 たとえば、1 つのエッジの場合:```
n = 2
edge: 1 2
allowed(1) = {1}
allowed(2) = {1}
```唯一有効な方向は、`1 -> 2`そして答えは`0`。 サブツリーの子側のみをチェックするソリューションでは、ルートにも indegree 制約があることを見逃す可能性があります。 

もう 1 つの注意が必要なケースは、ノードに複数の子があり、一部の子サブツリーの可能な方向が 1 つだけである場合です。 例えば：```
1
|
2
|
3
```頂点の場合`2`度数が必要です`1`、両方のエッジがそれを指すことはできません。 将来の子を無視する貪欲な選択により、最初のエッジが誤って選択され、残りのサブツリーが不可能になる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべての未知のエッジに対して両方向を試行することです。 完全な割り当てごとに、すべての頂点の入ってくるエッジをカウントし、すべてのカウントが許可されているかどうかを確認します。 これは、考えられるすべての向きを直接テストするため、正しいです。 ただし、`k`必要な未知のエッジ`2^k`課題。 いつ`k`これは制限時間の許容範囲をはるかに超えています。 

木の構造により、視界が良くなります。 木を根付かせます。 頂点の場合、その親が必要とする唯一の情報は、親からのエッジがこの頂点に入るのか、それともそこから出るのかということです。 それが分かれば、子供たちは独立して解決できるようになります。 

頂点ごとに 2 つの状態を計算します。`dp[v][0]`のサブツリーを意味します`v`親エッジが追加されない場合に有効にすることができます。`v`の度数。`dp[v][1]`親エッジが 1 を追加したときに有効にできることを意味します`v`の度数。 

頂点の子は貢献するだけです`0`または`1`頂点の入次数に。 すべての子が単一の値または両方の値に寄与するため、受信子エッジの可能な数は常に連続した間隔を形成します。 これにより、子からの達成可能な最小および最大の貢献のみを保存することができます。 

実現可能性を計算した後、再構築は貪欲に行われます。 未知のエッジは、出現した順に処理されます。 エッジを決定するときは、まず次のように割り当ててみます。`0`。 対応する子の状態と残りの可能な度数間隔で解決策がまだ可能な場合は、それを保持します。 それ以外の場合は割り当てなければなりません`1`。

 ## アルゴリズムのチュートリアル

 1. ツリーの頂点にルートを作成します`1`そして子リストを作成します。 これを行うとき、最終的な答えはその順序によって定義されるため、元のエッジの順序を覚えておいてください。 
2. ボトムアップ DFS を実行します。 すべての頂点について、そのサブツリーが両方の親エッジ状態で可能かどうかを計算します。 現在の頂点を指すことができる子エッジの最小数と最大数を追跡して、子を結合します。 
3. 親の寄与を持つ頂点の場合`p`、子供の寄付数を見つけます`x`そのような`p + x`は許容される度数です。 これにより、サブツリー状態が可能かどうかが決まります。 
4. DP が完了したら、ルートから再構築を開始します。 ルートの許容される次数を満たすようにしてください。 
5. エッジの昇順で各子エッジについて、辞書順に小さい方向を最初に試します。 子がその親の寄与を処理でき、残りの子が有効な度数カウントを提供できる場合は、それを選択します。 
6. 再帰的に続行します。 選択されたすべてのエッジは子サブツリーの親の寄与を修正するため、同じ実現可能性情報が有効なままになります。 

なぜ機能するのか: 不変条件は次のとおりです`dp[v][x]`のサブツリー内のすべての可能な方向を正確に記述します。`v`親エッジが寄与するという条件の下で`x`への入力エッジ`v`。 マージ ステップでは独立した子サブツリーのみが結合されるため、この意味は保持されます。 再構築中、テストされた方向は、この不変式が完了がまだ存在することを示している場合にのみ受け入れられるため、貪欲な選択によってすべての有効な答えが削除されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n = int(input())
    g = [[] for _ in range(n)]
    edges = []
    for i in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        g[u].append((v, i))
        g[v].append((u, i))

    allow = []
    for _ in range(n):
        s = input().strip()
        allow.append([c == '1' for c in s])

    parent = [-1] * n
    parent_edge = [-1] * n
    order = [0]
    parent[0] = -2

    for v in order:
        for u, idx in g[v]:
            if u != parent[v]:
                parent[u] = v
                parent_edge[u] = idx
                order.append(u)

    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)

    for v in range(n):
        children[v].sort(key=lambda x: parent_edge[x])

    dp0 = [False] * n
    dp1 = [False] * n
    low = [0] * n
    high = [0] * n

    for v in reversed(order):
        lo = 0
        hi = 0
        for u in children[v]:
            if dp0[u] and dp1[u]:
                hi += 1
            elif dp1[u]:
                lo += 1
                hi += 1
            elif dp0[u]:
                pass
            else:
                lo = 10**9
                hi = -10**9
        low[v] = lo
        high[v] = hi

        for parent_in in (0, 1):
            ok = False
            for x in range(lo, hi + 1):
                if parent_in + x < len(allow[v]) and allow[v][parent_in + x]:
                    ok = True
                    break
            if parent_in == 0:
                dp0[v] = ok
            else:
                dp1[v] = ok

    ans = ['0'] * (n - 1)

    def set_edge(v, u, idx, direction):
        a, b = edges[idx]
        if direction == 0:
            ans[idx] = '0' if a == v else '1'
        else:
            ans[idx] = '0' if a == u else '1'

    def build(v, par_in):
        need = -1
        for x in range(low[v], high[v] + 1):
            if par_in + x < len(allow[v]) and allow[v][par_in + x]:
                need = x
                break

        remain_lo = low[v]
        remain_hi = high[v]

        for u in children[v]:
            idx = parent_edge[u]

            can_zero = dp0[u]
            zero_contrib = 0
            one_contrib = 1

            choose_zero = False
            if can_zero:
                nlo = remain_lo - zero_contrib
                nhi = remain_hi - zero_contrib
                if nlo <= nhi:
                    choose_zero = True

            if choose_zero:
                set_edge(v, u, idx, 0)
                if dp0[u]:
                    build(u, 0)
                remain_lo -= 0
                remain_hi -= 0
            else:
                set_edge(v, u, idx, 1)
                build(u, 1)
                remain_lo -= 1
                remain_hi -= 1

    root_state = 0
    if not dp0[0]:
        root_state = 1

    build(0, root_state)
    return ''.join(ans)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve_case())
    print('\n'.join(out))

if __name__ == "__main__":
    main()
```最初の DFS はツリーの親子表現を構築し、エッジの順序を保持します。 すべてのノードはその子のみに依存するため、動的プログラミングには逆走査が使用されます。 

間隔配列`low`そして`high`考えられるすべての子の貢献数を保存することは避けてください。 子供はどちらかのみを寄付します`0`、 のみ`1`、またはその両方であるため、到達可能な合計は連続したままになります。 

再構築中に、コードは選択された親子方向を元のエッジ表現に変換します。 応答文字列ではルート ツリーの順序ではなく入力エッジの順序が使用されるため、元のエンドポイントとの比較が必要になります。

 ## 特殊なケース

 リーフ ノードの場合、DP には子がないため、可能な子の寄与間隔は次のようになります。`[0,0]`。 唯一の問題は、親エッジの寄与自体が許可されるかどうかです。 これは、両方の端点が同じ方向を強制する 2 つの頂点の場合を直接処理します。 

多くの子を持つ頂点の場合、アルゴリズムはすべての子エッジを独立して決定しません。 まず、受信する子エッジの総数が許容される入次数と一致できるかどうかを検証します。 再構築中に、各子の選択が残りの間隔に対してチェックされ、初期の貪欲な決定によって後の子が不可能になるのを防ぎます。 

すべての未知のエッジが入力順序の早い段階で出現する場合、再構成はツリーの走査順序ではなく、その順序に従います。 実現可能性テーブルを使用すると、ツリー全体を再計算することなく、必要な辞書編集順でこれらの選択を自由に行うことができます。
