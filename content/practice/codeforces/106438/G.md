 ## 解決策
 ## 問題の理解

 宮殿は格子状の部屋で、各部屋には特定の種類のチェストが置かれています。 チェストは種類の増加順に開けられます。 タイプのチェストを取った後`x`、内側の鍵により、どのタイプのチェストにもアクセスできます`x + 1`。 最初のタイプのチェストはすでに入手可能であり、最後の宝物は最大のタイプの唯一のチェストに保管されます。 

タスクは、必要な一連のチェスト タイプを訪問するときに移動するマンハッタンの最小合計距離を見つけることです。 現在のチェスト タイプに複数の可能な場所がある場合は、そのうちのいずれかを次の目的地として選択できます。 

入力により、グリッドの寸法、チェストのタイプの数、各部屋に保管されているタイプがわかります。 出力は、開始部屋から宝箱までの最短の徒歩距離です。 

グリッドには最大 300 行と 300 列を含めることができ、最大 90,000 個のセルが含まれます。 パスの数は指数関数的に増加するため、グリッドを介してすべての可能なパスを試行するソリューションは不可能です。 グリッドが大きい場合は、数万のセルが存在する可能性があるため、すべてのセルのペアをチェックするだけでもすでにコストが高くなりすぎます。 

便利な構造は、2 つの部屋間の移動がマンハッタン距離のみに依存するということです。 グリッド内を歩くことをシミュレートする必要はありません。 各チェスト タイプのどのオカレンスを参照するかを決定するだけで済みます。 すべてのタイプを順番に訪問する必要があるため、問題は各タイプに属する位置のグループに関する動的計画問題になります。 

いくつかの特殊なケースでは、より単純なソリューションが壊れる可能性があります。 

各宝箱の種類が 1 回のみ出現する場合、ルートの選択はありません。 例えば：```
Input
1 3 3
1 2 3

Output
2
```パスは列 1 から列 2、そして列 3 に強制されます。常に複数の選択肢があると想定するソリューションでは、遷移が誤って初期化される可能性があります。 

チェストの種類が何度も出現する場合、最も近いものを貪欲に選択すると失敗する可能性があります。 考慮する：```
Input
2 3 3
1 2 1
1 3 1

Output
3
```欲張りな選択は、タイプ 2 チェストに行くかもしれません。`(1,2)`ただし、より大きな例では以前の最良の位置が異なる可能性があるため、正しい遷移はすべてのタイプ 1 チェストの位置に依存します。 国家はあらゆる可能な立場を維持しなければならない。 

開始セルにすでにタイプ 1 が含まれている場合、その位置の初期距離はゼロでなければなりません。 例えば：```
Input
1 1 1
1

Output
0
```ゼロ以外の初期コストで開始する不用意な実装は、この最小のケースでは失敗します。 

## アプローチ

 簡単なアプローチは、各タイプを収集した後、可能なすべてのポジションを維持することです。 タイプのすべての位置について`x`、タイプのすべての位置の中から前の最良の位置を計算します。`x - 1`。 キー シーケンスによって型の順序が強制されるため、遷移は正確です。そのため、過去から必要な情報は、前の各位置に到達するための最小コストだけです。 

ブルートフォース実装はこの考え方に従っていますが、再計算が多すぎます。 あれば`k`1 種類のポジションと`t`次のタイプの位置を実行します。`k * t`マンハッタン距離の計算。 最悪の場合、多くの型で多くのオカレンスが発生する可能性があり、合計作業量はセル数の 2 乗に近づきます。`8 * 10^9`90,000 セル グリッドの操作では遅すぎます。 

重要な観察は、細胞の数はわずか 90,000 個ですが、種類の数は多数になる可能性があるということです。 すべてのタイプのポジションの合計数が固定されているという事実を利用する必要があります。 最適解でも動的プログラミング遷移は実行されますが、それは連続する型間でのみ実行されます。 すべてのグループのすべての位置の合計がセルの数になるため、実装で不必要な作業が回避されれば、遷移の総数は管理可能になります。 

タイプごとに、その座標を保存します。 現在のタイプのすべての座標に到達するための最小コストを維持します。 次に、それらの値を使用して次のタイプのコストを計算します。 最後の型を含む唯一のセルの最終値が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は O(n²m²) | O(nm) | 遅すぎる |
 | 最適 | 直接定式化における O(nmp) は、連続するタイプ グループ間の遷移の数によって制限されます。 O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセル位置を胸のタイプごとにグループ化して保存します。 型は複数のセルに出現する可能性があるため、単一の座標ではなく座標のリストが必要です。 
2. type の動的プログラミング値を初期化します。`1`。 プレーヤーは次から開始します`(0, 0)`したがって、タイプ 1 チェストに到達するコストは、最初からのマンハッタンまでの距離になります。 
3. チェストタイプを次から処理します。`2`に`p`。 現在のタイプのすべての位置について、前のタイプのすべての位置を試し、次の最小値を維持します。`cost of previous position + Manhattan distance between positions`プレイヤーは現在のタイプのチェストに到達する前に、すでに前のタイプのチェストを開けている必要があるため、これが遷移です。 
4. 以前の動的プログラミング配列を、現在の型に対して計算された値に置き換えます。 必要なのは前のタイプのみであるため、古い状態は破棄できます。 
5.後加工タイプ`p`、宝箱に保存されている唯一の値を出力します。 

効果がある理由: 後処理タイプ`x`、あらゆるタイプの動的プログラミング値`x`位置は、以前のタイプをすべて収集した後にそこに到着するために必要な最小距離を表します。 トランジションでは、以前の可能なすべてのタイプがチェックされます`x - 1`したがって、新しい地位に到達するためのあらゆる法的な方法が考慮されます。 最小限のものを選択すると、最適なルートが維持されます。 チェストの種類を誘導することにより、最終状態には宝物までの最小距離が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, p = map(int, input().split())

    groups = [[] for _ in range(p + 1)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j, x in enumerate(row):
            groups[x].append((i, j))

    INF = 10**18

    dp = []
    for r, c in groups[1]:
        dp.append((r, c, r + c))

    for typ in range(2, p + 1):
        ndp = []
        for r, c in groups[typ]:
            best = INF
            for pr, pc, val in dp:
                dist = abs(r - pr) + abs(c - pc) + val
                if dist < best:
                    best = dist
            ndp.append((r, c, best))
        dp = ndp

    print(dp[0][2])

if __name__ == "__main__":
    solve()
```の`groups`配列には、すべての胸のタイプの座標が格納されます。 これにより、不必要な状態の大きなグリッドが作成されるのではなく、保存された位置の合計がセルの数と等しくなります。 

動的プログラミングの初期状態は、タイプ 1 のチェストから構築されます。 出発点は`(0, 0)`したがって、最初の移動コストは、単純に、考えられるタイプ 1 の各場所までのマンハッタンの距離になります。 

遷移ループは、型を昇順に処理します。 新しい胸の位置ごとに、内側のループは以前のタイプの到達可能なすべての位置をスキャンし、最小の合計距離を選択します。 次の遷移には位置と累積距離の両方が必要であるため、コードは座標を現在の最小コストとともに保存します。 

答えは`dp[0][2]`最後にタイプするので`p`は正確に 1 回発生することが保証されています。 の使用`10**18`オーバーフローの懸念を回避し、グリッド内の可能なパス長よりも長くなります。

 ## 特殊なケース

 単一セルの場合:```
Input
1 1 1
1

Output
0
```胸部はすでに開始位置にあるため、アルゴリズムはコスト 0 のタイプ 1 状態を 1 つ作成します。 これも宝物なので最終的な保管コストはゼロです。 

繰り返し型の場合:```
Input
2 3 3
1 2 1
1 3 1

Output
3
```初期状態には、タイプ 1 の 3 つの位置すべてとその距離が含まれています。`(0,0)`。 タイプ 2 を処理するとき、アルゴリズムはそれらをすべてチェックし、最も安価なルートを維持します。 タイプ 3 に移行するときにも同じことが起こります。これは貪欲なローカル選択にコミットすることは決してないので、グローバルに最短のシーケンスを見つけます。 

一意の位置の場合:```
Input
1 3 3
1 2 3

Output
2
```各タイプには 1 つの座標があるため、すべての遷移には候補が 1 つだけあります。 アルゴリズムは自然に、強制されたマンハッタン距離を合計することになります。 

多くの繰り返し値を含む大規模なグリッドの場合、アルゴリズムはコストの 1 つのレイヤーのみを保持します。 前のタイプには次のタイプを計算するために必要なすべての情報が含まれているため、考えられるすべての移動履歴が保存されるわけではありません。
