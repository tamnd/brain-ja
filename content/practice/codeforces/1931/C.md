 ## 解決策
 ## 問題の理解

 整数の配列が与えられており、すべての要素を等しくしたいと考えています。 実行できる操作は最大 1 つです。この操作は、連続した部分配列を選択し、そのすべての要素を何らかの値に設定することで構成されます。 操作のコストは、選択した部分配列の長さに等しくなります。 私たちの目標は、このコストを最小限に抑えることです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列のサイズと配列自体が示されます。 各テストケースの最小コストを出力する必要があります。 

制約は重要です。 配列は最大で$2 \cdot 10^5$要素があり、最大で$10^4$テストケース。 すべてのテスト ケースにわたる要素の合計数が次を超えないこと$2 \cdot 10^5$。 これは、テスト ケースごとに直線的な時間を超えるソリューションは、遅すぎる可能性があることを意味します。 考えられるすべての部分配列をチェックする単純な総当たり法は、次のように二次式です。$n$、これは受け入れられません。 線形または線形に近いアプローチが必要です。 

エッジ ケースには、すでに均一な配列、長さ 1 の配列、および複数の要素がすでに繰り返されているが連続していない配列が含まれます。 たとえば、`[8, 8, 8, 1, 2, 8, 8, 8]`、繰り返される 8 が異なる値で区切られているため、最適な選択はすぐにはわかりません。 同じ値の最も長く連続する実行を常に選択する単純なアプローチは、ここでは失敗します。 

## アプローチ

 ブルート フォース手法では、配列に設定できるすべての値を反復し、値ごとにすべてのサブ配列を試して、設定した結果が均一な配列になるかどうかを確認します。 各サブ配列を評価するコストはその長さに比例し、およそ$O(n^2)$サブアレイ。 これは次のことにつながります$O(n^3)$すべての候補値の反復処理と組み合わせた場合の操作。 これは原理的には正しいですが、問題の制約に対して遅すぎます。 

より高速なソリューションを実現するための重要な洞察は、各候補値がすでに出現している位置に焦点を当てることです。 選択した値と等しくない配列のセグメントの数を数えることができます。 サブ配列を適切に拡張すれば、そのような各セグメントを 1 回の操作で「カバー」できます。 許可される操作は 1 つだけであるため、最小コストは、候補値のすべての不一致をカバーするために上書きする必要がある最長ストレッチの長さに等しくなります。 より正式には、配列は候補値によって区切られた一連のブロックと考えることができます。 各ブロックは上書きする必要がありますが、1 回の操作で複数のブロックをカバーすることを選択できます。 貪欲なアプローチが登場します。つまり、候補値を繰り返しスキップし、非候補値の連続セグメントの長さをカウントし、すべての候補値の中から最小の長さを選択します。 

この観察により、問題はすべてのサブアレイの考慮から各一意の値の位置の反復処理に軽減され、効率的な線形スキャン ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取り、一意の値のセットを記録します。 最終的な統一値の候補はこれらのみです。 
2. 変数を初期化する`min_cost`これにより、候補全体で見つかった最小コストが追跡されます。 
3. 各候補値について`v`、配列を左から右にスキャンします。 等しくない要素に遭遇するたびに、`v`、次の要素までの連続する要素をカウントします。`v`または配列の終わり。 このような各連続セグメントは、必要な操作の数に 1 を加えます。 
4. 候補者の費用`v`各セグメントは 1 回上書きする必要があるため、 は非候補セグメントの数です。 操作コストはセグメントの長さに等しく、この問題では任意のサブ配列を選択できるため、1 回の操作ですべての不一致をカバーする最小コストとして最小数のセグメントを選択します。 
5.アップデート`min_cost`この候補の方が総コストが小さい場合。 
6. 全ての候補をチェックしたら出力`min_cost`。 

機能する理由: 各候補値を個別に処理し、非候補値の連続ブロックを数えることで、上書きする必要がある最小限のセグメントを特定します。 1 回の操作で上書きする任意の連続したサブ配列を選択できるため、非候補ブロックの最小数は最小コストに直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n == 1:
            print(0)
            continue
        unique_vals = set(a)
        min_cost = n  # maximal cost is n
        for v in unique_vals:
            i = 0
            cost = 0
            while i < n:
                if a[i] != v:
                    cost += 1
                    while i < n and a[i] != v:
                        i += 1
                else:
                    i += 1
            min_cost = min(min_cost, cost)
        print(min_cost)

if __name__ == "__main__":
    solve()
```これらの一意の値のみが最終的な統一値となり得るため、それぞれの一意の値を反復処理します。 非候補値の連続セグメントをカウントすることで、必要な場合にのみ操作を適用できるようになります。 内側のループは、二重カウントを避けるために、候補に等しい要素を正しくスキップします。 使用する`min`複数の候補者にまたがって最適な選択肢を見つけることができます。 取り扱い`n == 1`特殊な場合として、不必要な計算を防止し、off-by-one エラーを回避します。
