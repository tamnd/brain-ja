 ## 解決策
 ## 問題の理解

 整数の配列と 2 つの数値が与えられます。$x$そして$y$。 インデックスのペア$(i, j)$と$i < j$2つの要素の合計が「美しい」とみなされる$a_i + a_j$で割り切れます$x$そしてその違い$a_i - a_j$で割り切れます$y$。 テスト ケースごとに、そのようなペアがいくつ存在するかを数える必要があります。 

制約を正しく解釈することが重要です。 各配列は最大で$2 \cdot 10^5$要素があり、最大で$10^4$テストケース。 の合計額$n$すべてのテストケースで次を超えない$2 \cdot 10^5$、それで治療できます$n$同様に効果的に$2 \cdot 10^5$バッチごとに。 すべてのペアを直接チェックするブルートフォース手法では、$O(n^2)$操作は次のように大規模になる可能性があります$4 \cdot 10^{10}$2 秒の制限には遅すぎます。 線形またはほぼ線形にスケールするソリューションが必要です。$n$。 

素朴な解決策を壊す可能性のあるエッジケースは、すべての数値が等しい場合、または次の場合です。$x$または$y$違いを簡単に分割します。 たとえば、次の場合$x = y = 1$、どのペアも美しいです。 不用意に実装すると、負の数を考慮せずにモジュロ演算を試行し、微妙な 1 による誤差や符号エラーが発生する可能性があります。 

## アプローチ

 素朴なアプローチはすべてのペアに対して繰り返されます$(i, j)$そして 2 つの割り切り条件をチェックします。 これは問題のステートメントを直接実装しているため正しいですが、次のことが必要です。$O(n^2)$小切手。 のために$n \approx 2 \cdot 10^5$、これはおおよその結果を生成します$2 \cdot 10^10$これは実行可能な計算限界をはるかに超えています。 

最適化のための重要な洞察は、モジュロの一致条件を調べることから得られます。$x$そして$y$。 させて$a_i + a_j \equiv 0 \pmod{x}$そして$a_i - a_j \equiv 0 \pmod{y}$。 これら 2 つの合同式を同時に解くことができます。 それらを加算および減算すると、次のことがわかります$2a_i \equiv 0 \pmod{\text{lcm}(x, y)}$そして$2a_j \equiv 0 \pmod{\text{lcm}(x, y)}$いくつかのシフトまで。 具体的には、問題を前の数字の数を数える問題に変換できます。$a_j$現在の数値に対して線形合同を満たす$a_i$これは、導出されたモジュラスを法とする残基のハッシュ マップ (辞書) を使用して実行できます。 これにより、配列の長さにおけるペアチェックが二次から線形に減少します。 

ここでの話は、和条件と差条件は一見複雑に見えますが、剰余演算の観点から言い換えると、一致する剰余を数える問題になるということです。 辞書を使用して各残基の頻度を保存すると、配列を 1 回だけ反復するときに美しいペアを増分的にカウントできるようになります。

 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | モジュラーハッシュマップ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次の最大公約数 (gcd) を事前計算します。$x$そして$y$、これは 2 つの合同式を 1 つの係数に減らすのに役立ちます。 させて$g = \gcd(x, y)$。 
2. 配列を左から右に繰り返します。 要素ごとに$a_i$、2 つの値を計算します。$r_i = a_i \bmod x$そして$s_i = a_i \bmod y$。 これらは、現在の要素の残りの部分を表します。$x$そして$y$。 
3. 結合された残基キーを構築する$(r_i, s_i)$そして、そのような各キーが何回出現したかの頻度マップを保存します。 これにより、以前の要素がどれだけ多くの要素と美しいペアを形成するために必要なモジュール条件を満たしているかを確認できます。$a_i$。 
4. 各要素について$a_i$、対応する相補的残基を計算します$(r_j, s_j)$それはペアになります$(a_j, a_i)$合同式から導かれた式を使用して、美しく仕上げます。 マップ内のそのキーの頻度を答えに追加します。 
5.加工後$a_i$、周波数マップ内のキーをインクリメントし、将来の要素がそのキーとペアを形成できるようにします。 

機能する理由: 各ステップで、マップは以前に確認されたすべての要素の数を剰余剰余でグループ化して保存します。$x$そして$y$。 新しい要素に遭遇するたびに、和条件と差条件を満たすためにどの残基とペアになるかを正確に計算します。 反復は 1 回だけで、マップは関連する以前の要素をすべて追跡するため、冗長なペアをチェックすることなく、有効なペアをすべて 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict
from math import gcd

def count_beautiful_pairs(n, x, y, a):
    freq = defaultdict(int)
    ans = 0
    g = gcd(x, y)
    lcm = x * y // g
    
    for val in a:
        # target residues for previous elements
        target = ((-val) % x, (val) % y)
        ans += freq[target]
        # current residue key
        key = (val % x, val % y)
        freq[key] += 1
    return ans

t = int(input())
for _ in range(t):
    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    print(count_beautiful_pairs(n, x, y, a))
```このソリューションは、剰余のモジュロのペアをキーとする頻度辞書を構築します。$x$そして$y$。 各要素について、前の要素との和および差の制約を満たす残差を計算します。 カウント後に頻度を増やすと、ペアが二重にカウントされなくなります。 の使用`%`負の数値を正しく処理できるようにします。これは、Python のモジュロ演算子が常に非負の結果を返すため、微妙です。
