 ## 解決策
 ## 問題の理解

 隠された 3 つの小文字の合計を表す 1 つの整数が与えられます。 各文字はアルファベット内での位置に影響します。`a`1に貢献し、`b`2 を貢献し、以下同様に最大`z`貢献 26. 元の単語には常に 3 文字が含まれており、それらの数値の合計のみを観察します。 

このタスクは、文字の合計が指定された合計に達する、有効な 3 文字の単語を 1 つ再構築することです。 すべての有効なトリプルの中で、辞書編集的に最小のものを返さなければなりません。 

ここでの辞書編集順は、同じ長さの文字列に対する辞書順と同様に動作するため、最初の文字を最小化することは 2 番目の文字よりも重要であり、2 番目の文字は 3 番目の文字よりも重要です。 これは、単に合計の分解を見つけているのではなく、前の文字を最小限に抑えながら、後の文字にできるだけ多くの値を押し込む分解を見つけていることを意味します。 

制約は非常に小さく、合計は最大 78 であり、これはまさに可能な最大値です。`26 + 26 + 26`。 これにより、テスト ケースごとの定数推論を超えた、大きな空間での検索や最適化手法の必要性が即座に排除されます。 考えられるすべてのトリプルを総当たりでスキャンすることも可能です。$26^3 = 17576$可能性。 

主なエッジケースは、辞書編集上の最小性から生じます。 単純なアプローチでは、すべてのトリプルを試して、最小の有効なトリプルを選択する可能性がありますが、反復の順序が間違っているなどの小さな実装上の選択であっても、辞書編集上最小ではない正しい合計のトリプルが選択される可能性があります。 

たとえば、合計が 24 の場合、有効なトリプルには次のものが含まれます。`aav`、`ava`、 そして`vaa`。 辞書順を強制せずに最後の文字を優先したり合計をチェックしたりする不注意な検索では、簡単に結果が返される可能性があります。`vaa`これは有効ですが、最小限ではありません。 正しい答えは、`aav`最初の文字が最初に最小化されるためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのトリプルを列挙します。`(x, y, z)`各変数の範囲は 1 ～ 26 であるかどうかを確認します。`x + y + z = n`、辞書編集上、対応する最小の文字列を追跡します。 これは、実行可能な空間全体を使い果たし、比較する際に辞書編集上の順序がタプルの順序と一致するため、正しいです。`(x, y, z)`直接的には、単純に最小の有効なトリプルを保持することができます。 

このアプローチのコストはテスト ケースごとに一定であり、反復回数は 17,576 回です。 最大 100 のテスト ケースの場合、これは約 170 万チェックに相当し、Python ではすでに十分に高速です。 ただし、このような小さな構造ではやや過剰で、ほとんどの自由度が不要なため、冗長な作業が行われます。 

重要な観察は、辞書編集的な最小化により貪欲な構造が強制されるということです。 最初の文字はできるだけ小さくする必要がありますが、それでも残りの 2 文字が残りの合計の有効な分解を形成できるようにします。 最初の文字が固定されたら、2 番目の文字は実行可能性を考慮して再び最小化する必要があり、3 番目の文字は自動的に決定されます。 

これにより、問題は 3 つのネストされたループから、定数時間チェックを使用する 2 つのネストされたループ、またはさらに単純な直接的な貪欲な構造に軽減されます。

 ## アルゴリズムのチュートリアル

 残りの位置の実現可能性を常に確保しながら、一度に 1 文字ずつ答えを作成します。 

1. 1 から 26 までのすべての値を昇順に試して、最初の文字を修正します。 候補者ごとに`a`、残額があるかどうかを確認します`n - a`は 1 ～ 26 の 2 つの値に分割できます。この実現可能性チェックは、`2 ≤ n - a ≤ 52`。 
2. 有効な最初の文字が見つかったら、それを永続的に修正します。最初に小さい値を試行すると、辞書編集上の最適性が保証されます。 
3. 2 番目の文字も同様に 1 から 26 まで繰り返して修正します。各候補について`b`、残価を確保`n - a - b`範囲内にあります`[1, 26]`。 最初の有効な`b`同じ辞書編集上の理由で最適です。 
4. 3 番目の文字は強制的に次のようになります。`n - a - b`、すべての制約により、それが存在することが保証されているため、`[1, 26]`。 
5. マッピングにより数値を文字に変換します。`1 → a`、`2 → b`、 等々。 

アルゴリズムの構造により、すべての決定が辞書編集順に関して局所的に最適であり、実現可能性とグローバルに一貫していることが保証されます。 

### なぜ効果があるのか

 正確さは単調な実現可能性の特性から得られます。 固定プレフィックスの場合、より小さい選択が可能であれば、常に辞書編集的により小さい有効な文字列が得られます。 和の制約を超えた将来の選択肢間の相互作用は存在しないため、早期の決定は、実現可能性の限界を除いて、後の辞書編集的な最適化を制限しません。 この分離により、後戻りすることなく各位置で貪欲な選択が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        for a in range(1, 27):
            rem = n - a
            if not (2 <= rem <= 52):
                continue

            for b in range(1, 27):
                c = rem - b
                if 1 <= c <= 26:
                    ans = chr(ord('a') + a - 1) + chr(ord('a') + b - 1) + chr(ord('a') + c - 1)
                    print(ans)
                    break
            else:
                continue
            break

if __name__ == "__main__":
    solve()
```コードは貪欲な構造に正確に従っています。 外側のループは最初の文字を昇順で選択し、残りの合計が有効な 2 文字を形成できる場合にのみ続行します。 2 番目のループでも同様に、コミットする前に 3 番目の文字が有効であることを確認します。 Python の使用`else`on ループでは、有効な 2 番目の文字が見つかったら、両方のループをきれいに終了します。 

よくある落とし穴は、3 番目の文字が一意に決定されることを忘れていることです。 別の人が誤って許可しています`c`外に出る`[1, 26]`、合計が一致した場合でも、無効な文字列が暗黙的に生成されます。

 ## 特殊なケース

 最小額の場合`n = 3`、アルゴリズムセット`a = 1`、`b = 1`、 そして`c = 1`他の分割は不可能であるためです。 実現可能性チェックでは、最初の有効な構成がすぐに受け入れられ、`aaa`。 

最大額の場合`n = 78`の場合、アルゴリズムはすべての小さな値をスキップします。`a`到達するまで`a = 26`、次に同様に強制します`b = 26`、出発`c = 26`。 構造は自然に次のように収束します。`zzz`特別な処理を必要とせずに。 

これらのケースは、明示的な分岐ロジックを必要とせずに、境界動作が純粋に実行可能性制約によって処理されることを確認します。
