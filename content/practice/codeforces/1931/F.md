 ## 解決策
 ## 問題の理解

 私たちはチャットを与えられます`n`参加者はそれぞれ固有の番号で識別されます。`1`に`n`。 チャットでは参加者がアクティビティ順にリストに表示されますが、各参加者には常に自分自身がリストの先頭に表示されます。 複数の参加者がチャット リストのスクリーンショットを撮り、見たままの順序をキャプチャしました。 各スクリーンショットには、それを取得した参加者が一番上に表示され、その後に残りの参加者が順に表示されます。 

この問題は、すべてのスクリーンショットを説明する単一の基本的な参加者の順序が存在するかどうかを尋ねます。 言い換えれば、各参加者が自分自身を先頭に表示した場合に、そのスクリーンショットが記録されたスクリーンショットと一致するような、一貫したアクティビティベースの全員の順序付けが 1 つ存在するかどうかを知りたいのです。 

制約は次のことを教えてくれます`n`そして`k`まで可能です`2·10^5`すべてのテスト ケースの合計。 これにより、すべてを試すブルートフォースアプローチが即座に排除されます。`n!`順列。 各スクリーンショットには次の内容が含まれます`n`したがって、ソリューションは配列を効率的に、理想的には要素の合計に対して線形時間で処理する必要があります。`n`価値観。 

最上位の参加者以外の参加者の相対的な順序が原因でスクリーンショットに一貫性がない場合、明らかではないエッジケースが発生します。 たとえば、3 人の参加者が次のようなスクリーンショットを投稿したとします。`[1,2,3]`、`[2,3,1]`、 そして`[3,1,2]`、一貫した根底にある秩序が存在します。 ただし、スクリーンショットに参加者が先頭に表示され、他の参加者との相対的な順序が別のスクリーンショットと矛盾する場合、答えは「いいえ」となります。 単純なアプローチでは、先頭の参加者をチェックするだけで残りの参加者の順序を無視する可能性があり、そのような場合は失敗します。 

## アプローチ

 ブルートフォースアプローチでは、すべてのものが生成されます。`n!`参加者の順列を確認し、すべてのスクリーンショットに対して各順列をチェックします。 順列ごとに、各参加者のビューをシミュレートし、それがスクリーンショットと一致するかどうかを確認します。 これは正しいですが、実行不可能です。`n`まで`2·10^5`、`n!`天文学的に大きいです。 

重要な洞察は、有効な基本注文の場合、他の参加者に対する各参加者の位置がスクリーンショット間で一貫している必要があるということです。 各スクリーンショットは、一連の有向制約として解釈できます。`x`直後に来る`y`スクリーンショット (最上位の参加者を無視)、次にグローバル順序で`y`前に来なければなりません`x`。 最上位の参加者が常に最初に表示されるため、それらを削除し、残りの参加者の相対的な順序に焦点を当てることができます。`n-1`参加者。 

この観察により、問題をシーケンスの一貫性チェックに帰着させることができます。 スクリーンショットの 1 つを基になる順序の候補として選択し、その順序を使用して、最上位の参加者を先頭に移動することで調整された他のすべてのスクリーンショットをシミュレートしようとします。 この操作でスクリーンショットが取得できない場合は、順序に矛盾があり、答えは「NO」です。 それ以外の場合、注文は有効であり、答えは「YES」です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・k・n) | O(n) | 遅すぎる |
 | 最適 | O(k・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`t`、テストケースの数。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`。 
3. すべて保存する`k`スクリーンショットをリストに表示します。 各スクリーンショットは次のリストです。`n`最初の整数はそれを取得した参加者になります。 
4. 基になる注文の候補としてスクリーンショットを 1 つ選択します。 これは任意であるため、通常は最初のスクリーンショットを選択します。 
5. この候補順で参加者から役職へのマッピングを構築します。 
6. 各スクリーンショットについて、最上位の参加者を候補順序の先頭に移動するとスクリーンショットが生成されるかどうかを確認します。 これを行うには:

 - 候補の順序から最上位の参加者を削除します。 
・前から差し込みます。 
- 結果のリストをスクリーンショットと比較します。 
- 一致しない場合は NO を返します。 
7. すべてのスクリーンショットが一致する場合は、YES を返します。 

機能する理由: 最上位の参加者を前に移動すると、各参加者のビューがシミュレートされます。 すべてのスクリーンショットが 1 つの候補順序に対するこの操作に一致する場合、すべてのスクリーンショットと一致する基礎となるグローバル順序が存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        screenshots = [list(map(int, input().split())) for _ in range(k)]
        
        candidate = screenshots[0]  # arbitrary candidate
        pos_in_candidate = {val: i for i, val in enumerate(candidate)}
        possible = True
        
        for shot in screenshots:
            top = shot[0]
            # simulate participant's view
            reordered = [top] + [x for x in candidate if x != top]
            if reordered != shot:
                possible = False
                break
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、すべての入力を効率的に読み取ります。`sys.stdin.readline`。 候補の順序は最初のスクリーンショットから選択されます。 重要な点は、参加者自身の識別子を候補リストから削除して先頭に置くことで、参加者のビューを正しく生成することです。 これにより、最上位の参加者を無視することによって生じる不一致を防ぎます。
