 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 これらは 2 列のスイッチであり、各位置がオンまたはオフになると考えてください。 目標は、2 種類の操作を使用して最初の行を 2 番目の行に変換することです。つまり、それらの位置の距離に等しいコストを払って、最初の文字列内の任意の 2 つの位置を交換するか、単位コストで 1 ビットを反転することができます。 

重要な問題は、スワップが無料ではなく、距離に依存するため、不一致のビットを移動させると単純に行うとコストが高くつくことです。 フリップは安価ですが、永続的に少し変化するため、移動によって不一致を修正するか直接修正するかを決定することが重要なトレードオフになります。 

最大 100 万文字という制約により、二次関数や偶数関数は除外されます。$O(n \log n)$重い定数を使用します。 どのソリューションでも基本的に文字列を一定の回数スキャンし、線形データ構造を維持する必要があります。 

素朴だが間違った考えは、不一致を左から右に貪欲に修正し、常にローカルで反転または交換することです。 たとえば、インデックスで不一致が見つかった場合、$i$、すぐに反転するかもしれません。 これは、ある位置での不一致は、2 つのフリップを支払うよりも、後の不一致と組み合わせて交換することで解決する方が安価になる可能性があるため、失敗します。 

もう 1 つの微妙な失敗は、2 つの不一致のポジションが存在する場合にスワップを常に有益なものとして扱うことから発生します。 距離を考慮せずにスワップすると、完全なペアリングが存在すると仮定する可能性がありますが、特に不一致が遠く離れている場合、不一致のビットを結合するコストは 2 回のフリップを超える可能性があります。 

## アプローチ

 問題は、不一致の位置を理解することだけに帰着します。 どのインデックスでも、$a[i] = b[i]$、 それは問題ではありません。 それ以外の場合は、反転するか、別の不一致と組み合わせて交換することによって修正する必要がある不一致があります。 

不一致を 2 つのタイプに分類してみましょう。$a[i] = 0, b[i] = 1$、および位置$a[i] = 1, b[i] = 0$。 それぞれタイプA、タイプBと呼びます。 1 つの A と 1 つの B を交換すると、両方のポジションを同時に固定できる可能性があります。 

強引なアイデアでは、不一致のペアをあらゆる方法で試し、交換するか反転するかを決定します。 これはすぐに組み合わせになります。$O(n)$不一致が発生し、指数関数的なマッチングの可能性、または距離の重みを含むライン上で少なくとも最小コストのマッチングの問題が発生します。 

重要な観察は、構造が 1 次元であるということです。 不一致インデックスを順番にリストすると、スワッピングが使用される場合は常に、反対のタイプの隣接する不一致をペアにすることが常に最適です。 隣接しないペアリングは、交差を考慮することで改善または一致させることができます。遠くにある不一致を交換すると中間インデックスを通過することになりますが、これはローカルで解決する場合と比較してコストが増加するだけです。 

これにより、問題は文字列をスキャンし、最後に一致しない不一致を維持し、それを現在の文字列と組み合わせるかペイ・フリップするかを決定するという問題に軽減されます。 

私たちは未解決の不一致のスタックのような構造を維持しています。 スタックの最上位と反対のタイプの不一致が見つかった場合は、それらをスワップと組み合わせるか、反転のために残しておくことができます。 スワップ コストはインデックス間の距離とまったく同じですが、2 つのフリップのコストは 2 です。したがって、各ペアについて、これら 2 つのオプションの最小値を採用します。 

インデックスが順番に処理されるため、距離がすぐにわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペアリングの不一致 | 指数 | O(n) | 遅すぎる |
 | 隣接する不一致の貪欲なペアリング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、まだ解決されていない不一致のリストを維持します。 

1. スキャンインデックス$i$0から$n-1$。 もし$a[i] = b[i]$、アクションは不要なのでスキップしてください。 
2. 保留中の不一致がない場合は、現在の不一致インデックスとそのタイプを構造体にプッシュします。 ペアリングは反対のタイプ間でのみ意味があるため、それが 0 対 1 の不一致であるか 1 対 0 の不一致であるかは記憶されます。 
3. 逆のタイプの保留中の不一致がある場合は、それを現在のインデックスと照合することを検討します。 これにより、次と等しい候補スワップ コストが作成されます。$i - j$、 どこ$j$は以前の不一致インデックスです。 
4. スワップ オプションを、両方のポジションを個別に反転する場合と比較します。コストは 2 です。これら 2 つの最小値を答えに追加し、保留中の不一致をクリアします。 
5. 保留中の不一致が現在の不一致と同じタイプの場合、それらをペアにすることはできないため、現在の不一致をプッシュし、前の不一致を待機させます。 
6. すべてのインデックスを処理した後、残りの一致しない不一致はフリップによって個別に解決する必要があり、それぞれが答えに 1 を与えます。 

### なぜ効果があるのか

 このアルゴリズムは、不一致によって 2 つの順序付けられたシーケンスが 1 行に形成されるという事実に基づいています。 最適なソリューションは、インデックス順で連続する反対タイプの不一致間でのみスワップが発生するように変換できます。 スワップコストは距離に対して線形であり、交差を解除すると総移動距離が減少するため、交差ペアリングはコストを増加させることなく解除できます。 隣接するペアに制限されると、すべての決定はローカルになります。つまり、ペアのスワップ コストを支払うか、2 枚のフリップを支払うかのいずれかになります。今後の決定によってこの選択を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    ans = 0

    prev_idx = -1
    prev_type = 0  # +1 for 0->1, -1 for 1->0

    for i in range(n):
        if a[i] == b[i]:
            continue

        cur_type = 1 if a[i] == '0' else -1

        if prev_idx == -1:
            prev_idx = i
            prev_type = cur_type
        else:
            if prev_type != cur_type:
                cost_swap = i - prev_idx
                ans += min(cost_swap, 2)
                prev_idx = -1
            else:
                ans += 1
                prev_idx = i
                prev_type = cur_type

    if prev_idx != -1:
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは文字列を 1 回スキャンし、一度に最大 1 つの未解決の不一致のみを追跡します。 変数`prev_idx`最後の一致しない不一致位置を保存します。`prev_type`その方向を保存します。 互換性の不一致が現れた場合、ペアリングのコストとフリッピングを評価します。 

微妙な点は、2 つの不一致が同じタイプである場合、スワップを形成できないため、前の不一致はフリップによって直ちに解決する必要があることです。 これにより、互換性のない状態が引き継がれることが防止され、グリーディ ペアリングの正確さが保証されます。 

最後に、残った不一致はフリップとして支払われます。

 ## 特殊なケース

 不一致のない文字列の場合、保留状態が作成されないため、アルゴリズムはペアリング ロジックに入らず、すぐにゼロを返します。 

次のような単一の不一致の場合$a = 0, b = 1$、アルゴリズムはそれを保存して最後に到達し、最適な動作に合わせて単一の反転コストを適用します。 

すべて 0 から 1 など、同じタイプの複数の連続した不一致の場合、アルゴリズムはそれらをペアにすることはなく、それぞれをフリップで解決します。これは、スワップでは同じ方向の不一致を修正できないため、これが最適です。
