 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 しましょう`k = (n+1)//2`、並べ替えられた順序での中央値のインデックス。 

1. 配列をソートします。 中央値は元の位置ではなく順序のみに依存するため、並べ替えは不可欠です。 
2. 要素を以下の要素に分割します。`s`、に等しい`s`、およびそれ以上`s`。 この分離により、何を調整する必要があるかが決まります。 
3. すでに以上の要素がいくつあるかを数えます。`s`。 この数値が少なくとも`k`の場合、中央値はすでに少なくとも次のように強制されます。`s`適切な最小限の調整後。 
4. 同様に、少なくとも次のことを確認してください。`k`要素は以下です`s`。 この条件が周囲の等価構造ですでに成立している場合`s`、中央値は正確に作成できます`s`最小限の変更で。 
5. 実際のコストは、しきい値を超える必要がある要素から発生します。`s`。 以下の各要素について`s`それは ≥ になる必要があります`s`、費用は`s - a[i]`。 より大きい各要素について`s`それは ≤ になる必要があります`s`、費用は`a[i] - s`。 
6. 中央値条件を満たすために必要な要素の最小セットを選択し、常に最も安価な調整を最初に選択します。 各ユニットの動作が独立かつ直線的であるため、これは最適です。 

### なぜ効果があるのか

 中央位置は順序によってのみ決定されます。 の各側にいくつの要素を配置する必要があるかを決定したら、`s`、残された唯一の自由は、どの要素がしきい値を超えるかを選択することです。 コストは距離に比例するため、`s`、最適な戦略では、最も近い要素を優先する必要があります。`s`横断用に。 これから逸脱すると、実現可能性を変えることなく、より小さなコスト調整がより大きなコスト調整に置き換わることになり、結果を改善することはできません。 これにより、最も近い要素を貪欲に選択することが最適であることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    
    k = (n + 1) // 2
    
    # Split costs depending on direction toward s
    left = []   # cost to increase to s
    right = []  # cost to decrease to s
    
    for x in a:
        if x < s:
            left.append(s - x)
        else:
            right.append(x - s)
    
    left.sort()
    right.sort()
    
    # We want at least k elements >= s for median to be >= s,
    # and at least k elements <= s for median to be <= s.
    # The median becomes s when we balance both sides optimally.
    
    # If we need to push elements upward to reach s
    need_left = max(0, k - len(right))  # elements that must become >= s
    
    # If we need to push elements downward to reach s
    need_right = max(0, k - len(left))  # elements that must become <= s
    
    ans = 0
    
    for i in range(need_left):
        ans += left[i]
    
    for i in range(need_right):
        ans += right[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードは要素を上下に分割します`s`、次に、中央位置が確実に一致するようにしきい値を越える必要がある数を計算します。`s`。 各グループを並べ替えることで、常に最も安価な要素を最初に選択して調整することができます。 変数`need_left`そして`need_right`周囲の不均衡により強制横断が必要となる回数をエンコードします。`s`。 

実装の微妙な点は、中央値を明示的にシミュレートしようとしていないことです。 代わりに、最終的に各辺にいくつの要素が配置される必要があるかという観点から推論します。`s`、これは実現可能性とコストを判断するのに十分です。

 ## 特殊なケース

 すべての要素が以下の場合に特殊なケースが発生します。`s`。 そのような状況では、上昇するためにあらゆる要素を考慮する必要がありますが、最も安価な要素のみを考慮する必要があります。`(n+1)//2`中央位置に影響を与えるのはそれらのみであるため、実際に重要なのはそのうちの 1 つです。 このアルゴリズムは、コストを上方にソートし、必要な最小のサブセットのみを選択することによってこれを処理します。 

もう 1 つのケースは、すべての要素が次の値より大きい場合です。`s`。 対称的に、最も安価な下方調整のみが考慮され、中央値の位置に無関係な要素に過剰な支払いをしないことが保証されます。 

3 番目のケースは、中央位置が構造的に正しいような混合がアレイにすでに含まれている場合です。 この場合はどちらも`need_left`そして`need_right`ゼロに評価され、アルゴリズムは変更を行わずに正しくゼロを返します。
