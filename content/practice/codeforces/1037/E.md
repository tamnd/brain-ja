 ## 問題の理解

 私たちにはダイナミックな友情システムが与えられています。$n$人々。 最初はそれらの間にエッジはありません。 毎朝、以前は接続されていなかった 2 つの頂点の間に、新しい無向エッジが追加されます。 追加するたびに、現在のグラフを検討し、夜の旅行に選択できる最大の頂点グループに関する質問に答える必要があります。 

有効なトリップ グループは、局所密度制約を持つ頂点のサブセットです。選択された頂点ごとに、グループから除外されるか、少なくとも次の要素が必要です。$k$そのグラフの近傍もグループに含まれます。 目標は、各エッジの挿入後にそのようなサブセットのサイズを最大化することです。 

重要なオブジェクトは接続性ではなく、誘導されたサブグラフ内の次数です。 最小次数が少なくとも次である最大の誘導部分グラフを効果的に検索しています。$k$、とよく説明されます。$k$-グラフのコア。 

制約$n, m \le 2 \cdot 10^5$毎日何もかも最初から再計算することを除外します。 の単純な再計算$k$-各エッジの後のコアでは、低次数の頂点を繰り返し剪定する必要があり、コストがかかります$O(n + m)$最悪の場合、クエリごとに、$O(m(n+m))$、これは大きすぎます。 

グラフが初期にはまばらであるが、後で密になる場合、微妙なエッジケースが現れます。 後で大きな有効なグループが存在する場合でも、初期の答えがゼロになる可能性があります。 たとえば、次の場合$k=2$グラフは 3 日目のみ三角形を形成し、最終的な構造は小さいものの自明ではないにもかかわらず、1 日目と 2 日目は 0 を出力する必要があります。 次数を再チェックせずに、頂点の包含ごとの答えの単調増加を仮定するアプローチは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 新しいエッジごとに、現在のグラフを構築し、残りのセット内の次数が 未満であるすべての頂点を繰り返し削除します。$k$。 これが標準的なピーリングプロセスです。$k$-core: 以下の次数を持つ頂点のキューを維持します。$k$、それらを削除し、安定するまで近隣を更新します。 残りの頂点は有効なセットを形成し、そのサイズが答えになります。 

これは正しいです。次数制約に違反する頂点は有効な解に属することができず、削除しても隣接次数が減少するだけであり、さらに削除がトリガーされる可能性があるためです。 問題は、これをエッジごとに最初から繰り返すと、基本的に同じピーリング プロセスが何度も再計算されることです。 それぞれの実行は$O(n + m)$、全体の複雑さは$O(m(n+m))$、これは受け入れられません$2 \cdot 10^5$。 

重要な点は、エッジは追加されるだけで、決して削除されないということです。 これは、次数は時間の経過とともに増加するだけであることを意味するため、頂点が有効になると、$k$-core を指定すると、後で無効になることはありません。 ただし、難しいのは、有効性が生の次数だけではなく、コアに存在する他の頂点に依存することです。 

重要な変革は時間を逆転させることです。 エッジを前方に追加する代わりに、ダイナミックなエッジを維持しながら後方に処理します。$k$-コア。 当初は、時間的には$m$、すべてのエッジが存在します。 最終的な値を計算します$k$-コアを1回。 次に、逆の順序でエッジを 1 つずつ削除します。 エッジが削除されると、一部の頂点が次数を下回る場合があります$k$コアから取り外す必要があります。 これにより、カスケード削除プロセスが作成されます。 各頂点は最大 1 回削除され、各エッジは削除全体で一定の回数処理されるため、合計の複雑さは線形になります。 

高速な更新をサポートするために、現在のコアに制限された隣接リストと現在の度数を維持します。 また、エッジが削除されるたびに無効になる頂点のキューも維持します。

 ## アルゴリズムのチュートリアル

 一連のエッジを逆に処理し、各頂点が有効なエッジに属さなくなった時点を追跡することで、この問題を解決します。$k$-コア。 

1. すべてのエッジを使用して完全なグラフを構築し、各頂点の初期次数を計算します。 

これは当日の状態を表します$m$、そこにはすべての友情が存在します。 
2. 初期値を計算します$k$-core 次数が以下のすべての頂点のキューを使用する$k$。 

このような頂点を繰り返し削除し、まだアクティブな隣接頂点の次数を減らします。 

これにより、その日の最終的な安定したセットが得られます$m$。 
3. 各頂点が現在コア内にあるかどうかをマークするブール配列を維持します。 

すべてのエッジの隣接リストも維持します。 
4. すべてのエッジを配列に格納し、それらを逆の順序で処理します。$m$まで$1$。 
5. 各エッジについて$(u, v)$、現在の状態からその効果を削除します。 

両方のエンドポイントがまだコア内にある場合は、現在の次数を減分します。 
6. 頂点の次数が以下になるたびに$k$、削除のキューに押し込みます。 

この頂点は現在の状態では無効になっているため、剥がす必要があります。 
7. キューが空でない間に、頂点を繰り返し削除します。 

それらを非アクティブとしてマークし、まだアクティブな近隣のレベルを減分します。 

隣人が下に落ちた場合$k$、キューに追加されます。 
8. エッジ削除による削除カスケードを完全に処理した後$i$、現在のコアのサイズをその日の答えとして記録します$i-1$。 

### なぜ効果があるのか

 逆処理のどの時点でも、アクティブな頂点のセットは正確に$k$-エッジの接尾辞によって形成されるグラフのコア。 ピーリング プロセスでは、すべてのアクティブな頂点が少なくとも次数を持つという不変条件が維持されます。$k$アクティブセット内。 エッジが削除されると、考えられる違反はそのエンドポイントでの次数の減少からのみ発生し、カスケードにより、結果として生じるすべての違反が確実に解決されます。 各頂点は一度削除され、再挿入されることはないため、構造はすべてのステップにわたって一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    
    edges = []
    adj = [[] for _ in range(n)]
    
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        adj[u].append((v, i))
        adj[v].append((u, i))
    
    deg = [len(adj[i]) for i in range(n)]
    alive = [True] * n
    removed = [False] * n
    
    q = deque()
    
    for i in range(n):
        if deg[i] < k:
            q.append(i)
            removed[i] = True
            alive[i] = False
    
    while q:
        u = q.popleft()
        for v, _ in adj[u]:
            if alive[v]:
                deg[v] -= 1
                if not removed[v] and deg[v] < k:
                    removed[v] = True
                    alive[v] = False
                    q.append(v)
    
    ans = [0] * m
    cur_alive = sum(alive)
    
    for i in range(m - 1, -1, -1):
        ans[i] = cur_alive
        
        u, v = edges[i]
        if alive[u] and alive[v]:
            deg[u] -= 1
            deg[v] -= 1
            
            for x in (u, v):
                if alive[x] and deg[x] < k:
                    alive[x] = False
                    q.append(x)
        
        while q:
            u = q.popleft()
            for v, _ in adj[u]:
                if alive[v]:
                    deg[v] -= 1
                    if alive[v] and deg[v] < k:
                        alive[v] = False
                        q.append(v)
        
        cur_alive = sum(alive)
    
    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```コードは、隣接リストを構築し、次数を完全なグラフの次数として初期化することから始まります。 次に、初期ピーリングを実行して最終的なピーリングを計算します。$k$- 日に対応するコア$m$。 逆処理では有効な開始コアが前提となるため、このステップは不可欠です。 

逆反復中に、各エッジがアクティブな構造から削除されます。 両方のエンドポイントが現在アクティブな場合、それらの次数は減らされ、潜在的に$k$-コアの状態。 BFS キューはカスケード削除を処理し、不変条件が確実に復元されます。 

実装の微妙な点は、削除後に頂点が再挿入されないことです。 の`alive`配列は単調な削除を保証し、これにより線形の複雑さが可能になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、カスケードの後でのみ頂点がしきい値をかろうじて満たす場合です。 たとえば、次のような三角形の場合、$k=2$、3 つのエッジがすべて存在するまで頂点は存続しません。 最初のピーリングではすべてが削除され、逆挿入では両方の隣接頂点がアクティブな場合にのみ頂点が復元され、いずれかが安定する前に 3 つすべてが同時に存在することが保証されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、単一のエッジの削除が大規模なカスケードをトリガーする場合です。 すべての頂点が正確に次数を持つ密なコンポーネントを考えてみましょう$k$。 1 つのエッジを削除すると、2 つのエンドポイントがしきい値を下回り、広範囲に伝播する可能性があります。 BFS キューは、次のステップに進む前にこの伝播が完全に解決されることを保証し、最悪の場合のカスケード削除でも正確さを維持します。
