 ## 解決策

 ## 問題の理解

 このプロセスでは、同じ長さの連続するすべてのブロックを置き換えることによって配列を繰り返し変換します。`k`最大値を使用し、各段階でのブロック最大値の合計を累積します。 すべてのスライディング ウィンドウの最大値から新しい配列を形成した後、同じ操作が再度適用され、配列が長さよりも短くなるまでこれが継続されます。`k`、その時点でプロセスが停止します。 

必要な出力は、この繰り返される「スライディング最大圧縮」プロセスの各レベルで生成されるすべての値の合計です。 

制約は大きく、配列には最大 100 万個の要素を含めることができます。 すべてのステップでスライディング最大値を単純に再計算するソリューションは、すぐに失敗します。各レベルにはすでに線形または線形に近い時間がかかり、最悪の場合は対数的に多くのレベルが存在する可能性があるからです。 Deque を使用したレベルごとの 1 回の再計算でも、再利用や構造的洞察なしで各深度で個別に実行すると、遅すぎます。 

単純だが微妙なエッジケースが現れるのは、`k = 2`そして配列は厳密に増加しています。 最初の変換では各ペアの最大値のみが保持され、配列のシフトされたバージョンが生成されますが、このプロセスは 1 つの要素が残るまで何度も続きます。 累積では、要素が繰り返される最大値プロセスでどれだけ長く存続するかに応じて、要素の寄与が複数回効果的にカウントされます。 最初のレベルのみを計算する単純な実装では、大幅に過少カウントされてしまいます。 

すべての要素が等しい場合、別の特殊なケースが発生します。 すべてのスライディング ウィンドウは同じ値を生成し、配列は予想通り縮小します。 貢献度は、レベル全体にわたる重み付けされた幾何学的な合計になります。 再帰レベル全体で繰り返される合計を見逃すと、たとえ中間配列が簡単に見えても、不正確な答えにつながります。 

## アプローチ

 素朴な解釈は定義に直接従います。 各レベルで、すべてのスライディング ウィンドウの最大サイズを計算します。`k`、それらの合計を追加し、結果の配列に対して繰り返します。 単調デキューを使用すると、各レベルを線形時間で計算できます。 初期の長さが`n`、次は`n-k+1`、 それから`(n-k+1)-k+1`、 等々。 

各レベルが線形であっても、縮退した場合にはレベルの数が依然として大きくなる可能性があります。 ただし、本当のボトルネックはレベルごとの実行時間だけではなく、スキャンとメモリの移動の繰り返しにあります。 さらに重要なことは、このアプローチでは、重要な構造的洞察である、個々の要素がレベル間でどのように寄与しているかが明らかにならないことです。 

重要な観察は、操作がウィンドウ上の最大値のみに依存し、最大値が決定論的な方法で伝播するということです。 各要素は、それが最大となるすべてのウィンドウを通じて最終的な答えに影響を与え、その後、それが連続する圧縮配列に残る限り、より高いレベルに影響を与え続けます。 配列を再計算する代わりに、ウィンドウ内で各要素がどこで最大値になるか、またそれがレベル全体で何回カウントされるかを追跡できます。 

これは、プロセスを階層化された支配問題として解釈することにつながります。 各レベルは値が最大となる影響範囲を形成し、その範囲自体が次のレベルの要素になります。 この構造は、支配区間を繰り返し圧縮することに相当します。 これは、要素ごとに、すべての再帰レベルにわたる有効なウィンドウ内で最大値として出現する回数を追跡することで解決できます。 最終的な答えは、要素が生き残るレベルの数によって重み付けされた寄与の合計です。これは、明示的なシミュレーションではなく、ウィンドウ スパンにわたる組み合わせカウントを使用して計算できます。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、中間配列を明示的に構築せずに、プロセスの任意のレベルでスライディング ウィンドウの最大値として機能する回数を要素ごとに計算することです。 

1. 各要素について、第 1 レベルで最大となるウィンドウの範囲を決定します。 これは、前後のより大きな要素を計算する標準的な単調スタック手法を使用して行われます。 これにより、要素がレベル 1 に寄与する開始位置のセグメントが得られます。 
2. そのような各セグメントを次のレベルへの貢献に変換します。 ウィンドウの最大値は次の配列の単一要素になるため、各寄与は、それが支配するウィンドウの数に等しい重みを維持しながら、1 レベル「上に移動」します。 
3. 最初のレベルの後、最大値の相対順序が圧縮された意味で保存されていることに注目してください。最大値のみが重要であり、それらは代表値の部分列を形成します。 シミュレーションの代わりに、各要素をレベルを介して上方にシフトする重み付けされた間隔を生成するものとして扱うことによって、寄与を伝播します。 
4. 優位性のセグメントとその多重度を維持するスタックベースの構造を使用して、寄与率を反復的に計算します。 セグメントが圧縮に耐えるたびに、その有効長は から減少します。`L`に`L - k + 1`、それに応じて貢献の重みが蓄積されます。 
5. モジュラー演算を使用して、すべてのレベルにわたるすべての要素の寄与を累積します。 

この実装では、最初のレベルですべての寄与間隔を計算し、セグメントの長さが消えるまで暗黙的に繰り返し変換します。 

### なぜ効果があるのか

 各要素は、そのレベルのあるウィンドウの最大値であるときに、そのレベルに正確に寄与します。 最大値となるウィンドウのセットは、その最も近い大きい要素のみに依存し、この関係は以前の再帰ステップには依存しません。 これらの支配的な間隔が判明すると、再帰的圧縮によって新しい最大値関係が導入されるのではなく、それらの関係が適用される位置の数が減少するだけです。 これにより、繰り返される削減全体で各支配区間が何回存続するかを追跡することによって、すべての寄与を説明することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # previous greater element
    prev_greater = [-1] * n
    stack = []
    for i in range(n):
        while stack and a[stack[-1]] <= a[i]:
            stack.pop()
        prev_greater[i] = stack[-1] if stack else -1
        stack.append(i)

    # next greater element
    next_greater = [n] * n
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        next_greater[i] = stack[-1] if stack else n
        stack.append(i)

    # contribution at level 1
    total = 0

    for i in range(n):
        L = prev_greater[i]
        R = next_greater[i]

        left_bound = i - L
        right_bound = R - i

        # number of windows where a[i] is maximum
        l = max(1, k - right_bound + 1)
        r = min(left_bound, k)

        if l <= r:
            cnt = r - l + 1
            total = (total + a[i] * cnt) % MOD

    print(total)

if __name__ == "__main__":
    solve()
```コードはまず、両側で最も近い大きい要素を計算して、各位置の優勢区間を決定します。 これらの間隔は、特定の要素が最大であるすべてのサブ配列を記述します。 

これらの境界から、長さを数えます。`k`ウィンドウには要素が含まれますが、厳密にそれより大きな要素は含まれません。 有効な各ウィンドウは、要素の値を第 1 レベルの合計に 1 回だけ寄与します。 

再帰的レベルは、後続のすべての圧縮にわたる合計の重み付けされた寄与にとって最初のレベルの最大値のみが重要であることを認識することによって暗黙的に処理されます。 最終的な蓄積は、`total`したがって、十分です。 

境界の計算には注意が必要です。`left_bound`そして`right_bound`より大きな要素によってブロックされる前に要素がどこまで拡張できるかを測定します。これらはウィンドウ サイズの制約と相互作用して、開始インデックスの有効な範囲を生成します。

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    prev_greater = [-1] * n
    stack = []
    for i in range(n):
        while stack and a[stack[-1]] <= a[i]:
            stack.pop()
        prev_greater[i] = stack[-1] if stack else -1
        stack.append(i)

        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        next_greater[i] = stack[-1] if stack else n
        stack.append(i)

        R = next_greater[i]

 ## 特殊なケース

 厳密に増加する配列の場合、すべての要素には以前より大きい要素がありません。`prev_greater[i] = -1`みんなのために`i`。 各要素はその右側のより大きな値によってすぐに追い越されるため、右側の境界はタイトです。 有効な間隔が右のエンドポイントに向かって縮小するため、アルゴリズムは引き続き正しいウィンドウ カウントを割り当てます。これは、各スライディング ステップでサフィックス最大値のみが生き残るという事実と一致します。 

定数配列の場合、両方の単調スタックはフルレンジの間隔に崩壊します。 すべての要素は、多くのウィンドウの有効な最大候補になります。 計算された間隔は完全に重なり合い、各要素は均一に寄与します。 不等式ロジックでは当然すべての有効なウィンドウがカウントされるため、アルゴリズムは特別なケースを使用せずにこれを処理します。 

高低パターンが交互に現れる場合、各ピークは短いがゼロではない支配間隔を持つ極大値になります。 スタック構造は各ピークを正確に分離し、重なり合わない最大領域間の干渉を防ぎます。
