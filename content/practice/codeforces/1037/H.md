 ## 解決策
 ## 問題の理解

 固定の基本文字列が与えられます`s`。 各クエリは連続したセグメントを選択します`s[l..r]`と比較文字列`x`。 そのセグメントから、すべての個別の部分文字列、つまり開始部分を選択することによって形成されるすべての文字列を考慮します。`i`そして終わり`j`と`l ≤ i ≤ j ≤ r`。 これらの部分文字列のうち、辞書編集的に大きいもののみを考慮します。`x`、そしてそれらのうち最小のものを辞書順に出力する必要があります。 

したがって、各クエリは、文字列の固定ウィンドウ内で、すべての部分文字列の中から、指定されたパターンを厳密に超える辞書編集上最小の部分文字列を見つけます。 

主な困難は、部分文字列を生成することではなく、それを効率的に推論することです。 ある長さのセグメント内の部分文字列の数`m`は`O(m^2)`、そして最大で`2 · 10^5`最大長の文字列に対するクエリ`10^5`、部分文字列さえも列挙するアプローチは直ちに不可能です。 

制約は、大まかに必要なことを意味します。`O((n + q) log n)`または`O((n + q) polylog n)`行動。 クエリごとの部分文字列の長さに依存するものや、間隔を繰り返しスキャンするものは、制限時間を超過します。 

微妙な問題は、「個別の部分文字列」が計算上直接的に役に立たないことです。 概念的には重複が無視されても、すべての部分文字列の構造は依然として 2 次です。 

もう 1 つの明白ではない複雑な問題は、回答の部分文字列が必ずしもクエリ文字列に関連付けられているわけではないことです。`x`単純な接頭辞の方法で。 素朴な考えは、次の間の最初の不一致を見つけることです。`x`いくつかの部分文字列と貪欲に文字を増やしますが、部分文字列は内部の開始と終了の両方によって制限されます`[l, r]`、これにより、ローカルの貪欲な推論は信頼できなくなります。 

素朴な推論の典型的な失敗例は、最適な部分文字列がそれよりもはるかに長い場合です。`x`、 例えば`x = "b"`そして最適な答えは`"baaa..."`、部分文字列の後半で改善が発生します。 1 ステップの拡張のみを考慮するメソッドでは、このようなケースは見逃されます。 

## アプローチ

 ブルートフォース戦略は簡単です。すべてのペアを列挙します。`(i, j)`内部`[l, r]`、各部分文字列を形成し、それを比較します`x`、最小の有効な候補を追跡します。 これは、検索スペース全体を直接チェックするため、正しいです。 ただし、それぞれのクエリは、`O((r-l+1)^2 · |substring|)`最悪の解釈では、約`O(n^3)`クエリ間の動作。 最適化を行ったとしても、クエリごとの部分文字列の 2 次数はすでに致命的です。 

重要な構造上の観察は、すべての部分文字列が何らかの接尾辞の接頭辞であるということです。`s`。 部分文字列`s[i..j]`は、正確に、で始まるサフィックスのプレフィックスです。`i`、位置で切り捨てられます`j`。 これにより、問題は次のように再構成されます。 開始位置ごとに`i ∈ [l, r]`で始まるサフィックスを考慮してください。`i`、ただし境界までのみ`r`。 その境界サフィックスのプレフィックスを選択しています。 

これはすぐに接尾辞ベースの構造を示唆します。 接尾辞が辞書編集的に整理されると、部分文字列間の比較は接尾辞の接頭辞比較になります。 残りの困難は、選択した部分文字列が内部に留まるという制約を強制することです。`[l, r]`、これは開始位置と終了位置の両方に依存します。 

接尾辞オートマトンは、次のすべての部分文字列を表す自然な方法を提供します。`s`コンパクトに。 各状態は、同じ終了位置構造を共有する部分文字列のセットに対応し、遷移は文字拡張を表します。 範囲制約を処理するために、各状態はその発生のすべての終了位置に関する情報を維持できます。 これにより、状態によって表される部分文字列が完全に内部で出現するかどうかをテストできます。`[l, r]`何かの出来事が次の時点で終了するかどうかをチェックすることによって`e`そしてから始まります`e - len + 1 ≥ l`と`e ≤ r`。 

より大きい、辞書編集上最小の有効な部分文字列`x`次に、と比較しながらオートマトンの走査をシミュレートすることによって構築できます。`x`。 私たちはフォローします`x`できるだけ長く。 上に逸脱できる最初の位置で、より大きな文字で遷移を試み、内部の少なくとも 1 つの有効な出現にまだ対応する最小の実行可能な継続を貪欲に続行します。`[l, r]`。 

実現可能性チェックを効率的にサポートするために、各オートマトン状態に対して終了位置にわたるセグメント ツリーを保存し、必要な間隔内に出現があるかどうかをクエリできるようにします。 これにより、部分文字列の有効性が範囲クエリに制限されます。

 ## アルゴリズムのチュートリアル

 まず、文字列の接尾辞オートマトンを構築します。`s`。 各状態は多くの部分文字列を表し、その状態の部分文字列が出現するすべての終了位置をクエリできる構造で各状態を強化します。 位置に関するセグメント ツリーは、「[L, R] で終わる出現が存在するかどうか」をサポートするのに十分です。 

次に、各クエリを個別に処理します。 

1. オートマトンの初期状態から開始して、文字列の照合を試みます。`x`文字ごとに、同じ文字をたどることが可能かどうかを常にチェックし、それでも完全に内部で少なくとも 1 つの出現が発生するかどうかを確認します。`[l, r]`。 これにより、次の最長のプレフィックスが得られます。`x`有効な部分文字列内で一致する可能性があります。 
2. なんとかすべて消費できたら`x`、それでも厳密に大きな文字列が必要です。 これは、それを超えて拡張する必要があることを意味します`x`ある位置で。 
3. 最初に逸れる可能性のある位置または終了直後`x`の対応する文字より厳密に大きいすべての文字を試します。`x`(またはから`'a'`もし`x`完全に一致します）。 辞書編集的に最小の結果が必要なため、昇順で試します。 
4. 候補文字遷移ごとに、対応するオートマトン状態に移動し、この状態に内部に配置できる部分文字列が少なくとも 1 つ含まれているかどうかを確認します。`[l, r]`現在のトラバーサルによって暗示される長さの制約を尊重しながら。 このチェックは、終了位置セグメント ツリーを使用して行われます。 
5. 有効な遷移が見つかると、内部に少なくとも 1 つの有効な出現を保持する利用可能な最小の文字遷移を常に選択することで、文字列の拡張を貪欲に続けます。`[l, r]`。 

重要な不変条件は、構築の各ステップで、現在のオートマトンの状態が、構築されたプレフィックスに一致するすべての部分文字列に正確に対応し、セグメント ツリーの条件によって、その部分文字列が少なくとも 1 回出現することが完全に内部に収まることが保証されるということです。`[l, r]`。 辞書編集的に可能な最小の次の文字が常に選択されるため、有効な部分文字列よりも小さいものは選択されません。`x`スキップできます。代替案は以前と異なるため、辞書編集的に大きくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Suffix Automaton with endpos tracking via segment tree-like lists

class State:
    __slots__ = ("next", "link", "length", "pos_list")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.length = 0
        self.pos_list = []

class SAM:
    def __init__(self, s):
        self.st = [State()]
        self.last = 0

        for i, ch in enumerate(s):
            self.extend(ch, i + 1)

        # sort positions for each state (end positions)
        for st in self.st:
            st.pos_list.sort()

    def extend(self, c, pos):
        cur = len(self.st)
        self.st.append(State())
        self.st[cur].length = self.st[self.last].length + 1
        self.st[cur].pos_list = [pos]

        p = self.last
        while p != -1 and c not in self.st[p].next:
            self.st[p].next[c] = cur
            p = self.st[p].link

        if p == -1:
            self.st[cur].link = 0
        else:
            q = self.st[p].next[c]
            if self.st[p].length + 1 == self.st[q].length:
                self.st[cur].link = q
            else:
                clone = len(self.st)
                self.st.append(State())
                self.st[clone].length = self.st[p].length + 1
                self.st[clone].next = self.st[q].next.copy()
                self.st[clone].link = self.st[q].link
                self.st[clone].pos_list = self.st[q].pos_list[:]

                while p != -1 and self.st[p].next.get(c) == q:
                    self.st[p].next[c] = clone
                    p = self.st[p].link

                self.st[q].link = self.st[cur].link = clone

        self.last = cur

    def has_occurrence(self, v, l, r, length):
        # need an end position e such that:
        # l + length - 1 <= e <= r
        need_l = l + length - 1
        need_r = r
        arr = self.st[v].pos_list

        # binary search
        import bisect
        i = bisect.bisect_left(arr, need_l)
        return i < len(arr) and arr[i] <= need_r

def solve():
    s = input().strip()
    sam = SAM(s)

    q = int(input())
    for _ in range(q):
        parts = input().split()
        l, r = int(parts[0]), int(parts[1])
        x = parts[2]

        v = 0
        cur_len = 0
        ans = []
        used = False

        i = 0
        while True:
            found = False

            # try to follow x
            if i < len(x):
                c = x[i]
                if c in sam.st[v].next:
                    to = sam.st[v].next[c]
                    if sam.has_occurrence(to, l, r, cur_len + 1):
                        v = to
                        cur_len += 1
                        i += 1
                        continue

            # try to exceed x
            for ch in sorted(sam.st[v].next.keys()):
                if i < len(x) and ch <= x[i]:
                    continue
                to = sam.st[v].next[ch]
                if sam.has_occurrence(to, l, r, cur_len + 1):
                    ans.append(ch)
                    v = to
                    cur_len += 1
                    used = True
                    found = True
                    break

            if not found:
                break

        if not used:
            print(-1)
        else:
            print("".join(ans))

if __name__ == "__main__":
    solve()
```コードは接尾辞オートマトンを構築します`s`、各状態の終了位置を保存します。 クエリごとに、一致を試みます`x`内部で実行可能な限り、貪欲にオートマトンに沿って進みます`[l, r]`。 安全に追従できなくなったとき`x`、区間内でまだ有効な出現を許容する、辞書編集的により大きな最小の遷移を見つけることに切り替えて、貪欲に続行します。 

重要な詳細は、`has_occurrence`チェック。終了位置と現在構築されている部分文字列の既知の長さを通じて、開始制約と終了制約の両方を間接的に適用します。

 ## 特殊なケース

 エッジケースの 1 つは、セグメント全体が`[l, r]`同一の文字が含まれています。 その場合、すべての部分文字列は以下になります。`x`もし`x`その性格と一致します。 オートマトンは引き続きトラバースを許可しますが、すべての拡張機能は厳密な大なり条件に失敗する必要があり、正しく次のようになります。`-1`。 

もう一つのケースは次のような場合です。`x`間隔内のどの部分文字列よりも長いです。 アルゴリズムは可能な限り一致しますが、それ以上拡張することはできません。 有効な拡張子はこれを超えることはできないため、`x`、正解は次のようになります`-1`。 

3 番目のケースは、続行したとしても、回答を得るために早めに別のブランチに切り替える必要がある場合です。`x`しばらくは可能です。 貪欲な偏差ステップにより、辞書編集的により大きな有効な文字が存在するとすぐにそれが選択され、より小さな有効な代替文字が見逃されることがなくなります。
