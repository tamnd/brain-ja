 ## 解決策
 ## 問題の理解

 最初はすべて塗装されていないセルの行が与えられます。 一連のペイント操作を実行します。各操作は固定長の連続したセグメントをペイントしますが、そのセグメントの開始位置は自由に選択できます。 各操作には独自の色があり、後の操作は以前の操作を上書きします。 

要件は、すべての操作が完了した後、行内のすべてのセルをペイントする必要があり、最終構成で各色が少なくとも 1 回表示される必要があることです。 課題は、最終的な色付けを計算することではなく、これら 2 つのグローバル条件が同時に成立するように、各セグメントの有効な開始位置を構築することです。 

重要な問題は、セグメントが任意に重複する可能性があり、後の操作が前の操作を支配するという事実にあります。 これは、初期の色は壊れやすいことを意味します。最終的な配置で少なくとも 1 つのカバーされていない位置を明示的に残した場合にのみ、それらは存続します。 

この制約により、最大 10 万個のセルと操作が許可されるため、すべての配置を試行したり、すべての構成をシミュレートしたりするアプローチは除外されます。 任意の二次関数または偶数$O(n \log n)$オペレーションごとの構築が遅すぎます。 実現可能性を貪欲に確保する直線的な構築戦略が必要です。 

全体のカバレッジが不十分な場合、または大きなセグメントを早期に配置する必要がある場合に、微妙な失敗のケースが発生します。 

たとえば、長さ 1 の単一の演算があるとします。$n = 2$、1 回の操作で 1 つのセルしかペイントできないため、すべてのセルをカバーすることは不可能です。 別の失敗例は、多くの長いセグメントが短いセグメントの前に配置され、短いセグメントに必要な可視カラーを配置する余地がなくなる可能性がある場合に発生します。 

## アプローチ

 この強引なアイデアは、各セグメントの可能な開始位置をすべて試して、その結果のペイントをシミュレートすることです。 選択した位置ごとに、すべてのセルの最終的な色を計算し、すべての色が表示され、配列全体がカバーされているかどうかを確認します。 各セグメントには最大$O(n)$選択肢、これはおおよその結果につながります$n^m$これは、たとえ小さな入力であっても完全に実行不可能です。 

より構造化された試みは、左から右へ貪欲にシミュレートし、常に可能な限り早くセグメントを配置することです。 ただし、これでは、最終構成ですべての色が表示されたままであることを保証する必要性が無視されます。 常に位置 1 から開始する単純な貪欲も失敗します。これは、後のセグメントが以前の色のすべての出現を上書きする可能性があるためです。 

重要な観察は、完全なカバレッジを動的に推論する必要がないということです。 代わりに、保証された可視位置の観点から逆方向にソリューションを構築できます。 各操作では、色が最終色のままとなる一意のセルを少なくとも 1 つ予約する必要があります。 後の操作は前の操作を上書きするため、自然な戦略は、各セグメントが後で上書きされない少なくとも 1 つの新しいカバーされていない位置を確実に導入することです。 

これは建設的な戦略につながります。セグメントを左から右に処理しながら、各ステップで将来のすべてのセグメントを配置するのに十分な残りの長さが確保され、それぞれに少なくとも 1 つの一意のセルを残すということです。 

重要な制約は、セグメントを右に置きすぎると、将来のセグメントのフィッティングがブロックされる可能性があることです。 左端に配置しすぎると、将来のセグメントに対して一意の表示セルを保証できなくなる可能性があります。 正しい構築では、各セグメントが開始する必要がある移動下限を維持することによって、これら 2 つのバランスがとれます。

 ## アルゴリズムのチュートリアル

 セグメントを順番に処理し、ポインターを維持します`cur`残りのすべてのセグメントに十分なスペースを残しながら、現在のセグメントを開始できる最も早い位置を表します。 

1. 将来のセグメントに必要な残りの合計長を計算します。 最初は、これはすべての長さの合計です。 
2. i 番目のセグメントについて、実行可能な最小の開始位置を決定します。 セグメントを所定の位置に配置すると`p`の場合、配置後も残りのセグメントが配列のサフィックスに収まることを確認する必要があります。 これにより、次のような制約が与えられます。$$p \geq cur$$3. セグメントが配列の境界を超えていないことも確認します。$$p \leq n - l_i + 1$$4. 有効な最小値を選択します`p`それは両方の制約を満たします。 先に配置しても後のセグメントの実現可能性が損なわれることがないため、これは最適です。 
5. セグメント i を位置 p に配置した後、更新します。`cur`少なくとも 1 つ進めることで、将来のセグメントが同じ領域に集約されるのではなく、新しい領域を強制的に占有するようになります。 
6. いずれかの時点で有効範囲が空になった場合、構築は不可能であると判断されます。 

### なぜ効果があるのか

 この構造では、i 番目のセグメントを配置した後、残りのすべてのセグメントに少なくとも 1 つの新しいセルを割り当てるのに十分な未使用容量が残るという不変条件が維持されます。 ポインタ`cur`すべてのサフィックス セグメントの実現可能性を維持できる最も古い位置をエンコードします。 各セグメントは少なくとも 1 つの可視セルに寄与する必要があり、後のセグメントは前のセグメントを上書きするため、確実に単調に進みます。`cur`最終構成に表示される唯一の機会を失うセグメントがないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
l = list(map(int, input().split()))

# total remaining length
remaining = sum(l)

# current minimum feasible start
cur = 1

ans = [0] * m

for i in range(m):
    remaining -= l[i]

    # earliest we can start so that future segments still fit
    min_start = cur
    max_start = n - l[i] + 1

    if min_start > max_start:
        print(-1)
        sys.exit()

    p = min_start
    ans[i] = p

    # move cur forward: ensure future uniqueness space
    cur = max(cur, p + 1)

print(*ans)
```コードは実行下限を維持します`cur`各セグメントの開始位置。 の値`cur`セグメントを配置するたびに増加し、後のセグメントが新しい位置を占めるようになります。 上限チェックにより、配列の外側にセグメントが配置されないことが保証されます。 

微妙な点は、セグメントごとに少なくとも 1 つの新しい位置を常に消費することでサフィックスの実現可能性が暗黙的に保証されるため、必要な移動制約は 1 つだけであるということです。 これにより、残りの空き領域を明示的に追跡することが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        n, m = map(int, input().split())
        l = list(map(int, input().split()))
        remaining = sum(l)
        cur = 1
        ans = []
        for i in range(m):
            remaining -= l[i]
            if cur > n - l[i] + 1:
                print(-1)
                return out.getvalue().strip()
            ans.append(cur)
            cur = max(cur, ans[-1] + 1)
        print(*ans)
    return out.getvalue().strip()

assert run("1 1\n1\n") == "1", "single cell"

assert run("5 5\n1 1 1 1 1\n") == "1 2 3 4 5", "all single cells"

 ## 特殊なケース

 すべてのセグメントの長さが 1 である場合、重大なエッジ ケースが発生します。この状況では、すべてのセルに個別の色の位置を割り当てる必要があります。 アルゴリズムは増加する開始位置を割り当てます。`cur`2 つのセグメントが重ならないように強制します。 入力用`5 5`みんなで星になる`1 2 3 4 5`、完全に有効なカラーリングが生成されます。 

もう 1 つの特殊なケースは、長いセグメントが短いセグメントの前にある場合です。 例えば`5 2`長さのある`5, 1`。 最初のセグメントは唯一の有効な位置であるため、1 から開始する必要があります。 その後、`cur`は 2 になり、2 番目のセグメントが強制的に 2 から開始されます。これは有効であり、短い色が最終的な配列に表示されるようになります。 

現在の状況でセグメントを境界内に配置できない場合、失敗ケースが発生します。`cur`。 たとえば、次の場合`cur`超えて進む`n - l[i] + 1`、法的な開始位置は残っておらず、構築は正しく終了します。`-1`。
