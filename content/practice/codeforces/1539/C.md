 ## 解決策
 ## 問題の理解

 生徒のスキルレベルが与えられます。 グループ内の生徒を並べ替えた後、すべての隣接するペアの差異が最大でも異なる場合、そのグループは安定していると見なされます。`x`。 

生徒は好きなようにグループに組み替えることができ、最大でも追加することもできます。`k`任意のスキルレベルを持つ新入生。 目標は、これらの追加の学生を最適に使用した後に残る安定したグループの数を最小限に抑えることです。 

最初の観察は、安定性はスキル レベルのソート順にのみ依存するということです。 配列全体がソートされると、`x`自然な休憩を生み出します。 連続する 2 つの値の差が最大でも異なる場合`x`、同じ安定したグループに属することができます。 差がそれよりも大きい場合`x`、間に追加の生徒を挿入しない限り、それらを接続することはできません。 

制約が主な手がかりです。 まであります`200,000`これにより、挿入された学生の多くの組み合わせを試したり、コストのかかる操作でグループを繰り返しマージしたりするソリューションは直ちに除外されます。 アン`O(n²)`アプローチには前後が必要です`4 × 10¹⁰`限界をはるかに超えた最悪の場合の動作。 並べ替え中`O(n log n)`この入力サイズでは完全に妥当な値であるため、解決策はそこから始まると予想する必要があります。 

の値`a[i]`、`k`、 そして`x`と同じ大きさにすることができます`10¹⁸`。 これは、すべての算術演算を 64 ビット サイズの整数で実行する必要があることを意味します。 Python はこれを自然に処理しますが、必要な挿入の式は、1 つずつの間違いを避けるために慎重に導出する必要があります。 

次のような特殊なケースを考えてみましょう。```
3 1 3
1 4 7
```ギャップはまさに`3`そして`3`。 正しい答えは、`1`差が等しいためグループ化`x`すでに許可されています。 を扱う不注意な実装`gap >= x`分割すると誤って 3 つのグループが作成されてしまうためです。 

別のケースを考えてみましょう。```
2 1 3
1 8
```ギャップは`7`。 挿入された生徒は 1 人で十分です。```
1 4 8
```両方の違いは次のようになります`3`。 正しい答えは、`1`。 よくある間違いは、必要な挿入を次のように計算することです。`gap // x`、それは与える`2`。 正しい式は次のことだけを与えます。`1`。 

より微妙なケースは次のとおりです。```
2 2 3
1 11
```ギャップは`10`。 2 回の挿入で十分です。```
1 4 7 11
```答えは`1`。 間違った式を使用すると、3 つの挿入が必要であると誤って主張される可能性があります。 

最後に、次のことを考慮してください。```
4 0 3
1 2 100 101
```挿入は許可されません。 問題のあるギャップが 1 つだけあるとしても、それを埋めることはできません。 答えは残っている`2`。 すべてのギャップは最終的にマージできると貪欲に想定するソリューションは、ここでは失敗します。 

## アプローチ

 強引な考え方は、ソートされた配列から開始して、すべての大きなギャップを個別に考慮することです。 ギャップごとに、挿入される生徒の数を変えて試し、結果のグループをシミュレートし、予算内で最適なマージの組み合わせを探すことができます。`k`。 

このアプローチは概念的には正しいです。すべての有効な解決策は、どのギャップを埋めるかによって決まるからです。 問題は、可能性の数が指数関数的に増加することです。 あれば`m`大きなギャップがあります`2^m`どのギャップを埋めるかを選択する方法。 まで`200,000`要素があれば、これは完全に不可能です。 

重要な観察は、大きなギャップはすべて独立しているということです。 

2 つの連続する並べ替えられた値が異なると仮定します。`d > x`。 結果として生じるすべての隣接する差を最大で作成するために必要な、挿入された生徒の最小数を知りたいと考えています。`x`。 

挿入すると`t`学生、ギャップは次のように分割されます。`t + 1`セグメント。 必要なものは次のとおりです。$$\frac{d}{t+1} \le x$$並べ替えると次のようになります。$$t+1 \ge \frac{d}{x}$$最小挿入数は次のようになります。$$\left\lfloor \frac{d-1}{x} \right\rfloor$$すでに提供されている 1 つのセグメントを差し引くと、次のように簡略化されます。$$\frac{d-1}{x}$$整数の除算を使用します。 

例えば：```
d = 10, x = 3
```

$$(10-1)//3 = 3$$必要な挿入:$$3 - 1 = 2$$構造にマッチするもの`1,4,7,10`。 

ブリッジ可能な各ギャップには、必要な挿入で測定されるコストと、ちょうど 1 グループ少ない利点があります。 どのマージでも同じ利点が得られます。 すべてのアイテムの価値が等しい場合、最適な戦略は、最初に最も安いものを購入することです。 

したがって、問題は次のようになります。 

1. 配列をソートします。 
2. 以下より大きいギャップをすべて見つけます。`x`。 
3. そのギャップを埋めるために必要な挿入コストを計算します。 
4. これらのコストを分類します。 
5. 使えるものを使う`k`まずは最も安価なギャップから。 

この貪欲な戦略は、マージが成功するたびにグループ数がちょうど 1 つ減るため、最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スキルレベルを並べ替えます。 

安定性はソートされた順序で隣接する値にのみ依存するため、ソートによりグループが自然に分割されるすべての場所が明らかになります。 
2. から始める`groups = 1`。 

大きなギャップのないソートされた配列は、1 つの安定したグループを形成します。 
3. すべての隣接するペアをスキャンします。 

させて`d = a[i] - a[i-1]`。 
4. もし`d <= x`、何もしません。 

これら 2 つの値は、すでに同じ安定したグループに属している可能性があります。 
5. もし`d > x`、新しいグループが強制的に作成されます。 

インクリメント`groups`。 
6. このギャップを埋めるために挿入された生徒の数を計算します。 

必要な数は次のとおりです。$$\frac{d-1}{x} - 1$$整数の除算を使用します。 

コード内:```
need = (d - 1) // x
need -= 1
```同様に:```
need = (d - 1) // x
```標準の Codeforces ソリューションによって保存されるマージ コストとして解釈される場合:```
need = (d - 1) // x
```そして、その多くの挿入を直接費やします。 この値はすでに必要な挿入数と等しくなります。 
7. すべてのマージ コストをリストに保存します。 

保存された各値は、削除できる可能性のある 1 つのギャップを表します。 
8. コストを並べ替えます。 

マージが成功するたびに答えがちょうど 1 ずつ減るため、最初に最も安価なギャップを埋める必要があります。 
9. ソートされたコストを繰り返し処理します。 

現在のコストが最大でも残りのコストである場合`k`、使う、から引く`k`、減少します`groups`1つずつ。 
10. の最終値を出力します。`groups`。 

### なぜ効果があるのか

 ソート後、すべてのギャップが次の値より大きくなります`x`グループ間に強制的な分離が生じます。 このような隔たりを解消する唯一の方法は、その特定のギャップを埋めるために十分な生徒を投入することです。 

各ギャップは独立して機能します。 あるギャップを埋めても、別のギャップのコストが変わることはありません。 ブリッジが成功するたびに、グループの数が 1 つずつ減ります。 すべてのブリッジが同じ利点を提供するため、限られた予算を最大限に活用するには、最初にコストが最小のブリッジを選択することになります。 これはまさに、コストをソートして昇順に処理するという貪欲な戦略です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, x = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort()

    groups = 1
    costs = []

    for i in range(1, n):
        gap = a[i] - a[i - 1]

        if gap > x:
            groups += 1
            costs.append((gap - 1) // x)

    costs.sort()

    for cost in costs:
        if cost <= k:
            k -= cost
            groups -= 1
        else:
            break

    print(groups)

solve()
```最初のステップでは、潜在的に問題となる可能性のある差異が隣接する要素間で現れるようにスキル レベルを並べ替えます。 

ギャップを超えるたびに`x`、新しいグループが強制されることがわかります。 同時に、その分離をなくすのにどれくらいの費用がかかるかを計算します。 表現`(gap - 1) // x`が重要な公式です。 これは、ほとんどの人が最初の試みで間違える部分です。 

Suppose the gap is exactly`x + 1`。 それから：```
(gap - 1) // x = 1
```これは正しくは、挿入された生徒が 1 人で十分であることを示しています。 

埋められたすべてのギャップが同じ報酬を生み出すため、コストはソートされ、グループが 1 つ少なくなります。 より安価なギャップの前に、より高価なギャップにリソースを費やしても、答えを改善することはできません。 

Python の整数は、次の値まで安全に処理します。`10¹⁸`, そのため、大きな差を計算する場合でもオーバーフローのリスクはありません。

 ## 特殊なケース

 ### ギャップは x に完全に等しい

 入力:```
3 0 3
1 4 7
```並べ替えられたギャップは、`3`そして`3`。 どちらもすでにせいぜい`x`、分割は発生しません。```
groups = 1
```このアルゴリズムによりコストや出力が追加されることはありません。`1`。 

### 1 つの大きなギャップに 1 回の挿入が必要

 入力:```
2 1 3
1 8
```ギャップは`7`。```
cost = (7 - 1) // 3 = 2
```これは、欲張りアカウンティングで成功した 1 つのブリッジ コストに相当する、元の分離を超えた 2 つのセグメントが必要であることを意味します。 予算は十分なのでグループを統合し、答えは`1`。 

### 10¹⁸ に近い大きな数

 入力:```
2 1000000000000000000 1000000000000000000
1 1000000000000000000
```ギャップは以下です`x`、だから答えはすぐにわかります`1`。 

このアルゴリズムは Python 整数に対して減算と整数除算のみを実行するため、オーバーフローは発生しません。 

### 利用可能な挿入はありません

 入力:```
4 0 3
1 2 100 101
```間のギャップ`2`そして`100`分割を強制します。```
groups = 2
costs = [32]
```以来`k = 0`、費用は一切かかりません。 

最終的な答えは次のとおりです。```
2
```これはまさに、安定したグループの達成可能な最小数です。
