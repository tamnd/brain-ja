 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられ、隣接する 2 つの要素をそれらの合計に置き換えることで繰り返しマージすることができます。 マージするたびにシーケンスが 1 要素ずつ短くなりますが、元のすべての値の合計は保持されます。 

好きな方法でマージを完了したら、スコアリング ルールを使用して結果のシーケンスを評価します。各要素は、その値の上限を固定整数で割った値に寄与します。$x$、そして全体的な美しさはこれらの貢献の合計です。 

このタスクは、考えられるすべてのマージをシミュレートすることではありません。 代わりに、すべてのマージ戦略にわたって可能な限り最小および最大の美しさを決定する必要があります。 

制約により、最大で$10^5$テストケースごとの数値と$10^3$テストケース、合計$10^5$全体的な要素。 すべてのマージ シーケンスを試行する解決策は、局所的な選択でも組み合わせが爆発的に増加するため、不可能です。 テストケースごとに線形なものが必要です。 

重要な微妙な点は、マージによって値と天井関数との相互作用の方法が変わることです。 合計は保存されますが、$\lceil (a+b)/x \rceil$に等しくありません$\lceil a/x \rceil + \lceil b/x \rceil$一般に、マージの構造が重要です。 

よくある失敗例は、貪欲なローカル マージが常に機能すると想定していることに起因します。 たとえば、$x = 3$, 結合により、合計が$x$。 残留動作を追跡せずに任意にマージするアプローチは、次のような入力では失敗します。$4, 11$、ここで:

 - 別途:$\lceil 4/3 \rceil + \lceil 11/3 \rceil = 2 + 4 = 6$- 統合:$\lceil 15/3 \rceil = 5$この 1 つの例は、生の値ではなく貢献の観点から推論する必要がある理由をすでに示しています。 

## アプローチ

 この強引なアイデアは、考えられるすべてのマージ シーケンスをシミュレートすることです。 マージごとに配列サイズが 1 つずつ減少し、各ステップで隣接するペアが選択されます。 サイズの配列の場合$n$、指数関数的に多くのマージ ツリーが存在し、基本的にはシーケンス上のすべてのバイナリ ツリーが存在します。 構造を数えても、これはカタルーニャ語のように増加し、それを超えると実行不可能になります。$n \approx 20$。 

障害は、マージが天井関数と非線形に相互作用することです。 ただし、各数値をサイズの完全なブロックに分割すると、天井は適切に動作します。$x$そして残り。 書き込み$$a_i = q_i x + r_i, \quad 0 \le r_i < x,$$グループ化に関係なく、各完全なブロックが美しさにちょうど 1 貢献していることが観察されます。$\lceil (qx)/x \rceil = q$。 問題は完全に残りの部分にあります。 

個別のグループとして存続する場合、各剰余は 1 を与えますが、その合計が交差する場合、複数の剰余を結合して追加の完全なブロックにすることができます。$x$。 したがって、問題は、余分なブロックに「スピルオーバー」する回数を最大化または最小化するために、どのように剰余をグループ化するかということになります。 

これにより、問題は残りのシーケンスを連続したセグメントに分割することになり、各セグメントが寄与します。$$\left\lceil \frac{\text{segment sum}}{x} \right\rceil.$$最大限の美しさを実現するには、オーバーフローを生み出すセグメントの数を最大化したいと考えています。 これは、残りのマージをできる限り回避し、可能な限りそれらを分離した場合に起こります。 最小限の美しさのために、余分なブロックができるだけ少なくなるように、残りを効率的に詰め込みたいと考えています。 

重要な単純化は、最適化には残りの部分のみが重要であるということです。 商の部分は、すべての要素にわたる固定の定数合計に寄与します。

 ## アルゴリズムのチュートリアル

 それぞれの数字を分割します$a_i$の中へ：

-$q_i = a_i // x$-$r_i = a_i \% x$合計の答えは常に次から始まります$\sum q_i$、残りがどのようにグループ化されるかに基づいて調整するだけです。 

### 最大限の美しさ

 1. コンピューティング$q_i$すべての要素について計算し、それらを合計して基本的な答えを求めます。 
2. 各要素の残りの部分を独立して処理します。 
3.追加$\sum \lceil r_i / x \rceil$、これは単にゼロ以外の剰余の数です。 
4. ベースとこのカウントを返します。 

これが機能する理由は、要素を分離しておくと剰余の取り消しが防止され、グループが次の倍数と交差する頻度が最大化されるためです。$x$。 

### 最低限の美しさ

 1. 商の同じ基本和を計算します。 
2. 残りをすべて抽出します。 
3. 剰余を降順に並べ替えます。 
4. それらを実行セグメントの合計に貪欲にパックします。 
5. 現在の合計額がそれに達するか、それを超えるたびに$x$、余分なブロックを 1 つカウントし、累積和モジュロをリセットします。$x$。 
6. 最終的な答えは、ベースに形成されたブロックの数を加えたものです。 

ソートのステップでは、大きな残りを最初にパックすることで、後で余分な交差を引き起こす断片化を最小限に抑えます。 

### なぜ効果があるのか

 不変条件は、すべての要素が固定数の完全な要素に寄与するということです。$x$-ブロックはその商によって決定され、すべての柔軟性は残りの塊がどのようにグループ化されるかによって決まります。 有効なマージ戦略はどれも、残りを連続セグメントに分割することに正確に対応します。 最大値を得るには、剰余の結合を避けるため、キャンセルを行わないとセグメントの効率が低下します。 最小限に抑えるために、質量をできるだけ少ないセグメントに最適にパッキングすることをシミュレートし、ソートにより、大きな残りが後で避けられないオーバーフローを引き起こす可能性がある場合に、小さな残りで初期に容量を無駄にしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        base = 0
        rem = []

        for v in a:
            base += v // x
            r = v % x
            if r:
                rem.append(r)

        # maximum: each non-zero remainder contributes 1 extra
        max_beauty = base + len(rem)

        # minimum: greedily pack remainders
        rem.sort(reverse=True)

        cur = 0
        add = 0
        for r in rem:
            if cur + r >= x:
                add += 1
                cur = 0
            else:
                cur += r

        min_beauty = base + add

        print(min_beauty, max_beauty)

if __name__ == "__main__":
    solve()
```コードは商と剰余の寄与を明確に分離しています。 商部分はすべての操作で不変であるため、すぐに累積されます。 

最大の計算を行うために、ロジックは、ゼロ以外の剰余が分離されたままであれば、追加の天井ユニットを強制的に提供できるという事実に依存しています。 これにより、交差点の数を減らす可能性のある偶発的な合流が回避されます。 

計算を最小限にするには、剰余を降順にソートすることが不可欠です。 ソートを行わないと、小さな残りが最初にパックされ、大きな残りが必要以上に頻繁にオーバーフローする可能性があります。

 ## 特殊なケース

 重大なエッジケースは、すべての要素が次の倍数である場合です。$x$。 その状況では、残りはすべて消え、マージに関係なく答えは固定されます。 剰余リストが空になり、最大値と最小値の両方が商の合計と等しくなるため、アルゴリズムはこれを自然に処理します。 

別のエッジケースが発生するのは次の場合です。$x = 1$。 すべての要素はその値を上限カウントとして正確に提供し、マージしても何も変わりません。$\lceil (a+b)/1 \rceil = a+b$。 このアルゴリズムはすべてを商の累積に換算し、再び同一の最小値と最大値を生成します。 

より微妙なケースは、剰余がすべて小さいものの、集合的に超過する場合に現れます。$x$。 貪欲なパッキングにより、これらの小さな断片が可能な限り少ない交差に蓄積されることが保証され、ソートのステップにより、後で追加のブロックを強制することになる低値の要素による容量の早期消費が防止されます。
