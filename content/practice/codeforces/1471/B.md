 ## 解決策
 ## 問題の理解

 この問題で説明されているプロセスは、配列が左から右にスキャンされながら拡張し続けるものと考えると理解しやすくなります。 要素を選択するたびに、要素を小さな部分に拡張するか、すべてをすぐに停止します。 

各要素は「値のパケット」のように動作します。 値が固定数で割り切れる場合`x`、その後、そのパケットは次のように置き換えられます`x`それぞれが値を運ぶ小さなパケット`q / x`。 そうしないと、システムはすぐに失敗し、それ以上の処理は行われません。 重要なのは、新しく作成されたパケットは最後に追加され、システムに障害が発生しない場合には後で処理されることです。 

タスクは、最終的な配列を明示的にシミュレートすることではなく、このプロセスが自然に停止するまで完全に実行された場合に表示されるすべての値の合計を計算することだけです。 

制約が非常に厳しいため、直接シミュレーションは安全ではありません。 敵対的なケースでは、要素の総数が非常に急速に増加する可能性があります。 すべての要素が分割され続けると、配列のサイズが指数関数的に爆発的に増大し、明示的に保存または反復できるサイズをはるかに超えてしまう可能性があります。 と`n`テスト全体で最大 100,000 件の場合、新しい要素を繰り返しキューにプッシュするアプローチでは、二次関数またはそれより悪い動作が発生する危険があります。 

よくある失敗例は、文字通りキューをシミュレートすることです。 たとえば、`x = 2`そして`[2^20]`、最終的な答えはまだ管理可能な場合でも、生成される要素の数は膨大になります。 もう 1 つの微妙な落とし穴は、停止が早すぎる、または遅すぎることです。分割できない要素に遭遇すると、プロセスが即座に停止するため、今後生成されるすべての要素は無関係になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 キューを使用してロボットをシミュレートします。 要素を順番に処理し、次の値で割り切れる値が見つかるたびに処理します。`x`を次のように置き換えます。`x`のコピー`q / x`。 そうでない場合は停止します。 

これが機能するのは、ルールに正確に従い、生成されたすべての要素が最終的に正しい順序で処理されるためです。 ただし、問題は、各除算ステップで要素の総数が 1 倍に増加することです。`x - 1`。 数の累乗のような割り算を繰り返すと、`x`、生成される要素の数は因数分解の深さに応じて指数関数的に増加します。 個々の値は減少しますが、拡張が完全に支配します。 

重要な観察は、最終的な構造は必要なく、合計だけが必要であるということです。 値が`q`で割り切れます`x`で置き換えます。`x`のコピー`q / x`合計を正確に保持します。`x * (q / x) = q`。 したがって、分割してもその時点の合計は変わりません。 合計が変化するのは、次の値で割り切れない値に遭遇したときだけです。`x`、その値は最終的なものであり、それ以上拡張されないためです。 

これは、元の各要素を何回繰り返し分割できるかを追跡するだけでよいことを意味します。`x`その間、それは分割可能なままであり、初めて分割不可能になったときに、それがさらなる拡大に寄与しなくなる場所が決まります。 

以前の拡張により元の各要素が複製された回数をカウントする実行乗数を実行することにより、圧縮された方法でプロセスを効果的にシミュレートします。

 | 最適 | O(n · logₓ A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの変数: 実行インデックスを維持しながら、要素を順番に処理します。`i`そして乗数`cnt`現在の要素が効果的に表すコピーの数を表します。 以前の拡張により、この値がカウントされる回数が増加した可能性があるため、これが必要になります。 
2. 各要素について`a[i]`を掛けます。`cnt`現段階で効果的な貢献を得るために。 これは、この要素に至るすべての重複したパスを表します。 
3. 現在値が次の値で割り切れる間、`x`で割ります。`x`そして掛け算する`cnt`による`x`。 これは、各部門が生産するという事実をモデル化しています。`x`新しいコピーは、それぞれ将来の処理に等しく貢献します。 
4. で割り切れない値に達したら`x`、追加します`value * cnt`応答すると、その瞬間にロボットがシャットダウンするため、処理が完全に停止します。 
5. 値が割り切れる場合`x`最初の配列の処理が完了すると、蓄積された乗算器によって暗黙的に処理される生成された寄与を継続して、すべての拡張が考慮されるようにします。 

微妙な部分は、`cnt`は、以前のすべての要素にわたる重複を集約するため、展開された配列を明示的に構築することはありません。 

### なぜ効果があるのか

 不変条件とは、`cnt`は常に、完全なシミュレーション内に存在する現在の値の同一の「アクティブ コピー」の数を表します。 各分割ステップでは合計を保持しながら、質量をより多くのコピーに再分配します。`cnt`そのようなコピーが何個存在するかを正確に追跡します。 有効な分割の下では合計は不変であるため、答えに追加するのは、シミュレートされた走査順序で最初に遭遇した分割不可能な要素でプロセスが停止したときだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0
    i = 0
    cnt = 1

    while i < n:
        val = a[i]

        # account for multiplicity coming from previous expansions
        val *= cnt

        # try to expand while divisible
        while val % x == 0:
            val //= x
            cnt *= x

        ans += val

        # once we hit a non-divisible value, process stops
        if val % x != 0:
            break

        i += 1

    print(ans)
```上記の構造は、圧縮シミュレーションの概念を直接反映しています。 変数`cnt`追加された要素の指数関数的な数を置き換えます。 乗算する`val`による`cnt`これにより、以前に作成された重複した投稿がすべて確実に考慮されます。 内側のループは、可能なすべての除算を次のように実行します。`x`、そしてすべての除算は多重度を正しく増加させます。 

停止条件は非常に重要です。割り切れない値が出現すると、システム内のどこにもそれ以上の拡張は発生しないため、ループを継続すると、有効な終了には存在しない値が誤って含まれてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0
        i = 0
        cnt = 1

        while i < n:
            val = a[i] * cnt

            while val % x == 0:
                val //= x
                cnt *= x

            ans += val

            if val % x != 0:
                break

            i += 1

        out.append(str(ans))

    return "\n".join(out)

assert run("""2
1 2
12
4 2
4 6 8 2
""") == "36\n44"

# minimum case
assert run("""1
1 2
1
""") == "1"

# power chain
assert run("""1
1 2
8
""") == "8"

# mixed case
assert run("""1
3 3
3 9 2
""") == "15"

 ## 特殊なケース

 重要なエッジケースは、最初の要素が次の要素で割り切れない場合です。`x`。 このような状況では、プロセスは即座に停止し、拡張はまったく行われません。 最初のチェックで除算ループが失敗し、値が直接追加されるため、アルゴリズムはこれを正しく処理します。 

すべての要素が次の要素で割り切れる場合、別の特殊なケースが発生します。`x`この場合、多重度は大幅に増加しますが、アルゴリズムは拡張された配列を実現しません。 代わりに、すべての展開を次のように集約します。`cnt`、概念的な構造が指数関数的であっても、計算が線形に保たれるようにします。
