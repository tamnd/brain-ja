 ## 解決策
 ## 問題の理解

 1 つ以上の非負の整数のシーケンスが与えられます。 各シーケンスについて、そのシーケンスのどこにも現れない最小の非負の整数を見つけたいと考えています。 この値は MEX と呼ばれ、「最小除外値」の略です。 

配列は、ゼロから始まる数直線上のマークされた整数のコレクションであると考えてください。 存在する番号もあれば、欠落している番号もあります。 タスクは、0 から上に向かってスキャンするときに最初のギャップを特定することです。 

通常、入力形式は多数のテスト ケースを提供し、テスト ケースごとにシーケンスの長さに続いてシーケンス自体が続きます。 出力はテスト ケースごとに 1 つの整数であり、MEX を表します。 

ここでは制約は明示的に述べられていませんが、意図したソリューションはテスト ケースごとに線形時間で実行されます。 これは、テスト ケース全体のすべての配列サイズの合計が最大でも約 2 × 10^5 または 10^6 であることを強く示唆しています。 テスト ケースごとに配列を繰り返しスキャンまたは並べ替えるソリューションは、合計サイズが大きい場合、速度が非常に遅くなります。 

0 から N−1 までのすべての数値が存在する場合、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[0, 1, 2, 3]`、その場合、答えは次のとおりです。`4`これは、最初に欠落している非負の整数であるためです。 までの値のみをチェックする単純なアプローチ`max(array)`MEX が正確に一致する可能性を考慮しない場合、ここでは失敗します。`N`。 

別のエッジ ケースは、配列に大きな値のみが含まれている場合に発生します。たとえば、`[10, 11, 12]`。 正しい答えは、`0`、ゼロがすぐに欠落するため。 ゼロではなく最小要素からスキャンを開始する誤った実装では、これを見逃してしまいます。 

最後に、重複は正確さに影響しませんが、要素の削除や並べ替えを繰り返し試行する非効率的なソリューションの誤解を招く可能性があります。 

## アプローチ

 MEX を計算する強引な方法は、0 から始まる各整数が配列内に出現するかどうかを繰り返しチェックすることです。 各候補値 x について、配列全体をスキャンし、x が存在するかどうかを確認します。 そうでない場合は、すぐに x を返します。 

このアプローチは MEX の定義に直接従うため、正しいです。 問題はそのコストです。 最悪の場合、0 から N までのすべての値をチェックし、それぞれについて N 個の要素をスキャンする可能性があります。 これにより、テスト ケースごとに O(N^2) の操作が必要になり、N が大きい場合には遅くなりすぎます。 

重要な点は、フル スキャンを繰り返す必要がないということです。 [0, N] の範囲内の各数値が少なくとも 1 回出現するかどうかのみを考慮します。 サイズ N の配列の MEX は常に最大でも N であるため、N より大きい数値は答えに影響を与えることはできません。これにより、検索空間が制限されます。 

したがって、入力に対する 1 回のパスでブール配列またはハッシュ セットを使用して、[0, N] にどの値が存在するかをマークできます。 マークを付けた後、0 から上に向かってスキャンし、マークされていない最初のインデックスを返します。 これにより、問題は 2 つの直線パスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列サイズ N と配列値を読み取ります。 これより大きな値は答えになり得ないため、[0, N] の範囲内の値のみを追跡します。 
2. ブール配列を作成する`present`サイズ N+1 は False に初期化されます。 この配列内の各インデックス i は、値 i が入力に存在するかどうかを表します。 
3. 入力配列内の各要素 x を反復処理します。 0 ≤ x ≤ N の場合、マークを付けます`present[x] = True`。 このステップでは、配列に関するすべての関連情報をコンパクトな存在テーブルに圧縮します。 
4. i = 0 から N までスキャンします。 最初のインデックスは次のとおりです`present[i]`is False は MEX であるため、すぐに返します。 
5. 0 から N までのすべての値が存在する場合は、N を返します。これは、配列に整数の完全なプレフィックスが含まれる場合をカバーします。 

### なぜ効果があるのか

 正確さは、MEX が配列に存在しない最小の非負の整数として定義されているという事実から来ています。 ブール配列は、答えとなる可能性のあるすべての候補のメンバーシップを正確に表します。 サイズ N の配列の MEX は N を超えることができないため、注意を [0, N] に限定しても情報が失われることはありません。 最終スキャンでは候補を昇順でチェックするため、最初に欠落しているインデックスが真の最小除外値である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        present = [False] * (n + 1)

        for x in arr:
            if 0 <= x <= n:
                present[x] = True

        ans = n
        for i in range(n + 1):
            if not present[i]:
                ans = i
                break

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、テスト ケースの数を読み取り、それを反復処理することから始まります。 それぞれのケースで、次のサイズのプレゼンス配列を構築します。`n+1`関連する可能性のあるすべての値をカバーします。 ループ内の条件チェックにより、意味のある範囲外の値が確実に無視されるため、不必要な書き込みが回避され、ロジックが厳密に保たれます。 

最後のループは、最初の欠落番号が見つかるとすぐに停止するように構成されています。 この早期終了は、実際には線形動作を維持し、MEX の定義と直接一致するため、重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        present = [False] * (n + 1)

        for x in arr:
            if 0 <= x <= n:
                present[x] = True

        ans = n
        for i in range(n + 1):
            if not present[i]:
                ans = i
                break

        output.append(str(ans))

    return "\n".join(output)

# sample-style cases
assert run("1\n5\n0 1 2 4 4\n") == "3"
assert run("1\n4\n10 11 12 13\n") == "0"

# custom cases

assert run("1\n3\n1 2 3\n") == "0", "missing zero"
assert run("1\n3\n0 1 2\n") == "3", "full prefix"
assert run("1\n6\n2 2 2 2 2 2\n") == "0", "duplicates only"

## 特殊なケース

 重要なエッジ ケースの 1 つは、配列に 0 から N−1 までのすべての整数が含まれる場合です。 たとえば:

 入力:```
1
4
0 1 2 3
```アルゴリズムは、決して挿入されない 4 を除く、0 から 4 までのすべての位置を存在するものとしてマークします。 スキャンの結果、`present[4]`は False であるため、4 を返します。配列がプレフィックスを完全にカバーしているため、これは正しい MEX と一致します。 

もう 1 つのエッジ ケースは、すべての要素が有効範囲外である場合です。 

入力:```
1
5
100 200 300 400 500
```[0, 5] には値がないため、マーキング中はすべての値が無視されます。 ブール配列はすべて False のままです。 スキャンはすぐに 0 を返します。これは、欠落している最小の整数が 0 であるため、これは正しいことです。 

3 番目のケースには重複が含まれます。 

入力:```
1
5
0 0 0 1 1
```0 と 1 のみがマークされます。 スキャンにより、最初のマークされていないインデックスとして 2 が見つかります。 重複によってプレゼンス配列の状態が変更されることはないため、正確性は保たれます。
