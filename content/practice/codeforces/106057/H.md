 ## 問題の理解

 2 つの整数が与えられます。$k$そして$m$。 目標金額を立てることを考える$n$正確に分割することで$k$順序付けされた部分。各部分は負ではない整数です。 2 つの分解は、$k$-タプルは異なります。 

固定の場合$n$、質問はそのようなものがいくつあるかを数えます$k$- エントリの合計が以下になるタプルが存在します$n$。 最小のものを見つけるように求められます$n \ge 0$このカウントが少なくとも$m$。 そうでない場合$n$存在するので戻らなければなりません$-1$。 

これは直接組み合わせ計数の問題です。 順序付けされた非負の解の数$$x_1 + x_2 + \dots + x_k = n$$は標準的な星と棒のアイデンティティによって与えられます。$$\binom{n+k-1}{k-1}.$$したがって、問題は最小のものを見つけることに帰着します$n$そのような$\binom{n+k-1}{k-1} \ge m$。 

入力サイズが十分大きいため、$n$は非常に大きくなる可能性があり、二項係数はすぐに巨大になります。 単純な階乗ベースの計算は不可能です。 直接の反復でも$n$遅すぎるので$n$周りまで届く$10^{18}$検索スペースで。 

主な困難は、組み合わせ論そのものではなく、大きな二項係数を効率的に評価し、オーバーフローせずにしきい値を検索することです。 

次の場合に 1 つのエッジ ケースが発生します。$k = 1$。 その場合、あらゆるものを表現する方法は正確に 1 つあります。$n$、だから、もし$m > 1$そうでない場合、解決策は存在しません$n = 0$すでに働いています$m = 1$。 もう一つのエッジケースは、$m = 1$、 どこ$n = 0$の合計としてゼロを書き込む方法は 1 つだけであるため、常に有効です。$k$負ではない整数。 

それぞれの構成をすべて列挙する素朴なアプローチ$n$コンポジションの数は組み合わせ的に増加し、非常に急速に膨大になるため、小さな値であってもすぐに失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 それぞれについて$n$の数を計算します。$k$-タプルの合計$n$、カウントが到達したら停止します$m$。 概念的には正しいですが、これにはすべての項目について二項係数を評価する必要があります。$n$、各評価には大きな中間値が含まれます。 たとえ乗算の公式を使ったとしても、それぞれの計算を最初から行うのは$n$最悪の場合の複雑さは次のとおりです。$O(n \cdot k)$、次の場合は不可能です$n$到達できる$10^{18}$。 

重要な観察点は、関数が$$f(n) = \binom{n+k-1}{k-1}$$は単調です$n$。 増加中$n$作曲の数が増えるだけです。 これにより、バイナリ検索が可能になります$n$、単調述語が true になる最小値を探しているためです。 

残りのタスクは、効率的な評価です。$\binom{n+k-1}{k-1}$大きな値の下では。 階乗の代わりに、乗算的に計算します。$$\binom{N}{r} = \prod_{i=1}^{r} \frac{N - r + i}{i}$$と$N = n + k - 1$そして$r = k - 1$。 走行値を超え次第早期停止$m$、しきい値を超える正確な値は二分探索の決定には無関係であるためです。 

また、比較前のオーバーフローを避けるために、128 ビット演算を使用して中間値に上限を設けます。

 ## アルゴリズムのチュートリアル

 1. 些細なケースを最初に処理します。 もし$m = 1$、最小の有効な合計は次のとおりです。$n = 0$なぜなら、ゼロを分割する方法は常に 1 つだけだからです。$k$部品。 
2. もし$k = 1$、すべての非負$n$には表現が 1 つだけあります。 もし$m > 1$、 いいえ$n$条件を満たすことができるので、答えは$-1$。 
3. 二分探索範囲を設定します。$n$から$0$などの十分に大きな上限まで$10^{18}$。 二項係数は非常に速く増加するため、この境界はすべての意味のある答えを安全にカバーします。 
4. 候補者にとって$n$、計算する$N = n + k - 1$そして$r = k - 1$、評価します$\binom{N}{r}$乗算公式を使用します。 これにより階乗計算が回避され、数値が管理しやすくなります。 
5. 積を計算するときに、項ごとに乗算し、各乗算の後に値が到達したか、超えているかを確認します。$m$。 そうなっている場合は、早めに停止し、その値を十分なものとして扱います。 これにより、オーバーフローや不要な作業が防止されます。 
6. 計算された値が少なくとも$m$、二分探索の右境界を に移動します。$n$。 それ以外の場合は、左側の境界を次の位置に移動します。$n + 1$。 
7. 二分探索が終了したら、結果が次のとおりであるかどうかを確認します。$n$実際に条件を満たしています。 そうでない場合は、返品してください$-1$。 

正しさは単調性、つまり増加にかかっています。$n$構成の数が増えるため、述語「$\binom{n+k-1}{k-1} \ge m$” は単一の境界で false から true に遷移します。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def ncr_at_least(n, r, limit):
    if r < 0 or r > n:
        return 0
    if r > n - r:
        r = n - r

    res = 1
    for i in range(1, r + 1):
        res *= n - r + i
        if res >= limit:
            return limit
        res //= i
    return res

def count_ways(n, k, m):
    N = n + k - 1
    r = k - 1
    return ncr_at_least(N, r, m)

def solve():
    k, m = map(int, input().split())

    if m == 1:
        print(0)
        return
    if k == 1:
        print(-1)
        return

    lo, hi = 0, 10**18
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if count_ways(mid, k, m) >= m:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```コアの実装は、しきい値を超えるとすぐに停止する安全な二項係数評価器に依存しています。$m$に達します。 除算は乗算の直後に行われ、Python の大きな整数が大きくなりすぎる前でも、実際のオーバーフローを回避できるように中間値を十分に小さく保ちます。 二分探索では、以下のすべての値が一致するという不変条件が維持されます。`lo`無効であり、すべての値がそれ以上である`ans`が有効な候補です。 

特殊なケース$m = 1$そして$k = 1$二項式が不必要か誤解を招くような退化的な動作を避けてください。
