 ## 解決策
 ## 問題の理解

 整数配列が与えられたので、そのすべての連続したセグメントを調べたいと思います。 セグメントごとに、そのセグメント内のすべての要素の最大公約数を計算します。 GCD が素数であることが判明したすべてのセグメントの中で、可能な最大長を見つけるように求められます。 素数 GCD を持つセグメントがない場合、答えは -1 です。 

キー オブジェクトはサブ配列 GCD です。 部分配列はその左右の端点によって完全に決定され、その値はその内部のすべての要素の GCD です。 タスクは、そのようなサブ配列がいくつ存在するかを数えることではなく、GCD が素数であるサブ配列の間で長さを最大化することだけです。 

制約 (このクラスの問題では一般的で、n が約 10^5 まで、値が約 2・10^5 まで) により、すべての O(n²) 部分配列を明示的にチェックすることが直ちに除外されます。 各 GCD 計算自体には少なくとも対数時間がかかるため、総当たりの列挙は許容範囲をはるかに超えます。 

いくつかの特殊なケースは、見た目よりも重要です。 

すべての要素が 1 の場合、すべての部分配列には GCD 1 があり、これは素数ではないため、答えは -1 でなければなりません。 素数フィルタリングを行わずに GCD 等価条件のみをチェックする単純な実装では、誤って n が返される可能性があります。 

配列に、GCD をすぐに 1 に下げる数値で囲まれた単一の素数要素が含まれている場合、単一要素の部分配列が許可され、その GCD が要素自体に等しいため、最良の答えは 1 になる可能性があります。 

すべての要素が同じ素数 p である場合、すべての部分配列は GCD p を持つため、答えは n になります。 これは、サブ配列を拡張しても GCD が素数から変化しないという特殊なケースです。 

## アプローチ

 最も直接的なアプローチは、考えられるすべての部分配列を考慮し、その GCD を計算し、それが素数であるかどうかを確認することです。 これは概念的には単純で正しいです。 左のエンドポイント i ごとに、実行中の GCD を維持しながら、j を i から n に拡張します。 GCD 演算のため各拡張のコストは O(log A) であり、O(n²) 個の部分配列があります。 これにより、おおよそ O(n² log A) が得られますが、n が大きい場合は遅すぎます。 

これが冗長になる理由は、セグメントを拡張するときに GCD 関数が強い単調な動作をするためです。 サブ配列を右に拡張すると、GCD は同じままか減少することしかできません。 決して増えることはありません。 これは、左側の終点が固定されている場合、右方向に拡張するにつれて GCD 値のシーケンスが減少チェーンを形成し、すぐに安定することを意味します。 

重要な構造的事実は、固定された右端点の場合、その位置で終わるすべてのサブアレイ中に異なる GCD 値が O(log A) しか存在しないということです。 これは、GCD が変化するたびに、前の値を除算する値まで低下する必要があり、そのような低下の数は値の大きさが対数であるために発生します。 

これにより、ある位置で終わるすべてのサブ配列を代表的な GCD 状態の小さなセットに圧縮することができます。 スクラッチから再計算する代わりに、これらの状態を前方に伝播し、進行するにつれて同一の GCD をマージします。 これは、対数サブ配列アグリゲーター トリックの背後にある考え方であり、各位置に、そこで終わるすべてのサブ配列の個別の GCD が格納されます。 

これらの圧縮状態を取得すると、素数 GCD のチェックが簡単になります。 位置ごとに少数の候補のみを評価し、有効な素数 GCD が現れるたびに最適な長さを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log A) | お(1) | 遅すぎる |
 | スパーステーブル + 二分探索 | O(n log² n) | O(n log n) | 承認済み |
 | GCD 状態圧縮 (LSA トリック) | O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、インデックス r ごとに、r で終わる部分配列のすべての個別の GCD 値の圧縮リストと、そのような部分配列の可能な限り最適な長さを維持するという考えを使用します。

1. ふるいを使用して、可能な最大値まですべての素数を事前計算します。 これが必要なのは、GCD を計算した後、それが素数であるかどうかをすぐに確認する必要があるためです。 
2. 構造体 cur を空のリストとして初期化します。 これは、現在のインデックスで終わるサブ配列のすべての個別の GCD 状態を表します。 
3. 配列を左から右に繰り返します。 各位置 r で、r で終わるすべての GCD 状態を格納する新しいリスト nxt を開始します。 
4. まず、r で終わる単一要素のサブ配列を挿入します。これにより、長さ 1 の a[r] に等しい GCD が得られます。これにより、常に現在の位置から始まるサブ配列を考慮することが保証されます。 
5. cur 内のすべてのペア (g, len) について、new_g = gcd(g, a[r]) および new_len = len + 1 を計算します。これを nxt に挿入し、最大長を維持して同じ gcd を生成するエントリをマージします。 このステップでは、前のサブ配列を 1 要素分拡張したすべてのサブ配列を構築します。 
6. 以前のすべての状態を処理した後、nxt には、r で終わるサブ配列のすべての個別の GCD 値が含まれます。各値は、このエンドポイントでの GCD の可能な限り最適な長さを持ちます。 
7. nxt 内のすべての (g, len) について、g が素数の場合、答えを len で更新します。 これにより、r で終わるすべての有効な候補がチェックされます。 
8. cur を nxt に置き換えて、次のインデックスに進みます。 
9. すべての位置を処理した後、有効なセグメントが見つからなかった場合は -1 を返し、それ以外の場合は記録された最大長を返します。 

これが機能する理由は、r で終わるすべてのサブ配列が、cur または新しく作成されたシングルトン状態の GCD 状態の 1 つで表現されるためです。 r で終わるサブ配列はすべて r で始まるか、r-1 で終わるサブ配列を拡張するため、すべての可能性が帰納的にカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n + 1)
    if n >= 0:
        is_prime[0] = False
    if n >= 1:
        is_prime[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_prime[j] = False
    return is_prime

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    maxA = max(a)
    is_prime = sieve(maxA)

    cur = []
    ans = 0

    for x in a:
        nxt = []

        def add(g, length):
            for i, (gg, ll) in enumerate(nxt):
                if gg == g:
                    if length > ll:
                        nxt[i] = (g, length)
                    return
            nxt.append((g, length))

        add(x, 1)

        for g, length in cur:
            ng = gcd(g, x)
            add(ng, length + 1)

        for g, length in nxt:
            if g <= maxA and is_prime[g]:
                if length > ans:
                    ans = length

        cur = nxt

    print(ans if ans > 0 else -1)

if __name__ == "__main__":
    solve()
```ふるいは、各 GCD 計算後の定数時間の素数チェックを可能にするために使用されます。 動的プログラミングの状態は次の場所に保存されます。`cur`、前の位置で終わるサブ配列のすべての個別の GCD を保持します。 

ヘルパー関数`add`重複した GCD 値を保持しないようにします。`nxt`。 同じ GCD が異なる拡張子を介して複数回出現する場合、対応する最長の部分配列のみが保持されます。 

遷移ステップが核心です。以前のすべての状態が現在の要素で拡張され、シングルトン サブ配列が個別に追加されます。 これにより、各インデックスで終わるすべてのサブ配列の完全性が保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての要素が 1 である場合です。この場合、すべての GCD 状態はすぐに 1 に崩壊し、答えの更新は行われません。 プライム チェックに合格しないため、アルゴリズムは正しく -1 を返します。 

別のケースは、次のような長い均一素数配列です。`[5, 5, 5, 5]`。 ここでは、状態が分岐することはなく、GCD はすべての拡張に対して 5 のままです。 DP はすべてを単一の状態に圧縮し、直線的に増加させます。その結果、答えは全長になります。 

3 番目のケースは、素数が互いに素数でインターリーブされている場合です。たとえば、`[6, 10, 15, 7]`。 互換性のない要素が結合されると、GCD 状態はすぐに 1 に縮小され、無効な長いセグメントがカウントされなくなります。
