 ## 解決策
 ## 問題の理解

 各セルに負でない整数が含まれる長方形のグリッドが与えられます。 各行から、要素を 1 つだけ選択する必要があります。 行ごとに 1 つの数値を選択した後、選択したすべての値のビット単位の AND を計算します。 タスクは、最終的な AND 結果が厳密に正になるように、そのような値を選択する方法が少なくとも 1 つ存在するかどうかを判断することです。 

ビット単位の AND は、選択されたすべての数値が 1 であるビット位置が少なくとも 1 つある場合に正になります。したがって、問題は実際には、選択されたすべての行要素で同時に共通にできるビットを見つけることができるかどうかです。 

グリッドが大きくなり、行ごとに 1 つの要素のすべての組み合わせを試すことが不可能になる場合があります。 N 行と M 列がある場合、総当たりアプローチでは M^N 個の選択をチェックする必要がありますが、これは指数関数的に増加し、N = 20、M = 20 のような中程度の値であっても実行不可能です。 

入力の構造から、正確な数値ではなく、行ごとのビットレベルの可用性のみを考慮していることがわかります。 各行は、その行内の少なくとも 1 つの要素によって潜在的に供給できるビットのセットに寄与します。 

主要なエッジ ケースは、ビットが各行のどこかに出現するが、行全体の同じ列インデックスには存在しない場合に発生します。 たとえば、次のことを考えてみましょう。 

行 1: 2 (010)、1 (001)

 行 2: 4 (100)、1 (001)

 各行にはビット 0 (値 1) が含まれているため、有効な選択が存在します。両方の行から 1 を選択します。 答えは「はい」です。 

しかし、代わりに次のようなことがあったとしたら:

 行 1: 2 (010)

 行 2: 4 (100)

 両方の行に共通する単一のビットはないため、選択に関係なく、AND は 0 になります。 

これは、問題が値の直接比較ではなく、行ごとのビット可用性の交差に関するものであることを示しています。 

## アプローチ

 ブルートフォースの考え方は単純です。行ごとに 1 つの要素を列挙し、AND を計算して、それがゼロ以外であるかどうかを確認します。 これは、有効な選択をすべて調査するため、正しいです。 ただし、各行には M 個の選択肢があるため、組み合わせの総数は M^N になります。 N = 10 および M = 10 の場合でも、これはすでに 10^10 の可能性に達しており、実現可能な限界をはるかに超えています。 

重要な観察は、AND の結果が、選択されたすべての数値にどのビット位置が存在するかによって完全に決定されるということです。 個々の選択について推論する代わりに、問題を再構成できます。すべての行にそのビットを含む数値が少なくとも 1 つあるようなビットが存在するかどうかを知る必要があります。 

これにより、行ごとのビット可用性の問題が軽減されます。 各行について、OR を使用して、その行の任意の数値に現れるすべてのビットを表すビットマスクを計算します。 次に、これらのマスクの AND を計算して、すべての行に共通するビットを確認します。 最終交差マスクがゼロ以外の場合、各行で少なくとも 1 ビットを保持できます。つまり、最終 AND でそのビットを保持する値を選択できます。 

別の観点は、各ビットを個別にテストすることです。 各ビット位置について、すべての行にそのビットが設定された数値が少なくとも 1 つ含まれているかどうかを確認します。 いずれかのビットがこの条件を満たす場合、有効な選択が存在することがすぐにわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(M^N・N) | O(N) | 遅すぎる |
 | 行 OR + グローバル AND | O(NM) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 行ごとにビットマスクを格納するように配列または変数を初期化します。 最初はビットが記録されないため、各マスクは 0 から始まります。 
2. 各行について、すべての M 値をスキャンし、ビットごとの OR を使用して行マスクを更新します。 これにより、その行の少なくとも 1 つの要素に出現するすべてのビットがキャプチャされます。 
3. すべてのビットセット (または最初の行マスク) に初期化されたグローバル マスクを維持します。 各行を処理した後、現在の行マスクとビット単位の AND を使用して行を更新します。 このステップでは、処理されたすべての行にわたってまだ可能なビットのみが保持されます。 
4. すべての行を処理した後、グローバル マスクがゼロ以外であるかどうかを確認します。 ゼロ以外の場合は、YES を出力します。 それ以外の場合は NO を出力します。 

行単位の OR マスクを作成する理由は、どの特定の要素がビットを提供するかではなく、ビットが行内で使用可能かどうかのみを考慮するためです。 行間の AND により、すべての行で生き残るビットのみが保持されます。 

### なぜ効果があるのか

 任意のビット位置 b について、その行にビット b が設定された要素が少なくとも 1 つ存在する場合、アルゴリズムは行マスクに b を正確に保存します。 すべての行に対して AND 演算を行った後、各行にそのビットを含む要素が少なくとも 1 つある場合に限り、最終マスクにビットが残ります。 これはまさに、選択されたすべての要素がそのビットを共有し、最終的な AND が正であることを保証するように、行ごとに 1 つの要素を選択するために必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    global_mask = (1 << 60) - 1  # large enough for constraints
    
    for _ in range(n):
        row_mask = 0
        row = list(map(int, input().split()))
        for x in row:
            row_mask |= x
        global_mask &= row_mask
    
    print("YES" if global_mask != 0 else "NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、各行を読み取り、単一のビットマスクに圧縮し、ビットごとの AND を使用してすべての行マスクを交差させます。 の初期化`global_mask`すべてのビットを設定すると、最初の行が可能なビットの開始セットを正しく定義するようになります。 

微妙な点は、実際に選択された要素を追跡する必要がないことです。 OR ステップは各行を利用可能なビット空間に抽象化し、AND ステップは行間の一貫性を強制します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各要素は行マスクを構築するために 1 回処理されます。 
| スペース | O(N) | 行ごとのストレージまたはストリーミング マスクのみが必要です。 

このアルゴリズムは、N と M の合計要素が最大 10^5 である一般的な制約に対して効率的です。 ビット操作は要素ごとに一定時間であるため、ソリューションは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, sys.stdin.readline().split())
    global_mask = (1 << 60) - 1
    
    for _ in range(n):
        row = list(map(int, sys.stdin.readline().split()))
        row_mask = 0
        for x in row:
            row_mask |= x
        global_mask &= row_mask
    
    return "YES\n" if global_mask != 0 else "NO\n"

# provided samples
assert run("2 3\n1 2 4\n4 8 1\n") == "YES\n"

# all zeros case
assert run("2 2\n0 0\n0 0\n") == "NO\n"

# single row
assert run("1 3\n1 2 4\n") == "YES\n"

# disjoint bits across rows
assert run("2 2\n1 2\n4 8\n") == "NO\n"

# full overlap via one bit
assert run("3 2\n1 0\n1 2\n5 1\n") == "YES\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 2 / 0 0 / 0 0 | いいえ | すべてゼロでは、正の AND | を生成できません。 
| 1 3 / 1 2 4 | はい | 数値が正の場合、単一行は常に機能します。 
| 2 2 / 1 2 / 4 8 | いいえ | 行全体で互いに素なビットセット |
 | 3 2 / 1 0 / 1 2 / 5 1 | はい | ビット 0 までの交差が存在します |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、行にゼロのみが含まれる場合です。 例えば：```
2 2
0 0
0 0
```各行マスクは 0 になるため、グローバル マスクはすぐに 0 になります。 アルゴリズムは NO を出力します。どの選択も正の AND を生成できないため、これは正しいです。 

もう 1 つのケースは単一行です。```
1 3
1 2 4
```行マスクは非ゼロであり、ビットを削除する 2 番目の行がないため、グローバル マスクは非ゼロのままです。 答えは「YES」です。任意の正の数値を選択でき、単一要素に対する AND はそれ自体であるためです。 

より微妙なケースは、素のビット分布です。```
2 2
1 2
4 8
```行マスクは 3 と 12 で、それらの交差は 0 です。各行に有効なビットが含まれている場合でも、両方の行にビットが表示されないため、最終的な AND でビットを保持できる選択はありません。
