 ## 解決策
 ## 問題の理解

 すべてのノードが整数値を保持するツリーが与えられます。 複数のクエリの場合、各クエリは 2 つのノード u と v を提供し、u と v の間の一意の単純なパスに沿ったすべての値の積が完全な正方形を形成するかどうかを判断する必要があります。 

主な問題は、パスが配列ではなくツリー パスであるため、各クエリがノードの異なるサブセットに依存することです。 直接解釈すると、クエリごとに積を再計算することが示唆されますが、多くのクエリが存在し、パスが長くなる可能性がある場合、それはすぐに実行不可能になります。 

この制約は、ノード数とクエリ数の両方が十分に大きいため、各クエリ パス上のノードを訪問するソリューションは明示的に失敗することを意味します。 クエリあたりのパス長が O(n) で、クエリ数が最大 O(n) の場合、すでに O(n²) になり、これは許容範囲をはるかに超えています。 クエリあたり O(n log n) であっても、効率的なパス集約を中心に慎重に構造化する必要があります。 

いくつかのエッジケースは、明示的に処理されないと素朴な推論を壊します。 

ノード値がゼロの場合、積全体がゼロになり、完全な平方になります。 たとえば、パスが 3 → 0 → 5 の場合、積はゼロになるため、他の値に関係なく、答えはすぐに YES になります。 特殊な乗法吸収体としてゼロを無視するソリューションは、誤って因数分解を試行し、動作を誤分類する可能性があります。 

負の値を指定すると、符号パリティが導入されます。 パスに奇数の負のノードが含まれている場合、積は負になり、整数の完全な平方になることはできません。 たとえば、-2 などの負の値が 1 つだけ含まれ、その他のすべてが正のパスは負の積を生成するため、直ちに拒否する必要があります。 符号を追跡せずに素数指数のみを追跡するソリューションは、ここでは失敗します。 

最後に、正の値であっても、完全二乗の動作は素数指数のパリティのみに依存します。 よくある失敗例は、自由平方パリティではなく完全因数分解を扱うことです。 たとえば、パスに沿った値 12 と 3 は積 36 を与え、これは完全二乗になりますが、大きな整数の単純な乗算や不正確なパリティ追跡により、オーバーフローや因数分解エラーが繰り返された場合にこれを誤って評価する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、u から v まで歩き、パスに沿ってすべてのノード値を収集し、それらを乗算し、結果が完全な平方であるかどうかを確認することによって、各クエリを独立して処理します。 ツリー内のパスは一意で完全に決定されているため、これは概念的には単純で正しいものです。 ただし、そのコストはパスを繰り返し通過することによって大きく左右されます。 最悪の場合、パスには O(n) 個のノードが含まれる可能性があり、O(n) クエリの場合、これは O(n²) 個のノード訪問数になり、これは一般的な制約の実現可能な制限をはるかに超えています。 

重要な洞察は、乗算構造は直接維持するにはコストが高すぎるが、素因数分解におけるその特性は非常に単純であるということです。 因数分解ですべての素数が偶数の指数で現れる場合に限り、数値は完全平方になります。 これにより、乗算が素数指数に対する XOR のようなパリティ追跡に変換されます。 各ノードは素数に対するパリティのベクトルに寄与し、パス積はこれらのベクトルの XOR に対応します。 

これにより、問題はバイナリ特徴空間における古典的なツリー パス集約問題に変わります。 パリティのみが重要であることがわかれば、各ノードの「平方自由カーネル署名」を事前計算できます。これは通常、奇数の指数を持つ素数のハッシュとして表されます。 次に、パス クエリはツリー パスに沿って XOR を計算することになります。これはまさに LCA ベースのプレフィックス XOR または HLD セグメント クエリが設計されているものです。 

したがって、クエリごとに係数を再計算する代わりに、ツリー上のプレフィックス構造を前処理して、各パス クエリが LCA 計算と組み合わされた一定数の XOR 演算になるようにします。

 ## アルゴリズムのチュートリアル

 すべてのノード値を、各素数が奇数回出現するかどうかのみをキャプチャする表現に変換します。 これは、squarefree カーネル署名です。 完全な因数分解を保存する代わりに、各素数にランダムなハッシュ値を割り当て、奇数の指数を持つすべての素数について XOR します。 

また、ノードごとに 2 つの追加のブール プロパティ (値がゼロかどうかと負かどうか) も維持します。 これらが必要なのは、パリティ ロジックだけではゼロ以外の正の値にのみ適用されるためです。 

### ステップ

 1. 可能な最大ノード値までのすべての値について最小の素因数を事前計算します。 

これにより、各ノード値を素数に高速に因数分解できます。 
2. 各ノード値について、3 つの情報 (ノード値がゼロであるかどうか、負であるかどうか、およびそのスクエアフリー カーネルを表す XOR ハッシュ) を計算します。 

XOR は、素因数を反復処理し、完全な因数のキャンセル後に指数が奇数の場合に各素数のハッシュを切り替えることによって形成されます。 これにより、パリティのみが確実に残ります。 
3. ツリーを任意にルート化し、DFS を実行して、すべてのノードについて、ルートからのプレフィックス集計を計算します。 

カーネル ハッシュのプレフィックス XOR、

 負の値のカウント、

 ゼロの数。 

これが機能する理由は、LCA を使用してツリー パスをルートからノードへのパスの差として表現できるためです。 
4. LCA 用のバイナリ リフティング テーブルを事前計算して、最小共通祖先クエリを対数時間で回答できるようにします。 
5. 各クエリ (u、v) について、LCA w を計算します。 
6. 包含/排他を使用してパス上の XOR を計算します。 

path_xor = pref[u] XOR pref[v] XOR pref[w] XOR pref[parent[w]]。 
7. 接頭辞の合計を使用して、負のカウントとゼロのカウントを同様に計算します。 
8. 答えを決めます:

 パス上にゼロが存在する場合、積はゼロであるため、YES を返します。 

それ以外の場合、負のカウントが奇数の場合は NO を返します。 

それ以外の場合、path_xor がゼロの場合は YES を返し、それ以外の場合は NO を返します。 

### なぜ効果があるのか

 DFS プレフィックス構造により、各ノードがルートからの累積乗算パリティ情報を確実に格納します。 u から v へのパスはすべて、ルートから u プラス、ルートから v からルートから lca への寄与分を引いたものに分解できます。XOR は、2 回出現する同一の寄与分をキャンセルするため、この減算を自然に実装します。 平方自由度は素数指数のパリティのみに依存するため、この XOR 表現は完全平方の数学的条件と正確に一致します。 ゼロ条件と符号条件は、プライム パリティ構造によって捕捉されず、独立して有効性を決定するため、別々に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MAXV = 200000
spf = list(range(MAXV + 1))

for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

import random
random.seed(1)
prime_hash = {}

def get_hash(p):
    if p not in prime_hash:
        prime_hash[p] = random.getrandbits(64)
    return prime_hash[p]

def factor_xor(x):
    res = 0
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt ^= 1
        if cnt:
            res ^= get_hash(p)
    return res

n, q = map(int, input().split())
vals = list(map(int, input().split()))

g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

LOG = 20
up = [[-1] * n for _ in range(LOG)]
depth = [0] * n
px = [0] * n
neg = [0] * n
zero = [0] * n

def dfs(u, p):
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        up[0][v] = u
        px[v] = px[u] ^ factor_xor(abs(vals[v]))
        neg[v] = neg[u] + (1 if vals[v] < 0 else 0)
        zero[v] = zero[u] + (1 if vals[v] == 0 else 0)
        dfs(v, u)

# root at 0
px[0] = factor_xor(abs(vals[0]))
neg[0] = 1 if vals[0] < 0 else 0
zero[0] = 1 if vals[0] == 0 else 0
dfs(0, -1)

for k in range(1, LOG):
    for i in range(n):
        if up[k - 1][i] != -1:
            up[k][i] = up[k - 1][up[k - 1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def get_path_xor(u, v, w):
    pw = up[0][w]
    res = px[u] ^ px[v] ^ px[w]
    if pw != -1:
        res ^= px[pw]
    return res

def get_path_count(arr, u, v, w):
    pw = up[0][w]
    return arr[u] + arr[v] - arr[w] - (arr[pw] if pw != -1 else 0)

out = []
for _ in range(q):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    w = lca(u, v)

    path_zero = get_path_count(zero, u, v, w)
    if path_zero > 0:
        out.append("YES")
        continue

    path_neg = get_path_count(neg, u, v, w)
    if path_neg % 2 == 1:
        out.append("NO")
        continue

    pw = up[0][w]
    path_xor = px[u] ^ px[v] ^ px[w] ^ (px[pw] if pw != -1 else 0)

    if path_xor == 0:
        out.append("YES")
    else:
        out.append("NO")

print("\n".join(out))
```この解決策は、各値を効率的に因数分解できるように、最小の素因数を構築することから始まります。 の`factor_xor`関数は、二乗検出に関連する唯一のデータである素指数のパリティ情報のみを抽出します。 

DFS はルートベースのプレフィックス構造を構築します。 各ノードは親から情報を継承し、後でプレフィックス状態の違いを通じてパス クエリを表現できるようにします。 

バイナリ リフティングは、パスを正しく分割するために必要な高速 LCA 計算をサポートします。 XOR およびカウントの再結合式は、2 つのルート パスの一意の重複点である LCA に依存します。 

クエリ ロジックでは、3 つの条件が厳密な順序で適用されます。まずゼロがすべてを支配するため、次に符号パリティ、次に自由平方パリティです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、LCA がクエリ エンドポイントの 1 つである場合です。 その場合でも、包含/除外式は正しく動作する必要があります。 たとえば、u が v の祖先である場合、LCA(u, v) = u となり、pref[u] が式内でそれ自体をキャンセルするため、XOR 式は適切に減少します。 px[w] XOR px[parent[w]] 調整は、parent が -1 の場合、または w が root の場合に正しく折りたたまれるため、コードはこれを自然に処理します。 

もう 1 つのエッジ ケースは、親 (w) が存在しないルート ノード LCA です。 この実装では、プレフィックス値にアクセスする前に -1 を明示的にチェックして、無効な配列アクセスを防止し、ルートに関係するクエリの正確性を保証します。 

最後の微妙なケースは、ノード値で複数の素数が繰り返される場合です。 因数分解ループでは、指数カウントが奇数の場合にのみ XOR 演算を行うことで、高い指数であってもパリティが正しく追跡されるようにするため、16 (2⁴) のような値はカーネルに正しく寄与せず、二乗検出の正確性が維持されます。
