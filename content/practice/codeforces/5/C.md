 ## 問題の理解

 のみで構成される文字列が与えられます。`(`そして`)`。 すべての連続する部分文字列の中で、有効な括弧シーケンスを形成する部分文字列の最大長を見つける必要があります。 また、その最大長に達する部分文字列の数をカウントする必要もあります。 

有効な括弧シーケンスは、式内で正しく一致した括弧とまったく同じように動作します。 すべての左括弧は最終的に閉じる必要があり、どの接頭辞にも左括弧よりも多くの閉じ括弧を含めることはできません。 

入力できる長さは`10^6`、実現可能なことが完全に変わります。 すべての部分文字列をチェックするアルゴリズムは不可能です。 おおよそあります`n^2`部分文字列ごとに一定の時間を費やしたとしても、すでに実用的な制限を超えています。 制限時間は 2 秒なので、直線タイムに近いか、最悪の場合でもタイムを目標にする必要があります。`O(n log n)`。 

厄介な点は、最長の有効な部分文字列が、一致する 2 つの括弧の間の有効な領域全体であるとは限らないことです。 無効な文字を使用すると、文字列が独立したセグメントに分割される可能性があります。 例えば：```
())(())
```正しい答えは次のとおりです。```

```部分文字列`(())`は有効ですが、プレフィックス`())(`シーケンスを壊します。 一致したペアのみをカウントする不注意な実装により、誤って長さが返される可能性がありました`6`。 

もう 1 つの簡単な間違いは、最長の部分文字列が複数ある場合に発生します。```
()()(()())
```正しい答えは次のとおりです。```
10 1
```文字列全体は有効ですが、その中に小さな有効な部分も存在します。 最大値を適切に追跡せずに、すべての有効なセグメントを個別にカウントすると、オーバーカウントになる可能性があります。 

特に重要なエッジ ケースは、有効な部分文字列がまったく存在しない場合です。```
))))
```出力は次のようになります。```
0 1
```カウントは`1`、 ない`0`。 この問題は、この特別な動作を明示的に定義します。 

もう 1 つの微妙なケースには、同じサイズの有効な領域が切断されていることが含まれます。```

4 1

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての部分文字列を生成し、それが有効な括弧シーケンスを形成しているかどうかを確認します。 有効性はバランスカウンターを使用してテストできます。`(`、の減少`)`、残高が決してマイナスになってゼロで終わることがないようにします。 

すべての有効な括弧シーケンスがこれらの条件を満たすため、これは論理的に機能します。 問題はコストです。 がある`O(n^2)`部分文字列。 たとえ有効性チェックが最適化されていても、`O(length)`、全体の複雑さは次のようになります。`O(n^3)`。 と`n = 10^6`、これは天文学的に遅すぎます。 

プレフィックスバランスを使用して妥当性テストを改善することはできますが、すべての部分文字列を列挙する余裕はまだありません。 平`O(n^2)`この規模では不可能です。 

重要な観察は、有効な括弧の部分文字列がローカルで動作するということです。 右括弧に遭遇したときは、その前に一致しない左括弧が存在するかどうかだけを気にします。 これは当然スタックを示唆します。 

スタックには、一致しない開始括弧のインデックスが格納されます。 見ると`(`、そのインデックスをプッシュします。 見ると`)`、最新の一致しないものと一致させようとします`(`。 

より深い洞察は、部分文字列の長さを効率的に回復する方法です。 位置を仮定します`i`有効なシーケンスを閉じます。 次に、次で終わる最長の有効な部分文字列`i`は、その前に最も近い一致しない括弧の直後から始まります。 最新の不一致位置のインデックスをスタック上に保持すると、一定時間で長さを計算できます。 

これにより、問題は、すべての部分文字列を個別にチェックすることから、文字列を左から右に 1 回ずつ処理することに変換されます。

 ## アルゴリズムのチュートリアル

 1. スタックを単一の値で初期化する`-1`。 

これは見張り役として機能します。 文字列が始まる前の位置を表し、インデックスから始まる有効な部分文字列を許可します。`0`正しく測定されること。 
2. 2 つの変数を維持します。`best_len`、これまでに見つかった有効な部分文字列の最大長。`count`、その長さに達する部分文字列の数。 
3. 文字列を左から右にトラバースします。 
4. 現在のキャラクターが`(`、そのインデックスをスタックにプッシュします。 

これらのインデックスは、後で有効なペアを形成する可能性がある、一致しない開始括弧を表します。 
5. 現在のキャラクターが`)`、スタックから 1 つの要素をポップします。 

この閉じ括弧を最も近い一致しない開始括弧と一致させようとしています。 
6. ポップ後、スタックが空になったかどうかを確認します。 

空いていればこれ`)`一致させることはできません。 そのインデックスを無効の新しい境界としてスタックにプッシュします。 

今後の有効な部分文字列は、この位置の後に開始する必要があります。 
7. それ以外の場合、スタックにはまだインデックスが含まれています。 

現在のインデックスを次のようにします`i`。 で終わる有効な部分文字列の長さ`i`等しい:```
i - stack[-1]
```スタックの最上部は、有効なセグメントの前に最も近い不一致の位置をマークします。 
8. この長さを次のものと比較してください`best_len`。 

サイズが大きい場合は更新してください`best_len`そしてリセット`count = 1`。 

等しい場合はインクリメントします`count`。 
9. 文字列全体を処理した後、次のような特殊なケースを処理します。`best_len == 0`。 

必要な出力は次のようになります`0 1`。 

### なぜ効果があるのか

 スタックには常に、一致しない括弧のインデックスが格納されます。 加工後の位置`i`、スタックの先頭は、で終わる有効な部分文字列の拡張を妨げる最も近い位置を表します。`i`。

## Python ソリューション```python

s = input().strip()

    if ch == '(':
        stack.append(i)
    else:

import sys
import io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    stack = [-1]

    best_len = 0
    count = 0

    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        else:
            stack.pop()

            if not stack:
                stack.append(i)
            else:
                length = i - stack[-1]

                if length > best_len:
                    best_len = length
                    count = 1
                elif length == best_len:
                    count += 1

    if best_len == 0:
        print("0 1")
    else:
        print(best_len, count)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()
