 ## 解決策
 ## 問題の理解

 私たちは 4 次元の整数グリッドで作業しています。 宇宙船は原点から一連の動作を実行します。各動作は 4 つの座標軸の 1 つを選択し、いずれかの方向に 1 単位ずつ進みます。 

ここでの工夫は、命令リストの i 番目の手が 1 回ではなく i 回実行されることです。 したがって、k 個の動きのシーケンスを決定すると、実際の変位は、最初の動きが 1 回寄与し、2 番目の動きが 2 回寄与するというように、最大​​ k 回まで寄与する加重和になります。 

この 4D グリッド内の任意のターゲット ポイントについて、この加重実行ルールに基づいて正確な変位を生成するために必要な最小移動数として f(a, b, c, d) を定義します。 タスクは、原点を中心とし、辺の長さが A、B、C、D によって決定されるボックス内のすべての整数点にわたるこの最小長の合計を計算することです。 

主な難点は、各移動の重みが増加するため、後の移動がディスプレイスメントを支配することです。 これは、均一コスト グラフ内の単純な最短経路を扱っているのではなく、係数が三角数である構造化された数体系を扱っていることを意味します。 

制約により、各次元の絶対値は 1000 まで許可されます。 最悪の場合、点の総数は最大約 10^12 になる可能性があるため、点を列挙したり、点ごとに個別に f を計算したりすることさえ不可能です。 どのソリューションでも、すべてのポイントを共有のカウント構造に圧縮し、ディメンション間で作業を再利用する必要があります。 

素朴な解釈では、加重シーケンスに対して DP または BFS を使用して f(a, b, c, d) を独立して計算しようとします。 単一の評価でもコストがかかり、すべてのポイントに対して評価を行うのは現実的ではありません。 

微妙なエッジケースは原点と小さな座標です。 たとえば、(0, 0, 0, 0) の値は 0 ですが、(1, 0, 0, 0) や (2, 0, 0, 0) のような点は非常に少ない手で達成できますが、複数の次元が相互作用すると、貪欲な直感は失敗します。これは、大きな重み付けされたステップを使用して初期のオーバーシュートを「修正」できるためです。 

## アプローチ

 最初のアイデアは、プロセスを直接解釈することです。 各移動は次元と符号を選択​​し、ステップ i でその座標に i 単位を寄与します。 k 個の手を修正すると、各座標は、発生ごとに割り当てられた符号を持つ {1, 2, ..., k} の一部の合計になります。 

したがって、固定 k の場合、各座標は三角形構造の符号付きサブセット和として表現できます。 重要な観察は、同じステップ インデックスを共有することを除いて、座標が独立しているということです。 その結合がブルートフォースを爆発させるのです。 

ブルートフォース手法では、最大 k までのすべての一連の動きを反復し、重み付けされた効果をシミュレートし、最小 k で到達可能なポイントを記録します。 中程度の k の場合でも、ステップごとに 4 つの選択肢、つまり 8^k 通りの可能性があり、対称性による枝刈りさえ十分に役立ちません。 

構造的洞察とは、視点を逆転させることです。 動きから点を構築する代わりに、固定 k が達成可能な座標にどのような制約を課すかを尋ねます。 各次元に対して独立して、k ステップの後、各インデックス i に符号を割り当てるか、その次元に対してスキップすることができますが、すべてのインデックスはグローバルに 1 回だけ使用されるため、各次元は同じ重みセットの符号付き選択を受け取ります。 これにより、三角形ウェイト上の 4D ナップザックとして再解釈できる結合制約が作成されます。 

この問題群の標準的なトリックは、質問を、f(a, b, c, d) が k に正​​確に等しい点がいくつあるかを数えることに変換し、その層のサイズの k 倍を合計することです。 したがって、k 回の移動内で到達可能なポイントのセットと、それが k でどのように拡張されるかを理解する必要があります。

k 回の移動の場合、各座標は 1..k の達成可能な最大符号付き和 (k(k+1)/2) によって制限されます。 これにより層状構造が得られます。すべての点は成長する 4D ボックス内にあり、各層 k は新しい到達可能な点のシェルを追加します。 核となる縮小は、f(a, b, c, d) が最小の k に等しく、各座標が 1..k の符号付きサブセット和として表現可能となり、これらの制約が次元ごとに分離されることです。 

これにより、問題は、最小 k 個のしきい値にわたる古典的な多次元プレフィックス合計に変わります。 各座標 x について、|x| となるような最小 k を計算します。 ≤ k(k+1)/2。その区間内の任意の値に到達するように常に貪欲に符号を割り当てることができるからです。 したがって、f(a, b, c, d) は、個々の最小 k 要件の 4 つの座標にわたる最大値です。 

したがって、問題を、座標範囲ごとに、各 k に必要な整数の数を計算し、独立した分布の畳み込みを使用して 4D 積空間上で集計することに集約します。 

gA[k] (最小 k が正確に k である [-A, A] の整数の数)、および同様に B、C、D についても事前計算します。その後、最終的な答えは、各点が max(k1, k2, k3, k4) に寄与する 4 方向の畳み込みになります。 これは、「最大 k」の累積カウントに変換し、プレフィックスに対する包含を使用することで計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シーケンスの総当たり列挙 | O(8^k) | O(k) | 遅すぎる |
 | 階層化しきい値 + 1D 前処理 + 4D 集計 | O(A + B + C + D + K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各座標範囲 [-A, A] について、各整数 x を表すために必要な最小の k を計算します。 これは、|x| となるような最小の k を見つけることによって行われます。 ≤ k(k+1)/2。k 個の移動により、その区間内で任意の符号付き和を生成できるためです。 
2. これを周波数配列 cntA[k] に変換します。ここで、cntA[k] は、[-A, A] 内の正確に k を必要とする整数の数をカウントします。 B、C、D についても繰り返します。これにより、幾何学的拘束が「難易度レベル」にわたる離散分布に変換されます。 
3. 各 cnt 配列をプレフィックス形式 prefA[k] に変換します。これは、最大で k 個の移動が必要な値の数をカウントします。 これは、「最大座標」を補数で処理する方が簡単なため便利です。 
4. 固定 k の場合、k が固定されると座標は独立するため、f(a, b, c, d) ≤ k の 4D 点の数は積 prefA[k] × prefB[k] × prefC[k] × prefD[k] になります。 
5. 連続する値を差分することにより、「最大 k」個のカウントを「正確に k」個のレイヤーに変換します。 
6. 実行可能な最小 k がその値に等しい点の数を乗算した k を合計することによって、最終的な答えを累積します。 

正確さの背後にある重要な考え方は、各座標制約はその大きさのみに依存し、重み付き移動システムは正確に三角数の容量にまで縮小されるということです。 k が固定されると、すべての結合は個別のステップ割り当てではなく、共有境界 k のみを介して行われるため、座標は独立します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc(x):
    x = abs(x)
    k = 0
    # find smallest k with k(k+1)/2 >= x
    # binary search up to 2000 is enough
    lo, hi = 0, 2000
    while lo < hi:
        mid = (lo + hi) // 2
        if mid * (mid + 1) // 2 >= x:
            hi = mid
        else:
            lo = mid + 1
    return lo

def build(limit):
    cnt = {}
    for x in range(-limit, limit + 1):
        k = calc(x)
        cnt[k] = cnt.get(k, 0) + 1
    maxk = max(cnt)
    arr = [0] * (maxk + 1)
    for k, v in cnt.items():
        arr[k] = v
    return arr

def prefix(arr):
    res = [0] * len(arr)
    s = 0
    for i in range(len(arr)):
        s += arr[i]
        res[i] = s
    return res

def solve():
    A, B, C, D = map(int, input().split())

    a = build(A)
    b = build(B)
    c = build(C)
    d = build(D)

    K = max(len(a), len(b), len(c), len(d))
    a += [0] * (K - len(a))
    b += [0] * (K - len(b))
    c += [0] * (K - len(c))
    d += [0] * (K - len(d))

    pa = prefix(a)
    pb = prefix(b)
    pc = prefix(c)
    pd = prefix(d)

    ans = 0
    total = (2*A+1)*(2*B+1)*(2*C+1)*(2*D+1)

    prev = 0
    for k in range(K):
        ca = pa[k]
        cb = pb[k]
        cc = pc[k]
        cd = pd[k]
        cur = ca * cb * cc * cd
        exact = cur - prev
        ans += k * exact
        prev = cur

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、座標ごとに「難易度レイヤー」を構築し、プレフィックス プロダクトを通じてそれらをマージします。 重要な実装の詳細は、プレフィックスの積が正しく整列するように、すべての配列を同じ長さにパディングすることです。 2 番目の微妙な点は、自然な計算では f = k ではなく f ≤ k の点の数が得られるため、累積差分を使用して正確な層を復元することです。

 ## 特殊なケース

 元のケースは最も単純な境界です。 すべての座標がゼロの場合、すべての座標は k=0 を必要とするため、合計はゼロになります。 最初のレイヤーにはすでに正確に 1 つのポイントが含まれているため、プレフィックス構築によりこれが保証されます。 

1 つの次元だけがゼロ以外の場合、製品構造は単一の座標分布にきれいに崩壊します。 他の次元が定数 pref[0]=1 に寄与するため、アルゴリズムはこれを処理し、カウントを歪めることはありません。 

A、B、C、D が等しく大きい場合、k 層の成長は三角数のしきい値によって支配されます。 すべての座標が同一の分布を共有し、最大集計がプレフィックスの差によって暗黙的に処理されるため、プレフィックス積は依然として正しく動作します。 

遷移点は |x| です。 交差 k(k+1)/2 は calc の二分探索によって正確に処理されるため、完全な三角数であってもオフバイワンの曖昧さはありません。
