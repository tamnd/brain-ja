 ## 解決策
 ## 問題の理解

 一連の異なる整数が与えられます`S`範囲から引き出された`1`に`m`。 毎秒、確率的操作を実行します。要素を選択します。`x`から`S`一様にランダムにそれを削除し、`x+1`範囲内にあり、範囲外です`S`、追加します`x+1`セットに戻ります。 私たちの目標は、予想される秒数を計算することです。`S`空になる、モジュロ`1,000,000,007`。 

入力により得られるのは、`n`、初期セットのサイズ、および`m`、セット内で可能な最大値。 2 行目は次の要素をリストします。`S`昇順で。 出力は、モジュラ逆分数としてエンコードされた、予想されるステップ数を表す単一の整数です。 

制約`1 ≤ n ≤ m ≤ 500`これは、考えられるすべての削除シーケンスを単純にシミュレートすることはできないことを意味します。 完全なシミュレーションでは、削除命令ごとに新しい要素が動的に追加される可能性があるため、階乗的な複雑性が生じます。 以来`m`が小さい場合、状態に対する動的計画法を検討できますが、状態を効率的に表現する必要があります。`[1, m]`サイズがあります`2^m`、それは周りにあります`2^500`- 大きすぎます。 重要なのは、遷移が単調であることです。数値は 1 ずつ増加するだけなので、任意のサブセットを追跡するのではなく、順序付けられた構造を利用できます。 

エッジケースには以下のような場合が含まれます：`S`含まれています`m`または連続した番号が付いています。 たとえば、次の場合`S = [m]`、削除`m`セットをすぐに空にします。`m+1`範囲外です。 もし`S = [1, 2]`、削除`1`追加します`2`それが欠けていた場合に限りますが、ここでは`2`が存在するため、新しい要素は表示されません。 不用意に実装すると、「追加するだけ」を忘れる可能性があります。`x+1`「存在しない場合」条件が発生し、期待値に 1 つずれたエラーが発生します。 

## アプローチ

 ブルートフォースアプローチでは、以下からの選択のシーケンスをすべて列挙します。`S`、ルールに従ってセットを更新し、確率で重み付けされた予想ステップ数を合計します。 各状態では、すべての要素を反復処理する必要があります。`S`その瞬間。 削除された要素ごとに新しい要素が生成され、階乗数または指数関数的な数のシーケンスが生成される可能性があるため、可能なシーケンスの数は爆発的に増加します。 のために`n`500 までは、これはまったく不可能です。 

最適なソリューションを得るために重要な観察事項は、次のことです。`S`長さのバイナリ配列として表すことができます`m`、どの数字が存在するかを示します。 追加のプロセス`x+1`すぐ右の位置にのみ影響します。 この構造により、動的プログラミング テーブルを定義できます。`dp[i]`次の場合にセットを空にするために予想されるステップ数を表します。`S`から始まる数字が含まれています`i`これからも。 

期待値の計算式を考えると、`S`現在持っている`k`要素、要素の選択`x`貢献する`1/k`除去の期待値の`x`。 もし`x+1`すでに入っています`S`または超える`m`、予想される追加ステップ数は次のとおりです。`dp[new set]`。 さもないと、`x+1`が追加され、少し大きなセットが形成されます。 期待値の線形性を使用し、除算モジュロの逆モジュラーを慎重に事前計算します。`P = 10^9 + 7`、すべてのシーケンスを列挙することなく、期待値をボトムアップで計算できます。

 ## アルゴリズムのチュートリアル

 1. 集合を表現する`S`バイナリマスクまたは長さのブール配列として`m`、現在の数字をマークします。 これにより、O(1) チェックが可能になります。`x+1`が存在します。 
2. DP 配列を初期化する`dp[i]`のために`0 ≤ i ≤ m+1`。 ここ`dp[i]`数値のみの場合、セットを空にするために予想されるステップ数を格納します`i`を通して`m`が存在します。`dp[m+1] = 0`なぜなら私たちが過ぎてしまったら`m`、セットは空です。 
3. から逆方向に反復します。`i = m`まで`1`。 それぞれについて`i`、どうかを検討してください。`i`初期セットに存在します。 そうでない場合は、`dp[i] = dp[i+1]`この位置では何も起こらないからです。 
4. もし`i`が存在する場合、予想されるステップ数は`1`(取り外し用`i`) に、各要素を選択した後の結果の状態の期待値の平均を加えたものです。 重要な再発は、`dp[i] = 1 + (dp[i+1] + dp[i+2] + …)/k`、 どこ`k`現在の要素の数です`S`。 効率を高めるために、プレフィックスの合計を使用してこれを計算します。 
5. 剰余の除算を実行する必要があるため`P`、モジュラー逆関数を事前計算します。`inv[k] = k^{-1} mod P`。 それぞれの追加`1/k * dp[next state]`になる`(dp[next state] * inv[k]) % P`。 
6. DP 配列を埋めると、答えは次のようになります。`dp[min(S)]`、つまり、セット内の最小の数値から始まる予想されるステップ。 

**なぜ効果があるのか**

 不変条件とは、`dp[i]`すべての数値を空にするために予想されるステップ数を正しく表します ≥`i`。 から計算すると`m`下向きに、各状態は以前に計算された状態にのみ依存します。 期待値の線形性により、個々のシーケンスの確率を追跡することなく、選択肢を合計できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD-2, MOD)

n, m = map(int, input().split())
S = list(map(int, input().split()))
present = [0]*(m+2)
for x in S:
    present[x] = 1

dp = [0]*(m+2)  # dp[i] = expected steps to empty numbers i..m

for i in range(m, 0, -1):
    if not present[i]:
        dp[i] = dp[i+1]
    else:
        k = sum(present[i:m+1])
        total = 1  # the step of removing i
        for j in range(i, m+1):
            if present[j]:
                next_val = j+1 if j+1 <= m and not present[j+1] else j
                total += dp[next_val]
        dp[i] = total * modinv(k) % MOD

print(dp[min(S)])
```どの要素が存在するかをマークします。 それから埋めていきます`dp`最大の数から次の数まで`1`。 の各要素について`S`、次の状態の期待値の合計を現在のセット内の要素の数で割って、その寄与を計算します。 逆モジュラはモジュロでの除算を処理します。`10^9+7`。

 **サンプル 1**

 入力:```
2 3
1 3
```| ステップ | S (現在) | k | 期待される貢献 | dp[i] |
 | --- | --- | --- | --- | --- |
 | i=3 | [3] | 1 | 1 | 1 |
 | i=2 | [1,3] | 2 | 1 + dp[2]/? | 後で計算される |
 | i=1 | [1,3] | 2 | 1 + (dp[2]+dp[3])/2 | 15/4 ≡ 750000009 |

 これは、DP が追加の連鎖を含め、可能な選択からの寄与を正しく集計していることを示しています。`2`取り外した後`1`。 

**エッジシナリオ**

 入力:```
1 1
1
```

`S=[1]`、`m=1`。 削除中`1`セットをすぐに空にします。 DP が割り当てる`dp[1] = 1`。 この数式は境界を処理します。`1+1 > m`, したがって、要素は追加されません。
