 ## 問題の理解

 整数に対するビット制約を使用しており、範囲内でビットごとの固定条件を満たす数値がいくつあるかをカウントする必要があります。 The condition is that a number$x$指定されたマスクに設定されているすべてのビットが有効である場合$b$にも設定されています$x$。 言い換えると、$x$すべての 1 ビットを「含む」必要があります$b$、位置の値を自由に選択できますが、$b$はゼロです。 

タスクは範囲にわたるクエリに答えることです$[l, r]$、各クエリは整数の数を尋ねます。$x$その間隔内でこの制約を満たします。 標準的な削減は、接頭辞関数を計算することです$count(N)$、有効とみなします$x$で$[0, N]$、次に減算を使用して範囲を回答します。 

重要な難しさは数字の大きさにあります。 簡単な場合は、総当たりでも問題ありませんが、後のサブタスクがプッシュします。$l, r, b$組み込みの整数型に収まらなくなり、最大数万の 16 進数を含めることができる範囲に分割されます。 これにより、ビット長の二次関数や候補を列挙するものは即座に除外されます。 

素朴なアプローチでは、あらゆることを繰り返すことになります。$x$で$[l, r]$そしてチェックしてください$(x \& b) = b$。 これは正しいですが、すぐに不可能になります$r - l$大きく成長します。 2 番目の素朴な改善は、ビットよりも桁の DP です。これにより、問題が次のように軽減されます。$O(\text{number of bits})$ただし、数値が標準の整数制限を超える場合には注意が必要です。 

微妙だが重要なエッジケースが現れるのは、$l = 0$。 プレフィックスの減算が含まれるため、$count(l-1)$、off-by-one の処理は、大きな整数表現で慎重に定義する必要があります。 もう 1 つの例外的なケースは次のような場合です。$b = 0$ここで、すべての数値が有効であり、答えは純粋な間隔サイズの計算に集約されます。 

## アプローチ

 ブルートフォースの解決策は簡単です。間隔内のすべての数値について、必要なビットがすべて存在するかどうかを確認します。 これが機能するのは、次の条件があるためです。$(x \& b) = b$数値ごとの定数時間です。 ただし、間隔の長さが長い場合は、最大$10^9$、整数ごとに 1 つのビット単位のチェックを実行するため、これは実行不可能になります。 

重要な観察は、任意の数値を比較しようとしているのではなく、上限の下で構造化されたビット パターンをカウントしようとしているということです。 これは、バイナリ表現よりも数字の DP がすぐに示唆されます。 すべての数値を反復処理する代わりに、接頭辞とまだ一致しているかどうかを維持しながら、最上位ビットからビットごとに数値を構築します。$N$。 

制約を解釈すると、ビットがどこにあるのかに気づきます。$b$has 1 は強制され、ビットはどこにありますか$b$0は無料です。 唯一厄介なのは上限です$x \le N$、これはまさに DP が処理する桁です。 

大きな入力に必要なさらなる最適化は、サフィックス数をビットごとに再計算することを避けることです。 すべてのサフィックス割り当てを繰り返す代わりに、どれだけの空きビットが残っているかを事前計算し、それを直接 2 の累乗に変換します。 これにより、サフィックスの列挙が O(1) に減ります。

 ## アルゴリズムのチュートリアル

 私たちはコンピューティングに重点を置いています$count(N)$範囲の回答はプレフィックス値から構築されるためです。 

1. 両方を変換する$N$そして$b$同じ長さに揃えられたバイナリ文字列に変換されます。 これにより、最上位ビットから位置ごとに推論することができます。 各インデックスが両方の数値の同じ重みに対応するように調整する必要があります。 
2. 配列を事前計算する`suffix_zeros[i]`、ポジションの数を保存します$j \ge i$持っている$b_j = 0$。 これは、ポジションに到達した場合にどれだけの自由な選択肢が残っているかを表します$i$制約に違反することなく。 これが機能する理由は、すべてのゼロビットが$b$の空きビットに対応します$x$、より高い決定とは独立しています。 
3. 2 のべき乗モジュロを事前計算する$10^9 + 7$。 空きビットごとに有効な完了の数が 2 倍になるため、高速にアクセスする必要があります。$2^k$サフィックスカウント用。 
4. 以下のビットを反復処理します。$N$旗を維持しながら左から右へ`tight`、構築された数値の接頭辞が依然として の接頭辞と等しいかどうかを示します。$N$。 もし`tight`は false、すでに下にいます$N$また、マスク制約のみに従って残りのビットを自由に割り当てることができます。 
5. 各ポジションで$i$、まず次のことを確認してください。$b_i = 1$。 そうであれば、現在のビット$x$1 である必要があります。これが矛盾する場合は、$N_i$その間`tight`が依然として true である場合、このブランチの寄与はゼロとなり、停止します。 
6. もし$b_i = 0$、私たちには選択肢があります。 0 または 1 を配置できますが、それでも厳しい場合は境界を尊重する必要があります。 より小さいビットを配置すると、$N_i$を使用して完了数をすぐに計算できます。$2^{\text{suffix\_zeros}[i+1]}$、残りのゼロの位置はすべて$b$自由に変えることができます。 
7. のビットと一致する場合は、タイトな状態の伝播を続けます。$N$に等しい一意のパスを正確に数えることを保証します。$N$有効な場合はそれ自体。 
8. 最後に、すべての分岐点の結果を結合し、累積されたカウントを返します。 

範囲の答えを計算するには、次のように評価します。$count(r)$そして$count(l-1)$、次の場合は減算を正しく処理するように注意してください。$l = 0$。 また、次のことを明示的にチェックします。$l$プリフィックスの減算は実装によっては境界の包含を省略できるため、それ自体が条件を満たします。 

### なぜ効果があるのか

 このアルゴリズムは、有効な数値のセットを、それらが異なる最初の位置に基づいて互いに素なセグメントに分割することに依存しています。$N$。 このような各位置は、サフィックスのバイナリ選択肢のサブツリーを一意に決定します。 の`tight`フラグは、時期尚早に上限に違反しないことを保証しますが、サフィックスの事前計算により、各サブツリーが独立ビットの 2 のべき乗拡張として 1 回だけカウントされることが保証されます。 これにより、有効な割り当てとカウントされた貢献の間に 1 対 1 のマッピングが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def to_bin(x: str):
    # hex string to binary string without leading zeros
    if x == "0":
        return "0"
    v = int(x, 16)
    return bin(v)[2:]

def normalize(a, b):
    n = max(len(a), len(b))
    return a.zfill(n), b.zfill(n)

def count(N, B):
    N, B = normalize(N, B)
    n = len(N)

    suffix_zeros = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_zeros[i] = suffix_zeros[i + 1] + (1 if B[i] == '0' else 0)

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    res = 0
    tight = True

    for i in range(n):
        if B[i] == '1':
            if N[i] == '0':
                return res
        else:
            if tight:
                if N[i] == '1':
                    res = (res + pow2[suffix_zeros[i + 1]]) % MOD
            # continue either way

        if tight and B[i] == '0':
            if N[i] == '0':
                tight = True
            else:
                tight = False
        elif tight:
            if B[i] == '1':
                if N[i] == '0':
                    return res

    return res

def solve():
    l = input().strip()
    r = input().strip()
    b = input().strip()

    def dec_hex(x):
        return int(x, 16)

    rl = r
    ll = l

    R = to_bin(r)
    L = to_bin(l)
    B = to_bin(b)

    def countN(x):
        return count(x, B)

    def is_ok(x):
        return (int(x, 16) & int(b, 16)) == int(b, 16)

    ans = (countN(rl) - countN(hex(int(ll, 16) - 1)[2:] if int(ll, 16) > 0 else "0")) % MOD
    if is_ok(l):
        ans = (ans + 1) % MOD

    print(ans)

if __name__ == "__main__":
    solve()

次の 16 進文字列の減算を処理する場合は注意が必要です。$l-1$単純な整数変換は概念的なサブタスクでオーバーフローする可能性があるためです。 コードでは安全のために Python 整数を使用していますが、意図したソリューションでは任意の長さの表現を前提としています。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$b = 0$。 この状況では、必要なビットがないため、すべての数値が自動的に条件を満たします。 アルゴリズムは不必要に数字 DP ロジックを入力すべきではなく、間隔のサイズを直接返す必要があります。 例えば、$l = 5, r = 10$6 つの有効な数値が得られます。 

別のエッジケースが発生するのは次の場合です。$l = 0$。 表現$count(l-1)$になる$count(-1)$、これはゼロとして解釈されなければなりません。 実装では、これは特殊なケースまたはバイナリ表現を保証することによって処理されます。$-1$は空の有効なプレフィックス スペースとして扱われます。 

3 番目のエッジケースは次のような場合です。$b$の最上位ビットを 1 ビット上回る$N$。 その場合は番号なし$x \le N$条件を満たすことができるため、アルゴリズムはプレフィックス チェック中に早期に終了する必要があります。 例えば、$N = 7$そして$b = 8$必要なビットを境界内に設定できないため、すぐにゼロが返されます。 

これらのケースは、必要なビットに強制的な不一致があるとすぐに状態空間を崩壊させ、無効な寄与がカウントされないようにするため、DP 遷移によって自然に処理されます。
