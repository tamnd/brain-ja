 ## 解決策
 ## 問題の理解

 数直線上の 2 つのソートされた位置のシーケンスが与えられます。 1 つのシーケンスは通り沿いにあるゴミ袋を表し、もう 1 つはトラックが通りから出る出口を表します。 各ゴミ袋について、最も近い出口までの距離を決定し、これらの距離を最終的な答えとして集計する必要があります。 

重要な制約は、両方のシーケンスが既に非降順でソートされていることです。 この構造は装飾的なものではなく、このソリューションがバッグごとに最初から比較を再計算する必要を回避できる理由全体です。 

出口の数を m、バッグの数を n とすると、直接解釈すると、各バッグをすべての出口と比較できる可能性があることがわかります。 これにより、距離チェックが n 回 m 回行われることになり、両方の配列が大きい場合には時間がかかりすぎます。 

すべての出口が厳密にバッグの片側にある場合、微妙なエッジケースが現れます。 この状況では、最も近い出口があいまいではありませんが、一方向のみをチェックするか、両方の隣接方向を考慮しない単純な実装では、誤った結果が返される可能性があります。 たとえば、出口が位置にある場合`[1, 2]`そしてバッグはここにあります`100`、正解は`98`ただし、バッグの位置を通過するまでのみ比較し、その後早期に停止する実装では、最後の有効な出口を誤って見逃す可能性があります。 

重複値またはクラスター化された値が存在する場合、別の障害モードが表示されます。 出口が`[10, 20, 30]`そしてバッグは`[21, 22, 23]`、バッグごとの単純なポインターのリセットでは、最初から繰り返し再スキャンする可能性があり、正しい最も近い出口インデックスが前方に移動するだけである場合でも、不必要な二次動作が生成されます。 

## アプローチ

 ブルートフォース手法では、すべてのバッグについて、すべての出口までの絶対距離を計算し、最小値を取得します。 これは、すべての可能性を明示的にチェックするので正しいですが、n × m の比較を実行します。 制約が大きい場合、両方の配列のサイズが増大し、この積が許容される演算を桁違いに超える可能性があるため、これは遅くなりすぎます。 

重要な観察は、バッグに沿って左から右に移動するときに、最も近い出口インデックスが後方に移動できないことです。 バッグがわずかに右に移動した場合、最適な出口候補は同じままであるか、次の出口に移動します。 この単調性により、exit 配列へのポインターを維持し、リセットせずに前方にのみ移動することができます。 

現在のバッグの右側またはそれに等しい最初の出口に到達すると、その出口と前の出口のうち、最も近い出口が常に存在します。 並べ替え順序により、右または左にあるものはすべて悪くなることが保証されています。 これにより、バッグごとの検索が償却一定時間に短縮されます。

 ## アルゴリズムのチュートリアル

 私たちはバッグを昇順に処理し、同時に出口を昇順に通過します。 

1. ポインタを初期化する`j = 0`出口配列上で。 このポインタは、現在のバッグからまだ除外されていない最初の出口を表します。 
2. バッグの位置ごとに`b[i]`、 前進`j`その間`j + 1 < m`そして、次の出口は、次の意味でさらに近いか同等です。`c[j + 1]`候補者としては悪くない`c[j]`このバッグの場合。 具体的には移動します`j`それまで`c[j]`最初の出口が次の値以上であるか`b[i]`、または出口がなくなるまで。 
3. 1回`j`が配置されている場合、最も近い出口は次のいずれかである必要があります。`c[j]`または`c[j - 1]`それが存在する場合。 両方の絶対距離を計算し、最小値を取得します。 
4. この最小距離を現在の合計に加算します。 
5. リセットせずに次のバッグに進みます`j`。 これは、将来のバッグが同じかそれ以上の位置にあるため、以前の出口が新たに最適になることはないため有効です。 

重要な構造上の決定は、各バッグの出口のスキャンを決して再開しないことです。 ポインタは前方にのみ移動するため、正確性が維持され、繰り返しの作業が不要になります。 

### なぜ効果があるのか

 不変条件はバッグを加工する前です`i`、ポインタ`j`すべてが厳密に左側に存在するように、最小のインデックスに配置されます。`j`の出口または右側の出口よりも優れているわけではないことが保証されています。`j`残りのすべてのバッグに対して。 両方の配列がソートされているため、バッグの位置を増やしても、以前に破棄された出口が再び最適になることはありません。 この単調な優位性により、周囲の 2 つの隣接する候補のみをチェックすることが保証されます。`j`正確さには十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    j = 0
    ans = 0

    for x in b:
        while j + 1 < m and abs(c[j + 1] - x) <= abs(c[j] - x):
            j += 1

        best = abs(c[j] - x)
        if j > 0:
            best = min(best, abs(c[j - 1] - x))

        ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```実装は単一のポインタを保持します`j`出口の上。 内側のループは、次の出口が現在のバッグの現在の出口と少なくとも同程度に優れている場合にのみループを進め、常に局所的に最適な候補で終了するようにします。 2 番目のチェック`j - 1`最も近い出口がポインターのすぐ左側にある境界を処理します。 

よくある間違いはリセットです`j`バッグごとに。 これにより、正確性は保たれますが、線形的な複雑性が損なわれます。 もう 1 つの間違いは、相対的に一方向のみをチェックすることです。`j`、最も近い出口が反対側にある場合は失敗します。

 ## 特殊なケース

 すべてのバッグが最初の出口の左側にある場合、ポインターは決して前進せず、すべてのバッグは最初の出口とのみ比較する必要があります。 アルゴリズムはこれを処理します。`j`ゼロのままで、`j - 1`チェックは決してトリガーされません。 

すべてのバッグが最後の出口の右側にあると、ポインタは最後のインデックスに到達するまで進み、その後停止します。 右側にはより良い候補が存在しないため、すべての距離は最後の出口に対してのみ計算されます。 

出口がまばらでバッグが密集している場合、ポインタはバッグに対してゆっくりと進みますが、それでも前進するだけです。 これにより、多くのバッグが同じ最も近い出口領域を共有する場合でも、直線的な動作が保証されます。
