 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられたフックの行が与えられます。 2 つの境界フック 1 と n は、プロセスが開始される前にすでに使用されているとみなされます。 その後、システムは残りの未使用のフックに対して決定的な操作を繰り返し実行します。 

各ステップで、アルゴリズムは行をスキャンし、未使用のフックの最大の連続セグメントに分割します。 これらのセグメントのうち、最大長の左端のセグメントが選択されます。 そのセグメント内で、その中間位置、またはセグメント長が偶数の場合は 2 つの中間位置を選択し、それらのフック位置を使用済みとしてマークします。 次に、未使用のフックの更新されたセットに対してプロセスが繰り返されます。 

重要な問題は、クエリ フック p ごとに、p が使用されるステップ番号を決定する必要があるということです。 

完全な問題における入力サイズは、n と q が最大 3 · 10^5 に達します。 配列を再スキャンしてステップごとにセグメントを再計算する単純なシミュレーションでは、O(n) ステップにわたって O(n) 位置を繰り返し走査するため、O(n^2) 個の動作が発生しますが、これは許容範囲をはるかに超えています。 q が大きい場合、クエリあたり O(n log n) であっても遅すぎます。 

グリーディ シミュレーションの正確性について考えると、微妙な構造上の問題が現れます。セグメントは対称的に縮小しますが、そのプロセスはローカルな再帰のみではなく、セグメントのグローバルな順序付けによって駆動されます。 不用意に実装すると、特に複数のセグメントが同じ長さで存在する場合、安定性は厳密な左から右への順序に依存するため、中心をマークした後にセグメントが正しく再計算されない可能性があります。 

素朴な考え方の具体的な失敗モードは、グローバルな左から右の順序を維持せずに、DFS のような再帰で各セグメントを個別に処理できると想定していることです。 たとえば、セグメント [2, 9] を分割した後、最初に片側を再帰的に完全に探索するのではなく、すべてのセグメントにわたって左側と右側の部分を FIFO 順序で処理する必要があります。 この順序は正しいステップ インデックスにとって不可欠です。 

## アプローチ

 ブルート フォース ソリューションはステートメントの直後に続きます。使用済みフックをマークする配列を維持し、すべてのインデックスを繰り返しスキャンして最大の未使用セグメントを見つけ、左端の最も長いセグメントを選択し、その中央を計算して、使用済みとしてマークします。 各スキャンのコストは O(n) で、ステップが O(n) であるため、完全なシミュレーションごとに合計作業量は O(n^2) になります。 これは、n が非常に小さい場合にのみ許容されます。 

重要な観察は、プロセスが非常に規則的な再帰構造を持っているということです。 選択されたすべてのセグメントは常に 2 つの小さな独立したセグメントに分割され、次の操作は常に、現在のすべてのセグメントの中でグローバルに最も左にある使用可能なセグメントに作用します。 これは、キュー内のセグメントを処理することと同じであり、各セグメントは処理後に 2 つの子セグメントを生成します。 

このように見ると、システムは区間 [2, n − 1] の完全にバランスの取れた二値分解ツリーの幅優先探索になります。 各ステップは 1 つのセグメントを処理し、その左側と右側のサブセグメントをキューに入れます。 これにより、アレイ全体を繰り返しスキャンする必要がなくなります。 

最終的な最適化では、すべてのステップをシミュレートする代わりに、この分解ツリーの特定の深さで指定された位置がセグメントの中心になるステップを直接計算します。 再帰の各レベルではセグメント サイズが半分になるため、深さは O(log n) になります。 ルート セグメントからその位置まで歩いていき、そのノードに到達するまでに処理されたセグメントの数を累積します。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | キューベースの BFS シミュレーション | O(n) | O(n) | 承認済み |
 | 対数深さの直接計算 | O(q log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 単一の位置 p のステップ数を計算することに焦点を当てます。

1. 最初のセグメント [2, n − 1] から始めます。これは、境界を除外した後のすべての使用可能なフックを表します。 このセグメントはレベル 0 にあり、まだ処理されているセグメントはありません。 
2. 任意のセグメント [L, R] で、その中間位置 mL と mR を計算します。 これらは、p がこのセグメント内にある場合にこのステップで削除される候補フックです。 
3. p が中間位置の 1 つに等しい場合、p が現在のステップ インデックスで削除されると直ちに判断します。これは、このステップより前に処理されたセグメントの数にレベル内でのこのセグメントの位置を加えたものに等しくなります。 それでやめます。 
4. それ以外の場合、分割のどちら側に p が含まれるかを決定します。 p が mL 未満の場合、左のサブセグメント [L, mL − 1] に移動します。 p が mR より大きい場合、右のサブセグメント [mR + 1, R] に移動します。 
5. 1 つ下のレベルに移動するたびに、前のレベルで処理されたすべてのセグメントが考慮されます。 各レベル k には正確に 2^k 個のセグメントが含まれるため、下降する前にこれらのカウントを累計として累積します。 
6. また、そのレベル内の現在のセグメントのインデックスも追跡します。 暗黙のバイナリ ツリー構造がセグメントの順序に対応しているため、左に移動するとこのインデックスが 2 倍になり、右に移動すると 2 倍になり 1 が加算されます。 

### なぜ効果があるのか

 レベル k の各セグメントは、再帰的な中間点分割によって形成される完全なバイナリ ツリー内のノードに対応します。 このプロセスは幅優先順序でノードを訪問します。つまり、レベル k のすべてのノードが、レベル k + 1 のノードよりも前に処理されます。レベル内では、順序は左から右です。 これにより、完全なレベルとレベル内の位置によるノードのカウントが、セグメントが処理されるステップ番号と正確に一致することが保証されます。 各位置 p は、そのパスに沿ったレベルごとに 1 つのノードに正確に属するため、p が中間点となる最初のレベルによって、その削除時間が一意に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    queries = list(map(int, input().split()))
    
    # initial segment is [2, n-1]
    # if n <= 2, everything is already "boundary-like"
    
    def solve_one(p):
        L, R = 2, n - 1
        k = 0
        x = 0
        processed = 0
        
        while L <= R:
            mL = (L + R) // 2
            mR = (L + R + 1) // 2
            
            # if p is center at this level
            if p == mL or p == mR:
                return processed + x + 1
            
            # accumulate previous full levels
            processed += 1 << k
            
            # go deeper
            if p < mL:
                R = mL - 1
                x = x * 2
            else:
                L = mR + 1
                x = x * 2 + 1
            
            k += 1
        
        return processed

    out = []
    for p in queries:
        out.append(str(solve_one(p)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、概念的なバイナリ分解ツリーを反映しています。 区間 [2, n − 1] は、その中間点で繰り返し分割されます。 処理される変数は、以前のすべてのレベルに存在するノードの数を追跡します。これは常にレベルごとに 2 のべき乗であるため、各深さで 2^k を加算します。 

変数 x は、そのレベル内の現在のセグメントのインデックスをエンコードし、バイナリ ヒープ インデックスとまったく同じように構築されます。 左に行くと 2 が乗算され、右に行くと 2 が乗算されて 1 が加算され、左から右への順序が維持されます。 

終了条件は、p がちょうど中間点位置の 1 つである場合に発生し、BFS 順序内のステップ番号が直接与えられます。 

off-by-one の処理には注意が必要です。戻り値には、以前の完全なレベルと現在のレベル内のオフセットの両方が含まれている必要があります。 もう 1 つの微妙な点は、2 つの中心要素が存在し、両方とも除去ポイントとみなされるため、中間点の計算が均等な長さで正しく分割されるようにすることです。 

## 実用的な例

 n = 9 とすると、最初のセグメントは [2, 8] になります。 クエリ p = 4。 

| ステップ | Ｌ | R | セグメント | mL | mR | 処理済み | × | アクション |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 8 | [2,8] | 5 | 4 | 0 | 0 | p < mL、左へ |
 | 1 | 2 | 4 | [2,4] | 3 | 3 | 1 | 0 | p == mL、停止 |

 ステップ 1 では p が中点になるため、時刻 1 で削除されます。 

次に、同じ設定で p = 7 を考えます。 

| ステップ | Ｌ | R | セグメント | mL | mR | 処理済み | × | アクション |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 8 | [2,8] | 5 | 4 | 0 | 0 | p > mR、右に進みます |
 | 1 | 5 | 8 | [5,8] | 6 | 7 | 1 | 1 | p == mR、停止 |

 ここでは、右に移動するとバイナリ インデックスが増加することがわかります。そのため、p を含むセグメントはレベル 1 の 2 番目のノードであり、p は中間点になるとすぐに削除されます。 

これらのトレースは、アルゴリズムがセグメント分解の一貫した BFS 順序に従っていること、および各位置に固有の検出時間が割り当てられていることを確認します。

 ## 特殊なケース

 重大なエッジ ケースは、間隔の長さが偶数で、2 つの中間位置が生成される場合に発生します。 [2, 7] のようなセグメントの場合、中間点は 4 と 5 です。どちらかに等しい位置は即時削除として扱われなければなりません。 アルゴリズムは両方を明示的にチェックし、中心の選択に曖昧さがなくなるようにします。 

分割を繰り返した後、p がサブセグメントの境界に正確に位置する場合、別のエッジ ケースが発生します。 境界 1 と n は使用済みとして事前にマークされているため、再帰にはそれらが含まれることはなく、計算されたサブセグメントは常に [2, n − 1] 内にとどまる必要があります。 このアルゴリズムは、左または右に移動するときに間隔を厳密に縮小することでこれを強制し、アクティブ領域外への無効なアクセスを防ぎます。 

最後の微妙なケースは、n が非常に小さい場合 (n ≤ 3 など) で、最初のセグメント [2, n − 1] が空または単一要素である可能性があります。 このような場合、それ以上の分割は発生せず、p がすでに使用されているとみなされるかどうかに応じて、クエリはすぐに解決されるか、簡単に解決されます。
