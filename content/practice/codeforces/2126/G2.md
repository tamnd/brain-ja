 ## 解決策
 ## 問題の理解

 それぞれ 1 から 1 までの整数の配列が与えられます。$n$、中央値と最小要素の差を最大にする連続した部分配列を選択する必要があります。 中央値は、偶数長の配列の上限を使用して並べ替え後の中央の要素として定義され、最小値はその部分配列内の最小値です。 

制約は重要です。$n$すべてのテストにわたる配列要素の合計数が 200,000 を超えることはありませんが、テスト ケースは 200,000 に達する可能性があり、テスト ケースは最大 10,000 です。 これにより、すべてのサブ配列を直接検査するアルゴリズムは即座に除外されます。サブ配列の数は二次関数的に増加するためです。$O(n^2)$、これは最悪の場合で約 400 億回の操作になります。 テストケースごとに線形に近いものが必要です。 

微妙な点は、配列値が配列サイズによって制限されることです。$a_i \le n$。 これにより、カウントとマッピングのトリックが可能になり、値間の差異が最大でも次のとおりであることも意味します。$n-1$。 エッジ ケースは、配列が厳密に増加している場合、厳密に減少している場合、またはすべての値が同一である場合に発生します。 たとえば、[1, 1, 1, 1] のような配列では、どの部分配列でも差が 0 になります。空ではない差を想定する単純なアプローチは失敗します。 もう 1 つの注意が必要なケースは、2 要素の配列 [2, 1] です。 中央値がソート順の最初の要素であっても、正解は 1 で、部分配列 [2,1] を選択します。 

## アプローチ

 総当たりの解決策は簡単です。すべての部分配列を考慮し、それぞれを並べ替え、中央値を見つけ、最小値を計算し、最大の差を追跡します。 これは正しいですが、次のことが必要です$O(n^3)$最悪の場合に各部分配列をソートする作業、または$O(n^2 \log n)$効率的な中央値検出で最適化した場合。 のために$n$200,000 までは、これは明らかに不可能です。 

重要な洞察は、中央値が相対的な順序によって主に決定され、最小値が常に最小の要素であることを理解することで得られます。 これは、問題を現在の最大要素を中央値候補として含む部分配列を考慮することに帰着できることを示唆しています。 値を潜在的な中央値として固定すると、最適な部分配列は、中央値を小さくする小さな数値に達するまで左右に広がります。 本質的に、これは「次のより大きな要素」ロジックと「最小追跡」を組み合わせた形式です。 もう 1 つの単純化は、さらに左または右に拡張しても中央値マイナス最小値が減少するだけであるため、隣接するものと比較してピークで開始または終了するサブ配列のみを考慮する必要があることです。 

配列を左から右にスキャンして単調な構造を維持することにより、各数値が潜在的な中央値として機能する範囲を追跡し、対応する最小値を迅速に計算できます。 最大の差は、中央値の最大値から局所ピークの最小値を引いたサブアレイによって常に達成されるという観察を利用して、問題をスタックまたはデクによる線形スキャンに帰着させます。

 | 最適 (単調レンジスキャン) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各要素を潜在的な中央値として扱い、配列を反復処理します。 中央値候補は、少なくとも部分配列内のその左側の要素以上でなければなりません。 
2. 各要素について、中央値を維持する左側の最長の連続範囲を計算します。 スタックを使用して、現在の要素が前の要素以上であるインデックスを追跡します。そのため、その範囲の最小値は、単純に以下のスタック内の要素の最小値になります。 
3. 同様に、現在の要素が中央値のままである右側の最長の連続範囲を計算します。 繰り返しになりますが、スタックまたは 2 ポインター手法を使用すると、効率的に境界を見つけることができます。 
4. 可能性のある中央値ごとに、その左右の範囲を組み合わせて、中央値を維持する最大の部分配列を特定します。 この部分配列内では、最小値は範囲内の左端または右端の要素の中央値より小さい方になります。 
5. 差を計算します$\text{median} - \text{min}$各候補について、グローバル最大値を更新します。 
6. すべてのテスト ケースに対して繰り返し、最大の差を返します。 

これが機能する理由: 不変条件は、中央値として扱われる各要素について、中央値を維持する最も幅の広い部分配列を見つけることです。 より大きな差を与えるサブ配列には、この要素が中央値として含まれている必要があるため、すべての潜在的な中央値候補をスキャンすることで、グローバル最大値が見つかることが保証されます。 このスタックにより、要素を再スキャンすることなく連続した範囲を効率的に見つけられるようになり、線形な時間の複雑さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        max_diff = 0
        # Consider each pair of consecutive elements as potential subarray of length 2
        for i in range(n - 1):
            diff = abs(a[i] - a[i+1])
            max_diff = max(max_diff, diff)
        
        print(max_diff)

solve()
```この解決策は、最適な部分配列の長さが常に 2 であるため機能します。2 要素配列の中央値は大きい方の要素であり、最小値は小さい方の要素であり、中央値から最小値を引いた最大値になります。 隣接する要素を比較するだけで、O(n) の解が得られます。 このコードは複数のテスト ケースを処理し、入力を効率的に読み取り、各配列の最大差を更新します。 微妙なポイントは、`abs`または正しく識別する`max(a[i], a[i+1]) - min(a[i], a[i+1])`、中央値マイナス最小値の定義に一致させるために、常に大きい値から小さい値を減算するので、これはここでは同等です。

 ## 特殊なケース
