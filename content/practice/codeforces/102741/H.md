 ## 解決策
 ## 問題の理解

 1 次元の廊下上にザッパーの位置のセットがあり、同じ線上にゴーストの位置のセットがあります。 各ゴーストは 1 つのザッパーを選択して除去する必要があります。 幽霊が遠くにいる場合`d`選択したザッパーから消費されるエネルギーは`d²`。 目標は、すべてのゴーストを可能な限り安価なザッパーに割り当てるときに必要な最小の総エネルギーを見つけることです。 答えはモジュロで出力する必要があります`10^9 + 7`。 元の問題の制約により、最大で次のことが可能になります。`10^5`ザッパーと`10^5`ゴースト、座標は次のとおりです`10^7`。 

入力サイズが大きいと、すべてのゴーストをすべてのザッパーに対してチェックできなくなります。 直接的な解決策は、`n * m`距離の計算。 両方の値が等しい場合`100000`、それは`10^10`これは、通常の競技プログラミングの時間制限をはるかに超えています。 すべての立場が一直線上にあるという事実を利用する必要があります。 

重要な構造は、ゴーストに最も近いザッパーが、ソート後にそのゴーストを囲む 2 つのザッパーのうちの 1 つでなければならないということです。 隣接する 2 つのザッパーの間にゴーストが存在する場合、どちらか一方から遠ざけても距離は広がるだけです。 ゴーストがザッパーの範囲全体の外側にある場合、最も近いザッパーは単に最も近いエンドポイントになります。 これは、問題が並べ替えとバイナリ検索に集約できることを意味します。 

いくつかの特殊なケースでは、一般的なケースのみを考慮した実装が壊れる可能性があります。 

ゴーストがまさにザッパー上にある場合、エネルギーの寄与はゼロです。 

入力例:```
2 1
5
10
5
```正しい出力は次のとおりです。```
0
```厳密な比較を使用し、等価性を無視する不注意な解決策は、誤って別のザッパーを選択し、プラスのコストを追加する可能性があります。 

すべてのザッパーがすべてのゴーストの片側にある場合は、最も近い極端なザッパーのみを使用する必要があります。 

入力例:```

10
20

```正しい出力は次のとおりです。```
125
```最初のゴーストが貢献`(10 - 0)² = 100`そして2番目は貢献します`(10 - 5)² = 25`。 すべてのゴーストの両側にザッパーがあると想定する実装では、無効なインデックスにアクセスしたり、間違った近傍を計算したりする可能性があります。 

ザッパーの位置が重複している場合も、対処する価値のあるケースです。 

入力例:```

7

7

```正しい出力は次のとおりです。```

```すべての重複ザッパーは単一の場所として動作します。 一意の位置を使用しようとするソリューションは問題ありませんが、バイナリ検索中に等しい値を誤って処理するソリューションでは、完全一致が誤ってスキップされる可能性があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのゴーストについて、すべてのザッパーを反復処理し、二乗距離を計算し、最小値を維持します。 そのゴーストに対して考えられるすべての割り当てが検査されるため、これは正しいです。 

問題は仕事量です。 と`n`ザッパーと`m`幽霊、これはパフォーマンスします`n * m`比較と距離の計算。 最大入力サイズでは、これは次の値に達します。`10^10`動作が遅すぎます。 

重要な観察は、位置が 1 次元であるということです。 ザッパーの位置をソートした後、ゴーストに最も近いザッパーは、ソートされた配列内のゴーストの挿入ポイントの近くで常に見つかります。 すべてのザッパーを検査する必要はありません。 

ゴーストポジションの場合`x`、二分探索により、少なくとも次の位置にある最初のザッパーが得られます。`x`。 このザッパーは右側で最も近い候補です。 前のザッパーが存在する場合、それが左側の最も近い候補になります。 右側の他のザッパーは、この最初の右側の候補よりも遠く、左側の他のザッパーは、この最初の左側の候補よりも遠くなります。 この 2 つを比較するだけで済みます。 

ブルートフォースは、考えられるすべてのザッパーをチェックするため機能します。 隣接するザッパーのみが重要であるという観察により、各ゴースト クエリは線形時間から対数時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n log n + m log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのザッパーの位置を読み取り、並べ替えます。 

ソートにより順序付けられた構造が作成され、二分探索により任意のゴースト位置の周囲のザッパーを迅速に見つけることができます。 
2. ゴースト位置ごとに、ソートされたザッパーに対して二分検索を実行して、最初のインデックスを見つけます。`i`どこ`zappers[i] >= ghost`。 

これにより、考えられる最も近いザッパーが 2 つの候補に分割されます。 インデックスのザッパー`i`ザッパーは右側の可能な限り近いものです。`i - 1`左側の可能な限り近いものです。 
3. 有効な候補を確認します。 

もし`i`が配列内にある場合は、次を使用してコストを計算します`zappers[i]`。 もし`i - 1`が負でない場合は、次を使用してコストを計算します。`zappers[i - 1]`。 小さい方の二乗距離を維持します。 
4. このゴーストの最小コストを実行中の答えに追加します。 

整数のサイズを管理しやすい状態に保つために、加算後にモジュロを適用します。 

なぜ効果があるのか:

 ゴーストの位置については、その周囲のソートされたザッパーを考慮してください。 左隣のザッパーよりも左にあるすべてのザッパーの距離は長くなり、右隣のザッパーよりも右にあるすべてのザッパーの距離も長くなります。 最も近いザッパーは、これら 2 つの隣接ザッパーのうちの 1 つである必要があります。 アルゴリズムは常にこれらの候補を正確にチェックするため、すべてのゴーストが受け取るエネルギー コストは最小限に抑えられます。 これらの独立した最小コストを合計すると、最小総エネルギーが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    zappers = []
    for _ in range(n):
        zappers.append(int(input()))

    zappers.sort()

    ans = 0

    for _ in range(m):
        x = int(input())

        left = 0
        right = n

        while left < right:
            mid = (left + right) // 2
            if zappers[mid] >= x:
                right = mid
            else:
                left = mid + 1

        best = 10**30

        if left < n:
            d = zappers[left] - x
            best = d * d

        if left > 0:
            d = zappers[left - 1] - x
            best = min(best, d * d)

        ans = (ans + best) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```ザッパーのソートされたリストが主要なデータ構造です。 二分探索の実装では、下限、つまり現在のゴースト位置以上の値を含む最初の位置が検索されます。 

変数`left`検索後は左隣ではなく、挿入位置になります。 等しい場合`n`、右側にはザッパーがありません。 ゼロの場合、左側にザッパーはありません。 これら 2 つの境界チェックにより、無効な配列アクセスが防止されます。 

Python の整数はオーバーフローしないため、座標の差が最大 2 までの場合でも、二乗距離は安全です。`10^7`。 固定幅の整数を使用する言語では、より幅の広い型を使用して乗算を実行する必要があります。
