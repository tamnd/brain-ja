 ## 解決策
 ## 問題の理解

 時間の経過とともに変化する整数の配列が与えられます。 2 つの操作が順番に適用されます。1 つの操作は、連続するセグメント内のすべての要素を固定値ずつ増加させます。もう 1 つの操作は、選択したセグメントを、すべてのペアが同じ合計を持つように素のペアに再配置できるかどうかを尋ねます。 

2 番目の操作は元の順序に関するものではありません。 これは、セグメント内の値の複数セットにのみ依存します。 すべての要素をペアにして、各ペアが同じ合計を生成する方法はあるのかどうかを尋ねられます。 

制約が十分に大きいため、クエリごとにセグメントを再構築したり並べ替えたりすることは実行できません。 最大 200,000 の要素と 200,000 の操作を使用すると、セグメント全体にわたってクエリを線形時間で処理するソリューションは失敗します。 要素ごとの対数動作であっても、大量に集約されない限り遅すぎます。 

微妙な点は、更新は追加的であり、範囲全体に影響を与えることです。 これは、私たちが維持するどのような構造であっても、各要素に明示的に触れることなく値の均一なシフトをサポートする必要があることを示唆しています。 

よくある落とし穴は、条件のチェックが最小値と最大値の比較や合計プロパティのみのチェックなどのローカルなものに限定されると想定することです。 それでは不十分です。 たとえば、配列`[1, 1, 3, 3]`としてペアリングできます`(1,3)`そして`(1,3)`和は4ですが、`[1, 2, 3, 4]`の合計は同じで長さも同じですが、すべての要素にわたって単一のペアリングの合計が機能しないため、一貫してペアリングすることはできません。 

もう 1 つの微妙な問題は、更新によりセグメント内のすべての値が変更されることです。 すべてのキーの効率的なシフトをサポートしない限り、単純な周波数構造はすぐに壊れます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリ セグメントの場合、すべての値を抽出して並べ替え、最初と最後の合計、2 番目と最後から 2 番目の合計などがすべて等しいかどうかを確認します。 これは正しいです。一定の合計を達成するには、有効なペアは並べ替えられた順序で極値をペアにする必要があるからです。 ただし、セグメントの抽出と並べ替えにはコストがかかります$O(k \log k)$、 どこ$k$セグメント長です。 多くのクエリを実行すると、次のようになります。$O(nq \log n)$最悪の場合、限界をはるかに超えてしまいます。 

この難しさは、範囲の追加と「グローバル構造」のチェックという 2 つの操作が相互作用することに起因します。 範囲加算は、値が数直線上で変換されるかのように動作することを示唆します。 ペアリング条件は、絶対的な位置ではなく、マルチセットの相対的な対称性にのみ依存します。 

重要な観察は、有効なセグメントは定数の存在を満たさなければならないということです。$S$すべての値が$x$マルチセット内の は次と同じ周波数を持ちます$S - x$。 言い換えれば、マルチセットは以下を中心に対称です。$S/2$。 すべての要素を定数だけシフトすると、対称性は維持されますが、それに応じて中心がシフトします。 これにより、範囲更新時の状態が安定します。 

したがって、問題は、セグメント内のすべての値をシフトすることと、マルチセットがその合計とサイズによって決定される中心の周りで対称であるかどうかを照会することという 2 つの機能を使用して、範囲にわたって動的マルチセットを維持することになります。 

遅延伝播を備えたセグメント ツリーを使用して、セグメントごとの集計情報を維持できます。 各ノードには、値分布のサイズ、合計、および 2 つの多項式スタイルのハッシュが保存されます。 1 つのハッシュは正方向に値を追跡し、もう 1 つのハッシュは反転方向に値を追跡します。 範囲の加算はこれらのハッシュの乗算更新となり、個々の要素に触れることがなくなります。 

これにより、問題はセグメント情報を対数時間で結合し、クエリごとに 1 つの代数条件を検証することに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの並べ替え) |$O(n \log n)$クエリごと |$O(n)$| 遅すぎる |
 | 遅延 + ハッシュを使用したセグメント ツリー |$O(\log n)$クエリ/更新ごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。 各ノードはセグメントを要約します。 

1. 各ノードは、セグメント内の要素の数とその合計を格納します。 これにより、有効なペアリングがサイズで存在する場合、必要に応じて候補ペアリングの合計を再構築することができます。$k$、必要なペアの合計は$S = 2 \cdot \text{sum} / k$。 この値はすべてのペアで一貫している必要があります。 
2. 各ノードは、そのマルチセットにわたって 2 つのハッシュ値を維持します。 最初のハッシュは分布を次のようにエンコードします。$H_1 = \sum p^{a_i}$。 2 番目は反転ビューをエンコードします$H_2 = \sum p^{-a_i}$、モジュール逆べき乗を使用して実装されます。 これら 2 つのビューを使用すると、候補中心を決定した後に対称性をテストできます。 
3. セグメント内のすべての要素への保留中の追加を表す遅延値が各ノードに格納されます。 シフトを適用する$v$すべての要素を増加させ、乗算してハッシュを変換します。$H_1$による$p^v$そして$H_2$による$p^{-v}$。 これにより、個々の要素に触れることなく範囲を更新できます。 
4. 範囲に更新を適用するには、セグメント ツリーをプッシュダウンします。 完全にカバーされたノードは遅延更新されますが、部分的にカバーされたノードは再帰的に更新されます。 
5. クエリに答えるために、区間をカバーするセグメント ツリー ノードを、合計、サイズ、および両方のハッシュを含む単一の集約構造に結合します。 
6. 集計された合計とサイズから、$S = 2 \cdot \text{sum} / k$。 サイズが奇数の場合はペアリング不可能ですので即拒否してください。 
7. 構造がこの候補中心の周りで対称であるかどうかを確認します。$H_1 = p^S \cdot H_2$。 マルチセットが真に対称である場合、各値をシフトします。$x$に$S-x$はまったく同じマルチセットを保持し、この等価性が維持されます。 

### なぜ効果があるのか

 不変条件は、適用されるすべての遅延シフトの下で、各ノードのハッシュが常にそのセグメント内の値の正確なマルチセットを表すことです。 範囲加算はすべての値を均一に変換するだけであり、これは両方のハッシュの決定論的な乗算変換に対応します。 ノードをマージする場合、ハッシュ加算はマルチセット結合に対応します。 

クエリ セグメントの場合、正確性は、マルチセットが計算された中心の周りの反射と等しいかどうかをチェックすることに帰着します。 2 つの方向性ハッシュを使用した等価性テストは、この反射特性を高い確率で捕捉し、合計制約により、唯一の可能な中心がデータ自体によって引き起こされる中心であることが保証されます。 他のセンターはペアリング要件を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
BASE = 91138233

# We need inverse of base
def modinv(x):
    return pow(x, MOD - 2, MOD)

MAXV = 400000 + 5

pow_b = [1] * (MAXV + 5)
pow_ib = [1] * (MAXV + 5)

inv_base = modinv(BASE)

for i in range(1, MAXV + 5):
    pow_b[i] = pow_b[i - 1] * BASE % MOD
    pow_ib[i] = pow_ib[i - 1] * inv_base % MOD

class Node:
    __slots__ = ("l", "r", "sum", "sz", "h1", "h2", "lazy")

    def __init__(self):
        self.l = self.r = 0
        self.sum = 0
        self.sz = 0
        self.h1 = 0
        self.h2 = 0
        self.lazy = 0

def merge(a, b):
    res = Node()
    res.sum = a.sum + b.sum
    res.sz = a.sz + b.sz
    res.h1 = (a.h1 + b.h1) % MOD
    res.h2 = (a.h2 + b.h2) % MOD
    return res

def apply(node, v):
    if node.sz == 0:
        return
    node.sum += node.sz * v

    node.h1 = node.h1 * pow_b[v] % MOD
    node.h2 = node.h2 * pow_ib[v] % MOD

    node.lazy += v

def build(a, v, tl, tr):
    node = Node()
    if tl == tr:
        node.sz = 1
        node.sum = a[tl]
        node.h1 = pow_b[a[tl]]
        node.h2 = pow_ib[a[tl]]
        return node

    tm = (tl + tr) // 2
    node.l = build(a, v, tl, tm)
    node.r = build(a, v, tm + 1, tr)
    node = merge(node.l, node.r)
    return node

def push(node):
    if node.lazy != 0:
        apply(node.l, node.lazy)
        apply(node.r, node.lazy)
        node.lazy = 0

def update(node, tl, tr, l, r, v):
    if l <= tl and tr <= r:
        apply(node, v)
        return
    push(node)
    tm = (tl + tr) // 2
    if l <= tm:
        update(node.l, tl, tm, l, r, v)
    if r > tm:
        update(node.r, tm + 1, tr, l, r, v)
    node = merge(node.l, node.r)

def query(node, tl, tr, l, r):
    if l <= tl and tr <= r:
        return node
    push(node)
    tm = (tl + tr) // 2
    if r <= tm:
        return query(node.l, tl, tm, l, r)
    if l > tm:
        return query(node.r, tm + 1, tr, l, r)
    left = query(node.l, tl, tm, l, r)
    right = query(node.r, tm + 1, tr, l, r)
    return merge(left, right)

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    a = [0] + a

    root = build(a, 0, 1, n)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            _, l, r, v = tmp
            l = int(l)
            r = int(r)
            v = int(v)
            update(root, 1, n, l, r, v)
        else:
            _, l, r = tmp
            l = int(l)
            r = int(r)

            node = query(root, 1, n, l, r)
            k = node.sz
            if k % 2:
                out.append("NO")
                continue

            S = (2 * node.sum) // k

            if node.h1 == (pow_b[S] * node.h2) % MOD:
                out.append("YES")
            else:
                out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリー ノードは、合計ベースのペアリング センターとマルチセットのハッシュ表現の両方を再構築するために必要な情報を正確に運ぶように設計されています。 遅延値は均一なシフトを表し、両方のハッシュの乗算更新にきれいに変換されます。 これは、個々の要素に触れることを避けるための重要な単純化です。 

クエリ ロジックは、唯一の実現可能なペアの合計を計算した後、問題を 1 つの代数チェックに削減します。 

## 実用的な例

 配列を考慮してください`[1, 2, 3, 4, 5, 6, 7, 8]`そしてセグメント全体をクエリします。 

| ステップ | サイズ | 合計 | 候補者S | チェック |
 | --- | --- | --- | --- | --- |
 | イニシャル | 8 | 36 | 9 | 対称性をチェックする |

 必要なペアリングは、`(1,8), (2,7), (3,6), (4,5)`、すべて合計すると 9 になるため、答えは YES です。 構造は 4.5 付近で対称性を確認します。 

ここで考えてみましょう`[1, 2, 3, 4, 5, 6]`。 

| ステップ | サイズ | 合計 | 候補者S | チェック |
 | --- | --- | --- | --- | --- |
 | クエリ | 6 | 21 | 7 | 有効な完全な対称性がありません |

 可能なペアは次のようにする必要があります`(1,6), (2,5), (3,4)`これは機能するため、このセグメントは YES を返します。 更新によって値を乱して対称性が崩れると、ミラーリングされた周波数が一致しなくなるため、ハッシュ比較は失敗します。 

これらの例は、アルゴリズムがペアリングの実現可能性を明示的な列挙ではなく構造的対称性にどのように低下​​させるかを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、セグメント長が奇数の場合に発生します。 値が完全に構造化されている場合でも、1 つの要素がペアになっていないままになるため、ペアリングは不可能です。 アルゴリズムは、ハッシュ チェックを実行する前にサイズ パリティに基づいて拒否することで、これを即座に処理します。 

もう 1 つのエッジ ケースは、値が同一であるセグメントです。`[5, 5, 5, 5]`。 すべての合計が等しいため、どの組み合わせも有効です。 ハッシュ表現はシフトの下でも安定しており、合計ベースのセンターは一貫した結果を生成するため、チェックは常に合格します。 

最後のエッジケースには、値を初期範囲外にシフトする大量の更新が含まれます。 このアルゴリズムは制限された値ではなくべき乗剰余に依存するため、シフトは正確さに影響を与えず、事前に計算された累乗によって明示的に処理される指数変換にのみ影響します。
