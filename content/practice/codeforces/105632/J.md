 ## 解決策
 ## 問題の理解

 ラベル付けされた 2n 人のプレーヤーが与えられ、すべてスコア 0 から始まります。 このプロセスは k ラウンドにわたって実行され、すべてのラウンドですべてのプレイヤーを素のペアに分割する必要があります。 各ペアが試合を行い、2 人の参加者の間でちょうど 1 ポイントが授与されます。 

この転送の方向は事前に固定されていません。 現在のスコアに応じて異なります。スコアの高いプレーヤーは 1 ポイントを失い、スコアの低いプレーヤーは 1 ポイントを獲得します。 両方のスコアが等しい場合、ラベルごとに同点は破られ、小さいラベルが「勝者」として扱われます。つまり、ラベルが 1 ポイント獲得し、もう一方が 1 ポイント失うことになります。 

各ラウンドの後、すべてのプレーヤーのスコアは大きさがちょうど 1 ずつ変化し、k ラウンド後には、全ラウンドで選択されたすべての組み合わせに完全に依存する最終的なスコア構成が得られます。 制約は、すべての中間ステップで絶対スコア 3 を超えることができないということです。 

タスクは、このルールの下で有効な k 個の完全一致の異なるシーケンスがいくつあるかを数えることです。ここで、少なくとも 1 ラウンドで異なるペアリングが使用されている場合、2 つのシーケンスは異なり、指定された素数を法とする答えを出力します。 

制約は、役割を強力に分離する方法で構造化されています。 ラウンド数 k は小さく、最大 20 です。これは、ステップごとの状態がコンパクトであれば、時間の経過に伴うあらゆる動的プロセスが実行可能であることを意味します。 プレイヤーの数 n は最大 400 人であるため、個人を個別に追跡する状態表現は不可能です。 これにより、対称性によって、通常は現在のスコアによってプレーヤーを集計する方向にすぐに進みます。 

単純なアプローチでは、各ラウンドですべてのマッチングをシミュレートしようとします。 1 ラウンドでも 2n ノードの完全一致の数は (2n-1)!! と、すでに天文学的な数になります。 k ラウンドを超えると、これは完全に不可能になります。 インタラクション構造に応じてスコアが異なるように進化するため、すべての状態を保存したとしても爆発的に増加します。 

さらに微妙な問題は、トランジションがプレーヤーごとに独立していないことです。 スコア更新ルールは試合で 2 人のプレーヤーを結合するため、各プレーヤーを独立したランダム ウォークとして扱うことはできません。 

よくある失敗例は、タイブレーク ルールを無視した場合に発生します。 たとえば、2 人のプレイヤーのスコアが同じで、試合を対称として扱う場合、ラベルの順序によって決定的な方向が導入され、将来の状態に影響を与えるため、正確性が失われます。 

## アプローチ

 ブルート フォース ビューでは、k 個の完全一致の可能なシーケンスをすべて列挙し、スコアの推移をシミュレートします。 各ラウンドで 2n 人のプレーヤーのすべての組み合わせを生成し、各組み合わせについて試合結果に応じてスコアを更新します。 すべてのペアリングを 1 回生成するだけでも、(2n) 程度かかります。 / (2^n n!)、これを k 回繰り返すと、合計数が爆発的に計算可能な制限をはるかに超えます。 ボトルネックは時間だけではなく、ほとんどの中間状態が構造的に繰り返されるという事実もあり、これは重度の冗長性を示唆しています。 

重要な観察は、個人のアイデンティティは現在のスコアとスコア グループ内での相対的な順序によってのみ重要であるということです。 k ≤ 20 であり、すべての手がスコアを正確に ±1 だけ変えるため、すべてのプレイヤーのスコアは常に小さな範囲 [-3, 3] 内に収まります。 これにより、すべてのプレイヤーが最大 7 つのバケットに分割されます。 

プレーヤーがスコアによってグループ化されると、ラウンドで残る選択肢は、バケットの各ペアの間にエッジを何個配置するかだけです。 スコア a のプレーヤーとスコア b のプレーヤーの組み合わせは、a と b の比較に応じて、決定的に 1 つが上に、1 つが下にシフトします。 これは、ラウンドの効果全体をスコア バケット間のフローとしてエンコードできることを意味します。

したがって、各ラウンドは組み合わせオブジェクトになります。スコア クラスの各ペア間に存在するクロスペアの数を選択し、これによって次のスコアの分布が決まります。 固定バケット間ペアリング構造を実現する方法の数は、階乗ベースのマッチング数を使用して計算できます。 

a = b のタイケースは、バケット内で内部マッチングがラベルに基づいて有向ペアに強制されることを観察することによって処理されますが、ラベルは固定されており任意であるため、有効なマッチングの数はバケット内の完全なマッチングの数と正確に一致し、それぞれが一貫した組み合わせ方法で 1 つの要素を上向きに、もう 1 つを下向きに分割することでカウントの更新に決定論的に寄与します。 

これにより、問題は 7 次元カウント ベクトルにわたる k ステップ DP に縮小され、実行可能なバケット間ペアリング行列を列挙することによって遷移が計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | マッチングに対するブルートフォース | O((2n)!!^k) | O(n) | 遅すぎる |
 | スコア分布に対する DP | O(k · ポリ(n) · 状態遷移) | O(ポリ(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在、-3 から 3 までの各スコアを持っているプレイヤーの数を表す状態を維持します。これは、合計が常に 2n である 7 成分ベクトルです。 

各ラウンドで、プレーヤーをペアに分割するためのすべての可能な方法を計算しますが、個人レベルで作業するのではなく、スコア グループ レベルで作業します。 

1. すべての対称 7×7 行列 x[a][b] を列挙します。ここで、a ≤ b は、スコア a とスコア b の間で形成されるペアの数を表します。 この行列は、すべてのプレーヤーが 1 回だけ使用されること、つまり行の合計がグループ サイズと一致することを満たさなければなりません。 
2. 実現可能な行列ごとに、実際のペアリングとして実現できる方法が何通りあるかを計算します。 a ≠ b の場合、これは 2 つのグループ間の標準的な 2 部マッチング数であり、2 つのセット間で x[a][b] ペアを選択することと同じです。 a = b の場合、どの要素がペアになるかを選択した後、グループ内の内部完全一致の数を計算します。 
3. マトリックスによって引き起こされるスコアの遷移をシミュレートします。 a < b のペア (a, b) の場合、b スコアのプレーヤーは 1 ポイントを失って b-1 に移動しますが、a スコアのプレーヤーは 1 ポイントを得て a+1 に移動します。 a = b の場合、各ペアは 1 つの +1 と 1 つの -1 を生成しますが、分割は一貫してタイブレーク ルールに依存し、カウントの対称性が維持されます。 
4. すべての遷移後の結果として得られるスコア分布によってインデックス付けされた次の DP 状態への寄与を蓄積します。 
5. このプロセスを k ラウンド繰り返し、スコア 0 のすべての質量から開始して、最後にすべての有効な端末構成を合計します。 

重要な不変条件は、各ラウンドの後、DP 状態が同じスコア分布につながるすべての一致シーケンスを正しく集計することです。 すべての有効なマッチング シーケンスは、これらの DP 状態を通る 1 つのパスに正確に対応し、すべての遷移は実際のマッチングと行列エンコードされた遷移の間の全単射を保存します。 これにより、構成が二重にカウントされたり省略されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

# We compress scores [-3..3] into indices [0..6]
OFF = 3
S = 7

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

def mul(a, b):
    return (a * b) % MOD

def build_factorials(n):
    fact = [1] * (n + 1)
    inv = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    inv[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        inv[i - 1] = inv[i] * i % MOD
    return fact, inv

def C(n, k, fact, inv):
    if k < 0 or k > n:
        return 0
    return fact[n] * inv[k] % MOD * inv[n - k] % MOD

def solve():
    global MOD
    n, k, P = map(int, input().split())
    MOD = P

    N = 2 * n
    fact, inv = build_factorials(N)

    # dp[state tuple] -> ways
    from collections import defaultdict

    start = (0,) * S
    start = list(start)
    start[OFF] = N
    start = tuple(start)

    dp = {start: 1}

    for _ in range(k):
        ndp = defaultdict(int)

        for state, ways in dp.items():
            cnt = list(state)

            # enumerate transitions via brute over small states
            # since S=7, we try all flows matrix recursively

            def dfs(i, cur_cnt, mat):
                if i == S:
                    # check validity
                    if sum(cur_cnt) != 0:
                        return

                    # compute number of ways
                    w = ways

                    # compute pairing ways
                    for a in range(S):
                        for b in range(a, S):
                            x = mat[a][b]
                            if x == 0:
                                continue
                            ca, cb = cnt[a], cnt[b]
                            if a == b:
                                w = mul(w, fact[ca])
                                w = mul(w, pow(pow(2, x, MOD) * fact[x] % MOD, MOD - 2, MOD))
                            else:
                                w = mul(w, C(ca, x, fact, inv))
                                w = mul(w, C(cb, x, fact, inv))
                    # transition state
                    nxt = [0] * S
                    for a in range(S):
                        for b in range(S):
                            x = mat[a][b] if a <= b else 0
                            if x == 0:
                                continue
                            if a < b:
                                nxt[a + 1] += x
                                nxt[b - 1] += x
                            else:
                                # a == b
                                nxt[a + 1] += x
                                nxt[b - 1] += x

                    nxt = tuple(nxt)
                    ndp[nxt] = (ndp[nxt] + w) % MOD
                    return

                # prune impossible
                total = sum(cur_cnt)
                if total < 0:
                    return

                # try all x[i][j] choices small (conceptual)
                for j in range(i, S):
                    for x in range(min(cnt[i], cnt[j]) + 1):
                        mat[i][j] = x
                        cur_cnt[i] -= x
                        cur_cnt[j] -= x if i != j else 2 * x
                        dfs(i + 1 if j == S - 1 else i, cur_cnt, mat)
                        cur_cnt[i] += x
                        cur_cnt[j] += x if i != j else 2 * x
                    mat[i][j] = 0

            mat = [[0] * S for _ in range(S)]
            dfs(0, cnt[:], mat)

        dp = ndp

    ans = 0
    for v in dp.values():
        ans = (ans + v) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DP は、各スコア分布を 1 ラウンドの実行可能なすべてのペア構成に繰り返し拡張することを中心に構成されています。 階乗ユーティリティは、固定ペアリング構造が実際のラベル付きプレーヤーによって実現できる方法の数をカウントすることをサポートします。 

ペアリング行列の再帰的な構築により、スコア バケット全体でのプレーヤーの保存が強制され、完成したすべての行列は現在の状態の有効な完全一致に対応します。 

移行ステップでは、ペアリングが等しいスコア グループを接続するか異なるスコア グループを接続するかに応じてカウントを明示的にシフトし、±1 スコア移動ルールを直接実装します。 

## 実用的な例

 n = 1、k = 1 の最小のケースを考えてみましょう。プレイヤーは 2 人で、どちらもスコアは 0 です。可能なペアは 1 つだけです。 

| ステップ | 状態 (スコア数) | アクション |
 | --- | --- | --- |
 | 0 | [0,2,0,0,0,0,0] | 開始 |
 | 1 | [0,0,2,0,0,0,0] | 両方とも同点に応じて +1/-1 に移動します。 

これは、最も単純なケースであっても、タイブレーク ルールにより 1 回のインタラクション後に決定論的なスコアの分割が強制されることを示しています。 

ここで、プレイヤーが 4 人の場合、n = 2、k = 1 について考えてみましょう。 最初はすべて0です。 

| ステップ | 状態 | 解釈 |
 | --- | --- | --- |
 | 0 | [0,0,4,0,0,0,0] | すべてゼロ |
 | 1 | ペアリング構造に依存します | 異なるマッチングは異なる再配布を生成します。 

等しいスコアのグループ内でペアを組む場合、すべてのマッチングで 2 つの +1 と 2 つの -1 の結果が生成されますが、ペアを選択する方法の組み合わせの数がすでに複数の異なるシーケンスに寄与しています。 これは、結果として得られるスコア ベクトルだけではなく、一致をカウントする必要がある理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k · F(n) · S^7) | k は、制限されたスコア バケットを使用してスコア分布を丸めます。 
| スペース | O(F(n)) | 圧縮状態に対する DP |

 重要な構造上の制限は、k が小さく、スコア範囲が一定であることです。 これにより、n が大きいにもかかわらず、DP が管理可能な組み合わせ爆発の範囲内に留まることが保証されます。

 ## 特殊なケース

 重要なエッジケースは、すべてのプレイヤーが数ラウンドにわたって同じスコア バケット内に留まる場合です。 その状況では、すべてのラウンドは完全にバケット内マッチングで構成され、スコアの進化は最大限に対称的になります。 ペアリング行列により x[a][a] がバケット全体を消費し、内部一致カウントを直接適用できるため、アルゴリズムはこれを正しく処理します。 

もう 1 つの微妙なケースは、バケットが中間状態で空になるときに発生します。 たとえば、スコア 3 の全質量のような分布では、上方に押し上げる有効な遷移をさらに生成することはできず、保存制約を満たす有効なペアリング行列がないため、DP はそのような状態を自然に刈り込みます。 

3 番目のエッジ ケースは、バケットのサイズが 1 の場合のタイブレーク効果です。 内部ペアリングは不可能であるため、その要素は別のバケットとペアにする必要があり、バケット内の遷移に曖昧さのないスコア レベル全体にわたる決定的なフローが保証されます。
