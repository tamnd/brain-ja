 ## 解決策
 ## 問題の理解

 三角形のグリッドが与えられ、その行は下に行くにつれて大きくなり、合計はおおよそ次のようになります。$n^2$に配置されたセル$n$行。 各セルには 1 から 4 までの数字が含まれています。このグリッド上を移動する四面体のサイコロもあります。 ダイスは最初の行の左上のセルから開始され、初期の方向は固定されています。面 4 が下にあり、他の面は固定された水平方向を向いています。 

移動は、サイコロを三角形のグリッド内の隣接するセルに転がすことで構成され、これにより位置と方向の両方が変わります。 着地後、移動先のセルに書かれた数字がダイスの底面の数字と一致する場合にのみ、移動は正当です。 さらに、開始セルとターゲット セルを含め、どのセルも複数回訪問することはできません。 

タスクは、これらの制約の下でターゲット セルに到達できるかどうかを判断し、到達できる場合は、必要な最小ロール数を計算することです。 

将来の移動の妥当性は位置だけでなくダイの方向にも依存するため、この構造は状態空間探索問題を即座に示唆します。 基板サイズは最大です$n \le 100$, したがって、セルの数は次のとおりです。$10^4$。 各状態には、四面体ダイの位置と 24 の可能な方向のうちの 1 つの両方が含まれており、周囲に上限が与えられます。$2.4 \cdot 10^5$州。 これは BFS にとって十分小さいです。 

微妙な点は、「単一訪問」という制約です。 位置と方向のみを追跡する単純な BFS は、最短経路の問題で通常は役立つ場合でも、方向が異なるセルを再訪することは禁止されているため、正しくありません。 これにより、問題は、各位置と方向のペアが最大 1 回訪問される状態グラフ内の最短経路に変換されます。 

もう 1 つのトリッキーなエッジ ケースは、開始セルがすでに条件を課しているという初期制約です。底面は開始セルの値とすぐに一致する必要があり、そうでない場合は移動できません。 

## アプローチ

 強引なアイデアは、各ステップを、ダイの方向を明示的に追跡しながら、ロールの可能なすべてのシーケンスを試行するものとして扱うことです。 各状態から、セルを再度訪問することなくすべてのパスを試行します。これは本質的に、パス履歴を持つ状態のグラフに対する DFS です。 パスの長さは最大であるため、$n^2$、分岐はセルごとに最大 6 方向 (三角形隣接)、可能な単純なパスの数は指数関数的に増加します。 剪定してもこれは無理です。 

重要な観察は、パスは単純である必要がある (セルの繰り返しがない) にもかかわらず、状態空間は依然として有限で構造化されているということです。 ダイの方向を含めると、それぞれの動きが決定的になります。特定の方向に回転すると、ある方向が別の方向にマッピングされます。 これにより、問題がノードが配置されたグラフに変換されます。$(cell, orientation)$、エッジは数一致制約を満たす有効なロールを表します。 

「セルを再訪問しない」という制約は、訪問した状態をレベルでマークすることで自然に処理されます。$(cell, orientation)$。 BFS はすでに最短パスを保証しており、任意の向きでセルを再訪問しても、パスの長さが増加するか制約に違反するだけであるため、状態を再訪問する必要はありません。 

したがって、解はこの拡張されたグラフ上の BFS になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース DFS | 指数 | O(n²) 再帰の深さ | 遅すぎる |
 | (セル、方向) 状態の BFS | O(n² · 24) | O(n² · 24) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、ダイの向きを表現する必要があります。 四面体のダイには 4 つの面があり、現在どの面が底にあるか、移動方向に対して他の面がどのように配置されているかを追跡することで方向を表すことができます。 構造が固定されているため、遷移を事前に計算します。各向きと、三角形グリッド内の 6 つの可能なロール方向のそれぞれについて、結果として生じる向きがわかります。 

次に、初期セルと初期方向から開始して BFS を実行します。 

1. 三角形グリッドの隣接性を計算します。 それぞれの細胞$(i, j)$行パリティと境界に応じて、最大 6 つの隣接ノードに接続します。 これにより、移動グラフが構築されます。 
2. 考えられるすべてのダイの方向状態を事前計算します。 四面体ダイには 24 の回転状態があるため、方向には 0 から 23 までのインデックスが付けられます。 向きごとに、底面の値を保存します。 
3. 遷移テーブルの事前計算`trans[orient][dir] -> new_orient`、各方向に回転させた後に方向がどのように変化するかを説明します。 これは、固定された物理的な回転ルールから導出されます。 
4. 状態を使用して BFS を初期化します。$(0, 0, initial_orientation)$。 初期方向はステートメントで指定されているため、それをエンコーディングに変換します。 
5. 初期状態をプッシュする前に、開始セルの値が初期方向の底面と一致していることを確認します。 そうでなければ、即答は不可能です。 
6. BFS を実行します。 州ごとに$(cell, orientation)$、すべての有効な隣接セルを試します。 近隣ごとに、必要な方向とその結果の方向を計算します。 隣接セルの値が新しい方向の下面と一致し、その状態がまだ訪問されていない場合は、そのセルをキューにプッシュします。 
7. BFS は最小距離を保証するため、任意の方向でターゲット セルに到達したら停止します。 

重要なアイデアは、BFS はロールの数の増加を調査し、方向は状態の一部であるため、正確性が維持されるということです。 

### なぜ効果があるのか

 アルゴリズムは、ノードがすべて有効であるグラフを定義します。$(cell, orientation)$ペア。 各エッジは、隣接性と面一致の制約の両方を満たす正当なロールに正確に対応します。 すべての移動のコストは 1 であるため、BFS はこのグラフ内の最短パスを見つけます。 セルを再訪問するには、すでに探索された状態または同じ構成へのより長いパスを再訪問する必要があり、BFS が再エンキューすることはないため、「繰り返しセルなし」制約が暗黙的に適用されます。 したがって、最初にターゲット セルに到達するときは、最小限のロールで到達する必要があります。

# Directions in triangular grid (axial-like representation)
# We build neighbors explicitly since indexing is irregular.

def build_neighbors(n, grid):
    # cell ids per row
    idx = [[0]* (2*i+1) for i in range(n)]
    cid = 0
    for i in range(n):
        for j in range(2*i+1):
            idx[i][j] = cid
            cid += 1

    total = cid
    adj = [[] for _ in range(total)]

    # directions depend on triangular layout
    for i in range(n):
        for j in range(2*i+1):
            u = idx[i][j]

            # same row neighbors
            if j-1 >= 0:
                adj[u].append(idx[i][j-1])
            if j+1 < 2*i+1:
                adj[u].append(idx[i][j+1])

                if j > 0:

            # down-left / down-right
            if i+1 < n:
                adj[u].append(idx[i+1][j])
                adj[u].append(idx[i+1][j+1])

    return adj, idx

## 実用的な例

 ダイが有効な一致するセルの短いチェーンに沿って移動できる小さなケースを考えてみましょう。 

| ステップ | セル | 方向 | 下 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | (1,1) | 初期化 | 4 | 開始 |
 | 1 | (2,1) | o1 | 3 | 左下にロール |
 | 2 | (3,2) | o2 | 2 | 右下にロール |

 このトレースは、方向の変更がいかに重要であるかを示しています。 パスが幾何学的に存在する場合でも、無効な底面位置合わせにより移動がブロックされます。 

2 番目のケースは、初手の不一致により不可能であることを示しています。 

| ステップ | セル | 方向 | 下 | アクション |

 | 0 | (1,1) | 初期化 | 4 | 開始 |
 | 1 | (2,1) | o1 | 3 | ブロックされました |

 ここでは、セル制約を満たす隣接移動がないため、BFS は初期状態を超えて拡大することはなく、すぐに失敗します。 

これらの例は、到達可能性がジオメトリだけでなく方向のダイナミクスにも大きく依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始セルがすでに底面条件に違反している場合です。 アルゴリズムは、BFS が開始される前にこれをチェックします。 たとえば、入力が (1,1) で 4 とは異なる値で始まる場合、状態空間は探索されず、出力はすぐに -1 になります。 

もう 1 つのケースは、ターゲットが隣接しているものの、回転の制約により開始方向から到達できない方向を必要とする場合です。 BFS は依然として到達可能なすべての方向を探索しますが、ターゲットで位置と底面制約の両方を満たす状態がないため、キューが空になり、アルゴリズムは正しく -1 を返します。 

最後の微妙なケースは、複数の方向が同じセルに到達する場合に発生します。 アルゴリズムは、訪問されたテーブル内でこれらを別々に保持します。 これが必要なのは、異なる方向で同じセルを再訪問すると、将来の異なる移動が可能になる可能性があるためですが、同じ状態への繰り返しの訪問は安全に枝刈りされ、指数関数的爆発を回避しながら正確さを維持します。
