 ## 解決策
 ## 問題の理解

 増加するペアのシーケンスが与えられ、各プレフィックスの後に、そのプレフィックスに関する仮説のゲームを評価する必要があります。 

長さ k の固定プレフィックスの場合、k 個のインデックス i の 1 つを選択すると想像してください。 アリスは値 aᵢ を受け取り、ボブは bᵢ を受け取り、両方のプレイヤーはプレフィックス内のペアのリスト全体を参照しますが、どのインデックスが選択されたかはわかりません。 また、彼らはお互いの受信値のタイプを知っています (アリスは aᵢ のみを知り、ボブは bᵢ だけを知っています)。 次に、アリスから始めて、他のプレイヤーの価値を推測できるかどうかを交互に発表します。 アリスが最初に bᵢ を一意に決定できれば、彼女は即座に勝ちます。 そうでなければ、ボブはアリスの発言を聞いた後に aᵢ を推測する機会を得ます。 どちらも独自の推論を強制できない場合、その i については誰も勝者になりません。 

すべての接頭辞 k について、その接頭辞内のインデックス i がアリスの勝利につながる個数とボブの勝利につながる個数を数えなければなりません。 

制約 q は最大 10⁶ であるため、以前のすべてのペアをスキャンして各プレフィックスの結果を再計算しようとするアプローチは遅すぎます。 O(q²) メソッドでさえ制限をはるかに超えているため、挿入ごとに基本的に償却された O(1) または O(log q) が必要です。 

微妙な問題は、固定インデックスの結果がローカル情報だけでなくプレフィックス全体に依存することです。 単純な間違いは、同じ aᵢ を持つすべてのペアが最終配列で同じ bᵢ を持つときはいつでも、アリスが勝つと仮定することです。しかしこれは、ボブがアリスの推論の失敗を利用して候補を排除できる相互作用を無視しています。 

もう 1 つの落とし穴は、2 人のプレーヤーを対称的に扱い、独立性を前提とすることです。 ボブの推論はアリスの応答パターンに依存しますが、それ自体は各 a グループ内のグローバル構造に依存します。 

素朴な推論が失敗する小さな例は次のような場合です。 

ペア: (1,1)、(1,2)、(2,1)

 i = 1 の場合、アリスは a=1 と b 値 {1,2} が見えるため、推測できません。 ボブは、候補 i=1 と i=3 で b=1 と見ますが、i=1 のみが一貫しており、アリスは推論できません (i=3 であればアリスはすぐにわかるため)。そのため、ボブが勝ちます。 アリスの応答フィルタリングを無視するアプローチでは、i=1 が未決定として誤ってマークされます。 

## アプローチ

 ブルートフォースの方法では、接頭辞 k とインデックス i ≤ k ごとに、推論プロセス全体をシミュレートします。 固定 i の場合、アリスはまず、aⱼ = aᵢ であるすべての j ≤ k の中で、対応する b 値が単一の値に折りたたまれるかどうかを確認します。 そうでない場合、彼女は「わかりません」と言います。 次に、ボブは、すべての j ≤ k を bⱼ = bᵢ とみなして、同じアリスの応答を生成するものをフィルタリングします。 1 つだけ残れば、ボブの勝ちです。 

これを i ごとにシミュレートするには、等しい a または等しい b で定義されたグループをスキャンする必要があり、インデックスごとに O(k) のコストがかかり、プレフィックスごとに O(k²)、最悪の場合は全体で O(q³) になります。 これはまったく実現不可能です。 

重要な観察は、アリスの動作は、プレフィックス内の各 a 値が「純粋」であるかどうかのみに依存するということです。つまり、すべての出現が同じ b 値を共有することを意味します。 固定プレフィックスの場合、同じ a を持つすべてのインデックスのアリスの動作は同じになります。 同様に、ボブのフィルタリングは、b とこのアリスの動作ラベルによるグループ化のみに依存します。 

これにより、問題は 2 つの進化する分類を維持することになります。つまり、各 a グループが純粋かどうか、およびそのラベルの下でインデックスが b グループにどのように分布するかです。 構造は動的になりますが、非常にまばらになります。これは、a グループが一度不純になると、プレフィックスが大きくなっても再び純粋になることはないためです。 

この単調性により、すべてを段階的に維持し、再計算を避けることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(q3) | O(q) | 遅すぎる |
 | 増分グループのメンテナンス | O(q) 償却 | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックスのデータ構造を維持しながら、ペアを順番に処理します。

1. 各値 a について、その a を持つインデックス間でこれまでに出現した別個の b 値の数を維持します。 この数がちょうど 1 の場合、a は現在「純粋」であると言います。 
2. それぞれに属するインデックスのリストを維持しているため、純度が変更された場合はすべてのインデックスを更新できます。 
3. 各 b について、2 つのカウンタを維持します。この b のインデックスの数が現在純粋な a グループに由来するものと、不純な a-グループに由来するインデックスの数です。 
4. 新しいペア (aᵢ, bᵢ) が到着すると、aᵢ に見られる b 値のセットを更新します。 これがその a の 2 番目の異なる b 値である場合、a グループは純粋から不純に移行します。 この移行は元に戻すことはできません。 
5. a グループが不純になった場合、その a を含む以前に挿入されたすべてのインデックスは、対応する b グループ内の「純粋な寄与」バケットから「不純な寄与」バケットに移動する必要があります。 
6. インデックス i の構造を更新した後、i の結果を決定します。 

aᵢ がまだ純粋な場合は、アリスが即座に勝ちます。 
7. それ以外の場合、ボブは同じ bᵢ を持つすべての候補 j を検査します。 彼は、a グループの純度が i に対するアリスの観察された応答と一致する j だけを見ます。 その応答は aᵢ の現在の純度によって決まるため、Bob の候補はまさにその純度ラベルに対応する bᵢ のバケット内の候補になります。 
8. ボブのフィルタリングされた候補セットのサイズがちょうど 1 の場合、ボブが i で勝ちます。 

重要な構造の単純化は、アリスの応答は a 値ごとに 1 つのブール値にのみ依存し、ボブの推論はそのブール値によって分割された固定 b グループ内でのカウントに帰着するということです。 

### なぜ効果があるのか

 どのプレフィックスでも、インデックスに対するアリスの決定は、a → b のマッピングがその a グループ内で単射的であるかどうかによってのみ決まります。 このプロパティは、同じ a-value を共有するすべてのインデックスで均一であるため、Alice の応答は、インデックスを a-value ごとに 2 つのクラス、つまり a-group が依然として純粋なものとそうでないものに分割します。 

ボブの演繹は、彼の候補セット (b 値によって固定) とアリスの応答クラスを交差させることと同じになります。 どちらのパーティションもプレフィックス統計によって完全に決定されるため、ゲームは、b グループ内の単一のブール制約と一貫性を保っているインデックスの数をカウントすることに帰着します。 

その後のインタラクションによってこれらの分類が変更されることはないため、プロセスは時間の経過とともに一貫性があり、単調になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    
    seen_b = {}
    bcnt = {}
    a_indices = {}
    a_seen = {}
    
    # bcnt[b] = [count_when_A_pure, count_when_A_impure]
    ansA = 0
    ansB = 0
    
    # current purity of a
    a_pure = {}
    
    for _ in range(q):
        a, b = map(int, input().split())
        
        if a not in a_seen:
            a_seen[a] = set()
            a_indices[a] = []
            a_pure[a] = True
        
        # update a structure
        if b not in a_seen[a]:
            if len(a_seen[a]) == 1:
                a_pure[a] = False
            a_seen[a].add(b)
        
        # initialize b counter
        if b not in bcnt:
            bcnt[b] = [0, 0]
        
        # insert index i (we don't store index id, only counts)
        # treat current element as "index"
        idx_state = 1 if a_pure[a] else 0
        
        bcnt[b][idx_state] += 1
        
        # store index in list for potential future flip handling
        a_indices[a].append((b, idx_state))
        
        # if a just became impure, we must migrate previous pure contributions
        if not a_pure[a] and len(a_seen[a]) == 2:
            # flip event: move all previous entries of this a
            for (bb, st) in a_indices[a]:
                if st == 1:
                    bcnt[bb][1] -= 1
                    bcnt[bb][0] += 1
        
        # compute answer for this index
        if a_pure[a]:
            ansA += 1
        else:
            # Bob checks only impure bucket (since Alice response is 0)
            if bcnt[b][0] == 1:
                ansB += 1
    
    print(ansA, ansB)

if __name__ == "__main__":
    solve()
```実装では、各 a 値について、いつ純粋でなくなるかを決定するための個別の b 値のセットが保持されます。 主要な状態はブール純度フラグで、インデックスが「Alice-knows」バケットに寄与するかどうかを制御します。 

各 b 値について、挿入時に a グループが純粋かどうかによってインデックスを分割する 2 つのカウンターを維持します。 a グループが純粋から不純に遷移するとき、その以前の寄与をすべて遡及的に移動します。これは、各インデックスがそのような遷移イベントに参加するのは多くても 1 つであるため安全です。 

各 i の最終決定は、これらのカウンターでの定数時間の検索に帰着します。 

## 実用的な例

 サンプルのプレフィックスを考えてみましょう。 

(1,1)、(1,2)、(2,1)

 構造がどのように進化するかを追跡します。 

| 私 | ペア | 純度（aあたり） | b バケットの状態 | アリスの勝ち | ボブが勝ちます |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) | a=1 純粋 | b=1:[1,0] | はい | いいえ |
 | 2 | (1,2) | a=1 不純 | b=2:[0,1] | いいえ | はい |
 | 3 | (2,1) | a=2 純粋 | b=1:[1,1] | はい | いいえ |

 i=2 の場合、a=1 には複数の b 値があるため、アリスは推測できません。 ボブは b=2 であると判断し、インデックス 2 のみが b とアリス応答の一貫性の両方に適合するため、ボブが勝ちます。 

次に、誰も勝たない場合を考えてみましょう。 

(1,1)、(1,2)

 | 私 | ペア | アリス州 | ボブ候補者の決意 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1) | 不純な a=1 | 候補者は 2 名残っています | なし |
 | 2 | (1,2) | 不純な a=1 | 候補者は 2 名残っています | なし |

 これは、フィルタリングによって単一の候補者を分離しない限り、不純物だけではボブの勝利が保証されないことを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q) 償却 | 各インデックスは、a-purity 遷移中に最大 1 回移動されます。 
| スペース | O(q) | a グループ、b カウンター、およびインデックス リストのストレージ |

## 特殊なケース

 重要なエッジ ケースは、新しい b 値が出現した瞬間に a 値が不純になる場合です。 たとえば、(1,1)、(1,2)などです。 2 回目の挿入で、a=1 グループは純粋から不純に移行し、以前のすべてのコントリビューションは一貫して移行される必要があります。 アルゴリズムは、その a の格納されたインデックスに対して 1 回のスイープを実行することでこれを処理し、古い要素と新しい要素の両方が不純な状態に分類されることを保証します。 

もう 1 つのエッジ ケースは、ボブの候補セットがアリスの応答フィルタリング後にのみサイズ 1 に折りたたまれる場合です。 (1,1)、(2,1) のようなシーケンスでは、値 1 の b グループには最初は 2 つの候補がありますが、アリスの応答パターンに一致するのは 1 つだけです。これが、生の候補が複数あるにもかかわらずボブが推測できる理由です。 アルゴリズムは、純度フラグに基づいて各 b グループを 2 つのカウンターに分割することでこれをキャプチャするため、フィルタリングは即時かつ正確になります。
