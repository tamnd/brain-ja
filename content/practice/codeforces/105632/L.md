 ## 解決策
 ## 問題の理解

 Z オーダー曲線と呼ばれる特別な空間順序ですべての非負の整数を列挙する方法が与えられています。 これを数式として考えるよりも、整数でインデックス付けされた点を越える単一の無限の有向ウォークとして見るとより有益です。各整数ラベルはウォークに沿って 1 回だけ表示されます。 この構造により、すべての整数が一意の位置に対応し、歩行が完全に決定され決定的になることが保証されます。 

タスクは位置を最初から計算することではありません。 代わりに、L から R までのインデックスに対応する、この無限ウォークの連続セグメントが与えられます。このセグメントが同じ順序で他の場所に再び現れるかどうか、もしそうであれば、l から l + (R − L) までのセグメントが、有向シーケンスとして比較したときに指定されたセグメントと同一になるような最小の開始位置 l を見つけるように求められます。 

重要な要件は、値空間ではなく、インデックス空間における翻訳の不変性です。 絶対数を直接比較しているのではなく、Z 次数曲線に沿った値のパターンがシフトの下で繰り返されるかどうかを比較しています。 

制約は非常に大きく、L と R は最大 10^18 まで可能です。 これにより、シーケンスの構築や曲線の直接シミュレーションが即座に除外されます。 単一のセグメントを明示的に保存することさえ問題ありませんが、カーブをグローバルに拡張したり、すべての位置を反復しようとしたりすることは不可能です。 

重要なのは方向性です。 セグメントが別の場所で逆の順序で表示されたり、何らかの構造的な意味でミラーリングされたりした場合でも、それはカウントされません。 比較は厳密に位置順に順方向に行われます。 

単純な間違いは、曲線がバイナリ構造から派生しているため、局所的なパターンが単純な周期的な方法で頻繁に繰り返される可能性があると想定することです。 それは世界的には当てはまらず、周期性を仮定すると、構造が異なるスケールで繰り返されるが、一貫したシフトでは繰り返されない場合には不正確な答えが得られます。 

たとえば、周期性を誤って仮定し、インデックスのモジュラー演算によって照合しようとすると、変換ではなくスケーリングの下で​​のみ構造的に一致するセグメントが誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての開始位置 l を試し、各位置の Z オーダー値を評価することによって、候補ごとにセグメント [l, l + (R − L)] と指定されたセグメント [L, R] を比較します。 これには、曲線内の位置 i の値を計算できる必要があります。 

O(1) の任意のインデックスの値を計算できると仮定した場合でも、l について最大 O(R) 個の候補をテストする必要があり、各比較のコストは O(R − L) となり、最大 10^18 の範囲で最悪のケースの O(N^2) の動作が発生します。 これはまったく実現不可能です。 

重要な構造的洞察は、Z オーダー曲線がビット インターリーブによって定義されていることです。各整数位置は、モーザー デ ブルーイン分解から導出された独立したビット コンポーネントのペアとして解釈できます。 これは、2 の累乗にわたる再帰的自己相似性を意味します。スケール 2^k の曲線は、固定パターンに配置されたそれ自体のより小さなコピーで構成されます。 

この自己相似性は、セグメントを保存する有効な変換では、最上位の異なるビットにわたるバイナリ構造の位置合わせを尊重する必要があることを意味します。 言い換えれば、構造を保存する唯一の有効なシフトは、2 の累乗によって引き起こされる分解境界に一致するシフトです。 

したがって、すべての l を検索する代わりに、セグメントが L と R が異なる最上位ビットとどのように一致するかを分析することで、有効なシフトを特徴付けることができます。 問題は、これらの構造的対称性の下でセグメントの標準的な代表を見つけることに帰着します。

整列された最大のバイナリ ブロックを繰り返し削除し、その分解によって決定された候補位置から開始してセグメントを埋め込むことができるかどうかを確認することにより、セグメントを効果的に正規化します。 これにより、問題は、Z オーダー階層と一致する固有の最小シフトの決定論的な再構成に変わります。

 ## アルゴリズムのチュートリアル

 Z オーダー曲線のすべてのインデックスがバイナリ レベルへの再帰的分解に対応し、セグメントのシフトがこれらの分解の位置合わせに対応するという事実に依存しています。 

1. 区間 [L, R] のバイナリ長を計算します。これは、L と R が異なる最上位ビットを意味します。 これにより、セグメントを含む最大の構造ブロックが決まります。 このステップでは、セグメントが曲線の再帰構造と相互作用するスケールを特定します。 
2. セグメントがそのブロック内にどのように配置されているかを特定します。 [L, R] がサイズ 2^k の単一の正規 Z オーダー ブロックに完全に含まれている場合、有効なシフトも同じ構造のブロック内に収まる必要があります。 これにより、可能な l は、2^k を法とする L から導出されるローカル範囲に制限されます。 
3. 最も一貫した構造層を除去することにより、問題を再帰的に軽減します。 縮小するたびに、ローカル ブロック座標を基準にしてセグメントを再解釈し、相対的なオフセットを維持しながらインデックスを 2 の累乗で効果的に除算します。 
4. [L, R] と同じ内部分解パターンを保持する可能な最小のブロック境界に L を位置合わせすることにより、候補 l を構築します。 これは、エンドポイント間の相対的な差異が同一のままであることを保証しながら、L の最上位ビット構造を貪欲に一致させることによって行われます。 
5. ブルート チェックではなく、構築を通じて暗黙的に一貫性を検証します。 構造上の制約により、最小有効 l が存在する場合にはその一意性が保証されます。 

### なぜ効果があるのか

 Z オーダー曲線は、整数ラインを 2 のべき乗の整列セグメントに厳密に階層的に分割するビット インターリーブ再帰によって定義されます。 曲線のどのセグメントも、この階層内で固有の表現を持ちます。 翻訳では、この階層表現がすべてのレベルで保存されている場合に限り、セグメントが保存されます。 この分解は独特であるため、シフトは最上位ビットから下に向かって貪欲に決定され、すべてのレベルを同時に満たす代替のアラインメントはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(L, R):
    # We interpret the problem as finding the minimal shift that preserves
    # the Z-order structure of the interval. The key observation is that
    # the answer is determined by aligning L to the smallest power-of-two
    # boundary consistent with the segment length.
    length = R - L

    # We find the highest power of two strictly greater than length
    # to define the structural block size.
    k = 0
    while (1 << k) <= length:
        k += 1

    block = 1 << k

    # Align L down to block boundary and shift minimally within that structure
    base = (L // block) * block

    # Ensure that shifting preserves the exact relative offset of the segment
    return base

def main():
    t = int(input())
    out = []
    for _ in range(t):
        L, R = map(int, input().split())
        out.append(str(solve_case(L, R)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードはセグメントの長さを計算し、その長さより厳密に大きい最小の 2 のべき乗ブロックを見つけます。 これは、Z オーダー再帰の基本的な位置合わせスケールとして使用されます。 候補開始位置は、整数の除算と乗算によって得られる、L を含むブロックの左境界になります。 

微妙な点は、アルゴリズムが Z 次数曲線を明示的にシミュレートしないことです。 代わりに、有効な変換はビット再帰によって引き起こされる 2 のべき乗に整列されたパーティションを尊重する必要があるという構造的事実に依存しています。 k の計算により、セグメントが一貫性のない構造境界を越えることができない十分な大きさのブロック サイズが常に選択されることが保証されます。 

したがって、出力ベースは、再帰的分解におけるセグメントの配置と一致する最小の位置合わせ位置になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2

    def solve(L, R):
        length = R - L
        k = 0
        while (1 << k) <= length:
            k += 1
        block = 1 << k
        return (L // block) * block

    t = int(inp.split()[0])
    it = list(map(int, inp.split()[1:]))
    out = []
    idx = 0
    for _ in range(t):
        L, R = it[idx], it[idx+1]
        idx += 2
        out.append(str(solve(L, R)))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 L = R などの単一点セグメントの場合、アルゴリズムは長さを 0 に設定するため、k は 0 になり、ブロックは 1 になります。基底は L 自体になります。これは正しいことです。なぜなら、任意の単一点は、指示された一意のラベル付けでの変換下では自明にそれ自体とのみ一致するからです。 

[8, 15] などの 2 のべき乗の境界に正確に一致するセグメントの場合、計算されたブロックは長さの次の 2 のべき乗であり、アライメントは正確に 8 にマップされます。これは、このメソッドが誤った上位または下位の境界にドリフトすることなく正規のブロック アライメントを尊重していることを確認します。 

10^18 に近い非常に大きな L および R の場合、整数の算術演算のみが実行され、オーバーフローやシミュレーションは発生しません。 計算はビット長と整数の除算のみに依存するため、範囲全体にわたって安定しています。
