 ## 解決策
 ## 問題の理解

 一連の点が与えられ、それらは 1 つずつ到着します。 各点は人物を座標で表します$(x_i, y_i)$。 長さのプレフィックスごとに$t$、最初のものだけを考慮します$t$ポイントがあり、注文されたペアの数を数えたいとします$(i, j)$このプレフィックス内では、非常に特殊な二重極値特性が満たされます。 

固定の人にとっては$i$では、現在のプレフィックス内の他のすべての人を調べて、2 つの距離の尺度を定義します。 1 つはチェビシェフ距離で、水平方向と垂直方向の差の最大値です。 もう 1 つはマンハッタン距離で、差の絶対値の合計です。 の「親友」$i$～とのチェビシェフ距離を最大化する人物は誰ですか$i$プレフィックス内にあります。 ～の「最悪の敵」$i$～からのマンハッタンまでの距離を最大化する人は誰ですか$i$プレフィックス内にあります。 

タスクは、すべてのプレフィックスについて、順序付けられたペアの数を維持することです。$(i, j)$どこ$j$彼は親友であると同時に最悪の敵でもある$i$。 

制約は非常に大きく、最大で$4 \cdot 10^5$ポイント。 プレフィックスごとに関係を最初から再計算しようとするソリューションでは、次のオーダーが必要になります。$n^2$制限時間をはるかに超えた距離チェック。 各ペアを 1 回だけ処理するソリューションであっても、各ペアが定数時間または対数時間で処理されない限り、依然として困難を伴います。 

重要な構造上の問題は、定義がプレフィックス内のグローバル最大値に依存するため、新しいポイントを追加すると、以前の多くのポイントに対して有効なペアが変わる可能性があることです。 これにより、グローバルな幾何学的構造を理解せずに、新しいポイントの周囲のローカル情報のみを更新するアプローチは即座に除外されます。 

「極端な」点のセットが時間の経過とともに変化する場合、微妙なエッジケースが現れます。 たとえば、最初に点が x または y で極端にない場合、その点はマンハッタン距離の考慮では永遠に無関係になる可能性がありますが、以前のプレフィックスでのチェビシェフ距離の比較では依然として潜在的に重要です。 これは、各点が時間に依存しない固定された小さな比較セットにのみ参加するという単純な仮定を無効にします。 

## アプローチ

 ブルートフォース手法は簡単です。 各プレフィックスとその内部の各順序ペアについて、両方の距離を計算し、2 番目の要素が同時に最初の要素のチェビシェフ距離とマンハッタン距離の最大値であるかどうかを確認します。 これにはすべてをスキャンする必要があります$O(t)$それぞれの候補者$i$、生産$O(n^3)$すべてのプレフィックスにわたる合計操作、またはせいぜい$O(n^2)$プレフィックスごとに最適化された場合。 と$n = 4 \cdot 10^5$、これは不可能です。 

主な構造の簡素化は、「プレフィックス内のマンハッタン距離の最大化」が実際に何を意味するかを理解することから生まれます。 任意の点からのマンハッタンの最も遠い距離は、常に、現在の軸に揃えられた境界ボックスの 4 つの隅の 1 つで達成されます。$(\min x, \min y)$、$(\min x, \max y)$、$(\max x, \min y)$、 または$(\max x, \max y)$。 したがって、最悪の敵は常にこれらの最大 4 つのポイントの中にあります。 

似ていますが、もう少し微妙な事実がチェビシェフ距離にも当てはまります。 固定点からの最も遠いチェビシェフ距離$i$一連の候補にわたるどれがどれくらいであるかは、x または y の極端な違いによって決定され、重要な候補はやはり境界ボックスの隅です。 これにより、すべての検索スペースが削減されます。$i$候補者は最大でも 4 人までです。 

この観察により、問題はプレフィックスの最大 4 つの「アクティブなコーナー ポイント」からなる小さな動的セットの追跡に変わります。 各プレフィックスについて、これらのコーナーのみが有効な候補となりえます。$j$。 さらにペアで$(i, j)$は次の場合にのみ有効です$j$ここはこれらの角の 1 つであり、チェビシェフで最も遠い角の 1 つでもあります。$i$。 

したがって、すべてのペアを考慮するのではなく、各ペアがどのようにポイントするかのみを考慮します。$i$最大 4 つの動的コーナー ポイント間で「投票」します。 タスク全体が各コーナーごとにメンテナンスになります$c$、前のポイントの数を考慮します$c$チェビシェフの距離の下で彼らの最も遠い角になります。 

難しいのは、コーナー セットが時間の経過とともに変化し、それが変化すると、以前のポイントの分類も変化する可能性があることです。 ただし、コーナー セットは、新しい点が x または y の新しい最小値または最大値になった場合にのみ変更されるため、各更新はこれら 4 つの極値点によって定義された構造にのみ影響し、過去のすべての点が恣意的に影響を受けるわけではありません。

 ## アルゴリズムのチュートリアル

 現在の境界ボックスとその最大 4 つのコーナーポイントを維持しながら、ポイントを順番に処理します。 

1. 現在の最小値と最大値を維持します。$x$そして$y$プレフィックスの上に。 これらから、最大 4 つのコーナーポイントを定義します。$(\min x, \min y)$、$(\min x, \max y)$、$(\max x, \min y)$、 そして$(\max x, \max y)$。 これらは、プレフィックスのどのポイントにおいても最悪の敵となり得る唯一の候補です。 
2.新規ポイントの場合$t$到着したら、境界ボックスを更新します。 もし$t$4 つのコーナーのいずれにもならないため、それ以前のポイントにとって最悪の敵になることはできません。そのため、有効なペアには寄与しません。$j$。 その場合、可能なものとしての役割だけが$i$問題は後であり、それ以上何もすることはありません$j$。 
3. もし$t$新しいコーナーになると、現在のアクティブなコーナーのセットを再計算します。 このセットのサイズは最大 4 で、更新された極値点で構成されます。 
4. 各ポイントについて$i < t$かどうかを判断します。$t$はその親友の一人です。 親友はまさにチェビシェフとの距離を最大化するコーナーであるため、比較します。$i$各アクティブコーナーまでのチェビシェフ距離を計算し、最大値を見つけます。 
5. この最大値に達するコーナーの数を数えます。 もし$t$その中には$(i, t)$は、現在のプレフィックスの有効な順序ペアです。 
6. このカウントをプレフィックスの答えに追加します$t$、また対称的に説明されます。$(t, i)$順序定義で必要な場合。 

重要な不変条件は、どのプレフィックスでも、すべての有効なプレフィックスが存在することです。$j$は境界ボックスの隅である必要があり、それぞれ$i$、その親友の正体は、せいぜいこれらの四隅との比較にのみ依存します。 コーナー セットは時間の経過とともに進化しますが、各ステップで固定プレフィックスの決定は外接する四角形の現在のジオメトリのみに依存し、コーナー以外の点がどちらの距離メトリックもグローバルに支配することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    
    minx = miny = 10**18
    maxx = maxy = -10**18
    
    # store points
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
    
    # current corners as indices
    corners = set()
    
    # helpers
    def cheb(a, b):
        return max(abs(a[0] - b[0]), abs(a[1] - b[1]))
    
    res = [0] * n
    
    for t in range(n):
        x, y = pts[t]
        
        # update bounding box
        minx = min(minx, x)
        maxx = max(maxx, x)
        miny = min(miny, y)
        maxy = max(maxy, y)
        
        # recompute corners
        cand = []
        cand.append((minx, miny))
        cand.append((minx, maxy))
        cand.append((maxx, miny))
        cand.append((maxx, maxy))
        
        # remove duplicates
        S = list(set(cand))
        
        # find which points are actual indices (we map coords to last occurrence)
        coord_to_idx = {}
        for i in range(t + 1):
            coord_to_idx[pts[i]] = i
        
        corner_idx = []
        for c in S:
            if c in coord_to_idx:
                corner_idx.append(coord_to_idx[c])
        
        # process contributions if current point is a corner
        if t in corner_idx:
            total = 0
            for i in range(t):
                best = 0
                d_t = 0
                for j in corner_idx:
                    d = cheb(pts[i], pts[j])
                    best = max(best, d)
                d_t = cheb(pts[i], pts[t])
                if d_t == best:
                    total += 1
            res[t] = total
        else:
            res[t] = 0
    
    for i in range(n):
        print(res[i])

if __name__ == "__main__":
    solve()
```この実装は、境界ボックスの角を維持し、新しい点がそれらの角の 1 つになった場合にのみチェックするという考えに従っています。 機能`cheb`チェビシェフ距離を直接計算します。 座標からインデックスへのマッピングは、プレフィックス内に実際に存在するコーナーポイントを識別するために使用されます。 

重要な点は、コーナーポイントのみが最悪の敵となる可能性があるため、すべてのチェックをコーナーポイントに制限することです。 2 番目の微妙な点は、固定ごとに$i$、最大 4 つの候補との距離を比較するだけでよいため、各チェックの範囲が制限されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、境界ボックスが 1 つまたは 2 つの一意の点のみで定義されている場合です。 その状況では、「4 つの角」がより少ない候補に分割されるため、アルゴリズムは欠落している角を有効なインデックスとして扱うことを避ける必要があります。 例えばポイントの場合$(1,1)$そして$(5,1)$、コーナー セットには 2 つの一意の点のみが含まれます。 このアルゴリズムは既存の候補との比較を適切に制限するため、無効なペアはカウントされません。 

もう 1 つのケースは、新しく追加された点がコーナーになるものの、4 つの極点すべてが変化しない場合です。 たとえば、最大 x のみが変更される場合、コーナー セットは前のセットと部分的にオーバーラップします。 アルゴリズムは引き続き、更新された境界ボックスからコーナー リストを再計算するため、過去のコーナー ID に依存することなく一貫性が維持されます。 

3 番目の微妙なケースは、異なる順序付け効果の下でジオメトリが重複することです。 すべての座標は少なくとも 1 次元で異なるため、2 つの点が一致することはありません。これにより、コーナーの識別が明確になり、同一候補の二重カウントが防止されます。
