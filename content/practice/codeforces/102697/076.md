 ## 解決策
 ## 問題の理解

 瓶はから始まります`n`キャンディー。 その後、キャンディが盗まれた最初の日から始めて、観察された日ごとに瓶の中にまだ残っているキャンディの数が与えられます。 毎日、前回の観察以降に消えたキャンディーの数を判断する必要があります。 

最初の観測値は元の量と比較されます`n`。 その後の観測ごとに、前日の残量と比較されます。 残額があれば、`n = 100`、 に続く`97 92 85`、

 それなら窃盗は`100 - 97 = 3`、`97 - 92 = 5`、 そして`92 - 85 = 7`。 

出力には、観測日ごとに 1 つの整数が含まれており、その日に盗まれたキャンディーの数を表します。 

公開された問題では、毎日の観測数に有用な上限が指定されていないため、最も安全な複雑さの目標は入力量が線形になります。 対応する答えを生成するには、すべての残りのキャンディーの値を少なくとも 1 回検査する必要があるため、`O(m)`の時間`m`観察が最適です。 二次アプローチでは、以前の観測を繰り返し再検討することになり、入力が増大するにつれて不必要にコストがかかることになります。 Python の整数では、減算を実行する際のオーバーフローの心配も回避されます。 

誤って処理されやすい境界ケースがいくつかあります。 観測値が 1 つしかない場合は、以前の日次値がないため、最初の量と直接比較する必要があります。 例えば、```
10
7
```生成する```
3
```毎日のリストの隣接する要素を減算することから始める不用意な実装では、まったく答えが得られません。 

初日の盗難は、翌日の盗難よりも​​規模が大きくなる可能性もあります。 例えば、```
20
13 12 5
```生成する```
7
1
7
```計算では、盗難金額が一定であると仮定するのではなく、常に直前の金額を使用する必要があります。 

最後に、2 つの連続する観測値が偶然に等しい場合でも、算術演算を実行する必要があります。 例えば、```
10
7 7 4
```生成する```
3
0
3
```元の問題では量が減少していると説明されていますが、入力を連続した観測値として扱うことで減算ルールが明示的になり、不注意な実装による等しい値のスキップが防止されます。 

## アプローチ

 ここでは、直接的なアプローチがすでに最適です。 ブルートフォース実装では、毎日、以前のすべての観察を逆方向に検索して、その日の直前に存在していたキャンディーの数を再構築できます。 以前の量が最終的に見つかった場合でもこれは正しいでしょうが、最悪の場合、約`m(m-1)/2`の比較`m`観察、つまり`O(m²)`仕事。 

入力の構造により、そのような検索はすべて不要になります。 今日の盗難を計算するために必要な唯一の値は、昨日のキャンディーの残りの数です。 歴史全体は必要ありません。 オリジナルから始める`n`、毎日の各値を読み取ります`x`、計算する`previous - x`、その違いを出力してから置き換えます`previous`と`x`。 

ブルートフォースアプローチは、入力履歴から以前の量を回復できるため機能しますが、履歴が順次処理できるという事実を利用できません。 各答えは直前の残量のみに依存するという観察により、問題は 1 つのパスに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(m) | 大量の入力には遅すぎる |
 | 最適 | O(m) | O(1) 補助スペース | 承認済み |

 ここ`m`毎日の観測数です。 

## アルゴリズムのチュートリアル

 1. 瓶の中のキャンディーの初期数を読み取り、次のように保管します。`previous`。 これは、初日の観察と比較する必要がある量です。 
2. 残りの毎日の観察をすべて読みます。 各値は、その日の盗難後に残ったキャンディーの数を表します。 
3. 観測値ごとに`current`、計算します`previous - current`。 これは、2 つの観測の間に除去されたキャンディーの数とまったく同じです。 
4. その差分を出力に追加して設定します`previous = current`。 当日の残額が翌日に必要な前回の金額となります。 
5. 計算された差分をすべて 1 行に 1 つずつ出力します。 観測値を指定された順序で処理すると、減算に必要な時系列関係が維持されます。 

### なぜ効果があるのか

 不変条件は、毎日の観測を処理する直前に`current`、`previous`その日の盗難前に瓶に入っていたキャンディーの数が正確に含まれています。 最初の観察では、これは真実です。`previous`初期金額としてスタート`n`。 1 日の処理後に割り当て`previous = current`次の日の不変式を true にします。 1 日に盗まれた数は、正確に盗難前の金額から盗難後の金額を引いたものであるため、生成されるすべての差は正しいことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    remaining = list(map(int, sys.stdin.read().split()))

    previous = n
    answer = []

    for current in remaining:
        answer.append(str(previous - current))
        previous = current

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```最初の行は初期化します`previous`元のキャンディーの数で。 残りの入力は次のように読み取られます。`sys.stdin.read()`2 行目に特定の数の値を想定するのではなく、 これは、一連の観察としての 2 行目の問題の記述に従いますが、通常の空白の書式設定に対してもソリューションを堅牢にします。 

ループは、観測ごとに 1 回だけ減算を実行します。 課題`previous = current`差を計算した後に発生する必要があります。 これら 2 つの演算を逆にすると、すべての減算がゼロになります。 

出力は文字列として蓄積され、最後に 1 回書き込まれます。 これにより、繰り返し呼び出しを避けることができます`print`、観測値が多い場合に便利です。 Python には整数オーバーフローの問題はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m) | 毎日の観測はすべて 1 回だけ処理されます。 
| スペース | O(m) | 実装では、観察結果と出力文字列を書き込む前に保存します。 

計算自体は、`O(1)`補助的な状態、つまり`previous`。 提示された実装は、観測値を完全なシーケンスとして読み取るため、入力と出力を保存します。 それでも、入力サイズでは線形です。 この問題では観測値の数に明示的な大きな制限がないため、線形処理が適切なターゲットであり、履歴を繰り返し検索する二次関数の動作を回避します。 

## テストケース```python
import sys
import io

def solve():
    n = int(input())
    remaining = list(map(int, sys.stdin.read().split()))

    previous = n
    answer = []

    for current in remaining:
        answer.append(str(previous - current))
        previous = current

    sys.stdout.write("\n".join(answer))

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output

        try:
            solve()
        finally:
            sys.stdout = old_stdout

        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run(
    "100\n"
    "97 92 85 80 72 65\n"
) == "3\n5\n7\n5\n8\n7", "sample 1"

# Minimum-size observation sequence
assert run(
    "10\n"
    "7\n"
) == "3", "single observation"

# All values equal, exercising a zero difference
assert run(
    "10\n"
    "7 7 4\n"
) == "3\n0\n3", "equal consecutive observations"

# Boundary-style decreasing sequence
assert run(
    "5\n"
    "4 3 2 1\n"
) == "1\n1\n1\n1", "consecutive one-candy thefts"

# Large input size
large = "100000\n" + " ".join(
    str(100000 - i) for i in range(1, 100000)
) + "\n"
expected = "\n".join(["1"] * 99999)
assert run(large) == expected, "large linear input"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`10 / 7`|`3`| 毎日の観察 |

 ## 特殊なケース

 単一の観測の場合、次のような```
10
7
```アルゴリズムはで始まります`previous = 10`、読みます`current = 7`、そして計算します`10 - 7 = 3`。 その後更新されます`previous`に`7`そして終わります。 出力は`3`。 以前の毎日の観測値にアクセスしようとすることはないため、オフバイの問題は発生しません。 

盗難金額が異なる場合は、次の点を考慮してください。```
20
13 12 5
```最初の反復で計算します`20 - 13 = 7`、2番目は計算します`13 - 12 = 1`、3番目は計算します`12 - 5 = 7`。 出力は`7`、`1`、`7`。 このアルゴリズムは、毎日同じ数のキャンディーが盗まれることを想定していません。 

等しい連続観測については、次のことを考慮してください。```
10
7 7 4
```最初の違いは`10 - 7 = 3`。 そのときの状態は、`7`したがって、2 番目の違いは次のとおりです。`7 - 7 = 0`。 最終的に状態はこうなります`7`もう一度言いますが、最後の違いは`7 - 4 = 3`。 出力は`3`、`0`、`3`。 逐次減算では、特別なケースを必要とせずに、これを自然に処理します。
