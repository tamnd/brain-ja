 ## 解決策
 ## 問題の理解

 (0) から (C) までの区間で、ユーザーが指定した関数 (f(x)) の下の面積を数値的に近似する必要があります。 関数は変数を含む算術式として与えられます。`x`、数字、括弧、加算、減算、乗算、除算、累乗`^`。 次のように、乗算を暗黙的に記述することもできます。`5x`。 

必要な近似は、具体的には左方形近似法です。 間隔は正確に (N=50000) 個の等しい幅の長方形に分割されます。 各長方形は幅 (C/N) を持ち、長方形 (k) の高さは (f(kC/N)) (k=0,\ldots,N-1) です。 したがって、必要な量は

 [
 A=\frac{C}{N}\sum_{k=0}^{N-1}f\left(\frac{kC}{N}\right)。 
】

 公式問題では (N=50000) と指定されており、256 MB のメモリで 10 秒の制限時間が与えられます。 評価ポイントの固定数は十分に大きいため、式を繰り返し解析するとコストがかかりすぎます。 式を 1 回解析し、繰り返し評価できる形式に変換してから、50,000 回評価する必要があります。 

主な重要な制約は (C) のサイズではなく、関数の評価が繰り返されることです。 式に (m) 個の演算子とオペランドが含まれる場合、サンプル ポイントごとに独立して評価するとコストがかかります (O(50000m))。 これは、適切なサイズの式では許容されますが、元の文字列を最初から 50,000 回解析または解釈すると、不要なオーバーヘッドが追加されます。 

公開された例には微妙な問題もあります。 2つ目の公式サンプルは、```
(x^2 + x + 3) / (x^3 + x^2 + 5x)
7
```出力付き`0.9806709605550483`。 記載された LRAM 定義では、分母がゼロであり、ゼロからの数値積分にも対数特異点があるため、(f(0)) は未定義です。 したがって、そのサンプルは、現在のステートメントに出力されている式に数学的に対応することはできません。 1 番目と 3 番目のサンプルは、記載されている LRAM の式と一致しています。 これは、アーカイブされた問題ステートメントのエラーと思われるため、実装では、矛盾するサンプルに対して特別な動作を考案するのではなく、正式な定義に従う必要があります。 

有効な式の場合、エッジ ケースは定数関数です。 例えば、```
5
2
```は (f(x)=5) なので、すべての長方形の高さは 5 であり、答えは正確に次のようになります。`10`。 誤ってエンドポイントのみを評価する不注意な実装がここでも機能する可能性があり、誤ったサンプリング戦略が隠蔽される可能性があります。 

もう 1 つの有用な境界ケースは、値がゼロ付近で急速に変化する関数です。 のために```
x^2
1
```最初の左側のサンプルは正確に (x=0) であるため、その高さはゼロです。 残りのサンプルは正しい終点に近づきますが、それを含むことはありません。 右エンドポイントの実装では、両方の方法が長方形の数が増加するにつれて同じ積分に収束する場合でも、異なる近似が計算されます。 

## アプローチ

 直接的な総当たりアプローチでは、式を繰り返し読み取り、(x) の値ごとにそれを解釈します。 これは正しいです。各評価では、LRAM 式で必要な長方形の高さが正確に計算されます。 問題は、同じ構文作業が 50000 回実行されることです。 式に (m) 個のトークンがある場合、解釈だけで (O(50000m)) のコストがかかり、文字列の繰り返しのスキャンと解析による追加のオーバーヘッドが発生します。 より不注意なブルート フォースは、部分文字列を再帰的に再解析する場合、さらに悪質になる可能性があり、(O(50000m^2)) に近づく可能性があります。 

有益な観察は、式自体は決して変わらないということです。 に割り当てられた値のみ`x`変化します。 式を一度解析して、後置記法とも呼ばれる逆ポーランド記法に変換できます。 例えば、```
x^3 + 2*x
```概念的になる```
x 3 ^ 2 x * +
```後置シーケンスには式の完全な構造が含まれているため、それを評価して次の新しい値を求めます。`x`浮動小数点値のスタックのみが必要です。 最初の変換後は解析は必要ありません。 

パーサーは暗黙的な乗算も処理します。 価値を生み出すトークンの直後に、次のような別の価値を生み出すトークンが続く場合`5x`または`2(x+1)`、乗算が自動的に挿入されます。 明示的なもののみを扱うため、これは重要です`*`乗算では有効な入力が正しく解析されないためです。 

結果のアルゴリズムは 1 回解析し、後置式を 50000 回評価し、四角形の高さを累積します。 2 つのアプローチは次のように比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサンプルの式を再解析する | パーサーによっては (O(Nm)) またはそれより悪い | (O(m)) | 遅すぎて不必要 |
 | 一度解析して後置を評価します | (O(m + Nm)) | (O(m)) | 承認済み |

 ここで (m) は式のサイズであり、(N=50000) です。 

## アルゴリズムのチュートリアル

 1. 式と値を読み取ります (C)。 空白は算術構文とは無関係であるため、解析中に式はそのままにしておく必要があるため、パーサーは最初に空白を削除します。 
2. 式を数値、変数にトークン化します。`x`、演算子、括弧。 数値は、複数の桁が含まれている場合でも 1 つのトークンとして扱われます。 
3. 通常の算術優先順位に従ってトークンを解析します。 加算と減算の優先順位が最も低く、次に乗算と除算が続き、累乗の優先順位が高くなります。 かっこはこれらのルールをオーバーライドします。 
4. 乗算を解析する際、明示的な乗算と暗黙的な乗算の両方を認識します。 たとえば、本を読んだ後、`5`、次のトークン`x`別の要素が始まるため、パーサーはシーケンスを次のように解釈します。`5 * x`。 同じルールで次のような式も許可されます。`2(x+1)`。 
5. 解析された式を後置表記に変換します。 演算子はオペランドの後に配置されるため、評価で優先順位を決定する必要がなくなりました。 
6. (N=50000) を設定し、共通の長方形の幅を (C/N) として計算します。 0 から (N-1) までのすべての (k) について、(x=kC/N) を計算します。 
7. この値を使用して後置式を評価します。`x`。 数値はその値をスタックにプッシュします。`x`は現在のサンプル座標をプッシュし、演算子はそのオペランドをポップして演算を実行し、結果をプッシュします。 
8. 評価された高さを現在の合計に加算します。 すべての長方形の幅は同じであるため、最終的な面積は、すべての高さの合計に (C/N) を掛けたものになります。 
9. 結果の浮動小数点値を出力します。 裁判官は近似比較を使用するため、特定の小数点以下の桁数を再現する必要はありません。 

機能する理由: 解析後、後置式は入力とまったく同じ算術式を表します。 評価スタックは、後置式の接頭辞を処理した後、スタック上のすべての値が 1 つのすでに完了した部分式の結果であるという不変条件を維持します。 したがって、演算子が処理されるとき、そのオペランドはその演算子が必要とする値とまったく同じになります。 したがって、各評価は現在のサンプル点の (f(x)) を返します。 外側のループは 50000 個の左側のエンドポイント (kC/N) を正確に評価するため、それらの合計に (C/N) を乗算すると、問題で指定された LRAM の近似値が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = 50000

def tokenize(s):
    s = ''.join(s.split())
    tokens = []
    i = 0

    while i < len(s):
        c = s[i]

        if c.isdigit() or c == '.':
            j = i
            while j < len(s) and (s[j].isdigit() or s[j] == '.'):
                j += 1
            tokens.append(('num', float(s[i:j])))
            i = j

        elif c == 'x':
            tokens.append(('x', None))
            i += 1

        else:
            tokens.append((c, None))
            i += 1

    return tokens

def is_value_end(token):
    return token[0] in ('num', 'x', ')')

def is_value_start(token):
    return token[0] in ('num', 'x', '(')

def to_postfix(tokens):
    output = []
    operators = []

    precedence = {
        '+': 1,
        '-': 1,
        '*': 2,
        '/': 2,
        '^': 3,
        'u+': 4,
        'u-': 4,
    }

    right_assoc = {'^', 'u+', 'u-'}

    prev = None

    for token in tokens:
        typ = token[0]

        if typ == 'num' or typ == 'x':
            if prev is not None and is_value_end(prev):
                while operators and operators[-1] != '(':
                    top = operators[-1]
                    if (
                        precedence[top] > precedence['*']
                        or (
                            precedence[top] == precedence['*']
                            and '*' not in right_assoc
                        )
                    ):
                        output.append(operators.pop())
                    else:
                        break
                operators.append('*')

            output.append(token)
            prev = token
            continue

        if typ == '(':
            if prev is not None and is_value_end(prev):
                while operators and operators[-1] != '(':
                    top = operators[-1]
                    if precedence[top] >= precedence['*']:
                        output.append(operators.pop())
                    else:
                        break
                operators.append('*')

            operators.append('(')
            prev = token
            continue

        if typ == ')':
            while operators and operators[-1] != '(':
                output.append(operators.pop())
            operators.pop()
            prev = token
            continue

        if typ in '+-':
            unary = prev is None or prev[0] in ('+', '-', '*', '/', '^', '(')
            op = 'u+' if unary and typ == '+' else 'u-' if unary else typ

            while operators and operators[-1] != '(':
                top = operators[-1]
                if (
                    precedence[top] > precedence[op]
                    or (
                        precedence[top] == precedence[op]
                        and op not in right_assoc
                    )
                ):
                    output.append(operators.pop())
                else:
                    break

            operators.append(op)
            prev = (op, None)
            continue

        if typ in '*/^':
            op = typ

            while operators and operators[-1] != '(':
                top = operators[-1]
                if (
                    precedence[top] > precedence[op]
                    or (
                        precedence[top] == precedence[op]
                        and op not in right_assoc
                    )
                ):
                    output.append(operators.pop())
                else:
                    break

            operators.append(op)
            prev = token
            continue

    while operators:
        output.append(operators.pop())

    return output

def evaluate(postfix, x):
    stack = []

    for token in postfix:
        typ = token[0]

        if typ == 'num':
            stack.append(token[1])
        elif typ == 'x':
            stack.append(x)
        elif typ == 'u+':
            stack[-1] = +stack[-1]
        elif typ == 'u-':
            stack[-1] = -stack[-1]
        else:
            b = stack.pop()
            a = stack.pop()

            if typ == '+':
                stack.append(a + b)
            elif typ == '-':
                stack.append(a - b)
            elif typ == '*':
                stack.append(a * b)
            elif typ == '/':
                stack.append(a / b)
            else:
                stack.append(a ** b)

    return stack[0]

def solve():
    expression = input().strip()
    C = float(input())

    tokens = tokenize(expression)
    postfix = to_postfix(tokens)

    width = C / N
    total = 0.0

    for k in range(N):
        x = k * width
        total += evaluate(postfix, x)

    print(total * width)

if __name__ == "__main__":
    solve()
```スペースは式内で数学的な意味を持たないため、トークナイザーは空白を削除します。 次に、連続する数字を 1 つの数値トークンにグループ化し、次の処理を行います。`x`別に。 

postfix への変換では、優先順位が解決されます。 括弧は、対応する右括弧が表示されるまで演算子スタックに保持されます。 べき乗は右結合なので、次のような式になります。`x^2^3`は ((x^2)^3) ではなく (x^{(2^3)}) として解釈されます。 

単項符号は、二項加算および減算とは別に処理されます。 これにより、次のような表現が可能になります。`-x`、`x*-2`、 そして`-(x+1)`単項マイナスを減算と混同せずに表すことができます。 

評価関数は意図的に`x`後置式を変更する代わりに引数として使用します。 したがって、同じ解析された式が 50000 個のサンプル ポイントすべてに対して再利用されます。 

ループは使用します`range(N)`、 ない`range(1, N)`これは、LRAM がすべての四角形の左端点をサンプリングするためです。 最後にサンプリングされた座標は、`(N-1)*C/N`したがって、右のエンドポイント (C) は評価されません。 の乗算`width`は合計の後に 1 回だけ発生します。これは、代数的にすべての四角形を個別に乗算することと同じです。 

Python の浮動小数点数は、タスクのおおよその性質に対して十分な精度を提供します。 Python の整数にも制限がないため、数値リテラルは評価のために浮動小数点に変換されますが、数値定数の読み取り中に整数オーバーフローの問題は発生しません。

    for typ, value in postfix:

# Minimum-size constant expression
out = float(solve_string("5\n2\n"))
assert math.isclose(out, 10.0, rel_tol=1e-12, abs_tol=1e-12)

# All samples are identical in height, so the LRAM result is exact
out = float(solve_string("7\n100\n"))
assert math.isclose(out, 700.0, rel_tol=1e-12, abs_tol=1e-12)

# Implicit multiplication and parentheses
out = float(solve_string("2(x + 1)\n3\n"))
assert math.isclose(out, 15.0, rel_tol=1e-9, abs_tol=1e-9)

# Boundary-sensitive left endpoint: x^2 on [0, 1]
out = float(solve_string("x^2\n1\n"))
assert 0.33330 < out < 0.33335

 ## 特殊なケース

 定数関数には特別な処理は必要ありません。 正確な入力のために```
5
2
```パーサーは単一の数値を作成します。 50000 件の評価はそれぞれ 5 を返し、累積された高さは 250000 で、幅 (2/50000) を掛けるとちょうど 10 になります。アルゴリズムは次のことを決して想定しません。`x`という表現が現れます。 

暗黙的な乗算を含む式には、明示的なパーサーのサポートも必要です。 のために```
2(x + 1)
3
```パーサーは乗算演算子を間に挿入します。`2`そして`(`。 結果の関数は (2(x+1)) で、0 から 3 までの積分は 15 です。リテラルのみを認識するパーサー`*`この式を拒否するか、誤って解釈することになります。 

左側の端点は別の境界条件です。 のために```
x^2
1
```最初の評価では (x=0) が使用され、高さはゼロになります。 最終的な評価では、(x=1) ではなく (x=49999/50000) が使用されます。 結果の LRAM 推定値は、正確な積分 (1/3) をわずかに下回ります。これは、増加関数の左端点近似の予想される動作です。 

単項減算もパーサー エラーを引き起こす可能性があります。 と```
-(x + 1)
2
```パーサーは最初のものを処理する必要があります`-`二項減算ではなく単項演算子として。 評価される各高さは負の値であり、数値面積は約 (-4) です。 先頭のマイナスを二項演算子として扱うと、左オペランドのない式が残ります。 

最後に、公開された 2 番目のサンプルは、ソリューションを検証するときに特別な処理が必要になります。 その分母は (x=0) でゼロと評価されますが、関数はゼロ付近では (3/(5x)) のように動作します。 したがって、記載されている LRAM 式では、公開されている有限値を生成できません。`0.9806709605550483`。 この矛盾に対する正しい対応は、数学的問題を変えるサンプル固有の例外を追加するのではなく、正式なアルゴリズムと有効なテスト データに従うことです。
