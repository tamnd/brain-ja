 ## 解決策
 ## 問題の理解

 このタスクは、すべてのアルファベットの大文字と小文字を変更して 1 つの文字列を変換することです。 大文字は小文字になる必要があり、小文字は大文字になる必要があります。 文字自体は同じ位置に留まり、このステートメントにより、文字列にはスペースやその他の記号が含まれず、英語の文字のみが含まれることが保証されます。 公式問題では、1 秒の時間制限と 256 MB のメモリ制限が指定されています。 

たとえば、入力`HeLlO`になる`hElLo`。 各位置は独立して処理されるため、文字間の相互作用はなく、配列、マップ、グラフなどのデータ構造も必要ありません。 

このステートメントでは、入力が 1 つの文字列であるという以外に、文字列の長さに関する有用な明示的な上限は公開されていません。 隠れた長さの制限に関係なく、アルゴリズムは少なくともすべての文字を読み取る必要があるため、長さ n の文字列では Ω(n) 時間は避けられません。 二次解法は、すでに見た文字を繰り返し処理することになるため、n が大きくなるにつれて不適切になります。 リニア スキャンは、キャラクタごとに一定量の作業のみを実行するため、自然なターゲットとなります。 

主なエッジケースはシンプルですが、誤って扱いやすいものです。 次のような 1 文字の文字列`A`生産すべき`a`、唯一のキャラクターをまだ切り替える必要があるためです。 小文字のみを含む文字列 (例:`abc`、生成する必要があります`ABC`; 大文字のみを変換する実装では、誤って入力が変更されないままになります。 同様に、`ABC`にならなければなりません`abc`。 最後に、次のような混合文字列`aBcD`にならなければなりません`AbCd`したがって、実装は文字列全体に 1 つの変換を適用するのではなく、位置ごとに独立して決定する必要があります。 

## アプローチ

 直接的な総当たり解釈では、各文字を処理し、現在の文字が見つかるまで、考えられるすべての大文字と小文字を含むコレクションを検索します。 対応するものが見つかったら、その対応するものを答えに追加します。 すべての入力文字は 52 個の英語アルファベットの 1 文字に正確に属するため、これは正しいです。 

検索で入力文字ごとに最悪のケースで 52 個の可能な文字がチェックされる場合、長さ n の文字列では最大 52n 文字の比較が必要になる可能性があります。 52 は定数であるため、これは技術的には O(n) であり、多くの強引なアプローチとは異なり、漸近的に遅くなりすぎることはありません。 この弱点は、文字値から大文字と小文字を直接判断できる場合に、不必要な比較を実行することです。 

重要な点は、Python で使用される文字エンコーディングでは、英語の大文字と小文字が連続した範囲を占めていることです。 さらに便利なことに、Python は必要な変換をすでに公開しています。`str.swapcase()`。 ライブラリ操作に依存するのではなく、基礎となるアルゴリズムを理解したい場合は、文字が次の場所にあるかどうかを検査できます。`a`を通して`z`または`A`を通して`Z`2 つのケース間で固定 ASCII 距離だけ移動します。 

すべての文字をその逆の大文字と小文字にマッピングできるため、ブルート フォース手法が機能します。 マッピングが固定変換であるという観察により、可能性のある文字の検索を文字ごとに 1 つの定数時間操作に置き換えることができます。 結果として得られるアルゴリズムは依然として O(n) ですが、漸近的な複雑性は可能な限り最小限に抑えられ、文字あたりの作業量はほとんどありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(52n) = O(n) | O(n) | 受け入れられたが、不必要な作業 |
 | 最適 | O(n) | 出力の O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列全体を読み取り、末尾の改行のみを削除します。 入力にはスペースが含まれていないため、`strip()`ここでは削除するだけで十分ですが、`\n`も機能するでしょう。 
2. 空の結果文字列を作成します。 すべての入力文字に対して 1 文字だけを追加するため、出力の長さは入力の長さと同じになります。 
3. 入力を左から右にスキャンします。 文字ごとに、小文字か大文字かを判断します。 
4. 文字が小文字の場合は、大文字に変換します。 大文字の場合は小文字に変換します。 パイソンの`swapcase()`は、各文字に対してこの変換を正確に実行します。また、入力にはアルファベット文字が含まれることが保証されているため、他の文字カテゴリを処理する必要はありません。 
5. 変換された文字列を出力します。 各文字は個別に変換されるため、すべての文字の相対的な順序は変わりません。 

### なぜ効果があるのか

 スキャン中に不変なのは、最初の k 文字を処理した後の結果には、同じ k 文字の大文字と小文字を切り替えたバージョンが元の順序で正確に含まれるということです。 次の文字が処理されるとき、`swapcase()`大文字を小文字に、小文字を大文字に変更するため、k + 1 文字については不変式が true のままになります。 最後の文字が処理された後、不変式は文字列全体をカバーします。これは、生成される文字列がまさに必要な出力であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    print(s.swapcase())

if __name__ == "__main__":
    solve()
```入力行は 1 回読み取られ、問題に単一の文字列が含まれているという事実と一致します。`strip()`標準入力によって追加された改行を削除します。 このステートメントは文字列内にスペースがないことを保証するため、意味のある空白を誤って削除することはありません。 

への呼び出し`swapcase()`必要な変換をすべての文字に個別に適用します。 また、大文字と小文字に対して別々の分岐を作成することも避けられます。 結果の文字列は直接出力されるため、off-by-one エラーを引き起こす可能性のあるインデックス付けや境界条件はありません。 

代替の実装では、`ord()`そして`chr()`ASCII の大文字と小文字の違いを手動で加算または減算する必要がありますが、漸近的な複雑さは改善されずに、解決策が長くなります。

2 番目の例として、次のことを考えてみましょう。`aBcD`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての文字は 1 回処理されます。 |
 | スペース | O(n) | 変換された文字列には n 文字が含まれます。 |

 入力自体に n 文字が含まれており、すべての文字を考慮する必要があるため、線形の時間制限が最適です。 このアルゴリズムは、出力文字列以外に比例する補助データ構造を使用しないため、問題で許容される実際の入力サイズの 256 MB のメモリ制限内にも問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()
    print(s.swapcase())

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

    return out.getvalue()

# Provided sample
assert run("HeLlO\n") == "hElLo\n", "sample 1"

# Minimum-size input
assert run("A\n") == "a\n", "single uppercase character"

# All lowercase
assert run("abcdef\n") == "ABCDEF\n", "all lowercase characters"

# All uppercase
assert run("ABCDEF\n") == "abcdef\n", "all uppercase characters"

# Mixed boundary characters
assert run("aAzZ\n") == "AaZz\n", "first and last letters of both cases"

# Large input
large = "a" * 100000
assert run(large + "\n") == ("A" * 100000) + "\n", "large input"

 ## 特殊なケース

 1文字入力の場合`A`、アルゴリズムは 1 文字を読み取り、呼び出します`swapcase()`を取得し、`a`。 したがって、出力は次のようになります。`a`。 すべての位置はまったく同じルールに従うため、最初または最後の位置には特別な処理はありません。 

すべて小文字入力の場合`abc`、すべての文字は独立して切り替えられます。 中間状態は次のとおりです。`A`、 それから`AB`、 それから`ABC`、最終的な出力を与える`ABC`。 これにより、誤って大文字のみを処理する実装が捕捉されます。 

すべて大文字入力の場合`ABC`、同じプロセスで生成されます`abc`。 これにより、実装では小文字は変換されるが、大文字は変更されないという逆の間違いが発生します。 

混合入力の場合`aBcD`、文字は次のようになります`A`、`b`、`C`、 そして`d`、生産`AbCd`。 これは、アルゴリズムがすべての文字が元の大文字と小文字が同じであると想定していないことを確認します。 

境界入力の場合`aAzZ`、最初の小文字は次のようになります。`A`、最初の大文字は次のようになります。`a`、最後の小文字は次のようになります。`Z`、最後の大文字は次のようになります。`z`。 正確な出力は次のとおりです`AaZz`。 手動による ASCII ベースの実装では、誤ったオフセットまたは境界条件が導入されることが多いため、アルファベットの両端をテストすることは役に立ちます。 

100,000 コピーからなる大量の入力の場合`a`、すべての文字が 1 回処理され、結果には 100,000 個のコピーが含まれます。`A`。 これにより、実装が文字列を繰り返し再スキャンするのではなく、線形な作業が実行されることが確認されます。
