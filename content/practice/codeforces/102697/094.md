 ## 問題の理解

 以下から包含的な整数間隔が与えられます。`x`に`y`。 その範囲内のすべての数値の中で、2 のべき乗である最大の数値を見つける必要があります。 間隔に 2 のべき乗が含まれていない場合は、次のように出力します。`-1`。 答えは符号付き 32 ビット整数に収まる必要があります。 

関連する 2 のべき乗は次のとおりです。`1, 2, 4, 8, 16, ...`。 答えは符号付き 32 ビット整数に収まるため、考えられる最大の答えは次のようになります。`2^30 = 1073741824`。 次なる力は、`2^31`、符号付き 32 ビット範囲外です。 これにより、検討すべき候補権限は 31 個だけになります。 

制限時間は 1 秒、メモリ制限は 256 MB です。 入力は 2 つの整数のみで構成されるため、このステートメントは大規模な配列またはグラフ構造を強制しません。 間隔が大きい場合でも、間隔内のすべての整数に対する線形スキャンには 20 億回を超える反復が必要になる可能性があるため、2 の累乗が非常にまばらであるという有益な観察が得られます。 べき乗自体のみをチェックするには対数時間がかかります。 

不注意な実装が失敗する可能性がある境界ケースがいくつかあります。 間隔自体に 2 のべき乗が含まれる場合、エンドポイントはその値を含みます。 たとえば、入力の場合`8 8`、正しい出力は次のとおりです。`8`。 エンドポイント間のみを厳密に検索する実装では、誤って出力されます。`-1`。 

もう 1 つのケースは、上限の終点が 2 の累乗ではないが、その下の最大累乗が区間内にある場合です。 入力用`86 375`、区間に近いパワーは次のとおりです。`64`、`128`、 そして`256`、したがって、答えは次のとおりです`256`。 少なくとも次の最初のパワーを選択します。`x`それは間違っているだろうから`128`は有効ですが最大ではありません。 

最後に、間隔には 2 の累乗をまったく含めることはできません。 入力用`35 55`、周囲の勢力は`32`そして`64`、両方とも区間外であるため、答えは次のようになります。`-1`。 を超えない最大電力を単純に計算する不用意な実装`y`得るだろう`32`そしてそれが少なくともであることを確認することを忘れてください`x`。 

## アプローチ

 直接的なアプローチは、次のすべての整数を検査することです。`x`を通して`y`、それが 2 の累乗であるかどうかをテストし、成功した最大の値を記憶します。 この方法は正しいです。考えられるすべての答えが明示的に検査されるからです。 正の整数は、そのバイナリ表現に 1 つのセット ビットが含まれている場合、正確に 2 のべき乗であるため、テストは次のようなビット演算で実行できます。`v & (v - 1) == 0`。 

問題は調べられる整数の数です。 最悪の場合、次のような間隔が発生します。`[1, 2147483647]`含まれています`2147483647`候補者たち。 各候補が数回の定数時間操作しか実行しない場合でも、数十億回の反復は 1 秒の制限をはるかに超えています。 

ブルートフォースは考えられるすべての答えをチェックするため機能しますが、間隔が広い場合は失敗します。 より高速な解決策を明らかにする観察は、通常の整数をまったく検査する必要がないということです。 可能な答えは 2 の累乗のみであり、連続する累乗は 2 を乗算することによって異なります。 から始まる`1`を繰り返すことで、関連するすべての候補を生成できます。 

符号付き 32 ビット範囲には、2 のべき乗が約 31 個しかありません。 それらをすべて生成して間隔内で最大のものを保持するか、以下を超えない最大の 2 のべき乗を見つけることができます。`y`少なくともそうであるかどうかを確認してください`x`。 2 番目の定式化は特に単純です。 最大勢力に達したら`p`満足のいく`p <= y`、すべてのより大きな電力は自動的に次の値よりも大きくなります。`y`、 それで`p`答えとなり得る唯一の候補です。

 ## アルゴリズムのチュートリアル

 1.読む`x`そして`y`。 この間隔には包括的な値が含まれるため、両方のエンドポイントが回答になることが許可されます。 
2. から始める`p = 1`、2 の最小の正の累乗。 後続のパワーはすべて、前のパワーを 2 倍にすることで得られます。 
3.倍増しながら`p`せいぜいそれを維持するだろう`y`、 交換する`p`と`2 * p`。 ループが止まると、`p`を満たす 2 の最大のべき乗`p <= y`。 
4. かどうかを確認します。`p >= x`。 そうであれば、`p`中にある`[x, y]`、それはその区間内で可能な最大の 2 のべき乗であるため、次のように出力します。`p`。 
5. もし`p < x`、印刷`-1`。 以来`p`を超えない最大の 2 のべき乗はすでに`y`、2 の累乗ごとに、最大でも次のいずれかになります。`p`以上`y`。 したがって、その区間内にはいかなる力も存在できません。 

不変条件は、反復のたびに、`p`は 2 の累乗であり、現在の上限を超えない最大の生成電力です。 終了時には、`p`最大でも 2 の累乗の最大値です`y`。 それも少なくとも`x`、まさに最大の有効回答です。 以下であれば`x`、後のすべてのパワーが次の値を超えるため、有効なパワーは存在しません。`y`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    p = 1

    while p * 2 <= y:
        p *= 2

    if x <= p <= y:
        print(p)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```の最初の行`solve`2 つのエンドポイントを読み取ります。 答えは現在の 2 のべき乗のみに依存するため、配列や補助データ構造は必要ありません。 

変数`p`から始まります`1`。 ループはそれを 2 倍にしますが、次のパワーは依然としてその値以下または正確に一致します。`y`。 使用する`p * 2 <= y`最初に 2 倍にするのではなく、上限を超える不要な候補の作成を回避します。 

ループ後は、`p`満足することが保証されています`p <= y`いつ`y >= 1`。 最終条件は区間の反対側をチェックします。`p >= x`。 完全な条件を次のように書きます`x <= p <= y`また、包括的な境界も明確になります。 

Python の整数はオーバーフローしないため、最終的に 2 倍になった後の一時的な値であっても安全です。 固定幅の整数を使用する言語では、実装は符号付きオーバーフロー範囲へのシフトを回避する必要があります。 ここでは、答え自体が符号付き 32 ビット整数に収まることが保証されています。 

もし`y < 1`、ループは 2 倍化を実行せず、`p`残っている`1`。 決勝戦`p <= y`チェックが失敗したため、アルゴリズムは正しく報告します`-1`。 これは、非正の整数のみを含む間隔も処理します。

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    result = sys.stdout.getvalue()

    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 区間に 1 つのべき乗が含まれている場合、アルゴリズムは包含比較を通じてそれを処理します。 入力用`8 8`、`p`最終的にはなる`8`、および条件`8 <= 8 <= 8`成功したため、出力は次のようになります`8`。 厳密な不等式を使用した実装はここで失敗します。 

区間内に 2 のべき乗がない場合は、それを超えない最大の電力`y`以下に落ちます`x`。 のために`35 55`、ループは次の位置で停止します。`32`。 以来`32 < 35`、アルゴリズムは出力します`-1`。 次なる力は、`64`、すでに より大きいため考慮できません`y`。 

間隔が非常に大きい場合、アルゴリズムは間隔の幅に依存しません。 のために`1 2147483647`までの電力しか生成しません。`1073741824`。 次の力は`2147483648`、上限の終点を超えているため、答えは次のようになります。`1073741824`。 すべての整数をスキャンするには 20 億回以上の反復が必要ですが、このソリューションでは数十回しか必要ありません。 

エンドポイントが両方とも同じ非電力値である場合、たとえば、`2147483647 2147483647`、アルゴリズムは特別な場合を除いて動作します。 その値を超えない最大の電力は、`1073741824`、両方のエンドポイントが等しいため、下限エンドポイントを下回ります。`2147483647`。 最終チェックにより、結果的に次の結果が生成されます。`-1`。 

中心となるアイデアは、再利用できるほど単純です。目的の値が予測可能な次の要素を持つ疎なシーケンスを形成する場合、数値間隔内のすべての値をスキャンするのではなく、そのシーケンスを検索します。 ここでのシーケンスは次のとおりです`1, 2, 4, 8, ...`したがって、倍加を繰り返すと、潜在的に数十億回の反復検索が対数時間に短縮されます。
