 ## 解決策
 ## 問題の理解

 タスクは、指定された正の整数が 2 で割り切れるかどうかを判断することです。割り切れる場合は、次のように出力します。`YES`; それ以外の場合は印刷します`NO`。 入力には正の整数が 1 つだけ含まれており、複数のテスト ケースはありません。 必要な出力は、数値が 2 の倍数であるかどうかを説明する 1 つの単語です。 

この声明では、整数の数値の上限は公表されていません。 制限時間は 1 秒、メモリ制限は 256 MB です。 必要なプロパティは 2 で割り切れるかどうかのみに依存するため、整数のサイズはその値に比例する演算を実行する必要はありません。 10 進表現を直接検査して、桁数に関して一定の処理を行うことができます。 これは、入力が非常に長い場合に Python 整数を構築するよりも安全です。 

主なエッジ ケースは、小さな値と最後の桁が 0 である値です。 たとえば、入力`1`生産しなければならない`NO`1 は 2 で割り切れないためです。数値が正かどうかだけをチェックする不注意な実装では、数値が誤って受け入れられてしまいます。 入力`2`生産しなければならない`YES`2 自体が 2 の最小の正の倍数であるためです。 入力`10`生産しなければならない`YES`たとえ最後の桁が別の偶数桁ではなくゼロであっても。 最後の桁に基づくチェックでは、3 つのケースすべてが直接処理されます。 

## アプローチ

 簡単な総当り的な方法では、可能な 2 の倍数を繰り返し検討することによって、数値が偶数の商を持つかどうかを判断しようとします。 さらに単純な総当たり解釈は、2 から指定された数値までの整数を列挙し、どれが 2 の倍数であるかをチェックし、入力に達したときに停止するというものです。 これは正しいです。2 の正の倍数がそのシーケンス内にすべて出現しますが、実際には`n - 1`入力値に対する反復回数`n`。 もし`n`が大きいということは、問題が必要とする作業よりもはるかに多くの作業が必要であり、このステートメントは、そのような列挙を合理的にするための小さな上限を示しています。 

10 進数表記の構造により、より強力な観察が得られます。 10 進整数は、最後の桁が次のいずれかである場合、正確に 2 で割り切れます。`0`、`2`、`4`、`6`、 または`8`。 それより前の桁を調べる必要はありません。 例えば、`123456`最後の桁が であるため偶数です`6`、 その間`987653`最後の桁が であるため奇数です`3`。 この総当たり法は、算術演算を繰り返すことで最終的に割り算のプロパティを発見するため機能しますが、10 進数表現のこのローカルなプロパティを無視するため失敗します。 最後の数字だけを見ると、問題は 1 つの文字チェックに減ります。 

したがって、入力がマシンの整数に適合する場合、最適なアプローチは数学的な意味での定数時間になります。`O(L)`厳密な入力サイズの意味では、`L`入力自体の読み取りには必要なため、 は 10 進数の桁数です。`O(L)`時間。 入力を読んだ後の実際の決定には時間がかかります`O(1)`時間。

 ## アルゴリズムのチュートリアル

 1. 正の整数を文字列として読み取ります。 10 進表現を直接読み取ることで、特定の整数のサイズに依存することがなくなります。 
2. 文字列の最後の文字を取得します。 2 で割り切れるかどうかはこの桁にのみ依存するため、数値の他の部分を処理する必要はありません。 
3. 最後の桁が次の数字に属するかどうかを確認します`02468`。 存在する場合は、印刷してください`YES`; それ以外の場合は、印刷します`NO`。 
4. 結果はこの単一のメンバーシップ テストの直後に決定されるため、候補倍数のループ、除算、または列挙は行われません。 

これが機能する理由: すべての 10 進整数は、その単位の桁が偶数である場合、正確に偶数になります。 可能な偶数の 10 進数は次のとおりです。`0`、`2`、`4`、`6`、 そして`8`。 したがって、アルゴリズムは 2 で割り切れる正の整数を正確に受け入れ、そうでないものは正確に拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、入力を変換するのではなく、文字列として読み取ります。`int`。 重要なキャラクターはただ一つ、`n[-1]`、これは単位の桁です。 のメンバーシップ`"02468"`固定サイズのチェックです。 

文字列を使用すると、Python の整数変換制限に依存せずに、任意の長さの 10 進数入力も処理されます。 この問題では 2 で割り切れるかどうかだけが問われているため、値全体を変換しても有用な情報は得られません。 

入力が正の整数であることが保証されているため、アルゴリズムにはオフバイ 1 の境界がなく、文字列には常に少なくとも 1 つの数字が含まれます。 値`0`指定された入力条件下では特別な処理は必要ありません。

## テストケース```python
import sys
import io

def solve():
    n = input().strip()
    if n[-1] in "02468":
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        solve()
        output = sys.stdout.getvalue()
        sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

    return output

# Provided samples
assert run("3\n") == "NO\n", "sample 1"
assert run("10\n") == "YES\n", "sample 2"

# Minimum-size positive integer
assert run("1\n") == "NO\n", "smallest positive integer"

# Smallest positive multiple of two
assert run("2\n") == "YES\n", "smallest even integer"

# All digits odd, but the number itself is odd
assert run("13579\n") == "NO\n", "odd number"

# Large value, testing that only the final digit matters
assert run("123456789012345678901234567890\n") == "YES\n", "large even number"

# Boundary digit 8
assert run("8\n") == "YES\n", "single-digit even number"

 ## 特殊なケース

 入力`1`最小の正の整数です。 アルゴリズムは最後の桁を読み取ります`1`、入っていないことがわかります。`02468`、およびプリント`NO`。 ゼロで除算したり、より小さい候補を列挙したりすることはないため、境界は直接処理されます。 

入力`2`生成されるべき最小の正の整数です。`YES`。 その唯一の数字は`2`、これは偶数であるため、アルゴリズムは次のように出力します。`YES`。 これにより、1 桁の入力によってインデックス付けの問題が発生しないことが確認されます。 

入力`10`特別に見える最後の数字を実行します`0`。 最後のキャラクターは、`0`、これは偶数桁のセットに属しているため、出力は次のようになります。`YES`。 誤ってのみをテストするチェック`2`、`4`、`6`、 そして`8`ここで失敗するだろう。 

次のような大きな値の場合、`123456789012345678901234567890`、アルゴリズムは最後の数字を除くすべての数字を無視します。`0`そしてプリント`YES`。 これは、ソリューションが数値をネイティブの整数に変換したり、その値に比例した演算を実行したりする必要がない理由を示しています。 割り算の決定は、単位の桁によって完全に決定されます。
