 ## 解決策
 ## 問題の理解

 タスクは、小さなカスタム プログラミング言語を実行することです。 入力はソースコード行のシーケンスを記述しており、プログラムはそれらの行が順番に実行されたかのように動作する必要があります。 この言語には、変数宣言、代入、出力という 3 種類のステートメントがあります。 宣言または代入は整数式を計算し、print ステートメントはリテラル テキストと変数の現在の値を結合します。 公式ステートメントでは構文が指定されており、以下に使用されるサンプル実行が示されています。 

宣言の形式は次のとおりです`var name = expression`、割り当ての形式は次のとおりです。`name = expression`。 式には、整定定数、事前に定義された変数、加算および減算が含まれます。 たとえば、その後`var a = 5`、ステートメント`a = a - 1`変化`a`に`4`。 

print ステートメントは、通常の算術構文とは少し異なります。 テキストは括弧内に表示されます。例:`(hello world)`、出力される変数は 2 つのプラス記号の間に表示されます。`+a+`。 部分は表示どおりに連結されます。 print ステートメントは 1 つの出力行を終了します。 

最初の入力行は、その後にソース行が何行続くかを示します。 残りの行はプログラムそのものです。 出力は、これらのソース行を順番に実行することによって生成されたテキストそのものです。 公式の制限は 1 秒の時間制限と 256 MB のメモリですが、この声明ではソース行数やその長さの個別の数値上限は公開されていません。 そのため、ソース コードの総量における線形時間を適切な目標とします。 以前のすべてのコードを繰り返しスキャンしたり、大きな文字列を繰り返し再構築したりするアルゴリズムは、不必要にコストがかかる可能性があります。 辞書を調べて各行を 1 回スキャンするだけで十分です。 

実装が静かに失敗する可能性がある小さなケースがいくつかあります。 考慮する```
1
print (hello)
```正しい出力は次のとおりです```
hello
```すべての print ステートメントに変数が含まれることを期待するパーサーは、ここで失敗します。 

もう一つのケースは、```
4
var a = 5
var b = a - 2
a = b + 10
print +a+( )+b+
```正しい出力は次のとおりです```
13 3
```不用意に実装すると、`b`すぐに評価するのではなく式テキストとして使用するか、古い値を使用する可能性があります。`a`任務の後。 

リテラル テキスト内のスペースも重要な詳細です。 で```
1
print (hello   world)
```出力は```
hello   world
```3 つのスペースはリテラルの一部であり、次のように折りたたんではなりません。`split()`。 

最後に、print ステートメントではいくつかの種類の部分を組み合わせることができます。```
4
var x = 7
var y = 2
var z = x - y
print +x+( - )+y+( = )+z+
```出力は```
7 - 2 = 5
```単純に行全体をスペースで分割するパーサーでは、リテラル テキストと変数置換の区別が失われます。 

## アプローチ

 最も直接的なブルート フォース実装では、すべての式を文字列として扱い、それを繰り返し検索して変数名を現在の値に置き換えます。 置換後、算術式を評価します。 これは正しいです。各変数の出現は最終的に辞書に格納される値になるため、結果の算術式は元の値と同じ値になります。 

問題は検索の繰り返しです。 式に長さがあると仮定します`L`そしてそこにあります`V`変数。 式をスキャンしてすべての変数を検索し、置換する場合、1 つのステートメントは`O(LV)`時間。 と`V`そして`L`どちらも入力のサイズに比例しますが、これは二次関数になる可能性があります。 あたりを含むソースファイル`10^5`関連するトークンは次の順序で必要になる可能性があります`10^10`1 秒の制限をはるかに超えたキャラクター操作。 

ブルートフォース手法は、変数置換によって最終的には通常の算術式が得られるため機能しますが、構文で必要のない作業が実行されるため失敗します。 重要な点は、式がすでに小さな独立した部分、つまり整数リテラル、変数名、演算子で構成されていることです。 式をスキャンしながら、辞書から各オペランドを直接解決できます。 変数が出現するたびにプログラム全体を検索する必要はありません。 

同じ考え方が印刷にも当てはまります。 印刷行は、区切り文字によってすでにリテラルテキスト部分と変数部分に分割されています。 これを 1 回スキャンし、リテラル テキストを直接コピーし、変数ごとに 1 回の辞書検索を実行できます。 したがって、すべてのソース文字は一定の回数だけ処理されます。 

算術評価の場合、ステートメントは加算と減算を使用した単純な方程式を記述します。 現在の変数を評価環境として提供した後、Python の算術エバリュエーターを使用できます。 入力は任意の Python コードではなく、制御されたコンテスト言語の式であり、エバリュエーターは組み込みを無効にして呼び出されます。 これにより、小規模な式言語の意図されたセマンティクスを維持しながら、実装がコンパクトに保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合はO(LV) | O(L + V) | 遅すぎる |
 | 最適 | ソースの全長は O(L) | O(V + L) | 承認済み |

 ここ`L`はソースプログラムの総文字数を示し、`V`は格納されている変数の数を示します。 

## アルゴリズムのチュートリアル

 1. ソース行数を読み取り、空の辞書を作成します。`variables`。 ディクショナリはシミュレートされたプログラムの現在の状態を表すため、ソースの接頭辞を処理した後、定義されたすべての変数が現在の整数値に正確にマップされます。 
2. 各ソース行を上から下に処理します。 式は前のステートメントによって確立された値に依存する可能性があるため、実行順序が重要になります。 
3. 行が次で始まる場合`var `、最初に宣言を分割します`=`。 左側のテキストは変数名を示し、右側のテキストはその式を示します。 現在の辞書を使用して式を評価し、結果の整数をその名前で保存します。 
4. それ以外の場合、行が割り当ての場合は、最初の行で分割します。`=`。 代入の直前に存在する値を使用して右側の式を評価し、左側の変数の古い値を新しい結果に置き換えます。 辞書を更新する前に完全な右辺を評価すると、部分的に変更された状態が誤って使用されることが回避されます。 
5. それ以外の場合、その行は print ステートメントです。 直後にスキャンを開始します`print `。 次のキャラクターが来たとき`(`、一致するものを見つけます`)`そしてそれらの間にあるものをすべて出力に追加します。 内容はリテラル テキストであるため、スペースと句読点は変更せずにコピーする必要があります。 
6. 次の文字が表示されたら`+`、次を見つけてください`+`。 これら 2 つの区切り文字の間のテキストは変数名です。 で調べてください`variables`、整数を文字列に変換し、それを現在の出力行に追加します。 
7. 完全な print ステートメントが消費されるまで続行します。 生成された出力に改行を追加し、次のソース行を処理します。 
8. すべてのソース行が実行された後、蓄積された出力を 1 回書き込みます。 文字列を蓄積して一度書き込むと、print ステートメントごとに個別のシステム出力呼び出しを行う必要がなくなります。 

重要な不変条件は、すべてのソース行を処理する直前に、`variables[name]`シミュレートされた疑似コード プログラムが割り当てる値と等しい`name`先行するすべての行の後に。 宣言と代入では、その右辺が現在の状態を使用して評価され、結果の値が格納されるため、この不変条件が維持されます。 print ステートメントは辞書を変更しないため、辞書も保存します。 すべての変数置換はその現在の値を正確に読み取るため、生成されるすべての出力行は、シミュレートされたプログラムによって生成される行と同一になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def evaluate(expr, variables):
    # The problem's expressions use integer constants, variables,
    # addition, and subtraction.
    return eval(expr, {"__builtins__": {}}, variables)

def solve():
    n = int(input())
    variables = {}
    output = []

    for _ in range(n):
        line = input().rstrip('\n')

        if line.startswith("var "):
            name, expr = line[4:].split("=", 1)
            name = name.strip()
            variables[name] = evaluate(expr.strip(), variables)

        elif line.startswith("print"):
            pos = 5

            # The syntax in the statement has a space after "print".
            if pos < len(line) and line[pos] == ' ':
                pos += 1

            current = []

            while pos < len(line):
                if line[pos] == '(':
                    end = line.find(')', pos + 1)
                    current.append(line[pos + 1:end])
                    pos = end + 1

                elif line[pos] == '+':
                    end = line.find('+', pos + 1)
                    name = line[pos + 1:end]
                    current.append(str(variables[name]))
                    pos = end + 1

                else:
                    # The grammar normally has delimiters immediately
                    # after "print", but skip harmless separator spaces.
                    pos += 1

            output.append(''.join(current))

        else:
            name, expr = line.split("=", 1)
            name = name.strip()
            variables[name] = evaluate(expr.strip(), variables)

    sys.stdout.write('\n'.join(output))

if __name__ == "__main__":
    solve()
```の`variables`Dictionary は、疑似コード プログラムのシミュレートされたメモリです。 宣言と代入は、キーワードと変数がすでに存在するかどうかだけが異なるため、最終的にはどちらも同じディクショナリ更新を実行します。 

式はに渡されます`evaluate`ステートメントが左側から分離された後でのみ。 最初`=`残り全体が式に属するため、分割に使用されます。 電話をかける`split("=", 1)`後から防ぐ`=`誤って解析境界を変更してしまうことを防ぎます。 

印刷パーサーは意図的に呼び出しません。`split()`ライン上で。 リテラル テキストにはスペースを含めることができ、それらのスペースは必要な出力の一部です。 代わりに、パーサーは区切り文字から区切り文字へと移動します。 括弧はリテラル テキストを識別し、プラス記号のペアは変数名を識別します。 

の`find`呼び出しも現在の印刷行によって制限されます。 区切り文字の各ペアは移動によって消費されます。`pos`そのため、印刷行は最初から繰り返し再スキャンされるのではなく、左から右にスキャンされます。 

Python の整数には任意の精度があるため、テスト データに固定幅の C++ 整数より大きい値が含まれている場合でも、算術値がオーバーフローすることはありません。 決勝戦`join`また、不要な末尾の改行も避けられます。 print ステートメントのないプログラムの場合、`output`は空のままで、プログラムは空の文字列を書き込みます。

print +x+( - )+y+( = )+z+
```スキャナーが変数を読み取ります`x`、次にリテラル`-`、 それから`y`、 それから`=`、 それから`z`。 結果の行は次のとおりです`7 - 2 = 5`。 パーサーはかっこ内のスペースを構文として扱うことはありません。これはまさにカスタム言語で必要とされるものです。 

最後のエッジケースは、print ステートメントを持たないプログラムです。 例えば、```
3

a = a - 3
var b = a + 2
```出力は生成されません。 後のステートメントはそれらの値に依存する可能性があるため、シミュレーターは引き続きすべての割り当てを実行しますが、出力リストは空のままで、何も書き込まれません。
