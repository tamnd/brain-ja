 ## 解決策
 ## 問題の理解

 2 次多項式を表す 3 つの正の整数 (a)、(b)、(c) が与えられます。 

[
 y=ax^2+bx+c。 
】

 この多項式を正の整数係数を持つ 2 つの二項式の積として記述するあらゆる方法を見つけなければなりません。 

[
 (ax^2+bx+c)=(px+q)(rx+s)、
 】

 ここで、(p,q,r,s) はすべて正の整数です。 各因数分解は形式で出力する必要があります`(px + q)(rx + s)`、係数 (1) が省略され、因数分解の完全なセットは ASCII 順にソートされなければなりません。 そのような因数分解が存在しない場合は、次のように出力します。`-1`。 これらは、Codeforces Gym の現在の声明で示されている要件です。 

2 つの二項式を展開すると、次のようになります。 

[
 (px+q)(rx+s)=prx^2+(ps+qr)x+qs。 
】

 したがって、有効な因数分解はすべて次の条件を満たす必要があります。 

[
 pr=a、\qquad ps+qr=b、\qquad qs=c。 
】

 このステートメントでは (a,b,c) の数値の上限は公開されていないため、アルゴリズムによって実行される算術作業を利用して制約を推論するのが便利です。 考えられるすべての係数を直接検索するには、値自体に比例した作業が必要になる可能性がありますが、係数が大きくなるにつれて不適切になります。 最適な方法では、検索が 1 つの整数の約数の検索に削減され、以下の実装では (O(\sqrt a)) 個の約数チェックのみが必要になります。 

単純な実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 まず、出力では 2 つの要素が順序付けされているため、両方の要素が出力されます。`(2x + 2)(x + 3)`そして`(x + 3)(2x + 2)`必要な出力は異なります。 入力用`2 8 6`、両方が発生し、一方を重複として削除すると不完全な回答が生成されます。 

次に、(1) に等しい係数は次のように出力されなければなりません。`x`、 ない`1x`。 入力用`1 17 60`、正しい出力には以下が含まれます`(x + 12)(x + 5)`それよりも`(1x + 12)(x + 5)`。 フォーマッタを不用意に使用すると、必要な出力と一致しない数学的に同等のテキストが生成される可能性があります。 

第三に、補助二次方程式の 2 つの根が一致する場合、反復因数分解を 2 回出力してはなりません。 たとえば、関連する値が (t) で判別式が 0 の場合、(t) の 2 つの可能な値は同一です。 両方を別個のケースとして扱うと、結果として得られるすべての因数分解が重複することになります。 

最後に、二次方程式は整数の根を持つことができますが、それでも正の係数の要件を満たしません。 ここでの条件は、多項式が有理根または整数根を持つというだけではありません。 両方の二項式内のすべての係数は正でなければなりません。 入力用`3 7 11`、必要な出力は次のとおりです。`-1`3 つの係数方程式をすべて満たす正の整数 (p,q,r,s) がないためです。 

## アプローチ

 最も直接的なアプローチは、2 つの因子の 4 つの係数を選択し、それらの積が元の多項式と等しいかどうかをテストすることです。 (pr=a) なので、(a) のすべての正の約数 (p) を試して (r=a/p) を導き出し、次に定数係数の可能​​な値を試して、中央の係数をチェックすることができます。 さらに単純な総当たり実装では、(1) から (a) までのすべての (p)、(1) から (c) までのすべての (q) を試し、結果の因数分解をテストできます。 最悪の場合、これには (O(ac)) 回の演算が必要ですが、これは、適度に大きい係数でもすでに大きすぎます。 4 つの係数すべてを個別に検索すると、さらに状況が悪化します。 

3 つの係数方程式の構造により、より強力な観測結果が得られます。 定義する

 [
 t= ps.
 】

 中間係数へのもう 1 つの寄与は (qr) であるため、

 [
 qr=b-t。 
】

 次に、これら 2 つの量を掛けます。 

[
 (ps)(qr)=pqrs。 
】

 (pr=a) と (qs=c) なので、

 [
 pqrs=(pr)(qs)=ac。 
】

 したがって、(t) は次の条件を満たさなければなりません

 [
 t(b-t)=ac。 
】

 並べ替えると、(t) のみを含む二次方程式が得られます。 

[
 t^2-bt+ac=0。 
】

 その判別式は

 [
 D=b^2-4ac。 
】

 これが重要な削減です。 4 つの未知の係数を検索する代わりに、最初に (t=ps) の唯一の可能な値を決定します。 彼らは

 [
 t=\frac{b\pm\sqrt D}{2}。 
】

 (D<0) の場合、(t) の実数値は存在しないため、因数分解は存在しません。 (D) が完全な正方形でない場合、(t) は整数になることができないため、やはり正の整数因数分解は存在しません。 (b+\sqrt D) のパリティが奇数の場合、候補 (t) も整数ではありません。 

有効な (t) がわかったら、(p\mid a) と (s\mid c) を同時に尊重しながら、それを (p) と (s) に分割する必要があります。 (t) の約数 (p) を列挙できます。 そのような (p) ごとに、次のように設定します。 

[
 r=\frac ap、\qquad s=\frac tp。 
】

 候補は、(r) が整数であり、(s) が (c) を除算する場合 (q=c/s) に正確に有効です。 結果として得られる因数分解は、

 [
 (px+q)(rx+s)。 
】

 中間係数を個別に確認する必要はありません。 (ps=t) および (qr=ac/t=b-t) であるため、中央の係数は自動的に (b) になります。 

(t) の約数を見つける必要があるだけであり、すべての約数は (\sqrt t) までの整数をチェックすることで見つけることができます。 (t\le ac) なので、(a) の約数を処理した後、(\sqrt a) を約数検索境界として使用すると、特に便利な実装が得られます。 各候補 (t) について、(a) の約数を (\sqrt a) まで列挙し、各約数 (p) について、(p\mid t) と (t/p\mid c) であるかどうかを確認します。 有効な順序付き因数分解はすべて 1 回だけ表示されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(ac)) | (O(1)) 出力とは別に | 遅すぎる |
 | 最適 | (O(\sqrt a)) | (O(k))、ここで (k) は回答の数 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (a)、(b)、(c) を読んでください。 (pr=a)、(qs=c)、(ps+qr=b) を満たすすべての正の整数 (p,q,r,s) を見つけたいと考えています。 
2. 判別式 (D=b^2-4ac) を計算します。 (D<0) の場合、(t=ps) の整数値は存在しません。したがって、答えは次のようになります。`-1`。 
3. 整数の平方根を計算します (d=\lfloor\sqrt D\rfloor)。 (d^2\ne D) の場合、判別式は完全な二乗ではないため、(t) の取り得る値は整数ではなく、有効な因数分解はありません。 
4. (b+d) のパリティをチェックします。 奇数の場合、((b+d)/2) も ((b-d)/2) も整数ではないため、有効な因数分解はありません。 
5. 2 つの可能な値を構築します

 [
 t_1=\frac{b+d}{2}、\qquad t_2=\frac{b-d}{2}。 
】

 正の値のみを保持してください。 (D=0) の場合、これら 2 つの候補は等しいため、コピーを 1 つだけ保持します。 

1. すべての候補 (t) について、(a) の約数 (p) を列挙します。 (p) から (\sqrt a) までを検査するだけで済みます。これは、平方根より大きい約数はすべて、小さい約数とペアになっているように見えるためです。 (p\mid a) の場合は常に、(a/p) も約数として考慮します。 
2. 各約数 (p) に対して、(p\mid t) が必要です。 次に設定します

 [
 s=\frac tp.
 】

 (s) は積が (c) である 2 つの正の因子のうちの 1 つであるため、(s\mid c) が必要です。 

1. 両方の割り算条件が成立する場合、計算します。 

[
 r=\frac ap,\qquad q=\frac cs.
 】

 4 つの係数は (pr=a) および (qs=c) を満たします。 (t) は (t(b-t)=ac) の根として構築されているため、残りの交差項も (ps+qr=b) を満たします。 

1. 両方の約数の方向が異なる場合は追加します。 (p) が平方根列挙によって見つかった約数である場合、そのペアの約数 (a/p) は別の考えられる先頭係数を表すため、これもテストする必要があります。 これにより、アルゴリズムは両方を生成できるようになります。`(2x + 2)(x + 3)`そして`(x + 3)(2x + 2)`。 
2. 係数を省略して、すべての有効な因数分解を必要な文字列表現に変換します。`1`前に`x`、すべての文字列を辞書順に並べ替えます。 Python の文字列の順序は、ここで使用される文字の ASCII 順序と一致します。 
3. ソートされた文字列を出力します。 候補が生成されなかった場合は、印刷します`-1`。 

### なぜ効果があるのか

 すべての有効な因数分解 ((px+q)(rx+s)) は (t=ps) を定義します。 その中間の係数は (ps+qr=b) を与え、2 つの交差項を乗算すると ((ps)(qr)=ac) を与えます。 したがって、(t) は (t^2-bt+ac=0) を満たす必要があるため、判別テストでは有効な因数分解を破棄できません。 

逆に、正の整数 (t) が (t(b-t)=ac) を満たすとします。 (p\mid a)、(p\mid t)、および (t/p\mid c) のような約数 (p) を選択した場合、(r=a/p)、(s=t/p)、および (q=c/s) を設定すると、(pr=a) および (qs=c) の正の整数が得られます。 さらに、

 [
 qr=\frac ac\cdot s
 】

 より直接的に次のように表現できます

 [
 qr=\frac{ac}{ps}=\frac{ac}{t}=b-t、
 】

 なぜなら (t(b-t)=ac) だからです。 したがって、(ps+qr=b) となり、構築された因数は元の多項式に乗算されます。 すべての有効な因数分解には、まさにそのような (t) とそのような約数 (p) があるため、列挙は完了します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def format_factor(coef_x, const):
    if coef_x == 1:
        return f"(x + {const})"
    return f"({coef_x}x + {const})"

def solve():
    a, b, c = map(int, input().split())

    disc = b * b - 4 * a * c

    if disc < 0:
        print(-1)
        return

    root = math.isqrt(disc)

    if root * root != disc:
        print(-1)
        return

    if (b + root) & 1:
        print(-1)
        return

    t1 = (b + root) // 2
    t2 = (b - root) // 2

    candidates = [t1]
    if t2 != t1:
        candidates.append(t2)

    answers = set()

    limit = math.isqrt(a)

    for t in candidates:
        if t <= 0:
            continue

        for d in range(1, limit + 1):
            if a % d != 0:
                continue

            p1 = d
            p2 = a // d

            for p in (p1, p2):
                if t % p != 0:
                    continue

                s = t // p

                if c % s != 0:
                    continue

                r = a // p
                q = c // s

                left = format_factor(p, q)
                right = format_factor(r, s)

                answers.add(left + right)

    if not answers:
        print(-1)
        return

    print("\n".join(sorted(answers)))

if __name__ == "__main__":
    solve()
```判別計算は、4 つの因子係数から 1 つの量 (t=ps) への中心の縮小を実行します。 Python の整数には任意の精度があるため、次のような式が使用できます。`b * b`そして`4 * a * c`入力係数が大きい場合でもオーバーフローしません。`math.isqrt`浮動小数点の代わりに使用されます`sqrt`。 浮動小数点平方根は、大きな整数をその真の値よりわずかに上または下で四捨五入する可能性があり、判別式を完全二乗として誤って分類する可能性があります。`isqrt`正確な整数の平方根が得られるので、`root * root == disc`信頼できます。 

二次公式は (2) で除算されるため、パリティ チェックが必要です。 完全二乗判別式だけでは、(t) が整数であることは保証されません。 たとえば、(b=5) および (d=2) は ((5+2)/2=3.5) となります。 

除数ループは通過するだけです`isqrt(a)`。 いつでも`d`分割する`a`、 両方`d`そして`a // d`テストされています。 これにより、小さな約数のみが考慮されるという簡単な完全性のバグが回避されます。 同じ因数分解はどちらかの二項式を最初に使用して表すことができるため、両方の方向を利用可能な状態にしておく必要があります。 

の`answers`set は偶発的な重複を削除します。 これは、2 つの除数列挙パスを通じて同じ因数分解に到達できる場合に便利です。 必要な順序付けは係数の数値順ではなくテキストの ASCII 順であるため、すべての候補が生成された後でのみ並べ替えます。

 [

】

 判別式は

 [
 8^2-4(2)(6)=16、
 】

 したがって (d=4)。 (t) の 2 つの可能な値は (6) と (2) です。 

(t=6) の場合、有効な除数を選択すると因数分解が行われます。`(2x + 2)(x + 3)`そしてその逆の順序。 (t=2) の場合、他の順序ペアが生成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(\sqrt a + k\log k)) | (a) から (\sqrt a) までの約数を検査し、生成された因数分解を (k) 並べ替えます。 
| スペース | (O(k)) | 回答セットには、並べ替え前の因数分解が保存されます。 

除数の検索は高価な算術部分であり、定数時間の割り算チェックを除いて (b) および (c) とは独立しています。 出力自体には複数の因数分解が含まれる可能性があるため、必要な順序が辞書編集的である場合、これらの文字列の保存と並べ替えは避けられません。 公開されたステートメントでは明示的な係数境界が提供されていないため、複雑さは (O(\sqrt a)) 算術検索に必要な出力を生成するコストを加えたものとして直接理解するのが最適です。 

## テストケース

 公式ステートメントでは 3 つのサンプルが提供されているため、以下の最初の 3 つのアサーションはそれらを再現しています。 次に、カスタム ケースは、因数分解のない多項式、因数の繰り返し、および大きな先行係数といくつかの順序付き因数分解を含むケースをターゲットとします。```python
import sys
import io
import math

def format_factor(coef_x, const):
    if coef_x == 1:
        return f"(x + {const})"
    return f"({coef_x}x + {const})"

def solve():
    a, b, c = map(int, input().split())

    disc = b * b - 4 * a * c

    if disc < 0:
        print(-1)
        return

    root = math.isqrt(disc)

    if root * root != disc or (b + root) % 2:
        print(-1)
        return

    t1 = (b + root) // 2
    t2 = (b - root) // 2

    candidates = [t1]
    if t2 != t1:
        candidates.append(t2)

    answers = set()

    for t in candidates:
        if t <= 0:
            continue

        for d in range(1, math.isqrt(a) + 1):
            if a % d != 0:
                continue

            for p in (d, a // d):
                if t % p != 0:
                    continue

                s = t // p

                if c % s != 0:
                    continue

                r = a // p
                q = c // s

                answers.add(
                    format_factor(p, q) + format_factor(r, s)
                )

    if answers:
        print("\n".join(sorted(answers)))
    else:
        print(-1)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()

        try:
            solve()
            return sys.stdout.getvalue()
        finally:
            sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
assert run("2 8 6\n") == (
    "(2x + 2)(x + 3)\n"
    "(2x + 6)(x + 1)\n"
    "(x + 1)(2x + 6)\n"
    "(x + 3)(2x + 2)\n"
), "sample 1"

assert run("1 17 60\n") == (
    "(x + 12)(x + 5)\n"
    "(x + 5)(x + 12)\n"
), "sample 2"

assert run("3 7 11\n") == "-1\n", "sample 3"

# No factorization, including the all-equal-value case.
assert run("5 5 5\n") == "-1\n", "all equal values"

# Repeated factor.
assert run("4 4 1\n") == "(2x + 1)(2x + 1)\n", "repeated factor"

# Boundary case where a = 1 and both factors have coefficient 1.
assert run("1 2 1\n") == "(x + 1)(x + 1)\n", "minimum coefficient"

# Several factorization orientations.
assert run("6 11 3\n") == (
    "(2x + 1)(3x + 3)\n"
    "(3x + 3)(2x + 1)\n"
), "ordered factorization"

| `1 2 1` | `(x + 1)(x + 1)` | Leading coefficient \(1\) and correct omission of `1x` |
| `6 11 3` | Two ordered factorizations | Divisor orientation and output ordering |

## Edge Cases

A zero discriminant is handled by constructing only one candidate \(t\). For input `4 4 1`, we have

\[
D=4^2-4(4)(1)=0,
\]

so \(t=2\). The only valid split is \(p=2,s=1\), giving \(r=2,q=1\). The result is `(2x + 1)(2x + 1)`. If both quadratic-formula branches were processed without deduplication, the same answer would be generated twice.

For input `1 2 1`, the discriminant is \(0\) and \(t=1\). The only possible coefficients are \(p=r=q=s=1\), giving

\[
(x+1)(x+1)=x^2+2x+1.
\]

The formatter prints `x` instead of `1x`, which matches the required representation.

For input `3 7 11`, the discriminant is

\[
7^2-4(3)(11)=-83.
\]

The algorithm stops immediately because a negative discriminant cannot produce an integer \(t\). The output is `-1`.

For input `5 5 5`, the values are all equal, but the discriminant is

\[
25-100=-75.
\]

Again there is no possible positive-integer factorization, so the answer is `-1`. This catches the common mistake of assuming that similar or equal coefficients imply a factorization.

For input `2 8 6`, the algorithm deliberately considers both divisors in each divisor pair. Choosing \(p=2,s=3\) gives `(2x + 2)(x + 3)`, while choosing \(p=1,s=6\) gives `(x + 1)(2x + 6)`. Reversing the factor roles gives the other two required strings. The final sort puts these four strings into exactly the required ASCII order.
