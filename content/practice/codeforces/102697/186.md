 ## 解決策
 ## 問題の理解

 入力は、ラジオ メッセージのノイズの多い文字起こしを含む 1 行です。 通常の文字は元のメッセージに属します。 radio static のすべての部分はアンダースコアで囲まれているため、次の形式の部分文字列になります。`_static_`両方のアンダースコアを含めて完全に削除する必要があります。 そのような領域の外側にある文字が答えを形成します。 

For example, in`hello_***_hello`、真ん中`***`静的であるため、復元されたメッセージは次のようになります。`hellohello`。 で`code ram_^_s^^^`、部分文字列`^`2 つのアンダースコアの間は静的ですが、その周囲のスペースと文字はメッセージの一部です。 

このステートメントでは、行の長さに対する個別の数値制限が指定されていないため、有用な制約は、入力が十分に長く、各文字を一定の回数だけ処理する必要があるということだけです。 O(L) アルゴリズム (L は行の長さ) は、入力の読み取りにもすでに O(L) のコストがかかるため、最適です。 O(L²) ソリューションは、転写が増加するにつれて遅くなりすぎる可能性があります。 

実装が一般的に失敗する境界ケースがいくつかあります。 行は次のように static で始めることができます。`_abc_code`、その正しい出力は`code`。 最初の文字が常にメッセージの一部であると仮定する不注意な解決策は、誤ってメッセージを保持してしまいます。`abc`。 次のように、行は static の直後に終了できます。`code_abc_`、その出力は`code`; 静的領域を閉じる前に別の通常の文字を待機する実装では、最後のアンダースコアが誤って処理される可能性があります。 次のように、複数の静的領域を隣接させることもできます。`a_x__y_b`、静的セクション間の 2 つのアンダースコアは個別の区切り文字であり、結果は次のようになります。`ab`。 最後に、次のように、行には本物のメッセージ文字であるスペースを含めることができます。`_noise_hello world_noise_`、その出力は`hello world`。 空白で分割すると、それらの空白が破壊されます。 

## アプローチ

 直接的ですが非効率なアプローチは、最初のアンダースコアを繰り返し検索し、次のアンダースコアを検索し、現在の文字列から静的領域全体を物理的に削除することです。 すべての静的領域は正確にアンダースコアのペアの間にあるテキストであるため、これは論理的に正しいです。 問題は、文字列の変更が繰り返されることです。 入力の長さが L で、Θ(L) 個の小さな静的領域が含まれている場合、削除ごとに Θ(L) 文字がコピーされる可能性があり、最悪の場合は Θ(L²) 文字操作が行われます。 たとえば、通常の文字と 1 文字の静的領域が交互に多数含まれる行では、実装で残りの文字列のほぼ全体を繰り返し再構築する必要が生じる可能性があります。 

入力の構造から、はるかに簡単な観察が得られます。 左から右にスキャンすると、静的状態に入るのか、静的状態から出るのかがアンダースコアによってわかります。 静的以外では、すべての文字が答えに属します。 静的内部では、すべての文字は無視される必要があります。 状態はアンダースコアに遭遇した場合にのみ変化するため、知る必要があるすべてを記述するには 1 つのブール変数で十分です。 

ブルートフォース手法は、アンダースコアで区切られたまったく同じ領域を識別するため機能しますが、すでに処理されたデータを繰り返し変更します。 静的が単純な交互の状態で表されるという観察により、転写を 1 回処理し、静的の外側に表示される文字のみを追加し、線形時間で終了することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(L²) | O(L) | 遅すぎる |
 | 最適 | O(L) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 途中のスペースを削除せずに、行全体を読みます。 入力は、空白で区切られたトークンのリストではなく、メッセージを表します。`input()`それよりも`split()`は適切な操作です。 

2. から始める`inside_static = False`。 アンダースコアが表示される前の文字は、元のメッセージに属します。 

3. すべての文字を左から右にスキャンします。 文字がアンダースコアの場合は、切り替えます`inside_static`。 アンダースコアは区切り文字であるため、回答にコピーされることはありません。 

4. 文字がアンダースコアではない場合、`inside_static`false の場合は、結果に追加します。 このような文字は静的の範囲外にあり、回復されたメッセージの一部です。 

5. 文字がアンダースコアではない場合、および`inside_static`それは真実です、それを破棄してください。 静的領域内のすべての文字はノイズです。 

6. スキャン後、蓄積された結果を印刷します。 区切り文字構造により、すべての静的セクションが開始アンダースコアと終了アンダースコアの間で正確にスキップされることが保証されます。 

重要な不変条件は、各文字を処理する直前に、`inside_static`現在の位置が静的領域内にある場合にのみ true になります。 アンダースコアはまさにメッセージと静的の間の境界であるため、その状態が変わります。 その結果、アンダースコア以外のすべての文字は、元のメッセージに属するときに正確に追加され、すべての静的文字は、破棄されるべきときに正確に破棄されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    inside_static = False
    ans = []

    for ch in s:
        if ch == '_':
            inside_static = not inside_static
        elif not inside_static:
            ans.append(ch)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```への呼び出し`rstrip('\n')`行終端記号のみを削除します。 意図的に使用していない`strip()`先頭または末尾のスペースが意味のあるメッセージ文字になる可能性があるためです。 

の`inside_static`flag は、アルゴリズムのウォークスルーの状態に直接対応します。 アンダースコアごとに切り替えが行われるため、最初のアンダースコアは静的になり、次のアンダースコアは静的のままになります。 これは、特別なケースを必要とせずに、static で始まるまたは終わる入力も処理します。 

結果は、文字列を繰り返し連結するのではなく、リストに保存されます。 Python 文字列は不変なので、繰り返します`ans += ch`不必要なコピーが発生する可能性があります。 リストへの文字の追加は定数償却時間であり、`''.join(ans)`最終文字列を一度構築します。 

整数演算はないので、オーバーフローは無関係です。 ループはすべての入力文字を 1 回処理し、唯一の境界条件はアンダースコアの切り替えであり、インデックス計算を完全に回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(L) | すべての文字は 1 回だけ検査され、最終的に`join`出力サイズは線形です。 |
 | スペース | O(L) | 結果リストには、非静的文字ごとに最大 1 つのエントリが保存されます。 |

 L 文字入力の読み取りにはすでに O(L) 作業が必要なため、線形スキャンが漸近的に最適になります。 また、アルゴリズムは残りの転写を繰り返しコピーすることを回避するため、実行時間は実際の入力サイズに比例して長くなります。 

## テストケース```python
import sys
import io

def solve():
    s = sys.stdin.readline().rstrip('\n')

    inside_static = False
    ans = []

    for ch in s:
        if ch == '_':
            inside_static = not inside_static
        elif not inside_static:
            ans.append(ch)

    print(''.join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run(
    "hellowor_*%^&&^%&^&%*_ldcoder_%^%^_ams\n"
) == "helloworldcoderams\n", "sample 1"

# Provided sample 2
assert run(
    "hello_***_hello\n"
) == "hellohello\n", "sample 2"

# Provided sample 3
assert run(
    "_^*&^^&**&^*^&*&^*^&_code ram_^_s^^^\n"
) == "code rams^^^\n", "sample 3"

# Minimum-size message
assert run("a\n") == "a\n", "single ordinary character"

# All characters are static
assert run("_abc_\n") == "\n", "everything is static"

# Consecutive static regions and empty message portions
assert run("a_x__y_b\n") == "ab\n", "adjacent static regions"

# Leading and trailing static
assert run("_noise_hello world_noise_\n") == "hello world\n", "boundary static regions"

# Spaces inside the actual message
assert run("hello_***_ world\n") == " world\n", "leading message space"

# Large input, checking linear behavior and repeated boundaries
large = ("a_x" * 10000) + "_"
assert run(large + "\n") == ("a" * 10000) + "\n", "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 |---|---|---|
 |`a`|`a`| 最小サイズの入力と静的領域なし |
 |`_abc_`| 空行 | メッセージ全体を静的にすることもできます。 
|`a_x__y_b`|`ab`| 連続する区切り文字と空白部分 |
 |`_noise_hello world_noise_`|`hello world`| 境界での静的と空間の保存 |
 |`hello_***_ world`|` world`| 実際のメッセージの一部にスペースを含めることもできます。 
| 繰り返し`a_x`パターン | 10000`a`キャラクター | 大きな入力に対する線形処理 |

 ## 特殊なケース

 入力が静的で始まると、ステート マシンは直ちに境界を処理します。 のために`_abc_code`、最初のアンダースコアが変更されます`inside_static`偽から真へ、`abc`は破棄され、2 番目のアンダースコアによって状態が false に戻ります。 登場人物たち`code`次に追加され、`code`。 文字列の先頭に特別なケースは必要ありません。 

静的な後に入力が終了した場合でも、スキャンが終了する前に、閉じアンダースコアによって状態が切り替わります。 のために`code_abc_`、`code`が追加されており、`abc`は無視され、最後のアンダースコアは状態を false に返します。 答えはまさに`code`。 終了デリミタの後の文字を検査する必要がないため、隣接するインデックスに基づく実装は回避されます。 

連続した静的領域の場合は、次のことを考慮してください。`a_x__y_b`。 最初のアンダースコアは静的に入り、次のアンダースコアは静的から離れ、次のアンダースコアはすぐに再び静的に入り、最後の関連するアンダースコアは静的から離れます。 登場人物たち`x`そして`y`どちらも破棄されますが、`a`そして`b`保存されています。 結果は`ab`。 トグル モデルは、2 つの区切り文字間の空のメッセージ セグメントを自然に処理します。 

スペースは、静的文字内にない限り、通常の文字として扱う必要があります。 で`_noise_hello world_noise_`、最初のノイズの多い領域が破棄され、両方の単語とその分離スペースが追加され、最後のノイズの多い領域が破棄されます。 出力は`hello world`。 これが、プログラムが行を空白で区切られたトークンに分割するのではなく、行全体を読み取る理由です。 

同じメソッドは、アンダースコアをまったく含まない入力も処理します。 のために`hello world`、状態はスキャン全体を通して false のままであるため、すべての文字がコピーされ、出力は入力と同一になります。 これは不変条件の最も単純なケースであり、スキャナは決して静的状態にはなりません。
