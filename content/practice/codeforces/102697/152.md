 ## 問題の理解

 このタスクは単位円を直接適用するものです。 入力は、度単位で測定される 0 から 359 までの 1 つの整数角度です。 正の x 軸をその角度だけ反時計回りに回転させることによって得られる光線を想像してください。 単位円との交点に座標があります

 (cosθ,sinθ)。 

必要な出力は x 座標のみなので、cosθ を出力する必要があります。 入力は度単位ですが、Python の三角関数はラジアンを想定しているため、最初に角度を次のように変換する必要があります。 

θ rad =θ 度 180 π 。 

入力範囲が狭いということは、アルゴリズム上の困難がないことを意味します。 処理する整数は 1 つだけであり、取り得る値は最大 360 個です。 定数時間の数学ライブラリ呼び出しでさえ、問題なく制限内に収まります。 公式問題では、制限時間は 1 秒、メモリは 256 MB であるため、事前計算や近似スキームは必要ありません。 

主なエッジ ケースは、コサインが数学的に正確にわかっているにもかかわらず、浮動小数点演算では値が若干異なる方法で表現される可能性があるという角度から発生します。 例えば、```
0
```は点 (1,0) に対応するため、正しい x 座標は 1 です。度をラジアンに誤って変換する不注意な実装により、1 とは異なる値が生成される可能性があります。 

もう一つの境界ケースは、```
180
```その点は (−1,0) なので、答えは −1 です。 第 2 象限と第 3 象限でコサインの符号が変化することを忘れたソリューションでは、誤って正の値が出力される可能性があります。

最後に、許容される最大角度は、```

## アプローチ

 リテラルの総当たりアプローチでは、0 から 359 までのすべての整数角度のコサインを保存し、要求された値を検索できます。 このようなテーブルを作成するには 360 回のコサイン評価が必要で、その後の答えの検索には一定の時間がかかります。 代わりに、テーブルを介した単純な順次検索を想像すると、最悪の場合、360 回の比較、または 359 回の比較の失敗とその後の最終的な一致が必要になります。 ドメインには可能な角度が 360 個しか含まれていないため、この問題に対してはすでに十分に高速です。 

しかし、そのアプローチではタスクの数学的構造が完全に欠落しています。 単位円上の x 座標はコサインによって直接定義されます。 入力自体がすでに必要な角度であるため、可能な角度を列挙する必要はありません。 ドメインが小さいため、ブルート フォース手法は機能しますが、不必要なストレージと計算が追加されます。 目的の座標が正確に cos(θ) であることが観察されると、問題全体が 1 度からラジアンへの変換と 1 回のライブラリ呼び出しに削減されます。

 ## アルゴリズムのチュートリアル

 1. 整数の角度を度単位で読み取ります。 問題には 1 つのテスト ケースが含まれているため、値は 1 つだけです。 
2. 次を使用して角度を度からラジアンに変換します。`angle * pi / 180`。 これが必要なのは、Python の`math.cos`関数はラジアンを使用します。 
3. 変換された角度のコサインを計算します。 単位円上では、コサインは正確に対応する点の x 座標です。 
4. 結果の浮動小数点値を出力します。 出力には浮動小数点数を使用できるため、手動で丸める必要はありません。 

### なぜ効果があるのか

 すべての角度 θ について、対応する光線が単位円と交わる点は (cosθ,sinθ) です。 この問題では特に x 座標が求められるため、その座標は正確に cosθ になります。 プログラミング言語で必要な唯一の表現変更は、コサイン関数を呼び出す前に入力を度からラジアンに変換することです。 したがって、アルゴリズムは要求された数学的量を正確に計算します。

 ## 特殊なケース

 角度 0 の場合、正確な入力は次のとおりです。```
0
```アルゴリズムはそれを 0 ラジアンに変換し、cos0=1 を計算し、次のようになります。`1.0`。 手動の象限ベースの実装では、不必要な特殊なケースが簡単に導入される可能性がありますが、直接式では自然に処理されます。 

角度 180 の場合、入力は次のようになります。```
180
```変換された角度は π であり、`math.cos(pi)`返品`-1.0`。 コサインはすでにすべての象限の x 座標の正しい符号をエンコードしているため、アルゴリズムのウォークスルーからの不変式は保持されます。 

角度 90 の場合、入力は次のようになります。```
90
```数学的な答えはゼロです。 π/2 はバイナリ浮動小数点で正確に表現できないため、浮動小数点ライブラリは正確にゼロではなく、極めてゼロに近い値を返す場合があります。 プログラムはその値を四捨五入したり切り捨てたりしないため、ソリューションに任意精度のポリシーが導入されることが回避されます。 判定者の浮動小数点比較では、小さな数値誤差がゼロと同等として扱われます。 

上限の場合、入力は次のとおりです。```
359
```アルゴリズムはこれを 359π/180 ラジアンに変換し、約 0.9998476951563913 を計算します。 これは、正確に 1 となる 360 度の答えとは異なります。入力制限は 359 で終了するため、プログラムは、指定された角度を近くの基本方向に換算するのではなく、正しく処理します。
