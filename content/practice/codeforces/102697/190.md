 ## 解決策
 ## 問題の理解

 私たちの町には (n) 人が住んでいます。 すべての人の名前と感染者の名前が入力されます。 まさに一人の人が持っている`OTHER`これは感染源が町の外から来たことを意味します。 

少なくとも他の 3 人に直接感染した場合、その人はスーパースプレッダーと呼ばれます。 タスクは、入力に登場した人物と同じ順序ですべてのスーパースプレッダーを出力することです。 誰も 3 人以上に感染させなかった場合、印刷します`NONE`。 

重要な詳細は、問題が**直接**感染について尋ねているということです。 アリスがボブに感染し、ボブがシェリルに感染した場合、アリスがシェリルに感染したとは考えられません。 特定の人物を直接の情報源として指定した入力レコードの数のみをカウントします。 

このステートメントにおける唯一の明示的な数値制約は、(n) が正の整数であるということです。 (n) には上限が定められていないため、アルゴリズムは人の数に応じて二次関数的に増加するものを回避する必要があります。 (n) 個のレコードを単一パスで通過するのが自然なターゲットです。 (n) 個のレコードの場合、(O(n^2)) アプローチでは約 (n^2) 件の名前比較が必要になる可能性がありますが、(O(n)) アプローチでは各レコードが一定回数だけ処理されます。 

不注意な実装が失敗する可能性のある小さなケースがいくつかあります。 

外部から感染した人だけがいる町を考えてみましょう。```
1
Alice OTHER
```正しい出力は次のとおりです。```
NONE
```アリスという名前の感染記録はないため、アリスは誰にも感染させませんでした。 誤ってカウントしてしまう実装`OTHER`アリスによる感染として記録すると、誤った結果が生じる可能性があります。 

同じ人物から 3 人が感染したとします。```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
```正しい出力は次のとおりです。```
Alice
```アリスには直接の犠牲者がちょうど 3 人いるため、しきい値は包括的です。 テスト`count > 3`の代わりに`count >= 3`間違って彼女を拒否してしまうでしょう。 

最後に、チェーンについて考えてみましょう。```
4
Alice OTHER
Bob Alice
Cheryl Bob
Darryl Cheryl
```正しい出力は次のとおりです。```
NONE
```すべての人が正確に他の人に感染させました。 定義では直接送信のみがカウントされているにもかかわらず、人から下流で到達可能な全員をカウントしようとするソリューションでは、アリスが誤って分類されてしまいます。 

## アプローチ

 最も直接的な総当たりの解決策は、すべての人を検査し、すべて (n 個) の感染記録をスキャンして、その人の名前が情報源として出現した回数を数えるというものです。 これは正しいです。すべての直接感染は入力レコードとして 1 回だけ出現するため、一致するソース名の数はその人の直接感染の数と正確に一致します。 ただし、すべての人物に対してフル スキャンを実行するには、(O(n^2)) 回の比較が必要です。 (n) 個のレコードの場合、最悪のケースは (n^2) 回の演算のオーダーであり、入力が増大するとすぐに実用的ではなくなります。 

入力の構造により、カウントする方法がはるかに簡単になります。 各レコードの形式は次のとおりです。`victim source`スーパースプレッダーに関連する唯一の情報はソースフィールドです。 感染源の名前が現れるたびに、その人の感染数をすぐに増やすことができます。 辞書はこの更新に一定の予想時間を与えるため、入力全体を 1 回のパスで処理できます。 

出力順序については別途注意が必要です。 辞書の反復順序は、必要な順序を決定するメカニズムとして使用されるべきではありません。 代わりに、人々の元の入力順序を保持し、その順序で最終的なフィルタリングを実行します。 これはステートメントに直接一致し、辞書の実装方法に関係なく機能します。 

ブルートフォースアプローチが機能するのは、完全な入力から各人の犠牲者の数を繰り返し再構築するためです。 失敗するのは、どの人に対してもほぼ同じ作業を繰り返すからです。 すべての感染が正確に 1 つのソース数に寄与するという観察により、繰り返されるすべてのスキャンを 1 つのパスに集約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 大きい (n) には遅すぎる |
 | 最適 | (O(n)) が期待されます | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) を読み取り、(n) 個の感染レコードを 1 つずつ処理します。 最終的な回答ではこの順序が維持される必要があるため、各人の名前を元の入力順序で保存します。 
2. すべてのレコードについて`person source`に関連付けられたカウントをインクリメントします。`source`、次の場合を除く`source`は`OTHER`。`OTHER`町外の情報源を代表する人物であるため、地元のスーパースプレッダーとして報告できる人物ではありません。 
3. すべての記録が処理された後、元の入力順序で人物をスキャンします。 累積カウントが少なくとも 3 になると、その人はスーパースプレッダーになるため、カウントがそのしきい値に達するたびに名前を追加します。 
4. 結果のリストが空の場合は、次のように出力します。`NONE`。 それ以外の場合は、保存されているすべてのスーパースプレッダーを独自の行に出力します。 

カウントを出力から分離する理由は、個人のカウントは、その人自身の入力レコードが読み取られた時点では必ずしも完了しているとは限らないためです。 入力の後半で誰かが情報源として現れる可能性があるため、すべてのレコードを読み取る前にその人が資格があるかどうかを判断すると、誤った結果が生成される可能性があります。 

### なぜ効果があるのか

 入力のプレフィックスを処理した後、名前の辞書数は、その名前をソースとする処理された感染レコードの数と等しくなります。 各レコードは 1 つの直接感染を正確に表すため、すべての直接被害者は正しいソースに 1 つの増分を正確に提供します。 すべて (n) 件のレコードが処理された後、各人の数は直接の犠牲者の合計数となります。 それらのカウントを条件でフィルタリングする`>= 3`したがって、スーパースプレッダーを正確に選択します。 最終スキャンは元の入力順序に従うため、出力順序も正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    people = []
    infected_by = {}

    for _ in range(n):
        person, source = input().split()
        people.append(person)

        if source != "OTHER":
            infected_by[source] = infected_by.get(source, 0) + 1

    answer = []

    for person in people:
        if infected_by.get(person, 0) >= 3:
            answer.append(person)

    if answer:
        sys.stdout.write("\n".join(answer) + "\n")
    else:
        sys.stdout.write("NONE\n")

if __name__ == "__main__":
    solve()
```の`people`list は、入力内で名前が出現する順序を正確に保持します。 これが必要なのは、ステートメントがアルファベット順やその他の順序ではなく入力順序を指定しているためです。 

の`infected_by`ディクショナリには、各感染源の直接感染数が保存されます。`get(source, 0)`は両方のケースをきれいに処理します。初めて検出されたソースはゼロから始まりますが、既存のソースはさらに 1 人の犠牲者を受け取ります。 

の`OTHER`辞書を更新する前にチェックを行う必要があります。`OTHER`は町の住人ではないため、この問題のスーパースプレッダーになることはできません。 

最後のループでは、`infected_by.get(person, 0)`なぜなら、多くの人は情報源として決して登場しないかもしれないからです。 欠落している名前をカウント 0 として扱うことは、まさに必要なことです。 

Python では整数オーバーフローの懸念はありません。 可能な最大数は (n) であり、Python 整数はそれを直接処理します。 この実装では、ブルート フォース ソリューションの主なパフォーマンス問題であるネストされたループも回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) が期待されます | 各レコードにより 1 回の辞書更新が行われ、その後、(n) 人の人物が 1 回スキャンされます。 |
 | スペース | (O(n)) | 入力順序と辞書には、それぞれ最大 (n) 個の名前を含めることができます。 |

 このアルゴリズムは、入力レコードごとに一定量の予想時間辞書作業と 1 回の追加の線形スキャンのみを実行します。 このステートメントでは (n > 0) を超える上限が指定されていないため、線形時間が適切なターゲットとなり、入力全体を繰り返しスキャンする二次関数の動作が回避されます。

 最初のエッジケースは、外部の感染源のみが存在する町です。```

Alice OTHER
```アルゴリズムはアリスを`people`、ただしスキップします`OTHER`更新時のソース`infected_by`。 したがって、アリスの暗黙的なカウントはゼロになります。 最終チェックは失敗します`>= 3`条件なので、出力は次のようになります`NONE`。 

2 番目のエッジ ケースは正確なしきい値です。```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
