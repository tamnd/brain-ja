 ## 解決策
 ## 問題の理解

 小文字の単語のコレクションが与えられているので、同じ単語を逆アルファベット順に出力する必要があります。 つまり、通常の辞書の順序では最後に出現する単語が最初に出力され、最初に出現する単語が最後に出力されなければなりません。 

入力に正の整数が含まれています`n`、 に続く`n`言葉。 すべての単語には英小文字のみが含まれています。 出力にはまったく同じものが含まれます`n`単語は 1 行に 1 つですが、辞書編集上の降順に並べられています。 同じ単語は区別できないため、任意の順序で並べて表示される場合があります。 

公表された声明では、明示的な上限は示されていない。`n`またはワード長については、制限時間は 1 秒、メモリ制限は 256 MB です。 そのため、大きな入力に対して二次ソート手順が望ましくないことは明らかです。 標準の比較ソートは、単語の比較の数を減らすため、自然な選択です。`O(n log n)`。 Python の組み込みソートは最適化されたネイティブ コードで実装されるため、ソート アルゴリズムを手動で実装するよりも推奨されます。 

実装が静かに失敗する可能性がある小さなケースがいくつかあります。 たとえば、たった一言で、```
1
apple
```正しい出力は```
apple
```少なくとも 2 つの単語が存在する必要があると想定したソリューションでは、存在しない 2 番目の要素に誤ってアクセスする可能性があります。 

重複する単語も保存する必要があります。 のために```
3
cat
cat
apple
```出力は```
cat
cat
apple
```入力をセットに変換して重複を削除するソリューションでは、誤って 2 つの単語だけが出力されます。 

ソートの方向もよくある間違いです。 のために```
3
apple
banana
cat
```正しい出力は```
cat
banana
apple
```逆にせずに通常の昇順ソートを使用すると、まったく逆の順序が生成されます。 

辞書編集上の比較は、長さではなく単語全体に対して実行されます。 例えば、```
3
aa
b
ab
```にならなければなりません```
b
ab
aa
```なぜなら`'b'`より大きい`'a'`、 その間`ab`より大きい`aa`。 長さで並べ替えると、異なる不正確な結果が生成されます。 

## アプローチ

 最も直接的な強引なアプローチは、残っている最大の単語を繰り返し見つけて出力し、考慮から除外することです。 最初の反復ではすべてを検査します`n`つまり、検査した瞬間に`n - 1`、 等々。 比較回数は正確に`n + (n - 1) + ... + 2 + 1 = n(n - 1) / 2`。 

すべての反復で、まだ出力されていない最大の単語が明示的に選択されるため、この手順は正しいです。 ただし、二次数の比較は次の場合にコストがかかります。`n`大きいです。 のために`n = 100000`、正確な比較数は次のとおりです。`4,999,950,000`これは、1 秒のソリューションが試みるべきものをはるかに超えています。 Python リストの途中から要素を繰り返し削除すると、削除自体に直線的な時間がかかる可能性があるため、状況がさらに悪化する可能性があります。 

重要な観察は、この問題には通常の辞書編集上の順序を超える特別な構造がないということです。 カスタムの貪欲なルールを発明したり、文字を個別に利用したりする必要はありません。 望ましい結果は、単に通常のソート順の逆になります。 比較ソートにより、すべての単語を並べ替えることができます。`O(n log n)`その後、降順を要求すると、必要な順序が正確に得られます。 

ブルートフォース手法は、次の最大値を直接検出するため機能しますが、並べ替えアルゴリズムがより効率的に整理できる情報を再検出します。 タスク全体が単に辞書順の降順ソートであるという観察により、繰り返される最大検索を 1 つの標準ソートに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 単語の比較 | O(n) | n が大きいと遅すぎます |
 | 最適 | O(n log n) の比較 | O(n) 補助/参照空間 | 承認済み |

 単語の比較自体を考慮すると、そのコストは共通のプレフィックスの長さに依存します。 最大語長の場合`L`、比較ソートの実際の上限は次のとおりです。`O(n log n * L)`。 Python は入力単語自体を保存するため、文字列に必要なメモリは合計入力サイズに比例します。 

## アルゴリズムのチュートリアル

 1.読む`n`そしてそれを読んでください`n`単語をリストに追加します。 出力には、重複も含めて入力単語が正確に含まれている必要があるため、すべての出現箇所を保持します。 
2. リストを辞書編集上の降順に並べ替えます。 パイソンの`sorted(..., reverse=True)`通常の辞書編集ソートを実行し、要求された順序を逆にします。これは、まさに必要な辞書の最大から最小の順序です。 
3. 並べ替えた単語を 1 行に 1 つずつ出力します。 それらを改行文字で結合すると、繰り返しの出力呼び出しが回避され、必要な形式が直接生成されます。 

### なぜ効果があるのか

 ソートステップの後、リストはすべての隣接するペアが次のように順序付けされます。`a[i]`そして`a[i + 1]`、`a[i]`辞書編集上以上である`a[i + 1]`。 したがって、最初の要素が最大のワード、2 番目の要素が残りの要素の中で最大のワード、というようになります。 並べ替えでは要素の削除や重複が行われないため、最終的なリストには、元の単語が必要な逆アルファベット順で正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    words.sort(reverse=True)

    sys.stdout.write("\n".join(words))

if __name__ == "__main__":
    solve()
```最初の行には単語の数が表示されます。 の値`n`入力に属する後続の行の数を知るためにのみ必要です。 

リスト内包表記はそれらを正確に読み取ります`n`言葉。 電話をかける`strip()`によって挿入された改行を削除します`readline()`単語を構成する小文字は変更せずに。`words.sort(reverse=True)`が中心的なオペレーションです。 Python は文字列を辞書順に文字ごとに比較し、小文字の英単語のアルファベット順と一致させます。`reverse=True`方向を昇順から降順に変更します。 

決勝戦`join`改行で区切られた 1 つの文字列が生成されます。 出力形式では最終行を改行なしで受け入れるため、最後の単語の後に特別な改行を追加する必要はありません。 

入力のサイズに関係する整数演算は実行されないため、Python では整数オーバーフローは無関係です。 避けるべき主な実装の詳細は、誤って使用することです。`sorted(words)`それなし`reverse=True`これにより、降順ではなく昇順が生成されます。 

## 実用的な例

 最初のサンプルでは、入力に 2 つの単語が含まれています。 

| ステップ | 並べ替え前の単語 | アクション | 結果 |
 | --- | --- | --- | --- |
 | 1 |`["coderams", "club"]`| 両方の単語を読んでください |`["coderams", "club"]`|
 | 2 |`["coderams", "club"]`| 辞書順の降順ソート |`["coderams", "club"]`|
 | 3 |`["coderams", "club"]`| 順番に印刷 |`coderams`、`club`|`coderams`後に来る`club`どちらもで始まるため、辞書編集上の昇順です。`c`、ただし、2番目の文字は`o`そして`l`、 と`o > l`。 通常の順序を逆にすると、結果的に次のようになります。`coderams`初め。 

2 番目のサンプルでは、​​単語が次のように配置されます。 

| ステップ | 現在の状態 | アクション |
 | --- | --- | --- |
 | 1 |`hello, world, we, hope, you, enjoy, the, contest, today, good, luck`| すべての単語を読む |
 | 2 |`hello, world, we, hope, you, enjoy, the, contest, today, good, luck`| 降順で並べ替え |
 | 3 |`you, world, we, today, the, luck, hope, hello, good, enjoy, contest`| 印刷 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n · L) | 並べ替えでは O(n log n) 回の比較が実行され、最大長 L | の単語の各比較に最大 O(L) かかります。 
| スペース | O(n・L) | 入力リストにはすべての単語が保存されますが、Python のソートでは補助メモリも使用されます。 

意図したアルゴリズムは、二次反復最大探索を標準的な探索に置き換えます。`O(n log n)`比較ソート。 単語数が多い場合、この違いは大きく、実装では Python の最適化された組み込みソート ルーチンを使用して、意図した入力サイズに対して指定された 1 秒の制限時間内に快適に収まります。 メモリ使用量は入力単語の保存によって支配され、入力サイズに比例します。

 ## 特殊なケース

 単一単語の場合は、特別な分岐を行わずに処理されます。 入力用```
1
apple
```リストには最初はのみが含まれます`apple`。 1 要素のリストを並べ替えても変更されないため、アルゴリズムは次のように出力します。`apple`。 2 つ以上の要素を想定した不用意な実装はここで失敗する可能性がありますが、組み込みの並べ替えによって自然に境界が処理されます。 

アルゴリズムではセットを構築するのではなく元のリストを並べ替えるため、重複した値が残ります。 のために```
3
cat
cat
apple
```ソートされたリストは`cat, cat, apple`。 両方の発生`cat`ソートに参加し、両方が出力されます。 出力に元の要素が正確に含まれるという不変条件が保持されます。 

注文の方向は次のように処理されます。`reverse=True`。 のために```
3
apple
banana
cat
```昇順ソートすると次のようになります`apple, banana, cat`ただし、降順ソートでは次のようになります。`cat, banana, apple`、これは必要な出力です。 この実装では、インデックス範囲を並べ替えたり手動で逆にしたりするのではなく、方向を直接指定するため、不必要な off-by-one エラーの原因が回避されます。 

長さの異なる単語は、長さではなく辞書順に比較されます。 のために```
3
aa
a
ab
```アルゴリズムはまず共通のプレフィックスを比較します`a`。 以来`a`その接頭辞の後で終わる場合は、両方よりも小さくなります`aa`そして`ab`。 間`aa`そして`ab`、2 番目の文字によって順序が決定されるため、最終結果は次のようになります。```
ab
aa
a
```これは、Python 文字列で使用されるものと同じ比較ルールに従い、アルファベット順に一致します。 

入力が大きい場合には、別のアルゴリズムは必要ありません。 100,000 単語の場合、最大値を繰り返し見つけるには、`100000 * 99999 / 2 = 4,999,950,000`最悪の場合のペアごとの比較。 代わりに、並べ替えソリューションは次の順序で実行されます。`100000 log₂(100000)`、各単語内の文字を比較するコストを考慮する前に、約 170 万の比較位置が計算されます。 この違いが標準を使用する理由です`O(n log n)`ソートはソリューションの重要な部分です。
