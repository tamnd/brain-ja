 ## 解決策
 ## 問題の理解

 1 つの整数が与えられます`N`、 と`1 <= N <= 1000`。 その数値を 3 と 5 で割り切れるに従って分類する必要があります。 

もし`N`が 3 と 5 の両方で割り切れる場合、必要な出力は次のとおりです。`FizzBuzz`。 3 でしか割り切れない場合は、次のように出力します。`Fizz`。 5 でしか割り切れない場合は、次のように出力します。`Buzz`。 どちらの条件も当てはまらない場合、プログラムは何も出力しません。 したがって、出力は 2 つの可分性テストによって完全に決定されます。 

境界が 1000 であるため、問題は非常に小さくなります。 1 から 1 までのすべての整数を検査するアルゴリズムであっても`N`最大 1000 回の反復が実行されますが、これは 1 秒の制限内に十分収まります。 ここには現実的な複雑さのプレッシャーはないため、最もクリーンな解決策は、2 つの割り切り条件を一定時間で直接テストすることです。 

主要なエッジ ケースは、両方の値で割り切れる数値です。 入力用`15`、正しい出力は次のとおりです。`FizzBuzz`、 ない`Fizz`または`Buzz`。 最初に 3 で割り切れるかどうかをチェックしてすぐに出力する不注意な実装`Fizz`5のテストには決して到達しないでしょう。 

もう 1 つの特殊なケースは、どちらの値でも割り切れない数値です。 入力用`1`、正しい出力は空です。 プログラムは、単語、ゼロ、または余分なメッセージを出力してはなりません。 公式サンプルではまさにこのケースが使用されています。 

境界値も通常どおりに動作します。 入力用`1`、入力の場合は何も出力されません。`1000`、この数値は 5 で割り切れますが、3 では割り切れないため、出力は次のようになります。`Buzz`。 

## アプローチ

 単純な総当たりアプローチでは、1 から 1 までのすべての整数を生成できます。`N`それぞれが割り切れるかどうかをテストし、割り切れた時点で停止します`N`。 最後の反復では、分類が必要な数値を正確に調べるため、これは正しいでしょう。 実際の制約がある場合`N <= 1000`、最悪の場合の反復回数はわずか 1000 回であるため、このアプローチでも十分に高速です。 

指定された制約の下で特定のブルート フォース メソッドが遅くなりすぎる、意味のある入力サイズはありません。 境界が大幅に増加すると、以前のすべての整数をスキャンする作業は不必要になります。`N`のみに依存する`N % 3`そして`N % 5`。 スキャン全体を削除して、これら 2 つのテストを直接実行できます。 

重要な詳細は条件の順序です。 3 と 5 の両方で割り切れる場合は、どちらかの個別の数で割り切れる場合よりも具体的です。 両方で割り切れる数は 3 のテストと 5 のテストも満たすため、結合された場合を最初にチェックする必要があります。 その後、個々のケースを独立して処理できます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`N`。 テスト ケースは 1 つだけであるため、外部のテスト ケース ループは必要ありません。
 2. かどうかを確認します。`N`は 3 と 5 の両方で割り切れます。つまり、`N % 3 == 0`そして`N % 5 == 0`。 その場合は印刷してください`FizzBuzz`そして終わります。 両方で割り切れるすべての数値もそれぞれのテストに合格するため、この条件を最初に指定する必要があります。 
3. 組み合わせた条件が false の場合は、次のことを確認します。`N`は 3 で割り切れます。そうであれば、出力します`Fizz`。 
4. それ以外の場合は、`N`は 5 で割り切れます。そうであれば、出力します`Buzz`。 
5. どの条件にも一致しない場合は、何も出力しません。 プログラムは出力を生成せずに単に終了することができます。 

### なぜ効果があるのか

 このアルゴリズムは、次の 4 つの可能な割り算状態を正確に考慮します。`N`: 3 と 5 の両方で割り切れる、3 でのみ割り切れる、5 でのみ割り切れる、またはどちらでも割り切れない。 最初の条件は、個々の条件がそれを要求できるようになる前に、重複する唯一のケースをキャプチャします。 このケースが除外されると、残りのテストは相互に排他的になるため、すべての有効な入力に対して必要な出力が正確に生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

if n % 3 == 0 and n % 5 == 0:
    print("FizzBuzz")
elif n % 3 == 0:
    print("Fizz")
elif n % 5 == 0:
    print("Buzz")
```最初の条件は両方の剰余を一度にチェックします。 パイソンの`%`演算子は除算後の余りを与えるので、ゼロの余りはまさに割り切れるかどうかのテストとなります。 

の`elif`構造は重要です。 一度`FizzBuzz`が印刷されると、それ以降の条件は評価されません。 これにより、`15`たとえば、単なるものとして分類されることから`Fizz`。 

明確な最終決定はありません`else`支店。 数値が 3 でも 5 でも割り切れない場合、必要な出力は空になるため、何もしないのがまさに必要な動作です。 

入力が最大 1000 であり、実装では小さな剰余演算が 2 つだけ実行されるため、整数オーバーフローは問題になりません。 

## 実用的な例

 最初の例では、`N = 1`、どちらの割り算テストも成功しません。 

| N |`N % 3`|`N % 5`| 状態 | 出力 |

 | 1 | 1 | 1 | どちらでもない | 空 |

 これは、正しい出力に文字が含まれていない場合を示しています。 の不在`else`印刷は意図的です。 

2 番目の例では、`N = 15`、両方の剰余はゼロです。 

| N |`N % 3`|`N % 5`| 状態 | 出力 |
 | --- | --- | --- | --- | --- |
 | 15 | 0 | 0 | 両方 |`FizzBuzz`|

 これは、個別の条件の前に結合条件をチェックする必要がある理由を示しています。 プログラムが最初に 3 で割り切れるかどうかをテストすると、誤って次の位置で停止してしまいます。`Fizz`。 

他の公式の例も同じロジックに従います。`3`生成する`Fizz`、 そして`5`生成する`Buzz`。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    if n % 3 == 0 and n % 5 == 0:
        print("FizzBuzz")
    elif n % 3 == 0:
        print("Fizz")
    elif n % 5 == 0:
        print("Buzz")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("1\n") == "", "sample 1"
assert run("3\n") == "Fizz\n", "sample 2"
assert run("5\n") == "Buzz\n", "sample 3"
assert run("15\n") == "FizzBuzz\n", "sample 4"

# Custom cases
assert run("2\n") == "", "minimum non-multiple case"
assert run("1000\n") == "Buzz\n", "maximum input"
assert run("30\n") == "FizzBuzz\n", "multiple of both"
assert run("999\n") == "Fizz\n", "large multiple of 3 only"
assert run("995\n") == "Buzz\n", "large multiple of 5 only"

 |`1000`|`Buzz`| 最大許容入力と 5 で割り切れる |
 |`30`|`FizzBuzz`| 結合された割り算条件 |
 |`999`|`Fizz`| 3 で割り切れるが 5 では割り切れない大きな値 |

 ## 特殊なケース

 のために`1`、アルゴリズムは次のように計算します。`1 % 3 = 1`そして`1 % 5 = 1`。 どちらの条件も成功しないため、何も出力されずに終了します。 これは、必要な空の出力と一致します。 

のために`15`の場合、アルゴリズムは両方の剰余をゼロとして計算します。 最初の条件はすぐに成功し、次の結果が生成されます。`FizzBuzz`。 個人`Fizz`そして`Buzz`分岐はスキップされ、重複するケースが誤って分類されるのを防ぎます。 

のために`1000`、アルゴリズムは次のようになります`1000 % 3 = 1`そして`1000 % 5 = 0`。 数値が 3 で割り切れないため結合条件は失敗しますが、最後の割り算テストは成功し、次の結果が得られます。`Buzz`。 これは、入力の上限境界に特別な処理が必要ないことも確認します。
