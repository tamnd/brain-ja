 ## 問題の理解

 目標カロリー数があります`n`そして`k`入手可能な食料品。 食料品`i`まさに貢献する`c[i]`カロリーと各食品は何度でも食べることができます。 課題は正確に到達することです`n`摂取する食品の数を最小限に抑えながらカロリーを削減します。 

入力には以下が含まれます`n`、 に続く`k`、続いて各食品のカロリー値が表示されます。 出力は、カロリー値の合計が正確に一致するアイテムの最小数です。`n`。 公式問題では 1 秒の制限と 256 MB のメモリが使用されます。 

決定的な問題は、食品の値が恣意的であることです。 より簡単なバージョンでは、500、100、および 50 の固定値があり、できるだけ多くの大きな項目を取得すると機能します。 よりハードなバージョンでは、その貪欲な性質は消えます。 たとえば、ターゲットが 600 で食品の値が 500、300、1 の場合、最初に可能な最大の項目を選択すると 500 が得られ、次に 100 カロリーの残りを 1 カロリーの項目のコピー 100 個で埋める必要があります。 代わりに最適な答えは 300 カロリーの商品 2 つであるため、答えは 2 になります。

## アプローチ

 直接的な総当りのアプローチは、食料品の可能な限りのコレクションを試し、合計が正確に一致する最小の数を保持することです。`n`。 これを実装する 1 つの方法は再帰的検索です。各状態で、次のいずれかを選択します。`k`食品の種類に応じて、蓄積カロリーが目標に達するかそれを超えるまで続けます。 これは正しいです。考えられるすべての選択肢の順序が検討されるため、最適な組み合わせを見逃すことはありません。 

問題は、この検索で​​は同じ部分問題が繰り返し調査されることです。 最小の食品のカロリーが 1 である場合、解決策には最大で 2 カロリーが必要となる場合があります。`n`選択肢。 順序付けられた再帰的検索では、次のものを含めることができます。`k^n`最悪の場合の選択シーケンス。 順序ではなく組み合わせが列挙されている場合でも、可能性の数は次数に応じて多項式に増加します。`k`、すぐに実行不可能になります。 

すべての解は一連の食品の選択肢として表すことができるため、総当り攻撃は機能しますが、多くの異なる接頭辞を介して同じ残りのカロリー量に到達する可能性があるため、この方法は失敗します。 2 つの異なる食品セットがすでに 300 カロリーを生成していると仮定します。 その時点から、さらに 500 カロリーを生成するための最適な方法は、その 300 カロリーがどのように得られたかとはまったく関係ありません。 残った問題を一度解決して、その答えを再利用する必要があります。 

この観察は動的計画法に直接つながります。 させて`dp[x]`正確に作るために必要な食品の最小数であること`x`カロリー。 到達可能な金額ごとに`x`、で食べ物を追加します`c`カロリーが生み出す`x + c`、結果として得られるソリューションでは、さらに 1 つの項目が使用されます。 したがって、移行は次のようになります`dp[x] = min(dp[x], dp[x - c] + 1)`あらゆる食品の価値観に合わせて`c`を超えない`x`。 

これは、無制限のナップザックまたは最小コイン交換問題です。 食べ物は繰り返し使えるので、計算してから`dp[x - c]`、同じものを使用することが許可されています`c`もう一度計算するときに`dp[x]`。 すべての遷移は、より小さいカロリー合計からより大きいカロリー合計に移行するため、処理合計は 0 から 0 までになります。`n`必要なすべての状態を依存関係の順序で示します。

 ## アルゴリズムのチュートリアル

 1. ターゲットを読み取る`n`そして`k`食べ物のカロリー値。 各値は、繰り返し使用できる食品の種類を表します。 
2. 配列を作成する`dp`長さの`n + 1`。 を除くすべてのエントリを無限大に設定します。`dp[0] = 0`。 

州`dp[x]`これは、生産に必要な食料品目の最小数がすでに正確にわかっていることを意味します。`x`カロリー。 カロリーゼロには食料品も必要ありません。これが基本的なケースです。 
3. カロリー合計を処理する`x`1から`n`。 

あらゆる有効な作り方`x`カロリーには最終的な食品が含まれています。 その最後の項目が`c`カロリー、その前に食べた食べ物が正確に寄与しているはずです`x - c`カロリー。 これは、すべての最適解が、以下で検討される遷移の 1 つによって表されることを意味します。 
4. あらゆる食品の価値に対応`c`と`c <= x`、 アップデート```
dp[x] = min(dp[x], dp[x - c] + 1)
```の最適解に1項目追加します。`x - c`。 もし`x - c`が到達不可能な場合、その無限値により、その遷移が答えに影響を与えることがなくなります。 

1. すべての合計が処理された後、出力します。`dp[n]`。 

どの州もより少ない総カロリーのみに依存しているため、最終的に考えられるすべての食品の選択は、その時点までにすでに検討されています。`dp[n]`が計算されます。 

### なぜ効果があるのか

 到達可能な合計に対する最適なソリューションを検討する`x`。 その溶液中の最終的な食品を見て、そのカロリー値を次のようにします。`c`。 最後の項目を削除すると、そのまま残ります`x - c`カロリー。 残りの食料が最適な解決策ではなかった場合`x - c`、より良いものに置き換えて、問題の解決策を得ることができます。`x`使用する項目が少なくなり、最適性と矛盾します。 したがって、あらゆる最適なソリューションは、`x`形を持っています`dp[x - c] + 1`一部利用可能なものについては`c`。 アルゴリズムはそのようなすべてを検査します`c`そして最小限のものを取るので、`dp[x]`が最適です。 正しい基本ケースから始める`dp[0] = 0`状態を昇順に処理すると、すべての状態に対してこのプロパティが確立されます。`x`、 含む`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data=None):
    if data is None:
        data = sys.stdin.buffer.read().split()
    else:
        data = data.split()

    it = iter(data)
    n = int(next(it))
    k = int(next(it))
    calories = [int(next(it)) for _ in range(k)]

    # Food items larger than n can never appear in a valid solution.
    calories = [c for c in calories if c <= n]

    INF = n + 1
    dp = [INF] * (n + 1)
    dp[0] = 0

    for x in range(1, n + 1):
        best = INF
        for c in calories:
            if c > x:
                continue
            candidate = dp[x - c] + 1
            if candidate < best:
                best = candidate
        dp[x] = best

    return str(dp[n])

if __name__ == "__main__":
    sys.stdout.write(solve() + "\n")
```実装の最初の部分では、入力全体を読み取ります。`sys.stdin.buffer.read()`。 テスト ケースは 1 つだけであるため、不必要なオーバーヘッドを回避しながらパーサーをシンプルに保ちます。 

食品の価値が次の値を超える`n`捨てられます。 このような食品は、正確な合計に参加することはできません。`n`なぜなら、すべてのカロリー値はプラスだからです。 このフィルタリングは正確性のために必要ではありませんが、内部ループでの無駄な比較を回避します。`dp[0]`何も食べてもカロリーがゼロになるため、 はゼロに初期化されます。 他のすべての状態は次から始まります`INF`、到達不可能な量を表します。 使用する`n + 1`これを超えるソリューションは使用できないため、無限大で十分です。`n`1 カロリーの食品が存在する場合の項目、および以下の有効な解決策`n`アイテムはこのセンチネルよりも小さいです。 

外側のループが増加します`x`1から`n`。 それぞれについて`x`、内側のループは、現在の合計に収まるすべての食品の値を試します。 表現`dp[x - c] + 1`これは、合計が小さい場合に最適な解を取得し、食品項目を 1 つ追加することに正確に対応します。`c`カロリー。 

ループの順序は意図的です。 食品の種類ごとに処理してから、誤って 0/1 の制限を課す可能性のある方法で合計を反復処理するのではなく、生成される合計を処理します。 ここでは、すべての状態が同じ食品タイプに関係する以前に計算された状態を使用する可能性があるため、無制限の繰り返しが自然にサポートされます。 

Python の整数はオーバーフローしないため、特別な数値型は必要ありません。 主な境界条件は次のとおりです。`c <= x`; それがなければ、`x - c`ネガティブになり、間違った DP 状態にアクセスします。 

問題ステートメントでは、到達不可能なターゲットの出力が指定されていません。 したがって、実装は、正確な解決策が存在するという意図された問題の仮定に従います。 到達不可能なターゲットが許可されている場合は、それらを出力する方法を決定する前に、ステートメントによる明示的な規則が必要になります。
