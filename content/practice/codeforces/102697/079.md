 ## 解決策
 ## 問題の理解

 このタスクは、固定された円形のカラー ホイール上で距離を測定することです。 ホイールには 7 つの色がこの順序で含まれています。`red -> orange -> yellow -> green -> blue-green -> blue -> purple -> red`各テスト ケースに対して 2 つの色の名前を受け取ります。 最初の色から 2 番目の色に移動するために必要な、ホイールに沿った最短の移動回数が必要です。 ある色から隣接する色に移動するには 1 コストかかります。ホイールは円形なので、どちらの方向にも移動できます。 最初の色はカウントされませんが、目的の色はカウントされるため、答えは正確に短いパス内のエッジの数になります。 

公式声明では、1 秒と 256 MB が与えられており、すべてのクエリにホイールからの 2 つの色の名前が含まれると指定されています。 可能な色の数は 7 に固定されているため、1 つのテスト ケースの実際の計算は一定時間になります。 テスト ケースの数が非常に多い場合でも、各ケースで必要な操作はほんの数回だけであるため、O(n) ソリューションで十分です。 

主なエッジケースは、ホイールの円形の性質から生じます。 2 つの色が等しい場合、距離はゼロになります。 例えば、```
1
green green
```出力があります```
0
```常に少なくとも 1 つの手をカウントする不注意な実装により、誤って出力される可能性があります。`1`。 

もう 1 つのよくある間違いは、ホイールが巻き付いていることを忘れることです。 例えば、```
1
purple orange
```出力があります```
2
```なぜなら、そのほうが短いルートだからです。`purple -> red -> orange`。 色を通常の線形配列として扱うと、代わりに 5 の距離が得られます。 

3 番目の境界ケースは隣接ペアです。`blue`そして`blue-green`:```
1
blue blue-green
```正しい出力は次のとおりです```
1
```2 つの色はホイール上で連続しているため、その距離は 1 です。 誤って両方のエンドポイントをカウントする実装では、2 つのエンドポイントが生成されます。 

## アプローチ

 最も直接的な解決策は、7 色をホイールの順序で保存し、そのシーケンスを検索することです。 2 つの色が与えられると、その位置を特定し、ホイールの周りの動きをシミュレートします。 色は 7 色しかないため、文字通りの総当たりシミュレーションでも一定数の操作しか実行できません。 7 色ホイール上の可能な最長の最短パスは 3 つのエッジですが、ホイール全体をスキャンするあまり慎重でない実装でも、クエリごとに最大 7 つの位置チェックが実行されます。 これが遅すぎる現実的な入力サイズはありません。 

有益な観察は、ホイールが決して変化しないため、すべての色に固定の整数位置を割り当てることができるということです。 一度`red`位置です`0`、`orange`は`1`、などの場合、問題はサイクル上の 2 つの位置間の距離になります。 

位置が`a`そして`b`。 配列内を直接移動すると、次の距離が得られます。`abs(a - b)`。 他の方向はホイールの端を包み込み、距離があります`7 - abs(a - b)`。 答えは、これら 2 つの値のうち小さい方です。 

状態空間には 7 色しかないため、総当たりシミュレーションと位置公式はどちらも正しいです。 この式は構造を直接表現し、各クエリを辞書検索、減算、および最小限の操作に減らすため、推奨されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ホイールシミュレーション | 全体で O(n)、テスト ケースごとに O(1) | お(1) | 承認済み |
 | 位置計算式 | 全体で O(n)、テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カラーをホイールの順序で次のように保存します。`red, orange, yellow, green, blue-green, blue, purple`。 各色のインデックスを割り当てる`0`を通して`6`。 
2. 現在のテスト ケースの 2 つの色を読み取り、そのインデックスを調べます。`a`そして`b`。 インデックスは、カラー ホイールによって記述された隣接関係を正確に保持します。 
3. コンピューティング`direct = abs(a - b)`。 これは、配列の通常の順序で移動するときの距離です。 
4. コンピューティング`wrap = 7 - direct`。 これは、円形の車輪の周りを反対方向に移動することを表します。 直接パスが配列の一端からもう一端まで交差する場合、これらはまさにパスが使用するエッジになります。 
5. 印刷`min(direct, wrap)`。 2 つの値は 1 サイクルの 2 方向のみを表すため、小さい方が可能な最短距離になります。 

これが機能する理由: 7 つの色に位置を割り当てた後、サイクル上で 1 つの色から別の色へのパスはすべて時計回りまたは反時計回りになります。 それらの長さは`abs(a-b)`そして`7-abs(a-b)`。 アルゴリズムはこれら 2 つの完全なパスのうち小さい方を選択するため、常に最短距離を返します。 両方の色が等しい場合、`direct`はゼロであり、答えは正しくゼロです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ORDER = {
    "red": 0,
    "orange": 1,
    "yellow": 2,
    "green": 3,
    "blue-green": 4,
    "blue": 5,
    "purple": 6,
}

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        first, second = input().split()

        a = ORDER[first]
        b = ORDER[second]

        direct = abs(a - b)
        wrap = 7 - direct

        out.append(str(min(direct, wrap)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`ORDER`辞書は、カ​​ラー ホイールの中心的な表現です。 明示的なインデックスを使用すると、文字列の順序への依存が回避されますが、アルファベット順はホイールとは関係がないため、これは不正確です。 

クエリごとに、2 つの文字列が整数の位置に変換されます。 絶対差はラップなしの距離を示します。 例えば、`purple`地位がある`6`そして`orange`地位がある`1`、したがって、直線距離は`5`。 

反対方向は長さがある`7 - 5 = 2`、に対応`purple -> red -> orange`。 最小値を取得すると、必要な最短距離が得られます。 

Python では整数オーバーフローの懸念はなく、最大の中間値は 7 のみです。 入力は 1 行ずつ処理され、出力は蓄積されて 1 回書き込まれます。これは、テスト ケースの数が多い場合にも適した単純な高速 I/O パターンです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | n 個のテスト ケースのそれぞれでは、2 つの辞書検索と定数時間演算が使用されます。 |
 | スペース | お(1) | カラー ディクショナリには正確に 7 つのエントリが含まれており、出力サイズは入力に比例します。 |

 ホイール自体のサイズは7色固定なので色数に依存しません。 と`n`テスト ケースでは、アルゴリズムはケースごとに一定の作業を実行するため、入力に応じて線形にスケールします。 公式の制限は 1 秒と 256 MB ですが、このソリューションは両方の制限をはるかに下回っています。

 ## 特殊なケース

 同じ色については、次の点を考慮してください。```
1
blue blue
```両方の色がインデックスにマップされます`5`、 それで`direct = abs(5 - 5) = 0`。 周回距離は`7`、最小値はゼロです。 アルゴリズムは次のように出力します。```
0
```それ自体から色に到達するために移動する必要がないため、直線距離がゼロであることが正しい解釈となります。 

ラップアラウンド ペアの場合は、次のことを考慮してください。```
1
purple red
```

`purple`インデックスあり`6`そして`red`インデックスあり`0`。 直線距離は`6`ですが、円周距離は`7 - 6 = 1`。 アルゴリズムは次のように出力します。```
1
```これは、次のエッジに対応します。`purple`に戻る`red`。 計算のみを行う線形配列ソリューション`abs(a-b)`間違って戻ってきます`6`。 

サイクルの反対側に近いペアについては、次のことを考慮してください。```
1
purple orange
```ポジションは`6`そして`1`、直接距離を与える`5`そして周回距離`2`。 答えは次のとおりです。```
2
```パスは`purple -> red -> orange`。 これが、問題を通常のシーケンスではなくサイクルとして扱う必要がある主な理由です。 

最後に、可能な最大の最短距離を考慮します。```
1
red green
```ポジションは`0`そして`3`したがって、関連するルートは両方とも長さを持ちます`3`そして`4`。 最小値は`3`、生産:```
3
```7 ノード サイクルでは、どの色のペアも最短距離が 3 を超えることはできません。 これにより、あらゆる実装に有用な健全性チェックが提供されます。すべての有効な答えは 0 から 3 の間になければなりません。
