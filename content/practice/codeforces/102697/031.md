 ## 問題の理解

## アプローチ

 直接的な総当たりアプローチは、次のすべての整数を試すことです。`2`を通して`n - 1`最初に分割したものを返します`n`。 これは正しいです。考えられるすべての答えが昇順に検査されるため、最初に成功した約数が必然的に最小になります。 問題は、最小の約数が次の値に近い大きな合成数の場合です。`n / 2`、これは大まかに実行されます`n / 2`モジュロ演算。 さらに悪いことに、入力範囲が大きい場合、リニア スキャンは、最小の要素である可能性のない数値のチェックにほとんどの時間を費やすことになります。 

因子ペアの構造により、はるかに優れた停止点が得られます。 もし`n = a * b`そして両方の要因がより大きかった`sqrt(n)`、彼らの製品はより大きいでしょう`n`、それは不可能です。 したがって、すべての合成数には、以下の因数が少なくとも 1 つあります。`sqrt(n)`。 その範囲を検索するだけで済みます。 

この問題に特有のさらに単純な観察があります。 最小の約数を探しているので、次から昇順に候補をテストできます。`2`。 最初に成功した候補者が答えです。答えが先に見つからない場合は、そのまま続行するだけで済みます。`sqrt(n)`。 複合入力の場合、ループは遅くともそこで終了することが保証されます。 

したがって、最適化された方法により、最悪の場合の可算性チェックの数が線形から削減されます。`n`直線的に入る`sqrt(n)`。

 ## アルゴリズムのチュートリアル

 1. 合成整数を読み取る`n`。 
2. 約数の候補を次の位置から開始します。`2`。 これは、次より大きい、可能な最小の正の約数です。`1`, したがって、最初にテストする必要があります。 
3. 候補者を昇順にテストします。`candidate * candidate <= n`。 もし`n % candidate == 0`、印刷`candidate`そしてやめてください。 候補は昇順に検査されるため、最初に見つかった約数が最小になります。 
4. ループは、約束された複合入力の除数を常に見つける必要があります。 そうでなかった場合は、`n`からの約数はありません`2`を通して`sqrt(n)`、これは次のことを意味します`n`プライムです。 

条件`candidate * candidate <= n`浮動小数点の平方根を計算するよりも適しています。 浮動小数点の精度の問題を回避し、数学的境界を直接表現します。 

### なぜ効果があるのか

 不変条件は、候補者をテストする前に`d`、からのすべての整数`2`を通して`d - 1`チェック済みですが分割されていません`n`。 したがって、`d`分割する`n`、これより小さい有効な約数は存在しないため、`d`まさに必要な答えです。 合成数には最大でも約数が必要です`sqrt(n)`したがって、検索では答えが見つからずに平方根の境界を通過することはできません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline
def solve():    n = int(input())
    d = 2    while d * d <= n:        if n % d == 0:            print(d)            return        d += 1
if __name__ == "__main__":    solve()
```プログラムは入力値のみを読み取り、初期化します。`d`に`2`、出力が許可されている最小の約数と一致します。 

ループは使用します`d * d <= n`の代わりに`d <= int(sqrt(n))`。 乗算は完全に整数演算にとどまるため、次のような完全平方での丸めの問題は発生しません。`49`。 

いつ`n % d == 0`、現候補者が分裂`n`。 小さい候補はすべてすでに失敗しているため、印刷`d`すぐに正しい答えが得られ、不必要な作業が回避されます。 

入力は複合であることが保証されているため、主要な場合に必要な出力はありません。 問題がプライム入力を許可する場合、アルゴリズムはループの後に追加の決定を必要とします。 ここではそのようなケースは起こりません。

 ## 特殊なケース

 のために`n = 4`、アルゴリズムは次から始まります`d = 2`。 条件`2 * 2 <= 4`それは真実であり、`4 % 2 == 0`、すぐに印刷されます`2`。 これは、特別な場合を除いて、可能な限り最小の合成数を処理します。 

のために`n = 8`、第一候補はまたしても`2`、 そして`8 % 2 == 0`。 答えは次のような候補の前に出力されます。`3`または`4`が考慮されます。 This is why the search must begin at`2`ではなく、`3`。 

のために`n = 49`、候補者`2`を通して`6`失敗。 いつ`d`到達する`7`、ループ条件は依然として true です。`7 * 7 == 49`。 割り算テストが成功し、プログラムが出力します。`7`。 使用する`d * d < n`代わりに、黙って間違った結果が生成されます。 

のために`n = 2001`、`2`失敗して、`3`成功したため、プログラムは出力します`3`。 アルゴリズムは残りの値を因数分解する必要がありません`667`なぜなら、この問題では単位以外の最小の約数のみが求められるからです。
