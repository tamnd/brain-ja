 ## 解決策
 ## 問題の理解

 このタスクは意図的に単純化されています。 1 つの文を 1 行として受け取り、その文には偶数の単語が含まれます。 一連の単語を 2 つの等しい半分に分割し、後半を前半の前に配置する必要があります。 

たとえば、次のような言葉が挙げられます。`reverse this sentence you have to`として分けられます`reverse this sentence`そして`you have to`したがって、翻訳された文は次のようになります`you have to reverse this sentence`。 

公式問題では、制限時間 1 秒とメモリ 256 MB が指定されており、単語数が偶数であることが保証されています。 このステートメントでは文の長さに関する数値の上限が提供されていないため、単語数が線形になるように設計するのが最も安全です。 文の読み取り、分割、再構築にはすべて当然 O(n) 時間がかかります (n は単語の数です)。 文の大部分を繰り返しスキャンまたはシフトするアプローチは、不必要に二次関数になる可能性があります。 

不注意な実装が露呈する可能性のある小さなケースがいくつかあります。 たった 2 つの単語で、例えば`hello world`、各半分には 1 つの単語が含まれるため、正しい出力は次のようになります。`world hello`。 両方の半分に複数の単語が含まれると想定した実装では、中間点が誤って処理される可能性があります。 

もう 1 つの境界ケースは、単語が繰り返される文です。 入力用`go go stay stay`、正しい出力は次のとおりです。`stay stay go go`。 2 つの半分は、個別の単語の値ではなく、その位置に従って処理される必要があるため、セットや重複を削除する操作を使用することは正しくありません。 

最後によくある間違いは、入力が一連の整数ではなく完全な行であることを忘れることです。 入力用`reverse this sentence you have to`、呼び出し中`input().split()`これは、行を単語に分割するのに適していますが、1 つのトークンのみを処理すると文の残りの部分が失われます。 

## アプローチ

 変換について考える強引な方法は、単語の可能な順序をすべて構築し、後半が最初に現れる順序を検索することです。 必要な答えがそれらの順列の 1 つであるため、これは正しいですが、まったく実用的ではありません。 n 個の単語があると、n 個あります。 したがって、n = 10 であってもすでに 3,628,800 の候補が得られ、その数はあまりにも急速に増加して役に立たなくなります。 

ブルートフォースアプローチは、最終的に望ましい配置を考慮するため機能しますが、問題が未知の順列を発見することを求めていないため失敗します。 動かなければならないポジションは中間地点までに完全に決まっている。 

重要な観察は、必要な出力は単に単語シーケンスをその長さの半分だけ回転したものであるということです。 もしその言葉が`w[0], w[1], ..., w[n-1]`、答えは`w[n/2], ..., w[n-1], w[0], ..., w[n/2-1]`。 

単語がリストに保存されると、Python はスライスして 2 つの半分を取得し、それらを連結できます。 すべての単語が一定回数コピーされるため、時間は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | 候補者あたり O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力行全体を読み取り、単語のリストに分割します。 変換は個々の文字ではなく単語の位置に作用するため、単語自体が必要です。 
2. 中点を次のように計算します。`n // 2`、 どこ`n`単語数です。 このステートメントでは偶数の単語が保証されているため、この中間点で文が 2 つの等しいサイズの部分に分割されます。 
3. 単語の中間点から最後までを取り上げます。 これらは後半を構成し、翻訳された文の最初に現れる必要があります。 
4. 単語の先頭から中間点の直前までを取得します。 これらは前半を構成し、後半の後に出現する必要があります。 
5. 2 つの部分をスペースを入れて連結し、結果の文を印刷します。 手動でスペースを追加するのではなくリストに参加すると、スペースの欠落や不要な末尾のスペースの両方が回避されます。 

これが機能する理由: 不変条件は、2 つのスライスに元の前半と後半が元の内部順序で正確に含まれていることです。 このアルゴリズムは、2 番目のスライスに続いて最初のスライスを出力します。これはまさに必要な変換です。 すべての元の単語はちょうど半分に属し、一度だけ出現し、同じ半分の他の単語との相対的な位置を維持するため、単語が失われたり、重複したり、間違って並べ替えられたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    words = input().split()
    mid = len(words) // 2

    answer = words[mid:] + words[:mid]
    print(" ".join(answer))

if __name__ == "__main__":
    solve()
```最初の行は文全体を読み、`split()`それをアルゴリズムで使用される単語のシーケンスに変換します。 複数のスペースが存在する場合、それは自然に処理されます。`split()`一方、必要な出力は、連続する単語の間にスペースを 1 つだけ入れて再構築されます。`mid = len(words) // 2`この問題では偶数の単語が保証されているため、安全です。 表現`words[mid:]`は後半の最初の単語から正確に始まりますが、`words[:mid]`まさに前半部分が含まれています。 

2 つのリストは必要な順序で連結されます。 ついに、`" ".join(answer)`末尾のスペースのない出力文を作成します。 唯一の算術演算は単語数を 2 で割ることであるため、整数オーバーフローの懸念はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 分割、スライス、連結、結合により、合計 O(n) ワードが処理されます。 |
 | スペース | O(n) | 単語リストと結果のリストには O(n) 個の単語が含まれます。 |

 制限時間は 1 秒、メモリ制限は 256 MB です。 入力自体には n 個の単語が含まれているため、O(n) 処理が漸近的に最適になります。アルゴリズムは少なくともそれらの単語を読み取る必要があります。 したがって、実装は不必要な繰り返しスキャンや順列生成を導入するのではなく、入力のサイズに直接応じてスケールされます。 

## テストケース```python
import sys
import io

def solve():
    words = input().split()
    mid = len(words) // 2
    answer = words[mid:] + words[:mid]
    print(" ".join(answer))

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output
        try:
            solve()
        finally:
            sys.stdout = old_stdout
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run("reverse this sentence you have to\n") == \
       "you have to reverse this sentence\n", "sample 1"

# Minimum-size input
assert run("hello world\n") == \
       "world hello\n", "minimum size"

# All words equal
assert run("go go go go\n") == \
       "go go go go\n", "all equal values"

# Boundary case with exactly two words in each half
assert run("one two three four\n") == \
       "three four one two\n", "half boundary"

# Larger input
large_words = [f"w{i}" for i in range(10000)]
large_input = " ".join(large_words) + "\n"
large_expected = " ".join(large_words[5000:] + large_words[:5000]) + "\n"
assert run(large_input) == large_expected, "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`hello world`|`world hello`| 最小の偶数ワードと中間点の処理 |
 |`go go go go`|`go go go go`| 繰り返された値は重複排除されずに保持されます。 
|`one two three four`|`three four one two`| 2 つの半分間の正しい境界 |
 | 10,000 の異なる単語 | 後半に続いて前半 | 大きな入力に対する線形処理 |

 ## 特殊なケース

 一番小さいケースは、`hello world`。 リストの長さは 2 なので、`mid = 2 // 2 = 1`。 スライス`words[1:]`は`["world"]`、 そして`words[:1]`は`["hello"]`。 それらの連結は`["world", "hello"]`、生産`world hello`。 これにより、実装で誤って使用される可能性のある off-by-one エラーが捕捉されます。`n // 2 - 1`あるいは、後半の開始が 1 つ早すぎます。 

繰り返される単語には特別な処理は必要ありません。 のために`go go go go`、中点は 2 であり、`["go", "go"]`両方の半分に。 それらを連結すると、同じ 4 つの単語のシーケンスが生成されます。 このアルゴリズムが機能するのは、単語の同一性ではなく位置に基づいて動作するためです。 

境界の場合`one two three four`、中間点は 2 です。 後半は`three four`、そして前半は`one two`、したがって、答えは次のとおりです`three four one two`。 これにより、インデックスにある単語が`mid`は後半に属し、単語はインデックスにあります`mid - 1`前半に属します。 

10,000 単語を含む大きな文の場合、中間点は 5,000 です。 アルゴリズムは 2 つの半分をコピーして一度結合するため、その作業は入力サイズに比例して増大します。 順列ベースのブルートフォース戦略では、最大 10,000 件を考慮する必要があります。 直接回転は線形のままですが、直接回転は直線的なままです。
