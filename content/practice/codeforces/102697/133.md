 ## 解決策
 ## 問題の理解

 このタスクは意図的に単純化されています。 テキスト行を表す 1 つの文字列を受け取り、その行を質問と見なすべきかどうかを決定する必要があります。 定義は純粋に構文的なものです。文字列の最後の文字は次のようにする必要があります。`?`。 その場合は印刷します`YES`; それ以外の場合は印刷します`NO`。 公式の問題では、単一の入力文字列と 1 秒の 256 MB 制限が指定されています。 

主な違いは、テキスト内のどこかに現れる疑問符と、最後の文字である疑問符との違いです。 例えば、`Is this?`は質問ですが、`Is this? really`最後の文字は`y`。 

入力は 1 つの文字列で構成されているため、ここでは意味のある大きな数値制約はありません。 実行時間は当然、読み取らなければならない入力量に比例します。 文字列が非常に長い場合でも、すべての文字を検査するアルゴリズムは入力サイズにおいて線形であり、通常の入力サイズに対して指定された制限時間に簡単に適合します。 さらに重要なことは、答えは 1 文字だけに依存するため、文字列を読み取った後に文字列全体を検査する必要がなくなることです。 

最初のエッジ ケースは、疑問符のみを含む文字列です。```
?
```正しい出力は次のとおりです`YES`。 この有効なケースを拒否する前に、疑問符に別の文字が含まれることを期待する不注意な実装。 

2 番目のエッジ ケースは、終了前に表示される疑問符です。```
hello? world
```正しい出力は次のとおりです`NO`。 文字列の存在を検索する`?`間違って戻ってきます`YES`疑問符は最後の文字ではないためです。 

3 番目のエッジ ケースには、末尾の空白が含まれます。```
hello?
```正しい結果は`NO`最後の文字がスペースではなくスペースであるため、その末尾のスペースが実際に入力文字列の一部である場合`?`。 このため、実装では盲目的に疑問符を検索するのではなく、入力行の意味のある内容を保存する必要があります。 Pythonでは、`rstrip('\n')`他の末尾文字を保持したまま、行末を削除します。 

## アプローチ

 簡単な総当たり解釈では、すべての文字をスキャンして、どれが最後の文字であるかを決定します。 これは正しいです。文字列全体を処理した後、最後に見つかった文字がまさに答えを制御する文字となるからです。 ある長さの文字列の場合`L`、これは実行します`L`最悪の場合は文字検査。 

ここには真のパフォーマンス障害はありません。 入力自体には以下が含まれます`L`文字数が多いので、読むのにすでに費用がかかります`O(L)`時間。 したがって、入力処理をカウントすると、フル スキャンが漸近的に最適になります。 文字列が読み取られた後に可能な唯一の改善策は、スキャンを回避し、その最終文字を直接検査することです。 

有益な観察は、問題には答えに影響を与える文字列の中間に関する情報が含まれていないということです。 入力行が読み取られた後のみ、`s[-1]`重要です。 したがって、フル スキャンを 1 つの直接文字比較に置き換えることができます。 

ブルート フォース スキャンは最終的に最終文字を検出するため機能しますが、結果に影響を与えない文字に対して作業を実行します。 答えが最終位置のみに依存するという観察により、入力後の計算を次のように減らすことができます。`O(1)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(L) | お(1) | 承認済み |
 | 最適 | 入力を含む O(L)、入力後は O(1) | お(1) | 承認済み |

 ここ`L`入力文字列の長さです。 入力の読み取りにはすでに線形時間がかかるため、この 2 つのアプローチの区別は、この問題に対する実際的なものというよりも、教育的なものであることがほとんどです。 

## アルゴリズムのチュートリアル

 1. 入力行全体を読み取り、改行文字のみを削除します。 実際の最後の文字によって答えが決まるため、他の文字は変更しないでおきます。 
2. 次のコマンドを使用して最後の文字にアクセスします。`s[-1]`。 Python のネガティブ インデックスでは、最後の位置にある文字が直接与えられるため、文字列をスキャンする必要はありません。 
3. その文字を次のものと比較します。`?`。 それらが等しい場合、出力します`YES`; それ以外の場合は、印刷します`NO`。 

### なぜ効果があるのか

 アルゴリズムは、質問の定義で使用されるプロパティ、つまり最後の文字が次の文字であるかどうかを正確にチェックします。`?`。 もし`s[-1] == '?'`、文字列は定義を満たしており、アルゴリズムは次のように出力します。`YES`。 もし`s[-1] != '?'`、定義が満たされていないため、アルゴリズムは次のように出力します。`NO`。 他のキャラクターはこの決定を変更できないため、最終的なキャラクターを検査するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().rstrip('\n')

print("YES" if s[-1] == '?' else "NO")
```入力は次のように読み取られます`input()`、改行が存在する場合は改行も含まれます。 正確にその改行を削除します`rstrip('\n')`。 使用する`strip()`文字列の末尾からスペースやその他の空白も削除され、最終的な文字が実際に何であるかを変更する可能性があるため、精度は低くなります。 

表現`s[-1]`最後の文字に直接アクセスします。 これにより、文字列に対する不必要なループが回避されます。 

比較は出力を選択する前に実行されます。 疑問符が生成されます`YES`、および他のすべての最後の文字が生成されます。`NO`。 

この問題では有効な入力文字列が保証されているため、`s[-1]`安全です。 整数演算がないため、整数のオーバーフローは無関係であり、off-by-one エラーを引き起こす可能性のある明示的な長さを伴うインデックス計算もありません。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    s = input().rstrip('\n')
    print("YES" if s[-1] == '?' else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("Welcome to the CodeRams contest?\n") == "YES\n", "sample 1"
assert run("We hope you like the problems!\n") == "NO\n", "sample 2"
assert run("Good luck today\n") == "NO\n", "sample 3"

# Minimum-size meaningful input
assert run("?\n") == "YES\n", "single question mark"

# All characters are ordinary text
assert run("hello\n") == "NO\n", "ordinary word"

# Question mark appears internally but is not final
assert run("hello? world\n") == "NO\n", "question mark not at end"

# Boundary case with a trailing space
assert run("hello? \n") == "NO\n", "trailing space changes final character"

 |`hello`|`NO`| 疑問符のない通常のテキスト |
 |`hello? world`|`NO`| の存在を混同することを防ぎます。`?`と`?`最後に |

## 特殊なケース

 1文字入力の場合`?`、文字列の長さは 1 であり、`s[-1]`は同じ疑問符です。 比較は成功し、出力は次のようになります。`YES`。 文字列に複数の文字が含まれている必要があると想定するソリューションは、ここでは失敗します。 

のために`hello? world`、疑問符は存在しますが、その後にスペースとその他のテキストが続きます。 このアルゴリズムでは、文字列内のどこにも疑問符が検索されることはありません。 読み取り専用です`s[-1]`、つまり`d`ので、正しく印刷されます`NO`。 

次のような入力の場合`hello? `、最後の文字はスペースです。 実装では使用します`rstrip('\n')`それよりも`strip()`, そのため、スペースは文字列の一部のままになります。 その結果`s[-1]`は空間であり、答えは`NO`。 

中心となる不変条件は単純です。答えが生成された時点では、比較される文字はまさに入力行の最後の文字です。 問題の定義はその文字のみに依存するため、考えられるすべての有効な文字列が正しく分類されます。
