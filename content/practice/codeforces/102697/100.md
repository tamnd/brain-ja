 ## 解決策
 ## 問題の理解

 私たちは持っています`n`並列に接続された正の抵抗。 2つの抵抗器に抵抗がある場合`a`そして`b`、それらの等価抵抗は

 [
 R=\frac{ab}{a+b}。 
】

 3 つ以上の抵抗の場合、ステートメントは、これまでに得られた等価抵抗と次の抵抗を繰り返し組み合わせることによって結果を定義します。 最終的な等価抵抗を手動で四捨五入せずに 10 進数として出力する必要があります。 公式声明では、時間制限は 1 秒、メモリ制限は 256 MB とされています。 

並列回路を再解釈する最も便利な方法は、コンダクタンスを利用することです。 抵抗のある抵抗器のコンダクタンス`r`は`1/r`。 並列コンダクタンスが追加されるため、抵抗については`r1, r2, ..., rn`最終的な抵抗は

 [
 R=\frac{1}{\frac1{r_1}+\frac1{r_2}+\cdots+\frac1{r_n}}。 
】

 この声明では、数値の上限は明らかにされていません。`n`したがって、特定の最大値に依存することは避けるべきです。 入力自体には`n`抵抗値。 すべてのペア、すべてのサブセット、またはすべての順序に比例して作業を実行するアプローチでは、入力サイズよりもはるかに速く増大します。 

注目に値する 2 つの特殊なケースがあります。 まず、最小の有効な入力にはちょうど 2 つの抵抗があります。 例えば、```
2
11 19
```与える```
6.966666666666667
```蓄積された抵抗をゼロに初期化してすぐに適用するという不用意な実装`(a * b) / (a + b)`最初の抵抗が処理されるときに無効な中間値が作成されます。 ゼロから開始することは、逆数公式を使用する場合にのみ意味を持ちます。 

第二に、同一の抵抗は完全に有効です。 例えば、```
3
10 10 10
```全コンダクタンスを持っています

 [
 \frac1{10}+\frac1{10}+\frac1{10}=\frac3{10}、
 】

 だから答えは```
3.333333333333333
```抵抗値が異なる必要があると想定する実装では、有効な回路が拒否されます。 入力では、抵抗が正の整数であることが示されているだけです。 

3 番目の浮動小数点のエッジ ケースは、通常、答えが整数ではなく、固定の小数点以下の桁数に四捨五入されることが期待されていないことです。 例えば、`11`そして`19`繰り返しの小数を生成します。 ジャッジは記号的な有理出力を要求するのではなく、10 進近似を受け入れるため、通常の Python 浮動小数点表現を出力するのが適切です。 

## アプローチ

 直接シミュレーションは、ステートメント内の再帰定義に従います。 最初の抵抗から始めて、現在の等価抵抗を繰り返し組み合わせます`R`次の抵抗で`x`使用して

 [
 R\leftarrow\frac{Rx}{R+x}。 
】

 これはすでに線形時間アルゴリズムです。 最初の抵抗を処理した後、次のようになります。`n-1`更新され、各更新では一定数の算術演算が実行されます。 したがって、その作業の合計は次のようになります。`O(n)`したがって、多くの問題とは異なり、単純なシミュレーションは実際にはそれほど遅くはありません。 

真に強引なアプローチでは、結果を評価する前に、さらに進んで、抵抗器のすべての順序を試したり、ペアごとの組み合わせの括弧で囲んだすべての可能性を試したりすることができます。 がある`n!`可能な順序だけでなく、固定順序であっても、`C(n-1)`可能な二項括弧、ここで`C`カタルーニャ語の数字です。 これは入力サイズよりもはるかに多くの作業を生成しますが、並列抵抗は抵抗器の結合順序とは数学的に独立しているため、不要です。 

この有益な観察は、単に操作が結合的であると言うよりも強力です。 から始まる

 [
 R=\frac{ab}{a+b}、
 】

 その逆数を取る：

 [
 \frac1R=\frac{a+b}{ab}=\frac1a+\frac1b。 
】

 これは、すべての並列抵抗が独立して同じ合計に寄与することを意味します。 新しい抵抗を繰り返し構築して次の抵抗と組み合わせる代わりに、単純に蓄積することができます。 

[
 S=\sum_{i=1}^{n}\frac1{r_i}
 】

 そして戻る`1 / S`。 

直接シミュレーションと逆数定式化は両方とも`O(n)`。 逆数定式化は、並列回路の物理構造に直接に従い、乗算と除算の繰り返しを回避し、正しさの証明が特に容易になるため、推奨されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順序付け/括弧に対するブルートフォース | 少なくとも超線形`O(n!)`|`O(n)`| 遅すぎる |
 | 直接逐次シミュレーション |`O(n)`|`O(1)`| 承認済み |
 | 逆和 |`O(n)`|`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`n`正の抵抗値。 必要なのは値自体だけであるため、回路グラフを作成したり、追加の構造を保存したりする必要はありません。 
2. 浮動小数点変数を初期化する`conductance`ゼロに。 この変数は、これまでに処理された抵抗から蓄積された合計コンダクタンスを表します。 
3. あらゆる抵抗に対して`r`、 追加`1.0 / r`に`conductance`。 抵抗のある抵抗器`r`まさに貢献する`1/r`コンダクタンスと並列コンポーネントのコンダクタンスが加算されます。 
4. すべての抵抗が処理されたら、計算します。`1.0 / conductance`。 総コンダクタンスの逆数は、完全な並列回路の等価抵抗です。 
5. 結果の浮動小数点値を直接出力します。 この問題では固定桁数や手動丸めは必要ないため、Python の通常の 10 進表現で十分です。 

不変条件は、最初の処理後の`k`抵抗器、`conductance`等しい

 [
 \sum_{i=1}^{k}\frac1{r_i}。 
】

 最初はこの合計はゼロであり、これは抵抗が加工されていない場合には正しい値です。 追加`1/r`次の抵抗を処理するときに、その抵抗のコンダクタンスだけ合計を拡張します。 最後の抵抗器の後の累積値は合計並列コンダクタンスであり、その逆数は必要な等価抵抗と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    resistances = list(map(int, input().split()))

    conductance = 0.0

    for r in resistances:
        conductance += 1.0 / r

    answer = 1.0 / conductance
    print(answer)

if __name__ == "__main__":
    solve()
```最初の 2 行は、抵抗器の数と抵抗配列を読み取ります。 入力には次の行のすべての抵抗が含まれているため、単一の`split()`指定された形式であれば十分です。`conductance`に初期化されます`0.0`、 それよりも`0`、目的の浮動小数点演算を明示的に行うため。 それぞれ`1.0 / r`は浮動小数点値であるため、累積された合計には部分コンダクタンスが保持されます。 

最後の逆数は、すべての抵抗が寄与した後にのみ取得されます。 順序を逆にして逆数を繰り返し取ろうとすると数式が変わるため、最初にコンダクタンス空間で累積を行う必要があります。 

Python の整数はオーバーフローせず、抵抗値は正であるため、ゼロによる除算は発生しません。 この問題には複数のテストケース構造がないため、呼び出しは 1 回だけです。`solve()`。

## テストケース

 元のステートメントでは 2 つのサンプルが提供されています。 数値の上限は公表されていないため、`n`、以下の最大サイズのテストでは、`100000`と主張するのではなく、ストレステストとして抵抗を使用します。`100000`公式の最大値です。```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    resistances = list(map(int, input().split()))

    conductance = 0.0
    for r in resistances:
        conductance += 1.0 / r

    print(1.0 / conductance)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run(
    "9\n"
    "37 23 56 85 41 99 33 22 11\n"
) == "3.319115819885067\n"

# Provided sample 2
assert run(
    "2\n"
    "11 19\n"
) == "6.966666666666667\n"

# Minimum-size input
assert run(
    "2\n"
    "1 1\n"
) == "0.5\n"

# All equal values
assert run(
    "3\n"
    "10 10 10\n"
) == "3.333333333333333\n"

# Boundary-style case with very different resistance magnitudes
assert run(
    "4\n"
    "1 2 4 8\n"
) == "0.5333333333333333\n"

large_input = "100000\n" + " ".join(["1"] * 100000) + "\n"
assert run(large_input) == "1e-05\n"

## 特殊なケース

 ちょうど 2 つの抵抗の場合、```
2
11 19
```コンダクタンスアキュムレータはゼロから始まり、`1/11`、その後受信します`1/19`、そして最終的には`1/(1/11 + 1/19)`。 結果は`6.966666666666667`。 2 つの抵抗器には特別なケースはなく、一般的な 1 つずつオフになるリスクが排除されます。 

抵抗が等しい場合、```
3
10 10 10
```アキュムレータは次のようになります`0.1`、 それから`0.2`、 それから`0.3`。 その逆数は`3.333333333333333`。 すべての抵抗は個別に処理されるため、重複した抵抗は特別な処理を必要としません。 

まったく異なる価値観に対して、```
4
1 2 4 8
```コンダクタンスは

 [
 1+\frac12+\frac14+\frac18=1.875、
 】

 したがって、等価抵抗は

 [
 \frac1{1.875}=0.5333333333333333。 
】

 これにより、コンダクタンスの代わりに誤って抵抗を追加する実装が捕捉されます。 

最後に、同一の単位抵抗の大規模な集合を考えてみましょう。```
100000
1 1 1 ... 1
```と`100000`の発生`1`。 すべての抵抗器はコンダクタンスの 1 単位に寄与するため、合計は次のようになります。`100000`そして等価抵抗は`0.00001`。 このアルゴリズムは抵抗ごとに 1 回の更新を正確に実行するため、実行時間は抵抗ペアの数ではなく入力量に比例して増加します。 

すべてのケースの背後にある重要な考え方は同じです。並列コンポーネントの場合、抵抗自体は加算されませんが、コンダクタンスは加算されます。 回路が逆数の和として表されると、問題は 1 つの線形スキャンに減ります。
