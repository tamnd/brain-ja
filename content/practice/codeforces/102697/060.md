 ## 解決策
 ## 問題の理解

 このタスクは、正確に (N) ビットを使用して表現できる最大の符号付き整数を要求します。 符号付き整数表現の場合、符号用に 1 ビットが予約され、正の最大値の大きさ用に (N-1) ビットが残ります。 したがって最大値は

 [
 2^{N-1}-1。 
]

 入力は単一の整数 (N) で構成されます (1 \le N \le 64)。 出力は、対応する最大符号付き整数です。 公式の問題ステートメントでも同じ式が示されており、特に 32 ビットを超える値には、より大きな値を表現できる整数型が必要であると警告されています。 

数学的演算自体は定数時間であるため、制約は意図的に小さくなっています。 (N) が 64 に達する場合でも、可能な整数を反復処理したり、個々のビットをシミュレートしたりする必要はありません。 (N) に比例するアルゴリズムはすでに十分以上ですが、(N) で指数関数的なものは不要であり、(N=64) では不可能になります。 

主なエッジ ケースは、最小ビット幅と大きな値から発生します。 (N=1) の場合、符号ビットは 1 つあり、大きさビットはありません。したがって、表現可能な最大の符号付き整数は (2^0-1=0) になります。 少なくとも 1 つの絶対値ビットが必要であると想定する不注意な実装では、誤って 1 が生成される可能性があります。 

(N=2) の場合、答えは (2^1-1=1) です。 完全な入力と出力は次のとおりです。```
2
```

```
1
```誤って (2^N-1) を計算する実装では 3 が返されます。これは、すべてのビットが絶対値ビットとして扱われ、符号付き表現が無視されるためです。 

大 (N) は、もう 1 つの実用的なエッジ ケースです。 たとえば、(N=64) の場合、答えは次のようになります。 

[
 2^{63}-1=9223372036854775807。 
]

 浮動小数点のべき乗を使用すると整数の精度が失われる可能性があり、固定幅の符号付き 32 ビット整数を使用するとオーバーフローが発生します。 Python の整数は任意精度であるため、直接の整数式は安全です。 

## アプローチ

 最も文字通りの総当たりアプローチでは、(N) ビットで表現可能なすべての符号付き整数を生成し、それが表現の正の範囲内にあるかどうかをテストし、最大のものを保持します。 (N) ビット表現には (2^N) 個の異なるビット パターンがあるため、最悪の場合でも (O(2^N)) 個の候補が必要になります。 (N=64)、つまり (2^{64})、つまり約 (1.84\times10^{19}) 回の操作です。 そのようなアプローチはまったく実行不可能です。 

ブルート フォースは、考えられるすべての表現が考慮されるため概念的に機能し、最終的に最大の有効な正の値が見つかります。 問題は、答えが単純な数学的形式であっても、その表現には膨大な数の可能性があることです。 

重要な点は、符号付き整数では符号に 1 ビットが使用されるということです。 正の符号付き整数を最大化するには、符号ビットを 0 にする必要があります。 残りの (N-1) ビットはすべて 1 である必要があります。これは、これらのビットのいずれかを 0 から 1 に変更すると、符号が正のまま値が増加するためです。 したがって、最適なビット パターンは、0 の後に (N-1) 個の 1 が続くものです。 

(N-1) 個の 1 から構成される 2 進数の値は (2^{N-1}-1) になります。 したがって、候補番号を作成したり検査したりする必要はありません。 1 回のべき乗と 1 回の減算により、直接答えが得られます。 

ブルート フォース検索は、すべての正の値がその大きさのビットによって順序付けされているという観察に置き換えられます。 利用可能なすべての振幅ビットを 1 に設定することが常に最適であり、これにより問題が指数列挙から一定数の算術演算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^N)) | (O(1)) | 遅すぎる |
 | 最適 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ビット数 (N) を読み取ります。 入力には値が 1 つだけ含まれるため、テストケース ループは必要ありません。 
2. (2^{N-1}) を計算します。 (N) ビットの 1 つが符号ビットであるため、大きさビットは (N-1) 個あります。 
3. 結果から 1 を減算します。 値 (2^{N-1}-1) は、正確に (N-1) 個の 1 から構成される 2 進数であり、可能な最大の正の値です。 
4. 結果の整数を出力します。 Python の任意精度の整数型は、オーバーフローすることなく最大のケース (N=64) を処理します。 

### なぜ効果があるのか

 正の符号付き (N) ビット整数の場合、符号ビットは 0 に固定されます。 残りの (N-1) ビットは 2 の正のべき乗に寄与するため、それらのいずれかを 1 に等しくすると、表現される値が増加するだけです。 すべての振幅ビットが 1 の場合、最大値に達します。 結果のバイナリ値は (1+2+4+\dots+2^{N-2}) となり、(2^{N-1}-1) と等しくなります。 したがって、アルゴリズムは常に (N) ビットで表現できる最大の符号付き整数を正確に出力します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
print((1 << (n - 1)) - 1)
```表現`1 << (n - 1)`整数ビットシフトを使用して (2^{N-1}) を計算します。 これにより、浮動小数点演算が完全に回避されますが、浮動小数点数はすべての大きな整数を正確に表すことができないため、これは重要です。 公式声明では、この問題に対する浮動小数点精度について明示的に警告しています。 

減算はシフト後に実行され、数式と正確に一致します。 順序は重要です。`(1 << n) - 1`すべての (N) ビットを誤って振幅ビットとして扱い、(2^N-1) を生成します。 

Python では、整数が必要なサイズに自動的に増加するため、オーバーフローの心配はありません。 この問題では、最大の中間値は (2^{63}) のみであり、Python の実用的な整数の範囲内に十分収まります。 

## 実用的な例

 公式サンプルでは(N=32)を使用しています。 

| (N) | 符号ビット | 大きさビット | (2^{N-1}) | 答え |
 | --- | --- | --- | --- | --- |
 | 32 | 1 | 31 | 2147483648 | 2147483647 |

 計算により (2^{31}-1=2147483647) が生成され、これはサンプル出力と一致します。 これは、1 つの符号ビットの意図された解釈を示し、この式がよく知られた 32 ビット符号付き整数に対して機能することを確認します。 

2 番目の例として、(N=64) を考えてみましょう。 

| (N) | 符号ビット | 大きさビット | (2^{N-1}) | 答え |
 | --- | --- | --- | --- | --- |
 | 64 | 1 | 63 | 9223372036854775808 | 9223372036854775807 |

 答えは (9223372036854775807)、つまり符号付き 64 ビット整数の最大の正の値です。 このケースは上限を行使し、実装で 32 ビット算術演算や浮動小数点のべき乗を使用してはならない理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(1)) | 1 つのビット シフトと 1 つの減算が実行されます。 |
 | スペース | (O(1)) | 入力値と結果の整数のみが保存されます。 |

 制約 (N\le64) により、算術演算が簡単になります。 小さな境界に依存しなくても、アルゴリズムは固定数の演算を実行し、考えられるビット パターンを決して列挙しないため、問題で指定された 1 秒の時間制限と 256 MB のメモリ制限に簡単に適合します。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    print((1 << (n - 1)) - 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    output = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

# Provided sample
assert run("32\n") == "2147483647\n", "sample 1"

# Minimum-size input
assert run("1\n") == "0\n", "one-bit signed integer"

# Small boundary case
assert run("2\n") == "1\n", "two-bit signed integer"

# All magnitude bits are set
assert run("8\n") == "127\n", "eight-bit signed integer"

# Maximum allowed input
assert run("64\n") == "9223372036854775807\n", "maximum bit width"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`32`|`2147483647`| 公式サンプルと標準の 32 ビット境界 |
 |`1`|`0`| 最小入力とゼロの利用可能な振幅ビット |
 |`2`|`1`| 正の値が存在する最小のケース |

 ## 特殊なケース

 (N=1) の場合、入力は次のようになります。```
1
```アルゴリズムが評価するのは、`(1 << 0) - 1`、(1-1=0) を与えます。 絶対値ビットがないため、実際にはゼロが最大の符号付き値になります。 出力は次のとおりです。```
0
```(N=2) の場合、入力は次のようになります。```
2
```アルゴリズムは計算します`(1 << 1) - 1 = 2-1 = 1`。 利用可能な正の表現はバイナリです`01`、 その間`11`は、符号付き 2 の補数解釈で負の値を表します。 出力は次のとおりです。```
1
```最大値 (N=64) の場合、入力は次のようになります。```
64
```アルゴリズムは (2^{63}-1) を計算し、次の結果を生成します。```
9223372036854775807
```Python の整数は任意の精度を持つため、オーバーフローは発生しません。 この計算では、整数ビット シフトを使用することにより、浮動小数点精度の問題も回避されます。 

最も一般的な 1 つ違いの間違いは、(2^{N-1}-1) の代わりに (2^N-1) を使用することです。 たとえば、(N=8) の場合、間違った式では 255 が得られますが、8 ビット符号付き整数は 127 までの正の値しか表現できません。正しい計算では 7 絶対値ビットを使用し、(2^7-1=127) となります。
