 ## 解決策
 ## 問題の理解

 課題は正三角形の集合に関するものです。 各三角形は 1 辺の長さのみで表されます。 正三角形の3つの辺はすべて等しいので、辺の長さのある三角形の周囲の長さは次のようになります。`t`は`3 * t`。 目標は、指定されたすべての三角形の周囲長を加算し、合計値を出力することです。 

入力には、三角形の数とそれに続く辺の長さが含まれます。 出力は、すべての三角形の周囲の合計を表す単一の整数です。 主な観察は、等辺プロパティを使用した後にジオメトリが消えることです。 問題は、各辺の長さを 3 倍した後の値の単純な累積になります。 

制約は、入力を直接走査するのに十分小さいものです。 たとえ三角形の数が非常に多かったとしても、すべての辺の長さが独立して答えに寄与するため、唯一の合理的なアプローチは線形であることに変わりはありません。 不要な情報を保存したり、三角形を相互に比較したりするアプローチでは、問題のプロパティをまったく使用せずに作業が追加されます。 

主なエッジケースは、算術を正しく処理することで発生します。 単一の三角形も処理する必要があります。 たとえば、次のような入力です。```
1
5
```出力があります:```
15
```不用意に実装すると、入力値が周囲長ではなく辺の長さであることを忘れる可能性があります。 

もう 1 つのケースは、すべての三角形の辺の長さが同じである場合です。```
3
7
7
7
```出力は次のとおりです。```
63
```すべての三角形の寄与は独立しているため、すべての三角形を含める必要があります。 最大または最小の辺の長さのみを保持する実装は、ここで失敗します。 

大きな値も間違いの原因となる可能性があります。 周囲の合計は個々の辺の長さよりもはるかに大きくなる可能性があるため、実装では結果を手動で制限するのではなく、Python の整数演算に依存する必要があります。 

## アプローチ

 強引なアプローチは、各三角形をオブジェクトとして扱い、その 3 つの辺を計算し、周囲長を計算して、それを答えに追加することです。 これは正しいです。なぜなら、すべての三角形はそれ自身の周囲に正確に寄与しており、他の三角形に影響を与える三角形はないからです。 ただし、各三角形から必要な情報は辺の長さだけであるため、不必要な表現を作成しても役に立ちません。 

有益な観察は、正三角形の周長が常に辺の長さの 3 倍に等しいということです。 ジオメトリを再構築したり、条件を確認したりする必要はありません。 各辺の長さを読み取り、3 倍し、すぐに加算できます。 

三角形ごとの演算数が一定であるため、総当たりのアイデアは機能しますが、不必要なステップをすべて削除することでさらに簡素化できます。 問題の構造により、解決策を入力の 1 回のパスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 受け入れられますが、不要なデータが保存されます |

 ## アルゴリズムのチュートリアル

 1. 三角形の数を読み取ります。 次の各値は、最終的な答えに独立して寄与する 1 つの辺の長さを表します。 
2. 辺の長さごとに`t`、 追加`3 * t`現在の合計に。 3 の因数は、正三角形の周長の公式から直接得られます。 
3. すべての三角形が処理された後、累積合計を出力します。 

なぜ効果があるのか:

 スキャン中に維持される不変条件は、最初のスキャンの処理後の不変条件です。`k`三角形の場合、保存されている答えは、それらの周囲の長さの正確な合計です。`k`三角形。 次の辺の長さを読み込むときに加算します。`3 * t`その三角形の欠落している寄与を正確に追加します。 最後の三角形が処理された後、不変式により必要な合計周長が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = 0

    for _ in range(n):
        side = int(input())
        ans += 3 * side

    print(ans)

if __name__ == "__main__":
    solve()
```以前の辺の長さの寄与が追加された後は不要になるため、プログラムは現在の答えのみを保持します。 

乗算は、各三角形がその周囲全体に寄与するように、答えに加算する前に実行されます。 Python の整数は大きな合計を自動的に処理するため、オーバーフローの心配はありません。 

ループは三角形ごとに 1 回だけ実行されます。 並べ替え、検索、または追加のストレージがないため、実装が問題の構造に合わせて調整されます。

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.read().split()

    sys.stdin = old_stdin

    if not data:
        return ""

    n = int(data[0])
    ans = 0

    for i in range(1, n + 1):
        ans += 3 * int(data[i])

    return str(ans)

 ## 特殊なケース

 一辺の長さのある三角形 1 つの場合`5`、アルゴリズムが値を読み取り、計算します`3 * 5`、およびプリント`15`。 複数の三角形の存在に依存しないため、可能な限り最小の入力が自然に処理されます。 

次のような等しい三角形が繰り返される場合:```

7
7
```アルゴリズムは同じ計算を 3 回実行し、累積します。`21 + 21 + 21`、生産`63`。 これにより、入力を一意の長さのセットとして扱うことによって引き起こされる間違いを回避できます。 

次のような非常に長い辺の長さの場合:```
2
1000000000
1000000000
```累計は次のようになります`6000000000`。 Python 整数は、値が通常のマシン整数サイズを超えると自動的に拡張されるため、計算は正しいままになります。
