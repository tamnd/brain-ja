 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられます。 それらの長さと順序は必ずしも一致する必要はありません。 チェッカーは答えるべきです`YES`両方の配列にまったく同じ個別の値が含まれている場合、各値が何回出現するか、および値が出現する順序は関係ありません。 それ以外の場合は応答するはずです`NO`。 

例えば、`[1, 2, 3]`そして`[3, 1, 1, 2, 3]`2 番目の配列から繰り返し出現した部分を削除すると、それらは等しいと見なされます。`{1, 2, 3}`、これは最初の配列の値のセットでもあります。 対照的に、`[1, 2, 3, 4]`そして`[1, 2, 7]`異なるのは、それぞれの個別の値セットが異なるためです。 

入力は次のもので構成されます`n`、続いて`n`最初の配列の要素、その後`m`、続いて`m`2 番目の配列の要素。 元のステートメントでは、1 秒の時間制限と 256 MB のメモリが与えられていますが、有効な数値の上限は公開されていません。`n`そして`m`。 このため、漸近的な動作が特に重要になります。 要素を繰り返し比較したり、不必要な作業を実行したりするよりも、入力に対して 1 回だけパスを実行するソリューションの方が適しています。 

最初のエッジ ケースは、重複が多い入力です。 考慮する：```
3

2

1

3
```正しい出力は次のとおりです。```
YES
```配列を要素ごとに比較する不注意な実装では、長さが異なり、2 番目の配列に繰り返し値が含まれているため、配列が拒否されます。 実際の条件では多重度が無視されているため、この比較は不適切です。 

2 番目のエッジケースは順序が異なります。 考慮する：```
3

```正しい出力は次のとおりです。```

```位置を直接比較すると、誤った結果が生成されます。`NO`両方の配列にまったく同じ異なる整数が含まれている場合でも。 

3 番目のエッジ ケースは、1 つの配列内で重複としてのみ現れる値です。 考慮する：```

## アプローチ

 簡単なアプローチは、両方の配列を並べ替えて、連続する重複を削除することです。 並べ替えでは等しい値が互いに並べられるため、重複排除後に結果として得られる 2 つの配列を直接比較できます。 これは正しいです。並べ替えでは元の順序の関連性が削除され、重複排除では多重性の関連性が削除されるためです。 

このアプローチの問題は、仕分けコストがかかることです。`O(n log n + m log m)`。 両方の配列に around が含まれている場合`10^5`これは、何百万もの比較を意味します。 より正確には、大まかな比較数は次のようになります。`n log2 n + m log2 m`、両方のサイズを比較すると約 340 万件になります。`10^5`。 これは多くの環境で実現可能ですが、この問題には不要です。 

すべての要素を他の配列のすべての要素と比較してチェックすることによって、ブルート フォースがさらに悪化する可能性もあります。 それには必要なもの`O(nm)`比較。 と`n = m = 10^5`、これは届きます`10^10`これは、1 秒のコンテスト ソリューションで実現できる範囲をはるかに超えています。 

重要な観察は、この問題では順序や頻度が重要ではないということです。 これらはまさに、セットが破棄する 2 つのプロパティです。 各配列をセットに変換すると、重複はすぐに削除され、セットの等価性は順序付けを自動的に無視します。 ソートと重複排除が各配列の正規表現を明示的に構築するため、ブルート フォースが機能します。 個別の値のみが重要であるという観察により、ハッシュ セットを使用してその表現を直接構築できます。 

したがって、最適な解決策は、単純に両方の配列を読み取り、それらのセットを構築し、2 つのセットを比較することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 並べ替え、重複排除、比較 |`O(n log n + m log m)`|`O(n + m)`| 受け入れられたが、不必要な作業 |
 | ペアごとの比較 |`O(nm)`|`O(1)`入力ストレージとは別に | 大規模な配列には遅すぎる |
 | 等価性を設定する |`O(n + m)`平均 |`O(n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして次を消費する`n`最初の配列として整数を指定します。 すべての値をセットに挿入します。 繰り返し発生しても必要な答えには影響しないため、セットはまさに重要な情報です。 
2.読む`m`そして次を消費する`m`2 番目の配列として整数を指定します。 同じ理由で、すべての値を別のセットに挿入します。 
3. 2 つのセットを比較します。 まったく同じ値が含まれている場合は、出力します。`YES`; それ以外の場合は印刷します`NO`。 Python のセットの等価性は暗黙的に両方向をチェックするため、いずれかの配列に値が欠落していると比較が失敗します。 
4. 元の長さを比較しないでください。 1 つの配列に重複が含まれる場合、異なる長さは完全に有効です。 たとえば、長さ`3`そして`5`最初のサンプルでは依然として等しいセットが生成されます。 

機能する理由: すべての要素が処理された後、最初のセットには最初の配列で発生するすべての個別の値が正確に含まれ、2 番目のセットには 2 番目の配列で発生するすべての個別の値が正確に含まれます。 集合の等価性は、一方の配列のすべての個別の値がもう一方の配列に出現する場合、またはその逆の場合に正確に当てはまります。 これはまさに、重複を削除し、順序を無視することによって説明される条件であるため、アルゴリズムは有効なペアを次のように分類できません。`NO`または無効なペア`YES`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    pos = 0

    n = data[pos]
    pos += 1

    first = set(data[pos:pos + n])
    pos += n

    m = data[pos]
    pos += 1

    second = set(data[pos:pos + m])

    print("YES" if first == second else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは入力全体を整数として読み取り、それを介してインデックスを進めます。 これは、入力形式によって正確な配列の長さが示されるため、ここでは便利です。`sys.stdin.buffer.read()`繰り返しの行読み取りのオーバーヘッドを回避します。 

最初のスライスには正確に次の内容が含まれています`n`値なので、位置は次のように進みます。`n`読む前に`m`。 同じ考え方が 2 番目の配列にも使用されます。 これらの境界を明示的に保つことで、2 番目の配列の長さが誤ってその要素の 1 つとして解釈される可能性がある、off-by-one エラーを防ぐことができます。 

への変換`set`中心的なオペレーションです。 Python は繰り返された値を自動的に破棄するため、明示的な並べ替えや重複削除パスは必要ありません。 Python の整数には任意の精度があるため、配列値の整数オーバーフローの問題もありません。 

このステートメントでは、配列要素が別々の行で提供されると述べていますが、空白で区切られた整数の読み取りは同等であり、実装はさまざまな空白レイアウトに対して堅牢になります。 

## 実用的な例

 最初のサンプルの最初の配列は次のとおりです。`[1, 2, 3]`、一方、2 番目の配列は`[1, 1, 2, 2, 3]`。 2 番目の配列がセットに変換されると、重複した出現は消えます。 

| ステップ |`first`|`second`| 結果 |
 | --- | --- | --- | --- |
 | 最初の配列を読み取る |`{1, 2, 3}`| まだ読んでいません | |
 | 2 番目の配列を読み取る |`{1, 2, 3}`|`{1, 2, 3}`| |
 | 比較 |`{1, 2, 3}`|`{1, 2, 3}`|`YES`|

 トレースは、多重度を無視する必要がある理由を示しています。 2 番目の配列には 5 つの要素がありますが、そのセットには 3 つの異なる値のみが含まれており、最初の配列と完全に一致します。 これは正式な最初のサンプルです。 

2 番目のサンプルの配列は次のとおりです。`[1, 2, 3, 4]`そして`[1, 2, 7]`。 

| ステップ |`first`|`second`| 結果 |
 | --- | --- | --- | --- |
 | 最初の配列を読み取る |`{1, 2, 3, 4}`| まだ読んでいません | |
 | 2 番目の配列を読み取る |`{1, 2, 3, 4}`|`{1, 2, 7}`| |
 | 比較 |`{1, 2, 3, 4}`|`{1, 2, 7}`|`NO`|

 値`3`第2セットには欠落しているが、`7`最初から欠席です。 したがって、等価性の設定は失敗します。 こちらは公式サンプル第二弾です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n + m)`平均 | 各配列要素はハッシュ セットに 1 回挿入され、その後平均線形時間セット比較が行われます。 
| スペース |`O(n + m)`| 2 つのセットには、各個別の値のコピーが最大 1 つ保存されます。 

このソリューションは、入力要素の数において線形の期待される作業のみを実行します。 配列に多くの繰り返し値が含まれている場合でも、すべての入力要素は 1 回処理され、重複した要素が追加のセット エントリを占有することはありません。 1 秒の制限があるため、これは大きな入力に対する適切な漸近アプローチです。
