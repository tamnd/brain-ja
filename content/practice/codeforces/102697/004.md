 ## 解決策
 ## 問題の理解

 この問題は、多角形の辺の数がわかっている場合に、その内角の合計を求めます。 すべてのテスト ケースで、入力は多角形の辺の数を示し、出力はその多くの辺を持つ多角形のすべての内角の合計になるはずです。 この問題は、基本的な幾何学的観察から生じています。多角形に 1 つの余分な辺を追加すると、角度の合計がちょうど 180 度増加します。 

多角形`n`側面は次のように分割できます`n - 2`1 つの頂点から対角線を引いて三角形を作成します。 すべての三角形は 180 度に寄与するため、角度の合計は次のようになります。`(n - 2) * 180`。 入力には複数の独立したテスト ケースが含まれているため、アルゴリズムはこの式を各ポリゴンに個別に適用する必要があります。 

制約は小さく、辺の数は 100 に制限されています。これは、直接シミュレーションでも十分に高速であることを意味しますが、意図したソリューションでは角度を繰り返し追加する代わりに数学的関係を使用する必要があります。 テスト ケースごとに必要な作業量は一定であるため、テスト ケースの数が非常に多くても、必要な時間はテスト ケースの数に比例するだけです。 

主なエッジケースは、式を誤って使用したことに起因します。 よくある間違いは、辺の数を三角形の数として扱い、次のような多角形であることを忘れることです。`n`側面のみを作成します`n - 2`三角形。 

たとえば、入力が次の場合:```
1
3
```正しい出力は次のとおりです。```
180
```増殖する不注意な実装`n`by 180 は 540 を出力します。これは、三角形に対角線がなく、1 つの三角形のみで構成されていることを無視するためです。 

別のケースは四角形です。```
1
4
```正しい出力は次のとおりです。```
360
```多角形は 4 つではなく 2 つの三角形に分割されるため、答えは次のようになります。`(4 - 2) * 180`。 

## アプローチ

 強引なアプローチは、角度の合計が 180 度の三角形から開始し、必要な辺の数に達するまで、追加の辺ごとに 180 度を繰り返し加算することです。 このアプローチは正しいです。なぜなら、新しい各辺が三角形分割にちょうど 1 つ多くの三角形を提供するからです。 多角形の場合`n`側面、これは実行します`n - 2`追加。 

指定された境界で`n <= 100`、これはすでに十分に高速です。 ただし、圧縮できる作業を繰り返します。 加算を数学的に展開すると、合計は次のようになります。`180 + 180 + ... + 180`まさに`n - 2`条件、つまり単純に`(n - 2) * 180`。 

すべての多角形を正確に三角形分割できるという観察`n - 2`三角形を使用すると、反復の必要がなくなります。 解はテスト ケースごとに 1 つの乗算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n) | お(1) | 受け入れられますが、不要です |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは 1 つのポリゴンを独立して記述します。 
2. 各多角形について、辺の数を読み取ります。`n`。 多角形`n`側面は次のように分割できます`n - 2`1 つの頂点から対角線を引いて三角形を作成します。 これらの三角形はそれぞれ、内角の合計に 180 度寄与します。 
3. コンピューティング`(n - 2) * 180`そして結果を出力します。 乗算は、三角形の数と各三角形の寄与を乗算したものを直接表します。 

なぜ効果があるのか:

 このアルゴリズムは、固定された幾何学的プロパティ、つまりすべての単純なポリゴンに依存しています。`n`辺を正確に分割できます`n - 2`三角形。 すべての三角形の内側の角度の合計は常に 180 度であるため、多角形の内角の合計は三角形の数に 180 を乗じた値でなければなりません。式は考えられるすべての有効な多角形サイズを考慮しているため、特別な構築やシミュレーションは必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        ans.append(str((n - 2) * 180))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラムは最初に読み取ります`t`、処理するポリゴンの数。 次に、各辺のカウントを個別に処理します。 

表現`(n - 2) * 180`は数学的解全体です。 多角形は表現できないため、減算は乗算の前に行う必要があります。`n`三角形、それは表します`n - 2`三角形。 

最大サイドカウントが小さいため、出力値は通常の整数の範囲内に簡単に収まります。 Python の整数を使用すると、オーバーフローの心配もなくなります。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        ans.append(str((n - 2) * 180))
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 三角形の場合:```
1
3
```アルゴリズムが計算します`(3 - 2) * 180`、ちょうど 1 つの三角形を残します。 出力は`180`これにより、サイド数自体を乗算するというよくある間違いを回避できます。 

四角形の場合:```
1
4
```アルゴリズムが計算します`(4 - 2) * 180`、生産`360`。 四角形は 2 つの三角形に分割されるため、結果は 180 度の 2 つの寄与から得られます。 

許可される最大のポリゴンの場合:```
1
100
```アルゴリズムが計算します`(100 - 2) * 180 = 17640`。 同じ式が追加の処理なしで適用され、実装が小さなポリゴン サイズに依存しないことがわかります。
