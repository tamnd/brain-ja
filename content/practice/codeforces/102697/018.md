 ## 解決策
 ## 問題の理解

 この問題では、いくつかのレバーの機械的利点を計算するように求められます。 各テスト ケースに対して、2 つの正の長さが与えられます。`A`そして`B`、レバーの両側を表します。 機械的な利点はこれらの長さの比率であるため、必要な値は次のようになります。`A / B`。 最初の入力整数は、レバーの説明がいくつ続くかを示し、次のそれぞれの説明は`n`行には 1 つのペアが含まれます`A B`。 ペアごとに 1 つの実数を出力します。 公式の例では、次のような直接比率が確認されています。`10 / 5 = 2.0`そして`2 / 3 = 0.6666666666666666`。 

公表された声明では、明示的な数値限界は示されていない。`n`、`A`、 または`B`, ただし、制限時間は 1 秒のみ、メモリ制限は 256 MB です。 幸いなことに、各テスト ケースで必要な算術演算は 1 つだけなので、非常に多くのケースでも線形時間で処理できます。 ここで二次アルゴリズムや指数アルゴリズムを考慮する理由はありません。 実装上の主な懸念は、誤って整数の除算を実行するのではなく、除算を浮動小数点値として生成することです。 

単純なエッジケースは等しい辺です。 入力用`1`に続く`5 5`、答えは`1.0`。 整数の除算を使用した実装では、依然として次の結果が得られます。`1`これは数値的には正しいですが、問題で示された浮動小数点出力に従っていません。 

より明らかなケースは、入力などの分子が小さい場合です。`1`に続く`2 3`。 正しい出力は次のとおりです`0.6666666666666666`。 整数除算を不注意に実装すると、`0`、メカニカルアドバンテージを完全に失います。 

双方の順序も重要です。 入力用`1`に続く`3 2`、答えは`1.5`、 ない`0.6666666666666666`。 比率を順序のないペアとして扱うか、オペランドを逆にすると、2 つの辺の物理的な意味が変わります。 

## アプローチ

 最も直接的なアプローチは、すべてのレバーを個別に処理することです。 読む`A`そして`B`、計算します`A / B`をクリックし、結果をすぐに出力します。 すべての入力ペアを読み取る必要があり、すべてのペアには計算する必要がある個別の答えがあるため、これはすでに最適な漸近解です。 

問題の背後に隠れている意味のある高速アルゴリズムはありません。 仮説的な総当たりアプローチでは、減算を繰り返したり、10 進表現を検索したりして比率を導出するために追加の作業がかかる可能性があります。 このようなアプローチは原理的には正しいですが、不必要な操作が実行されます。 たとえば、コンピューティング`10 / 5`減算を繰り返すと、1 回の除算ではなく複数のステップが必要になり、値が大きい場合、数値の大きさに応じて演算の数も増加します。 入力に次のものが含まれている場合`n`値が大きいペアの場合、必要な値よりもはるかに高価になる可能性があります`n`部門。 

重要な観察は、式自体がすでに答えを与えているということです。 異なるレバー間の相互作用、可能な構成に対する最適化、およびあるテスト ケースから別のテスト ケースに状態を引き継ぐ必要はありません。 一度`A`そして`B`がわかっていても、答えは完全に決定されます。`A / B`。 

したがって、最適解はテスト ケースごとに 1 つの浮動小数点除算を単純に実行します。 実行時間は入力ペアの数に比例し、追加のメモリ使用量は一定です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 反復減算実装における O(n · max(A, B)) | お(1) | 値が大きいと遅すぎる |
 | 直接部門 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レバー構成の数を読み取り、`n`。 これにより、処理する必要があるペアの数が正確にわかります。 
2. 繰り返します`n`回して 2 つの正の長さを読み取ります`A`そして`B`。 各ペアは独立しているため、前のペアを保存する必要はありません。 
3. コンピューティング`A / B`Python を使用する`/`オペレーター。 パイソンの`/`は常に浮動小数点除算を実行します。これはまさに出力に必要なものです。 
4. 結果の値を出力します。 Python の標準の浮動小数点表現は、これらの通常の整数入力の例に示されている表現と一致します。 

### なぜ効果があるのか

 すべてのレバーについて、機械的利点は 2 つの側面の長さの比によって定義されます。`A`分子として、そして`B`分母として。 アルゴリズムは、入力ペアごとにその比率を 1 回正確に計算し、出力します。 各テスト ケースは独立しているため、一度に 1 つずつ処理しても他の回答に影響を与えることはできません。 したがって、印刷されるすべての値は、必要な機械的利点となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    for _ in range(n):
        a, b = map(int, input().split())
        print(a / b)

if __name__ == "__main__":
    solve()
```最初の行はテスト ケースの数を読み取ります。 ループは正確に実行されます`n`そのため、誤って余分な行を処理したり、ペアをスキップしたりするリスクはありません。 

表現`a / b`の代わりに意図的に使用されます`a // b`。 前者は浮動小数点除算を生成しますが、後者は小数部分を破棄します。 この区別は次のような場合に不可欠です。`2 3`、その答えはおよそ`0.6666666666666666`。 

分母は問題ステートメントによって正であることが保証されているため、ゼロによる除算には特別な処理は必要ありません。 Python の整数は入力の読み取り中のオーバーフローも回避し、実際の除算は Python の浮動小数点演算によって処理されます。 

入力は次のように処理されます`sys.stdin.readline`、高速な競合プログラミング I/O に必要です。 各回答は、対応するペアが読み取られた直後に出力できるため、配列は必要ありません。 

## 実用的な例

 最初のサンプルでは、アルゴリズムは 4 つの独立したレバー構成を処理します。 

| ステップ | あ | B | A / B | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 5 | 2.0 | 2.0 |
 | 2 | 2 | 3 | 0.6666666666666666 | 0.6666666666666666 |
 | 3 | 7 | 5 | 1.4 | 1.4 |
 | 4 | 18 | 7 | 2.5714285714285716 | 2.5714285714285716 |

 これは、各ペアが独立して処理され、端数の回答が切り捨てられるのではなく保存されることを示しています。 サンプル自体は、次の 4 つの出力を提供します。 

2 番目の例として、2 つの等面レバーと逆面レバーを考えてみましょう。 

| ステップ | あ | B | A / B | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 5 | 1.0 | 1.0 |

 トレースは、オペランドの順序を保持する必要がある理由を示しています。 スワッピング`A`そして`B`2つの辺が同じ長さでない限り、答えは変わります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | それぞれの`n`レバー構成では 1 つの分割と 1 つの出力操作が必要です。 |
 | スペース | お(1) | 現在の辺の長さのペアのみが保存されます。 |

 このソリューションは入力ペアごとに一定の作業を実行するため、実行時間は構成の数に応じて直線的に増加します。 1 秒の制限では、これは適切な複雑さであり、一定のメモリ使用量は問題で指定された 256 MB の制限を余裕で下回ります。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    for _ in range(n):
        a, b = map(int, input().split())
        print(a / b)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run(
    "4\n"
    "10 5\n"
    "2 3\n"
    "7 5\n"
    "18 7\n"
) == (
    "2.0\n"
    "0.6666666666666666\n"
    "1.4\n"
    "2.5714285714285716\n"
), "sample 1"

# Minimum-size style case
assert run("1\n1 1\n") == "1.0\n", "minimum-size / equal sides"

# All values equal
assert run(
    "4\n"
    "5 5\n"
    "100 100\n"
    "999 999\n"
    "1000000 1000000\n"
) == (
    "1.0\n"
    "1.0\n"
    "1.0\n"
    "1.0\n"
), "all equal values"

# Fraction smaller than one
assert run(
    "3\n"
    "1 2\n"
    "2 3\n"
    "7 10\n"
) == (
    "0.5\n"
    "0.6666666666666666\n"
    "0.7\n"
), "fractional answers"

# Boundary-oriented large values and reversed operands
assert run(
    "4\n"
    "1000000000 1\n"
    "1 1000000000\n"
    "999999999 1000000000\n"
    "1000000000 999999999\n"
) == (
    "1000000000.0\n"
    "1e-09\n"
    "0.999999999\n"
    "1.000000001\n"
), "large values and operand order"

# Large number of test cases
large_input = "100000\n" + "7 5\n" * 100000
assert run(large_input).count("1.4\n") == 100000, "large n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`1.0`| 最小サイズのケースと等しい辺 |
 | いくつかの`x / x`ペア |`1.0`すべてのペアについて | すべて等しい値 |
 |`1 / 2`、`2 / 3`、`7 / 10`| 小数値 | 正しい浮動小数点除算 |
 | 非常に大きな逆ペア | 上下の値`1`| 大きな値とオペランドの順序 |
 | 100000部`7 5`| 100000部`1.4`| 線形処理と入力処理 |

 ## 特殊なケース

 除算では正確に結果が得られるため、等しい辺の長さは直接処理されます。`1.0`。 入力用`1`に続く`5 5`、アルゴリズムは次のように読み取ります`A = 5`そして`B = 5`、計算します`5 / 5`、およびプリント`1.0`。 特別なケースは必要ありません。 

小数の結果も追加のロジックなしで処理されます。 入力用`1`に続く`2 3`、アルゴリズムは次のように評価します`2 / 3`、生産`0.6666666666666666`Python の標準浮動小数点表現を使用します。 整数除算の実装では、誤って生成される可能性があります。`0`。 

オペランドの順序は保持されます。 入力用`1`に続く`3 2`、アルゴリズムは次のように計算します。`3 / 2 = 1.5`。 ペアを逆にすると、代わりに次のようになります。`2 / 3`したがって、2 つの値を正しい分子と分母に読み取る必要があります。 

大きな値には、Python での特別なオーバーフロー処理は必要ありません。 のために`1`に続く`1000000000 1`、アルゴリズムは次のように計算します。`1000000000 / 1`そしてプリント`1000000000.0`。 正の入力値の大きさに関係なく、同じ定数作業アプローチが適用されます。 

最後に、多数の独立したテスト ケースでは、入力構造全体を保存する必要がありません。 各ペアは読み取られ、分割され、すぐに印刷されます。 したがって、コンフィギュレーションの数が多い場合でも、メモリ消費量は一定に保たれます。
