 ## 問題の理解

 この問題では、最初の部分を出力するように求められます。`n`の倍数ごとに存続する正の整数`3`が削除されます。 番号`0`も削除されますが、出力には正の整数のみが含まれるため、答えには表示されません。 生き残るシーケンスが始まる`1, 2, 4, 5, 7, 8, 10, 11, ...`したがって、3 つの連続する整数の各ブロックは、正確に 2 つの生存者を提供します。 

入力には 1 つの正の整数が含まれています`n`、出力する必要がある残りの整数の数。 出力にはそれらが含まれます`n`整数、1 行に 1 つ。 公式声明では、1 秒の時間制限と 256 MB のメモリが与えられており、明示的な上限はありません。`n`問題ページに表示されます。 出力自体には次のものが含まれているため、`n`整数の場合、どのソリューションでも少なくとも`O(n)`答えを書くだけの時間です。 線形以上の処理を行うアルゴリズムは不要です。 

最初の微妙なケースは、`n = 1`。 答えは`1`、 ない`0`、 なぜなら`0`明示的に破棄されます。```
1
```正しい出力は次のとおりです。```
1
```から検索を開始する実装`0`そして、すべての非倍数を扱います`3`生存者が誤って印刷してしまう可能性があるため、`0`出力が正の整数であることを忘れた場合。 

別の境界ケースは、完全なブロックの終わりに正確に発生します。 例えば：```
3

## アプローチ

 最も直接的な解決策は、破壊プロセスをシミュレートすることです。 から開始`1`、各整数をテストし、それが次の値で割り切れない場合は常にそれを出力します。`3`。 印刷後に停止する`n`生存者。 これは正しいです。`x % 3 != 0`まさに、存続する整数の定義です。 

ここでのシミュレーションは、実際には漸近的に遅くなりすぎることはありません。 連続する 3 つの正の整数ごとに、ちょうど 2 つが生き残るため、最初の整数を見つけることができます。`n`生存者は正確に調べる必要がある`n + floor((n - 1) / 2)`正の整数。 せいぜいそれくらいです`1.5n`モジュロ演算の後に続く`n`出力操作。 したがって、ブルートフォース手法はすでに`O(n)`また、必要な出力でサポートされる実際の入力サイズとして受け入れられます。 

有益な観察は、生き残った数には一定のパターンがあるということです。 各グループ`3k + 1, 3k + 2, 3k + 3`正確に 2 つの生き残った値が含まれています。`3k + 1`そして`3k + 2`。 この構造を使用して、`i`候補者を 1 つずつ確認するのではなく、-th の生存者を直接確認します。 

1 から始まるインデックスの場合`i`、破壊された倍数の数`3`の前に`i`-番目の生存者はまさに`floor((i - 1) / 2)`。 破壊された数字を生存者の 1 ベースの位置に追加すると、次のようになります。`answer(i) = i + floor((i - 1) / 2)`。 

たとえば、次のようなとき`i = 5`、私たちは得ます`5 + 2 = 7`。 いつ`i = 6`、私たちは得ます`6 + 2 = 8`。 数式はシーケンスを直接生成します。 

出力自体が次のものを持っているため、どちらの方法も線形です。`n`線。 出力されるすべての値が一定時間で計算され、シーケンスの構造が明示的であるため、式ベースのソリューションが推奨されます。

 ## アルゴリズムのチュートリアル

 1.読む`n`、必要な生存者の数。 
2. 1 ベースのポジションごとに`i`から`1`を通して`n`、計算する`i + (i - 1) // 2`。 追加された項は次の倍数を数えます。`3`はこのサバイバーの前に出現しているため、サバイバーをすべての正の整数の中で実際の位置に移動します。 
3. 計算された各値を出力に追加し、すべての値をまとめて出力します。 まさにあるはずなので、`n`出力行で各回答を 1 回生成すると、必要な直線的な実行時間が得られます。 

### なぜ効果があるのか

 正の整数が 3 つのブロックに分割されていると考えてください。`1, 2, 3`、`4, 5, 6`、`7, 8, 9`、 等々。 

各ブロックは最初の 2 つの数値を提供し、3 番目の数値を破棄します。 1ベースの位置にいるサバイバーの前`i`、 その通り`(i - 1) // 2`破壊された番号はスキップされました。 したがって、すべての正の整数の中のその値が生存者の位置になります。`i`スキップされた値と正確に同じ数が加算されます。 式`i + (i - 1) // 2`その結果、すべての生存者が昇順に生成され、倍数は存在しません。`3`含まれ、残りの正の整数は省略されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = []
    for i in range(1, n + 1):
        ans.append(str(i + (i - 1) // 2))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```数式は自然に最初の生存者、2 番目の生存者などの観点から表現されるため、ループでは 1 から始まるインデックスが使用されます。 のために`i = 1`、式は次のようになります`1`、特別な場合を除いて最小の有効な入力を処理します。 

表現`(i - 1) // 2`は重要な実装の詳細です。 使用する`i // 2`奇数のインデックスが付けられたすべての生存者が誤ってシフトされてしまいます。 たとえば、`i = 3`、正解は`4`、 その間`3 + 3 // 2`生み出すだろう`4`偶然ですが、`i = 5`、正しい表現は次のようになります。`7`一方、異なる丸め規則を使用するとエラーが発生する可能性があります。 整数除算の前の減算は、位置に先行する完全な生存ペアの数を直接表します。`i`。 

Python の整数には任意の精度があるため、整数オーバーフローの問題はありません。 答え自体はほんの約です`1.5n`、出力文字列の保存は出力サイズに線形です。

## テストケース```python
import sys
import io

def solve():
    n = int(input())
    ans = [str(i + (i - 1) // 2) for i in range(1, n + 1)]
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

# Provided samples
assert run("5\n") == "1\n2\n4\n5\n7", "sample 1"
assert run("11\n") == (

), "sample 2"
assert run("3\n") == "1\n2\n4", "sample 3"

# Minimum-size input

# All early positions, catches the alternating gap pattern

# Boundary across several complete groups
assert run("8\n") == "1\n2\n4\n5\n7\n8\n10\n11", "group boundary"

assert large_lines[0] == "1", "large first value"

 ## 特殊なケース

 のために`n = 1`、入力は```
1
```ループは次のようにして 1 回実行されます`i = 1`。 スキップカウント項は次のとおりです。`(1 - 1) // 2 = 0`、したがって、答えは次のとおりです`1 + 0 = 1`。 したがって、出力は正確に次のようになります`1`、および破壊された値`0`正の整数シーケンスには決して入りません。 

のために`n = 3`、入力は```

```3 回の反復により生成されるのは、`1`、`2`、 そして`4`。 3 番目の値は次より大きいです`3`なぜなら`3`破壊されます。 この式は次のように説明されます。`(3 - 1) // 2 = 1`、与える`3 + 1 = 4`。 

のために`n = 5`、入力は```
