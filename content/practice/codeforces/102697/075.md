 ## 問題の理解

 店内には、農産物、肉、乾物、そして最後に農産物に戻るという、一定のサイクルで配置された 3 つのセクションがあります。 ストアを 1 周する間に、各セクションから最大 1 つのアイテムを収集できます。 

1 つのテスト ケースでは、3 つの整数`p`、`m`、 そして`d`農産物、肉、乾物からそれぞれ必要なアイテムの数を教えてください。 要求されたすべてのアイテムを収集するために必要な完全なループの最小数を見つける必要があります。 元々の問題は`n`各テスト ケースには、これら 3 つの量が正確に含まれています。 

キー制約は実際には数値的な境界ではありません。`p`、`m`、 または`d`。 公開されたステートメントでは、これら 3 つの値の明示的な上限が示されていないため、実行時間が値の大きさに依存するアルゴリズムは不必要に危険です。 最適な解は、1 つのテスト ケース内の定数の数量のみに依存する必要があります。 セクションが 3 つしかないので、一定時間も可能です。 

最初のエッジケースは、あるセクションが他のセクションよりも多くの項目を必要とする場合です。 例えば、```
1
1 5 2
```答えは`5`。 肉には 5 つのアイテムが必要ですが、ループごとに肉アイテムは 1 つしか取得できないため、4 つのループでは十分ではありません。 アイテムの総数を 3 で割る不注意な解決策では、次のように計算されます。`8 / 3`、それはただ`2`整数除算では明らかに不十分です。 

2 番目のエッジ ケースは、3 つの量がすべて等しい場合です。```
1
4 4 4
```答えは`4`。 各ループはすべてのセクションから 1 つのアイテムを収集できるため、4 つのループでそれぞれ 4 つのアイテムが正確に収集されます。 シミュレーションでも同じ結果が得られますが、不必要な作業が実行されます。 

3 番目のエッジ ケースは、収集するものが 1 つのセクションのみにある場合です。```
1
0 0 7
```答えは`7`。 Dry Goods はループごとに 1 つのアイテムしか提供できないため、依然として 7 つのループが必要です。 要求されたアイテムの総数に基づくソリューションでは、同じセクションへの 1 回の訪問中に複数のアイテムを収集できると誤って想定される可能性があります。 

## アプローチ

 直接シミュレーションでは、3 つのセクションを繰り返し実行できます。 各ループ中に、農産物アイテムが残っている場合は 1 つ、肉アイテムが残っている場合は 1 つ、乾物アイテムが残っている場合は 1 つずつ消費されます。 3 つのカウンタがすべて 0 に達すると、プロセスは停止します。 これは正しいです。各ループは、各セクションから 1 つの項目を取得する 1 つの機会に正確に対応しているからです。 

もし`L = max(p, m, d)`、シミュレーションは正確に実行されます`L`ループします。 各ループは 3 つのセクションを検査するため、`3L`セクションの操作。 したがって、その実行時間は`O(max(p, m, d))`。 大量の場合、答えは最大の要件によってすぐに決まるにもかかわらず、不必要に高価になる可能性があります。 

重要な観察は、各ループが各セクションに正確に 1 単位の容量を与えるということです。 プロデュースが必要だとします`p`アイテム。 どのような戦略も、それより短い時間でプロデュースを完了することはできません。`p`ループごとに最大 1 つの Produce アイテムを収集できるためです。 同じ引数で下限が与えられます。`m`そして`d`ループします。 したがって、すべての有効なソリューションには少なくとも次のものが必要です。`max(p, m, d)`ループします。 

その下限も達成可能です。 正確に実行すれば`max(p, m, d)`ループでは、必要なアイテム数が最大でもその最大値であるため、すべてのセクションに十分な機会が与えられます。 より早く終了したセクションは、他のセクションが続行している間、単にアイテムの取得を停止します。 したがって、最小値は、まさに 3 つの量のうちの最大値となります。 

ブルート フォース シミュレーションは、個々のループをすべて正確にモデル化するため機能しますが、すべてのループが同一であるという事実を活用できません。 終了までの最も遅いセクションのみがループ数を決定するという観察により、問題全体が 1 つに集約されます。`max`手術。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは独立しているため、同じ定数時間の計算をすべてのケースに適用できます。 
2.読む`p`、`m`、 そして`d`、必要な数の農産物、肉、乾物アイテム。 
3. コンピューティング`max(p, m, d)`。 要件が最大のセクションではループごとに 1 つの項目しか提供できないため、これは下限です。 
4. その最大値を出力します。 必要なアイテムの最大数も十分です。これは、その回数のループの後、各セクションには少なくとも必要なアイテムの数と同じ数の収集機会があるためです。 

正確さは、下限と上限が一致することから決まります。 させて`L = max(p, m, d)`。 どのソリューションでも少なくとも必要なものは、`L`必要なセクションがループするため、`L`items はループごとに 1 つのアイテムのみを提供できます。 一方、その後`L`ループ、プロデュースにはありました`L`ミートにはチャンスがあった`L`ドライグッズにはチャンスがあった`L`チャンス。 それぞれの必要数量は最大でも`L`、要求されたアイテムをすべて収集できます。 したがって、ループの最小数は正確に次のようになります。`L`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())

    out = []
    for _ in range(t):
        p, m, d = map(int, input().split())
        out.append(str(max(p, m, d)))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("""3
2 6 1
3 2 1
1 5 7
""") == """6
3
7""", "provided sample"

# Minimum-size case
assert run("""1
0 0 0
""") == """0""", "minimum requirements"

# All values equal
assert run("""1
4 4 4
""") == """4""", "all sections finish together"

# One section dominates
assert run("""1
1 5 2
""") == """5""", "largest middle value"

assert run("""2
0 0 1000000000
999999999 1000000000 999999998
""") == """1000000000
1000000000""", "large values"
