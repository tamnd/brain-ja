 ## 解決策
 ## 問題の理解

 この問題では、整数間隔で通常の FizzBuzz シーケンスを生成するように求められます。 2 つの整数が与えられます。`a`そして`b`で始まるすべての整数を処理する必要があります。`a`そしてその前に止まる`b`。 各整数について、通常は整数自体を出力します。 3の倍数は、`Fizz`、5の倍数は次のようになります。`Buzz`、両方の倍数は次のようになります`FizzBuzz`。 各結果はそれぞれの行に出力されます。 公式問題では、包括的な下限と排他的な上限が使用されます。 

間隔には正確に次のものが含まれます`b - a`整数の場合`a < b`。 出力自体には間隔内の整数ごとに 1 行が含まれるため、データ構造、前処理、または高度な数学的手法は必要ありません。 間隔に次のものが含まれる場合、`k`正しいプログラムが生成する必要がある値`k`したがって、値ごとに一定の作業を費やすアルゴリズムは、すでに漸近的に最適化されています。 指定された時間制限は 1 秒、メモリ制限は 256 MB であるため、実装では不要なストレージを回避し、出力を効率的に構築する必要があります。 

最初のエッジ ケースは、3 と 5 の両方で割り切れる値です。入力の場合```
15
16
```正しい出力は```
FizzBuzz
```をチェックする不注意な実装`n % 3 == 0`5 で割り切れるかどうかを確認する前に、印刷のみが行われる可能性があります`Fizz`。 結合された大文字と小文字を最初に処理するか、印刷する前に両方の文字列を蓄積する必要があります。 

2 番目のエッジ ケースは排他的な上限です。 入力用```
11
18
```処理される値は 11 ～ 17 であるため、出力は次のようになります。`17`。 番号`18`印刷してはなりません。 次のように書かれたループ`range(a, b + 1)`サイレントに off-by-one エラーが発生します。 Python の正しい範囲は次のとおりです。`range(a, b)`。 この動作は、公式の 2 番目のサンプルでも見られます。 

3 番目のエッジ ケースは、どちらの数でも割り切れない値です。 入力用```
1
3
```出力は```
1
2
```どちらの割り算条件も当てはまらない場合、プログラムは元の整数を出力する必要があります。 すべての値を無条件に文字列に置き換えたり、倍数が見つからない限り何も出力しないと、間違った結果が生成されます。 

## アプローチ

 直接的なアプローチは、以下のすべての整数を訪問することです。`a`を通して`b - 1`そして何を印刷するかを決定します。 各値について、3 と 5 で割り切れるかどうかを判断するには、2 つのモジュロ演算で十分です。両方の条件が当てはまる場合、次のように出力します。`FizzBuzz`; それ以外の場合は、適用される個々の置換を出力し、どちらにも当てはまらない場合は、番号自体を出力します。 これは正しいです。置換ルールは現在の整数のみに依存するため、すべての出力行を独立して決定できます。 

ここでは、総当たり実装と最適実装は事実上同じです。 最適化するための隠れた検索スペースはありません。 間隔に次のものが含まれる場合、`k = b - a`整数の場合、出力自体は`k`線。 値を検査せずにすべての置換を何らかの方法で決定する想像上のアルゴリズムであっても、これらの行を記述するのに Ω(k) 時間を費やす必要があります。 直接シミュレーションでは O(k) 時間を使用しますが、これは避けられない下限と一致します。 

重要な観察は、これはシミュレーションがすでに最適化されているケースの 1 つであるということです。 可分性テストは定数時間であり、問​​題では結果を要約するのではなく、すべての位置を出力することが求められます。 Fizz 値または Buzz 値の数の式を導出しようとしても、それらの正確な順序を出力する必要があるため、役に立ちません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(b - a) | O(1)、出力ストレージを除く | 承認済み |
 | 最適 | O(b - a) | 出力がバッファリングされている場合は O(b - a) | 承認済み |

 2 つの行の区別はアルゴリズムではなく概念的なものです。 単純なシミュレーションはすでに最適な漸近解です。 

## アルゴリズムのチュートリアル

 1.読む`a`そして`b`。 処理する必要がある間隔は`[a, b)`、 それで`a`含まれており、`b`は除外されます。 
2. すべての整数を反復処理します。`x`で`range(a, b)`。 各反復は、必要な 1 つの出力行に正確に対応します。 
3. かどうかを確認します。`x`は 3 と 5 の両方で割り切れます。そうであれば、次のように計算します。`FizzBuzz`。 15 の倍数は両方の割り切りテストを満たすため、この条件は個々のケースの前に考慮する必要があります。 
4. それ以外の場合は、`x`は 3 で割り切れます。`Fizz`そうなったとき。 
5. それ以外の場合は、`x`は 5 で割り切れます。`Buzz`そうなったとき。 
6. どの割り算条件も当てはまらない場合は、次の 10 進表現を生成します。`x`。 
7. 生成されたすべての行を元の順序で印刷します。 行をバッファリングすることで繰り返しの呼び出しを回避します`print`必要な出力にのみ比例してメモリを使用しながら。 

不変式は単純です。最初の処理後、`i`間隔の値を指定すると、出力にはそれらの正確な FizzBu​​zz 表現が含まれます。`i`値を同じ順序で並べます。 次の値については、相互排他的な決定シーケンスでは、最初に両方の分割可能なケースが考慮され、次に個々のケースが考慮されるため、その表現は正しいです。 その表現を追加すると、すべての値が保存されるまで不変式が保持されます。`[a, b)`処理されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())

    ans = []

    for x in range(a, b):
        if x % 15 == 0:
            ans.append("FizzBuzz")
        elif x % 3 == 0:
            ans.append("Fizz")
        elif x % 5 == 0:
            ans.append("Buzz")
        else:
            ans.append(str(x))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```このステートメントでは 2 つの行で区切られた整数が指定されているため、2 つの入力行は別々に読み取られます。 

ループは使用します`range(a, b)`、これは必要な包含-排他間隔を正確にモデル化します。 使用する`range(a, b + 1)`間違って処理されてしまう`b`。 

15 が最小公倍数であるため、最初に 15 で割り切れるかどうかをテストすることは、3 と 5 の両方で割り切れるかどうかをテストすることと同じです。 また、`FizzBuzz`明示的な。 そのケースが失敗すると、`elif`チェーンは、次のうちの 1 つだけを保証します。`Fizz`、`Buzz`, or the original number is selected.

 答えはリストに蓄積され、一度書き込まれます。 これにより、数値ごとに個別の出力操作を行うオーバーヘッドが回避されます。 このリストはアルゴリズムのアイデアには必要ありませんが、大規模な出力を行う場合の実際的な Python 実装の選択肢です。 

Python の整数はオーバーフローしないため、特別な整数幅の処理は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(b - a) | 内のすべての整数`[a, b)`整数ごとに一定の作業が行われ、必要な出力を生成するコストが加えられ、一度処理されます。 |
 | スペース | O(b - a) | 実装では、すべての出力行が次の場所に保存されます。`ans`それらを書く前に。 |

import io

def solve():
    input = sys.stdin.readline

    a = int(input())
    b = int(input())

        if x % 15 == 0:
            ans.append("FizzBuzz")
        elif x % 3 == 0:
            ans.append("Fizz")
        elif x % 5 == 0:
            ans.append("Buzz")
        else:

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:

        sys.stdout = old_stdout
