 ## 解決策
 ## 問題の理解

 Arseny には 100 ルーブル紙幣が無制限に供給されており、以下から始まります。`m`1ルーブル硬貨。 当日`i`、彼は少なくとも支払わなければなりません`c_i`ルーブル。 レジ係は支払いが多すぎると必ずおつりを渡します。その日の不満は、返された個々の紙幣と硬貨の数に次の値を掛けたものになります。`w_i`。 目標は、合計の不満が最小限になるように、毎日支払う紙幣と硬貨の枚数を選択することです。 おつりとして受け取ったコインは後日もご利用いただけます。 

100で割り切れる部分は決して面白くありません。 もし`c_i = 100q + r`、 どこ`0 <= r < 100`、いつでもお支払いいただけます`q`メモを作成し、残りの部分については個別に処理します`r`ルーブル。 いつ`r > 0`、その残りを処理する便利な方法が正確に 2 つあります。 支払い可能です`r`小銭を出さない場合は、追加で 100 ルーブル紙幣を 1 枚支払って受け取ることもできます。`100-r`お釣りとしてのコイン。 後者の費用は`(100-r) * w_i`不満。 

制約により許可されるのは、`n`到達する`100000`、それぞれの価格と重量は最大です`100000`。 二次アルゴリズムはすでに次のように実行されます。`10^10`最悪の場合、1 秒の制限をはるかに超えて操作が行われる可能性があります。 必要なのは`O(n log n)`またはより良い解決策。 関連するすべてのコインの量が 100 未満であるという事実が、重要な構造の簡素化です。 

最初のエッジ ケースは 100 の正確な倍数です。たとえば、次のようになります。```
1 01007
```答えがあります`0`、支払いあり`1 0`。 不注意な実装では、毎日を正確な支払いと 1 枚の追加紙幣の支払いのどちらかを選択できるものとして扱う可能性がありますが、ここで追加の紙幣を支払うと 1 枚の紙幣で構成される 100 ルーブルの小銭が作成され、厳密には正確な支払いよりも悪い金額になります。 

2 番目のエッジケースは、ちょうど十分なコインを持っていることです。 例えば、```
1 501503
```答えがあります`0`、支払いあり`1 50`。 テスト`m > r`の代わりに`m >= r`誤ってレジ担当者におつりを受け取らせることになります。 

3 番目のエッジケースは、当日のコインが不足しているが、以前の日に遡って変更できる場合です。 考慮する```
3 0150 50 1501 1 100
```初日は50コインを受け取る必要があります。 2 日目には、その 50 コインを正確に使うことができます。 3日目、また足りなくなりました。 2日目は100ルーブル紙幣に両替して50枚のコインを受け取った方が良かった。`50`、一方、3 日目に 50 コインを受け取るにはコストがかかります`5000`。 現在の日のみを考慮する貪欲なアルゴリズムでは、この交換を見逃してしまいます。 

## アプローチ

 直接的な総当たりアプローチは、ゼロ以外の剰余で毎日可能な両方のアクションを検討することです。 1 つのアクションで残りをコインで支払い、もう 1 つのアクションで追加の紙幣を 1 枚支払っておつりを受け取ります。 選択の完全なシーケンスごとに、コインの残高をシミュレートし、不満を計算できます。 これら 2 つのアクションは 100 未満の部分を処理する便利な方法をすべてカバーしているため、これは正しいですが、最大で`2^n`さまざまな選択肢。 と`n = 100000`、つまり`2^100000`可能性があるため、列挙することは完全に不可能です。 

有益な観察は、残りをコインで支払うと、後で取り消すことができる機会が生まれるということです。 仮にその日`i`残りがあります`r`。 現在支払っている場合`r`コインを支払った場合は、後でその決定を変更して、代わりに追加の 100 ルーブル紙幣を 1 枚支払うことができます。 最初の決定と比較して、コイン残高はちょうど 100 増加しますが、さらなる不満は次のとおりです。`(100-r) * w_i`。 

その最後の数量は、**その日から追加のコインを 100 枚購入するコストと見なすことができます。`i`**。 コインを使用して残りを支払うたびに、この潜在的な将来の購入を優先キューに保存します。 

さて、後の日が残っていると仮定します`r`しかし、以下よりも少ない`r`コインが利用可能です。 意味のある選択肢が 2 つあります。 今日追加の紙幣を支払って苦しむこともできる`(100-r) * w_i`または、以前の正確な支払いを 1 つ取り消すことができます。 以前の支払いを取り消すと、ちょうど 100 コインが追加されます。これは、現在の残りを支払うのに十分です。`r < 100`。 

元に戻す必要がある以前の支払いは 1 つだけであるため、最も良い早期の支払いは、交換コストが最小のものです。 最小ヒープにより、その候補が得られます。`O(log n)`時間。 そのコストが今日の変更を受け取るコストよりも小さい場合は、変更を取り消します。 それ以外の場合は、今日から変更を受け入れます。 

これが中心的な貪欲交換です。 不足が生じた場合は、必要な 100 コインを今すぐ購入するか、以前に購入した最も安いコインを交換して購入します。 早期の支払いをより高価な支払いに置き換える理由はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |`O(2^n * n)`|`O(n)`| 遅すぎる |
 | 貪欲 + 最小ヒープ |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 価格ごとに次のように分割します。`c_i = 100q_i + r_i`。 当初は支払う予定`q_i`メモ。 のみ`r_i`コインの管理に影響します。 
2. もし`r_i = 0`、正確に支払います`q_i`メモ。 価格はすでに 100 の倍数であるため、コインを関与させる有効な理由はありません。 
3. 少なくとも`r_i`コイン、支払い`q_i`メモと`r_i`コイン。 コイン残高が減ります`r_i`、そしてこの日が将来の後継者の候補を作成します。 この正確な支払いを追加の紙幣 1 枚に置き換えるコストは次のとおりです。`(100-r_i) * w_i`なので、そのコストを日のインデックスと一緒に最小ヒープに挿入します。 
4. 数が少ない場合`r_i`コインの場合、現在の正確な支払いは不可能です。 現在の代替手段は支払うことです`q_i + 1`メモと受け取り`100-r_i`コイン。 その不満は、`(100-r_i) * w_i`。 
5. そのコストを受け入れる前に、ヒープ内で最も安価な候補を検査します。 以前の正確な支払いを追加の紙幣 1 枚に置き換えると、ちょうど 100 枚の追加のコインが得られます。 以来`r_i < 100`、これらの 100 コインは現在の残りを正確に支払うのに十分です。 
6. 前回の最も安い交換品のコストが当日の変更額よりも低かった場合、その候補をヒープから削除し、その日を支払い済みとしてマークし、追加のメモを 1 つ追加して、そのコストを答えに追加し、現在のコイン残高に 100 を追加してから支払います。`r_i`当日のコイン。 
7. それ以外の場合は、以前の決定をすべて変更しないでください。 今日追加の紙幣を 1 枚お支払いいただき、お受け取りください`100-r_i`コイン、追加`(100-r_i) * w_i`答えに答えて、今日の支払いに追加メモを使用するとしてマークを付けます。 
8. 1 日がコインで正確に支払われるたびに、その交換コストをヒープに挿入します。 その日が後で置き換えられる場合は、その候補をヒープから削除します。 したがって、ヒープには、まだ交換可能な以前の正確な支払いが正確に含まれています。 

重要な不変条件は、すべてのヒープ エントリが、支払いを変更できる前日を表すということです。`r`コインを追加の 100 ルーブル紙幣 1 枚に換算すると、蓄積された不満コストでさらに 100 枚のコインが生成されます。 現在の日に十分なコインが不足している場合は、その日を置き換えることで現在の支払いが可能になります。 すべての交換品で同じ 100 コインが追加され、コストのみが異なるため、入手可能な最も安価な交換品を選択するのが最適です。 以前の最安の交換が今日の変更を受け入れるよりも安くない場合、当日の変更は少なくとも前日の変更と同じくらい効果があります。 

## Python ソリューション```python
Pythonimport sysimport heapq
input = sys.stdin.readline

def solve():    n, m = map(int, input().split())    c = list(map(int, input().split()))    w = list(map(int, input().split()))
    notes = [x // 100 for x in c]    rem = [x % 100 for x in c]
    extra = [False] * n    heap = []    answer = 0
    for i in range(n):        r = rem[i]
        if r == 0:            continue
        current_cost = (100 - r) * w[i]
        if m >= r:            m -= r            heapq.heappush(heap, (current_cost, i))            continue
        if not heap or heap[0][0] >= current_cost:            m += 100 - r            answer += current_cost            extra[i] = True            continue
        old_cost, old_i = heapq.heappop(heap)
        extra[old_i] = True        answer += old_cost
        m += 100        m -= r
        heapq.heappush(heap, (current_cost, i))
    out = [str(answer)]
    for i in range(n):        if extra[i]:            out.append(f"{notes[i] + 1} 0")        else:            out.append(f"{notes[i]} {rem[i]}")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":    solve()

ヒープストア`(replacement_cost, day_index)`。 パイソンの`heapq`は最小ヒープなので、`heap[0]`自動的に、置き換え可能な前回の支払いの中で最も安価な支払いになります。 

前日に代わると現在のコイン残高が反映されます`100`元の正確な支払い履歴に対する追加のコイン。 コードはすぐに現在の剰余を減算します。`r`。 以来`r < 100`、結果として得られる残高は負ではありません。 

比較には、`>=`より早い日に交換するかどうかを決定するとき。 2 つのコストが等しい場合、以前の決定を維持し、今日変更を行うことがすでに最適であるため、どちらの選択も有効です。 

Python の整数には任意の精度があり、不満の合計がおおよそのレベルに達する可能性があるため便利です。`100 * 10^5 * 10^5`、符号付き 32 ビット整数の範囲をはるかに超えています。

 ## 特殊なケース

 正確に 100 の倍数の場合、```
1 01007
```残りはゼロです。 このアルゴリズムはヒープを完全にスキップし、1 つのノートを支払います。 出力は`0`に続く`1 0`。 これにより、残金ゼロをあたかも追加の紙幣を支払えば何とかなるかのように扱うというよくある間違いを回避できます。 

ちょうど十分なコインがあれば、```
1 501503
```初期残高は 50 で、残りも 50 です。条件`m >= r`成功したため、アルゴリズムは 1 枚の紙幣と 50 枚のコインを支払います。 変化は生じず、答えはゼロになります。 この条件では平等であることが重要です。 

ワンコインでは少なすぎるので、```
1 491501
```正確な支払いは不可能です。 以前のヒープエントリがないため、2 枚の紙幣を支払って 50 コインを受け取る唯一の選択肢があります。 不満は、`50 * 1 = 50`、出力コストを与える`50`、支払いあり`2 0`。 

さらに興味深い交換ケースについては、```
3 0150 50 1501 1 100
```1日目にはコインがないため、2枚の紙幣を支払い、コスト50で50コインを受け取ります。2日目はそれらの50コインを正確に使いますが、その交換コストも50です。3日目には再びコインがなく、小銭を取るにはコストがかかります`50 * 100 = 5000`。 ヒープには置換コスト 50 の 2 日目が含まれているため、アルゴリズムは代わりに 2 日目を置換します。 これにより、前の状態に比べて 100 コインが追加され、3 日目は残りの 50 コインを正確に支払うことができます。 最終的なコストは 5050 ではなく 100 であり、初期の決定を後の貪欲な交換に利用できるようにしておかなければならない理由を示しています。 

これらすべてのケースの背後にある不変条件は同じです。ヒープに記録された正確な支払いは、追加の 100 ルーブル紙幣 1 枚に変換され、既知のコストで正確に 100 枚の追加コインが生成されます。 すべての残りは厳密に 100 未満であるため、このような変換を 1 回行うだけで、1 枚のコイン不足を補うことができます。 ヒープは常に最も安価な変換を選択します。これはまさに、全体的な不満を最小限に抑えるために必要な交換です。
