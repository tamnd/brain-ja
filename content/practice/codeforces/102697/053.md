 ## 解決策
 ## 問題の理解

 どのプレイヤーをコントロールするかが与えられます。`X`または`O`、その後に現在の 3 by 3 Tic-Tac-Toe ボードが続きます。 空のセルはスペースで表されます。 マークを配置するとすぐに行、列、または対角に 3 つの等しいマークが作成される空のセルが少なくとも 1 つあるかどうかを判断する必要があります。 

たとえば、プレーヤーの場合`X`そしてボード```
X OX  O X
```置く`X`中央右のセルでは、```
X OX XO X
```主対角線を完成させるのはどれですか? いいえ、主対角線はすでにあります`X X X`中心を考慮した後でのみ、この手が勝ちます。 

ボードのサイズは 3 × 3 のみに固定されています。大きなサイズはありません。`n`入力に隠されているため、ここでは漸近的な複雑さは勝利条件を正しくすることほど重要ではありません。 すべての空のセルを調べて 8 つの勝ち筋をチェックするというアプローチでも、ほんのわずかです。最大で 9 つの候補手と各手について検査する 8 つのラインがあり、最大 72 のライン チェックが行われます。 二次または三次アプローチは、この入力サイズに対して完全に安全です。 

難しいのはパフォーマンスではなく、ボードを正しく解釈することです。 

1 つのエッジ ケースは、すでに完了した行です。 のために```
XXXXOO
```正しい出力は`Yes you can.`なぜなら`X`任意の空のセルにマークを配置できますが、さらに重要なのは、既存のマークが 2 つだけあるセルのみをチェックする不注意な実装では、プレーヤーがすでに勝ったことを認識できない可能性があることです。 通常、タスクの意図された解釈は、勝ち手が存在するかどうかであるため、最も安全な実装は、候補手を直接テストすることです。 

もう 1 つのエッジケースは、対角勝利です。 のために```
OXOX O X
```置く`O`右下隅の主対角線が完成するため、出力は次のようになります。`Yes you can.`。 行と列のみをチェックする実装では、このケースが無視されます。 

3 番目のエッジケースは、対角での勝ち手です。 のために```
XX O O   X
```置く`X`右上のセルでは、反対角線が与えられます。`X X X`、したがって、答えは次のとおりです`Yes you can.`。 両方の対角線を処理する必要があります。 

Codeforces によって表示されるサンプルには、末尾に`|`各ボード列の後に。 これはステートメントで示されるボード表現の一部であるため、以下の実装では次の部分が削除されます。`|`行を読み取るときに、スペースを空のセルとして保持します。 

## アプローチ

 最も直接的な総当たりの解決策は、すべての空の正方形を試すことです。 各候補の正方形について、一時的にそこにマークを置き、3 行すべて、3 列すべて、および両方の対角線をチェックします。 これら 8 つのラインのいずれかが完全にこちらのマークで構成されている場合、その手が勝ちます。 

これでもすでに十分速いです。 可能な手は最大 9 つあり、勝ちラインはちょうど 8 つあるため、最悪のケースでは最大 72 のライン チェックが実行されます。 各ラインには 3 つのセルのみが含まれており、最大 216 個の個別のセル検査が可能です。 ボードは永続的に 3 × 3 であるため、これは事実上一定時間です。 

移動が行、列、および選択したセルを通過する 1 つまたは 2 つの対角線にのみ影響することを確認することで、実装をさらに簡素化できます。 各手ごとに 8 つのラインすべてをチェックする代わりに、勝ちラインに現在ちょうど 2 つのマークと 1 つの空のセルが含まれているかどうかを直接尋ねることができます。 その空のセルが勝ち手になります。 

三目並べで勝ち取れるラインは 8 つだけです。 それぞれを検査し、マークと空のセルを数え、行にちょうど 2 つのマークと 1 つの空のセルが含まれているかどうかを受け入れます。 これにより、ボードの変更が回避され、条件が特に明確になります。 

入力が固定の 3 x 3 ボードであるため、ブルート フォース ソリューションはすでに受け入れられています。 2 番目のアプローチは、勝ち手の数学的条件を直接表現し、操作する状態が少ないため、推奨されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(1)、最大 216 セル検査 | お(1) | 承認済み |
 | すべての勝ちラ​​インを確認する | O(1)、長さ 3 の 8 行 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレーヤーのマークとボードの 3 列を読み取ります。 可能性のある末尾を削除する`|`ただし、スペースは空のセルを表すため、スペースは削除しないでください。 
2. 8 つの勝ちラインを列挙します。3 行、3 列、主対角線、対対角線です。 三目並べの勝利の可能性はすべて、まさにこれらのラインの 1 つに属します。 
3. 各行について、マークが含まれるセルの数と空のセルの数を数えます。 
4. 行にマークが 2 つと空のセルが 1 つだけ含まれている場合、その空のセルは正当な勝ち手です。 印刷する`Yes you can.`すぐに。 
5. 8 行すべてをチェックしてもそのような行が見つからない場合は、次のように出力します。`No you can't.`。 

The key invariant is that after processing any prefix of the eight winning lines, every possible one-move win belonging to those processed lines has already been detected. 三目並べの勝ちはすべて 8 つのラインの 1 つであるため、何も見つからなかった場合にスキャンを完了すると、勝ち手が存在しないことが証明されます。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    player = input().strip()
    board = []    for _ in range(3):        row = input().rstrip("\n")        if row.endswith("|"):            row = row[:-1]        board.append(row)
    lines = []
    for r in range(3):        lines.append([(r, 0), (r, 1), (r, 2)])
    for c in range(3):        lines.append([(0, c), (1, c), (2, c)])
    lines.append([(0, 0), (1, 1), (2, 2)])    lines.append([(0, 2), (1, 1), (2, 0)])
    for line in lines:        mine = 0        empty = 0
        for r, c in line:            if board[r][c] == player:                mine += 1            elif board[r][c] == " ":                empty += 1
        if mine == 2 and empty == 1:            print("Yes you can.")            return
    print("No you can't.")

if __name__ == "__main__":    solve()
```最初の入力行は、どのシンボルが現在のプレーヤーに属するかを識別します。 単一の文字として保持するため、後の比較はすべて単純に行われます。`board[r][c] == player`。 

各ボード行は次のように読み取られます。`rstrip("\n")`それよりも`strip()`。 この区別は重要です。`strip()`先頭と末尾のスペースが削除され、空のセルに関する情報が破壊されます。 入力表現に末尾の`|`公式サンプルでは表示されていますが、別途削除されています。 

8 つの勝ちラインは、3 つの座標ペアで表されます。 最初の 6 つは 3 つの水平線と 3 つの垂直線を表し、最後の 2 つは対角線を表します。 

行ごとに、`mine`現在のプレーヤーのマークをカウントし、`empty`スペースを数えます。 勝利の一手は、これらのカウントが揃ったときにこそ存在します。`2`そして`1`。 3 番目のセルは必ず空であり、プレイヤーのマークを入力して 3 つ連続で作成できます。 

ボードを変更したり、移動を元に戻したり、候補セルを検索したりする必要はありません。 これにより、次の候補がテストされる間に一時的な手がボード上に残されるという、総当たりバージョンで最も一般的な実装ミスが回避されます。 

ここでは Python 整数がオーバーフローすることはできず、すべてのインデックスは明示的に次のように制限されます。`0`、`1`、 そして`2`。

 ## 特殊なケース

 プレイヤーのマークが 2 つあり、空のセルが 1 つある行は、最も単純な勝ちのケースです。 のために```
XXX OO
```最初の行には 2 つが含まれます`X`マークとスペース 1 つ。 アルゴリズムの記録`mine = 2`そして`empty = 1`、すぐに戻ります`Yes you can.`。 これにより、誤って特定の列に空のセルが必要になる実装が捕捉されます。 

対角線の場合については、次のように考えます。```
OOXX O
```主対角線は`O O space`。 アルゴリズムがそのラインに到達すると、そのカウントは次のようになります。`mine = 2`そして`empty = 1`, そのため、右下のセルが勝ち手として識別されます。 水平線と垂直線のみをチェックするソリューションでは、誤った結果が返されます。`No you can't.`。 

反対側の対角線は独立して処理する必要があります。 と```
X O  XO  X
```対角線には次のものが含まれます`X X space`右上から左下へ。 アルゴリズムには座標が明示的に含まれています`(0, 2)`、`(1, 1)`、 そして`(2, 0)`したがって、コード内の他の場所に隠された特別なケースに依存せずに、勝ち手を見つけます。 

最後に、サンプルの末尾`|`文字の入力には注意が必要です。 のために```
XXOX|XO |O X|
```パーサーは最後の部分のみを削除します`|`、各行内のスペースはそのままにします。 結果のボードはちょうど 3 セル幅で、3 番目の列には次の内容が含まれます。`X`、スペース、および`X`、必要な勝利の手を与えます。 出力は`Yes you can.`。
