 ## 解決策
 ## 問題の理解

 文字列は小文字とスペースで構成されます。 その面白さは、現在登場するキャラクターの多さです。`f`、`u`、 または`n`。 同じ巡回シーザー シフトをすべての文字に何度でも適用できます。 シフトにより、すべての文字がアルファベットの 1 位置ずつ前に移動します。`z`に巻き付ける`a`。 空間は決して変わりません。 

タスクは、可能な限り多くの従業員を生み出すシフトを選択することです。`f`、`u`、 そして`n`文字を入力し、その最大数を出力します。 公式問題では、1 秒の制限と 256 MB のメモリが使用されます。 

アルファベットには 26 文字しか含まれておらず、これが重要な構造上の制約です。 長い入力文字列がある可能性があるため、考えられるすべてのシフトに対して新しいシフト文字列を構築すると、同じデータを繰り返しスキャンすることになります。 すべてのキャラクターに 1 回だけ触れる解決策が望ましいです。 アルファベットが固定されているということは、入力が 26 文字の頻度で要約された後は、あらゆる可能なシフトを試しても一定量の作業しかかからないことも意味します。 

実装を騙す可能性のある小さなケースがいくつかあります。 まず、ラップアラウンド`z`重要です。 入力用`z`、1シフトで得られる`a`、一方、6 シフトでは`f`、したがって、正しい答えは次のとおりです。`1`。 モジュロ 26 をとらずに単純にシフトを追加する実装では、これを認識できません。 

次に、スペースはスコアに影響を与えてはならず、文字として扱ってはなりません。 例えば、`a a`には 2 つの文字と 1 つのスペースが含まれます。 正しく実装すると、両方の文字を一緒にシフトして、最大限の面白さを得ることができます。`2`。 スペースを別のアルファベット文字として扱うと、周波数の計算が破損します。 

第三に、ターゲットとなる 3 つの文字はアルファベット内で隣接していません。 例えば、`fun`それ自体がすでに面白さを持っています`3`したがって、ゼロシフトは最適です。 ターゲット文字が 1 つの連続した間隔を形成していると想定する実装では、間違った条件が使用されます。 

4 番目に、同じシフトが文字列全体に適用されます。 のために`fu`、両方の文字をシフト 0 で同時にターゲット文字にすることができ、次のようになります。`2`。 キャラクタごとに異なるシフトを選択することは無効です。 これを行うと、ほぼすべての文字が誤って独立してカウントされてしまいます。 

## アプローチ

 最も直接的なアプローチは、可能なすべての循環シフトを試すことです。 シフトを 26 回適用するとすべての文字が元の値に戻るため、個別のシフトは 26 個のみです。 シフトごとに、文字列全体をスキャンし、各文字をシフトされた値に変換し、結果が次の場合はそれをカウントします。`f`、`u`、 または`n`。 これは正しいです。なぜなら、考えられるすべての最終文字列は、これら 26 のシフトの 1 つで表されるからです。 

一定の長さの文字列の場合`n`、ブルートフォース実装は正確に実行されます`26n`文字の訪問は、シフトされた各文字を計算するために必要な、より小さな一定の作業を無視します。 たとえば、100 万文字の文字列では、約 2,600 万文字のチェックが行われます。 漸近的な複雑さはまだ続いています`O(n)`26 は固定定数であるため、このアプローチは成功する可能性がありますが、同じ高価なスキャンを 26 回実行します。 

有益な観察は、文字の位置はまったく重要ではないということです。 各文字の出現数のみが重要です。 元の文字列に次のものが含まれているとします。`cnt[c]`手紙のコピー`c`。 選択したシフトについて`k`、それらのコピーはすべて同じシフトされた文字になります`(c + k) mod 26`。 したがって、26 の周波数カウントからそのシフトのスコアを直接計算できます。 

文字列を 1 回スキャンすると、すべてのシフトを評価するために必要な情報がすべて得られます。 26 のシフトごとに、元の 3 つの文字を検査するだけで済みます。`f`、`u`、 そして`n`。 これは、入力の長さに関係なく、最大 78 回の周波数ルックアップになります。 

文字列が長い場合、その違いは顕著になります。 ブルート フォース バージョンは元のテキストを繰り返し処理しますが、最適化バージョンはテキスト全体を 26 個のカウンタに圧縮し、それらのカウンタ全体で動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26n) = O(n) | お(1) | 漸近的に受け入れられますが、スキャンが不必要に繰り返されます。 
| 最適 | O(n + 26 × 3) = O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スペースは文字列の一部ですが、変更しない必要があるため、スペースを含む入力行全体を読み取ります。 
2. 配列を作成する`cnt`長さ 26。入力内のすべての小文字について、そのアルファベット インデックスに対応するカウンタをインクリメントします。 スペースは決して無視されません。`f`、`u`、 または`n`。 
3. すべてのシフトを試す`k`から`0`を通して`25`。 26 のシフトは 0 のシフトと同じであるため、これらはすべて可能な個別の最終構成です。 
4. 現在のシフトについて`k`、どの文字が元の文字になるかを決定します`f`、`u`、 そして`n`。 対象文字にインデックスがある場合`t`、元の文字にはインデックスが必要です`(t - k) mod 26`。 したがって、このシフトのスコアは次の合計になります。`cnt[(5 - k) mod 26]`、`cnt[(20 - k) mod 26]`、 そして`cnt[(13 - k) mod 26]`、 どこ`f`、`u`、 そして`n`インデックスは 5、20、13 です。 
5. 26 シフトすべてで発生した最大スコアを保持し、印刷します。 考えられるすべての循環シフトが検査されているため、記録された最大値がまさに達成可能な最大の楽しさになります。 

### なぜ効果があるのか

 不変条件とは、`cnt[c]`インデックス付きの文字が元の文字の数を常に正確に表します`c`。 固定シフトの場合`k`、オリジナルの手紙`c`になる`(c + k) mod 26`。 この値が 5、20、または 13 の場合にこそ、面白さに貢献します。その関係を逆転すると、3 つの元のインデックスが得られます。`(5-k) mod 26`、`(20-k) mod 26`、 そして`(13-k) mod 26`。 したがって、シフトごとに計算されたスコアは、次の文字になる文字を正確にカウントします。`f`、`u`、 または`n`。 26 の可能なシフトすべてがテストされるため、それらの最大値を採用すると、より良い結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    cnt = [0] * 26

    for ch in s:
        if ch != ' ':
            cnt[ord(ch) - ord('a')] += 1

    targets = (ord('f') - ord('a'),
               ord('u') - ord('a'),
               ord('n') - ord('a'))

    ans = 0

    for shift in range(26):
        score = 0
        for target in targets:
            original = (target - shift) % 26
            score += cnt[original]
        ans = max(ans, score)

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループでは頻度テーブルを作成します。`ord(ch) - ord('a')`改宗する`a`を通して`z`インデックスに`0`を通して`25`。 入力行にはスペースを含めることができ、スペースは巡回アルファベットの一部ではないため、スペースの条件が必要です。 

の`targets`タプルには、楽しさを定義する 3 つの文字が格納されます。 考えられるすべてのシフトに対して、コードは各ターゲットから逆方向に動作して、そのターゲットとなる元の文字を見つけます。 モジュロ演算はラップアラウンドを正しく処理します。 たとえば、ターゲットが次のような場合`f`シフトは 7 で、必要な元のインデックスは次のとおりです。`(5 - 7) % 26 = 24`、つまり`y`。 まさに、シフトしてる`y`7 つの位置が与える`f`。 

シフトされた文字列を作成する必要はありません。 頻度配列には、各文字のコピーがいくつ存在するかに関するすべての情報がすでに含まれています。 ここでも、Python の整数には固定幅のオーバーフローの問題はなく、答えは最大でも入力の文字数です。 

使用する`rstrip('\n')`の代わりに`strip()`意図的です。`strip()`文字列ではスペースは有効な文字ですが、入力から先頭と末尾のスペースが削除されます。 改行のみを削除すると、実際の入力テキストが保持されます。

## テストケース```python
import sys
import io

def solve():
    s = sys.stdin.readline().rstrip('\n')

    cnt = [0] * 26

    for ch in s:
        if ch != ' ':
            cnt[ord(ch) - ord('a')] += 1

    targets = (5, 20, 13)
    ans = 0

    for shift in range(26):
        score = 0
        for target in targets:
            score += cnt[(target - shift) % 26]
        ans = max(ans, score)

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("hello world\n") == "5\n", "sample 1"
assert run("coderams contest number eight\n") == "9\n", "sample 2"

# Minimum-size input
assert run("a\n") == "1\n", "single letter"

# All characters equal
assert run("aaaa\n") == "4\n", "all equal"

# Wraparound at z: shifting z by 6 gives f
assert run("zzz\n") == "3\n", "z wraparound"

# Spaces must not affect the count
assert run("a a a\n") == "3\n", "spaces"

# Large input
assert run("a" * 100000 + "\n") == "100000\n", "large input"

 ## 特殊なケース

 ラップアラウンドの場合については、次のことを考慮してください。`zzz`。 毎に 6 マップずつシフト`z`に`f`、したがって、答えは次のとおりです`3`。 度数表には次の内容が含まれます。`cnt[25] = 3`。 アルゴリズムがシフト 6 とターゲットを検査するとき`f`、それは計算します`(5 - 6) % 26 = 25`、の 3 つのコピーすべてを取得します。`z`、スコア 3 が得られます。モジュロ演算により、アルファベットが線形ではなく円形になります。 

スペースについては、次の点を考慮してください。`a a a`。 入力には 3 つの文字と 2 つのスペースが含まれます。 ごとにシフト`a`by 5 は 3 文字すべてを次のように変換します`f`、したがって、答えは次のとおりです`3`。 頻度テーブルには、`cnt[0] = 3`スペースについては何もありません。 シフト 5 を調べると、元の文字は次のようになります。`f`は`(5 - 5) % 26 = 0`, したがって、3 つの出現すべてがカウントされます。 

すでに最適な入力については、次のことを考慮してください。`fun`。 シフト 0 では、3 文字すべてがすでにターゲット文字に含まれているため、答えは次のようになります。`3`。 頻度表には、次のものが 1 つずつ含まれています。`f`、`u`、 そして`n`、ゼロシフト計算はこれら 3 つのカウンターを正確に読み取ります。 別のシフトにより他の場所に移動することもできますが、最大値は 3 のままです。 

単一の文字の場合、次のような`a`、ターゲット文字の 1 つにマッピングするシフトが常に存在します。 シフトする`a`5ギブまでに`f`、したがって、アルゴリズムは戻ります`1`。 これは、答えが文字列の元の面白さではなく、1 つの共通のシフトの下で楽しくなる文字数に基づいていることも裏付けています。 

重要な境界条件は、26 シフトのみを考慮する必要があるということです。 シフト 0 は文字列を変更しないままにしますが、シフト 25 はすべての文字を 1 つ後方にシフトすることと同じです。 仮定のシフト 26 は元の文字列に戻るため、テストしても新しい可能性は追加されません。
