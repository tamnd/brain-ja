 ## 問題の理解

 この問題は、最短パスに正確に含まれるツリー内の順序付けされていない頂点のペアの数を求めます。`k`エッジ。 入力は無向ツリーを次のように記述します。`n`頂点、その後にターゲット距離`k`。 出力は、この距離要件を満たす頂点の異なるペアの数を表す単一の整数です。 

ツリーには、頂点のすべてのペアの間に一意のパスがあり、これが問題を扱いやすくする特性です。 任意の 2 つのノード間には可能なパスが 1 つしかないため、最短パスを繰り返し検索する必要はありません。 

重要な制約は、`n`50,000に達する可能性がありますが、`k`頂点のすべてのペアをチェックするアルゴリズムには、最大でも 500 が必要です。`n² / 2`距離計算は、最大サイズで約 12 億 5,000 万回の演算になります。 通常のコンテスト環境では遅すぎます。 の小さな値`k`長距離の考慮を避け、最大の長さのパスのみに焦点を当てるべきであることを示唆しています。`k`。 

いくつかの特殊なケースでは、単純な実装が壊れる可能性があります。 

単一の頂点ツリーの場合、カウントするペアはありません。 

入力：```
1 1
```正しい出力は次のとおりです。```
0
```少なくとも 1 つのエッジが存在することを前提としたソリューションは、隣接リストの構築中または再帰の初期化中に失敗する可能性があります。 

いつ`k = 1`、すべての有効なペアは単にツリーの端にすぎません。 例えば：```
3 1
1 2
2 3
```正しい出力は次のとおりです。```
2
```より深い共通の祖先を共有するペアのみを対象として設計された方法では、これらの直接的なつながりが失われる可能性があります。 

連鎖により、二重カウントミスが露呈する可能性もあります。 のために：```

```正しい出力は次のとおりです。```

```有効なペアは次のとおりです。`(1,3)`、`(2,4)`、 そして`(3,5)`。 重複を回避する方法なしに両方のエンドポイントからのパスを個別にカウントすると、すべてのペアが 2 回カウントされます。 

## アプローチ

 直接的な解決策では、すべての頂点のペアを試します。 各ペアについて、幅優先検索を実行するか、ツリー構造を使用してペアの距離を計算し、距離が等しい場合に答えをインクリメントします。`k`。 考えられるすべてのペアが検査されるため、これは正しいです。 

問題はコストです。 おおよそあります`n²`ペア、および単純な定数時間の距離計算であっても、次のような場合にはまだ多すぎるでしょう。`n = 50000`。 すべての頂点からの BFS を使用すると、複雑さは次のようになります。`O(n²)`実装の詳細によっては、制限をはるかに超えてさらに悪化する場合もあります。 

重要な観察点は、有効な長さのパスはすべて、`k`固有の中点または中エッジを持っています。 ツリーの重心を選択した場合、すべてのパスは、その重心を削除した後に残った 1 つのコンポーネント内に完全に収まるか、重心を通過します。 これにより、重心を通過するすべてのパスを数え、より小さな部分問題を削除し、それらを再帰的に解決できます。 

重心の場合、そこからの各距離に頂点がいくつ存在するかを知る必要があるだけです。 1 つのサブツリー内の頂点が距離である場合`d`重心から離れたところにある別のサブツリーの頂点から`k-d`有効なペアを作成します。 同じ重心ステップで同じサブツリーから 2 つの頂点をカウントしないようにしながら、異なるサブツリーからの情報を結合します。 

ブルートフォース手法は、すべてのペアが直接チェックされるため機能しますが、ペアが多すぎるため失敗します。 重心分解の観察により、問題がより小さなツリーに縮小され、すべての頂点が対数的に多くの分解レベルにのみ参加できるようになります。

 ## アルゴリズムのチュートリアル

 1. 現在のツリー コンポーネントの重心を見つけます。 重心とは、削除した後に残っているすべての接続コンポーネントが元の頂点の最大半分を持つような頂点です。 これにより、再帰的分解が対数的な深さを持つことが保証されます。 
2. この重心を通過するすべての有効なパスを数えます。 まずは周波数配列から始めます。`distance 0`重心自体が含まれます。 各子サブツリーについて、重心からの距離ごとに存在する頂点の数を収集します。 そのサブツリーの距離をグローバル頻度配列に追加する前に、その距離にあるすでに処理された頂点の数をクエリします。`k - current_distance`。 これらのペアは、異なるサブツリーからのものであり、そのパスが重心を通過するため、有効です。 
3. 現在のサブツリーの距離を頻度配列に追加します。 この重心処理ステップでは同じサブツリー内の頂点をペアにしてはいけないため、順序が重要になります。 それらのパスは重心を通過せず、後でそのサブツリーが別個の再帰コンポーネントになるときに処理されます。 
4. 重心を削除済みとしてマークし、残りのすべてのコンポーネントを再帰的に解決します。 コンポーネント内のすべてのパスは削除された重心を使用できないため、各コンポーネントは独立しています。 
5. すべてのコンポーネントが処理されるまで続行します。 セントロイド処理中に見つかったすべてのカウントの合計が最終的な答えになります。 

なぜ効果があるのか:

 すべての頂点のペアには、分解において 2 つの頂点が異なるコンポーネントに分離されるか、またはそれらの 1 つが重心自体となる、分解における最高レベルの重心が 1 つだけあります。 その瞬間、彼らの経路はその重心を通過し、正確に 1 回カウントされます。 両方の頂点が同じコンポーネント内に残っている場合、そのペアはまだカウントされませんが、より深い分解レベルで考慮されます。 考えられるすべてのペアはその固有の分離重心で処理されるため、ペアの欠落や重複はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    removed = [False] * n
    size = [0] * n
    ans = 0

    def calc_size(v, p):
        size[v] = 1
        for u in graph[v]:
            if u != p and not removed[u]:
                size[v] += calc_size(u, v)
        return size[v]

    def find_centroid(v, p, total):
        for u in graph[v]:
            if u != p and not removed[u]:
                if size[u] > total // 2:
                    return find_centroid(u, v, total)
        return v

    def collect(v, p, d, arr):
        if d > k:
            return
        arr.append(d)
        for u in graph[v]:
            if u != p and not removed[u]:
                collect(u, v, d + 1, arr)

    def decompose(v):
        nonlocal ans

        total = calc_size(v, -1)
        c = find_centroid(v, -1, total)

        freq = [0] * (k + 1)
        freq[0] = 1

        for u in graph[c]:
            if removed[u]:
                continue

            distances = []
            collect(u, c, 1, distances)

            for d in distances:
                if d <= k:
                    ans += freq[k - d]

            for d in distances:
                if d <= k:
                    freq[d] += 1

        removed[c] = True

        for u in graph[c]:
            if not removed[u]:
                decompose(u)

    decompose(0)
    print(ans)

if __name__ == "__main__":
    solve()
```すべての頂点はその近隣へのアクセスのみを必要とするため、隣接リストにはツリーが保存されます。 の`removed`配列は、すでに重心になっている頂点を表しており、後の再帰コンポーネントには含めるべきではありません。 

最初の関数のペア、`calc_size`そして`find_centroid`、現在のコンポーネントの重心を見つけます。 分解は残りの各コンポーネントに対して独立して実行されるため、サイズの計算では削除された頂点は無視されます。 

の`collect`関数は、重心からの距離を 1 つの子サブツリーに収集します。 距離を置くと止まる`k`なぜなら、パスが長くても答えには決して貢献できないからです。 

カウントフェーズでは次を使用します。`freq`距離から既に処理された頂点の数までのマップとして。 新しいサブツリーを処理するとき、クエリを実行する`freq[k - d]`重心を通る合計距離が正確に一致するすべてのペアをカウントします。`k`。 クエリを実行した後でのみ、サブツリーの距離を追加します。`freq`これにより、同じサブツリーからのペアがこのレベルでカウントされなくなります。 

Python の整数は、応答サイズが大きくても自動的に処理します。`n²`。 距離配列にはサイズがあります`k + 1`したがって、大きなパスによる隠れたメモリの増加はありません。
