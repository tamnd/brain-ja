 ## 解決策
 ## 問題の理解

 スペースが無視される場合、最大 7 文字を含むターゲット文字列と、その後に単語の辞書が与えられます。 単語間のスペースを無視して、結合された文字がターゲットの文字と正確に一致する辞書単語のすべての個別のシーケンスを出力する必要があります。 The order of the words matters, so`arm code`そして`code arm`は異なる答えです。 回答はアルファベット順に印刷する必要があります。 辞書エントリが重複しているため、同じ語句が 2 回出力されてはなりません。 

たとえば、ターゲットを使用すると、`coderam`、辞書には次のように書かれています`arm`、`code`、`coderam`、`dore`、 そして`mac`。 たった一言`coderam`は有効ですが、`arm code`そして`code arm`3 つすべてにまったく同じ 7 文字が含まれているため、これらも有効です。 のような言葉`codes`が必要なため参加できません`s`ターゲットに存在しないもの。 

ターゲットの長さは中心の制約です。 最大 7 文字ということは、考えられる残りの文字の状態が少数しかないことを意味します。 7 つの文字がすべて異なる場合、すべての状態はこれら 7 つの文字のサブセットを選択することに対応し、最大 (2^7=128) 個の状態が得られます。 文字を繰り返しても、この数は減るだけです。 公式の制限時間は 15 秒、メモリ制限は 256 MB であるため、意図したソリューションでは辞書を処理して実際の答えを列挙する余裕はありますが、辞書の単語の任意の組み合わせを探索することは避けるべきです。 

Codeforces によって示されるステートメントには辞書サイズに関する有効な数値上限がないため、回答の印刷に避けられないコストが発生する前に、アルゴリズムは辞書サイズを線形または線形に近い値にする必要があります。 7 文字の制限はまさにその機会を与えてくれます。 

1 つ目のエッジ ケースは、辞書エントリの重複です。 考慮する：```
a
2
a
a
```正しい出力は次のとおりです。```
a
```辞書の 2 行は同じ単語を表すため、辞書エントリを別々の選択肢として扱うと、誤って出力されます。`a`2回。 

2 番目のエッジ ケースは、ターゲット内で決して出現しない文字を含む辞書の単語です。 考慮する：```
ab
2
a
ac
```正しい出力は次のとおりです。```
a
```言葉`ac`ターゲットには何も含まれていないため、アナグラムの一部にすることはできません。`c`。 単語の長さを比較するだけの不注意な実装では、それが受け入れられる可能性があります。 

3 番目の特殊なケースは、文字が繰り返されることです。 考慮する：```
aa
2
a
aa
```正しい出力は次のとおりです。```
a a
aa
```言葉`a`ターゲットには のコピーが 2 つ含まれているため、2 回使用できます。`a`。 すべての辞書の単語が最大 1 回しか使用できないと仮定したソリューションでは、失敗します。`a a`。 

4 番目のエッジ ケースは、ある回答が別の回答のプレフィックスである場合のアルファベット順に関するものです。 考慮する：```
ab
2
a
ab
```正しい出力は次のとおりです。```
a b
ab
```比較は完全な出力文字列間で行われます。 以来`a b`もっている`a`その後にスペースが続き、`ab`もっている`b`、通常の辞書編集上の比較の場所`a b`前に`ab`。 DFS は、長さではなく、実際の単語列に基づいて回答を生成する必要があります。 

## アプローチ

 最も直接的な強引なアイデアは、辞書の単語の順序付けられたシーケンスをすべて試してみることです。 ターゲットには最大 7 文字が含まれるため、辞書の各単語には少なくとも 1 文字が含まれるため、有効な回答には最大 7 つの単語を含めることができます。 (n) 個の辞書単語を使用すると、長さ 1 ～ 7 のシーケンスの数は次のようになります。 

[
 n+n^2+n^3+\cdots+n^7。 
】

 大きい (n) 場合、最終項が優勢であるため、これは (O(n^7)) 個の候補シーケンスになります。 また、選択したすべての単語の文字を検査して、結合されたマルチセットがターゲットと等しいかどうかを確認すると、候補ごとの作業量は 7 つのターゲット文字で区切られた別の定数になります。 考えられるすべての順序付けされたシーケンスが考慮されるため、総当り攻撃は正しいのですが、(n^7) の増大が速すぎます。 

たとえば、(n=100) の場合でも、単独でおよそ (10^{14}) 個の 7 単語のシーケンスが得られます。 15 秒の制限内でそれらを列挙する方法はありません。 

ブルートフォース手法は、辞書のサイズを組み合わせの複雑さの原因として扱うため、失敗します。 ターゲットの長さから、ほとんどすべての辞書の単語が無関係であることがわかります。 単語は、それに含まれるすべての文字をターゲットから取得できる場合にのみ使用でき、単語を選択した後は、残りの文字のみが問題になります。 

各単語を複数の文字セットで表します。 ターゲットが`coderam`そして私たちは選択します`arm`、次の決定に必要な唯一の情報は、残りの文字が`cdeor`。 これらの文字が元々どの位置を占めていたかは気にしません。 同じ残りのマルチセットを残す 2 つの異なるパスは、まったく同じ部分問題を解決します。 

このような状態は最大 128 個存在します。 各状態で使用可能な辞書単語を保存し、残りの文字状態に対して DFS を実行できます。 残りの状態が空の場合は常に、現在のシーケンスが完全な答えになります。 

順序付けの要件は、このアプローチに自然に適合します。 使用可能なすべての辞書単語がアルファベット順に格納されており、DFS がその順序でそれらを試行する場合、小さい最初の単語で始まるすべての補完が、より大きな最初の単語で始まるすべての補完の前に生成されます。 同じ議論が後の単語に再帰的に適用されます。 したがって、DFS 自体が辞書編集順に完全なフレーズを生成するため、後で潜在的に膨大な回答セットを収集して並べ替える必要がありません。 

重複する辞書エントリは検索前に削除されます。 同じ文字マルチセットを持つ異なる単語は、まったく異なるフレーズを生成するため、保持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^7)) 個の候補シーケンス | (O(7)) 再帰の深さ | 遅すぎる |
 | 状態ベースの DFS | (O(n\log n + 128n + A)) | (O(128n + 7)) | 承認済み |

 ここで (A) は、出力の量と、それを生成するために必要な再帰的作業を表します。 プログラムは有効な答えをすべて出力する必要があるため、ソリューションでは出力サイズに比例する作業を漸近的に回避することはできません。 

## アルゴリズムのチュートリアル

 1. ターゲット文字列を読み取り、その文字列のスペースを削除します。 スペースはアナグラムに文字を寄与しないため、ターゲットは実際の文字によってのみ表されます。 
2. ターゲット内で発生する個別の文字を収集し、それぞれにインデックスを割り当てます。 たとえば、`coderam`、該当する文字は次のとおりです。`c`、`o`、`d`、`e`、`r`、`a`、 そして`m`。 
3. ターゲットをカウント ベクトルで表します。 各コンポーネントは、関連する 1 つの文字のコピーが何個残っているかを保存します。 辞書の単語も同じ表現になります。 ターゲット外の文字が含まれている場合は、有効な回答には決して含まれないため、すぐに破棄してください。 7 文字を超える単語も自動的に無関係になります。 
4. 重複する辞書の単語を削除し、残りの関連する単語をアルファベット順に並べ替えます。 元の単語をカウント ベクトルと一緒に保持することで、すべてのアナグラム チェックにコンパクト ベクトルを使用しながら、正確なスペルを出力できます。 
5. DFS 状態を、まだ使用されていない文字のカウント ベクトルとして定義します。 初期状態は完全なターゲット ベクトルです。 空のベクトルは、すべてのカウントがゼロであることを意味し、1 つの完全な有効なフレーズを表します。 
6. 残りの特定の状態について、関連するすべての辞書の単語をアルファベット順に検討します。 単語は、その文字数がすべて対応する残りの文字数以下である場合に正確に選択できます。 
7. 選択した単語のカウントを残りの状態から減算し、より小さい状態を再帰的に解決します。 辞書のメンバーシップは、エントリが 1 回の使用後に消費されることを意味するものではないため、同じ辞書の単語が後で再度選択される可能性があります。 残りの文字数によって、別のコピーが収まるかどうかが決まります。 
8. 答えを生成する前に、メモ化された実現可能性 DFS を使用して、状態がゼロに到達できるかどうかを判断します。 出力生成中は、解決可能な状態に至る遷移のみを追跡します。 これにより、ターゲットを完了できない方法で文字を消費する死んだブランチが削除されます。 
9. 残りの状態がゼロの場合、現在のシーケンスを出力します。 選択肢はすべての再帰レベルでアルファベット順に考慮されるため、生成されるフレーズはすでにアルファベット順になっています。 

### なぜ効果があるのか

 不変条件は、すべての再帰状態が、現在の接頭辞の単語にまだ割り当てられていないターゲットの文字を正確に表すということです。 遷移は、選択した辞書単語の文字数がその状態内に収まる場合にのみ許可されるため、新しい状態は正確に古い状態からその単語を除いたものになります。 状態がゼロに達すると、選択された単語の集合体にターゲットの文字が正確に含まれ、そのフレーズが有効なアナグラムになります。 

逆に、有効な回答を選択し、その回答の言葉を左から右に検討します。 すべての単語は辞書に属し、その前の単語の後にまだ使用可能な文字のみを使用するため、DFS は各ステップで対応する有効な遷移を持ちます。 それは最終的にゼロの状態に到達し、その答えを生み出します。 重複する辞書エントリを削除すると、同じ語句が 2 回生成されなくなります。 アルファベット順の走査により、必要な出力順序が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    target = input().rstrip("\n").replace(" ", "")
    n = int(input())

    if not target:
        for _ in range(n):
            input()
        return

    chars = sorted(set(target))
    index = {ch: i for i, ch in enumerate(chars)}
    k = len(chars)

    target_count = [0] * k
    for ch in target:
        target_count[index[ch]] += 1

    words = set()

    for _ in range(n):
        word = input().rstrip("\n")

        if len(word) > len(target):
            continue

        count = [0] * k
        ok = True

        for ch in word:
            pos = index.get(ch)
            if pos is None:
                ok = False
                break
            count[pos] += 1
            if count[pos] > target_count[pos]:
                ok = False
                break

        if ok:
            words.add(word)

    words = sorted(words)

    if not words:
        return

    word_data = []
    for word in words:
        count = [0] * k
        for ch in word:
            count[index[ch]] += 1
        word_data.append((word, tuple(count)))

    initial = tuple(target_count)

    candidate_cache = {}

    def candidates(rem):
        if rem in candidate_cache:
            return candidate_cache[rem]

        result = []
        for word, cnt in word_data:
            ok = True
            for i in range(k):
                if cnt[i] > rem[i]:
                    ok = False
                    break

            if ok:
                result.append((word, cnt))

        candidate_cache[rem] = result
        return result

    feasible = {}

    def can_solve(rem):
        if not any(rem):
            return True

        if rem in feasible:
            return feasible[rem]

        for _, cnt in candidates(rem):
            nxt = tuple(rem[i] - cnt[i] for i in range(k))
            if can_solve(nxt):
                feasible[rem] = True
                return True

        feasible[rem] = False
        return False

    if not can_solve(initial):
        return

    answer = []
    current = []

    def generate(rem):
        if not any(rem):
            answer.append(" ".join(current))
            return

        for word, cnt in candidates(rem):
            nxt = tuple(rem[i] - cnt[i] for i in range(k))

            if can_solve(nxt):
                current.append(word)
                generate(nxt)
                current.pop()

    generate(initial)

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```ターゲットは、まずスペースを削除して正規化されます。 辞書は読み取られる際にフィルタリングされます。 の`index`マッピングを使用すると、単語にターゲットに存在しない文字が含まれるとすぐにその単語を拒否することができます。 

の`words`set は重複した辞書エントリを削除します。 入力中にソートされた構造を維持するのではなく、後でソートするため、辞書処理がシンプルになります。 

保持された各ワードはカウントタプルに変換されます。 タプルにはターゲット内に出現する文字のみが含まれるため、タプルの長さは最大 7 です。 タプルは不変でハッシュ可能であるため、メモ化の辞書キーとして使用できます。 

の`candidates`関数は、特定の残りの状態に適合するすべての辞書単語をキャッシュします。 個別の状態は最大 128 個あるため、辞書をスキャンする場合でも、スキャンは状態ごとに 1 回しか実行できません。 

の`can_solve`関数は、この残りのマルチセットを完全に完了できるかどうかという、より小さな決定問題に答えます。 メモ化は、多くの異なる接頭辞を介して同じ残りの状態に到達できるため便利です。 

の`generate`関数は答えを生成することのみを担当します。 ワードのカウント ベクトルを減算し、結果の状態が実現可能であることを確認し、再帰的に続行します。 の`current`list は正確なフレーズ接頭辞を表します。 

すべてのカウントは最大 7 であるため、整数のオーバーフローは発生しません。 選択されたすべての単語が少なくとも 1 つのターゲット文字を消費するため、再帰の深さも最大 7 です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log n + 128n + A)) | 関連する辞書のソートにはコスト (O(n\log n))、最大 128 の状態が辞書をスキャンし、(A) は生成された出力とその再帰作業を表します。 
| スペース | (O(128n + A_{\text{バッファ}} + 7)) | キャッシュされた候補リストは最悪の場合 (O(128n)) のスペースを使用しますが、再帰の深さは最大でも 7 | です。 

決め手は7文字ターゲット。 7 つの異なる文字があっても、可能な残りの文字のマルチセットは 128 個しかありません。 辞書は大きいかもしれませんが、(n^7) 個の組み合わせを通じて探索されることはありません。 残りの作業は辞書をスキャンすることと、回答自体を印刷することによって占められますが、これは避けられません。 

公式の制限は 15 秒および 256 MB です。 このアルゴリズムは、特定のアルファベットに関する仮定を回避しながら、小さなターゲット長を使用して状態空間を小さく保ちます。

            if can_solve(nxt):
                feasible[rem] = True
                return True

        feasible[rem] = False
        return False

    if not can_solve(initial):
        return

    result = []
    current = []

    def generate(rem):
        if not any(rem):
            result.append(" ".join(current))
            return

        for word, cnt in candidates(rem):
            nxt = tuple(rem[i] - cnt[i] for i in range(k))

            if can_solve(nxt):
                current.append(word)
                generate(nxt)
                current.pop()

    generate(initial)
    sys.stdout.write("\n".join(result))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        from contextlib import redirect_stdout

        out = io.StringIO()
        with redirect_stdout(out):
            solve()

        return out.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

## 特殊なケース

 重複する辞書エントリについては、次の点を考慮してください。```
a
2
a
a
```目標の状態は、`(1)`。 辞書セットには 1 つだけ含まれています`a`したがって、DFS は一度空の状態に達し、次のように出力します。`a`一度。 重複排除を行わないと、同じ再帰パスが 2 つの同一の辞書エントリによって表され、出力が重複します。 

使用できない文字については、次の点を考慮してください。```
ab
2
a
ac
```ターゲットには次のものだけが含まれます`a`そして`b`。 読みながら`ac`、キャラクター`c`ターゲットにインデックスがないため、単語は DFS に入る前に破棄されます。 唯一可能な出力は次のとおりです`a`ターゲットが完全にカバーされていない場合、この正確な入力には実際には完全なアナグラムはなく、正しい出力は空になります。 実装では出力が正しく生成されません。 

文字や単語を繰り返し再利用する場合は、次の点を考慮してください。```
aa
2
a
aa
```初期カウントは 2 コピーです`a`。 選択する`a`コピーが 1 つ残るので、`a`再び有効になり、ゼロになります。 選択する`aa`両方のコピーがすぐに消費されます。 出力は次のとおりです。```
a a
aa
```検索ではマークされません`a`世界的に使用されているように。 残りのカウントのみが、別のオカレンスが適合するかどうかを決定します。 

アルファベット順については、次の点を考慮してください。```
ab
3
a
b
ab
```辞書は次のように分類されています`a`、`ab`、`b`。 から始まる`a`生成する`a b`、前に来ます`ab`。 の`ab`その後ブランチが生成します`ab`、続いて`b a`支店。 出力は次のとおりです。```
a b
ab
b a
```この順序付けは、単語の長さや文字の署名による並べ替えではなく、DFS の前に実際の辞書の単語を並べ替えることによって行われます。 

最後に、ターゲットより長い単語を含む辞書を考えてみましょう。```
abc
3
abcd
ab
c
```

`abcd`は、長さが使用可能なターゲット文字数を超えているため、すぐに拒否されます。 残りの単語を組み合わせると次のようになります。`ab c`したがって、出力は次のようになります。```
ab c
```この早期のフィルタリングは正確性のためには必要ありませんが、明らかに不可能な単語が状態検索に入るのを防ぎ、すべてのターゲット文字が 1 回だけ使用されなければならないという事実から直接導き出されます。
