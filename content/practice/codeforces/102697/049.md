 ## 解決策
 ## 問題の理解

 合成整数 (n) が与えられます。 (1) より大きい (n) のすべての約数は、円の周りに正確に 1 回配置する必要があります。 最初の循環順序を自由に選択できます。 

その順序を選択した後、1 つの操作で 2 つの隣接する数値 (a) と (b) を取得し、それらの最小公倍数を計算して、それらの間に挿入します。 すべての隣接するペアの公約数が (1) より大きい場合、その円は復号化されたとみなされます。 

タスクは、そのような挿入の数を最小限に抑え、その最小値を達成する初期順序を出力することです。 

中心的な観察は、約数の実際の値は、それに含まれる個別の素因数ほど重要ではないということです。 仮定してください

 [
 n=p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}。 
】

 すべての約数 (d>1) に対して、(k) ビットのマスクを定義します。 ビット (i) は (p_i\mid d) のときに正確に設定されます。 2 つの約数は、それらのマスクに少なくとも 1 つの共通の設定ビットがある場合、正確には非互いに素になります。 

公式の制約では (4\le n\le 10^9) が与えられ、テスト ケースは最大 (100) 個、約数は合計で最大 (2\cdot10^5) 個になります。 (\sqrt n\le31623) ため、試行分割によるファクタリングは結果的に安価になります。 さらに重要なのは、約数の総数が十分に小さいため、明示的に生成して保存できることです。 総当たりの順列検索は完全に不可能ですが、(O(\sqrt n+\tau(n))) または同様の線形に近い構築は簡単に十分に高速です。 

建設に注意が必要な理由を明らかにするいくつかの特殊なケースがあります。 

(n=4) の場合、(1) より大きい約数は (2,4) です。 これらは素因数 (2) を共有しているため、正しい最小値はゼロです。 次のような出力```
2 4
0
```有効です。 約数が少ないすべての合成数に挿入が必要であると想定する不注意な解決策では、(1) が誤って出力される可能性があります。 

(n=6) の場合、約数は (2,3,6) です。 数 (2) と (3) は互いに素であり、両方の素数を含む約数は (6) だけです。 最初の円には (2) から (3) への隣接関係があるため、少なくとも 1 つの挿入が必要です。 正しい最小値は 1 です。たとえば、```
2 3 6
1
```(n=12=2^2\cdot3) の場合、2 つの異なる素因数があるにもかかわらず、答えはすでに 0 です。 有効な注文の 1 つは、```
2 6 3 12 4
0
```循環ペア (4,2) を含め、すべての隣接するペアには共通因数があります。 「2 つの異なる素因数は 1 つの演算を意味する」という単純なルールは、ここでは静かに失敗します。 このケースが機能する理由は、両方の素数を含む約数が少なくとも 2 つ (6) と (12) あるため、円の周囲で (2) のみのグループと (3) のみのグループを分離できるためです。 

(n=30=2\cdot3\cdot5) の場合、3 つの素因数の空でないサブセットはすべて、何らかの約数の素因数マスクとして発生します。 適切な順序付けにより、すべての隣接するペアが素数を共有できるため、最小値はゼロになります。 これは、ビットマスク構築が特に役立つ最初のケースです。 

## アプローチ

 最も直接的な総当たりアプローチは、(1) より大きい約数のすべての順列を生成し、各順列について、最後の要素と最初の要素を含むすべての隣接するペアをチェックすることです。 すべてのペアの gcd が (1) より大きい場合、ゼロオペレーションの解が得られます。 それ以外の場合は、すべての不良ペアは最小公倍数を挿入することで修正できるため、不良ペアができるだけ少ない配置を検索できます。 

この総当りは、考えられるすべての初期円を明示的に考慮するため、正しいです。 問題は順列の階乗数です。 (\tau(n)) を (1) を含む (n) の約数の数とします。 (\tau(n)-1) 個の数を配置する必要があります。 ゼロオペレーションの取り決めが存在するかどうかだけをチェックしたとしても、最悪の場合の gcd チェックの数はおよそ

 [
 (\tau(n)-1)\cdot(\tau(n)-1)!。 
】

 (n\le10^9) の場合、最大除数数は 1344 で、たとえば (931170240) によって達成されます。 そのため、総当たり検索には (1343\cdot1343!) 個の gcd 計算が必要になりますが、これはリモートでは実行できません。 

有用な構造は因数分解 (n) 後に表示されます。 除数は、完全な指数ベクトルで表す必要はありません。 共素性条件では、それぞれの異なる素数が少なくとも 1 回出現するかどうかのみを考慮します。 

これにより、すべての約数が異なる素因数の空ではないサブセットに変わります。 2 つのマスクが交差する場合、対応する約数は互いに素ではありません。 この問題は、小さな集合の空でない部分集合に対する建設的な問題になります。 

少なくとも 3 つの異なる素数がある場合、修正されたバイナリ グレイ コードを使用して空でないマスクをすべて順序付けることができます。 連続するグレイコード マスクは 1 ビットだけ異なります。そのため、2 つの連続する空でないマスクは、人工的なゼロマスク境界を除き、少なくとも 1 つの設定ビットを共有します。 その境界を削除し、すべて 1 のマスクから始まるサフィックスを逆にします。 すべて 1 のマスクが最終マスクになりますが、最初のマスクは最初の素数を含むシングルトンになります。 これら 2 つのマスクも交差し、円を閉じます。 

2 つの異なる素数の場合は、個別に処理する必要があります。 (n=p^a q^b)と書きます。 すべての約数は、(p) のみを含む約数、(p) と (q) の両方を含む約数、(q) のみを含む約数の 3 つのグループのいずれかに属します。 (a=b=1) の場合、中間群 (pq) にはちょうど 1 つの約数があり、1 つの演算は避けられません。 少なくとも 1 つの指数が 1 より大きい場合、少なくとも 2 つの混合約数が存在します。 一方の (p) のみのグループと (q) のみのグループの間に 1 つの混合ブロックを配置し、もう一方の側に別の混合ブロックを配置できます。 これにより、操作はゼロになります。 

異なる素数が 1 つだけの場合、すべての約数はその素数のべき乗になるため、すべてのペアは自動的に非素となり、答えはゼロになります。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(\tau(n)\cdot\tau(n)!)) | (O(\tau(n))) | 遅すぎる |
 | 因数分解 + マスク構築 | (O(\sqrt n+\tau(n)+2^k)) | (O(\tau(n)+2^k)) | 承認済み |

 ここで (k) は個別の素因数の数です。 (n\le10^9)、(k\le9) なので、(2^k\le512) になります。 

## アルゴリズムのチュートリアル

1. (n) をその個別の素因数 (p_0,p_1,\ldots,p_{k-1}) とその指数に因数分解します。 (n) は最大でも (10^9) であるため、試行除算で十分です。 
2. (1) より大きいすべての約数を生成します。 同時に、そのプライムプレゼンスマスクを計算します。 除数の (p_i) の指数が正の場合、ビット (i) を設定します。 除数を対応するマスク グループに保存します。 
3. (k=1) の場合、その単一グループ内のすべての約数を連結し、ゼロ演算を出力します。 すべての約数には素因数のみが含まれます。 
4. (k=2) の場合、マスク (01)、(11)、および (10) に対応するグループ (P)、(M)、および (Q) を呼び出します。 (M) に少なくとも 2 つの約数が含まれる場合、それを 2 つの空でない部分に分割して出力します。 

[
 P、\ M_1、\ Q、\ M_2。 
】

 すべての境界は、(p) または (q) のいずれかを共有する数値間にあり、(M_2) から (P) に戻る循環境界も (p) を共有します。 
5. (k=2) かつ (M) に含まれる約数が 1 つだけの場合、両方の指数は 1 でなければならないため、(n=pq) となります。 3 つのグループを任意の順序で出力します。 (p) のみの約数と (q) のみの約数の間に、不正な隣接関係が 1 つだけ存在します。 そこに最小公倍数 (n) を挿入します。 最小値は正確に 1 です。 
6. (k\ge3) の場合、通常のバイナリ グレイコード シーケンスを構築します。 

[
 G_i=i\oplus(i\mathbin{>>}1)
 】

 (0\le i<2^k) の場合。 すべて 1 のマスク (2^k-1) を見つけます。 
7. 最初のゼロ マスクを削除し、すべて 1 のマスクから始まるサフィックスを逆にします。 結果のマスクを順番に参照し、各マスクに属するすべての約数を追加します。 
8. 出力ゼロ操作。 グレイ コードから継承された連続するマスクは 1 ビットが異なるため、両方のマスクには少なくとも 1 つの共通の素数が含まれます。 サフィックスを反転しても、そのサフィックス内で隣接するマスクは変わりませんが、全 1 マスクを最後に移動すると、円形の境界が全 1 マスクと最初のシングルトン マスクを接続します。 

### なぜ効果があるのか

 不変条件は、2 つの連続するマスク グループが互いに隣り合って配置されるたびに、それらのマスクが交差するということです。 1 つのグループ内のすべての約数は、まったく同じ一連の個別の素因数を持っているため、グループ内の約数は自動的に非互いに素になります。 (k\ge3) の場合、グレイ コード隣接関係により、すべての通常の隣接ペアの交差が保証され、最後のオール 1 マスクが最初のシングルトン マスクと交差するため、循環ペアも有効です。 2 つの素数の場合、分割混合群は純粋な群の両側に混合約数を明示的に提供します。 この方法で 2 つの素数を分離できない唯一のケースは (n=pq) です。この場合、一意の混合約数が両側を占めることができないため、1 回の操作が必要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factorize(n):
    factors = []

    if n % 2 == 0:
        e = 0
        while n % 2 == 0:
            n //= 2
            e += 1
        factors.append((2, e))

    p = 3
    while p * p <= n:
        if n % p == 0:
            e = 0
            while n % p == 0:
                n //= p
                e += 1
            factors.append((p, e))
        p += 2

    if n > 1:
        factors.append((n, 1))

    return factors

def solve_case(n):
    factors = factorize(n)
    k = len(factors)

    groups = [[] for _ in range(1 << k)]

    def generate(i, value, mask):
        if i == k:
            if value > 1:
                groups[mask].append(value)
            return

        p, e = factors[i]

        generate(i + 1, value, mask)

        cur = value
        for _ in range(e):
            cur *= p
            generate(i + 1, cur, mask | (1 << i))

    generate(0, 1, 0)

    if k == 1:
        order = groups[1]
        return order, 0

    if k == 2:
        pure_p = groups[1]
        mixed = groups[3]
        pure_q = groups[2]

        if len(mixed) == 1:
            order = pure_p + mixed + pure_q
            return order, 1

        cut = len(mixed) // 2
        left_mixed = mixed[:cut]
        right_mixed = mixed[cut:]

        order = pure_p + left_mixed + pure_q + right_mixed
        return order, 0

    total_masks = 1 << k
    gray = [i ^ (i >> 1) for i in range(total_masks)]
    full = total_masks - 1

    pos = gray.index(full)

    mask_order = gray[1:pos] + list(reversed(gray[pos:]))

    order = []
    for mask in mask_order:
        order.extend(groups[mask])

    return order, 0

def solve_all(numbers):
    output = []

    for n in numbers:
        order, moves = solve_case(n)
        output.append(" ".join(map(str, order)))
        output.append(str(moves))

    return "\n".join(output)

def main():
    t = int(input())
    numbers = [int(input()) for _ in range(t)]
    sys.stdout.write(solve_all(numbers))

if __name__ == "__main__":
    main()
```因数分解ルーチンは、まず因数 (2) を削除し、次に残りの数値の平方根まで奇数の候補をテストします。 ループ後に残りの値が 1 より大きくなると、それは必然的に素数となり、最終因子になります。 

再帰的除数ジェネレータは、個別の素数ごとに指数を選択します。 指数 0 の再帰分岐ではマスク ビットが設定されないままになりますが、正の指数ごとに対応するビットが設定されます。 これは、すべての約数が 1 回だけ生成され、素数存在マスクによって決定されるグループに即座に配置されることを意味します。 

1 素数の場合は、そのグループを出力する以外に構築する必要はありません。 すべての約数は同じ素数の正のべき乗です。 

2 つの素数の場合、`mixed`グループには、両方の素数で割り切れるすべての約数が含まれます。 そのサイズは 2 つの指数の積です。 したがって、両方の指数が 1 の場合、それは正確に 1 になります。 その特殊な場合、答えは 1 つです。 それ以外の場合は、少なくとも 2 つの混合約数が存在するため、グループを 2 つの空ではない部分に分割することが可能です。 

少なくとも 3 つの素数については、`gray`すべてのマスクが 1 回だけ含まれます。 問題では除数 (1) が除外されるため、ゼロ マスクは除外されます。 すべて 1 のマスクは、適切なサフィックスを反転することによって最後に移動されます。 これがキー境界操作です。 これがないと、最初と最後の非ゼロ グレー マスクが互いに素になる可能性があり、循環ペアが無効なままになります。 

Python の整数はオーバーフローせず、生成されるすべての約数は最大 (n) です。 再帰の深さは最大でも個別の素因数の数 (n\le10^9) の場合は最大 9 であるため、再帰は安全です。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 (n=4) の場合、因数分解には 1 つの異なる素数があるため、アルゴリズムは (2) と (4) を同じマスク グループに入れます。 出力は`2 4`操作はゼロです。 それらの gcd は (2) であるため、循環ペアはすでに有効です。 

(n=6) の場合、因数分解には 2 つの素数があり、両方の指数が 1 に等しいことになります。 混合グループには (6) のみが含まれるため、アルゴリズムは (2) のみのグループ、混合グループ、および (3) のみのグループを出力します。 結果として得られる円には、まさに 1 つの共素境界 (3,2) があります。 それらの最小公倍数は (6) であるため、1 回の挿入で円が固定されます。 (2) と (3) は両方とも出現する必要があり、混合除数は 1 つだけであるため、ゼロ演算の配置は存在しません。 

(n=12) の場合、グループは (P={2,4})、(M={6,12})、および (Q={3}) です。 このアルゴリズムは (M) を 2 つの空でない部分に分割し、`2 6 3 12 4`。 円形境界が含まれる場合、連続するペアはそれぞれ gcd (2,3,3,2,2) を持ちます。 したがって、操作はゼロで十分です。 

(n=16) のような数値の場合、(1) より大きいすべての約数は (2) の累乗になります。 このアルゴリズムには、グレイ コードや特別な挿入は必要ありません。 すべての約数は同じマスクに属しており、すべてのペアの gcd が少なくとも (2) であるため、どのような順序付けも機能します。 

(n=30) の場合、マスクはすべて 3 つの素数の 7 つの空でないサブセットです。 変更されたグレイコードの順序は次のとおりです。`1,3,2,6,4,5,7`。 これらのマスクを約数に変換すると、次のようになります。`2,6,3,15,5,10,30`。 循環ペア (30,2) を含むすべての連続するペアは素因数を共有します。 したがって、答えはゼロになります。 

大きなストレス ケース (931170240) の場合、この数値には 1344 の約数があり、これは (10^9) までの数値の最大約数です。 このアルゴリズムでは順列は考慮されません。 数値を因数分解し、その約数を 1 回生成し、各約数をマスク グループに割り当て、最大 (2^9=512) 個のマスクを処理します。 これはまさに、建設的な解決策と階乗的総当たり法の違いです。
