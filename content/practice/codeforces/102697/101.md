 ## 解決策
 ## 問題の理解

 大都市を表す (n \times n) 個の正方形グリッドがあります。 各セルには 0 から 9 までの数字が含まれており、これはそのセル内の建物の高さを表します。 建物の高さが、その側面または角を共有するすべての建物の高さよりも厳密に高い場合、その建物は超高層ビルと呼ばれます。 したがって、各セルには最大 8 つの関連する隣接セルがあります。 タスクは、次のように別の (n \times n) グリッドを生成することです。`Y`まさに超高層ビルの位置にあり、`N`他のどこでも。 元の問題では、1 秒の時間制限と 256 MB のメモリ制限が使用されています。 

入力には (n) の後に長さ (n) の (n) 個の文字列が含まれます。 入力自体には (n^2) 個の高さの値が含まれているため、(O(n^2)) 時間で実行されるアルゴリズムが自然なターゲットになります。 (O(n^3)) を採用したソリューションは、検査する必要があるデータ量よりも (n) 倍多くの作業を実行することになりますが、(O(n^4)) は、中程度のサイズのグリッドであってもコストが高すぎます。 グリッドには (n^2) 個の小さな文字しか含まれていないため、メモリ要件も簡単に満たすことができます。 

最初のエッジ ケースはコーナー セルまたは境界セルです。 8 つの隣接セルがないため、グリッドの外側のセルにアクセスしてはなりません。 例えば：```
1
5
```唯一の建物には隣接する建物がないため、すべての建物よりも空に大きくなっています。 正しい出力は次のとおりです。```
Y
```少なくとも 1 つの近傍を必要とする不用意な実装、または欠落している近傍を高さ 9 であるものとして扱うと、誤って出力されます。`N`。 

2 番目のエッジケースは平等です。 比較は、以上ではなく、厳密に大きい必要があります。 例えば：```
2
55
55
```どの建物にも同じ高さの隣の建物があるため、超高層ビルはありません。 正しい出力は次のとおりです。```
NN
NN
```を使用した実装`>=`すべてのセルが誤って超高層ビルとしてマークされてしまいます。 

3 番目のエッジ ケースは、対角線上の隣接ケースです。 斜めのセルは、エッジを共有していなくても、隣接しているものとしてカウントされます。 例えば：```
2
91
19
```左上の建物の高さは 9 で、他の 3 つの建物よりも高いため、正しい出力は次のようになります。```
YN
NY
```4 つの隣り合うものだけをチェックする実装はたまたまこの例を正しく実現していますが、次のような場合には対角関係が決定的になります。```
2
19
91
```ここでは、右上と左下の建物の高さは 9 で、両方ともマークする必要があります。`Y`。 唯一の競合する建物が斜めである場合、斜めを無視すると、誤った答えが生成される可能性があります。 

## アプローチ

 最も文字通りの強引な解釈は、1 つの建物を処理し、その高さを大都市内の他のすべての建物と比較することです。 現在の建物を見つけた後、すべての (n^2) 個のセルをスキャンし、それらのいずれかがより高いかどうかを確認できます。 すべての (n^2) 個の建物に対してこれを行うには、最悪の場合、(n^2 \cdot n^2 = n^4) 個の比較が必要になります。 これは正しいですが、遠くにある建物が現在の建物が超高層ビルであるかどうかに影響を与えることはできないため、隣接性の定義は無視されます。 

すべての建物をチェックすることで高い建物を見逃さないことが保証されるため、総当り攻撃は機能しますが、グリッドが大きくなると、それらの比較のほとんどすべてが無関係になるため、この方法は失敗します。 重要な観察点は、定義では対角線を含む直接隣接するセルのみが言及されていることです。 大都市の規模に関係なく、どの建物にもそのようなセルが最大 8 つあります。 

この観察により、1 つのセルの作業が (O(n^2)) から (O(1)) に減少します。 セルの周囲の 8 つの可能な方向を検査し、グリッドの外側の位置をスキップし、その高さ以上の高さの隣接セルを見つけるとすぐにそのセルを拒否します。 既存の隣接セルがすべて厳密に小さい場合、セルは超高層ビルになります。 

より高度なデータ構造や前処理技術は必要ありません。 入力にはすでに (n^2) 個のセルが含まれており、セルごとに一定量の作業のみを実行するため、最適な (O(n^2)) 実行時間が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^4)) | (O(1)) 入力とは別に | 遅すぎる |
 | 最適 | (O(n^2)) | (O(n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを (n) 文字列として読み取ります。 すべての高さは 1 桁であるため、各行を文字列として保持するだけで十分です。 
2. すべてのセル ((r,c)) を訪問します。 これは、すべての建物が独立した規制を受ける必要があるため必要です。`Y`または`N`決断。 
3. 現在のセルについて、オフセット ((0,0)) を除く、(-1) から (1) までの行と列のオフセットのすべての組み合わせを検査します。 これら 8 つのオフセットは、4 つの側方近傍と 4 つの斜め近傍を表します。 
4. 各近傍候補について、その座標がグリッド内に残っているかどうかを確認します。 当然、境界セルと隅のセルには有効な隣接セルが 8 つ未満しかないため、範囲外の位置は単純に無視されます。 
5. 有効な近傍の高さが現在の高さ以上である場合、現在の位置にマークを付けます。`N`。 現在の建物はすべての近隣の建物よりも厳密に高くなければならないため、平等であるというだけで失格には十分です。 
6. すべての有効な近傍の高さが低い場合は、現在の位置を次のようにマークします。`Y`。 (1 \times 1) グリッド内の唯一のセルなど、隣接するセルがないセルもこのケースに該当し、正しく超高層ビルと見なされます。 
7. 結果の (n) 行を出力します。 

不変条件は、セルを処理した後の出力文字が次のようになることです。`Y`exactly when every existing adjacent cell has a strictly smaller height. The algorithm examines every possible adjacent position and ignores only positions that do not exist, so no relevant neighbor can be missed. Since every cell is processed independently, applying this invariant to all (n^2) cells produces exactly the required grid.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    ans = []

    for r in range(n):
        row = []

        for c in range(n):
            height = grid[r][c]
            skyscraper = True

            for dr in (-1, 0, 1):
                for dc in (-1, 0, 1):
                    if dr == 0 and dc == 0:
                        continue

                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < n:
                        if grid[nr][nc] >= height:
                            skyscraper = False
                            break

                if not skyscraper:
                    break

            row.append('Y' if skyscraper else 'N')

        ans.append(''.join(row))

    sys.stdout.write('\n'.join(ans))

if __name__ == "__main__":
    solve()
```グリッドは文字列として直接保存されるため、`grid[r][c]`特定の位置の高さ文字を与えます。 文字は数字であるため、辞書編集上の順序が数値の順序と同じであるため、それらを直接比較することは有効です。`0`を通して`9`。 

2 つのネストされたループ`dr`そして`dc`8 つの隣接する位置をすべて列挙します。 明示的な`(0, 0)`check は、現在のセルがそれ自体と比較されないようにします。 境界条件`0 <= nr < n and 0 <= nc < n`特別な場合を除いて 4 つの境界線すべてを処理します。 

比較には、`>=`、 それよりも`>`。 隣接する建物の高さがまったく同じ場合、現在の建物の方が厳密には高いわけではないため、マークを付ける必要があります。`N`。 

の`skyscraper`フラグは次のように始まります`True`そしてなる`False`不適格な隣人が見つかったらすぐに。 初期の`break`ステートメントは、答えがすでにわかっている場合は、残りの近傍をチェックすることを避けます。 これによって漸近的な複雑さは変わりませんが、一般的なグリッドでの不必要な作業が軽減されます。 

Python の整数では、サイズが大きくなる可能性のある値に対してアルゴリズムが演算を実行しないため、ここでは特別なオーバーフロー処理は必要ありません。 出力は行ごとに蓄積され、最後に 1 回書き込まれます。

## 特殊なケース

 一つの建物の場合、```
1
5
```セルには有効な隣接セルがありません。 8 方向のループでは範囲外の位置のみが生成されるため、どの比較も建物を拒否できません。 旗は残っている`True`、そしてアルゴリズムは出力します`Y`。 これは数学的条件と一致します。なぜなら、既存の隣接するものはすべて、存在しないものはすべて、より低い高さを持つからです。 

隣接する高さが等しい場合、```
2
55
55
```左上のセルを考えてみましょう。 その右と下に隣接するものは両方とも高さ 5 です。条件チェックは`grid[nr][nc] >= height`、したがって、最初の等しい近隣が変更されます`skyscraper`に`False`。 他のすべての細胞でも同じことが起こり、`NN`両方の列にあります。 のみを使用する`>`これは、平等であるために建物が厳密に高くなることを防ぐ必要があるため、off-by-one スタイルの論理エラーになります。

2
19
91
```右上のセルの高さは 9 です。その対角線上に隣接するセルは左下のセルで、同じく高さ 9 です。この対角線の等価性は、右上のセルを作成するのに十分です。`N`。 左下のセルも同じ理由で拒否されますが、高さ 1 の 2 つのセルは隣接する 9 が存在するため拒否されます。 出力は`NY / YN`、8 つの方向がすべて含まれていることを確認します。 

大きなグリッドの右上隅などの境界セルの場合、アルゴリズムは 8 つのオフセットすべてを試行しますが、座標が境界チェックを満たすオフセットのみを受け入れます。 コーナー、エッジ、または内部セルに特別なブランチを必要とすることはありません。 同じコードでそれらをすべて処理することで、境界エラーとオフバイワン エラーの共通の原因が除去されます。
