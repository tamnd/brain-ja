 ## 問題の理解

 列車ネットワークは無向グラフとしてモデル化できます。 すべての都市は頂点であり、すべての鉄道路線はどちらの方向にも移動できるため、方向のないエッジです。 特定の 1 つの都市が出発点として与えられ、そこから任意の数の鉄道路線を使用して到達できる別の都市がいくつあるかを数える必要があります。 公式の問題では明示的に BFS が示唆されており、グラフ走査を実行する前に都市名を数値識別子にマッピングする必要があります。 

最初の入力行は都市の数を示します。`n`そして電車の路線も`m`。 次の行は開始都市の名前を示します。 以下のそれぞれ`m`線には、鉄道線で接続された 2 つの都市名が含まれています。 出力は、開始都市を含む接続コンポーネントのサイズです。 

この声明では明示的な上限は公表されていない。`n`そして`m`したがって、小さなグラフを想定すべきではありません。 制限時間はわずか 1 秒、メモリ制限は 256 MB です。 これは線形グラフの走査に非常に有利です。`O(n + m)`、都市を探索しながらすべての鉄道路線を繰り返しスキャンするのではなく。 隣接リストには、BFS が必要とする関係が正確に保存されるため、構築と走査の両方が入力グラフのサイズにおいて線形のままになります。 

都市名は整数の ID ではなく文字列です。 都市名を配列インデックスとして使用しようとする直接実装は不可能であるため、検出されたすべての名前を整数にマップするには辞書が必要です。 もう 1 つの微妙な問題は、都市が複数の路線にまたがって発生する可能性があることです。 インシデントエッジごとに 1 回ではなく、1 回カウントする必要があります。 

次の切断されたネットワークを考えてみましょう。```
4 2
A
A B
C D
```正しい出力は次のとおりです`2`。 から開始`A`、私たちは到達することができます`B`、しかし、どちらからもそこに至るルートはありません。`C`または`D`。 入力に含まれるすべての都市をカウントする実装では、誤って返される可能性があります。`4`。 

2 番目のエッジ ケースはサイクルです。```
3 3
A
A B
B C
C A
```正しい出力は次のとおりです`3`。 BFS が遭遇する可能性がある`A`処理中にまた`C`ただし、キューに入れたりカウントしたりしてはなりません`A`2回目。 訪問した構造物がなければ、横断はサイクルの周りを繰り返し歩くことができます。 

開始都市に鉄道路線がまったくない場合もあります。```
1 0
A
```正しい出力は次のとおりです`1`。 それ自体から到達可能であるためには電車に乗る必要がないため、開始都市はエッジがない場合でも到達可能なセットに属します。 

## アプローチ

 単純だが非効率な実装では、列車の路線をペアのリストとして表すことができます。 BFS は都市を処理するたびに、都市のリスト全体をスキャンします。`m`電車の路線を調べて、その都市に接続している路線を見つけてください。 考えられるすべての接続が検査されるため、これは正しいですが、処理`v`到達可能な都市はすべてスキャンする必要がある場合があります`m`毎回エッジ。 最悪の場合、すべてが終わったとき、`n`都市は到達可能、つまり`n * m`エッジチェック。 密なグラフの場合、`m`の命令で`n²`、これは次のようになります`O(n³)`、まばらなグラフの場合でも、無関係な鉄道路線を繰り返し調べることで作業が無駄になります。 

重要な観察点は、グラフが静的であるということです。 BFS を開始する前に、鉄道路線を都市ごとにグループ化できます。 あらゆる都市に`u`、直接接続されている都市を正確に含むリストを保存します。`u`。 そしてBFSが到達したとき`u`、無関係なエッジを検査する理由はありません。 単に反復処理するだけです`u`の隣接リスト。 

すべての無向列車回線は、各エンドポイントの隣接関係リストに 1 回ずつ、計 2 回保存されるため、保存される隣接関係エントリの総数は次のようになります。`2m`。 BFS は各都市を最大 1 回訪問し、保存されている各隣接エントリを最大 1 回処理します。 したがって、完全な走査は次のようになります。`O(n + m)`。 

これを実用的にするのは、都市名の圧縮に使用される辞書です。 都市名が最初に見つかったら、次に利用可能な整数を割り当てます。 以降、その名前が出現する場合はすべて、同じ頂点を参照します。 グラフ アルゴリズムは、文字列を繰り返し比較する代わりに、整数の配列とリストを操作できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、および開始都市名。 都市名を整数 ID にマッピングする辞書を作成し、グラフの隣接リストを作成します。 このステートメントでは数値の頂点ラベルではなく都市名が直接与えられるため、辞書は不足している数値表現を提供します。 
2. 各列車の路線を読みます。 両方のエンドポイント名を整数 ID に変換し、名前が初めて表示されたときに新しい ID を作成します。 トレインラインは両方向で使用できるため、各エンドポイントを他のエンドポイントの隣接リストに追加します。 
3. 開始都市名を整数 ID に変換します。 訪問済みとしてマークし、キューに入れます。 キューから削除されるまで待つのではなく、すぐにマークすると、すでに検出されているいくつかの都市がその都市を指している場合に、同じ都市が複数回挿入されるのを防ぐことができます。 
4. キューの先頭から 1 つの都市を繰り返し削除します。 隣接リスト内のすべてのネイバーを検査します。 訪問されていないすべての近隣都市について、訪問済みのマークを付け、到達可能な都市の数を増分し、それをキューに追加します。 
5. キューが空になったら停止します。 この時点では、未探索の発信接続を持つ発見された都市は存在しないため、開始都市から到達可能なすべての都市が発見されました。 訪問した都市の数を出力します。 

それが機能する理由は単純な不変条件として表現できます。BFS 操作が行われるたびに、訪問したすべての都市は最初から到達可能であり、すでに探索されたグラフの部分までの距離にある到達可能な都市はすべて発見されています。 訪問した都市が処理されるとき、すべての直接の近隣都市が考慮されます。 したがって、到達可能な都市はいずれも最終的にキューに入ります。 都市はキューに登録される前に訪問済みとしてマークされるため、すべての都市が 1 回だけカウントされます。 キューが空になると、到達可能な未検出の近隣都市は残らないため、カウントは開始都市の接続コンポーネントのサイズとまったく同じになります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    start = input().strip()

    city_id = {}
    graph = [[] for _ in range(n)]

    def get_id(name):
        if name not in city_id:
            city_id[name] = len(city_id)
        return city_id[name]

    start_id = get_id(start)

    for _ in range(m):
        a, b = input().split()

        u = get_id(a)
        v = get_id(b)

        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * len(city_id)
    visited[start_id] = True

    queue = deque([start_id])
    answer = 1

    while queue:
        u = queue.popleft()

        for v in graph[u]:
            if not visited[v]:
                visited[v] = True
                answer += 1
                queue.append(v)

    print(answer)

if __name__ == "__main__":
    solve()
```辞書`city_id`任意の都市名から連続した整数への座標圧縮を実行します。`get_id`はすべての鉄道路線の両方のエンドポイントに意図的に使用されるため、同じ名前には常に同じ頂点 ID が与えられます。 

グラフは、無向隣接リストとして構築されます。 二人`append`両方の操作が必要です。 逆エッジを省略すると、誤って列車ネットワークが有向グラフになってしまいます。 

キューには、隣接リストをまだ処理する必要がある都市が含まれています。`visited[start_id]`最初のエンキューの前に設定され、新しく検出されたすべての都市はキューに入れられる前にマークされます。 この順序により、同じ都市間のサイクルや複数のパスを含むグラフの重複が防止されます。 

答えは次から始まります`1`なぜなら、出発都市そのものに到達できるからです。 後続の各増分は、これまでに表示されなかった 1 つの都市に対応するため、最終的な値は到達可能な都市の数となります。 

Python の整数はオーバーフローせず、最大のデータ構造は都市名と鉄道の終点の数に比例します。 実装では次のことも回避できます。`list.pop(0)`、キュー操作が行われます`O(n)`。`collections.deque.popleft()`一定時間のキューの削除を提供します。 

慎重に扱う価値のある実装の詳細が 1 つあります。`n`ただし、すべてを含む別のリストは提供されません。`n`都市名。 名前は出発都市と鉄道路線の終点から検出されます。 隣接リストは最初に次のように割り当てられます。`n`スロット、一方`visited`すべての名前が見つかった後にサイズが設定されます。 入力はそれらの名前を通じてグラフを説明するため、これは安全です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n + m) | 各都市は 1 回訪問され、各無向列車路線は 2 つの隣接エントリに寄与し、1 回検査されます。 |
 | スペース | O(n + m) | ディクショナリ、訪問済み配列、キュー、および隣接リストは一緒に線形空間を使用します。 |
