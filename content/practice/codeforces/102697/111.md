 ## 解決策
 ## 問題の理解

 この問題では、2 つの逆テキスト置換のうちの 1 つを実行するように求められます。 メッセージ、単一文字キー、および単語キーが与えられます。 単一の文字がキーワード内のどこにも出現しないことが保証されます。 

メッセージによって、どの方向の置換を実行する必要があるかが決まります。 メッセージにキーワードが含まれている場合、メッセージは暗号化されたテキストとして扱われ、出現するすべてのキーワードがキー文字に置き換えられます。 それ以外の場合は、メッセージをプレーン テキストとして扱い、出現するすべてのキー文字をキーワードに置き換えます。 必要な出力は、変換されたメッセージです。 公式声明はこの規則を確認し、2 つの例を示しています`hello world -> hebruhbruho worbruhd`そしてまた戻ってきます。 

パブリッシュされたステートメントには明示的なサイズ制限がないため、結果の文字列を構築するための避けられないコストを除けば、ソリューションをメッセージの長さにおいて線形にすることが最も安全な解釈となります。 1 秒の制限と 256 MB のメモリでは、入力が大きい場合にメッセージの検索と再構築を繰り返すと不必要にコストがかかります。 Python の組み込み文字列置換操作は、この単純な置換に十分効率的に実装されており、キーワードにキー文字を含めることはできないため、重要な曖昧さの原因が除去されます。 

最初のエッジ ケースは、キーワードは含まれるが、キー文字が含まれないメッセージです。 例えば：```
bruh
l
bruh
```メッセージには次の内容が含まれます`bruh`, したがって、これは復号化操作です。 正しい出力は次のとおりです。```
l
```キー文字が出現するかどうかのみをチェックする不用意な解決策は、誤って暗号化を試行する可能性があります。 

2 番目のエッジ ケースは、キーワードもキー文字も含まないメッセージです。 例えば：```
hello
l
xyz
```以来`xyz`発生しない場合、操作は暗号化です。 唯一の`l`は置き換えられ、次のようになります。```
hexyz
```キーワードが存在しないという事実が方向性を決定するものであり、実際に置き換えられるかどうかではありません。 

3 番目のエッジ ケースは、複数の隣接する発生です。 例えば：```
ll
l
ab
```メッセージには次の内容が含まれていません`ab`したがって、両方の出現が`l`交換する必要があります。 結果は次のとおりです。```
abab
```最初に出現したものだけを置き換えると、暗黙のうちに間違った答えが得られます。 

## アプローチ

 直接的な総当たりアプローチは、暗号化または復号化が必要な場合は常にメッセージを 1 文字ずつスキャンし、キーワードを手動で検索することです。 これは正しいです。すべての置換は、選択された方向と現在の部分文字列によって完全に決定されるからです。 ただし、キーワードに長さがある場合は、`k`そしてメッセージには長さがある`n`、考えられるすべての開始位置を文字ごとにチェックする必要がある場合があります`O(nk)`比較。 最悪の場合、長いメッセージの大部分が繰り返しの文字と同様に長いキーワードで構成されている場合、これは次のような問題につながる可能性があります。`O(n^2)`操作。 

問題の構造により、パターン マッチングを自分たちで実装する必要がなくなります。 1 つの固定部分文字列の出現をすべて別の固定文字列に置き換えるだけで済みます。 Python はすでにこの操作を正確に提供しています。`str.replace`。 

ブルート フォース ソリューションは、各出現を独立して処理できるため機能しますが、置換ターゲットがメッセージ全体で固定されているという事実を利用できません。 キーワードが出現するかどうかを確認して方向を決定すると、変換全体は 1 回の呼び出しに減ります。`replace`。 

キーワードにキー文字が含まれていないことを保証することも有用です。 暗号化中に、文字をキーワードに置き換えても、挿入された単語内にキー文字が再度出現することはありません。 復号化中に、キーワードをキー文字に置き換えても、キーワードの別のコピーを作成することはできません。 したがって、再帰的にさらに置換がトリガーされる置換を心配することなく、変換を 1 回のパスで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 大きな文字列には遅すぎる |
 | 最適 | O(n + 出力) | O(n + 出力) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 内部スペースを削除せずにメッセージ全体を読みます。 メッセージはテキスト行なので、次のように使用します。`strip()`は不要であり、意味のある先頭または末尾のスペースを誤って変更する可能性があります。 
2. キー文字とキーワードを読み、これら 2 行から改行だけを削除します。 これらは個別の入力値であり、スペースは含まれません。 
3. キーワードがメッセージ内のどこかに出現するかどうかを確認します。 暗号化されている場合、メッセージは暗号化されていると見なされ、復号化する必要があります。 
4. 復号化の場合、出現するすべてのキーワードをキー文字に置き換えます。 電話をかける`replace`カウントを指定しないと、すべての出現箇所が置き換えられます。これはまさに問題が必要とするものです。 
5. キーワードが出現しない場合、メッセージは平文とみなされ、暗号化する必要があります。 出現するすべてのキー文字をキーワードに置き換えます。 
6. 結果のメッセージを、生成されたとおりに正確に出力します。 スペースとその他すべての文字は変更されません。 

正しさはステートメント内の決定ルールから導き出されます。 アルゴリズムは、まずキーワードが出現したときに正確に復号化を選択し、それ以外の場合は暗号化を選択します。 復号化分岐では、出現するすべてのキーワードがキー文字に置き換えられます。これはまさに指定された逆演算です。 暗号化ブランチでは、キー文字が出現するたびにキーワードに置き換えられます。 キー文字はキーワード内に出現しないため、挿入されたキーワードによって、さらに置換が必要となる別のキー文字が誤って導入されることはありません。 したがって、結果として得られるメッセージは、まさに必要な変換となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

message = input().rstrip('\n')
key_letter = input().rstrip('\n')
key_word = input().rstrip('\n')

if key_word in message:
    answer = message.replace(key_word, key_letter)
else:
    answer = message.replace(key_letter, key_word)

print(answer)
```最初`input`スペースを含む完全なメッセージを読み取ります。 使用する`rstrip('\n')`行終端文字のみを削除するため、実際のメッセージは保持されます。 

次の 2 つの読み取りにより、キー文字とキーワードが取得されます。 これらの値は独自の行を占めるため、改行を削除するだけで十分です。 

会員テストは`key_word in message`操作が暗号化であるか復号化であるかを決定する正確なルールを実装します。 復号ブランチを選択するには 1 回の出現で十分であるため、出現回数をカウントする必要はありません。 

への呼び出し`replace` deliberately omit the optional count argument. A limited replacement such as `replace(old, new, 1)`最初の出現のみを変更し、同じキーが複数回出現すると失敗します。 

ここでは Python の整数は関係ないため、オーバーフローの心配はありません。 また、組み込みの部分文字列置換によって内部的に処理されるため、インデックス作成の境界を管理する必要もありません。 

## 実用的な例

 ### サンプル 1

 最初のサンプルのメッセージは次のとおりです。`hello world`、キー文字は`l`、そしてキーワードは`bruh`。 

| メッセージ | キーレター | キーワード | キーワードプレゼント? | 操作 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 |`hello world`|`l`|`bruh`| いいえ |`l -> bruh`|`hebruhbruho worbruhd`|

 言葉`bruh`が存在しないため、アルゴリズムは暗号化を選択します。 両方の発生`l`独立して交換されます。 最初`l`で`hello`になる`bruh`、そして2番目`l`別のものになる`bruh`。 

### サンプル 2

 2 番目のサンプルのメッセージは次のとおりです。`hebruhbruho worbruhd`、同じキーで。 

| メッセージ | キーレター | キーワード | キーワードプレゼント? | 操作 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 |`hebruhbruho worbruhd`|`l`|`bruh`| はい |`bruh -> l`|`hello world`|

 今回はキーワードが複数回出現するため、アルゴリズムは復号化を選択します。 毎`bruh`に変換されて戻されます`l`、元のメッセージを再構築します。 

2 つの例は共に、中心の不変条件を示しています。つまり、キーワードの存在によって逆の操作が選択され、すべての出現がその方向に変換されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + 出力) | メッセージをスキャンしてキーワードを見つけ、処理して置換文字列を構築します。 |
 | スペース | O(n + 出力) | Python は入力メッセージと結果の文字列を保存します。 |

 ここ`n`メッセージの長さです。 公開された問題には、1 秒の時間制限と 256 MB のメモリ制限があります。 このソリューションは、一定数の文字列操作のみを実行し、明示的な 2 次部分文字列検索を回避するため、意図した制約に容易に適合します。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    message = input().rstrip('\n')
    key_letter = input().rstrip('\n')
    key_word = input().rstrip('\n')

    if key_word in message:
        return message.replace(key_word, key_letter)
    return message.replace(key_letter, key_word)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + '\n'
    finally:
        sys.stdin = old_stdin

# Provided sample 1
assert run("hello world\nl\nbruh\n") == "hebruhbruho worbruhd\n"

# Provided sample 2
assert run("hebruhbruho worbruhd\nl\nbruh\n") == "hello world\n"

# Minimum-size message
assert run("a\na\nb\n") == "b\n"

# Key word occurs repeatedly and adjacently
assert run("abab\nx\nab\n") == "xx\n"

# Message contains neither key word nor key letter
assert run("hello\nx\nxyz\n") == "hello\n"

# Multiple key-letter occurrences
assert run("aaaa\na\nlong\n") == "longlonglonglong\n"

# Large message
large = "a" * 10000
assert run(large + "\na\nxyz\n") == ("xyz" * 10000) + "\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a / a / b`|`b`| 最小サイズの入力と 1 つの置換 |
 |`abab / x / ab`|`xx`| 複数の隣接するキーワードの出現 |
 |`hello / x / xyz`|`hello`| どちらのキーも表示されないため、暗号化によって何も変更されません。 
|`aaaa / a / long`|`longlonglonglong`| すべての出現箇所を置き換える必要があります。 
|`a...a / a / xyz`| 繰り返し`xyz`| 大入力と線形処理 |

 ## 特殊なケース

 最初のエッジ ケースは、メッセージ自体がまさにキーワードである場合です。```
bruh
l
bruh
```メンバーシップ テストはすぐに成功します。 アルゴリズムは復号化ブランチを取得し、以下を評価します。`bruh.replace(bruh, l)`、生産:```
l
```完全一致に特別なケースは必要ありません。 

2 番目のエッジ ケースは、キーワードが存在せず、キー文字も存在しない場合です。```
hello
x
xyz
```テスト`xyz in hello`false であるため、アルゴリズムは暗号化を選択します。 以来`x`発生しない、`hello.replace(x, xyz)`メッセージは変更されないままになります。```
hello
```この問題ではキーワードの欠如のみから暗号化が選択されるため、これは正しいです。 

3 番目のエッジ ケースには、隣接するオカレンスが含まれます。```
abab
x
ab
```キーワード`ab`位置 0 と位置 2 から始まる 2 回発生します。 復号化操作により、両方の出現が同時に置き換えられ、次のようになります。```
xx
```一致を見つけた後に文字ごとに実装を進めすぎると、誤って 2 番目の出現をスキップする可能性があります。`str.replace`インデックス作成エラーを回避します。 

4 番目のエッジ ケースには、重要な文字が繰り返されています。```
aaaa
a
long
```キーワード`long`がないため、暗号化が選択されます。 ４人それぞれが`a`文字が置き換えられ、次の結果が得られます。```
longlonglonglong
```キーワードに含まれないもの`a`、ステートメントで保証されているため、新たに挿入されることはありません`a`文字が表示されるため、変換を繰り返す必要はありません。
