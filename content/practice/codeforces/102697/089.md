 ## 解決策
 ## 問題の理解

 この問題は、模型飛行機の輪ゴムを巻くプロセスをモデル化しています。 クランクワインダーを 1 回転させると、一定数の輪ゴムが巻かれます。 最初の入力値 (n) は必要な風の合計数であり、2 番目の値 (m) はワインダーの 1 回転で生成される風の数を示します。 正確に (n) 回の風に達するために、ワインダーを何回転する必要があるかを決定する必要があります。 このステートメントは、この数値が整数であることを保証します。 

数学的には、回転するたびに (m) 個の風が発生し、(w) 回転すると、輪ゴムは (w \cdot m) 個の風を受けます。 必要です

 [
 w \cdot m = n、
 】

 したがって、必要なターン数は単純に

 [
 w = \frac{n}{m}。 
】

 公式の制限では、1 秒の時間制限と 256 MB のメモリが与えられていますが、入力値自体は、割り算条件を持つ正の整数としてのみ記述されます。 タスク全体が 1 つの算術演算に削減されるため、非常に大きな整数値であってもアルゴリズムの問​​題は発生しません。 Python における唯一の実際的な考慮事項は、答えが正確な整数であることが保証されているため、入力を浮動小数点値ではなく整数として解析する必要があることです。 

確認する価値のある 2 つの小さなエッジケースがあります。 まず、答えは 1 つだけです。 例えば、```
64
64
```ちょうど 1 回転が必要なので、出力は次のようになります。```
1
```誤って少なくとも 2 ターンを想定した実装は、ここで失敗します。 

第 2 に、必要なターン数が 1 よりもはるかに大きくなる可能性があります。 例えば、```
100
1
```100 回転が必要なため、出力は次のようになります。```
100
```除算を逆にして (m/n) を計算する解決策では、必要な巻き数ではなく 1 より小さい値が生成されます。 サンプル`2250 15`同様に 150 ターンを与え、必要な量が総風量を 1 ターンごとに生成される風で割ったものであることを確認します。 

## アプローチ

 直接シミュレーションでは、風がゼロの状態で開始し、合計が (n) に達するまで、ワインダーを繰り返し回転させ、回転するたびに (m) 個の風を追加します。 入力では (n) が (m) で割り切れることが保証されているため、このプロセスは最終的に (n) で正確に停止するため、これは正しいことになります。 ただし、(n/m=k) の場合、シミュレーションは正確に (k) 回反復実行されます。 最悪の場合、(m=1) では、(n) 回の反復が実行されます。 このステートメントは (n) に小さな上限を与えていないため、これは不必要な作業であり、十分に大きな入力に対しては遅くなりすぎる可能性があります。 

重要な観察は、各ターンがまったく同じ量を寄与するため、シミュレートする変化する状態がないということです。 (k) ターンが (n) 個の風を生み出す場合、(k m=n) となります。 この方程式を解くと、(k=n/m) が直接得られます。 ブルートフォース手法は同じ加算を繰り返し実行するため機能しますが、最適手法はすべての同一の加算を 1 つの除算に置き換えます。 

したがって、2 つのアプローチは次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n / m)、最悪の場合 O(n) | お(1) | 不必要に大きな入力に対して遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) を読み取り、必要な風の合計数を読み取ります。 
2. ワインダーの 1 回転によって生成される巻き数 (m) を読み取ります。 
3. コンピューティング`n // m`。 割り算の保証は余りがないことを意味するため、整数の割り算では近似値ではなく正確なターン数が得られます。 
4. 結果を印刷します。 

### なぜ効果があるのか

 ワインダーを (w) 回回転させるとします。 各ターンは正確に (m) 個の風をもたらすため、風の総数は (w m) になります。 この合計が (n) に等しく、(w m=n) になる必要があります。 (m>0) なので、両辺を (m) で割ると、(w=n/m) が得られます。 入力により、この商が整数であることが保証されるため、アルゴリズムは必要なターン数を正確に出力します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
m = int(input())

print(n // m)
```最初の 2 行は、標準入力から 2 つの正の整数を直接読み取ります。 使用する`int`計算を正確に保ちます。必要な答えが整数であるため、浮動小数点除算よりも適しています。 

表現`n // m`整数の除算を実行します。 この問題では、要求された風の数が 1 回転で生成される風の数で割り切れることが保証されているため、これは正確に数学的な商です。 使用する`/`次のような浮動小数点値を作成します`150.0`、元のチェッカーもステートメントに従って受け入れることができますが、整数除算は必要な結果をより正確に表現します。 

ループ、配列、再帰、または補助データ構造はありません。 入力の順序も重要です。`n`は希望する風の合計数です。`m`は 1 回転で発生する風の数なので、除算は次のようになります。`n // m`、 ない`m // n`。

| 変数 | 値 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 2 つの整数のみが読み取られ、1 つの除算が実行されます。 
| スペース | お(1) | 2 つの入力整数と結果のみが保存されます。 

このソリューションは、実行時間と補助メモリが入力値の大きさに依存しないため、1 秒の時間制限と 256 MB のメモリ制限に簡単に適合します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()

        input = sys.stdin.readline

        n = int(input())
        m = int(input())
        print(n // m)

        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("2250\n15\n") == "150\n", "sample 1"
assert run("64\n4\n") == "16\n", "sample 2"

# custom cases
assert run("1\n1\n") == "1\n", "minimum-size values"
assert run("100\n1\n") == "100\n", "one wind per turn"
assert run("1000000000\n1000\n") == "1000000\n", "large values"
assert run("72\n8\n") == "9\n", "exact division boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`1`| 最小の正の値と 1 ターンの場合 |
 |`100 / 1`|`100`| 商が大きく、加算を繰り返すアプローチの最悪のケース |
 |`1000000000 / 1000`|`1000000`| 浮動小数点演算を行わない大きな整数値 |

 ## 特殊なケース

 1 ターンの場合は次のように考えます。```
64
64
```アルゴリズムは計算します`64 // 64 = 1`そしてプリント`1`。 これは、必要な巻き線全体を 1 回の巻きで完了できるため機能します。 シミュレーションも機能しますが、商がすでに直接利用可能な場合には反復を実行する理由はありません。 

1 ターンあたり 1 ワインドの場合は、次のように考えます。```
100
1
```アルゴリズムは計算します`100 // 1 = 100`そしてプリント`100`。 ここで、加算を繰り返すソリューションには 100 回の反復が必要ですが、最適なソリューションでは 1 回の算術演算が実行されます。 これは、(m) を 1 まで小さくできる場合のシミュレーションで考えられる最悪のケースでもあります。 

大きな価値の場合は、次のことを考慮してください。```
1000000000
1000
```アルゴリズムは計算します

 [
 1000000000 / 1000 = 1000000
 】

 そして次のように出力します:```
1000000
```Python の整数には任意の精度があり、浮動小数点変換が含まれないため、計算は正確なままです。 

最後に、入力の順序は次のようにして確認できます。```
72
8
```正しい結果は`9`, 各ターンで 8 つの風が発生し、9 ターンで (9 \times 8=72) が与えられるためです。 オペランドを逆にすることは論理的に正しくないため、このケースでは、必要な合計とターンごとのレートを混同する実装が検出されます。
