 ## 解決策
 ## 問題の理解

 このタスクは、leet speech の基本的な形式に 1 文字ずつ翻訳することです。 入力は、任意のテキストを含む 1 つの文字列です。 リート置換が指定された小文字ごとに、対応する数字に置き換えます。 スペース、句読点、数字、変換テーブルに存在しない文字など、他のすべての文字は変更されません。 

必要な変換は次のとおりです。`a -> 4`、`b -> 8`、`e -> 3`、`i -> 1`、`l -> 1`、`o -> 0`、`s -> 5`、`t -> 7`、 そして`z -> 2`。 たとえば、この言葉は、`test`になる`7357`、 なぜなら`t`、`e`、`s`、 そして`t`独自に翻訳されています。 

入力には単一の文字列が含まれるため、テストケースのカウントはなく、完全な 1 行を読み取る以上の解析は必要ありません。 公式問題では制限時間は 1 秒、メモリは 256 MB です。 入力は長さの文字列として扱うことができるため、`n`、`O(n)`解決策が自然な目標です。 ステートメントに有用な明示的な最大長がない場合でも、すべての文字が出力に影響を与える可能性があるため、各文字を 1 回読み取って処理することが最適です。 

実装が静かに失敗する可能性がある小さなケースがいくつかあります。 インプットを考慮する`a`。 正しい出力は次のとおりです`4`。 サンプル文に出現する文字のみを処理する実装では、誤って変更されないままになる可能性があります。 

入力用`all`、正しい出力は次のとおりです。`411`。 両方の発生`l`にならなければなりません`1`、そして 2 つの置換は独立して行われます。 

入力用`hello!`、正しい出力は次のとおりです。`h3110!`。 感嘆符は変更されずに存続する必要があります。 元の文字を処理するのではなく単語を再構築する不注意な実装では、誤ってスペースや句読点が失われる可能性があります。 

入力用`123`、正しい出力は次のとおりです。`123`。 既存の数字は再度変換されません。 特に、`1`入力の内容はルールに関係ありません`i -> 1`、ルールは文字に適用されるため、`i`、数字ではありません`1`。 

## アプローチ

 直接のブルートフォース実装では、すべての入力文字を検査し、一致する文字が見つかるまで、文字ごとに 9 つのソース文字すべてと比較できます。 これは正しいです。すべての文字が完全な変換テーブルに対してテストされ、一致しない文字は変更されずにコピーされるからです。 最悪の場合、入力に長さがある場合、`n`、これは最大で実行されます`9n`キャラクターの比較。 のために`n = 100000`これは最大 900,000 件の比較であり、ここでも問題なく通過できますが、繰り返しの検索は不要です。 

重要な点は、変換ルールが 1 つの文字から 1 つの文字への固定マッピングであるということです。 隣接する文字間に依存関係はなく、以前の入力を記憶する必要も、文字列の長さを変更する変換も必要ありません。 9 つの置換を辞書に保存し、平均を実行できます。`O(1)`各入力文字を検索します。 

変換テーブルは小さいため、総当たり攻撃は機能しますが、決して変更されない情報を繰り返し検索します。 すべての文字に独立した固定置換があるという観察により、各文字の作業を 1 回の辞書検索に減らすことができます。 したがって、完全な変換は入力長に対して線形になります。

 ## アルゴリズムのチュートリアル

 1. 内部スペースを削除せずに、入力行全体を読み取ります。 標準入力によって追加された改行は削除する必要がありますが、テキスト内のスペースは文字列の一部であり、出力に残さなければなりません。 
2. 指定された 9 つの文字から数字への変換を含むマッピングを作成します。 現在の入力文字が検索キーを直接識別するため、辞書は自然な表現です。 
3. 入力文字列内のすべての文字を 1 回だけ訪問します。 文字がマッピングに存在する場合は、その文字の置換を出力に追加します。 それ以外の場合は、元の文字を追加します。 
4. 構築された出力文字列を出力します。 すべての入力文字は 1 つの出力文字に寄与するため、出力は入力と同じ長さになります。 

### なぜ効果があるのか

 不変条件は、最初の処理後の`k`入力文字を入力すると、出力には同じ文字の正確なリート翻訳が含まれます。`k`文字。 最初は文字が処理されていないため、不変条件は自明に成り立ちます。 次の文字を処理するとき、アルゴリズムは、指定された置換が存在する場合はそれを使用し、存在しない場合は文字を変更せずにコピーします。これはまさに必要な変換ルールです。 したがって、不変条件はすべての文字の後でも true のままであり、最後の文字以降の完全な出力は正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    mapping = {
        'a': '4',
        'b': '8',
        'e': '3',
        'i': '1',
        'l': '1',
        'o': '0',
        's': '5',
        't': '7',
        'z': '2',
    }

    result = ''.join(mapping.get(ch, ch) for ch in s)
    print(result)

if __name__ == "__main__":
    solve()
```の最初の行`solve`文全体を読みます。 使用する`rstrip('\n')`を呼び出すのではなく、行終端記号のみを削除します。`strip()`これにより、入力の先頭または末尾から意味のある空白が削除される可能性があります。 

辞書には、問題に含まれる 9 つのルールが正確に含まれています。 の`get`call は、文字が 9 つのキーのいずれでもない場合に、元の文字をデフォルトとして提供するため便利です。 

ジェネレーターは文字を左から右に処理し、入力文字ごとに 1 つの出力文字を生成します。`''.join(...)`ループ内で文字列を繰り返し連結するのではなく、それらを最終的な文字列に効率的に結合します。 

インデックスの計算や明示的な境界がないため、オフバイワンの問題は発生しません。 Python の整数は、置換が数値演算ではなく文字として処理されるため、計算には無関係です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().rstrip('\n')

    mapping = {
        'a': '4',
        'b': '8',
        'e': '3',
        'i': '1',
        'l': '1',
        'o': '0',
        's': '5',
        't': '7',
        'z': '2',
    }

    return ''.join(mapping.get(ch, ch) for ch in s)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve() + '\n'
    finally:
        sys.stdin = old_stdin

# Provided sample
assert run("this is a test input\n") == "7h15 15 4 7357 1npu7\n", "sample 1"

# Minimum-size input
assert run("a\n") == "4\n", "single replaceable character"

# All characters that have replacements
assert run("abeilos tz\n") == "4831105 72\n", "all mappings"

# Characters that must remain unchanged
assert run("123! XYZ\n") == "123! XYZ\n", "non-mapped characters"

# Repeated mappings and punctuation
assert run("all!!!\n") == "411!!!\n", "repeated l and punctuation"

# Large input
large_input = "a" * 100000 + "\n"
assert run(large_input) == "4" * 100000 + "\n", "large input"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`a`|`4`| 最小サイズの入力と直接置換 |
 |`abeilos tz`|`4831105 72`| すべての置換ルールとスペースの保存 |
 |`123! XYZ`|`123! XYZ`| 数字、句読点、およびマップされていない文字は変更されません。 
|`all!!!`|`411!!!`| 繰り返される置換と末尾の句読点 |
 | 100000部`a`| 100000部`4`| 大きな入力に対する線形処理 |

 ## 特殊なケース

 次のような単一文字入力の場合`a`、アルゴリズムは 1 回の辞書検索を実行し、`4`、生成します`4`。 長さ 1 には特別な処理はありません。これは、一般的なループがすでに最小のケースを正しくカバーしていることを意味するため、便利です。 

繰り返し交換する場合は、次の点を考慮してください。`all`。 最初`a`になる`4`、そして両方`l`キャラクターが独立してなる`1`、与える`411`。 このアルゴリズムでは、連続する等しい文字を 1 つの単位として扱うことはないため、出現が失われることはありません。 

マッピング外の文字については、次の点を考慮してください。`123!`。 これらの文字はどれも辞書キーではないため、すべての検索は元の文字に戻ります。 結果は残る`123!`。 これにより、次のような既存の数字も使用できなくなります。`1`別のルールが偶然その数字を生成するために、誤って変換されないようにします。`1`。 

空白と句読点については、次の点を考慮してください。`hello! world`。 文字は翻訳され、スペースと感嘆符がコピーされます。 の使用`rstrip('\n')`それよりも`strip()`実際のテキストの内容が保持され、文字ごとの変換によって入力の途中にある空白が変更されることはありません。 

入力が大きい場合でも、アルゴリズムは 1 文字につき 1 回の翻訳試行を実行します。 100000の文字列`a`したがって、文字は 100,000 回の辞書検索を必要とし、100,000 個の辞書検索が生成されます。`4`ネストされた検索や文字列の再構築を繰り返すことはありません。
