 ## 解決策
 ## 問題の理解

 入力は、サッカーの試合の集合の結果を記述します。 各試合には 2 つのチーム名と結果の文字が含まれます。 あ`W`最初のチームが勝ったことを意味しますが、`T`チームが引き分けたことを意味します。 勝利すると最初のチームに3ポイント、負けたチームには0ポイントが与えられ、引き分けの場合は両チームに1ポイントが与えられます。 このタスクは、各チームの合計ポイントを計算し、最高スコアから最低スコアまですべてのチームを出力することです。 同スコアのチームはアルファベット順に並べられます。 公式声明では、同じ採点ルールと順序付け要件が示されています。 

チームは名前だけで識別できるため、辞書は現在のスコアを保存するための自然なデータ構造です。 すべての試合は 2 つのエントリーに影響を与え、チームは試合に初めて登場するときにのみ作成する必要があります。 すべての一致が処理された後、最大でも`2n`異なるチームの出現のため、異なるチームの数も最大で`2n`。 

この声明では明示的な上限は公表されていない。`n`現在の Codeforces ページにあります。 制限時間は 1 秒、メモリ制限は 256 MB です。 これにより、アルゴリズムは試合数が線形になり、その後に 1 種類の異なるチーム、つまり適切なターゲットが続きます。 すべての試合をチームごとに個別にスキャンするアプローチでは二次作業が必要になる可能性があり、試合数が増えるにつれて問題が発生します。 

最初のエッジケースは単一の一致です。 のために```
1
A B W
```正しい出力は```
A 3
B 0
```ポイントを付与したチームだけを記録するという不注意な実装は忘れてしまう可能性があります`B`、負けたチームは 0 ポイントを受け取りますが、それでも出力に表示される必要があるためです。 

2 番目のエッジケースは引き分けです。```
1
A B T
```正しい出力は次のとおりです```
A 1
B 1
```治療するソリューション`T`最初のチームの勝利は不正確な結果をもたらすため、`A`3つのポイントと`B`ゼロ。 

3 番目のエッジケースは、最終順位が同点です。 のために```
2
Bob Alice T
Charlie Alice T
```スコアは`Alice = 2`、`Bob = 1`、 そして`Charlie = 1`したがって、出力は次のようになります```
Alice 2
Bob 1
Charlie 1
```同スコアのチームは、入力順ではなくアルファベット順に並べる必要があります。 この場合、スコアのみを使用する並べ替えキーは失敗します。 

## アプローチ

 直接的な総当たりソリューションでは、最初にチーム名を収集し、次にすべてのチームについてすべての試合をスキャンして、そのチームが獲得したポイント数を判断できます。 これは正しいです。各チームの合計を計算するときにすべての試合が検査されるため、結果が見逃されることはありません。 あれば`m`個性的なチームと`n`ただし、ゲームではこのパフォーマンスは`m * n`ゲームチェック。 以来`m`と同じ大きさにすることができます`2n`、最悪の場合は約`2n²`小切手。 その後、チームを分類する必要があります。 

1 つのチームの得点ルールはすべての試合を検査することで独立して決定できるため、強引な方法が機能します。 問題は、同じ試合が異なるチームで何度も検査されることです。 重要な観察は、各試合で 2 人の参加者のスコアがどのように変化するかをすでに正確に示しているということです。 これらの更新を延期して、後で試合をスキャンする理由はありません。 

各ゲームを 1 回だけ処理できます。 結果が`W`、最初のチームのスコアに 3 を追加し、2 番目のチームのスコアは変更しません。 結果が`T`、両チームに 1 を加えます。 最後に、辞書エントリをスコアの降順、次にチーム名の昇順で並べ替えることで、必要なランキングが正確に生成されます。 

唯一の非線形部分は、最終的な並べ替えです。 もし`m`チームが現れるとコストがかかる`O(m log m)`、すべてのゲームコストを処理しながら`O(n)`。 以来`m <= 2n`、合計は`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(mn + m log m)、最悪の場合 O(n²) | O(m) | 大量の入力には遅すぎる |
 | 最適 | O(n + m log m)、したがって O(n log n) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の辞書を作成する`score`。 そのキーはチーム名で、その値はそのチームの現在のポイント数です。 試合に参加するすべてのチームが最終順位に属するため、最初の結果が負けの場合でもチームを挿入する必要があります。 
2. 各一致を次のように読み取ります。`team1`、`team2`、 そして`result`。 両方のチームが以前に登場したことがない場合は、辞書内の両方のチームをスコア 0 で初期化します。 
3. 結果が次の場合`W`に 3 点を追加します。`team1`。 2 番目のチームはポイントを獲得しませんが、その辞書エントリはそのまま残ります。 
4. 結果が次の場合`T`、両チームに1点を追加します。 入力仕様に従って他に考えられる結果はありません。 
5. 辞書を次のペアに変換します。`(team, score)`キーを使用して並べ替えます`(-score, team)`。 スコアを無効にすると、数値の降順になりますが、チーム名は通常のアルファベット順のままです。 
6. ソートされたすべてのペアを次のように出力します。`team score`。 出力行の数は、ゲームに登場した個別のチームの数とまったく同じです。 

### なぜ効果があるのか

 入力の接頭辞を処理した後、辞書に保存されているすべてのチームには、それまでに処理された試合で獲得したポイントが正確に含まれることが不変になります。 あ`W`ルールで規定されている 3 ポイントだけ勝者を更新します。`T`両方の参加者をちょうど 1 ポイント更新します。 すべての試合は 1 回処理されるため、最終試合後のすべてのディクショナリ値はチームの完全なトーナメント スコアになります。 最終的な並べ替えキーは、これらの完全なスコアを最大から最小の順に並べ、等しいスコアをアルファベット順に分割するため、印刷されるすべての行が必要なランキングを満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    score = {}

    for _ in range(n):
        team1, team2, result = input().split()

        if team1 not in score:
            score[team1] = 0
        if team2 not in score:
            score[team2] = 0

        if result == "W":
            score[team1] += 3
        else:
            score[team1] += 1
            score[team2] += 1

    teams = sorted(score.items(), key=lambda item: (-item[1], item[0]))

    sys.stdout.write(
        "\n".join(f"{team} {points}" for team, points in teams)
    )

if __name__ == "__main__":
    solve()
```辞書は実装の中心部分です。`score[team]`には常に、そのチームがこれまでに蓄積したポイントが含まれており、アルゴリズムのウォークスルーの不変条件と一致します。 

結果を調べる前に、両方のチームが初期化されます。 負けたチームは 0 ポイントを受け取りますが、それでも印刷する必要があるため、これは負けの場合に必要です。 両側を初期化すると、描画ケースも簡単になります。 

のために`W`、 のみ`team1`最初にリストされているチームが勝者であることがステートメントによって保証されているため、ポイントが付与されます。 のために`T`、両チームとも 1 ポイントを獲得します。 必要はありません`L`分岐するので`L`入力では発生しません。 

ソート式は次を使用します`(-item[1], item[0])`。 2 つのチームのスコアが 7 と 4 の場合、キーは次で始まります。`-7`そして`-4`, したがって、7が最初になります。 2 つのチームが両方とも 4 を持っている場合、最初のキー コンポーネントは等しいため、Python は 2 番目のコンポーネント (チーム名) をアルファベット順に比較します。 

Python の整数はオーバーフローしないため、ゲーム数が多い場合でもスコア値を特別に処理する必要はありません。 出力は次のように構築されます`join`、個々のチームごとに不必要なフラッシュまたは書き込み操作を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m log m) | それぞれの`n`ゲームは一度処理され、その後`m`異なるチームが並べ替えられます |
 | スペース | O(m) | ディクショナリとソートされたチーム リストには、個別のチームごとに 1 つのエントリが保存されます。 

ここ`m`は個別のチームの数であり、`m <= 2n`すべてのゲームには 2 つのチームが含まれるためです。 したがって、合計時間は`O(n log n)`ゲーム数の点では、リニアメモリを使用します。 これは、1 秒の制限内ですべてのチームのすべてのゲームを繰り返しスキャンするよりも快適です。

 ## 特殊なケース

 単一一致の場合```
1
A B W
```結果が処理される前に、両方のチームが挿入されます。 スコアはこうなります`A = 3`そして`B = 0`。 仕分け場所`A`まず与えること```
A 3
B 0
```重要な詳細は、`B`スコアが増加しない場合でも作成されます。 

引き分けの場合```
1
A B T
```辞書は次のように始まります`{A: 0, B: 0}`。 の`T`ブランチは両方のエントリをインクリメントし、`{A: 1, B: 1}`。 出力は```
A 1
B 1
```両方の参加者を更新する以外に、抽選に必要な特別なケースはありません。 

最終スコアが等しい場合、```
2
Bob Alice T
Charlie Alice T
```最初の試合では`Bob = 1`そして`Alice = 1`。 2番目は与えます`Charlie = 1`そして`Alice = 2`。 最終的な値は次のとおりです。`Alice = 2`、`Bob = 1`、 そして`Charlie = 1`。 ボブとチャーリーの並べ替えキーは次のとおりです。`(-1, "Bob")`そして`(-1, "Charlie")`、結果は次のようになります```
Alice 2
Bob 1
Charlie 1
```入力順序は、同じスコアを持つチーム間の最終的な順序には影響しません。 

繰り返しのゲームの場合、```
4
Zed Amy T
Amy Bob W
Bob Zed T
Zed Amy W
```スコアは次のように進化します`Zed = 1, Amy = 1`、 それから`Amy = 4, Bob = 0`、 それから`Bob = 1, Zed = 2`、そして最後に`Zed = 5, Amy = 4`。 したがって、出力は次のようになります```
Zed 5
Amy 4
Bob 1
```チームが出現するたびに同じ辞書エントリに寄与するため、2 つのチームが最大 1 回対戦するという想定はありません。 

最後に、毎試合負けるチームが消滅してはなりません。 で```
2
A B W
C B W
```アップデートによって生成される`A = 3`、`C = 3`、 そして`B = 0`。 以来`B`最初の一致が読み取られたときに挿入され、辞書に残り、最後に出力されます。```
A 3
C 3
B 0
```これは、完全な順位決定ソリューションと、ポイントを獲得したチームのみを追跡するソリューションを区別する主な実装の詳細です。
