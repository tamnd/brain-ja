 ## 解決策
 ## 問題の理解

 文字列内のすべての文字が次のいずれかである場合、その文字列は退屈と呼ばれます。`a`または`b`。 空ではない文字列が 1 つ与えられた場合、それがそのルールを満たすかどうかを判断する必要があります。 出力は`YES`他の文字が出現しない場合、および`NO`少なくとも 1 文字が外に出るとすぐに`a`そして`b`が表示されます。 元の問題には 1 秒の時間制限と 256 MB のメモリ制限があります。 

制約に関する重要な観察点は、このタスクでは 1 つの文字列の文字を検査することだけが要求されるということです。 文字列が非常に長い場合でも、すべての文字を 1 回処理するアルゴリズムは長さが線形であり、1 秒の制限に十分適しています。 補助構造を構築したり、位置のすべてのペアを比較したりする理由はありません。 二次アルゴリズムでは、最悪の場合、おおよそ (n^2/2) 個の文字チェックが実行されますが、文字列が大きくなるとすぐに実用的ではなくなります。 

一般的に間違いを引き起こす小さなケースがいくつかあります。 たとえば、入力```
a
```生産しなければならない```
YES
```唯一の文字が許可されているためです。 誤って両方を必要とするソリューション`a`そして`b`発生すると、誤って拒否されてしまいます。 

入力```
baaaaabba
```生産しなければならない```
YES
```繰り返される文字やその順序は`a`そして`b`許可されています。 条件はどの文字が出現するかに関するものであり、その配置に関するものではありません。 これも正式な例の 1 つです。 

入力```
baaaaabad
```生産しなければならない```
NO
```決勝だから`d`それ以前の文字はすべて有効であっても、禁止されています。 文字列の先頭のみをチェックする不注意な実装では、この違反を見逃す可能性があります。 

ついに、```
ccabbabbdd
```生産しなければならない```
NO
```なぜなら両方とも`c`そして`d`許可されているアルファベットの範囲外です。 文字列全体を拒否するには、無効な文字を 1 つだけ必要とします。 

## アプローチ

 簡単な総当たり解釈では、より大きなプレフィックスを繰り返し検証します。 最初の文字から始めて、そのプレフィックスに次の文字が含まれているかどうかを確認します。`a`そして`b`、次に最初の 2 文字をチェックし、次に最初の 3 文字をチェックするというように、文字列全体がチェックされるまで続けます。 これは正しいです。接頭辞のすべてが退屈であれば、文字列全体も退屈になるからです。 ただし、プレフィックスを最初からチェックすると、これまでのほぼすべての作業が繰り返されます。 長さ (n) の文字列の場合、文字検査の合計数は次のようになります。 

[
 1 + 2 + 3 + \dots + n = \frac{n(n+1)}2、
 】

 つまり (O(n^2)) です。 (n=10^5) の場合、これは約 (5\times10^9) 個の文字検査に相当し、1 秒の制限でサポートできる量をはるかに超えています。 

この繰り返しを取り除く観察ははるかに単純です。プロパティは各文字に対してローカルです。 すでにチェックされている文字を再度確認する必要はありません。 左から右にスキャンしているときに、現在の文字が`a`または`b`、文字列を無効にすることはできないので、続行します。 それ以外の場合、答えはすでにわかっています。`NO`、スキャンはすぐに停止できます。 

これにより、繰り返されるプレフィックス検証が 1 つの線形パスに変わります。 ブルートフォース手法は、最終的にすべての文字を検査するため機能しますが、同じ文字を何度も検査するため失敗します。 シングルパスアプローチでは、これまでに確認されたすべての文字が許可されたセットに属しているかどうかなど、重要な情報が正確に保持されます。`{a, b}`。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、次のコマンドを使用して末尾の改行を削除します。`strip()`。 入力にはスペースが含まれていないため、チェックする必要がある文字列が正確に得られます。 
2. 文字を左から右にスキャンします。 すべての文字について、次のいずれかをテストします。`a`または`b`。 この定義では、許可される 2 つの文字間の位置、頻度、または遷移に制限が設けられていないため、これで十分です。 
3. キャラクターが両方と異なる場合`a`そして`b`、すぐに印刷`NO`そしてやめてください。 無効な文字が存在すると、他の文字を追加または検査しても、既存の文字列を有効にすることはできません。 
4. 無効な文字が見つからずにスキャンが終了した場合は、印刷します。`YES`。 その後、すべての文字が許可されたアルファベットに属していることが検証されます。これはまさに退屈な文字列の定義です。 

### なぜ効果があるのか

 スキャン中の不変条件は、これまでに検査されたすべての文字が以下に属しているということです。`{a, b}`。 現在のキャラクターも`a`または`b`、不変式は真のままです。 現在の文字がそれ以外の場合、文字列には禁止された文字が含まれており、退屈であってはなりません。そのため、次の値が返されます。`NO`は正しいです。 ループが終了すると、不変式が文字列全体をカバーし、すべての文字が許可され、正しい答えが次のとおりであることが証明されます。`YES`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for ch in s:
        if ch != 'a' and ch != 'b':
            print("NO")
            return

    print("YES")

solve()
```入力は 1 回読み取られ、`strip()`によって生成された改行を削除します`readline()`。 文字列にはスペースが含まれないように指定されているため、使用によるあいまいさはありません。`strip()`ここ。 

このループは、アルゴリズムの 2 番目と 3 番目のステップを直接実装します。 この条件では、より大きな文字範囲に依存するのではなく、2 つの比較を使用します。これは、正確な文字のみが含まれるためです。`a`そして`b`有効です。 のようなキャラクター`c`、`A`、 または`1`全て拒否しなければなりません。 

の`return`印刷後`NO`も意図的です。 禁止文字が見つかった場合、スキャンを続行しても答えを変更することはできません。 早期リターンが発生しない場合、ループはすべての文字を検査したため、次のように出力されます。`YES`正当化される。 

整数の計算はないため、整数のオーバーフローは無関係です。 また、この実装では、文字列自体を超える入力長に比例する構造体は割り当てられません。

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 単一文字入力`a`ループによって処理され、1 つの文字を検査し、それが有効であることがわかり、最後に到達すると、次の結果が生成されます。`YES`。 同じ推論により、`YES`のために`b`。 両方のキャラクターが登場する必要はありません。

```アルゴリズムが調べます`b`、その後のシーケンス`a`キャラクターと`b`すべての文字が許可文字テストに合格します。 ループが終了して出力される`YES`。 このプロパティはメンバーシップのみに依存するため、順序と繰り返しは重要ではありません。`{a, b}`。 

入力用```
baaaaabad
```アルゴリズムは初期値を受け入れます`b`そして以下のすべて`a`文字。 届いたら`d`、条件`ch != 'a' and ch != 'b'`trueになるのですぐに出力されます`NO`。 無効な文字は終わり近くにありますが、左から右へのスキャンで正しく検出されます。

ccabbabbdd
