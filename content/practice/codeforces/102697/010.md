 ## 解決策
 ## 問題の理解

 この問題では、バスケットボール選手の試合ごとの現在のポイントを計算するように求められます。 入力により、これまでに獲得した合計ポイント数と、これまでにプレイされた合計ゲーム数が得られます。 必要な出力は、1 ゲームで獲得された平均ポイント数であり、ポイントをゲームで割ったものとして計算されます。 

制約が十分に小さいため、アルゴリズムの課題は効率ではなく、計算を正しく実行することになります。 処理される整数は 2 つだけなので、定数時間の解でも十分です。 主な関心事は、除算の精度を維持することです。 整数の除算では小数部分が切り捨てられるため、計算は浮動小数点演算を使用して実行する必要があります。 

最も一般的な間違いは、値を整数として扱ったり、回答を不必要にフォーマットしたりすることに起因します。 たとえば、入力が次の場合:```
78
7
```正しい出力は次のとおりです。```
11.142857142857142
```整数の除算を使用した不用意な実装では、次のような出力が出力されます。`11`、小数部分が完全に失われます。 

もう 1 つのエッジケースは、ポイント数がゲーム数よりも少ない場合です。 例えば：```
5
10
```正しい出力は次のとおりです。```
0.5
```答えが常に 1 より大きいと想定する実装、または結果を整数に変換して戻す実装では、不正な値が生成されます。 

## アプローチ

 直接的な総当たりアプローチでは、平均を計算する前にゲームをシミュレートし、各ゲームのポイントをカウントしようとします。 この問題ではすでに合計ポイントと合計ゲームが提供されているため、このアプローチは不要です。 ゲームが多数ある場合、すべてのゲームをシミュレートするには、入力に存在しない情報を保存または処理する必要があり、結果は改善されません。 

重要な観察は、ゲームごとのポイントは単純に 2 つの合計の比率であるということです。 隠れた構造を発見したり、検索したり、反復したりする必要はありません。 タスク全体は、2 つの数値を読み取り、1 回の浮動小数点除算を実行するだけで済みます。 

強引なアイデアは、必要以上に詳細なバージョンの問題を解決してしまうため、失敗します。 最終的な合計のみが重要であるという観察により、あらゆるシミュレーションを単一の算術演算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. プレーヤーが獲得した合計ポイントを読み取り、それを整数として保存します。 プレイされたゲームの合計数を読み取り、別の整数として保存します。 これら 2 つの値には、計算に必要なすべての情報が含まれています。 
2. 浮動小数点除算を使用して、合計ポイントを合計ゲーム数で割ります。 ゲームごとのポイントは必ずしも整数ではないため、除算では小数部分を保持する必要があります。 
3. 結果の値を直接出力します。 必要な出力は通常の浮動小数点表現を受け入れるため、手動で丸める必要はありません。 

なぜ効果があるのか:

 ゲームあたりのポイントの定義は、合計ポイントをプレイされた合計ゲーム数で割ったものです。 このアルゴリズムは、指定された 2 つの合計を使用して、まさにこの操作を実行します。 他の情報が平均に影響を与えることはないため、計算された値が常に必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p = int(input())
    g = int(input())
    print(p / g)

if __name__ == "__main__":
    solve()
```各値が独自の行に表示されるため、ソリューションでは 2 つの入力値を別々に読み取ります。 表現`p / g`整数の除算とは異なり、Python の浮動小数点の除算を使用するため、小数点以下の値が保持されます。 

Python の整数は固定整数制限を超えて大きくなる可能性があり、計算では 2 つの数値のみを使用するため、オーバーフローに対する特別な処理は必要ありません。 また、裁判官は Python によって生成された標準の 10 進表現を受け入れるため、プログラムは回答の書式設定を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 2 つの数値だけが読み取られ、1 つの除算が実行されます。 |
 | スペース | お(1) | プログラムは 2 つの入力値のみを保存します。 |

 この解は、数値の読み取りと除算のコストを超えて数値のサイズに依存しないため、指定された制限に簡単に適合します。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        p = int(sys.stdin.readline())
        g = int(sys.stdin.readline())
        return str(p / g) + "\n"
    finally:
        sys.stdin = old_stdin

# provided samples
assert solution("78\n7\n") == "11.142857142857142\n", "sample 1"
assert solution("89\n15\n") == "5.933333333333333\n", "sample 2"

# custom cases
assert solution("1\n1\n") == "1.0\n", "minimum values"
assert solution("0\n5\n") == "0.0\n", "zero points"
assert solution("100\n100\n") == "1.0\n", "equal values"
assert solution("5\n10\n") == "0.5\n", "fraction smaller than one"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`そして`1`|`1.0`| 最小の正規計算をチェックします。 |
 |`0`そして`5`|`0.0`| ゼロ点が正しく処理されていることを確認します。 |
 |`100`そして`100`|`1.0`| 等しい値をチェックします。 |

 ## 特殊なケース

 得点がゲーム数で割り切れない場合は、小数点以下を含む。 入力の場合:```
78
7
```アルゴリズムが計算します`78 / 7`浮動小数点除算として実行され、完全な 10 進数値が出力されます。 整数除算の実装では、誤って小数部分が失われます。 

プレーヤーがプレイしたゲームよりもポイントが少ない場合、平均は 1 未満になることがあります。 入力の場合:```
5
10
```アルゴリズムが計算します`5 / 10`、与える`0.5`。 答えが 1 より大きい必要があるとは想定していないため、結果は正しいままになります。 

合計が等しい場合、除算により正確に 1 が生成されます。 入力の場合:```
100
100
```アルゴリズムの出力`1.0`。 これにより、同じ計算が整数の答えと分数の答えに対して機能することが確認されます。
