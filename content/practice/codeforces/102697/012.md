 ## 解決策
 ## 問題の理解

 タスクは、小さな累乗を計算することです。 入力には 2 つの整数が含まれています。`n`そして`k`、底と指数を表します。 出力は次の正確な値になるはずです。`n`の累乗`k`、単なる数字や短縮形ではありません。 制約は意図的に小さくなっています。どちらの値も最大 10 であるため、考えられる最大の答えは次のとおりです。`10^10`、一般的な整数型に簡単に適合します。 元の問題ステートメントでは、ここでは総当たりアプローチで十分であるため、直接計算が期待されることが確認されています。 

数値が非常に小さいため、高度なべき乗テクニック、モジュラー演算、または巨大な値に対する特別な処理は必要ありません。 基数を単独で 10 回乗算するループでも、一定数の演算しか実行されません。 多項式または対数の複雑さを持つアルゴリズムも合格しますが、実際に与えられたものよりもはるかに難しいバージョンの問題を解決することになります。 

主なエッジケースは、指数を正しく処理することで発生します。 指数が 0 の場合、数学的結果は 1 になりますが、この入力範囲は 1 から始まるため、そのようなケースは現れません。 最小の有効な入力は、1 の基数と指数です。 例えば：```
Input:
1 1

Output:
1
```ゼロから開始するなど、答えを誤って初期化する不注意な実装では、すべての乗算でその間違いが保持されるため、ゼロが出力されます。 

もう 1 つの考えられる間違いは、2 つの数字の意味を逆にしてしまうことです。 最初の値は基数で、2 番目の値は指数です。 例えば：```
Input:
2 3

Output:
8
```コンピューティング`3^2`代わりに生成します`9`、それは間違いです。 

## アプローチ

 最も簡単なアプローチは、べき乗の定義をシミュレートすることです。 1 に等しい答えから始めて、それに基数を正確に掛けます`k`回。 これが機能する理由は、`n^k`は次のように定義されます`n * n * ... * n`と`k`のコピー`n`。 最大の指数はわずか 10 なので、最大でも 10 回の乗算が必要になります。 

より一般的なアプローチは 2 進累乗です。これは、基数を繰り返し 2 乗することで、非常に大きな指数の乗算の回数を減らします。 ただし、現在の問題にはその最適化は必要ありません。 これを追加すると、これらの制約の下でソリューションが改善されずにコードが長くなります。 

指数が非常に小さな定数によって制限されているため、総当たり法が機能します。 指数が次のように大きくなる可能性がある場合`10^18`、繰り返しの乗算は不可能になり、対数法が必要になります。 ここでは、入力の構造によりその必要がなくなります。

 ## アルゴリズムのチュートリアル

 1. ベースを読む`n`と指数`k`入力から。 最初の数値は乗算される内容を制御し、2 番目の数値は乗算が行われる回数を制御します。 
2. 答えを次のように初期化します。`1`。 これは乗算の中立値であるため、最初の乗算では正しい部分結果が生成されます。 
3. 繰り返します`k`倍、現在の答えを乗算します`n`各反復の後。 最初の反復後の値は次のようになります。`n`、2番目以降は`n^2`、最後の反復の後は次のようになります`n^k`。 
4. 最終値を出力します。 

機能する理由: 各乗算ステップの後、答えには、完了した反復回数で表されるべき乗が正確に保存されます。 ループは正確に実行されます`k`乗算なので、それが終了すると、保存された値は正確に`n^k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    ans = 1
    for _ in range(k):
        ans *= n

    print(ans)

if __name__ == "__main__":
    solve()
```制約によって両方の値が正常に適合することが保証されるため、入力は整数として直接読み取られます。 変数`ans`1 を乗算しても結果は変わらないため、1 から開始します。これにより、累乗を構築するための正しい開始点が得られます。 

ループは使用します`range(k)`だからまさにそれ`k`乗算が起こります。 ここで 1 つ違いの間違いを犯すのは簡単です。`range(k + 1)`計算するだろう`n^(k+1)`、ただし、反復回数を少なくすると、次の要素が失われます。`n`。 

Python の整数は必要に応じて自動的に増加するため、オーバーフローの心配はありません。 ここでの最大の答えは小さいですが、通常の整数演算を使用するだけで十分です。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, k = map(int, sys.stdin.readline().split())
    ans = 1
    for _ in range(k):
        ans *= n

    sys.stdin = old_stdin
    return str(ans)

# provided sample
assert solution("3 5\n") == "243", "sample 1"

# minimum values
assert solution("1 1\n") == "1", "minimum input"

# base equal to maximum value
assert solution("10 10\n") == "10000000000", "maximum input"

# same values
assert solution("5 5\n") == "3125", "all equal values"

# boundary where reversing base and exponent changes result
assert solution("2 10\n") == "1024", "base exponent order"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 5`|`243`| 提供されたサンプル動作 |
 |`1 1`|`1`| 最小の有効な入力 |
 |`10 10`|`10000000000`| 最大制約 |
 |`5 5`|`3125`| 底と指数が等しい |
 |`2 10`|`1024`| 基数と指数の正しい解釈 |
