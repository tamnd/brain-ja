 ## 解決策
 ## 問題の理解

 コンパスは 16 の主要方向と中間方向に分割できます。 4 つの基本方向は北、東、南、西であり、4 つの対角方向は北東、南東、南西、北西です。 残りの 8 方向は、隣接する方向の中間に位置します。 これらは、北北東の NNE や東南東の ESE など、半風です。 

入力は、これら 8 つの半風のうち 1 つを指定する 3 文字の頭字語を 1 つだけ入力します。 タスクは、2 つの単語の間にハイフンを入れて、その頭字語を小文字の英語名に展開するだけです。 例えば、`ESE`になる`east-southeast`。 

ここには大きな数値の入力はありません。 入力サイズは 3 文字に固定されているため、あらゆる方向をチェックするアプローチでも事実上一定時間になります。 1 秒の時間制限と 256 MB のメモリ制限は、直接実装するには十分すぎるものです。 主な関心事は、漸近的なパフォーマンスではなく正確さです。 

有効な 8 つの頭字語は次のとおりです。`NNE`、`ENE`、`ESE`、`SSE`、`SSW`、`WSW`、`WNW`、 そして`NNW`。 入力はこれらの有効なハーフワインドのいずれかであることが保証されているため、不正な形式の文字列を処理する必要はありません。 

一般的な境界ケースは次のとおりです。`NNW`。 それは間に座っています`NW`そして`N`、だからその名前は`north-northwest`。 コンパスの方向を単純な線形シーケンスとして処理して名前を生成しようとする実装では、誤ってコンパスからの遷移を誤って処理してしまう可能性があります。`NW`に戻る`N`。 

もう 1 つの簡単な間違いは、名前の 2 つの部分を逆にしてしまうことです。 例えば、`ENE`は`east-northeast`、 ない`northeast-east`。 頭字語の最初の文字は、英語名の最初に来る基本方向を識別します。 

文字の繰り返しも正常です。 たとえば、入力`NNE`2つ含まれています`N`文字と生成する必要があります`north-northeast`。 3 つの文字がすべて異なるものでなければならないと想定する実装では、この有効な方向が誤って拒否されます。 

## アプローチ

 最も直接的なブルート フォース ソリューションは、8 つの考えられる頭字語とそれに対応する名前を保存し、入力が一致するまでそれらを 1 つずつチェックします。 可能性は 8 つしかないため、最悪のケースでは、答えを見つける前に 8 つの比較が実行されます。 これはすでに一定時間であり、最も単純な実装でも現実的なパフォーマンスの問題はありません。 

よりクリーンなアプローチは、各頭字語をその完全名に直接マッピングする辞書を使用することです。 入力自体がキーであるため、8 つの可能性を明示的にたどることなく、答えをすぐに取得できます。 有益な観察は、問題には有効な翻訳の閉じられた固定セットがあるということです。 実行する計算や実行時に推測する必要のあるパターンがないため、直接検索することで問題を正確に表現できます。 

入力ドメインには 8 つの値しか含まれていないため、ブルート フォース手法が機能しますが、ルックアップ テーブルの方が検証と保守が容易です。 また、北西と北の間の循環境界に対する特別な処理も回避されます。

 ## アルゴリズムのチュートリアル

 1. 標準入力から 3 文字の頭字語を読み取ります。 入力には頭字語のみが含まれるため、周囲の空白を削除するだけで十分です。 
2. 8 つの有効な頭字語から名前への翻訳を辞書に保存します。 各キーは 1 つの可能なハーフワインドであり、その値はまさに必要な小文字の出力です。 
3. 入力された頭字語を辞書キーとして使用し、関連付けられたフルネームを出力します。 入力は有効であることが保証されているため、キーが見つからない場合に対処する必要はありません。 

### なぜ効果があるのか

 辞書には有効な半風ごとに 1 つのエントリが含まれており、各エントリはその頭字語を必要な英語名にマップします。 入力はこれら 8 つの頭字語のいずれかであることが保証されているため、検索では常に固有の正しい翻訳が選択されます。 コンパスの名前は固定マッピングによってすでに完全に表現されているため、幾何学的計算や解釈は必要ありません。

## テストケース

# helper: run solution on input string, return output string
import sys
import io

def solve():
    direction = input().strip()

    names = {
        "NNE": "north-northeast",
        "ENE": "east-northeast",
        "ESE": "east-southeast",
        "SSE": "south-southeast",
        "SSW": "south-southwest",
        "WSW": "west-southwest",
        "WNW": "west-northwest",
        "NNW": "north-northwest",
    }

    print(names[direction])

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output
        try:
            solve()
        finally:
            sys.stdout = old_stdout
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
assert run("ESE\n") == "east-southeast\n", "sample 1"
assert run("NNE\n") == "north-northeast\n", "sample 2"

# Custom cases
assert run("NNW\n") == "north-northwest\n", "cyclic compass boundary"
assert run("SSW\n") == "south-southwest\n", "repeated S character"
assert run("WNW\n") == "west-northwest\n", "repeated W character"
assert run("ENE\n") == "east-northeast\n", "repeated E character"

# All eight valid values together
all_input = "NNE\nENE\nESE\nSSE\nSSW\nWSW\nWNW\nNNW\n"

 ## 特殊なケース

 の`NNW`境界は明示的な辞書エントリによって処理されます。 入力用```
NNW
```ルックアップで見つかる`north-northwest`、北西と北の間の方向です。 ルックアップ テーブルにはそのような依存関係がないにもかかわらず、方向の線形リストを単に順方向に進むだけの生成されたソリューションでは、このラップアラウンド ケースを誤って見逃す可能性があります。 

文字が繰り返される場合は、文字ごとの仮定なしで処理されます。 のために```
NNE
```3 文字の文字列が 1 つのキーとして使用され、```
north-northeast
```という事実`N`2 回出現する場合は検索とは無関係です。 同じ理由が次の場合にも当てはまります`ENE`、`SSE`、 そして`WNW`。 

すべての有効な入力にはちょうど 3 文字が含まれるため、最小入力サイズと最大入力サイズは一致します。 次のような入力```
ESE
```にはすでに有効な最小長と最大長の両方が含まれています。 このアルゴリズムは、8 つの法的頭字語のどれが指定されたかに関係なく、辞書検索を 1 回実行します。 

次のようなすべてが等しい頭字語```
NNN
```は、問題の入力保証に基づく有効なテスト ケースではありません。 これは 8 つの半風のうちの 1 つを表していないため、解に結果を割り当てる必要は意図的にありません。 これは、問題が決して許さない入力に対する出力を発明するよりも好ましいです。
