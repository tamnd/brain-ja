 ## 解決策
 ## 問題の理解

 タスクは、オイラーの合計関数 φ(n) を計算することです。 正の整数 n の場合、φ(n) は、n との最大公約数が正確に 1 である整数 k を 1 から n までカウントします。 gcd(n, n) = n であるため、値 n 自体は、n = 1 の場合にのみ寄与します。 

たとえば、n = 15 の場合、有効な値は 1、2、4、7、8、11、13、および 14 であるため、φ(15) = 8 となります。入力には 1 つの正の整数 n が含まれており、出力はその合計値です。 公式の制約は特に小さく、n は 1000 未満で、時間制限は 1 秒、メモリは 256 MB です。 

これらの境界により、実際の選択は大きく変わります。 直接的な解法では、1 から n までのすべての k をテストして gcd(k, n) を計算でき、Euclid アルゴリズムの通常の分析では O(n log n) の時間を要します。 n が 1000 未満の場合、gcd 計算は最大 999 回であるため、この単純なアプローチでも快適に高速です。 n を因数分解することで、より良い漸近解を導き出すことができます。これにより、O(√n) 個の試行分割が行われ、O(1) 個の追加スペースが使用されます。 

間違いが明らかになる可能性のある小さなケースがいくつかあります。 1 つ目は n = 1 です。1 を超えない唯一の正の整数は 1 であり、gcd(1, 1) = 1 であるため、正しい出力は 1 です。1 を個別に処理せずに素数 p に対して公式 φ(p) = p - 1 を盲目的に適用するプログラムは、誤った結果を生成する可能性があります。 

2 番目のケースは、n = 7 などの素数です。```
7
```1 から 6 までのすべての数値は 7 に対して素であるため、正しい出力は 6 です。適切な約数だけを数えたり、合成数だけを探したりする不注意な実装では、この間違いが発生する可能性があります。 

素因数の繰り返しも間違いのよくある原因です。 のために```
60
```素因数分解は 2² × 3 × 5 で、正しい出力は 16 です。 2 回出現する 2 を 2 つの独立した除外として扱うと、合計の公式で同じ因数が 2 回誤って適用されてしまいます。 

## アプローチ

 最も直接的なアプローチは、文字通り定義に従います。 1 から n までのすべての整数 k について、gcd(k, n) を計算し、gcd が 1 になるたびに答えをインクリメントします。φ(n) の定義は正確にそのような k の数であるため、これは正しいです。 指定された入力範囲の最悪のケースは n = 999 であるため、プログラムは 999 回の gcd 計算を実行します。 一般に、実行時間は O(n log n) ですが、余分なスペースは O(1) です。 この問題に関しては、すでに十分に高速です。 

より有用なアプローチは、すべての候補 k をチェックするのではなく、n の素因数を調べることから得られます。 n に異なる素因数 p₁、p₂、...、pᵣ があるとします。 数値 k は、これらの素数の少なくとも 1 つで割り切れる場合、正確には n に対して素ではありません。 1 から n までの n 個の整数のうち、正確に n / pᵢ は pᵢ で割り切れます。 これらの集合の結合を数えるために包含-排他を使用することもできますが、同じ推論によりコンパクトな式が得られます。 

φ(n) = n × (1 - 1/p₁) × (1 - 1/p₂) × ... × (1 - 1/pᵣ)。 

重要な点は、異なる素因数のみが重要であるということです。 それらの指数は製品には表示されません。 

たとえば、60 = 2² × 3 × 5 です。60 から開始すると、係数 2 により候補の半分が削除され、30 が得られます。係数 3 により、残りの候補の 3 分の 1 が削除され、20 が得られます。係数 5 により、5 分の 1 が削除され、16 が得られます。したがって、φ(60) = 16 となります。 

したがって、n の異なる素因数を発見するだけで済みます。 試し割りは√nまでで十分です。 約数 p が見つかるたびに、全体更新を 1 回適用し、p を完全に除算します。 これを完全に削除することで、同じ素数が再度処理されないことが保証されます。 

ブルートフォース手法はより単純であり、これらの制約の下では受け入れられますが、因数分解手法はその複雑さが n ではなく √n に依存するため、より優れた一般的な手法です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n log n) | お(1) | 承認済み |
 | 素因数分解 | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. n を読み取り、答えを n に初期化します。 n から始めます。これは、全数の公式が、それぞれの異なる素因数で割り切れる数の部分を繰り返し除去するものとみなすことができるためです。 
2. 試行的な約数 p を 2 に設定し、p² ≤ n の範囲で可能な約数をテストします。 p² が残りの n より大きくなると、p より小さい別の因数は存在できないため、1 より大きい残りの値はそれ自体が素数でなければなりません。 
3. p が n を割る場合、次を使用して答えを更新します。`answer -= answer // p`。 これは係数を適用します`(1 - 1/p)`整数演算のみを使用し、浮動小数点計算を回避します。 
4. n を p で除算できなくなるまで、繰り返し n で除算します。 これを行うのは、数式がそれぞれの異なる素因数を 1 回だけ必要とするためです。 たとえば、係数が 2³ の場合、2 の更新は 3 回ではなく 1 回実行する必要があります。 
5. 次に考えられる約数に移動し、p² > n になるまで続けます。 
6. ループ後、n が 1 より大きい場合、残りの n は処理されていない素因数になります。 このプライムに最後の全体更新を 1 つ適用します。 
7. 結果の回答を印刷します。 

不変条件は、すべての素因数 p が処理された後、`answer`これまでに処理されたすべての素因数によって課せられる割り算の制限を乗り越えた、1 から元の入力までの整数の数に等しくなります。 n から p のコピーをすべて削除しても、p で割り切れる整数は変わらないため、各素数は 1 回の乗法縮約に正確に寄与します。 因数分解が完了すると、gcd(k,original_n) を 1 より大きくできるすべての素数が処理されるため、正確に相対的に素な整数が残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    original = n
    ans = n
    p = 2

    while p * p <= n:
        if n % p == 0:
            ans -= ans // p

            while n % p == 0:
                n //= p

        p += 1

    if n > 1:
        ans -= ans // n

    print(ans)

if __name__ == "__main__":
    solve()
```変数`ans`元の n から始まり、異なる素因数ごとに 1 回更新されます。 表現`ans -= ans // p`を乗算する整数形式です`(p - 1) / p`したがって、浮動小数点演算は必要ありません。 

内側の`while`ループは、現在の素因数のすべての出現を削除します。 これは微妙ですが必要な詳細です。 n = 60 の場合、2 を求めた後、n の値は 15 になります。係数 2 はすでに考慮されているため、再度考慮する必要はありません。 

ループ条件`p * p <= n`それも意図的です。 現在の約数が残りの n の平方根を超えると、残りの因数は最大 1 つまでになり、その因数は素数でなければなりません。 チェック中`n > 1`ループがその状況を正確に処理した後。 

Python の整数には、C++ などの言語で発生する可能性がある固定幅のオーバーフローの問題はありませんが、ここでは大きな中間値は必要ありません。 

## 実用的な例

 サンプル 1 の入力は 15 です。因数分解は 15 = 3 × 5 です。 

| p | 因数分解前の n | アップデート前 | 更新後の結果 | p を削除した後の n |
 | --- | --- | --- | --- | --- |
 | 2 | 15 | 15 | 15 | 15 |
 | 3 | 15 | 15 | 10 | 5 |
 | 残り 5 | 5 | 10 | 8 | 5 |

 約数 2 は発生しないため、影響はありません。 処理 3 では、候補の 3 分の 1 が 3 で割り切れるため、15 が 10 に変更されます。次に、処理 5 では、10 が 8 に変更されます。最終結果は 8 です。 

サンプル 2 の入力は 60 です。その因数分解は 2² × 3 × 5 です。 

| p | 因数分解前の n | アップデート前 | 更新後の結果 | p を削除した後の n |
 | --- | --- | --- | --- | --- |
 | 2 | 60 | 60 | 30 | 15 |
 | 3 | 15 | 30 | 20 | 5 |
 | 残り 5 | 5 | 20 | 16 | 5 |

 2 の指数は 2 ですが、2 の更新は 1 回だけ発生します。 2 の両方のコピーを削除すると、残りの値は 15 になります。その固有の素因数は 3 と 5 です。最終結果は 16 です。 

サンプル 3 では、n = 7 が素数です。 

| p | 因数分解前の n | アップデート前 | 更新後の結果 | 因数分解後の n |
 | --- | --- | --- | --- | --- |
 | 残り 7 | 7 | 7 | 6 | 7 |

 7 には最大 √7 の因数がないため、試行ループでは約数が見つかりません。 したがって、残りの値 7 は素数であり、最後の更新で 6 になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(√n) | 試行除算では、検出された各因子が完全に削除され、p² ≤ n の場合にのみ約数がチェックされます。 |
 | スペース | お(1) | 一定数の整変数のみが保存されます。 |

 n < 1000 の場合、√n は 32 未満であるため、最適なアルゴリズムは最悪の場合でも数十個の候補因子のみを検査します。 これは 1 秒の制限時間を大幅に下回っており、メモリの使用量は無視できます。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    ans = n
    p = 2

    while p * p <= n:
        if n % p == 0:
            ans -= ans // p
            while n % p == 0:
                n //= p
        p += 1

    if n > 1:
        ans -= ans // n

    return str(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin

assert run("60\n") == "16\n", "sample 2"
assert run("7\n") == "6\n", "sample 3"

 ## 特殊なケース

 可能な最小の入力は n = 1 です。```
1
```アルゴリズムが初期化されます`ans = 1`。 処理する約数がなく、残りの n が 1 より大きくないため、答えは 1 のままです。 gcd(1, 1) = 1 であるため、これは定義と一致します。 

次のような主要な入力```
7
```因子処理ブランチには決して入りません。 7 の平方根までの約数をテストした後、残りの n は 7 のままです。最後の更新では計算が行われます。`7 - 7 // 7 = 6`、これは素数の正しい合計です。 

繰り返される素因数は次のように表示されます。```
60
```最初に発見された因数は 2 です。答えは 60 から 30 に変化し、内側のループは 2 の両方のコピーを削除し、作業中の n を 60 から 15 に変更します。素数 2 が再度適用されることはありません。 残りの因数 3 と 5 により、答えは 20 に減り、最終的には 16 になります。 

最大入力は```
999
```これは 33 × 37 として因数分解されます。アルゴリズムは 3 を見つけ、その合計の削減を 1 回適用し、3 の 3 つのコピーすべてを削除します。試行ループの後、残りの値 37 は 1 より大きいため、素因数として認識され、1 回処理されます。 結果は648です。 

などの主要なパワー```
729
```これは、全体の更新を指数ごとに 1 回適用するという間違いを見つけるのに特に役立ちます。 729 = 3⁶ なので、係数 3 は式に 1 回だけ影響を与える必要があります。 正しい計算は、アルゴリズムによって生成される 729 × (1 - 1/3) = 486 です。
