 ## 解決策
 ## 問題の理解

 このタスクは、1 回の車旅行の燃料費を計算することです。 入力により、車の燃費 (ガロンあたりのマイル数)、走行距離 (マイル)、および 1 ガロンのガソリンの価格という 3 つの浮動小数点値が得られます。 

車が走れば`distance`マイルを獲得すると`mpg`各ガロンからマイルに達すると、必要なガソリンの量は

 [
 \frac{\text{距離}}{\text{mpg}}
 ]

 ガロン。 その数量に 1 ガロンの価格を掛けると、旅行費用の合計が求められます。 

[
 \text{コスト} =
 \frac{\text{距離}}{\text{mpg}}
 \回
 \text{ガロンあたりの価格}。 
]

 必要な出力は、結果として得られる浮動小数点値としての金額です。 公式ステートメントでは、正確に 3 つの浮動小数点値を含む 1 つのテスト ケースを指定しています。 

公開されたステートメント内の 3 つの浮動小数点値には明示的な数値制限はありません。 これにより、入力の大きさに基づく漸近アルゴリズムが不要になります。 問題全体は 3 つの数値を読み取り、2 つの算術演算を実行することで構成されているため、実行時間は値に関係なく一定です。 

一般的なエッジケースは、距離がゼロの旅行です。 たとえば、入力の場合`20 0 5`、車の消費量は 0 ガロンなので、正しい出力は次のようになります。`0.0`。 距離を燃料効率で割るのではなく、乗算するような不注意な実装を行うと、間違った結果が生じる可能性があります。 

もう 1 つの有用な境界ケースは、燃料価格がゼロの場合です。 例えば、`20 100 0`には 5 ガロンが必要ですが、1 ガロンは無料なので、答えは次のようになります。`0.0`。 公式ではこれを自然に処理します。 

3 番目のケースは、燃費が整数ではない場合です。 入力用`7.5 30 4`、車に必要なもの`30 / 7.5 = 4`ガロンの答えは`16.0`。 値を整数として読み取る実装は、計算に到達する前に失敗します。 

公開されているサンプルは、`10 100 3.5`。 車に必要なのは`100 / 10 = 10`ガロン、および10ガロン`⟦PROTECT_4⟧35.00`したがって、出力は次のようになります`35.0`。 

## アプローチ

 文字通りの強引なアプローチでは、一度に 1 単位の距離の移動をシミュレートし、対応する燃料コストを累積します。 距離が整数の場合`D`、これには必要になります`D`反復。それぞれが別の 1 マイルの走行を表します。 したがって、最悪の場合の操作数は次のようになります。`D`、 または`O(D)`。 これはこの問題にはすでに不要であり、実際の距離は浮動小数点値であるため、反復処理の対象となる自然な離散単位さえありません。 

この強引なアイデアが機能するのは、総費用が旅行のあらゆる小さな部分の費用の合計と見なせる場合に限られます。 重要な観察点は、各マイルの燃料コストが同じであるため、旅行中に状態が変化することはないということです。 消費量をシミュレーションする代わりに、消費ガロン数を直接計算できます。 総距離をガロンあたりのマイル数で割ると、1 回の操作で必要な正確な燃料が得られ、ガロンの価格を掛けると答えが得られます。 

したがって、問題全体は次の式に還元できます。 

[
 \frac{距離\×価格}{mpg}。 
]

 配列、ループ、動的プログラミング、グラフ アルゴリズム、数値検索は必要ありません。

 ## アルゴリズムのチュートリアル

 1. 3 つの浮動小数点値を次のように読み取ります。`mpg`、`distance`、 そして`price`。 

燃費とガソリン価格には小数値が含まれる可能性があるため、浮動小数点入力が必要です。 
2. 距離を燃料効率で割って、消費ガロン数を計算します。 

旅する車`mpg`ガロンあたりのマイル数が必要`distance / mpg`要求された距離を移動するためのガロン。 
3. ガロン数に 1 ガロンあたりの価格を掛けます。 

これにより、燃料の量が旅行の合計金額に変換されます。 
4. 結果の浮動小数点値を出力します。 

この問題には Python の標準の浮動小数点出力で十分であり、次のようなサンプル出力が生成されます。`35.0`。 

### なぜ効果があるのか

 燃料効率は、1 ガロンごとに車が正確に動くことを示しています`mpg`マイル。 その関係を逆転すると、1マイルの移動に消費される`1 / mpg`ガロン、だから旅行中`distance`マイルが消費される`distance / mpg`ガロン。 どのガロンでも同じ値段なので、`price`, 消費ガロンにその価格を掛けると、旅行に対して支払われた合計金額が正確に得られます。 アルゴリズムはこれら 2 つの変換を正確に実行するため、その結果が必要なガスコストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    mpg, distance, price = map(float, input().split())

    gallons = distance / mpg
    cost = gallons * price

    print(cost)

if __name__ == "__main__":
    solve()
```最初の行はインポートします`sys`、 そして`input`に割り当てられています`sys.stdin.readline`高速標準入力の要求に応じて。 ここでは入力サイズは小さいですが、これは通常の競技プログラミングのセットアップです。 

3 つの値は次のように解析されます。`float`これは、ステートメントが浮動小数点値を明示的に許可しているためです。 変数`gallons`消費される燃料の物理量を表すため、計算が読みやすくなり、数学的導出が反映されます。 

分割は価格を適用する前に行う必要があります。`distance / mpg`にはガロンという単位があり、それにガロンあたりのドルを掛けるとドルが残ります。 この順序で計算を書くと、燃料効率と燃料消費量の混同も避けられます。 

パイソンの`float`倍精度浮動小数点演算を使用します。 計算では整数サイズのアキュムレータが使用されず、3 つの値のみが処理されるため、整数オーバーフローの懸念はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    mpg, distance, price = map(float, input().split())

    gallons = distance / mpg
    cost = gallons * price

    print(cost)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided sample
assert run("10 100 3.5\n") == "35.0\n", "sample 1"

# minimum-style zero-distance case
assert run("1 0 10\n") == "0.0\n", "zero distance"

# all values are equal
assert run("5 5 5\n") == "5.0\n", "all equal values"

# fractional miles per gallon
assert run("7.5 30 4\n") == "16.0\n", "fractional mpg"

# zero fuel price
assert run("20 100 0\n") == "0.0\n", "free fuel"

 ## 特殊なケース

 距離がゼロの場合、正確な入力は次のとおりです。`1 0 10`。 アルゴリズムが計算するのは、`0 / 1 = 0`ガロン、そしてその後`0 * 10 = 0`、生産`0.0`。 数式は物理的な状況をすでに正確に捉えているため、特別な条件は必要ありません。 

燃料価格がゼロの場合、入力`20 100 0`必要`100 / 20 = 5`ガロン。 最終的な乗算は、`5 * 0 = 0`したがって、出力は次のようになります`0.0`。 これにより、アルゴリズムが燃料消費量と燃料価格を正しく分離していることが確認できます。 

部分燃料効率については、次の点を考慮してください。`7.5 30 4`。 部門が与えるのは`30 / 7.5 = 4`ガロン、そして最後の乗算は次のようになります`4 * 4 = 16`。 入力を読み取る`float`それが許可するものです`7.5`正しく表現されること。 

公式サンプルについては`10 100 3.5`、計算は`100 / 10 = 10`ガロン、続いて`10 * 3.5 = 35`。 印刷された結果は、`35.0`、公式出力と一致します。 

実装の主な落とし穴は、最初の操作を逆にすることです。 ガロンあたりのマイル数は、1 ガロンで走行できるマイル数を示すため、燃料消費量は距離をガロンあたりのマイル数で割ったものとなります。 距離にガロンあたりのマイルを掛けると単位が間違ってしまい、間違った答えが得られます。
