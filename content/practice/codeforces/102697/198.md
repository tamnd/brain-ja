 ## 解決策
 ## 問題の理解

 2 の累乗のチーム数によるシングルエリミネーション トーナメントを開催します。 各チームにはシードがあり、シードによって固定ブラケットが決まります。 最初のラウンドでは、シード (s) がシード (n-s+1) と対戦します。 勝者はその後、ブラケットによって決定された順位に進むため、番狂わせによってブラケット自体は変更されず、特定のポジションを占めるチームが変わるだけです。 入力により、すべてのチームが他のすべてのチームに勝つ確率もパーセントで示されます。 

このタスクは、すべてのチームが最終的にトーナメント全体で優勝する確率を計算し、その確率の降順にチームを出力することです。 確率は完全な精度を使用して並べ替える必要があり、印刷時に最も近い整数にのみ四捨五入する必要があります。 問題のステートメントでは (n) が 2 の正の累乗であると指定されていますが、公開されたステートメントでは (n) の数値の上限が示されていません。 入力にはすでに (n \times n) 確率行列が含まれているため、入力の読み取りには (O(n^2)) のコストがかかり、実質的に 2 次を超えるアルゴリズムはすぐに実用的ではなくなります。 意図した動的プログラミング アプローチでは、(O(n^2 \log n)) 算術演算を使用します。これは、トーナメント サイズの入力を簡単に管理できます。 

最初の自明ではないケースは、1 チームのみが含まれるトーナメントです。 例えば、```
1
Solo
50
```正しい出力がある```
Solo 100
```自己一致確率 50 は実際には使用されません。 1 チーム トーナメントのチームは自動的に勝利するため、対角線の確率を実際の試合として扱うと、間違った答えが得られます。 

もう 1 つの一般的なエッジ ケースは、完全に対称的なトーナメントです。 例えば、```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```は、各チームの正しい出力確率が 25 になります。 対角線のエントリを敵として使用したり、並べ替えの前に確率を四捨五入したりする不注意な実装は、この対称性を乱す可能性があります。 

3 番目のエッジケースは、ブラケットのレイアウト自体に由来します。 4 チームの場合、第 1 ラウンドの試合はシード 1 対シード 4、およびシード 2 対 シード 3 になります。第 2 ラウンドは、これら 2 つの試合の勝者となります。 したがって、対応するリーフの順序は (1,2,3,4) ではなく (1,4,2,3) になります。 8 チームの場合、順序は (1,8,4,5,2,7,3,6) になります。 シード順を直接使用すると、別のトーナメントの確率が計算されます。 

最後に、答えは丸め境界上に正確に存在する可能性があります。 チームに確率 (12.5%) がある場合、必要な出力値は 13 です。 2 つの近い確率は、実際の順序が異なっていても同じ整数に丸められる可能性があるため、この丸めの前に並べ替えを行う必要があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、考えられるあらゆるトーナメント結果を列挙できます。 シングルエリミネーション トーナメントには (n-1) 個のゲームがあり、各ゲームには 2 人の勝者が考えられるため、(2^{n-1}) 通りの完全な結果パターンが考えられます。 パターンごとにトーナメントをシミュレートし、個々のゲーム結果の確率を乗算し、その確率を勝利チームの合計に加算できます。 これは正しいです。なぜなら、ゲーム勝者の考えられるすべての順序は相互に排他的な結果であり、トーナメントのチャンピオンの確率は、そのチャンピオンを生み出すすべての結果の確率の正確な合計であるからです。 

問題は結果の数です。 それらをすべて列挙するには (2^{n-1}) 件のケースが必要であり、各ケースがすべての (n-1) ゲームを通じてシミュレートされる場合、ゲーム解決操作の最悪のケースの数は正確に ((n-1)2^{n-1}) になります。 (n=32) であっても、これはすでに 330 億回を超えるゲーム操作に相当します。 指数関数的な増加により、このアプローチは使用できなくなります。 

有益な観察は、トーナメントの完全な履歴を実際には気にしていないということです。 特定のブラケット位置について、私たちが知る必要があるのは、各チームがその位置に到達する確率だけです。 これらの確率がわかれば、特定のチームがブラケットの残りの半分から出てくる対戦相手に対して勝つ確率を計算できます。 

括弧ブロックに 2 つの小さなブロックが含まれているとします。 (p_i) をチーム (i) が小さいブロックに勝つ確率とします。 チーム (i) が左側のブロックにいる場合、そのチームが結合されたブロックに勝つ確率は次のとおりです。 

[
 p_i \sum_j p_j P_{i,j},
 】

 ここで、(j) は右ブロック内のチームの範囲であり、(P_{i,j}) は (i) が (j) に勝つ確率です。 同じ公式が右ブロックのチームにも当てはまります。 

ブルートフォース手法は、これらのイベントのあらゆる組み合わせを考慮するため機能します。 各小さいブラケットの勝者の分布のみが重要であるという観察により、内部結果を列挙することなくサブツリー全体を結合することができます。 トーナメントは一度に 1 ラウンドずつ処理され、各チームに対して 1 つの確率が維持されます。 

最初に処理する必要がある構造上の詳細が 1 つあります。 シードは、ブラケット内で葉が発生する順序で保存されません。 実際のブラケットの順序を再帰的に構築します。 8チームの場合は、

 [
 [1,8,4,5,2,7,3,6]。 
】

 このようにチームが配置されると、各トーナメント ラウンドは隣接するブロックの結合に対応するため、動的プログラミングが簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n^2\log n)) | (O(n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. チーム名と直接対決の勝利確率の完全なマトリックスを読みます。 すべての行列エントリをパーセンテージから 0 から 1 までの数値に変換するため、乗算は確率の乗算を直接表します。 
2. トーナメント ブラケットの実際のリーフ順序を構築します。 (l) から (r) までの連続したシードの区間について、その下半分の順序を再帰的に構築します。 (l+r-x) を使用して間隔全体のすべてのシード (x) を反映し、元の順序と反映された順序をインターリーブします。 たとえば、間隔 (1\ldots4) は ([1,4,2,3]) になり、(1\ldots8) は ([1,8,4,5,2,7,3,6]) になります。 これは、記載されたシードの組み合わせが後のラウンドにどのようにフィードされるかを正確に反映しています。 
3. すべてのチームが現在の 1 チーム ブロックに勝つ確率を 1 に初期化します。この時点では試合は行われていないため、すべてのチームは確実にそれぞれの開始位置に到達します。 
4. 処理ブロック サイズ (2、4、8、\ldots、n)。 現在のサイズのブロックごとに、左半分と右半分に分割します。 チーム (i) がブロック全体に勝つ確率は、自陣に勝つ確率と、反対側の陣営から出てくるチームに勝つ確率を掛けたものに等しくなります。 
5. 左半分のチーム (i) の場合、次のように計算します。 

[
 新しい_i = 古い_i
 \sum_{j\in right} old_j P_{i,j}。 
】

 合計は、右半分の考えられるすべての対戦相手の加重平均です。 同じ計算が、左半分を対戦相手セットとして使用して、右半分のすべてのチームに対して実行されます。 

1. 古い確率配列を新しく計算された値に置き換え、次のブロック サイズに進みます。 ブロック サイズが (n) に達した後、各確率は、対応するチームがトーナメント全体で優勝する確率を表します。 
2. 四捨五入されていないトーナメント優勝確率に基づいてチームを降順に並べ替えます。 ステートメントでは、丸めは並べ替え後にのみ行われると明示的に規定されているため、並べ替え中に丸められていない値を保持する必要があります。 
3. 各確率をパーセンテージに変換し、最も近い整数に丸めます。 使用する`int(probability * 100 + 0.5)`非負の確率に必要な四捨五入を実装します。 チーム名に続いてこの四捨五入されたパーセンテージを出力します。 

重要な不変条件は、ブロック サイズ (2^k) を処理した後、`dp[pos]`は、チームが次の時点に格納される確率とまったく同じです`order[pos]`(2^k) チームのブラケット ブロックの勝者になるために必要なすべてのゲームに勝ちます。 1 チームのブロックが確率 1 で勝つため、基本ケースは true です。2 つのブロックが結合されると、他のブロックからのあらゆる対戦相手が出現する確率で表され、対応する直接対決の確率を掛けると、その完全なパスの確率が得られます。 考えられるすべての対戦相手を合計すると、チームが結合されたブロックで勝つための相互に排他的なすべての方法が説明されます。 したがって、不変式はすべてのラウンドで真のままであり、最終ラウンドでは望ましいチャンピオンシップの確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def bracket_order(lo, hi):
    if lo == hi:
        return [lo]

    mid = (lo + hi) // 2
    left = bracket_order(lo, mid)

    # Reflect the seeds in the interval.
    right = [lo + hi - x for x in left]

    order = []
    for a, b in zip(left, right):
        order.append(a)
        order.append(b)

    return order

def solve():
    n = int(input())
    names = input().split()

    win = []
    for _ in range(n):
        row = list(map(int, input().split()))
        win.append([x / 100.0 for x in row])

    order = bracket_order(0, n - 1)

    # dp[pos] is the probability that order[pos] wins
    # its current bracket block.
    dp = [1.0] * n

    size = 2
    while size <= n:
        half = size // 2
        new_dp = [0.0] * n

        for start in range(0, n, size):
            middle = start + half
            end = start + size

            for i in range(start, middle):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(middle, end):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

            for i in range(middle, end):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(start, middle):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

        dp = new_dp
        size *= 2

    probability = [0.0] * n
    for pos, team in enumerate(order):
        probability[team] = dp[pos]

    teams = list(range(n))
    teams.sort(key=lambda i: (-probability[i], i))

    out = []
    for team in teams:
        rounded = int(probability[team] * 100.0 + 0.5)
        out.append(f"{names[team]} {rounded}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`bracket_order`この関数は、シード番号を物理的なブラケット位置に変換することのみを担当します。 その再帰反射は、シード (s) がシード (n-s+1) をプレイするという単純なルールを、後のすべてのラウンドが隣接するブロックで構成される順序に変えるものです。 

の`dp`配列には、チーム番号ではなくブラケットの位置によってインデックスが付けられます。 すべてのチームが確実に独自の 1 チーム ブロックを占有しているため、最初はすべてのエントリは 1 です。 ラウンド中に、`new_dp`変更する代わりに使用されます`dp`所定の位置にあります。 これが必要なのは、現在のラウンドのすべての計算で前のラウンドの確率を使用する必要があるためです。 適切に更新すると、1 つのチームが現在のラウンドをすでに含む確率を確認することになり、誤った結果が生成されます。 

マトリックスは依然として元のチーム番号によってインデックス付けされているため、`order[i]`そして`order[j]`直接対決の確率が要求されるたびに使用されます。 ブラケットの位置とチーム ID をこのように分離することで、この問題で最も一般的なインデックス作成エラーを防ぐことができます。 

決勝戦`probability`配列は、ブラケット位置の確率を元のチーム番号に変換します。 並べ替えでは、これらの正確な浮動小数点値が使用されます。 セカンダリ シード インデックスは決定的なタイ ブレーカーにすぎず、確率が異なる場合に必要な順序付けには影響しません。 

すべての確率は負ではないので、次のように追加します。`0.5`に変換する前に`int`Python のバンカー丸め動作を使用せずに、必要な最も近い整数の丸めを実行します。 Python の整数にも任意の精度があるため、整数オーバーフローの問題はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n^2\log n)) | (\log_2 n) ラウンドがあり、各ラウンドでは合計 (O(n^2)) 個のチームと対戦相手のペアが考慮されます。 |
 | スペース | (O(n^2)) | 確率行列は (O(n^2)) 空間を使用しますが、動的プログラミング配列は (O(n)) を使用します。 |

 (n \times n) 確率行列にはすでに 2 次入力空間が必要であるため、指定された表現では (O(n^2)) のストレージは避けられません。 動的プログラミングでは、線形の追加スペースのみが追加されます。 実行時間はトーナメント ラウンドの対数係数で増加し、総当たりによる指数関数的 (2^{n-1}) 完全なトーナメント結果を回避します。

 ## 特殊なケース

 ワンチームの場合は、```
1
Solo
50
```

`bracket_order(0, 0)`返品`[0]`。 初期ブロック サイズがすでに (n) より大きいため、ラウンド ループは実行されません。 唯一のチームの確率が 1 のままであるため、出力される値は 100 です。対角値 50 は実際のゲームとして解釈されることはありません。 

決定論的な 2 チームの場合、```
2
A B
50 100
0 50
```括弧の順序は`[A, B]`。 唯一のラウンド中、A の以前の確率は 1 で、B に勝つ確率は 1 であるため、A は確率 1 を受け取ります。B は (1 \times 0 = 0) を受け取ります。 最終的な出力は次のとおりです`A 100`そして`B 0`。 これにより、誤って自己確率を使用したり、行列のインデックスを逆にした実装が捕捉されます。 

対称的な 4 チームの場合、```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```最初のラウンドでは、各チームにそのペアに勝つ確率 (0.5) が与えられます。 決勝では、各チームには決勝に進出する確率 (0.5) があり、その後、相手に勝つ確率が加重 50% で与えられます (0.25)。 結果的に、すべてのチームは 25 を出力します。これは、チームに保存されている確率には、勝つためにすでに必要なすべてのゲームが含まれるという不変条件を確認します。 

ブラケット順序の境界の場合、4 つのシードが次のように表示される必要があります。`[1,4,2,3]`、 ない`[1,2,3,4]`。 再帰的な構築では、最初に次のものが作成されます。`[1,2]`、それを反映します`[4,3]`、それらをインターリーブして取得します`[1,4,2,3]`。 したがって、最初のペアは、トーナメント ルールで要求されているとおり、シード 1 と 4 になります。 8 つのシードの場合、同じ構造で次の結果が得られます。`[1,8,4,5,2,7,3,6]`したがって、番狂わせによって、次のラウンドに進む位置は変更されずに、ブラケット位置を占めるチームが変更されます。 

64 チームによる大規模な対称ケースでは、各チームの優勝確率は (1/64)、つまり (1.5625%) になります。 アルゴリズムは 6 ラウンドを実行し、毎回ブロック サイズを 2 倍にし、最終的な確率はどのチームでも (1/64) のままです。 (1.5625) は 2 に四捨五入されるため、すべてのチームに確率 2 が出力されます。これにより、すべての動的プログラミング ラウンドが実行され、最終的な並べ替えステップの後にのみ確率が四捨五入されることも確認されます。 

公開された問題文では、チーム数が 2 の正のべき乗としてのみ示されており、数値の最大値は示されていないため、上記の 64 チームのテストは、主張されている公式の最大値ではなく、代表的な大きな入力として解釈される必要があります。 アルゴリズム自体は、特定の 2 の累乗には依存せず、ブラケット構造と (n \times n) 確率行列のみに依存します。
