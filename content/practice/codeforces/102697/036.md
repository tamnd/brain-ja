 ## 解決策
 ## 問題の理解

 この問題は状態のデータベースを維持します。 データベースには、状態ごとに、その最大許容速度が保存されます。 このデータベースを構築した後、各クエリが 1 つの州を指定するいくつかのクエリを受け取ります。 クエリされたすべての状態について、その状態に保存されている制限速度を出力する必要があります。 

重要な点は、クエリが独立していることです。 クエリ後にデータベース内では何も変更されないため、唯一のタスクは、各州名をその格納されている整数に効率的に関連付けることです。 

このステートメントでは、状態の数とクエリの数が正の整数であることのみが示されており、明示的な数値の上限は示されていません。 制限時間は 1 秒、メモリ制限は 256 MB です。 これは、合計入力サイズにおける線形時間ソリューションを強く支持します。 クエリごとにデータベース全体をスキャンする方法では、入力の両方の部分が大きい場合、二次作業が必要になる可能性があります。 ハッシュ テーブルにより、予期される一定時間のルックアップが行われるため、合計作業量はデータベース エントリとクエリの数に比例します。 

州名にはスペースが含まれていません。つまり、各データベース エントリは、空白で区切られた 2 つのトークンとして読み取ることができます。 クエリされた状態名も同様に 1 つのトークンとして直接読み取ることができます。 

不用意に実装すると失敗するケースがいくつかあります。 繰り返されるクエリには、データベースを変更せずに繰り返し応答する必要があります。 例えば、```
2
Texas 85
Hawaii 60
3
Texas
Texas
Hawaii
```生成する```
85
85
60
```最初のクエリに応答した後に誤って状態を削除する実装は、2 番目のクエリで誤って失敗します。`Texas`。 

州名はスペースを含まない単なる文字列であるため、1 文字の名前を持つ州も有効です。 例えば、```
1
A 50
1
A
```生産しなければならない```
50
```状態名が特定の長さであると仮定するコードは、不必要に脆弱になります。 

入力形式で許可されている場合、データベースには速度制限がゼロの状態を含めることもでき、その値は他の整数とまったく同じように保存および出力される必要があります。 正しいアプローチでは、数値に特別な意味を与えません。 

## アプローチ

 直接的な総当たりアプローチは、データベース エントリを配列に格納することです。 すべてのクエリについて、要求された状態が見つかるまでその配列を最初からスキャンし、その速度制限を出力します。 これは正しいです。すべてのデータベース エントリが州名とその速度制限を明示的に関連付けているため、一致する名前を見つけると必要な答えが正確に得られます。 

問題は繰り返しスキャンすることです。 (S) データベース エントリと (T) クエリがある場合、クエリは状態を見つける前にすべての (S) エントリを検査できます。 最悪の場合、これは (S \times T) の比較を実行します。 両方の値が (100000) 程度の場合、つまり約 (10^{10}) 回の比較となり、1 秒の制限時間でサポートできる比較をはるかに超えます。 

有益な観察は、クエリ キーが州名そのものであるということです。 データベースの順序を維持する必要はなく、範囲や数値プロパティによって検索する必要もありません。 「この文字列に属する値は何ですか?」という形式の完全に等しいクエリに答えるだけで済みます。 ハッシュ テーブルは、この操作のために正確に設計されています。 

各ペアを次のように保存できます。`speed[state] = limit`。 辞書が構築されると、状態の検索には予想される (O(1)) 時間がかかります。 データベースの読み取りには (O(S)) かかり、すべてのクエリへの応答には予想される時間 (O(T)) がかかります。 ブルートフォース法と最適化法は同じ論理演算を実行しますが、辞書によって一致状態の見つけ方が異なります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(ST)) | (O(S)) | 大量の入力には遅すぎる |
 | ハッシュテーブル | 期待される (O(S + T)) | (O(S)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. データベース内の状態の数 (S) を読み取ります。 この値は、後に続くデータベース レコードの数を知るためにのみ必要です。 
2. 空の辞書を作成します。 今後のすべてのクエリから州名が得られるため、州名がキーとなり、その速度制限が関連する値となります。 
3. (S) データベース レコードをそれぞれ読み取ります。 行を州名とその整数の制限速度に分割し、そのペアを辞書に保存します。 このフェーズの後は、すべての状態をその名前から直接見つけることができます。 
4. クエリの数 (T) を読み取ります。 次の各行には州名が 1 つだけ含まれます。 
5. すべてのクエリについて、辞書で州名を検索し、対応する速度制限を出力に追加します。 回答を追加して一緒に印刷すると、不必要な繰り返しの出力操作を回避できます。 
6. 収集したすべての回答を 1 行に 1 つずつ出力します。 クエリが処理されると回答が追加されるため、この順序はクエリの順序とまったく同じです。 

### なぜ効果があるのか

 不変条件は、データベースの処理後、辞書に入力内の各州の保存された速度制限が含まれることです。 クエリで州に名前を付けると、辞書検索により、まさにその名前に関連付けられた値が取得されます。 クエリの応答中にデータベースが変更されることはないため、クエリを繰り返すと毎回同じ値が取得されます。 したがって、印刷されたすべての数字は、照会された州に属する制限速度です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = int(input())
    speed = {}

    for _ in range(s):
        name, limit = input().split()
        speed[name] = int(limit)

    t = int(input())
    answer = []

    for _ in range(t):
        name = input().strip()
        answer.append(str(speed[name]))

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```辞書`speed`ステップ 2 で説明した州名から速度制限へのマッピングを実装します。データベース ループは正確に (S) レコードを読み取り、数値フィールドを整数に変換してから保存します。 

クエリ ループは正確に (T) 名前を読み取ります。`strip()`各入力行の末尾にある改行を削除し、辞書キーとして使用される州名を残します。 州名にはスペースが含まれていないため、`strip()`または`split()[0]`ここで働くだろう。 

回答は文字列として保存されるため、改行文字で結合して一度に書き込むことができます。 これは電話するよりも望ましいです`print`クエリの数が多い場合は、クエリごとに。 

Python の整数はオーバーフローしないため、速度制限値に特別な処理は必要ありません。 実装の主な詳細は、正確な州名を辞書キーとして保持することです。 入力内の州名は識別子であり、大文字と小文字を区別しないテキストではないため、大文字と小文字は正規化されません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 期待される (O(S + T)) | 各データベース エントリは 1 回挿入され、各クエリは予想される定数時間ハッシュ ルックアップを 1 回実行します。 |
 | スペース | (O(S)) | ディクショナリには、データベースの状態ごとに 1 つのマッピングが保存されます。 |

 このソリューションは、各入力レコードを一定の回数だけ処理します。 (S) と (T) の値が非常に大きい場合でも、作業量は 2 つのサイズを乗算するのではなく、入力に応じて直線的に増加します。 これは、1 秒の時間制限と 256 MB のメモリ制限に適した複雑さです。

        speed[name] = int(limit)

    t = int(input())
    answer = []

        name = input().strip()

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 辞書検索は読み取り専用であるため、繰り返しクエリのケースは自然に処理されます。 のために```
2
Texas 85
Hawaii 60
3
Texas
Texas
Hawaii
```最初`Texas`ルックアップの戻り値`85`、2 番目は同じ検索を実行し、再び返します。`85`、 そして`Hawaii`返品`60`。 最終的な出力は次のとおりです`85`、`85`、`60`。 検索後に辞書からは何も削除されません。 

最小サイズの場合には、データベース レコードが 1 つとクエリが 1 つだけ含まれます。```

1
A
```アルゴリズムが挿入する`A -> 1`、すぐに取得します`1`。 出力は`1`。 1 エントリの辞書はより大きな辞書とまったく同じように動作するため、実装には特別なケースはありません。

大きな数値も直接処理されます。 と```

LongState

最後に、クエリの数が多くても、ソリューション内のクエリの数に比例してメモリが増加するわけではありません。 辞書にはデータベースが含まれ、回答リストには出力文字列が含まれます。 ルックアップ自体は平均して一定時間であるため、クエリが繰り返されたり、非常に集中したりしても、漸近的な実行時間は変わりません。
