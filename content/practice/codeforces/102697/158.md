 ## 問題の理解

 タスクは通常の行列の乗算です。 入力は 2 つの長方形行列を記述します。`m1`そして`m2`。 最初の 4 つの整数は、2 つの行列の幅と高さをこの順序で示します。 の列`m1`最初に指定され、その直後に次のすべての行が続きます。`m2`。 

仮定する`m1`高さがある`H1`と幅`W1`、 その間`m2`高さがある`H2`と幅`W2`。 行列乗算を定義するには、次の列の数が必要です。`m1`の行数と等しくなければなりません`m2`、 それで`W1 = H2`。 結果は、`H1`行と`W2`列。 行のエントリ`i`そしてコラム`j`行を取得することで取得されます`i`の`m1`、 カラム`j`の`m2`、対応する値を乗算し、それらの積を加算します。 

たとえば、```
m1 = [1 2]
     [3 4]

m2 = [5 6]
     [7 8]
```左上の結果は`1 * 5 + 2 * 7 = 19`、右下の結果は`3 * 6 + 4 * 8 = 50`。 したがって、完全な結果は次のようになります。```
19 22
43 50
```公開された声明では、行列の次元や要素の値に対する明示的な数値の上限は示されていません。 指定されているのは、1 秒の時間制限と 256 MB のメモリです。 直接行列乗算アルゴリズムは、結果行、共有次元位置、および結果列で構成されるトリプルごとに 1 つの乗算と 1 つの加算を実行するため、その実行時間は次のようになります。`O(H1 * W1 * W2)`。 ステートメントで使用できる強力な次元制約がないため、推論する正当な二次二次または最適化された行列乗算の要件はありません。 意図された解決策は、標準的なトリプルループ乗算です。 

不注意な実装で間違いが明らかになる可能性のある入力状況がいくつかあります。 1 行または 1 列のみの行列は、単純な境界ケースです。 例えば、```

```生成する```

```乗算する値のペアが 1 つだけあるためです。 少なくとも 2 つの行または列を想定した実装は、ここで失敗する可能性があります。 

長方形行列もインデックス付けエラーの一般的な原因です。 例えば、```

```生成する```

```単一行なので`[1, 2, 3]`2 番目の行列の各列に対して乗算されます。 コードが誤って最初の次元を幅ではなく行数として扱うと、行列が正しく読み取られません。 

行列自体が空でない場合でも結果にゼロが含まれる可能性があるため、ゼロ値も重要です。 例えば、```

0 0
5

```生成する```

```各結果セルをゼロからではなく最初の積から初期化する不注意な実装では、このようなケースで誤った結果が生じる可能性があります。

## アプローチ

 直接的なアプローチは、行列乗算の数学的定義に正確に従います。 すべての結果セルについて`(i, j)`、共有ディメンションを反復処理します。`k`そして追加します`m1[i][k] * m2[k][j]`答えに。 これは正しいです。行列の乗算の定義は、まさに対応する行と列の間のドット積であるからです。 

もし`m1`寸法があります`H1 × W1`そして`m2`寸法があります`W1 × W2`、 がある`H1 * W2`結果のセル。 1 つのセルを計算するとすべてのセルが検査されます`W1`位置を共有しているため、乗算演算の合計数は正確に次のようになります。`H1 * W1 * W2`。 加算も同様の順序で行われます。 サイズの正方行列の場合`n`、これは次のようになります`n^3`操作。 

ここでは、総当たりの説明と最適解は事実上同じです。 この問題で利用する必要がある行列には追加の構造はなく、ステートメントにはスパース性、バイナリ値、クエリの繰り返しなどの特別な制限もありません。 重要な観察は、2 つの入力行列が読み取られると、各結果エントリが独立しているということです。 すべてのエントリは、対応する行と列から直接計算できます。 

実装では、次の転置を明示的に構築できます。`m2`行と行のドット積を取得するか、アクセスします。`m2[k][j]`最も内側のループのすぐ内側。 後者は、別の行列を保存することを回避し、この基本的な問題によって予想される次元に対してすでに十分に簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(H1 * W1 * W2)`|`O(H1 * W1 + W1 * W2 + H1 * W2)`| 承認済み |
 | 最適 |`O(H1 * W1 * W2)`|`O(H1 * W1 + W1 * W2 + H1 * W2)`| 承認済み |

 ここで、問題は完全な行列積を直接要求するため、「総当たり」と「最適」は同じ漸近的な複雑さを持ちます。 有用な最適化とは、実装を明確にし、不必要な作業を回避することであり、異なる漸近アルゴリズムではありません。 

## アルゴリズムのチュートリアル

 1.読む`W1`、`H1`、`W2`、 そして`H2`。 幅は各行の値の数であり、高さは行の数です。`m1`もっている`H1`行と`m2`もっている`H2`行。 行列乗算には次のことが必要です`W1 = H2`。 
2.読む`H1`行、それぞれに含まれる行`W1`値を作成し、次のように保存します。`m1`。 行をそのまま保持すると、アクセスできるようになります。`m1[i][k]`直接。 
3. 読む`H2`行、それぞれに含まれる行`W2`値を作成し、次のように保存します。`m2`。 に直接アクセスする必要があります`m2[k][j]`結果セルの計算中`(i, j)`。 
4. 次の結果行列を作成します。`H1`行と`W2`列。最初はゼロで埋められます。 すべての結果エントリは積の合計であるため、一部の行列値が負の場合でも、ゼロが正しい開始値となります。 
5. すべての結果行について`i`、すべての結果列を反復処理します。`j`。 これら 2 つのインデックスは、出力行列の 1 つのセルを完全に識別します。 
6. 選ばれた者のために`(i, j)`、反復します`k`から`0`を通して`W1 - 1`そして追加します`m1[i][k] * m2[k][j]`結果に。 インデックス`k`行から一致するコンポーネントを選択します`i`最初の行列と列の`j`2番目の行列の。 
7. 結局のところ`k`値が処理されると、結果のセルには選択した行と列のドット積が正確に含まれます。 ごとに繰り返します`(i, j)`完成したマトリックスを印刷します。 

### なぜ効果があるのか

 最も内側のループの不変条件は、位置を処理した後のものです。`0`を通して`k - 1`、現在の結果セルには以下が含まれます`m1[i][0] * m2[0][j] + ... + m1[i][k-1] * m2[k-1][j]`。 

最初はポジションが処理されていないため、合計はゼロになります。 各反復では、不変条件を維持しながら、次に必要な積が追加されます。 結局`W1`位置が処理され、セルには行の完全な内積が含まれます。`i`の`m1`そしてコラム`j`の`m2`。 アルゴリズムはこれを出力位置ごとに独立して実行するため、生成された行列のすべてのセルは数学的に正しい値を持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    w1, h1, w2, h2 = map(int, input().split())

    m1 = [list(map(int, input().split())) for _ in range(h1)]
    m2 = [list(map(int, input().split())) for _ in range(h2)]

    result = [[0] * w2 for _ in range(h1)]

    for i in range(h1):
        for j in range(w2):
            total = 0
            for k in range(w1):
                total += m1[i][k] * m2[k][j]
            result[i][j] = total

    sys.stdout.write(
        "\n".join(" ".join(map(str, row)) for row in result)
    )

if __name__ == "__main__":
    solve()
```最初の行は次のように読み取られます`width, height`マトリックスごとに。 この順序は実際の入力形式に従い、高さの前に幅が与えられます。 それらの値を次のように変換すると、`w1`、`h1`、`w2`、 そして`h2`行と列を逆にするというよくある間違いを防ぎます。 

最初のリスト内包表記は正確に読み取れます`h1`の行`m1`、各行には次の内容が含まれることが期待されます`w1`価値観。 2 番目も同じことを行います`m2`。 2 番目の行列には`h2 = w1`行、`m2[k]`すべての場合に有効です`k`乗算ループによって使用されます。 

結果の行列は次のようになります。`h1`行と`w2`行列の乗算では最初の行列の行数と 2 番目の行列の列数が保持されるためです。 すべてのセルは、そのドット積が累積される前にゼロから始まります。 

最も内側の式では、`m1[i][k] * m2[k][j]`。 最初のインデックス ペアは、`m1`、2番目は次の列にアクセスします。`m2`。 これらのインデックスのいずれかを交換することは、行列乗算の古典的なバグです。 

Python の整数には任意の精度があるため、乗算や累算による整数のオーバーフローの問題はありません。 

決勝戦`join`値の間にスペースを入れて、結果行ごとに 1 つの出力行を生成します。 また、各行の末尾にある不要な末尾のスペースも避けられます。
