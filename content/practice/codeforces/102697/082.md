 ## 問題の理解

 タスクは、1 つの文字列を検査し、その文字列の先頭に繰り返しパターンが含まれているかどうかを判断することです。 パターンは位置 0 から始まり、長さが少なくとも 2 で、完全に少なくとも 2 回出現する必要があります。 これら 2 つ以上の完全なコピー以降の文字は無関係です。 例えば、`hellohelloasd`接頭辞があるため、これは有効です`hello`2回表示されますが、`asd`単なる末尾のテキストです。 求められている答えはまさに`True`または`False`。 

入力文字列の長さが (n) であると仮定します。 (k \ge 2) と (2k \le n) を使用して、最初の (k) 文字が次の (k) 文字と等しくなるようなパターン長 (k) があるかどうかを判断する必要があります。 このステートメントでは文字列の長さの明示的な上限が提供されていないため、最も安全なアプローチは入力サイズを線形にすることです。 二次解法は小さな文字列には機能する可能性がありますが、最悪の場合、おおよそ (n^2/2) 文字の比較が行われ、非表示のテストに長い文字列が含まれている場合には有用な保証がありません。 1 秒の制限があるため、(O(n)) 個のソリューションが自然なターゲットになります。 

短い文字列は誤った仮定を立てやすい場所です。 入力用`abc`、答えは`False`少なくとも 2 つ以上の長さのパターンのコピーを 2 つ含めるのに十分な文字がないためです。 繰り返される文字のみを検索する不注意なソリューションでは、誤って受け入れられる可能性があります。 

入力用`aaaa`、答えは`True`。 パターンとしては、`aa`, 2回登場します。 文字列全体が 1 つのパターンの正確に 2 つのコピーであることを必要とする解決策は、この特定のケースを受け入れますが、次の場合には失敗します。`hellohelloasd`、無関係な末尾文字が許可されます。 

入力用`ababx`、答えは`True`なぜならプレフィックスは`ab`2回発生し、最後に`x`無視できます。 文字列全体の長さがパターンの長さで割り切れなければならないと主張するソリューションは、誤って次のエラーを返します。`False`。 

入力用`abcabc`、答えは`True`、 と`abc`繰り返されるパターンとして。 パターンの長さは必ずしも 2 であるとは限らないため、最初の 2 文字だけをチェックするだけでは不十分です。 

## アプローチ

 直接的な総当たりアプローチでは、2 から (n/2) までのすべての可能なパターン長 (k) が試行されます。 各 (k) について、最初の (k) 文字と位置 (k) で始まる部分文字列が比較されます。 それらが等しい場合、答えはすぐに得られます`True`。 これは正しいです。考えられる有効なパターンはすべて、そのような長さ (k) を 1 つだけ持ち、2 つのコピーが位置 ([0,k)) と ([k,2k)) を占有する必要があるからです。 

このアプローチの問題は、繰り返し作業が行われることです。 文字列の長さが (n) の場合、1 つの候補をテストすると (k) 文字を検査でき、候補の合計サイズは大きくなります。 

[
 2 + 3 + 4 + \dots + \left\lfloor\frac n2\right\rfloor,
 】

 これは (O(n^2)) であり、最悪の場合でも約 (n^2/8) 回の比較になります。 (100,000) 文字の文字列の場合、数十億の文字を比較することになります。 

重要な観察は、すべての候補パターンが文字列のプレフィックスであるということです。 すべての接頭辞を後続の部分文字列と個別に比較する代わりに、Z 関数を使用して文字列を前処理できます。 Z 値は、すべての位置 (i) について、(i) で始まる文字が文字列全体のプレフィックスと一致する数を示します。 

ここで、長さ (k) の候補パターンを考えます。 最初の (k) 文字と一致するには、(k) で始まる部分文字列が必要です。 まさにその条件です

 [
 Z[k] \ge k.
 】

 Z 関数は、これらのプレフィックス一致の長さをすべて線形時間で計算します。 2 つの完全なコピーが文字列に収まる必要があるため、2 から (n/2) までの (k) のみを検査します。 すべての有効なパターンがプレフィックスであるという観察により、繰り返される部分文字列比較を 1 回の線形前処理パスに減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取り、終了の改行のみを削除します。 文字列自体は分析対象の完全なオブジェクトであるため、入力形式で明示的に許可されていない限り、文字列内の空白を破棄する必要はありません。 
2. 文字列が 4 文字未満の場合は、すぐに戻ります。`False`。 有効なパターンには少なくとも 2 文字が必要で、2 回出現する必要があるため、少なくとも 4 文字が必要です。 
3. Z 配列を計算します。 ポジションごとに`i`、`z[i]`で始まる最長の部分文字列の長さです。`i`これは文字列全体の接頭辞でもあります。 
4. 考えられるすべてのパターン長を検査する`k`2から`n // 2`。 上限により、ある長さの 2 つの完全なコピーが保証されます。`k`パターンが入力内に収まります。 
5. もし`z[k] >= k`、 戻る`True`。 位置から開始`k`、文字列は少なくともプレフィックスと一致します`k`文字、つまり位置`[0,k)`そして`[k,2k)`同一の文字列が含まれています。 位置の後の任意の文字`2k`一致しないままにすることができます。 
6. 条件を満たす長さの候補がない場合は、リターンします。`False`。 考えられるすべてのパターン長がチェックされているため、有効な反復プレフィックスは存在しません。 

### なぜ効果があるのか

 不変条件とは、`z[k]`位置から始まる文字列の量を正確に測定します`k`元のプレフィックスと一致します。 長さのパターン`k`は、最初のときに正確に有効です`k`登場人物とその次`k`文字は同一です、まさにその通りです`z[k] >= k`。 あらゆる可能性をチェックします`k >= 2`したがって、考えられるすべての有効なパターンが考慮されます。 条件を満たす場合、アルゴリズムは真に繰り返されるプレフィックスを受け入れます。 存在しない場合、有効なパターンは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def has_pattern(s):
    n = len(s)

    if n < 4:
        return False

    z = [0] * n
    left = right = 0

    for i in range(1, n):
        if i <= right:
            z[i] = min(right - i + 1, z[i - left])

        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1

        if i + z[i] - 1 > right:
            left = i
            right = i + z[i] - 1

    for k in range(2, n // 2 + 1):
        if z[k] >= k:
            return True

    return False

s = input().rstrip("\n")
print("True" if has_pattern(s) else "False")
```の`has_pattern`関数は最初に可能な最小の長さを処理します。 後のループでもそのような文字列が拒否されるため、これは厳密には必要ありませんが、境界条件が明示的になり、不必要な前処理が回避されます。 

Z アレイは標準を使用して構築されています。`[left, right]`Zボックス。 現在の位置がそのボックス内にある場合、その Z 値の一部は以前のプレフィックス比較からすでにわかっています。 の`while`ループは、追加の文字が実際に一致する場合にのみ、既知の一致を拡張します。 

アップデート`right = i + z[i] - 1`包括的な右エンドポイントを使用します。 1の引き算は間違いやすいです。 たとえば、次の場合`z[i] == 3`、マッチング間隔は次の時点で終了します。`i + 2`、 ない`i + 3`。 

最終ループは次から始まります`2`1 文字のパターンは禁止されているためです。 で止まります`n // 2`長いパターンは完全に 2 回発生することはできないためです。 テスト`z[k] >= k`末尾の文字を許可します。これは、繰り返しセクションの後のテキストが無視されるという要件を直接実装します。 

Python の整数はオーバーフローせず、アルゴリズムは文字列と 1 文字につき 1 つの整数のみを保存します。 入力には 1 つの文字列が含まれるため、テストケース ループは必要ありません。

## テストケース```python
import sys
import io

def solve_string(s):
    n = len(s)

    if n < 4:
        return "False"

    z = [0] * n
    left = right = 0

    for i in range(1, n):
        if i <= right:
            z[i] = min(right - i + 1, z[i - left])

        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1

        if i + z[i] - 1 > right:
            left = i
            right = i + z[i] - 1

    for k in range(2, n // 2 + 1):
        if z[k] >= k:
            return "True"

    return "False"

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().rstrip("\n")
    return solve_string(s) + "\n"

# Provided sample
assert run("hellohelloasd\n") == "True\n", "sample 1"

# Minimum-size strings
assert run("a\n") == "False\n", "too short"
assert run("abcd\n") == "False\n", "minimum length capable of a pattern"

# Smallest true case: pattern "ab" repeated twice
assert run("abab\n") == "True\n", "minimum valid repeated pattern"

# All characters equal
assert run("aaaaaa\n") == "True\n", "many possible repeated patterns"

# Trailing text after the repeated prefix
assert run("ababxyz\n") == "True\n", "trailing text must be ignored"

# Repeated prefix of length greater than two
assert run("abcabc\n") == "True\n", "pattern length three"

# Looks repetitive, but no complete repeated prefix exists
assert run("abacaba\n") == "False\n", "no valid repeated prefix"

# Large boundary-style input
assert run("a" * 100000 + "\n") == "True\n", "large input"

 ## 特殊なケース

 4 文字より短い文字列には、長さが 2 以上のパターンのコピーを 2 つ含めることはできません。 例えば、`abc`生成する`False`。 アルゴリズムはすぐに戻ります。`n < 4`、無効な候補パターン長へのアクセス試行を回避します。 

のために`abab`、考えられる唯一の候補は`k = 2`。 位置 2 の Z 値は 2 です。これは、そこから始まるサフィックスが正確に一致するためです。`ab`。 以来`z[2] >= 2`、アルゴリズムは戻ります`True`。 これにより、ソリューションが誤ってパターン長のテストを 3 で開始する下限エラーが捕捉されます。 

のために`ababxyz`、 同じ`k = 2`テストは成功します。 Z 値はサフィックス全体の長さと一致する必要はなく、必要なパターンの長さのみと一致する必要があります。 最初の 4 文字が次のとおりであるため、アルゴリズムは受け入れます。`abab`、 その間`xyz`無視することが許されています。 

のために`abcabc`、候補者`k = 2`失敗しますが、`k = 3`もっている`z[3] = 3`。 アルゴリズムは、パターンが可能な限り短い長さでなければならないと仮定するのではなく、より小さい候補を通過して続行し、正しく返します。`True`。 

のために`aaaaaa`、いくつかのパターンの長さが機能します。`k = 2`最初の 2 文字が次のとおりであるため、すでに成功しています。`aa`そして次の2つも`aa`。 アルゴリズムは最初の有効な長さを見つけるとすぐに戻るため、考えられるすべてのパターンを識別する必要はありません。 

完全に以下のものからなる大規模な入力の場合`a`、100000部など`a`、Z 関数は長いプレフィックスの一致を線形時間で計算します。 二次解では大きな同一のプレフィックスを繰り返し比較しますが、Z ボックスはそれらの比較を再利用します。 最適化されたアルゴリズムは、入力長に比例した数の操作の後に終了します。
