 ## 問題の理解

 良いコンテストの後、あなたの評価は正の整数になります`n`、この評価はディビジョン 1 に入れるのに十分な高さです。Codeforces では、少なくとも の評価を考慮します。`1900`その後のコンテストが終わるたびに、あなたの評価はちょうど 1 ずつ下がります。`50`。 

課題は、ディビジョン 1 に留まりながら今後何回のコンテストに参加できるかを決定することです。つまり、レーティングが最初に厳密に下回るまでに必要なコンテストの数を決定することです。`1900`。 公式の例は次のとおりです`1970 -> 2`、`2035 -> 3`、 そして`3549 -> 33`。 

入力には 1 つの整数が含まれています`n`、コンテストが成功した直後の評価を表します。 出力は 1 つの整数で、レーティングがディビジョン 2 に入るまでの後続のコンテストの数です。ステートメントは、記載されている状況を保証するため、開始レーティングは少なくとも`1900`。 

ここには大きな組み合わせ構造はありません。 制限時間は 1 秒だけですが、計算全体は数回の整数演算に減ります。 シミュレーションは論理的には有効ですが、その実行時間は評価自体に応じて長くなります。 このステートメントは有用な有限の上限を与えていないため、`n`、反復回数が以下に依存するアルゴリズム`n`意味のある最悪の場合の保証はありません。 定数時間の算術公式が当然の目標です。 

主な境界ケースはまさに次のとおりです`1900`。 のために```
1900
```正しい出力は```
1
```なぜなら、1回のコンテストの後、評価は次のようになります。`1850`、これはディビジョン 2 です。ディビジョン 1 のレーティングで終了するコンテストのみをカウントする不注意な実装により、リターンが返される可能性があります。`0`、しかし、要求されたコンテストはまさに、評価が境界を越えた後のコンテストです。 

その他の微妙なケースは正確に評価されます`50`境界の上の点。 のために```
1950
```正しい出力は```
1
```最初のコンテストでレーティングが正確に変更されるため、`1900`、まだディビジョン 1 ですが、次のコンテストではディビジョン 1 に入るでしょう。`1850`。 答えは、ディビジョン 2 になるまでに残りのコンテストが何回あるかを尋ねるため、答えは次のようになります。`1`、 ない`2`。 これは、条件が正しく記述されていない場合に、off-by-one エラーが発生する一般的な原因です。 

より大きな例としては、次のようなものがあります。```

3
```なぜなら、連続したコンテスト後の評価は`1985`、`1935`、 そして`1885`。 3 番目のコンテストは、ディビジョン 2 のレーティングを生成する最初のコンテストです。 

## アプローチ

 直接的なアプローチは、コンテストをシミュレートすることです。 電流定格から開始し、繰り返し減算します。`50`評価が小さくなるまで`1900`、実行された減算の数を数えます。 これは正しいです。シミュレーションは、問題で説明されているレーティングの変化に正確に従っており、最初にループが停止するのは、プレーヤーがディビジョン 2 に初めて参加するときとまったく同じであるためです。 

開始時の評価が`n`。 シミュレーションが実行される

 [
 \左\lf階\frac{n-1900}{50}\右\r階+1
 】

 繰り返し。 入力には明示的な上限がないため、この数値は任意に大きくすることができます。 個々の反復は低コストですが、アルゴリズムは開始評価に線形依存しており、答え自体は直接計算できます。 

重要な観察は、その後です。`c`コンテスト、評価は

 [
 n-50c。 
】

 この値が以下の場合、正確にディビジョン 2 になります。`1900`:

 [
 n-50c < 1900。 
】

 並べ替えると

 [
 50c > n-1900。 
】

 この不等式を満たす最小の正の整数は次のとおりです。 

[
 c=\left\lfloor\frac{n-1900}{50}\right\rfloor+1。 
】

 の`+1`厳密な不等式を扱います。 もし`n-1900`はすでに次の倍数です`50`、プレーヤーはまだ正確にレーティングにいます`1900`その後多くのコンテストが行われるため、ディビジョン 2 に参加するにはさらに 1 つのコンテストが必要です。 

シミュレートされたすべてのステップが 1 つの実際のコンテストに対応するため、総当り攻撃は機能しますが、コンテストの数が多い場合は失敗します。 評価が毎回一定量ずつ変化するという観察により、シミュレーション全体を 1 つの除算と 1 つの加算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 開始定格を読む`n`。 この問題はディビジョン 1 に入ったばかりのプレイヤーについて説明しているため、`n >= 1900`。 
2. コンピューティング`(n - 1900) // 50`。 これにより、完全に減少した回数がわかります。`50`開始レーティングとディビジョン 1 境界の間に適合します。 
3.追加`1`その値に。 正確に到達するため、追加のコンテストが必要です`1900`ディビジョン 1 を終了しません。ディビジョン 2 は以下からのみ開始します`1900`。 
4. 結果のカウントを出力します。 

### なぜ効果があるのか

 後`c`コンテスト、評価は正確です`n - 50c`。 この数量が以下になると、プレイヤーはディビジョン 2 に参加します。`1900`。 コンプリート数は最多`50`・最低残存期間中に発生する可能性のあるポイント減少`1900`は`(n - 1900) // 50`。 次のコンテストでは必ず評価が下に押し上げられます`1900`、したがって、必要なコンテストの数は正確に`(n - 1900) // 50 + 1`。 また、整数の除算では完全な減少が破棄され、最後の除算では等価境界も正しく処理されます。`+1`は境界を越える最初の減少を表します。

表現`(n - 1900) // 50`の完全なグループをカウントします`50`間の点`n`そして`1900`。 Python の整数除算はまさにここで必要なものです。なぜなら、答えは境界に到達する前に完全な減少が何回発生するかによって決まるからです。 
決勝戦`+ 1`実装の微妙な部分です。 のために`n = 1900`、商は`0`、したがって、答えは次のようになります`1`。 のために`n = 1950`、商は`1`, したがって、答えも次のようになります。`1`。 後者の場合、1 つのコンテストは以下から評価を取得します。`1950`に`1900`、ディビジョン 2 に到達するには次のコンテストが必要になります。これは、回答が移行前にまだ実行できるコンテストをカウントするという解釈と一致します。 

Python の整数には任意の精度があるため、入力定格が非常に大きい場合でもオーバーフローの問題は発生しません。
