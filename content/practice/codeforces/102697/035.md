 ## 解決策
 ## 問題の理解

 を含むリストがあります`n`タスクは、少なくとも 1 回出現する異なる値の数を判断することです。 値の位置は関係ありません。 たとえば、リスト`2 2 3 5 6`4 つの異なる値が含まれています`2`、`3`、`5`、 そして`6`、したがって、答えは次のとおりです`4`。 

公式の問題ページでは制限時間は 1 秒、メモリは 256 MB とされていますが、公開された声明では上限が指定されていません。`n`またはリスト内の整数値の場合。 この限界が欠けているということは、二次スキャンに依存するのではなく、実行時間が入力値の数において線形または線形に近いアルゴリズムを選択する必要があることを意味します。 Python はこの設定で数十万の単純な操作を快適に処理できますが、二次アルゴリズムはすぐに数十億の比較に到達できます。 

主なエッジ ケースは、繰り返される値や隣接しない値から発生します。 考慮する`1`に続く`1`:```
1
1
```正しい出力は次のとおりです`1`。 すべての位置をカウントする不注意なアルゴリズムでは、次のような出力が出力されます。`1`ここでは偶然ですが、違いは次のようになります。`4`コピー:```
4
7 7 7 7
```正しい出力は次のとおりです`1`異なる値が 1 つしかないためです。 個別の値ではなく出現回数をカウントすると、誤って生成される`4`。 

重複は他の値で区切ることもできます。```
5
1 2 1 3 2
```正しい出力は次のとおりです`3`、個別の値は次のとおりであるため、`1`、`2`、 そして`3`。 隣接する要素のみを比較するアプローチでは、2 番目の要素が誤って処理されます。`1`そして二番目`2`新しい価値観として。 

最後に、すべての要素はすでに異なるものにすることができます。```
4
1 2 3 4
```正しい出力は次のとおりです`4`。 誤って多くの値を削除したり、繰り返しのみをカウントしたりする実装は、この場合に失敗する可能性があります。 

## アプローチ

 直接的な総当たりの解決策は、すべての値を調べて、それより前のすべての値と比較することです。 ポジションごとに`i`、位置をスキャンできます`0`を通して`i - 1`そして、現在の値が以前に出現したかどうかを判断します。 そうでない場合は、答えをインクリメントします。 これは正しいです。値は、その値が出現する最初の位置で 1 回だけ寄与するからです。 

問題は比較の回数です。 最悪の場合、すべての値が異なる場合、最初の値は比較する必要がなく、2 番目の値は 1 つ、3 番目の値は 2 つ、というようになります。 合計は`0 + 1 + 2 + ... + (n - 1) = n(n - 1)/2`比較。 のために`n = 100000`、つまり`4,999,950,000`これは、1 秒のソリューションが合理的に実行できるものをはるかに超えています。 

重要な観察は、値がどこに出現したか、あるいは何回出現したかは実際には気にしていないということです。 「この値をすでに見たことがありますか?」という質問に「はい」または「いいえ」で答えるだけで済みます。 ハッシュ セットは、まさにこの操作のために設計されています。 リストを 1 回スキャンするときに、以前に表示されていないすべての値をセットに挿入します。 最終的に、セットのサイズは正確に個別の値の数になります。 

ブルートフォースは、以前の位置を明示的にチェックすることで値が以前に出現したかどうかを知ることができるため機能しますが、リストが大きい場合は同じ履歴が繰り返し検索されるため失敗します。 履歴がセットによって要約できるという観察により、繰り返されるすべてのスキャンを予期される定数時間のメンバーシップ チェックに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | n が大きいと遅すぎます |
 | ハッシュセット | O(n) が予想されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`n`整数。 各値を検査する必要があるのは 1 回だけであるため、元の位置に関する情報を保持する必要はありません。 
2. という空のセットを作成します。`seen`。 このセットは、これまでに遭遇した値を正確に表しています。 
3. 値を左から右にスキャンします。 現在の値が入っていない場合`seen`、挿入します。 値は最初に出現したときにのみ挿入されるため、すべての個別の値はセットに 1 つの要素だけを提供します。 
4. すべての値が処理されたら、印刷します。`len(seen)`。 このセットには、入力内の異なる整数ごとに 1 つの要素が含まれるため、そのサイズが必須の答えとなります。 

不変条件は、最初の処理後の`i`価値観、`seen`最初の値の間で正確に異なる値が含まれています`i`価値観。 最初は両方のセットが空です。 次の値がすでに確認されている場合、セットは正しいままです。 新しい場合、これを追加すると、これまでに確認された個別の値が正確にセットに含まれます。 帰納法により、最終値の後、セットには配列全体のすべての個別の値が含まれ、それ以外は何も含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    values = list(map(int, input().split()))

    seen = set(values)
    print(len(seen))

if __name__ == "__main__":
    solve()
```最初の行は値の数を読み取り、2 行目は配列を読み取ります。 ステートメントはすべてを配置します`n`次の行に値があるので、1 つ`input()`公式形式には call で十分です。 

表現`set(values)`個別値操作全体を直接実行します。 Python のセットはハッシュ テーブルによってサポートされているため、整数の挿入と検索には予想される O(1) 時間がかかります。 決勝戦`len`動作も一定時間です。 

配列をソートする必要はありません。 並べ替えによっても O(n log n) の問題が解決されますが、個別の値の順序は無関係であるため、必要以上の作業が実行されます。 また、各値の出現回数は要求されないため、頻度辞書も必要ありません。 

このコードでは、値が正であることや、小さな定数によって制限されることは想定されていません。 公開されたステートメントでは、数値範囲を指定せずにそれらを整数としてのみ説明しているため、Python のセットは、負の値またはゼロが発生した場合でも安全な表現です。

## テストケース

 公式サンプルは以下に含まれています。 公表された声明には上限が明記されていないため、`n`、大きなカスタムケースでは、`100000`これが公式の最大値であると主張するのではなく、ストレステストとしての値を使用します。```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    values = list(map(int, input().split()))
    print(len(set(values)))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run("5\n2 2 3 5 6\n") == "4\n", "sample 1"

# Provided sample 2
assert run("4\n1 2 3 4\n") == "4\n", "sample 2"

# Minimum-size input
assert run("1\n42\n") == "1\n", "minimum size"

# All values equal
assert run("6\n9 9 9 9 9 9\n") == "1\n", "all equal"

# Values can repeat non-consecutively and can include zero/negative integers
assert run("7\n-3 0 5 -3 0 8 5\n") == "4\n", "non-consecutive duplicates"

# Large stress case, 100000 distinct values
large_values = list(range(100000))
assert run(
    "100000\n" + " ".join(map(str, large_values)) + "\n"
) == "100000\n", "large distinct input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`に続く`42`|`1`| 可能な最小入力サイズ |
 |`6`続いて6`9`s |`1`| すべての値は同一です |
 |`7`に続く`-3 0 5 -3 0 8 5`|`4`| 連続しない重複と一般的な整数値 |
 |`100000`に続く`0`を通して`99999`|`100000`| 線形時間ストレスが大きいケース |

 ## 特殊なケース

 単一要素リストの場合、次のようになります。```
1
42
```セットは空で始まり、受信します`42`、サイズで終わります`1`。 このアルゴリズムは比較する要素のペアに依存しないため、特殊な場合がなくても最小の有効な入力が機能します。 

重複のみを含む配列の場合、```
4
7 7 7 7
```最初`7`が挿入されますが、残りの 3 つの値はすでに存在します。 最終セットは、`{7}`したがって、出力は次のようになります`1`。 これは、個別の値ではなく位置をカウントすると間違った結果が生じるケースを直接処理します。 

他の値で区切られた重複の場合、```
5
1 2 1 3 2
```最初`1`そして最初に`2`が挿入され、2 番目の`1`無視されます、`3`が挿入され、最後に`2`無視されます。 結果のセットは次のとおりです`{1, 2, 3}`、出力を与える`3`。 このため、隣接する要素の比較では不十分です。 

すべての値が異なる配列の場合、```
4
1 2 3 4
```値が以前に出現したことがないため、すべてのメンバーシップ チェックは失敗します。 4 つの値すべてがセットに入力され、答えは次のようになります。`4`。 このケースは、すべての新しい値が以前のすべての位置をスキャンする必要があるため、ブルート フォース手法の最悪のケースでもあります。 

この実装では、ゼロや負の整数などの値も変更せずに処理します。 例えば、```
5
-2 0 -2 7 0
```生成する`3`、セットになるので、`{-2, 0, 7}`。 人為的な値の範囲や直接アドレスの配列は必要ないため、公開されている問題ステートメントで明示されていない数値の範囲から解決策を独立させることができます。
