 ## 解決策
 ## 問題の理解

 正の整数のリストが与えられます。 整数を 1 つだけ削除する必要があり、その後、残りのすべての整数を乗算します。 削除された整数のすべての可能な選択肢の中で、可能な限り最大の積を出力する必要があります。 

重要な条件は、すべての値が正であることです。 これにより、ゼロまたは負の数値で表示される合併症が削除されます。 値を削除すると`x`、結果の積には 1 つおきの値が含まれます。 すべての値は正であるため、より小さい値を削除すると、より大きな値を削除するよりも大きな積が残ります。 したがって、問題全体は、リスト内の最小の整数を見つけて、他のすべての整数を乗算することに帰着します。 

この声明では有用な上限は公表されていない。`n`問題ページに進みますが、制限時間はわずか1秒です。 省略される可能性のあるすべての要素に対して個別の積計算を実行するアルゴリズムには、`n(n-1)`掛け算。 たとえ`n = 100000`、それは約です`10^10`これは、1 秒のソリューションで処理できる範囲をはるかに超えています。 リニア スキャンが適切なターゲットです。 

不注意な実装が失敗する可能性のある特殊なケースがいくつかあります。 1 つの数字を使用すると、次のようになります。```
1
7
```唯一の法的な選択は削除することです`7`、空の製品が残ります。 空の積の従来の値は、`1`したがって、正しい出力は次のようになります。```
1
```最初の入力値から応答を初期化する実装では、誤って次の結果が生成されます。`7`。 

値が等しいということは、もう 1 つの単純な境界ケースです。 のために```
5
3
3
3
3
3
```どの選択肢を選んでも同じ値が削除されるため、答えは次のようになります。`3 * 3 * 3 * 3 = 81`。 ソリューションでは、最小値が一意の位置で発生することを想定してはなりません。 

最小値は任意の位置に出現する可能性があります。 のために```
4
8
2
5
7
```私たちは削除します`2`、出発`8 * 5 * 7 = 280`。 最初または最後の要素を誤って削除したソリューションでは、間違った製品が生成されてしまいます。 

## アプローチ

 直接的なアプローチは、省略された可能性のある要素をすべて試してみることです。 インデックスごとに、配列全体をスキャンし、そのインデックスを除くすべての要素を乗算し、最大の積を保持します。 これは正しいです。すべての正当な結果は、省略された 1 つのインデックスに正確に対応するため、すべてのインデックスを検査すると、考えられるすべての答えが検査されることになります。 ただし、それぞれの`n`選択肢には必要なものがある`n - 1`乗算、正確に与える`n(n-1)`最悪の場合は乗算、つまり二次関数です。 

有益な観察は、すべての数値が正であるという事実から得られます。 概念的に総積が次のようになると仮定します。`a1 * a2 * ... * an`。 

取り除いたら`ai`、結果は、を除くすべての値の積です。`ai`。 2 つの選択肢を比較して、小さい値を削除すると、常に大きい値が残ります。 たとえば、部分的な製品がある場合、`P`以外のすべての値を含む`x`そして`y`、その後削除します`x`与える`P * y`、取り外しながら`y`与える`P * x`。 もし`x < y`、 それから`P * y > P * x`。 

したがって、最適な選択は常に最小限の要素を削除することです。 配列の読み取り中にその最小値を見つけて、その最小値が 1 つ出現する以外のすべての要素を乗算します。 さらに簡単な実装は、すべての要素の積を計算し、最小値で割ることです。これは、最小値が積全体の係数であることが保証されているためです。 Python の整数は、この計算中のオーバーフローも回避します。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | n が大きいと遅すぎます |
 | 最適 | O(n) | O(n) | 承認済み |

 入力値が読み取り中に処理される場合は、合計の積と最小値のみが必要となるため、最適な実装を O(1) 補助スペースにすることもできます。 

## アルゴリズムのチュートリアル

 1.読む`n`そして`n`正の整数。 最小値が必要なのは、その値を削除すると可能な限り最大の積が残るためです。 
2. すべての値の積を計算し、見つかった最小値を追跡します。 合計積を保持すると、あらゆる省略があった場合にほぼ同一の積を再計算することが回避されます。 
3. 合計を最小値で割ります。 これにより、積全体から最小値が 1 つだけ削除されます。これは、省略された要素の 1 つの正当な選択に対応します。 
4. 結果として得られた製品を印刷します。 もし`n = 1`、積の合計は唯一の要素に等しく、その要素で割ると次のようになります。`1`、空の製品を正しく表します。 

### なぜ効果があるのか

 しましょう`m`を配列内の最小値とし、`P`すべての値の積になります。 削除中`m`生成する`P / m`。 他の値を検討してください`x`。 以来`m <= x`残りの要素はすべて正であり、`m`少なくとも削除と同じ大きさの製品を残します`x`。 したがって`P / m`は、要素を 1 つだけ削除することによって得られる最大の積です。 複数の要素が等しい場合`m`の場合、いずれかを削除しても同じ結果が得られるため、最小値で割ることは依然として有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    values = [int(input()) for _ in range(n)]

    total = 1
    minimum = values[0]

    for x in values:
        total *= x
        if x < minimum:
            minimum = x

    print(total // minimum)

if __name__ == "__main__":
    solve()
```の`values`list は入力整数を格納するため、積の合計と最小値を 1 回のパスで計算できます。`total`から始まります`1`、これは乗法恒等式であり、`n = 1`ケースは自然に機能します。 

最小値は次から初期化されます`values[0]`任意の定数からではなく。 これにより、入力値がその定数よりも大きい場合に誤って誤った最小値を選択することが回避されます。 

乗算は、最小の比較が最終的な除算に関連する前に行われます。 Python の任意精度の整数は、固定幅の C++ や Java の整数のように中間合計積がオーバーフローできないことを意味します。 このステートメントは、最終的な答えが 32 ビットに収まることを保証しますが、積自体の合計は省略された値に等しい係数だけ大きくなる可能性があります。 

最小値は計算に使用される係数の 1 つであるため、最終的な整数の除算は正確です。`total`。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    total = 1
    minimum = None

    for _ in range(n):
        x = int(input())
        total *= x
        if minimum is None or x < minimum:
            minimum = x

    print(total // minimum)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("5\n3\n5\n6\n8\n10\n") == "2400\n", "sample 1"
assert run("4\n4\n3\n2\n1\n") == "24\n", "sample 2"
assert run("5\n3\n3\n3\n3\n3\n") == "81\n", "sample 3"

# Minimum-size input
assert run("1\n7\n") == "1\n", "single element"

# Minimum at the beginning
assert run("4\n1\n5\n6\n10\n") == "300\n", "minimum at beginning"

# Minimum at the end
assert run("4\n8\n5\n6\n1\n") == "240\n", "minimum at end"

# Large stress case, with an answer that still fits comfortably
large_input = "100000\n" + ("1\n" * 99999) + "2\n"
assert run(large_input) == "1\n", "large input"

# Several equal minima
assert run("5\n2\n7\n2\n9\n4\n") == "504\n", "repeated minimum"
