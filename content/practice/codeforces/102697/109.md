 ## 問題の理解

 このタスクは、小さな出力構築問題です。 1 つの整数が与えられます`n`、大文字の各部分のサイズを指定します`H`。 各垂直脚には次のものが含まれます`n`水平バーは 2 本の脚の間の距離と同じ長さになります。 必要な図面には、`n`水平バーの上の行、バー全体を含む中央の 1 行、および`n`その下の行。 

たとえば、次のようなとき`n = 3`、2 本の垂直の脚が列を占めます。`0`そして`4`、中央のバーは 5 つの列すべてを占めます。 したがって、最終的な図面は次のようになります。`2n + 1`行と`2n - 1`列。 出力は単純にこの長方形の文字パターンです。`H`中央以外の行の外側の 2 つの列、および`H`中列のすべての位置にあります。 

この声明では、明示的な上限は示されていません。`n`利用可能なバージョンで。 したがって、関連する制約は出力量そのものになります。 図面には次の内容が含まれます`(2n + 1)(2n - 1) = 4n² - 1`改行文字前の文字位置がカウントされるため、これより小さい値を漸近的に使用するソリューションはありません。`O(n²)`図面を明示的に印刷する場合の時間。 1 秒という制限は、必要な行を直接構築するよりもコストのかかる作業を実行する理由がないことも意味します。 

主なエッジケースは`n = 1`。 この場合、2 本の脚と中央のバーがすべて一致するため、答えは 1 つのバーを含む 3 行になります。`H`、2 つの分離された列を持つ形状ではありません。 正確な入力と出力は次のとおりです。```
1

```2 つの脚が異なる列を占有すると常に想定する不注意な実装では、誤って余分なスペースや空のギャップが作成される可能性があります。 

別の境界ケースは中央の行です。 のために`n = 2`、出力は次のようになります。```
H H
HHH
H H
```中央の行には次の内容を含める必要があります`2n - 1 = 3`連続した`H`文字。 すべての行に垂直脚パターンを出力する実装では、次のようになります。`H H`中央で水平バーを完全に外します。 

## アプローチ

 直接的な総当たりアプローチは、出力四角形内のすべての位置を考慮することです。 ポジションのために`(r, c)`、印刷`H`いつ`r`中央の行またはいつ`c`2 つの外側の列のうちの 1 つです。 それ以外の場合はスペースを出力します。 出力は正確なので、`(2n + 1)(2n - 1) = 4n² - 1`位置、これは正確に実行されます`4n² - 1`位置チェック。 文字の定義が正しいので、`H`は、左脚、右脚、中央の水平バーの 3 本のラインによって完全に特徴付けられています。 

ブルート フォース バージョンは、出力自体が 2 次サイズであるため、時間的にはすでに漸近的に最適化されています。 それらの文字の生成を回避できる隠れたアルゴリズム上の課題はありません。 有益な改善点は、図面全体を保存しないようにすることです。 一度に 1 行を作成し、すぐに出力に追加できます。 中間行以外の行は単純に`H`に続く`2n - 3`スペースと別の`H`、中央の行は次で構成されます`2n - 1` `H`文字。 

これも扱います`n = 1`列の構造が慎重に選択されていれば当然のことです。 この場合、列は 1 つだけであるため、中間行以外の数式は 2 つの別々の脚を生成しようとしてはいけません。 最も単純な実装は、最初の`n`行を垂直パターンとして生成し、中央の行を生成してから、残りの行を生成します。`n`行。 いつ`n = 1`、縦のパターンはちょうど`H`、中段も`H`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 印刷が問題の大半を占めるため、2 つのアプローチの漸近時間は同じになります。 最適な実装は、個々のセルをすべてチェックするのではなく、完全な行を直接構築するため、よりクリーンです。 

## アルゴリズムのチュートリアル

 1.読む`n`。 最終的な図面には、`2n + 1`行と`2n - 1`したがって、これらの寸法によって出力が完全に決まります。 
2. 中央以外の行のパターンを作成します。 もし`n = 1`、行は単純に`H`。 それ以外の場合は、以下で構成されます`H`、 に続く`2n - 3`スペース、その後に別のスペースが続く`H`。 二人`H`文字はまさに2本の縦の脚です。 
3. この縦の行を出力します`n`回。 これらの行は文字の上半分を形成し、水平バーは含まれません。 
4. 以下で構成される行を出力します。`2n - 1`連続した`H`文字。 これは水平バーで、ちょうど 1 行の幅です。 
5. 同じ縦の行を別の行に出力する`n`回。 これらの行は手紙の下半分を形成します。 

構築全体を通じて不変なのは、出力されるすべての行が、その位置で必要な行とまったく同じであるということです。 最初で最後`n`行には 2 本の垂直脚のみが含まれますが、固有の中央の行には完全な水平バーが含まれます。 これらはすべてなので、`2n + 1`行ごとに、必要な図面内のすべての位置が、正しい文字で 1 回だけ生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n == 1:
        row = "H"
    else:
        row = "H" + " " * (2 * n - 3) + "H"

    middle = "H" * (2 * n - 1)

    out = []
    out.extend([row] * n)
    out.append(middle)
    out.extend([row] * n)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のブランチは唯一の縮退次元を処理します。 のために`n > 1`、2つの垂直方向の間の距離`H`文字は`2n - 3`スペース。 2 つのエンドポイント文字を含めると、合計幅は次のようになります。`2 + (2n - 3) = 2n - 1`。 

リスト`out`個々の文字ではなく完全な行を保存します。 最初`n`エントリは上部の脚を表し、次のエントリは中央のバー、最後のエントリは`n`エントリは下肢を表します。 使用する`"\n".join(out)`不要な末尾改行の追加を回避し、1 回の操作で出力を実行します。 

Python では整数オーバーフローの懸念はなく、入力配列に関係するインデックス計算もありません。 注意が必要な唯一の算術は、`2n - 3`、これは個別に有効です`n = 1`上記で扱ったケース。
