 ## 解決策
 ## 問題の理解

 一連の整数を一度に 1 つずつ受け取ります。 各整数が到着したら、それを降順でないリストに挿入する必要があります。 必要な出力は、最終的にソートされたシーケンスだけではありません。 最初の値の後に、1 要素のソートされたリストを出力します。 2 番目の値の後に、両方の値を含む並べ替えられたリストが出力され、すべての値が挿入されるまで同様に印刷されます。 

たとえば、受信シーケンスが次の場合、`3, 4, 2, 8, 7`、維持されるリストは次のとおりです。`[3]`、`[3, 4]`、`[2, 3, 4]`、`[2, 3, 4, 8]`、 そして`[2, 3, 4, 7, 8]`。 

この声明では、明示的な上限は示されていません。`n`。 制限時間は 1 秒、メモリ制限は 256 MB です。 さらに重要なのは、出力自体に次のものが含まれていることです。 

1+2+⋯+n= 2 n(n+1)

 整数なので、必要な答えを書くだけでもすでに二次時間かかります`n`。 これにより、追加の対数係数または線形係数を使用するアルゴリズムが除外されます。`n`大きいです。 メンテナンス作業は、避けられない出力サイズと同等にしたいと考えています。 

最初のエッジ ケースは重複値です。 入力用```
3555
```正しい出力は```
55 55 5 5
```厳密に小さい値のみを検索する実装では、等しい要素が誤って処理される可能性がありますが、等しい値が隣り合って挿入された場合、最終的な順序は依然として有効です。 

別の特殊なケースは、新しい最小値を挿入することです。 のために```
3421
```出力は```
42 41 2 4
```最初の要素の後のどこかへの挿入のみを処理する不用意な実装は、挿入位置がインデックス 0 の場合に失敗する可能性があります。 

対称の場合は、新しい最大値を挿入します。 のために```
3135
```出力は```
11 31 3 5
```挿入位置は最後にあるため、挿入ポイントの後にシフトする要素が常に存在すると想定する実装では、配列の境界を越えて実行される可能性があります。 

## アプローチ

 直接的な解決策は、ソートされたリストを明示的に維持することです。 受信する数値ごとに、新しい数値より大きい最初の要素が見つかるまで既存のリストを最初からスキャンし、そこに数値を挿入して、リスト全体を出力します。 これは正しいです。挿入位置より前のすべては最大でも新しい値ですが、その位置以降はすべてその値以上であるためです。 

最悪の場合、`k`番目の値はシフトする必要がある場合があります`k-1`既存の要素。 すべての挿入にわたって、これにより次のことが得られます

 0+1+2+⋯+(n−1)= 2 n(n−1)

 要素の動き。 答えを出力するには、正確に n(n+1)/2 の整数出力も必要です。 したがって、合計作業量は O(n 2 ) となり、要求された出力の避けられないサイズと一致します。 

解決策を単純にする観察は、出力自体が 2 次であるということです。 完全な挿入構造であっても O(n 2 ) の値を出力する必要があるため、O(logn) 時間で挿入できる特殊なデータ構造を検索する必要はありません。 Python リストとバイナリ検索を組み合わせると、クリーンな実装が可能になります。バイナリ検索は O(logn) 内の挿入位置を見つけ、リストの挿入により O(n) 内の要素がシフトされます。 後者が優勢で、合計時間は O(n 2 ) になります。 

ブルート フォース バージョンでは挿入位置の線形検索を使用できますが、最適な実装では二分検索が使用されます。 Python リストのシフトはすでに線形であるため、両方とも同じ漸近的な複雑さになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 線形検索 + 挿入 | O(n²) | O(n) | 承認済み |
 | 二分探索 + 挿入 | O(n²) | O(n) | 承認済み |

 合計の複雑さは O(n 2 ) のままですが、挿入位置を見つけるのにかかるコストは O(logn) のみであるため、二分探索バージョンが推奨されます。 

## アルゴリズムのチュートリアル

 1.読む`n`そして、という空のリストを初期化します。`arr`。 このリストは、これまでに到着した並べ替えられた値を正確に表します。 
2. 各受信値を読み取ります`x`順番に。 前回の内容は、`arr`すでにソートされているので、どこにあるかを見つけるだけで済みます。`x`所属しています。 
3. 二分探索を使用して最初のインデックスを見つけます`pos`そのような`arr[pos] >= x`。 これが標準の下限位置です。 既存のすべての値が次の値より小さい場合`x`、位置は次のようになります`len(arr)`、 意味`x`最後に属します。 
4.挿入`x`で`pos`。 Python は既存のサフィックスを右にシフトし、そのまま残します。`arr`並べ替えました。 
5. のすべての要素を出力します。`arr`。 この瞬間に`arr`正確に最初のものが含まれています`k`入力値がソート順に並べられているため、これはまさに、`k`2行目。 
6.すべてになるまで繰り返します`n`値が処理されました。 

### なぜ効果があるのか

 不変条件は、新しい値を処理する直前に、`arr`これまでに確認された値が正確に含まれており、降順でない順に並べ替えられます。 二分探索では、その順序に違反せずに新しい値を配置できる最初の位置が検索されます。 その位置より前のすべての要素は新しい値より小さく、その位置以降のすべての要素は新しい値以上になります。 挿入後、不変条件は true のままです。 したがって、出力されるすべてのリストは、問題で必要とされるソートされたプレフィックスと正確に一致します。 

## Python ソリューション```python
Pythonimport sysfrom bisect import bisect_left
input = sys.stdin.readline

def solve():    n = int(input())    arr = []    output = []
    for _ in range(n):        x = int(input())
        pos = bisect_left(arr, x)        arr.insert(pos, x)
        output.append(" ".join(map(str, arr)))
    sys.stdout.write("\n".join(output))

if __name__ == "__main__":    solve()
```

`bisect_left`ステップ 3 で使用される下限を実装します。少なくとも値を含む最初の位置を使用します。`x`等しい値が既存の等しい値の前に挿入されることを意味します。これは、必要な順序が非降順であるため、完全に有効です。`arr.insert(pos, x)`実際の動的挿入を実行する部分です。 もし`pos`がゼロの場合、既存の要素はすべて右に移動します。 もし`pos == len(arr)`, Python では値が自然に追加されます。 これら 2 つの境界は、可能な最小および最大の挿入位置をカバーします。 

出力は文字列として蓄積され、最後に 1 回書き込まれます。 繰り返し電話をかける`print`すべての行については論理的には正しいですが、完全な出力を構築して最終的な出力を作成する必要があります。`sys.stdout.write`不要な I/O 呼び出しを回避します。 出力自体のサイズは 2 次であるため、文字列は必然的に大量のメモリを消費します。`n`大きいです。 ストリーミング実装により余分なメモリを削減できますが、上記のバージョンではコードが単純化されています。 

Python の整数には任意の精度があるため、整数のオーバーフローの心配はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

問題文には数値の最大値が示されていません。`n`したがって、正直なところ、固定された上限を計算する必要はありません。 このソリューションは、必要な出力サイズに関して漸近的に最適になります。
