 ## 解決策
 ## 問題の理解

 この問題は、唯一の測定値が初上昇速度であるロケットの打ち上げについて説明しています。 ロケットが落下し始める前に、ロケットが到達する最大の高さを予測する必要があります。 ロケットは速度がゼロになると最高点に達します。そのため、与えられた初速度と重力によって引き起こされる一定の加速度を使用して、上向きに移動する距離を計算することがタスクとなります。 

入力には、ロケットの初速度 (メートル/秒) を表す 1 つの浮動小数点値が含まれます。 出力は、メートル単位の浮動小数点数としての最大の高さである必要があります。 速度、加速度、距離の関係は、次の運動方程式で与えられます。$$V_f^2 = V_i^2 + 2ad$$最高点では、$V_f = 0$、そして重力が与える$a = -9.8$。 高さを解くと次のようになります。$$d = \frac{V_i^2}{19.6}$$入力は単一の double 値であるため、大規模なデータ構造や処理する多くのテスト ケースはありません。 このアルゴリズムには定数時間の演算のみが必要です。 飛行のシミュレーションは不要であり、精度の問題が発生する可能性がありますが、直接式は問題で期待される正確な数学的結果を与えます。 

主なエッジケースは、浮動小数点値を正しく処理することに起因します。 開始速度がゼロのロケットは、開始位置から決して離れることがないため、高さはゼロになるはずです。 入力用`0`、正しい出力は次のとおりです。`0.0`一方、常に上向きの動きを想定するソリューションでは、誤った正の値が生成される可能性があります。 

非常に小さい初速度も重要です。 入力用`0.1`、答えはおよそ`0.0005102040816326531`。 丸めるのが早すぎるか、入力を整数に変換すると、誤ってゼロが出力されます。 

より大きな速度も浮動小数点演算で処理する必要があります。 入力用`100`、答えはおよそ`510.2040816326531`。 整数の除算を使用する不注意な実装では、小数部分が失われる可能性があります。 

## アプローチ

 強引なアプローチは、ロケットの動きを時間の経過とともにシミュレートすることです。 加速度を追加することで速度を繰り返し更新し、速度がゼロになるまで移動距離を追加することができます。 これは最終的に最大高さに近似しますが、結果は選択したタイム ステップによって異なります。 タイムステップを非常に小さくすると、反復回数が増えると同時に精度が向上します。 高速の場合、数千または数百万のシミュレーション ステップが必要になる場合があり、浮動小数点誤差が蓄積されます。 

より良いアプローチは、問題が動きを記述する正確な方程式をすでに与えていることを認識することから生まれます。 最高点は、最終速度がゼロになる特定の状態です。 飛行のあらゆる瞬間を再現する代わりに、未知の高度の方程式を直接解くことができます。 

ブルートフォース手法は物理プロセスに従うため機能しますが、連続動作には自然なシミュレーション ステップ数がないため失敗します。 最終速度が既知であるという観察により、問題全体を 1 つの式の評価にまとめることができます。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ロケットの初速度を浮動小数点数として読み取ります。 
2. 既知の値を運動方程式に代入します。 最高点での最終速度はゼロであり、加速度は`-9.8`、方程式は次のようになります。$$0 = V_i^2 - 19.6d$$並べ替えると次のようになります。$$d = \frac{V_i^2}{19.6}$$1. 式を使用して高さを計算し、結果を印刷します。 

この計算では、ロケットが上昇を停止する瞬間を直接モデル化します。 打ち上げから最高点までの経路を追跡する必要はありません。 

### なぜ効果があるのか

 この式は、一定の加速度の下での速度、加速度、変位の間の正確な関係から得られます。 上昇中の加速は重力のみであるため、方程式は常に成り立ちます。 最大高度では、ロケットの上向き速度はゼロになります。 この条件を代入すると、不明な点は 1 つだけ残り、アルゴリズムが計算する高さになります。 数学的モデルは問題の説明と正確に一致するため、戻り値は最大高さになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    v = float(input())
    height = v * v / 19.6
    print(height)

if __name__ == "__main__":
    solve()
```このソリューションでは速度を次のように読み取ります。`float`入力が整数に制限されておらず、出力には小数精度が必要なためです。 

掛け算`v * v`方程式から初速度の 2 乗を計算します。 で割る`19.6`再配置された運動学的公式を適用します。 この問題では通常の印刷 10 進表現のみが必要であるため、ここでは Python 浮動小数点演算で十分です。 

計算全体で単一の浮動小数点値が使用されるため、境界インデックスや整数オーバーフローの懸念はありません。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    v = float(sys.stdin.readline())
    ans = v * v / 19.6
    out = str(ans)
    sys.stdin = old_stdin
    return out

assert solve("7.78\n") == "3.0881836734693877", "sample 1"
assert solve("0\n") == "0.0", "zero velocity"
assert solve("0.1\n") == "0.0005102040816326531", "small velocity"
assert solve("100\n") == "510.2040816326531", "large velocity"
assert solve("19.6\n") == "19.6", "boundary precision"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`0`|`0.0`| 初動のないロケット |

```アルゴリズムは計算します`0 * 0 / 19.6`、それは与える`0.0`。 これは、高度が上がらないロケットを正しく表しています。 

速度が非常に小さい場合、入力は次のようになります。```
0.1
```アルゴリズムは値を浮動小数点数として保持し、計算します。`0.01 / 19.6`、およその値を返します`0.0005102040816326531`。 整数変換を行うと、結果全体が誤って削除されてしまいます。 

起動速度を大きくするには、入力は次のようになります。```
100
```計算は次のようになります`10000 / 19.6`、約生産`510.2040816326531`。 一定時間の式により、ロケットの高さに応じたループ回数が回避されるため、計算は正確かつ高速に行われます。
