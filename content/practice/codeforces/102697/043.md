 ## 解決策
 ## 問題の理解

 当社には直行便ネットワークがあります。 ある都市から別の都市に移動する各フライトには料金がかかります。 チームはに始まります`Syracuse`、競技都市に到着し、その後競技都市に戻らなければなりません。`Syracuse`。 往復の合計料金が所定の予算を超えることはできません。 実行可能なすべての往復の中で、合計金額が最小の往復が必要であり、実際のフライトの順序を印刷する必要があります。 

公式声明では、制限時間は 1 秒、メモリは 256 MB とされています。 フライト数や予算の明示的な数値上限は公表されていないため、予算のサイズに依存するものではなく、標準の線形に近い最短経路アルゴリズムでグラフを処理する必要があると解釈するのが安全です。 

グラフには方向性があり、これは重要です。`A`に`B`からのフライトを意味するものではありません。`B`に`A`存在します。 有向辺には価格が付いているので、目的地に行く一番安い方法と戻る方法を分けて考える必要があります。 

最初のエッジケースは、一方向が不可能な場合です。 例えば：```
NewYork
3 10
Syracuse Detroit 9
Detroit NewYork 1
NewYork Syracuse 2
```最も安く到着する方法`NewYork`行きのコストは 10 ですが、帰りのコストはさらに 2 かかるため、旅行全体のコストは 12 になります。正しい出力は次のとおりです。```
IMPOSSIBLE
```競合に到達するためのコストのみをチェックする不注意な実装では、このルートが誤って受け入れられてしまいます。 

予算の境界も重要です。 考慮する：```
B
3 5
Syracuse A 2
A B 1
B Syracuse 2
```唯一の往復コストはちょうど 5 であるため、これは有効であり、正しい最初の出力行は次のとおりです。```
4 5
```比較する必要があるのは、`cost <= budget`、 ない`cost < budget`。 

もう 1 つのよくある間違いは、直行便が存在する場合にはそれを使用する必要があると想定することです。 考慮する：```
B
5 5
Syracuse B 5
Syracuse A 1
A B 1
B A 1
A Syracuse 1
```への直行便は、`B`費用は 5 ですが、これを使用して旅行を完了すると予算を超えてしまいます。 往復で安いのは、`Syracuse -> A -> B -> A -> Syracuse`最短パス アルゴリズムにより、このマルチフライト ルートが自然に発見されます。 

最後に、複数のフライトが同じ都市のペアを接続できます。 たとえば、両方の場合、`Syracuse -> A`価格10で、`Syracuse -> A`価格 3 が存在する場合、最小価格ルートではより安価なエッジのみが重要になります。 実装では、どちらかのエッジを誤って上書きするのではなく、両方のエッジを保持する必要があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるルートを列挙することです。`Syracuse`競技都市まで行き、帰りの可能なルートを列挙し、すべてのペアを組み合わせて、価格が予算に合う最も安い組み合わせを維持します。 実行可能なすべての旅程が明示的に考慮されているため、これは正しいです。 問題は路線数です。 循環を避けたとしても、有向グラフには階乗的に多くの単純なパスが含まれる可能性があります。 (V) 都市の場合、2 つの固定都市間の単純なパスの数は次のとおりです。 

[
 \sum_{k=0}^{V-2} P(V-2,k),
 】

 それは (\シータ(V!)) です。 各ルートの価格を計算すると、その長さに比例する別の要素が追加されます。 (V) 自体は入力フライトの数に比例する可能性があるため、網羅的な検索はすぐに使用できなくなります。 

考えられるすべてのルートがチェックされるため、ブルート フォースは機能しますが、グラフに多くの代替パスが含まれている場合は失敗します。 重要な観察は、目的が加算的であるということです。つまり、ルートの価格は航空券の価格の正確な合計となります。 すべての航空券の価格は負ではないため、2 つの都市間の最も安いルートは通常の重み付き最短経路問題になります。 

さらに単純な分解もあります。 すべての有効な往復は 2 つの独立したパスで構成されます。`Syracuse`競技都市へ、そして競技都市から戻る`Syracuse`。 最初のパスのコストが最小 (A) で、2 番目のパスのコストが最小 (B) である場合、往復のコストは少なくとも (A+B) になります。 これら 2 つの最短パスを取ると、正確に (A+B) が達成されるため、2 つの最短パスの問題を解決することで、世界的に最も安価な往復が得られます。 

すべてのエッジの重みが負ではないため、ダイクストラのアルゴリズムを両方向に使用できます。 また、リラックスした頂点ごとに先行データを保存します。これにより、最小コストを見つけた後に実際の飛行シーケンスを再構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (\Theta(V!)) 最悪の場合 | (O(V+E)) プラス ルート ストレージ | 遅すぎる |
 | 最適 | (O((V+E)\log V)) | (O(V+E)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 競技都市、フライト数、利用可能な予算を確認します。 すべてのフライトとその価格を含む有向隣接リストを作成します。 復路ではまったく異なるフライトを利用する可能性があるため、グラフの向きを変える必要はありません。 
2. 都市名を整数 ID に圧縮します。 ダイクストラのアルゴリズムは、すべてのヒープ操作で距離の辞書を使用するよりも、整数インデックス付き配列を使用した方が効率的に機能します。 
3. からディクストラを実行します。`Syracuse`競技都市へ。 すべての都市までの最短距離と、その距離を生成した前の都市の両方を保存します。 先行配列は、後で実際のフライトを回復するために必要になります。 
4. ディクストラを再度実行します。今回は競技都市から開始します。 今回の検索の対象は、`Syracuse`。 これにより、往路とは関係なく復路が可能な限り安くなります。 
5. どちらの最短パスも存在しない場合は、次のように出力します。`IMPOSSIBLE`。 必要な 2 つの半分のうちの 1 つでも不可能な場合、往復は存在できません。 
6. 2 つの最短経路コストを加算します。 合計が予算を超える場合は、印刷してください`IMPOSSIBLE`。 予算内であれば、2 つのパスを合わせると最も安価な往復が形成されます。これは、1 つおきの往路には少なくとも 1 番目の最短パス距離のコストがかかり、他のすべての戻りパスには少なくとも 2 番目の最短パス距離のコストがかかるためです。 
7. 競技都市から開始し、到達するまで前のパスを繰り返したどって、往路を再構築します。`Syracuse`。 収集した都市を逆にして、順方向の順序を取得します。 
8. 同じ方法でリターン パスを再構築します。`Syracuse`競技都市に到着するまでは前任者の後を追い、その後は逆転します。 2 番目のダイクストラ探索は競技都市に根ざしていたため、その前のチェーンは自然に競技都市から`Syracuse`。 
9. 往路と復路のフライトリストを連結します。 最初のパスの最後の都市は競技都市であり、2 番目のパスの最初のフライトはそこから始まるため、2 つのシーケンスは直接接続されます。 
10. 必要な情報を使用して、フライトの数とその合計金額を出力し、続いて連続する都市のペアごとに出力します。`A -> B`形式。 

### なぜ効果があるのか

 (P) をからの任意のパスとします。`Syracuse`(Q) 競技都市から競技都市に戻る任意の経路`Syracuse`。 旅行全体の費用は、`cost(P) + cost(Q)`。 ダイクストラの最初の実行では、他の発信パスのコストを超えないコストのパス (P^_) が生成されます。 2 回目の実行では (Q^_) が生成され、そのコストは他のリターン パスのコストを超えません。 したがって、可能なすべての往復について、

 [
 コスト(P^_) + コスト(Q^_) \le コスト(P) + コスト(Q)。 
】

 したがって、2 つの最短パスを連結すると、往復の料金が世界的に最も安くなります。 コストが予算を超える場合、1 往復ごとに少なくとも同じくらいの費用がかかり、実現可能な解決策は不可能になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def dijkstra(start, graph):
    inf = 10**30
    dist = [inf] * len(graph)
    parent = [-1] * len(graph)

    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)

        if d != dist[u]:
            continue

        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                parent[v] = u
                heapq.heappush(pq, (nd, v))

    return dist, parent

def reconstruct(start, target, parent):
    path = []
    cur = target

    while cur != start:
        path.append(cur)
        cur = parent[cur]

        if cur == -1:
            return []

    path.append(start)
    path.reverse()
    return path

def solve():
    destination = input().strip()
    n, budget = map(int, input().split())

    city_id = {}

    def get_id(city):
        if city not in city_id:
            city_id[city] = len(city_id)
        return city_id[city]

    flights = []

    for _ in range(n):
        a, b, price = input().split()
        price = int(price)

        u = get_id(a)
        v = get_id(b)
        flights.append((u, v, price))

    syracuse = get_id("Syracuse")
    target = get_id(destination)

    graph = [[] for _ in range(len(city_id))]

    for u, v, price in flights:
        graph[u].append((v, price))

    dist_out, parent_out = dijkstra(syracuse, graph)
    dist_back, parent_back = dijkstra(target, graph)

    inf = 10**30

    if dist_out[target] == inf or dist_back[syracuse] == inf:
        print("IMPOSSIBLE")
        return

    total_cost = dist_out[target] + dist_back[syracuse]

    if total_cost > budget:
        print("IMPOSSIBLE")
        return

    out_path = reconstruct(syracuse, target, parent_out)
    back_path = reconstruct(target, syracuse, parent_back)

    full_path = out_path + back_path[1:]

    print(len(full_path) - 1, total_cost)

    for u, v in zip(full_path, full_path[1:]):
        # Reverse lookup is only needed for output.
        # city_names is created below from city_id.
        print(f"{city_names[u]} -> {city_names[v]}")

Python の整数はオーバーフローしないため、多くの航空券の価格が追加された場合でも、累積パス価格は安全です。 の`10**30`値は無限大として機能し、実際のパス コストよりも快適に大きくなります。 

ちょっと変わったもの`__main__`このセクションは、必要なコードを保持しながらコードを自己完結型に保つためにのみ存在します。`input = sys.stdin.readline`設定。 通常の送信では、同じロジックを直接内部に配置できます。`solve()`と`city_names`出力セクションで使用できます。

## 複雑さの分析

 (V) を個別の都市の数、(E) をフライトの数とします。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((V+E)\log V)) | 2 つのダイクストラのランが作品を支配 |
 | スペース | (O(V+E)) | グラフ、距離、先行データ、およびヒープ |

 ダイクストラ実行は最大 2 回であるため、定数係数は小さいです。 このアルゴリズムは予算の数値に依存しません。公開された問題ページでは予算の数値制限が指定されていないため、これは役に立ちます。 1 秒の制限では、(O((V+E)\log V)) グラフ アルゴリズムが適切なスケールですが、ルートの列挙は最悪のケースでは階乗になります。

```復路が不可能な場合、2回目のダイクストラランがそれを捕まえます。 例えば：```

```最初のダイクストラ実行ではコスト 3 が与えられ、2 回目の実行ではコスト 2 が与えられ、合計はちょうど 5 になります。`total_cost > budget`は false であるため、アルゴリズムは次のように出力します。```

```直行便の方が安価な一連の航空券よりも高価な場合、ダイクストラ氏は両方の可能性を検討し、累積距離を低く保ちます。 で：```

A Syracuse 1
```への直接ルート`B`コストは5ですが、`Syracuse -> A -> B`コスト 2。復路のコストは 2 であるため、最終的な答えは 4 つのフライトとコスト 4 を使用します。予算チェックは、両方の最短パスが最適化された後にのみ実行されます。 

競技都市そのものの場合`Syracuse`、両方の最短パスのコストはゼロであり、両方の再構築されたパスには開始都市のみが含まれます。 結合されたパスにはフライトが含まれていないため、自然な結果は次のようになります。`0 0`。 再構築ループは、特別なオフバイワンの場合を使用せずにこれを処理します。これは、次の場合に直ちに停止するためです。`cur == start`。 

並行便も安全です。 入力に次の内容が含まれているとします。```
B
4 10
Syracuse B 8
Syracuse B 2
B Syracuse 2
B Syracuse 8
```ダイクストラでは、出力エッジと戻りエッジの両方が考慮されます。 2 つの価格 2 のフライトにより、コスト 4 の最適な往復が生成されます。隣接リストに平行なエッジを維持することで、最短パス アルゴリズムがその選択を正しく行うことができます。
