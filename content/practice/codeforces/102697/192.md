 ## 問題の理解

 数人の騎士を含む 8 × 8 のチェス盤が与えられます。 すべてのセルは空であるか、次のように表されます。`.`、または次のように表されるナイトが含まれています。`K`。 ナイトは、一方の座標を 2 変更し、もう一方の座標を 1 変更することで、到達可能なセルを正確に攻撃します。少なくとも 1 人のナイトが正確に 1 回の移動で到達できるすべての空のセルにマークを付ける必要があります。`*`。 既存の騎士は残る`K`、空のセルは 1 つおきに残ります。`.`。 結果として 8 x 8 のボードが印刷されます。 

ボードの寸法は 8 x 8 に固定されているため、セルは 64 個のみです。 数百または数千の操作を実行するソリューションであっても、快適に高速です。 複数の手が含まれるパスではなく、1 つのナイトの動きのみを考慮するため、高度なグラフ アルゴリズムや幅優先検索は必要ありません。 特に、可能なナイトの最大数は 64 で、各ナイトには可能な移動オフセットが 8 つしかないため、検査対象の候補先は最大 512 個になります。 

主なエッジケースは、ボードの境界と重複する動きによって発生します。 窮地に追い込まれた騎士の正当な手は 2 つだけです。 たとえば、```

別の微妙なケースは、複数の騎士が同じ空のセルに到達できる場合に発生します。 セルにはまだ 1 つだけが含まれている必要があります`*`出力には、セルに到達できる騎士の数ではなく、セルに到達できるかどうかが記述されるためです。 例えば、```

3 番目のケースは、すでにナイトが含まれている目的地です。 出力は保存する必要があります`K`と置き換えるのではなく、`*`。 例えば、```

## アプローチ

 簡単な総当たりソリューションでは、すべてのボード セルを検査し、少なくとも 1 人のナイトがそこに移動できるかどうかを尋ねることができます。 目的地ごとに、すべてのセルをナイトの候補として検査し、8 つのナイト オフセットをテストできます。 64 の可能な宛先、64 の可能なソース セル、および 8 つのオフセットがある場合、最悪の場合のパフォーマンスは次のようになります。`64 * 64 * 8 = 32,768`移動チェック。 この特定のボードではこれは小さいため、このアプローチは実際には十分に高速です。 

より直接的なアプローチは、代わりに騎士から始まります。 私たちが何かに遭遇するたびに、`K`、考えられる 8 つの騎士の動きをすべて試します。 宛先が 8 x 8 ボード内にあり、現在含まれている場合`.`に変更します。`*`。 各ナイトは最大で 8 つのチェックに貢献するため、64 人のナイトでは最大で 8 つのチェックが行われます。`64 * 8 = 512`候補者が動きます。 

重要な観察点は、この問題では 1 回の移動で到達可能なセルが求められているということです。 中間位置を検索する必要はありません。 ナイトの可能なワンステップ目的地の完全なセットは事前にわかっているため、各ナイトを個別に処理できます。 これにより、すべての送信元と宛先のペアをチェックする作業が、各実際のナイトの幾何学的に可能な 8 つの宛先のみをチェックする作業に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(64²×8) | お(64) | 受け入れられたが、不必要な作業 |
 | 最適 | O(64×8) | お(64) | 承認済み |

 64 は定数であるため、技術的にはどちらのアプローチも入力サイズに関しては O(1) です。 2 番目のアプローチは、問題の構造を直接表現し、ナイトではないセルの検査を避けるため、依然として望ましい方法です。 

## アルゴリズムのチュートリアル

 1. 8 つのボード行を可変の 8 x 8 文字グリッドに読み取ります。 グリッドを変更可能な状態にしておくと、次のように書くことができます`*`到達可能な空のセルに直接アクセスできます。 
2. すべての行とすべての列をスキャンします。 現在のセルに次の内容が含まれている場合`K`、それを 1 つのナイト移動のソース位置として扱います。 
3. その騎士のために、8 つの変位ペアを試してください`(2,1)`、`(2,-1)`、`(-2,1)`、`(-2,-1)`、`(1,2)`、`(1,-2)`、`(-1,2)`、 そして`(-1,-2)`。 These are exactly the legal ways to move two cells in one direction and one cell perpendicular to it.
 4. For each destination, first check that its row and column are between`0`そして`7`。 この範囲外の動きはチェス盤から離れるため、無視する必要があります。 
5. 宛先がボード内にあり、`.`に置き換えてください`*`。 意図的に交換はしません`K`なぜなら、ナイトは出力内に表示されたままでなければならないからです。 同じセルに繰り返し到達しても問題はありません。`*`再度実行しても結果は変わりません。 
6. すべてのナイトが処理された後、結果の 8 行を出力します。 マークされたすべてのセルには少なくとも 1 人の騎士が到達できますが、マークされていない空のセルはいかなる合法的な手によっても到達できませんでした。 

### なぜ効果があるのか

 不変条件は、ナイトの接頭辞を処理した後、すべての`*`ボード上の場所は、少なくとも 1 人の処理されたナイトから 1 回の合法的な手で到達可能であり、ナイトによって占領されていない限り、すべての処理されたナイトのすべての合法的な目的地がマークされています。 新しいナイトが処理されるとき、8 つの可能なナイト宛先すべてと 8 つだけが検査されるため、無効な宛先を導入することなく不変式がそのナイトに拡張されます。 すべてのナイトが処理された後、可能なすべての 1 つの移動先が考慮されます。これは、最終的なボードには、必要な到達可能な空のセルが正確に含まれていることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    board = [list(input().strip()) for _ in range(8)]

    moves = [
        (2, 1), (2, -1),
        (-2, 1), (-2, -1),
        (1, 2), (1, -2),
        (-1, 2), (-1, -2)
    ]

    for r in range(8):
        for c in range(8):
            if board[r][c] != 'K':
                continue

            for dr, dc in moves:
                nr = r + dr
                nc = c + dc

                if 0 <= nr < 8 and 0 <= nc < 8:
                    if board[nr][nc] == '.':
                        board[nr][nc] = '*'

    for row in board:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```個々のセルを次から変更する必要があるため、ボードは文字列ではなくリストとして保存されます。`.`に`*`。 の`moves`配列には 8 つのリーガル ナイト ディスプレイスメントがすべて含まれているため、水平方向と垂直方向の移動に個別の特殊なケースを使用する必要はありません。 

境界チェックでは以下を使用します。`0 <= nr < 8`そして`0 <= nc < 8`。 Python はゼロベースのインデックスを使用するため、有効な行と列のインデックスは正確に`0`を通して`7`。 アクセス前に宛先を確認する`board[nr][nc]`無効な配列アクセスを防止します。 

条件`board[nr][nc] == '.'`それも意図的です。 を含む宛先`K`騎士であり続けなければなりません。 すでに含まれている宛先`*`割り当てられるため、特別な処理は必要ありません。`*`再びまったく同じ効果が得られます。 

アルゴリズムは文字と座標のみを保存するため、整数オーバーフローの問題はありません。 このような小さな入力には高速 I/O は実際には必要ありませんが、`sys.stdin.readline`標準的な競技プログラミングの入力パターンに従います。
