 ## 問題の理解

 タスクは、バイナリ文字列として表現される 2 つの非負の整数を加算することです。 最初の行には 1 つの 2 進数が含まれ、2 行目には別の 2 進数が含まれます。必要な出力は、やはり 2 進数で書かれたそれらの合計です。 文字列の長さは異なる場合があるため、加算では欠落している上位桁をゼロとして処理する必要があります。 

たとえば、入力```
101
11
```(5)と(3)を表します。 それらの合計は (8) であり、そのバイナリ表現は次のようになります。`1000`。 

このステートメントでは、2 つの文字列の長さの数値の上限は指定されていません。 数値は文字列として直接表現されるため、バイナリ値自体が固定幅の整数型には大きすぎる場合でも、意図したアプローチは機能するはずです。 数値をマシン整数に格納するソリューションは、入力では課されないサイズ制限を不必要に課すことになります。 すべての入力桁が桁上げ伝播に影響を与える可能性があり、潜在的に検査する必要があるため、線形時間ソリューションが自然な目標となります。 

不注意な実装によって誤って処理される可能性のあるいくつかの特殊なケースがあります。 まず、数値はさまざまな長さにすることができます。 例えば、```
1
111
```出力があります```
1000
```最初の数値の欠落した桁はゼロとして扱われるためです。 両方の文字列にまだ数字がある間に位置のみを処理する実装では、停止が早すぎて先頭のキャリーが失われます。 

2 番目のエッジケースは最終キャリーです。 のために```
1
1
```正しい出力は```
10
```入力数字の唯一のペアを処理した後も桁上げは 1 のままであるため、これは新しい最上位数字になる必要があります。 処理された位置のみを出力する実装では、誤って生成される可能性があります。`0`。 

入力が通常の 10 進整数表現として扱われる場合、先頭のゼロも問題の原因となる可能性があります。 例えば、```
00101
0011
```は (5+3=8) を表すため、出力は次のようになります。```
01000
```操作が入力表現の幅を維持するものとして理解されているが、「合計をバイナリで返す」という通常の解釈が正規表現である場合、`1000`。 以下の安全な実装では、バイナリ加算を直接実行し、同じ長さの入力文字列に依存せずに正規形式を自然に生成します。 

## アプローチ

 このタスクについて考える強引な方法は、考えられる数値を列挙し、正しい合計を検索することです。 長い入力に (L) 個の 2 進数がある場合、表現される数値は (2^L-1) まで大きくなる可能性があります。 その大きさまでのすべての可能な値を考慮する検索には (\Theta(2^L)) 個の候補が必要になる可能性があり、候補のバイナリ表現をチェックするだけでも最大 (O(L)) のコストがかかります。 最悪の場合、(\Theta(L2^L)) が機能しますが、わずか数十ビットの入力後には実行不可能になります。 ブルートフォースアプローチは、最終的には実際の合計を考慮するため正しいですが、バイナリ加算には非常に小さなローカル状態があるという事実が無視されます。 

重要な点は、各バイナリ列が 3 つの値 (2 つの入力ビットと下位列からのキャリー) のみに依存していることです。 2 つのビット (a) と (b) と受信キャリー (c) の場合、結果の桁は次のようになります。 

[
 (a+b+c)\bmod 2
 】

 そして発信キャリーは

 [
 \左\lf床\frac{a+b+c}{2}\右\r床。 
】

 可能な入力ビットのペアは 4 つだけで、キャリー値は 2 つしかないため、グローバル検索は必要ありません。 通常の紙と鉛筆の足し算に使用されるのとまったく同じプロセスを、最下位桁から開始して左に移動して再現できます。 

ブルート フォースは、考えられる結果の空間全体を検索するため機能しますが、その空間がビット数とともに指数関数的に増大するため失敗します。 バイナリ加算列は現在のビットのみに依存し、1 つのキャリーによって問題が入力の 1 回のパスに軽減されるという観察結果が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | バイナリ加算 | (O(L)) | (O(L)) | 承認済み |

 ここで (L=\max(|a|,|b|))。 

## アルゴリズムのチュートリアル

 1. 2 つのバイナリ文字列を読み取り、2 つのインデックスを最後の位置に設定します。 最下位桁は、別の列からのキャリーを必要とせずに合計が分かる最初の桁であるため、右から開始します。 
2. 初期キャリーをゼロに設定します。 最下位位置の右側には桁がないため、最初の加算にはキャリーは入りません。 
3. いずれかの文字列に未処理の桁が残っているか、キャリーが残っている間に、各文字列から現在の桁を読み取ります。 インデックスが文字列の先頭より前に移動した場合は、代わりにゼロを使用します。 これにより、2 つの数値の長さが異なる場合でも、最下位ビットで位置が揃えられます。 
4. コンピューティング`total = a_digit + b_digit + carry`。 出力ビットは`total % 2`、次のキャリーは`total // 2`。 以来`total`0、1、2、または 3 のみを指定でき、キャリーは常に 0 または 1 のいずれかになります。 
5. 生成されたビットを結果リストに追加します。 数字は最下位から最上位の順に生成されるため、リストは現在、通常の表現に対して逆になっています。 
6. 両方のインデックスを 1 つ左に移動し、入力桁とキャリーがなくなるまで続けます。 
7. 結果を反転して印刷します。 この反転により、通常の最上位ビットが最初の表現が復元されます。 

### なぜ効果があるのか

 任意の位置を処理した後、アルゴリズムによって保存されるキャリーは、通常の 2 進加算によって次の位置に送信されるキャリーとまったく同じです。 現在の位置の場合、アルゴリズムは、実際の入力ビットが存在する場合は両方を使用し、欠落ビットの場合は 0、そして正確にその入力キャリーを使用します。 したがって、2 を法として計算された剰余がその位置の唯一の有効な出力ビットとなり、整数を 2 で割ることで唯一の有効な出力キャリーが得られます。 最下位位置から最上位位置への帰納法により、生成されるすべての数字が正確になります。 すべての入力桁が消費され、桁上げが残っている場合は処理が続行されるため、最終的な先頭が`1`決して失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_binary(a: str, b: str) -> str:
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - ord('0') if i >= 0 else 0
        y = ord(b[j]) - ord('0') if j >= 0 else 0

        total = x + y + carry
        result.append(str(total & 1))
        carry = total >> 1

        i -= 1
        j -= 1

    return ''.join(reversed(result))

def main():
    a = input().strip()
    b = input().strip()
    print(add_binary(a, b))

if __name__ == "__main__":
    main()
```2 つのインデックスは、(2^0) 位置に対応する各文字列の最後の文字から始まります。 各反復では、右から 1 列だけを消費します。 

の条件式は、`x`そして`y`これにより、長さが等しくない文字列を追加できるようになります。 インデックスが負になると、対応する数値は残りのすべての列にゼロを与えます。 

ビット計算には次のものを使用します。`total & 1`、これは以下と同等です`total % 2`、 そして`total >> 1`これは、これらの非負の値の場合、整数を 2 で除算することに相当します。 どちらの式も、実行されている 2 進演算を直接反映します。 

結果は、入力を Python 整数に変換するのではなく、文字として保存されます。 これにより、数値のサイズへの依存が回避され、アルゴリズムが入力ビット数に比例した状態が保たれます。 

このアルゴリズムでは、潜在的に巨大な 2 進数をマシンサイズの整数として格納することがないため、整数オーバーフローの問題は発生しません。 数値変数は、個々のビット、キャリー、およびそれらの合計だけです。

## テストケース```python
import sys
import io

def add_binary(a: str, b: str) -> str:
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - ord('0') if i >= 0 else 0
        y = ord(b[j]) - ord('0') if j >= 0 else 0

        total = x + y + carry
        result.append(str(total & 1))
        carry = total >> 1

        i -= 1
        j -= 1

    return ''.join(reversed(result))

def solve():
    a = input().strip()
    b = input().strip()
    return add_binary(a, b)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        return solve() + "\n"
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run("101\n11\n") == "1000\n", "sample 1"

# Minimum-size inputs
assert run("0\n0\n") == "0\n", "minimum values"

# Final carry
assert run("1\n1\n") == "10\n", "final carry"

# Unequal lengths
assert run("1\n111\n") == "1000\n", "different lengths"

# All equal digits
assert run("111111\n111111\n") == "1111110\n", "all ones"

# Leading zeroes
assert run("00101\n0011\n") == "1000\n", "leading zeroes"

# Large input, exercising linear processing
n = 10000
assert run("1" * n + "\n" + "1\n") == "1" + "0" * (n - 1) + "0\n", "large input"
