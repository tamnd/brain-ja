 ## 解決策
 ## 問題の理解

 このシミュレーションでは、米国の累積感染者数を追跡します。 (N) を現在の感染者数、(N_{\max}=328.2) 百万を曲線が平坦になる人口、(a) を特定のテスト ケースの感染率とします。 

このモデルでは、1 日の新規感染者数は次のように計算されます。 

[
 \デルタ N = a\left(1-\frac{N}{N_{\max}}\right)N。 
】

 1 タイム ステップは 1 日を表すため、次の日の人口は、この数量を現在の人口に加算することによって取得されます。 当初の感染者数は（1人）。 感染者数が少なくとも（3億2,000万）人に達する最初の日が必要です。 各テスト ケースでは (a) の異なる値が提供され、答えはそのレートに必要な日数になります。 公式声明では、1 秒の制限時間と 256 MB のメモリが指定されており、以下に示すサンプル レートと回答が示されています。 

この声明では、検査件数や感染率の明確な数値限界は示されていない。 そのため、入力制約に関する従来の漸近的な最悪の場合の限界をより正確に記述することが不可能になります。 意図したシミュレーションは、サンプル レートのわずか数百回の反復で要求された母集団に到達するため、関連する実装では、シミュレーション 1 日あたりの少量の一定量の浮動小数点作業が行われます。 ターゲット自体が 3 億 2,000 万人であるため、1 秒の制限がある場合、個々の人の数に比例した作業を実行するアプローチではコストがかかりすぎます。 シミュレーションの自然な単位は 1 人ではなく、丸 1 日です。 

停止条件または初期状態が正しく処理されない場合、答えが変わる可能性のある境界ケースがいくつかあります。 たとえば、人口がすでに目標に達している場合、必要な追加日数はゼロです。 この問題では、実際の初期母集団は (1) であるため、この状況は公式の入力モデルでは発生しませんが、別の更新を実行する前にループでターゲットをテストする必要がある理由が説明されています。 

より関連性の高いケースは、人口が目標を超えた最初の日です。 答えは前日ではなく、その日の指数です。 概念的に、人口が (66) 日目には (3 億 2,000 万) 未満で、(67) 日目には少なくとも (3 億 2,000 万) であった場合、正しい出力は次のようになります。`67`。 人口をチェックした翌日にインクリメントするループにより、誤って報告される可能性があります`66`。 

もう 1 つのエッジ ケースは、ターゲット付近の平坦化係数です。 (N) が (N_{\max}) に近づくと、係数 (1-N/N_{\max}) が小さくなるため、新規感染者数は急激に減少します。 式を (aN) に置き換えると、この効果が無視され、目標に到達するのが早すぎます。 

初期値も重要です。 (N=0) から開始すると、式には係数として (N) が含まれるため、後続の増分はすべてゼロになります。 問題で指定されているように (N=1) から開始すると、その縮退状態が回避されます。 

## アプローチ

 強引な解釈では、流行を個人レベルでシミュレートすることになる。 毎日、現在感染している集団を検査し、感染がどのように蓄積するかを繰り返し判断することができます。 たとえこれが決定論的であったとしても、最大 3 億 2,000 万人を約 400 日間処理するには、大規模な場合、(3 億 2,000,000\times400=128) 億人レベルの操作が必要になります。 これでは 1 秒の制限時間に収まりません。 

この方程式では、1 日全体の新規感染者数の合計がすでに得られているため、人々を個別に処理する理由はありません。 現在 (N) が与えられると、1 回の乗算で 1 日全体の増加が計算されます。 更新します

 [
 N \leftarrow N+a\left(1-\frac{N}{328200000}\right)N
 】

 (N\ge320000000) まで繰り返します。 

重要な観察は、問題が決定論的に再発するということです。 (N) と (a) がわかれば、次の (N) の値が完全に決まります。 シミュレーション内に隠れた分岐、検索、グラフの走査、または最適化の問題はありません。 目標に到達するまでその繰り返しを追跡するだけで済みます。 

したがって、毎日の直接的な繰り返しは、すでに最適な実用的なアプローチです。 唯一意味のある最適化は、繰り返しを 1 人あたり 1 回ではなく 1 日に 1 回実行することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 人間レベルの総当たり攻撃 | (O(DP)) | (O(1)) | 遅すぎる |
 | 毎日の繰り返しシミュレーション | (O(D)) テスト ケースごと | (O(1)) | 承認済み |

 ここで (D) はシミュレートされた日数、(P) は仮想の人物レベルの方法によって処理される人口です。 意図したレートの場合、(D) はわずか数百程度です。 

## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、各感染率を個別に処理します。 すべてのテスト ケースは同じ初期母集団から開始され、同じ定数を使用するため、ケース間で共有する必要がある状態はありません。 
2. 現在の感染者数を (N=1) に設定し、経過日数を 0 に設定します。 最初の感染者は最初のシミュレーション日よりも前に存在するため、この集団は 1 日分の新規感染者数としてカウントされてはなりません。 
3. (N<320000000) の間、次の 1 日の新規感染者数を計算します。 

[
 \デルタ N=a\left(1-\frac{N}{328200000}\right)N。 
】

 係数 (1-N/N_{\max}) は、モデルに従ってまだ感染していない人口の割合を表します。 
4. (\Delta N) を (N) に加算し、日カウンターを 1 つ増やします。 新しく計算された人口は次の日に属するため、増分は日カウンタが進む前に行われる必要があります。 
5. (N\ge320000000) になったらすぐに停止し、日カウンターを出力します。 私たちが使用するのは`>=`再帰は浮動小数点値で動作し、通常はターゲットに正確に到達するのではなく、ターゲットを横切るためです。 

### なぜ効果があるのか

 不変条件は、(d) 回の反復の後、(N) は、(d) シミュレートされた日数の後に通常の浮動小数点丸めまでの問題の再発によって正確に生成される母集団であるということです。 更新は、指定された感染方程式を使用し、指定された初期集団 1 から開始されます。 したがって、各反復は正確に追加の 1 日のシミュレーションを表します。 ループは、シミュレートされた人口が少なくとも 3 億 2,000 万人に達する最初の反復で終了するため、報告されるカウンターは正確に最初に必要な日になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N_MAX = 328_200_000.0
TARGET = 320_000_000.0

def days_to_target(a):
    n = 1.0
    days = 0

    while n < TARGET:
        n += a * (1.0 - n / N_MAX) * n
        days += 1

    return days

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a = float(input())
        ans.append(str(days_to_target(a)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```再発には部分的な感染率が含まれており、母集団の更新は一般に整数ではないため、定数は浮動小数点値として保存されます。 人口を浮動小数点として保持すると、整数表現と浮動小数点表現の間で繰り返し変換することも避けられます。`days_to_target`アルゴリズムからの反復が正確に含まれています。`n`から始まります`1.0`、 その間`days`シミュレートされた日がまだ経過していないため、ゼロから始まります。 条件`n < TARGET`各更新の前にチェックされるため、ループが終了すると、`days`人口が必要なしきい値に達した最初の日です。 

式は、新しい値を割り当てる前に評価されます。`n`。 これは、その日の初めの人口を使用してその日の感染者数を計算することに相当します。 すでに更新された母集団を同じ反復で再度使用すると、1 日以内に複数の感染の更新を効果的にシミュレートし、異なるモデルが生成されます。 

Python の浮動小数点型は、通常の競技プログラミング環境では 64 ビット IEEE-754 double です。 ここでの母集団の値は有効な精度の範囲内にはるかに収まっており、目的の入力に対して必要な更新は数百回だけです。

## テストケース

 公式声明では 4 つのサンプルケースが提供されていますが、(a) の正式な最小値または最大値の限界は指定されていません。 そのため、テスト ハーネスは、文書化された最大レートの制約があるかのように振る舞うのではなく、再発を直接検証できます。```python
import sys
import io

N_MAX = 328_200_000.0
TARGET = 320_000_000.0

def days_to_target(a):
    n = 1.0
    days = 0

    while n < TARGET:
        n += a * (1.0 - n / N_MAX) * n
        days += 1

    return days

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        a = float(input())
        out.append(str(days_to_target(a)))

    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided sample
assert run("4\n.394\n.212\n.107\n.059\n") == "67\n118\n226\n403", "official sample"

# Small positive rate. This catches accidental zero-based initialization.
assert days_to_target(1.0) > 0, "initial population must be one"

# Equal rates must produce equal answers.
assert run("3\n.212\n.212\n.212\n") == "118\n118\n118", "all equal rates"

# A larger rate must reach the target sooner than a smaller rate.
assert days_to_target(0.394) < days_to_target(0.212), "rate ordering"

# Rates very close to each other should still be processed independently.
a = days_to_target(0.059)
b = days_to_target(0.060)
assert b < a, "boundary between nearby rates"

print("All tests passed.")

 ## 特殊なケース

 初期集団はちょうど 1 人です。 実装がゼロから始まる場合、(N) は感染項全体を乗算するため、反復により永久にゼロが生成されます。 から始まる`1.0`このサイレントエラーを回避し、問題の指定された初期条件に従います。 

停止条件は次のとおりである必要があります`n < TARGET`、 ない`n <= TARGET`。 1 日の更新により人口が 319,999,999 人から 320,000,001 人に変化すると仮定します。 人口がちょうど 3 億 2,000 万人に達することはありませんが、目標は達成されたため、正解はその日です。 特に、浮動小数点シミュレーションが偶然に正確な整数ターゲットに到達する可能性はほとんどありません。 

平坦化項もターゲット付近で重要になります。 たとえば、(N) が 3 億 2,820 万に近い場合、式 (1-N/N_{\max}) はゼロに近づきます。 実装が誤って書き込んだ場合`a * n`の代わりに`a * (1 - n / N_MAX) * n`、平坦化効果全体が除去され、実質的に小さな答えが生成されます。 

最後に、更新ではその日の初めからの人口を使用する必要があります。 正しい遷移は

 N+a\left(1-\frac{N}{N_{\max}}\right)N.
 】

 この式の一部を次から計算します。`N`そして修正する`N`式を終了する前に繰り返しが変更されます。 Python では、右辺全体を書いてから代入します。`n`必要な順序が自然に保持されます。
