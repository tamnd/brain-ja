 ## 解決策
 ## 問題の理解

 最初の入力行に平文の文が与えられ、2 行目にキーワードが与えられます。 課題は、古典的なヴィジェネール暗号を使用して文を暗号化することです。 

キーワードの各文字はアルファベットのシフトを表します。`a`シフトすることを意味します`0`、`b`シフトすることを意味します`1`、などまで`z`、つまりシフト`25`。 キーワードは必要なだけ繰り返されますが、平文内のスペースは暗号化されず、キーワードの文字を消費しません。 暗号化された文は、元のスペースを維持し、平文の各文字の大文字と小文字を保持する必要があります。 

たとえば、平文の場合`Here is an example test case`そして鍵`fish`、最初の 4 文字はシフトを使用します`f`、`i`、`s`、`h`。 スペースの後の次の平文文字は、キーを再開するのではなく、次のキー文字に続きます。 

公開された問題には、1 秒の時間制限と 256 MB のメモリ制限があります。 このステートメントでは、平文の制限的な最大長が公開されていないため、本来のターゲットは入力に対する単一の線形パスです。 文字数に比例した作業を行うアルゴリズムで十分ですが、大規模な補助構造を構築したり、アルファベットを繰り返し検索したりする必要はありません。 

最初のエッジ ケースは、スペースを含むプレーンテキストです。 入力用```
a a
b
```正しい出力は```
b b
```最初`a`キーを使用します`b`、そして2番目`a`キーも使用します`b`キー文字を消費するのではなく、スペースがスキップされるためです。 すべての文字のキー インデックスを進める実装では、2 番目の文字に対して異なるキー位置が誤って使用されてしまいます。`a`。 

2 番目のエッジ ケースは、平文よりも短いキーです。 入力用```
abcde
bc
```キーシーケンスは`bcbc b`したがって、出力は次のようになります```
bddff
```各キー文字を 1 回だけ使用する不注意な実装では、先頭に戻る代わりにキー文字が不足してしまいます。 

3 番目のエッジ ケースは、大文字と小文字の混合です。 入力用```
Az
b
```出力は```
Ba
```シフトは同じアルファベットの位置を使用して計算されますが、結果は元の文字の大文字と小文字を使用して記述する必要があります。 すべてを小文字として扱うと、大文字が間違って使用されます。 

## アプローチ

 直接実装すると、ヴィジュネールのタブローをシミュレートできます。 すべての平文文字を次の数値に変換します。`0`に`25`、対応するキー文字を別の数値に変換し、2 つの値を剰余として加算します。`26`、結果を文字に変換し直します。 これが、プレーンテキスト文字ごとに 26 個の可能な出力文字すべてを検索することによって実装される場合、作業は次のようになります。`26n`長さの平文の文字比較`n`。 アルファベットのサイズが 26 に固定されているため、これは依然として線形であり、実際の問題ではそれほど遅いわけではありません。 ただし、不必要な作業が実行され、数学的演算に必要な実装よりも複雑になります。 

重要な観察は、ヴィジェネールのタブローは単なるモジュール加算であるということです。 もし`p`は平文文字のアルファベット位置であり、`k`はキー文字の位置、暗号化された位置は`(p + k) mod 26`。 

タブローを作成したり、検索したりする必要はありません。 答えを直接計算できます。 

キー インデックスは、アルファベットの平文文字が処理される場合にのみ進みます。 スペースが見つかった場合は、それを直接コピーし、キー インデックスは変更しないままにします。 最後のキー文字を使用した後、インデックスはモジュロでラップアラウンドします。`len(key)`。 

この総当りアプローチは、最終的には同じアルファベット シフトを実行するため機能しますが、Vigenère テーブルのすべての検索には単純な算術式があるという事実を利用できません。 暗号化はモジュール加算であるという観察により、入力文字ごとに 1 つの一定量の計算に作業が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26n) = O(n) | お(26) | 受け入れられましたが、不必要な作業 |
 | 最適 | O(n) | 出力の O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 平文とキーを読み取り、改行文字のみを削除します。 内部スペースは出力内で変更されずに表示される必要があるため、内部スペースを削除する変換を使用してはなりません。 
2. キーポインタを`0`。 このポインタは、次の平文文字を暗号化するキー文字を表します。 
3. 平文を左から右に処理します。 すべてのスペースについて、結果にスペースを追加し、キー ポインタを変更しないでください。 暗号ではスペースがスキップされるため、次の実際の文字は同じキー位置を使用し続ける必要があります。 
4. すべてのアルファベット文字について、次のコマンドを使用してそのアルファベットの位置を取得します。`ord(character.lower()) - ord('a')`。 対応するキーシフトを取得するには、`ord(key[key_index].lower()) - ord('a')`。 
5. 平文の位置とキーシフトモジュロを追加します。`26`。 モジュロは次のものです`z`に巻き付ける`a`。 
6. 結果の位置を文字に変換し直します。 元の平文文字が大文字の場合は、結果も大文字に変換します。 暗号化された文字を結果に追加します。 
7. キー ポインタを進め、モジュロでラップします。`len(key)`。 これにより、繰り返し文字列を明示的に構築することなく、キーワードが無限に繰り返されます。 
8. 完成した結果を印刷します。 結果はリストに蓄積され、一度結合されるため、プログラムは不変の Python 文字列を繰り返し再構築することを回避します。 

### なぜ効果があるのか

 キー ポインタは暗号化された文字ごとに 1 回進み、スペースを越えて進むことはないため、アルゴリズムは、アルファベットの各位置で、繰り返されるキーワード内のその位置を占めるキー文字を正確に使用します。 暗号化されたアルファベットの位置は次のように計算されます。`(plaintext_position + key_position) % 26`、これはまさにヴィジェネール暗号化ルールです。 結果は元の大文字と小文字に変換され、暗号化されていない文字はすべて変更されずにコピーされるため、出力される文字はすべて正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    plaintext = input().rstrip('\n')
    key = input().rstrip('\n')

    result = []
    key_pos = 0
    key_len = len(key)

    for ch in plaintext:
        if ch == ' ':
            result.append(ch)
            continue

        base = ord('A') if ch.isupper() else ord('a')

        p = ord(ch) - base
        k = ord(key[key_pos].lower()) - ord('a')

        encrypted = (p + k) % 26
        out = chr(base + encrypted)

        result.append(out)
        key_pos = (key_pos + 1) % key_len

    sys.stdout.write(''.join(result) + '\n')

if __name__ == "__main__":
    solve()
```最初の 2 行は、スペースを保持しながらプレーンテキストとキーを読み取ります。`rstrip('\n')`文から意味のあるスペースを削除せずに、入力された改行を削除します。`key_pos`生の文字位置ではなく、暗号化された文字をカウントします。 この違いが、この問題の主な実装の詳細です。 プレーンテキストにスペースが含まれている場合、ループは変更されずに続行されます。`key_pos`。 

の`base`変数を使用すると、同じ算術で大文字と小文字を処理できます。 のために`A`、アルファベットの位置は`0`、その間、`a`それもです`0`。 暗号化された位置は大文字小文字に関係なく計算され、`base`その後、元のケースを復元するために使用されます。 

モジュロ演算はラップアラウンドを処理します。 例えば、`z`地位がある`25`、そしてシフトを追加します`2`与える`(25 + 2) % 26 = 1`に対応します。`b`。 

キー ポインタは、文字を暗号化した後にのみ進められます。 書き込み`(key_pos + 1) % key_len`キーを自動的に繰り返します。 ポインターがインクリメントされる前に現在のキー文字が読み取られるため、off-by-one の問題は発生しません。 

などの連結を繰り返すため、結果はリストに格納されます。`result += out`不必要な文字列コピーが発生する可能性があります。 最後に一度結合すると、きれいな線形時間構造が得られます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    plaintext = input().rstrip('\n')
    key = input().rstrip('\n')

    result = []
    key_pos = 0
    key_len = len(key)

    for ch in plaintext:
        if ch == ' ':
            result.append(ch)
            continue

        base = ord('A') if ch.isupper() else ord('a')
        p = ord(ch) - base
        k = ord(key[key_pos].lower()) - ord('a')

        encrypted = (p + k) % 26
        result.append(chr(base + encrypted))

        key_pos = (key_pos + 1) % key_len

    sys.stdout.write(''.join(result) + '\n')

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("Here is an example test case\nfish\n") == \
       "Mmjl na su jfstutw ajal jfaw\n", "sample 1"

# Minimum-size input
assert run("a\nb\n") == "b\n", "minimum-size case"

# Key longer than the plaintext
assert run("abc\nxyz\n") == "xzz\n", "key longer than plaintext"

# Spaces must not advance the key
assert run("a a\nb\n") == "b b\n", "spaces must not consume key characters"

# Uppercase/lowercase preservation and alphabet wraparound
assert run("Az\nb\n") == "Ba\n", "case and wraparound"

# Repeated key and exact key-boundary transition
assert run("abcde\nbc\n") == "bddff\n", "key repetition"

 ## 特殊なケース

 スペースの場合は、正確な入力を考慮してください```
a a
b

abcde
bc
