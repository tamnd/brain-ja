 ## 解決策
 ## 問題の理解

 この問題では、1 つの正の整数 (n) を調べるように求められます。 (n) 自体を除く、(n) のすべての正の約数を合計する必要があります。 その合計が (n) に等しい場合、(n) は完全数になります。 出力では、まず、必要な語句を正確に使用して、これが発生するかどうかを示し、次に除数の合計を出力する必要があります。 アーカイブされた問題は Gym 102697、問題 138 で、制限は 1 秒、メモリは 256 MB です。 

たとえば、(n=28) の場合、適切な約数は (1,2,4,7,14) で、その合計は (28) となるため、出力は次のようになります。`PERFECT NUMBER`に続く`28`。 (n=48) の場合、適切な約数の合計は (76) となるため、出力は次のようになります。`NOT A PERFECT NUMBER`に続く`76`。 

このステートメントは、表示される制約に小さな明示的な上限を与えていません。 代わりに、計算に含まれるすべての値が Java に適合することが保証されます。`int`したがって、実装では (n) までの試行ループが実用的であると想定すべきではありません。 32 ビットの符号付き整数は、おおよそ (2.1\times10^9) ほどの大きさになる可能性があり、そのような値まですべての整数を反復処理するには、何十億回もの割り切りチェックが必要になります。 要求された合計自体が指定された整数の範囲内に収まる場合でも、アルゴリズムは依然として間隔全体のスキャンを回避する必要があります。 

直接実装では誤って処理される可能性のある境界ケースがいくつかあります。 1 つ目は (n=1) です。 その唯一の約数は (1) ですが、その約数は数値そのものであるため除外され、適切な約数の合計は (0) になります。 正しい出力は次のとおりです`NOT A PERFECT NUMBER`に続く`0`。 すべての入力に対して合計を (1) で初期化する不注意な実装では、(1) が誤って分類されてしまいます。 

2 番目のケースは、(n=7) のような素数です。 唯一の適切な約数は (1) なので、答えは次のようになります。`NOT A PERFECT NUMBER`に続く`1`。 除数のペアのみを検索し、除数 (1) を忘れた実装では、誤った合計がゼロになる可能性があります。 

3 番目のケースは、(n=36) のような完全な正方形です。 その約数のペア (6\times6) には同じ約数が 2 回含まれているため、(6) は 1 回だけ加算する必要があります。 適切な約数の合計は (1+2+3+4+6+9+12+18=55) です。 平方根を通常の約数のペアと同じように扱うと、(6) が 2 回カウントされ、結果は (61) になります。 

最後に、(n=6) のような真の完全数には適切な約数 (1,2,3) があり、正確に (6) が得られます。 正しい出力は次のとおりです`PERFECT NUMBER`に続く`6`。 このケースでは、ペア内の約数の 1 つを誤って除外する実装が検出されます。 

## アプローチ

 簡単なアプローチは、(1) から (n-1) までのすべての整数 (d) をテストし、(d) が (n) を割るかどうかを確認し、割れる場合はそれを加算することです。 すべての適切な約数が 1 回だけ考慮されるため、これは正しいです。 問題はチェックの数です。 署名付き Java で許可される最大値に近い入力の場合`int`これは、およそ (2.1\times10^9) のモジュラス演算を意味します。これは、1 秒の競合プログラミング ソリューションで実現できる量をはるかに超えています。 

便利な構造は、約数がペアで出現することです。 (d) が (n) を割る場合、(n/d) も約数になります。 たとえば、(48) の約数は、(1,48)、(2,24)、(3,16)、(4,12)、(6,8) のようにペアになります。 適切な約数のみが必要な場合は、(n) に等しいメンバーを除外する必要がありますが、他のすべての約数はこれらのペアを通じて見つけることができます。 

これは、(\sqrt n) までの候補約数をテストするだけでよいことを意味します。 (d) が (n) を割るときは常に、(d) とそのペアの約数 (n/d) を加算します。 (d) が正確に (\sqrt n) である場合、2 つの値は同一であるため、加算する必要があるのは 1 回だけです。 また、(d=1) でそのペアの約数が (n) である場合に発生する (n) 自体の加算も避ける必要があります。 

ブルートフォース手法は、考えられるすべての適切な約数を明示的にチェックするため機能しますが、検索間隔が (n) と同じくらい大きいため失敗します。 約数が相補的なペアで到着するという観察により、(O(n)) 検索を (O(\sqrt n)) 検索に置き換えることができます。 (2\times10^9) 付近の値の場合、約数候補の数は数十億からわずか約 46,000 に減ります。

 ## アルゴリズムのチュートリアル

 1. 整数 (n) を読み取り、適切な除数の合計をゼロに初期化します。 (n=1) の場合、(1) は適切な約数ではないため、ゼロから開始する必要があります。 
2. (1) から (\lfloor\sqrt n\rfloor) まで (d) を繰り返します。 (\sqrt n) より大きい約数は、ループ内で遭遇するより小さい約数とペアになるため、より大きな候補を直接調べる必要はありません。 
3. (d) が (n) を割るたびに、対の約数 (q=n/d) を計算します。 ペア ((d,q)) は、この (d) の値に関連付けられたすべての約数を与えます。 
4. (d<n) の場合は (d) を追加します。 この条件は、自明な場合 (n=1) を除いて (d\leq\sqrt n) に対して常に true ですが、条件を明示的に記述することで、正除数の要件が明確になります。 
5. (q\neq d) および (q<n) の場合は (q) を追加します。 最初の条件は、完全二乗がその平方根を 2 回カウントすることを防ぎ、2 番目の条件は、(n) 自体が正約数の合計に入るのを防ぎます。 
6. 結果の合計を (n) と比較します。 印刷する`PERFECT NUMBER`等しい場合、そうでない場合は出力します`NOT A PERFECT NUMBER`、2 行目に合計が続きます。 

### なぜ効果があるのか

 不変条件は、すべての候補除数 (d\leq\sqrt n) を処理した後、累積和には補数にすでに達しているすべての適切な約数が含まれ、そのような各約数が 1 回だけ含まれることです。 (n) のすべての約数は、最大 1 つのメンバー (\sqrt n) を持つペア ((d,n/d)) に属しているため、ループは最終的にすべての約数を検出します。 条件 (q\neq d) は、ペアが 1 つの値、つまり完全な正方形に折りたたまれる唯一のケースを処理します。 条件 (q<n) は (n) 自体を除外し、適切な約数を正確に残します。 したがって、最終的な合計は問題で必要な量と正確に一致するため、それを (n) と比較することで正しい分類が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    divisor_sum = 0
    d = 1

    while d * d <= n:
        if n % d == 0:
            q = n // d

            if d < n:
                divisor_sum += d

            if q != d and q < n:
                divisor_sum += q

        d += 1

    if divisor_sum == n:
        print("PERFECT NUMBER")
    else:
        print("NOT A PERFECT NUMBER")

    print(divisor_sum)

if __name__ == "__main__":
    solve()
```(1) はすべての正の整数の約数であるため、ループは (1) から始まります。 可算性テストが成功するたびに、`q = n // d`別の検索を行わずに相補的な約数を返します。 

条件`d * d <= n`浮動小数点の平方根を計算するよりも適しています。 これにより、丸めの問題が回避され、計算全体が整数演算に保たれます。 Python の整数ではオーバーフローの懸念も解消されますが、元のステートメントでは関連する値が Java に適合することが保証されています。`int`。 

除数を追加する前の 2 つのチェックにより、定義が正確に適用されます。 いつ`n = 48`そして`d = 1`、ペアは`(1, 48)`。 値`1`が追加されますが、`48`番号そのものであるため拒否されます。 いつ`n = 36`そして`d = 6`、ペアは`(6, 6)`したがって、最初の条件が追加されます`6`そして 2 番目の条件はそれを拒否します。`q == d`。 

除数を保存する必要はありません。 必要なのはそれらの合計だけであるため、アキュムレータは 1 つで十分です。

 ## 特殊なケース

 (n=1) の場合、正確な入力は次のとおりです。`1`。 ループは (d=1) から始まり、(1) を除算して (q=1) を与えます。 最初の条件は (d<n) が false であるため (d) を拒否し、2 番目の条件は (q=d) であるため (q) を拒否します。 合計はゼロのままなので、出力は次のようになります。`NOT A PERFECT NUMBER`に続く`0`。 これにより、(1) をそれ自身の適切な約数として扱うというよくある間違いを回避できます。 

(n=7) のような素数の場合、見つかる約数のペアは (1,7) だけです。 このアルゴリズムは (1) を加算し、(n) と等しいため (7) を拒否し、(1) の合計を取得します。 出力は`NOT A PERFECT NUMBER`に続く`1`。 除数ペア手順では素数が自然に処理されるため、特別な素数性テストは必要ありません。 

完全な正方形 (n=36) の場合、ループは最終的に (d=6) (q=36/6=6) に到達します。 アルゴリズムは、最初の条件を通じて (6) を 1 回追加し、再度追加することを拒否します。`q != d`は誤りです。 他のペアは (1,36)、(2,18)、(3,12)、および (4,9) に寄与しますが、(36) 自体は除外されます。 結果の合計は (55) となるため、出力は次のようになります。`NOT A PERFECT NUMBER`に続く`55`。 

完全数 (n=6) の場合、ペアは (1,6) と (2,3) になります。 アルゴリズムは (1) を加算し、(6) を拒否し、次に (2) と (3) を加算して (6) を生成します。 等価性テストは成功し、次のようになります。`PERFECT NUMBER`に続く`6`。 これは、既知の完全数のハードコードされたリストを必要とせずに、同じ約数ペア機構が本物の完全数に対して機能することを確認します。
