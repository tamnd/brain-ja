 ## 解決策
 ## 問題の理解

 このタスクは、加算と減算によって接続された整数を含む単一の算術方程式を評価することです。 方程式は等号で終わり、必要な出力は元の方程式をそのまま維持しながら、その数値結果を追加します。 

たとえば、入力`1 + 5 + 7 - 2 =`は計算 (1+5+7-2) を表し、その値は (11) です。 必要な出力は次のとおりです`1 + 5 + 7 - 2 = 11`。 問題のステートメントでは、方程式のサイズに関する個別の数値制限は示されていませんが、制限時間は 1 秒で、式は通常の入力文字列です。 そのため、リニア スキャンが自然なターゲットになります。 式に (L) 個の文字が含まれている場合、(O(L)) ソリューションは文字ごとに一定量の作業を実行しますが、繰り返し再スキャンすると式が (O(L^2)) まで増大する可能性があります。 

主なエッジ ケースは、減算が可換ではないこと、および等号が入力形式の一部であるという事実から生じます。 のために`8 - 3 - 2 =`、正しい出力は次のとおりです。`8 - 3 - 2 = 3`。 すべての数値を正の値として扱う不注意な実装では (13) が生成され、減算を 1 つの演算として解釈する実装では間違ったグループ化が生成される可能性があります。 

のために`5 - 5 + 5 - 5 =`、正しい出力は次のとおりです。`5 - 5 + 5 - 5 = 0`。 これにより、解析されたすべての数値を誤って追加し、後で演算子のみを検査する実装が捕捉されます。 

有用な最小の方程式については、`7 =`、正しい出力は次のとおりです。`7 = 7`。 処理する演算子がないため、最初の数値が直接結果になる必要があります。 

## アプローチ

 簡単なアプローチは、残りの式で次の数値とそれに続く演算子を繰り返し検索することです。 これは正しいです。式には加算と減算のみが含まれており、項を左から右に評価すると正確な算術結果が得られます。 この実装の問題は、不必要な再スキャンです。 すべての検索が未処理部分の先頭から再度開始される場合、(L) 個の文字を含む式により、おおよそ (L+(L-1)+\cdots+1=O(L^2)) 個の文字検査が発生する可能性があります。 十分に長い入力の場合、その二次関数の動作は回避可能な作業です。 

重要な点は、加算と減算には優先順位の違いがないということです。 数値とその符号が読み取られると、最終的な答えに対するその寄与が完全に決定されます。 以前のキャラクターを再訪する必要はありません。 左から右への 1 回のスキャンで現在の数値を累積することができ、プラスまたはマイナス記号に遭遇すると、完成した数値をすぐに答えに加算または減算できます。 

等号は計算に関与しません。 これは単に算術式の終了をマークするだけです。 到達したら処理を停止し、必要な出力に対して元の入力行を保持できます。 

したがって、2 つのアプローチの違いは、それほど複雑な数学的手法ではありません。 式が独立した署名付き用語のストリームであることが認識されるため、各文字を検査する必要があるのは 1 回だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(L²) | O(L) | 大規模な式には遅すぎる |
 | 最適 | O(L) | お(1) | 承認済み |

 ここで (L) は入力方程式の長さを示します。 

## アルゴリズムのチュートリアル

 1. 完全な方程式を文字列として読み取り、最終出力用に正確に保存します。 元の書式設定は、問題が印刷するよう要求する内容の一部です。 
2. 累積された答え、現在の数値、およびその数値に適用される符号を維持しながら、方程式を左から右にスキャンします。 正の符号で始めると、最初の数値が自然に処理されます。 
3. 数字が見つかったら、現在の数字をその数字で拡張します。 たとえば、読書`42`現在の数値を次から変更します`4`に`42`。 
4. いつ`+`または`-`が発生した場合は、以前に保存した符号を完成した現在の数値に適用し、現在の数値をゼロにリセットして、新たに発生した符号を記憶します。 符号を変更する前に前の数値を処理すると、間違った演算子との関連付けが回避されます。 
5. いつ`=`が発生した場合は、保存されている符号を使用して最終数値を適用し、停止します。 この時点で方程式は完成です。 
6. 変更されていない元の式を印刷し、その後にスペースと計算された答えを続けます。 これにより、式の評価と必要な出力のフォーマットが分離されます。 

### なぜ効果があるのか

 スキャン中のすべての時点で、累積された答えは、現在の数値の前に表示されるすべての完全な用語の値と等しくなります。 現在の数値には次の項の数字が正確に含まれており、保存されている符号はまさにその項の直前の演算子です。 演算子または等号に到達すると、その符号を適用すると、累積された答えに次の項の寄与が正確に追加されます。 すべての用語は 1 回だけ処理され、最後の用語は次の時点で処理されるため、`=`に達すると、最後の累積値は方程式全体の値とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    equation = input().rstrip("\n")

    answer = 0
    number = 0
    sign = 1

    for ch in equation:
        if ch.isdigit():
            number = number * 10 + ord(ch) - ord('0')
        elif ch == '+' or ch == '-':
            answer += sign * number
            number = 0
            sign = 1 if ch == '+' else -1
        elif ch == '=':
            break

    answer += sign * number

    print(equation + " " + str(answer))

if __name__ == "__main__":
    solve()
```の`equation`変数は元の行を格納するため、式を再構築せずに出力でそれを再現できます。 使用する`rstrip("\n")`式から任意の空白を削除するのではなく、行末のみを削除します。 

スキャナは、すべての桁を現在の整数の一部として扱います。 式には複数の桁の値が含まれる場合があるため、`number`現在の数字では正しくありません。 アップデート`number = number * 10 + digit`通常の方法で 10 進整数を構築します。 

演算子が見つかると、コードはまず古い符号を使用して現在の数値を追加します。 その後になって初めて符号が変わります。 この順序は次のような式に不可欠です。`10 - 3 + 4 =`。 

等号は、その後のすべてが算術式の外にあるため、評価を終了します。 決勝戦`answer += sign * number`最後の数値の後に処理をトリガーする演算子がないため、これが必要です。 

Python の整数は、通常の整数入力サイズではオーバーフローしないため、特別なオーバーフロー処理は必要ありません。

## テストケース```python
import sys
import io

def solve():
    equation = input().rstrip("\n")

    answer = 0
    number = 0
    sign = 1

    for ch in equation:
        if ch.isdigit():
            number = number * 10 + ord(ch) - ord('0')
        elif ch == '+' or ch == '-':
            answer += sign * number
            number = 0
            sign = 1 if ch == '+' else -1
        elif ch == '=':
            break

    answer += sign * number
    print(equation + " " + str(answer))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("1 + 5 + 7 - 2 =\n") == "1 + 5 + 7 - 2 = 11\n", "sample 1"

# Minimum-size equation
assert run("7 =\n") == "7 = 7\n", "single number"

# All values cancel
assert run("5 - 5 + 5 - 5 =\n") == "5 - 5 + 5 - 5 = 0\n", "all-equal values"

# Multi-digit values and repeated subtraction
assert run("20 - 7 - 3 + 10 =\n") == "20 - 7 - 3 + 10 = 20\n", "multi-digit terms"

# Boundary-style large expression
terms = ["1"] * 100000
large_equation = " + ".join(terms) + " =\n"
assert run(large_equation) == large_equation.rstrip("\n") + " 100000\n", "large input"

 ## 特殊なケース

 単一番号の場合`7 =`、スキャナーが読み取ります`7`の中へ`number`、に達します`=`、最初の正符号を使用して最後の項を追加します。 結果は`7`したがって、出力は次のようになります`7 = 7`。 アルゴリズムが機能するために演算子は必要ありません。 

のために`8 - 3 - 2 =`、 最初`-`原因`8`が追加され、符号が負に変わります。 2番目`-`追加します`-3`次の項では符号を負のままにします。 決勝戦`2`したがって、 が減算され、`3`。 出力は`8 - 3 - 2 = 3`。 

のために`5 - 5 + 5 - 5 =`、答えは (5)、(0)、(5)、そして最後に (0) と展開します。 すべての演算子はその直後の数値にのみ適用されますが、アキュムレータにはすでに完了したすべての項が含まれます。 

次のような 100,000 個の用語を含む大きな式の場合、`1 + 1 + 1 + ... + 1 =`、スキャナーは依然として各キャラクターを 1 回ずつ訪問します。 答えは次のようになります`100000`また、作業を二次時間に変える可能性のあるネストされたループや繰り返しの部分文字列検索はありません。
