 ## 解決策
 ## 問題の理解

 正の整数 (n) と整数 (k) が与えられます。 (n) に最も近い (k) 個の正の回文整数を出力する必要があります。 順序は、まず (n) からの絶対距離によって決定され、2 つの回文が同じ距離にある場合、小さい回文が最初に配置されます。 (n=6) のサンプルに示されているように、回文の場合は数値 (n) 自体も含まれます。 

たとえば、(600) の周囲の回文は、(595) と (606) になります。 距離は (5) と (6) なので、最初の 2 つの答えになります。 次に下位と上位の回文は (585) と (616) で、距離は (15) と (16) になります。 

公開されたステートメントでは、1 秒の時間制限と 256 MB のメモリが指定されていますが、現在利用可能なステートメントの (n) と (k) の明示的な上限は公開されていません。 そのため、通常の整数をスキャンするソリューションは特に魅力的ではありません。 さらに重要なのは、出力自体に (k) 個の数値が含まれるため、どのような解法でも単純に答えを生成するだけで少なくとも (\Omega(k)) 時間を費やす必要があります。 したがって、自然なターゲットは (O(k \log n)) または (O(kd)) になります。ここで、(d) は (n) の 10 進数の桁数です。 

いくつかの境界ケースにより、単純な実装が失敗する可能性があります。 (n) 自体が回文である場合は、それを最初に出力する必要があります。 入力用`6 10`、正しい出力は次で始まります。`6`、 に続く`5`、`7`、`4`、`8`、 等々。 (n) より厳密に小さい回文と厳密に大きい回文だけを検索する実装では、誤って省略されてしまいます。`6`。 

正の整数のみが許可されるため、下限も特別です。 入力用`1 2`、最も近い正の回文は次のとおりです。`1`そして`2`。 普通の前任者`1`は`0`、 しかし`0`印刷できません。 前任者を盲目的に受け入れる不注意な実装では、無効な答えが生成されます。 

10 のべき乗を超えることも、エラーの一般的な原因です。 入力用`99 3`、次の回文は`101`、元の長さを持たなくなったプレフィックスを誤ってミラーリングすることによって得られた 3 桁の回文ではありません。 同様に、`1000`、前の回文は`999`、次は`1001`。 

最後に、同点は小さい方の数で解決する必要があります。 入力用`10 3`、最も近い回文は次のとおりです。`9`そして`11`、両方とも距離 (1) にあるため、`9`最初に印刷する必要があります。 距離のみに基づいて比較すると、出力順序が指定されず、判定に失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、(n) から開始して、一度に 1 つの整数を外側に移動し、すべての整数が回文であるかどうかをテストすることです。 回文が見つかると、(k) 個の回文が収集されるまで答えに追加されます。 これは正しいです。すべての正の整数が (n) からの距離が増加するにつれて検査され、距離が等しい場合には小さいほうの数値が最初に検出されます。 

問題は、回文がまばらであることです。 (d) 桁の範囲の場合、回文は約 (10^{\lceil d/2\rceil}) 個しかないため、検索では十分な答えが見つかる前に非常に多くの非回文整数を通過する可能性があります。 選択した最も遠い回文が距離 (R) にある場合、総当たり法により (\Theta(R)) 回文チェックが実行されます。 1 つの数値をチェックするには (O(d)) のコストがかかり、(\Theta(Rd)) 桁の演算が行われます。 (R) は (k) によって制限されないため、これは避けられない (O(k)) 出力コストよりもはるかに大きくなる可能性があります。 

重要な観察は、固定桁長の回文は、長さが奇数の場合は中央の桁を含む前半部分によって完全に決定されるということです。 そのプレフィックスが選択されると、残りの数字はリフレクションによって強制されます。 これは、通常の整数を検索する必要がまったくないことを意味します。 ある回文から前または次の回文に直接ジャンプできます。 

次のような数値の場合、`753`、最初の 2 桁を取得し、`75`、なぜなら (\lceil 3/2\rceil=2) だからです。 このプレフィックスをミラーリングすると、`757`、元の接頭辞またはそれに近い最小の回文。 プレフィックスを減らすと、`74`与える`747`、そして再び減少すると、`737`。 増やすと得られるもの`767`、 それから`777`、など。 これらはまさに周囲の回文です`753`番号順に。 

任意の値の直前の先行および後続の回文を取得できると、残りのタスクは双方向のマージになります。 候補を 1 つ下 (n) に、もう 1 つを上 (n) に保持します。 反復ごとに、(n) からの距離を比較します。 近い方を出力し、同点の場合は小さい方を出力します。 次に、その面を次の回文に置き換えます。 両側の回文はソートされた順序で生成されるため、問題に必要な全体的な順序が生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Rd))、ここで (R) は必要な検索半径 | (O(k)) | 回文がまばらな場合は遅すぎる |
 | 最適 | (O(kd)) | (O(k+d)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) を 10 進数の文字列に変換し、その長さを決定します。 回文は前半をミラーリングすることによって定義されるため、10 進数の接頭辞を使用します。 
2. (n) の最初の (\lceil d/2\rceil) 桁を取得し、それらを中心に反映して得られる回文を作成します。 これにより、定義接頭辞が正確に (n) の接頭辞となる回文が得られます。 
3. 値 (x) より厳密に小さい最大の回文を見つけるには、まず (x) の接頭辞から回文を構築します。 その回文がすでに (x) より小さい場合、それが答えになります。 それ以外の場合は、プレフィックスを 1 つ減らして再度ミラーリングします。 プレフィックスを減らすことは、回文を小さくする可能性がある最も重要な部分に対する最小限の変更です。 
4. (x) より厳密に大きい最小の回文を見つけるには、(x) の接頭辞から回文を構築します。 (x) より大きければ、それが答えです。 それ以外の場合は、プレフィックスを 1 つ増やしてミラーリングします。 これにより、可能な限り最小の大きな回文が得られます。 
5. 下位候補を (n) の先行者として初期化し、上位候補を (n) の後続者として初期化します。 (n) 自体が回文である場合は、まずそれを出力してから、これら 2 つの厳密な近傍を続行します。 サンプルは、(n) が要求された回文の 1 つとしてカウントされることを示しています。 
6. 下位候補と上位候補をペアで比較する`(distance, value)`。 距離が主な順序付け基準であり、値がタイ ブレーカーであるため、より小さいペアを持つ候補が次に必要な候補となります。 
7. 下位の候補を出力した後、その厳密に下の次の回文に置き換えます。 上の候補を出力した後、それをその厳密に上の次の回文に置き換えます。 (k) 個の回文が生成されるまで繰り返します。 
8. 下側がゼロに達した場合は、使用不可としてマークします。 ゼロは有効な出力ではないため、残りのすべての答えは上位側から得られる必要があります。 

不変条件は、すべての反復の前に、`lower`は、(n) の下でまだ印刷されていない最大の正の回文です。`upper`は、上記 (n) のまだ印刷されていない最小の回文です。 下側の印刷されていない回文はすべて、次のサイズよりも大きくありません。`lower`したがって、それよりも (n) に近づくことはなく、同じ性質が対称的に当てはまります。`upper`。 したがって、最も近い残りの回文は、常にこれら 2 つの候補のいずれかでなければなりません。 それらを比較すると、`(distance, value)`必要な次の回答を正確に選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def make_pal(prefix: int, length: int) -> int:
    s = str(prefix)
    if length % 2 == 0:
        return int(s + s[::-1])
    return int(s + s[-2::-1])

def prev_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p < x:
        return p

    prefix -= 1

    if prefix == 0:
        return 0

    return make_pal(prefix, length)

def next_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p > x:
        return p

    prefix += 1

    if prefix == 10 ** half:
        return 10 ** length + 1

    return make_pal(prefix, length)

def solve():
    n, k = map(int, input().split())

    answer = []

    if str(n) == str(n)[::-1]:
        answer.append(n)

    lower = prev_pal(n)
    upper = next_pal(n)

    while len(answer) < k:
        if lower <= 0:
            answer.append(upper)
            upper = next_pal(upper)
            continue

        if upper <= 0:
            answer.append(lower)
            lower = prev_pal(lower)
            continue

        dl = n - lower
        du = upper - n

        if dl <= du:
            answer.append(lower)
            lower = prev_pal(lower)
        else:
            answer.append(upper)
            upper = next_pal(upper)

    sys.stdout.write("\n".join(map(str, answer)))

if __name__ == "__main__":
    solve()
```

`make_pal`中心的な構築ルーチンです。 For an even number of digits, the entire prefix is reflected. For an odd number of digits, the last prefix digit is the center and must not be duplicated, so`s[-2::-1]`中心より前のすべてを反映します。`prev_pal`まず現在のプレフィックスをミラーリングします。 結果の回文がすでに以下の場合`x`、どんなに小さな変更でも、より近い回文を生成することはできません。 それ以外の場合、プレフィックスは 1 回デクリメントされます。 これにより接頭辞が 0 になる場合、現在の値よりも同じ桁数の下にある正の回文は存在しないため、次の値が返されます。`0`下側は消耗済みとしてマークされます。`next_pal`対称ロジックに従います。 接頭辞を増やすと新しい桁数が作成される場合、次の回文は次の形式になります。`100...001`。 たとえば、その後`999`、定義プレフィックスをインクリメントすると長さの境界を越え、次の結果が生成されます。`1001`。 

メイン ループは、下位シーケンスと上位シーケンスを 2 つのソートされたストリームとして扱います。 比較`dl <= du`意図的に使用する`<=`、 ない`<`。 距離が等しい場合、より低い候補を選択すると、より小さい回文が最初に来るという問題の要件が実装されます。 

Python の整数には任意の精度があるため、実装には固定幅のオーバーフローの問題はありません。 コストがかかる可能性がある唯一の操作は、10 進数の接頭辞の変換とミラーリングであり、そのコストは桁数に比例します。
