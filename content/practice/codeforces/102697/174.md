 ## 解決策
 ## 問題の理解

 私たちの三次元空間には最大でも 8 つの惑星があります。 地球が原点`(0, 0, 0)`、そして宇宙船はそこから出発し、少なくとも一度はすべての惑星を訪問し、地球に戻らなければなりません。 2 点間を直接移動するにはユークリッド距離が必要となるため、課題は、指定されたすべての惑星を訪問する最小長の閉じたツアーを見つけることです。 公式の制約により、`n <= 8`、制限時間は 1 秒、メモリは 256 MB です。 

出力は最小総移動距離です。 ステートメントではこれを正の整数と呼んでいますが、例では意図した答えが実数であることが明確に示されており、丸めないという命令は浮動小数点の結果を直接出力する必要があることを意味します。 

の小さな値`n`アルゴリズムの全体像を完全に変えます。 一般的な巡回セールスマン問題は惑星の数で指数関数的になりますが、`2^8 = 256`小さいです。 階乗解であっても、`8! = 40320`可能性のある惑星の順序なので、ブルート フォースは実際には、指定された制約に対して十分に高速です。 それでも、サブセット動的プログラムは、部分的なルートに関する重要な情報を正確に取得し、制限が適度に増加した場合でも有用であるため、よりクリーンなソリューションです。 

不用意に実装すると問題が発生するケースがいくつかあります。 惑星が 1 つだけの場合、ルートは地球からその惑星に向かい、直接戻る必要があります。```
1
3 4 0
```答えは`10.0`。 連続する惑星間の距離のみを計算し、地球への最終帰還を忘れる実装では、誤った出力が発生します。`0.0`または`5.0`。 

複製された惑星にも特別な処理は必要ありません。 のために```
3
0 0 0
1 0 0
-1 0 0
```最小距離は`4.0`。 すでに地球に存在する惑星は訪問するのに費用がかかりませんが、他の 2 つの惑星は地球から行く必要があります。`0`に`1`、その後に`-1`、その後に戻ります`0`。 すべての惑星が地球から正の距離にあると仮定した実装では、距離がゼロの点が誤って処理される可能性があります。 

2 つの固定惑星間の距離が対称であっても、惑星の順序は重要です。 のために```
4
-1 0 0
-2 0 0
2 0 0
1 0 0
```答えは`8.0`。 マイナスポイントを連続して訪れ、プラスポイントを連続して訪れることで最適なルートが得られます。 惑星を地球からの距離で並べ替えるだけでは、一般的には問題は解決されません。これは、連続する惑星間のコストがルートの長さを決定するものであるためです。 これは最初の公式サンプルでもあります。 

## アプローチ

 最も直接的な解決策は、惑星の可能な順序をすべて列挙することです。 各順列では、地球から開始し、その順序で惑星を訪れ、最後に地球に戻ります。 あらゆる順序が検討されるため、最適なルートを見つける必要があります。 のために`n`惑星、あります`n!`順列があり、各ルートには`n + 1`したがって、距離評価のワーストケースの数は次のようになります。`(n + 1)n!`。 実際の最大値では`n = 8`、これだけです`9 * 40320 = 362880`距離の評価は非常に扱いやすいものです。 

ブルートフォースの問題は次のような場合に発生します。`n`成長します。 階乗成長はすぐに非現実的になります。 で`n = 12`、たとえば、すでにあります`479001600`各ルートのエッジを考慮する前の順列。 1 秒の制限は、同じ問題構造でよりスケーラブルな指数関数的アプローチが許容される場合、階乗増加を中心としたソリューションを構築する理由がないことを意味します。 

重要な観察は、多くの異なる部分ルートが同じ有用な状態を持っているということです。 すでにサブセット内の惑星を正確に訪れたと仮定します。`mask`そして現在は惑星に立っています`i`。 どうやってたどり着いたかは関係ない`i`; 同じサブセットとエンドポイントを持つすべてのルートの中で、後で役立つのは最短のものだけです。 同じ状態の長いルートは永久に破棄できます。 

これにより、標準のサブセット動的プログラミング状態が得られます。`dp[mask][i] = minimum distance needed to start at Earth, visit exactly the planets in mask, and finish at planet i`。 

そのような状態から、私たちはまだ訪れたことのない惑星を選ぶことができます`j`そしてそれをルートに追加します。 移行は単純に、`dp[mask | (1 << j)][j] = min(dp[mask | (1 << j)][j], dp[mask][i] + dist[i][j])`。 

すべての惑星を訪れた後も、ルートは地球に戻らなければならないため、最終的な答えは次の最小値になります。`dp[all][i] + dist[i][Earth]`。 

ブルート フォース ソリューションは、すべての順列を明示的に考慮するため機能しますが、同じ部分ルートを何度も繰り返します。 訪問先のサブセットと現在のエンドポイントのみが重要であるという観察により、すべての同等の部分ルートを 1 つの状態にマージできます。 これにより、実行時間が階乗から階乗に変更されます。`O(2^n n^2)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! n) | O(n) | n <= 8 の場合は受け入れられますが、スケーラビリティは低くなります。 
| 最適 | O(2^nn^2) | O(2^n n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. を読んでください。`n`惑星座標を使用し、地球を座標を持つ別の点とみなします`(0, 0, 0)`。 インデックスを使用します`0`を通して`n - 1`惑星については、地球は別個に扱われます。 
2. すべての惑星のペア間の距離と、すべての惑星から地球までの距離を事前計算します。 多くの DP 遷移では同じ幾何学的距離が使用されるため、それらを一度計算すると、平方根を繰り返し評価する必要がなくなります。 
3. 次のコマンドを使用して DP テーブルを作成します。`2^n`マスクと`n`可能なエンドポイント。 少し`i`で`mask`惑星が正確に設定される`i`はすでに訪問されています。 エンドポイント ディメンションは、宇宙船が現在いる惑星を記録します。 
4.初期化`dp[1 << i][i]`地球から惑星までの直線距離で`i`。 これは、唯一訪問する惑星が存在する最短ルートを表します。`i`。 
5. 到達可能なものすべてを処理する`(mask, i)`州。 あらゆる惑星のために`j`そのビットが設定されていない`mask`からルートを延長します。`i`に`j`そして、より大きなマスクで状態を更新します。 遷移では、その正確なサブセットとエンドポイントの最短ルートが維持されます。 
6. すべてのマスクが処理されたら、考えられるすべての最終惑星を検討します。`i`。 値`dp[full][i]`すべての惑星を訪れて終わるアカウント`i`、からの距離を追加します。`i`back to Earthでクローズドツアーは終了。 これらの値の最小値が答えになります。 

なぜ機能するのか: 不変条件は次のとおりです`dp[mask][i]`地球から始まり、次のように表される惑星を正確に訪問するすべてのルート間の可能な最小距離を常に保存します。`mask`、で終わります`i`。 より大きなサブセットへのすべてのルートは、1 つの最終エッジが後に続く小さなサブセット ルートと見なすことができるため、考えられるすべてのツアーは DP 遷移のシーケンスによって表されます。 各状態は、その特定のサブセットとエンドポイントを持つ最も安価なルートのみを保持するため、より高価なルートを破棄しても最適なソリューションを削除することはできません。 地球への最終的な移行では、考えられるすべての最後の惑星が考慮されるため、最終的な最小値はまさに最短の完全なツアーとなります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    planets = [tuple(map(int, input().split())) for _ in range(n)]

    earth = (0, 0, 0)

    dist = [[0.0] * n for _ in range(n)]
    to_earth = [0.0] * n

    for i in range(n):
        x, y, z = planets[i]
        to_earth[i] = math.hypot(x, y, z)

        for j in range(i + 1, n):
            x2, y2, z2 = planets[j]
            dist[i][j] = math.hypot(
                x - x2,
                y - y2,
                z - z2
            )
            dist[j][i] = dist[i][j]

    size = 1 << n
    inf = float("inf")
    dp = [[inf] * n for _ in range(size)]

    for i in range(n):
        dp[1 << i][i] = to_earth[i]

    full = size - 1

    for mask in range(size):
        for i in range(n):
            cur = dp[mask][i]

            if cur == inf:
                continue

            remaining = full ^ mask

            while remaining:
                bit = remaining & -remaining
                j = bit.bit_length() - 1
                new_mask = mask | bit

                candidate = cur + dist[i][j]
                if candidate < dp[new_mask][j]:
                    dp[new_mask][j] = candidate

                remaining -= bit

    answer = inf

    for i in range(n):
        answer = min(answer, dp[full][i] + to_earth[i])

    print(answer)

if __name__ == "__main__":
    solve()
```距離マトリックスは、DP が開始される前に構築されます。`math.hypot`ユークリッド ノルムを直接計算し、すべてのペアの平方根式を手動で記述する必要がなくなります。 行列は対称なので、一度`dist[i][j]`が計算されると、同じ値が割り当てられます。`dist[j][i]`。 

初期化により、考えられるすべての最初の惑星に対して 1 つの状態が作成されます。 他の惑星はまだ訪れていないため、コストは正確に地球からその惑星までの距離です。 

メインループは、すべてのマスクとすべての可能なエンドポイントをスキャンします。`remaining`まだ訪れていない惑星が正確に含まれています。 最も低い設定ビットを抽出すると、次の惑星の候補が 1 つ得られ、そのビットを削除すると、未訪問の惑星をすべて考慮できるようになります。 

の`new_mask`式は惑星を追加するのと同じです`j`訪問先のサブセットに。 以来`bit`欠席することが保証されている`mask`、この操作はちょうど 1 ビットを変更します。 

Python 整数は任意精度であるのに対し、距離は浮動小数点値であるため、DP 自体には整数オーバーフローの問題はありません。 公式声明には座標の大きさの限界が示されていませんが、意図された解では通常の浮動小数点ユークリッド距離が使用され、答えは実数として判断されます。
