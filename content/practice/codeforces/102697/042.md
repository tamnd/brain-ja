 ## 解決策
 ## 問題の理解

 この問題では、単語の辞書といくつかの数字列が与えられます。 エンコードでは 6 文字のみが使用されます。`o`になる`0`、`i`になる`1`、`e`になる`3`、`a`になる`4`、`s`になる`5`、 そして`t`になる`7`。 1 文字おきに空白が含まれるため、結果として得られる数値シーケンスだけを見ると空白が消えてしまいます。 

例えば、`hasty`関連する文字が含まれています`a`、`s`、 そして`t`, となるので、`457`。 言葉`funtastuc`含まれています`u`、`n`、 そして`c`、消える、離れる`t`、`a`、`s`、`t`、 または`7457`。 タスクは、エンコードされた形式が要求された数値文字列と正確に一致する辞書の単語をすべて検索することです。 辞書はすでにアルファベット順にソートされているため、一致する単語は同じ順序で印刷する必要があります。 

公式声明では、1 秒の時間制限と 256 MB のメモリ制限が指定されていますが、辞書のサイズ、単語の長さ、クエリ数の数値上限は公開されていません。 この省略により、意図した複雑さが特に重要になります。 多くの辞書単語と多くのクエリが存在する可能性があるため、クエリごとに辞書全体をスキャンするのは安全ではありません。 各辞書の単語を 1 回処理し、その後のすべてのクエリを直接検索する必要があります。 

実装が静かに失敗する簡単なケースがいくつかあります。 まず、マップされた 6 文字以外の文字は、数字として扱わずに無視する必要があります。 入力用```
1
hasty
1
457
```出力は```
1
hasty
```単語のすべての文字にマッピングが必要なソリューションでは、誤って拒否されます。`hasty`のため`h`そして`y`。 

第 2 に、異なる単語が同じエンコードを持つ可能性があります。 例えば、```
3
a
ba
ca
1
4
```生成する```
3
a
ba
ca
```なぜなら、3 つの単語はすべて次のようになります。`4`。 エンコードされた文字列ごとに 1 つの単語だけを保持すると、有効な回答が失われます。 

第三に、マップされた文字の間に消える文字が発生する可能性があります。 のために```
2
taste
tasty
1
7457
```正しい出力は```
2
taste
tasty
```どちらの単語も次のようになります`7457`。 数値文字列を元の単語内の連続する文字と比較するソリューションは、マップされていない文字が消えることが許可されているため失敗します。 

最後に、クエリには一致する辞書単語がない場合があります。 のために```
2
a
hello
1
57
```正しい出力は単純に```
0
```一致する単語がないため、カウントの後に単語行はありません。 

## アプローチ

 直接的なアプローチは、すべてのクエリを個別に処理することです。 1 つのクエリについて、辞書のすべての単語をスキャンし、マップされていない文字を無視してその文字を数字に変換し、結果の文字列をクエリと比較します。 比較はエンコード ルールを正確にモデル化するため、これは正しいです。 

あると仮定します`D`辞書の単語、すべての単語には最大でも長さがあります`L`、そして、あります`T`クエリ。 最悪の場合、総当たり方式で検査される`D * L`すべてのクエリに文字を指定すると、`T * D * L`エンコーディングを構築するためだけの文字検査。 生成されたエンコーディングを比較すると、別のエンコーディングが追加される可能性があります`O(TDL)`最悪の場合は動作します。 すべてのクエリに対してこの作業を繰り返すことは、入力が大きくなった場合にこのアプローチが不適切になる部分です。 

ブルートフォース方式が機能するのは、各単語を要求された数値に対して個別にテストできるためです。 問題は、クエリ間で辞書が変更されないため、同じエンコーディングを再計算するのは無駄な作業になることです。 

重要な観察点は、すべての辞書単語には、エンコードされた数値文字列が 1 つだけ含まれていることです。 辞書を読み取るときにその文字列を 1 回計算し、ハッシュ テーブルのキーとして使用できます。 キーに関連付けられた値は、そのエンコーディングを持つ辞書の単語のリストです。 

たとえば、サンプル辞書を処理した後、キー`7457`店`funtastuc`、`tasty`、 そして`untasty`。 のクエリ`7457`この場合、8 つの単語すべてをチェックするのではなく、辞書を調べるだけで済みます。 

元の辞書はすでにアルファベット順にソートされているため、各単語をそのエンコードされたキーのリストに追加すると、必要な出力順序が自動的に保持されます。 前処理後のソートは必要ありません。 

結果として得られるアプローチは次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(TDL)`プラス比較 |`O(1)`追加、入力を除く | 大量の入力には遅すぎる |
 | 最適 |`O(S + Q + R)`予想される |`O(S + D + R)`| 承認済み |

 ここ`S`辞書内の文字の総数です。`Q`すべてのクエリ文字列の合計長であり、`R`出力された一致する単語の総数です。 期待される`O(1)`ハッシュ テーブル ルックアップは各クエリに適用されます。 

## アルゴリズムのチュートリアル

 1. 関連する 6 つの文字からその数字へのマッピングを作成します。`o -> 0`、`i -> 1`、`e -> 3`、`a -> 4`、`s -> 5`、 そして`t -> 7`。 他の文字は、エンコードされた形式で空白を表すため、無視されます。 
2. キーがエンコードされた数値文字列で、値が元の辞書単語のリストであるハッシュ テーブルを作成します。 これにより、同じ数字になるすべての単語がグループ化されます。 
3. 辞書の各単語を指定された順序で読みます。 すべての文字にアクセスし、その文字がマッピングに表示される場合にのみ数字を追加することで、エンコードされた形式を構築します。 次に、そのエンコードされた形式に属するリストに元の単語を追加します。 

辞書はすでにアルファベット順にソートされているため、入力順に単語を挿入すると、保存されているすべてのリストもアルファベット順にソートされます。 
4. 各クエリ番号文字列を読み取り、それをハッシュ テーブル キーとして直接使用します。 キーが存在する場合、その格納されたリストには、一致する辞書の単語が正確に含まれます。 存在しない場合、クエリに一致するものはありません。 
5. 選択したリスト内の単語の数を出力し、その後に単語そのものを出力します。 キーが存在しない場合は、印刷のみ`0`。 

### なぜ効果があるのか

 不変条件は、辞書の接頭辞を処理した後、処理されたすべての単語が、その単語に問題のエンコード規則を適用することによって得られた文字列とまったく同じ下に格納されることです。 マップされていない文字はそのキーには決して表示されませんが、マップされた文字はすべて、所定の数字とともに元の順序で表示されます。 したがって、辞書全体が処理された後、クエリ文字列の下に保存されるリストには、エンコードがそのクエリと等しいすべての辞書単語が含まれ、エンコードが異なる単語は含まれません。 単語はアルファベット辞書順に挿入されるため、各リストはすでに必要な出力順序になっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    d = int(input())

    mapping = {
        'o': '0',
        'i': '1',
        'e': '3',
        'a': '4',
        's': '5',
        't': '7',
    }

    encoded_words = {}

    for _ in range(d):
        word = input().strip()
        code = ''.join(mapping[c] for c in word if c in mapping)
        encoded_words.setdefault(code, []).append(word)

    t = int(input())
    out = []

    for _ in range(t):
        query = input().strip()
        matches = encoded_words.get(query, [])

        out.append(str(len(matches)))
        out.extend(matches)

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```の`mapping`Dictionary は、ステートメントからの 6 つの変換を正確に表します。 辞書の前処理中に、ジェネレーター式は各文字を 1 回スキャンします。 条件`c in mapping`空白になる文字を削除します。`mapping[c]`対応する数字を提供します。`setdefault(code, [])`初めてエンコーディングが見つかったときに新しいリストを作成し、その後の単語を同じリストに追加します。 これは、いくつかの異なる辞書単語が同一のエンコーディングを持つ可能性があるため必要です。 

辞書はアルファベット順に読み取られるため、リストに追加のコードは必要ありません。`sort()`。 後ですべてのグループを並べ替えると、不必要な作業が追加され、入力順序によって必要な順序がすでに提供されているという事実がわかりにくくなります。 

クエリごとに、`get(query, [])`エンコーディングが存在する場合は一致するリストを返し、そうでない場合は空のリストを返します。 出力は次のように蓄積されます。`out`最後に一度書き込まれるため、多くの個別の作業のオーバーヘッドが回避されます。`print`呼び出します。 

Python の整数はエンコードに関与しないため、オーバーフローの心配はありません。 数値シーケンスは意図的に文字列として保持され、そのようなクエリが存在する場合には先頭のゼロも保持されます。
