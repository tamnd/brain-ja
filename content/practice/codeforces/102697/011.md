 ## 解決策
 ## 問題の理解

 このタスクでは、トレイルが簡単、難しい、非常に難しい、エキスパート専用の 4 つの難易度カテゴリに分けられているスキー リゾートについて説明します。 入力により各カテゴリのトレイルの数が与えられ、目的は単純に合計でいくつのトレイルが存在するかを計算することです。 答えは、提供された 4 つのカウントの合計です。 

4 つの整数のみが読み取られるため、制約は小さくなります。 高度なデータ構造、検索、シミュレーションは必要ありません。 入力サイズが大きくなっても作業量が増加することはないため、定数時間のソリューションでも十分です。 主な要件は、入力形式を正確に処理し、すべてのカテゴリを 1 回だけ正確に合計することです。 

主なエッジケースは、すべてのカテゴリが答えに寄与しているということを忘れていることから生まれます。 いくつかのカテゴリを追加するだけのソリューションは、多くのランダム テストに合格する可能性がありますが、単純な境界ケースでは失敗する可能性があります。 

たとえば、次のようになります。```
Input:
0 0 0 1

Output:
1
```唯一のトレイルは専門家専用のカテゴリーにあります。 この値を無視すると、誤ってゼロが生成されます。 

別のケースは次のとおりです。```
Input:
5 0 0 0

Output:
5
```ここではどの道も歩きやすい道です。 すべてのカテゴリが非ゼロであると仮定するソリューションでも、ゼロ値を正しく処理する必要があります。 

## アプローチ

 強引なアイデアは、トレイルを列挙し、それらを 1 つずつ数えることです。 ただし、入力によって各カテゴリのトレイルの数がすでに与えられているため、個別のトレイル オブジェクトを構築すると不必要な作業が追加されます。 4 つの数値が大きい場合、そのようなアプローチではトレイルの総数に比例した数の演算が実行されますが、答えには 4 つの加算だけが必要です。 

重要な点は、カテゴリがすでに集約されていることです。 トレイル間には隠された関係はなく、順序付けやフィルタリングも必要ありません。 トレイルの総数は、4 つのカウントを加算することで直接取得されます。 個々の証跡をカウントすると最終的に正しい合計が得られるため、総当りアプローチは機能しますが、入力にすでに存在する情報は無視されます。 各値がすでに部分和であるという観察により、問題全体を定数時間に縮小することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(トレイルの総数) | お(1) | 不要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの難易度カテゴリのトレイルの数を表す 4 つの整数を読み取ります。 
2. すべての証跡は 1 つのカテゴリにのみ属するため、4 つの値を加算します。そのため、カテゴリの合計が証跡の総数となります。 
3. 結果の合計を出力します。 

機能する理由: このアルゴリズムは、すべての証跡が入力内で 1 回だけカウントされるという不変式に依存しています。 カテゴリは重複しないため、そのサイズを追加しても証跡が見逃されたり、証跡が複数回カウントされたりすることはありません。 出力される合計は、証跡の総数と等しくなければなりません。

```プログラムは 1 つの入力行を読み取り、4 つのカテゴリ数を保存します。 中間構造が必要ないため、加算は直接実行されます。 

Python では、インデックス作成、ループ、オーバーフローに関する境界の問題はありません。 重要な実装の詳細は、4 つの数値すべてが最終的な式に含まれている必要があるということです。 カテゴリが 1 つ欠けていることが、誤った答えを生み出す唯一の現実的な原因となります。

## テストケース```python
import sys
import io

def solve():
    a, b, c, d = map(int, input().split())
    print(a + b + c + d)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        out = io.StringIO()
        sys.stdout = out
        solve()
        return out.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

assert run("20 16 13 6\n") == "55\n", "sample 1"
assert run("0 0 0 1\n") == "1\n", "single expert trail"
assert run("5 0 0 0\n") == "5\n", "only easy trails"

## 特殊なケース

 3 つのカテゴリにトレイルが含まれていない場合でも、値についての仮定を行わずにすべてのカテゴリを追加するため、アルゴリズムは引き続き機能します。 のために：```
Input:
0 0 0 1
```4 つの値は次のように加算されます`0 + 0 + 0 + 1`、生産`1`。 

すべてのトレイルが 1 つのカテゴリに属する​​場合、同じロジックが適用されます。 のために：```
Input:
5 0 0 0
```結果は`5`3 つのゼロ カテゴリは合計を変更しないためです。 

整数の範囲が制限されている言語で不用意に実装するとオーバーフローする可能性があるため、大きな値にも注意が必要です。 Python の整数は、大きな値を格納するために自動的に拡張されるため、次のようになります。```
Input:
1000000000 1000000000 1000000000 1000000000
```正しく生成されるもの:```
4000000000
```このアルゴリズムは、すべてのケースを同じ不変条件によって処理します。各入力数値は合計の 1 つの素な部分であり、4 つの部分をすべて加算すると完全な答えが得られます。
