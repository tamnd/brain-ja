 ## 解決策
 ## 問題の理解

 この問題は、6 桁と 6 文字の間の固定置換コードを定義します。`0`を表します`o`、`1`を表します`i`、`3`を表します`e`、`4`を表します`a`、`5`を表します`s`、 そして`7`を表します`t`。 

各テスト ケースは、スペースで区切られた一連の数値文字列です。 すべての数値文字列は 1 つの単語を表し、その文字列内のすべての数字はコードを使用して個別に変換できます。 簡単なバージョンでは、元の単語にはコードで表される文字のみが含まれることが保証されるため、あいまいさはありません。 すべての数値文字列をデコードし、それらの間のスペースを保存するだけです。 

例えば、`74573`になる`taste`:`7 -> t`、`4 -> a`、`5 -> s`、`7 -> t`、 そして`3 -> e`。 

公式の制限は 1 秒の時間制限と 256 MB のメモリですが、この声明ではテスト ケースの数や各シーケンスの長さの数値制限は示されていません。 安全な解釈は、アルゴリズムは入力量において線形であるべきであるということです。 指定された数字を直接変換するのではなく、候補となる単語を探索するアプローチでは、数値文字列が大きくなるにつれてコストが急激に増加する可能性があります。 どの文字も複数回検査する必要がないため、すべての入力文字を直接スキャンするのが最適です。 問題のページでは、6 つのマッピング、入力形式、および 1 秒、256 MB の制限を確認します。 

不注意な実装が露呈する可能性のある小さなケースがいくつかあります。 単一の数字はすでに完全な単語です。 入力用```
1
0
```正しい出力は```
o
```すべての単語に少なくとも 2 桁の数字が含まれると想定する実装は、ここでは失敗します。 

単語には繰り返しの数字を含めることができます。 入力用```
1
55 555
```正しい出力は```
ss sss
```個別の数字のみを変換する不用意な実装や、重複する文字を誤って削除すると、間違った単語が生成されてしまいます。 

数字`0`文字にデコードされるため、これも重要です`o`。 入力用```
1
101
```正しい出力は```
ioi
```数値を文字列ではなく整数として扱うと、先頭のゼロを自動的に削除できます。 例えば、`010`デコードする必要があります`oio`、 ない`io`。 

最後に、スペースは単語を区切るため、出力ではスペースのままにする必要があります。 入力用```
1
50 50
```正しい出力は```
so so
```スペースを個別に処理せずに行全体を 1 文字ずつデコードすると、誤って 2 つの単語が連結されてしまう可能性があります。 

## アプローチ

 最も文字通りの総当り的なアプローチは、エンコードされた各数値を未知の単語として扱い、許可されている 6 文字のすべての単語を試してみることです。 長さのある数値`L`持っていただろう`6^L`考えられる言葉。 各候補単語をエンコードし、そのエンコードが指定された数値と一致するかどうかを確認できます。 これは正しいです。元の単語はコードで表される 6 文字のみで構成されている必要があるため、そのような単語をすべて列挙すると最終的に答えが得られます。 

問題は、この検索が急激に増加することです。 20 桁の数字が 1 つあれば、すでに`6^20 = 3,656,158,440,062,976`候補となる単語。 1 秒の制限では、小さな入力ラインでも不可能になります。 総当たりは、入力が実際に解決を要求するよりもはるかに難しい問題を解決します。 

重要な点は、マッピングが 1 対 1 であるということです。 入力可能なすべての数字には、対応する文字が 1 つだけあり、このステートメントは、元の単語に他の文字が出現しないことを保証します。 したがって、何も推測する必要はありません。 を読むと、`5`、対応する文字は次でなければなりません`s`; 私たちが何かを読むとき`7`、それはそうでなければなりません`t`。 すべてのキャラクターには正確に 1 つの答えがあります。 

したがって、最適なアルゴリズムは各入力行を左から右にスキャンします。 数字は 6 エントリのマッピングを使用して置換され、スペースは変更されずにコピーされます。 同様に、行を数値文字列に分割し、各文字列を個別にデコードし、デコードされた単語をスペースで結合することができます。 どちらの実装でも、入力文字ごとに一定の作業が必要になります。 

ブルートフォース手法は、考えられるすべての単語を考慮するため機能しますが、考えられる単語の数が指数関数的に増加するため失敗します。 すべてのエンコードされた文字には、可能性のある文字が 1 つだけ存在するという観察により、検索が完全に削除され、問題が直接置換に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 長さ L のワードの場合は O(6^L) | 候補者あたりの O(L) | 遅すぎる |
 | 最適 | O(N) | 出力の場合は O(N) | 承認済み |

 ここ`N`入力シーケンス内の文字の合計数です。 ブルート フォースの指数関数的限界は最長の個々のエンコードされた単語に適用されますが、最適な方法では完全な入力が線形に処理されます。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 次の各行は 1 つのエンコードされた文を表すため、1 つの数字だけを読み取るのではなく、完全な行を保存する必要があります。 
2. 6 つの数字から文字へのマッピングを辞書に保存します。`0 -> o`、`1 -> i`、`3 -> e`、`4 -> a`、`5 -> s`、 そして`7 -> t`。 辞書は、各翻訳を一定時間の検索にします。 
3. 各テスト ケースについて、行全体を読み取り、末尾の改行のみを削除します。 内部スペースは単語を区切るために必要です。 
4. 行内のすべての文字をスキャンします。 スペースの場合は、スペースを直接追加します。 それ以外の場合は、マッピング内で対応する文字を検索し、その文字を追加します。 
5. 結果のデコードされた行を印刷します。 すべての入力文字には 1 つの翻訳があるため、出力は一意に決定されます。 

### なぜ効果があるのか

 不変条件は、入力行のプレフィックスを処理した後、構築された出力がそのプレフィックスのデコードされたバージョンとまったく同じであるということです。 スペースは変更されずにコピーされるため、単語の境界は保持されます。 マッピングでは、許可されているすべての数字に対して、エンコード ルールで指定された文字が正確に与えられるため、デコードされたすべての文字が正確になります。 この不変条件を一度に 1 文字ずつ拡張すると、最後の文字以降の完全な出力行が、デコードされた単語の必要なシーケンスになることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    mapping = {
        '0': 'o',
        '1': 'i',
        '3': 'e',
        '4': 'a',
        '5': 's',
        '7': 't',
    }

    t = int(input())

    for _ in range(t):
        line = input().rstrip('\n')
        decoded = []

        for ch in line:
            if ch == ' ':
                decoded.append(' ')
            else:
                decoded.append(mapping[ch])

        print(''.join(decoded))

if __name__ == "__main__":
    solve()
```の`mapping`Dictionary はコードを直接表すため、6 桁のいずれにも算術変換や特殊なケースはありません。 

プログラムはテスト ケース全体を次のように読み取ります。`input()`個々のトークンを繰り返し読み取るのではなく、 これにより、単語間のスペースが保持されます。`rstrip('\n')`意味のあるスペースはすべて残したまま、行末を削除します。 

次に、ループはアルゴリズムで説明されている変換を正確に適用します。 スペースはコピーされ、数字は辞書を介して変換されます。 入力では、スペース以外のすべての文字が許可された 6 桁の数字に属することが保証されるため、フォールバック ケースは必要ありません。 

出力はリストにまとめられ、一度結合されます。 これにより、より大きな文字列を繰り返し構築することがなくなります。`+=`これにより、一部の文字列構築パターンで不必要なコピーが発生する可能性があります。 

Python integers are not involved at all. エンコードされた値を文字列として扱うことも必要です。`0`はエンコードされた単語の一部であり、消えてはなりません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | すべての入力文字は 1 回だけ検査されます。 |

 ここ`N`エンコードされたテスト ケース内の文字の合計数です。 このアルゴリズムは、各文字に対して定数時間の辞書検索またはスペース コピーのみを実行するため、実際の入力サイズに応じて線形にスケールされます。 エンコードされた単語に対する検索、再帰、またはネストされたループがないため、1 秒の時間制限と 256 MB のメモリ制限はこのアプローチと快適に互換性があります。 

## テストケース

 公式声明では、4 つのテスト ケースを含む 1 つのサンプルが提供されています。 この問題では文字数の最大数値が指定されていないため、以下のストレス テストでは、存在しない正式な最大値を主張するのではなく、大きな入力を使用します。```python
import sys
import io

def solve():
    mapping = {
        '0': 'o',
        '1': 'i',
        '3': 'e',
        '4': 'a',
        '5': 's',
        '7': 't',
    }

    t = int(input())

    for _ in range(t):
        line = input().rstrip('\n')
        print(''.join(
            mapping[ch] if ch != ' ' else ' '
            for ch in line
        ))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()
        try:
            solve()
            return sys.stdout.getvalue()
        finally:
            sys.stdout = old_stdout
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
sample = """4
50 50
45 15
1 473 4 74573
17 15 70 517
"""

assert run(sample) == """so so
as is
i ate a taste
it is to sit
""", "provided sample"

# Minimum-size input
assert run("1\n0\n") == "o\n", "single digit"

# All digits and repeated values
assert run("1\n013457\n") == "oieast\n", "all six mappings"

# Leading zero and word boundaries
assert run("1\n010 55 707\n") == "oio ss tot\n", "leading zero and spaces"

# All equal values
assert run("1\n777 0000 11111\n") == "ttt oooo iiiii\n", "repeated digits"

# Large stress-sized input
large_word = "013457" * 10000
expected_large = "oieast" * 10000 + "\n"
assert run("1\n" + large_word + "\n") == expected_large, "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 0`|`o`| 最小サイズの入力と単一文字のデコード |
 |`1 / 013457`|`oieast`| すべてのマッピングは 1 回だけ使用され、先頭に置かれます。`0`保存されます |
 |`1 / 010 55 707`|`oio ss tot`| 先頭のゼロと単語の境界 |
 |`1 / 777 0000 11111`|`ttt oooo iiiii`| 繰り返される文字とすべて等しい値 |
 | 60,000 文字のエンコードされた単語 1 つ | 対応する 60,000 文字のデコードされた単語 | 大きな入力での線形時間動作 |

 ヘルパーは標準入力をメモリ内ストリームに置き換え、標準出力をキャプチャして、同じことを可能にします。`solve()`直接テストされる提出物によって使用される関数。 大規模なテストは、有効な数値の繰り返しから意図的に構築されているため、パフォーマンスと、特定の値に対する偶発的な特別な処理がないかどうかの両方がチェックされます。
