 ## 解決策
 ## 問題の理解

 自転車旅行中に訪れた地点の標高が、訪れた順に与えられます。 連続した標高が個々のライディング セグメントを形成します。 丘は、すべてのセグメントが厳密に上向きに伸びる最大の連続ストレッチです。 その垂直方向の上昇は、単にその区間の終わりの標高から始まりの標高を引いたものです。 

課題は、そのような最大の垂直上昇を見つけることです。 下り坂セグメントまたは平坦なセグメントは現在の上り坂区間を壊すため、次に増加するセグメントが新しい丘の候補を開始します。 このステートメントは、厳密に上り坂のセグメントが少なくとも 1 つ存在することを保証します。 

公式問題ページには上限が明記されていません。`n`または標高値の場合。 1 秒の時間制限と 256 MB のメモリ制限が与えられます。 必要な計算は標高を 1 回通過するだけで実行できるため、`O(n)`アルゴリズムは自然なターゲットであり、たとえ`n`とても大きいです。 二次アルゴリズムはすぐに問題が発生します。`n`通常の競技プログラミングの規模に達する`10^5`、ここで大まかに`5 * 10^9`ペアを考慮する必要があります。 

実装が微妙に間違っている可能性があるいくつかの特殊なケースがあります。 平坦なセグメントは丘を終了する必要があります。 例えば、```
8
100 200 300 300 400 500 600 700
```答えがあります`400`、 ない`600`。 からの最初の立ち上がり`100`に`300`一つの丘、等しい`300`価値観がそれを打ち破り、2番目の丘がそこから立ち上がります。`300`に`700`。 減少しないシーケンスを上り坂として扱う不注意な実装では、2 つの部分が誤って結合され、返されます。`600`。 こちらも3回目の公式サンプルとなります。 

下り坂セグメントも現在の丘を終了します。 例えば、```
7
600 650 700 690 740 520 600
```答えがあります`100`。 最初の丘がそこから立ち上がります`600`に`700`、与える`100`、 その間`690`に`740`与える`50`そして`520`に`600`与える`80`。 下り坂ステップの後に累積し続ける実装では、関連のない登りが誤って結合される可能性があります。 

丘は最終標高で正確に終了する可能性があるため、たとえ後続の下り坂や平坦なセグメントがない場合でも、最後の増加する走行をチェックする必要があります。 例えば、```
5
100 150 120 300 500
```答えがあります`380`、 から`120`に`500`。 ブレークに遭遇したときにのみ答えを更新する実装では、最後の丘を見逃してリターンする可能性があります。`50`。 

このステートメントは正の上り坂セクションを保証するため、最小の有効な入力には少なくとも 2 つのポイントが含まれている必要があります。 例えば、```
2
10 20
```答えがあります`10`。 利用可能な 1 つのセグメント自体が完全な丘です。 

## アプローチ

 直接的な総当たりの解決策では、考えられるすべての開始点が考慮され、標高が増加し続ける間に丘が拡張されます。 次の標高が厳密に大きくない場合、その候補の丘は停止します。 有効な上り坂セクションの標高は最初と最後の標高によって完全に決定されるため、このアプローチは正しいです。考えられるすべての丘が検査され、その標高が現在の最大値と比較されます。 

問題は、これらの候補者の多くが重複していることです。 厳密に増加する長さの配列について`n`、最初の点から開始すると、おおよその原因が発生します`n - 1`拡張子、2 番目の原因から開始`n - 2`、 等々。 拡張子の総数は、`(n - 1) + (n - 2) + ... + 1 = n(n - 1)/2`。 

したがって、最悪のケースは、`O(n^2)`。 のために`n = 100000`、これについてです`4,999,950,000`1 秒のソリューションで処理できる範囲をはるかに超えています。 

有益な観察は、上り坂では中間の増加をすべて覚えておく必要はないということです。 現在の丘が標高から始まったと仮定します`start`、そして私たちは現在標高にいます`h`。 次の標高が大きい限り、シーケンス全体は 1 つの有効な丘のままであり、その上昇は単純に`h - start`。 次の値が大きくなくなったら、丘は終了します。 その後、その内部ポイントをすべて破棄し、新しい標高で次の候補を開始できます。 

これにより、問題は 1 回のスキャンに変わります。 現在厳密に増加しているランの開始標高を維持し、それぞれの新しい標高を以前の標高と比較します。 新しい値が大きい場合、現在の丘の立ち上がりは次のようになります。`current - start`。 それが大きくない場合、現在の実行は終了し、新しいポイントが次の可能な丘の開始点になります。 

ブルート フォースは、増加する実行をすべて明示的に調査するため機能しますが、同じプレフィックスを繰り返し調べるため失敗します。 増加するランは開始標高と現在の終点によってのみ表現できるという観察により、隣接する各ペアを 1 回だけ処理することができます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(1) 補助 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 標高ポイントの数と標高配列を読み取ります。 必要なのは、以前の標高、現在の上り坂の開始標高、およびこれまでに見つかった最高の標高だけです。 
2.セット`start`最初の標高まで、そして`prev`最初の標高へ。 初めは、現在の丘にはセグメントが含まれていないため、その立ち上がりはゼロです。 
3. 残りの立面図を左から右にスキャンします。 それぞれについて`cur`、と比較してください`prev`。 
4. もし`cur > prev`、乗り心地は厳密に上り坂が続きました。 同じ状態を保つ`start`、それ以降、増加するセグメントごとに`start`同じ丘に属しています。 現在の上昇率は、`cur - start`, したがって、この値が大きい場合は最大値を更新します。 
5. もし`cur <= prev`、現在の坂は終了しました。 定義ではすべてのセグメントが厳密に上り坂であることが求められるため、平等は下り坂セグメントと同様に休憩としてカウントされます。 セット`start = cur`この時点から新しい丘が始まるように。 
6.セット`prev = cur`そしてスキャンを続けます。 最大値の最終値が答えになります。 

### なぜ効果があるのか

 不変条件は、新しい標高を処理する直前に、`start`は、処理された配列の現在の最大値の厳密に増加する接尾辞の最初の標高です。 次の標高がより大きい場合`prev`、その接尾辞は厳密に増加し続けるため、その増加は正確に`cur - start`。 次の標高がそれより大きくない場合、有効な上り坂セクションはその境界を越えることができないため、現在の接尾辞は終了する必要があり、新しい点がそれに続く丘の唯一の可能な開始点になります。 すべての有効な丘は厳密に増加する 1 つの最大の実行であるため、すべての候補が評価され、最大の上昇が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    start = a[0]
    prev = a[0]
    best = 0

    for cur in a[1:]:
        if cur > prev:
            best = max(best, cur - start)
        else:
            start = cur

        prev = cur

    print(best)

if __name__ == "__main__":
    solve()
```最初の 2 つの変数、`start`そして`prev`、現在の丘を記述するために必要な 2 つの端点を表します。`start`すべての新しいポイントは依然として同じ丘に属しているため、標高が厳密に増加している間は変化しません。 

厳密な比較`cur > prev`が中心的な詳細です。 使用する`cur >= prev`平らなセグメントが丘の内側に残ることを誤って許可してしまいます。 公式の 3 番目のサンプルは、この間違いを検出するのに特に役立ちます。 

休憩が発生すると、`start`割り当てられています`cur`、 それよりも`prev`。 これにより、次のセグメントが現在の点から始まる丘を形成できるようになります。 たとえば、`100 150 120 300`、新しい丘はから始まります`120`ではありません`150`。 

増加するセグメントが見つかると、答えはすぐに更新されます。 これは、配列の終わりに達する丘を処理します。この丘には、リセットをトリガーする後続の値がありません。 特別な後処理は必要ありません。 

Python の整数には任意の精度があるため、標高差によって整数がオーバーフローする危険はありません。
