 ## 解決策
 ## 問題の理解

 2 つのスペースラボは太陽系の惑星にあります。 惑星には、太陽からの距離によって固定された順序があります。`Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus, Neptune`。 

入力により、1 行目にあなたのスペースラブを含む惑星が表示され、2 行目にライバルのスペースラブを含む惑星が表示されます。 タスクは単に、この順序付けされたシーケンス内のそれらの位置を比較することです。 あなたの惑星が早く出現する場合は、印刷してください`CLOSER`。 後で表示される場合は印刷してください`FARTHER AWAY`。 両方の名前が等しい場合、出力します`THE SAME`。 

考えられる惑星名は 8 つだけで、入力には常に有効な太陽系惑星が含まれます。 実行時間の制限は 1 秒、メモリの制限は 256 MB です。 入力自体には 8 つの値の固定セットからの 2 つの短い文字列しか含まれていないため、すべての惑星をリニア スキャンしても、実行される比較はせいぜい数回です。 ここでは、時間制限の問題による重大なリスクはありません。 主な目標は、惑星の口頭による順序を、プログラムが直接比較できるものに変えることです。 

最初のエッジケースは、両方のスペースラブが同じ惑星上にある場合です。 例えば：```
Neptune
Neptune
```正しい出力は次のとおりです。```
THE SAME
```最初の惑星が 2 番目の惑星の前に来るか後ろに来るかをチェックするだけの不注意な実装では、必要な等価結果が得られずに失敗する可能性があります。 

2 番目のエッジ ケースは、最初の惑星が可能な限り最も遠い惑星で、2 番目の惑星が最も近い惑星である場合です。```
Neptune
Mercury
```正しい出力は次のとおりです。```
FARTHER AWAY
```誤って惑星の順序を逆に解釈して実装すると、反対の答えが生成されます。 

3 番目の有用な境界ケースは、2 つの隣接する惑星です。```
Earth
Mars
```正しい出力は次のとおりです。```
CLOSER
```これにより、インデックスベースの表現におけるオフバイワンの間違いが捕捉されます。 ゼロから数えた場合、地球のインデックスは 2、火星のインデックスは 3 であるため、地球はより近いものとして分類される必要があります。 

## アプローチ

 最も直接的なアプローチは、8 つの惑星を太陽からの順序で保存し、その配列を検索して各入力惑星の位置を見つけることです。 最初の惑星がその位置に見つかった場合`a`そして2番目の位置`b`、比較する`a`そして`b`すぐに答えを出します。 これは事実上、一定サイズのコレクションに対する総当り攻撃です。 最悪の場合、各惑星を見つけるには 8 つのエントリすべてをチェックする必要があるため、惑星名の比較は最大 16 個になります。 

リストのサイズは 8 に固定されているため、このアプローチはすでに十分に高速です。 この特定の問題に関してスキャンが問題となる入力サイズはありません。 それでも、惑星の名前から必要な情報は順序付けにおける位置だけであることを観察することで、根底にある考え方をより明確にすることができます。 辞書は各名前をその位置に直接マッピングするため、各検索には予期した値がかかります。`O(1)`時間。 

探索空間には惑星が 8 つしか含まれていないため、総当たりスキャンは機能しますが、惑星の順序が固定されているという観察により、すべての惑星を数値ランクで表すことができます。 両方の名前がランクに変換されると、残りの問題は通常の整数比較になります。

 | 最適 | O(1) が期待されます | O(8)、実質的には O(1) | 承認済み |

 辞書版は、中心的な考え方を直接表現しているため、編集ソリューションでは推奨されます。つまり、各惑星には固定のランクがあり、答えはそれらのランクの比較によってのみ決まります。 

## アルゴリズムのチュートリアル

 1. 太陽から順に、すべての惑星名からその位置へのマッピングを作成します。 水星はランク 0、金星はランク 1、海王星はランク 7 になります。正確な数値は重要ではなく、相対的な順序のみが重要です。 
2. 入力から 2 つの惑星の名前を読み取ります。 最初の名前は私たちのスペースラボに属し、2 番目の名前はライバルのスペースラボに属します。 
3. マッピングで両方の名前を検索します。 これにより、惑星名に関する元の問題が 2 つの整数間の比較に変換されます。 
4. 2 つのランクを比較します。 私たちのランクが小さい場合、私たちの惑星は太陽に近くなります。`CLOSER`。 私たちのランクが大きい場合は印刷してください`FARTHER AWAY`。 ランクが等しい場合、両方のスペースラボは同じ惑星上にあるため、次のように出力します。`THE SAME`。 

### なぜ効果があるのか

 マッピングは、問題で指定された順序を正確に保持します。ランクが小さいほど、惑星が太陽に近いことを意味します。 したがって、両方の惑星名をランクに変換すると、考えられるすべてのペアが 3 つのケースのいずれかに正確に当てはまります。 私たちのランクはライバルのランクより小さいことも、大きいことも、同じこともでき、これら 3 つのケースは、必要な 3 つの出力文字列に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    order = {
        "Mercury": 0,
        "Venus": 1,
        "Earth": 2,
        "Mars": 3,
        "Jupiter": 4,
        "Saturn": 5,
        "Uranus": 6,
        "Neptune": 7,
    }

    mine = input().strip()
    rival = input().strip()

    a = order[mine]
    b = order[rival]

    if a < b:
        print("CLOSER")
    elif a > b:
        print("FARTHER AWAY")
    else:
        print("THE SAME")

if __name__ == "__main__":
    solve()
```の`order`Dictionary は、アルゴリズム ウォークスルー ステップ 1 のコア データ構造です。値は惑星が太陽から遠ざかるにつれて増加するため、それらを比較することは、問題内の物理的な位置を比較することと同じ意味になります。 

二人の呼びかけは、`input()`2 つの惑星の名前を正確に読んでください。 使用する`.strip()`惑星名自体は変更せずに改行を削除します。 

3 つの分岐は、2 つのランク間の可能な 3 つの関係に直接対応します。 惑星は両方のスペースラボで同じである可能性があるため、等価分岐が必要です。 

ランクの範囲は 0 ～ 7 のみであるため、整数オーバーフローの懸念はありません。また、ステートメントにより両方の名前が有効な惑星であることが保証されるため、辞書検索の際に必要な境界チェックもありません。

 ## 特殊なケース

 平等な惑星については、次のことを考慮してください。```
Neptune
Neptune
```どちらの辞書検索でもランク 7 が生成されます。`a < b`そして`a > b`両方とも false の場合、アルゴリズムは等価分岐に到達し、出力します。`THE SAME`。 これにより、平等を近いか遠いかのどちらかとして扱うというよくある間違いを防ぐことができます。 

極端な順序については、次のことを考慮してください。```
Neptune
Mercury
```ランクは 7 と 0 です。最初のランクの方が大きいため、アルゴリズムは次のように出力します。`FARTHER AWAY`。 ランク表現は両方の境界を自然に処理するため、最初または最後の惑星に対する特別な処理は必要ありません。 

隣接する惑星については、次のことを考慮してください。```
Earth
Mars
```地球は 2 にマップされ、火星は 3 にマップされます。2 は 3 より小さいため、結果は次のようになります。`CLOSER`。 入力を反転すると、`Mars`そして`Earth`ランク 3 と 2 が生成されるため、`FARTHER AWAY`。 これは、実装が名前のアルファベット順やテキストの外観に依存するのではなく、実際の順序を比較していることを確認します。
