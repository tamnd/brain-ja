 ## 問題の理解

 この課題は、温度に依存する音速を直接適用することです。 すべてのテスト ケースについて、気温 (摂氏) と、スピーカーから群衆の最も遠い端までの距離 (キロメートル) が与えられます。 音がその距離を伝わるのに何秒必要かを計算する必要があります。 

音速は

 [
 V = 331.3 + 0.606\vartheta
 】

 ここで、(\vartheta) は摂氏温度、(V) はメートル/秒で測定されます。 入力距離はキロメートル単位であるため、最初にメートルに変換する必要があります。 移動時間は単純に距離を速度で割ったものになります。 必要な答えは小数点以下 2 桁まで出力されます。 公式声明では、制限時間は 1 秒、メモリは 256 MB とされています。 問題ページのテスト ケース数の有効な数値上限は公開されていませんが、アルゴリズムはケースごとに一定数の算術演算のみを使用するため、実行時間はケース数に比例します。 (O(n)) よりも複雑なアルゴリズムを使用する理由はありません。 

最初のエッジケースは負の温度です。 例えば、```
1
-1 1.2
```速度は (331.3 - 0.606 = 330.694) m/s になります。 距離は1200メートルなので、答えはおよそ`3.63`。 温度が正でなければならないと仮定するソリューションでは、有効な入力が拒否されたり、間違った速度が計算されたりする可能性があります。 

2 番目のエッジ ケースは分数距離です。 例えば、```
1
7 3.6
```距離は3.6メートルではなく3600メートルです。 音速は (335.542) m/s で、移動時間は約`10.73`秒。 キロメートルからメートルへの変換を忘れると、1000 分の 1 小さい答えが生成されます。 

3 番目のエッジ ケースは、丸めが必要な結果です。 例えば、```
1
24 1.1
```速度は (345.844) m/s、移動時間は約`3.18068`秒なので、必要な出力は次のようになります。`3.18`。 生の浮動小数点値を出力するプログラムは、必要な出力形式に従っていません。 

4 番目のエッジ ケースは、入力範囲で許可されている場合、距離がゼロです。 例えば、```
1
20 0
```旅行はまったく必要ないので、答えは次のとおりです。`0.00`。 分子がゼロであるため、数式はこれを自然に処理します。 

## アプローチ

 文字通りの強引なソリューションでは、群衆に向かって伝わる音をシミュレートし、目標の距離に到達するまでその位置を繰り返し前進させることができます。 距離が (D) キロメートル、速度が 1 秒あたり (V) メートルの場合、このようなシミュレーションでは、1 秒進む場合におよそ (1000D/V) 回の反復が必要になります。必要な精度を得るためにより小さな時間増分を使用する場合は、さらに多くの反復が必要になります。 正確な最悪ケースの数は最大距離と温度によって異なり、公開されている問題ページにはそれらの数値限界が示されていません。 さらに重要なのは、シミュレーションではテスト ケースの速度が一定であるという中心的な事実が無視されるため、反復ごとに 1 つの部門で置き換えることができる作業が繰り返されることです。 

直接的な数学的アプローチは、より簡単かつ高速です。 総当たりシミュレーションが機能するのは、各時間間隔の後に音がどれだけ遠くまで伝わったかがわかるからです。 テスト ケース中に速度は変化しないため、合計移動時間は距離を速度で割った値となります。 物理モデルがすでに一定の速度を与えているという観察により、シミュレーション全体を数回の算術演算に減らすことができます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 次の各行は、1 つの独立した温度と距離のペアを記述します。 
2. 温度 (\vartheta) と距離 (d) をキロメートル単位で読み取ります。 温度は負の値になる場合があるため、通常の符号付き数値として扱う必要があります。 
3. 次を使用して音速を計算します。 

[
 V = 331.3 + 0.606\vartheta。 
】

 この問題で必要な物理式はこれだけです。 

1. 距離を 1000 倍して、キロメートルからメートルに変換します。速度はメートル/秒で測定されるため、これが必要です。 
2.次の方法で移動時間を計算します。 

[
 t = \frac{1000d}{V}。 
】

 単位が正しくキャンセルされるようになりました。メートルをメートル/秒で割ると秒が得られます。 

1. (t) を小数点以下 2 桁で出力します。 Python の浮動小数点形式は、通常のコンテスト入力に必要な丸めを実行します。 

### なぜ効果があるのか

 すべてのテスト ケースで、温度から計算された速度は、音が伝わる間一定です。 一定速度では、基本的な関係は (d = Vt) であるため、整理すると (t=d/V) となります。 このアルゴリズムは、入力距離を速度公式で使用されるのと同じ単位に変換した後、まさにこの関係を使用します。 計算されたすべての値はそのテスト ケースの物理的な移動時間を表すため、小数点以下 2 桁にフォーマットすると必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = []

    for _ in range(n):
        temperature, distance_km = input().split()
        temperature = int(temperature)
        distance_km = float(distance_km)

        speed = 331.3 + 0.606 * temperature
        distance_m = distance_km * 1000.0
        time = distance_m / speed

        ans.append(f"{time:.2f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```ステートメントでは整数の温度が指定されているため、最初の変換では温度が整数として読み取られます。 次のような例があるため、距離は浮動小数点値として読み取られます。`3.6`そして`1.1`有効です。 

速度の計算は、指定された式に直接に従います。 定数を浮動小数点値として維持すると、偶発的な整数演算が回避されます。 

の乗算`1000.0`キロメートルからメートルへの単位変換です。 速度はメートル/秒で表現されるため、これは除算の前に発生する必要があります。 

表現`f"{time:.2f}"`どちらも値を小数点以下 2 桁に四捨五入し、末尾のゼロが出力されることを保証します。 例えば、`3.1`になる`3.10`、これは出力形式で必要です。 

答えは蓄積され、最後に一度書かれます。 これにより、繰り返し呼び出しを避けることができます`print`多数のテスト ケースに対応し、I/O オーバーヘッドを小さく保ちます。
