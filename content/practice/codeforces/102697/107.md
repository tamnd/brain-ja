 ## 問題の理解

 (N \times N) 個のチェス盤があり、2 人のクイーンが互いに攻撃できないように、正確に (N) 個のクイーンを配置したいと考えています。 クイーンは水平、垂直、斜めに攻撃するため、各ペアのクイーンは異なる行、異なる列、異なる対角線を占有する必要があります。 出力は、これらの条件を満たす個別の配置の合計数です。 入力には (N) のみが含まれます。 

重要な制約は (N \le 9) です。 これは、積極的なプルーニングによる徹底的な検索には十分小さいですが、すべてのボード構成を盲目的に試すのはコストがかかりすぎるほど大きいです。 すべての行でクイーンの列を個別に選択すると、(N^N) 通りの配置が可能になります。 (N=9) では、(9^9 = 387{,}420{,}489) 個の候補になります。 すべての完全な候補ですべてのクイーンのペアをチェックするには、最大 (\binom{9}{2}=36) のペア チェックが必要となり、およそ (139 億 5) 億のペア チェックが必要になります。 5 秒のソリューションでは、これほどの作業量を賄うことはできません。

## アプローチ

 最も直接的な強引な方法は、ボードを行ごとに処理することです。 すべての行について、すべて (N) 列を試し、すべて (N) 行にクイーンができるまで続行し、結果のボードが有効かどうかを確認します。 これは正しいです。考えられるすべての配置では、行ごとに列の選択肢が 1 つだけあるため、検索では最終的に考えられるすべてのボードが考慮されます。 

問題は候補者の数だ。 (N) 行のそれぞれに (N) 個の選択肢があるため、検索には (N^N) 個の完全な配置が含まれます。 最大 (N=9) では、387,420,489 の配置になります。 それらの多くは即座に無効になりますが、競合をチェックする前にボードが完成するまで待機するブルートフォース実装は、依然としてそれらすべての代償を払うことになります。 

2 つの女王が行を共有できないことを観察することで、検索をすぐに改善できます。 任意のボード位置を考慮するのではなく、各行に 1 つのクイーンを正確に配置します。 新しい女王が以前の女王を攻撃するとすぐに、部分的な配置を拒否することもできます。 これにより、検索がすべて (N^N) 個の行と列の割り当てから、部分的な配置に対するプルーニングされた検索に変更されます。 

もう一つ有益な観察があります。 行を上から下に処理したら、次のクイーンがどこに移動できるかを決定するために必要な情報は、どの列と対角線がすでに占有されているかだけです。 完全なボードは必要ありません。 (N) は最大 9 であるため、これらのセットはそれぞれ整数ビットマスク内に自然に収まります。 

各再帰状態について、1 ビットが各列を表します。 セットビットイン`cols`は、その列にすでにクイーンが含まれていることを意味します。 他の 2 つのマスクは、次の行の上のクイーンによって現在攻撃されている対角線を表します。 ビット演算を使用して、すべての有効な列を一度に計算できます。 

仮定する`full`1 に設定された最下位 (N) ビットが含まれます。```
available = full & ~(cols | diag1 | diag2)
```次のクイーンを配置できる列が正確に含まれています。 1 つのセット ビットを選択すると、1 つの法的な選択肢が与えられます。 クイーンを配置すると、次の行が 1 行下になるため、斜めのマスクが移動します。 

ブルート フォースは、考えられるすべての配置を検査するため機能しますが、すでに制約に違反している膨大な数の配置を調査するため失敗します。 無効な部分配置はすべて即座に破棄できるという観察により、実行可能なプレフィックスのみを検索できます。 次に、ビットマスクにより、実行可能な列の検索と更新が一定時間行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^N \cdot N^2)) | (O(N)) | 遅すぎる |
 | ビットマスクを使用したバックトラック | (O(N!)) 最悪の場合 | (O(N)) | 承認済み |

 (O(N!)) 境界は、枝刈り検索の保守的な上限です。これは、行が固定されると列を再利用できなくなり、枝刈りされていない順列に沿って最大で (N, N-1, \ldots, 1) 列の選択肢が残るためです。 斜め枝刈りにより、実際の検索は大幅に小さくなります。 

## アルゴリズムのチュートリアル

 1. 読み取り(N)と作成`full = (1 << N) - 1`。 最下位 (N) ビットは 1 になり、すべてのボード列を表します。 
2. 空の列と対角マスクを使用して、行 0 から再帰的検索を開始します。 行 (r) では、再帰状態は行 (0) から (r-1) までのクイーンの有効な配置を表します。 
3. 計算する`available = full & ~(cols | diag1 | diag2)`。 このマスク内のすべてのセット ビットは、占有されておらず、前のクイーンによって斜めに攻撃されていない列を表します。 
4. もし`available`すべての行が埋まる前に 0 の場合は、この分岐を停止します。 次期女王には法的な立場がないため、継続しても解決策は生まれません。 
5. 使用可能なビットを 1 つ取得します`bit = available & -available`。 これにより、最下位の正当な列が分離されます。 すべての法的分岐は最終的にはカウントされる必要があり、一度に 1 ビットずつ選択すると重複することなく単に列挙されるため、順序は無関係です。 
6. そのビットを次から削除します。`available`、次に再帰的にその列にクイーンを配置します。 列マスクは次のようになります。`cols | bit`。 
7. 斜め攻撃を次の列に移動します。 最初の対角マスクは左にシフトされ、2 番目の対角マスクは右にシフトされます。```
next_diag1 = ((diag1 | bit) << 1) & full
next_diag2 = (diag2 | bit) >> 1
```1 行下に移動するたびに、対角線が 1 列水平に移動するため、シフトが必要です。 

1. いつ`row == N`、各行にはちょうど 1 つのクイーンが含まれており、3 つのマスクすべてで 2 つのクイーンが競合しないことが保証されています。 答えを 1 つ増やします。 

### なぜ効果があるのか

 不変条件は、すべての再帰呼び出しが、2 つのクイーンが互いに攻撃することなく、以前に処理されたすべての行内のクイーンの配置を表すことです。`cols`は占有されているすべての列を記録し、2 つの対角マスクは次の行で斜めに攻撃されたすべての列を記録します。 その結果、`available`次の女王の法的地位が正確に含まれています。 有効な完全な配置はすべて、行ごとにこれらの正当な位置の 1 つを選択するため、削除されることはありません。 すべての無効な配置には 2 つのクイーンが列または対角線を共有しており、競合する位置はブロックから削除されます。`available`選べる前に。 したがって、すべての有効なボードは 1 回だけカウントされ、無効なボードはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    full = (1 << n) - 1
    answer = 0

    def backtrack(row, cols, diag1, diag2):
        nonlocal answer

        if row == n:
            answer += 1
            return

        available = full & ~(cols | diag1 | diag2)

        while available:
            bit = available & -available
            available -= bit

            backtrack(
                row + 1,
                cols | bit,
                ((diag1 | bit) << 1) & full,
                (diag2 | bit) >> 1
            )

    backtrack(0, 0, 0, 0)
    print(answer)

if __name__ == "__main__":
    solve()
```の`full`マスクには、ボードに属する列が正確に含まれています。 (N=4) の場合、次のようになります。`1111`バイナリで。 (N=8) の場合、次のようになります。`11111111`。 によるマスキング`full`シフト後`diag1`右端を越えて移動したビットが後の行に影響を与えるのを防ぎます。 

再帰関数は、現在の行と 3 つのマスクを受け取ります。 占有される列と対角線がわかればボード自体は不要となるため、個別のボード配列はありません。 

表現`available & -available`1 つのセットビットを分離します。 これにより、ループは一度に 1 つの有効な列を処理できるようになります。 そのビットを減算すると、現在の再帰状態に属するマスクを変更することなく、残りの候補からそのビットが削除されます。 

再帰呼び出しの左シフトと右シフトは、1 つ違いの間違いを犯しやすい場所です。 列 (c) に配置されたクイーンは、次の行の列 (c-1) と列 (c+1) を攻撃するため、2 つの対角方向は逆方向に移動する必要があります。 の`& full`左シフト後、ボードから離れる攻撃を破棄します。 

基本ケースのチェック`row == n`、 それよりも`row == n - 1`。 その時点で、すべての (N) 行がクイーンを受け取っているため、正確に 1 つの完全なソリューションが構築されています。 これは (N=1) も正しく処理します。 

Python の整数はオーバーフローしないため、答えを直接累積できます。 この問題では、最大の答えは (N=9) で 352 にすぎませんが、それでも整数カウンターを使用するのが自然な実装です。
