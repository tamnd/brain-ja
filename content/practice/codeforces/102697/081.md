 ## 解決策
 ## 問題の理解

 ライブラリには本があり、各本は著者の姓と本のジャンルという 2 つの単語で説明されます。 入力により、書籍が任意の順序で与えられます。 タスクは、本がジャンルごとにグループ化され、ジャンル自体がアルファベット順に表示され、すべてのジャンル内で著者の姓もアルファベット順に表示されるように書籍を再編成することです。 各ジャンルが 1 回出力され、その後にその著者がカンマで区切られて出力されます。 このステートメントは、ジャンル名と著者名の両方が 1 つの単語で構成されていることを保証します。 

重要な点は、本の元の順序を保持する必要がないことです。 ここでは 2 つの独立したアルファベット順のみを考慮します。つまり、ジャンル名の順序と、各ジャンル内の著者の順序です。 そのため、これはグラフや動的計画法の問題ではなく、グループ化と並べ替えの問題になります。 

公表された声明では書籍数の上限は明記されていない。 1 秒の時間制限と 256 MB のメモリが与えられるため、実装では不必要な繰り返しスキャンを回避し、標準的なソートの複雑さを持つ必要があります。 O(n log n) ソリューションは通常の競技プログラミングの入力サイズに快適に適していますが、O(n²) メソッドは n が大きくなるにつれて問題が発生します。 たとえば、100,000 冊の書籍の場合、二次手法は約 5,000,000,000 回のペアごとの比較を実行できますが、これは 1 秒の Python プログラムが試行すべき量をはるかに超えています。 

微妙なエッジケースは、1 冊しか含まれないジャンルです。 例えば、```
1
Tolkien fantasy
```生成する```
fantasy: Tolkien
```著者が 1 人だけであるため、カンマはありません。 常に追加する実装`", "`作成者が誤った末尾区切り文字を作成した後。 

もう 1 つのエッジ ケースは、入力順序が必要な出力順序と関係がないことです。 例えば、```
3
Zola history
Asimov science
Adams history
```生産しなければならない```
history: Adams, Zola
science: Asimov
```正しくグループ化しても、ジャンルを最初に見た順序で印刷するソリューションでは、誤って配置されてしまいます。`science`前に`history`入力がたまたまそれを最初に導入した場合。 

ジャンル内でも同じ問題が発生します。 例えば、```
3
Zola history
Adams history
Brown history
```生産しなければならない```
history: Adams, Brown, Zola
```入力の読み取り中に単に作成者を追加すると、必要なアルファベット順ではなく、乱雑な入力順序が保持されます。 

## アプローチ

 簡単な総当りの解決策では、次のジャンルを繰り返し検索し、すべての書籍を検索してそのジャンルに属する著者を見つけることができます。 書籍を処理済みとしてマークし、アルファベット順で最も小さい未処理のジャンルを選択し、その書籍をすべて収集し、それらの著者を並べ替えて、これを繰り返すことで正しくすることができます。 問題は、n 冊すべての書籍を繰り返しスキャンすると、Θ(n²) 個の作業が必要になる可能性があることです。 最悪の場合、およそ n² 個の比較が実行され、n = 100,000 の場合、約 100 億回の演算が実行されます。 

この強引な方法は、すべての本が最終的に 1 つのジャンルに割り当てられるため機能しますが、入力が読まれたときにすでに入手可能だった情報を再発見するのに時間がかかります。 有益な観察は、本は当然そのジャンルによって特定される 1 つのグループに属するということです。 これらのグループを辞書に直接保存できます。 グループ分けが構築されたら、あとはジャンル名を並べ替えて、各ジャンルの著者リストを並べ替えるだけです。 

より複雑なデータ構造は必要ありません。 Python の辞書では、書籍ごとに O(1) 回の挿入が期待され、組み込みの並べ替えでは、k 人の著者のリストに対して O(k log k) の時間がかかります。 ジャンル グループにサイズ k₁、k₂、...、k_g が含まれる場合、著者を並べ替える総コストは Σ kᵢ log kᵢ で、最大でも O(n log n) です。 g 個のジャンル名のソートには O(g log g) のコストがかかり、これも O(n log n) によって制限されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | n が大きいと遅すぎます |
 | 辞書でグループ化して並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. キーがジャンル名、値が著者のリストである辞書を作成します。 本に著者がいる場合`A`そしてジャンル`G`、追加`A`に関連付けられたリストへ`G`。 これにより、単一の入力パス中にグループ化が実行されるため、ジャンルの書籍を見つけるためにコレクション全体を再度スキャンする必要がなくなります。 
2. 辞書からすべてのジャンル名を抽出し、アルファベット順に並べ替えます。 出力ではジャンル自体を順序付けする必要があるため、辞書を直接反復処理するだけでは十分ではありません。 
3. ソートされたジャンルを一度に 1 つずつ処理します。 ジャンルごとに、著者リストをアルファベット順に並べ替えます。 そのジャンルに属するすべての著者がすでに集まっているため、この並べ替えは関連するサブセットに対してのみ機能します。 
4. ソートされた著者を次のように結合します。`", "`ジャンルを出力し、続いて`": "`。 区切り文字を手動で追加するのではなく結合すると、末尾のカンマが回避され、著者が 1 人の場合が自動的に処理されます。 

### なぜ効果があるのか

 不変条件は、入力の接頭辞を読み取った後、その接頭辞内のすべての本が、そのジャンルに属する著者リストに 1 回だけ表示されるということです。 したがって、完全な入力が読み取られた後、各ジャンルにはその本の著者が正確に含まれ、他のジャンルは含まれません。 ジャンルキーをソートすると、必要なジャンルの順序が生成され、対応する各著者リストをソートすると、そのジャンル内で必要な著者の順序が生成されます。 その結果、最終出力にはすべての入力ブックが 1 回だけ含まれ、必要なアルファベット順の両方が満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    genres = {}

    for _ in range(n):
        author, genre = input().split()
        if genre not in genres:
            genres[genre] = []
        genres[genre].append(author)

    for genre in sorted(genres):
        authors = sorted(genres[genre])
        print(f"{genre}: {', '.join(authors)}")

if __name__ == "__main__":
    solve()
```辞書`genres`は、アルゴリズムで説明されているグループ化を直接表現したものです。 メンバーシップ チェックでは、ジャンルが初めて表示されるときにリストが作成され、その後の書籍ではその著者がそのリストに追加されるだけです。 

表現`sorted(genres)`ジャンル名を辞書順に生成します。 Python は文字列を辞書順に比較します。これは、ステートメントで要求されるアルファベット順とまったく同じです。 著者名は次の場合に同じ順序を使用します。`sorted(genres[genre])`と呼ばれます。 

の`join`出力フォーマットが問題の一部であるため、この操作には注意が必要です。 3人の著者のために制作します`A, B, C`、一方、ある著者の場合は、`A`。 したがって、最後の作成者にとって特別なケースはなく、誤って余分なコンマを出力する可能性もありません。 

制御フローに使用される唯一の整数は本の数であり、Python の整数は任意の精度を持っているため、整数オーバーフローの懸念はありません。 入力ループも各書籍を 1 回だけ処理します。 

## 実用的な例

 サンプル 1 の入力は次のとおりです。```
7
Bradbruy scifi
Asimov scifi
Kafka dystopian
Huxley dystopian
Tolkien fantasy
Collins dystopian
Herbert scifi
```グループ化状態は次のように展開します。 

| 本を読む | ジャンル | そのジャンルで現在保存されている著者 |
 | --- | --- | --- |
 | ブラッドブリュイのSF | サイエンスフィクション | ブラッドブリュイ |
 | アシモフ SF | サイエンスフィクション | ブラッドブリュイ、アシモフ |
 | カフカのディストピア | ディストピア | カフカ |
 | ハクスリーのディストピア | ディストピア | カフカ、ハクスリー |
 | トールキンのファンタジー | ファンタジー | トールキン |
 | コリンズのディストピア | ディストピア | カフカ、ハクスリー、コリンズ |
 | ハーバートSF | サイエンスフィクション | ブラッドブリュイ、アシモフ、ハーバート |

 ジャンルキーは次のようにソートされます。`dystopian`、`fantasy`、`scifi`。 著者リストごとにソートすると、`Collins, Huxley, Kafka`のために`dystopian`、`Tolkien`のために`fantasy`、 そして`Asimov, Bradbruy, Herbert`のために`scifi`。 

結果の出力は次のようになります。```
dystopian: Collins, Huxley, Kafka
fantasy: Tolkien
scifi: Asimov, Bradbruy, Herbert
```この例では、両方のレベルの並べ替えを示します。 ジャンルの初登場の順序も、著者の初登場の順序も保存されません。 

2 番目の例として、次のことを考えてみましょう。```
5

Adams history
Newton science
Brown history
Curie science
```グループ化のプロセスは次のとおりです。 

| 本を読む | ジャンル | そのジャンルで現在保存されている著者 |
 | --- | --- | --- |
 | ゾラの歴史 | 歴史 | ゾラ |
 | アダムスの歴史 | 歴史 | ゾラ、アダムス |
 | ニュートン科学 | 科学 | ニュートン |
 | ブラウンの歴史 | 歴史 | ゾーラ、アダムス、ブラウン |
 | キュリーの科学 | 科学 | ニュートン、キュリー |

 グループ化後のジャンル名は、`history`そして`science`。 著者リストを並べ替えると、`Adams, Brown, Zola`そして`Curie, Newton`。

history: Adams, Brown, Zola

```このトレースは、グループ化と並べ替えを別の操作として扱う必要がある理由を示しています。 辞書には入力順序が記録されますが、最終的な並べ替えではその順序が意図的に破棄されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | グループ化のコストは O(n)、すべてのジャンル名の並べ替えのコストは O(g log g)、すべての著者リストの並べ替えのコストは最大でも O(n log n) |
 | スペース | O(n) | すべての著者はグループ化された辞書に一度保存されます。 

ここで、n は本の数、g は個別のジャンルの数です。 g ≤ n であるため、合計実行時間は O(n log n) です。 このソリューションは入力情報を辞書に保存するため、メモリ消費量は線形です。 規定の 1 秒の時間制限では、二次再スキャンを回避することが主なパフォーマンス要件です。 

## テストケース```python

import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    genres = {}

    for _ in range(n):
        author, genre = input().split()
        genres.setdefault(genre, []).append(author)

    out = []
    for genre in sorted(genres):
        out.append(f"{genre}: {', '.join(sorted(genres[genre]))}")

    print("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 単一ブックのケースは、通常のグループ化および結合ロジックによって処理されます。 のために```
1
Tolkien fantasy
```辞書はこうなる`{"fantasy": ["Tolkien"]}`。 唯一のジャンルは、`fantasy`、その著者リストは残っています`["Tolkien"]`並べ替えた後、そして`", ".join(...)`返品`Tolkien`。 出力は正確に`fantasy: Tolkien`。 

書籍数が多いジャンルでも入力順序が任意の場合も特別なロジックなしで対応します。 のために```
4
Zola classics
Young classics
Smith classics
Adams classics
```保存されている著者リストは最初は`["Zola", "Young", "Smith", "Adams"]`。 並べ替えると次のように変わります`["Adams", "Smith", "Young", "Zola"]`、結合すると生成される`classics: Adams, Smith, Young, Zola`。 ソートせずにグループのみを実装すると、間違った順序が暗黙的に保持されます。 

不都合な順序で表示されるジャンルは、2 番目の並べ替え要件を実行します。 のために```
4
Zed author1
Amy author2
Bob author1
Cal author3
```辞書は次の順序で構築されます`author1`、`author2`、`author3`ですが、実装はその順序に依存しません。 キーをソートすると、ここでは同じアルファベット順になりますが、`author1`から別々に分類されます`Zed, Bob`に`Bob, Zed`。 最終結果は```
author1: Bob, Zed
author2: Amy
author3: Cal
```より一般的な教訓は、入力順序が出力のどちらのレベルにも影響を与えてはならないということです。 辞書は一時的なグループ化構造にすぎません。 キーと値の両方が印刷前に明示的に並べ替えられるため、図書館の書籍が最初にどのように配置されていたかに関係なく、アルゴリズムは正しいままになります。
