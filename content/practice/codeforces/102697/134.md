 ## 解決策
 ## 問題の理解

 タスクは、指定された文字列が「警報文字列」であるかどうかを判断することです。 文字列は、文字が次の場合にこのプロパティを持ちます。`a`その中に3回登場します。 入力に出現するスペースを含む他のすべての文字は無関係です。 必要な出力は次のとおりです`YES`カウントがちょうど 3 のとき、`NO`さもないと。 公式の問題ページでは、入力が単一の文字列であり、警告となる文字列にはちょうど 3 つの文字列が含まれていることを確認しています。`a`文字。 

問題ページに記載されている文字列の長さに数値制限はないため、解決策は入力量において線形であるはずであると解釈するのが安全です。 二次アルゴリズムは同じ文字を繰り返し検査するため、文字列が大きくなるにつれて不必要にコストがかかります。 1 つのパスには文字ごとに 1 つの操作が必要ですが、これは 1 秒、256 MB の問題の自然な目標です。 公式アーカイブでは、1 秒の時間制限と 256 MB のメモリ制限が設けられています。 

実装のバグを引き起こす可能性のある主な入力の詳細は、文字列にスペースが含まれる可能性があることです。 一緒に読む`input().split()`スペースを破棄し、さらに深刻な場合は最初の単語のみを読み取ります。 たとえば、入力`an apple actually appeared`4つ入っています`a`文字と生成する必要があります`NO`、公式の例で示されているように。 

もう 1 つの特殊なケースは、出現場所に関係なく、ちょうど 3 回発生することです。 のために`aardvark`、`a`文字は最初の 2 つの位置と最後の位置に出現するため、答えは次のようになります。`YES`。 誤って 3 回連続してチェックしてしまう解決策`a`キャラクターはそれを誤って拒否してしまうでしょう。 

3 つ以上の出現を含む文字列も拒否する必要があります。 例えば、`aaaa`4つあります`a`文字なので、その出力は次のようになります`NO`。 文字列に 3 つ以上の文字列が含まれているかどうかだけをチェックするという不用意な解決策`a`文字が正しく印刷されない`YES`。 

最後に、出現回数が 3 回未満であれば、`NO`。 例えば、`abc`含まれていません`a`、したがって、答えは次のとおりです`NO`。 カウンタを誤って初期化するコード、またはカウンタの存在をチェックするコード`a`この場合、カウントする代わりに失敗します。 

## アプローチ

 最も直接的な総当たりアプローチは、すべての出現位置を考慮して、その数をカウントすることです。`a`文字列全体を再度スキャンして文字をスキャンします。 完全なスキャンごとに正確な数が得られるため、これは正しいです。`a`しかし、不必要な繰り返し作業が実行されます。 文字列に長さがある場合`n`、それぞれのフルスキャンを実行します。`n`ポジションは正確に実行されます`n^2`最悪の場合は文字検査。 スキャンを 3 回だけ実行したとしても、作業量は依然として必要量の 3 倍になります。 

私たちが気にするプロパティは総数のみに依存するため、ブルートフォースアプローチが機能します`a`文字。 重要な観察は、文字列を 1 回読み取る間にこの合計が累積できるということです。 遭遇したとき`a`、カウンターをインクリメントします。 1 文字おきにカウンターは変更されません。 最後の文字の後、カウンタは正確に次の文字の数になります。`a`元の文字列内の文字。 

これにより、問題は単純な線形スキャンに変わります。 重要なのは 1 文字だけであるため、頻度辞書は必要ありません。また、文字列を読み取った後に保存する必要もありません。 パイソンの`count('a')`も必要な線形スキャンを直接実行しますが、明示的なループにより基礎となるアルゴリズムが明確になり、入力の処理方法に関する曖昧さが回避されます。

 ## アルゴリズムのチュートリアル

 1. スペースを保持したまま、入力行全体を文字列として読み取ります。 使用する`input().rstrip('\n')`行末のみを削除し、文字列のすべての文字を検査に使用できるようにします。 
2. カウンタをゼロに初期化します。 カウンタは数を表します`a`これまで見てきたキャラクターたち。 
3. 文字列を左から右にスキャンします。 現在のキャラクターがいるたびに、`a`、カウンターを 1 つ増やします。 定義は次の出現のみに依存するため、他の文字は答えに影響しません。`a`。 
4. スキャンが終了したら、カウンターを 3 と比較します。 印刷する`YES`3 に等しい場合は出力します`NO`さもないと。 平等性をチェックするのではなく`>= 3`4 回以上発生しても心配する必要はないため、これは必要です。 

機能する理由: 文字列の接頭辞を処理した後、カウンターは、文字列の数と正確に等しくなります。`a`そのプレフィックス内の文字。 最初はプレフィックスは空でカウンタはゼロであるため、プロパティは保持されます。 次の文字がないとき`a`、両方とも実際の数`a`文字とカウンターは変更されません。 そうなったとき`a`、両方とも 1 ずつ増加します。 したがって、不変条件はスキャン全体にわたって真のままです。 文字列全体が処理されると、カウンタは正確に文字列の合計数になります。`a`文字なので印刷する`YES`まさに 3 に等しい場合は定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().rstrip('\n')

count_a = 0

for ch in s:
    if ch == 'a':
        count_a += 1

print("YES" if count_a == 3 else "NO")
```最初の行は完全な入力行を読み取ります。`rstrip('\n')`の代わりに使用されます`strip()`なぜなら`strip()`文字列の両端から空白を削除しますが、空白は入力内で有効な文字であり、変更しないでください。 問題の例には、スペースを含む文字列が明示的に含まれています。 

ループはカウント ステップを直接実装します。 境界演算、インデックス付け、または部分文字列の構築がないため、1 つずつずれた位置を管理する必要はありません。 カウンタは正確な文字に対してのみインクリメントされます`a`。 

最後の条件文は意図的に使用します`count_a == 3`。 のような条件`count_a >= 3`4つ以上を含む文字列を受け入れます`a`定義に違反する文字。 

Python の整数は、可能なカウンター値に対してオーバーフローしないため、特別な数値処理は必要ありません。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    s = input().rstrip('\n')
    count_a = 0

    for ch in s:
        if ch == 'a':
            count_a += 1

    print("YES" if count_a == 3 else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("coderams competition number eleven\n") == "NO\n", "sample 1"
assert run("aardvark\n") == "YES\n", "sample 2"
assert run("an apple actually appeared\n") == "NO\n", "sample 3"

# Minimum-size input
assert run("a\n") == "NO\n", "fewer than three a characters"

# Exactly three, all adjacent
assert run("aaa\n") == "YES\n", "exactly three adjacent a characters"

# More than three
assert run("aaaa\n") == "NO\n", "more than three a characters"

# Three occurrences separated by spaces and other letters
assert run("a b a c a\n") == "YES\n", "spaces and separated occurrences"

# No a characters
assert run("bcdef\n") == "NO\n", "no a characters"

# Large input, exactly three a characters
large = "b" * 100000 + "a" + "b" * 100000 + "a" + "b" * 100000 + "a\n"
assert run(large) == "YES\n", "large boundary-sized input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 |`aaa`|`YES`| 隣接する位置でちょうど 3 回出現 |
 |`aaaa`|`NO`| 3 回を超える出現を拒否する |
 |`a b a c a`|`YES`| スペースを保持し、区切られた出現をカウントする |

 ## 特殊なケース

 最初の微妙なケースは、スペースを含む入力です。 のために`an apple actually appeared`の場合、アルゴリズムは行を単語に分割するのではなく、行全体を読み取ります。 4人に遭遇`a`キャラクター、だから`count_a`4 時に終了し、出力は次のようになります。`NO`。 不注意な`input().split()[0]`実装は検査のみを行います`an`間違ったカウントが生成される可能性があります。 公式問題には、まさにこのサンプルが含まれています。 

2 番目のケースは、連続していない 3 回の出現です。 入力あり`aardvark`、カウンターは次のように進化します。`0 -> 1 -> 2 -> 2 -> 2 -> 2 -> 3 -> 3 -> 3`したがって、最終結果は次のようになります。`YES`。 このアルゴリズムでは、定義に一致する隣接性については何も仮定しません。 

3 番目のケースは 3 回以上発生します。 入力あり`aaaa`、カウンターは`1`、 それから`2`、 それから`3`、 それから`4`。 最後の比較は、`4 == 3`これは false なので、出力は次のようになります。`NO`。 これにより、カウントが少なくとも 3 に達したかどうかをテストするというよくある間違いが見つかります。 

4 番目のケースは、発生回数が 3 回未満です。 入力あり`aa`、カウンターは 2 で終了し、出力は次のようになります。`NO`。 アルゴリズムは、最初または 2 番目のメッセージを見つけても、時期尚早に受け入れません。`a`完全な文字列が処理された後にのみ決定が行われるためです。 

5 番目のケースは、関連する 3 つの文字が遠く離れている大きな入力です。 100,000を含む文字列`b`文字、その後`a`、さらに100,000`b`キャラクター、別の`a`、さらに100,000`b`登場人物と最後`a`まだ生産しています`YES`。 スキャンでは文字ごとに 1 つの定数チェックが実行されるため、実行時間は 3 つの出現間の距離ではなく、入力サイズに比例して増加します。
