 ## 問題の理解

 このタスクは、10 進数の 4 と 7 のみを使用し、まったく同じ数の 4 と 7 を使用して、少なくとも指定された数値 (n) である最小の整数を見つけることです。 このような数字をスーパーラッキーと呼びます。 入力には 1 つの正の整数が含まれていますが、その値は 10 進数で最大 100,000 桁まで含めることができるため、マシン整数に変換するのではなく文字列として扱う必要があります。 出力は、下限を満たす最小の超ラッキーな数値です。 

スーパー ラッキー ナンバーの長さは偶数である必要があります。その桁は 4 と 7 の間で均等に分割する必要があるためです。入力長が奇数の場合、その長さのスーパー ラッキー ナンバーは存在しないため、答えはすぐに次の偶数の長さを使用する必要があります。 10万桁もあれば、候補を列挙することはまったく不可能です。 4 と 7 のみから構成される (2^{100000}) 個の文字列があり、バランスの取れた文字列に限定しても (\binom{100000}{50000}) 個の候補が残ります。 意図したソリューションでは、10 進表現を線形時間で処理する必要があります。 元の問題には 2 秒の制限時間があり、(n) は 100,000 桁まで許容されます。 

不注意な実装により、気付かれずに問題が発生する可能性があるケースがいくつかあります。 入力用`47`、数字自体はすでに非常に幸運であるため、正しい出力は次のようになります。`47`。 常に厳密に大きい数値を検索する実装では、誤って生成される可能性があります。`74`。 

入力用`1`、長さが奇数です。 1 桁のバランスの取れたラッキー ナンバーは存在しません。したがって、答えは 2 桁のバランスのとれたラッキー ナンバーの中で最も小さいものになります。`47`。 同じ長さの数値のみを検索する実装は、ここで失敗します。 

入力用`4500`、正しい出力は次のとおりです。`4747`。 最初の数字は 4 のままですが、2 番目の数字 5 はラッキー ナンバーとして使用できません。 その位置を 7 に増やしてから、残りの位置を 1 つの 4 と 1 つの 7 で埋める必要があります。既存の 4 を 7 に変更することのみを考慮したソリューションでは、5 などの無効な数字を 7 に置き換える可能性が失われます。 

入力用`7777`、少なくとも 4 桁のスーパーラッキーナンバーを入力することはできません。 先頭にあらゆる変更を加えると、プレフィックスに 7 が多すぎるため、答えは次の偶数の長さに移動し、次のようになります。`444777`。 同じ長さの答えが常に存在すると仮定する実装では、無効な数値が作成されるか、文字列の先頭を超えて実行されます。 

## アプローチ

 直接的な総当たりの解決策では、関連する長さのすべての幸運な数字を生成し、同数の 4 と 7 を含む数字を保持し、少なくとも (n) である最初の数字を選択します。 長さ (L) の場合、4 と 7 のみを含む文字列は正確に (2^L) 個あります。最悪のケース (L=100000) では、桁数のバランスが取れているかどうかを確認する前に、候補が正確に (2^{100000}) 個あることを意味します。 バランスの取れた候補のみを生成したとしても、その数は依然として (\binom{100000}{50000}) となり、これは天文学的に大きくなります。 各候補を (n) に対してチェックすること自体が (O(L)) 文字の比較を必要とする場合があります。 ブルート フォース アプローチは、候補セット全体を明示的に検査するため正しいですが、指数関数的に増加するため使用できなくなります。 

有益な観察は、候補を個別に構築する必要がないということです。 同じ長さのスーパー ラッキー ナンバーはすべて、位置のちょうど半分が 4 で占められ、半分が 7 で占められます。2 つの同じ長さの数字を比較する場合、それらが異なる最初の位置によってどちらが小さいかが決まります。 つまり、プレフィックスをできるだけ長く (n) に保つ必要があります。 平等が継続できなくなる最初の位置では、その桁を可能な限り最小量だけ増やしてから、接尾辞を可能な限り小さくしたいと考えます。 

幸運の数字は 2 つしかないため、どの位置にも役に立つ大きな数字は 1 つだけです。 入力桁が 4 の場合、7 に置き換えることができます。入力桁が 0 ～ 3 の場合、4 に置き換えることができます。入力桁が 5 または 6 の場合、7 に置き換えることができます。7、8、または 9 の場合、それより大きい幸運の桁はありません。 位置が増加すると、4 は小さい数字であるため、サフィックスには残りの 7 がすべて含まれる前に、残りの 4 がすべて含まれる必要があります。 

微妙な部分は、増やす位置の選択です。 (n) に等しい長いプレフィックスが保持されるため、後の位置は常に前の位置よりも優先されます。 左から右にスキャンしている間、桁数を必要な制限内に保ちながら、現在の桁を増やすことが可能になった最新の位置を思い出すことができます。 元の番号がすでに超幸運である場合は、すぐにその番号を返します。 実現可能な増加が存在しない場合、同じ長さの答えは存在しないため、次の偶数の長さを持つ最小のスーパー ラッキー番号を使用します。

 ## アルゴリズムのチュートリアル

1. (n) を文字列として読み取り、その長さを (L) とします。 (L) は通常のマシンの整数範囲をはるかに超える 100,000 になる可能性があるため、これを整数に変換することはありません。 
2. (L) が奇数の場合、それを 1 増やして、その長さの最小のスーパー ラッキー数を作成します。 4 は 7 より小さいため、その数は (L/2) 個の 4 の後に (L/2) 個の 7 が続くブロックになります。 奇数長の数値には、2 桁のカウントが同じになることはありません。 
3. (L) が偶数の場合は、まず (n) 自体に 4 と 7 だけが含まれているかどうか、およびそれぞれの正確に (L/2) 個のコピーが含まれているかどうかを確認します。 一致する場合、必要な値は少なくとも (n) であるため、それはすでに可能な最小の答えになります。 
4. プレフィックスの 4 と 7 の数を維持しながら、左から右に数字をスキャンします。 位置 (i) では、(i) の前のプレフィックスは完全に幸運な数字で構成されている必要があります。 無効な数字がすでに出現している場合は、変更されていないプレフィックスにその無効な数字が含まれるため、それ以降の位置を最初に変更された位置として使用することはできません。 
5. 現在の位置で、厳密に (n[i]) より大きい最小の幸運の数字を決定します。 4 より下の数字の場合は 4、5 または 6 の場合は 7、4 の場合は 7 です。数字 7、8、および 9 には、これより大きな幸運の数字はありません。 
6. 大きい桁を配置すると、いずれかの桁数が (L/2) を超えるかどうかを確認します。 可能であれば、この位置と置換桁を覚えておいてください。 元のプレフィックスをより多く保持することにより、後で実行可能な位置が生成される最終的な数値が小さくなるため、意図的にスキャンを続けます。 
7. スキャン後、実行可能な位置が見つかった場合は、その位置の前のプレフィックスをコピーし、記憶されている大きい数字をそこに置き、残りの位置を必要な数の 4 と、その後に必要な数の 7 で正確に埋めます。 すべての 4 はすべての 7 よりも小さいため、この接尾辞は辞書編集的に最小になります。 
8. 実行可能な位置が存在しない場合は、長さ (L+2) の最小のスーパー ラッキー番号を作成します。 より多くの桁の数値はすべて (L) 桁の数値よりも大きいため、これは正しいフォールバックです。 

不変条件は、記憶されているすべての候補が (n) と同じ接頭辞を持ち、その後に候補が大きくなる最初の位置が続くということです。 その桁カウントは、各桁の正確に (L/2) コピーまで完了することができます。 このようなすべての候補の中で、最後に変更された位置は、(n) との共通接頭辞が最も長く、したがって最小になります。 その位置が固定されたら、残りの 4 をすべて残りの 7 の前に置くと、最小のサフィックスが得られます。 そのような位置が存在しない場合、同じ長さのスーパーラッキーナンバーは少なくとも (n) 個以上存在することはできないため、長さを増やすことは避けられません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(n: str) -> str:
    length = len(n)

    # An odd length cannot contain equal numbers of 4 and 7.
    if length % 2 == 1:
        half = (length + 1) // 2
        return '4' * half + '7' * half

    half = length // 2

    # If n is already super lucky, it is the answer.
    if n.count('4') == half and n.count('7') == half:
        return n

    count4 = 0
    count7 = 0

    best_pos = -1
    best_digit = ''

    for i, ch in enumerate(n):
        if ch not in '47':
            # Find the smallest lucky digit strictly greater than ch.
            if ch < '4':
                digit = '4'
            elif ch < '7':
                digit = '7'
            else:
                digit = ''

            if digit:
                new4 = count4 + (digit == '4')
                new7 = count7 + (digit == '7')

                if new4 <= half and new7 <= half:
                    best_pos = i
                    best_digit = digit

            # The unchanged prefix would contain an invalid digit,
            # so no later position can be the first changed position.
            break

        # ch is lucky. It can only be increased if it is 4.
        if ch == '4':
            if count4 <= half and count7 + 1 <= half:
                best_pos = i
                best_digit = '7'
            count4 += 1
        else:
            count7 += 1

    if best_pos == -1:
        # No valid answer with the same length.
        new_length = length + 2
        half = new_length // 2
        return '4' * half + '7' * half

    # Use the longest possible unchanged prefix.
    prefix = n[:best_pos]
    new4 = count4
    new7 = count7

    # The counts above correspond to the prefix when best_pos is after
    # the scan, so recompute them directly for the chosen prefix.
    new4 = prefix.count('4')
    new7 = prefix.count('7')

    if best_digit == '4':
        new4 += 1
    else:
        new7 += 1

    remaining4 = half - new4
    remaining7 = half - new7

    return prefix + best_digit + '4' * remaining4 + '7' * remaining7

def main():
    n = input().strip()
    print(solve(n))

if __name__ == "__main__":
    main()
```最初のブランチは、詳細な比較を行う前に、奇数の長さを処理します。 新しい長さは、入力長より大きい最小の偶数の長さであり、等しいカウントを持つ辞書編集上の最小の文字列は、すべて 4 の後にすべて 7 が続きます。 

完全一致チェックでは、偶数長の超ラッキーな数字には正確な値が含まれている必要があるという事実を利用します。`half`両方の数字のコピー。 すぐに返すと、貪欲な検索で不必要に厳密に大きな数値が生成されるのを防ぎます。 

メインスキャン中に、`count4`そして`count7`現在の位置の前に変更されていないプレフィックスを記述します。 現在の数字が 4 の場合、幸運を維持しながら数字を大きくするには、それを 7 に変更することが唯一の方法です。 現在の数字が幸運でない場合、コードはそれを超える最小の幸運な数字を試します。 以降の候補ではその無効な桁を変更しない必要があるため、スキャンは最初の無効な桁の後で停止します。 

の`best_pos`変数には、最新の実現可能な増加量が格納されます。 最初のものではなく最新のものを保存することが重要な貪欲な選択です。 後で変更すると、元の数値より多くの桁が保持され、結果の数値が小さくなります。 

スキャン後、コードは残りの数の 4 に続いて残りの数の 7 を使用してサフィックスを再構築します。 この実装では全体で文字列演算が使用されるため、100,000 桁の整数に対して算術演算が実行されることはありません。 したがって、Python の整数変換の制限は無関係です。 

の`prefix.count`コールは候補位置が選択された後に 1 回だけ発生するため、追加されるのはせいぜい線形パスです。 合計実行時間は線形のままです。 次のような式での Python ブール値の使用`digit == '4'`意図的であるため、`True`そして`False`カウントに追加すると 1 と 0 として動作します。 

## 実用的な例

 最初のサンプルでは、`n = 4500`、長さは 4 で、半分は 2 です。数字自体は、すべての桁が 4 と 7 ではないため、それほど幸運ではありません。スキャンは次のように進行します。 

| ポジション | 数字 | 4 秒前 | 7秒前 | より大きな幸運の数字の可能性 | 実現可能な候補 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 4 | 0 | 0 | 7 | 7 |
 | 1 | 5 | 1 | 0 | 7 | 7 |

 位置 0 では、4 を 7 に変更すると有効な候補が得られますが、後の変更が望ましいため続行します。 位置 1 では、数字 5 が 7 になることもあり、接頭辞は`4`残りの桁に十分な容量を残します。 したがって、最適な位置は 1 です。プレフィックスは次のとおりです。`4`、変更された桁は`7`、残りのカウントには 4 が 1 つと 7 が 1 つ必要です。`4747`。 これは公式サンプルと一致します。 

2 番目のサンプルについては、`n = 47`、長さは 2 で、半分は 1 です。どちらの数字も幸運であり、その数はすでに等しいです。 

| ポジション | 数字 | 読んでから 4 秒 | 読んでから 7 秒 | ステータス |
 | --- | --- | --- | --- | --- |

 | 1 | 7 | 1 | 1 | まさにバランスのとれた |

## テストケース```python
import sys
import io

def solve(n: str) -> str:
    length = len(n)

    if length % 2 == 1:
        half = (length + 1) // 2
        return '4' * half + '7' * half

    half = length // 2

    if n.count('4') == half and n.count('7') == half:
        return n

    count4 = 0
    count7 = 0

    best_pos = -1
    best_digit = ''

    for i, ch in enumerate(n):
        if ch not in '47':
            if ch < '4':
                digit = '4'
            elif ch < '7':
                digit = '7'
            else:
                digit = ''

            if digit:
                new4 = count4 + (digit == '4')
                new7 = count7 + (digit == '7')

                if new4 <= half and new7 <= half:
                    best_pos = i
                    best_digit = digit

            break

        if ch == '4':
            if count4 <= half and count7 + 1 <= half:
                best_pos = i
                best_digit = '7'
            count4 += 1
        else:
            count7 += 1

    if best_pos == -1:
        new_length = length + 2
        half = new_length // 2
        return '4' * half + '7' * half

    prefix = n[:best_pos]
    count4 = prefix.count('4')
    count7 = prefix.count('7')

    if best_digit == '4':
        count4 += 1
    else:
        count7 += 1

    return (
        prefix
        + best_digit
        + '4' * (half - count4)
        + '7' * (half - count7)
    )

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve(sys.stdin.readline().strip()) + '\n'

# Provided samples

assert run("47\n") == "47\n", "sample 2"

# Minimum-size input
assert run("1\n") == "47\n", "minimum size"

# All-equal digits
assert run("4444\n") == "4477\n", "all 4s"

# Boundary where an invalid digit must be increased
assert run("4478\n") == "4747\n", "invalid trailing digit"

# No valid answer with the original length
assert run("7777\n") == "444777\n", "length increase"

# Maximum-size input, already super lucky
maximum = "4" * 50000 + "7" * 50000
assert run(maximum + "\n") == maximum + "\n", "maximum size"
