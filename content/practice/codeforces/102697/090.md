 ## 解決策
 ## 問題の理解

 このタスクは、コンピュータのハード ドライブ容量を直接分類することです。 入力は次のような文字列です。`300GB`、数値部分はギガバイト単位の容量で、最後の部分は`GB`は固定接尾辞です。 この接尾辞を削除し、残りの部分を整数として解釈し、容量を 3 つのカテゴリのいずれかに分類する必要があります。 

最大200GBの容量は、`SMALL`。 200 GB を超え、最大 500 GB の容量は、`MEDIUM`。 500GBを超えるものは`LARGE`。 公式問題は 1 秒の制限時間と 256 MB のメモリを使用します。 短い入力文字列が 1 つだけあり、計算はそれを解析し、最大 2 つの比較を実行することで構成されるため、アルゴリズムはこれらの制限内に問題なく収まります。 実行時間は、入力文字列の文字数にのみ比例します。 

主な境界ケースは 2 つのしきい値そのものです。 のために`200GB`、答えは`SMALL`、 ない`MEDIUM`、最初の間隔が含まれるためです。 のために`500GB`、答えは`MEDIUM`、 ない`LARGE`2 番目の間隔も含まれるためです。 たとえば、入力`200GB`生成する`SMALL`、 その間`500GB`生成する`MEDIUM`。 を使用した不用意な実装`< 200`または`< 500`これらの正確な境界値を誤って分類してしまう可能性があります。 

もう 1 つの簡単な間違いは、完全な文字列を次のような文字列と比較することです。`"200GB"`最初に数値部分を解釈せずに。 辞書編集上の文字列比較は、一般に数値比較を表しません。 例えば、`"1000GB"`そして`"500GB"`必要なロジックでは同じ順序がありません。 整数を抽出すると、そのクラス全体のエラーが回避されます。 

## アプローチ

 強引な解釈では、可能な最小値から指定された容量までのすべての可能な容量をシミュレートし、どの間隔にその容量が含まれるかを判断することになります。 これは、シミュレートされた値が最終的に実際の容量に達するという意味では正しいですが、ギガバイトごとに 1 回の反復が実行されます。 容量があれば`C`、そのアプローチは実行します`C`したがって、最悪の場合の操作数は、入力の長さではなく、可能な最大容量に比例します。 分類は 2 つの固定境界によって完全に決定されるため、値を列挙する必要はありません。 

重要な観察は、3 つのカテゴリが連続した間隔を形成していることです。 数値容量がわかったら、答える必要がある質問は 2 つだけです。それは最大 200 ですか? そうでない場合は最大 500 ですか? 最初の真の条件によって、答えが完全に決まります。 両方の条件が false の場合、容量は 500 より大きい必要があるため、`LARGE`。 

ブルート フォースは、最終的に容量を含む同じ間隔を検出するため機能しますが、結果に影響を与えない値に対して不必要な作業を実行するため失敗します。 2 つのしきい値のみが重要であるという観察により、問題は 1 つの整数を解析し、2 つの定数時間比較を行うことに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C) | お(1) | 原理的に遅すぎる |
 | 最適 | O(L) | お(1) | 承認済み |

 ここ、`C`は数値容量であり、`L`入力文字列の長さです。 最適な解決策は、問題で使用される小さな固定サイズの入力に対して事実上一定時間です。 

## アルゴリズムのチュートリアル

 1. たとえば、容量文字列を読み取ります。`450GB`。 の`GB`接尾辞は数値の一部ではないため、容量を整数に変換する前に削除する必要があります。 
2. 最後の 2 文字より前のすべてを整数に変換します。 のために`450GB`、これは与えます`450`。 
3. 容量が最大の場合`200`、印刷`SMALL`。 ちょうど 200 GB がこのカテゴリに属する​​ため、比較は包括的である必要があります。 
4. それ以外の場合、容量が最大でも`500`、印刷`MEDIUM`。 このブランチに到達すると、キャパシティが 200 を超えていることがすでにわかっているため、結果の間隔は正確に次のようになります。`201`を通して`500`。 
5. どちらの比較も成功しなかった場合は、出力します。`LARGE`。 この時点で、容量は必然的に 500 より大きくなります。 

機能する理由: 削除後`GB`、すべての有効な容量は、正確に 1 つの整数で表されます。 3 つの可能な出力により、すべての容量が次のように分割されます。`x <= 200`、`200 < x <= 500`、 そして`x > 500`。 アルゴリズムはこれらの間隔を順番にチェックするため、正確に 1 つのブランチが数値容量と一致し、対応する分類が出力されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    capacity = int(s[:-2])

    if capacity <= 200:
        print("SMALL")
    elif capacity <= 500:
        print("MEDIUM")
    else:
        print("LARGE")

if __name__ == "__main__":
    solve()
```中の最初の行`solve`完全な入力を読み取り、末尾の改行を削除します。`strip()`。 表現`s[:-2]`正確に 2 文字を削除します`GB`、容量の小数表現のみが残ります。 

パイソンの`int`必要な数値変換を実行するため、次のような比較が行われます。`capacity <= 200`辞書編集的ではなく数値的です。 

最初の条件では、`<= 200`、包括的な下位カテゴリ境界と一致します。 2 番目の条件はチェックするだけで済みます`<= 500`なぜなら、以前の`if`すでに最大 200 のすべての値が除外されています。`else`したがって、 は 500 を超えるすべての値を表します。 

Python には整数オーバーフローの問題はなく、アルゴリズムは入力文字列と 1 つの整数のみを保存します。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()
    capacity = int(s[:-2])

    if capacity <= 200:
        print("SMALL")
    elif capacity <= 500:
        print("MEDIUM")
    else:
        print("LARGE")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("800GB\n") == "LARGE\n", "sample 1"
assert run("200GB\n") == "SMALL\n", "sample 2"

# minimum-size style case

assert run("501GB\n") == "LARGE\n", "501 must be LARGE"

 ## 特殊なケース

 最初の境界ケースはまさに`200GB`。 アルゴリズムが解析する`200`、小切手`200 <= 200`、すぐに印刷します`SMALL`。 を使用した実装`< 200`誤って次のカテゴリに進んでしまう可能性があります。 

2 番目の境界ケースはまさに`500GB`。 最初の比較は失敗します。`500`より大きい`200`, 一方、2 番目の比較は成功します。`500 <= 500`。 出力は`MEDIUM`。 使用する`< 500`ここでは誤って次のように分類されてしまいます`LARGE`。 

2 番目の境界のすぐ上の値、`501GB`、反対の道をたどります。`501 <= 200`は誤りであり、`501 <= 500`これも false なので、最後の分岐は出力されます。`LARGE`。 これにより、間にギャップがないことが確認されます。`MEDIUM`そして`LARGE`範囲。 

最後に、変換前にサフィックスを削除する必要があります。 のために`450GB`、`s[:-2]`生成する`450`、 どれの`int`次にアルゴリズムは、元のテキストについて推論するのではなく、その数値を数値しきい値と比較します。
