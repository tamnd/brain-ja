 ## 解決策
 ## 問題の理解

 すべての文字の直後に異なる文字がある場合、その文字列は多様であると呼ばれます。 言い換えれば、最後の位置を除くすべての位置で、その位置の文字は次の位置の文字と等しくない必要があります。 

入力にはスペースを含まない 1 つの文字列が含まれます。 必要な出力は次のとおりです`YES`文字列がどこでも条件を満たしている場合、そして`NO`隣接する等しい文字のペアが少なくとも 1 つ存在するとすぐに。 元の問題には 1 秒の時間制限と 256 MB のメモリ制限があります。 

このアルゴリズムの重要な制約は文字列の長さです。 このステートメントでは有用な小さい上限が指定されていないため、ソリューションは入力サイズに応じて線形にスケールする必要があります。 O(n²) メソッドは大きな文字列では実用的ではなくなりますが、O(n) スキャンでは各文字を一定の回数検査するだけで済みます。 

不注意な実装が失敗する可能性がある小さなケースがいくつかあります。 入力用`a`、正しい出力は次のとおりです。`YES`隣接するペアがまったくないためです。 次の文字が常に存在すると想定しているコードは、文字列の外側にアクセスできます。 

入力用`aa`、正しい出力は次のとおりです。`NO`。 最初の文字は 2 番目の文字と等しいため、これは可能な最小の反例です。 最後の隣接するペアを比較する前にループが誤って停止すると、誤って出力される可能性があります。`YES`。 

入力用`aba`、正しい出力は次のとおりです。`YES`。 最初のペアは`ab`そして2つ目は`ba`したがって、両方のペアには異なる文字が含まれています。 すべての文字がグローバルに異なるかどうかをチェックする実装では、隣接しない文字の繰り返しが許可されている場合でも、この文字列が誤って拒否されます。 

入力用`abb`、正しい出力は次のとおりです。`NO`。 最初のペアは有効ですが、最後のペアは`bb`そうではありません。 これにより、最後の 2 つの位置より前で始まるペアのみが検査される、off-by-one エラーが捕捉されます。 

## アプローチ

 直接的な総当たりアプローチにより、すべてのポジションのペアを検査できる可能性がある`(i, j)`そして、それが隣接するペアであるかどうかをテストします。`j = i + 1`。 このようなペアに等しい文字が含まれている場合、答えは次のようになります。`NO`; そうでなければ答えは`YES`。 無効な可能性のあるすべてのペアが検査されるため、これは正しいです。 

問題は、この方法ではすべてが検査されることです。`n(n-1)/2`たとえペアであっても、`n-1`そのうちのどれかが重要になる可能性があります。 最悪の場合、それはおおよそ`n²/2`ペアチェック。 長さ 100,000 の文字列の場合、これは約 4,999,950,000 チェックに相当し、1 秒の制限として妥当な値をはるかに超えています。 

条件の構造により、検索スペースがはるかに小さくなります。 文字列が多様であるかどうかは、隣接するペアにのみ依存するため、隣接しないペアを検査する理由はありません。 単純に左から右に歩いて、各文字をその直前の文字と比較することができます。 

最初の等しい隣接ペアは、答えが次であることを証明します。`NO`, そのため、スキャンはすぐに停止できます。 このようなペアが見つからずに文字列全体を走査した場合、必要な比較はすべて成功し、答えは次のようになります。`YES`。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります。 2 文字未満の文字列は、条件に違反する可能性のある隣接するペアが含まれていないため、自動的に多様になります。 
2. 2 番目の文字から開始して、その直前の文字と比較します。 これらは、まさにチェックする必要がある最初の隣接ペアです。 
3. 2 つの文字が等しい場合、出力します。`NO`そしてやめてください。 無効な隣接ペアが 1 つあれば、文字列全体が失格になります。 
4. 残りのすべての文字について同じ比較を続けます。 各反復では、新しい隣接するペアが 1 つだけチェックされるため、関連するすべてのペアが 1 回検査されます。 
5. 隣接する等しい文字が見つからないままループが終了した場合は、次のように出力します。`YES`。 この時点で、文字列内の隣接するすべてのペアに異なる文字が含まれていることが確認されます。 

### なぜ効果があるのか

 加工後の位置`i`、それ以前で終わるすべての隣接するペア`i`チェックされ、有効であることが判明しました。 この不変条件は最初のペアから始まり、各反復で次の隣接するペアをチェックするため保存されます。 等しいペアが存在する場合、そのペアを含む反復が出力されます。`NO`; そのような反復が存在しない場合、隣接するすべてのペアは異なります。これはまさに多様な文字列の定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for i in range(1, len(s)):
        if s[i] == s[i - 1]:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```ループはインデックスから始まります`1`なぜならインデックス`0`その前に文字はありません。 それぞれについて`i`、式`s[i] == s[i - 1]`隣接するペアを 1 つだけ調べます。 

同等であることが判明したらすぐに戻ることで、不必要な作業を回避できます。 また、1 つの無効なペアの存在によって完全に答えが決まるため、論理的に安全です。 

ループ条件`i < len(s)`Python によって自然に処理されます`range(1, len(s))`。 1 文字の文字列の場合、これは次のようになります。`range(1, 1)`これは空なので、プログラムは正しく出力します。`YES`。 

補助配列、セット、または度数テーブルは必要ありません。 この条件は隣接する文字に対してローカルであるため、一定の追加スペースで十分です。

## テストケース```python
import sys
import io

def solve():
    s = input().strip()

    for i in range(1, len(s)):
        if s[i] == s[i - 1]:
            print("NO")
            return

    print("YES")

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        from contextlib import redirect_stdout
        output = io.StringIO()
        with redirect_stdout(output):
            solve()
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
assert run("coderamsclub\n") == "YES\n", "sample 1"
assert run("helloworld\n") == "NO\n", "sample 2"

# Minimum-size input
assert run("a\n") == "YES\n", "single character has no adjacent pair"

# Smallest invalid string
assert run("aa\n") == "NO\n", "equal adjacent characters"

# Repeated but non-adjacent character is allowed
assert run("aba\n") == "YES\n", "non-adjacent repetition is valid"

# Invalid pair at the very end
assert run("abb\n") == "NO\n", "last adjacent pair must be checked"

# Large input, exercising linear behavior
large = ("ab" * 50000) + "\n"
assert run(large) == "YES\n", "large diverse string"

# Large input with one violation at the end
large_bad = ("ab" * 49999) + "abb\n"
assert run(large_bad) == "NO\n", "violation at the final pair"

 | --- | --- | --- |
 |`a`|`YES`| 最小サイズの文字列と空の比較ループ |
 |`aa`|`NO`| 可能な最小の無効な文字列 |
 |`aba`|`YES`| 隣接しない文字の繰り返しは許可されます。 
|`abb`|`NO`| 最後の隣接ペアをスキップしてはなりません。

 ## 特殊なケース

 1文字入力の場合`a`の場合、隣接するペアがないため、アルゴリズムは反復を実行しません。 決勝進出です`print("YES")`条件が空虚に満たされているため、これは正しいです。 

のために`aa`、ループは次で始まります`i = 1`。 比較する`s[1]`、つまり`a`、 と`s[0]`、 また`a`、すぐに印刷します`NO`。 これにより、最初の隣接違反の可能性が検出されたことが確認されます。 

のために`aba`、比較は次のとおりです`a`対`b`、 に続く`b`対`a`。 Both differ, so the scan finishes and prints`YES`。 繰り返された`a`位置 0 と 2 は隣接していないため、問題ありません。 

のために`abb`、最初の比較、`a`対`b`、成功します。 ２回目の比較ですが、`b`対`b`、失敗したため、アルゴリズムは次のように出力します。`NO`。 これは、最後の文字を含むペアが含まれるため、特にループの上限を検証します。 

次のような大きな交互文字列の場合、`abababab`、すべての比較は成功します。 このアルゴリズムは無関係なペアを構築したり検査したりすることはないため、実行時間は文字列の長さに比例します。 最後の文字が次のように変更された場合`bb`、アルゴリズムは引き続きその最終ペアをチェックしてレポートします`NO`、線形動作と正しい境界処理の両方を示します。
