 ## 解決策
 ## 問題の理解

 このタスクは、小文字の単語のすべての文字を個別に回転することです。 位置のキャラクターの場合`i`、入力は整数シフトを与えます`k[i]`。 正のシフトでは文字がアルファベット内で前方に移動し、負のシフトでは後方に移動します。 アルファベットは循環するので、過去に移動します`z`に続く`a`、そしてその前に移動します`a`に続く`z`。 

たとえば、回転させると、`a`による`5`与える`f`、回転しながら`a`による`-5`与える`v`。 シフトは次の間である必要はありません`-25`そして`25`、 それで`a`ずらして`30`と同じです`a`ずらして`4`、与える`e`。 

最初の入力行は単語そのものです。 2 行目には、文字ごとに 1 つの整数が含まれており、その整数は位置にあります。`i`そのキャラクターがどこまで移動するかを説明します。 出力は、すべての回転が適用された後の結果の単語です。 

この問題で使用できるステートメントでは、語長または回転値の数値上限が指定されていません。 制限時間は 1 秒、メモリ制限は 256 MB です。 明示的な境界が欠落しているかどうかに関係なく、目的のソリューションでは各文字を一定の回数だけ処理する必要があります。 単一のシフトが 26 よりはるかに大きくなる可能性があるため、シフトの大きさに比例するアルゴリズムは安全ではありません。アルファベットには 26 桁しかないため、すべてのシフトは最初に 26 を法として削減できます。 

最初のエッジ ケースは負のシフトです。 例えば、```
a
-5
```生成する```
v
```のみを使用した不用意な実装`ord(c) + k`また、直接文字に変換し直すと、小文字のアルファベット以外の文字が生成される可能性があります。 モジュロ演算は、負の値に対しても正しく機能する必要があります。 

2 番目のエッジ ケースは、完全なアルファベット 1 文字よりも大きなシフトです。 例えば、```
a
30
```生成する```
e
```なぜなら`30 mod 26 = 4`。 キャラクターを繰り返し 30 位置移動するのは不要であり、非常に大きな移動の場合は特に非効率的になります。 

3 番目のエッジ ケースは、シフトがアルファベットの境界に正確に到達した場合に発生します。 例えば、```
z
1
```生成する```
a
```文字の位置は、固定するのではなく、26 を法として計算する必要があります。`z`。 

4 番目のエッジ ケースは、アルファベットの先頭を横切る負のシフトです。 例えば、```
b
-3
```生成する```
y
```これにより、負の位置を別の減算分岐で処理しようとするが、ラップアラウンドを忘れる実装が捕捉されます。 

## アプローチ

 直接的な総当たりアプローチでは、文字通り一度に 1 つのキャラクターの動作が実行されます。 キャラクターの場合`c`そしてシフト`k`になるまで、アルファベットの位置を繰り返し増減できます。`|k|`といった動きが行われていました。 これは正しいです。なぜなら、個々の動きは循環アルファベットの周りの 1 ステップを正確に表しているからです。 

問題は、この作業が入力のサイズではなくシフトの大きさに依存することです。 単語に長さがある場合`N`そして最大の絶対シフトは`K`、最悪の場合は`O(NK)`個々の動き。 たとえば、`100,000`文字とすべてのシフトには大きさがあります`10^9`、これには最大で`10^14`キャラクターの動き。 これは、1 秒のソリューションが実行できるものをはるかに超えています。 

重要な観察は、26 文字のアルファベットの移動が周期的であるということです。 26 回前進すると、キャラクターはまさに開始位置に戻ります。 後進26回も同様です。 その結果、シフト`k`とまったく同じ効果があります`k mod 26`。 

シフトが 26 を法として削減されると、現在の文字を 0 から 25 までの数値に変換し、削減されたシフトを加算し、その結果を 26 を法として取得することができます。これにより、元のシフトがどれほど大きいか負であるかに関係なく、最終的なアルファベットの位置が即座に得られます。 

すべての動作がシミュレートされるため、総当り攻撃は機能しますが、シフトが大きい場合は失敗します。 アルファベットが 26 桁ごとに繰り返されるという観察により、任意の数の動きを 1 つのモジュラー算術演算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 単語とシフトの順序を読みます。 文字ごとに 1 つのシフトがあるため、インデックスの文字は`i`とペアにする必要があります`shift[i]`。 
2. 各文字について、次のコマンドを使用してゼロから始まるアルファベットの位置に変換します。`ord(c) - ord('a')`。 したがって`a`になる`0`、`b`になる`1`、 そして`z`になる`25`。 
3. 対応するシフト モジュロ 26 を減らします。26 桁でアルファベットの 1 つの完全なサイクルが形成されるため、剰余のみが問題になります。 
4. 減少したシフトを元のアルファベットの位置に追加し、結果のモジュロ 26 を取得します。これにより、結果を範囲内に保ちながら、正と負の両方の回転が処理されます。`0`を通して`25`。 
5. 次のコマンドを使用して、結果のアルファベットの位置を小文字に変換します。`chr(position + ord('a'))`。 
6. 結果の文字を出力リストに追加し、すべての文字を処理した後にリストに結合します。 リストを構築して結合すると、ますます大きくなる文字列を繰り返し構築することを回避できます。 

### なぜ効果があるのか

 すべての文字について、その位置は 26 を法として表されます。`k`その位置を次のように変更します`(position + k) mod 26`。 26 の倍数異なる 2 つのシフトは同じ位置を生成するため、`k`による`k mod 26`結果は変わりません。 このアルゴリズムは、この変換をすべての文字に独立して適用するため、すべての出力文字は、対応する回転に必要な文字になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    shifts = list(map(int, input().split()))

    base = ord('a')
    result = []

    for c, shift in zip(s, shifts):
        position = ord(c) - base
        position = (position + shift) % 26
        result.append(chr(position + base))

    print(''.join(result))

if __name__ == "__main__":
    solve()
```最初の行は、末尾の改行なしで単語を読み上げます。 2 行目は整数に分割され、各値を同じインデックスの文字と組み合わせることができます。 

ループは使用します`zip(s, shifts)`文字と回転の対応を明確にするため。 各ペアごとに、`ord(c) - ord('a')`文字を 0 から 25 までの数値に変更します。 

パイソンの`%`演算子は、ここで役立つ方法で負のオペランドを処理します。 例えば、`(-3) % 26`は`23`、つまり、位置にある文字`1`を表す`b`、になります`(1 - 3) % 26 = 24`を表します。`y`。 特別な負のシフト分岐は必要ありません。 

モジュロ演算はシフトを追加した後に適用されるため、結果の位置は常に 0 から 25 の間になります。Python では整数オーバーフローの懸念はなく、シフトが非常に大きい場合でも演算は定数のままです。

## テストケース

 元のステートメントは 1 つのサンプルを提供しているため、以下の最初のアサーションはそのサンプルを使用しています。 公開された声明では数値の最大値が明らかにされていないため、`N`、ストレスケースでは、`100000`公式の最大値であると主張するのではなく、代表的な大きな入力として文字数を指定します。```python
import sys
import io

def solve():
    input = sys.stdin.readline

    s = input().strip()
    shifts = list(map(int, input().split()))

    base = ord('a')
    result = []

    for c, shift in zip(s, shifts):
        position = (ord(c) - base + shift) % 26
        result.append(chr(position + base))

    print(''.join(result))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run(
    "agjnp\n"
    "7 -2 54 -80 25\n"
) == "hello\n", "sample 1"

# Minimum-size input
assert run(
    "a\n"
    "0\n"
) == "a\n", "minimum size"

# All-equal values
assert run(
    "aaaaa\n"
    "1 1 1 1 1\n"
) == "bbbbb\n", "all equal characters"

# Boundary wrapping in both directions
assert run(
    "azb\n"
    "1 -1 -3\n"
) == "byy\n", "alphabet boundaries"

# Very large positive and negative shifts
assert run(
    "abcde\n"
    "1000000000000 -1000000000000 26 52 -78\n"
) == "abcde\n", "large shifts"

# Large input stress case
n = 100000
large_input = "a" * n + "\n" + " ".join(["1"] * n) + "\n"
assert run(large_input) == "b" * n + "\n", "large input"

 ## 特殊なケース

 負のシフトの場合、```
a
-5
```文字の位置は次から始まります`0`。 アルゴリズムは計算します`(0 - 5) % 26 = 21`、位置 21 は`v`。 したがって、出力は次のようになります。`v`。 モジュラー演算はラップアラウンドを直接表すため、負の値に対する特別な処理は必要ありません。 

アルファベット 1 文字より大きいシフトの場合、```
a
30
```計算された位置は`(0 + 30) % 26 = 4`に対応します。`e`。 アルゴリズムは、このシフトに対して、次のシフトの場合と同じ一定量の作業を実行します。`4`。 

順方向ラップアラウンドの場合、```
z
1
```位置は`(25 + 1) % 26 = 0`、与える`a`。 モジュロ演算はまさに、結果をアルファベットの末尾から先頭に戻すものです。 

逆方向ラップアラウンドの場合、```
b
-3
```位置は`(1 - 3) % 26 = 24`、与える`y`。 中間位置が非負でなければならないと想定する手動で作成された実装では、この境界の場合を簡単に誤ってしまう可能性がありますが、モジュラー式はそれを直接処理します。 

サンプル自体は、これらのケースのいくつかを 1 つの入力に組み合わせています。 シフト`54`26 より大きい値をテストします。`-80`大きな負の値をテストし、結果の文字により、一致するインデックスの文字に各回転が適用されることが確認されます。
