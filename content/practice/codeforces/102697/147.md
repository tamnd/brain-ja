 ## 解決策
 ## 問題の理解

 凸多角形の頂点が境界順序で与えられます。 各頂点は整数の座標を持ち、多角形は任意の辺の長さと角度を持つことができます。 タスクは、多角形の正確な面積を計算し、それを 10 進数として出力することです。 このアーカイブされた問題に対して示されている公式の制約には、n の数値上限は示されていませんが、制限時間は 1 秒のみ、メモリ制限は 256 MB です。 ポリゴンには 3 つ以上の頂点があり、完全に垂直なポリゴン エッジはありません。 凸面性の保証は、すべての境界ターンが同じ方向を向いていることを意味するため、頂点は自己交差する多角形ではなく、1 つの単純な凸面領域を表します。 

明示された座標境界がないということは、正確な整数計算が利用できるときは常に浮動小数点ジオメトリを回避する必要があることを意味します。 整数座標の場合、多角形の 2 倍の面積は常に整数であるため、整数演算を使用してその量を計算し、答えをフォーマットする場合にのみ 2 で割ることができます。 Python 整数では、座標が大きい場合に固定幅言語で発生するオーバーフローの問題も解消されます。 

主なエッジケースは、答えが整数または半整数である可能性があるという事実によって引き起こされます。 例えば、```
40 02 02 10 1
```エリア 2 があるため、正しい出力は次のようになります。`2.0`。 常に答えを整数として扱う実装では、必要な 10 進表現が失われます。 

2 番目の例は、最初のサンプルのダイヤモンドです。```
40 55 00 -5-5 0
```その面積は 50 なので、正しい出力は次のようになります。`50.0`。 不注意な実装では、頂点が反時計回りではなく時計回りに指定された場合、負の符号付き領域が得られる可能性があります。 多角形はどちらの方向でも有効であるため、符号付き領域の絶対値が必要です。 

3 番目の便利なケースは、2 倍の面積が奇数である多角形です。```
56 64 32 11 53 7
```正しい出力は次のとおりです`15.5`。 整数の 2 倍の領域を使用して計算すると、丸めの問題が回避されます。 

## アプローチ

 直接的な三角測量アプローチは簡単に導き出すことができます。 1 つの頂点、たとえば P 0 を選択し、凸多角形を三角形 (P 0 、P 1 、P 2 )、(P 0 、P 2 、P 3 ) などに分割します。 多角形は凸状であるため、これらの三角形はすべて多角形の内側にあり、一緒に多角形を正確に覆います。 外積を使用して各三角形の面積を計算し、結果を加算できます。 

n 個の頂点を持つ多角形は正確に n−2 個の三角形を生成するため、このアプローチはすでに O(n) です。 n 角形の三角形分割の数はカタロニア数 C n−2 であり、指数関数的に増加するため、可能なすべての三角形分割を試みる真の強引な方法は、はるかに悪いものになります。 凸性によって特に単純な三角形分割が 1 つ無料で提供されるため、これらの可能性を探る理由はありません。 

同じジオメトリを表現するさらにきれいな方法があります。 三角形ABCの2倍の符号付き面積は、

 (x A y B ＋x B y C ＋x C y A )−(y A ｘ B ＋y B ｘ C ＋y C ｘ A )

 P 0 から多角形を三角形化すると、三角形の領域が追加されると、P 0 に関係するすべての項が伸縮します。 残るのはまさに

 i=0 ∑ n−1 (x i y i+1 −y i ｘ i+1 )、

 ここで、P n =P 0 です。 これが靴紐の式です。 

重要な洞察は、三角形分割では明示的に三角形を構築する必要がないということです。 署名された領域はエッジごとに蓄積できます。 これにより、三角形分割引数の正確な整数演算を維持しながら、実装がポリゴン上で 1 回のパスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 明示的なファンの三角形分割 | O(n) | O(n) | 承認済み |
 | 靴紐の公式 | O(n) | O(n) | 承認済み |

 靴紐の実装は、連続したエッジのみが必要であり、インデックス付けの間違いが発生する可能性が少ないため、推奨されます。 

## アルゴリズムのチュートリアル

 1. 多角形の周囲に表示される順序で n 個の頂点を読み取ります。 最後の頂点から最初の頂点までの最後のエッジを処理できるように、それらの座標を保存します。 
2. 整数アキュムレータを初期化する`twice_area`ゼロに。 外積によって自然にこの値が生成され、浮動小数点演算が回避されるため、符号付き領域の 2 倍を意図的に格納します。 
3. すべての頂点 P i =(x i ,y i ) について、j=(i+1)modn で P j を次の頂点とする。 追加

 x i y j −y i x j

 に`twice_area`。 これは 2 つの位置ベクトルの符号付き外積であり、エッジの符号付き面積寄与の 2 倍を表します。 
4. の絶対値を取得します。`twice_area`。 時計回りの入力では負の合計が得られ、反時計回りの入力では正の合計が得られますが、両方とも同じ幾何学的領域を表します。 
5. 印刷`abs(twice_area) / 2`。 2 倍の領域は整数であるため、結果は常に整数か末尾のいずれかになります。`.5`。 小数点以下 1 桁を付けて印刷すると、必要な 10 進数表現が得られます。 

### なぜ効果があるのか

 すべてのポリゴンの頂点を原点に接続して形成される三角形を考えてみましょう。 各境界エッジの外積により、対応する三角形の符号付き面積が求められます。 これらの符号付き三角形が多角形の外側で重なると、それらの寄与はペアでキャンセルされます。 キャンセルされていない唯一の署名領域は、ポリゴン自体です。 同様に、靴紐の合計は、選択した扇形の頂点がキャンセルされたすべての項を含む扇形三角形分割の符号付き領域の合計となります。 絶対値を取得すると、頂点が時計回りにリストされるか反時計回りにリストされるかに依存することがなくなります。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    points = [tuple(map(int, input().split())) for _ in range(n)]
    twice_area = 0
    for i in range(n):        x1, y1 = points[i]        x2, y2 = points[(i + 1) % n]        twice_area += x1 * y2 - y1 * x2
    twice_area = abs(twice_area)
    print(f"{twice_area / 2:.1f}")

if __name__ == "__main__":    solve()
```最初の部分は頂点を読み取り、保存します。 リスト全体を保持すると、ラップアラウンド エッジが単純になります。`(i + 1) % n`最後の頂点を頂点ゼロにマップし直します。 

メインループは靴紐の合計を直接実装します。 表現`x1 * y2 - y1 * x2`各エッジの絶対値に置き換えてはなりません。 個々のエッジには正または負の符号付き寄与があり、それらの符号によってキャンセルが機能します。 

絶対値は、完全な合計が計算された後にのみ適用されます。 これをループ内で適用すると、異なる量が計算され、通常は間違った面積が得られます。 

Python の整数は必要に応じて増加できるため、座標積が大きくてもアキュムレータがオーバーフローすることはありません。 値はフォーマット前にすでに正確であるため、最後の除算は安全です。 この問題は 10 進数を要求するので、`f"{twice_area / 2:.1f}"`両方を印刷します`50.0`そして`15.5`正しく。

## 特殊なケース

 最初のエッジ ケースは、最小の法定多角形です。 のために```
40 01 01 10 1
```相互貢献は`0`、`1`、`1`、 そして`0`、面積が 2 倍になります`2`そして出力`1.0`。 モジュロ式`(i + 1) % n`からの最終エッジを正しく含むものです`(0,1)`に戻る`(0,0)`。 

2 番目のエッジ ケースは、奇数の 2 倍の領域です。 のために```
40 03 02 10 1
```貢献は`0`、`3`、`2`、 そして`0`、したがって、2倍の面積は`5`。 アルゴリズムは出力します`5 / 2 = 2.5`、座標や部分領域を時期尚早に浮動小数点に変換するよりも、整数の 2 倍の領域を使用することが好ましい理由を示しています。 

3 番目のエッジ ケースは時計回りの入力です。 のために```
40 00 23 23 0
```靴紐の合計は`-12`たとえ幾何学的領域が正であっても。 アルゴリズムは計算します`abs(-12) = 12`そしてプリント`6.0`。 入力が反時計回りでなければならないと仮定した解決策では、ネガ領域が誤って印刷されてしまいます。 

最後の微妙なケースはクロージングエッジです。 実装がペアのみを処理する場合`(P_i,P_{i+1})`のために`i < n-1`、最後の頂点から最初の頂点までのエッジを黙って省略します。 上の単位正方形の場合、これらの 3 つの処理されたエッジのみが寄与します。`1`、与える`0.5`の代わりに`1.0`。 モジュロ インデックス付けには、欠落しているエッジが正確に含まれ、特殊な場合の分岐が回避されます。
