 ## 解決策
 ## 問題の理解

 すべての文字の直後にアルファベットの次の文字が続く場合、文字列はマジェスティックと呼ばれます。 アルファベットは円形なので、その後`z`来る`a`。 例えば、`cdefghij`すべての遷移が 1 文字ずつ進むため、雄大です。`acd`ないからではありません`a`続いて`c`の代わりに`b`。 同様に、`xyzab`からの遷移なので有効です`z`に`a`許可されています。 

入力は 1 つの文字列で構成されます`s`。 出力は次のようになります。`YES`すべての隣接するペアがこのルールに従っている場合、そして`NO`少なくとも 1 つの隣接するペアがそうでなくなるとすぐに。 

公式声明では、制限時間は 1 秒、メモリは 256 MB とされています。 文字列の最大長を個別に公開しないため、実行時間を文字数に比例させるのが安全な設計です。 単一パスは、隣接するペアごとに 1 つの定数時間チェックを実行します。これは、無効な文字遷移が入力内の任意の場所で発生する可能性があり、文字列全体を検査する必要がある場合があるため、最適です。 二次関数または指数関数の手法は、文字列が大きくなるにつれて不必要に高価になります。 

実装がサイレントに失敗する可能性のある小さなケースがいくつかあります。 次のような 1 文字の文字列`a`には隣接するペアがまったくないため、雄大であり、正しい出力は次のとおりです。`YES`。 検査するペアが常に存在すると想定しているコードは、それを誤って拒否する可能性があります。 

からのラップアラウンド`z`に`a`も重要なケースです。 入力用```
yzab
```正しい出力は`YES`。 次の文字の ASCII 値がちょうど 1 つ大きいことを要求するだけのチェックは拒否されます。`za`たとえ問題がアルファベットを円形として明示的に扱っていたとしてもです。 

繰り返される文字も拒否する必要があります。 入力用```
hellllo
```正しい出力は`NO`。 特に繰り返されるのは、`l`文字はアルファベット順に進むわけではないため、文字がアルファベット順に並んでいるかどうかだけをチェックするだけでは不十分です。 

## アプローチ

 完全に総当りの解釈では、同じ長さの可能なすべての文字列が生成され、各候補が堂々としているかどうかがテストされ、入力自体が見つかった時点で停止します。 一定の長さの文字列の場合`n`、 がある`26^n`考えられる小文字の文字列、および 1 つの候補のコストをチェックする`n - 1`隣接した比較。 最悪の場合、これはおよそ`26^n(n - 1)`性格チェック。 この方法は、考えられるすべての文字列を明示的に考慮するため正しいですが、指数関数的に増加するため、控えめな値であっても役に立たなくなります。`n`。 

ブルート フォース アプローチは、最終的には関心のあるプロパティを正確にチェックするため機能しますが、入力と関係のない文字列の考慮にほとんどすべての作業が費やされます。 重要な点は、雄大な文字列を検索する必要がまったくないということです。 入力はすでに固定されており、雄大であるかどうかは隣接する各ペアによって独立して決定されます。 

キャラクターの場合`c`、次の有効な文字は次の文字のみです。`(c + 1) mod 26`文字がゼロから始まるアルファベットの位置で表される場合。 したがって、入力を 1 回スキャンできます。 位置で`i`、比較します`s[i + 1]`必要な後継者と`s[i]`。 不一致は、文字列全体が荘厳ではないことを直ちに証明します。 スキャンが不一致なく最後まで到達した場合、隣接するすべての遷移は有効であり、文字列は堂々としたものになります。 

これにより、一定の追加スペースを使用しながら、文字列長の指数関数的な作業から線形な作業に変更されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単一の入力文字列を読み取り、末尾の改行を削除します。 
2. すべての隣接するペアを横断する`s[i]`、`s[i + 1]`。 まさにあります`n - 1`このような長さの文字列のペア`n`したがって、トランジションがスキップされることはありません。 
3. 現在の文字を 0 から始まるアルファベットの位置に変換します。 必要な後続関数は 1 つ後の位置にあり、からラップされます。`z`に戻る`a`。 
4. 必要な後継者と比較します。`s[i + 1]`。 異なる場合は印刷してください`NO`すぐに。 無効な遷移が 1 つあるだけで文字列全体が非雄大になるため、後の文字を調べても答えを変えることはできません。 
5. すべての隣接するペアがチェックに合格した場合、出力します。`YES`。 その時点で、完全な文字列内のすべての遷移が有効になります。 

### なぜ効果があるのか

 不変条件は、最初の処理後の`i`トランジション、最初のトランジション間のすべてのトランジション`i + 1`文字は有効です。 次のペアがチェックされるとき、そのペアが定義に違反する場合、アルゴリズムは正確に拒否します。 拒否しない場合、不変式は次のペアに拡張されます。 結局`n - 1`トランジションが処理され、隣接するすべてのペアが有効になります。これはまさに雄大な文字列の定義です。 したがって、アルゴリズムは有効な文字列を正確に受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for i in range(len(s) - 1):
        current = ord(s[i]) - ord('a')
        expected = (current + 1) % 26
        actual = ord(s[i + 1]) - ord('a')

        if actual != expected:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```このループは、アルゴリズムの隣接ペア スキャンに直接対応します。`ord(s[i]) - ord('a')`地図`a`を通して`z`に`0`を通して`25`。 1 を加算してモジュロ 26 を取得すると、次のような両方の通常の遷移が処理されます。`c -> d`、および特別な移行`z -> a`。 

範囲は次で終了します`len(s) - 1`最後の文字にはその後に文字がないためです。 使用する`range(len(s))`アクセスしようとします`s[i + 1]`いつ`i`は最終的なインデックスであり、範囲外エラーが発生します。 

ループが 0 回実行され、アルゴリズムが出力するため、単一文字の場合は自然に機能します。`YES`。 特別な分岐は必要ありません。 

Python の整数はオーバーフローせず、演算は次の値に対してのみ実行されます。`0`を通して`25`。 この解は最初の無効な遷移でも停止しますが、最悪の場合の複雑さは線形のままです。

## テストケース

 公式サンプルは、`cdefghij -> YES`、`tuvwxyzab -> YES`、 そして`hellllo -> NO`。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()

    for i in range(len(s) - 1):
        current = ord(s[i]) - ord('a')
        expected = (current + 1) % 26
        actual = ord(s[i + 1]) - ord('a')

        if actual != expected:
            print("NO")
            return

    print("YES")

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output
        try:
            solve()
        finally:
            sys.stdout = old_stdout
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input

# provided samples
assert run("cdefghij\n") == "YES\n", "sample 1"
assert run("tuvwxyzab\n") == "YES\n", "sample 2"
assert run("hellllo\n") == "NO\n", "sample 3"

# minimum-size input
assert run("a\n") == "YES\n", "single character has no invalid transition"

# all-equal values
assert run("aaaaa\n") == "NO\n", "equal consecutive characters are invalid"

# wraparound at z -> a
assert run("xyzab\n") == "YES\n", "alphabet must wrap around"

# invalid transition at the final pair
assert run("abcdefgq\n") == "NO\n", "invalid transition at the end"

# large input
large = "a" + "bcdefghijklmnopqrstuvwxyz" * 4000
assert run(large + "\n") == "NO\n", "large input with a boundary mismatch"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`|`YES`| 最小サイズの入力とゼロ隣接ペア |
 |`aaaaa`|`NO`| 繰り返される文字は拒否されます。 
|`xyzab`|`YES`| 正しい`z -> a`ラップアラウンド |
 |`abcdefgq`|`NO`| 最終比較で不一致が検出されました。 
| 構築された大きな文字列 |`NO`| リニア スキャンは大入力でも実用的です |

 ## 特殊なケース

 1文字入力`a`正確な入力によって処理されます`a\n`。 隣接するペアがないため、ループには反復がありません。 アルゴリズムは出力します`YES`これは定義から直接導き出されます。ルールに違反する遷移はありません。 

ラップアラウンドケース`xyzab`単純な文字値の比較では誤って処理されがちな遷移を実行します。 実行の関連部分は次のとおりです`x -> y`、`y -> z`、`z -> a`、 そして`a -> b`。 のために`z`、ゼロベースの値は`25`、 それで`(25 + 1) % 26`になる`0`に対応します。`a`。 すべてのペアが合格し、結果は次のようになります。`YES`。 

文字が繰り返される場合`aaaaa`最初の比較で失敗します。 現在のキャラクターは`a`、必要な後継者は`b`、実際の次の文字は`a`。 アルゴリズムはすぐに出力します`NO`文字列を誤ってアルファベット順に減少しないものとして扱うのではなく、

 ついに、`abcdefgq`実装が単にプレフィックスをチェックするだけではないことを示しています。 最初の 6 つの遷移は有効ですが、`g -> q`は無効です。 スキャンは最後のペアに到達し、不一致を検出して出力します。`NO`。 これが、最初の増加の実行を確認した後に停止するのではなく、すべての隣接するペアをチェックすることが必要な理由です。
