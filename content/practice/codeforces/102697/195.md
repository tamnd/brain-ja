 ## 解決策
 ## 問題の理解

 ダンジョンは (n \times n) 個のグリッドです。 ドットは歩行可能なセルを表し、`X`壁を表します。 プレーヤーは左上のセルから開始し、一度に 1 つのセルを 4 つの基本方向に移動できます。 タスクは、開始セルと同じ接続領域に属する歩行可能なセルの数を数えることです。 斜めの移動は許可されず、グリッドの外側の壁や位置を越えることはできません。 公式声明では、時間制限は 1 秒、メモリ制限は 256 MB とされていますが、(n) の数値の上限は規定されていません。 

数値境界が欠落していることの重要な結果は、アルゴリズムがグリッド上で繰り返し作業を実行するのではなく、セルの数に応じてスケールする必要があることです。 グリッド自体には (n^2) 個の文字が含まれているため、入力を読み取るだけでもすでに (O(n^2)) 時間がかかります。 したがって、(O(n^2)) トラバーサルが自然なターゲットになります。 (O(n^3)) または (O(n^4)) メソッドは、(n) が大きくなるにつれて、特に 1 秒の制限の下では問題が発生します。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 グリッドが単一の歩行可能なセルの場合、次のようになります。```
1
.
```答えは`1`。 移動後に到達したセルのみをカウントする実装では、誤って返される可能性があります。`0`。 

たとえば、開始セルが壁で囲まれている場合、```
3
.X.
XXX
...
```アクセスできる唯一のセルは開始セルであるため、答えは次のようになります。`1`。 トラバースでは、隣接するものを探す前に開始位置をカウントする必要があります。 

リージョンは、複数のルートを通じてそれ自体にアクセスすることもできます。 例えば、```
3
...
...
...
```答えがあります`9`。 セルを訪問済みとしてマークしない不注意な検索は、同じサイクルに繰り返し入り、セルを複数回カウントするか、終了しない可能性があります。 

最後に、ダンジョン内の他の場所の壁は、開始コンポーネントを分離しない限り、答えに影響を与えません。 のために```
3
..X
XXX
...
```答えは`2`左上のコンポーネントの 2 つのセルのみに到達できるためです。 グリッド内のすべてのドットをカウントすると、誤って返される`5`。 

## アプローチ

 直接的な総当たりアプローチでは、グリッド全体を繰り返しスキャンして、アクセス可能であることがすでにわかっているセルからアクセス可能なセルを見つけることができます。 たとえば、1 つの新しいセルを発見した後、すべての (n^2) 個の位置を検査して、そのセルによって別の位置が到達可能になるかどうかを確認できます。 最悪の場合、(n^2) 個の検出が存在する可能性があり、各検出により完全な (n^2) セル スキャンがトリガーされ、(n^4) 個のグリッド検査が行われる可能性があります。 (n=1000) の場合、これは最大 (10^{12}) 回の検査に相当し、1 秒のプログラムで処理できる量をはるかに超えています。 

ブルートフォース手法が機能するのは、到達可能性が推移的であるためです。セルが到達可能になると、隣接するすべての歩行可能なセルも同様に到達可能になります。 問題は、無関係なセルをスキャンすることでこの事実を繰り返し再発見すると、ほぼすべての計算が無駄になることです。 

有益な観察は、これがまさにグリッド上の接続コンポーネントの問題であるということです。 各歩行可能なセルはグラフの頂点であり、セルが辺を共有する場合、2 つの頂点の間にエッジが存在します。 ((0,0)) を含む連結成分のみが必要です。 幅優先検索または深さ優先検索では、到達可能なすべてのセルを 1 回訪問し、そのセルに隣接する可能性のある 4 つのセルを調べます。 各セルは 1 回処理されるため、総作業量はグリッド内のセルの数に比例します。 

訪問済みマーカーは必須です。 これがないと、隣接する 1 対の歩行可能セルが相互に検索を送り続ける可能性があります。 検出されたすべてのドットを次のように変更することで、別の訪問配列を回避できます。`X`。 これらのセルを再度処理する必要がないため、グリッドを変更すると、補助メモリの使用量を減らしながら同じ効果が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返しのフルグリッドスキャン | (O(n^4)) | (O(n^2)) | 遅すぎる |
 | BFS または DFS フラッド フィル | (O(n^2)) | (O(n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n \times n) ダンジョンを読み、開始セルを確認します。 それが壁の場合、歩行可能な開始コンポーネントがないため、答えは次のようになります。`0`。 元の問題では開始位置がダンジョン内のスペースとして記述されていますが、このケースを処理することで実装が堅牢になります。 
2. 開始セルをスタックに置き、すぐに訪問済みとしてマークします。 深さ優先の反復検索にはスタックを使用します。これにより、Python の再帰の深さの制限が回避されます。 
3. スタックが空でない間に、セルを 1 つ削除し、答えを 1 つ増やします。 スタックに配置されたすべてのセルが新しい到達可能なセルであることがすでに確認されているため、セルは削除時にカウントされます。 
4. 隣接する 4 つの位置を調べます。 各近傍について、まずその行と列がグリッド内にあることを確認します。 次に、それがドットであるかどうかを確認します。 そうであれば、次のように変更します`X`そしてそれをスタックにプッシュします。 

隣人を押す前にマークするのは意図的です。 すでに発見されている 2 つのセルが両方とも同じ新しいセルに触れるとします。 最初のものはそれをマークして押すので、2番目のものはそれを見るでしょう`X`そして再び押すことはできません。 
5. スタックが空になると、開始位置から到達可能なすべてのセルが訪問されたことになります。 処理されたセルの数を出力します。 

### なぜ効果があるのか

 不変条件は、現在スタックにあるすべてのセル、およびすでに処理されたすべてのセルが開始セルの接続されたコンポーネントに属し、すべてのセルが検出されるとすぐにマークされるということです。 アルゴリズムが処理されたセルから歩行可能な隣接セルに移動すると、その隣接セルは既存のパスによって開始コンポーネントに接続され、その後にこの 1 つの追加エッジが続くため、これを追加することは正しいことです。 逆に、到達可能なセルには最初からパスが必要です。 そのパスを一度に 1 エッジずつたどって、以前に発見されていない限り、検索は最終的にパス上のすべての歩行可能なセルを検出します。 したがって、スタックは最終的に、到達可能なすべてのセルを含めて 1 回だけ処理しますが、壁や切断された領域はカウントされません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [bytearray(input().strip(), "ascii") for _ in range(n)]

    if grid[0][0] != ord('.'):
        print(0)
        return

    stack = [(0, 0)]
    grid[0][0] = ord('X')
    answer = 0

    directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

    while stack:
        r, c = stack.pop()
        answer += 1

        for dr, dc in directions:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == ord('.'):
                grid[nr][nc] = ord('X')
                stack.append((nr, nc))

    print(answer)

if __name__ == "__main__":
    solve()
```グリッドは次のように保存されます`bytearray`行を追加して、検出されたセルを直接変更できるようにします。`.`に`X`。 これにより、2 番目 (n \times n) のブール訪問済み行列が不要になります。 

スタックには、処理を待機している座標が含まれています。 開始セルは、ポップされるときではなく、スタックに入る前にマークされます。これは、挿入時にマークすることでエントリの重複が防止されるためです。 

4 つの方向のペアは、下、上、右、左を表します。 境界条件には次のものを使用します。`0 <= nr < n`そして`0 <= nc < n`これは有効なグリッド座標を正確に記述し、負のインデックス付けと最後の行または列を超えるアクセスの両方を回避します。 

再帰がないため、非常に大きな接続コンポーネントであっても Python の再帰制限をオーバーフローすることはできません。 Python の整数にも任意の精度がありますが、答えは最大でも (n^2) なので、通常の整数のオーバーフローは問題になりません。 

輸入されたもの`deque`スタックには Python リストで十分であるため、この実装では実際には必要ありません。 スタックをリストとして保持すると効率的になります (O(1))`append`そして`pop`端からの操作。
