 ## 解決策
 ## 問題の理解

 入力は、次のようなシーケンスを含む 1 行です。`3 + 4 * 3 - 6 / 3 * 3`。 すべての数字は 1 つのトークンを占め、正確に 1 つの数字で構成され、連続するトークンの間にはスペースが 1 つだけ含まれます。 最初と最後のトークンは数字です。 

必要な優先順位ルールを適用した後、式で表される整数を出力する必要があります。 このステートメントは、最終的な答えが符号付き 32 ビット整数に収まり、それ自体が整数であることを保証します。 

ステートメント内のトークンの数に明示的な上限はありません。 そのため、実行時間が式の長さに応じて二次関数的に増大するアルゴリズムは不必要に危険になります。 1 秒の制限があるため、長さが線形である式を 1 回通過することを目指す必要があります。 すべての数値が 1 桁であるという事実により、トークン化が特に簡単になりますが、任意の長さのシーケンスを効率的に処理する必要があることに変わりはありません。 

誤って扱いやすいエッジケースが 2 つあります。 

考慮する：```
3 - 6 * 3
```正しい出力は次のとおりです。```
-15
```計算に遭遇したすべての操作を単純に実行する左から右への計算機`(3 - 6) * 3 = -9`、これは乗算の優先順位に違反します。 

より微妙なケースは次のとおりです。```
5 / 2 * 2
```正しい結果は次のとおりです。```
5
```除算と乗算は同じ優先順位を持っているため、左から右に評価する必要があります。`(5 / 2) * 2`。 中間値は`5/2`たとえ最終的な答えが整数であっても。 整数除算を使用した実装は次のようになります。`5 / 2`の中へ`2`そして間違って生産する`4`。 現在の乗算値を正確な分数として保持すると、この問題が回避されます。 

もう 1 つの便利な境界ケースは、数値を 1 つだけ含む式です。```
7
```その答えは単純です`7`。 演算子が常に存在すると想定しているコードでは、存在しないトークンに誤ってアクセスしたり、結果を誤って初期化したりする可能性があります。 

## アプローチ

 直接的なアプローチは、次の乗算または除算を繰り返し見つけて実行し、関係する 3 つのトークンをその結果に置き換えてから、加算と減算でも同じことを行うことです。 これは、優先規則に明示的に従うため、正しいです。 式に次のものが含まれる場合`k`ただし、残りの式の各検索では O(k) 個のトークンを検査でき、そのような検索が O(k) 回存在する可能性があります。 最悪の場合、これはおおよそのパフォーマンスを発揮します`k + (k - 1) + ... + 1 = k(k + 1)/2`トークン検査、これは O(k²) です。 

ブルートフォース手法は、優先順位の構造が単純であるため機能しますが、すでに理解されている式の部分を繰り返し再処理します。 重要な観察は、私たちが遭遇したとき、`+`または`-`、先行するすべての`*`そして`/`動作はすでに解決されています。 未解決の乗算/除算チェーンを 1 つの変数に保持し、加算または減算に達するたびにそのチェーン全体を最終合計にコミットできます。 

除算では端数の中間結果が作成される可能性があるため、詳細が 1 つ追加されています。 現在の乗算/除算チェーンは、整数除算や浮動小数点を使用するのではなく、正確な有理数として表す必要があります。 パイソンの`Fraction`まさにその表現を提供します。 最終結果は整数であることが保証されているため、分母が 1 であることを確認した後で分子を出力できます。 

結果として得られるアルゴリズムは式を 1 回スキャンし、各操作を即座に実行するため、トークンの再スキャンや再配置は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k²) | O(k) | 長い式には遅すぎる |
 | 最適 | O(k) | O(k) | 承認済み |

 ここ`k`演算子の数、つまり式内の Θ(k) トークンの数です。 

## アルゴリズムのチュートリアル

 1. 入力行をトークンに分割します。 入力には各トークンの間にスペースが 1 つだけ含まれているため、数値は偶数の位置に、演算子は奇数の位置に表示されます。 
2.初期化`total = 0`そして`term`最初の番号に。 変数`term`は、読み取られたがまだ最終的な答えに追加されていない完全な乗除算チェーンを表します。 
3. 残りの各演算子をその直後の数値とともに処理します。 オペレーターが`*`、乗算する`term`その数字で。 そうであれば`/`、 分ける`term`正確な有理表現を使用してその数値によって計算されます。 
4. オペレータが`+`または`-`、現在のものを追加します`term`に`total`、適切な記号を付けて、次の番号から新しい用語を開始します。 コミットできる`term`この時点では、それに属するすべての乗算または除算がすでに処理されているためです。 
5. 最後のトークンが処理された後、最後のトークンを追加します。`term`に`total`。 フォローはありません`+`または`-`この操作をトリガーするには演算子を使用するため、明示的に実行する必要があります。 
6. 結果の整数を出力します。 この問題では、最終的な数学的結果が整数であることが保証されているため、正確な分数の分母は 1 になります。 

不変条件とは、加算または減算を処理する前に、`term`は正確に現在の最大乗除算セグメントの値です。`total`は、完了したすべての加算/減算セグメントの正確な値です。 乗算と除算は即座に解決され、加算/減算は完了した項を結合するだけであるため、アルゴリズムはあらゆる点で必要な優先順位を維持します。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline
from fractions import Fraction

def solve():    tokens = input().split()
    total = Fraction(0)    term = Fraction(int(tokens[0]))
    i = 1    while i < len(tokens):        op = tokens[i]        value = int(tokens[i + 1])
        if op == '*':            term *= value        elif op == '/':            term /= value        elif op == '+':            total += term            term = Fraction(value)        else:  # op == '-'            total += term            term = Fraction(-value)
        i += 2
    total += term
    print(total.numerator // total.denominator)

if __name__ == "__main__":
```最初の数字は初期化されます`term`それよりも`total`乗算と除算は、その値が加算または減算に参加する前に完了する必要があるためです。 

のために`*`そして`/`、現在の用語はすぐに変更されます。 これにより、当然のことながら、同じ優先順位の操作に対して左から右への評価が行われます。 例えば、`8 / 4 * 3`になる`2 * 3`、 それから`6`と解釈するのではなく、`8 / (4 * 3)`。 

のために`+`、完成した用語が追加されます`total`、次の番号から新しい学期が始まります。 のために`-`、新しい用語が否定的に始まることを除いて、同じ考え方が使用されます。 これにより、別個の符号変数が必要なくなります。`Fraction`実装の微妙な部分です。 パイソンの`//`通常の算術除算ではない整数のフロア除算を実行します。`/`整数では浮動小数点値が生成されます。 のような表現`5 / 2 * 2`どちらも適切ではない理由を示します。`Fraction`店`5/2`正確に、次に乗算します`2`正確に返します`5`。 

入力は有効な式を保証するため、ゼロによる除算は発生しません。 Python の整数には任意の精度もあるため、公式の最終結果が 32 ビットに収まることが保証されている場合でも、オーバーフローの問題は発生しません。

 ## 特殊なケース

 次のような単一の数値式```
7
```から始まる`term = 7`、ループには処理する演算子がなく、最後の`total += term`生成する`7`。 このアルゴリズムは、演算子が存在することを決して想定しません。 

優先順位として、次のことを考慮してください。```
3 - 6 * 3
```アルゴリズムは次から始まります`term = 3`。 減算はコミットします`3`に`total`そして始まります`term = -6`。 乗算によりその項は次のように変化します。`-18`。 最後に、`total + term`は`3 - 18 = -15`。 乗算は減算後に評価されることはないため、必要な優先順位は維持されます。 

優先順位が等しい操作については、次のことを考慮してください。```
5 / 2 * 2
```最初の項は`5`。 除算は正確な分数に変更します`5/2`、乗算すると次のように変わります。`5`。 最終的な出力は次のとおりです`5`。 整数除算の実装では、代わりに次の結果が得られます。`2`除算後、誤って出力される`4`。 

最後に、次のような負の乗算/除算の連鎖を考えてみましょう。```
1 - 5 / 2 * 2 + 4
```減算後、`term`は`-5`。 ディビジョンプロデュース`-5/2`、乗算により次の結果が得られます。`-5`、次の追加でその項がコミットされ、次のようになります。`1 - 5 = -4`。 次の学期から始まります`4`最終的な答えを出します`0`。 正確な有理表現は、言語固有の整数の除算規則に依存せずに、負の中間値を処理します。
