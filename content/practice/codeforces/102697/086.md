 ## 解決策
 ## 問題の理解

 タスクは、長方形の整数配列が両方の種類のミラー対称性を持っているかどうかを判断することです。 水平対称とは、ある行が反対側のエッジから同じ距離にある行と一致する必要があることを意味します。 垂直対称とは、列が反対側のエッジから同じ距離にある列と一致する必要があることを意味します。 行または列の数が奇数の場合、中央の行または中央の列は対応する軸上に直接位置するため、その軸の別の行または列と比較する必要はありません。 公式声明で求められているのは、`True`両方の対称性が成立する場合のみ。 

配列に`R`行と`C`コラム、あります`R * C`値を読み取る必要があるため、どのソリューションでも少なくとも`O(RC)`入力を検査するだけの時間です。 公開された声明では、明示的な数値の上限は示されていません。`R`そして`C`; 1 秒の時間制限と 256 MB のメモリ制限が与えられます。 これは、セル数が線形よりも遅いアルゴリズムを考慮する有効な理由がないことを意味します。 セルの二次検索、つまり行全体と列全体を繰り返し比較すると、行列が大きくなるにつれてコストが不必要に高くなります。 アン`O(RC)`スキャンは自然なターゲットです。 

最初のエッジケースは単一セルです。 入力用```
1 1
7
```正しい出力は`True`。 軸のどちらの側にも、中心と一致しないセルはありません。 すべての行と列に個別のミラー パートナーがあることを期待する不用意な実装は、それを誤って拒否する可能性があります。 

2 番目のエッジ ケースは奇数サイズの行列で、その中央の行は水平方向に無関係ですが、垂直方向の対称性をチェックする必要があります。 例えば、```
3 3
1 0 1
2 3 4
1 0 1
```上部と下部の行は一致していますが、中央の行は垂直方向に対称ではありません。`2 != 4`したがって、正しい出力は次のようになります。`False`。 横軸上にあるため中央行全体を単純に無視する実装では、誤って印刷されます。`True`。 

同じ区別が中央の列にも当てはまります。 例えば、```
3 3
1 2 1
0 3 0
1 4 1
```は垂直方向の対称性を持っていますが、中央の列の上部と下部のセルが異なるため、水平方向の対称性は失われ、答えは次のようになります。`False`。 中央の列は垂直反射の場合のみ無視され、水平反射の場合は無視されません。 

最後に、長方形配列を正方行列として扱ってはなりません。 例えば、```
2 3
1 2 1
1 2 1
```は両方の軸で対称であり、次の結果が得られるはずです`True`。 行数と列数には個別のミラー インデックスがあるため、行数を使用して両方の反射座標を計算すると、インデックス付けエラーが発生しやすくなります。 

## アプローチ

 直接的なアプローチは、行列全体を読み取り、すべてのセルに対して`(i, j)`、水平方向に反射された位置と比較します。`(R - 1 - i, j)`とその垂直方向の反射位置`(i, C - 1 - j)`。 比較が失敗した場合、答えはすぐに得られます`False`; すべての比較が成功した場合、答えは次のようになります。`True`。 この 2 つの等式は、必要な水平対称と垂直対称の定義と正確に一致するため、これは正しいです。 

この直接バージョンが両方の条件をすべてチェックする場合`R * C`セルの値比較のワーストケース数は正確に`2RC`。 このステートメントは、このアプローチを漸近的に無効にする限界を与えていません。`O(RC)`行列自体に以下が含まれるため、最適です。`RC`価値観。 したがって、総当たりスキャンは間違っていませんし、根本的に遅すぎるわけでもありません。 この弱点は、セルとそのミラーの比較もミラー セルにアクセスしたときに繰り返されるため、同じ対称性の比較を 2 回実行することです。 

有益な観察は、各反射がセルをペアにするということです。 水平対称の場合、最後の行から最初の行への逆比較にはまったく同じ情報が含まれるため、最初の行と最後の行を比較するだけで十分です。 同じことが行のすべてのペアに当てはまります。 したがって、最初のものだけが必要です`R // 2`水平チェック用の行。 同様に最初だけ`C // 2`列は垂直チェックに必要です。 中央の行または列は、その次元が奇数の場合、これらのループから自然に消えます。 

最適化されたスキャンが実行される`floor(R / 2) * C + R * floor(C / 2)`最悪の場合の比較。 まだあります`O(RC)`複雑ではありますが、冗長な作業が回避され、どのペアが実際にチェックする必要があるかを直接表現します。 さらに重要なことは、特殊なケースを使用せずに奇数の次元を自然に処理することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(RC) | O(RC) | 受け入れられますが、冗長です |
 | 最適 | O(RC) | O(RC) | 承認済み |

 反射されたセルが入力内のどこにでも存在する可能性があるため、行列を保存する必要があります。そのため、漸近最適解では依然として次のものが使用されます。`O(RC)`簡単な実装によるメモリ。 

## アルゴリズムのチュートリアル

 1.読む`R`そして`C`を保存してから、`R x C`マトリックス。 セルとその反射セルの両方にランダムにアクセスする必要があるため、行列を維持することですべての比較が一定時間になります。 
2. 行のみの水平対称性をチェックします。`i`どこ`0 <= i < R // 2`。 比較する`a[i][j]`と`a[R - 1 - i][j]`すべての列に対して`j`。 これらはまさにリフレクションによってペアになった 2 つの行であり、すべてのペアが 1 回ずつアクセスされます。 
3. 列のみの垂直対称性をチェックする`j`どこ`0 <= j < C // 2`。 比較する`a[i][j]`と`a[i][C - 1 - j]`行ごとに`i`。 繰り返しますが、反映されたすべての列ペアは 1 回だけアクセスされます。 
4. 印刷`False`比較が異なる場合はすぐに。 1 つの不一致ペアが必要な対称性を破壊するのに十分であるため、継続しても時間の無駄になるだけです。 
5. 両方のループが不一致なく終了した場合は、次のように出力します。`True`。 すべての行ペアが水平方向に一致し、すべての列ペアが垂直方向に一致します。これはまさに必要な条件です。 

これが機能する理由: 水平ループ中の不変条件は、これまでに処理されたすべての行ペアが垂直位置の保存下で同一であるということです。 ループは個別の行のすべてのペアを 1 回だけカバーするため、終了時には行列全体が水平対称になります。 垂直ループは、列のすべてのペアに対して同様のプロパティを確立します。 中央の行と列は、それ自体に反映されるため、対応するループには含まれません。 その結果、両方のループが終了すると、必要なすべてのリフレクションの等価性が維持されるため、アルゴリズムはリターンできなくなります。`True`非対称行列の場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(R)]

    # Horizontal symmetry.
    # Only one row from each mirrored pair needs to be checked.
    for i in range(R // 2):
        ri = R - 1 - i
        for j in range(C):
            if a[i][j] != a[ri][j]:
                print("False")
                return

    # Vertical symmetry.
    # Only one column from each mirrored pair needs to be checked.
    for j in range(C // 2):
        cj = C - 1 - j
        for i in range(R):
            if a[i][j] != a[i][cj]:
                print("False")
                return

    print("True")

if __name__ == "__main__":
    solve()
```最初のループは、ウォークスルーの水平部分を実装します。`range(R // 2)`次の場合に中央の行を意図的に除外します。`R`奇数です。 行数が偶数の場合、ミラー化されたすべてのペアの最初の行が正確にカバーされます。 

反映された行は`R - 1 - i`Python はゼロベースのインデックスを使用するためです。 たとえば、5 行の場合、行`0`行に反映されます`4`、 行`1`行に反映されます`3`、行`2`自分自身に反映します。 ループが手前で止まってしまうので、`i == 2`、自己反省に比較する必要はありません。 

2 番目のループも同じ考え方で、行と列が交換されます。`C - 1 - j`反映された列が得られますが、`range(C // 2)`場合に中央の列をチェックすることを回避します。`C`奇数です。 

この関数は、最初の不一致の直後に戻ります。 Python では整数オーバーフローの懸念はなく、実装ではインデックス計算以外の演算は実行されません。 出力文字列も、必要な大文字と小文字の区別に正確に一致します。`True`そして`False`。
