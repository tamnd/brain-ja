 ## 解決策
 ## 問題の理解

 ツリーはちょうど 1 つの枝から始まります。 現在 (b) の分岐があるとします。 翌日、木は (n \cdot b) 個の新しい枝を作成するため、合計は次のようになります。 

[
 b+n b=(n+1)b。 
】

 同じ値の (n) が毎日使用されます (n>1)。 1 つのブランチから開始して、(k) 日後にブランチの数は結果的に次のようになります。 

[
 (n+1)^k。 
】

 タスクは、指定された数値 (x) が発生する可能性のある最小の有効な (n) を見つけることです。 公式声明では、(x<10000)、制限時間は 1 秒、メモリは 256 MB とされています。 

重要な変換は、(a=n+1) を定義することです。 (n>1) なので、(a\ge3) が必要で、ある正の整数 (k) に対して (x=a^k) となる最小の (a\ge3) を探します。 したがって、必要な答えは (a-1) です。 

境界が小さい (x<10000) ということは、単純な検索でも十分に高速であることを意味します。 それでも、この構造により、より明確な境界が得られます。つまり、(x=a^k) と (k\ge2) の場合、(a^2\le x)、つまり (a\le\sqrt{x}) になります。 (\sqrt{x}) までのベースをテストするだけで済み、その後は 1 日のケースを個別に処理します。 

分離する価値のある 2 つの境界ケースがあります。 (x=1) の場合、成長が起こる前にツリーにはすでに 1 つの分岐があるため、許容される最小値は (n=2) になります。 たとえば、入力`1`出力があります`2`。 少なくとも 1 つの成長ステップを実行することを要求するソリューションは、このケースを誤って拒否することになります。 

(x=2) にも仕様上の問題があります。 最初の成長によって 1 つの枝が (n+1\ge3) 個の枝に変化するため、いいえ (n>1) で 2 つの枝が生成されることはありません。 したがって、入力`2`公開されたルールに基づく有効な出力はありません。 このステートメントでは、(x) が正であることのみを示しているため、この値を暗黙的に除外する必要があります。 規定された要件を満たす出力が存在しないため、公式テスト データは必然的にそのような入力を回避する必要があります。 

よくある実装上の間違いは、基数 (2) を許可することです。 入力用`64`、基数 (2) は (n=1) を示唆しますが、(n=1) は禁止されています。 正しい答えは、`3`、(64=4^3) なので。 ベース (3) から検索を開始すると、このエラーが回避されます。 

もう一つの間違いは、マス目を確認しただけで止めてしまう事です。 入力用`27`、答えは`2`、(27=3^3) なので。 (x) が整数の平方根を持つかどうかだけをチェックすると、このケースは見逃されます。 

## アプローチ

 最も直接的な総当たりアプローチは、(2) から上のすべての可能な (n) を試すことです。 候補 (n) について、分岐の総数は (1) から開始して (x) に達するか (x) を超えるまで繰り返し (n+1) 倍されます。 (n) を昇順にテストしたため、(x) に到達した場合、その候補が答えになります。 

固定 (n) の成長プロセスは完全に決定されているため、このアプローチは正しいです。 順序は

 [
 1,\ n+1,\ (n+1)^2,\ (n+1)^3,\ldots
 】

 したがって、シミュレーションすると、(x) が発生する可能性があるかどうかが正確にわかります。 

実際の制約 (x<10000) の下では、このブルート フォースはすでに十分に高速です。 最大の関連値 (x=9999) の場合、すべての候補をテストするには、最大 9997 個の候補値 (n) が必要です。 候補のシミュレーション中に使用されるすべての乗算をカウントすると、最悪の場合は約 20,124 回の乗算になります。 1 秒の制限としては非常に小さいです。 したがって、公開された制約に対してこのアプローチを「遅すぎる」と呼ぶのは不正確です。 その弱点は、(x) に応じて線形にスケールされる一方で、数学的構造により、はるかに少ない作業しか実行できないことです。 

有用な観察は、自明ではないべき乗 (x=a^k) ((k\ge2) は (a^2\le x) を持たなければならないということです。 したがって、その底は (\sqrt{x}) を超えることはできません。 テストできるのは (a=3,4,\ldots,\lfloor\sqrt{x}\rfloor) だけです。 各基数について、乗算を繰り返すことで、その基数の累乗が (x) に等しいかどうかが決まります。 塩基を昇順にテストするため、最初に成功した塩基が自動的に可能な最小の塩基となり、最小値 (n) が得られます。 

(\sqrt{x}) までの基数が機能しない場合、(x) は少なくとも 2 の指数と少なくとも 3 の基数を持つべき乗ではありません。 残された唯一の可能性は、ちょうど 1 日後に (x) に到達すること、つまり (x=n+1) であるため、答えは (x-1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(x\log x)) | (O(1)) | (x<10000) として受け入れられますが、必要以上に広くなります。 
| 最適 | (O(\sqrt{x}\log x)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (x) を読み取ります。 (x=1) の場合、(2) を出力します。これは、拡張する必要がなく、(2) が (n) の最小許容値であるためです。 
2. (a=n+1) を指数関数的増加のベースとして扱います。 (n>1) なので、(3) から (a) のテストを開始します。 
3. (a^2\le x) の間、すべての塩基 (a) をテストします。 各塩基について、次から始めます。`value = a`(x) より小さい間は (a) を繰り返し乗算します。 
4. 繰り返された乗算が正確に (x) に達すると、一部の (k\ge2) に対して (x=a^k) になります。 塩基は最小から最大の順にテストされるため、これが最小の有効な塩基になります。 出力 (a-1)。 
5. ベースが成功しなかった場合は、(x-1) を出力します。 (n=x-1) を選択すると、((x-1)\cdot1) 個の新しい枝が作成され、(x) 個の枝が離れるため、これは 1 日の成長 (1\rightarrow x) を表します。 

検索が (\sqrt{x}) で停止できる理由は、少なくとも 2 の指数を持つすべての累乗には、2 乗が最大 (x) である底があるためです。 より大きな基数は指数 1 の (x) にのみ到達でき、その場合は (n=x-1) によってすでに処理されています。 

### なぜ効果があるのか

 固定 (n) の場合、(k) 日後の分岐の数は正確に ((n+1)^k) になります。 したがって、有効な (n) を見つけることは、(x=a^k) の基底 (a=n+1\ge3) を見つけることと同じです。 

このアルゴリズムは、指数 (k\ge2) を持つ可能性のあるすべての基数をチェックします。これは、そのような基数が (a\le\sqrt{x}) を満たす必要があるためです。 塩基は昇順にチェックされるため、最初の正確な検出力により可能な限り最小の値 (a) が得られ、したがって可能な限り最小の値 (n=a-1) が得られます。 存在しない場合、すべての有効な表現は指数 1 を使用し、(n=x-1) を与える必要があります。 これは、すべての有効な成長シーケンスをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x = int(input())

    if x == 1:
        print(2)
        return

    base = 3

    while base * base <= x:
        value = base

        while value < x:
            value *= base

        if value == x:
            print(base - 1)
            return

        base += 1

    print(x - 1)

if __name__ == "__main__":
    solve()
```最初の特殊なケースは、初期状態を直接処理します。 (x=1) の場合、ツリーを成長させる必要はなく、許容される最小値 (n) は (2) です。 

メインループは次の処理を行います。`base`(n) としてではなく、(n+1) として。 この区別は、解決策における中心的な代数ステップです。 から始まる`base = 3`条件 (n>1) を強制します。 

各拠点ごとに、`value`ベース自体から始まります。 同じ基数を繰り返し乗算すると、(a^2,a^3,\ldots) が生成されます。 ループはすぐに停止します`value >= x`, そのため、ターゲットを通過した後に不必要な乗算を実行することはありません。 

条件`base * base <= x`浮動小数点の平方根を回避し、正確な整数比較を保証します。 Python の整数にも任意の精度がありますが、指定された境界によりオーバーフローは無関係になります。 

正確な検出力が見つかったら、`base - 1`は必須 (n) です。 ループ全体が終了すると、自明でない電力表現は存在しないため、1 日の構築で次の結果が得られます。`x - 1`。 

## 実用的な例

 ### サンプル 1

 (x=36) の場合、可能な最小の底は (3) ですが、(3) の累乗は (3,9,27,81) であるため、(36) に等しいものはありません。 次のベースは (4) で、そのパワーは (4,16,64) ですが、やはり失敗しました。 基数 (5) は (5,25,125) を与えます。 基数 (6) から (6,36) が得られるため、答えは (6-1=5) となります。

 (x=66) の場合、(3) から (\sqrt{66}) までのすべての塩基は正確に (66) を生成できません。

この例では、フォールバックのケースを確認します。 (n=x-1) を選択すれば、すべての (x\ge3) に 1 日で到達できるため、数値が到達可能であるために完全な累乗である必要はありません。

## 特殊なケース

 のために`1`、特殊な場合には実行が即座に停止します。 ツリーはすでに 1 本の枝から始まっているため、成長する必要はありません。 (n) は 1 より大きくなければならないため、最小の有効な選択肢は次のとおりです。`2`、出力を生成します`2`。 

のために`3`の場合、(\sqrt3<3) であるため、アルゴリズムは自明でない検出力を見つけられません。 フォールバックに到達し、出力します (3-1=2)。 実際、(n=2) の場合、初日は (2\cdot1=2) 個の枝を追加し、ツリーを 1 つの枝から 3 つにします。 

のために`16`、アルゴリズムテストベース`3`、その累乗は (3,9,27) であり、その後底になります。`4`、その力には (16) が含まれます。 印刷します`4-1=3`。 (n=1) は禁止されているため、(16=2^4) であってもこれは正しいです。 

のために`27`、ベース`3`が最初にテストされます。 値は次のようになります`3`、`9`、 そして`27`したがって、アルゴリズムはすぐに出力します`2`。 これにより、平方根だけをチェックして高次の累乗を忘れてしまうというよくある間違いを防ぐことができます。 

のために`36`、最初に成功した塩基は`6`, なぜなら、(36=6^2)だからです。 答えは`5`。 より大きなベース、例えば`36`1 日の成長でも機能しますが、最小ではありません。 

のために`66`、からのベースはありません`3`(\sqrt{66}) を介して正確に到達します`66`。 したがって、アルゴリズムは 1 日表現 (66=(66)^1) を使用し、これは (n=65) に対応します。 This matches the second sample.

 のために`9999`、ループは考えられるすべての非自明な基底をチェックしますが、正確に生成されるものはありません`9999`。 フォールバックにより得られるのは、`9998`。 この実装では浮動小数点演算が使用されないため、平方根の境界によって丸め誤差が生じることはありません。
