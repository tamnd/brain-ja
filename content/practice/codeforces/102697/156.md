 ## 解決策
 ## 問題の理解

 ユニークな名前の住宅を集めました。 各家には、番地と番地という 2 つの整数座標があります。 家の 1 つが基準住宅として指定され、それに最も近いもう 1 つの家の名前を印刷する必要があります。 

距離ルールは珍しいですが、単純です。 2 つの家が同じ通りにある場合、それらの距離は家番号間の絶対的な差になります。 それらが異なる通りにある場合、それらの距離は、家番号間の絶対差と番地間の絶対差の積になります。 公式声明はこの定義を確認し、必要な入力および出力形式を示しています。 

たとえば、参照住宅が通り 3、住宅番号 7 にある場合、通り 3、住宅番号 7 の別の家は距離 3 になります。通り 5、住宅番号 9 にある家の距離は ( |9-7| \times |5-3| = 4 ) となります。 

公開された声明では (n) の上限が明示的に示されていませんが、コンテストのページでは 1 秒の時間制限と 256 MB のメモリ制限が指定されています。 完全な順序付けではなく、最も近い家が 1 つだけ必要なため、ソートよりも (O(n)) スキャンの方が適しており、通常のコンテストサイズの入力であれば十分に高速です。 (n) が大きい場合、二次アルゴリズムは不要になりますが、(O(n \log n)) ソートも問題が要求する以上の作業を行います。 

不用意に実装すると問題が発生するケースがいくつかあります。 1つ目はリファレンスハウスそのものです。 例えば：```
2
a 1 10
b 1 20
a
```正しい出力は次のとおりです`b`。 基準住宅はそれ自体からの距離がゼロですが、答えの候補ではありません。 スキャンでは明示的にスキャンをスキップする必要があります。 

2 番目のケースは、同じ通りにある 2 つの家です。 例えば：```
3
a 1 10
b 1 13
c 2 11
a
```正しい出力は次のとおりです`b`、その距離は (3) であるため、`c`には距離 ( |11-10| \times |2-1| = 1) があるため、実際の正しい出力は次のようになります。`c`。 この例では、特別な距離公式を適用する代わりに 2 つの座標を独立して扱うというよくある間違いを明らかにしています。 正しい出力は次のとおりです`c`。 

3 番目のケースは、家番号の差は小さいが、通りの差が大きい、異なる通りにある 2 軒の家です。 例えば：```
3
a 1 10
b 10 11
c 2 20
a
```までの距離`b`は (1 \times 9 = 9) であり、一方、`c`は (10 \times 1 = 10) であるため、正しい出力は次のようになります。`b`。 番地の違いのみを比較するソリューションでは、誤った選択が発生します。`b`間違った理由で、道路の違いだけを比較するソリューションでは、他のケースでは間違った選択をする可能性があります。 

この声明ではタイブレークルールは指定されていない。 自然な実装では、複数の家が同じ最小距離を持つ場合、最初に見つかった家が維持されます。 したがって、コンテストのデータは、あいまいな関係を避けるか、元の審査設定に従って適切な最も近いハウスを受け入れる必要があります。 

## アプローチ

 最も直接的な強引なアイデアは、基準の家から他のすべての家までの距離を計算し、それらの距離をすべて保存し、並べ替えて、最小の距離に関連付けられた家を取得することです。 すべての候補が考慮され、並べ替えでは最小距離が最初に設定されるため、これは正しいです。 ただし、問題が単一の最小値のみを求めている場合でも、(n) 個の候補を並べ替えるには (O(n \log n)) 時間がかかります。 

ブルート フォース アプローチでは、ソート ステップがあるため、最悪の場合、大まかに (n \log_2 n) 個の比較が実行されます。 (n=100000) の場合、距離計算と Python のオーバーヘッドを考慮しないと、約 170 万回の比較になります。 1 秒の制限時間により、不必要な並べ替えを避けることが賢明な選択になります。 

重要な点は、家を並べ替える必要がないということです。 どちらの距離が最小であるかを知る必要があるだけです。 ランニングミニマムで十分です。 住宅を読んだりスキャンしたりしながら、各候補者の距離を計算し、これまでに確認された最良の距離と比較します。 新しい距離が小さい場合は、現在の答えを置き換えます。 

これにより、問題は標準的な線形最小探索に変わります。 基準住宅から各候補までの距離は一定時間で独立して計算できるため、距離式には特別なデータ構造は必要ありません。 

すべての家が評価されるため、総当り攻撃は機能しますが、最小限のものだけが必要であるという事実を利用できません。 最小値を段階的に維持できることが観察されたため、並べ替えステップを完全に削除できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ソートによるブルートフォース | O(n log n) | O(n) | 多くの設定で受け入れられますが、不要です |
 | 最適な 1 パスの最小値 | O(n) | 入力を保存するための O(n)、または参照を見つけた後の追加の O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての家を読み取り、その名前、番地、番地を保存します。 距離を計算する前に参照住宅の座標が必要なので、レコードを保存しておくと、入力を読み取った後にそれを識別できるようになります。 
2. 参照住宅の名前を読み取り、番地と住宅番号を取得します。 これにより、あらゆる距離を測定するための固定点が得られます。 
3. 最適な候補を存在しないものとして初期化し、最適な距離を無限大として初期化します。 Infinity は、最初の有効な候補が自動的に現在の回答になるため便利です。 
4. 基準住宅を除くすべての家を訪問します。 参照ハウスは、それ自体からの距離がゼロであり、要求された他のハウスになることはできないため、除外する必要があります。 
5. 候補者が参照家と同じ通りにある場合、家番号間の絶対差として距離を計算します。 それ以外の場合は、絶対的な番地の差と絶対的な番地の差を乗算して距離を計算します。 
6. 計算された距離を現在の最小値と比較します。 新しい距離が小さくなるたびに、現在の答えを置き換えます。 将来のすべての候補がこれまでに見つかった最適な距離と比較されるため、最適な候補のみを保持するだけで十分です。 
7. 最終候補者の名前を出力します。 すべての非参照住宅が検査されたため、保存された候補はすべての有効な選択肢の中で最小距離を持ちます。 

### なぜ効果があるのか

住宅の接頭辞を処理した後、保存された候補は、これまでに処理された住宅の中で最も近い非参照住宅になります。 最初は候補がないため、不変式は空です。 新しい家が処理されると、その距離は問題の定義に従って正確に計算されます。 現在の最良値よりも遠い場合、不変条件は変更されません。 近い場合、現在の候補を置き換えることで、保存された家がすべての処理された家の中で最も近くなります。 最終的なハウスが処理された後、不変条件はすべての非参照ハウスをカバーするため、保存された名前は入力全体の中で最も近いハウスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    houses = {}

    for _ in range(n):
        name, street, number = input().split()
        houses[name] = (int(street), int(number))

    target = input().strip()
    target_street, target_number = houses[target]

    best_name = None
    best_distance = float("inf")

    for name, (street, number) in houses.items():
        if name == target:
            continue

        house_diff = abs(number - target_number)

        if street == target_street:
            distance = house_diff
        else:
            street_diff = abs(street - target_street)
            distance = house_diff * street_diff

        if distance < best_distance:
            best_distance = distance
            best_name = name

    print(best_name)

if __name__ == "__main__":
    solve()
```辞書は、それぞれの一意の家の名前をその 2 つの座標にマッピングします。 名前の一意性により、参照ハウスの検索が直接的に行われます。 

ターゲット名を読み取った後、コードはその番地と番地を 1 回抽出します。 後続の距離計算ではすべて、これら 2 つの固定値を使用できます。 

の`target`チェックは必須です。 それがなければ、ターゲットは即座に距離をゼロにし、常に勝利することになります。 

同じ番地の場合は、問題ではその距離が家番号の違いのみとして定義されているため、別個に処理されます。 通りが異なると、両方の座標の差が増加します。`abs`距離は、候補が数値的にターゲットの前後にあるかどうかに依存しないため、必須です。 

比較には、`<`それよりも`<=`。 距離が等しい場合、最初に見つかった候補が維持されます。 この声明にはタイブレークのルールが示されていないため、後の等距離ハウスを優先する根拠はありません。 

Python の整数はオーバーフローしないため、2 つの座標の差の乗算に特別な処理は必要ありません。
