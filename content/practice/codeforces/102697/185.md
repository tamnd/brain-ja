 ## 問題の理解

 因数分解で現れるすべての素因数が 2 または 3 の場合、その数値は「pleasing」と呼ばれます。同様に、数値は次の形式でなければなりません。 

[
 2^a3^b
 】

 いくつかの非負の整数 (a) と (b) の場合。 値 1 には素因数がまったくないため、値 1 も適格となります。 

たとえば、18 は (18=2\cdot3^2) であるため快適ですが、35 は (35=5\cdot7) ため快適ではありません。 タスクは、指定された正の整数にこのプロパティがあるかどうかを判断し、出力するだけです。`YES`または`NO`。 元の問題には、(n\le1000) の単一の整数入力、1 秒の時間制限、および 256 MB のメモリ制限があります。 

1000 という制限により、単純な試行分割ソリューションでも簡単に十分な速度になります。 考えられるすべての約数をチェックするループは最大で約 1000 回の反復を実行するため、高度な整数理論は必要ありません。 それでも、定義に直接従う、よりクリーンな解決策があります。つまり、2 のすべての因数と 3 のすべての因数を繰り返し削除します。1 より大きいものが残っている場合、その余りには禁止された素因数が含まれます。 

実装が静かに失敗する可能性がある小さなケースがいくつかあります。 入力用`1`、正しい出力は次のとおりです。`YES`1 には素因数がないためです。 2 または 3 の少なくとも 1 つの因数を見つけることを要求する解決策は、誤って拒否することになります。 

入力用`6`、正しい出力は次のとおりです。`YES`、(6=2\cdot3) なので。 数値が 2 と 3 のどちらかで割り切れるかどうかをチェックする不注意な解決策は、両方の因数が許可されている場合でも、その数値を拒否する可能性があります。 

入力用`12`、正しい出力は次のとおりです。`YES`, なぜなら、(12=2^2\cdot3)だからです。 要素がなくなるまで分割を繰り返す必要があります。 1 回だけ 2 で割ると 6 が残り、6 には望ましくない係数が含まれていると誤って結論付けられる可能性があります。 

入力用`1000`、正しい出力は次のとおりです。`NO`。 2 の因数を 3 つ削除すると 125 が得られますが、125 には素因数 5 が含まれています。2 で割り切れるかどうかだけをチェックし、割り切れる可能性が見つかったら停止するという解決策では、数値が誤って受け入れられてしまいます。 

## アプローチ

 最も直接的なブルートフォース手法は、(n) に 2 または 3 以外の素約数があるかどうかをテストすることです。2 から (n) までのすべての整数 (d) を試し、(d) が (n) を割るかどうかを判断し、(d) が (n) を割るかどうかを判断し、割れる場合、(d) が素数で 2 や 3 とは異なるかどうかを判断できます。そのような約数が存在する場合、答えは次のようになります。`NO`; それ以外の場合はそうです`YES`。 これは正しいです。すべての合成数には素約数があるため、禁止された素因数は最終的に発見される必要があります。 

(n=1000) の場合、このブルート フォースには最大 999 個の除数チェックと、それらの除数に使用される素数処理が必要です。 これはすでに問題なく制限内にあるため、この問題を実際に受け入れるために最適化する必要はありません。 

より有益な観察は、素因数を 1 つずつ発見する必要がないということです。 定義では、すべての要素は 2 または 3 でなければならないとされているため、これらの要素を正確に削除して、何が生き残るかを検査できます。 (n) から始めて、可能な限り 2 で除算を繰り返し、次に可能な限り 3 で除算を繰り返します。 最終値が 1 の場合、因数分解全体は 2 と 3 で構成されています。 最終値が 1 より大きい場合、残りの値には 2 または 3 以外の素因数が少なくとも 1 つ含まれている必要があります。 

ブルートフォースは、禁止された要素を明示的に検索するため機能しますが、許可された要素の特別な構造は使用できません。 許可される素数は 2 と 3 だけであるという観察により、これらの因数を直接取り除き、作業を対数的に多くの除算に減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 正の整数 (n) を読み取ります。 禁止された因数の存在のみが重要であるため、完全な素因数分解を構築するのではなく、数値自体を保持します。 
2. (n) が 2 で割り切れる場合は、それを 2 で割ります。このような割り算を行うたびに、許容される素因数が 1 つ削除され、元の数値が適切かどうかを変更することはできません。 
3. (n) が 3 で割り切れる場合、それを 3 で割ります。この操作を繰り返すと、残りの許容される 3 の因数がすべて削除されます。 
4. 残量を確認します。 正確に 1 の場合、元の数値のすべての素因数は 2 または 3 であるため、次のように出力します。`YES`。 そうしないと、2 または 3 以外の係数が残るので、出力します。`NO`。 

これが機能する理由: 最初の 2 つのループの後、現在の値には 2 の因数も 3 の因数もありません。その前に実行されたすべての除算では、許可された因数のみが削除されます。 残りの値が 1 より大きい場合、その素因数分解には 2 または 3 以外の素数が含まれている必要があり、元の数値が美しくなくなります。 残りの値が 1 の場合、元の数値を構成するのに 2 と 3 の因数以外は何も必要ないため、この数値は満足のいくものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

while n % 2 == 0:
    n //= 2

while n % 3 == 0:
    n //= 3

print("YES" if n == 1 else "NO")
```最初のループは、素因数 2 のすべての出現を削除します。`while`ループではなく、`if`16 のような数値には 2 の因数が 4 つ含まれるためです。 

2 番目のループは 3 に対して同じことを行います。素因数の乗算は可換であるため、これら 2 つのループの順序は結果に影響しません。そのため、2 と 3 のすべての因数はどちらの順序でも削除できます。 

1 との最後の比較が重要な境界条件です。 1 に達すると、禁止されたものは何も残らないことを意味します。 特に入力は、`1`どちらのループにも入らず、すぐに受け入れられます。 

ここでは、Python 整数にはオーバーフローの問題はなく、入力範囲は 1000 のみです。実装には配列や補助データ構造も必要ありません。

 残りの値は 1 なので、出力は次のようになります。`YES`。 これは、要因が複数回発生する可能性があり、それらをすべて除去する必要があることを示しています。

 入力用`35`、2でも3でも数値を割ることはできません。 

| ステップ | (n) 前 | 操作 | (n) 後 |
 | --- | --- | --- | --- |
 | 1 | 35 | 2 で割り切れない | 35 |

 出力は`NO`。 残りの 35 には素因数 5 と 7 が含まれており、どちらも禁止されています。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    while n % 2 == 0:
        n //= 2

    while n % 3 == 0:
        n //= 3

    print("YES" if n == 1 else "NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert run("18\n") == "YES\n", "sample 1"
assert run("35\n") == "NO\n", "sample 2"

assert run("1\n") == "YES\n", "1 has no prime factors"
assert run("2\n") == "YES\n", "single allowed factor"
assert run("72\n") == "YES\n", "72 = 2^3 * 3^2"
assert run("1000\n") == "NO\n", "1000 = 2^3 * 5^3"
assert run("999\n") == "NO\n", "999 has a forbidden factor"
assert run("648\n") == "YES\n", "648 = 2^3 * 3^4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`YES`| 最小値と空の素因数分解 |
 |`2`|`YES`| 許容される素因数が 1 つだけの境界ケース |
 |`72`|`YES`| 2 と 3 の両方の因子の繰り返し |
 |`1000`|`NO`| 最大入力と除算後に残る禁止係数 |
 |`999`|`NO`| 許容される素数でも割り切れない数値 |

 ## 特殊なケース

 入力`1`は最も重要な特殊なケースです。 アルゴリズムは (n=1) から始まるため、両方の割り算ループはスキップされます。 最終値はすでに 1 になっており、`YES`。 1 には素因数がないため、禁止された素数が含まれないため、これは数学的定義と一致します。 

入力用`6`、実行は`6 -> 3`係数 2 を削除した後、続いて`3 -> 1`係数 3 を削除すると、出力は次のようになります。`YES`。 これにより、両方の許可された素数を持つことが完全に有効であることが確認されます。 

入力用`12`、実行は`12 -> 6 -> 3 -> 1`。 最初のループは 2 の係数を両方とも削除し、その後 2 番目のループは 3 の係数を削除します。結果は次のようになります。`YES`、各割り算テストを一度だけ実行するのではなく、繰り返し実行する必要がある理由を示しています。 

入力用`1000`、係数 2 ループによって生成される`1000 -> 500 -> 250 -> 125`。 125 は 3 で割り切れないため、係数 3 ループは変更を加えません。125 は 1 より大きいため、アルゴリズムは次のように出力します。`NO`。 生き残った値には禁止された素因数 5 が含まれているため、拒否は正しいです。 

入力用`35`、どちらのループも値を変更しません。 1 より大きい 35 のままなので、出力は次のようになります。`NO`。 これは、禁止された素因数が最初から存在する最も単純なケースです。
