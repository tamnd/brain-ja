 ## 解決策
 ## 問題の理解

 2 つの大文字の文字列が与えられます。 最初の文字列は視力検査表に実際に表示されるテキストであり、2 番目の文字列は読み取られたテキストです。 文字列の長さは同じであるため、最初の文字列のすべての位置は 2 番目の文字列の 1 つの位置に正確に対応します。 

いくつかの文字のペアは、視覚的に類似していると宣言されています。 類似性は推移的です:`D`に似ています`P`、 そして`P`に似ています`G`、 それから`D`、`P`、 そして`G`すべて同じ類似性グループに属します。 文字は、その位置にある 2 つの文字が同一である場合に正しいものとして分類されます。 それらが異なっていても同じ類似グループに属している場合、そのキャラクターは近いものとみなされます。 そうでなければ、それは完全に間違っています。 

入力により、正しい文字列、解釈された文字列、その後にペアそのものが後に続く類似関係の数が得られます。 出力には、正しい、近い、間違ったという順序で 3 つのカウントが含まれます。 

ここで最も有用な制約は、大きな数値制限ではなく、すべての文字が大文字の英字であるという事実です。 したがって、類似度グラフには 26 個の頂点しかありません。 文字列が非常に長くても、グラフ自体は小さいです。 したがって、ソリューションでは、グラフを繰り返し検索するのではなく、関係の読み取りと 2 つの文字列のスキャンに本質的に直線的な時間を費やす必要があります。 

この問題のページでは、1 秒の時間制限と 256 MB のメモリ制限が指定されていますが、文字列の長さや類似性ペアの数の明示的な上限は公開されていません。 これらの値は、グラフ検索を繰り返すことが望ましくないほど大きくなる可能性があるため、自然なターゲットは次のとおりです。`O(|s| + n)`時間。 

最初のエッジケースは同一の文字です。 考慮する：```
A
A
1
A B
```出力は次のとおりです。```
1 0 0
```明示的な類似関係によって、これが厳密に一致することはありません。 正確に正しく読み取られた文字は正しいものとしてカウントされるため、平等性が優先されます。 

2 番目のエッジケースは推移的な類似性です。 考慮する：```
A
C
2
A B
B C
```出力は次のとおりです。```
0 1 0
```かどうかだけをチェックする不用意な実装`A C`入力ペアの間に直接出現すると、その文字は間違っていると報告されます。 この問題は、接続されたコンポーネント全体にわたる類似性を定義するため、パスは`A -> B -> C`で十分です。 

3 番目のエッジケースは、比較される文字とは何の関係もない類似関係です。```
A
C
1
B C
```出力は次のとおりです。```
0 0 1
```という事実`C`似ている`B`似せません`A`。 グラフを通じて 2 つの特定の文字間の類似性を確立する必要があります。 

## アプローチ

 直接的なアプローチは、頂点が 26 文字であり、エッジが宣言された類似性ペアであるグラフを構築することです。 2 つの文字列内のすべての位置について、対応する文字を比較します。 それらが等しい場合、正しいカウンタをインクリメントします。 それ以外の場合は、正しい文字からグラフ検索を実行し、解釈された文字に到達できるかどうかを確認できます。 到達可能性は類似性の推移的な定義と正確に一致するため、この方法は正しいです。 

位置ごとに独立して検索を実行する場合の問題は、同じ小さなグラフが何度も検索されることです。 文字列に長さがある場合`L`そしてそこにあります`n`入力ペアでは、1 つの BFS または DFS が最大 26 個の頂点を検査でき、`2n`隣接エントリ。 すべてのキャラクターに対してこれを繰り返すと、最大で`L(26 + 2n)`頂点とエッジの検査。 入力自体はグラフを一度記述するだけなので、この作業を繰り返す必要はありません。 

重要な観察は、推移的な類似性がまさに無向グラフにおける接続性であるということです。 グラフには 26 文字しか含まれていないため、連結成分は 1 回で計算できます。 ここでは、DSU または Union-find とも呼ばれる素セット共用体構造が特に自然です。 入力で 2 つの文字が似ていると示されるたびに、それらのコンポーネントがマージされます。 すべてのペアが処理された後、DSU の代表値が等しい場合、2 つの異なる文字は正確に類似します。 

ブルート フォースは、グラフ内のパスを明示的にたどることで各類似性の質問に答えるため機能しますが、文字列内に多くの位置がある場合は失敗します。 すべての位置が同じ 26 文字のグラフをクエリしているという観察により、グラフを 1 回前処理することができます。 後続の各比較は、ほぼ一定時間の DSU 操作のペアになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(L(26 + n))`|`O(26 + n)`| 大きいものには遅すぎる`L`そして`n`|
 | 最適 |`O(n α(26) + L α(26))`|`O(26 + n)`| 承認済み |

 ここ`L`は文字列の長さであり、`α`は逆アッカーマン関数であり、実際の入力サイズに対して事実上一定です。 

## アルゴリズムのチュートリアル

 1. 26 個の大文字ごとに 1 つの個別のコンポーネントを含む DSU を作成します。 最初は、類似している 2 つの異なる文字は知られていません。 
2. すべての類似性ペアを読み取り、対応する 2 つの文字を結合します。 いくつかのペアが中間文字を介して接続されている場合、結合を繰り返すと、接続されたコンポーネント全体が自然にマージされます。 たとえば、加工`A B`その後`B C`作る`A`、`B`、 そして`C`代表者を1名共有します。 
3. 2 つの文字列を位置ごとにスキャンします。 2 つの文字が等しい場合は、正しいカウンタを直ちにインクリメントします。 同一の文字は単に近いだけではなく正しいものとして分類されるため、このチェックは類似性チェックの前に行う必要があります。 
4. さまざまな手紙について、DSU の代表者を比較してください。 等しい代表は、文字が同じ類似性コンポーネントにあることを意味するため、近接カウンタをインクリメントします。 異なる代表は、それらの間に類似関係の連鎖がないことを意味するため、間違ったカウンタをインクリメントします。 
5. 3 つのカウンタを必要な順序で印刷します。 

不変条件は、すべての類似性ペアが処理された後、それらを接続する宣言された類似性関係のチェーンが存在する場合に限り、2 つの文字が同じ DSU 代表を持つということです。 すべてのユニオンは、宣言された関係を 1 つだけ追加するため、無関係なコンポーネントをマージすることはできません。 逆に、関係のすべてのパスはエッジごとに処理されるため、そのパス上のすべての文字は最終的に同じ代表を受け取ります。 次に、各文字列の位置が、正しい、近い、または間違っているという定義に従って分類されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    s = input().strip()
    t = input().strip()
    n = int(input())

    dsu = DSU(26)

    for _ in range(n):
        a, b = input().split()
        x = ord(a) - ord('A')
        y = ord(b) - ord('A')
        dsu.union(x, y)

    correct = 0
    close = 0
    wrong = 0

    for a, b in zip(s, t):
        if a == b:
            correct += 1
        else:
            x = ord(a) - ord('A')
            y = ord(b) - ord('A')

            if dsu.find(x) == dsu.find(y):
                close += 1
            else:
                wrong += 1

    print(correct, close, wrong)

if __name__ == "__main__":
    solve()
```の`DSU`クラスは文字ごとに 1 つの親を保存します。`find`コンポーネントの代表を返し、パス圧縮を実行します。`union`2 つのコンポーネントを組み合わせて、小さいコンポーネントを大きいコンポーネントの下に取り付けます。 

変換`ord(ch) - ord('A')`地図`A`を通して`Z`整数に`0`を通して`25`。 これにより、グラフ表現がコンパクトに保たれ、辞書や文字列ベースのグラフ ノードが回避されます。 

類似性ペアは、文字列が検査される前に処理されます。 順序が重要なのは、次のようなペアであるためです。`A B`、その後に続きます`B C`、比較時に 3 つの文字がすべてマージされている必要があります。`A`対`C`作られています。 

比較ループは明示的にテストします`a == b`初め。 この分岐がないと、同じ DSU コンポーネント内に文字が偶然存在する同一のペアが、誤って近いものとしてカウントされてしまいます。 

Python の整数は任意の精度を持ち、すべてのカウンターは最大でも文字列の長さであるため、オーバーフローの心配はありません。

## テストケース

 公式声明では 2 つのサンプルが提供されています。 以下のカスタム ケースでは、1 文字入力、推移的類似性、すべて等しい文字、および大規模な文字列ストレス テストもカバーしています。```python
import sys
import io

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    input = sys.stdin.readline

    s = input().strip()
    t = input().strip()
    n = int(input())

    dsu = DSU(26)

    for _ in range(n):
        a, b = input().split()
        dsu.union(ord(a) - 65, ord(b) - 65)

    correct = close = wrong = 0

    for a, b in zip(s, t):
        if a == b:
            correct += 1
        elif dsu.find(ord(a) - 65) == dsu.find(ord(b) - 65):
            close += 1
        else:
            wrong += 1

    return f"{correct} {close} {wrong}\n"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 同一の文字の場合、入力```
A
A
1
A B
```から始まる`A == A`、したがってアルゴリズムは増加します`correct`DSU を決してチェックしません。 結果は`1 0 0`。 これにより、同等性がより弱い形式の類似性としてカウントされるのを防ぎます。 

推移的な類似性については、次のことを考慮してください。```
A
C
2
A B
B C
```最初の結合はコンポーネントを作成します`{A, B}`。 2 番目のユニオンがマージされる`C`そのコンポーネントに入力して、`{A, B, C}`。 文字列を比較すると、`A != C`、ただし、両方の文字の代表者が同じであるため、結果は次のようになります。`0 1 0`。 

無関係な文字については、次の点を考慮してください。```
A
C
1
B C
```複数の文字を含む唯一のコンポーネントは、`{B, C}`。`A`孤立したままなので、`find(A) != find(C)`。 結果は`0 0 1`。 

最後の境界ケースは、すべての位置で推移的な検索が必要な長い文字列です。 100000部で`A`正しい文字列では、100000 コピー`C`解釈された文字列と関係`A B`そして`B C`、どのポジションも近いです。 DSU は一度構築されると、各ポジションは定常時間のコンポーネント チェックのみを実行し、`0 100000 0`。 これはまさに、文字ごとに個別のグラフ検索を実行するよりも、26 文字のグラフを前処理する方が望ましい状況です。
