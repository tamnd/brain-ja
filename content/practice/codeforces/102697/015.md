 ## 解決策
 # 問題の理解

 この問題は、各路線が訪問する駅の順序付きリストとして与えられる地下鉄ネットワークについて説明します。 最初の駅は空港で、目標はホテルです。 乗客は現在の駅を含む路線に沿って乗車できます。 地下鉄の路線から別の路線への乗り換えは別の路線に乗車したものとしてカウントされますが、同じ路線に乗り続けるとカウントは増えません。 課題は、空港からホテルまでの移動に必要なさまざまな地下鉄路線の最小数を見つけることです。 

コストは通過する駅の数ではないため、入力を確認する便利な方法は、線路で接続された駅のグラフとして見ることではありません。 ある路線で長距離乗車しても、その路線で短時間乗車した場合と同じ料金がかかります。 答えを変える唯一の出来事は、新しい地下鉄路線に乗り入れることです。 

個別の駅の数は十分に少ないため、地下鉄ネットワーク上のグラフ検索が実用的です。 数十万の駅や路線がある場合は、より慎重な前処理が必要になりますが、ここでは入力内の駅の出現総数が制限されているため、路線と乗り換え駅の間に明示的な関係を構築することが可能です。 乗客は路線内の中間駅を気にしないため、考えられるすべての駅経路にわたる二次探索は依然として無駄になります。 

難しいケースは、複数の路線が同じ駅を共有している場合や、出発地と目的地が同じ路線上にある場合です。 例えば：```
3
Airport A Hotel
A B C
C Hotel
```正しい答えは、`1`、最初の路線がすでに必要な 2 つの駅を接続しているためです。 路線変更の代わりに訪問駅をカウントするような不注意な解決策では、より大きな答えが得られるでしょう。 

もう 1 つのケースは、すぐに転送が必要な場合です。```
2
Airport X
X Hotel
```正しい答えは、`2`。 乗客はまず空港のある路線に乗り、次に駅 X でホテルのある路線に乗り換える必要があります。 

3 番目のケースは、同じ駅を経由する複数の乗り換えです。```
3
Airport A
A B
B Hotel
```答えは、`3`。 駅をメインのグラフとして扱い、路線変更ごとにコストがかかることを忘れると、答えが過小評価される可能性があります。 

## アプローチ

 簡単なアプローチは、考えられる駅の経路を検索することです。 空港から出発して、現在の地下鉄路線で到達可能なすべての駅を繰り返し試し、使用された路線の数を追跡することができます。 これは正しいです。考えられるすべての行程が考慮されますが、多くの同等のパスが探索されます。 同じ路線上である駅から別の駅に乗車すると、多くの不要な状態が発生します。 

重要な観察は、乗客がその路線に留まる限り、路線内の正確な駅は問題ではないということです。 意味のある状態は現在の地下鉄路線です。 現在 X 線を使用していることがわかっていれば、別の線路に料金を支払うことなく、X 線が乗り入れるすべての駅にすぐに到着できます。 X 線のどの駅からでも、1 本の追加料金を支払えば、その駅を通過する 1 つおきの路線に乗り換えることができます。 

これにより、問題は地下鉄路線の最短経路の問題に変換されます。 各ノードは地下鉄の路線を表します。 2 つの線分が少なくとも 1 つの測点を共有する場合、2 つの線分の間にエッジが存在します。 ある路線から別の路線に移動すると、移動にちょうど 1 つの路線が追加されるため、エッジ コストは 1 です。 開始ノードは空港を含むすべての路線で、初期コストは 1 です。 次に、幅優先検索により、ホテルを含む路線に到達するために必要な最小限の路線数が検索されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステーションパス上のブルートフォース | 選択肢の数は指数関数的 | O(状態の数) | 遅すぎる |
 | 地下鉄路線上の BFS | O(総ステーション発生数 + 乗り換え) | O(路線数+駅数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての地下鉄路線を読み取り、それに属する駅を保存します。 同時に、各駅からその駅を訪れる地下鉄路線のリストまでのマッピングを作成します。 乗り換えは駅で行われるため、この逆マッピングは重要な構造です。 
2. 空港を含むすべての地下鉄路線を検索します。 これらのラインを距離 1 の BFS キューに入れます。 距離 1 から始まると、地下鉄のどの路線を利用してもすでに 1 路線を利用したものとしてカウントされるという事実を表します。 
3. 地下鉄の列から並びます。 この路線のすべての駅について、その駅を通過する他のすべての地下鉄路線を検査します。 そのようなラインが訪問されていない場合は、そのラインに 1 つ大きい距離を割り当ててキューに追加します。 
4. 訪問路線にホテルの駅が含まれる場合、保存される距離は必要な地下鉄路線の最小数になります。 

なぜ効果があるのか:

 BFS は、使用される地下鉄路線の数が多い順に州を調査します。 路線内での移動には追加料金はかからないため、路線上のすべての駅がまとめて処理されます。 考えられるすべての転送は、2 つの線の間のエッジによって表されます。 BFS は重み付けされていないグラフで最短経路を見つけるため、初めてホテルの行に到達した時点で、可能な最小限の行数が見つかったことになります。 

## Python ソリューション```python
import sys
from collections import deque, defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    
    lines = []
    station_to_lines = defaultdict(list)
    
    for i in range(n):
        stations = input().split()
        lines.append(stations)
        for s in stations:
            station_to_lines[s].append(i)

    start = "Airport"
    target = "Hotel"

    dist = [-1] * n
    q = deque()

    for line in station_to_lines[start]:
        dist[line] = 1
        q.append(line)

    answer = -1

    while q:
        line = q.popleft()

        if target in lines[line]:
            answer = dist[line]
            break

        for station in lines[line]:
            for nxt in station_to_lines[station]:
                if dist[nxt] == -1:
                    dist[nxt] = dist[line] + 1
                    q.append(nxt)

    print(answer)

if __name__ == "__main__":
    solve()
```リスト`station_to_lines`地下鉄システムの逆インデックスです。 これがないと、すべての転送ですべてのラインをスキャンする必要があり、実行時間が不必要に増加します。 

BFS キューには、駅ではなく地下鉄の路線が格納されます。 これにより、単一のラインに沿った移動を追加コストとしてカウントすることがなくなります。 距離配列には路線番号によってインデックスが付けられ、その値はその路線に到達するために使用される地下鉄の路線の正確な数になります。 

初期化は間違いのよくある原因です。 最初の地下鉄路線はすでに答えに 1 つ貢献しているため、開始距離は次のとおりである必要があります。`1`、 ない`0`。 

ホテルのチェックは、列がキューから削除されたときに行われます。 BFS は距離の増加順に状態を削除するため、最初に見つかったそのようなラインが最適です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S + T) | Sは全路線の総出現駅数、Tは接続路線間の乗換検数 |
 | スペース | O(S) | 保存された路線リストと駅から路線へのマッピングには、すべての駅の出現が含まれます。 

入力サイズは十分に小さいため、すべてのステーションの出現を明示的に保存しても安全です。 BFS は地下鉄各路線を 1 回訪問し、駅のマッピングを通じてすべての乗り換え関係を調査します。 

## テストケース```python
import sys
import io
from collections import deque, defaultdict

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    lines = []
    station_to_lines = defaultdict(list)

    for i in range(n):
        stations = input().split()
        lines.append(stations)
        for s in stations:
            station_to_lines[s].append(i)

    dist = [-1] * n
    q = deque()

    for x in station_to_lines["Airport"]:
        dist[x] = 1
        q.append(x)

    ans = -1
    while q:
        x = q.popleft()
        if "Hotel" in lines[x]:
            ans = dist[x]
            break
        for s in lines[x]:
            for y in station_to_lines[s]:
                if dist[y] == -1:
                    dist[y] = dist[x] + 1
                    q.append(y)

    sys.stdin = old
    return str(ans)

assert run("""1
Airport Hotel
""") == "1"

assert run("""2
Airport X
X Hotel
""") == "2"

assert run("""3
Airport A
A B
B Hotel
""") == "3"

assert run("""4
Airport A B
C D
B C
D Hotel
""") == "3"

 | --- | --- | --- |
 | 単一の直通ライン | 1 | 同じ行で始まり、終わる |
 | 接続された 2 本の線 | 2 | 基本的な転送処理 |
 | 転送の連鎖 | 3 | 複数の BFS レイヤー |

 ## 特殊なケース

 空港とホテルが同じ地下鉄路線上にある場合、BFS はその路線から距離 1 で開始し、すぐに 1 を返します。 このアルゴリズムにより、不必要な転送が強制されることはありません。 

のために：```
1
Airport Hotel
```キューには最初は距離のある行のみが含まれています`1`。 この行には Hotel が含まれているため、答えは次のようになります。`1`。 

乗換駅が複数の路線に属する場合、逆マッピングの候補が多くなる場合がある。 すべてのラインは最初に検出されたときにのみ距離を受け取るため、アルゴリズムは各候補を 1 回チェックします。 

のために：```
3
Airport X
X Y
X Hotel
```最初の路線は駅 X を経由して他の路線に到達します。ホテルの路線には距離が割り当てられています`2`、これは可能な最小値です。 

多くの路線が駅を共有していても、ホテルにつながっていない場合でも、それらの路線は 1 回だけ処理されます。 これにより、同じ中継ステーションの繰り返しの探索が防止され、BFS が必要な複雑さの範囲内に保たれます。
