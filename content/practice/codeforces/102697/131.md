 ## 解決策
 ## 問題の理解

 で表される長方形のホールがあります。`n × m`グリッド。 グリッドには空のセルが含まれており、対角ミラーは次のように表されます。`/`または`\`、特別な`*`細胞。 レーザーが列の下からホールに進入します`x`なので、最初の方向は上向きです。 

空のセルでは、レーザーが同じ方向に継続するだけです。 斜めミラーは向きに応じて方向を変えます。 あ`/`ミラーは通常の反射パターンで垂直方向と水平方向の動きを入れ替えますが、`\`ミラーはその逆です。 あ`*`は異なります。光が到達すると、光は 4 つの基本方向すべてに進み続けるため、単一のレーザー経路が複数の経路になります。 

出力では、すべてのミラーとスターが変更されません。 空のセルを横に交差させると、`-`、空のセルが縦に交差すると、`|`、両方の方向に交差した空のセルは次のようになります。`+`。 

公式声明では 1 秒の時間制限と 256 MB のメモリ制限が示されていますが、公開されたバージョンでは数値の上限が公開されていません。`n`そして`m`目に見える制約の中で。 したがって、意図したアプローチは、グリッド セルの数に比例して拡張する必要があります。 ミラーがサイクルを作成する可能性があるため、同じレーザー状態を無限に再訪する可能性のあるシミュレーションは安全ではありません。 解決策`O(nm)`は、セルごとに一定数の方向性状態のみを処理するため、自然なターゲットです。

```レーザーは鏡に到達して反射し、すぐにホールから出ます。 ミラー自体は絶対に交換しないでください。`|`または`-`。

最後の危険なケースはサイクルです。 鏡は、すでに訪れた場所にビームを送り返すことができます。 実装がボードから出るまでレイを追跡するだけの場合、永久にループする可能性があります。 正しい状態単位は、単なるセルではなく、セルとビームが現在進行している方向を合わせたものです。 

## アプローチ

 最も直接的なアプローチは、すべてのビームを個別にシミュレートすることです。 入口から始めて、現在の方向に 1 つずつセルをたどり、鏡で反射し、星で分岐します。 プログラムによって実行されるすべての操作は、ホール内でのライトの動作に直接対応しているため、これは概念的には正しいです。 

問題は、同じ物理的状態に何度も到達する可能性があることです。 状態はセルと方向で構成されます。`4nm`しかし、単純なパスの列挙ではそれがわかりません。 1 つの星では 4 つの新しいパスを作成できるため、考えられるすべてのパスを独立して探索すると、星の数に応じて指数関数的に増加する可能性があります。 と`s`分岐する星、到達できる道の選択肢の数`4^s`、それらのパスの長さを考慮する前に。 さらに悪いことに、ミラー サイクルにより、保護されていないシミュレーションが単に遅くなるだけでなく、永久に実行される可能性があります。 

重要な観察は、レーザーの将来の動作は現在のセルと方向のみに依存するということです。 同じ方向で同じセルに 2 回目に到達すると、その後に起こることはすべてすでにシミュレートされています。 もう一度探索する理由はありません。 

これにより、問題は小さな有向状態グラフに変わります。 それぞれの状態は、`(row, column, direction)`。 通常の空のセルには 1 つの出力状態があり、ミラーには 1 つの反射出力状態があり、星には最大 4 つの出力状態があります。 初期状態からグラフの走査を実行し、処理されるとすぐに各状態をマークします。 

出力には追加の詳細が 1 つあります。 同じ空のセルを 1 つの枝が水平に横切り、別の枝が垂直に横切ることができます。 したがって、すべてのセルに対して 2 つの独立したビットを保持します。1 つは水平方向の光がセルを通過したことを示し、もう 1 つは垂直方向の光がセルを通過したことを示します。 最後の文字は、これらの 2 ビットから直接続きます。 

ブルートフォース手法では、状態を指数関数的に何度も再訪したり、無限にループしたりする可能性があります。 状態ベースのトラバーサルは、最大でも各プロセスを処理します。`4nm`状態を 1 回繰り返すことで、グリッド サイズに線形の複雑さを与えます。

 ## アルゴリズムのチュートリアル

 1. グリッドを指定どおりに保存します。 などのマーキングを出力するため、元の文字を保持します。`-`、`|`、 そして`+`後のレーザー分岐がセルを解釈する方法を変更してはなりません。 
2. 4 方向を上、右、下、左と表します。 各方向に行と列の増分があるため、1 ステップの移動は定数時間の操作となります。 
3. 状態とのトラバースを開始します`(n - 1, x, up)`。 レーザーは列の一番下の行のセルに入ります`x`上に移動しながら、そのセルが処理する必要がある最初のグリッド位置になります。 
4. 毎回訪問済みの状態を維持します。`(row, column, direction)`。 状態を処理する前に、その状態がすでに訪問されているかどうかを確認してください。 存在する場合は、その継続全体がすでに探索されているため、それを破棄します。 
5. 現在のセルが空の場合、ビームが水平に移動しているか垂直に移動しているかを記録します。 後で別のビームが同じセルに到達する可能性があるため、実際のグリッド文字はまだ変更しないでください。 
6. 現在のセルに次の内容が含まれている場合`/`を使用して方向を反映します。`up ↔ right`そして`down ↔ left`。 含まれている場合`\`、 使用`up ↔ left`そして`down ↔ right`。 反射された方向によって次の状態が決まります。 
7. 現在のセルに次の内容が含まれている場合`*`、同じセルからの 4 つの方向すべてをキューに入れます。 スターは分岐点であるため、トラバースを入力方向に制限すると有効なビームが失われます。 
8. 選択した方向ごとに 1 つのセルを移動します。 その位置がホールの外側にある場合、対応するビームがミラー ホールから出ているため、その状態は破棄されます。 
9. 走査が終了したら、元々空だったすべてのセルを、その 2 つの走査ビットに従って変換します。 ノービットとは`.`、水平のみを意味します`-`、垂直方向のみを意味します`|`、両方のビットの意味は、`+`。 

### なぜ効果があるのか

 不変条件は、到達可能なすべてのレーザー状態です。`(row, column, direction)`は 1 回だけ処理され、処理後はその状態からのレーザーのあらゆる継続がスケジュールされます。 空のセルは方向を保存し、ミラーはそれを決定論的に反映し、星は許可される 4 つの方向をすべて生成します。 したがって、到達可能なビームセグメントは省略されません。 

逆に、ある状態がすでに処理されると、その同じ状態に再び到達しても、新しい動作を生み出すことはできません。 グリッドは静的であるため、その状態に到達するたびに、その出力遷移は同一になります。 したがって、訪問した状態をマークすると、重複した作業のみが削除され、レーザー パスの個別の部分が削除されることはありません。 交差した空のセルはそれぞれ水平方向と垂直方向の移動を個別に記録するため、最後の文字はホールに到達するすべての光を正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, x = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    # Directions: 0 = up, 1 = right, 2 = down, 3 = left.
    dr = (-1, 0, 1, 0)
    dc = (0, 1, 0, -1)

    # For every cell:
    # bit 0 means horizontal light passed through it.
    # bit 1 means vertical light passed through it.
    marks = bytearray(n * m)

    # Four possible directions for every cell.
    visited = bytearray(4 * n * m)

    stack = [(n - 1, x, 0)]

    while stack:
        r, c, d = stack.pop()

        if not (0 <= r < n and 0 <= c < m):
            continue

        state = ((r * m + c) << 2) | d
        if visited[state]:
            continue
        visited[state] = 1

        cell = grid[r][c]

        if cell == '.':
            idx = r * m + c
            if d == 0 or d == 2:
                marks[idx] |= 2
            else:
                marks[idx] |= 1

        if cell == '*':
            for nd in range(4):
                nr = r + dr[nd]
                nc = c + dc[nd]
                if 0 <= nr < n and 0 <= nc < m:
                    stack.append((nr, nc, nd))
            continue

        if cell == '/':
            if d == 0:
                d = 1
            elif d == 1:
                d = 0
            elif d == 2:
                d = 3
            else:
                d = 2

        elif cell == '\\':
            if d == 0:
                d = 3
            elif d == 3:
                d = 0
            elif d == 2:
                d = 1
            else:
                d = 2

        nr = r + dr[d]
        nc = c + dc[d]

        if 0 <= nr < n and 0 <= nc < m:
            stack.append((nr, nc, d))

    for r in range(n):
        row = []
        for c in range(m):
            cell = grid[r][c]

            if cell != '.':
                row.append(cell)
                continue

            value = marks[r * m + c]

            if value == 0:
                row.append('.')
            elif value == 1:
                row.append('-')
            elif value == 2:
                row.append('|')
            else:
                row.append('+')

        print(''.join(row))

if __name__ == "__main__":
    solve()
```の`grid`配列には元のホールのみが含まれます。 この分離が必要なのは、空のセルは概念的にすでに変更されているためです。`-`または`|`物理的にはまだ別のビーム用の空のセルです。 

の`marks`配列はセルごとに 2 ビットを使用します。 少し`1`水平移動とビットを表します`2`垂直方向の移動を表します。 の値`3`当然に対応する`+`。 

の`visited`配列にはセルごとに 4 つのエントリがあり、各入力方向に 1 つずつ含まれます。 あ`bytearray`状態の数が大きくなる可能性があり、状態ごとのバイトによりメモリ使用量が予測できるため、Python のタプル セットの代わりに使用されます。 

ミラー遷移は明示的に記述されます。 のために`/`、上向きのビームは右向き、右向きのビームは上向き、下向きのビームは左向き、左向きのビームは下向きになります。 のために`\`、対応するペアは上と左、下と右です。 

星は単一のビームを反射しないため、通常の方向遷移の前に処理されます。 4 つの出射ビームを作成します。 出力は保持する必要があるため、現在のスター セル自体は決してマークされません。`*`。 

境界チェックは、状態が処理される前と、次の状態を作成するときに再度行われます。 最初のチェックは外部の状態がプッシュされる可能性がある防御的なケースを処理し、2 番目のチェックは外部の座標がスタックに入るのを防ぎます。 

再帰的 DFS ではなく、反復的 DFS が使用されます。 長い直線ビームには多くのセルが含まれる可能性があり、アルゴリズム自体は線形であっても、再帰を行うと Python の再帰制限を超える危険があります。

## 特殊なケース

 1マスの空きホールの場合、```
1 1 0
.
```スタックには最初に含まれています`(0, 0, up)`。 状態はグリッド内にあるため、空のセルは垂直ビットを受け取ります。 次の位置はグリッドの外側にあるため、これ以上の状態は追加されません。 最終的なマーク値は、`2`となり、`|`。 出力は正確に`|`。 

玄関すぐの鏡には、```
1 1 0
/
```状態が到達する`/`上に移動しながら。 反射によって方向が右に変わり、次の座標は 1 列のホールの外側になります。 現在のセルは空のセルではなくミラーであるため、そこには出力マークは書き込まれません。 オリジナル`/`保存されています。 

入り口のスターに、```
1 3 1
.*.
```レーザーが最初に処理します`(0, 1, up)`。 セルなので、`*`、トラバースは 4 方向すべてを押します。 左の枝が入ります`(0, 0)`水平にマークを付けます`-`。 右の枝が入ります`(0, 2)`水平にマークを付けます`-`。 上向きの枝と下向きの枝はグリッドから外れます。 星は変わらず、生み出し続ける`-*-`。 

より微妙なエッジ ケースは、両方の方向で到達したセルです。 1 つのブランチが空のセルを水平方向にマークし、それにマーク値を与えるとします。`1`。 別のブランチが垂直に到達すると、アルゴリズムは次のことを実行します。`marks[idx] |= 2`、値を次のように変更します。`3`。 最終的な変換マップ`3`に`+`。 グリッドに 1 文字だけを直接保存するソリューションでは、2 番目の分岐が到着したときに最初の方向が簡単に失われる可能性があります。 

サイクルは、セル単独ではなく、方向性の状態によって処理されます。 レーザーが元に戻った場合`(r, c)`同じ方向からの場合、対応する訪問済みバイトはすでに設定されており、状態は破棄されます。 異なる方向から返された場合、それはまったく異なる状態であり、処理されます。 2 回目の訪問が冗長であることを意味することなく、同じセルが水平パスと垂直パスの両方に参加できるため、この区別はまさに必要なものです。
