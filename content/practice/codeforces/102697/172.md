 ## 解決策
 ## 問題の理解

 (n)人います。 人(i)はコートの色とブーツの色を持っています。 戦いの間、2 人のコートの色とブーツの色が異なる場合、人 (i) はちょうど 1 つの雪玉を人 (j) に投げます。 人は決して自分自身に投げかけることはありません。 

タスクは、そのような順序付きペア ((i,j)) をすべてカウントすることです。 方向が重要です。人 (i) が人 (j) に投げることができれば、それは 1 つの雪玉に貢献し、逆に投げることも可能であれば、別個にカウントされます。 

入力により、人数が示され、続いて (n) 個のコートの色と (n) 個のブーツの色が一致する順序で示されます。 出力は、投げられた雪玉の総数です。 

公開された問題ページでは、1 秒の制限時間と 256 MB のメモリが示されていますが、(n) の明示的な上限は公開されていません。 これにより、(O(n^2)) 解は安全でなくなります。これは、自然な総当たり手法がすべての順序付きペアを検査するためです。 (O(n)) ソリューションが推奨され、周波​​数情報のみを使用するため、(n) が大きい場合でもパフォーマンスは良好です。 

最初のエッジケースは 1 人です。```
1
red
blue
```答えは、`0`。 他に投げかける人は誰もいません。 単に異なる属性を持つ人をカウントする式では、その人自身をカウントしないように注意する必要があります。 

2 番目のエッジケースは、全員が同じコートの色で異なるブーツを履いている場合に発生します。```
3
red red red
blue green yellow
```答えは、`0`。 どのペアも同じコートを着ているので、誰も有効なターゲットになりません。 ブーツの色のみをチェックする不注意な解決策では、注文された 6 つのペアすべてが誤ってカウントされてしまいます。 

逆の状況も同様に重要です。```
3
red green blue
black black black
```答えは、`0`, すべてのペアが同じブーツを共有しているためです。 2 つの条件は両方とも必須です。 

最後に、人々は両方の属性を共有できるようになります。```
3
red red blue
black black green
```有効な順序ペアのみが、`red/black`グループと`blue/green`人、与える`2`。 オーバーラップを修正せずに、コートを共有する人々とブーツを共有する人々を個別に減算すると、両方の属性を共有する人々のペアが 2 回減算されます。 

## アプローチ

 直接的なアプローチでは、異なる人々のすべての順序付きペアが考慮されます。 各ペアについて、コートの色とブーツの色を比較し、両方の色が異なる場合は正確に答えに 1 を加えます。 これは正しいです。考えられるすべてのスローが 1 つの順序付きペアに対応し、すべての有効な順序付きペアが 1 つのスローに寄与するからです。 

(n(n-1)) 個の順序ペアがあるため、総当たりソリューションでは (\Theta(n^2)) 個のペア チェックが実行されます。 たとえば、(n=100000) は (9,999,900,000) 回のチェックを意味し、1 秒のソリューションが合理的に実行できる量をはるかに超えています。 

有益な観察は、私たちは実際には特定の人のどの色を持っているかを気にしていないということです。 固定の人 (i) について、コートの色が (C_i) 回発生し、ブーツの色が (B_i) 回発生し、コートとブーツの正確な組み合わせが (P_i) 回発生するとします。 

考えられるすべての (n) ターゲットのうち、(C_i) は同じコートを持ち、(B_i) は同じブーツを持っています。 両方のグループを削除したいと考えています。 同じコートと同じブーツを持っている人が 2 回削除されていたため、1 回追加し直しました。 したがって、人物 (i) の有効なターゲットの数は次のようになります。 

[
 n-C_i-B_i+P_i。 
】

 その人自身のエントリは、この式によってすでに正しく処理されています。 これらは 3 つの周波数グループすべてに属しているため、その寄与は次のようになります。 

[
 1-1-1+1=0。 
】

 ハッシュ マップを使用して 3 つの周波数すべてを 1 回のパスで取得し、すべての人の式を合計することができます。 ブルート フォースは、考えられるすべてのターゲットを明示的にテストするため機能しますが、二次関数的に多くのペアがあるため失敗します。 頻度の観察により、ターゲットを個別に調べることなく、人物全体の有効なターゲットをすべてカウントすることができます。 

同等のグローバル導出では、包含-除外を使用します。 (n(n-1)) 個の可能なスローから開始し、コートを共有する順序ペアを減算し、ブーツを共有する順序ペアを減算し、両方を共有する逆順序ペアを追加します。 色が (k) 回出現すると、(k(k-1)) 個の順序付きペアが作成されます。 個人ごとの式は、必要な周波数がすべてすぐに利用できるため、実装が簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(1)) | 大きい (n) には遅すぎる |
 | 最適 | (O(n)) が期待されます | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 人数、コートの色、ブーツの色を読み取ります。 同じインデックスにある 3 つの情報は 1 人の人物を表すため、頻度を数えながらその位置を保存します。 
2. 毛色の頻度マップを作成します。 すべての人について、何人が同じコートを着ているかを記録します。 
3. ブーツの色の周波数マップを作成します。 これにより、各人とブーツを共有するために除外される人の数が得られます。 
4. ペアの頻度マップを構築する`(coat, boots)`。 これは、両方のプロパティを共有する人々が両方の除外グループにカウントされるため必要です。 
5. すべての人について計算します

 [
 n-\text{コート数}-\text{ブーツ数}+\text{ペア数}。 
】

 これは包含と除外です。考えられるすべてのターゲットから開始し、同じコートを持つターゲットを削除し、同じブーツを持つターゲットを削除し、次に削除されたターゲットを 2 回復元します。 
6. これらの値を回答に追加し、結果を出力します。 有効な順序ペアはそれぞれ、投げる人の観点から 1 回だけカウントされます。 

### なぜ効果があるのか

 各人物 (i) について、考えられるすべてのターゲットが最初に (n) 人の候補に含まれます。 同じコートを持つターゲットはすべて除去され、(n-C_i) が得られます。 残った候補者の中から、同じブーツを履いている全員も除外しなければなりません。 コートとブーツの両方を共有している人は両方の操作で削除されたため、一度追加し直す必要があります。 結果として得られる値 (n-C_i-B_i+P_i) は、異なるコートと異なるブーツの両方を履いている人の数とまったく同じです。 

その人自身のエントリは 3 つの周波数グループすべてに含まれるため、寄与はゼロになります。 すべての人についてこの正確なカウントを合計すると、すべての有効な指示されたスローが 1 回カウントされ、無効なスローはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    n = int(input())
    coats = input().split()
    boots = input().split()

    coat_count = Counter(coats)
    boot_count = Counter(boots)
    pair_count = Counter(zip(coats, boots))

    answer = 0

    for coat, boot in zip(coats, boots):
        answer += n - coat_count[coat] - boot_count[boot] + pair_count[(coat, boot)]

    print(answer)

if __name__ == "__main__":
    solve()
```3人`Counter`オブジェクトは、アルゴリズムからの 3 つの周波数に直接対応します。`coat_count[coat]`教えてくれます (C_i)、`boot_count[boot]`(B_i) と教えてくれます。`pair_count[(coat, boot)]`と教えてくれます(P_i)。 

の`zip`この操作により、同じ人のコートとブーツが一緒に保管されます。 コートとブーツを個別にカウントすると、実際にどの組み合わせが発生するかについての情報が失われるため、これはペア頻度マップを作成する場合に特に重要です。 

表現```
n - coat_count[coat] - boot_count[boot] + pair_count[(coat, boot)]
```包含-排他を直接実装します。 その人自身の組み合わせはすでに式によって考慮されているため、現在の人に対する特別な減算は必要ありません。 

Python の整数はオーバーフローしないため、順序付けされたペアの数が多くても、答えは安全です。 入力は次を使用します`sys.stdin.readline`ただし、入力自体は十分小さいため、通常の入力でも十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) が期待されます | 3 つの周波数マップ構造と 1 つは人々の上を通過します。 
| スペース | (O(n)) | コート、ブーツ、およびペアの頻度マップには、それぞれ最大 (n) 個の異なるエントリが含まれます。 

このアルゴリズムは、各人に対して予想される一定量のハッシュ マップ作業を実行するため、(n) に応じて線形にスケールします。 これにより、多くの人にとって非現実的となる二次ペア列挙が回避され、メモリ使用量は線形のままになります。

 ## 特殊なケース

 一人の人の場合、```
1
red
blue
```3 つの周波数はすべて 1 つです。 式は (1-1-1+1=0) を与えるため、アルゴリズムは自分自身に向かって投げている人を正確に数えることを回避します。 

誰もが同じコートを着ていると、```
3
red red red
blue green yellow
```人それぞれが持っている`coat_count = 3`。 有効なターゲット数は (3-3-1+1=0) です。 ブーツは違っても、コートを共有すればあらゆるスローを防ぐのに十分です。 

誰もが同じブーツを履いていると、```
3
red green blue
black black black
```人それぞれが持っている`boot_count = 3`、(3-1-3+1=0) となります。 共用ブーツによりあらゆる投げ込みが排除されます。 

複数の人が両方の財産を共有する場合、```
3
red red blue
black black green
```最初の 2 人はそれぞれ、コート数 2、ブーツ数 2、ペア数 2 を持っています。 有効なターゲット数は (3-2-2+2=1) で、これは`blue/green`人。 3 人目は有効なターゲットを 1 つ持ち、合計で`2`。 

この最後のケースは、主な包含/排他トラップです。 完全ペアの頻度が加算されなかった場合、最初の 2 人は、共有コートと共有ブーツが 2 回減算されるため、それぞれ誤って有効なターゲットを 0 個受け取ることになります。
