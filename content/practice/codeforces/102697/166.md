 ## 解決策
 ## 問題の理解

 このタスクには、正確に 3 つの食べ物の選択肢があります。ステーキは 500 カロリー、リンゴは 100 カロリー、パンは 50 カロリーです。 目標を与えられた`n`、これは 50 で割り切れることが保証されているため、正確に消費する必要があります`n`できるだけ少ない個別の食品を使用しながら、カロリーを抑えます。 出力では、最小項目ソリューション内のステーキ、リンゴ、パンの数をこの順序で求めます。 

重要な制限は、すべてのカロリー値が 50 の倍数であるということです。問題全体を 50 で割ると、3 つの食品の値は次のようになります。`10`、`2`、 そして`1`。 そのため、構造が特に単純になります。ステーキは、リンゴ 5 個またはパン 10 個の代わりとなるため、残りのカロリーを構成できなくなることなくステーキを使用できる場合は、ステーキを使用することで食品の数を減らすだけです。 

この声明では、明示的な上限は示されていません。`n`問題のページにあるため、アルゴリズムは、`n`、特にネストされた列挙。 定数時間の算術ソリューションが推奨され、1 秒の時間制限と 256 MB のメモリ制限に簡単に適合します。 

最初のエッジケースはまさに 1 つのパンです。 入力用`50`、唯一可能な解決策は`0`ステーキ、`0`リンゴと`1`パンなので、出力は次のようになります`Steak: 0`、`Apples: 0`、`Bread: 1`。 少なくとも 1 つのステーキまたはリンゴが使用できることを前提とした実装は、ここでは失敗します。 

2 番目のエッジ ケースは、ステーキには十分な大きさではありませんが、リンゴで正確に割り切れるターゲットです。 入力用`200`、正しい出力は次のとおりです。`Steak: 0`、`Apples: 2`、`Bread: 0`。 常に最初にステーキを予約しようとする不用意な実装では、ステーキを使用できなくなりますが、正しいアプローチでは単にステーキをゼロにして、残りをリンゴで処理します。 

3 番目の有用な境界ケースは、ステーキのすぐ上のターゲットです。 入力用`550`、正しい出力は次のとおりです。`Steak: 1`、`Apples: 0`、`Bread: 1`。 ステーキを食べた後、残りの50カロリーはパン1枚にならなければなりません。 最後の余りを忘れると、不完全な解が生成されます。 

最後に、次のような 500 の倍数の場合、`2500`、答えは`5`ステーキだけで、それ以外は何もありません。 出力形式では、未使用の食品を省略するのではなく、ゼロ カウントを含む 3 つのカウントすべてが必要です。 公式の例では、この動作を示しています。`2500`。 

## アプローチ

 直接的な総当たりの解決策では、可能な限りの数のステーキを試し、次に可能な限りの数のリンゴを試し、残りのカロリーをパンで賄えるかどうかを確認できます。 カウントのペアごとに総カロリーが決定されるため、最終的にはすべての可能な組み合わせが検査されるため、この方法は正しいです。 もし`n`ただし、候補ペアの数は二次関数的に増加します。 カロリーを 50 ずつスケールした後、可能なステーキの枚数は約`n / 500`、ステーキの枚数ごとに約`n / 100`リンゴの数を大まかに数えます`n² / 50000`最悪の場合の組み合わせ。 正確な定数は小さいですが、二次依存性は不要です。 

ブルートフォースは、実行可能な空間全体を明示的に検索するため機能しますが、宗派の構造により、より強力なものが得られます。 ステーキにはリンゴの 5 倍、パンの 10 倍のカロリーが含まれています。 すべてのターゲットは 50 で割り切れるため、できるだけ多くのステーキを選択した後、残りの量は常に 50 の倍数となり、リンゴとパンを使用して常に表すことができます。 これら 2 つの食品のうち、リンゴにはパンの 2 倍のカロリーが含まれているため、できるだけ多くのリンゴを使用する必要があります。 残りの量はゼロかちょうど 50 で、パンが必要です。 

これにより、整数の除算と剰余のみを使用した貪欲な解決策が得られます。 私たちは取る`n // 500`ステーキからカロリーを取り除き、残りからリンゴを最大数取り、残りの50カロリーをパンとして使用します。

 ## アルゴリズムのチュートリアル

 1. 目標カロリー数を読み取る`n`。 以来`n`が 50 で割り切れる場合、500 カロリーのステーキを除いた余りも 50 で割り切れます。 
2. コンピューティング`steaks = n // 500`。 これはステーキの最大枚数です。 ステーキの使用量を減らすと、少なくとも 1 つの 500 カロリーのアイテムがいくつかの小さなアイテムに置き換えられるため、最小アイテム数を改善することはできません。 
3. それらのステーキのカロリーを以下から差し引きます。`n`。 残りのカロリーは厳密に 500 未満になります。 
4. コンピューティング`apples = remainder // 100`。 これは、残りのカロリーに収まる最大のリンゴの数です。 リンゴはステーキに次いで2番目に多い食品なので、リンゴをパンに置き換えても品数は増えるだけです。 
5. 残りからリンゴのカロリーを引きます。 剰余は 50 の倍数であり、現在は 100 未満であるため、残される可能な値は 0 または 50 のみです。 
6. コンピューティング`bread = remainder // 50`。 これにより、残りのカロリーを正確にカバーするゼロまたは 1 つのパンが生成されます。 
7. 必要なラベルを使用して 3 つのカウントを印刷します。 

### なぜ効果があるのか

 不変条件は、それぞれの貪欲な選択の後でも、残りのカロリーは、より小さい食品サイズで正確に表現できるということです。 すべてのステーキには最大のカロリー値があるため、可能な限り多くのステーキを摂取することが安全です。そのため、ステーキ 1 枚を小さな食品に置き換えるには、少なくとも 2 つの追加アイテムが必要です。 ステーキの枚数が決まれば、同じ議論がリンゴとパンにも当てはまります。 最終的な余りは 0 または 50 であることが保証されているため、パンは正確な目標を達成します。 したがって、貪欲な構築が可能であり、すべての決定により利用可能な最大の食料の使用が最大化され、アイテムの総数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    steaks = n // 500
    n %= 500

    apples = n // 100
    n %= 100

    bread = n // 50

    print(f"Steak: {steaks}")
    print(f"Apples: {apples}")
    print(f"Bread: {bread}")

if __name__ == "__main__":
    solve()
```最初の除算では、ステーキの最大数を計算します。 ループではなく整数除算を使用すると、この演算が定数時間になります。 

剰余演算子は、ステーキによって占められたカロリーを直ちに削除します。 この時点で、残りの値は 500 未満です。次に、同じパターンがリンゴに適用され、値は 100 未満のままになります。 

元のターゲットは 50 で割り切れるため、最終剰余も 50 で割り切れる必要があります。100 未満であるため、0 または 50 しか取ることができません。そのため、整数を 50 で割ると、必要なパン数が正確に得られます。 

ソリューションのどこにも浮動小数点演算はありません。 これにより、丸めの問題が回避され、割り算の引数が正確になります。 Python の整数には任意の精度があるため、ターゲットが通常の 32 ビット範囲より大きい場合でも、整数オーバーフローの心配はありません。 

操作の順序が重要です。 最初にステーキを取り除き、次にリンゴを取り除く必要があります。これは、貪欲な証明は、食品をカロリー値の最大値から最小値まで処理することに依存するためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())

    steaks = n // 500
    n %= 500

    apples = n // 100
    n %= 100

    bread = n // 50

    print(f"Steak: {steaks}")
    print(f"Apples: {apples}")
    print(f"Bread: {bread}")

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

    return out.getvalue()

# Provided samples
assert run("2350\n") == (
    "Steak: 4\n"
    "Apples: 3\n"
    "Bread: 1\n"
), "sample 1"

assert run("2500\n") == (
    "Steak: 5\n"
    "Apples: 0\n"
    "Bread: 0\n"
), "sample 2"

# Minimum-size target
assert run("50\n") == (
    "Steak: 0\n"
    "Apples: 0\n"
    "Bread: 1\n"
), "minimum target"

# All calories fit exactly into steaks
assert run("5000\n") == (
    "Steak: 10\n"
    "Apples: 0\n"
    "Bread: 0\n"
), "all steaks"

# Exact apple boundary

 ## 特殊なケース

 のために`50`、アルゴリズムは最初に計算します`50 // 500 = 0`, したがって、ステーキは選択されていません。 残りは50のままで、`50 // 100 = 0`, したがって、リンゴも選択されていません。 ついに、`50 // 50 = 1`、生産`Steak: 0`、`Apples: 0`、`Bread: 1`。 これにより、最小の法的ターゲットが特別なケースなしで処理されることが確認されます。 

のために`200`、ステーキの枚数は`200 // 500 = 0`。 残りの200カロリーが生成します`200 // 100 = 2`リンゴなのでカロリーはゼロです。 最終的なパンの数はゼロです。`Steak: 0`、`Apples: 2`、`Bread: 0`。 このアルゴリズムでは、最大の食べ物を強制的に表示する必要はありません。 

のために`550`、ステーキの枚数は`550 // 500 = 1`50 個に収まるリンゴはないので、リンゴの数はゼロになります。 残りの50個がちょうど1個のパンになります。 結果は`Steak: 1`、`Apples: 0`、`Bread: 1`、合計2つの食品が含まれます。 

のために`2500`、最初の部門は与えます`2500 // 500 = 5`そして余りはゼロになります。 後続の両方の除算でもゼロが生成されます。 出力は`Steak: 5`、`Apples: 0`、`Bread: 0`これにより、ゼロ値のカテゴリは引き続き印刷する必要があり、最大額面の正確な倍数にはそれより小さい食品は必要ないことが確認されます。 

非常に大きなターゲットの場合、`1000000000`、アルゴリズムは、小さな入力の場合と同じ 3 つの除算段階を実行します。 ステーキは 200 万枚得られ、残りはゼロになります。 ターゲットに応じてループが成長することはありません。これが、算術貪欲ソリューションの主な利点です。
