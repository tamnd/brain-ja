 ## 解決策
 ## 問題の理解

 この問題は RGB カラーで機能します。 色は 3 つの整数で表されます。`R`、`G`、 そして`B`、それぞれの間`0`そして`255`。 このようなトリプルが 1 つ与えられ、それが赤、緑、青、黄色の 4 つの名前付き色のうちどれを表すかを識別する必要があります。 関連する 4 つの RGB トリプルは次のとおりです。`(255, 0, 0)`、`(0, 255, 0)`、`(0, 0, 255)`、 そして`(255, 255, 0)`。 出力は、対応する色名を大文字で表示します。 

入力トリプルは 1 つだけあり、各コンポーネントには 256 個の可能な値の小さな固定範囲があります。 考えられるすべての RGB トリプルを検査するアルゴリズムであっても、`256^3 = 16,777,216`ただし、ここでそうする理由はありません。 必要な色は明示的にわかっているため、自然な解決策では一定数の比較のみが実行されます。 したがって、時間とメモリの要件は入力値とは無関係です。 

主なエッジケースは、黄色を三原色から区別することです。 たとえば、入力```
255 255 0
```生産しなければならない```
YELLOW
```かどうかだけをチェックする不用意な実装`R == 255`黄色にも最大値の赤色成分があるため、これを赤色として分類できます。 完全なトリプルを比較する必要があります。 

もう 1 つの有用な境界ケースは青です。```
0 0 255
```生み出すのは```
BLUE
```1 つのコンポーネントが存在するかどうかのみを確認する`255`すべての有効な色には、以下に等しいコンポーネントが少なくとも 1 つあるため、これでは不十分です。`255`。 3 つのコンポーネントすべての位置によって答えが決まります。 

このステートメントは、4 つの名前付き色のいずれかに対応する入力を記述しているため、次のようなトリプルになります。`(0, 0, 0)`または`(255, 255, 255)`問題の有効な入力ドメインの外にあります。 このようなトリプルには必須の出力はなく、ソリューションではそれらに余分な色の名前を作成すべきではありません。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての RGB トリプルを列挙します。`(0, 0, 0)`を通して`(255, 255, 255)`そして各候補を入力と比較します。 まさにあります`256^3 = 16,777,216`したがって、最悪の場合、最大約 1,700 万回のチェックが実行されます。 問題が必要とするよりもはるかに多くの作業が必要です。 

可能な RGB 値のセットが有限であり、ターゲットとなる 4 つの色が既知であるため、ブルート フォースが機能します。 答えとなるトリプルは 4 つだけであるという観察により、列挙全体を削除できます。 入力トリプルと既知の 4 つのトリプルを単純に比較し、一致する名前を出力します。 最大 4 つの比較が必要です。 

これは本質的には直接検索の問題です。 RGB 表現の背後に隠されたグラフ、動的プログラミング状態、検索スペース、または算術最適化はありません。 3 つの数値は、4 つの固定値の 1 つをコンパクトにエンコードしたものにすぎません。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取ります`R`、`G`、 そして`B`。 これらは、入力色の赤、緑、青の強度コンポーネントを表します。 
2. 比較する`(R, G, B)`と`(255, 0, 0)`。 等しい場合、色は赤なので印刷します。`RED`。 
3. それ以外の場合は、次と比較します。`(0, 255, 0)`。 等しいということは色が緑色であることを意味するので、印刷します`GREEN`。 
4. それ以外の場合は、次と比較します。`(0, 0, 255)`。 等しいということは色が青であることを意味するので、印刷します`BLUE`。 
5. これら 3 つのトリプルのいずれも一致しない場合、有効入力の保証は残ります。`(255, 255, 0)`残された可能性として。 印刷する`YELLOW`。 

### なぜ効果があるのか

 アルゴリズムは、考えられるすべての有効な回答に対して入力をチェックします。 4 つの RGB トリプルは個別であるため、入力は 2 つの異なる色と一致することはできません。 この問題では、入力がこれら 4 つの色のいずれかを表すことが保証されているため、正確に 1 回の比較でそれを識別する必要があります。 したがって、印刷される名前は、入力 RGB トリプルに関連付けられた名前になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, g, b = map(int, input().split())

    if (r, g, b) == (255, 0, 0):
        print("RED")
    elif (r, g, b) == (0, 255, 0):
        print("GREEN")
    elif (r, g, b) == (0, 0, 255):
        print("BLUE")
    else:
        print("YELLOW")

if __name__ == "__main__":
    solve()
```最初の行は唯一の入力行を読み取り、その 3 つのコンポーネントを整数に変換します。 テスト ケースは 1 つだけであるため、テスト ケースのループはありません。 

各条件では、3 つのコンポーネントすべてが同時に比較されます。 これにより、1 つのコンポーネントのみから色を識別するというよくある間違いを回避できます。 例えば、`R == 255`赤と黄の両方に当てはまりますので、チェックのみを行います`R`それらを区別することはできません。 

決勝戦`else`入力が 4 つの色のいずれかを表すことが保証されているため、安全です。 また、4 番目の明示的な等価性テストを作成するよりも若干クリーンです。 インデックス付けや境界の問題はなく、Python 整数は許可された範囲全体を簡単に処理できます。

## テストケース

 公式サンプルは、声明で示された 2 つのケースです。 以下のカスタム ケースは、他の名前付き色と RGB コンポーネント範囲の境界をカバーしています。 有効な入力ドメインには指定された 4 つの色のみが含まれるため、次のようなすべてが等しいトリプルになります。`(0, 0, 0)`は正当なテスト ケースではないため、予期される出力を定義することはできません。```python

def run(inp: str) -> str:

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

assert run("255 255 0\n") == "YELLOW\n", "sample 2"

## 特殊なケース

 黄色のケースは、論理的な間違いの原因である可能性が最も高いです。 正確な入力のために```
255 255 0
```赤との最初の比較は、緑のコンポーネントが次のとおりであるため失敗します。`255`の代わりに`0`。 赤のコンポーネントが次のとおりであるため、緑の比較も失敗します。`255`。 赤成分も緑成分も必要な値を持たないため、青の比較は失敗します。 アルゴリズムは最後の分岐に到達し、出力します。`YELLOW`、それは正しいです。 

青色のケースでは、最大コンポーネントの位置をテストします。 のために```
0 0 255
```赤の比較は失敗します。`R`は`0`、緑の比較は失敗します。`G`は`0`。 青色の比較は 3 つのコンポーネントすべてに一致し、出力されます。`BLUE`。 一部のコンポーネントが等しいかどうかのみをチェックするソリューション`255`この区別では失敗するでしょう。 

コンポーネントの最小境界も原色でカバーされます。 で```
0 255 0
```2 つの成分は正確に最小値にあります。`0`、一方、中央のコンポーネントは`255`。 アルゴリズムはトリプル全体を比較し、正しく出力します。`GREEN`。 

最後に、最大の RGB 境界が次のように表示されます。```
255 255 0
```2 つの成分が同時に存在する場合`255`。 このアルゴリズムは、正確に 1 つの成分が最大であるとは想定していないため、黄色を正しく認識します。
