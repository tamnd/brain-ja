 ## 解決策
 ## 問題の理解

 次のように書かれた 1 つの正の分数が与えられます。`a/b`。 分子`a`分母より小さい必要はない`b`, したがって、次のような仮分数は`72/48`有効です。 出力に関連する唯一の制限は、`a`の倍数ではありません`b`, そのため、元の分数がすでに整数を表すことはできません。 

タスクは、分子と分母に共有されるすべての共通因数を削除することです。 の最大公約数が`a`そして`b`は`g`、次に両方の部分を次のように割ります。`g`ユニークで最も単純な形式を与える`a/g`以上`b/g`。 

公開された声明では、明示的な数値の上限は示されていません。`a`そして`b`。 代わりに、入力は効率的に実行するために考えられる要素を試す総当りソリューションにとって十分小さいと述べています。 これにより、より簡単なバージョンの直接検索が受け入れられるようになりますが、さらにクリーンな解決策がまだあります。最大公約数は、対数時間で Euclid のアルゴリズムを使用して見つけることができます。 入力には小数部が 1 つしか含まれていないため、非常に小さな定数係数であっても、データ構造の選択よりも重要です。 

不用意に実装すると失敗するケースがいくつかあります。 のために`6/8`、正しい出力は次のとおりです。`3/4`。 かどうかだけをチェックするプログラム`a`で割り切れます`b`分数は変更されないままになります。`6`で割り切れない`8`、両方の数値に次の共通因数があるにもかかわらず、`2`。 

のために`72/48`、正しい出力は次のとおりです。`3/2`。 分子が分母よりも大きくなりますが、簡略化には影響しません。 分子が小さくなければならないと想定するソリューションでは、入力が誤って拒否されたり、間違った検索範囲が使用されたりする可能性があります。 

のために`37/73`、正しい出力は次のとおりです。`37/73`。 2 つの数値は互いに素であるため、減らすものはありません。 両方の数値を除算することを最初に確認せずに、常に何らかの係数で除算する解法では、分数の値が変化します。 

次のような入力`6/2`このステートメントは分子が分母の倍数ではないことを保証しているため、このステートメントは有効なテスト ケースではありません。 同様に、`a = b`分子は分母の倍数であるため、除外されます。 テスト ジェネレーターは、そのような入力を通常のエッジ ケースとして扱うのではなく、これらの保証を尊重する必要があります。 

## アプローチ

 最も直接的なアプローチは、共通因子を探すことです。 すべての整数を検査できます`d`から`2`を通して`min(a, b)`、いつでも`d`両方の数値を割ります。両方をそれで割ります。 これを因数がなくなるまで繰り返すと、分子と分母に以下の公約数がない分数が生成されます。`1`, したがって、結果は正しいです。 

欠点は、この方法では、小さい入力までの基本的にすべての整数に対して 1 つの割り算テストを実行できることです。 もし`m = min(a, b)`、全範囲をスキャンすると実行されます`m - 1`最悪の場合の候補者チェック。 より簡単なバージョンでは、数値がそのような総当り的な方法に対して十分に小さいことが明示的に保証されているため、このアプローチがここで実行可能です。 

同じタスクを表現する、より基本的な方法があります。 実際には、すべての共通因子を個別に発見する必要はありません。 必要なのは、分子と分母の最大公約数である積だけです。 ユークリッド アルゴリズムは、考えられる約数を列挙せずにこの値を計算します。 

重要な観察は、正の整数の場合です。`a`そして`b`、ペアを次のように置き換えます`(b, a mod b)`最大公約数は変わりません。 のすべての公約数`a`そして`b`も分割します`a - qb`、 そして`a mod b`まさに`a - qb`適切な整数の場合`q`。 この変換を繰り返すと、最終的には残りが 0 に達し、最後の 0 以外の値が GCD になります。 

総当たり法が機能するのは、考えられるすべての要素を試してみると、最終的にはすべての公約数が見つかるからです。 関連する可能性のない要素の調査に時間を費やすため、拡張できません。 すべての共通因数が 1 つの数値 GCD で表現できるという観察により、全体の単純化が 1 つのユークリッド アルゴリズムとそれに続く 2 つの除算に縮小されます。

 | 最適 | O(log(min(a, b))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 分数を文字列として読み取り、次の位置で分割します。`/`。 結果として得られる 2 つの部分が分子になります`a`と分母`b`。 
2. コンピューティング`g = gcd(a, b)`ユークリッドアルゴリズムを使用します。 値`g`は、分数の値を変更せずに両方の部分を除算できる最大の正の整数です。 
3. 両方を分割します`a`そして`b`による`g`。 以来`g`両方の数値を除算すると、結果の値は整数となり、これらの値に以下の共通因数はありません。`1`。 
4. 元の分子と分母を縮小して出力します。`a/b`形式。 必要な答えは正確な分数であるため、小数への変換は実行されません。 

これが機能する理由: ユークリッド アルゴリズム全体を通じて、現在のペアの公約数のセットは変わりません。 2 番目の値がゼロになると、すべての数値がゼロを除算するため、残りの最初の値は元の分子と分母の最大公約数になります。 両方の部分をその値で割ると、それらの共通因数全体が削除され、2 つの互いに素な整数が残ります。 分子と分母が互いに素である分数は、まさに最も単純な形です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a, b = map(int, s.split('/'))

    x, y = a, b
    while y != 0:
        x, y = y, x % y

    g = x
    print(f"{a // g}/{b // g}")

if __name__ == "__main__":
    solve()
```スラッシュは入力形式の一部であるため、入力は最初は文字列として保持されます。 スプリットオン`/`計算に必要な 2 つの整数が正確に得られます。 

このループは Euclid のアルゴリズムを直接実装します。 各反復の後、ペアは次のように変化します。`(x, y)`に`(y, x % y)`。 ループは次の場合に停止します。`y`ゼロになり、その時点で`x`GCDです。 

分割は GCD が見つかった後にのみ発生します。 これは、特徴づけようとしている公約数の値を変更することを避けるため、検索中に繰り返し除算を行うよりも望ましい方法です。 

Python の整数は指定された問題ではオーバーフローせず、解決策では一定の補助メモリが使用されます。 また、Euclid のアルゴリズムは考えられる要素を列挙していないため、最適アルゴリズムにはオフバイワンの問題はありません。

## 特殊なケース

 のために`6/8`、入力は次のとおりです。```
6/8
```Euclid のアルゴリズムが生成するのは、`gcd(6, 8) = 2`。 アルゴリズムは両方の値を次のように除算します。`2`、与える`3/4`。 分子を除算する 1 つの数値のみを検索する単純な解決策では、分母の割り算を要求することを忘れると、無効な分数が生成される可能性があります。 

のために`72/48`、入力は次のとおりです。```
72/48
```余りの数列は、`72 % 48 = 24`に続く`48 % 24 = 0`したがって、GCD は次のようになります。`24`。 換算された分数は`3/2`。 分子が分母より大きくても、GCD の計算方法は変わりません。 

のために`37/73`、入力は次のとおりです。```
37/73
```剰余数列は最終的に次の値に達します`1`したがって、GCD は次のようになります。`1`。 で割る`1`元の分数は変更されません。 これは、すでに単純化された分数の正しい動作です。 

のために`1/2`、入力は次のとおりです。```
1/2
```ユークリッドの最初のステップは、`1 % 2 = 1`、 に続く`2 % 1 = 0`。 GCD は`1`、出力は次のようになります`1/2`。 これは、実装が分子の因数が より大きいことを想定していないことをチェックします。`1`。 

のために`100/80`、入力は次のとおりです。```
100/80
```Euclid のアルゴリズムは次のようになります。`gcd(100, 80) = 20`。 このアルゴリズムは両辺を完全な GCD で 1 回除算し、`5/4`。 単一因数の削減を繰り返すこともできますが、GCD を計算すると、数値に含まれる共通因数の数に関係なく演算が行われます。 

のために`99991/99989`、入力は次のとおりです。```
99991/99989
```2 つの数値は互いに素であるため、GCD は次のようになります。`1`そして出力は変わりません。 このケースでは、より簡単なバージョンの不特定の数値上限への依存を回避しながら、小さな例よりも大幅に大きな値に対して対数アルゴリズムを実行します。 

公式声明では、1 秒と 256 MB の制限、3 つのサンプル、および簡単なバージョンの入力がブルート フォースに十分小さいという保証が確認されています。
