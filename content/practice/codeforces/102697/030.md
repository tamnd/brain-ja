 ## 解決策
 ## 問題の理解

 チームはグループステージでいくつかの試合を行った。 入力により、勝ち、負け、引き分けの固定順序で 3 つのカウントが得られ、値はハイフンで区切られます。 勝利は 3 ポイント、引き分けは 1 ポイント、負けは何も貢献しません。 タスクは、これら 3 つのカウントからチームの合計ポイント数を計算することです。 公式声明では、まさにこの入力形式を指定しており、`5-3-2`例として、答えは 17 です。 

勝ち数、負け数、引き分け数が`w`、`l`、 そして`t`、それぞれ、答えは簡単です。`3w + t`。 

すべての損失は 0 ポイントとなるため、損失の数は計算式には表示されません。 入力には整数が 3 つだけ含まれており、テスト ケースも 1 つだけあるため、配列、グラフ、動的プログラミング状態、または繰り返し処理は必要ありません。 時間制限は 1 秒、メモリ制限は 256 MB ですが、実際の計算には一定数の解析と算術演算のみが必要です。 公開されたステートメントでは 3 つのカウントの明示的な上限が指定されていないため、実装では単純に Python 整数を使用する必要があります。これにより、固定幅のマシン整数の制限を超える値が自動的に処理されます。 

ハイフンで区切られた特殊な入力形式が原因で、誤って処理されやすい小さなケースがいくつかあります。 たとえば、```
0-0-0
```正しい出力は```
0
```すべてのチームが少なくとも 1 試合を行ったことを前提とした解決策は、この自然な境界のケースでは失敗します。 式は次のようになります`3 * 0 + 0 = 0`直接。 

もう一つのケースは、```
0-5-4
```正しい出力は次のとおりです```
4
```不用意に実装すると、すべてのカウントが 3 倍になり、負けや引き分けが勝ちのように誤って扱われる可能性があります。 勝利のみが 3 ポイントを獲得し、4 回の引き分けはさらに 4 ポイントを獲得します。 

3 番目の有用な境界ケースは次のとおりです。```
7-0-0
```生み出すのは```
21
```ここでは、別途追加するタイがないため、答えは完全に勝利から得られます。 損失数はその値に関係なく無関係です。 

## アプローチ

 最も直接的なアプローチは、レコードの一致を 1 つずつシミュレートすることです。 3 つのカウントを読み、勝利ごとに 3 ポイントの追加を 1 回、引き分けごとに 1 ポイントの追加を 1 回実行し、負けごとに何も追加しません。 これは文字通り採点ルールに従っているので、これは正しいです。 チームが持っている場合`w`勝ち、`l`損失、および`t`同点の場合、このシミュレーションは実行されます`w + l + t`繰り返しますが、`l`損失反復では有用な演算は行われません。 

このアプローチの弱点は、入力自体には 3 つの数値しか含まれておらず、明示的な大きな制限が与えられていないため、通常の入力でタイムアウトになる可能性が高いことではありません。 そのコストはまったく不要です。 合計一致数が`m = w + l + t`、シミュレーションにはかかります`O(m)`時間を正確に実行し、`m`繰り返し。 10 億件の一致を含むレコードの場合、3 つのカウントからすぐに答えが得られるとしても、10 億回のループ反復を意味します。 

重要な観察は、同じ結果の一致はすべて同じ数のポイントを与えるということです。 勝ち、負け、引き分けが起こった順序を知る必要はありません。 必要なのはその数だけです。 すべての勝利は次のように組み合わせることができます`3w`ポイント、すべての損失は`0l`、そしてすべてがつながります`t`ポイント。 これにより、計算全体が 1 つの定数時間式に減ります。 

ブルートフォース手法は、すべての一致を個別に考慮するため機能しますが、各一致の寄与がその結果のみに依存するという事実を利用できません。 同一の結果が集計できるという観察により、潜在的に多くの反復を 3 つの算術演算に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(w + l + t) | お(1) | 実際には受け入れられますが、不要です |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 唯一の入力行を文字列として読み取ります。 ハイフンは区切り文字であるため、この行を空白で区切られた 3 つの通常の整数として解析することはできません。 
2. 各ハイフンで文字列を分割し、結果として得られる 3 つの部分を整数に変換します。 順序は固定されており、1 番目に勝ち、2 番目に負け、3 番目に引き分けです。 
3. 勝利ごとに 3 ポイントが付与されるため、勝利数に 3 を掛けます。 
4. 負けるたびに 0 ポイントが付与されるため、スコアを計算するときに負け数を無視します。 
5. 同点の数を加算します。これは、同点ごとに 1 ポイントが付与されるためです。 
6. 印刷`3 * wins + ties`。 

### なぜ効果があるのか

 勝利するたびに、アルゴリズムはスコアリング ルールによって与えられる 3 ポイントを正確に付与します。 すべての損失に対して寄与するのはゼロであり、これがまさに損失の値です。 同点ごとに 1 ポイントが加算されます。 3 つの入力カウントによってチームの試合結果がこれら 3 つのカテゴリに分割されるため、それらの貢献を合計すると、チームのグループステージ合計スコアが正確に得られます。 計算はカウントのみに依存するため、一致の順序に関する情報は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

record = input().strip()
wins, losses, ties = map(int, record.split('-'))

answer = 3 * wins + ties
print(answer)
```3 つの整数がスペースではなくハイフンで区切られているため、最初の行では完全なレコードが文字列として読み取られます。 使用する`strip()`意味のある内容を変更せずに末尾の改行を削除します。 

の`split('-')`call は、勝ち、負け、引き分けに対応する 3 つの文字列を正確に生成します。`map(int, ...)`それらを整数に変換し、タプルのアンパックにより、問題で使用されたのと同じ順序でそれらが割り当てられます。 

変数`losses`最終的な式では意図的に使用されていません。 これは省略ではありません。 損失によるポイントはゼロであるため、ゼロを乗算しても効果はありません。 変数を保持すると、入力順序が明確になり、問題の採点ルールとの関係が明確になります。 

Python の整数には、32 ビットまたは 64 ビットの整数型を使用する言語で見られる固定幅のオーバーフローの問題がありません。 計算`3 * wins + ties`したがって、カウントが一般的なマシンの整数より大きくても、Python の利用可能なメモリにのみ依存し、安全です。 

## 実用的な例

 提供されたサンプルの入力は次のとおりです。`5-3-2`。 解析された 3 つの値は、5 勝、3 敗、2 引き分けです。 

| 勝ちます | 損失 | ネクタイ | 勝ち点 | タイポイント | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 5 | 3 | 2 | 15 | 2 | 17 |

 5勝が貢献`5 * 3 = 15`ポイント。 3 敗の寄与はゼロ、2 つの引き分けは寄与`2 * 1 = 2`。 最終的なスコアは、`15 + 2 = 17`、公式サンプルと一致します。 

2 番目の例として、次のことを考えてみましょう。```
0-5-4
```| 勝ちます | 損失 | ネクタイ | 勝ち点 | タイポイント | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 5 | 4 | 0 | 4 | 4 |

 未勝利なので勝利貢献度はゼロです。 5 敗の貢献度も 0 ですが、4 回の引き分けの貢献度は 4 です。 結果は`4`。 このトレースは、損失を誤って勝ちまたは引き分けとして扱ってはいけない理由を示しています。

 | スペース | お(1) | 3 つのカウントといくつかのスカラー変数のみが保存されます。 |

 入力にはレコードが 1 つだけ含まれているため、最適解は問題で指定された 1 秒および 256 MB の制限内に収まります。 非常に大きな数値であっても、アルゴリズムの複雑さは変わりません。 

## テストケース```python
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    record = input().strip()
    wins, losses, ties = map(int, record.split('-'))
    print(3 * wins + ties)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("5-3-2\n") == "17\n", "sample 1"

# Minimum-size / all-zero record
assert run("0-0-0\n") == "0\n", "all results absent"

# All losses
assert run("0-10-0\n") == "0\n", "losses give zero points"

# All ties
assert run("0-0-10\n") == "10\n", "each tie gives one point"

# Large values
assert run("1000000000-999999999-1000000000\n") == "4000000000\n", \
    "large counts"

# Boundary-style case with no wins
assert run("0-5-4\n") == "4\n", "losses must not contribute points"

 |`0-10-0`|`0`| 損失は​​何も貢献しません。 
|`0-0-10`|`10`| 同点の場合はそれぞれ 1 ポイントが貢献します。

 ## 特殊なケース

 オールゼロの記録```
0-0-0
```は、3 つのコンポーネントすべてをゼロとして解析することによって処理されます。 答えの計算は次のようになります`3 * 0 + 0`、プログラムは次のように出力します`0`。 特別な条件は必要ありません。 

損失だけを含む記録、```
0-5-0
```生成する`0`。 アルゴリズムは次のように読み取ります`wins = 0`、`losses = 5`、 そして`ties = 0`、次に計算します`3 * 0 + 0`。 負け数によって答えが変わることはなく、スコアリング システムと正確に一致します。 

同点のみを含むレコード、```
0-0-5
```生成する`5`。 アルゴリズムが計算するのは、`3 * 0 + 5`, したがって、すべての引き分けはちょうど 1 ポイントに貢献します。 

勝利のみを含む記録、```
7-0-0
```生成する`21`。 計算は`3 * 7 + 0 = 21`したがって、少なくとも 1 回の引き分けまたは負けには依存しません。 

最後に、ハイフン区切り文字自体が実装のエッジ ケースです。 のために```
5-3-2
```電話をかける`input().split()`1 つの文字列が生成されます。`"5-3-2"`3 つの値ではなく、 明示的に分割する`'-'`3カウントを回復するには必要となります。 その解析ステップの後、問題は直接スコア計算式に帰着します。`3 * wins + ties`。
