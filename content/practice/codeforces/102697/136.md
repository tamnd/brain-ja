 ## 解決策
 ## 問題の理解

 入力は、いくつかの独立した問題セットにわたる生徒の成績を記述します。 各行には次のような形式があります`a/b`、 どこ`a`は正解した質問の数であり、`b`そのセット内の質問の総数です。 タスクは、すべてのセットを結合し、同じものを使用して、生徒の正解の合計数と不正解の合計数を出力することです。`correct/total`スタイル。 

たとえば、セットが次の場合、`2/5`そして`3/5`と生徒は答えた。`2 + 3 = 5`正しく質問します。 あった`5 + 5 = 10`合計質問数なので、最終結果は次のようになります。`5/10`。 同様に、不正解の数は次のようになります。`(5 - 2) + (5 - 3) = 5`。 

The official statement gives a 1 second time limit and 256 MB of memory. 数値の上限は公表していない`n`したがって、最も安全な設計は、一定の追加状態を持つ入力を単一パススルーすることです。 二次作業を行うアルゴリズムは、問題セットの数が増えると不適切になりますが、必要な計算自体は各入力行を 1 回処理するだけで済みます。 

不注意な解析やアカウンティングにより、誤った結果が生成される可能性がある小さなケースがいくつかあります。 などのワンセットで```
1
3/7
```答えは`3/7`。 A solution that only computes the number of wrong answers but forgets to preserve the number of correct answers would lose information.

 セットには正解がゼロである場合もあります。 のために```
1
0/6
```正しい出力は`0/6`。 ゼロを欠損値として扱う実装、またはすべてのセットに少なくとも 1 つの正解が含まれると想定する実装は、ここで失敗する可能性があります。 

すべての質問にも正しく答えることができます。 のために```
1
6/6
```出力は`6/6`、 ない`6/0`。 概念的には合計正解数と合計不正解数を求める文言にもかかわらず、出力の分母は問題の合計数であり、不正解の質問の数ではありません。 実際に必要な出力形式は、スラッシュで区切られた正解数と総問題数です。 

最後に、スラッシュは入力構文の一部であり、数学的な除算演算ではありません。 のために```
2
2/5
4/6
```答えは`6/11`。 周囲の 2 つの整数を解析する`/`また、それらを個別に追加することで、誤って整数の除算を実行することを回避できます。 

## アプローチ

 意図的に単純な解決策では、これまでに確認されたすべての問題セットを保存し、新しいセットをそれぞれ読み取った後、保存されているコレクション全体を再度スキャンして 2 つの合計を再計算することができます。 すべての再計算ですべてのセットが考慮され、その正しいカウントと合計カウントが加算されるため、これは正しいです。 読んだ後`k`セットしますが、実行します`k`追加なので、全体的に`n`設定された検査の数は

 [
 1 + 2 + \cdots + n = \frac{n(n+1)}2.
 ]

のために`n = 100000`、つまり`5,000,050,000`1 秒のプログラムが試みるべきものをはるかに超えた検査を設定します。 

ブルートフォース手法は、目的の結果がすべてのセットからの独立した寄与の単純な合計であるため機能しますが、すでに答えに組み込まれている情報を繰り返し処理します。 重要な観察は、加算は結合的であるということです。 現在の合計が判明したら、新しく読み取られたセットは、独自の正しいカウントと独自の合計カウントを提供するだけで済みます。 以前のセットを再検討する理由はありません。 

したがって、2 つの実行値を維持できます。 1 つは正解の合計を保存し、もう 1 つはすべての質問の合計を保存します。 すべての入力行に対して`a/b`、追加します`a`最初の値と`b`2番目に。 最終的に、これら 2 つの累積値がまさに必要な出力となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | n が大きいと遅すぎます |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、問題セットの数。 処理する必要がある分数行の数が正確にわかっているため、ループはそれらの行を正確に消費できます。 
2.初期化`correct = 0`そして`total = 0`。 これらの変数は、これまでに処理されたすべてのセットの合計スコアを表します。 
3. それぞれについて`n`行、次のような文字列を読み取ります`8/11`。 で分割します`/`2 つの整数値を取得するには`8`そして`11`。 
4. 最初の値を`correct`そして2番目の値は`total`。 現在の行のみが新しい情報を提供するため、以前に処理されたセットを再度調べる必要はありません。 
5. すべてのセットの処理が完了したら、印刷します。`correct`そして`total`によって区切られる`/`。 累積分子は総正解数、累積分母は総問題数です。 

不変条件は、入力の接頭辞を処理した後、`correct`そのプレフィックスの正解の総数に等しく、`total`は、そのプレフィックス内の質問の合計数に等しくなります。 最初は両方の合計がゼロであるため、何かを処理する前に不変式が保持されます。 各入力行は、不変条件を維持しながら、両方の合計に独自の寄与を正確に加算します。 最終行の後のプレフィックスはコンテスト全体であるため、2 つの変数はまさに必要な出力です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    correct = 0
    total = 0

    for _ in range(n):
        a, b = map(int, input().strip().split('/'))
        correct += a
        total += b

    print(f"{correct}/{total}")

if __name__ == "__main__":
    solve()
```最初の行は、後続のレコードの数を決定するため、整数として読み取られます。 2 つのアキュムレータは一度初期化され、ループ全体で更新され、アルゴリズムのウォークスルーからの不変式と一致します。 

レコードごとに、`split('/')`合計カウントから正しいカウントを分離します。 申請中`map(int, ...)`両方の部分を直接整数に変換するため、手動による文字処理は必要ありません。 

このコードでは、誤った回答の数ではなく、質問の総数が追加されます。 これは、必要な出力形式と一致し、結合された合計数の上に結合された正しい数が出力されます。 概念的に誤答数が必要な場合は、すでに次のように表されています。`total - correct`。 

Python の整数は、大きな値に対応できるように自動的に拡張されるため、入力合計の合計が 32 ビット整数より大幅に大きい場合でも、整数オーバーフローの心配はありません。 

に応じた配列インデックスや範囲はありません。`n`したがって、メインループではオフバイワンの問題は発生しません。 ループは問題セットごとに 1 回だけ実行されます。

2 番目のサンプルでは、​​入力には完璧なパフォーマンスとゼロ正解の両方が含まれています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての問題セット行が 1 回だけ読み取られて処理されます。 |
 | スペース | お(1) | 2 つの累計といくつかの一時解析変数のみが保存されます。 |

 このソリューションでは、入力の検査に必要な作業量を最小限に抑えます。 このステートメントは 1 秒の制限を指定しており、目に見える数値の上限を提供していないため、`n`、スキャンの繰り返しを避けるのが適切な選択です。 現在処理中の入力行を除けば、メモリ使用量は一定のままです。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    correct = 0
    total = 0

    for _ in range(n):
        a, b = map(int, input().strip().split('/'))
        correct += a
        total += b

    print(f"{correct}/{total}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample 1
assert run(
    """5
2/5
4/6
8/11
3/8
1/9
"""
) == "18/39\n", "sample 1"

# Provided sample 2
assert run(
    """5
6/6
5/6
3/6
0/6
5/8
"""
) == "19/32\n", "sample 2"

# Minimum-size input
assert run(
    """1
0/1
"""
) == "0/1\n", "minimum size"

# All questions answered correctly
assert run(
    """4
1/1
5/5
100/100
7/7
"""
) == "113/113\n", "all correct"

# All questions answered incorrectly
assert run(
    """3
0/4
0/7
0/10
"""
) == "0/21\n", "all incorrect"

# Boundary-style large input with many records
assert run(
    "5\n" + "100000/100000\n" * 5
) == "500000/500000\n", "large values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`に続く`0/1`|`0/1`| 最小数の問題セットとゼロの正解 |
 |`1/1`、`5/5`、`100/100`、`7/7`|`113/113`| すべての質問に正解した場合の正しい累積 |
 |`0/4`、`0/7`、`0/10`|`0/21`| 正解合計への寄与はゼロ |

 テスト スイートには両方の公式サンプルも含まれており、問題によって提供される例に対して完全な解析および蓄積プロセスを検証します。 

## 特殊なケース

 単一の問題セットに対して、アルゴリズムは 1 回だけ更新を実行します。 と```
1
3/7
```初期状態は`(correct, total) = (0, 0)`。 処理`3/7`に変更します`(3, 7)`したがって、出力は次のようになります`3/7`。 特別なケースは必要ありません`n = 1`。 

正解を含まないセットについては、次のように考えます。```
1
0/6
```アップデートは`correct += 0`そして`total += 6`、生産`(0, 6)`。 出力は`0/6`。 これが機能するのは、ゼロが正当な寄与であり、プログラムが次のような真理値チェックをまったく使用しないためです。`if a:`誤ってスキップしてしまう可能性があります。 

完璧なセットを実現するには、```
1
6/6
```状態になります`(6, 6)`そして出力は`6/6`。 分母は、分数ごとに 2 番目の数値から意図的に累積されます。 これを誤答数に置き換えると、誤って生成されます。`6/0`。 

次のような混合ケース```
3
2/5
0/3
4/4
```状態を生み出す`(2, 5)`、 それから`(2, 8)`、 それから`(6, 12)`。 最終的な答えは、`6/12`。 これにより、同じ入力でゼロ寄与と完全集合の両方が実行され、すべての行が 2 つの合計に独立して寄与していることが確認されます。 

入力構文自体も、慎重に扱う価値のあるもう 1 つの境界です。 次のような行`8/11`2 つの部分を整数に変換する前に、リテラルのスラッシュで分割する必要があります。 表現`map(int, line.split('/'))`はまさにそれを行い、整数の除算を回避し、両方の量を独立して保存します。
