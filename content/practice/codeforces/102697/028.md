 ## 解決策
 ## 問題の理解

 この問題では、与えられた正の整数が「おかしな数」であるかどうかを判断するように求められます。 数値は、5 と 7 の両方で均等に割り切れる場合にのみこのラベルを受け取ります。入力には 1 つの整数が含まれており、出力は次のようになります。`YES`条件が満たされている場合と、`NO`さもないと。 

必要な操作は、可算性をチェックすることだけです。 数値は 2 つの固定値に対してテストされるため、アルゴリズムは入力数値の読み取り以外は入力数値のサイズに依存しません。 値が非常に大きい場合でも、一定数の算術演算で十分です。 複数の値を検索したり、繰り返し値を減算しようとするソリューションでは、不必要な作業が追加され、直接の割り算チェックよりもはるかに遅くなる可能性があります。 

主なエッジケースは、両方の条件が必要であることを忘れていることから発生します。 5 で割り切れる数だけでは十分ではありません。 たとえば:

 入力:```
25
```正しい出力は次のとおりです。```
NO
```25 は 5 では割り切れますが、7 では割り切れないためです。1 つの除数のみをチェックする不注意な解決策では、誤って出力されてしまいます。`YES`。 

もう 1 つのケースは、7 で割り切れるが 5 では割り切れない数です。 

入力:```
14
```正しい出力は次のとおりです。```
NO
```なぜなら、14 は要件の半分しか満たさないからです。 

有効な最小のケースは、5 と 7 の最小公倍数です。 

入力:```
35
```正しい出力は次のとおりです。```
YES
```35 は両方の数で割り切れるからです。 

## アプローチ

 簡単な強引なアイデアは、5 または 7 を引いて数値を減らすことができるかどうかを、ゼロになるまで繰り返しテストすることです。 これにより、数値がいずれかの値の倍数であるかどうかが最終的に明らかになりますが、この問題のモデルとしては間違っています。 入力値が大きい場合、多くの不必要な反復が必要になる可能性があり、それでも 2 つの割り算条件が自然に結合されません。 

重要な観察は、割り算が剰余演算によってすでに提供されているということです。 数字`x`別の数で割り切れる`y`まさにいつ`x % y`ゼロに等しい。 この問題では 2 つの固定値で割り切れる必要があるため、剰余チェックは 2 回だけ必要です。 

ブルートフォース手法が機能するのは、数値が約数の倍数のセットに属しているかどうかを検出しようとするためです。 剰余がその集合のメンバーシップに直接応答するという観察により、問題全体が定数時間に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 不必要に大きな値を指定すると遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力から指定された数値を読み取ります。 条件は割り切れるかどうかのみに依存するため、必要な情報は数値だけです。 
2. 5 で割ったときと 7 で割ったとき、数値が 0 になるかどうかを確認します。定義では両方のプロパティが同時に必要なため、両方のチェックが成功する必要があります。 
3. 印刷`YES`両方の余りがゼロの場合。 それ以外の場合は印刷します`NO`。 

なぜ効果があるのか

 アルゴリズムの背後にある不変条件は単純です。各割り算チェックの後、入力がその割り数の倍数に属するかどうかがわかります。 数値が 5 と 7 の両方の倍数に属する場合、その数値は正確におかしいため、最終条件は定義と直接一致します。 すべての整数は、各約数で割ったときにゼロまたは非ゼロの余りがあるため、欠落するケースはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    if n % 5 == 0 and n % 7 == 0:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは 1 つの整数を読み取り、2 つのモジュロ演算を適用します。 表現`n % 5 == 0`5 が数値を正確に除算するかどうかをチェックします。`n % 7 == 0`7 に対しても同じチェックを実行します。論理`and`が必要なのは、条件を 1 つだけ満たす数値では面白くないためです。 

Python では整数演算が大きな値を自動的に処理するため、オーバーフローの心配はありません。 また、両方の約数が定数であり、すべての正の整数が同じ 2 つのチェックで処理されるため、条件順序によって境界問題が発生することもありません。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    ans = "YES" if n % 5 == 0 and n % 7 == 0 else "NO"

    sys.stdin = old_stdin
    return ans + "\n"

assert solve("21\n") == "NO\n", "sample 1"
assert solve("35\n") == "YES\n", "sample 2"

assert solve("1\n") == "NO\n", "minimum value"
assert solve("1000000000\n") == "NO\n", "large boundary value"
assert solve("70\n") == "YES\n", "multiple of both divisors"
assert solve("25\n") == "NO\n", "divisible by only one divisor"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | いいえ | 可能な最小の入力 |
 | 1000000000 | いいえ | 大きな値の処理 |
 | 70 | はい | 両方の約数の有効な倍数 |
 | 25 | いいえ | 1 つの約数のみで割り切れる数を拒否する |

 ## 特殊なケース

 5 で割り切れるが 7 では割り切れない数値は拒否する必要があります。 入力用`25`、アルゴリズムは次のように計算します。`25 % 5 = 0`そして`25 % 7 = 4`したがって、2 番目の条件は失敗し、出力は次のようになります。`NO`。 

7 で割り切れるが 5 では割り切れない数値も拒否する必要があります。 入力用`14`、アルゴリズムは次のことを見つけます。`14 % 5 = 4`そして`14 % 7 = 0`したがって、最初の条件は失敗し、出力は次のようになります。`NO`。 

最初の有効な数値は 35 です。入力の場合`35`、両方の剰余がゼロであるため、アルゴリズムは受け入れブランチに到達し、出力します。`YES`。
