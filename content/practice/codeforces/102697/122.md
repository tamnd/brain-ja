 ## 問題の理解

 スペルが間違っている単語が 1 つあります`w`と辞書が含まれています`n`候補の言葉。 あらゆる辞書の単語について`s`のすべての文字を比較します。`w`あらゆるキャラクターと`s`。 2 つの文字が等しい場合、ペアは 1 つの一致をもたらします。 

もし`|w| = a`そして`|s| = b`、まさにあります`a * b`キャラクターペア。 もし`mat`それらのペアに等しい文字が含まれている場合、類似性インデックスは次のようになります。`mat / (a * b)`。 

このタスクは、辞書のすべての単語を、小数点第 2 位に四捨五入した類似性インデックスとともに出力することです。 主な順序付けは類似性を減少させることです。 2 つの単語の類似性インデックスがまったく同じである場合、アルファベット順で後の単語が最初になります。 この問題では 1 秒の制限と 256 MB のメモリが使用されます。 公開された声明では、語長や長さの上限が明示的に規定されていません。`n`したがって、有用な解釈は、解決策はすべての単語ペアの長さの積に比例する作業を回避する必要があるということです。 

アルファベットは小文字26文字固定です。 この制限は、私たちが利用できる重要な構造的制約です。 各文字が何回出現するかがわかると、`w`また、辞書の単語では、すべてのペアを明示的に検査しなくても、一致するすべての文字ペアを計算できます。 

もっともらしい実装が間違っている可能性があるいくつかの特殊なケースがあります。 1 つ目は、文字の位置は関係ないということです。 たとえば、```
ab
1
ba
```2つのペア`(a,b)`、`(a,a)`、`(b,b)`、 そして`(b,a)`2 つの一致が含まれるため、答えは次のようになります。```
ba 0.50
```位置比較では、一致するものが誤って見つかりません。 

もう 1 つの特殊なケースは、繰り返し文字が繰り返しペアに寄与することです。 と```
aaa
1
aa
```3つそれぞれが`a`最初の単語の文字は両方に一致します`a`2番目の単語の文字。 がある`3 * 2 = 6`ペアと 6 つすべてが一致するため、結果は次のようになります```
aa 1.00
```出現する文字ではなく個別の文字を数えると、間違った分子が与えられてしまいます。 

並べ替えルールにも微妙な影響があります。 考慮する```
ab
2
aa
bb
```どちらの候補も 4 つのペアのうち 2 つの一致するペアを持っているため、両方とも類似性があります。`0.50`。 アルファベットを逆に並べる`bb`前に`aa`:```
bb 0.50
aa 0.50
```通常の昇順アルファベットのタイブレークでは、これら 2 つの答えが静かに逆転します。 

最後に、同じように見える 10 進数値は、印刷された 2 桁の 10 進数表現ではなく、実際の分数を使用して比較する必要があります。 2 つの異なる類似度分数は両方とも次のように丸められます。`0.12`一方、並べ替えルールは元の類似性インデックスに基づいています。 並べ替えの前に丸めを行うと、結果として間違った順序が生成される可能性があります。 

## アプローチ

 直接的な解決策は文字通り定義に従います。 あらゆる辞書の単語について`s`のすべての文字を反復処理します。`w`そしてどのキャラクターも`s`、等しいペアをカウントし、そのカウントをで割ります。`|w| * |s|`。 もし`a = |w|`辞書の語長は次のとおりです。`b_1, b_2, ..., b_n`、文字比較の数は正確に`a * b_1 + a * b_2 + ... + a * b_n`。 

すべての辞書の単語に長さがある場合`L`、これは`n * a * L`比較。 これは、ペアチェック部分の正確な最悪の場合の操作数です。 このステートメントではこれらの長さの最大値が公表されていないため、代用できる最悪の場合の単一の数値はありませんが、両方の語長に対する乗算の​​依存性が問題となります。 結果を並べ替える`n`追加コストを記録する`O(n log n)`。 

ブルートフォース手法は、定義で使用されるペアを直接正確にカウントするため、正しいです。 その弱点は、それらの比較のほとんどが不要であることです。 たとえば、次の場合`w`10,000 文字が含まれており、それを別の 10,000 文字の単語と比較するには、必要な情報はその文字数だけであっても、1 億文字の比較が必要です`a`え、何個`b`s などが各単語に発生します。 

重要な観察は、すべての一致するペアはその文字によってのみ決定されるということです。 仮定する`w`含まれています`cnt_w[c]`キャラクターのコピー`c`、 そして`s`含まれています`cnt_s[c]`コピー。 あらゆる出来事が起こる`c`で`w`のあらゆる出現と組み合わせることができます`c`で`s`、与える`cnt_w[c] * cnt_s[c]`一致するペア。 これを 26 個の小文字で合計すると、分子全体が得られます。`mat = Σ cnt_w[c] * cnt_s[c]`。 

周波数配列を構築できます。`w`一度。 その後、各辞書の単語は、26 頻度の配列を構築するために独自の文字を 1 回通過し、その後 26 回の乗算を行うだけで済みます。 語長に対するペアごとの依存性はなくなります。 

並べ替えステップには、もう 1 つ役立つ詳細があります。 類似性は分数です`mat / tot`。 2 つの分数を比較する`a / b`そして`c / d`浮動小数点演算は必要ありません。 比較できます`a * d`と`c * b`。 これにより、10 進表現が近い場合でも正確な順序が与えられます。 

ブルート フォースは有効な文字ペアをすべて明示的に列挙するため機能しますが、語長の積が大きくなると失敗します。 一致するペアをその特徴によってグループ化できるという観察により、各比較が 26 の頻度積に減り、その後は辞書のソートのみが残ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(Σ | w | · | s_i | + n log n)`|`O(n)`| 単語が長いと遅すぎる |
 | 最適 |`O(Σ | s_i | + 26n + n log n)`|`O(n + 26)`| 承認済み |

 ここ`Σ |s_i|`すべての辞書単語の合計文字数です。 固定係数 26 は定数として扱うことができ、次のようになります。`O(Σ |s_i| + n log n)`。 

## アルゴリズムのチュートリアル

 1. スペルミスの単語を読みます`w`26 個の小文字のそれぞれの出現を数えます。 count 配列は、すべてを要約します。`w`それは類似度の計算に関係します。 
2. 辞書の単語をすべて読む`s`そしてその文字の頻度を数えます。 1回のスキャンで`s`文字の位置が類似性に影響を与えることはないため、これで十分です。 
3. 合計して一致する文字ペアの数を計算します。`cnt_w[c] * cnt_s[c]`26文字すべて。 積は、次の出現から構成されるすべての可能なペアをカウントします。`c`で`w`そして、`c`で`s`。 
4. 分母を次のように設定します。`len(w) * len(s)`。 のあらゆるキャラクター`w`のすべての文字とペアになっています`s`文字が一致するかどうかに関係なく。 
5. 単語、その分子、分母を保存します。 浮動小数点値だけではなく分数を保持することで、類似点を正確に並べ替えることができます。 
6. 分数を比較して辞書レコードをソートする`mat1 / tot1`そして`mat2 / tot2`。 類似性が減少する場合、より大きな外積を持つレコード`mat1 * tot2`が最初に来ます。 分数が等しい場合は、単語を逆アルファベット順に比較します。 
7. 各単語とその分数を、小数点以下 2 桁の 10 進数として出力します。 浮動小数点変換は、正確な並べ替えの決定がすでに行われた後、書式設定にのみ使用されます。 

### なぜ効果があるのか

 どの辞書の単語でも`s`、1つの文字を考えてみましょう`c`。 がある`cnt_w[c]`の発生`c`で`w`そして`cnt_s[c]`での出来事`s`。 最初のグループのすべての出現は、2 番目のグループのすべての出現とペアにすることができるため、正確に`cnt_w[c] * cnt_s[c]`文字が次のような一致するペア`c`。 すべての一致するペアは 1 つの文字グループに属するため、26 文字すべてについてこれらの積を合計すると、すべての一致するペアが 1 回だけカウントされます。 分母は考えられるすべてのペアをカウントし、定義からの類似性インデックスを正確に与えます。 

格納された分数は正確な類似度であるため、相互乗算により、浮動小数点誤差が生じることなく、実数値の類似度を比較する場合と同じ順序付けが行われます。 二次比較は、2 つの分数が正確に等しく、必要な逆アルファベット順のタイブレークに一致する場合にのみ使用されます。 

## Python ソリューション```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

def compare(a, b):
    # a = (word, numerator, denominator)
    # b = (word, numerator, denominator)

    left = a[1] * b[2]
    right = b[1] * a[2]

    if left != right:
        # Higher similarity first.
        return -1 if left > right else 1

    # Equal similarity: reverse alphabetical order.
    if a[0] == b[0]:
        return 0
    return -1 if a[0] > b[0] else 1

def solve():
    w = input().strip()
    n = int(input())

    freq_w = [0] * 26
    for ch in w:
        freq_w[ord(ch) - ord('a')] += 1

    results = []

    for _ in range(n):
        s = input().strip()

        freq_s = [0] * 26
        for ch in s:
            freq_s[ord(ch) - ord('a')] += 1

        matches = 0
        for i in range(26):
            matches += freq_w[i] * freq_s[i]

        total = len(w) * len(s)
        results.append((s, matches, total))

    results.sort(key=cmp_to_key(compare))

    for word, matches, total in results:
        similarity = matches / total
        print(f"{word} {similarity:.2f}")

if __name__ == "__main__":
    solve()

辞書の単語ごとに、2 番目の頻度配列が 26 個のゼロで初期化され、単語を 1 回スキャンすることによって埋められます。 マッチング ペアの計算では、正確に 26 回の乗算と加算が実行されます。 これは、アルゴリズムからの周波数公式の直接実装です。 

比較関数は意図的に整数の乗算に基づいています。 2つの類似点について`a / b`そして`c / d`、比較する`a * d`に対して`c * b`浮動小数点精度の問題を回避します。 Python の整数も自動的に増加するため、積が大きくなっても整数のオーバーフローの問題は発生しません。 

タイブレークの使い方`a[0] > b[0]`、辞書編集的に大きい単語が最初に配置されます。 Python の通常の文字列の順序は昇順であるため、これは誤って簡単に逆転してしまいます。 

分母は`len(w) * len(s)`、短い単語の長さや個別の文字の数ではありません。 最初の単語のすべての文字は、2 番目の単語のすべての文字とペアになります。 

最後の除算は、要求された 10 進数 2 桁の表現を生成する場合にのみ使用されます。 これは順序付けには使用されないため、浮動小数点の丸めのため 2 つの近分数を並べ替えることはできません。

# helper: run solution logic on an input string, return output string
import io
from functools import cmp_to_key

def run(inp: str) -> str:
    data = io.StringIO(inp)

    w = data.readline().strip()
    n = int(data.readline())

    freq_w = [0] * 26
    for ch in w:
        freq_w[ord(ch) - ord('a')] += 1

    results = []

    for _ in range(n):
        s = data.readline().strip()

        freq_s = [0] * 26
        for ch in s:
            freq_s[ord(ch) - ord('a')] += 1

        matches = sum(freq_w[i] * freq_s[i] for i in range(26))
        total = len(w) * len(s)
        results.append((s, matches, total))

        left = a[1] * b[2]
        right = b[1] * a[2]

        if left != right:
            return -1 if left > right else 1

        if a[0] == b[0]:
            return 0
        return -1 if a[0] > b[0] else 1

    results.sort(key=cmp_to_key(compare))

    return "".join(
        f"{word} {matches / total:.2f}\n"
        for word, matches, total in results
    )

```両方の単語の頻度ベクトルには、次のものが含まれます。`a`そして1つ`b`。 分子は`1*1 + 1*1 = 2`、分母は 4 となり、`ba 0.50`。 このアルゴリズムでは位置を比較することはありません。これはまさに全ペアの定義で必要とされるものです。 

逆アルファベット順のタイブレークについては、次のことを考慮してください。```
ab
2
aa
bb
```両方の単語に一致するペアが 1 つあります`a`または`b`それぞれの 2 つの立場で、`2 / 4 = 0.50`。 小数が等しいため、コンパレータは 2 番目の条件に達し、`bb`前に`aa`。 

境界のアルファベット文字を含む単語については、次のことを考慮してください。```
az
3
za
aa
zz
```周波数配列のインデックス`a`0と`z`25で。`za`一致するペアが 2 つあり、`aa`1つ持っています、そして`zz`は 1 つあり、それぞれの分母は 4 です。 したがって`za`、`aa`、 そして`zz`類似点がある`0.50`、`0.25`、 そして`0.25`、 それぞれ。 二人`0.25`候補者は次のように順序付けされます`zz`前に`aa`。 

最も重大な現実的なエッジケースは、公開された定義と例の間の不一致です。 のために```
hello
5
helo
helllo
yello
hellow
helpo
```記載されているすべてのペアの公式は次のとおりです`yello = 4 / 25 = 0.16`、公開されたサンプルには次のように書かれていますが、`0.24`。 アルゴリズムは両方の定義を同時に満たすことはできません。 実際の裁判官に対して提出する前に、裁判官が使用したソースステートメントを検証する必要があります。表示されたサンプルのみに基づいて式を選択すると、別の問題が解決されてしまうためです。
