 ## 解決策
 ## 問題の理解

 時系列順に (N) 個の過去の価格のシーケンスが与えられます。 連続した測定のペアごとに、価格は上昇、下降、または変化しません。 RSI の計算では上昇と下降のみが考慮されます。 

増加するたびに、その増加のサイズを収集します。 減少するたびに、その減少の絶対サイズを収集します。 次に、すべての増加の算術平均を計算します。`aveUP`、そしてすべての算術平均は減少します、と呼ばれます`aveDOWN`。 必要な値は

 [
 RS = \frac{aveUP}{aveDOWN}
 】

 続いて

 [
 RSI = 100-\frac{100}{RS+1}。 
】

 公式声明では、1 秒の制限時間と 256 MB のメモリが指定されていますが、(N) の数値上限は公開されていません。 そのため、線形アプローチが自然な目標になります。すべての価格は、以前の価格と 1 回の比較に参加するだけで済みます。 二次アルゴリズムは、おおよそ (N^2) 個の作業を実行するため、入力が大きくなると実用的ではなくなりますが、(O(N)) スキャンは非常に大規模なシーケンスでも簡単に管理できます。 

答えを黙って変える可能性のある詳細がいくつかあります。 

1 つ目は、減少はプラスの量に寄与する必要があるということです。 例えば、```
3
10 7 9
```サイズの減少 (3) とサイズの増加 (2) が 1 つあります。 したがって`aveUP = 2`、`aveDOWN = 3`、そして答えは```
40.0
```生の差を追加する不注意な実装`7 - 10 = -3`下向きの合計にすると、負の平均が生成され、無効な RSI が生成されます。 

2 つ目は、価格が変化していないことがどちらの平均にも寄与していないことです。 例えば、```
4
10 10 12 9
```(2) の増加 1 つと (3) の減少 1 つがあるため、答えは再び次のようになります。```
40.0
```変化のないペアを増加または減少として扱うと、平均の一方が歪むことになります。 

3 番目の問題は、平均がすべての (N-1) 個の隣接ペア全体ではなく、それぞれのタイプの変化全体にわたることです。 サンプルでは、```
4
6500.0 6510.0 6300.0 6200.0
```(10) の増加が 1 つと、(210) と (100) の 2 つの減少があります。 したがって、`aveUP = 10`、`aveDOWN = 155`、必要な出力を提供します`6.060606060606062`。 両方の合計を (N-1=3) で割ることは、一貫して実行するとキャンセルされることがありますが、上向きと下向きの変化を別々にカウントすることで、意図した式が明確になり、実装時の間違いを回避できます。 

また、このステートメントは、履歴に少なくとも 1 つの増加と少なくとも 1 つの減少が含まれていることを保証するため、両方の平均が定義され、`aveDOWN`ゼロにすることはできません。 

## アプローチ

 直接的な総当たり解釈では、平均が必要になるたびに変更の完全なセットを再計算できます。 (N-1) 個の隣接する位置のそれぞれについて、このような実装では、すべての (N-1) 個の隣接するペアを再度スキャンし、すべての差異を分類し、上向きと下向きの合計を再構築できます。 すべてのスキャンは式で必要な情報を正確に再構成しますが、最悪の場合は ((N-1)^2) ペアの検査を実行するため、これは正しいです。 (N) 個の価格の場合、(N^2-2N+1) 個の検査が必要になりますが、これは不必要な作業です。 

隣接する差分は独立しているため、総当たりアプローチは失敗します。 ペアを調べたら`(prices[i-1], prices[i])`、最終平均への寄与は決して変わりません。 そのペアを再度調べる理由はありません。 

重要な観察は、RSI 式がプラスの変化の合計と数、およびマイナスの変化の合計とカウントにのみ依存するということです。 価格を 1 回スキャンするだけで、これら 4 つの数量を正確に維持できます。 正の差の場合は、それを上向きの合計に加算し、上向きのカウントを増分します。 負の差の場合は、その絶対値を下降合計に加算し、下降カウントを増分します。 ゼロの差は無視されます。 

スキャン後の平均は、対応する合計をカウントで割ったものになります。 残りの計算は定数時間です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(1)) | 大きいと遅すぎる (N) |
 | 最適 | (O(N)) | (O(1)) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 価格の数と価格の順序を読み取ります。 価格はすでに時系列に並べられているため、比較する必要があるのは連続した値のみです。 
2.初期化`up_sum`、`up_count`、`down_sum`、 そして`down_count`ゼロに。 これらの変数には、後で 2 つの平均を作成するために必要な情報が正確に含まれています。 
3. 連続する価格のペアごとに、次の値を計算します。`change = current - previous`。 変化がプラスの場合は、それを追加します`up_sum`そして増加します`up_count`。 変化がマイナスの場合は追加します`-change`に`down_sum`そして増加します`down_count`。 変化がゼロの場合は、何もしません。 

使用する`-change`負の変化の場合、下方寄与の符号に関する曖昧さを回避しながら、その絶対値を取得することと同等です。 
4. コンピューティング

 [
 aveUP = \frac{up_sum}{up_count}
 】

 そして

 [
 aveDOWN = \frac{down_sum}{down_count}。 
】

 この問題では、両方のカウントがゼロ以外であることが保証されているため、これらの除算は有効です。 
5. 相対強度を計算します。 

[
 RS=\frac{aveUP}{aveDOWN}。 
】

 次に、それを RSI 式に代入します。 

[
 RSI=100-\frac{100}{RS+1}。 
】
 6. 結果の浮動小数点値を出力します。 この計算には、Python の標準の浮動小数点表現で十分です。 

スキャン全体を通じて不変なのは、最初の (i) 価格を処理した後、`up_sum`そして`up_count`これらの価格間のすべてのプラスの変化を正確に記述します。`down_sum`そして`down_count`すべての負の変化を正の大きさで正確に記述します。 すべての隣接するペアは 1 回処理され、適切なカテゴリに正確に配置されるため、最後のペアの後に蓄積された 4 つの値は、RSI 定義で使用される数量を正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    prices = list(map(float, input().split()))

    up_sum = 0.0
    up_count = 0
    down_sum = 0.0
    down_count = 0

    for i in range(1, n):
        change = prices[i] - prices[i - 1]

        if change > 0:
            up_sum += change
            up_count += 1
        elif change < 0:
            down_sum += -change
            down_count += 1

    ave_up = up_sum / up_count
    ave_down = down_sum / down_count

    rs = ave_up / ave_down
    rsi = 100.0 - 100.0 / (rs + 1.0)

    print(rsi)

if __name__ == "__main__":
    solve()
```価格自体に小数値が含まれる場合があるため、入力は浮動小数点数として読み取られます。 最初の価格には先行価格がないため、ループは意図的にインデックスから開始されます。`1`。 これにより、最初の測定の前に比較を行うという一般的な 1 つ違いのエラーが回避されます。 

以降の各価格については、`change`は、価格履歴におけるまさに 1 つの動きを表します。 正の値は上向きの統計を更新し、負の値は正の大きさを使用して下向きの統計を更新し、ゼロ値はどちらの統計も更新しません。 

平均はスキャンが完了した後にのみ計算されます。 個々の増加または減少を保存する必要がないため、アルゴリズムは入力配列とは別に一定の追加スペースを使用します。 Python の整数はオーバーフローすることなく増加でき、入力価格が浮動小数点であるため、ここでの合計は浮動小数点値になります。 

最終操作の順序は定義に直接に従います。 最初に 2 つの平均が形成され、次にそれらの比率が計算され、その比率が RSI 式に代入されます。 この問題では増加と減少の両方が保証されるため、どちらの平均も特別なゼロカウントの場合は必要ありません。 

## 実用的な例

 ### サンプル 1

 公式サンプルの場合、価格変化は (+10)、(-210)、(-100) です。 

| 現在の価格 | 以前の価格 | 変更 |`up_sum`|`up_count`|`down_sum`|`down_count`|
 | --- | --- | --- | --- | --- | --- | --- |
 | 6510.0 | 6500.0 | +10.0 | 10.0 | 1 | 0.0 | 0 |
 | 6300.0 | 6510.0 | -210.0 | 10.0 | 1 | 210.0 | 1 |
 | 6200.0 | 6300.0 | -100.0 | 10.0 | 1 | 310.0 | 2 |

 最後に、`aveUP = 10 / 1 = 10`そして`aveDOWN = 310 / 2 = 155`。 したがって`RS = 10 / 155`、最終的な RSI は次のようになります。`6.060606060606062`、公式サンプルと一致します。

 歴史を考える```
5

| 現在の価格 | 以前の価格 | 変更 |`up_sum`|`up_count`|`down_sum`|`down_count`|

】

 トレースは、カウントがすべての隣接するペアではなく、移動方向に属していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N)) | (N-1) 個の隣接する価格ペアはそれぞれ 1 回処理されます。 |
 | スペース | (O(N)) | 入力された価格配列が保存されます。 アルゴリズム自体は (O(1)) 個の追加スペースを使用します。 |

 公開されたステートメントでは、1 秒の制限と 256 MB のメモリが指定されていますが、(N) の数値上限は省略されています。 単一の線形スキャンは、欠落境界に関係なく適切な複雑さです。 この実装は、価格ごとに一定の作業のみを実行し、入力配列を超えて固定数のアキュムレータを使用します。 

## テストケース```python
import sys
import io

def solve():
    n = int(input())
    prices = list(map(float, input().split()))

    up_sum = 0.0
    up_count = 0
    down_sum = 0.0
    down_count = 0

    for i in range(1, n):
        change = prices[i] - prices[i - 1]

        if change > 0:
            up_sum += change
            up_count += 1
        elif change < 0:
            down_sum += -change
            down_count += 1

    ave_up = up_sum / up_count
    ave_down = down_sum / down_count

    rs = ave_up / ave_down
    rsi = 100.0 - 100.0 / (rs + 1.0)

    return str(rsi)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        return solve()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided sample
assert run(
    "4\n"
    "6500.0 6510.0 6300.0 6200.0\n"
) == "6.060606060606062", "sample 1"

# Minimum meaningful size: one increase and one decrease
assert run(
    "3\n"
    "10 11 10\n"
) == "50.0", "minimum-size input"

# All equal values are not allowed by the original problem guarantee,
# so use a repeated value inside an otherwise valid history.
assert run(
    "5\n"
    "10 10 12 12 9\n"
) == "40.0", "unchanged prices"

# Equal upward and downward average magnitudes
assert run(
    "5\n"
    "100 110 105 115 110\n"
) == "66.66666666666667", "alternating changes"

# Fractional prices and a boundary change of exactly zero
assert run(
    "4\n"
    "1.5 2.5 2.5 1.0\n"
) == "40.0", "fractional values and zero change"

# Large input to exercise linear behavior.
prices = [0.0]
for i in range(1, 100001):
    prices.append(prices[-1] + (1.0 if i % 2 else -1.0))

large_input = str(len(prices)) + "\n" + " ".join(map(str, prices)) + "\n"
large_output = run(large_input)
assert abs(float(large_output) - 50.0) < 1e-12, "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / 10 11 10`|`50.0`| 1 回の増加と 1 回の減少を含む最小の有効な履歴 |
 |`5 / 10 10 12 12 9`|`40.0`| ゼロの変更は無視する必要があります。 
|`5 / 100 110 105 115 110`|`66.66666666666667`| 同じ大きさの複数の増加と減少 |
 |`4 / 1.5 2.5 2.5 1.0`|`40.0`| 端数価格と変更されていない境界ペア |
 | 100001 交互価格 |`50.0`| 大入力時のリニアなパフォーマンス |

 元のステートメントでは、少なくとも 1 つの増加と 1 つの減少が保証されているため、真にすべてが等しい入力は有効な入力領域の外にあります。 代わりに、テストは、問題の保証に違反することなく同じ実装ブランチを実行する、そうでなければ有効な履歴内に等しい連続値を配置します。 

## 特殊なケース

 負の動きの場合、アルゴリズムは明示的に追加します。`-change`それよりも`change`。 の上```
3
10 7 9
```最初の違いは`-3`、 それで`down_sum`になる`3`、 ない`-3`。 2つ目の違いは、`+2`、 それで`up_sum`になる`2`。 平均は次のとおりです`2`そして`3`、与える`RS = 2/3`そして`RSI = 40.0`。 これはステートメント内の符号要件を直接処理します。 

価格が変わらない場合は、```
4
10 10 12 9
```最初の差はゼロなので無視されます。 次の違いは、`+2`そして最後の違いは`-3`。 蓄積された値は、`up_sum = 2`、`up_count = 1`、`down_sum = 3`、 そして`down_count = 1`、生産`40.0`。 ゼロの動きはどちらの平均にも属しません。 

最初の価格については、```
3
10 11 10
```ループは 2 番目の価格から始まるため、比較は次のようになります。`11 - 10`そして`10 - 11`。 最初の価格を存在しない以前の価格と比較する試みはありません。 上昇平均と下降平均は、`1`そして`1`、与える`RS = 1`そして`RSI = 50.0`。 

端数価格については、次の点を考慮してください。```
4
1.5 2.5 2.5 1.0
```変更点は、`+1.0`、`0.0`、 そして`-1.5`。 ゼロは無視され、次のようになります。`aveUP = 1.0`そして`aveDOWN = 1.5`。 結果の RSI は次のようになります。`40.0`。 価格を次のように読み取る`float`入力に浮動小数点測定値を含めることが明示的に許可されているため、値が必要です。 

最後に、このアルゴリズムは、少なくとも 1 つの価格が上昇し、少なくとも 1 つの価格が下落するという問題の保証に依存しています。 つまり、`up_count > 0`そして`down_count > 0`スキャン後に、ゼロ除算のための人為的な処理を行わずに、両方の平均を安全に計算できます。
