 ## 解決策
 ## 問題の理解

 この問題は、周囲温度が 70 度の部屋で 210 度から開始されるコーヒーをモデル化します。 その温度はニュートンの冷却の法則に従い、

 [
 T(t)=T_s+(T_0-T_s)e^{-kt}。 
】

 ここで、(T_s=70)、(T_0=210)、および未知の冷却定数 (k) は、指定された校正点によって決定されます。15 分後、コーヒーは 120 度まで冷却されます。 すべてのテスト ケースに対して目標温度 (T(t)) が与えられ、コーヒーがその温度に達する時間を分単位で出力する必要があります。 公式声明には、これらの量とサンプル出力が正確に記載されています。 

アルゴリズムの観点から見ると、有効な入力サイズは非常に小さいです。 独立した温度クエリは (n) 個だけあり、各クエリには一定数の算術演算と対数演算が必要です。 時間制限は 1 秒、メモリ制限は 256 MB であるため、多数のテスト ケースを直線的に通過することさえ簡単です。 方程式を直接反転できる場合、数値シミュレーションや反復手法を使用する理由はありません。 

物理的に意味のある目標温度は、初期温度と周囲温度の間にあります。 (T=210) の場合、コーヒーはそこから始まるため、答えは正確に 0 です。 (T=120) のようなターゲットの場合、キャリブレーション条件により、答えは 15 になります。 モデルは上から 70 に近づくため、70 未満の目標は有限の時間に達成されることはありません。 70 に等しい目標も同様に漸近的にのみ近づきます。 このステートメントでは、各テスト値を正の整数としてのみ説明しているため、これらの非物理的な値は、冷却モデルの意図した領域の外にあるものとして理解するのが最もよいでしょう。 

たとえば、入力```
1
210
```開始温度に到達するまでに冷却時間が必要ないため、出力は 0 になります。 対数引数が常に厳密に 1 より大きいと仮定する不用意な実装でも、これを正しく計算できますが、誤った式によって特殊なケースが誤って導入される可能性があります。 

入力用```
1
120
```正しい出力は 15 です。キャリブレーション ポイント自体は保存する必要があります。 (k) を四捨五入小数で近似しすぎると、わずかに異なる値が生成され、精度が不必要に失われる可能性があります。 

室温に近い対象物などの場合```
1
71
```指数曲線が 70 付近で徐々に遅くなるため、答えはサンプル値よりもはるかに大きくなります。冷却時間が小さな定数によって制限されると仮定したり、温度を分ごとにシミュレートしたりする実装では、必要な実数値の答えを正確に得ることができません。 

## アプローチ

 強引な数値アプローチでは、小さな時間増分で冷却プロセスをシミュレートし、(T(t)) を繰り返し評価し、シミュレートされた温度がターゲットに十分に近づいたときに停止することができます。 ニュートンの公式は選択した任意の時点の温度を直接示すため、これは概念的には簡単です。 問題は、答えが実数であるため、必要な精度を与える自然な離散時間ステップが存在しないことです。 (10^{-6}) 分のステップを試し、71 度付近の温度を約 72 分間カバーする必要がある場合、1 回のテストで約 7,200 万回の評価が必要になる可能性があります。 (n) 個のテスト ケースでは、すぐに時間がかかりすぎて、ステップをさらに減らすと状況が悪化するだけです。 

より洗練された数値総当りでは、時間通りに二分探索を使用します。 温度は単調減少するので、中点を繰り返し確認することで目標温度に相当する時間を求めることができます。 倍精度を得るには約 60 ～ 100 回の反復で十分であるため、このアプローチは実際には十分に高速です。 ただし、正確な代数逆関数を持つ方程式を解くので、反復機構は不要になります。 

重要な観察は、未知数 (k) を数値的に推定する必要がないということです。 キャリブレーションポイントは対数形式で正確に与えます。 (T_s=70)、(T_0=210)、および (T(15)=120) を代入すると、次のようになります。 

[
 120=70+140e^{-15k}、
 】

 それで

 [
 50=140e^{-15k}、
 】

 したがって

 [
 e^{-15k}=\frac{5}{14}。 
】

 自然対数を取ると、

 [
 k=\frac{\ln(14/5)}{15}。 
】

 ここで、任意の目標温度 (T) について、

 [
 T=70+140e^{-kt}。 
】

 並べ替えると、

 [
 e^{-kt}=\frac{T-70}{140}。 
】

 もう一度対数を取ると、

 [
 -kt=\ln\left(\frac{T-70}{140}\right),
 】

 それで

 [
 t=\frac{\ln\left(\frac{140}{T-70}\right)}{k}。 
】

 (k) の値を代入すると、

 [
 \箱入り{
 t=
 15\frac{\ln\left(\frac{140}{T-70}\right)}
 {\ln(14/5)}
 }。 
】

 温度関数が単調であるため、強引なアプローチは機能しますが、代数が直接提供できる値を検索するために計算が費やされます。 指数方程式を逆にできるという観察により、すべてのテスト ケースの作業量が一定に減ります。

 ## アルゴリズムのチュートリアル

 1. 温度クエリの数を読み取ります。 各クエリは独立しているため、テスト ケース間で維持する必要のある状態はありません。 
2. 目標温度 (T) を読み取ります。 固定の物理定数はすでにわかっています。部屋の温度は 70 度、コーヒーの開始温度は 210 度、校正点は 15 分後の 120 度です。 
3. 時間を直接計算します。 

[
 t=
 15\frac{\ln(140/(T-70))}
 {\ln(14/5)}。 
】

 分子は要求された温度に対する冷却方程式の逆数から得られ、分母は冷却定数を決定するために使用される校正測定から得られます。 

1. 結果の浮動小数点値を出力します。 裁判官は十分に正確な実数を受け入れるため、固定の小数点以下の桁数に四捨五入する必要はありません。 

機能する理由: ニュートン方程式を再構成すると、指数項が 1 から 0 に向かって連続的に減少するため、すべての目標温度は正確に 1 つの有限時間に対応します。キャリブレーション ポイントは唯一の未知のパラメーター (k) を決定し、2 番目の対数が分離 (t) します。 したがって、各クエリに対して出力される値は、指定された冷却モデルによって表される時間と正確に一致します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())

    denominator = math.log(14 / 5)

    for _ in range(n):
        temperature = int(input())

        time = 15 * math.log(140 / (temperature - 70)) / denominator
        print(time)

if __name__ == "__main__":
    solve()
```分母はすべてのテスト ケースで一定であるため、繰り返し計算されるのではなく、1 回だけ計算されます。 これは、校正測定値の対数形式を表します。 

目標温度ごとに、`temperature - 70`コーヒーが室温を超える量です。 140 をこの量で割ると、指数係数の逆数が得られます。 自然対数を取ると、時間依存の指数が分離されます。 

15 による乗算と除算`log(14 / 5)`既知の校正点を組み込みます。 計算を浮動小数点で維持すると、冷却定数を手動で近似することによる丸め誤差の発生を回避できます。 

Python の整数には任意の精度があり、主な計算には Python の倍精度浮動小数点が使用されるため、整数オーバーフローの問題はありません。`float`。 数学的に重要な唯一の境界は`temperature - 70 > 0`、対数は正の引数を受け取る必要があるためです。

import io
import math
from contextlib import redirect_stdout

def solve():

    for _ in range(n):
        temperature = int(input())
        time = 15 * math.log(140 / (temperature - 70)) / denominator
        print(time)

input = sys.stdin.readline

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    try:
        with redirect_stdout(out):
            solve()
    finally:
        sys.stdin = old_stdin
        input = old_input

    return out.getvalue()
