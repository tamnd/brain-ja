 ## 解決策
 ## 問題の理解

 2 つのカレンダー日付を受け取ります。 最初の日付は今日を表し、2 番目の日付は予定されている会議を表します。 各日付は、次のように月名、日番号、年として記述されます。`July 5, 2019`。 

ここでのタスクは、2 つの日付の間の日数を決定することです。 両方の日付が同じ場合、会議は今日になります。 会議の日付が早い場合は、会議が何日遅れているかを報告する必要があります。 それ以外の場合は、会議までの残り日数を報告します。 この声明では、うるう年を考慮する必要がないことが明確に述べられています。 

ここには、大きな配列、グラフ、または繰り返されるテスト ケースはありません。 入力には正確に 2 つの日付が含まれているため、短い固定月数にわたる線形スキャンでも実質的には一定時間になります。 したがって、1 秒の制限で十分です。 主な課題はパフォーマンスではなく、人間が判読できる日付を、2 つの日付を安全に比較および減算できる表現に変換することです。 

最初のエッジケースは平等です。 例えば、```
January 10, 2020January 10, 2020
```生成する```
It is today
```会議の日付が今日より大きいかどうかだけをチェックし、それ以外の場合は過去の日付として扱う不注意な実装では、会議が 1 日または 0 日遅れていると誤って報告されてしまいます。 

2 番目のエッジケースは、来月の会議です。 例えば、```
January 31, 2020February 1, 2020
```1日の差があります。 日数の差だけを数えると、次のようになります。`-30`、月の境界を完全に無視します。 

3 番目のエッジケースは、前月の会議です。 例えば、```
March 1, 2020February 28, 2020
```2 月は 28 日であり、閏年は無視されるため、問題の簡略化されたカレンダーでは 2 日遅れます。 日付フィールドのみを比較するソリューションでは、次のようになります。`28 > 1`会議が将来行われると誤って結論付ける可能性があります。 

4 番目のエッジ ケースは、年の境界です。 例えば、```
December 31, 2019January 1, 2020
```1日の差があります。 年を含めずに月と日を比較すると、順序を簡単に逆転させることができます。 

## アプローチ

 直接的な総当たりアプローチでは、最初の日付から開始して会議の日付に達するまで 1 日ずつ繰り返し進めるか、会議がすでに開催されている場合は繰り返し後戻りします。 すべての遷移が正確に 1 暦日を表すため、これは正しいです。 ただし、実行時間は日付を区切る日数によって異なります。 この問題では入力の年に関する数値限界が公開されていないため、このアプローチには有用な固定上限がなく、大まかに必要な値が必要になる可能性があります。`365 * |year_difference|`繰り返し。 

もっとすっきりした表現があります。 すべての月の長さがわかっており、うるう年は無視できるため、すべての日付に絶対的な日番号を割り当てることができます。 日付の絶対位置は、その日付より前の完全な年数に、その前のすべての完全な月による日数と、その月内の日付を加えたものです。 

たとえば、日付が 3 月 10 日の場合、1 月と 2 月のすべての日はすでにその前になっています。 両方の入力日付がこの表現に変換されると、カレンダーの計算全体が通常の整数の減算になります。 

一度に 1 日ずつ進めるとカレンダーが正確にモデル化されるため、総当り攻撃は機能しますが、1 日に 1 回の操作を実行するため失敗します。 すべての日付を絶対日インデックスにマッピングできるという観察により、数千または数百万の個々の遷移を 2 つの変換と 1 つの減算で置き換えることができる可能性があります。 

月の長さは次のように保存できます。`[31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]`。 うるう年は明示的に除外されるため、2 月は常に 28 日になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(D) | お(1) | 日付が離れていると遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ここ`D`2 つの日付の間の日数です。 最適なソリューションでは 12 か月の長さのみを検査しますが、これは継続的な作業です。 

## アルゴリズムのチュートリアル

 1. 各月の日数をカレンダー順に保存します。 閏年はこの問題に含まれないため、2 月は 28 日に固定されます。 
2. 各入力行を月名、日、年に解析します。 日の後のカンマはテキスト形式の一部であるため、日と年を整数に変換する前にカンマを削除するのが最も簡単です。 
3. 各月の名前を数値の月インデックスに変換します。 これにより、月の長さの配列を直接使用できるようになります。 
4. 各日付を絶対的な日数に変換します。 日付より前のすべての完全な年から開始し、貢献します`year * 365`日々。 次に、現在の月の前のすべての完全な月の長さを追加し、最後に現在の日を追加します。 
5. 会議の絶対日から最初の日の絶対日を減算します。 正の結果は会議が将来に行われることを意味し、ゼロは会議が今日であることを意味し、負の結果は会議がすでに終了したことを意味します。 
6. 差の符号に従って回答をフォーマットします。 プラスの違いを得るには`d`、あることを印刷します`d`会議までの日数。 ゼロの場合は、印刷します`It is today`。 負の差の場合は、次を使用します。`-d`遅れた日数として。 

これが機能する理由は、絶対日表現によって把握されます。 通常の各年はちょうど 365 日を占め、毎月はその固定日数を占めます。 したがって、暦日で 1 日離れている 2 つの日付には、ちょうど 1 だけ異なる絶対日番号が与えられます。 したがって、減算は正確に日付を区切る日数になります。 また、その符号によって時系列の順序も示されるため、最終メッセージで間違ったケースが選択されることはありません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline
MONTHS = {    "January": 1,    "February": 2,    "March": 3,    "April": 4,    "May": 5,    "June": 6,    "July": 7,    "August": 8,    "September": 9,    "October": 10,    "November": 11,    "December": 12,}
DAYS_IN_MONTH = [    31, 28, 31, 30, 31, 30,    31, 31, 30, 31, 30, 31]

def parse_date(s):    month_name, rest = s.split()    day, year = rest.split(",")
    return MONTHS[month_name], int(day), int(year)

def to_day_number(date):    month, day, year = date
    total = year * 365
    for i in range(month - 1):        total += DAYS_IN_MONTH[i]
    total += day    return total

def solve():    first = input().strip()    meeting = input().strip()
    first_date = parse_date(first)    meeting_date = parse_date(meeting)
    first_day = to_day_number(first_date)    meeting_day = to_day_number(meeting_date)
    diff = meeting_day - first_day
    if diff == 0:        print("It is today")    elif diff > 0:        print(f"There are {diff} days until your meeting")    else:        print(f"Sorry you are {-diff} days late")

if __name__ == "__main__":    solve()
```

`parse_date`日付の正確なテキスト構造を処理します。 分割`July 5, 2019`与える`July`そして`5, 2019`、その後、2 番目の部分をカンマで分割すると、数値の日と年が生成されます。`to_day_number`意図的に使用する`year * 365`、閏年を意識した式ではなく。 これはソリューションによって導入された近似ではなく、問題によって指定されたカレンダー モデルそのものです。 

前月のループでは、`range(month - 1)`。 1 月の場合、これは 0 回実行されます。これは、1 月より前に完全な月がないため、正しい境界条件です。 3 月の場合、1 月と 2 月、つまり 3 月までの完全な 2 か月が処理されます。 

Python の整数はオーバーフローしないため、大きな年に対して特別な処理は必要ありません。 減算は、両方の日付が同じ座標系に変換された後にのみ実行されるため、月や年をまたぐ場合に別々のケースが発生することが回避されます。

 ## 特殊なケース

 日付が等しい場合は、次の点を考慮してください。```
January 1, 1January 1, 1
```どちらの日付もまったく同じ絶対日番号を受け取ります。 それらの差はゼロであるため、アルゴリズムは等価分岐を選択して出力します。`It is today`。 この場合、特別なカレンダー計算は必要ありません。 

月の境界については、次のことを考慮してください。```
January 31, 2020February 1, 2020
```1 月は 31 日になります。 最初の日付には絶対位置があります`year * 365 + 31`、2番目のものは`year * 365 + 31 + 1`, したがって、それらの違いはちょうど 1 です。 これにより、日フィールドを直接減算する実装が捕捉されます。 

過去の会議については、次の点を考慮してください。```
March 1, 2020February 28, 2020
```3 月 1 日の前には 2 月の 28 日があり、2 月 28 日にはその日の位置の前に 2 月の最初の 27 日しかありません。 絶対的な位置は 2 つ異なり、会議の位置は小さくなります。 アルゴリズムが取得するのは、`diff = -2`、表示された大きさに対してそれを否定し、出力します`Sorry you are 2 days late`。 

年の境界については、次の点を考慮してください。```
December 31, 2019January 1, 2020
```最初の日付は 2019 年で表される最終日であり、2 番目の日付はその直後です。 年の寄与は 365 ずつ変化し、月の寄与はリセットされますが、絶対表現では両方の変化が自動的に吸収されます。 結果として生じる差は 1 です。 

最後に、2 月は常に 28 日として扱う必要があります。 この問題により、うるう年の処理が明示的に削除されるため、`February 28, 2020`続いて`March 1, 2020`この問題のカレンダー モデルには 1 日のズレがあります。 うるう年のロジックを追加すると、ステートメントが要求しない動作が導入される可能性があります。
