 ## 解決策
 ## 問題の理解

 教室は、(n \times n \times n) 個のサブルームの立方体です。 各サブルームには 1 人の生徒の年齢が含まれており、入力により層ごとに年齢が (n) 正方形 (n \times n) グリッドとして与えられます。 2 つのサブルームは、サブルーム自体が含まれない場合を除き、3 つの座標がすべての次元で最大 1 つ異なる場合に隣接しています。 したがって、内部のサブルームには 26 の隣接サブルームがありますが、面、端、コーナーの近くのサブルームにはそれより少ないサブルームがあります。 

生徒の年齢が、隣接するすべてのサブルームの年齢よりも厳密に大きい場合、その生徒はリーダーとなります。 平等だけでは十分ではないため、年齢が隣り合った 2 人の生徒が両方ともリーダーになることはできません。 トラブルメーカーは逆の条件を満たさなければなりません。隣接する生徒の年齢が少なくとも同じくらい大きくなければならず、生徒の隣接するサブルームにはリーダーが存在してはなりません。 必要な出力は、両方の条件を満たすサブルームの数だけです。 

この問題で使用できるステートメントでは、(n) の数値の上限は明らかにされていませんが、制限時間は 1 秒で、教室には (n^3) 個の値が含まれています。 入力だけを読み取るにはすでに (\Omega(n^3)) の作業が必要であるため、意図したソリューションでは各サブルームを一定の回数だけ処理する必要があります。 (O(n^6)) メソッドは (n) が大きくなるにつれて不適切ですが、(O(n^3)) メソッドは検査する必要がある入力量に一致します。 

最初のエッジ ケースは、サブルームが 1 つだけある教室です。 入力用`1`に続く`7`、正しい出力は次のとおりです。`0`。 唯一の生徒には隣接するサブルームがないため、隣接するすべての生徒よりも実質的に年上であり、リーダーです。 「より大きな隣接セルが見つかりませんでした」を学生がリーダーではない証拠として扱う不注意な実装では、このセルが誤ってカウントされてしまいます。 

2 番目のエッジケースは平等です。 入力用```
2
4 4
4 4
5 5
5 5
```正しい出力は`8`。 どの生徒にも少なくとも 1 人は同じ年齢かそれ以上の年齢の隣人がいます。そのため、誰もリーダーではありません。 リーダーもどこにもいないので、8人の生徒は全員が問題児の条件を両方とも満たしている。 使用する`>=`セルがリーダーであるかどうかをテストする場合、一部の同じ値のセルがリーダーとして誤って分類されてしまいます。 

3 番目のエッジ ケースは境界セルです。 (n=2) の場合、コーナーに隣接する可能性のある位置は 26 ではなく 7 つだけです。```
2
1 0
0 0
0 0
0 0
```正しい出力は`0`。 age-1 のコーナーがリーダーであり、他のすべてのセルがそれに隣接しています。 26 個のオフセットがすべて存在すると仮定したソリューションでは、キューブの外側にアクセスしたり、無関係なセルと誤って比較したりする可能性があります。 

## アプローチ

 直接的なブルートフォース解釈により、サブルームのすべてのペアを比較し、そのペアが隣接しているかどうかを判断し、それらの比較を使用してリーダーとトラブルメーカーを見つけることができます。 これは正しいです。すべての関連関係は 2 つのサブルーム間にあるため、最終的にはすべての隣接関係が検出されます。 ただし、(n^3) 個のサブルームがあり、すべてのペアをチェックするには、最悪の場合、(n^3 \cdot n^3 = n^6) 個のペア チェックが必要になります。 2 つの条件に対する追加の作業を考慮する前でさえ、これは 1 秒の制限でサポートできる範囲をはるかに超えています。 

問題の構造により、検査対象となる近傍がはるかに小さくなります。 固定サブルームの場合、考えられるすべての近傍は、(-1) から (1) までの 3 つの座標オフセットによって記述されます。 このようなオフセットは (3^3-1=26) だけあり、境界位置は立方体から出るオフセットを単純に破棄します。 したがって、ある生徒がリーダーであるかどうかを判断するには、(n) に関係なく一定の時間がかかります。 

重要な 2 番目の依存関係があります。 ある生徒がトラブルメーカーであるかどうかは、その生徒自身の年齢だけでなく、近隣の生徒がリーダーであるかどうかにも左右されます。 最初にリーダーの完全なセットを計算する必要があります。 その情報が保存されると、2 回目のローカル スキャンで、各非リーダーがリーダーに接触したかどうかを判断できます。 これにより、問題全体が (n^3) 個のセルにわたる 2 つのパスに変換され、パスごとに最大 26 個の隣接セルが考慮されます。 

ブルートフォース手法は、すべての隣接関係を明示的に検出するため機能しますが、決して隣接することのできないペアを多数検出するため失敗します。 隣接関係が固定半径の 3 次元近傍であるという観察により、全ペアの比較をセルごとの一定量のローカル作業に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^6)) | (O(n^3)) | 遅すぎる |
 | 最適 | (O(n^3)) | (O(n^3)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n^3) 個の年齢を 3 次元配列に読み取ります`a[z][r][c]`。 座標を明示的に保つことで、3 次元近傍テストが簡単になり、入力は自然に (n) 個の 2 次元レイヤーとして到着します。 
2. 3次元ブール配列を配置する`leader`同じ寸法で。 最初は、どのポジションもリーダーではないとみなされます。 
3. ポジションごとに`(z, r, c)`、すべてのオフセットを検査します`(dz, dr, dc)`各オフセットが属する場所`{-1, 0, 1}`そして 3 つのオフセットはすべてゼロではありません。 結果の座標が立方体から外れる場合は、オフセットを無視します。 これらはまさに有効な隣接サブルームです。 
4. マーク`(z, r, c)`その年齢がすべての有効な隣人の年齢よりも厳密に大きい場合、リーダーとして。 境界位置には隣接する位置が少なくなりますが、有効な座標のみが検査されるため、同じ比較が機能します。 
5. すべての位置を 2 回目のパスで通過します。 リーダーは最初のトラブルメーカー条件を満たすことができないため、リーダーの場合はそのポジションをスキップします。 
6. 残りの各位置について、同じ 26 個の可能な隣接オフセットを再度検査します。 少なくとも 1 人の有効な隣人がリーダーとしてマークされている場合、この生徒はトラブルメーカーではありません。 隣接するリーダーが見つからない場合は、答えをインクリメントします。 
7. 最終的なカウントを出力します。 

なぜ機能するのか: 最初のパスの後、`leader[z][r][c]`これは、その生徒の年齢が隣接するすべての年齢よりも厳密に大きい場合に当てはまります。 2 番目のパスでは、すべての候補が非リーダーであることがすでにわかっており、スキャンでは、隣接するセルがリーダーではないという条件が正確にチェックされます。 したがって、必要な条件が両方とも満たされる場合、セルは正確にカウントされ、すべての有効なセルが 1 回検査されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    a = []
    for _ in range(n):
        layer = []
        for _ in range(n):
            layer.append(list(map(int, input().split())))
        a.append(layer)

    leader = [
        [[False] * n for _ in range(n)]
        for _ in range(n)
    ]

    for z in range(n):
        for r in range(n):
            for c in range(n):
                age = a[z][r][c]
                is_leader = True

                for dz in (-1, 0, 1):
                    nz = z + dz
                    if nz < 0 or nz >= n:
                        continue

                    for dr in (-1, 0, 1):
                        nr = r + dr
                        if nr < 0 or nr >= n:
                            continue

                        for dc in (-1, 0, 1):
                            nc = c + dc
                            if nc < 0 or nc >= n:
                                continue

                            if dz == 0 and dr == 0 and dc == 0:
                                continue

                            if a[nz][nr][nc] >= age:
                                is_leader = False
                                break

                        if not is_leader:
                            break

                    if not is_leader:
                        break

                leader[z][r][c] = is_leader

    answer = 0

    for z in range(n):
        for r in range(n):
            for c in range(n):
                if leader[z][r][c]:
                    continue

                has_adjacent_leader = False

                for dz in (-1, 0, 1):
                    nz = z + dz
                    if nz < 0 or nz >= n:
                        continue

                    for dr in (-1, 0, 1):
                        nr = r + dr
                        if nr < 0 or nr >= n:
                            continue

                        for dc in (-1, 0, 1):
                            nc = c + dc
                            if nc < 0 or nc >= n:
                                continue

                            if dz == 0 and dr == 0 and dc == 0:
                                continue

                            if leader[nz][nr][nc]:
                                has_adjacent_leader = True
                                break

                        if has_adjacent_leader:
                            break

                    if has_adjacent_leader:
                        break

                if not has_adjacent_leader:
                    answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```入力ループの構成`a`として`a[z][r][c]`、 どこ`z`層です、`r`はそのレイヤー内の行であり、`c`コラムです。 このステートメントはレイヤーを連続して与えるため、入力の変換は必要ありません。 

最初のトリプル ループはリーダー パスを実装します。 比較には、`>=`、 ない`>`なぜなら、学生は厳密にすべての隣人よりも年上でなければならないからです。 同じ年齢以上の近隣者を 1 人見つけるだけでリーダー ステータスを拒否できるため、ネストされたループを早期に終了できます。 

境界チェックはアクセス前に行われます`a[nz][nr][nc]`。 これにより、同じ 26 オフセットのセットが、面、エッジ、またはコーナーの特別なケースを必要とせずに、内部セルと境界セルに使用できるようになります。 

2 番目の三重ループは、すべてのリーダーを拒否することから始まります。 リーダー以外のすべてについて同じ近傍を検索しますが、今回は事前に計算された値を読み取ります。`leader`年齢を比較するのではなく、配列を使用します。 候補を拒否するには隣接するリーダーが 1 つあれば十分であるため、このパスでも早期終了が使用されます。 

Python の整数はオーバーフローせず、答えは最大でも (n^3) です。 メイン メモリのコストは、age 配列にセルごとに 1 つのブール値を加えたものです。 の使用`input = sys.stdin.readline`教室に多くの整数が含まれている場合に、不必要なオーバーヘッドを回避します。 

## 実用的な例

 ### サンプル 1

 最初のサンプルでは、3 つのセルがリーダーです。 ゼロベースの座標の使用`(layer, row, column)`、 彼らです`(0, 0, 0)`13歳になると、`(0, 1, 2)`18歳で、そして`(1, 2, 0)`これらのリーダーが判明した後、5 人の非リーダーは、自分の 26 セルの近隣エリアでリーダーを持たなくなります。 

次の表は、2 つの論理パス中の層ごとの重要な状態を示しています。 

| レイヤー | この層で発見されたリーダー | この層によって提供されたトラブル候補 |
 | --- | --- | --- |
 | 0 |`(0,0,0)`、`(0,1,2)`| 0 |
 | 1 |`(1,2,0)`| 0 |
 | 2 | なし | 5 |

 最初の 2 つのレイヤーには、3 つのリーダーがすべて含まれています。 これらのレイヤー内のすべての非リーダーは、少なくとも 1 つのレイヤーに隣接しています。 最後の層では、年齢を表す 5 つのセルが表示されます。`14, 15, 16, 8, 7`隣接するリーダーがないので、最終的な答えは次のようになります。`5`。 これは、トラブルメーカーを数える前にリーダー情報を計算する必要がある理由を示しています。 

### サンプル 2

 2 番目のサンプルには 8 つのセルがあり、最初のレイヤーのすべての年齢は 4 に等しく、2 番目のレイヤーのすべての年齢は 5 に等しくなります。すべてのセルには、年齢が等しいかそれ以上の隣接するセルがあるため、リーダーはまったくありません。 

| レイヤー | 年齢 | リーダー | トラブル候補 |
 | --- | --- | --- | --- |
 | 0 | 全4 | 0 | 4 |
 | 1 | 全5 | 0 | 4 |

 リーダー配列は完全に false であるため、すべてのセルが 2 番目の条件を通過します。 8 つのセルすべてがカウントされ、必要な出力が得られます。`8`。 これは、隣接する年齢が等しいとリーダーシップが妨げられることを具体的に裏付けています。
