 ## 解決策
 ## 問題の理解

 Ken Ken パズルは (n \times n) グリッドであるため、正確に (n^2) 個のセルが含まれます。 それらのセルの一部はすでに本に記入されています。 これらは (k) 個の景品セルなので、ソルバーによって埋める必要はありません。 

タスクは単に、埋める必要のあるセルがいくつ残っているかを判断することです。 すべてのセルは (k) 個の景品の 1 つであるか、入力する必要があるセルの 1 つであるため、答えは次のようになります。 

[
 n^2-k。 
】

 入力には、正方形グリッドの辺の長さ (n) と、その後にすでに塗りつぶされているセルの数 (k) が含まれます。 出力は、まだエントリが必要なセルの数です。 元の問題では (n) が正であることだけが示されているため、複雑さが入力要素の大規模なコレクションに依存するデータ構造やアルゴリズムは必要ありません。 計算全体は 1 回の乗算と 1 回の減算で構成されます。 

便利なエッジ ケースは、唯一のセルが既に埋められている (1 \times 1) パズルです。```
1
1
```正しい出力は次のとおりです。```
0
```少なくとも 1 つのセルが入力される必要があると仮定した不用意な解決策では、誤って (1) が生成される可能性があります。 

もう 1 つの境界ケースは、すべてのセルが景品である場合です。 例えば：```
3
9
```(3^2=9) 個のセルがあり、9 つすべてがすでに入力されているため、答えは次のようになります。```
0
```ここでよくある間違いは、景品を減算せずに (n^2) を出力することです。 

反対の極端な例として、2 つの景品を含む (4 \times 4) パズルを考えてみましょう。```
4
2
```合計で (16) 個のセルがあり、(2) 個は作業を必要としないため、(16-2=14) 個のセルを埋める必要があります。 正しい出力は次のとおりです。```
14
```## アプローチ

 直接的なブルートフォース解釈では、すべての (n^2) 個のセルを明示的に考慮し、(k) 個の既に入力されたセルに含まれていないセルがいくつあるかを数えます。 すべてのセルが塗りつぶされたカウントまたは残りのカウントのいずれかに 1 回だけ寄与するため、このアプローチは正しいです。 最悪の場合の操作数は (n^2) に比例し、グリッド セルごとに 1 回の訪問が行われます。 

ただし、この問題では景品の場所はわかりません。 カウントのみが表示されます。 つまり、個々の細胞の検査に役立つ情報はないということです。 グリッドに (n^2) 個のセルがあり、そのうちちょうど (k) 個が既に埋められていることがわかれば、残りのセルの数がすぐに決まります。 

最適な解決策を導き出す観察は、単に景品の場所は重要ではないということです。 必要なのは、セルの総数とすでに完了したセルの数だけです。 (n^2-k) を計算すると、すべてのセルを訪問する作業が一定数の算術演算に減ります。

 ## アルゴリズムのチュートリアル

 1. Ken Ken グリッドの辺の長さ (n) を読み取ります。 辺の長さ (n) の正方形には、(n \times n=n^2) 個のセルが含まれます。 
2. すでに入力されているセルの数 (k) を読み取ります。 これらの細胞は、私たちが今後行わなければならない作業から除外されます。 
3. (n^2-k) を計算します。 これはまさに景品ではないセルの数です。 
4. 結果を印刷します。 

### なぜ効果があるのか

 完全なグリッドには、正確に (n^2) 個のセルが含まれます。 (k) 個の景品セルはすでに入力されているため、再度入力する必要のない正確に (k) 個のセルを占めます。 1 つおきのセルを埋める必要があります。 したがって、残りのセル数は正確に (n^2-k) となり、これがアルゴリズムによって出力されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())

print(n * n - k)
```最初`input()`グリッドの寸法を読み取ります。 2 番目は景品の数を読み取ります。 塗りつぶされたセルの位置が入力に表示されることはないため、グリッドを保存する必要はありません。 

表現`n * n`セルの総数を計算します。 引き算`k`まだ値が必要な数値を与えます。 Python の整数は、オーバーフローの問題なく算術演算を処理します。 

また、ループがないため、実装はアルゴリズムのウォークスルーからの数学的観察を直接反映しています。 

## 実用的な例

 サンプル 1 の入力は次のとおりです。```

```実行は次のとおりです。 

| n | k | セルの総数 (n^2) | 残り (n^2-k) |

 グリッドには 16 個のセルがあり、2 つはすでに埋められています。 したがって、アルゴリズムは次のように出力します。`14`。 

サンプル 2 の入力は次のとおりです。```
6
3
```実行は次のとおりです。 

| n | k | セルの総数 (n^2) | 残り (n^2-k) |

 (6 \times 6) グリッドには 36 個のセルがあります。 3 つは景品なので、33 個のセルを埋める必要があります。 アルゴリズムは出力します`33`。 

これらの例は、寸法と景品の数のみが答えに影響を与えることを示しています。 グリッド内のそれらの位置は影響を与えません。

## テストケース

 次のテストでは、提供されたサンプル、可能な最小のグリッド、すべてのセルがすでに埋められているケース、およびより大きな算術ケースを実行します。```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    k = int(input())
    print(n * n - k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# Provided samples
assert run("4\n2\n") == "14\n", "sample 1"
assert run("6\n3\n") == "33\n", "sample 2"

# Minimum-size grid, with its only cell already filled
assert run("1\n1\n") == "0\n", "minimum grid"

# Every cell is a freebie
assert run("3\n9\n") == "0\n", "all cells are freebies"

# Larger values, checking the arithmetic without constructing a grid
assert run("1000\n1\n") == "999999\n", "large grid"

# One cell remains to be filled
assert run("10\n99\n") == "1\n", "exactly one remaining cell"

 ## 特殊なケース

 最小サイズの場合```
1
1
```アルゴリズムは (1^2-1=0) を計算します。 セルは 1 つあり、すでに景品なので、埋めるものは何もありません。 減算では、特別な場合を除いて、ゼロの答えが自然に処理されます。 

全額無料の場合```
3
9
```アルゴリズムは (3^2-9=0) を計算します。 セルが残らないため、別の分岐は必要ありません。 この式はすでに状況を正確に表しています。 

セルが 1 つだけ残った場合、```
10
99
```グリッドには (10^2=100) 個のセルが含まれます。 (99) 個の景品を除くと、結果は (100-99=1) になります。 これにより、誤って 1 つ減算しすぎたり、セルの総数とまだ埋める必要があるセルの数を混同したりする実装が捕捉されます。 

これらすべてのケースで重要なプロパティは変更されていません。答えは、セルの合計数と既に入力されているセルの数にのみ依存します。 これらのセルの実際の位置に関する情報は必要ありません。
