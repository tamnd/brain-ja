 ## 解決策
 ## 問題ステートメント

 エンジニアリングプロジェクトには目標高さがある`n`そして寛容さ`k`。 プロジェクトは、実際の高さが範囲内にある場合にはいつでも受け入れられます。`k`両方のエンドポイントを含むターゲットのユニット。 

タスクは、許容可能な最小の高さと許容可能な最大の高さを決定するだけです。 

## 入力

 入力には 2 つの正の整数が含まれています。 まずは目標身長です`n`、2 番目は許容誤差です。`k`。 これらは別の行に記述されます。 

## 出力

 許容可能な高さの下限を 1 行目に、許容可能な高さの上限を 2 行目に出力します。 

## 問題の理解

 許容可能な間隔の中心は次のとおりです。`n`。 最大許容値だけ下に移動すると、許容される最小の高さが得られ、同じ量だけ上に移動すると、許容される最大の高さが得られます。 したがって、必要な 2 つの値は次のとおりです。`n - k`そして`n + k`。 

公式声明では上限を設けていない`n`または`k`、それらが正の整数であるというだけです。 制限時間は 1 秒、メモリ制限は 256 MB です。 このソリューションに必要なのは 2 つの算術演算と 2 つの出力のみであるため、入力値がどれほど大きくても実行時間は一定です。 ループ、配列、グラフ アルゴリズム、またはその他のデータ構造を使用する理由はありません。 

最初のエッジ ケースは、許容差がゼロの場合です。 例えば、```
5
0
```生成する```
5
5
```下限値と上限値が異なるはずだと仮定する不注意な解決策は間違っています。許容範囲がゼロであるということは、ターゲットの高さのみが許容されることを意味するためです。 

2 番目のエッジ ケースは、許容値がターゲットよりも大きい場合です。 例えば、```
2
5
```生成する```
-3
7
```ステートメントは次のことを要求しているため、下限エンドポイントは負の値になる可能性があります。`n - k`これは、計算された下限が正でなければならないという制限を直接課すものではありません。 答えをゼロに固定する実装では、必要な間隔が黙って変更されます。 

3 番目のエッジケースは次のような場合です。`n`そして`k`等しいです。 例えば、```
8
8
```生成する```
0
16
```下限の終点は正確にゼロであるため、包含区間の代わりに厳密な不等式を使用する実装は、この境界を誤って処理することになります。 

## アプローチ

 ブルートフォースアプローチでは、許容可能なすべての高さを次から生成できます。`n - k`を通して`n + k`、次に、最初と最後に生成された値を記憶します。 これは正しいです。許容可能な高さが 1 つの連続した包含区間を形成するからです。 ただし、正確に実行します`2k + 1`繰り返し。 もし`k`が非常に大きい場合、要求されたエンドポイントをすぐに取得できる場合でも、不必要な作業量が発生することを意味します。 

許容可能なセットが間隔であるため、ブルート フォースは機能しますが、必要なエンドポイントが 2 つだけであるという事実を利用できません。 重要な観察は、下限のエンドポイントが正確に`k`下に`n`、そして上端点は正確に`k`その上`n`。 中間の高さを調べる必要はありません。 

これにより、問題全体が 2 つの算術式に縮小されます。`n - k`そして`n + k`、続いて印刷します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | お(1) | 不必要で遅すぎる可能性があります |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 目標高さを読み取る`n`と寛容性`k`。 2 つの値を分離しておくと、エンドポイントの式が直接的になります。 
2. 下限値を次のように計算します。`n - k`。 これは、ターゲットの下で許容される最大の高さです。 
3. Compute the upper limit as`n + k`。 これは、ターゲットから最も遠い許容可能な高さです。 
4. 必要な出力順序に合わせて、下限値と上限値をそれぞれ別の行に出力します。 

### なぜ効果があるのか

 公差の定義では、許容可能な高さはすべて次の範囲にあるとされています。`n - k`そして`n + k`、包括的に。 この間隔の最小の数値は正確に`n - k`、最大の数値は正確に`n + k`。 アルゴリズムはこれら 2 つの値を直接出力するため、必要なエンドポイントは両方とも正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())

    print(n - k)
    print(n + k)

if __name__ == "__main__":
    solve()
```最初の 2 行は、個別の入力行からターゲットの高さと許容値を読み取ります。 ステートメントでは値に固定の上限を課さないため、ここでは Python 整数が適しています。 

2 つの算術式は、ステップ 2 と 3 のエンドポイント計算を直接実装します。 中間の許容可能な高さが答えに影響しないため、ループはありません。 

二人`print`呼び出しでは必要な順序が意図的に保持されます。 下側のエンドポイントが最初に表示され、次に上側のエンドポイントが続きます。 間隔のエンドポイントは反復ではなく直接取得されるため、インデックス付けや境界の問題はありません。 

## 実用的な例

 ### サンプル 1

 入力は`n = 5`そして`k = 2`。 

| ステップ |`n`|`k`| より低い`n-k`| アッパー`n+k`|
 | --- | --- | --- | --- | --- |
 | 入力を読み取る | 5 | 2 | | |
 | コンピューティングエンドポイント | 5 | 2 | 3 | 7 |
 | 出力 | 5 | 2 | 3 | 7 |

 ターゲットは 5 で、どちらかの方向に 2 単位を移動すると、間隔は 3 ～ 7 になります。アルゴリズムは、これら 2 つのエンドポイントを正確に生成します。 

### サンプル 2

 入力は`n = 7`そして`k = 3`。 

| ステップ |`n`|`k`| より低い`n-k`| アッパー`n+k`|
 | --- | --- | --- | --- | --- |
 | 入力を読み取る | 7 | 3 | | |
 | コンピューティングエンドポイント | 7 | 3 | 4 | 10 |
 | 出力 | 7 | 3 | 4 | 10 |

 ここではターゲットは 7 であるため、3 単位下方向は 4 を与え、3 単位上方向は 10 を与えます。これは、間隔が包括的であることも示しているため、計算された両方のエンドポイントが許容範囲に属します。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 2 つの算術演算と 2 つの出力演算のみが実行されます。 |
 | スペース | お(1) | 2 つの入力整数と一定数の変数のみが保存されます。 |

 公式の制限は 1 秒および 256 MB です。 このアルゴリズムは一定時間と一定メモリを使用するため、リソースの使用量は無視できます。 このステートメントでは明示的な最大値が提供されていないため、`n`または`k`、特徴づけるための有限の最大サイズの数値テストはありませんが、アルゴリズムは、整数の読み取りと出力のコストを除けば、その大きさに依存しません。 

## テストケース

 公式声明では、以下に示す 3 つのサンプルが提供されています。 カスタム テストは、ゼロ許容値、ゼロの下限エンドポイント、負の下限エンドポイント、等しいターゲットと許容値、大きな整数値をカバーします。 元のステートメントでは数値の上限が指定されていないため、指定された制約からリテラルの最大サイズ入力を構築することはできません。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())
    k = int(input())
    print(n - k)
    print(n + k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("5\n2\n") == "3\n7\n", "sample 1"
assert run("7\n3\n") == "4\n10\n", "sample 2"
assert run("8\n4\n") == "4\n12\n", "sample 3"

# custom cases
assert run("5\n0\n") == "5\n5\n", "zero tolerance"
assert run("5\n5\n") == "0\n10\n", "lower endpoint exactly zero"
assert run("2\n5\n") == "-3\n7\n", "negative lower endpoint"
assert run("8\n8\n") == "0\n16\n", "target equals tolerance"
assert run("1000000000000000000\n999999999999999999\n") == "1\n1999999999999999999\n", "large integers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`5 0`|`5 5`| ゼロトレランスと同等のエンドポイント |
 |`5 5`|`0 10`| 下限は正確にゼロ |
 |`2 5`|`-3 7`| 下の結果をクランプしてはならないことを確認します。 
|`8 8`|`0 16`| ターゲットと許容範囲が等しい |

 ## 特殊なケース

 いつ`k = 0`、正確な入力は次のとおりです```
5
0
```アルゴリズムは計算します`5 - 0 = 5`そして`5 + 0 = 5`したがって、出力は次のようになります```
5
5
```保存された 2 つの値が許容区間の正確な終点であるという不変条件は、区間に整数が 1 つしか含まれていない場合でも保持されます。 

許容値がターゲットよりも大きい場合、正確な入力は次のようになります。```
2
5
```アルゴリズムは最初に計算します`2 - 5 = -3`、 それから`2 + 5 = 7`、生産```
-3
7
```エンドポイント定義では、下位の結果が正のままである必要はありません。 算術演算は人為的な手段を使用せずに実行する必要があります。`max(0, ...)`。 

ターゲットが許容値と等しい場合、正確な入力は次のようになります。```
8
8
```下限のエンドポイントは、`8 - 8 = 0`、一方、上限の終点は`8 + 8 = 16`。 出力は```
0
16
```これにより、負の結果と非負の結果の間の正確な境界が検証され、1 ずつ調整せずに減算が実行されることが確認されます。 

入力値が非常に大きい場合でも、アルゴリズムはまったく同じ 2 つの演算を実行します。 例えば、```
1000000000000000000
999999999999999999
```与える```
1
1999999999999999999
```Python の整数型は、固定幅のオーバーフローを発生させずにこれらの値を処理し、アルゴリズムはどちらの数値にも比例してメモリを割り当てません。
