 ## 解決策
 ## 問題の理解

 メルセンヌ数の形式は次のとおりです。 

[
 M_p = 2^p - 1。 
】

 入力には指数 (p) が含まれており、タスクは (M_p) が実際に素数であるかどうかを判断することです。 必要な出力は小文字の単語です`true`プライムのときと`false`さもないと。 公式問題では、特にルーカス・レーマー素数性検定が求められます。これは、膨大な数を直接構築し、それを通常の試行分割でテストすることはすぐに不可能になるためです。 このステートメントでは、中間値が 32 ビットまたは 64 ビットの整数を超える可能性があるため、任意精度の算術演算が必要であることも警告しています。 

公式の制約では、(p) の数値の上限は規定されていません。 彼らが明らかにしているのは、意図した方法は、1 秒の時間制限と 256 MB のメモリの下で、サイズが標準のマシン整数を超える可能性のある数値を処理できる必要があるということです。 Python では、これは、任意精度の整数を直接使用し、(2^p-1) の約数を列挙しようとするアルゴリズムを避ける必要があることを意味します。 Lucas-Lehmer 検定は (p-2) モジュラー反復を実行し、すべての値が (2^p-1) 未満のままであるため、メモリ要件は数値ではなくメルセンヌ数のサイズに比例します。 

不注意な実装が失敗する可能性のある小さなケースがいくつかあります。 (p=2) の場合、数値は (2^2-1=3) であり、素数であるため、入力に対する出力は`2`は`true`。 次のように書かれたループ`for _ in range(p - 2)`は、ゼロ反復を実行することでこれを自然に処理しますが、これは初期値が正しく処理された場合に限ります。 

合成指数の場合、メルセンヌ数を素数にすることはできません。 たとえば、入力`4`与える

 [
 2^4-1=15、
 】

 したがって、正しい出力は次のとおりです`false`。 すべての入力指数が素数であると盲目的に仮定してルーカス・レーマー漸化式を実行する実装は、定理の前提条件に違反する可能性があります。 

素数指数とメルセンヌ素数の区別も、よくある罠です。 入力`11`素指数がありますが、

 [
 2^{11}-1=2047=23\cdot89、
 】

 したがって、正しい出力は次のとおりです`false`。 (p) が素数かどうかをテストするだけでは十分ではありません。 

最後に、最終的な答えが 1 つのブール値のみである場合でも、中間シーケンスは 64 ビット整数よりもはるかに大きくなる可能性があります。 たとえば、(p=61) は 61 ビットのメルセンヌ数を生成します。 C++ ソリューションには big-integer ライブラリが必要ですが、Python の組み込み`int`必要な演算はすでに提供されています。 

## アプローチ

 最も直接的なアプローチは、(M_p=2^p-1) を構築し、それを通常の素数テストでテストすることです。 合成整数の約数は平方根以下でなければならないため、試行的な除算は正しいです。 問題はその平方根の大きさです。 以来

 [
 \sqrt{2^p-1}\about2^{p/2}、
 】

 最悪の場合は、(2^{p/2}) 回の割り切りチェックが必要になります。 (p=61) でさえ、すでに数十億の可能な約数のスケールでチェックすることを意味するため、このアプローチはまったく不適切です。 

より良いアプローチは、メルセンヌ数の特殊な構造から得られます。 素数指数 (p) については、ルーカス・レーマーの定理によれば、(M_p=2^p-1) は、特定の漸化がゼロ モジュロ (M_p) で終了するときに正確に素数になります。 (s_0=4) から開始し、繰り返し計算します。 

[
 s_{i+1}=(s_i^2-2)\bmod M_p.
 】

 正確に (p-2) 回反復した後、結果の値が 0 である場合に限り、(M_p) は素数になります。 公式問題は、このテストを中心に明示的に設計されています。 

この総当たり法は、定義から素数を確立しようとするため機能しますが、テストされる数値には (p) に対して指数関数的に多くの可能な値があるため、失敗します。 Lucas-Lehmer の観察により、その膨大な検索を (p-2) モジュラー二乗のみで置き換えることができます。 算術演算は依然として (p) ビット整数に対して実行されますが、これは (2^{p/2}) 個の可能な約数を調べるよりも大幅に小さくなります。 

再帰を適用する前に、複合 (p) を拒否できます。 (p) が合成の場合、(2^p-1) も合成です。 (p) 自体が素数であるかどうかを確認するのにかかるコストは (O(\sqrt p)) だけであり、大きな素数指数に対する Lucas-Lehmer の作業と比較すると無視できます。 特殊なケース (p=2) は直ちに受け入れられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^{p/2})) 割り算チェック | (O(p)) ビット | 遅すぎる |
 | 最適 | (O(p)) 多倍長整数の反復 | (O(p)) ビット | 承認済み |

 (O(p)) 記述は、Lucas-Lehmer 反復をカウントし、各任意精度算術演算を 1 つの演算として扱います。 ビットレベルのモデルでは、(p) ビット整数の 2 乗は定数時間ではないためコストが高くなりますが、重要な改善点は指数関数的な反復回数を線形の反復回数に置き換えることです。 

## アルゴリズムのチュートリアル

 1. 指数 (p) を読み取ります。 入力は単一の整数で構成されているため、テスト ケースは 1 つだけです。 
2. (p=2) の場合、印刷します。`true`すぐに。 対応するメルセンヌ数は (3) であり、これは素数であり、ルーカス・レーマー漸化式は通常、この最小の指数に対して個別に定義されます。 
3. (p) が素数かどうかを確認します。 複合の場合は印刷する`false`。 

この拒否は因数分解から生じます

 [
 2^{ab}-1=(2^a)^b-1、
 】

 これは (p=ab) の場合は常に (2^a-1) で割り切れます。 したがって、合成指数は素数メルセンヌ数を生成することはできません。 
4. メルセンヌ数を次のように構築します。`m = (1 << p) - 1`。 左シフトすると正確に (2^p) が作成され、1 を引くと (2^p-1) が得られます。 
5. 次のようにして Lucas-Lehmer 状態を初期化します。`s = 4`。 これは、定理によって指定された固定の開始値です。 
6. 繰り返しを正確に (p-2) 回繰り返します。 反復ごとに置換`s`と

 [
 (s^2-2)\bmod m.
 】

 モジュロ演算は二乗後に実行されるため、保存された状態がモジュラス自体を超えて大きくなる必要はありません。 モジュロ演算がないと、中間整数は反復ごとに爆発的に増加します。 
7. 印刷`true`最終的な値が`s`がゼロであり、`false`さもないと。 素指数の場合、ルーカス・レーマーの定理により、このゼロ テストは (M_p) が素数になるために必要かつ十分になります。 

なぜ機能するのか: 初期化後、変数`s`は、Lucas-Lehmer シーケンスのモジュロ (M_p) に正確に対応する項です。 各ループ反復では次の項を定義する再帰が適用されるため、(p-2) 回の反復後には (s_{p-2}\bmod M_p) が含まれます。 ルーカス・レーマーの定理は、素数 (p>2) の場合、(s_{p-2}=0\pmod{M_p}) のときに正確に (2^p-1) が素数になることを示しています。 複合指数はすでに個別に拒否され、(p=2) が直接処理されました。 その結果、考えられるすべての入力が正しいブール結果に達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(n):
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2

    d = 3
    while d * d <= n:
        if n % d == 0:
            return False
        d += 2

    return True

def solve():
    p = int(input())

    if p == 2:
        print("true")
        return

    if not is_prime(p):
        print("false")
        return

    m = (1 << p) - 1
    s = 4

    for _ in range(p - 2):
        s = (s * s - 2) % m

    print("true" if s == 0 else "false")

if __name__ == "__main__":
    solve()
```の`is_prime`関数は指数にのみ適用され、巨大なメルセンヌ数には適用されません。 (\sqrt p) までの割り算をチェックし、処理後の候補もスキップします`2`。 

表現`(1 << p) - 1`より好ましい`2 ** p - 1`これは、メルセンヌ数の 2 進構造を直接表現しているためです。 Python の整数には任意の精度があるため、値が 64 ビットに収まらなくなった場合でも、この式と後続の二乗は機能します。 

ループが実行されます`p - 2`回ではなく`p - 1`または`p - 3`。 Lucas-Lehmer の定理は (s_0=4) で始まり、(s_{p-2}) を必要とし、正確に (p-2) 回の反復適用後に到達します。 

表現`(s * s - 2) % m`モジュロ演算をループ内に保持する必要があります。 すべての反復後にのみ削減すると、(M_p) よりも大幅に大きな数値が作成され、実装が使用できなくなります。 

Python の任意精度の整数は、元のステートメントで言及されたオーバーフローの問題も回避します。

## テストケース

import io

def is_prime(n):
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2

    d = 3
    while d * d <= n:
        if n % d == 0:
            return False
        d += 2

    return True

def mersenne_prime(p):
    if p == 2:
        return True

    if not is_prime(p):
        return False

    m = (1 << p) - 1
    s = 4

    for _ in range(p - 2):
        s = (s * s - 2) % m

    return s == 0

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    p = int(sys.stdin.readline())
    return "true\n" if mersenne_prime(p) else "false\n"

# Larger boundary-style test with a prime exponent that is not a
