 ## 問題の理解

 このタスクでは、要求された回数だけ連続して出現する繰り返し部分文字列が文字列に含まれているかどうかを判断するように求められます。 前のパターンの問題とは異なり、繰り返しセクションは入力文字列内の任意の位置から開始できます。 繰り返しの前後の文字は関係ありません。 コンテストの前の問題で確立されたルールに従って、繰り返されるブロック自体に少なくとも 2 文字が含まれている必要があります。 公式ステートメントでは、最初の入力行に文字列を、2 行目に必要な繰り返し回数を指定しています。答えは次のとおりです。`True`または`False`。 

たとえば、`abcXYZXYZXYZdef`と要求された数`3`、部分文字列`XYZ`を3回繰り返すので、答えは次のようになります。`True`。 と`abcXYXYdef`と要求された数`3`、2部のみ`XY`が発生するため、特定のパターンでは要求が満たされません。 

このステートメントでは、入力文字列の明示的な最大長は提供されません。 それによって、複雑さについて推論する方法が変わります。 直接 3 次検索は驚くほど早くコストが高くなる可能性がありますが、O(n²) 解では 1 秒の制限というより安全な制限が与えられます。 公開されている数値限界がないため、`n`、たとえこれがコンテストの入門問題であっても、小さな固定文字列長に依存することは避けるべきです。 公式の制限は 1 秒および 256 MB です。 

単純な実装では誤って処理される可能性のあるエッジケースがいくつかあります。 まず、繰り返されるブロックには少なくとも 2 文字が必要です。 入力用```
aaaaa
2
```正しい出力は`True`、 なぜなら`aa`2回連続で発生します。 繰り返される文字のみを検索する不注意な解決策では、誤った理由で入力が受け入れられる可能性があります。また、誤って長さ 1 のブロックを許可する解決策では、前述の問題で明示的に禁止されているパターンが報告される可能性があります。 

2 番目のエッジ ケースは、繰り返しを位置 0 から開始する必要がないことです。 入力用```
xxabcabcabczz
3
```正しい出力は`True`。 解決策は以前の問題から直接継承され、プレフィックスをチェックするだけでは誤って返されます。`False`、有用な繰り返しはインデックス 2 から始まるためです。 

3 番目のエッジケースは、繰り返し後の無関係なテキストです。 入力用```

2
```正しい出力は`True`。 の`abcabc`セクションは有効な 2 コピーの繰り返しであり、末尾の`XYZ`無視されます。 これは明らかに意図されたパターン動作の一部です。 

最後に、繰り返しでは、要求された回数よりも長い繰り返し実行が行われる可能性があります。 入力用```

```答えはまだです`True`, の 4 つの連続したコピーがあるため、`HELLO`有効な繰り返しセクションを形成し、残りのコピーは周囲のテキストとして扱われます。 「正確に一致する」という表現は、要求された数のコピーを持つ選択された繰り返しセクションを指し、入力内の最大ラン全体に正確にその数のコピーが含まれる必要があるわけではありません。 

## アプローチ

 最も直接的な総当たりアプローチは、繰り返されるブロックの可能なすべての開始位置と可能なすべての長さを試すことです。 スタートポジションについては`i`とブロック長`L`、候補ブロックを構築します`s[i:i+L]`そして以下を比較してください`k - 1`それをブロックします。 それらがすべて一致する場合、必要なパターンが見つかったことになります。 

このアプローチは正しいです。考えられるすべての繰り返しセクションには開始位置とブロック長があり、両方のパラメーターを列挙しても有効な答えを見逃すことはありません。 問題は繰り返し作業の量です。 O(n²) 個の選択肢があります。`(i, L)`、1 つの候補をチェックすると、O(kL) 文字を検査できます。 と`k`入力の一部として扱われますが、最悪の場合は文字列長が 3 次になり、固定の小さい場合でも`k`総仕事量は Θ(n³) のままです。 長さ 1000 の文字列では、最悪の場合、既に数億件の文字レベルの比較が行われる可能性があります。 

有益な観察は、開始位置とブロック長が固定されると、実際にはすべてのコピーを個別に比較する必要がないということです。 候補者が次から始まるとします。`i`そして長さがある`L`。 という条件が`k`コピーは等しいです`S[i : i + (k-1)L] = S[i+L : i+kL]`。 

つまり、で始まるサフィックスは、`i`で始まるサフィックスと一致する必要があります`i+L`少なくとも`(k-1)L`文字。 

これはまさに、Z 関数によって応答される種類のクエリです。 で始まるサフィックスの場合`i`、オフセットの Z 値`L`そのサフィックスとサフィックスの先頭の間の最長の共通プレフィックスの長さを示します。`L`文字は後ほど。 その値が少なくとも`(k-1)L`、次に最初の`k`長さのブロック`L`は同一です。 

可能な開始位置ごとに Z 配列を個別に計算します。 長さの接尾辞の Z 配列を計算する`m`コストは O(m)、すべての接尾辞の長さの合計は O(n²) になります。 1 つの開始位置の Z 配列を取得した後、すべての可能なブロック長をチェックするにはさらに O(n) のコストがかかり、全体で O(n²) のアルゴリズムが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 最悪の場合は遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取る`s`および要求された繰り返し回数`k`。 もし`k < 2`、 戻る`False`なぜなら、繰り返しにはブロックの少なくとも 2 つのコピーが必要だからです。 
2. しましょう`n`文字列の長さになります。 繰り返されるブロックには少なくとも 2 文字が含まれ、次の範囲に収まる必要があります。`k`残りのサフィックス内の回数。 スタートポジションとしては`start`したがって、可能な最大のブロック長は次のようになります。`(n - start) // k`。 
3. それぞれの可能性について`start`、サフィックスの Z 配列を構築します`s[start:]`。 この Z 配列では、`z[L]`の最長プレフィックスの長さです`s[start:]`これは部分文字列の先頭にも等しい`L`文字は後ほど。 
4. あらゆるブロック長を試してみる`L`から`2`を通して`(n - start) // k`。 必要です`k`このブロックのコピーなので、最初のコピーは次のコピーと一致する必要があります。`k - 1`合計のコピー数`(k - 1) * L`文字。 
5. もし`z[L] >= (k - 1) * L`、で始まる部分文字列`start`少なくとも`k`同じブロックの連続したコピー。 戻る`True`すぐに。 
6. すべての開始位置とすべての可能なブロック長が失敗した場合は、リターンします。`False`。 

重要な不変条件は、固定された`start`、`z[L]`最初のブロックの後に、シフトされた文字列と一致し続ける文字数を正確に測定します。`L`ポジション。 その結果、`z[L] >= (k-1)L`すべての人の平等に等しい`k`コピー。 すべての有効な繰り返しには開始点とブロック長があるため、ネストされた検索では考えられるすべての答えが考慮され、アルゴリズムは返されるもののみを返します。`True`必要な等価性が実際に成立する場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def has_pattern(s: str, k: int) -> bool:
    n = len(s)

    if k < 2:
        return False

    for start in range(n):
        m = n - start

        if m < 2 * k:
            continue

        t = s[start:]
        z = [0] * m

        left = right = 0

        for i in range(1, m):
            if i < right:
                z[i] = min(right - i, z[i - left])

            while i + z[i] < m and t[z[i]] == t[i + z[i]]:
                z[i] += 1

            if i + z[i] > right:
                left = i
                right = i + z[i]

        max_len = m // k

        for length in range(2, max_len + 1):
            if z[length] >= (k - 1) * length:
                return True

    return False

def solve():
    s = input().rstrip("\n")
    k = int(input())
    print("True" if has_pattern(s, k) else "False")

if __name__ == "__main__":
    solve()
```の`has_pattern`関数には完全なアルゴリズムが含まれています。 初期の`k < 2`check は、文字列処理が開始される前に、無効な繰り返し回数を処理します。 

あらゆる人にとって`start`、`t`はその位置から始まるサフィックスを表します。 標準を使用して Z 配列を構築します`[left, right)`一致するウィンドウ。 いつ`i`現在のウィンドウ内にある場合、対応するミラーリングされた位置の値を下限として再利用でき、不必要な文字比較を回避できます。 

ループオーバー`length`から始まります`2`、 それよりも`1`なぜなら、繰り返されるブロックには少なくとも 2 文字が必要だからです。 上限は`m // k`、それより長いブロックは収まらないため`k`サフィックスに回。 

条件`z[length] >= (k - 1) * length`は中心となる実装の詳細です。 建設する必要はありません`block * k`であり、各コピーを個別に比較する必要はありません。 Z 値は、最初のコピーと 1 ブロック分シフトした後のすべてのコピーとの間の比較全体をすでに表しています。 

Python では整数オーバーフローの問題はありません。 繰り返し回数を伴う最大の式は次のとおりです。`(k - 1) * length`、Python は任意精度の整数を処理します。 

入力文字列は次のように読み取られます。`rstrip("\n")`それよりも`strip()`スペースは文字列内の正当な文字であり、入力の一部として残す必要があるためです。

## テストケース```python
import sys
import io

def has_pattern(s: str, k: int) -> bool:
    n = len(s)

    if k < 2:
        return False

    for start in range(n):
        m = n - start

        if m < 2 * k:
            continue

        t = s[start:]
        z = [0] * m

        left = right = 0

        for i in range(1, m):
            if i < right:
                z[i] = min(right - i, z[i - left])

            while i + z[i] < m and t[z[i]] == t[i + z[i]]:
                z[i] += 1

            if i + z[i] > right:
                left = i
                right = i + z[i]

        for length in range(2, m // k + 1):
            if z[length] >= (k - 1) * length:
                return True

    return False

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().rstrip("\n")
    k = int(sys.stdin.readline())

    ans = "True" if has_pattern(s, k) else "False"

    sys.stdin = old_stdin
    return ans + "\n"

    "uyboubawlefjbasdHELLOHELLOHELLOHELLOsygvfubklkj\n4\n"
) == "True\n", "sample 1"

# Minimum useful repetition
assert run("abab\n2\n") == "True\n", "minimum repeated block"

# Repetition starts after irrelevant text
assert run("xxabcabcabczz\n3\n") == "True\n", "nonzero starting position"

# Requested number is too large
assert run("abcabc\n3\n") == "False\n", "not enough repetitions"

# A single-character block must not count
assert run("aaaa\n3\n") == "False\n", "block length must be at least two"

# More copies than requested are still enough to select the requested section
assert run("HELLOHELLOHELLOHELLOHELLO\n4\n") == "True\n", "longer run"

# Boundary case where the pattern reaches the end exactly
assert run("zzxyxyxy\n3\n") == "True\n", "pattern reaches string end"

# No repeated section
assert run("abcdefgh\n2\n") == "False\n", "no repetition"
