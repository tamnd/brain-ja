 ## 解決策
 ## 問題の理解

 各行は次の形式で与えられます

 [
 y = mx + b
 ]

 ここで、(m) はその傾き、(b) はその (y) 切片です。 入力には、ある行の最初のラインの 2 つの係数と、次の行の 2 番目のラインの 2 つの係数が含まれています。 

タスクは、2 本の線が交差する点の (x) 座標を見つけることです。 この問題では 2 つの線が実際に交差することが保証されているため、平行な線や同一の線を処理する必要はありません。 

公開された問題では、1 秒の制限時間と 256 MB のメモリが使用されます。 ここには、大きな (n)、配列、グラフ、または繰り返されるテスト ケース パラメーターはありません。 入力には浮動小数点値が 4 つしか含まれていないため、目的のソリューションでは一定数の算術演算を実行する必要があります。 実行時間が多くの可能な (x) 座標の試行に依存するようなアルゴリズムは不要です。 

主なエッジケースは、入力サイズではなく代数に由来します。 まず、交差点は負の (x) 座標を持つことができます。 例えば、```
5 3
-6 -20
```生成する```
-2.090909090909091
```線が (y) 軸の左側で交差するためです。 答えが負ではないことを前提とした実装は正しくありません。 

2 番目のケースは、斜面が互いに非常に近い場合です。 例えば、```
1.000001 2
1 1
```持っています

 [
 x = \frac{1-2}{1.000001-1} = -1000000。 
]

 分母が小さいため、除算を実行する前に傾きをあまりにも積極的に四捨五入すると、答えが大きく変わる可能性があります。 

3 番目のケースは、一方または両方の切片がゼロの場合です。 例えば、```
2 0
-1 3
```与える

 [
 2x=-x+3、
 ]

 したがって (x=1)。 ゼロを欠損値として扱うソリューションや、ゼロ以外の切片に対する特別な処理に依存するソリューションは、不必要に失敗します。 

最後に、問題の交差保証では 2 つの傾きが等しくなることはありません。 たとえば、両方の線が傾き (2) を持っていた場合、次のようになります。```
2 1
2 5
```は平行線を表し、交差はありません。 この場合、ステートメントは指定されたすべての線のペアが交差することを保証するため、出力を作成する必要はありません。 

## アプローチ

 ブルートフォース手法では、(x) 座標を数値的に検索できます。 選択した精度 (\varepsilon) については、両方の行を連続する (x) 値で評価し、それらの (y) 値が十分に近づく点を探すことができます。 これは、2 つの交差する線がその交差点で正確に等しい (y) 値を持つため、概念的に機能します。 

問題は、これが直接の代数的質問を恣意的な数値検索に変えてしまうということです。 検索が長さ (R) と間隔 (\varepsilon) の間隔をカバーする場合、次のことが必要です。 

[
 \left\lceil\frac{R}{\varepsilon}\right\rceil+1
 ]

 最悪の場合の候補者の評価。 このステートメントでは、このような方法を推奨する有限の検索間隔や必要な離散化は提供されていません。 さらに悪いことに、(\varepsilon) を小さくすると、正確な代数的答えが得られずに演算数が増加します。 

重要な観察は、交点では両方の方程式が同じ (y) 値を持つということです。 線が

 [
 y=m_1x+b_1
 ]

 そして

 [
 y=m_2x+b_2、
 ]

 単純に右辺を等しく設定することができます。 

[
 m_1x+b_1=m_2x+b_2。 
]

 (x) 項を一方の側に、定数をもう一方の側に移動すると、次のようになります。 

[
 (m_1-m_2)x=b_2-b_1。 
]

 線分は交差することが保証されているため (m_1-m_2\neq0)、

 [
 x=\frac{b_2-b_1}{m_1-m_2}。 
]

 ブルートフォースは、この等式を数値的に正確に検索するため機能しますが、等式を直接解くことができるという事実を利用できません。 代数では、問題全体が分子の減算 1 回、分母の減算 1 回、除算 1 回に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(R/\バレプシロン)) | (O(1)) | 遅すぎて精度に依存します |
 | 最適 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のラインの傾きと切片である (m_1) と (b_1)、および 2 番目のラインの対応する値である (m_2) と (b_2) を読み取ります。 
2. (y) 座標がそれらの交点で同じであるため、2 つの直線方程式を等しく設定します。 

[
 m_1x+b_1=m_2x+b_2。 
]
 3. 方程式を並べ替えて (x) を分離します。 

[
 (m_1-m_2)x=b_2-b_1。 
]

 この問題では交差が保証されているため、傾きが等しくなることはありません。 したがって、(m_1-m_2) による除算は有効です。 
4. コンピューティング

 [
 x=\frac{b_2-b_1}{m_1-m_2}。 
]
 5. 結果の浮動小数点値を出力します。 この問題には Python の浮動小数点表現で十分ですが、Python の`str`変換では、任意の小数点以下の桁数を選択する必要がなく、適切な 10 進表現が出力されます。 

重要な不変式は、2 つの直線を等しくすることによって得られる方程式です。 交点となるすべての点で、(y) の両方の式が同じ値を持つ必要があります。 代数変換では等価性が維持されるため、(x) の最終値は、両方の直線方程式を満たす正確な一意の座標になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m1, b1 = map(float, input().split())
    m2, b2 = map(float, input().split())

    x = (b2 - b1) / (m1 - m2)
    print(x)

if __name__ == "__main__":
    solve()
```最初の入力行は次のように解析されます。`m1`そして`b1`、最初の方程式 (y=m_1x+b_1) と一致します。 2 行目も同様に解析されます。 

表現`(b2 - b1) / (m1 - m2)`導出された式に直接続きます。 減算順序を文書どおりに正確に保つことが重要です。 分子を次のように変更すると、`b1 - b2`分母も変更しないと、答えが否定されてしまいます。 

パイソンの`float`入力が浮動小数点値で構成されるため、type が使用されます。 Python には固定幅整数言語で発生する整数オーバーフローの問題はありませんが、浮動小数点演算には通常の有限精度の動作が引き続き存在します。 交差を計算する前に係数を四捨五入する理由はありません。傾斜が近い場合、四捨五入を行うと特に悪影響を及ぼす可能性があります。 

また、問題には複数のテスト ケースではなく 1 組の行が含まれているため、ループも必要ありません。 ソース問題では、2 つの入力行と 1 つの出力値が明示的に記述されています。

## テストケース

 元のソースでは 1 つのサンプルが提供されており、複数のテスト ケースは定義されていません。 このステートメントでは浮動小数点係数の数値の最大限界も提供していないため、公開された仕様からリテラルの最大サイズのテストを構築することはできません。 代わりに、以下のカスタム テストでは、この式にとって重要な数値の極値と構造境界のケースを実行します。```python
# Helper: run solution on input string, return output string.
import sys
import io

def solve():
    m1, b1 = map(float, input().split())
    m2, b2 = map(float, input().split())

    x = (b2 - b1) / (m1 - m2)
    print(x)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

# Provided sample.
assert run("5 3\n-6 -20\n") == "-2.090909090909091\n", "sample 1"

# Minimum-size style case: two simple intersecting lines.
assert run("1 0\n-1 2\n") == "1.0\n", "simple intersection"

# Zero intercepts and positive intersection.
assert run("2 0\n-1 3\n") == "1.0\n", "zero intercept"

# Negative intersection.
assert run("3 5\n1 1\n") == "-2.0\n", "negative x-coordinate"

# Very close slopes, exercising a small denominator.
assert run("1.000001 2\n1 1\n") == "-1000000.0\n", "close slopes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`5 3`/`-6 -20`|`-2.090909090909091`| 提供されたサンプルと陰性結果 |
 |`1 0`/`-1 2`|`1.0`| 基本的な代数と正の座標での交差 |
 |`2 0`/`-1 3`|`1.0`| ゼロインターセプトの処理 |
 |`3 5`/`1 1`|`-2.0`| 負の交差点 |
 |`1.000001 2`/`1 1`|`-1000000.0`| 分母が小さく、傾きが近い |

 テストでは、これらの特定の入力に対して Python によって生成された正確な 10 進表現を比較します。 より一般的なテスト ハーネスの場合は、数学的に等しい浮動小数点計算でも最終の下位ビットが異なる場合があるため、浮動小数点値を許容値と比較することが望ましいと考えられます。 

## 特殊なケース

 負の座標の場合は、特別な分岐を行わずに処理されます。 のために```
5 3
-6 -20
```アルゴリズムは (b_2-b_1=-23) と (m_1-m_2=11) を計算し、(x=-23/11) を求めます。 負の分子は自然に正しい負の座標を生成します。 

ゼロ切片の場合も同様に直接的です。 のために```
2 0
-1 3
```分子は (3-0=3)、分母は (2-(-1)=3) であるため、結果は (1) になります。 両方の方程式に (x=1) を代入すると (y=2) が得られ、交差が確認されます。 

傾きが近いケースは、解法で検索や積極的に丸められた係数を使用すべきではない理由を示しています。 と```
1.000001 2
1 1
```分母は (0.000001) のみです。 式は次のようになります

 [
 x=\frac{1-2}{1.000001-1}
 =\frac{-1}{0.000001}
 =-1000000。 
]

 粗い数値検索では、検索範囲が小さすぎるとこの交差部分を完全に見逃してしまう可能性がありますが、直接式ではすぐに交差部分が得られます。 

最後に、等しい傾きは入力保証によって除外されます。 のために```
2 1
2 5
```分母はゼロとなり、平行線を表します。 裁判官が特別な出力を提供することはないため、プログラムはこの場合に特別な出力を追加しません。 任意の分岐を追加すると、実際には、すべての入力が 2 つの交差する線で構成されるという問題の中心的な保証が曖昧になる可能性があります。
