 ## 解決策
 ## 問題の理解

 ピタゴラス トリプルを形成する整数のトリプル (a、b、c) を数え、追加の方程式も満たす必要があります。 辺は 1≤a≤b≤c≤n の順序で並べられるため、c は斜辺になります。 通常のピタゴラス方程式のほかに

 a 2 +b 2 =c 2 、

 トリプルは Vasya の誤った公式も満たさなければなりません

 c=a 2 −b。 

各テスト ケースの入力は単一の上限 n です。 3 つの辺の長さがすべて n 以下である場合に、両方の方程式を満たすトリプルがいくつあるかを出力する必要があります。 公式の制約は 1≤t≤10 4 および 1≤n≤10 9 で、時間制限は 2 秒、メモリ制限は 256 MB です。 

n の値は十分に大きいため、n までのすべての可能な辺の長さをチェックするのはコストがかかりすぎます。 O( n ) ループでも、1 つの最大サイズのテスト ケースの反復回数は約 44722 回ですが、これを 10 4 のテスト ケースに対して個別に実行すると、反復回数は 4.5×10 8 に近づく可能性があります。 2 つの方程式の便利な構造により、テスト ケース全体を一定数の整数演算に減らすことができます。 

直接式が間違っている可能性がある小さなケースがいくつかあります。 n=1 の場合、有効な三角形は存在しないため、答えは次のようになります。`0`。 a≥3 を必要とせずに a の奇数値を単にカウントする式では、a=1 が誤ってカウントされ、b=0 が得られる可能性があります。 

n=3 の場合、答えは次のようになります。`0`。 a=3 は奇数の候補ですが、対応する値は b=4 および c=5 であるため、斜辺はすでに n を超えています。 

n=5 の場合、答えは次のようになります。`1`、(3,4,5)に対応します。 c≤n ではなく c<n などの境界条件を使用すると、このトリプルが誤って拒否されます。 

## アプローチ

 簡単なアプローチは、両方の式をチェックしながら、考えられるすべての a、b、c を試してみることです。 すべての有効な答えが明示的に検査されるため、これは正しいですが、O(n 3 ) 個の組み合わせが必要です。 n=10 9 では、およそ 10 27 通りの組み合わせがあり、これはまったく実行不可能です。 

a が固定されると、2 つの方程式によって b と c が決定されることを観察することで、これをすでに改善できます。 から始まる

 a 2 +b 2 =c 2

 c=a 2 −b を代入すると、次のようになります。 

ａ ２ ＋ｂ ２ ＝（ａ ２ −ｂ） ２ 。 

右側を展開すると、

 ａ ２ ＋ｂ ２ ＝ａ ４ −２ａ ２ ｂ＋ｂ ２ 。 

b 2 をキャンセルして a 2 で割ります。これは、a が正であるため有効です。 

1=a 2 -2b。 

したがって、

 b= 2 a 2 −1 、

 c=a 2 −b を使用すると、

 c= 2 a 2 +1 。 

これで、なぜ a が奇数でなければならないのかがすぐに説明できます。 さらに重要なのは、考えられるすべてのトリプルが単一の整数 a によって決定されるようになったということです。 

私たちもそれを知っています

 c= 2 a 2 +1 ≤n、

 それで

 ａ ２ ≦２ｎ−１。 

したがって、a は最大でも

 L=⌊ 2n−1 ⌋.

 順序付け条件により、制限が 1 つ追加されます。 a=1 の場合、式では b=0 が得られますが、これは無効です。 a≥3 のすべての奇数について、a≤b≤c が成立します。 したがって、 a の有効な値は、正確に 3 から L までの奇数の整数です。 

これらの値をループする代わりに、直接カウントすることもできます。 1 から L までの奇数の整数の数は、⌊(L+1)/2⌋ です。 a=1 を削除すると葉が残ります

 ⌊ 2 L+1 ⌋−1=⌊ 2 L−1 ⌋.

 したがって、各テスト ケースは、正確な整数の平方根を使用して O(1) 時間で解決できます。

 ## アルゴリズムのチュートリアル

 1. n を読み取り、計算します

 L=⌊ 2n−1 ⌋.

 c=(a 2 +1)/2 は n を超えてはいけないため、値 L は a の可能な最大値です。 

1. 3≤a≤Lを満たす奇数の整数aを数えます。 

カウントは

 ⌊ 2 L−1 ⌋.

 このような奇数の a はすべて、有効なトリプルを 1 つだけ生成するため、対応する b と c を構築したり個別にテストしたりする必要はありません。 

1. そのカウントを出力します。 

直接計数式は小さな n も処理します。 n=1 の場合、L=1 となり、結果は 0 になります。 n=2の場合もL=1となります。 n=5、L=3 の場合、ちょうど 1 つのトリプルが得られます。 

### なぜ効果があるのか

 2 つの必要な方程式により、すべての有効なトリプルが形式に強制されます。 

(a, 2 a 2 −1 , 2 a 2 +1 )。 

したがって、有効なトリプルと、得られる斜辺が最大でも n になる奇数整数 a≥3 の間には 1 対 1 の対応関係があります。 斜辺条件は正確に a 2 ≤2n−1 であるため、a の奇数値をカウントすると、すべての有効なトリプルが 1 回だけカウントされ、無効なトリプルを含めることはできません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    t = int(input())
    for _ in range(t):        n = int(input())
        # c = (a^2 + 1) / 2 <= n        # so a^2 <= 2n - 1.        limit = (2 * n - 1) ** 0.5        limit = int(limit)
        # Correct possible floating-point rounding using integer adjustment.        while (limit + 1) * (limit + 1) <= 2 * n - 1:            limit += 1        while limit * limit > 2 * n - 1:            limit -= 1
        # Valid a are odd integers in [3, limit].        answer = (limit - 1) // 2        print(answer)

if __name__ == "__main__":    solve()
```この導出は、実装には実現可能な最大の a のみが必要であることを意味します。 コードは最初に 2n−1 の整数値を計算し、次に 3 から始まる奇数値をカウントします。 

初期推定で浮動小数点が使用されている場合でも、補正ループにより平方根計算が正確になります。 n≤10 9 の場合、平方根される値は最大でも 2⋅10 9 −1 であるため、補正に必要な作業量は最大でもごくわずかで一定です。 Python の整数演算もオーバーフローを回避します。 

表現`(limit - 1) // 2`奇数値 3、5、7、… までの数です。`limit`。 使用する`limit + 1`または、カウントを 1 から開始すると、無効な a=1 のケースが発生します。 

より単純な実装では、`math.isqrt`これは、正確な整数の平方根を直接計算するため、Python では推奨されます。```python
Pythonimport sysfrom math import isqrt
input = sys.stdin.readline

def solve():    t = int(input())
    for _ in range(t):        n = int(input())        limit = isqrt(2 * n - 1)        print((limit - 1) // 2)

if __name__ == "__main__":    solve()
```これが推奨バージョンです。

 ## 特殊なケース

 n=1 の場合、入力は次のようになります。`1`そしてアルゴリズムは L=⌊ 1 ⌋=1 を計算します。 表現`(1 - 1) // 2`与える`0`。 これは、正の辺の長さではない b=0 を生成するため、正式な代数候補 a=1 を正しく拒否します。 

n=3 の場合、入力は次のようになります。`3`。 L=⌊ 5 ⌋=2 となるため、必要な範囲 3≤a≤2 に奇数の a はありません。 答えは`0`。 a が奇数かどうかだけをチェックする不注意な実装では、a=1 と誤ってみなされる可能性があります。 

n=5 の場合、入力は次のようになります。`5`。 ここで、L=⌊ 9 ⌋=3 なので、a=3 とカウントされます。 b=4 および c=5 が生成され、条件が c≤n であるため、トリプルは有効です。 答えは`1`。 

n=12 の場合、考えられる最大の a は 4 であるため、a=3 のみがカウントされます。 トリプル (5,12,13)​​ は、斜辺が 13>12 であるため含まれません。 これは、c が最大の辺であり、実際の制限量であるため、c ではなく b を使用して a を境界付けるというよくある間違いを捕らえます。 

最大入力 n=10 9 の場合、次のようになります。 

L=⌊ 1999999999 ⌋=44721。 

有効な値は、3 ～ 44721 のすべての奇数です。 

2 44721−1 ＝22360。 

このアルゴリズムは、これらの 22360 個の値を列挙することなくこの結果に達します。これは、最大 10 4 個のテスト ケースが存在できるため、特に便利です。
