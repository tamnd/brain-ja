 ## 解決策
 ## 問題の理解

 このタスクは、直接文字列フィルタリングの問題です。 文字列があります`S`、その後にコレクションが続きます`C`消えなければならない文字が含まれています。 あらゆる出来事が`S`にリストされているキャラクターの`C`他の文字はすべて削除する必要がありますが、他のすべての文字はまったく同じ相対順序に保たれなければなりません。 出力は、このようなすべての削除を行った後の結果の文字列です。 公式問題には例が示されています`howdy`、 と`w`そして`y`禁止、生産`hod`。 

公開された問題ページでは、1 秒の時間制限と 256 MB のメモリが与えられていますが、長さの明示的な制限は公開されていません。`S`またはのための`N`。 つまり、実行時間が文字列の長さに削除する文字数を乗算するようなアルゴリズムを避けるのが安全な解釈です。 すべての文字が生き残るかどうかを判断するために少なくとも 1 回検査する必要があるため、入力のリニア スキャンが自然なターゲットになります。 

主なエッジ ケースは、削除ルールが最初の出現だけでなくすべての出現に適用されるという事実から生じます。 たとえば、入力の場合```
banana
1
a
```正しい出力は```
bnn
```出現したものを 1 つだけ削除する不用意な実装`a`どちらかを誤って残してしまいます`bnana`または`banan`。 

もう 1 つの境界ケースは、削除する必要がある文字がない場合です。 入力あり```
abc
0
```正しい出力は```
abc
```削除文字がないため、元の文字列を正確に保存する必要があります。 整数の後に少なくとも 1 つの文字が続くことを想定した実装`N`ここで失敗する可能性があります。 

逆の場合は、すべての文字が削除セットに属している場合です。 入力あり```
abc
3
a
b
c
```正しい出力は空の文字列です。 結果は正しく構築されるが、終了の改行を出力するのを忘れた解決策は、依然としてほとんどの審査員に受け入れられますが、結果が空ではないことを前提とする解決策は失敗したり、誤って文字を保持したりする可能性があります。 

入力が区別性を強制するものとして信頼されていない場合、削除文字が繰り返されることも実装のトラップとなる可能性があります。 例えば、```
aaa
2
a
a
```それでも空の文字列が生成されるはずです。 削除セットのメンバーシップはブール型プロパティとして扱われる必要があるため、同じ文字を 2 回挿入しても追加の効果はありません。 

## アプローチ

 単純な総当たりソリューションは、次のすべての文字を処理できます。`S`そして、それぞれについて、一致するものが見つかるまで削除リスト全体をスキャンします。 これは正しいです。なぜなら、文字は、次の場合に出現しない場合でもそのまま存続するからです。`C`。 もし`|S| = n`そして`N`文字が指定されている場合、最悪の場合でも実行されます。`nN`メンバーシップの比較。 両方の値が存在する場合`10^5`、それは約です`10^10`1 秒の制限でサポートできる比較をはるかに超えています。 

削除の定義を直接チェックするため総当りが機能しますが、繰り返しの検索は不要です。 重要な観察は、メンバーシップについて尋ねる必要がある唯一の質問であるということです。`C`。 文字が削除リストのどこに出現するか、またはそれが何回出現するかは気にしません。 すべての削除文字をセットに入れることができるため、メンバーシップのテストが期待できます。`O(1)`。 次に、左から右に 1 回スキャンします。`S`十分です。 

の各キャラクターごとに、`S`、削除セットに属しているかどうかを確認します。 そうなった場合はスキップします。 それ以外の場合は、回答に追加します。 文字は左から右に処理され、不要な文字のみがスキップされるため、生き残った文字は自動的に元の順序を保持します。

 | --- | --- | --- | --- |
 | ブルートフォース | O( | S | N) | O(N) | 最悪の場合は遅すぎる |
 | 最適 | O( | S | + N) が期待されます | O(N + | S | ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の文字列を読み取る`S`、それから読んでください`N`そして次`N`文字。 それらの文字を というセットに格納します。`deleted`。 セットを使用すると、削除リストを繰り返しスキャンする代わりに、メンバーシップを直接テストできます。 
2. 空のリストを作成する`answer`。 文字列の連結を繰り返すと不必要なコピーが発生する可能性があるため、Python 文字列を繰り返し連結するよりもリストを使用することをお勧めします。 
3. すべての文字をスキャンします`ch`の`S`左から右へ。 もし`ch`いる`deleted`、無視してください。 それ以外の場合は追加します`ch`に`answer`。 決定はそのキャラクターが禁止されているかどうかのみに依存するため、以前の位置に関する情報は必要ありません。 
4. 残った文字を結合し、結果の文字列を出力します。 すべての文字が削除された場合、リストは空になり、`''.join(answer)`空の文字列が正しく生成されます。 

### なぜ効果があるのか

 スキャン中の不変条件は次のとおりです。`answer`既に処理されたプレフィックスの文字が正確に含まれています`S`入っていないもの`deleted`、元の順序で。 次のキャラクターが所属するとき`deleted`を省略することは、まさに必要な操作です。 に属さないとき`deleted`、削除セット内の文字のみが削除される可能性があるため、これを保持することは必須です。 したがって、不変式はすべての文字の後、および文字列全体が処理された後も true のままになります。`answer`はまさに必要な最終文字列です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')
    n = int(input())
    deleted = {input().strip() for _ in range(n)}

    answer = [ch for ch in s if ch not in deleted]
    print(''.join(answer))

if __name__ == "__main__":
    solve()
```最初の行は、フィルタリングされる文字列を読み取ります。`rstrip('\n')`行末のみを削除するため、文字列内の他の文字が誤って破棄されることはありません。 

集合内包表記はすべてを読み取ります`N`文字を削除して保存します`deleted`。 問題ではこれらを異なる文字として説明していますが、セットを使用すると偶発的な繰り返しも自然に処理されます。 

リスト内包表記は、アルゴリズムのウォークスルーからのスキャンを実装します。 に存在しないすべての文字`deleted`保持されます。 Python は文字列を順番に反復処理するため、結果のリストにはすでに正しい順序が設定されています。 

ついに、`join`1 回の操作で出力文字列を構築します。 インデックスの計算がないため、1 つずつ異なる境界を管理する必要はありません。 Python の整数にも任意の精度がありますが、この問題ではオーバーフローが問題になるほど大きな算術演算が必要になることはありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().rstrip('\n')
    n = int(input())
    deleted = {input().strip() for _ in range(n)}
    answer = [ch for ch in s if ch not in deleted]
    print(''.join(answer))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

    return out.getvalue()

# Provided sample
assert run("""howdy
2
w
y
""") == "hod\n", "sample 1"

# Minimum-size string, one character deleted
assert run("""a
1
a
""") == "\n", "single character deleted"

# No characters are deleted
assert run("""abc
0
""") == "abc\n", "empty deletion set"

# All characters are deleted
assert run("""abcabc
3
a
b
c
""") == "\n", "all characters deleted"

# Repeated occurrences and alternating survivors
assert run("""banana
1
a
""") == "bnn\n", "repeated deleted characters"

# Boundary case where only the first and last characters survive
assert run("""xabcy
3
a
b
c
""") == "xy\n", "boundary characters"

# Large input to exercise linear behavior
large_s = "ab" * 50000
large_input = large_s + "\n1\nb\n"
assert run(large_input) == ("a" * 50000) + "\n", "large input"

 空の削除セットの場合、正確な入力は次のとおりです。```

1
