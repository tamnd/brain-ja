 ## 解決策
 # 問題の理解

 この問題では、ゴール後のサッカー解説者の長々とした祝賀を表す 1 つの文字列が得られます。 この単語は通常の「目標」という単語と同じように始まり、終わりますが、`o`アナウンサーが叫ぶ長さに応じて、真ん中の文字が延長される場合があります。 課題は、正確に何個かを数えるということです`o`記録された反応全体に文字が表示されます。 

入力には 1 つの文字列が含まれるため、必要な操作はその文字をスキャンすることだけです。 この制限により、文字列上の直接の線形パスが許可されます。 文字列が非常に大きい場合でも、`O(n)`このソリューションでは、文字ごとに 1 つの単純なチェックのみが実行されますが、文字列の検索や変更を繰り返し行う遅いアプローチでは、不必要な作業が追加されてしまいます。 

主なエッジケースは、単語が常に固定長であると仮定すること、または中央のセクションのみを手動でカウントすることによって発生します。 たとえば、入力は次のとおりです。```
goal
```出力があります:```
1
```常に複数存在することを前提としたソリューション`o`キャラクターは最短の有効な反応で失敗します。 

別のケースは次のとおりです。```
goooooooooal
```出力あり:```
9
```の数`o`文字は固定されていないため、次のような特定のパターンを確認します。`"goal"`または、ハードコードされた範囲内の位置のみをカウントすると、間違った答えが生成されます。 

最後によくある間違いは、入力を別の型に変換するのではなく、文字列として扱う必要があることを忘れていることです。 キャラクター自体が情報を伝え、あらゆる出来事が起こります。`o`数えなければなりません。 

## アプローチ

 問題には高度なアルゴリズムを必要とする隠れた構造がないため、総当りのアイデアはすでに最適解に近づいています。 直接的な方法は、アナウンサーの反応のすべての文字を調べて、現在の文字が反応するたびにカウンターを増やすことです。`o`。 これが機能するのは、それぞれ`o`必要な回答に 1 つだけ貢献し、他の文字は重要ではありません。 

唯一考えられる非効率なアプローチは、文字列内で次の出現箇所を繰り返し検索することです。`o`または、カウント中に多数の一時文字列を作成します。 最悪の場合、文字列の長さが`n`、文字列全体を繰り返しスキャンすると、到達する可能性があります`O(n²)`不要な操作です。 

重要な観察は、答えは個々のキャラクターにのみ依存するということです。 文字の位置を理解したり、単語の構造を確認したり、アナウンサーをシミュレートしたりする必要はありません。 左から右への 1 回のトラバースで十分です。

 ## アルゴリズムのチュートリアル

 1. 入力から反応文字列を読み取ります。 文字列は完全に転写されたものであるため、すべての文字を考慮する必要があります。 
2. カウンタを値 0 で初期化します。 この変数には、次の数が格納されます。`o`これまでのキャラクターが登場しました。 
3. 文字列を一度に 1 文字ずつ調べます。 現在のキャラクターがいるたびに、`o`、カウンターを 1 つ増やします。 などのキャラクター`g`、`a`、 そして`l`結果には影響しません。 
4. 最終的なカウンター値を出力します。 トラバースが終了すると、カウンターは正確な数を表します。`o`反応の中の文字。 

なぜ効果があるのか:

 不変条件は、文字列の接頭辞を処理した後、カウンターが次の数に等しいということです。`o`そのプレフィックス内の文字。 最初はプレフィックスは空でカウンタはゼロであるため、不変条件は true です。 新しい文字が処理されると、その文字が処理された時点でカウンタが変更されます。`o`、不変式が true に保たれます。 文字列全体が処理された後は、プレフィックスが入力文字列全体になるため、カウンターが必要な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    print(s.count('o'))

if __name__ == "__main__":
    solve()
```文字自体が分析する必要があるデータであるため、ソリューションは反応全体を文字列として読み取ります。 

Pythonの組み込み`count`このメソッドは、アルゴリズムで説明されているのと同じ線形スキャンを実行します。 すべての文字を 1 回チェックし、対象の文字が何回出現したかを返します。 

使用する`strip()`リアクション内の文字に影響を与えることなく、入力によって追加された改行を削除します。 数値計算がないため、整数のオーバーフローは心配ありません。
