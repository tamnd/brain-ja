 ## 解決策
 ## 問題の理解

 三次元空間の特定の点に星があります。 各惑星は、その 3 つの座標と名前によっても与えられます。 このタスクは、恒星に最も近い惑星から最も遠い惑星の名前までを出力することです。 

ある惑星のために`(x, y, z)`そしてスター`(sx, sy, sz)`、そのユークリッド距離は`sqrt((x - sx)^2 + (y - sy)^2 + (z - sz)^2)`。 

2 つの距離を比較する場合、平方根は不要です。 平方根関数は非負の値に対して厳密に増加するため、距離の比較は距離の 2 乗を比較することとまったく同じです。 これにより、アルゴリズム全体で整数演算を使用できるようになります。 

公式問題では制限時間は 1 秒、メモリは 256 MB です。 数値の上限は公表されていない`n`問題のページでは、それだけです`n`は正の整数です。 それは`O(n log n)`自然な目標を解決するため、非常に大きな入力に対しては依然として実用的ですが、`O(n^2)`メソッドはすぐに使用できなくなります。 入力自体には惑星ごとに一定量の作業のみが含まれるため、すべての惑星とその並べ替えキーを保存するには線形メモリが必要です。 

最初のエッジ ケースは、座標が星の座標と等しい惑星です。 例えば、```
0 0 0
1
0 0 0 Home
```出力があります```
Home
```その二乗距離はゼロです。 正のセンチネルまでの最小距離を初期化するが、その他の点では減算を正しく処理する不注意な実装は引き続き機能しますが、すべての惑星の距離が厳密に正であると仮定する実装は、このケースを誤って処理する可能性があります。 

2 番目のエッジ ケースは、1 つ以上の軸の負の方向にある惑星です。 例えば、```
10 10 10
2
9 10 10 A
8 10 10 B
```出力があります```
A
B
```なぜなら距離は`1`そして`2`。 減算は二乗する前に実行する必要があります。 座標を直接比較するか、誤って使用してしまう`x - sx`正方形をとらないと、幾何学的な距離を表すことはできません。 

3 番目のよくある間違いは、並べ替えの前に平方根を取ることです。 例えば、```
0 0 0
2
3 4 0 A
0 0 6 B
```出力があります```
A
B
```なぜなら二乗距離は`25`そして`36`。 実際の距離の計算は数学的に機能しますが、浮動小数点演算が導入されてしまい、何のメリットもありません。 二乗距離により、正確な整数の比較が行われます。 

入力により、星からの距離が同じ惑星が 2 つ存在しないことが保証されるため、タイブレーク ルールを定義する必要はありません。 

## アプローチ

 最も直接的な強引なアプローチは、まだ印刷されていない最も近い惑星を繰り返し検索することです。 最初の反復ではすべてを検査します`n`惑星、我々が検査した瞬間に`n - 1`、 等々。 距離比較の総数は次のとおりです。`n + (n - 1) + ... + 1 = n(n + 1) / 2`。 

したがって、メソッドは次のようになります`O(n^2)`時間。 これは正しいです。各反復では距離が最小の残りの惑星が明示的に選択されますが、二次関数の増加により、次のような場合には不適切になります。`n`大きくなる。 のために`n = 100000`、それは約を実行します`5 * 10^9`1 秒の制限時間で対応できる比較をはるかに超えています。 

重要な観察は、問題は単純に、恒星からの距離を示す 1 つの数値キーによって惑星を順序付けるように求めているということです。 各惑星に二乗距離が付加されると、幾何学的な部分が完成します。 すべてのペアを入れることができます`(squared_distance, name)`を配列に変換し、その配列を最初のコンポーネントでソートします。 

この総当たり法は、一度に最小の惑星を 1 つずつ発見するため機能しますが、相対的な順序がすでに決定されている惑星を繰り返しスキャンします。 すべての惑星に独立して距離を割り当てることができるという観察により、すべてのキーを一度に計算し、順序付けを標準に委任することができます。`O(n log n)`選別。 

平方根を計算する必要はありません。 距離の二乗を持つ 2 つの惑星の場合`d1²`そして`d2²`、`d1 < d2`まさにいつ`d1² < d2²`。 Python の整数はオーバーフローも回避するため、大きな座標値でも安全に二乗できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | n が大きいと遅すぎます |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 星の座標を読み取る`(sx, sy, sz)`。 すべての惑星の距離は、この同じ点を基準にして測定されます。 
2. 惑星の数を読み取り、各惑星について、`(x, y, z)`そしてその名前。 コンピューティング`d2 = (x - sx)^2 + (y - sy)^2 + (z - sz)^2`。 

平方距離を使用するのは、平方根や浮動小数点精度を回避しながら、通常の距離の順序を維持するためです。 
3.ストア`(d2, name)`配列内のすべての惑星に対して。 距離が最初に配置されるのは、その値によって配列を順序付ける必要があるためです。 
4. 配列をソートします。 Python のタプルの順序付けは主に最初のコンポーネントによってソートされるため、惑星は最小二乗距離から最大二乗距離まで自動的に表示されます。 
5. 名前を結果の順序で出力します。 入力によって明確な距離が保証されるため、タイ処理は必要ありません。 

### なぜ効果があるのか

 不変条件は、保存されているすべての惑星が、星からのユークリッド距離の 2 乗に等しい正確なキーを持っているということです。 任意の 2 つの惑星について`A`そして`B`、平方根は非負の数では厳密に増加するため、キーの順序は実際の距離の順序と同じです。 したがって、これらのキーを並べ替えると、問題で必要とされる最も近いものから最も遠いものまでの順序が正確に生成されます。 ソートによって行われるすべての比較は、実際の幾何学的距離の比較と同等であるため、惑星が間違った位置に表示されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    sx, sy, sz = map(int, input().split())
    n = int(input())

    planets = []

    for _ in range(n):
        x, y, z, name = input().split()
        x = int(x)
        y = int(y)
        z = int(z)

        dx = x - sx
        dy = y - sy
        dz = z - sz

        dist2 = dx * dx + dy * dy + dz * dz
        planets.append((dist2, name))

    planets.sort()

    sys.stdout.write("\n".join(name for _, name in planets))

if __name__ == "__main__":
    solve()
```最初の 2 つの入力行は、星と惑星の数を示します。 次にループは、惑星名を文字列として残したまま、3 つの座標フィールドを整数に変換します。 

減算は二乗する前に座標ごとに行われます。 これは 3D 距離の 2 乗式を直接変換したもので、3 つの個別の変数を使用すると、座標の差ではなく絶対座標を誤って 2 乗することが難しくなります。 

タプル`(dist2, name)`並べ替えには十分です。 Python はタプルを辞書編集的に比較します。`dist2`順序が決まります。 この問題では明確な距離が保証されており、2 番目のタプル コンポーネントが答えに影響を与えることはありません。 

最終的なジェネレーターは名前のみを抽出します。`"\n".join(...)`不要な末尾改行を追加せずに、出力行ごとに 1 つの名前を生成します。 Python では整数の精度が任意であるため、整数オーバーフローの心配はありません。

 ## 特殊なケース

 星の座標と全く同じ位置にある惑星の二乗距離はゼロです。 のために```
0 0 0
1
0 0 0 Home
```アルゴリズムが計算します`dx = dy = dz = 0`、 それで`dist2 = 0`。 1 要素の配列をソートすると、`Home`配置され、出力は`Home`。 当然、ゼロは可能な最小二乗距離であるため、実装には特別なケースはありません。 

負の座標には個別の処理は必要ありません。 のために```
10 10 10
2
9 10 10 A
8 10 10 B
```アルゴリズムは二乗距離を計算します`1`そして`4`。 農産物の仕分け`A`前に`B`。 の負の値`dx`は 2 乗であるため無害であり、これはまさにユークリッド距離の式が必要とするものです。 

この実装により、浮動小数点エラーも回避されます。 のために```
0 0 0
2
3 4 0 A
0 0 6 B
```鍵は`25`そして`36`。 実際の距離は、`5`そして`6`ただし、平方根を計算すると、順序を変更せずに仕事量と浮動小数点値が追加されます。 整数二乗距離ではまったく同じ結果が得られます。 

最後に、惑星は、非常に類似した距離を持ちながら、異なる座標軸に沿って異なる場合があります。 この実装では、惑星を比較する前に、常に 3 つの二乗差をすべて計算します。 例えば、```
0 0 0
2
1 1 1 A
2 0 0 B
```二乗距離を生成します`3`そして`4`したがって、出力は次のようになります```
A
B
```1 つの座標のみを比較するソリューションはこの種の入力では失敗しますが、完全二乗距離キーには 3 つの次元すべてが正しく組み込まれます。
