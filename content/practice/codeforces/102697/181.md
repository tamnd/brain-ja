 ## 問題の理解

 シーケンスの 3 つの位置を表す、正確に 3 つの整数が与えられます。 タスクは、シーケンスが厳密に増加しているかどうかを判断することです。 つまり、最初の値は 2 番目の値より小さく、2 番目の値は 3 番目の値より小さくなければなりません。 

出力は`SORTED`両方の比較が成立する場合。 隣接する 2 つの値が等しい場合を含め、どちらかの比較が失敗した場合、出力は次のようになります。`UNSORTED`。 公式問題には 1 秒の時間制限と 256 MB のメモリ制限があり、入力には 3 つの整数のみが含まれます。 

シーケンスには常に正確に 3 つの値が含まれるため、大規模入力のパフォーマンスに関する重大な懸念はありません。 定数時間ソリューションは問題なく制限内に収まっており、一般的な並べ替えベースのソリューションでも十分高速です。 より有用なアルゴリズムの観察は、ソートが不要であるということです。つまり、必要な条件は 2 つの厳密な不等式として直接記述されます。 

主なエッジケースは平等です。 例えば、```
6 6 7
```生産しなければならない```
UNSORTED
```最初の値が 2 番目の値より厳密に小さいわけではないためです。 を使用した不用意な実装`<=`の代わりに`<`はこのシーケンスを誤って受け入れてしまいます。 こちらも公式サンプル第2弾です。 

もう 1 つのエッジ ケースは、2 回目の比較でのみ減少するシーケンスです。 例えば、```

## アプローチ

 単純な総当たりアプローチでは、3 つの値の可能な順序をすべて生成し、増加する配列を探します。 あるのは`3! = 6`したがって、これは一定数の演算を実行し、慎重に実装すれば正しいものになります。 ただし、この特定の問題については、必要以上に一般的な問題が解決されます。 値の数が 3 に固定されているため、このブルート フォースが遅すぎる場合の入力サイズのしきい値はありません。 一般化されたバージョンでは、`n`価値観が同じであれば、同じ戦略が必要になります`n!`順列、到達`3,628,800`可能性はすでにある`n = 10`そしてすぐに使えなくなってしまいます。 

より直接的なアプローチは、並べ替え順序の定義を文字通りに読み取ることによって得られます。 シーケンス`[a, b, c]`厳密に言うといつ増加するか`a < b`そして`b < c`。 これら 2 つの条件を直接テストして、対応する結果を出力できます。 2 つのアプローチはどちらも実際の問題に対して定数時間ですが、直接比較することで無駄な作業がなく、必要な条件を正確に表現できます。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取ります`a`、`b`、 そして`c`。 これらは、順序を確認する必要がある値です。 
2. かどうかをテストします。`a < b`そして`b < c`。 この問題では非降順ではなく厳密な昇順が必要であるため、両方の比較が真である必要があります。 
3. 印刷`SORTED`両方の比較が真の場合。 それ以外の場合は印刷します`UNSORTED`。 シーケンスを拒否するには、比較が 1 回失敗するだけで十分です。 

### なぜ効果があるのか

 このアルゴリズムは、長さ 3 の厳密に増加するシーケンスを定義する 2 つの条件を正確にチェックします。 両方の場合`a < b`そして`b < c`保持すると、連続するすべてのペアが必要な順序になっているため、シーケンス全体がソートされます。 いずれかの条件が満たされない場合、少なくとも 1 つの連続するペアが厳密な順序に違反するため、シーケンスを並べ替えることはできません。 等価性は正しく拒否されます。`<`ではなく使用されます`<=`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    if a < b and b < c:
        print("SORTED")
    else:
        print("UNSORTED")

if __name__ == "__main__":
    solve()
```入力行は 1 回読み取られ、3 つの整数値に分割されます。 問題にはテスト ケースが 1 つだけ含まれているため、テスト ケースのループはありません。 

この条件では、結合された 2 つの比較が使用されます。`and`。 Python は、両方の不等式が成立し、厳密な昇順の数学的定義と一致する場合にのみ、これを true と評価します。 使用する`<=`この問題では、隣接する等しい値は並べ替えられたとはみなされないため、off-by-one スタイルの論理エラーが発生します。 

並べ替え操作は必要なく、追加のデータ構造も必要ありません。 Python の整数にも任意の精度があるため、入力で許可される大きさに関係なく、整数オーバーフローの心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()

        a, b, c = map(int, sys.stdin.readline().split())

        if a < b and b < c:
            print("SORTED")
        else:
            print("UNSORTED")

        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3 5 8\n") == "SORTED\n", "sample 1"
assert run("6 6 7\n") == "UNSORTED\n", "sample 2"
assert run("5 2 1\n") == "UNSORTED\n", "sample 3"

# Minimum-size style case, with the smallest values in increasing order
assert run("1 2 3\n") == "SORTED\n", "minimum increasing case"

# All values equal
assert run("7 7 7\n") == "UNSORTED\n", "equality must not be accepted"

# Only the second comparison fails
assert run("1 10 9\n") == "UNSORTED\n", "second boundary comparison"

# Large values and a fully increasing sequence
assert run("1000000000 1000000001 1000000002\n") == "SORTED\n", "large values"

 ## 特殊なケース

 平等の場合`6 6 7`最初の比較が次のように評価されるため、処理されます。`6 < 6`、これは誤りです。 アルゴリズムは即座に選択します`UNSORTED`。 次のような非厳密な比較`6 <= 6`誤った結果が生成されるため、演算子の選択が重要です。 

ケース`1 5 3`は、両方の隣接するペアをチェックする必要がある理由を示しています。 最初の比較では、`1 < 5`、成功しますが、2 番目の比較では、`5 < 3`、失敗します。 アルゴリズムは両方の条件を組み合わせて、`and`ので、正しく印刷されます`UNSORTED`。 

ケース`5 2 8`最初の比較で演習が失敗します。 以来`5 < 2`が false の場合、3 番目の要素の値に関係なく、完全なシーケンスは増加することはできません。 アルゴリズムは引き続き完全なブール式を正しく評価し、出力します。`UNSORTED`。 

ついに、`1 2 3`を生み出す唯一の状況を示しています。`SORTED`: 隣接する比較は両方とも真です。 このアルゴリズムでは、値に特別な違いがある必要はなく、連続する要素間の厳密な順序付けのみが必要です。
