 ## 解決策
 ## 問題の理解

 入力は整数のように見えるトークンのシーケンスですが、これらのトークンは通常の 10 進数ではなく 8 進数で書き込まれます。各 8 進数は、10 進数に変換された後の 1 つの Unicode コード ポイントを表します。 必要な出力は、すべてのトークンを対応する Unicode 文字に変換し、それらの文字を元の順序で連結することによって形成された文字列です。 たとえば、公式の例は次のように始まります。`164 150 151`、10 進値の 8 進数表現です。`116 104 105`、文字を与える`t`、`h`、 そして`i`。 

公開されている問題の説明には、配列のサイズや数値の上限は記載されていません。 したがって、関連する入力サイズは、8 進数の桁とトークンの合計数になります。 正しいソリューションでは各トークンを 1 回処理する必要があるため、その実行時間は入力量に対して直線的になるはずです。 考えられる文字値を検索したり、無関係なエンコーディングを繰り返しテストしたりするアプローチは、不必要な作業を追加することになります。 

入力には、依存する固定の行数もありません。 数値はスペースで区切られているため、実装では 1 行に 1 文字を想定するのではなく、空白で区切られたすべてのトークンを読み取る必要があります。 次のようなトークン`040`これも便利な境界ケースです。先頭のゼロは 8 進数表現の一部ですが、数値は変わらないため、10 進数を表します`32`、スペース文字。 トークンを 10 進数として扱う不注意な実装では、次のように解釈されます。`40`32 ではなく 40 として間違った文字が生成されます。 

もう 1 つの特殊なケースは、単一の文字です。 たとえば、入力`141`小数を表します`97`したがって、出力は次のようになります`a`。 複数の数値が存在する必要があると想定したソリューションでは、インデックス作成エラーや連結エラーが不必要に発生します。 

ステートメントでは結果を英語の文字に制限するのではなく Unicode 値を記述するため、値は通常の小文字および大文字の ASCII 以外の文字を表すこともできます。 したがって、変換では、ASCII のみのルックアップ テーブルを使用するのではなく、結果のコード ポイントから Unicode 文字を生成する必要があります。 

## アプローチ

 最も直接的なアプローチは、すべての 8 進トークンを手動で変換することです。 数字を含むトークンの場合`d1 d2 ... dk`、その値は繰り返し適用することで取得されます。`value = value * 8 + digit`。 新しい数字ごとに、前に処理された値が 1 進数 8 桁ずつシフトされるため、これは正しいです。 入力桁数の合計が`L`、これは正確に実行されます`L`数値処理の反復により、`O(L)`時間と`O(1)`出力とは別に補助スペース。 

2 番目の単純な解釈は、8 進表現がトークンと一致するものが見つかるまで、考えられるすべての Unicode 値を試してみることです。 そのアプローチは原理的には正しいですが、ここに存在する有用な理由はありません。 すべての入力トークンに対して潜在的に大きなコードポイント範囲を検索するには、実際に存在する桁数よりもはるかに多くの作業がかかる可能性があります。 

重要な観察は、問題が要求する操作をプログラミング言語がすでに正確に提供しているということです。 パイソンの`int(token, 8)`文字列を基数 8 の整数として解釈し、`chr(value)`Unicode コードポイントをその文字に変換します。 問題は、隠されたエンコーディングを発見したり、パターンを推測したりすることを求めているわけではありません。 これは単に、トークンごとにこれら 2 つの決定論的な変換を個別に実行するように求めているだけです。 

ブルートフォース文字検索は、その動作が入力のサイズではなく Unicode 範囲のサイズに依存するため、失敗します。 直接変換では、各トークンが 1 つの Base-8 解析操作に減らされ、その後に文字変換が行われます。 Python の整数パーサーはトークンの数字を処理するため、合計作業量は入力サイズに線形のままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 直接 8 進数変換 | O(L) | 出力の場合は O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 標準入力から空白で区切られたすべてのトークンを読み取ります。 入力では区切り文字としてスペースが使用されるため、空白を均一に扱うことで、行の構造についての仮定を避けることができます。 
2. 各トークンについて、次の基数 8 の整数として解釈します。`int(token, 8)`。 2 番目の引数は、数字が 8 進数システムを使用して解釈される必要があることを Python に明示的に伝えます。 
3. 結果の整数を Unicode 文字に変換します。`chr(value)`。 この問題により、値が有効な Unicode 文字を表すことが保証されるため、変換ごとに 1 つの文字が生成されます。 
4. 結果として得られるすべての文字をリストに追加し、リストの最後に 1 回結合します。 この方法で完全な文字列を構築すると、より大きな中間文字列を繰り返し作成することを回避できます。 

### なぜ効果があるのか

 入力トークンごとに、`int(token, 8)`そのトークンによって表される整数を基数 8 で正確に計算します。この問題では、その整数を目的の文字の Unicode コード ポイントとして定義し、`chr`そのコードポイントに関連付けられた文字を正確に返します。 トークンは元の順序で処理されるため、生成される文字も必要な順序になります。 したがって、出力内のすべての位置は 1 つの入力数値に正確に対応し、正しい Unicode 値を持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    tokens = sys.stdin.read().split()
    result = []

    for token in tokens:
        value = int(token, 8)
        result.append(chr(value))

    sys.stdout.write("".join(result))

if __name__ == "__main__":
    solve()
```このソリューションは、完全な入力を読み取ります。`sys.stdin.read().split()`。 必要なテンプレートでは次のように定義されていますが、`input = sys.stdin.readline`、実際の解決策は使用します`read()`入力に意味のある行構造がないためです。 を維持する`input`定義は引き続き、要求された競技プログラミング テンプレートに従います。 

各トークンは直接渡されます`int`ベース付き`8`。 これは、意図した数値体系を明示し、先頭のゼロを自然に処理するため、最初に 10 進数のテキストを介して変換するよりも安全です。 

結果の整数はに渡されます`chr`、Unicode コードポイント変換を実行します。 Python の整数には任意の精度があるため、変換中に C++ スタイルの符号付き整数のオーバーフローの問題は発生しません。 

文字が保存されている場所は、`result`そして一度参加しました。 これにより、ループ内で文字列を繰り返し連結するのではなく、最終的な出力サイズで線形の動作が得られます。

## 複雑さの分析

 | --- | --- | --- |
 | 時間 | O(L) | すべての入力数字は 1 回の 8 進数変換の一部として処理され、結果のすべての文字が 1 回出力されます。 |

## 特殊なケース

 次のような単一の入力トークン`141`正確に 1 文字を生成する必要があります。 アルゴリズムは 1 つのトークンを読み取り、評価します`int("141", 8)`として`97`、変換します`97`に`a`、そして 1 要素の結果リストに結合します。 出力は`a`。
