 ## 解決策
 ## 問題の理解

 このタスクは、2 つの有効な日付が何暦日離れているかを計算することです。 各日付は、たとえば、月名、日番号、年として書き込まれます。`June 21, 2019`。 2 番目の日付は最初の日付よりも後になることが保証されているため、答えは単純に最初の日付から 2 番目の日付までの前進距離になります。 この問題の以前のバージョンとは異なり、うるう年をカウントする必要があります。 

入力にはちょうど 2 行が含まれており、各行に 1 つの日付が含まれています。 出力は 1 つの整数で、これらの日付間の午前 0 時から午前 0 時までの境界の数を表します。 たとえば、2019 年 6 月 21 日から 2020 年 6 月 21 日へ移動すると、間隔に 2020 年 2 月 29 日が含まれるため、366 日を超えます。 

この声明では、年数の上限は公表されていない。 制限時間は 1 秒、メモリ制限は 256 MB です。 入力は 2 つの日付のみで構成されているため、最もクリーンなソリューションでは、日付の間の年数に依存するのではなく、一定量の作業を使用する必要があります。 一度に 1 日ずつ進むソリューションは暦日ごとに 1 回の反復を実行するため、実行時間は日付間の距離に応じて長くなります。 絶対的な日数に基づくソリューションは、その依存関係を完全に回避します。 

一見単純な実装が間違っている可能性がある箇所がいくつかあります。 1 つ目はエンドポイントです。 のために```
June 21, 2019
June 22, 2019
```答えは`1`、 ない`2`。 経過日数を測定しているため、開始日は 0 日であり、次の日付はちょうど 1 日離れています。 両方のエンドポイントをカウントする実装では、1 つずつ異なる回答が生成されます。 

第2回は閏年の2月です。 のために```
February 28, 2020
March 1, 2020
```答えは`2`2 月 29 日が 2 つの日付の間にあるためです。 毎年 2 月を 28 日あるものとして扱うソリューションでは、次の結果が返されます。`1`。 

3 番目の問題は、完全なグレゴリオ暦閏年規則です。 4 で割り切れる年は通常閏年ですが、世紀の年は 400 で割り切れない限り閏年ではありません。```
February 28, 1900
March 1, 1900
```答えがあります`1`、 その間```
February 28, 2000
March 1, 2000
```答えがあります`2`。 チェックのみ`year % 4 == 0`1900 年をうるう年として誤って扱います。 

4番目の問題は、年の境界を越えることです。 のために```
December 31, 2019
January 1, 2020
```答えは`1`。 日付が連続していても年が変わるため、日フィールドと月フィールドのみを比較する計算ではこれを正しく処理できません。 

## アプローチ

 最も直接的な解決策は、最初の日付から開始し、2 番目の日付に到達するまで 1 日ずつ進めることを繰り返すことです。 進むたびに答えが 1 つずつ増えます。 日付を進めるには、現在の月の日数を把握し、翌月への移行を処理し、12 月から 1 月への移行を処理する必要があります。 2 月は、その年がうるう年かどうかによっても異なります。 すべての反復が間隔内のちょうど 1 暦日に対応するため、この方法は正しいです。 

このアプローチの問題は、日付間の距離に依存していることです。 年が (Y) だけ異なる場合、ループはおよそ (365Y) 回の反復を実行します。 たとえば、100 万年のギャップには、約 3 億 6,500 万日の移行が必要になります。 それぞれの遷移は単純ですが、それは 1 秒のソリューションに求められるものをはるかに超えています。 このステートメントでは年の差に小さな上限が示されていないため、日ごとのシミュレーションは確実な選択肢ではありません。 

重要な観察は、日付を絶対日インデックスに変換できることです。 両方の日付にそのようなインデックスがあると、それらの距離は単に 2 つのインデックスの差になります。 個々の日をシミュレーションする必要はありません。 

このインデックスを作成するには、日付までの完全な年数をすべてカウントし、次にその年内の日付までのすべての完全な月数をカウントし、最後に日番号を追加します。 完全な平年は 365 日になります。 完全な閏年は 366 に寄与します。年 (y) より前の閏年の数は、次の式を使用して直接計算できます。 

\left\lfloor\frac{y-1}{100}\right\rloor
 +
 \left\lfloor\frac{y-1}{400}\right\r 床。 
】

 100 を減算すると閏年ではない世紀年が削除され、400 を加算すると 2000 年などの年が復元されます。 

次に、任意の固定原点を基準にして、すべての有効な日付をその日付より前の日数にマッピングする関数を定義できます。 2 つの日付を減算するとキャンセルされるため、原点の選択は重要ではありません。 これにより、問題全体が固定数の算術演算に削減されます。

 | 最適 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの日付文字列を読み取り、それぞれを月名、日、年に分割します。 日の後のカンマは入力書式設定の一部であるため、日を整数に変換する前にカンマを削除してください。 
2. 月の名前を 1 ～ 12 の数値に変換します。月の名前は 12 個しかないため、固定の辞書で十分です。 
3. グレゴリオ暦のうるう年の述語を定義します。 400 で割り切れる場合、または 4 で割り切れるが 100 では割り切れない場合、その年はうるう年になります。 
4. 関数を定義する`days_before_year(year)`これは、指定された年より厳密に前のすべての年の日数を返します。 がある`year - 1`前の年とその中の閏年の数は上記の式で求められます。 したがって、合計は`365 * (year - 1) + leap_years`。 
5. 関数を定義する`days_before_date(year, month, day)`。 年の前の日数から始めて、現在の月までのすべての月の長さを追加し、最後に追加します。`day - 1`。 私たちが使用するのは`day - 1`月の最初の日には、その月の初めからの経過日数がゼロになる必要があるためです。 
6. 両方の入力日付の絶対日インデックスを計算し、最初のインデックスを 2 番目のインデックスから減算します。 このステートメントは 2 番目の日付が後であることを保証しているため、結果はすでに負ではありません。 

重要な不変条件は次のとおりです`days_before_date(y, m, d)`日付の始まりから遡る完全な暦日数を正確に表します`(y, m, d)`。 すべての完全な年はその正確な 365 日または 366 日を表し、すべての完全な月は実際の長さを表します。`day - 1`当月の完了日数をカウントします。 したがって、2 つのインデックスを減算すると、最初の日付より前のすべてが削除され、2 つの日付を区切る日が正確に残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MONTHS = {
    "January": 1,
    "February": 2,
    "March": 3,
    "April": 4,
    "May": 5,
    "June": 6,
    "July": 7,
    "August": 8,
    "September": 9,
    "October": 10,
    "November": 11,
    "December": 12,
}

MONTH_DAYS = [
    31, 28, 31, 30, 31, 30,
    31, 31, 30, 31, 30, 31
]

def is_leap(year):
    return year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)

def parse_date(s):
    parts = s.strip().replace(",", "").split()
    month = MONTHS[parts[0]]
    day = int(parts[1])
    year = int(parts[2])
    return year, month, day

def days_before_year(year):
    y = year - 1
    leap_years = y // 4 - y // 100 + y // 400
    return 365 * y + leap_years

def days_before_date(year, month, day):
    result = days_before_year(year)

    for m in range(1, month):
        result += MONTH_DAYS[m - 1]

    if month > 2 and is_leap(year):
        result += 1

    result += day - 1
    return result

def solve():
    date1 = parse_date(input())
    date2 = parse_date(input())

    first = days_before_date(*date1)
    second = days_before_date(*date2)

    print(second - first)

if __name__ == "__main__":
    solve()
```の`MONTHS`Dictionary は、脆弱な文字列比較を使用する代わりに、テキストの月表現を直接処理します。 カンマを削除した後、次のような入力`June 21, 2019`3 つのクリーン トークンになります。`June`、`21`、 そして`2019`。 

の`is_leap`関数は完全なグレゴリオ規則を使用します。 条件を次のように書くと、`year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)`通常の閏年、非閏世紀年、閏世紀年を 1 つの式で処理します。 

の`days_before_year`関数の使用法`year - 1`それよりも`year`。 この境界は間違えやすいです。 2020 年の場合、1 年から 2019 年までの閏年の数が必要なので、すべての除算は 2019 年に実行されます。 

month ループでは、厳密に現在の月より前の月のみが追加されます。 1 月の日付の場合、ループは 0 回実行されます。 3 月の日付の場合は、1 月と 2 月が追加されます。 2月の臨時日はその年に依存するため別途加算されます。 

最後の追加は、`day - 1`。 1 月 1 日の場合、関数は 1 月内の 1 日ではなく、0 日をカウントする必要があります。 この選択により、連続する日付が 1 つだけ異なることになります。 

Python の整数はオーバーフローしないため、非常に大きな年の値であっても特別な整数処理を必要としません。
