 ## 解決策
 ## 問題の理解

 この問題は、長方形の箱の山を一方の隅から反対側の隅まで横切ったホバークラフトについて説明しています。 飛んだ距離は長方形の対角線です。 長方形の一辺の長さは既知であり、タスクは長方形の外側を一周してホバークラフトに到達するために必要な歩行距離を見つけることです。 必要な距離は、長方形の 2 つの辺の長さの合計です。 

入力には対角線の長さが含まれます`n`長方形と一辺の長さ`m`。 出力は、残りの辺の長さを加算したものになります。`m`。 対角線、幅、高さは直角三角形を形成するため、ピタゴラスの定理を使用して不足している辺を見つけることができます。 

制約は十分に小さいため、主な課題はパフォーマンスではなく、幾何学的関係を認識することです。 値が非常に大きい場合でも、解決には一定数の算術演算のみが必要です。 シミュレーション、可能な辺の長さの検索、または距離にわたる反復を伴うアプローチでは、必要以上に難しい問題を解決することになります。 

主なエッジケースは、ジオメトリを正しく処理することで発生します。 指定された辺が対角線と等しい場合、入力は長さ 0 の欠損辺を持つ長方形を表すことになるため、負の値の平方根を盲目的に取得する不用意な実装は失敗します。 たとえば、入力`5 5`残りの辺は次のようになります`0`、したがって、答えは次のとおりです`5.0`。 

もう 1 つのよくある間違いは、歩道ではなく対角線を返すことです。 入力の場合:```
10
6
```対角線は`10`、しかし反対側は`8`ですので、歩いて行ける距離は、`6 + 8 = 14.0`。 飛距離を印刷するソリューションでは、間違った答えが生まれます。 

浮動小数点フォーマットも考えられる問題です。 入力の場合:```
14
13
```欠けている側は`sqrt(27)`、これはおよそ`5.1961524227`、したがって、答えはおよそ`18.1961524227`。 整数演算では必要な精度が失われます。 

## アプローチ

 この問題を考える強引な方法は、未知の側の可能な値を試してみることです。 For every candidate length`x`かどうかを確認できます。`m^2 + x^2 = n^2`。 有効な辺が見つかったら、それを追加します`m`。 すべての長方形はピタゴラスの定理を満たさなければならないため、このアプローチは正しいです。 

ただし、このアプローチは不必要であり、時間がかかる可能性があります。 対角線が大きくなる可能性がある場合、考えられるすべての辺の長さをチェックするには、最大で`O(n)`試行し、各試行で算術チェックが実行されます。 最悪の場合、問題が必要とする作業をはるかに超える作業が必要になります。 

重要な観察は、長方形の対角線によって、必要な正確な関係がすでに得られているということです。 3 つの長さは直角三角形を形成するため、未知の辺は直接決定されます。$$x^2 + m^2 = n^2$$並べ替えると次のようになります。$$x = \sqrt{n^2 - m^2}$$この方程式を満たす値を検索するため、総当り的なアプローチが機能しますが、方程式にはすでに直接の解が存在します。 長方形が直角三角形に縮小されることが観察されると、検索は完全に削除されます。

 ## アルゴリズムのチュートリアル

 1.対角線の長さを読み取る`n`既知の辺の長さ`m`。 これら 2 つの値は、長方形の辺と対角線によって形成される直角三角形を定義します。 
2. 次を使用して未知の辺を計算します。`sqrt(n * n - m * m)`。 対角線は三角形の斜辺であるため、減算により不足している辺の 2 乗が得られます。 
3. 既知の側面を追加する`m`そして計算された側も一緒に。 長方形の周りを歩くということは、対角線に沿ってではなく、垂直な 2 つの辺に沿って移動することを意味します。 
4. 結果を浮動小数点数として出力します。 平方根は整数ではない可能性があるため、出力では小数精度を維持する必要があります。 

アルゴリズムの背後にある不変条件は、対角線が常に長方形によって形成される直角三角形の斜辺のままであるということです。 計算された値は欠落している辺の唯一の可能な長さであるため、それを既知の辺に追加すると、ホバークラフトに到達する長方形の周囲の正確なパスが得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = float(input())
    m = float(input())

    other = math.sqrt(n * n - m * m)
    ans = m + other

    print(ans)

if __name__ == "__main__":
    solve()
```最終的な答えには小数が含まれる可能性があるため、プログラムは 2 つの長さを浮動小数点値として読み取ります。 ステートメントでは入力を正の整数として記述していますが、次のように使用します。`float`平方根演算と出力フォーマットに関して実装を安全に保ちます。 

表現`n * n - m * m`未知の辺の二乗の長さを計算します。 後で平方根を取ると、実際の辺の長さがわかります。 ここでは演算の順序が重要です。減算する前に平方根を取ることはジオメトリを表しません。 

最後の追加では、歩行ルートが箱の山を周回するため、長方形の 2 辺を使用します。 ループ、検索、または格納された配列がないため、実装のサイズは一定のままです。

## テストケース```python
import sys
import io
import math

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    n = float(sys.stdin.readline())
    m = float(sys.stdin.readline())
    print(m + math.sqrt(n * n - m * m))

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out.getvalue()

assert solve_case("10\n6\n").strip() == "14.0", "sample 1"
assert solve_case("14\n13\n").strip() == "18.196152422706632", "sample 2"

assert solve_case("5\n5\n").strip() == "5.0", "zero missing side"
assert solve_case("13\n5\n").strip() == "17.0", "12-5-13 triangle"
assert solve_case("100000\n60000\n").strip() == "140000.0", "large values"
assert solve_case("25\n24\n").strip() == "32.0", "boundary precision case"

 ## 特殊なケース

 既知の辺が対角線と等しい場合、残りの辺はゼロになります。 入力の場合:```
5
5
```計算は次のようになります`sqrt(25 - 25) = 0`、そして答えは`5.0`。 アルゴリズムはゼロの平方根を許可するため、これを自然に処理します。 

長方形の辺の長さが整数でない場合、ソリューションでは整数の切り捨てを回避する必要があります。 入力の場合:```
14
13
```欠けている側は`sqrt(27)`、 ない`5`。 アルゴリズムは 10 進数値を保持し、正しい歩行距離を返します。 

歩行距離とホバークラフトの飛行距離を混同すると、単純な場合に誤差が生じます。 入力の場合:```
10
6
```ホバークラフトが旅した`10`足は斜めに歩きますが、側面に沿って歩かなければなりません。`6 + 8 = 14`。 このアルゴリズムでは、対角線ではなく長方形の辺を使用するため、正しいルートが返されます。
