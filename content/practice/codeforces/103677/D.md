 ## 解決策
 ## 問題の理解

 ブドウの種類のセットが与えられており、各種類には必要な最低使用量が定められています。 ワイナリーはワインのボトルを製造しており、各ボトルは正確に選択されて形成されます。$n-1$特徴的なブドウの種類のうち、$n$選択したタイプごとに 1 つのユニットを使用して利用可能です。 

したがって、すべてのボトルは、そのボトルで除外されている 1 つの選択されたタイプを除くすべてのブドウのタイプに +1 の使用量をもたらします。 

私たちの仕事は、すべてのブドウの種類に応じて必要なボトルの最小数を決定することです。$i$少なくとも使われている$a_i$回。 

言い換えれば、各ボトルはちょうど 1 つのブドウの種類を「ミス」します。ミスはそのボトルでブドウが使用されていないことを意味するため、どのタイプも何度もミスしないように、これらのミスをスケジュールする必要があります。 

重要な隠された構造は、ブドウが使用される合計回数は、それを回避するボトルの数にのみ依存するということです。 作ったら$k$ボトル、次にブドウの種類$i$まさに使われている$k - b_i$回、どこで$b_i$それを除いたボトルの数です。 制約は次のようになります。$$k - b_i \ge a_i \quad \Rightarrow \quad b_i \le k - a_i$$各ボトルは正確に 1 つのタイプを除外するため、すべての除外の合計は正確に次のようになります。$k$:$$\sum b_i = k$$私たちは、タイプごとの上限の下でこれらの除外を分散する方法を選択しています。 

制約から$n \le 10^5$そして$a_i \le 10^9$、ボトルを 1 つずつシミュレートしようとするソリューションは不可能です。 単純なシミュレーションでは、潜在的に最大で$10^9$タイプごとの操作は時間制限をはるかに超えています。 平$O(nk)$アプローチはすぐに除外されます。$k$それ自体は大きくなる可能性があります。 

微妙なエッジケースが現れるのは、$a_i$等しいです。 たとえば、すべての値が 4 の場合、対称性は除外のバランスの取れた分布を示唆しており、「常に現在の最小の満たされたタイプを選択する」という貪欲な方法は、慎重に分析しないと失敗する可能性があります。 もう 1 つの注意が必要なケースは、次のような場合です。$a_i$他のタイプよりもはるかに大きいため、ほとんどのボトルはそのタイプを早期に除外することを余儀なくされます。そうしないと、他のタイプを満たすことができなくなります。 

## アプローチ

 強引な解釈では、ボトルを一度に 1 つずつシミュレートします。 ボトルごとに、除外するブドウの種類を選択し、使用数を更新します。 これはプロセス定義に直接従うため、正しいです。 ただし、各ボトルでは以下から除外を選択する必要があります。$n$タイプがあり、最大で必要になる場合があります$k$ボトル、どこ$k$のオーダーにすることができます$10^9$。 これにより、最悪の場合の複雑さが生じます。$O(nk)$、それは不可能です。 

重要な洞察は、視点を逆転させることです。 各ボトルにどのブドウを使用するかを決めるのではなく、各ブドウを何回除外するかを決定します。 除外するたびに、そのブドウの使用量への貢献が減ります。 問題は配布になる$k$同一の除外トークン$n$バケツ、それぞれのバケツ$i$容量がある$k - a_i$。 

これにより、問題は特定の条件の実行可能性チェックに変換されます。$k$。 実現可能性を確認できたら、最小限の二分探索を行うことができます。$k$。 実現可能性の条件は、次のことを確認することになります。$$\sum \max(0, k - a_i) \ge k$$なぜならそれぞれ$k - a_i$は最大回数タイプです$i$除外することができ、除外の合計は正確に合計される必要があります$k$。 

次に、最小のものを二分探索できます$k$この不等式を満たすこと。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(nk)$|$O(n)$| 遅すぎる |
 | 二分探索 + 実現可能性チェック |$O(n \log A)$|$O(n)$| 承認済み |

 ここ$A = \max a_i$。 

## アルゴリズムのチュートリアル

 ### 最適なアルゴリズム

 1. 一定の数のボトルについて観察します。$k$、各ブドウの種類$i$除外されるボトルを除くすべてのボトルに使用されています。 これにより使用感が得られます$k - b_i$、 どこ$b_i$タイプに割り当てられた除外の数です$i$。 
2. 要件を翻訳する$k - b_i \ge a_i$除外の制約に変換します。$b_i \le k - a_i$。 これは、各タイプを「スキップ」できる回数を示します。 
3.固定の場合$k$、すべてのタイプにわたって割り当てることができる除外の合計数を計算します。 これは$\sum \max(0, k - a_i)$型を否定的に除外することはできないため、次の場合$a_i > k$、何も貢献しません。 
4. 実現可能性を確認します: 利用可能な除外容量の合計が少なくとも$k$、その後、それぞれを割り当てることができます$k$タイプごとの制限に違反することなく、明確に除外されたタイプをボトルに入れます。 そうでなければ不可能です。 
5. 二分探索を使用する$k$。 下限は$0$、安全な上限は$2 \cdot \max(a_i)$、それを超えると、すべての制約が自明に満たされるようになるためです。 
6. 二分探索の各中間値について、全体にわたって線形時間で実現可能性チェックを実行します。$a_i$。 

### なぜ効果があるのか

 このアルゴリズムは、各ボトルが 1 つの除外に寄与するという不変条件に依存しているため、システムは分散と同等になります。$k$同一のトークンを境界のあるコンテナに入れます。 実現可能性チェックでは、コンテナーの総容量がすべてのトークンを保持するのに十分であるかどうかを正確に特徴付けます。 容量が不十分な場合は、少なくとも 1 つのブドウの種類を許容回数を超えて除外する必要があり、その要件に違反します。 容量が十分な場合、総容量とタイプごとの制限を超える制約の間には結合がないため、除外の貪欲な割り当てが常に存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, a):
    total = 0
    for x in a:
        if k > x:
            total += k - x
    return total >= k

def main():
    n = int(input())
    a = list(map(int, input().split()))

    lo, hi = 0, 2 * max(a)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, a):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    main()
```コードの中心となる構造は実現可能性関数です。`can(k, a)`、ボトルの候補数に基づいて割り当てられる除外の数を計算します。 各エントリは次の場合にのみ貢献します。$k$それを超えていると、要件に違反することなくそのブドウを一度でも除外することができないためです。 

二分探索では、指定された数のボトルが十分であるかどうかを繰り返しテストすることで、答えを絞り込みます。 単調性は、増加するという事実から来ます。$k$除外能力を決して減少させず、必要な除外を常に直線的に増加させます。 

よくある実装の落とし穴は、条件がグローバルであることを忘れていることです。ボトルごとに除外を貪欲に割り当てるのではなく、総容量のみに依存します。 ボトルごとの決定をシミュレートしようとすると、ロジックが複雑になりすぎて順序付けのバグが発生する危険があります。

 ## 特殊なケース

 ブドウの種類が 1 つある最小限の入力。$n=1, a_1=1$、アルゴリズムが実現可能性の不等式のみに依存するように強制されます。 のために$k=1$、容量はゼロなので実行不可能ですが、$k=2$、容量がプラスとなり条件を満たします。 アルゴリズムは正しく 1 を返します。

次のような均一な配列$a_i = 5$対称性をテストします。 小型用$k$、容量が足りないのですが、一応$k$5 を超えると、すべてのタイプが均等に寄与し、実現可能性は次のように二次関数的に増加します。$k$、二分探索が正しいバランスの値に確実に収束するようにします。
