 ## 解決策
 ## 問題の理解

 このタスクでは、各エッジにも色が付けられる、成長する無向グラフについて説明します。 エッジは追加されるだけで、削除されることはありません。 これらの更新には接続性クエリがインターリーブされますが、接続性は通常の任意のウォークの意味では定義されません。 代わりに、有効なパスはエッジの色に関する厳密な交互規則を満たさなければなりません。 

パスは、そのエッジが連続するペアにグループ化でき、各ペア内の 2 つのエッジが同じ色であれば、許容されます。 つまり、パスをエッジごとに見ると、エッジ 1 とエッジ 2 は同じ色を共有する必要があり、エッジ 3 とエッジ 4 は同じ色を共有する必要があり、以下同様になります。 したがって、エッジ内のパスの長さはペアで構成されているため、偶数である必要があります。 

この問題では、更新またはクエリのたびに、すでに表示されているエッジのみを使用するこのような制約されたパスで 2 つの都市を接続できるかどうかが問われます。 

制約が十分に大きいため、クエリごとの到達可能性を再計算するアプローチは遅すぎます。 最大 200,000 の合計操作と同様に大きくなる可能性のあるグラフでは、クエリごとの BFS など、パスを直接探索するメソッドは、密度が高い場合には二次関数の動作に低下し、時間制限の下で失敗します。 制約はペアリング構造を通じて色全体の隣接するエッジを結合するため、色ごとに標準の接続性を個別に維持するだけでは不十分です。 

単純なソルバーが各色のサブグラフを個別に処理する場合、微妙なエッジ ケースが発生します。 たとえば、都市 1 が赤を介して 2 に、赤を介して 2 から 3 に、青を介して 3 から 4 に接続する場合、単純なアプローチでは部分的な接続プロパティを誤って仮定する可能性がありますが、色は自由に交互するのではなく、隣接するペアで繰り返す必要があるため、パス 1 から 4 は無効になります。 ソリューションが交互カラー パスが有効であると想定している場合、別の障害モードが発生します。 交互ではなく、ペアで繰り返すというより厳しい条件です。 

## アプローチ

 クエリに答える最も直接的な方法は、有効なパスを明示的に検索することです。 これは、ソースから BFS または DFS を実行することを意味しますが、次のエッジが前の色と一致する必要があるか、新しいペアを開始する必要があるかどうかを状態に含める必要があります。 この改善を行ったとしても、各クエリはグラフの大部分を探索する可能性があり、最大 200,000 のクエリとエッジでは、これは実行不可能になります。 最悪の場合、各トラバースがすべてのエッジに触れることになり、およそ O(nq) 個の動作が発生します。 

重要な構造的洞察は、「同じ色の二重エッジ」という制約を再解釈することです。 単一のエッジについて考える代わりに、有効な 2 段階の遷移の観点から考えることができます。中間ノード u と色 c が存在し、両方のエッジ (x, u) と (u, v) が存在し、同じ色 c を共有する場合、ノード x からノード v に進むことができます。 解決策の経路におけるすべての有効な動きは、まさにこのような 2 つのエッジの連鎖です。 

この再フレーム化により、問題は同じノード上に暗黙的な色のないグラフを構築することに変換されます。x と v が 2 ステップの同色ウォークで接続できる場合、それらの間にエッジが存在します。 各クエリに対する答えは、単純に、x と y がこの派生グラフの同じ連結成分にあるかどうかです。 

難しいのは、この派生グラフが明示的に与えられることはなく、エッジが追加されると動的に変化することです。 ただし、段階的に構築することはできます。 色付きのエッジ (u、v、c) を追加するたびに、以前に隣接していたすべての同じ色のエッジを使用して、新しい 2 ステップの機会が作成されます。 u がすでに色 c を介して多くのノードに接続されている場合、v を u に接続すると、v とそれらすべてのノード間の接続が直ちに誘導され、u に対して対称的に接続されます。

ノードと色ごとに、その色で接続されている隣接ノードのリストを維持します。 新しいエッジが到着すると、すべての新しい誘導 2 ステップ接続が生成され、素セット結合構造を使用してコンポーネントがマージされます。 この効率を維持するために、常に小さな隣接構造を大きな隣接構造にマージし、各隣接エントリがプロセス全体で対数的にのみ移動されるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース検索 | O(nq) | O(n + m) | 遅すぎる |
 | 小から大へのマージを伴う DSU 誘導 2 段階グラフ | O((n + q) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 都市全体にわたって素のセット和集合構造を維持し、派生した 2 段階のグラフで接続性を表します。 また、都市と色ごとに、その色の下にある隣接都市のセットも維持します。 

初期エッジは更新とまったく同じように処理するため、初期化は挿入のバッチを処理することと同じです。 

### ステップ

 1. すべての都市に対して DSU を初期化します。各都市は独自のコンポーネントで開始します。 この DSU は、生のエッジではなく、有効なダブル レインボー トランジションを使用して接続を表します。 
2. 色 c のエッジによって接続された u のすべての近傍を格納する構造体 adj[u][c] を維持します。 
3. すべてのエッジ挿入 (最初のエッジを含む) を 1 つずつ処理します。 エッジ (u、v、c) については、まず adj[u][c] と adj[v][c] の両方が存在することを確認します。 
4. adj[u][c] と adj[v][c] の小さい方を反復のソースとして扱います。 新しく追加されたエッジを介して新しい 2 ステップのパスが形成されているため、より小さいセット内のすべてのノード x について、x を他のエンドポイントの新しい隣接ノードと結合します。 

その理由は、色 c を介した u の以前の近傍が v を通る有効な 2 段階パスを形成し、その逆も同様であるということです。 
5. 相互接続を処理した後、2 つの隣接セットをマージします。これにより、u と v の両方が、色 c について完全に結合された隣接情報を共有するようになります。 
6. 各クエリ (x、y) について、x と y が同じ DSU コンポーネント内にある場合は「Yes」を出力し、それ以外の場合は「No」を出力します。 

### なぜ効果があるのか

 DSU は、有効な 2 つのエッジの同じ色の遷移シーケンスの下での到達可能性を表します。 新しいエッジを挿入するたびに、このエッジが有効にする新しい有効な 2 ステップ パスをすべて明示的に追加します。 有効なダブル レインボー パスはまさにそのような 2 段階の遷移のチェーンであるため、2 つのノードを接続するペアのカラー セグメントの有効なシーケンスが存在する場合にのみ、2 つのノードは同じ DSU コンポーネントになります。 小規模から大規模へのマージでは、すべての隣接エントリが対数的にのみ移動されることが保証され、効率が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))
        self.r = [0] * (n + 1)

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

n, m, c, q = map(int, input().split())

adj = [{} for _ in range(n + 1)]
# adj[u][col] = set of neighbors

dsu = DSU(n)

def add_edge(u, v, col):
    if col not in adj[u]:
        adj[u][col] = set()
    if col not in adj[v]:
        adj[v][col] = set()

    su = adj[u][col]
    sv = adj[v][col]

    if len(su) < len(sv):
        su, sv = sv, su
        u, v = v, u

    # connect v with all in sv (smaller side originally)
    for x in sv:
        dsu.union(x, u)

    # connect u with all in su? handled via merging logic below

    for x in sv:
        su.add(x)
        adj[x][col].add(u)

    for x in su:
        sv.add(x)
        adj[x][col].add(v)

    adj[u][col] = su
    adj[v][col] = sv

for _ in range(m):
    x, y, z = map(int, input().split())
    add_edge(x, y, z)

out = []

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '?':
        x, y = map(int, tmp[1:])
        out.append("Yes" if dsu.find(x) == dsu.find(y) else "No")
    else:
        x, y, z = map(int, tmp[1:])
        add_edge(x, y, z)

print("\n".join(out))
```DSU は、派生グラフ内の到達可能性クエリに答えるためにのみ使用されるため、すべての結合は、有効な 2 ステップの同色ブリッジの検出に対応します。 隣接構造により、グラフ全体をスキャンすることなく、新しいエッジごとに作成されたブリッジを正確に列挙できるようになります。 

各カラー クラス内での大小のマージが、中心となる実装の詳細です。 これがないと、単一色の高次ノードでフル スキャンの繰り返しが強制され、二次的な動作が発生する可能性があります。 常に小さいセットを反復処理することにより、コンテナーが大幅に増大した場合にのみ、格納された各近隣ノードが処理されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各隣接エントリは、小規模から大規模へのマージにより対数回セット間で移動され、各 DSU 動作はほぼ一定です。 
| スペース | O(n + m) | 各エッジは隣接ストレージと DSU 親アレイに貢献します。 

この制約では最大 200,000 の演算が許可されるため、対数因数の解決策で十分です。 DSU の操作は事実上一定であり、主なコストは制御されたセットのマージです。

 ## 特殊なケース

 重要なエッジ ケースは、単一色のすべてのエッジが 1 つの高度なハブに接続される場合です。 その状況では、ハブに関係するすべての新しいエッジを非常に大きな隣接セットと結合する必要があります。 小規模から大規模への戦略では、大きなセットは固定されたままであり、小さなセットはそれに吸収されるため、総コストが制限されたままであることが保証されます。 

もう 1 つの微妙なケースは、新しいエッジが既存の隣接構造の両方向に接続を同時に作成する場合です。 実装では両方のエンドポイントのカラー セットを慎重に更新する必要があります。そうしないと、今後のマージで有効な 2 ステップのパスが失われます。
