 ## 解決策
 ## 問題の理解

 開始値が与えられています`a`、終了値`b`、パラメータ`m`。 で始まる正の整数のシーケンスを構築できるかどうかを判断する必要があります。`a`、で終わります`b`、非常に特殊な累積的な方法で成長します。 

最初のステップ以降の各ステップで、前のすべての要素の合計を取得し、要素間に「小さな」追加値を追加することによって、新しい要素が形成されます。`1`そして`m`。 これは、シーケンスが常に厳密に増加しており、各ステップでの増加がプレフィックスの合計がどれだけ大きくなったかに大きく依存することを意味します。 

したがって、核心的な問題は、単に到達できるかどうかということではありません。`b`ただし、制御された累積ジャンプのシーケンスを使用してそれに到達できるかどうか、各ジャンプは相対的に制限されています。`m`。 

制約は、私たちを建設的または貪欲な推論へと駆り立てます。 最大 1000 個のクエリと最大 10^14 の値があります。 これにより、プレフィックスの合計は指数関数的に増加し、シーケンスの長さは暗黙的にのみ制限されるため、シーケンスに対する状態空間検索や値に対する動的プログラミングは即座に除外されます。 

重要な構造上のエッジケースが現れるのは、`m = 1`。 その場合、すべてのステップが正確に実行されるように強制されます。`prefix_sum + 1`、したがって、シーケンスは完全に決定的になります。 決定論的な成長との間に不一致がある場合`b`答えは不可能であり、ここでの推論の小さな逸脱でさえ正しさを損なうことになります。 

もう一つの微妙なケースは次のような場合です。`a`すでに等しい`b`。 単純な 1 要素シーケンスは有効ですが、少なくとも 1 つの遷移を強制しようとする試みは、依然として「プレフィックス合計への正の整数の加算」ルールを尊重する必要があります。 

最後に、各ステップはプレフィックスの合計全体に依存するため、単純な順方向の構築は非常に早くオーバーシュートする傾向があり、制御された逆方向のプロセスなしではターゲットを「狙う」ことが困難になります。 

## アプローチ

 直接的な総当たり的なアイデアでは、次から順にシーケンスを構築しようとします。`a`。 各ステップで、現在のプレフィックス合計を維持し、可能なすべての値を試します。`r_i`で`[1, m]`、次の項を生成し、再帰的に継続します。 これは定義に正確に従っているので正しいですが、分岐要素は次のとおりです。`m`値が急速に増加するため、深さも大幅に増加する可能性があります。 問題保証ではシーケンスの長さが 50 に制限されていますが、`m`は最大 10^14 になる可能性があるため、このアプローチは不可能です。 

重要な洞察は、反復がプレフィックス合計において線形であるということです。 定義すると`S_i = x_1 + ... + x_i`の場合、遷移は次のようになります。`x_i = S_{i-1} + r_i`、 それで`S_i = 2S_{i-1} + r_i`。 

これにより、問題が構築に変換されます`S_k = b + S_{k-1}`加法性境界ノイズによって制御される指数関数的な増加を伴います。 シーケンスはステップごとに約 2 倍になるため、前方への作業は不安定ですが、後方への作業は自然になります。 

このプロセスを逆に行うことができます。`b`、有効な以前のプレフィックスの合計を減算しようとします。 以来`S_i = 2S_{i-1} + r_i`、次のようになります。`S_{i-1} = (S_i - r_i) / 2`。 

これが有効であるためには、`(S_i - r_i)`均等である必要があり、`r_i`に横たわらなければなりません`[1, m]`。 これにより、可能な先行者に対する限定検索が作成されます。 シーケンスの長さが短い (≤ 50) ため、到達するまで貪欲にまたは BFS スタイルで逆方向に再構築できます。`a`。 

この構築が機能するのは、各ステップで 1 つの後方遷移の実現可能性を確認するだけで済み、指数関数的縮小によって状態空間がすぐに崩壊することが保証されるためです。

 ## アルゴリズムのチュートリアル

 1. 次のような些細なケースを処理します。`a == b`単一要素シーケンスを出力することによって。 遷移は必要ないため、制約は空のまま満たされます。 
2. 目標値からスタート`b`そしてそれを最終的なプレフィックスの合計として解釈します`S_k`。 
3. 各ステップで、有効な以前のプレフィックスの合計を見つけようとします。`S_{i-1}`そのような`S_i - S_{i-1}`次のように表現できます`S_{i-1} + r_i`、つまり`S_i = 2S_{i-1} + r_i`。 
4. この関係を再整理して、次の候補を表現します。`S_{i-1}`として`(S_i - r_i) / 2`。 の値を試してください`r_i`から`1`に`m`これは、この整数を正の値にします。 私たちがテストする理由`r_i`それは、各ステップで許可される自由をエンコードしているということです。 
5. プレフィックスの合計が次の値に達したら停止します。`a`。 これにより、再構築されたシーケンスが正しく開始されることが保証されます。 
6. プレフィックスの合計が逆方向に再構築されたら、次を使用して元のシーケンス値を復元します。`x_i = S_i - S_{i-1}`。 

### なぜ効果があるのか

 不変条件は、再構成されたすべてのプレフィックス合計が逆形式の m-cute シーケンスの定義的反復を満たすということです。 各逆方向ステップでは、正確に 1 つの有効な分解が適用されます。`S_i`の中へ`2S_{i-1} + r_i`と`r_i`許容範囲内です。 プレフィックスの合計は厳密に逆に減少し、正のままであるため、プロセスは最大 50 ステップで終了する必要があり、有効な構造は可逆変換を通じて保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        a, b, m = map(int, input().split())

        if a == b:
            print(1, a)
            continue

        # We store prefix sums backward
        seq = [b]

        # Try to reconstruct backwards
        ok = False

        # BFS-style limited search (since depth <= 50 guaranteed)
        from collections import deque
        dq = deque()
        dq.append((b, [b]))

        seen = set([b])

        while dq:
            s, path = dq.popleft()

            if len(path) > 50:
                continue

            if s == a:
                seq = path
                ok = True
                break

            # try previous prefix sums
            for r in range(1, m + 1):
                if s - r <= 0:
                    break
                if (s - r) % 2 != 0:
                    continue
                prev = (s - r) // 2
                if prev <= 0:
                    continue

                if prev in seen:
                    continue
                seen.add(prev)
                dq.append((prev, path + [prev]))

        if not ok:
            print(-1)
            continue

        # convert prefix sums to actual sequence
        path = seq[::-1]
        ans = [a]
        for i in range(1, len(path)):
            ans.append(path[i] - path[i - 1])

        print(len(ans), *ans)

if __name__ == "__main__":
    solve()
```このソリューションは、候補プレフィックスの合計を逆方向に構築します。`b`逆再帰を使用します。 キューには部分的な再構築状態が保存され、可能なものから導出された有効な先行候補のみが展開されます。`r_i`価値観。 

微妙な部分はパリティを強制することです。次の値のみです。`r_i`それは作る`(S_i - r_i)`整数の前任者を生成することもできます。 もう 1 つの重要な制約は、プレフィックスの合計が以下に下がったときに早期に停止することです。`a`、これ以上の拡張は回復できないため。 

最後に、有効なプレフィックス チェーンが見つかったら、隣接するプレフィックスの合計を差分することによって、それを実際のシーケンス値に変換し直します。

 ## 特殊なケース

 いつ`a == b`の場合、アルゴリズムは単一要素シーケンスをただちに出力します。 入力用`a = 7, b = 7, m = 100`、プレフィックスの合計がすでにターゲットと一致しており、正確さの条件が自明に満たされているため、後方検索は必要ありません。 

いつ`m = 1`、トランジションが硬くなります。 たとえば、から始めて、`a = 3, b = 9`、後方再構成の試行`9 → 4 → 1.5`、非整数の除算が原因で失敗します。 有効な先行データがパリティ レベルに存在しないため、アルゴリズムはこのケースを正しく拒否し、誤った構築を防ぎます。
