 # 問題の理解

 この問題は単純な状況を説明しています。`n`均等に配置する必要があるキノコ`k`瓶。 もし`n`で割り切れない`k`、さらにいくつかのキノコを収集する必要があります。 目標は、キノコの総数をすべての瓶に均等に分割できるように、必要な追加のキノコの最小数を見つけることです。 

入力には 2 つの整数が含まれています。 1 つ目は現在のキノコの数、2 つ目は瓶の数です。 出力は、必要な追加のキノコの最小数です。 

制約により、両方の値を次の値まで大きくすることができます。`10^9`。 これにより、キノコを 1 つずつ追加するシミュレーションを試みることが直ちに除外されます。最悪の場合、答え自体が`10^9`。 たとえ数億回の反復を伴うループであっても、遅すぎるでしょう。 ソリューションでは定数時間演算を使用する必要があります。 

主なエッジケースは、すでに割り切れる数値を処理することと、剰余を正しく解釈することから生じます。 

考慮する`n = 8`そして`k = 4`。 正しい出力は次のとおりです`0`8 つのキノコが既に 4 つの瓶に均等に充填されているためです。 常に追加をもたらす不用意な解決策`k - n % k`ここではまだ機能しますが、特殊なケースが欠落していて誤って実装された場合は、返される可能性があります。`4`。 

もう一つのケースは、キノコの数が瓶の数より少ない場合です。 例えば：```
n = 3
k = 5
```正しい出力は次のとおりです`2`, さらに 2 つのキノコを収集すると、各瓶に 1 つずつ、計 5 つのキノコができるからです。 かどうかだけをチェックするソリューション`n / k`すでに陽性である場合、配布は不可能であると誤って結論付けられる可能性があります。 

最後の境界ケースは、剰余が に近い場合です。`k`。 例えば：```
n = 17
k = 10
```正しい出力は次のとおりです`3`、 なぜなら`17 + 3 = 20`、これは 17 の後の最初の 10 の倍数です。 余りを取り除くだけではなく、次の倍数に到達する必要があることを忘れると、間違った答えにつながります。 

# アプローチ

 簡単なアプローチは、合計が で割り切れるまで 1 つのキノコを繰り返し追加することです。`k`。 すべての有効な答えは、移動する加算の数でなければならないため、これが機能します。`n`の倍数に`k`。 試してみると`0`、 それから`1`、 それから`2`など、最初に成功した値は最小であることが保証されます。 

問題は、答えが非常に大きくなる可能性があることです。 仮定する`n = 1`そして`k = 10^9`。 シミュレーションでは、有効な合計に達するまでにほぼ 10 億回の反復が必要になります。 これは、一般的なコンテストの制限時間内でプログラムが実行できる範囲をはるかに超えています。 

重要な観察は、割り算は次の方法で除算した後の余りにのみ依存するということです。`k`。 もし`n % k = r`、 それから`n`すでに`r`以前の倍数から離れたキノコ`k`。 次の倍数に到達するには、以下を追加する必要があります`k - r`キノコ。 唯一の例外は次の場合です。`r = 0`、番号はすでに有効なので、何も追加する必要はありません。 

全体の問題は、剰余を計算し、それを次の倍数までの距離に変換することに帰着します。

 # アルゴリズムのチュートリアル

 1. 現在のキノコの数を読み取ります`n`そして瓶の数`k`。 
2. コンピューティング`n % k`、完全なグループをできるだけ多く作成した後に残るキノコの数がわかります。`k`できるだけ。 
3. 余りがゼロの場合、出力`0`キノコはすでに均等に分配できるからです。 
4. それ以外の場合は出力`k - (n % k)`なぜなら、それはまさに現在の剰余から次の倍数に移動するのに必要なキノコの数だからです。`k`。 

なぜ機能するのか: 割り切れるすべての数値`k`の倍数です`k`。 から始まる`n`、最も近い大きい倍数`k`剰余を増加することで得られます`k`。 剰余がすでにゼロである場合、最も近い有効な倍数は数値そのものです。 可能な限り最も近い倍数に移動するため、追加されるキノコの数は最小限になります。

# テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    n = int(input())
    k = int(input())

    rem = n % k
    ans = 0 if rem == 0 else k - rem

    sys.stdin = old_stdin
    return str(ans) + "\n"

# provided samples
assert solve("3\n4\n") == "1\n", "sample 1"
assert solve("7\n5\n") == "3\n", "sample 2"

# custom cases
assert solve("8\n4\n") == "0\n", "already divisible"
assert solve("1\n1000000000\n") == "999999999\n", "large gap"
assert solve("1000000000\n1000000000\n") == "0\n", "maximum equal values"
assert solve("17\n10\n") == "3\n", "next multiple boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
