 ## 解決策
 ## 問題の理解

 3 つのゲーム ラウンドのスコアを区切り記号なしで順番に書き込むことによって形成された数字の列が与えられます。 

もともと、負ではない整数はちょうど 3 つありました。 各整数は、数値を除き、先頭のゼロなしで書き込まれます。`0`それ自体は許可されています。 どのラウンドのスコアも最大で`1,000,000`。 

3 つの数字の間の区切り文字が失われました。 私たちの仕事は、有効なラウンド スコアの 3 倍を生成し、その合計を最大化する方法でそれらを復元することです。 有効な分割が存在しない場合は、次のように出力する必要があります。`-1`。 

文字列の長さは最大 30 です。これが重要な点です。 数値自体は部分文字列として解釈すると大きくても、文字列は非常に短いです。 長さが 30 ということは、2 つのセパレータを挿入できる場所が少数しかないことを意味します。 

スコアを超えることはできません`1,000,000`、最大 7 桁です。 この制限は、文字列の長さの制限よりもはるかに強力です。 有効な部分には最大 7 桁を含める必要があります。そうでない場合、その値は自動的に大きすぎます。 

いくつかの特殊なケースでは、不注意な実装が簡単に壊れてしまう可能性があります。 

考慮する：```
1000
```有効な分割は次のとおりです。`1 | 0 | 0`, しかし、余分な桁が残ります。 すべての数字を使用する唯一の方法は、`10 | 0 | 0`、その合計は`10`。 どのようなソリューションでも、すべての文字が 3 つの数字のいずれかに正確に属することを保証する必要があります。 

考慮する：```
009
```考えられる 3 つの部分の分割は次のとおりです。```
0 | 0 | 9
0 | 09 | ...
00 | ...
```部分文字列`"09"`先頭にゼロがあり、`"00"`先行ゼロも付いています。 有効な分割が存在しないため、答えは次のようになります。`-1`。 

考慮する：```
10000011000001
```次のような分割:```
1000001 | 1000001 | 0
```は、許容制限内の値を正確に使用します。 境界は包括的であるため、`1,000,000`許可されていますが、`1,000,001`そうではありません。 

考慮する：```
123456789012345678901234567890
```文字列は 7 桁の 3 倍よりもはるかに長いです。 有効なスコアはすべて最大 7 桁であるため、3 つのスコアを合わせて最大 21 桁を占めることができます。 長さ 30 の文字列を 3 つの有効なスコアに分割することはできないため、答えはすぐに得られます。`-1`。 

## アプローチ

 最も直接的なアイデアは、2 つのセパレーターを配置するためにあらゆる方法を試してみることです。 

最初のセパレータが位置の後にある場合`i`2 番目のセパレータは位置の後ろにあります`j`の場合、3 つの数字は次のようになります。```
s[0:i]
s[i:j]
s[j:n]
```分割ごとに 3 つの条件を検証します。 すべての部分は空であってはなりません。 長さがちょうど 1 でない限り、どの部分にも先頭にゼロを含めることはできません。 その数値は以下を超えてはなりません`1,000,000`。 

分割が有効な場合は常に合計を計算し、最大値を保持します。 

本当に単純な総当り攻撃では、可能なすべての部分文字列のトリプルが生成され、それらがチェックされます。 文字列の長さが最大 ​​30 の場合、```
30 * 30 = 900
```セパレータの位置の選択肢。 数値を解析した後でも、これはわずかです。 

重要な観察は、制約が非常に小さいため、この強引な方法がすでに最適化されているということです。 動的プログラミング、貪欲なメソッド、または高度なプルーニングは必要ありません。 問題全体は、分割候補を正しく検証することにあります。 

有効な数値が最大 7 桁であることに注意することで、実装を少しすっきりさせることができますが、その事実を使用しなくても、すべての区切り文字のペアをチェックするのは十分に高速です。

 ## アルゴリズムのチュートリアル

 1. 数字列を読み取る`s`そしてその長さを`n`。 
2.初期化`best = -1`。 
3. 最初の数値の終了位置を列挙します。 なるがままに`i`、 どこ`1 ≤ i < n`。 
4. 2 番目の数値の終了位置を列挙します。 なるがままに`j`、 どこ`i + 1 ≤ j < n`。 
5. 3 つの部分文字列を抽出します。```
a = s[:i]
b = s[i:j]
c = s[j:]
```6. 各部分文字列が正当なスコアを表しているかどうかを確認します。 

次の場合、部分文字列は有効です。 

- 長さは少なくとも 1 です。 
- 長さが 1 より大きい場合、次で始まらない`'0'`。 
- その数値は最大です。`1,000,000`。 
7. 3 つの部分文字列のいずれかが不正な場合は、この分割を破棄して続行します。 
8. それ以外の場合は、3 つの部分文字列すべてを整数に変換し、それらの合計を計算して更新します。```
best = max(best, a + b + c)
```9. すべてのセパレータ ペアのテストが完了したら、印刷します。`best`。 

### なぜ効果があるのか

 元のゲーム スコアの有効な再構成はすべて、正確に 1 組の区切り位置に対応します。 このアルゴリズムは考えられるすべてのペアを列挙するため、有効な再構成が見逃されることはありません。 

候補分割ごとに、検証ではステートメントで指定されたルール (空でない 3 つの数値、先頭のゼロなし、および最大値) が正確にチェックされます。`1,000,000`。 これらのチェックに合格した分割は合法的な再構築であり、チェックに失敗した分割は違法です。 

アルゴリズムはすべての法的再構築の合計を評価し、最大値を維持するため、最終値は`best`正確には、達成可能な最大の合計スコアです。 法的な再建が存在しない場合、`best`残る`-1`、これは必要な出力です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 1000000

s = input().strip()
n = len(s)

best = -1

for i in range(1, n):
    for j in range(i + 1, n):
        parts = (s[:i], s[i:j], s[j:])
        values = []
        ok = True

        for p in parts:
            if len(p) > 1 and p[0] == '0':
                ok = False
                break

            v = int(p)
            if v > LIMIT:
                ok = False
                break

            values.append(v)

        if ok:
            best = max(best, sum(values))

print(best)
```外側の 2 つのループは、2 つのセパレータの可能なすべての位置を列挙します。 セパレータは空ではない部分を正確に 3 つ生成する必要があるため、`i`から始まります`1`そして`j`から始まります`i + 1`。 

検証ロジックはステートメントに直接続きます。 のような部分文字列`"0"`合法ですが、`"00"`そして`"09"`そうではありません。 小切手```
len(p) > 1 and p[0] == '0'
```はこのルールを正確に捉えています。 

その後、部分文字列が整数に変換され、比較されます。`1,000,000`。 Python の整数には任意の精度があるため、オーバーフローの心配はありません。 

分割が有効な場合は常に、その合計が現在の最良の回答と比較されます。 有効な分割が見つからない場合は、`best`残る`-1`、不可能な入力を自然に処理します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    s = inp.strip()
    n = len(s)
    best = -1

    for i in range(1, n):
        for j in range(i + 1, n):
            parts = (s[:i], s[i:j], s[j:])
            vals = []
            ok = True

            for p in parts:
                if len(p) > 1 and p[0] == '0':
                    ok = False
                    break

                v = int(p)
                if v > 1000000:
                    ok = False
                    break

                vals.append(v)

            if ok:
                best = max(best, sum(vals))

    return str(best)

# provided sample
assert run("1234") == "37", "sample 1"

# custom cases
assert run("900") == "90", "zeros allowed as standalone numbers"
assert run("009") == "-1", "leading zeros invalidate all splits"
assert run("111") == "3", "minimum valid length"
assert run("1000000100000010") == "2000001", "boundary value 1000000"
assert run("123456789012345678901234567890") == "-1", "too long for three valid scores"

 ## 特殊なケース

 次の入力を考えてみましょう。```
009
```候補者が分かれる`0 | 0 | 9`は、区切り文字がそれらの部分文字列を正確に生成する場合にのみ有効です。 他の可能性としては、次のような部分文字列が考えられます。`"00"`または`"09"`現れる。 検証ステップでは、長さが 1 を超え、次で始まる部分文字列はすべて拒否されます。`'0'`。 考えられる分割はすべて失敗するため、`best`残る`-1`。 

考慮する：```
100000110000010
```候補の分割の 1 つは次のとおりです。```
1000001 | 1000000 | 10
```最初の値は制限を超えているため、拒否されます。 別の分割により、次のような結果が生じる可能性があります。```
1000000 | 1000000 | 10
```この制限は包括的であるため受け入れられます。 このアルゴリズムは、解析された整数を直接比較します。`1,000,000`なので、境界は正しく処理されます。 

考慮する：```
123456789012345678901234567890
```空ではない 3 つの部分に分割する場合は、少なくとも 1 つの部分に 7 桁を超える部分を残す必要があります。 7 桁を超える数字は次の値を超えます`1,000,000`したがって、すべての分割は値のチェックに失敗します。 アルゴリズムは体系的にすべての可能性を検証し、正しく返します。`-1`。 

考慮する：```
111
```これは、空ではない 3 つの数値を形成できる最短の文字列です。 唯一の分割は次のとおりです。```
1 | 1 | 1
```ループは引き続き正しく検査します。`i = 1`そして`j = 2`は有効な区切り位置です。 結果の合計は次のとおりです`3`、それが答えになります。
