 ## 解決策
 ## 問題の理解

 頂点 1 がルートであり、他の各頂点にはちょうど 1 つの親があるルート付きツリーが与えられているため、構造は固定されており、非巡回です。 一部の非ルート頂点には 1 つのフルーツが含まれます。 各果物には特定の頂点、熟す日、そして熟したときに正確に収穫できた場合に得られる報酬を表す値があります。 

果物を集める唯一の方法は、時間をかけて木の端を繰り返し切ることです。 刃先で木の一部が切り離され、根を含まないすべての切り離された構成要素がすぐに取り除かれ、その日に熟した果実はすべて集められます。 成分が除去された時点で熟していない果物は永久に失われます。 

重要な緊張点は、早めに切ると果物を孤立させることができるが、まだ熟していない場合は報われずに消えてしまうということです。 刈り取るのが遅いと、貴重な果実が根に長時間付着したままになり、最適に収穫できない可能性があります。 

入力サイズは 100,000 ノードとフルーツに達するため、日々の操作をシミュレートしたり、すべてのカット サブセットを試したりするアプローチは排除されます。 ノードやフルーツの二次関数は直ちに実行不可能になります。 日数が 100,000 に達する可能性があるため、数日間繰り返してツリーの状態を再計算するアプローチでも、時間がかかりすぎます。 

複数の果物が同じ根から葉の経路上にあり、成熟時間が増減する場合、微妙なエッジケースが現れます。 たとえば、親の果実は遅く熟すが、子の果実は早く熟す場合、切断の決定が妨げられます。子の端を早く切断すると、子自体は最適であっても、親の潜在的な将来の収穫が廃棄される可能性があります。 

もう 1 つの特殊なケースは、果物が木の奥深くにあるにもかかわらず熟すのが非常に遅い場合です。 果物が熟したらすぐに切ってしまう単純な貪欲な人は、同じサブツリーのさらに上にあるより価値の高い果物を失う可能性があります。 

## アプローチ

 この難しさは、エッジを切断するとサブツリー全体が削除され、その中のすべての果物が同時に影響を受けるという事実から来ています。 これは、決定が単一の果物に局所的なものではなく、サブツリー内のすべての果物の構造に依存することを示唆しています。 

強引なアプローチでは、すべての果物について、熟した日にその入射端をカットするかどうかを決定しようとします。 しかし、カットは相互作用します。1 つの果物の端をカットすると、他の多くの節が削除されます。 より明示的なブルート フォースでは、エッジのすべてのサブセットを一日中シミュレートし、結果として得られる収穫されたフルーツを計算します。 それぞれのフルーツを個別に考慮したとしても、カットのタイミングを選択する方法の数はエッジの数に応じて指数関数的に増加するため、このアプローチはおおよそ次のように増加します。$2^n$、それは限界をはるかに超えています。 

重要な観察は、視点を逆転させることです。 私たちは、いつ端を切るかを考えるのではなく、どの果物が以前の決定によって「強制」されずに熟す日まで生き残ることができるかを考えます。 ノード v の果物は、根からの経路全体が d 日目まで無傷のままである場合にのみ収集できます。 つまり、他の果物を最適に収集するのに役立つ場合を除き、v のすべての先祖をその日の前または当日に分離してはなりません。 

これにより、問題はツリー DP に変わり、各ノードは、果物の期限によって課される制約を考慮して、そのサブツリーからどれだけの値を取得できるかを決定します。 ツリーをボトムアップで処理し、サブツリーからの実現可能な「タイミング制約」を表す構造をノードごとに維持します。 このための自然なツールは、期限を守りながらどのフルーツを「生かし続ける」ことができるかを追跡する優先キューベースの貪欲なマージです。 

それぞれの果実には期限があり、熟す日まで根とつながったままにしなければなりません。 子を親にマージする場合、候補となるフルーツを蓄積し、制約に違反するたびに最も有用でないフルーツを破棄します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (カットをシミュレート) | O(2^n) | O(n) | 遅すぎる |
 | 貪欲なマージを使用したツリー DP (DSU / ヒープ) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、それぞれの果物をノードに位置する仕事として解釈し、期限は熟した日、利益は果汁の価値に等しくなります。 果物は、期限まで「ノードを根に接続した状態に保つ」ことができた場合にのみ収集できます。つまり、早めに切り取って取り除くことがないようにする必要があります。 

ボトムアップ DFS 方式でツリーを処理します。 

1. 各ノードについて、そのサブツリー内の候補フルーツのマルチセット (または実装に応じて最大ヒープ/最小ヒープ) を維持します。 各エントリには (期限、値) が格納されます。 これは、このサブツリーが接続されたままであれば存続できるように現在計画している成果を表しています。 
2. DFS をリーフから開始します。 葉ノードでは、そのフルーツ (存在する場合) を構造に挿入します。 その下にはそれ以上の構造はないので、これが基本状態です。 
3. 子から親に戻るとき、子の構造を親の構造にマージします。 これは、子サブツリーからのすべての成果機会を親の決定空間に結合することに対応します。 
4. 子を結合した後、実現可能性を確認します。 制約は、現在のサブツリー境界に対してすでに有効期限が切れているフルーツがある場合、あまりにも多くの「アクティブな」フルーツを保持できないことです。 最適性を強制するために、格納されているフルーツの数がツリー構造の下で満たせる量を超えるたびに、最小値のフルーツが削除されます。 直観的には、何かをドロップしなければならない場合、残りの実現可能性制約は価値を除いてすべて同一であるため、常に最も価値の低い果物を廃棄することになります。 
5. すべての子がノードにマージされたら、ノード自体での実行可能性を再度強制し、保持されるフルーツのセットがそのサブツリーにとって最適であることを確認します。 
6. 答えは、根の構造に残っているすべての果実の値の合計です。 

重要な不変条件は、ノード u をルートとするすべてのサブツリーについて、維持されるセットが、祖先の接続性制約に違反することなく収集できる、そのサブツリー内のフルーツの最大合計値サブセットを表すことです。 すべてのマージ ステップで、必要に応じて最も価値の低いフルーツのみを削除することで実現可能性を維持します。これにより、サブツリー内の k 個のフルーツを使用する有効なソリューションは、維持されているセットよりも高い合計値を持つことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())
parent = [0] * (n + 1)
tree = [[] for _ in range(n + 1)]

for i in range(2, n + 1):
    p = int(input())
    parent[i] = p
    tree[p].append(i)

fruits = [[] for _ in range(n + 1)]
for _ in range(m):
    v, d, w = map(int, input().split())
    fruits[v].append((d, w))

def dfs(u):
    heap = []  # min-heap of values kept in this subtree
    size = 0   # number of fruits considered

    for d, w in fruits[u]:
        heapq.heappush(heap, w)
        size += 1

    for v in tree[u]:
        child_heap, child_size = dfs(v)

        if len(heap) < len(child_heap):
            heap, child_heap = child_heap, heap
            size, child_size = child_size, size

        for val in child_heap:
            heapq.heappush(heap, val)
            size += 1

        while size > k:
            heapq.heappop(heap)
            size -= 1

    return heap, size

heap, size = dfs(1)
print(sum(heap))
```この実装では、ルートから DFS を実行し、サブツリーごとに選択されたフルーツ値のヒープを返します。 各ノードは、独自のフルーツ値が存在する場合は挿入することから始まります。 子をマージするときは、DSU-on-tree マージと同様に、複雑さを制御するために、常に小さいヒープを大きいヒープにマージします。 各マージの後、最小値を削除することで、サブツリーに合計 k 個を超えるフルーツが保持されないようにします。 

主要な実装上の選択は、制約により削減が強制された場合に、最小ヒープを使用して最も価値の低いフルーツを常に破棄することです。 これは、最適な部分問題の分解に必要な貪欲な構造と一致します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    tree = [[] for _ in range(n + 1)]
    for i in range(2, n + 1):
        p = int(input())
        tree[p].append(i)

    fruits = [[] for _ in range(n + 1)]
    for _ in range(m):
        v, d, w = map(int, input().split())
        fruits[v].append((d, w))

    import heapq
    sys.setrecursionlimit(10**7)

    def dfs(u):
        heap = []
        size = 0
        for d, w in fruits[u]:
            heapq.heappush(heap, w)
            size += 1
        for v in tree[u]:
            child_heap, child_size = dfs(v)
            if len(heap) < len(child_heap):
                heap, child_heap = child_heap, heap
                size, child_size = child_size, size
            for val in child_heap:
                heapq.heappush(heap, val)
                size += 1
            while size > k:
                heapq.heappop(heap)
                size -= 1
        return heap, size

    heap, size = dfs(1)
    return str(sum(heap))

 ## 特殊なケース

 k がフルーツの数に比べて非常に小さい場合、重要なエッジ ケースが発生します。 すべてのノードに果物がある鎖状のツリーでは、最も価値のある上位 k 個の果物だけが生き残るべきです。 ヒープベースの枝刈りは、最小値を繰り返し破棄することでこれを保証し、より深いが値の低いフルーツが最初に削除されます。 

もう 1 つの特殊なケースは、すべてのフルーツが別々のサブツリーに存在する場合です。 この場合、ヒープ間に競合は存在せず、アルゴリズムは単にすべての値を累積します。 マージ プロセスではプルーニングがトリガーされることはありません。これにより、独立性が正しく維持されることが確認されます。 

最後の微妙なケースは、サブツリー内に複数のフルーツが存在するが、祖先の制約により一部のみが到達可能な場合です。 容量制約に違反するフルーツはローカルで削除され、上位レベルの決定に影響を与えることがないため、ボトムアップ マージでは当然これが尊重されます。
