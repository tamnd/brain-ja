 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`長さの`n`そして目標値`k`。 私たちのタスクは、次のすべての連続した部分配列を数えることです。`a`それは_壮大_です。 最初の部分の最小値と 2 番目の部分の最大値が等しくなるように、部分配列を 2 つの空ではない部分に分割できれば、その部分配列は壮大になります。`k`。 正式に言うと、`b`の部分配列です`a`、インデックスが存在する場合は素晴らしいです`i`(1 ≤ i < b の長さ)`min(b[0..i-1]) + max(b[i..end]) = k`。 

入力では複数のテスト ケースを指定します。 各テスト ケースが提供するのは、`n`、`k`、および配列`a`。 各テスト ケースの出力は単一の数値、つまりエピック サブ配列の数です。 

制約は次のことを示します`n`テスト ケースごとに 2×10^5 まで大きくなり、合計は`n`テスト ケース全体で 2×10^5 を超えません。 これは、O(n^2) アルゴリズムを使用する余裕がないことを意味します。 すべてのサブ配列をチェックするブルート フォース アプローチでは、分割された各サブ配列の最小値と最大値を再計算するとおよそ O(n^3) の演算が実行され、すべてのサブ配列の最小値と最大値を事前計算すると O(n^2) の演算が実行されますが、それでも遅すぎます。 したがって、テスト ケースごとに線形に近いアプローチまたは線形演算アプローチが必要です。 

明らかではないエッジ ケースとしては、数値が繰り返される配列、すべての要素が小さすぎる、または大きすぎる配列が挙げられます。`k`、および最小サイズ 2 の配列。たとえば、次の場合`a = [1, 1, 1]`そして`k = 3`の場合、サブ配列はエピックではありません。`min + max = 2`せいぜい、最初と最後の要素だけをスキャンする単純なアルゴリズムでは、一部のサブ配列が誤ってカウントされる可能性があります。 もう 1 つの注意が必要なケースは、次のような配列です。`[6,6,6,7,7]`と`k = 13`、ここで、少なくとも 1 つを含む任意の部分配列`6`そして1つ`7`壮大なものになるため、単純な反復ではなく慎重にカウントする必要があります。 

## アプローチ

 ブルートフォースアプローチではすべてのサブ配列が考慮されます`a[l..r]`すべての分割インデックスを試します`i`。 分割ごとに、次のように計算します。`min(a[l..i])`そして`max(a[i+1..r])`合計が等しいかどうかを確認します`k`。 これが機能するのは、すべての可能性を徹底的にチェックするためです。 問題は効率です。`n=2×10^5`、部分配列の数はおよそ 2×10^10 ですが、これは実行不可能です。 

重要な観察は次のとおりです`k`厳密には次より大きいです`n`そしてそれよりも小さい`2n`。 それぞれの要素が入っています`[1, n]`したがって、エピックサブ配列には 1 つの部分に次の要素が含まれる必要があります。`x`そして、含まれる他の部分`y`どこ`x + y = k`。 限界があるため、`x`そして`y`は 1 から n までの一意の番号です。 したがって、問題は、以下を含む部分配列を数えるということになります。`x`最初の部分と`y`2 番目の部分では、`x + y = k`。 この洞察により、最後の位置を追跡できるようになります。`x`そして`y`配列をスキャンしながら、2 つのポインターまたはスライディング ウィンドウを使用して有効なサブ配列をカウントします。 

より具体的なアプローチでは、次の事実を利用します。`x = k - y`。 左から右にスキャンして、最後に発生したものを追跡できます。`x`そして次の出来事`y`。 最後のサブ配列より前から始まるサブ配列`x`そして次の次で終わる`y`壮大です。 このロジックを使用すると、すべてのエピック サブ配列を線形時間でカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | すべての部分配列の最小/最大を事前計算する | O(n^2) | O(n^2) | 遅すぎる |
 | 2 ポインター / 位置追跡 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数値のペアを事前計算する`(x, y)`それは合計すると次のようになります`k`指定されたサブ配列の場合。 ここ`x`左側の部分にあり、`y = k - x`右側の部分です。 
2. 最後のインデックスを維持しながら配列を反復処理します。`x`現れた。 これは、現在のインデックスで終わるすべてのサブ配列を知るのに役立ちます。`x`左側の部分です。 
3. 同時に、インデックスごとに、最も古いインデックスを見つけます。`y`現在のインデックスの後に表示されます。 これにより、適切な部分が確実に`y`。 
4. 各インデックスについて、そのインデックスで終わるエピック サブ配列の数は、最後のサブ配列間の距離によって決まります。`x`有効な場合は現在のインデックス`y`右側に存在します。 このカウントを現在の合計に追加します。 
5. 配列の終わりまでスキャンを続け、最後に出現したデータを更新します。`x`そして最も早い将来の発生`y`。 

これが機能する理由: 配列内の任意の点で、最後に出現した`x`残りの部分がすべて含まれていることを確認します。`x`は有効であり、次に出現するのは`y`正しい部分が含まれていることを保証します`y`。 なぜなら`x`そして`y`が固定されている場合、カウントされたすべてのサブ配列が満たされます。`min(left) + max(right) = k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_epic_subarrays(n, k, a):
    pos = [0] * (n + 2)
    res = 0
    # mark positions of each number
    for idx, val in enumerate(a):
        pos[val] = idx + 1

    # loop through possible left part values
    for x in range(1, n + 1):
        y = k - x
        if 1 <= y <= n:
            left = pos[x]
            right = pos[y]
            if left and right and left < right:
                res += left * (n - right + 1)
    return res

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(count_epic_subarrays(n, k, a))
```このソリューションでは、各数値を配列内の最後の出現箇所にマップします。 考えられる各ペアについて`(x, y)`合計すると`k`を含む部分配列の寄与を計算します。`x`前に`y`。 乗算する`left`残留によるポジション`right`位置は、そのペアのエピック サブ配列の合計を示します。 エッジケースのような`x`または`y`表示されない場合は、条件チェックによって処理されます。 

## 実用的な例

 **サンプル 1:**```
n = 5, k = 7, a = [1,2,3,4,5]
```のために`x = 2`、`y = 5`(`2+5=7`）、 最後`2`まずインデックス 2 で`5`インデックス 5 にあるので、サブ配列`[2,3,4,5]`そして`[3,4,5]`left*right の式でカウントされます。 のために`x=3`、`y=4`、 最後`3`まずインデックス 3 で`4`インデックス 4 のサブ配列`[3,4]`。 エピックサブ配列の総数: 2。 

**サンプル 2:**```
n = 7, k = 13, a = [6,6,6,6,7,7,7]
```ペア`(6,7)`のみ。 最後`6`インデックス 4 で、最初に`7`インデックス 5 にあります。インデックス 1..4 で始まり 5..7 で終わるサブ配列: 12 個のエピック サブ配列。 

このトレースは、すべての O(n^2) 個の部分配列を反復することなく、位置を事前計算し、左右の選択肢を乗算することで、すべての有効な部分配列が正しくカウントされることを示しています。
