 ## 解決策
 ## 問題の理解

 バイナリ文字列から始めます`s`そして空の文字列`t`。 

移動により、1 つの文字列の接尾辞を取得して、それをもう 1 つの文字列に追加することができます。 移動できるのはサフィックスだけであるため、文字の相対的な順序が変わることはありません。 キャラクターは境界線を越えることができます。`s`そして`t`。 

目標は、すべてで終了することです`0`内部`s`そしてすべての`1`内部`t`。 その状態に到達するために必要な最小限のサフィックス転送が必要です。 

各文字列の長さは最大 1000 であり、すべてのテスト ケースの合計の長さも最大 1000 です。制約は小さいにもかかわらず、目的のソリューションは検索ベースのアプローチよりもはるかに単純です。 答えは、文字列を 1 回スキャンすることで計算できます。 

難しいのは、移動によって実際に何が変わるのかを理解することです。 サフィックスのみを転送できるため、文字を任意に並べ替えることはできません。 すべての動きは 2 つの文字列間の境界を移動するだけです。 等しい文字の連続したブロックの構造が重要な観察になります。 

簡単なエッジケースをいくつか考えてみましょう。 

次のように、文字列にすでにゼロのみが含まれている場合:```
s = "00000"
```それから`t`空のままでも構いません。 答えは`0`。 

常にすべてを動かす不用意な解決策`1`に入る`t`不要な操作を誤って実行する可能性があります。 

次に、次のことを考えてみましょう。```
s = "1111"
```唯一の有効な最終状態は次のとおりです。```
s = ""
t = "1111"
```1 回の移動で文字列全体が転送されます。 答えは`1`。 

別の微妙なケースは次のとおりです。```
s = "001"
```最後のブロックはすでに 1 のブロックになっています。 そのサフィックスを直接次の場所に移動できます。`t`つまり、答えは次のとおりです`1`。 

よくある間違いは、ブロックの数を数えてその値を返すことです。 ここには 2 つのブロックがあります (`00`そして`1`)、必要な移動は 1 つだけです。 

最後に、次のことを考慮してください。```
s = "101"
```答えは`3`。 

交互構造により、複数の接尾辞を前後に移動する必要があります。 1 または 0 の数だけを数えるアプローチは、この例では失敗します。 

## アプローチ

 ブルート フォース ビューでは、各状態を文字列のペアとして扱います。`(s, t)`そしてBFSを実行します。 あらゆる可能なサフィックス転送により、新しい状態が作成されます。 すべての移動のコストは等しいため、BFS は最終的に最小の移動数を見つけます。 

問題は、州の数が爆発的に増加することです。 適度な長さの文字列であっても、考えられる文字列のペアが多すぎて探索できません。 このアプローチはすぐに実用的ではなくなります。 

より良い解決策を見つけるには、移動によって何が達成されるかを理解する必要があります。 

文字列を等しい文字の連続したブロックとして見てください。 例えば：```
001110011
```ブロックが含まれています:```
00 | 111 | 00 | 11
```キャラクターが隣接する位置間で変わるたびに、新しいブロックが始まります。 

文字列を左から右にスキャンするとします。 ブロックごとに`1`が表示されますが、それらは最終的には`t`。 移動はサフィックスに基づいて動作するため、異なるキャラクター間の移行ごとに追加の障害が発生し、別の移行が必要になります。 

いくつかの例を検討すると、単純なパターンが見えてきます。 

させて`changes`ポジションの数になります`i`次のような:```
s[i] != s[i - 1]
```次に:

 文字列が次で始まる場合`0`、答えはまさにそのとおりです`changes`。 

文字列が次で始まる場合`1`、答えは`changes + 1`。 

なぜ開始文字が重要なのでしょうか?

 文字列が次で始まる場合`1`、1 の最初のブロックは最終的に外に移動する必要があります。`s`。 それには追加の操作が 1 つ必要です。 文字列が次で始まる場合`0`、最初のブロックはすでに正しい側にあるため、その最初の動きは必要ありません。 

これによりすぐに次の結果が得られます`O(n)`解決。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列を読み取ります`s`。 
2. 隣接する文字が何回異なるかを数えます。 

あらゆるインデックスに対して`i > 0`、 もし`s[i] != s[i-1]`、カウンターをインクリメントします`changes`。 

このような各位置は、新しいブロックの始まりを示します。 
3. 最初の文字が`1`、答えにもう 1 つ追加します。 

1 の先頭ブロックは外部に転送する必要があります。`s`、追加の必要な動きが 1 つ作成されます。 
4. それ以外の場合、最初の文字が`0`、答えは簡単です。`changes`。 
5. 結果を出力します。 

### なぜ効果があるのか

 文字列は、0 と 1 が交互に並んだブロックとして見ることができます。 

2 つの隣接するブロック間のすべての境界は、ある時点で移動する接尾辞の境界と交差する必要があります。 各キャラクターの変更は、必要な転送を 1 回だけ実行します。 これは文字列内のすべての遷移を考慮します。 

文字列が 1 のブロックで始まる場合、すべての 1 が内部で終了する必要があるため、そのブロックは最初は間違った場所にあります。`t`。 最初のブロックを移動するには、すでにカウントされている遷移を超える追加の操作が 1 つ必要です。 

したがって、最小移動数は、キャラクター変更の数に、最初のキャラクターが変更された場合に 1 を加えたものに等しくなります。`1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        changes = 0
        for i in range(1, n):
            if s[i] != s[i - 1]:
                changes += 1

        answer = changes + (1 if s[0] == '1' else 0)
        print(answer)

solve()
```実装はブロックに関する観察に直接従うものです。 

ループは、現在の文字が前の文字と異なるすべての位置をカウントします。 これはまさに、連続するブロック間の遷移の数です。 

その後、最初の文字を確認します。 そうであれば`1`、さらに 1 つの動きを追加します。 それ以外の場合は何も追加する必要はありません。 

唯一の境界条件は、長さ 1 の文字列です。 その場合、ループは決して実行されません。`changes`はゼロのままで、数式は引き続き正しく機能します。`"0"`生成する`0`、 その間`"1"`生成する`1`。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []

        for _ in range(t):
            n = int(input())
            s = input().strip()

            changes = 0
            for i in range(1, n):
                if s[i] != s[i - 1]:
                    changes += 1

            out.append(str(changes + (1 if s[0] == '1' else 0)))

        return "\n".join(out)

    return solve()
