 ## 問題の理解

 正の整数から始めます$n$。 2 人のプレイヤーが交互にターンを行い、アリスが最初に動きます。 各ターンで、現在のプレイヤーは現在の数字の適切な約数、つまりどちらでもない約数を選択します。$1$数値自体も減算されます。 

ゲームは更新された値で続行されます。 プレイヤーがターンを開始し、減算する有効な約数がない場合、そのプレイヤーは負けます。 

すべてのテスト ケースで、両方が完璧にプレイしたと仮定して、どちらのプレイヤーが勝つかを判断する必要があります。 

入力は最大で構成されます$10^4$独立したゲーム。 開始値$n$と同じ大きさにすることができます$10^9$。 テスト ケースが多数あるため、各値に対して広範なゲーム状態の探索を実行するソリューションは直ちに疑わしいものになります。 解決策$O(\sqrt n)$テストケースごとに完全に安全であるため、$\sqrt{10^9} \approx 31623$一方で、大規模な動的プログラミング テーブルに関係するものはすべて、$n$不可能です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

いつ$n=1$、約数はまったくありません。 アリスはすぐに負けます。 

入力：```
1
1
```出力：```
Bob
```すべての正の数に少なくとも 1 つの移動があると仮定する解決策は、ここでは失敗します。 

素数も終端位置です。 たとえば:

 入力:```
1
13
```出力：```
Bob
```素数の約数は次のとおりです。$1$とそれ自体、両方とも禁止されています。 

2 の累乗は他の偶数とは異なる動作をします。 たとえば:

 入力:```
1
8
```出力：```
Bob
```「すべての偶数が勝つ」などの単純なルールでは、間違った答えが得られます。 

番号$2$は別の特殊なケースです。 

入力:```
1
2
```出力：```
Bob
```偶数ですが、約数は次のとおりであるため、有効な動きはありません。$1$そして$2$。 

## アプローチ

 自然な最初のアイデアは、ゲームを標準的な公平なゲームとして扱うことです。 あらゆる価値観に対して$x$、すべての合法的な手を生成できます$x \to x-d$、 どこ$d$はの適切な約数です$x$。 少なくとも 1 つの手が負けポジションにつながる場合、そのポジションは勝ちであり、すべての手が勝ちポジションにつながる場合は負けです。 

このブルートフォースの定義は、最適なプレイに直接一致するため、正しいです。 残念ながら、それは実用的ではありません。 以来$n$到達できる$10^9$までの DP テーブルを構築することはできません。$n$。 制限がはるかに小さい場合でも、ゲーム状態を繰り返し列挙するとコストがかかりすぎます。 

重要な観察は、ゲームが非常に厳格な構造を持っているということです。 移動するたびに適切な約数が減算されるため、数値は常に減少します。 これにより、勝ちポジションと負けポジションを再帰的に計算するのではなく、数学的に分析することができます。 

小さな値を調べてみましょう。 

| n | 結果 |
 | --- | --- |
 | 1 | 負ける |
 | 2 | 負ける |
 | 3 | 負ける |
 | 4 | 勝つ |
 | 5 | 負ける |
 | 6 | 勝つ |
 | 7 | 負ける |
 | 8 | 負ける |
 | 9 | 負ける |
 | 10 | 勝つ |

 奇数はすべて負けているように見えます。 

これは偶然ではありません。 もし$n$奇数、のすべての約数$n$も奇数です。 奇数から奇数の約数を引くと偶数が生成されます。 したがって、奇数の位置からのすべての移動は偶数の位置に進みます。 奇数から到達可能な偶数のポジションがすべて勝っている場合、すべての奇数が負けています。 

次に偶数について考えてみましょう。 

偶数が 2 のべき乗ではない場合、奇数の因数が含まれます。 させて$d$その奇妙な要因である可能性があります。 引き算$d$偶数を維持し、奇数を生成します。 奇数は負けているので、偶数が勝ちです。 

唯一の難しいケースは 2 の累乗です。 

させて$n=2^k$。 

すべての適切な約数も 2 のべき乗です。 どの動きも次のようになります$$2^k \to 2^k - 2^m$$と$m<k$。 

因数分解すると得られる$$2^k - 2^m = 2^m(2^{k-m}-1).$$2 番目の因数は奇数であり、より大きいです$1$, したがって、結果は 2 の累乗ではない偶数になります。 

2 のべき乗ではないすべての偶数が勝つことはすでに確立されています。 したがって、からのあらゆる動きは、$2^k$勝利のポジションにつながります。 

これは、2 の累乗が指数平価に従って勝ちと負けを繰り返すことを意味します。$$2^1=2 \text{ is losing}$$

$$2^2=4 \text{ is winning}$$

$$2^3=8 \text{ is losing}$$

$$2^4=16 \text{ is winning}$$等々。 

最終的な特性評価は非常にシンプルです。 

もし$n$奇妙です、ボブが勝ちます。 

もし$n$が 2 の累乗ではない偶数であれば、アリスが勝ちます。 

もし$n=2^k$、アリスが勝つのは次の場合です。$k$が偶数で、ボブが勝つとき$k$奇数です。

 | 最適 |$O(\log n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在値を読み取る$n$。 
2. もし$n$奇数です、出力`"Bob"`。 

奇数から偶数に移動するたびに、奇数の位置は負けになります。 
3. かどうかを確認します。$n$は 2 の累乗です。 

繰り返し除算する$2$均等なまま、何回分割するかを数えます。 
4.残額がない場合$1$、 それから$n$2の累乗ではありませんでした。 

このような数値は偶数であり、奇数の要素が含まれているため、負けた奇数の位置に移動することができます。 出力`"Alice"`。 
5. それ以外の場合$n=2^k$。 
6. もし$k$偶数、出力`"Alice"`。 
7. もし$k$奇数です、出力`"Bob"`。 

### なぜ効果があるのか

 ソリューション全体は、ポジションを 3 つのカテゴリに分類することに基づいています。 

すべての正当な手は偶数につながるため、奇数はすべて負けます。 

2 の累乗ではないすべての偶数には奇数の約数が含まれているため、勝ちとなります。 その約数を引くと奇数が得られ、これは損失になります。 

2 のべき乗の場合、すべての動きは 2 のべき乗ではない偶数になります。 これらのポジションは勝ちであるため、2 の累乗自体は指数の等価に従って負けと勝ちを繰り返します。 以来$2=2^1$は負けており、奇数の指数はすべて負けており、偶数の指数はすべて勝ちです。 

考えられるすべての値はこれらのカテゴリのいずれかに正確に属するため、アルゴリズムは常に正しい勝者を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())

    if n % 2 == 1:
        print("Bob")
        continue

    x = n
    cnt = 0

    while x % 2 == 0:
        x //= 2
        cnt += 1

    if x != 1:
        print("Alice")
    else:
        print("Alice" if cnt % 2 == 0 else "Bob")
```最初のブランチは、ポジションを失っているため、すべての奇数をすぐに処理します。 

偶数の場合、コードは 2 の要素をすべて削除し、削除された数をカウントします。 残りの値が 1 より大きい場合、その数値には奇数の因数があり、純粋な 2 の累乗ではありません。 そういったポジションは常に勝利を収めています。 

残りの値がちょうど 1 の場合、元の数値は$2^{\text{cnt}}$。 勝者は指数が偶数か奇数かによってのみ決まります。 

大規模な配列や再帰は必要ありません。 ループは最大で約 30 回実行されます。$2^{30} > 10^9$。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        if n % 2:
            ans.append("Bob")
            continue

        x = n
        cnt = 0

        while x % 2 == 0:
            x //= 2
            cnt += 1

        if x != 1:
            ans.append("Alice")
        else:
            ans.append("Alice" if cnt % 2 == 0 else "Bob")

    print("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

# provided sample
assert run("4\n1\n4\n12\n69\n") == "Bob\nAlice\nAlice\nBob\n", "sample 1"

# minimum value
assert run("1\n1\n") == "Bob\n", "n = 1"

# smallest power of two
assert run("1\n2\n") == "Bob\n", "2 is losing"

# even but not power of two
assert run("1\n6\n") == "Alice\n", "contains odd factor"

# largest power of two below 1e9
assert run("1\n536870912\n") == "Bob\n", "2^29"

# large odd value
assert run("1\n999999937\n") == "Bob\n", "large prime"
