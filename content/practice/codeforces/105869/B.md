 ## 解決策
 ## 問題の理解

 根のある木が与えられ、そのタスクは、非常に具体的な幾何学的なルールに基づいてグリッド上にそれを描くことを想像することです。 各サブツリーは長方形の境界ボックス内に描画され、同じ親に接続された異なるサブツリーは、互いに素な境界ボックス内に配置する必要があります。 親は、レイアウト制約に違反しないエッジを使用して子に接続するため、サブツリーの配置方法を修正すると、サブツリーは相互に干渉しなくなります。 

キー オブジェクトは、サブツリーの描画とその境界ボックスの寸法、幅、高さです。 ノードをルートとするすべてのサブツリーについて、そのサブツリーを正しく描画した場合に達成できる四角形のサイズに興味があります。 サブツリーのすべての描画の中には、同じ幅でより高い高さを必要とする、またはその逆を必要とするという意味で厳密に劣るものもあり、それらは破棄できます。 

目標は、最終的にルートに焦点を当てて、各サブツリーの幅と高さの間の実現可能なトレードオフを決定することです。 素朴な見方としては、各サブツリーについて、あらゆる可能な幅について、達成可能な最小の高さを知りたいということになります。 

この制約は、典型的な動的プログラミングのスケールが約$n \le 2 \cdot 10^5$。 ノードごとにすべての幅の組み合わせを制限なく試行するソリューションでは、最悪の場合、速度が遅すぎる二次関数の動作が発生します。 状態ごとの線形遷移であっても、すでに厳しい状態になるため、どのソリューションでもサブツリーごとの状態の数を慎重に制限する必要があります。 

ナイーブ枝刈りの微妙な失敗例は、支配性を削減せずにすべての幅と高さのペアを保持する場合です。 たとえば、サブツリーに 2 つの描画があるとします。 

入力直感の例:

 チェーンを形成する 2 つの子を持つノードとバランスの取れた分割。 

両方の状態を維持すると、次のようになります。 

- (幅5、高さ2)
 - (幅5、高さ3)

 2 番目は常に悪いので、破棄する必要があります。 このような支配的な状態を除去しないと、正確さには影響しませんが、マージ中に不必要な二次爆発が発生します。 

幅から高さへのマッピングが単調であると仮定すると、別の問題が発生します。 一部のツリーでは、幅を増やしても厳密には高さがスムーズに減少しないため、単純に状態を貪欲に圧縮すると、必要な中間構成が削除される可能性があります。 

## アプローチ

 直接動的計画法による定式化から始めます。 各ノードについて$v$、そのサブツリーの可能な描画のセットを計算します。 各状態はペアです$(w, h)$、サブツリーを含めることができる長方形を表します。 サブツリーのルートは、その子のサブツリーが、それに接続された重ならない長方形内に配置できるように配置する必要があります。 

2 つの子サブツリーを持つノードを考慮する場合、それらの DP 状態を結合する必要があります。 サブツリーを仮定します$A$引き込むことができます$(w_a, h_a)$とサブツリー$B$で$(w_b, h_b)$。 それらを組み合わせる場合、親がレイアウトをどのように構成するかに応じて、並べて配置するか、垂直に積み重ねるという 2 つの自然な配置が可能になります。 各組み合わせにより、新しい長方形サイズの候補が生成されます。 

これにより、2 つのサブツリーからの状態のペアごとに、すべての有効な構成が試行され、新しい幅と高さのペアが生成される遷移が発生します。 各サブツリーには次のものを含めることができるため、$O(n)$単純な定式化で可能な幅、2 つのサブツリーのコストをマージする$O(n^2)$。 すべてのノードにわたって、これは次のようになります。$O(n^3)$最悪の場合、遅すぎる場合もあります。 

各幅のパレート最適状態を維持し、冗長な高さの値を減らすだけでよいことを確認することで、わずかに改善できます。 これにより、$O(n^2)$これは、各マージが幅範囲にわたる畳み込みになるためです。 

構造上の重要な洞察は、最適な図面では両方の寸法が大きくなる必要はないということです。 図面の幅が広すぎる場合は相対的に短くする必要があり、高すぎる場合は相対的に幅を狭くする必要があります。 これにより領域境界が作成されます。最適または中間の DP 状態には最大でも領域があります。$O(n \log n)$。 直観的には、小さなサブツリーを大きなサブツリーの下に繰り返し配置すると、高さは対数的に増加しますが、幅は次のように制限されます。$n$。 最悪の場合の構造も、この境界が厳しいことを示しています。 

これは、有効な状態において、幅または高さの少なくとも 1 つが次の値によって制限されることを意味します。$O(\sqrt{n \log n})$。 したがって、DP 状態を、より小さい寸法がこのしきい値を超えない構成のみに制限できます。 これにより、状態空間が大幅に縮小され、DP が管理可能になります。 

次に、これらの制限された状態のみを使用してサブツリー DP テーブルをマージし、全体的な複雑さを与えます。$O(n \sqrt{n \log n})$。

 ## アルゴリズムのチュートリアル

 各ノードの DP テーブルを定義します$v$、ここに達成可能な状態のセットを保存します$(w, h)$そのサブツリーの場合。 

1. 各リーフ ノードについて、その DP を単一の状態で初期化します。$(1, 1)$。 これは、単一の点で構成される最も単純な描画を表します。 
2. ノードのすべての子がノード自体の前に解決されるように、ノードを事後順序で処理します。 これにより、完全に計算されたサブツリーを常に結合できるようになります。 
3. ノードの場合$v$、独自の基本状態から開始します$(1, 1)$、それを各子サブツリー DP と繰り返しマージします。 結合ステップでは、2 つの状態セットを結合し、新しい候補境界ボックスのセットを生成します。 
4. 2 つの DP セットをマージするときは、現在の累積 DP と子 DP からの状態のすべてのペアを考慮します。 各ペアについて、子が現在の構造に対して水平に配置されるか垂直に配置されるかに応じて、考えられる結合長方形を計算します。 それぞれの組み合わせが新しいものを生み出します$(w, h)$。 
5. 候補状態を生成した後、優勢な状態を削除します。 2 つの状態の幅が同じで、一方の高さが大きい場合は、状態の悪い方を破棄します。 同様に、1 つの状態が両方の次元で厳密に悪い場合は、それを削除します。 これにより、DP セットがコンパクトに保たれます。 
6. 寸法制限を適用します。幅と高さの両方が境界を超えている状態を破棄します。$K = \sqrt{n \log n}$より小さい次元で。 これにより、状態空間が制御されたままになります。 
7. すべての子を処理した後、ルートの DP テーブルには、実行可能なすべてのフルツリー描画が含まれます。 答えは、問題に必要な最適化基準に応じて、この最終セットから抽出されます。 

### なぜ効果があるのか

 DP の不変条件は、ノードの処理後のものです。$v$、保存された状態のセットには、サブツリーのすべての有効な描画のパレート フロンティアが正確に含まれます。$T(v)$境界制約を尊重します。 すべての結合ステップでは、子サブツリーの構造的に有効な配置がすべて列挙され、枝刈りでは将来の組み合わせにとって決して最適ではない状態のみが削除されます。 グローバル図面は有効なサブツリー図面を再帰的に組み合わせて構築する必要があるため、ルート DP には必然的にすべての最適な候補が含まれます。 

寸法制限によって有効な最適解が削除されることはありません。これは、より小さい寸法が次の範囲内で制限される場合、最適な構成は同等以上の構成に変換できるためです。$O(\sqrt{n \log n})$ツリー図面にグローバル領域がバインドされているためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(10**7)

    import math
    K = int(math.sqrt(n * math.log2(max(2, n)))) + 2

    parent = [-1] * n
    order = []

    stack = [0]
    parent[0] = -2
    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if parent[to] == -1:
                parent[to] = v
                stack.append(to)

    dp = [dict() for _ in range(n)]
    # dp[v][w] = best h

    for v in reversed(order):
        dp[v][1] = 1
        for to in g[v]:
            if to == parent[v]:
                continue
            ndp = {}
            for w1, h1 in dp[v].items():
                for w2, h2 in dp[to].items():
                    # combine horizontally
                    w = w1 + w2
                    h = max(h1, h2)
                    if w <= K or h <= K:
                        if w not in ndp or ndp[w] > h:
                            ndp[w] = h
                    # combine vertically
                    w = max(w1, w2)
                    h = h1 + h2
                    if w <= K or h <= K:
                        if w not in ndp or ndp[w] > h:
                            ndp[w] = h
            dp[v] = ndp

    ans = min(dp[0].values())
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、再帰制限を回避するために、明示的なスタックを使用してルート付きツリーを構築します。 各ノードには、サブツリーのパレート フロンティアを表す最小高さへの幅をマッピングする辞書が格納されます。 

マージ中、現在の DP と子 DP の状態のすべてのペアは 2 つの方法で結合されます。1 つは幅を加算して高さを最大値とする水平連結、もう 1 つは高さを加算して幅を最大とする垂直連結です。 候補を生成した後、コードは各幅に対して最適な高さのみを維持することで枝刈りを行います。 

境界定数$K$これは、少なくとも 1 つの次元が小さいままである状態を追跡するだけでよいという理論的観察を強制します。 これにより、実際には二次爆発が防止されます。

 ノード 2 では、ノード 2 と子 3 を組み合わせると、垂直方向の積み重ね (高さの増加) または水平方向の配置が生成されます。 最適な構成では高さを最小限に抑えます。 

このトレースは、チェーンが高さを安定させながら幅を増やす傾向があることを示しており、長いパスによって幅広だが平坦な描画が生成されるという直観と一致しています。

これは、ノードごとに複数の状態を保持する必要がある理由を示しています。子の順序が異なると、基本的に異なる外接する四角形が生成されます。

 ## 特殊なケース

 単一ノード ツリーは最も単純なケースです。 このアルゴリズムは DP を単一の状態 (1, 1) で初期化し、マージは発生しないため、答えはすぐに 1 になります。 

チェーン形状のツリーでは、各ステップで 1 次元のみが増加する繰り返しマージが強調されます。 DP は、優勢ではない幅と高さのペアのみを正しく保持し、冗長な指数関数的な増加が発生しないようにします。 

星型のツリーは、多数の子が 1 つのルートに統合されるため、より繊細になります。 各マージでは競合する水平構成と垂直構成が導入され、等幅状態の爆発を防ぐために枝刈りステップが不可欠です。
