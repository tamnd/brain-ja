 ## 解決策
 ## 問題の理解

 1 から n までの整数のセットが存在するプロセスを扱っており、その中からサイズ k のサブセットをランダムに選択します。 そのサブセットから、最大の要素に興味があります。 ランダム性は固定サイズ k のすべてのサブセットにわたって均一であるため、{1, 2, ..., n} のすべての k 要素サブセットの可能性は等しくなります。 

1 から n までの考えられる k ごとに、k 要素のサブセットを選択するときに最大要素の期待値を考慮します。 最終的な対象量は、すべての k にわたるこれらの期待値の平均です。これは、すべてのサブセット サイズが均等に重み付けされることを意味します。 

出力は、すべてのサブセット サイズにわたってこの動作を集約した単一の期待値です。 

主な困難は、ランダム性自体ではなく、サブセットの列挙や何かのシミュレーションを回避する形式で期待値を表現することです。 この制約は、n が大きくなる可能性があることを暗示しているため、すべてのサブセット、またはサブセット内の要素のすべてのペアを反復するアプローチは直ちに実行不可能になります。 n の二次関数はすでに遅すぎます。複数のテスト ケースが存在する場合、テスト ケースごとに O(n^2) の組み合わせ推論さえも受け入れられません。 

微妙なエッジケースは、n が非常に小さい場合です。 n が 1 に等しい場合、各 k にはサブセットが 1 つだけ存在し、期待される最大値は自明のことながら 1 です。調和数を含む派生式を不用意に実装すると、ゼロによる除算や H1 マイナス 1 スタイルの式の誤った処理により、ここで機能が壊れる可能性があります。 

もう 1 つの特殊なケースは、浮動小数点精度です。 最終的な式には、対数的に増加する調波数が含まれており、浮動小数点を使用した単純な合計は、慎重に累算しなかったり、クエリごとに繰り返し再計算されたりすると、精度が失われる可能性があります。 

## アプローチ

 ブルート フォース ビューは定義から始まります。固定 k について、{1, ..., n} の k 要素のサブセットをすべて列挙し、各サブセットの最大値を計算し、これらの値を平均します。 これは確率空間に直接従うため、概念的には単純で正しいものです。 ただし、サブセットの数は C(n, k) で、各サブセットは最大値を見つけるために最大 k 個の要素をスキャンする必要があるため、単一の k にはすでに O(C(n, k) · k) のコストがかかります。 これをすべての k で合計すると、組み合わせ爆発的になり、合計で 2^n 個のサブセットのオーダーで増加しますが、これは中程度の n の場合でも完全に実行不可能です。 

重要な観察は、サブセットについて直接推論する代わりに、最大要素の分布について推論できることです。 ある値 x に等しい最大値は、選択されたすべての要素が {1, ..., x} 内にあるイベントから、すべてが {1, ..., x-1} 内にあるイベントを差し引いたものとして表すことができます。 これにより、問題は単純な二項係数式である制約付きサブセットのカウントに変換されます。 

そこから、期待値の線形性により、最大値の期待値を P(max > i) の形式の確率の合計として書き直すことができます。 このような確率はそれぞれ、サブセットが i より大きい要素を回避するかどうかにのみ依存し、これも単純な組み合わせの比率になります。 これにより、問題はサブセットの合計からプレフィックス制約の合計に軽減され、既知の組み合わせのアイデンティティ、特にホッケースティックのアイデンティティを使用して簡素化できます。 

単純化後、固定 k の期待値は、n と k のみに依存する閉じた形式に崩壊し、期待値内での i の反復に対する依存性が排除されます。 

最後に、1 から n までのすべての k の平均をとります。 これにより、1/(k+1) を含む項の合計が導入されます。これはまさに調和数のような構造です。 高調波数を事前計算すると、O(n) 前処理の後、すべてのテスト ケースを n あたりの一定時間で回答できるようになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | 組み合わせ + 調和の単純化 | O(N) 前処理、クエリごとに O(1) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、サブセットについて明示的に考えるのをやめ、代わりに各値がどのくらいの頻度で最大になるかを追跡することです。 

1. サブセット サイズ k を固定し、選択したサブセットの最大値が最大でもある値 i である確率を表します。 これは、最初の i 個の整数からすべての k 個の要素が選択されたときに正確に発生します。その確率は C(i, k) / C(n, k) です。 この再定式化により、最大値に関する推論が純粋なカウント制約に置き換えられます。 
2. 最大値の期待値を末尾和形式に変換し、P(max > i) の i にわたる合計として書き込みます。 このステップは、イベント「max > i」が単純な組み合わせイベントの補数であるため、最大値を直接合計するよりも計算が容易になるため便利です。 
3. 確率式を代入し、結果として得られる二項係数の合計を単純化します。 和の構造から C(i, k) という形式の繰り返し項が明らかになり、ホッケースティックの恒等式を使用して累積二項和を分解することが示唆されます。 
4. 組み合わせ恒等式を適用した後、固定 k の期待値は、n、k、および単一の二項項のみを含むコンパクトな式に単純化されます。 結果では、i またはサブセットを反復する必要がなくなりました。 
5. 次に、1 から n までのすべての k にわたって E[X_k] を平均します。 これにより、k+1 の逆数の和が導入され、自然に調和数が形成されます。 合計を H_{n+1} マイナス 1 として書き換えます。 
6. 各クエリが一定時間内に応答できるように、単純な再帰を使用して最大 n までの高調波数を事前計算します。 

これが機能する理由は、同じイベント空間のカウント解釈を切り替えることで、すべての変換が等価性を維持するためです。 確率空間は k 個のサブセットにわたって均一であるため、すべてのイベントは組み合わせの比率に帰着します。 各代数的単純化は、サブセットの対称的な寄与を効果的に集約しており、各要素の寄与は正確なサブセット構成ではなく、その下にある要素の数にのみ依存するため、調和構造が現れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    # precompute harmonic numbers H[i] = 1 + 1/2 + ... + 1/i
    H = [0.0] * (max_n + 2)
    for i in range(1, max_n + 2):
        H[i] = H[i - 1] + 1.0 / i

    # final formula: E = n + 1 - (n + 1) * (H[n + 1] - 1) / n
    # derived from averaging E[X_k]
    out = []
    for n in ns:
        if n == 1:
            out.append("1.0")
            continue
        val = (n + 1) - (n + 1) * (H[n + 1] - 1) / n
        out.append(str(val))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、すべてのテスト ケースを読み取ることから始まり、高調波数を最大 n まで事前計算できるようになります。 これにより、テスト ケースごとの再計算が回避されます。 

調和配列 H には、逆数の接頭辞の合計が格納されます。これは、最終的な式が 1/(k+1) タイプの項の合計に依存するため、不可欠です。 期待値が正確な整数値である必要はないため、浮動小数点演算を使用すれば十分です。 

n = 1 の場合は特殊なケースが処理されます。この式では、n による除算と高調波項が含まれており、そうでない場合は不必要な浮動小数点エッジ動作が発生します。 

## 実用的な例

 n = 2 について考えてみましょう。 

H を事前計算します: H1 = 1、H2 = 1.5、H3 = 1.8333...

 次のように計算します。 

| n | H[n+1] | H[n+1] - 1 | (n+1)*(H[n+1]-1)/n | 最終値 |
 | --- | --- | --- | --- | --- |
 | 2 | 1.8333 | 0.8333 | (3 * 0.8333)/2 = 1.25 | 3 - 1.25 = 1.75 |

 これは、高調波項がどのように線形ベースライン n+1 を直接減少させるかを示しています。 

ここで、n = 1 について考えてみましょう。 

| n | H2 | 数式の動作 | 出力 |
 | --- | --- | --- | --- |
 | 1 | 1.5 | 特殊ケース使用 | 1.0 |

 これにより、エッジ ケースでは除算が回避され、依然として正しい決定論的最大値が返されることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    H = [0.0] * (max_n + 2)
    for i in range(1, max_n + 2):
        H[i] = H[i - 1] + 1.0 / i

    out = []
    for n in ns:
        if n == 1:
            out.append("1.0")
            continue
        val = (n + 1) - (n + 1) * (H[n + 1] - 1) / n
        out.append(str(val))

    return "\n".join(out)

# minimal input
assert run("1\n1\n") == "1.0"

# small cases
assert run("2\n1\n2\n") == "1.0\n1.75"

# uniform structure check
assert run("1\n3\n")[:3] != "", "basic non-empty output"

# larger sanity
assert run("1\n10\n") != "", "produces numeric output"

 ## 特殊なケース

 n = 1 の場合、式には通常、n で除算して高調波の差を評価することが含まれるため、浮動小数点演算が不安定になる可能性があります。 この場合、唯一のサブセットが常に最大値 1 を持つため、アルゴリズムは明示的に 1.0 を返します。したがって、期待値は決定的です。 

n が非常に大きい場合、高調波数 H[n] は増分的に計算されるため、クエリごとに逆数値を個別に合計するのではなく、1 から上に構築することで精度の損失が最小限に抑えられます。 これにより、浮動小数点寄与の一貫した蓄積が保証されます。 

n = 2 の場合、式は H[3] に大きく依存し、1/2 と 1/3 の小さな丸めの違いにより、最終値がわずかにシフトする可能性があります。 直接プレフィックス構築により、両方が正確に 1 回含まれることが保証され、最終的な期待値の安定性が維持されます。
