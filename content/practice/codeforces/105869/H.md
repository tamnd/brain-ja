 ## 解決策
 ## 問題の理解

 私たちは、各状態が単なる頂点値ではなく、有向エッジトラバーサルの決定であるグラフを扱っています。 頂点ごとに$v$、そしてすべての隣人$u$それに隣接して、数量を定義します$L(v, u)$これは、次から始まる可能な最長の歩行を表します。$v$そして優位に立たされることになる$(v, u)$その最初の動きとして。 この最初のステップの後、歩行は最適に継続されます。$u$, ただし、すぐに戻ることはできません。$v$再帰で簡単な後戻り依存関係を作成する方法です。 

重要なアイデアは、コンピューティング$L(v, u)$フォームの値に依存します$L(u, w)$すべての隣人のために$w \neq v$。 したがって、すべての有向エッジ状態は、その元の頂点を指すものを除き、次の頂点の他のすべての出力エッジ状態に依存します。 

これにより、頂点ではなく有向エッジ上に依存構造が作成されます。 出力は最終的にこれらから導出されます。$L(v, u)$値。通常は、すべての開始選択肢に対して可能な最良の答えに集約されます。 

入力は無向グラフを次のように記述します。$n$頂点と$m$エッジ。 目標は、上記の依存関係ルールに基づいて、グローバルに一貫した最長パス値のセットを計算することです。 

複雑さの観点から見ると、どちらも$n$そして$m$線形スケール制約です。 これにより、エッジの二次関数は即座に除外されます。$m$のオーダーにすることができます$10^5$または$2 \cdot 10^5$。 どのようなソリューションでも、各有向エッジを一定回数効率的に処理する必要があります。 すべての無向エッジは 2 つの有向状態に対応するため、次のサイズの空間で動作します。$O(n + m)$これは、グラフ DP または依存構造上のシングルパス伝播を強く示唆しています。 

グラフにサイクルが含まれる場合、微妙な問題が発生します。 の素朴な再帰的定義$L(v, u)$特に循環コンポーネントでは、同じエッジ状態を無限に再訪する可能性があるようです。 課題は、グラフが無向であるにもかかわらず、依存方向によって正しく方向付けられると、有向エッジ状態間の依存関係が有向非循環構造を形成することです。 

典型的な失敗例は、メモ化順序を指定せずに単純な DFS 再計算を試行した場合に発生します。 

入力:```
3 3
1 2
2 3
3 1
```三角形で計算する$L(1,2)$に依存します$L(2,3)$に依存します$L(3,1)$、ループバックします$L(1,2)$。 順序付けのない単純な再帰では、無限ループまたは状態の再計算が繰り返し行われます。 

正しい出力は明確に定義されたままですが、それは依存関係がエッジ状態全体にわたって有効なトポロジー順序で解決されている場合に限られます。 

## アプローチ

 直接的なブルートフォースアプローチでは、それぞれを計算しようとします。$L(v, u)$再帰を使用して独立して実行します。 頂点から$u$、私たちはすべての隣人を試します$w \neq v$、計算する$L(u, w)$を選択し、最適な拡張子を選択します。 これはすぐに、各有向エッジのグラフの完全な探索に拡張されます。 

あるので$2m$有向エッジ状態であり、各状態がノードのほぼすべての隣接ノードにわたる走査をトリガーできるため、最悪の場合の複雑さは次のようになります。$O(m \cdot n)$密なグラフまたは循環グラフ。 これでは遅すぎます。 

重要な観察は、依存関係がローカルに構造化されていることです。 それぞれ$L(v, u)$からのすべての発信状態に依存します$u$、1つを除いて。 これは、すべての値がすでにわかっている場合を意味します$L(u, w)$、次に計算$L(v, u)$それらを集約しているだけです。 問題は、各ノードがその依存状態の 1 つを除くすべてが判明するまで待機する、有向エッジを介した値の伝播になります。 

これは、有向エッジごとに、未解決の必要な依存関係の数のカウンターを維持することを示唆しています。 各頂点を、その発信エッジ状態に依存する「待機中の先行者」のキューを管理するものとして扱うことができます。 一度値を取得すると$L(u, w)$が計算されると、関連する状態の保留中の要件が減り、新しい計算が可能になる可能性があります。 これは本質的に、暗黙的に指示された非循環構造に対する依存関係解決プロセスです。 

このプロセスはトポロジカル ソートに似たキューベースの伝播になりますが、頂点ではなくエッジ状態に適用されます。 各状態は 1 回だけ処理され、各依存関係の更新は一定時間で処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの有向エッジ状態を再解釈します$(v, u)$依存関係システムのノードとして。 そのような各状態について、それが依存する「まだ不足している」子状態の数を維持します。 

1. グラフの隣接リストを構築し、各有向辺を処理します。$(v, u)$状態として計算する必要があります。 依存性$(v, u)$すべての状態です$(u, w)$のために$w \neq v$。 
2. 各頂点について$u$、まだ最終化されていない送信有向エッジ状態の数を追跡します。 最初に、各有向状態は$(v, u)$すべての隣人に依存する$u$を除外する$v$、したがって、その依存関係の数は$\deg(u) - 1$。 
3. 依存関係カウントが 0 であるすべての有向エッジ状態を使用してキューを初期化します。 これは、頂点の次数が 1 の場合に発生します。その場合、唯一の状態には依存する代替の近傍がないためです。 これらは、これ以上の拡張が不可能な基本的なケースです。 
4. キューを繰り返し処理します。 状態のとき$(v, u)$が解決されると、その効果がそれに依存するすべての状態に伝播されます。 これは、状態の依存関係カウンターを減らすことを意味します$(u, x)$どこ$x \neq v$。 これは、次からの継続が必要であることを反映しています。$u$現在は解決されています。 
5. ある状態で依存関係カウンタがゼロになるたび$(u, x)$、これは、必要な継続がすべて計算されたことを意味するため、次のように計算します。$L(u, x)$そしてそれをキューにプッシュします。 
6. Continue until all reachable directed edge states are processed.

 The correctness relies on the fact that each state becomes computable exactly when all states it depends on are already finalized.

 ### なぜ効果があるのか

 The system defines a partial order over directed edge states induced by dependency exclusion of the parent vertex. 元のグラフには循環が含まれている可能性がありますが、すべての遷移は厳密に状態から移動するため、状態間の依存関係は非循環になります。$(v, u)$～に根ざした国家へ$u$ただし除く$v$、すぐに逆転するのを防ぎ、依存関係のサイクルが閉じられないようにします。 これにより、キューベースの解決が暗黙的な依存関係グラフ上で有効なトポロジー順序で状態を処理することが保証されるため、すべての$L(v, u)$は、必要な部分問題がすべてすでに解決されている状態で 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)
        edges.append((a, b))

    # Each directed edge (v -> u) is a state
    # We map states to ids
    state_id = {}
    rev_state = []
    
    for v in range(1, n + 1):
        for u in g[v]:
            state_id[(v, u)] = len(rev_state)
            rev_state.append((v, u))

    deg = [len(g[v]) for v in range(n + 1)]
    
    # dependency count: deg[u] - 1 for state (v -> u)
    indeg = [0] * len(rev_state)
    dependents = [[] for _ in range(len(rev_state))]

    pos = defaultdict(list)
    for idx, (v, u) in enumerate(rev_state):
        pos[u].append(idx)

    # Build dependency graph
    for idx, (v, u) in enumerate(rev_state):
        indeg[idx] = deg[u] - 1

    # For each state (v->u), all states (u->w), w != v depend on it
    for idx, (v, u) in enumerate(rev_state):
        for w in g[u]:
            if w == v:
                continue
            to_idx = state_id[(u, w)]
            dependents[idx].append(to_idx)

    q = deque()
    for i in range(len(rev_state)):
        if indeg[i] == 0:
            q.append(i)

    value = [0] * len(rev_state)

    while q:
        cur = q.popleft()
        v, u = rev_state[cur]

        for nxt in dependents[cur]:
            value[nxt] = max(value[nxt], value[cur] + 1)
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                q.append(nxt)

    # final answer is max over all states
    print(max(value) if value else 0)

if __name__ == "__main__":
    solve()
```このコードは、各有向エッジを DP 状態として明示的にモデル化します。 隣接構造`dependents`特定の状態が解決された後にどの状態が使用可能になるかをエンコードします。 の`indeg`配列は、各状態が計算される前に残っている依存関係の数を追跡します。 

キューは、依存関係の意味でリーフに付加されているすべての基本状態を最初に処理します。 状態が解決されるたびに、既知の最良の値が増加することで、依存状態のパスの拡張に貢献します。 

微妙な点は、依存関係の数がゼロになると、その状態を再訪することは決してないということです。 これにより、各状態が 1 回プッシュされ、各依存関係エッジが 1 回処理されるため、線形的な複雑さが保証されます。

 ## 特殊なケース

 単一エッジのグラフは最もクリーンな基本ケースです。 入力用`1-2`、両方の有向状態には代替継続がないため、両方ともすぐに計算可能です。 キューは両方の状態で開始され、伝播は発生しません。 

三角グラフは循環依存関係をテストします。 すべての状態が別の状態に依存している場合でも、逆エッジを除外すると依存関係空間のサイクルが中断され、最小限の入次数で任意の状態から初期化が可能になり、すべての状態が安定するまで一貫して伝播します。 

星型グラフは、高度な不均衡をテストします。 中心ノードには多くの依存関係がありますが、すべてのリーフ状態は独立した基本ケースであるため、計算はデッドロックなく内側に正しく流れます。
