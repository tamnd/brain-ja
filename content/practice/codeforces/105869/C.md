 ## 解決策
 ## 問題の理解

 グリッドには、ダイヤモンドを表すすべてのセルの値が含まれています。 ジャックは右と下のステップのみを使用してこのグリッド内を移動するため、パスは左上隅から右下隅まで単調になります。 

問題は、単一の単純なパスを単独で最適化しているわけではないということです。 代わりに、ソリューションの構造は、最適なルートには、パスが一時的に逸れてから再び合流するセルの周囲のローカルな「迂回パターン」を含めることができることを示唆しています。これにより、2 つの前方到達可能領域と 2 つのサフィックス到達可能領域の間に小さな 2 x 2 の相互作用が作成されます。 目標は、そのような有効なパス構成をすべて考慮したときに、収集されるダイヤモンドの合計を最大化することです。 

推論を容易にするために、2 つの動的計画表が導入されています。 最初のテーブルは、$A[i][j]$、開始セルからセルまでの有効なパスで収集できるダイヤモンドの最大数を表します。$(i, j)$。 2番目のテーブルは、$B[i][j]$、からの有効なパスで収集できるダイヤモンドの最大数を表します。$(i, j)$右下隅に。 

Both tables are standard grid DP with transitions from top and left for$A$、下から右へ$B$。 Each can be computed in linear time over the grid.

 自明ではない部分は、最適な答えが 1 つの点での 1 つのきれいな分解に対応しない可能性があることです。 代わりに、パスが 2 x 2 ブロックの周囲に 4 つのパターンのいずれかをローカルに形成する構成があり、これにより前方および後方の最適なサブパスの接続方法が効果的に「再配置」されます。 Each configuration corresponds to a small constant-size correction on top of combining prefix and suffix optimal values.

 出力は、そのようなすべてのローカル構成の中で達成可能な最大値と、単純な直線パスの値です。$A[n][m]$。 

ここでの単純な間違いは、最適な答えが常に次のように仮定されることです。$A[n][m]$, since that already represents the best single monotone path. ただし、問題の構造により、単一の DP パスでは表現できない方法で 2 つの最適なサブパスを効果的に組み合わせる、制御されたローカルの再構築が可能になります。 

2 番目のよくある間違いは、すべての候補分割点のグローバル パスを再計算しようとすることです。これは、中間状態のすべてのペアに対して直接実行すると、三次的な動作につながります。 

## アプローチ

 ブルートフォース解釈では、最初から最後まですべての単調パスを列挙し、考えられるすべての局所偏差パターンを挿入しようとします。 動的プログラミング状態に限定しても、すべてのセルを結合の可能性があるとみなして、最適なプレフィックスとサフィックスの寄与を繰り返し再計算してみることもできます。 これにより、少なくとも$O(n^2 m^2)$2 つのパス セグメント間の各候補相互作用には再計算または部分構造のスキャンが必要になるため、単純に実行した場合の動作は問題になります。 

重要な観察は、問題の構造が 2 × 2 の小さな領域の周囲に完全に局所的であるということです。 その領域の外側にあるものはすべて、すでに最適に処理されています。$A$そして$B$。 唯一の自由は、単一セルとその隣接セルが関与する一定数の構成を通じて 2 つの最適なサブパスをどのように接続するかです。 

これが認識されると、解決策は事前計算に移ります。$A$そして$B$, and then scanning the grid once, evaluating a constant number of configurations per cell. 各構成では、事前に計算された DP 値といくつかの直接隣接するセル値を使用して重複を修正し、寄与が二重にカウントされないようにします。 

This transforms the problem from global path manipulation into local pattern evaluation over a precomputed optimal landscape.

 ## アルゴリズムのチュートリアル

 ### 1. プレフィックス DP を計算します。$A$細胞ごとに$(i, j)$、から最高のスコアを計算します$(1,1)$上または左からの移動のみを使用してそのセルに移動します。 すべての最適なパスが到達する必要があるため、これは標準のグリッド DP です。$(i,j)$2 つの前任者のうちの 1 つからのものです。 

### 2. サフィックス DP を計算します。$B$細胞ごとに$(i, j)$、そのセルから最高のスコアを計算して、$(n,m)$を使用すると、右または下にのみ移動します。 トランジションは下または右に進むため、これは逆の順序で行われます。

### 3. 直線パスで答えを初期化する

 値$A[n][m]$は、可能な限り最良の単一の単調パスを表します。 これは常に有効な候補です。 

### 4. 各セルを潜在的な相互作用中心としてスキャンします。 

あらゆる細胞に$(i, j)$、最適な構造が、$(i,j)$、$(i+1,j)$、$(i,j+1)$、 そして$(i+1,j+1)$、これらのセルが存在する場合に限ります。 

### 5. 4 つのローカル構成を評価する

4 つのパターンは、動きの制約に違反することなく、同じ 2 x 2 構造に 2 つの単調なパスを通すさまざまな方法に対応しています。

### なぜ効果があるのか

 DP テーブル$A$そして$B$すべてのグローバル パス構造はすでに最適なプレフィックスおよびサフィックス情報に圧縮されています。 有効な最適解はどれも、プレフィックス セグメント、ローカル インタラクション領域、およびサフィックス セグメントに分解できます。 移動が右と下に制限されているため、相互作用領域は一定サイズの近傍を超えて拡張することはできません。 したがって、単一パスを超える改善はすべて 2 x 2 構造内で実現する必要があり、すべてのグローバル構成は一定のローカル パターンのセットの 1 つに還元されます。 これにより、すべてのセルと構成にわたるスキャンの完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    A = [[0] * m for _ in range(n)]
    B = [[0] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            best = 0
            if i > 0:
                best = max(best, A[i-1][j])
            if j > 0:
                best = max(best, A[i][j-1])
            A[i][j] = best + g[i][j]

    for i in range(n - 1, -1, -1):
        for j in range(m - 1, -1, -1):
            best = 0
            if i + 1 < n:
                best = max(best, B[i+1][j])
            if j + 1 < m:
                best = max(best, B[i][j+1])
            B[i][j] = best + g[i][j]

    ans = A[n-1][m-1]

    for i in range(n - 1):
        for j in range(m - 1):
            # four-cell block:
            # (i,j) (i,j+1)
            # (i+1,j) (i+1,j+1)

            # configuration 1
            v1 = A[i][j] + B[i+1][j+1] + g[i][j+1] + g[i+1][j]

            # configuration 2
            v2 = A[i][j+1] + B[i+1][j] + g[i][j] + g[i+1][j+1]

            # configuration 3 (horizontal swap flavor)
            v3 = A[i][j] + B[i+1][j] + g[i][j+1] + g[i+1][j+1]

            # configuration 4 (vertical swap flavor)
            v4 = A[i][j+1] + B[i+1][j+1] + g[i][j] + g[i+1][j]

            ans = max(ans, v1, v2, v3, v4)

    print(ans)

if __name__ == "__main__":
    solve()
```最初の DP が埋まる$A$すべての状態が以前に計算された上と左の近傍のみに依存するように、順方向で実行されます。 2 番目の DP が埋まる$B$対称的な理由から逆の順序になります。 

2 x 2 ブロックにわたるネストされたループにより、考えられるすべてのローカル インタラクション センターが 1 回だけチェックされることが強制されます。 4 つの式はそれぞれ、ブロック内で相互作用する 2 つのモノトーン セグメントの個別のルーティングに対応し、中央セルの欠落や二重カウントを防ぐために実際のグリッド値を使用した補正が行われます。 

の初期化`ans`と`A[n-1][m-1]`ローカルでのインタラクションがないケースも有効であるとみなされるようにします。

 ## 特殊なケース

 サイズ 1 × 1 の最小グリッドは初期化によって直接処理されます。`ans = A[n-1][m-1]`2 x 2 ブロックが存在せず、ネストされたループは実行されないためです。 

サイズが 1 × m または n × 1 のグリッドでも、相互作用ループが完全に回避されます。 遷移が単一方向に減少し、答えが唯一の有効なパスのままであるため、DP テーブルは引き続き正しく計算されます。 

すべての値が同一であるグリッドは、すべての補正項が対称的にキャンセルされ、合計が変化する配置がないため、4 つの構成すべてが同じ値に評価されることを示しています。
