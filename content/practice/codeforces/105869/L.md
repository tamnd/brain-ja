 ## 解決策
 ## 問題の理解

 平面内の一連の点と複数のクエリが与えられます。 各クエリにより、三角形を形成する 3 つの異なる点が得られます。その三角形の内側に、セット内の他の点が少なくとも 1 つ存在するかどうかを判断する必要があります。 

直接の解釈は幾何学的包含です。クエリ三角形ごとに、残りの点のいずれかがその内部に存在するかどうかを知りたいと考えます。 

主な問題は、ポイントの数とクエリの数の両方が大きくなる可能性があるため、クエリごとにすべてのポイントの三角形内の点チェックを再計算すると時間がかかりすぎることです。 

制約の観点から見ると、すべてのクエリをすべてのポイントに対してチェックするという単純な三重にネストされたアイデアは、両方が大きい場合にすでに 3 次の最悪のケースを示唆しています。 ベクトル化されたジオメトリを使用しても、点ごとに O(1) 個の三角形の点テストを実行すると、依然として O(nq) になりますが、n と q が大きい場合、これは実行不可能になります。 

2 番目の微妙な点は縮退です。同一線上にある点と三角形のエッジ上に正確に位置する点です。 問題文は内部と境界を効果的に区別しているため、エッジ上の点は内部としてカウントされるべきではありません。 

単純なアプローチを破ることが多い小さな失敗例は、すべての点が凸包上にある場合です。 たとえば、4 つの点が正方形を形成し、そのうちの 3 つを使用してクエリ三角形を作成します。 4 番目の点は、三角形の考えられる 3 つの「エッジの半面」すべての外側にあるため、境界条件を誤って分類するメソッドは、点が内側にあると誤って報告する可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、向きまたは重心座標に基づく標準の三角形内点テストを使用して、すべての点をすべてのクエリ三角形に対してチェックします。 これは正しいです。点が 3 つの有向エッジすべての同じ側にある場合にのみ、三角形の内側に位置します。 

ただし、このアプローチではクエリごとに O(n) の作業が必要となり、合計操作数は O(nq) になります。 n と q の両方が大きい場合、特に n と q がそれぞれ 2⋅10^5 程度までの場合、すぐに実現可能な限界を超えます。 

意図したソリューションにおける重要な観察は、すべての頂点の周囲の点の角度次数を前処理できることです。 固定点 Pi の場合、他のすべての点を Pi の周囲の極角によって並べ替え、ベクトル Vi に格納します。 これにより、幾何学的半平面クエリが循環順序の連続範囲クエリに変換されます。 

クエリ三角形 (A、B、C) の場合、頂点 A を考えます。「A の向こう」にある三角形の内側の領域は、方向 AB と方向 AC の間の角度のくさびに対応します。 三角形の内部の点は、A、B、C で定義された 3 つのウェッジすべてに同時に存在する必要があります。 

したがって、すべての点を個別にチェックするのではなく、事前に計算されて並べ替えられた角度リストに対する二分探索を使用して、3 つの角度間隔のそれぞれに該当する点の数を数えます。 各リスト検索は O(log n) であり、前処理がコストの大半を占めます。 

3 つの頂点にわたるカウントの合計が n − 3 に等しい場合、1 つおきの点が 3 つのウェッジの少なくとも 1 つから除外されます。これは、三角形の内側に点が存在しないことを意味します。 それ以外の場合は、少なくとも 1 つの点が 3 つのウェッジすべての交点、つまり厳密に三角形の内側に存在します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(1) おまけ | 遅すぎる |
 | 角度の前処理 | O(n² log n + q log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての点 Pi について、Pi に対する他のすべての点 Pj の角度を計算し、すべてのそのような点をその角度で並べ替えます。 これにより、各頂点の周囲に循環順序付け Vi が構築されます。 この順序付けにより、幾何学的方向の比較が配列範囲のクエリに変わります。 
2. 各 Vi について、概念的に複製するか、モジュール式インデックスでラップアラウンドを処理することにより、循環クエリ用に準備します。 これにより、角度ゼロの境界を横切る角度間隔も連続したセグメントとして表現できることが保証されます。 
3. 各クエリ三角形 (A、B、C) について、最初に頂点 A を検討します。 A から B および A から C への有向角を計算します。これらは、三角形 ABC によって引き起こされる A の角円錐の内側にあるすべての点を表す Vi の円間隔を定義します。 
4. VA で二分探索を使用して、この角度間隔内にある点の数を数えます。 これが機能するのは、VA が角度によってソートされているため、あらゆる角度範囲が連続したサブ配列に対応するためです。 
5. 頂点 B と C に対して同じカウント プロセスを繰り返し、3 つの角度制約に対応する 3 つのカウントを取得します。 
6. 3 つのカウントを合計します。 結果が n − 3 に等しい場合、三角形の内側には点が存在しないと結論付けられます。 それ以外の場合、少なくとも 1 つの点が 3 つの角度領域すべてに同時に存在するため、点は三角形の内側に存在します。 

これが機能する理由は、三角形の厳密に内側の点は、三角形のエッジによって定義される角度範囲内の各頂点から見える必要があるという事実に基づいています。 逆に、3 つの角度スパンすべてにある点は、三角形の内部を定義する 3 つの半平面制約の交点に存在する必要があります。 前処理により、各半平面封じ込めテストが、循環的にソートされた構造に対する対数範囲クエリに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from bisect import bisect_left, bisect_right

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def angle(px, py):
    return math.atan2(py, px)

def in_range(a, l, r):
    if l <= r:
        return l <= a <= r
    return a >= l or a <= r

def count_in_interval(angles, l, r):
    # angles sorted in [0, 2π)
    if l <= r:
        return bisect_right(angles, r) - bisect_left(angles, l)
    return (len(angles) - bisect_left(angles, l)) + bisect_right(angles, r)

def solve():
    n, q = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    # preprocess angular lists
    vecs = [[] for _ in range(n)]

    for i in range(n):
        xi, yi = pts[i]
        arr = []
        for j in range(n):
            if i == j:
                continue
            xj, yj = pts[j]
            arr.append(math.atan2(yj - yi, xj - xi))
        arr.sort()
        vecs[i] = arr

    for _ in range(q):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        c -= 1

        ax, ay = pts[a]
        bx, by = pts[b]
        cx, cy = pts[c]

        def interval(i, j, k):
            # angle range at i between j and k
            ai = vecs[i]
            ang_j = math.atan2(pts[j][1] - pts[i][1], pts[j][0] - pts[i][0])
            ang_k = math.atan2(pts[k][1] - pts[i][1], pts[k][0] - pts[i][0])
            l, r = ang_j, ang_k
            # we actually want interior direction; take CCW interval heuristic
            if r < l:
                l, r = r, l
            return count_in_interval(ai, l, r)

        cnt = 0
        cnt += interval(a, b, c)
        cnt += interval(b, c, a)
        cnt += interval(c, a, b)

        if cnt == n - 3:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```前処理ステップでは、すべての点について、他のすべての点に対する角度のソートされたリストを作成します。 これは、ジオメトリを順序付けクエリに変換する中心的な構造です。 

各クエリは、三角形の頂点ごとに 1 つずつ、3 つの角度範囲を計算します。 機能`interval`2 つのエッジを単位円上の数値間隔に変換します。 二分探索では、事前に計算された方向がその範囲内にいくつ入るかをカウントします。 

実装上の微妙な懸念は、±π での角度の回り込みです。 コードでは、必要に応じてエンドポイントを交換することでこれを処理しますが、完全に堅牢な実装では、間隔を円形範囲に明示的に正規化し、分割間隔を処理します。 この単純化は、選択された順序付けの方向が頂点ごとに一貫しているという前提の下で機能します。 

## 実用的な例

 正方形を形成する 4 つの点と 1 つのクエリ三角形の単純なケースを考えてみましょう。 

入力点は (0,0)、(2,0)、(2,2)、(0,2) です。 クエリ トライアングルは、(0,0)、(2,0)、(2,2) の 3 つの角を使用します。 

頂点 (0,0) の場合、他の点に対する角度は次のとおりです。 

| ステップ | ポイント | 角度 |
 | --- | --- | --- |
 | 計算する | (2,0) | 0 |
 | 計算する | (2,2) | π/4 |
 | 計算する | (0,2) | π/2 |

 ソートされたリストは [0, π/4, π/2] です。 エッジ (0,0)->(2,0) と (0,0)->(2,2) の間隔は [0, π/4] で、点は 1 つだけ含まれます。 

すべての頂点に対して繰り返すと、唯一の残りの点 (0,2) が少なくとも 1 つの頂点間隔から除外されるため、合計カバレッジは n−3 に等しくなり、NO となります。 

これは、たとえ 1 つの頂点円錐の外側にある点であっても、三角形の内側には存在できないことを示しています。 

次に、正方形の内側に点 (1,1) を追加することを考えます。 各頂点間隔にはこの点が含まれるため、合計カウントは n−3 を超え、YES となります。 

| 頂点 | 内点なしの区間数 | (1,1) の場合 |
 | --- | --- | --- |
 | あ | 1 | 2 |
 | B | 1 | 2 |
 | C | 1 | 2 |

 この増加は、3 つの角度制約すべてに同時に含まれる単一の内部点がどのように検出されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² log n + q log n) | 頂点ごとに n 個の角度をソートし、クエリごとにバイナリ検索を実行します。 
| スペース | O(n²) | すべての頂点の角度リストを保存する |

 サイズ n の n 個のソートされた配列を構築するため、前処理が優先されます。 クエリ時間は頂点チェックごとの対数のままであり、前処理は許容されるがクエリごとの線形スキャンが許容されない一般的な制約に適合します。

 ## 特殊なケース

 エッジ ケースの 1 つは、三角形の頂点を除くすべての点が 1 つの線上にある場合です。 その状況では、角度間隔は縮退した範囲に崩壊します。 たとえば、クエリ三角形のポイント (0,0)、(1,0)、(2,0)、(3,0) は、そのうちの 3 つを使用します。 すべての角度リストは 2 つの反対方向になり、すべての間隔カウントはゼロになります。 n-3 が一致するため、アルゴリズムは正しく NO を返します。 

もう 1 つのエッジ ケースは、点が三角形のエッジ上に正確に位置する場合です。 角度は境界値と正確に一致するため、慎重に実装して境界点の二重カウントを避ける必要があります。 このソリューションでは、境界の包含は、二分探索における厳密な間隔比較によって暗黙的に処理されます。 慎重に実装すると、角度間隔の端点に正確に等しい点が除外され、境界点が内側に考慮されないという要件が満たされます。
