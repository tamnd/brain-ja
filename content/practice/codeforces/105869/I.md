 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 このタスクは、配列内の各要素がモジュラー式の除数として機能する、すべての順序付きペアのグローバル合計を計算することです。 固定要素ごとに$a_j$、他のすべての要素を見ていきます$a_i$、計算する$a_i \bmod a_j$、それを二乗し、すべてを 1 つの答えに蓄積します。 

したがって、この構造は基本的にソートされた配列に対するペアごとの相互作用であり、各ペアは方法に応じて値を提供します。$a_i$～に関して分解する$a_j$。 

重要な観察は、固定除数の候補についての観察です。$a_j$、の値$a_i$商でグループ化すると、構造化された方法で動作する$\left\lfloor \frac{a_i}{a_j} \right\rfloor$。 この商は、モジュラー式が線形になるセグメントに配列を分割します。$a_i$これにより、プレフィックス合計の集計が可能になります。 

入力サイズが十分に大きいため、すべてのペアを直接反復するソリューションは直ちに実行不可能になります。 ナイーブ$O(n^2)$アプローチとは、～までを意味します$10^{10}$最悪の場合、許容範囲をはるかに超えた操作が行われます。 内部計算が自明ではないため、わずかに最適化されたペアワイズ手法でも依然として遅すぎるままです。 

隠された構造は、$n^2$ペア、それぞれ固定$a_j$値が除算によってグループ化されている場合、限られた数の商区間のみと相互作用します。 これにより、効率的な作業が大幅に減少します。 

値が大きく偏っている場合、微妙なエッジケースが発生します。 たとえば、配列に繰り返し大きい値が多数含まれている場合、商による単純なグループ化は、適切な範囲処理を実装していない場合、多くのチェックに堕落する可能性があります。 もう 1 つの特殊なケースは、値が小さい場合 (すべて 1 など) です。 その場合、すべての剰余はゼロであり、答えは自明のことながらゼロですが、不注意な実装では依然として不必要なセグメンテーション ロジックを試行する可能性があります。 

## アプローチ

 直接的なアプローチではすべてのペアを考慮します$(i, j)$そして計算します$(a_i \bmod a_j)^2$明示的に。 これは定義に正確に従っているため、正しいです。 ただし、そのコストは配列サイズで 2 次になります。 と$n = 2 \cdot 10^5$、これにより数十億の操作が発生し、時間内に実行できなくなります。 

これを改善するために、次のように修正します。$a_j$そしてその方法を理解しようとします$a_i \bmod a_j$次のように動作します$a_i$が増加します。 重要な考え方は、商$\left\lfloor \frac{a_i}{a_j} \right\rfloor$連続した範囲にわたって一定に保たれます$a_i$。 このような範囲内では、剰余は次のように単純化されます。$a_i - t \cdot a_j$、 どこ$t$は商の値です。 これにより、非線形モジュラー式が連続セグメントにわたる二次式に変換されます。 

配列がソートされると、すべての値が同じ商を共有します$t$連続したセグメントを形成します。 これにより、次のプレフィックスの合計を事前計算することが可能になります。$a_i$、$a_i^2$、および定数カウントを実行し、各セグメントを一定時間で評価します。 

残りの懸念は、そのようなセグメントが 1 つあたりにいくつ存在するかということです。$a_j$。 それぞれについて$a_j$、商$t$からの範囲$0$まで$\lfloor \max(a) / a_j \rfloor$。 これだと大きく見えますが、$a_j$が配列全体の一様分布からランダムに選択される場合、期待される個別の商遷移の数は対数になります。 これは、除数をカウントする引数に現れる高調波系列の動作と同じです。 

したがって、それぞれの$a_j$貢献するだけ$O(\log A)$平均してセグメント数が増加し、期待される$O(n \log n \log A)$解決。

 ## アルゴリズムのチュートリアル

 すべての商ベースのパーティションが連続するように配列をソートすることから始めます。 この構造的な順序付けにより、要素ごとの計算ではなく範囲の集計が可能になります。 

次に、配列値のべき乗に対するプレフィックスの合計を事前計算します。 具体的には、$a_i$、$a_i^2$、および二次式を展開するときに便利な単純な接頭辞の合計も含まれます。 

固定値ごとに$a_j$、考えられる商の値を反復処理します。$t$。 それぞれ$t$インデックスの範囲を定義します$i$そのような$\left\lfloor \frac{a_i}{a_j} \right\rfloor = t$。 ソートされた配列の二分探索境界を使用して、この範囲を特定します。 

セグメントを特定したら$[p, q]$、コントリビューションを書き換えます。$$(a_i \bmod a_j)^2 = (a_i - t \cdot a_j)^2 = a_i^2 - 2 t a_j a_i + t^2 a_j^2$$各項が一定時間で得られるように、プレフィックス合計を使用してセグメント全体の合計を計算します。 これにより、セグメントの明示的な反復処理が回避されます。 

有効なすべてに対してこれを繰り返します$t$現在の値$a_j$、最終的な回答への貢献を蓄積します。 

### なぜ効果があるのか

 正確さは、配列を最大の連続セグメントに分割することで得られます。$\left\lfloor \frac{a_i}{a_j} \right\rfloor$は一定です。 各セグメント内では、モジュラー式は次の固定二次関数になります。$a_i$。 プレフィックス合計は線形性を維持するため、連続した区間にわたるこの二次形式の合計は正確で損失がありません。 すべてのペア$(i, j)$はその商に対応する 1 つのセグメントにのみ含まれるため、寄与が見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(n):
        pref1[i + 1] = pref1[i] + a[i]
        pref2[i + 1] = pref2[i] + a[i] * a[i]

    def range_sum(l, r):
        return pref1[r + 1] - pref1[l]

    def range_sum2(l, r):
        return pref2[r + 1] - pref2[l]

    ans = 0

    for j in range(n):
        aj = a[j]
        i = 0
        max_val = a[-1]

        t = 0
        while t * aj <= max_val:
            # find range of i where floor(ai / aj) == t
            left_val = t * aj
            right_val = (t + 1) * aj - 1

            # binary search for bounds
            l = j + 1
            r = n - 1

            # lower bound
            lo = l
            hi = r
            L = n
            while lo <= hi:
                mid = (lo + hi) // 2
                if a[mid] >= left_val:
                    L = mid
                    hi = mid - 1
                else:
                    lo = mid + 1

            lo = l
            hi = r
            R = j - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                if a[mid] <= right_val:
                    R = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if L <= R and L < n:
                cnt = R - L + 1
                s1 = range_sum(L, R)
                s2 = range_sum2(L, R)

                # sum (ai - t*aj)^2
                ans += s2 - 2 * t * aj * s1 + cnt * (t * aj) * (t * aj)

            t += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、連続した商範囲を有効にするためにソートすることから始まります。 次に、プレフィックス合計が構築され、線形項と二次項の両方について定数時間範囲の集計が可能になります。 

それぞれについて$a_j$、商の値をスキャンします$t$。 それぞれ$t$数値間隔を定義します$[t a_j, (t+1)a_j - 1]$、二分探索を使用して、どのインデックスがこの範囲に該当するかを見つけます。 寄与度は、セグメント上の反復をプレフィックス合計演算に置き換えて、拡張平方恒等式を使用して計算されます。 

境界には注意が必要です。検索では、その前にインデックスを除外する必要があります。$j$問題が順序付きペアを定義している場合$i \ne j$また、二分探索では空の範囲を正しく処理する必要があります。 

## 実用的な例

 小さな配列を考えてみましょう$a = [1, 3, 5]$。 

それぞれの貢献度を計算します$a_j$。 

| j | a[j] | t | セグメント [L, R] | s1 | s2 | 貢献 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | [1,2] 無効 | - | - | 0 |
 | 1 | 3 | 0 | [0,2] → [1] | 1 | 1 | (1-0)^2 = 1 |
 | 1 | 3 | 1 | [3,5] → [5] | 5 | 25 | (5-3)^2 = 4 |

| j | a[j] | t | セグメント | CNT | 貢献 |

 ## 特殊なケース

 すべての要素が等しい場合、どのペアでもすべての剰余はゼロとなり、アルゴリズムは値がゼロの単一の商セグメントを処理します。 のような入力の場合$[5, 5, 5]$、唯一関連する$t$はゼロであり、計算されたセグメントの合計はゼロになります。$a_i - 0 \cdot a_j = 5$ただし、インデックス付けルールに応じてそれ自体とのみペアになるため、対称ペアの処理でキャンセルが発生します。 

配列に次のような単一の要素が含まれる場合$[10]$、有効なペアがないため、外側のループは実行されますが、寄与するセグメントはありません。 二分探索では、すべての範囲が空になります。$t$、累積された答えは変更されずゼロのままになります。 

次のように値の間隔が広い場合$[1, 10^9]$、 それぞれ$a_j$商区間はわずかしか生成されません。$t a_j$配列の最大値をすぐに超えてしまいます。 ループオーバー$t$は早期に終了し、1 つまたは 2 つのセグメントのみが評価されるため、実際には対数的な動作が示されます。
