 ## 解決策
 ## 問題の理解

 ゲームは有向非巡回グラフ上でプレイされます。 1 つのターンはノード 1 から始まり、ノード n に到達すると終了します。 ターンがノードを訪問するたびに、そのノードはその報酬を合計スコアに貢献します。 各有向エッジは、すべてのターンにわたって限られた回数のみ使用できます。 目標は、収集された報酬の最大額を与える 1 から n までのパスのコレクションを選択することです。 

重要な詳細は、いくつかのターンが頂点上でオーバーラップできるが、エッジの容量を超えることはできないということです。 これにより、問題は最適な単一パスを見つけることとは異なります。 ローカルで最適なパスは、後で他の多くの価値のあるパスを許可するエッジを消費する可能性があります。 

制約はグラフ アルゴリズムには十分小さいですが、パスの考えられるすべての組み合わせを試すには大きすぎます。 頂点が最大 100 個、エッジが 500 個であっても、DAG 内の可能なパスの総数は依然として指数関数的になる可能性があるため、パスを列挙したり、ターンのすべてのサブセットを試行したりすることは不可能です。 グラフの構造に基づいた多項式の解が必要です。 

いくつかの特殊なケースでは、誤った実装が壊れる可能性があります。 1 から n までのパスが 1 つだけあるグラフを考えてみましょう。```
2 1
5 7
1 2 3
```同じパスを 3 回プレイでき、プレイするたびに両方のノードの報酬が収集されるため、答えは 36 です。 最適なパスを 1 つだけ見つけるソリューションは 12 を返し、失敗します。 

もう 1 つの注意が必要なケースは、2 つのパスが限られたエッジを共有する場合です。```
4 4
1 10 1 1
1 2 1
2 4 1
1 3 5
3 4 1
```答えは 18 です。ノード 2 を通るパスは 12 を与え、ノード 3 を通るパスは 7 を与えます。現在最も価値のあるパスを常に選択する貪欲なアプローチは、他の例で共有ボトルネックを消費し、より適切なグローバル分散を妨げる可能性があります。 

ノード 1 の報酬も見逃しがちです。 プレーヤーは各ターンをノード 1 から開始します。この例では、この開始ノードがスコアに貢献することを示しています。 どのフロー モデルでも、使用されるパスごとにノード 1 とノード n を正確に 1 回カウントする必要があります。 

## アプローチ

 ブルートフォースのアイデアは、ノード 1 からノード n までの最も収益性の高いパスを繰り返し検索し、それを 1 回使用し、そのエッジの容量を減らし、パスがなくなるまで続行するというものです。 これは、選択されたすべてのパスが有効であり、使用されているすべてのエッジがルールに従うため、いくつかの小規模なケースでは機能します。 

問題は、各瞬間に最適なパスを選択することが全体的に最適ではないことです。 さらに重要なのは、DAG 内の可能なパスの数は指数関数的に増加する可能性があるため、すべての候補を保存することすら不可能であるということです。 多数の異なるブランチがある場合、検索スペースは制約が許容する範囲をはるかに超えて拡大します。 

重要な点は、各ターンがノード 1 からノード n へのフローの単位であるということです。 エッジパス制限は、まさにエッジ容量です。 合計報酬は、フローのユニットによって使用されるすべての頂点に付加されます。つまり、すべての頂点を受信コピーと送信コピーに分割することで、頂点報酬をエッジのコストに変換できます。 

分割後、1 つのフロー単位を頂点に送信すると、フローはその頂点報酬を表すエッジを強制的に通過します。 エッジコストを与える`-a[i]`この問題は、最小コスト最大フローを見つけることに変換されます。 すべての報酬は正であるため、可能なパスが追加されるたびに答えが増加するため、1 から n までのパスが存在しなくなるまで拡張を続けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | パス数の指数関数 | 指数 | 遅すぎる |
 | 最適 | O(F * V * E) SPFA の場合、F は総流量 | O(V + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の頂点をすべて分割します`i`2 つのノードに分割します。`i_in`そして`i_out`。 からエッジを追加します`i_in`に`i_out`容量もコストも無限大`-a[i]`。 このエッジを通過することは、その頂点の報酬を収集することを表します。 
2. 元の道路をすべて置き換える`u -> v`からのエッジを持って`u_out`に`v_in`所定の容量でコストはゼロです。 道路は依然として限られた回数しか使用できないため、容量は変わりません。 
3. から最小コスト最大フローアルゴリズムを開始します。`1_in`に`n_out`。 それぞれの最短の増強パスは、さらに 1 回のプレイ可能なターンを表します。 マイナスのコストにより、収益性の高いパスの総コストが低くなります。 
4. 各拡張の後、そのフローによって得られる報酬の量を答えに追加します。 拡張パスが存在しなくなるまで続行します。 
5. フローコストが負の報酬として保存されたため、最終的な最小コストの否定を出力します。 

なぜ効果があるのか:

 すべての有効なゲーム戦略は、ノード 1 からノード n までのパスの集合です。 各パスは 1 つのフロー単位で表すことができ、エッジ容量により、道路が許容回数を超えて使用されないことが保証されます。 頂点を分割するエッジは、その頂点を訪問する各ユニットによって正確に 1 回交差されるため、負のコストは収集された報酬を正確に差し引きます。 したがって、総コストを最小化することは、収集されるゴールドの総量を最大化することと同じです。 すべての報酬はプラスであるため、利用可能なすべての拡張パスは別の収益性の高いターンに対応するため、アルゴリズムは正当なターンが残っていない時点で正確に停止します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

class Edge:
    __slots__ = ("to", "rev", "cap", "cost")

    def __init__(self, to, rev, cap, cost):
        self.to = to
        self.rev = rev
        self.cap = cap
        self.cost = cost

def add_edge(g, u, v, cap, cost):
    g[u].append(Edge(v, len(g[v]), cap, cost))
    g[v].append(Edge(u, len(g[u]) - 1, 0, -cost))

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    size = 2 * n
    graph = [[] for _ in range(size)]

    def inn(x):
        return 2 * x

    def out(x):
        return 2 * x + 1

    INF = 10**9

    for i in range(n):
        add_edge(graph, inn(i), out(i), INF, -a[i])

    for _ in range(m):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        add_edge(graph, out(u), inn(v), c, 0)

    source = inn(0)
    sink = out(n - 1)

    ans = 0

    while True:
        dist = [10**18] * size
        inq = [False] * size
        parent = [(-1, -1)] * size

        dist[source] = 0
        q = deque([source])
        inq[source] = True

        while q:
            u = q.popleft()
            inq[u] = False
            for idx, e in enumerate(graph[u]):
                if e.cap and dist[e.to] > dist[u] + e.cost:
                    dist[e.to] = dist[u] + e.cost
                    parent[e.to] = (u, idx)
                    if not inq[e.to]:
                        inq[e.to] = True
                        q.append(e.to)

        if dist[sink] == 10**18:
            break

        flow = INF
        cur = sink
        while cur != source:
            u, idx = parent[cur]
            flow = min(flow, graph[u][idx].cap)
            cur = u

        cur = sink
        while cur != source:
            u, idx = parent[cur]
            e = graph[u][idx]
            e.cap -= flow
            graph[cur][e.rev].cap += flow
            cur = u

        ans -= dist[sink] * flow

    print(ans)

if __name__ == "__main__":
    solve()
```実装はフロー モデルに直接に従います。 の`add_edge`関数は前方エッジとその残留エッジの両方を作成します。これにより、最終的な答えが改善される場合は、後でパスを拡張して以前の選択を元に戻すことができます。 

グラフでは、元の頂点ごとに 2 つのインデックスが使用されます。 入力コピーから出力コピーへのエッジには報酬が格納され、元の道路は出力コピーと入力コピーを接続します。 開始ノードの報酬を収集する必要があるため、ソースはノード 1 の受信コピーです。 ノード n に到達すると、報酬を受け取った後にターンが完了することを意味するため、シンクはノード n の発信コピーです。 

SPFA ループは、残差グラフ内で最も安価な増強パスを見つけます。 グラフは残留エッジを持つフロー ネットワークを表し、アルゴリズムがそれらを自然に処理するため、ここでは負のエッジ コストは安全です。 容量は整数であるため、すべての増強は整数のターンを送信します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(F * V * E) | 各拡張では、残差グラフに対して SPFA を使用します。 総流量 F は、エッジ容量の合計によって制限されます。 |
 | スペース | O(V + E) | 分割グラフには、2 倍の数の頂点と、元のエッジと残りのエッジが含まれます。 |

 分割後の頂点の最大数はわずか 200 であり、エッジの数は少ないままであるため、最小コスト フローのアプローチは制限に問題なく適合します。

 ## 特殊なケース

 パスが繰り返される場合:```
2 1
5 7
1 2 3
```分割グラフには、コストを伴うノード 1 の報酬エッジが含まれています`-5`ノード 2 とコスト`-7`。 道路の容量は 3 なので、最小コスト フロー アルゴリズムは 3 つのユニットを送信します。 最終的な費用は、`-36`、正解は 36 になります。 

開始ノードの報酬の場合:```
3 2
10 1 1
1 2 1
2 3 1
```よくある間違いは、ノード 1 を離れた後のノードのみをカウントすることです。フローは次から始まります。`1_in`、ノード 1 の報酬エッジを横切り、パスを通過し続けます。 唯一可能なターンが収集されます`10 + 1 + 1 = 12`、これは意図したスコアと一致します。 

ボトルネックが枯渇した場合、残存グラフが重要になります。 初期の貪欲な選択によってより適切な配置が妨げられた場合、フローの実装によって作成された逆エッジにより、アルゴリズムは以前の選択をキャンセルしてフローのルートを変更できます。 これは、局所的に最適なパスのシーケンスではなく、全体的な最適化を可能にする特性です。
