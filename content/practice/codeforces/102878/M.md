 ## 解決策
 ## 問題の理解

 迷彩は白と黒のピクセルの長方形のグリッドとして表されます。 白いピクセルは別々のスポットを形成し、スポットは 4 つの直交する方向で黒いピクセルに完全に囲まれている場合にのみ再描画できます。 Long Long は、このように囲まれた白い斑点のうち、面積が を超えないものだけを塗り直すことができます。`d`。 タスクは、選択したスポットを黒いピクセルで埋めた後、最終的なグリッドを出力することです。 

グリッドの寸法は両方とも 1000 に達する可能性があるため、最大 100 万個のセルが存在する可能性があります。 グリッドを繰り返し検索したり、考えられるすべての領域をチェックしたりするソリューションは、すぐに遅くなりすぎます。 このサイズでは、意図したアプローチではすべてのセルを一定の回数だけ処理する必要があり、予想される複雑さは次のようになります。`O(n * m)`。 

主なトラップは、局所的に囲まれたピクセルと囲まれたスポット全体を混同することです。 ピクセルは、別のパスを介して外側に接する大きな白コンポーネントに属しながら、4 つの側面すべてに黒の隣接要素を持つことができます。 この決定は、個々のセルではなく、白セルの接続されたコンポーネントに対して行う必要があります。 

たとえば、次のことを考えてみましょう。```
3 3 1
###
#.#
###
```中央のセルは、領域のある囲まれた白いスポットです。`1`したがって、正しい出力は次のようになります。```
###
###
###
```ここでは、セルに 4 つの黒の隣接セルがあるかどうかだけをチェックする不用意な解決策は機能するかもしれませんが、複数の白のセルが接続されている場合は失敗する可能性があります。 

別のケース:```
5 5 3
#####
#...#
#.#.#
#...#
#####
```白い成分には面積がある`8`。 内部のいくつかのセルは黒いピクセルで囲まれていますが、コンポーネント全体は大きすぎるため、変更しないでください。 正しい出力は次のとおりです。```
#####
#...#
#.#.#
#...#
#####
```接続された白い領域ではなく、囲まれた個々のセルをペイントするソリューションでは、グリッドが誤って変更されてしまいます。 

## アプローチ

 直接的な総当たり手法では、すべての白いピクセルを検査し、検索を実行して囲まれているかどうかを判断し、その領域のサイズをカウントし、サイズが十分に小さい場合は再描画します。 すべての決定は実際の白色コンポーネントに基づいているため、これは正しいです。 ただし、100 万個のセルがそれぞれ独自の検索を開始すると、同じエリアを何度も横断することができます。 最悪の場合はこうなる`O((n * m)^2)`これはグリッド サイズの許容範囲をはるかに超えています。 

重要な観察は、すべての白い点が接続されたコンポーネントであるということです。 塗りつぶしでは、セルやコンポーネントが境界に接触しているかどうかなど、必要な情報がすでに正確に提供されています。 境界線に接するコンポーネントは開いており、再描画することはできません。 ステートメントによりスポットがグリッドの境界を越えないことが保証されるため、境界に触れないコンポーネントは完全に黒のピクセルで囲まれます。 

これにより、問題はすべての白いコンポーネントの単一の走査に変わります。 走査中に、1 つのコンポーネントに属するセルを収集します。 そのサイズが最大でも`d`そしてそれが外部に到達することは決してないので、それらの保存されたセルを黒に変換します。 

個々のコンポーネントを塗りつぶすだけで答えを決定できるため、総当り攻撃は機能しますが、同じ作業を繰り返すと失敗します。 各セルが正確に 1 つのコンポーネントに属しているという観察により、すべてのピクセルを 1 回処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n * m)^2) | O(n * m) | 遅すぎる |
 | 最適 | O(n * m) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドのすべてのセルを反復処理します。 未訪問の白いセルが見つかったら、そこから塗りつぶしを開始します。 
2. フラッドフィル中に、現在の白コンポーネントに属するすべてのセルを保存し、そのサイズをカウントします。 訪問したセルが外側の境界線上にある場合は、コンポーネントを開いているとマークします。 
3. 充填が完了したら、コンポーネント情報を確認します。 開いていない状態で、そのサイズが最大以下の場合`d`、保存されているすべてのセルを黒で再ペイントします。 
4. すべての白いコンポーネントが処理されるまで続行します。 

セルをすぐに再描画せずに保存する理由は、塗りつぶしが完了するまでコンポーネントが有効かどうかがわからないためです。 コンポーネントは開始セルの近くで囲まれているように見えますが、後で境界に到達することがあります。 

なぜ効果があるのか:

 すべての白いピクセルは 1 つの連結成分に属しているため、アルゴリズムは考えられるすべての再描画候補を 1 回だけ考慮します。 コンポーネントは境界に触れていない場合にのみ再描画できます。つまり、コンポーネントから出るすべてのパスが黒いセルに到達することを意味します。 エリア チェックはコンポーネント全体に対して実行されるため、アルゴリズムによってスポットが部分的に描画されることはありません。 したがって、ペイントされたすべてのセルは必要な条件を満たし、すべての有効なスポットがペイントされます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, d = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    visited = [[False] * m for _ in range(n)]
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '.' and not visited[i][j]:
                q = deque([(i, j)])
                visited[i][j] = True
                cells = []
                closed = True

                while q:
                    x, y = q.popleft()
                    cells.append((x, y))

                    if x == 0 or x == n - 1 or y == 0 or y == m - 1:
                        closed = False

                    for dx, dy in dirs:
                        nx, ny = x + dx, y + dy
                        if 0 <= nx < n and 0 <= ny < m:
                            if grid[nx][ny] == '.' and not visited[nx][ny]:
                                visited[nx][ny] = True
                                q.append((nx, ny))

                if closed and len(cells) <= d:
                    for x, y in cells:
                        grid[x][y] = '#'

    print("\n".join("".join(row) for row in grid))

if __name__ == "__main__":
    solve()
```外側のループは、すべてのセルが最大 1 つのフラッド フィルの開始点になることを保証します。 の`visited`配列が必要なのは、そうしないと同じ白いコンポーネントが繰り返し探索されてしまうためです。 

キューは、4 方向の隣接キューに対して幅優先検索を実行します。 コンポーネントの収集中、コードは座標のみを記録し、コンポーネントの分類が完了するまでペイントを遅らせます。 これにより、コンポーネントを変更する必要があるかどうかを知る前にコンポーネントを変更するというよくある間違いを回避できます。 

境界チェックでは次のように使用します。`0`そして`n - 1`行と`0`そして`m - 1`列用。 オープン スポットはこれらのセルを通じてのみ検出できるため、これら 4 つの条件のうち 1 つが欠けていると、誤った答えが生じる典型的な原因となります。 

可能なコンポーネントの最大サイズが 100 万にすぎないため、ここでは Python 整数にはオーバーフローの問題はありませんが、実装では依然として不必要な演算が回避され、必要な座標のみが保存されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m) | すべてのセルはフラッド フィルによって 1 回アクセスされ、一定の回数チェックされます。 |
 | スペース | O(n * m) | 訪問された行列と最大の保存されたコンポーネントには線形メモリが必要です。 |

 最大グリッドには 100 万個のセルが含まれるため、線形トラバースは意図した制限内に快適に収まります。 このアルゴリズムは再帰を回避し、大規模なコンポーネントでの Python 再帰の深さの問題を防ぎます。
