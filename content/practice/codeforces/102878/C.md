 ## 解決策
 ## 問題の理解

 それぞれが正の値を持つオブジェクトのリングがあります。 移動すると、まだ存在している 1 つのオブジェクトが削除されます。 その削除によって得られるスコアは、削除されたオブジェクトの現在の 2 つの隣接オブジェクトと、削除されたオブジェクト自体の値の積です。 2 つの隣接オブジェクトは、その時点で残っているリング内でそのすぐ隣にあるオブジェクトです。 1 つを除くすべてのオブジェクトが削除された後、最後に残ったオブジェクトが削除され、そのオブジェクト自体の値のみが提供されます。 目標は、合計スコアを最大化する除去順序を選択することです。 

入力により、オブジェクトの数と円の周囲に配置された値が与えられます。 出力は可能な最大の合計スコアです。 値は正であるため、すべての選択は、オブジェクトが近傍として残ることによってのみ将来の乗算に影響します。 この制約では最大 500 個のオブジェクトが許可されますが、可能なシーケンスの数は階乗的に増加するため、考えられるすべての削除命令を探索することができなくなります。 約 1 億 2,500 万の状態遷移が、厳密な実装に収まる範囲の上限であるため、O(n³) 程度の動的プログラミング ソリューションが必要です。 

主な難点は、この円には自然な始まりや終わりがないことです。 最初のオブジェクトを永続的な境界として扱う不用意な解決策は、どのオブジェクトも最終的に生き残る可能性があるため、可能な最適な順序を失います。 

たとえば、1 つのオブジェクトの場合:```
Input:
1
7

Output:
7
```唯一のオブジェクトが特別な最終ルールを使用して削除されるため、削除前に常に 2 つの隣接オブジェクトが存在する必要があると想定するソリューションは失敗します。 

もう 1 つの重要なケースは次のとおりです。```
Input:
4
1 2 3 4

Output:
84
```間違った場所で円を破り、1 つの直線配置だけを解決すると、最適な順序を逃す可能性があります。 円を使用すると、最後の生存者として選択されたオブジェクトがベスト カットを決定できます。 

3 番目のケースは値が繰り返される場合です。```
Input:
3
5 5 5

Output:
255
```答えは、1 つのオブジェクトを削除して 125 ポイント、2 つ目のオブジェクトを削除して 125 ポイント、最後のオブジェクトを削除して 5 ポイントから得られます。 誤って等しい値を同じ位置として扱う実装では、使用可能な選択肢が誤って減少する可能性があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての削除命令をシミュレートすることです。 最初の移動ごとに、オブジェクトを 1 つ削除し、円を更新してから、考えられるすべての次の移動を再帰的に試行します。 これは正しいです。すべての有効なゲームは、まさに 1 つの選択肢のシーケンスによって表されるからです。 ただし、n 個のオブジェクトの場合、最初のステップでは n 個の選択肢があり、2 番目のステップでは n-1 個というようになります。 次数はn!となり、小さな入力でも不可能になります。 

質問を変えることで有益な観察が得られます。 どのオブジェクトを最初に削除するかを決定するのではなく、より短い間隔内で最後に削除するオブジェクトを決定します。 これは、区間動的計画法の問題で使用される考え方の逆転と同じです。 

2 つのオブジェクトが境界として保持されている場合、厳密にそれらの間にあるオブジェクトは独立した部分問題を形成します。 オブジェクト k が境界 l と r の間で削除された最後のオブジェクトであると仮定します。 この時点で、k の近傍は正確に l と r であるため、この区間内の最後の演算により、a[l] × a[k] × a[r] のスコアが得られます。 k より前に削除されたものはすべて、2 つの小さな区間に属しており、独立して解くことができます。 

残る問題はサークルだけだ。 配列を複製し、考えられるすべての円形セグメントを通常の間隔に変換します。 最大 n までの長さのセグメントの間隔値を計算します。 最後に生き残るオブジェクトのあらゆる可能な選択は、これらの間隔の 1 つとして表示されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 円形配列がすべての位置の 2 つのコピーを含む線形配列になるように配列を複製します。 任意のサークル カットを長さ n の連続したセグメントで表すことができるようになりました。 
2. 定義する`dp[l][r]`l と r を境界として維持しながら、位置 l と r の間のすべてのオブジェクトを厳密に削除することによって得られる最大スコアとして。 この定義が機能するのは、間隔内の最後の削除には、これら 2 つの境界の間に隣接するものが両方なければならないためです。 
3. 境界間にオブジェクトがない間隔をゼロとして初期化します。 削除するものがないため、これらの状態はスコアに寄与しません。 
4. 長さを増やして間隔を処理します。 間隔ごとに`(l, r)`、最後に削除されたオブジェクトをすべて試してみます`k`彼らの間で。 候補スコアは、左側の部分の最良のスコア、右側の部分の最良のスコア、および最後に k を削除することによって得られるスコアです。 
5. すべての間隔を計算した後、倍増配列内の長さ n のすべてのセグメントを調べます。 各セグメントは、元の円上の 1 つの開始点を選択することに対応します。 最後に残ったオブジェクトの値 (カットに使用される境界) を加算し、最大値を取得します。 

それが機能する理由: すべての完全なゲームには、最終的に生き残るオブジェクトがあります。 そのオブジェクトを境界として想像すると、他のすべての削除は、そこにある円を切断することによって形成される間隔内で発生します。 任意の間隔内では、最後に削除されたオブジェクトによって残りの操作が 2 つの独立した間隔に分割され、再帰によってそのオブジェクトの可能な選択肢がすべてチェックされます。 すべての間隔内のすべての可能な最終生存者とすべての可能な最後の除去が考慮されるため、動的プログラムにはすべての有効なゲームが含まれ、互換性のない選択肢が結合されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print(a[0])
        return

    b = a + a
    m = 2 * n

    dp = [[0] * m for _ in range(m)]

    for length in range(2, n + 1):
        for l in range(m - length):
            r = l + length
            best = 0
            for k in range(l + 1, r):
                value = dp[l][k] + dp[k][r] + b[l] * b[k] * b[r]
                if value > best:
                    best = value
            dp[l][r] = best

    ans = 0
    for start in range(n):
        end = start + n
        ans = max(ans, dp[start][end] + b[start])

    print(ans)

if __name__ == "__main__":
    solve()
```複製された配列`b`ラップアラウンドネイバーの特別な処理の必要がなくなります。 で始まるセグメント`start`そして終わる`start + n`円全体を表す`start`最後の生き残りに選ばれる。 

テーブル`dp`2 つの境界が残っている区間のみを保存します。 トランジションでは、最後に削除されたオブジェクトをすべて試します。そのため、乗算では 2 つのエンドポイントと中間位置が使用されます。 

より大きな間隔はより小さな間隔に依存するため、間隔の長さのループは小さな範囲から開始されます。 最後のオブジェクトは通常の 3 オブジェクトの乗算スコアを受け取らないため、最終的な回答では生存者の値が個別に加算されます。 

Python の整数は、大きな値を安全に処理します。 多くの乗算項が蓄積されるため、最大スコアは 32 ビット整数の制限を超える可能性があります。

 ## 特殊なケース

 単一オブジェクトの場合、動的プログラミング テーブルは不要です。 唯一可能なアクションは最終的な削除であるため、アルゴリズムはオブジェクト自体の値を直接返します。 

2 つのオブジェクトの場合、3 番目の近傍を選択することはできません。 いずれかのオブジェクトを削除すると、最初に両方の値と残りのオブジェクトの積が得られ、その後に残りの値が続きます。 間隔 DP には中間オブジェクトの可能性が 1 つ含まれており、最後の生存者が後で追加されるため、実装はこれを自然に処理します。 

繰り返される値の場合、数値が同じであっても位置が重要になります。 二重化された配列によりすべての位置が分離されるため、動的プログラムは、等しいオブジェクトをまとめて折りたたむのではなく、考えられるすべての円形カットを探索します。 

円形境界の場合、2 倍の配列の長さ n の間隔をすべてスキャンすることによって、考えられるすべての生存者がテストされます。 最初の入力要素を生存者として固定する解決策は、これらの可能性の 1 つだけを評価することになり、最適なものを逃す可能性があります。
