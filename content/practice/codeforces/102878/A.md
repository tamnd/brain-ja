 ## 解決策
 ## 問題の理解

 タスクは、パリティが他のすべての数値と異なる単一の数値をリスト内で見つけることです。 入力は一連の整数を記述します。 1 つを除くすべての値は偶数または奇数のいずれかであり、残りの値は逆のパリティを持ちます。 出力は、元のシーケンス内の異なる値の 1 から始まる位置です。 

シーケンスのサイズは小さいですが、目的とするレッスンは実際に重要な情報を認識することです。 値自体は、2 で割り切れるかどうかを除いて無関係です。 すべての要素を一度検査するだけで済むため、リニア スキャンで十分です。 たとえシーケンスサイズが約3000まで大きくなったとしても$10^5$または$10^6$、$O(n)$このソリューションは通常の競技プログラミングの制限内に問題なく収まりますが、すべてのペアを比較するアプローチは不可能になります。$O(n^2)$操作。 

よくある間違いは、最初の値が多数派パリティを決定すると仮定することです。 たとえば、入力が次の場合:```
3
1 2 4
```正しい出力は次のとおりです。```
1
```最初の数は奇数で、他の 2 つは偶数です。 最初の要素のみに基づいて回答を初期化するメソッドは、過半数を適切にカウントまたは検証しないと失敗する可能性があります。 

もう 1 つのエッジ ケースは、最後に異常な値が表示される場合です。```
5
2 4 6 8 7
```正しい出力は次のとおりです。```
5
```最初のいくつかの値の間で一致するパリティを見つけた後、スキャンがあまりにも早く停止すると、答えが見つかりません。 

3 番目のケースは、最初の 2 つの数値が異なるパリティを持つ場合です。```
3
1 2 3
```正しい出力は次のとおりです。```
2
```ここでは、過半数のパリティは奇数であり、中央の値が唯一の偶数です。 最初の 2 つの要素が代表的であると仮定するアプローチでは、追加のチェックが必要です。 

## アプローチ

 ブルートフォースの方法は、すべての数値を他のすべての数値と比較し、そのパリティを共有する値の数を数えることです。 あるので$n$候補番号の選択肢と最大$n$各候補を比較すると、合計作業量は次のようになります。$O(n^2)$。 これは正しいです。固有の要素だけがパリティ数が他の要素と異なるためですが、繰り返しの比較は不要です。 

問題を単純にする観察は、パリティには 2 つの可能な状態しかないということです。 要素を相互に比較する必要はありません。 奇数がいくつ存在し、偶数がいくつ存在するかを知る必要があるだけです。 正確に 1 つの要素が異なるため、これらのカウントの一方は 1 になり、もう一方は次のようになります。$n-1$。 少数派パリティを識別した後、1 回のスキャンでそのパリティを持つ要素の位置が得られます。 

ブルートフォース ソリューションは、必要なプロパティを直接チェックするため機能しますが、同じパリティ チェックを何度も繰り返します。 考えられる 2 つのパリティ グループをカウントすると、すべての情報が 2 つのカウンタに圧縮され、問題が線形パスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 大きな入力には遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンス内の偶数の数と奇数の数を数えます。 過半数のカウントは通常の数値がどのパリティを持っているかを示し、小さいカウントは異常なパリティを識別します。 
2. スキャン中に最後の偶数と最後の奇数のインデックスを保存します。 これらの位置を維持すると、後で別のパスが必要になることを回避できます。 
3. 偶数と奇数のカウントを比較します。 偶数の数が少ない場合、答えは保存されている偶数の位置になります。 それ以外の場合、答えは保存された奇数の位置になります。 
4. 問題では位置に 1 から番号が付けられるため、1 から始まるインデックスを使用して選択した位置を出力します。 

これが機能する理由: 入力により、正確に 1 つの数値が異なるパリティを持つことが保証されます。 したがって、一度出現するパリティは答えのパリティでなければならず、もう一方のパリティは残りの要素ごとに出現します。 このアルゴリズムは、カウントによってこの少数パリティを識別し、そのグループに属する唯一のインデックスを返します。 すべての要素が 1 回だけカウントされ、考えられるすべてのパリティが考慮されるため、他のインデックスは条件を満たすことができません。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    even_count = 0
    odd_count = 0
    even_pos = -1
    odd_pos = -1

    for i, x in enumerate(a, start=1):
        if x % 2 == 0:
            even_count += 1
            even_pos = i
        else:
            odd_count += 1
            odd_pos = i

    if even_count == 1:
        print(even_pos)
    else:
        print(odd_pos)

if __name__ == "__main__":
    solve()
```スキャンでは、偶数値の数、奇数値の数、各タイプの最新の位置の 4 つの情報のみが保存されます。 パリティが決定された後は、正確な値が必要になることはありません。 

条件`even_count == 1`単一の異なる値が偶数である場合に、異常なグループを選択します。 それ以外の場合、この問題では例外が 1 つだけ保証されるため、単一の異なる値は奇数でなければなりません。 列挙は 1 から開始されるため、保存された位置はすでに 1 ベースになっており、最後のインデックス付けの修正が回避されます。

 最初の例の場合:```

 奇数が 1 つだけあるため、アルゴリズムは位置 3 を出力します。これは、値自体は重要ではなく、そのパリティ グループのみが重要であることを示しています。 

2 番目の例の場合:```
4

```スキャンは次のように動作します。 

| インデックス | 値 | 偶数カウント | 奇数の数 | 偶数位置 | 奇数の位置 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての数値はパリティをカウントするために 1 回検査されます。 |
 | スペース | お(1) | カウンタと 2 つのポジションのみが保存されます。 |

 このアルゴリズムは要素ごとに一定量の作業のみを実行するため、入力サイズに応じて線形にスケールします。 メモリ使用量は、入力が読み取られた後のシーケンスの長さに依存しません。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    even_count = 0
    odd_count = 0
    even_pos = -1
    odd_pos = -1

    for i, x in enumerate(a, start=1):
        if x % 2 == 0:
            even_count += 1
            even_pos = i
        else:
            odd_count += 1
            odd_pos = i

    ans = even_pos if even_count == 1 else odd_pos

    sys.stdin = old_stdin
    return str(ans) + "\n"

assert solution("5\n2 4 7 8 10\n") == "3\n", "sample 1"
assert solution("4\n1 2 1 1\n") == "2\n", "sample 2"

assert solution("3\n2 4 1\n") == "3\n", "single odd value"
assert solution("3\n7 8 10\n") == "1\n", "single odd value at start"
assert solution("7\n6 2 4 8 12 14 3\n") == "7\n", "single odd value at end"
assert solution("5\n1 3 5 8 7\n") == "4\n", "single even value"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / 2 4 1`|`3`| 異なるパリティが最後に表示されます。 |
 |`3 / 7 8 10`|`1`| 異なるパリティが先頭に表示されます。 |
 |`7 / 6 2 4 8 12 14 3`|`7`| 遅い例外を除いて大多数のグループ。 |
 |`5 / 1 3 5 8 7`|`4`| 単一の偶数値の場合。 |

 ## 特殊なケース

 異常な数値が最初の要素である場合:```
3
7 8 10
```このアルゴリズムは、2 つの偶数と 1 つの奇数を数えます。 偶数カウントは 1 ではないため、保存されている奇数の位置、つまり 1 が選択されます。最初の値が過半数を確立しないという事実を正しく処理します。 

異常な番号が最後にある場合:```
5
2 4 6 8 7
```スキャンでは 4 つの偶数値と 1 つの奇数値が記録されます。 保存された奇数の位置は 5 になり、アルゴリズムはフル スキャン後にそれを返します。 それはシーケンスに関する初期の仮定に依存しません。 

最初の 2 つの値のパリティが異なる場合:```
3
1 2 3
```最終的なカウントは、2 つの奇数と 1 つの偶数です。 アルゴリズムは、保存されている偶数の位置、つまり 2 を選択します。大部分は、最初のいくつかの要素ではなく完全なカウントから検出され、早すぎる推測というよくある間違いを回避します。
