 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点。 ゲームは 2 人のプレイヤーがツリー上で順番にエッジを削除してプレイします。 エッジが削除された後、「固定された」頂点を含まない接続されたコンポーネントは完全に破棄されます。 最初に行動できなかったプレイヤーが負けとなります。 工夫すべき点は、固定された頂点のセットが次のように変更されることです。$k$から$1$に$n$、頂点のみ$1, 2, ..., k$固定されています。 それぞれについて$k$、両方のプレイヤーが最適にプレイした場合にどちらが勝つかを判断する必要があります。 

入力は頂点の数で構成されます$n$に続く$n-1$ツリーを定義するエッジ。 出力は長さの文字列です$n$どこで$i$-番目の文字は`1`最初のプレイヤーが最初のゲームで勝った場合$i$頂点が固定されている、または`2`さもないと。 

制約は重要です。$n$まで可能です$3 \cdot 10^5$したがって、すべての可能なエッジ削除を反復するソリューションは、$k$遅すぎるでしょう。 ツリーの場合、ブルートフォース手法では、考えられるすべての一連の動きを調べる必要があり、これは指数関数的です。$n$。 それぞれのエッジを単純に処理することも可能$k$おおよそにつながります$O(n^2)$実行不可能な操作です。 

エッジケースは微妙です。 もし$k = 1$、固定された頂点は葉である可能性があり、ゲームを単一のパスに沿って強制します。 もし$k = n$、すべての頂点が固定されているため、明示的に削除されるまですべてのエッジが残ります。 サイズ 1 または 2 の小さなツリーは、インデックス作成やゼロ移動エラーを避けるために慎重に扱う必要があります。 さらに、固定されていない頂点によって引き起こされる切断されたサブツリーは正しく無視する必要があります。無視しないと、グランディ値の計算が不正確になります。 

## アプローチ

 ブルートフォース手法では、考えられる各ゲーム状態を再帰的に考慮します。 エッジが残っている各サブツリーにラベルを付け、そのノードでのゲームの番号 (グランディ数) を計算できます。 すべてのアクティブなコンポーネントの数値の XOR がゼロ以外の場合、最初のプレーヤーが勝ちます。 これが機能するのは、ツリー上のエッジ削除ゲームが独立した番号の合計に等しいためです。 問題は、すべての場合に番号を再計算することです。$k$独立して$O(n^2)$の制限時間を超えます。$n = 3 \cdot 10^5$。 

重要な洞察は、ツリー構造が静的であり、固定された頂点を段階的に追加するだけであるということです。 サブツリー内の単一のピン留めされた頂点の場合、番号は、その頂点からピン留めされた祖先までのパスに沿ったエッジのパリティによって決まります。 新しいピン留めされた各頂点は、それ自体からルートに向かうパスにのみ影響するため、ツリー全体をそれぞれの頂点ごとに再計算するのではなく、変更を段階的に伝播することができます。$k$。 これにより、各頂点の数を計算するルートからの単一の DFS に問題が軽減され、その後、ゲームの XOR を動的に計算するために固定された頂点にわたるプレフィックスが蓄積されます。 

アプローチを要約すると次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 増分グランディ伝播 | O(n) | O(n) | 承認済み |

 最適な解決策は、番号と、新しく固定されたノードからルートまでのパスに沿った頂点のみが XOR を変更できるという観察を活用します。 これにより、すべてが許可されます$k$結果は線形時間で計算されます。 

## アルゴリズムのチュートリアル

 1. ツリーを読み取り、各頂点の隣接リストを作成します。 ツリーにはルートがありませんが、簡単にするために頂点 1 をルートとして扱うことができます。 
2. 配列を初期化する`degree`各頂点の子の数を保存します。 リーフ ノードはゲームの番号に寄与しますが、内部ノードの番号は子番号の XOR です。 
3. ルートから DFS を実行して、すべてのノードが固定されていると仮定して、すべての頂点の初期番号値を計算します。 各頂点の番号は次の XOR です。`(nimber of child + 1)`すべての子供たちのために。 の`+1`頂点を子に接続するエッジを表します。 
4. 固定された頂点のセットに沿った数値の累積 XOR を維持します。 頂点 1 から始めて、頂点 2 から n まで徐々に含めます。 各ステップで、XOR はピン留めされたすべてのコンポーネントの数値の合計を表します。 
5. 現在の累積 XOR がゼロ以外の場合、最初のプレーヤーが勝利戦略を持っています。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 これを次のように記録します`1`または`2`出力文字列に含まれます。 
6. すべての頂点を処理した後、出力文字列を出力します。 

機能する理由: このゲームは公平な組み合わせゲームです。 多数の独立コンポーネントの XOR によって、どのプレイヤーが勝利戦略を持っているかが完全に決まります。 固定された頂点を段階的に追加することで、ツリー全体を最初から再計算することなく、各ステップでアクティブなコンポーネントごとに正しい数値を計算できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

n = int(input())
tree = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    tree[u].append(v)
    tree[v].append(u)

nimber = [0] * (n + 1)

def dfs(u, p):
    res = 0
    for v in tree[u]:
        if v != p:
            res ^= dfs(v, u) + 1
    nimber[u] = res
    return res

dfs(1, 0)

result = []
cumulative_xor = 0
for i in range(1, n + 1):
    cumulative_xor ^= nimber[i]
    result.append('1' if cumulative_xor != 0 else '2')

print(''.join(result))
```DFS はルートから番号を計算します。 の`+1`XOR の内側は、親と子の間のエッジを表します。 ピン留めされた頂点間の累積 XOR によって勝者が決まります。 頂点を 1 から n まで段階的に追加することで、問題のプログレッシブ ピンニングが確実に尊重されます。 

微妙な点としては、深いツリーに対して大きな再帰制限を使用すること、循環を回避するために DFS での親追跡を確実にすること、および`+1`エッジを数値として正しく表現します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    tree = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        tree[u].append(v)

        res = 0
        for v in tree[u]:
            if v != p:

        nimber[u] = res
        return res
    dfs(1, 0)
    result = []
    cumulative_xor = 0
    for i in range(1, n + 1):
        cumulative_xor ^= nimber[i]
        result.append('1' if cumulative_xor != 0 else '2')
    return ''.join(result)
