 ## 解決策
 ## 問題の理解

 配列が与えられ、非常に特殊なタイプの変換を実行できます。値を 1 つ選択できます。`x`そして、その値の出現箇所を配列から削除します。必ずしもすべてを削除する必要はありません。 削除後、残りの要素はまとめて折りたたまれ、結果のシーケンスが回文であるかどうかを確認します。 

タスクは、少なくとも 1 つの選択肢が存在するかどうかを判断することです。`x`この操作により配列を回文にすることができます。 最終出力で削除を明示的に構築する必要はなく、それが可能かどうかを答えるだけです。 

この制約により、最大 10^4 のテスト ケースが許可され、すべてのテストにわたる配列の合計長は最大 2 × 10^5 になります。 これは、テストごとに O(n^2) であるか、テストごとに線形よりも悪いものは安全ではないことを直ちに意味します。 どのようなソリューションでも、場合によっては少数の線形スキャンで、各テストを線形時間で効果的に処理する必要があります。 

素朴なアプローチでは、考えられるすべての値を試します。`x`を削除して、結果の配列が回文であるかどうかを確認します。 最悪の場合、テストごとに O(n^2) になりますが、値が頻繁に繰り返される場合、これでは遅すぎます。 

より微妙な失敗例は、配列がほぼ回文であるにもかかわらず、多くの位置で出現する値を削除する必要がある場合に発生します。 最初に見つかった不一致値を削除する貪欲な削除の試みは失敗します。`x`ローカルではなくグローバルです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。配列内の個別の値ごとに、その値の出現箇所をすべて削除することをシミュレートし、結果の配列が回文であるかどうかを確認します。 各チェックのコストは O(n) で、O(n) 個の個別の値が存在する可能性があるため、合計コストは O(n^2) になります。 これはすぐに制約を破ります。 

重要な観察は、有効なソリューションの構造が元の配列の不一致によって大きく制約されていることです。 2 つのポインターを使用した標準的な回文チェックから始めます。 配列がすでに回文である場合は、作業は完了です。 それ以外の場合は、値が異なる左右の最初の位置を見つけます。 この時点で、有効な解決策は、不一致に関係する左の値または右の値のいずれかをすべて削除する必要があります。これは、その位置で競合を排除できる可能性のある候補がこれらのみであるためです。 

これにより、問題は最大 2 つの候補をテストするだけになります。 各候補値について、その値が出現するたびにスキップしながら、2 ポインター回文チェックをシミュレートします。 どちらかのシミュレーションが成功すると、配列は kalindrome になります。

 |---|---|---|---|
 | すべての x に対するブルート フォース | O(n^2) | O(n) | 遅すぎる |
 | ツーポインタ候補チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列の終端にある 2 つのポインターから始めます。 値が一致している間、それらを内側に移動します。 中央に到達すると、配列はすでに回文になります。 

位置の不一致が発生した場合`l`そして`r`、可能な唯一の修正は、発生したすべてのを削除することです。`a[l]`またはすべての発生`a[r]`。 両方のオプションを個別にテストします。 

候補値をテストするには`x`、ここでも 2 つのポインターを使用します。 私たちが見るたびに`x`、ポインタを内側に移動してスキップします。 それ以外の場合は、通常どおり比較します。 いずれかの時点でスキップされていない値が一致しない場合、この候補は不合格になります。 

どちらかの候補が成功した場合は YES を返します。 

これが機能する理由は、2 ポインター スキャンの最初の不一致によって、対称性が崩れる正確な領域が特定されるためです。 有効な解決策では、競合する 2 つの値のうちの 1 つを削除する必要があります。削除しないと、配列の縮小バージョンごとに不一致が残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_pal_after_removal(a, x):
    l, r = 0, len(a) - 1
    while l < r:
        while l < r and a[l] == x:
            l += 1
        while l < r and a[r] == x:
            r -= 1
        if l >= r:
            break
        if a[l] != a[r]:
            return False
        l += 1
        r -= 1
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        l, r = 0, n - 1
        
        while l < r and a[l] == a[r]:
            l += 1
            r -= 1
        
        if l >= r:
            print("YES")
            continue
        
        x, y = a[l], a[r]
        
        if is_pal_after_removal(a, x) or is_pal_after_removal(a, y):
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```最初の不一致を特定した後、コードは有効なソリューションの構造に影響を与える可能性のある 2 つの値を正確に分離します。 ヘルパー関数は、フィルター処理された回文チェックを線形時間で実行し、1 つの候補値を完全にスキップします。 これにより、配列の再構築が回避され、メモリ使用量が一定に保たれます。 

微妙な点は、部分的な出現を恣意的に削除しようとしていないことです。 スキップ ロジックにより、問題の定義と一致する順序を維持しながら、選択的な削除が暗黙的に可能になります。 

## 実用的な例

 次の入力を考えてみましょう。```
5
1 4 4 1 4
```最初の 2 ポインター スキャンでは 1 と 4 が比較されますが、これらはすぐに不一致になります。 ということで候補は1と4です。 

1 の除去をテストすると、回文である [4, 4, 4] が得られます。 

4 の除去をテストすると [1, 1] が得られますが、これも回文です。 

アルゴリズムは正しく YES を返します。 

次に、次のことを考えてみましょう。```
3
1 2 3
```最初の不一致は、両端 (1 と 3) ですぐに発生します。 1 だけを削除すると、回文ではなく [2, 3] が得られます。 3 つだけを削除すると [1, 2] が得られますが、これも回文ではありません。 アルゴリズムは正しく NO を返します。

 ## 特殊なケース

 重要なエッジ ケースは、配列がすでに回文になっている場合です。 その場合、不一致ポインタが分岐することはなく、アルゴリズムは削除候補をテストすることなく早期に正しく終了します。 これにより、不必要な計算が防止され、偽陰性が回避されます。 

もう 1 つの特殊なケースは、すべての要素が同一である場合です。 不一致ループは決してトリガーされず、削除しても回文または空の配列が残るため、答えはすぐに「YES」になります。
