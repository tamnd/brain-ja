 ## 解決策
 ## 問題の理解

 各人が自分のインデックスに等しい固定資産を持っている人々のコレクションが与えられました。つまり、人 1 は 1 ドル、人 2 は 2 ドルというように、n まで続きます。 これらの人々の一部を選択してパーティーに招待したいと考えています。 

人にはそれぞれ 2 つの制約があります。 i 人が招待された場合、招待されたゲスト全員の中に自分より裕福な人が多くても a_i 人、自分より貧しい人が多くても b_i 人いる場合にのみ出席に同意します。 富はインデックスに厳密に関連付けられているため、選択したサブセット内で「より裕福である」ということはより高いインデックスを意味し、「より貧しい」ということはより低いインデックスを意味します。 

タスクは、最終的に選択されたセットに関して、すべての招待者が両方の制約を満たすように、招待者の数を最大化することです。 

重要な問題は、各人の状態がその人個人だけではなく、選択したサブセットの全体的な構造に依存することです。 1 人の人物を追加または削除すると、複数の制約が一度に無効になる可能性があります。 

この制約により、テスト ケース全体で n が最大 2×10^5 まで許可され、すべてのサブセットを試行するアプローチが除外されます。 サブセットの列挙は指数関数的になるため、候補ごとに二次チェックを行っても遅すぎます。 We need something around O(n log n) or O(n).

 微妙なエッジケースは対称的な制約から生じます。 たとえば、ある人は多くの裕福な人々を許可するが、貧しい人々はほとんど許可しない場合や、その逆の場合も同様です。 インデックスの昇順で貪欲に人物を選択すると、後の要素の「貧弱な」制約に簡単に違反してしまう可能性があります。 逆に、制約のみによって任意に選択すると失敗する可能性があります。これは、実現可能性が絶対数ではなくサブセットの最終的なサイズに依存するためです。 

## アプローチ

 ブルートフォースのアイデアは、人々のすべてのサブセットを試し、各サブセットについて、選択されたすべての人々がそのサブセットに配置されたときに制約を満たすかどうかを確認することです。 固定サブセットの場合、各人 i について、選択されたインデックスが i より小さいか大きいものがいくつあるかを計算し、a_i と b_i を検証できます。 このチェックは慎重に実行すればサブセットあたり O(n) ですが、サブセットが 2^n あるため、合計は完全に不可能になります。 

重要な観察は、最終グループのサイズを k にすでに固定している場合、選択された各個人 i はサイズ k の線形順序のどこかに配置される必要があり、正確にいくつかの位置がその前後にあるということです。 選ばれた人々をインデックスによって並べ替えることを想像すると、人 i の場合、貧しい人の数はその並べ替えられたサブセット内での位置であり、より裕福な人の数は k からその位置を引いた 1 になります。 

したがって、サブセットサイズ k を決定する場合、実際には、k 個のインデックスを選択して、選択された各 i が p ≤ b_i および k−1−p ≤ a_i を満たす位置 p を占有することができるように、それらに位置 0 から k−1 を割り当てることができるかどうかを尋ねることになります。 これは p に対する区間制約になります。p は [k−1−a_i, b_i] 内になければなりません。 

したがって、各人は、サイズ k のサブセット内で占めることができる有効な位置の範囲を定義します。 問題は、k 人を k のポジションに割り当てて、各人に許容される間隔内で個別のポジションを割り当てることができるかということです。 これは、間隔に関する古典的な貪欲な実行可能性チェックです。 

サイズ k の有効なセットを構築できれば、要素を削除することでさらに小さいサイズも可能になるため、k を二分探索できます。 

固定 k の場合、区間の左端ですべての人々を並べ替え、0 から k−1 までの位置に貪欲に割り当て、常に最も早い有効な候補者を選択します。 ソートされた候補に対するポインタと、利用可能な適切なエンドポイントに対する最小構造を維持します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | Binary Search + Greedy | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 範囲 [0, n] にわたる二分探索を使用して候補解答 k を決定します。 目的は、サイズ k の有効なグループを構築できるかどうかをテストすることです。 有効な構成から人を削除すると有効性が維持されるため、単調性が維持されます。 
2. 各人 i について、サイズ k のグループに含まれる場合の有効な位置の範囲を計算します。 貧しい人々に対する制約から、彼らの位置 p は p ≤ b_i を満たさなければなりません。 より裕福な人々から見ると、p は k−1−p ≤ a_i を満たす必要があり、p ≥ k−1−a_i となります。 したがって、各人は区間 [L_i, R_i] = [k−1−a_i, b_i] を寄与します。 
3. 間隔が無効である人、つまり L_i > R_i を持つ人はすべて破棄します。そのような人はこの k の有効な割り当てに含めることができないためです。 
4. 残りの間隔を L_i でソートします。 0 から k−1 までの位置の割り当てを昇順にシミュレートします。 
5. 位置 p を 0 から k−1 まで繰り返します。 各ステップで、L_i ≤ p であるすべての区間を利用可能な候補のプールに追加します。 これらは、潜在的にポジション p を占める可能性のある人々です。 
6. 利用可能なすべての候補の中から、R_i が最小のものを選択します。 これは、将来のポジションに対する柔軟性を保つため、非常に重要です。 R_i が小さい人は将来の機会が少ないため、早期に割り当てることで実現可能性が妨げられることを回避できます。 
7. いずれかの時点で位置 p に利用可能な候補がない場合、サイズ k は不可能であると結論付けます。 
8. 0 から k-1 までのすべての位置が正常に埋められた場合、k は実行可能です。 

二分探索では、この実現可能性チェックを使用して最大 k を見つけます。 

### なぜ効果があるのか

 正確さは、標準的な貪欲マッチングの不変式に依存します。つまり、すべての位置 p で、割り当てが可能であれば、最小の右端点を持つ利用可能な間隔を選択しても、割り当てが完了する可能性が低下することはありません。 より大きな右端点を以前に使用する代替割り当ては、将来の配置をより厳しく制限することしかできません。これは、将来の位置には十分に右に広がる間隔が必要であるためです。 これにより、貪欲な手順が、位置と間隔制約の間の完全な一致の存在を確認することと同等であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, arr):
    intervals = []
    for a, b in arr:
        l = k - 1 - a
        r = b
        if l <= r:
            intervals.append((l, r))
    if len(intervals) < k:
        return False

    intervals.sort()
    import heapq

    heap = []
    i = 0
    n = len(intervals)

    for p in range(k):
        while i < n and intervals[i][0] <= p:
            heapq.heappush(heap, intervals[i][1])
            i += 1

        while heap and heap[0] < p:
            heapq.heappop(heap)

        if not heap:
            return False

        heapq.heappop(heap)

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = [tuple(map(int, input().split())) for _ in range(n)]

        lo, hi = 0, n
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, arr):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```中心となる変換は、「より豊かな制約」と「より貧弱な制約」から、仮説的なソートされたサブセット内の位置間隔制約への変換です。 二分探索では、この実現可能性チェックをラップして、可能な最大のサブセット サイズを見つけます。 

内部`can(k, arr)`、推論で導き出されたとおりに各間隔を正確に計算します。 この k の間隔が存在しない人は、有効な取り決めに参加できないため、自動的に除外されます。 

ヒープにより、現在の位置の最小の正しい境界を持つ参加者が常に選択されることが保証されます。これは、将来の実現可能性を維持する貪欲な選択です。 

二分探索ループはこのチェッカーを繰り返し呼び出して、効率的に答えを絞り込みます。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
(1,2), (2,1), (1,1)
k = 2 check
```k = 2 の間隔を計算します。 

| 人 | | b | L = k−1−a | R = b | 間隔 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 0 | 2 | [0,2] |
 | 2 | 2 | 1 | -1 | 1 | [-1,1] |
 | 3 | 1 | 1 | 0 | 1 | [0,1] |

 位置 0 と 1 を割り当てようとします。 

p = 0 では、3 つすべてが利用可能です。 最小の R を持つ区間、つまり人物 3 ([0,1]) を選択します。 

p = 1 の場合、残りの間隔には [0,2] と [-1,1] が含まれます。 どちらも有効です。 [-1,1] を選択します。 

代入は成功したため、k = 2 が実現可能です。 

これは、貪欲な戦略が最初に厳しい制約を尊重し、実現可能性を維持していることを裏付けています。 

### 例 2

 入力:```
n = 2
(0,0), (0,1)
k = 2 check
```間隔:

 | 人 | | b | Ｌ | R | 間隔 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 0 | 無効 |
 | 2 | 0 | 1 | 1 | 1 | [1,1] |

 有効な候補者は 1 人だけ残っているため、2 つのポジションを割り当てることはできません。 アルゴリズムは k = 2 を正しく拒否します。 

これは、実行不可能な参加者が即座に除外され、マッチングが歪められないことを示しています。

 ## 特殊なケース

 重要なエッジケースは、多くの参加者が非常に制限的な b_i 値を持っており、早期ポジションを強制される場合です。 たとえば、数人が最大 0 人の貧しい人々のみを許可する場合、全員がポジション 0 を必要とし、これは 1 つの選択を超えることは不可能です。 間隔の構築により、これが 0 で重なる右側のエンドポイントに変換され、2 番目のそのような間隔が必要な最初の割り当てでヒープが失敗します。 

もう 1 つのエッジ ケースは、ある人の a_i が大きくても b_i が非常に小さい場合に発生します。つまり、多くの裕福な人々を許容できるが、順序付けの早い段階で出現する必要があることを意味します。 右エンドポイントが小さいため、アルゴリズムは自然にそれらを優先します。そのため、それらは早期に選択され、後のポジションをブロックしません。 

最後のケースは、k が大きいが、変換後に多くの区間が無効になる場合です。 小切手`l <= r`は、そのような候補を直ちに削除し、二分探索が生のカウントだけから実現可能性を誤って仮定しないようにします。
