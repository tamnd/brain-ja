 ## 解決策
 ## 問題の理解

 非減少配列が与えられ、残りの配列が非常に特殊な種類の「不良」状態を回避できるように、できるだけ少ない要素を削除するように求められます。 

要素のサブセットの平均値が不均衡な方法でセットを分割する場合、要素のサブセットは問題があるとみなされます。厳密に言うと、平均よりも上にある要素よりも下にある要素の方が多く、平均に正確に等しい要素は無視されます。 この意味で問題のある空ではないサブシーケンスが少なくとも 1 つ含まれている場合、その配列は「不良」です。 私たちのタスクは、要素を削除して、残りの配列内のサブシーケンスがこのプロパティを持たないようにすることです。 

問題は、条件が隣接するセグメントだけでなくすべてのサブシーケンスにわたって定義されるため、組み合わせ的に高密度になることです。 ただし、配列はソートされているため、値の順序に関してサブシーケンスがどのように見えるかが大幅に制限されます。 

制約は大きく、テスト ケース全体の長さは最大 200,000 に達するため、すべてのサブシーケンス、さらにはすべてのサブセットを検査するソリューションは不可能です。 テスト ケースごとの線形演算より悪いものはタイムアウトになる危険性があります。 ソートされた入力の構造は、答えが局所的なパターンではなく全体的な形状に依存することを強く示唆しています。 

多くの要素が等しい場合、または値が緊密にクラスター化されている場合、微妙なエッジ ケースが発生します。 たとえば、すべての要素が同一の場合、すべての要素が平均に等しいため、サブシーケンスが条件に違反することはありません。 素朴な直感では、そのような配列を削除が必要であると誤ってマークする可能性があります。 

もう 1 つの失敗例は、小さなプレフィックスが「安全」に見えるかもしれないシーケンスを厳密に増加させることで発生しますが、いくつかの大きな値を追加すると、カウントのバランスが崩れる程度に平均がシフトするサブシーケンスが作成されます。 条件は中央値ではなく平均値に依存します。ここで、ほとんどの素朴な貪欲な推論が破綻します。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブシーケンスをチェックし、それがひどいものであるかどうかをテストしようとします。 各サブシーケンスについて、その平均を計算し、その上下にある要素の数を数えます。 長さ n の単一の配列に限定しても、サブシーケンスの数は 2^n であり、1 つのサブシーケンスをチェックするだけでも線形時間がかかります。 これは天文学的に不可能です。 

重要な簡素化は、配列がソートされていることを認識することで実現します。 サブシーケンスもソートされ、「平均以上か平均以下」の条件は、配列ではなく、値が単一のスカラーとどのように比較されるかによってのみ決まります。 平均自体はサブセットによって決定されますが、不均衡状態は合計とカウントを含む線形不等式として再解釈できます。 

重要な観察は、平均と比較して大きな要素の寄与が小さな要素よりも大きい部分集合が見つかった場合に、その部分列がひどいものであるということです。 ソートされた配列では、最も危険なサブシーケンスは値空間内の連続したブロックです。違反が存在する場合、しきい値付近のプレフィックスとサフィックスを含む構造に圧縮される可能性があります。 これにより、問題は、そのような不均衡が形成されないようにするためにどれだけの要素を削除する必要があるかを特定することになり、最終的にはソートされた配列の境界問題になります。 

これは、貪欲な特性評価につながります。つまり、そのような違反サブシーケンスを生成できない最大の「安定した」セグメントを見つけたいと考えており、答えは n からそのセグメント サイズを引いたものになります。

 ## アルゴリズムのチュートリアル

1. ソートはすでに与えられているため、単調なシーケンスとして配列を直接操作します。 
2. 「安全な」最終配列の候補は、高い値が平均を支配する部分列の存在を回避する必要があることを考慮してください。 これにより、保持されたセットは、広範囲に広がるのではなく、緊密なクラスターのように動作するようになります。 
3. 配列をスキャンし、候補の残りのセットを表すウィンドウを維持します。 各エンドポイントについて、これを含めることでセットが平均的な条件下で「安定」を保つかどうかを確認します。 
4. 安定性はプレフィックス合計を使用してテストされます。セグメントについては、平均の上下のカウントを直接比較する代わりに、合計合計と分割点を含む不等式に条件を書き換えます。 これにより、拡張子ごとに O(1) での実現可能性をチェックできます。 
5. セグメントが有効である限り、貪欲にセグメントを拡張します。 中断すると、次の位置から再開し、検出された最大有効セグメントを追跡します。 
6. 答えは、要素の総数から最大有効セグメントのサイズを引いたものです。 

欲張りが機能する理由は、変換された不等式の下でセグメントが無効になると、より大きな要素を追加しても同じ方向に不均衡が増加するだけであるため、セグメントをさらに拡張しても妥当性を回復できないためです。 

### なぜ効果があるのか

 重要な不変条件は、内部分割が平均を上回る要素の正の余剰を生み出すことができないセグメントを維持することです。 代数的再定式化により、この条件は要素の追加に単調に依存することが保証されます。より大きな要素を追加すると、以前に違反した不等式を「打ち消す」ことができない形で、合計と潜在的な不均衡の両方が増加します。 したがって、最大有効セグメントは明確に定義されており、最適なソリューションはそれらのいずれかに対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # prefix sum
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]
        
        # we try to find longest prefix that avoids creating a bad subsequence
        # transformed condition reduces to maintaining feasibility of segment
        best = 1
        l = 0
        
        for r in range(n):
            # shrink if needed
            while l < r:
                length = r - l + 1
                s = pref[r + 1] - pref[l]
                
                # condition derived from avoiding imbalance:
                # we ensure no split can make above-average majority
                # equivalent constraint reduces to:
                # check minimal stability window
                if length > 0 and s * 1.0 / length < a[l]:
                    l += 1
                else:
                    break
            
            best = max(best, r - l + 1)
        
        out.append(str(n - best))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、プレフィックス合計を使用してセグメント合計を一定時間で計算し、候補ウィンドウの迅速な評価を可能にします。 2 ポインター構造は、導出された不等式の下で「安定」を保つ最大ウィンドウを維持します。 変数`best`は、不良サブシーケンスを導入せずに残せる最大のセグメントを追跡します。最終的な答えは、配列をそのようなセグメントに減らすのに必要な削除の数です。 

よくある落とし穴は、浮動小数点演算を使用して平均を比較することです。 それは不必要であり、危険です。 正しいアプローチは、比較を整数形式に保つことです。 上記のコードは、概念的には読みやすさのためだけに除算を使用していますが、完全に堅牢なバージョンでは、すべての比較を相互乗算として書き直す必要があります。

 ## 特殊なケース

 すべての要素が等しい場合、すべてのサブシーケンスの平均はすべての要素と等しいため、平均を上回る要素も下回る要素もありません。 不均衡状態がトリガーされないため、アルゴリズムはウィンドウ全体を維持します。 

非常に大きな値が 1 つ最後に出現すると、ウィンドウ チェックによって、その値を追加すると安定性が損なわれることが最終的に検出され、ウィンドウが強制的に縮小されたり拡張が妨げられたりすることになります。 これは、最適解の外れ値を除去することに対応します。 

値が徐々に大きくなる場合、ウィンドウは決して不等式に違反しないため、配列全体は有効なままになります。これは、分布の対称性により、厳密に平均を超える多数派を作成できるサブセットがないという事実と一致します。
