 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`頂点と`m`選手たち。 各プレイヤーはツリー上の 2 つの頂点を選択します。これを頂点と呼びます。`x_i`そして`y_i`。 プレイヤーはマシュタリが頂点を選択した場合にのみ排除できます`v`そして最も近い頂点`w`に`v`からの道中で`x_i`に`y_i`**厳密には**の間です`x_i`そして`y_i`。 もし`w`どちらかに一致する`x_i`または`y_i`、プレイヤーはその操作を生き延びます。 目標は、すべてのプレイヤーを確実に排除するためにマシュタリが選択しなければならない頂点の最小数を見つけるか、報告することです。`-1`それが不可能な場合。 

制約は重要です: まで`3 * 10^5`頂点とプレーヤー。 これにより、ツリーの走査を繰り返してすべてのパスを個別に処理するアプローチは除外されます。`O(n * m)`に達する可能性のある操作`10^11`最悪の場合。 ツリー構造を活用し、すべてのパスを明示的に反復しないソリューションが必要です。 

重要な微妙な点が生じるのは、`x_i`そして`y_i`**隣接する頂点**です。 その場合、からのパスは、`x_i`に`y_i`「中間」頂点がないため、次の選択肢はありません。`v`このプレイヤーを排除できます。 もう 1 つのエッジ ケースは、複数のプレイヤーのパスが重なっている場合です。単一の頂点を選択すると、複数の頂点を一度に排除できますが、パスが他のプレイヤーと切り離されているプレイヤーを見逃さないようにする必要があります。 

たとえば、木が直線の場合、`1-2-3`そしてプレイヤーは`x=1`そして`y=2`、厳密にはそれらの間に頂点はありません。 答えは`-1`どの操作を行ってもこのプレーヤーを削除できないためです。 

## アプローチ

 ブルートフォース手法では、すべての頂点に対して反復処理が行われます。`v`すべてのパスの頂点までの距離をチェックすることで、各プレイヤーの排除をシミュレートします。 各操作では、プレーヤーの一部を削除し、すべてが排除されるまで繰り返します。 これは原理的には機能しますが、各操作には歩行経路が必要になります。`O(n)`長く、繰り返します`O(n)`頂点は～につながります`O(n^2 * m)`複雑。 と`n`そして`m`まで`3 * 10^5`、これは不可能です。 

重要な観察は、プレーヤーにとって次のことです。`i`、それらを削除できる頂点は **厳密に 2 つの頂点の間にあるすべての頂点です。`x_i`そして`y_i`パス上**。 任意の頂点をルートとするツリーを考慮すると、各パスの内部頂点が接続されたサブパスを形成します。 すべてのプレイヤーを排除すると、古典的な **ツリー上のヒット セット問題** に帰着します。つまり、すべてのプレイヤーの内部パスと交差する最小の頂点セットを選択する必要があります。 

ツリーによって貪欲な戦略が可能になるため、問題は単純化されます。つまり、すべてのパスの最深点に最も近い頂点が最大プレイヤー数をカバーすることになります。 ツリーを葉から根まで処理する場合、以前の操作でパスを完全にカバーできないプレイヤーを排除するために使用する必要があるエッジ (または頂点) をマークできます。 これにより、この問題は、「ツリー内のパス上の頂点カバー」と呼ばれることが多い **ツリー上の動的プログラミング** 問題に変換されます。 

最適なアプローチは、各プレーヤーの **最下位共通祖先 (LCA)** を特定することです。`x_i`そして`y_i`。 パスの内部頂点は 2 つのチェーンを形成します。`x_i`LCAへ、そしてから`y_i`エンドポイントを除き、LCA に変換します。 各頂点を通過するパスの数のカウントを維持することで、ポストオーダー DFS で頂点を貪欲に選択し、すべてのパスの内部頂点が少なくとも 1 回選択されるようにすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | LCA を使用した貪欲な DFS | O(n + m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを任意に (たとえば頂点 1 に) ルートし、LCA クエリの深さと親配列を事前計算します。 これにより、バイナリ リフティングを使用した任意の 2 つのノードの LCA に対する定数時間クエリが可能になります。 
2. プレイヤーごとに`i`、計算する`lca_i = LCA(x_i, y_i)`。 もし`x_i`の親です`y_i`(またはその逆)、パスには内部頂点がありません。 この場合、プレイヤーを排除不可能としてマークします。 
3. 他のすべてのプレイヤーについては、**厳密にその間**にある頂点をマークします。`x_i`そして`y_i`彼らの道の上で。 各パスは内部的に次の範囲として表すことができます。`x_i`LCAへ、そしてから`y_i`エンドポイントを除き、LCA に適用されます。 これにより、このプレイヤーを排除できる頂点のセットが得られます。 
4. リーフからルートまで DFS を実行します。 頂点ごとに、この頂点を必要とするパスの内部セグメントの数のカウンターを維持します。 子サブツリーに未解決のパスがある場合は、現在の頂点を操作の選択肢としてマークし、残りの要件を上方に伝播します。 
5. 操作のために選択された各頂点を数えます。 DFS 後、パスがマークされていないままになっている場合 (たとえば、パスに内部頂点がない場合)、出力`-1`。 それ以外の場合、選択された頂点の合計が最小操作数となります。 
6. カウントを返します。 

ポストオーダー DFS で頂点を選択することにより、すべての内部パス頂点がカバーされるため、正確性が保証されます。 より高い頂点を選択するのは冗長であり、すべてのプレーヤーのパスには少なくとも 1 つの頂点が選択されています。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(1 << 25)
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    parents = list(map(int, input().split()))
    tree = [[] for _ in range(n + 1)]
    for i, p in enumerate(parents, start=2):
        tree[p].append(i)
        tree[i].append(p)

    LOG = 20
    up = [[-1] * (LOG + 1) for _ in range(n + 1)]
    depth = [0] * (n + 1)

    def dfs(u, par):
        up[u][0] = par
        for k in range(1, LOG + 1):
            if up[u][k-1] != -1:
                up[u][k] = up[up[u][k-1]][k-1]
        for v in tree[u]:
            if v != par:
                depth[v] = depth[u] + 1
                dfs(v, u)
    dfs(1, -1)

    def lca(u, v):
        if depth[u] < depth[v]:
            u, v = v, u
        for k in reversed(range(LOG + 1)):
            if up[u][k] != -1 and depth[up[u][k]] >= depth[v]:
                u = up[u][k]
        if u == v:
            return u
        for k in reversed(range(LOG + 1)):
            if up[u][k] != -1 and up[u][k] != up[v][k]:
                u = up[u][k]
                v = up[v][k]
        return up[u][0]

    counter = [0] * (n + 1)
    impossible = False
    for _ in range(m):
        x, y = map(int, input().split())
        l = lca(x, y)
        if (l == x or l == y) and abs(depth[x] - depth[y]) == 1:
            impossible = True
            continue
        if x != l:
            counter[x] += 1
            counter[l] -= 1
        if y != l:
            counter[y] += 1
            counter[l] -= 1

    res = 0
    def dfs_count(u, par):
        nonlocal res
        for v in tree[u]:
            if v == par:
                continue
            dfs_count(v, u)
            counter[u] += counter[v]
        if counter[u] > 0 and u != 1:
            res += 1
            counter[u] = 0
    if impossible:
        print(-1)
        return
    dfs_count(1, -1)
    print(res)

if __name__ == "__main__":
    main()
```バイナリ リフティングを使用した LCA 前処理により、パスを効率的に計算できます。 DFS でカウンター配列を使用すると、要件がツリーの上に伝播されます。 サブツリーに未解決のパスがある場合に頂点を選択すると、最小限の選択ですべてのプレイヤーが確実に排除されます。 微妙な部分は、内部頂点のないパスを慎重に処理することであり、これによりすぐに答えが不可能になります。
