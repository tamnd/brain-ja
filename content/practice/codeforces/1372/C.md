 ## 問題の理解

 1 から n までの数値の順列が与えられており、制限された操作を使用してそれをソートされた恒等順列に変換したいと考えています。 この操作では、連続するセグメントを選択して任意に並べ替えることができますが、重要な制限が 1 つあります。操作後にそのセグメント内の元の位置に要素を残すことはできません。 

したがって、各移動は部分配列の制約された「再シャッフル」であり、選択されたセグメント内のすべての要素は同じセグメント内の別の場所に移動する必要があります。 

タスクは、並べ替えをソートされた順序に変えるために必要なそのような操作の最小数を計算することです。 

入力サイズはすべてのテスト ケースにわたって 2 · 10^5 に達するため、すべての解はテスト ケースごとに線形または線形に近いものでなければなりません。 n = 2 · 10^5 の 1 回のテストでもすでに 10^10 のオーダーの演算が必要になるため、O(n^2) 戦略はすぐに遅すぎます。 

この問題の微妙な点は、この操作はスワップよりも強力ですが、配列全体の任意の再配置よりは弱いということです。 セグメントの完全な置換は許可されますが、そのセグメント内の固定点は禁止されます。 この制約は、要素を開始位置に戻すことを回避できる限り、長さが 2 以上のセグメントでは無関係になります。これは、セグメントが既に正しく位置合わせされていない限り、常に可能です。 

素朴な推論を打ち破るエッジケースには、通常、「セグメントの有効な並べ替え」の意味の誤解が含まれます。 たとえば、配列がすでにソートされている場合、操作は必要ありません。 配列内に既に正しい位置に要素が散在している場合、一度に 1 つの要素を修正する単純な貪欲な考えでは、単一セグメント内で誤って配置された複数の要素を修正する利点を過小評価する可能性があります。 

## アプローチ

 ブルートフォースの視点では、プロセスをシミュレートしようとします。 各ステップで、セグメントを検索し、そのセグメントの有効な乱れをすべて適用し、配列がソートされるまで再帰的に続行できます。 長さ k の各セグメントには多くの有効な順列があり、考えられるすべての操作シーケンスをチェックすると指数関数的な動作が発生するため、これはすぐに組み合わせ的に爆発します。 状態空間が n! であるため、置換に対して BFS を試みることさえ不可能です。 

重要な構造上の観察は、実際には、選択したセグメントの内部配置によって制約されるのではなく、そのセグメント内の要素が既に正しく配置されているかどうかによってのみ制約されるということです。 この操作では、その区間内の恒等順列と完全に一致していない限り、任意のセグメントを「修復」できます。 これにより、問題は、順列が、すでに正しい最大の接頭辞と接尾辞の構造にどのように分解されるかを数えることに変わります。 

「正しいプレフィックス」がどこまで拡張できるかを追跡しながら、左から右へ順列をスキャンします。 現在間違って配置されているすべての要素を含む操作を安全に実行できるようになる前に、到達する必要がある最も遠い位置を維持します。 ある境界までのすべての位置がすでに正しいプレフィックス セグメントに遭遇するたびに、そのセグメントには何の操作も必要ありません。 この構造の破損に遭遇するたびに、私たちは障害の最大領域をカバーする 1 回の手術を実行することを余儀なくされます。 

これは貪欲なセグメンテーションのアイデアにつながります。配列を最大のブロックに分割し、各ブロックに修正ステップを強制する少なくとも 1 つの誤って配置された要素が含まれるようにし、各操作でそのような 1 つのブロックを最適に修正します。

 ## アルゴリズムのチュートリアル

1. 現在の障害領域を追跡しながら、アレイを左から右にスキャンします。 考慮されている現在のセグメントに含める必要がある最大インデックスを表す変数を維持します。 
2. 各位置 i について、i の値がすでに i + 1 であれば、それはすでに正しいので、現在の領域は拡張されません。 
3. i の値が正しい位置にない場合は、この値が移動する位置を含むように現在のセグメント境界を拡張します。修正するには、その位置に触れる必要があるためです。 
4. この「依存関係クロージャー」に属するすべての要素が含まれるまで、この境界を拡張し続けます。 
5. スキャン インデックスが現在の境界に達すると、1 回の操作で修正できる最小セグメントが 1 つ特定されたため、1 回の操作をカウントし、次のインデックスから新しいセグメントを開始します。 
6. 配列の最後まで繰り返します。 

重要な考え方は、各操作が「配置ミスの依存関係」によって形成される 1 つの連結コンポーネントの解決に対応し、インデックス i が位置 a[i] に依存するということです。 

機能する理由: 配置されていない各要素により、有効な修正には現在の位置とターゲット位置の両方が強制的に含まれます。 これにより依存関係チェーンが作成され、操作の最小数は、位置からターゲットへのリンクのグラフとして見たときの順列内の互いに素な依存関係コンポーネントの数と同じになります。 各特別な交換は、そのようなコンポーネント 1 つを完全に解決できますが、必要以上にセグメントを不必要に拡張せずに、切断された 2 つのコンポーネントをマージすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ops = 0
        i = 0

        while i < n:
            if a[i] == i + 1:
                i += 1
                continue

            ops += 1

            max_reach = i
            j = i
            while j <= max_reach:
                if a[j] - 1 > max_reach:
                    max_reach = a[j] - 1
                j += 1

            i = max_reach + 1

        print(ops)

if __name__ == "__main__":
    solve()
```この実装は貪欲なスイープに依存しています。 外側のループは操作を必要としないため、すでに正しい位置をスキップします。 間違って配置された要素を見つけたら、セグメントの拡張を開始します。 内側のループは、その内部の要素のターゲット位置を使用してセグメント境界を拡大します。 これにより、1 つの操作に含める必要があるインデックスのクロージャが効果的に構築されます。 

微妙なポイントは、`a[j] - 1`順列は 1 ベースですが、Python 配列は 0 ベースであるため、位置インデックスとして使用されます。 新しい依存関係がさらに拡張されなくなると、セグメントは終了します。

 ## 特殊なケース

 境界がきれいなケースとは、順列がすでにソートされている場合です。 アルゴリズムはすべてのインデックスを即座にスキップします。`a[i] == i + 1`したがって、セグメントは作成されず、出力はゼロのままになります。 

もう 1 つの重要なケースは、次のような単一の大きなサイクルです。`[2,3,4,5,1]`。 ここでは、すべてのインデックスが別のインデックスに依存しているため、依存関係クロージャーは 1 回のパスで配列全体に展開されます。 アルゴリズムはインデックス 0 から始まり、拡張されます。`max_reach`これは、配列全体が 1 回の有効な交換で修正できるという事実と一致します。
