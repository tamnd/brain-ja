 ## 問題の理解

 まずは数字を円形に配置することから始めます。 各移動は円上の 1 つの位置を取り、その位置をその 2 つの近傍の合計で置き換え、それらの 2 つの近傍を削除します。 円は毎回 2 要素ずつ縮小し、数字が 1 つだけ残るまで続けます。 目標は、削除の順序を最適に選択して、この最終的な残りの値を最大化することです。 

この操作を解釈する便利な方法は、「隣接する要素のペアを削除する」たびに、それらの値が生き残った要素に追加されるということです。 したがって、このプロセスは実際には構造を構築することではなく、どの要素がペアになり、隣接制約を通じて他の要素に吸収されるかを決定することです。 

という制約が$n$奇数は必須です。 各操作でサイズが 2 ずつ削減されるため、常に最終要素の 1 つに正確に到達します。 

主な問題点は、隣接関係が円上で動的に変化するため、マージの順序が後でどの要素が隣接できるかに影響することです。 考えられるすべてのシーケンスの単純なシミュレーションは、それぞれの選択によって円の将来の構造が変化するため、組み合わせ論的に爆発します。 

制約については、$n$まで行くことができます$2 \cdot 10^5$これにより、構成を調査したり、間隔を超えて 2 次またはそれより悪い DP を実行したりするソリューションは直ちに除外されます。 平$O(n^2)$Python では遅すぎるでしょう。 直線または直線に近い構造が必要です。 

微妙なエッジ ケースは、1 つの大きな値を除いてすべての値がゼロである場合です。 常にローカルでマージする貪欲な戦略では、たとえ最適な戦略が周囲にマージを分散させていたとしても、大きな値を誤って早期に分離し、十分な寄与を蓄積できなくなる可能性があります。 

もう 1 つの特殊なケースは、小さな円です。 のために$n = 1$、答えは簡単です。 のために$n = 3$、唯一の有効な操作がすでに結果を決定しており、「選択」に関する誤った推論は実際の分岐のないケースを複雑にしすぎます。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての操作シーケンスを試行します。 各ステップでは、中心要素を選択し、その近傍要素を削除し、結果として得られる小さな円を再帰的に実行します。 各状態は最大で$n$次の状態、深さはおよそ$n/2$。 メモ化を行ったとしても、構造はその値だけでなくどの要素が削除されたかによって定義されるため、個別の循環状態の数は指数関数的になります。 これにより、総当たり攻撃が不可能になります。 

重要な洞察は、動的な隣接性の観点から考えるのをやめ、代わりに、円上にバイナリ マージ構造を構築するプロセスとして再解釈することです。 すべての操作で 2 つの要素が削除され、それらの要素が 3 番目の要素に結合されます。 プロセスを逆にすると、最終的な値は、生き残った 1 つのノードを繰り返し拡張し、他の 2 つのノードをそれに接続することによって形成されると考えることができます。 

重要な観察は、どのような最適なプロセスでも、最後に生き残る要素を事前に選択し、常にその周りに対称的にペアをマージする方法が存在するということです。 最後のルートを修正すると、最適な戦略が決定的になります。強制的な隣接マージによって残りの各要素がこのルートに吸収されるときに、その要素がどの程度寄与するかを最大化したいと考えます。 

これにより、直線的な構造が得られます。概念的に、最終的に生き残る位置で円を「カット」し、貢献を最大化するために両側の要素がどのようにペアになるかをシミュレーションします。 寄与は常に加算的で負ではないため、最終ルートに近い大きな要素を保持する方法でマージを遅らせても価値が失われることはありません。 

最適な構成は、選択した中心に向かって外側のペアを内側に繰り返しマージすることに対応することが判明し、明示的なシミュレーションではなくプレフィックスとサフィックスの累積ロジックを使用して効率的に評価できます。

 ## アルゴリズムのチュートリアル

 私たちは問題を、円内の「ルート」位置を選択し、他のすべての要素から収集できる可能な限り最良の寄与を計算することに変換します。 

1.位置を固定する$i$最後に生き残る要素として。 私たちはそれを建設のアンカーとして扱います。 
2. サークルを壊す$i$、両方向の順序を維持しながら線形配列に変換します。 
3. ルートに近い要素はマージ プロセスの初期に寄与する可能性が高いため、両端からルートに向かって要素を対称的にペアにしたいと考えます。 
4. 2 つの実行累積を構築します。1 つはルートに向かって左に移動し、もう 1 つはルートに向かって右に移動します。 
5. 2 つの対称要素を組み合わせるたびに、それらの寄与がルートの合計に効果的に追加されます。 
6. この内向きプロセスでペアの要素からの寄与を合計することにより、このルートの達成可能な合計値を計算します。 
7. 考えられるすべての根に対してこの評価を繰り返し、最大値を取得します。 

微妙なステップは、すべての有効な操作シーケンスがルートの選択と内向きのペアの削除の順序に対応していることを理解することです。 ルートが固定されたら、常にペアリング効率を最大化することが最善の戦略であり、これは対称的な内向きマージによって達成されます。 

### なぜ効果があるのか

 このプロセスでは、円上にバイナリ リダクション ツリーを定義します。 各内部ノードは、2 つの隣接する要素を結合して存続する要素にする操作に対応します。 すべての操作は加算的であり、減算は存在しないため、最終的な値は、このツリーを通じて上方に伝播された寄与の正確な合計になります。 

根を固定することで、この木の上部の構造が決まります。 最適なツリーは任意の位置にルート化でき、サブツリーのペアを再配置しても、すべての寄与が保持されるため、総和は減少しません。 したがって、ルートのすべての選択肢を評価すると、有効な最適な構成がすべてカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(a[0])
        return
    
    # duplicate array to simulate circular rotations
    b = a + a
    prefix = [0] * (2 * n + 1)
    
    for i in range(2 * n):
        prefix[i + 1] = prefix[i] + b[i]
    
    # try every possible root window of length n
    ans = 0
    
    # we simulate optimal inward pairing cost as total sum minus minimal removable structure
    total = prefix[n]
    
    # compute best pairing score via greedy symmetric collapse idea
    # two pointers inward for each rotation
    for start in range(n):
        l = start
        r = start + n - 1
        
        # greedy pairing from outside inward
        cur = 0
        i, j = l, r
        
        while i < j:
            cur += b[i] + b[j]
            i += 1
            j -= 1
        
        ans = max(ans, cur)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、配列を複製することによって、ルートの考えられる各選択肢をシミュレートします。 開始位置ごとに、要素を端から内側に向​​かって対称的にペアにします。 最適なマージ プロセスでは、これら 2 つの要素が吸収される前に常に隣接するように配置できるため、各ペアは最終的なルートに直接寄与します。 

double 配列により、循環インデックスのモジュラー演算が回避され、プレフィックス ロジックは最終実装では厳密には必要ありませんが、累積を理解するのに役立ちます。 2 ポインターの内向きスイープは、固定ルートの最適なペアリング構造を表します。 

主な微妙な点は、ローテーション間で状態を再利用すると、異なるルートの選択が誤って混在してしまうため、各構成が独立して評価されるようにすることです。

 ## 特殊なケース

 のために$n = 1$の場合、演算が存在しないため、アルゴリズムはただちに単一の値を返す必要があります。 ペアリング ロジックを適用しようとすると、少なくとも 1 つのマージが可能であると誤って想定されてしまいます。 

均一な配列の場合、すべてのペアリング戦略が同じ値を生成するため、正確さは内向きの走査で off-by-one エラーが発生しないことに依存します。 対称ループは、ポインターが交差するときに正確に停止する必要があります。そうしないと、要素が二重にカウントされるかスキップされます。
