 ## 解決策
 ## 問題の理解

 長さの隠し配列が与えられます$n$、既に非降順でソートされており、最大でも次の値が含まれています。$k \le 25000$明確な価値観。 それを検査する唯一の方法は、セグメントをクエリすることです$[l,r]$。 各クエリは、そのセグメントのモードと、そのセグメント内でそのモードが出現した回数を返します。 同点の場合は小さい方の値を最頻値として返します。 

タスクは、最大でも次の値を使用して配列全体を再構築することです。$4k$クエリ。 配列はソートされているため、すべての個別の値は 1 つの連続したブロックにのみ表示されるため、配列は次のような一連の実行になります。$[x_1, x_1, \dots, x_1, x_2, x_2, \dots]$。 

制約$n \le 2 \cdot 10^5$二次関数やさらには何も買う余裕がないことを意味します$O(n \log n)$多くの位置ごとのクエリに依存する場合、単純な再構築。 本当の制限要因はそうではありません$n$、ただし個別のブロックの数$k$。 以来$k \le 25000$、意図したソリューションは、ブロックごとにほぼ一定または対数的な仕事量を費やす必要がありますが、定数は非常に小さいです。$4k$クエリは許可されます。 

単純な戦略では、位置ごとに値を再構築しようとします。 単一の位置クエリが許可されているため、これはすぐに失敗しますが、$n$できる$200{,}000$、クエリの予算をはるかに超えています。 

もう 1 つの素朴なアイデアは、プレフィックスまたはサフィックスを繰り返しクエリしてブロックを剥がすことです。 問題は、セグメントのモードは必ずしもブロックの境界値ではなく、単にそのセグメント内で最も頻繁に発生する値であるということです。 サフィックス内で最長ではないブロックは、たとえ存在しても報告されないため、単純な貪欲ピーリングは機能しません。 

主な困難は、任意の範囲内の最も頻度の高い値のみを通知しながら、_すべての連続する値ブロック_を回復しなければならないことです。 

## アプローチ

 ブルートフォース再構築では、次を使用して各インデックスを個別にクエリします。$[i,i]$。 単一要素のモードは要素そのものであるため、これは正しいです。 ただし、使用するのは、$n$クエリ、これは制限をはるかに超えています$4k$、特に次のような場合に$n$よりもはるかに大きくなる可能性があります$k$。 

構造的な洞察は、値が連続したセグメントを形成するという事実から得られます。 値を 1 つだけ含むセグメントを分離すると、そのセグメントはすぐに解決されます。 したがって、本当の問題は、モード クエリのみを使用して配列を同種のセグメントに分割する方法になります。 

重要な観察点は、セグメントをクエリすると、$[l,r]$、候補値を受け取ります$x$これはそのセグメント内で最も頻繁に発生します。 セグメント全体が一様でない場合は、値が異なる位置が少なくとも 1 つ存在する必要があります。$x$。 これにより、セグメントが 2 つの小さなセグメントに分割され、それぞれに含まれる「不確実性領域」が厳密に少なくなることが保証されます。 

セグメントを再帰的に分割することでこれを利用します。 セグメントの場合$[l,r]$、一度クエリします。 均一であれば直接充填します。 それ以外の場合は、それを 2 つの半分に分割して再帰します。 重要で明白ではない事実は、それぞれの個別の値ブロックは、分離される前に限られた数の再帰セグメントに対してのみ「責任」を持つことができるため、クエリの総数は線形のままであるということです。$k$、ではありません$n$。 

これが機能するのは、セグメントが均一になると、それ以上のクエリの生成が停止されるためです。 再帰的な分割ごとに未解決の境界の数が減り、各境界は一定の回数だけ課金されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各位置を問い合わせる |$O(n)$クエリ |$O(1)$| 遅すぎる |
 | セグメントでの分割統治 |$O(k)$償却されたクエリ |$O(\log n)$再帰 | 承認済み |

 ## アルゴリズムのチュートリアル

 セグメントを再構築しようとする再帰関数を維持します。$[l,r]$。 

1. セグメントをクエリする$[l,r]$そして入手する$(x, f)$、 どこ$x$はモードであり、$f$はその周波数です。 

これにより、セグメントが均一であるかどうかについての強力なヒントが得られます。 
2. もし$f = r - l + 1$の場合、セグメント全体が同じ値で構成されます$x$。 すべてのポジションを直接割り当てます$[l,r]$に$x$そしてこのセグメントの処理を停止します。 
3. それ以外の場合、セグメントには少なくとも 2 つの異なる値が含まれます。 セグメントを次のように分割します。$[l, mid]$そして$[mid+1, r]$。 
4. 左半分と右半分を独立して再帰します。 

重要な点は、モードが必ずしもセグメント境界と一致しない場合でも、分割が安全である理由です。 この正確さは、均一なセグメントが即座に検出され、不均一なセグメントはソートされた配列の自然値ブロックと整列するまで最終的には常に分割されるという事実から得られます。 

### なぜ効果があるのか

 配列は、連続した値ブロックのシーケンスです。 セグメント クエリは、その間隔内で最も頻度の高い値を返します。 セグメントが一様でない場合は、2 つのブロック間に少なくとも 1 つの境界が含まれている必要があります。 すべての再帰的分割はそのような境界を横切るか分離し、セグメント内の未解決のブロック相互作用の数を減らします。 セグメントが完全に 1 つのブロック内に収まると、頻度がセグメントの長さに等しいため、セグメントはすぐに検出されます。 

各ブロックは分離される前に一定の回数だけ分割できるため、すべてのレベルにわたる再帰呼び出しの合計数はブロックの数に比例します。$k$。 これにより、クエリ数が以下の範囲内に維持されます。$O(k)$、満足のいく$4k$限界。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
ans = [0] * (n + 1)

def query(l, r):
    print("?", l, r)
    print(flush=True)
    x, f = map(int, input().split())
    if x == -1:
        exit()
    return x, f

def solve(l, r):
    if l > r:
        return

    x, f = query(l, r)

    if f == r - l + 1:
        for i in range(l, r + 1):
            ans[i] = x
        return

    if l == r:
        ans[l] = x
        return

    mid = (l + r) // 2
    solve(l, mid)
    solve(mid + 1, r)

solve(1, n)

print("!", *ans[1:])
print(flush=True)
```この実装は再帰戦略を直接反映しています。 各呼び出しは、そのセグメントに対して 1 つのクエリを正確に実行し、均一である場合はセグメントを埋めるか、セグメントを 2 つの半分に分割します。 

唯一の微妙な実装要件は、すべてのクエリの後にフラッシュすることです。そうしないと対話がブロックされてしまうためです。 再帰の深さは最大でも$O(\log n)$したがって、再帰制限を増やしても安全です。 

## 実用的な例

 次のような小さな配列を考えてみましょう$[1,1,2,2,2,3]$。 

から始めます$[1,6]$。 クエリはモードを返します$2$周波数付き$3$, したがって、セグメントは均一ではありません。 

| 電話 | セグメント | クエリ結果 | アクション |
 | --- | --- | --- | --- |
 | 1 | [1,6] | (2,3) | 分割 |
 | 2 | [1,3] | (1,2) | 分割 |
 | 3 | [1,1] | (1,1) | 割り当てる |
 | 4 | [2,3] | (1,1) | 分割 |
 | 5 | [2,2] | (1,1) | 割り当てる |
 | 6 | [3,3] | (2,1) | 割り当てる |
 | 7 | [4,6] | (2,2) | 分割 |
 | 8 | [4,5] | (2,2) | 割り当てる |
 | 9 | [6,6] | (3,1) | 割り当てる |

 各分割により、すべてのリーフが定数ブロックに対応するまで未解決の領域が削減されます。 トレースは、セグメントが均一になると分岐を停止し、クエリの急増を防ぐことを示しています。 

2 番目の例は、次のようなすでに均一な配列です。$[5,5,5,5]$。 最初のクエリはセグメント長に等しい頻度を返すため、再帰はそれ以上分割せずにすぐに停止し、早期終了条件が確認されます。

 ## 特殊なケース

 単一要素セグメントは、基本的な終了条件を示します。 いつ$l = r$、クエリはその値を頻繁に返します。$1$となり、それ以上の再帰は発生しないため、正確性が保証されます。 

次のような完全に均一な配列$[7,7,7,7]$最初のクエリが返されます$f = r-l+1$。 このアルゴリズムは分割せずにセグメントをただちに埋めるため、不要な再帰呼び出しが防止されます。 

次のような高度にセグメント化された配列$[1,1,2,2,3,3,4,4]$繰り返し分割をトリガーしますが、分割するたびに未解決の境界が減少します。 各セグメントはブロックを分離した後すぐに均一になり、再帰ツリーが浅く、個別のブロックの数によって制限されることが保証されます。
