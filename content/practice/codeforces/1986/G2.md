 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$、インデックスのペアが何ペアあるかを数えるように求められます。$(i, j)$満足する$i < j$そして$p_i \cdot p_j$で割り切れる$i \cdot j$。 概念的には、順列は 1 から 1 までの数値の並べ替えを表します。$n$, したがって、各数字は 1 回だけ表示されます。 順列を変更するように求められるのではなく、この可分性の特性について位置のペアを分析することだけを求められます。 

主な課題は制約です$n \le 5 \cdot 10^5$複数のテストケースにわたって。 すべてをチェックするブルートフォースアプローチにより、$\binom{n}{2}$ペアの場合、操作の数は約$10^{11}$最悪の場合、それは明らかに実行不可能です。 すべてのインデックス ペアを反復するソリューションはタイムアウトになります。 したがって、問題の構造を利用して、考えられるすべてのペアを明示的にチェックすることを回避する方法が必要です。 

素朴な実装を壊す可能性のあるエッジケースには、次のような小さな順列が含まれます。$n = 1$または$n = 2$不注意な実装では、配列の境界を超えてインデックスにアクセスしようとする可能性があるためです。 もう 1 つの微妙なケースは、順列内の数値がその位置よりも大きい場合であり、これは割り算チェックに影響します。 たとえば、次の場合$p = [2, 1]$、ペア$(1, 2)$は有効です。$2 \cdot 1 = 2$で割り切れます$1 \cdot 2 = 2$。 割り切れる条件の両側をチェックするのを忘れると、間違った答えが生成される可能性があります。 

## アプローチ

 ブルートフォース ソリューションは、すべてのペアに対して単純に反復処理を行います。$(i, j)$と$i < j$かどうかをテストします$p_i \cdot p_j$で割り切れます$i \cdot j$。 この方法は原理的には正しいですが、その複雑さは次のとおりです。$O(n^2)$。 と$n$まで$5 \cdot 10^5$、これはおおよその結果を生成します$10^{11}$最悪の場合、3 秒の時間制約の制限をはるかに超えて操作が可能になります。 したがって、最適化が必要です。 

重要な洞察は、可算条件を変換することです$i \cdot j \mid p_i \cdot p_j$比率チェックに: 固定用$i$、条件は次のように書き換えることができます。$\frac{p_i}{i} \cdot \frac{p_j}{j}$整数であること。 と表すと$x_i = p_i / i$、すると条件は次のようになります$x_i \cdot x_j$は整数です。 すべての値ではありません$x_i$は整数ですが、$p_i$そして$i$整数です、$x_i$は有理数であり、約数の数が有限であるため、$p_i \le n$。 これにより、次の倍数のみを考慮する必要があるという観察が得られます。$i$潜在的な一致のために$j$どこ$p_j = k \cdot i$整数の場合$k$。 約数または倍数をループすることにより、候補ペアの数を大幅に減らします。 

各ポジションについて、次の事実を利用できます。$i$、有効な数$j$は小さく、具体的には の倍数によって制限されます。$i$それは$\le n$。 これにより、複雑さが軽減されます。$O(n \log n)$複数のふるいのような反復を使用します。 基本的に、すべてをチェックするのではなく、$j > i$、それらのみをチェックします$j$どこ$i \mid p_j$そして$p_j / i \le n / i$。 これにより、問題は二次複雑さから線形に近い複雑さになります。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`ans`これには、有効なペアの数が保存されます。 
2. 各インデックスを反復処理します。$i$1から$n$。 それぞれについて$i$、すべての倍数を識別します$j = i \cdot k$そのような$i < j \le n$。 これらは、割り切れる可能性がある候補ポジションです。 
3. それぞれについて$j$、どうかを確認してください$p_i \cdot p_j$で割り切れます$i \cdot j$。 これが実際の可分性テストです。 倍数ロジックだけに依存することはできません。$p_i$そして$p_j$並べ替えられます。 複数のヒューリスティックにより候補が削減されますが、可算性は保証されません。 
4. 条件が成立する場合、インクリメントします。`ans`。 
5.すべての処理が完了したら$i$、出力`ans`。 

これが機能する理由は、複数の反復処理により、候補ペアのみを考慮するためです。$i \cdot j$分割できる$p_i \cdot p_j$。 不変条件は、すべての有効なペアが$(i, j)$満足する$i \mid p_j$または$j \mid p_i$、これは使用する乗法構造と同等です。 有効なペアはスキップされず、無効なペアはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for idx, val in enumerate(p):
            pos[val] = idx + 1  # 1-based index

        ans = 0
        for i in range(1, n + 1):
            j = i
            while j <= n:
                if i < j:
                    if (p[i - 1] * p[j - 1]) % (i * j) == 0:
                        ans += 1
                j += i
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、インデックスの乗算を容易にするために、まず 1 から始まる位置のマッピングを構築します。 外側のループは繰り返します$i$内側のループは次の倍数にわたって反復されます。$i$候補者を減らす$j$価値観。 モジュロ チェックにより、有効なペアのみがカウントされることが保証されます。 

微妙なポイントは、`i < j`内側のループ内。 いくつかの倍数`i`以下になる可能性があります`i`から始めたら`i = 1`。 1 から始まるインデックスを使用すると、アクセス時の off-by-one エラーが回避されます。`p`。
