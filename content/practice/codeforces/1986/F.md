 ## 解決策
 ## 問題の理解

 接続された無向グラフが与えられます。 任意の 2 つの頂点の間に、それらを接続するパスがあるかどうかを尋ねることができます。 パスが存在する場合、そのペアが最終的な答えに寄与します。 グラフは最初に接続されているため、頂点のすべてのペアに到達できるため、最初はすべての頂点が接続されます。$\frac{n(n-1)}{2}$ペアがカウントされます。 

エッジを 1 つだけ削除することができますが、削除した後、グラフが分割されたり、接続されたままになったりすることがあります。 目標は、削除によって結果のグラフ内で到達可能な頂点ペアの数が最小になるエッジを選択することです。 同様に、最終的な答えは「各接続コンポーネント内のペアの数をコンポーネント全体で合計したもの」に過ぎないため、削除によって接続性がどの程度低下するかを最大化したいと考えています。 

制約$n, m \le 10^5$すべてのテスト ケースにおいて、すべてのエッジの接続を最初から再計算することはできないことを意味します。 エッジ除去をシミュレートしてコンポーネントを再計算しようとするソリューションは、非常に遅すぎる可能性があります。$O(m(n+m))$、これは使用できません。 グラフの線形または線形に近い構造分解が必要です。 

グラフが 2 つのエッジで接続されている場合、微妙なエッジ ケースが表示されます。これは、いずれか 1 つのエッジを削除しても接続が維持されることを意味します。 この場合、グラフは 1 つのコンポーネントのままであるため、選択に関係なく答えは変わりません。 たとえば、三角形はエッジを削除した後も接続されたままになるため、すべてのペアが到達可能な状態になります。 

もう 1 つの重要なケースは、エッジを削除するとグラフが 2 つの大きなコンポーネントに分割される場合です。 その後、コンポーネントをまたぐペアが到達不能になるため、到達可能なペアの数が大幅に減少します。 

重要な課題は、コンポーネントの分割に関してどのエッジが最も「損傷」を引き起こすかを特定することです。 

## アプローチ

 ブルート フォースを試す場合は、各エッジを考慮して削除し、DFS または BFS を実行して接続されたコンポーネントを見つけ、次の合計を計算します。$\binom{s_i}{2}$コンポーネントのサイズを超えています。 各接続の再計算にかかるコスト$O(n+m)$、すべてのエッジに対してそれを行うと、$O(m(n+m))$、これは大きすぎます$10^5$スケール入力。 

重要な観察は、非ブリッジ エッジを削除しても接続には何も影響しないということです。 したがって、重要なのは橋だけです。 ブリッジはエッジであり、その削除により接続されるコンポーネントの数が増加します。 これらはまさに、到達可能なペアの数を減らす可能性があるエッジです。 

注目をブリッジに限定すると、ブリッジを削除すると、コンポーネントが正確に 2 つの部分に分割されます。 失われた到達可能なペアの数は、コンポーネント間ペアの数であり、結果として得られる 2 つの辺のサイズのみに依存します。 したがって、ブリッジごとに積を計算する必要があります。$a \cdot b$、 どこ$a$そして$b$ブリッジを削除した後の両側のサイズです。 この積を最大化すると、残りの到達可能なペアが最小化されるため、この積を最大化したいと考えます。 

これにより、すべてのブリッジを見つけて DFS ツリー内のサブツリー サイズを計算するという問題が軽減されます。 標準の Tarjan DFS は、ブリッジを識別するための検出時間と低リンク値を提供します。 ブリッジ ツリーの分解が完了すると、各ブリッジは 2 つの DFS サブツリー パーティション間のエッジに対応し、サブツリーのサイズから各側のサイズを計算できます。 

最後に、最初の到達可能なペアの合計を計算し、可能な限り最良の損失を差し引いて、結果を出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m(n+m))$|$O(n+m)$| 遅すぎる |
 | 最適 (DFS + ブリッジ) |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 DFS をルート化し、標準のローリンク計算を使用してブリッジとサブツリーのサイズを同時に特定します。 

1. グラフの隣接リストを作成します。 すべてのエッジが 1 回処理されるため、DFS 中に近隣ノードを高速に走査する必要があります。 
2. 検出時間を維持しながら、任意のノードから DFS を実行します。`tin[u]`到達可能な最小検出時間`low[u]`。 の意味`low[u]`のサブツリーから到達可能な最も早く訪問したノードです。`u`最大でも 1 つのバックエッジを使用します。 この構造により、橋を局所的に検出できるようになります。 
3. からの DFS トラバーサル中`u`に`v`、 もし`low[v] > tin[u]`、次にエッジ`(u, v)`橋です。 その理由は、`v`のサブツリーに到達できません`u`またはその先祖`u`そのエッジなしで。 
4. DFS から戻るときに、サブツリーのサイズを計算します。`sz[u]`。 各ノードは、1 にそのすべての子のサブツリー サイズを加えたものを提供します。 これにより、橋の片側にいくつの頂点があるかを知ることができます。 
5. あらゆる橋について`(u, v)`どこ`u`の親です`v`DFS ツリーでは、結果として得られる 2 つのコンポーネント サイズは次のとおりです。`sz[v]`そして`n - sz[v]`。 
6. サイズのコンポーネント内の到達可能なペアの数を計算します。$k$として$k(k-1)/2$。 ブリッジ分割の場合、合計は次のようになります。$$\frac{sz[v](sz[v]-1)}{2} + \frac{(n-sz[v])(n-sz[v]-1)}{2}$$7. すべてのブリッジの最小値を追跡します。 橋がない場合、答えは単純です。$\frac{n(n-1)}{2}$。 

### なぜ効果があるのか

 DFS ツリーは、エッジをツリー エッジとバック エッジに分割します。 ブリッジはまさに、サブツリーのバック エッジで覆われていないツリー エッジです。 これにより、これを削除すると、グラフが正確に 2 つの独立したコンポーネントに切断され、そのサイズが DFS サブツリー サイズによって完全に決定されることが保証されます。 1 つおきのエッジがサイクル内にあるため、エッジを削除しても到達可能性に影響を与えず、目的を改善できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    tin = [-1] * (n + 1)
    low = [0] * (n + 1)
    sz = [0] * (n + 1)
    timer = 0

    bridges = []

    def dfs(u, p):
        nonlocal timer
        timer += 1
        tin[u] = low[u] = timer
        sz[u] = 1

        for v in g[u]:
            if v == p:
                continue
            if tin[v] != -1:
                low[u] = min(low[u], tin[v])
            else:
                dfs(v, u)
                sz[u] += sz[v]
                low[u] = min(low[u], low[v])

                if low[v] > tin[u]:
                    bridges.append((u, v))

    dfs(1, -1)

    total = n * (n - 1) // 2
    best = total

    for u, v in bridges:
        # ensure v is child in DFS tree
        # if not guaranteed, recompute orientation via tin
        if tin[u] > tin[v]:
            u, v = v, u
        a = sz[v]
        b = n - sz[v]
        comp = a * (a - 1) // 2 + b * (b - 1) // 2
        best = min(best, comp)

    print(best)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```DFS は、1 回の走査でローリンク値とサブツリー サイズの両方を計算します。 ブリッジ リストには、削除によって接続性が実際に変更される候補エッジが保存されます。 細心の注意を払って、サブツリーのサイズを計算するときに DFS の親子方向を正しく解釈するようにしています。 発見時間に基づいて交換することで、サブツリー側に立つことが保証されます。 

最終的な答えは完全なグラフ値から始まり、最適なブリッジ分割を考慮して値を減らします。 

## 実用的な例

 ### 例 1

 入力:```
3 3
1 2
2 3
1 3
```| ステップ | 橋？ | サブツリーのサイズ | コンポーネントの分割 | 結果 |
 | --- | --- | --- | --- | --- |
 | エッジをチェックする | なし | すべてのサイクル | 分割なし | 3ペア |

 グラフは三角形です。 すべてのエッジはサイクル上にあるため、ブリッジは存在しません。 答えは残っている$\binom{3}{2} = 3$。 

これは、サイクルが豊富なグラフが単一エッジの除去下でも変化しないことを確認します。 

### 例 2

 入力:```
5 4
1 2
2 3
3 4
4 5
```| ステップ | 橋 | 分割サイズ | コンポーネントペア |
 | --- | --- | --- | --- |
 | (3,4) を削除 | はい | 3 と 2 | 3 + 1 = 4 |
 | (2,3) を削除 | はい | 2 と 3 | 1 + 3 = 4 |

 すべてのエッジは橋です。 削除するとチェーンが 2 つの部分に分割されます。 最適な分割では、残りの到達可能なペアが最小限に抑えられますが、すべての分割で対称性までは同じ構造が得られます。 

これは、ツリーではすべてのエッジが重要であり、すべての分割候補がサブツリー サイズによって評価される必要があることを示しています。

 ## 特殊なケース

 重要なケースの 1 つは、完全なグラフやサイクルが豊富な構造など、ブリッジのないグラフです。 その状況では、DFS は何も検出しません。`(low[v] > tin[u])`状態なので、ブリッジ リストは空のままです。 アルゴリズムは直接出力します$n(n-1)/2$これは、エッジを削除してもグラフが分割されないという事実と一致します。 

もう一つのケースは木です。 すべてのエッジがブリッジとなり、サブツリーのサイズによって可能なすべての分割が完全に決まります。 DFS はサイズを正しく計算し、各ブリッジを評価すると、エッジ除去によって引き起こされる可能性のあるすべての 2 分割が再現されます。
