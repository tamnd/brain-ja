 ## 解決策
 ## 問題の理解

 大文字のラテン文字で構成される文字列が与えられ、その中に「C-A-T」形式の順序付けられた部分列がいくつ存在するかを数えることに興味があります。 サブシーケンスはインデックスを選択することによって形成されます$i < j < k$これらの位置の文字はそれぞれ「C」、「A」、「T」になります。 文字は隣接している必要はなく、順序だけが重要です。 

このタスクは純粋に組み合わせです。有効な位置の選択ごとに、パターンの出現を 1 回カウントします。 出力は、そのようなトリプルの合計数です。 

文字列の長さが長い場合は、$10^5$それ以上、インデックスのすべてのトリプルを明示的に試行する解決策は、最悪の場合でも 3 次または少なくとも 2 次の動作が必要になるため、不可能です。 位置をまたがる二重ループでも、別のスキャンとネストすると、すぐに遅くなりすぎます。 

微妙な特殊ケースは、文字列に繰り返し文字が多数含まれている場合です。 たとえば、文字列が「CATCAT」の場合、単純な貪欲な解釈では、重複するパターンが互いに干渉すると誤って仮定する可能性がありますが、実際には、有効なインデックスのすべてのトリプルは独立しています。 別の障害モードでは、問題を部分シーケンスのカウントではなく、連続した部分文字列の一致として扱います。これにより、次のような有効な隣接しない形式が失われます。 

入力:```
CAXAT
```正しい出力:```
2
```なぜなら、ペア (1 の C、3 の A、5 の T) と (1 の C、4 の A、5 の T) は両方とも有効なサブシーケンスを形成するためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。「C」のすべての位置を選択し、次に「A」のすべての位置を選択し、その後「T」のすべての後の位置を選択します。 これは問題の定義に直接従っており、有効なトリプルをすべて列挙しているので正しいです。$i < j < k$。 ただし、これにはすべてをチェックする必要があります$O(n^3)$最悪の場合は3倍になります。 と$n = 10^5$、これは実現可能な限界をはるかに超えています。 

部分構造を再利用することでこれを改善できます。 各トリプルを個別に検索するのではなく、すべての「A」が左側の一連の「C」と右側の一連の「T」の間にあることを観察します。 各「A」について、その部分で終わる有効な「C-A」接頭辞の数と、そこから始まる「A-T」接尾辞拡張子の数がわかっていれば、それらを効率的に組み合わせることができます。 

これは自然な動的蓄積戦略につながります。 文字列を右から左に処理して、右側にいくつの「T」が存在するか、右側にいくつの「AT」ペアが存在するか、いくつの「CAT」トリプルを形成できるかを維持します。 

部分構造のカウンターを維持することで、重複する部分問題の再計算を回避します。 各キャラクターは、以前に蓄積された情報に基づいて、より高いレベルのパターンに貢献します。

 | 右から左への累積 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 3 つのカウンターを維持しながら、文字列を右から左にスキャンします。 

1. カウンター`cntT`これまでに見た「T」文字の数を保存します。 
2. カウンター`cntAT`これは、サフィックスの「A」がそれらの「T」の左側にある場合に、「A-T」のペアが何組存在するかを保存します。 
3. カウンター`cntCAT`処理されたサフィックスに完全な「C-A-T」サブシーケンスがいくつ存在するかを保存します。 

現在のキャラクターに基づいてこれらのカウンターを更新します。 

1. すべてのカウンタをゼロに設定して開始します。 最後のインデックスから最初のインデックスまで文字を処理します。 
2. 現在の文字が「T」の場合、インクリメントします`cntT`この「T」が将来の「AT」および「CAT」パターンの末尾として機能する可能性があるためです。 
3. 現在の文字が「A」の場合、現在サフィックスにあるすべての「T」がこの「A」とペアになって、新しい「AT」を形成できます。 追加します`cntT`に`cntAT`。 
4. 現在の文字が「C」の場合、サフィックス内のすべての既存の「AT」ペアを先頭にこの「C」を付けて拡張し、完全な「CAT」を形成できます。 追加します`cntAT`に`cntCAT`。 

すべての文字を処理した後、`cntCAT`答えを持っています。 

### なぜ効果があるのか

 右から左へのスキャン中の任意の位置で、`cntT`すでに処理されたサフィックス内のパターンの最後の文字に対する有効な選択肢をすべて正確にカウントします。 同様に、`cntAT`サフィックス内にあるすべての有効な順序付きペア (T の前の A) をカウントします。 最後に、「C」が表示されるたびに、それを既存のすべての「AT」ペアと組み合わせると、すべてのトリプル (C、A、T) が正しい順序で正確に列挙されます。 各拡張ステップでは、現在の位置の厳密に右側にあるサフィックスからのみ寄与するため、順序が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    cntT = 0
    cntAT = 0
    cntCAT = 0
    
    for ch in reversed(s):
        if ch == 'T':
            cntT += 1
        elif ch == 'A':
            cntAT += cntT
        elif ch == 'C':
            cntCAT += cntAT
    
    print(cntCAT)

if __name__ == "__main__":
    solve()
```実装は逆方向スキャンに直接続きます。 重要な詳細は、更新の厳密な順序です。`cntT`前に更新する必要があります`cntAT`、 そして`cntAT`前に`cntCAT`各レイヤーは以前に蓄積されたサフィックス情報に依存するため、文字の種類に応じて異なります。 

関連するすべての構造が 3 つのカウンターに圧縮されるため、中間ストレージは必要ありません。

 ## 特殊なケース

 主なエッジケースは、文字が頻繁に繰り返され、有効な組み合わせがすべて存在する場合です。 たとえば:

 入力:```
CCAAATTT
```右から左に処理していきます。 「T」が増えるたびに`cntT`、すべての「A」が現在のすべてに寄与します`T`に`cntAT`、すべての「C」は現在のすべての値を乗算します`AT`ペアにする`cntCAT`。 同一の文字が複数あるため、カウンタはすぐに大きくなりますが、常に近似値ではなく正確な組み合わせのカウントを表します。 

もう 1 つの特殊なケースは、文字列に「A」が含まれていないなど、必須の文字が 1 つ欠落していることです。 そのような状況では、`cntAT`ゼロから増えることはないので、`cntCAT`「C」と「T」がいくつ存在しても、ゼロのままです。 中間文字なしでは有効なトリプルを形成できないため、これは定義と一致します。
