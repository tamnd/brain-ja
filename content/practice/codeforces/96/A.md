 ## 解決策
 ## 問題の理解

 のみで構成される文字列が与えられます。`'0'`そして`'1'`。 各キャラクターは、並んでいるサッカー選手のチームを表します。 連続して 7 人以上のプレイヤーが同じチームに所属している場合、危険な状況が発生します。 

タスクは、文字列に 7 つの連続したいずれかが含まれているかどうかを確認するだけです。`'0'`文字または7連続`'1'`文字。 そのようなセグメントが存在する場合、印刷します。`"YES"`。 それ以外の場合は印刷します`"NO"`。 

入力サイズは非常に小さく、最大でも 100 文字です。 非効率的なソリューションであっても、制限内に簡単に収まります。 二次アルゴリズムでは、最悪の場合でも約 10,000 回の演算が実行されますが、2 秒の制限ではわずかです。 それでも、この問題では当然、より単純でクリーンなリニア スキャンが考慮されます。 

難しいのはパフォーマンスではなく、連続した実行を正しく処理することです。 

簡単な間違いの 1 つは、キャラクターが変わったときにカウンターを誤ってリセットしてしまうことです。 

考慮する：```
1111110
```正しい答えは、`"NO"`等しい文字の最長の連続の長さは 6 であるため、合計数だけをチェックする不注意な実装`'1'`文字が正しく印刷されない`"YES"`。 

もう 1 つのよくある間違いは、少なくとも 7 文字ではなく、ちょうど 7 文字だけをチェックすることです。 

例：```
11111111
```正しい答えは、`"YES"`長さ 8 のランでも条件を満たしているためです。 コードが 7 に等しい実行のみをチェックする場合、ここで失敗します。 

3 番目のエッジ ケースは、危険なシーケンスが文字列の先頭で始まるか、文字列の末尾で終了する場合に発生します。 

例：```
0000001
```正しい答えは、`"NO"`最長ランはわずか6回だからです。 

例:```
10000000
```正しい答えは、`"YES"`最後の 7 文字はすべて`'0'`。 

中間位置のみを比較する実装では、誤って境界ランを見逃す可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、長さ 7 のすべての部分文字列を調べて、その中のすべての文字が同一かどうかを確認することです。 

すべての開始位置について、次の 7 文字を検査し、それらがすべて正しいかどうかを確認できます。`'0'`またはすべて`'1'`。 文字列の長さは最大 100 であるため、このアプローチは完全に十分に高速です。 最悪の場合、サイズ 7 のウィンドウを約 100 個検査するため、作業はおよそ 700 文字の比較になります。 

危険な状態はローカルの連続セグメントにのみ依存するため、ブルートフォースが機能します。 有効なランが存在する場合、長さ 7 の少なくとも 1 つのウィンドウに同一の文字が含まれている必要があります。 

より明確な観察により、実装がさらに簡素化されます。 ウィンドウを繰り返しチェックする代わりに、現在のストリークの長さを追跡しながら文字列を 1 回スキャンできます。 

現在の文字が前の文字と一致する場合、連続値を延長します。 それ以外の場合は、新しい実行が開始されたため、ストリークを 1 にリセットします。 連続数が 7 に達した瞬間、答えはすでにわかっています。`"YES"`。 

これにより、問題は定数メモリを使用した単純な線形探索に変わります。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 
2. カウンタの初期化`count = 1`最初の文字がすでに長さ 1 のストリークを形成しているためです。 
3. インデックス 1 から開始して文字列を走査します。 
4. 各位置について、現在の文字と前の文字を比較します。 
5. 等しい場合は増分します。`count`連続走行が続くからです。 
6. それ以外の場合はリセットします`count = 1`新しいストリークは現在のキャラクターから始まるためです。 
7. カウンタを更新した後、次のことを確認します。`count >= 7`。 
8. そうであれば、印刷します。`"YES"`危険な状況が発見されたので直ちに停止してください。 
9. このような縞が見つからずにループが終了した場合は、次のように出力します。`"NO"`。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`count`は常に、現在の位置で終了する現在の連続ランの長さと等しくなります。 

隣接する 2 つの文字が一致すると、ランは自然に 1 つ伸びます。 それらが異なる場合、前の実行が終了し、長さ 1 の新しい実行が始まります。 

文字列内のすべての連続したセグメントは 1 回だけ処理されるため、少なくとも 7 個の長さのランは最終的に`count`アルゴリズムがその値に到達しない場合、危険なセグメントは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

count = 1

for i in range(1, len(s)):
    if s[i] == s[i - 1]:
        count += 1
    else:
        count = 1

    if count >= 7:
        print("YES")
        break
else:
    print("NO")
```プログラムは文字列を読み取り、末尾の改行を削除することから始まります。`strip()`。 

変数`count`現在の連続シーケンスの長さを格納します。 単一の文字がすでに長さ 1 の有効なランを形成しているため、1 から始まります。 

すべての比較ではインデックス 1 からループが開始されます。`s[i - 1]`。 インデックス 0 から開始すると、無効なアクセスが発生します。 

隣接する文字が等しい場合、ストリークは 1 つずつ増えます。 それ以外の場合は、連続性が切れたため、ストリークがリセットされます。 

の`if count >= 7`check は、ストリークの長さを更新した直後にループ内に配置されます。 これにより、危険になるとすぐに走りをキャッチします。 

の`for ... else`ここで構造が役に立ちます。 の`else`ブロックは、ループが次のエラーに遭遇しない場合にのみ実行されます。`break`。 つまり印刷するということです`"NO"`危険なセグメントが見つからなかった場合のみ。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    s = input().strip()

    count = 1

    for i in range(1, len(s)):
        if s[i] == s[i - 1]:
            count += 1
        else:
            count = 1

        if count >= 7:
            print("YES")
            break
    else:
        print("NO")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue().strip()

# provided sample
assert run("001001\n") == "NO", "sample 1"

# custom cases
assert run("1111111\n") == "YES", "exactly seven consecutive ones"
assert run("0000001\n") == "NO", "six consecutive zeros only"
assert run("10000000\n") == "YES", "seven zeros at the end"
assert run("1010101010\n") == "NO", "alternating characters"
assert run("11111111\n") == "YES", "more than seven consecutive ones"
```| テスト入力 | 期待される出力 | 検証内容 |
