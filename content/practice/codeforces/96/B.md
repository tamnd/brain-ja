 ## 解決策
 ## 問題の理解

 次のような、指定された整数以上の最小の数値を見つける必要があります。 

1. すべての数字は次のいずれかです`4`または`7`。 
2. の数`4`s は次の数に等しい`7`s.

 これらの数字はスーパーラッキーナンバーと呼ばれます。 

例えば、`47`が含まれているため有効です`4`そして1つ`7`。 番号`7744`各桁が 2 つあるため、 も有効です。 番号`4447`カウントが異なるため無効です。 

入力には単一の整数が含まれています`n`、 まで`10^9`。 少なくとも次の最小の超ラッキーな数を出力する必要があります`n`。 

限界`n`が重要な観察です。 以来`10^9`は最大 10 桁であり、どの答えも少数の桁しかありません。 幸運な数字はまばらであるため、通常の整数に対する総当たり検索は依然としてひどいものになります。 すべての番号をチェックする`n`上向きに行うには、数百万回または数十億回の反復が必要になる可能性があります。 

ラッキーナンバーの構造は問題を完全に変えます。 有効な数値には次の値のみを含めることができます`4`そして`7`、カウントが一致する必要があるため、長さは偶数である必要があります。 最大でも 10 桁なので、候補の総数はごくわずかです。 

長さに関しては`2k`、どれを選択するかだけです。`k`位置に含まれる`4`。 残りのポジションは、`7`。 このような文字列の数は次のとおりです。$$\binom{2k}{k}$$最大 10 桁の長さの場合:$$\binom{2}{1} + \binom{4}{2} + \binom{6}{3} + \binom{8}{4} + \binom{10}{5} = 2 + 6 + 20 + 70 + 252 = 350$$候補者は全部で 350 人しかいません。 これは、すべての可能性を直接生成できるほど小さいです。 

いくつかのエッジケースでは、不注意なソリューションを静かに破壊する可能性があります。 

もし`n = 1`、答えは`47`。 同じ桁数を維持しようとする貪欲なアプローチは、1 桁の超ラッキーな番号が存在しないために失敗する可能性があります。 

もし`n = 999999999`、答えは次のようになります`4444477777`、より多くの桁があります`n`。 元の桁数に制限されたソリューションでは、これが見逃されます。 

もし`n`それ自体はすでに超幸運です、など`4477`、変更せずに返す必要があります。 厳密な使用法`>`代わりに比較`>=`誤ってスキップしてしまいます。 

もう 1 つの微妙なケースは、辞書編集的な順序です。 仮定する`n = 4500`。 有効な 4 桁の候補は次のとおりです。`4477, 4747, 4774, 7447, 7474, 7744`答えは`4747`。 単純な貪欲な構造は、最初の桁を誤って選択した後に行き詰まる可能性があります。 

## アプローチ

 最も直接的な強引なアイデアは、以下から始めることです。`n`各整数を 1 つずつテストします。 

すべての数値について、その桁を調べて次のことを確認します。 

1. すべての数字は`4`または`7`。 
2. の数`4`そして`7`マッチ。 

これは論理的には機能しますが、パフォーマンスは悲惨です。 幸運の数字は非常にまばらです。 その周り`10^9`、次の有効な整数を見つける前に、何百万もの通常の整数をスキャンする必要がある場合があります。 最大 10 億の値が考えられるため、このアプローチは現実的ではありません。 

重要な点は、回答スペース自体が小さいということです。 

超ラッキーな数字:

 1. 数字のみを使用する`4`そして`7`。 
2. 長さが均一である。 
3.ちょうど半分が入っています`4`半`7`s.

 すべての整数を検索する代わりに、すべての有効な候補を直接生成できます。 

偶数の長さごとに次のようになります。 

1. ポジションを選択します。`4`s.
 2. 残りの位置を次のように埋めます。`7`s.
 3. 結果の数字シーケンスを数値に変換します。 

必要な最大長はわずか 10 桁であるため、有効な候補の総数はわずか 350 です。 

それらを生成した後:

 1. リストを並べ替えます。 
2. 少なくとも次の最初の値を見つけます。`n`。 

これにより、問題は巨大な数値範囲の検索から、事前に計算された小さなセットの検索に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(答え - n) | お(1) | 遅すぎる |
 | 最適 | O(350 ログ 350) | O(350) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. すべての長さのスーパーラッキーナンバーを生成します`2, 4, 6, 8, 10`。 

これより長い長さは必要ありません。`n ≤ 10^9`、次に考えられる答えは 10 桁以内に収まります。 
3. 均等な長さごとに`L`、からすべてのバイナリ マスクを生成します。`0`に`(1 << L) - 1`。 

各ビットは、位置に次のものが含まれるかどうかを決定します。`4`または`7`。 
4. マスクに設定されているビット数を数えます。 

有効なスーパーラッキーナンバーには正確に含まれている必要があります`L / 2`に等しい桁`4`。 
5. 数字を一桁ずつ組み立てていきます。 

ビットが設定されている場合は、`4`。 それ以外の場合は配置します`7`。 
6. 構築された文字列を整数に変換して保存します。 
7. 生成されたすべての候補を並べ替えます。 

並べ替えにより、数値の昇順が保証されます。 
8. ソートされたリストをスキャンし、最初の番号を出力します。`x`そのような`x >= n`。 

### なぜ効果があるのか

 すべてのスーパーラッキーナンバーには次のような特徴があります。 

1. 均等な長さ。 
2. 桁のちょうど半分が以下に等しい`4`。 
3. 残りのすべての桁は以下に等しい`7`。 

アルゴリズムは、関連するすべての長さについてこれらの条件を満たすすべての文字列を生成します。 有効な候補はスキップされません。 

並べ替え後の最初の値以上`n`まさに最小の有効な答えです。 候補リストは完全で順序付けされているため、アルゴリズムはより小さい有効な数値を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lucky = []

    for length in range(2, 11, 2):
        half = length // 2

        for mask in range(1 << length):
            if bin(mask).count("1") != half:
                continue

            s = []

            for i in range(length):
                if (mask >> i) & 1:
                    s.append('4')
                else:
                    s.append('7')

            lucky.append(int("".join(s)))

    lucky.sort()

    for x in lucky:
        if x >= n:
            print(x)
            return

solve()
```このソリューションは生成戦略を直接実装します。 

外側のループは、2 から 10 までのすべての偶数の長さを反復します。この問題でスーパー ラッキー ナンバーに使用できる長さはこれらのみです。 

各ビットマスクは、数字の 1 つの割り当てを表します。 セットされたビットは数字を意味します`4`、設定されていないビットは数字を意味します`7`。 小切手:```
bin(mask).count("1") != half
```正確に半分を含まないマスクをフィルタリングして除外します。`4`s.

 数値は最初に文字列として構築されます。これは、その方が数字の連結が簡単でエラーが発生しにくいためです。 

マスクでは自然に番号順に数値が生成されるわけではないため、並べ替えは不可欠です。 

微妙な詳細の 1 つは比較です。```
if x >= n:
```平等が重要です。 もし`n`すでにとても幸運なので、すぐに返さなければなりません。 

もう 1 つの微妙な点は、答えの桁数がより多くなる可能性があることです。`n`。 例えば：```
999999999 -> 4444477777
```最大 10 までのすべての長さを生成すると、このケースが正しく処理されることが保証されます。
