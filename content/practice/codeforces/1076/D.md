 ## 解決策
 ## 問題の理解

 重み付けされた無向グラフが与えられ、最初に頂点 1 から最短経路の計算を実行することを想像します。これにより、すべての頂点の距離値が生成されます。これは、元のグラフでその頂点に到達するための真の最適コストと考えることができます。 

この後、エッジを削除できますが、合計で k 個を超えるエッジを保持することはできません。 グラフが縮小されたら、頂点 1 からの到達可能性を再度調べます。頂点 1 からその頂点までの、合計の重みが元の最短パス距離と一致する少なくとも 1 つのパスがまだ存在する場合、頂点は成功したとみなされます。 言い換えれば、距離を増やすことは許可されておらず、その頂点に対して少なくとも 1 つの最適なパスがそのまま残ることだけを考慮します。 

タスクは、最短パスを介してできるだけ多くの頂点に到達できるように、最大​​ k 個のエッジを選択することです。 

制約は大きく、最大 300,000 の頂点とエッジがあります。 これにより、多数の削除後に最短パスを再計算しようとしたり、エッジのサブセットを明示的に考慮したりするアプローチは即座に排除されます。 エッジの数が線形演算時間を超えると遅すぎるため、単一の最短パスの計算と貪欲な構築を期待する必要があります。 

複数の最短パスが存在する場合、微妙な問題が発生します。 最短パス ツリーを 1 つだけ保持する単純なアプローチでは、保持できる頂点の数が過小評価される可能性があります。これは、頂点が削除後に最適な状態を保つために複数の代替最短パスの親に依存する可能性があるためです。 

別のエッジ ケースは、保持されるエッジの数の制限 k から生じます。 たとえすべての最短パス エッジを保持できたとしても、いくつかは削除せざるを得なくなる可能性があるため、予算の制約の下でどの頂点を「残す」かを優先順位付けする必要があります。 

## アプローチ

 k の制約を無視した場合、すべての適切な頂点を保存するための自然な構造は、ノード 1 をルートとする最短パス DAG です。ダイクストラのアルゴリズムを使用して最短距離を計算すると、すべての頂点 i には、dist[u] + w = dist[i] となるような複数の入力エッジ (u, i) が含まれる可能性があります。 これらのエッジはまさに、最短経路上に存在できるエッジです。 

無制限のエッジが許可されている場合は、そのようなエッジをすべて保持することができ、最短パス DAG で到達可能なすべての頂点は良好なままになります。 これにより、すべての頂点が即座に保存されます。 

この難しさは、最大でも k 個のエッジを維持できるという制限によって生じます。 最短パス DAG には多くのエッジ (潜在的に O(m)) が含まれる可能性があるため、サブセットを選択する必要があります。 

重要な点は、すべての頂点を保持するためにすべての最短パス エッジが必要ないということです。 保持したいすべての頂点に、以前に到達した頂点からそこにつながる親エッジが少なくとも 1 つあることを確認するだけで済みます。 これは、完全な DAG ではなく最短パス ツリーを構築することを示唆しています。 

ノード 1 からダイクストラを実行し、最初に完成したときに頂点ごとに 1 つの親エッジを記録します。 これにより、正確に n − 1 個のエッジを持つ最短パス ツリーが得られ、すべての頂点は良好なままになります。 k ≥ n − 1 の場合、すでに作業は完了しています。 

k が n − 1 より小さい場合、完全なツリーを維持することはできません。 その場合、ダイクストラにおける発見順序の意味で、ルートに近い頂点を優先したいと考えます。 優先キューからポップされた順序で頂点を処理すると、最初の k 個の頂点 (ルートを除く) は、それらの頂点への最短パスを保証する接続された構造を与えます。これは、それぞれの頂点が、すでに処理されたノードの中から選択された最短パスの親を持っているためです。 

これが機能するのは、ダイクストラが、ノードが抽出されるとき、その最短距離が最終的なものであり、最短パスで使用される先行ノードは、以前のまたは等しい距離の状態からのものである必要があることを保証するためです。 したがって、抽出時に親エッジを安全に割り当ててツリーを段階的に構築できますが、k 個のエッジを選択した後で停止します。

強引なアイデアは、サイズ k のエッジのすべてのサブセットを試して、どの頂点が最適に到達可能であるかを確認することです。 それは m では指数関数的であり、実行不可能です。 

最適化されたアイデアは、ダイクストラを使用して最短パス ツリーを貪欲に構築し、ノードが確定した順序で最初の k ツリー エッジのみを選択してそれを切り詰めることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(2^m · (n + m)) | O(n + m) | 遅すぎる |
 | 最適 (ダイクストラ + 貪欲な木) | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点 1 からダイクストラを実行して、すべての頂点までの最短距離を計算します。 
このステップでは、保存したいすべての頂点の正確さを定義するターゲット値 d[i] を修正します。 

2. 空として初期化された配列parent_edge[i]を維持します。これには、各頂点に対して選択された 1 つの最短パス入力エッジが格納されます。 
到達可能性を確保するには、頂点ごとにそのようなエッジが 1 つだけ必要です。 

3. ダイクストラ中に、頂点 v がファイナライズされる (優先キューからポップされる) と、それを緩和するために使用されるエッジをその親エッジとして記録します。 
現時点では、dist[v] は最小で安定しているため、最短パスはすでに処理された構造を通過する必要があります。 

4. 頂点 2 から n までのすべての親エッジを、確定された順序で収集します。 
この順序により、ダイクストラ探索順序で近い頂点が優先されるようになります。 

5. 収集したエッジの数が k 以下の場合は、すべてを出力します。 
これは、接続を切断せずに完全な最短パス ツリーまたはそのサブセットを維持することに対応します。 

6. k 個を超えるエッジがある場合は、最初の k 個のエッジのみをこの順序で出力します。 
これにより、正確に k 個の頂点に対して有効なルート構造が維持され、各頂点が依然として最短パスで接続されていることが保証されます。 

### なぜ効果があるのか

 ダイクストラのアルゴリズムは、各頂点が距離の短い順に最終化されることを保証します。 ファイナライズ時に親エッジを割り当てると、そのエッジはソースからの最短パスの一部になります。 このような割り当てを最初の k 個に限定すると、選択した親を通る最短パスがそのまま残る k 個の頂点を効果的に選択することになります。 選択されたすべての頂点の親は以前に確定されているため、サイクルや無効な距離の再構成は発生せず、保持された各頂点は 1 からの正しい最短パスを保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

n, m, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for i in range(m):
    x, y, w = map(int, input().split())
    g[x].append((y, w, i + 1))
    g[y].append((x, w, i + 1))

INF = 10**30
dist = [INF] * (n + 1)
dist[1] = 0

parent_edge = [-1] * (n + 1)

pq = [(0, 1)]
visited = [False] * (n + 1)

order_edges = []

while pq:
    d, v = heapq.heappop(pq)
    if visited[v]:
        continue
    visited[v] = True

    if v != 1 and parent_edge[v] != -1:
        order_edges.append(parent_edge[v])

    for to, w, idx in g[v]:
        if dist[to] > d + w:
            dist[to] = d + w
            parent_edge[to] = idx
            heapq.heappush(pq, (dist[to], to))

if len(order_edges) > k:
    order_edges = order_edges[:k]

print(len(order_edges))
print(*order_edges)
```この実装は、標準の優先キューを使用したダイクストラに従います。 重要な詳細は、頂点ごとに、最適なリラクゼーションで使用されるエッジを保存することです。 頂点が初めてポップされると、そのエッジは応答リストにコミットされます。 この順序は、どの頂点を k エッジ制約の下に維持することを優先するかを定義します。 

よくある落とし穴は、ヒープからポップするときではなく、エッジを緩和するときに答えを更新することです。 暫定的な緩和ではまだ最適性が保証されていないため、これは正確性を損なうことになります。 もう 1 つの微妙な点は、古いヒープ エントリの処理を避けるために、訪問したノードを追跡する必要があることです。 

## 実用的な例

 ### 例 1

 入力:```
3 3 2
1 2 1
3 2 1
1 3 3
```1 からの最短距離を計算します。パス 1-2-3 を介して d2 = 1、d3 = 2 が得られます。 

ダイクストラ中は、ノード 2 が最初にファイナライズされ、次にノード 3 がファイナライズされます。 

| ステップ | ノード | 選択された親エッジ | 選択されたエッジ |
 |------|------|---------------------|----------------|
 | 1 | 1 | - | [] |
 | 2 | 2 | (1,2) エッジ 1 | [1] |
 | 3 | 3 | (2,3) エッジ 2 | [1,2] |

 k に一致する 2 つのエッジがすでにあるので、両方とも保持されます。 すべての頂点は良好なままです。 

### 例 2

 入力:```
4 4 2
1 2 1
2 3 1
3 4 1
1 4 10
```最短パスは 1-2-3-4 のチェーンです。 

| ステップ | ノード | 選択された親エッジ | 選択されたエッジ |
 |------|------|---------------------|----------------|
 | 1 | 1 | - | [] |
 | 2 | 2 | (1,2) | [1] |
 | 3 | 3 | (2,3) | [1,2] |
 | 4 | 4 | (3,4) | [1,2,3] |

 k = 2 なので、最初の 2 つのエッジのみを保持します。 ノード 2 と 3 は正常なままですが、ノード 4 は最短パスでは到達できなくなります。 

これは、貪欲な順序付けにより以前のダイクストラ層が優先されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(m log n) | 各エッジ緩和は優先キューを通じて 1 回処理されます。 
| スペース | O(n + m) | 隣接リストと距離および親ストレージ |

 この制約により、最大 3 × 10^5 のエッジが許可されるため、O(m log n) ダイクストラは、ヒープベースの実装を使用した Python の時間制限内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for i in range(m):
        x, y, w = map(int, input().split())
        g[x].append((y, w, i + 1))
        g[y].append((x, w, i + 1))

    INF = 10**30
    dist = [INF] * (n + 1)
    dist[1] = 0
    parent = [-1] * (n + 1)

    pq = [(0, 1)]
    vis = [False] * (n + 1)
    ans = []

    while pq:
        d, v = heapq.heappop(pq)
        if vis[v]:
            continue
        vis[v] = True
        if v != 1 and parent[v] != -1:
            ans.append(parent[v])

        for to, w, idx in g[v]:
            if dist[to] > d + w:
                dist[to] = d + w
                parent[to] = idx
                heapq.heappush(pq, (dist[to], to))

    if len(ans) > k:
        ans = ans[:k]

    out = [str(len(ans)), " ".join(map(str, ans))]
    return "\n".join(out).strip()

 ## 特殊なケース

 ゼロなどの最小の k 値は、アルゴリズムが正しい初期化を維持しながらエッジを安全に生成しないかどうかをテストします。 この場合、ルートを超える頂点は接続されたままになりますが、出力制約によりこれが可能になります。 

全結合スターでは、ダイクストラが最初にルートからすべてのエッジを選択することが保証され、k が大きい場合、早期の抽出順序によって高値の接続が正しく優先されることがわかります。 

長いチェーン グラフでは、各頂点が前の頂点に依存するため、順序付けが強調されます。 早期の切り詰めは、親チェーンが切断されると、より深い頂点の最短パスの保持が失われることを示しており、これはまさに問題のスコアリング関数が反映しているものです。
