 ## 解決策
 ## 問題の理解

 頂点 1 がルートとして機能し、すべての頂点が最初に値 0 を保持するルート付きツリーが与えられます。ツリーは静的ですが、一連の更新操作を処理するように求められます。 各操作で頂点が選択されます$v$、距離制限$d$、および値$x$、そして追加します$x$すべてのノードに$u$それはサブツリー内にあります$v$そしてせいぜい距離にある$d$から$v$。 

主要な幾何学的オブジェクトは標準のサブツリーではなく、その内部の切り詰められた領域です。 固定根から$v$、両方とも子孫であるノードにのみ影響します。$v$から測定された限られた深さの範囲内にあります。$v$。 

出力は、すべての更新が適用された後に各頂点に保存された最終値です。 

この制約により、クエリ集計ごとに線形または線形対数に近いソリューションが求められます。 まで$3 \cdot 10^5$ノードとクエリの場合、影響を受けるノードをクエリごとに明示的にアクセスするソリューションは、次のように縮退します。$O(nm)$、これは実現可能な限界をはるかに超えています。 クエリごとの DFS であっても受け入れられません。 

更新領域が重複すると、微妙な問題が発生します。 ノードは多くのクエリの影響を受ける可能性があり、各クエリはツリー構造内の軸が揃っていない領域に影響を与えるため、単純な伝播は困難になります。 

素朴なアプローチによる代表的な失敗例は、チェーン状のツリーです。 すべてのクエリが深い深さのルートをターゲットにしている場合、各クエリはほぼすべてのノードにアクセスし、二次的な動作が発生します。 もう 1 つの障害モードは、重複するクエリ範囲にわたって作業が重複する、深いノードのサブツリーを繰り返し再走査することです。 

## アプローチ

 ブルート フォース メソッドは定義に直接続きます。クエリごとに、から DFS を実行します。$v$、深さが超えると停止します$d$、と追加します$x$訪問したすべてのノードに送信されます。 これは、影響を受ける領域の定義を正確に列挙しているため、正しいです。 ただし、最悪の場合、各 DFS が$O(n)$ノードと$m$これはクエリになります$O(nm)$、これは大きすぎます$3 \cdot 10^5$。 

重要な観察は、各クエリは基本的に「ノードの周りのボールであるが、そのサブツリーに限定される」ということです。 これは深さによる分離を示唆しています。 ルートからの深さの観点からツリーを見ると、すべてのノードはちょうど 1 つの深さレベルに属し、サブツリー制約はオイラー ツアー順序付けの連続セグメントに対応します。 

重要なアイデアは、深さグループ化と組み合わせたツリーのオイラー ツアーを使用して寄与を処理することです。 各ノードについて$v$、そのサブツリーはオイラー順序で連続したセグメントになります。 そのセグメント内では、クエリは深さが制限された間隔内にあるノードにのみ影響します。$[depth[v], depth[v] + d]$。 

これにより、各クエリがオイラー間隔にわたる一連の範囲更新に変換されますが、深さによって分割されます。 深さレベルごとに個別の差分配列を維持することも、より効率的には、スイープのような DFS トラバーサルを使用して深さによる寄与を追跡するグローバル構造を維持することもできます。 標準ソリューションでは、トラバーサル中に DSU-on-tree または深さインデックス付きのフェンウィック スタイルの蓄積を使用します。クエリ効果を開始深さでプッシュし、サブツリーを出た後に削除します。 

これにより、各クエリが次のように削減されます。$O(1)$ノードごとに 1 回クエリされる構造の償却更新。

 | クエリごとのブルート フォース DFS |$O(nm)$|$O(n)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、各ノードの 2 つの主要な属性 (ルートからの深さとオイラー ツアー間隔) を計算します。$[tin, tout]$ここで、ノードのサブツリーは連続したセグメントに対応します。 

次に、各クエリを再解釈します。 クエリ$(v, d, x)$すべてのノードに影響を与える$u$そのような$u$のサブツリーにあります$v$そして$depth[u] \le depth[v] + d$。 同様に、申請するだけで済みます。$x$オイラーセグメントのノードへ$[tin[v], tout[v]]$ただし、深さが上限を満たしている場合に限ります。 

これを効率的に管理するために、DFS 順序でノードを処理し、深さによってインデックス付けされたアクティブなコントリビューションを集約する構造を維持します。 

1. ルートから DFS を実行して、深さとオイラーの入口/出口時間を計算します。 このステップでは、サブツリー クエリを間隔クエリに変換します。 
2. 各ノードについて$v$、それに添付されたクエリを保存しますが、「値をアクティブ化」として書き換えられます。$x$深さで$depth[v]$、深度の後に非アクティブ化されます$depth[v] + d + 1$」 非アクティブ化は概念的なものであり、限定的な影響を保証します。 
3. 深さごとにアクティブな貢献の累積合計を追跡するグローバル構造を維持します。 ツリーをトラバースするときに、ノードに入るときにこの構造を更新し、そのサブツリーから出るときに元に戻ります。 
4. DFS トラバーサル中、ノードにアクセスするとき$u$、深度での現在の累積値をクエリします。$depth[u]$。 この値は、制約が対象とするすべてのアクティブなクエリの合計を正確に表します。$u$。 
5. この値を次の答えに追加します。$u$、その後、子へのトラバースを継続し、アクティブな状態を一貫して維持します。 

中心的なアイデアは、クエリごとに影響を受けるノードを明示的に訪問するのではなく、クエリを下方向に伝播し、各ノードがその深さに関連する寄与を「収集」できるようにするということです。 

### なぜ効果があるのか

 DFS 内のどの時点でも、アクティブなコントリビューションのセットは、ソース ノードが現在のノードの祖先であり、深さの制約によってまだ包含が許可されているクエリに正確に対応します。 オイラー走査ではサブツリーの境界が尊重されるため、クエリが意図したサブツリーの外に漏れることはありません。 各ノードは、アクティブな深さ制限のある更新の正しいマルチセットに対して 1 回だけ評価されるため、累積された値は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

m = int(input())
queries = [[] for _ in range(n + 1)]

for _ in range(m):
    v, d, x = map(int, input().split())
    queries[v].append((d, x))

depth = [0] * (n + 1)
ans = [0] * (n + 1)

# We maintain a map from depth -> current sum of active contributions
from collections import defaultdict
active = defaultdict(int)

def dfs(u, p):
    # activate queries at node u
    for d, x in queries[u]:
        active[depth[u]] += x
        active[depth[u] + d + 1] -= x

    ans[u] += active[depth[u]]

    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

    # rollback
    for d, x in queries[u]:
        active[depth[u]] -= x
        active[depth[u] + d + 1] += x

dfs(1, -1)

print(*ans)
```DFS は深さを計算し、親から子の順序でツリーを走査し、サブツリー構造が確実に尊重されるようにします。 の`active`辞書は、深さインデックス付きの差分配列として機能します。各クエリは、開始深度で正の寄与を挿入し、許容される深さの範囲を超えるとそれをキャンセルします。 

微妙な点は、オイラー ツアー インデックスを決して明示的に維持しないことです。これは、DFS 再帰自体が、サブツリー内にいるときはすべての祖先ベースのアクティブ化が有効なままであることを保証し、ロールバックによってサブツリー スコープ外への漏洩がないことを保証するためです。 

各ノードの答えは、その深さに適用される寄与のみを使用して、訪問の瞬間に計算されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    m = int(input())
    queries = [[] for _ in range(n + 1)]
    for _ in range(m):
        v, d, x = map(int, input().split())
        queries[v].append((d, x))

    depth = [0] * (n + 1)
    ans = [0] * (n + 1)

    from collections import defaultdict
    active = defaultdict(int)

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        for d, x in queries[u]:
            active[depth[u]] += x
            active[depth[u] + d + 1] -= x

        ans[u] += active[depth[u]]

        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)

        for d, x in queries[u]:
            active[depth[u]] -= x
            active[depth[u] + d + 1] += x

    dfs(1, -1)
    return " ".join(map(str, ans[1:]))

 ## 特殊なケース

 単一ノードを持つ最小ツリーは、アルゴリズムが子への再帰なしでルートでのアクティブ化と評価を正しく処理するかどうかをテストします。 その場合、DFS はノード 1 にアクセスし、深さ 0 ですべてのクエリ効果を適用し、伝播の問題を発生させることなく最終値を直接生成します。 

ディープチェーンは、深さのインデックス作成が範囲内のノードと範囲を超えるノードを正しく区別するかどうかをテストします。 DFS が深くなると、深さのしきい値を超えた時点で寄与分が期限切れになり、許容距離を超えたノードが誤って値を蓄積することがなくなります。 

同じノードで重複するクエリがある場合、同じ深さでの複数のアクティベーションが正しくスタックされることが確認されます。`active`これは、子孫によってクエリされる前に、すべての増分が同じ深さのバケットに蓄積されるためです。
