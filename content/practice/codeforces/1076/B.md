 ## 問題の理解

 単一の大きな整数が与えられ、それを常に減らす決定論的なプロセスを繰り返し適用します。 各ステップで、現在の数値を検査し、その最小の素因数を見つけて、数値からその素因数を減算し、値がゼロになるまで続けます。 タスクは、プロセスが終了するまでにそのような減算ステップが何回発生するかを決定することです。 

入力サイズは次のとおりです$10^{10}$これは、単純な試行除算を使用してすべてのステップで数値をゼロから因数分解しようとするアプローチを即座に除外します。$n$。 までのリニアスキャン$n$実行可能な限界をはるかに超えており、繰り返しごとに平方根因数分解を繰り返す場合でも、回数が多すぎると境界線になってしまいます。 

重要な点は、反復回数が次のような小さなものによって制限されないことです。$\log n$。 最悪の場合、小さな素数による減算が繰り返されると、長いチェーンが作成される可能性があります。 ただし、各ステップは厳密に減少します$n$、そしてもっと重要なことは、一度$n$が偶数になると、その最小の素約数は 2 で安定し、長い決定論的な半分のシーケンスが作成されます。 

各ステップで素数または最小素約数を非効率的に再計算すると、単純な間違いが発生します。 たとえば、次の値までのすべての数値をチェックして約数を再計算すると、$n$、入力さえも$n = 10^{10}$処理することは不可能でしょう。 もう 1 つの微妙な失敗モードは、奇数の素数を減算した後、数値が偶数になり、最小の約数が劇的に変化する可能性があることを忘れていることです。 

## アプローチ

 ブルート フォース シミュレーションはルールに直接に従います。反復ごとに、現在の数値の最小の約数が見つかるまで 2 から上に向かってスキャンし、それを減算して繰り返します。 これはプロセスを正確に反映しているため、これは正しいです。 ただし、最大の除数をスキャンして最小の除数を見つけます。$\sqrt{n}$各ステップでは、最悪の場合の複雑さが生じます。$O(n \sqrt{n})$もし$n$ゆっくりと減少しますが、これは遅すぎます。$10^{10}$。 

重要な観察は、実際には各ステップで完全な因数分解を必要としないということです。 必要なのは最小の素約数だけです。 数値が偶数かどうかを検出すると、答えが 2 であることがすぐにわかります。それ以外の場合は、奇数の約数をチェックするだけで済みます。$\sqrt{n}$。 以来$n$奇数の場合は少なくとも 2 減少し、偶数の場合は半分に減少しますが、コストのかかる因数分解の数は実際には少ないままです。 これにより、問題は、完全に繰り返される因数分解ではなく、制御された一連の素数形式のチェックに変わります。 

ほとんどの長いシーケンスは数値が偶数になると発生し、コストのかかる再計算を行わずに繰り返し 2 を減算するため、この構造は効率的になります。

 ## アルゴリズムのチュートリアル

 1. 指定された番号から開始します$n$。 操作のカウンターをゼロに初期化します。 各演算は、現在の最小の素約数の 1 回の減算に対応します。 
2. その間$n > 0$、の最小の素約数を決定します。$n$。 可能な限り最小の候補が 2 からテストされますが、より小さい因数はすでに素数である必要があるため、最初に見つかった約数で停止できます。 
3. 最小の約数が得られたら$d$が特定されたら、それを差し引きます$n$。 操作カウンタを 1 つ増やします。 これは、まさに説明したプロセスの 1 つのアプリケーションを反映しています。 
4. まで繰り返します。$n$ゼロになります。 

効率性の重要なポイントは、それを検出したら、$n$は偶数であるため、すぐにわかります$d = 2$それ以上確認せずに。 奇数の場合のみ、奇数の候補による試行除算が必要です。$\sqrt{n}$。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムはプロセスを定義する正確なルールを複製します。 唯一の最適化は最小の素約数を見つける方法ですが、減算の順序は変更されず、減算を特定する速度のみが変わります。 最小の素約数は一意であり、反復ごとに常に 1 回だけ減算されるため、プロセスとそのカウントは元の定義と同じままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def smallest_prime_divisor(x: int) -> int:
    if x % 2 == 0:
        return 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return i
        i += 2
    return x  # x is prime

n = int(input().strip())
cnt = 0

while n > 0:
    d = smallest_prime_divisor(n)
    n -= d
    cnt += 1

print(cnt)
```コア関数は、最小の素約数を分離します。 偶数の場合は、常に 2 が可能な最小の素因数であるため、すぐに処理されます。 奇数の場合は、平方根までの奇数の候補のみをテストします。これは、合成数にはその範囲内の因数が含まれている必要があるためです。 

メインループはプロセスを直接実装します。 反復ごとに減少します$n$厳密には終了を保証します。

 ## 特殊なケース

 のために$n = 2$の場合、アルゴリズムはすぐに 2 を最小の素約数として特定し、それを 1 回減算してゼロで終了します。 これにより、最小入力サイズが正しく処理されることが確認されます。 

次のような素数の場合$n = 11$、最小の約数は数値そのものなので、プロセスは 1 つのステップで終了します。 これにより、アルゴリズムがより小さな存在しない要素を誤って検索しないことがチェックされます。 

次のような偶数の場合$n = 10$、最初の減算後は 8 になり、その後 2 の減算がゼロになるまで繰り返し続けられます。 これにより、アルゴリズムが再計算エラーなしで除数 2 で正しく安定していることが検証されます。
