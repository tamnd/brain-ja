 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、それに非常に具体的な変換を繰り返し適用します。 1 つの変換ステップで、各要素がそれ自体を除く配列内の他のすべての要素の合計になるように、すべての位置が同時に更新されます。 

この変換を正確に実行した後、$k$2 つの要素間の最大絶対差として測定される、最終的な配列値の広がりを計算するよう求められる場合があります。 

演算を再解釈する重要な方法は、配列の合計に注目することです。 現在の合計を次のようにします$S$。 1 回の操作の後、各要素は$a_i$になる$S - a_i$。 これは、すべての値が非常に構造化された方法で現在の合計の周囲に反映されていることを意味し、配列の進化が無秩序ではなく非常に規則的であることを示唆しています。 

制約があるため、この観察は重要になります。 操作数$k$非常に大きくなる可能性があり、最大で$10^9$, そのため、プロセスを段階的にシミュレートすることは不可能です。 すべてのテスト ケースを合計すると、操作ごとに 1 つのパスでもすでに制限時間を超えてしまいます。 これにより、変換を明示的に繰り返し適用することに依存するアプローチは即座に除外されます。 

重要なもう 1 つの制約は、すべてのテスト ケースにわたる要素の合計数が最大であることです。$2 \cdot 10^5$。 これは、私たちが目指すべきことを示唆しています。$O(n)$または$O(n \log n)$テスト ケースごとにソリューションを実行します。理想的には、前処理後にテストごとに一定時間の処理を行います。 

微妙なエッジケースが現れるのは、$n = 1$。 その場合、この操作では、唯一の要素が他のすべての要素の合計 (ゼロ) に置き換えられます。 しかし、「他の要素」がないので、和はゼロとなり、永遠にゼロのままです。 これは、次の条件に関係なく、答えは常にゼロであることを意味します。$k$。 不要な計算や不正な変換を避けるために、どのソリューションでもこのケースを明示的に処理する必要があります。 

2 番目の重要なエッジ ケースは、すべての要素が等しい場合です。 1 回の操作の後、各要素は次のようになります。$(n-1)x$、したがって配列は均一のままです。 最大値と最小値の差はゼロのままであり、これはその後のすべての操作に当てはまります。 

興味深い動作は値が異なる場合にのみ現れます。重要な課題は、変換を繰り返すと要素間の違いがどのように変化するかを理解することです。 

## アプローチ

 ブルート フォース シミュレーションにより、変換が直接適用されます。$k$回。 各操作で合計が再計算され、配列が再構築されます。$O(n)$、全体的に複雑になります$O(nk)$。 と$k$まで$10^9$、これはまったく不可能です。 

重要な洞察は、個々の要素の絶対値ではなく、個々の要素が互いにどのように関係しているかを追跡することです。 1 つの演算を展開すると、各要素は次のようになります。$S - a_i$、これは以下と同等です$(n-1)\cdot \text{mean of array} - (a_i - \text{mean})$線形変換まで。 さらに重要なことは、最終的な答えにとって重要なのは、絶対値ではなく、2 つの位置の差であるということです。 

2つの要素を考えてみましょう$a_i$そして$a_j$。 1 回の操作の後、それらの違いは次のようになります。$$(S - a_i) - (S - a_j) = a_j - a_i$$したがって、差は符号を反転しますが、大きさは維持されます。 

2 回の操作の後、差は再び反転し、元の符号に戻ります。 これは、ペアごとの差分の構造が周期 2 で周期的であることを意味します。配列全体が 2 つの状態の間で切り替わります。元の配列と、各値が次のように変換されたバージョンです。$S - a_i$。 

したがって、問題は、以下に応じて最大 2 つの状態を評価することになります。$k$偶数または奇数です。 

次のように計算します。 

- もし$k$が偶数の場合、配列構造はオリジナルと同等です。 
- もし$k$が奇数の場合、各要素は次のようになります$S - a_i$、 どこ$S$は最初の合計です。 

そこから、最大の差を計算するのは簡単です。対応する状態の最大と最小の差を取るだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(nk)$|$O(n)$| 遅すぎる |
 | パリティ観測（2状態システム） |$O(n)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、その合計を計算します。$S$、およびその最小値と最大値。 変換は次の要素のみに依存するため、これら 3 つの値はシステムの可能な両方の状態を完全に決定します。$S$そして個々の要素。 
2. もし$n = 1$、すぐに 0 を出力します。要素が 1 つある場合、変換では常に 0 が生成され、変化はありません。 
3. もし$k$が偶数である場合、アレイは元の構成を効果的に維持していることがわかります。 最大の差は単純に$\max(a) - \min(a)$構造的な変更が相対的な順序に影響を与えないためです。 
4. もし$k$が奇数の場合、各要素は次のようになります$S - a_i$。 この変換された配列では、最大の要素は次のようになります。$S - \min(a)$、最小値は次のようになります。$S - \max(a)$。 この逆転は、減算によって順序が逆になるために発生します。 
5. 変換された状態の差を計算します。$$(S - \min(a)) - (S - \max(a)) = \max(a) - \min(a)$$したがって、数値的には差は変わりません。 
6. この計算された差を出力します。 

これが機能する理由は、各操作が配列値にアフィン変換を適用するという事実に根ざしています。 値自体は大きく変化しますが、すべてのペアごとの差は符号が変わるだけで、大きさが変わることはありません。 この問題では最大絶対差のみが求められるため、システムは 2 つの交互の状態に崩壊し、それ以上の反復は無意味になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))

        if n == 1:
            print(0)
            continue

        total = sum(arr)
        mn = min(arr)
        mx = max(arr)

        if k % 2 == 0:
            print(mx - mn)
        else:
            # transformed array would be S - a[i]
            # min becomes S - mx, max becomes S - mn
            print((total - mn) - (total - mx))

if __name__ == "__main__":
    solve()
```この実装は、中間配列を明示的に構築しないという観察に従っています。 私たちは集計統計のみを追跡します。 唯一の微妙な点は、パリティの処理です。$k$これは、元の配列を評価するか、その変換されたバージョンを評価するかを決定するためです。 

表現`(total - mn) - (total - mx)`正しい変換された最大値から変換された最小値を引いた値を反映するように慎重に順序付けされます。 これを代数的に展開すると、単純化されて次のようになります。`mx - mn`ただし、この形式にしておくことでロジックが明確になり、問題の変形にアイデアを適応させる際の間違いを避けることができます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$テストケースごと | 合計、最小、最大を配列ごとに 1 回計算します。 
| スペース |$O(1)$番外編 | スカラー集合体のみが格納されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []

    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if n == 1:
            out.append("0")
            continue

        s = sum(a)
        mn, mx = min(a), max(a)

        if k % 2 == 0:
            out.append(str(mx - mn))
        else:
            out.append(str((s - mn) - (s - mx)))

    return "\n".join(out)

 ## 特殊なケース

 のために$n = 1$の場合、差を形成する要素のペアがないため、アルゴリズムはすぐにゼロを出力します。 変換は定数ゼロのシーケンスに縮退するため、これ以上の推論は必要ありません。 

すべての要素が等しい配列の場合、すべての変換により、次のようにスケールされた別の均一な配列が生成されます。$n-1$、ゼロスプレッドを維持します。 計算された最大値と最小値はゼロのままで、偶数と奇数の両方の正解と一致します。$k$。 

大型用$k$、ソリューションは操作を決してシミュレートしません。 代わりに、完全にパリティに依存するため、次のような値になります。$10^9$実行時間や正確さには影響しません。
