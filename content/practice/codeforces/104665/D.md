 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、次のサイズの正方形のチェス盤です。$N \times N$。 各セルは整数の座標によって識別され、単一のナイト ピースは 1 つのセルから始まり、ターゲット セルはボード上の他の場所に固定されます。 ナイトは標準的なチェスのルールを使用して動きます。つまり、各動きは 8 つの可能な L 字型オフセットの 1 つによって位置を変更します。 

タスクは、開始セルからターゲット セルまで移動するために必要なナイトの最小移動数を計算するか、ターゲットにまったく到達できないと判断することです。 

ボードサイズは最大でも可能ですが、$800 \times 800$、基礎となる構造は最大 640,000 個のノードを含むグラフであり、各ノードには最大 8 つのエッジがあります。 これは、ボードを探索するアルゴリズムがセル数に対してほぼ直線的に動作する必要があり、そうでないと時間内に終了しないことを直ちに示唆しています。 

ステートを何度も再訪する直接検索では、考えられるパスの数が深さに応じて指数関数的に増加するため、時間がかかりすぎます。 一方、均一なエッジコストを持つ重み付けされていないグラフ上の最短経路問題は、当然ながら幅優先探索に適しています。 

微妙な点は到達可能性です。 ナイトは移動ごとに正方形の色を交互に切り替えます。これは、移動ごとにパリティが変化するためです。$x + y$。 開始位置と終了位置のパリティが異なる場合、答えは即座に不可能になります。 たとえば、次から始まります$(0,0)$そして到達しようとしている$(1,0)$どのようなボードサイズでも$-1$というのは、ナイトが移動するたびにパリティが反転し、ナイトは偶数回移動した後は同じパリティ クラスに留まることはできないからです。 

開始位置と終了位置が同じ場合には、別のエッジ ケースが発生します。 この場合、移動する必要はなく、答えはゼロです。 これを明示的に処理しない単純な BFS はまだ機能する可能性がありますが、少なくとも 1 つの拡張を前提とした不適切な実装は失敗する可能性があります。 

## アプローチ

 簡単なアイデアは、各ボード セルをグラフ内のノードとして扱い、開始位置から検索を実行することです。 各ノードから 8 つのナイトの動きをすべて試し、ターゲットに到達するまで続けます。 このブルートフォース探索は、基本的に、考えられるすべての動きシーケンスを探索することです。 

このアプローチは、最終的には到達可能なすべての位置を列挙するため正しいですが、注意深い構造を持たないと、異なるパスを介して同じセルを繰り返し訪問する可能性があります。 最悪のケースでは、各位置が最大 8 つの次の状態に分岐するため、長さが増加する指数関数的な数のパスを探索することになります。 

重要な観察は、すべての移動のコストが等しいということです。 これにより、問題は重み付けされていないグラフで最短経路を見つけることに変わります。 このようなグラフでは、幅優先検索により、最初にノードに到達したときに、そのノードへの最短パスが見つかることが保証されます。 これにより、高コストで状態を再検討することが回避され、各ノードが最大 1 回処理されることが保証されます。 

ナイトの動きグラフの構造は固定されており、まばらであるため、BFS は最大ボード サイズでも効率的に実行されます。

 | --- | --- | --- | --- |

 | BFS 最短パス | O(N^2) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 問題をグラフ走査に変換します。$(x, y)$はノードであり、ナイトの各移動は別のノードへのエッジを定義します。 この再構成が必要なのは、もはや幾何学的に推論するのではなく、重み付けされていないグラフ内の最短経路の観点から推論しているからです。 
2. 開始位置と目標位置が同じかどうかを確認します。 そうである場合、移動は必要なく、BFS が不要な作業を実行するため、答えは直ちにゼロになります。 
3. を使用して座標のパリティを確認します。$(x + y) \bmod 2$。 開始とターゲットのパリティが異なる場合は、戻り値を返します。$-1$すぐに。 これは、各ナイトの動きがパリティを反転させるため、ボードのサイズに関係なく、反対のパリティに到達することは不可能であるという事実に基づいています。 
4. サイズの距離グリッドを初期化します。$N \times N$、次のようなセンチネル値が入力されます。$-1$、未訪問のセルを意味します。 このグリッドは、これまでに発見された各セルまでの最短距離を追跡します。 
5. 開始位置をキューにプッシュし、その距離をゼロに設定します。 キューは BFS フロンティアを表し、常に距離の増加順に拡張します。 
6. キューが空でない間に、前のセルをポップし、そこから 8 つのナイトの動きをすべて試します。 各候補セルについて、それがボード内にあるか、まだ訪問されていないかを確認します。 両方の条件が当てはまる場合、その距離を現在の距離に 1 を加えたものとして割り当て、キューにプッシュします。 これにより、各ノードが可能な限り最短のパスを介して検出されるようになります。 
7. 拡張中にターゲット セルに到達した場合は、BFS によって最初にターゲット セルに到達するのが最適であることが保証されるため、早期に停止します。 

### なぜ効果があるのか

 BFS は、最初から距離が増加するレイヤーでノードを処理します。 あるレイヤーから次のレイヤーに移動するたびに、パスの長さは 1 移動分だけ増加します。 各エッジの重みは等しいため、ノードを訪問した後は、そのノードへの短いパスは表示されません。 したがって、訪問距離グリッドには、開始点から到達可能なすべてのセルまでの真の最短距離が格納されます。 パリティ枝刈りは、不可能なケースを除去するだけであり、到達可能性の必要条件であるため、正確さには影響しません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    if (x1, y1) == (x2, y2):
        print(0)
        return

    if (x1 + y1) % 2 != (x2 + y2) % 2:
        print(-1)
        return

    moves = [
        (2, 1), (2, -1), (-2, 1), (-2, -1),
        (1, 2), (1, -2), (-1, 2), (-1, -2)
    ]

    dist = [[-1] * n for _ in range(n)]
    q = deque()
    q.append((x1, y1))
    dist[x1][y1] = 0

    while q:
        x, y = q.popleft()
        if (x, y) == (x2, y2):
            print(dist[x][y])
            return

        for dx, dy in moves:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n and dist[nx][ny] == -1:
                dist[nx][ny] = dist[x][y] + 1
                q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、挿入と削除の両方が実行されるように、両端キューを使用して BFS キューを維持します。$O(1)$。 距離配列により、各セルが 1 回だけ処理されることが保証され、異なるパスを介して同じ位置を繰り返し探索することが防止されます。 境界チェックは、私たちがボードから離れることがないことを保証します。 

パリティ チェックは、答えが不可能であることがわかっている場合に不必要なメモリ割り当てとトラバーサルを回避するために、早めに実行されます。

 ## 特殊なケース

 開始値がターゲットと等しい場合、通常、BFS ループはキューを初期化して拡張を開始しますが、正しい動作はすぐにゼロを返すことです。 アルゴリズムは処理の前にこれを明示的にチェックするため、不必要なトラバーサルは発生しません。 

スタートとターゲットのパリティが異なる場合、BFS はターゲットに到達することなく接続コンポーネント全体を探索します。 大規模なボードではこれは時間を無駄にしますが、パリティ チェックは不可能を即座に検出します。 たとえば、次のように入力します。```
8
0 0
1 0
```返品$-1$すぐにだから$(0+0)\%2 \neq (1+0)\%2$。 

のような最小限のボードでは、$1 \times 1$、唯一の有効な位置は$(0,0)$。 他のターゲットは無効であり、BFS は有効な移動をキューに入れることはありません。 生成されたすべての手がグリッドの外側にあり、境界チェックによって破棄され、キューが空のままになり、$-1$開始とターゲットが等しい場合を除きます。
