 ## 解決策
 ## 問題の理解

 位置 0 から始まり、次のように進化するプロセスが与えられています。$T$ステップ。 毎秒、ポジションを 1 ずつ増やすか、1 ずつ減らします。時間の経過に伴う一連のポジションは、0 から始まる整数のウォークを形成します。下向きの移動が許可されているため、ウォークはマイナスになる可能性がありますが、私たちが気にするのは、それがどのくらい高くなるかだけです。 

各テスト ケースについて、長さを数えるよう求められます。$T$のシーケンス$+1$そして$-1$ステップにより、すべてのプレフィックスの最大値が正確に一致するウォークが生成されます。$M$。 最大値には時間 0 の開始点が含まれるため、$M > 0$、歩行は水平に到達する必要があります$M$少なくとも 1 回、それを超えてはなりません$M$。 

制約は特定の点で厳しいです。$T$最大 2000 ですが、テスト ケースの数は最大です。$10^5$。 これにより、すぐに前処理ベースのソリューションが強制されます。 テストごとの動的プログラミングはすべて終了$T^2$さらに悪いことに、単純に繰り返すと遅すぎます。 すべての答えを事前に計算するメソッドが必要です。$(T, M)$一度ペアリングします。 

単純なカウントについて考えると、微妙な問題が生じます。 すべての歩行をシミュレートし、その最大値を追跡しようとすると、次のようになります。$2^T$テストケースごとの可能性。 たとえ$T = 30$、これは不可能になります。 もう 1 つの潜在的な間違いは、「最大値と等しい」を扱おうとすることです。$M$」を「で終了」として$M$「それは間違いです。歩いて行ける距離にあります」$M$、その後下に戻り、はるか下で終了します$M$、依然として最大値を正確に保持しながら$M$。 

## アプローチ

 ブルートフォースのアイデアは簡単です。次のすべてのシーケンスを生成します。$+1$そして$-1$、ウォークをシミュレートし、最大プレフィックス値を計算し、最大値が等しいものをカウントします。$M$。 これは定義と直接一致するため、正しいです。 問題は、すべてを探索することです$2^T$パスと$T = 2000$、テスト ケースが 1 つだけでも、これは完全に不可能になります。 

問題の構造は、最大値に境界条件がある古典的なランダム ウォークを示唆しています。 すべてのパスを追跡するのではなく、最大値の制約を尊重しながら、特定の位置で終了できる方法が何通りあるかを追跡します。 これにより、時間と位置に応じた動的プログラミングが自然に行われます。 

重要な観察は、「最大値が正確に一致する」という条件を変換することです。$M$” を 2 つの単純な条件の差に置き換えます。$F(T, M)$長さの歩行の数になります$T$その最大値は最大です$M$。 次に、最大値が正確に一致する四球の数$M$は：$$F(T, M) - F(T, M-1)$$したがって、問題全体はコンピューティングに帰着します$F(T, M)$。 

ここでは、上限を超えない四球をカウントするだけで済みます。 これは標準の有界ランダム ウォーク DP です。 させて：$$dp[t][x]$$位置に到達する方法の数になります$x$時に$t$、パスが上に到達することはありません$M$。 移行は通常通りです。$$dp[t][x] = dp[t-1][x-1] + dp[t-1][x+1]$$しかし、私たちは次のような州を禁止します$x > M$。 

なぜなら$T \le 2000$、位置も次のように制限されます。$-T$そして$T$、つまりDPは$O(T^2)$。 すべてを事前計算します$F(T, M)$みんなのために$T, M$で質問に答えます。$O(1)$。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^T)$テストごと |$O(T)$| 遅すぎる |
 | 最適なDP |$O(T^2)$事前計算 +$O(1)$クエリごと |$O(T^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 2000 までのすべての長さの答えを事前計算します。 

1. DP テーブルを初期化します。$dp[t][x]$位置にある方法の数を表します$x$後$t$計算中に選択された上限を超えることなくステップを実行できます。 位置 0 がインデックスにマップされるようにインデックスをシフトします。$T$。 
2. 固定された上限ごとに$M$、上記の状態が存在する場合の有界 DP を計算します。$M$は無効です。 これは、ポジションのみを許可することを意味します$\le M$。 禁止状態への遷移は 0 になります。 
3. から始める$dp[0][0] = 1$。 これは空の散歩を表します。 
4. 1 から 1 までの各時間ステップについて$T$、前のタイム ステップからの遷移を使用して、到達可能なすべての位置を更新します。 各位置は、隣接する 2 つの位置からの寄与を蓄積します。 ポジションが境界を超えた場合$M$、スキップします。 
5. DPを時間まで充填した後$T$、それぞれの有効なエンドポイント数をすべて合計します。$T$そして縛られた$M$。 これにより、$F(T, M)$を超えない四球数$M$。 
6. 事前計算$F(T, M)$みんなのために$M$0 から 2000 まで。次に、次を使用して正確な答えを導き出します。$$ans(T, M) = F(T, M) - F(T, M-1)$$### なぜ効果があるのか

 各状態が一意のプレフィックス終了位置をエンコードしているため、DP はすべての有効なウォークを 1 回だけ列挙します。 制約は「決して超えない」$M$「」は各遷移でローカルに適用されるため、無効なパスがカウントに入ることができません。すべての有効なパスは一度に何らかのエンドポイントに到達する必要があるため、$T$、すべての DP 状態を合計すると、すべての有効なウォークがキャプチャされます。 減算ステップでは、決して超えないものを削除します。$M-1$、最大値が であるものだけを残します。$M$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXT = 2000

# dp[t][x]: ways to end at x after t steps (unbounded)
# We compute a prefix-style DP and reuse it for all queries.

dp = [[0] * (2 * MAXT + 1) for _ in range(MAXT + 1)]
offset = MAXT

dp[0][offset] = 1

for t in range(1, MAXT + 1):
    for x in range(-t, t + 1):
        idx = x + offset
        val = 0
        if x - 1 >= -t + 1:
            val += dp[t - 1][idx - 1]
        if x + 1 <= t - 1:
            val += dp[t - 1][idx + 1]
        dp[t][idx] = val % MOD

# prefix sums over max constraint:
# best[t][m] = number of walks of length t with max <= m
best = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]

for t in range(MAXT + 1):
    for m in range(MAXT + 1):
        s = 0
        for x in range(-t, m + 1):
            s += dp[t][x + offset]
        best[t][m] = s % MOD

# convert to exact maximum
ans = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
for t in range(MAXT + 1):
    for m in range(MAXT + 1):
        if m == 0:
            ans[t][m] = best[t][0]
        else:
            ans[t][m] = (best[t][m] - best[t][m - 1]) % MOD

q = int(input())
for _ in range(q):
    t, m = map(int, input().split())
    print(ans[t][m] % MOD)
```このソリューションでは、まず、時間と位置によってインデックス付けされた標準のランダムウォーク DP テーブルを構築します。 範囲はオフセットを使用して中央に配置されるため、負の位置は有効な配列インデックスにマップされます。 

次に、指定された最大値を決して超えない歩行の累積数を計算します。$m$。 これは、許可された領域内にあるすべてのエンドポイントの状態を合計することによって行われます。 この実装では明示的な合計を使用しますが、概念的なオブジェクトは次のとおりです。$F(T, M)$、制限された最大数。 

最後に、差分演算を使用して累積カウントを正確な最大カウントに変換します。 これは、「最大等しい」制約をプレフィックスの違いによって計算可能なものに変える重要な変換です。 

## 実用的な例

 ### 例 1

 入力:```
1
1 1
```長さ 1 のすべての歩行を考慮します。考えられるシーケンスは次のとおりです。$+1$そして$-1$。 

| ステップ | パス | 最大値 |
 | --- | --- | --- |
 | +1 | [0, 1] | 1 |
 | -1 | [0, -1] | 0 |

 最大値が正確に 1 に達するパスは 1 つだけです。 

これは、減算法が少なくとも 1 回レベル 1 に達するパスを正しく分離していることを確認します。 

### 例 2

 入力:```
1
2 1
```すべての長さ 2 の歩行:

 | パス | ポジション | マックス |
 | --- | --- | --- |
 | ++ | 0、1、2 | 2 |
 | +- | 0,1,0 | 1 |
 | -+ | 0、-1、0 | 0 |
 | -- | 0、-1、-2 | 0 |

 We want max exactly 1, so only`+-`貢献します。 

これは、「M 未満で終了」と「最大は M」を同一視できない理由を示しています。 ほとんどのパスは 1 未満で終了しますが、そこには到達しません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(T^2)$事前計算 +$O(1)$クエリごと | 2000 年までのすべての時間位置状態にわたる DP |
 | スペース |$O(T^2)$| DP およびプレフィックス テーブルのストレージ |

 事前計算はすべてのテスト ケースに対して 1 回実行されます。$10^5$答えるのが簡単な質問。 二次 DP は制限内に快適に適合します。$2000^2 = 4 \times 10^6$。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    MAXT = 200

    dp = [[0] * (2 * MAXT + 1) for _ in range(MAXT + 1)]
    off = MAXT
    dp[0][off] = 1

    for t in range(1, MAXT + 1):
        for x in range(-t, t + 1):
            dp[t][x + off] = (dp[t-1][x-1 + off] + dp[t-1][x+1 + off]) % MOD

    best = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
    for t in range(MAXT + 1):
        for m in range(MAXT + 1):
            s = 0
            for x in range(-t, m + 1):
                s += dp[t][x + off]
            best[t][m] = s % MOD

    ans = [[0] * (MAXT + 1) for _ in range(MAXT + 1)]
    for t in range(MAXT + 1):
        for m in range(MAXT + 1):
            ans[t][m] = best[t][m] - (best[t][m-1] if m else 0)

    out = []
    for line in inp.strip().splitlines()[1:]:
        t, m = map(int, line.split())
        out.append(str(ans[t][m] % MOD))
    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次のような場合です$M = 0$。 この状況では、最大値は強制的に 0 に留まることになります。これは、ウォークが原点を超えてはいけないことを意味します。 位置を 1 に増やす遷移は即座にパスを無効にするため、DP はこれを正しく処理します。$F(T, 0)$。 たとえば、$T = 2, M = 0$、 のみ`-1, +1`そして`-1, -1`最大値を 0 以下に保ち、減算ステップで 0 に触れないものを削除します。 

もう一つの微妙なケースは次のような場合です。$M > T$。 散歩は超えられないので$T$で$T$ステップごとに、すべてのパスに最大値が自動的に設定されます$T$、 それで$F(T, M) = 2^T$。 減算により、到達可能な範囲を超える不可能な最大値に対して正しく 0 が得られます。
