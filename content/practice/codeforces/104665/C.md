 ## 問題の理解

 それぞれの麺線のコレクションが味の数値を持っています。 これらのストランドをいくつかの皿に分割する必要があります。 すべての料理には少なくとも次のものを含める必要があります$K$料理の価値は、その中に入れられたストランドの中で最大の風味として定義されます。 

タスクは、ディッシュ値の合計ができるだけ大きくなるように、すべてのストランドを有効なディッシュに分割することです。 

したがって、決定の中心となるのは、個々のストランドだけではなく、それらをグループ化する方法です。各グループ内の最大の要素のみがスコアに寄与し、グループ内の他のすべての要素は、グループの存在を可能にする効果的な「サポート」要素となるためです。 

入力サイズは最大です$10^5$これにより、すべてのパーティションを試行したり、グループ化の選択を繰り返しシミュレートしたりするソリューションは直ちに除外されます。 ストランドの数が 2 次または指数関数的なものはすべて失敗します。$10^10$実際の操作では 1 秒の制限にはすでに大きすぎます。 

微妙な点は、すべてのストランドが正確に 1 つのディッシュに属している必要があることです。 これにより、問題は選択の問題ではなく分割の問題になります。 ストランドの破棄を許可する単純な解釈は構造を完全に変更し、別のより簡単な目的につながるため、「すべての要素を使用する」という制約が重要です。 

エッジケースは次の場合に発生します。$K = 1$、すべてのストランドが独自のディッシュを形成し、答えは単にすべての値の合計になります。 もう 1 つのエッジケースは次のような場合です$K = N$、料理は1つだけ形成でき、答えは最大の要素です。 貪欲な直感を打ち破る 3 番目のケースは、大きな値が分散している場合です。慎重なグループ化ロジックがなければ、最大値ではないグループ内で誤って大きな値を無駄にしてしまう可能性があります。 

たとえば、$f = [10, 9, 9, 1, 1]$そして$K = 3$、のような不注意なグループ化$[10, 1, 1]$そして$[9, 9]$2 番目のグループはサイズ要件を満たしていないため、無効です。 この種の間違いは、グループ化がローカルではなくグローバルに最小サイズ制約を尊重しなければならない理由を示しています。 

## アプローチ

 ブルートフォース戦略では、配列を少なくともサイズのグループに分割する可能なすべての方法を列挙しようとします。$K$。 パーティションごとに、すべてのグループの最大値の合計を計算します。 有効なパーティションに限定したとしても、分割する方法は多数あります。$N$要素は非常に速く増加し、制約が追加されたベル番号に似ています。 のために$N = 20$、これはすでに実行可能な計算をはるかに超えており、$N = 10^5$、それはまったく不可能です。 

重要な観察点は、各グループ内では最大の要素のみが重要であり、他のすべての要素はサイズ要件を満たすだけであるということです。 これにより、強い非対称性が生じます。大きな要素はグループ最大値になる場合にのみ価値があり、小さな要素は交換可能なフィラーとなります。 

配列を降順に並べ替えると、最適な戦略は構造的に単純になります。 可能な限り、最大の残りの要素をグループ最大値として割り当てたいと考えています。 最大値を選択するたびに、少なくとも「費やす」必要があります$K-1$他の要素を使用して有効なグループを形成します。 合計を最大化するには、常に次のことが必要です。$K-1$要素はできるだけ小さくし、将来のグループのために大きな要素を保存します。 

これにより、ソートされた配列をスキャンしてすべてを選択する貪欲な構造が得られます。$K$- 番目の要素をグループ リーダーとして使用します。各リーダーはそれ自体に加えて消費するためです。$K-1$フィラー。

 ## アルゴリズムのチュートリアル

 ここで、最適なグループ化を直接構築する建設的な戦略について説明します。 

1. すべてのフレーバー値を降順に並べ替えます。 

これにより、誰が皿の最大値になるかを決定するときに、常に大きな候補を最初に考慮することが保証されます。これは、小さな要素が常にフィラーとして使用できるため、必要です。 
2. 答えのアキュムレータをゼロとして初期化します。 
3. ソートされた配列をステップ サイズで反復処理します。$K$、インデックス 0 から始まります。 

訪問した各位置は、選択したディッシュ リーダーに対応します。 
4. 訪問した各位置の値を答えに加算します。 

その理由は、この要素が有効なグループの最大値になり、次の要素が有効なグループの最大値になるからです。$K-1$ソート順の要素はフィラーとして暗黙的に消費されます。 
5. インデックスが配列の境界を超えたら停止します。 

重要なメンタル モデルは、ソートされた配列を連続したサイズのブロックに分割するということです。$K$ただし、スコアに寄与するのは各ブロックの最初の要素のみです。 

### なぜ効果があるのか

 ソート後、配列は最大から最小の順に並べられます。 この順序でグループを形成することを検討してください。 現在最大の未使用要素をグループ最大値として選択するときは常に、依然として次のものが必要です。$K-1$他の要素。 次に利用可能な最小の要素をフィラーとして選択することは、常に最適です。なぜなら、それらの要素は、それ自体がリーダーにならない限り、将来の最大値に寄与しないからです。また、大きな要素がリーダーになるのを遅らせても、フィラーの位置に追い込まれる前に選択される可能性が低くなるだけです。 

これにより、不変条件が作成されます。各ステップで、ソートされた配列の残りの未使用プレフィックスには、将来のグループ最大値の利用可能な最大の候補が常に含まれ、消費されます。$K$グループごとの要素は、選択されたすべてのリーダーが残りの有効な候補の中で可能な限り最大であるという特性を保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]
    
    a.sort(reverse=True)
    
    ans = 0
    for i in range(0, n, k):
        ans += a[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはすべての値を読み取り、降順に並べ替えて、すべての値を累積します。$K$-th 要素はインデックス 0 から始まります。ループ構造は、各グループのサイズが次のとおりであるという考えを直接エンコードします。$K$は、ソート順の最初の要素である 1 つの有用な値を提供します。 

よくある間違いは、明示的にグループを形成し、残りの要素を追跡しようとすることです。 それは不必要であり、間違いが発生しやすくなります。 ソートされたステッピング手法では、最適なグループ化がすでに暗黙的にエンコードされています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]
    a.sort(reverse=True)
    ans = sum(a[i] for i in range(0, n, k))
    return str(ans)

# provided samples
