 ## 解決策
 ## 問題の理解

 すべて同じ長さの偶数の順列が与えられます。 各順列は循環オブジェクトを表します。オブジェクトを何度でも回転させることができます。これは、要素の循環シフトを選択できることを意味します。 順列は、一定回数の回転の後、1 から s までソートされたシーケンスになったときに解決されたとみなされます。 

重要な点は、順列が独立していないことです。 それらをペアにする必要があり、各ペア内では、両方の順列が常に同時に同じ回転を受けます。 一方に適用された回転は、そのパートナーにも自動的に適用されます。 ペアごとに回転方法を選択できますが、両方の配列が一緒に移動します。 

単一の順列の場合、それを解くことは、それを恒等順列に変える回転が存在することを意味します。 これは、順列が同一性の循環シフトであると言うのと同じです。 

ペアの場合、回転カウントを選択し、それを両方に適用して、2 つのどちらがソートされるかを確認します。 目標は、解決可能な順列の総数が最大化されるように順列をペアにすることです。 

制約は小さく、N は最大 1000、各順列の長さは最大 1000 です。これにより、各比較が高価な場合、すべてのペア間の高度なマッチングと組み合わせた回転に対するペアごとの 2 次シミュレーションが除外されます。 ただし、N は十分小さいため、慎重に前処理を行った O(N^2) 構成が妥当です。 

素朴なアプローチでは、すべてのペアを試し、各ペアが 0、1、または 2 つの順列を解決できるかどうかをシミュレートします。 それはすぐに N の階乗になりますが、N = 20 の場合でも実行不可能です。 

共有回転互換性を考慮せずに、個別に「修正が簡単」に見える順列を貪欲に組み合わせようとすると、より微妙な障害モードが発生します。 2 つの順列はそれぞれ単独で解決可能ですが、同じシフトの下で同時に解決することはできません。 

## アプローチ

 中心となる観察は、回転は循環等価性までにのみ重要であるということです。 それぞれの順列について、どのシフトによって恒等順列になるかに注目します。 恒等式は固定されているため、各順列は、それを解決する回転を意味する「適切なシフト」のセットに対応します。 

参照を修正する場合、たとえば回転 0 を同一位置として扱う場合、順列ごとに、最初の要素 (または任意のアンカー) を 1 に揃える固有のシフトを計算し、すべての位置にわたる一貫性を検証できます。 より堅牢には、置換を恒等式と等しくするすべてのシフトを計算します。 これは、順列が恒等の巡回シフトであるかどうかに応じて、0 または 1 の値になります。 

ただし、すべての順列は 1..s の任意の順列であるため、ほとんどは個別に解くことはできません。 順列が回転のもとで解けるようになる唯一の方法は、それがまさに恒等配列の循環回転である場合です。 つまり、[k, k+1, ..., s, 1, ..., k-1] の形式でなければなりません。 

したがって、各置換は 1 つの有効な回転 (単一のシフト値) に寄与するか、まったく寄与しません。 

次にペアを考えてみましょう。 2 つの順列がそれぞれ有効なシフト値 x と y を持っていると仮定します。 それらをペアにする場合は、単一回転 r を選択します。 回転 r の後、順列 A は r が x を法とする s に等しい場合に解決され、B は r が y を法として s に等しい場合に解決されます。 それで:

 - x == y の場合、両方が解決されます。 
- それ以外の場合、そのペアでは最大でも 1 つしか解決できません。 

これにより、問題は、有効なシフト値または無効な (-1) のいずれかでラベル付けされたインデックスのペアに限定されます。 無効なものはペアリングに関係なく決して解決できないため、寄与はゼロです。

したがって、両方の要素が同じシフト値を共有するペアの数を最大化したいと考えます。 このような各ペアは 2 つの暗号を解決します。 有効と無効をペアにした場合、他のすべてはペアごとに最大 1 を寄与しますが、無効は有効になることができないため、これらのペアは解釈に応じて 0 または 1 を寄与します。 無効な順列は決して解決できず、常に 0 を寄与するため、可能であれば有効な順列との組み合わせを避ける必要がありますが、構造のペアリングでは完全な一致が強制されます。 

最適な戦略は、シフト値によってグループ化することです。 各シフト値 c について、cnt[c] 順列がある場合、floor(cnt[c]/2) のペアを形成でき、それぞれ 2 つの解が得られ、2 * Floor(cnt[c]/2) に寄​​与します。 ペアになっていない有効なものは、パートナーが同じシフトを共有できないため、貢献度は 0 になります。 

これは単純な計算問題になります。

 | ローテーション クラスごとにグループ化 | O(N・s) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各順列について、それが恒等順列の循環回転であるかどうかを判断します。 
2. そうであれば、その回転オフセット r、つまりソート順にマッピングし直すシフトを計算します。 
3. それぞれの有効な r を生成する順列の数を数えます。 
4. 各 r について、同じ r を持つ順列をペアにします。 
5. 各ペアは 2 つの解決された暗号を提供するため、2 * (count[r] // 2) を加算します。 
6. すべての r を合計して、最終的な答えを求めます。 

### なぜ効果があるのか

 巡回シフト下では恒等配置が固定的であるため、各順列にはそれを解く回転が最大 1 つあります。 したがって、すべての解決可能な順列は、その必要なシフトによって定義される正確に 1 つの同値クラスに属します。 2 つの順列は、同じシフトが必要な場合に限り、単一の共有回転の下で同時に解決できます。 したがって、クラス間のペアリングでは解決可能な要素の数を増やすことができないため、クラス内のペアリングが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cnt = {}

    for _ in range(n):
        data = list(map(int, input().split()))
        s = data[0]
        p = data[1:]

        # find rotation that makes p sorted [1..s]
        pos1 = p.index(1)
        shift = (s - pos1) % s

        ok = True
        for i in range(s):
            if p[(pos1 + i) % s] != i + 1:
                ok = False
                break

        if ok:
            cnt[shift] = cnt.get(shift, 0) + 1

    ans = 0
    for v in cnt.values():
        ans += (v // 2) * 2

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、1 の位置に固定し、順序の一貫性をチェックすることによって、各順列が恒等の巡回シフトであるかどうかを識別します。 変数`shift`並べ替えをソートされた順序に揃える回転をエンコードします。 

有効なシフト クラスの数のみを保存します。 無効な順列は、ペアリングに関係なく解決できないため、無視されます。 

最後に、各シフト クラス内のペアを累積し、ペアごとに 2 つの解決された順列を追加します。 

実装の微妙な点は、明示的にペアリングを試みないことです。 周波数だけを数えます。 これにより、順序への依存が回避され、クラスごとに O(1) の集計が保証されます。
