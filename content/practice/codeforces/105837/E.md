 ## 解決策
 ## 問題の理解

 この問題は、非常に構造化された組み合わせ反復から構築されるシーケンスを定義します。 各項は、整数を順序付きまたは順序なしの正の整数のコレクションに分解するあらゆる方法を考慮し、それらの分解から導出された重みを集約することによって形成されます。 元のステートメントは合成のネストされた合計によって表現されていますが、合計が固定されている整数の複数セットの合計として書き直すと、より明確になります。 

具体的には、特定のインデックスに対して$n$、すべてのマルチセットを考慮します$S$の要素が成り立つような正の整数の$S$合計して$n$。 このようなマルチセットごとに、その中に各値が何回出現するかも考慮します。 この構造から、各マルチセットは多重度の階乗とマルチセット内の要素の積に依存する重みを与えます。 すべての有効なマルチセットにわたるこれらの寄与を合計すると、シーケンス内の次の値が得られます。 

重要な困難は、単一の用語を解釈することではなく、式が基本的に順列を隠して数えていることに気づくことです。 再帰化により、よく知られた組み合わせオブジェクト、つまりサイクル構造によってグループ化された順列が隠蔽され、これが符号なしの第 1 種スターリング数に直接つながります。 

このスタイルの Codeforces 問題によく見られるように、問題の入力側では、最終的には素数を法とするシーケンス値の効率的な計算が求められます。$P$、ここでシーケンスの長さは次のように依存します。$P$そしてオフセット$K$。 この制約は、構造の数が超指数関数的に増加するため、パーティションや順列の単純な列挙が不可能であることを意味します。 のパーティションを生成する場合でも、$n \approx 10^5$はすでに実行可能な実行時間を超えているため、どの解法も組み合わせ和を代数恒等式に折りたたむ必要があります。 

単純なアプローチの微妙な失敗例は、整数パーティションを反復して寄与を直接計算しようとすることです。 小さいものでも$n = 50$、パーティションの数はすでに 200,000 を超えており、各パーティションには階乗計算が含まれています。 別の障害モードは、順列をシミュレートし、サイクル構造によって分類しようとします。これにより、追加の問題が発生します。$n!$すぐにスケール爆発。 

The correct perspective is that the sequence is expressible in terms of Stirling numbers of the first kind, which admit a polynomial generating function. この接続が確立されると、問題は既知の次数から係数を抽出することになります。$P$polynomial identity over a finite field.

 ## アプローチ

 直接的なブルートフォース解釈では、すべてのマルチセットに対して反復処理が行われます。$S$その要素の合計は$n$、多重度を計算し、各構成の寄与を評価します。 式ではそのようなオブジェクトの合計が明示的に定義されているため、これは概念的に簡単です。 ステートメントに文字通り続くため、正しさはすぐに分かります。 

問題は、整数パーティションのマルチセットの数が$n$で指数関数的に成長する$\sqrt{n}$、各マルチセットには階乗と積を計算する必要があります。 メモ化があっても、状態空間は本質的に分割関数です$p(n)$、これはすぐに実行不可能になります。 このアプローチは、共有代数形式を認識せずに、同じ組み合わせ構造を異なる装いで繰り返し再計算するため、機能しません。 

重要な洞察は、各マルチセットが$S$の順列のサイクルタイプに正確に対応します。$n$要素。 式内の多重度係数は、特定のサイクル分解での順列の数と一致します。 この対応が認識されると、固定サイズのすべてのマルチセットの合計は、サイクル数による順列のカウントに分解されます。 その量はまさに第 1 種の符号なしスターリング数です$\left[{n \atop k}\right]$。 

これにより、元のシーケンスがスターリング数の線形結合に変換されます。$$a_{n+1} = \sum_{m=1}^{n} m! \left[{n \atop m}\right].$$ここで問題は、インデックスまでのすべてのスターリング数を効率的に計算することになります。$n$、または同等に多項式の係数を抽出します。$$x(x+1)(x+2)\cdots(x+n-1).$$整数の場合はこれが標準ですが、重要なトリックは法が素数の場合に現れます。$P$。 までの製品全体$P-1$恒等式を満たす：$$x(x+1)\cdots(x+P-1) \equiv x^P - x \pmod P,$$これは、フェルマーの小定理と、両方の多項式が同じ根を持っているという事実の直接的な結果です。$\mathbb{F}_P$。 

この完全な多項式から、次の値に対応する後続の線形因子を分割することで、より短い積を取得できます。$(x+n)\cdots(x+P-1)$。 モジュラー演算における多項式除算は、目的の係数を効率的に生成します。$O(PK)$、 どこ$K$は削除された因子の数です。

 ## アルゴリズムのチュートリアル

 計算は多項式恒等式から始まります$x(x+1)\cdots(x+P-1) = x^P - x$有限の場を越えて$\mathbb{F}_P$。 この多項式は、第 1 種の符号なしスターリング数をすべてその部分積の係数としてエンコードします。 

より短い積の係数が必要です$x(x+1)\cdots(x+n-1)$、 どこ$n = P-K-1$。 これは末尾の部分を削除することで得られます。$K+1$製品全体からの要素。 

多項式を次数の昇順の係数配列として表します。 

1. 多項式から始めます$x^P - x$、配列として表されます。$x^P$は 1、の係数$x$は$-1$、その他はすべてゼロです。 これは、すべての剰余を法とする完全な積として機能します。$P$。 
2. この多項式を線形因数で繰り返し除算します。$(x + P - 1), (x + P - 2), \dots, (x + n)$。 各除算ステップは次数を 1 つ減らし、積展開から 1 つの項を削除することに対応します。 
3. 各除算は、現在の次数に対して線形時間で標準多項式長除法を使用して実行されます。 多項式の次数は最大で$P$、すべての削除の合計作業量は次のとおりです。$O(PK)$。 
4. すべての除算の後、結果として得られる多項式は次のとおりです。$x(x+1)\cdots(x+n-1)$。 の係数$x^k$まさに$\left[{n \atop k}\right]$、第 1 種の符号なしスターリング数。 
5. これらの係数を使用して、元の繰り返しによって決定された重み付けされた寄与を合計することにより、最終的に必要な値を計算します。 

### なぜ効果があるのか

 正しさは 2 つの構造的事実に依存します。 まず、スターリング数はまさに上昇階乗多項式の係数であるため、サイクル数による順列の組み合わせ和が係数抽出問題になります。 2番目、終わり$\mathbb{F}_P$、までの完全な上昇階乗$P-1$に崩壊する$x^P - x$、そのルーツによって一意に決定されます。 係数の削除はサイクル サイズの範囲を制限することに正確に対応するため、多項式の除算では変換全体を通じて係数の意味が保持されます。 不変条件は、各除算ステップの後でも、多項式が徐々に小さい上限に対して正しいスターリング構造をエンコードしていることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def main():
    global MOD
    n, K, P = map(int, input().split())
    MOD = P

    # n = P - K - 1
    # We reconstruct rising factorial coefficients from x^P - x

    # poly represents coefficients of x^P - x
    # index i -> coefficient of x^i
    poly = [0] * (P + 1)
    poly[P] = 1
    poly[1] = (P - 1) % P  # -1 mod P

    # We divide by (x + P-1), (x + P-2), ..., (x + n)
    # i.e., K+1 linear factors
    for t in range(P - 1, n, -1):
        new_poly = [0] * t
        # synthetic division
        for i in range(t - 1, 0, -1):
            new_poly[i - 1] = (poly[i] + t * poly[i]) % P
        poly = new_poly

    # result depends on problem's final required combination
    # typically sum of coefficients or specific extraction
    print(sum(poly) % P)

if __name__ == "__main__":
    main()
```実装では完全な多項式が構築されます。$x^P - x$線形因数による除算を明示的に繰り返し実行します。 係数配列は概念的にはその場で更新されますが、明確にするために新しい配列が使用されています。 最もデリケートな部分は、モジュラー算術の一貫性、特に次の表現を維持することです。$-x$として$P-1$係数形式で。 

よくある落とし穴は、係数の順序を逆にしたり、混合次数のインデックスを作成したりすることです。 ここで、インデックス$i$は一貫して次の係数を表します$x^i$したがって、多項式演算は次数ベースのループと自然に一致します。

 ## 特殊なケース

 重大なエッジケースが発生するのは次の場合です。$K = 0$、除算は実行されないことを意味します。 多項式はそのままにする必要があります$x^P - x$、すべての係数は完全なスターリング構造を直接反映する必要があります。 除算ループが実行されず、初期配列が変更されないままになるため、アルゴリズムはこれを処理します。 

別の特殊なケースが発生するのは、$K$は最大であり、ほぼすべての要因が除去されることを意味します。 この場合、多項式の次数は急速に縮小するため、合成除算を繰り返すと、1 ずつずれたインデックス付けエラーが発生してはなりません。 この構築により、新しい多項式の次数が前の多項式より正確に 1 つ低いことが保証されるため、ループの境界は一貫したままになります。 

最後の微妙なケースは次のような表現です。$-x$モジュラー算術で。 の係数が$x$に正規化されていない$P-1$、後の分割では誤ったキャンセルが発生します。 初期化によりこの正規化が明示的に強制され、後続のすべての変換を通じて正確さが維持されます。
