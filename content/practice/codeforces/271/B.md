 ## 解決策
 ## 問題の理解

 正の整数のグリッドが与えられます。 このグリッドから、任意の単一セルを繰り返し選択し、その値を 1 ずつ増やすことができます。 増加ごとに 1 回の移動がかかります。 目標は、少なくとも 1 つの行全体が素数になるか、少なくとも 1 つの列全体が素数になるという意味で、グリッドを「素数」にすることです。 

値は、素数になる場合にのみ、選択した行または列で受け入れられます。 値を増やすことしかできないため、各セルには独立したコスト、つまりセルを現在の値以上の素数に変えるのに必要な増分の数がかかります。 

タスクは、行または列を選択し、その中のすべての値を素数に変換するための総コストを支払い、すべての行と列にわたってこのコストを最小化することです。 

制約は最大 500 x 500 グリッドまで適用されるため、セルは最大 250,000 個になります。 各値は最大 100,000 ですが、任意に増やすことができます。 これは、セルごとの負荷の高い計算はすべて前処理する必要があることを直ちに示唆しています。これは、入れ子になったループ内で素数距離を繰り返し再計算しても合格するからです。ただし、素数チェックが効率的で再利用されている場合に限ります。 

微妙なエッジケースとして、ある行または列で数値がすでに素数である場合があります。 その行または列のコストはゼロになり、答えはゼロになります。 もう 1 つの重要なケースは、多くの値が素数のすぐ下 (14、20、26 など) である場合です。セルごとに「1 つずつ増分して次の素数をチェックする」という素朴な処理は、ループ内で繰り返し実行すると遅すぎます。 

隠れた重要な要件は、グリッド内のすべての数値について、その数値以上の最小の素数を効率的に計算する必要があるということです。 

## アプローチ

 ブルートフォース手法では、各行と列が個別に処理されます。 固定行の場合、そのすべてのセルを反復処理し、素数に達するまで各セルを繰り返し増分して増分を合計します。 次に、すべての列に対して同じことを繰り返し、最小値を取得します。 

これは正しいですが、各セルに多くの増分が必要になる可能性があり、最大 250,000 個のセルに対してこれを行うため、遅すぎます。 最悪の場合、値が 100,000 に近く、素数が局所的にまばらな場合、増分ごとに素数チェックを繰り返すと、何十億ものチェックが必要になります。 

重要な観察は、各セルのコストは独立しており、その値にのみ依存するということです。 増分をシミュレートする必要はありません。 代わりに、100,000 をわずかに超える安全な制限まで、すべての整数に対して次の素数を事前計算します。 次に、各セルが固定コストに寄与します。`next_prime[a[i][j]] - a[i][j]`。 

このコスト グリッドを取得すると、問題はすべての行とすべての列の最小合計を見つけることになります。 これは、事前に計算された値の単なる集計です。 

したがって、ソリューションの構造は次のようになります。ふるいを使用して素数を事前計算し、次の素数配列を構築し、セルごとのコストを計算し、次に行の合計と列の合計を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースインクリメントシミュレーション | O(nm × ステップ) | お(1) | 遅すぎる |
 | ふるい + 事前計算 + 集計 | O(MAX log log MAX + nm) | O(MAX) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 可能な最大値よりわずかに大きい上限値を選択します。通常は 100000 + マージン (130000 など)。 これにより、すべての数値の上に到達可能な素数が存在することが保証されます。 
2. エラトステネスのふるいをかけて、この境界までのすべての素数をマークします。 これにより、定数時間の素数検索が行われます。 
3. アレイを構築する`next_prime`すべての整数 x に対して、`next_prime[x]`は x 以上の最小の素数です。 

これは、最後に確認された素数を記憶しながら、最大値から下方向にスキャンすることによって行われます。 
4. コスト行列を暗黙的に作成します。セル (i, j) ごとに、次の値を計算します。`cost[i][j] = next_prime[a[i][j]] - a[i][j]`。 これは、そのセルに必要な最小増分数を表します。 
5. セルのコストを合計して、各行のコストを計算します。 
6. 各列のコストを同様に計算します。 
7. すべての行の合計と列の合計の最小値を返します。 

各ステップは、問題を動的な増分操作から静的な事前計算された差分に削減します。これが中心的な簡素化です。 

### なぜ効果があるのか

 各セルは、行または列が完全に素数になるかどうかに独立して影響します。 異なるセルに対する操作は相互作用しないため、行の変換コストは個々の最小コストの合計にすぎません。 常に各値の上に最も近い素数を選択するため、セルごとに過剰な支払いを行うことはありません。 これにより、計算された行または列のコストがその構造の真の最小コストであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 130000

# sieve
is_prime = [True] * (MAXV + 1)
is_prime[0] = is_prime[1] = False

for i in range(2, int(MAXV ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            is_prime[j] = False

# build next prime
next_prime = [0] * (MAXV + 2)
last = -1
for i in range(MAXV, -1, -1):
    if is_prime[i]:
        last = i
    next_prime[i] = last

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

row_cost = [0] * n
col_cost = [0] * m

for i in range(n):
    for j in range(m):
        v = a[i][j]
        cost = next_prime[v] - v
        row_cost[i] += cost
        col_cost[j] += cost

ans = min(min(row_cost), min(col_cost))
print(ans)
```ふるいの部分により、素数を即座に決定し、任意の値の次の素数を導き出すことができます。 逆スキャンは、スパース素数分布を直接ルックアップ テーブルに変換するため、重要です。 

行列に対するネストされたループは、セルごとにコストを 1 回計算し、行と列の両方の合計を同時に累積して、余分なパスを回避します。 

微妙な点は、`next_prime[v]`常に存在します。 このため、ふるいの範囲は最大入力値を超える十分な大きさにする必要があります。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    MAXV = 130000

    is_prime = [True] * (MAXV + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(MAXV ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, MAXV + 1, i):
                is_prime[j] = False

    next_prime = [0] * (MAXV + 2)
    last = -1
    for i in range(MAXV, -1, -1):
        if is_prime[i]:
            last = i
        next_prime[i] = last

    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    row = [0] * n
    col = [0] * m

    for i in range(n):
        for j in range(m):
            c = next_prime[a[i][j]] - a[i][j]
            row[i] += c
            col[j] += c

    print(min(min(row), min(col)))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# provided sample
assert run("""3 3
1 2 3
5 6 1
4 4 1
""") == "1"

# single cell already prime
assert run("""1 1
2
""") == "0"

# all same small composite
assert run("""2 2
1 1
1 1
""") == "2"

# mixed case
assert run("""2 3
4 6 8
9 10 1
""") == str(min(1+1+1, 1+1, 1+1))

# max-ish structure sanity
assert run("""3 3
100000 100000 100000
100000 100000 100000
100000 100000 100000
""") >= "0"

 ## 特殊なケース

 重要なエッジ ケースは、行列に完全なプライム行または列がすでに含まれている場合です。 たとえば、行が`[2, 3, 5]`、そのコストはゼロになり、答えはすぐにゼロになるはずです。 アルゴリズムはこれを処理します。`next_prime[p] - p`ゼロのとき`p`は素数なので、行の合計は自動的にゼロになります。 

もう 1 つのケースは、複数の行と列が結合している場合です。 たとえば、すべて 1 の均一な行列では、行と列のコストが同じになります。 このアルゴリズムはすべての合計を独立して正しく計算し、一意性を仮定せずに最小値を取得します。 

3 番目のケースは、値が 14、20、26 などの素数のすぐ下にある場合です。各セルは独立して最も近い素数 (17、23、29) にジャンプします。 各コストはローカルであるため、合計はグローバル構造に干渉せず、行と列の両方の評価は一貫したままになります。 

最後に、ふるいの境界は十分に高い必要があります。 小さすぎる場合は、`next_prime[x]`値が大きい場合は未定義となり、誤った結果が生じる可能性があります。 上限が固定されているため、すべての入力値に有効な次の素数が含まれることが保証されます。
