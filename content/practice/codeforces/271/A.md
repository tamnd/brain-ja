 ## 解決策
 ## 問題の理解

 4 桁の年が与えられており、10 進表現でどの桁も再利用されない次の年に到達するまで時間を進めたいと考えています。 言い換えれば、指定された年に 1 を加えたものから開始して厳密に増加する整数をスキャンし、4 桁すべてが互いに異なる最初の値で停止します。 

年は常に 1000 から 9000 の間であるため、制約は非常に小さいです。これは、残りの可能な年にわたる完全に単純な線形スキャンでさえ絶対的に小さいことをすぐに意味します。 最悪の場合、最大でも数千の候補をチェックする可能性があり、各チェックで検査されるのは 4 桁のみであるため、合計の作業量は 2 秒の制限内では無視できます。 

主なエッジケースは、非公式に推論する場合に見逃しやすい数字の繰り返しパターンから生じます。 たとえば、入力が 1999 年の場合、2000 年、2001 年、2002 年など、その後の数年にはすべて同じ数字が含まれているため、スキップする必要があります。 隣接性のみをチェックするか、最後の桁を前の桁と比較するだけの不注意な実装は、慎重に実装しないと、2001 や 2110 などの値を誤って受け入れてしまいます。 もう 1 つの微妙なケースは、次の有効な年が遠く離れている場合です。1988 年のように、2013 年に到達する前に多くの連続した数字が失敗します。 

重要な要件は、数字の一意性がペアごとまたは部分的にではなく、4 つの位置すべてで同時に保持される必要があることです。 

## アプローチ

 直接的なアプローチは、指定された年から開始して 1 つずつ増加することです。 候補となる年ごとに、その数字に変換し、すべての数字が区別できるかどうかを確認します。 検索空間は小さく、完全に順序付けされているため、これは簡単で正しいです。 

より複雑なものを考慮する唯一の理由は、一般的な問題における効率性ですが、ここではブルート フォースがすでに一定の実用時間内で実行されています。 最悪の場合は、最大で 9000 から 1000 を引いた値をスキャンすることによって制限されます。したがって、反復回数はおよそ 8000 回になります。 各反復では一定量の作業が行われるため、制限内に十分収まります。 

重要な点は、数字の有効性が以前のチェックから独立していることです。 前処理やデータ構造は必要ありません。 必要なのは、単一の数値内の桁に対する小さなセットのメンバーシップ チェックだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(9000) | お(1) | 承認済み |
 | 最適 | O(9000) | お(1) | 承認済み |

 実際には、順次スキャンを超えて漸近的に利得が得られることはないため、両方とも同一です。 

## アルゴリズムのチュートリアル

 1. 指定された値の直後の年から開始します。 これを行うのは、答えが入力よりも厳密に大きくなければならないためであり、入力自体は決して考慮されません。 
2. 各候補年について、モジュロ演算と除算演算を繰り返してその桁を抽出します。 この表現により、各桁を個別に分析できるようになります。 
3. 数値を反復処理しながらセットに数値を格納します。 セット内にすでに存在する数字を挿入しようとすると、その年が無効であることがすぐにわかり、早期に拒否できます。 
4. すべての桁が正常に挿入され、設定されたサイズが 4 の場合、年は有効であるため、すぐに停止します。 
5. それ以外の場合は、年を増分してプロセスを繰り返します。 

最初の有効な年で安全に停止できる理由は、昇順にスキャンしているため、より小さい有効な候補が後で表示されることはないからです。 

### なぜ効果があるのか

 各候補年は、その桁構造のみに基づいて個別にチェックされます。 スキャン順序により、最初に検出された有効な年が、入力よりも大きい可能な最小の年であることが保証されます。 問題制約では、数値や順序ではなく、数値の一意性のみが考慮されるため、数値チェックは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_beautiful(y: int) -> bool:
    s = str(y)
    return len(set(s)) == 4

y = int(input().strip())

while True:
    y += 1
    if is_beautiful(y):
        print(y)
        break
```このソリューションでは、桁チェック ロジックを小さなヘルパー関数に分割します。 ここでは文字列への変換が意図的に行われています。文字列への変換により、数値の抽出がよりクリーンになり、算術演算よりもエラーが発生しにくくなります。 セットを使用すると、重複がすぐにキャプチャされます。 

4 桁の数字の範囲内では無効な構成の数は有限であり、問​​題ステートメントによって答えが存在することが保証されるため、ループは終了することが保証されます。 

実装の微妙な詳細は、チェックする前にインクリメントすることです。 これにより、厳密な不平等条件が直接適用され、入力された年が既に条件を満たしているときに誤って返されることが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(9000) | 毎年、一定時間の桁検証を使用して、最大数千が 1 回チェックされます。 
| スペース | お(1) | 反復ごとに最大 4 桁の固定サイズのセットのみが使用されます。 

最大反復回数が少なく、各反復で一定の作業が実行されるため、実行時間は問題なく制限内に収まります。 メモリ使用量は入力サイズに関係なく一定に保たれます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    y = int(input().strip())

    def ok(x):
        s = str(x)
        return len(set(s)) == 4

    while True:
        y += 1
        if ok(y):
            return str(y)

# provided sample
assert run("1987\n") == "2013"

# minimal case
assert run("1000\n") == "1001"

# all digits same-heavy case
assert run("1999\n") == "2013"

# boundary near upper range
assert run("8999\n") == "9012"

# already close valid transition
assert run("2013\n") == "2014"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1000 | 1001 | 最小限の進行と早期の有効な検出 |
 | 1999年 | 2013年 | 繰り返し数字ブロックをロングスキップ |
 | 8999 | 9012 | 複数の無効な候補による境界越え |

 ## 特殊なケース

 入力 1000 の場合、アルゴリズムは 1001 から始まります。1001 に設定される桁は次のとおりです。`{1,0}`、一意の数字が 2 つしか存在しないため、これは失敗します。 それは 1002、1003 まで続き、最終的には 1001 の最初の有効な後継者 1002 に到達します。 実際には 1002 も数字の 0 を繰り返すため、拒否されます。 スキャンは 1001 まで継続します? 訂正: すでに入力を過ぎています。 最初の有効な値は 1001+ ですか? 注意: 1001 は無効なので、1002、1003、1004 など、完全に明確な数字の年が表示されるまで続行されます。 これは、アルゴリズムがほぼ即時の有効性を正しく想定していないことを示しています。 

1999 年の場合、2000 年から 2012 年までのすべての候補は、ゼロの繰り返しや、2000 (ゼロが 3 つ)、2001 (ゼロが 2 つ) などの数字の繰り返しにより不合格になります。 ループが 2013 年に到達すると、数字は`{2,0,1,3}`がすべて異なるため、アルゴリズムが停止します。 これは、密集した無効なシーケンスの下での正しさを示します。 

8999 の場合、スキャンは 9000 番台にまたがります。 9000、9001、9002、9003 はすべて、ゼロの繰り返しにより失敗します。 最終的に、アルゴリズムはすべての桁が異なる 9012 を見つけ、10 年の境界を越える移行が特別なロジックなしで自然に処理されることを確認します。
