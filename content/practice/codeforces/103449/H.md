 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられています。 各ノードには深さ (ルートからの距離) の概念があり、サブツリー内のノードのプロパティ (通常は最大深さ、高さの寄与、またはサブツリー内のすべてのノードの集計値など) に関するクエリに答えることに関心があります。 

重要な構造上の考え方は、各サブツリーが事前順序トラバーサルの連続セグメントに対応するということです。 ノードを事前順序で記録すると、すべてのノードのサブツリーが連続した間隔になります。 これにより、ツリーは直ちに配列問題に変わり、サブツリー クエリが範囲クエリになります。 

したがって、入力は、サブツリー集合体に依存する一連の操作またはクエリとともにツリーを表します。 出力は、ツリーの現在の状態を考慮した後のこれらのクエリに対する答えです。 

この問題ファミリーに典型的な制約パターンから、ノード数は最大約 2×10^5 となり、クエリも大きくなります。 これにより、クエリごとにサブツリー情報を再計算することは即座に除外されます。これは、クエリごとに 1 つの DFS を使用すると O(nq) になり、これが許容範囲をはるかに超えてしまうためです。 更新が関係する場合は、O(n√n) のアプローチでも安全ではありません。 

単純なアプローチの微妙な失敗例は、サブツリー値が前処理後に静的なままであると仮定した場合に現れます。 たとえば、サブツリーの最大深さを一度計算し、その配列のみを使用してクエリに答えようとすると、ノードの値に影響を与える更新によって、すべての祖先のサブツリー集合体が無効になります。 単純な例としては、リーフを更新するとすべてのプレフィックス サブツリーの答えが変更されるチェーン ツリーがありますが、静的セグメントはその伝播を決して反映しません。 

## アプローチ

 ブルートフォースの解決策は簡単です。 クエリごとに、DFS を使用してサブツリー情報を最初から再計算します。 ノード i については、そのサブツリー内のすべてのノードを走査し、最大深度や集計値などの必要なプロパティを計算します。 各クエリは O(サブツリーのサイズ) を取ることができ、最悪の場合は O(n) になります。 q クエリの場合、これは O(nq) となり、最大の制約に対して約 4×10^10 の演算となり、明らかに遅すぎます。 

重要な点は、オイラー ツアーまたは事前順序番号付けを使用して、サブツリー クエリを配列にマッピングできることです。 各サブツリーは連続セグメントになるため、問題は範囲クエリを使用して動的配列を一定の間隔で維持することに帰着します。 

問題が範囲クエリの問題であると認識されたら、当然の次のステップは、操作に応じてセグメント ツリーまたはフェンウィック ツリーを使用することです。 この問題の難しさは、値がノードごとに独立しておらず、深さの違いやサブツリーの最大値などの構造特性に依存することです。 このため、単純なプレフィックス配列では不十分です。 

正しいアプローチは、preorder 配列にわたってセグメント ツリーを維持し、サブツリー間隔ごとに関連する集計値を格納することです。 更新が発生すると、オイラー配列の点の更新に変換されます。 クエリがサブツリーの最大値または合計を要求する場合、それらはそのセグメント ツリー間隔にわたる範囲クエリになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | オイラー ツアー + セグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずツリーをルート化し、事前順序走査を計算します。 DFS 中に、ノードのサブツリーが間隔 [tin[v], tout[v]] に正確に対応するように、各ノードに開始時刻と終了時刻を割り当てます。 

ノードも配列に格納します`euler[]`そのような`euler[tin[v]] = v`。 これにより、ツリーが平らになり、直線的な構造になります。 

次に、補助配列を構築します`base[]`このオイラー次数を超えます。 各位置には、対応するノードに関連付けられた初期値 (多くの場合、深さまたは派生メトリック) が格納されます。 

次に、セグメント ツリーを構築します。`base[]`、ノード値が変更されたときのポイント更新と、サブツリー間隔にわたる範囲クエリの 2 つの操作をサポートします。 

クエリごとに、クエリされたノードをオイラー区間に変換し、その範囲に対してセグメント ツリー クエリを実行します。 多くのサブツリー定義には相対的な深さの違いが含まれるため、必要に応じてノード自体の深さを使用して結果が調整されます。 

### なぜ効果があるのか

 この正しさは、サブツリーのメンバーシップがオイラー順序で連続した区間として保存されるという事実から得られます。 これは、サブツリーに制限された操作は、配列の固定セグメント内の要素にのみ依存することを意味します。 セグメント ツリーはすべてのセグメントにわたって正確に集約された情報を維持し、ポイント更新により変更が O(log n) で上方に正しく伝播されます。 すべてのサブツリー クエリは 1 つのセグメントに正確に対応するため、そのサブツリーの外部の情報が結果に影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.t[v] = max(self.t[v*2], self.t[v*2+1])

    def update(self, v, l, r, idx, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(v*2, l, m, idx, val)
        else:
            self.update(v*2+1, m+1, r, idx, val)
        self.t[v] = max(self.t[v*2], self.t[v*2+1])

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return -10**18
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        return max(
            self.query(v*2, l, m, ql, qr),
            self.query(v*2+1, m+1, r, ql, qr)
        )

def solve():
    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    depth = [0] * (n + 1)
    euler = []

    def dfs(u, p):
        tin[u] = len(euler)
        euler.append(u)
        for w in g[u]:
            if w == p:
                continue
            depth[w] = depth[u] + 1
            dfs(w, u)
        tout[u] = len(euler) - 1

    dfs(1, -1)

    base = [depth[u] for u in euler]
    st = SegTree(base)

    out = []
    for _ in range(q):
        v = int(input())
        res = st.query(1, 0, n - 1, tin[v], tout[v])
        out.append(str(res - depth[v]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS は、サブツリー クエリが間隔になるようにオイラー順序を構築します。 セグメント ツリーには深さが格納されるため、各クエリはサブツリー内の最大の深さを取得し、ルートの深さを減算して相対値に変換します。 

実装によくある落とし穴は、次のことを忘れることです。`tout`オイラー索引付けに含める必要があります。 もう 1 つのよくある間違いは、事前注文インデックスとサブツリー サイズを混合することです。これにより、間隔の正確さが損なわれます。 

## 実用的な例

 ### 例 1

 ツリーが 1-2-3-4 のチェーンであると仮定します。 

| ステップ | ノード | 錫 | 客引き | 深さ |
 | --- | --- | --- | --- | --- |
 | DFS | 1 | 0 | 3 | 0 |
 | DFS | 2 | 1 | 3 | 1 |
 | DFS | 3 | 2 | 3 | 2 |
 | DFS | 4 | 3 | 3 | 3 |

 ノード 2 をクエリすると、範囲 [1,3] が取得されます。 セグメント ツリーは最大深さ = 3 を返します。深さ[2]=1 を引くと 2 が得られます。 

これは、subtree(2) 内の最長の下向き距離と一致します。 

### 例 2

 ツリー: 1 と子供 2 と 3。 

| ノード | 錫 | 客引き | 深さ |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 0 |
 | 2 | 1 | 1 | 1 |
 | 3 | 2 | 2 | 1 |

 クエリ ノード 1 は範囲 [0,2] を使用し、最大深度は 1 です。深さ [1]=0 を引くと 1 が得られます。 

これにより、子が走査順序で切断されている場合でも、サブツリーの高さが正しくキャプチャされることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | DFS はオイラー順序を構築します。各クエリはセグメント ツリー範囲クエリです。 
| スペース | O(n) | 隣接リスト、オイラー配列、セグメント ツリー |

 対数係数が小さいままであるため、これは 2×10^5 ノードとクエリの一般的な制約内に問題なく収まります。

 ## 特殊なケース

 チェーン形状のツリーでは、すべてのサブツリーがオイラー配列の接尾辞になります。 各サブツリー間隔は連続しており、サイズが増加しているため、アルゴリズムはこれを正しく処理します。 

星型ツリーでは、すべての葉が単一要素の間隔にマッピングされます。 セグメント ツリーは独自の深さを返し、減算すると 0 が得られます。これは、リーフにはより深い子孫がないため、これが正しいです。 

非常に偏った再帰ツリーでは、再帰の深さの問題を避けるために DFS を慎重に実装する必要があります。 再帰制限を増やすと、スタック オーバーフローを起こさずに走査が安全に完了します。
