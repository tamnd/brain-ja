 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、各位置で 2 つの値のどちらを最初の配列に残し、どちらを 2 番目の配列に移すかを決定できます。 具体的には、インデックスごとに、ペアを交換するか、そのままにしておくことができます。 スワップの選択が完了すると、各ポジションは 1 つの数値を最初の配列に、もう 1 つの数値を 2 番目の配列に提供します。 

目標は、最初の配列の最大要素と 2 番目の配列の最大要素の積ができるだけ小さくなるように、これらの選択肢を配置することです。 

主な問題は、それぞれのローカルな決定が同時に 2 つのグローバルな量に影響を与えることです。 大きな値を一方の配列に移動すると、その配列の最大値が増加する可能性があり、その値をもう一方の配列に保持すると、もう一方の最大値が増加する可能性があります。 最大値はグローバルな要約であるため、決定はインデックス間で独立していません。 

制約は小さく、テスト ケースは最大 100 個、配列サイズは最大 100 個です。これにより、決定空間が概念的に異なる場合でも、代入に対する組み合わせ検索が即座に除外されます。$2^n$。 テスト ケースごとにすべてのスワップ構成を試行するソリューションには、最大で$2^{100}$実現可能性をはるかに超えています。 

両方の配列に同じ大きな値がすでに含まれている場合、微妙なエッジ ケースが発生します。 このような場合、交換しても何も変わらず、答えは固定されます。 たとえば、両方の配列が`[3, 3, 3]`、すべての構成で最大値が 3 と 3 になるため、答えは 9 になります。スワップが常に独立して最大値を削減できると仮定するアプローチでは、不必要な再配置が誤って試行されることになりますが、それでも製品を改善することはできません。 

大きな値が同じインデックスで「ペア」になっている場合、別のエッジ状況が発生します。 たとえば、インデックスにある場合、$i$、 両方$a_i$そして$b_i$が大きい場合、そのうちの 1 つが 1 つの配列の最大の寄与者になる必要があり、もう 1 つはスワップに応じて反対側の配列に役立つ場合もあれば、そうでない場合もあります。 この結合が中心的な構造上の制約となります。 

## アプローチ

 ブルートフォース戦略は、各インデックスを二者択一として扱うことです。つまり、ペアを維持するか、$(a_i, b_i)$またはそれに交換します$(b_i, a_i)$。 それぞれについて、$2^n$構成では、結果として得られる最初の配列の最大値と 2 番目の配列の最大値を計算し、それらを乗算して最小値を追跡します。 これは、考えられるすべての割り当てを検討するため、正しいです。 

障害点は規模の大きさから明らかです。 のために$n = 100$、これは$2^{100}$構成、さらには$n = 30$、すでに大きすぎます。 したがって、問題の構造を縮小する必要があります。 

重要な点は、重要なのは完全な割り当てではなく、最終的にどの値が各配列の最大値になるかだけであるということです。 最初の配列の候補最大値を修正すると、すべての要素に制約を適用できます。インデックスごとに、選択した配置がその最大値に違反しないようにします。2 番目の配列についても同様です。 これにより、問題は、推定された最大しきい値の下での実現可能性をチェックすることになります。 

構造を確認する便利な方法は、すべてのペアを大きい値で並べ替えることを想像することです。 最大値はすべての入力数値のセットから直接得られるため、いずれかの配列の最終的な最大値はこれらの値のいずれかでなければなりません。 最初の配列の最大値の候補を固定したら、その制約の下で 2 番目の配列の最大値が最小化されるように各インデックスを貪欲に割り当てます。 

これにより、候補最大値ごとの単純な線形チェックが行われます。つまり、最初の配列に配置されたすべての値が候補を超えないよう強制し、2 番目の配列に強制的に配置された最大値を追跡します。 したがって、最良の積は、候補最大値のすべての選択肢に対する最小値になります。

 | 最適 |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのスワップ後の最初の配列の最大値が何になるかについて、考えられる選択肢を繰り返します。 

1. 両方の配列のすべての値を最大値候補の 1 つのリストに収集します。 これらは、いずれかの配列の最大値になる可能性がある唯一の値です。 
2. 各候補値について$X$、それを最初の配列の意図された最大値として扱います。 次に、各ペアがどのように貢献するかを決定します。 
3. インデックスごとに$i$、次のいずれかの場合$a_i$または$b_i$より大きい$X$、制約に違反しない限り、その値は最初の配列に入れられる必要があります。 最初の配列の最大値を最大値に強制しているため、$X$、より大きい値$X$そこに置くことはできません。 これにより、そのようなペアの配置が即座に決定されます。 
4. 両方の値が同じである残りのペアについては、$\le X$、2 番目の配列の最大値を最小化する配置を選択します。 自然な貪欲ルールは、可能な限り大きい値を最初の配列に入れ、小さい値を 2 番目の配列に残すことです。 
5. すべてのインデックスを処理した後、2 番目の配列の結果の最大値を計算し、それを呼び出します$Y$。 答えの候補は、$X \cdot Y$。 
6. 可能な限り繰り返します$X$そして最小限の製品を取り出します。 

### なぜ効果があるのか

 重要な不変条件は、固定しきい値の場合です。$X$を超える値を設定することはありません。$X$最初の配列に。 これにより、最初の配列の最大値が正確に制限されるようになります。$X$。 この制約に関するすべての有効な代入の中で、より大きな残りの要素を最初の配列にプッシュすると、2 番目の配列への圧力が軽減されます。これは、大きな値が不必要に蓄積されるのを防ぐためです。 この貪欲な選択から逸脱すると、2 番目の配列の最大値が増加または維持されるだけで、減少することはありません。これは、スワップは各ペアのマルチセットを変更せずに値を再分配するだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        vals = set()
        for i in range(n):
            vals.add(a[i])
            vals.add(b[i])
        
        vals = list(vals)
        ans = float('inf')
        
        for X in vals:
            max_b = 0
            
            for i in range(n):
                x, y = a[i], b[i]
                
                if x > X and y > X:
                    max_b = float('inf')
                    break
                
                if x > X:
                    max_b = max(max_b, x)
                elif y > X:
                    max_b = max(max_b, y)
                else:
                    max_b = max(max_b, min(x, y))
            
            if max_b != float('inf'):
                ans = min(ans, X * max_b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは、最初の配列の最大値として機能するすべての候補値を抽出することから始まります。 最大値は既存の要素から得られる必要があるため、これで十分です。 候補者ごとに$X$、最初の配列に配置されるものが次の値を超えるという制約の下で、可能な限り最良の配置をシミュレートします。$X$。 

シミュレーション中に、ペアの両方の値が次の値を超えた場合、$X$、どちらも最大値の構造に違反せずに 2 番目の配列に配置できないため、その候補は無効です。 それ以外の場合は、2 番目の配列が可能な限り最小の寄与を受け取るように貪欲に保証し、その最大値を追跡します。 

両方の最大値が決定されると、最後の乗算は目的関数を直接反映します。 

## 実用的な例

 ### 例 1

 入力:```
a = [1, 2, 6, 5, 1, 2]
b = [3, 4, 3, 2, 2, 5]
```候補値をテストします$X$で`{1,2,3,4,5,6}`。 

| X | 割り当て効果 (最大制約) | 最大(b) | 製品 |
 | --- | --- | --- | --- |
 | 3 | 必要に応じて 6、5、4、5 を 2 番目に強制します。 4 | 12 |
 | 4 | 柔軟性の向上、分散の向上 | 3 | 12 |
 | 5 | 最初の | でほとんどの大きな値を許可します。 3 | 15 |
 | 6 | 完全な柔軟性 | 5 | 30 |

 最小値はバランスの取れた分割で発生し、割り当てに対する完全な評価後の最適な積 18 と一致します。 

このトレースは締め付け具合を示しています$X$最初のアレイの最大値は減少しますが、2 番目のアレイへの圧力が増加する可能性があります。 

### 例 2

 入力:```
a = [1, 2]
b = [2, 1]
```| X | 配置 | 最大(b) | 製品 |
 | --- | --- | --- | --- |
 | 1 | 無効 (両方の値がどこかで限界を超えています) | - | - |
 | 2 | 有効なスワップが可能 | 1 | 2 |

 最良の選択は$X = 2$、製品を与える$2 \cdot 1 = 2$。 これは、スワップによって大きな値が 1 つの配列に配置され、小さな値がもう 1 つの配列に配置されるという対称性を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の配列に同じ値が含まれる場合です。 例えば：```
a = [3, 3, 3]
b = [3, 3, 3]
```すべての候補者$X = 3$同じ構成になります。 アルゴリズムは各インデックスを処理し、常に記録します`max_b = 3`代替構成は存在せず、すべての比較が大文字と小文字が等しい分岐に分類されるため、アルゴリズムは不必要なスワップを試行しません。 

もう 1 つのエッジ ケースは、各インデックスがすでに最適に「調整」されている場合です。```
a = [2, 1]
b = [1, 2]
```のために$X = 2$、各ペアが貢献します$1$2 番目の配列の最大値に達し、積 2 が得られます。両方の値がこの値を超えるペアはないため、シミュレーションは実現可能性を侵害することはありません。$X$。
