 ## 解決策
 ## 問題の理解

 私たちには建物の木が与えられています。 各建物はノード、各道路はエッジであり、この構造により、2 つのノード間には 1 つの単純なパスが存在することが保証されます。 

2 人が同時に開始します: 1 人はノードから開始します$a$、もう一方はノードから始まります$b$。 1 分ごとに、両方が留まるか、1 つのエッジに沿って隣接するノードに移動することができ、同じ速度で移動します。 同じ瞬間に、同じノードにいるか、同じエッジを反対方向に横断している場合、移動している人はすぐに捕らえられ、プロセスが停止します。 

そのうちの 1 つは、捕まる前に訪問できる建物の数を最大化しようとしています。 タスクは、両側からの最適なプレイを想定して、彼女が訪問できる個別のノードの最大可能数を計算することです。 

重要な構造的制約は次のとおりです。$n \le 10^6$これにより、すべてのペアの最短パスや開始位置ごとの BFS シミュレーションの繰り返しなどの二次関数が即座に除外されます。 どのような解も本質的に線形または線形対数的でなければなりません。 

微妙な失敗のケースは、両方のプレイヤーがプレイヤーの間の固有のパスに沿って対称的に移動するときに発生します。$a$そして$b$。 たとえば、単純な行で$1 - 2 - 3 - 4$、 もし$a = 1$そして$b = 4$素朴な考えでは、ランナーは自由に「分岐」できると思われるかもしれませんが、実際には、合流点の制約により、経路に沿った決定的な相互作用が強制され、正確に距離が一致したときにキャッチが発生します。 

もう 1 つの例外的なケースは次のような場合です。$a = b$。 その状況では、即座に捕獲され、移動は不可能であるため、答えはゼロです。 

最後に、キャプチャは同じエッジを同じ分内に反対方向に横断するときにも発生するため、正しい推論では、それらの移動を単に個別のノード占有ではなく、ツリー メトリックに沿った連続的な距離の減少として効果的に扱う必要があります。 

## アプローチ

 強引なアイデアは、両プレイヤーの動きを段階的にシミュレートすることです。 各時間単位で、ランナーの可能なすべての動きとチェイサーの可能なすべての応答を考慮し、到達可能なすべての状態を追跡します。 各状態には、位置と、これまでに訪問したノードのセットの両方が含まれます。 状態空間が爆発するため、これはすぐに実行不可能になります。$O(n^2)$位置ペア、および訪問セットの複雑さを無視しても、遷移は指数関数的に拡大します。 状態空間上の単一の BFS であっても、次のオーダーが必要になります。$n^2$またはそれ以上の操作は不可能です$10^6$。 

重要な観察は、ツリー構造により非常に厳格な相互作用が強制されるということです。 間にはパスが 1 つだけあります$a$そして$b$、そしてチェイサーは常に最短経路に沿ってランナーに向かって移動します。 これにより、インタラクション全体がツリー メトリックに沿った 1 つの次元に縮小されます。 

ランナーは、チェイサーの前進によって「支配」されていないノードのみを安全に探索できます。 木を根付かせると、$b$の場合、すべてのノードにはチェイサーの開始点までの距離が明確に定義されます。 チェイサーは常にランナーとの距離を縮めるために移動するため、いつでも効果的にチェイサーのリーチは外側から全方向に広がります。$b$速度 1 で、ランナーも速度 1 で移動します。ランナーは、チェイサーがノードに到達する前にのみノードを訪問できます。 

これにより、問題はツリー上の古典的な最先着比較に変換されます。つまり、からの距離を計算します。$b$すべてのノードにアクセスし、ランナーが次から始まる実行可能な探索パスに沿ってどこまで進むことができるかを決定します。$a$追い越される前に。 正しい解釈は、ランナーがチェイサーよりも厳密に早く到着できれば、ノードはランナーにとって「安全」であるということです。 

したがって、からのすべての距離を計算します。$b$BFS を使用します。 次に、次から 2 番目の BFS を実行します。$a$ただし、ランナーの到着時間がチェイサーの到着時間よりも厳密に短いエッジのみをトラバースします。 この制約された BFS 内の到達可能なノードの数が答えです。

 ## アルゴリズムのチュートリアル

 私たちは、両方のプレイヤーが木の上を同じ速度で移動するという事実を利用するため、到達可能性は完全に最短経路の距離によって決まります。 

1. ノードからの最短距離を計算する$b$BFS を使用して他のすべてのノードに送信します。 これにより、チェイサーが各ノードを占有できる最も早い時間が得られます。 これが有効なのは、ツリーには単位重みのエッジがあるため、BFS は正確な最短パスを生成します。 
2. ノードから開始して 2 番目の BFS を初期化します。$a$。 ランナーの到着時刻を次のように設定します。$a$ゼロに設定し、訪問済みとしてマークします。 
3. BFS 拡張中は、ノードからの移動を検討してください。$u$隣人に$v$。 ランナーが到着するのは、$v$時に$dist_a[u] + 1$。 
4. 次への移行のみを許可します。$v$もし$dist_a[u] + 1 < dist_b[v]$。 これにより、ランナーがチェイサーよりも厳密に先に到着することが保証されます。これは、同時に到着するとノードまたはエッジに沿ってキャプチャされるため、必要です。 
5. この BFS で訪問した有効なノードごとに、応答を増加させます。 これは、ランナーが捕まる前に安全に到達できるすべての建物をカウントします。 
6. BFS キューがなくなるまで続行します。 

重要な実装の詳細は、厳密な不等式を使用することです。 エッジでの出会いもキャプチャ イベントであるため、平等は拒否されなければなりません。 

なぜ機能するのか: BFS の$b$すべてのノードに対してグローバルな「脅威時間」を定義します。 ランナーの BFS は、到着時間が脅威時間よりも厳密に小さくなければならないという制約の下で、到達可能なノードの最大プレフィックスを構築します。 どちらのプロセスもツリー上の単位速度で同期して進化するため、この制約に違反するとノードまたはミッドエッジでの遮断が避けられないことを意味するため、これに違反するパスは最適な安全な軌道の一部にはなり得ません。 逆に、それを尊重するパスは、チェイサーの到着と同期することなく、最短ステップの動きを選択し続けることで実行できます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    a -= 1
    b -= 1

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    INF = 10**18

    dist_b = [INF] * n
    q = deque([b])
    dist_b[b] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist_b[v] == INF:
                dist_b[v] = dist_b[u] + 1
                q.append(v)

    dist_a = [-1] * n
    q = deque([a])
    dist_a[a] = 0

    ans = 1

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist_a[v] != -1:
                continue
            nd = dist_a[u] + 1
            if nd < dist_b[v]:
                dist_a[v] = nd
                ans += 1
                q.append(v)

    print(ans)

if __name__ == "__main__":
    solve()
```最初の BFS は、チェイサーの最早到着時間を次から計算します。$b$。 2 番目の BFS は、$a$ここで、各ステップでは、ランナーが次のノードでチェイサーよりも厳密に早く到着するかどうかがチェックされます。 答えは、この制約されたトラバーサルで正常にキューに入れられたすべてのノードをカウントします。$a$自体。 

よくある間違いは、厳密な不等式を忘れて平等を許すことです。これにより、キャプチャが正確に到着時間またはエッジに沿って発生するノードが誤ってカウントされます。 もう 1 つの微妙な問題は、開始ノードの答えを 1 で初期化するのを忘れていることです。$a$は常に移動の前に最初にアクセスされます。

    def solve():
        n, a, b = map(int, input().split())
        a -= 1
        b -= 1

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1

        dist_b[b] = 0
        while q:
            u = q.popleft()
            for v in g[u]:
                if dist_b[v] == INF:
                    dist_b[v] = dist_b[u] + 1
                    q.append(v)

 ## 特殊なケース

 いつ$a = b$、BFSから$a$チェイサー距離がゼロのノードから開始します。 この条件は厳密な不等式を必要とするため、拡張はできません。 アルゴリズムは開始ノードのみを考慮して 1 を正しく返します。 

木が単純なパスの場合、$a$そして$b$がエンドポイントである場合、距離配列は対称になり、あらゆる潜在的な動きはある時点で等しくなります。 BFSから$a$開始ノードを超えて拡張することはできません。これは、あらゆる動きがノードまたはエッジに沿った即時の遮断につながるという事実と一致します。 

いつ$n = 1$、両方の BFS プロシージャは単一ノードの初期化に縮退し、答えは 1 のままです。これは、唯一の建物が自明に訪問されるため、一貫しています。
