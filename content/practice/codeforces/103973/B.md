 ## 問題の理解

 1 から次の形式の大きな上限までの連続する整数のセットが与えられます。$nm + k$。 このセットから、考えられるすべてのサブセットを検討します。 各サブセットについて、その要素の合計を計算し、その合計を剰余で減らします。$m$。 タスクは、剰余クラスごとにカウントすることです$r$から$0$に$m-1$、何個のサブセットが一致する合計を生成するか$r$モジュロ$m$。 

入力は 3 つのパラメーターを中心に構造化されています。 値$m$は、サブセット合計の係数と、出力する必要がある回答の数の両方を定義します。 整数$n$非常に大きくなる可能性があり、最大で$10^{13}$これは、概念的には間隔が非常に長いことを意味します。 値$k$小さい、厳密には両方よりも小さい$m$500 は、高度に構造化された基本システムに対する摂動として個別に処理されることを意味していることを示唆しています。 

当面の制約問題は、ユニバースのサイズが$nm + k$巨大になる可能性があるため、要素を反復するメソッドは不可能です。 セットを保管することさえ不可能です。 解決策は、次の点に関する構造周期性にのみ依存する必要があります。$m$、明示的な列挙ではありません。 

単純な間違いは、次の要素までのすべての要素に対して動的プログラミング テーブルを構築できると仮定することです。$nm + k$。 たとえば、次のような場合でも、$m = 1$、設定できるサイズは$10^{13}$、だからどれでも$O(nm)$または$O(nm \cdot m)$アプローチは即座に除外されます。 

もう 1 つの微妙な失敗例は、プレフィックスを次のように処理することに起因します。$nm$そして長さの接尾辞$k$畳み込みモジュロを正しく処理せずに独立して$m$。 2 つの部分は関数を生成する際に乗算的に相互作用するため、分離が正しくないと、分布が間違ってしまいます。 

## アプローチ

問題は規模だ。 移行コストは、$O(m)$要素ごとに、$nm + k$要素。 これは次のことにつながります$O((nm + k)m)$、これは完全に不可能です。$nm$できる$10^{13}$。

 ## アルゴリズムのチュートリアル

 サブセット選択プロセスは、各要素が次のような多項式を構築するものと解釈します。$i$要因に寄与する$(1 + x^{i \bmod m})$、および係数$x^r$合計が一致するサブセットをカウントします$r \mod m$。 何よりもこの商品が欲しい$i$から$1$に$nm + k$、モジュロで評価される$x^m - 1$。 

### ステップ 1: 範囲を完全なブロックとサフィックスに分割する

 セットを 2 つの部分として書きます。$1 \ldots nm$そして$nm+1 \ldots nm+k$。 2 番目の部分は小さいので、後で直接処理します。 最初の部分は強い周期構造を持っています。 

### ステップ 2: 1 つの完全なブロックを減らす

 1つのブロックを考えてみましょう$1 \ldots m$。 各剰余モジュロ$m$は 1 回だけ表示されます。 このブロックの役割は、現在の DP 状態に次の値を乗算する畳み込み演算子です。$$P(x) = \prod_{i=1}^{m} (1 + x^{i \bmod m})$$モジュロ$x^m - 1$。 残基は順列であるため、これは残基の順序ではなく、残基のマルチセットにのみ依存します。 

これにより基本的な変換が行われます$F$長さ的には-$m$DP ベクトル。 

### ステップ 3: ブロック効果を累乗する

 範囲$1 \ldots nm$は$n$同一のブロック。 ブロック変換を適用する$n$申請に相当する時間$F^n$。 

シミュレーションする代わりに$n$畳み込みを計算します$F^n$2進累乗を使用します。 各構成は長さの循環畳み込みです$m$したがって、各乗算にはコストがかかります$O(m^2)$、およびべき乗コスト$O(m^2 \log n)$。 FFT のような巡回畳み込み構造または直接 DP 最適化を使用した最適化では、これは所定の制約内で許容されます。 

### ステップ 4: ハンドル接尾辞$k$DP をアイデンティティ状態として初期化し、適用します$F^n$。 次に要素を処理します$nm+1 \ldots nm+k$直接、標準サブセット DP で DP を更新します。 

要素ごとに$v$、DPを次のようにシフトします$v \bmod m$。 

以来$k < 500$、このステップは無視できます。 

### ステップ 5: 答えを抽出する

 すべての変換の後、DP 配列には、和の法でグループ化されたサブセットの数が含まれます。$m$。 全部出力します$m$価値観。 

### なぜ効果があるのか

 核となる不変条件は、DP ベクトルが常にサブセット合計のモジュロの係数分布を表すことです。$m$要素のプレフィックスを処理した後。 各要素は二項因数による乗算に対応します$(1 + x^v)$リングの中で$\mathbb{Z}[x]/(x^m - 1)$。 このリングでの乗算は結合的であるため、要素をブロックにグループ化すると正確さが保たれます。$n$累乗を伴う連続した同一の乗算は、最終的な多項式を変更しません。 接尾辞は、不変条件を維持しながら、そのような少数の係数を単純に追加乗算したものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def conv(a, b, m):
    res = [0] * m
    for i in range(m):
        if a[i]:
            ai = a[i]
            for j in range(m):
                if b[j]:
                    res[(i + j) % m] = (res[(i + j) % m] + ai * b[j]) % MOD
    return res

def identity(m):
    res = [0] * m
    res[0] = 1
    return res

def build_block(m):
    dp = [0] * m
    dp[0] = 1
    for i in range(1, m + 1):
        ndp = dp[:]
        v = i % m
        for r in range(m):
            ndp[(r + v) % m] = (ndp[(r + v) % m] + dp[r]) % MOD
        dp = ndp
    return dp

def power(base, exp, m):
    res = identity(m)
    cur = base
    while exp:
        if exp & 1:
            res = conv(res, cur, m)
        cur = conv(cur, cur, m)
        exp >>= 1
    return res

def apply_suffix(dp, k, m):
    for i in range(1, k + 1):
        v = i % m
        ndp = dp[:]
        for r in range(m):
            ndp[(r + v) % m] = (ndp[(r + v) % m] + dp[r]) % MOD
        dp = ndp
    return dp

n, k, m = map(int, input().split())

block = build_block(m)
dp = power(block, n, m)
dp = apply_suffix(dp, k, m)

print(*dp)
```コードは最初に、サイズの単一の完全なブロックによって引き起こされる DP 変換を構築します。$m$。 その変換は長さとして表されます。$m$ベクトルのエントリ$i$は、1 つのブロックがサブセット合計カウントをシフトする方法を示します。 次に、繰り返しの巡回畳み込みを使用してこの変換をべき乗します。 

べき乗ルーチンは、各変換を多項式モジュロとして処理します。$x^m - 1$、合成は畳み込みになります。 これが、乗算の理由です`conv`インデックスにモジュロ加算を使用します。 

最後に、接尾辞は直接適用されます。これは、そのサイズが十分に小さいため、残基に対する線形 DP が許容されるためです。 

微妙な点は、恒等変換ではすべての質量を剰余 0 に配置する必要があることです。そうしないと、累乗中に畳み込みが正確さを破壊してしまいます。

 ## 特殊なケース

 重要なコーナーケースの 1 つは次のような場合です。$n = 0$。 この状況では、完全なブロックはまったく存在せず、サフィックスのみが存在します。$1 \ldots k$貢献します。 指数がゼロの場合、べき乗は恒等変換を返すため、アルゴリズムはこれを正しく処理します。そのため、DP はクリーンな状態から開始され、サフィックスの更新のみが適用されます。 

もう一つのエッジケースは、$m = 1$。 あらゆる数字は$0 \mod 1$, したがって、すべてのサブセットの合計はゼロになります。 DP は、すべてのサブセットをカウントする単一の値に折りたたまれます。$2^{nm+k}$。 このアルゴリズムでは、すべてのインデックスは 0 のままで、畳み込みはスカラー倍算に縮退し、特別なケースを使用せずに正確さを維持します。 

3 番目の微妙なケースは、$k = 0$。 ここでは、サフィックス ループが完全にスキップされ、結果は純粋に累乗されたブロック変換になります。 これにより、不必要な作業が回避され、全範囲が正確に測定されるため、正確さが保証されます。$n$基本構造の繰り返し。
