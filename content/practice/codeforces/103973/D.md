 ## 問題の理解

 固定数のビットに適用されるビットごとの変換が与えられます。 符号なし整数`x`を使用して正確に表されます`k`ビットなので、すべての値は次の範囲にあります。`0`に`2^k - 1`。 操作の配列も与えられます。 各操作により、現在の値が変更されます。`x`演算値が正か負かに応じて、それ自体を左シフトまたは右シフトしたバージョンと XOR 演算します。 

すべての操作を順番に適用すると、最終的な値が得られます。 タスクは、次の初期値がいくつあるかを数えることです。`x`完全な変換後も変更されません。つまり、関数はまったく同じものを返します。`x`私たちはから始めました。 答えは 998244353 を法として計算する必要があります。 

主な難点は、変換が単純な算術関数ではなく、位置全体でビットを混合するビット単位のプロセスであり、考えられるすべての開始状態に暗黙的に適用されることです。 

制約が非常に厳しいため、すべてを試すことができます`2^k`可能な値が不可能な場合`k`は 1000 にもなります。すべての状態を 1 回通過するだけでも、すでに制限を超えています。`2^1000`天文学的に大きいです。 同様に、各候補の関数をシミュレートします。`x`状態ごとに最大 1000 の操作を適用する必要がありますが、これは完全に不可能です。 

単純だがより構造化された試みでは、各ビットの変換を個別にシミュレートしようとする可能性がありますが、これも失敗します。シフトによってビット間の依存関係が生じるため、つまり各出力ビットが複数の入力ビットに依存するためです。 

微妙なエッジケースが現れるのは、`n = 0`。 その場合、関数は何もしないので、`x`は固定点です。 そのときの答えは次のようになります。`2^k mod MOD`。 少なくとも 1 つの操作が存在することを前提としたソリューションでは、誤った値が返されます。`0`または`1`実装に応じて。 

もう 1 つの重要なエッジ ケースは、シフトによってビットが完全に範囲外に押し出される場合です。 たとえば、次の場合`k = 5`そして私たちは次のようにシフトします`4`または`-4`、ビットのごく一部だけが有効のままです。 正しく取り扱うにはマスキングが必要です`k`すべての操作の後にビットが表示されます。 

## アプローチ

 変換はフォームの繰り返し操作から構築されます。`x ^= (x << s)`または`x ^= (x >> s)`。 XOR は加算法 2 に対応し、シフトはビット位置の固定線形マッピングに対応するため、このような各演算はフィールド GF(2) 上で線形です。 これは、関数全体が次の線形変換であることを意味します。`k`GF(2) 上の - 次元ベクトル空間。 

ブルートフォースのアイデアでは、可能なすべての関数を明示的にシミュレートします。`x`。 候補ごとにすべての操作を適用し、結果が元のものと一致するかどうかを確認します。 これには必要です`2^k`シミュレーション、それぞれのコスト`O(nk)`最悪の場合はビット操作が行われます。 定数を無視したとしても、これは実現可能な限界をはるかに超えています。 

重要な点は、すべての入力に対して関数を評価する必要がないということです。 線形変換は、その効果によって完全に決定されます。 各基底ベクトルがどのように進化するかを維持すると、変換を次のように表すことができます。`k × k`バイナリ行列。 各演算は、シフト XOR ルールによって引き起こされる別のスパース線形演算子をこの行列に左乗算することに対応します。 

完全な変換行列を取得したら`T`、固定点の条件は次のとおりです。`T(x) = x`、次のように書き換えることができます`(T - I)x = 0`。 GF(2) では、減算は XOR となるため、これは次のようになります。`(T XOR I)x = 0`。 解の数は、この行列のヌル空間のサイズと正確に一致します。`2^(k - rank)`。 

したがって、問題をランクの計算に縮小します。`k × k`バイナリ行列。ガウス消去法で実行できます。`O(k^3 / 64)`ビットセットを使用します。

 ## アルゴリズムのチュートリアル

 変換を GF(2) 上の行列として解釈します。ここで、各列は基底ベクトルのイメージを表します。 この行列を段階的に構築し、線形システムを解きます。 

1. を初期化します。`k × k`アイデンティティの変革。 これは、演算を適用する前に、各ビットがそれ自体にマップされるという事実を表します。 
2. 変換をビットセットの配列として表現します。`T`、 どこ`T[i]`基底ベクトルの画像です`i`。 当初は、`T[i]`位置に 1 が 1 つあります`i`。 
3. 配列内の各操作を処理します。 シフトの場合`s`、線形演算子を定義します`L`シフトされたバージョンとの XOR 演算によって任意のベクトルを変換します。 これをすべての可能なベクトルに適用する代わりに、変換行列の各列に直接適用します。 これが機能するのは、線形マップの出力に線形演算子を適用することは、線形マップを作成することと同じであるためです。 
4. 各列について`T[i]`、shift-XOR ルールを適用してその場で更新します。 これにより、行列と構成された変換の一貫性が保たれます。 
5. すべての操作を処理した後、完全な変換行列を取得します。`T`。 
6. マトリックスの構築`B = T XOR I`に対応します。`(T - I)`GF(2) を超えます。 この行列は、固定小数点の条件をエンコードします。 
7. ビットセットを使用して GF(2) に対してガウス消去法を実行し、次のランクを計算します。`B`。 各ピボットは、解空間の次元を 1 つ減らします。 
8. 答えを次のように計算します。`2^(k - rank)`モジュロ 998244353。 

正確さは、各操作後に次の不変条件に依存します。`T`これまでに見られたすべての変換の構成を正しく表しています。 各演算は線形であるため、すべての基礎画像に適用して合成すると正確性が保たれます。 最終的なシステム`Bx = 0`完全な変換後も変更されないすべてのベクトルを正確にキャプチャし、その解空間の次元によって有効なベクトルの数が決まります。`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def gauss_rank(mat, k):
    rank = 0
    row = 0

    for col in range(k - 1, -1, -1):
        pivot = -1
        for i in range(row, k):
            if (mat[i] >> col) & 1:
                pivot = i
                break
        if pivot == -1:
            continue

        mat[row], mat[pivot] = mat[pivot], mat[row]

        for i in range(k):
            if i != row and ((mat[i] >> col) & 1):
                mat[i] ^= mat[row]

        row += 1
        rank += 1
        if row == k:
            break

    return rank

def apply_op(cols, s, k):
    new_cols = [0] * k
    if s >= 0:
        for i in range(k):
            x = cols[i]
            new_cols[i] = x ^ ((x << s) & ((1 << k) - 1))
    else:
        s = -s
        for i in range(k):
            x = cols[i]
            new_cols[i] = x ^ (x >> s)
    return new_cols

def main():
    n, k = map(int, input().split())
    A = list(map(int, input().split()))

    cols = [(1 << i) for i in range(k)]

    mask = (1 << k) - 1

    for a in A:
        if a >= 0:
            s = a
            for i in range(k):
                cols[i] = cols[i] ^ ((cols[i] << s) & mask)
        else:
            s = -a
            for i in range(k):
                cols[i] = cols[i] ^ (cols[i] >> s)

    mat = cols[:]
    for i in range(k):
        mat[i] ^= (1 << i)

    rank = gauss_rank(mat, k)

    pow2 = 1
    exp = k - rank
    for _ in range(exp):
        pow2 = pow2 * 2 % MOD

    print(pow2)

if __name__ == "__main__":
    main()
```このソリューションは、各列を 1 つの列として扱い、列ごとに変換を構築します。`k`-ビット整数。 各シフト XOR 演算はすべての列に直接適用され、これは線形マップの作成に相当します。 その後、単位行列の XOR 演算によって問題を同次線形システムの解法に変換し、ビットセットに対するガウス消去法を使用してそのランクを計算します。 最後の指数はシステムの無効さから導出されます。 

左シフトをマスクする際には注意が必要です。`k`-ビット境界が無効な位置に漏れません。 右シフトでは当然ビットが破棄されます。 消去ステップでは、列を高位から低位に処理して、ピボット選択が安定して効率的であることを保証します。

 ## 特殊なケース

 いつ`n = 0`、変容はアイデンティティです。 マトリックスは変わらないので、`T XOR I`はゼロ行列になります。 ガウス消去法によりランク 0 が見つかり、答えは次のようになります。`2^k`、つまり、考えられるすべてのビットマスクが固定小数点であることを意味します。 

すべての操作が境界を超えてシフトする場合、たとえば、相対的に大きなプラスのシフトが発生する場合、`k`、マスキング後、左シフト部分はゼロになります。 変換はより単純な XOR 構造になりますが、依然として線形のままです。 マトリックスの構築により、範囲外のビットが決して出現しないことが保証されるため、最終的なランク計算は有効なままになります。 

いつ`k = 1`、すべての変換は単一ビット演算に集約され、すべての行列は 1×1 システムに縮小されます。 消去ステップはこの縮退ケースを正しく処理し、単一ビットが保存されるかどうかに応じて 0 または 1 の固定点を生成します。
