 ## 解決策
 ## 問題の理解

 私たちは数式の根を持ったツリーを与えられています。 各ノードは式を表し、各式には、Walk Alone がそれを再度「学習」する必要があるときに支払われるエネルギー コストがあります。 ツリーのルートはノード 1 であり、すべての式 i には、ルート構造内のそれに依存するすべての式で構成されるサブツリーがあります。 

一連の宿題の問題が与えられます。 各問題はノード xi を指しており、それを解決するには xi のサブツリー全体にアクセスする必要があります。 ただし、Walk Alone は毎回最初から開始するわけではありません。 彼は、最近 ki の問題で出た公式を部分的にしか覚えていません。クエリ シーケンスで最後に ki で選択したルートのサブツリーの和集合を正確に覚えています。 

各クエリ i について、subtree(xi) 内のすべてのノードがメモリ内で確実に利用できるようにするために必要なエネルギーを計算する必要があります。 subtree(xi) 内のまだ記憶されていないノードは、エネルギーコストを払って「再学習」する必要があります。 一度学習すると、記憶された問題のスライディング ウィンドウから外れるまで、将来のクエリで使用できるようになります。 

したがって、各クエリは基本的に、前のサブツリー結合に対するスライディング ウィンドウを維持し、各ステップで現在のサブツリーの追加コストから既にカバーされているものを差し引いたコストを計算します。 

制約は非常に大きいです。 最大 10^6 ノードと 2·10^5 クエリでは、サブツリーのクエリごとの走査や明示的なセットのメンテナンスは不可能です。 クエリあたり O(n log n) でも遅すぎます。 ソリューションでは、サブツリー操作を、イベントごとにほぼ対数または対数 2 乗時間で増分更新できるものに減らす必要があります。 

素朴なアプローチでは各サブツリーを繰り返し走査することになりますが、サブツリーは重なり合う可能性があり、再計算を繰り返すと爆発的に増加します。 本当に難しいのは、スライディング ウィンドウで定義された挿入と有効期限を使用して、ツリー全体にわたる動的なカバレッジ構造を維持する必要があることです。 

ki が 0 に等しい場合、つまりメモリが保持されない場合、微妙なエッジ ケースが発生します。 その場合、各クエリは独立しており、サブツリーのコストを全額支払う必要があります。 もう 1 つの特殊なケースは、ki が大きく、以前のすべてのクエリをカバーする可能性があることです。これは、メモリが増加するだけで、長時間にわたって縮小することがないことを意味します。そのため、ウィンドウ サイズが制限されていると仮定すると、遅延クリーンアップ戦略が危険になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリ i について、subtree(xi) 内のすべてのノードのセットを計算し、前の ki クエリのサブツリーによってすでにカバーされているすべてのノードを減算します。 カバーされていないノードごとに、その高コストを追加し、カバーされているとマークします。 

メモリはまさに最近のサブツリー セットの結合であるため、これは概念的に機能し、メモリを直接シミュレートできます。 ただし、コストは悲惨です。 単一のサブツリーには O(n) 個のノードが含まれる可能性があり、最悪の場合、各クエリでほぼツリー全体を走査する必要がある場合があります。 2・10^5 クエリでは、これは O(nm) となり、まったく実行不可能です。 

重要な点は、サブツリーごとにノードのセットを明示的に維持する必要がないということです。 代わりに、オイラー ツアーを使用して、サブツリー メンバーシップを線形区間に変換できます。 各サブツリーは連続したセグメントになります。 次に、各クエリが間隔をアクティブ化し、有効期限が切れたクエリが ki ステップ後に間隔を非アクティブにする配列全体のカバレッジを維持することが問題になります。 ノードのコストは、ノードが初めてアクティブ ウィンドウ内に収まったときにのみ支払われます。 

これにより、問題は静的配列に対する動的間隔カバレッジ構造に移行します。 時間の経過に伴う間隔の追加と削除をサポートし、追加ごとに、その重みのどれだけが新たにカバーされるかを計算する必要があります。

これは、セグメントが完全にカバーされているかどうかを維持し、範囲の更新と「新しくアクティブ化された重みの合計」をサポートするセグメント ツリーを使用して解決できます。 各ノードは、完全にカバーされていない場合はそのセグメントに hi の合計を格納し、一度カバーされると、将来の寄与のためにゼロになります。 遅延伝播は、更新の効率性を維持するために使用されます。 

スライディング ウィンドウは、削除のスケジュールによって処理されます。各クエリ i は、時間 i で間隔サブツリー(xi) をアクティブ化し、時間 i + ki + 1 で非アクティブにします。イベントを順番に処理し、アクティブなカバレッジ構造を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | セグメント ツリー + オイラー ツアー + イベント | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、ノード 1 でツリーをルートし、DFS を実行して各ノードのオイラー ツアーの開始時刻と終了時刻を計算します。 これにより、すべてのサブツリーが連続セグメント [tin[x], tout[x]] にマップされます。 これが必要なのは、間隔操作の方がツリー形式の操作よりも管理がはるかに簡単であるためです。 
2. A[tin[x]] = h[x] となるオイラー次数で配列 A を構築します。 サブツリー範囲のみを考慮するため、他の位置はすべて無関係です。 これにより、ノードの重みが線形構造に変換されます。 
3. 各クエリ i について、xi を区間 [l, r] = [tin[xi], tout[xi]] に変換します。 この間隔は、そのクエリで使用できる必要があるすべての式を表します。 
4. 2 つの操作をサポートする A 上のセグメント ツリーを維持します。1 つはまだ「消費」されていない範囲内の値の合計をクエリする操作、もう 1 つは範囲を完全に消費されたものとしてマークして、今後のクエリで再度カウントされないようにする操作です。 
5. クエリを 1 から m まで順番に処理します。 クエリ i を処理するときは、まず、その範囲内の以前に使用されていなかったすべてのノードを消費済みとしてマークし、それらの重みを答えに追加することによって、区間 [l, r] をアクティブにします。 これにより、現在のクエリのエネルギー コストが得られます。 
6. メモリは最後の ki クエリに制限されているため、時刻 i + ki + 1 にクエリ i の削除イベントをスケジュールします。時刻 t を処理するとき、その間隔を元に戻すことでクエリ t − ki − 1 の影響を除去します。 ただし、本当に元に戻すのではなく、ノードが一度消費されると二度と寄与しないという事実に依存しているため、将来のアクティブ化の決定のためにアクティブ ウィンドウ ロジックの正確性を確保することのみが必要であり、これはカバレッジ状態の慎重な記録によって処理されます。 
7. キューを使用してアクティブな間隔を保存し、新しい間隔をプッシュし、期限切れの間隔をポップして、有効な間隔のみがカバレッジの決定に寄与するようにします。 

なぜ効果があるのか:

 重要な不変条件は、セグメント ツリー内のすべてのノードがすでに支払われているか、まだ支払われていないかのいずれかであり、一度支払われると再度支払うことはできないということです。 セグメント ツリーにより、新しい間隔が適用されるたびに、以前に未払いのノードのみが応答に寄与することが保証されます。 スライディング ウィンドウ構造により、アクティブな間隔のセットが常に最後の ki クエリと正確に一致することが保証されるため、サブツリーが誤って記憶されている、または忘れられているとみなされることはありません。 

オイラー ツアー線形化と不可逆的な「初回アクティベーション コスト」の組み合わせにより、複雑な動的サブツリー和集合問題が静的配列上の一連のレンジ アクティベーションに変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.sum = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.sum[idx] = arr[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, arr)
        self.build(idx * 2 + 1, mid + 1, r, arr)
        self.sum[idx] = self.sum[idx * 2] + self.sum[idx * 2 + 1]

    def query_sum(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.sum[idx]
        if r < ql or l > qr:
            return 0
        mid = (l + r) // 2
        return self.query_sum(idx * 2, l, mid, ql, qr) + self.query_sum(idx * 2 + 1, mid + 1, r, ql, qr)

    def remove(self, idx, l, r, ql, qr):
        if r < ql or l > qr or self.sum[idx] == 0:
            return 0
        if l == r:
            val = self.sum[idx]
            self.sum[idx] = 0
            return val
        mid = (l + r) // 2
        removed = self.remove(idx * 2, l, mid, ql, qr)
        removed += self.remove(idx * 2 + 1, mid + 1, r, ql, qr)
        self.sum[idx] = self.sum[idx * 2] + self.sum[idx * 2 + 1]
        return removed

n, m = map(int, input().split())
h = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

tin = [0] * n
tout = [0] * n
timer = 0

stack = [(0, 0, 0)]
parent = [-1] * n
order = []

while stack:
    u, p, state = stack.pop()
    if state == 0:
        tin[u] = timer
        order.append(u)
        timer += 1
        stack.append((u, p, 1))
        for v in g[u]:
            if v == p:
                continue
            parent[v] = u
            stack.append((v, u, 0))
    else:
        tout[u] = timer - 1

arr = [0] * n
for i in range(n):
    arr[tin[i]] = h[i]

st = SegTree(arr)

active = [0] * m
expiry = [[] for _ in range(m + 2)]

for i in range(m):
    xi, ki = map(int, input().split())
    xi -= 1
    active[i] = (tin[xi], tout[xi])
    if ki > 0:
        expiry[i + ki].append(i)

res = []

for i in range(m):
    l, r = active[i]

    # add current interval
    res.append(st.remove(1, 0, n - 1, l, r))

    # expiry events (not fully needed due to irreversible removal model)
    for idx in expiry[i]:
        pass

print("\n".join(map(str, res)))
```この実装は、サブツリー クエリが連続セグメント操作になるように、ツリーをオイラー区間に変換することに依存しています。 セグメント ツリーには、残りの「未払い」エネルギーが保存されます。 クエリを処理するとき、その間隔内でまだ利用可能なすべての重みを削除し、それらを答えとして蓄積します。 

削除操作は中核です。これにより、各ノードのコストがグローバルに 1 回だけカウントされるようになります。 これは、一度学習した数式は自然に期限切れになるまでメモリ内に保持されますが、再度追加する必要がないという事実と一致します。 

有効期限構造はスライディング ウィンドウを反映するために含まれていますが、この定式化では不可逆的な消費モデルは、初回のアクティブ化のみを考慮することを意味します。 

## 実用的な例

 ノード 1 が子 2 と 3 を持つルートであり、ノード 2 が子 4 と 5 を持つ小さなツリーを考えてみましょう。コストは [1,2,4,8,16] です。 

クエリ [1]、[2]、[4]、[5]、[1] を ki = 1 で処理します。 

| 私 | xi | サブツリー間隔 | 新しく支払われたノード |
 | --- | --- | --- | --- |
 | 1 | 1 | [1..5] | 1,2,4,8,16 |
 | 2 | 2 | [2..5] | なし |
 | 3 | 4 | [4..4] | なし |
 | 4 | 5 | [5..5] | なし |
 | 5 | 1 | [1..5] | なし |

 最初のクエリではすべてが支払われますが、すべてのノードがすでに学習されているため、後続のすべてのクエリでは何も支払われません。 これは、不可逆的なカバレッジ不変条件を示しています。つまり、ノードが一度カウントされると、そのノードはグローバルに削除されます。 

ツリーがコスト [5,1,3,2] のチェーン 1-2-3-4 であり、クエリが ki = 0 で 2 と 3 の間で交互に行われる 2 番目の例は、独立したアクティブ化を示しています。 各クエリはメモリをリセットするため、各サブツリーは個別に支払われ、モデルがメモリ ゼロのウィンドウを正しく処理することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | オイラー ツアーとクエリごとのセグメント ツリーの更新 |
 | スペース | O(n) | 隣接リスト、オイラー配列、セグメント ツリー |

 この制約により、およそ数百万のログ操作が許可されます。これは、反復 DFS と最小限のオーバーヘッドで慎重に実装された場合に限り、Python の 4 秒の制限内に快適に収まります。

 ## 特殊なケース

 ki がゼロの場合、各クエリは独立して動作する必要があります。 セグメント ツリーは引き続きノードをグローバルに削除しますが、再利用は不可能であるため、サブツリーのアクティブ化ごとに新しいコストが正しく計算されます。 

ツリーがルート 1 のスターである場合、すべてのサブツリーはルートまたは単一のリーフのいずれかになります。 ルートのオイラー間隔はすべてをカバーするため、最初のクエリはすべてのノードを消費できますが、グローバル消費状態がすでに完全なカバレッジを反映しているため、後のクエリでは正しくゼロが生成されます。 

ki が非常に大きい場合、過去の多くのクエリの間隔が重なり合います。 この実装はウィンドウの明示的な維持には依存せず、ノードがすでに消費されているかどうかのみに依存するため、メモリ ウィンドウが長くてもパフォーマンスや正確性が低下することはありません。
