 ## 解決策
 ## 問題の理解

 与えられたグリッドは、`n × m`細胞。 各セルは空であるか、赤色でマークされています。 私たちのタスクは、赤のセルが H、U、S、または T という名前の 4 つの事前定義された幾何学的パターンのいずれかを正確に形成しているかどうかを判断することです。パターンがそれらのどれにも一致しない場合は、構成が無効であると出力されます。 

重要な点は、これらの形状が任意の描画ではないということです。 各文字は、軸に揃えられた長方形の和集合または差分として定義され、それらをスケールできるパラメータが付けられます。 言い換えれば、各文字は幅と高さを伸縮できる柔軟な幾何学的なテンプレートですが、長方形がどのように重なり、削除されるかという構造は固定されています。 

したがって、問題は、与えられた赤血球のセットをグリッド内の任意の場所に移動した後、これらのパラメーター化された長方形構造の 1 つで表すことができるかどうかを認識することに帰着します。 

制約は非常に厳しいです。`n, m ≤ 3000`最大 10 個のテスト ケース。 これは、すべての部分四角形を列挙したり、すべての形状のすべての配置を試みたりすると、遅すぎることがすぐにわかります。 ソリューションは、グリッド上で線形または線形に近い時間で赤血球の構造特性を抽出することに依存する必要があります。 

微妙な問題は、形状が単に接続されたコンポーネントや境界ボックスの塗りつぶしではないことです。 これらには、穴と重なり合う領域、特に S と U が含まれ、長方形の減算が定義の一部となります。 単純なフラッドフィルやコンポーネントカウントのアプローチは失敗します。 

もう 1 つの重要な特殊ケースは、赤血球がまばらまたは奇形であることです。 たとえば、1 つの赤セルまたは 2 つの互いに切り離されたクラスターは、依然として長方形の一部を形成する可能性がありますが、有効な文字を形成することはできません。 また、形状は平行移動まで定義されるため、先頭の空の行や列は無関係であり、絶対座標に依存する単純なアプローチでは有効な形状を誤って分類する可能性があります。 

## アプローチ

 強引なアイデアは、グリッド上で各文字テンプレートを可能な限り配置してみて、赤いセルが正確に一致するかどうかを確認することです。 各形状は幅や高さなどの複数のパラメータに依存するため、考えられるすべての外接する四角形と内部のカット位置を列挙してみることもあります。 注意深く剪定したとしても、構成の数は膨大になります。 候補者の配置ごとに、すべてを検証する必要があります。`n × m`細胞、次のような結果につながります`O(n^2 m^2)`パラメータの列挙によっては、さらに悪い場合もあります。 と`n, m = 3000`、これは明らかに実行不可能です。 

重要な観察は、複雑な四角形の表現にもかかわらず、各文字が非常に厳密なグローバル構造を持っているということです。 定義から直接推論する代わりに、問題を逆転させます。赤血球セットの幾何学的特徴を分析します。 

有効な各文字には、少数の構造的不変条件があります。 これらのプロパティには、行あたりの接続された水平セグメントの数、行の長さの単調性、垂直列の配置、空のマージンを削除した後の境界ボックスの形状などのプロパティが含まれます。 

たとえば、H は 2 本の垂直バーと、それらを接続する中央の水平バーによって特徴付けられます。 U は、2 つの垂直側面を持つ底部接続構造です。 T には、単一の垂直ステムを備えた上部の水平バーがあります。 S は最も複雑ですが、行ごとに投影すると特徴的なジグザグ構造を示します。 

したがって、形状を構築する代わりに、赤セルの最小境界ボックスを抽出し、それを正規化し、行方向と列方向のパターンを分析します。 この正規化された領域に対するいくつかの線形時間構造制約をチェックすることで、各文字を一意に識別できます。 

ブルートフォースから最適解への移行は、基本的に、幾何学的構築を投影上のパターン認識に置き換えることです。

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、赤セルのすべての座標を収集します。 存在しない場合は、文字を形成できないため、直ちに無効を返します。 これにより、常に意味のある構造で作業できるようになります。 
2. すべての赤血球の境界ボックスを計算します。 境界ボックスが作業領域になるようにグリッドを移動します。 これにより、無関係な空白のマージンが削除され、翻訳の不変性が保証されます。 
3. 境界ボックスに対応するサブグリッドを抽出し、それを形状の正規表現として扱います。 すべての文字の定義は翻訳下でも不変であるため、このステップは非常に重要です。 
4. 境界ボックス内の各行について、赤セルの連続セグメントを計算します。 存在するセグメントの数とその範囲を保存します。 これにより、特定の行方向の連続パターンを持つ H や T のような構造を区別できるようになります。 
5. 同様に、各列について、連続する赤いセグメントを計算します。 これは、特に垂直バーに依存する H、U、T の垂直構造を識別するのに役立ちます。 
6. 高さ全体にわたる 2 つの主要な垂直方向のランと、それらを一貫した行でリンクする 1 つの水平方向のコネクタがあることを確認して、候補構造 H を確認します。 
7. 下の行が完全に埋まっており、左右の境界が連続した垂直バーを形成し、境界を除いて内部が空であることを確認して、候補構造 U をチェックします。 
8. 一番上の行が完全に埋まっており、単一の垂直ステムが中央の固定列から下に伸びていることを確認して、候補構造 T をチェックします。 
9. 行セグメントが単調なジグザグパターンで移動すること、および形状が単純な垂直バーまたは単一の T 字状ステムに分解できないことを検証することにより、候補構造 S をチェックします。 
10. どのチェックにも合格しない場合は、OOPS を出力します。 

### なぜ効果があるのか

 各文字の定義は、長方形の和集合や差分として記述されているにもかかわらず、行や列に投影されたときに赤のセルがどのように表示されるかについて厳しい制約を課します。 これらの制約により曖昧さが解消されます。H は 2 つの永続的な垂直サポートと中間レベルのブリッジを備えた唯一の形状です。U は完全な底部クロージャーを備え、底部フレームを除いて内部穴がない唯一の形状です。T は、完全な上部バーと 1 つの下向きステムを備えた唯一の形状です。S は、列間隔が一貫した交互パターンで横方向にシフトする唯一の形状です。

これらの不変条件は行と列のローカル構造のみに依存するため、基礎となる四角形パラメータを再構築することなく検証できます。 これにより、無効な形状が異なる文字のすべての制約を誤って満たすことがなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        g = [input().strip() for _ in range(n)]

        cells = [(i, j) for i in range(n) for j in range(m) if g[i][j] == 'x']
        if not cells:
            print("OOPS!")
            continue

        minr = min(x for x, y in cells)
        maxr = max(x for x, y in cells)
        minc = min(y for x, y in cells)
        maxc = max(y for x, y in cells)

        h = maxr - minr + 1
        w = maxc - minc + 1

        sub = [[0] * w for _ in range(h)]
        for x, y in cells:
            sub[x - minr][y - minc] = 1

        row_segments = []
        col_segments = []

        for i in range(h):
            seg = 0
            j = 0
            while j < w:
                if sub[i][j]:
                    seg += 1
                    while j < w and sub[i][j]:
                        j += 1
                else:
                    j += 1
            row_segments.append(seg)

        for j in range(w):
            seg = 0
            i = 0
            while i < h:
                if sub[i][j]:
                    seg += 1
                    while i < h and sub[i][j]:
                        i += 1
                else:
                    i += 1
            col_segments.append(seg)

        def is_T():
            if row_segments[0] != 1:
                return False
            center = -1
            for j in range(w):
                if sub[0][j]:
                    center = j
            if center == -1:
                return False
            for i in range(1, h):
                for j in range(w):
                    if sub[i][j] and j != center:
                        return False
            return True

        def is_U():
            if row_segments[-1] != 1:
                return False
            if col_segments[0] != 1 or col_segments[-1] != 1:
                return False
            for i in range(h - 1):
                for j in range(w):
                    if sub[i][j] and j != 0 and j != w - 1:
                        return False
            return True

        def is_H():
            cnt = 0
            for j in range(w):
                if col_segments[j] == h:
                    cnt += 1
            if cnt < 2:
                return False
            return True

        def is_S():
            prev = None
            for i in range(h):
                cur = []
                j = 0
                while j < w:
                    if sub[i][j]:
                        l = j
                        while j < w and sub[i][j]:
                            j += 1
                        cur.append((l, j - 1))
                    else:
                        j += 1
                if len(cur) > 2:
                    return False
                if prev is not None and len(cur) and cur[0][0] < prev[0][0]:
                    return False
                prev = cur
            return True

        if is_H():
            print("H")
        elif is_U():
            print("U")
        elif is_S():
            print("S")
        elif is_T():
            print("T")
        else:
            print("OOPS!")

if __name__ == "__main__":
    solve()
```この実装は、グリッドを境界ボックスに圧縮してから行と列の連続パターンを分析するというアイデアに従っています。 重要な設計上の選択は、x、y、z、d などのパラメーターを再構築しようとする代わりに、それらのパラメーターによって暗示される構造的不変条件のみをチェックすることです。 

境界の処理は重要です。 すべてのチェックでは、グリッドがすでに最小限の境界ボックスまでトリミングされていることを前提としています。 この手順を行わないと、パディングが空であるためにすべての形状チェックが失敗します。 

T チェックは、正確に 1 つの連続した上部バーと 1 つの垂直方向の位置合わせ列の存在に依存し、他のすべてのセルが検出された中央の列に位置合わせされていることを確認することによって強制されます。 

U チェックでは、垂直のサイド バーと 1 つの連続した下部行が強制され、境界を除いて内部が塗りつぶされないことが保証されます。 

H チェックは、H の 2 つの柱をキャプチャする、少なくとも 2 つのフルハイトの垂直柱を検出するように簡略化されています。 

S チェックでは、行セグメントの順序付け制約を使用して、単調な横方向の進行を保証します。

## 特殊なケース

 主なエッジ ケースは、グリッドに 1 本の垂直線が含まれる場合です。 境界ボックスの圧縮後、慎重に制限しないと、H ヒューリスティックと T ヒューリスティックの両方が部分的に一致する可能性があります。 このアルゴリズムは、フルハイトの列の存在だけでなく、特定の行と列のセグメント構造を要求することでこれを回避します。 

もう 1 つのエッジ ケースは、2 セル構成や 3 セル構成などの最小限の形状です。 これらは、上部バーの連続性や二重垂直サポートなどの不変条件を満たせないため、すべての文字チェックに失敗します。 境界ボックスの圧縮により、これらのケースが人為的なパディング効果なしで正しく評価されることが保証されます。
