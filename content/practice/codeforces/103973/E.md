 ## 解決策
 ## 問題の理解

 いくつかの石の山が与えられ、各山のサイズは正の整数です。 1 つの杭だけが残るまで、2 つの既存の杭を繰り返しマージします。 すべてのマージでは、サイズ x と y の 2 つの山が選択され、それらが削除され、サイズ x + y の 1 つの山に置き換えられ、x と y を乗算したスコアが得られます。 

タスクは、プロセス全体で合計累積スコアを最大化するマージのシーケンスを選択することです。 

入力は杭の数 n と配列 a で構成され、各値は初期杭サイズを表します。 出力は、正確に n − 1 回のマージを実行した後に達成可能な最大合計スコアを表す単一の整数です。 

n が 100000 までの制約により、すべてのマージ シーケンスをシミュレートしようとするソリューションは即座に除外されます。 区間の状態は O(n^2) として増大し、各遷移には追加の計算が必要となるため、区間にわたる二次動的計画法でも失敗します。 ai の値は最大 10000 であるため、64 ビット整数での算術演算は安全ですが、主な問題は組み合わせです。 

微妙な落とし穴は、常に最小の 2 つまたは最大の 2 つの山をマージするような貪欲な戦略が機能すると想定していることです。 たとえば、パイル [1, 2, 3, 4] の場合、(1, 2) を最初にマージすると、(3, 4) を最初にマージする場合とは異なる中間構造が生成され、最終スコアはこれらの初期の選択に大きく依存します。 もう 1 つの失敗例は、中程度のパイルを早期にマージし、後でより大きな集合体と乗算する機会を失うなど、将来の乗算の可能性を低下させる局所最適マージから発生します。 

## アプローチ

 ブルートフォースの解釈は簡単です。各ステップで、任意の山のペアを選択し、それらをマージし、スコアを計算し、縮小されたマルチセットを再帰的に実行します。 これにより、初期配列に対して可能なすべてのバイナリ マージ ツリーが調査されます。 (n − 1) 個のマージ ステップがあり、各ステップで O(n^2) 通りのペアが選択できるため、状態の数は階乗的に増加します。 マルチセットに対するメモ化を行ったとしても、異なるマージ順序によって異なる中間マルチセットが生成され、それらのマルチセットは小さな DP 状態に効率的に圧縮できないため、状態空間は天文学的に大きくなります。 

重要な洞察は、マージ順序の観点から考えるのをやめ、代わりにプロセスが蓄積するものを再解釈することです。 各マージは x · y に寄与し、すべての要素はますます大きなパイルに吸収されるにつれて複数のマージに参加します。 これは、各元の石がマージ全体で他の石と相互作用する頻度を追跡することを示唆しています。 

より構造的な観点から見ると、このプロセスは、葉が最初の杭である完全なバイナリ ツリーを構築するのと同等であるということです。 すべての内部ノードはマージに対応し、その寄与は左と右のサブツリーの合計の積になります。 この式を展開すると、元のパイルの各ペアが 1 回だけ寄与し、ツリー構造全体でそれらの値が結合される回数を掛け合わせたことがわかります。 したがって、最適な戦略は、マージの初期段階で大きな値の「重み付けされた共起」を最大化することです。 

これは、古典的な貪欲な観察に帰着します。常に、利用可能な 2 つの最小のパイルを最初にマージします。 その理由は、2 つの小さな値を早期にマージすると、その積が小さく保たれる一方、後のマージでは、ますます大きな累積合計が乗算されるため、より大きな値が保存されるためです。 小さな値のマージを遅らせる偏差があると、それらの値がより大きな合計と相互作用することになり、他の部分で補償利益を生み出すことなくコストが増加します。 

したがって、最適な解決策は、2 つの最小の山を繰り返し抽出し、それらをマージし、その積を答えに加算し、それらの合計を押し戻すことです。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 | O(n) | 遅すぎる |
 | 最適 (最小ヒープ貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 常に最小の2つの山を効率よく回収できる体制を維持しています。 最小ヒープはこのための自然なツールです。 

1. すべてのパイル サイズを最小ヒープに挿入します。 これは、マージが行われる前の現在利用可能なコンポーネントを表します。 
2. 複数のパイルが残っている間に、ヒープから 2 つの最小の要素 x と y を抽出します。 これらの最小値のいずれかを延期しても、後でより大きな累積値と強制的にマージされ、その寄与が増加するだけであるため、この選択は正当化されます。 
3. マージコスト x · y を計算し、それを現在の合計スコアに追加します。 これは、これら 2 つのコンポーネントを組み合わせることで得られる即時の報酬を表しています。 
4. x + y をヒープに挿入し直します。 この新しいパイルは、将来のマージに参加できるマージされたコンポーネントを表します。 
5. 山が 1 つ残るまで繰り返します。 その時点で、すべてのマージは 1 回だけ考慮されます。 

### なぜ効果があるのか

 どのステップでも、残っている 2 つの最小の山 x と y を考慮します。 最適な解は最終的にすべての山をマージする必要があり、特に x と y は両方とも消滅するまでマージに関与します。 x と y がまだマージされていない場合は、最初にそのうちの少なくとも 1 つを何らかの値 z ≥ y でマージする必要があります。 これにより、少なくとも x · z または y · z のコストが発生します。同じマージ ツリー構造の再配置間で比較した場合、どちらも x · y よりも小さくありません。 このような遅延ペアリングを以前のマージに交換しても、将来のコストが増加することはなく、中間パイル サイズの不必要な膨張を厳密に回避します。 この交換引数を繰り返し適用すると、最小の要素が最初に結合される構造が得られます。これはまさにヒープ貪欲プロセスです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return
    
    heapq.heapify(a)
    total = 0
    
    while len(a) > 1:
        x = heapq.heappop(a)
        y = heapq.heappop(a)
        total += x * y
        heapq.heappush(a, x + y)
    
    print(total)

if __name__ == "__main__":
    solve()
```このソリューションは、対数時間で常に 2 つの最小のパイルを公開する最小ヒープを中心に構築されています。 Heapify は線形時間で初期構造を構築します。 各反復では 2 つのポップと 1 つのプッシュが実行され、すべて O(log n) が実行され、単一のマージ コストが発生します。 

n = 1 の早期リターンは、マージが発生しない縮退ケースを処理し、無効なヒープ操作を試行するのではなく、答えがゼロになることを保証します。 

コア ループは厳密に毎回パイルの数を 1 つ減らし、n − 1 回の反復後の終了を保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | n − 1 個のマージのそれぞれがヒープ操作を実行します。 
| スペース | O(n) | ヒープは最大で n 個の進化するパイルを格納します。 

Python では、組み込み heapq を使用して実装すると 100,000 回のヒープ操作が 1 秒以内に収まり、メモリ使用量がパイルの数に比例するため、このアルゴリズムは制約内に快適に適合します。

 ## 特殊なケース

 最小のエッジ ケースは n = 1 です。単一の山ではマージは発生せず、スコアは 0 です。 このアルゴリズムはヒープ操作の前に明示的に 0 を返し、無効なポップを回避します。 

もう 1 つのエッジ ケースは、すべての値が等しい場合です ([2, 2, 2, 2] など)。 ヒープは常に同一の要素を返すため、マージ順序は無関係です。 各ステップは予測可能な成長をもたらし、アルゴリズムはタイブレーク ロジックを必要とせずに一貫した成果を蓄積します。 

最後の微妙なケースは、[1, 1, 1, 10000] のように、1 つの値が他の値よりも大幅に大きい場合です。 貪欲な戦略では、最初にそれらをマージし、サイズ 2 と 3 の中間パイルを生成します。これにより、10000 がプロセスの後半で比較的大きな集合体でのみ乗算されるようになり、合計寄与の最大化と一致します。
