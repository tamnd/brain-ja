 ## 解決策
 ## 問題の理解

 プレイヤーが固定された順序でモンスターと次々と戦う連続戦闘ゲームをシミュレートしています。 各モンスターには固定の攻撃閾値があり、プレイヤーは現在の攻撃能力を表す単一の整数状態を維持します。 

プレイヤーの能力は最初はゼロです。 モンスター i と対峙する場合、一度の戦闘の勝敗は現在の能力 m とモンスターの強さ ai の比較によって決まります。 能力がモンスターと完全に一致した場合、モンスターはすぐに倒されます。 能力が大きい場合はモンスターを倒すことはできますが、プレイヤーの能力が1つ減少する可能性があります。 能力が小さい場合、モンスターは生き残り、プレイヤーの能力は一定の確率で1つ増加し、その後同じモンスターと再度戦う必要があります。 プレイヤーは現在のモンスターが倒されるまで次のモンスターに進むことができないため、各モンスターは自己完結型の確率プロセスを定義しますが、状態は引き継がれます。 

このタスクは、すべてのモンスターを倒すのに必要な予想合計戦闘数を計算することです。 答えは有理数なので、998244353 を法として出力する必要があります。 

制約は、n が最大 1000、各 ai が最大 1000 であることを示していますが、確率は 0.01 の小さな有理数倍として与えられます。 これは、すべてのモンスターにわたる可能な能力値の状態空間が大きく、遷移が確率的であるため、ランダム性をめぐるシミュレーションや確率的プロセスのパスの列挙を即座に排除します。 どのソリューションでも、代わりに期待値を分析的に計算し、モンスター全体で構造を再利用する必要があります。 

微妙な難点は、単一のモンスターとの戦闘を繰り返すと能力が変化し、それが将来のすべてのモンスターに影響を与えることです。 モンスターを独立して扱うような素朴な解釈は失敗します。 

重要なエッジケースの 1 つは、ai が大きく、プレイヤーの能力がそれを下回ることが多い場合です。 たとえば、m = 0、a1 = 100 から開始すると、失敗を繰り返す戦闘が多くなり、確率の増加が繰り返されるため、予想される戦闘回数は多くなります。 もう 1 つのエッジ ケースは、確率が xi = 100 などの極端な場合であり、負けたときに行動が決定的な上向きドリフトになります。 

## アプローチ

 ブルートフォースアプローチでは、（現在のモンスターインデックス、現在の能力）によって定義される状態にわたるマルコフ連鎖としてプロセスをシミュレートします。 各状態から確率に基づいて分岐し、予想されるステップを再帰的に蓄積します。 これはシステムを正しくモデル化していますが、状態の数は m の可能な範囲の少なくとも n 倍であり、m 自体は実際には最大約 2000 まで変動する可能性があります。 さらに悪いことに、モンスターが失敗すると同じインデックスが維持されますが、m が確率的に変化するため、遷移はサイクルを形成します。これは、単純な再帰がメモ化されない限り無限に状態を再訪することを意味します。 

すべての (i, m) に対して動的計画法を試みると、各状態からの予想されるステップを定義できますが、固定 i の遷移は m と ai の両方に依存し、また (i, m) を (i, m+1) または (i, m-1) または (i+1, m) に接続して、密な線形方程式系を形成します。 これをグローバルに解決することは可能ですが、約 10^6 の状態を処理する必要があり、これは境界線にあり不必要です。 

重要な単純化は、各モンスターのプロセスが m の現在の値にのみ依存し、単一のモンスターとの戦闘中の進化が将来のモンスターから独立していることを観察することです。 これにより、すべての可能な開始 m について、モンスター i を倒すのに必要な予想される戦闘回数と、敗北後の結果として得られる最終 m の分布という 2 つの量を計算することができます。 ただし、ディストリビューションを直接維持するのは依然として重いです。

重要な観察は、各モンスターのプロセスが単一の吸収成功条件を備えた 1 次元のランダム ウォークであり、m の予想時間と遷移は、m の制限された間隔にわたる線形方程式を使用して計算できることです。 最適な状態では m が max(ai) を 1 以上超える必要はないため、状態空間を圧縮して、O(A) または O(A^2) でモンスターごとの DP を解くことができます。ここで、A は max ai です。 

各モンスターについて、能力 m から開始して、それを倒すまでの予想される残りの戦いを表す期待値系 E[m] を計算します。 各状態は、m、m+1、m-1、および固定閾値 ai のみに依存する一次方程式を満たします。 これらの方程式をモンスターごとに繰り返し解くと、効率的に答えが得られます。

 ## アルゴリズムのチュートリアル

 取り得る各能力状態mからの予想残り戦闘数を維持しながら、順番にモンスターを処理していきます。 E[m] を現在の能力 m から開始して、現在のインデックス以降のすべてのモンスターを終了するまでに必要な予想される戦闘数を表すものとします。 

1. DP 配列 E を初期化します。ここで、E[m] は、能力 m のモンスター 1 から開始して必要な予想される戦闘数です。 最初は m = 0 なので、必要なのは E[0] だけですが、関連するすべての m の値を計算します。 
2. 1 から n までの各モンスター i について、現在の E に基づいて新しい DP 配列 nextE を計算します。そのアイデアは、モンスター i を倒す効果をトランジションに「組み込む」ということです。 
3. 固定能力 m について、モンスター i を仕上げるのにかかる予想コストを分析します。 m が ai と等しい場合、モンスターは 1 回の戦闘で敗北し、次の DP 状態に直接移行します。 したがって、nextE[m] は、遷移後に評価される 1 に E[m] を加えたものと等しくなります。 
4. m が ai より大きい場合、1 回の戦闘で必ずモンスターを倒しますが、確率で pi の能力が 1 減少します。 これにより、nextE[m] が nextE[m] 自体と nextE[m−1] に依存するという繰り返しが発生します。これは、敗北後、おそらく能力が低下した次のモンスターに進むためです。 
5. m が ai 未満の場合、モンスターを倒さないので、同じモンスター状態に留まり、1 戦闘コストを支払います。 確率 pi の場合、能力は 1 増加しますが、それ以外の場合は変化しません。 これにより、確率的な上方ドリフトを伴う自己ループが作成され、期待値は nextE[m] と nextE[m+1] を含む線形方程式を満たします。 
6. これらの線形方程式を m の昇順で解き、必要なときに依存関係がすでに計算されるようにします。 この順序付けは、遷移が隣接する m の値の間でのみ移動するため機能します。 
7. モンスター i のすべての m を処理した後、E を nextE に置き換え、次のモンスターに進みます。 
8. 最終的な答えは E[0] で、最初のモンスターの前に能力 0 から始まる戦闘の予想回数です。 

### なぜ効果があるのか

 核となる不変条件は、モンスター i を処理した後、DP 配列 E[m] が、能力 m から開始してモンスター i から n を終了するのに必要な予想される残りの戦闘回数を正しく表すことです。 各モンスターは、戦闘ごとに m を最大 1 つだけ変更するローカル確率プロセスに寄与します。そのため、各 m の期待値は隣接する州にのみ依存し、現在の DP レイヤーを超えるグローバル ヒストリーを必要としません。 これにより、システムは、正確さを失うことなく段階的に解くことができる一連の局所線形方程式に還元可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n = int(input())
    monsters = []
    max_a = 0
    for _ in range(n):
        a, x = map(int, input().split())
        p = x * modinv(100) % MOD
        monsters.append((a, p))
        max_a = max(max_a, a)

    # DP over ability values up to max_a + 2
    LIM = max_a + 5
    dp = [0] * (LIM + 1)

    for a, p in monsters:
        ndp = [0] * (LIM + 1)

        for m in range(LIM, -1, -1):
            if m == a:
                ndp[m] = (1 + dp[m]) % MOD

            elif m > a:
                # always kill, possibly drop m-1
                ndp[m] = (1 + (p * ndp[m - 1] + (1 - p) * dp[m]) % MOD) % MOD

            else:
                # must retry until success
                # expected geometric-like structure
                ndp[m] = (modinv(p) + ndp[m + 1]) % MOD if p != 0 else (1 + ndp[m]) % MOD

        dp = ndp

    print(dp[0] % MOD)

if __name__ == "__main__":
    main()
```DP 配列は、現在の能力値によってパラメータ化された、モンスターの各プレフィックスを終了した後の予想される残りの戦闘数を表します。 遷移ロジックは、3 つのレジームを期待値の反復に直接エンコードしようとします。 実装の主な困難は、m < ai の場合の「成功するまで再試行」動作を処理することです。これは、各失敗が独立して確率 1 - p で同じ状態を繰り返し、確率 p で進むため、幾何学的期待構造に崩壊します。 

上位 m から下向きの反復は、ndp を計算するときに、m − 1 や m + 1 などの依存関係が同じ層ですでに解決されていることを確認するために使用されます。

 ## 特殊なケース

 重要なエッジケースは、プレーヤーがモンスターの強さをはるかに下回る値 (m = 0 や a = 100 など) で開始したときに発生します。この状況では、アルゴリズムは「成功するまで再試行」ルールを繰り返し適用します。これは、DP 遷移の制限された数ではなく、幾何学的期待に対応します。 反復は、1/p に比例する閉形式の期待値に崩壊します。DP は、発散することなく繰り返される自己ループを正しく考慮する必要があります。 

もう 1 つのエッジ ケースは、確率が 1 (xi = 100) の場合です。 その後、失敗した試行ごとに m が決定論的に増加し、プロセスが事実上決定論的なウォークになります。 DP はこれを処理します。これは、失敗した分岐が消えて上向きの遷移だけが残るためであり、モンスターごとに最大でも制限された回数の増加後に終了することが保証されます。 

最後のエッジケースは、モンスターの複数の段階で m が ai と正確に等しい場合です。 DP は、等号が確率的分岐を行わずに常に単一ステップの遷移をトリガーするため、一貫性を保証します。そのため、等しいしきい値が繰り返されても予期しないドリフトが蓄積されません。
