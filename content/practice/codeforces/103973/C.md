 ## 解決策
 ## 問題の理解

 半径を持つ 2 つの円が与えられます$a$そして$b$。 1 つの円は所定の位置に固定され、もう 1 つの円は外側からそれに接するように配置されます。 次に、2 番目の円は最初の円の周りを回転し、常に接線を維持し、固定円の周りを 1 周した後、最終的に開始位置に戻ります。 

この動きが起こる間、回転する円もそれ自身の中心の周りを回転します。 課題は、固定円の周りを 1 回転する間に移動円が何回転するかを決定することです。 答えは必ずしも整数であるとは限らないため、小数で指定する必要があります。 

入力は多くの独立したテスト ケースで構成され、各テスト ケースは単なる半径のペアにすぎません。 以来$T$と同じ大きさにすることができます$10^5$、各テスト ケースは一定時間で処理される必要があります。 半径自体は最大で$10^{18}$これにより、モーションのシミュレーションやパスに沿った反復的なステップを伴うアプローチは即座に除外されます。 

素朴な解釈では、パスに沿って少しずつ回転角度を追跡し、回転運動をシミュレートすることを提案するかもしれません。 これは、パスが連続的であることと、移動の規模が$10^{18}$半径スケールで離散化された場合のステップ。 

両方の半径が等しい場合、微妙なエッジケースが発生します。 例えば、$a = b = 1$。 素朴な直感では、円はちょうど 1 回回転すると思われるかもしれませんが、幾何学的な推論では、実際には 2 回完全に回転することがわかります。 これは、ローカルな回転速度よりもさらにグローバルな何かが関係していることをすでに示唆しています。 

## アプローチ

 この問題を考える強引な方法は、小さな円が大きな円の円周に沿って移動し、その回転を継続的に更新すると想像することです。 外側のパスに沿って微小に移動するたびに、回転する円は、移動する円弧の長さをそれ自体の半径で割った値に比例して回転します。 これには、全長にわたって回転を統合する必要があります。$2\pi(a + b)$、移動する円の中心は半径の円を描くため、$a + b$。 

この推論は原理的には正しいですが、制約の下ではそれを直接シミュレートしたり離散化したりすることは不可能です。 主な非効率性は、連続パス全体を処理する必要があり、無制限の数の小さな更新を効果的に実行する必要があることです。 

重要な洞察は、モーションが 2 つの寄与にきれいに分解されるということです。 まず、移動する円の中心が半径の円に沿って移動します。$a + b$のローテーションに貢献$\frac{a + b}{b}$。 第 2 に、円が直線ではなく別の曲面の周りを回転するという事実によって引き起こされる追加の効果があり、これにより中心パスの 1 回転ごとに余分な 1 回転が発生します。 これは古典的な「閉じた曲線上で滑らずに転がる」現象であり、曲率が追加の影響を与えます。$1$フルターン。 

これらの効果を組み合わせると、合計で次の回転が得られます。$$\frac{a + b}{b} + 1 = \frac{a + b + b}{b} = \frac{a + 2b}{b}$$ただし、これはまだサンプルの動作と一致していないため、より注意深く幾何学的に分解すると、正しい不変式が対称であることがわかります。$a$そして$b$。 寄与を非対称に分離するのではなく、各円が効果的なローリング ジオメトリに等しく寄与していることが観察されます。 

正しい最終的な式は次のように単純化されます。$$\frac{a + b}{\gcd(a, b)} \Big/ \frac{b}{\gcd(a, b)} = \frac{a + b}{b} \text{ reduced properly via gcd}$$より安定して導出する方法は、1 回転中に接触点が描く円弧の長さが次の値に相当することに注意することです。$2\pi(a + b)$、移動する円の各 1 回転が円弧の長さに対応します。$2\pi b$。 したがって、生の回転数は次のようになります。$$\frac{a + b}{b}$$ただし、パスが閉じているため、分数で表現する場合、実際のカウントは最低項まで減らされる必要があります。そのため、出力は縮小された形式で必要になります。 

したがって、タスク全体は、分数を計算し、分子と分母の gcd を使用して単純化することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$a$そして$b$テストケースごとに。 これらは固定円と回転円の形状を定義し、動きを完全に決定します。 
2. 生の回転数を次のように計算します。$a + b$。 これは、1 回の完全な横断にわたる回転運動に対する両方の円の有効合計寄与度を表します。 
3. 分母を次のように設定します。$b$回転する円の各全回転は、その半径に比例した円弧の長さに対応するためです。 
4. コンピューティング$g = \gcd(a + b, b)$。 このステップでは、分子と分母の間で共有されているスケーリング係数を削除することで、分数が既約形式で表現されるようにします。 
5. 出力$\frac{a + b}{g} / \frac{b}{g}$。 これは回転数を表す小数部分です。 

最後に縮小する背後にある重要な考え方は、長さの幾何学的比率が回転を決定し、絶対的な単位ではなく相対的なスケーリングのみが重要であるということです。 

### なぜ効果があるのか

 回転運動は円弧の長さの比率のみに依存します。 完全に 1 回転すると、移動する円の中心は閉曲線を描き、その長さは次のようになります。$a + b$。 回転円は、移動した円弧の長さを独自の円周スケールで割ることによって回転に変換します。これは次のように比例します。$b$。 これら 2 つの量の間の公約数は、最終的なカウントに影響を与えないモーション内の繰り返し構造に対応します。これは、まさに gcd 除去でキャプチャされるものです。 これにより、結果として得られる分数が最小かつ正確であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        num = a + b
        den = b
        g = gcd(num, den)
        num //= g
        den //= g
        print(f"{num}/{den}")

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に読み取り、換算分数を直接計算します。 唯一の重要な演算は gcd であり、これにより分数が最小になることが保証されます。 整数の除算は、加算した場合でもすべての値が 64 ビットの範囲内に収まるため安全です。 

よくある間違いは、分数の切り捨てを忘れることです。これにより、数値が正しい場合でも、誤った書式設定が行われます。

## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        num = a + b
        den = b
        g = gcd(num, den)
        out.append(f"{num//g}/{den//g}")
    return "\n".join(out)

# provided samples
assert run("2\n1 1\n4 6") == "2/1\n5/3"

# minimum size
assert run("1\n1 1") == "2/1"

# co-prime case
assert run("1\n2 3") == "5/3"

# equal large values
assert run("1\n1000000000000000000 1000000000000000000") == "2/1"

# boundary asymmetry
assert run("1\n1 1000000000000000000") == "1000000000000000001/1000000000000000000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | 2/1 | 同一半径の倍増効果 |
 | 2 3 | 5/3 | 自明ではない削減 |
 | 1 10^18 | (10^18+1)/10^18 | 極端な不均衡 |
 | 10^18 10^18 | 2/1 | 大きな等しい値の安定性 |

 ## 特殊なケース

 のために$a = b$、アルゴリズムは分子を生成します$2a$と分母$a$、これは次のようになります。$2/1$。 ここで gcd ステップが不可欠なのは、リダクションがないと出力が誤って残るためです。$2a/a$、必須の形式ではありません。 

次のような非常に大きな値の場合、$a = 10^{18}, b = 1$、分子は次のようになります。$10^{18} + 1$。 これは共素なので、$1$、gcd は$1$、分数は変化しません。 Python の整数は自然に任意の精度をサポートしているため、このアルゴリズムはオーバーフローの問題を発生させることなくこれを処理します。 

いつ$a$そして$b$大きな gcd を共有する、など$a = 6, b = 4$、分子は$10$そして分母は$4$、そして gcd リダクションはそれを正しく単純化します。$5/2$。 これは、単純化ステップが表面的なものではなく、正確さを保つために構造的に必要であることを裏付けています。
