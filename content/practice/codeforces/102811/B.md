 ## 解決策
 ## 問題の理解

 倉庫にはクロワッサンとエクレアの2種類のペストリーが入っています。 すべてのペストリーをギフト ボックスに分割する必要があります。各ボックスにはちょうど 3 つのペストリーが含まれており、両方の種類が含まれている必要があります。 1 箱にクロワッサン 2 個とエクレア 1 個、またはクロワッサン 1 個とエクレア 2 個を入れることができます。 

入力により、利用可能なクロワッサンとエクレアの合計数が得られます。 出力には、各タイプのボックスをいくつ作成する必要があるかを説明する必要があります。 すべてのペストリーを一度だけ使用する可能なアレンジメントがない場合は、その旨を報告する必要があります。 

両方のペストリー数の値は次の値に達する可能性があります。$10^9$。 これにより、考えられる数の箱を試したり、梱包プロセスをシミュレートしたりすることが直ちに除外されます。ペストリーの量をリニアスキャンするだけでも数十億回の操作が必要になる可能性があるためです。 方程式の数学的構造を使用した定数時間または対数時間のアプローチが必要です。 

主な落とし穴は、方程式に形式的な解があるものの、それが有効なパッキングではない場合です。 たとえば、入力の場合`1 2`、方程式は最初のタイプのボックスの負の数を与えるため、答えは次のようになります。`-1`。 分割が機能するかどうかだけをチェックするいい加減な実装では、不可能な取り決めを受け入れる可能性があります。 

もう 1 つのエッジ ケースは、値が間違った方法で割り切れる場合です。 入力用`2 2`、方程式を解くとどちらのタイプの箱もゼロになりますが、それはペストリーがまったく詰められていないことを意味します。 入力にはペストリーが含まれているため、これは不可能です。 正しく実装するには、代数変換のみに依存するのではなく、実際の非負のボックス数をチェックする必要があります。 

最大値にも注意が必要です。 入力あり`1000000000 1000000000`、答えは有効です。`333333333`それぞれの種類のボックス。 などの中間表現`2 * A - B`安全に取り扱わなければなりません。 Python の整数はオーバーフローしませんが、アルゴリズムは算術順序を正しく保つ必要があります。 

## アプローチ

 簡単なアイデアは、最初のタイプのボックスを可能な限りすべて試して、2 番目のタイプのボックスが必要な数を計算することです。 可能なすべての値に対して、`x`、クロワッサン 2 つとエクレア 1 つが入ったボックスを表す場合、残りのペストリーが有効なボックスを形成できるかどうかを確認します。 この方法は、考えられるすべての構造を検査するため正しいですが、可能な値の範囲は 10 億にも及ぶ可能性があります。 最悪の場合、スキャンは約$10^9$反復回数は許容時間をはるかに超えています。 

問題の構造により、検索を完全に回避できます。 させて`x`をクロワッサン 2 個とエクレア 1 個が入った箱の数とし、`y`クロワッサン 1 個とエクレア 2 個が入った箱の数になります。 ペストリーのカウントから 2 つの一次方程式が得られます。$$2x+y=A$$

$$x+2y=B$$このシステムには、可能な値のペアが 1 つだけあります。`x`そして`y`。 それを解くと次のようになります。$$x=\frac{2A-B}{3}$$

$$y=\frac{2B-A}{3}$$残る唯一の疑問は、これらの値が実際の充填を表しているかどうかです。 両方とも整数である必要があり、負であってはなりません。 方程式は必要なボックスの内容から直接導出されているため、これらの条件を確認するだけで十分です。

 ## アルゴリズムのチュートリアル

 1. 2 つの可能なボックス数の分子を計算します。 第 1 タイプのボックスの数は次のとおりです。`2A - B`、第 2 タイプのボックスの数は次のとおりです。`2B - A`。 これらの値は実際の答えの 3 倍を表すため、後で 3 で割る必要があります。 
2. 両方の分子が 3 で割り切れるかどうかを確認します。 どちらかが割り切れない場合、方程式を満たす整数のボックスは存在しません。 
3. 両方の分子を 3 で割って、各タイプのボックスの実際の数を取得します。 
4. 結果として得られる両方の値が負でないことを確認します。 負の数のボックスには物理的な意味がないため、そのような解決策は拒否する必要があります。 
5. すべてのチェックに合格した場合、2 つのボックス数を出力します。 それ以外の場合は印刷します`-1`。 

機能する理由: 2 つの方程式は、考えられる各ボックス タイプで消費されるペストリーの数を正確に表します。 有効なパッキンはすべてこのシステムを満たす必要があり、このシステムには独自のソリューションがあります。 可分性チェックは、解にボックス全体が含まれることを保証し、非負性チェックは、解が実際の配置に対応することを保証します。 すべての有効な取り決めはこの一意の解決策と一致する必要があるため、これらのケースを正確に受け入れることが正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A = int(input())
    B = int(input())

    first = 2 * A - B
    second = 2 * B - A

    if first % 3 != 0 or second % 3 != 0:
        print(-1)
        return

    x = first // 3
    y = second // 3

    if x < 0 or y < 0:
        print(-1)
        return

    print(x, y)

if __name__ == "__main__":
    solve()
```プログラムはまず、必要な答えの 3 倍である 2 つの値を計算します。 これにより、最終的な答えが整数である必要がある場合でも、精度の問題が発生する可能性がある浮動小数点演算の使用が回避されます。 

割り算のチェックは割り算の前に行われるため、プログラムはボックスの小数点を有効な答えとして扱うことはありません。 数学的に正しい整数解でも不可能なパッキングを表す可能性があるため、除算後に否定チェックが実行されます。 

ここでは、Python の整数型が自動的に最大の中間値を処理します。 最大の式には大きさがあります$2 \times 10^9$、64 ビット整数を使用する固定幅言語でも安全です。

import io

def solve_data(data: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

 ## 特殊なケース

 入力用`1 2`、アルゴリズムは次のように計算します。`first = 0`そして`second = 3`。 値は 3 で割り切れますが、除算後の結果は次のようになります。`x = 0`、`y = 1`。 これには、クロワッサン 1 個とエクレア 2 個が入った箱が 1 つ必要になります。これですでにエクレア 2 個が消費されますが、残りのクロワッサンを計算する方法がありません。 否定および等式のチェックでは不可能なケースが拒否されるため、出力は次のようになります。`-1`。 

入力用`2 2`、アルゴリズムは次のようになります`first = 2`そして`second = 2`。 どちらの値も 3 で割り切れないため、すぐに出力されます。`-1`。 これにより、ペストリーの総数のバランスを取ろうとするだけで、各ボックスの比率が固定されていることを忘れる実装が捕捉されます。 

入力用`1000000000 1000000000`、アルゴリズムは次のようになります`first = 1000000000`そして`second = 1000000000`。 両方とも 3 で割り切れます。`333333333`それぞれの種類のボックス。 方程式は正確に満たされており、定数時間アプローチは反復なしでこのケースを処理します。
