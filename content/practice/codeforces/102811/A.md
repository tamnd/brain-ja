 ## 解決策
 ## 問題の理解

 通りには一定間隔でバス停が設置されています。 最初の停留所が位置 0 にある場合、後続の停留所はすべて正確に K メートル離れているため、それらの位置は K の倍数になります。Sveta はすでに通りの始まりから N メートルを歩いており、バス停に到達するために歩かなければならない最短距離を知りたいと考えています。 

入力には、ストップ間の間隔 K と、開始点 N からのスベタの現在の距離が含まれます。出力は、位置 N から K の倍数の位置までの最小距離です。 

K と N の値は、2 * 10^9 まで大きくすることができます。 これにより、道路をシミュレートしたり、すべての停留所を 1 つずつチェックしたりすることが直ちに排除されます。 最悪の場合、停止の可能性は数十億に及ぶ可能性があり、O(N) ソリューションであっても非常に多くの操作が必要になる可能性があります。 ソリューションでは、一定数の算術演算のみを使用する必要があります。 

主なエッジ ケースは、ちょうど停止位置、または間隔の開始点に非常に近い位置から発生します。 常に次の停留所に進むような不注意な解決策は、このような場合には失敗します。 

たとえば、次の入力を使用します。```
5
10
```ストップは 0、5、10、15 などの位置にあります。 Sveta はすでに停止しているため、正しい答えは 0 です。次の停止までの距離のみを計算するソリューションでは、誤って 5 が返されます。 

もう 1 つの境界ケースは、最寄りの停留所が次の停留所ではなく、前の停留所である場合です。 例えば：```
10
14
```最も近い停留所は 10 と 20 です。距離は 4 と 6 なので、答えは 4 です。常に上向きに四捨五入する解は 6 を返します。 

最後のケースは、Sveta が最初の非ゼロ ストップの前にある場合です。```
100
1
```最も近い停留所は 0 と 100 です。答えは 1 です。通りの始まりは有効なバス停として扱われなければなりません。 

## アプローチ

 簡単なアプローチは、すべてのバス停の位置を生成し、スヴェタからの距離を比較することです。 位置 0 から開始して、0、K、2K、3K をチェックし、距離が現在の最良の答えより大きくなるまで続けることができます。 

考えられるすべての宛先が検査されるため、このアプローチは正しいです。 ただし、指定された制限に対しては遅すぎます。 K が 1、N が 2 * 10^9 の場合、スヴェタの位置に到達するまでに 20 億回のストップがあります。 数十億回の反復を伴うループは制限時間内に終了できません。 

有用な観察は、スヴェタの位置が最も近い K の倍数にのみ依存するということです。彼女の直前のバス停は、距離 N を K で割って切り捨て、K を乗じた距離にあります。次の停留所は、そこからちょうど K メートル先です。 他のすべての停留所はより遠くにあるため、他の停留所を検査する必要はありません。 

問題は、K で割った余りを求めることです。N = q * K + r の場合、r は前の停留所までの距離、K - r は次の停留所までの距離です。 これら 2 つの値のうち小さい方のみが必要です。 r が 0 のとき、スヴェタはすでに停止しており、答えは 0 です。

 ## アルゴリズムのチュートリアル

 1. N を K で割った余りを計算します。すべての停止位置は K の倍数であるため、この余りはスベタの位置から前のバス停までの距離です。 
2. 余りがゼロの場合は、ゼロを出力します。 スヴェタはバス停に正確に立っているので、移動する必要はありません。 
3. それ以外の場合は、余りを K から余りを引いたものと比較します。 最初の値は前の停留所までの距離、2 番目の値は次の停留所までの距離です。 小さい方が必要な歩行距離です。 

2 つの距離だけがチェックされる理由は、連続するバス停がスヴェタの現在位置の周囲にあるためです。 他の停留所は、これら 2 つの停留所の 1 つよりもさらに遠くなります。 

機能する理由: すべてのバス停には K の倍数の位置があります。任意の位置 N について、整数除算により N が以前の K の倍数と残りのオフセットに分離されます。 前のストップはちょうど残りの距離にあり、次のストップはちょうどインターバルの未使用部分だけ離れています。 N に最も近い停留所はこれら 2 つだけであるため、距離が小さい方を選択すると常に正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K = int(input())
    N = int(input())

    remainder = N % K

    if remainder == 0:
        print(0)
    else:
        print(min(remainder, K - remainder))

if __name__ == "__main__":
    solve()
```この問題では K と N が別々の行に与えられるため、入力は 2 つの整数として読み取られます。 K はストップ間の間隔を定義し、N はスヴェタの位置を定義するため、順序は重要です。 

表現`N % K`前のバス停までの距離を示します。 Python の整数はオーバーフローしないため、制約の最大値は安全に処理されます。 

ゼロ剰余チェックは不必要な比較を回避し、Sveta がすでに停止している場合を直接処理します。 他のすべてのケースでは、可能な 2 つの方向が比較されます。 この実装では、丸めや浮動小数点演算を使用しないため、精度エラーやオフバイワンの間違いが回避されます。

 この例は、次の停留所だけをチェックすることが間違っている理由を示しています。 最も近い停留所はスヴェタの前ではなく、スヴェタの後ろにあります。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    K = int(input())
    N = int(input())

    remainder = N % K

    if remainder == 0:
        print(0)
    else:
        print(min(remainder, K - remainder))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert run("600\n2000\n") == "200\n", "sample style case"
assert run("10\n10\n") == "0\n", "already at a stop"
assert run("1\n2000000000\n") == "0\n", "minimum interval and maximum distance"
assert run("100\n1\n") == "1\n", "closest stop is the starting point"
assert run("10\n15\n") == "5\n", "exact middle of two stops"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 600、2000 | 200 | 以前のクローザーストップを伴う通常のケース |
 | 10、10 | 0 | バス停の正確な位置 |
 | 1、2000000000 | 0 | 最大値の処理 |
 | 100、1 | 1 | 位置 0 での停止 |
