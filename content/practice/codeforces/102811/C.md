 ## 解決策
 ## 問題の理解

 ボードには各行および各列にちょうど 1 つのルークが含まれているため、すべてのルークの位置は順列として表すことができます。 入力配列`a`行番号をインデックスとして使用します。`a[i]`どの列にルークが入っているかを教えてくれる`i`。 

タスクは、ボード全体を時計回りに 90 度回転し、新しい順列表現を印刷することです。 回転後、各ルークの行は古い列番号から変更されますが、新しい列は古い行番号に依存します。 

座標のルークについて`(i, a[i])`、時計回りに回転すると、座標が次のように変わります。`(a[i], N + 1 - i)`。 最初の座標が新しい行になり、2 番目の座標が新しい列になります。 回答配列には、新しい行ごとに新しい列を格納する必要があります。 

ボードのサイズに達することができます`N = 100000`したがって、ボードを明示的にシミュレートするソリューションは無駄になります。 このサイズのボードには最大 100 億個のセルが含まれることになりますが、メモリに収まらず、一般的なコンテストの制限時間内に処理することはできません。 考えられる多くの行と列のペアをチェックするアプローチでさえ遅すぎるため、ソリューションは線形時間で順列を直接処理する必要があります。 

いくつかの小さなケースでは、誤った実装が壊れる可能性があります。 最も一般的な間違いは、新しい行が古い行ではなく古い列であることを忘れることです。 たとえば、ボードにルークが 1 つある場合:```
1
1
```回転後もまだ唯一のセル内にあります。```
1
```この場合、基板のサイズを考慮せずに誤って座標を交換する解決策が正しいように見える可能性があります。 

もう 1 つのよくある間違いは、`N - i`の代わりに`N + 1 - i`1 ベースの座標を使用します。 例えば：```
3
1
2
3
```ルークは主対角線上にあります。 回転後は次のようになります。```
3
2
1
```行 1 のルークは列 3 に移動し、行 3 のルークは列 1 に移動する、というようになります。 1 ベースの入力に対して 0 ベースの数式を直接使用すると、不正確な値が生成されます。 

3 番目の問題は、配列を適切に変換しようとするときに情報を上書きすることです。 例えば：```
4
2
4
1
3
```新しい位置はすべての元のペアによって決定されます`(row, column)`。 番組が変わったら`a[2]`行 2 の元の値を使用する前は、結果は処理の順序に依存し、暗黙のうちに間違った値になる可能性があります。 

## アプローチ

 直接的なアプローチは、2 次元のボードを作成し、その上にすべてのルークを配置し、マトリックスを回転して、回答配列を再構築することです。 これは物理的な操作に正確に従っているため、正しいことを証明するのは簡単です。 ただし保管が必要です`N * N`細胞。 いつ`N = 100000`、つまり`10^10`細胞、それは不可能です。 

もう少し良い方法ですが、それでも不要なアプローチは、行と列を検索して、回転した各ルークがどこに行くべきかを見つけることです。 これによりボード全体を保存することは避けられますが、それでも多数のポジションをチェックする必要がある可能性があります。 と`N`ルーク、繰り返し検索すると到達できる`O(N^2)`操作、つまり約`10^10`最大の場合の操作。 

重要な観察は、入力によりすべてのルークの正確な座標がすでに与えられていることです。 空のセルをモデル化する必要はありません。 ローテーション公式により、各ルークの行き先がすぐにわかります。 ルーク`(i, a[i])`に移動します`(a[i], N + 1 - i)`、したがって、配置するだけで済みます`N + 1 - i`解答位置に入る`a[i]`。 

ブルートフォース手法は完全なボードを再構築するため機能しますが、完全なボードには必要のない情報が含まれています。 置換表現にはすでにすべてのルーク座標が含まれており、座標変換を使用するとタスクが 1 回のパスに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N²) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズの回答配列を作成します`N`。 この配列のインデックスは回転後の行を表し、格納された値はその行のルークの列を表します。 
2. 元の各行を読み取ります`i`とそのルーク列`a[i]`。 ルークは次の場所にあります`(i, a[i])`、時計回りに回転した後、ローに移動します。`a[i]`そしてコラム`N + 1 - i`。 
3.置く`N + 1 - i`の中へ`answer[a[i]]`。 ボードを作成せずに回転位置を直接記録します。 
4. 回答配列を行順に出力します。 各ポジションは、回転したボード内の 1 つのルークを正確に表します。 

機能する理由: すべてのルークが独立して処理され、時計回りの回転の座標変換が正確になります。 元の列にはすべてルークが 1 つだけ含まれているため、すべての値が`a[i]`これは、すべての新しい行が 1 つの割り当てを受け取ることを意味します。 したがって、回答配列には行ごとに 1 つの有効なルークの位置が含まれており、各割り当ては正しい回転ルークに対応します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    ans = [0] * n

    for i in range(n):
        col = int(input())
        ans[col - 1] = n - i

    print(*ans)

if __name__ == "__main__":
    solve()
```配列`ans`回転されたボード表現を保存します。 入力行と列は 1 から始まりますが、Python 配列は 0 から始まるため、宛先行は`col`に変換されます`col - 1`。 

ループ中に、`i`ゼロベース、つまり元の行を表す`i + 1`。 新しい列は次のとおりです。```
N + 1 - (i + 1) = N - i
```これがコードが割り当てる理由です`n - i`。 これにより、座標系間の不必要な相互変換が回避されます。 

元の列はすべて 1 回だけ出現するため、割り当て順序は重要ではありません。 各ルークは、次の異なる位置に書き込みます。`ans`, したがって、以前の結果は上書きされません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | すべてのルークは一度読み取られて変換されます。 |
 | スペース | O(N) | 結果として得られる順列のみが保存されます。 |

 最大入力サイズは`100000`したがって、線形アルゴリズムは約 10 万回の演算のみを実行し、制限内に簡単に収まります。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()

        n = int(sys.stdin.readline())
        ans = [0] * n

        for i in range(n):
            col = int(sys.stdin.readline())
            ans[col - 1] = n - i

        print(*ans)
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

assert run("""5
4
2
3
5
1
""") == "1 4 3 5 2", "sample"

assert run("""1
1
""") == "1", "minimum board"

assert run("""3
1
2
3
""") == "3 2 1", "diagonal rotation"

assert run("""4
2
4
1
3
""") == "3 1 4 2", "arbitrary permutation"

assert run("""5
5
4
3
2
1
""") == "1 2 3 4 5", "reverse permutation"

 | --- | --- | --- |

 ## 特殊なケース

 シングルセルボードの場合、アルゴリズムは行の唯一のルークを読み取ります。`1`、 カラム`1`。 それは書きます`1`の中へ`ans[0]`したがって、出力は次のようになります。```
1
```新しい行と新しい列は両方とも 1 に等しいため、数式は引き続き機能します。 

対角線の場合:```
3
1
2
3
```最初のルークは次の位置にあります`(1,1)`そしてに移動します`(1,3)`、2番目はに留まります`(2,2)`、3番目はに移動します`(3,1)`。 アルゴリズムの配置`3`、`2`、 そして`1`対応する位置に配置すると、以下が生成されます。```
3 2 1
```これにより、減算が次を使用することが確認されます。`N - i`正しく。 

自明でない順列の場合:```
4
2
4
1
3
```ルークは次のように動きます。 ルーク`(1,2)`に行きます`(2,4)`、ルーク`(2,4)`に行きます`(4,3)`、ルーク`(3,1)`に行きます`(1,2)`、ルーク`(4,3)`に行きます`(3,1)`。 解答の位置は次のようになります。```
2 4 1 3
```実際に新しい列を行ごとに書き込むと、次のようになります。```
2 4 1 3
```実装ではこれを処理します。これは、古い列がそれぞれ一意の宛先行として使用され、すべてのルークが 1 回だけ配置されるためです。
