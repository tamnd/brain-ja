 ## 解決策
 ## 問題の理解

 行と列が 1 から始まる無限グリッドがあります。セルは、ますます大きな正方形の境界線を歩き回ることで、連続する整数で埋められます。 タスクは、指定された数値 n を含むセルの座標を見つけることです。 

重要な観察は、充填が恣意的ではないということです。 辺の長さが k の正方形を完成すると、正確に k² のセルが埋められます。 これは、すべての数字が 1 つの正方形のレイヤーに属していることを意味し、主な課題は、そのレイヤーをすばやく見つけて、その境界線内の位置を特定することです。 

n の値は 10¹8 に達する可能性があるため、充填プロセスをシミュレートすることは不可能です。 答えは正方形の層といくつかの算術演算のみに依存するため、O(√n) シミュレーションさえも不要です。 ソリューションは、64 ビット整数演算を使用して、一定時間またはそれに近い時間で機能する必要があります。 

よくある間違いは、浮動小数点平方根を使用することです。 10¹⁸ に近い値の場合、浮動小数点計算が誤って丸められ、n が間違った層に配置される可能性があります。 たとえば、16 などの正確に正方形の数値は、4 × 4 の境界線に属している必要があります。 実装を不注意にすると、わずかに小さい平方根が計算され、それが前の層に属するものとして扱われ、誤った座標が生成される可能性があります。 

もう 1 つのエッジ ケースは、可能な最小値です。 入力用`1`、答えは`1 1`。 最初の層には以前のセルがないため、層に前の正方形があると想定するコードは失敗します。 

もう 1 つの重要な境界は、レイヤーの端です。 たとえば、次のような数字です。`9`3 x 3 の正方形の最後の値です。 その座標は`1 3`。 実装が包括的な比較ではなく厳密な比較を使用する場合、この値を次の層に移動できます。 

## アプローチ

 直接的なアプローチは、セルごとにスパイラルを構築することです。 最初のセルから開始して、正方形の境界に沿って移動し続け、n に達するまで数えます。 これは、数字が書かれた順序に正確に従っているため、正しいです。 ただし、最大の入力には最大 10¹⁸ の値が含まれるため、訪問セルの数も約 10¹⁸ になる可能性があります。 このようなシミュレーションは、実際的な時間内では完了できません。 

スパイラル構造により素早いアプローチが可能です。 辺の長さが k の正方形には正確に k² のセルが含まれているため、n を含む層は最小の k (k² が少なくとも n) になります。 この層がわかったら、最初の (k-1)² 数値はすでに終わっています。 残りのオフセットは、n が現在の正方形の境界線のどこにあるかを示します。 

境界線の方向は、k が奇数か偶数かによってのみ決まります。 奇数レイヤーでは、新しい四角形は左下隅から始まり、右に移動し、次に右側に沿って上に移動します。 偶数レイヤーでは、右上隅から開始して下に移動し、下側に沿って左に移動します。 これにより、他のセルにアクセスすることなく答えを計算できます。

 ## アルゴリズムのチュートリアル

 1. k² が少なくとも n となるような最小の整数 k を見つけます。 これは、n を含む正方形の境界線の辺の長さです。 この境界線の前のセルの数は次のとおりです。`(k - 1)²`, したがって、レイヤー内のすべての数値は、その値からのオフセットによって識別できます。 
2. コンピューティング`offset = n - (k - 1)²`。 オフセットは 1 ～`2k - 1`なぜなら、正方形の境界線はちょうどその数の新しいセルを追加するからです。 
3. k が奇数の場合、左下隅から境界線を処理します。 オフセットが最大でも k の場合、数値は一番下の行にあるため、行が k で列がオフセットになります。 それ以外の場合、数値は右の列にあり、下から上に移動するため、列は k のままで行が減少します。 
4. k が偶数の場合、右上隅から境界線を処理します。 オフセットが最大でも k の場合、数値は右側の列にあるため、行がオフセットで列が k になります。 それ以外の場合、数値は一番下の行にあり、左に移動するため、行は k のままで、列は減少します。 

なぜ効果があるのか:

 各レイヤー k には、前の正方形を辺の長さ k-1 から辺の長さ k まで拡張するセルが正確に含まれています。 すべての小さなレイヤーには正確な内容が含まれているため、アルゴリズムは最初にこの一意のレイヤーを識別します。`(k-1)²`セルと現在のレイヤーは k² で終了します。 境界線の通過順序が固定されているため、レイヤー内ではオフセットによって位置が一意に決まります。 境界上のすべての可能な位置が 1 回だけカバーされるため、計算された座標は n の位置と一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    k = int(n ** 0.5)
    while k * k < n:
        k += 1
    while (k - 1) * (k - 1) >= n:
        k -= 1

    offset = n - (k - 1) * (k - 1)

    if k % 2 == 1:
        if offset <= k:
            row = k
            col = offset
        else:
            row = 2 * k - offset
            col = k
    else:
        if offset <= k:
            row = offset
            col = k
        else:
            row = k
            col = 2 * k - offset

    print(row, col)

if __name__ == "__main__":
    solve()
```層の計算により、n を含むのに十分な大きさの最初の正方形が見つかります。 補正ループが使用されるのは、最初の平方根が浮動小数点演算から取得され、入力範囲が十分に大きいため丸め誤差が発生する可能性があるためです。 

オフセット計算では、グローバル番号が 1 つの正方形の境界線のみの内側の位置に変換されます。 これにより、以前のレイヤーのサイズへの依存が回避されます。 

パリティ チェックはトラバース方向を制御します。 奇数と偶数の正方形サイズでは開始角が反対になるため、間違った分岐を使用すると正方形全体で答えが反映され、入力の約半分で失敗します。 

Python の整数には任意の精度があるため、k² などの中間値が 10¹⁸ に近づく可能性がある場合でも、オーバーフローの問題は発生しません。 

## 実用的な例

 サンプル出力の場合、欠落している入力は次のようになります。`n = 15`。 

| n | k | オフセット | ケース | 行 | 列 |
 | --- | --- | --- | --- | --- | --- |
 | 15 | 4 | 6 | 平ら、底面 | 4 | 2 |

 4 x 4 レイヤーは 9 の後に始まります。下の行に沿って右側に移動し、次に左側に移動すると、この境界線の 6 番目の新しい値に到達し、座標が得られます。`(4,2)`。

 最初のレイヤーには最初のセルのみが含まれるため、アルゴリズムはすぐに開始位置を返します。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())

    k = int(n ** 0.5)
    while k * k < n:
        k += 1
    while (k - 1) * (k - 1) >= n:
        k -= 1

    offset = n - (k - 1) * (k - 1)

    if k % 2 == 1:
        if offset <= k:
            row, col = k, offset
        else:
            row, col = 2 * k - offset, k
    else:
        if offset <= k:
            row, col = offset, k
        else:
            row, col = k, 2 * k - offset

    sys.stdin = old_stdin
    return f"{row} {col}"

assert solve_case("15\n") == "4 2", "sample"
assert solve_case("1\n") == "1 1", "minimum value"
assert solve_case("9\n") == "1 3", "perfect square boundary"
assert solve_case("16\n") == "4 1", "even layer end"
assert solve_case("25\n") == "1 5", "maximum corner of odd layer"

 ## 特殊なケース

 入力用`1`、アルゴリズムは k = 1 および offset = 1 を見つけます。k は奇数で、オフセットは最初の k セル内にあるため、値が行 1、列 1 に配置されます。これにより、存在しない前の正方形にアクセスしようとすることが回避されます。 

入力用`9`の場合、9 は正確に正方形であるため、アルゴリズムは k = 3 を見つけます。 8 つのセルが前のレイヤーに属しているため、オフセットは 5 です。 k は奇数で、オフセットは k より大きいため、数値は行の右側の列にあります。`2 * 3 - 5 = 1`、与える`(1,3)`。 これにより、正確な二乗値が正しいレイヤーに割り当てられていることが確認されます。 

入力用`16`の場合、アルゴリズムは k = 4 の次の層に移動します。オフセットは 7 で、右側の最初の 4 つのセルを超えています。 残りの移動は一番下の行に沿って行われ、列が表示されます。`2 * 4 - 7 = 1`と行4。答えは次のとおりです。`(4,1)`、新しい境界線の最初のセル。
