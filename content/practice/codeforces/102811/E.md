 # 問題の理解

 与えられた初期サイズを持つ細菌の系列があります。 2 つの細菌が出会うと、厳密に大きい細菌のみがもう一方の細菌を吸収でき、吸収された量だけ自分自身のサイズが大きくなります。 同じ大きさの細菌は互いに影響を与えることができません。 私たちは、すべての元の細菌について、その細菌が唯一残った細菌として残される何らかの一連の遭遇が存在するかどうかを判断する必要があります。 

入力サイズはすでに降順ではない順序で並べ替えられています。 出力は、すべての位置に対する二項回答です。`1`ということは、この特定の出発菌には何らかの勝利戦略がある可能性があるということですが、`0`つまり、どの一連の動きも単独で生き残ることはできないということです。 

までの制約`10^5`バクテリアは、考えられるすべての遭遇順序を試みることを排除します。 考えられる配列の数は非常に急速に増加するため、すべての出発細菌からのシミュレーションでさえ、利用可能な時間をはるかに超えてしまいます。 ほぼ線形の解決策を可能にするために、ソートされたサイズから直接勝者を記述するプロパティを見つける必要があります。 

いくつかの特殊なケースは見落とされがちです。 単一のバクテリアが常に勝ちます。なぜなら、それはすでに唯一残っているからです。 

例：```
1
7
```正しい出力は次のとおりです。```
1
```最終的なサイズを元の最大サイズと常に比較する式では、細菌が自分自身を倒す必要がないため、このケースは誤って拒否されます。 

もう 1 つの注意が必要なケースは、すべての細菌のサイズが同じ場合です。 

例：```
3
5
5
5
```正しい出力は次のとおりです。```
0
0
0
```考えられるすべてのペアは同じサイズであるため、細菌は他の細菌を食べることはできません。 等しい値を自動的に互いに助け合うものとして扱うソリューションでは、間違った答えが得られます。 

最大値が繰り返される 3 番目の境界ケースが表示されます。 

例：```
3
1
4
4
```正しい出力は次のとおりです。```
0
0
0
```サイズ 4 の細菌はサイズ 1 の細菌を食べてサイズ 5 になることはできますが、2 つのサイズ 4 の細菌は協力することができません。 最初のサイズ 4 の細菌は、増殖する前に他の細菌を消費することができず、増殖後は、利用可能な唯一の増殖源がすでに使用されています。 最大値が等しい場合は、特別な処理が必要です。 

# アプローチ

 直接的なアプローチは、すべての開始細菌についてゲームをシミュレートすることです。 選択したバクテリアについて、残っているより小さいバクテリアを繰り返し検索し、それを吸収し、すべてが食べられるか、進歩が不可能になるまで続けることができます。 これは正しいです。なぜなら、将来の勝者にとって有益な行動は、すでに倒せる細菌から大量に獲得することだけだからです。 

問題は、このプロセスが遅すぎることです。 あり得る`10^5`バクテリア、そして勝者となる可能性のあるものを個別にテストすることはすでに費用がかかります`O(n)`仕事。 さらに、シミュレーションでは多くの吸収が実行される場合があります。 最悪の事態は簡単に起こります`O(n^2)`オペレーション、つまり`10^10`最大入力のステップ数。 

重要な観察は、勝利したバクテリアは、より小さなバクテリアを生かしておくことによって決して利益を得られないということです。 より小さな細菌はすべてそれを強くすることしかできないため、勝者となる可能性のある人は、まず自分よりも小さな細菌をすべて吸収することができます。 その後、そのサイズは固定され、より大きなまたは同等の細菌と戦う前に到達できる最強の状態を表します。 

ある程度の大きさの細菌の場合`x`、 させて`s`厳密に以下より小さいすべての細菌の合計であること`x`。 残りの細菌を攻撃する前に考えられる最大サイズは次のとおりです。`x + s`この値が残りのすべての敵よりも大きい場合、細菌はすべてを吸収し続けることができます。 残っている対戦相手が少なくともこれほど大きい場合、その対戦相手を除去するために必要な吸収の連鎖を開始することはできません。 

配列はソートされているため、同じ値を持つすべてのバクテリアは同じ小さなバクテリアのセットを持っているため、すべての等しい値は同じ答えを受け取ります。 必要なのはプレフィックスの合計と最大値に関する情報だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 単一の細菌の場合は個別に処理します。 すでに勝者なので、答えは次のとおりです。`1`。 
2. 最大値と、それが 1 回または複数回出現するかどうかを見つけます。 これにより、細菌が倒す必要がある最も困難な敵が決まります。 通常、この相手は全体最大値ですが、固有最大値の細菌は自分自身に勝つ必要がないため、2 番目に大きい値を超えれば十分です。 
3. 等しい値のグループごとにソートされた配列を走査します。 グループを処理する前に、すべての値の合計が現在のグループより小さくなるように維持してください。 グループ内のすべての細菌は、まったく同じ量の増殖可能量を持っています。 
4. 各グループの値について`x`、グループ内の各細菌が倒さなければならない最大の敵を計算します。 もし`x`は固有の最大値であり、その対戦相手は 2 番目に大きい値です。 それ以外の場合はすべて、グローバル最大値です。 
5. 次の場合にグループ全体を勝利としてマークします。`x + sum_of_smaller_values`その相手よりも厳密に大きいです。 同じサイズの細菌は互いに消費できないため、厳密な不平等が必要です。 

それが機能する理由: 不変条件は、細菌がより大きな細菌または同等の細菌を倒そうとする前に、考えられる最良の状況は、細菌がすでにすべての小さな細菌を吸収していることです。 勝利シーケンスは、すべての小さな吸収が最初に発生するように再配置できます。これらの吸収はサイズを増やすだけであり、将来の機会を取り除くことはありません。 この可能な最大の中間サイズに達した後は、残りの敵がすべて小さくなって細菌が勝つか、細菌が勝てない敵が存在するかのどちらかになります。 アルゴリズムはこの条件を正確にチェックします。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]

    if n == 1:
        print(1)
        return

    total_max = a[-1]
    second_max = a[-2]

    cnt_max = 1
    i = n - 2
    while i >= 0 and a[i] == total_max:
        cnt_max += 1
        i -= 1

    ans = [0] * n
    smaller_sum = 0
    i = 0

    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1

        value = a[i]

        if value == total_max and cnt_max == 1:
            opponent = second_max
        else:
            opponent = total_max

        if value + smaller_sum > opponent:
            for k in range(i, j):
                ans[k] = 1

        smaller_sum += value * (j - i)
        i = j

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```ソートされた順序は問題の有用な構造の一部であるため、入力は配列に読み込まれます。 Python の整数はオーバーフローしないため、プレフィックスの合計は安全に次の値まで増加できます。`10^14`。 

スキャンでは、等しい値がまとめて処理されます。 変数`smaller_sum`常に、より小さい値を持つ細菌の合計サイズのみが含まれ、現在のグループは含まれません。 現在の細菌が増殖する前に同じサイズの細菌を食べることはできないため、この詳細は不可欠です。 

最大値については別途処理が必要です。 一度出現した場合、その細菌は自らを倒す必要はないため、最大値と比較すると、誤ってその条件を不可能にしてしまいます。 最大値が複数回出現すると、別の最大サイズの細菌が相手として残ります。

 # エッジケース

 1 つの細菌の場合、アルゴリズムはすぐに戻ります。`1`。 

入力：```
1
7
```倒すべき相手がいないので、バクテリアは何もせずに勝利します。 

すべての値が等しい場合、走査によって単一のグループが作成されます。 より小さい細菌は存在しないため、小さい方の合計はゼロになります。 

入力：```
3
5
5
5
```手の届くサイズは、`5`、一方、別のサイズの細菌`5`残っています。 等価性では吸収が許可されないため、条件は失敗します。 

最大値が繰り返される場合、その最大値は別の最大値を踏み台として使用できません。 

入力：```
3
1
4
4
```価値のあるグループ`4`もっている`smaller_sum = 1`。 到達可能なサイズは、`5`、しかし比較相手はまだです`4`別の最大値が存在するためです。 この条件は 1 つの最大値に対して true であるように見えますが、この例には最大値のバクテリアが 2 つあるため、両方ともグループとして処理され、相手は残ります。`4`、与える`5 > 4`。 アルゴリズムは両方を勝者として正しくマークします。 

最後のケースは、グループ処理が必要な理由を示しています。 等しい値は、同じ小さい合計と同じ将来の可能性を共有するため、それらを誤って分割すると、一貫性のない答えが作成される可能性があります。
