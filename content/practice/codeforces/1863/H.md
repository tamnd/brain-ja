 ## 解決策
 ## 問題の理解

 私たちは完全なルート付き二分木を扱っています。これは、すべての非葉ノードがちょうど 2 つの子を持つことを意味します。 各リーフには、最終的に受信する必要がある Cookie の数を表す「ハンガー値」があります。 非リーフ ノードには、Cookie がどの子に移動するかを決定するセレクターがあります。 Cookie が内部ノードを通過するたびに、セレクターが反転し、次の Cookie がたどるパスが切り替わります。 

タスクは、すべてのセレクターの状態を最初に設定できることを前提として、すべてのリーフを満たすために必要な Cookie の最小数を決定することです。 特定のリーフの飢餓を更新する各クエリの後に、この最小値を再計算する必要があります。 答えはモジュロである必要があります$998244353$。 

制約は重要です。ツリーには最大 200,000 個のノードを含めることができ、クエリは 200,000 個存在する可能性があります。 各葉の満腹度は最大です$10^9$。 Cookie ドロップを直接シミュレートするアプローチでは、何十億もの操作が必要となり、実行不可能です。 

明らかではないエッジケースは、葉の飢餓状態が不均等であるか、飢餓状態がゼロである場合に発生します。 たとえば、最初にすべての葉の飢餓がゼロの場合、Cookie は必要ありません。 1 つのリーフが非常に多くの数を必要とし、他のリーフが非常に少ない数を必要とする場合、初期セレクター状態を選択する機能を考慮していない単純なアプローチでは、交互のパス 反転を誤ってカウントする可能性があります。 また、クエリ内でリーフの飢餓が変化した場合、動的更新をサポートする構造がなければ、以前の計算を再利用することはできません。 

## アプローチ

 ブルートフォース手法では、Cookie を 1 つずつ挿入することをシミュレートし、Cookie がツリーの下に移動するにつれてセレクターを更新します。 クッキーごとに、ルートからリーフまでトラバースし、パスに沿ってセレクターを反転し、すべての飢餓値が満たされるまでリーフの数を増やします。 最悪の場合、必要に応じて$10^9$cookie を使用すると、このアプローチは絶望的に遅いです。 操作数は、すべてのリーフ ハングリーの合計にツリーの深さを乗じた値に比例します。 

重要な観察は、各内部ノードが時間の経過とともにその 2 つの子に Cookie を均等に配布するということです。 内部ノードをルートとするサブツリーを考えると、$2^k$Cookie は、セレクターが最適な初期状態で開始した場合、ちょうど半分が左に進み、半分が右に進みます。 より一般的には、左右の子を持つノードの場合、両方のサブツリーを満たすために必要な最小 Cookie は、奇数の分布のバランスをとるために切り上げられた、左と右の最小値の合計になります。 

これは、ツリー上でのボトムアップ動的プログラミング アプローチにつながります。 各ノードについて、そのサブツリーに必要な Cookie の最小数を表す値を維持します。 葉は空腹値を自明に受け取ります。 内部ノードは、その値を左右の子の値の合計として計算し、適切な交互になるように切り上げます。 これが機能するのは、いつでも初期セレクター状態を選択して、分散のバランスを最適にできるためです。 

クエリを効率的に処理するために、リーフ ハンガー値の配列を維持し、更新されたリーフからルートまでのパスに沿って DP 値を再計算します。 木の高さがあるので、$O(\log n)$、各クエリのコストのみがかかります$O(\log n)$操作。 これは 200,000 クエリに対して実現可能です。

 ## アルゴリズムのチュートリアル

 1. ツリー構造とリーフ飢餓値を解析します。 子を表す隣接リストを作成します。 リーフノードを特定します。 
2. DP 配列を初期化する`dp[node]`をルートとするサブツリーを満たすために必要な最小数の Cookie を保存します。`node`。 葉っぱに関しては、`dp[leaf] = hunger[leaf]`。 
3. 内部ノードの場合、次のように定義します。`dp[node]`子の DP 値の合計の半分に交代のバランスを取るための上限補正を加えた上限として。 正式には、左の子に対して`L`そして右の子`R`、`dp[node] = ceil((dp[L] + dp[R])/2)`2 倍、または同等の`dp[L] + dp[R]`。 
4. 事後 DFS トラバーサルを使用して初期 DP 値を計算します。 この後、`dp[1]`マシンを満たす最小限の数の Cookie が含まれています。 
5. クエリごとにリーフを更新する`v`新たな飢えとともに`x`、 セット`dp[v] = x`そして変更をルートまでのパスに伝播します。 各祖先で、その祖先を再計算します。`dp`2人の子供に基づいています。 
6. 各更新後に記録します。`dp[1]`答えはモジュロ 998244353 です。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`dp[node]`は常に、最適な初期セレクター状態を想定して、そのノードをルートとするサブツリーに必要な最小限の Cookie を保管します。 開始状態を選択することで Cookie のシーケンスを最適に配置できるため、セレクターの交互の性質は子の最小値を合計することによって処理されます。 ルートへのパスに沿ってのみ更新を伝播すると、効率的でありながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)
MOD = 998244353

n = int(input())
p = list(map(int, input().split()))
h = list(map(int, input().split()))
q = int(input())

children = [[] for _ in range(n)]
for i, parent in enumerate(p):
    children[parent - 1].append(i + 1)

is_leaf = [len(children[i]) == 0 for i in range(n)]
dp = [0] * n

def dfs(u):
    if is_leaf[u]:
        dp[u] = h[u]
    else:
        dfs(children[u][0])
        dfs(children[u][1])
        dp[u] = dp[children[u][0]] + dp[children[u][1]]

dfs(0)
print(dp[0] % MOD)

leaf_to_index = [i for i in range(n) if is_leaf[i]]

for _ in range(q):
    v, x = map(int, input().split())
    v -= 1
    h[v] = x
    dp[v] = x
    u = v
    while u != 0:
        parent = p[u-1] - 1 if u != 0 else None
        if parent is not None:
            left, right = children[parent]
            dp[parent] = dp[left] + dp[right]
        u = parent if u is not None else 0
    print(dp[0] % MOD)
```コードは最初にツリーを構築し、葉を識別し、事後 DFS を実行して計算します。`dp`価値観。 各クエリはリーフの飢餓を更新し、その効果を上方に伝播し、ルートに常に正しい合計最小 Cookie が含まれるようにします。 印刷時にのみモジュロ演算を使用すると、不必要な計算オーバーヘッドが回避されます。
