 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられており、それを各値が一致するインデックス位置に位置する恒等順列に変換したいと考えています。 唯一許可される移動は、一種の安定したパーティションです。しきい値 x を選択し、x より小さいすべての要素を現在の相対順序で取得し、その後に x 以上のすべての要素を取得して、再び相対順序を維持することによって配列を並べ替えます。 

この操作では、任意の再配置は許可されません。 各グループ内の内部順序を維持しながら、値のしきい値に基づいてシーケンスを繰り返し分割できるだけです。 目標は、順列を完全に並べ替えるのに必要な分割の最小数を決定することです。 

n が最大 100,000、テスト全体の合計も最大 100,000 という制約は、テスト ケースごとに線形または線形に近い解が必要であることを意味します。 各操作を明示的にシミュレートしたり、配列を繰り返し再構築したりするなど、二次的なものはすべて生き残れません。 

微妙な点は、この操作は位置ではなく値に依存しますが、位置にグローバルに影響を与えることです。 素朴な直観では「段階的に並べ替えている」と思われるかもしれませんが、各操作が単一のパーティションであるという制限により、プロセスは通常の並べ替えよりも構造化されます。 

誤解を招きやすいエッジケースとしては、すでにソート済みの配列、完全に反転した配列、ローカルな順序は部分的にソートされているように見えるが、グローバル構造ではまだ複数のパーティションが必要である順列などが挙げられます。 たとえば、次のような順列`[2, 1, 3, 4]`はすでにほぼソートされていますが、単一のしきい値分割で 1 と 2 を正しく分離できるため、必要な操作は 1 つだけです。 

もう 1 つの罠は、操作ごとに 1 つの要素を修正できると仮定していることです。 これは真実ではありません。なぜなら、複数の誤って配置された要素がしきい値分割に一致していれば、1 回の操作で同時に修正できるからです。 

## アプローチ

 ブルートフォース戦略では、プロセスを直接シミュレートします。 現在の順列から、2 から n までのすべての可能な x を試し、安定した分割操作を適用し、ソートされた配列に到達するまでの最小ステップを再帰的に検索します。 各操作のコストは O(n) で、状態空間はすべて順列であるため、最悪の場合のサイズは階乗になります。 状態を BFS に制限しても、n! が得られます。 原理的には不可能であると述べています。 

重要な観察は、操作が本質的に値のしきい値の階層を構築していることです。 各操作では、位置空間ではなく値空間のカット ポイントが選択されます。 最終的に並べ替えられた配列がどのように表示される必要があるかを考えると、各値は最終的にはその前に表示される大きな値から分離されなければなりません。 

重要な構造的洞察は、値を n から 1 までスキャンし、連続する値の「位置順序」が特定の方法で何回壊れるかを数えるということです。 正しい最終状態では、値 1 から n が昇順に表示されます。 連続する値 i と i+1 の間の反転は、それらが現在、それらを分離する操作なしでは修正できない異なる相対ブロック内にあることを意味します。 

各操作では、複数の隣接する正しいセグメントを値の順序で 1 つのソートされた構造にマージできますが、すべてのブレークを一度に修正することはできません。 これは、i+1 の位置が i の前に何回現れるかによって答えが決まり、少なくとも 1 つの新しい演算境界が強制されるという考えにつながります。 

したがって、操作をシミュレートする代わりに、値の昇順に関して順列がどの程度断片化されているかを測定します。

 ## アルゴリズムのチュートリアル

 1. pos[v] が順列内の値 v のインデックスを示す配列 pos を構築します。 

これにより、問題はポジションに関する問題から純粋に値の順序制約に関する問題に変わります。 
2. カウンタセグメントを 1 に初期化し、形成する必要がある少なくとも 1 つの連続した構造を表します。 
3. v を 1 から n-1 まで繰り返し、pos[v] と pos[v+1] を比較します。 

pos[v] が pos[v+1] より大きくなるたびに、順列において v が v+1 の後に出現し、増加構造が壊れることを意味します。 
4. このようなブレークが発生するたびに、セグメントを 1 ずつインクリメントします。 

これは、v と v+1 が同じ「すでに正しく順序付けされたブロック」に属することができないことを反映しているため、順序を分離して修正するには少なくとも 1 つの追加操作が必要です。 
5. セグメントから 1 を引いた値を答えとして出力します。 

1 の減算は、操作が適用される前に最初の配列がすでに 1 つのセグメントとみなされ、ブレークが検出されるたびにセグメント間で必要なマージの数が増加するという事実に基づいています。 

### なぜ効果があるのか

 しきい値 x を使用した各操作では、値が 2 つの単調グループ (x 未満の値と x 以上の値) に分割され、内部順序が維持されます。 これは、並べ替えられた順序で連続する値間の不規則性を修正する唯一の方法は、最終的には、位置順序で前のすべての値が後の値よりも前に表示されるようにすることであることを意味します。 

pos[v] > pos[v+1] になるたびに、ペア (v, v+1) は位置の順序が反転され、少なくとも 1 つの操作境界がなければ統合できない異なる構造層に強制されます。 このような構造的ブレークの数によって、必要な独立したマージの数が決まり、最良の場合、各操作で断片化の層をちょうど 1 つ減らすことができます。 

したがって、これらのブレークの数は、必要な操作の最小数に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i
        
        segments = 1
        for v in range(1, n):
            if pos[v] > pos[v + 1]:
                segments += 1
        
        print(segments - 1)

if __name__ == "__main__":
    solve()
```実装の中核は位置反転配列です。 値を位置に変換することで、操作を完全にシミュレートする必要がなくなります。 

v に対するループは、連続する値が正しい左から右の順序で表示されるかどうかをチェックします。 違反ごとに、必要な構造セグメントの数が増加します。 最後の減算により、最初のセグメントのベースラインが考慮されます。 

ここでインデックス作成エラーが発生するとロジックが完全に逆転してしまうため、pos を正しく構築するように注意する必要があります。 また、複数のテスト ケースが存在するため、リークを避けるためにケースごとにすべてのアレイを再構築する必要があります。 

## 実用的な例

 ### 例 1

 入力順列:`[2, 1, 3, 4]`位置を計算します。 

pos[1] = 1、pos[2] = 0、pos[3] = 2、pos[4] = 3

 | v | pos[v] | pos[v+1] | 壊す？ | セグメント |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | はい | 2 |
 | 2 | 0 | 2 | いいえ | 2 |
 | 3 | 2 | 3 | いいえ | 2 |

 答えは 2 - 1 = 1 です。 

これは、1 と 2 の間の 1 つの反転を示しており、1 つの操作が必要です。 

### 例 2

 入力順列:`[3, 2, 1]`ポジション:

 pos[1] = 2、pos[2] = 1、pos[3] = 0

 | v | pos[v] | pos[v+1] | 壊す？ | セグメント |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | はい | 2 |
 | 2 | 1 | 0 | はい | 3 |

 答えは 3 - 1 = 2 です。 

隣接する各反転は、順列が完全に反転していることを反映して、個別の構造分割要件に寄与します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0] * (n + 1)

            pos[v] = i

        for v in range(1, n):
            if pos[v] > pos[v + 1]:
                segments += 1
        out.append(str(segments - 1))
    return "\n".join(out)

 ## 特殊なケース

 すでにソート済みの順列の場合、`[1, 2, 3, 4]`、すべての連続するペアは pos[v] < pos[v+1] を満たすため、セグメントの分割は発生せず、アルゴリズムはゼロを出力します。 これは、操作が必要ないという事実と一致します。 

次のような完全に逆の順列の場合`[n, n-1, ..., 1]`、すべての隣接するペアの位置順序が反転されるため、セグメント数は n になり、答え n-1 が生成されます。 各反転により明確な構造分離が強制され、アルゴリズムは必要なすべての操作を正しく蓄積します。 

次のような単一のローカル スワップを含む順列の場合`[1, 3, 2, 4]`の場合、ペア (2, 3) のみがブレークを作成し、単一の必要な操作を生成します。 スキャンでは位置反転が 1 つだけ検出され、アルゴリズムによってそれが 1 つの分割ステップに直接変換されます。
