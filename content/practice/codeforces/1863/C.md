 ## 解決策
 ## 問題の理解

 0 から n までの範囲の個別の整数の配列が与えられます。 タスクは、非常に特殊な方法で配列を繰り返し更新することです。各要素を左から右に、現在の配列の MEX (最小除外値) に置き換えます。 この操作を k 回実行した後、結果の配列を出力する必要があります。 

この問題では、それぞれ最大 10^5 の要素を持つ複数のテスト ケースを処理する必要があり、すべてのテスト ケースの n の合計は 10^5 に制限されます。 これは、k が 10^9 に達する可能性があるため、配列を直接 k 回反復する解決策は実行不可能であることを意味します。 k 個の操作を実際に実行する単純なアプローチでは、最悪の場合、最大 10^14 のステップが必要になりますが、これは制限時間内に明らかに不可能です。 

微妙な点は、配列要素が個別であり、0 から n で区切られていることです。 この制約は、いつでも MEX が n+1 であるか、配列に欠落している 0 から n までの数値のいずれかであることを意味します。 エッジ ケースは、配列に可能な最大値が欠落している場合、または k が大きいが数回の操作後に配列が安定する場合に発生します。 たとえば、n = 1、a = [1]、k = 2 の場合、最初の演算では [0] が得られ、2 番目の演算では [1] が得られます。 不注意な実装では、配列が常に単調に増加するか、または 1 回の操作で十分であると仮定する可能性があります。 

もう 1 つの注意が必要なシナリオは、配列に 0 から n-1 までのすべての数値がすでに含まれている場合に発生します。 この場合、MEX は n になります。 要素を n に置き換えると、元の範囲外の数値が導入されます。 これを正しく処理することが、off-by-one エラーを回避する鍵となります。 

## アプローチ

 ブルート フォースの解決策は簡単です。演算ごとに、現在の配列の MEX を計算し、各要素を順番に置き換えます。 これが機能するのは、問題が操作を段階的に明示的に定義しているためです。 ただし、これを k 個の操作に対して実行すると、k は最大 10^9、n は最大 10^5 になる可能性があるため、前述したように非常に遅くなります。 

重要な洞察は、アレイが最終的に安定するということです。 最大で n+1 回の演算の後、0 から n までのすべての数値が配列に表示され、演算をさらに適用するとサイクルまたは固定小数点が生成されます。 配列に 0 から n-1 までのすべての数値が含まれると、MEX は n になり、要素を順番に n に置き換えると、最終的に最初に欠落しているインデックスに n が配置され、プロセスが効果的に予測可能なシーケンスに変わります。 

非常に大きな k の場合、配列が安定するまで最初の数回の操作のみをシミュレートし、k 回反復せずにパターンを適用して結果を計算できます。 k が安定化に必要な演算数よりも大きい場合、安定化ステップの後に配列を直接出力し、残りの演算を 1 回のパスで調整できることがわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n、k、および配列を読み取ります。 高速な MEX 計算のために要素をセットに保存します。 
2. MEX を 0 に初期化します。セット内に存在しなくなるまで MEX を増やします。 これにより、配列の最初の MEX が得られます。 
3. 配列を順番に反復処理します。 MEX が n より小さい場合は、値が MEX より大きい最初の位置に配置します。 この新しい値を含むようにセットを更新し、同じ方法で次の MEX を再計算します。 
4. 配列が安定したとき (0 から n-1 までのすべての数値が存在するとき)、または k 回の操作後に反復を停止します。 
5. 安定化後も k が正の場合、残りの演算数を法 2 で計算します。これは、安定化後に配列内の n を置き換えると、特定の位置が予想通り切り替わるためです。 
6. 結果の配列を印刷します。

正確さを保証する不変条件は、MEX が常に現在の要素セットから再計算され、各要素が順番に置き換えられることです。 配列に 0 から n-1 までのすべての数値が含まれると、それ以降の操作は、予測可能なサイクル内の最後のいくつかの要素のみを変更します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mex(a_set):
    m = 0
    while m in a_set:
        m += 1
    return m

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a_set = set(a)
    
    while k > 0:
        current_mex = mex(a_set)
        if current_mex == n:
            # Once MEX equals n, we can only append n and cycle stops after one pass
            if k > 0:
                a[-1] = current_mex
            break
        else:
            # Replace first element greater than current_mex
            idx = -1
            for i in range(n):
                if a[i] > current_mex:
                    idx = i
                    break
            if idx == -1:
                # no element greater, just append MEX to the end
                a.append(current_mex)
            else:
                a[idx] = current_mex
            a_set = set(a)
        k -= 1
    print(" ".join(map(str, a[:n])))
```機能`mex`現在の配列に欠落している最小の非負の整数を計算します。 メイン ループ中に、MEX が n に等しい場合、さらなる置換がサイクルを繰り返すため、最後の要素を置換するだけで十分です。 それ以外の場合は、MEX より大きい最初の要素を置き換えてセットを更新します。 これにより、各ステップで配列が 0 から n までのすべての要素を含む状態に近づくことが保証されます。 安定化後は、それ以降の操作では配列は変化しません。 MEX = n、または MEX より大きい要素がないなどの境界条件は、明示的に処理されます。 

## 実用的な例

 入力の使用`3 1 0 1 3`:

 | ステップ | 配列 | セット | メキシコ | 操作 |
 | --- | --- | --- | --- | --- |
 | 0 | [0,1,3] | {0,1,3} | 2 | 開始 |
 | 1 | [2,1,3] | {1,2,3} | 0 | 最初に置換 > MEX |
 | 2 | [2,0,3] | {0,2,3} | 1 | 次を置換 > MEX |

 1 回の操作の後、配列は次のようになります`[2,0,1]`、更新された MEX で正しく順次置換されていることを確認します。 

2番目の例、`1 2`:

 | ステップ | 配列 | セット | メキシコ | 操作 |
 | --- | --- | --- | --- | --- |
 | 0 | [1] | {1} | 0 | 開始 |
 | 1 | [0] | {0} | 1 | 最初の作戦 |
 | 2 | [1] | {1} | 0 | 2番目の作戦 |

 これは、MEX が 2 つの値の間で切り替わる、小さな配列の循環動作を示しています。
