 ## 解決策
 ## 問題の理解

 私たちには一連のクエストが与えられており、それぞれのクエストは、繰り返されるゲーム 1 日内の特定の時間にのみ完了できます。 一部のクエストは他のクエストに依存しているため、前の特定のクエストが完了するまで完了できません。 時間は不連続な時間単位で進み、その日の最後の時間が経過すると、次の日は 0 時に始まります。私たちは、最初のクエストと最後のクエストを完了するまでの合計経過時間を最小限に抑えるために、すべてのクエストを有効な順序でスケジュールするという任務を負っています。 

入力は複数のテスト ケースで構成されます。 各テスト ケースはクエストの数を指定します`n`、依存関係の数`m`、そして一日の長さ`k`。 各クエストには利用可能な時間が固定されています`h_i`で`[0, k-1]`、依存関係はペアとして与えられます`(a_i, b_i)`、クエストを意味します`b_i`後のみ行うことができます`a_i`。 

制約とは、次のことを意味します。`n`すべてのテスト ケースで 200,000 に達する可能性があります。 テスト ケースあたりの複雑さが O(n log n) より悪いアルゴリズムは、遅すぎる可能性があります。 さらに、時間の剰余の性質は、日の折り返しを考慮して慎重に調整しないと、単純に時間の減算を行うとマイナスの期間を生じる可能性があることを意味します。 これを小さな例で説明します。18 時間目のクエストが 2 時間目のクエストに依存している場合、単純な差 2-18 = -16 は無効です。 翌日を考慮した場合の正しい経過時間は 8 時間です。 

エッジケースには、同じ時間に実行できるクエスト、長いチェーンを形成する依存関係、および大規模な依存関係が含まれます。`k`単純なモジュロ計算を誤解させる可能性のある値。 たとえば、すべてのクエストが同じ時間に発生しているが、依存関係チェーン内にある場合、合計経過時間は次のようになります。`k`ゼロではなく、必要な日数の倍です。 

## アプローチ

 ブルート フォース アプローチでは、クエストのすべてのトポロジー的順序を試し、それぞれの合計経過時間を計算します。 これは正しいですが、実行不可能です。`n!`トポロジカルな順序。 利用可能な最も早い時間を貪欲に選択して最適化を試みたとしても、モジュロ日の長さと依存関係を慎重に処理する必要があります。 直接シミュレーションでは、依存関係のチェーンの最悪の場合、O(n²) がかかります。 

重要な洞察は、この問題が有向非巡回グラフ (DAG) 上の動的プログラミングによるグラフ問題に還元できるということです。 各クエストはノードであり、依存関係はエッジを形成します。クエストの最も早い完了時間は、すべての先行クエストの完了時間の最大値に、モジュロ日の制約により必要な待ち時間を加えたものとして表現できます。 

正式に定義すると、`dp[u]`最初に完了したクエストから完了するまでの最短経過時間`u`。 依存関係の場合`v -> u`、時間増分は`(h_u - h_v + k) % k`時間の折り返しを考慮するため。 それから`dp[u] = max(dp[v] + (h_u - h_v + k) % k for all predecessors v)`。 DAG をトポロジ順に処理すると、答えは次のようになります。`max(dp)`。 

これにより、潜在的に階乗問題がすべてのエッジにわたる線形パスに変換され、テスト ケースごとに O(n + m) の複雑さが与えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのトポロジー次数) | お(ん!) | O(n + m) | 遅すぎる |
 | トポロジカルソートを使用した DAG + DP | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 依存関係を表すグラフを作成します。 クエストごとに、それに依存するクエストのリストを維持します。 
2. 各ノードの入次数を計算して、依存関係のないクエストを特定します。 
3.初期化`dp[u] = 0`すべてのクエストに。 これはクエストに到達するまでの最小経過時間を表します`u`いくつかの開始クエストから。 
4. キューを使用して、次数 0 のすべてのノードから開始してトポロジカル ソートを実行します。 
5. キューが空でない間にノードをポップします`u`。 依存クエストごとに`v`:

 - 時差を計算します`(h[v] - h[u] + k) % k`。 これは、モジュロ日ラップを考慮した最小待ち時間を表します。 
- アップデート`dp[v] = max(dp[v], dp[u] + (h[v] - h[u] + k) % k)`。 
- の入次数を減らす`v`。 ゼロになった場合はキューにプッシュします。 
6. すべてのノードが処理されると、答えは次のようになります。`max(dp)`。 

機能する理由: トポロジカルな並べ替えにより、すべてのクエストはその先行するすべてのクエストの後で処理されます。 DP の繰り返しにより、任意の開始点から各クエストに到達するために必要な最小限の時間が正しく累積され、モジュロ調整により時間が正しくラップアラウンドされるようになります。 全体的に最大限のことを考える`dp`値は、最適なスケジュールの最初のクエストから最後のクエストまでの合計経過時間をキャプチャします。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        h = list(map(int, input().split()))
        g = [[] for _ in range(n)]
        indeg = [0] * n
        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            indeg[b] += 1

        dp = [0] * n
        queue = deque([i for i in range(n) if indeg[i] == 0])
        while queue:
            u = queue.popleft()
            for v in g[u]:
                delta = (h[v] - h[u] + k) % k
                dp[v] = max(dp[v], dp[u] + delta)
                indeg[v] -= 1
                if indeg[v] == 0:
                    queue.append(v)
        print(max(dp))

solve()
```コードは、入力を読み取り、DAG を構築することから始まります。 の`dp`配列には、各クエストの最も早い経過時間が格納されます。 トポロジカルな並べ替えにより、依存関係が確実に尊重されます。 エッジごとに、日の折り返しを正しく処理するためにモジュロ差が計算されます。 これにより、依存するクエストがその日の早い時間に発生した場合でも、次の日がカウントされることが保証されます。 

## 実用的な例

 サンプル 1、最初のテスト ケース:```
n=4, k=24
h=[12,16,18,12]
dependencies: 1->2, 1->3, 2->4, 3->4
```| クエスト | dp[u] | 計算 |
 | --- | --- | --- |
 | 1 | 0 | 開始ノード |
 | 2 | 4 | 0 + (16-12) |
 | 3 | 6 | 0 + (18-12) |
 | 4 | 12 | max(4 + (12-16+24)%24=4+20=24, 6 + (12-18+24)%24=6+18=24)=24 |

 最大`dp`は24です。 

サンプル 2、3 番目のテスト ケース:```
n=2, k=10
h=[5,5]
dependencies: 1->2
```| クエスト | dp[u] | 計算 |
 | --- | --- | --- |
 | 1 | 0 | 開始ノード |
 | 2 | 0 | 0 + (5-5+10)%10 = 0 |

 最大`dp`は0です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各ノードはトポロジ順に 1 回処理され、各エッジは 1 つの DP 更新に貢献します。 
| スペース | O(n + m) | グラフ隣接リスト、次数配列、DP 配列 |
