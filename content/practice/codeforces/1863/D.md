 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$ボードは部分的にドミノで覆われています。 各ドミノは、水平方向または垂直方向に、ちょうど 2 つの隣接するセルを占有します。 一部のセルは空のままになる場合があります。 入力は、セルに垂直ドミノの場合は U/D、水平ドミノの場合は L/R としてラベルを付けることにより、各ドミノをエンコードします。 空のセルは次のようにマークされます。`.`。 

このタスクは、各ドミノに黒 (B) と白 (W) の 2 色で色を付け、各ドミノに黒と白のセルが 1 つずつあるようにすることです。 さらに、色付けはバランス条件を満たす必要があります。つまり、すべての行に同じ数の黒と白のドミノ セルがあり、各列にも同じ数が当てはまらなければなりません。 ドミノで覆われていないセルは、これらのカウントでは無視されます。 

制約は、ソリューションが高速である必要があることを意味します。 すべてのテスト ケースにわたるセルの総数は最大 250,000 であり、上記のいずれのソリューションも有効であることを示唆しています。$O(n \cdot m)$テストケースごとに安全ではありません。 ブルートフォースカラーリングやドミノカラーのすべての並べ替えを試みると、指数関数的に遅くなります。 また、完全に空の行、バランスが取れない奇数の長さの行または列を含むボード、バランスのとれた色付けが不可能になるドミノがサイクルを形成するボードなど、エッジ ケースも考慮する必要があります。 

列パリティを考慮せずにドミノを行ごとに貪欲に色付けする不注意なアプローチは、次のような場合には失敗します。```
2 2
LR
LR
```ここで、最初の行を B/W、W/B に色付けすると、各列に同じ色の 2 つのセルがあるため、2 行目のバランスが崩れます。 アルゴリズムは行と列のバランスを同時に調整する必要があります。 

## アプローチ

 素朴なアプローチはすべてを試すことです$2^k$黒/白の色を割り当てる方法$k$ドミノを作成し、行と列の数がバランスが取れているかどうかを確認します。 これは明らかに実行不可能ですので、$k$まで可能です$n \cdot m / 2 \approx 125,000$最悪の場合でも均衡を保つ$O(2^{20})$大きすぎる。 

重要な洞察は、これを **グリッド上の 2 部構成の色付け問題**として見ることです。 ボードのチェッカーボードの色を考えてみましょう。セルに黒と白を交互に色付けします。 各ドミノでは、チェッカーボードでは常に異なる色である 2 つの隣接するセルがカバーされます。 このグローバル チェッカーボード パターンにドミノを割り当てると、ドミノ制約が自動的に満たされます。 

ただし、行と列のバランス要件によりパリティ条件が課されます。 奇数のドミノ セルが含まれる行は、セルの半分が黒、半分が白である必要があるため、バランスをとることができません。 したがって、各行と各列には偶数のドミノ セルが含まれている必要があります。 これは、色付けする前のローカル実行可能性チェックです。 

実現可能性が確認されたら、チェッカーボード パターンに沿ってボードを貪欲に埋めていくことができます。 水平ドミノの場合は、左から右または右から左に色を割り当てます。 垂直ドミノの場合は、上から下または下から上に割り当てます。 これにより、ドミノとチェッカーボードの両方の制約が自然に満たされます。 チェッカーボードの色付けによって行または列の不均衡が生じた場合は、その行または列のローカル ドミノの色付けを交換してパリティを修正できます。 偶数のみが表示されるため、これらの交換はいつでも可能です。 

これにより、問題がすべてのセルにわたる線形スキャンに縮小され、アルゴリズムが次のようになります。$O(n \cdot m)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(n*m) | 遅すぎる |
 | チェッカーボード + パリティ チェック | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボードをスキャンして、各行と列のドミノ セルの数を数えます。 行または列に奇数のドミノ セルが含まれている場合、出力`-1`すぐに。 奇数のカウントを白と黒に均等に分けることはできません。 
2. 同じサイズの空のボードを初期化して、答えを保存します。 
3. すべてのドミノを繰り返します。 水平ドミノ (L/R) の場合、行インデックスに基づいて色を決定します。行インデックスが偶数の場合は、左のセルを白、右のセルを黒にします。 奇数の場合は、色を反転します。 垂直ドミノ (U/D) の場合も、列インデックスを同様に使用します。列インデックスが偶数の場合は、上部のセルを白、下部のセルを黒にします。 奇数の場合は反転します。 
4. 空のセルを次のように入力します。`.`to preserve the input structure.
 5. ボードを出力します。 すべての行と列に偶数のドミノ セルがあることを確認したため、上記の色分けはすべてのバランス条件を満たします。 

**機能する理由**: 各ドミノには反対色のセルがあり、ドミノの状態が保証されます。 パリティベースの割り当てにより、すべての行と列に同じ数の黒と白のセルが含まれることが保証されます。 すべての行数と列数が偶数であるため、チェッカーボードの交互により常に有効な解を生成できます。 このグローバルなパリティにより、ドミノ内で色を交換しても他のドミノのバランスが崩れることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        board = [list(input().strip()) for _ in range(n)]
        ans = [['.']*m for _ in range(n)]
        
        row_domino_count = [0]*n
        col_domino_count = [0]*m
        
        for i in range(n):
            for j in range(m):
                if board[i][j] != '.':
                    row_domino_count[i] += 1
                    col_domino_count[j] += 1

        if any(x % 2 != 0 for x in row_domino_count) or any(x % 2 != 0 for x in col_domino_count):
            print(-1)
            continue

        for i in range(n):
            for j in range(m):
                cell = board[i][j]
                if cell == 'L':
                    if i % 2 == 0:
                        ans[i][j] = 'W'
                        ans[i][j+1] = 'B'
                    else:
                        ans[i][j] = 'B'
                        ans[i][j+1] = 'W'
                elif cell == 'U':
                    if j % 2 == 0:
                        ans[i][j] = 'W'
                        ans[i+1][j] = 'B'
                    else:
                        ans[i][j] = 'B'
                        ans[i+1][j] = 'W'

        for row in ans:
            print(''.join(row))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず行および列ごとにドミノ セルをカウントします。 奇数のカウントは直ちに不可能を示します。 次に、行と列のパリティを使用してドミノに色を付けます。 水平ドミノは行ごとに色を反転し、垂直ドミノは列ごとに色を反転します。 これにより、各行と列の黒と白のセルのバランスが自動的に保たれます。 空のセルはそのまま残ります。
