 ## 問題の理解

 サイズの順列を形成する整数のシーケンスが与えられます。$n$。 このタスクは、残りのサフィックス内の最小要素を見つけて、それを正しい位置に配置するセグメントを反転することによって、配列を左から右に繰り返し「固定」する決定論的プロセスをシミュレートすることです。 

より具体的には、最初の位置から始めて、各ステップで現在のインデックスから始まる部分配列を調べ、そのサフィックス内の最小要素がどこにあるかを見つけ、そのセグメント全体を反転し、反転したセグメントの長さに等しいコストを累積します。 最終的な答えは、最後のポジションを除くすべてのポジションを処理した後の合計コストです。 

入力サイズの制約は、配列が十分な大きさになる可能性があることを意味しており、各ステップでのスキャンと反転による最小値の単純な繰り返し検索は慎重に処理する必要があります。 スキャンして反転する単純な実装は、ステップごとにすでに線形であり、全体として二次的な動作につながります。 これは次の場合にのみ許容されます。$n$周りにいる$10^3$、しかしそれを超えると失敗します。 問題の構造は意図的に操作が単純になっていますが、サフィックスを最小限に抑えたクエリが繰り返されることでパフォーマンスのボトルネックが決まります。 

正確さのためには、いくつかの特殊なケースが重要です。 配列がすでにソートされている場合、各ステップでは現在の要素が最小値として選択され、意味のある逆転は起こりませんが、コストは依然として自明なセグメントの長さとして蓄積されます。 たとえば、入力の場合`[1, 2, 3]`、配列が目に見えて変化しない場合でも、各ステップは依然としてコストに寄与します。 

もう 1 つの微妙なケースは、最小要素がすでに現在の位置にある場合です。 不注意な実装では、反転をスキップしたり、コストの追加をスキップしたりする可能性がありますが、正しい動作には、長さ 1 のセグメントの反転が含まれており、コスト 1 が寄与します。 

## アプローチ

 ブルート フォース シミュレーションは、説明どおりのプロセスに従います。 ポジションごとに$i$、サフィックスをスキャンします$i \ldots n$最小要素のインデックスを見つけるには、部分配列を逆にします。$i$そのインデックスにセグメントの長さを答えに追加します。 各ステップにはリニア スキャンが必要です。$n$ステップが増えるため、全体の複雑さは次のようになります。$O(n^2)$。 これは次の場合に機能します$n$は小さいですが、次の場合はすぐに遅くなりすぎます$n$数千を超えて増加します。 

重要な点は、この問題では動的更新のために高度なデータ構造を維持する必要がないことです。 反転により配列は変化しますが、各ステップで考慮するのは、残りのサフィックスの最小値の位置だけです。 プロセスは固定されており順次的であるため、このバージョンでは最適化を行わなくても、ステップごとに線形時間で直接シミュレーションできます。これは、意図したサブタスク A1 に対して制約が十分に小さいためです。 

したがって、最適な解決策は、同じシミュレーションを、慎重なスライスまたはインプレース反転によってクリーンに実装することです。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 実行総コストをゼロに初期化して開始します。 これにより、各反転ステップのコストが累積されます。 
2. 配列を最初の位置から最後から 2 番目の位置まで繰り返します。 各インデックスで$i$、最終的な並べ替え順序でその位置に正しい要素を配置しようとしています。 
3. 現在のインデックスの場合$i$、サフィックスをスキャンします$i \ldots n-1$位置を見つけるために$j$最小限の要素です。 このステップでは、所定の位置に移動する必要がある要素を特定します。$i$リバースソートの法則によると。 
4. コスト寄与度を次のように計算します。$j - i + 1$、それは反転されるセグメントの長さであるためです。 この値を合計コストに加算します。 
5. サブ配列を元に戻す$i$に$j$所定の位置にあります。 これにより、最小要素がインデックスに正しく配置されるようになります。$i$、前に位置する不変式を保持します。$i$はすでに修正されています。 

すべてのインデックスを処理した後、累積コストが返されます。 

### なぜ効果があるのか

 あらゆる段階で$i$、アルゴリズムにより、プレフィックスが$[0, i]$正しい最小の残りの要素が順番に含まれているという意味でソートされます。 反転操作は任意ではありません。 これは、最小要素を位置に移動する唯一の操作です。$i$そして、後のステップに必要な相対的な順序が保持されます。 各ステップは厳密にもう 1 つの位置を固定し、以前に固定された位置を決して妨げないため、プロセスは正確に終了する必要があります。$n-1$完全にソートされた配列を含むステップ。 コストは選択したセグメントの長さによって一意に決定されるため、累積合計は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    total = 0
    
    for i in range(n - 1):
        j = i
        for k in range(i, n):
            if a[k] < a[j]:
                j = k
        
        total += (j - i + 1)
        a[i:j+1] = reversed(a[i:j+1])
    
    print(total)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに正確に従います。 外側のループは各位置を 1 つずつ固定します。 内側のループは、残りのサフィックスの最小要素を見つけます。 スライスの逆転`a[i:j+1] = reversed(...)`必要な操作を直接実行し、次のような場合を含むすべてのケースを安全に処理します。`i == j`ここで、セグメントの長さは 1 で、配列は変更されませんが、依然としてコストに影響します。 

よくある落とし穴は、最小値がすでに設定されているときにコストを含めることを忘れることです。`i`。 コードでは常に追加することでこれを回避します。`j - i + 1`反転が視覚的に意味があるかどうかは関係ありません。

 ## 特殊なケース

 次のような単一要素配列の場合`[1]`の場合、ループは実行されないため、合計コストはゼロのままです。 反転するセグメントがないため、これは正しいです。 

すでにソートされている配列の場合、次のようになります。`[1, 2, 3, 4]`、各ステップでは現在のインデックスが最小値として選択されます。 目に見える変化は発生しませんが、各反転の長さは 1 であるため、コストは次のように累積します。$n - 1$。 アルゴリズムは反転ステップを決してスキップしないため、これらの寄与が正しく含まれます。 

次のような反転配列の場合`[4, 3, 2, 1]`、各ステップで次に小さい要素が端から前方に引っ張られ、最大量の動きが生成されます。 この実装は、古い構造に依存するのではなく、常に現在のサフィックスの最小値を再計算するため、これを引き続き正しく処理します。
