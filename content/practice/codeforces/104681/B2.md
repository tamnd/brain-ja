 ## 解決策
 ## 問題の理解

 3 種類の文字で構成される文字列が与えられます。`C`、`J`、 そして`?`。 この文字列は、それぞれに次のいずれかを割り当てる必要がある一連の位置を表します。`C`または`J`、 どこ`?`ポジションは未定で自由に選べます。 

最終文字列が次から切り替わるたびにコストが発生します。`C`に`J`またはから`J`に`C`。 さらに、`?`どちらの文字を使用しても、最終的にそのようなスイッチがいくつ出現するかに影響するため、目標はそれぞれのスイッ​​チを割り当てることです。`?`最終的に完全に解決された文字列全体の移行コストの合計を最小限に抑えるために最適化されます。 

具体的には、全て交換した後、`?`、左から右にスキャンし、隣接する 2 つの文字が異なるたびにコストを支払います。 の費用`CJ`移行は`X`、および のコスト`JC`移行は`Y`。 

タスクは、結果として生じる総コストが可能な限り小さくなるように、すべての未知のポジションの代替を選択することです。 

入力サイズは、長い文字列を処理する必要がある可能性があることを暗示しており、テスト ケースごとに最大で大きな線形サイズに達する可能性があります。 これにより、すべての割り当てを試みるアプローチは即座に除外されます。`?`、それぞれから`?`検索スペースが 2 倍になり、指数関数的な動作が発生します。 文字列の長さが数十万に達すると、位置のペアに対する二次動的計画法でも速度が遅すぎます。 

微妙な問題が現れるのは、`?`長く連続したブロックに出現します。 たとえば、次のことを考えてみましょう。```
C???J
X = 5, Y = 2
```「全部埋める」みたいな欲張りな決断`?`最も近い既知の近隣を使用する」は、境界で単一の遷移を作成するか、内部で複数の遷移を回避するかによって、最適なグローバルな選択が依存する可能性があることを無視するため、失敗する可能性があります。 

もう 1 つの注意が必要なケースは、文字列が次で始まるか終わる場合です。`?`、 例えば：```
???CJ
```未知のブロック内のローカル遷移のみを最適化する単純なアプローチでは、最初のブロックを完全に正しい境界に位置合わせして余分な遷移を回避できるという事実を見落とす可能性があります。 

これらの問題は、ローカルでの貪欲な決定が十分ではないことを示しています。 各位置での選択は、構造化された方法で前の文字に依存します。 

## アプローチ

 強引なアイデアは単純明快です。すべてを扱います。`?`どちらかとして`C`または`J`、考えられるすべての文字列を生成し、それぞれの移行コストを計算し、最小値を取得します。 これは、近似を行わずに完全な解空間を探索するため、正しいです。 

ただし、ある場合は、`k`疑問符、これにより生成されます`2^k`構成。 たとえ`k = 30`、これはすでに 10 億の可能性を超えており、典型的な制約では`k`が文字列全体の長さに比例する場合、このアプローチは不可能になります。 

重要な観察は、コストは隣接するペアにのみ依存するということです。これは、決定が左から右に線形に伝播することを意味します。 各位置で唯一関連する状態は、前に選択した文字が何であったかです。 これにより、グローバル構造が小さな状態遷移問題に縮小されます。 

すべての割り当てを試す代わりに、2 つの可能性の下で各ポジションまでの最小コストを維持します。現在のキャラクターは`C`または`J`。 既知の文字を処理する場合、状態は固定されます。 私たちが処理するとき、`?`、両方のオプションを考慮し、最適なコストを前方に伝播します。 これにより、問題は文字列に対する単純な動的プログラミングに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k · n) | O(n) | 遅すぎる |
 | 州を越えたDP | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の位置が次で終わる場合の最小コストを追跡しながら、文字列を左から右に処理します。`C`またはで終わる`J`。 

1. 2 つの変数を初期化する`dpC`そして`dpJ`最後の文字が次の場合、現在位置までの最小コストを表します。`C`または`J`それぞれ。 個別に処理される最初の位置を除き、最初は無限大に設定します。 
2. 最初の文字が固定されている場合 (`C`または`J`)、その状態にコスト 0 を割り当て、その他の状態に無限を割り当てます。 もしそうなら`?`、コスト 0 の両方の状態を許可します。 
3. 次の文字ごとに、新しい値を計算します。`nextC`そして`nextJ`。 現在のキャラクターが`C`、 それから`nextC`以前からの拡張の最小値です`C`（追加料金なし）そして以前から`J`(追加コスト`Y`なぜなら`J -> C`）。 そのキャラクターが`J`、対称ロジックはコストとともに適用されます`X`のために`C -> J`。 そのキャラクターが`?`、私たちは両方の可能性を、それが可能であるかのように評価します。`C`または`J`そして最高のものを手に入れましょう。 
4. キャラクターを加工した後、更新します`dpC = nextC`そして`dpJ = nextJ`。 
5. 最終的な答えは次のとおりです。`min(dpC, dpJ)`。 

重要な点は、キャラクターが隣接する位置間で変化するときの移行コストを常に考慮していることです。 DP 状態により、以前のキャラクター選択を見失うことがなくなります。 

### なぜ効果があるのか

 DP 状態は、将来の決定に影響を与えるすべての情報を取得します。将来の移行コストに影響するのは、最後に選択された文字のみです。 同じ最後の文字で終わり、異なる内部履歴を持つ 2 つの部分解は、累積コストを除き、将来の決定に対して同等です。 したがって、終了文字あたりの最小コストのみを維持することで、最適性が維持されます。 これは標準的な最適な部分構造の議論です。固定された最後の文字と組み合わせたプレフィックスの最適な解決策は、以前の構造を再検討する必要がなく、常に最適に拡張できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    X, Y = map(int, input().split())
    s = input().strip()
    
    dpC, dpJ = INF, INF
    
    # initialize first character
    if s[0] == 'C':
        dpC, dpJ = 0, INF
    elif s[0] == 'J':
        dpC, dpJ = INF, 0
    else:
        dpC, dpJ = 0, 0
    
    for i in range(1, len(s)):
        c = s[i]
        nextC, nextJ = INF, INF
        
        if c == 'C' or c == '?':
            # end in C
            nextC = min(
                dpC,          # C -> C
                dpJ + Y       # J -> C
            )
        
        if c == 'J' or c == '?':
            # end in J
            nextJ = min(
                dpJ,          # J -> J
                dpC + X       # C -> J
            )
        
        dpC, dpJ = nextC, nextJ
    
    return min(dpC, dpJ)

def main():
    t = int(input())
    for i in range(t):
        print(solve())

if __name__ == "__main__":
    print(main())
```DP は反復的に実装され、テスト ケースごとに 2 つのスカラーのみを保持します。 初期化ステップは非常に重要です。`?`最初はペナルティなしで両方の状態を許可します。 

よくある実装上の間違いは、遷移が方向に依存することを忘れることです。`C -> J`コストを使用します`X`、 その間`J -> C`コストを使用します`Y`。 これらをサイレントに交換すると、DP 構造が正しいままであっても、間違った答えが生成されます。 

## 実用的な例

 ### 例 1

 入力:```
1
2 3
CJ?C
```私たちは追跡します`(dpC, dpJ)`。 

| 私 | 文字 | dpC | dpJ | 説明 |
 | --- | --- | --- | --- | --- |
 | 0 | C | 0 | インフ | 固定スタート |
 | 1 | J | 2 | 0 | C→Jのコストは2 |
 | 2 | ? | 2 | 0 | 州ごとに最適なものを選択する |
 | 3 | C | 2 | 3 | J→C コスト 3 |

 最終的な答えは 2 です。 

これは、`?`すぐに選択を強制するものではありません。 将来のコンテキストによって最適な継続が解決されるまで、両方の可能性が保持されます。 

### 例 2

 入力:```
1
4 1
?J?C
```| 私 | 文字 | dpC | dpJ | 説明 |
 | --- | --- | --- | --- | --- |
 | 0 | ? | 0 | 0 | 両方許可 |
 | 1 | J | インフ | 0 | J で終わるか、C からのコストが必要です |
 | 2 | ? | 1 | 0 | J を拡張するか切り替える |
 | 3 | C | 1 | 1 | 選択された最適なアライメント |

 このケースは、非対称性がどのようなコストをもたらすかを示しています (`X ≠ Y`）以前に影響を与える`?`将来の移行を通じて決定を下します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

このアルゴリズムは、文字ごとに一定量の作業を実行するため、合計入力サイズが大きい場合でも制限内に快適に収まります。

def run(inp: str) -> str:

    INF = 10**30

    def solve():
        X, Y = map(int, input().split())
        s = input().strip()
        dpC, dpJ = INF, INF
        
        if s[0] == 'C':
            dpC, dpJ = 0, INF
        elif s[0] == 'J':
            dpC, dpJ = INF, 0
        else:
            dpC, dpJ = 0, 0

 ## 特殊なケース

 先頭または末尾のブロック`?`最初の文字が不明な場合は両方の状態が最初に許可されるため、DP によって自然に処理されます。 のような入力の場合`???C`、DP は両方の状態のコストがゼロで開始され、強制`C`最後に状態を正しく折りたたみ、必要な遷移のみを蓄積します。 

各ステップでは常に両方向が明示的に考慮されるため、高い遷移コストと低い遷移コストが交互に起こる文字列でもアルゴリズムが壊れることはありません。 たとえ一方向の方が大幅に安くなったとしても、DP はさらに悪化することが判明するまで代替状態を保持します。 

単一文字の文字列または完全に未知の文字列には遷移がなく、隣接するペアが存在しないため、DP は正しくゼロを返します。
