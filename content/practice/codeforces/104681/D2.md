 ## 解決策
 ## 問題の理解

 2 つのシーケンスが与えられており、それぞれすでに非降順でソートされています。 どちらのシーケンスも奇数の長さです。 目標は、それらを直接並べ替えることではなく、2 つのシーケンスが同一になるまで、どちらかのシーケンスに非常に特殊な変換操作を繰り返し適用することです。 

1 つの操作で、単一のシーケンスを選択し、その要素の奇数サイズのサブセットを選択し、その選択したサブセットの中央値を計算し、選択したすべての要素を削除して、その中央値を同じシーケンス内の任意の場所に挿入し直すことができます。 サブセットのサイズが奇数であるため、中央値は常に明確に定義され、選択された要素に属します。 

本当に難しいのは、この操作でどのような種類の変換が可能になるかを理解することです。 値を恣意的に並べ替えることはありませんが、再挿入後に並べ替えられた性質を維持しながら、複数の値を 1 つの代表値 (中央値) にまとめることができます。 これにより、複数の操作にわたって、特定の順序統計を安定に保ちながら、配列の一部を効果的に「圧縮」できます。 

出力は、どちらかの配列に独立してこのような操作を任意の数だけ適用した後、2 つの配列を同一にすることができるかどうかだけです。 

制約は全体として大きく、合計入力サイズは最大約 3×10^5 になります。 これにより、テスト ケースごとに二次関数が除外されます。 各操作自体が本質的に組み合わせである可能性があるため、操作を明示的にシミュレートしたり、サブセットを探索したりするアプローチは、直ちに実行不可能になります。 

微妙なエッジ ケースは、配列がすでに一致しているか、サイズのみが異なる場合です。 たとえば、1 つの配列が`[1,3,5]`そしてもう一つは`[1,3,5,7,9]`、素朴な直感では、いつでも大きい方を「縮小」できると思われるかもしれませんが、この操作では中央値の構造が維持され、恣意的な削除は許可されません。 答えは長さだけに基づいているのではなく、以下に説明する構造上の不変条件に基づいています。 

もう 1 つの特殊なケースは、値が繰り返されることです。 中央値はマルチセットに渡って取得されるため、重複が予期せず崩壊する可能性があり、そのため、区別性の仮定に依存するソリューションは失敗します。 例えば、`[1,2,2,3,4]`～とは異なる動作をする`[1,2,3,4,5]`両方とも奇数長のソートされた配列であっても、メディアン圧縮が行われます。 

## アプローチ

 ブルートフォースの観点は、操作をシミュレートすることです。 すべての奇数のサブセットを試し、中央値を計算し、変換を適用して、両方の配列を等しくする一連の操作を検索することができます。 単一の操作に制限するだけでも、すでに指数関数的に多くのサブセットを列挙する必要があります。 各状態は多くの新しい状態に分岐し、値を任意の位置に再挿入できるため、メモ化しても状態空間は制御不能に拡大します。 

重要な洞察は、操作が実際には位置には依存せず、マルチセット構造と中央値の動作のみに依存するということです。 中央値は奇数セットの安定した代表値であり、中央値の置換を繰り返すとグローバル順序制約が維持されます。つまり、奇数のサブセットの中央値はそのサブセットの最小値と最大値の間になければなりません。さらに重要なことに、繰り返し適用しても元の配列の凸包の外側に値を作成することはできません。 

このことから、問題は、中央値の削減の下でどの値が「安定」するかという推論に集約されます。 サブセットを繰り返し選択して中央値で置き換えるという観点から考えると、考えられるすべての削減を生き残った値は、全体的な意味で中央値のように動作する必要があることがわかります。 これにより、最終的に到達可能な配列は、すべての要素が元の配列に対する分割構造の中央値として機能する値に対応するシーケンスとして表現可能でなければならないという不変条件が得られます。 

重要な簡略化は、両方の配列がソートされ、操作によって順序の一貫性が維持されるため、意味のある情報はプレフィックスとサフィックスの中央値に対して値がどのように分布するかということだけです。 これにより、問題は両方の配列が同じ「メディアン閉包」を共有するかどうかをチェックすることになり、実際には、奇数グループの崩壊が繰り返された場合に達成可能な安定したメディアンの同じセットを生成するかどうかをチェックすることになります。 

構造を確認する直接的な方法は、奇数セグメントを中央値で繰り返し置き換える効果をシミュレートすることです。このプロセスは、要素のマルチセットとその中央値階層のみに依存する標準形式に収束します。 2 つの配列は、それらの正準中央値削減形式が同一である場合に限り、等しくなります。

 ## アルゴリズムのチュートリアル

 1. 各配列を独立して処理し、奇数グループのメディアン圧縮が繰り返された場合に値がどのように動作するかをシミュレートすることによって、そのメディアン階層を計算します。 目的は、任意の有効な操作の後にどの要素が「アンカー」として存続できるかを理解することです。 
2. 配列を繰り返し縮小することによって正規表現を構築します。各段階で、概念的に要素を奇数サイズのブロックにグループ化し、それらを中央値で置き換えます。 明示的にグループ化するのではなく、唯一の永続的な構造は、値が部分範囲の全体的な中央値および再帰的に相対的な中央値に対してどのように配置されるかによって決定されることが観察されます。 
3. 構造にさらなる変化が生じなくなるまで、この概念の縮小を続けます。 結果として得られる固定小数点は、許可された操作の下での配列の正規形式です。 
4. 2 番目のアレイに対しても同じ構築を実行します。 
5. 2 つの標準形式を比較します。 完全に一致する場合はYESを出力し、そうでない場合はNOを出力します。 

この手順が有効である理由は、許可されたすべての操作が同じ中央値削減等価クラスのメンバーシップを保持するためです。 逆に、一連の操作は、配列をこの標準構造に徐々に折りたたむものとして解釈できます。そのため、2 つの配列は、同じ固定点を共有する場合に限り、相互に変換可能です。 

### なぜ効果があるのか

重要な不変条件は、すべての操作で奇数サイズのマルチセットがその中央値で置き換えられ、中央値がネスト下でも安定していることです。奇数のグループの中央値の中央値は、正しく構造化されている場合、結合の中央値と一致します。 これにより、2 つの配列が同じメディアン リダクション固定点に変換できる場合に等価であるという配列上の等価関係が生じます。 演算では元の順序制約の外に値を導入することはできず、常に中央値の階層が維持されるため、固定小数点は各同値クラスに対して一意であり、有効な標準署名になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def canonical(arr):
    """
    Compute a stable signature of the array under repeated odd-median reductions.
    We simulate the structural effect by repeatedly compressing triples, which
    is sufficient because any odd subset can be decomposed into chained triples
    without changing the median propagation behavior.
    """
    a = arr[:]
    
    # Repeated compression until stable
    while len(a) > 1:
        b = []
        i = 0
        n = len(a)
        
        while i < n:
            # take blocks of size 3 where possible
            if i + 2 < n:
                x, y, z = a[i], a[i+1], a[i+2]
                b.append(sorted((x, y, z))[1])
                i += 3
            else:
                # leftover elements move up unchanged
                b.extend(a[i:])
                break
        
        if b == a:
            break
        a = b
    
    return tuple(a)

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    print("YES" if canonical(a) == canonical(b) else "NO")

if __name__ == "__main__":
    solve()
```この実装では、ローカルの 3 の中央値演算を使用して配列を繰り返し圧縮することにより、固定小数点を構築します。 これは、サブセットを列挙せずに奇数中央値の動作をエミュレートする標準的な方法です。 ソートされたトリプル メディアンはグローバル メディアン操作の局所的な類似物であり、繰り返し適用すると安定した構造に収束します。 

最後に比較すると、両方の配列が同一の構造に折りたたまれるかどうかがチェックされます。 すべての操作でこの構造が維持されるため、署名が等しいことが必要かつ十分です。 

反復ロジックには注意が必要です。各パスの最後の 1 つまたは 2 つの要素はトリプルを形成できないため、変更せずに繰り越す必要があります。そうしないと、パリティ構造が壊れ、プロセスが誤ってドリフトする可能性があります。 

## 実用的な例

 2 つの配列を考えてみましょう`[1, 2, 3, 4, 5]`そして`[1, 3, 7]`。 

最初の配列の最初の圧縮ステップでは、トリプルを取得します。`(1,2,3)`生産する`2`、 そして`(4,5)`が引き継がれます。 配列は次のようになります`[2, 4, 5]`。 次のステップで生成されるのは、`(2,4,5) -> 4`、出発`[4]`。 したがって、その標準形式は次のようになります`[4]`。 

2 番目の配列の場合、`(1,3,7) -> 3`、したがって、それはまた次のように直接的に減少します`[3]`。 これは異なる固定点を示しているため、同等ではありません。 

| ステップ | 配列 A | 配列 B |
 | --- | --- | --- |
 | 開始 | [1,2,3,4,5] | [1,3,7] |
 | 1以降 | [2,4,5] | [3] |
 | アフター2 | [4] | [3] |

 このトレースは、プロセスが単一の代表的な中央値のような値に向けてどのように構造を積極的に崩壊させるのか、そしてなぜ分布が異なると異なる固定点が生じるのかを示しています。 

次に、同一の配列を考えます。`[1,3,5]`そして`[1,3,5]`。 どちらもすぐに次のように減少します`[3]`、同一のメディアン構造が同一の標準形式を生成することを確認しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列のサイズがすでに 1 である場合です。その状況では演算は不可能であるため、等価性は直接比較に帰着します。 アルゴリズムの標準形式はすぐに単一の要素自体になるため、それ以上削減することなく等価性が正しくチェックされます。 

もう 1 つのエッジ ケースは、配列が同じ中央値階層を維持しながら値の順列だけが異なる場合です。 生の値の位置が異なる場合でも、メディアン圧縮を繰り返すと位置情報が削除され、構造的なバランスのみが保持されるため、両方の配列が同じ固定小数点に折りたたまれ、正しく YES が返されます。 

最後のエッジケースは、中央値の選択を歪める重複値を除いて配列が同一である場合に発生します。 奇数のマルチセットの中央値は常に特定のランクを選択するため、重複によって削減プロセスが不安定になることはなく、圧縮は依然として決定論的に収束し、一貫した正規形式が保証されます。
