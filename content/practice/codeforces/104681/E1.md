 ## 解決策
 ## 問題の理解

 一連の参加者が多数の質問にどのように回答したかを説明する大きなバイナリ テーブルが与えられます。 各行は 1 人の参加者に対応し、各列は 1 つの質問に対応します。 参加者がその質問に正解した場合、セルは 1 になり、そうでない場合は 0 になります。 

すべての参加者のうち、ちょうど 1 人が他の参加者とは異なる行動をします。 残りは自然なパターンに従い、一部の質問は本質的に他の質問よりも簡単で、一部の参加者は他の参加者よりも強いため、正しさは行と列の構造の両方に影響されます。 特別な参加者はこの構造を無視します。参加者は、質問ごとに独立して、時には「普通に解決」し、時には常に答えを知っているかのように振る舞うため、質問の難易度に関しては本質的にランダムです。 

課題は、回答行列のみを使用して、この異常な参加者を特定することです。 

入力サイズが十分に大きいため、プレーヤーのすべてのペアを質問のすべてのペアと直接比較するアプローチは実行不可能になります。 参加者が約 100 人、質問が 10,000 件あるため、質問に対する 3 次または密な 2 次法でもすでに遅すぎます。 この構造は、質問ごと、プレーヤーごとの情報を小さな統計に圧縮し、それらの要約を使用してプレーヤーを比較する必要があることを示唆しています。 

単純な実装では、各参加者のスキルを明示的にモデル化したり、プレーヤーのすべてのペアと質問のすべてのサブセット間の相関関係を計算したりする可能性があります。 これはすぐに不安定になり、遅くなります。 

合計スコアだけを比較すると、微妙な失敗例が発生します。 たとえば、2 人のプレーヤーが両方とも 5000 問正解したとします。 1 つは強力で一貫性があり、もう 1 つはランダムですが、偶然同様の完全な正しさを持ちます。 純粋な合計ではそれらを区別できません。 質問の難易度を考慮せずに行ごとの分散のみを比較すると、別の失敗が発生します。列効果によって正規化しない場合、強いプレーヤーとランダムなプレーヤーは依然として似ている可能性があります。 

## アプローチ

 この強引なアイデアは、各プレーヤーがデータセットの「自然な構造」とどの程度一致しているかを直接測定することです。 1 つの方法は、質問の考えられるすべてのパーティションを簡単なセットと難しいセットに分けて試し、各プレーヤーがこれらのパーティション間でどのように行動するかを評価することです。 候補となる各パーティションについて、プレイヤーの成功率が 2 つのグループ間でどの程度異なるかを計算できます。 これは原理的には正しいです。実際のプレイヤーは相関するのに対し、チーターは難易度に相関しないからです。 

ただし、質問を分割できる数は列の数に応じて指数関数的に増加します。 バランスの取れた分割に限定したとしても、依然として膨大な組み合わせ探索空間に直面しています。 質問が 10000 件あると、これはまったく不可能です。 

重要な洞察は、実際には真の難易度構造を完全に発見する必要はないということです。 必要なのは、簡単な質問と難しい質問を区別する大まかな代理文だけです。 データ自体から問題の難易度を推定できれば、簡単な問題と難しい問題に対して各プレイヤーがどのように行動するかを比較することができます。 

質問の難易度を自然に見積もるのは、正解したプレイヤーの割合です。 多くのプレイヤーが解決した問題はおそらく簡単です。 少数の人で解決するのはおそらく難しいでしょう。 これにより、本当のスキルを知らなくても、質問をグローバルに順序付けることができます。 

この推定された難易度に従って質問が順序付けされると、各プレイヤーはその範囲全体でパフォーマンスが有意に変化するかどうかをテストできます。 実際のプレイヤーは、簡単な問題では成績が良く、難しい問題では成績が悪くなる傾向があり、難易度と正の相関関係が生じます。 異常な参加者は、難易度に関してランダムであり、簡単な質問と難しい質問の間にほとんど違いを示しません。

これにより、問題は 2 つの集約された質問グループに基づいてプレーヤーごとに 1 つのスコアを計算するという問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション検索 | 指数 | O(nm) | 遅すぎる |
 | 難易度の並べ替え + 分割比較 | O(nm log m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 生の行列を、各参加者が質問の難易度にどの程度一致しているかを捕捉する信号に変換します。 

1. 各列を合計し、参加者の数で割ることにより、各質問の正答率を計算します。 これにより、各質問の難易度が数値的に推定されます。 簡単な問題ほど頻繁に解決されるため、列の合計が高くなるという考えです。 
2. すべての質問を、この推定難易度に従って、最も簡単なものから最も難しいものへと並べ替えます。 これにより、スキルを明示的にモデル化することはありませんが、難易度の隠れた構造に近似するグローバルな順序付けが作成されます。 
3. 並べ替えた質問を 2 つに分割します。 前半は簡単な質問、後半は難しい質問を表します。 必要なのは方向性信号のみであり、正確なキャリブレーションは必要ないため、この粗い分割で十分です。 
4. 各参加者について、簡単な半分と難しい半分の成功率を別々に計算します。 これにより、参加者ごとに 2 つの値が得られます。1 つは簡単な質問でのパフォーマンスを説明するもの、もう 1 つは難しい質問でのパフォーマンスを説明するものです。 
5. 各参加者について、これら 2 つのレートの差を計算します。 通常の参加者は、より簡単な質問で成功する可能性が高いため、プラスの差が生じる傾向があります。 異常な参加者は、正しさが難易度に関連付けられていないため、差がゼロに近い傾向があります。 
6. 差の絶対値が最も小さい参加者を選択します。 

中心となる考え方は、質問の難易度に関して単調な行動からの逸脱を測定しているということです。 

### なぜ効果があるのか

 正答率マトリックスには隠れた構造が含まれています。質問の難易度は、通常の参加者のパフォーマンスに単調な傾向を引き起こします。 真のスキル値がわからなくても、列ごとの平均は多くの独立したベルヌーイ結果を集約しているため、この順序が高い確率で維持されます。 

通常の参加者の場合、質問のしやすさに応じて正解確率が高くなるため、2/2 の差はゼロから離れる方向に集中します。 異常な参加者にとって、正しさは質問のアイデンティティとは無関係であるため、両方の半分の期待成功率は本質的に同じになります。 これにより、それらの差がゼロ付近に集中し、他のすべてから区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = 100
    m = 10000
    
    a = [input().strip() for _ in range(n)]
    
    col_sum = [0] * m
    for i in range(n):
        row = a[i]
        for j, ch in enumerate(row):
            col_sum[j] += (ch == '1')
    
    idx = list(range(m))
    idx.sort(key=lambda j: col_sum[j])
    
    half = m // 2
    easy = idx[:half]
    hard = idx[half:]
    
    best_player = -1
    best_score = 10**18
    
    for i in range(n):
        row = a[i]
        
        easy_cnt = 0
        hard_cnt = 0
        
        for j in easy:
            if row[j] == '1':
                easy_cnt += 1
        
        for j in hard:
            if row[j] == '1':
                hard_cnt += 1
        
        easy_rate = easy_cnt / len(easy)
        hard_rate = hard_cnt / len(hard)
        
        diff = abs(hard_rate - easy_rate)
        
        if diff < best_score:
            best_score = diff
            best_player = i + 1
    
    print(best_player)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを直接反映しています。 列の合計は難易度を概算するために使用され、並べ替えにより安定した順序が生成されます。 次に、各プレーヤーは 2 つのハーフをスキャンすることによって評価されます。 唯一のデリケートな部分は、除算が浮動小数点で行われるようにすることです。 整数の除算はプレイヤー間の区別を消去します。 

インデックス付けも重要です。出力ではプレーヤーのインデックスが 1 であるため、`i + 1`最適な候補者を追跡するとき。 

## 実用的な例

 元のサンプルは大きいため、3 人のプレイヤーと 8 つの質問を含む小さな合成インスタンスでメカニズムを説明します。 

### 例 1

 マトリックスが次のようになっているとします。 

| プレーヤー | Q1 | Q2 | Q3 | Q4 | Q5 | Q6 | Q7 | Q8 |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 0 | 0 | 0 | 0 | 0 |
 | 2 | 1 | 1 | 0 | 1 | 0 | 0 | 0 | 0 |
 | 3 | 1 | 0 | 1 | 0 | 1 | 0 | 1 | 0 |

 列の合計は次のとおりです。 

| Q | 合計 |
 | --- | --- |
 | Q1 | 3 |
 | Q2 | 2 |
 | Q3 | 2 |
 | Q4 | 1 |
 | Q5 | 1 |
 | Q6 | 0 |
 | Q7 | 1 |
 | Q8 | 0 |

 難易度で並べ替えると、Q6、Q8、Q4、Q5、Q2、Q3、Q1 のような弱い順序になります。 

半分に分割する:

 | プレーヤー | 簡単料金 | ハードレート | 違い |
 | --- | --- | --- | --- |
 | 1 | 高い | 非常に高い | 大 |
 | 2 | 中 | 中 | 中 |
 | 3 | 似たような | 似たような | 0に近い |

 プレイヤー 3 は、アルゴリズムの選択ルールと一致し、難易度構造と最も一致していないことが際立っています。 

### 例 2

 すべてのプレイヤーの合計スコアが同じであっても、簡単な質問と難しい質問で分布が異なる場合でも、分割は行の合計ではなく列の構造に依存するため、アルゴリズムはそれらを区別します。 

これは、生のスコアの平等性が、難易度階層化の下での同様の動作を意味しないことを示しています。

 ## 特殊なケース

 多くの質問にわたって列の合計がほぼ同じである場合、微妙なエッジ ケースが発生します。 この状況では、並べ替え順序にノイズが多くなりますが、大まかな分割のみが必要なため、アルゴリズムは引き続き機能します。 たとえ一部の質問が半分の間で誤って分類されたとしても、不正行為者が期待する半分間の均等性は安定したままですが、実際のプレイヤーは依然として方向性の偏りを示しています。 

別のエッジケースは、強いプレイヤーが難易度全体で異常に均一なパフォーマンスをするときに発生し、不正行為者を模倣する可能性があります。 ただし、強力なプレイヤーであっても、基礎となる生成プロセスにより難易度とある程度の相関関係が保たれるため、イージーとハードのギャップは期待値においてゼロではないままです。 

最後に、データセットが小さいか、極端に不均衡な場合、列平均の信頼性が低くなります。 このような場合、分離は弱まりますが、意図された制約では、順序を安定させるために大数の法則の効果に十分なデータが想定されています。
