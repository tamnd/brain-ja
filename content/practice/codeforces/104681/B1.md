 ## 解決策
 ## 問題の理解

 シンボルのシーケンスを表す単一の文字列が与えられます。各位置は固定文字または未知のプレースホルダーのいずれかです。 固定文字は 2 種類あり、これらを 2 文字と考え、不明文字はその 2 文字のいずれかに置き換えることができます。 すべての未知の文字列を置き換える方法を決定した後、隣接するペアをスキャンして結果の文字列を評価し、ペアがある文字タイプから別の文字タイプに変更されるたびにコストを請求します。変更の方向に応じて 2 つの異なるコストがかかります。 

より具体的には、最終文字列には、特定の隣接遷移が発生するたびにペナルティがあり、逆遷移に対しては別のペナルティが適用されます。 課題は、移行コストの合計が最小限に抑えられるように、未知のポジションすべての後任を選択することです。 

入力は、文字列と、考えられる 2 つの隣接する遷移に対するペナルティを記述する 2 つの整数を含む 1 つのテスト ケースで構成されます。 出力は単一の整数で、すべての未知数を最適に置き換えた後の達成可能な最小コストです。 

問題の構造は、局所的な決定がグローバルなコストに影響を与えることを即座に示唆していますが、その影響は限定的なものであり、コストは隣接するペアにのみ依存し、長距離の相互作用には依存しません。 これは、キャラクターをある位置に固定すると、その効果はその左右の隣の 2 か所でのみ感じられることを意味します。 

文字列の長さが 1 万以上のオーダーである場合、未知数のすべての代入を試みる解決策は不可能です。これは、各未知数によって検索スペースが 2 倍になるためです。 割り当てごとの 3 次または 2 次チェックでも、通常の制限時間内では失敗します。 これにより、文字列を組み合わせのプロセスではなく、順次の決定プロセスとして扱う必要があります。 

いくつかの特殊なケースは、早期に切り分ける価値があります。 文字列に未知数が含まれていない場合、答えは遷移の 1 回の線形スキャンだけです。 文字列が完全に未知のもので構成されている場合、単純な考えはすべてを試してみることです。$2^n$しかし、40 のような短い長さでさえ、これはすでに実行不可能になります。 もう 1 つの微妙なケースは、未知の文字が固定文字間で分離されている場合です。たとえば、C???J のようなパターンでは、エンドポイントによって制約された構造が強制され、将来の遷移を考慮せずにコミットが早すぎると、素朴な貪欲な埋め込みが誤って処理する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、あらゆる未知の位置を二者択一として扱うことです。 文字列の割り当てごとに、遷移が発生するたびに隣接するペアをスキャンし、ペナルティを合計することで総コストを計算します。 これは、問題の定義を正確に評価するため、正しいです。 ただし、ある場合は、$k$未知の位置、これには必要です$2^k$課題と各評価コスト$O(n)$、全体の複雑さは次のようになります。$O(n \cdot 2^k)$。 これは中程度の場合でも爆発的に増加します$k$。 

重要な観察は、コスト関数には前の文字以降のメモリがないということです。 どのシンボルを配置するかを決めたら$i$、将来の唯一の依存関係は、位置とどのように相互作用するかです。$i+1$。 これにより、問題は、最後に選択した文字を記憶するだけで済む逐次的な最適化に変換されます。 

これは当然、位置と最後の文字の選択に関する動的プログラミングの定式化につながります。 各位置で、いずれかの文字タイプでその位置で終了した場合に達成可能な最小コストを追跡します。 固定キャラに遭遇すると遷移が制限されてしまいます。 未知のものに遭遇した場合、両方の遷移が許可されます。 各ステップでは前の状態からの拡張のみが考慮されるため、計算全体が線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 2^k)$|$O(n)$| 遅すぎる |
 | 動的プログラミング |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの文字のそれぞれの状態で終了するための最適なコストを維持しながら、文字列を左から右に構築するという問題を扱います。 

1. 可能な各文字で終わるプレフィックスの処理の最小コストを表す 2 つの値を初期化します。 開始時は文字が固定されていないため、どちらの状態も「未使用」としてゼロに設定されます。 
2. 文字列を左から右に繰り返します。 各位置で、この位置の各文字タイプで終了するためのコストの新しいペアを計算します。 
3. 現在のキャラクターが固定されている場合、そのキャラクターへの移行のみが許可されます。 以前のいずれかの状態からのコストを計算し、前の文字が現在の文字と異なる場合のペナルティを追加します。 
4. 現在の文字が不明な場合は、両方の可能性を独立して評価します。 可能な割り当てごとに、以前の両方の状態を再度考慮し、その割り当てに至る最小コスト パスを選択します。 
5. 位置を処理した後、古い状態を新しく計算された状態に置き換えて続行します。 
6. 文字列を終了すると、答えは 2 つの終了状態の最小値になります。 

重要なアイデアは、過去に関するすべての関連情報が最後の文字にのみエンコードされるため、各ステップですべての可能な履歴を 2 つの数値に圧縮するということです。 

### なぜ効果があるのか

 正しさは、任意の位置のコスト寄与がそのすぐ左隣の位置のみに依存するという事実に依存します。 これにより、最適な下部構造が作成されます。位置に到達するための最適なコストが決定されると、$i$特定の最後の文字の場合、後の決定が以前の移行を遡及的に改善または悪化させることはできません。 したがって、グローバルに最適な割り当てには、すべての位置と状態のペアに対して最適なプレフィックスが含まれている必要があり、DP は、より適切な完全なソリューションにつながる可能性のあるプレフィックスを決して破棄しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    x, y = map(int, input().split())

    INF = 10**18

    # dp[C], dp[J]
    dpC, dpJ = 0, 0

    first = True

    for ch in s:
        newC, newJ = INF, INF

        if ch == 'C' or ch == '?':
            # place C here
            costC = min(
                dpC,
                dpJ + y  # J -> C transition
            )
            newC = min(newC, costC)

        if ch == 'J' or ch == '?':
            # place J here
            costJ = min(
                dpJ,
                dpC + x  # C -> J transition
            )
            newJ = min(newJ, costJ)

        dpC, dpJ = newC, newJ

    print(min(dpC, dpJ))

if __name__ == "__main__":
    solve()
```実装では 2 つのローリング DP 状態のみが保持されます。1 つは処理されたプレフィックスが C で終わるもの、もう 1 つは J で終わるものです。各文字で、同じ文字に留まるか、もう一方の文字から切り替えるかを考慮してこれらの状態を更新し、方向を切り替えるときに適切な移行コストを追加します。 

微妙な点は、どちらの初期状態もゼロであり、先行文字が存在する前には遷移コ​​ストが追加されないため、最初の文字にいるかどうかを明示的に追跡する必要がないことです。 これが機能するのは、最初の文字が隣接コストに寄与しないためです。 

## 実用的な例

 ### 例 1

 次のような文字列を考えてみましょう`C?J`費用がかかる$X = 2$、$Y = 3$。 

| ポジション | シャア | dpC | dpJ |
 | --- | --- | --- | --- |
 | 開始 | - | 0 | 0 |
 | 1 | C | 0 | INF |
 | 2 | ? | 0 | 2 |
 | 3 | J | 2 | 0 |

 位置 2 では、C から開始した場合に J を割り当てる方が安価になりますが、C の割り当ては引き続き有効です。 位置 3 では、C の後に J で終わるとコスト 2 が導入されます。最小の結果は 2 です。 

このトレースは、移行によってコスト構造が明確になるまで、DP がどのように意思決定を遅らせるかを示しています。 

### 例 2

 検討してください`??`と$X = 5$、$Y = 1$。 

| ポジション | シャア | dpC | dpJ |
 | --- | --- | --- | --- |
 | 開始 | - | 0 | 0 |
 | 1 | ? | 0 | 0 |
 | 2 | ? | 0 | 0 |

 常に同じ文字を一貫して割り当てることができ、遷移を完全に回避できるため、両方の状態はゼロのままです。 これは、DP が最適な場合には均一な割り当てを自然に見つけることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 各文字は一定数の状態を更新します。

このソリューションは文字列の長さに比例してスケールされます。すべての文字を少なくとも 1 回検査する必要があるため、これが最適です。

def run(inp: str) -> str:

 ## 特殊なケース

 完全に不明な文字列は、貪欲な割り当てが失敗する理由を示しています。 もし持っていたら`????`コストが等しい場合、貪欲な戦略ではキャラクターを早い段階で切り替えて不必要な遷移を作成する可能性がありますが、DP は一貫して両方の状態を調整し、早すぎるコミットを回避します。 

次のような固定文字が交互に並ぶ文字列`CJCJ`すべての隣接するペアに強制的にコストを寄与させます。 DP はここでの移行を避けることができず、すべてのペナルティを正しく累積しており、人為的に滑らかにしようとするのではなく、強制された構造を尊重していることを示しています。 

単一文字を入力すると、隣接関係が存在しない場合には移行コストが追加されないことが確認されます。 DP は両方の状態を正しく初期化し、特別なケースを使用せずにゼロを返します。
