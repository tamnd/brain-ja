 ## 解決策
 ## 問題の理解

 完全な重み付きグラフが与えられます。$n$選手たち。 プレイヤー間の体重$i$そしてプレイヤー$j$対称値です$P_{i,j}$、これらの 2 人のプレーヤーが試合をした場合の人気の増加を表します。 

試合では常に 1 人のプレイヤーが脱落します。 順序付けルールは次のように固定されています。$i < j$、プレーヤー$i$常に勝ちます。 試合後、プレーヤーは$i$ビートプレイヤー$j$、プレーヤー$i$プレイヤーを吸収する$j$の人気プロフィール、つまりプレイヤーの 3 人に 1 人が占めることを意味します$x$、値$P_{i,x}$になる$\max(P_{i,x}, P_{j,x})$。 対称的に、$P_{x,i}$同じ方法で更新されるため、実質的にプレーヤー$i$は行列の 2 つの行の和集合になります。 

正確に選択しなければなりません$n-1$すべてのプレイヤーを最終的な 1 人の勝者に絞り込むノックアウト プロセスを形成します。 試合は順序付けする必要があり、各試合の後、敗者は消え、次の試合の前に勝者の列が更新されます。 

間の試合のスコア$i$そして$j$は常に現在の値です$P_{i,j}$以前のすべてのマージによってマトリックスが更新された後、一致が発生した時点で。 目標は、これらの一致スコアの合計を最大化するために、ペアリング構造と一致順序の両方を選択することです。 

制約$n \le 1000$任意の意味$O(n^2)$または$O(n^2 \log n)$この戦略はもっともらしいが、それに近いものは何か$O(n^3)$高度に最適化されているか、反復ごとに非常に単純でない限り、危険です。 また、値だけでなく、実際の消去シーケンスを出力する必要もあります。 

微妙な点は、行列のエントリは時間の経過とともに進化するため、マージのたびに最大更新を再計算する単純なシミュレーションでは簡単に次のような結果になる可能性があることです。$O(n^3)$あるいはさらに悪いことに。 もう 1 つの落とし穴は、一致の構造が任意であると仮定していることです。実際には、「小さいインデックスが常に勝つ」という制約により、有向構造が強制されます。 

更新がカスケードされる場合、まれなケースが発生します: マージ後$i$そして$j$、勝者は将来の対戦相手に対する重みを突然増やし、次の試合の最適な選択を変更することができます。 将来の成長を無視した貪欲な選択は失敗する可能性があります。 

## アプローチ

 直接的な総当たりのアイデアは、トーナメントをシミュレートすることです。各ステップで、残りのすべてのペアを試し、マージをシミュレートし、結果の状態を計算し、再帰します。 これは、考えられるすべてのトーナメント ツリーと順序を調査するため、概念的には正しいですが、分岐要素は大まかに次のとおりです。$O(n^2)$各レベルで深さのある$n$。 メモ化を行ったとしても、状態空間はすべての可能なサブセットとすべての可能なマージ行列のセットであり、これは天文学的に大きくなります。 ボトルネックは、組み合わせの爆発だけでなく、各仮説一致後の行列の更新コストでもあります。$O(n)$アップデートごとに、少なくとも$O(n^3)$パスごとに。 

重要な構造的観察は、勝者ルールが方向を決定するということです。つまり、生存している 2 人のプレイヤー間で試合が発生するたびに、インデックスの小さい方が常に生き残ります。 これにより、このプロセスは、より高い指数のプレーヤーが徐々により低い指数の代表者に吸収される、根付いた構造の構築に変わります。 したがって、各プレイヤーは最終的に、より小さいインデックスを持つ 1 つの祖先に吸収されることになります。 

これは、プロセスを逆に行うことを示唆しています。 消去をシミュレートする代わりに、インデックスの昇順でコンポーネントを徐々にマージし、より大きなインデックスをより小さなインデックスに常に接続することによって、最終的な生存者を構築することを考えることができます。 マージ操作は決定的であるため、残っているのは、エッジ ゲインを最大化するアタッチメントのシーケンスを決定することです。 

ここで、プロセスを別の方法で解釈します。どの時点でも、生きている各プレーヤーは元のプレーヤーのセットを表し、その行はそのセットの要素ごとの最大値になります。 あの選手を決めたら$j$に吸収されます$i$、その後、得られます$P_{i,j}$その瞬間と将来の価値観$i$～によって豊かになる$j$の行。 

これは最大スパニング ツリーのような構造になりますが、動的な重み効果があります。マージにより、最大伝播によって将来のエッジの重みが向上します。 重要な観察は、任意の 2 つのコンポーネントについて、最適な即時マージはそれらの代表間の現在の最大エッジによって決定され、マージされると、結果として得られる代表は重みを増やすだけで、決して減らすことはないということです。 この単調性により、優先順位構造を使用してコンポーネント間の可能な限り最良の接続を貪欲に維持できるようになります。 

最終的な解決策は、異なるコンポーネント間のすべてのエッジの中から可能な限り最良の次の一致を繰り返し選択し、それらをマージし、最大伝播によって影響を受けるエッジを更新することとみなすことができます。 これは、動的重み付けの下での最大スパニング ツリー構築のように動作します。マージ操作は将来のエッジの重みのみを増加させ、ローカル決定の有効性を維持するため、Prim のような貪欲さが機能します。

 ## アルゴリズムのチュートリアル

 We maintain a disjoint set of active components, each representing a merged player. Each component has a representative index, always the smallest index inside it to respect the rule that smaller indices win merges.

 We also maintain a matrix of current best weights between components, which evolves via max-merge when components are unified.

 ### ステップ

 1. Initialize each player as its own component, and set the current representative of each component to the player itself. 現在の行列は最初は$P$。 
2. ペアごとに$(i, j)$、コンポーネント間で現在達成可能な最良のエッジ ウェイトを維持します。 最初はこれだけです$P_{i,j}$。 
3. 異なるコンポーネントのペアを繰り返し選択します$(A, B)$現在の値を最大化するもの$P_{rep[A], rep[B]}$。 これは可能な限り最良の即時一致です。 
4. 間のマッチングを実行します。$rep[A]$そして$rep[B]$。 小さいインデックスが常に勝つため、小さいインデックスを持つ代表が他の代表を吸収します。 
5. 一致を出力に追加し、そのスコアを合計に追加します。 
6. 負けたコンポーネントを勝ちのコンポーネントにマージします。 他のすべてのコンポーネントについて$C$、 アップデート：$$P_{win, C} = \max(P_{win, C}, P_{lose, C}), \quad P_{C, win} = P_{win, C}$$これは人気の継承をシミュレートします。 
7. 負けたコンポーネントを非アクティブとしてマークし、コンポーネントが 1 つだけ残るまで続行します。 

### なぜ効果があるのか

 核となる不変条件は、アクティブなコンポーネントのどのペアでも、保存されているエッジの重みが、以前のすべてのマージの後、現在そのコンポーネント内にあるプレーヤーの元のペアが取得できる最大値と常に等しいということです。 マージは要素ごとの最大値のみを取るため、それ以降の操作ではエッジの重みを減らすことはできず、増やすだけです。 

この単調性により、現在の最大エッジの選択が安全であることが保証されます。将来エッジを改良しても、すでに形成されたコンポーネント内の重みが増加するだけであり、以前は利用できなかったコンポーネント間のより良い選択が作成されることはありません。 したがって、貪欲な選択によって将来の最適なマージ構造が妨げられることはなく、プロセスは非減少エッジ更新の下で最大スパニング ツリーのように動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    P = [list(map(int, input().split())) for _ in range(n)]

    parent = list(range(n))
    alive = [True] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    # current representative is always smallest index in component
    def merge(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return ra
        if ra > rb:
            ra, rb = rb, ra

        parent[rb] = ra
        alive[rb] = False

        for k in range(n):
            if alive[k] and k != ra:
                P[ra][k] = max(P[ra][k], P[rb][k])
                P[k][ra] = P[ra][k]
        return ra

    active = set(range(n))
    total = 0
    edges = []

    import heapq
    heap = []

    for i in range(n):
        for j in range(i + 1, n):
            heapq.heappush(heap, (-P[i][j], i, j))

    while len(active) > 1:
        w, i, j = heapq.heappop(heap)
        w = -w
        i = find(i)
        j = find(j)
        if i == j or not alive[i] or not alive[j]:
            continue

        if i > j:
            i, j = j, i

        total += P[i][j]
        edges.append((i + 1, j + 1))

        new_rep = merge(i, j)

        # push updated edges from new_rep
        for k in list(active):
            rk = find(k)
            if rk != new_rep:
                heapq.heappush(heap, (-P[new_rep][rk], new_rep, rk))

        # rebuild active set lazily
        active = {find(x) for x in active if alive[find(x)]}

    print(total)
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```この実装では、候補エッジのヒープを維持し、現在利用可能な最良の一致を常に抽出します。 マージによって重みが変更されるため、古いヒープ エントリのエンドポイントが有効なアクティブ コンポーネントを表さなくなった場合、そのエントリは遅延してスキップされます。 

The merge operation is where correctness lives: after selecting a winner, we propagate maximum values from loser to winner across all remaining active nodes, exactly simulating the “inherit popularity” rule.

 A common pitfall is forgetting that edge weights change over time, so a static priority queue alone is insufficient unless we validate representatives at extraction time.

 ## 実用的な例

 Consider a small instance with three players:

 入力行列:$$P =
\begin{bmatrix}
0 & 5 & 1 \\
5 & 0 & 4 \\
1 & 4 & 0
\end{bmatrix}$$コンポーネントから始めます$\{1\}, \{2\}, \{3\}$。 

| ステップ | 選ばれたエッジ | コンポーネント | マージ結果 | スコア |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2) | {1,2}、{3} | 1 は 2 を吸収します | 5 |
 | 2 | (1,3) | {1,2,3} | 1 は 3 を吸収します | 1 |

 合計は$6$。 1 と 2 をマージすると、行 1 は次のようになります。$[0,5,1]$。 3 をマージしても、すでに高いエッジは 2 に変更されません。これは、すでに 2 によって支配されている 2 を除くすべての次元に対する 3 の影響が弱いためです。 

このトレースは、後のマージでは関連する比較が増加または保持されるだけであるため、初期の高重みエッジが安全に取得されることを示しています。 

ここで、利益の遅延が問題となるケースを考えてみましょう。$$P =
\begin{bmatrix}
0 & 2 & 100 \\
2 & 0 & 3 \\
100 & 3 & 0
\end{bmatrix}$$| ステップ | 選ばれたエッジ | コンポーネント | マージ結果 | スコア |
 | --- | --- | --- | --- | --- |
 | 1 | (1,3) | {1,3}、{2} | 1 は 3 を吸収します | 100 |
 | 2 | (1,2) | {1,2,3} | 1 は 2 を吸収します | 2 |

 ここで、1 と 3 をマージすると、最初に最も強いエッジが即座にロック解除され、その後のマージによってその利得は減少しません。 

これらの例は、貪欲な抽出が、将来の可能性を安全に保持しながら、即時の高価値マージを最大化することと一致していることを確認しています。

 ## 特殊なケース

 単一プレーヤーの場合は、一致が発生しないため、重要ではありません。 アクティブ セットのサイズは最初から 1 であるため、アルゴリズムは直ちに合計 0 とエッジを出力しません。 

すべての非対角値が等しい完全に均一な行列は、ヒープベースのタイ ブレークが有効なシーケンスを生成するかどうかをテストします。 すべてのエッジが同一であるため、どのマージ順序も最適であり、アルゴリズムは対称性と単調なマージにより正確さを維持しながら任意のペアを選択できます。 

1 つのエッジが他のすべてのエッジよりも大幅に大きいドミナント ペア構成では、アルゴリズムがそのマージを最初に優先することが確認されます。 ドミナントペアをマージした後、伝播によって重みが増加しますが、最大のエッジがすでに貪欲に取得されているため、初期の逃した機会を改善することはできません。 

小さなチェーン構造は、中間マージが将来の高価値エッジをブロックしないかどうかをテストします。 マージごとに重みが増加または維持されるため、アルゴリズムは最適な構造を失うことなくマージを安全に遅延または加速します。
