 ## 解決策
 ## 問題の理解

 頂点に 1 から n までの番号が付けられている重み付き無向グラフを使用しています。 各エッジは 2 つの頂点を接続し、正のコストを持ちます。 重要な構造上の制限は、各エッジはラベルの違いが最大 10 である頂点のみを接続することです。これにより、重み自体は任意に大きくても、グラフは頂点インデックスの数直線に沿って「局所的に接続」されます。 

タスクは、複数の独立した最短パス クエリに答えることです。 各クエリでは 2 つの頂点が与えられ、それらを接続するパスの可能な最小合計重みを計算するか、パスが存在しないことを報告する必要があります。 

制約が十分に大きいため、どのソリューションでもグラフをまばらに扱う必要があります。 最大 100,000 個の頂点と 200,000 個のエッジの場合、隣接リストの保存は問題ありませんが、全ペアの前処理などは不可能です。 クエリ数が最大 25,000 なので、クエリごとに大規模なグローバル最短パス アルゴリズムを不用意に実行する必要がなくなります。 

最も重要な構造上のヒントは、エッジ制約 |u − v| です。 ≤ 10。これにより、すべての頂点がインデックス空間内の小さな近傍にのみ接続されることが保証されるため、各隣接リストは小さく、グラフは単位直線の周囲の疎なバンドのように動作します。 

ダイクストラを使用したクエリごとの素朴な最短パスは正しいですが、問題は多くのクエリにわたる繰り返しです。 それでも、エッジがまばらでクエリが独立しているため、問題は不必要な作業を回避する十分に高速な単一ソースから単一ターゲットへの最短パス ルーチンを設計することに帰着します。 

微妙なエッジケースは、コンポーネントが切断されていることです。 グラフが接続されていることが保証されていないため、異なるコンポーネント間のクエリは -1 を返す必要があります。 もう 1 つのケースは、a と b が同じノードである場合です。この場合、関係するエッジがない場合でも、答えは常に 0 になります。 

## アプローチ

 最も直接的なアプローチは、各クエリを個別に処理し、ソース頂点 ai から bi に到達するまでダイクストラを実行することです。 すべてのエッジの重みが正であるため、ダイクストラは正しいため、常に距離の増加順にパスを探索し、最初に bi を設定するときに最短パスが見つかることが保証されます。 

これが許容される可能性がある理由は、各頂点の次数が非常に小さいためです。 エッジはインデックス空間のサイズ 10 のウィンドウ内の頂点のみを接続するため、各ノードは最大 20 個の隣接ノードを持つことができます。 これにより、各緩和の定数係数が小さく保たれ、グラフが密なネットワークではなく、非常に薄い疎なネットワークのように動作します。 

ブルートフォースの思考プロセスは、すべてのペア間の最短パスを計算することですが、それにはすべてのノードからダイクストラを実行するか、フロイド-ウォーシャルを使用する必要があります。 どちらも、100,000 までの n には遅すぎます。 クエリが独立しており、グラフがまばらであるという観察は、全体的な距離を事前に計算するのではなく、各クエリに答えるために必要なグラフの部分のみを調査する必要があることを示唆しています。 

これにより、早期停止によるクエリごとのダイクストラが得られます。 すべてのノードが処理されるまで実行するのではなく、ターゲット ノードが優先キューから抽出されるとすぐに停止します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | オールペア / フロイド-ウォーシャル | O(n3) | O(n²) | 遅すぎる |
 | すべてのノードからのダイクストラ | O(n (m log n)) | O(n + m) | 遅すぎる |
 | クエリごとのダイクストラ (早期停止) | O(q · m log n) 最悪の場合 | O(n + m) | 実際に受け入れられる |

 ## アルゴリズムのチュートリアル

 優先キューに基づく最短パス検索を使用して、各クエリを個別に処理します。

1. 指定されたエッジからグラフの隣接リストを作成します。 各頂点にはペア (近傍、重み) のリストが保存されます。 これは、考えられるすべての頂点ペアをスキャンせずに、有効なエッジのみを効率的にトラバースするために必要です。 
2. 各クエリ (a、b) について、まず a が b と等しいかどうかを確認します。 そうである場合、ノードからノード自体への最短パスにはエッジが必要ないため、答えは直ちにゼロになります。 
3. 無限値で満たされた距離配列を初期化し、dist[a] = 0 に設定します。また、ペア (0, a) を含む優先キューも初期化します。 このキューは常に、次に処理する可能性の高い頂点を保持します。 
4. 優先キューが空ではない間に、暫定距離が最小となる頂点 u を抽出します。 この距離がすでに保存されている dist[u] よりも大きい場合は、古いためスキップします。 
5. u が b に等しい場合、このクエリの答えとして dist[u] をすぐに返します。 ダイクストラでは、既知の最短距離の非降順でノードがポップされることが保証されているため、これは有効です。 
6. それ以外の場合は、u のすべての近傍 v に対して反復処理を行います。 各エッジ (u、v、w) に対して、緩和を試みます。 dist[v] > dist[u] + w の場合、dist[v] を更新し、(dist[v], v) を優先キューにプッシュします。 
7. b に到達せずに優先キューが空になった場合、a から b に到達できないため、-1 を出力します。 

### なぜ効果があるのか

 正しさは標準的なダイクストラの動作から得られます。 優先キューには常に、フロンティア ノードまでの最短距離の候補が格納されます。 ノードがポップされると、その距離が確定します。これは、代替パスは、すでに処理されている同等以下の暫定距離を持つノードを通過する必要があるためです。 

初めて b がキューからポップされるとき、その距離は a から b までのすべての可能なパスの中で最小であることが保証されるため、b で早期に停止しても正確性は損なわれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

n, m, q = map(int, input().split())

adj = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, w = map(int, input().split())
    adj[u].append((v, w))
    adj[v].append((u, w))

INF = 10**30

def dijkstra(s, t):
    if s == t:
        return 0

    dist = [INF] * (n + 1)
    dist[s] = 0
    pq = [(0, s)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if u == t:
            return d

        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return -1

for _ in range(q):
    a, b = map(int, input().split())
    print(dijkstra(a, b))
```隣接リストの構築は簡単で、無向走査のために各エッジが 2 回保存されることが保証されます。 ダイクストラ ルーチンは、距離配列とヒープを使用した標準形式で作成されます。 ターゲット ノードをポップするときの早期終了条件は、グラフの無関係な部分の探索を避けるために使用される主な最適化です。 

微妙な点の 1 つは、エントリ チェックが古いことです。`if d != dist[u]`これは、古いヒープ エントリの処理を回避し、複雑さを制御するために不可欠です。 

## 実用的な例

 パスが分岐する小さなグラフを考えてみましょう。 

入力の場合:```
4 4 1
1 2 5
2 4 2
1 3 1
3 4 100
1 4
```アルゴリズムは距離 0 の 1 から始まります。1 から、コスト 5 の 2 とコスト 1 の 3 が検出されます。キューは常に 3 を次に優先します。 

| ステップ | 現在のノード | 距離 | アップデート |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | (2:5)、(3:1) |
 | 2 | 3 | 1 | (4:101) |
 | 3 | 2 | 5 | (4:7) は 101 から 7 に改善します |
 | 4 | 4 | 7 | 停止 |

 これは、2 を介してより適切なルートが検出されるため、一見高価に見えるエッジ (3,4) が実際には決して使用されないことを示しています。 

接続が切断された場合:```
5 2 1
1 2 3
4 5 2
1 5
```| ステップ | 現在のノード | 距離 | アップデート |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | (2:3) |
 | 2 | 2 | 3 | なし |
 | 3 | キューが空です | - | パスが見つかりません |

 これは、到達不能なノードが空のキューと -1 出力をもたらすことを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · m log n) 最悪の場合 | 各クエリは、エッジを介したヒープ操作を使用してダイクストラを実行します。 
| スペース | O(n + m) | 隣接リストと距離の配列とヒープ |

 |u − v| のため、各ノードの次数が非常に小さいと仮定します。 ≤ 10 の制限では、クエリごとの実際の緩和数は、一般的なケースでは m よりも大幅に少なくなります。 これにより、ソリューションは 25,000 クエリの制限時間内に保たれます。 

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, q = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))

    INF = 10**30

    def dijkstra(s, t):
        if s == t:
            return 0
        dist = [INF] * (n + 1)
        dist[s] = 0
        pq = [(0, s)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            if u == t:
                return d
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return -1

    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        out.append(str(dijkstra(a, b)))
    return "\n".join(out)

 ## 特殊なケース

 最初の重要なエッジ ケースは、送信元が宛先と等しい場合です。 このような状況では、アルゴリズムは優先キューに触れることなく、すぐにゼロを返します。 これにより、不必要なヒープの初期化が回避され、グラフにエッジがない場合の偶発的な障害が防止されます。 

もう 1 つのエッジ ケースは、頂点が切断されていることです。 このようなシナリオでは、ダイクストラはソースから到達可能なすべてのノードを使い果たし、ターゲットが見つかる前に優先キューが空になります。 緩和によって目的地を探索領域に導入することはできないため、アルゴリズムは正しく -1 を返します。 

3 番目のケースは、最初は直接的だが高価なエッジによって支配されている、より長い迂回を介してのみノードに到達できる場合です。 緩和プロセスにより、不良エッジが早期に処理された場合でも、検出されるとすぐに安価なパスによって上書きされ、古いキュー エントリは距離チェックによって安全に無視されます。
