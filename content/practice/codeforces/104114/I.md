 ## 解決策
 ## 問題の理解

 一列に並べられた非負の整数のシーケンスが与えられます。 各操作では、2 つの隣接する位置を選択し、両方の値を同じ数値、具体的には 2 つの値の最大値から 1 を引いた値 (最大値が正である限り) に置き換えます。 この操作は、ペアを 2 つのうちの強い方より 1 つ少ない単一レベルに効果的に「圧縮」し、同時に両方の位置を上書きします。 

このプロセスは、配列内のすべての要素がゼロになるまで繰り返されます。目標は、このすべてゼロの構成に到達するために必要な操作の数を最小限に抑えることです。 

重要な制約は、配列サイズは最大 200000 まで可能ですが、値は 10^9 まで可能であることです。 各操作はせいぜい 1 レベルずつ値を減らすだけであり、大きな値の場合はその大きさの操作が必要になるため、操作を直接シミュレートするソリューションは直ちに実行不可能になります。 

微妙なエッジの動作は、極大値がどのように伝播するかによって発生します。 次のようなプラトーを考えてみましょう`[5, 5, 5]`。 素朴な直感は、各位置を個別に削減する必要があると示唆するかもしれませんが、隣接するペアに対する操作により削減の「共有」が可能になります。 同様に、次のようなパターン`[1, 0, 1]`操作は常にローカルですが、値を内部に伝播できるため、ゼロを越えて相互作用できます。 

誤解を招きやすいのは、値がゼロで区切られている場合です。 例えば、`[3, 0, 3]`。 素朴なアプローチでは、各側が独立して動作すると考えるかもしれませんが、`(3,0)`両方の位置を繰り返し減少させ、セグメントを間接的に結合する相互作用を引き起こします。 

最大の難点は、演算は常に隣接するペアに作用しますが、常に最大値を使用することです。つまり、より大きな値が優先され、より小さな値が下に引きずり込まれることを意味します。 これにより、ピークから外側に向かう「高さの減少」の流れのように動作するプロセスが作成されます。 

## アプローチ

 ブルート フォース シミュレーションでは、文字通り操作が繰り返し適用されます。 各操作は 2 つのインデックスに触れ、極大値と比較してそれらを 1 つ減らします。 各操作は局所的な最大値から最大で 1 単位の高さを減少させるため、最悪の場合の操作の総数はすべての値の合計に比例し、最大 2×10^14 になる可能性があります。 さらに悪いことに、各操作では有効な位置をスキャンまたは選択する必要があるため、これが完全に不可能になります。 

重要な構造的洞察は、個々の操作の観点から考えるのをやめ、代わりにプロセスを削減の伝播として再解釈することです。 各要素は初期の高さからゼロまで縮小する必要がありますが、縮小は隣接するペア間を「流れる」ことができます。 操作を詳しく調べると、隣接する 2 つの値の最大値が唯一の要因であることがわかります。つまり、より小さな値は他の値を増やすのに役立たず、下に引きずられるだけです。 

これは方向性のある解釈につながります。 エッジで操作するたびに、現在どちらの側が高いかを効果的に選択し、その高さを局所的に下げることになりますが、そのアクションは影響力を広げます。 アレイ全体でどれだけの「下降容量」が必要かを追跡すると、隣接するアレイ間の一貫性を確保しながら、ピークからの寄与を蓄積するプロセスをモデル化できます。 

標準的な変換では、各位置を特定の数の「デクリメント イベント」が必要であると見なし、最適な操作はエッジに沿ってリダクションを貪欲にペアにすることに対応することを認識し、隣接する要素と共有できるデクリメントを決して無駄にしないようにします。 最適な解決策は、削減を輸送するために隣接する各境界を何回使用する必要があるかを分析することによって得られます。 

これは、位置ごとに、最適なプロセスで制御最大値として機能する回数を計算することになります。 最終的な答えは、隣接する要素間の遷移から得られる寄与の合計として表すことができます。高い値から低い値に移動するたびに、超過した高さはその境界に固定された操作によって支払われる必要があります。 

最終的な定式化は線形になります。配列をスキャンして、隣接する要素間の絶対差に加えて、最後に残った高さの寄与を累積します。これは、高さのすべての単位が最終的には境界演算を通じて削除される必要があるためです。

 ## アルゴリズムのチュートリアル

 最適な観点は、すべての高さの単位が隣接する操作を通じてシステムから「出る」必要があるということであり、これを説明する最も安価な方法は、隣接する単位間で高さがどのように異なるかを測定することです。

1. 配列を左から右に繰り返し、必要な操作の実行回数を維持します。 アイデアは、各境界を越えてどのくらいの高さを移動する必要があるかを測定することです。 
2. 隣接するペア (a[i]、a[i+1]) ごとに、それらの値を比較します。 a[i] が a[i+1] より大きい場合、この境界を含む操作によって超過高さ a[i] - a[i+1] を削減する必要があります。 これは答えに直接貢献します。 
3. a[i] が a[i+1] 以下の場合、より高い値が減少した場合に将来のインタラクションによって削減を処理できるため、この境界では当面の追加コストはカウントされません。 この構造により、二重に減額されることはありません。 
4. すべての隣接するペアを処理した後、最後の要素の値を追加します。 これは、最後に残ったものはすべてゼロに減らす必要があり、それを転送するためのそれ以上の境界がないという事実を説明しています。 
5. 最終的な累積合計が最小操作数として返されます。 

微妙な点は、連続する要素間のすべての「ドロップ」が避けられない作業を表していることです。上位のセグメントは、隣接するセグメントと一致するように最終的に縮小する必要があり、それらの縮小は必要な操作に正確に対応します。 

### なぜ効果があるのか

 重要な不変条件は、高さのすべての単位が、隣接するペアの最大値となる境界を介して少なくとも 1 回削除されなければならないということです。 左から右に移動する場合、a[i] から a[i+1] への減少は、a[i] の余剰の高さをこの境界で処理せずに将来の要素で吸収できないことを示します。 同様に、最後の要素はそれ以上エクスポートできないため、その値の全額を操作として支払う必要があります。 

これにより、必要な削減単位がそれぞれ 1 回だけカウントされ、操作が無駄になったり二重にカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ans += a[i] - a[i + 1]
    
    ans += a[-1]
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、境界累積のアイデアを直接エンコードします。 ループは、シーケンスが減少するときにのみ寄与を追加します。これは、高さの不可逆的な低下に相当します。 これらの削減は、他の場所に移すことのできない強制的な削減を表しています。 

最後に追加`a[-1]`プロセスの最後に除去する必要がある残りの質量を占めます。 下向きの遷移のみをカウントすることを選択すると、値が増加したときの二重カウントが回避されます。これは、値が増加した分は、最終的に値が減少するときに後で支払われるためです。

 ## 特殊なケース

 重要なエッジ ケースは、次のような厳密に増加する配列です。`[1,2,3,4]`。 アルゴリズムは最終値 4 のみをカウントします。減少がないため、実行ではエッジに寄与は生成されません。 解釈では、すべての削減は最後まで延期され、最終的な高さは完全に削除されなければなりません。 

別のエッジケースは、次のような交互構造です。`[3,0,3]`。 3 から 0 への移行では 3 が寄与し、0 から 3 への変化では何も寄与せず、その後 3 が加算されます。合計は 6 となり、各側が中央のボトルネックから独立して排水する必要があることが正しく反映されています。 

最後のエッジケースは、次のようなフラット配列です。`[5,5,5]`。 下方への遷移がないため、最後の要素のみが寄与し、5 が与えられます。これは、すべての削減を同期して、中間ペナルティなしで最終境界で支払うことができるという考えと一致します。
