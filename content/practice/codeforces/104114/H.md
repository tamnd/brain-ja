 ## 解決策
 ## 問題の理解

 3 本の棒と 1 から n までの異なるサイズのディスクの集合を含むスタックベースのパズルが与えられます。 すべてのディスクは最初はロッド 1 上にありますが、古典的なハノイの塔とは異なり、ロッド 1 はサイズ順序規則を強制しません。つまり、プロセス中にロッド 1 上のディスクは任意の順序になる可能性があります。 ただし、他の 2 つのロッドは依然として標準的なハノイ ロッドと同様に動作し、大きなディスクを小さなディスクの上に置くことはできません。 

目標は、正当な移動を使用してすべてのディスクをロッド 3 に移動することです。各移動では、ロッドの上部のディスクのみが別のロッドに転送され、ロッド 2 とロッド 3 は常にサイズ制約に従います。 

入力は、ロッド 1 上のディスクの初期配置を下から上に 1 から n の順列として記述します。 ロッド 2 と 3 は空の状態で開始します。 出力は一連の移動である必要があり、各移動はソース ロッドと宛先ロッドを指定し、移動の合計数は 2n² を超えてはなりません。 

n ≤ 500 という制約は、2 次またはそれよりわずかに悪い手生成の解は許容されるが、手数に関して 3 次のものはすべて危険であることを意味します。 各動きが明示的に出力されるため、アルゴリズムの予算は、実際には最大約 500,000 回の操作のシーケンスの構築に相当します。 

素朴な解釈では、ロッド 1 のスクランブル スタックから正しいディスクを繰り返し抽出しながら、古典的なハノイの動作をシミュレートしようとします。重要な難点は、ロッド 1 が順序が無関係なバッファのように動作するため、制約に違反することなく任意のディスクを一時的に格納するために使用できることです。 この緩和を誤解することが最も一般的な失敗モードです。ロッド 1 を通常のハノイ ロッドと同じように扱うと、不必要な制限が生じ、問題が実際よりもはるかに難しく見えるようになります。 

初期構成がすでにソートに近づいているものの、正しい順序ではない場合、微妙なエッジ ケースが発生します。 たとえば、n = 3 で入力が 3 2 1 の場合、ロッド 1 にはすでに正しい降順スタックがありますが、古典的な考え方では不必要な再配置が試みられます。 もう 1 つのエッジ ケースは n = 1 です。この場合、移動シーケンスは追加の中間ステップなしで簡単な転送を正しく処理する必要があります。 

## アプローチ

 ブルートフォース解釈では、最大のディスクを徐々に分離し、それをロッド 3 に移動し、残りの構造を再帰的に解決する有効な一連の動きを検索しながら、完全なハノイ ロジックをシミュレートしようとします。 ただし、初期構成は任意であるため、単純なシミュレーションでは、ロッド 1 と 2 の間でディスクをシャッフルすることによって局所的な違反を繰り返し「修正」する傾向があり、移動に大きな爆発を引き起こします。 最悪の場合、これによりディスクのスキャンと再配置が繰り返され、再帰的または貪欲なローカル修復戦略の二次境界を簡単に超えてしまいます。 

重要な観察は、ロッド 1 が事実上、順序制約を無視する無制限のバッファであるということです。 これは、ロッド 1 上で不変のスタック構造を維持することに制約がないことを意味するため、制御された仕分けプロセスをシミュレートするための一時ストレージとしてロッド 1 を自由に使用できます。 

この問題は、ロッド 2 と 3 にのみ標準的なハノイ制約を尊重しながら、各ディスクが最終的にロッド 3 に移動することを保証する、昇順でのディスクの制御された抽出に帰着します。ロッド 1 は制限されていないため、移動のブロックを解除するために必要な中間構成を吸収できます。 

これにより、建設的な戦略が可能になります。ロッド 1 の上部に必要なディスクを繰り返し配置し、構造化された補助スタックとしてロッド 2 を使用して邪魔なディスクを別の場所に移動し、次にターゲット ディスクをロッド 3 に配置します。重要な構造の単純化は、ロッド 1 を制約のあるスタックではなく作業用の配列として扱うことができることです。これにより、古典的なハノイ推論の指数関数的分岐が排除されます。

 | 単純な再帰シミュレーション | O(指数) | O(n) | 遅すぎる |
 | バッファーロッドによる制御されたディスク抽出 | O(n²) の移動 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ロッド 3 には、すでに配置されている最大のディスクの正しいスタックが上から下に昇順で常に含まれており、ロッド 2 は一時的に厳密に有効なハノイ スタックとして機能するという不変条件を維持します。 

また、ロッド 1 がいつでも任意のディスクを受け入れることができるという事実にも大きく依存しています。つまり、順序違反を心配することなく、いつでもそこにディスクを「パーク」できるということです。 

### ステップ

 1. ロッド上に配置する次のディスクを特定します。 3. ディスクを 1 から n まで昇順に処理します。 これにより、ディスクがロッド 3 に置かれたときに、すべての小さなディスクがすでにその下に正しく配置されることが保証されます。 
2. 現在の構成でターゲット ディスクを見つけます。 ロッド 1 の上部にない場合は、ターゲット ディスクにアクセスできるようになるまで、ロッド 1 の上部ディスクをロッド 2 に繰り返し移動します。 ロッド 2 は有効なハノイ順序を維持する必要があるため、ロッド 2 への各挿入はその最上位要素に対してチェックされます。 
3. ターゲット ディスクがロッド 1 の上に来たら、それをロッド 3 に直接移動します。ロッド 3 には正しい順序でのみ大きなディスクが含まれるため、この移動は常に有効です。 
4. 移動したディスクをロッド 2 からロッド 1 に戻します。ロッド 1 には制限がないため、順序を確認することなくすべてのディスクを安全に戻すことができます。 
5. 次のディスクに対してこのプロセスを繰り返します。 

各ディスクは、ロッド 1 と 2 の間を一定回数移動してから、最終的にロッド 3 に移動します。これが O(n²) 以内に収まる重要な理由は、各ディスクが最大で O(n) 個のブロック操作に関与し、各ブロック操作が 1 回の移動に対応するためです。 

### なぜ効果があるのか

 正しさは 2 つの構造的事実に基づいています。 まず、ロッド 3 は厳密にディスク サイズの増加順に構築されているため、そこでの不正な配置は決して発生しません。 第 2 に、一時的な再配置はロッド 1 と 2 の間でのみ発生し、ロッド 1 には順序の制約がないため、実現可能性が制限されることはありません。 ロッド 2 は標準スタックのように動作し、システム内の唯一の実際の制約に違反しないようにします。 すべてのディスクは最終的にターゲットとして 1 回だけ選択され、昇順でロッド 3 に配置されるため、最終的な構成は正しい必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    # positions: where each disk currently is
    pos = {p[i]: i for i in range(n)}

    rod1 = p[:]  # bottom to top
    rod2 = []
    rod3 = []

    moves = []

    def move(src, dst):
        x = src.pop()
        dst.append(x)
        # encode rods: 1=rod1,2=rod2,3=rod3
        if src is rod1: a = 1
        elif src is rod2: a = 2
        else: a = 3
        if dst is rod1: b = 1
        elif dst is rod2: b = 2
        else: b = 3
        moves.append((a, b))

    for target in range(1, n + 1):
        while rod1[-1] != target:
            x = rod1[-1]
            if not rod2 or rod2[-1] > x:
                move(rod1, rod2)
            else:
                move(rod2, rod1)

        move(rod1, rod3)

        while rod2:
            move(rod2, rod1)

    print(len(moves))
    for a, b in moves:
        print(a, b)

if __name__ == "__main__":
    solve()
```このコードは、3 つのロッドをスタックとして明示的にシミュレートします。 重要な実装の詳細は、ロッド 1 とロッド 2 の間の対称移動ルールです。ロッド 2 がロッド 1 の現在のトップを受け入れることができない場合は常に、ロッド 1 には順序制約が課されていないという事実を利用して、ロッド 2 からロッド 1 に戻ります。 

ループオーバー`target`これにより、ロッド 3 上にディスクが昇順に配置されます。内側のループにより、障害となるすべてのディスクが一時的にロッド 2 に移動され、その後復元されるため、ターゲット ディスクが常に最終的にロッド 1 の上部に露出することが保証されます。 最後のクリーンアップ ステップでは、ロッド 2 を空にしてロッド 1 に戻し、次の反復で一貫した動作状態を復元します。 

よくある微妙な間違いは、ロッド 2 が常に有効な減少スタックを維持する必要があることを忘れていることです。 条件付き`rod2[-1] > x`まさにその制約を強制します。

 初期構成 [3, 1, 2] で n = 3 を考えてみましょう。

| ステップ | ロッド 1 | ロッド2 | ロッド3 | アクション |

 ## 特殊なケース

 n = 1 の場合、アルゴリズムはただちに唯一のディスクをターゲットとして識別し、それをロッド 1 からロッド 3 に直接移動します。ロッド 2 は決して使用されないため、無効な中間状態は発生しません。 

[n, n-1, ..., 1] などの降順の初期スタックの場合、ロッド 1 にはすでに最上部に最小のディスクがあるため、最初の反復ですぐにロッド 3 に転送されます。ロッド 2 はロッド 1 にフラッシュバックされる前に少数以上の要素を蓄積することがないため、大きなバッファリングを必要とせずに徐々に露出します。 

高度にシャッフルされた構成では、ロッド 2 が一時ストレージとしてアクティブになりますが、次のターゲット ディスクが処理される前に各障害物がローカルで解決されるため、各ディスクの移動回数は制限されています。
