 ## 解決策
 ## 問題の理解

 それぞれに数値スキル値を持つ 2n 人の生徒のコレクションが与えられました。 最初に、生徒は固定のペア、具体的には連続したインデックスにグループ化されるため、生徒 1 は 2 とペアになり、生徒 3 は 4 とペアになります。 タスクは、1 つの制限を尊重しながら、すべての生徒を n 個の新しいペアに完全に再ペアにすることです。元のペアはいずれも、新しい配置でペアとして再び出現することは許可されません。 

新しい組み合わせごとに、2 人の生徒のスキル値の絶対差に等しいコストがかかります。 目標は、すべてのペアの総コストを最小限に抑える有効な再ペアリングを選択することです。 

構造は重要です。すべてのスチューデントは 1 回だけ使用する必要があり、禁止されたペアは元の n 個の互いに素なエッジとまったく同じです。 

n が 100000 までという制約は、2n が 200000 要素までであることを意味します。 どの解も線形または n log n に近いものでなければなりません。 すべてのマッチングを列挙したり、任意のペア間の互換性をチェックしたりするには、(2n)^2 回以上の演算が必要になるため、すべての生徒を対象とした 3 次または 2 次のペアリング戦略は不可能です。 

単純にすべての値を並べ替えて近傍をペアにしようとすると、単純な貪欲ペアリングの微妙な失敗例が現れます。 これは、禁止されたペアを誤って再作成する可能性があるため、正しくありません。 

たとえば、n = 2 で次の値があるとします。```
1 2 3 4
```元のペアは (1,2) と (3,4) です。 並べ替えても同じ順序が維持されます。 隣接する要素をペアリングすると (1,2) と (3,4) が得られますが、制約のないマッチングでは最適ですが、これは禁止されています。 正しい解決策は、これらの固定エッジを回避するために、一致する構造をわずかに混乱させる必要があります。 

もう 1 つのよくある落とし穴は、元の各ペア内でのローカル スワップです。 これでは、ペアごとに 2 つの選択肢のみが生成され、ペア間の相互作用が無視されます。これは制限が厳しすぎるため、最適なグローバルな再配置を逃す可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、n 個の禁止エッジを除外しながら、2n 個のノード上のすべての可能な完全一致が考慮されます。 完全一致の数は指数関数的で、約 (2n) です。 / (2^n n!)、禁止エッジを枝刈りしても、実行可能なほど十分に削減されません。 サブセット上の DP でも O(2^(2n)) 状態が必要ですが、200000 までの 2n では不可能です。 

重要な観察は、禁止された構造が非常に規則的であるということです。つまり、連続するインデックスで完全に一致します。 これは、ペアを原子単位として考え、これらの単位がどのように相互作用するかを決定することを示唆しています。 

すべての生徒をスキル別に分類すると、制約のない最適なマッチングにより、隣接する要素がペアになります。 唯一の問題は、一部の隣接する要素が禁止されたペアに正確に対応することです。 そこで問題は、2 つの既知の位置をそれぞれ接続する n 個の特定のエッジを回避しながら、ソートされた完全一致をどのように「修正」するかということです。 

これを理解する便利な方法は、元の各ペアをセグメントとして扱うことができ、各セグメントが 2 つの候補を提供することです。 ソート後の最適なソリューションでは、要素を順番に照合する必要がありますが、禁止されたエッジが発生する場合は常に、隣接するペア間でパートナーを交換することによってそれを「スキップ」する必要があります。 これにより、当然のことながら、遷移が連続する要素のローカル構造のみに依存する、ソート順序を超えた動的プログラミングが行われます。 

結果として得られる解決策は、並べ替えてからペアを貪欲に構築することになりますが、その一方で、2 つの連続する要素が禁止されたペアを形成する場合は、代わりに、コストを最小限に抑えながらそのエッジを回避する唯一の方法で境界を越えてペアにする必要があります。 このローカル修復構造により、グローバル検索が必要なくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースマッチング | O((2n)!) | O(n) | 遅すぎる |
 | ソート + ローカル修復マッチング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを思い出しながら、すべての 2n 値を読み取ります。 禁止されたペアは値ではなく固定のインデックス構造によって定義されるため、インデックスが重要になります。 
2. 元のインデックスを追跡しながら、スキル値で生徒を並べ替えます。 並べ替え後、制約のない最適なペアリングは、単純に連続する要素と一致します。 
3. ソートされたリストを左から右に繰り返し、可能な限り i と i + 1 のペアを試みます。 これは、絶対的な差異を最小限に抑えるための自然な貪欲な構造です。 
4. ペア (i, i + 1) にコミットする前に、それらの元のインデックスが禁止されたペアを形成しているかどうか、つまりそれらが同じ初期 (2j − 1, 2j) ブロックからのものであるかどうかを確認します。 そうでない場合は、そのペアを受け入れます。 
5. それらが禁止されたペアを形成した場合、それらのペアを避ける必要があります。 代わりに、ペアリングをローカルにシフトします。つまり、i と i + 2、i + 1 と i + 3 をペアにして、効果的に隣接構造を交換します。 これにより、無効なエッジを排除しながら、ソート順序の最適性が維持されます。 
6. スワップの実行時にインデックスを適切にスキップし、各要素が 1 回だけ使用されるようにしてプロセスを続行します。 

重要な考え方は、競合は同じ元のペアに由来する連続する並べ替えられた要素間でのみ発生するということです。 このような競合を解決するには、4 つの要素をローカルに再構成するだけで済みます。 

### なぜ効果があるのか

ソート後、制約のない最適解は、コスト関数がソートされた順序で凸であるため、隣接する順序で要素をペアにする必要があります。 この構造からの唯一の逸脱は、禁止されたエッジから生じます。 各禁止エッジは、ソートされた 2 つの連続する要素が同じ最初のペアに由来する場合にのみ表示されます。 その場合、最適なマッチングではそのエッジを回避する必要があり、最も安価な代替方法は、並べ替えられた隣接関係を維持する唯一の方法でこれら 4 つの要素を再接続することです。 競合はローカルであり、グローバルな調整が必要なほど重複していないため、左から右へ貪欲に解決することで全体の最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    a = [(c[i], i // 2) for i in range(2 * n)]
    a.sort()
    
    used = [False] * (2 * n)
    ans = 0
    
    i = 0
    while i < 2 * n - 1:
        if used[i]:
            i += 1
            continue
        
        j = i + 1
        while j < 2 * n and used[j]:
            j += 1
        
        if j >= 2 * n:
            break
        
        if a[i][1] != a[j][1]:
            ans += abs(a[i][0] - a[j][0])
            used[i] = used[j] = True
            i += 1
        else:
            k = j + 1
            while k < 2 * n and used[k]:
                k += 1
            if k >= 2 * n:
                break
            ans += abs(a[i][0] - a[k][0]) + abs(a[j][0] - a[k+1][0] if k + 1 < 2 * n else 0)
            used[i] = used[k] = True
            used[j] = used[k+1] = True
            i += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、整数の 2 による除算を使用して、各生徒に元のペア識別子をタグ付けすることから始まります。これにより、スキルごとに並べ替えた後、禁止されたペアを定期的にチェックできるようになります。 

貪欲スキャンでは、常に最も古い未使用要素と次に使用可能な未使用要素との一致を試みるポインターが使用されます。 これにより、ソートされた最適な構造が維持されます。 禁止されたペアが出現すると、アルゴリズムは次に利用可能な要素間でローカルな再ルーティングを実行し、元のペアが再構築されないようにします。 

実装の重要な詳細は、すでに使用されている要素をスキップすることです。 これがないと、ポインター ロジックが要素を誤って再利用したり、無効なオーバーラップを形成したりする可能性があります。 の`used`配列は正確さを保証するだけでなく、線形動作も保持します。

 ## 特殊なケース

 1 つのエッジ ケースは、ソートされた連続するペアがすべて同じ元のペア構造に属している場合に発生します。 次のような入力では`1 2 100 101`、ソートすると、隣接する禁止されたペアが繰り返し生成されます。 このアルゴリズムは、禁止されている各隣接関係を検出し、ローカル スワップを実行して、無効なペアリングが残らないようにします。 各スワップでは 1 つの禁止エッジのみが、同じ 4 つの要素間で最も安価な代替接続に置き換えられるため、結果は最適なままになります。 

もう 1 つのエッジ ケースは、値が高度にクラスター化されているため、多くのスワップが連続してトリガーされる場合です。 各スワップが要素の固定ブロックを消費し、カスケードの曖昧さを防ぐため、左から右へのスキャンは引き続き機能します。
