 ## 解決策
 ## 問題の理解

 私たちには、一組の人々と一連の集団新型コロナウイルス検査が与えられました。 各検査は人々のサブセットを検査し、そのサブセット内に少なくとも 1 人の感染者がいる場合に陽性を返します。 この問題では、すべての検査で陽性反応が得られたため、すべての検査グループには少なくとも 1 人の感染者が含まれています。 

結果が表示される前に、各人は確率 1/2 で独立して感染します。これは、前の段階では人々のすべてのサブセットの可能性が等しいことを意味します。 すべての検査結果が陽性であることを確認した後、すべての検査結果と一致する感染構成のみに注意を限定します。 これらの有効な構成の中で、各構成の可能性は同等であり、特定の人が感染する事後確率は、その人が含まれる有効な構成の数に比例します。 

タスクは正確な確率を計算することではなく、すべての検査が陽性であるという条件を付けた上で、感染する可能性が最も低い人から最も感染する可能性が高い人までランク付けすることです。 

重要な入力構造は、最大 1000 人が参加できますが、テストは最大 15 件であり、各テストは人々の小さなサブセットであるということです。 この不均衡こそが、この問題が扱いやすくなる理由のすべてです。検査数については指数関数的に作業を行う余裕がありますが、人数については余裕がありません。 

単純な試みでは、2^n 個の感染状態をすべて列挙し、どれがすべてのテストを満たすかを確認し、1 人あたりの寄与をカウントしようとします。 2^1000 は実行可能な計算をはるかに超えているため、これはすぐに失敗します。 

より微妙な失敗モードは、個人ごとの確率を個別にシミュレートしようとすることから生じます。 テストはグローバルな制約の中で人々を結合するため、テスト間の相互作用を追跡せずに人ごとにローカルな推論を行うと、不正確な相対ランキングが発生します。 

有用なエッジケースは、すべてのテストが重度に重複する場合です。 たとえば、すべてのテストに人物 1 が含まれている場合、構成が存在する場合は常に、人物 1 がすべての有効な構成に自動的に含まれるため、他のテストよりも厳密にその可能性が高くなります。 テストごとの平均化アプローチでは、この優勢効果が見逃されます。 

もう 1 つのエッジ ケースは、テストがユニバースを分割し、重複しない場合です。 その場合、すべての人は対称的になる傾向があり、正しい解決策は数​​値的なドリフトを導入するのではなく、正確な平等を維持する必要があります。 

## アプローチ

 ブルートフォース戦略では、人々の各サブセットが感染候補セットとして扱われます。 サブセットごとに、すべてのテストに少なくとも 1 人の選択された人物が含まれているかどうかを検証します。 感染した場合、そのサブセット内のすべての感染メンバーの数が増加します。 これは確率的解釈に直接従うので正しいですが、すべての 2^n サブセットを反復処理し、サブセットごとに m 回のテストをチェックする必要があり、おおよそ O(2^n · m) が得られますが、これは n が 1000 までの場合はまったく実行不可能です。 

m が小さいことを観察すると、問題の構造が変わります。 人々のサブセットを反復処理する代わりに、視点を反転して、テスト全体の包含と除外を扱うことができます。 一部のテストが完全に感染していないという悪いイベントが回避される場合、構成は有効です。 それぞれの悪いイベントは、特定の人々のサブセットに感染がないことのみに依存しており、わずか 15 回の検査で、これらのイベントのすべての組み合わせを列挙できます。 

主なアイデアは、すべてのサブセットから開始して、少なくとも 1 つのテスト制約に違反するものを差し引いて、テスト サブセットに対する包含/除外を使用して重複を修正することによって、有効な感染セットをカウントすることです。 有効なセットを効率的にカウントできるようになったら、固定の人が感染していなければならないという追加の制約を付けて同じカウントを繰り返します。 この 2 つの数値の差によって、その人の体重が決まります。

テストは最大 15 個しかないため、2^m 個のテスト サブセットをすべて列挙することは可能です。 テストの各サブセットについて、人々の集合の結合のサイズを知る必要があるだけです。これは、これらすべてのテストを同時に回避する感染構成の数が決定されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 人々のサブセットに対するブルートフォース | O(2^n・m) | O(n) | 遅すぎる |
 | テストにおける包含排除 | O(n · 2^m + m · 2^m) | O(2^m・n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、テストのサブセットごとにテスト グループのすべての和集合を事前計算します。 これはサイズ m のビットマスクに対して実行され、そのサブセット結合によってカバーされる個別の人の数が格納されます。 これにより、後でそれらの人々を効率的に回避する割り当ての数を計算できるようになります。 

次に、人 i を固定し、感染させることを強制します。 これにより、制約を変更しながら、問題を残りの n − 1 人に絞り込みます。つまり、すでに感染者がいるテストには、すでに人 i が含まれているテストは自動的に満たされます。 他の感染者が満足する必要があるのは、i が含まれていない検査のみです。 

各個人 i に対して、どのテストに i が含まれるかを示すテスト上のビットマスクを表します。 制約を適用する場合、ビットが 1 であるテストはその人にとって無関係になります。 

次に、残りのアクティブなテストのサブセットに対して包含/除外を適用します。 テスト K のサブセットについて、K のテストの和集合に含まれるすべての人々をカバーすることを避ける、残りの人々の感染構成を検討します。人々のセットを避けるということは、補集合から感染セットのみを選択することを意味するため、そのような構成の数は、除外される人の数に応じて 2 の累乗になります。 

これらの寄与を交互の符号で合計すると、人 i が感染しているという条件で、テストに違反しない有効な構成の数が得られます。 

最後に、すべての人のこの値を計算し、それによって並べ替えます。 

正しさは、テストのサブセットにわたる包含-排除が、少なくとも 1 つのテストに違反するすべての構成を正確に説明し、人物を修正すると、関連する各テストに存在するその人物がすでに満たしているすべての制約を単に削除するだけであるという不変条件に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    tests = []
    in_test = [[False] * m for _ in range(n)]

    for j in range(m):
        arr = list(map(int, input().split()))
        k = arr[0]
        group = [x - 1 for x in arr[1:]]
        tests.append(group)
        for v in group:
            in_test[v][j] = True

    size = [0] * (1 << m)
    for mask in range(1 << m):
        union = 0
        cnt = 0
        seen = set()
        for j in range(m):
            if mask & (1 << j):
                for v in tests[j]:
                    if v not in seen:
                        seen.add(v)
                        cnt += 1
        size[mask] = cnt

    total = 1 << (n - 1)
    ans = []

    for i in range(n):
        allowed = ((1 << m) - 1) ^ 0
        mask_i = 0
        for j in range(m):
            if in_test[i][j]:
                mask_i |= (1 << j)

        res_bad = 0

        for K in range(1, 1 << m):
            if K & mask_i:
                continue

            # compute union size of tests in K
            seen = set()
            cnt = 0
            for j in range(m):
                if K & (1 << j):
                    for v in tests[j]:
                        if v not in seen:
                            seen.add(v)
                            cnt += 1

            sign = 1 if bin(K).count("1") % 2 == 1 else -1
            # inclusion-exclusion for bad sets
            res_bad += sign * (1 << ((n - 1) - cnt))

        ans.append((total - res_bad, i + 1))

    ans.sort(key=lambda x: (x[0], x[1]))
    print(*[x[1] for x in ans])

if __name__ == "__main__":
    solve()
```このソリューションは、人からテストへの隣接関係を構築することから始まります。これにより、人が感染していると判明したときにどの制約が重要かを迅速にフィルタリングできるようになります。 人々に関するメインループは、無関係なテストのビットマスクを再計算し、まだ満たす必要があるテストのサブセットに対して包含/除外を実行します。 

べき乗`1 << ((n - 1) - cnt)`これは、現在の包含-除外サブセットによって強制的に排除されている人を除くすべての人々に対して任意の感染パターンを選択することに相当します。 交互の符号により、過剰にカウントされた構成が確実に修正されます。 

最終的な並べ替えでは、計算された重みが直接使用され、同順位はインデックスによって自動的に分割されます。

 ## 特殊なケース

 すべてのテストに人物が現れると、その人物が含まれると、すべての制約が自動的に満たされます。 アルゴリズムは、その人物が関係するテストを含むすべてのテスト サブセットをスキップすることでこれを反映し、アクティブな制約の数を効果的に減らし、その重みを増やします。 

ある人がテストに何も出ていない場合、制約を満たすことはできません。 包含-除外フレームワークでは、これは、その人を条件付けするときにテストが削除されないことを意味するため、制約の複雑さはすべて継承され、通常は確率が低くなります。 

テストが同一であるか、重なり合う場合、包含-排他における結合サイズが小さくなり、アルゴリズムは共有制約を早期に満たす構成の寄与を正しく増幅し、対称性を維持し、過剰カウントを回避します。
