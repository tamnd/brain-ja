 ## 解決策
 ## 問題の理解

 ゲームは一連のレルムで構成されており、順番にクリアする必要があります。 プレイヤーはレルム 1 から開始し、レベル 1 と初期​​体力を自由に選択します。 各レルムには小さな敵のコレクションが含まれており、各レルムでプレイヤーはそれらの敵の空でないサブセットを選択して戦うことになります。 

レルム内での戦いは、選択されたサブセットによって完全に決定されます。 選択した敵がまだ生きている間、現在生きているすべての敵はその強さの合計に等しいダメージを与え、プレイヤーはターンごとに生きている敵を 1 人だけ殺します。 キルごとにプレイヤーのレベルが 1 ずつ増加し、固定最大レベル m まで増加します。 レルム内で選択したすべての敵を倒すと、プレイヤーは最終レベルに応じて回復し、次のレルムに進みます。 目的は、最終的にレベル m に到達しながらすべてのレルムを完了することであり、これを可能にする最小限の初期体力が必要です。 

重要な難しさは、各領域で戦う敵のサブセットを選択することで、ダメージ パターンと得られるレベルアップの数の両方が決定されることです。 レベルは後の治癒に影響するため、初期の決定は後のすべての領域に影響します。 

この制約は、単純な方法では任意のサブセットをシミュレートできないことをすでに示唆しています。 最大 100 のレルムがあり、各レルムには最大 2000 人の敵が含まれますが、敵の総数は少なくとも m − 1 であるため、レベル m に到達するには、全体で少なくとも m − 1 人の敵を倒す必要があります。 m の値は最大 50,000 であるため、レベルの進行はシステムのグローバルな状態であり、レルムごとに指数関数的に個別に再計算できるものではありません。 

単純な考えとしては、レルムごとに敵のすべてのサブセットを試したり、ローカルのダメージ効率に基づいてサブセットを貪欲に選択したりすることも考えられます。 ダメージの順序とレベルの増加の間の相互作用はグローバルであるため、どちらも失敗します。 

レルムに多数の弱い敵と少数の強い敵が含まれる場合、微妙なエッジケースが発生します。 強い敵と早い段階で戦うと、即時ダメージが大幅に増加しますが、ユニットが受けるダメージごとに利用できるレベルアップの数が減少する可能性があります。 逆に、弱い敵とだけ戦うと、ターンが長くなり、フルセット攻撃の繰り返しにより総ダメージが増加する可能性があります。 

もう 1 つのエッジ ケースは、レルム内で敵をスキップすることが有益であるように見えても、実際には早期にレベル m に到達するのを妨げる場合です。これにより、後で治癒値が変更され、たとえローカルの健康状態が十分であるように見えても、パスが実行不可能になります。 

## アプローチ

 直接的な総当たりアプローチでは、レルムごとに敵のサブセットと殺害の順序を選択し、ゲーム全体をシミュレートしようとします。 順序を無視したとしても、各レルムには最大 2^{2000} 個のサブセットがあるため、これはまったく実行不可能です。 サブセット サイズのみを考慮するように制限したとしても、レルム全体の可能性の数は n で指数関数的に増加します。 

最初の重要な観察は、レルムの選択されたサブセット内では、最適なプレイ順序が敵の強さによって決定されるということです。 いつでも、生きているすべての敵は最大の合計ダメージを与えるため、強力な敵をより長く生かし続けると、蓄積されるダメージの合計が増加するだけです。 これは、固定サブセットの場合、最適な戦略は、強さの増加しない順に敵を倒し、現在最も強い残りの敵を常に除去することであることを意味します。 

この順序を修正すると、各サブセットは、レベルの増加に対応するダメージとキル数に関して決定的なコストを生成します。 

2 番目の観察は、実際には任意のサブセットを考慮する必要がないということです。 各レルムについて、強さによって敵を並べ替えると、最適なサブセットは、この並べ替えられた順序の接頭辞を取得することに対応します。 これは、弱い敵をスキップしてより強い敵を攻撃した場合、レベルアップの数を変更せずに、初期ターンのダメージのみが増加するためです。

したがって、各レルムは、含める最弱の敵の数を選択し、最適な殺害順序 (選択したセット内で最も強いものから最も弱いものまで効果的に殺す) で k 人の最も弱い敵を倒すコストをシミュレートできます。 

ここで、問題はレベルをめぐる全体的な DP になります。敵を倒すたびにレベルが 1 ずつ増加し、レベル m に到達する必要があります。 すべてのレルムにわたる合計キル数は m − 1 に固定されているため、必要な初期 HP を最小限に抑えながら、これらのレベルアップをレルム全体に分散することになります。 

各レルムとそこから得られるキル数ごとに、正確に k 人の敵を最適に倒した場合にそのレルムで被る合計ダメージを計算できます。 これにより、レベル x から x + k への遷移のリストが生成されます。これには、ダメージのコストと、結果のレベルに応じた治癒効果が含まれます。 

次に、レベル全体にわたって最短パスのような DP を実行します。ここで、状態は、特定のレベルのレルムに入る前に最低限必要な健全性です。 移行は、現在のレルムで k 人の敵を選択し、ダメージ コストを追加し、最終レベルに基づいてレルムの後に治癒を適用することで行われます。 

この構造により、各レルムをレベル間の小さな遷移グラフとして扱うことができ、グローバル ソリューションは階層化された DP 遷移のシーケンスになります。

 ## アルゴリズムのチュートリアル

 DP 配列を維持しながら、レルムを 1 つずつ処理します。ここで dp[l] は、レベル l で現在のレルムに入るために必要な最小限の健全性を表します。 

各レルムについて、k 人の敵を倒すと状態がどのように変化するかを計算します。 

1. 敵を強い順に並べ替えます。 これにより、殺害をシミュレートするときに、常に最も強力な残りの敵を最初に除去し、蓄積ダメージを最小限に抑えることが保証されます。 
2. この順序で強さのプレフィックス合計を構築します。 これらのプレフィックスの合計により、複数の敵が同時に生きている場合に、合計ダメージの寄与を高速に計算できます。 
3. 1 から ki までの考えられる k ごとに、k 人の敵を攻撃した場合に被る合計ダメージを計算します。 このダメージ パターンは、k 人の敵が生きている場合、各ターンで残りのすべての強さの合計が寄与し、敵を 1 人ずつ倒すにつれて減少するために発生します。 
4. 各 k を遷移として解釈します。レベル l から開始して、k キルを取るとレベル min(m, l + k) に移動します。コストはそれらの k 人の敵に対する計算されたダメージです。 
5. レルムごとに、新しい DP 配列 ndp を大きな値で初期化します。 開始レベル l ごとに、l + k が m + 1 を超えないようにすべての有効な k を試し、dp[l] にダメージを加えたものを使用して ndp[l + k] を更新し、レベル l + k でレルムを終了した後に治癒を減算します。 
6. dp を ndp に置き換えて、次のレルムに進みます。 

答えは dp[m] です。これは、すべてのレルムを処理した後にレベル m に到達するために必要な最小限の初期ヘルスを意味します。 

### なぜ効果があるのか

 正しいかどうかは、どのサブセット内でも、より強力な敵の除去を遅らせても総ダメージが増加するだけであるという事実にかかっています。 したがって、強度を下げることによってソートすると、最適な内部順序が得られます。 この順序が固定されると、k 人の敵を倒すコストは決定的となり、他の領域から独立したものになります。 その後、DP は蓄積されたキル数のみを追跡し、各キルは 1 つのレベルアップに正確に対応するため、状態を失ったり重複したりすることはありません。 治癒関数は最終レベルにのみ依存するため、各レルムを終了した後にのみ適用すると正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))
    
    realms = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        mobs = arr[1:]
        mobs.sort(reverse=True)
        realms.append(mobs)

    INF = 10**30
    
    dp = [INF] * (m + 1)
    dp[1] = 0  # start at level 1 with 0 required damage taken so far

    for mobs in realms:
        k = len(mobs)

        # prefix sums of sorted strengths
        pref = [0] * (k + 1)
        for i in range(k):
            pref[i + 1] = pref[i] + mobs[i]

        ndp = [INF] * (m + 1)

        for lvl in range(1, m + 1):
            if dp[lvl] == INF:
                continue

            # try taking t enemies
            cur_sum = 0
            for t in range(1, k + 1):
                if lvl + t > m:
                    break

                # compute damage for taking first t strongest enemies
                # each remaining set contributes repeatedly; derive incremental cost
                cur_sum += pref[t]

                new_lvl = min(m, lvl + t)
                cost = dp[lvl] + cur_sum

                # apply healing based on final level
                heal = h[new_lvl - 1] if new_lvl >= 1 else 0
                cost -= heal

                if cost < ndp[new_lvl]:
                    ndp[new_lvl] = cost

        dp = ndp

    print(dp[m])

if __name__ == "__main__":
    solve()
```DP アレイは、レルムのプレフィックスを処理した後、各レベルに到達するために必要な最小のネットヘルス損失を追跡します。 各レルムは、そこで戦うために選択した敵の数に基づいて、一連の遷移に貢献します。 内側のループは、さらに 1 人の敵を追加すると、その強さの合計によって以前のすべてのターンのダメージが増加するため、ダメージを段階的に蓄積します。これは、プレフィックスの蓄積によって捕捉されます。 

実装でよくある落とし穴は、治癒が各キルの後ではなく、レルムを終了した後のレベルに依存することを忘れていることです。 そのため、ヒーリングは内側のループ内ではなく、トランジションごとに 1 回適用されます。 

もう 1 つの微妙な点は、m によるレベルの境界です。 レベル m に達すると、それ以上の kill は状態遷移には無関係になるため、不必要な計算を避けるためにクランプします。

 ## 特殊なケース

 レルムに単一の非常に強い敵と多数の弱い敵が含まれる場合、重大なエッジケースが発生します。 アルゴリズムは降順でソートすることでこれを処理し、強い敵が最初に倒されるようにするため、そのダメージはターンをまたいで繰り返し適用されるのではなく、1 回だけ適用されます。 

もう 1 つのエッジケースは、プレイヤーが早期にレベル m に到達する場合です。 DP はレベルをクランプするため、それ以上キルしても状態空間は拡張されません。 これにより、m がMob の合計よりもはるかに小さい場合でも、不必要な遷移が防止され、正確さが保証されます。 

最後のエッジケースは、高レベルでの回復が被ったダメージよりも大幅に大きい場合です。 マイナスの実効コスト遷移が許可され、それに応じて状態がより低い必要な初期健全性値を介して伝播するため、DP はこれを自然に利用します。
