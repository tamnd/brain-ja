 ## 解決策
 ## 問題の理解

 チョコチップとイチゴの2種類のポイントが入ったユニットスクエアケーキをいただきました。 ケーキを貫通する直線セグメントを 1 つだけ描くことができます。 カット後、ラインの片側を子供に与えるピースとして選択しますが、このピースにはイチゴが含まれていてはいけないという制限があります。 このようなすべての有効な選択肢の中で、選択した側にあるチョコレート チップの数を最大化したいと考えています。 

各成分は平面内の点であるため、選択している幾何学オブジェクトは線で定義された半平面になります。 「食材を貫通しない」という制約は、線が特定の点を通過できないことを意味します。 同様に、すべての点は厳密に線の両側の一方に位置する必要があります。 

出力は単一の整数、つまりすべてのイチゴ ポイントから 1 本の線で分離できるチョコレート ポイントの最大数です。 

制約は非常に非対称です。チョコレート ポイントは最大 50,000 ポイントですが、イチゴは最大 100 個までです。 これは、チョコレートの二次関数に依存する解決策は実行不可能である一方、イチゴの二次関数はまだ許容される可能性があることを即座に示唆しています。 点のペアまたはチョコレートのすべての分割によって引き起こされるすべての候補の分割線を評価しようとする単純なアプローチでは、少なくとも O(n^2) またはそれより悪い幾何学的チェックが必要になります。これは、最大 50,000 までの n の制限をはるかに超えています。 

すべてのチョコレートがすべての有効なストロベリー セパレータ方向の片側にある場合、微妙なエッジ ケースが発生します。 たとえば、イチゴがぎっしりと集まっていて、その周りをチョコレートが囲んでいる場合、答えはすべてチョコレートである可能性があります。 逆に、イチゴがチョコレートを「包み込む」場合、大きな部分集合はまったく分離できない可能性があります。 素朴な推論によるもう 1 つの失敗モードは、イチゴの凸包だけで十分であると仮定することです。 分離線はイチゴに触れないようにする必要はなく、イチゴを避けるためだけなので、そうではありません。 

## アプローチ

 重要な幾何学的な再定式化は、イチゴを区切る線の意味を修正することです。 すべてのイチゴがその片側に厳密に配置されている場合、そのラインは有効です。 そのようなラインでは、より多くのチョコレートが含まれる側を自由に選択できます。 

したがって、ラインそのものについて考えるのではなく、その方向について考えます。 すべての有向線は半平面を定義し、すべてのイチゴが同じ開いた半平面内に位置し、その同じ半平面内でチョコレートが最大化されるような方向が必要です。 

この強引なアイデアは、すべての材料の中の 2 つの点によって決定されるすべての可能な線を考慮することです。 このような各行は区切り記号の候補として使用でき、どちらの側が有効であるかをテストしてチョコレートの数を数えることができます。 このような行は O((n+m)^2) 個あり、各チェックのコストは O(n) であるため、最悪の場合は 3 次になり、非常に遅すぎます。 

主な観察は、制約が完全にイチゴに由来しており、イチゴは 100 個しかないということです。 有効な分離線は、イチゴ セットの周囲の角度位置によって決まります。 参照点を固定して光線をスイープすると、角度によるイチゴの順序は安定しており、重要な遷移を列挙するのに十分な大きさになります。 

幾何学的な考え方は、切断線の方向を固定するか、同様に法線ベクトルを固定することです。 特定の方向について、署名された投影を確認することで、すべてのイチゴが片側にあるかどうかを判断できます。 これにより、有効性チェックが方向ごとに O(m) に削減されます。 次に、有効な側に最大のチョコレートが含まれる方向を見つけます。

任意の方向を繰り返す代わりに、分離線がイチゴに接するか、2 つのイチゴによって定義される角度の境界を通過する場合にのみ、実現可能性に関連する変化が発生することに注意します。 したがって、イチゴの各ペアは、掃引線に関して相対的な順序が反転する重要な方向を定義するため、候補方向は O(m^2) に減らすことができます。 m ≤ 100 の場合、最大でも約 10,000 方向が得られ、これは管理可能です。 

候補となる方向ごとに、その方向と一致する分離半平面を計算し、すべてのイチゴ (存在する場合) がどちらの側に含まれているかを判断し、その同じ半平面にあるチョコレートの数を数えます。 チョコレートの数が実行時間の大半を占めますが、注意して実装すれば、許容可能なパフォーマンスで 10,000 方向に対して 50,000 ポイントで実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (全行) | O((n+m)^3) | お(1) | 遅すぎる |
 | イチゴに対する角度列挙 | O(m^2 (n+m)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各イチゴを、最終ラインの同じ側に厳密に配置する必要がある幾何学的制約として扱います。 これは、分割線がイチゴのセットと交差しない半平面を定義する必要があることを意味します。 
2. 順序付けられたイチゴのペアごとに、それらを通過する線から導出される候補分離方向を構築します。 この方向は、「有効な側」が組み合わせ的に変化する潜在的な境界を表します。 
3. このような方向ごとに、線の法線ベクトルを定義し、線のどちら側が安全な半平面の候補であるかを決定します。 向きは、イチゴが常に片側に配置されるように選択されます。 それが不可能な場合は、その指示を直ちに破棄してください。 
4. 有効な半平面が確立されたら、すべての点を反復処理して、その半平面内に厳密に存在するチョコレートの数を数えます。 イチゴは有効性が保証されているため除外されているため、カウントされません。 
5. すべての有効な方向にわたって最大チョコレート数を追跡​​します。 

重要な点は方向性の一貫性です。 特定の有向線について、外積の符号によってどちらの側が正であるとみなされるかが決まります。 方向を反転すると、同じ幾何学的な線が得られますが、半平面が入れ替わるため、常に候補ごとに方向を正規化する必要があります。 

### なぜ効果があるのか

 最適な分離線は、実現可能性を損なうことなく、臨界状態になるまで継続的に回転させることができます。つまり、2 つのイチゴに接触または整列します。 この回転中、各側の点のセットは、線がイチゴを通過するか、一対のイチゴと同一直線上になる離散イベントでのみ変化します。 したがって、これらのイベント定義の方向のみをチェックするだけで十分です。 すべてのイチゴは最大 100 ポイント内にあるため、このような重要なイベントはすべてペアに対応し、候補セットの完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def side(x, y, a, b, c, d):
    return cross(a, b, x, y) >= cross(a, b, c, d)

def solve():
    n, m = map(int, input().split())
    pts = []
    for _ in range(n + m):
        x, y = map(float, input().split())
        pts.append((x, y))

    ch = pts[:n]
    st = pts[n:]

    if m == 0:
        print(n)
        return

    best = 0

    # iterate over candidate separating directions induced by strawberry pairs
    for i in range(m):
        for j in range(i + 1, m):
            xi, yi = st[i]
            xj, yj = st[j]

            dx = xj - xi
            dy = yj - yi

            # normal vector candidates: perpendicular directions
            # we test one orientation; flipping handled implicitly by max side choice
            nx, ny = -dy, dx

            # skip degenerate
            if nx == 0 and ny == 0:
                continue

            # decide which side strawberries lie on (using i as reference side)
            # we want st[k] all on same side; pick side based on majority consistency
            def ok(sign):
                for xk, yk in st:
                    v = cross(nx, ny, xk - xi, yk - yi)
                    if sign * v < 0:
                        return False
                return True

            valid = False
            for sign in [1, -1]:
                if ok(sign):
                    valid = True
                    break

            if not valid:
                continue

            # count chocolates on that side
            for xk, yk in ch:
                v = cross(nx, ny, xk - xi, yk - yi)
                if v * sign >= 0:
                    best += 1

            best = max(best, best)

    print(best)

if __name__ == "__main__":
    solve()
```この実装では、チョコレートとイチゴを分離し、イチゴのペアを反復して候補の方向を定義します。 各方向について、垂直変換を使用して法線ベクトルが計算されます。 すべてのイチゴがラインの一貫した片側に配置されるように方向がテストされます。 

ここでよくある落とし穴は、外積で使用される基準点を混同することです。 表現`(xk - xi, yk - yi)`すべてのチェックをペア内の 1 つのイチゴに相対的に固定します。外積は相対的な側面のみを決定するため、これで十分です。 もう 1 つの微妙な問題は、厳密な分離を確保することです。 外積の等しさは共線性に対応しますが、この問題では許可されていないため、これらのケースは無効として扱うか、候補の生成では回避する必要があります。 

最終的なカウントでは、選択した半平面条件を満たすチョコレートが集計されます。

 最良の選択は、下半分の平面を維持し、両方のイチゴを除外しながら 2 つのチョコレートをキャプチャします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m² · (n + m)) | 各イチゴのペアは方向を定義し、各方向はすべての点をスキャンします。 
| スペース | O(n + m) | 点セットのストレージ |

 m ≤ 100 の場合、m² は最大 10,000 であり、方向ごとに 50,000 点をスキャンすると、最悪の場合でもおよそ 5×10⁸ の原始演算が発生します。これは境界線ですが、最適化された演算と無効な方向の早期拒否により許容可能です。 m の厳密な制限は、このアプローチを可能にする重要な構造特性です。

 ## 特殊なケース

 重要なエッジケースは、イチゴが分割候補線と同一線上にある場合です。 このような構成では、単純な外積チェックによって境界点が誤って有効なものとして扱われる可能性があります。 たとえば、チョコレートが 2 つのイチゴを通る線上に正確にある場合、符号はゼロになるため除外する必要があります。除外しないと、アルゴリズムが無効な構成としてカウントする可能性があります。 実装では、等価性を許可されていないものとして扱う必要があります。 

すべてのイチゴがほぼ同一線上にある場合、別の特殊なケースが発生します。 この場合、多くの候補方向が同様の半平面に崩れ、重複した評価が発生する可能性があります。 このアルゴリズムは各ペアを独立して処理するため引き続き機能しますが、注意を怠ると、反復ごとに結果が適切にリセットされない限り、カウントが繰り返される可能性があります。 

最後に、イチゴがすべてのチョコレートの周囲に凸状のエンベロープを形成すると、すべての有効な半平面が高度に制約されます。 アルゴリズムは依然としてすべての方向を列挙しますが、ほとんどはパフォーマンスに不可欠な実現可能性テストにすぐに合格しません。
