 ## 問題の理解

 基本文字列が与えられています`s`。 Momo は毎日、内部で文字列を変更するのではなく、元の文字列のコピーを連結してより長い文字列を構築します。`s`。 1 日目以降、文字列は正確に次のようになります。`s`。 2日目以降はこうなります`s + s`。 k日目以降は、`s`k回連続で繰り返しました。 

ボボは別の弦を持っています`t`。 問題は、次のように最小の日数 k を決定することです。`t`を繰り返すことによって形成された文字列の部分列として見つけることができます。`s`ちょうどk回です。 

サブシーケンスとは、順序を変更せずに繰り返し文字列から文字を削除できることを意味します。`t`。 

重要な問題は、次のことを尋ねられないことです。`t`固定文字列の部分列ですが、繰り返しの最小数です。`s`それが可能になるために必要です。 

制約により両方が許可されます`s`そして`t`最大 500,000 文字までです。 これにより、繰り返される文字列を明示的に構築するアプローチは即座に除外されます。 最大サイズの文字列を 2 回繰り返すだけでもすでにメモリ制限を超えており、答えを構築することは不可能です。 

という点にも注意が必要です。`t`スキャンを何度も繰り返す必要がある場合があります`s`。 1 日あたりの単純なサブシーケンス チェックでは、最大 k 個のパス オーバーがシミュレートされます。`s`、二次またはそれより悪い動作を与えます。 

いくつかのエッジの状況が重要です。 

もし`t`に存在しない文字が含まれています`s`の場合、一般的には不可能ですが、ステートメントでは答えが存在することが保証されているため、このケースは除外されます。 

もし`t`はすでに次のサブシーケンスです`s`、答えは1です。 

の文字の場合`t`一致するとスキャンが強制的に再開されるように分散されています`s`多くの場合、答えは大きくなる可能性がありますが、繰り返される文字列を明示的に構築せずにこれを検出する必要があります。 

## アプローチ

 直接的な総当たり戦略は、毎日シミュレーションすることです。 k 日目には、概念的に構築します`s`k回繰り返して、`t`は、2 ポインター スキャンを使用するサブシーケンスです。 このサブシーケンス チェックは、構築された文字列の長さに対して線形であるため、1 日あたり O(k · |s| + |t|) となります。 

最悪の場合、k 自体が |t| と同じくらい大きくなる可能性があります。たとえば、`t`のコピーごとに 1 文字のみに一致します`s`。 これにより、O(|s| · |t|) 付近が全体的に複雑になり、5 · 10^5 の制限には遅すぎます。 

重要な点は、繰り返される文字列を明示的に構築する必要がないということです。 代わりに、循環的にサブシーケンスのマッチングを貪欲にシミュレートします。`s`。 

スキャンします`t`左から右にポインタを維持します`s`。 次の文字と一致しない場合`t`現在のスキャンで`s`、次のコピーに「ラップアラウンド」します。`s`これは、翌日の繰り返し境界に移動することに正確に対応します。 スキャンを再開するたびに`s`、日カウンターをインクリメントします。 

これが機能するのは、部分シーケンスのマッチングが相対的な順序と繰り返しにのみ依存するためです。`s`単に別の同一のスキャンウィンドウを提供するだけです。 

これを効率的に行うために、各文字の位置を前処理します。`s`これにより、配列を使用して O(log σ) または O(1) 内の次の有効な出現箇所にジャンプできるようになります。 ただし、さらに単純な O(n + m) 貪欲な場合は、スキャンによって機能します。`s`ポインターリセットを繰り返し使用します。 

このプロセスは、繰り返しトラバースすることに相当します。`s`消費しながら`t`。

 ## アルゴリズムのチュートリアル

 マッチングをシミュレーションします`t`の繰り返しコピーのサブシーケンスとして`s`構築せずに。 

1. ポインタを初期化する`i = 0`文字列用`t`そしてカウンター`days = 1`、現在、最初のコピーの中にいることを表します。`s`。 

ポインタも維持します`j = 0`スキャン用`s`。 
2. その間`i < len(t)`、一致を試みます`t[i]`スキャンすることで`s`位置から始める`j`。 
3. 移動`j`前方に進む`s`どちらかになるまで`s[j] == t[i]`あるいは終わりに達する`s`。 

このステップは、現在の繰り返し内で次の一致を見つけようとすることを表します。 
4. 一致するものが見つかった場合`s[j] == t[i]`、両方のポインタを進めます (`i += 1`、`j += 1`) 続けてください。 

これにより、サブシーケンスの順序が維持されます。 
5. もし終わりに達したら`s`一致するものが見つからない場合は増分します`days`、リセット`j = 0`、スキャンを続行します`s`最初から。 

これは、次の繰り返されるコピーに移動することに対応します。`s`。 
6. すべての文字が表示されるまで繰り返します。`t`一致しています。 

最終的な値は、`days`必要な最小繰り返し回数です。 

### なぜ効果があるのか

 いつでも、アルゴリズムは、次の無限連結にわたる走査を効果的にシミュレートしています。`s`。 疲れ果てるたびに`s`仕上げずに`t`、次の同一のブロックに移動することを強制されます。 すべてのブロックは同一であるため、重要な状態は内部の現在の位置だけです。`s`と現在のインデックス`t`。 貪欲スキャンにより、各文字が`t`現在または次のコピーの最も早い位置で一致する`s`, そのため、ブロックを不必要に使いすぎることはありません。 これにより、最小限の日数に正確に対応する最小限のリセット回数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    n = len(s)

    i = 0
    j = 0
    days = 1

    while i < len(t):
        if j == n:
            days += 1
            j = 0

        if s[j] == t[i]:
            i += 1
            j += 1
        else:
            j += 1

    print(days)

if __name__ == "__main__":
    solve()
```コードは 2 つのポインターを維持します。1 つはオーバーです。`t`そして現在のコピーの上に 1 つ`s`。 をスキャンすると、`s`終了したら、日カウンターをインクリメントし、スキャンを再開します。 重要な実装の詳細は、繰り返される文字列を決して構築しないことと、ポインタ`j`現在の繰り返し内の仮想位置として機能します。 

微妙な点は、リセットする必要があるということです`j`まさにそれが届くとき`len(s)`不一致があっても同じ繰り返し内でスキャンを進める必要があるため、一致が失敗した場合ではありません。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`t`フルスキャンを繰り返す必要がある`s`なぜなら、一致は各コピーの終わり近くでのみ発生するからです。 

たとえば、次の場合`s = abcd`そして`t = dddd`、各コピー`s`最後の文字で使用可能な一致が 1 つだけ提供されます。 アルゴリズムは最後までスキャンを繰り返し、インクリメントします。`days`、継続して、発生回数に等しい正しい日数が生成されます。 

もう 1 つのエッジケースは次のような場合です`t`に比べて非常に短いです`s`、 のような`s = abcde...`そして`t = single character`。 アルゴリズムは最初のスキャンですぐに一致し、増加することはありません`days`、正しく 1 を返します。 

最後に、もし`s`次のような単一の繰り返し文字です。`aaaaa`そして`t`それもすべてです`a`、アルゴリズムは必要になるまで決してリセットされず、日数は`t`、これは最小繰り返し要件に一致します。
