 ## 解決策
 ## 問題の理解

 長さ (N) のバイナリ文字列を構築する必要があります。 各要件には間隔 ([X,Y]) が与えられ、その間隔内の文字は両端から同じように読み取られる必要があります。 最終的な文字列は、0 と 1 の合計数を可能な限り近づけながら、このような回文要件をすべて満たす必要があります。 

入力にはいくつかの独立したコミッションが含まれています。 それぞれの (N) は文字列の長さ、(M) は回文要件の数、次の (M) のペアはそれらのエンドポイントを表します。 出力には、ケース番号が接頭辞として付けられた、コミッションごとに 1 つの有効な最適な文字列が含まれている必要があります。 最適な文字列は多数存在する可能性があるため、構築する必要があるのは 1 つだけです。 

制約は、考えられるすべての文字列に対する推論を直接除外できるように、意図的に十分に大きくなっています。 (N\le 4000) の場合、考えられる文字列は (2^{4000}) 個あるため、網羅的な検索は完全に不可能です。 要件が (10,000) 存在する場合もあるため、大規模な構造を繰り返しコピーまたは再構築してすべての要件を処理するのは無駄です。 公式コンテストでは、15 秒の制限時間と 512 MB のメモリが使用されており、(O(N^2)) ソリューションは実用的ですが、指数関数的アプローチまたは (O(MN^2)) アプローチを受け入れる理由はほとんどありません。 

最初のエッジ ケースは (M=0) です。 たとえば、入力の場合`1 0`、制限はありませんので、どちらでも構いません。`0`または`1`が最適です。 すべての位置が制約されたコンポーネントに属していると想定する不用意な実装は、空の割り当てを生成したり、シングルトン コンポーネントを忘れたりして失敗する可能性があります。 

2 番目のエッジ ケースは、次のような長さ 1 の回文です。`1 1`。 間隔には 1 文字しか含まれていないため、まったく等価性が課せられません。 のために`N=3, M=1`要件付き`2 2`、最適な答えは次のようになります。`010`、ゼロが 2 つと 1 が 1 つあります。 回文の中心を 2 つの異なる位置間の等しいものとして扱うと、存在しない制約が導入されてしまいます。 

3 番目のエッジ ケースは、奇数長の回文です。 のために`N=5`要件付き`1 5`、ポジション`1`そして`5`一致する必要があります、位置`2`そして`4`一致する必要があります。`3`無料です。 文字列`00100`が最適です。 2 つのポインターが交差するまで常にペアを処理する不注意なループにより、誤って中心に 2 回アクセスしたり、無効なインデックスが作成されたりする可能性があります。 

4 番目の特殊なケースは、要件が重複していることです。 のために`N=6`、 要件`[1,5]`そして`[2,6]`暗示する`B1=B5`、`B2=B4`、`B2=B6`、 そして`B3=B5`。 等式は推移的に相互作用するため、同じ回文によって直接ペアにならなかったいくつかの位置が等しくなります。 すべての要件を個別に処理し、ビットを即座に割り当てると、この推移的な関係に違反する可能性があります。 

最後の微妙なケースは、複数の要件が同じ値 (X+Y) を持つ場合に発生します。 例えば、`[1,7]`そして`[2,6]`どちらもエンドポイント合計 (8) を持ちます。 2 番目の間隔は最初の間隔に完全に含まれているため、最初の間隔は 2 番目の間隔で必要なすべての等価性をすでに強制しています。 各エンドポイント合計の最も広い間隔のみを維持すると、制約を変更せずに冗長な作業が削除されます。 

## アプローチ

 直接的な総当たりアプローチは、すべてのバイナリ文字列を試し、必要な間隔が回文でない場合はそれを拒否し、生き残った文字列の中で最小のゼロ 1 の差を持つものを保持することです。 考えられるすべての文字列が考慮されるため、これは正しいです。 問題は検索スペースそのものです。(2^N) 個の文字列が存在します。 (N=4000) では、(2^{4000}) 個の候補になります。 すべての候補が (M) 間隔でチェックされ、各回文チェックで最大 (N) 文字がスキャンされる場合、最悪の場合は (2^{4000}\cdot 10,000\cdot4,000) 文字の比較になります。 候補を生成することさえすでに不可能です。 

最初の有益な観察は、回文の要件が実際には値を独立して制約するわけではないということです。 平等の制約が生じます。 のために`[l,r]`、私たちは必要とします

 [
 B_l=B_r,\quad B_{l+1}=B_{r-1},\quad\ldots
 】

 したがって、問題全体は、まず位置に関するグラフとして見ることができます。 必要なすべての等価性はエッジであり、すべての接続されたコンポーネントは単一ビットを受け取る必要があります。 

等式の構築を (O(MN)) ではなく (O(N^2)) に保つ 2 番目の観測があります。 対称ペア ((i,j)) には、一意のエンドポイント合計 (i+j) があります。 回文の場合`[l,r]`、作成されるすべての等式は同じ合計 (l+r) を持ちます。 2 つの要件の合計が同じである場合、次のようにします。`[l,r]`そして`[l',r']`、(r=s-l) であるため、それらの間隔は入れ子になっています。 左の端点が小さい方にはもう一方の端点が完全に含まれているため、その合計の最も広い間隔のみが問題になります。 

可能なエンドポイント合計は (2N-1) 個だけです。 すべての合計の最も広い間隔を保持した後、その対称ペアを生成し、それらの端点を素集合の共用体構造とマージします。 合計は一意であるため、すべての合計において、順序のない位置の各ペアは最大 1 回出現する可能性があります。 その結果、最大で (\binom N2) 個の等価ペアが処理され、結合フェーズに (O(N^2\alpha(N))) の時間が与えられます。 

等式が解決された後、連結成分のサイズが (s_1,s_2,\ldots,s_k) であると仮定します。 含めるコンポーネントの選択`1`全体のサイズが 1 の数に寄与します。 したがって、合計が (N/2) にできるだけ近いコンポーネント サイズを選択する必要があります。 これはサブセット合計の問題ですが、(N\le4000) により特にコンパクトなビットセット DP が可能になります。 Python の整数は、到達可能なすべての合計をビットとして表すことができ、サイズ (s) のコンポーネントの遷移は次のようになります。`reachable |= reachable << s`。 

ブルート フォース ソリューションは、すべての割り当てを明示的に検査するため機能します。 指数関数的に多くの割り当てがあるため、失敗します。 等式の観測により、問題は完全に変わります。まず、強制的に一致させられるすべての位置を折りたたんでから、コンポーネントのサイズのみに関する部分集合和問題を解きます。

 ## アルゴリズムのチュートリアル

 1. すべて (M) 個の回文間隔を読み取り、値 (s=X+Y) でグループ化します。 各合計について、最小値 (X) のみを保持します。 (Y=s-X) であるため、この区間はその和を持つ最も広い区間であり、同じ和を持つ他のすべての区間はその中にあります。 
2. 文字列位置ごとに 1 つの要素を含む DSU を作成します。 平等性が確立されていないため、最初はすべての位置が独自のコンポーネントになります。 
3. 保持された間隔ごとに`[l,r]`、マージ`l`と`r`、 それから`l+1`と`r-1`、2 つの位置が一致するまで続きます。 これらはまさに回文で要求される等式です。 
4. 最終的なすべての DSU コンポーネントのサイズを数えます。 1 つのコンポーネント内のすべての位置は同じビットを受け取る必要があるため、サイズ (複数可) のコンポーネントは、重み (複数可) の分割できない項目のように動作します。 
5. これらのコンポーネント サイズに対してサブセット合計 DP を実行します。 到達可能な合計のセットを 1 つの Python 整数のビットで表します。 ビット (x) は、コンポーネントのコレクションの合計サイズが (x) である場合に正確に設定されます。 合計ゼロから開始して、サイズ (s) のコンポーネントによって到達可能なセットが変更されます。`dp`に`dp | (dp << s)`。 
6. (N/2) に最も近い到達可能な合計を見つけます。 この合計が (z) の場合、次のように代入します。`1`これらの選択されたコンポーネントに (z) 個の 1 と (N-z) 個の 0 が与えられるため、結果として得られる差は (|N-2z|) となり、(z) の選択により最小になります。 
7. 選択したサブセットを構成するコンポーネントを再構築します。 各コンポーネントの後に DP ビットセットを保存します。 選択したターゲットから開始してコンポーネントを逆方向に処理すると、コンポーネントなしではターゲットをすでに形成できない場合にコンポーネントが選択されます。 選択すると、ターゲットからそのサイズが減算されます。 
8. 割り当てる`1`コンポーネントが選択されているすべての位置に、`0`他のすべての位置に移動します。 結果の文字列にプレフィックスを付けます`Case #k:`出力形式の要求に応じて。 

### なぜ効果があるのか

 DSU の不変条件は、これまでに処理された等価制約によって同じビットを持つように強制された場合、2 つの位置が同じコンポーネント内にあるということです。 すべての回文間隔は、対称エンドポイントの等価性を正確に反映するため、すべての間隔が処理された後、すべての有効な文字列が各 DSU コンポーネントで定数になる必要があります。 逆に、各コンポーネントに 1 ビットを割り当てると、すべての等式が自動的に満たされ、したがってすべての回文要件が自動的に満たされます。 

サブセット合計フェーズでは、可能な 1 の数が正確に考慮されます。 コンポーネントは完全に 0 か完全に 1 のみであるため、合計サイズ (z) のコンポーネントを選択すると、正確に (z) 個のサイズが生成されます。 DP はそのような (z) をすべて見つけ、(N/2) に最も近い到達可能な値を選択することで、(|z-(N-z)|) が最小化されます。 したがって、構築された文字列は有効かつ最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = [-1] * n

    def find(self, x):
        parent = self.parent
        while parent[x] >= 0:
            if parent[parent[x]] >= 0:
                parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(self, a, b):
        parent = self.parent
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return

        if parent[a] > parent[b]:
            a, b = b, a

        parent[a] += parent[b]
        parent[b] = a

def solve_case(n, intervals):
    # For each sum l + r, only the widest interval is necessary.
    widest = [n + 1] * (2 * n + 1)

    for l, r in intervals:
        s = l + r
        if l < widest[s]:
            widest[s] = l

    dsu = DSU(n)

    # Positions are zero-based here.
    # For a fixed sum s, r = s - l, so the interval is determined by l.
    for s in range(2, 2 * n + 1):
        l = widest[s]
        if l == n + 1:
            continue

        l -= 1
        r = s - l - 2

        while l < r:
            dsu.union(l, r)
            l += 1
            r -= 1

    # Compress all components and obtain their sizes.
    components = []
    root_to_id = {}
    comp_id = [-1] * n

    for i in range(n):
        root = dsu.find(i)
        if root not in root_to_id:
            root_to_id[root] = len(components)
            components.append(-dsu.parent[root])
        comp_id[i] = root_to_id[root]

    k = len(components)

    # Bitset subset sum.
    # dp bit x == 1 iff sum x is reachable.
    dp_history = [1]
    dp = 1

    for size in components:
        dp |= dp << size
        dp_history.append(dp)

    target = n // 2

    # Find the reachable sum closest to n / 2.
    best = target
    while best >= 0 and ((dp >> best) & 1) == 0:
        best -= 1

    # For odd n, the upper side can be equally good.
    upper = target + 1
    if upper <= n and ((dp >> upper) & 1):
        if abs(n - 2 * upper) < abs(n - 2 * best):
            best = upper

    # Reconstruct the selected components.
    selected = [False] * k
    cur = best

    for i in range(k, 0, -1):
        size = components[i - 1]

        if ((dp_history[i - 1] >> cur) & 1) == 0:
            selected[i - 1] = True
            cur -= size

    answer = ['0'] * n

    for i in range(n):
        if selected[comp_id[i]]:
            answer[i] = '1'

    return ''.join(answer)

def main():
    t = int(input())
    out = []

    for case_no in range(1, t + 1):
        n, m = map(int, input().split())
        intervals = [tuple(map(int, input().split())) for _ in range(m)]

        ans = solve_case(n, intervals)
        out.append(f"Case #{case_no}: {ans}")

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    main()
```の`widest`配列のインデックスは次のとおりです`l+r`。 その初期値は、考えられるすべての左端点よりも大きいセンチネルです。 間隔が読み取られるとき、その合計の最小の左端点が保持されます。 正しいエンドポイントは合計によって決定されるため、これはまさにその合計の最大間隔になります。 

DSU は負の値を使用します。`parent`コンポーネントのサイズをルートに保存します。 これにより、個別のサイズの配列が回避されます。 サイズごとに結合することで木を浅く保ち、`find`パス圧縮を実行します。 

1 から始まる入力から 0 から始まる位置への変換は、間隔を処理するときに発生します。 オリジナルの間隔の場合`[l,r]`から 1 を引いた後、`l`、ゼロベースの右端点は次のとおりです。`s-l-2`。 ループは対称位置をマージし、中心で停止するため、長さ 1 または奇数長の回文によって無効なペアが生成されることはありません。 

コンポーネント リストには、すべての DSU コンポーネントの位置の数が含まれています。 サブセットサム遷移では、Python の任意サイズの整数をビットセットとして使用します。 サイズ (s) のコンポーネントを処理する前にビット (x) が存在する場合、ビット (x+s) が表示されます。`dp << s`。 

の`dp_history`list には、コンポーネントごとに到達可能な合計が格納されます。 これには最悪の場合 (O(N^2)) ビットがかかりますが、(N=4000) の場合はわずか数メガバイトです。 サイズのコンポーネントを考慮すると、再構成が簡単になります。`size`、現在のターゲットがそのコンポーネントの前にすでに到達可能であったかどうかを確認できます。 そうでない場合、コンポーネントは選択したサブセットに属している必要があります。 

Python では整数オーバーフロー処理は必要ありません。 潜在的に大きな値はビットセット整数だけであり、そのサイズは (N+1) ビットによって制限されます。

## テストケース

        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.p[a] > self.p[b]:
            a, b = b, a
        self.p[a] += self.p[b]
        self.p[b] = a

def solve_case(n, intervals):
    widest = [n + 1] * (2 * n + 1)

    for l, r in intervals:
        s = l + r
        widest[s] = min(widest[s], l)

    dsu = DSU(n)

    for s in range(2, 2 * n + 1):
        l = widest[s]
        if l == n + 1:
            continue

        l -= 1
        r = s - l - 2

        while l < r:
            dsu.union(l, r)
            l += 1
            r -= 1

    root_id = {}
    comp = [-1] * n
    sizes = []

    for i in range(n):
        root = dsu.find(i)
        if root not in root_id:
            root_id[root] = len(sizes)
            sizes.append(-dsu.p[root])
        comp[i] = root_id[root]

    dp = 1
    hist = [dp]

    for s in sizes:
        dp |= dp << s
        hist.append(dp)

    target = n // 2
    best = None

    for x in range(n + 1):
        if (dp >> x) & 1:
            if best is None or abs(n - 2 * x) < abs(n - 2 * best):
                best = x

    chosen = [False] * len(sizes)
    cur = best

    for i in range(len(sizes), 0, -1):
        s = sizes[i - 1]
        if ((hist[i - 1] >> cur) & 1) == 0:
            chosen[i - 1] = True
            cur -= s

    ans = ['0'] * n
    for i in range(n):
        if chosen[comp[i]]:
            ans[i] = '1'

    return ''.join(ans)

def solution(inp):
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    t = int(sys.stdin.readline())
    out = []

    for case_no in range(1, t + 1):
        n, m = map(int, sys.stdin.readline().split())
        intervals = [
            tuple(map(int, sys.stdin.readline().split()))
            for _ in range(m)
        ]
        out.append(f"Case #{case_no}: {solve_case(n, intervals)}")

    sys.stdin = old_stdin
    return '\n'.join(out)

def validate(inp):
    lines = inp.strip().splitlines()
    it = iter(lines)
    t = int(next(it))

    expected_cases = []

    for _ in range(t):
        n, m = map(int, next(it).split())
        intervals = [tuple(map(int, next(it).split())) for _ in range(m)]
        expected_cases.append((n, intervals))

    output = solution(inp).splitlines()
    assert len(output) == t

    for case_no, ((n, intervals), line) in enumerate(
        zip(expected_cases, output), 1
    ):
        prefix = f"Case #{case_no}: "
        assert line.startswith(prefix)
        s = line[len(prefix):]

        assert len(s) == n
        assert set(s) <= {'0', '1'}

        for l, r in intervals:
            part = s[l - 1:r]
            assert part == part[::-1]

        # Build equality components independently.
        dsu = DSU(n)
        for l, r in intervals:
            l -= 1
            r -= 1
            while l < r:
                dsu.union(l, r)
                l += 1
                r -= 1

        sizes = {}
        for i in range(n):
            root = dsu.find(i)
            sizes[root] = sizes.get(root, 0) + 1

        dp = 1
        for size in sizes.values():
            dp |= dp << size

        ones = s.count('1')
        best = min(
            abs(n - 2 * x)
            for x in range(n + 1)
            if (dp >> x) & 1
        )

        assert abs(n - 2 * ones) == best

 ## 特殊なケース

 のために`1 0`、DSU はサイズ 1 の 1 つのコンポーネントから始まります。 サブセット合計 DP は 0 と 1 の両方に達するため、差がゼロのどちらかのターゲットを選択します。 したがって、再構成された出力は単一の有効ビットになります。 

のために`3 1`要件付き`2 2`、保存された間隔には合計 (4) がありますが、それをゼロベースの座標に変換すると、左右の位置は同じになります。 ループ条件`l < r`はすぐに false になるため、結合は実行されません。 3 つの位置はすべて独立したままで、サブセット合計フェーズでは 1 つのビットに対して 2 つの位置を選択し、もう 1 つのビットに対して 1 つの位置を選択して、差分 1 を与えます。 

のために`5 1`要件付き`1 5`、DSU はポジションをマージします`1`そして`5`、 それから`2`そして`4`、ポジションを離れながら`3`一人で。 したがって、コンポーネントのサイズは次のようになります。`2,2,1`。 到達可能な 1 カウントには以下が含まれます`0,1,2,3,4,5`, したがって、ターゲット 2 または 3 では差が 1 になります。 結果として得られる文字列は次のとおりです`00100`は回文であり、3 つのゼロと 2 つの 1 があります。 

重複する要件については、`1 8`、`2 7`、 そして`3 6`、各区間は対称的な等式に寄与します。 DSU は等式を推移的に結合するため、1 つの要件がポジションを接続する場合`1`そして`8`、そして別のものが最終的に接続します`8`別の位置では、3 つすべてが同じコンポーネントに属します。 最終的な割り当てはコンポーネントごとに行われるため、その後の選択によって、強制的に等しくされた位置に誤って異なるビットが与えられる可能性があります。 

同じエンドポイント合計を持つ複数の間隔の場合、最も幅の広い間隔のみが保持されます。 要件が次のようになっているとします。`[1,7]`そして`[2,6]`。 どちらも合計が 8 になります。 最初の間隔でペアが生成されます`(1,7)`、`(2,6)`、 そして`(3,5)`したがって、2 番目の間隔は何も新しいものにはなりません。 等価グラフは変更されないため、破棄しても安全です。 

(N=4000) および (M=0) の場合、すべての位置はシングルトン コンポーネントです。 DSU フェーズでは結合は実行されませんが、ビットセット DP は 0 から 4000 までのすべての合計に達します。選択されたターゲットは正確に 2000 であるため、出力には 2000 個のゼロと 2000 個の 1 が含まれます。 これは、可能な限り最大数のコンポーネントを実行し、パックされた整数のサブセット合計表現が二次 Python ブール テーブルよりも好ましい理由を示します。
