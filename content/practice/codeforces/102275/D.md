 ## 解決策
 ## 問題の理解

 パーシーは数直線上の位置 0 から始まります。 すべてのオブジェクトには位置、硬さ、タイプがあります。 パーシーが貝の位置を訪れると、貝を拾うことができます。 岩は、現在運ばれている硬度が岩の硬度よりも厳密に小さい貝をすべて砕く可能性があります。 

時間がかかるのは移動自体だけです。 パーシーは何度も物体を通過する可能性があり、岩は以前に岩を訪れた後に拾った貝を砕く可能性があるため、岩を再訪問することは役に立ちます。 課題は、すべてのアサリを食べるために必要な最小合計遊泳距離を見つけるか、報告することです。`-1`貝が決して割れないとしたら。 

位置と硬さは 2 つの 2 次再帰によって生成されるため、最初に実際のオブジェクトを構築する必要があります。 反復値は乗算中に 32 ビットの範囲を超えることがありますが、整数の精度は任意であるため、Python では問題ありません。 

1 つのテスト ケースに最大 800,000 個のオブジェクトが含まれるため、すべての貝とすべての岩を比較するアルゴリズムはすでに遅すぎます。 二次アルゴリズムは、最悪の場合、およそ 6.4 × 10^11 の比較を実行します。 目的のソリューションは、生成されたオブジェクトが位置順に与えられていないために必要なソートを含め、線形または O(N log N) に近い必要があります。 

最初の微妙なケースは厳密な硬度です。 考慮する```
2
1 2 0 0 0 10
5 5 0 0 0 10
CR
```ハマグリも岩も硬度は5なので、岩はハマグリを砕くことができません。 答えは、`-1`。 を使用した解決策`>=`の代わりに`>`有限の答えを誤って報告してしまいます。 

2 番目の微妙なケースは、世界で最も硬い岩が最短ルートを与えるのに十分役立つ必要はないということです。 例えば、```
3
9 10 0 0 99 100
6 5 0 0 5 10
RCR
```オブジェクトは、硬度 6 の岩が 9、硬度 5 の貝が 10、硬度 6 の岩が 100 です。パーシーは 10 まで泳いで、1 ユニットを 9 の岩に戻し、そこでゴールすることができます。所要時間は 11 秒です。 100 位まで行くとさらに悪くなります。 常に最も硬い岩を選択する解決策は、この可能性を世界的に見逃してしまいます。 

3 番目の微妙なケースは、アサリの前に訪れた岩が、単にパーシーが後にアサリを通過したからといって、そのアサリを壊すわけではないということです。 で```
4
10 50 0 1 40 80
50 10 0 1 38 80
RRCC
```オブジェクトは、10で硬度50の岩、50で硬度10の岩、11で硬度49のハマグリ、52で硬度8のハマグリです。最適なルートは次のとおりです。```
0 -> 11 -> 10 -> 50 -> 52 -> 50
```最初の貝は位置 10 で壊れ、2 番目の貝は拾った後位置 50 で壊れます。 すべてのオブジェクトを 1 回だけ訪問するという不注意なアプローチは、最初に 50 の岩を訪問した後に 2 番目の貝が拾われるため、失敗します。 

最後に、生成された位置はソートされていないため、非常に大きくなる可能性があります。 幾何学的推論を行う前に、位置によるソートが必須です。 生成インデックスを空間順序として使用すると、誤った優先順位関係が生成されます。 

## アプローチ

 直接総当りの解決策を使用すると、すべての貝に対して可能な限りすべての岩を試すことができます。 アサリの位置に`p`そして硬さ`h`あらゆる岩石を調べて、その硬度が次の値より大きいかどうかを確認できます。`h`、そして、結果として得られるルートについて推論してみてください。 すべてのハマグリに対して可能な破砕機を見つけるだけでも、最悪の場合 O(N²) かかります。 800,000 個のオブジェクトがあるため、これは完全に不可能です。 

もっと便利な総当たりの方法は、パーシーが実際に貝を割るのに使用する岩を列挙し、その選択に対する最短ルートを見つけることです。 それぞれの貝がいずれかの側の岩を選択する可能性があり、複数の貝が同じ岩を共有する可能性があるため、この値は依然として指数関数的です。 

重要な観察は、パーシーが常に左から右に新しい位置を発見するということです。 すべての位置は正であるため、初めて新しい最大位置に到達した時点で、より小さい位置にあるすべてのオブジェクトがすでに訪問されています。 複雑な部分は、岩を再訪することだけです。 

パーシーが実際に貝を割った岩を考えてみましょう。 これらのサービス ロックが位置の昇順で発生するように、最適なソリューションを正規化できます。 2 つの連続するサービス ロックが位置の降順で表示されるとします。 それらの硬度を`a`そして`b`。 もし`a >= b`、最初の岩は、2 番目の岩が砕く貝をすべて砕くこともできます。 もし`b > a`, 2 番目の岩も、最初の岩が砕いたすべての貝を砕くことができます。 いずれの場合も、2 つのサービス イベントのうち 1 つは不要です。 これを繰り返すとすべての減少が解消されます。 

次に、ポジションで 2 つの連続したサービス ロックを取得します。`L < R`。 それらの間にある貝殻はすべて、次のいずれかの方法で壊すことができます。`L`、パーシーが戻った後、または`R`、パーシーは右に移動しています。 隣接しないサービスロックは必要ありません。 ハマグリが以前の石を必要とした場合、`L`では、以前の岩はより硬かったです`L`、そしてそれは置き換えることができます`L`以前に提供されたハマグリについては、`L`同じように。 同じ議論が後の岩石にも当てはまります。 

これにより、移動の問題が、位置の昇順で岩の上を移動する動的計画法の問題に変わります。 

前のサービス ロックが`L`そして新しいサービスロックは`R`。 アサリがすべて入っていれば`(L,R)`より小さい硬度を持っています`H_R`、パーシーは単にから移動します`L`に`R`、原価計算`R-L`。 

そうしないと、アサリによっては硬すぎるものもあります。`R`。 以来`L`すべての貝を彼らに提供できなければなりません`(L,R)`硬度は以下でなければなりません`H_L`。 させて`q`の一番右の貝になる`(L,R)`その硬度は少なくとも`H_R`。 パーシーはから旅行できます`L`に`q`、に戻る`L`すべての貝を割るには`L`壊れても、その後も継続できる`R`。 費用は`(q-L) + (q-L) + (R-q) = R + 2q - 3L`。 

以前の岩かどうかを認識する特に便利な方法があります。`L`この 2 番目のタイプの遷移を実行できます。 させて`bad[L]`厳密に右側の最初のハマグリである`L`その硬度は少なくとも`H_L`。 それから`L`新しい岩までの全インターバルに対応できる`R`まさにいつ`R < bad[L]`。 

これにより、2 種類の候補値を持つ漸化式が得られます。 通常の移行には必要なものがあります`dp[L] - L`。 

への復帰を伴う移行の場合`L`、必要です`dp[L] - 3L`。 

最初の値は期限切れになりません。 2 番目の値は次の場合にのみ使用できます。`R < bad[L]`。 フェンウィック ツリーは最初の種類の接尾辞の最小値を処理し、セグメント ツリーと有効期限ヒープは 2 番目の種類の接頭辞の最小値を処理します。 

残りの幾何学的クエリは、前の右端のハマグリです。`R`その硬度は少なくとも`H_R`。 これはまさに単調なスタック クエリです。 同じタイプのスタックを右から左にスキャンして計算します。`bad[L]`。

### なぜ効果があるのか

 不変条件は、岩石を加工した後、`R`、`dp[R]`最新のサービス ロックが含まれるすべての正規化されたルートの最小コストです。`R`最初の訪問者が`R`。 連続する 2 つのサービスロックの間`L<R`、すべてのハマグリは次のいずれかによって処理されます。`R`右方向への移動で、または`L`ある帰りの小旅行中。 もし`R`すべてを処理します、コストは`R-L`。 さもないと`q`一番右の貝は`R`対処できず、そして`L`正確なコストを与えて、間隔全体を処理する必要があります`R+2q-3L`。 条件`R<bad[L]`まさにその条件です`L`インターバル内のどのアサリよりも難しいです。 すべての正規化された最適なルートは、このような増大するサービス ロックとして表すことができるため、DP はあらゆる最適な可能性を考慮し、無効な遷移は受け入れられません。 

## Python ソリューション```python
import sys
import heapq
from bisect import bisect_left

input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    out = []

    for tc in range(1, T + 1):
        n = int(input())

        p1, p2, ap, bp, cp, dp_mod = map(int, input().split())
        h1, h2, ah, bh, ch, dh_mod = map(int, input().split())
        ops = input().strip()

        objects = [(p1, h1, ops[0] == 'C'),
                   (p2, h2, ops[1] == 'C')]

        pp, p = p1, p2
        hh, h = h1, h2

        for i in range(2, n):
            np = ((ap * pp + bp * p + cp) % dp_mod) + 1
            nh = ((ah * hh + bh * h + ch) % dh_mod) + 1
            objects.append((np, nh, ops[i] == 'C'))
            pp, p = p, np
            hh, h = h, nh

        objects.sort()

        # For every rock, compute:
        # bad = first clam to the right with hardness >= rock hardness
        # final_ok = every clam to the right is strictly easier
        rock_rev = []
        stack = []
        suffix_max_clam = -1

        for pos, hard, is_clam in reversed(objects):
            if is_clam:
                stack.append((pos, hard))
                if hard > suffix_max_clam:
                    suffix_max_clam = hard
            else:
                while stack and stack[-1][1] < hard:
                    stack.pop()

                bad = stack[-1][0] if stack else INF
                final_ok = suffix_max_clam < hard
                rock_rev.append((pos, hard, bad, final_ok))

        rock_rev.reverse()
        rocks = rock_rev
        m = len(rocks)

        if m == 0:
            out.append(f"Case #{tc}: -1")
            continue

        # q[i] = nearest clam to the left of rock i
        # whose hardness is >= hardness of rock i.
        q = []
        stack = []

        for pos, hard, is_clam in objects:
            if is_clam:
                stack.append((pos, hard))
            else:
                while stack and stack[-1][1] < hard:
                    stack.pop()
                q.append(stack[-1][0] if stack else 0)

        positions = [r[0] for r in rocks]
        max_clam_pos = -1

        for pos, hard, is_clam in objects:
            if is_clam:
                max_clam_pos = pos

        # Fenwick tree for minimum dp[L] - pos[L].
        # Indexes are reversed so a suffix in position order becomes
        # a prefix query in the Fenwick tree.
        bit = [INF] * (m + 1)

        def bit_update(idx, value):
            while idx <= m:
                if value < bit[idx]:
                    bit[idx] = value
                idx += idx & -idx

        def bit_query(k):
            res = INF
            while k > 0:
                if bit[k] < res:
                    res = bit[k]
                k -= k & -k
            return res

        # Segment tree for minimum dp[L] - 3*pos[L] among active
        # return-transition candidates.
        size = 1
        while size < m:
            size <<= 1

        seg = [INF] * (2 * size)

        def seg_set(idx, value):
            p = idx + size
            seg[p] = value
            p >>= 1
            while p:
                nv = seg[p << 1]
                rv = seg[p << 1 | 1]
                seg[p] = nv if nv < rv else rv
                p >>= 1

        def seg_query(k):
            # Minimum over indexes [0, k).
            if k <= 0:
                return INF

            left = size
            right = size + k
            res = INF

            while left < right:
                if left & 1:
                    if seg[left] < res:
                        res = seg[left]
                    left += 1
                if right & 1:
                    right -= 1
                    if seg[right] < res:
                        res = seg[right]
                left >>= 1
                right >>= 1

            return res

        # (expiry_position, rock_index)
        expiry = []

        dp_values = [INF] * m
        answer = INF

        for i in range(m):
            pos, hard, bad, final_ok = rocks[i]
            qi = q[i]

            # Return-transition candidates with bad <= pos are no longer valid.
            while expiry and expiry[0][0] <= pos:
                _, idx = heapq.heappop(expiry)
                seg_set(idx, INF)

            if qi == 0:
                best = pos
            else:
                k = bisect_left(positions, qi)
                best = pos + bit_query(m - k)

                # Previous rocks strictly to the left of q.
                left_best = seg_query(k)
                if left_best < INF:
                    candidate = pos + 2 * qi + left_best
                    if candidate < best:
                        best = candidate

            dp_values[i] = best

            # Insert current rock as a future previous service rock.
            rev_index = m - i
            bit_update(rev_index, best - pos)

            if bad > pos:
                seg_set(i, best - 3 * pos)
                heapq.heappush(expiry, (bad, i))

            # Can this rock be the last service rock?
            if final_ok:
                if pos >= max_clam_pos:
                    candidate = best
                else:
                    candidate = best + 2 * (max_clam_pos - pos)

                if candidate < answer:
                    answer = candidate

        if answer >= INF:
            answer = -1

        out.append(f"Case #{tc}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の最初の部分では、前の 2 つの繰り返し値のみを保持しながら、生成された配列を構築します。 Python の任意精度整数は、大きな中間積を直接処理します。 

ソート後、逆スキャンで計算が行われます。`bad`そして最終サービスロックとなるための条件。 単調なスタックにはハマグリだけが含まれています。 スタックトップが柔らかすぎるときにポップすると、現在の岩を打ち負かすのに十分な硬度を持つ最も近い貝が残ります。 

順方向スキャンは、次の対称クエリを実行します。`q`。 2 つのスキャンは別々です。1 つは右側の最も近い適格なクラムを要求し、もう 1 つは左側の最も近い適格なクラムを要求するからです。 

フェンウィック・ツリー・ストア`dp[L] - P_L`。 再帰には岩の上に最小限の接尾辞が必要なため、そのインデックスは逆になります。`P_L >= q`。 フェンウィック ツリーは減少する最小更新のみを受け取るため、そこで削除する必要はありません。 

セグメントツリーストア`dp[L] - 3P_L`。 これらの候補者は一時的なものです。 スイープが到達したら`bad[L]`、 ロック`L`現在の岩で終わるギャップ内のすべてのハマグリを処理できなくなったため、候補は削除されます。 ヒープは、各候補者の有効期限がいつ切れるかを正確に示します。 

厳密な比較は意図的なものです。 堅い岩`h`厳密に以下の硬度のハマグリのみを砕くことができます`h`、つまり、次の硬度を持つハマグリです。`h`ブロックされたセットに属しており、`bad`イベント。 

最終的な計算でも厳密な不等式が使用されます。 硬さのラストサービスロック`h`残りのハマグリがすべて よりも硬度が低い場合にのみ有効です。`h`。 

## 実用的な例

 ### サンプル 1

 オブジェクトは、位置 5 の硬度 30 の貝と、位置 10 の硬度 31 の岩です。 

| ポジション | タイプ | 硬度 |`q`|`dp`| アクション |
 | --- | --- | --- | --- | --- | --- |
 | 5 | C | 30 | | | ハマグリを拾う | 写真
 | 10 | R | 31 | 0 | 10 | ロックは右に移動しながらハマグリを扱います |

 ハマグリの硬度 30 が 31 より小さいため、10 の岩の左側には適格なハマグリがありません。仮想開始点はそこに直接移行でき、次のようになります。`dp = 10`。 岩の後にアサリがないので、最後のサービス岩としても有効です。 答えは、`10`。 

### サンプル 2

 現在、岩は硬度 31 の位置 5 にあり、ハマグリは硬度 30 の位置 10 にあります。 

| ポジション | タイプ | 硬度 |`q`|`dp`| アクション |
 | --- | --- | --- | --- | --- | --- |
 | 5 | R | 31 | 0 | 5 | 岩に到達する | 写真 岩に到達する
 | 10 | C | 30 | | | ハマグリを拾う | 写真
 | 5 | R | 31 | | | 貝を返して割る |

 ５番の岩が最後のサービス岩になります。 その硬さはアサリの硬さを超えるため、10 でアサリに到達した後、パーシーは 10 から 5 に戻ります。追加の最終距離は次のとおりです。`2(10-5) = 10`、与える`5 + 10 = 15`。 

トレースは、最終的なサービス遷移が通常の遷移と異なる理由を示しています。 パーシーは最後のサービスの後に再び戻る必要がないため、最も遠くに残っている貝から最後の岩まで往復する必要があるのは 1 回だけです。 

### サンプル 4

 オブジェクトは

 | ポジション | タイプ | 硬度 |
 | --- | --- | --- |
 | 10 | R | 50 |
 | 11 | C | 49 |
 | 50 | R | 10 |
 | 52 | C | 8 |

 岩 10 の場合、11 のハマグリの硬度は 49 であるため、その右側に同等以上の硬度のハマグリはありません。最初の岩にはコスト 10 で直接到達できます。 

岩 50 の場合、その左側にある硬度が 10 以上で最も近い貝は 11 の貝です。`q = 11`。 前の岩は 10 番の左側にあります。`q`、その硬度 50 は、位置 10 と 50 の間のすべての貝を上回ります。返品移行コスト`50 + 2*11 + (dp[10] - 3*10) = 50 + 22 + 10 - 30 = 52`。 

これは以下に対応します```
0 -> 11 -> 10 -> 50
```コスト 52 です。52 の残りの貝は硬度 8 で、50 の岩は砕けます。 これが最後のサービスロックであるため、パーシーは 52 から 50 に戻り、4 を加えます。最終的な答えは 56 です。 

この例は、DP に両方の遷移形式が必要な理由を示しています。 岩を通る単純な最短経路では、岩 10 に戻る前に 11 のハマグリを拾わなければならないという事実が捉えられません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | ソートのコストは O(N log N) ですが、単調スタック、フェンウィック ツリー、セグメント ツリー、および有効期限ヒープは合計作業量 O(N log N) を実行します。 
| スペース | O(N) | ソートされたオブジェクト、岩石情報、スタック、DP 値、およびデータ構造はすべてリニア メモリを使用します。 

主な操作は、生成されたオブジェクトを位置によって並べ替えることです。 その後、すべてのオブジェクトは各単調スタックに出入りするのは多くても 1 回だけであり、すべての岩は一定数の対数データ構造操作のみを引き起こします。 オブジェクトが 800,000 個ある場合、これは特定の制約に対して適切なスケールですが、二次関数の代替案は利用可能な操作予算をはるかに超えています。

 ## 特殊なケース

 硬度を等しくするために、単調積層では現在の岩石と硬度が等しいハマグリを意図的に保持します。 入力で```
2
1 2 0 0 0 10
5 5 0 0 0 10
CR
```岩の硬度は厳密にはハマグリの硬度よりも高いわけではありません。 岩はハマグリにはならない、`final_ok`は誤りであり、他に岩石は存在しないので、答えは次のようになります。`-1`。 

近くの左側の岩と遠くの右側の岩について考えてみましょう。```
3
9 10 0 0 99 100
6 5 0 0 5 10
RCR
```生成される位置は 9、10、および 100 です。9 の岩の硬度は 6、10 のハマグリの硬度は 5 です。DP は仮想スタートを使用して岩 9 に到達し、その後、最後の遷移で 10 のハマグリから岩 9 に戻ります。そのコストは次のとおりです。`9 + 2(10-9) = 11`。 100 にある遠く​​の岩は最適値とは無関係です。 

後の貝が来る前に訪れた岩の場合、最後の遷移が戻りを明確に説明します。 サンプルの 4 番目のケースでは、パーシーが 52 で貝を拾う前にすでに岩 50 に到達しているため、最初の訪問で貝が食べられたとはみなされません。 最終的な計算では次のようになります。`2(52-50)=4`、ロック 10 での初期のサービスの後、合計の答えは 56 になります。 

生成された値が大きい場合、係数を適用する前に Python 整数を使用して反復が評価されます。 コードは中間積を 32 ビット値に変換しません。 次に、ソートのステップにより、反復によってオブジェクトが生成された順序とは無関係に、実際の空間順序が確立されます。 

右側に十分に硬いハマグリがない岩の場合、`bad`無限大になります。 戻り遷移候補は、以降のすべての間隔を処理できるため、有効期限が切れることはありません。 逆に、もし`bad[L]`は実際のアサリの位置であり、スイープがその位置に到達するとすぐに候補が削除され、間隔内のすべてのアサリの硬度が以下である必要があるという厳密な要件に一致します。`H_L`。 

パーシーは最後の貝を食べた後に右に戻る必要がないため、最後のサービス ロックは通常の遷移とは別に処理されます。 最後の岩があれば`L`そして一番遠くに残っている貝はここにあります`C`、必要な距離は`2(C-L)`、 ない`2(C-L)+(C-L)`。 この違いにより、サンプルの最終コストはより大きな値ではなく 56 になります。
