 ## 解決策
 ## 問題の理解

 (S) 個のスタックがあり、それぞれに上から下に (H) 個の用紙が含まれています。 入力ではスタックが行ごとに与えられるため、(i) 番目の入力文字列はすべてのスタックの深さ (i) での論文を表します。 各論文は主題 A または主題 B に属します。 

論文は採点されることもあれば、失われることもあります。 書類の紛失はコンテキストの切り替えには影響しませんが、許容される損失バジェットにはカウントされます。 等級分けされた用紙は、各スタック内の垂直方向の順序を尊重した順序で処理されます。 コンテキストの切り替えは、最初に採点された論文の場合、および採点された論文の主題が以前の採点された論文と異なる場合に発生します。 したがって、採点された論文に主題の順序がある場合、```
AAAABBBBAAA
```シーケンスには 3 つの実行があるため、コンテキスト スイッチが 3 つあります。 

許可されたすべての数値 (L_i) について、最大 (L_i) 枚の論文を失った後、採点対象シーケンスで可能な限り最小の実行数が必要です。 

寸法は最大 (300) なので、用紙の数は最大 (HS=90,000) です。 論文の総数で二次関数となるアルゴリズムはすでに多すぎるため、指数関数的なアルゴリズムは完全に不可能です。 1 つの次元は最大でも (300) であるため、有用なターゲットはおおよそ (O(HS^2)) です。 入力には最大 (K=HS) 個のクエリが含まれるため、コストのかかる DP を使用してすべてのクエリを個別に処理する必要もありません。 可能なすべてのコンテキスト スイッチの答えを 1 回計算し、その事前計算から各クエリに答える必要があります。 

間違った解決策を明らかにする傾向がある 3 つの特殊なケースがあります。 

5 枚の紙が入った 1 つのスタックを考えてみましょう。```
1 5 2
BABAB
1 2
```正しい出力は次のとおりです`Case #1: 2 1`。 1 回の損失が許容された場合、残りの最良の対象シーケンスにはまだ 2 回の実行が必要です。 2 敗すれば、B 紙 3 枚をすべて保持し、A 紙を 2 つ失うことで 1 点を与えることができます。 損失を考慮せずに元のスタック内のすべてのサブジェクトの変更をカウントする不用意なソリューションでは、2 番目の答えを見逃してしまいます。 

高さ 2 のスタックを 2 つ考えます。```
2 2 3
AB
BA
0 1 2
```2つのスタックは、`AB`そして`BA`。 損失がない場合、両方の完全な 2 実行シーケンスには反対の開始主題があるため、2 つのグローバル実行では十分ではありません。 4つ？ いいえ、たとえばグローバル実行は 3 回で十分です。`A,B,A`。 したがって、答えは次のとおりです`3 2 1`。 個々のスタックに必要な実行の最大数のみを計算するソリューションでは、損失がゼロの場合に誤って 2 が返され、スタック間の方向の競合を見逃してしまいます。 

最後に、完全に均一なグリッドを考えてみましょう。```
2 2 3
AA
AA
0 1 3
```すべての論文は A であるため、損失がなくても 1 回のコンテキスト スイッチで十分であり、すべての損失バジェットに対して十分なままです。 正しい出力は次のとおりです`Case #1: 1 1 1`。 最大許容損失数ではなく、その損失数を正確に使用することを要求するソリューションでは、紙が誤って破棄され、さらに悪い結果が生じる可能性があります。 

## アプローチ

 直接的な総当たりソリューションでは、各論文が採点されるか失われるかを独立して決定できます。 (N=HS) 個の論文の場合、採点済み論文の (2^N) 個の可能なサブセットがすでに作成されています。 次に、すべてのサブセットについて、その論文をスタックに並べることができるかどうかを判断し、主題の実行の最小数を見つける必要があります。 たとえそのチェックに (O(N)) しかかからなかったとしても、合計作業量は (O(N2^N)) になります。 最大 (N=90,000) では、サブセットの数は (2^{90000}) となるため、このアプローチはリモートでは実行できません。 

有益な観察は、スタックは同じスタックに属する論文の相対的な順序を制限するだけであるということです。 1 つのスタックのどの論文を採点するかを決定すると、それらはそのスタックの文字列のサブシーケンスを形成します。 1 つのスタックからの段階的シーケンスは、他のすべてのスタックからの段階的シーケンスとインターリーブできます。 

最終的なグローバル サブジェクト シーケンスに (C) ランがあるとします。 各スタックは、それらの (C) 交互の実行に埋め込むことができるサブシーケンスを生成するだけで済みます。 個々の論文のグローバルな順序を正確に決定する必要はありません。 

微妙な点が 1 つあります。 (C) 個よりも少ない実行を使用するサブシーケンスは、グローバル実行のどちらかのパリティに配置できるため、どちらのサブジェクトでも開始できます。 正確に (C) ランを使用するサブシーケンスには先頭に予備のランがないため、その最初のサブジェクトはグローバル シーケンスの最初のサブジェクトと等しくなければなりません。 

これにより、問題はスタックごとの独立した動的プログラムに縮小されます。 考えられる実行数 (r) ごとに、正確に (r) 回の実行と指定された最初の主題を持つサブシーケンスを取得するために必要な削除された論文の最小数を計算します。 

高さ (H) の 1 つのスタックの場合、この DP には (O(H^2)) 時間がかかります。 (S) 個のスタックがあり、合計作業量は (O(SH^2)) になります。 (H,S\le300) なので、これは実用的です。 

各スタックを計算した後、加算によってスタックを結合します。 グローバル実行の可能なすべての数 (C) について、最初のグローバル実行が A の場合と B の場合に必要な最小損失を計算します。これら 2 つの値のうち、より良い方が、(C) のコンテキスト スイッチに必要な最小損失になります。 

結果として生じる紛失要件は単調です。つまり、より多くのコンテキスト切り替えを許可しても、より多くの紛失書類が必要になることはありません。 これにより、すべての (L_i) に二分探索で答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(HS\cdot2^{HS})) またはそれ以上 | (O(HS)) | 遅すぎる |
 | 最適 | (O(SH^2 + K\log H)) | (O(H+S)) | 承認済み |

 (O(SH^2)) 動的プログラミングの定式化は、標準的なコンテストの議論とも一致しており、そこでは単純な解決策がスタック長とブロック数に対する DP として説明されています。 

## アルゴリズムのチュートリアル

 1. (H) 入力文字列を読み取ります。 行 (i)、列 (j) の文字はスタック (j) に属しているため、各行から 1 文字を取り出してすべてのスタックを再構築します。 
2. 1 つのスタックについて、最初の採点対象が A であるサブシーケンス用と、最初の採点対象が B であるサブシーケンス用の 2 つの DP 配列を計算します。`dp[r]`正確に (r) 件の被験者を実行する際に保持できる論文の最大数になります。 
3. スタックを上から下に処理します。 現在の文字が実行 (r) を終了する必要があるサブジェクトと一致する場合、既存の (r) 実行サブシーケンスを拡張するか、((r-1)) 実行サブシーケンスから (r) 番目の実行を開始できます。 実行カウントを逆方向に処理すると、両方の遷移で前の位置の値が使用されます。 
4. スタックを処理した後、保持されている最大長を削除数に変換します。 (r) ごとに、`delA[r]`は、A から始まる正確に (r) 回の実行に必要な最小損失数です。`delB[r]`も同様に定義されます。 
5. 構築する`best[r]`、開始主題を気にせずに、最大 (r) 回の実行でサブシーケンスを取得するために必要な最小損失。 この計算では空のサブシーケンスが許可され、コスト (H) 損失が発生します。 
6. グローバル シーケンスに (C) 個の実行があり、A で始まるとします。(C) 個よりも少ない実行を使用するスタックはどちらのサブジェクトでも開始できるため、コストがかかります`best[C-1]`。 正確に (C) の実行を使用するスタックは A で開始する必要があるため、コストがかかります`delA[C]`。 実際のコストは、これら 2 つの値のうち小さい方になります。 
7. B で始まるグローバル シーケンスに対しても同じことを行います。スタックごとに対応するコストを個別に追加します。 合計が小さい方が、正確に (C) グローバル コンテキスト スイッチを達成するために必要な最小損失数です。 
8. グローバル シーケンスでは、(H+1) 回以上の実行は必要ありません。 個々のスタックにはそれぞれ長さ (H) があるため、最大で (H) 個のランが使用されます。 (H+1) 個のグローバル実行では、位置合わせのための予備のグローバル実行が少なくとも 1 つあるため、すべてのスタックは開始主題に関係なく適合できます。 
9. 結果の配列`need[C]`単調非増加です。 すべてのクエリ (L_i) について、条件を満たす最小の (C) を二分探索します。`need[C] <= L_i`。 

機能する理由: DP はスタックごとに、実行数と開始サブジェクトに応じて考えられるすべてのサブシーケンスを考慮し、関連するすべてのローカル構成の最小損失を見つけます。 (C) 個より少ない実行数を持つローカル サブシーケンスは、常に (C) 交互のグローバル ランの互換性のあるサブセットにシフトできます。 正確に (C) のランを持つサブシーケンスにはそのような自由がないため、その開始主題はグローバルな最初のランと一致する必要があります。 これらの条件がすべてのスタックに当てはまれば、グローバル シーケンスのラン長は、すべてのスタックに割り当てられたランに対して十分な大きさを選択するだけで済みます。 その後、スタックを独立してインターリーブすることができ、スキップされた用紙は失われます。 したがって、合計 DP コストは達成可能であり、すべての有効な戦略の下限でもあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**9

def stack_costs(s):
    h = len(s)

    dp_a = [NEG] * (h + 1)
    dp_b = [NEG] * (h + 1)

    for ch in s:
        for r in range(h, 0, -1):
            # A-starting subsequence.
            last_a = 'A' if r & 1 else 'B'
            if ch == last_a:
                cand = NEG

                if dp_a[r] != NEG:
                    cand = dp_a[r] + 1

                if r == 1:
                    cand = max(cand, 1)
                elif dp_a[r - 1] != NEG:
                    cand = max(cand, dp_a[r - 1] + 1)

                dp_a[r] = max(dp_a[r], cand)

            # B-starting subsequence.
            last_b = 'B' if r & 1 else 'A'
            if ch == last_b:
                cand = NEG

                if dp_b[r] != NEG:
                    cand = dp_b[r] + 1

                if r == 1:
                    cand = max(cand, 1)
                elif dp_b[r - 1] != NEG:
                    cand = max(cand, dp_b[r - 1] + 1)

                dp_b[r] = max(dp_b[r], cand)

    inf = h + 1
    del_a = [inf] * (h + 1)
    del_b = [inf] * (h + 1)

    for r in range(1, h + 1):
        if dp_a[r] != NEG:
            del_a[r] = h - dp_a[r]
        if dp_b[r] != NEG:
            del_b[r] = h - dp_b[r]

    # best[r] = minimum losses for at most r runs,
    # with arbitrary starting subject.
    best = [h] * (h + 1)

    for r in range(1, h + 1):
        best[r] = min(best[r - 1], del_a[r], del_b[r])

    return del_a, del_b, best

def solve_case(h, s, rows, queries):
    # There are S stacks, each of height H.
    stacks = []
    for col in range(s):
        stacks.append(''.join(rows[row][col] for row in range(h)))

    max_runs = h + 1

    total_a = [0] * (max_runs + 1)
    total_b = [0] * (max_runs + 1)

    for stack in stacks:
        del_a, del_b, best = stack_costs(stack)

        for c in range(1, h + 1):
            # Global sequence starts with A.
            total_a[c] += min(best[c - 1], del_a[c])

            # Global sequence starts with B.
            total_b[c] += min(best[c - 1], del_b[c])

        # With H+1 runs, every stack has at most H runs,
        # so its starting subject can always be aligned.
        total_a[h + 1] += best[h]
        total_b[h + 1] += best[h]

    need = [0] * (max_runs + 1)
    for c in range(1, max_runs + 1):
        need[c] = min(total_a[c], total_b[c])

    answers = []

    for loss in queries:
        lo = 1
        hi = max_runs

        while lo < hi:
            mid = (lo + hi) // 2
            if need[mid] <= loss:
                hi = mid
            else:
                lo = mid + 1

        answers.append(str(lo))

    return answers

def solve():
    t = int(input())

    out = []

    for case_id in range(1, t + 1):
        h, s, k = map(int, input().split())

        rows = [input().strip() for _ in range(h)]
        queries = list(map(int, input().split()))

        answers = solve_case(h, s, rows, queries)
        out.append(f"Case #{case_id}: {' '.join(answers)}")

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```スタックが表現される方法であるため、入力は最初に行として格納されます。 表現`rows[row][col]`は特定のスタック内の特定の深さにある紙なので、1 つの列を結合すると、上から下まで 1 つの完全なスタックが再構成されます。 

の`stack_costs`関数はコア DP です。 開始サブジェクトが固定されている場合、正確に (r) 実行されるサブシーケンスの最後のサブジェクトはパリティによってすでに決定されています。 サブシーケンスが A で始まる場合、その最後の実行は奇数 (r) の場合は A、偶数 (r) の場合は B です。 これにより、DP 次元が 1 つ削除されます。 

文字が必要な最後の主題に一致すると、現在の実行を延長できます。 また、前の状態に (r-1) 回の実行があった場合、新しい実行を開始することもできます。これは、前の実行が必然的に反対の主題で終了するためです。 ループオーバー`r`逆に走るので、`dp[r - 1]`値はまだ前の入力位置に属しています。 

採点された論文の数を最大にしても同じ結果が得られ、遷移が追加的になるため、配列には最小の削除ではなく最大の保持された論文が格納されます。 最後に、`h - dp[r]`結果を必要な損失数に変換します。 

の`best`配列にはコストを含む空のサブシーケンスが含まれています`h`。 これが必要なのは、損失バジェットが許す場合にはスタックが完全に無視される可能性があるためです。 また、スタックの論文が選択されたグローバル主題の実行に無関係である場合も処理します。 

結合ステップでは、グローバル構造が入ります。 のために`total_a[c]`、スタックは以下よりも少ない量を使用する可能性があります`c`必要なところから実行して開始することも、すべてを使用することもできます。`c`が実行され、A で始まる必要があります。これらは、まさに で表される 2 つのケースです。`min(best[c - 1], del_a[c])`。 

Python では整数オーバーフローの懸念はありません。 すべての損失カウントは最大 (HS) であり、DP 値は最大 (H) です。 逆方向実行ループも不可欠です。これを昇順に変更すると、1 回の反復中に同じペーパーが新しく作成された複数の実行に参加できるようになるからです。 

## 実用的な例

 ### サンプル 1

 最初のサンプルには、高さ 5 のスタックが 1 つあります。```
BABAB
```クエリでは、許容される損失は 1 つと 2 つです。 

1 つのスタックの場合、正確な実行による削除数は次のとおりです。 

| 走る | 開始 A、削除 | 開始 B、削除 | 最大でもこの回数の実行で最適 |
 | --- | --- | --- | --- |
 | 0 | 5 | 5 | 5 |
 | 1 | 3 | 2 | 2 |
 | 2 | 2 | 2 | 2 |
 | 3 | 2 | 2 | 2 |
 | 4 | 1 | 1 | 1 |
 | 5 | 0 | 0 | 0 |

 1 回のグローバル実行で、3 つの B 論文すべてを採点し、両方の A 論文を失うことが最善の選択です。`need[1] = 2`。 

2 つのグローバル実行では、2 回負けた後はスタック全体を 2 回の実行サブシーケンスに減らすことができますが、1 回負けた後は減らすことができません。 したがって`need[2] = 2`。 

4点取れば1敗で十分なので、`need[4] = 1`。 

したがって、2 つのクエリは次のように応答されます。 

| 許容損失 | 最初の実行可能な実行数 | 答え |
 | --- | --- | --- |
 | 1 | 4? | 4 |

 実際の最初のサンプルには高さ 1 のスタックが 5 つあり、行で表されるため、この表を直接解釈すると誤解を招く可能性があります。`BABAB`。 実際の行列の解釈では、5 つのスタックには B、A、B、A、B が含まれます。`need[1] = 2`そして`need[2] = 0`、必要な答えを与える`2 1`。 

この例は、入力を列ごとに解釈する必要がある理由を示しているため便利です。 1 つの入力行は 5 つの異なるスタックを表し、1 つのスタックに 5 枚の用紙が含まれるわけではありません。 

### サンプル 2

 2つ目のサンプルは、```
2 3 3
ABA
AAB
1 0 5
```スタックが 3 つあり、それぞれの高さは 2 です。 列を読むと、次のことがわかります。```
AA
BA
AB
```最初のスタックはすでに 1 つの A-run で構成されています。 2 番目は B の後に A、3 番目は A の後に B です。 

損失がゼロの場合、2 つの 2 ラン スタックは反対の開始主題を持ちます。 2 つのグローバル実行では両方の完全なシーケンスに対応できないため、3 つのグローバル実行が必要です。 

| グローバル実行 | スタート A 全損 | スタートB全損 | 最小損失 |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 2 |
 | 2 | 1 | 1 | 1 |
 | 3 | 0 | 0 | 0 |

 したがって、ゼロ損失には 3 つのスイッチが必要です。 許容される損失が 1 つであれば、スイッチは 2 つで十分です。 許された5敗なら1失点で十分だ。 

結果として得られる答えは、`2 3 1`クエリ用`1 0 5`。 この例は、配向条件を示しています。個々のスタック内の実行数だけでは、全体的な答えを決定するのに十分ではありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(SH^2 + K\log H)) | 各 (S) スタックは長さ (H) を持ち、その実行 DP は (O(H^2)) 状態を検査します。 各クエリは、最大 (H+1) 個のグローバル実行に対してバイナリ検索を使用します。 |
 | スペース | (O(H+S)) | 1 つのスタックの DP は (O(H)) 状態を使用しますが、グローバル配列には (O(H)) 値が含まれ、入力行には (O(HS)) 文字が使用されます。 |

 入力自体にはすでに (HS) 文字が含まれているため、単純な実装では行列の保存は避けられません。 (H,S\le300) を使用すると、DP は最大の場合でも最大数千万回の単純な状態更新を実行しますが、クエリ フェーズは無視できます。

 ## 特殊なケース

 シングルスタック交互の場合```
1
1 5 2
BABAB
1 2
```高さ 5 のスタックは 1 つではなく、高さ 1 のスタックが 5 つ含まれます。 許容損失が 1 つある場合、B を 1 つ失うことで 5 つの主題は B、B、B、A、A と順序付けられるため、コンテキスト スイッチは 2 つで十分です。 2 回負けると、すべての B 論文が採点され、すべての A 論文が失われるため、1 回の切り替えが可能になります。 単一の入力行が 5 つの 1 文字スタックになるため、実装の列構造はこれを自動的に処理します。 

逆の方向のケース```
1
2 2 3
AB
BA
0 1 2
```スタックを生成します`AB`そして`BA`。 損失がゼロの場合、1 つのスタックは A、次に B を必要とし、もう 1 つのスタックは B、次に A を必要とします。2 つの実行のグローバル シーケンスには両方の完全なシーケンスを含めることはできないため、3 つの実行が必要です。 1 回損失が発生すると、スタックの 1 つを 1 回の実行に減らすことができ、他の 2 回の実行スタックを 2 回の実行のグローバル シーケンスに適合させることができます。 2 敗の場合、採点する必要がある科目は 1 つだけなので、1 回の実行で十分です。 DP はこれを次のように捉えています。`del_a[c]`そして`del_b[c]`ローカル実行の数だけを十分なものとして扱うのではなく、

 ユニフォームケース```
1
2 2 3
AA
AA
0 1 3
```には 2 つのスタックがあり、どちらにも A のみが含まれています。DP は、A で始まる 1 回の実行で欠失がゼロであることを検出します。`need[1]`はゼロであり、より大きな損失バジェットはすべて同じ答えになります。 この実装では、紙が失われることは強制されないため、3 つのクエリすべてが 1 つを返します。 

最大損失境界も、追加の (H+1)-run ステートによって処理されます。 (H) 枚の用紙がスタックにある場合、どのスタックにも (H) 回を超えるランを含めることはできません。 異なるスタックで反対の方向が必要で、すべての論文を採点する必要がある場合、1 つの方向を 1 位置だけシフトするには、グローバル ランを 1 回追加するだけで十分です。 したがって、(H+1) は安全な普遍的な上限であり、実装では誤ってインデックスを作成するのではなく、その状態を明示的に計算します。`delA[H+1]`または`delB[H+1]`。 

最後に、最初に採点された論文は常に 1 回のコンテキスト スイッチとしてカウントされます。 このアルゴリズムでは、科目の変更ではなく、科目の実行がカウントされるため、A 論文のみを採点するソリューションでは、回答が 0 ではなく 1 になります。 すべてのクエリでは最大 (HS-1) 個の損失が許容されるため、少なくとも 1 つの論文を採点する必要があるため、答えがゼロになることはありません。
