 ## 解決策
 ## 問題の理解

 花の列が与えられ、それぞれの花は整数で表されるタイプを持ちます。 花屋は、その花束がこの行の連続したセグメントに対応し、そのセグメントにちょうど K 個の異なる花の種類が含まれている場合にのみ、その花束を「有効」であるとみなします。 

このタスクは、正確に K 個の異なる値を持つ連続したサブ配列がいくつあるかを数えるというものです。 

入力サイズは最大 300,000 要素になります。 すべてのサブ配列を直接検査しようとするソリューションでは、最悪の場合でもおよそ N 乗のチェックが必要になります。これは 10^10 の演算のオーダーに相当し、一般的な時間制限内では実現できません。 これにより、間隔ごとに個別のカウントを個別に再計算するアプローチは即座に除外されます。 

この問題の微妙な点は、「正確に K 個の異なる」の方が「最大 K 個の異なる」よりもはるかに難しいことです。 最大で K 個の個別の値を持つ部分配列をカウントすることは、スライディング ウィンドウ手法の下では適切に動作しますが、正確な K にはリダクション トリックが必要です。 

典型的な失敗例は、一貫したウィンドウ構造を維持せずに両端を独立して拡張しようとした場合に発生します。 たとえば、すべての要素が個別であり、K = 2 の場合、単純な拡張では、重複の処理方法によっては二重にカウントされたり、有効なセグメントが欠落したりする可能性があります。 問題は個々のチェックの正しさではなく、重複するサブ配列のアカウンティングに一貫性がないことです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての左端点を反復処理し、現在のセグメント内の要素の周波数マップを追跡しながら右端点を拡張します。 拡張子ごとに、存在する個別の値の数を数え、それが K に等しい場合は答えを増分します。これは、考えられるすべての部分配列を 1 回だけ列挙するため、論理的に機能します。 

複雑さを分析すると問題が現れます。 周波数マップの維持は挿入ごとに O(1) で償却されますが、O(N^2) 個のサブ配列があるため、合計作業量は O(N^2) となり、3 × 10^5 までの N には遅すぎます。 

重要な洞察は、問題を「ちょうど K」から「最大で 2 つの K」カウントの差に変換することです。 最大 K 個の個別の値を持つ部分配列を効率的に数えることができる場合、正確に K 個の個別の値を持つ部分配列の数は、最大 K を持つサブ配列と最大 K − 1 を持つサブ配列の差になります。これが機能するのは、最大 K を持つすべての部分配列が合計に寄与し、最大 K − 1 を持つサブ配列を減算すると、K 未満の個別の値を持つすべてのケースが削除され、正確に K が残るからです。 

「最大で K 個の異なる」問題は、スライディング ウィンドウに適しています。 ウィンドウ [l, r] を維持し、必要に応じて左ポインターを移動することで、個別の要素の数が K を超えないようにします。

 | ブルートフォース | O(N^2) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を atMost(K) − atMost(K − 1) の計算に落とし込みます。 

### ステップ

1. 最大 K 個の個別の値を含む部分配列をカウントする関数 atMost(K) を定義します。 スライディング ウィンドウを使用して計算します。 
2. 現在のウィンドウ内の要素の頻度マップと、現在ゼロ以外の頻度を持つ値の数を追跡する個別のカウンターを維持します。 
3. 2 つのポインター l と r を 0 に初期化し、応答変数 ans = 0 を初期化します。 
4. r を配列上で左から右に展開します。 新しい要素 A[r] ごとに、その頻度を増やします。 この要素がウィンドウに初めて表示される場合は、distinct をインクリメントします。 
5.distinct が K より大きい場合、l を前方に移動し、distinct が再び最大 K 以下になるまで周波数を減少させることにより、ウィンドウを左から縮小します。周波数が 0 になると、distinct を減分します。 
6. ウィンドウが制約を満たすと、r で終わり、l から r までの任意の場所で始まるすべての部分配列が有効になります。 (r − l + 1) を ans に加算します。 
7. r が最後まで手順 4 ～ 6 を繰り返します。 
8. 最終的な答えは atMost(K) − atMost(K − 1) です。 

### なぜ効果があるのか

 アルゴリズムは、すべての位置 r で、ウィンドウ [l, r] に最大で K 個の異なる値が含まれるように、最小の左境界 l を維持します。 l より前に始まる r で終わる部分配列は、少なくとも K + 1 個の個別の値を導入します。これは、左に拡張しても要素が追加されるだけであり、個別の数を減らすことができないためです。 

これにより、単調な構造が作成されます。各 r について、すべての有効な開始点が連続セグメントを形成します。 それらを r − l + 1 としてカウントすると、各有効なサブ配列が正確に 1 回カウントされ、無効なサブ配列が含まれないことが保証されます。 次に、減算ステップで、重複の問題を発生させることなく、正確に K 個の個別の値を分離します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def at_most(k, a):
    if k <= 0:
        return 0
    freq = defaultdict(int)
    l = 0
    distinct = 0
    res = 0

    for r in range(len(a)):
        if freq[a[r]] == 0:
            distinct += 1
        freq[a[r]] += 1

        while distinct > k:
            freq[a[l]] -= 1
            if freq[a[l]] == 0:
                distinct -= 1
            l += 1

        res += r - l + 1

    return res

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(at_most(k, a) - at_most(k - 1, a))

if __name__ == "__main__":
    solve()
```実装はヘルパー関数 at_most を中心に展開します。 頻度辞書は現在のウィンドウ内の要素数を追跡しますが、distinct は制約に違反したときを確実に把握します。 while ループは、ウィンドウが多様になりすぎるたびに有効性を復元する重要な部分です。 

ソルブでの減算は、正確な K カウントから最大 K カウントへの変換を直接実装します。 エッジケース k = 0 は、空でない部分配列がゼロの個別要素を持つことができないため、早期にゼロを返すことによって処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各ポインター l および r は、各 atMost 呼び出しで合計最大 N 回移動します。 
| スペース | O(N) | 周波数マップはウィンドウ内のアクティブな要素の数を保存します |

 このソリューションは配列に対して 2 つの線形パスを実行するため、合計の複雑さは N で線形のままであり、最大 3 × 10^5 の N の制限内に快適に収まります。 

## テストケース```python
import sys, io
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def at_most(k, a):
        if k <= 0:
            return 0
        freq = defaultdict(int)
        l = 0
        distinct = 0
        res = 0
        for r in range(len(a)):
            if freq[a[r]] == 0:
                distinct += 1
            freq[a[r]] += 1
            while distinct > k:
                freq[a[l]] -= 1
                if freq[a[l]] == 0:
                    distinct -= 1
                l += 1
            res += r - l + 1
        return res

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    return str(at_most(k, a) - at_most(k - 1, a))

assert run("8 2\n1 2 1 2 1 3 1 2\n") == "14"
assert run("8 3\n1 2 1 2 1 3 1 2\n") == "14"

# minimum size
assert run("1 1\n5\n") == "1"

# impossible case
assert run("5 2\n1 1 1 1 1\n") == "0"

# all distinct
assert run("5 3\n1 2 3 4 5\n") == "3"

# boundary
assert run("6 2\n1 2 3 1 2 3\n") == "10"

 ## 特殊なケース

 エッジ ケースの 1 つは、K が 1 に等しい場合です。この場合、同一の要素で構成されるすべてのサブ配列が有効です。 atMost(1) はすべての一様セグメントをカウントし、部分配列がゼロの個別の値を持つことができないため、atMost(0) は正しくゼロを返すため、atMost 変換は引き続き機能します。 

K が配列内の個別の値の数よりも大きい場合、別のエッジ ケースが発生します。 ここで、atMost(K) はすべての部分配列をカウントしますが、atMost(K − 1) はすでに atMost(K) と等しく、ゼロが生成されます。 個別のカウンタが K を超えることがないため、スライディング ウィンドウは完全なリセットをトリガーすることはなく、配列全体が可能な限り単一の有効な領域として扱われます。 

最後の微妙なケースは、頻繁な変更により左ポインタが繰り返し縮小される場合です。 1、2、1、2、1、2 のようなパターンでも、ウィンドウは振動しますが、各インデックスはポインターの移動ごとに最大 1 回処理され、線形の複雑さを維持しながら、重複する有効なセグメントの正しいカウントを維持します。
