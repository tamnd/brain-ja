 ## 解決策
 ## 問題の理解

 すでに 1×1×1 の立方体である非常に小さなルービックのようなオブジェクトの状態が与えられています。これは、内部構造を持たないちょうど 6 つの色の面があることを意味します。 各面は空間内で固定位置を持ち、入力はその固定方向で 6 つのラベル付き面のそれぞれに現在どの色が表示されているかを記述します。 

各面が特定のターゲット色を持つ解決された構成から、立方体の面の回転を適用できます。 各移動により 1 つの面 (前後左右上下) が時計回りに 90 度回転し、同じ面の回転を最大 3 回繰り返すと、表示される面の異なる並べ替えに対応します。 目標は、任意のシーケンスを物理的にシミュレートすることではなく、指定された構成を、前面が白く、立方体の残りの部分が有効な立方体の回転によって引き起こされる一貫した解決された配置となるターゲット構成に変換する最短の一連の動きを見つけることです。 

重要な構造上の制約は、有効な面の回転を使用して解決された状態から入力状態に到達できることが保証されていることです。 これは、6 色の任意の並べ替えではなく、立方体対称性によって引き起こされる有限状態空間内で完全に作業していることを意味します。 

各移動は可逆的でコストが均一であるため、このタスクは、ノードが立方体状態、エッジが面の回転である有限グラフ上の最短経路問題になります。 隠れた難しさは、グラフが非常に小さいにもかかわらず明示的に与えられておらず、6 つの面の順列を単純に検索すると、すでに最大 6 個しか示されていないことです。 ただし、有効な立方体の回転により、到達可能な状態は 24 の方向状態のみに制限されます。 

単純な間違いは、これを 6 つの面にわたる完全な置換問題として扱い、720 の州にわたって BFS を実行することです。これはまだ小さいですが不必要であり、構造を曖昧にします。 もう 1 つの間違いは、回転によって面間の隣接性制約が維持されるため、すべての置換が有効な状態になるわけではないことを無視していることです。 

強調する価値のあるエッジケースは、キューブがすでに解決されている場合です。 たとえば、入力`1 2 3 4 5 6`ID 構成に対応するため、答えは次のようになります。`0`動きます。 一連の回転をやみくもに出力するソリューションは、ここでは正しくありません。 

もう 1 つの微妙なケースは、複数の異なるシーケンスが同じ最小状態変換を生成する場合です。 たとえば、次のような逆回転`L1`そして`L3`は逆なので、ローカルでキャンセルする素朴な貪欲なアプローチでは、真の最短解がゼロまたは 1 つの手であることを見逃してしまう可能性があります。 

## アプローチ

 ブルート フォースの観点では、立方体の各状態をグラフ内のノードとして扱い、許容される各面の回転をエッジとして扱います。 初期構成から、ターゲットの解決済み構成に到達するまで幅優先検索を実行します。 各状態は 6 要素の配列として表され、各動きは面の回転ルールに従ってこれら 6 つの値を並べ替えます。 

重み付けされていないグラフ上の BFS は常に最短パスを見つけるため、このアプローチは正しいです。 問題は正確さではなく、状態と遷移をどのように表現するかです。 6 つすべてを明示的に列挙すると、 順列を作成し、回転ごとに遷移を定義しても、BFS は約 720 の状態と最大でも数千のエッジで動作しますが、これは制約にとってはすでに自明です。 

ただし、これはより深い構造を無視しています。つまり、すべての順列に到達できるわけではなく、到達可能なセットは立方体の 24 個の回転方向とまったく同じです。 したがって、完全な置換空間は過剰です。 問題は、キューブの状態空間がサイズ 24 のキューブの回転グループであることを認識することに帰着します。これにより、すべての状態と遷移を事前定義し、BFS を 1 回実行することができます。 

状態インデックスに対する各移動の影響を事前計算し、次に 24 状態にわたる BFS を実行して、ターゲットの解決された状態からの最短パスを計算できます。 これにより、任意の入力状態から最適な移動シーケンスまでの固定ルックアップ テーブルが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての順列に対するブルート フォース BFS | O(6! · 移動) | お(6!) | 受け入れられるが不要 |
 | キューブの方向状態に関する BFS | O(24・手数) | お(24) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず立方体の状態空間を形式化します。 各状態は、剛立方体の 24 の可能な方向の 1 つに対応します。 色を任意に追跡するのではなく、回転の下で 6 つの面がどのように並べ替えられるかを追跡します。 

解決された状態を、各面がターゲット カラーを持つ構成として事前定義し、それを BFS のルートとして扱います。 

1. 各立方体の方向を、前、後、左、右、上、下などの固定順序の 6 つの面の色のタプルとしてエンコードします。 このエンコーディングは、回転によって隣接構造が維持されるため、到達可能な空間内の状態を一意に識別します。 
2. F、B、L、R、U、D の 6 つの動きのそれぞれの効果を定義します。各動きは 6 つの顔の位置の順列です。 たとえば、前面を回転すると、反対側の面を固定したまま、周囲のエッジ隣接面が循環します。 これらの順列をハードコーディングします。 
3. 解決された状態から開始して、6 つの手を繰り返し適用することで、到達可能なすべての状態に対して BFS を実行します。 状態ごとに、親状態と、そこに到達するために使用された移動を保存します。 これにより、24 状態グラフにわたる最短パス ツリーが構築されます。 
4. BFS が完了したら、状態からその距離までのルックアップと、解決された状態からその距離に到達するために必要な移動シーケンスを構築します。 
5. 入力構成が与えられると、それをエンコーディング内の状態にマッピングし、その事前計算された最短シーケンスを直接読み取ります。 

重要なアイデアは、通常の検索方向を逆にするということです。 入力から検索する代わりに、解決された状態からあらゆる可能な方向への最短パスを事前計算します。これにより、すべてのクエリが定数時間の検索になることが保証されます。 

### なぜ効果があるのか

 面の回転の下での立方体方向空間は、各エッジが等しい重みを持つ有限の接続されたグラフを形成します。 BFS は、解決された状態から、到達可能なすべての状態への最短距離を同時に計算します。 解決された構成からはすべての有効な入力状態に到達できることが保証されているため、BFS ツリーはすべての可能な入力をカバーします。 保存された親ポインターは、クエリ時に再計算を行わずに最適なシーケンスを再構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We assume faces are ordered as [F, B, L, R, U, D]

# Each move is a permutation of indices 0..5
moves = {
    'F': (4, 5, 2, 3, 1, 0),
    'B': (5, 4, 2, 3, 0, 1),
    'L': (0, 1, 4, 5, 3, 2),
    'R': (0, 1, 5, 4, 2, 3),
    'U': (3, 2, 0, 1, 4, 5),
    'D': (2, 3, 0, 1, 5, 4),
}

# Precompute all 24 cube orientations by BFS from identity
from collections import deque

def apply(state, mv):
    perm = moves[mv]
    return tuple(state[i] for i in perm)

start = (1, 2, 3, 4, 5, 6)

dist = {start: 0}
parent = {start: (None, None)}
q = deque([start])

while q:
    s = q.popleft()
    for m in moves:
        ns = apply(s, m)
        if ns not in dist:
            dist[ns] = dist[s] + 1
            parent[ns] = (s, m)
            q.append(ns)

def build_path(state):
    path = []
    while parent[state][0] is not None:
        state, m = parent[state]
        path.append(m + "1")
    return path[::-1]

# read input state
arr = tuple(map(int, input().split()))
res = build_path(arr)

print(len(res))
for x in res:
    print(x)
```この実装では、キューブの状態を 6 タプルとしてエンコードし、BFS を使用して解決された構成から最短パスを事前計算します。 の`apply`関数は、立方体力学がエンコードされる唯一の場所であり、面の回転を表す固定順列を適用します。 

実装の微妙な点は、クエリ時に幾何学的推論を試みないことです。 すべての幾何学的構造は固定順列テーブルにプッシュされます。 これにより、隣接する面を誤って回転したり、向きの規則を混合したりするような間違いを回避できます。 

の`parent`マップは以前の状態と使用された動きの両方を保存するため、バックトラッキングによって最短シーケンスを再構築できます。

 ## 特殊なケース

 ID 状態は最も単純ですが、最も重要な例外ケースです。 入力が解決された構成と等しい場合、BFS 距離はゼロになり、親ポインターは移動を格納しません。 再構築ループはすぐに終了し、必要な出力形式と一致する空のシーケンスが生成されます。 

2 番目のケースは、反対側の面を独立して交換したように見える構成です。 このような入力の場合、BFS グラフには同じ長さの複数の最短パスが含まれる場合があります。 親ポインターの再構成では任意に 1 つが選択されますが、BFS レイヤーの距離が厳密に増加しているため、最小性が保証されます。 

3 番目のケースは、立方体が複数の軸で反転して表示される場合です。たとえば、`(6,5,4,3,2,1)`。 この問題は解決には程遠いように見えますが、依然として 24 州の軌道内にあります。 BFS は、少数の回転でこの配列に到達することを保証し、再構成は置換構造を直接解釈しようとすることなく、有効な最小シーケンスを正しくバックトラックします。
