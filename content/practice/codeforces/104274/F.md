 ## 解決策
 ## 問題の理解

 長さの隠されたバイナリ配列を扱っています$N$。 ちょうど 2 つの位置に値 1 が含まれ、他のすべての位置には 0 が含まれます。配列を直接見ることはできません。 代わりに、次の形式のクエリを行うことができます: サブセグメントの値の合計を教えてください$[L, R]$。 それぞれの答えは、そのセグメント内に 2 つの隠されたもののうちのいくつが存在するかを示します。 

私たちのタスクは、最大 50 個の範囲合計クエリを使用して、2 つのインデックスが存在する場所を特定することです。 

重要な制約は、$N$と同じ大きさにすることができます$10^6$したがって、各位置を個別に検査する方法はすぐに遅すぎます。 リニアスキャンには次のことが必要です$N$最悪の場合、制限を大幅に超えるクエリが実行されます。 対話制限 50 クエリは、通常、慎重に設計された範囲クエリと組み合わせた二分探索を伴う対数戦略を強く示唆しています。 

両方の位置がすべてのクエリに寄与するという事実を考慮せずに、接頭辞の合計に対する素朴な二分探索を使用して両方の位置を独立して見つけようとすると、微妙な失敗のケースが発生します。 たとえば、それらが位置 3 と 10 にあるとします。プレフィックスの合計を使用して最初の値を見つけようとすると、すべてがうまくいきます。 しかし、最初に見つかった位置を除外せずに、同じロジックを使用して 2 番目の位置を見つけようとすると、その後のすべてのクエリが依然として既知の位置によって汚染され、バイナリ検索条件が矛盾します。 これにより、個々のクエリが正しい場合でも、誤った分岐や誤った答えが発生します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。1 を返す 2 つのインデックスが見つかるまで、すべての単一の位置をクエリします。これは正しいです。各クエリは単一の位置を分離しますが、それには次のことが必要です。$N$最悪の場合はクエリ。 と$N = 10^6$、これはすぐに 50 クエリの制限を超えてしまい、実行不可能になります。 

より構造化されたアイデアは、プレフィックス合計を使用することです。 金額を直接問い合わせることができれば$[1, i]$次に、プレフィックスの合計が 1 になる最初の位置を二分探索して、一番左のボールを識別します。 これが機能するのは、プレフィックスの合計が単調であるためです。 最初の位置を見つけた後$p_1$、2 番目の位置は除外することで見つけることができます。$p_1$将来のレンジ合計から。 既知のインデックスを無視するクエリをシミュレートできると、残りの構造は再び単一の非表示構造のように動作し、別の二分探索が可能になります。 

重要な点は、範囲クエリと 1 つのインデックスの知識を組み合わせれば、2 番目のインデックスのクリーンなバイナリ検索空間をシミュレートするのに十分であるということです。 各クエリは、既知の位置が範囲内にあるかどうかを減算することで調整できます。

 | ブルートフォース |$O(N)$クエリ |$O(1)$| 遅すぎる |
 | 調整されたクエリによる二分検索 |$O(\log N)$クエリ |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 任意のセグメント内の非表示の数を返すクエリ関数へのアクセスを維持します。 

### ステップ 1: 最初のボールを見つける

 範囲で二分探索をします$[1, N]$。 中間点に向けて$mid$、私たちは合計を求めます$[1, mid]$。 答えが少なくとも 1 の場合、最初のボールは左半分にあり、そうでない場合は右半分にあります。 正確なインデックスを分離するまで検索を絞り込みます$p_1$。 

The correctness comes from the fact that prefix sums over a binary array with a single known threshold transition from 0 to 1 exactly once at the first occurrence of a 1.

 ### ステップ 2: セカンド ボールを探す準備をする

 これで 1 つの位置がわかりました$p_1$。 セグメントに対する後続のすべてのクエリ$[L, R]$は次のように解釈できます。$$\text{true\_sum}(L, R) = \text{query}(L, R) - [p_1 \in [L, R]]$$この修正により、すでに発見されたボールの寄与が除去されます。 

### ステップ 3: 修正された二分探索を使用して 2 番目のボールを見つける

 もう一度二分探索をしてみます$[1, N]$。 各中間点について$mid$、調整されたプレフィックスの合計を計算します。$[1, mid]$。 この調整された合計が少なくとも 1 であれば、2 番目のボールは左半分にあります。 それ以外の場合は、右半分にあります。 これにより 2 番目の位置が分離されます$p_2$。 

この調整により、配列内に未知の 1 が 1 つだけ存在するかのように検索が動作するようになります。 

### ステップ 4: 両方の位置を出力する

 検出された 2 つのインデックスを昇順に出力します。 

### なぜ効果があるのか

 二分探索の各段階で、決定述語は、少なくとも 1 つの目に見えないボールが接頭語内にあるかどうかのみに依存します。 すでに発見されている位置の寄与を除去した後、構造は正確に単一 1 問題に縮小されます。 これにより述語の単調性が維持され、二分探索の正確さが保証されます。 各フェーズでは 1 つの一意の位置が分離されるため、アルゴリズムは重複を返したり、有効なインデックスを見逃したりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r)
    sys.stdout.flush()
    return int(input().strip())

def find_one(exclude=-1):
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        res = ask(l, mid)
        if exclude != -1 and l <= exclude <= mid:
            res -= 1
        if res >= 1:
            r = mid
        else:
            l = mid + 1
    return l

n = int(input().strip())

# find first position
p1 = find_one()

# find second position with exclusion
def ask_adj(l, r):
    res = ask(l, r)
    if l <= p1 <= r:
        res -= 1
    return res

l, r = 1, n
while l < r:
    mid = (l + r) // 2
    if ask_adj(l, mid) >= 1:
        r = mid
    else:
        l = mid + 1

p2 = l

if p1 > p2:
    p1, p2 = p2, p1

print("!", p1, p2)
sys.stdout.flush()
```このソリューションでは、インタラクションを小さなラッパー関数に分割します。`ask`これにより、すべてのクエリが即座にフラッシュされます。 最初の二分探索では、生の接頭語クエリを使用して 1 つのボールを見つけます。 その後、すべてのクエリは既知の位置の影響を差し引くことによって修正され、クリーンな単一ターゲット検索空間が効果的に復元されます。 2 番目のバイナリ検索は構造的には同じですが、この調整されたクエリ関数の下で動作します。 

除外ロジックには注意が必要です。 減算は、既知のインデックスがクエリ範囲内にある場合にのみ実行する必要があります。そうでない場合、調整によりカウントが誤って減少し、単調性が崩れてしまいます。

 ## 特殊なケース

 エッジケースの 1 つは、2 つのボールが隣接している場合です。 この状況では、プレフィックス クエリは 0 から 1 に変化し、その後すぐに 2 に変化しますが、バイナリ検索ではプレフィックスの合計が 1 以上であるかどうかのみがチェックされるため、2 番目のインデックスと混同されることなく最初のインデックスが正しく分離されます。 

もう 1 つのエッジ ケースは、2 回目の検索中に、最初に見つかったインデックスがクエリ範囲の境界に正確に位置する場合です。 除外ロジックにより、関連する場合にのみその寄与が削除されることが保証されます。 たとえば、次の場合$p_1 = 5$そして私たちはクエリします$[1,5]$、生の答えは包含に応じて 1 または 2 になる可能性がありますが、ちょうど 1 を減算すると正確さが維持され、バイナリ述語が単調に保たれます。
