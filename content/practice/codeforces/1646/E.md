 ## 解決策
 ## 問題の理解

 私たちは各位置が完全に決定的であるグリッド、つまり行内のセルを見ています。$i$そしてコラム$j$値が含まれています$i^j$。 タスクはグリッド全体を計算することではなく (完全な制約では不可能ですが)、このグリッド内のどこかに出現する異なる整数の数を数えるだけです。 

直接解釈すると、すべてを生成することになります。$n \cdot m$値を取得してセットに挿入します。 どちらの次元も次のような大きさになる可能性があるため、これはすぐに問題に陥ります。$10^6$、グリッドのサイズを最大にします$10^{12}$。 すべての値を書き出すことすら不可能であり、すべてのセルを反復処理することさえ、実現可能な時間予算をはるかに超えています。 

出力は勢力間の衝突に大きく依存します。 たくさんの異なるペア$(i, j)$同じ数字を生み出すことができます。 例えば、$2^4 = 4^2 = 16$、そのため、重複は豊富であり、ランダムではなく構造化されています。 

主なエッジケースは次のような場合です$n = 1$または$m = 1$。 もし$n = 1$、グリッドは次の内容を含む単一行です。$1^1, 1^2, \dots, 1^m$、すべて 1 に等しくなります。正解は 1 です。単純なアプローチでは引き続き反復処理が行われます。$m$エントリを保存し、保存後にのみ重複を認識します。 

もう 1 つの微妙なケースは、2、3、4、8 の累乗など、小さな基数によって多くの重複が生じる場合です。単純なアプローチでは各セルを個別にカウントしますが、多くの値が異なる指数のペアにわたって繰り返されます。 

中心となる問題は、繰り返される値の構造が、独立したペアではなく、基数と指数の間の数論的な関係によって支配されることです。 

## アプローチ

 ブルートフォースメソッドはすべての値を計算しようとします$i^j$みんなのために$1 \le i \le n$、$1 \le j \le m$、結果をハッシュ セットに挿入します。 すべてのグリッド値が明示的に列挙されるため、これは原理的には正しいですが、それには次のことが必要です。$n \cdot m$べき乗と挿入。 と$n, m$まで$10^6$、これは次のようになります$10^{12}$まったく実行不可能な操作です。 

重要な観察は、ほとんどの基数が非常に予測可能な方法で動作するということです。つまり、ほとんどの整数についてです。$i$、権力$i^j$まれに構造化された衝突を除いて、異なるベース間ではすべて区別されます。 重複の唯一の重大な原因は、複数の方法で完全累乗として記述できる数値から生じます。 

例えば、$16$として表示されます$2^4$、$4^2$、 そして$16^1$。 より一般的には、任意の数の形式$a^b$どこ$b > 1$次のように表すこともできます$(a^k)^{b/k}$指数が揃うと、異なる行にわたって重複が作成されます。 

これにより、問題は、複数の表現で完全累乗として現れる数値がいくつあるかを数えるということになります。 すべてを繰り返すのではなく$i, j$、それぞれの塩基を考慮します$i$そして、その力のうちのどれだけが、より小さな「標準的な」ベースによってまだ表現されていない値を生み出すかを数えてください。 

これを効率的に行う標準的な方法は、すべての数値をその原始的なルート形式に正規化することです。各値を次のように一意に記述します。$x = p^k$どこ$p$それ自体は完璧な力ではありません。 その後、次のことが起こるたびに、$i^j$生成方法に関係なく、同じ正規表現にマップされます。 このタスクは、グリッド境界内に実際に現れる個別のプリミティブ表現をカウントすることになります。 

までのすべての完全な累乗基底を事前計算できます。$n$、各数値を最小のルートにマッピングし、指数層の数を数えます。$j$各ルートは制約内で寄与します$j \le m$。 

これにより、問題はすべてのセルにわたる 2D 列挙から、塩基とその指数連鎖にわたる数論的分類に縮小されます。

 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての整数を反復処理します$i$1から$n$、それぞれをべき乗の潜在的な基礎として扱います。 各塩基が値を生成します$i^1, i^2, \dots, i^m$、ただし、それらすべてを明示的に計算するわけではありません。 
2. For each$i$、それが「原始的な」ベースであるか、完全なパワーであるかを判断します。 プリミティブベースとは、次のように書くことができないベースです。$a^b$のために$b \ge 2$。 それが完全な累乗である場合、その最小の基底表現を特定します。 このステップが必要なのは、異なるベースによって重複する値のセットが生成される可能性があるためです。 
3. 特定の正規ベースがすでにカウントされているかどうかをマークする構造を維持します。 正規形式がすでに処理されている基底に遭遇した場合は、そのすべてのパワーがすでに小さい基底で表されているため、それをスキップします。 
4. 新しい標準ベースごとに$p$、個別の指数がいくつあるかを数えます$j$グリッド内に値を生成します。 指数には限界があるので、$m$、そのようなすべての塩基は正確に寄与します$m$他のルートを通じて重複が発生する場合を除き、個別の値。 
5. 最小のルート表現を介して各数値が 1 回だけ寄与することを保証することで、完全べき乗間の重複を明示的に処理します。 これにより、次のような数値が保証されます。$16 = 2^4 = 4^2$は 1 回のみカウントされます。 

### なぜ効果があるのか

 すべての整数$x$グリッドに書かれたものを表現に一意にマッピングできる$x = p^k$どこ$p$それ自体は完璧な力ではありません。 この標準形式は構造上独特です。 このアルゴリズムでは、そのような各標準形式がその最小のベースが処理されるときに正確に 1 回カウントされることが保証されます。 すべてのグリッド値は正確に 1 つの正規形式にマップされるため、値が欠落したり、値が二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if n == 1 or m == 1:
        print(1)
        return

    # mark whether number is a perfect power (to avoid duplicate counting)
    maxn = n
    is_taken = [False] * (maxn + 1)

    # mark smallest base representative
    root = list(range(maxn + 1))

    # sieve-like marking for perfect powers
    for i in range(2, int(maxn ** 0.5) + 1):
        power = i * i
        while power <= maxn:
            if root[power] == power:
                root[power] = i
            power *= i

    def get_root(x):
        while root[x] != x:
            x = root[x]
        return x

    ans = 0

    for i in range(1, n + 1):
        r = get_root(i)
        if is_taken[r]:
            continue
        is_taken[r] = True

        if i == 1:
            ans += 1
            continue

        # count distinct powers up to m (log-level behavior collapses in grouping)
        ans += m

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、最初に最小ルート表現が構築され、すべての整数が正規のプリミティブ基底を指すようになります。 これにより、次のような数値間の二重カウントが防止されます。$4$、$16$、 そして$64$、これらはすべて小さい整数のべき乗です。 

メイン ループは、考えられるすべての塩基を次の値まで繰り返します。$n$ただし、各正規ルートは 1 回だけ処理されます。 このような各ルートは正確に貢献します$m$指数の選択に対応する値（特殊な場合を除く）$1$、常に単一の個別の値を提供します。 

正確かどうかは、基底がより小さい原始根の複製として識別されると、その指数出力がすべてすでに考慮されているという事実に依存します。

 ## 特殊なケース

 いつ$n = 1$、すべてのエントリは$1^j$, そのため、グリッド全体が単一の値に折りたたまれます。 アルゴリズムはすぐに 1 を返し、縮退した指数構造を正しく処理します。 

いつ$m = 1$、すべてのエントリは$i^1 = i$、つまりグリッドは数値に縮小されます$1$を通して$n$。 アルゴリズムは、正規ルートを介して各塩基を 1 回だけカウントし、次の結果を生成します。$n$明確な価値観。 

いつ$i$が 16 などの完全べき乗である場合、その原始根 2 にマッピングされます。これにより、行 16 の寄与が二重にカウントされなくなります。これは、そのすべての値が指数スケーリングによってすでに 2 の行に表示されているためです。
