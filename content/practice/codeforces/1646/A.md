 ## 問題の理解

 長さのシーケンスが与えられます$n+1$。 Each element is either a “small” number in the range$[0, n-1]$、または以下に等しい特別な大きな値$n^2$。 伝えられるのは 2 つのことだけです: パラメータ$n$シーケンス内のすべての要素の合計は、次のように示されます。$s$。 元のシーケンスは失われ、その値が含まれる位置の数を判断する必要があります。$n^2$。 

シーケンスの構造は非常に厳密です。 特殊でない要素はすべて最大でも寄与します$n-1$それぞれの特別な要素が正確に寄与する一方で、合計に$n^2$、他のものよりもはるかに大きいです。 このスケールの分離が、再構成を可能にする重要な特徴です。 

制約により、最大で$2 \cdot 10^4$テストケース、$n$まで$10^6$そして$s$まで$10^{18}$。 これにより、シーケンスを再構築したり、個々の要素について推論したりしようとするアプローチは除外されます。 有効なソリューションでは、各テスト ケースを定数時間の演算に削減する必要があります。 

素朴なアプローチでは、その数を推測しようとするかもしれません。$n^2$要素が存在する場合は、残りの合計に値を入力できるかどうかを確認します。$[0, n-1]$。 論理的には正しいですが、構造は次のような直接的な代数関係を暗示しているため、そのようなシミュレーションは不要です。$s$、$n$、および特殊な要素の数。 

微妙なエッジケースが現れるのは、$s = 0$。 この場合、すべての要素はゼロである必要があり、答えは必然的に特殊要素がゼロになります。 もう一つのコーナー状況は次のような場合です。$s$非常に大きく、ほぼ全体が以下によって形成されています。$n^2$貢献。 ここで、残りは依然として有限の小さな値を使用して実現可能でなければならず、問題はそのような一貫性を保証します。 

## アプローチ

 強引なアイデアは、特殊な要素の数を仮定することです。$k$からの範囲$0$に$n+1$。 候補者ごとに$k$、残りの合計が以下を使用して説明できるかどうかを確認しようとします。$n+1-k$それぞれの要素$[0, n-1]$。 固定の場合$k$、減算します$k \cdot n^2$から$s$、剰余が間にあるかどうかを確認します。$0$そして$(n+1-k)(n-1)$。 これが機能するのは、残りの要素の可能な最小の寄与がゼロであり、すべての要素が寄与する場合が最大になるためです。$n-1$。 

この総当たりスキャンは正しいですが、不必要です。 それはまだ実行されます$O(n)$テストケースごとに、次の場合には遅すぎるでしょう。$n$が大きく、テストケースの数も多い。 

重要な観察は、実際にはすべての値を試す必要はないということです。$k$。 制約構造により、一意の有効な制約が強制されます。$k$、合計から直接導き出すことができます。 それぞれの特別な要素が過剰に寄与するため、$n^2$通常の値と比較すると、問題を分割として扱うことができます。$s$小さな値から基本部分に、そして特別な値から固定寄与度に変換されます。 

させて$k$要素の数が次と等しいこと$n^2$。 残り$n+1-k$要素はせいぜい寄与する$n-1$それぞれなので、それらの最大可能合計は次のようになります。$(n+1-k)(n-1)$。 これは次のことを意味します:$$k \cdot n^2 \le s \le k \cdot n^2 + (n+1-k)(n-1)$$検索する代わりに計算します$k$貪欲な抽出により、できるだけ多くを取得します$n^2$できるだけから$s$ただし、残りの部分が依然として境界値によって形成できることを確認する必要があります。 なぜなら$n^2$範囲を支配する$[0, n-1]$、正しい$k$の整数除算構造によって決定されます。$s$に対して$n^2$そして残された実現可能性。 

より簡単な再定式化は、次のことを一度観察することです。$k$が固定され、残りは$r = s - k n^2$満たさなければなりません$0 \le r \le (n+1-k)(n-1)$。 一意性の保証により、正確に 1 つが保証されます。$k$はこれを満たしており、上限付近の算術推論を使用して定数時間で見つけることができます。 

実際的な解決策は、可能な最大値から反復することになります。$k$下向きまたは直接派生$k$限界から。 以来$k \le n+1$、 だけでなく$k n^2 \le s$、すぐに得られます$k \le s // n^2$。 この上限から開始して、最大でも一定数のチェックによって下方調整すると、効率的に答えが得られます。

 ## アルゴリズムのチュートリアル

 以下に等しい数の要素を抽出することに焦点を当てます。$n^2$合計金額から。 

1. 特殊要素の最大可能数を次のように計算します。$k = s // n^2$。 各特殊要素が寄与するため、これは絶対的な上限です。$n^2$, したがって、これを超えると合計がオーバーシュートします。 
2. クランプ$k$せいぜい$n+1$、しかないので、$n+1$合計の要素。 
3. この候補があるかどうかを確認します$k$残りの合計が確認されることで有効です$r = s - k \cdot n^2$を使用して形成できます$n+1-k$それぞれの数字$[0, n-1]$。 これには必要です$r \le (n+1-k)(n-1)$。 
4. 条件が失敗した場合は、減少します$k$有効になるまで。 制約の構造により、必要な調整は最大でも一定数であることが保証されます。$k$実現可能性の不等式を満たします。 

### なぜ効果があるのか

 合計は、次の 2 つの部分に一意に分解されます。$n^2$特別な要素と通常の要素からの制限された寄与から。 通常の要素には上限があるため、$n-1$の過大評価を補うことはできません。$k$たとえ一杯でも$n^2$残りの容量が正確に許可しない限り。 これにより、厳密な実現可能性のウィンドウが作成されます。$k$1 つの整数だけが下限と上限の両方を同時に満たすようにします。 このアルゴリズムは、単調な条件内を効果的に検索します。$k$したがって、修正は常に固有の有効な解決策に向かって進みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        max_k = s // (n * n)
        max_k = min(max_k, n + 1)

        def ok(k):
            r = s - k * n * n
            if r < 0:
                return False
            return r <= (n + 1 - k) * (n - 1)

        k = max_k
        while k >= 0 and not ok(k):
            k -= 1

        print(k)

if __name__ == "__main__":
    solve()
```コードは、次の数の初期上限を計算します。$n^2$整数除算を使用する要素。 余計なものがないので安心です$n^2$合計を超えることになります。 ヘルパー関数`ok(k)`残りの合計が非特殊要素の最大容量内に収まることを確認することで、実現可能性をチェックします。 

実現可能条件が単調であるため、下方調整ループは短いです。$k$。 正しい値を渡すと、それ以上減少しても利用可能な容量が増加するだけなので、最初の有効な値は$k$遭遇したものが答えです。 

整数演算には注意が必要です。$s$到達できる$10^{18}$ですが、Python はこれを安全に処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, s = map(int, input().split())
        max_k = s // (n * n)
        max_k = min(max_k, n + 1)

        def ok(k):
            r = s - k * n * n
            return r >= 0 and r <= (n + 1 - k) * (n - 1)

        k = max_k
        while k >= 0 and not ok(k):
            k -= 1
        out.append(str(k))

    return "\n".join(out) + "\n"
