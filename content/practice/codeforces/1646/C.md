 ## 解決策
 ## 問題の理解

 私たちは数値を与えられ、それを個別の「構成要素」の合計として表現するように求められます。 各構成要素は、2 のべき乗または階乗値のいずれかである必要があります。 2 の累乗は指数関数的に増加しますが、階乗はさらに速く増加するため、許容される値のセットは最大の範囲と比較して非常に希薄になります。$10^{12}$。 

タスクは、そのような分解が存在するかどうかを判断するだけではなく、使用される個別のブロックの数を最小限に抑えることです。 区別性が重要であるため、たとえ合計が単純化されるとしても、同じ強力な数値を 2 回再利用することはできません。 

主な問題点は、両方の数値ファミリーが小さなスケールで値が重複していることです。たとえば、$1 = 1! = 2^0$、階乗はすぐに大きくなりますが、それでもターゲット範囲内の 2 のべき乗の合計に匹敵します。 以来$n \le 10^{12}$、任意のサブセットを試すことはできませんが、状態空間を注意深く制御せずに貪欲な減算に依存することもできません。 

素朴な失敗例は、貪欲な選択が最初に 2 の大きなべき乗を取り、最適に分解できない余りが残る場合に発生します。 たとえば、ピッキング$64$最初に$n=70$につながる$6$、 しかし$6$自体は階乗なので、直接ペアにして、より小さな表現を生成する必要があります。 

制約$t \le 100$テスト ケースごとに独立した処理が可能ですが、テストごとの指数探索を厳密に制限する必要があります。 以下の強力な数字の合計数なので、$10^{12}$は小さい (約 60 の 2 乗と 15 階乗) ため、実際の構造は小さな固定宇宙にわたる組み合わせです。 

## アプローチ

 ブルートフォースのアイデアは単純です。強力な数値のすべてのサブセットを列挙し、それらの合計を計算し、次の値に等しい最小サブセット サイズを追跡します。$n$。 候補者の数は約 75 人であるため、これは次のようになります。$2^{75}$サブセットは天文学的に大きく、枝刈りしても使用できません。 

次のステップは、実際に扱っているのは任意の数値ではなく、テスト ケース間で決して変わらない固定された小さな宇宙であることを認識することです。 これにより、以下のすべての 2 のべき乗を前処理できます。$10^{12}$、および同じ制限までのすべての階乗。 この後、各テストは一定サイズのセットに対するサブセット選択問題になります。 

ただし、サブセットの列挙でも大きすぎます。 重要な観察は、答えは順序や構築ではなく、サブセットの選択のみに依存するということです。 これにより、問題は小さなセットにわたる最短和表現に変わり、ビットマスク DP によって自然に処理されます。 

強力な数字をリストに分割します$a_0, a_1, \dots, a_{m-1}$。 次に、状態がどの数値が使用されたかを表すビットマスク上で DP を使用し、形成された合計を追跡します。 以来$n$が大きい場合は、代わりにマスクまたは最小カウントの合計をキーとした辞書に達成可能な合計を格納し、積極的にプルーニングします。 小さいサイズの$m$これを実現可能にします。 

競合ソリューションで使用されるよりクリーンで標準的な単純化は、まず階乗のサブセットのすべての合計を事前計算し (階乗が非常に少ないため)、次に 2 の累乗を貪欲にまたはバイナリ分解によって処理します。 これが機能するのは、バイナリ表現が使用される階乗和と競合しない場合に限り、2 のべき乗は任意の剰余を表すことができるからです。 

これは最終的なアイデアにつながります。階乗のすべてのサブセット (最大 15) を試し、それらの合計を計算し、使用されているビットと重複しない個別の 2 の累乗を使用して剰余を表現できるかどうかを確認します。 「はい」の場合、答えは階乗サブセットのサイズに残りのビット数を加えたものになります。

 ## アルゴリズムのチュートリアル

 まず、以下を超えないすべての階乗のリストを作成します。$10^{12}$。 これらは数が少ないため、安全に列挙できます。 

次に、これらの階乗のすべてのサブセットを試します。 

1. 各サブセットについて、その合計を計算します。 すでに超えている場合$n$、すべての数値が正であり、区別性により再利用が妨げられるため、すぐに破棄します。 
2. 残りの値を次のようにします。$r = n - \text{factorial\_sum}$。 もし$r < 0$、このサブセットはスキップしてください。 
3. ここで、次のように表現してみます。$r$異なる 2 の累乗を使用します。 これは、バイナリ分解が行われた場合にのみ可能です。$r$階乗によってすでに暗示されている 2 のべき乗を再利用しません。 階乗値は固定整数であるため、その寄与は数値的にすでに考慮されているため、単純に以下のことをチェックします。$r$は個別の 2 のべき乗に分解できます。これはバイナリ表現では常に真です。 
4. この構成の項の数は、選択された階乗の数に設定ビットの数を加えたものです。$r$。 
5. すべてのサブセットにわたって最小値を追跡します。 

答えは達成可能な最小値、または$-1$サブセットが機能しない場合。 

### なぜ効果があるのか

 有効な分解はすべて、階乗と 2 の累乗という 2 つの独立した要素に自然に分割されます。 階乗はスパースであり、区別性制約を変更せずに 2 の累乗でマージまたはシミュレーションすることはできません。 ただし、2 の累乗は、バイナリ表現におけるすべての整数の完全な基礎を形成するため、階乗を選択した後の剰余は独自の分解を持ちます。 すべての階乗サブセットを試すため、階乗寄与を含めるための構造的に異なるすべての方法を探索し、それぞれについて、バイナリ表現を使用して合計を最適に完成させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def popcount(x):
    return bin(x).count("1")

# precompute factorials up to 1e12
facts = []
val = 1
i = 1
while val <= 10**12:
    facts.append(val)
    i += 1
    val *= i

def solve(n):
    ans = float('inf')
    m = len(facts)

    for mask in range(1 << m):
        s = 0
        cnt = 0

        for i in range(m):
            if mask & (1 << i):
                s += facts[i]
                cnt += 1
                if s > n:
                    break

        if s > n:
            continue

        r = n - s
        total = cnt + popcount(r)
        ans = min(ans, total)

    return -1 if ans == float('inf') else ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve(n))
```コードはまず階乗をグローバルに 1 回構築します。これは、テスト ケースが同じ制約を共有するため有効です。 各テストは、ビットマスクを使用して階乗のすべてのサブセットを反復します。 サブセットごとに合計とカウントを累積し、合計が超過した場合に早期にプルーニングします。$n$。 

残りはビットカウントを使用して処理されます。これは、2 の個別の累乗を選択することに正確に対応します。 

実装の微妙な詳細は、サブセット ループ内の早期終了です。 それがなければ、不必要な蓄積は依然として正しいですが、速度は遅くなります。 もう 1 つの重要な点は、階乗の数が少ないため、ビットマスクの反復が引き続き実行可能であることです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    facts = []
    val = 1
    i = 1
    while val <= 10**12:
        facts.append(val)
        i += 1
        val *= i

    def popcount(x):

    def solve(n):
        ans = float('inf')
        m = len(facts)

        for mask in range(1 << m):
            s = 0
            cnt = 0
            ok = True

                if mask & (1 << i):

                    cnt += 1

        return -1 if ans == float('inf') else ans

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve(n)))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ状況は次のような場合です。$n$それ自体が強力な数字です。 例えば$n = 32$。 アルゴリズムは空の階乗サブセットを正しく見つけ、剰余が 2 の単乗であることを観察して、答えを導き出します。$1$。 階乗包含を強制しようとすると、カウントが増加するだけであり、列挙により、引き続き空のサブセットが考慮されることが保証されます。 

もう 1 つの微妙なケースは、階乗包含が有益であるように見えても、実際にはビット数が悪化する場合です。 のために$n = 31$、階乗を選択すると、2 の累乗のみを使用する場合と比較して、残りのバイナリ効率が直ちに低下します。 サブセット列挙により、最適性を維持しながら純粋なバイナリ分解パスを確実に評価できます。 

最後の構造的なエッジ ケースは、複数の階乗の組み合わせが同じ合計を生成するが、カウントが異なる場合です。 アルゴリズムはサブセット サイズを明示的に追跡するため、剰余構造が同一の場合は自然に階乗数が少なくなることが優先され、最小化が保証されます。$k$。
