 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられ、各要素を赤、青にペイントすることも、ペイントしないままにすることもできます。 目標は、赤い数字の合計が青い数字の合計よりも厳密に大きく、一方、赤い数字の数が青い数字の数よりも厳密に小さいような色を見つけることです。 各テスト ケースでは、そのような色分けが存在するかどうかを判断するだけで済みます。 カラーリング自体を作成する必要はありません。 

入力制約は重要です。 各シーケンスの長さは 200,000 に達する可能性があり、テスト ケースにわたるすべてのシーケンスの長さの合計も 200,000 に制限されます。 サブセットの数は指数関数的に増加するため、数値のすべてのサブセットを考慮するアプローチは即座に除外されます。 したがって、私たちのアルゴリズムは、テスト ケースごとの要素数が線形であるか、線形に近いものでなければなりません。 値自体は最大 10^9 ですが、値を追加するだけなので、Python では整数のオーバーフローは問題になりません。 

最大の数値が並べ替えられたシーケンスの最後または先頭にある場合、微妙なエッジ ケースが発生します。 たとえば、すべての要素が等しい場合、合計がカウントに応じて線形に増加し、小さい赤色のサブセットが大きい青色のサブセットの合計を超えることが不可能になるため、どの色も条件を満たすことはありません。 もう 1 つの注意が必要なケースは、いくつかの非常に大きな数値が多数の小さな数値と組み合わされる場合です。 要素を任意の順序で選択しようとする単純な試みは、最適な分布を見逃す可能性があります。 この問題は基本的に、赤の場合は「品質」(大きな値)、青の場合は「量」(多くの要素)を優先するように求められます。 

## アプローチ

 ブルートフォースアプローチでは、要素を赤、青、または未塗装に割り当てるためにあらゆる方法が試行されます。 赤と青の各サブセットについて、合計とカウントを計算し、条件を確認できます。 このアプローチは非常に小さなシーケンスには機能しますが、n が 2・10^5 までの場合、サブセットの数が 2^n であるため、まったく実行できません。 

重要な洞察は、赤の数を低く抑えながら赤の合計を最大化するには、赤の最大の要素を選択する必要があるということです。 逆に、合計を低く抑えながら青の数を最大化するには、青の最小要素を選択する必要があります。 これにより、シーケンスをソートし、最大要素と最小要素のプレフィックスをチェックするという問題が軽減されます。 具体的には、配列を昇順にソートし、青には最小の k 要素、赤には最大の k 要素を考慮し、赤の合計が青の合計を超えるまで k を増やすことができます。 任意の時点で、赤のカウントが青のカウントより小さく、赤の合計が青の合計より大きい場合は、停止してYESを宣言できます。 これを満たさないまま真ん中に到達すると答えはNOです。 このアプローチは、並べ替えによりテスト ケースごとに O(n log n) になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | ソート + 2 ポインタの貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取り、昇順に並べ替えます。 並べ替えにより、青色の最小要素と赤色の最大要素を系統的に選択できるため、合計条件とカウント条件の両方を満たすのに最適です。 
2. 2 つのポインターを初期化します。1 つは青い要素のソートされた配列の先頭から始まり、もう 1 つは赤色の要素の終わりです。 
3. 2 つの合計を初期化します。`sum_blue = 0`そして`sum_red = 0`。 
4. 最小の要素を段階的に追加します。`sum_blue`そして最大の要素は`sum_red`それぞれのステップで。 赤と青のカウントを追跡します。 
5. 加算するたびに、現在の赤の合計が青の合計を超えているかどうか、および赤のカウントが青のカウントより小さいかどうかを確認します。 両方の条件が当てはまる場合は、YES と出力して停止します。 
6. 赤のポインタが青のポインタと交差する点に到達し、有効な色が見つからない場合は、「NO」と出力します。 

機能する理由: 並べ替えにより、すべての赤色の要素が青色の要素に対してできるだけ大きくなるようにするため、赤色の数を最小限に抑えながら赤色の合計が最大になります。 より大きなサブセットを段階的にチェックすることにより、赤の合計が青の合計を超える最初のポイントも最小赤カウント要件を満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        sum_red = 0
        sum_blue = 0
        i = 0  # index for blue (smallest)
        j = n - 1  # index for red (largest)
        count_blue = 0
        count_red = 0
        possible = False
        while i < j:
            sum_blue += a[i]
            sum_red += a[j]
            count_blue += 1
            count_red += 1
            i += 1
            j -= 1
            if sum_red > sum_blue and count_red < count_blue:
                possible = True
                break
        print("YES" if possible else "NO")

solve()
```このソリューションは、まずテスト ケースの数を読み取り、各シーケンスを反復処理します。 並べ替えにより、赤の最大値と青の最小値を確実に選択できます。 while ループは、割り当てられていない要素がある限り継続し、合計とカウントの両方を同時に更新します。 有効なカラーリングが見つかった場合は、早期に停止するため、効率的です。 2 つのポインターを選択すると、赤が常に最大の残りの値を持ち、青が最小の値をもつことが保証され、問題の制約を直接反映します。
