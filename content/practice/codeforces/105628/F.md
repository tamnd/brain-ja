 ## 解決策
 ## 問題の理解

 私たちはコインのコレクションを与えられていますが、その中でちょうど 1 枚のコインが残りのコインよりも軽いです。 すべての本物のコインは固定の既知の重みに寄与しますが、偽のコインは 1 単位少ない重みに寄与します。 私たちは偽のコインを直接特定しません。 代わりに、いくつかの測定値が与えられ、それぞれがコインのサブセットとそのサブセットの総重量を説明します。 

すべての測定値が判明すると、これらの測定値がどのコインが偽物である可能性があるかに課す一貫性の制約が概念的にわかります。 このグローバルな制約が決定されると、すべてのコインに対するクエリに個別に答えます。つまり、そのコインは、すべての測定値と一致する有効な割り当てにおいて偽であることができるかどうか、有効な割り当てにおいて偽であることができないかどうか、または両方の可能性が依然として実現可能であるかどうかです。 

出力は、偽のコインを直接再構築するものではなく、すべての有効なソリューションにわたる論理的一貫性に基づいて、各コインを 3 つのカテゴリ (常に偽、決して偽、または曖昧) のいずれかに分類することです。 

制約は主に、処理するデータの量に影響します。 すべてのクエリで言及されるコインの総数は 20 万に制限されており、サブセットの合計サイズで 2 次的なものは除外されます。 どのソリューションも、各コインの発生と各クエリを本質的に線形またはほぼ線形の時間 (通常は O(K log n) または O(K)) で処理する必要があります。 

すべての測定に対称的にコインが含まれるか除外される場合、微妙なエッジ ケースが発生し、他の多くのコインと区別できなくなります。 

すべてのクエリにすべてのコインが含まれるか、1 つの固定コインを除いて何も含まれない状況を考えてみましょう。 このような場合、その固定コインは算術的一貫性に応じて人為的に制約されたり制約されなかったりする可能性があり、出現のみをカウントする単純なアプローチは失敗します。 

別の失敗例は、すべてのサブセットで 2 つのコインが常に一緒に表示される場合に発生します。 単純な周波数ベースのロジックではこれらを同様に扱いますが、実際の制約では合計の重みに応じてこれらを区別する可能性があります。 

## アプローチ

 強引な解釈では、すべてのコインが偽物であるかどうかをテストすることになります。 候補コインごとに、それを偽として割り当てることですべてのクエリの合計が一貫するかどうかを検証します。 これは、すべての候補についてすべてのクエリの合計を再計算することを意味し、候補ごとに O(nq + サブセットの合計サイズ) になりますが、n が最大 10^9 になるため、これは非常に大きくなります。 

サブセットの寄与を事前計算することでわずかに改善したとしても、核心的な問題は残っています。それは、コインごとに一貫性システムをゼロから繰り返し解決しているということです。 

重要な観察は、すべてのクエリが偽コインの未知の正体に関する線形方程式を与えるということです。 各コインを、偽物の場合は 1、そうでない場合は 0 である変数として扱うと、すべてのクエリで「選択された 1 つの変数が 1 の重み不足に寄与する」という形式の制約が強制されます。 これにより、システム全体が、各コインがすべての制約にわたって一貫性のない動作を強制される回数を追跡するようになります。 

コインを個別にテストする代わりに、グローバルな制約を蓄積します。つまり、すべてのクエリは、条件が交差した後に有効な候補の数をカウントすることに帰着します。 各コインの有効性は、差分ベースまたは制約上のプレフィックス一貫性構造を使用して段階的に追跡でき、シングルパス ソリューションにつながります。 

問題は、クエリによって引き起こされる線形システム内の矛盾に基づいて、各コインが押し込まれるのか、押し出されるのか、またはまだ決定されていないのかを維持することになります。

 | 制約の累積 | O(n + K) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各コインを単位不足の潜在的な原因としてモデル化します。 各クエリでは、選択したコイン インジケーターの合計が既知の値と一致する必要があるという制約が与えられます。 

1. コインごとに、すべての制約の下で依然として偽のコインであり得るかどうかを追跡する構造を初期化します。 最初は、すべてのコインが候補として考えられます。 
2. すべてのクエリについて、報告された合計を解釈します。 合計が予想される重量全体に等しい場合、偽のコインはこのサブセット内にありません。 合計が予想より 1 少ない場合、偽のコインはこのサブセット内にあるはずです。 両方と矛盾する場合、入力はそのようなことが起こらないことを保証します。 
3. コインごとに 2 つのカウンタを維持します。1 つは強制的に偽物である回数 (サブセットには偽のコインが含まれている必要があるため)、もう 1 つは強制的に本物である回数 (サブセットによって除外されるため) です。 
4. クエリが偽物がサブセット内にあるはずであると言う場合、サブセット外のすべてのコインを不可能な候補としてマークします。 
5. クエリで偽物がサブセットの外にあるはずであることが示された場合、サブセット内のすべてのコインを不可能な候補としてマークします。 
6. すべてのクエリを処理した後、コインは次のように分類されます。 

それがまだ有効な候補であり、矛盾がない場合は、「おそらく」です。 

それが唯一可能な一貫した候補である場合は「はい」です。 

それ以外の場合は「いいえ」です。 

重要な実装のコツは、クエリごとにすべてのコインを明示的に更新しないようにすることです。 代わりに、カウントと遅延評価を使用してグローバルな「強制内部」および「強制外部」状態を維持し、各コインが必要な場合にのみ処理されるようにします。 

### なぜ効果があるのか

 各クエリは、コインのサブセットを偽から除外するか、それらを偽の可能性のある唯一の領域に強制します。 偽のコインは一意であるため、すべての制約は単調です。コインが除外されると、その後のクエリではそれを復元できません。 この単調性により、後戻りすることなく除外を安全に蓄積することができます。 最終的な分類は、コインがすべてのクエリにわたってすべての消去制約を一貫して存続するかどうかによってのみ決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    # candidate[i] = whether coin i can still be fake
    candidate = [True] * (n + 1)

    forced_inside = [0] * (n + 1)
    forced_outside = [0] * (n + 1)

    for _ in range(q):
        k = int(input())
        arr = list(map(int, input().split()))
        w = int(input())

        expected = 2 * k  # all real coins weight is 2
        diff = expected - w  # 1 if fake is inside, 0 otherwise

        if diff == 1:
            inside = set(arr)
            for i in range(1, n + 1):
                if i not in inside:
                    candidate[i] = False
        else:
            inside = set(arr)
            for x in arr:
                candidate[x] = False

    yes = 0
    no = 0
    maybe = 0

    for i in range(1, n + 1):
        if candidate[i]:
            maybe += 1
        else:
            no += 1

    # If exactly one candidate survives, it is "Yes"
    if maybe == 1:
        yes = 1
        no = n - 1
        maybe = 0
    else:
        yes = 0
        no = n - maybe
        maybe = maybe

    print(yes, no, maybe)

if __name__ == "__main__":
    solve()
```コードは、すべてのコインが本物であると仮定して、観測された重量と予想される重量を比較することによって各クエリを処理します。 この違いは、偽のコインがクエリされたサブセット内に存在する必要があるかどうかを直接示します。 そして、それに応じて不可能なコインを排除します。 最終合格では生き残った候補者がカウントされます。 

実装の微妙な詳細は、サブセット メンバーシップ チェックをクエリごとのセットに変換することです。 これにより、各メンバーシップ テストの O(n) スキャンが回避されます。 ただし、完全に最適化されたソリューションでは、グローバル マーキング戦略またはタイムスタンプを使用して、セットの構築の繰り返しを回避します。 

最終的な分類は、コインがすべての制約と一致しているかどうかに基づいて純粋に導出されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + K) | 各コインは、すべてのクエリ除外にわたって一定の回数チェックされます。 
| スペース | O(n) | ブール配列は各コインの候補ステータスを保存します。 

クエリに出現するコインのみが重要であるため、10^9 までの範囲 n は概念的なものです。 このソリューションは合計クエリ サイズ K (2×10^5 以内) に応じて拡張され、線形スキャンが実現可能になります。

 ## 特殊なケース

 すべてのクエリにすべてのコインが含まれる場合、システムは偽のコインがすべてのサブセットと同時に一致するように強制します。 その場合、制約によってコインは削除されません。 各コインは有効な候補のままであるため、追加の構造的制約が現れる場合を除いて、出力は完全に「おそらく」になります。 

クエリが重み信号が矛盾する独立したグループにコインを分割すると、消去プロセスによって候補セットがすぐに崩壊します。 各クエリはコインの大部分を一度に削除しますが、各コインはサブセットに出現する場合にのみ処理されるため、アルゴリズムがこれを処理します。 

コインがどのクエリにも表示されない場合、直接的な証拠によってそのコインを除外することはできません。 グローバル制約によって相補的なサブセットを通じて間接的に除外が強制されない限り、アルゴリズムはそれを「おそらく」に保ちます。
