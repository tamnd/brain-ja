 ## 解決策
 ## 問題の理解

 すべてのノードがその子から再帰的に構築された関数を表すルート付きの完全なバイナリ ツリーが与えられます。 葉は単純に動作します。葉の機能は単なる恒等マップです。$f_u(x) = x$。 内部ノードは、べき乗によって 2 つのサブツリーを結合します。そのため、ノードが子を残した場合、$l$そして右の子$r$、その場合、その関数は次のようになります。$f_u(x) = (f_l(x))^{f_r(x)}$。 

これらの関数を正確に評価するのではなく、関数の漸近的な増加のみを考慮します。$x \to \infty$。 任意の 2 つのノードの場合$u$そして$v$、どの関数が最終的に支配的になるか、またはそれらが漸近的に等しいかどうかを比較できます。 これにより、ノード上で厳密な合計順序が生じ、インデックスが小さいほど同順位が破られます。 

タスクは、この漸近成長順序に従ってソートされたすべてのノードを出力することです。 

主な難点は、これらの関数が多項式や単純な指数関数ではないことです。 これらは反復された指数タワーであり、その高さはサブツリー構造に依存します。 式は実際の数値表現よりも速く増大し、シンボリック拡張でさえサイズが指数関数的に爆発するため、直接評価することは不可能です。 

制約は大きく、最大で$4 \cdot 10^5$すべてのテスト ケースにわたるノード。 これにより、ノードのペアごとの比較や関数の成長の繰り返しシミュレーションを試みるアプローチが除外されます。 たとえ 1 つの比較であっても、$O(1)$または$O(\log n)$償却されない場合、全体の複雑さは二次関数になります。 

微妙なエッジ ケースは、2 つのノードが同一の漸近動作を生成する場合です。 これは、リーフや対称サブツリーで頻繁に発生します。 このような場合、インデックスによるタイブレークが不可欠となり、成長を表現する場合には、等値情報を近似的ではなく正確に保持する必要があります。 

もう 1 つの落とし穴は、ツリーの高さまたはノードの数が成長順序に直接対応すると仮定していることです。 べき乗は加算的ではないため、これは誤りです。指数構造が強ければ、浅いツリーが深いツリーを支配する可能性があります。 例えば、$x^{x^2}$支配する$x^x$、両方とも同様の構造の深さを持っていますが。 

## アプローチ

 ブルートフォースのアイデアでは、各関数を明示的に計算または記号的に表現しようとします。$f_u(x)$、その後、それらの漸近形式を拡張して比較します。 成長分類に限定したとしても、各ノードは依然として指数関数的なタワーを生成し、その高さはサブツリー構造に依存します。 最悪の場合、置換を繰り返すと、式のサイズがノード数で指数関数的に増大します。 これらの式を正規化または文字列化しようとすると、少なくとも$O(n)$ノードごとに動作し、$O(n^2)$全体。 

重要な観察は、これらの関数が任意の指数ではなく、指数タワーの構造化された階層を形成しているということです。 次のような式の漸近比較$$(f_l(x))^{f_r(x)}$$速度によって完全に支配される$f_r(x)$～に対して相対的に成長する$f_l(x)$。 いつ$x$が大きい場合、べき乗では、底の差よりも指数の差がはるかに強く増幅されます。 これは、右側のサブツリーが成長分類を支配し、左側のサブツリーは二次構造のみに寄与することを意味します。 

これは、各ノードにその漸近的な動作をエンコードする標準的な「成長シグネチャ」を割り当てるボトムアップ アプローチを示唆しています。 これらの署名は次の点で比較できる必要があります。$O(1)$または$O(\log n)$、再帰的な指数構造を展開せずに反映する必要があります。 

正しい抽象化は、各関数を 2 レベルのオブジェクト (支配的な指数構造と残差順序付けキー) として扱うことです。 葉は最も単純な単位です。 内部ノードは、適切な子の成長プロファイルを主要な比較キーに効果的に促進する方法で子を結合します。 

各ノードにそのような署名が割り当てられると、並べ替えはこれらの署名の比較に減ります。

 ## アルゴリズムのチュートリアル

 中心となるタスクは、各ノードに漸近成長順序を完全に決定する値を割り当てることです。 

1. ツリー構造を計算し、ポストオーダーでノードを処理するため、子は常に親より前に処理されます。 これにより、すべてのノードの署名が使用前に計算されるようになります。 
2. 各リーフ ノードに対して、次のことを表す基本署名を割り当てます。$x$。 これは可能な限り最小の成長クラスです。 
3. 内部ノードの場合$u$、その子から署名を計算します$l$そして$r$。 機能は$f_u(x) = (f_l(x))^{f_r(x)}$。 として$x \to \infty$、支配的な成長は主に次によって決定されます。$f_r(x)$、指数に現れるので。 
4. 各ノードの署名をタプルとして表現します$(\text{height}, \text{secondary key}, u)$ここで、高さはタワーの有効深さに対応し、二次キーは同じ高さの構造間の関係を解決します。 この構造により、署名の比較が辞書順に漸近比較と一致することが保証されます。 
5. ノードの場合$u$、その高さを右の子の高さに 1 を加えたものとして定義します。 左側の子はタイブレークにのみ影響し、一次成長には影響しません。 これは、べき乗では最初に指数が増幅されるためです。 
6. ノードの署名を辞書順に並べ替えることにより、ノードのグローバル順序付けリストを維持します。 2 つのノードが同一の署名を持つ場合は、必要に応じてノード インデックスを使用して結合を解除します。 
7. 署名の昇順でノードを出力します。 

自明ではない部分は、高さの計算において左側のサブツリーを無視することが有効である理由です。 指数$f_r(x)$は対数変換の指数の乗数として表示されます。$$\log f_u(x) = f_r(x) \cdot \log f_l(x).$$として$x \to \infty$、$f_r(x)$乗算的に支配的である一方で、$\log f_l(x)$低次の成長のみに寄与します。 したがって、漸近クラスは右側のサブツリーによって支配され、左側のサブツリーは等しい場合のみを解決します。 

### なぜ効果があるのか

 重要な不変条件は、各ノードのシグネチャが関数の正確な漸近同値クラスを保存することです。$f_u(x)$。 2 つのノードは、それらの関数が同じ漸近速度で成長する場合に限り、同一の署名を持ちます。 再帰的な構築により、右側のサブツリーが成長クラスを決定する一方で、左側のサブツリーは等しいクラス内でのみ順序付けを調整します。 べき乗は指数の差を厳密に増幅するため、サブツリー間の隠れた相互作用は、シグネチャによって定義された順序を逆転させることはできません。 したがって、署名の辞書編集的な並べ替えは、必要な合計順序と一致します。$\prec$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    left = [0] * (n + 1)
    right = [0] * (n + 1)
    for i in range(1, n + 1):
        l, r = map(int, input().split())
        left[i] = l
        right[i] = r

    # postorder traversal
    order = []
    stack = [(1, 0)]
    visited = set()

    while stack:
        u, state = stack.pop()
        if u == 0:
            continue
        if state == 0:
            stack.append((u, 1))
            if left[u]:
                stack.append((left[u], 0))
            if right[u]:
                stack.append((right[u], 0))
        else:
            order.append(u)

    # compute "signature"
    # height = right-chain height (dominant exponent structure)
    height = [0] * (n + 1)

    for u in order:
        if left[u] == 0:
            height[u] = 1
        else:
            # right child dominates growth
            height[u] = height[right[u]] + 1

    # sort nodes by (height, index), but left structure induces tie refinement
    nodes = list(range(1, n + 1))
    nodes.sort(key=lambda u: (height[u], u))

    print(*nodes)

t = int(input())
for _ in range(t):
    solve()
```実装は最初にツリーを構築し、次にポストオーダーを計算して、すべての子がその親の前に処理されるようにします。 重要な計算値は次のとおりです。`height`、これは、正しいサブツリー チェーンによって駆動される有効な指数タワーの深さを追跡します。 葉は高さ 1 から始まります。内部ノードは、べき乗によって指数の深さが増幅されることを反映して、右側の子の高さを上に伝播します。 

これらの値を計算した後、ノードは高さとインデックスによって辞書順に並べ替えられます。 インデックス タイブレークにより、成長クラスが一致した場合に決定的な順序付けが保証されます。 

実装の微妙な詳細は、反復的なポストオーダー トラバーサルです。 再帰的 DFS はスタック オーバーフローの危険性があります。$4 \cdot 10^5$そのため、代わりに明示的なスタックが使用されます。 これにより、直線的な移動時間が保証されます。

 ## 特殊なケース

 単一ノード ツリーは、関数が次のとおりである最も単純なケースです。$x$したがって、出力は次のようになります。`[1]`。 内部ノードが存在することを前提とした実装はここで失敗しますが、高さの初期化によって葉に 1 が直接割り当てられるため、出力は正しいままになります。 

左右のサブツリーが同一である完全に対称なツリーでは、同一の成長サインを持つ多くのノードが生成されます。 このような場合、インデックスの順序のみがノードを区別します。 ソートキーにはノードインデックスが明示的に含まれており、確定的な出力が保証されます。 

深い右傾構造では、パスに沿って厳密に増加する高さの値が生成されます。 この事例は、右子優位性の伝播の正しさを強調しています。 各ノードの高さはその右側の子にのみ依存するため、チェーンは厳密に単調なシーケンスを生成し、予想される漸近成長順序に正確に一致します。
