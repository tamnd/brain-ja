 ## 解決策
 ## 問題の理解

 道路で結ばれた町のグラフが与えられ、各町には人口値が示されています。 「地域」とは、現在使用可能な道路を使用して形成される接続されたコンポーネントにすぎません。 地域の値は、その接続されたコンポーネント内のすべての町の人口の合計です。 

時間の経過とともに、2 種類の変化が起こります。 一部の道路は永久に破壊され、一部の町では人口が変化します。 変更が行われるたびに、その時点で存在するすべての接続コンポーネントの最大領域値を報告する必要があります。 

このプロセスについて考えるのに役立つのは、道路が消滅するだけであるため、時間の経過とともに接続が弱くなるだけであるということです。 同時に、ノードの重みは独立して変化し、構造には影響を与えずにコンポーネントの値に影響を与えます。 

制約が十分に大きいため、クエリのたびに連結成分を再計算するソリューションは直ちに不可能になります。 接続の 1 回の再構築には O(N + M) のコストがかかり、それを最大 500,000 回実行すると、10^11 のオーダーの作業が必要となり、これは実行可能な制限をはるかに超えています。 クエリごとにコンポーネントを繰り返し走査する増分アプローチは失敗します。これは、コンポーネントが依然として大きい可能性があり、ノードの更新がコンポーネントを通じて伝播するためです。 

オンラインでの削除をサポートする単純な動的接続構造も、変化するノードの重みの下で集約されたコンポーネントの合計を効率的に維持できない場合には不十分です。 

大規模な接続コンポーネント内で多くの人口更新が発生する場合、微妙な特殊なケースが発生します。 構造が変化しなくても、最大領域は純粋に重みの更新によって変化する可能性があります。 単純なソリューションでは、グローバル最大値を効率的に更新することを忘れ、各クエリの後にすべてのコンポーネントの合計を再計算することになり、再びクエリごとに完全な走査が行われる可能性があります。 

もう 1 つの特殊なケースは、最終的にすべての道路が削除される場合です。 その時点で、すべての町は独自の領域となるため、答えは単一ノードの最大値になりますが、これは更新が遅れたことが原因である可能性があります。 接続が安定していることを前提としたソリューションは、ここでは失敗します。 

## アプローチ

 直接シミュレーションでは、現在のグラフが維持され、DFS または BFS を使用して各クエリの後に接続成分が再計算されます。 領域の定義は純粋に接続ベースであるため、これは概念的には正しいです。 ただし、各再計算にはグラフ サイズに比例した時間がかかります。 最大 500,000 のクエリでは、約 500,000 回のグラフ全体の走査が必要になり、これでは遅すぎます。 

重要な構造上の観察は、道路は削除されるだけであり、追加されることはないということです。 これは、時間を逆行すると、道路が追加されるだけであることを意味します。 動的接続は増分的になります。これはまさに、Disjoint Set Union 構造が効率的に処理することです。 

ノード数の変更は接続とは無関係ですが、コンポーネントの集合体には影響します。 DSU コンポーネントごとにそのノード値の合計を維持する場合、ノードの更新は 1 つのコンポーネントに保存されている合計にのみ影響します。 

逆転のトリックは、問題を最終状態から開始するシーケンスに変換します。つまり、すべての削除がすでに適用され、すべての母集団の更新がすでに処理されています。 次に、操作を逆方向に処理します。 この逆転した世界では、道路の削除はエッジの追加になり、人口の更新は値のロールバックになります。 どちらの操作も段階的に維持するのが簡単です。 

接続用の DSU を維持し、すべてのコンポーネントの合計を追跡するグローバル構造を維持して、逆の各ステップの後に最大値を迅速にクエリできるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにコンポーネントを再計算する | O(Q(N + M)) | O(N + M) | 遅すぎる |
 | 増分更新による反転 DSU | O((N + M + Q) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、問題を段階的に処理しやすい状態に変換します。 時間を進めていくのではなく、クエリを最後から最初に処理します。 

1. どの道路が削除されたかを特定します。 削除されなかった道路は、最終状態でも存在したままになります。 これはすべての削除がすでに行われた後のグラフを表すため、これらの残りの道路のみを使用して最初の DSU を構築します。 
2. すべての人口更新を順に適用した後、各町の最終人口を計算します。 これにより、逆プロセスの開始ノードの重みが得られます。 
3. DSU コンポーネントを初期化します。各コンポーネントはノード値の合計を格納します。 これに加えて、いつでもコンポーネントの最大合計を返すことができるグローバル構造を維持します。 
4. 逆の順序でクエリを実行します。 逆の操作ごとに、その逆効果を適用します。 
5. 操作が順方向の道路削除に対応する場合、逆方向にその道路を追加します。 2 つのエンドポイントを結合します。 結合中に、古い 2 つのコンポーネントの合計をグローバル構造から削除し、マージされた合計を挿入することにより、コンポーネントの合計をマージします。 
6. 操作が人口の更新に対応する場合、影響を受けるノードの以前の値が復元されます。 古い値と新しい値の差を計算し、そのノードの現在の DSU ルートを見つけて、この差によってそのコンポーネントの合計を調整します。 それに応じてグローバル構造を更新します。 
7. 各逆演算を適用した後、グローバル構造内の最大要素は、対応する前方プレフィックスの正確な答えとなるため、それを記録します。 

正確さは、すべての逆ステップで、DSU が順方向プレフィックスのグラフ状態を正確に表し、コンポーネントの合計がその時点の正確なノード値を反映しているという事実に依存します。 

不変条件は、DSU コンポーネントが常に反転プレフィックス グラフの接続と一致し、維持されるコンポーネントの合計がそのコンポーネントに現在割り当てられているノード値の合計に等しいということです。 すべての更新では、構造に影響を与えることなく 2 つの正しいコンポーネントをマージするか、単一のコンポーネントの合計を調整するため、プロセス全体にわたって不変条件が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, val):
        self.parent = list(range(n))
        self.size = [1] * n
        self.comp_sum = val[:]  # sum per component root

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b, multiset):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra

        multiset.remove(self.comp_sum[ra])
        multiset.remove(self.comp_sum[rb])

        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.comp_sum[ra] += self.comp_sum[rb]

        multiset.add(self.comp_sum[ra])

class MultiSetMax:
    def __init__(self):
        self.freq = {}
        self.mx = 0

    def add(self, x):
        self.freq[x] = self.freq.get(x, 0) + 1
        if x > self.mx:
            self.mx = x

    def remove(self, x):
        self.freq[x] -= 1
        if self.freq[x] == 0:
            del self.freq[x]
            if x == self.mx:
                self.mx = max(self.freq) if self.freq else 0

    def max(self):
        return self.mx

def solve():
    n, m, q = map(int, input().split())
    init = list(map(int, input().split()))
    edges = []
    for _ in range(m):
        x, y = map(int, input().split())
        edges.append((x - 1, y - 1))

    ops = []
    deleted = [False] * m

    # read queries
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == 'D':
            j = int(tmp[1]) - 1
            ops.append(('D', j))
            deleted[j] = True
        else:
            i = int(tmp[1]) - 1
            z = int(tmp[2])
            ops.append(('P', i, z))

    # final values after forward processing
    cur_val = init[:]
    for op in ops:
        if op[0] == 'P':
            cur_val[op[1]] = op[2]

    # initial DSU after all deletions
    dsu = DSU(n, cur_val)
    ms = MultiSetMax()

    for i in range(n):
        ms.add(cur_val[i])

    for j, (u, v) in enumerate(edges):
        if not deleted[j]:
            dsu.union(u, v, ms)

    res = [0] * q

    # process in reverse
    for idx in range(q - 1, -1, -1):
        op = ops[idx]
        if op[0] == 'D':
            j = op[1]
            u, v = edges[j]
            dsu.union(u, v, ms)
        else:
            i, new_val = op[1], op[2]
            old_val = cur_val[i]
            root = dsu.find(i)

            ms.remove(dsu.comp_sum[root])
            dsu.comp_sum[root] += old_val - new_val
            ms.add(dsu.comp_sum[root])

            cur_val[i] = old_val

        res[idx] = ms.max()

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```DSU は接続を維持し、各ルートはそのコンポーネントの合計を保存します。 マルチセット抽象化はすべてのコンポーネントの合計を追跡するため、平均して一定時間内に最大値をクエリできます。 

主要な実装の詳細は、母集団の更新は 1 つの DSU コンポーネントのみに影響するため、単一の根和の更新以外の構造を再計算する必要がないことです。 

もう 1 つの微妙な点は、すべての削除後に残ったエッジのみを使用して DSU を初期化することです。 これにより、リバースプロセスの開始状態が最終的なフォワード状態とすでに一致していることが保証されます。 

## 実用的な例

 ### 例 1

 最初にすべての道路が存続し、人口更新が 1 つだけ発生する小さなグラフを考えてみましょう。 

| ステップ | 操作（逆） | アクション | 成分の合計 | マックス |
 | --- | --- | --- | --- | --- |
 | 開始 | 最終状態 | すべてのノードが分離または部分的にマージされます。 初期合計 | 現在の最大値 |
 | 1 | 人口更新を元に戻す | 1 根の和を調整する | 更新された合計 | 再計算された最大値 |
 | 2 | エッジの削除を元に戻す | 2 つのコンポーネントを結合する | マージされた合計 | 最大値を更新しました |

 このトレースは、母集団の更新は単一コンポーネントの合計にのみ影響するのに対し、エッジの追加では構造が変化し、合計のマージが必要であることを示しています。 

### 例 2

 2 番目のシナリオは、すべてのエッジが削除された完全接続グラフです。 

| ステップ | 操作（逆） | アクション | #コンポーネント | マックス |
 | --- | --- | --- | --- | --- |
 | 開始 | すべてのノードが分離されました | エッジなし | N | 最大ノード値 |
 | エッジを追加 | 結合ノード | コンポーネントを減らす | N-1 | 最大値を更新しました |
 | 続ける | より多くの組合 | 徐々に大型化するコンポーネント | 減少する | 進化する |

 これにより、接続が完全に切断された状態から逆に完全に接続された状態に移行するという極端なケースをアルゴリズムが正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + M + Q) log N) | 各結合またはマルチセットの更新は最悪の場合でも対数的になります。

 ## 特殊なケース

 重大なエッジケースは、ノードが大きなコンポーネント内に留まりながら値を複数回変更する場合です。 このアルゴリズムは、常に現在のルートを特定し、正確に 1 つのコンポーネントの合計にデルタ更新を適用することでこれを処理します。 ノードが更新間で移動した場合でも、DSU はルートが常に逆の時間でその時点で正しいことを保証します。 

もう 1 つのケースは、母集団が変更される前にすべてのエッジが削除される場合です。 逆のビューでは、最初に空のグラフから接続を再構築するため、人口の更新は最初にシングルトン コンポーネントに適用されます。 各更新は単一ノードのコンポーネントにのみ影響し、その後の結合では累積された合計が正しくマージされます。 

最後のケースは、複数のエッジがすでに統合されているコンポーネントを逆に接続する場合です。 これらの結合は構造を変更せず、マルチセットは変更されず、最大追跡の正確性が維持されるため、DSU によって安全に無視されます。
