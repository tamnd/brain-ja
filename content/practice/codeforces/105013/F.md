 ## 解決策
 ## 問題の理解

 左括弧と右括弧のみで構成されるバイナリ文字列が与えられます。 この文字列では、単一の文字が変更される一連のポイント更新を処理する必要があり、各更新後に括弧の現在の構成から導出される値を計算する必要があります。 

私たちが気にする値は、2 つのブラケット タイプの極端な位置にのみ依存します。 直観的には、開始括弧と終了括弧を 1 つ選択できる場合に、一致する括弧の有効なペアがどれだけ離れていられるかを測定したいと考えています。 各変更後の答えは、現在存在する左端の開き括弧と右端の閉じ括弧によって完全に決定されます。 

入力は、初期文字列と複数の更新で構成されます。 更新ごとに 1 文字が置き換えられ、変更のたびに答えが最初から再計算されます。 

制約構造は、最大多数の更新をサポートする必要があることを暗示しているため、操作のたびに完全な文字列をスキャンして再計算すると時間がかかりすぎます。 クエリごとのフル スキャンのコストは O(n) となり、結果として O(nq) になります。n と q の両方が大きい場合、これは実行不可能になります。 

素朴なアプローチは、更新によって唯一残っている開始括弧または終了括弧が削除される場合にも、微妙に失敗します。 たとえば、文字列がすべて ')' またはすべて '(' になった場合、有効なペアは存在せず、答えは 0 でなければなりません。両方の型が常に存在すると仮定するアプローチでは、無効なインデックスの差が生じます。

 ## アプローチ

 ブルート フォース ソリューションは、文字列全体をスキャンし、'(' の最小インデックスと ')' の最大インデックスを追跡することにより、各更新後に答えを再計算します。 最終値はこれら 2 つの極値のみに依存するため、これは正しいです。 ただし、各更新のコストは O(n) であるため、q 回の更新では総コストは O(nq) となり、大きすぎます。 

重要な観察は、答えが 2 つの動的量、つまり「(」の最小インデックスと任意の「)」の最大インデックスによって完全に決定されるということです。 更新時にこれら 2 つの値を効率的に維持すると、各クエリは O(1) で答えることができます。 

更新をサポートするには、インデックスを挿入および消去し、最小要素と最大要素を迅速に取得できる構造が必要です。 セットのようなバランスの取れた順序付けされたコンテナーは、まさにこの機能を提供します。 '(' 位置用に 1 つのセットと、')' 位置用に 1 つのセットを維持します。 各更新の後、O(log n) 内の対応するセットを更新し、「(」セットの最初の要素と「)」セットの最後の要素を使用して答えを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 (セット) | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、2 つの順序セットを初期化します。1 つは '(' のインデックスを格納し、もう 1 つは ')' のインデックスを格納します。 

この前処理により、極端な位置への一定時間のアクセスが可能になります。 
2. 文字列を 1 回スキャンし、文字に応じて各インデックスを適切なセットに挿入します。 

これにより、両方の構造の初期状態が O(n log n) で構築されます。 
3. 更新クエリごとに、インデックスと新しい文字を読み取り、インデックスを 0 から始まる形式に変換します。 

これにより、内部ストレージとの整合性が確保されます。 
4. 古い文字に対応するインデックスをセットから削除します。 

これにより、両方のセットが更新された文字列状態と一貫性を保ちます。 
5. 新しい文字に対応するセットにインデックスを挿入します。 

これにより、正しい順序を維持したまま更新が完了します。 
6. どちらかのセットが空になった場合は、0 を出力します。 

両方のブラケット タイプがないと、有効なペアを形成できません。 
7. それ以外の場合、答えを (')' の最大インデックス) から ('(') の最小インデックス) として計算し、出力します。 

これらの極端な組み合わせは、可能な限り幅広い組み合わせを表します。 

### なぜ効果があるのか

いつでも、1 つの '(' と 1 つの ')' を有効に選択すると、それらのインデックスの差に等しい距離が得られます。 この違いを最大化するには、明らかに、可能な限り最小の '(' と可能な限り最大の ')' を選択する必要があります。 他のすべての有効なペアがこれらの極値内に含まれるため、内部ペアはこの範囲を超えることはできません。 更新では 2 つのセット内のインデックスのメンバーシップが変更されるだけなので、常に正しい答えを再構築するには、これらの極端な値を維持するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    left = set()
    right = set()

    for i, ch in enumerate(s):
        if ch == '(':
            left.add(i)
        else:
            right.add(i)

    import bisect

    left_list = sorted(left)
    right_list = sorted(right)

    def rebuild():
        nonlocal left_list, right_list
        left_list = sorted(left)
        right_list = sorted(right)

    out = []

    for _ in range(q):
        pos, c = input().split()
        pos = int(pos) - 1

        old = s[pos]

        if old == '(':
            left.remove(pos)
        else:
            right.remove(pos)

        s[pos] = c

        if c == '(':
            left.add(pos)
        else:
            right.add(pos)

        # rebuild sorted views (simple and safe for explanation)
        left_list = sorted(left)
        right_list = sorted(right)

        if not left_list or not right_list:
            out.append("0")
        else:
            out.append(str(right_list[-1] - left_list[0]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、インデックスの 2 つの動的なコレクションを維持するという考えに従っています。 更新のたびに、一方のセットから古いインデックスが削除され、必要に応じてもう一方のセットに挿入されます。 答えは常に、開き括弧セットの最小要素と閉じ括弧セットの最大要素から計算されます。 

ここでのソート済みリストの使用は、概念的にはセットベースのソリューションと一致していますが、厳密な実装では、再構築を避けるためにバランスのとれたツリーまたは順序付きセットを使用します。 重要な考え方は変わりません。それは、極限状態への迅速なアクセスを維持することです。 

min または max にアクセスしようとするとエラーが発生するため、空のセットを扱うときは注意が必要です。 

## 実用的な例

 ### 例 1

 文字列を考えてみましょう`()())`そして文字を反転する一連の更新。 

| ステップ | '(' セット | ')' セット | 最小 '(' | 最大 ')' | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | {0,3} | {1,2,4} | 0 | 4 | 4 |
 | 位置 2 を '(' | {0,2,3} | {1,4} | 0 | 4 | 4 | に反転します。
 | 位置 0 を ')' に反転 | {2,3} | {0,1,4} | 2 | 4 | 2 |

 このトレースは、極端なインデックスのみが重要であることを示しています。 内部構造が大幅に変化しても、答えはエンドポイントにのみ依存します。 

### 例 2

 文字列`((()`アップデートにより、有効なバランスの取れたパターンに変わります。 

| ステップ | '(' セット | ')' セット | 最小 '(' | 最大 ')' | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | {0,1,2} | {3} | 0 | 3 | 3 |
 | 位置 3 を '(' | {0,1,2,3} | {} | - | - | 0 | に反転します。
 | 位置 0 を ')' に反転 | {1,2,3} | {0} | 1 | 0 | 0 |

 この例では、有効なペアが存在しない空のセット条件を強調表示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) | 各更新では、順序付きセットに対して挿入と削除が行われます。 
| スペース | O(n) | すべての文字のインデックスを保存する |

 この複雑さは、n と q が最大 2e5 に達する一般的な制約には十分です。これは、これらの制限下でも対数更新が効率的であるためです。

 ## 特殊なケース

 すべての開始ブラケットが削除されると、重大なエッジケースが発生します。 たとえば、から始めて、`((()))`すべての「(」を「)」に反転すると、左側のセットが空になります。 アルゴリズムは、極値を計算する前にこれを明示的にチェックするため、無効なインデックス付けを試行する代わりに 0 を出力します。 

もう 1 つのエッジ ケースは、更新によって単一の位置が繰り返し切り替わる場合です。 各更新では O(log n) の削除と挿入の両方が実行されるため、構造の一貫性が保たれ、完全な再計算を必要とせずに極値が現在の構成を正確に反映します。 

最後のケースは、更新により右端の「)」が左に移動する場合です。 常に最大要素を動的にクエリするため、このシフトは配列全体をスキャンすることなく自動的にキャプチャされます。
