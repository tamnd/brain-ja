 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられます。 テスト ケースごとに、次の長さの文字列を受け取ります。$n$。 タスクは、非常に特殊な方法で文字列を変換し、処理後に 3 つの固定出力のどれに一致するかを決定することです。 

処理ルールはシンプルですが厳密です。 まず、大文字と小文字が同じように扱われるように、すべての文字が小文字に変換されます。 次に、連続する同一文字が圧縮されて、次のように実行されます。`"aaaa"`シングルになる`"a"`、`"bbbbb"`になる`"b"`、 等々。 この正規化の後、結果の文字列が 2 つの特別なパターンと比較されます。 等しい場合`"meow"`、出力は`"0_0"`。 等しい場合`"waov"`、出力は`"*_*"`。 その他の結果は次のようになります。`"???"`。 

ステートメントでは制約が明示的に制限されていませんが、テスト ケースごとに直接文字列処理が存在することは、次のことを強く示唆しています。$n$テスト ケースごとの線形よりも悪いものは危険となるほど十分に大きい可能性があります。 これにより、非効率的に文字列を繰り返し再構築したり、二次的な動作に低下する可能性のあるネストされたスキャンを使用したりするアプローチが即座に除外されます。 

微妙なエッジケースは圧縮ステップから発生します。 単純な解釈では、連続した実行を折りたたむだけでなく、重複する文字をグローバルに削除する可能性があります。 例えば、`"mmeeooww"`になるはずです`"meow"`ですが、グローバル重複排除により誤って次のように削減されます。`"meow"`秩序が注意深く保たれている場合に限ります。 別のエッジケースは次のような混合ケーシングです`"MeOoW"`ただし、圧縮前に正しく正規化する必要があります。 

## アプローチ

 この強引なアイデアは文字通り説明に従います。 各文字列について、最初にすべての文字を小文字に変換します。 次に、隣接する等しい文字がなくなるまで、文字列を繰り返しスキャンして重複を削除します。 単純な実装では、パスごとに文字列を再構築するか、隣接する文字を繰り返しチェックして重複を 1 つずつ消去します。 

これは、連続圧縮の定義を直接強制するため、正しく機能します。 ただし、ストリングが長い場合にはその弱点が現れます。 消去操作ごとに残りのサフィックスがシフトされる可能性があり、これを繰り返し実行すると、テスト ケースごとに最悪の二次関数の動作が発生します。 複数のテスト ケースがある場合、これはすぐに遅くなりすぎます。$n$大きいです。 

重要な点は、パスを繰り返す必要がないということです。 圧縮は、各文字が最終的に処理される文字列の前の文字と等しいかどうかのみに依存します。 これは、最後に追加された文字と異なる場合にのみ文字を追加することで、1 回のパスで結果を構築できることを意味します。 シングルパスの小文字変換と組み合わせると、変換全体が線形になります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 文字列を読み取り、すべての文字を小文字に変換します。 これにより、ターゲット パターンは小文字でのみ定義されるため、大文字と小文字が比較に影響を与えなくなります。 
2. 圧縮形式を格納する空の結果文字列を初期化します。 
3. 正規化された文字列の各文字を繰り返し処理します。 
4. すでに結果にある最後の文字と異なる場合にのみ、その文字を結果に追加します。 同じ場合は、連続する同じブロックに属するためスキップします。 
5. スキャン後、結果の圧縮文字列を次と比較します。`"meow"`そして`"waov"`。 
6. 出力`"0_0"`それが一致すれば`"meow"`、`"*_*"`それが一致すれば`"waov"`、それ以外の場合は出力`"???"`。 

### なぜ効果があるのか

 圧縮ステップは、同一文字の最大の連続ブロックをすべて 1 つの代表文字に置き換えることと同じです。 ワンパス構造では、同じ文字の直後に続く繰り返しのみが抑制されるため、ブロックごとに 1 文字だけが保持されることが保証されます。 すべてのブロック境界は、文字が変更されるときに 1 回だけ検出されるため、結果として得られる文字列は、完全な文字列の重複排除を繰り返した結果、最終的に生成されるものと同じになりますが、作業を繰り返す必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    # lowercase conversion
    s = s.lower()

    # run-length compression
    t = []
    for c in s:
        if not t or t[-1] != c:
            t.append(c)

    t = ''.join(t)

    if t == "meow":
        print("0_0")
    elif t == "waov":
        print("*_*")
    else:
        print("???")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策では、まず次を使用して入力文字列を正規化します。`.lower()`、均一な文字比較を保証します。 圧縮はリストを使用して行われます`t`文字列の連結が繰り返されるのを避けるためです。そうしないと、Python で二次的な動作が発生します。 各文字は最後に保持された文字とのみ比較され、線形時間処理が保証されます。 最後に、2 つのターゲット パターンと比較します。 

よくある落とし穴は、`t += c`文字列を繰り返し使用すると、パフォーマンスが低下します。 もう 1 つは、圧縮では順序を保持しながら、すべての重複をグローバルに削除するのではなく、連続する重複のみを削除する必要があることを忘れていることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列全体が単一の繰り返し文字で構成されている場合です。`"AAAAA"`。 小文字に変換して圧縮すると、次のようになります。`"a"`。 アルゴリズムは、最初の文字を追加し、最後に追加された文字と一致するため他の文字をすべてスキップすることによって処理します。 最後の文字列は`"a"`、どちらにも一致しません`"meow"`または`"waov"`したがって、出力は次のようになります`"???"`。 

もう 1 つのエッジ ケースは、次のようなランとケーシングを交互に使用することです。`"MeEeOoWw"`。 小文字の変換により、`"meeooww"`、圧縮収量`"meow"`。 比較は常に正規化後に行われ、実行境界は元の大文字と小文字ではなく隣接する文字の同等性によって純粋に決定されるため、アルゴリズムはこれを正しく処理します。
