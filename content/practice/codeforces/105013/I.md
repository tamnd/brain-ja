 ## 解決策
 ## 問題の理解

 それらのインデックスの要素が固定バリアであるという意味で、いくつかの位置が「ロック」されている配列が与えられています。 これらのロックされたインデックスは、配列を連続した領域に分割します。 各領域内では要素を自由に再配置できますが、異なる領域にわたる要素はロックされた境界を越えることはできません。 

タスクは、コストを最小限に抑えながら、これらの移動制約の下でアレイを「有効な最終構成」に変換することです。 解に一致するコスト解釈は、再順序付け後に各セグメントが非減少構造と互換性を持つようにするために削除する必要がある要素の合計です。 

したがって、問題は 2 つの層に分かれます。 まず、グローバル順序制約が満たされるようにセグメントを配置することが可能かどうかを判断します。 次に、可能であれば、最小コストを計算します。これにより、各独立したセグメント内に保持するものを最大化することができます。 

入力サイズは最大 n に達するため、すべてのペアを比較したり、すべての並べ替えを試行したりする解決策は直ちに不可能になります。 2 次または 3 次戦略は、10^5 要素でも 10^10 の演算が行われるため、タイムアウトになります。 これにより、ソリューションはほぼ線形または n log n スタイルの構造になり、通常は並べ替え、貪欲チェック、またはフェンウィック ツリーとセグメント ツリーが含まれます。 

グローバルな実現可能性チェックをスキップすると、微妙な失敗例がいくつか発生します。 右側のセグメントに非常に小さな値が含まれ、左側のセグメントに大きな値が含まれている 2 つの隣接する強制セグメントを考えてみましょう。 たとえば、左側のセグメントの値が [10, 9] で、右側のセグメントの値が [1, 2] である場合、内部再配置後でも右側のセグメントの最大値が左側のセグメントの最小値より小さいため、境界を越える有効な非減少配列は存在しません。 この制約を無視するソリューションは、有効な取り決めが存在すると誤って主張し、コストの計算を続行することになります。 

セグメント間の順序の一貫性を検証せずに、セグメントが独立していると仮定すると、別の失敗ケースが発生します。 正しいロジックでは、固定制約を考慮した後、後のセグメントの最小値が前のセグメントの最大値よりも小さくならないことが必要です。 

## アプローチ

 強引なアイデアは、各セグメントを個別に扱い、考えられるすべての並べ替えを試し、結果として生じるコストを計算し、最適な構成を選択することです。 単一のセグメントであっても、最適な構造を見つけるためにすべての順列をチェックする必要があるため、これはすでに階乗動作を暗示しています。 複数のセグメントがある場合、これは指数関数的に悪化します。 

各セグメント内で実際に任意の順列を選択しているわけではないことを観察することで、アイデアを洗練させることができます。 最終的な配置を検討するときに違反が発生しないように、できる限り「順序付けられた」サブシーケンスを保持しようとしています。 これにより、問題は順列から部分列に移ります。 

重要な点は、各セグメント内で、非減少構造を維持しながらできるだけ多くの要素を保持する最良の方法は、非減少サブシーケンスの最大合計を見つけることであるということです。 すべての要素にはその値に等しい重みがあるため、長さを最大化する代わりに、保持される合計の合計を最大化します。 

これは古典的な動的計画法の問題です。要素ごとに、それ以下の値で終わる有効なシーケンスの最適な合計を知りたいと考えます。 単純な DP ではすべてのペアを比較することになり、セグメントあたり O(n²) になります。 それは遅すぎます。 

これを最適化するために、値を圧縮し、プレフィックス最大値を効率的にクエリおよび更新できるデータ構造を維持します。 フェンウィック ツリーまたはセグメント ツリーを使用すると、O(log n) で遷移を計算でき、セグメントあたりの DP を O(n log n) に減らすことができます。

DP を適用する前に、範囲の最小値と最大値のチェックを使用して、セグメント境界がグローバルに一貫していることも検証する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |
 | Fenwick / SegTree によるセグメント DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、交差できない位置を抽出し、それらを使用して配列を連続するセグメントに分割します。 各セグメントは独立したブロックとして扱われますが、隣接するブロック間の互換性を確保する必要があります。 

1. ロックされた位置からセグメントを構築します。 各セグメントは配列の連続部分を表し、内部で再配置することはできますが、他のセグメントと混合することはできません。 
2. 隣接するセグメントのペアごとに、左側のセグメントの最大値と右側のセグメントの最小値を計算します。 右セグメントの最小値が左セグメントの最大値より小さい場合、有効なグローバル順序付けが存在しないため、すぐに停止します。 このチェックにより、再配置後にセグメント境界を越えた強制的な反転が発生しないことが保証されます。 
3. 実現可能性が確認されたら、各セグメントを個別に処理して、最適な非減少構造に「保持」できる要素の数を計算します。 
4. セグメント内で、値が減少しないように合計が最大になるサブシーケンスを選択するという問題を再解釈します。 
5. セグメントの値を並べ替えて圧縮し、比較をインデックスベースの順序付けに置き換えることができるようにします。 
6. フェンウィック ツリーまたはセグメント ツリーを使用し、各位置にその圧縮値で終わる達成可能な最良の合計を格納します。 
7. セグメントの要素を繰り返し処理します。 各要素について、現在の値以下のすべての値について達成可能な最良の合計をクエリし、現在の値を追加してそれを拡張します。 この新しい最適値で構造を更新します。 
8. DP の最良の値は、有効に保持されたサブシーケンスの最大合計を表します。 これをセグメントの合計から差し引くと、最小の除去コストが求められます。 
9. すべてのセグメントの結果を合計します。 

正確さは、最適解が固定境界制約によりセグメントの混合から恩恵を受けることはなく、セグメント内で最適に維持される構造はまさに重み付けされた非減少サブシーケンスであるという事実に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

    def clear(self, i):
        while i <= self.n:
            self.bit[i] = 0
            i += i & -i

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    ban = list(map(int, input().split()))
    ban = sorted(set(ban))

    segs = []
    prev = 1

    for x in ban:
        if prev <= x - 1:
            segs.append((prev, x - 1))
        segs.append((x, x))
        prev = x + 1

    if prev <= n:
        segs.append((prev, n))

    if not ban:
        segs = [(1, n)]

    for i in range(len(segs) - 1):
        l1, r1 = segs[i]
        l2, r2 = segs[i + 1]
        mx = max(a[l1:r1 + 1])
        mn = min(a[l2:r2 + 1])
        if mn < mx:
            print(-1)
            return

    ans = 0

    for l, r in segs:
        if l == r:
            continue

        arr = a[l:r + 1]
        total = sum(arr)

        vals = sorted(set(arr))
        mp = {v: i + 1 for i, v in enumerate(vals)}

        bit = BIT(len(vals))

        best = 0
        for v in arr:
            idx = mp[v]
            cur = bit.query(idx) + v
            if cur > best:
                best = cur
            bit.update(idx, cur)

        ans += total - best

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```実装は、禁止された位置を使用してセグメントを構築することから始まり、境界が正しく尊重されるようにします。 実現可能性チェックでは、配列に対する直接範囲クエリを使用して隣接するセグメントを比較します。これは、セグメントが互いに素で固定されているため安全です。 

各セグメント内では値が大きくなる可能性があるため、座標圧縮が必要です。 フェンウィック ツリーは、各圧縮値で終わる有効な非減少サブシーケンスの達成可能な最良の合計を維持します。 クエリ操作は常に、現在の要素に遷移できる最適なサブシーケンスを取得し、更新によってこの新しい状態が前方に伝播されます。 

微妙な点は、カウントではなく最大合計を追跡するため、すべての DP 状態は長さではなく累積された重みを保存することです。 

## 実用的な例

 ### 例 1

 配列が 2 つのセグメントに分割されているとします。```
a = [3, 1, 2, 5]
segments: [3,1] and [2,5]
```まず実現可能性を確認します。 最初のセグメントの最大値は 3、2 番目のセグメントの最小値は 2 であるため、2 < 3 であるため、配置は不可能で、出力は次のようになります。```
-1
```これは、DP の前に境界検証が必要な理由を示しています。 

### 例 2```
a = [1, 5, 2, 3]
no bans
```単一セグメント処理:

 | ステップ | 要素 | ここで終わる最良の部分列の合計 | 世界最高 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 5 | 6 | 6 |
 | 3 | 2 | 3 | 6 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各要素は、Fenwick ツリーのクエリと更新によって 1 回処理されます。 
| スペース | O(n) | 圧縮マップと BIT ストレージ |

 log n 操作は一般的な制約下でも効率的であるため、この複雑さはテスト ケースごとに最大 10^5 の n の制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def update(self, i, v):
            while i <= self.n:
                self.bit[i] = max(self.bit[i], v)
                i += i & -i

        def query(self, i):
            res = 0
            while i > 0:
                res = max(res, self.bit[i])
                i -= i & -i
            return res

    def solve():
        n, k = map(int, input().split())
        a = [0] + list(map(int, input().split()))
        ban = list(map(int, input().split()))
        ban = sorted(set(ban))

        segs = []
        prev = 1
        for x in ban:
            if prev <= x - 1:
                segs.append((prev, x - 1))
            segs.append((x, x))
            prev = x + 1
        if prev <= n:
            segs.append((prev, n))
        if not ban:
            segs = [(1, n)]

        for i in range(len(segs) - 1):
            l1, r1 = segs[i]
            l2, r2 = segs[i + 1]
            if min(a[l2:r2 + 1]) < max(a[l1:r1 + 1]):
                return "-1\n"

        ans = 0
        for l, r in segs:
            if l == r:
                continue
            arr = a[l:r + 1]
            total = sum(arr)
            vals = sorted(set(arr))
            mp = {v:i+1 for i,v in enumerate(vals)}
            bit = BIT(len(vals))
            best = 0
            for v in arr:
                idx = mp[v]
                cur = bit.query(idx) + v
                bit.update(idx, cur)
                best = max(best, cur)
            ans += total - best

        return str(ans) + "\n"

    return solve()

 ## 特殊なケース

 主なエッジ ケースは、各セグメントを個別に並べ替えることができるにもかかわらず、2 つの隣接するセグメントが順序に違反する場合です。 たとえば、左セグメント [10, 1] と右セグメント [2, 3] は内部ソートには合格しますが、2 < 10 であるため境界チェックに失敗します。実現可能性ステップは DP の前にこれをキャッチします。 

もう 1 つのエッジ ケースは、サイズ 1 のセグメントです。このようなセグメントは DP に何も寄与しないため、空の構造へのアクセスを避けるために慎重にスキップする必要があります。
