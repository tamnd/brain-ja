 ## 解決策
 ## 問題の理解

 正の整数でインデックス付けされた無限のバイナリ文字列を維持しています。 最初は、すべての位置がゼロを含んでいるかのように動作し、その後、この無限の文字列のセグメントを繰り返し上書きできるようになります。 各更新では、指定された間隔内のすべての文字が 0 または 1 に設定されます。 このような更新を何度も行った後、次の形式のクエリが要求されます。現在の無限文字列内の k 番目のゼロの位置を見つけます。 

主な問題点は、文字列が明示的に保存されず、更新やクエリに含まれるインデックスが非常に大きくなる可能性があることです。 座標範囲と演算数の両方が明示的に実現するには大きすぎるため、配列に対する直接シミュレーションは不可能です。 操作ごとに各位置を個別に扱うアプローチは、すぐに二次関数またはさらに悪い動作に退化します。 

この制約により、操作ごとに対数構造が暗黙的に強制されます。 各更新は広い範囲に効率的に影響を与える必要があり、各クエリはドメイン全体をスキャンせずにグローバル統計 (k 番目のゼロ) を取得する必要があります。 これは、圧縮された座標空間上のセグメント ツリーまたは動的に割り当てられた暗黙的なツリーが実行可能になる古典的な設定です。 

微妙なエッジケースは、割り当ての重複によって発生します。 適切なセグメント構造を維持せずに間隔を保存したり更新を適用したりする単純な実装では、以前に割り当てられた領域の一部のみを簡単に上書きすることができ、0 と 1 のカウントが不一致になる可能性があります。 別の失敗モードは、プレフィックス数を維持せずに k 番目のゼロ クエリに応答しようとしたときに発生します。 クエリごとにセグメントをスキャンしてゼロを再計算すると、最悪の場合の繰り返しクエリが発生します。 

中核的な要件は、実質的に無限のバイナリ配列に対する範囲の割り当てと k 次の統計クエリをサポートすることです。 

## アプローチ

 ブルートフォース手法では、影響を受けるすべての位置のマップまたは配列が明示的に維持されます。 各更新は指定された間隔で反復され、値が設定され、各クエリは最初から k 個のゼロを数えるまでスキャンします。 操作は文字列定義に基づいて直接シミュレートされるため、これは原理的には正しいです。 ただし、1 つの更新が長い間隔をカバーし、クエリで潜在的に巨大なプレフィックスをスキャンする必要がある場合、複雑さは操作ごとに線形に低下し、敵対的なケースではおよそ O(n²) の動作が発生します。 

この改善は、個人の立場は決して必要ではないということを認識することから生まれます。 必要なのはセグメントにわたる集約された情報だけです。 各セグメントは、長さとセグメントに含まれるセグメントの数という 2 つの重要な情報を提供します。 これから、プレフィックス内のゼロの数は、長さから 1 を引いたものとして計算できます。 これは、範囲割り当てをサポートする遅延伝播を備えたセグメント ツリーを即座に示唆します。 

プレフィックス ゼロのカウントが効率的に計算できるようになると、k 番目のゼロ クエリが検索問題になります。つまり、位置をバイナリ検索して、プレフィックス内にゼロがいくつあるかを確認できます。 チェック自体はセグメント ツリーを介して対数的であるため、完全なクエリは実装に応じて対数 2 乗以上になります。

 残りの障害は、最大 2e18 に達する可能性がある座標範囲です。 これは、すべてのエンドポイントでの座標圧縮、または必要な場合にのみノードを作成する動的に割り当てられたセグメント ツリーの構築によって処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n・R) | O(R) | 遅すぎる |
 | セグメントツリー + 二分探索 | O(n log² R) | O(R log R) または O(n log R) | 承認済み |

 ここで、R は座標範囲を示します。 

## アルゴリズムのチュートリアル

 提供された実装アイデアと一致する圧縮座標セグメント ツリー ソリューションについて説明します。 

### 1. 関連する境界をすべて収集する

更新操作からすべての間隔エンドポイントを抽出し、包含性が正しく処理されるようにそれらをわずかに拡張します。 これらのポイントは、文字列の値が変更できる唯一の場所を定義します。 連続する 2 つのポイント間のすべては均一なので、これらの圧縮セグメントを維持するだけで済みます。 

このステップにより、無限のドメインが有限数の意味のあるセグメントに縮小されます。 

### 2. 圧縮されたセグメント上にセグメント ツリーを構築する

 セグメント ツリーの各ノードは、圧縮座標系の連続ブロックを表します。 ノードには、セグメントの全長とセグメント内に現在割り当てられている 1 の数という 2 つの値が格納されます。 これらから、ゼロの数が暗黙的に決定されます。 

遅延伝播を使用すると、セグメント全体を 0 または 1 に割り当てることが、すぐに降下することなくノードごとに O(1) で実行できます。 

### 3. 範囲の割り当てを適用する

 範囲を 0 または 1 に設定する操作ごとに、標準の遅延伝播割り当てを使用してセグメント ツリーを更新します。 ノードが完全にカバーされている場合は、その状態を直接上書きします。 それ以外の場合は、割り当てをプッシュダウンして再帰します。 

ここで重要な特性は、代入がべき等であるということです。 セグメントが完全に 0 または 1 に設定されると、部分的に上書きされるまで、より深い構造は問題になりません。 

### 4. プレフィックス ゼロのカウントを計算する

 どのプレフィックスでも、ゼロの数は、プレフィックスの長さからセグメント ツリーに格納されている 1 の数を引いたものに等しくなります。 これにより、プレフィックス統計を対数時間で計算できるようになります。 

### 5. k 番目のゼロの二分探索

 k 番目のゼロを見つけるには、座標領域で二分探索を行います。 候補位置 Mid については、プレフィックス [1, Mid] にゼロがいくつ存在するかをクエリします。 その数が少なくとも k であれば、答えは左側にあり、それ以外の場合は右側にあります。 

これにより、順序統計の問題がプレフィックス クエリの繰り返しに軽減されます。 

### なぜ効果があるのか

 セグメント ツリーは、バイナリ文字列の正確な集約表現を常に維持します。 すべての更新では、各ノードがその間隔内の 1 の数を正確に反映するという不変条件が保持されます。 ゼロは長さから 1 を引いた値から直接導出されるため、接頭辞のゼロのカウントは常に正確です。 二分探索が有効なのは、プレフィックスのゼロカウントが位置インデックス内で単調であるため、k 番目のゼロ位置が一意に決定されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.ones = [0] * (4 * n)
        self.lazy = [-1] * (4 * n)

    def apply(self, idx, l, r, val):
        self.lazy[idx] = val
        if val == 1:
            self.ones[idx] = (r - l + 1)
        else:
            self.ones[idx] = 0

    def push(self, idx, l, r):
        if self.lazy[idx] == -1:
            return
        mid = (l + r) // 2
        val = self.lazy[idx]
        self.apply(idx * 2, l, mid, val)
        self.apply(idx * 2 + 1, mid + 1, r, val)
        self.lazy[idx] = -1

    def update(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(idx, l, r, val)
            return
        self.push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, val)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, val)
        self.ones[idx] = self.ones[idx * 2] + self.ones[idx * 2 + 1]

    def query_ones(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.ones[idx]
        self.push(idx, l, r)
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += self.query_ones(idx * 2, l, mid, ql, qr)
        if qr > mid:
            res += self.query_ones(idx * 2 + 1, mid + 1, r, ql, qr)
        return res

def solve():
    q = int(input())
    ops = []
    coords = {1, 10**18}

    for _ in range(q):
        parts = input().split()
        if parts[0] in ['+', '-']:
            op, l, r = parts[0], int(parts[1]), int(parts[2])
            ops.append((op, l, r))
            coords.add(l)
            coords.add(r + 1)
        else:
            ops.append((parts[0], int(parts[1])))

    coords = sorted(coords)
    mp = {v: i + 1 for i, v in enumerate(coords)}
    n = len(coords)

    st = SegTree(n)

    def prefix_zeros(x):
        ones = st.query_ones(1, 1, n, 1, x)
        length = coords[x - 1] - coords[0]
        return length - ones

    for op in ops:
        if op[0] == '+':
            l, r = mp[op[1]], mp[op[2] + 1] - 1
            st.update(1, 1, n, l, r, 1)
        elif op[0] == '-':
            l, r = mp[op[1]], mp[op[2] + 1] - 1
            st.update(1, 1, n, l, r, 0)
        else:
            k = op[1]
            lo, hi = 1, n
            ans = n
            while lo <= hi:
                mid = (lo + hi) // 2
                ones = st.query_ones(1, 1, n, 1, mid)
                length = coords[mid - 1] - coords[0]
                zeros = length - ones
                if zeros >= k:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1
            right = coords[ans] - 1
            ones = st.query_ones(1, 1, n, 1, ans)
            length = coords[ans - 1] - coords[0]
            zeros_before = length - ones
            offset = k - zeros_before - 1
            print(coords[ans - 1] + offset)

if __name__ == "__main__":
    solve()
```セグメント ツリーには 0 が導出されるため、1 のカウントのみが保存されます。 座標圧縮により、すべての更新境界がセグメント境界と一致することが保証され、部分的な重複エラーが防止されます。 二分探索は、圧縮ドメイン内で単調であるプレフィックス ゼロのカウントに依存します。 

## 実用的な例

 すべてゼロから開始し、位置 2 ～ 5 を 1 に設定してから、3 番目のゼロをクエリする小さなシナリオを考えてみましょう。 更新により、中央に 1 のブロックが作成され、0 が 2 つの領域に分割されます。 

更新後のセグメント ツリーは [2,5] に集中しているものを反映しており、プレフィックス ゼロのカウントは位置 1 までゆっくりと増加し、その後 1 ブロック全体で平坦になり、位置 5 の後に再び増加します。 

k = 3 の二分探索は、1 つのブロックを通過して 2 番目のゼロ領域に到達するまで右に移動し、位置 6 を返します。 

2 番目のシナリオは、範囲が最初に 1 に設定され、次に部分的にゼロにリセットされる交互更新です。 遅延伝播により、2 番目の更新がその間隔内の前の状態を完全にオーバーライドし、残差値によるカウントの破損を防ぎます。

 ## 特殊なケース

 主なエッジケースは、間隔が繰り返し上書きされる場合です。 たとえば、[1,10] を 1 に設定し、その後 [5,6] を 0 に戻すには、セグメント ツリーが情報を正しく分割して、内部領域にのみ 0 が再導入されるようにする必要があります。 遅延伝播メカニズムにより、影響を受けるノードのみが 2 番目の割り当てによってオーバーライドされます。 

もう 1 つのエッジ ケースは、k 番目のゼロが明示的に更新されたすべてのセグメントを超えた場合に発生します。 この場合、答えは触れられていない無限の尾部から得られ、暗黙的にゼロとして扱われます。 変更されたセグメントの外側ではプレフィックス ゼロのカウントが増加し続けるため、バイナリ検索は自然にその領域に拡張されます。
