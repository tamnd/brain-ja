 ## 解決策
 ## 問題の理解

 入力は、固定サイズの長さのチャンクで処理されるバイナリ文字列を記述します。`k`。 文字列を連続したブロックに分割し、最初に各ブロックを独立して処理し、後で隣接するブロックと対話することを考えることができます。 

各ブロック内では、ブロック内の文字の反転がより少なくて済む選択に基づいて、そのブロックをすべて 0 として解釈するか、すべて 1 として解釈するかを効果的に決定することになります。 ブロックに既に明らかに過半数の 0 または 1 がある場合、決定はその過半数によって強制されます。 ブロックが完全にバランスが取れている場合、どちらの解釈でも同じ回数の反転が必要となり、ブロックは固定方向を課しません。 

このようにしてすべてのブロックが削減された後、残りの構造は多数決によって決定される一連の「方向」となり、コストを変更せずにどちらの方向にも割り当てることができる曖昧なブロックが散在します。 最終的な答えには 3 つの量が必要です。ブロック内の反転の最小数、隣接する決定されたブロック間の強制遷移の数、および総コストを最小限に抑えるために曖昧さを解決する個別のグローバルな方法の数です。 

この制約は、文字列が大きくなる可能性があることを意味するため、どのソリューションでも各ブロックを線形時間で処理する必要があります。 二次関数または対数関数のブロックごとの戦略は、多くのテスト ケースで繰り返すと遅すぎます。 重要な制限は、連続するブロック間の単純な相互作用パターンを除き、すべての決定がブロックに対してローカルであることです。これは、シングル パス集約アプローチを示唆しています。 

ブロックが完全にバランスがとれている場合、つまりブロックにちょうど半分の 1 と半分の 0 が含まれている場合、微妙なエッジ ケースが発生します。 この場合、どちらの選択も同様に最適です。 このようなブロックを恣意的に修正する単純なアプローチが早すぎると、有効なグローバル構成の数が歪められる可能性があります。 もう 1 つの失敗ケースは、多数決の方向が異なる 2 つの強制ブロックがいくつかのあいまいなブロックで区切られている場合に発生します。 これらのあいまいさを解決する方法の数は、強制された決定の間にどれだけの「ギャップ」が存在するかによって決まり、それらのギャップを無視すると過少カウントにつながります。 

## アプローチ

 ブルートフォース戦略では、各ブロックにすべて 0 またはすべて 1 を割り当てるあらゆる方法を列挙し、その結果として得られる各構成の反転コストを計算し、最適なコストとそれを達成する構成の数を追跡します。 各ブロックには最大 2 つの選択肢があります。`m`これにより生成されるブロック`2^m`各構成を評価するにはすべてのブロックをスキャンする必要があり、非常に小さな入力を超えると完全に実行不可能な指数関数的な爆発につながります。 

重要な観察は、各ブロックが独立して、その構成にのみ依存する最小の反転コストに寄与するということです。 各ブロックがこの最小コストの決定に削減されると、グローバル構造は一連の制約されたラベルになります。一部のブロックはゼロまたは 1 に強制され、一部は柔軟になります。 問題は、これらの強制された決定がシーケンス全体にどのように伝播するかを理解することに帰着します。 

重要な構造の単純化は、連続する強制ブロック間の遷移のみが重要であるということです。 あいまいなブロックはコストを増加させませんが、隣接する強制セグメントによってどのように「吸収」されるかに応じて、有効なグローバル解釈の数を増やします。 これにより、グローバル計数問題が、連続する制約変更間の距離にわたる積に変換されます。 

これが分かると、解決策は線形スキャンになります。ブロックごとのコストと方向を計算し、ニュートラル ブロックを破棄し、残りのシーケンスを処理して遷移と組み合わせ多重度を蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m・n) | O(m) | 遅すぎる |
 | 最適 | O(n) | O(n/k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 文字列を一定のサイズのブロックに分割します`k`次のステップで文字列を反復処理します。`k`、各部分文字列を独立して扱います。 これが必要なのは、フリップはブロックごとに評価され、ブロック間の構造は圧縮後にのみ問題となるためです。 

### 2. 各ブロックの大部分のコストを計算します。 

各ブロックについて、1 の数を数えます。 1 がブロック サイズの半分を超える場合は、0 を 1 に反転し、それ以外の場合は 1 を 0 に反転する方がコストが安くなります。 保存されるコストは、そのブロックに必要な最小のフリップです。 

ブロックのバランスが正確に保たれている場合、両方の割り当てが同様に最適であるため、ブロックは方向を強制しません。 このようなブロックを個別にマークし、構造処理から除外します。 

### 3. 各非ニュートラル ブロックをエンコードする

 各ブロックはペアで表されます`(tag, index)`どこ`tag`最適な状態が 0 に傾いているのか 1 に傾いているのかをエンコードします。`index`ブロック間の位置を記録します。 中立ブロックはコストに影響を与えることなくどちらの側にも適応できるため無視されます。 

### 4. フリップコストの合計

 ブロックごとの最小コストを直接累積します。 これにより、全体的な配置に関係なく、可能な限り最小の数のフリップが生成されます。 

### 5. 強制ブロック間のプロセス遷移

 フィルタリングされたブロック リスト内の連続するエントリをスキャンします。 2 つの隣接するブロックが異なるタグを持つ場合は常に、強制遷移境界が作成されます。 このような遷移をカウントし、遷移ごとにウェイの数にブロック インデックス間の距離を掛けます。 

その理由は、それらの間のすべての中間中立ブロックは、コストを変更せずにどちらかの側に吸収でき、そのギャップ内の各位置が個別の有効な構成を生成するためです。 

### 6. 空のケースまたは完全に中立的なケースを処理する

 強制ブロックが存在しない場合、文字列全体は中立セグメントで構成され、両方のグローバル割り当て (すべて 0 またはすべて 1) が有効な最小ソリューションになります。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのブロックが最適なローカル状態に還元され、それ以上のフリップはローカル ペナルティを増やすことなくコストを改善できるという不変式に依存しています。 削減されると、強制ブロック間の不一致のみがシステムを制約します。 ニュートラル ブロックは、コストに影響を与えず、組み合わせの自由度を拡張する自由変数として機能します。 これらの空きセグメントは強制制約の間にのみ表示されるため、カウントは制約の変更間の距離を測定することになり、構成が二重にカウントされたり省略されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def check(s, k):
    cnt1 = s.count('1')
    if cnt1 * 2 == k:
        return cnt1, -1
    if cnt1 > k // 2:
        return k - cnt1, 1
    return cnt1, 0

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    s = "?" + s

    total_cost = 0
    blocks = []

    for i in range(1, n + 1, k):
        cost, tag = check(s[i:i+k], k)
        total_cost += cost
        if tag != -1:
            blocks.append((tag, i // k))

    transitions = 0
    ways = 1

    if len(blocks) >= 2:
        for i in range(len(blocks) - 1):
            if blocks[i][0] != blocks[i + 1][0]:
                transitions += 1
                ways = (ways * (blocks[i + 1][1] - blocks[i][1])) % MOD

    if not blocks:
        ways = 2

    print(total_cost, transitions + 1, ways % MOD)

t = int(input())
for _ in range(t):
    solve()
```実装では、まず各ブロックを最小限の表現に圧縮します。 の`check`関数はローカルな決定を実行します。コストを計算し、ブロックが方向を強制するか中立を保つかを決定します。 コストはブロック間で独立しているため、メイン ループはコストを即座に集計します。 

リスト`blocks`意味のある制約のみを保存します。 ニュートラル ブロックは柔軟性に寄与するだけであるため、完全に削除されます。 このため、保存されるインデックスは`i // k`これにより、制約の間に完全なブロックがいくつあるかを測定できます。 

遷移のカウントは、この縮小されたシーケンスの 1 回のパスで発生します。 隣接するタグが異なる場合は常に、その距離に比例した寄与が蓄積されます。 これは、最適性に影響を与えることなく中間中立領域を割り当てることができる方法の数を直接エンコードします。 

特別な場合`blocks`is empty は、文字列全体がニュートラル ブロックであることに対応し、2 つの対称的なグローバル ソリューションを提供します。 

## 実用的な例

 ### 例 1

 圧縮後のブロックが次のようになる場合を考えてみましょう。 

| ブロック | タグ | インデックス |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 2 | 1 | 3 |
 | 3 | 1 | 5 |

 ここで次のように計算します。 

| ステップ | アクション | トランジション | 方法 |
 | --- | --- | --- | --- |
 | 開始 | 初期化 | 0 | 1 |
 | 1→2 | タグが異なります | 1 | 1 × (3 − 1) = 2 |
 | 2→3 | 同じタグ | 1 | 2 |

 最終結果は、1 つの強制スイッチと中間構造の 2 つの有効な配置を反映しています。 

これは、異なる隣接する強制ブロックのみがカウントにどのように影響するかを示しています。 

### 例 2

 すべてのブロックが中立の場合:

 | ステップ | アクション | トランジション | 方法 |
 | --- | --- | --- | --- |
 | 開始 | ブロックはありません | 0 | 1 |
 | 最終回 | 特別な場合 | 0 | 2 |

 これは、方向を強制するブロックがない場合、システムは正確に 2 つの対称的なグローバル解釈を許容することを確認します。

 ## 特殊なケース

 すべてのブロックがちょうど半分の 1 と半分の 0 を持つ完全に中立な分解は、`if not blocks`支店。 この状況では、対称性を破る制約がないため、アルゴリズムはゼロに等しいコストと 2 つのグローバル割り当てを正しく出力します。 

2 番目のエッジ ケースは、強制ブロックが 1 つだけ存在する場合に発生します。 この場合、遷移はないため、セグメントの数は 1 として正しく報告され、異なる強制状態の間にギャップがないため、組み合わせ係数は 1 のままになります。 

3 番目のエッジ ケースには、異なるタグを持つ 2 つの強制ブロック間の大きな中立ギャップが含まれます。 の乗算`(next_index - current_index)`これにより、中立領域内の境界のあらゆる配置が正確に 1 回カウントされ、ギャップが多くのブロックにまたがる場合でも正確さが保たれます。
