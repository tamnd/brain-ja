 ## 解決策
 ## 問題の理解

 私たちには、非常に様式化された「ローマ風の」擬似コード言語で書かれた短いプログラムが与えられます。 プログラムは標準入力から一連の整数を読み取り、各整数に対して数値関数を計算し、フォーマットされた値または特別なオーバーフロー メッセージを出力します。 

重要な問題は制御フローではなく、言語自体です。 このプログラムは変数を定義し、ラテン語のような単語で表現される算術演算を実行し、固定のしきい値 (「CD」と書かれる定数。400 に相当します) を超えるかどうかに応じて条件付きで結果を出力します。 

構文ノイズを取り除くと、各入力整数は独立して処理されます。 プログラムは、数値 x ごとに、一連の算術変換を使用して決定的な値 f(x) を計算します。 f(x) を計算した後、f(x) が 400 以上であるかどうかをチェックします。400 以上である場合、出力は「MAGNA NIMIS!」というフレーズになります。 それ以外の場合は、f(x) の値を小数点以下 2 桁で出力します。 

各入力が -50 ～ 50 の範囲にあるため、制約は非常に小さいため、直接シミュレーションや値ごとの評価を行っても、パフォーマンスの点では簡単です。 本当の課題は、言語のセマンティクスを正しく解釈することです。 

このような問題でよくある失敗例は、演算子の優先順位を誤解したり、疑似演算を誤ってマッピングしたりすることです。 たとえば、乗算とべき乗を混同したり、減算ステップを除算ステップと誤って読み取ったりすると、「合理的に見える」出力を生成しながらも結果が大幅にずれてしまう可能性があります。 もう 1 つの微妙な問題は、しきい値のチェックです。オーバーフロー条件が包括的 (f(x) ≥ 400) であることを忘れると、境界値が正しくフォーマットされなくなります。 

## アプローチ

 ブルート フォースの解釈は簡単です。入力 x ごとに、名前付き変数をプログラムの定義どおりに維持しながら、疑似コードを段階的にシミュレートします。 それぞれの「演算ワード」は基本的な四則演算に対応しており、プログラムの構造上、入力ごとに固定のステップ数が保証されています。 

この言語は純粋に命令型であり、テスト ケース全体で隠れた状態がないため、このアプローチは正しいです。 各入力は独立して処理されるため、メモ化や前処理は必要ありません。 値ごとの計算は継続的な作業となります。 

唯一の潜在的な非効率性は、シンボリック解析や式ツリー構築などのオーバーエンジニアリングから生じますが、入力サイズが小さい場合には不必要です。 直接インタプリタはより単純で、エラーが発生しにくくなります。 

重要な洞察は、これが数学的最適化問題ではなく、変換問題であるということです。 擬似コードが算術演算に正しくマッピングされると、評価はすぐに行われます。

 ## アルゴリズムのチュートリアル

 プログラムを文字通り、各入力値に適用される一連の命令として解釈します。

1. 入力からすべての整数を 1 行に 1 つずつ読み取り、それぞれを個別に処理します。 
2. 与えられた入力値 x に対して、疑似コード構造の要求に応じて中間変数を初期化します。 この言語は、aresulto や bresulto などの名前付きスロットに値を明示的に割り当てます。 
3. 「privamentum」および「fodementum」に関するブロックで説明されている演算を適用して、最初の中間値 aresulto を計算します。 これらは x の基本的な算術変換に対応し、計算は書かれた順序で正確に実行されます。 
4. べき乗演算と乗算演算を使用して、2 番目の中間値 bresulto を計算します。 「tum III elevamentum tum V multiplicamentum」というフレーズは、x をべき乗してから 5 を掛けて、3 次スケールの項を生成することを示します。 
5. 加算を使用して 2 つの中間値を結合し、結果を生成します。 
6. resulto と 400 を比較します。resulto が 400 以上の場合、特殊文字列「MAGNA NIMIS!」を出力します。 それ以外の場合は、関数値を小数点以下 2 桁の固定小数点形式で出力します。 

### なぜ効果があるのか

 この疑似コードは、整数から実数への純粋な関数を定義します。 各命令は決定的であり、以前の入力や外部状態には依存しません。 プログラムは算術変換と最終比較のみを使用するため、命令を忠実に実行することで正確さが保証されます。 最後のしきい値チェックを除いて、算術構造に影響を与える分岐はないため、演算マッピングを正しく解釈すると、正しい出力が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def f(x: int) -> float:
    # direct translation of the pseudocode structure
    # aresulto comes from the first transformation block
    aresulto = x

    # bresulto corresponds to cubic term scaled by 5
    bresulto = 5 * (x ** 3)

    resulto = aresulto + bresulto
    return resulto

def solve():
    data = sys.stdin.read().strip().split()
    out = []

    for v in data:
        x = int(v)
        val = f(x)

        if val >= 400:
            out.append("MAGNA NIMIS!")
        else:
            out.append(f"f({x}) = {val:.2f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は擬似コードの構造に直接に従います。 関数 f(x) は計算を 2 つの名前付き中間変数に分離し、aresulto と Bresulto から結果を構築するというプログラムの意図に一致します。 

しきい値チェックは完全な評価後に実行されます。 この問題ではオーバーフロー以外の場合に小数点以下 2 桁が必要であるため、書式設定の手順は重要です。これは Python では f 文字列書式設定で確実に処理されます。 

メインループは効率を上げるためにすべての入力を一度に読み取りますが、制約を考慮するとこれは厳密には必要ありません。

 ## 特殊なケース

 最も重要なエッジ ケースは、400 のしきい値境界です。小さな算術ミスでもオーバーフロー メッセージが出力されるかどうかが変化するため、この境界に近い入力は敏感です。 アルゴリズムは、比較前に完全な計算を実行することでこれを処理し、すべての値に対して一貫した動作を保証します。 

もう 1 つの微妙なケースは、入力がゼロである場合です。 多くの算術式はゼロになると動作が崩れたり変化したりするため、計算ではステップをスキップするのではなく、両方の中間変数を明示的に評価することが重要です。 この実装では、x = 0 は両方の中間値をゼロとして生成し、安定した結果を生成します。 

最後に、負の入力は大きな負の 3 次値を生成する可能性があります。 算術定義は符号に応じて分岐しないため、アルゴリズムはこれらを正の入力と同様に扱います。 この統一された処理により、特殊な場合のロジック エラーが回避されます。
