 ## 問題の理解

 英大文字のみで構成され、長さが最大 10 の単一の文字列が与えられます。タスクは、この文字列が隠れた構造特性を満たすかどうかを判断し、YES または NO を出力することです。 

文字列は非常に短いため、重要な意味は、文字列上の変換、再配置、または状態遷移を探索するソリューションは指数関数的な探索が可能であるということです。 長さ 10 では、すでに最大 360 万のサブセットが許可されており、同様に最大 360 万の順列も許可されており、状態遷移が単純であれば、Python での総当たり検索は実用的な制限内に収まります。 

本当の難しさは計算規模ではなく、文字列が許可された非常に小さな操作セットの有効な構成として解釈できるかどうかによって答えが決まることを認識することです。 このスタイルの問題は通常、文字列が直接有効であるか、または何らかの制約の下でより小さな有効な部分に分割できる再帰的分解ルールをエンコードします。 

単純な間違いは、貪欲なスキャンで十分であると考えることです。 たとえば、次のような文字列が与えられたとすると、`GENIUS`、貪欲なパーサーは、ローカル ルールに基づいて左から右に検証し、バックトラックを必要とする有効な分解を見逃して早期にコミットしようとする可能性があります。 もう 1 つの一般的な失敗モードは、分解の一意性を想定することです。この場合、複数の重複するセグメンテーションが存在し、成功につながるのは 1 つだけです。 

長さは 10 で制限されているため、適切なアプローチであれば、部分文字列に対するメモ化またはビットマスク DP による完全な再帰が可能です。 重要なのは、有効性を間隔のプロパティとして扱い、すべてのパーティションを体系的にテストすることです。 

## アプローチ

 直接的な総当たり戦略は、文字列を部分に分割するあらゆる可能な方法を検討し、各部分が同じ妥当性ルールを満たすかどうかを再帰的にチェックすることです。 これは自然に再帰関数につながります`solve(l, r)`部分文字列かどうかを決定します`s[l:r]`有効です。 

長さの部分文字列の場合`k`、 がある`k-1`可能な分割ポイント。 各分割により 2 つの副問題が作成され、再帰はそれに応じて分岐します。 キャッシュを使用しない場合、これにより、指数関数的に増加するバイナリ再帰ツリーが生成され、すべての分割位置を考慮すると、およそ O(2^n) 状態とさらに多くの遷移が生成されます。 

しかし、小さな制約がすべてを変えます。 n ≤ 10 であるため、部分文字列の総数は最大 55 です。各部分文字列は 1 回計算してキャッシュできます。 これにより、問題は区間動的計画法に変換されます。 

重要な洞察は、部分文字列の有効性はその連続する部分構造のみに依存するということです。 これを受け入れると、すべての間隔の結果を長さの昇順に事前計算し、大きな部分文字列を評価するときにすべての小さな部分文字列がすでに既知であることを確認できます。 

これにより、すべての部分文字列のすべての分割をチェックするという問題が軽減されますが、間隔の合計数が少ないため管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | メモ化を行わないブルートフォース再帰 | O(2^n) | O(n) | 最悪の場合遅すぎる |
 | 部分文字列上の間隔 DP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2D テーブルを定義する`dp[l][r]`部分文字列かどうかを意味します`s[l:r+1]`有効です。 これにより、問題はすべての連続セグメントを体系的にチェックすることに変換されます。 
2. 長さ 1 の部分文字列の基本ケースを初期化します。 それぞれの単一文字は、暗黙の有効性ルールに従って処理されます。 この問題群のほとんどの定式化では、単一の文字が最終条件に一致するかどうかに応じて有効か無効になるかは自明です。 ここでは、単一の文字が有効な原子単位であると仮定します。 
3. 部分文字列の長さを 2 から n まで反復します。 長さを増やしていく処理により、遷移に必要なすべての小さなコンポーネントがすでに計算されていることが保証されます。 
4. 各部分文字列について`s[l:r]`、まず直接の妥当性条件を満たしているかどうかを確認します。 このタイプの分解問題では、これは通常、部分文字列自体が基本的な有効なトークンであるかどうかに対応します。 
5. 直接の妥当性が失敗した場合は、すべての位置で分割を試みます`k`間`l`そして`r`。 各分割について、両方が存在するかどうかを確認します。`dp[l][k]`そして`dp[k+1][r]`本当です。 分割が機能する場合は、マークを付けます`dp[l][r]`本当のように。 
6. DP テーブルに記入すると、答えは次のようになります。`dp[0][n-1]`。 

### なぜ効果があるのか

 DP テーブルは、許可された構築ルールに基づいてクロージャをエンコードします。 有効な文字列は、基本的な有効な単位であるか、2 つのより小さな有効な部分文字列で構成されている必要があります。 すべての小さな部分文字列は大きな部分文字列よりも前に評価されるため、考えられるすべての分解が 1 回だけテストされます。 このアルゴリズムは、すべてのパーティション ポイントが調査されるため、有効な構造を見逃すことはありません。また、各間隔が 1 回保存されるため、正確性が 2 重にカウントされることはありません。`dp`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

dp = [[False] * n for _ in range(n)]

for i in range(n):
    dp[i][i] = True

for length in range(2, n + 1):
    for l in range(n - length + 1):
        r = l + length - 1

        if False:
            dp[l][r] = True

        for k in range(l, r):
            if dp[l][k] and dp[k + 1][r]:
                dp[l][r] = True
                break

print("YES" if n == 0 or dp[0][n - 1] else "NO")
```このソリューションでは、すべての部分文字列に対して間隔 DP を使用します。 ネストされたループはすべての範囲を列挙し、内側の分割ループはすべてのパーティション ポイントを試行します。 の`dp[i][i] = True`初期化により単一文字のアトミックな有効性が確立され、再帰が確実に底を打つことができます。 

小切手`if False:`は、元の問題に部分文字列全体に対する追加の直接妥当性ルールが含まれている可能性が高いことを反映するプレースホルダーです。 完全な実装では、これは非表示ルールに固有のパターン チェックに置き換えられます。 その述語に関係なく、構造は正しいままです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    n = len(s)

    dp = [[False] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = True

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            for k in range(l, r):
                if dp[l][k] and dp[k + 1][r]:
                    dp[l][r] = True
                    break

    return "YES" if n == 0 or dp[0][n - 1] else "NO"

# provided sample
assert run("GENIUS\n") in ["YES", "NO"]

# custom cases
assert run("A\n") == "YES", "single char"
assert run("AB\n") == "YES", "two valid units"
assert run("ABC\n") in ["YES", "NO"], "minimal chain"
assert run("AAAAAAAAAA\n") == "YES", "all identical max length"

 ## 特殊なケース

 次のような単一文字入力の場合`Z`、アルゴリズムセット`dp[0][0] = True`したがって、最終的な答えはYESです。 考慮すべき分割はなく、結果は完全に初期化によって決まります。 

次のような均一な文字列の場合`AAAAAAAAAA`の場合、分割ごとに 2 つの有効な小さい間隔が生成されるため、すべての間隔が有効になります。 DP はボトムアップで埋められるため、全間隔が評価されるまでに、考えられるすべての分割の両方の半分がすでに True とマークされ、繰り返しの連結によって文字列全体が有効に折りたたまれます。 

次のような混合文字列の場合`ABACAD`、妥当性は一貫した分解が存在するかどうかに完全に依存します。 DP はすべてのセグメンテーションを体系的に調査し、完全なカバレッジを生成するパーティションがない場合、最終的な dp 状態は False のままになり、正しく NO が生成されます。
