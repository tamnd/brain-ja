 ## 解決策
 ## 問題の理解

 配列が与えられており、それを非降順に並べ替えたいと考えていますが、スワップは制限されています。 2 つの位置間の交換は、2 つの値の少なくとも 1 つが「幸運な数字」である場合にのみ許可されます。これは、その 10 進表現が数字 4 と 7 のみで構成されることを意味します。私たちのタスクは、実現可能性を判断するだけではなく、最大 2n 操作の上限で有効な交換シーケンスを実際に生成するか、これらのルールでは並べ替えが達成できないことを報告することです。 

重要なオブジェクトは位置そのものではなく、「幸運な」要素がコネクタとしてどのように動作するかです。 スワップは、少なくとも 1 つの幸運の値に触れた​​場合にのみ可能であるため、幸運の要素が交換の仲介に参加しない限り、非幸運の要素は自由に対話することはできません。 

n を 100000 までに制限すると、配列上でのスワップまたは貪欲なバブリングの O(n²) シミュレーションが即座に排除されます。 線形または線形に近いものが必要です。おそらく O(n log n) または O(n) です。 最大 2n スワップの出力制約は、局所的な調整を繰り返すのではなく、インデックスごとに少数の移動で要素を修正する建設的な方法を強く示唆しています。 

幸運な数字がまったくない場合、微妙な問題が発生します。 この場合、配列がすでにソートされていない限り、スワップは有効になりません。 もう 1 つのエッジ ケースは、ラッキー ナンバーが存在するものの、切断された領域を越えて要素を移動するのに役立たない位置に閉じ込められている場合です。たとえば、間違って配置されたすべての要素がラッキーではなく、移動を容易にするラッキー ピボットがない場合です。 

最小限の失敗例は次のとおりです。 

入力:

 n = 3

 arr = [3, 2, 1]

 これらのいずれも幸運でなかった場合、スワップは許可されないため、配列が通常の意味でソート可能であっても、出力は「-1」になる必要があります。 

別のケース:

 n = 3

 arr = [4, 2, 1]

 ここで4は幸運です。 4 がハブとして機能しないと、2 と 1 を直接交換することはできませんが、4 を使用して交換することはできます。 隣接するスワップのみを試みる単純な戦略は、幸運な要素を仲介者として明示的に使用しない限り失敗します。 

## アプローチ

 強引なアイデアは、ソートを直接シミュレートすることです。 配列を繰り返しスキャンし、隣接する反転を見つけて、それらを交換しようとすることができます。 ただし、これを隣接関係を超えて一般化したとしても、各スワップでは有効性をチェックし、多くの中間ステップを試行する必要があります。 最悪の場合、単一の反転を解決するには O(n) 個のスワップが必要になる可能性があり、O(n²) 個の反転が存在するため、考えられるすべてのスワップの単純なシミュレーションでは O(n³) 個の動作が発生します。 これは限界をはるかに超えています。 

重要な観察は、幸運な数字が普遍的な仲介者のように機能するということです。 幸運な位置を選択した場合、それを一時ストレージとして使用して、幸運でない要素間の任意の交換をシミュレートできます。 この考え方は、グラフ再構成のバッファー ノードを使用すると、他の方法では不可能なスワップをシミュレートできるようにする方法と似ています。 

少なくとも 1 つの幸運なインデックスを取得すると、すべての要素をそのインデックスと交換でき、そこから間接的に値を再配置できます。 問題は、標準的な並べ替えプロセスを模倣するシーケンスを構築するものの、固定されたラッキー ピボットを介してすべての交換をルーティングすることに帰着します。 

これにより、問題が制御された順列構造に変換されます。幸運な位置を 1 つハブとして保持し、それを使用して要素を 1 つずつ正しい位置に移動します。 各配置には最大でも一定数のスワップが必要であり、これが 2n の限界を説明します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォーススワッピングシミュレーション | O(n³) 最悪の場合 | O(n) | 遅すぎる |
 | Lucky Index を使用したハブベースの構築 | ソートによる O(n log n) + O(n) スワップ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 幸運な数字を含むすべてのインデックスを特定します。 存在しない場合、配列がすでにソートされている場合にのみソートが可能です。それ以外の場合はスワップが無効になるためです。 これは、厳密な実現可能性チェックとして機能します。 
2. 固定の「ピボット」として幸運なインデックスを 1 つ選択します。 すべてのスワップ操作の一時ストレージとして使用されます。 単一のピボットを修正すると、複数のヘルパーを操作する複雑さが回避されます。 
3. 配列値のコピーを並べ替えて、各値の目標の最終位置を確認します。 これにより、値から正しい位置へのマッピングが得られます。 
4. 配列の位置を左から右に繰り返します。 位置 i で、現在の値がすでに正しい場合は、何もしません。 それ以外の場合は、位置 i に入れる値を決定します。 
5. 配列内のターゲット値の現在位置 j を見つけます。 位置 i に移動するには、ピボットを使用します。 

まず、j の要素をピボットと交換し、次にピボットを位置 i と交換します。 これにより、スワップの正当性を維持しながら、正しい要素が i に効果的に配置されます。 
6. 値が移動するため、交換のたびに位置追跡を更新します。 ピボットは、値が変化しても常に有効な仲介者であり続けます。 
7. 配列が完全にソートされるまで続行します。 スワップの数は、配置ミスされた要素ごとに最大 2 であり、2n の範囲内に収まります。 

### なぜ効果があるのか

 正しさは、幸運な要素を永続的なゲートウェイとして扱うことから生まれます。 任意の 2 つの位置間のスワップは、ピボットを含む一連のスワップに分解できます。これは、ピボットは、現在幸運ではない要素やそれ自体が幸運でない要素とのスワップが常に正当であるためです。 これにより、任意の転置をシミュレートするのに十分な柔軟性が得られます。 ステップごとに常に 1 つの正しい要素を配置し、以前の配置を取り消すことは決してないため、プロセスは正しく固定された位置の増加するプレフィックスを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    while x > 0:
        d = x % 10
        if d != 4 and d != 7:
            return False
        x //= 10
    return True

n = int(input())
a = list(map(int, input().split()))

pos = {}
for i, v in enumerate(a):
    pos[v] = i

sorted_a = sorted(a)

lucky_indices = [i for i, v in enumerate(a) if is_lucky(v)]

if not lucky_indices:
    if a == sorted_a:
        print(0)
    else:
        print(-1)
    sys.exit()

pivot = lucky_indices[0]

ops = []

def do_swap(i, j):
    a[i], a[j] = a[j], a[i]
    pos[a[i]] = i
    pos[a[j]] = j
    ops.append((i + 1, j + 1))

for i in range(n):
    correct = sorted_a[i]
    if a[i] == correct:
        continue

    j = pos[correct]

    if i == pivot:
        do_swap(pivot, j)
        pivot = j
    elif j == pivot:
        do_swap(pivot, i)
        pivot = i
    else:
        do_swap(pivot, j)
        do_swap(pivot, i)

print(len(ops))
for x, y in ops:
    print(x, y)
```コードは、任意の値の現在位置を見つけることが O(1) になるように位置マップを維持します。 ピボットは動的バッファとして使用され、スワップのたびに配列が更新され、マップの一貫性が維持されます。 注意すべき点は、移動時にピボット インデックスを更新することです。そうしないと、後続のスワップで古い位置が参照されてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
3
4 2 1
```ソート対象は[1,2,4]です。 ピボットはインデックス 0 (値 4) です。 

| ステップ | 配列 | ピボット | アクション |
 | --- | --- | --- | --- |
 | 開始 | [4,2,1] | 0 | イニシャル |
 | i=0 | [4,2,1] | 0 | 正しい |
 | i=1 | [4,2,1] | 0 | 位置 1 に 2 が必要 |
 | ピボット-jを交換 | [1,2,4] | 更新されました | ピボットをインデックス 2 と交換してから調整します |

 2 回の交換の後、2 は正しく配置され、ピボットは 1 を所定の位置に配置するのに役立ちます。 トレースは、1 と 2 を直接交換することはできませんが、4 を経由する配線により可能になることを示しています。 

### 例 2

 入力:```
4
77 3 4 2
```ソートされたターゲットは [2,3,4,77]、ピボットはインデックス 0 です。 

| ステップ | 配列 | ピボット | アクション |
 | --- | --- | --- | --- |
 | 開始 | [77,3,4,2] | 0 | イニシャル |
 | i=0 | [77,3,4,2] | 0 | 正しい |
 | i=1 | [77,3,4,2] | 0 | ピボット経由で 2 を前面に持ってくる |
 | i=2 | [2,3,4,77] | 0 | 配置を続ける |

 これは、すでに固定されたプレフィックスを壊すことなく、ピボットがどのように繰り返し一時ストレージとして機能するかを示しています。

 ## 特殊なケース

 幸運な数字がない場合、配列がすでにソートされていない限り、アルゴリズムは直ちに拒否します。 有効なピボットがないとスワップをまったく実行できないため、これが必要になります。 例えば、`[3,1,2]`幸運な値がない場合は、`-1`これは、いかなる操作も合法ではないという事実と一致します。 

並べ替え中にピボット要素自体が移動すると、アルゴリズムは交換のたびにそのインデックスを更新します。 この更新を省略すると、後続のスワップで間違った位置が参照され、静かに構造が破損します。 これは、ピボットが初期位置の固定に関与し、配列内を複数回移動する場合に特に顕著です。
