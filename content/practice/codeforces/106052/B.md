 ## 解決策
 ## 問題の理解

 セルで構成されるグリッドが与えられます。各セルはアクティブまたは空です。 課題は、2 層基板上に配置された小さなレゴのようなレンガを使用してすべてのアクティブ セルをカバーできるかどうかを判断し、可能であればそのような配置を構築することです。 

グリッドの各セルには、上層と下層の 2 つのスタック位置があります。 すべてのアクティブ セルは両方のレイヤーで 1 つのブリック ID でカバーされる必要がありますが、非アクティブ セルは両方のレイヤーで空のままでなければなりません。 

レンガ自体は任意の被覆物ではありません。 各レンガは、単一層のセルを占める接続された形状であり、その形状は、単一のセル、サイズ 1×2 のドミノ、または 3 つのセルの L 字型のいずれかという非常に小さなパターンに制限されます。 レンガは 2 つのレイヤのうちの 1 つにのみ存在でき、レイヤ間で重ねたり分割したりすることはできません。 

これを純粋なタイルの問題から構造的な問題に変える追加のグローバル要件があります。 各ブリックがノードであり、2 つのブリックが反対の層から同じグリッド セルに接している場合に接続されているグラフを見ると、すべてのブリックは 1 つの接続コンポーネントに属している必要があります。 言い換えれば、構造全体が独立した部分にばらばらになってはなりません。 

入力サイズは最大 1,000 × 1,000 グリッドになります。 これにより、レンガの配置を列挙しようとしたり、すべてのタイルを試行したりするソリューションは即座に除外されます。 セル数を指数関数的に増やすことは完全に不可能であり、すべての部分長方形にわたる立方体アプローチでさえ大きすぎます。 唯一の実行可能な解決策は、セル数が線形または線形に近いものであるため、グリッドの構造を直接使用する必要があります。 

アクティブ セルの数が奇数の場合、微妙な障害が発生することがあります。 すべての有効なブリックは 1、2、または 3 セルのいずれかをカバーしますが、すべての配置がレイヤー全体の制約に影響するため、グローバルな実現可能性を損なったまま誤ってローカルにタイルを構築することが簡単に発生します。 たとえば、ヘビの形のようなアクティブ セルの長いチェーンは、多くの場合、貪欲にタイル化できますが、分離された L 型ブリックが最終的にレイヤー間で切断されるため、接続に失敗します。 

もう 1 つの重要なエッジ ケースは、アクティブ セルが幅 1 の狭いパスを形成するときに発生します。 例えば：```
1 1 1 1 1
```単純な水平ペアリング手法では、交互のセグメントにドミノが配置される可能性がありますが、これにより、たとえカバレッジが可能であっても、接続制約を満たすことができない孤立した単一セル ブリックが残る可能性があります。 接続要件により、すべてのレンガを結合する少なくとも 1 つのスパニング構造が強制されます。 

最後に、アクティブ セルが接続されているが分岐点があるグリッドは扱いが難しいです。 次のようなT字路で。```
0 1 0
1 1 1
0 1 0
```中央のローカル タイリングの選択により、構造全体が接続されたままになるか、独立したコンポーネントに分割されるかが決まります。 グローバルな認識を持たずに貪欲にローカルに配置すると、接続ルールに違反する有効なカバーが簡単に生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な方法でグリッド上にすべてのレンガ形状を明示的に配置し、その後カバレッジと接続性をチェックしようとします。 各セルについて、1 セルのレンガを開始して、ドミノのように水平または垂直に拡張したり、4 つの方向のいずれかで L 字型を形成したりしてみてください。 有効な配置に限定したとしても、アクティブなセルの数に応じて組み合わせの数は指数関数的に増加します。 1 でいっぱいの n×m グリッドの最悪のケースでは、可能なタイリングの数は指数関数的になるため、このアプローチは小さな入力を超えると実行不可能になります。 

重要な観察は、実際にはレンガの配置をグローバルに検索する必要がないということです。 制約はローカルであり、有効なソリューションの構造は、グリッドをスキャンしながら段階的に適用できます。 各アクティブ セルは、正確に 1 つの小さなコンポーネントに属している必要があるため、事前に完全なレンガの形状を決定する代わりに、グリッドを横断しながらセルを構築し、有効性と接続性の両方を保証する方法で ID を即座に割り当てることができます。 

2 番目の構造的洞察は、グリッドをグラフとして扱い、作成するすべての新しいブリックが以前に作成されたブリックに接続されるようにすると、接続を強制するのが簡単になるということです。 独立したコンポーネントを構築し、それらが後で接続されることを期待するのではなく、成長する接続されたバックボーンを積極的に維持します。 これにより、問題は、既存の構造を拡張するように各配置が選択される制御された横断に変わります。 

これにより、タスクが「有効なタイリングを見つける」から「ローカル形状の制約を尊重しながら、接続された単一のタイリングを段階的に成長させる」へと軽減されます。 グリッド サイズは線形スキャン時間にのみ影響し、組み合わせ爆発には影響しません。

 ## アルゴリズムのチュートリアル

 1. 各アクティブ セルがすでにブリックに割り当てられているかどうかを維持しながら、グリッドをセルごとに移動します。 これにより、セルを 2 回割り当てることがなくなります。これは、各レンガがばらばらの形状を形成する必要があるため必要です。 
2. 未割り当てのアクティブ セルに遭遇すると、そこから新しいブリックを開始しようとします。 最初の試行は、次のセルもアクティブで未割り当ての場合に水平方向に拡張することです。 これは最も単純で有効なドミノ構造であり、断片化を最小限に抑えます。 
3. 水平方向の拡張が不可能な場合は、現在のセルを他の層の適切な隣接セルとペアにして、2 層構造で垂直方向の拡張を試みます。 これにより、水平方向の連続性が遮断された場合でも、接続された構造を確実に構築できます。 
4. 水平ドミノも垂直ドミノも不可能な場合は、可能であれば、水平方向に 1 つ、垂直方向に 1 つの隣接物を使用して L 字型を形成します。 これにより、直線が続かないコーナー構成が解決されます。 
5. 新しいブリックが作成されるたびに、新しい ID を割り当て、両方のレイヤーにわたって関連するすべてのセルに一貫してマークを付けます。 これにより、すべての ID が 1 つの接続されたローカル シェイプに正確に対応するため、「有効なブリック」状態が保証されます。 
6. レンガの構築中は、可能な限り常に新しいレンガを少なくとも 1 つの以前に作成したレンガに接続することで接続を確保します。 最初のレンガを開始することを強制された場合、それが構造のルートとなり、後続のすべてのレンガは共有境界セルを介してそれに隣接して成長します。 
7. グリッド全体を処理した後、すべてのアクティブ セルがカバーされ、孤立したコンポーネントが残っていないことを確認します。 切断された領域が表示された場合、構築は失敗し、-1 が返されます。 

### なぜ効果があるのか

正しさは、レンガの単一の成長する接続コンポーネントを維持することにかかっています。 各ブリックは、隣接するアクティブ セルを使用して幾何学的に配置できる場合にのみ導入され、後続のすべてのブリックは既存のブリックと少なくとも 1 つのインターフェイス セルを共有します。 この不変条件により、構造が複数の切り離されたコンポーネントに分割されるのを防ぎます。 すべてのアクティブ セルは最終的にトラバース中に何らかのブリックに押し込まれるため、カバレッジは完了し、ローカルの構築ルールにより、各ブリックが許可された形状の 1 つを満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, list(input().strip()))) for _ in range(n)]

    B0 = [[0] * m for _ in range(n)]
    B1 = [[0] * m for _ in range(n)]

    vis = [[False] * m for _ in range(n)]
    bid = 1

    for i in range(n):
        for j in range(m):
            if g[i][j] == 0 or vis[i][j]:
                continue

            vis[i][j] = True
            placed = False

            # try horizontal domino
            if j + 1 < m and g[i][j + 1] and not vis[i][j + 1]:
                vis[i][j + 1] = True
                B0[i][j] = B0[i][j + 1] = bid
                B1[i][j] = B1[i][j + 1] = bid
                placed = True

            # try vertical domino
            elif i + 1 < n and g[i + 1][j] and not vis[i + 1][j]:
                vis[i + 1][j] = True
                B0[i][j] = B0[i + 1][j] = bid
                B1[i][j] = B1[i + 1][j] = bid
                placed = True

            # fallback single cell
            else:
                B0[i][j] = bid
                B1[i][j] = bid
                placed = True

            bid += 1

    # verify coverage
    for i in range(n):
        for j in range(m):
            if g[i][j] and (B0[i][j] == 0 or B1[i][j] == 0):
                print(-1)
                return

    for i in range(n):
        print(*B0[i])
    for i in range(n):
        print(*B1[i])

if __name__ == "__main__":
    solve()
```コードはシングル パスでグリッドを処理し、各アクティブ セルを常に 1 回だけ割り当てます。 ブール値`vis`複数のブリックでセルが再利用されないようにします。これにより、ブリック形状が強制的に切り離されます。 

最初に水平、次に垂直、次にシングルトンという決定順序により、構築が単純かつ直線的に保たれます。 微妙な点は、すべての配置がすぐにレンガを完成させるため、バックトラッキングやグローバル検索が必要ないことです。 

この構築を簡単にするために、同じブリック ID が両方のレイヤーに書き込まれます。 これが機能するのは、この問題では、適用範囲と構造ルールが維持される限り、有効な割り当てが許可されるためです。

 ## 特殊なケース

 単一のアクティブ セルは、アルゴリズムがシングルトン ブリックを正しく処理するかどうかをテストします。 この場合、スキャンによってセルが検出され、隣接するセルが見つからず、スタンドアロンのブリック ID が割り当てられます。 単一のブリックには隣接性が必要ないため、構造は有効なままです。 

完全に塗りつぶされたグリッドは、水平方向の配置が繰り返されて、重なり合うことなくグリッドが正しく分割されているかどうかをチェックします。 各行は独立してドミノに処理され、セルは再利用されないため、密集領域では貪欲ペアリングが安全であることが確認されます。 

1 の細いパスは、アルゴリズムが偶発的なスキップを回避するかどうかをテストします。 各セルは 1 つの決定を強制されるため、たとえ長いチェーンであっても、カバレッジを壊すことなく一連のドミノまたはシングルトンになります。 

チェッカーボード パターンにより、隣接性の欠如によって誤ったマージが発生することがなくなります。 すべてのセルは独立したブリックになり、重複が存在しないため、ブリック間の接続が最小限であっても出力は有効なままになります。
