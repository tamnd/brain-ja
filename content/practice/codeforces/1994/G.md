 ## 解決策
 ## 問題の理解

 整数の固定配列とターゲット値が与えられ、負でない整数を 1 つ選択できます。`x`。 配列に適用される演算は単純です。配列のすべての要素を XOR します。`x`、結果を合計します。 目標は、何かを見つけることです`x`この変換された合計が必要なターゲットと一致するようにする`s`。 

重要な難点は、すべての数値が最大で 2 進数で表現されることです。`k`ビット、および配列と`s`大きくなる可能性があります。 各テスト ケースには最大で次のものを含めることができます。`n`すべてのテスト ケースにわたって、入力の合計量は次の範囲に制限されます。`n * k ≤ 2 × 10^6`これにより、あらゆる解が入力サイズで線形に近くなるように強制されます。 列挙しようとするものすべて`x`または、候補者ごとにすべての可能性をシミュレートすることは直ちに不可能です。`x`まであります`k`ビットなので、総当たり攻撃を行うと、最大まで探索することになります。`2^k`候補者たち。 

単純な間違いは、これが単純なビットごとの貪欲な問題であると想定することです。`x`独立して決めることができます。 XOR は個々のビット内ではなく、合計を通じてのみキャリーと対話するため、これは失敗します。 たとえば、上位ビットを反転すると、`x`すべての人からの貢献を変更します`a_i`、グローバル合計制約はすべてのビットを結合します。 

ビットごとに局所的に考える場合、別の微妙な問題が発生します。各ビット位置の寄与を個別に照合しようとすると、XOR が 10 進数の累算において構造化されているが非線形な方法で各数値の値を変更することを無視します。 

## アプローチ

 ブルートフォースアプローチはあらゆる可能なことを試みるでしょう`x`から`0`に`2^k - 1`、すべてを計算します`a_i XOR x`、合計が等しいかどうかを確認します`s`。 これは正しいですが、まったく実行不可能です。 それぞれの評価にかかる費用`O(nk)`バイナリ文字列から実行された場合、または`O(n)`数値が事前に解析されており、`2^k`候補者は天文学的に多い。 

重要な観察点は、次の XOR です。`x`は要素ごとにビットごとに独立しており、合計制約は最下位から最上位までビットごとに処理され、影響を上向きに伝えます。 選択する代わりに`x`直接的には、それを少しずつ構築し、各ビット位置でどの程度の「過剰」または「不足」を考慮する必要があるかを維持します。 

各ビット位置の寄与を個別のバランス方程式として扱います。 ビットごとに`j`、現在、配列要素の数を計算できます。`1`その部分と何人が持っていますか`0`。 ビットを設定すると`j`の`x`に`0`または`1`、これがそのビットレベルで寄与をどのように反転するかを正確に知っています。 ただし、ビットを反転すると合計が次の倍数に変化するため、効果は上方向に伝播します。`2^j`。 

これにより、ビットに対する digit-DP のような構造が得られ、ここで部分的な代入が行われるかどうかをシミュレートします。`x`上位ビットでどれだけの差が説明されているかを表す実行中のキャリーのような状態を使用してターゲットと一致させることができます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n · k · 2^k) | お(1) | 遅すぎる |
 | ビット単位の DP オーバービット | O(n · k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 下位ビットが上位ビットへのキャリー寄与を完全に決定するため、ビットを最下位ビットから最上位ビットに処理します。 

1. すべての入力バイナリ文字列を整数のようなビット アクセスに変換しますが、完全な整数は必要ありません。 代わりに、ビットごとに何個かをカウントします。`a_i`持っています`1`。 
2. しましょう`cnt[j]`ビットの 1 の数になる`j`配列内で。 次に、ビットのゼロの数`j`は`n - cnt[j]`。 
3. 変数を維持します`carry`、現在達成可能な合計と目標の差が下位ビットからどれだけ蓄積されたかを表します。 このキャリーは次の単位で測定されます。`2^j`上に向かって進んでいきます。 
4. 各ビット位置について`j`から`0`に`k-1`の値を決定します。`x_j`。 もし`x_j = 0`、このビットの貢献は`cnt[j] * 2^j`。 もし`x_j = 1`、すべてのビットが反転するため、貢献度は次のようになります。`(n - cnt[j]) * 2^j`。 
5. 結果として得られる寄与と現在のキャリーをこのレベルでのターゲット ビット寄与と比較します。 不一致によって次のキャリーが決まります。 代数的に、`x_j`差を正確に割り切れるようにする`2^(j+1)`現在のターゲットビットに合わせて調整した後。 
6. 両方の選択肢がある場合、`x_j`一貫したキャリー遷移を生成できない場合、解決策は存在せず、出力します。`-1`。 
7. それ以外の場合は修正します`x_j`実現可能性をもとに貪欲に上昇し続けます。 

すべてのビットを終了した後、有効な解を得るには、最後のキャリーがゼロになる必要があります。 

### なぜ効果があるのか

 アルゴリズムは、ビットの処理後に不変条件を維持します。`j`、構築された合計と目標との間の累積差は次の数で割り切れます。`2^(j+1)`そして完全に説明されています`carry`。 それぞれの決断を少しずつ`j`キャリー伝播を通じて上位ビットにのみ影響し、XOR により、ビットの反転により寄与が線形かつ可逆的に変化します。 すべてのビットの決定では、次の 2 のべき乗を法とした剰余の一貫性が維持されるため、有効な解は同じ制約に従う必要があるため、解が存在する場合、貪欲な実現可能性チェックではその解は削除されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        
        cnt = [0] * k
        
        a = []
        for _ in range(n):
            x = input().strip()
            a.append(x)
            for i, ch in enumerate(x):
                if ch == '1':
                    cnt[i] += 1
        
        x_bits = ['0'] * k
        
        carry = 0
        
        for i in range(k - 1, -1, -1):
            bit_val = 1 << (k - 1 - i)
            
            ones = cnt[i]
            zeros = n - ones
            
            # try x_i = 0
            cost0 = ones
            # try x_i = 1
            cost1 = zeros
            
            # target bit
            sb = 1 if s[i] == '1' else 0
            
            # adjust with carry in a normalized way
            # we compare parity of feasible transitions
            if (cost0 + carry) % 2 == sb:
                x_bits[i] = '0'
                carry = (cost0 + carry - sb) // 2
            elif (cost1 + carry) % 2 == sb:
                x_bits[i] = '1'
                carry = (cost1 + carry - sb) // 2
            else:
                print(-1)
                break
        else:
            if carry != 0:
                print(-1)
            else:
                print("".join(x_bits))

if __name__ == "__main__":
    solve()
```このコードは、中心となるアイデアをビットごとの実現可能性チェックに圧縮します。 重み付けされた 2 の累乗を明示的に計算する代わりに、ビット境界間の一貫性のみが重要となるため、すべてをパリティおよびキャリー遷移に正規化します。 

の`cnt`配列は、入力の各ビットが XOR の下でどのように動作するかを事前計算します。 ループ構成`x`下位ビットからの未解決の寄与を表すキャリーを維持しながら、上位ビットから下位ビットへ。 現在のビットのどちらを選択しても、ターゲット ビットおよびキャリーとの必要なパリティを満たせない場合、構築はただちに失敗します。

 ## 特殊なケース

 すべての数値が同一である場合には、デリケートなケースが発生します。`s`交互のビット寄与を強制します。 このような状況では、すべてのビットの決定によりアレイ全体で同一の変換が行われるため、実現可能性は早期に崩壊します。 アルゴリズムはこれを検出します。`x_j = 0`そして`x_j = 1`～と同じパリティの不一致が生じる`s_j`、すぐに失敗を引き起こします。 

もう一つのケースは次のような場合です。`n = 1`。 次に、方程式は次のようになります。`a_1 XOR x = s`、 それで`x = a_1 XOR s`は常に有効です。 アルゴリズムはこれを自然に処理します。`cnt[j]`どちらかです`0`または`1`、そして正確に 1 つのブランチがすべてのビットに対して一貫性を保ち、直接 XOR ソリューションを生成します。
