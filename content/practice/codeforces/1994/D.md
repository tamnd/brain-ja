 ## 解決策
 ## 問題の理解

 接続されたグラフを構築するように求められます。$n$頂点を空のグラフから開始して、次のコマンドを実行します。$n-1$操作。 各操作には 1 から 1 までの番号が付けられます。$n-1$。 操作用$x$、2つの頂点を選択できます$u$そして$v$配列内の関連する値の絶対差$a$で割り切れます$x$、そしてそれらの間に無向エッジを追加します。 目的は、この方法で接続されたグラフを構築できるかどうかを判断し、構築できる場合は、各操作に使用される正確なエッジを出力することです。 

制約により許可されるのは、$n$2000までの値と、$n$すべてのテスト ケースの合計も最大 2000 です。これは、テスト ケースごとに 2 次複雑度を持つアルゴリズムであっても ($O(n^2)$）は実現可能です。 配列内の値$a$最大で大きくすることができます$10^9$ただし、小さい数を法とした差分のみを考慮します。$1 \le x \le n-1$, そのため、大きな数の計算には問題はありません。 

すべての数値が次の場合に、微妙なエッジケースが発生します。$a$等しいです。 たとえば、次の場合$n=3$そして$a = [5,5,5]$、 それから$|a_u - a_v| = 0$、任意の数で割り切れます$x$。 これは、接続が自明に可能である特殊なケースですが、ゼロより厳密に大きい差異のみを探す単純なアプローチは失敗する可能性があります。 もう 1 つのシナリオは、数値間の差がすべて素数で、最初のいくつかの演算のインデックスよりも大きい場合です。 このような場合、小さいサイズのエッジを選択できない場合があります。$x$「中心」頂点に接続しない場合。 

## アプローチ

 ブルート フォース アプローチでは、演算ごとに頂点のすべてのペアを列挙し、割り算条件をチェックしてから、接続されたグラフを段階的に構築しようとします。 それぞれの操作について$x$、すべてを調べます$O(n^2)$ペア、つまり$O(n^3)$全体的な時間の複雑さ。 これは非常に小さい場合には許容されます$n$、しかし、$n \approx 2000$それは遅すぎて、パフォーマンスが最大になります$8 \times 10^9$最悪の場合の運用。 

重要な洞察は、すべての操作ですべてのペアを考慮する必要はないということです。 分割可能性の要件は、小さいほど弱くなります。$x$なぜなら、すべての整数は 1 で割り切れ、多くの違いは 2、3 などで割り切れるからです。 したがって、貪欲な戦略が機能します。つまり、1 つの頂点を「ルート」として選択し、他のすべての頂点を操作の順序でそれに接続します。 通常、差は相対的に大きいため、$x$最初に、すべての頂点を配列内の最初の頂点に接続すると、次の条件が保証されます。$|a_u - a_v| \% x == 0$少なくとも満足している$x=1$。 最初の接続の後、必要に応じて後続の操作を使用して残りの頂点を接続できますが、実際には、すべての頂点を 1 つの頂点に順番に接続することでスパニング ツリーが保証されます。 

したがって、最適なアプローチは頂点を選択することです。$r$(簡単にするために頂点 1)、常に他のすべての頂点をそれに接続しようとして、操作ごとに移動します。 全部作れたら$n-1$このように接続すると、グラフが接続されます。 そうでなければ不可能です。 これにより問題は次のように縮小されます$O(n^2)$テストケースごとに、これは実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 貪欲なルート接続 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$。 
2. スパニング ツリーのルートとして頂点 1 を選択します。 エッジを格納するリストを初期化します。 
3. 操作を反復する$x$1から$n-1$。 操作ごとに頂点を見つけます$v$を満たすルートにまだ接続されていません$|a_1 - a_v| \% x == 0$。 候補が複数ある場合はどれかを選択してください。 
4. エッジを追加する$(1, v)$エッジとマークのリストへ$v$接続されたまま。 
5. すべての頂点が接続された場合$n-1$操作を行う場合は、「YES」とエッジのリストを出力します。 何らかの操作で有効な値が見つからない場合は、$v$、「いいえ」を出力します。 

機能する理由: 常に新しい頂点をルートに接続することで、成長する接続コンポーネントを維持します。 通常、数値の差は 1 または小さな数値で割り切れるため、最初の数回の操作はほとんどの場合成功します。 不変条件は次のとおりです$i$操作では、ルートに接続された頂点が単一の接続コンポーネントを形成します。 すべての頂点が接続されると、スパニング ツリーが完成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        edges = []
        connected = [False] * n
        connected[0] = True
        remaining = set(range(1, n))
        possible = True

        for x in range(1, n):
            found = False
            for v in list(remaining):
                if abs(a[0] - a[v]) % x == 0:
                    edges.append((1, v + 1))
                    connected[v] = True
                    remaining.remove(v)
                    found = True
                    break
            if not found:
                possible = False
                break

        if possible:
            print("YES")
            for u, v in edges:
                print(u, v)
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースを処理します。 の`remaining`set により、まだ接続されていない頂点のみが考慮されるようになります。 割り切れる可能性をチェックします`abs(a[0] - a[v]) % x == 0`エッジを段階的に追加します。 演算に有効なエッジが存在しない場合、アルゴリズムは「NO」で正しく終了します。 頂点 1 をルートとして使用するのは任意ですが、貪欲な選択が簡素化されます。
