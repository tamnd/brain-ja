 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられます。 何も残らなくなるまで、要素のグループを繰り返し削除します。 各グループは 2 つの制約を尊重する必要があります。選択したインデックスを昇順に見る場合、対応する値は減少していない必要があり、インデックス自体はサブシーケンスの通常どおり厳密に増加している必要があります。 グループを削除するコストは、グループ内のすべての値の積であり、すべてのグループにわたる合計コストをできるだけ小さくしたいと考えています。 

重要な自由は、連続したセグメントの削除を強制されないことです。 インデックス順に読み取ったときに値が減少しない限り、任意のサブシーケンスを選択できます。 これは、配列を複数の有効なサブシーケンスに効果的に分割し、各要素が 1 つのサブシーケンスにのみ属することを意味します。 コストは各グループ内では純粋に乗算的であり、グループ間では加算されるため、目的は値をどのようにグループ化するかによってのみ決まります。 

制約は小さく、配列の要素数は最大 100、値は最大 100 です。これは、位置に対する 2 次または 3 次動的計画法が妥当であることをすぐに示唆していますが、サブセットに対する指数関数は妥当ではありません。 

単純だが重要なエッジケースは、局所的に乗算コストが増加するにもかかわらず、グループ化が有益である場合に発生します。 たとえば、価値観`[1, 2, 2]`別途費用がかかります`1 + 2 + 2 = 5`ただし、それらを 1 つの有効な非減少サブシーケンスにグループ化すると、コストが生じます。`1 * 2 * 2 = 4`。 これは、問題が単純な「数値の乗算を避ける」ヒューリスティックではないことを示しています。 小さい値を早期にグループ化すると、総コストを削減できます。 

もう 1 つの微妙な問題は、実現可能性が値だけではなくインデックスの順序に依存することです。 例えば、`[2, 1]`ソート値が別の方法を示唆している場合でも、サブシーケンスの順序によって強制的に減少するため、グループ化することはできません。 

## アプローチ

 強引なアイデアは、配列を有効なサブシーケンスに分割する可能なあらゆる方法を試みることです。 各パーティションについて、各グループがインデックス順に非減少シーケンスを形成していることを確認し、そのコストを計算します。 パーティションの数はベル数のように増加し、有効なサブシーケンスに限定しても指数関数的に増加します。`n`。 と`n = 100`、これはまったく不可能です。 

問題の構造は貪欲な視点を示唆しています。サブシーケンスを形成するたびに、そのチェーン内で値が決して減少しないように要素をチェーンする方法を決定します。 要素がチェーンに割り当てられると、その寄与はそのチェーンのコストに乗算的にロックされます。 これにより、チェーンの初期に小さな値を追加すると、後の乗算の増加を軽減できるという意味で、要素間の相互作用がローカルになります。 

重要な観察は、1 より大きい値を乗算するとすぐにコストが増加するため、コスト関数は可能な限り小さな値をグループ化することに報酬を与えるということです。 同時に、グループ化はインデックスに沿った非減少制約によって制限され、これにより事実上、チェーンは位置と値の順序の両方を尊重することになります。 

これは、建設的な貪欲な戦略につながります。有効なサブシーケンスを左から右に繰り返し構築し、非減少順序を破ることなく次の利用可能な要素を追加できる場合は常にサブシーケンスを拡張し、それができない場合は新しいサブシーケンスを開始します。 これは、各実行がサブシーケンス ルールを尊重するという制約の下で、配列を最小数の「局所的に増加する」実行に分割し、各実行の積を合計することと同じです。

 ## アルゴリズムのチュートリアル

 1. 構築中の現在のサブシーケンスを維持しながら、配列を左から右にスキャンします。 このサブシーケンスに最後に追加された値も維持します。 
2. 各要素について、非減少条件を破ることなく現在のサブシーケンスを拡張できるかどうかを確認します。 可能であれば、それを現在のサブシーケンスに追加し、実行中の製品を更新します。 
3. サブシーケンスを拡張できない場合は、現在のサブシーケンスを閉じ、その積を答えに追加し、現在の要素から始まる新しいサブシーケンスを開始します。 
4. すべての要素が消費されるまで続けてから、最後のサブシーケンスの積を追加します。 

この構築が意味のある理由は、各サブシーケンスがインデックス順の非減少制約の下で最大限に拡張されるため、ローカルで有効な拡張がセグメント内で未使用のまま残されないためです。 

### なぜ効果があるのか

 このアルゴリズムは、貪欲な拡張ルールに基づいて、配列のパーティションを最大の有効なサブシーケンスに構築します。 サブシーケンスを停止するときは常に、次の要素が最後に選択した要素よりも厳密に小さいためです。つまり、実行可能性に違反せずに同じサブシーケンスに属することはできません。 これにより、各サブシーケンスが有効であることが保証されます。 

各サブシーケンス内で、新しいサブシーケンスを開始するよりも早く拡張しても、貪欲な構築のコストが増加することはありません。これは、新しいサブシーケンスを開始すると、既存のプロダクト構造を共有する代わりに別の乗算係数が強制されるためです。 したがって、貪欲なセグメンテーションは、実現可能性の制約を尊重しながら、不必要な断片化を回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 676767677

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        i = 0
        while i < n:
            cur_prod = a[i]
            last = a[i]
            j = i + 1
            
            while j < n and a[j] >= last:
                cur_prod = (cur_prod * a[j]) % MOD
                last = a[j]
                j += 1
            
            ans = (ans + cur_prod) % MOD
            i = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装は各テスト ケースを独立して処理し、現在の位置から開始して最大の非減少セグメントを繰り返し構築します。 変数`cur_prod`現在のサブシーケンスの乗算コストを追跡します。`last`非減少制約を強制します。 制約が破られると、サブシーケンスは閉じられ、そのコストがグローバルな答えに累積されます。 

ここでの一般的な実装の落とし穴は、新しいサブシーケンスを開始するときに、実行中のプロダクトと最終値トラッカーの両方をリセットするのを忘れることです。 もう 1 つの微妙な点は、中間積が 64 ビットの制限を超える可能性があるため、各ステップでのモジュラー乗算です。`n ≤ 100`。

## テストケース```python
import sys, io

MOD = 676767677

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        i = 0
        while i < n:
            cur = a[i]
            last = a[i]
            j = i + 1
            while j < n and a[j] >= last:
                cur = (cur * a[j]) % MOD
                last = a[j]
                j += 1
            ans = (ans + cur) % MOD
            i = j

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、次のような厳密に減少する配列です。`[5, 4, 3, 2]`。 拡張は不可能であるため、アルゴリズムは単一要素の後のすべてのサブシーケンスを直ちに閉じます。 各要素は独自のグループを形成し、合計コストは次のようになります。`5 + 4 + 3 + 2`。 

別のケースは、次のような完全に減少しない配列です。`[1, 1, 1, 1]`。 貪欲な構築により単一のサブシーケンスが拡張され続け、コストが発生します`1 * 1 * 1 * 1 = 1`。 人為的な分割は乗算グループの数を増やすだけであり、コストを削減することはできません。 

次のような混合ケース`[2, 1, 3]`は、再起動の動作を明確に示しています。`[2]`すぐに閉じてから、`[1, 3]`有効なサブシーケンスを形成し、総コストを生成します`2 + 3 = 5`。
