 ## 問題の理解

 各配列要素は個別に変更できます。 価値のために$x$、任意の正の整数を選択できます$b$、交換してください$x$による$x \bmod b$。 

目標は、結果として得られる配列の MEX を最大化することです。 操作はすべての位置に独立して適用されるため、問題は次のようになります。 

各要素が変換できる一連の値が与えられた場合、各要素に 1 つのターゲット値を割り当てることで構築できる最大の MEX はどれですか?

 制約は、直接構築が意図されていないことを示す最初の手がかりです。 すべてのテスト ケースの要素の合計数は最大で$2\cdot 10^5$、最大値の合計は次のとおりです。$10^6$。 これは、アルゴリズムの複雑さが値の範囲ではなく値の範囲に依存することを強く示唆しています。$n^2$。 

主な困難は、どの数値がどの値であるかを正確に理解することです$x$1 回のモジュロ演算後には次のようになります。 

いくつかの例を考えてみましょう。 

もし$x=6$、 それから：$$6\bmod 7=6,$$それで$6$到達可能です。 

また、$$6\bmod 6=0,\quad 6\bmod 5=1,\quad 6\bmod 4=2.$$到達可能な値は次のとおりです。$$\{0,1,2,6\}.$$単純な仮定では、間のすべての値は次のようになります。$0$そして$x$到達可能です。 それは誤りです。 例えば、$3$から生産することはできません$6$。 

もう 1 つの簡単な間違いは、大きな値が重複すると常に任意の欠損値が生成される可能性があると考えることです。 例えば：$$a=[2,2].$$それぞれ$2$になることしかできない$0$または$2$。 作成できます$0$、しかし私たちは決して創造することはできません$1$。 答えは$1$、 ない$2$。 

3 番目の微妙なケースは、ゼロの存在です。 

のために$$a=[0,0,0],$$すべての要素は常に残ります$0$、 なぜなら$$0\bmod b = 0.$$結果の配列には決して次のものを含めることはできません。$1$、したがって、答えは次のとおりです$1$。 

これらの例は、到達可能な値を正確に特徴付ける必要があることを示しています。 

## アプローチ

 ブルート フォースの観点では、すべての要素の到達可能なすべての値を計算し、要素とターゲット値の間のマッチングによって取得可能な最大の MEX を検索します。 

それぞれの値が$O(x)$到達可能な状態では、結果として得られる 2 部マッチング定式化はあまりにも高価すぎます。 までの値$10^6$、このアプローチは完全に非現実的です。 

重要な観察結果は、単一の数値の分析から得られます$x$。 

係数を変えるとします$b$。 

もし$b>x$、 それから$$x\bmod b=x.$$もし$b\le x$の場合、剰余は常に厳密に以下になります。$x/2$。 公式社説はこれをケースに分けて証明している$b\le x/2$そして$x/2<b\le x$。 

また、あらゆる値が$$0\le y<\frac{x}{2}$$を選択することで達成可能です$$b=x-y.$$したがって、完全な到達可能なセットは次のようになります。$$R(x)=\{x\}\cup \left\{ 0,1,\dots,\left\lfloor\frac{x-1}{2}\right\rfloor \right\}.$$この特徴付けにより、問題は完全に変わります。 

次に、次のことを確認することを検討してください。$$\operatorname{mex}\ge k$$可能です。 

私たちはあらゆる数字を認識する必要がある$$0,1,\dots,k-1.$$値$x<k$は特別です。 以来$x$それ自体は到達可能です。$x$実現する$x$常に、より小さい数に対して使用するのと少なくとも同等の効果があります。 より小さなターゲットは、後で十分に大きな値によって生成される可能性もあります。 

そこで、確認しながら、$k$、すべての値の 1 つの出現を貪欲に予約します。$x<k$表す$x$。 

これを実行した後、いくつかの数字が$[0,k-1]$覆われていないままです。 欠けている数字をそのままにしておきます$$m_1<m_2<\cdots.$$残りのすべての要素$x$間隔を正確にカバーできる$$0 \le y \le \left\lfloor\frac{x-1}{2}\right\rfloor.$$同様に、欠損値をカバーできます。$m$もし$$x\ge 2m+1.$$ここで、問題は古典的な貪欲マッチングの問題になります。 

不足している番号をどんどん並べ替えます。 利用可能な大きな要素を徐々に並べ替えます。 欠落している数値を最小から最大の順に処理し、現在の欠落している数値をカバーできる最小の利用可能な要素を常に割り当てます。 

ある時点でそのような要素が存在しない場合、$\operatorname{mex}\ge k$不可能です。 

実現可能性が単調なので、$k$、答えの二分探索が可能になります。

## アルゴリズムのチュートリアル

 ### 到達可能な値

 あらゆる価値観に対して$x$、$$R(x)= \{x\} \cup \{0,1,\dots,\lfloor (x-1)/2\rfloor\}.$$これが基本的な構造的事実です。 

### 修正の実現可能性チェック$k$1. すべての値の頻度を数えます。 
2. あらゆる人にとって$x<k$、未使用のオカレンスの場合、$x$存在する場合は、表すために 1 つのオカレンスを予約します。$x$。 
3. すべての数字を収集します。$[0,k-1]$予約されていなかったもの。 これらは欠損値です。 
4. 残りのすべての配列要素が使用可能なリソースになります。 
5. 利用可能な要素ごとに$x$、計算する$$t=\left\lfloor\frac{x-1}{2}\right\rfloor.$$この要素は、以下を超えない欠損値をカバーする場合があります。$t$。 

1. 欠損値を最小値から最大値まで処理します。 複数セットの利用可能な容量を維持する$t$。 
2. 欠損値の場合$m$、満足できる最小の容量を選択してください$$t\ge m.$$マルチセットから削除します。 

1. そのような容量が存在しない場合、チェックは失敗します。 
2. すべての欠落値が割り当てられていれば、チェックは成功します。 

### 二分探索

 答えは次の間にあります$0$そして$n$、長さの配列なので$n$より大きい MEX は使用できません$n$。 

二分探索が最大$k$実現可能性チェックが成功した場合。 

### なぜ効果があるのか

 値が指定されるたびに、$x<k$存在し、1 つのコピーを直接割り当てます$x$決して実現可能性を下げることはできません。 そのコピーを別の方法で使用すると、次の値よりも小さい値が生成されます。$x$、 その間$x$それ自体は、の別のコピーによってのみ生成される可能性があります。$x$。 そのようなコピーをすぐに予約することが常に最適です。 

これらの予約の後、残りのすべての要素はそのしきい値を通じてのみ寄与します。$$\left\lfloor\frac{x-1}{2}\right\rfloor.$$その結果、欠落している数値をしきい値と一致させるという問題が発生します。 不足している数値を昇順に処理し、常に実行可能な最小のしきい値を使用するのが、標準的な最適な貪欲戦略です。 以前に使用したより大きなしきい値は、将来の柔軟性を低下させるだけです。 

したがって、チェックは正しく、単調な実現可能性述語に対する二分探索により、達成可能な最大の MEX が得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_left
from collections import Counter
import heapq

input = sys.stdin.readline

def can_make(a, k):
    cnt = Counter(a)

    missing = []

    for x in range(k):
        if cnt[x] > 0:
            cnt[x] -= 1
        else:
            missing.append(x)

    caps = []

    for x, c in cnt.items():
        if c <= 0:
            continue

        if x == 0:
            cap = -1
        else:
            cap = (x - 1) // 2

        for _ in range(c):
            caps.append(cap)

    caps.sort()

    ptr = 0
    m = len(caps)

    for need in missing:
        pos = bisect_left(caps, need, ptr)
        if pos == m:
            return False
        ptr = pos + 1

    return True

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        lo, hi = 0, n

        while lo < hi:
            mid = (lo + hi + 1) // 2

            if can_make(a, mid):
                lo = mid
            else:
                hi = mid - 1

        ans.append(str(lo))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()

## テストケース```python
import sys, io

def run(inp: str) -> str:
    from bisect import bisect_left
    from collections import Counter

    data = iter(inp.strip().split())

    t = int(next(data))
    out = []

    def can_make(a, k):
        cnt = Counter(a)

        missing = []

        for x in range(k):
            if cnt[x]:
                cnt[x] -= 1
            else:
                missing.append(x)

        caps = []

        for x, c in cnt.items():
            cap = -1 if x == 0 else (x - 1) // 2
            caps.extend([cap] * c)

        caps.sort()

        ptr = 0

        for need in missing:
            pos = bisect_left(caps, need, ptr)
            if pos == len(caps):
                return False
            ptr = pos + 1

        return True

    for _ in range(t):
        n = int(next(data))
        a = [int(next(data)) for _ in range(n)]

        lo, hi = 0, n

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can_make(a, mid):
                lo = mid
            else:
                hi = mid - 1

        out.append(str(lo))

    return "\n".join(out)
