 ## 解決策
 ## 問題の理解

 私たちは、無限に続く家々の列に沿って感染の広がりを追跡するよう求められています。 感染は 0 日目にハウス 0 で始まり、毎日、現在感染しているハウスに隣接するさらに 1 軒の家に広がります。 後$n$何日もの間、私たちは家の連続した部分を与えられます$[l, r]$感染しているもの。 タスクは、有効なセグメントを判断することです。$[l', r']$前日に感染していた可能性がある$m \le n$。 

入力は複数のテスト ケースで構成されます。 各テスト ケースのキー値は次のとおりです。$n$、既知のセグメントがある日、$m$、セグメントを見つける必要がある前の日、および座標$l$そして$r$後のセグメントの$n$日々。 この問題はそれを保証します$r-l = n$、毎日感染する住宅の数がちょうど 1 つずつ増加することを反映しています。 

制約は小さい ($n \le 2000$）そのため、総当りシミュレーションでも技術的には実行できますが、より単純な建設的なアプローチが機能します。$O(1)$テストケースごとに。 

明らかではないエッジ ケースには負の境界が含まれます。たとえば、セグメントに 0 の左側に家が含まれている場合や、感染が完全に右側にある場合などです。 たとえば、次の場合$n=4$そしてセグメントは$[-2,2]$、次に有効なセグメント$m=1$そうかもしれない$[0,0]$、$[-1,0]$、 または$[0,1]$。 単純なアプローチでは、左側の境界が 0 のままでなければならない、または右側の境界が正のままでなければならないと誤って仮定する可能性がありますが、セグメントは、その長さが日数と等しい限り自由にシフトできます。 

## アプローチ

 最も簡単なアプローチは、0 日目から毎日をシミュレートすることです。日に達するまで、セグメントを左または右に 1 軒ずつ拡張するためにあらゆる方法を試すことができます。$n$。 これは日数がかかるため機能します。$n$小さいですが、それでも$n=2000$、すべてのテスト ケースについて毎日シミュレーションするのは不必要に複雑です。 操作数はおおよそ次のようになります$O(n \cdot t)$、ここでは許容されますが、エレガントではありません。 

重要な洞察は、感染セグメントが連続的であり、左右またはその組み合わせで対称的に (1 日あたり 1 軒ずつ) 拡大しているということです。 後のセグメントの長さを知る$n$日 ($r-l = n$)、日時に有効なセグメントを直接計算できます。$m$現在のセグメントを縮小することにより、$n-m$左側の境界を右に移動するか、右側の境界を左に移動するか、またはその両方によって住宅を作成します。 最も単純な選択は、左側の境界を右にシフトすることです。$n-m$そして右側の境界を固定したままにします。 これにより、有効なセグメントが保証され、次のすべての値に対して機能します。$l$そして$r$感染はどちらの方向にも拡大する可能性があるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * t) | お(1) | 受け入れられるが、不必要に冗長 |
 | 建設的な変化 | O(t) | お(1) | 受け入れられ、シンプル |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、$l$、$r$。 
3. その日以降に追加で感染した住宅の数を計算する$m$:$extra = n - m$。 
4. 日中の有効なセグメントを選択します$m$。 簡単な選択の 1 つは、左側の境界を右にシフトすることです。$extra$右側の境界を変更せずに家を配置します。$$l' = l + extra, \quad r' = r$$これは、日中のセグメントの長さにより機能します。$m$になるだろう$r' - l' = n - extra = m$、正確に日ごとに感染した家の数$m$。 
5. 印刷$l'$そして$r'$テストケースごとに。 

**効果がある理由:** 感染は毎日、連続的なセグメントを形成します。 セグメントの長さは、開始からの日数に等しくなります。 セグメントをどちらかの側から対称的に縮小することで、連続性を維持しながら以前の日のセグメントを再構築できます。 複数の有効な選択肢が存在するため (代わりに右から縮小するなど)、単一の建設的な選択肢は受け入れられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, l, r = map(int, input().split())
    extra = n - m
    l_prime = l + extra
    r_prime = r
    print(l_prime, r_prime)
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースを処理します。`extra`日から戻す歩数を計算します$n$今日$m$。 左側の境界が右にシフトされます`extra`、セグメントの長さが次と等しくなることが保証されます。`m`。 これにより、off-by-one エラー、負のインデックス付けの問題、境界ミスが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n, m, l, r = map(int, input().split())
        extra = n - m
        print(l + extra, r)
    return out.getvalue().strip()

 ## 特殊なケース

 のために`n=m`の場合、セグメントは縮小しません。 のために`n>m`セグメントが負のインデックスと正のインデックスにまたがる場合、アルゴリズムは左側の境界のみを正しくシフトし、連続性を維持します。 たとえば、入力`n=4, m=2, l=-2, r=2`収量`l'=-2+2=0`、`r'=2`、与える`[0,2]`。 左境界が正になっても、問題では有効な連続セグメントが許可されるため、セグメントは有効なままです。 

完全に右のセグメントの場合、たとえば、`n=4, m=2, l=0, r=4`、境界を左にシフトします`extra=2`与える`[2,4]`、再び有効です。 

これは、アルゴリズムがネガティブ、ポジティブ、混合セグメントの両方を一貫して処理していることを示しています。
