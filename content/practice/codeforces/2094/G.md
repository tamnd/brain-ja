 ## 解決策
 ## 問題の理解

 要素を末尾に追加する、配列を反転する、最後の要素を先頭に移動する循環シフトを実行するという 3 種類の操作で配列を維持することが求められます。 すべての演算の後、配列要素の重み付き合計を計算する必要があります。この問題ではこれを「乱雑さ」と呼びます。これは、各要素の合計に 1 から始まる位置を乗算したものとして定義されます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、最初の操作が追加であることが保証されます。 テスト ケースごとの操作数は 200,000 に達する可能性があり、テスト ケース全体のすべての操作の合計は 200,000 に制限されます。 これは、効率的な操作ごとのアルゴリズム、理想的には O(1) または O(log n) が必要であることを示唆しています。これは、操作ごとに O(n) 回の再計算を行うと、最悪の場合、2 秒の制限をはるかに超えて最大 2×10^10 の操作に達するためです。 

配列を物理的にシフトまたは反転して毎回乱雑さを再計算する単純な実装は、配列のサイズと操作の頻度が原因で失敗します。 注意すべきエッジケースには、連続した反転やシフトが含まれます。これらは互いに打ち消し合ったり、単純なアルゴリズムでは誤って管理できない形で複合したりする可能性があるためです。 たとえば、配列が次の場合、`[1,2,3]`それを 2 回反転すると、次のようになります。`[1,2,3]`ただし、状態を適切に追跡することを忘れた単純なアルゴリズムでは、位置の計算を誤る可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、単純に配列を Python リストとして維持します。 追加の場合は、要素を最後に追加します。 反転するには、次のように呼びます。`arr.reverse()`。 循環シフトの場合は、次を使用します。`arr.insert(0, arr.pop())`。 各操作の後、配列を反復処理して計算します。`sum(arr[i] * (i+1) for i in range(len(arr)))`。 これは小さな配列では正しく機能しますが、200,000 回の演算と同様のサイズの配列では、各 O(n) の計算が遅くなりすぎます。 

最適化のための重要な洞察は、特定のプレフィックス合計と方向フラグを維持する場合、ざらつきを計算するために実際の配列が必要ないということです。 配列要素の現在の合計、加重合計 (ざらつき)、および配列の長さを保存することを検討してください。 追加は簡単です。 逆にすると、各要素の寄与が変化します。`i * a[i]`に`(n-i+1) * a[i]`。 巡回シフトは、最初または最後の要素を使用した加重合計の単純な更新としてモデル化できます。 デキューを使用してシーケンスを追跡し、ブール値フラグを使用して方向を反転すると、各操作が O(1) 更新に減り、完全な再計算が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 操作ごとに O(n) | O(n) | 遅すぎる |
 | 最適 | 操作ごとに O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列要素を保持するために空の両端キューを初期化します。 変数も初期化します`rizz`現在のさわやかさを保存し、`total`すべての要素の合計を保存します。 ブール値フラグを維持する`reversed`配列が反転したかどうかを追跡します。 
2. 追加操作の場合は、`reversed`フラグ。 逆にしない場合は、両端キューの右端に追加します。 逆の場合は左側に追加します。 アップデート`rizz`追加することで`len(array) * new_element`逆にならない場合、または`1 * new_element`逆の場合。 インクリメント`total`追加された要素によって。 
3. 逆の操作を行うには、`reversed`フラグ。 新しいリジネスを次のように計算します。`rizz = total * (len(array)+1) - rizz`。 これは、反転後の i*a[i] の合計は次の式から得られます。`(n+1)*sum(a[i]) - old_rizz`。 
4. 循環シフト操作の場合、反転していない場合は右からポップして左に追加するか、反転している場合は左からポップして追加します。 アップデート`rizz`引き算して`(n-1)*x`x が最後から移動された要素である場合、または追加`(n-1)*x`最初から、ポジションの変化を反映している場合。 
5. 各操作の後、現在の値を出力します。`rizz`。 

不変条件は、逆転を考慮して両端キューが要素の論理順序を常に正しく表すことです。`rizz`位置の変更を反映するために段階的に更新されるため、最初から再計算する必要はありません。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        q = int(input())
        arr = deque()
        rizz = 0
        total = 0
        reversed_flag = False

        for _ in range(q):
            cmd = input().split()
            op = int(cmd[0])
            
            if op == 3:
                k = int(cmd[1])
                if not reversed_flag:
                    arr.append(k)
                    rizz += len(arr) * k
                else:
                    arr.appendleft(k)
                    rizz += k
                total += k
            elif op == 2:
                reversed_flag ^= True
                rizz = total * len(arr) - rizz
            elif op == 1:
                if not arr:
                    print(rizz)
                    continue
                if not reversed_flag:
                    x = arr.pop()
                    arr.appendleft(x)
                    rizz = rizz - x * len(arr) + x
                else:
                    x = arr.popleft()
                    arr.append(x)
                    rizz = rizz - x + x * len(arr)
            print(rizz)

if __name__ == "__main__":
    solve()
```このソリューションは、効率的な appendleft および Popleft 操作をサポートするために、リストの代わりに両端キューを維持します。 の`reversed_flag`デクを物理的に逆転することを回避します。 更新中`rizz`は、シフトまたは反転された要素の新しい位置に正確な式を使用します。 これにより、操作ごとに O(1) が保証されます。
