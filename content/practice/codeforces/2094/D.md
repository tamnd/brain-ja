 **評価:** 1100
 **タグ:** 貪欲、文字列、2 つのポインター
 **解決時間:** 1 分 6 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 意図したドラムヒットの記録されたシーケンスが与えられます。各文字は左ヒットまたは右ヒットのいずれかです。 意図した各ヒットが固定の音長を生成するわけではありません。 代わりに、最終的に録音されたサウンドでは、単一のヒットが 1 つの文字または 2 つの同一の文字として聞こえる場合があります。 

したがって、元のシーケンス内の各文字は独立して短いブロックに展開されます。左のヒットは 1 つの「L」または 2 つの「L」のいずれかになり、右のヒットは 1 つの「R」または 2 つの「R」のいずれかになります。 すべての展開の後、結果の文字列が連結されて、観測される音声文字列になります。 

タスクは、観察された特定の文字列が、これらのルールに従って意図されたシーケンスから生成できるかどうかを判断することです。 

制約が十分に大きいため、すべての展開に対する 2 次またはバックトラッキングのアプローチは実行できません。 すべてのテスト ケースの合計の長さは最大 200,000 であるため、ソリューションは全体として線形時間で各文字を処理する必要があります。 

グループ化を尊重せずに文字ごとに一致させようとすると、単純な落とし穴が発生します。 たとえば、p = "LR" および s = "LLRL" の場合、貪欲な文字ごとのチェックでは部分一致が受け入れられるのが早すぎて、2 番目のグループがきれいに整列できないことを検出できない可能性があります。 

もう 1 つの一般的な失敗ケースは、p の 1 文字に対して s の文字を過剰に消費することです。 たとえば、p に 1 つの 'L' がある場合、s で 3 つの連続する 'L' を消費することは不可能ですが、不注意なポインタの実装ではグループ間の境界を検出できない可能性があります。 

主な困難は、グループ化を尊重しなければならないことです。p の各文字は、長さ 1 または 2 の s の連続ブロックに対応し、ブロックは異なる文字間でマージできません。 

## アプローチ

 強引なアイデアは、p の各文字を処理して 2 つの選択肢に分岐することです。それを 1 文字または 2 文字として展開し、結果の文字列をシミュレートして s と比較します。 これにより、最大 2^{|p|} という指数関数的な数の可能性が生まれますが、これは中程度の入力サイズでも不可能です。 

問題の構造は、列挙ではなく貪欲なマッチング戦略を示唆しています。 p の各文字は s の同一文字の連続ブロックを生成するため、両方の文字列を左から右にスキャンしてグループに一致させることができます。 

重要な観察は、p と s の両方を同じ文字の連続に圧縮できることです。 p の各ランは、同じ文字の s のランに対応する必要があり、各文字は独立して長さ 1 または 2 に拡張されるため、s のラン長は、p のラン長とそのラン長の 2 倍の間でなければなりません。 

したがって、問題はランレングスを順番に比較することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ランレングス貪欲マッチング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列 p と s の両方をランのシーケンスに圧縮します。各ランはペア (文字、長さ) です。 これが必要なのは、拡張によって隣接関係が維持され、実行境界のみが問題となるためです。 
2. p と s の実行数が異なる場合は、すぐに NO を返します。 各ヒットは正確に 1 つのランを生成するため、構造の不一致は拡張によって修正できません。 
3. p と s の対応する実行を順番に繰り返します。 
4. 実行のペアごとに、文字が一致することを確認します。 展開によって文字が変更されることはないため、異なる場合は直ちに NO を返します。 
5. p のランレングスを x、s を y とします。 p の各文字は 1 文字または 2 文字になるため、x 個の同一ヒットのランの合計展開は x ≤ y ≤ 2x を満たさなければなりません。 
6. 実行がこの不等式に違反する場合は、NO を返します。 
7. すべての実行が条件を満たしている場合は、YES を返します。 

### なぜ効果があるのか

p の各文字は独立して展開されますが、順序は保持されるため、最終的な文字列は、p の実行と 1 対 1 に対応するブロックの連結となります。 各ラン内で、元の各文字は 1 つまたは 2 つの同一の文字を提供します。つまり、ランの長さは、隣接するランに影響を与えることなく、一定の間隔内でのみ変更できます。 異なる文字間で実行をマージしたり分割したりすることはできないため、各実行を個別に検証することが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compress(s):
    runs = []
    i = 0
    n = len(s)
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        runs.append((s[i], j - i))
        i = j
    return runs

t = int(input())
for _ in range(t):
    p = input().strip()
    s = input().strip()

    rp = compress(p)
    rs = compress(s)

    if len(rp) != len(rs):
        print("NO")
        continue

    ok = True
    for (cp, lp), (cs, ls) in zip(rp, rs):
        if cp != cs:
            ok = False
            break
        if ls < lp or ls > 2 * lp:
            ok = False
            break

    print("YES" if ok else "NO")
```圧縮ステップにより、個々の文字ではなく、意味のある構造のみを比較することが保証されます。 各実行は文字とその頻度として保存されます。 

次に、メイン ループは、同じ実行パターンと有効な拡張境界という構造的制約を強制します。 小切手`ls < lp or ls > 2 * lp`独立して展開される各ヒットの許可された動作を直接エンコードします。 

## 実用的な例

 ### 例 1

 入力:

 | ステップ | 走る | 走る | チェック |

 | 1 | L:1 | L:2 | 1 ≤ 2 ≤ 2 |
 | 2 | R:1 | R:2 | 1 ≤ 2 ≤ 2 |

 すべての実行が一致するため、出力は YES になります。 

これは、すべてのヒットが最大限に拡大するケースを示しています。 

### 例 2

 入力:

 p = "LRLR"、s = "LRLR"

 | ステップ | 走る | 走る | チェック |
 | --- | --- | --- | --- |
 | 1 | L:1 | L:1 | |
 | 2 | R:1 | R:1 | |
 | 3 | L:1 | L:1 | |
 | 4 | R:1 | R:1 | |

 すべての実行は制約を満たしているため、「YES」です。 

これは、すべてのヒットが単一長である最小限の拡張を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は圧縮中に 1 回、比較中に 1 回アクセスされます。 
| スペース | O(n) | 圧縮が不可能な場合は最悪の場合にストレージを実行します。 

合計入力サイズはすべてのテスト ケースにわたって 2×10^5 によって制限されるため、線形ソリューションは時間制限内に問題なく収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、 s の実行内に余分な繰り返しがあり、局所的にはまだ有効であるように見えますが、グローバルにはアライメントが崩れる場合です。 たとえば、p = "LR"、s = "LLLR" となります。 圧縮により、p 個の実行 [(L,1),(R,1)] と s 個の実行 [(L,3),(R,1)] が生成されます。 最初の実行では 3 > 2 × 1 であるため制約が満たされないため、答えは NO になります。 アルゴリズムは、比較の実行中にこれを即座に検出します。 

もう 1 つのエッジ ケースは、境界を越えたマージがルール上不可能であるため、s の実行数が p よりも少ない場合です。 たとえば、p = "LRL" および s = "LLRR" です。 圧縮では p は 3 回の実行として与えられますが、s は 2 回の実行として与えられるため、アルゴリズムはすぐに拒否します。 これにより、文字間の結合が誤って許可されることがなくなります。
