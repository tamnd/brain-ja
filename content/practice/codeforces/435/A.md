 ## 解決策
 ## 問題の理解

 バス停には行列ができていますが、グループ分けされています。 各グループの人数は決まっており、順番に列に並びます。 最大でも運べるバスが来ます`m`グループ順に入場します。 次に並んでいるグループがバスに完全に乗りきれない場合、バスはすでに乗車している人を乗せたまま出発し、待っているグループ全員が次のバスを待ちます。 すべてのグループを輸送するのに必要なバスの数を計算するように求められます。 

入力により提供されるのは、`n`、グループの数、`m`、バスの容量、および配列`a`サイズの`n`各グループの人数を表します。 出力は単一の整数、つまり必要なバスの数です。 

制約は小さいです。`n`そして`m`これは、各グループの処理に必要な反復回数が最大 100 回であるため、単純なシミュレーションでも十分高速であることを意味します。 バス充填ロジックを慎重に処理する以外に、高度なデータ構造や最適化は必要ありません。 

エッジ ケースは、グループがバス容量と正確に等しい場合、または複数の小さなグループが 1 つのバスに正確に収まる場合に発生します。 たとえば、次の場合`m = 5`そしてグループのサイズは`[2, 3, 2]`の場合、最初のバスは最初の 2 つのグループ (2+3=5) を利用できますが、最後の 2 つのグループには新しいバスが必要です。 バスを満たすためにグループを「分割」しようとする不注意な実装では、誤った結果が生成されます。 

## アプローチ

 単純なアプローチは、プロセスを文字通りシミュレートすることです。空のバスから開始し、グループを反復処理し、適合する場合はグループをバスに追加し、グループが適合しない場合は常にバスを起動します。 グループごとにバスの残りスペースを確認し、バスを積むか新たにバスを発車するかを決定します。 制約によって許可されるため、これは簡単です。 のために`n=100`、各ステップは定数時間演算であるため、全体の複雑さは実質的に O(n) になります。 

問題は逐次的なものであるため、これより大幅に高速なアルゴリズムはありません。各グループの配置は前のバス占有率に依存します。 重要な洞察は、個人を管理する必要はなく、各バスの負荷の合計のみを管理する必要があるということです。 現在のバスの乗客数の累計を保持することで、グループが収容できない場合に新しいバスを運行するかどうかを決定できます。 これにより、各人を個別に管理する場合と比較して、潜在的なミスが削減されます。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`buses`少なくとも 1 つのバスと変数が必要なので、1 にします。`current_load`現在のバスの乗車人数を追跡するには、0 に設定します。 
2. 各グループを反復処理します。`g`配列内で`a`。 
3.追加する場合`g`に`current_load`を超えるだろう`m`、増分`buses`そしてリセット`current_load`これは、現在のバスの送信と新しいバスの開始をシミュレートします。 
4. グループサイズを追加する`g`に`current_load`新しく搭乗したグループを説明するため。 
5. すべてのグループを繰り返した後、`buses`必要なバスの数が含まれています。 

ここでの不変条件は、各ステップで、`current_load`決して超えない`m`、そして各グループは分割されることなくバスに満載されます。 私たちは「グループは一緒に過ごす」ルールを尊重し、バスを満員にしすぎないため、これは正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))

buses = 1
current_load = 0

for g in a:
    if current_load + g > m:
        buses += 1
        current_load = 0
    current_load += g

print(buses)
```常に少なくとも 1 つのグループが存在するため、このソリューションは 1 つのバスから始まります。 小切手`current_load + g > m`バスが過負荷にならないようにし、グループ制約を尊重します。 リセットする`current_load`新しいバスを開始した後、次のバスが正しくカウントされるようになります。 すべての演算は単純な整数演算であるため、オーバーフローの危険はありません。 

## 実用的な例

 **サンプル 1:**

 入力:`4 3`グループで`[2, 3, 2, 1]`| グループ | 現在の負荷 | バス |
 | --- | --- | --- |
 | 2 | 2 | 1 |
 | 3 | 3 (以前の 2+3>3 → 新しいバス) | 2 |
 | 2 | 2 | 2 |
 | 1 | 3 | 2 → 新しいバスは不要 |

 この表は、グループが適合しない場合は必ず新しいバスが開始されることを示しており、これは問題の説明と正確に一致します。 

**サンプル 2:**

 入力:`5 5`グループで`[1, 2, 3, 4, 5]`| グループ | 現在の負荷 | バス |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 3 | 1 |
 | 3 | 3+3>5 → 新しいバス | 2 |
 | 4 | 4 | 2 |
 | 5 | 5 | 3 |

 これは、大規模なグループが自然に新しいバスを開始し、小さなグループがバスがいっぱいになるまで蓄積されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各グループは 1 回だけ処理され、一定時間のチェックと更新が行われます。 |
 | スペース | お(1) | 入力配列のほかに維持される整数変数は 2 つだけです。 |

 以来`n`が最大 100 の場合、このアルゴリズムは 1 秒の制限時間内で快適に実行され、メモリ使用量は最小限に抑えられます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    buses = 1
    current_load = 0
    for g in a:
        if current_load + g > m:
            buses += 1
            current_load = 0
        current_load += g
    return str(buses)

# provided sample
assert run("4 3\n2 3 2 1\n") == "3", "sample 1"

# minimum-size input
assert run("1 1\n1\n") == "1", "minimum size"

# all groups equal to bus capacity
assert run("3 5\n5 5 5\n") == "3", "each group fits exactly one bus"

# groups smaller than bus capacity
assert run("4 10\n2 3 4 1\n") == "1", "all groups fit in one bus"

# groups that force alternating bus counts
assert run("5 5\n1 4 2 3 5\n") == "4", "mix of fits and overshoot"

# maximum-size groups for maximum bus
assert run("100 100\n" + "100 "*100 + "\n") == "100", "each group fills one bus"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1\n1`| 1 | 最小入力シナリオ |
 |`3 5\n5 5 5`| 3 | バス容量とまったく同じグループ |
 |`4 10\n2 3 4 1`| 1 | 複数の小グループが 1 台のバスに収まります |
 |`5 5\n1 4 2 3 5`| 4 | グループはバス間で分割する必要があります。 
|`100 100\n100 100 ...`| 100 | 大きな入力、最大サイズ |

 ## 特殊なケース

 単一のグループがバスを正確に埋めると、アルゴリズムはインクリメントされます。`buses`そしてすぐにグループを配置し、正確に数えます。 複数の小さなグループが一緒になってバスを満員にする場合、`current_load`に達するまで蓄積される`m`、その後初めて新しいバスが開始され、off-by-one エラーが防止されます。 最後のグループがバスを部分的に埋めた場合でも、アルゴリズムは引き続きバスをカウントします。`buses`1から始まります。
