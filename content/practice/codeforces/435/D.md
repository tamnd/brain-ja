 ## 解決策
 ## 問題の理解

 次の長方形グリッドが与えられます。`n`行と`m`列。 水平線と垂直線の各交差点、つまり各「ノード」は、黒または白のいずれかで色付けされます。 さらに、グリッド内のすべての単位正方形には対角線が描かれています。 三角形の各辺がグリッドの水平線、垂直線、または対角線のいずれかに沿って配置され、どの辺も黒いノードを通過しないように、3 つの白いノードによって形成されるすべての三角形を頂点として数えるよう求められます。 面積がゼロの三角形 (縮退三角形) は除外されます。 

入力により提供されるのは、`n`そして`m`に続く`n`一定の長さの文字列`m`からなる`0`と`1`どこで`0`は白いノードを示し、`1`は黒いノードを示します。 出力は有効な三角形の数です。 

この制約により、最大 400×400 のグリッドが許可されます。これは、最大 160,000 個のノードが存在することを意味します。 ホワイト ノードのすべてのトリプレットをチェックする単純なアプローチでは、およそ 160,000 回の select 3 = 10^15 操作が試行されますが、これは明らかに実行不可能です。 どのソリューションでも、すべてのトリプレットの反復を避ける必要があります。 代わりに、グリッドの構造を利用して有効な三角形を効率的に識別する必要があります。 

明らかではないエッジ ケースには、行全体または列全体が黒いノードを持つグリッドが含まれます。 たとえば、中央に黒い行がある 3×3 のグリッドでは、対角線に沿って多くの三角形ができなくなります。 もう 1 つの注意が必要なケースは、グリッドが完全に白い場合です。カウントは急速に増加し、インデックス付けまたは対角線の処理で 1 つずつずれたエラーがあると、間違った結果が生成されます。 2×2 の完全に白いグリッドには、1 つの正方形の対角線によって形成される三角形が 4 つありますが、対角線の接続性を無視する単純なアプローチではゼロが報告されます。 

## アプローチ

 ブルートフォースアプローチでは、白いノードのすべてのトリプレットを列挙し、それらが許可された線に沿って三角形を形成しているかどうか、および各辺に黒いノードがないかどうかを確認します。 各チェックでは、潜在的な三角形の辺に沿って歩く必要があり、O((n*m)^3) のオーダーの操作カウントが得られます。 これは、n、m が 400 までの場合は不可能です。 

より迅速な解決を可能にする重要な観察は、問題内のすべての三角形が「グリッドに整列」していることです。つまり、三角形の辺は水平、垂直、または 2 つの対角線の方向に沿っています。 したがって、三角形は、同じ行または列上の 2 つのノードによって形成される四角形、または対角に沿った直角三角形に含まれる必要があります。 これにより、三角形候補の数が大幅に減少します。 

グリッドは、水平、垂直、および 2 つの対角方向の 4 方向に個別に処理できます。 各ノードについて、そのノードまでの各方向に沿って連続する白いノードがいくつ存在するかを事前計算します。 次に、単位正方形または対角セグメントごとに、事前に計算された数を組み合わせることで、それを辺として使用する三角形の数を数えることができます。 これにより、すべてのノードが事前に計算された方向の長さに基づいて一定数の三角形に寄与するため、複雑さが O((n_m)^3) から O(n_m) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n*m)^3) | O(n*m) | 遅すぎる |
 | 最適 | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを解析し、2D ブール配列として表現します。`white[i][j]`どこ`True`は白いノードを示します。 
2. 4 つの方向 (左から右) で連続する白いノードの数を事前計算します。`horiz[i][j]`)、上から下(`vert[i][j]`)、左上から右下への対角線 (`diag1[i][j]`)、右上から左下への対角線 (`diag2[i][j]`）。 各セルについて、ノードが白の場合、ある方向のカウントは 1 にその方向の前のノードを加えたものになります。 それ以外の場合はゼロです。 これにより、三角形の辺を形成できる最大セグメント長にすばやくアクセスできます。 
3. グリッド内の各単位正方形を繰り返します。 各正方形は、その対角線とエッジを使用して複数の三角形に寄与できます。 事前に計算された方向の長さを使用して、水平垂直辺および対角線に沿って直角である三角形を数えます。 具体的には、水平辺と垂直辺に沿った直角三角形の場合、直角として特定のノードを持つ三角形の数は次のとおりです。`(horiz[i][j]-1) * (vert[i][j]-1)`。 
4. 対角三角形の場合は、対角線で形成される正方形を考慮します。 斜辺として対角線を使用する三角形は、対角線に沿った白いノードに 2 つの頂点を持たなければなりません。 使用する`diag1`そして`diag2`配列を使用して、その対角方向の有効な三角形の数を計算します。 
5. すべてのノードの 4 方向すべてからの寄与を合計します。 これにより、有効な三角形の総数が得られます。 

これが機能する理由: グリッドに沿って整列されたすべての三角形は、軸または対角に沿って直角になります。 セグメントの長さを事前に計算することにより、頂点のトリプレットを列挙することなく、すべての三角形を効率的にカウントできます。 反復では各直角ノードまたは対角斜辺ノードがカウントの「アンカー」とみなされるため、各三角形は 1 回だけカウントされます。 事前計算された配列では黒いノードを含む辺の長さが 0 であるため、三角形を見逃すことはなく、無効な三角形もカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [list(map(int, list(input().strip()))) for _ in range(n)]
white = [[cell == 0 for cell in row] for row in grid]

horiz = [[0]*m for _ in range(n)]
vert = [[0]*m for _ in range(n)]
diag1 = [[0]*m for _ in range(n)]
diag2 = [[0]*m for _ in range(n)]

for i in range(n):
    for j in range(m):
        if white[i][j]:
            horiz[i][j] = 1 + (horiz[i][j-1] if j>0 else 0)
            vert[i][j] = 1 + (vert[i-1][j] if i>0 else 0)
            diag1[i][j] = 1 + (diag1[i-1][j-1] if i>0 and j>0 else 0)
            diag2[i][j] = 1 + (diag2[i-1][j+1] if i>0 and j<m-1 else 0)

total = 0
for i in range(n):
    for j in range(m):
        if white[i][j]:
            total += (horiz[i][j]-1)*(vert[i][j]-1)
            total += (diag1[i][j]-1)*(diag2[i][j]-1)

print(total)
```まずグリッドを読み取って前処理して、白いノードのブール配列を作成します。 次に、連続する白いノードの 4 つの方向のカウントを計算します。 三角形を数えるときは、セグメントの長さが 1 では三角形の辺を形成できないため、方向の数から 1 を減算します。 組み合わせ`(horiz[i][j]-1)*(vert[i][j]-1)`現在のノードが直角であるすべての直角三角形をカウントします。 同様に、`(diag1[i][j]-1)*(diag2[i][j]-1)`対角線に沿って三角形を数えます。
