 ## 解決策
 ## 問題の理解

 開始日と終了日によって定義される長い連続期間が与えられ、この期間内で祝日のリストも受け取ります。 各休日は、毎年決まった月日に繰り返されるか、特定の年に 1 回だけ発生します。 

人事部門は、期間全体を通じて、固定平日 2 日を週末として宣言したいと考えています。 平日がこれら 2 つの選択された週末のいずれでもない日は、その日が祝日でない限り、営業日となります。 目標は、期間全体にわたって稼働日数ができるだけ多くなるように、週末と平日のペアを選択することです。 

重要な問題は、祝日と日付が閏年を含むグレゴリオ暦の広い範囲にわたるため、簡略化されたカレンダーや事前に計算された小さな周期に頼ることができないことです。 すべての日付をその平日に正しくマッピングし、発生回数を正確にカウントする必要があります。 

範囲は 1900 から 3000 で、暦日の観点からは大きいですが、それでも十分に小さいため、1 日ごとのシミュレーションが実行可能です。 すべてのテスト ケースの合計日数は約 4000 年、つまり約 150 万日で制限されるため、テスト ケースごとの線形スイープは許容されます。 

微妙な問題は、繰り返される年次休暇をどのように処理するかです。 「DD-MM」休日は毎年適用されますが、その年にその日付が存在する場合にのみ適用されるため、2 月 29 日は閏年にのみ表示されます。 毎年 2 月 29 日を盲目的に適用する単純なアプローチでは、無効な日付と破損した平日の調整が発生します。 

もう 1 つの一般的な失敗例は、平日のペアの辞書編集的な順序付けです。 この問題では順序付きペアが明示的に区別されるため、「金曜日土曜日」は「土曜日金曜日」と同じではなく、最初に最初の曜日名によって比較が行われ、次に 2 番目の曜日名によって比較が行われます。 

## アプローチ

 ブルートフォース戦略は簡単です。異なる平日の 21 個の順序付きペアをすべて試してみます。 各ペアについて、間隔内の毎日をシミュレートし、それが週末か休日かを判断し、稼働日をカウントします。 最後に、最大数が得られるペアを選択します。 

これが機能するのは、曜日のペアが固定されると、毎日が独立して最終的なカウントに寄与するためです。 評価あたりのコストは、範囲内の日数と休日の数に比例します。 テスト ケースあたり最大約 150 万日、平日のペアが 21 であるため、最悪の場合、テスト ケースあたり約 3,000 万日のチェックが行われることになり、T が最大 400 になると、これは非常に遅くなります。 

重要な点は、実際にはペアごとにカレンダー全体を再スキャンする必要がないということです。 平日ごとに、範囲内に何回出現するかを事前に計算できます。 同様に、各平日について、その平日に休日が何日あるかをカウントすることもできます。 これらのカウントが分かれば、任意のペアの寄与は単純な算術式になります。 

平日を週末として選択した場合、その平日が出現するたびに 1 つの営業日が削除されます。 したがって、候補のペア (a、b) の場合、削減の合計は、平日 a に平日 b を加えた日数から、それらの平日に既に含まれている休日の数を引いたものになります。これは、休日はすでに非稼働日であり、休業日として二重にカウントされるべきではないためです。 

したがって、問題は、日付範囲にわたる平日の頻度を計算し、定数時間で 21 個のペアすべてを評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(21 · D) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとに O(D + H + 1) | お(1) | 承認済み |

 ここで D は間隔の日数です。 

## アルゴリズムのチュートリアル

 ## 事前計算

1. 両方の入力日付を、01-01-1900 などの固定参照日から始まる絶対日インデックスに変換します。 これにより、カレンダーを単純な整数の線として扱うことができます。 変換では、グレゴリオ暦を使用して閏年を考慮する必要があります。そうしないと、平日の調整が長い範囲にわたって変動します。 
2. 変換中に、既知の基本曜日からの現在のオフセットを維持することにより、各日付の曜日も計算します。 標準の CF カレンダー設定では 1900 年 1 月 1 日が月曜日であるため、1 日増えるごとに曜日が周期的にシフトします。 

## 平日の頻度を数える

 1. 開始日のインデックスから終了日のインデックスまで反復し、各エントリが間隔内で各平日が何回出現するかをカウントする頻度配列 freq[7] を維持します。 この 1 つのパスで、カレンダーの構造分布全体がすでにキャプチャされています。 
2. 各休日について、毎年の場合は実際の日付に変換し、固定の場合は直接変換します。 休日が間隔内にある場合は、その曜日を決定し、別の配列 hol[7] を増分します。 これにより、各平日と重なる休日の数がわかります。 

## 平日ペアの評価

 1. 個別の平日の順序付きペア (i、j) ごとに、total_days から i と j を週末として選択することによって除去された寄与分を差し引いた総稼働日数を計算します。 
2. 平日によって寄与される削除はその全頻度ですが、その平日にすでにカウントされている休日を差し引く必要があります。 したがって、実効損失は、freq[i] + freq[j] マイナス hol[i] - hol[j] です。 
3. 最大稼働日数でペアを追跡します。 複数のペアが同じ結果を生成する場合は、曜日名の順序で辞書順に最小のペアを選択します。 

## なぜ機能するのか

 重要な不変条件は、平日間の相互作用は固定された集計カウントのみであるということです。 間隔内に各平日が何日存在し、そのうちの何日がすでに休日になっているかがわかったら、週末の日の選択はすべて、これらの独立したバケットから減算されるだけです。 曜日の分類を超えて個々の日の間に依存関係はないため、カレンダーを 7 つのカウンタに折りたたむと、必要な情報がすべて保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

WEEK = ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"]
idx = {w: i for i, w in enumerate(WEEK)}

# leap year check
def is_leap(y):
    return (y % 4 == 0 and y % 100 != 0) or (y % 400 == 0)

mdays = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

def to_day(d, m, y):
    # convert to days since 01-01-1900
    res = 0
    for yy in range(1900, y):
        res += 366 if is_leap(yy) else 365
    for mm in range(1, m):
        res += mdays[mm - 1]
        if mm == 2 and is_leap(y):
            res += 1
    res += d - 1
    return res

def weekday_of(day_index):
    return (day_index + 0) % 7  # 01-01-1900 assumed Monday

def parse_date(s):
    parts = s.strip().split("-")
    if len(parts) == 3:
        return int(parts[0]), int(parts[1]), int(parts[2])
    else:
        return int(parts[0]), int(parts[1]), None

def expand_holiday(dd, mm, yy, start_y, end_y):
    if yy is not None:
        if start_y <= yy <= end_y:
            return [(dd, mm, yy)]
        return []
    res = []
    for y in range(start_y, end_y + 1):
        if mm == 2 and dd == 29 and not is_leap(y):
            continue
        res.append((dd, mm, y))
    return res

def main():
    T = int(input())
    for _ in range(T):
        s, e = input().split()
        d1, m1, y1 = map(int, s.split("-"))
        d2, m2, y2 = map(int, e.split("-"))

        start = to_day(d1, m1, y1)
        end = to_day(d2, m2, y2)

        freq = [0] * 7
        hol = [0] * 7

        # count weekdays in range
        for d in range(start, end + 1):
            freq[d % 7] += 1

        H = int(input())
        holidays = []

        for _ in range(H):
            s = input().strip()
            dd, mm, yy = parse_date(s)
            holidays.append((dd, mm, yy))

        start_year = y1
        end_year = y2

        # process holidays
        for dd, mm, yy in holidays:
            if yy is not None:
                if start_year <= yy <= end_year:
                    di = to_day(dd, mm, yy)
                    if start <= di <= end:
                        hol[di % 7] += 1
            else:
                for y in range(start_year, end_year + 1):
                    if mm == 2 and dd == 29 and not is_leap(y):
                        continue
                    di = to_day(dd, mm, y)
                    if start <= di <= end:
                        hol[di % 7] += 1

        total_days = end - start + 1

        best = -1
        best_pair = (0, 1)

        for i in range(7):
            for j in range(7):
                if i == j:
                    continue
                removed = freq[i] + freq[j] - hol[i] - hol[j]
                working = total_days - removed
                name_i = WEEK[i]
                name_j = WEEK[j]
                if working > best or (working == best and (name_i, name_j) < (WEEK[best_pair[0]], WEEK[best_pair[1]])):
                    best = working
                    best_pair = (i, j)

        print(WEEK[best_pair[0]], WEEK[best_pair[1]])

if __name__ == "__main__":
    main()

 ## 特殊なケース

 最初のエッジケースは閏日です。 単純な拡張で 2 月 29 日をすべての年で有効なものとして扱うと、うるう年以外では 2 月以降に平日インデックスが誤ってシフトします。 このアルゴリズムは、年間休日を拡張するときに無効な閏日を明示的にスキップすることでこれを回避します。 

もう 1 つの特殊なケースは、日付範囲が週の半ばに開始または終了する場合です。 曜日の頻度は正確な開始インデックスから反復して計算されるため、位置合わせについての仮定は行われず、部分的な週も自然に処理されます。 

3 番目のケースは、すべての休日が同じ平日に該当し、後で週末として選択される場合です。 そのような状況では、hol 配列はこれらの重複を正しく減算し、それらの日が休日と週末の両方として二重にペナルティを受けることがないようにします。
