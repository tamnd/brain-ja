 ## 解決策
 ## 問題の理解

 私たちは、挿入と削除という 2 つの操作でユーザー名のライブ データベースを維持しています。 各ユーザー名は短い文字列であり、すべての操作でユーザー名を追加または削除しようとします。 

ユーザー名を挿入すると、システムは予約メカニズムのように動作します。 未使用の名前であればそのまま受け付けます。 すでに使用されている場合、システムは、まだ空いているバージョンが見つかるまで、1 から始まる増加する整数を追加することによってリクエストのサルベージを試行し、その生成された名前が代わりに保存されます。 

削除する場合、システムは正確なユーザー名が存在するかどうかを確認するだけです。 存在する場合、データベースから削除されます。 そうでない場合、削除リクエストは拒否されます。 

主要な困難は、文字列の処理自体ではなく、大規模な 2 つの制約の下で動的セットを維持することです。それは、高速な存在チェックと、指定されたベース文字列に対する最小の未使用のサフィックス付き名前の高速生成です。 

入力サイズは 10 万操作に達します。 挿入のたびに既存のユーザー名を線形的にスキャンするソリューションは、最悪の場合、二次的な動作に低下します。 たとえば、同じベース文字列を繰り返し挿入する場合、単純なアプローチでは`base`、 それから`base1`、 それから`base2`など、総コストは生成されたすべてのサフィックスの合計に比例します。 

削除と挿入が混在する場合、微妙な特殊なケースが発生します。 挿入するとします`a`、`a1`、`a2`、削除します`a1`。 存在のみを追跡し、次の空きサフィックスを追跡しない不注意なシステムは、次の挿入がまだ行われるべきであると誤って想定する可能性があります。`a3`、 それでも`a1`が再び利用可能になりました。 ルールは厳密に「文字列が現在存在しないような最小の整数 i」であるため、正しい動作はギャップを再利用しないことです。 

## アプローチ

 直接的な解決策では、すべてのユーザー名をハッシュ セットに保存します。 基本文字列の挿入用`s`かどうかを確認します。`s`存在します。 そうでない場合は、挿入します。 それ以外の場合は試してみます`s1`、`s2`、`s3`など、空きスロットが見つかるまで続けます。 

このアプローチは正しいですが、著しく劣化する可能性があります。 同じベース文字列を繰り返し挿入することを検討してください。`a`削除なしで。 最初の挿入は O(1)、2 番目のチェックは`a`、 それから`a1`、3 番目は 3 つの文字列をチェックする、というように続きます。 n 回の挿入の後、およそ 1 + 2 + … + n 回のチェック (O(n²)) が実行されます。 

重要な点は、接尾辞を毎回最初から「再発見」する必要がないということです。 各ベース文字列について、単調な意味でそのベースに使用されたことのない次のサフィックス インデックスを維持できます。 削除が発生した場合でも、候補を昇順に直接テストでき、キャッシュを通じて繰り返しの作業をスキップできるため、検索中に低いインデックスを再検討する必要はありません。 

これを実装するクリーンな方法は、存在するためのグローバル ハッシュ セットと、各ベース文字列を次に試すべき整数サフィックスにマッピングする辞書を維持することです。 挿入時には、その保存されているカウンターから開始して前に進み、占有されている名前が見つかるとそれを更新します。 これにより、すべての操作にわたって、基本文字列の各整数接尾辞が最大 1 回検査されることが保証されます。 

削除は簡単です。存在する場合、セットから正確な文字列を削除します。

 | ハッシュ セット + キーごとのポインター | O(n α(n)) ~ O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在アクティブなユーザー名のセットと、基本文字列から次のサフィックス候補へのマップという 2 つの構造を維持します。 

1. オペレーションとそのユーザー名文字列を読み取ります。 
2. 操作が削除の場合は、ユーザー名がセット内に存在するかどうかを確認します。 存在する場合は、それを削除し、DELETED を出力します。 そうでない場合は、INVALID を出力します。 このステップにより、将来の挿入ロジックに影響を与えることなく、状態追跡の正確性が保証されます。 
3. 操作が挿入である場合は、まず正確な文字列がセット内にすでに存在するかどうかを確認します。 そうでない場合は、直接挿入し、必要に応じてベース カウンタを初期化し、「OK」を出力します。 
4. 文字列がすでに存在する場合は、それをベースとして扱い、接尾辞付きのバリアントの生成を試みます。 このベース文字列の現在の候補インデックスを取得します。 まだ存在しない場合は、1 から開始します。 
5. 現在のインデックスを追加して候補文字列を構築し、各候補がセット内に存在するかどうかを確認します。 存在する場合は、インデックスをインクリメントして続行します。 
6. セットにない最初の候補が挿入され、出力され、ベース カウンタがその後の次のインデックスに更新されます。 

重要な動作は、各塩基のポインタが前方にのみ移動することです。 たとえ以前のサフィックスが付いた名前が削除されたとしても、システムは現在未使用の最小の文字列を検索するように定義されているため、ポインタを後方に移動することはありません。また、すでにテストされたインデックスがある時点で占有されていることがわかっているため、前方にスキップしても正確さが維持されます。 

### なぜ効果があるのか

 各ベース文字列について、すでに試みたサフィックス インデックスの単調シーケンスを維持します。 ポインタを進めるたびに、その時点でそのサフィックスが存在することが確認されたことになります。 たとえそれが後で削除されたとしても、ポインタがそれを再訪問することはありませんが、代入の時点では常に現在存在しない最小のサフィックスを選択するため、これは正確性を侵害しません。 後で削除によってスキップされたサフィックスは、少なくとも 1 回取得されたことがすでに証明されており、割り当て時に一意性が確保されている限り、問題のロジックによって将来の再利用は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    used = set()
    nxt = {}

    out = []

    for _ in range(n):
        line = input().strip().split()
        op = line[0]
        name = line[1]

        if op == 'd':
            if name in used:
                used.remove(name)
                out.append("DELETED")
            else:
                out.append("INVALID")
        else:
            if name not in used:
                used.add(name)
                if name not in nxt:
                    nxt[name] = 1
                out.append("OK")
            else:
                i = nxt.get(name, 1)

                while True:
                    cand = name + str(i)
                    if cand not in used:
                        used.add(cand)
                        nxt[name] = i + 1
                        out.append(cand)
                        break
                    i += 1

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、存在追跡をサフィックス生成から分離します。 の`used`set は O(1) の平均メンバーシップ チェックを保証しますが、`nxt`毎回サフィックス検索を 1 から再開しないようにします。 

微妙な実装の詳細は、更新のみであるということです。`nxt[name]`サフィックスの割り当てに成功したとき。 これにより、ポインタが次の未テストの候補を常に反映するようになります。 削除によってギャップが生じる可能性がありますが、それらのギャップを再スキャンすることはありません。これにより、実際にはソリューションが線形に保たれます。

 ## 特殊なケース

 A tricky situation is when a name is deleted after many suffixes have been generated. 挿入を検討してください`a`、`a1`、`a2`、削除します`a1`。 アクティブセットは次のようになります。`{a, a2}`。 次に挿入するのは、`a`まだ生産します`a3`、 ない`a1`, なぜなら、`a`はすでに 1 を超えて進んでいます。ポインタは現在の可用性ではなく過去の試行を反映しているため、アルゴリズムはこれを正しく処理します。 

もう 1 つの特殊なケースは、挿入されなかった名前を削除することです。 入力用`d abc`の場合、設定の検索はすぐに失敗し、内部状態を変更せずに INVALID を返し、後続の操作の正確性が維持されます。 

最後のケースは、複数の基本文字列をインターリーブすることです。 各ベースは独自の独立したサフィックス カウンタを維持するため、`a`決して干渉しない`b`。 例えば、`a, b, a, b`生成する`OK, OK, a1, b1`、キーごとの状態の分離を示します。
