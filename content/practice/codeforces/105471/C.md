 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた文字列が与えられます。 インデックスのペアを見てみましょう$(l, r)$と$l \le r$。 このような各ペアは部分文字列を定義します$s[l..r]$ただし、エンドポイントが互いに素である場合にのみ受け入れられます。つまり、$\gcd(l, r) = 1$。 

受け入れられたすべてのペアは、正確に 1 つの文字列 (これら 2 つのエンドポイント間の部分文字列) に寄与します。 同じ部分文字列が複数の異なる有効なペアから出現する場合でも、それは 1 回だけカウントされます。 このタスクは、有効な互いに素なエンドポイントのペアから少なくとも 1 回出現するすべての個別の部分文字列の長さの合計を計算することです。 

キー オブジェクトは文字列のすべての部分文字列ではなく、エンドポイント インデックスが互いに素になるようにエンドポイントを選択できる部分文字列のみです。 したがって、出力は、これらの有効なエンドポイントのペアによって生成されるすべての個別の文字列の和集合の長さの合計になります。 

制約$n \le 100000$ペアまたは部分文字列の二次列挙を除外します。 候補部分文字列の数は潜在的に$O(n^2)$、各ペアを個別にチェックすることすら不可能です。 どのソリューションも算術条件の構造を利用する必要があります$\gcd(l, r) = 1$すべての部分文字列を明示的に反復処理することは避けてください。 

すべての部分文字列が有効である、または有効性が部分文字列の内容のみに依存すると仮定すると、微妙な失敗のケースが発生します。 たとえば、次のような文字列では`"abca"`、繰り返される部分文字列が多数ありますが、互いに素なインデックスのペアに位置合わせされたもののみが対象となります。 もう 1 つのよくある間違いは、部分文字列が一度有効であれば、その内部部分文字列もすべて有効であると想定することです。 有効性は内部構造ではなくエンドポイントに関連付けられているため、これは false です。 

サンプル入力はこれを厳密に示しています。すべてではありません。$n(n+1)/2$部分文字列がカウントされ、慎重に選択されたサブセットのみが最終的な合計に寄与します。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべてのペアを反復処理します$(l, r)$、どうかを確認してください$\gcd(l, r) = 1$、存在する場合は部分文字列を抽出します$s[l..r]$。 これらの文字列をハッシュ セットに挿入し、最後にすべての一意のエントリの長さを合計します。 これは定義に直接従っているため、正しいです。 

問題は複雑さです。 がある$O(n^2)$ペアと部分文字列の抽出コスト$O(n)$最適化されていない場合、抽出ごとに問題が発生し、3 次の最悪のケースが発生します。 完全な部分文字列のコピーを避けるためにハッシュを使用したとしても、gcd チェックの数だけでも約$5 \cdot 10^9$いつ$n = 10^5$、それは限界をはるかに超えています。 

重要な点は、重要なのは有効なエンドポイント ペアのセットだけであるということです。 有効な各ペアは、正確に 1 つの部分文字列に寄与します。 したがって、問題は次のようになります: すべてのペアを列挙する$(l, r)$と$\gcd(l, r)=1$、それぞれを部分文字列にマップし、結果の文字列の和集合を計算します。 

これにより、焦点は部分文字列からインデックス ペア上の算術構造に移ります。 すべてのペアを反復する代わりに、数論的な構造を使用します。$r$、有効な$l$まさにそれらです$[1, r]$と互いに素である$r$。 これは、素因数に対する包含-排他を使用して生成できます。$r$これにより、有効なペアの数が実際に管理可能になります。$r$異なる素因数にのみ依存します。 

すべての有効なペアを大まかに列挙できたら、$O(n \log n)$、残りの困難は部分文字列の重複除去です。 そのために、接尾辞オートマトンは、次のすべての部分文字列のコンパクトな表現を提供します。$s$。 各有効なペアはオートマトン内のパスに対応し、少なくとも 1 つの有効な間隔からどの状態 (つまり部分文字列) に到達できるかをマークします。 答えは、到達可能なすべての個別の部分文字列の長さの合計になります。

 ## アルゴリズムのチュートリアル

 ソリューションを 2 つの部分に分けます。有効なエンドポイント ペアを効率的に生成する部分と、サフィックス オートマトンを使用してそれらのペアから個別の部分文字列を蓄積する部分です。 

1. 文字列の接尾辞オートマトンを構築します$s$。 

この構造は、すべての個別の部分文字列をコンパクトに表現し、各部分文字列を明示的に実体化するのではなく、状態または遷移パスとして扱うことができます。 オートマトンは$O(n)$州。 
2. 各右端点について$r$、すべてのインデックスを生成します$l \le r$そのような$\gcd(l, r)=1$。 

全部チェックするのではなく、$l$、の素因数に対して包含-排他を使用します。$r$。 素因数を共有しないすべての数値$r$は有効であり、これらは、素数の倍数を減算し、素数の積の積の交差を加算し直すことによって列挙できます。 
3. 有効なペアごとに$(l, r)$、部分文字列を見つけます$s[l..r]$サフィックスオートマトンの内部。 

位置に応じた状態からスタート$l$オートマトンのサフィックス構造内で、長さに達するまでトランジションを 1 文字ずつ拡張します$r-l+1$。 到達した状態はその部分文字列を表します。 
4. 到達した状態を「アクティブ」としてマークします。 

これは、少なくとも 1 つの有効な共素エンドポイント ペアがこの部分文字列を生成することを意味します。 
5. すべてのペアを処理した後、各アクティブ状態の寄与を計算します。 

接尾辞オートマトンの各状態は、その長さが連続した範囲を形成する部分文字列のセットを表します。 状態がアクティブな場合、その区間内のすべての部分文字列の長さの合計を加算します。$[len(link[v]) + 1, len(v)]$。 

### なぜ効果があるのか

 問題内のすべての有効な部分文字列は、次の形式の 1 つの文字列です。$s[l..r]$どこ$(l, r)$は素です。 接尾辞オートマトンは、それぞれの個別の文字列が 1 つの状態に正確に対応することを保証します。 少なくとも 1 つの有効な生成ペアの存在に基づいて状態をマークすると、生成される異なる共素ペアの数に関係なく、個別の部分文字列を 1 回ずつカウントすることが保証されます。 接尾辞オートマトン状態の間隔プロパティにより、状態の長さの範囲にわたる合計により、重複することなくすべての部分文字列の長さが正しく集計されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Suffix Automaton implementation
class SAM:
    def __init__(self, s):
        self.next = [{}]
        self.link = [-1]
        self.length = [0]
        self.last = 0

        for ch in s:
            self.extend(ch)

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def sieve_factors(n):
    spf = list(range(n + 1))
    for i in range(2, n + 1):
        if spf[i] == i:
            for j in range(i * i, n + 1, i):
                if spf[j] == j:
                    spf[j] = i
    return spf

def get_primes(x, spf):
    ps = set()
    while x > 1:
        ps.add(spf[x])
        x //= spf[x]
    return list(ps)

def main():
    n = int(input())
    s = input().strip()

    sam = SAM(s)

    spf = sieve_factors(n)

    active = [False] * len(sam.next)

    for r in range(1, n + 1):
        primes = get_primes(r, spf)
        bad = []

        # inclusion-exclusion subsets
        m = len(primes)
        for mask in range(1, 1 << m):
            mult = 1
            bits = 0
            for i in range(m):
                if mask >> i & 1:
                    mult *= primes[i]
                    bits += 1
            if mult > r:
                continue
            bad.append((mult, bits))

        bad_l = set()
        for mult, bits in bad:
            for l in range(mult, r + 1, mult):
                bad_l.add(l)

        for l in range(1, r + 1):
            if l in bad_l:
                continue
            # mark substring s[l:r]
            cur = 0
            ok = True
            for i in range(l - 1, r):
                c = s[i]
                if c not in sam.next[cur]:
                    ok = False
                    break
                cur = sam.next[cur][c]
            if ok:
                active[cur] = True

    # propagate activity upward
    order = sorted(range(len(sam.next)), key=lambda x: sam.length[x], reverse=True)
    for v in order:
        if sam.link[v] != -1:
            active[sam.link[v]] |= active[v]

    ans = 0
    for v in range(1, len(sam.next)):
        if not active[v]:
            continue
        l = sam.length[sam.link[v]] + 1
        r = sam.length[v]
        ans += (l + r) * (r - l + 1) // 2

    print(ans)

if __name__ == "__main__":
    main()
```このコードは、すべての部分文字列のサフィックス オートマトンを構築し、各右エンドポイントの素因数に対する包含/除外を使用して、有効なエンドポイントのペアを列挙します。 有効な各部分文字列がオートマトン内でトレースされ、その最終状態がマークされます。 アクティビティは、状態によって表されるすべての部分文字列が含まれるように上方に伝播されます。 最後に、各アクティブ状態は、その表現された部分文字列範囲の長さの合計に寄与します。 

微妙な実装の詳細は、部分文字列のトラバーサルがオートマトン内で直接行われることですが、この単純な形式ではコストが高くなります。 より最適化されたバージョンでは、位置リンクを事前に計算するか、追加のブックキーピングを備えたサフィックスリンク ツリーを使用して、反復的な走査を回避します。

 ## 特殊なケース
