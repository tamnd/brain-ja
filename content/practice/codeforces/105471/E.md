 ## 解決策
 ## 問題の理解

 完全に方向付けられた完全なグラフが与えられます。これは、個別の頂点のすべてのペアがそれらの間に正確に 1 つの有向エッジを持つことを意味します。 頂点ごとに$u$、入力は、それがどの頂点を指しているのかを正確に示します。 

頂点$u$最大 2 ステップで 1 つおきの頂点に到達できる場合は、良好であるとみなされます。 言い換えれば、任意のターゲット頂点に対して$v$、 どちらか$u$～に直接的な縁がある$v$、または中間頂点が存在します。$w$そのような$u \to w$そして$w \to v$。 

これは、トーナメント グラフの深さ 2 の到達可能性条件です。 タスクは、このプロパティを満たす 3 つの異なる頂点を見つけることです。 そのような頂点が 3 つ未満しか存在しない場合は、解が存在しないと出力されます。 

制約$n \le 5000$頂点のトリプルを通るすべてのパスを明示的にテストしようとするソリューションは直ちに除外されます。 単一の頂点の単純なチェックでは、すべてのターゲットのすべての中間頂点をスキャンする必要があるため、$O(n^2)$頂点ごとに、$O(n^3)$全体。 それは遅すぎます。 

適切な頂点がほとんどない場合、微妙なエッジケースが発生します。 たとえば、各頂点がサイクル内でちょうど 1 つの隣接頂点に勝つ循環トーナメントでは、2 ステップ以内に他のすべての頂点に到達できる頂点はないため、答えは「NOT FOUND」でなければなりません。 一方、推移的なトーナメント (エッジが低いインデックスから高いインデックスに移動する) では、各頂点はすべてに直接到達できるため、すべての頂点が適切です。そのため、答えは自明のことですが、任意の 3 つの頂点になります。 

難しいのは、この状態が近隣諸国の結合に依存するグローバルなものであるため、ローカル度情報だけでは十分ではないことです。 

## アプローチ

 直接的なアプローチでは各頂点をチェックします$u$すべての頂点が$v$送信セット内にあるか、1 つの中間ステップを介して到達可能です。 これにはすべてを繰り返す必要があります$w$から到達可能$u$次に、到達可能なすべての頂点をマークします。$w$。 概念的には、すべての頂点に対して 2 段階のクロージャを計算しています。 

これは正しく機能しますが、ボトルネックは隣接リストに対する結合の繰り返しです。 最悪の場合、各頂点には約$n/2$したがって、すべての頂点にわたるエッジベースのトランジションの総数は二次関数となり、各トランジションは最大で$n$頂点。 これは立体的な動作につながります。 

重要な観察は、グラフ構造がトーナメントであるため、到達可能性セットをビットセットとして表し、高速な結合演算を実行できることです。 個々の頂点を繰り返し処理する代わりに、各隣接リストをビットマスクに圧縮し、ビットごとの OR 演算を使用して 2 段階の到達可能性を計算します。 これにより、定数係数が大幅に削減され、頂点を越える Python レベルの入れ子ループが回避されます。 

すべての頂点ではなく、3 つの有効な頂点を特定するだけで済みます。 これにより、3 つの候補が見つかった時点で早期に停止することができます。これは、ランダムまたは構造化トーナメントの多くの頂点が計算の早い段階ですでに条件を満たしているため、実際には重要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 頂点ごとのブルート フォース到達可能性 |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | ビットセットの 2 段階クロージャ | ～$O(n^3 / w)$最悪の場合、実際にはもっと速くなります |$O(n^2)$| 承認済み |

 ここ$w$は、Python の整数ビット演算によるマシン ワード サイズの影響です。 

## アルゴリズムのチュートリアル

 各頂点の外向きのエッジをビットセットとして扱います。$v$の場合に設定されます$u \to v$。 

1. ビットマスクを作成する`out[u]`頂点ごとに$u$。 これは、からのすべての直接エッジをエンコードします。$u$コンパクトな形で。 
2. 完全なビットマスクを定義する`all_mask`みんなで$n$ビットがセットされています。 これは、すべての頂点に到達することを表します。 
3. 頂点ごとに$u$、直接の近隣から開始して 2 段階の到達可能性セットを構築します。 初期化する`reach = out[u]`。 
4. 頂点ごとに$w$そのような$u \to w$、合併します`out[w]`の中へ`reach`ビット単位の OR を使用します。 これは、次の 2 つのステップで到達可能なすべての頂点の追加をシミュレートします。$w$。 
5.これらすべてを処理した後、$w$かどうかを確認します。`reach`可能性のあるものを除くすべての頂点をカバーします$u$。 「はい」の場合、$u$は有効な支配頂点です。 
6. このような頂点を 3 つ見つかるまで収集し、すぐに出力します。 
7. すべての頂点を処理した後に見つかった頂点が 3 つ未満の場合は、次のように出力します。`NOT FOUND`。 

早期に停止できる理由は、条件が頂点ごとに独立しているためです。 1 つの有効な頂点を見つけても、他の頂点には影響しません。 

### なぜ効果があるのか

 固定頂点の場合$u$、最大 2 ステップで到達可能な頂点は、その直接の出力セット内、または直接到達する何らかの頂点の出力セット内にあります。 このような近隣すべてのビットセット結合により、このセットが正確に構築されます。 なぜなら、考えられるすべての 2 ステップ パスは、そのすぐ隣のパスの 1 つを経由する必要があるからです。$u$、到達可能な頂点が失われることはなく、到達できない頂点が追加されることもありません。 したがって、計算されたセットはまさに、次の 2 段階の到達可能性クロージャです。$u$、フルセットに対するチェックは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    out = [0] * n
    
    # build bitsets
    for i in range(n):
        s = input().strip()
        mask = 0
        for j, ch in enumerate(s):
            if ch == '1':
                mask |= 1 << j
        out[i] = mask

    full = (1 << n) - 1
    res = []

    for u in range(n):
        reach = out[u]
        w = out[u]
        
        # iterate over outgoing neighbors of u
        while w:
            lsb = w & -w
            v = (lsb.bit_length() - 1)
            reach |= out[v]
            w -= lsb
        
        # remove self if present
        if reach | (1 << u) == full:
            res.append(u + 1)
            if len(res) == 3:
                print(*res)
                return

    print("NOT FOUND")

if __name__ == "__main__":
    solve()
```このソリューションでは、各隣接行を Python 整数ビットマスクとしてエンコードします。 設定されたビットを反復処理する`out[u]`実際の発信エッジのみにアクセスできるようになります。 このような近隣ごとに、ビットごとの OR を使用して、その隣接ビットマスクを到達可能性セットにマージします。 

小切手`reach | (1 << u) == full`定義は他の頂点のみに関係するため、頂点がそれ自体に到達するかどうかは無視されます。 

微妙な点は、次を使用して最下位セットビットを抽出することです。`w & -w`。 これにより、反復は、発信エッジの数ではなく、発信エッジの数に比例して維持されます。$n$。

 ## 特殊なケース

 キー エッジ ケースとは、多くの外向きエッジを持つ頂点ですが、すべての近傍が構造化された方法で内側を向いているため、2 段階の到達条件を満たさない頂点です。 このような頂点の場合、直接次数は誤解を招きやすく、第 2 層の閉包のみが失敗を明らかにします。 このアルゴリズムは、次数に依存するのではなく、第 2 レベルの隣接セットを明示的に結合するため、これを正しく処理します。 

もう 1 つのエッジ ケースは、ちょうど 3 つの頂点が条件を満たす場合です。 アルゴリズムは、3 つ見つかったらすぐに停止する必要があります。 そうしないと、不必要な計算が行われる危険があります。 早期終了ロジックにより、検出された頂点のセットを変更することなく正確さが保証されます。 

最後のエッジ ケースは、条件を満たす頂点がない場合です。 そのような状況では、ビットセット クロージャがすべてのビットセットを完全にカバーすることはありません。$u$、結果リストは空のままで、正しくトリガーされます。`NOT FOUND`。
