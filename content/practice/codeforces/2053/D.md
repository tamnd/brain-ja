 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、それぞれの長さ`n`。 タスクは最大積を計算することです$$P = \prod_{i=1}^{n} \min(a_i, b_i)$$何らかの再配置の後`b`。 概念的には、これを次の要素のペアと考えることができます。`a`からの要素を含む`b`各ペアからの寄与が最大化されるようにします。 最初の計算の後、次の処理を行うように求められます。`q`1 つの要素が含まれる増分変更`a`または`b`1 ずつ増加し、変更のたびに、新しい可能な最大値を報告する必要があります。`P`。 すべての結果はモジュロです`998244353`。 

制約は高いです:`n`そして`q`それぞれ 200,000 に達する可能性があり、すべてのテスト ケースの合計は最大 400,000 になります。 ブルートフォース再計算`P`各変更の後はソートが必要になるため遅すぎます`b`各クエリの積を計算します。 クエリごとに並べ替えを行ったとしても、これは次のような可能性があります。$O(n \log n \cdot q) = O(4 \cdot 10^5 \cdot \log(2 \cdot 10^5))$最悪の場合、動作がギリギリまたは遅い場合。 製品を最初から再計算せずに効率的に更新できるソリューションが必要です。 

難しいのはペアリングです。単純に並べ替えるだけです。`a`そして`b`値が動的に変化する場合、独立して最小値を乗算するだけでは十分ではありません。 もう 1 つの微妙な点は、積が巨大になる可能性があるため、オーバーフローを避けるために各乗算ステップでモジュラー演算が必要になることです。 エッジ ケースには、すべての値が等しい場合、一方の配列が他方の配列よりも厳密に大きい場合、単一の要素に複数の変更が蓄積される場合などが含まれます。 

不用意なアプローチは危険をもたらす`b`一度固定インデックスのペアリングを続けてみます。 の値を増やすと失敗します`a`または`b`最大の積を得るためにどの要素を組み合わせる必要があるかを変更する可能性があります。 

## アプローチ

 素朴なアプローチは簡単です。 初期配列の場合、ソートします。`a`そして並べ替える`b`、次に最小のものをペアリングします`a`最小のもので`b`、次に小さいものとその次に小さいもの、というように続きます。 これにより、どの偏差ペアもより小さいため、各ペアの最小値が最大化されることが保証されます。`a`より大きなもので`b`- 最小値の 1 つを減らすことになります。 クエリごとに、増分を次のように適用します。`a`または`b`、配列を再ソートし、積を再計算します。 最悪の場合の時間計算量は次のとおりです。$O(q \cdot n \log n)$、最大の入力に対しては遅すぎます。 

重要な洞察は、$$P = \prod \min(a_i, b_{\pi(i)})$$それぞれの個別の値のカウントを知る必要があるだけです。`a`そして`b`また、並べ替えられた順序で要素ごとの最小値の積を計算しながら、値の増加を効率的にサポートする構造を維持します。 仕分け`a`そして`b`最初は問題ありませんが、増加するたびに、マルチセットまたはバランスのとれた BST を維持できます。`b`これにより、完全な再計算を行わずに積を迅速に調整できます。 具体的に言うと、`b`ソートされた順序では、古い値を削除して新しい値を挿入することで、インクリメント操作をシミュレートできます。 同様に、`a`。 積を計算するには、利用可能な最小のものを組み合わせて順番に反復できます。`a`利用可能な最小のもので`b`それはまだ使用されていません。 

もう 1 つの最適化は、**ソートされた値** のみが必要であることです。`a`そして`b`それぞれの時点で。 If we maintain counts of each value (e.g., via a Counter or dictionary) and a prefix product structure, we can adjust`a`または`b`完全な並べ替えを行わずにカウントを更新し、最小限の寄与を再計算することにより、段階的に増加します。

 ## アルゴリズムのチュートリアル

 1. 配列のソート`a`降順ではない順に。 の順序`b`自由に並べ替えることができるので、並べ替えてください。`b`同じく降順ではありません。 ペア`a[i]`と`b[i]`それぞれに`i`。 これにより製品が保証されます`P`ペアリングが最小であるため、最大化されます。`a`最小のもので`b`大量の無駄を防ぐ`b`小さなもので`a`。 
2. 初期積を計算する`P`モジュロ`998244353`。 すべてのインデックスを繰り返して乗算します`min(a[i], b[i])`各ステップでモジュロを取ります。 
3. 両方を維持する`a`そして`b`リストとして、およびインクリメント操作ごとに次のようになります。 

- 操作がオンの場合`a[x]`、 増加`a[x]`1までに。 
- 操作がオンの場合`b[x]`、 増加`b[x]`1までに。 
- 増加するたびに、影響を受ける配列を再ソートします。 変更される要素は 1 つだけなので、二分検索を使用して古い値を削除し、新しい値を挿入できます (`bisect`) O(log n) で。 
4. 新しくソートされた配列を使用して積を再計算します。 両方の配列がソートされたままであるため、要素ごとにペアリングしても最大の積が得られます。 
5. 初期状態後および各操作後に積を出力します。 

最適なペアリングは常にソートされたものであるため、正確性が保証されます。 単一の要素をインクリメントし、それを並べ替えられた配列に再挿入すると、i 番目に小さい要素のペアとなる不変式が維持されます。`a`i 番目に小さいもの`b`最大限のものを生み出す`P`。 

## Python ソリューション```python
import sys, bisect
input = sys.stdin.readline
MOD = 998244353

def max_product(a, b):
    prod = 1
    for x, y in zip(a, b):
        prod = (prod * min(x, y)) % MOD
    return prod

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    ans = [max_product(a, b)]
    
    for _ in range(q):
        o, x = map(int, input().split())
        x -= 1
        if o == 1:
            old = a[x]
            a.pop(x)
            bisect.insort(a, old + 1)
        else:
            old = b[x]
            b.pop(x)
            bisect.insort(b, old + 1)
        ans.append(max_product(a, b))
    
    print(' '.join(map(str, ans)))
```コードが並べ替えられる`a`そして`b`最初は。 増分ごとに、リストから古い値が削除され、増分された値が再挿入されます。`bisect.insort`これにより、配列が効率的にソートされます。 各変更後に積を計算すると、ソートされたペアリング戦略により結果が最大になることが保証されます。
