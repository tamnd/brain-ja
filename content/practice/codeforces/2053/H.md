 ## 解決策
 ## 問題の理解

 それぞれ 1 から最大値までの一連の整数が与えられます。$w$。 シーケンスには繰り返しの数値を含めることができますが、特別な操作を何度でも実行することができます。つまり、等しい 2 つの連続する要素を選択し、それらが等しくなくなっている限り、両方を任意の 2 つの数値に変更します。 私たちの目標は、これらの操作を実行した後のシーケンスの合計を最大化し、その最大合計に達するために必要な最小操作数を報告することです。 

最初の観察は、操作の制約を無視すれば、シーケンスの合計を最大化するのは簡単であるということです。理想的には、各要素は次のようにする必要があります。$w$。 この課題は、どのような操作を行っても、連続する 2 つの要素が等しくならないという制限によって生じます。 シーケンスにすでに連続した重複が含まれている場合、操作を適用せずにそれらの要素を個別に単純に増やすことはできません。 各操作は、繰り返されるペアを 2 つの異なる数値に変更します。$[1, w]$。 合計を最大化するための最適な選択は、常に可能な限り最大の 2 つの異なる数値を選択することです。$w$そして$w-1$。 

制約は高いです。 配列の長さ$n$まで可能です$2\cdot10^5$、およびテストケースの数$t$できる$10^5$ただし、すべてのテスト ケースにわたる配列要素の総数は次の制限を受けます。$10^6$。 これは、最悪の場合、操作の数が 1 に近づく可能性があるため、単純に操作をシミュレートできないことを意味します。$n$繰り返し繰り返すと遅すぎます。 必要なのは$O(n)$テストケースごとのソリューション。 

シーケンスがすでに厳密に交互になっている場合、明らかではないエッジ ケースが発生します。 たとえば、次の場合$a = [1, 2, 1, 2, 1]$と$w = 2$、操作は必要ありません。 あらゆる要素を盲目的に増やそうとする無謀な解決策$w$反復しないペアの操作を誤ってカウントする可能性があります。 

別の厄介な状況は、繰り返される数字が連続して複数回出現する場合に発生します。たとえば、$a = [3, 3, 3, 3]$と$w = 5$。 連続する重複を効率的にペアにする必要があります。各操作の後、2 つの数値は区別され、選択に注意しないと新しい重複のペアが形成される可能性があります。$w$そして$w-1$。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列を繰り返しスキャンし、連続する重複が見つかるたびに、それらを 2 つの最大の個別の数値に変換する操作を適用します。$w$そして$w-1$。 各操作をカウントし、重複がなくなるまで繰り返します。 これは原理的には正しいですが、最悪の場合の複雑さは次のとおりです。$O(n^2)$1 回のパスで新たな重複が発生する可能性があり、このプロセスを繰り返すと最大で 3 分かかることがあるためです。$n/2$繰り返し。 

重要な洞察は、必要な最終配列は厳密に反単調なシーケンスであるということです。これは、連続するすべてのペアが個別であり、各要素が次のいずれかであることを意味します。$w$または$w-1$。 これが分かれば、元のシーケンスで繰り返される連続するペアをカウントすることで、演算の数を直接計算できます。 繰り返される各ペアには 1 回の操作が必要です。 繰り返されるペアは他のペアから独立しているため、操作を順番にシミュレートする必要はありません。 最大合計は、繰り返される各ペアを次のように置き換えることによって常に達成されます。$w$そして$w-1$、必要に応じて交互に。 

この観察により、問題は配列を 1 回スキャンし、重複を検出し、最大値を合計し、演算をカウントすることに帰着します。 複雑さは線形です$n$制約を考慮すると、これはテスト ケースごとに許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 繰り返しをカウントして最大化 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 合計をゼロに、演算カウントをゼロに初期化します。 これらの変数は、達成可能な最大合計と必要な操作の最小数を追跡します。 
2. 配列を左から右に繰り返します。 各要素について、それが前の要素と等しい場合、操作カウントをインクリメントします。 これにより、連続する各重複ペアが 1 回だけカウントされます。 操作のシミュレーションは行いません。 それが必要になることにのみ注意してください。 
3. 演算をカウントした後、最大合計を計算します。 もし$n = 1$、合計は単に要素そのものです。 のために$n \ge 2$、最終シーケンスの各要素は次のいずれかである必要があります。$w$または$w-1$。 合計の公式は$(n//2) \cdot (w + (w-1)) + (w \text{ if n is odd else 0})$、交互に$w$そして$w-1$連続した重複を避けるため。 
4. 最大合計値と演算回数を返します。 

正確性を保証する不変条件は、各操作が連続する重複を 1 つだけ修正すること、および次を使用することです。$w$そして$w-1$新しい重複が導入されないようにします。 最初に繰り返されるペアをカウントすると、必要な操作の正確な数がわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, w = map(int, input().split())
        a = list(map(int, input().split()))
        
        ops = 0
        for i in range(1, n):
            if a[i] == a[i-1]:
                ops += 1
        
        full_pairs = n // 2
        max_sum = full_pairs * (w + (w-1))
        if n % 2:
            max_sum += w
        
        print(max_sum, ops)

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取ります。 配列ごとに、連続する重複をカウントして、操作の数を決定します。 次に、長さの最大の反単調配列の合計を計算します。$n$を使用して$w$そして$w-1$交互に。 長さ 1 の配列などのエッジ ケースは、自然に合計の式で処理されます。
